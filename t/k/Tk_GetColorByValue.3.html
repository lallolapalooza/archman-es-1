NOMBRE

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - mantener la base de datos de colores

SINOPSIS

#include <tk.h>

XColor *
Tk_AllocColorFromObj(interp, tkwin, objPtr)

XColor *
Tk_GetColor(interp, tkwin, name)

XColor *
Tk_GetColorFromObj(tkwin, objPtr)

XColor *
Tk_GetColorByValue(tkwin, prefPtr)

const char *
Tk_NameOfColor(colorPtr)

GC
Tk_GCForColor(colorPtr, drawable)

Tk_FreeColorFromObj(tkwin, objPtr)

Tk_FreeColor(colorPtr)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para la notificación de errores.
Tk_Window tkwin (entrada)
Token para la ventana en la que se utilizará el color.
Tcl_Obj *objPtr (entrada/salida)
El valor de cadena describe el color deseado; la representación interna se modificará para almacenar en caché un puntero al (XColor *) correspondiente.
const char *name (entrada)
Igual que objPtr, excepto que la descripción del color se pasa como una cadena y el (XColor *) resultante no se almacena en caché.
XColor *prefPtr (entrada)
Indica las intensidades de rojo, verde y azul del color deseado.
XColor *colorPtr (entrada)
Puntero a la información de color X. Debe haber sido asignado por una llamada anterior a Tk_AllocColorFromObj, Tk_GetColor o Tk_GetColorByValue, excepto cuando se pasa a Tk_NameOfColor.
Drawable drawable (entrada)
Dibujo en el que se utilizará el contexto gráfico resultante. Debe tener la misma pantalla y profundidad que la ventana para la que se asignó el color.

DESCRIPCION

Estos procedimientos gestionan los colores que está utilizando una aplicación Tk. Permiten compartir colores siempre que sea posible, de modo que se conserve el espacio del mapa de colores, y seleccionan los colores disponibles más cercanos cuando el espacio del mapa de colores se agota.

Dado una descripción textual de un color, Tk_AllocColorFromObj localiza un valor de píxel que puede utilizarse para representar el color en una ventana determinada. El color deseado se especifica con un valor cuya representación de cadena debe tener una de las siguientes formas:

nombredelcolor
Cualquiera de los nombres textuales válidos para un color definido en el archivo de base de datos de colores del servidor, como red o PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Una especificación numérica de las intensidades de rojo, verde y azul a utilizar para mostrar el color. Cada R, G o B representa un solo dígito hexadecimal. Las cuatro formas permiten especificar colores con valores de 4 bits, 8 bits, 12 bits o 16 bits. Cuando se proporcionan menos de 16 bits para cada color, representan los bits más significativos del color, mientras que los bits inferiores no completados se replicarán repetidamente a partir de los bits superiores disponibles. Por ejemplo, #3a7 es lo mismo que #3333aaaa7777.

Tk_AllocColorFromObj devuelve un puntero a una estructura XColor; la estructura indica las intensidades exactas del color asignado (que pueden diferir ligeramente de las solicitadas, dependiendo de las limitaciones de la pantalla) y un valor de píxel que puede utilizarse para dibujar con el color en tkwin. Si ocurre un error en Tk_AllocColorFromObj (como un nombre de color desconocido), se devuelve NULL y se almacena un mensaje de error en el resultado de interp si interp no es NULL. Si el mapa de colores de tkwin está lleno, Tk_AllocColorFromObj utilizará el color existente más cercano en el mapa de colores. Tk_AllocColorFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocColorFromObj y Tk_GetColorFromObj.

Tk_GetColor es idéntico a Tk_AllocColorFromObj excepto que la descripción del color se especifica con una cadena en lugar de un valor. Esto evita que Tk_GetColor almacene en caché el valor de retorno, por lo que Tk_GetColor es menos eficiente que Tk_AllocColorFromObj.

Tk_GetColorFromObj devuelve el token de un color existente, dado la ventana y la descripción utilizadas para crear el color. Tk_GetColorFromObj no crea realmente el color; el color debe haber sido creado previamente con una llamada a Tk_AllocColorFromObj o Tk_GetColor. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetColorFromObj con el mismo objPtr y tkwin.

Tk_GetColorByValue es similar a Tk_GetColor excepto que el color deseado se indica con los campos red, green y blue de la estructura apuntada por colorPtr.

Este paquete mantiene una base de datos de todos los colores actualmente en uso. Si el mismo color se solicita varias veces desde Tk_GetColor o Tk_AllocColorFromObj (por ejemplo, por diferentes ventanas), o si las mismas intensidades se solicitan varias veces desde Tk_GetColorByValue, entonces se reutilizarán los valores de píxel existentes. Reutilizar un píxel existente evita cualquier interacción con el servidor de ventanas, lo que hace que la asignación sea mucho más eficiente. Estos procedimientos también proporcionan una interfaz portable que funciona en todas las plataformas. Por esta razón, generalmente debe usar Tk_AllocColorFromObj, Tk_GetColor, o Tk_GetColorByValue en lugar de procedimientos de nivel inferior como XAllocColor.

Dado que diferentes llamadas a este paquete pueden devolver el mismo valor de píxel compartido, los llamadores nunca deben cambiar el color de un píxel devuelto por los procedimientos. Si necesita cambiar un valor de color dinámicamente, debe usar XAllocColorCells para asignar el valor de píxel para el color.

El procedimiento Tk_NameOfColor es aproximadamente lo inverso de Tk_GetColor. Si su argumento colorPtr fue creado por Tk_AllocColorFromObj o Tk_GetColor, entonces el valor de retorno es la cadena que se utilizó para crear el color. Si colorPtr fue creado por una llamada a Tk_GetColorByValue, o por cualquier otro mecanismo, entonces el valor de retorno es una cadena que podría pasarse a Tk_GetColor para devolver el mismo color. Nota: la cadena devuelta por Tk_NameOfColor solo se garantiza que persista hasta la siguiente llamada a Tk_NameOfColor.

Tk_GCForColor devuelve un contexto gráfico cuyo campo foreground es el píxel asignado para colorPtr y cuyos otros campos tienen todos valores predeterminados. Esto proporciona una forma fácil de realizar dibujos básicos con un color. El contexto gráfico se almacena en caché con el color y existirá solo mientras colorPtr exista; se libera cuando la última referencia a colorPtr se libera llamando a Tk_FreeColor.

Cuando un color ya no es necesario, se debe llamar a Tk_FreeColorFromObj o Tk_FreeColor para liberarlo. Para Tk_FreeColorFromObj, el color a liberar se especifica con la misma información utilizada para crearlo; para Tk_FreeColor, el color a liberar se especifica con un puntero a su estructura XColor. Debe haber exactamente una llamada a Tk_FreeColorFromObj o Tk_FreeColor por cada llamada a Tk_AllocColorFromObj, Tk_GetColor, o Tk_GetColorByValue.
