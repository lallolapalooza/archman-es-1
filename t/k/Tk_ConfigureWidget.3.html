Tk_ConfigureWidget(3) Procedimientos de la biblioteca Tk Tk_ConfigureWidget(3)

NOMBRE

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - procesar opciones de configuración para widgets

SINOPSIS

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para devolver mensajes de error.
Tk_Window tkwin (entrada)
Ventana utilizada para representar el widget (necesaria para configurar recursos X).
const Tk_ConfigSpec *specs (entrada)
Puntero a la tabla que especifica las opciones de configuración legales para este widget.
int argc (entrada)
Número de argumentos en argv.
const char **argv (entrada)
Opciones de línea de comandos para configurar el widget.
char *widgRec (entrada/salida)
Punta a la estructura del registro del widget. Los campos de esta estructura se modifican por Tk_ConfigureWidget para contener la información de configuración.
int flags (entrada)
Si no es cero, especifica una combinación OR de banderas que controlan el procesamiento de la información de configuración. TK_CONFIG_ARGV_ONLY hace que se ignoren la base de datos de opciones y los valores predeterminados, y las banderas TK_CONFIG_USER_BIT y superiores se utilizan para deshabilitar selectivamente las entradas en specs.
nombre de tipo type (entrada)
El nombre del tipo de un registro de widget.
nombre de campo field (entrada)
El nombre de un campo en registros del tipo type.
const char *argvName (entrada)
El nombre utilizado en las líneas de comando de Tcl para referirse a una opción particular (p. ej., al crear un widget o invocar el comando configure del widget). Si no es NULL, solo se devuelve información para esta opción. Si es NULL, se devuelve información para todas las opciones disponibles.
Display *display (entrada)
Pantalla que contiene el widget cuyo registro se está liberando; es necesario para liberar recursos.

DESCRIPCIÓN

Nota: Tk_ConfigureWidget debería ser reemplazado por la nueva API basada en Tcl_Obj Tk_SetOptions. La interfaz antigua se conserva por compatibilidad con versiones anteriores.

Tk_ConfigureWidget se llama para configurar varios aspectos de un widget, como colores, fuentes, ancho del borde, etc. Está diseñado como un procedimiento de conveniencia para reducir la cantidad de código que debe escribirse en los administradores de widgets individuales para manejar la información de configuración. Normalmente se invoca cuando se crean los widgets y de nuevo cuando se invoca el comando configure para un widget. Aunque está diseñado principalmente para widgets, Tk_ConfigureWidget se puede usar en otras situaciones donde la información argc-argv se va a utilizar para rellenar una estructura de registro, como la configuración de elementos gráficos para un widget de lienzo o entradas de un menú.

Tk_ConfigureWidget procesa una tabla que especifica las opciones de configuración que se admiten (specs) y una colección de argumentos de línea de comandos (argc y argv) para rellenar campos de un registro (widgRec). Utiliza la base de datos de opciones y los valores predeterminados especificados en specs para rellenar los campos de widgRec que no se especifican en argv. Tk_ConfigureWidget normalmente devuelve el valor TCL_OK; en este caso, no modifica interp. Si ocurre un error, se devuelve TCL_ERROR y Tk_ConfigureWidget dejará un mensaje de error en el resultado del intérprete interp de la forma estándar de Tcl. En caso de un retorno de error, algunos de los campos de widgRec podrían ya haber sido establecidos si la información de configuración para ellos se procesó correctamente antes de que ocurriera el error. Los otros campos se establecerán en valores iniciales razonables para que se pueda llamar a Tk_FreeOptions para la limpieza.

La matriz specs especifica los tipos de opciones de configuración que espera el widget. Cada una de sus entradas especifica una opción de configuración y tiene la siguiente estructura:

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
El campo type indica qué tipo de opción de configuración es (p. ej., TK_CONFIG_COLOR para un valor de color, o TK_CONFIG_INT para un valor entero). El campo type indica cómo usar el valor de la opción (más sobre esto a continuación). El campo argvName es una cadena como “-font” o “-bg”, que se compara con los valores en argv (si argvName es NULL, significa que es una entrada agrupada; consulte ENTRADAS AGRUPADAS a continuación). Los campos dbName y dbClass se utilizan para buscar un valor para esta opción en la base de datos de opciones. El campo defValue especifica un valor predeterminado para esta opción de configuración si no se especifica ningún valor en argv o en la base de datos de opciones. Offset indica dónde en widgRec almacenar la información sobre esta opción, y specFlags contiene información adicional para controlar el procesamiento de esta opción de configuración (consulte FLAGS a continuación). El último campo, customPtr, solo se usa si type es TK_CONFIG_CUSTOM; consulte TIPOS DE OPCIONES PERSONALIZADAS a continuación.

Tk_ConfigureWidget primero procesa argv para ver cuáles (si los hay) opciones de configuración se especifican allí. Argv debe contener un número par de campos; el primero de cada par de campos debe coincidir con el argvName de alguna entrada en specs (se aceptan abreviaturas únicas), y el segundo campo del par contiene el valor para esa opción de configuración. Si hay entradas en spec para las cuales no hubo entradas coincidentes en argv, Tk_ConfigureWidget utiliza los campos dbName y dbClass de la entrada specs para sondear la base de datos de opciones; si se encuentra un valor, se utiliza como el valor para la opción. Finalmente, si no se encuentra ninguna entrada en la base de datos de opciones, el campo defValue de la entrada specs se utiliza como el valor para la opción de configuración. Si defValue es NULL, o si el bit TK_CONFIG_DONT_SET_DEFAULT está establecido en flags, entonces no hay valor predeterminado y esta entrada specs será ignorada si no se especifica ningún valor en argv o en la base de datos de opciones.

Una vez que se determina un valor de cadena para una opción de configuración, Tk_ConfigureWidget traduce el valor de cadena a una forma más útil, como un color si type es TK_CONFIG_COLOR o un entero si type es TK_CONFIG_INT. Luego, este valor se almacena en el registro apuntado por widgRec. Se asume que este registro contiene información relevante para el administrador del widget; su tipo exacto es desconocido para Tk_ConfigureWidget. El campo offset de cada entrada specs indica dónde en widgRec almacenar la información sobre esta opción de configuración. Debe usar la macro Tk_Offset para generar valores de offset (consulte a continuación una descripción de Tk_Offset). La ubicación indicada por widgRec y offset se denominará "destino" en las descripciones a continuación.

El campo type de cada entrada en specs determina qué hacer con el valor de cadena de esa opción de configuración. Los valores legales para type, y las acciones correspondientes, son:

TK_CONFIG_ACTIVE_CURSOR
El valor debe ser una cadena ASCII que identifique un cursor en un formato adecuado para pasarlo a Tk_GetCursor. El valor se convierte en un Tk_Cursor llamando a Tk_GetCursor y el resultado se almacena en el destino. Además, el cursor resultante se establece como el cursor activo para tkwin llamando a XDefineCursor. Si se especifica TK_CONFIG_NULL_OK en specFlags, entonces el valor puede ser una cadena vacía, en cuyo caso el destino y el cursor activo de tkwin se establecerán en None. Si el valor anterior del destino no era None, entonces se libera pasándolo a Tk_FreeCursor.
TK_CONFIG_ANCHOR
El valor debe ser una cadena ASCII que identifique un punto de anclaje en una de las formas aceptadas por Tk_GetAnchor. La cadena se convierte en un Tk_Anchor

OPTION TYPES

The type field of an entry in specs specifies the data type of the configuration option. The following types are available:

TK_CONFIG_ACTIVE_CURSOR
The value must be an ASCII string identifying a cursor in a form suitable for passing to Tk_GetCursor. The value is converted to a Tk_Cursor by calling Tk_GetCursor and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target is set to None. If the previous value of the target was not None, then it is freed by passing it to Tk_FreeCursor.
TK_CONFIG_ANCHOR
The value must be an ASCII string identifying an anchor position in one of the ways accepted by Tk_GetAnchor. The string is converted to a Tk_Anchor by calling Tk_GetAnchor and the result is stored in the target.
TK_CONFIG_BITMAP
The value must be an ASCII string identifying a bitmap in a form suitable for passing to Tk_GetBitmap. The value is converted to a Pixmap by calling Tk_GetBitmap and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target is set to None. If the previous value of the target was not None, then it is freed by passing it to Tk_FreeBitmap.
TK_CONFIG_BOOLEAN
The value must be an ASCII string specifying a boolean value. Any of the values “true”, “yes”, “on”, or “1”, or an abbreviation of one of these values, means true; any of the values “false”, “no”, “off”, or “0”, or an abbreviation of one of these values, means false. The target is expected to be an integer; for true values it will be set to 1 and for false values it will be set to 0.
TK_CONFIG_BORDER
The value must be an ASCII string identifying a border color in a form suitable for passing to Tk_Get3DBorder. The value is converted to a (Tk_3DBorder *) by calling Tk_Get3DBorder and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to NULL. If the previous value of the target was not NULL, then it is freed by passing it to Tk_Free3DBorder.
TK_CONFIG_CAP_STYLE
The value must be an ASCII string identifying a cap style in one of the ways accepted by Tk_GetCapStyle. The string is converted to an integer value corresponding to the cap style by calling Tk_GetCapStyle and the result is stored in the target.
TK_CONFIG_COLOR
The value must be an ASCII string identifying a color in a form suitable for passing to Tk_GetColor. The value is converted to an (XColor *) by calling Tk_GetColor and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to None. If the previous value of the target was not NULL, then it is freed by passing it to Tk_FreeColor.
TK_CONFIG_CURSOR
This option is identical to TK_CONFIG_ACTIVE_CURSOR except that the new cursor is not made the active one for tkwin.
TK_CONFIG_CUSTOM
This option allows applications to define new option types. The customPtr field of the entry points to a structure defining the new option type. See the section CUSTOM OPTION TYPES below for details.
TK_CONFIG_DOUBLE
The value must be an ASCII floating-point number in the format accepted by strtod. The string is converted to a double value, and the value is stored in the target.
TK_CONFIG_END
Marks the end of the table. The last entry in specs must have this type; all of its other fields are ignored and it will never match any arguments.
TK_CONFIG_FONT
The value must be an ASCII string identifying a font in a form suitable for passing to Tk_GetFont. The value is converted to a Tk_Font by calling Tk_GetFont and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to NULL. If the previous value of the target was not NULL, then it is freed by passing it to Tk_FreeFont.
TK_CONFIG_INT
The value must be an ASCII integer string in the format accepted by strtol (e.g. “0” and “0x” prefixes may be used to specify octal or hexadecimal numbers, respectively). The string is converted to an integer value and the integer is stored in the target.
TK_CONFIG_JOIN_STYLE
The value must be an ASCII string identifying a join style in one of the ways accepted by Tk_GetJoinStyle. The string is converted to an integer value corresponding to the join style by calling Tk_GetJoinStyle and the result is stored in the target.
TK_CONFIG_JUSTIFY
The value must be an ASCII string identifying a justification method in one of the ways accepted by Tk_GetJustify. The string is converted to a Tk_Justify by calling Tk_GetJustify and the result is stored in the target.
TK_CONFIG_MM
The value must specify a screen distance in one of the forms acceptable to Tk_GetScreenMM. The string is converted to double-precision floating-point distance in millimeters and the value is stored in the target.
TK_CONFIG_PIXELS
The value must specify screen units in one of the forms acceptable to Tk_GetPixels. The string is converted to an integer distance in pixels and the value is stored in the target.
TK_CONFIG_RELIEF
The value must be an ASCII string identifying a relief in a form suitable for passing to Tk_GetRelief. The value is converted to an integer relief value by calling Tk_GetRelief and the result is stored in the target.
TK_CONFIG_STRING
A copy of the value is made by allocating memory space with Tcl_Alloc and copying the value into the dynamically-allocated space. A pointer to the new string is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to NULL. If the previous value of the target was not NULL, then it is freed by passing it to Tcl_Free.
TK_CONFIG_SYNONYM
This type value identifies special entries in specs that are synonyms for other entries. If an argv value matches the argvName of a TK_CONFIG_SYNONYM entry, the entry is not used directly. Instead, Tk_ConfigureWidget searches specs for another entry whose argvName is the same as the dbName field in the TK_CONFIG_SYNONYM entry; this new entry is used just as if its argvName had matched the argv value. The synonym mechanism allows multiple argv values to be used for a single configuration option, such as “-background” and “-bg”.
TK_CONFIG_UID
The value is translated to a Tk_Uid (by passing it to Tk_GetUid). The resulting value is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags and the value is an empty string then the target will be set to NULL.
TK_CONFIG_WINDOW
The value must be a window path name. It is translated to a Tk_Window token and the token is stored in the target.

GROUPED ENTRIES

In some cases it is useful to generate multiple resources from a single configuration value. For example, a color name might be used both to generate the background color for a widget (using TK_CONFIG_COLOR) and to generate a 3-D border to draw around the widget (using TK_CONFIG_BORDER). In cases like this it is possible to specify that several consecutive entries in specs are to be treated as a group. The first entry is used to determine a value (using its argvName, dbName, dbClass, and defValue fields). The value will be processed several times (one for each entry in the group), generating multiple different resources and modifying multiple targets within widgRec. Each of the entries after the first must have a NULL value in its argvName field; this indicates that the entry is to be grouped with the entry that precedes it. Only the type and offset fields are used from these follow-on entries.

FLAGS

The flags argument passed to Tk_ConfigureWidget is used in conjunction with the specFlags fields in the entries of specs to provide additional control over the processing of configuration options. These values are used in three different ways as described below.

First, if the flags argument to Tk_ConfigureWidget has the TK_CONFIG_ARGV_ONLY bit set (i.e., flags | TK_CONFIG_ARGV_ONLY != 0), then the option database and defValue fields are not used. In this case, if an entry in specs does not match a field in argv then nothing happens: the corresponding target is not modified. This feature is useful when the goal is to modify certain configuration options while leaving others in their current state, such as when a configure widget command is being processed.

Second, the specFlags field of an entry in specs may be used to control the processing of that entry. Each specFlags field may consists of an OR-ed combination of the following values:

TK_CONFIG_COLOR_ONLY
If this bit is set then the entry will only be considered if the display for tkwin has more than one bit plane. If the display is monochromatic then this specs entry will be ignored.
TK_CONFIG_MONO_ONLY
If this bit is set then the entry will only be considered if the display for tkwin is monochromatic. If the display has more than one bit plane then this specs entry will be ignored.
TK_CONFIG_NULL_OK
If this bit is set then an empty string is a valid value for the option. An empty string will correspond to a NULL value for pointer-based types (like TK_CONFIG_STRING, TK_CONFIG_FONT, etc.) or 0 for integer types (though this is unusual). If the option is specified as an empty string, then the old value is freed (if applicable) and the target is set to NULL (or 0).
TK_CONFIG_DONT_SET_DEFAULT
If this bit is set then the default value field (defValue) is ignored. This is useful for options that don't have a sensible default value, or whose default value is handled in some other way.

Third, the specFlags field may also contain the TK_CONFIG_USER_BIT bit or any higher value. These bits are passed through to the customPtr field of the Tk_OptionParseSpec structure when defining custom option types.
