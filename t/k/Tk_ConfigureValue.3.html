Tk_ConfigureWidget(3) Procedimientos de la biblioteca Tk Tk_ConfigureWidget(3)

NOMBRE

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - procesar opciones de configuración para widgets

SINOPSIS

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para devolver mensajes de error.
Tk_Window tkwin (entrada)
Ventana utilizada para representar el widget (necesaria para configurar recursos X).
const Tk_ConfigSpec *specs (entrada)
Puntero a la tabla que especifica las opciones de configuración legales para este widget.
int argc (entrada)
Número de argumentos en argv.
const char **argv (entrada)
Opciones de línea de comandos para configurar el widget.
char *widgRec (entrada/salida)
Punta a la estructura del registro del widget. Los campos de esta estructura se modifican por Tk_ConfigureWidget para mantener la información de configuración.
int flags (entrada)
Si no es cero, especifica una combinación OR de banderas que controlan el procesamiento de la información de configuración. TK_CONFIG_ARGV_ONLY hace que se ignoren la base de datos de opciones y los valores predeterminados, y las banderas TK_CONFIG_USER_BIT y superiores se usan para deshabilitar selectivamente las entradas en specs.
nombre de tipo type (entrada)
El nombre del tipo de un registro de widget.
nombre de campo field (entrada)
El nombre de un campo en registros del tipo type.
const char *argvName (entrada)
El nombre utilizado en las líneas de comandos de Tcl para referirse a una opción particular (por ejemplo, al crear un widget o invocar el comando configure del widget). Si es NULL, entonces la información se devuelve solo para esta opción. Si es NULL, entonces la información se devuelve para todas las opciones disponibles.
Display *display (entrada)
Pantalla que contiene el widget cuyo registro se está liberando; necesario para liberar recursos.

DESCRIPCIÓN

Nota: Tk_ConfigureWidget debe ser reemplazado por la nueva API basada en Tcl_Obj Tk_SetOptions. La interfaz antigua se conserva por compatibilidad con versiones anteriores.

Tk_ConfigureWidget se llama para configurar varios aspectos de un widget, como colores, fuentes, ancho del borde, etc. Está pensada como un procedimiento de conveniencia para reducir la cantidad de código que debe escribirse en los administradores de widgets individuales para manejar la información de configuración. Se invoca típicamente cuando se crean los widgets y nuevamente cuando se invoca el comando configure para un widget. Aunque está pensada principalmente para widgets, Tk_ConfigureWidget se puede usar en otras situaciones donde la información argc-argv se utilizará para rellenar una estructura de registro, como la configuración de elementos gráficos para un widget de lienzo o entradas de un menú.

Tk_ConfigureWidget procesa una tabla que especifica las opciones de configuración que se admiten (specs) y una colección de argumentos de línea de comandos (argc y argv) para rellenar los campos de un registro (widgRec). Utiliza la base de datos de opciones y los valores predeterminados especificados en specs para rellenar los campos de widgRec que no se especifican en argv. Tk_ConfigureWidget normalmente devuelve el valor TCL_OK; en este caso, no modifica interp. Si ocurre un error, devuelve TCL_ERROR y Tk_ConfigureWidget dejará un mensaje de error en el resultado del intérprete interp de la forma estándar de Tcl. En caso de un retorno de error, algunos de los campos de widgRec ya podrían haberse establecido si la información de configuración para ellos se procesó correctamente antes de que ocurriera el error. Los demás campos se establecerán en valores iniciales razonables para que se pueda llamar a Tk_FreeOptions para la limpieza.

La matriz specs especifica los tipos de opciones de configuración que espera el widget. Cada una de sus entradas especifica una opción de configuración y tiene la siguiente estructura:

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
El campo type indica qué tipo de opción de configuración es esta (por ejemplo, TK_CONFIG_COLOR para un valor de color, o TK_CONFIG_INT para un entero). El campo type indica cómo usar el valor de la opción (más sobre esto a continuación). El campo argvName es una cadena como “-fuente” o “-fondo”, que se compara con los valores en argv (si argvName es NULL, significa que es una entrada agrupada; consulte ENTRADAS AGRUPADAS a continuación). Los campos dbName y dbClass se utilizan para buscar un valor para esta opción en la base de datos de opciones. El campo defValue especifica un valor predeterminado para esta opción de configuración si no se especifica ningún valor en argv o en la base de datos de opciones. Offset indica dónde en widgRec almacenar la información sobre esta opción, y specFlags contiene información adicional para controlar el procesamiento de esta opción de configuración (consulte BANDERAS a continuación). El último campo, customPtr, solo se usa si type es TK_CONFIG_CUSTOM; consulte TIPOS DE OPCIONES PERSONALIZADAS a continuación.

Tk_ConfigureWidget procesa primero argv para ver cuáles (si los hay) opciones de configuración se especifican allí. Argv debe contener un número par de campos; el primero de cada par de campos debe coincidir con el argvName de alguna entrada en specs (se aceptan abreviaturas únicas), y el segundo campo del par contiene el valor para esa opción de configuración. Si hay entradas en spec para las que no hubo entradas coincidentes en argv, Tk_ConfigureWidget utiliza los campos dbName y dbClass de la entrada specs para consultar la base de datos de opciones; si se encuentra un valor, se utiliza como valor para la opción. Finalmente, si no se encuentra ninguna entrada en la base de datos de opciones, el campo defValue de la entrada specs se utiliza como valor para la opción de configuración. Si defValue es NULL, o si el bit TK_CONFIG_DONT_SET_DEFAULT está establecido en flags, entonces no hay valor predeterminado y esta entrada specs se ignorará si no se especifica ningún valor en argv o en la base de datos de opciones.

Una vez que se determina un valor de cadena para una opción de configuración, Tk_ConfigureWidget traduce el valor de cadena a una forma más útil, como un color si type es TK_CONFIG_COLOR o un entero si type es TK_CONFIG_INT. Este valor se almacena luego en el registro apuntado por widgRec. Se supone que este registro contiene información relevante para el administrador del widget; su tipo exacto es desconocido para Tk_ConfigureWidget. El campo offset de cada entrada specs indica dónde en widgRec almacenar la información sobre esta opción de configuración. Debe usar la macro Tk_Offset para generar valores offset (consulte a continuación una descripción de Tk_Offset). La ubicación indicada por widgRec y offset se denominará el “objetivo” en las descripciones a continuación.

El campo type de cada entrada en specs determina qué hacer con el valor de cadena de esa opción de configuración. Los valores legales para type, y las acciones correspondientes, son:

TK_CONFIG_ACTIVE_CURSOR
El valor debe ser una cadena ASCII que identifique un cursor en un formato adecuado para pasar a Tk_GetCursor. El valor se convierte en un Tk_Cursor llamando a Tk_GetCursor y el resultado se almacena en el objetivo. Además, el cursor resultante se convierte en el cursor activo para tkwin llamando a XDefineCursor. Si TK_CONFIG_NULL_OK se especifica en specFlags, entonces el valor puede ser una cadena vacía, en cuyo caso el objetivo y el cursor activo de tkwin se establecerán en None. Si el valor anterior del objetivo no era None, entonces se libera pasándolo a Tk_FreeCursor.
TK_CONFIG_ANCHOR
El valor debe ser una cadena ASCII que identifique un punto de anclaje en una de las formas aceptadas por Tk_GetAnchor. La cadena se convierte en un Tk_Anchor

DESCRIPTION

Tk_ConfigureWidget is the primary procedure used by Tk widgets to implement their configure options. It processes a list of option-value pairs, sets the widget’s internal state variables, and returns an error if any option is invalid. The configSpecs argument describes the legal options for the widget, including their types, internal variable offsets, and default values. The flags argument can be used to control the behavior of Tk_ConfigureWidget in special cases.

Tk_ConfigureValue is used to parse a single option value (given as a Tcl_Obj *) into internal form. It returns an error if the value is invalid. The varPtr argument is used to store the parsed value. If varPtr is NULL, the value is simply parsed and checked for validity, but not stored anywhere.

Tk_ConfigureInfo is used to retrieve information about the current configuration of a widget. If objPtr refers to a specific option name, Tk_ConfigureInfo returns the current value of that option as a Tcl object. If objPtr is NULL, it returns a Tcl object containing a list of all options and their current values.

Tk_ConfigureMutableValue is similar to Tk_ConfigureValue, but it is intended for use when the widget may need to free the old value before setting a new one. This is typically used for options whose values are allocated dynamically (e.g. strings).

Tk_ConfigureLine is used for configuring widgets that support the "configure" subcommand of the Tk dispatcher. It parses option-value pairs and updates the widget's internal state.

Tk_ConfigureCmd is the command procedure for the generic Tk configure command.

Tk_FreeOptions is used to free any memory that was dynamically allocated by Tk_ConfigureWidget or Tk_SetOptions for the widget’s configuration values.

Tk_SetOptions is used to parse and set widget options from a list of option-value pairs. It allocates memory for option values as needed and stores them in the widget record pointed to by varPtr. It returns an error if any option is invalid.

Tk_AllocConfigTable allocates memory for a configuration table with the given number of entries. It returns a pointer to the allocated table.

Tk_FreeConfigTable frees the memory allocated for a configuration table by Tk_AllocConfigTable.

GROUPED ENTRIES

Some configuration options may be grouped together in the configSpecs table. This is useful for options that are related, such as those for controlling the appearance of a border. When options are grouped, they are all processed together, and any changes to one option may affect the others. This is done by setting the flags field of a Tk_ConfigSpec entry to TK_CONFIG_GROUP. The first entry in a group should have this flag set. Subsequent entries in the group do not need this flag set.

FLAGS

The flags field of a Tk_ConfigSpec entry may have any of the following values:

TK_CONFIG_VALIDATE
This flag is used in conjunction with Tk_ConfigureInfo. It indicates that the configuration option should be validated before being returned. This is useful for options that have default values that are computed dynamically.
TK_CONFIG_MONOTONIC
This flag is used in conjunction with Tk_ConfigureWidget. It indicates that the configuration option should only be set if it has not already been set. This is useful for options that are only intended to be set once when the widget is created.
TK_CONFIG_USER_BIT
Reserved for use by the application programmer. Any value obtained by ORing this bit with other flags will be passed unmodified to the custom parsing and freeing procedures.
TK_CONFIG_ARRAY
This flag indicates that the option value is an array. The size of the array is specified by the defValueString field. The custom parsing procedure will be responsible for allocating and initializing the array.
TK_CONFIG_WRITABLE
This flag indicates that the option is writable. If this flag is not set, the option is read-only.
TK_CONFIG_SKIP_UNMATCHED
This flag is used in conjunction with Tk_ConfigureWidget. It indicates that if an option is not found in the configSpecs table, it should be skipped rather than generating an error. This is useful for implementing generic configuration commands.
TK_CONFIG_SPECIFIED
This flag indicates that the option has been specified in the arguments to Tk_ConfigureWidget. This is useful for determining which options have actually been changed.
TK_CONFIG_COLOR_INTERP
This flag indicates that the option value is a color string that should be parsed using Tk_AllocColor. The value will be stored as a Tk_Color structure.
TK_CONFIG_FONT_INTERP
This flag indicates that the option value is a font specification that should be parsed using Tk_AllocFont. The value will be stored as a Tk_Font structure.
TK_CONFIG_RELIEF_INTERP
This flag indicates that the option value is a relief style string that should be parsed using Tk_AllocRelief. The value will be stored as an integer representing the relief style.
TK_CONFIG_ANCHOR_INTERP
This flag indicates that the option value is an anchor style string that should be parsed using Tk_AllocAnchor. The value will be stored as an integer representing the anchor style.
TK_CONFIG_JUSTIFY_INTERP
This flag indicates that the option value is a justify style string that should be parsed using Tk_AllocJustify. The value will be stored as an integer representing the justify style.
TK_CONFIG_CAPSTYLE_INTERP
This flag indicates that the option value is a cap style string that should be parsed using Tk_AllocCapStyle. The value will be stored as an integer representing the cap style.
TK_CONFIG_JOINSTYLE_INTERP
This flag indicates that the option value is a join style string that should be parsed using Tk_AllocJoinStyle. The value will be stored as an integer representing the join style.
TK_CONFIG_BITMAP_INTERP
This flag indicates that the option value is a bitmap specification that should be parsed using Tk_AllocBitmap. The value will be stored as a Pixmap handle.
TK_CONFIG_CURSOR_INTERP
This flag indicates that the option value is a cursor specification that should be parsed using Tk_AllocCursor. The value will be stored as a Tk_Cursor structure.
TK_CONFIG_BORDER_INTERP
This flag indicates that the option value is a border specification that should be parsed using Tk_AllocBorder. The value will be stored as a Tk_Border structure.
TK_CONFIG_PIXELS_INTERP
This flag indicates that the option value is a screen distance in pixels that should be parsed using Tk_AllocPixels. The value will be stored as an integer representing the number of pixels.
TK_CONFIG_MM_INTERP
This flag indicates that the option value is a screen distance in millimeters that should be parsed using Tk_AllocMM. The value will be stored as an integer representing the number of millimeters.
TK_CONFIG_STRING_INTERP
This flag indicates that the option value is a string that should be parsed using Tcl_GetStringFromObj. The value will be stored as a string.
TK_CONFIG_INT_INTERP
This flag indicates that the option value is an integer that should be parsed using Tcl_GetIntFromObj. The value will be stored as an integer.
TK_CONFIG_DOUBLE_INTERP
This flag indicates that the option value is a double-precision floating-point number that should be parsed using Tcl_GetDoubleFromObj. The value will be stored as a double.
TK_CONFIG_BOOLEAN_INTERP
This flag indicates that the option value is a boolean that should be parsed using Tcl_GetBooleanFromObj. The value will be stored as an integer (0 or 1).
TK_CONFIG_UID_INTERP
This flag indicates that the option value is a unique identifier that should be parsed using Tcl_GetUIDFromObj. The value will be stored as a Tcl_Uid.
TK_CONFIG_CUSTOM
This flag indicates that the option value is of a custom type. The customPtr field of the Tk_ConfigSpec entry points to a Tk_CustomOption structure that describes how to parse and free the option value.

TK_OFFSET

Tk_OFFSET(type, field) is a macro that returns the offset in bytes of field within a structure of type type. This macro is used to specify the offset of an option's value within the widget record.

TK_CONFIGUREINFO

This function is used to retrieve information about the configuration of a Tk widget. It takes an interpreter, a Tk window, a configuration specification table, the number of entries in the table, and a Tcl object as arguments. The Tcl object can either be NULL (to retrieve all configuration information) or it can refer to a specific option name. The function returns a Tcl object containing the requested configuration information.

TK_CONFIGUREVALUE

This function is used to parse a single configuration option value. It takes an interpreter, a Tk window, a configuration specification table, the number of entries in the table, a Tcl object containing the option value, and a pointer to the widget record as arguments. The function parses the option value and stores it in the widget record. It returns TCL_OK if the value is parsed successfully, or TCL_ERROR if there is an error.

TK_FREEOPTIONS

This function is used to free any memory that was dynamically allocated by Tk_ConfigureWidget or Tk_SetOptions for the widget's configuration values. It takes a pointer to the widget record, the configuration specification table, the number of entries in the table, and a flags argument as arguments.

CUSTOM OPTION TYPES

Tk supports custom option types, which allow you to define your own option parsing and freeing procedures. To define a custom option type, you need to create a Tk_CustomOption structure that contains pointers to your parsing and freeing procedures. The parsing procedure (parseProc) takes a Tcl interpreter, a Tk window, a Tcl object containing the option value, and a pointer to the widget record as arguments. It should parse the option value and store it in the widget record. If the option value is stored in static memory, then freeProcPtr need not do anything with the freeProcPtr argument.

Once parseProc and printProc have been defined and a Tk_CustomOption structure has been created for them, options of this new type may be manipulated with Tk_ConfigSpec entries whose type fields are TK_CONFIG_CUSTOM and whose customPtr fields point to the Tk_CustomOption structure.

EXAMPLES

Although the explanation of Tk_ConfigureWidget is fairly complicated, its actual use is pretty straightforward. The easiest way to get started is to copy the code from an existing widget. The library implementation of frames (tkFrame.c) has a simple configuration table, and the library implementation of buttons (tkButton.c) has a much more complex table that uses many of the fancy specFlags mechanisms.
