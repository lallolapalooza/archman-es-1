NOMBRE

Tk_ParseArgv - procesar opciones de línea de comandos

SINOPSIS

#include <tk.h>

int
Tk_ParseArgv(interp, tkwin, argcPtr, argv, argTable, flags)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para devolver mensajes de error.
Tk_Window tkwin (entrada)
Ventana a usar cuando los argumentos especifican opciones de Tk. Si es NULL, entonces no se procesarán opciones de Tk.
int argcPtr (entrada/salida)
Puntero al número de argumentos en argv; se modifica para contener el número de argumentos no procesados que quedan después de la llamada.
const char **argv (entrada/salida)
Argumentos de la línea de comandos pasados al programa principal. Se modifica para contener los argumentos no procesados que quedan después de la llamada.
Tk_ArgvInfo *argTable (entrada)
Matriz de descriptores de argumentos, terminada por un elemento con el tipo TK_ARGV_END.
int flags (entrada)
Si no es cero, especifica una o más banderas que controlan el análisis de argumentos. Diferentes banderas pueden combinarse con OR. Las banderas definidas actualmente son TK_ARGV_DONT_SKIP_FIRST_ARG, TK_ARGV_NO_ABBREV, TK_ARGV_NO_LEFTOVERS y TK_ARGV_NO_DEFAULTS.

DESCRIPCIÓN

Tk_ParseArgv procesa una matriz de argumentos de línea de comandos de acuerdo con una tabla que describe los tipos de argumentos que se esperan. Cada uno de los argumentos en argv se procesa por turnos: si coincide con una de las entradas en argTable, el argumento se procesa de acuerdo con esa entrada y se descarta. Los argumentos que no coinciden con nada en argTable se copian al principio de argv (conservando su orden original) y se devuelven al llamador. Al final de la llamada, Tk_ParseArgv establece *argcPtr para contener el número de argumentos que quedan en argv, y argv[*argcPtr] contendrá el valor NULL. Normalmente, Tk_ParseArgv asume que argv[0] es un nombre de comando, por lo que se trata como un argumento que no coincide con argTable y se devuelve al llamador; sin embargo, si el bit TK_ARGV_DONT_SKIP_FIRST_ARG está activado en flags, entonces argv[0] se procesará de manera similar a los demás elementos de argv.

Tk_ParseArgv normalmente devuelve el valor TCL_OK. Si ocurre un error al analizar los argumentos, devuelve TCL_ERROR y Tk_ParseArgv dejará un mensaje de error en el resultado del intérprete interp en el estilo estándar de Tcl. En caso de un retorno de error, *argvPtr no habrá sido modificado, pero argv podría haber sido modificado parcialmente. Las posibles causas de errores se explican a continuación.

La matriz argTable especifica los tipos de argumentos que se esperan; cada una de sus entradas tiene la siguiente estructura:

typedef struct {
    const char *key;
    int type;
    char *src;
    char *dst;
    const char *help;
} Tk_ArgvInfo;
El campo key es una cadena como “-display” o “-bg” que se compara con los valores en argv. Type indica cómo procesar un argumento que coincide con key (más sobre esto a continuación). Src y dst son valores adicionales utilizados para procesar el argumento. Su uso exacto depende de type, pero típicamente src indica un valor y dst indica dónde almacenar el valor. Las declaraciones char * para src y dst son marcadores de posición: los tipos reales pueden ser diferentes. Finalmente, help es una cadena que proporciona una breve descripción de esta opción; esta cadena se imprime cuando los usuarios solicitan ayuda sobre las opciones de la línea de comandos.

Al procesar un argumento en argv, Tk_ParseArgv compara el argumento con cada una de las key en argTable. Tk_ParseArgv selecciona el primer especificador cuya key coincide exactamente con el argumento, si existe tal especificador. De lo contrario, Tk_ParseArgv selecciona un especificador para el cual el argumento es una abreviatura única. Si el argumento es una abreviatura única para más de un especificador, se devuelve un error. Si no hay una entrada coincidente en argTable, el argumento se omite y se devuelve al llamador.

Una vez encontrado un especificador de argumento coincidente, Tk_ParseArgv procesa el argumento de acuerdo con el campo type del especificador. El argumento que coincidió con key se llama “el argumento coincidente” en las descripciones siguientes. Como parte del procesamiento, Tk_ParseArgv puede usar también el siguiente argumento en argv después del argumento coincidente, que se llama “el argumento siguiente”. Los valores legales para type, y el procesamiento que causan, son los siguientes:

TK_ARGV_END
Marca el final de la tabla. La última entrada en argTable debe tener este tipo; todos sus otros campos se ignoran y nunca coincidirá con ningún argumento.
TK_ARGV_CONSTANT
Src se trata como un entero y dst se trata como un puntero a un entero. Src se almacena en *dst. El argumento coincidente se descarta.
TK_ARGV_INT
El siguiente argumento debe contener una cadena de enteros en el formato aceptado por strtol (por ejemplo, los prefijos “0” y “0x” pueden usarse para especificar números octales o hexadecimales, respectivamente). Dst se trata como un puntero a un entero; el siguiente argumento se convierte a un valor entero y se almacena en *dst. Src se ignora. Los argumentos coincidente y siguiente se descartan de argv.
TK_ARGV_FLOAT
El siguiente argumento debe contener un número de punto flotante en el formato aceptado por strtol. Dst se trata como la dirección de un valor de punto flotante de doble precisión; el siguiente argumento se convierte a un valor de doble precisión y se almacena en *dst. Los argumentos coincidente y siguiente se descartan de argv.
TK_ARGV_STRING
En esta forma, dst se trata como un puntero a un (char *); Tk_ParseArgv almacena en *dst un puntero al siguiente argumento, y descarta los argumentos coincidente y siguiente de argv. Src se ignora.
TK_ARGV_UID
Esta forma es similar a TK_ARGV_STRING, excepto que el argumento se convierte en un Tk_Uid llamando a Tk_GetUid. Dst se trata como un puntero a un Tk_Uid; Tk_ParseArgv almacena en *dst el Tk_Uid correspondiente al siguiente argumento, y descarta los argumentos coincidente y siguiente de argv. Src se ignora.
TK_ARGV_CONST_OPTION
Esta forma hace que se establezca una opción de Tk (como si se hubiera invocado el comando option). El campo src se trata como un puntero a una cadena que da el valor de una opción, y dst se trata como un puntero al nombre de la opción. El argumento coincidente se descarta. Si tkwin es NULL, entonces los especificadores de argumentos de este tipo se ignoran (como si no existieran).
TK_ARGV_OPTION_VALUE
Esta forma es similar a TK_ARGV_CONST_OPTION, excepto que el valor de la opción se toma del siguiente argumento en lugar de src. Dst se usa como el nombre de la opción. Src se ignora. Los argumentos coincidente y siguiente se descartan. Si tkwin es NULL, entonces los especificadores de argumentos de este tipo se ignoran (como si no existieran).
TK_ARGV_OPTION_NAME_VALUE
En este caso, el siguiente argumento se toma como el nombre de una opción de Tk y el argumento posterior se toma como el valor de esa opción. Tanto src como dst se ignoran. Los tres argumentos se descartan de argv. Si tkwin es NULL, entonces los especificadores de argumentos de este tipo se ignoran (como si no existieran).

Tk_ParseArgv(3) - Arch Linux

NAME

Tk_ParseArgv - parse command-line arguments

SYNOPSIS

#include <tk.h>

int
Tk_ParseArgv(interp, tkwin, argcPtr, argv, argTable, flags)
    Tcl_Interp *interp;
    Tk_Window tkwin;
    int *argcPtr;
    char **argv;
    Tk_ArgvInfo argTable[];
    int flags;

ARGUMENTS

TK_ARGV_HELP
This option is used to generate a help message. The dst field is treated as the address of a string containing the help message. The key field is not used. If this argument is encountered, then Tk_ParseArgv formats a message describing all of the valid arguments. The message is placed in interpreter interp's result and Tk_ParseArgv returns TCL_ERROR. When this happens, the caller normally prints the help message and aborts. If the key field of a TK_ARGV_HELP specifier is NULL, then the specifier will never match any arguments; in this case the specifier simply provides extra documentation, which will be included when some other TK_ARGV_HELP entry causes help information to be returned.
TK_ARGV_REST
This option is used by programs or commands that allow the last several of their options to be the name and/or options for some other program. If a TK_ARGV_REST argument is found, then Tk_ParseArgv does not process any of the remaining arguments; it returns them all at the beginning of argv (along with any other unprocessed arguments). In addition, Tk_ParseArgv treats dst as the address of an integer value, and stores at *dst the index of the first of the TK_ARGV_REST options in the returned argv. This allows the program to distinguish the TK_ARGV_REST options from other unprocessed options that preceded the TK_ARGV_REST.
TK_ARGV_FUNC
For this kind of argument, src is treated as the address of a procedure, which is invoked to process the following argument. The procedure should have the following structure:
int
func(dst, key, nextArg)
    char *dst;
    char *key;
    char *nextArg;
{
}
The dst and key parameters will contain the corresponding fields from the argTable entry, and nextArg will point to the following argument from argv (or NULL if there are not any more arguments left in argv). If func uses nextArg (so that Tk_ParseArgv should discard it), then it should return 1. Otherwise it should return 0 and TkParseArgv will process the following argument in the normal fashion. In either event the matching argument is discarded.
TK_ARGV_GENFUNC
This form provides a more general procedural escape. It treats src as the address of a procedure, and passes that procedure all of the remaining arguments. The procedure should have the following form:
int
genfunc(dst, interp, key, argc, argv)
    char *dst;
    Tcl_Interp *interp;
    char *key;
    int argc;
    char **argv;
{
}
The dst and key parameters will contain the corresponding fields from the argTable entry. Interp will be the same as the interp argument to Tcl_ParseArgv. Argc and argv refer to all of the options after the matching one. Genfunc should behave in a fashion similar to Tk_ParseArgv: parse as many of the remaining arguments as it can, then return any that are left by compacting them to the beginning of argv (starting at argv[0]). Genfunc should return a count of how many arguments are left in argv; Tk_ParseArgv will process them. If genfunc encounters an error then it should leave an error message in interpreter interp's result, in the usual Tcl fashion, and return -1; when this happens Tk_ParseArgv will abort its processing and return TCL_ERROR.

FLAGS

TK_ARGV_DONT_SKIP_FIRST_ARG
Tk_ParseArgv normally treats argv[0] as a program or command name, and returns it to the caller just as if it had not matched argTable. If this flag is given, then argv[0] is not given special treatment.
TK_ARGV_NO_ABBREV
Normally, Tk_ParseArgv accepts unique abbreviations for key values in argTable. If this flag is given then only exact matches will be acceptable.
TK_ARGV_NO_LEFTOVERS
Normally, Tk_ParseArgv returns unrecognized arguments to the caller. If this bit is set in flags then Tk_ParseArgv will return an error if it encounters any argument that does not match argTable. The only exception to this rule is argv[0], which will be returned to the caller with no errors as long as TK_ARGV_DONT_SKIP_FIRST_ARG is not specified.
TK_ARGV_NO_DEFAULTS
Normally, Tk_ParseArgv searches an internal table of standard argument specifiers in addition to argTable. If this bit is set in flags, then Tk_ParseArgv will use only argTable and not its default table.

EXAMPLE

Here is an example definition of an argTable and some sample command lines that use the options. Note the effect on argc and argv; arguments processed by Tk_ParseArgv are eliminated from argv, and argc is updated to reflect reduced number of arguments.

/*
 * Define and set default values for globals.
 */
int debugFlag = 0;
int numReps = 100;
char defaultFileName[] = "out";
char *fileName = defaultFileName;
Boolean exec = FALSE;
/*
 * Define option descriptions.
 */
Tk_ArgvInfo argTable[] = {
    {"-X", TK_ARGV_CONSTANT, (char *) 1, (char *) &debugFlag,
        "Turn on debugging printfs"},
    {"-N", TK_ARGV_INT, NULL, (char *) &numReps,
        "Number of repetitions"},
    {"-of", TK_ARGV_STRING, NULL, (char *) &fileName,
        "Name of file for output"},
    {"x", TK_ARGV_REST, NULL, (char *) &exec,
        "File to exec, followed by any arguments (must be last argument)."},
    {NULL, TK_ARGV_END, NULL, NULL,
        NULL}
};
main(argc, argv)
    int argc;
    char *argv[];
{
    ...
    if (Tk_ParseArgv(interp, tkwin, &argc, argv, argTable, 0) != TCL_OK) {
        fprintf(stderr, "%s\n", Tcl_GetString(Tcl_GetObjResult(interp)));
        exit(1);
    }
    /*
     * Remainder of the program.
     */
}

Note that default values can be assigned to variables named in argTable: the variables will only be overwritten if the particular arguments are present in argv. Here are some example command lines and their effects.

prog -N 200 infile        # just sets the numReps variable to 200
prog -of out200 infile    # sets fileName to reference "out200"
prog -XN 10 infile        # sets the debug flag, also sets numReps
In all of the above examples, argc will be set by Tk_ParseArgv to 2, argv[0] will be “prog”, argv[1] will be “infile”, and argv[2] will be NULL.
