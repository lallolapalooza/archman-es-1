NOMBRE

Tk::bindtags - Determinar qué enlaces se aplican a una ventana y el orden de evaluación

SINOPSIS

$widget->bindtags([listaEtiquetas]);

@etiquetas = $widget->bindtags;

DESCRIPCIÓN

Cuando se crea un enlace con el comando bind, se asocia con una ventana particular como $widget, un nombre de clase como Tk::Button, la palabra clave all, o cualquier otra cadena. Todas estas formas se denominan etiquetas de enlace. Cada ventana tiene una lista de etiquetas de enlace que determinan cómo se procesan los eventos para la ventana. Cuando ocurre un evento en una ventana, se aplica a cada una de las etiquetas de la ventana en orden: para cada etiqueta, se ejecuta el enlace más específico que coincida con la etiqueta y el evento dados. Consulte la documentación de Tk::bind para obtener más información sobre el proceso de coincidencia.

Por defecto, cada ventana tiene cuatro etiquetas de enlace que consisten en el nombre de la clase de la ventana, el nombre de la ventana, el nombre del antepasado de nivel superior más cercano de la ventana y all, en ese orden. Las ventanas de nivel superior solo tienen tres etiquetas por defecto, ya que el nombre de nivel superior es el mismo que el de la ventana.

Tenga en cuenta que este orden es *diferente* del orden utilizado por Tcl/Tk. Tcl/Tk tiene la ventana antes del nombre de la clase en el orden de enlace. Esto se debe a que Tcl es procedimental en lugar de orientada a objetos y la forma normal para que las aplicaciones Tcl/Tk anulen los enlaces de clase es con un enlace de instancia. Sin embargo, con perl/Tk, la forma normal de anular un enlace de clase es derivar una clase. El orden de perl/Tk hace que los enlaces de instancia se ejecuten después del enlace de clase, y por lo tanto, las devoluciones de llamada de enlace de instancia pueden utilizar cambios de estado (por ejemplo, cambios en la selección) que los enlaces de clase han realizado.

El comando bindtags permite leer y modificar las etiquetas de enlace de una ventana.

Si $widget->bindtags se invoca sin argumento, entonces el conjunto actual de etiquetas de enlace para $widget se devuelve como una lista. Si se especifica el argumento listaEtiquetas para bindtags, entonces debe ser una referencia a una matriz; las etiquetas para $widget se cambian a los elementos de la matriz. (Una referencia a una matriz anónima se puede crear encerrando los elementos entre corchetes [ ].) Los elementos de listaEtiquetas pueden ser cadenas arbitrarias u objetos de widget, si no existe una ventana para un objeto en el momento en que se procesa un evento, entonces la etiqueta se ignora para ese evento. El orden de los elementos en listaEtiquetas determina el orden en el que se ejecutan las devoluciones de llamada de enlace en respuesta a los eventos. Por ejemplo, el comando

$b->bindtags([$b,ref($b),$b->toplevel,'all'])

aplica el orden de enlace de Tcl/Tk, de modo que las devoluciones de llamada de enlace se evaluarán para un botón (por ejemplo) $b de modo que los enlaces de instancia de $b se invoquen primero, seguidos de los enlaces para la clase de $b, seguidos de los enlaces para el nivel superior de $b, seguidos de los enlaces 'all'.

Si listaEtiquetas es una lista vacía, es decir, [], entonces las etiquetas de enlace para $widget se devuelven al estado predeterminado de perl/Tk descrito anteriormente.

El comando bindtags se puede utilizar para introducir etiquetas de enlace adicionales arbitrarias para una ventana, o para eliminar etiquetas estándar. Por ejemplo, el comando

$b->bindtags(['TrickyButton',$b->toplevel,'all'])

reemplaza la etiqueta (por ejemplo) Tk::Button para $b con TrickyButton. Esto significa que los enlaces de widget predeterminados para los botones, que están asociados con la etiqueta Tk::Button, ya no se aplicarán a $b, pero se aplicarán los enlaces asociados con TrickyButton (quizás un nuevo comportamiento de botón).

ERRORES

La asignación actual del comportamiento 'nativo' de Tk de este método, es decir, devolver una lista pero solo aceptar una referencia a una matriz, es contraintuitiva. La interfaz de perl/Tk puede ser retocada, devolver una lista es sensato, por lo que la corrección más probable será permitir que se pase una lista para *establecer* los bindtags.
