NOMBRE

Tk_CreateOptionTable, Tk_DeleteOptionTable, Tk_InitOptions, Tk_SetOptions, Tk_FreeSavedOptions, Tk_RestoreSavedOptions, Tk_GetOptionValue, Tk_GetOptionInfo, Tk_FreeConfigOptions, Tk_Offset - procesar opciones de configuración

#include <tk.h>

Tk_FreeSavedOptions(savePtr)

Tk_RestoreSavedOptions(savePtr)

Tk_GetOptionValue(interp, recordPtr, optionTable, namePtr, tkwin)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Un intérprete de Tcl. La mayoría de los procedimientos usan esto solo para devolver mensajes de error; si es NULL, no se devuelven mensajes de error. Para Tk_CreateOptionTable el valor no puede ser NULL; da el intérprete en el que se usará la tabla de opciones.
const Tk_OptionSpec *templatePtr (entrada)
Punta a una matriz de información estática que describe las opciones de configuración que son compatibles. Se usa para construir una Tk_OptionTable. La información apuntada por este argumento debe existir durante la vida útil de la Tk_OptionTable.
Tk_OptionTable optionTable (entrada)
Token para una tabla de opciones. Debe haber sido devuelto por una llamada previa a Tk_CreateOptionTable.
char *recordPtr (entrada/salida)
Punta a la estructura en la que se almacenan los valores de las opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (entrada)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la que se usará la opción. Si optionTable no utiliza opciones dependientes de la ventana, se puede proporcionar un valor NULL para este argumento.
int objc (entrada)
Número de valores en objv.
Tcl_Obj *const *objv (entrada)
Argumentos de línea de comandos para establecer opciones de configuración.
Tk_SavedOptions *savePtr (salida)
Si no es NULL, la estructura apuntada por este argumento se rellena con los valores antiguos de cualquier opción que se haya modificado y los valores antiguos se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (salida)
Si no es NULL, la palabra apuntada por maskPtr se rellena con el OR a nivel de bits de los campos typeMask para las opciones que se modificaron.
Tk_SavedOptions *savedPtr (entrada/salida)
Punta a una estructura previamente rellenada por Tk_SetOptions con los valores antiguos de las opciones modificadas.
Tcl_Obj *namePtr (entrada)
El valor de este objeto es el nombre de una opción particular. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL cuando se llama a Tk_GetOptionValue.
nombre de tipo type (entrada)
El nombre del tipo de un registro.
nombre de campo field (entrada)
El nombre de un campo en registros de tipo type.

DESCRIPCIÓN

Estos procedimientos manejan la mayoría de los detalles de análisis de opciones de configuración, como las de los widgets Tk. Dada una descripción de las opciones compatibles, estos procedimientos se encargan de todos los detalles de análisis de opciones y almacenamiento de sus valores en una estructura C asociada con el widget u objeto. Los procedimientos se diseñaron principalmente para widgets en Tk, pero también se pueden usar para otros tipos de objetos que tienen opciones de configuración. En el resto de esta página del manual, se usará "widget" para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto puede no ser realmente un widget. El término "registro de widget" se usa para referirse a la estructura a nivel de C en la que se almacena la información sobre un widget u objeto particular.

Tenga en cuenta que la forma más fácil de aprender a usar estos procedimientos es observar un ejemplo funcional. En Tk, el ejemplo más sencillo es el código que implementa la familia de widgets de botones, que se encuentra en tkButton.c. Otros ejemplos se encuentran en tkSquare.c y tkMenu.c.

Para usar estos procedimientos, el código que implementa el widget debe contener una matriz estática de estructuras Tk_OptionSpec. Esta es una plantilla que describe las diversas opciones compatibles con esa clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor predeterminado y dónde se almacena el valor de la opción en el registro del widget. Consulte PLANTILLAS a continuación para obtener más detalles.

Para procesar las opciones de configuración de manera eficiente, la plantilla estática debe complementarse con información adicional que solo está disponible en tiempo de ejecución. El procedimiento Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token Tk_OptionTable que describe tanto la información estática como la dinámica. Todos los demás procedimientos, como Tk_SetOptions, toman un token Tk_OptionTable como argumento. Típicamente, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase particular y la Tk_OptionTable resultante se utiliza en el futuro para todos los widgets de esa clase. Una Tk_OptionTable solo se puede usar en un intérprete único, proporcionado por el argumento interp a Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, se debe llamar a Tk_DeleteOptionTable para liberar todos sus recursos. Todas las tablas de opciones para un intérprete Tcl se liberan automáticamente si se elimina el intérprete.

Tk_InitOptions se invoca cuando se crea un nuevo widget para establecer los valores predeterminados. A Tk_InitOptions se le pasa un token para una tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene información sobre este widget. Tk_InitOptions utiliza la información de la tabla de opciones para elegir un valor predeterminado apropiado para cada opción, luego almacena el valor predeterminado directamente en el registro del widget, sobrescribiendo cualquier información que ya estuviera presente en el registro del widget. Tk_InitOptions normalmente devuelve TCL_OK. Si ocurrió un error al establecer los valores predeterminados (por ejemplo, porque un valor predeterminado era erróneo), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite por completo, ver más abajo.

Tk_SetOptions se invoca para modificar las opciones de configuración basándose en la información especificada en un comando Tcl. El comando podría ser uno que crea un nuevo widget o un comando que modifica las opciones en un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, verifica que el nuevo valor de la opción se ajuste al tipo en optionTable y almacena el valor de la opción en el registro del widget dado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si ocurrió un error (como un nombre de opción desconocido o un valor de opción ilegal), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, entonces apunta a un valor entero que se rellena con información sobre las opciones que se modificaron. Para cada opción en la plantilla pasada a Tk_CreateOptionTable hay un campo typeMask. Los bits de este campo los define el código que implementa el widget; por ejemplo, cada bit podría corresponder a una opción de configuración particular. Alternativamente, los bits podrían usarse funcionalmente. Por ejemplo, un bit podría usarse para redibujar: todas las opciones que afectan la visualización del widget, de modo que cambiar la opción requiera que el widget se redibuje, podrían tener ese bit establecido. Otro bit podría indicar que la geometría del widget debe recalcularse, y así sucesivamente. Tk_SetOptions OR-ea conjuntamente los campos typeMask

OPTION TYPES

The following option types are supported:

TK_OPTION_BOOLEAN
The string value must be true or false (or abbreviations). The internal form is a C int value, 1 for true and 0 for false.
TK_OPTION_BITMAP
The value must be a standard bitmap name such as gray50 or @mybitmap.xbm. The internal form is a Tk_Bitmap token like the one returned by Tk_AllocBitmapFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions.
TK_OPTION_COLOR
The value must be a standard color name such as red or #ff8080. The internal form is a token (XColor *) like the ones returned by Tk_AllocColorFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.
TK_OPTION_CURSOR
The value must be a standard cursor name such as cross or @foo. The internal form is a Tk_Cursor token like the ones returned by Tk_AllocCursorFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and when the option is set the cursor for the window is changed by calling XDefineCursor. This option type also supports the TK_OPTION_NULL_OK flag.
TK_OPTION_CUSTOM
This option allows applications to define new option types. The clientData field of the entry points to a structure defining the new option type. See the section CUSTOM OPTION TYPES below for details.
TK_OPTION_DOUBLE
The string value must be a floating-point number in the format accepted by strtod. The internal form is a C double value. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to zero.
TK_OPTION_END
Marks the end of the template. There must be a Tk_OptionSpec structure with type TK_OPTION_END at the end of each template. If the clientData field of this structure is not NULL, then it points to an additional array of Tk_OptionSpec's, which is itself terminated by another TK_OPTION_END entry. Templates may be chained arbitrarily deeply. This feature allows common options to be shared by several widget classes.
TK_OPTION_FONT
The value must be a standard font name such as Times 16. The internal form is a Tk_Font handle like the ones returned by Tk_AllocFontFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.
TK_OPTION_INT
The string value must be an integer in the format accepted by strtol (e.g. 0 and 0x prefixes may be used to specify octal or hexadecimal numbers, respectively). The internal form is a C int value.
TK_OPTION_JUSTIFY
The value must be a standard justification value such as left. The internal form is a Tk_Justify like the values returned by Tk_GetJustifyFromObj.
TK_OPTION_PIXELS
The value must specify a screen distance such as 2i or 6.4. The internal form is an integer value giving a distance in pixels, like the values returned by Tk_GetPixelsFromObj. Note that if the objOffset field is not used, information about the original value of this option will be lost. See OBJOFFSET VS. INTERNALOFFSET below for details. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to INT_MIN.
TK_OPTION_RELIEF
The value must be standard relief such as raised. The internal form is an integer relief value such as TK_RELIEF_RAISED. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to TK_RELIEF_NULL.
TK_OPTION_STRING
The value may be any string. The internal form is a (char *) pointer that points to a dynamically allocated copy of the value. This option type supports the TK_OPTION_NULL_OK flag.
TK_OPTION_STRING_TABLE
For this type, clientData is a pointer to an array of strings suitable for passing to Tcl_GetIndexFromObj. The value must be one of the strings in the table, or a unique abbreviation of one of the strings. The internal form is an integer giving the index into the table of the matching string, like the return value from Tcl_GetStringFromObj. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to -1.
TK_OPTION_SYNONYM
This type is used to provide alternative names for an option (for example, -bg is often used as a synonym for -background). The clientData field is a string that gives the name of another option in the same table. Whenever the synonym option is used, the information from the other option will be used instead.
TK_OPTION_WINDOW
The value must be a window path name. The internal form is a Tk_Window token for the window. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions (in order to identify the application), and it supports the TK_OPTION_NULL_OK flag.

STORAGE MANAGEMENT ISSUES

If a field of a widget record has its offset stored in the objOffset or internalOffset field of a Tk_OptionSpec structure then the procedures described here will handle all of the storage allocation and resource management issues associated with the field. When the value of an option is changed, Tk_SetOptions (or Tk_FreeSavedOptions) will automatically free any resources associated with the old value, such as Tk_Fonts for TK_OPTION_FONT options or dynamically allocated memory for TK_OPTION_STRING options. For an option stored as an object using the objOffset field of a Tk_OptionSpec, the widget record shares the object pointed to by the objv value from the call to Tk_SetOptions. The reference count for this object is incremented when a pointer to it is stored in the widget record and decremented when the option is modified. When the widget is deleted Tk_FreeConfigOptions should be invoked; it will free the resources associated with all options and decrement reference counts for any objects.

However, the widget code is responsible for storing NULL or None in all pointer and token fields before invoking Tk_InitOptions. This is needed to allow proper cleanup in the rare case where an error occurs in Tk_InitOptions.

OBJOFFSET VS. INTERNALOFFSET

In most cases it is simplest to use the internalOffset field of a Tk_OptionSpec structure and not the objOffset field. This makes the internal form of the value immediately available to the widget code so the value does not have to be extracted from an object each time it is used. However, there are two cases where the objOffset field is useful. The first case is for TK_OPTION_PIXELS options. In this case, the internal form is an integer pixel value that is valid only for a particular screen. If the value of the option is retrieved, it will be returned as a simple number. For example, after the command .b configure -borderwidth 2m, the command .b configure -borderwidth might return 7, which is the integer pixel value corresponding to 2m. Unfortunately, this loses the original screen-independent value. Thus for TK_OPTION_PIXELS options it is better to use the objOffset field. In this case the original value of the option is retained in the object and can be returned when the option is retrieved. In most cases it is convenient to use the internalOffset field as well, so that the integer value is immediately available for use in the widget code (alternatively, Tk_GetPixelsFromObj can be used to extract the integer value from the object whenever it is needed). Note that the problem of losing information on retrievals exists only for TK_OPTION_PIXELS options.

The second reason to use the objOffset field is in order to implement new types of options not supported by these procedures. To implement a new type of option, you can use TK_OPTION_STRING as the type in the Tk_OptionSpec structure and set the objOffset field but not the internalOffset field. Then, after calling Tk_SetOptions, convert the object to internal form yourself.

Ttk widgets do not support the internalOffset machinery. Option values of Ttk widgets are always stored as (Tcl_Obj *), meaning that the objOffset field must be used.

CUSTOM OPTION TYPES

Applications can extend the built-in configuration types with additional configuration types by writing procedures to parse, print, free, and restore saved copies of the type and creating a structure pointing to those procedures:

typedef struct Tk_ObjCustomOption {
    const char *name;
    Tk_CustomOptionSetProc *setProc;
    Tk_CustomOptionGetProc *getProc;
    Tk_CustomOptionRestoreProc *restoreProc;
    Tk_CustomOptionFreeProc *freeProc;
    ClientData clientData;
} Tk_ObjCustomOption;
typedef int Tk_CustomOptionSetProc(
    ClientData clientData,
    Tcl_Interp *interp,
    Tk_Window tkwin,
    Tcl_Obj **valuePtr,
    char *recordPtr,
    int internalOffset,
    char *saveInternalPtr,
    int flags);
typedef Tcl_Obj *Tk_CustomOptionGetProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *recordPtr,
    int internalOffset);
typedef void Tk_CustomOptionRestoreProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr,
    char *saveInternalPtr);
typedef void Tk_CustomOptionFreeProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr);

The Tk_ObjCustomOption structure contains six fields: a name for the custom option type; pointers to the four procedures; and a clientData value to be passed to those procedures when they are invoked. The clientData va

lue apunta típicamente a una estructura que contiene información necesaria para los procedimientos al analizar e imprimir opciones. RestoreProc y freeProc pueden ser NULL, indicando que no se debe llamar a ninguna función para esas operaciones.

El procedimiento setProc es invocado por Tk_SetOptions para convertir un Tcl_Obj en una representación interna y almacenar el valor resultante en el registro del widget. Los argumentos son:

clientData
Una copia del campo clientData en la estructura Tk_ObjCustomOption.
interp
Un puntero a un intérprete Tcl, utilizado para reportar errores.
Tkwin
Una copia del argumento tkwin a Tk_SetOptions
valuePtr
Un puntero a una referencia a un Tcl_Obj que describe el nuevo valor para la opción; podría haber sido especificado explícitamente en la llamada a Tk_SetOptions o podría provenir de la base de datos de opciones o de un valor predeterminado. Si objOffset para la opción no es negativo (el valor de la opción se almacena como un (Tcl_Obj *) en el registro del widget), el puntero Tcl_Obj al que se hace referencia en valuePtr es el puntero que se almacenará en objOffset para la opción. SetProc puede modificar el valor si es necesario; por ejemplo, setProc puede cambiar el valor a NULL para admitir la bandera TK_OPTION_NULL_OK.
recordPtr
Un puntero al inicio del registro del widget a modificar.
internalOffset
Desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se colocará la representación interna del valor de la opción.
saveInternalPtr
Un puntero a un almacenamiento asignado en una estructura Tk_SavedOptions para la representación interna del valor original de la opción. Antes de establecer la opción a su nuevo valor, setProc debe establecer el valor al que se hace referencia en saveInternalPtr al valor original de la opción para admitir Tk_RestoreSavedOptions.
flags
Una copia del campo flags en la estructura Tk_OptionSpec para la opción

SetProc devuelve un resultado Tcl estándar: TCL_OK para indicar un procesamiento exitoso, o TCL_ERROR para indicar una falla de cualquier tipo. Se puede dejar un mensaje de error en el intérprete Tcl proporcionado por interp en caso de error.

El procedimiento getProc es invocado por Tk_GetOptionValue y Tk_GetOptionInfo para recuperar una representación Tcl_Obj de la representación interna de una opción. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. RecordPtr es un puntero al inicio del registro del widget a consultar. InternalOffset es el desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se almacena la representación interna del valor de la opción. GetProc debe devolver un puntero a un Tcl_Obj que represente el valor de la opción.

El procedimiento restoreProc es invocado por Tk_RestoreSavedOptions para restaurar una representación interna previamente guardada de un valor de opción personalizado. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. InternalPtr es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. SaveInternalPtr es un puntero al valor guardado. RestoreProc debe copiar el valor de saveInternalPtr a internalPtr para restaurar el valor. RestoreProc no necesita liberar ninguna memoria asociada con internalPtr o saveInternalPtr; se invocará freeProc para liberar esa memoria si es necesario. RestoreProc no tiene valor de retorno.

El procedimiento freeProc es invocado por Tk_SetOptions y Tk_FreeSavedOptions para liberar cualquier almacenamiento asignado para la representación interna de una opción personalizada. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. InternalPtr es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. El freeProc debe liberar cualquier almacenamiento asociado con la opción. FreeProc no tiene valor de retorno.
