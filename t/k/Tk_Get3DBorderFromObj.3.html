ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para reportar errores.
Tk_Window tkwin (entrada)
Token de la ventana (para todos los procedimientos excepto Tk_Get3DBorder, debe ser la ventana para la cual se asignó el borde).
Tcl_Obj *objPtr (entrada)
Puntero al valor cuya descripción de color corresponde al fondo (áreas planas). Los bordes iluminados serán más brillantes que este y los bordes sombreados serán más oscuros que este.
const char *colorName (entrada)
Igual que objPtr excepto que el valor se proporciona como una cadena en lugar de un valor.
Drawable drawable (entrada)
Token X de la ventana o mapa de bits; indica dónde se dibujarán los gráficos. Debe ser la ventana X para tkwin o un mapa de bits con la misma pantalla y profundidad que tkwin.
Tk_3DBorder border (entrada)
Token del borde previamente asignado en una llamada a Tk_Get3DBorder.
int x (entrada)
Coordenada X de la esquina superior izquierda del rectángulo que describe el borde o el bisel, en píxeles.
int y (entrada)
Coordenada Y de la esquina superior izquierda del rectángulo que describe el borde o el bisel, en píxeles.
int width (entrada)
Ancho del rectángulo que describe el borde o el bisel, en píxeles.
int height (entrada)
Alto del rectángulo que describe el borde o el bisel, en píxeles.
int borderWidth (entrada)
Ancho del borde en píxeles. Un valor positivo significa que el borde está dentro del rectángulo dado por x, y, width, height; un valor negativo significa que el borde está fuera del rectángulo.
int relief (entrada)
Indica la posición 3D del interior del valor en relación con el exterior; debe ser TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID, o TK_RELIEF_RIDGE (también puede ser TK_RELIEF_FLAT para Tk_Fill3DRectangle).
XPoint *pointPtr (entrada)
Puntero a una matriz de puntos que describe el conjunto de vértices de un polígono. El polígono no necesita estar cerrado (se cerrará automáticamente si no lo está).
int numPoints (entrada)
Número de puntos en *pointPtr.
int polyBorderWidth (entrada)
Ancho del borde en píxeles. Si es positivo, el borde se dibuja a la izquierda de la trayectoria dada por pointPtr; si es negativo, el borde se dibuja a la derecha de la trayectoria. Si leftRelief es TK_RELIEF_GROOVE o TK_RELIEF_RIDGE, el borde se centrará en la trayectoria.
int leftRelief (entrada)
Altura del lado izquierdo de la ruta del polígono en relación con el derecho. TK_RELIEF_RAISED significa que el lado izquierdo debe parecer más alto y TK_RELIEF_SUNKEN significa que el lado derecho debe parecer más alto; TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan lo obvio. Para Tk_Fill3DPolygon, también se puede especificar TK_RELIEF_FLAT para indicar ninguna diferencia en la altura.
int leftBevel (entrada)
Un valor distinto de cero significa que este bisel forma el lado izquierdo del valor; cero significa que forma el lado derecho.
int leftIn (entrada)
Un valor distinto de cero significa que el borde izquierdo del bisel horizontal se inclina hacia adentro, de modo que la parte inferior del borde está más a la derecha que la parte superior. Cero significa que el borde se inclina hacia afuera, de modo que la parte inferior está más a la izquierda que la parte superior.
int rightIn (entrada)
Un valor distinto de cero significa que el borde derecho del bisel horizontal se inclina hacia adentro, de modo que la parte inferior del borde está más a la izquierda que la parte superior. Cero significa que el borde se inclina hacia afuera, de modo que la parte inferior está más a la derecha que la parte superior.
int topBevel (entrada)
Un valor distinto de cero significa que este bisel forma el lado superior del valor; cero significa que forma el lado inferior.
int which (entrada)
Especifica cuál de los contextos gráficos del borde se desea. Debe ser TK_3D_FLAT_GC, TK_3D_LIGHT_GC, o TK_3D_DARK_GC.

DESCRIPCION

Estos procedimientos proporcionan facilidades para dibujar bordes de ventana de una manera que produce una apariencia tridimensional. Tk_Alloc3DBorderFromObj asigna colores y mapas de bits necesarios para dibujar un borde en la ventana proporcionada por el argumento tkwin. El valor de objPtr es un nombre de color estándar de Tk que determina los colores del borde. El color indicado por objPtr no se usará realmente en el borde; indica el color de fondo de la ventana (es decir, un color para superficies planas). Las porciones iluminadas del borde parecerán más brillantes que las indicadas por objPtr, y las porciones sombreadas del borde parecerán más oscuras que objPtr.

Tk_Alloc3DBorderFromObj devuelve un token que puede ser usado en llamadas posteriores a Tk_Draw3DRectangle. Si ocurre un error al asignar información para el borde (por ejemplo, se proporcionó un nombre de color inválido), se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp. Si se devuelve correctamente, Tk_Alloc3DBorderFromObj almacena en caché la información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a Tk_Alloc3DBorderFromObj con el mismo objPtr y tkwin.

Tk_Get3DBorder es idéntico a Tk_Alloc3DBorderFromObj excepto que el color se especifica con una cadena en lugar de un valor. Esto evita que Tk_Get3DBorder almacene en caché el valor de retorno, por lo que Tk_Get3DBorder es menos eficiente que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj devuelve el token de un borde existente, dado la ventana y el nombre del color utilizados para crear el borde. Tk_Get3DBorderFromObj no crea realmente el borde; ya debe haber sido creado con una llamada anterior a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_Get3DBorderFromObj con el mismo objPtr y tkwin.

Una vez creado un borde, se puede invocar Tk_Draw3DRectangle para dibujar el borde. El argumento tkwin especifica la ventana para la cual se asignó el borde, y drawable especifica una ventana o mapa de bits en el cual se dibujará el borde. Drawable no tiene que referirse a la misma ventana que tkwin, pero debe referirse a un mapa de bits o ventana compatible: uno asociado con la misma pantalla y con la misma profundidad que tkwin. Los argumentos x, y, width y height definen el cuadro delimitador de la región del borde dentro de drawable (normalmente x e y son cero y width y height son las dimensiones de la ventana), y borderWidth especifica el número de píxeles realmente ocupados por el borde. El argumento relief indica cuál de varios efectos tridimensionales se desea: TK_RELIEF_RAISED significa que el interior del rectángulo debe parecer elevado en relación con el exterior del rectángulo, y TK_RELIEF_SUNKEN significa que el interior debe parecer hundido. TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan que debe haber un surco o una cresta alrededor del exterior del rectángulo.

El procedimiento Tk_Draw3DPolygon puede usarse para dibujar formas más complejas con una apariencia tridimensional. Los argumentos pointPtr y numPoints definen una trayectoria, polyBorderWidth indica qué tan ancho debe ser el borde (y a qué lado de la trayectoria dibujarlo), y leftRelief indica qué lado de la trayectoria debe aparecer realzado. Tk_Draw3DPolygon dibuja un borde alrededor de la trayectoria dada usando los colores de border para producir una apariencia tridimensional. Si la trayectoria no se autointersectaa, la apariencia será una forma poligonal realzada o hundida. La trayectoria puede autointersectar, aunque no está claro qué tan útil es esto.

Tk_Fill3DPolygon es a Tk_Draw3DPolygon lo que Tk_Fill3DRectangle es a Tk_Draw3DRectangle: llena el área poligonal con el color de fondo de border, luego llama a Tk_Draw3DPolygon para dibujar un borde alrededor del área (a menos que leftRelief sea TK_RELIEF_FLAT; en este caso no se dibuja ningún borde).

Los procedimientos Tk_3DVerticalBevel y Tk_3DHorizontalBevel proporcionan primitivas de dibujo de menor nivel que se utilizan en procedimientos como Tk_Draw3DRectangle. Estos procedimientos también son útiles por sí mismos para dibujar formas de borde rectilíneas. Tk_3DVerticalBevel dibuja un borde biselado vertical, como el lado izquierdo o derecho de un rectángulo, y Tk_3DHorizontalBevel dibuja un borde biselado horizontal, como la parte superior o inferior de un rectángulo. Cada procedimiento toma argumentos x, y, width y height que describen el área rectangular del borde biselado (por ejemplo, width es el ancho del borde para Tk_3DVerticalBevel). Los argumentos leftBorder y topBorder indican la posición del borde en relación con el "interior" del valor, y relief indica el relieve del interior del valor en relación con el exterior. Tk_3DVerticalBevel solo dibuja una región rectangular. Tk_3DHorizontalBevel dibuja una región trapezoidal para generar esquinas en inglete; debe llamarse después de Tk_3DVerticalBevel (de lo contrario, Tk_3DVerticalBevel sobrescribirá el inglete en la esquina). Los argumentos leftIn y rightIn para Tk_3DHorizontalBevel describen el inglete en las esquinas; un valor de 1 significa que el borde inferior del trapecio será más corto que el superior, 0 significa que será más largo. Por ejemplo, para dibujar un borde rectangular, el bisel superior debe dibujarse con 1 para leftIn y rightIn, y el bisel inferior debe dibujarse con 0 para ambos argumentos.

El procedimiento Tk_SetBackgroundFromBorder modificará el píxel y/o pixmap de fondo de tkwin para producir un resultado compatible con border. Para pantallas en color, el fondo resultante será simplemente el color especificado cuando se creó border; para pantallas monocromáticas, el fondo resultante será un patrón de sombreado claro, para distinguir el fondo de la porción iluminada del borde.

Dado un token para un borde, el procedimiento Tk_NameOf3DBorder devolverá el nombre del color que se utilizó para crear el borde.

El procedimiento Tk_3DBorderColor devuelve la estructura XColor que se utilizará para las superficies planas dibujadas para su argumento border por procedimientos como Tk_Fill3DRectangle. El valor de retorno corresponde al nombre del color que se utilizó para crear el borde. La XColor, y su valor de píxel asociado, permanecerán asignadas mientras exista border.

El procedimiento Tk_3DBorderGC devuelve uno de los contextos gráficos X que se utilizan para dibujar el borde. El argumento which selecciona cuál de los tres GC's posibles: TK_3D_FLAT_GC devuelve el contexto utilizado para superficies planas, TK_3D_LIGHT_GC devuelve el contexto para sombras claras y TK_3D_DARK_GC devuelve el contexto para sombras oscuras.

Cuando un borde ya no es necesario, se debe llamar a Tk_Free3DBorderFromObj o Tk_Free3DBorder para liberar los recursos asociados con él. Para Tk_Free3DBorderFromObj, el borde a liberar se especifica con la ventana y el nombre del color utilizados para crear el borde; para Tk_Free3DBorder, el borde a liberar se especifica con el token Tk_3DBorder del borde. Debe haber exactamente una llamada a Tk_Free3DBorderFromObj o Tk_Free3DBorder por cada llamada a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder.
