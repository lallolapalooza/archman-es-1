TPMLIB_SetProfile(3)

TPMLIB_SetProfile(3) TPMLIB_SetProfile(3)

NOMBRE

TPMLIB_SetProfile - Establecer un perfil para un TPM 2

BIBLIOTECA

TPM library (libtpms, -ltpms)

SINOPSIS

#include <libtpms/tpm_types.h>

#include <libtpms/tpm_library.h>

#include <libtpms/tpm_error.h>

TPM_RESULT TPMLIB_SetProfile(const char *profile);

DESCRIPCIÓN

TPMLIB_SetProfile() se utiliza para aplicar uno de los perfiles proporcionados por libtpms a un TPM 2 cuando se inicia por primera vez. TPMLIB_SetProfile() debe llamarse después de TPMLIB_ChooseTPMVersion() y antes de TPMLIB_MainInit(). Un perfil solo se puede aplicar a un TPM 2 y siempre fallará para un TPM 1.2.

Una vez que se ha establecido un perfil, el TPM 2 lo utilizará a partir de entonces y el perfil se mantendrá junto con el estado del TPM 2 si el estado del TPM 2 se guardó utilizando la devolución de llamada registrada con TPMLIB_RegisterCallbacks(). Los intentos posteriores de establecer un perfil diferente para la misma instancia de TPM 2 utilizando esta llamada de API no tendrán ningún efecto.

Libtpms v0.10 y versiones posteriores admiten varios perfiles integrados. El perfil 'null' proporciona compatibilidad con versiones anteriores para libtpms v0.9 y solo habilita los algoritmos y comandos que estaban disponibles en esa versión de libtpms. El perfil predeterminado habilita todos los comandos y algoritmos disponibles actualmente. Ninguno de estos perfiles permite modificaciones por parte del usuario. El perfil 'custom' es el único que un usuario puede modificar y donde el usuario puede deshabilitar cualquier comando y/o algoritmo que se pueda deshabilitar.

Si se proporciona un puntero NULL como perfil, se utilizará el perfil 'null' y solo se habilitarán los comandos y algoritmos de libtpms v0.9. El estado de dicha instancia de TPM 2 será legible por la versión actual de libtpms, así como por versiones posteriores de libtpms, y permitirá la degradación de libtpms a la versión 0.9 desde una versión posterior.

Los perfiles con el prefijo 'default' habilitan tantos algoritmos y comandos como sea posible. El perfil 'default-v1', introducido con libtpms v0.10, permite ejecutar con libtpms v0.10 y versiones posteriores, pero no permitirá la degradación a versiones anteriores de libtpms, como v0.9.

Un perfil es un mapa JSON en formato de cadena. Debe contener el campo 'Name' con el nombre de un perfil conocido. Puede contener un campo 'Algorithms' que contiene una lista separada por comas de algoritmos (verbos) para habilitar o el campo 'Commands' que contiene una lista separada por comas de rangos de códigos de comando para habilitar.

Los siguientes son ejemplos de perfiles de TPM 2:

{"Name":"default-v1"}
{
 "Name":"custom",
 "Algorithms":"rsa,rsa-min-size=1024,tdes-min-size=128,hmac,aes,\
               aes-min-size=128,mgf1,keyedhash,xor,sha256,sha384,\
               sha512,null,rsassa,rsaes,rsapss,oaep,ecdsa,ecdh,ecdaa,\
               sm2,ecschnorr,ecmqv,kdf1-sp800-56a,kdf2,kdf1-sp800-108,\
               ecc,ecc-min-size=192,ecc-nist,ecc-nb,symcipher,camellia,\
               camellia-min-size=128,cmac,ctr,ofb,cbc,cfb,ecb",
 "StateFormatLevel":2
}

El primer perfil selecciona el perfil predeterminado actual junto con todos los comandos y algoritmos disponibles. El segundo perfil selecciona el perfil custom pero restringe el conjunto de algoritmos que el TPM 2 proporciona a los enumerados. Dado que 'sha1' y 'tdes' faltan en la lista, deshabilita esos algoritmos. Tenga en cuenta que el perfil custom es el único perfil que permite personalizaciones de Algoritmos, Comandos y Atributos habilitados (no se muestran aquí).

Solo un subconjunto de los algoritmos implementados puede ser deshabilitado. Para determinar la lista de algoritmos que se pueden deshabilitar, utilice la lista de algoritmos devuelta por TPMLIB_GetInfo(TPMLIB_INFO_RUNTIME_ALGORITHMS) en el campo 'CanBeDisabled'. De manera similar, solo un subconjunto de los comandos implementados puede ser deshabilitado y TPMLIB_GetInfo(TPMLIB_INFO_RUNTIME_COMMANDS) se puede usar para determinar la lista de comandos 'CanBeDisabled'. Por defecto, no se habilita ningún atributo, por lo que todos pueden ser deshabilitados. Para ver qué atributos están implementados y se pueden habilitar, use TPMLIB_GetInfo(TPMLIB_INFO_RUNTIME_ATTRIBUTES).

Dado que es posible deshabilitar algoritmos que son obligatorios para el TPM 2 de cliente PC, se puede crear una instancia de TPM 2 que provoque fallos en las aplicaciones. Por lo tanto, es necesario seleccionar cuidadosamente qué algoritmos deshabilitar siguiendo los requisitos de las aplicaciones que se utilizarán. Al mismo tiempo, la elección de los comandos habilitados es importante para que los algoritmos habilitados puedan usarse con el conjunto de comandos habilitados y que las aplicaciones no fallen inesperadamente debido a comandos deshabilitados. Por lo tanto, determinar la lista de algoritmos y comandos para habilitar y deshabilitar se deja al usuario.

StateFormatLevel

El campo StateFormatLevel existe en cada perfil transportado por el estado de un TPM 2. El StateFormatLevel es un entero que se incrementa cada vez que se habilitan nuevos comandos o algoritmos de TPM 2 para los perfiles. El efecto de este parámetro es que un perfil con StateFormatLevel 'n' no será aceptado por una versión de libtpms que no implemente al menos StateFormatLevel 'n'. Esto evita que las aplicaciones que puedan haber utilizado algoritmos o comandos recién habilitados fallen porque intentan usarlos nuevamente con un TPM 2 de una versión de libtpms que no los admite.

Cuando lo anterior se aplica a un entorno de máquina virtual, esto significa que la migración del estado de un TPM 2 solo es posible a una versión de libtpms que implemente al menos el mismo StateFormatLevel. Por lo tanto, se debe tener cuidado al elegir qué perfil se selecciona para que el StateFormatLevel del perfil no se convierta en un obstáculo para migrar el estado del TPM entre diferentes versiones de libtpms. Esto, a su vez, significa que en un entorno donde existen versiones anteriores de libtpms, que pueden ser un objetivo para la migración, se debe elegir el perfil compatible con la versión más antigua de libtpms. Si existe libtpms v0.9, este debería ser el perfil 'null', para libtpms v0.10, este puede ser el perfil 'default-v1'.

La siguiente lista describe el significado de los StateFormatLevel:

1: (desde v0.10)
Este StateFormatLevel está reservado para el perfil null. Solo se habilitan los algoritmos y comandos compatibles con libtpms v0.9. Para mantener la compatibilidad con el formato de estado de libtpms v0.9, el perfil null no se escribirá como parte del estado.
2: (desde v0.10)
Este StateFormatLevel habilitó la escritura del perfil como parte del estado.
3: (desde v0.10)
Este StateFormatLevel habilitó los comandos TPM 2 ECC_Encrypt (0x199) y ECC_Decrypt (0x19a).
4: (desde v0.10)
Este StateFormatLevel:
  • habilitó Camellia-192 y AES-192.
  • habilitó el establecimiento del indicador de atributo de sesión interno del TPM 2 isNameHashDefined que se agregó; puede cambiar ligeramente el comportamiento de las sesiones cuando, por ejemplo, son utilizadas por el perfil default-v1 en comparación con el perfil null (libtpms v0.9).
5: (desde v0.10)
Este StateFormatLevel habilitó los comandos TPM 2 PolicyCapability (0x19b) y PolicyParameters (0x19c).
6: (desde v0.10)
Este StateFormatLevel realizó algunos cambios internos en el código de serialización y deserialización de un OBJECT. Solo los OBJECT de clave RSA tienen el campo de exponente privado serializado y el campo de jerarquía ahora también se serializa siempre. Los OBJECT de clave RSA pueden ser 4 bytes más grandes, mientras que otros son más pequeños ahora.
7: (desde v0.10)
Este StateFormatLevel habilitó los siguientes atributos del perfil:
  • no-unpadded-encryption
  • no-sha1-signing
  • no-sha1-verification
  • no-sha1-hmac-creation
  • no-sha1-hmac-verification
  • no-sha1-hmac
  • fips-host
  • drbg-continous-test
  • pct
  • no-ecc-key-derivation

Un usuario puede especificar el StateFormatLevel al usar el perfil custom. En este caso, el StateFormatLevel dado sirve como el StateFormatLevel máximo que los algoritmos y comandos dados pueden requerir (por ejemplo, '2' no permitiría habilitar el comando ECC_Encrypt, que requiere '3') o permite habilitar tamaños de clave, como AES-192, cuando por ejemplo se proporciona StateFormatLevel '4'. Si se proporciona StateFormatLevel '3', entonces AES-192 no se habilitará.

Atributos

Un perfil puede tener la clave Attributes, que es similar a Algorithms o Commands. La siguiente es una lista de verbos soportados:

no-unpadded-encryption: (desde v0.10)
•
Evita el cifrado y descifrado RSA sin relleno (raw)
no-sha1-signing: (desde v0.10)
•
Evita la generación de firmas con algoritmos SHA1 con RSA y ECC
no-sha1-verification: (desde v0.10)
•
Evita la verificación de firmas con un resumen SHA1 con algoritmos RSA y ECC
no-sha1-hmac-creation: (desde v0.10)
•
Evita la creación de un HMAC usando SHA1
no-sha1-hmac-verification: (desde v0.10)
•
Evita la verificación de un HMAC usando SHA1
no-sha1-hmac: (desde v0.10)
•
Evita la creación y verificación de un HMAC usando SHA1
fips-host: (desde v0.10)
  • Evita el cifrado y descifrado RSA sin relleno (raw)
  • Evita la generación de firmas con SHA1 con algoritmos RSA y ECC
  • Evita la verificación de firmas con un resumen SHA1 con algoritmos RSA y ECC

Al agregar este verbo a Attributes, un TPM 2 puede ejecutarse en un host con FIPS habilitado donde la biblioteca criptográfica OpenSSL puede restringir algoritmos criptográficos como se muestra arriba (referencia a RHEL 9.4+, pero varía según la distribución). Tenga en cuenta que el uso de este verbo no hace que una instancia de TPM 2 cumpla con FIPS-140. Consulte también la sección sobre 'Modo FIPS en el host'.

drbg-continous-test: (desde v0.10)
•
Activa pruebas continuas del DRBG
pct: (desde v0.10)
•
Activa la prueba de consistencia por pares (pct) para claves RSA y claves de firma EC
no-ecc-key-derivation: (desde v0.10)
•
Evita la derivación de claves ECC

Modo FIPS en el host

Si el modo FIPS está habilitado en un host (referencia a RHEL 9.4+) entonces la biblioteca criptográfica OpenSSL no podrá usar ciertos algoritmos. En este caso, la siguiente lista de verbos debe omitirse de un perfil para evitar fallos en las autocomprobaciones o tener que deshabilitar el modo FIPS en la instancia de OpenSSL.

  • camellia, camellia-min-size
  • tdes, tdes-min-size
  • rsaes
  • ecc-nist-p192
  • ecc-bn, ecc-bn-p256, ecc-bn-p638
  • ecc-sm2-p256

Un perfil debe contener los siguientes verbos para tamaños mínimos de clave:

  • rsa-min-size=2048
  • ecc-min-size=224

ERRORES

TPM_SUCCESS
La función se completó correctamente.
TPM_FAIL
Ocurrió un error. Esto puede deberse a un perfil JSON mal formado, a un campo faltante en el perfil JSON, a un verbo desconocido en el perfil JSON o a un error de falta de memoria. El archivo de registro puede mostrar la razón del error.

A un TPM 1.2 no se le puede aplicar un perfil y siempre responderá con este código de error.

Para obtener una lista completa de los códigos de error de TPM, consulte el archivo de inclusión libtpms/tpm_error.h

EJEMPLO

#include <stdio.h>
#include <libtpms/tpm_types.h>
#include <libtpms/tpm_library.h>
#include <libtpms/tpm_error.h>
int main(void) {
    TPM_RESULT res;
    unsigned char *respbuffer = NULL;
    uint32_t resp_size = 0;
    uint32_t respbufsize = 0;
    unsigned char *command;
    uint32_t command_size;
    [...]
    if (TPMLIB_ChooseTPMVersion(TPMLIB_TPM_VERSION_2) != TPM_SUCCESS) {
        fprintf(stderr, "No se pudo elegir un TPM 2.\n");
        return 1;
    }
    if (TPMLIB_SetProfile(NULL) != TPM_SUCCESS) {
        fprintf(stderr, "No se pudo establecer el perfil.\n");
        return 1;
    }
    if (TPMLIB_MainInit() != TPM_SUCCESS) {
        fprintf(stderr, "No se pudo iniciar el TPM.\n");
        return 1;
    }
    [...]
    /* construir comando TPM */
    [...]
    res = TPMLIB_Process(&respbuffer, &resp_size,
                         &respbufsize,
                         command, command_size);
    [...]
    TPMLIB_Terminate();
    return 0;
}
