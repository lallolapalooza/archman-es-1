TPMLIB_RegisterCallbacks(3)

Paquete: libtpms

Licencias: BSD-3-Clause

TPMLIB_RegisterCallbacks(3) TPMLIB_RegisterCallbacks(3)

NOMBRE

TPMLIB_RegisterCallbacks - Registrar callbacks para implementar comportamiento personalizado de ciertas funciones

BIBLIOTECA

Biblioteca TPM (libtpms, -ltpms)

SINOPSIS

#include <libtpms/tpm_types.h>

#include <libtpms/tpm_library.h>

#include <libtpms/tpm_error.h>

TPM_RESULT TPMLIB_RegisterCallbacks(struct tpmlibrary_callbacks *);

DESCRIPCIÓN

La función TPMLIB_RegisterCallbacks() permite registrar varias funciones de callback con libtpms que permiten a un usuario implementar comportamiento personalizado de varias funciones internas de la biblioteca. Esta característica se usaría típicamente si el comportamiento de las funciones internas proporcionadas no es el necesario. Un ejemplo sería que libtpms escribe todos los datos en archivos con ciertos nombres. Si, sin embargo, los datos necesitan ser escritos en un tipo especial de almacenamiento, el usuario registrará callbacks con la biblioteca que se invocarán cuando el TPM necesite escribir, leer o eliminar datos del almacenamiento y el usuario podrá implementar comportamiento personalizado en estas funciones.

Lo siguiente muestra la estructura de datos utilizada para registrar los callbacks.

struct libtpms_callbacks {  
        int sizeOfStruct;
        TPM_RESULT (*tpm_nvram_init)(void);
        TPM_RESULT (*tpm_nvram_loaddata)(unsigned char **data,
                                         uint32_t *length,
                                         uint32_t tpm_number,
                                         const char *name);
        TPM_RESULT (*tpm_nvram_storedata)(const unsigned char *data,
                                          uint32_t length,
                                          uint32_t tpm_number,
                                          const char *name);
        TPM_RESULT (*tpm_nvram_deletename)(uint32_t tpm_number,
                                           const char *name,
                                           TPM_BOOL mustExist);
        TPM_RESULT (*tpm_io_init)(void);
        TPM_RESULT (*tpm_io_getlocality)(TPM_MODIFIER_INDICATOR *localityModifer,
                                         uint32_t tpm_number);
        TPM_RESULT (*tpm_io_getphysicalpresence)(TPM_BOOL *physicalPresence,
                                                 uint32_t tpm_number);
};

Actualmente se admiten 7 callbacks. Si un puntero de callback en la estructura anterior se establece en NULL, se utilizará la implementación interna predeterminada de la biblioteca de esa función.

Si se establece uno de los callbacks en el grupo tpm_nvram o tpm_io, entonces todos los callbacks del grupo respectivo deben ser implementados.

tpm_nvram_init
Esta función se llama antes de que se realice cualquier acceso al almacenamiento persistente. Permite al usuario inicializar el acceso al almacenamiento persistente.

Al éxito, esta función debe devolver TPM_SUCCESS, un código de error en caso contrario.

La implementación predeterminada requiere que la variable de entorno TPM_PATH esté configurada y apunte a un directorio donde se pueda escribir el estado del TPM. Si la variable no está configurada, devolverá TPM_FAIL y la inicialización del TPM en TPMLIB_MainInit() fallará.

tpm_nvram_loaddata
Esta función se llama cuando el TPM quiere cargar el estado desde el almacenamiento persistente. La función implementadora debe asignar un buffer (data) y devolverlo al TPM junto con la longitud del buffer (length). El tpm_number es siempre 0 y puede ignorarse. El parámetro name es TPM_SAVESTATE_NAME, TPM_VOLATILESTATE_NAME o TPM_PERMANENT_ALL_NAME e indica cuál de los 3 tipos de estado se debe cargar.

Al éxito, esta función debe devolver TPM_SUCCESS, un código de error en caso contrario.

La implementación predeterminada escribe el estado del TPM en archivos en un directorio al que apuntaba la variable de entorno TPM_PATH cuando se ejecutó TPMLIB_MainInit(). El fallo al escribir el estado del TPM en archivos pondrá al TPM en modo de fallo.

Si esta función no está configurada (NULL), se leerá el archivo NVChip original al usar un TPM 2. Este archivo contiene el volcado de memoria de las estructuras de datos internas y no es portable entre endiannesses ni arquitecturas de diferentes tamaños (32 bits, 64 bits), ni permitirá manejar extensiones de esas estructuras de datos internas que contiene a través de adiciones en el código del TPM 2. En el peor de los casos, esto puede resultar en errores de acceso a memoria por parte de funciones internas y provocar bloqueos. Por lo tanto, se recomienda configurar esta función y manejar la escritura del estado del TPM.

tpm_nvram_storedata
Esta función se llama cuando el TPM quiere almacenar el estado en el almacenamiento persistente. Los parámetros data y length proporcionan los datos a almacenar y el número de bytes. La función implementadora no debe liberar el buffer data. El tpm_number es siempre 0 y puede ignorarse. El parámetro name es TPM_SAVESTATE_NAME, TPM_VOLATILESTATE_NAME o TPM_PERMANENT_ALL_NAME e indica cuál de los 3 tipos de estado se debe almacenar.

Al éxito, esta función debe devolver TPM_SUCCESS, un código de error en caso contrario.

La implementación predeterminada lee el estado del TPM desde archivos en un directorio al que apuntaba la variable de entorno TPM_PATH cuando se ejecutó TPMLIB_MainInit(). El fallo al leer el estado del TPM desde archivos puede poner al TPM en modo de fallo.

Si esta función no está configurada (NULL), el volcado de memoria se escribirá en el archivo NVChip (TPM 2) y se aplican los mismos comentarios que cuando la función de interfaz tpm_nvram_loaddata no está configurada.

tpm_nvram_deletename
Esta función se llama cuando el TPM quiere eliminar el estado en el almacenamiento persistente. El tpm_number es siempre 0 y puede ignorarse. El parámetro name es TPM_SAVESTATE_NAME, TPM_VOLATILESTATE_NAME o TPM_PERMANENT_ALL_NAME e indica cuál de los 3 tipos de estado se debe eliminar. El parámetro mustExist indica si los datos proporcionados deben existir y la función implementadora debe devolver TPM_FAIL si los datos no existían.

Al éxito, esta función debe devolver TPM_SUCCESS, un código de error en caso contrario.

La implementación predeterminada elimina los archivos de estado del TPM en un directorio al que apuntaba la variable de entorno TPM_PATH cuando se ejecutó TPMLIB_MainInit(). El fallo al eliminar los archivos de estado del TPM puede poner al TPM en modo de fallo.

tpm_io_init
Esta función se llama para inicializar el subsistema de E/S del TPM.

Al éxito, esta función debe devolver TPM_SUCCESS, un código de error en caso contrario.

La implementación predeterminada simplemente devuelve TPM_SUCCESS.

tpm_io_getlocality
Esta función se llama cuando el TPM necesita determinar la localidad bajo la cual se debe ejecutar un comando. La función implementadora debe devolver el número de la localidad escribiéndolo en el puntero localityModifier.

Se espera que esta función devuelva TPM_SUCCESS junto con un número de localidad válido. El programa que implementa la función llamada se considera confiable para gestionar los números de localidad correctamente.

La implementación predeterminada devuelve 0 como la localidad.

tpm_io_getphysicalpresence
Esta función se llama cuando el TPM necesita determinar si la presencia física ha sido afirmada. La función implementadora debe escribir TRUE o FALSE en el puntero physicalPresence.

Al éxito, esta función debe devolver TPM_SUCCESS, un código de error en caso contrario.

La implementación predeterminada devuelve FALSE para la presencia física.

VALOR DE RETORNO

La función TPMLIB_RegisterCallbacks() siempre devuelve TPM_SUCCESS.

TPMLIB_MainInit(3) — libtpms — Arch Linux

NAME

TPMLIB_MainInit - Initialize the TPM library

LIBRARY

libtpms - TPM library (libtpms)

SYNOPSIS

TPM_RESULT TPMLIB_MainInit(void);

DESCRIPTION

TPMLIB_MainInit() initializes the TPM library. It should be called before any other TPM library function. After calling this function, the TPM is ready to receive commands.

The function initializes the TPM state, allocates memory, and sets up the necessary internal structures. It also initializes the callbacks that were registered using TPMLIB_RegisterCallbacks(3).

TPMLIB_MainInit() must be called after TPMLIB_RegisterCallbacks(3) and before TPMLIB_Process(3) or TPMLIB_Terminate(3).

RETURN VALUE

Upon successful completion, TPMLIB_MainInit() returns TPM_SUCCESS, an error value otherwise.

ERRORS

TPM_SUCCESS
The function completed successfully.
TPM_FAIL
General failure.

For a complete list of TPM error codes please consult the include file libtpms/tpm_error.h

EXAMPLE

#include <libtpms/tpm_types.h>
#include <libtpms/tpm_library.h>
#include <libtpms/tpm_error.h>
static TPM_MODIFIER_INDICATOR locality;
static TPM_RESULT mytpm_io_init(void)
{
       return TPM_SUCCESS;
}
static TPM_RESULT mytpm_io_getlocality(TPM_MODIFIER_INDICATOR *locModif,
                                       uint32_t tpm_number)
{
       *locModif = locality;
       return TPM_SUCCESS:
}
static TPM_RESULT mytpm_io_getphysicalpresence(TPM_BOOL *physicalPresence,
                                               uint32_t tpm_number)
{
       *physicalPresence = FALSE;
       return TPM_SUCCESS;
}
int main(void) {
    TPM_RESULT res;
    unsigned char *respbuffer;
    uint32_t resp_size;
    uint32_t respbufsize;
    unsigned char *command;
    uint32_t command_size;
    struct libtpms_callbacks cbs = {
        .sizeOfStruct               = sizeof(struct libtpms_callbacks),
        .tpm_nvram_init             = NULL,
        .tpm_nvram_loaddata         = NULL,
        .tpm_nvram_storedata        = NULL,
        .tpm_nvram_deletename       = NULL,
        .tpm_io_init                = mytpm_io_init,
        .tpm_io_getlocality         = mytpm_io_getlocality,
        .tpm_io_getphysicalpresence = mytpm_io_getphysicalpresence,
    };
    [...]
    if (TPMLIB_RegisterCallbacks(&cbs) != TPM_SUCCESS) {
        fprintf(stderr, "Could not register the callbacks.\n");
        return 1;
    }
    if (TPMLIB_MainInit()) != TPM_SUCCESS) {
        fprintf(stderr, "Could not start the TPM.\n");
        return 1;
    }
    [...]
    /* build TPM command */
    [...]
    res = TPMLIB_Process(&respbuffer, &resp_size,
                         &respbufsize,
                         command, command_size);
    [...]
    TPMLIB_Terminate();
    return 0;
}
