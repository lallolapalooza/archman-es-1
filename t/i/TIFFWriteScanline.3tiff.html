NOMBRE

TIFFWriteScanline - escribe una línea de escaneo en un archivo TIFF abierto

SINOPSIS

#include <tiffio.h>
int TIFFWriteScanline(TIFF *tif, tdata_t buf, uint32_t row, tsample_t sample)

DESCRIPCIÓN

Escribe datos en un archivo en la fila especificada. El parámetro sample se utiliza solo si los datos están organizados en planos separados (PlanarConfiguration = 2). Se asume que los datos no están comprimidos y están en el orden de bits y bytes nativo de la máquina anfitriona. Los datos escritos en el archivo se comprimen de acuerdo con el esquema de compresión del directorio TIFF actual (ver más abajo). Si la línea de escaneo actual está más allá del final del subarchivo actual, el campo ImageLength se incrementa automáticamente para incluir la línea de escaneo (excepto para PlanarConfiguration = 2, donde ImageLength no puede cambiarse una vez que se escriben los primeros datos). Si se incrementa ImageLength, los campos StripOffsets y StripByteCounts se amplían de manera similar para reflejar los datos escritos más allá del final anterior de la imagen.

NOTAS

La biblioteca escribe datos codificados utilizando el orden de bytes nativo de la máquina. Se espera que los lectores TIFF implementados correctamente realicen cualquier cambio de orden de bytes necesario para procesar correctamente los datos de imagen con BitsPerSample mayor que 8. La biblioteca intenta ocultar las diferencias de orden de bits entre la imagen y la máquina nativa convirtiendo los datos del orden nativo de la máquina.

En C++, el parámetro sample por defecto es 0.

Una vez que se escriben datos en un archivo para el directorio actual, es posible que los valores de ciertas etiquetas no se puedan alterar; consulte TIFFSetField() para obtener más información.

No es posible escribir líneas de escaneo en un archivo que utiliza una organización de teselas (tiles). La rutina TIFFIsTiled() se puede utilizar para determinar si el archivo está organizado como teselas o tiras.

VALORES DE RETORNO

TIFFWriteScanline() devuelve -1 si detecta un error inmediatamente y 1 si la escritura es exitosa.

DIAGNÓSTICOS

Todos los mensajes de error se dirigen a la rutina TIFFErrorExtR().

%s: File not open for writing:

El archivo se abrió para lectura, no para escritura.

"Can not write scanlines to a tiled image":

Se intentó escribir líneas de escaneo en una imagen con teselas. Se asume que la imagen está organizada en teselas porque las etiquetas TileWidth y TileLength se establecieron con TIFFSetField().

"Compression algorithm does not support random access":

Se escribieron datos en un orden no secuencial en un archivo que utiliza un algoritmo de compresión y que tiene RowsPerStrip mayor que uno. Es decir, los datos de la imagen se almacenarán en forma comprimida, y con varias filas empaquetadas en una tira. En este caso, la biblioteca no soporta el acceso aleatorio a los datos. Los datos deben escribirse como tiras completas, secuencialmente por filas, o el valor de RowsPerStrip debe establecerse en uno.

%s: Must set "ImageWidth" before writing data:

El ancho de la imagen no se estableció antes de la primera escritura. Consulte TIFFSetField() para obtener información sobre cómo hacerlo.

%s: Must set "PlanarConfiguration" before writing data:

La organización de los datos no se definió antes de la primera escritura. Consulte TIFFSetField() para obtener información sobre cómo hacerlo.

Can not change "ImageLength" when using separate planes:

Se están utilizando planos de imagen separados (PlanarConfiguration = 2), pero el número de filas no se especificó antes de la primera escritura. La biblioteca soporta el crecimiento dinámico de una imagen solo cuando los datos están organizados de forma contigua (PlanarConfiguration = 1).

"%d: Sample out of range, max %d":

El parámetro sample fue mayor que el valor de la etiqueta SamplesPerPixel.

%s: No space for strip arrays:

No había suficiente espacio para los arreglos que contienen los desplazamientos de las tiras y los recuentos de bytes.

ERRORES

La escritura de datos YCbCR submuestreados no funciona correctamente porque, para PlanarConfiguration = 2, el tamaño de una línea de escaneo no se calcula por muestra, y para PlanarConfiguration = 1, la biblioteca no empaqueta las muestras intercaladas en bloques.
