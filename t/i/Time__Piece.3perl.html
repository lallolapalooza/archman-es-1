Time::Piece(3perl) Perl Programmers Reference Guide Time::Piece(3perl)

NOMBRE

Time::Piece - Objetos de tiempo orientados a objetos

SINOPSIS

use Time::Piece;

my $t = localtime;
print "La hora es $t\n";
print "El año es ", $t->year, "\n";

DESCRIPCIÓN

Este módulo reemplaza las funciones estándar "localtime" y "gmtime" con implementaciones que devuelven objetos. Lo hace de manera compatible con versiones anteriores, de modo que usar localtime/gmtime de la manera documentada en perlfunc aún devolverá lo que esperas.

El módulo implementa en realidad la mayor parte de una interfaz descrita por Larry Wall en la lista de correo perl5-porters aquí: https://www.nntp.perl.org/group/perl.perl5.porters/2000/01/msg5283.html

USO

Después de importar este módulo, cuando uses localtime o gmtime en un contexto escalar, en lugar de obtener una cadena escalar ordinaria que represente la fecha y hora, obtienes un objeto Time::Piece, cuya estratificación produce el mismo efecto que las funciones localtime y gmtime. También se proporciona un constructor new(), que es el mismo que localtime(), excepto cuando se le pasa un objeto Time::Piece, en cuyo caso es un constructor de copia. Los siguientes métodos están disponibles en el objeto:

$t->sec                 # también disponible como $t->second
$t->min                 # también disponible como $t->minute
$t->hour                # formato de 24 horas
$t->mday                # también disponible como $t->day_of_month
$t->mon                 # 1 = Enero
$t->_mon                # 0 = Enero
$t->monname             # Feb
$t->month               # igual que $t->monname
$t->fullmonth           # Febrero
$t->year                # basado en 0 (el año 0 d.C. es, por supuesto, 1 a.C.)
$t->_year               # año menos 1900
$t->yy                  # año de 2 dígitos
$t->wday                # 1 = Domingo
$t->_wday               # 0 = Domingo
$t->day_of_week         # 0 = Domingo
$t->wdayname            # Mar
$t->day                 # igual que wdayname
$t->fullday             # Martes
$t->yday                # también disponible como $t->day_of_year, 0 = 01 Ene
$t->isdst               # también disponible como $t->daylight_savings
$t->hms                 # 12:34:56
$t->hms(".")            # 12.34.56
$t->time                # igual que $t->hms
$t->ymd                 # 2000-02-29
$t->date                # igual que $t->ymd
$t->mdy                 # 29-02-2000
$t->mdy("/")            # 29/02/2000
$t->dmy                 # 29-02-2000
$t->dmy(".")            # 29.02.2000
$t->datetime            # 2000-02-29T12:34:56 (ISO 8601)
$t->cdate               # Mar 29 Feb 12:34:56 2000
"$t"                    # igual que $t->cdate
$t->epoch               # segundos desde la época
$t->tzoffset            # desplazamiento de zona horaria en un objeto Time::Seconds
$t->julian_day          # número de días desde el inicio del período juliano
$t->mjd                 # fecha juliana modificada (días JD-2400000.5)
$t->week                # número de semana (ISO 8601)
$t->is_leap_year        # verdadero si es un año bisiesto
$t->month_last_day      # 28-31
$t->time_separator($s)  # establece el separador predeterminado (predeterminado ":")
$t->date_separator($s)  # establece el separador predeterminado (predeterminado "-")
$t->day_list(@dias)     # establece los días de la semana predeterminados
$t->mon_list(@meses)     # establece los meses predeterminados
$t->strftime(FORMAT)    # igual que POSIX::strftime (sin la sobrecarga
                        # de la extensión POSIX completa)
$t->strftime()          # "Mar, 29 Feb 2000 12:34:56 GMT"

Time::Piece->strptime(STRING, FORMAT)
                        # ver la página man de strptime. Crea un nuevo
                        # objeto Time::Piece

Nótese que "localtime" y "gmtime" no están listados arriba. Si se llaman como métodos en un objeto Time::Piece, actúan como constructores, devolviendo un nuevo objeto Time::Piece para la hora actual. En otras palabras: no son útiles como métodos.

Local Localizaciones

Tanto wdayname (día) como monname (mes) permiten pasar una lista para usar como índice para el nombre de los días. Esto puede ser útil si necesitas implementar alguna forma de localización sin instalar o usar realmente localizaciones. Nótese que esta es una anulación global y afectará a todas las instancias de Time::Piece.

my @days = qw( Domingo Lunes Martes Miércoles Jueves Viernes Sábado );
my $dia_frances = localtime->day(@days);

Estos ajustes también se pueden anular globalmente:

Time::Piece::day_list(@days);

O para meses:

Time::Piece::mon_list(@meses);

O localmente para meses:

print localtime->month(@meses);

O para poblar con la llamada de tu localización del sistema actual:
Time::Piece->use_locale();

Cálculos de Fechas

Es posible usar adición y sustracción simple de objetos:

use Time::Seconds;

my $segundos = $t1 - $t2;
$t1 += ONE_DAY; # añade 1 día (constante de Time::Seconds)

Lo siguiente es válido ($t1 y $t2 son objetos Time::Piece):

$t1 - $t2; # devuelve un objeto Time::Seconds
$t1 - 42; # devuelve un objeto Time::Piece
$t1 + 533; # devuelve un objeto Time::Piece

Sin embargo, sumar un objeto Time::Piece a otro objeto Time::Piece causará un error en tiempo de ejecución.

Nótese que el primero de los anteriores devuelve un objeto Time::Seconds, así que mientras que examinar el objeto imprimirá el número de segundos (debido a la sobrecarga), también puedes obtener el número de minutos, horas, días, semanas y años en ese delta, usando la API de Time::Seconds.

Además de añadir segundos, hay dos APIs para añadir meses y años:

$t = $t->add_months(6);
$t = $t->add_years(5);

Los meses y años pueden ser negativos para sustracciones. Nótese que hay un comportamiento "extraño" al sumar y restar meses al final de los meses. Generalmente, cuando el mes resultante es más corto que el mes de inicio, se añaden los días de solapamiento. Por ejemplo, restar un mes del 2008-03-31 no resultará en 2008-02-31 ya que esta es una fecha imposible. En su lugar, obtendrás 2008-03-02. Esto parece ser consistente con otras herramientas de manipulación de fechas.

Truncamiento

Llamar al método "truncate" devuelve una copia del objeto pero con la hora truncada al inicio de la unidad suministrada.

$t = $t->truncate(to => 'day');

Este ejemplo establecerá la hora a medianoche en la misma fecha que $t tenía previamente. Los valores permitidos para el parámetro "to" son: "year", "quarter", "month", "day", "hour", "minute" y "second".

Comparaciones de Fechas

Las comparaciones de fechas también son posibles, usando el conjunto completo de "<", ">", "<=", ">=", "<=>", "==" y "!=".

Análisis de Fechas

Time::Piece tiene una función incorporada strptime() (de FreeBSD), que te permite unas rutinas de análisis de fechas increíblemente flexibles. Por ejemplo:

my $t = Time::Piece->strptime("Domingo 3 Nov, 1943",
                              "%A %drd %b, %Y");

print $t->strftime("%a, %d %b %Y");

Muestra:

Mié, 03 Nov 1943

(¿ves?, es lo suficientemente inteligente como para corregir mi obvio error de fecha)

Para más información consulta "man strptime", que debería estar en todos los sistemas unix.

O mira aquí: http://www.unix.com/man-page/FreeBSD/3/strftime/

ADVERTENCIA %A, %a, %B, %b, y amigos

Time::Piece::strptime por defecto solo puede analizar nombres de fechas en inglés americano. Mientras tanto, Time::Piece->strftime() devolverá nombres de fechas que utilizan la localización del sistema configurada actualmente. Esto significa que las fechas devueltas por strf

Time::Piece(3perl) - Arch Linux MANPAGE

NAME

Time::Piece - Time and date handling

SYNOPSIS

    use Time::Piece;
    use Time::Seconds;

    my $now = localtime;

    print $now->ymd;          # 2001-02-17
    print $now->mdy;          # 02/17/01
    print $now->dmy;          # 17/02/01
    print $now->hms;          # 16:14:30
    print $now->tz;           # EST

    print $now->strftime("%Y-%m-%d %H:%M:%S %Z"); # 2001-02-17 16:14:30 EST

    my $past = $now - (3 * ONE_DAY);
    print $past->perf;        # 2001-02-14 16:14:30 EST

    my $future = $now + ONE_HOUR;
    print $future->epoch, "\n"; # 982437270

    my $str = "2001-02-14 10:00:00";
    my $time = Time::Piece->strptime($str, "%Y-%m-%d %H:%M:%S");

    # Global overrides for strptime()
    # use Time::Piece ':locale';
    # use Time::Piece ':override';

DESCRIPTION

Time::Piece is a module that provides a convenient object oriented interface to the Perl built-in time functions time, gmtime and localtime.

It is intended as a simpler, more intuitive alternative to the standard Time::gmtime and Time::localtime modules, and should be useful for most common date and time manipulation tasks.

The core of the module is the Time::Piece object, which is returned by the built-in localtime and gmtime functions when use Time::Piece; is in effect.

The module provides a number of methods for accessing different parts of the date and time, and for formatting them into strings.

USAGE

Constructor

Time::Piece objects are normally created by calling the built-in localtime or gmtime functions after loading the module:

    use Time::Piece;
    my $now = localtime;
    my $gm  = gmtime;

You can also create a Time::Piece object from epoch seconds:

    my $t = Time::Piece->new(time());

Or parse a string using strptime:

    my $t = Time::Piece->strptime("14 Feb 2001", "%d %b %Y");
    my $t = Time::Piece->strptime("2001-02-14 10:00:00 EST", "%Y-%m-%d %H:%M:%S %Z");

Note that strptime may not be able to parse time correctly if the locale is not the C locale. For example, if you are using a German locale, month names like 'Feb' may not be recognised. You can force strptime to use the C locale by setting $ENV{LC_TIME} = $ENV{LC_ALL} = 'C'; before calling strptime.

Accessors

The following methods provide access to the components of a Time::Piece object:

year
The year (e.g., 2001).
month
The month (1-12).
day
The day of the month (1-31).
hour
The hour (0-23).
minute
The minute (0-59).
second
The second (0-61, allowing for leap seconds).
wday
The day of the week (0=Sunday, 6=Saturday).
yday
The day of the year (1-366).
is_dst
A boolean indicating whether Daylight Saving Time is in effect.
epoch
The number of seconds since the epoch (Jan 1, 1970, 00:00:00 UTC). This is equivalent to the value returned by time().
tzname
The name of the timezone (e.g., "EST", "EDT"). This may be empty if the timezone is unknown.

Formatting Methods

These methods return formatted strings. They are shortcuts for using strftime.

ymd
Returns the date in YYYY-MM-DD format.
mdy
Returns the date in MM/DD/YY format.
dmy
Returns the date in DD/MM/YY format.
hms
Returns the time in HH:MM:SS format (24-hour clock).
ymdhms
Returns the date and time in YYYY-MM-DD HH:MM:SS format.
mon day
Returns the month name and day number (e.g., "Feb 17").
dow
Returns the abbreviated day name (e.g., "Sat").
month_name
Returns the full month name (e.g., "February").
day_name
Returns the full day name (e.g., "Saturday").
tz
Returns the timezone name (e.g., "EST").
perf
Returns the date and time in a format suitable for filenames, similar to the output of the C strftime function with the %Y-%m-%d_%H:%M:%S_%Z format.

All formatting methods accept an optional argument, which is the separator character to use. The default is usually a hyphen or a space.

    print $now->ymd('/'); # 2001/02/17
    print $now->hms(':'); # 16:14:30

The strftime method allows for complete control over the output format, using the standard strftime format codes:

    print $now->strftime("%A, %d %B %Y %I:%M:%S %p %Z");
    # Saturday, 17 February 2001 04:14:30 PM EST

String Conversion

When a Time::Piece object is used in a string context, it defaults to the ymdhms format.

    my $t = Time::Piece->strptime("2001-02-14 10:00:00", "%Y-%m-%d %H:%M:%S");
    my $s = "$t"; # $s is now "2001-02-14 10:00:00"

Time Arithmetic

Time::Piece objects can be added to and subtracted from each other, and from objects in the Time::Seconds module.

    use Time::Seconds;

    my $now = localtime;
    my $yesterday = $now - ONE_DAY;
    my $tomorrow = $now + ONE_DAY;
    my $diff = $tomorrow - $yesterday; # $diff is ONE_DAY

Note that arithmetic operations always result in a new Time::Piece object representing local time. The timezone information is preserved where possible.

Locale Support

By default, strptime uses the C locale for parsing day and month names. This means it will only recognize English names (e.g., "Jan", "Feb", "Sunday", "Monday").

The time might not be able to be parsed by strptime. This is the default behavior and can be overridden by calling Time::Piece->use_locale(). This builds a list of the current locale's day and month names which strptime will use to parse with. Note this is a global override and will affect all Time::Piece instances.

For instance with a German locale:

localtime->day_list();

Returns

('Sun', 'Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat')

While:

Time::Piece->use_locale();
localtime->day_list();

Returns

('So', 'Mo', 'Di', 'Mi', 'Do', 'Fr', 'Sa')

YYYY-MM-DDThh:mm:ss

The ISO 8601 standard defines the date format to be YYYY-MM-DD, and the time format to be hh:mm:ss (24 hour clock), and if combined, they should be concatenated with date first and with a capital 'T' in front of the time.

Week Number

The week number may be an unknown concept to some readers. The ISO 8601 standard defines that weeks begin on a Monday and week 1 of the year is the week that includes both January 4th and the first Thursday of the year. In other words, if the first Monday of January is the 2nd, 3rd, or 4th, the preceding days of the January are part of the last week of the preceding year. Week numbers range from 1 to 53.

Global Overriding

Finally, it's possible to override localtime and gmtime everywhere, by including the ':override' tag in the import list:

use Time::Piece ':override';

CAVEATS

Setting $ENV{TZ} in Threads on Win32

Note that when using perl in the default build configuration on Win32 (specifically, when perl is built with PERL_IMPLICIT_SYS), each perl interpreter maintains its own copy of the environment and only the main interpreter will update the process environment seen by strftime.

Therefore, if you make changes to $ENV{TZ} from inside a thread other than the main thread then those changes will not be seen by strftime if you subsequently call that with the %Z formatting code. You must change $ENV{TZ} in the main thread to have the desired effect in this case (and you must also call _tzset() in the main thread to register the environment change).

Furthermore, remember that this caveat also applies to fork(), which is emulated by threads on Win32.

Use of epoch seconds

This module internally uses the epoch seconds system that is provided via the perl time() function and supported by gmtime() and localtime().

If your perl does not support times larger than "2^31" seconds then this module is likely to fail at processing dates beyond the year 2038. There are moves afoot to fix that in perl. Alternatively use 64 bit perl. Or if none of those are options, use the DateTime module which has support for years well into the future and past.

Also, the internal representation of Time::Piece->strftime deviates from the standard POSIX implementation in that is uses the epoch (instead of separate year, month, day parts). This change was added in version 1.30. If you must have a more traditional strftime (which will normally never calculate day light saving times correctly), you can pass the date parts from Time::Piece into the strftime function provided by the POSIX module (see strftime in POSIX ).
