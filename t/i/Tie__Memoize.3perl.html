Tie::Memoize(3perl) Guía de programación para Perl Tie::Memoize(3perl)

NOMBRE

Tie::Memoize - añadir datos a un hash cuando sea necesario

SINOPSIS

require Tie::Memoize;
tie %hash, 'Tie::Memoize',
    \&fetch,                  # El resto es opcional
    $DATA, \&exists,
    {%ini_value}, {%ini_existence};

DESCRIPCIÓN

Este paquete permite que un hash enlazado cargue automáticamente sus valores en el primer acceso y utilice el valor almacenado en caché en los accesos posteriores.

Solo los accesos de lectura (a través de la obtención del valor o la comprobación de "exists") resultan en llamadas a las funciones; los accesos de modificación se realizan como en un hash normal.

Los argumentos requeridos durante "tie" son el hash, el paquete y la referencia a la función "FETCH". Los argumentos opcionales son un escalar arbitrario $data, la referencia a la función "EXISTS" y los valores iniciales del hash y de la caché de existencia.

Tanto las funciones "FETCH" como "EXISTS" tienen la misma firma: los argumentos son "$key, $data"; $data es el mismo valor que se pasó como argumento durante tie(). Ambas funciones deben devolver una lista vacía si el valor no existe. Si la función "EXISTS" es diferente de la función "FETCH", debe devolver un valor VERDADERO en caso de éxito. La función "FETCH" debe devolver el valor deseado si la clave es válida.

Herencia de Tie::Memoize

La estructura de los datos tied() es una referencia a un array con los elementos:

0:  caché de valores conocidos
1:  caché de la existencia conocida de claves
2:  función FETCH
3:  función EXISTS
4:  $data

El resto es para uso interno de este paquete. En particular, si se sobrescribe TIEHASH, debería llamar a SUPER::TIEHASH.

EJEMPLO

sub slurp {
  my ($key, $dir) = shift;
  open my $h, '<', "$dir/$key" or return;
  local $/; <$h>                      # leerlo todo
}
sub exists { my ($key, $dir) = shift; return -f "$dir/$key" }
tie %hash, 'Tie::Memoize', \&slurp, $directory, \&exists,
    { fake_file1 => $content1, fake_file2 => $content2 },
    { pretend_does_not_exists => 0, known_to_exist => 1 };

Este ejemplo trata el contenido ligeramente modificado de $directory como un hash. Las modificaciones son que las claves fake_file1 y fake_file2 obtienen los valores $content1 y $content2, y pretend_does_not_exists nunca se accederá. Además, la existencia de known_to_exist nunca se comprobará (por lo que si no existe cuando se necesita su contenido, el usuario de %hash puede confundirse).

ERRORES

Los métodos FIRSTKEY y NEXTKEY recorren las claves que ya se han leído, no todas las posibles claves del hash.
