Tie::File(3perl) Perl Programadores Guía de Referencia Tie::File(3perl)

NOMBRE

Tie::File - Acceder a las líneas de un archivo en disco a través de un array de Perl

SINOPSIS

use Tie::File;
tie @array, 'Tie::File', nombre_archivo or die ...;
$array[0] = 'blah';      # la primera línea del archivo es ahora 'blah'
                           # (la numeración de líneas empieza en 0)
print $array[42];        # muestra la línea 43 del archivo
$n_recs = @array;        # cuántos registros hay en el archivo?
$#array -= 2;            # trunca dos registros del final
for (@array) {
  s/PERL/Perl/g;        # Reemplaza PERL con Perl en todo el archivo
}
# Estas son como push, pop, unshift, shift y splice normales
# Excepto que modifican el archivo como esperarías
push @array, nuevos_regs...;
my $r1 = pop @array;
unshift @array, nuevos_regs...;
my $r2 = shift @array;
@old_recs = splice @array, 3, 7, nuevos_regs...;
untie @array;            # todo terminado

DESCRIPCIÓN

"Tie::File" representa un archivo de texto regular como un array de Perl. Cada elemento en el array corresponde a un registro en el archivo. La primera línea del archivo es el elemento 0 del array; la segunda línea es el elemento 1, y así sucesivamente.

El archivo *no* se carga en memoria, por lo que esto funcionará incluso para archivos gigantescos.

Los cambios en el array se reflejan inmediatamente en el archivo.

Los perezosos y los principiantes pueden dejar de leer el manual ahora.

"unicode"

Puedes leer un archivo unicode (UTF-8) proporcionando un manejador de archivo abierto con la codificación deseada. No es seguro escribir en uno porque la longitud en bytes y en caracteres a menudo es diferente, Tie::File calculará incorrectamente la longitud de las escrituras, sobrescribiendo partes de otros registros.

"recsep"

¿Qué es un 'registro'? Por defecto, el significado es el mismo que para el operador "<...>": es una cadena terminada por $/, que probablemente sea "\n". (Pequeña excepción: en sistemas DOS y Win32, un 'registro' es una cadena terminada por "\r\n".) Puedes cambiar la definición de "registro" proporcionando la opción "recsep" en la llamada "tie":

tie @array, 'Tie::File', $archivo, recsep => 'es';

Esto dice que los registros están delimitados por la cadena "es". Si el archivo contuviera los siguientes datos:

Curse these pesky flies!\n

entonces el @array parecería tener cuatro elementos:

"Curse th"
"e p"
"ky fli"
"es!\n"

Un valor indefinido no está permitido como separador de registros. La semántica especial de "modo párrafo" de Perl (como en "$/ = """) no se emula.

Los registros leídos del array enlazado no tienen la cadena separadora de registro al final; esto es para permitir

$array[17] .= "extra";

que funcione como se espera.

(Ver "autochomp", más abajo.) Los registros almacenados en el array tendrán la cadena separadora de registro añadida antes de escribirse en el archivo, si no tienen una ya. Por ejemplo, si la cadena separadora de registro es "\n", entonces las dos siguientes líneas hacen exactamente lo mismo:

$array[17] = "Pastel de cereza";
$array[17] = "Pastel de cereza\n";

El resultado es que el contenido de la línea 17 del archivo se reemplazará con "Pastel de cereza"; un carácter de nueva línea separará la línea 17 de la línea 18. Esto significa que este código no hará nada:

chomp $array[17];

Porque al valor "chomp"e se le volverá a adjuntar el separador cuando se escriba de nuevo en el archivo. No hay forma de crear un archivo al que le falte la cadena separadora de registro final.

Insertar registros que *contienen* la cadena separadora de registro no está soportado por este módulo. Probablemente producirá un resultado razonable, pero cuál será ese resultado puede cambiar en una futura versión. Usa 'splice' para insertar registros o para reemplazar un registro con varios.

"autochomp"

Normalmente, a los elementos del array se les quita el separador de registro, de modo que si el archivo contiene el texto

Oro
Incienso
Mirra

el array enlazado parecerá contener "("Oro", "Incienso", "Mirra")". Si estableces "autochomp" a un valor falso, el separador de registro no se eliminará. Si el archivo anterior se enlazó con

tie @gifts, "Tie::File", $gifts, autochomp => 0;

entonces el array @gifts parecerá contener "("Oro\n", "Incienso\n", "Mirra\n")", o (en sistemas Win32) "("Oro\r\n", "Incienso\r\n", "Mirra\r\n")".

"mode"

Normalmente, el archivo especificado se abrirá para acceso de lectura y escritura, y se creará si no existe. (Es decir, las banderas "O_RDWR | O_CREAT" se proporcionan en la llamada "open".) Si deseas cambiar esto, puedes proporcionar banderas alternativas en la opción "mode". Ver Fcntl para una lista de banderas disponibles. Por ejemplo:

# abrir el archivo si existe, pero fallar si no existe
use Fcntl 'O_RDWR';
tie @array, 'Tie::File', $archivo, mode => O_RDWR;
# crear el archivo si no existe
use Fcntl 'O_RDWR', 'O_CREAT';
tie @array, 'Tie::File', $archivo, mode => O_RDWR | O_CREAT;
# abrir un archivo existente en modo de solo lectura
use Fcntl 'O_RDONLY';
tie @array, 'Tie::File', $archivo, mode => O_RDONLY;

Abrir el archivo de datos en modo de solo escritura o de añadir no está soportado.

"memory"

Este es un límite superior en la cantidad de memoria que "Tie::File" consumirá en cualquier momento mientras gestiona el archivo. Esto se usa para dos cosas: gestionar la *caché de lectura* y gestionar el *búfer de escritura diferida*.

Los registros leídos del archivo se almacenan en caché, para evitar tener que volver a leerlos repetidamente. Si lees el mismo registro dos veces, la primera vez se almacenará en memoria y la segunda vez se obtendrá de la *caché de lectura*. La cantidad de datos en la caché de lectura no excederá el valor que especificaste para "memory". Si "Tie::File" quiere almacenar en caché un nuevo registro, pero la caché de lectura está llena, creará espacio expirando los registros menos visitados recientemente de la caché de lectura.

El límite de memoria por defecto es 2MIB. Puedes ajustar el tamaño máximo de la caché de lectura proporcionando la opción "memory". El argumento es el tamaño de caché deseado, en bytes.

# Tengo mucha memoria, así que uso una caché grande para acelerar el acceso
tie @array, 'Tie::File', $archivo, memory => 20_000_000;

Establecer el límite de memoria a 0 inhibirá el almacenamiento en caché; los registros se obtendrán del disco cada vez que los examines.

El valor de "memory" no es un límite absoluto o exacto de la memoria utilizada. Los objetos de "Tie::File" contienen algunas estructuras además de la caché de lectura y el búfer de escritura diferida, cuyos tamaños no se cargan contra "memory".

La caché en sí consume aproximadamente 310 bytes por registro en caché, por lo que si tu archivo tiene muchos registros cortos, es posible que desees disminuir el límite de memoria de la caché, o de lo contrario, la sobrecarga de la caché podría exceder el tamaño de los datos almacenados en caché.

DEFERRED WRITING

By default, when you modify an element of a "Tie::File" array, the change is written to the file immediately. This is usually the safest and most predictable behavior. However, it can be slow, especially if you are modifying many elements in rapid succession, since each modification requires a system call to write to the file.

To improve performance, you can enable deferred writing. When deferred writing is enabled, modifications to the array elements are not written to the file immediately. Instead, they are stored in memory in a cache. When the cache is full, or when a non-deferred operation is performed, the contents of the cache are written to the file.

You can enable deferred writing by passing the "defer => 1" option when you tie the array, or by calling the "defer()" method on the tied array object:

(tied @a)->defer(1);

or

tie @array, 'Tie::File', $file, defer => 1;

When deferred writing is enabled, the following operations cannot be deferred:

  • "push"
  • "pop"
  • "shift"
  • "unshift"
  • "splice"

When you perform one of these operations, any deferred data is written to the file and the operation is performed immediately. This may change in a future version.

If you resize the array with deferred writing enabled, the file will be resized immediately, but deferred records will not be written. This has a surprising consequence: "@a = (...)" erases the file immediately, but the writing of the actual data is deferred. This might be a bug. If it is a bug, it will be fixed in a future version.

Autodeferring

"Tie::File" tries to guess when deferred writing might be helpful, and to turn it on and off automatically.

for (@a) {
  $_ = "> $_";
}

In this example, only the first two assignments will be done immediately; after this, all the changes to the file will be deferred up to the user-specified memory limit.

You should usually be able to ignore this and just use the module without thinking about deferring. However, special applications may require fine control over which writes are deferred, or may require that all writes be immediate. To disable the autodeferment feature, use

(tied @o)->autodefer(0);

or

tie @array, 'Tie::File', $file, autodefer => 0;

Similarly, "->autodefer(1)" re-enables autodeferment, and "->autodefer()" recovers the current value of the autodefer setting.

CONCURRENT ACCESS TO FILES

Caching and deferred writing are inappropriate if you want the same file to be accessed simultaneously from more than one process. Other optimizations performed internally by this module are also incompatible with concurrent access. A future version of this module will support a "concurrent => 1" option that enables safe concurrent access.

Previous versions of this documentation suggested using "memory => 0" for safe concurrent access. This was mistaken. Tie::File will not support safe concurrent access before version 0.96.

CAVEATS

(That's Latin for 'warnings'.)

  • Reasonable effort was made to make this module efficient. Nevertheless, changing the size of a record in the middle of a large file will always be fairly slow, because everything after the new record must be moved.
  • The behavior of tied arrays is not precisely the same as for regular arrays. For example: 
    # This DOES print "How unusual!"
undef $a[10];  print "How unusual!\n" if defined $a[10];

    "undef"-ing a "Tie::File" array element just blanks out the corresponding record in the file. When you read it back again, you'll get the empty string, so the supposedly-"undef"'ed value will be defined. Similarly, if you have "autochomp" disabled, then 

    # This DOES print "How unusual!" if 'autochomp' is disabled
undef $a[10];
print "How unusual!\n" if $a[10];

    Because when "autochomp" is disabled, $a[10] will read back as "\n" (or whatever the record separator string is.)

    There are other minor differences, particularly regarding "exists" and "delete", but in general, the correspondence is extremely close.

  • I have supposed that since this module is concerned with file I/O, almost all normal use of it will be heavily I/O bound. This means that the time to maintain complicated data structures inside the module will be dominated by the time to actually perform the I/O. When there was an opportunity to spend CPU time to avoid doing I/O, I usually tried to take it.
  • You might be tempted to think that deferred writing is like transactions, with "flush" as "commit" and "discard" as "rollback", but it isn't, so don't.
  • There is a large memory overhead for each record offset and for each cache entry: about 310 bytes per cached data record, and about 21 bytes per offset table entry.

    The per-record overhead will limit the maximum number of records you can access per file. Note that accessing the length of the array via "$x = scalar @tied_file" accesses all records and stores their offsets. The same for "foreach (@tied_file)", even if you exit the loop early.

Tie::File

Tie::File - Módulos de interfaz de archivo para acceso aleatorio a líneas de archivo

NOMBRE

Tie::File - Módulos de interfaz de archivo para acceso aleatorio a líneas de archivo

SINOPSIS

    use Tie::File;

    # Lee el archivo completo en memoria
    tie @array, "Tie::File", $filename, (@options);
    # o
    my $fh = Tie::File->new($filename, (@options));
    tie @array, $fh;

    # Accede a las líneas por índice
    $array[10] = "nueva línea";
    push @array, "última línea";
    print $array[5];
    my $line = shift @array;
    my $last = pop @array;

    # La escritura en el archivo se realiza al salir del ámbito dinámico
    # de la matriz enlazada, o cuando el enlazamiento se rompe explícitamente
    # (por ejemplo, con untie).
    untie @array;

DESCRIPCIÓN

Tie::File es un módulo de Perl que permite tratar un archivo como si fuera una matriz de Perl. Cada elemento de la matriz corresponde a una línea del archivo. Los cambios realizados en la matriz (como asignar a un índice, usar push, pop, shift, unshift, splice) se reflejan en el archivo. Los cambios se escriben en el archivo cuando se rompe el enlace (untie) o cuando el intérprete de Perl finaliza normalmente.

Cuando el archivo se abre por primera vez, se carga en memoria. Si el archivo es muy grande, esto podría consumir mucha memoria. Sin embargo, las modificaciones posteriores se realizan de forma más eficiente, escribiendo solo las líneas modificadas.

A diferencia de otros módulos de enlazamiento de archivos, Tie::File puede funcionar con un archivo ya abierto. Esto es útil para la concurrencia, ya que evita la sobreescritura accidental de datos.

MÉTODOS PÚBLICOS

new(filename, @options)
Crea un nuevo objeto Tie::File que se puede usar para enlazar a una matriz. Los argumentos son el nombre del archivo y una lista de opciones. Las opciones admitidas son:
  • autoflush => 1: Fuerza la escritura inmediata de los cambios al archivo. Esto es útil para la concurrencia, pero puede ser ineficiente.
  • binary => 1: Abre el archivo en modo binario.
  • mode => "0644": Establece el modo de permisos para el archivo nuevo.
  • recsep => $regexp: Establece el separador de registros (predeterminado es newline).
tie(arrayref, filename, @options)
Este es un método de conveniencia que llama a new y luego enlaza la matriz proporcionada a la interfaz de Tie::File.
untie(arrayref)
Rompe el enlace de la matriz proporcionada. Asegura que todos los cambios se escriban en el archivo.
read(filename, @options)
Lee el contenido de un archivo y lo almacena en la matriz enlazada. Esto es útil si ya ha enlazado una matriz y desea actualizar su contenido desde el archivo.
write(filename, @options)
Escribe el contenido de la matriz enlazada en el archivo especificado. Si no se proporciona un nombre de archivo, se utiliza el nombre de archivo original.
insert(index, line)
Inserta una línea en el índice especificado. Equivale a splice(@array, index, 0, line).
append(line)
Agrega una línea al final del archivo. Equivale a push(@array, line).

Enlazando a un filehandle ya abierto

Puede enlazar un objeto Tie::File a un filehandle que ya está abierto. Esto es útil para evitar que otros procesos modifiquen el archivo mientras está trabajando en él.

    open my $fh, "<>", $filename or die "No se pudo abrir $filename: $!";
    my $tie_file = Tie::File->new($filename, ()); # Opcionalmente, pasa opciones
    tie @lines, $tie_file, $fh;

Cuando usa un filehandle existente, Tie::File asume que usted se encargará de abrir y cerrar el filehandle. Sin embargo, la escritura diferida y la finalización de la escritura de los cambios se seguirán manejando a través de untie o al finalizar el script.

Escritura diferida

Por defecto, los cambios realizados en la matriz enlazada no se escriben inmediatamente en el archivo. Se almacenan en memoria y se escriben cuando se llama a untie o cuando el script termina.

Para forzar la escritura inmediata de los cambios, puede pasar la opción autoflush => 1 al constructor new:

    tie @array, "Tie::File", $filename, (autoflush => 1);

Tenga en cuenta que habilitar autoflush puede tener implicaciones de rendimiento, ya que cada modificación requerirá una operación de escritura en el disco.

ACCESO CONCURRENTE A ARCHIVOS

Tie::File proporciona cierto nivel de seguridad para el acceso concurrente a archivos, especialmente cuando se utiliza un filehandle existente. Sin embargo, para una concurrencia robusta, se recomienda utilizar mecanismos de bloqueo de archivos externos.

Si varios procesos intentan modificar el mismo archivo usando Tie::File sin ningún mecanismo de bloqueo, puede ocurrir una condición de carrera y los datos podrían corromperse.

La opción autoflush => 1 puede ayudar a asegurar que los cambios se reflejen más rápidamente, pero no previene que otro proceso lea datos inconsistentes si escribe mientras el otro está leyendo.

PRECAUCIONES

  • Uso de memoria: Cargar un archivo grande completo en memoria puede consumir una cantidad significativa de RAM. Tenga cuidado al usar Tie::File con archivos muy grandes.
  • Bloqueo: Tie::File no implementa bloqueo de archivos por sí mismo. Para acceso concurrente seguro, utilice módulos de bloqueo de archivos como File::Lockf o Flock.
  • Finalización del script: Si el script falla o se interrumpe de forma inesperada antes de que se complete la escritura diferida, es posible que los últimos cambios no se guarden en el archivo.
  • Manipulación de final de línea: Tie::File trata cada línea como una unidad independiente. La manipulación de los finales de línea puede ser delicada, especialmente en diferentes sistemas operativos (Windows vs. Unix).

SUBCLASES

Puede subclassificar Tie::File para agregar funcionalidad personalizada o modificar su comportamiento. Por ejemplo, podría crear una subclase que valide las líneas antes de escribirlas en el archivo.

    package MyTieFile;
    use base 'Tie::File';

    sub STORE {
        my ($self, $index, $value) = @_;
        # Realizar validación aquí
        return $self->SUPER::STORE($index, $value);
    }

    package main;
    tie @lines, 'MyTieFile', $filename;

¿QUÉ PASA CON "DB_File"?

Tie::File es para acceso línea por línea a archivos de texto planos. Si necesita una base de datos clave-valor en disco que sea más eficiente para búsquedas, inserciones y eliminaciones que un archivo de texto plano, debería considerar el módulo DB_File.
