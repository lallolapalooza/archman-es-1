TIOCPKT(2const) TIOCPKT(2const)

NOMBRE

TIOCPKT, TIOCGPKT, TIOCSPTLCK, TIOCGPTLCK, TIOCGPTPEER - ioctls de pseudoterminal

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <asm/termbits.h>  /* Definición de constantes TIOC* */
#include <sys/ioctl.h>
int ioctl(int fd, TIOCPKT, const int *mode);
int ioctl(int fd, TIOCPKT, int *mode);
int ioctl(int fd, TIOCSPTLCK, const int *lock);
int ioctl(int fd, TIOCGPTLCK, int *lock);
int ioctl(int fd, TIOCGPTPEER, int flags);

DESCRIPCIÓN

TIOCPKT
Habilita (cuando *mode es distinto de cero) o deshabilita el modo paquete. Solo se puede aplicar al lado maestro de un pseudoterminal (y de lo contrario devolverá ENOTTY). En modo paquete, cada read(2) subsiguiente devolverá un paquete que contendrá un solo byte de control distinto de cero, o que tendrá un solo byte que contiene cero ('\0') seguido de datos escritos en el lado esclavo del pseudoterminal. Si el primer byte no es TIOCPKT_DATA (0), es una combinación OR de uno o más de los siguientes bits:
TIOCPKT_FLUSHREAD Se vacía la cola de lectura del terminal.
TIOCPKT_FLUSHWRITE Se vacía la cola de escritura del terminal.
TIOCPKT_STOP Se detiene la salida al terminal.
TIOCPKT_START Se reinicia la salida al terminal.
TIOCPKT_DOSTOP Los caracteres de inicio y parada son ^S / ^Q.
TIOCPKT_NOSTOP Los caracteres de inicio y parada no son ^S / ^Q.
Mientras el modo paquete está en uso, la presencia de información de estado de control para ser leída desde el lado maestro se puede detectar mediante un select(2) para condiciones excepcionales o un poll(2) para el evento POLLPRI.
Este modo es utilizado por rlogin(1) y rlogind(8) para implementar un inicio de sesión remoto con eco remoto y control de flujo local de ^S/^Q.
TIOCGPKT
Devuelve la configuración actual del modo paquete en el entero apuntado por mode.
TIOCSPTLCK
Establece (si *lock es distinto de cero) o elimina (si *lock es cero) el bloqueo en el dispositivo esclavo del pseudoterminal. (Ver también unlockpt(3).)
TIOCGPTLCK
Coloca el estado actual del bloqueo del dispositivo esclavo del pseudoterminal en la ubicación apuntada por lock.
TIOCGPTPEER
Dado un descriptor de archivo en fd que se refiere a un maestro de pseudoterminal, abre (con los flags dados, de estilo open(2)) y devuelve un nuevo descriptor de archivo que se refiere al dispositivo esclavo de pseudoterminal emparejado. Esta operación se puede realizar independientemente de si la ruta del dispositivo esclavo es accesible a través del espacio de nombres de montaje del proceso de llamada.
Los programas sensibles a la seguridad que interactúan con espacios de nombres pueden desear usar esta operación en lugar de open(2) con la ruta devuelta por ptsname(3), y funciones de biblioteca similares que tienen APIs inseguras. (Por ejemplo, la confusión puede ocurrir en algunos casos al usar ptsname(3) con una ruta donde se ha montado un sistema de archivos devpts en un espacio de nombres de montaje diferente.)

VALOR DEVUELTO

Al éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

ENOTTY

HISTORIA

TIOCGPKT
Linux 3.8.
TIOCGPTLCK
Linux 3.8.
TIOCGPTPEER
Linux 4.13.

Los ioctls de BSD TIOCSTOP, TIOCSTART, TIOCUCNTL y TIOCREMOTE no se han implementado en Linux.
