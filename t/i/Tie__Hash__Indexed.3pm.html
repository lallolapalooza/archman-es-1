Tie::Hash::Indexed(3) Documentación de Perl contribuida por usuarios Tie::Hash::Indexed(3)

NOMBRE

Tie::Hash::Indexed - Hashes ordenados para Perl

SINOPSIS

use Tie::Hash::Indexed;
# Interfaz orientada a objetos
my $hash = Tie::Hash::Indexed->new(
             I => 1, n => 2, d => 3, e => 4);
$hash->push(x => 5);
print $hash->keys, "\n";   # imprime 'Index'
print $hash->values, "\n"; # imprime '12345'
# Interfaz atada
tie my %hash, 'Tie::Hash::Indexed';
%hash = ( I => 1, n => 2, d => 3, e => 4 );
$hash{x} = 5;
print keys %hash, "\n";    # imprime 'Index'
print values %hash, "\n";  # imprime '12345'

DESCRIPCION

Tie::Hash::Indexed es intencionalmente muy similar a otros módulos de hash ordenado, principalmente Hash::Ordered. Sin embargo, Tie::Hash::Indexed está escrito completamente en XS y es, a menudo significativamente, más rápido que otros módulos. Para muchas operaciones, es más del doble de rápido que Hash::Ordered, especialmente cuando se utiliza la interfaz orientada a objetos en lugar de la interfaz atada. Otros módulos, por ejemplo Tie::IxHash, son incluso más lentos.

La interfaz orientada a objetos de Tie::Hash::Indexed es casi idéntica a la de Hash::Ordered, por lo que en la mayoría de los casos podrá reemplazar fácilmente uno con el otro.

Si no necesita el último ápice de rendimiento y se siente más cómodo con un módulo puramente Perl, Hash::Ordered es definitivamente una buena alternativa.

COMPATIBILIDAD

Tie::Hash::Indexed debería compilarse con versiones de perl tan antiguas como 5.005. Debería compilarse en cualquier plataforma si hay un compilador C disponible.

Hash::Ordered

Tie::Hash::Indexed no tiene un método "clone", pero la clonación se puede emular con:

$clone = Tie::Hash::Indexed->new($orig->items);

Tie::Hash::Indexed tiene un método "items" como alias de "as_list", que Hash::Ordered no tiene. Si quiere poder cambiar de módulo, debería preferir usar "as_list".

Tie::Hash::Indexed también tiene un método "has" como alias de "exists".

Tie::Hash::Indexed también tiene "dor_assign" y "or_assign" como alias de "dor_equals" y "or_equals".

Tie::Hash::Indexed tiene métodos "multiply", "divide" y "modulo" además de "add" y "subtract". Hash::Ordered solo admite "add" y "subtract".

Tie::Hash::Indexed tiene un método "assign" que se puede usar para asignar directamente una nueva lista de pares clave-valor a una instancia existente. Con Hash::Ordered, puede llamar a "clear" seguido de "merge" para obtener el mismo comportamiento.

Tie::Hash::Indexed tiene un método "reverse_iterator", que se puede emular en Hash::Ordered pasando la lista invertida de claves a "iterator". Por otro lado, el método "iterator" de Tie::Hash::Indexed no admite pasar una lista de claves en absoluto.

Los objetos Tie::Hash::Indexed siempre se evalúan como verdaderos en contexto booleano, a diferencia de los objetos Hash::Ordered, que se evalúan como falsos si están vacíos, y verdaderos en caso contrario. Puede usar "$obj->keys" con Tie::Hash::Indexed en su lugar, lo cual es extremadamente barato de llamar en contexto escalar.

Devuelve el valor en contexto escalar o el par clave-valor en contexto de lista.

NAME

Tie::Hash::Indexed - An indexed hash implementation

SYNOPSIS

 use Tie::Hash::Indexed;

 my %h;
 tie %h, "Tie::Hash::Indexed";

 %h = (
     apple  => 1,
     banana => 2,
     orange => 3,
 );
 print $h{banana}; # prints 2

 my $h = Tie::Hash::Indexed->new(
     apple  => 1,
     banana => 2,
     orange => 3,
 );
 print $h->get('banana'); # prints 2
 print $h->get('grape');  # prints undef

 $h->set('grape', 4);
 print $h->get('grape');  # prints 4

 my @keys = $h->keys; # keys is ('apple', 'banana', 'orange', 'grape')
 my @vals = $h->values; # vals is (1, 2, 3, 4)

 my @items = $h->items; # items is ( ['apple', 1], ['banana', 2], ['orange', 3], ['grape', 4] )

 my ($k, $v) = $h->first; # $k is 'apple', $v is 1
 my ($k, $v) = $h->next;  # $k is 'banana', $v is 2

 $h->remove('orange');
 print $h->exists('orange'); # prints 0 (false)

 my $cnt = keys %h;
 print $cnt; # prints 3

DESCRIPTION

Tie::Hash::Indexed implements a tied hash that keeps its keys and values in the order in which they were inserted. It also provides methods to access the keys and values in that order.

Tie::Hash::Indexed allows you to take advantage of the ordered nature of the hash without resorting to complicated data structures.

All methods are implemented in XS for maximum efficiency.

COMPATIBILITY

Tie::Hash::Indexed requires Perl 5.005 or later.

METHODS

new

my $h = Tie::Hash::Indexed->new(%args);
my $h = Tie::Hash::Indexed->new(\%args);

Creates and returns a new Tie::Hash::Indexed object. The optional arguments are used to initialize the hash.

tie

tie my %hash, "Tie::Hash::Indexed";
tie my %hash, "Tie::Hash::Indexed", %args;
tie my %hash, "Tie::Hash::Indexed", \%args;

Ties a hash to the Tie::Hash::Indexed class. Optionally initializes the hash with the provided arguments.

fetch

$obj->fetch($key);
$obj->fetch(@keys);

Returns the value associated with the specified key, or a list of values if multiple keys are provided. In scalar context, returns the value for the first key or the number of elements that would be returned in list context.

If a key is not found, the associated value will be returned as "undef".

STORE

$obj->STORE($key, $value);
$obj->STORE($key, $value, @more);

Stores the value associated with the key. If the key already exists, its value is updated. If the key does not exist, it is added to the end of the hash.

exists

$obj->exists($key);

Returns true if the key exists in the hash, false otherwise.

delete

$obj->delete($key);
$obj->delete(@keys);

Deletes the specified key(s) from the hash. Returns the value(s) that were associated with the deleted key(s). In scalar context, returns the value for the first key or the number of elements that would be returned in list context.

first

my ($key, $value) = $obj->first;

Returns the first key-value pair from the hash.

next

my ($key, $value) = $obj->next;

Returns the next key-value pair from the hash.

prev

my ($key, $value) = $obj->prev;

Returns the previous key-value pair from the hash.

last

my ($key, $value) = $obj->last;

Returns the last key-value pair from the hash.

items

my @items = $obj->items;
my @items = $obj->items(@keys);

Returns a list of key-value pairs for all items in the hash, or just for the selected keys. In scalar context, returns the number of list elements that would be returned in list context.

If a key is not found, the associated value will be returned as "undef".

as_list

An alias for "items".

keys

@keys = $obj->keys;
@keys = $obj->keys(@keys);

Returns the keys for all items in the hash, or just for the selected keys. In scalar context, returns the number of list elements that would be returned in list context.

values

@values = $obj->values;
@values = $obj->values(@keys);

Returns the values for all items in the hash, or just for the selected keys. In scalar context, returns the number of list elements that would be returned in list context.

If a key is not found, the associated value will be returned as "undef".

concat

$obj->concat($key, $str);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) . $str);

add

$obj->add($key, $value);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) + $value);

subtract

$obj->subtract($key, $value);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) - $value);

multiply

$obj->multiply($key, $value);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) * $value);

divide

$obj->divide($key, $value);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) / $value);

modulo

$obj->modulo($key, $value);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) % $value);

dor_assign

$obj->dor_assign($key, $value);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) // $value);

dor_equals

This is an alias for "dor_assign".

or_assign

$obj->or_assign($key, $value);

This is equivalent to, but more efficient than:

$obj->set($key, $obj->get($key) || $value);

or_equals

This is an alias for "or_assign".

postinc

$val = $obj->postinc($key);

This is equivalent to, but more efficient than:

$val = $obj->get($key);
$obj->set($key, $val + 1);

postdec

$val = $obj->postdec($key);

This is equivalent to, but more efficient than:

$val = $obj->get($key);
$obj->set($key, $val - 1);

preinc

$val = $obj->preinc($key);

This is equivalent to, but more efficient than:

$val = $obj->set($key, $obj->get($key) + 1);

predec

$val = $obj->predec($key);

This is equivalent to, but more efficient than:

$val = $obj->set($key, $obj->get($key) - 1);

iterator

my $i = $h->iterator;
while (my($k, $v) = $i->next) {
  push @key, $k;
  push @val, $v;
}

Bidirectional forward iterator for ordered hash traversal.

reverse_iterator

for (my $i = $h->reverse_iterator; $i->valid; $i->next) {
  push @key, $i->key;
  push @val, $i->value;
}

Bidirectional reverse iterator for ordered hash traversal.

ENVIRONMENT

"THI_DEBUG_OPT"

If Tie::Hash::Indexed is built with debugging support, you can use this environment variable to specify debugging options. Currently, the only useful values you can pass in are "d" or "all", which both enable debug output for the module.

PROBLEMS

As the data of Tie::Hash::Indexed objects is hidden inside the XS implementation, cloning/serialization is problematic. Tie::Hash::Indexed implements hooks for Storable, so cloning or serializing objects using Storable is safe.

Tie::Hash::Indexed tries very hard to detect any corruption in its data at runtime. So if something goes wrong, you'll most probably receive an appropriate error message.
