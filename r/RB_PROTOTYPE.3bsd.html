DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles de splay y árboles rojo-negros.

En las definiciones de las macros, TYPE es el nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es el nombre de una estructura definida por el usuario que debe ser declarada usando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME debe ser un nombre de prefijo único para cada árbol definido.

Los prototipos de las funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE o RB_GENERATE_STATIC. Vea los ejemplos a continuación para una explicación más detallada de cómo se utilizan estas macros.

ÁRBOLES DE SPLAY

Un árbol de splay es una estructura de datos auto-organizativa. Cada operación en el árbol causa un splay. El splay mueve el nodo solicitado a la raíz del árbol y rebalancea parcialmente el árbol.

Esto tiene el beneficio de que la localidad de las solicitudes resulta en consultas más rápidas, ya que los nodos solicitados se mueven a la cima del árbol. Por otro lado, cada consulta causa escrituras en memoria.

El Teorema de Equilibrio limita el tiempo de acceso total para m operaciones e n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos en un árbol de splay es O(lg n).

Un árbol de splay está dirigido por una estructura definida a través de la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara así:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y TYPE es el tipo de los elementos a insertar en el árbol.

La macro SPLAY_ENTRY declara una estructura que permite la conexión de elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE, donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que gestiona el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY.

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE. Toma los mismos argumentos que la macro SPLAY_PROTOTYPE() pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar nodos del árbol con otros. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, devuelve un valor menor que cero. Si son iguales, devuelve cero. De lo contrario, devuelve un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT inicializa el árbol referenciado por head.

El árbol de splay también se puede inicializar estáticamente usando la macro SPLAY_INITIALIZER, como se muestra:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT inserta el nuevo elemento elm en el árbol. Al éxito, devuelve NULL. Si ya existe un elemento coincidente en el árbol, la inserción se aborta y devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE elimina el elemento elm del árbol apuntado por head. Al éxito, devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no existe en el árbol.

La macro SPLAY_FIND se puede usar para encontrar un elemento específico en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden usar para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para simplificar, se puede usar la macro SPLAY_FOREACH:

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY debe usarse para verificar si un árbol de splay está vacío.

ÁRBOLES ROJO-NEGROS

Un árbol rojo-negro es un árbol de búsqueda binario con el color del nodo como un atributo adicional. Cumple un conjunto de condiciones:

  1. Cada camino desde la raíz hasta un nodo hoja contiene el mismo número de nodos negros.
  2. Cada nodo rojo (excepto la raíz) tiene un padre negro.
  3. Cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg(n+1).

Un árbol rojo-negro está dirigido por una estructura definida mediante la macro RB_HEAD(). Una estructura RB_HEAD se declara así:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y TYPE es el tipo de los elementos a insertar en el árbol.

La macro RB_ENTRY declara una estructura que permite la conexión de elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC() donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que gestiona el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY.

Los cuerpos de las funciones se generan con las macros RB_GENERATE() o RB_GENERATE_STATIC() donde estos toman los mismos argumentos que la macro RB_PROTOTYPE() y RB_GENERATE() y RB_GENERATE_STATIC().

DESCRIPTION

These macros provide an implementation of red-black trees. Red-black trees are a type of self-balancing binary search tree. They are a common choice for implementing ordered maps and sets. This implementation is inspired by the implementation in The Design and Implementation of the FreeBSD Operating System, Chapter 7, by Marshall Kirk McKusick and George V. Neville-Neil.

The tree structure is defined using the RB_HEAD() macro. The RB_HEAD() macro takes two arguments: name is the name of the tree structure, and type is the name of the structure that will hold the tree nodes. The user must also include a structure definition for the tree node linkage. This is done using the RB_ENTRY() macro:

struct my_node {
    RB_ENTRY(my_node) next;
    /* other data */
};

The tree itself is represented by a pointer to the tree structure defined by RB_HEAD(). For example:

RB_HEAD(my_tree, my_node) my_tree_head;

In order to use the red-black tree macros, the user must define a comparison function. This function takes two arguments of type struct TYPE *, where TYPE is the type of the structure used for the tree nodes. The comparison function should return a negative value if the first argument is smaller than the second, zero if they are equal, and a positive value otherwise. The comparison function defines the order of the tree elements.

The RB_PROTOTYPE() macro should be used in a header file to declare the tree functions and the comparison function. The RB_GENERATE() macro should be used in exactly one source file to generate the tree functions and the comparison function.

The CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

RB_INIT()

The RB_INIT() macro initializes the tree referenced by head. It should be called before any other tree operations.

RB_INITIALIZER()

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

RB_INSERT()

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

RB_REMOVE()

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

RB_FIND() and RB_NFIND()

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), RB_PREV()

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

RB_FOREACH() and RB_FOREACH_REVERSE()

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE()

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

RB_EMPTY()

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
    RB_ENTRY(node) entry;
    int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
    return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
    20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
    7, 11, 14
};

void
print_tree(struct node *n)
{
    struct node *left, *right;

    if (n == NULL) {
        printf("nil");
        return;
    }
    left = RB_LEFT(n, entry);
    right = RB_RIGHT(n, entry);
    if (left == NULL && right == NULL)
        printf("%d", n->i);
    else {
        printf("%d(", n->i);
        print_tree(left);
        printf(",");
        print_tree(right);
        printf(")");
    }
}

int
main(void)
{
    int i;
    struct node *n;

    for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
        if ((n = malloc(sizeof(struct node))) == NULL)
            err(1, NULL);
        n->i = testdata[i];
        RB_INSERT(inttree, &head, n);
    }

    RB_FOREACH(n, inttree, &head) {
        printf("%d\n", n->i);
    }
    print_tree(RB_ROOT(&head));
    printf("\n");
    return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
    SPLAY_REMOVE(NAME, &head, var);
    free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
    nxt = SPLAY_NEXT(NAME, &head, var);
    SPLAY_REMOVE(NAME, &head, var);
    free(var);
}
