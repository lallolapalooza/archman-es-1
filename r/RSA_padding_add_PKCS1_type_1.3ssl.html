NOMBRE

RSA_padding_add_PKCS1_type_1, RSA_padding_check_PKCS1_type_1, RSA_padding_add_PKCS1_type_2, RSA_padding_check_PKCS1_type_2, RSA_padding_add_PKCS1_OAEP, RSA_padding_check_PKCS1_OAEP, RSA_padding_add_PKCS1_OAEP_mgf1, RSA_padding_check_PKCS1_OAEP_mgf1, RSA_padding_add_none, RSA_padding_check_none - relleno de cifrado asimétrico

#include <openssl/rsa.h>

DESCRIPCIÓN

Todas las funciones descritas en esta página están obsoletas. Las aplicaciones deberían usar en su lugar las APIs de EVP PKEY.

Las funciones RSA_padding_xxx_xxx() son llamadas desde las funciones de cifrado, descifrado, firma y verificación de RSA. Normalmente no deberían ser llamadas desde programas de aplicación.

Sin embargo, también pueden ser llamadas directamente para implementar relleno para otros cifrados asimétricos. RSA_padding_add_PKCS1_OAEP() y RSA_padding_check_PKCS1_OAEP() pueden ser utilizadas en una aplicación combinada con RSA_NO_PADDING para implementar OAEP con un parámetro de codificación.

RSA_padding_add_xxx() codifica fl bytes de f para que quepan en tlen bytes y almacena el resultado en to. Se produce un error si fl no cumple los requisitos de tamaño del método de codificación.

Los siguientes métodos de codificación están implementados:

PKCS1_type_1
PKCS #1 v2.0 EMSA-PKCS1-v1_5 (tipo de bloque 1 de PKCS #1 v1.5); utilizado para firmas
PKCS1_type_2
PKCS #1 v2.0 EME-PKCS1-v1_5 (tipo de bloque 2 de PKCS #1 v1.5)
PKCS1_OAEP
PKCS #1 v2.0 EME-OAEP
none
simplemente copia los datos

El generador de números aleatorios debe ser inicializado antes de llamar a RSA_padding_add_xxx(). Si la inicialización automática o la re-inicialización del CSPRNG de OpenSSL falla debido a circunstancias externas (ver RAND(7)), la operación fallará.

RSA_padding_check_xxx() verifica que los fl bytes en f contienen una codificación válida para una clave RSA de rsa_len bytes en el método de codificación respectivo y almacena los datos recuperados de como máximo tlen bytes (para RSA_NO_PADDING: de tamaño tlen) en to.

Para RSA_padding_xxx_OAEP(), p apunta al parámetro de codificación de longitud pl. p puede ser NULL si pl es 0.

Para RSA_padding_xxx_OAEP_mgf1(), md apunta al hash md; si md es NULL significa md=sha1, y mgf1md apunta al hash mgf1; si mgf1md es NULL significa mgf1md=md.

VALORES DE RETORNO

Las funciones RSA_padding_add_xxx() devuelven 1 en caso de éxito, 0 en caso de error. Las funciones RSA_padding_check_xxx() devuelven la longitud de los datos recuperados, -1 en caso de error. Los códigos de error pueden obtenerse llamando a ERR_get_error(3).

ADVERTENCIAS

El resultado de RSA_padding_check_PKCS1_type_2() es exactamente la información que se utiliza para montar un ataque clásico de oráculo de relleno de Bleichenbacher. Esta es una debilidad inherente en el diseño del relleno PKCS #1 v1.5. Prefiera el relleno PKCS1_OAEP. Si eso no es posible, el resultado de RSA_padding_check_PKCS1_type_2() debe ser verificado en tiempo constante si coincide con la longitud esperada del texto plano y, además, se deben realizar comprobaciones de consistencia específicas de la aplicación sobre el texto plano en tiempo constante. Si el texto plano es rechazado, se debe mantener en secreto qué comprobación causó que la aplicación rechazara el mensaje. No elimine el relleno de ceros de los datos RSA en bruto descifrados que fueron computados por RSA_private_decrypt() con RSA_NO_PADDING, ya que esto crearía un pequeño canal lateral de tiempo que podría ser utilizado para montar un ataque de Bleichenbacher contra cualquier modo de relleno, incluido PKCS1_OAEP.

Debería preferir el uso de las APIs de EVP PKEY para el descifrado PKCS#1 v1.5, ya que implementan las soluciones necesarias internamente.
