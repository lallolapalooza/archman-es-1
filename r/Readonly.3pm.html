NOMBRE

Readonly - Facilidad para crear escalares, arrays y hashes de solo lectura

Sinopsis

use Readonly;
# Escalar de solo lectura profundo
Readonly::Scalar    $sca => $valor_inicial;
Readonly::Scalar my $sca => $valor_inicial;
# Array de solo lectura profundo
Readonly::Array    @arr => @valores;
Readonly::Array my @arr => @valores;
# Hash de solo lectura profundo
Readonly::Hash    %has => (clave => valor, clave => valor, ...);
Readonly::Hash my %has => (clave => valor, clave => valor, ...);
# o:
Readonly::Hash    %has => {clave => valor, clave => valor, ...};
# Puedes usar las variables de solo lectura como cualquier variable normal:
print $sca;
$algo = $sca + $arr[2];
next if $has{$alguna_clave};
# Pero si intentas modificar un valor, tu programa morirá:
$sca = 7;
push @arr, 'siete';
delete $has{clave};
# El mensaje de error es "Intentada modificación de un valor de solo lectura"
# Forma alternativa (Perl 5.8 y posteriores)
Readonly    $sca => $valor_inicial;
Readonly my $sca => $valor_inicial;
Readonly    @arr => @valores;
Readonly my @arr => @valores;
Readonly    %has => (clave => valor, clave => valor, ...);
Readonly my %has => (clave => valor, clave => valor, ...);
Readonly my $sca; # undef implícito, valor de solo lectura
# Forma alternativa (para Perls anteriores a v5.8)
Readonly    \$sca => $valor_inicial;
Readonly \my $sca => $valor_inicial;
Readonly    \@arr => @valores;
Readonly \my @arr => @valores;
Readonly    \%has => (clave => valor, clave => valor, ...);
Readonly \my %has => (clave => valor, clave => valor, ...);

Descripción

Esta es una facilidad para crear variables no modificables. Esto es útil para archivos de configuración, encabezados, etc. También puede ser útil como herramienta de desarrollo y depuración para detectar actualizaciones en variables que no deben cambiarse.

Profundidad de la Variable

Readonly tiene la capacidad de crear variables de solo lectura tanto profundas como superficiales.

Si pasas una $ref, un @array o un %hash a las funciones correspondientes ::Scalar(), ::Array() y ::Hash(), entonces esas funciones recursan sobre la estructura de datos, marcando todo como de solo lectura. Toda la estructura es entonces no modificable. Esto es normalmente lo que quieres.

Si solo quieres que el nivel superior sea de solo lectura, usa las funciones alternativas (y mal nombradas) ::Scalar1(), ::Array1() y ::Hash1().

El Readonly() simple crea lo que el autor original llama una variable de solo lectura "superficial", lo cual es genial si no planeas usarla en nada más que valores escalares unidimensionales.

Readonly::Scalar() hace que la variable sea de solo lectura "profunda", por lo que el siguiente fragmento muere como esperas:

use Readonly;
Readonly::Scalar my $ref => { 1 => 'a' };
$ref->{1} = 'b';
$ref->{2} = 'b';

Mientras que el siguiente fragmento NO hace que tu estructura sea de solo lectura "profunda":

use Readonly;
Readonly my $ref => { 1 => 'a' };
$ref->{1} = 'b';
$ref->{2} = 'b';

El Pasado

Las siguientes secciones son versiones actualizadas de la documentación de los autores anteriores.

Comparación con "use constant"

Perl proporciona una facilidad para crear valores constantes, a través del pragma constant. Existen varios problemas con este pragma.

  • Las constantes creadas no tienen sigilos iniciales.
  • Estas constantes no pueden interpolarse en cadenas.
  • La sintaxis a veces puede ser complicada. Por ejemplo: 
    use constant CARRAY => (2, 3, 5, 7, 11, 13);
$a_prime = CARRAY[2];        # ¡incorrecto!
$a_prime = (CARRAY)[2];      # correcto -- DEBE usar paréntesis
  • Debes tener mucho cuidado en lugares donde se permiten palabras desnudas.

    Por ejemplo:

    use constant SOME_KEY => 'key';
%hash = (key => 'value', other_key => 'other_value');
$some_value = $hash{SOME_KEY};        # ¡incorrecto!
$some_value = $hash{+SOME_KEY};       # correcto

    (¿quién piensa en usar un más unario cuando se usa un hash para escalarizar la clave?)

  • "use constant" funciona para escalares y arrays, no para hashes.
  • Estas constantes son globales para el paquete en el que se declaran; no pueden ser léxicamente acotadas.
  • Funciona solo en tiempo de compilación.
  • Puede ser anulado: 
    use constant PI => 3.14159;
...
use constant PI => 2.71828;

    (esto genera una advertencia, sin embargo, si tienes las advertencias habilitadas).

  • Es muy difícil crear y usar estructuras profundas (estructuras de datos complejas) con "use constant".

Comparación con constantes de typeglob

Otra forma popular de crear escalares de solo lectura es modificar la entrada de la tabla de símbolos de la variable usando un typeglob:

*a = \'valor';

Esto funciona bien, pero solo funciona para variables globales (las variables "my" no tienen entrada en la tabla de símbolos). Además, las siguientes construcciones similares NO funcionan:

*a = [1, 2, 3];      # NO crea un array de solo lectura
*a = { a => 'A'};    # NO crea un hash de solo lectura

Pros

Readonly.pm, por otro lado, funcionará con variables globales y con variables léxicas ("my"). Creará escalares, arrays o hashes, todos los cuales se ven y funcionan como variables de Perl normales, de lectura/escritura. Puedes usarlos en contexto escalar, en contexto de lista; puedes tomar referencias a ellos, pasarlos a funciones, cualquier cosa.

Readonly.pm también funciona bien con estructuras de datos complejas, permitiéndote etiquetar toda la estructura como no modificable, o solo el nivel superior.

Además, las variables Readonly no pueden ser reasignadas. El siguiente código morirá:

Readonly::Scalar $pi => 3.14159;
...
Readonly::Scalar $pi => 2.71828;

Contras

Readonly.pm solía imponer una penalización de rendimiento. Era bastante lento. ¿Qué tan lento? Ejecuta el script "eg/benchmark.pl" que viene con Readonly. En mi sistema de prueba, "use constant" (const), constantes de typeglob (tglob), variables de Perl regulares de lectura/escritura (normal/literal) y el nuevo Readonly (ro/ro_simple) tienen aproximadamente la misma velocidad, mientras que las constantes antiguas de Readonly.pm basadas en tie eran aproximadamente 1/22 de la velocidad.

Sin embargo, hay alivio. Hay un módulo complementario disponible, Readonly::XS. No lo necesitarás si estás usando Perl 5.8.x o superior.

Repito, no necesitas Readonly::XS si tu entorno tiene perl 5.8.x o superior. Consulta la sección titulada Internals para más detalles.

Funciones

Readonly::Scalar $var => $valor;
Crea un escalar no modificable, $var, y le asigna un valor de $valor. A partir de entonces, su valor no puede ser cambiado. Cualquier intento de modificar el valor hará que su programa muera.

Se *debe* suministrar un valor. Si quieres que la variable tenga "undef" como valor, debes especificar "undef".

Si $valor es una referencia a un escalar, array o hash, entonces esta función marcará el escalar, array o hash al que apunta como de Solo Lectura también, y recorrerá recursivamente la estructura, marcando toda la estructura como de Solo Lectura. Normalmente, esto es lo que quieres. Sin embargo, si solo quieres que $valor sea marcado como de Solo Lectura, usa "Scalar1".

Si $var ya es una variable de Solo Lectura, el programa morirá con un error sobre la reasignación de variables de Solo Lectura.

Readonly::Array @arr => (valor, valor, .

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Readonly::Array @arr => (value, value, ...);

Readonly::Array @arr => value, value, ...;
Crea un array no modificable, @arr, y le asigna la lista de valores especificada. A partir de entonces, ninguno de sus valores podrá ser modificado; el array no podrá alargarse, acortarse ni cortarse. Cualquier intento de hacerlo provocará que tu programa termine.

Si alguno de los valores pasados es una referencia a un escalar, array o hash, entonces esta función marcará también como de Solo Lectura el escalar, array o hash al que apunta, y recorrerá recursivamente la estructura, marcando toda la cosa como de Solo Lectura. Normalmente, esto es lo que quieres. Sin embargo, si solo quieres que el hash %@arr en sí sea marcado como de Solo Lectura, usa "Array1".

Si @arr ya es una variable de Solo Lectura, el programa terminará con un error sobre la reasignación de variables de Solo Lectura.

Readonly::Hash %h => (key => value, key => value, ...);
Readonly::Hash %h => {key => value, key => value, ...};
Crea un hash no modificable, %h, y le asigna las claves y valores especificados. A partir de entonces, sus claves o valores no podrán ser modificados. Cualquier intento de hacerlo provocará que tu programa termine.

Se puede especificar una lista de claves y valores (con paréntesis en el sinopsis anterior), o se puede especificar una referencia a un hash (llaves en el sinopsis anterior). Si se especifica una lista, debe tener un número par de elementos, o la función terminará.

Si alguno de los valores es una referencia a un escalar, array o hash, entonces esta función marcará también como de Solo Lectura el escalar, array o hash al que apunta, y recorrerá recursivamente la estructura, marcando toda la cosa como de Solo Lectura. Normalmente, esto es lo que quieres. Sin embargo, si solo quieres que el hash %h en sí sea marcado como de Solo Lectura, usa "Hash1".

Si %h ya es una variable de Solo Lectura, el programa terminará con un error sobre la reasignación de variables de Solo Lectura.

Readonly $var => $value;
Readonly @arr => (value, value, ...);
Readonly %h => (key => value, ...);
Readonly %h => {key => value, ...};
Readonly $var;
La función "Readonly" es una alternativa a las funciones "Scalar", "Array" y "Hash". Tiene la ventaja (si la consideras una ventaja) de ser una sola función. Eso puede hacer que tu programa se vea más ordenado, si estás inicializando un montón de constantes a la vez. Puedes o no preferir este estilo uniforme.

Tiene la desventaja de tener una sintaxis ligeramente diferente para versiones de Perl anteriores a la 5.8. Para versiones anteriores, debes proporcionar una barra invertida, ya que requiere una referencia como primer parámetro.

Readonly \$var => $value;
Readonly \@arr => (value, value, ...);
Readonly \%h   => (key => value, ...);
Readonly \%h   => {key => value, ...};

Puedes o no considerar esto feo.

Ten en cuenta que puedes crear variables indefinidas implícitas con esta función, como por ejemplo "Readonly my $var;", mientras que un valor indefinido explícito debe ser pasado a las funciones estándar "Scalar", "Array" y "Hash".

Readonly::Scalar1 $var => $value;
Readonly::Array1 @arr => (value, value, ...);
Readonly::Hash1 %h => (key => value, key => value, ...);
Readonly::Hash1 %h => {key => value, key => value, ...};
Estas funciones alternativas crean variables de Solo Lectura superficiales, en lugar de profundas. Por ejemplo: 
Readonly::Array1 @shal => (1, 2, {perl=>'Rules', java=>'Bites'}, 4, 5);
Readonly::Array  @deep => (1, 2, {perl=>'Rules', java=>'Bites'}, 4, 5);
$shal[1] = 7;           # error
$shal[2]{APL}='Weird';  # ¡Permitido! ya que el hash no es de Solo Lectura
$deep[1] = 7;           # error
$deep[2]{APL}='Weird';  # error, ya que el hash es de Solo Lectura

Clonación

Al clonar usando Storable o Clone notarás que el valor permanece de solo lectura, lo cual es correcto. Si deseas clonar el valor sin copiar la bandera de solo lectura, usa la función "Clone":

Readonly::Scalar my $scalar => {qw[this that]};
# $scalar->{'eh'} = 'foo'; # Se intentó modificar un valor de solo lectura
my $scalar_clone = Readonly::Clone $scalar;
$scalar_clone->{'eh'} = 'foo';
# $scalar_clone ahora es {this => 'that', eh => 'foo'};

La nueva variable ($scalar_clone) es un clon mutable del $scalar original.

Ejemplos

Estos son algunos ejemplos muy sencillos:

Escalares

Un valor simple de solo lectura:

Readonly::Scalar $a => "Un valor de cadena";

El valor no tiene por qué ser una constante en tiempo de compilación:

Readonly::Scalar $a => $valor_calculado;

Arrays/Listas

Un array de solo lectura:

Readonly::Array @a => (1, 2, 3, 4);

Los paréntesis son opcionales:

Readonly::Array @a => 1, 2, 3, 4;

Puedes usar la sintaxis de comillas de array incorporada de Perl:

Readonly::Array @a => qw/1 2 3 4/;

Puedes inicializar un array de solo lectura a partir de una variable:

Readonly::Array @a => @valores_calculados;

Un array de solo lectura también puede estar vacío:

Readonly::Array @a => ();
Readonly::Array @a;        # equivalente

Hashes

Uso típico:

Readonly::Hash %a => (clave1 => 'valor1', clave2 => 'valor2');

Un hash de solo lectura se puede inicializar a partir de un hash variable:

Readonly::Hash %a => %valores_calculados;

Un hash de solo lectura puede estar vacío:

Readonly::Hash %a => ();
Readonly::Hash %a;        # equivalente

Si pasas un número impar de valores, el programa terminará:

Readonly::Hash %a => (clave1 => 'valor1', "valor2");
# Esto termina con "No se puede almacenar un número impar de valores en un hash"

Exportaciones

Históricamente, este módulo exporta el símbolo "Readonly" al espacio de nombres del programa llamador por defecto. Los siguientes símbolos también están disponibles para importar en tu programa, si lo deseas: "Scalar", "Scalar1", "Array", "Array1", "Hash" y "Hash1".

Internos

Algunas personas simplemente no entienden la relación entre este módulo y Readonly::XS, así que añado esta sección. Lo más probable es que sigan sin entenderlo, pero me gusta escribir, así que...

En el pasado, la "magia" de Readonly se realizaba enlazando (tie()) variables a los paquetes "Readonly::Scalar", "Readonly::Array" y "Readonly::Hash" (que no deben confundirse con las funciones del mismo nombre) y actuando sobre "WRITE", "READ", etc. Si bien esto funcionó bien, fue lento. Muy lento. Como 20-30 veces más lento que acceder directamente a las variables o usar uno de los otros módulos relacionados con constantes que han surgido desde que Readonly fue lanzado en 2003.

Para 'arreglar' esto, se escribió Readonly::XS. Si está instalado, Readonly::XS usaba los métodos internos "SvREADONLY" y "SvREADONLY_on" para bloquear escalares simples. En la superficie, todo estaba bien, pero las cosas no eran iguales entre bastidores. En casos extremos, el código se comportaba de manera muy diferente si Readonly::XS estaba instalado y como no era una dependencia requerida en la mayoría del código, hacía que los errores posteriores fueran muy difíciles de rastrear.

En los años transcurridos desde el lanzamiento de Readonly::XS, los métodos internos, entonces privados, se han expuesto y pueden usarse en perl puro. Módulos similares se escribieron para aprovechar esto y se creó un parche para Readonly. Ya no necesitamos compilar e instalar otro módulo para que Readonly sea útil en las compilaciones modernas de perl.

  • No necesitas instalar Readonly::XS.
  • Deberías dejar de listar Readonly::XS como una dependencia o esperar que esté instalado.
  • Deja de probar la variable $Readonly::XSokay.

Requisitos

Tenga en cuenta que la mayoría de los usuarios de Readonly ya no necesitan instalar el módulo complementario Readonly::XS, el cual es recomendado pero no requerido para perl 5.6.x y anteriores. Por favor, no lo fuerces como requisito en código nuevo y no uses la variable de paquete $Readonly::XSokay en código/pruebas. Para más información, consulta "Internals" en la sección sobre los nuevos internos de Readonly.

No hay requisitos no estándar.
