NOMBRE

RELEASE_SAVEPOINT - libera un punto de guardado previamente definido

SINOPSIS

RELEASE [ SAVEPOINT ] nombre_punto_de_guardado

DESCRIPCIÓN

RELEASE SAVEPOINT libera el punto de guardado con nombre y todos los puntos de guardado activos que se crearon después del punto de guardado con nombre, y libera sus recursos. Todos los cambios realizados desde la creación del punto de guardado que no se hayan revertido previamente se fusionan en la transacción o punto de guardado que estaba activo cuando se creó el punto de guardado con nombre. Los cambios realizados después de RELEASE SAVEPOINT también formarán parte de esta transacción o punto de guardado activo.

PARÁMETROS

nombre_punto_de_guardado

El nombre del punto de guardado a liberar.

NOTAS

Especificar un nombre de punto de guardado que no se haya definido previamente es un error.

No es posible liberar un punto de guardado cuando la transacción está en estado abortado; para hacerlo, use ROLLBACK TO SAVEPOINT (ROLLBACK_TO_SAVEPOINT(7)).

Si varios puntos de guardado tienen el mismo nombre, solo se libera el más recientemente definido y no liberado. Los comandos repetidos liberarán puntos de guardado progresivamente más antiguos.

EJEMPLOS

Para establecer y luego liberar un punto de guardado:

BEGIN;
    INSERT INTO tabla1 VALUES (3);
    SAVEPOINT mi_punto_de_guardado;
    INSERT INTO tabla1 VALUES (4);
    RELEASE SAVEPOINT mi_punto_de_guardado;
COMMIT;

La transacción anterior insertará tanto 3 como 4.

Un ejemplo más complejo con múltiples subtransacciones anidadas:

BEGIN;
    INSERT INTO tabla1 VALUES (1);
    SAVEPOINT sp1;
    INSERT INTO tabla1 VALUES (2);
    SAVEPOINT sp2;
    INSERT INTO tabla1 VALUES (3);
    RELEASE SAVEPOINT sp2;
    INSERT INTO tabla1 VALUES (4))); -- genera un error

En este ejemplo, la aplicación solicita la liberación del punto de guardado sp2, que insertó 3. Esto cambia el contexto de la transacción de la inserción a sp1. Cuando la sentencia que intenta insertar el valor 4 genera un error, las inserciones de 2 y 4 se pierden porque están en el mismo punto de guardado, ahora revertido, y el valor 3 está en el mismo contexto de transacción. La aplicación ahora solo puede elegir uno de estos dos comandos, ya que todos los demás comandos serán ignorados:

ROLLBACK;
ROLLBACK TO SAVEPOINT sp1;

Elegir ROLLBACK abortará todo, incluido el valor 1, mientras que ROLLBACK TO SAVEPOINT sp1 conservará el valor 1 y permitirá que la transacción continúe.

COMPATIBILIDAD

Este comando cumple con el estándar SQL. El estándar especifica que la palabra clave SAVEPOINT es obligatoria, pero PostgreSQL permite omitirla.
