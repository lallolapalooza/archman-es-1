val create : ?runtime_begin:(int -> Runtime_events.Timestamp.t -> Runtime_events.runtime_phase -> unit) -> ?runtime_end:(int -> Runtime_events.Timestamp.t -> Runtime_events.runtime_phase -> unit) -> ?runtime_counter:(int -> Runtime_events.Timestamp.t -> Runtime_events.runtime_counter -> int -> unit) -> ?alloc:(int -> Runtime_events.Timestamp.t -> int array -> unit) -> ?lifecycle:(int -> Runtime_events.Timestamp.t -> Runtime_events.lifecycle -> int option -> unit) -> ?lost_events:(int -> int -> unit) -> unit -> t

Crea un Callback que se suscribe opcionalmente a uno o más eventos de tiempo de ejecución. El primer entero proporcionado a los callbacks es el índice del búfer circular. Cada dominio posee un único búfer circular durante la existencia del dominio. Después de que un dominio termina, un dominio recién iniciado puede tomar posesión del búfer circular. Se llama a un callback runtime_begin cuando el tiempo de ejecución entra en una nueva fase (por ejemplo, se llama a un runtime_begin con EV_MINOR al inicio de un GC menor). Se llama a un callback runtime_end cuando el tiempo de ejecución sale de una cierta fase. El callback runtime_counter se llama cuando un contador es emitido por el tiempo de ejecución. Los callbacks lifecycle se llaman cuando el búfer experimenta un cambio en su ciclo de vida y un consumidor puede necesitar responder. Los callbacks alloc actualmente solo se llaman en el tiempo de ejecución instrumentado. Los callbacks lost_events se llaman si el código consumidor detecta que algunos eventos no consumidos han sido sobrescritos.

val add_user_event : 'a Runtime_events.Type.t -> (int -> Runtime_events.Timestamp.t -> 'a Runtime_events.User.t -> 'a -> unit) -> t -> t

add_user_event ty callback t extiende t para suscribirse adicionalmente a eventos de usuario de tipo ty. Cuando ocurre dicho evento, se llama a callback con el evento y la carga útil correspondientes.
