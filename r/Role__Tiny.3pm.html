NOMBRE

Role::Tiny - Roles: una porción de cocina nouvelle de Moose

SINOPSIS

package Some::Role;
use Role::Tiny;
sub foo { ... }
sub bar { ... }
around baz => sub { ... };
1;

en otro lugar

package Some::Class;
use Role::Tiny::With;
# bar se importa, pero no foo
with 'Some::Role';
sub foo { ... }
# baz está envuelto en el modificador around por Class::Method::Modifiers
sub baz { ... }
1;

Si también quisieras atributos, mira Moo::Role.

DESCRIPCIÓN

"Role::Tiny" es una herramienta minimalista de composición de roles.

COMPOSICIÓN DE ROLES

La composición de roles puede pensarse como una herencia múltiple mucho más inteligente y significativa. Los aspectos básicos de esta implementación de roles son:

  • Si un método ya está definido en una clase, ese método no se compondrá desde el rol. Sin embargo, un método heredado por una clase es sobrescrito por el método del rol del mismo nombre.
  • Si un método que el rol "requiere" ser implementado no se implementa, la aplicación del rol fallará ruidosamente.

A diferencia de Class::C3, donde la última clase heredada "gana", la composición de roles es al revés, donde la clase gana. Si se aplican múltiples roles en una sola llamada (una sola declaración 'with'), entonces si alguno de sus métodos proporcionados choca, se plantea una excepción a menos que la clase proporcione un método, ya que este conflicto indica un problema potencial.

MÉTODOS DEL ROL

Todas las subs creadas después de importar Role::Tiny se considerarán métodos a componer. Por ejemplo:

package MyRole;
use List::Util qw(min);
sub mysub { }
use Role::Tiny;
use List::Util qw(max);
sub mymethod { }

En este rol, "max" y "mymethod" se incluirán al componer MyRole, y "min" y "mysub" no. Para control adicional, namespace::clean puede usarse para excluir subs no deseadas de los roles.

SUBRUTINAS IMPORTADAS

requires

requires qw(foo bar);

Declara una lista de métodos que deben definirse para componer el rol.

with

with 'Some::Role1';
with 'Some::Role1', 'Some::Role2';

Compone otro rol en el rol actual (o clase a través de Role::Tiny::With).

Si tienes conflictos y quieres resolverlos a favor de Some::Role1, puedes escribir en su lugar:

with 'Some::Role1';
with 'Some::Role2';

Si tienes conflictos y quieres resolver diferentes conflictos a favor de diferentes roles, por favor refactoriza tu base de código.

before

before foo => sub { ... };

Ver "before method(s) => sub { ... };" en Class::Method::Modifiers para documentación completa.

Ten en cuenta que dado que no es obligatorio usar modificadores de métodos, Class::Method::Modifiers se carga de forma perezosa y no lo declaramos como una dependencia. Si tu rol Role::Tiny usa modificadores, debes depender tanto de Class::Method::Modifiers como de Role::Tiny.

around

around foo => sub { ... };

Ver "around method(s) => sub { ... };" en Class::Method::Modifiers para documentación completa.

Ten en cuenta que dado que no es obligatorio usar modificadores de métodos, Class::Method::Modifiers se carga de forma perezosa y no lo declaramos como una dependencia. Si tu rol Role::Tiny usa modificadores, debes depender tanto de Class::Method::Modifiers como de Role::Tiny.

after

after foo => sub { ... };

Ver "after method(s) => sub { ... };" en Class::Method::Modifiers para documentación completa.

Ten en cuenta que dado que no es obligatorio usar modificadores de métodos, Class::Method::Modifiers se carga de forma perezosa y no lo declaramos como una dependencia. Si tu rol Role::Tiny usa modificadores, debes depender tanto de Class::Method::Modifiers como de Role::Tiny.

Strict y Warnings

Además de importar subrutinas, el uso de "Role::Tiny" aplica strict y warnings al llamador.

SUBRUTINAS

does_role

if (Role::Tiny::does_role($foo, 'Some::Role')) {
  ...
}

Devuelve verdadero si la clase se ha compuesto con el rol.

Esta subrutina también se instala como ->does en cualquier clase a la que se compone un Role::Tiny, a menos que esa clase ya tenga un método ->does, por lo que

if ($foo->does('Some::Role')) {
  ...
}

funcionará para clases, pero para probar un rol, se debe usar directamente ::does_role.

Además, Role::Tiny sobrescribirá el método estándar de Perl "DOES" para tu clase. Sin embargo, si "alguna" clase en la jerarquía de herencia de tu clase proporciona "DOES", entonces Role::Tiny no lo sobrescribirá.

MÉTODOS

make_role

Role::Tiny->make_role('Some::Role');

Convierte un paquete en un rol, pero no exporta ninguna subrutina en él.

apply_roles_to_package

Role::Tiny->apply_roles_to_package(
  'Some::Package', 'Some::Role', 'Some::Other::Role'
);

Compone el rol con el paquete. Ver también Role::Tiny::With.

apply_roles_to_object

Role::Tiny->apply_roles_to_object($foo, qw(Some::Role1 Some::Role2));

Compone los roles en orden directamente en el objeto. El objeto se re-bendice en la clase resultante. Ten en cuenta que los métodos del objeto son sobrescritos por los del rol con los mismos nombres.

create_class_with_roles

Role::Tiny->create_class_with_roles('Some::Base', qw(Some::Role1 Some::Role2));

Crea una nueva clase basada en 'base', con los roles compuestos en ella en orden. Se devuelve la nueva clase.

is_role

Role::Tiny->is_role('Some::Role1')

Devuelve verdadero si el paquete dado es un rol.

ADVERTENCIAS

  • En perl 5.8.8 y anteriores, aplicar un rol a un objeto no aplicará ninguna sobrecarga del rol a otras copias del objeto.
  • En perl 5.16 y anteriores, aplicar un rol a una clase no aplicará ninguna sobrecarga del rol a ninguna instancia existente de la clase.

VER TAMBIÉN

Role::Tiny es el subconjunto sin atributos de Moo::Role; Moo::Role es un subconjunto sin meta-protocolo del rey de los sistemas de roles, Moose::Role.

Role::Basic de Ovid proporciona roles con un alcance similar, pero sin modificadores de métodos, y con algunas restricciones de uso adicionales.
