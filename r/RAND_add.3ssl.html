RAND_add(3ssl)

Paquete: openssl

Licencias: Apache-2.0

RAND_ADD(3ssl) OpenSSL RAND_ADD(3ssl)

NOMBRE

RAND_add, RAND_poll, RAND_seed, RAND_status, RAND_event, RAND_screen, RAND_keep_random_devices_open - añadir aleatoriedad al PRNG u obtener su estado

SINOPSIS

#include <openssl/rand.h>
int RAND_status(void);
int RAND_poll();
void RAND_add(const void *buf, int num, double randomness);
void RAND_seed(const void *buf, int num);
void RAND_keep_random_devices_open(int keep);

Las siguientes funciones han sido marcadas como obsoletas desde OpenSSL 1.1.0, y pueden ser ocultadas completamente definiendo OPENSSL_API_COMPAT con un valor de versión adecuado, ver openssl_user_macros(7):

int RAND_event(UINT iMsg, WPARAM wParam, LPARAM lParam);
void RAND_screen(void);

DESCRIPCIÓN

Estas funciones pueden ser usadas para inicializar el generador aleatorio y para comprobar su estado inicializado. En general, la inicialización (o reinicialización) manual del generador aleatorio predeterminado de OpenSSL (RAND_OpenSSL(3)) no es necesaria (pero está permitida), ya que se inicializa (o reinicializa) automáticamente usando fuentes de entropía confiables del sistema. Esto se aplica a menos que se haya reemplazado el método RAND_METHOD predeterminado o OpenSSL se haya compilado con la reinicialización automática deshabilitada, ver RAND(7) para más detalles.

RAND_status() indica si el generador aleatorio ha sido inicializado con suficiente información. Si no es así, funciones como RAND_bytes(3) fallarán.

RAND_poll() utiliza las capacidades del sistema para inicializar el generador aleatorio utilizando entrada aleatoria obtenida de la consulta a varias fuentes de entropía confiables. La opción predeterminada de la fuente de entropía puede ser modificada en tiempo de compilación, ver RAND(7) para más detalles.

RAND_add() mezcla los num bytes en buf en el estado interno del generador aleatorio. Esta función normalmente no será necesaria, como se mencionó anteriormente. El argumento randomness es una estimación de cuánta aleatoriedad contiene buf, en bytes, y debe ser un número entre cero y num. Detalles sobre fuentes de aleatoriedad y cómo estimar su aleatoriedad se pueden encontrar en la literatura; por ejemplo [NIST SP 800-90B]. El contenido de buf no puede ser recuperado de la salida posterior del generador aleatorio. Las aplicaciones que pretendan guardar y restaurar el estado aleatorio en un archivo externo deberían considerar usar RAND_load_file(3) en su lugar.

NOTA: En modo FIPS, los datos aleatorios proporcionados por la aplicación no se consideran una fuente de entropía confiable. Se mezclan en el estado interno del RNG como datos adicionales únicamente y esto no cuenta como una reinicialización completa. Para más detalles, ver EVP_RAND(7).

RAND_seed() es equivalente a RAND_add() con randomness establecido a num.

RAND_keep_random_devices_open() se utiliza para controlar el uso de descriptores de archivo por las fuentes de semilla aleatoria. Algunas fuentes de semilla mantienen descriptores de archivo abiertos por defecto, lo que permite que dichas fuentes operen en una chroot(2) jail sin los nodos de dispositivo asociados disponibles. Cuando el argumento keep es cero, esta llamada deshabilita la retención de descriptores de archivo. Por el contrario, un argumento distinto de cero habilita la retención de descriptores de archivo. Esta función se suele llamar durante la inicialización y surte efecto inmediatamente. Esta capacidad solo se aplica al proveedor predeterminado.

RAND_event() y RAND_screen() son equivalentes a RAND_poll() y existen solo por razones de compatibilidad. Ver la sección HISTORIAL a continuación.

VALORES DE RETORNO

RAND_status() devuelve 1 si el generador aleatorio ha sido inicializado con suficientes datos, 0 en caso contrario.

RAND_poll() devuelve 1 si generó datos de semilla, 0 en caso contrario.

RAND_event() devuelve RAND_status().

Las otras funciones no devuelven valores.

VER TAMBIÉN

RAND_bytes(3), RAND_egd(3), RAND_load_file(3), RAND(7) EVP_RAND(7)

HISTORIAL

RAND_event() y RAND_screen() fueron marcadas como obsoletas en OpenSSL 1.1.0 y no deben ser usadas.
