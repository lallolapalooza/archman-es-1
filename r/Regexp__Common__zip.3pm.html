NAME

Regexp::Common::zip -- provide regexes for postal codes.

SYNOPSIS

use Regexp::Common qw /zip/;
while (<>) {
    /^$RE{zip}{Netherlands}$/   and  print "Dutch postal code\n";
}

DESCRIPTION

Please consult the manual of Regexp::Common for a general description of the works of this interface.

Do not use this module directly, but load it via Regexp::Common.

This module offers patterns for zip or postal codes of many different countries. They all have the form "$RE{zip}{Country}[{options}]".

The following common options are used:

"{-prefix=[yes|no|allow]}" and "{-country=PAT}".

Postal codes can be prefixed with a country abbreviation. That is, a Dutch postal code of 1234 AB can also be written as NL-1234 AB. By default, all the patterns will allow the prefixes. But this can be changed with the "-prefix" option. With "-prefix=yes", the returned pattern requires a country prefix, while "-prefix=no" disallows a prefix. Any argument that doesn't start with a "y" or a "n" allows a country prefix, but doesn't require them.

The prefixes used are, unfortunately, not always the same. Officially, ISO country codes need to be used, but the usage of CEPT codes (the same ones as used on cars) is common too. By default, each postal code will recognize a country prefix that's either the ISO standard or the CEPT code. That is, German postal codes may prefixed with either "DE" or "D". The recognized prefix can be changed with the "-country" option, which takes a (sub)pattern as argument. The arguments "iso" and "cept" are special, and indicate the language prefix should be the ISO country code, or the CEPT code.

Examples:
/$RE{zip}{Netherlands}/;
# Matches '1234 AB' and 'NL-1234 AB'.
/$RE{zip}{Netherlands}{-prefix => 'no'}/;
# Matches '1234 AB' but not 'NL-1234 AB'.
/$RE{zip}{Netherlands}{-prefix => 'yes'}/;
# Matches 'NL-1234 AB' but not '1234 AB'.

/$RE{zip}{Germany}/;
          # Matches 'DE-12345' and 'D-12345'.
/$RE{zip}{Germany}{-country => 'iso'}/; 
          # Matches 'DE-12345' but not 'D-12345'.
/$RE{zip}{Germany}{-country => 'cept'}/;
          # Matches 'D-12345' but not 'DE-12345'.
/$RE{zip}{Germany}{-country => 'GER'}/;
          # Matches 'GER-12345'.

"{-sep=PAT}"

Some countries have postal codes that consist of two parts. Typically there is an official way of separating those parts; but in practise people tend to use different separators. For instance, if the official way to separate parts is to use a space, it happens that the space is left off. The "-sep" option can be given a pattern as argument which indicates what to use as a separator between the parts.

Examples:
/$RE{zip}{Netherlands}/;
# Matches '1234 AB' but not '1234AB'.
/$RE{zip}{Netherlands}{-sep => '\s*'}/;
# Matches '1234 AB' and '1234AB'.

""$RE{zip}{Australia}{-lax}""

Returns a pattern that recognizes Australian postal codes. Australian postal codes consist of four digits; the first two digits, which range from '10' to '97', indicate the state, although there are exceptions. Territories use '02' or '08' as starting digits. '0909' is the only postal code starting with '09' - this is the postal code for the Northern Territory University). The (optional) country prefixes are AU (ISO country code) and AUS (CEPT code).

It the past, it was claimed that for postal codes starting with a 0, the leading 0 may be omitted, and up to (and including) version 2016060201, the leading 0 was optional. But there doesn't seem be solid evidence the leading 0 is optional. So, we now require there always to be four digit -- unless the "{-lax}" option is given, then a possibly leading 0 is optional.

Regexp::Common 2.107 and before used "$RE{zip}{Australian}". This is still supported.

If "{-keep}" is used, the following variables will be set:

$1
The entire postal code.
$2
The country code prefix.
$3
The postal code without the country prefix.

As of version 2016060201, no $4 or $5 will be set.

"$RE{zip}{Germany}"

Devuelve un patrón que reconoce códigos postales alemanes. Los códigos postales alemanes constan de cinco números; los dos primeros números indican un área postal más amplia, los tres últimos dígitos un distrito postal. Los prefijos de país (opcionales) son DE (código de país ISO) y D (código CEPT). Regexp::Common 2.107 y anteriores usaban "$RE{zip}{German}". Esto todavía es compatible.

Si se usa "{-keep}", se establecerán las siguientes variables:

$1
El código postal completo.
$2
El prefijo del código de país.
$3
El código postal sin el prefijo del país.

"$RE{zip}{Greenland}"

Devuelve un patrón que reconoce códigos postales de Groenlandia. Groenlandia utiliza el sistema de códigos postales danés. Los códigos postales que comienzan con 39 están reservados para Groenlandia, y todos los códigos postales groenlandeses comienzan con 39. Excepto el código postal de Santa. Él usa 2412.

El prefijo de país (opcional) es GL, que se utiliza tanto como código de país ISO como código CEPT. Las versiones anteriores usaban DK como prefijo.

Si se usa "{-keep}", se establecerán las siguientes variables:

$1
El código postal completo.
$2
El prefijo del código de país.
$3
El código postal sin el prefijo del país.

"$RE{zip}{Italy}"

Devuelve un patrón que reconoce códigos postales italianos. Los códigos postales italianos constan de 5 dígitos. El primer dígito indica la región, el segundo la provincia. El tercer dígito es impar para las capitales de provincia y par para la propia provincia. El cuarto dígito indica la ruta y el quinto una posición en la ruta (0 para lugares pequeños, alfabéticamente para el resto).

Los códigos que comienzan con 4789 son códigos postales para San Marino; no son reconocidos por el patrón. Utilice "$RE {zip} {'San Marino'}" en su lugar.

El prefijo de país es IT (el código de país ISO) o I (el código CEPT).

Si se usa "{-keep}", se establecerán las siguientes variables:

El código postal completo.
$2
El prefijo del código de país.
$3
El código postal sin el prefijo del país.

Los códigos postales que comienzan con 94 y utilizan 8 o 9 como tercer dígito son códigos postales para Liechtenstein.

Si se usa "{-keep}", se establecerán las siguientes variables:

El código postal completo.
$2
El prefijo del código de país.
$3
El código postal sin el prefijo del país.

El prefijo de país ISO es LI, el prefijo de país CEPT es LIE.

Devuelve un patrón para los códigos postales utilizados en Mónaco. Mónaco utiliza un rango del sistema utilizado en Francia. Son 5 dígitos, comenzando con 980. El número 98000 se utiliza para direcciones físicas. Los números que terminan en 01 a 99 se utilizan para entregas especiales.

$1
El código postal completo.
$2
El prefijo del código de país.
$3
El código postal sin el prefijo del país.

El prefijo de país es CH, tanto para los prefijos ISO como CEPT.

"$RE{zip}{US}{-extended => [yes|no|allow]}"

Devuelve un patrón que reconoce los códigos postales de EE. UU. Los códigos postales de EE. UU. constan de 5 dígitos, con una extensión opcional de 4 dígitos. Por defecto, las extensiones están permitidas, pero no son obligatorias. Esto puede verse influenciado por la opción "-extended". Si su argumento comienza con "y", las extensiones son obligatorias; si el argumento comienza con "n", las extensiones no serán reconocidas. Si se utiliza una extensión, se utiliza un guion para separar la parte principal de la extensión, pero esto se puede cambiar con la opción "-sep".

El prefijo de país es US (el código de país ISO) o USA (el código CEPT).

Si se está utilizando "{-keep}", se establecerán las siguientes variables:

$1
El código postal completo.
$2
El prefijo del código de país.
$3
El código postal sin el prefijo del país.
$4
Los primeros 5 dígitos del código postal.
$5
Los primeros tres dígitos del código postal, que indican un centro seccional o una ciudad grande. Nuevo en Regexp::Common 2.119.
$6
Los últimos 2 dígitos de la parte de 5 dígitos del código postal, que indican una instalación de oficina de correos o un área de entrega. Nuevo en Regexp::Common 2.119.
$7
El separador entre la parte de 5 dígitos y la parte de 4 dígitos. Hasta Regexp::Common 2.118, esto solía ser $5.
$8
La parte de 4 dígitos del código postal (si la hay). Hasta Regexp::Common 2.118, esto solía ser $6.
$9
Los primeros dos dígitos de la parte de 4 dígitos del código postal, que indican un sector o varios bloques. Nuevo en Regexp::Common 2.119.
$10
Los últimos 2 dígitos de la parte de 4 dígitos del código postal, que indican un área de entrega dentro del sector. Nuevo en Regexp::Common 2.119.
Regexp::Common::zip - Regular expressions for postal codes

NAME

Regexp::Common::zip - Regular expressions for postal codes

SYNOPSIS

    use Regexp::Common;
    use Regexp::Common qw(:zip);

    # US zip codes
    if ( $string =~ /$RE{zip}{US}/ ) { ... }

    # Canadian postal codes
    if ( $string =~ /$RE{zip}{CA}/ ) { ... }

    # UK postal codes
    if ( $string =~ /$RE{zip}{UK}/ ) { ... }

    # UK postal codes, with options
    if ( $string =~ /$RE{zip}{UK, 'outward', 'inward'}/ ) { ... }

    # Vatican City postal codes
    if ( $string =~ /$RE{zip}{'Vatican City'}/ ) { ... }

    # More specific UK postal codes
    if ( $string =~ /$RE{zip}{'UK', 'outward'}/ ) { ... }
    if ( $string =~ /$RE{zip}{'UK', 'inward'}/ ) { ... }

    # All postal codes
    if ( $string =~ /$RE{zip}/ ) { ... }

DESCRIPTION

This module provides regular expressions for matching various national postal codes.

The following postal codes are supported:

US
United States ZIP codes. These can be either 5 digits, or 5 digits, a hyphen, and 4 digits.
CA
Canadian postal codes. These are of the form letter-digit-letter digit-letter-digit, with no spaces.
UK
United Kingdom postal codes. These are quite complex. See http://www.parliament.uk/commons/lib/research/briefings/sn03042.pdf for details.

The regular expressions may be invoked using the Regexp::Common interface, e.g. $RE{zip}{US}.

If Regexp::Common is imported with the :zip tag, then $RE{zip} is available for direct use.

If the optional argument {-keep} is passed to the regular expression, then the following variables will be set:

$1
The entire postal code.
$2
The country code (e.g. US, CA, UK).
$3
The country-specific postal code itself.

If {-keep} is used with the UK postal code, then the following variables will also be set:

$4
The outward code (the first part of the UK postal code).
$5
The inward code (the second part of the UK postal code).

The UK postal code is the most complex. It can be specified in several ways:

$RE{zip}{'UK'}
Matches the entire UK postal code.
$RE{zip}{'UK', 'outward'}
Matches only the outward code.
$RE{zip}{'UK', 'inward'}
Matches only the inward code.
$RE{zip}{'UK', 'outward', 'inward'}
Matches the entire UK postal code, and sets $4 to the outward code and $5 to the inward code.

For example:

    if ( $string =~ /$RE{zip}{US, -keep}/ ) {
        my ($entire, $country, $zip) = ($1, $2, $3);
        # ...
    }

    if ( $string =~ /$RE{zip}{UK, -keep}/ ) {
        my ($entire, $country, $outward, $inward) = ($1, $2, $3, $4);
        # ...
    }

Note: The $3 variable when matching the UK postal code using $RE{zip}{UK} will contain the entire postal code.

The regular expression $RE{zip} (with no arguments) matches any of the supported postal codes.

New in Regexp::Common 2.119.

A regular expression for the two last digits of the 4 digit part of the postal code, indicating a segment or one side of a street. New in Regexp::Common 2.119.

Questions

  • Can the 5 digit part of the zip code (in theory) start with 000?
  • Can the 5 digit part of the zip code (in theory) end with 00?
  • Can the 4 digit part of the zip code (in theory) start with 00?
  • Can the 4 digit part of the zip code (in theory) end with 00?

"$RE {zip} {'Vatican City'}"

Vatican City uses a single postal code; taken from the Italian system of postal codes, and sharing the single code with a part of Rome.

If "{-keep}" is used, the following variables will be set:

$1
The entire postal code.
$2
The country code prefix.
$3
The postal code without the country prefix.

The country prefix for Vatican City is "VA".
