DESCRIPCIÓN

Se admiten curvas con radios por vértice con bases lineales, Bézier cúbicas, B-spline cúbicas y Hermite cúbicas. Dichas geometrías de curva se crean pasando RTC_GEOMETRY_TYPE_FLAT_LINEAR_CURVE, RTC_GEOMETRY_TYPE_FLAT_BEZIER_CURVE, RTC_GEOMETRY_TYPE_FLAT_BSPLINE_CURVE, RTC_GEOMETRY_TYPE_FLAT_HERMITE_CURVE, RTC_GEOMETRY_TYPE_FLAT_CATMULL_ROM_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_BEZIER_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_BSPLINE_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_HERMITE_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_CATMULL_ROM_CURVE, RTC_GEOMETRY_TYPE_CONE_LINEAR_CURVE, RTC_GEOMETRY_TYPE_ROUND_LINEAR_CURVE, RTC_GEOMETRY_TYPE_ROUND_BEZIER_CURVE, RTC_GEOMETRY_TYPE_ROUND_BSPLINE_CURVE, RTC_GEOMETRY_TYPE_ROUND_HERMITE_CURVE o RTC_GEOMETRY_TYPE_ROUND_CATMULL_ROM_CURVE a la función rtcNewGeometry. Los índices de la curva se pueden especificar a través de un búfer de índices (RTC_BUFFER_TYPE_INDEX) y los vértices de la curva a través de un búfer de vértices (RTC_BUFFER_TYPE_VERTEX). Para la base Hermite, se debe especificar además un búfer de tangentes (RTC_BUFFER_TYPE_TANGENT), para curvas orientadas a normales un búfer de normales (RTC_BUFFER_TYPE_NORMAL) y para curvas Hermite orientadas a normales un búfer de derivadas normales (RTC_BUFFER_TYPE_NORMAL_DERIVATIVE). Consulte rtcSetGeometryBuffer y rtcSetSharedGeometryBuffer para obtener más detalles sobre cómo establecer búferes.

El búfer de índices contiene una matriz de índices de 32 bits (formato RTC_FORMAT_UINT), cada uno apuntando al primer vértice de control en el búfer de vértices, pero también a la primera tangente en el búfer de tangentes y a la primera normal en el búfer de normales si estos búferes están presentes.

El búfer de vértices almacena cada vértice de control en forma de una posición y un radio de precisión simple almacenados en orden (x, y, z, r) en memoria (formato RTC_FORMAT_FLOAT4). El número de vértices se infiere del tamaño de este búfer. Los radios pueden ser menores que cero, pero los radios interpolados siempre deben ser mayores o iguales a cero. Del mismo modo, el búfer de tangentes almacena la derivada de cada vértice de control (orden (x, y, z, r) y formato RTC_FORMAT_FLOAT4) y el búfer de normales almacena una normal de precisión simple por vértice de control (orden (x, y, z) y formato RTC_FORMAT_FLOAT3).

Base Lineal

Para la base lineal, los índices apuntan a los primeros de 2 puntos de control consecutivos en el búfer de vértices. El primer punto de control es el inicio y el segundo punto de control el final del segmento de línea. Al construir hebras de cabello en esta base, el punto final puede compartirse con el inicio del siguiente segmento de línea.

Para la base lineal, el usuario puede proporcionar opcionalmente un búfer de flags de tipo RTC_BUFFER_TYPE_FLAGS que contiene bytes que codifican si el segmento vecino izquierdo (flag RTC_CURVE_FLAG_NEIGHBOR_LEFT) y/o el segmento vecino derecho (flags RTC_CURVE_FLAG_NEIGHBOR_RIGHT) existen (ver [RTCCurveFlags]). Si este búfer no se establece, los bits de vecino izquierdo/derecho se calculan automáticamente basándose en el búfer de índices (el segmento izquierdo existe si segment(id-1)+1 == segment(id) y el segmento derecho existe si segment(id+1)-1 == segment(id)).

Se asume que un segmento vecino izquierdo termina en el vértice de inicio del segmento actual y comienza en el vértice anterior del búfer de vértices. Del mismo modo, se asume que el segmento vecino derecho comienza en el vértice final del segmento actual y termina en el vértice siguiente del búfer de vértices.

Solo cuando los bits izquierdo y derecho se especifican correctamente, el segmento actual puede unirse correctamente al vecino izquierdo y/o derecho, de lo contrario, el área de contacto puede no renderizarse correctamente.

Base Bézier

Para la base Bézier cúbica, los índices apuntan a los primeros de 4 puntos de control consecutivos en el búfer de vértices. Estos puntos de control utilizan la base Bézier cúbica, donde el primer punto de control representa el punto de inicio de la curva y el cuarto punto de control el punto final de la curva. La base Bézier es interpolante, por lo que la curva pasa exactamente a través del primer y cuarto vértice de control.

Base B-spline

Para la base B-spline cúbica, los índices apuntan a los primeros de 4 puntos de control consecutivos en el búfer de vértices. Estos puntos de control forman una B-spline cúbica cardinal (vector de nudos equidistantes implícito). Esta base no es interpolante, por lo que la curva en general no pasa directamente por ninguno de los puntos de control. Una gran ventaja de esta base es que 3 puntos de control pueden compartirse para dos segmentos de curva continuos vecinos, por ejemplo, las curvas (p0,p1,p2,p3) y (p1,p2,p3,p4) son C1 continuas. Esta característica hace de esta base una buena opción para construir curvas continuas de múltiples segmentos, ya que el consumo de memoria se puede mantener al mínimo.

Base Hermite

Para la base Hermite cúbica, los índices apuntan al primer de 2 puntos consecutivos en el búfer de vértices y al primero de 2 tangentes consecutivas en el búfer de tangentes. Estos dos puntos y dos tangentes forman una curva Hermite cúbica. Esta base es interpolante, por lo que pasa exactamente a través del primer y segundo punto de control, y la derivada de primer orden en el inicio y el final coincide exactamente con el valor especificado en el búfer de tangentes. Al conectar dos segmentos continuamente, el punto final y la tangente del segmento anterior pueden compartirse. Se pueden construir fácilmente diferentes versiones de splines de Catmull-Rom utilizando la base Hermite, calculando un búfer de tangentes apropiado a partir de los puntos de control.

Base Catmull-Rom

Para la base Catmull-Rom, los índices apuntan al primer de 4 puntos de control consecutivos en el búfer de vértices. Esta base pasa por p1 y p2, con tangentes (p2-p0)/2 y (p3-p1)/2.

NAME

RTC_GEOMETRY_TYPE_CURVE - curve geometry type

DESCRIPTION

The curve geometry type allows you to create curves for rendering and ray tracing. Curves are specified by vertex buffers that hold the control points of the curve segments. The type of basis (linear, quadratic, cubic) determines how these control points are interpreted.

You can create a curve geometry through the rtcNewGeometry function call and specify the geometry type as RTC_GEOMETRY_TYPE_FLAT_LINEAR_BSPLINE, RTC_GEOMETRY_TYPE_FLAT_QUADRATIC_BSPLINE, RTC_GEOMETRY_TYPE_FLAT_CUBIC_BSPLINE, RTC_GEOMETRY_TYPE_FLAT_MONOTONIC_CUBIC_BSPLINE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_LINEAR_BSPLINE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_QUADRATIC_BSPLINE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_CUBIC_BSPLINE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_MONOTONIC_CUBIC_BSPLINE, RTC_GEOMETRY_TYPE_ROUND_LINEAR, RTC_GEOMETRY_TYPE_ROUND_QUADRATIC_BSPLINE, RTC_GEOMETRY_TYPE_ROUND_CUBIC_BSPLINE, RTC_GEOMETRY_TYPE_ROUND_MONOTONIC_CUBIC_BSPLINE.

The curve geometry requires at least one vertex buffer. The format of the vertex buffer depends on the curve type and basis. For basis types like B-splines, vertices are typically stored as an array of structures, where each structure contains the control points for a curve segment. For Hermite splines, you need to provide vertices and tangents.

For cubic B-spline curves, Embree supports Catmull-Rom splines through the RTC_GEOMETRY_TYPE_FLAT_CATMULL_ROM, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_CATMULL_ROM, and RTC_GEOMETRY_TYPE_ROUND_CATMULL_ROM geometry types. These curves pass through their control points, making them suitable for animation paths.

The tessellation rate determines how many quads each curve segment is subdivided into for rendering. Individual quads are considered to have subpixel size, and zooming onto the curve might show geometric artifacts. The number of quads to subdivide into can be specified through the rtcSetGeometryTessellationRate function. By default the tessellation rate is 4.

Normal Oriented Curves

The RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_* mode is a mode designed to render blades of grass. In this mode a vertex spline has to get specified as for the previous modes, but additionally a normal spline is required. If the Hermite basis is used, the RTC_BUFFER_TYPE_NORMAL and RTC_BUFFER_TYPE_NORMAL_DERIVATIVE buffers have both to be set.

The curve is rendered as a flat band whose center approximately follows the provided vertex spline, whose half width approximately follows the provided radius spline, and whose normal orientation approximately follows the provided normal spline.

To intersect the normal oriented curve, we perform a newton-raphson style intersection of a ray with a tensor product surface of a linear basis (perpendicular to the curve) and cubic Bézier basis (along the curve). We use a guide curve and its derivatives to construct the control points of that surface. The guide curve is defined by a sweep surface defined by sweeping a line centered at the vertex spline location along the curve. At each parameter value the half width of the line matches the radius spline, and the direction matches the cross product of the normal from the normal spline and tangent of the vertex spline. Note that this construction does not work when the provided normals are parallel to the curve direction. For this reason the provided normals should best be kept as perpendicular to the curve direction as possible. We further assume second order derivatives of the center curve to be zero for this construction, as otherwise very large curvatures occurring in corner cases, can thicken the constructed curve significantly.

Round Curves

In the RTC_GEOMETRY_TYPE_ROUND_* round mode, a real geometric surface is rendered for the curve, which is more expensive but allows closeup views.

For the linear basis the round mode renders a cone that tangentially touches a start-sphere and end-sphere. The start sphere is rendered when no previous segments is indicated by the neighbor bits. The end sphere is always rendered but parts that lie inside the next segment are clipped away (if that next segment exists). This way a curve is closed on both ends and the interior will render properly as long as only neighboring segments penetrate into a segment. For this to work properly it is important that the flags buffer is properly populated with neighbor information.

For the cubic polynomial bases, the round mode renders a sweep surface by sweeping a varying radius circle tangential along the curve. As a limitation, the radius of the curve has to be smaller than the curvature radius of the curve at each location on the curve.

The intersection with the curve segment stores the parametric hit location along the curve segment as u-coordinate (range 0 to +1).

For flat curves, the v-coordinate is set to the normalized distance in the range -1 to +1. For normal oriented curves the v-coordinate is in the range 0 to 1. For the linear basis and in round mode the v-coordinate is set to zero.

In flat mode, the geometry normal Ng is set to the tangent of the curve at the hit location. In round mode and for normal oriented curves, the geometry normal Ng is set to the non-normalized geometric normal of the surface.

For multi-segment motion blur, the number of time steps must be first specified using the rtcSetGeometryTimeStepCount call. Then a vertex buffer for each time step can be set using different buffer slots, and all these buffers must have the same stride and size. For the Hermite basis also a tangent buffer has to be set for each time step and for normal oriented curves a normal buffer has to get specified for each time step.

Also see tutorials [Hair] and [Curves] for examples of how to create and use curve geometries.

EXIT STATUS

On failure NULL is returned and an error code is set that can be queried using rtcGetDeviceError.
