DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negros.

En las definiciones de macros, TYPE es la etiqueta de nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD, del tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es la etiqueta de nombre de una estructura definida por el usuario que debe declararse usando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME debe ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Consulte los ejemplos a continuación para obtener más explicaciones sobre cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos auto-organizativa. Cada operación en el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de las solicitudes provoca búsquedas más rápidas, ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en memoria.

El Teorema de Balance limita el tiempo total de acceso para m operaciones y n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y struct TYPE es el tipo de los elementos a insertar en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos del árbol entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debe devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol referenciado por head.

El árbol splay también se puede inicializar estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si un elemento coincidente ya existe en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede utilizar para encontrar un elemento particular en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden usar para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para mayor simplicidad, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGROS

Un árbol rojo-negro es un árbol de búsqueda binaria con el color del nodo como un atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y struct TYPE es el tipo de los elementos a insertar en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

Los cuerpos de las funciones se generan con las macros RB_GENERATE() o RB_GENERATE_STATIC(). Estas macros toman los mismos argumentos que las macros RB_PROTOTYPE() y RB_PROTOTY

LIBRARY

The tree macros are provided by libbsd. To use them, define -lbsd and include <sys/tree.h>.

DESCRIPTION

These macros provide an implementation of red-black trees. A red-black tree is a binary search tree where each node has a color, red or black. These colors are used to ensure that the tree remains balanced during insertions and deletions. Red-black trees are self-balancing, meaning that they automatically adjust their structure to maintain a maximum depth of O(log n), where n is the number of nodes in the tree. This ensures that operations like search, insertion, and deletion have a time complexity of O(log n).

To use the red-black tree macros, you must first define a structure for your tree nodes. This structure must include a field that will serve as the entry point for the red-black tree macros. This field must be of type RB_ENTRY(TYPE), where TYPE is the name of your node structure.

For example, if you want to create a tree of integers, you might define your node structure as follows:

struct my_node {
        RB_ENTRY(my_node) next;
        int value;
        /* other data */
};

Next, you must define the head of the tree using the RB_HEAD() macro. The first argument is the name of the tree head structure, and the second argument is the name of your node structure.

RB_HEAD(my_tree_head, my_node) my_tree;

Then, you must declare the tree's comparison function. This function is used to compare nodes within the tree. It takes two pointers to your node structure as arguments and returns a negative value if the first node is less than the second, zero if they are equal, and a positive value if the first node is greater than the second. The comparison function determines the order of elements in the tree.

int my_compare_function(struct my_node *a, struct my_node *b);

Finally, you must generate the tree functions using the RB_GENERATE() macro. This macro takes the tree head name, the node structure name, the name of the entry field within the node structure, and the comparison function as arguments.

RB_GENERATE(my_tree_head, my_node, next, my_compare_function);

Note that you should only call RB_GENERATE() once for each tree type in your program. If you need to use the tree functions in multiple files, you should use the RB_PROTOTYPE() macro in the other files.

SPLAY TREES

The macros SPLAY_HEAD, SPLAY_PROTOTYPE, SPLAY_GENERATE, SPLAY_INSERT, SPLAY_REMOVE, SPLAY_FIND, SPLAY_NFIND, SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, SPLAY_NEXT, SPLAY_PREV, SPLAY_INIT, SPLAY_INITIALIZER, SPLAY_EMPTY, SPLAY_FOREACH, SPLAY_FOREACH_REVERSE, SPLAY_FOREACH_SAFE, and SPLAY_FOREACH_REVERSE_SAFE are also available for splay trees. The usage is identical to the red-black tree macros, except that you should include <sys/tree.h> and use the splay tree macros instead of the red-black tree macros. Splay trees are self-adjusting binary search trees that automatically move frequently accessed nodes closer to the root. This can improve performance for applications with non-uniform access patterns. Like red-black trees, splay tree operations have a time complexity of O(log n) in the average case, but can degrade to O(n) in the worst case.

RED-BLACK TREES

The macros RB_HEAD, RB_PROTOTYPE, RB_GENERATE, RB_INSERT, RB_REMOVE, RB_FIND, RB_NFIND, RB_ROOT, RB_MIN, RB_MAX, RB_NEXT, RB_PREV, RB_INIT, RB_INITIALIZER, RB_EMPTY, RB_FOREACH, RB_FOREACH_REVERSE, RB_FOREACH_SAFE, and RB_FOREACH_REVERSE_SAFE are used to implement red-black trees. The arguments are as follows:

RB_HEAD(HEADNAME, TYPE)
Declares a structure named HEADNAME that will be used as the head of a red-black tree containing nodes of type TYPE.
RB_PROTOTYPE(NAME, TYPE, FIELD, CMP)
Declares the function prototypes for the red-black tree functions. This should be used in header files or when the tree functions are defined in a different source file. NAME is the name used for the tree functions (e.g., the HEADNAME from RB_HEAD). TYPE is the node structure name. FIELD is the name of the RB_ENTRY field within the node structure. CMP is the name of the comparison function.
RB_GENERATE(NAME, TYPE, FIELD, CMP)
Generates the implementation of the red-black tree functions. This macro should be used in exactly one source file. The arguments are the same as for RB_PROTOTYPE.
RB_INSERT(NAME, head, elm)
Inserts the element elm into the red-black tree pointed to by head. NAME is the tree name used in RB_GENERATE. If insertion is successful, a pointer to the inserted element is returned. If an element with the same key already exists in the tree, insertion is aborted and a pointer to the existing element is returned.
RB_REMOVE(NAME, head, elm)
Removes the element elm from the red-black tree pointed to by head. NAME is the tree name. The function returns a pointer to the removed element, elm.
RB_FIND(NAME, head, elm)
Finds an element in the tree that matches the key of elm. NAME is the tree name. Returns a pointer to the found element, or NULL if no match is found.
RB_NFIND(NAME, head, elm)
Finds the first element in the tree whose key is greater than or equal to the key of elm. NAME is the tree name. Returns a pointer to the found element, or NULL if no such element is found.
RB_ROOT(head)
Returns a pointer to the root node of the tree pointed to by head.
RB_MIN(NAME, head)
Returns a pointer to the node with the smallest key in the tree. NAME is the tree name.
RB_MAX(NAME, head)
Returns a pointer to the node with the largest key in the tree. NAME is the tree name.
RB_NEXT(NAME, head, elm)
Returns a pointer to the next node in the tree after elm in ascending order. NAME is the tree name.
RB_PREV(NAME, head, elm)
Returns a pointer to the previous node in the tree before elm in ascending order. NAME is the tree name.
RB_INIT(head)
Initializes the red-black tree pointed to by head. This macro should be used to initialize a tree before it is used.
RB_INITIALIZER(head)
Returns an initializer for a red-black tree head structure. This can be used for static initialization of a tree.
RB_EMPTY(head)
Returns true if the tree pointed to by head is empty, and false otherwise.
RB_FOREACH(var, NAME, head)
A loop that iterates over all nodes in the tree in ascending order. var will be assigned each node in turn. NAME is the tree name.
RB_FOREACH_REVERSE(var, NAME, head)
A loop that iterates over all nodes in the tree in descending order. var will be assigned each node in turn. NAME is the tree name.
RB_FOREACH_SAFE(var, NAME, head)
A loop that iterates over all nodes in the tree in ascending order. This macro is similar to RB_FOREACH, but it is safe to remove nodes from the tree within the loop. var will be assigned each node in turn. NAME is the tree name.
RB_FOREACH_REVERSE_SAFE(var, NAME, head)
A loop that iterates over all nodes in the tree in descending order. This macro is similar to RB_FOREACH_REVERSE, but it is safe to remove nodes from the tree within the loop. var will be assigned each node in turn. NAME is the tree name.

The comparison function CMP takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
