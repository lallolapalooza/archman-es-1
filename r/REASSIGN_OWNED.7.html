NOMBRE

REASSIGN_OWNED - cambiar la propiedad de objetos de base de datos pertenecientes a un rol de base de datos

SINOPSIS

REASSIGN OWNED BY { rol_antiguo | CURRENT_ROLE | CURRENT_USER | SESSION_USER } [, ...]
               TO { rol_nuevo | CURRENT_ROLE | CURRENT_USER | SESSION_USER }

DESCRIPCIÓN

REASSIGN OWNED indica al sistema que cambie la propiedad de objetos de base de datos pertenecientes a cualquiera de los roles_antiguos a rol_nuevo.

PARÁMETROS

rol_antiguo

El nombre de un rol. La propiedad de todos los objetos dentro de la base de datos actual, y de todos los objetos compartidos (bases de datos, tablespaces), pertenecientes a este rol se reasignará a rol_nuevo.

rol_nuevo

El nombre del rol que se convertirá en el nuevo propietario de los objetos afectados.

NOTAS

REASSIGN OWNED se utiliza a menudo para preparar la eliminación de uno o más roles. Dado que REASSIGN OWNED no afecta a los objetos dentro de otras bases de datos, generalmente es necesario ejecutar este comando en cada base de datos que contenga objetos pertenecientes a un rol que se va a eliminar.

REASSIGN OWNED requiere membresía tanto en los roles de origen como en el rol de destino.

El comando DROP OWNED es una alternativa que simplemente elimina todos los objetos de base de datos pertenecientes a uno o más roles.

El comando REASSIGN OWNED no afecta a ningún privilegio otorgado a los roles_antiguos sobre objetos que no les pertenecen. Del mismo modo, no afecta a los privilegios predeterminados creados con ALTER DEFAULT PRIVILEGES. Utilice DROP OWNED para revocar dichos privilegios.

Consulte la Sección 21.4 para obtener más información.

COMPATIBILIDAD

El comando REASSIGN OWNED es una extensión de PostgreSQL.

VER TAMBIÉN
