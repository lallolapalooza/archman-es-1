NOMBRE

Regexp::Common::URI::ftp -- Devuelve un patrón para URIs FTP.

SINOPSIS

use Regexp::Common qw /URI/;
while (<>) {
    /$RE{URI}{FTP}/       and  print "Contiene una URI FTP.\n";
}

DESCRIPCIÓN

$RE{URI}{FTP}{-type}{-password};

Devuelve una expresión regular para URIs FTP. Nota: Las URIs FTP no están definidas formalmente. RFC 1738 define URLs FTP, pero partes de ese RFC han sido obsoletas por RFC 2396. Sin embargo, las diferencias entre RFC 1738 y RFC 2396 son tales que no son aplicables directamente a las URIs FTP.

Hay dos problemas principales:

Contraseñas.
RFC 1738 permitía un nombre de usuario opcional y una contraseña opcional (separados por dos puntos) en la URL FTP. Por lo tanto, los dos puntos no estaban permitidos en el nombre de usuario ni en la contraseña. RFC 2396 recomienda encarecidamente que las contraseñas no se utilicen en las URIs. Permite userinfo en su lugar. Esta parte de userinfo puede contener dos puntos y, por lo tanto, contener más de un par de dos puntos. La expresión regular devuelta sigue la especificación RFC 2396, a menos que se proporcione la opción {-password}; en ese caso, la expresión regular permite un nombre de usuario y una contraseña opcionales, separados por dos puntos.
El especificador ;type.
RFC 1738 no permite puntos y comas en los nombres de ruta FTP, ya que el punto y coma es un carácter reservado para las URIs FTP. El punto y coma se utiliza para separar la ruta del especificador de opción type. Sin embargo, en RFC 2396, las rutas consisten en segmentos separados por barras, y cada segmento es un grupo de parámetros separados por punto y coma. La aplicación directa de RFC 2396 significaría que un especificador de type final no podría distinguirse del último segmento de la ruta que tiene dos parámetros, el último de los cuales comienza con type=. Por lo tanto, hemos optado por no permitir un punto y coma en la parte de la ruta de una URI FTP.

Además, RFC 1738 permite tres valores para el especificador type: A, I y D (mayúscula o minúscula). Sin embargo, el borrador de Internet sobre URIs FTP [DRAFT-FTP-URL] (que expiró en mayo de 1997) señala la falta de implementación consistente del parámetro D y elimina D del conjunto de valores posibles. Seguimos esta práctica; sin embargo, el comportamiento de RFC 1738 se puede lograr utilizando el parámetro -type = "[ADIadi]">.

Las URIs FTP tienen la siguiente sintaxis:

"ftp:" "//" [ userinfo "@" ] host [ ":" port ]
            [ "/" path [ ";type=" value ]]

Al usar {-password}, tenemos la sintaxis:

"ftp:" "//" [ user [ ":" password ] "@" ] host [ ":" port ]
            [ "/" path [ ";type=" value ]]

Bajo "{-keep}", se devuelven los siguientes:

$1
La URI completa.
$2
El esquema.
$3
El userinfo, o si se usa {-password}, el nombre de usuario.
$4
Si se usa {-password}, la contraseña, de lo contrario "undef".
$5
El nombre de host o la dirección IP.
$6
El número de puerto.
$7
La ruta completa y la especificación de tipo, incluida la barra inicial.
$8
La ruta completa y la especificación de tipo, sin la barra inicial.
$9
La ruta completa, sin la especificación de tipo ni la barra inicial.
$10
El valor de la especificación de tipo.
