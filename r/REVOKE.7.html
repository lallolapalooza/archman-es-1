NOMBRE

REVOKE - eliminar privilegios de acceso

SINOPSIS

REVOKE [ GRANT OPTION FOR ]
    { { SELECT | INSERT | UPDATE | DELETE | TRUNCATE | REFERENCES | TRIGGER | TRONCALAR }
    [, ...] | ALL [ PRIVILEGES ] }
    ON { [ TABLE ] nombre_tabla [, ...]
         | ALL TABLES IN SCHEMA nombre_esquema [, ...] }
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { SELECT | INSERT | UPDATE | REFERENCES } ( nombre_columna [, ...] )
    [, ...] | ALL [ PRIVILEGES ] ( nombre_columna [, ...] ) }
    ON [ TABLE ] nombre_tabla [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { USAGE | UPDATE } [, ...] | ALL [ PRIVILEGES ] }
    ON { SEQUENCE nombre_secuencia [, ...]
         | ALL SEQUENCES IN SCHEMA nombre_esquema [, ...] }
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { CREATE | CONNECT | TEMPORARY | TEMP } [, ...] | ALL [ PRIVILEGES ] }
    ON DATABASE nombre_base_datos [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON DOMAIN nombre_dominio [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON FOREIGN DATA WRAPPER nombre_fdw [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON FOREIGN SERVER nombre_servidor [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { EXECUTE | ALL [ PRIVILEGES ] }
    ON { { FUNCTION | PROCEDURE | ROUTINE } nombre_funcion [ ( [ [ argmode ] [ arg_name ] arg_type [, ...] ] ) ] [, ...]
         | ALL { FUNCTIONS | PROCEDURES | ROUTINES } IN SCHEMA nombre_esquema [, ...] }
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON LANGUAGE nombre_lenguaje [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { SELECT | UPDATE } [, ...] | ALL [ PRIVILEGES ] }
    ON LARGE OBJECT loid [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { SET | ALTER SYSTEM } [, ...] | ALL [ PRIVILEGES ] }
    ON PARAMETER parametro_configuracion [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ CREATE | USAGE } [, ...] | ALL [ PRIVILEGES ] }
    ON SCHEMA nombre_esquema [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { CREATE | ALL [ PRIVILEGES ] }
    ON TABLESPACE nombre_tablespace [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON TYPE nombre_tipo [, ...]
    FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
REVOKE [ { ADMIN | INHERIT | SET } OPTION FOR ]
    nombre_rol [, ...] FROM especificación_rol [, ...]
    [ GRANTED BY especificación_rol ]
    [ CASCADE | RESTRICT ]
donde especificación_rol puede ser:
    [ GROUP ] nombre_rol
  | PUBLIC
  | CURRENT_ROLE
  | CURRENT_USER
  | SESSION_USER

DESCRIPCIÓN

El comando REVOKE revoca privilegios que fueron previamente otorgados a uno o más roles. El término PUBLIC se refiere al grupo implícito de todos los roles.

Ver la descripción del comando GRANT para el significado de los tipos de privilegios.

Nota: Cualquier rol tendrá la suma de los privilegios concedidos directamente a él, los privilegios concedidos a cualquier rol del cual sea miembro, y los privilegios concedidos a PUBLIC. Por lo tanto, revocar SELECT de PUBLIC no necesariamente significa que todos los roles pierdan SELECT en el objeto: aquellos que tienen el privilegio concedido directamente o a través de otro rol seguirán teniendo el privilegio. De manera similar, revocar SELECT de un usuario puede no impedir que este usuario use SELECT si PUBLIC o algún otro rol de membresía tiene los derechos de SELECT.

Si se especifica GRANT OPTION FOR, solo se revoca la opción de otorgar del privilegio, no el privilegio en sí mismo. De lo contrario, tanto el privilegio como la opción de otorgar son revocados.

Si un usuario tiene un privilegio con opción de otorgar y lo ha otorgado a otros usuarios, los privilegios que estos otros usuarios tienen se denominan privilegios dependientes. Si el privilegio o la opción de otorgar que tiene el primer usuario está siendo revocado y existen privilegios dependientes, estos también se revocarán si se especifica CASCADE; si no se especifica, la acción de revocación fallará. Esta revocación recursiva solo afecta los privilegios que fueron otorgados a través de una cadena de usuarios que se puede rastrear hasta el usuario que es el sujeto de este REVOKE. Por lo tanto, los usuarios afectados pueden mantener efectivamente el privilegio incluso si fue otorgado a través de otros usuarios.

Cuando se revocan privilegios en una tabla, los privilegios correspondientes de columna (si existen) se revocan automáticamente en cada columna de la tabla, al igual que los privilegios de columna. Por otro lado, si a un rol se le han otorgado privilegios en una tabla, revocar los mismos privilegios en columnas individuales no tiene efecto.

Cuando se revoca la membresía en un rol, GRANT OPTION se denomina ADMIN OPTION, pero el comportamiento es similar. Aunque en versiones anteriores a PostgreSQL 16, los privilegios dependientes no se registraban para las concesiones de membresía de rol, por lo que CASCADE no afectaba la membresía de rol. Esto ya no es el caso. Además, esta forma del comando no permite el término GROUP en especificación_rol.

Así como se puede eliminar ADMIN OPTION de una concesión existente, también es posible revocar INHERIT OPTION o SET OPTION. Esto es equivalente a establecer el valor de la opción correspondiente a FALSE.

NOTAS

Un usuario solo puede revocar privilegios que fueron otorgados directamente por él. Si, por ejemplo, el usuario A ha otorgado un privilegio con opción de otorgar al usuario B, y el usuario B lo ha otorgado a C, entonces el usuario A no puede revocar directamente el privilegio de C. En su lugar, el usuario A puede revocar la opción de otorgar del usuario B y usar la opción CASCADE para revocar el privilegio de C. Para otro ejemplo, si A y B han otorgado el mismo privilegio a C, A puede revocar su propia opción de otorgar, pero no la de B, por lo que C aún tendrá el privilegio.

Cuando un usuario intenta revocar privilegios en un objeto y no tiene permisos sobre el objeto, el comando fallará inmediatamente. Aunque algún privilegio pueda estar disponible, el comando se ejecutará, pero solo revocará aquellos privilegios para los cuales el usuario tenga opciones de otorgar. Las formas REVOKE ALL PRIVILEGES emitirán un mensaje de advertencia si no se tienen opciones de otorgar, mientras que las formas restantes emitirán un mensaje de advertencia si no se tienen opciones de otorgar para ningún privilegio nombrado específicamente en el comando.

Si un superusuario elige emitir un comando GRANT o REVOKE, el comando se ejecutará como si fuera emitido por el propietario del objeto afectado. (Pero los roles no tienen propietarios, por lo que en el caso de un GRANT de membresía de rol, el comando se ejecutará como si fuera emitido por el superusuario bootstrap). Dado que todos los privilegios provienen en última instancia del propietario del objeto (posiblemente de forma indirecta a través de cadenas de opciones de otorgar), es posible que un superusuario revoque todos los privilegios, pero esto podría requerir el uso de CASCADE como se mencionó.

REVOKE también puede ser realizado por un rol que no es el propietario del objeto afectado, pero que es miembro del rol que posee el objeto o es miembro de un rol que tiene privilegios con GRANT OPTION sobre el objeto. En este caso, el comando se ejecutará como si fuera emitido por el rol que realmente posee el objeto o que tiene los privilegios con GRANT OPTION. Por ejemplo, si la tabla t1 es propiedad del rol g1, del cual el rol u1 es miembro, entonces u1 puede revocar los privilegios de t1.

REVOKE(7) — PostgreSQL manual

NAME

REVOKE — remove security label declarations

SYNOPSIS

REVOKE [ GRANT OPTION FOR ] privilege [ ... ] [ ON [ TYPE ] objetivo [ ... ] ] FROM { miembro_rol | PUBLIC } [ ... ] [ CASCADE | RESTRICT ]

REVOKE [ GRANT OPTION FOR ] privilegio_rol [ ... ] FROM { miembro_rol | PUBLIC } [ ... ] [ CASCADE | RESTRICT ]

REVOKE [ GRANT OPTION FOR ] ADMIN opciones_rol [ ... ] FROM { miembro_rol | PUBLIC } [ ... ] [ CASCADE | RESTRICT ]

DESCRIPTION

REVOKE elimina una o más concesiones de privilegios de un rol. Los privilegios pueden ser privilegios de acceso a objetos (como SELECT, INSERT, UPDATE, etc. en tablas) o membresías en roles.

El primer formato de sintaxis revoca privilegios específicos sobre objetos. El privilegio puede ser ALL PRIVILEGES para revocar todos los privilegios aplicables. El objetivo puede ser TABLE, SEQUENCE, DATABASE, FUNCTION, LANGUAGE, SCHEMA, TABLESPACE, TYPE, y otros tipos de objetos.

El segundo formato de sintaxis revoca la membresía en un rol. Este es el modo de uso del comando GRANT para otorgar membresía en roles.

El tercer formato de sintaxis revoca las opciones de administrador de roles de un rol. Consulte la documentación de GRANT para obtener una descripción de las opciones de administrador.

Alguien que ejecuta REVOKE debe ser el propietario del objeto o un superusuario. Al revocar la membresía de un rol, el usuario que ejecuta REVOKE debe ser el propietario del rol que se está modificando, o un superusuario.

Si se especifica GRANT OPTION FOR, solo se revoca el privilegio de otorgar ese privilegio a otros, no el privilegio en sí.

Si se especifica CASCADE, también se revocan los privilegios que se concedieron basándose en el privilegio que se está revocando. Si se especifica RESTRICT (el valor predeterminado), se denegará la revocación si otros roles tienen ese privilegio concedido a ellos. CASCADE es generalmente más útil.

NOTES

Al revocar privilegios, solo se revocarán los privilegios que fueron concedidos directamente por el rol que ejecuta REVOKE. Si un rol tiene privilegios a través de la pertenencia a otro rol, estos privilegios no se verán afectados a menos que se revoque explícitamente la membresía en ese otro rol.

Por ejemplo, si el rol g1 tiene privilegios sobre el objeto t1, y el rol u1 es miembro de g1, entonces u1 tiene privilegios sobre t1. Si el rol de comando actual es miembro de g1, y emite:

REVOKE INSERT ON t1 FROM u1;

Esto no tendrá ningún efecto sobre los privilegios de u1 sobre t1, porque u1 no obtuvo los privilegios directamente de g1, sino a través de su membresía en g1. Sin embargo, si el rol de comando actual es u1, y emite el comando anterior, entonces u1 revoca sus propios privilegios de inserción en t1.

Si el rol que ejecuta REVOKE tiene privilegios indirectamente a través de más de una ruta de membresía de rol, no está especificado qué rol contenedor se utilizará para realizar el comando. En tales casos, la mejor práctica es usar SET ROLE para convertirse en el rol específico que desea utilizar para realizar la REVOKE. No hacerlo podría llevar a revocar privilegios distintos de los que pretendía, o no revocar nada en absoluto.

Consulte la Sección 5.8 para obtener más información sobre tipos específicos de privilegios, así como sobre cómo inspeccionar los privilegios de los objetos.

EXAMPLES

Revocar el privilegio de inserción para el público en la tabla films:

REVOKE INSERT ON films FROM PUBLIC;

Revocar todos los privilegios del usuario manuel en la vista kinds:

REVOKE ALL PRIVILEGES ON kinds FROM manuel;

Tenga en cuenta que esto en realidad significa "revocar todos los privilegios que he concedido".

Revocar la membresía en el rol admins del usuario joe:

REVOKE admins FROM joe;

COMPATIBILITY

Las notas de compatibilidad del comando GRANT se aplican análogamente a REVOKE. La palabra clave RESTRICT o CASCADE es requerida según el estándar, pero PostgreSQL asume RESTRICT por defecto.
