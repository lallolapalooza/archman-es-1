DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negros.

En las definiciones de macros, TYPE es la etiqueta de nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD, de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es la etiqueta de nombre de una estructura definida por el usuario que debe declararse usando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME debe ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Consulte los ejemplos a continuación para obtener más información sobre cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos autoorganizada. Cada operación en el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de las solicitudes acelera las búsquedas, ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en memoria.

El Teorema de Equilibrio limita el tiempo total de acceso para m operaciones e n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura que se va a definir, y la estructura TYPE es el tipo de los elementos que se insertarán en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo administrada por el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos de los árboles entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debe devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol referenciado por head.

El árbol splay también se puede inicializar estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si un elemento correspondiente ya existe en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede utilizar para encontrar un elemento particular en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden utilizar para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para simplificar, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGROS

Un árbol rojo-negro es un árbol de búsqueda binario con el color del nodo como un atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura que se va a definir, y la estructura TYPE es el tipo de los elementos que se insertarán en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo administrada por el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

DESCRIPTION

These macros provide an implementation of red-black trees.

A red-black tree is a binary search tree where each node has a color, red or black, and satisfies the following properties:

  • Every node is either red or black.
  • The root is black.
  • Every leaf (NIL) is black.
  • If a node is red, then both its children are black.
  • For each node, all simple paths from the node to descendant leaves contain the same number of black nodes.

The tree implementation is stored in a generic way, so that it can be used with any data structure. The only requirement is that the data structure must contain a field of type RB_ENTRY(TYPE). This field is used to link the nodes together.

The macros are parameterized by NAME, which is the name of the tree, and TYPE, which is the name of the structure being used as the tree nodes. For example, to create a tree of integers, you might use:

struct int_node {
	RB_ENTRY(int_node) next;
	int value;
};

RB_HEAD(inttree, int_node);
int int_cmp(struct int_node *, struct int_node *);
RB_PROTOTYPE(inttree, int_node, next, int_cmp);
RB_GENERATE(inttree, int_node, next, int_cmp);

The RB_PROTOTYPE and RB_GENERATE macros declare and define the necessary functions and structures for the tree, respectively. The RB_PROTOTYPE_STATIC and RB_GENERATE_STATIC variants are identical except that they declare static functions and do not emit any function definitions.

The first argument to RB_HEAD defines the head structure of the tree. The second argument defines the type of the nodes in the tree.

The field argument is the name of the RB_ENTRY field within the structure defined by TYPE. This field is used to link the nodes together.

The cmp argument is the name of a function used to compare nodes. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function should return a value smaller than zero. If they are equal, the function should return zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the elements in the tree.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
