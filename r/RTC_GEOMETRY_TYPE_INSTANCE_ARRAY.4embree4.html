NOMBRE

RTC_GEOMETRY_TYPE_INSTANCE_ARRAY - tipo de geometría de matriz de instancias

SINOPSIS

#include <embree4/rtcore.h>
RTCGeometry geometry =
   rtcNewGeometry(device, RTC_GEOMETRY_TYPE_INSTANCE_ARRAY);

DESCRIPCIÓN

Embree soporta matrices de instancias, que es una forma más eficiente en cuanto a memoria para representar grandes cantidades de instancias de la misma o un pequeño conjunto de escenas (sub)escenas. La principal diferencia con las instancias regulares de Embree es que las matrices de instancias de Embree tienen un búfer de transformaciones (ya sean transformaciones afines o descomposiciones de cuaterniones [RTCQuaternionDecomposition]) que pueden ser asignadas por Embree o un búfer compartido, similar a los búferes de vértices para mallas de triángulos. Opcionalmente, en lugar de instanciar solo una escena, una matriz de instancias puede instanciar múltiples escenas al proporcionar una matriz de escenas y un búfer de índices correspondiente que especifica qué instancia de la matriz de instancias instancia cuál de las escenas en la matriz de escenas.

Las matrices de instancias se crean pasando RTC_GEOMETRY_TYPE_INSTANCE_ARRAY a la llamada a la función rtcNewGeometry. La escena instanciada puede establecerse usando la llamada rtcSetGeometryInstancedScene, o si se deben instanciar múltiples escenas, pasando una matriz de escenas usando rtcSetGeometryInstancedScenes. Esta última también requiere especificar un búfer de índices usando rtcSetNewGeometryBuffer o rtcSetSharedGeometryBuffer con RTC_BUFFER_TYPE_INDEX como tipo de búfer.

Dado que la información de transformación puede ser grande para una gran cantidad de instancias, la matriz de instancias permite compartir el búfer de transformaciones entre la aplicación del usuario y Embree. Puede ser almacenado en un búfer creado por Embree con rtcSetNewGeometryBuffer o un búfer ya existente puede ser compartido usando rtcSetSharedGeometryBuffer. En cualquier caso, el tipo de búfer debe ser RTC_BUFFER_TYPE_TRANSFORM y los formatos permitidos son RTC_FORMAT_FLOAT4X4_COLUMN_MAJOR, RTC_FORMAT_FLOAT3X4_COLUMN_MAJOR, RTC_FORMAT_FLOAT3X4_ROW_MAJOR, y RTC_FORMAT_QUATERNION_DECOMPOSITION. Embree no modificará los datos en el búfer de transformaciones.

Las matrices de instancias de Embree admiten instanciación de un solo nivel y de varios niveles. La profundidad máxima de anidamiento de instancias es RTC_MAX_INSTANCE_LEVEL_COUNT; se puede configurar en tiempo de compilación usando la constante EMBREE_MAX_INSTANCE_LEVEL_COUNT. Los usuarios deben adaptar esta constante a sus necesidades: las instancias anidadas a una profundidad mayor son ignoradas silenciosamente en modo de lanzamiento, y causan aserciones en modo de depuración.

Tenga en cuenta que rtcCommitScene en la(s) escena(s) instanciada(s) debe ser llamada primero, seguida de rtcCommitGeometry en la matriz de instancias, seguida de rtcCommitScene para la escena de nivel superior que contiene la matriz de instancias.

Si un rayo golpea la instancia, los miembros geomID y primID del golpe se establecen en el ID de geometría y el ID de primitiva de la primitiva golpeada en la escena instanciada. El miembro instID del golpe se establece en el ID de geometría de la matriz de instancias en la escena de nivel superior y el miembro instPrimID se establece en el índice de la instancia golpeada de la matriz de instancias.

Para desenfoque de movimiento multi-segmento, el número de pasos de tiempo debe especificarse primero usando la función rtcSetGeometryTimeStepCount. Luego, una transformación para cada paso de tiempo se puede especificar usando la función rtcSetNewGeometryBuffer o rtcSetSharedGeometryBuffer y pasando el paso de tiempo como parámetro de ranura de estas llamadas.

Consulte el tutorial de [Matriz de Geometría de Instancia] para ver un ejemplo de cómo usar matrices de instancias.

ESTADO DE SALIDA

En caso de error se devuelve NULL y se establece un código de error que se puede consultar con rtcGetDeviceError.
