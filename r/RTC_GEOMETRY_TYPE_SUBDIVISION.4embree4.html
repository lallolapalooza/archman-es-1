RTC_GEOMETRY_TYPE_SUBDIVISION(3) Embree Ray Tracing Kernels 4 RTC_GEOMETRY_TYPE_SUBDIVISION(3)

NOMBRE

RTC_GEOMETRY_TYPE_SUBDIVISION - tipo de geometría de subdivisión

SINOPSIS

#include <embree4/rtcore.h>
RTCGeometry geometry =
  rtcNewGeometry(device, RTC_GEOMETRY_TYPE_SUBDIVISION);

DESCRIPCIÓN

Se admiten mallas de subdivisión Catmull-Clark, incluido el soporte para bordes con pliegues, vértices con pliegues, agujeros, geometría no manifold y interpolación de cara variable. El número de vértices por cara puede oscilar entre 3 y 15 vértices (triángulos, cuadriláteros, pentágonos, etc.).

Las mallas de subdivisión se crean pasando RTC_GEOMETRY_TYPE_SUBDIVISION a la función rtcNewGeometry. La aplicación necesita configurar varios búferes para configurar la malla de subdivisión. Consulte rtcSetGeometryBuffer y rtcSetSharedGeometryBuffer para obtener más detalles sobre cómo configurar búferes. El búfer de caras (tipo RTC_BUFFER_TYPE_FACE y formato RTC_FORMAT_UINT) contiene el número de bordes/índices de cada cara (de 3 a 15), y el número de caras se infiere del tamaño de este búfer. El búfer de índices (tipo RTC_BUFFER_TYPE_INDEX) contiene múltiples (de 3 a 15) índices de vértices de 32 bits (formato RTC_FORMAT_UINT) para cada cara, y el número de bordes se infiere del tamaño de este búfer. El búfer de vértices (tipo RTC_BUFFER_TYPE_VERTEX) almacena una matriz de coordenadas flotantes de precisión simple x, y, z (formato RTC_FORMAT_FLOAT3), y el número de vértices se infiere del tamaño de este búfer.

Opcionalmente, la aplicación puede configurar búferes de índices adicionales utilizando diferentes ranuras de búfer si se requieren topologías múltiples para la interpolación de cara variable. Los búferes de vértices estándar (RTC_BUFFER_TYPE_VERTEX) siempre están vinculados a la topología de geometría (topología 0), por lo tanto, utilizan RTC_BUFFER_TYPE_INDEX con la ranura de búfer 0. Los datos de vértices de usuario pueden utilizar diferentes topologías, como se describe más adelante.

Opcionalmente, la aplicación puede configurar el búfer de agujeros (RTC_BUFFER_TYPE_HOLE), que contiene una matriz de índices de 32 bits (formato RTC_FORMAT_UINT) de caras que deben considerarse inexistentes en todas las topologías. El número de agujeros se infiere del tamaño de este búfer.

Opcionalmente, la aplicación puede rellenar el búfer de nivel (RTC_BUFFER_TYPE_LEVEL) con una tasa de teselación para cada uno de los bordes de cada cara. Este búfer debe tener el mismo tamaño que el búfer de índices. El nivel de teselación es un valor flotante positivo (formato RTC_FORMAT_FLOAT) que especifica cuántos cuadriláteros a lo largo del borde se deben generar durante la teselación. Si no se especifica ningún búfer de nivel, se utiliza un nivel de 1. El nivel de borde máximo admitido es 4096, y los niveles más grandes se limitan a ese valor. Tenga en cuenta que los bordes pueden ser compartidos entre (típicamente 2) caras. Para garantizar una teselación hermética, el nivel de estos bordes compartidos debe ser idéntico. Se puede establecer una tasa de teselación uniforme para toda una malla de subdivisión utilizando la función rtcSetGeometryTessellationRate. La existencia de un búfer de nivel tiene prioridad sobre la tasa de teselación uniforme.

Opcionalmente, la aplicación puede rellenar los búferes de pliegues de bordes dispersos para que los bordes parezcan más nítidos. El búfer de índices de pliegues de bordes (RTC_BUFFER_TYPE_EDGE_CREASE_INDEX) contiene una matriz de pares de índices de vértices de 32 bits (formato RTC_FORMAT_UINT2) que especifican bordes no orientados en la topología de geometría. El búfer de pesos de pliegues de bordes (RTC_BUFFER_TYPE_EDGE_CREASE_WEIGHT) almacena para cada uno de estos bordes con pliegues un peso flotante positivo (formato RTC_FORMAT_FLOAT). El número de pliegues de bordes se infiere del tamaño de estos búferes, que deben ser idénticos. Cuanto mayor sea el peso, más nítido será el borde. Se admite la especificación de un peso infinito, que marca un borde como infinitamente nítido. Almacenar un borde varias veces con el mismo peso de pliegue está permitido, pero tiene un rendimiento menor. Almacenar un borde varias veces con diferentes pesos de pliegue resulta en un comportamiento indefinido. Para un borde almacenado (i,j), no es necesario almacenar los bordes en dirección inversa (j,i), ya que ambos se consideran el mismo borde no orientado. Las características de pliegues de bordes se comparten entre todas las topologías.

Opcionalmente, la aplicación puede rellenar los búferes de pliegues de vértices dispersos para que los vértices parezcan más nítidos. El búfer de índices de pliegues de vértices (RTC_BUFFER_TYPE_VERTEX_CREASE_INDEX) contiene una matriz de índices de vértices de 32 bits (formato RTC_FORMAT_UINT) para especificar un conjunto de vértices de la topología de geometría. El búfer de pesos de pliegues de vértices (RTC_BUFFER_TYPE_VERTEX_CREASE_WEIGHT) especifica para cada uno de estos vértices un peso flotante positivo (formato RTC_FORMAT_FLOAT). El número de pliegues de vértices se infiere del tamaño de estos búferes y debe ser idéntico. Cuanto mayor sea el peso, más nítido será el vértice. Se admite la especificación de un peso infinito, que hace que el vértice sea infinitamente nítido. Almacenar un vértice varias veces con el mismo peso de pliegue está permitido, pero tiene un rendimiento menor. Almacenar un vértice varias veces con diferentes pesos de pliegue resulta en un comportamiento indefinido. Las características de pliegues de vértices se comparten entre todas las topologías.

Los modos de subdivisión se pueden utilizar para forzar la interpolación lineal en partes de la malla de subdivisión; consulte rtcSetGeometrySubdivisionMode para obtener más detalles.

Para el desenfoque de movimiento multisegmento, primero se debe especificar el número de pasos de tiempo utilizando la llamada rtcSetGeometryTimeStepCount. Luego, se puede configurar un búfer de vértices para cada paso de tiempo utilizando diferentes ranuras de búfer, y todos estos búferes deben tener el mismo paso y tamaño.

Consulte también el tutorial [Geometría de subdivisión] para ver un ejemplo de cómo crear superficies de subdivisión.

Parametrización

La parametrización para las caras de subdivisión es diferente para los cuadriláteros y las caras que no son cuadriláteros.

La parametrización de una cara cuadrilátera utiliza el primer vértice p0 como punto base, y el vector p1 - p0 como dirección u y p3 - p0 como dirección v.

La parametrización para todos los demás tipos de caras (con un número de vértices distinto de 4), tiene una parametrización especial donde el ID de subparche n (del n-ésimo cuadrilátero que se obtendría mediante un solo paso de subdivisión) y la ubicación local del impacto dentro de este cuadrilátero se codifican en las coordenadas UV. El siguiente código extrae el ID de subparche i y las UV locales de este subparche:

unsigned int l = floorf(0.5f*U);
unsigned int h = floorf(0.5f*V);
unsigned int i = 4*h+l;
float u = 2.0f*fracf(0.5f*U)-0.5f;
float v = 2.0f*fracf(0.5f*V)-0.5f;

Esta codificación permite que las UV del subparche local estén en el rango [-0.5,1.5[, de modo que se puedan pasar UV de subparche negativas a rtcInterpolate para muestrear subparches ligeramente fuera de los límites. Esto puede ser útil para calcular derivadas mediante diferencias finitas si es necesario. La codificación tiene además la propiedad de que se puede mover simplemente el valor u (o v) en un subparche sumando du (o dv) a la codificación UV especial, siempre que no caiga fuera del rango [-0.5,1.5[.

Para interpolar sin problemas los atributos de vértices en la superficie de subdivisión, recomendamos usar la función rtcInterpolate, que aplicará las reglas de subdivisión estándar para la interpolación y se encargará automáticamente de la codificación UV especial para los no cuadriláteros.

Datos de cara variable

La interpolación de cara variable se admite a través de múltiples topologías por malla de subdivisión y vinculando dichas topologías a búferes de atributos de vértice para interpolar. De esta manera, las coordenadas de textura pueden usar una topología diferente con límites adicionales para construir regiones UV separadas dentro de una misma malla de subdivisión.

Cada topología i tiene un búfer de índices separado (especificado con RTC_BUFFER_TYPE_INDEX y ranura de búfer i) y un modo de subdivisión separado que se puede configurar con rtcSetGeometrySubdivisionMode. Un búfer de atributos de vértice RTC_BUFFER_TYPE_VERTEX_ATTRIBUTE vinculado a una ranura de búfer j se puede asignar para usar una topología para la interpolación utilizando la llamada rtcSetGeometryVertexAttributeTopology.

El búfer de caras (tipo RTC_BUFFER_TYPE_FACE) se comparte entre todas las topologías, lo que significa que el n-ésimo primitivo siempre tiene el mismo número de vértices (por ejemplo, siendo un triángulo o un cuadrilátero) para cada topología. Sin embargo, los índices de las topologías en sí mismos pueden ser diferentes.

Name

RTC_GEOMETRY_TYPE_SUBDIVISION — subdivision geometry type

Description

The RTC_GEOMETRY_TYPE_SUBDIVISION geometry type is used to represent subdivision surfaces.

A subdivision geometry contains an array of RTC_BUFFER_TYPE_VERTEX, an array of RTC_BUFFER_TYPE_FACE, and an array of RTC_BUFFER_TYPE_EDGE_CREASE. Optionally, it can also contain an array of RTC_BUFFER_TYPE_HOLE and an array of RTC_BUFFER_TYPE_SUBDIVISION_CONTROL_POINT.

The vertex buffer stores the positions of the vertices. The face buffer stores the number of vertices for each face. The edge crease buffer stores the crease weight for each edge. The hole buffer stores the indices of the edges that represent holes.

Subdivision surfaces are defined by a set of control points and rules for how to refine the surface. The Embree library supports various types of subdivision surfaces, including Catmull-Clark subdivision surfaces.

The following code snippet demonstrates how to create and populate a subdivision geometry:

// Create a subdivision geometry
    RTCGeometry geom = rtcNewGeometry(device, RTC_GEOMETRY_TYPE_SUBDIVISION);

    // Define vertices
    float vertices[N][3] = {{...}};
    // Create vertex buffer
    RTCBuffer vertexBuffer = rtcNewSharedBuffer(device, vertices, sizeof(vertices));
    // Set vertex buffer for the geometry
    rtcAttachBuffer(geom, vertexBuffer, RTC_BUFFER_TYPE_VERTEX);

    // Define faces
    unsigned int faces[M] = {...}; // Each element specifies the number of vertices for a face
    // Create face buffer
    RTCBuffer faceBuffer = rtcNewSharedBuffer(device, faces, sizeof(faces));
    // Set face buffer for the geometry
    rtcAttachBuffer(geom, faceBuffer, RTC_BUFFER_TYPE_FACE);

    // Define edge creases
    // ...

    // Commit the geometry
    rtcCommitGeometry(geom);
