NOMBRE

Role::Hooks - callbacks de roles

SINOPSIS

package Local::Role {
  use Moo::Role;
  use Role::Hooks;

  Role::Hooks->after_apply(__PACKAGE__, sub {
    my ($role, $target) = @_;
    print "$role ha sido aplicado a $target.\n";
  });
}

package Local::Class {
  use Moo;
  with "Local::Role";   # imprime el mensaje anterior
}

DESCRIPCIÓN

Este módulo permite que un rol ejecute un callback cuando se aplica a una clase o a otro rol.

Compatibilidad

Debería funcionar con Role::Tiny, Moo::Role, Moose::Role, Mouse::Role, Role::Basic y Mite. No todos los constructores de clases funcionan bien con todos los constructores de roles (por ejemplo, una clase Moose que consume un rol Mouse). Pero cuando funcionan juntos, Role::Hooks debería poder ejecutar los callbacks. (La única combinación que he probado es Moo con Moose).

Otras implementaciones de roles (como Moos::Role, exact::role y OX::Role) son solo envoltorios alrededor de uno de los constructores de roles soportados, por lo que deberían funcionar en su mayor parte.

Con Role::Basic, el hook "after_apply" se llama un poco antes de lo ideal; después de que el rol se ha cargado completamente y sus métodos se han copiado al paquete de destino, pero antes de manejar "requires", y antes de parchear el método "DOES" en el paquete de destino. Si está utilizando Role::Basic, considere cambiar a Role::Tiny.

Con Mite, el hook "before_apply" se llama bastante tarde; después de que el rol se carga completamente y los atributos y métodos se han copiado al paquete de destino, después de que "DOES" ha sido parcheado, pero antes de que los modificadores de métodos del rol se hayan aplicado al paquete de destino.

Aparte de Role::Tiny/Moo::Role, se puede pasar un hashref de argumentos adicionales (cosas como "-excludes" y "-alias") al consumir un rol. Aunque desaliento a la gente de usar estos en general, si necesita acceder a estos argumentos en el callback, puede revisar %Role::Hooks::ARGS.

Los roles generados a través de Package::Variant deberían funcionar; consulte t/20packagevariant.t para una demostración.

Métodos

"before_apply"
Role::Hooks->before_apply($nombre_rol, $callback);

Configura un callback para un rol que se llamará antes de que el rol se aplique a un paquete de destino. El callback recibirá dos parámetros: el rol que se está aplicando y el paquete de destino.

El rol que se está aplicando puede no ser el mismo rol que el rol en el que se definió el callback.

package Local::Role1 {
  use Moo::Role;
  use Role::Hooks;
  Role::Hooks->before_apply(__PACKAGE__, sub {
    my ($role, $target) = @_;
    print "$role ha sido aplicado a $target.\n";
  });
}

package Local::Role2 {
  use Moo::Role;
  with "Local::Role1";
}

package Local::Class1 {
  use Moo::Role;
  with "Local::Role2";
}

Esto imprimirá:

Local::Role1 ha sido aplicado a Local::Role2.
Local::Role2 ha sido aplicado a Local::Class1.

Si solo le interesan las aplicaciones directas de roles (es decir, la primera):

Role::Hooks->before_apply(__PACKAGE__, sub {
  my ($role, $target) = @_;
  return if $role ne __PACKAGE__;
  print "$role ha sido aplicado a $target.\n";
});

Si solo le interesan los roles que se aplican a clases (es decir, la segunda):

Role::Hooks->before_apply(__PACKAGE__, sub {
  my ($role, $target) = @_;
  return if Role::Hooks->is_role($target);
  print "$role ha sido aplicado a $target.\n";
});
"after_apply"
Role::Hooks->after_apply($nombre_rol, $callback);

Lo mismo que "before_apply", pero llamado más tarde en el proceso de aplicación del rol.

Tenga en cuenta que cuando se llama al callback, aunque sea después de que el rol se haya aplicado al destino, no significa que el destino haya terminado de construirse. Por ejemplo, podría haber declaraciones "has" después de la declaración "with", y esas aún no se habrán evaluado.

Si desea lanzar un error cuando alguien aplique su rol a un destino inapropiado, es probable que sea mejor hacerlo en "before_apply" si es posible.

"after_inflate"
Role::Hooks->after_inflate($nombre_paquete, $callback);

Aunque esto es parte de Role::Hooks, también funciona en clases. Pero solo funciona en clases y roles construidos con Moo. Esto ejecuta su callback si su clase o rol Moo se "infla" a una clase o rol Moose.

Si configura un callback para un rol, entonces el callback también se llamará si se inflan los paquetes a los que se aplicó ese rol.

"is_role"
Devolverá verdadero si el paquete dado parece ser un rol, falso en caso contrario.

(De hecho, devuelve una cadena que representa qué constructor de roles parece estar utilizando el rol: "Role::Tiny", "Moose::Role", "Mouse::Role", "Role::Basic", o "Mite::Role"; los roles construidos con Moo::Role se detectan como "Role::Tiny".)

NOMBRE

Role::Hooks - Un rol simple para la gestión de hooks

SINOPSIS

package MyApp::Role::WithHooks;

use Role::Hooks;

has hooks => (
    handles_with => 'Role::Hooks',
    default      => sub { Role::Hooks->new },
);

# ...

sub some_method {
    my $self = shift;

    $self->hooks->trigger('before_something');

    # ... hacer algo ...

    $self->hooks->trigger('after_something', $arg1, $arg2);
}

# ...
package MyApp;

use Moose;
with 'MyApp::Role::WithHooks';

# ...

MyApp->new->some_method;

DESCRIPCIÓN

Este rol proporciona una forma sencilla de implementar el patrón Observer (o pub/sub) dentro de tu aplicación. Permite registrar callbacks para ser ejecutados cuando se dispara un "hook".

MÉTODOS

  • trigger( $hook_name, @args ): Dispara un hook dado su nombre y pasa los argumentos especificados a todos los callbacks registrados para ese hook.
  • register( $hook_name, \&callback ): Registra un callback (una referencia a una subrutina) para un hook dado su nombre.
  • unregister( $hook_name, \&callback ): Elimina un callback registrado para un hook dado su nombre.
