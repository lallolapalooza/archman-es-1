DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles de splay y árboles de color rojo-negro.

En las definiciones de las macros, TYPE es el nombre del tag de una estructura definida por el usuario que debe contener un campo con el nombre FIELD de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es el nombre del tag de una estructura definida por el usuario que debe ser declarada usando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME tiene que ser un nombre único de prefijo para cada árbol definido.

Las declaraciones de prototipos están realizadas con SPLAY_PROTOTYPE, RB_PROTOTYPE o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE o RB_GENERATE_STATIC. Véase los ejemplos a continuación para una explicación adicional de cómo se utilizan estas macros.

ÁRBOLES DE SPLAY

Un árbol de splay es una estructura de datos autogestionada. Cada operación en el árbol causa un splay. El splay mueve el nodo solicitado a la raíz del árbol y parcialmente rebalanza el árbol.

Tiene el beneficio de que la localidad de las solicitudes causa consultas más rápidas ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada consulta causa escrituras en memoria.

El Teorema de Equilibrio limita el tiempo total de acceso para m operaciones y n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para m accesos en un árbol de splay es O(lg n).

Un árbol de splay está dirigido por una estructura definida mediante la macro SPLAY_HEAD(). Una SPLAY_HEAD estructura se declara así:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir y TYPE es el tipo de los elementos a insertar en el árbol.

La macro SPLAY_ENTRY declara una estructura que permite conectar elementos en el árbol.

Para usar las funciones que manipulan la estructura del árbol, sus prototipos deben ser declarados con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol particular. El argumento TYPE es el tipo de la estructura que gestiona el árbol. El argumento FIELD es el nombre del elemento definido mediante SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE() pero se debe utilizar solo una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar nodos de árboles entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, devuelve cero. De lo contrario, debe devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol referido por head.

El árbol de splay puede también ser inicializado de forma estática usando la macro SPLAY_INITIALIZER() de esta manera:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. Por éxito, se devuelve NULL. Si ya existe un elemento con el mismo valor en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. Por éxito, se devuelve un puntero al elemento eliminado. NULL se devuelve si no se encuentra el elemento en el árbol.

La macro SPLAY_FIND() puede usarse para encontrar un elemento particular en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX() y SPLAY_NEXT() pueden usarse para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para simplicidad, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol de splay está vacío.

ÁRBOLES DE COLOR ROJO-NEGRO

Un árbol de color rojo-negro es un árbol de búsqueda binario con el color del nodo como un atributo adicional. Fulfilla una serie de condiciones:

  1. Todo camino desde la raíz hasta un hoja contiene el mismo número de nodos negros.
  2. Cada nodo rojo (excepto la raíz) tiene un padre negro.
  3. Cada nodo hoja es negro.

Cada operación en un árbol de color rojo-negro está limitada a O(lg n). La altura máxima de un árbol de color rojo-negro es 2lg(n+1).

Un árbol de color rojo-negro está dirigido por una estructura definida mediante la macro RB_HEAD(). Una RB_HEAD estructura se declara así:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y TYPE es el tipo de los elementos a insertar en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para usar las funciones que manipulan la estructura del árbol, sus prototipos deben ser declarados con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC() donde NAME es un identificador único para este árbol particular. El argumento TYPE es el tipo de la estructura que gestiona el árbol. El argumento FIELD es el nombre del elemento definido mediante RB_ENTRY().

LIBRARY

libbsd - Red-black tree routines (libbsd)

SYNOPSIS

#include <sys/tree.h>

DESCRIPTION

These macros provide an implementation of red-black trees. Red-black trees are a form of self-balancing binary search tree. Insertion and deletion operations maintain the balance, ensuring that the tree does not become too unbalanced. This guarantees a worst-case time complexity of O(log n) for these operations and for most other operations, including search.

The tree macros are designed to be used in a generic way. The user must provide the definition of the node structure, which must contain a field of type RB_ENTRY(TYPE). This field is used by the macros to link nodes together. TYPE is the name of the structure node type.

The tree itself is represented by a pointer to a structure defined using the RB_HEAD() macro. The tree head structure contains pointers to the root of the tree and possibly other internal data needed for balancing. The first argument to most macros is the name of the tree head structure, referred to as NAME in the following descriptions.

A comparison function, CMP, must also be provided. This function defines the ordering of the elements in the tree. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero.

The macros RB_PROTOTYPE() and RB_GENERATE() are used to declare and define the tree head structure and its associated functions. The former should be used in header files, and the latter in one of the source files.

The RB_PROTOTYPE() macro declares the tree head structure and the comparison function. The arguments are the name of the tree head structure (HEADNAME), the type of the nodes in the tree (TYPE), the name of the entry field within the node structure (FIELDNAME), and the comparison function (CMP).

The RB_GENERATE() macro defines the tree head structure and the necessary functions. The arguments are the same as for RB_PROTOTYPE().

The RB_HEAD() macro declares the tree head structure. The arguments are the name of the tree head structure (HEADNAME) and the type of the nodes in the tree (TYPE).

The RB_ENTRY() macro declares the entry field within the node structure. The argument is the type of the nodes in the tree (TYPE).

The RB_COLOR() macro returns the color of the node elm. The color is either RB_RED or RB_BLACK.

The RB_SETCOLOR() macro sets the color of the node elm to color. The color must be either RB_RED or RB_BLACK.

The RB_PARENT() macro returns a pointer to the parent of the node elm. The node must be present in the tree.

The RB_NEXT() macro returns a pointer to the next node in the tree, according to an in-order traversal. The node must be present in the tree.

The RB_PREV() macro returns a pointer to the previous node in the tree, according to an in-order traversal. The node must be present in the tree.

The RB_END() macro returns a sentinel value that indicates the end of the tree during traversal.

The RB_FIRST() macro returns a pointer to the first node in the tree, according to an in-order traversal.

The RB_ROOT() macro returns a pointer to the root node of the tree.

The RB_MIN() macro returns a pointer to the node with the smallest key in the tree.

The RB_MAX() macro returns a pointer to the node with the largest key in the tree.

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
