Eventos de tiempo de ejecución - Rastreo en tiempo de ejecución basado en búfer de anillo

Este módulo permite a los usuarios habilitar y suscribirse a eventos de rastreo del Colector de Basura y otras partes del tiempo de ejecución de OCaml. Esto puede ser útil para fines de diagnóstico o monitoreo de rendimiento. Este módulo se puede utilizar para suscribirse a eventos del proceso actual o de procesos externos de forma asíncrona.

Cuando se habilita (ya sea configurando la variable de entorno OCAML_RUNTIME_EVENTS_START o llamando a Runtime_events.start), se creará un archivo con el pid del proceso y la extensión .events. Por defecto, esto se encuentra en el directorio actual, pero puede ser anulado por la variable de entorno OCAML_RUNTIME_EVENTS_DIR. Cada dominio mantiene su propio búfer de anillo en una sección del archivo más grande en el que emite eventos.

Adicionalmente, existe un conjunto de APIs C en runtime_events.h que pueden habilitar el monitoreo de impacto cero del proceso actual o enlaces para otros lenguajes.

El comportamiento del sistema de eventos en tiempo de ejecución puede ser controlado por las siguientes variables de entorno:

-OCAML_RUNTIME_EVENTS_START si está configurado, hará que el sistema de eventos en tiempo de ejecución se inicie como parte de la inicialización del tiempo de ejecución de OCaml.

-OCAML_RUNTIME_EVENTS_DIR establece el directorio donde se ubicarán los búferes de anillo de eventos en tiempo de ejecución. Si no está presente, se utilizará el directorio de trabajo del programa.

-OCAML_RUNTIME_EVENTS_PRESERVE si está configurado, evitará que el tiempo de ejecución de OCaml elimine sus búferes de anillo cuando termine. Esto puede ayudar si se monitorean programas de ejecución muy corta.

val start : unit -> unit

start () will start the collection of events in the runtime if not already started.

Events can be consumed by creating a cursor with create_cursor and providing a set of callbacks to be called for each type of event.

val path : unit -> string option

If runtime events are being collected, path () returns Some p where p is a path to the runtime events file. Otherwise, it returns None.

val pause : unit -> unit

pause () will pause the collection of events in the runtime. Traces are collected if the program has called Runtime_events.start () or the OCAML_RUNTIME_EVENTS_START environment variable has been set.

val resume : unit -> unit

resume () will resume the collection of events in the runtime. Traces are collected if the program has called Runtime_events.start () or the OCAML_RUNTIME_EVENTS_START environment variable has been set.

val create_cursor : (string * int) option -> cursor

create_cursor path_pid creates a cursor to read from an runtime_events. Cursors can be created for runtime_events in and out of process. A runtime_events ring-buffer may have multiple cursors reading from it at any point in time and a program may have multiple cursors open concurrently (for example if multiple consumers want different sets of events). If path_pid is None then a cursor is created for the current process. Otherwise the pair contains a string path to the directory that contains the pid .events file and int pid for the runtime_events of an external process to monitor.

val free_cursor : cursor -> unit

Free a previously created runtime_events cursor.

val read_poll : cursor -> Callbacks.t -> int option -> int

read_poll cursor callbacks max_option calls the corresponding functions on callbacks for up to max_option events read off cursor 's runtime_events and returns the number of events read.
