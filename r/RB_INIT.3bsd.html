DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negros.

En las definiciones de las macros, TYPE es la etiqueta de nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD, de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es la etiqueta de nombre de una estructura definida por el usuario que debe declararse utilizando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME tiene que ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de las funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Vea los ejemplos a continuación para una mayor explicación sobre cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos autoorganizativa. Cada operación sobre el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de las peticiones causa búsquedas más rápidas ya que los nodos solicitados se mueven a la cima del árbol. Por otro lado, cada búsqueda provoca escrituras en memoria.

El Teorema de Balance limita el tiempo total de acceso para m operaciones e n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura que se va a definir, y la estructura TYPE es el tipo de los elementos que se insertarán en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite conectar los elementos en el árbol.

Para poder utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos del árbol entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debe devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol al que hace referencia head.

El árbol splay también se puede inicializar estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si un elemento coincidente ya existe en el árbol, la inserción se interrumpe y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede utilizar para encontrar un elemento particular en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden utilizar para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para simplificar, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() debe usarse para comprobar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGROS

Un árbol rojo-negro es un árbol de búsqueda binaria con el color del nodo como atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura que se va a definir, y la estructura TYPE es el tipo de los elementos que se insertarán en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar los elementos en el árbol.

Para poder utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

Los cuerpos de las funciones se generan con las macros RB_GENERATE() o RB_GENERATE_STATIC(). Estas macros toman los mismos argumentos que las macros RB_PROTOTYPE() y RB_PROTOTY

DESCRIPCIÓN

El árbol está definido por una estructura de punteros opaca RB_HEAD, que es un puntero a una entrada de árbol declarada con RB_ENTRY. La lista de entrada de árbol debe estar incrustada en la estructura de datos que se va a almacenar en el árbol. Los árboles de color rojo-negro están definidos por el tipo de estructura RB_HEAD, la estructura de nodo TYPE y el nombre del campo de entrada del árbol FIELD.

El macro RB_GENERATE() define el tipo HEADNAME y las funciones necesarias para operar en el árbol.

RB_GENERATE(HEADNAME, TYPE, FIELD, CMP)
Define el tipo de cabeza del árbol HEADNAME, que es una lista enlazada de punteros TYPE. Define el tipo de entrada del árbol FIELD. Define la función de comparación de nodos CMP. Se define el tipo TYPE, que debe ser un puntero a la estructura que contiene el campo FIELD.

El macro RB_GENERATE() debe ser llamado una vez en el archivo de implementación del árbol. El macro RB_PROTOTYPE() es un prototipo para que se pueda usar en los archivos de cabecera.

Las definiciones del árbol son las siguientes:

#define RB_HEAD(NAME, TYPE) struct NAME { struct TYPE *rbh_root; int rbh_nnodes; }
#define RB_PROTOTYPE(NAME, TYPE, FIELD, CMP)                \
	extern int CMP(struct TYPE *, struct TYPE *);         \
	extern void RB_INIT(struct NAME *);                   \
	extern struct TYPE *RB_INSERT(struct NAME *, struct TYPE *); \
	extern struct TYPE *RB_REMOVE(struct NAME *, struct TYPE *); \
	extern struct TYPE *RB_FIND(struct NAME *, struct TYPE *);   \
	extern struct TYPE *RB_NEXT(struct NAME *, struct TYPE *);   \
	extern struct TYPE *RB_PREV(struct NAME *, struct TYPE *);   \
	extern struct TYPE *RB_MIN(struct NAME *);                   \
	extern struct TYPE *RB_MAX(struct NAME *);                   \
	extern struct TYPE *RB_ROOT(struct NAME *);
#define RB_GENERATE(NAME, TYPE, FIELD, CMP)                \
	int CMP(struct TYPE *, struct TYPE *);                 \
	RB_HEAD(NAME, TYPE);                                   \
	RB_GENERATE_INTERNAL(NAME, TYPE, FIELD, CMP)
#define RB_GENERATE_INTERNAL(NAME, TYPE, FIELD, CMP)       \
	RB_PROTOTYPE(NAME, TYPE, FIELD, CMP)
#define RB_ENTRY(TYPE) struct { struct TYPE *rb_left, *rb_right, *rb_parent; int rb_color; }

El campo FIELD es el nombre de la estructura de datos utilizada para la entrada del árbol. El campo CMP es el nombre de la función que compara dos entradas.

La función de comparación debe devolver un valor menor que cero si el primer argumento es menor que el segundo, cero si son iguales y un valor mayor que cero si el primer argumento es mayor que el segundo.

El macro RB_INIT() inicializa el árbol. El macro RB_INITIALIZER() se utiliza para inicializar estáticamente un árbol.

El macro RB_INSERT() inserta un nuevo elemento en el árbol. Si el elemento ya existe, se devuelve un puntero al elemento existente. De lo contrario, se devuelve NULL.

El macro RB_REMOVE() elimina un elemento del árbol. Devuelve el elemento eliminado.

Los macros RB_FIND() y RB_NFIND() buscan un elemento en el árbol. RB_FIND() busca un elemento con la misma clave que el elemento proporcionado. RB_NFIND() busca el primer elemento cuya clave sea mayor o igual que la clave del elemento proporcionado.

Los macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT() y RB_PREV() se utilizan para recorrer el árbol.

Los macros RB_FOREACH() y RB_FOREACH_REVERSE() recorren el árbol en orden ascendente o descendente, respectivamente. El puntero np se asigna a cada elemento.

Los macros RB_FOREACH_SAFE() y RB_FOREACH_REVERSE_SAFE() son similares a sus contrapartes no seguras, pero permiten la eliminación y liberación segura de elementos durante el recorrido.

El macro RB_EMPTY() comprueba si un árbol de color rojo-negro está vacío.

EJEMPLOS

El siguiente ejemplo muestra cómo declarar un árbol de color rojo-negro que contiene enteros. Se insertan valores en él y se imprimen los contenidos del árbol en orden. Por último, se imprime la estructura interna del árbol.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIA

Los macros de árbol aparecieron por primera vez en FreeBSD 4.6.

NOTAS

Intentar liberar un árbol de la siguiente manera es un error común:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}

Dado que var se libera, el macro FOREACH() hace referencia a un puntero que puede haber sido reasignado. El código correcto necesita una segunda variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
