NOMBRE

Razor::Errorhandler - Mecanismo de manejo de errores para Razor.

SINOPSIS

package Foo;
use Razor::Errorhandler;
@ISA = qw(Razor::Errorhandler);
sub alive { 
    ..
    ..
    return 
    $self->error ("¡Despierta, despierta! Toca la campana de alarma. \
                   ¡Asesinato y traición!", $dagger) 
        if $self->murdered($king);
}
package main; 
use Foo;
my $foo = new Foo;
$foo->alive($king) or print $foo->errstr(); 
# imprime "¡Despierta, despierta! ... "

DESCRIPCIÓN

Razor::Errorhandler encapsula el mecanismo de manejo de errores utilizado por los módulos en el paquete Razor. Razor::Errorhandler no tiene un constructor y está destinado a ser heredado. Los módulos derivados utilizan sus dos métodos, error() y errstr(), para comunicar mensajes de error al llamador.

Cuando un método del módulo derivado falla, llama a $self->error() y devuelve el control al llamador. El mensaje de error pasado a error() se pone a disposición del llamador a través del accesor errstr(). error() también acepta una lista de datos sensibles que elimina (undef'es) antes de devolver el control.

El llamador nunca debe llamar a errstr() para comprobar errores. errstr() solo debe llamarse cuando un método indica (generalmente a través de un valor de retorno indefinido) que ha ocurrido un error. Esto se debe a que errstr() nunca se sobrescribe y siempre contendrá un valor después de la ocurrencia del primer error.

MÉTODOS

error($mesage, ($wipeme, $wipemetoo))
El primer argumento de error() es $message que se coloca en $self->{errstr} y los argumentos restantes se interpretan como variables que contienen datos sensibles que se eliminan de la memoria. error() siempre devuelve undef.
errstr()
errstr() es un método accesor para $self->{errstr}.
