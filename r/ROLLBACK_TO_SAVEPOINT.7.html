NOMBRE

ROLLBACK TO SAVEPOINT - retroceder a un punto de guardado

SINOPSIS

ROLLBACK [ WORK | TRANSACTION ] TO [ SAVEPOINT ] nombre_punto_guardado

DESCRIPCIÓN

Revierte todos los comandos que se ejecutaron después de que se estableció el punto de guardado y luego inicia una nueva subtransacción al mismo nivel de transacción. El punto de guardado permanece válido y se puede revertir a él nuevamente más tarde, si es necesario.

ROLLBACK TO SAVEPOINT destruye implícitamente todos los puntos de guardado que se establecieron después del punto de guardado nombrado.

PARÁMETROS

nombre_punto_guardado

El punto de guardado al que revertir.

NOTAS

Utilice RELEASE SAVEPOINT para destruir un punto de guardado sin descartar los efectos de los comandos ejecutados después de que se estableció.

Especificar un nombre de punto de guardado que no ha sido establecido es un error.

Los cursores tienen un comportamiento algo no transaccional con respecto a los puntos de guardado. Cualquier cursor que se abra dentro de un punto de guardado se cerrará cuando se revierta el punto de guardado. Si un cursor abierto previamente se ve afectado por un comando FETCH o MOVE dentro de un punto de guardado que luego se revierte, el cursor permanece en la posición que FETCH le dejó apuntando (es decir, el movimiento del cursor causado por FETCH no se revierte). Cerrar un cursor tampoco se desvanece al revertir. Sin embargo, otros efectos secundarios causados por la consulta del cursor (como efectos secundarios de funciones volátiles llamadas por la consulta) sí se revierten si ocurren durante un punto de guardado que luego se revierte. Un cursor cuya ejecución causa que una transacción sea abortada se pone en un estado de no poder ejecutar, por lo que, aunque la transacción se pueda restaurar usando ROLLBACK TO SAVEPOINT, el cursor ya no se puede usar.

EJEMPLOS

Para deshacer los efectos de los comandos ejecutados después de que se estableció my_savepoint:

ROLLBACK TO SAVEPOINT my_savepoint;

Las posiciones del cursor no se ven afectadas por la reversión de puntos de guardado:

BEGIN;
DECLARE foo CURSOR FOR SELECT 1 UNION SELECT 2;
SAVEPOINT foo;
FETCH 1 FROM foo;
 ?column?
----------
        1
ROLLBACK TO SAVEPOINT foo;
FETCH 1 FROM foo;
 ?column?
----------
        2
COMMIT;

COMPATIBILIDAD

El estándar SQL especifica que la palabra clave SAVEPOINT es obligatoria, pero PostgreSQL y Oracle permiten omitirla. SQL permite solo WORK, no TRANSACTION, como palabra de relleno después de ROLLBACK. Además, SQL tiene una cláusula opcional AND [ NO ] CHAIN que actualmente no es soportada por PostgreSQL. Por lo demás, este comando cumple con el estándar SQL.
