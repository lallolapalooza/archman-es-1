DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles de splay y árboles rojo-negros.

En las definiciones de las macros, TYPE es el nombre de la etiqueta de una estructura definida por el usuario que debe contener un campo llamado FIELD, de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es el nombre de la etiqueta de una estructura definida por el usuario que debe ser declarada usando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME debe ser un prefijo único para cada árbol definido.

Los prototipos de las funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE o RB_GENERATE_STATIC. Ver los ejemplos a continuación para una explicación más detallada de cómo se utilizan estas macros.

ÁRBOLES DE SPLAY

Un árbol de splay es una estructura de datos autoorganizada. Cada operación en el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y reequilibra parcialmente el árbol.

Tiene el beneficio de que la localidad de las solicitudes provoca búsquedas más rápidas ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en memoria.

El Teorema de Equilibrio limita el tiempo total de acceso para m operaciones y n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para m accesos en un árbol de splay es O(lg n).

Un árbol de splay se encabeza con una estructura definida por la macro SPLAY_HEAD(). Una SPLAY_HEAD se declara como:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y struct TYPE es el tipo de los elementos a insertar en el árbol.

La macro SPLAY_ENTRY declara una estructura que permite conectar elementos en el árbol.

Para usar las funciones que modifican la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que gestiona el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE() pero debe usarse solo una vez.

Finalmente, el argumento CMP es el nombre de una función que compara nodos de árbol con otros. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, devuelve un valor menor que cero. Si son iguales, devuelve cero. De lo contrario, devuelve un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol referenciado por head.

El árbol de splay también puede inicializarse de forma estática usando la macro SPLAY_INITIALIZER() como:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. Una vez que se realiza con éxito, se devuelve NULL. Si ya existe un elemento correspondiente en el árbol, se aborta la inserción y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. Una vez que se realiza con éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() puede usarse para encontrar un elemento específico en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX() y SPLAY_NEXT() pueden usarse para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para mayor simplicidad, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol de splay está vacío.

ÁRBOLES ROJO-NEGRO

Un árbol rojo-negro es un árbol de búsqueda binario con el color de los nodos como una propiedad adicional. Cumple una serie de condiciones:

  1. Todo camino desde la raíz hasta un nodo hoja contiene el mismo número de nodos negros.
  2. Cada nodo rojo (excepto la raíz) tiene un padre negro.
  3. Cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada como O(lg n). La altura máxima de un árbol rojo-negro es 2lg(n+1).

Un árbol rojo-negro se encabeza con una estructura definida por la macro RB_HEAD(). Una RB_HEAD se declara así:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y struct TYPE es el tipo de los elementos a insertar en el árbol.

La macro RB_ENTRY declara una estructura que permite conectar elementos en el árbol.

Para usar las funciones que modifican la estructura del árbol, sus prototipos deben declararse con la macro RB_PROTOTYPE() o RB_PROTOTYPE_STATIC() donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que gestiona el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

Los cuerpos de las funciones se generan con la macro RB_GENERATE() o RB_GENERATE_STATIC() donde estas macros toman los mismos argumentos que la macro RB_PROTOTYPE() y RB_PROTOT

DESCRIPCIÓN

La macro RB_ENTRY se utiliza para definir una entrada en un árbol rojo-negro. La macro RB_INITIALIZER inicializa un árbol rojo-negro. La macro RB_INSERT inserta un nuevo elemento en el árbol. La macro RB_REMOVE elimina un elemento del árbol. Las macros RB_FIND y RB_NFIND buscan elementos en el árbol. Las macros RB_ROOT, RB_MIN, RB_MAX, RB_NEXT y RB_PREV recorren el árbol. Las macros RB_FOREACH y RB_FOREACH_SAFE iteran a través del árbol. La macro RB_EMPTY comprueba si el árbol está vacío.

La macro SPLAY_FOREACH itera a través de un árbol splay. La macro SPLAY_REMOVE elimina un elemento del árbol. Las macros SPLAY_MIN y SPLAY_MAX encuentran los elementos mínimo y máximo en el árbol. Las macros SPLAY_NEXT y SPLAY_PREV recorren el árbol.

EJEMPLOS

El siguiente ejemplo demuestra cómo declarar un árbol rojo-negro que contiene enteros. Se insertan valores en él y se imprime el contenido del árbol en orden. Por último, se imprime la estructura interna del árbol.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int intcmp(struct node *, struct node *);
void print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIA

NOTAS

Intentar liberar un árbol de la siguiente manera es un error común:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Dado que var se libera, la macro FOREACH() se refiere a un puntero que puede haber sido realocado ya. El código correcto necesita una segunda variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
