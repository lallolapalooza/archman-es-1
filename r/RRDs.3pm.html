NAME

RRDs - Accede a RRDtool como módulo compartido

SYNOPSIS

use RRDs;
RRDs::error
RRDs::last ...
RRDs::info ...
RRDs::create ...
RRDs::update ...
RRDs::updatev ...
RRDs::graph ...
RRDs::fetch ...
RRDs::tune ...
RRDs::times(start, end)
RRDs::dump ...
RRDs::restore ...
RRDs::flushcached ...
RRDs::register_fetch_cb ...
$RRDs::VERSION

DESCRIPTION

Secuencia de Llamada

Este módulo accede directamente a la funcionalidad de RRDtool desde Perl. Los argumentos de las funciones listadas en SYNOPSIS se explican en la documentación regular de RRDtool. La llamada a línea de comandos

rrdtool update mydemo.rrd --template in:out N:12:13

se traduce a

RRDs::update ("mydemo.rrd", "--template", "in:out", "N:12:13");

Nota que

--template=in:out

también es válido.

La función RRDs::times toma dos parámetros: un tiempo de "start" y uno de "end". Estos deben especificarse en el formato de especificación de tiempo estilo AT de RRDtool. Consulta la documentación de rrdfetch para una explicación detallada de cómo especificar el tiempo.

Manejo de Errores

Las funciones RRDs::update no detienen el programa incluso si no pueden interpretar los argumentos que les pasas.

La función RRDs::error debe ser llamada para obtener el estado del error después de cada llamada a una función. Si RRDs::error no devuelve nada, entonces la función anterior completó su tarea con éxito.

use RRDs;
RRDs::update ("mydemo.rrd","N:12:13");
my $ERR=RRDs::error;
die "ERROR while updating mydemo.rrd: $ERR\n" if $ERR;

Valores de Retorno

Las funciones RRDs::last, RRDs::graph, RRDs::info, RRDs::fetch y RRDs::times devuelven sus hallazgos.

RRDs::last devuelve un único ENTERO que representa el tiempo de la última actualización.

$lastupdate = RRDs::last ...

RRDs::graph devuelve un array con el ancho y alto de la imagen creada y un puntero a un array con los resultados de los argumentos PRINT.

($result_arr,$xsize,$ysize) = RRDs::graph ...
print "Image size: ${xsize}x${ysize}\n";
print "Averages: ", (join ", ", @$averages);

RRDs::info devuelve un puntero a un hash. Las claves del hash representan los nombres de las propiedades del RRD y los valores del hash son los valores de las propiedades.

$hash = RRDs::info "example.rrd";
foreach my $key (keys %$hash){
  print "$key = $$hash{$key}\n";
}

RRDs::graphv toma los mismos parámetros que RRDs::graph pero devuelve un puntero a un hash. El hash devuelto contiene información meta sobre la gráfica. Algunos ejemplos incluyen su tamaño y la posición de la zona gráfica en la imagen. Cuando se llama con '-' como nombre de archivo, el contenido de la gráfica se devuelve en el hash como (clave 'image').

RRDs::updatev también devuelve un puntero a un hash. Las claves del hash son cadenas concatenadas de un tiempo, índice de RRA y nombre de fuente de datos para cada punto de datos consolidado (CDP) escrito en disco como resultado de la llamada actual. Los valores del hash son los valores de los CDP.

RRDs::fetch es la más compleja en términos de valores devueltos. Hay cuatro valores. Dos enteros normales, un puntero a un array y un puntero a un array de punteros.

my ($start,$step,$names,$data) = RRDs::fetch ... 
print "Start:       ", scalar localtime($start), " ($start)\n";
print "Step size:   $step seconds\n";
print "DS names:    ", join (", ", @$names),"\n";
print "Data points: ", $#$data + 1, "\n";
print "Data:\n";
for my $line (@$data) {
  print "  ", scalar localtime($start), " ($start) ";
  $start += $step;
  for my $val (@$line) {
    printf "%12.1f ", $val;
  }
  print "\n";
}

RRDs::xport expone la funcionalidad de rrdxport y devuelve datos con la siguiente estructura:

my ($start,$end,$step,$cols,$names,$data) = RRDs::xport ...

# $start : timestamp
# $end   : timestamp
# $step  : segundos
# $cols  : número de columnas devueltas
# $names : arrayref con los nombres de las columnas
# $data  : arrayref de arrayrefs con los datos (primer índice es tiempo, segundo es columna)

RRDs::times devuelve dos enteros que son el número de segundos desde la época (1970-01-01) para los argumentos "start" y "end" respectivamente.

Consulta la carpeta de ejemplos para más formas de usar esta extensión.

Función de Callback de Recuperación

Normalmente, cuando se usa graph, xport o fetch, los datos que ves se obtendrán de un archivo rrd real. Algunos usuarios que disfrutan del estilo de gráficas de rrd exportan sus datos de una base de datos y luego los cargan en un archivo rrd para poder llamar a rrdgraph sobre ellos. Usando una función de callback personalizada, puedes proporcionar tu propio código para manejar las solicitudes de datos de graph, xport y fetch.

Para hacer esto, primero debes escribir una función fetch en perl, y luego registrar esta función usando RRDs::fetch_register_callback.

Finalmente puedes usar el nombre de ruta pseudo cb//[nombre de archivo] para indicar a rrdtool que use tu rutina de callback en lugar del método normal de recuperación de datos de rrd para organizar los datos necesarios.

La función de callback debe verse así:

sub fetch_callback {
    my $args_hash = shift;
    # {
    #  filename => 'cb//somefilename',
    #  cd => 'AVERAGE',
    #  start => 1401295291,   
    #  end => 1401295591,
    #  step => 300 }
    # hacer algo inteligente para obtener esos datos
    return {
        start => $unix_timestamp,
        step => $step_width,
        data => {
            dsName1 => [ value1, value2, ... ],
            dsName2 => [ value1, value2, ... ],
            dsName3 => [ value1, value2, ... ],
        }
   };
}

NOTA

Si manipulas la variable TZ, también debes llamar a la función POSIX tzset(3) para inicializar todos los estados internos de la biblioteca en la zona horaria de tu elección.

use POSIX qw(tzset);
$ENV{TZ} = 'CET';   
POSIX::tzset();
