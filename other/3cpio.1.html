DESCRIPCIÓ

N

3cpio es una herramienta para gestionar archivos cpio de initramfs para el kernel de Linux. El formato de búfer de initramfs https://www.kernel.org/doc/html/latest/driver-api/early-userspace/buffer-format.html del kernel de Linux se basa en los formatos cpio newc o crc. Se pueden concatenar múltiples archivos cpio y el último archivo puede estar comprimido. Se pueden usar diferentes algoritmos de compresión dependiendo del soporte compilado en el kernel de Linux. newc o crc. Se pueden concatenar múltiples archivos cpio y el último archivo puede estar comprimido. Se pueden usar diferentes algoritmos de compresión dependiendo del soporte compilado en el kernel de Linux. 3cpio está adaptado a los archivos cpio de initramfs y no obtendrá soporte para otros formatos

cpio.

Se admiten los siguientes forma

tos de compresión: bzip2, gzip,
lz4, lzma, lzop, xz, zstd.

OPCIONE

S

--data-align ALINEACIÓ

N
Al crear un archivo cpio, rellena los metadatos cpio para alinear los datos del archivo en ALINEACIÓN en bytes. Esta opción es útil para hacer reflink de los datos del archivo cpio en sistemas de archivos que admiten reflinks. Este relleno/alineación se omitirá para archivos que sean más pequeños que ALINEACIÓN, archivos donde el campo namesize rellenado excedería PATH_MAX, y para archivos cpio que estén comprimidos. ALINEACIÓN debe ser un múltiplo de 4 bytes. Esta opción solo se tiene en cuenta en el modo --create.

El archivo cpio resultante puede estar altamente fragmentado, lo que puede llevar a una degradación del rendimiento al leer/extraer la imagen desde dispositivos con E/S aleatoria lenta (p. ej. disco giratorio)

.

Nota: Usar esta opción "doblará" un poco la especificación cpio newc para inyectar ceros después del nombre de archivo para proporcionar alineación del segmento de datos. Estos ceros se tienen en cuenta en el namesize, pero algunas aplicaciones pueden esperar solo un único terminador cero (y alineación de 4 bytes). GNU cpio y el initramfs de Linux manejan esto bien siempre que PATH_MAX no se

exceda.

El siguiente comando se puede usar para determinar el tamaño de transferencia óptimo del sistema de archivos (donde $path es la ruta donde se escribirá el archivo cpio)

MANIFIEST

O

Al generar archivos cpio de initrd, se usará el siguiente formato de manifiesto. El manifiesto es un formato de texto que se analiza línea por

línea.

Si la línea comienza con #cpio se interpreta como un marcador de sección para empezar un nuevo cpio. Se puede especificar una compresión añadiendo dos puntos seguidos del formato de compresión y un nivel de compresión opcional. Ejemplo para un cpio comprimido con Zstandard con nivel de compresión

9: iv class="Bd-indent"> 
#cpio
: zs
td -9

Todas las líneas que comiencen con # excluyendo #cpio (ver arriba) se tratarán como comentarios y serán

ignoradas.

Cada elemento en la línea está separado por un tabulador y se espera que sea uno de los siguientes tipos de

archivo: 
<ubicación> <nombre> file <modo> <uid> <gid> <mtime> <tamaño_archivo>
<ubicación> <nombre> dir <modo> <uid> <gid> <mtime>
<ubicación> <nombre>
block <modo> <uid> <gid> <mtime> <mayor> <menor> <ubicación> <nombre> char <modo> <uid> <gid> <mtime> <mayor> <menor> <ubicación> <nombre> link
<modo> <uid> <gid> <mtime> <destino> <ubicación> <nombre> fifo <modo> <uid> <gid> <mtime> <ubicación> <nombre> sock <modo> <uid> <gid> <mtime>

fifo también se conoce como tubería con nombre (ver fifo(7))

.

En caso de que un elemento esté vacío o sea igual a -, se trata como no especificado y se deriva del archivo de

entrada.

<ubicación

>
Ruta del archivo de entrada. Se puede dejar sin especificar en caso de que todos los demás campos necesarios estén especificados (y el archivo esté vacío de lo contrario). Limitación: La ruta no debe comenzar con #, ser igual a -, ni contener
tabuladores.

<nombre

>
Ruta del archivo dentro del cpio. Si el nombre se deja sin especificar, se derivará de <ubicación>. Limitación: La ruta no debe ser igual a - ni contener
tabuladores.

<modo

>
Modo de archivo especificado en
octal.

<uid

>
ID de usuario (propietario) del archivo especificado en
decimal.

<gid

>
ID de grupo del archivo especificado en
decimal.

<mtime

>
Hora de modificación del archivo especificada como segundos desde la Época (1970-01-01 00:00 UTC). La hora especificada puede ser limitada por la hora establecida en la variable de entorno SOURCE_DATE_EPOCH
.

<tamaño_archivo

>
Tamaño del archivo de entrada en bytes. 3cpio fallará en caso de que el archivo de entrada sea más pequeño que el tamaño de archivo
proporcionado.

<mayor

>
Número mayor del dispositivo de bloque/carácter en
decimal.

<menor

>
Número menor del dispositivo de bloque/carácter en
decimal.

<destino

>
Destino del enlace simbólico. Limitación: La ruta de destino no debe ser igual a - ni contener
tabuladores.

Limitaciones: Los archivos no pueden comenzar con # (se tratará como comentario), ser igual a - (se tratará como no especificado), ni contener

tabuladores (se dividirán por tabuladores). Estas limitaciones del ar
chivo de manifiesto no se espera que causen problemas en la práctica.
