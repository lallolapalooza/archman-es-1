NOMBRE

__pmProcessAddArg, __pmProcessUnpickArgs, __pmProcessExec - soporte para la ejecución de procesos

S C SINOPSIS

#include "pmapi.h"
#include "libpcp.h"

int __pmProcessAddArg(__pmExecCtl_t **handle, const char *arg);
int __pmProcessUnpickArgs(__pmExecCtl_t **handle,
const char *command);

int __pmProcessExec(__pmExecCtl_t **handle,
int toss, int wait);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada al uso interno de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las APIs de PCP que se garantiza que permanecerán fijas en las diferentes versiones, y pueden no funcionar, o proporcionar semánticas diferentes en algún momento futuro.

DESCRIPCIÓN

Dentro de las bibliotecas y aplicaciones de Performance Co-Pilot (PCP), estas rutinas proporcionan una alternativa conveniente y segura a system(3) para ejecutar comandos en un proceso separado.

Utilice __pmProcessAddArg para registrar el ejecutable y los argumentos del comando en orden. handle debe establecerse en NULL antes de la primera llamada a __pmProcessAddArg para una ejecución de comando particular y se establecerá en un puntero opaco a estructuras de datos que se manipulan en __pmProcessAddArg, __pmProcessExec y las rutinas relacionadas de __pmProcessPipe(3).

Cuando se llama con handle establecido en NULL, arg se trata como el nombre del comando a ejecutar y las llamadas posteriores (si las hay) son para los argumentos de ese comando. El nombre del comando puede ser una ruta completa, o el nombre de un ejecutable que se puede encontrar en el $PATH actual según las reglas de execvp(2) que utiliza __pmProcessExec.

__pmProcessUnpickArgs es un envoltorio de conveniencia para asistir en la conversión de código que asume que el command es un comando de shell que ha sido preparado para su uso con system(3) o popen(3) en código existente. Los argumentos en command se extraen uno por uno y se usan para llamar a __pmProcessAddArg. El analizador es simple, ya que la rutina está diseñada para una sintaxis de comando de shell simple, donde los argumentos están separados por uno o más espacios, pero se permiten espacios incrustados dentro de un argumento si el argumento está entre comillas simples o dobles. No se reconocen sintaxis de shell más avanzadas, como caracteres de escape y redirección de entrada-salida.

Una vez que se han registrado el nombre del comando y todos sus argumentos, llamar a __pmProcessExec utiliza una secuencia de fork(2) y execvp(2) para ejecutar el comando.

El argumento toss se puede usar para asignar algunos o todos los flujos de E/S estándar del comando a /dev/null - específicamente, toss es PM_EXEC_TOSS_NONE para mantener todos los flujos de E/S iguales que el proceso padre, o el bitwise OR de PM_EXEC_TOSS_STDIN y/o PM_EXEC_TOSS_STDOUT y/o PM_EXEC_TOSS_STDERR para reasignar stdin, stdout y stderr respectivamente. PM_EXEC_TOSS_ALL es una macro de conveniencia equivalente a PM_EXEC_TOSS_STDIN | PM_EXEC_TOSS_STDOUT | PM_EXEC_TOSS_STDERR.

El argumento wait debe ser PM_EXEC_WAIT si __pmProcessExec debe esperar a que el comando se complete y recoja el estado de salida, de lo contrario, PM_EXEC_NOWAIT, en cuyo caso __pmProcessExec regresa inmediatamente (ejecutando efectivamente el comando en segundo plano).

No se permiten llamadas anidadas de __pmProcessExec y/o __pmProcessPipe(3). Una vez que se llama a __pmProcessAddArg con handle establecido en NULL para iniciar la secuencia de registro y ejecución, cualquier intento de iniciar una segunda secuencia de registro se bloqueará hasta que la primera se complete llamando a __pmProcessExec o __pmProcessPipe(3).

DIAGNÓSTICO

Si tiene éxito, __pmProcessAddArg devuelve 0. Otras condiciones son raras (por ejemplo, falla de asignación de memoria) y se indican mediante un valor de retorno que puede ser decodificado usando pmErrStr(3). Cuando ocurre un error, __pmProcessAddArg limpia cualquier asignación realizada en la llamada actual y utiliza handle para limpiar cualquier asignación realizada por llamadas anteriores, por lo que no es necesario que el llamador se preocupe por fugas de memoria, y luego (re)establece handle en NULL antes de regresar.

__pmProcessUnpickArgs devuelve 0 si tiene éxito. En el caso de una cadena no terminada, se genera un mensaje y se devuelve PM_ERR_GENERIC. Otros valores de retorno menores que 0 indican un error más grave y el valor puede ser decodificado usando pmErrStr(3). Cuando ocurre un error, la limpieza es similar a __pmProcessAddArg, por lo que no es necesario que el llamador se preocupe por fugas de memoria.

El estado de retorno de __pmProcessExec es más complicado. Si se especifica PM_EXEC_NOWAIT, o si el comando se completa con un estado de salida de 0, el valor de retorno es 0. Los valores de retorno menores que 0 indican un error más grave y el valor puede ser decodificado usando pmErrStr(3). Si el comando se ejecutó, pero no salió con un estado de 0, entonces el valor de retorno es una codificación del estado de waitpid(2) de la siguiente manera: 2000 si algo desconocido salió mal, de lo contrario, si 1000 + el número de señal del comando fue terminado o detenido por una señal, de lo contrario, el estado de salida del comando.

VER TAMBIÉN

execvp(2), fork(2), __pmProcessPipe(3), popen(3), system(3) y waitpid(3).
