DESCRIPCIÓ

N

__pmControlLog puede usarse para habilitar o deshabilitar el archivo de métricas de rendimiento particulares, identificadas por el parámetro request; consulte pmFetch(3) para una explicación de la estructura pmResult

.

La aplicación debe haber emitido previamente una llamada a __pmConnectLogger(3) para establecer una conexión de puerto de control con la instancia de pmlogger(1) a la que se dirigirá la solicitud de control, y fd (el resultado de __pmConnectLogger(3)) identifica esta

conexión.

Dentro de request, solo se usarán los detalles de las métricas de rendimiento y sus instancias asociadas, es decir, los valores de las métricas, si los hay, serán ignorados. request normalmente se construiría como el resultado de una llamada anterior a pmFetch(3). Para métricas con un valor singular (teniendo un dominio de instancia de PM_INDOM_NULL) el pmValueSet correspondiente debería tener el valor uno en el campo numval y PM_IN_NULL como el campo inst del único pmValue suministrado. Si se van a registrar múltiples instancias explícitas, el campo numval del pmValueSet debería contener el número de instancias suministradas y los campos inst de las estructuras pmValue deberían contener identificadores de instancia específicos (que no pueden tener el valor reservado PM_IN_NU

LL).

Si el campo numval dentro de cualquiera de las estructuras pmValueSet en request tiene un valor de cero, indica que todas las instancias disponibles de la métrica deberían usarse. La enumeración del dominio de instancia se difiere hasta que el registrador obtiene la métrica antes de escribirla en el archivo, en lugar de realizarse cuando se recibe la solicitud __pmControlLog. Esto es útil para métricas con dominios de instancia que cambian con el tiempo. Es un error especificar numval igual a cero si la métrica correspondiente tiene un valor singular (sin dominio de instancia)

.

Hay varios tipos de control de registro disponibles, a saber, obligatorio o consultivo, según lo definido por el argumento control, y on, off o maybe según lo definido por el argumento state. Estos diferentes tipos de control pueden usarse para garantizar que algunas métricas de rendimiento estén siempre en el archivo, mientras que otras pueden habilitarse o deshabilitarse dinámicamente según el nivel y tipo de actividad del

sistema.

La acción real a realizar está definida por la combinación de control y state como sigue. Si control es PM_LOG_MANDATORY y state es PM_LOG_ON, entonces el registro se habilita. Si control es PM_LOG_MANDATORY y state es PM_LOG_OFF, entonces el registro se deshabilita. Si control es PM_LOG_MANDATORY y state es PM_LOG_MAYBE, entonces los controles consultivos subsiguientes serán atendidos. Si el estado de registro previo a la solicitud era obligatorio (on u off), el estado se cambia a consultivo off. Si el estado de registro ya era consultivo (ya sea on u off), permanece sin cambios. Si control es PM_LOG_ADVISORY y el último control obligatorio para la métrica fue PM_LOG_MAYBE, entonces el registro se habilita o deshabilita según lo especificado por el argumento state, es decir, PM_LOG_ON o PM_LOG_OFF. Cuando los argumentos state y control especifican una solicitud para cambiar el comportamiento de registro, el argumento delta define el intervalo de registro en milisegundos que se aplicará a todas las métricas e instancias identificadas en request

.

El argumento resultado status devuelve el estado de registro actual para cada una de las métricas de rendimiento nominadas. Hay una correspondencia 1:1 entre los elementos de request y status. Para las métricas en request que tienen pmValueSets con numval igual a cero, el pmValueSet correspondiente en result contendrá un valor para cada instancia disponible en el momento de la llamada. Cada valor de métrica en status tendrá el estado de registro actual codificado en él. El resultado detallado de la operación para cada métrica puede determinarse comparando estos valores con los solicitados a través de control, state y delta

.

Las macros definidas en libpcp.h pueden usarse para extraer el estado y el intervalo de registro de los valores de métrica devueltos. PMLC_GET_ON devuelve true si el registro está activado, o false si está desactivado; PMLC_GET_MAND devuelve true si el registro es obligatorio, o false si es consultivo; PMLC_GET_INLOG devuelve true si la métrica ha sido registrada al menos una vez, o false en caso contrario; PMLC_GET_AVAIL devuelve true si la métrica estuvo disponible de su fuente la última vez que se suponía que debía registrarse, o false si no estuvo disponible; y PMLC_GET_DELTA devuelve el intervalo de registro actual para la métrica (en milisegundos). PMLC_MAX_DELTA define el mayor delta que puede devolverse en un valor de métrica

codificado.

Como caso especial, cuando control es PM_LOG_ENQUIRE, state y delta se ignoran, y status devuelve el estado de registro actual de las métricas de rendimiento nominadas (esta variante no hace cambios en el estado de registro)

.

Si el valor del intervalo de registro es 0, ya sea para delta en una solicitud para cambiar el estado a PM_LOG_ON, o codificado en el valor devuelto desde PM_LOG_ENQUIRE, entonces esto corresponde al registro especial "solo una vez" de métricas que aparecen una vez en el archivo y nunca se registran de

nuevo.
