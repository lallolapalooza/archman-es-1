PMNOTIFYTHROTTLE(3) Manual de funciones de biblioteca PMNOTIFYTHROTTLE(3)

NOMBRE

__pmNotifyThrottle, __pmResetNotifyThrottle - controlar la "inundación" de mensajes de salida de diagnóstico

C SINOPSIS

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>

int __pmNotifyThrottle(char *key, int subkey);
int __pmResetNotifyThrottle(char *key, int subkey);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada al uso interno de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las API de PCP que se garantiza que permanecerán fijas entre versiones, y pueden no funcionar, o proporcionar semánticas diferentes en algún momento en el futuro.

DESCRIPCIÓN

Cuando la misma condición de error ocurre una y otra vez, como en un ataque DoS, o un fallo catastrófico de red, o una mala configuración del sistema, o un error de software, existe el riesgo de que una aplicación PCP pueda generar un gran número de mensajes de diagnóstico idénticos, llenando un archivo de registro y, por lo tanto, un sistema de archivos. __pmNotifyThrottle está diseñado para usarse como una guardia que puede detectar llamadas repetidas para la misma condición de error y permitir al llamador dejar de emitir mensajes cuando ocurren repetidamente cosas malas.

La condición de error se identifica mediante key y subkey, y el caso de uso más común sería que estos fueran __FILE__ y __LINE__ en el punto donde se llama a __pmNotifyThrottle.

Para cada par único de key y subkey, __pmNotifyThrottle mantiene un recuento del número de veces que se ha llamado durante la vida del proceso llamador.

Los valores de retorno son 0 si el límite de aceleración para key y subkey no se ha alcanzado, 1 si el límite de aceleración se ha alcanzado, y 2 si el límite de aceleración se ha superado.

El mismo límite de aceleración se aplica a todas las condiciones de error y se establece mediante la variable de entorno PCP_NOTIFY_THROTTLE, o un valor predeterminado de 10 si la variable de entorno no está establecida, aunque esto puede modificarse posteriormente llamando a __pmResetNotifyThrottle.

__pmResetNotifyThrottle se puede utilizar para restablecer el contador de una condición de error a cero, de modo que la salida de diagnóstico pueda reanudarse si el llamador determina que es seguro hacerlo. Si limit es mayor que cero, entonces también se restablece el límite para la condición de error; de lo contrario, el límite no cambia.

Llamar a __pmResetNotifyThrottle con un valor de key NULL restablecerá los contadores (y posiblemente los límites) para todas las condiciones de error, y en este caso, si limit es mayor que cero, también se establecerá el límite predeterminado para cualquier nueva condición de error (anulando la configuración predeterminada o el valor inicializado desde la variable de entorno PCP_NOTIFY_THROTTLE).

__pmResetNotifyThrottle devolverá -ENOENT si key y subkey no coinciden con una condición de error existente; de lo contrario, el valor de retorno es la suma del número de veces que se ha superado el límite en todas las condiciones de error seleccionadas.

EJEMPLO

El siguiente es un simple acelerador que deja de informar errores después de 10 ejecuciones. 

if ((sts = __pmNotifyThrottle(__FILE__, __LINE__)) < 2) {
    fprintf(stderr, "Algún mensaje de error\n");
    if (sts == 1)
	fprintf(stderr, "[se suprimirán más mensajes]\n");
}

El ejemplo más sofisticado a continuación limita los mensajes, pero los habilita nuevamente después de 10 minutos. 

int    lineno;
time_t first_throttle;
...
lineno = __LINE__ + 1;
if ((sts = __pmNotifyThrottle(__FILE__, lineno)) < 2) {
    pmNotifyErr(LOG_INFO, "Algún mensaje de error");
    if (sts == 1) {
	first_throttle = time(NULL);
	pmNotifyErr(LOG_INFO, "[se suprimirán más mensajes]");
    }
}
else if (sts == 2) {
    if (time(NULL) - first_throttle >= 600) {
	sts = __pmResetNotifyThrottle(__FILE__, lineno, -1);
	pmNotifyErr(LOG_INFO, "[%d mensajes fueron suprimidos]", sts);
    }
}
