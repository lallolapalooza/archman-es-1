__pmProcessPipe(3)

PMPROCESSPIPE(3) Manual de funciones de la biblioteca PMPROCESSPIPE(3)

NOMBRE

__pmProcessPipe, __pmProcessPipeClose - soporte para la ejecución de procesos al final de una tubería

SINOPSIS C

#include"pmapi.h"
#include"libpcp.h"

int __pmProcessPipe(__pmExecCtl_t **handle,
const char *type, int toss, FILE **fp);

int __pmProcessPipeClose(FILE *fp);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada únicamente al uso interno por parte de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las APIs de PCP que se garantiza que permanecerán fijas entre versiones, y es posible que no funcionen o que ofrezcan semánticas diferentes en algún momento futuro.

DESCRIPCIÓN

Dentro de las bibliotecas y aplicaciones de Performance Co-Pilot (PCP), estas rutinas proporcionan una alternativa conveniente y segura a popen(3) y pclose(3) para ejecutar comandos en un proceso separado que está conectado al llamador mediante una tubería.

La configuración del comando y los argumentos está completamente documentada en __pmProcessAddArg(3) y es idéntica al procedimiento utilizado para configurar __pmProcessExec(3).

Una vez que se han registrado el nombre del comando y todos los argumentos, llamar a __pmProcessPipe utiliza una secuencia de pipe(2), fork(2) y execvp(2) para ejecutar el comando.

El argumento type debe ser ``r'' para leer de la tubería, de lo contrario ``w'' para escribir en la tubería.

El argumento toss se puede utilizar para asignar todos o algunos de los flujos de E/S estándar del comando a /dev/null; específicamente, toss es PM_EXEC_TOSS_NONE para mantener todos los flujos de E/S iguales a los del proceso padre, o bien, el OR a nivel de bits de PM_EXEC_TOSS_STDIN y/o PM_EXEC_TOSS_STDOUT y/o PM_EXEC_TOSS_STDERR para reasignar stdin, stdout y stderr respectivamente. PM_EXEC_TOSS_ALL es una macro de conveniencia equivalente a PM_EXEC_TOSS_STDIN | PM_EXEC_TOSS_STDOUT | PM_EXEC_TOSS_STDERR.

Obviamente, algunas combinaciones de valores de argumento no tienen sentido, por ejemplo, type igual a ``r'' y PM_EXEC_TOSS_STDOUT establecido en toss o type igual a ``w'' y PM_EXEC_TOSS_STDIN establecido en type.

__pmProcessPipe devuelve un flujo de E/S estándar para la tubería a través del argumento fp.

Una vez que el llamador determina que se ha completado todo el trabajo, se debe llamar a __pmProcessPipeClose.

No se permiten llamadas anidadas a __pmProcessExec(3) y/o __pmProcessPipe. Una vez que se llama a __pmProcessAddArg(3) con handle establecido en NULL para iniciar la secuencia de registro y ejecución, cualquier intento de iniciar una segunda secuencia de registro se bloqueará hasta que la primera se complete llamando a __pmProcessExec(3) o __pmProcessPipe.

DIAGNÓSTICO

Si tiene éxito, __pmProcessPipe devuelve 0. Otras condiciones son raras (por ejemplo, error de asignación de memoria) y se indican mediante un valor de retorno que se puede decodificar utilizando pmErrStr(3).

El estado de retorno de __pmProcessPipeClose es un poco más complicado. Si el comando se completa con un estado de salida de 0, el valor de retorno es 0. Los valores de retorno menores que 0 indican un error más grave y el valor se puede decodificar utilizando pmErrStr(3). Si el comando se ejecutó, pero no finalizó con un estado de 0, el valor de retorno es una codificación del estado de waitpid(2) de la siguiente manera: 2000 si ocurrió algo desconocido, o si 1000 + el número de señal del comando fue terminado o detenido por una señal, o el estado de salida del comando.

VER TAMBIÉN

execvp(2), fork(2), pclose(2), pipe(2), popen(2), __pmProcessAddArg(3), __pmProcessExec(3) y waitpid(3).
