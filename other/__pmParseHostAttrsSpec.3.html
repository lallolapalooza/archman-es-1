NOMBRE

__pmParseHostAttrsSpec, __pmUnparseHostAttrsSpec, __pmFreeHostAttrsSpec, __pmFreeAttrsSpec - analizador de especificación de hosts y atributos

C SINOPSIS

#include "pmapi.h"
#include "libpcp.h"

int __pmParseHostAttrsSpec(const char *string,
__pmHostSpec **hostsp, int *count, __pmHashCtl *attrs, char **errmsg);

int __pmUnparseHostAttrsSpec(__pmHostSpec *hostsp,
int *count, __pmHashCtl *attrs, char *string, size_t size);

void __pmFreeHostAttrsSpec(__pmHostSpec *hosts,
int count, __pmHashCtl *attrs);

void __pmFreeAttrsSpec(__pmHashCtl *attrs);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada únicamente al uso interno de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las API de PCP que se garantiza que permanecerán fijas a lo largo de las versiones, y es posible que no funcionen, o que proporcionen una semántica diferente en algún momento futuro.

DESCRIPCIÓN

__pmParseHostAttrsSpec acepta una cadena que especifica la ubicación de un demonio colector de métricas de rendimiento de PCP, y cualquier atributo que deba asociarse con la conexión a ese demonio.

La sintaxis permite la especificación opcional de un protocolo (protocolo nativo de PCP, protocolo de PCP cifrado o protocolo de socket de dominio Unix).

Si el protocolo especificado es el protocolo nativo de PCP o el protocolo de PCP cifrado, se puede especificar un nombre de host de pmcd(1) inicial con números de puerto opcionales y un host proxy opcional, y atributos opcionales que se asociarán con la conexión. Algunos ejemplos son:


pcp://nas1.servers.com:44321@firewalls.r.us?compress
pcps://nas1.servers.com?user=otto&pass=blotto&compress

Si el protocolo especificado es un protocolo de socket de dominio Unix, se puede especificar la ruta al socket en el sistema de archivos local junto con atributos opcionales que se asociarán con la conexión. Por ejemplo:


unix://$PCP_RUN_DIR/pmcd.socket:?compress
local://my/local/pmcd.socket:?user=otto&pass=blotto&compress

Si no se especifica el componente de protocolo opcional, se utilizará la configuración predeterminada, que es el protocolo binario nativo de PCP. Sin embargo, esto aún se puede anular a través del entorno como se describe en PCPIntro(1). Si se especifica el prefijo del protocolo, debe ser uno de los siguientes: "pcp://" (claro), "pcps://" (seguro, cifrado), "unix://" (local autenticado) o "local://" ("unix://" y luego "pcp://").

La ruta especificada para los protocolos "unix://" y "local://" siempre se interpretará como una ruta de nombre absoluto. Por ejemplo, las siguientes se interpretan de forma idéntica como $PCP_RUN_DIR/pmcd.socket.


unix://$PCP_RUN_DIR/pmcd.socket
unix:/$PCP_RUN_DIR/pmcd.socket
unix:$PCP_RUN_DIR/pmcd.socket

Consulte __pmParseHostSpec(3) para obtener más detalles sobre los componentes de host y host proxy.

Si se van a especificar atributos de conexión opcionales, estos se separan del componente del nombre de host mediante el carácter '?'. Cada atributo se separa mediante el carácter '&', y cada uno puede ser una bandera de atributo simple (como "compress") o un par nombre=valor (como "username=fred").

__pmParseHostAttrsSpec toma una cadena de especificación de host y atributos terminada en nulo string y devuelve una matriz de estructuras __pmHostSpec, donde la matriz tiene count entradas, y una tabla hash attrs que contiene cualquier atributo (incluido el protocolo opcional, si se especificó).

Los detalles completos de las estructuras __pmHostSpec se proporcionan en __pmParseHostSpec(3).

La estructura __pmHashCtl que se rellena al regresar a través de attributes, representa cada atributo individual en la especificación string con cualquier valor asociado. Debe considerarse una estructura opaca y debe inicializarse a cero de antemano.

La estructura de control de tabla hash devuelta puede iterarse utilizando uno de los mecanismos de iteración proporcionados: __pmHashWalkCB (un mecanismo basado en callbacks) o __pmHashWalk (un mecanismo procedural simple). Estos proporcionan acceso a los nodos hash individuales, como entradas __pmHashNode, que proporcionan acceso a los atributos decodificados y sus valores (opcionales).

    typedef struct __pmHashNode {
        __pmHashNode    *next;    /* próximo nodo en el cubo hash (interno) */
        unsigned int    key;      /* clave que identifica un atributo particular */
        void            *data;    /* valor del atributo (opcional, cadena) */
    } __pmHashNode;

Existe un número fijo de atributos válidos, sin embargo, estos pueden extenderse en futuras versiones a medida que se necesiten nuevos parámetros de conexión. Estos pueden identificarse a través de las macros PCP_ATTR_* en los archivos de encabezado de PCP.

__pmUnparseHostSpec realiza la operación inversa, creando una representación de cadena a partir de las estructuras hosts y attributes. El tamaño del búfer de cadena suministrado debe ser proporcionado por el llamante utilizando el parámetro size.

VALOR DEVUELTO

Si la cadena dada se analiza correctamente, __pmParseHostAttrsSpec devuelve cero. En este caso, el almacenamiento dinámico asignado por __pmParseHostAttrsSpec se puede liberar llamando a __pmFreeHostAttrsSpec utilizando las direcciones devueltas por __pmParseHostAttrsSpec

Alternativamente, la memoria de hosts y attributes puede liberarse por separado, utilizando __pmFreeHostSpec(3) y __pmFreeAttrsSpec.

__pmParseHostAttrsSpec devuelve PM_ERR_GENERIC y una cadena de mensaje de error asignada dinámicamente en errmsg, si la cadena dada no se analiza y el puntero errmsg proporcionado por el usuario no es nulo. Asegúrese de free(3) la cadena de mensaje de error en esta situación.

En caso de error, tanto hosts como attributes no están definidos. En caso de éxito, errmsg no está definido.

En caso de éxito, __pmUnparseHostAttrsSpec devuelve un valor positivo que indica el número de caracteres escritos en el búfer suministrado. Sin embargo, si el búfer suministrado era demasiado pequeño, se devolverá un código de estado negativo de -E2BIG.
