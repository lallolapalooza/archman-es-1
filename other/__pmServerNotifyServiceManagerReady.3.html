PMSERVERNOTIFYSERVICEMANAGERREADY(3) Manual de Funciones de Biblioteca PMSERVERNOTIFYSERVICEMANAGERREADY(3)

NOMBRE

__pmServerNotifyServiceManagerReady, __pmServerNotifyServiceManagerStopping - Notificar inicio y fin de servicio

S C SINOPSIS

#include "pmapi.h"
#include "libpcp.h"

int __pmServerNotifyServiceManagerReady(pid_t mainpid);
int __pmServerNotifyServiceManagerStopping(pid_t mainpid);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada únicamente para uso interno de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las APIs de PCP que se garantizan que permanezcan fijas a lo largo de las versiones, y pueden no funcionar, o pueden proporcionar semántica diferente en algún momento futuro.

DESCRIPCIÓN

Dentro de las bibliotecas y aplicaciones de Performance Co-Pilot (PCP), estas rutinas proporcionan una interfaz conveniente y portátil a las APIs del gestor de servicios, como sd_notify(3).

Los demonios de servicio de PCP deben llamar a __pmServerNotifyServiceManagerReady inmediatamente antes de entrar en su bucle principal, independientemente de si se han bifurcado o se han desvinculado. Esto notificará al gestor de servicios (si lo hay, dependiendo de la plataforma) que el servicio del demonio ha comenzado, y que el proceso principal a seguir es mainpid.

Del mismo modo, al apagar, los demonios de servicio deben llamar a __pmServerNotifyServiceManagerStopping para notificar al gestor de servicios (si lo hay) que el proceso rastreado del servicio ha regresado de su bucle principal y está a punto de apagarse.

Estas rutinas están destinadas a ser portátiles y, por lo tanto, no se necesitará código condicional para ningún demonio de servicio en ninguna plataforma.

DIAGNÓSTICOS

Estas funciones imprimirán diagnósticos en el flujo stderr si pmDebugOptions.services está establecido.

C ÓDIGO DE RETORNO

Si tiene éxito, __pmServerNotifyServiceManagerReady devuelve un entero positivo que depende del gestor de servicios de la plataforma. En el caso de systemd(1), el código de retorno es de sd_notify(3). Si la plataforma soporta systemd(1) pero la variable de entorno NOTIFY_SOCKET no está establecida (como puede ser el caso si el programa servidor se inicia manualmente en lugar de por systemd(1)), el código de retorno será PM_ERR_GENERIC que normalmente se ignorará, pero se imprimirá un diagnóstico si pmDebugOptions.services está establecido. En plataformas que no tienen gestor de servicios, el código de retorno será PM_ERR_NYI. Para compatibilidad hacia atrás en estas plataformas, el código de retorno debe ser ignorado.
