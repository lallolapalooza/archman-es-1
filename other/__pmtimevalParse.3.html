NOMBRE

__pmtimevalParse, __pmtimespecParse - analizar especificación de punto en el tiempo

SINOPSIS C

#include "pmapi.h"
#include "libpcp.h"

int __pmtimevalParse(const char *string,
struct timeval *logStart, struct timeval *logEnd, struct timeval *rslt, char **errMsg);

int __pmtimespecParse(const char *string,
struct timespec *logStart, struct timespec *logEnd, struct timespec *rslt, char **errMsg);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada al uso interno de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las APIs de PCP que se garantiza que permanecerán fijas a lo largo de las versiones, y pueden no funcionar, o proporcionar semánticas diferentes en algún momento futuro.

DESCRIPCIÓN

__pmtimevalParse y __pmtimespecParse están diseñados para encapsular la interpretación de una especificación de punto en el tiempo en modificadores de línea de comandos para su uso por las herramientas cliente de PCP.

Estas funciones esperan ser llamadas con la especificación del punto en el tiempo como string. Si la herramienta se está ejecutando contra archivos de PCP, también necesita proporcionar la hora de inicio del primer (y único) archivo como logStart, y el final del último (y único) archivo como logEnd. Consulte pmGetArchiveLabel(3) y pmGetArchiveEnd(3) para saber cómo obtener los valores para estos parámetros. Si la herramienta se está ejecutando contra una transmisión en vivo de datos de rendimiento, logStart debe ser la hora actual (pero podría alinearse al próximo segundo, por ejemplo), mientras que logEnd debe tener su componente tv_sec establecido a PM_MAX_TIME_T.

La estructura rslt debe ser asignada antes de llamar a __pmtimevalParse o __pmtimespecParse.

También necesita establecer la zona horaria de informes de PCP actual para reflejar correctamente los parámetros de línea de comandos -z y -Z antes de llamar a __pmtimevalParse o __pmtimespecParse. Consulte pmUseZone(3) y similares para obtener información sobre cómo se hace esto.

Si la conversión es exitosa, tanto __pmtimevalParse como __pmtimespecParse devuelven 0 y rellenan rslt con el valor de tiempo definido por los parámetros de entrada. Si las cadenas de argumentos no pudieron ser analizadas, devuelven -1 y un mensaje de error asignado dinámicamente en errMsg. Asegúrese de free(3) este mensaje de error.
