select(2) Manual de Llamadas al Sistema select(2)

NOMBRE

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - multiplexación de E/S síncrona

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/select.h>
typedef /* ... */ fd_set;
int select(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
void FD_CLR(int fd, fd_set *set);
int  FD_ISSET(int fd, const fd_set *set);
void FD_SET(int fd, fd_set *set);
void FD_ZERO(fd_set *set);
int pselect(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           const struct timespec *_Nullable restrict timeout,
           const sigset_t *_Nullable restrict sigmask);

DESCRIPCIÓN

ADVERTENCIA: select() solo puede monitorizar descriptores de archivo cuyos números sean menores que FD_SETSIZE (1024), un límite irrazonablemente bajo para muchas aplicaciones modernas, y esta limitación no cambiará. Todas las aplicaciones modernas deberían usar en su lugar poll(2) o epoll(7), que no sufren esta limitación.

select() permite a un programa monitorizar múltiples descriptores de archivo, esperando hasta que uno o más de los descriptores de archivo se vuelvan "listos" para alguna clase de operación de E/S (por ejemplo, entrada posible). Un descriptor de archivo se considera listo si es posible realizar una operación de E/S correspondiente (por ejemplo, read(2), o un write(2) suficientemente pequeño) sin bloquear.

fd_set

Un tipo de estructura que puede representar un conjunto de descriptores de archivo. Según POSIX, el número máximo de descriptores de archivo en una estructura fd_set es el valor de la macro FD_SETSIZE.

Conjuntos de descriptores de archivo

Los argumentos principales de select() son tres "conjuntos" de descriptores de archivo (declarados con el tipo fd_set), que permiten al llamador esperar tres clases de eventos en el conjunto de descriptores de archivo especificado. Cada uno de los argumentos fd_set puede especificarse como NULL si no se van a observar descriptores de archivo para la clase de eventos correspondiente.

¡Atención!: Tras el retorno, cada uno de los conjuntos de descriptores de archivo se modifica in situ para indicar cuáles descriptores de archivo están actualmente "listos". Por lo tanto, si se utiliza select() dentro de un bucle, los conjuntos *deben reinicializarse* antes de cada llamada.

El contenido de un conjunto de descriptores de archivo se puede manipular utilizando las siguientes macros:

FD_ZERO()
Esta macro borra (elimina todos los descriptores de archivo de) set. Debería emplearse como primer paso en la inicialización de un conjunto de descriptores de archivo.
FD_SET()
Esta macro añade el descriptor de archivo fd a set. Añadir un descriptor de archivo que ya está presente en el conjunto no tiene efecto y no produce un error.
FD_CLR()
Esta macro elimina el descriptor de archivo fd de set. Eliminar un descriptor de archivo que no está presente en el conjunto no tiene efecto y no produce un error.
FD_ISSET()
select() modifica el contenido de los conjuntos de acuerdo con las reglas descritas a continuación. Después de llamar a select(), la macro FD_ISSET() puede utilizarse para comprobar si un descriptor de archivo todavía está presente en un conjunto. FD_ISSET() devuelve un valor distinto de cero si el descriptor de archivo fd está presente en set, y cero si no lo está.

Argumentos

Los argumentos de select() son los siguientes:

readfds
Los descriptores de archivo de este conjunto se monitorizan para ver si están listos para lectura. Un descriptor de archivo está listo para lectura si una operación de lectura no se bloquea; en particular, un descriptor de archivo también está listo en fin de archivo.
Después de que select() haya retornado, readfds se borrará de todos los descriptores de archivo excepto aquellos que estén listos para lectura.
writefds
Los descriptores de archivo de este conjunto se monitorizan para ver si están listos para escritura. Un descriptor de archivo está listo para escritura si una operación de escritura no se bloquea. Sin embargo, incluso si un descriptor de archivo indica ser escribible, una escritura grande puede aún bloquearse.
Después de que select() haya retornado, writefds se borrará de todos los descriptores de archivo excepto aquellos que estén listos para escritura.
exceptfds
Los descriptores de archivo de este conjunto se monitorizan para "condiciones excepcionales". Para ejemplos de algunas condiciones excepcionales, ver la discusión de POLLPRI en poll(2).
Después de que select() haya retornado, exceptfds se borrará de todos los descriptores de archivo excepto aquellos para los que ha ocurrido una condición excepcional.
nfds
Este argumento debe establecerse al descriptor de archivo con el número más alto en cualquiera de los tres conjuntos, más 1. Los descriptores de archivo indicados en cada conjunto se comprueban, hasta este límite (pero ver ERRORES).
timeout
El argumento timeout es una estructura timeval (mostrada abajo) que especifica el intervalo durante el cual select() debe bloquearse esperando a que un descriptor de archivo esté listo. La llamada se bloqueará hasta que ocurra alguna de las siguientes situaciones:
•
un descriptor de archivo esté listo;
•
la llamada sea interrumpida por un manejador de señales; o
•
el tiempo de espera expire.
Tenga en cuenta que el intervalo de timeout se redondeará hasta la granularidad del reloj del sistema, y los retrasos de programación del kernel significan que el intervalo de bloqueo puede excederse en una pequeña cantidad.
Si ambos campos de la estructura timeval son cero, entonces select() retorna inmediatamente. (Esto es útil para sondeo.)
Si timeout se especifica como NULL, select() se bloquea indefinidamente esperando que un descriptor de archivo esté listo.

pselect()

La llamada al sistema pselect() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo esté listo o hasta que se capture una señal.

La operación de select() y pselect() es idéntica, excepto por estas tres diferencias:

•
select() usa un tiempo de espera que es un struct timeval (con segundos y microsegundos), mientras que pselect() usa un struct timespec (con segundos y nanosegundos).
•
select() puede actualizar el argumento timeout para indicar cuánto tiempo quedaba. pselect() no modifica este argumento.
•
select() no tiene argumento sigmask, y se comporta como pselect() llamado con sigmask NULL.

sigmask es un puntero a una máscara de señales (ver sigprocmask(2)); si no es NULL, entonces pselect() primero reemplaza la máscara de señales actual por la o

The reason that pselect() is needed is that if one wants to wait for either a signal or for a file descriptor to become ready, then an atomic test is needed to prevent race conditions. (Suppose the signal handler sets a global flag and returns. Then a test of this global flag followed by a call of select() could hang indefinitely if the signal arrived just after the test but just before the call. By contrast, pselect() allows one to first block signals, handle the signals that have come in, then call pselect() with the desired sigmask, avo

The

timeout

The timeout argument for select() is a structure of the following

type: 


struct timeval {
    time_t      tv_sec;         /* seconds */
    suseconds_t tv_usec;        /* microseconds */
}
;

The corresponding argument for pselect() is a timespec(3)

structure.

On Linux, select() modifies timeout to reflect the amount of time not slept; most other implementations do not do this. (POSIX.1 permits either behavior.) This causes problems both when Linux code which reads timeout is ported to other operating systems, and when code is ported to Linux that reuses a struct timeval for multiple select()s in a loop without reinitializing it. On error, -1 is returned, and errno is set to indicate the error; the file descriptor sets are unmodified, and timeout becomes

NOTE

S

The following header also provides the fd_set type: <sys/time.h>

.

An fd_set is a fixed size buffer. Executing FD_CLR() or FD_SET() with a value of fd that is negative or is equal to or larger than FD_SETSIZE will result in undefined behavior. Moreover, POSIX requires fd to be a valid file

descriptor.

The operation of select() and pselect() is not affected by the O_NONBLOCK

flag.

The self-pipe

trick

On systems that lack pselect(), reliable (and more portable) signal trapping can be achieved using the self-pipe trick. In this technique, a signal handler writes a byte to a pipe whose other end is monitored by select() in the main program. (To avoid possibly blocking when writing to a pipe that may be full or readi

ng from a pipe that may be empty, nonblocking I/O
is used when reading from and writing to the pipe.)

Multithreaded

applications

If a file descriptor being monitored by select() is closed in another thread, the result is unspecified. On some UNIX systems, select() unblocks and returns, with an indication that the file descriptor is ready (a subsequent I/O operation will likely fail with an error, unless another process reopens the file descriptor between the time select() returned and the I/O operation is performed). On Linux (and some other systems), closing the file descriptor in another thread has no effect on select(). In summary, any application that relies on a p

articular behavior in this scen
ario must be considered buggy.

C library/kernel

differences

The Linux kernel allows file descriptor sets of arbitrary size, determining the length of the sets to be checked from the value of nfds. However, in the glibc implementation, the fd_set type is fixed in size. See also

BUGS.

The pselect() interface described in this page is implemented by glibc. The underlying Linux system call is named pselect6(). This system call has somewhat different behavior from the glibc wrapper

function.

The Linux pselect6() system call modifies its timeout argument. However, the glibc wrapper function hides this behavior by using a local variable for the timeout argument that is passed to the system call. Thus, the glibc pselect() function does not modify its timeout argument; this is the behavior required by POSIX.

1-2001.

The final argument of the pselect6() system call is not a sigset_t * pointer, but is instead a structure of the

form: 


struct {
    const kernel_sigset_t *ss;   /* Pointer to signal set */
    size_t ss_len;               /* Size (in bytes) of object
                                    pointed to by 'ss' */
}
;

This allows the system call to obtain both a pointer to the signal set and its size, while allowing for the fact that most architectures support a maximum of 6 arguments to a system call. See sigprocmask(2) for a discussion of the difference be

tween the kernel and libc n
otion of the signal set.

BUG

S

POSIX allows an implementation to define an upper limit, advertised via the constant FD_SETSIZE, o

BUGS

The limit of 1024 for file descriptors in the range of file descriptors that can be specified in a file descriptor set. The Linux kernel imposes no fixed limit, but the glibc implementation makes fd_set a fixed-size type, with FD_SETSIZE defined as 1024, and the FD_*() macros operating according to that limit. To monitor file descriptors greater than 1023, use poll(2) or epoll(7) instead.

The implementation of the fd_set arguments as value-result arguments is a design error that is avoided in poll(2) and epoll(7).

According to POSIX, select() should check all specified file descriptors in the three file descriptor sets, up to the limit nfds-1. However, the current implementation ignores any file descriptor in these sets that is greater than the maximum file descriptor number that the process currently has open. According to POSIX, any such file descriptor that is specified in one of the sets should result in the error EBADF.

Starting with glibc 2.1, glibc provided an emulation of pselect() that was implemented using sigprocmask(2) and select(). This implementation remained vulnerable to the very race condition that pselect() was designed to prevent. Modern versions of glibc use the (race-free) pselect() system call on kernels where it is provided.

On Linux, select() may report a socket file descriptor as "ready for reading", while nevertheless a subsequent read blocks. This could for example happen when data has arrived but upon examination has the wrong checksum and is discarded. There may be other circumstances in which a file descriptor is spuriously reported as ready. Thus it may be safer to use O_NONBLOCK on sockets that should not block.

On Linux, select() also modifies timeout if the call is interrupted by a signal handler (i.e., the EINTR error return). This is not permitted by POSIX.1. The Linux pselect() system call has the same behavior, but the glibc wrapper hides this behavior by internally copying the timeout to a local variable and passing that variable to the system call.

EJEMPLOS

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Watch stdin (fd 0) to see when it has input.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Wait up to five seconds.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Don't rely on the value of tv now! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Data is available now.\n");
        /* FD_ISSET(0, &rfds) will be true.  */
    else
        printf("No data within five seconds.\n");
    exit(EXIT_SUCCESS);
}
