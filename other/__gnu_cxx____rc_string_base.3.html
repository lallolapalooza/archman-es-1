Descripción detallada

template<typename _CharT, typename _Traits, typename _Alloc>

class __gnu_cxx::__rc_string_base< _CharT, _Traits, _Alloc >"Documentación? ¿Qué es eso? Nathan Myers ncm@cantrip.org.

Una cadena se ve así:

                                     [_Rep]
                                     _M_length
[__rc_string_base<char_type>]        _M_capacity
_M_dataplus                          _M_refcount
_M_p ---------------->               array anónimo de char_type

Donde _M_p apunta al primer carácter de la cadena, y se hace un cast a un puntero a _Rep y se resta 1 para obtener un puntero a la cabecera.

Este enfoque tiene la enorme ventaja de que un objeto de cadena requiere solo una asignación. Toda la fealdad se confina dentro de un par de funciones en línea, cada una se compila en una sola instrucción de *suma*: _Rep::_M_refdata(), y __rc_string_base::_M_rep(); y la función de asignación que obtiene un bloque de bytes crudos con suficiente espacio y construye un objeto _Rep al frente.

La razón por la que _M_data apunta al array de caracteres y no al _Rep es para que el depurador pueda ver el contenido de la cadena. (Probablemente deberíamos añadir un miembro no en línea para obtener el _Rep para que el depurador lo use, para que los usuarios puedan verificar la longitud real de la cadena.)

Tenga en cuenta que el objeto _Rep es un POD para que pueda tener un objeto _Rep de *cadena vacía* estático ya *construido* antes de que se hayan ejecutado los constructores estáticos. La codificación del contador de referencias se elige de tal manera que un 0 indica una referencia, por lo que nunca intenta destruir el objeto _Rep de cadena vacía.

Todo excepto el último párrafo se considera bastante convencional para una implementación de cadena C++.
