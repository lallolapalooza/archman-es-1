NOMBRE

__pmLocalPMDA - cambia la tabla de PMDA DSO para contextos PM_CONTEXT_LOCAL

SINOPSIS

#include "pmapi.h"
#include "libpcp.h"

int __pmLocalPMDA(int op,
int domain, const char *name, const char *init);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada al uso interno por parte de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las API de PCP que se garantiza que permanecerán fijas entre versiones, y pueden no funcionar, o proporcionar semánticas diferentes en algún momento futuro.

DESCRIPCIÓN

Los contextos PCP de tipo PM_CONTEXT_LOCAL son utilizados por clientes que desean obtener métricas directamente de uno o más PMDA en el host local sin involucrar a pmcd(1). Un PMDA que se va a utilizar de esta manera debe haber sido compilado como un Objeto Compartido Dinámico (DSO).

Históricamente, la tabla de PMDA disponibles para usar con PM_CONTEXT_LOCAL estaba codificada de la siguiente manera:

  • El (los) PMDA que exporta(n) los datos de rendimiento del sistema operativo y datos sobre la actividad de procesos.
  • El PMDA mmv.
  • El PMDA sample siempre que $PCP_LITE_SAMPLE o $PMDA_LOCAL_SAMPLE estén establecidos en el entorno (utilizado principalmente para control de calidad y pruebas).

La tabla inicial de PMDA disponibles para usar con PM_CONTEXT_LOCAL ahora se genera dinámicamente a partir de todos los PMDA que se han instalado como DSOs en el host local. La única excepción es el PMDA ``pmcd'', que solo opera correctamente en el espacio de direcciones de un proceso pmcd(1) en ejecución y, por lo tanto, no está disponible para una aplicación que utiliza un contexto PM_CONTEXT_LOCAL.

__pmLocalPMDA proporciona una serie de servicios para modificar la tabla de PMDA disponibles para usar con PM_CONTEXT_LOCAL.

El argumento op especifica qué se debe hacer y toma uno de los siguientes valores y acciones:

PM_LOCAL_ADD
Añade una entrada a la tabla para el PMDA con un Dominio de Métricas de Rendimiento (PMD) de domain, la ruta al PMDA DSO se da por path y la rutina de inicialización del PMDA es init.
PM_LOCAL_DEL
Elimina todas las entradas de la tabla donde domain coincide, o path coincide. Establecer los argumentos domain a -1 o path a NULL para forzar la coincidencia en el *otro* argumento. El argumento init se ignora.
PM_LOCAL_CLEAR
Elimina todas las entradas de la tabla. Todos los demás argumentos se ignoran en este caso.

Los argumentos domain, name e init tienen sintaxis y semántica similares a los campos asociados en el archivo de configuración de pmcd(1). La única diferencia es el argumento path, que es utilizado por __pmLocalPMDA para encontrar un DSO de apariencia probable buscando en este orden: $PCP_PMDAS_DIR/path, path, $PCP_PMDAS_DIR/path.dso-suffix y finalmente path.dso-suffix (dso-suffix es el sufijo de nombre de archivo predeterminado específico de la plataforma local para un DSO, p. ej., so para Linux, dylib para macOS, dll para Windows, etc.).

VALOR DE RETORNO

En la mayoría de los casos, __pmLocalPMDA devuelve 0 para indicar éxito. Si op es inválido, el valor de retorno es PM_ERR_CONV; si no se encuentra ninguna entrada de tabla coincidente para una operación PM_LOCAL_DEL, se devuelve PM_ERR_INDOM.

VER TAMBIÉN

pmcd(1), PMAPI(3), pmNewContext(3) y pmSpecLocalPMDA(3).
