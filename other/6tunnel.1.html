6TUNNEL(1) Manual de Comandos Generales 6TUNNEL(1)

NOMBRE

6tunnel - tunelización para aplicaciones que no hablan IPv6

SINOPSIS

6tunnel [ -146dhfv ] [ -u nombre_usuario ] [ -i contraseña ] [ -I contraseña ] [ -l host_local ] [ -L límite ] [ -p archivo_pid ] [ -m archivo_mapa ] puerto_local host_remoto [ puerto_remoto ]

DESCRIPCIÓN

6tunnel te permite usar servicios proporcionados por hosts IPv6 con aplicaciones que solo usan IPv4 y viceversa. Puede enlazarse a cualquiera de tus direcciones IPv4 (por defecto) o IPv6 y reenviar todos los datos a un host IPv4 o IPv6 (por defecto). Por ejemplo:

6tunnel -1 6668 irc6.net 6667

será suficiente para conectarte a un servidor IRC IPv6 con

irc foobar localhost:6668

Si no deseas ejecutar 6tunnel cada vez que quieras mostrar tu dirección IPv6 :c001: o :dead: en IRC, puedes usar el parámetro -i, que hace que 6tunnel solicite la contraseña especificada a tu cliente. Simplemente ejecuta

6tunnel -i dupa.8 31337 irc6.net 6667

y luego escribe

irc foobar localhost:31337:dupa.8

Si tu servidor IRC requiere que envíes una contraseña, especifícala con el parámetro -I; después de una autenticación de proxy exitosa, 6tunnel se la enviará al servidor.

6tunnel también puede usarse como un túnel para todas las demás combinaciones de puntos finales IPv4 e IPv6. Si el host remoto no tiene direcciones IPv6, 6tunnel usará la IPv4. En otros casos, usa el parámetro -4 que hace que la dirección IPv4 sea la preferida. Para túneles de IPv6 a cualquiera, usa -6 que hace que 6tunnel se enlace a una dirección IPv6.

OPCIONES

-1
Salir después de la primera conexión.
-4
Preferir el punto final IPv4 si la máquina tiene ambos tipos de dirección.
-6
Escuchar en dirección IPv6 (IPv4 es por defecto).
-d
No separar (detach).
-f
Forzar la tunelización incluso si el host remoto no se puede resolver en el momento de la ejecución.
-h
Mostrar un volcado hexadecimal de cada paquete recibido o enviado.
-u nombre_usuario
Cambiar UID y GID después de bind().
-i contraseña
Actuar como un proxy IRC y requerir que el usuario se autentique.
-I contraseña
Si estás usando 6tunnel como proxy IRC y el servidor IRC requiere que envíes una contraseña, colócala aquí.
-l host_local
Escuchar en la dirección especificada (IPv4, o IPv6 si se usa -6).
-L límite
Limitar conexiones simultáneas.
-p archivo_pid
Escribir el PID en el archivo especificado.
-s host_origen
Conectarse al host remoto usando la dirección de origen especificada.
-m archivo_mapa
Se enlaza a direcciones IPv6 especificadas basándose en la dirección IPv4 de origen. El archivo contiene un mapeo por línea con la dirección IPv4 de origen y la dirección IPv6 correspondiente. Solo se permite la conexión a los hosts listados. Si deseas permitir cualquier host, agrega un mapeo para la dirección default o 0.0.0.0. Ejemplo:
192.168.0.2 3ffe:8010:18::1000:2
192.168.0.3 3ffe:8010:18::1000:3
-v
Ser verboso y no separar (detach).

NOTAS

La opción -H para deshabilitar todas las sugerencias del resolutor ha sido eliminada, ya que la combinación adecuada de -4 y -6 resultará en cualquier combinación de fuentes y destinos IPv4 e IPv6.

SEÑALES

Enviar SIGHUP fuerza la recarga del archivo de mapeo.

AGRADECIMIENTOS

Tripulación de #ipv6, Lam.

ERRORES

Página del manual terrible. El volcado hexadecimal no incluye la autenticación del proxy IRC. El proxy IRC requiere que tu cliente envíe la contraseña primero (no te preocupes, ircii, EPIC, BitchX, mIRC y muchos más funcionarán). No hay registro excepto la salida de depuración.
