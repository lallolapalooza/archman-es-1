NOMBRE

Net::SNMP - Interfaz orientada a objetos a SNMP

SINOPSIS

El módulo Net::SNMP implementa una interfaz orientada a objetos al Protocolo Simple de Gestión de Red. Las aplicaciones Perl pueden usar el módulo para recuperar o actualizar información en un host remoto usando el protocolo SNMP. El módulo soporta SNMP versión-1, SNMP versión-2c (SNMPv2 basado en comunidad) y SNMP versión-3. El módulo Net::SNMP asume que el usuario tiene una comprensión básica del Protocolo Simple de Gestión de Red y conceptos relacionados de gestión de red.

DESCRIPCIÓN

El módulo Net::SNMP abstrae los intrincados detalles del Protocolo Simple de Gestión de Red proporcionando una interfaz de programación de alto nivel al protocolo. Cada objeto Net::SNMP proporciona un mapeo uno a uno entre un objeto Perl y un agente o gestor SNMP remoto. Una vez que se crea un objeto, se puede utilizar para realizar las acciones básicas de intercambio de protocolo definidas por SNMP.

Se puede crear un objeto Net::SNMP de forma que tenga propiedades "bloqueantes" o "no bloqueantes". Por defecto, los métodos utilizados para enviar mensajes SNMP no regresan hasta que el intercambio de protocolo se completa con éxito o expira un período de tiempo de espera. Este comportamiento otorga al objeto una propiedad "bloqueante" porque el flujo del código se detiene hasta que el método retorna.

El argumento con nombre opcional -nonblocking puede pasarse al constructor del objeto con un valor verdadero para otorgar al objeto comportamiento "no bloqueante". Un método invocado por un objeto no bloqueante pone en cola el mensaje SNMP y retorna inmediatamente, permitiendo que el flujo del código continúe. Los mensajes SNMP en cola no se envían hasta que se entra en un bucle de eventos llamando al método snmp_dispatcher(). El bucle de eventos sale cuando todos los mensajes han sido eliminados de la cola ya sea recibiendo una respuesta o excediendo el número de reintentos en la Capa de Transporte.

Objetos Bloqueantes

El comportamiento por defecto de los métodos asociados con un objeto Net::SNMP es bloquear el flujo del código hasta que el método se complete. Para métodos que inician un intercambio de protocolo SNMP que requiere una respuesta, se retorna una referencia a hash que contiene los resultados de la consulta. El valor indefinido es retornado por todos los métodos cuando ha ocurrido un fallo. El método error() puede usarse para determinar la causa del fallo.

La referencia a hash retornada por un intercambio de protocolo SNMP apunta a un hash construido a partir de la VarBindList contenida en el mensaje de respuesta SNMP. El hash se crea utilizando los pares ObjectName y ObjectSyntax en la VarBindList. Las claves del hash consisten en los IDENTIFICADORES DE OBJETO en notación de puntos correspondiente a cada ObjectName en la VarBindList. El valor de cada entrada del hash se establece igual al valor del ObjectSyntax correspondiente. Esta referencia a hash también se puede recuperar usando el método var_bind_list().

Objetos No Bloqueantes

Cuando un objeto Net::SNMP se crea con comportamiento no bloqueante, la invocación de un método asociado con el objeto retorna inmediatamente, permitiendo que el flujo del código continúe. Cuando se invoca un método que iniciaría un intercambio de protocolo SNMP que requiere una respuesta, se retorna un valor verdadero (es decir, 0x1) inmediatamente o el valor indefinido si ha ocurrido un fallo. El método error() puede usarse para determinar la causa del fallo.

El contenido de la VarBindList contenida en el mensaje de respuesta SNMP se puede recuperar llamando al método var_bind_list() usando la referencia al objeto pasada como primer argumento a la función de devolución de llamada. El valor retornado por el método var_bind_list() es una referencia a hash creada usando los pares ObjectName y ObjectSyntax en la VarBindList. Las claves del hash consisten en los IDENTIFICADORES DE OBJETO en notación de puntos correspondiente a cada ObjectName en la VarBindList. El valor de cada entrada del hash se establece igual al valor del ObjectSyntax correspondiente. El valor indefinido se retorna si ha ocurrido un fallo y el método error() puede usarse para determinar la razón.

MÉTODOS

Cuando los métodos esperan argumentos con nombre, se admiten dos estilos diferentes. Todos los ejemplos en esta documentación utilizan el estilo de opción con guion:

$object->method(-argument => $value);

Sin embargo, el estilo IO:: también está permitido:

$object->method(Argument => $value);
Argumentos de Objetos No Bloqueantes
Cuando un objeto Net::SNMP ha sido creado con una propiedad "no bloqueante", la mayoría de los métodos que generan un mensaje SNMP toman argumentos adicionales para soportar esta propiedad.
Callback (Función de devolución de llamada)
La mayoría de los métodos asociados con un objeto no bloqueante tienen un argumento con nombre opcional llamado -callback. El argumento -callback espera una referencia a una subrutina o a un array cuyo primer elemento debe ser una referencia a una subrutina. La subrutina definida por la opción -callback se ejecuta cuando se recibe una respuesta a un mensaje SNMP, ha ocurrido una condición de error, o se ha excedido el número de reintentos para el mensaje.

Cuando el argumento -callback solo contiene una referencia de subrutina, la subrutina se evalúa pasando una referencia al objeto Net::SNMP original como único parámetro. Si el argumento -callback fue definido como una referencia de array, todos los elementos del array se pasan a la subrutina después de la referencia al objeto Net::SNMP. El primer elemento, que debe ser una referencia a una subrutina, se elimina antes de que los argumentos restantes se pasen a esa subrutina.

Una vez que se invoca un método con el argumento -callback, este argumento permanece con el objeto y es utilizado por cualquier llamada posterior a métodos que usen la opción -callback si el argumento está ausente. El valor indefinido puede pasarse al argumento -callback para eliminar la función de devolución de llamada.

NOTA: La subrutina que se pasa con el argumento con nombre -callback no debe causar bloqueo por sí misma. Esto hará que todas las acciones en el bucle de eventos se detengan, frustrando la propiedad no bloqueante del módulo Net::SNMP.

Retraso
También se puede pasar un argumento opcional -delay a los objetos no bloqueantes. El argumento -delay instruye al objeto a esperar el número de segundos pasado al argumento antes de ejecutar el intercambio de protocolo SNMP. El período de retraso comienza cuando se entra en el bucle de eventos. El parámetro -delay se aplica a todos los métodos asociados con el objeto una vez especificado. El valor de retraso debe establecerse de nuevo a 0 segundos para deshabilitar el parámetro de retraso.
Argumentos SNMPv3
Un contexto SNMP es una colección de información de gestión accesible por una entidad SNMP. Un elemento de información de gestión puede existir en más de un contexto y una entidad SNMP potencialmente tiene acceso a muchos contextos. La combinación de un contextEngineID y un contextName identifica de forma única un contexto dentro de un dominio administrativo. En un mensaje SNMPv3, el contextEngineID y contextName se incluyen como parte del scopedPDU. Todos los métodos que generan un mensaje SNMP toman opcionalmente un argumento -contextengineid y -contextname para configurar estos campos.
ID de Motor de Contexto
El argumento -contextengineid espera una cadena hexadecimal que representa el contextEngineID deseado. La cadena debe tener entre 10 y 64 caracteres (5 a 32 octetos) de longitud y puede ir precedida opcionalmente por un "0x". Una vez especificado el -contextengineid, permanece con el objeto hasta que se cambia de nuevo o se restablece a su valor predeterminado al pasarlo como valor indefinido. Por defecto, el contextEngineID se establece para que coincida con el authoritativeEngineID del motor SNMP autoritativo.
Nombre de Contexto
El contextName es
pasado como una cadena que debe tener entre 0 y 32 octetos de longitud usando el argumento -contextname. El contextName permanece con el objeto hasta que se cambia. El contextName por defecto es una cadena vacía que representa el contexto "por defecto".

session() - crear un nuevo objeto Net::SNMP

$session, $error = Net::SNMP->session(
                        [-hostname      => $hostname,]
                        [-port          => $port,]
                        [-localaddr     => $localaddr,]
                        [-localport     => $localport,]
                        [-nonblocking   => $boolean,]
                        [-version       => $version,]
                        [-domain        => $domain,]
                        [-timeout       => $segundos,]
                        [-retries       => $cuenta,]
                        [-maxmsgsize    => $octetos,]
                        [-translate     => $translate,]
                        [-debug         => $mascara_de_bits,]
                        [-community     => $community,]   # v1/v2c
                        [-username      => $username,]    # v3
                        [-authkey       => $authkey,]     # v3
                        [-authpassword  => $authpasswd,]  # v3
                        [-authprotocol  => $authproto,]   # v3
                        [-privkey       => $privkey,]     # v3
                        [-privpassword  => $privpasswd,]  # v3
                        [-privprotocol  => $privproto,]   # v3
                     );

Este es el constructor para objetos Net::SNMP. En contexto escalar, se devuelve una referencia a un nuevo objeto Net::SNMP si la creación del objeto es exitosa. En contexto de lista, se devuelve una referencia a un nuevo objeto Net::SNMP y una cadena de error vacía. Si ocurre un fallo, la referencia del objeto se devuelve como valor indefinido. La cadena de error puede usarse para determinar la causa del error.

La mayoría de los argumentos nombrados pasados al constructor definen atributos básicos para el objeto y no son modificables una vez que el objeto ha sido creado. Los argumentos -timeout, -retries, -maxmsgsize, -translate y -debug son modificables usando un método accesorio. Consulte sus definiciones de método correspondientes para una descripción completa de su uso, valores por defecto y rangos válidos.

Argumentos del Dominio de Transporte
El módulo Net::SNMP usa UDP/IPv4 como el Dominio de Transporte por defecto para intercambiar mensajes SNMP entre los dispositivos locales y remotos. El módulo también soporta UDP/IPv6, TCP/IPv4 y TCP/IPv6 como Dominios de Transporte alternativos. El argumento -domain puede usarse para cambiar el Dominio de Transporte estableciendo el valor a una de las siguientes cadenas: 'udp6', 'udp/ipv6'; 'tcp', 'tcp4', 'tcp/ipv4'; 'tcp6' o 'tcp/ipv6'. El argumento -domain también acepta las cadenas 'udp', 'udp4' o 'udp/ipv4' que corresponden al Dominio de Transporte por defecto de UDP/IPv4.

La dirección de transporte del dispositivo SNMP de destino puede ser especificada usando el argumento -hostname. Este argumento es opcional y por defecto es "localhost". El número de puerto de destino puede ser especificado como parte de la dirección de transporte o usando el argumento -port. Se puede especificar un número de puerto numérico o un nombre de servicio textual. Un número de puerto numérico entre paréntesis puede seguir opcionalmente al nombre del servicio. Este número de puerto se usará si el nombre del servicio no puede ser resuelto. Si el número de puerto de destino no se especifica, se usa el número de puerto bien conocido de SNMP 161.

Por defecto, la dirección y el número de puerto de transporte de origen son asignados dinámicamente por el dispositivo local en el que se está utilizando el módulo Net::SNMP. Esta asignación dinámica puede ser anulada usando los argumentos -localaddr y -localport. Estos argumentos aceptan los mismos valores que los argumentos -hostname y -port respectivamente. La dirección resuelta debe corresponder a una dirección válida de una interfaz en el dispositivo local.

Al usar un Dominio de Transporte IPv4, la dirección de transporte puede ser especificada como un nombre de host de red IP o una dirección IPv4 en notación decimal estándar. La información del puerto puede ser añadida opcionalmente al nombre de host o dirección delimitada por dos puntos. Los formatos de dirección de transporte IPv4 aceptados son "address", "address:port", "hostname" y "hostname:port".

Al usar un Dominio de Transporte IPv6, la dirección de transporte puede ser especificada como un nombre de host IP (que se resolverá como un registro quad-A de DNS) o una dirección IPv6 en formato de presentación. La información del puerto puede ser incluida opcionalmente después de dos puntos después del nombre de host o dirección. Al incluir esta información después de una dirección IPv6, la dirección debe estar encerrada entre corchetes. El índice de zona de ámbito (descrito en RFC 4007) puede ser especificado después de la dirección como un valor decimal delimitado por un signo de porcentaje. Los formatos de dirección de transporte aceptados para IPv6 son "address", "address%zone", "[address]:port", "[address%zone]:port", "hostname" y "hostname:port".

Argumentos del Modelo de Seguridad
El argumento -version controla qué otros argumentos son esperados o requeridos por el constructor session(). El módulo Net::SNMP soporta SNMPv1, SNMPv2c y SNMPv3. El módulo por defecto es SNMPv1 si no se especifica ningún argumento -version. El argumento -version espera un dígito (es decir, '1', '2' o '3') o una cadena que especifica la versión (es decir, 'snmpv1', 'snmpv2c' o 'snmpv3') para definir la versión SNMP.

El Modelo de Seguridad utilizado por el objeto Net::SNMP se basa en la versión SNMP asociada con el objeto. Si la versión SNMP es SNMPv1 o SNMPv2c, se utilizará un Modelo de Seguridad basado en Comunidad, mientras que se utilizará el Modelo de Seguridad Basado en Usuario (USM) si la versión es SNMPv3.

Argumento del Modelo de Seguridad basado en Comunidad
Si el Modelo de Seguridad está basado en Comunidad, el único argumento disponible es el argumento -community. Este argumento espera una cadena que se usará como el nombre de comunidad SNMP. Por defecto, el nombre de comunidad se establece en 'public' si el argumento no está presente.
Argumentos del Modelo de Seguridad Basado en Usuario
El Modelo de Seguridad Basado en Usuario (USM) utilizado por SNMPv3 requiere que se especifique un securityName usando el argumento -username. La creación de un objeto Net::SNMP con la versión establecida a SNMPv3 fallará si el argumento -username no está presente. El argumento -username espera una cadena de 1 a 32 octetos de longitud.

Diferentes niveles de seguridad son permitidos por el Modelo de Seguridad Basado en Usuario que abordan preocupaciones de autenticación y privacidad. Un objeto Net::SNMP SNMPv3 derivará el nivel de seguridad (securityLevel) basándose en cuáles de los siguientes argumentos se especifican.

Por defecto se asume un securityLevel de 'noAuthNoPriv'. Si se especifican los argumentos -authkey o -authpassword, el securityLevel se convierte en 'authNoPriv'. El argumento -authpassword espera una cadena que tenga al menos 1 octeto de longitud. Opcionalmente, se puede usar el argumento -authkey para que no se tenga que especificar una contraseña en texto plano en un script. El argumento -authkey espera una cadena hexadecimal producida al localizar la contraseña con el authoritativeEngineID para el dispositivo de destino específico. La utilidad "snmpkey" incluida con la distribución puede usarse para crear la cadena hexadecimal (ver snmpkey).

Se definen dos algoritmos de hash diferentes por SNMPv3 que pueden ser utilizados por el Modelo de Seguridad para la autenticación. Estos algoritmos son HMAC-MD5-96 "MD5" (RFC 1321) y HMAC-SHA-96 "SHA-1" (NIST FIPS PUB 180-1). El algoritmo por defecto utilizado por el módulo es HMAC-MD5-96. Este comportamiento puede ser cambiado usando el argumento -authprotocol. Este argumento espera que se pase la cadena 'md5' o 'sha' para modificar el algoritmo de hash.

Al especificar los argumentos -privkey o -privpassword, el securityLevel asociado con el objeto se convierte en 'authPriv'. De acuerdo con SNMPv3, la privacidad requiere el uso de autenticación. Por lo tanto, si cualquiera de estos dos argumentos está presente y los argumentos -authkey o -authpassword faltan, la creación del objeto falla. Los argumentos -privkey y -privpassword esperan la misma entrada que los argumentos -authkey y -authpassword respectivamente.

El Modelo de Seguridad Basado en Usuario descrito en RFC 3414 define un único protocolo de cifrado a utilizar para la privacidad. Este protocolo, CBC-DES "DES" (NIST FIPS PUB 46-1), se usa por defecto o si se pasa la cadena 'des' al argumento -privprotocol. El módulo también soporta RFC 3826 que describe el uso de CFB128-AES-128 "AES" (NIST FIPS PUB 197) en el USM. El protocolo de cifrado AES puede ser seleccionado pasando 'aes' o 'aes128' al argumento -privprotocol. Al trabajar con el Extended Security Options Consortium http://www.snmp.com/protocol/eso.shtml, el módulo también soporta CBC-3DES-EDE "Triple-DES" (NIST FIPS 46-3) en el Modelo de Seguridad Basado en Usuario. Esto está definido en el borrador http://www.snmp.com/eso/draft-reeder-snmpv3-usm-3desede-00.txt. El protocolo de cifrado Triple-DES puede ser seleccionado usando el argumento -privprotocol con la cadena '3des' o '3desede'.

close() - borrar el Dominio de Transporte asociado con el objeto

$session->close();

Este método borra el Dominio de Transporte y cualquier error asociado con el objeto. Una vez cerrado, el objeto Net::SNMP ya no puede ser utilizado para enviar o recibir mensajes SNMP.

snmp_dispatcher() - entrar en el bucle de eventos del objeto no bloqueante

$session->snmp_dispatcher();

Este método entra en el bucle de eventos asociado con los objetos Net::SNMP no bloqueantes. El método sale cuando todos los mensajes SNMP en cola han recibido una respuesta o han caducado en la Capa de Transporte. Este método

d es también exportada como la función independiente snmp_dispatcher() por defecto (ver "EXPORTS").

get_request() - envía una solicitud SNMP get-request al agente remoto

$result = $session->get_request(
                       [-callback        => sub {},]     # no bloqueante
                       [-delay           => $segundos,]   # no bloqueante
                       [-contextengineid => $engine_id,] # v3
                       [-contextname     => $nombre,]      # v3
                       -varbindlist      => \@oids,
                    );

Este método realiza una consulta SNMP get-request para recopilar datos del agente remoto en el host asociado con el objeto Net::SNMP. El mensaje se construye utilizando la lista de IDENTIFICADORES DE OBJETO en notación decimal punteada pasada al método como una referencia de arreglo usando el argumento -varbindlist. Cada IDENTIFICADOR DE OBJETO se coloca en una única PDU SNMP GetRequest en el mismo orden en que se encontraba en la lista original.

Se devuelve una referencia a un hash en modo bloqueante que contiene el contenido de la VarBindList. En modo no bloqueante, se devuelve un valor verdadero cuando no ha ocurrido ningún error. En cualquier modo, se devuelve el valor indefinido cuando ha ocurrido un error. El método error() puede usarse para determinar la causa de la falla.

set_request() - envía una solicitud SNMP set-request al agente remoto

$result = $session->set_request(
                       [-callback        => sub {},]     # no bloqueante

Este método se utiliza para modificar datos en el agente remoto que está asociado con el objeto Net::SNMP utilizando un set-request SNMP. El tipo de objeto es un octeto correspondiente al tipo ASN.1 del valor que se va a establecer. En cualquier modo, se devuelve el valor indefinido cuando ha ocurrido un error. El método error() puede usarse para determinar la causa de la falla.

trap() - envía una trampa SNMP al gestor remoto

$result = $session->trap(
                       [-delay           => $segundos,]   # no bloqueante
                       [-enterprise      => $oid,]
                       [-agentaddr       => $direccion_ip,]
                       [-generictrap     => $generico,]
                       [-specifictrap    => $especifico,]
                       [-timestamp       => $ticks_tiempo,]
                       -varbindlist      => \@oid_valor,
                    );

Este método envía una trampa SNMP al gestor remoto asociado con el objeto Net::SNMP. Todos los argumentos son opcionales y se les asignarán los siguientes valores por defecto en ausencia de un argumento con nombre correspondiente:

  • El valor por defecto para la trampa -enterprise es "1.3.6.1.4.1", que corresponde a "iso.org.dod.internet.private.enterprises". Se espera que el valor enterprise sea un IDENTIFICADOR DE OBJETO en notación decimal punteada.
  • Cuando el Dominio de Transporte es UDP/IPv4 o TCP/IPv4, el valor por defecto para la trampa -agentaddr es la dirección IP asociada con la interfaz en la que se transmitirá la trampa. Para otros Dominios de Transporte, el -agentaddr se establece por defecto a "0.0.0.0". Cuando se especifica, se espera que la agente-addr sea una IpAddress en notación decimal punteada.
  • El valor por defecto para el tipo -generictrap es 6, que corresponde a "enterpriseSpecific". Los tipos de trampa genéricos se definen y pueden exportarse bajo petición (ver "EXPORTS").
  • El valor por defecto para el tipo -specifictrap es 0. No hay valores predefinidos disponibles para los tipos de trampa específicos.
  • El valor por defecto para la trampa -timestamp es el "uptime" del script. El "uptime" del script es el número de centésimas de segundo que han transcurrido desde que el script comenzó a ejecutarse. Se espera que la marca de tiempo sea un número TimeTicks en centésimas de segundo.
  • El valor por defecto para -varbindlist es una referencia a un arreglo vacío. Se espera que las variable-bindings estén en formato de arreglo consistente en grupos de un IDENTIFICADOR DE OBJETO, un tipo de objeto y el valor real del objeto. Esto es idéntico a la lista esperada por el método set_request(). Los IDENTIFICADORES DE OBJETO en cada trío deben estar en notación decimal punteada. El tipo de objeto es un octeto correspondiente al tipo ASN.1 para el valor. Cada uno de los tipos soportados ha sido definido y se exporta por defecto (ver "EXPORTS").

Se devuelve un valor verdadero cuando el método es exitoso. Se devuelve el valor indefinido cuando ha ocurrido un fallo. El método error() puede usarse para determinar la causa del fallo. Dado que no hay acuses de recibo para las PDUs de Trampa, no hay forma de determinar si el host remoto realmente recibió la trampa.

NOTA: Cuando el objeto está en modo no bloqueante, la trampa no se envía hasta que se ingresa al bucle de eventos y nunca se ejecuta ningún callback.

NOTA: Este método solo puede usarse cuando la versión del objeto está configurada a SNMPv1.

get_bulk_request() - envía una solicitud SNMP get-bulk-request al agente remoto

$result = $session->get_bulk_request(
                       [-callback        => sub {},]     # no bloqueante
                       [-delay           => $segundos,]   # no bloqueante
                       [-contextengineid => $engine_id,] # v3
                       [-contextname     => $nombre,]      # v3
                       [-nonrepeaters    => $no_reps,]
                       [-maxrepetitions  => $max_reps,]
                       -varbindlist      => \@oids,
                    );

Este método realiza una consulta SNMP get-bulk-request para recopilar datos del agente remoto en el host asociado con el objeto Net::SNMP. Todos los argumentos son opcionales excepto -varbindlist y se les asignarán los siguientes valores por defecto en ausencia de un argumento con nombre correspondiente:

  • El valor por defecto para la solicitud get-bulk-request -nonrepeaters es 0. El valor non-repeaters especifica el número de variables en la lista de variable-bindings para las cuales se debe devolver un único sucesor.
  • El valor por defecto para la solicitud get-bulk-request -maxrepetitions es 0. El valor max-repetitions especifica el número de sucesores que se deben devolver para las variables restantes en la lista de variable-bindings.
  • El argumento -varbindlist espera una referencia de arreglo que consta de una lista de IDENTIFICADORES DE OBJETO en notación decimal punteada. Cada IDENTIFICADOR DE OBJETO se coloca en una única PDU SNMP GetBulkRequest en el mismo orden en que se encontraba en la lista original.

Se devuelve una referencia a un hash en modo bloqueante que contiene el contenido de la VarBindList. En modo no bloqueante, se devuelve un valor verdadero cuando no ha ocurrido ningún error. En cualquier modo, se devuelve el valor indefinido cuando ha ocurrido un error. El método error() puede usarse para determinar la causa de la falla.

NOTA: Este método solo puede usarse cuando la versión del objeto está configurada a SNMPv2c o SNMPv3.

get_table() - recuperar una tabla de la agente remoto

$result = $session->get_table(
                       [-callback        => sub {},]     # no bloqueante
                       [-delay           => $seconds,]   # no bloqueante
                       [-contextengineid => $engine_id,] # v3
                       [-contextname     => $name,]      # v3
                       -baseoid          => $oid,
                       [-maxrepetitions  => $max_reps,]  # v2c/v3
                    );

Este método realiza consultas SNMP get-next-request o get-bulk-request (cuando se usa SNMPv2c o SNMPv3) para recolectar datos del agente remoto asociado al objeto Net::SNMP. El primer mensaje enviado se construye utilizando el IDENTIFICADOR DE OBJETO en notación punto-dos pasados al método por el argumento -baseoid. Las consultas SNMP repetidas se emiten hasta que el IDENTIFICADOR DE OBJETO en la respuesta no sea más hijo que el IDENTIFICADOR DE OBJETO base.

El argumento -maxrepetitions puede usarse para especificar el valor máximo de repetición que se pasa a get-bulk-requests cuando se use SNMPv2c o SNMPv3. Si este argumento no está presente, se calcula un valor basado en el tamaño máximo del mensaje para el objeto Net::SNMP. Si el valor se establece en 1 o menos, se usan get-next-requests en lugar de get-bulk-requests.

En modo bloqueante, se devuelve una referencia a un hash que contiene los contents del VarBindList. En modo no bloqueante, se devuelve un valor verdadero cuando no hay error. En cualquiera de los modos, se devuelve un valor undefined cuando hay error. El método error() puede usarse para determinar la causa del error.

ADVERTENCIA: Los resultados de este método pueden volverse muy grandes si el IDENTIFICADOR DE OBJETO base está cercano al raíz de la arbol MIB de SNMP.

get_entries() - recuperar entradas de tabla de la agente remoto

$result = $session->get_entries(
                       [-callback        => sub {},]     # no bloqueante
                       [-delay           => $seconds,]   # no bloqueante
                       [-contextengineid => $engine_id,] # v3
                       [-contextname     => $name,]      # v3
                       -columns          => \@columns,
                       [-startindex      => $start,]
                       [-endindex        => $end,]
                       [-maxrepetitions  => $max_reps,]  # v2c/v3
                    );

Este método realiza consultas SNMP get-next-request o get-bulk-request (cuando se use SNMPv2c o SNMPv3) para recolectar datos del agente remoto asociado al objeto Net::SNMP. Cada mensaje especifica datos para cada IDENTIFICADOR DE OBJETO especificado en el array -columns. Los IDENTIFICADORES DE OBJETO deben corresponder a entradas de columna en una fila conceptual de una tabla. Pueden ser columnas en diferentes tablas, siempre que cada tabla esté indexada de manera similar. Los argumentos opcionales -startindex y -endindex pueden especificarse para limitar la consulta a filas específicas en las tablas.

El -startindex puede especificarse como un valor decimal único o en notación punto-dos si el índice asociado con la entrada requiere. Si el -startindex se especifica, se incluirá como parte de los resultados de la consulta. Si no se especifica -startindex, el primer mensaje de consulta se enviará sin índice. Para asegurar que el -startindex se incluya, el último sub-identificador en el índice se decrementa en 1. Si el último sub-identificador tiene un valor de cero, se remueve del índice.

El argumento opcional -endindex puede especificarse como un valor decimal único o en notación punto-dos. Si el -endindex se especifica, se incluirá como parte de los resultados de la consulta. Si no se especifica -endindex, se emiten consultas SNMP repetidas hasta que la respuesta no devuelva entradas que coincidan con cualquier de las columnas especificadas en el array -columns.

El -maxrepetitions puede usarse para especificar el valor máximo de repetición que se pasa a get-bulk-requests cuando se use SNMPv2c o SNMPv3. Si este argumento no está presente, se calcula un valor basado en el tamaño máximo del mensaje del objeto y el número de columnas especificado en el array -columns. Si el valor se establece en 1 o menos, se usarán get-next-requests en lugar de get-bulk-requests.

En modo bloqueante, se devuelve una referencia a un hash que contiene los contents del VarBindList. En modo no bloqueante, se devuelve un valor verdadero cuando no hay error. En cualquiera de los modos, se devuelve un valor undefined cuando hay error. El método error() puede usarse para determinar la causa del error.

Si se especifica un parámetro, el maxMsgSize del objeto se establece en el valor proporcionado si está en el rango de 484 a 65535 octetos. El valor undefined se devuelve en caso de error y el método error() puede ser usado para determinar la causa.

translate() - habilitar o deshabilitar el modo de traducción para el objeto

$mask = $session->translate([ 
                     $mode |
                     [ # Referencia de ARRAY anónimo de Perl 
                        ['-all'            => $mode0,]
                        ['-octetstring'    => $mode1,]
                        ['-null'           => $mode2,]
                        ['-timeticks'      => $mode3,]
                        ['-opaque'         => $mode4,]
                        ['-nosuchobject'   => $mode5,] 
                        ['-nosuchinstance' => $mode6,]
                        ['-endofmibview'   => $mode7,]
                        ['-unsigned'       => $mode8]  
                     ]
                  ]);

Cuando el objeto decodifica el PDU GetResponse devuelto en respuesta a un mensaje SNMP, ciertos valores se traducen a una forma más "legible". Por defecto, ocurren las siguientes traducciones:

  • Los OCTET STRINGs y OPAQUE que contienen cualquier octeto que no sea parte del conjunto de caracteres definido como DisplayString en RFC 2679 se convierten en una representación hexadecimal precedida por "0x". Los códigos de control NUL(0x00), BEL(0x07), BS(0x08), HT(0x09), LF(0x0A), VT(0x0b), FF(0x0C), y CR(0x0D) son parte del conjunto de caracteres y no generarán traducción. La secuencia "CR x" para cualquier x que no sea LF o NUL es ilegal y generará traducción.
  • Los valores de TimeTicks se convierten a formato de tiempo.
  • Los valores NULL devuelven la cadena "NULL" en lugar de una cadena vacía.
  • Los valores noSuchObject devuelven la cadena "noSuchObject" en lugar de una cadena vacía.
  • Los valores noSuchInstance devuelven la cadena "noSuchInstance" en lugar de una cadena vacía.
  • Los valores endOfMibView devuelven la cadena "endOfMibView" en lugar de una cadena vacía.
  • Los valores Counter64, Counter, Gauge y TimeTick que han sido incorrectamente codificados como valores negativos se devuelven como valores sin signo.

El método translate() puede ser llamado con dos tipos diferentes de argumentos.

Si el argumento pasado es cualquier tipo de variable Perl excepto una referencia a un array, el modo de traducción de todos los tipos ASN.1 se establece en habilitado o deshabilitado según el valor del parámetro pasado. Cualquier valor que Perl considere verdadero activa el modo de traducción para todos los tipos, mientras que un valor falso deshabilita la traducción para todos los tipos.

Se puede pasar una referencia a un array al método translate() para definir el modo de traducción por tipo ASN.1. La referencia esperada contiene una lista de pares de argumentos nombrados para cada tipo ASN.1 que se va a modificar. Los argumentos de la lista se aplican en el orden en que se pasan a través del array. Los argumentos al final de la lista anulan a los pasados anteriormente en la lista. El argumento "-all" puede ser usado para especificar que el modo aplica a todos los tipos ASN.1. Solo deben incluirse en la lista los argumentos para los tipos ASN.1 a modificar.

El método translate() devuelve una máscara de bits que indica los tipos ASN.1 a traducir. Las definiciones de los bits a tipos ASN.1 pueden exportarse usando la etiqueta :translate (ver "EXPORTS"). El valor undefined se devuelve en caso de error y el método error() puede ser usado para determinar la causa.

debug() - establecer o obtener el modo de depuración del módulo

$mask = $session->debug([$mask]);

Este método se utiliza para habilitar o deshabilitar la depuración del módulo Net::SNMP. La depuración puede habilitarse a nivel de componente mediante una máscara de bits pasada al método debug(). La máscara de bits se descompone de la siguiente manera:

  • 0x02 - Codificación y decodificación de mensajes o PDU
  • 0x04 - Capa de transporte
  • 0x08 - Dispatcher
  • 0x10 - Procesamiento de mensajes
  • 0x20 - Seguridad

Los símbolos que representan estos valores de máscara de bits son definidos por el módulo y pueden exportarse usando la etiqueta :debug (ver "EXPORTS"). Si se pasa un valor no numérico al método debug(), se evalúa en contexto booleano. La depuración de todos los componentes se habilita o deshabilita según el valor resultante de la evaluación.

El valor actual de la máscara de depuración es devuelto por el método. La depuración también puede habilitarse usando la función independiente snmp_debug(). Esta función puede exportarse bajo petición (ver "EXPORTS").

SUBROUTINAS

oid_base_match() - determinar si un OID tiene un OID base especificado

$value = oid_base_match($base_oid, $oid);

Esta función toma dos OBJECT IDENTIFIERs en notación de punto y devuelve un valor verdadero (es decir, 0x1) si el segundo OBJECT IDENTIFIER es igual al primero o es un hijo en el árbol MIB definido en la Base de Información de Gestión SNMP (MIB). Esta función puede usarse junto con los métodos "get-next-request()" o "get-bulk-request()" para determinar cuándo un OID en el PDU GetResponse ya no pertenece al árbol MIB deseado.

$cmp = oid_lex_cmp($oid1, $oid2);

Esta función toma dos OBJECT IDENTIFIERs en notación de punto y devuelve 1, 0 o -1 si $oid1 es respectivamente mayor, igual o menor que $oid2 lexicográficamente.

@sorted_oids = oid_lex_sort(@oids);

Esta función toma una lista de OBJECT IDENTIFIERs en notación de punto y devuelve la lista ordenada en orden lexicográfico.

snmp_type_ntop() - convertir un tipo ASN.1 a formato de presentación

$text = snmp_type_ntop($type);

Esta función toma un valor octal del tipo ASN.1 y devuelve una cadena de texto adecuada para su presentación. Algunos tipos de definiciones ASN.1 se mapean a valores octales iguales cuando se codifican. Esta metodología no puede distinguir entre estos múltiples mapeos y se devuelve el nombre básico del tipo más simple.

ticks_to_time() - convertir TimeTicks a formato de tiempo

$time = ticks_to_time($timeticks);

Esta función toma un valor de TimeTicks y devuelve una cadena que representa el tiempo definido por el valor. El valor de TimeTicks esperado es un valor entero no negativo que representa el tiempo en centésimas de segundo desde alguna época. La cadena devuelta mostrará el tiempo en formato de días, horas y segundos según el valor del argumento TimeTicks.

EJEMPLOS

1. Bloqueo de solicitud-get SNMPv1 para sysUpTime

Este ejemplo obtiene el sysUpTime de un host remoto.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP;
my $OID_sysUpTime = '1.3.6.1.2.1.1.3.0';
my ($session, $error) = Net::SNMP->session(
   -hostname  => shift || 'localhost',
   -community => shift || 'public',
);
if (!defined $session) {
   printf "ERROR: %s.\n", $error;
   exit 1;
}
my $result = $session->get_request(-varbindlist => [ $OID_sysUpTime ],);
if (!defined $result) {
   printf "ERROR: %s.\n", $session->error();
   $session->close();
   exit 1;
}
printf "El sysUpTime para el host '%s' es %s.\n",
       $session->hostname(), $result->{$OID_sysUpTime};
$session->close();
exit 0;

2. Bloqueo de solicitud-set SNMPv3 para sysContact

Este ejemplo establece la información de sysContact en el host remoto a "Help Desk x911". Los argumentos nombrados pasados al constructor session() son para la demostración de la sintaxis únicamente. Estos parámetros deberán configurarse según los parámetros SNMPv3 del host remoto. La utilidad "snmpkey" incluida con la distribución puede utilizarse para crear los valores clave.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP;
my $OID_sysContact = '1.3.6.1.2.1.1.4.0';
my ($session, $error) = Net::SNMP->session(
   -hostname     => 'myv3host.example.com',
   -version      => 'snmpv3',
   -username     => 'myv3Username',
   -authprotocol => 'sha1',
   -authkey      => '0x6695febc9288e36282235fc7151f128497b38f3f',
   -privprotocol => 'des',
   -privkey      => '0x6695febc9288e36282235fc7151f1284',
);
if (!defined $session) {
   printf "ERROR: %s.\n", $error;
   exit 1;
}
my $result = $session->set_request(
   -varbindlist => [ $OID_sysContact, OCTET_STRING, 'Help Desk x911' ],
);
if (!defined $result) {
   printf "ERROR: %s.\n", $session->error();
   $session->close();
   exit 1;
}
printf "El sysContact para el host '%s' se estableció en '%s'.\n",
       $session->hostname(), $result->{$OID_sysContact};
$session->close();
exit 0;

3. Solicitud-get-bulk no bloqueante SNMPv2c para ifTable

Este ejemplo obtiene el contenido de ifTable enviando solicitudes get-bulk hasta que las respuestas ya no formen parte de ifTable. ifTable también se puede recuperar usando el método get_table(). El objeto ifPhysAddress en la tabla tiene una sintaxis de CADENA_OCTAL. Por defecto, la traducción está habilitada y las CADENAS_OCTAL no imprimibles se traducen a un formato hexadecimal. A veces, la CADENA_OCTAL contiene caracteres imprimibles y esto produce una salida inesperada cuando no se traduce. El ejemplo desactiva la traducción para las CADENAS_OCTAL y formatea específicamente la salida para los objetos ifPhysAddress.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP qw(:snmp);
my $OID_ifTable = '1.3.6.1.2.1.2.2';
my $OID_ifPhysAddress = '1.3.6.1.2.1.2.2.1.6';
my ($session, $error) = Net::SNMP->session(
   -hostname    => shift || 'localhost',
   -community   => shift || 'public',
   -nonblocking => 1,
   -translate   => [-octetstring => 0],
   -version     => 'snmpv2c',
);
if (!defined $session) {
   printf "ERROR: %s.\n", $error;
   exit 1;
}
my %table; # Hash para almacenar los resultados
my $result = $session->get_bulk_request(
   -varbindlist    => [ $OID_ifTable ],
   -callback       => [ \&table_callback, \%table ],
   -maxrepetitions => 10,
);
if (!defined $result) {
   printf "ERROR: %s\n", $session->error();
   $session->close();
   exit 1;
}
# Ahora inicia el intercambio de mensajes SNMP.
snmp_dispatcher();
$session->close();
# Imprime los resultados, formateando específicamente ifPhysAddress.
for my $oid (oid_lex_sort(keys %table)) {
   if (!oid_base_match($OID_ifPhysAddress, $oid)) {
      printf "%s = %s\n", $oid, $table{$oid};
   } else {
      printf "%s = %s\n", $oid, unpack 'H*', $table{$oid};
   }
}
exit 0;
sub table_callback
{
   my ($session, $table) = @_;
   my $list = $session->var_bind_list();
   if (!defined $list) {
      printf "ERROR: %s\n", $session->error();
      return;
   }
   # Recorre cada uno de los OID en la respuesta y asigna
   # los pares clave/valor a la referencia que se pasó con
   # la devolución de llamada. Asegúrate de que todavía estamos en la tabla
   # antes de asignar la clave/valor.
   my @names = $session->var_bind_names();
   my $next  = undef;
   while (@names) {
      $next = shift @names;
      if (!oid_base_match($OID_ifTable, $next)) {
         return; # La tabla ha terminado.
      }
      $table->{$next} = $list->{$next};
   }
   # La tabla no ha terminado, envía otra solicitud, comenzando en el último
   # IDENTIFICADOR_OBJETO en la respuesta. No es necesario incluir el
   # argumento de devolución de llamada, se utilizará la misma devolución de
   # llamada que se especificó para la solicitud original.
   my $result = $session->get_bulk_request(
      -varbindlist    => [ $next ],
      -maxrepetitions => 10,
   );
   if (!defined $result) {
      printf "ERROR: %s.\n", $session->error();
   }
   return;
}

4. Solicitud-get y solicitud-set SNMPv1 no bloqueantes en múltiples hosts

Este ejemplo primero sondea varios hosts para su sysUpTime. Si el sondeo del host es exitoso, la información sysContact y sysLocation se establece en el host. La información sysContact está codificada como fija a "Help Desk x911" mientras que la información sysLocation se pasa como argumento al callback.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP;
my $OID_sysUpTime = '1.3.6.1.2.1.1.3.0';
my $OID_sysContact = '1.3.6.1.2.1.1.4.0';
my $OID_sysLocation = '1.3.6.1.2.1.1.6.0';
# Hash de hosts y datos de ubicación.
my %host_data = (
   '10.1.1.2'  => 'Building 1, Second Floor',
   '10.2.1.1'  => 'Building 2, First Floor',
   'localhost' => 'Right here!',
);
# Crea una sesión para cada host y pone en cola una solicitud get para sysUpTime.
for my $host (keys %host_data) {
   my ($session, $error) = Net::SNMP->session(
      -hostname    => $host,
      -community   => 'private',
      -nonblocking => 1,
   );
   if (!defined $session) {
      printf "ERROR: No se pudo crear la sesión para el host '%s': %s.\n",
             $host, $error;
      next;
   }
   my $result = $session->get_request(
      -varbindlist => [ $OID_sysUpTime ],
      -callback    => [ \&get_callback, $host_data{$host} ],
   );
   if (!defined $result) {
      printf "ERROR: No se pudo poner en cola la solicitud get para el host '%s': %s.\n",
             $session->hostname(), $session->error();
   }
}
# Ahora inicia el intercambio de mensajes SNMP.
snmp_dispatcher();
exit 0;
sub get_callback
{
   my ($session, $location) = @_;
   my $result = $session->var_bind_list();
   if (!defined $result) {
      printf "ERROR: La solicitud get falló para el host '%s': %s.\n",
             $session->hostname(), $session->error();
      return;
   }
   printf "El sysUpTime para el host '%s' es %s.\n",
           $session->hostname(), $result->{$OID_sysUpTime};
   # Ahora establece el sysContact y sysLocation para el host.
   $result = $session->set_request(
      -varbindlist =>
      [
         $OID_sysContact,  OCTET_STRING, 'Help Desk x911',
         $OID_sysLocation, OCTET_STRING, $location,
      ],
      -callback    => \&set_callback,
   );
   if (!defined $result) {
      printf "ERROR: No se pudo poner en cola la solicitud set para el host '%s': %s.\n",
             $session->hostname(), $session->error();
   }
   return;
}
sub set_callback
{
   my ($session) = @_;
   my $result = $session->var_bind_list();
   if (defined $result) {
      printf "El sysContact para el host '%s' se estableció en '%s'.\n",
             $session->hostname(), $result->{$OID_sysContact};
      printf "El sysLocation para el host '%s' se estableció en '%s'.\n",
             $session->hostname(), $result->{$OID_sysLocation};
   } else {
      printf "ERROR: La solicitud set falló para el host '%s': %s.\n",
             $session->hostname(), $session->error();
   }
   return;
}

REQUISITOS

  • El módulo Net::SNMP utiliza una sintaxis que no es compatible en versiones de Perl anteriores a la v5.6.0.
  • Se requieren los módulos no principales Crypt::DES, Digest::MD5, Digest::SHA1 y Digest::HMAC para admitir SNMPv3.
  • Para admitir el Algoritmo de Cifrado AES como protocolo de privacidad SNMPv3, se necesita el módulo no principal Crypt::Rijndael.
  • Para usar UDP/IPv6 o TCP/IPv6 como Dominio de Transporte, se necesita el módulo no principal Socket6.
