NAME

Net::FTP - Clase de cliente FTP

SYNOPSIS

use Net::FTP;
$ftp = Net::FTP->new("some.host.name", Debug => 0)
  or die "No puede conectarse a some.host.name: $@";
$ftp->login("anonymous",'-anonymous@')
  or die "No puede iniciar sesión ", $ftp->message;
$ftp->cwd("/pub")
  or die "No puede cambiar el directorio trabajo ", $ftp->message;
$ftp->get("that.file")
  or die "get falló ", $ftp->message;
$ftp->quit;

DESCRIPCIÓN

Net::FTP es una clase que implementa un cliente FTP simple en Perl, tal como se describe en RFC959. Ofrece envoltorios para el subconjunto común de comandos de RFC959. Si IO::Socket::IP o IO::Socket::INET6 están instalados, también proporciona soporte para IPv6 según RFC2428. Con IO::Socket::SSL instalado, también proporciona soporte para FTPS implícito y FTPS explícito según RFC4217.

La clase Net::FTP es una subclase de Net::Cmd y (dependiendo de la disponibilidad) de IO::Socket::IP, IO::Socket::INET6 o IO::Socket::INET.

Sobre

FTP es el Protocolo de Transferencia de Archivos. Es una forma de transferir archivos entre máquinas de red. El protocolo define un cliente (cuya información se proporciona por este módulo) y un servidor (no implementado en este módulo). La comunicación siempre se inicia por el cliente, y el servidor responde con un mensaje y un código de estado (y a veces con datos).

El protocolo FTP permite enviar archivos a o recuperarlos del servidor. Cada transferencia involucra un archivo local (en el cliente) y un archivo remoto (en el servidor). En este módulo, el mismo nombre de archivo se utilizará tanto para el local como para el remoto si se especifica solo uno. Esto significa que la transferencia de archivo remoto "/path/to/file" intentará colocar ese archivo en "/path/to/file" localmente, a menos que se especifique un nombre de archivo local.

El protocolo también define varios tipos estándar de traducciones que el archivo puede aplicar durante la transferencia. Estos son ASCII, EBCDIC, binario y byte. ASCII es el tipo por defecto, indicando que el emisor de los archivos traducirá los fin de línea en una representación estándar que el receptor luego traducirá a su representación local. EBCDIC indica que el archivo que se está trasladando está en formato EBCDIC. El binario (también conocido como imagen) envía los datos como una secuencia de bits contigua. El byte envía los datos como bytes, los valores de los cuales se mantienen iguales, independientemente de las diferencias en el tamaño de byte entre las dos máquinas (en teoría - en práctica, deberías usar esto solo si realmente conoces lo que estás haciendo). Esta clase no soporta los formatos EBCDIC o byte, y por defecto se usará binario si se intenta usar uno de estos.

Métodos_de_Clase

"new([$host][, %options])"
Este es el constructor para un objeto Net::FTP. $host es el nombre de la máquina remota a la cual se necesita una conexión FTP.

$host es opcional. Si no se especifica $host, puede ser pasado como el parámetro "Host" descrito a continuación.

%options se pasan en forma de pares clave-valor, usando la forma de clave-valor. Las posibles opciones son:

Host - Máquina FTP a la que se conectará. Puede ser un escalar único, como se define para el parámetro "PeerAddr" en IO::Socket::INET, o una referencia a un array de hosts a probar en orden. El método "host" devolverá el valor que se usó para conectarse a la máquina.

Firewall - El nombre de una máquina que actúa como un firewall FTP. Esto puede ser sobrescrito por un entorno variable "FTP_FIREWALL". Si se especifica y la máquina dada no puede conectarse directamente, la conexión se hace a la máquina de firewall y el identificador se agrega con @hostname. Esta configuración también se llama como proxy FTP.

FirewallType - El tipo de firewall que se encuentra en la máquina indicada por Firewall. Esto puede ser sobrescrito por un entorno variable "FTP_FIREWALL_TYPE". Para una lista de tipos permitidos, vea la descripción de ftp_firewall_type en Net::Config.

BlockSize - El tamaño de bloque que Net::FTP usará durante las transferencias. (predeterminado: 10240)

Port - El número de puerto a conectar a la máquina remota para la conexión FTP

SSL - Si la conexión debe hacerse desde el principio con SSL, en lugar de actualizarse con "starttls".

SSL_* - Argumentos SSL que se aplican cuando se actualiza la conexión de control o datos a SSL. Puedes usar los argumentos SSL como documentados en IO::Socket::SSL, pero generalmente usarán los argumentos correctos ya.

Timeout - Establece un valor de tiempo limite en segundos (predeterminado: 120)

Debug - nivel de depuración (ver el método debug en Net::Cmd)

Passive - Si se establece a un valor no cero, todos los transferidos de datos se realizarán en modo pasivo. Si se establece a cero, los transferidos de datos se realizarán en modo activo. Si la máquina está conectada directamente a Internet, ambos modos deberían funcionar igualmente bien. Por detrás de la mayoría de firewalls y configuraciones NAT, el modo pasivo tiene un mejor chance de funcionar. Sin embargo, en algunas configuraciones raras de firewalls, el modo activo funciona cuando el modo pasivo no funciona. Algunas máquinas muy antiguas pueden no implementar transferencias pasivas. Si no se especifica, el modo de transferencia se establece por el entorno variable "FTP_PASSIVE" o si esa variable no está establecida por el utilitario libnetcfg. Si ninguno de estos aplica, se usará el modo pasivo.

Hash - Si se le pasa un referencia a un archivo de salida (por ejemplo, "*STDOUT"), imprime # en ese archivo de salida cada 1024 bytes. Esto simplemente invoca el método hash() por ti, así que se muestran # para todas las transferencias. Puedes llamar explícitamente al método hash() cuando quieras.

LocalAddr - Dirección local a utilizar para todas las conexiones de socket. Este argumento se pasa al superclase, es decir, a IO::Socket::INET o IO::Socket::IP.

Domain - Dominio a utilizar, es decir, AF_INET o AF_INET6. Este argumento se pasa al superclase IO::Socket. Esto puede usarse para forzar IPv4 incluso aunque IO::Socket::IP se use, que se comportaría por defecto como IPv6. Family es aceptado como nombre alternativo de Domain.

Si el constructor falla, undef será devuelto y un mensaje de error estará en $@

Métodos_de_Objeto

A menos que se indique de otro modo, todos los métodos devuelven verdadero o falso, con verdadero indicando que la operación fue exitosa. Cuando un método indica que devuelve un valor, se devolverá falso o una lista vacía en caso de fracaso.

Net::FTP hereda de Net::Cmd, por lo que los métodos definidos en Net::Cmd pueden usarse para enviar comandos a la máquina FTP remota además de los mencionados aquí.

"login([$login[, $password[, $account]]])"
Inicia sesión en la máquina FTP remota con la información de inicio de sesión proporcionada. Si no se proporcionan argumentos, el "Net::FTP" usa el paquete "Net::Netrc" para buscar la información de inicio de sesión para el host conectado. Si no se encuentra información, se usa un inicio de sesión de anonymous. Si no se proporciona un password y el inicio de sesión es anonymous, se usará anonymous@ como password.

Si la conexión se hace a través de un firewall, se llamará al método "authorize" sin argumentos.

starttls()
Actualiza la conexión existente a SSL. Los argumentos SSL deben ser dados en "new".

stoptls()
Reduce una conexión SSL existente de vuelta a texto plano. Esto es necesario para trabajar con algunos ayudantes de FTP en cortafuegos, que necesitan ver los comandos y respuestas PORT y PASV para abrir dinámicamente los puertos necesarios. En este caso, "starttls" generalmente solo se hace para proteger la autorización.
prot($level)
Establece qué tipo de protección de canal de datos usarán el cliente y el servidor. Solo se admiten los niveles $level "C" (claro) y "P" (privado).
host()
Devuelve el valor utilizado por el constructor y pasado a la clase superior IO::Socket para conectarse al host.
account($acct)
Establece una cadena que identifica la cuenta del usuario.
"authorize([$auth[, $resp]])"
Este es un protocolo utilizado por algunos proxies FTP de cortafuegos. Se utiliza para autorizar al usuario a enviar datos. Si no se especifican ambos argumentos, entonces "authorize" utiliza "Net::Netrc" para realizar una búsqueda.
site($args)
Envía un comando SITE al servidor remoto y espera una respuesta.

Devuelve el dígito más significativo del código de respuesta.

ascii()
Transfiere el archivo en ASCII. Se realizará la traducción de CRLF si es necesario.
binary()
Transfiere el archivo en modo binario. No se realizará ninguna transformación.

Pista: Si tanto la máquina del servidor como la del cliente utilizan el mismo final de línea para los archivos de texto, será más rápido transferir todos los archivos en modo binario.

type([$type])
Establece u obtiene si los archivos se transferirán en modo ASCII o binario.
"rename($oldname, $newname)"
Renombra un archivo en el servidor FTP remoto de $oldname a $newname. Esto se hace enviando los comandos RNFR y RNTO.
delete($filename)
Envía una solicitud al servidor para eliminar $filename.
cwd([$dir])
Intenta cambiar de directorio al directorio dado en $dir. Si $dir es "..", se utiliza el comando FTP "CDUP" para intentar subir un directorio. Si no se proporciona ningún directorio, se intenta cambiar al directorio raíz.
cdup()
Cambia al directorio padre del directorio actual.
passive([$passive])
Establece u obtiene si las conexiones de datos se iniciarán en modo pasivo.
pwd()
Devuelve la ruta completa del directorio actual.
restart($where)
Establece el desplazamiento de bytes en el que comenzar la próxima transferencia de datos. Net::FTP simplemente registra este valor y lo utiliza durante la próxima transferencia de datos. Por esta razón, este método no devolverá un error, pero su establecimiento puede hacer que una transferencia de datos posterior falle.
"rmdir($dir[, $recurse])"
Elimina el directorio con el nombre $dir. Si $recurse es *verdadero*, entonces "rmdir" intentará eliminar todo dentro del directorio.
"mkdir($dir[, $recurse])"
Crea un nuevo directorio con el nombre $dir. Si $recurse es *verdadero*, entonces "mkdir" intentará crear todos los directorios en la ruta dada.

Devuelve la ruta completa al nuevo directorio.

"alloc($size[, $record_size])"
El comando alloc permite dar al servidor FTP una pista sobre el tamaño del archivo que se va a transferir utilizando el comando ftp ALLO. Algunos sistemas de almacenamiento lo utilizan para tomar decisiones inteligentes sobre cómo almacenar el archivo. El argumento $size representa el tamaño del archivo en bytes. El argumento $record_size indica un tamaño máximo de registro o página para archivos enviados con una estructura de registro o página.

El tamaño del archivo se determinará y se enviará automáticamente al servidor para archivos normales, por lo que este método solo necesita ser llamado si está transfiriendo datos desde un socket, tubería con nombre u otro flujo no asociado con un archivo normal.

ls([$dir])
Obtiene una lista del directorio de $dir, o del directorio actual.

En un contexto de array, devuelve una lista de líneas devueltas por el servidor. En un contexto escalar, devuelve una referencia a una lista.

dir([$dir])
Obtiene una lista del directorio de $dir, o del directorio actual en formato largo.

En un contexto de array, devuelve una lista de líneas devueltas por el servidor. En un contexto escalar, devuelve una referencia a una lista.

"get($remote_file[, $local_file[, $where]])"
Obtiene $remote_file del servidor y lo almacena localmente. $local_file puede ser un nombre de archivo o un manejador de archivo. Si no se especifica, el archivo se almacenará en el directorio actual con el mismo nombre de hoja que el archivo remoto.

Si se proporciona $where, los primeros $where bytes del archivo no se transferirán, y los bytes restantes se añadirán al archivo local si ya existe.

Devuelve $local_file, o el nombre de archivo local generado si no se proporciona $local_file. Si se encontró un error, se devuelve undef.

"put($local_file[, $remote_file])"
Sube un archivo al servidor remoto. $local_file puede ser un nombre o un manejador de archivo. Si $local_file es un manejador de archivo, entonces se debe especificar $remote_file. Si no se especifica $remote_file, el archivo se almacenará en el directorio actual con el mismo nombre de hoja que $local_file.

Devuelve $remote_file, o el nombre de archivo remoto generado si no se proporciona $remote_file.

NOTA: Si por alguna razón la transferencia no se completa y se devuelve un error, los contenidos que se habían transferido no se eliminarán automáticamente.

"put_unique($local_file[, $remote_file])"
Igual que put pero utiliza el comando "STOU".

Devuelve el nombre del archivo en el servidor.

"append($local_file[, $remote_file])"
Igual que put pero añade al archivo en el servidor remoto.

Devuelve $remote_file, o el nombre de archivo remoto generado si no se proporciona $remote_file.

unique_name()
Devuelve el nombre del último archivo almacenado en el servidor utilizando el comando "STOU".
mdtm($file)
Devuelve la *hora de modificación* del archivo dado.
size($file)
Devuelve el tamaño en bytes del archivo dado tal como está almacenado en el servidor remoto.

NOTA: El tamaño reportado es el tamaño del archivo almacenado en el servidor remoto. Si el archivo se transfiere posteriormente desde el servidor en modo ASCII y el servidor remoto y la máquina local tienen diferentes ideas sobre "Fin de Línea", entonces el tamaño del archivo en la máquina local después de la transferencia puede ser diferente.

supported($cmd)
Devuelve TRUE si el servidor remoto soporta el comando dado.
"hash([$filehandle_glob_ref[, $bytes_per_hash_mark]])"
Si se llama sin parámetros, o con el primer argumento falso, se suprimen las marcas de hash. Si el primer argumento es verdadero pero no es una referencia a un glob de manejador de archivo, entonces se usa \*STDERR. El segundo argumento es el número de bytes por marca de hash impresa, y por defecto es 1024. En todos los casos, el valor de retorno es una referencia a un array de dos elementos: la referencia al glob del manejador de archivo y los bytes por marca de hash.
feature($name)
Determina si el servidor soporta la característica especificada. El valor de retorno es una lista de líneas con las que el servidor respondió para describir las opciones que soporta para la característica dada. Si la característica no es compatible, se devuelve la lista vacía. 
if ($ftp->feature( 'MDTM' )) {
  # Hacer algo
}
if (grep { /\bTLS\b/ } $ftp->feature('AUTH')) {
  # El servidor soporta TLS
}

Los siguientes métodos pueden devolver resultados diferentes dependiendo de cómo se llamen. Si el usuario llama explícitamente a cualquiera de los métodos "pasv" o "port", entonces estos métodos devolverán un valor *verdadero* o *falso*. Si el usuario no llama a ninguno de estos métodos, el resultado será una referencia a un objeto basado en "Net::FTP::dataconn".

nlst([$dir])
Envía un comando "NLST" al servidor, con un parámetro opcional.
list([$dir])
Igual que "nlst" pero usando el comando "LIST".
retr($file)
Inicia la recuperación de un archivo llamado $file del servidor remoto.
stor($file)
Indica al servidor que desea almacenar un archivo. $file es el nombre del nuevo archivo que debe crearse.
