Net::DNS::Resolver(3) Documentación de Perl aportada por el usuario Net::DNS::Resolver(3)

NOMBRE

Net::DNS::Resolver - clase de resolución DNS

SINOPSIS

use Net::DNS;
$resolver = Net::DNS::Resolver->new();
# Realiza una búsqueda, utilizando la lista de búsqueda si es apropiado.
$reply = $resolver->search( 'example.com' );
# Realiza una búsqueda, sin la lista de búsqueda
$reply = $resolver->query( 'example.com', 'MX' );
# Realiza una búsqueda, sin pre o post-procesamiento
$reply = $resolver->send( 'example.com', 'MX', 'IN' );
# Envía un paquete de consulta preconstruido
$query = Net::DNS::Packet->new( ... );
$reply = $resolver->send( $query );

DESCRIPCIÓN

Las instancias de la clase Net::DNS::Resolver representan objetos resolutores. Un programa puede tener múltiples objetos resolutores, cada uno manteniendo su propia información de estado, como los servidores de nombres a consultar, si la recursión está deseada, etc.

MÉTODOS

new

# Usa la configuración por defecto
$resolver = Net::DNS::Resolver->new();
# Usa mi propio archivo de configuración
$resolver = Net::DNS::Resolver->new( config_file => '/my/dns.conf' );
# Establece opciones en el constructor
$resolver = Net::DNS::Resolver->new(
                nameservers => [ '2001:DB8::1', 'ns.example.com' ],
                recurse     => 0,
                debug       => 1
                );

Devuelve un objeto resolutor. Si no se proporcionan argumentos, new() devuelve un objeto que tiene la configuración por defecto.

En sistemas Unix y Linux, los valores por defecto se leen de los siguientes archivos, en el orden indicado:

/etc/resolv.conf, $HOME/.resolv.conf, ./.resolv.conf

Las siguientes palabras clave son reconocidas en los archivos de configuración del resolutor:

nameserver
Dirección IP de un servidor de nombres que el resolutor debe consultar.
domain
El sufijo de dominio que se añadirá a un nombre corto no absoluto.
search
Una lista separada por espacios de dominios en la ruta de búsqueda deseada.
options
Una lista separada por espacios de elementos clave:valor.

Excepto para /etc/resolv.conf, los archivos solo se leerán si pertenecen al ID de usuario efectivo que ejecuta el programa. Además, varias variables de entorno pueden contener información de configuración; véase "AMBIENTE".

Tenga en cuenta que las palabras clave domain y searchlist son mutuamente excluyentes. Si ambas están presentes, el comportamiento resultante no está especificado. Si ninguna de las dos está presente, el dominio se determina a partir del nombre de host local.

En sistemas Windows, se intenta determinar los valores por defecto del sistema utilizando el registro. Los sistemas con muchas interfaces de red configuradas dinámicamente pueden confundir a Net::DNS.

Si se especifica un archivo de configuración personalizado en la primera instanciación, todos los demás archivos de configuración y variables de entorno se ignorarán.

Los argumentos explícitos a new() anulan las variables de configuración correspondientes. La lista de argumentos consta de una secuencia de pares (nombre=>valor), cada uno interpretado como una invocación del método correspondiente.

print

$resolver->print;

Imprime el estado del resolutor en la salida estándar.

query

$packet = $resolver->query( 'host' );
$packet = $resolver->query( 'host.example.com' );
$packet = $resolver->query( '2001:DB8::1' );
$packet = $resolver->query( 'example.com', 'MX' );
$packet = $resolver->query( 'annotation.example.com', 'TXT', 'IN' );

Realiza una consulta DNS para el nombre dado; la lista de búsqueda no se aplica. Si "defnames" es verdadero, se añadirá el dominio por defecto a los nombres no cualificados.

El tipo de registro y la clase se pueden omitir; por defecto son A e IN. Si el nombre parece una dirección IP (IPv4 o IPv6), se realizará una consulta dentro de in-addr.arpa o ip6.arpa.

Devuelve un objeto Net::DNS::Packet, o "undef" si no se encontraron respuestas. El motivo del fallo puede determinarse usando errorstring().

Si necesita examinar el paquete de respuesta, independientemente de si contiene respuestas o no, utilice el método send() en su lugar.

search

$packet = $resolver->search( 'host' );
$packet = $resolver->search( 'host.example.com' );
$packet = $resolver->search( '2001:DB8::1' );
$packet = $resolver->search( 'example.com', 'MX' );
$packet = $resolver->search( 'annotation.example.com', 'TXT', 'IN' );

Realiza una consulta DNS para el nombre dado, aplicando la lista de búsqueda si es apropiado. El algoritmo de búsqueda es el siguiente:

Si el nombre contiene uno o más puntos no terminales, realiza una consulta inicial utilizando el nombre sin modificar.

Si el número de puntos es menor que "ndots", y no hay un punto terminal, intenta añadir cada sufijo de la lista de búsqueda.

El tipo de registro y la clase se pueden omitir; por defecto son A e IN. Si el nombre parece una dirección IP (IPv4 o IPv6), se realizará una consulta dentro de in-addr.arpa o ip6.arpa.

Devuelve un objeto Net::DNS::Packet, o "undef" si no se encontraron respuestas. El motivo del fallo puede determinarse usando errorstring().

Si necesita examinar el paquete de respuesta, independientemente de si contiene respuestas o no, utilice el método send() en su lugar.

send

$packet = $resolver->send( $query );
$packet = $resolver->send( 'host.example.com' );
$packet = $resolver->send( '2001:DB8::1' );
$packet = $resolver->send( 'example.com', 'MX' );
$packet = $resolver->send( 'annotation.example.com', 'TXT', 'IN' );

Realiza una consulta DNS para el nombre dado. Ni la lista de búsqueda ni el dominio por defecto se añadirán.

La lista de argumentos puede ser un paquete Net::DNS::Packet de consulta preconstruido o una lista de cadenas. El tipo de registro y la clase se pueden omitir; por defecto son A e IN. Si el nombre parece una dirección IP (IPv4 o IPv6), se realizará una consulta dentro de in-addr.arpa o ip6.arpa.

Devuelve un objeto Net::DNS::Packet, haya o no respuestas. Utilice "$packet->header->ancount" o "$packet->answer" para saber si hubo algún registro en la sección de respuestas. Devuelve "undef" si no se recibió ninguna respuesta.

axfr

@zone = $resolver->axfr();
@zone = $resolver->axfr( 'example.com' );
@zone = $resolver->axfr( 'example.com', 'IN' );
$iterator = $resolver->axfr();
$iterator = $resolver->axfr( 'example.com' );
$iterator = $resolver->axfr( 'example.com', 'IN' );
$rr = $iterator->();

Realiza una transferencia de zona utilizando la lista de servidores de nombres del resolutor, intentándolo en el orden indicado.

Si la zona se omite, se utilizará por defecto la primera zona listada en la lista de búsqueda del resolutor.

Si la clase se omite, se utilizará por defecto IN.

Cuando se llama en contexto de lista, axfr() devuelve una lista de objetos Net::DNS::RR. El registro SOA redundante que termina la transferencia de zona no se devuelve al llamador.

En deferencia a RFC1035(6.3), se espera que una transferencia de zona completa devuelva todos los registros de la zona o nada en absoluto. Cuando axfr() no devuelve ningún registro de recurso, el motivo del fallo puede determinarse usando errorstring().

Aquí hay un ejemplo que usa un tiempo de espera y verificación TSIG:

$resolver->tcp_timeout( 10 );
$resolver->tsig( $keyfile );
@zone = $resolver->axfr( 'example.com' );
foreach $rr (@zone) {
        $rr->print;
}

Cuando se llama en contexto escalar, axfr() devuelve un objeto iterador. Cada invocación del iterador devuelve un solo Net::DNS::RR o "undef" cuando la zona se agota.

Se genera una excepción si la transferencia de zona no se puede completar.

$resolver->tcp_timeout( 10 );

bgsend

$handle = $resolver->bgsend( $packet ) || die $resolver->errorstring;
$handle = $resolver->bgsend( 'host.example.com' );
$handle = $resolver->bgsend( '2001:DB8::1' );
$handle = $resolver->bgsend( 'example.com', 'MX' );
$handle = $resolver->bgsend( 'annotation.example.com', 'TXT', 'IN' );

Realiza una consulta DNS en segundo plano para el nombre dado y devuelve inmediatamente sin esperar la respuesta. El programa puede entonces realizar otras tareas mientras espera la respuesta del servidor de nombres.

La lista de argumentos puede ser un objeto Net::DNS::Packet o una lista de cadenas. El tipo de registro y la clase se pueden omitir; por defecto son A e IN. Si el nombre parece una dirección IP (IPv4 o IPv6), se realizará una consulta dentro de in-addr.arpa o ip6.arpa.

Devuelve un manejador opaco que se pasa a invocaciones posteriores de los métodos bgbusy() y bgread(). Los errores se indican devolviendo "undef", en cuyo caso la razón del fallo se puede determinar usando errorstring().

El objeto Net::DNS::Packet de respuesta se obtiene llamando a bgread().

CUIDADO: Los programas no deben hacer suposiciones sobre la naturaleza de los manejadores devueltos por bgsend(), que deben usarse estrictamente como se describe aquí.

bgread

$handle = $resolver->bgsend( 'www.example.com' );
$packet = $resolver->bgread($handle);

Lee la respuesta después de una consulta en segundo plano. El argumento es el manejador devuelto por bgsend().

Devuelve un objeto Net::DNS::Packet o "undef" si no se recibió ninguna respuesta antes de que expirara el intervalo de tiempo de espera.

bgbusy

$handle = $resolver->bgsend( 'foo.example.com' );
while ($resolver->bgbusy($handle)) {
        ...
}
$packet = $resolver->bgread($handle);

Devuelve verdadero mientras se espera la respuesta o mientras la transacción expira. El argumento es el manejador devuelto por bgsend().

Los paquetes UDP truncados se reenviarán transparentemente usando TCP mientras se sigue afirmando que está ocupado al llamador.

debug

print 'debug flag: ', $resolver->debug, "\n";
$resolver->debug(1);

Obtiene o establece la bandera de depuración. Si está activada, las llamadas a search(), query() y send() imprimirán información de depuración en la salida estándar. El valor predeterminado es falso.

defnames

print 'defnames flag: ', $resolver->defnames, "\n";
$resolver->defnames(0);

Obtiene o establece la bandera defnames. Si es verdadera, las llamadas a query() agregarán el dominio predeterminado para resolver nombres que no están completamente calificados. El valor predeterminado es verdadero.

dnsrch

print 'dnsrch flag: ', $resolver->dnsrch, "\n";
$resolver->dnsrch(0);

Obtiene o establece la bandera dnsrch. Si es verdadera, las llamadas a search() aplicarán la lista de búsqueda para resolver nombres que no están completamente calificados. El valor predeterminado es verdadero.

domain

$domain = $resolver->domain;
$resolver->domain( 'domain.example' );

Obtiene o establece el dominio predeterminado del resolvedor.

igntc

print 'igntc flag: ', $resolver->igntc, "\n";
$resolver->igntc(1);

Obtiene o establece la bandera igntc. Si es verdadera, los paquetes truncados serán ignorados. Si es falsa, la consulta se reintentará usando TCP. El valor predeterminado es falso.

nameserver, nameservers

@nameservers = $resolver->nameservers();
$resolver->nameservers( '2001:DB8::1', '192.0.2.1' );
$resolver->nameservers( 'ns.domain.example.' );

Obtiene o establece los servidores de nombres que se consultarán.

También véase las notas de transporte IPv6 más abajo.

persistent_tcp

print 'Persistent TCP flag: ', $resolver->persistent_tcp, "\n";
$resolver->persistent_tcp(1);

Obtiene o establece la configuración de TCP persistente. Si es verdadera, Net::DNS mantendrá un socket TCP abierto para cada host:puerto al que se conecte. Esto es útil si estás usando TCP y necesitas hacer muchas consultas o actualizaciones al mismo servidor de nombres.

El valor predeterminado es falso a menos que estés ejecutando un Perl con SOCKS, en cuyo caso el valor predeterminado es verdadero.

persistent_udp

print 'Persistent UDP flag: ', $resolver->persistent_udp, "\n";
$resolver->persistent_udp(1);

Obtiene o establece la configuración de UDP persistente. Si es verdadera, un resolvedor Net::DNS utilizará el mismo socket UDP para todas las consultas dentro de cada familia de direcciones.

Esto evita el costo de crear y cerrar sockets UDP, pero también elimina la aleatorización del puerto de origen.

port

print 'sending queries to port ', $resolver->port, "\n";
$resolver->port(9732);

Obtiene o establece el puerto al que se envían las consultas. Conveniente para probar servidores de nombres usando un puerto no estándar. El valor predeterminado es el puerto 53.

recurse

print 'recursion flag: ', $resolver->recurse, "\n";
$resolver->recurse(0);

Obtiene o establece la bandera de recursión. Si es verdadera, esto dirigirá a los servidores de nombres a realizar una consulta recursiva. El valor predeterminado es verdadero.

retrans

print 'retrans interval: ', $resolver->retrans, "\n";
$resolver->retrans(3);

Obtiene o establece el intervalo de retransmisión. El valor predeterminado es de 5 segundos.

retry

print 'number of tries: ', $resolver->retry, "\n";
$resolver->retry(2);

Obtiene o establece el número de veces que se intentará la consulta. El valor predeterminado es 4.

searchlist

@searchlist = $resolver->searchlist;
$resolver->searchlist( 'a.example', 'b.example', 'c.example' );

Obtiene o establece la lista de búsqueda del resolvedor.

srcaddr

$resolver->srcaddr('2001::DB8::1');

Establece la dirección de origen desde la que se envían las consultas. Conveniente para forzar consultas desde una interfaz específica en un host multi-homed. El valor predeterminado es usar cualquier dirección local.

srcport

$resolver->srcport(5353);

Establece el puerto desde el que se envían las consultas. El valor predeterminado es 0, lo que significa cualquier puerto.

tcp_timeout

print 'TCP timeout: ', $resolver->tcp_timeout, "\n";
$resolver->tcp_timeout(10);

Obtiene o establece el tiempo de espera de TCP en segundos. El valor predeterminado es de 120 segundos (2 minutos).

udp_timeout

print 'UDP timeout: ', $resolver->udp_timeout, "\n";
$resolver->udp_timeout(10);

Obtiene o establece el tiempo de espera de UDP de bgsend() en segundos. El valor predeterminado es de 30 segundos.

udppacketsize

print "udppacketsize: ", $resolver->udppacketsize, "\n";
$resolver->udppacketsize(2048);

Obtiene o establece el tamaño del paquete UDP. Si se establece en un valor no menor que el tamaño predeterminado del paquete DNS, se agregará una extensión EDNS que indica soporte para datagramas UDP grandes.

usevc

print 'usevc flag: ', $resolver->usevc, "\n";
$resolver->usevc(1);

Obtiene o establece la bandera usevc. Si es verdadera, las consultas se realizarán utilizando circuitos virtuales (TCP) en lugar de datagramas (UDP). El valor predeterminado es falso.

replyfrom

print 'last response was from: ', $resolver->replyfrom, "\n";

Devuelve la dirección IP desde la que se recibió el paquete más reciente en respuesta a una consulta.

errorstring

print 'query status: ', $resolver->errorstring, "\n";

Devuelve una cadena que contiene información de error de la interacción DNS más reciente. errorstring() solo tiene sentido cuando se interroga inmediatamente después de la llamada al método correspondiente.

dnssec

print "dnssec flag: ", $resolver->dnssec, "\n";
$resolver->dnssec(0);

La bandera dnssec hace que el resolvedor transmita consultas DNSSEC y agregue un registro EDNS0 según lo requerido por RFC2671 y RFC3225. Las acciones y la respuesta del servidor de nombres remoto están determinadas por la configuración de las banderas AD y CD.

Llamar al método dnssec() con un valor no cero también establecerá el tamaño del paquete UDP al valor predeterminado de 2048. Si ese valor es demasiado pequeño o demasiado grande para su entorno, debería llamar al método udppacketsize() inmediatamente después.

$resolver->dnssec(1);
$resolver->udppacketsize(1250); # ajustar el tamaño del paquete UDP

Se generará una excepción fatal si el

dnssec() se llama pero la biblioteca Net::DNS::SEC no se ha instalado.

adflag

$resolver->dnssec(1);
$resolver->adflag(1);
print "bandera de autenticación deseada: ", $resolver->adflag, "\n";

Obtiene o establece el bit AD para consultas dnssec. Este bit indica que el llamador está interesado en el bit AD (datos auténticos) devuelto, pero no requiere que se incluyan RRs dnssec en la respuesta. El valor predeterminado es falso.

cdflag

$resolver->dnssec(1);
$resolver->cdflag(1);
print "bandera de verificación deshabilitada: ", $resolver->cdflag, "\n";

Obtiene o establece el bit CD para consultas dnssec. Este bit indica que se debe suprimir la autenticación por parte de los servidores de nombres superiores. Se deben incluir en la respuesta los RRs dnssec necesarios para ejecutar el procedimiento de autenticación. El valor predeterminado es falso.

tsig

$resolver->tsig( $keyfile );
$resolver->tsig( $keyfile, fudge => 60 );
$resolver->tsig( undef );

Establece el registro TSIG utilizado para firmar automáticamente las consultas salientes, transferencias de zona y actualizaciones. La firma automática se deshabilita si se llama con argumentos indefinidos.

El comportamiento predeterminado del resolvedor es no firmar ningún paquete. Debe llamar a este método para establecer la clave si desea que el resolvedor firme y verifique los paquetes automáticamente.

Los paquetes también se pueden firmar manualmente; consulte las páginas del manual de Net::DNS::Packet y Net::DNS::Update para ver ejemplos. Los registros TSIG en paquetes firmados manualmente tienen prioridad sobre los que el resolvedor agregaría automáticamente.

AMBIENTE

Las siguientes variables de entorno también se pueden utilizar para configurar el resolvedor:

RES_NAMESERVERS

# Bourne Shell
RES_NAMESERVERS="2001:DB8::1 192.0.2.1"
export RES_NAMESERVERS
# C Shell
setenv RES_NAMESERVERS "2001:DB8::1 192.0.2.1"

Una lista separada por espacios de servidores de nombres para consultar.

RES_SEARCHLIST

# Bourne Shell
RES_SEARCHLIST="a.example.com b.example.com c.example.com"
export RES_SEARCHLIST
# C Shell
setenv RES_SEARCHLIST "a.example.com b.example.com c.example.com"

Una lista separada por espacios de dominios para incluir en la lista de búsqueda.

LOCALDOMAIN

# Bourne Shell
LOCALDOMAIN=example.com
export LOCALDOMAIN
# C Shell
setenv LOCALDOMAIN example.com

El dominio predeterminado.

RES_OPTIONS

# Bourne Shell
RES_OPTIONS="retrans:3 retry:2 inet6"
export RES_OPTIONS
# C Shell
setenv RES_OPTIONS "retrans:3 retry:2 inet6"

Una lista separada por espacios de opciones del resolvedor para establecer. Las opciones que toman valores se especifican como "opción:valor".

TRANSPORTE IPV4

Los métodos force_v4(), force_v6(), prefer_v4() y prefer_v6() con un argumento distinto de cero pueden usarse para configurar la selección del transporte.

El comportamiento del método nameserver() ilustra el mecanismo de selección del transporte. Si, por ejemplo, se ha forzado el transporte IPv4, el método nameserver() solo devolverá direcciones IPv4:

$resolver->nameservers( '192.0.2.1', '192.0.2.2', '2001:DB8::3' );
$resolver->force_v4(1);
print join ' ', $resolver->nameservers();

imprimirá

192.0.2.1 192.0.2.2

RESOLVEDORES PERSONALIZADOS

Net::DNS::Resolver es en realidad una subclase vacía. En tiempo de compilación se elige una superclase basada en la plataforma actual. Un beneficio secundario de esto permite la fácil modificación de los métodos en Net::DNS::Resolver. Simplemente puede agregar un método al espacio de nombres.

Por ejemplo, si quisiéramos almacenar en caché las búsquedas:

package Net::DNS::Resolver;
my %cache;
sub send {
        my ( $self, @q ) = @_;
        return $cache{"@q"} ||= $self->SUPER::send(@q);
}
