Net::IDN::Encode(3) Documentación de Perl aportada por el usuario Net::IDN::Encode(3)

NOMBRE

Net::IDN::Encode - Internacionalización de nombres de dominio en aplicaciones (IDNA)

SINOPSIS

use Net::IDN::Encode ':all';
my $a = domain_to_ascii("müller.example.org");
my $e = email_to_ascii("POSTMASTER@例。テスト");
my $u = domain_to_unicode('EXAMPLE.XN--11B5BS3A9AJ6G');

DESCRIPCIÓN

Este módulo proporciona una interfaz fácil de usar para codificar y decodificar nombres de dominio internacionalizados (IDN).

Los IDN utilizan caracteres extraídos de un gran repertorio (Unicode), pero IDNA permite que los caracteres no ASCII se representen utilizando solo los caracteres ASCII que ya están permitidos en los llamados nombres de host actuales ("/[A-Z0-9-]/i").

Utilice este módulo si solo desea convertir nombres de dominio (o direcciones de correo electrónico), utilizando el estándar IDNA que sea la mejor opción en este momento.

Debe estar familiarizado con el soporte de Unicode en Perl, ya que este módulo espera una entrada codificada correctamente. Consulte perlunitut, perluniintro y perlunicode para obtener más detalles.

VERSIÓN UNICODE

Para convertir etiquetas correctamente entre Unicode y ASCII, cada carácter de la etiqueta debe estar presente en la versión de Unicode admitida por su Perl. En consecuencia, este módulo se negará a convertir etiquetas con nuevos caracteres Unicode en versiones de Perl antiguas (ver más abajo).

FUNCIONES

Por defecto, este módulo no exporta ninguna subrutina. Puede usar la etiqueta ":all" para importar todo. También puede usar expresiones regulares como "/^to_/" o "/^email_/" para seleccionar algunas de las funciones, consulte Exporter para obtener más detalles.

Las siguientes funciones están disponibles:

to_ascii( $etiqueta, %param )
Convierte una sola etiqueta $etiqueta a ASCII. Lanzará una excepción ante una entrada inválida. Si $etiqueta ya es una etiqueta de dominio ASCII válida (incluidas la mayoría de las etiquetas NO LDH como las utilizadas para registros SRV y etiquetas A falsas), esta función nunca fallará sino que devolverá $etiqueta tal cual si la conversión fallara.

Esta función toma los siguientes parámetros opcionales (%param):

AllowUnassigned
(booleano) Si se establece en un valor verdadero, se permiten los puntos de código que no están asignados en la versión de Unicode admitida por su Perl. Esta es una extensión sobre UTS #46.

Si bien esto aumenta el número de etiquetas que se pueden convertir correctamente (especialmente en versiones de Perl antiguas) y puede, por lo tanto, maximizar la compatibilidad con los nombres de dominio creados bajo futuras versiones de Unicode, también introduce el riesgo de conversiones incorrectas. Los caracteres añadidos en versiones posteriores de Unicode podrían tener propiedades que afecten la conversión; si estas propiedades no se conocen en su versión de Perl, es posible que termine con una conversión incorrecta.

El valor predeterminado es falso.

UseSTD3ASCIIRules
(booleano) Si se establece en un valor verdadero, verifica que la etiqueta cumpla con la sintaxis STD 3 (RFC 1123) para las partes del nombre de host. Las comprobaciones exactas realizadas dependen del estándar IDNA utilizado. Por lo general, querrá establecer esto en verdadero.

Tenga en cuenta que UseSTD3ASCIIRules solo afecta la conversión entre etiquetas ASCII (etiquetas A) y etiquetas Unicode (etiquetas U). Las etiquetas que están en ASCII aún pueden pasarse tal cual.

Por razones históricas, el valor predeterminado es falso (a diferencia de "domain_to_ascii").

TransitionalProcessing
(booleano) Si se establece en verdadero, la conversión será compatible con IDNA2003. Esto solo afecta a cuatro caracteres: 'ß' (U+00DF), 'ς' (U+03C2), ZWJ (U+200D) y ZWNJ (U+200C). Por lo general, querrá establecer esto en falso.

El valor predeterminado es falso.

Esta función no maneja cadenas que consisten en múltiples etiquetas (como los nombres de dominio). Utilice "domain_to_ascii" en su lugar.

to_unicode( $etiqueta, %param )
Convierte una sola etiqueta $etiqueta a Unicode. Lanzará una excepción ante una entrada inválida. Si $etiqueta es una etiqueta ASCII (incluidas la mayoría de las etiquetas NO LDH como las utilizadas para registros SRV), esta función no fallará sino que devolverá $etiqueta tal cual si la conversión fallara.

Esta función toma los mismos parámetros opcionales que "to_ascii", con los mismos valores predeterminados.

Si $etiqueta ya está en ASCII, esta función nunca fallará sino que devolverá $etiqueta tal cual como último recurso (es decir, paso directo).

Esta función toma los siguientes parámetros opcionales (%param):

AllowUnassigned
UseSTD3ASCIIRules
Ver "to_unicode" arriba. Tenga en cuenta que no hay necesidad de "TransitionalProcessing" para "to_unicode".

Esta función no maneja cadenas que consisten en múltiples etiquetas (como los nombres de dominio). Utilice "domain_to_unicode" en su lugar.

domain_to_ascii( $etiqueta, %param )
Convierte todas las etiquetas del nombre de host $dominio (con etiquetas separadas por puntos) a ASCII (usando "to_ascii"). Lanzará una excepción ante una entrada inválida.

Esta función toma los siguientes parámetros opcionales (%param):

AllowUnassigned
TransitionalProcessing
Ver "to_unicode" arriba.
UseSTD3ASCIIRules
(booleano) Si se establece en un valor verdadero, verifica que la etiqueta cumpla con la sintaxis STD 3 (RFC 1123) para las partes del nombre de host.

El valor predeterminado es verdadero (a diferencia de "to_ascii").

Esta función convertirá todos los puntos a ASCII, es decir, a U+002E (punto). Los siguientes caracteres se reconocen como puntos: U+002E (punto), U+3002 (punto ideográfico), U+FF0E (punto de ancho completo), U+FF61 (punto ideográfico de medio ancho).

domain_to_unicode( $dominio, %param )
Convierte todas las etiquetas del nombre de host $dominio (con etiquetas separadas por puntos) a Unicode. Lanzará una excepción ante una entrada inválida.

Esta función toma los mismos parámetros opcionales que "domain_to_ascii", con los mismos valores predeterminados.

Esta función toma los siguientes parámetros opcionales (%param):

AllowUnassigned
UseSTD3ASCIIRules
Ver "domain_to_unicode" arriba. Tenga en cuenta que no hay "TransitionalProcessing" para "domain_to_unicode".

FUNCTIONS

This function will preserve the original version of dots. The following characters are recognized as dots: U+002E (full stop), U+3002 (ideographic full stop), U+FF0E (fullwidth full stop), U+FF61 (halfwidth ideographic full stop).

email_to_ascii( $email, %param )
Convierte la parte del dominio (lado derecho, separada por una arroba) de una dirección de correo electrónico RFC 2821/2822 a ASCII, usando "domain_to_ascii". Puede lanzar una excepción ante una entrada inválida.

Toma los mismos parámetros que "domain_to_ascii".

Esta función actualmente no maneja la internacionalización de la parte local (lado izquierdo). Las versiones futuras de este módulo podrían implementar una conversión ASCII para la parte local, si alguna se estandariza.

Esta función convertirá la arroba a ASCII, es decir, a U+0040 (arroba comercial), así como los separadores de etiquetas. Los siguientes caracteres son reconocidos como arrobas: U+0040 (arroba comercial), U+FE6B (arroba comercial pequeña) y U+FF20 (arroba comercial de ancho completo).

email_to_unicode( $email, %param )
Convierte la parte del dominio (lado derecho, separada por una arroba) de una dirección de correo electrónico RFC 2821/2822 a Unicode, usando "domain_to_unicode". Puede lanzar una excepción ante una entrada inválida.

Toma los mismos parámetros que "domain_to_unicode".

Esta función actualmente no maneja la internacionalización de la parte local (lado izquierdo). Las versiones futuras de este módulo podrían implementar una conversión desde ASCII para la parte local, si alguna se estandariza.

Esta función preservará la versión original de las arrobas (y los separadores de etiquetas). Los siguientes caracteres son reconocidos como arrobas: U+0040 (arroba comercial), U+FE6B (arroba comercial pequeña) y U+FF20 (arroba comercial de ancho completo).
