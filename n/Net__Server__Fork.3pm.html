NOMBRE

Net::Server::Fork - Personalidad de Net::Server

SINOPSIS

use base qw(Net::Server::Fork);
sub process_request {
    #...código...
}
__PACKAGE__->run();

DESCRIPCIÓN

Por favor, lee la documentación de Net::Server primero. Este módulo es una personalidad, o extensión, o subclase, del módulo Net::Server.

Esta personalidad se enlaza a uno o más puertos y luego espera una conexión de cliente. Cuando se recibe una conexión, el servidor crea un proceso hijo (fork). El hijo maneja la solicitud y luego se cierra.

Con la excepción de la señalización entre padre/hijo, este módulo funcionará (con funcionalidad básica) en sistemas Win32.

ARGUMENTOS

check_for_dead
Número de segundos a esperar antes de buscar procesos hijos muertos. Esto solo ocurre si se ha alcanzado el número máximo de procesos hijos (max_servers). El valor predeterminado es 60 segundos.
max_servers
El número máximo de procesos hijos a crear. El servidor no aceptará conexiones hasta que haya procesos hijos libres. El valor predeterminado es 256 procesos.
max_dequeue
El número máximo de procesos de desencolado a iniciar. Si se da un valor de cero o indefinido, no se iniciarán procesos de desencolado. El número de procesos de desencolado en ejecución se verificará mediante la variable check_for_dead.
check_for_dequeue
Segundos a esperar antes de crear un proceso de desencolado. Está previsto utilizar el proceso de desencolado para gestionar elementos como colas de correo. Si se da un valor indefinido, no se iniciarán procesos de desencolado.

ARCHIVO DE CONFIGURACIÓN

Ver Net::Server.

FLUJO DEL PROCESO

El flujo del proceso sigue a Net::Server hasta la fase post_accept. En este punto se crea un proceso hijo. El proceso padre está inmediatamente disponible para esperar otra solicitud. El proceso hijo maneja la solicitud y luego sale.

GANCHOS

El servidor Fork tiene los siguientes ganchos además de los ganchos proporcionados por la clase base Net::Server. Ver Net::Server

"$self->pre_accept_hook()"
Este gancho ocurre justo antes de llamar a accept.
"$self->post_accept_hook()"
Este gancho ocurre en el proceso hijo después de accept y fork.
"$self->run_dequeue()"
Este gancho solo se llama en conjunto con la configuración check_for_dequeue.

DESPLIEGUE EN CALIENTE

Desde la versión 2.000, el servidor Fork ha aceptado las señales TTIN y TTOU. Cuando se recibe una TTIN, max_servers se incrementa en 1. Si se recibe una señal TTOU, max_servers se decrementa en 1. Esto permite ajustar el número de procesos de manejo sin tener que reiniciar el servidor.
