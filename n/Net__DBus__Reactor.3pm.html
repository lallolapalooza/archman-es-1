Net::DBus::Reactor(3) Documentación Perl contribuida por el usuario Net::DBus::Reactor(3)

NOMBRE

Net::DBus::Reactor - bucle de eventos de la aplicación

SINOPSIS

Crear y ejecutar un bucle de eventos:

use Net::DBus::Reactor;
my $reactor = Net::DBus::Reactor->main();
$reactor->run();

Gestionar algunos manejadores de archivos

$reactor->add_read($fd,
                   Net::DBus::Callback->new(method => sub {
                      my $fd = shift;
                      ...leer algunos datos...
                   }, args => [$fd]));
$reactor->add_write($fd,
                    Net::DBus::Callback->new(method => sub {
                       my $fd = shift;
                       ...escribir algunos datos...
                    }, args => [$fd]));

Habilitar/deshabilitar temporalmente un manejador

# Deshabilitar
$reactor->toggle_read($fd, 0);
# Habilitar
$reactor->toggle_read($fd, 1);

Eliminar permanentemente un manejador

$reactor->remove_read($fd);

Gestionar un tiempo de espera regular cada 100 milisegundos

my $timer = $reactor->add_timeout(100,
                                  Net::DBus::Callback->new(
           method => sub {
              ...procesar la alarma...
           }));

Habilitar/deshabilitar temporalmente un temporizador

# Deshabilitar
$reactor->toggle_timeout($timer, 0);
# Habilitar
$reactor->toggle_timeout($timer, 1);

Eliminar permanentemente un temporizador

$reactor->remove_timeout($timer);

Añadir un hook posterior al dispatch

my $hook = $reactor->add_hook(Net::DBus::Callback->new(
      method => sub {
         ...hacer algo de trabajo...
      }));

Eliminar un hook

$reactor->remove_hook($hook);

DESCRIPCIÓN

Esta clase proporciona un bucle de eventos de propósito general para la multiplexación de eventos de E/S y tiempos de espera en un solo proceso. La implementación subyacente se realiza utilizando la llamada al sistema select. Se pueden registrar manejadores de archivos para su monitorización en eventos de lectura, escritura y excepción (datos fuera de banda). Se pueden registrar temporizadores para que expiren con una frecuencia periódica. Estos se implementan utilizando el parámetro de tiempo de espera de la llamada al sistema select. Dado que este parámetro simplemente representa un límite superior en la cantidad de tiempo que la llamada al sistema select puede dormir, el período real de los temporizadores puede variar. Bajo carga normal, esta variación suele ser de 10 milisegundos. Finalmente, se pueden registrar hooks que se invocarán en cada iteración del bucle de eventos (es decir, después de procesar los eventos de archivo, o los tiempos de espera indicados por el retorno de la llamada al sistema select).

MÉTODOS

my $reactor = Net::DBus::Reactor->new();
Crea un nuevo bucle de eventos listo para monitorizar manejadores de archivos o generar tiempos de espera. Excepto en circunstancias muy inusuales (de las que no se me ocurren ejemplos), no es necesario ni deseable crear instancias de reactor explícitamente. En su lugar, llame al método main para obtener un manejador de la instancia singleton.
$reactor = Net::DBus::Reactor->main;
Devuelve un manejador a la instancia singleton del reactor. Esta es la forma recomendada de obtener un reactor, ya que elimina la necesidad de que los módulos pasen manejadores a sus reactores creados privadamente.
$reactor->manage($connection);
$reactor->manage($server);
Registra un objeto de "Net::DBus::Binding::Connection" o "Net::DBus::Binding::Server" para su gestión por el bucle de eventos. Esto básicamente implica conectar las callbacks de watch y timeout al bucle de eventos. Para las conexiones, también registrará un hook para invocar el método "dispatch" periódicamente.
$reactor->run();
Inicia el bucle de eventos monitorizando los manejadores de archivos y tiempos de espera registrados. Debe haberse registrado al menos un manejador de archivo o un temporizador antes de ejecutar el reactor, de lo contrario, saldrá inmediatamente. El reactor se ejecutará hasta que se eliminen o deshabiliten todos los manejadores de archivos o tiempos de espera registrados. El reactor se puede detener explícitamente llamando al método "shutdown".
$reactor->shutdown();
Apaga explícitamente el reactor después de que se hayan procesado los eventos pendientes.
$reactor->step();
Realiza una iteración del bucle de eventos, yendo a dormir hasta que ocurra un evento en un manejador de archivo registrado, o ocurra un tiempo de espera. Este método generalmente no es necesario en el uso diario.
$reactor->add_read($fd, $callback[, $status]);
Registra un manejador de archivo para monitorizar eventos de lectura. El parámetro $callback especifica una referencia de código a una subrutina, o una instancia del objeto "Net::DBus::Callback" para invocar cada vez que ocurre un evento. El parámetro opcional $status es un valor booleano para especificar si el watch está inicialmente habilitado.
$reactor->add_write($fd, $callback[, $status]);
Registra un manejador de archivo para monitorizar eventos de escritura. El parámetro $callback especifica una referencia de código a una subrutina, o una instancia del objeto "Net::DBus::Callback" para invocar cada vez que ocurre un evento. El parámetro opcional $status es un valor booleano para especificar si el watch está inicialmente habilitado.
$reactor->add_exception($fd, $callback[, $status]);
Registra un manejador de archivo para monitorizar eventos de excepción. El parámetro $callback especifica una referencia de código a una subrutina, o una instancia del objeto "Net::DBus::Callback" para invocar cada vez que ocurre un evento. El parámetro opcional $status es un valor booleano para especificar si el watch está inicialmente habilitado.
my $id = $reactor->add_timeout($interval, $callback, $status);
Registra un nuevo tiempo de espera para que expire cada $interval milisegundos. El parámetro $callback especifica una referencia de código a una subrutina, o una instancia del objeto "Net::DBus::Callback" para invocar cada vez que el tiempo de espera expira. El parámetro opcional $status es un valor booleano para especificar si el tiempo de espera está inicialmente habilitado. El parámetro de retorno es un identificador único que se puede usar para eliminar o deshabilitar el tiempo de espera más tarde.
$reactor->remove_timeout($id);
Elimina un tiempo de espera registrado previamente especificado por el parámetro $id.
$reactor->toggle_timeout($id, $status[, $interval]);
Actualiza el estado de un tiempo de espera registrado previamente especificado por el parámetro $id. El parámetro $status especifica si el tiempo de espera debe habilitarse o deshabilitarse, mientras que el parámetro opcional $interval se puede usar para cambiar el período del tiempo de espera.
my $id = $reactor->add_hook($callback[, $status]);
Registra un nuevo hook para que se dispare en cada iteración del bucle de eventos. El parámetro $callback especifica una referencia de código a una subrutina, o una instancia de la clase "Net::DBus::Callback" para invocar. El parámetro $status determina si el hook está inicialmente habilitado o deshabilitado. El parámetro de retorno es un id único que debe usarse para eliminar o deshabilitar el hook más tarde.
$reactor->remove_hook($id)
Elimina el hook registrado previamente identificado por $id.
$reactor->toggle_hook($id, $status)
Actualiza el estado del hook registrado previamente identificado por $id. El parámetro $status determina si el hook debe habilitarse o deshabilitarse.
$reactor->remove_read($fd);
$reactor->remove_write($fd);
$reactor->remove_exception($fd);
Elimina un watch en el manejador de archivo $fd.
$reactor->toggle_read($fd, $status);
$reactor->toggle_write($fd, $status);
$reactor->toggle_exception($fd, $status);
Actualiza el estado de un watch en el manejador de archivo $fd. El parámetro $status especifica si el watch debe habilitarse o deshabilitarse.

VER TAMBIÉN
