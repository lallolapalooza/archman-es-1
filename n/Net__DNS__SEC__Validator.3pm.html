NOMBRE

Net::DNS::SEC::Validator - interfaz para libval(3) y constantes, estructuras y funciones relacionadas

SINOPSIS

use Net::DNS::SEC::Validator;
use Net::DNS::Packet;
use Net::hostent;
use Net::addrinfo;
use Socket qw(:all);
sub callback {
}
my $validator = new Net::DNS::SEC::Validator(policy => ":");
$validator.map_ns("dnssec-tools.org", "127.0.0.1");
my (@r) = $validator->getaddrinfo("good-A.test.dnssec-tools.org");
my $r = $validator->res_query("dnssec-tools.org", "IN", "MX");
my $h = $validator->gethostbyname("good-AAAA.test.dnssec-tools.org",
                                  AF_INET6);
$validator->async_submit("badsign-a.test.dnssec-tools.org", 
      "IN", "A", 0, \&callback, undef);
do {
  my $ref = $val->async_gather($readfds, $timeout);
  my $ret = $ref->[0];
  my $readfds = $ref->[1];
  my $timeout = $ref->[2];
  if (! @$readfds) {
      last;
  }
  my @readyarr = IO::Select->new(@$readfds)->can_read($timeout);
  $ret = $validator->async_check(\@readyarr);
} while(1);

DESCRIPCIÓN

El módulo Validator proporciona acceso a la biblioteca del resolutor de validación libval(3) y sus constantes, estructuras y funciones asociadas. Las funciones de la biblioteca se acceden a través de una interfaz orientada a objetos. La interfaz está diseñada para ocultar parte de la complejidad de los resolutores de validación. El comportamiento de la interfaz de aplicación se puede personalizar a través de archivos de configuración proporcionados por libval, y se devuelven códigos de error extensos.

Dado que Validator es una puerta de enlace a libval, la documentación de libval proporcionará más detalles sobre cómo se pueden utilizar las interfaces y los parámetros de Validator.

Los detalles de DNSSEC y el comportamiento asociado del resolutor se pueden encontrar en los RFC principales de DNSSEC (4033-4035).

INTERFAZ

Este módulo soporta búsquedas tanto síncronas como asíncronas. A continuación se describe la API.

Constructor Validator

Este constructor crea un nuevo objeto validador, que se utiliza para realizar las diversas llamadas al resolutor. Cuando se crea el objeto validador, se crea un objeto de *política*. El objeto de *política* proporciona una serie de configuraciones que controlarán varios aspectos de la resolución de DNS.

Para crear un objeto validador, use el método Net::DNS::SEC::Validator-new()>. Este método toma una serie de parámetros opcionales, que se describirán a continuación.

Una política puede nombrarse con el parámetro *policy*, que asocia una etiqueta con una política particular. Esto permite que esa política se referencie más adelante. Si no se especifica la etiqueta, se le asignará la etiqueta predeterminada del archivo dnsval.conf de libval.

Los parámetros del constructor se pasan como un hash, con la clave y el valor dados en la llamada. Además de la etiqueta de política, hay dos conjuntos de parámetros del constructor. Estos se separan según cómo se almacenan y utilizan en libval.

Opciones de contexto

Este grupo de parámetros se almacena en una estructura *val_context_opt* en libval. Esta estructura se define en dnssec/validator/include/validator/validator.h. Las opciones de contexto a continuación son los valores de clave de hash utilizados en la llamada al constructor.

dnsval_conf
Política de configuración para la biblioteca libval.

Este archivo contiene la política del validador. El valor predeterminado es /usr/local/etc/dnssec-tools/dnsval.conf, pero esto puede haber cambiado cuando se compiló e instaló libval.

Campo de *val_context_opt*: vc_val_conf

nslist
Esta es una lista de servidores de nombres que se deben utilizar para resolver nombres. Debe ser una lista delimitada por espacios en blanco de direcciones IP o IPv6.

Campo de *val_context_opt*: vc_nslist

polflags
Este es un conjunto de indicadores de política mapeados en bits. Los indicadores válidos se definen en dnssec/validator/include/validator/validator.h. El valor predeterminado es CTX_DYN_POL_RES_OVR.

Campo de *val_context_opt*: vc_polflags

qflags
Este es el conjunto de indicadores de consulta predeterminados. Los indicadores válidos se definen en dnssec/validator/include/validator/validator.h. El valor predeterminado es 0.

Campo de *val_context_opt*: vc_qflags

resolv_conf
Este archivo contiene opciones de servidores de nombres y de búsqueda para la biblioteca libval. El valor predeterminado es /usr/local/etc/dnssec-tools/resolv.conf, pero esto puede haber cambiado cuando se compiló e instaló libval.

Campo de *val_context_opt*: vc_res_conf

root_hints
Este archivo contiene información de arranque para el resolutor de nombres. El valor predeterminado es /usr/local/etc/dnssec-tools/root.hints, pero esto puede haber cambiado cuando se compiló e instaló libval.

Campo de *val_context_opt*: vc_root_conf

valpol
Esto proporciona una parte personalizada de la configuración del validador a la configuración predeterminada del validador como una extensión o una anulación. Esto es nulo por defecto.

Campo de *val_context_opt*: vc_valpol

Opciones globales

Este grupo de parámetros se almacena en una estructura *val_global_opt*, que a su vez se almacena en el campo *gopt* de la estructura *val_context_opt*. Esta estructura se define en dnssec/validator/include/validator/validator.h. Las opciones globales a continuación son los valores de clave de hash utilizados en la llamada al constructor.

Para todos los campos excepto *log_target*, un valor de -1 indica una condición de "ignorar". Esto significa que el validador no incluirá las opciones globales suministradas dinámicamente con un valor de -1 al crear su contexto. Esto permite que una aplicación anule un subconjunto de opciones globales mientras utiliza las opciones globales suministradas en el archivo dnsval.conf por defecto.

Aunque libval utiliza las opciones globales en una estructura separada de las opciones de contexto, todas se especifican en el mismo hash cuando se pasan como parámetros al constructor de Validator.

app_policy
Este campo es equivalente a la opción *env-policy* en un archivo dnsval.conf. Los siguientes son los valores legales y sus equivalencias *env-policy*: 
VAL_POL_GOPT_DISABLE       "disable"
VAL_POL_GOPT_ENABLE        "enable"
VAL_POL_GOPT_OVERRIDE      "override"

El valor predeterminado es -1.

Campo de *val_global_opt*: gopt.app_policy

closest_ta_only
Este campo es equivalente a la opción *closest-ta-only* en un archivo dnsval.conf. Establecer esto a 1 es equivalente a establecer *closest-ta-only* a "yes"; establecerlo a 0 es equivalente a "no". El valor predeterminado es -1.

Campo de *val_global_opt*: gopt.closest_ta_only

edns0_size
Este campo es equivalente a la opción *edns0-size* en un archivo dnsval.conf. El valor predeterminado es -1.

Campo de *val_global_opt*: gopt.edns0_size

env_policy
Este campo es equivalente a la opción *env-policy* en un archivo dnsval.conf. Los siguientes son los valores legales y sus equivalencias *env-policy*: 
VAL_POL_GOPT_DISABLE       "disable"
VAL_POL_GOPT_ENABLE        "enable"
VAL_POL_GOPT_OVERRIDE      "override"

El valor predeterminado es -1.

Campo de *val_global_opt*: gopt.env_policy

local_is_trusted
Este campo es equivalente a la opción *trust-oob-answers* en un archivo dnsval.conf. Establecer esto a 1 es equivalente
log_target
Este campo permite al llamante especificar targets de registro adicionales que se encuentran en el archivo dnsval.conf. Por defecto, no se listan otros targets de registro.

Campo de val_global_opt: gopt.log_target

rec_fallback
Este campo es equivalente a la opción rec-fallback en un archivo dnsval.conf. Establecer este a 1 es equivalente a establecer rec-fallback a "yes"; establecerlo a 0 es equivalente a "no". El valor por defecto es -1.

Campo de val_global_opt: gopt.rec_fallback

max_refresh
Este campo es equivalente a la opción max-refresh en un archivo dnsval.conf.

Campo de val_global_opt: gopt.max_refresh

proto
Este campo es equivalente a la opción proto en un archivo dnsval.conf. Establecer este valor a 1 es equivalente a establecer proto a "ipv4"; establecer este valor a 2 es equivalente a establecer proto a "ipv6". El valor por defecto es 0, equivalente a establecer proto a "any".

Campo de val_global_opt: gopt.proto

timeout
Este campo es equivalente a la opción timeout en un archivo dnsval.conf.

Campo de val_global_opt: gopt.timeout

retry
Este campo es equivalente a la opción retry en un archivo dnsval.conf.

Campo de val_global_opt: gopt.retry

Campos de resultado del validador

El estado de la operación y los resultados se encuentran en los siguientes campos de resultado del validador:

$validator->{error}        => el código de error de la última llamada
$validator->{errorStr}     => la cadena de error de la última llamada
$validator->{valStatus}    => el val_status de la última llamada (si es una sola llamada)
$validator->{valStatusStr} => la cadena val_status de la última llamada

Los valores para estos campos se describen en la sección siguiente.

$validator->getaddrinfo(<name>[,<service>[,<hints>]])

donde:

<name> => es el nombre del nodo o la dirección numérica que se está consultando
<service> => es el nombre o el número que representa el servicio
(por favor notar: <name> o <service> puede ser indefinido, pero no ambos)
<hint> => un objeto Net::addrinfo que especifica los flags, la familia, etc.

devuelve:

Un array de objetos Net::addrinfo (con un campo 'val_status') en caso de éxito. En caso de error, devuelve un array vacío. En contexto escalar, devuelve el primer objeto Net::addrinfo, o undef en caso de error.

$validator->gethostbyname(<name>[,<family>])

donde:

<name> => es el nombre del nodo o la dirección numérica que se está consultando
<family> => la familia de dirección del registro devuelto (por defecto: AF_INET)

devuelve:

Un objeto Net::hostent. Los campos valStatus/valStatusStr del validador se actualizarán. En caso de error, se devuelve undef y los campos del objeto validador se actualizan.

$validator->res_query(<name>[,<class>[,<type>]])

donde:

<name>      => es el nombre del nodo o la dirección numérica que se está consultando
<class>     => es la clase DNS del registro que se está consultando (por defecto: IN)
<type>      => es el tipo de registro DNS que se está consultando (por defecto: A)

devuelve:

Un resultado de consulta DNS empaquetado se devuelve en caso de éxito. Este objeto es adecuado para pasar a la interfaz Net::DNS::Packet(\$result) para su análisis. Los campos valStatus/valStatusStr del validador se actualizarán. En caso de error, se devuelve undef y los campos del objeto validador se actualizan.

$validator->policy([<label>])

donde:

<label>     => la etiqueta de política a utilizar (el contexto anterior se destruye)
(por defecto: ": " política por defecto de dnsval.conf)

devuelve:

La etiqueta de política actual (después del cambio).

$validator->istrusted([<val_status>])

donde:

<val_status> => el código numérico del estado del validador
(por defecto: $validator->{valStatus})

devuelve:

Un valor booleano positivo si <val_status> es un resultado confiable.

$validator->valStatusStr([<val_status>])

donde:

<val_status> => el código numérico del estado del validador
(por defecto: $validator->{valStatus})

devuelve:

Una representación textual del valor dado <val_status>.

$validator->map_ns(<zone>, <ipaddr>, <recursive>)

donde:

<zone> => el valor de la zona
<ipaddr> => la dirección IP a la que deben dirigirse todas las consultas asociadas con la "zona" anterior.
<recursive> => si se establece a 1, este servidor de nombres se considera recursivo (se envían consultas con el bit RD establecido). El valor por defecto es considerar a este servidor de nombres como autoritativo.

devuelve:

0 si se puede hacer la asociación entre la zona y la dirección IP con éxito; otro valor si no se puede crear la asociación.

CAMPOS DE DATOS DEL VALIDADOR

Los campos error y errorStr del validador se establecen con valores correspondientes a los de las funciones estándar herror() y hstrerror() de netdb.h. Estos valores se definen en netdb.h. Estos valores son:

error      errorStr
  0        Resolver Error 0 (sin error)
  1        Host no encontrado
  2        Error de búsqueda de nombre de host
  3        Error de servidor de error
  4        No hay dirección asociada al nombre

Los valores del campo valStatus del validador se definen en .../dnssec-tools/validator/include/validator/val_errors.h. Los valores de los campos valStatusStr se representan textualmente como los valores de las constantes de valStatus. Los valores posibles para valStatus se muestran a continuación, y más detalles se encuentran en libval(3):

VAL_BARE_RRSIG
VAL_INDETERMINATE
VAL_BOGUS
VAL_DNS_ERROR
VAL_IGNORE_VALIDATION
VAL_NONEXISTENT_NAME
VAL_NONEXISTENT_NAME_NOCHAIN
VAL_NONEXISTENT_TYPE
VAL_NONEXISTENT_TYPE_NOCHAIN
VAL_NOTRUST
VAL_OOB_ANSWER
VAL_PINSECURE
VAL_PINSECURE_UNTRUSTED
VAL_SUCCESS
VAL_TRUSTED_ANSWER
VAL_UNTRUSTED_ANSWER
VAL_UNTRUSTED_ZONE
VAL_VALIDATED_ANSWER

Las funciones istrusted() y isvalidated() se pueden utilizar para probar si un valor particular de valStatus corresponde a un estado confiable o validado. Los valores que no son confiables o validados deben tratarse como no confiables por la aplicación.

EJEMPLOS

  use Net::DNS::SEC::Validator;
  use Net::DNS::Packet;
  use Net::hostent;
  use Net::addrinfo;
  use Socket qw(:all);

  # construir objeto
  my $validator = new Net::DNS::SEC::Validator(policy => ":");

  # cambiar la política de validación
  $validator->policy("validate_tools:");

  # obtener array de Net::addrinfo
  my (@r) = $validator->getaddrinfo("good-A.test.dnssec-tools.org");
  foreach $a (@r) {
     print $a->stringify, " is trusted\n"
        if $validator->istrusted($a->val_status));
  }

  # consultar un registro MX
  my $r = $validator->res_query("dnssec-tools.org", "IN", "MX");
  my ($pkt, $err) = new Net::DNS::Packet(\$r);
  print ($validator->istrusted ?
        "result is trusted\n" :
        "result is NOT trusted\n");

  my $h = $validator->gethostbyname("good-A.test.dnssec-tools.org");
  if ( @{$h->addr_list}) {
  my $i;
     for $addr ( @{$h->addr_list} ) {
        printf "\taddr #%d is [%s]\n", $i++, inet_ntoa($addr);
     }
  }
  # obtener detalles de validación
  my $a = $validator->resolve_and_check("good-a.test.dnssec-tools.org", "IN", "A", 0);
  foreach my $h (@$a) {
   print "Status: " .  ${$h}{status} . "\n";
   print ($validator->istrusted(${$h}{status}) ?
           "result is trusted\n" :
           "result is NOT trusted\n");
   $acs = ${$h}{answer};
   foreach my $ac ($acs) {
        print "AC status: " . ${$ac}{status} . "\n";
        $acr = ${$ac}{rrset};
        $acd = ${$acr}{data};
        foreach $d (@$acd) {
            print "Data RR status: " . ${$d}{rrstatus} . "\n";
            ${$d}{rrdata}->print;
        }
        $acs = ${$acr}{sigs};
        foreach $d (@$acs) {
            print "Sig RR status: " . ${$d}{rrstatus} . "\n";
            ${$d}{rrdata}->print;
        }
   }
}
