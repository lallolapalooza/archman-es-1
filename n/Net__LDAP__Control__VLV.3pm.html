NAME

Net::LDAP::Control::VLV - Control de lista virtual de LDAP (v3)

SYNOPSIS

use Net::LDAP;
use Net::LDAP::Control::VLV;
use Net::LDAP::Constant qw( LDAP_CONTROL_VLVRESPONSE );
$ldap = Net::LDAP->new( "ldap.mydomain.eg" );
# Obtener los primeros 20 registros
$vlv  = Net::LDAP::Control::VLV->new(
          before  => 0,        # Número de registros antes del registro objetivo
          after   => 19,       # 19 registros después del registro objetivo
          content => 0,        # Tamaño del listado desconocido
          offset  => 1,        # El registro objetivo es el primero
        );
$sort = Net::LDAP::Control::Sort->new( order => 'cn' );
@args = ( base     => "o=Ace Industry, c=us",
          scope    => "subtree",
          filter   => "(objectClass=inetOrgPerson)",
          callback => \&process_entry, # Llama esta subrutina para cada registro
          control  => [ $vlv, $sort ],
);
$mesg = $ldap->search( @args );
# Obtener el control de respuesta VLV
($resp)  = $mesg->control( LDAP_CONTROL_VLVRESPONSE )  or die;
$vlv->response( $resp );
# Establecer el control para obtener los últimos 20 registros
$vlv->end;
$mesg = $ldap->search( @args );
# Obtener el control de respuesta VLV
($resp)  = $mesg->control( LDAP_CONTROL_VLVRESPONSE )  or die;
$vlv->response( $resp );
# Ahora obtener el anterior de la página
$vlv->scroll_page( -1 );
$mesg = $ldap->search( @args );
# Obtener el control de respuesta VLV
($resp)  = $mesg->control( LDAP_CONTROL_VLVRESPONSE )  or die;
$vlv->response( $resp );
# Ahora mostrar el primer registro comenzando con "B" en el medio
$vlv->before(9);       # Cambiar la página para mostrar 9 antes
$vlv->after(10);       # Cambiar la página para mostrar 10 después
$vlv->assert("B");     # Asertar "B"
$mesg = $ldap->search( @args );

DESCRIPCIÓN

"Net::LDAP::Control::VLV" proporciona una interfaz para la creación y manipulación de objetos que representan la lista virtual de LDAP como descrito en draft-ietf-ldapext-ldapv3-vlv-09.txt.

Cuando se utiliza un control de lista virtual de LDAP en una búsqueda, debe estar acompañado de un control de ordenación. Véase Net::LDAP::Control::Sort.

ARGS DE CONSTRUCTOR

Además de los argumentos de constructor descritos en Net::LDAP::Control, se proporcionan los siguientes.

after
Establece el número de registros que el servidor devolverá del listado después del registro objetivo.
assert
Establece el valor de asertación del usuario para localizar el registro objetivo. Este valor debe ser un valor legal para comparar con el primer atributo en el control de ordenación que se pasa con el control VLV. El registro objetivo es el primero en el listado que sea mayor o igual al valor de asertación.
before
Establece el número de registros que el servidor devolverá del listado antes del registro objetivo.
content
Establece el número de registros en el listado. En la primera búsqueda, este valor debe ser establecido a cero. En las búsquedas posteriores, debe ser establecido a la longitud del listado, como se devuelve por el control VLVResponse.
context
Establece el identificador de contexto. En la primera búsqueda, este valor debe ser establecido a cero. En las búsquedas posteriores, debe ser establecido a valor de contexto devuelto por el control VLVResponse.
offset
Establece el offset del registro objetivo.

MÉTODOS

Como con Net::LDAP::Control, cada argumento de constructor descrito anteriormente también está disponible como método en el objeto, que devolverá el valor actual de la propiedad si se llama sin argumento, y establecerá un nuevo valor para la propiedad si se le pasa un argumento.

Los atributos "offset" y "assert" son excluyentes. Establecer uno o el otro causará que los valores anteriores establecidos por el otro sean olvidados. El atributo "content" también está asociado al atributo "offset", por lo que establecer "assert" causará que cualquier valor de "content" sea olvidado.

end
Establece el registro objetivo a la última entrada del listado. Este método cambiará los atributos "before" y "after" de manera que el registro objetivo sea el último en la página.
response VLV_RESPONSE
Establece los atributos en el control según VLV_RESPONSE. VLV_RESPONSE debe ser un control de tipo Net::LDAP::Control::VLVResponse devuelto por el servidor. "response" llenará los atributos "context", "offset" y "content" del control con los valores de VLV_RESPONSE. Porque este establece el atributo "offset", cualquier anterior establecimiento del atributo "assert" será olvidado.
scroll NUM
Mueve el registro objetivo por NUM entradas. Un valor positivo moverá el registro objetivo hacia el final del listado, y un valor negativo hacia el inicio. Devuelve el índice del nuevo registro objetivo, o "undef" si el registro actual está identificado por un assert.

"scroll" puede cambiar los atributos "before" y "after" si el valor de scroll causaría que la página salga por un extremo del listado. Sin embargo, el tamaño de la página se mantendrá.

scroll_page NUM
Mueve la página por NUM páginas. Este método calcula el tamaño actual de la página y llama a "scroll" con "NUM * $page_size"
start
Establece el registro objetivo en el inicio del listado. Este método cambiará los atributos "before" y "after" de manera que el registro objetivo sea la primera entrada en la página.

Net::LDAP::Control::VLV(3pm)

SYNOPSIS

use Net::LDAP::Control::VLV;

my $vlv_control = Net::LDAP::Control::VLV->new(
    type       => 'VLV',
    value      => {
        after        => 10,
        before       => 10,
        contextCookie => $cookie,
        offset       => 0,
        target       => 'uid=testuser,dc=example,dc=com',
        type         => ' dn',
    },
);

$ldap->add_control($vlv_control);

DESCRIPTION

El módulo Net::LDAP::Control::VLV proporciona una interfaz para el control VLV (Virtual List View) del RFC 2647. Este control permite a los clientes solicitar subconjuntos específicos de resultados de búsqueda que pueden ser muy grandes. Esto es particularmente útil para las aplicaciones que necesitan mostrar datos en una lista de paginación, como una libreta de direcciones.

El control VLV se utiliza para solicitar una porción de una lista de resultados. El servidor mantiene el estado entre las solicitudes, y el cliente puede navegar por la lista hacia adelante y hacia atrás utilizando este control.

Los argumentos clave para el control VLV son:

  • offset: El índice del elemento deseado en la lista completa de resultados.
  • after: El número de elementos que se desean después del elemento especificado por offset.
  • before: El número de elementos que se desean antes del elemento especificado por offset.
  • target: Una cadena que especifica el elemento objetivo. Si type es dn, este debe ser el DN del elemento objetivo. Si type es index, este debe ser el índice del elemento objetivo.
  • type: El tipo de target. Puede ser dn o index.
  • contextCookie: Una cookie proporcionada por el servidor que identifica el contexto de la vista de lista virtual. Se utiliza para mantener el estado entre las solicitudes.

CONSTRUCTOR ARGUMENTS

El constructor new() para Net::LDAP::Control::VLV acepta los siguientes argumentos:

  • type: El tipo de control. Debe ser 'VLV'.
  • value: Un hash que contiene los parámetros para el control VLV. Los parámetros válidos son offset, after, before, target, type y contextCookie.
