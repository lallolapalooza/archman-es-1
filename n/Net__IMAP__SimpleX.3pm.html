NOMBRE

Net::IMAP::SimpleX - Complementos para Net::IMAP::Simple

SINOPSIS

use strict;
use warnings;
use Net::IMAP::SimpleX;

Net::IMAP::SimpleX utiliza Net::IMAP::Simple como base, por lo que la creación del objeto es la misma que para el antecesor:

my $imap = Net::IMAP::SimpleX->new('imap.example.com') ||
   die "No se pudo conectar a IMAP: $Net::IMAP::Simple::errstr\n";
$imap->select("INBOX");

Net::IMAP::SimpleX es una colección de métodos útiles que no son simples, requieren Parse::RecDescent o son experimentales.

DESCRIPCIÓN

Este módulo añade algunas extensiones útiles, aunque no tan simples, sobre Net::IMAP::Simple.

MÉTODOS

new
Para obtener detalles sobre la invocación, lee Net::IMAP::Simple.
body_summary
Las invocaciones típicas tendrán esta forma general. 
# obtener una representación de objeto del cuerpo del mensaje
my $summary = $imap->body_summary($message_number);
# mensaje multipart
if ($summary->has_parts) {
    for my $subpart ($summary->parts) {
        if ($subpart->has_parts) { ... }
        # examinar la parte del mensaje
        my @attr = map { $subpart->$_ } qw/content_type encoding encoded_size/;
        # obtener el cuerpo sin procesar de la parte
        my $subpart_body = $imap->get($message_number, $subpart->part_number);
    }
} else {
    my $body = $summary->body;
    my @attr = map { $body->$_ } qw/content_type encoding encoded_size/
}

Este método devuelve un objeto simple que contiene una representación del cuerpo de un mensaje. El objeto se construye mediante un analizador Parse::RecDescent utilizando la salida de un comando IMAP fetch body. El analizador utiliza la sintaxis formal definida por RFC3501 http://tools.ietf.org/html/rfc3501#section-9.

my $body = $summary->body;
my @attr = map { $body->$_ } qw/
    content_description
    encoded_size
    charset
    content_type
    part_number
    format
    id
    encoding
/;

Para mensajes multipart, el objeto contiene subobjetos para cada parte del mensaje, accesibles a través del método parts() e inspeccionados a través del método has_parts(). El método type describe el tipo de multipart (como mixed o alternative). El método parts devuelve una lista de subpartes, que a su vez pueden tener subpartes, y así sucesivamente.

Un ejemplo de mensaje alternativo multipart con un cuerpo de texto y una versión HTML del cuerpo sería algo como:

if ($summary->has_parts) {
    if ($summary->type eq 'alternative') {
        my ($html) = grep { $_->content_type eq 'text/html' } $summary->parts;
    }
}

Un mensaje multipart muy complejo podría verse así:

if ($summary->has_parts && $summary->type eq 'mixed') {
    for my $part ($summary->parts) {
        if ($part->has_parts && $part->type eq 'mixed') { ... }
        ...
    }
}
fetch
El comando fetch devuelve las diversas partes de los mensajes que los usuarios solicitan. Es bastante complicado (siguiendo RFC3501 usando una gramática/analizador), pero hay algunos patrones básicos que sigue. 
my $res  =$imap->fetch('30:32' => 'UID BODY.PEEK[HEADER.FIELDS (DATE)] FLAGS')
# $res = {
#   30 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Sun, 18 Jul 2010 20:54:48 -0400\r\n\r\n",
#           "FLAGS" => ["\\Flagged", "\\Seen"],
#           "UID" => 58890,
#         },
#   31 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Wed, 21 Jul 2010 09:09:04 -0400\r\n\r\n",
#           "FLAGS" => ["\\Seen"],
#           "UID" => 58891,
#         },
#   32 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Sat, 24 Jul 2010 05:12:06 -0700\r\n\r\n",
#           "FLAGS" => ["\\Seen"],
#           "UID" => 58892,
#         },
# }

Las llamadas listas "entre paréntesis" se devolverán como una matriz (ver "FLAGS"), pero casi todo lo demás se devolverá como cadenas. Esto incluye las consultas entre paréntesis. Toma "BODY.PEAK[HEADER.FIELDS (DATE FROM SUBJECT)]"), por ejemplo. El resultado se devolvería como las líneas de encabezado RFC822 (como ha hecho la anterior "Date: Sun, ...").

Para obtener más información sobre los diferentes tipos de consultas, consulta RFC3501. Hay un número sorprendente de cosas que se pueden consultar.

uidfetch
Esto es más o menos lo mismo que el método fetch() anterior, pero la consulta se ejecuta sobre UIDs en lugar de números de secuencia. Sin embargo, las claves de $res son los números de secuencia. 
my $res  =$imap->fetch('58890' => 'UID BODY.PEEK[HEADER.FIELDS (DATE)] FLAGS')
# $res = {
#   30 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Sun, 18 Jul 2010 20:54:48 -0400\r\n\r\n",
#           "FLAGS" => ["\\Flagged", "\\Seen"],
#           "UID" => 58890,
#         },
#   ...

NOMBRE

Net::IMAP::SimpleX - Interfaz Perl para IMAP

SINOPSIS

use Net::IMAP::SimpleX;

my $imap = Net::IMAP::SimpleX->new(
    host => 'imap.example.com',
    port => 993,
    ssl  => 1,
);

$imap->login('username', 'password');

my @folders = $imap->folders;

foreach my $folder (@folders) {
    $imap->select($folder);
    my @messages = $imap->search();
    foreach my $message_id (@messages) {
        my $headers = $imap->fetch_headers($message_id);
        print "Subject: ", $headers->{subject}, "\n";
    }
}

$imap->logout;

DESCRIPCIÓN

Net::IMAP::SimpleX proporciona una interfaz sencilla para interactuar con servidores IMAP. Permite conectarse, iniciar sesión, listar carpetas, seleccionar carpetas, buscar mensajes, recuperar cabeceras y cerrar la conexión.

MÉTODOS

Los métodos disponibles incluyen:

  • new(): Crea una nueva instancia de Net::IMAP::SimpleX. Acepta argumentos como host, port y ssl.
  • login(): Inicia sesión en el servidor IMAP con el nombre de usuario y la contraseña proporcionados.
  • folders(): Devuelve una lista de las carpetas disponibles en el servidor.
  • select(): Selecciona una carpeta específica para su posterior manipulación.
  • search(): Busca mensajes en la carpeta seleccionada. Puede aceptar criterios de búsqueda.
  • fetch_headers(): Recupera las cabeceras de un mensaje específico.
  • logout(): Cierra la sesión y la conexión con el servidor IMAP.
