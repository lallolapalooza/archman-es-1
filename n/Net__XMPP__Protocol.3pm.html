Nombre

Net::XMPP::Protocol - Módulo de protocolo XMPP

Sintaxis

Net::XMPP::Protocol es un módulo que permite a los desarrolladores tener fácil acceso al protocolo XMPP de mensajería instantánea. Ofrece funciones de alto nivel a los objetos Net::XMPP Client. Estas funciones son heredadas por este módulo.

Descripción

Protocol.pm busca ofrecer suficientes APIs de nivel alto y automatización de las APIs de nivel bajo para que escribir un cliente XMPP en Perl sea sencillo. Para quienes desean trabajar con el nivel bajo, pueden hacerlo también, pero las funciones son cubiertas en la documentación de cada módulo.

Net::XMPP::Protocol ofrece funciones para iniciar sesión, enviar y recibir mensajes, establecer información personal, crear un nuevo usuario, gestionar el roster y desconectar. Puedes usar todas o ninguna de las funciones, no hay requisitos.

Para más información sobre cómo se escriben los detalles del Net::XMPP, vea la ayuda de Net::XMPP.

Para más información sobre cómo escribir un cliente, vea Net::XMPP::Client.

Modos

Varias de las funciones toman un argumento de modo que te permiten especificar cómo debe comportarse la función:

block
envía el paquete con un ID, y luego espera hasta que una respuesta llegue. Puedes opcionalmente especificar un tiempo límite para que no se bloquee eternamente.
nonblock
envía el paquete con un ID, pero luego devuelve ese ID y control al programa principal. Net::XMPP sigue registrando este paquete, así que debes usar la función CheckID para saber cuando llega. (Este podría no ser muy útil...)
passthru
envía el paquete con un ID, pero no lo registra con Net::XMPP, y luego devuelve el ID. Esto es útil cuando se combina con la función XPath, ya que puedes registrar una función única vinculada al ID que recibes.

MÉTODOS

Funciones Básicas

GetErrorCode()
devuelve una cadena que con suerte contendrá información útil sobre por qué una función te devolvió undef.
SetErrorCode
SetErrorCode(cadena)

establece un mensaje de error útil antes de devolver undef al llamador.

SetCallBacks
SetCallBacks(message=>función, 
               presence=>función,
               iq=>función,      
               send=>función,    
               receive=>función, 
               update=>función)

establece las funciones de callback para las etiquetas de nivel superior listadas. Las etiquetas disponibles para buscar son <message/>, <presence/>, y <iq/>. Si se recibe un paquete con un ID que se encuentra en la lista de IDs registrados (ver RegisterID abajo) entonces no se envía a estas funciones, en su lugar se inserta en una LISTA y puede ser recuperado por algunas funciones que mencionaremos más adelante.

send y receive se utilizan para registrar qué XML se envía y recibe. update se utiliza como una forma de actualizar tu programa mientras esperas un paquete con un ID para ser devuelto (útil para aplicaciones GUI).

Un cambio importante que vino con la última versión es que el ID de sesión se pasa al callback como el primer argumento. Esto se hizo para facilitar el módulo Server.

El siguiente argumento depende de qué callback estés hablando. message, presence e iq reciben objetos Net::XMPP que coinciden con esos tipos. send y receive reciben cadenas. update no recibe nada, ni siquiera el ID de sesión.

Si estableces la función a undef, entonces el callback se elimina de la lista.

SetPresenceCallBacks
SetPresenceCallBacks(type=>función etc...)

establece las funciones de callback para el tipo de presencia especificado. La función toma tipos como clave principal y te permite especificar una función para cada tipo de paquete que puedes recibir.

"available"
"unavailable"
"subscribe"
"unsubscribe"
"subscribed"
"unsubscribed"
"probe"
"error"

Cuando recibe un paquete <presence/> comprueba type='' para un callback definido. Si hay uno entonces llama a la función con dos argumentos:

el ID de sesión y el
objeto Net::XMPP::Presence.

Si estableces la función a undef, entonces el callback se elimina de la lista.

NOTA: Si usas esto, que es un método más limpio, entonces debes *NO* especificar un callback para presencia en la función SetCallBacks.

Net::XMPP define algunos
callbacks predeterminados para varios tipos:
"subscribe" -
  responde con subscribed
"unsubscribe" -
  responde con unsubscribed
"subscribed" -
  responde con subscribed
"unsubscribed" -
  responde con unsubscribed
SetMessageCallBacks
SetMessageCallBacks(type=>función, etc...)

establece las funciones de callback para el tipo de mensaje especificado. La función toma tipos como clave principal y te permite especificar una función para cada tipo de paquete que puedes recibir.

"normal"
"chat"
"groupchat"
"headline"
"error"

Cuando recibe un paquete <message/> comprueba type='' para un callback definido. Si hay uno entonces llama a la función con dos argumentos:

el ID de sesión y el
objeto Net::XMPP::Message.

Si estableces la función a undef, entonces el callback se elimina de la lista.

NOTA: Si usas esto, que es un método más limpio, entonces debes *NO* especificar un callback para message en la función SetCallBacks.

SetIQCallBacks
SetIQCallBacks(namespace=>{      
                   get=>función,  
                   set=>función,  
                   result=>función
                 },                
                 etc...)

establece las funciones de callback para el namespace especificado. La función toma namespaces como clave principal y te permite especificar una función para cada tipo de paquete que puedes recibir.

"get"
"set"
"result"

Cuando recibe un paquete <iq/> comprueba type='' y xmlns='' para un callback definido. Si hay uno entonces llama a la función con dos argumentos: el ID de sesión y el objeto Net::XMPP::xxxx.

Si estableces la función a undef, entonces el callback se elimina de la lista.

NOTA: Si usas esto, que es un método más limpio, entonces debes *NO* especificar un callback para iq en la función SetCallBacks.

SetXPathCallBacks
SetXPathCallBacks(xpath=>función, etc...)

registra una función de callback para cada xpath especificado. Si Net::XMPP coincide con el xpath, entonces llama a la función con dos argumentos:

el ID de sesión y el
objeto Net::XMPP::Message.

Los xpaths están enraizados en cada paquete:

/message[@type="chat"]
/iq/*[xmlns="jabber:iq:roster"][1]
...
RemoveXPathCallBacks
RemoveXPathCallBacks(xpath=>función, etc...)

anula el registro de una función de callback para cada xpath especificado.

SetDirectXPathCallBacks
SetDirectXPathCallBacks(xpath=>función, etc...)

registra una función de callback para cada xpath especificado. Si Net::XMPP coincide con el xpath, entonces llama a la función con dos argumentos:

el ID de sesión y el
objeto XML::Stream::Node.

Los xpaths están enraizados en cada paquete:

/anything
/anotherthing/foo/[1]
...

La gran diferencia entre esto y los XPathCallBacks regulares es el hecho de que esto pasa directamente el XML y no un objeto basado en Net::XMPP.

RemoveDirectXPathCallBacks
RemoveDirectXPathCallBacks(xpath=>función, etc...)

anula el registro de una función de callback para cada xpath especificado.

Process
    Process(entero)
toma el período de tiempo de espera como argumento. Si no se especifica tiempo de espera, la función se bloquea hasta que se recibe un paquete. De lo contrario, espera ese número de segundos y luego sale para que tu programa pueda continuar haciendo cosas útiles. NOTA: Esto es importante para las GUI. Necesitas dejar tiempo para procesar comandos GUI incluso si estás esperando paquetes. Los siguientes son los posibles valores de retorno y lo que significan:
    1   - Estado ok, datos recibidos.
    0   - Estado ok, no se recibieron datos.
  undef - Estado no ok, detener el procesamiento.

IMPORTANTE: Debes comprobar la salida de cada Process. Si obtienes un undef, la conexión murió y debes actuar en consecuencia.

Send
Send(objeto, ignorarActividad) 
Send(cadena, ignorarActividad)

toma un objeto Net::XMPP::xxxxx o una cadena XML como argumento y la envía al servidor. Si estableces ignorarActividad a 1, entonces el módulo XML::Stream no registrará este paquete como actividad del usuario.

Funciones de ID

SendWithID
SendWithID(objeto)
SendWithID(cadena)

toma un objeto Net::XMPP::xxxxx o una cadena XML como argumento, añade el próximo número de ID disponible y envía ese paquete al servidor. Devuelve el número de ID asignado.

SendAndReceiveWithID
SendAndReceiveWithID(objeto, tiempo_de_espera)
SendAndReceiveWithID(cadena, tiempo_de_espera)

utiliza SendWithID y WaitForID para proporcionar una forma completa de enviar y recibir paquetes con IDs. Puede tomar un objeto Net::XMPP::xxxxx o una cadena XML. Devuelve el objeto Net::XMPP::xxxxx apropiado basado en el tipo de paquete recibido. El tiempo de espera se pasa a WaitForID, ver esa función para cómo funciona el tiempo de espera.

ReceivedID
ReceivedID(entero)

devuelve 1 si se ha recibido un paquete con el ID especificado, 0 en caso contrario.

GetID
GetID(entero)

devuelve el objeto Net::XMPP::xxxxx apropiado basado en el tipo de paquete recibido con el ID especificado. Si el ID ha sido recibido, GetID devuelve 0.

WaitForID
WaitForID(entero, tiempo_de_espera)

se bloquea hasta que se recibe un paquete con el ID. Devuelve el objeto Net::XMPP::xxxxx apropiado basado en el tipo de paquete recibido. Si se alcanza el límite de tiempo de espera, y el paquete llega, será descartado.

NOTA: Solo <iq/> soporta oficialmente los IDs, por lo que enviar un <message/>, o <presence/> con un ID es un riesgo. El servidor ignorará la etiqueta ID y la pasará, por lo que ambos clientes deben soportar la etiqueta ID para que estas funciones sean útiles.

AddNamespace(ns=>cadena,

Funciones de Mensaje

MessageSend
MessageSend(hash)

toca el hash y lo pasa a SetMessage en Net::XMPP::Message (ver allí para los valores válidos). Luego envía el mensaje al servidor.

Funciones de Presencia

PresenceSend
PresenceSend()
PresenceSend(hash, signature=>string)

Sin argumentos, envía una presencia vacía al servidor para indicar que estás disponible. Si proporcionas un hash, pasa ese hash a la función SetPresence() definida en el módulo Net::XMPP::Presence. Opcionalmente, puedes especificar un signatura y se colocará en <presence/> el atributo jabber:x:signed.

Funciones de Suscripción

Subscription
Subscription(hash)

toca el hash y lo pasa a SetPresence en Net::XMPP::Presence (ver allí para los valores válidos). Luego envía la suscripción al servidor.

Los tipos válidos de suscripción son:

subscribe    - suscribirse a la presencia de un JID
unsubscribe  - desuscribirse de la presencia de un JID
subscribed   - respuesta a un subscribe
unsubscribed - respuesta a un unsubscribe

Funciones de Base de Datos de Presencia

PresenceDB
PresenceDB()

pide al objeto que inicie los callbacks para automáticamente popular la base de datos de presencia.

PresenceDBParse
PresenceDBParse(Net::XMPP::Presence)

para cada presencia que recibas, pasa el objeto de presencia a la DB para que pueda registrar los recursos y prioridades por ti. Devuelve either la presencia pasada, si no puede parsearse para la DB, o la presencia actual encontrada por la función PresenceDBQuery.

PresenceDBDelete
PresenceDBDelete(string|Net::XMPP::JID)

elimina la entrada del JID de la DB.

PresenceDBClear
PresenceDBClear()

elimina todas las entradas de la base de datos.

PresenceDBQuery
PresenceDBQuery(string|Net::XMPP::JID)

devuelve la presencia NX que fue última recibida para el prioridad más alta de este JID. Puedes pasarle un string o un objeto de JID de NX.

PresenceDBResources
PresenceDBResources(string|Net::XMPP::JID)

devuelve un array de recursos en orden de prioridad más alta a más baja.

IQ Funciones

Funciones de Autenticación

AuthSend
AuthSend(username=>string,
         password=>string,
         resource=>string)

toca toda la información y construye un paquete Net::XMPP::IQ::Auth. Luego lo envía al servidor con un ID y espera a que el ID devuelva. Luego mira el paquete resultado para determinar si la autenticación fue exitosa. El array devuelto por AuthSend tiene este formato:

[ type , message ]

Si type es "ok", entonces la autenticación fue exitosa, de lo contrario message contiene un poco más de detalles sobre el error.

IQ::Register Funciones

RegisterRequest
RegisterRequest(to=>string,  timeout=>int)
RegisterRequest()

envía una <iq/> solicitud al servidor/transporte especificado, si no se especifica, se envía al servidor activo actual. La función devuelve un hash que contiene los campos necesarios. Aquí es un ejemplo del hash:

$hash{fields} - los campos RAW de iq:register.

$hash{instructions} - cómo llenar el formulario.

$hash{form} - los formularios dinámicos nuevos.

En $hash{form}, los campos presentes son los campos requeridos por el servidor.

RegisterSend
RegisterSend(hash)

toca el contenido del hash y lo pasa a la función SetRegister en el módulo Net::XMPP::Query jabber:iq:register. Esta función devuelve un array que tiene este formato:

[ type , message ]

Si type es "ok", entonces la registro fue exitosa, de lo contrario message contiene un poco más de detalles sobre el error.

Funciones de Roster

Roster
Roster()

devuelve un objeto Net::XMPP::Roster. Este automáticamente intercepta todas las paquetes de roster y presencia enviados por el servidor y te da un Roster preciso. Para más información, consulta la página de manuales de Net::XMPP::Roster.

RosterParse
RosterParse(IQ object)

devuelve un hash que contiene la roster parseado en la estructura siguiente:

$roster{'bob@jabber.org'}->{name}

$roster{'bob@jabber.org'}->{subscription}
                    - Estado de suscripción
                      (to, from, both, none)
$roster{'bob@jabber.org'}->{ask}
                    - Estado de ask de este usuario
                      (subscribe, unsubscribe)
$roster{'bob@jabber.org'}->{groups}
                    - Lista de grupos que bob@jabber.org está en
RosterGet
RosterGet()

envía un paquete Net::XMPP::IQ::Roster al servidor para que el servidor envíe el roster al cliente. Devuelve el hash del roster del anterior RosterParse.

RosterRequest
RosterRequest()

envía un paquete Net::XMPP::IQ::Roster al servidor para que el servidor envíe el roster al cliente.

RosterAdd
RosterAdd(hash)

envía un paquete pidiendo que el jid se agregue al roster. El formato del hash es definido en la función SetItem en el módulo Net::XMPP::Query jabber:iq:roster.

RosterRemove

RosterDB()
