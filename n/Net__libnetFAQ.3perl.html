Obtener e instalar libnet

¿Qué es libnet?

libnet es una colección de módulos perl5 relacionados con la programación de redes. La mayoría de los módulos proporcionados ofrecen el lado cliente de protocolos populares cliente-servidor que se utilizan en la comunidad de Internet.

¿Qué versión de perl necesito?

Esta versión de libnet requiere Perl 5.8.1 o superior.

¿Qué otros módulos necesito?

No se requieren módulos no principales para un uso normal, excepto en os390, que requiere Convert::EBCDIC.

Authen::SASL es necesario para el soporte AUTH.

IO::Socket::SSL versión 2.007 o superior es necesario para el soporte SSL.

IO::Socket::IP versión 0.25 o IO::Socket::INET6 versión 2.62 es necesario para el soporte IPv6.

¿Qué máquinas soportan libnet?

libnet en sí mismo es una distribución de código puramente Perl, por lo que debería funcionar en cualquier máquina donde se ejecute Perl.

¿Dónde puedo obtener la última versión de libnet?

La última versión de libnet siempre está en CPAN, la encontrarás en

https://metacpan.org/release/libnet

Usando Net::FTP

¿Cómo descargo archivos de un servidor FTP?

Ejemplo extraído de un artículo publicado en comp.lang.perl.misc

#!/your/path/to/perl
# un módulo que facilita la vida
use Net::FTP;
# para depuración: $ftp = Net::FTP->new('site','Debug',10);
# abre una conexión e inicia sesión!
$ftp = Net::FTP->new('sitio_objetivo.algún_lugar.xxx');
$ftp->login('nombre_de_usuario','contraseña');
# establece el modo de transferencia a binario
$ftp->binary();
# cambia el directorio en el sitio ftp
$ftp->cwd('/alguna/ruta/a/algún_lugar/');
foreach $nombre ('archivo1', 'archivo2', 'archivo3') {
# los argumentos de get son en el siguiente orden:
# nombre de archivo en el servidor ftp
# nombre de archivo para guardar la transferencia localmente
# puede usarse simplemente como get($name) si deseas el mismo nombre
  $ftp->get($nombre,$nombre);
}
# ¡ftp terminado!
$ftp->quit;

¿Cómo transfiero archivos en modo binario?

Para transferir archivos sin traducción de <LF><CR>, Net::FTP proporciona el método "binary"

$ftp->binary;

¿Cómo puedo cambiar los permisos de un archivo en un servidor remoto?

El protocolo FTP no tiene un comando para cambiar los permisos de un archivo en el servidor remoto. Pero algunos servidores ftp pueden permitir que se emita un comando chmod a través de un comando SITE, por ejemplo

$ftp->quot('site chmod 0777',$nombre_archivo);

Pero esto no garantiza que funcione.

¿Cambiar de directorio a "" no falla?

Pasar un argumento de "" a ->cwd() tiene el mismo efecto que llamar a ->cwd() sin argumentos. Activa Debug (ver más abajo) y verás lo que está sucediendo

$ftp = Net::FTP->new($host, Debug => 1);
$ftp->login;
$ftp->cwd("");

da como resultado

Net::FTP=GLOB(0x82196d8)>>> CWD /
Net::FTP=GLOB(0x82196d8)<<< 250 CWD command successful.

Estoy detrás de un firewall SOCKS, pero la opción Firewall no funciona?

La opción Firewall solo es para soportar un tipo de firewall. El tipo soportado es un proxy ftp.

Para usar Net::FTP, o cualquier otro módulo de la distribución libnet, a través de un firewall SOCKS, debes crear un ejecutable perl "socksificado" compilando perl con la biblioteca socks.

Estoy detrás de un firewall proxy FTP, pero no puedo acceder a máquinas externas?

Net::FTP implementa el enfoque de firewall proxy ftp más popular. El esquema implementado es aquel en el que inicias sesión en el firewall con "usuario@nombre_host"

Obtaining and installing libnet

libnet is available from CPAN, and can be found in the latest release of Perl.

If you do not have the latest release of Perl then you can download libnet from:

  • http://www.cpan.org

libnet depends on the following modules:

  • IO::Socket
  • IO::Handle
  • Net::Cmd

The modules above are all included with Perl, so you should not need to install them separately.

Using Net::FTP

My ftp proxy firewall does not listen on port 21

FTP servers usually listen on the same port number, port 21, as any other FTP server. But there is no reason why this has to be the case.

If you pass a port number to Net::FTP then it assumes this is the port number of the final destination. By default Net::FTP will always try to connect to the firewall on port 21.

Net::FTP uses IO::Socket to open the connection and IO::Socket allows the port number to be specified as part of the hostname. So this problem can be resolved by either passing a Firewall option like "hostname:1234" or by setting the "ftp_firewall" option in Net::Config to be a string in the same form.

Is it possible to change the file permissions of a file on an FTP server ?

The answer to this is "maybe". The FTP protocol does not specify a command to change file permissions on a remote host. However many servers do allow you to run the chmod command via the "SITE" command. This can be done with

$ftp->site('chmod','0775',$file);

I have seen scripts call a method message, but cannot find it documented ?

Net::FTP, like several other packages in libnet, inherits from Net::Cmd, so all the methods described in Net::Cmd are also available on Net::FTP objects.

Why does Net::FTP not implement mput and mget methods

The quick answer is because they are easy to implement yourself. The long answer is that to write these in such a way that multiple platforms are supported correctly would just require too much code. Below are some examples how you can implement these yourself.

sub mput {
my($ftp,$pattern) = @_;
foreach my $file (glob($pattern)) {
$ftp->put($file) or warn $ftp->message;
} }

sub mget {
my($ftp,$pattern) = @_;
foreach my $file ($ftp->ls($pattern)) {
$ftp->get($file) or warn $ftp->message;
} }

Using Net::SMTP

Why can't the part of an Email address after the @ be used as the hostname ?

The part of an Email address which follows the @ is not necessarily a hostname, it is a mail domain. To find the name of a host to connect for a mail domain you need to do a DNS MX lookup

Why does Net::SMTP not do DNS MX lookups ?

Net::SMTP implements the SMTP protocol. The DNS MX lookup is not part of this protocol.

The verify method always returns true ?

Well it may seem that way, but it does not. The verify method returns true if the command succeeded. If you pass verify an address which the server would normally have to forward to another machine, the command will succeed with something like

252 Couldn't verify <someone@there> but will attempt delivery anyway

This command will fail only if you pass it an address in a domain the server directly delivers for, and that address does not exist.

Debugging scripts

How can I debug my scripts that use Net::* modules ?

Most of the libnet client classes allow options to be passed to the constructor, in most cases one option is called "Debug". Passing this option with a non-zero value will turn on a protocol trace, which will be sent to STDERR. This trace can be useful to see what commands are being sent to the remote server and what responses are being received back.

#!/your/path/to/perl
use Net::FTP;
my $ftp = new Net::FTP($host, Debug => 1);
$ftp->login('gbarr','password');
$ftp->quit;

this script would output something like

Net::FTP: Net::FTP(2.22)
Net::FTP:   Exporter
Net::FTP:   Net::Cmd(2.0801)
Net::FTP:   IO::Socket::INET
Net::FTP:     IO::Socket(1.1603)
Net::FTP:       IO::Handle(1.1504)
Net::FTP=GLOB(0x8152974)<<< 220 imagine FTP server (Version wu-2.4(5) Tue Jul 29 11:17:18 CDT 1997) ready.
Net::FTP=GLOB(0x8152974)>>> user gbarr
Net::FTP=GLOB(0x8152974)<<< 331 Password required for gbarr.
Net::FTP=GLOB(0x8152974)>>> PASS ....
Net::FTP=GLOB(0x8152974)<<< 230 User gbarr logged in.  Access restrictions apply.
Net::FTP=GLOB(0x8152974)>>> QUIT
Net::FTP=GLOB(0x8152974)<<< 221 Goodbye.

The first few lines tell you the modules that Net::FTP uses and their versions, this is useful data to me when a user reports a bug. The last seven lines show the communication with the server. Each line has three parts. The first part is the object itself, this is useful for separating the output if you are using multiple objects. The second part is either "<<<<" to show data coming from the server or "&gt&gt&gt&gt" to show data going to the server. The remainder of the line is the command being sent or response being received.
