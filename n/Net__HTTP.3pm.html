NAME

Net::HTTP - Low-level HTTP connection (client)

VERSION

version 6.24

SYNOPSIS

use Net::HTTP;
my $s = Net::HTTP->new(Host => "www.perl.com") || die $@;
$s->write_request(GET => "/", 'User-Agent' => "Mozilla/5.0");
my($code, $mess, %h) = $s->read_response_headers;
while (1) {
   my $buf;
   my $n = $s->read_entity_body($buf, 1024);
   die "read failed: $!" unless defined $n;
   last unless $n;
   print $buf;
}

DESCRIPTION

The "Net::HTTP" class is a low-level HTTP client. An instance of the "Net::HTTP" class represents a connection to an HTTP server. The HTTP protocol is described in RFC 2616. The "Net::HTTP" class supports "HTTP/1.0" and "HTTP/1.1".

The "Net::HTTP" is a subclass of one of the following: "IO::Socket::IP" (IPv6+IPv4), "IO::Socket::INET6" (IPv6+IPv4), or "IO::Socket::INET" (IPv4 only). You can combine the methods described below with direct reading and writing on the connection. This is not necessarily a good idea, unless you know what you are doing.

The following methods are provided (in addition to those of "IO::Socket::INET"):

"$s = Net::HTTP->new( %options )"
The "Net::HTTP" constructor method takes the same options as "IO::Socket::INET" and also these:
Host:            Initial value of the "Host" attribute
KeepAlive:       Initial value of the "KeepAlive" attribute
SendTE:          Initial value of the "SendTE" attribute
HTTPVersion:     Initial value of the "HTTPVersion" attribute
PeerHTTPVersion: Initial value of the "PeerHTTPVersion" attribute
MaxLineLength:   Initial value of the "MaxLineLength" attribute
MaxHeaderLines:  Initial value of the "MaxHeaderLines" attribute

The "Host" attribute is also the default value for "IO::Socket::INET"'s "PeerAddr". The default value of "PeerPort" is 80 if not supplied. The "PeerPort" specifier can also be included in the "PeerAddr" with a ":" prefix and closing the IPv6 address in brackets "[]" if necessary:

The "Listen" attribute provided by the "IO::Socket::INET" constructor method is not allowed.

If it cannot connect to the given HTTP server, the constructor returns "undef" and $@ contains the reason. After a successful connection, an instance of "Net:HTTP" is returned.

"$s->host"
Get/set the default "Host" header value to be sent. The $host value must not be set to an empty string (or "undef") for HTTP/1.1.
"$s->keep_alive"
Get/set the keep-alive value. If this value is TRUE, a header is sent indicating that the server should try to keep the connection open so that multiple requests can be sent.

The headers actually set depend on the values of the "http_version" and "peer_http_version" attributes.

"$s->send_te"
Get/set a value indicating whether a "TE" header should be sent to indicate transfer codings that the server may choose from. The list of codings announced as accepted by this client depends on the availability of the following modules: "Compress::Raw::Zlib" for deflate, and "IO::Compress::Gunzip" for gzip.
"$s->http_version"
Get/set the HTTP protocol version number that this client should announce. This value may only be set to "1.0" or "1.1". The default value is "1.1".
"$s->peer_http_version"
Get/set the protocol version number of our peer. This value is initialized to "1.0", but it is updated by a call to the read_response_headers() method.
"$s->max_line_length"
Get/set a limit on the length of the response line and response header lines. The default value is 8192. A value of 0 means no limit.
"$s->max_header_length"
Get/set a limit on the number of header lines that a response may have. The default value is 128. A value of 0 means no limit.
"$s->format_request($method, $uri, %headers, [$content])"
Format a request message and return it as a string. If the headers do not include a "Host" header, a header is inserted with the value of the "host" attribute. Headers such as "Connection" and "Keep-Alive" may also be added depending on the state of the "keep_alive" property.

If the $content value is given (and not empty), a "Content-Length" header is automatically added unless it already exists.

"$s->write_request($method, $uri, %headers, [$content])"
Format and send a request message. The arguments are the same as for format_request(). Returns true on success.
"$s->format_chunk( $data )"
Return the string to write for the given chunk of data.
"$s->write_chunk($data)"
Write a new chunk of request body data. This method should only be used if a "Transfer-Encoding" header with value "chunked" was sent in the request. Note: writing zero-length data is a NOP. Use the write_chunk_eof() method to signal the end of the data body.

Returns true on success.

"$s->format_chunk_eof( %trailers )"
Return the string to write to signal the end of chunked data, plus optional trailer headers.
"$s->write_chunk_eof( %trailers )"
Write a chunk end marker for chunked data and optional trailer headers. Note: trailer headers should not really be used, unless a "Trailer" header was sent.

Returns true on success.

"($code, $mess, %headers) = $s->read_response_headers( %opts )"
Read the response headers from the server and return them. The $code value is the 3-digit status code of the HTTP protocol (see HTTP::Status) and $mess is the textual message that accompanied it. The headers are returned as key/value pairs. As the case of the key is not normalized and the same key may appear multiple times, assigning these values directly to a hash is not recommended. Only $code is returned if this method is called in scalar context.

As a consequence of this method, the "peer_http_version" attribute is updated.

Options may be passed as key/value pairs. Currently only two options are supported: "laxed" and "junk_out".

The "laxed" option will cause read_response_headers() to be more tolerant of servers that have not learned to speak HTTP correctly. The "laxed" option is a boolean flag, and is activated by passing a true value. The "junk_out" option may be used to capture malformed headers when "laxed" is enabled. The value should be an array reference. Malformed headers will be appended to this array.

The "laxed" option must be specified in order

Net::HTTP(3pm)

VERSION

This man page documents version 6.24 of Net::HTTP.

SYNOPSIS

 use Net::HTTP;

 my $host = shift || "www.example.com";
 my $res = Net::HTTP->new($host, %options);
 if ($res) {
     $res->method(GET => "/");
     $res->send;
     my($code, $mess, %headers) = $res->top_line;
     if ($code == 200) {
         my $c;
         while (($c = $res->read_entity_body($buf, 1024)) && $c > 0) {
             # process body chunk $buf
         }
     }
     $res->close;
 }

DESCRIPTION

Net::HTTP is a low-level HTTP client library. It implements the HTTP protocol as specified in RFC 2068 and RFC 2616. It handles both HTTP/1.0 and HTTP/1.1. The library is designed to be used as a building block for higher-level libraries like LWP::UserAgent.

A Net::HTTP object represents a single HTTP connection to a server.

The main methods are:

"Net::HTTP->new(host, port, %options)"

Creates a new Net::HTTP object and connects to the specified host and port. If port is not given, it defaults to 80. The %options are passed to IO::Socket::INET– a subset of options are relevant: "Proxy", "proxy_user", "proxy_pass", "timeout", "keep_alive", "localaddr", "localport", "peer_host_header".

If the connection fails, it returns undef.

"$s->method(METHOD => URI, %headers)"

Prepares a request to be sent. METHOD is the HTTP method (e.g., GET, POST, PUT). URI is the request URI. %headers are the request headers. Several headers are automatically added or overridden: "Host", "User-Agent", "Accept", "Accept-Encoding", and "Connection".

See also "send_entity_body" for sending request bodies with POST, PUT etc.

"$s->req->proxy_user($user)"
"$s->req->proxy_pass($pass)"

Set the proxy username and password. This is only useful when using a proxy server.

"$s->send"

Sends the request on the socket. This method should only be called once per request.

"$s->send_entity_body($data)"

Sends the request entity body. This method can be called multiple times for sending large data.

"$code = $s->top_line"
"($code, $mess, %headers) = $s->top_line"

Reads and parses the first line of the response. Returns the HTTP status code and message. Also returns any response headers. If keep_alive is true, it may return 204 ("No Content") or 304 ("Not Modified") even if there is no response body.

If keep_alive is true and the server closes the connection, this method will return undef.

"$code = $s->read_response_headers"
"($code, $mess, %headers) = $s->read_response_headers"

This is the preferred method to read the response line and headers. It is similar to top_line but it will automatically read more data from the socket if needed, until all headers have been read. It returns the status code, status message, and a hash of headers.

The headers hash will contain header names mapped to their values. If a header appears multiple times in the response, the header name will be mapped to an array reference containing all the values.

Special header values:

The value of the "Set-Cookie" header is an array reference of cookie values.

The values of "Content-Type" and "Content-Disposition" are objects of type HTTP::Message::ParamValue.

The values of "WWW-Authenticate" and "Proxy-Authenticate" are objects of type HTTP::Headers::WWWAuth.

If the server doesn't send a response line and headers (e.g. a pre-HTTP/1.0 server), this method will return (200, "Assumed OK", ()).

If the server does not speak proper HTTP or if the "max_line_length" or "max_header_length" limits are reached, this method will raise an exception (die). If the "laxed" option is turned on and "max_line_length" and "max_header_length" checks are turned off, then no exception will be raised and this method will always return a response code.

To communicate with pre-HTTP/1.0 servers that don't describe the response outcome or the data they send back with a header block. For these servers peer_http_version is set to "0.9" and this method returns (200, "Assumed OK").

The method will raise an exception (die) if the server does not speak proper HTTP or if the "max_line_length" or "max_header_length" limits are reached. If the "laxed" option is turned on and "max_line_length" and "max_header_length" checks are turned off, then no exception will be raised and this method will always return a response code.

"$n = $s->read_entity_body($buf, $size);"

Reads chunks of the entity body content. Basically the same interface as for read() and sysread(), but the buffer offset argument is not supported yet. This method should only be called after a successful read_response_headers() call.

The return value will be "undef" on read errors, 0 on EOF, -1 if no data could be returned this time, otherwise the number of bytes assigned to $buf. The $buf is set to "" when the return value is -1.

You normally want to retry this call if this function returns either -1 or "undef" with $! as EINTR or EAGAIN (see Errno). EINTR can happen if the application catches signals and EAGAIN can happen if you made the socket non-blocking.

This method will raise exceptions (die) if the server does not speak proper HTTP. This can only happen when reading chunked data.

"%headers = $s->get_trailers"

After read_entity_body() has returned 0 to indicate end of the entity body, you might call this method to pick up any trailers.

"$s->_rbuf"

Get/set the read buffer content. The read_response_headers() and read_entity_body() methods use an internal buffer which they will look for data before they actually sysread more from the socket itself. If they read too much, the remaining data will be left in this buffer.

"$s->_rbuf_length"

Returns the number of bytes in the read buffer. This should always be the same as: 

length($s->_rbuf)

but might be more efficient.

SUBCLASSING

The read_response_headers() and read_entity_body() will invoke the sysread() method when they need more data. Subclasses might want to override this method to control how reading takes place.

The object itself is a glob. Subclasses should avoid using hash key names prefixed with "http_" and "io_".
