NOMBRE

Net::LDAP::Server - Manejo del protocolo del lado del servidor LDAP

SINOPSIS

package MyServer;
use Net::LDAP::Server;
use Net::LDAP::Constant qw(LDAP_SUCCESS);
use base 'Net::LDAP::Server';
sub search {
    my $self = shift;
    my ($reqData, $fullRequest) = @_;
    print "Buscando\n";
    ...
    return {
        'matchedDN' => '',
        'errorMessage' => '',
        'resultCode' => LDAP_SUCCESS
    }, @entries;
}

package main;
my $handler = MyServer->new($socket);
$handler->handle;
# o con manejadores de entrada y salida distintos
package main;
my $handler = MyServer->new( $input_handle, $output_handle );
$handler->handle;

RESUMEN

Esta clase proporciona el manejo del protocolo para un servidor LDAP. Puedes crear una subclase de ella e implementar los métodos que necesites (ver abajo). Luego, simplemente instancia tu subclase y llama a su método "handle" para establecer una conexión con el cliente.

SUBCLASES

Puedes crear una subclase de Net::LDAP::Server con las siguientes líneas:

package MyServer;
use Net::LDAP::Server;
use base 'Net::LDAP::Server';

Luego, puedes agregar tus métodos personalizados simplemente implementando una subrutina con el mismo nombre que cada método. Estos son los métodos soportados:

"bind"
"unbind"
"search"
"add"
"modify"
"delete"
"modifyDN"
"compare"
"abandon"

Para cualquier método que no se proporcione, Net::LDAP::Server devolverá un "LDAP_UNWILLING_TO_PERFORM".

new()

También puedes crear una subclase del constructor "new" para hacer algo en el momento de la conexión:

sub new {
   my ($class, $sock) = @_;
   my $self = $class->SUPER::new($sock);
   printf "Conexión aceptada desde: %s\n", $sock->peerhost();
   return $self;
}

Ten en cuenta que $self se construye usando el pragma `fields`, por lo que si deseas agregar datos a él, deberías agregar una línea como esta en tu subclase:

use fields qw(myCustomField1 myCustomField2);

Métodos

Cuando se invoca un método, se le pasará obviamente $self generado por "new", y dos variables:

  • la estructura de datos de Solicitud específica para este método (por ejemplo, BindRequest);
  • el mensaje de solicitud completo (útil si deseas acceder a las partes de messageID o controls)

Puedes consultar Net::LDAP::ASN o usar Data::Dumper para averiguar qué se presenta a tu método:

use Data::Dumper;
sub search {
   print Dumper \@_;
}

Si algo sale mal en el módulo que especificas (por ejemplo, si falla o el resultado no es una estructura ldapresult correcta), Net::LDAP::Server devolverá un "LDAP_OPERATIONS_ERROR" donde errorMessage especificará qué salió mal.

Todos los métodos deben devolver un hashref de LDAPresult, por ejemplo:

return({
    'matchedDN' => '',
    'errorMessage' => '',
    'resultCode' => LDAP_SUCCESS
});

"search" debe devolver un hashref de LDAPresult seguido de una lista de entradas (si aplica). Las entradas pueden estar codificadas como estructuras searchResEntry o searchRefEntry, o como objetos Net::LDAP::Entry o Net::LDAP::Reference.

MANEJO DEL CLIENTE

handle()

Cuando obtienes un socket de un cliente, puedes instanciar la clase y manejar la solicitud:

my $handler = MyServer->new($socket);
$handler->handle;

O, alternativamente, puedes pasar dos manejadores para entrada y salida, respectivamente.

my $handler = MyServer->new(*STDIN{IO},*STDOUT{IO});
$handler->handle;

Consulta los ejemplos en el directorio examples/ para ver servidores de ejemplo, usando IO::Select, Net::Daemon o Net::Server.
