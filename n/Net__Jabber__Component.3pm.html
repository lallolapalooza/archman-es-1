NOMBRE

Net::Jabber::Component - Biblioteca de componentes Jabber

SINOPSIS

Net::Jabber::Component es un módulo que proporciona a los desarrolladores un fácil
acceso al desarrollo de componentes de servidor en el protocolo de mensajería instantánea Jabber.

DESCRIPCIÓN

Component.pm busca proporcionar suficientes APIs de alto nivel y automatización de
las APIs de bajo nivel para que escribir un Componente Jabber en Perl sea trivial.
Para aquellos que deseen trabajar con el bajo nivel, también pueden hacerlo,
pero esas funciones se cubren en la documentación de cada módulo.
Net::Jabber::Component proporciona funciones para conectarse a un servidor Jabber,
iniciar sesión, enviar y recibir mensajes, operar como un componente del lado del servidor y
desconectarse. Puede usar todas o ninguna de las funciones, no hay ningún requisito.
Para obtener más información sobre cómo se escribe Net::Jabber, consulte la ayuda de
Net::Jabber en sí.
Para obtener una lista completa de las funciones de alto nivel disponibles, consulte
Net::Jabber::Protocol y Net::XMPP::Protocol.

Funciones básicas

use Net::Jabber;
$Con = new Net::Jabber::Component();
$Con->Execute(hostname=>"jabber.org",
              componentname=>"service.jabber.org",
              secret=>"XXXX"
             );
#
# Para la lista de funciones disponibles, consulte Net::XMPP::Protocol.
#
$Con->Disconnect();

MÉTODOS

Funciones básicas

new(debuglevel=>0|1|2, - crea el objeto Component.
    debugfile=>cadena,   debugfile debe establecerse en la ruta del registro
    debugtime=>0|1)      de depuración que se escribirá. Si se establece en "stdout"
                         entonces la depuración irá allí. debuglevel controla la cantidad
                         de depuración. Para obtener más información sobre la configuración
                         válida para debuglevel, debugfile y debugtime, consulte
                         Net::Jabber::Debug.
AuthSend(secret=>cadena) - Realiza el apretón de manos y se autentica
                           con el servidor.
Connect(hostname=>cadena,       - abre una conexión al servidor
            port=>entero,            basada en el valor de
            componentname=>cadena,    connectiontype. La única configuración válida
            connectiontype=>cadena)   es:
                                        accept - conexión remota TCP/IP
                                  En el futuro, esto podría usarse de nuevo
                                  ofreciendo nuevas características.
                                  Si se acepta, se conecta al
                                  servidor listado en el valor del host,
                                  en el puerto listado. Los valores predeterminados
                                  para los dos son localhost y 5269.

                                  Nota: Un cambio respecto a versiones anteriores es que Component
                                  ahora comparte su núcleo con Client. Para ese fin, el
                                  secreto ya no debe usarse. Llame a AuthSend después de
                                  conectarse. Mejor aún, use Execute.
Connected() - devuelve 1 si el Componente está conectado al servidor,
              y 0 si no.
Disconnect() - cierra la conexión al servidor.
Execute(hostname=>cadena,       - Bucle interno genérico para manejar
            port=>int,                la conexión al servidor, llamar a
            secret=>cadena,           Process y reconectar si se pierde
            componentname=>cadena,    la conexión. Hay cuatro callbacks disponibles
            connectiontype=>cadena,   que se llaman en varios lugares del bucle.
        connectattempts=>int,     onconnect - cuando el componente
        connectsleep=>int)          se conecta al servidor.
                                    onauth - cuando el componente ha
                                             completado su apretón de manos
                                             con el servidor, se llamará a este.
                                    onprocess - este es el bucle más
                                                interno y, por lo tanto,
                                                se llama con más frecuencia.
                                                Tenga mucho, mucho cuidado con
                                                lo que pone aquí, ya que puede
                                                afectar *DRÁSTICAMENTE* el
                                                rendimiento.
                                    ondisconnect - cuando se pierde la conexión.
                                    onexit - cuando la función renuncia a intentar
                                             conectar y sale.
                                  Los argumentos se pasan directamente a la función Connect,
                                  excepto por connectattempts y connectsleep.
                                  connectattempts es el número de veces que el
                                  Componente debe intentar conectarse antes de rendirse.
                                  -1 significa intentar para siempre. El valor predeterminado es -1.
                                  connectsleep es el número de segundos a dormir entre cada
                                  intento de conexión.
Process(entero) - toma el período de tiempo de espera como argumento. Si no se
                   enumera ningún tiempo de espera, la función se bloquea hasta
                   que se recibe un paquete. De lo contrario, espera ese
                   número de segundos y luego sale para que su programa
                   pueda continuar haciendo cosas útiles. NOTA: Esto es
                   importante para las GUI. Necesita dejar tiempo para
                   procesar comandos de GUI incluso si está esperando paquetes.
                   Los siguientes son los posibles valores de retorno y lo que significan:
                       1   - Estado ok, datos recibidos.
                       0   - Estado ok, no se recibieron datos.
                     undef - Estado no ok, detener el procesamiento.

                   IMPORTANTE: Debe verificar la salida de cada Process.
                   Si obtiene un undef, la conexión falló y debe actuar
                   en consecuencia.
