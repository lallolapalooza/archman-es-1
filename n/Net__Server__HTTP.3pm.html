Net::Server::HTTP(3) Documentación de Contribución de Usuario de Perl Net::Server::HTTP(3)

NOMBRE

Net::Server::HTTP - clase de servidor HTTP muy básica basada en Net::Server

TEST ONE LINER

perl -e 'use base qw(Net::Server::HTTP); main->run(port => 8080)'
# iniciará un servidor de eco

SINOPSIS

use base qw(Net::Server::HTTP);
__PACKAGE__->run;
sub process_http_request {
    my $self = shift;
    print "Content-type: text/html\n\n";
    print "<form method=post action=/bam><input type=text name=foo><input type=submit></form>\n";
    require Data::Dumper;
    local $Data::Dumper::Sortkeys = 1;
    require CGI;
    my $form = {};
    my $q = CGI->new; $form->{$_} = $q->param($_) for $q->param;
    print "<pre>".Data::Dumper->Dump([\%ENV, $form], ['*ENV', 'form'])."</pre>";
}

DESCRIPCIÓN

Aunque Net::Server::HTTP no entra en el paralelismo normal de los otros sabores de Net::Server, el manejo de solicitudes HTTP es una característica solicitada con frecuencia y es un protocolo estándar y simple.

Net::Server::HTTP comienza con el tipo base MultiType, que por defecto es Net::Server::PreFork. Es fácil cambiarlo a cualquiera de los otros sabores de Net::Server pasando server_type => $otro_sabor en la configuración del servidor. El puerto también se ha establecido por defecto en el puerto 80, pero podría cambiarse fácilmente a otro a través de la configuración del servidor. También puede añadir SSL muy fácilmente incluyendo proto=>"ssl" y proporcionando un SSL_cert_file y SSL_key_file.

Por ejemplo, aquí hay un servidor básico que se vinculará a todas las interfaces, hablará HTTP en el puerto 8080 y HTTPS en 8443, y hablará tanto IPv4 como IPv6 si está disponible.

use base qw(Net::Server::HTTP);
__PACKAGE__->run(
    port  => [8080, "8443/ssl"],
    ipv   => '*', # IPv6 si está disponible
    SSL_key_file  => '/my/key',
    SSL_cert_file => '/my/cert',
);

MÉTODOS

"_init_access_log"
Se utiliza para abrir e inicializar cualquier access_log solicitado (ver access_log_file y access_log_format).
"_tie_client_stdout"
Se utiliza para inicializar el análisis automático de las cabeceras de respuesta.
"process_http_request"
Se le pasará el manejador del cliente, y tendrá STDOUT y STDIN enlazados al cliente.

Durante este método, el %ENV se habrá establecido a un entorno de estilo CGI estándar. Deberá asegurarse de imprimir la cabecera Content-type. Este es un cambio con respecto a las otras clases base estándar de Net::Server.

Durante este método, puede leer de %ENV y STDIN como en una solicitud HTTP normal en otros servidores web. Puede imprimir en STDOUT y Net::Server se encargará de la negociación de cabeceras por usted.

Nota: Net::Server::HTTP no tiene concepto de raíz de documentos ni alias de scripts ni manejo por defecto de contenido estático. Eso depende del consumidor de Net::Server::HTTP para resolverlo.

Net::Server::HTTP viene con una visualización básica de %ENV instalada como método por defecto process_http_request.

"process_request"
Este método ha sido sobrescrito en Net::Server::HTTP; no debe usarlo mientras use Net::Server::HTTP. Este método sobrescrito analiza el entorno y configura alarmas de solicitud y maneja fallos de terminación. Llama a process_http_request una vez que la solicitud está lista y las cabeceras han sido analizadas.
"request_denied_hook"
Este método ha sido sobrescrito para llamar a send_400. Este es un comportamiento nuevo. Para obtener el comportamiento anterior (donde el cliente se cerraba sin ninguna indicación), simplemente proporcione
"process_headers"
Se utiliza para leer las cabeceras entrantes y establecer la ENV.
"_init_http_request_info"
Se llama al final de process_headers. Inicializa el contenido de http_request_info.
"http_request_info"
Devuelve un hashref de información específica de la solicitud actual. Esta información se utilizará para el registro más adelante.
"send_status"
Toma un estado HTTP, un mensaje opcional, un cuerpo opcional y un flag generate_body opcional. Envía las cabeceras correctas. 
$self->send_status(500);
$self->send_status(500, 'Internal Server Error');
$self->send_status(500, 'Internal Server Error', "<h1>Internal Server Error</h1><p>Msg</p>");
$self->send_status(500, undef, undef, ['Msg']);
"send_400"
Llama a send_status con 400 y los argumentos pasados como generate_body.
"send_500"
Llama a send_status con 500 y el argumento pasado a send_500.
c<log_http_request>
Se llama al final de post_process_request. El método por defecto busca el access_log_format por defecto y comprueba si el registro se inicializó durante _init_access_log. Si ambos existen, http_request_info se formatea usando http_log_format y el resultado se registra.
"http_log_format"
Toma una cadena de formato, y request_info y devuelve una cadena formateada. El formato debe seguir la especificación mod_log_config de apache. Al igual que en la especificación mod_log_config, las barras invertidas y las comillas deben escaparse con barras invertidas y también puede incluir caracteres \n y \t.

%%                %                 # un porcentaje
%a                ::1               # ip remota
%A                ::1               # ip local
%b                83                # tamaño de respuesta (- si es 0) Formato de Registro Común
%B                83                # tamaño de respuesta
%{bar}C           baz               # valor de la cookie con ese nombre
%D                916               # transcurrido en microsegundos
%{HTTP_COOKIE}e   bar=baz           # valor de %ENV con ese nombre
%f                -                 # nombre de archivo - no utilizado
%h                ::1               # host remoto si las búsquedas están activadas, de lo contrario, ip remota
%H                http              # protocolo de solicitud
%{Host}i          localhost:8080    # cabecera de solicitud con ese nombre
%I                336               # bytes recibidos incluyendo cabeceras
%l                -                 # nombre de registro remoto - no utilizado
%m                GET               # método de solicitud
%n                Just a note       # http_note con ese nombre
%{Content-type}o  text/html         # cabecera de salida con ese nombre
%O                189               # tamaño de respuesta incluyendo cabeceras
%p                8080              # puerto del servidor
%P                22999             # pid - no soporta %{tid}P
q                 ?hello=there      # cadena de consulta incluyendo ? (- de lo contrario)
r                 GET /bam?hello=there HTTP/1.1      # la primera línea de la solicitud
%s                200               # estado de respuesta
%u                -                 # usuario remoto - no utilizado
%U                /bam              # ruta de la solicitud (sin cadena de consulta)
%t                [06/Jun/2012:12:14:21 -0600]       # formato estándar de http_log_time
%t{%F %T %z}t     [2012-06-06 12:14:21 -0600]        # http_log_time con formato
%T                0                 # tiempo transcurrido en segundos
%v                localhost:8080    # http_log_vhost - implementación parcial
%V                localhost:8080    # http_log_vhost - implementación parcial
%X                -                 # Conexión completada y es 'close' (-)

Además, el análisis de registros permite los siguientes formatos.

%>s               200               # estado de la última solicitud
%<s               200               # estado de la solicitud original
%400a             -                 # ip remota si el estado es 400
%!400a            ::1               # ip remota si el estado no es 400
%!200a            -                 # ip remota si el estado no es 200

Hay pocas partes que no están completamente implementadas:

> y <    # No hay redirección interna
%I         # La respuesta a esto se basa en el tamaño de la cabecera y Content-length
             en lugar del número de bytes leídos real más correcto, aunque
             en casos comunes serían lo mismo.
%X         # No hay keepalive de conexión en el servidor por defecto.
%v y %V  # No hay hosts virtuales en el servidor HTTP por defecto.
%{tid}P    # Los servidores por defecto no están en hilos.

Vea la opción "access_log_format" para saber cómo establecer un formato diferente, así como para ver la cadena por defecto.

NAME

Net::Server::HTTP - A generic HTTP server class

SYNOPSIS

    use base qw(Net::Server::HTTP);

    __PACKAGE__->run;

    sub process_http_request {
        my $self = shift;

        # Default handler
        print "Content-type: text/html\n\n";
        print "<html><body>Hello World!</body></html>\n";
    }

DESCRIPTION

This module provides a generic HTTP server that can be used as a base class for building HTTP servers. It handles the low-level details of network communication, HTTP protocol parsing, and request processing, allowing you to focus on your application logic.

It is built on top of the Net::Server framework, inheriting its core functionality for network server management.

Subclasses and Methods

This class provides several methods that can be overridden or used by subclasses to customize behavior:

process_http_request
This is the primary method for handling incoming HTTP requests. Subclasses should override this method to implement their specific request handling logic. The method receives the server object ($self) as its only argument.
exec_cgi
This method is used to execute an external CGI script. It forks a new process and uses IPC::Open3 to communicate with the script, allowing it to read from STDIN and write to STDOUT/STDERR. 
use base qw(Net::Server::HTTP);
__PACKAGE__->run;
sub process_http_request {
    my $self = shift;
    if ($ENV{'PATH_INFO'} && $ENV{'PATH_INFO'} =~ s{^ (/foo) (?= $ | /) }{}x) {
       $ENV{'SCRIPT_NAME'} = $1;
       my $file = "/var/www/cgi-bin/foo"; # assuming this exists
       return $self->exec_cgi($file);
    }
    print "Content-type: text/html\n\n";
    print "<a href=/foo>Foo</a>";
}

At this first release, the parent server is not tracking the child script which may cause issues if the script is running when a HUP is received.

http_log_time
Used to implement the %t format.
http_log_env
Used to implement the %e format.
http_log_cookie
Used to implement the %C format.
http_log_header_in
used to implement the %i format.
http_log_note
Used to implement the %n format.
http_note
Takes a key and an optional value. If passed a key and value, sets the note for that key. Always returns the value. These notes currently only are used for %{key}n output format.
http_log_header_out
Used to implement the %o format.
http_log_pid
Used to implement the %P format.
http_log_vhost
Used to implement the %v and %V formats.
http_log_constat
Used to implement the %X format.
exec_trusted_perl
Allow for calling an external perl script. This method will still fork, but instead of using IPC::Open3, it simply requires the perl script. That means that the running script will be able to make use of any shared memory. It also means that the STDIN/STDOUT/STDERR handles the script is using are those directly bound by the server process. 
use base qw(Net::Server::HTTP);
__PACKAGE__->run;
sub process_http_request {
    my $self = shift;
    if ($ENV{'PATH_INFO'} && $ENV{'PATH_INFO'} =~ s{^ (/foo) (?= $ | /) }{}x) {
       $ENV{'SCRIPT_NAME'} = $1;
       my $file = "/var/www/cgi-bin/foo"; # assuming this exists
       return $self->exec_trusted_perl($file);
    }
    print "Content-type: text/html\n\n";
    print "<a href=/foo>Foo</a>";
}

At this first release, the parent server is not tracking the child script which may cause issues if the script is running when a HUP is received.

exec_fork_hook
This method is called after the fork of exec_trusted_perl and exec_cgi hooks. It is passed the pid (0 if the child) and the file being ran. Note, that the hook will not be called from the child during exec_cgi.
http_dispatch
Called if the default process_http_request and process_request methods have not been overridden and "app" configuration parameters have been passed. In this case this replaces the default echo server. You can also enable this subsystem for your own direct use by setting enable_dispatch to true during configuration. See the "app" configuration item. It will be passed a dispatch qr (regular expression) generated during _check_dispatch, and a dispatch table. The qr will be applied to path_info. This mechanism could be used to augment Net::Server::HTTP with document root and virtual host capabilities.

OPTIONS

In addition to the command line arguments of the Net::Server base classes you can also set the following options.

max_header_size
Defaults to 100_000. Maximum number of bytes to read while parsing headers.
server_revision
Defaults to Net::Server::HTTP/$Net::Server::VERSION.
timeout_header
Defaults to 15 - number of seconds to wait for parsing headers.
timeout_idle
Defaults to 60 - number of seconds a request can be idle before the request is closed.
access_log_file
Defaults to undef. If true, this represents the location of where the access log should be written to. If a special value of STDERR or /dev/stderr is passed, the access log entry will be written to the same location as the ERROR log. If a special value of STDOUT or /dev/stdout is passed, the access log entry will be written to standard out.
access_log_function
Can take a coderef or method name to call when an log_http_request method is called. Will be passed the formatted log access log message.

Note that functions depending upon stdout will not function during Net::Server::HTTP process_request because stdout is always tied for the client (and not restored after running).

access_log_format
Should be a valid apache log format that will be passed to http_log_format. See the http_log_format method for more information.

The default value is the NCSA extended/combined log format:

'%h %l %u %t "%r" %>s %b "%{Referer}i" "%{User-Agent}i"'
app
Takes one or more items and registers them for dispatch. Arguments may be supplied as an arrayref containing a location/target pairs, a hashref containing a location/target pairs, a bare code ref that will use "/" as the location and the codref as the target, a string with a space indicating "location target", a string containing "location=target", or finally a string that will be used as both location and target. For items passed as an arrayref or hashref, the target may be a coderef which will be called and should handle the request. In all other cases the target should be a valid executable suitable for passing to exec_cgi.

The locations will be added in the order that they are configured. They will be added to a regular expression which will be applied to the incoming PATH_INFO string. If the match is successful, the $ENV{'SCRIPT_NAME'} will be set to the matched portion and the matched portion will be removed from $ENV{'PATH_INFO'}.

Once an app has been passed, it is necessary for the server to listen on /. Therefore if "/" has not been specifically configured for dispatch, the first found dispatch target will also be used to handle "/".

For convenience, if the log_level is 2 or greater, the dispatch table is output to the log.

This mechanism is left as a generic mechanism suitable for overriding by servers meant to handle more complex dispatch. At the moment there is no handling of virtual hosts. At some point we will add in the default ability to play static content and likely for the ability to configure virtual hosts - or that may have to wait for a third party module.

app => "/home/paul/foo.cgi",
  # Dispatch: /home/paul/foo.cgi => home/paul/foo.cgi
  # Dispatch: / => home/paul/foo.cgi (default)
app => "../../foo.cgi",
app => "./bar.cgi",
app => "baz ./bar.cgi",
app => "bim=./bar.cgi",
  # Dispatch: /foo.cgi => ../../foo.cgi
  # Dispatch: /bar.cgi => ./bar.cgi
  # Dispatch: /baz => ./bar.cgi
  # Dispatch: /bim => ./bar.cgi
  # Dispatch: / => ../../foo.cgi (default)
app => "../../foo.cgi",
app => "/=./bar.cgi",
  # Dispatch: /foo.cgi => ../../foo.cgi
  # Dispatch: / => ./bar.cgi
# you could also do this on the commandline
net-server HTTP app ../../foo.cgi app /=./bar.cgi
# extended options when configured from code
Net::Server::HTTP->run(app => { # loses order of matching
  '/' => sub { ... },
  '/foo' => sub { ... },
  '/bar' => '/path/to/some.cgi',
});
Net::Server::HTTP->run(app => [
  '/' => sub { ... },
  '/foo' => sub { ... },
  '/bar' => '/path/to/some.cgi',
]);
default_content_type
Default is text/html. Set on any responses that have not yet passed a content-type
allow_body_on_all_statuses
By default content-type and printing a body are not allowed on 204, 304, or 1xx statuses. Set this flag to automatically send a content-type on those statuses as well.
