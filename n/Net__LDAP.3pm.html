NOMBRE

Net::LDAP - Protocolo ligero de acceso a directorios

SINOPSIS

use Net::LDAP;
$ldap = Net::LDAP->new( 'ldap.example.com' )  or  die "$@";
$mesg = $ldap->bind;                         # enlace anónimo
$mesg->code  and  die $mesg->error;          # comprobar si hay errores
$srch = $ldap->search( base   => "c=US",     # realizar una búsqueda
                       filter => "(&(sn=Barr)(o=Texas Instruments))"
                     );
$srch->code  and  die $srch->error;          # comprobar si hay errores
foreach $entry ($srch->entries) { $entry->dump; }
$mesg = $ldap->unbind;                       # cerrar sesión
$ldap = Net::LDAP->new( 'ldaps://ldap.example.com' )  or  die "$@";
# enlace simple con DN y contraseña
$mesg = $ldap->bind( 'cn=root, o=University of Michigan, c=us',
                     password => 'secret'
                   );
$mesg->code  and  die $mesg->error;          # comprobar si hay errores
$result = $ldap->add( 'cn=Barbara Jensen, o=University of Michigan, c=US',
                      attrs => [
                        cn          => ['Barbara Jensen', 'Barbs Jensen'],
                        sn          => 'Jensen',
                        mail        => 'b.jensen@umich.edu',
                        objectclass => ['top', 'person',
                                        'organizationalPerson',
                                        'inetOrgPerson' ],
                      ]
                    );
$result->code  and  warn "no se pudo añadir la entrada: ", $result->error;
$mesg = $ldap->unbind;                       # cerrar sesión

DESCRIPCIÓN

Net::LDAP es una colección de módulos que implementa una API de servicios LDAP para programas Perl. El módulo puede usarse para buscar directorios o realizar funciones de mantenimiento como añadir, eliminar o modificar entraciones.

Este documento asume que el lector tiene algún conocimiento del protocolo LDAP.

CONSTRUCTOR

new ( HOST, OPCIONES )
Crea un nuevo objeto Net::LDAP y abre una conexión al host especificado.

"HOST" puede ser un nombre de host o una dirección IP. El puerto TCP se puede especificar después del nombre del host seguido de dos puntos (como localhost:10389). El puerto TCP por defecto para LDAP es 389.

También puede especificar una URI, como 'ldaps://127.0.0.1:666' o 'ldapi://%2fvar%2flib%2fldap_sock'. Tenga en cuenta que los '%2f' en la ruta del socket LDAPI se traducirán a '/'. Esto es para soportar opciones de consulta LDAP como base, search, etc., aunque la parte de la consulta de la URI se ignorará en este contexto. Si el puerto no se especificó en la URI, el valor por defecto es 389 o 636 para los esquemas 'LDAP' y 'LDAPS' respectivamente.

"HOST" también puede ser una referencia a una matriz de hosts, pares host-puerto o URIs a probar. Cada uno se intentará en orden hasta que se establezca una conexión. Solo cuando todos fallen, se devolverá el resultado de "undef".

port => N
Puerto al que conectarse en el servidor remoto. Puede ser anulado por "HOST".
scheme => 'ldap' | 'ldaps' | 'ldapi'
Esquema de conexión a usar cuando no se usa una URI como "HOST". (Por defecto: ldap)
keepalive => 1
Si se proporciona, establece la opción SO_KEEPALIVE del socket dependiendo del valor booleano de la opción. (Por defecto: usar el valor por defecto del sistema)

Los fallos al cambiar la opción SO_KEEPALIVE del socket se ignoran.

timeout => N
Tiempo de espera pasado a IO::Socket al conectar al servidor remoto. (Por defecto: 120)
multihomed => N
Se pasará a IO::Socket como parámetro "MultiHomed" al conectar al servidor remoto.
localaddr => HOST
Se pasará a IO::Socket como parámetro "LocalAddr", que establece la dirección IP del cliente (en contraposición a la dirección IP del servidor).
debug => N
Establece el nivel de depuración. Ver el método debug para más detalles.
async => 1
Realiza todas las operaciones de forma asíncrona.
onerror => 'die' | 'warn' | 'undef' | sub { ... }
En modo síncrono, cambia lo que sucede cuando se detecta un error.
'die'
Net::LDAP provocará un error (croak) siempre que se detecte un error.
'warn'
Net::LDAP advertirá (warn) siempre que se detecte un error.
'undef'
Net::LDAP advertirá siempre que se detecte un error y "-w" esté activo. El método que se llamó devolverá "undef".

Nota: este valor es la cadena 'undef', no el valor "undef".

sub { ... }
La subrutina dada se llamará en contexto escalar con un único argumento, el mensaje de resultado. El valor devuelto será el valor de retorno para el método que se llamó.
version => N
Establece la versión del protocolo que se está utilizando (por defecto es LDAPv3). Esto es útil si desea hablar con un servidor antiguo y, por lo tanto, tiene que usar LDAPv2.
raw => REGEX
Usa REGEX para denotar los nombres de los atributos que se considerarán binarios en los resultados de búsqueda.

Cuando se proporciona esta opción, Net::LDAP convierte todos los valores de los atributos que no coinciden con esta REGEX en cadenas UTF-8 de Perl para que los operadores de Perl (coincidencia de patrones, ...) funcionen como se espera, incluso en cadenas con caracteres internacionales.

Si esta opción no se proporciona, los valores de los atributos se tratan como cadenas de bytes.

Ejemplo: raw => qr/(?i:^jpegPhoto|;binary)/

inet4 => N
inet6 => N
Intenta conectarse al servidor usando solo el protocolo IP especificado, es decir, IPv4 o IPv6. Si el protocolo seleccionado no es compatible, la conexión fallará.

El valor por defecto es usar cualquiera de los dos protocolos.

Ejemplo

$ldap = Net::LDAP->new( 'remote.host', async => 1 );

Las conexiones LDAPS tienen algunas opciones adicionales válidas, consulte el método start_tls para más detalles. Tenga en cuenta que el puerto por defecto para LDAPS es 636, y el valor por defecto para 'sslversion' es el valor utilizado por defecto por IO::Socket::SSL.

Para las conexiones LDAPI, HOST es en realidad la ubicación de un socket de dominio UNIX al que conectarse. La ubicación por defecto es '/var/run/ldapi'.

MÉTODOS

Cada uno de los siguientes métodos toma como argumentos un número de parámetros fijos seguidos de opciones, estas opciones se pasan de forma nombrada, por ejemplo

attrs => [ ATTR => VALOR, ... ]
"VALOR" debe ser una cadena si solo se desea un único valor, o una referencia a un array de cadenas si se desean múltiples valores.

Este argumento no se utiliza si "DN" es un objeto Net::LDAP::Entry.

control => CONTROL
control => [ CONTROL, ... ]
Ver "CONTROLS" abajo
callback => CALLBACK
Ver "CALLBACKS" abajo

Ejemplo

bind ( DN, OPCIONES )
Se conecta (inicia sesión) al servidor. "DN" es el DN con el que se inicia sesión. Se puede realizar una conexión anónima llamando a bind sin argumentos.
control => CONTROL
control => [ CONTROL, ... ]
Ver "CONTROLS" abajo
callback => CALLBACK
Ver "CALLBACKS" abajo
noauth | anonymous => 1
Inicia sesión sin contraseña. El valor pasado con esta opción se ignora.
password => PASSWORD
Inicia sesión con la contraseña dada.
sasl => SASLOBJ
Inicia sesión utilizando un mecanismo SASL. El argumento proporcionado debe ser una subclase de Authen::SASL o una conexión de cliente Authen::SASL llamando a "client_new" en un objeto Authen::SASL.

Si se pasa un objeto Authen::SASL, se llamará a "client_new" para crear un objeto de conexión de cliente. El nombre de host pasado por "Net::LDAP" a "client_new" se puede establecer usando la opción "sasl_host" abajo. Si esto no es correcto para su entorno, considere llamar a "client_new" usted mismo y pasar el objeto de conexión de cliente como "SASLOBJ".

sasl_host => SASLHOST
Al iniciar sesión usando SASL, permite que el nombre de host utilizado en la comunicación SASL difiera del nombre de host al que se está conectado.

Si "SASLHOST" se evalúa como TRUE, entonces se utiliza como nombre de host SASL.

Si se evalúa como FALSE, entonces el valor se determina llamando a "peerhost" en el socket. En versiones anteriores de Net::LDAP este era el comportamiento estándar, pero resultó causar más problemas de los que solucionaba.

Cuando la opción no se proporciona, el nombre de host SASL utilizado por defecto es el nombre de host / dirección IP tomados del parámetro "HOST" al conectar.

Ejemplo

$mesg = $ldap->bind; # Conexión anónima
$mesg = $ldap->bind( $dn, password => $password );
# $sasl es un objeto de la clase Authen::SASL
$mesg = $ldap->bind( $dn, sasl => $sasl, version => 3 );

modify ( DN, OPCIONES )
Modifica el contenido de la entrada dada por "DN" en el servidor. "DN" puede ser una cadena o un objeto Net::LDAP::Entry.
add => { ATTR => VALOR, ... }
Añade más atributos o valores a la entrada. "VALOR" debe ser una cadena si solo se desea un único valor en el atributo, o una referencia a un array de cadenas si se desean múltiples valores. 
$mesg = $ldap->modify( $dn,
  add => {
    description => 'Lista de miembros',    # Añadir atributo de descripción
    member      => [
      'cn=miembro1,ou=people,dc=example,dc=com',    # Añadir al atributo
      'cn=miembro2,ou=people,dc=example,dc=com',
    ]
  }
);
delete => [ ATTR, ... ]
Elimina atributos completos de la entrada. 
$mesg = $ldap->modify( $dn,
  delete => ['member','description'] # Eliminar atributos
);
delete => { ATTR => VALOR, ... }
Elimina valores individuales de un atributo. "VALOR" debe ser una cadena si solo se está eliminando un único valor del atributo, o una referencia a un array de cadenas si se están eliminando múltiples valores.

Si "VALOR" es una referencia a un array vacío o si se están eliminando todos los valores existentes del atributo, entonces el atributo se eliminará de la entrada.

$mesg = $ldap->modify( $dn,
  delete => {
    description => 'Lista de miembros',
    member      => [
      'cn=miembro1,ou=people,dc=example,dc=com',    # Eliminar miembros
      'cn=miembro2,ou=people,dc=example,dc=com',
    ],
    seeAlso => [],   # Eliminar atributo
  }
);
replace => { ATTR => VALOR, ... }
Reemplaza cualquier valor existente en cada atributo dado con "VALOR". "VALOR" debe ser una cadena si solo se desea un único valor en el atributo, o una referencia a un array de cadenas si se desean múltiples valores. Una referencia a un array vacío eliminará el atributo completo. Si el atributo no existe previamente en la entrada, se creará. 
$mesg = $ldap->modify( $dn,
  replace => {
    description => 'Nueva Lista de miembros', # Cambiar la descripción
    member      => [ # Reemplazar toda la lista con estos
      'cn=miembro1,ou=people,dc=example,dc=com',
      'cn=miembro2,ou=people,dc=example,dc=com',
    ],
    seeAlso => [],   # Eliminar atributo
  }
);
increment => { ATTR => VALOR, ... }
Incrementa atómicamente el valor existente en cada atributo dado por el "VALOR" proporcionado. Los atributos deben tener sintaxis de entero, o ser de otra manera "incrementables". Tenga en cuenta que esto funcionará
El servidor solo funciona si el servidor anuncia soporte para LDAP_FEATURE_MODIFY_INCREMENT. Utilice "supported_feature" en Net::LDAP::RootDSE para verificar esto.
$mesg = $ldap->modify( $dn,
  increment => {
    uidNumber => 1 # incrementa uidNumber en 1
  }
);
changes => [ OP => [ ATTR => VALUE ], ... ]
Este es un alternativo a add, delete, replace y increment, donde toda la operación puede ser proporcionada en un solo argumento. "OP" debe ser add, delete, replace o increment. "VALUE" debe ser una cadena o una referencia a un array de cadenas, como antes.

Utilice esta forma si desea controlar el orden en el que se realizarán las operaciones.

$mesg = $ldap->modify( $dn,
  changes => [
    add => [
      description => 'Una descripción',
      member      => $newMember,
    ],
    delete => [
      seeAlso => [],
    ],
    add => [
      anotherAttribute => $value,
    ],
  ]
);
control => CONTROL
control => [ CONTROL, ... ]
Ver "CONTROLS" abajo.
callback => CALLBACK
Ver "CALLBACKS" abajo.

Ejemplo

$mesg = $ldap->modify( $dn, add => { sn => 'Barr' } );
$mesg = $ldap->modify( $dn, delete => [qw(faxNumber)] );
$mesg = $ldap->modify( $dn, delete => { 'telephoneNumber' => '911' } );
$mesg = $ldap->modify( $dn, replace => { 'mail' => 'gbarr@pobox.com' } );
$mesg = $ldap->modify( $dn,
                       changes => [
                           # add sn=Barr
                         add     => [ sn => 'Barr' ],
                           # delete all fax numbers
                         delete  => [ faxNumber => []],
                           # delete phone number 911
                         delete  => [ telephoneNumber => ['911']],
                           # change email address
                         replace => [ mail => 'gbarr@pobox.com']
                       ]
                     );
search ( OPTIONS )
Busca en el directorio usando un filtro dado. Esto puede usarse para leer atributos de una sola entrada, de entradas inmediatamente debajo de una entrada específica o de todo el subárbol de entradas.

El resultado es un objeto de clase Net::LDAP::Search.

base => DN
El DN que es la entrada del objeto base relativa a la cual se realiza la búsqueda.
scope => 'base' | 'one' | 'sub' | 'subtree' | 'children'
Por defecto, la búsqueda se realiza en todo el árbol debajo del objeto base especificado. Esto puede cambiarse especificando un parámetro "scope" con uno de los siguientes valores:
base
Busca solo en la entrada del objeto base.
one
Busca en las entradas inmediatamente debajo de la entrada del objeto base.
sub
subtree
Busca en todo el subárbol de entradas (incluyendo la propia entrada del objeto base). Este es el valor por defecto.
children
Busca en todo el subárbol de entradas debajo de la entrada del objeto base, excepto la propia entrada del objeto base.

Nota: El scope children requiere la extensión de características de LDAPv3.

deref => 'never' | 'search' | 'find' | 'always'
Por defecto, los alias se desreferencian para localizar la entrada del objeto base de la búsqueda, pero no cuando se busca en los subordinados de la entrada del objeto base. Esto puede cambiarse especificando un parámetro "deref" con uno de los siguientes valores:
never
No desreferenciar alias durante la búsqueda ni al localizar la entrada del objeto base de la búsqueda.
search
Desreferenciar alias en los subordinados de la entrada del objeto base durante la búsqueda, pero no en la localización de la entrada del objeto base de la búsqueda.
find
Desreferenciar alias en la localización de la entrada del objeto base de la búsqueda, pero no cuando se busca en los subordinados de la entrada del objeto base. Este es el valor por defecto.
always
Desreferenciar alias tanto en la búsqueda como en la localización de la entrada del objeto base de la búsqueda.
sizelimit => N
Un límite de tamaño que restringe el número máximo de entradas a devolver como resultado de la búsqueda. Un valor de 0, y el valor por defecto, significa que no se solicita un límite. Los servidores pueden imponer un máximo de entradas a devolver.
timelimit => N
Un límite de tiempo que restringe el tiempo máximo (en segundos) permitido para una búsqueda. Un valor de 0 (por defecto), significa que no se solicita un límite de tiempo.
typesonly => 1
Se devuelven solo tipos de atributos (sin valores). Normalmente, se devuelven ambos tipos de atributos y sus valores.
filter => FILTER
Un filtro que define las condiciones que una entrada del directorio debe cumplir para ser devuelta por la búsqueda. Esto puede ser una cadena o un objeto Net::LDAP::Filter. Los valores dentro de los filtros pueden necesitar ser escapados para evitar problemas de seguridad; vea Net::LDAP::Filter para una definición del formato del filtro, incluyendo las reglas de escapado.
attrs => [ ATTR, ... ]
Una lista de atributos que se devuelven para cada entrada que coincide con el filtro de búsqueda.

Si no se especifica, los servidores devolverán los atributos que son accesibles por defecto dadas tus credenciales de bind.

Algunos atributos adicionales como "createTimestamp" y otros atributos operativos también pueden estar disponibles:

$mesg = $ldap->search( ... ,
                       attrs => ['createTimestamp']
                     );

Para recuperar atributos por defecto y otros atributos, usa '*'.

$mesg = $ldap->search( ... ,
                       attrs => ['*', 'createTimestamp']
                     );

Para recuperar ningún atributo (el servidor solo devuelve los DN de las entradas coincidentes), usa '1.1':

$mesg = $ldap->search( ... ,
                       attrs => ['1.1']
                     );
control => CONTROL
control => [ CONTROL, ... ]
Ver "CONTROLS" abajo.
callback => CALLBACK
Ver "CALLBACKS" abajo.
raw => REGEX
Usa REGEX para denotar los nombres de atributos que se consideran binarios en los resultados de la búsqueda.

Cuando esta opción se proporciona, Net::LDAP convierte todos los valores de atributos que no coincidan con este REGEX en cadenas Perl UTF-8 para que los operadores Perl regulares (patrón de búsqueda, etc.) puedan operar como se espera incluso sobre cadenas con caracteres internacionales.

Si esta opción no se proporciona, los valores de atributos se tratan como cadenas de bytes.

El valor proporcionado aquí sobreescribe el valor heredado del constructor.

Ejemplo: raw => qr/(?i:^jpegPhoto|;binary)/

                       base   => $base_dn,
                       scope  => 'sub',

start_tls ( OPTIONS )
Llamar a este método convertirá la conexión existente en una conexión usando Transport Layer Security (TLS), que proporciona una conexión cifrada. Esto es *solo* posible si la conexión utiliza LDAPv3 y requiere que el servidor anuncie soporte para LDAP_EXTENSION_START_TLS. Use "supported_extension" en Net::LDAP::RootDSE para verificar esto.
verify => 'none' | 'optional' | 'require'
¿Cómo verificar la certificación del servidor:
none
El servidor puede proporcionar una certificación pero no se verificará - esto puede significar que estás conectado a un servidor incorrecto.
optional
Verifica solo cuando el servidor ofrece una certificación.
require
El servidor debe proporcionar una certificación y esta debe ser válida.

Si establece verify a optional o require, también debe establecer cafile o capath. La opción más segura es require.

sslversion => 'sslv2' | 'sslv3' | 'sslv23' | 'tlsv1' | 'tlsv1_1' | 'tlsv1_2'
Define la versión del protocolo SSL/TLS a usar. El valor por defecto es el valor que usa IO::Socket::SSL por defecto.

Ver "SSL_version" en IO::Socket::SSL para más detalles.

sslserver => SSLHOST
Permite cambiar el nombre del servidor para su uso en la verificación de la certificación, en caso de que el nombre del objetivo no coincida con el certificado del servidor LDAP. Si no se especifica, el valor por defecto es el nombre del HOST conectado.

Ver "SSL_verifycn_name" en IO::Socket::SSL para más detalles.

ciphers => CIPHERS
Especifica el subconjunto de suites de cifrado permitidas para esta conexión.

If the control being requested requires a value then this element should hold the value for the server.

CALLBACKS

Most of the above commands accept a callback option. This option should be a reference to a subroutine. This subroutine will be called for each packet received from the server as a response to the request sent.

When the subroutine is called the first argument will be the Net::LDAP::Message object which was returned from the method.

If the request is a search then multiple packets can be received from the server. Each entry is received as a separate packet. For each of these the subroutine will be called with a Net::LDAP::Entry object as the second argument.

During a search the server may also send a list of references. When such a list is received then the subroutine will be called with a Net::LDAP::Reference object as the second argument.

LDAP ERROR CODES

Net::LDAP also exports constants for the error codes that can be received from the server, see Net::LDAP::Constant.
