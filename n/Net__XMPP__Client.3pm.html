NOMBRE

Net::XMPP::Client - Módulo Cliente XMPP

SINOPSIS

Net::XMPP::Client es un módulo que proporciona a los desarrolladores un acceso fácil al Protocolo de Mensajería y Presencia Extensible (XMPP).

DESCRIPCIÓN

Client.pm utiliza Protocol.pm para proporcionar suficientes API de alto nivel y automatización de las API de bajo nivel para que escribir un Cliente XMPP en Perl sea trivial. Para aquellos que deseen trabajar con el bajo nivel, también pueden hacerlo, pero esas funciones se cubren en la documentación de cada módulo.

Net::XMPP::Client proporciona funciones para conectarse a un servidor XMPP, iniciar sesión, enviar y recibir mensajes, establecer información personal, crear una nueva cuenta de usuario, gestionar la lista de contactos y desconectarse. Puede usar todas o ninguna de las funciones, no hay ningún requisito.

Para obtener más información sobre cómo está escrito Net::XMPP, consulte la ayuda de Net::XMPP.

Para obtener una lista completa de las funciones de alto nivel disponibles, consulte Net::XMPP::Protocol.

Funciones Básicas

use Net::XMPP;
$Con = Net::XMPP::Client->new();
$Con->SetCallbacks(...);
$Con->Execute(hostname=>"jabber.org",
              username=>"bob",
              password=>"XXXX",
              resource=>"Trabajo"
             );

Para obtener la lista de funciones disponibles, consulte Net::XMPP::Protocol.

$Con->Disconnect();

MÉTODOS

Funciones Básicas

new

new(debuglevel=>0|1|2,
    debugfile=>cadena,
    debugtime=>0|1)

Crea el objeto Cliente. debugfile debe establecerse en la ruta del archivo de registro de depuración donde se escribirá. Si se establece en "stdout", la depuración irá allí. debuglevel controla la cantidad de depuración. Para obtener más información sobre la configuración válida para debuglevel, debugfile y debugtime, consulte Net::XMPP::Debug.

Connect

Connect(hostname=>cadena,
        port=>entero,
        timeout=>int,
        connectiontype=>cadena,
        tls=>0|1,
        srv=>0|1,
        componentname=>cadena)

Abre una conexión al servidor listado en hostname (por defecto localhost), en el puerto (por defecto 5222), utilizando el connectiontype listado (por defecto tcpip). Los dos tipos de conexión disponibles son:

tcpip  socket TCP estándar
http   socket TCP, pero con las
       cabeceras necesarias para hablar
       a través de un proxy web

Si especifica tls, se usará TLS si está disponible como característica.

Si se especifica srv Y Net::DNS está instalado y se puede cargar, se enviará una consulta SRV a srv.hostname y se procesarán los resultados para reemplazar el nombre de host y el puerto. Si la consulta falla o Net::DNS no se puede cargar, el nombre de host y el puerto se dejan solos como los predeterminados.

Alternativamente, puede especificar manualmente componentname como la parte del dominio del jid y dejar hostname establecido en el nombre de host real del servidor XMPP.

Execute

Execute(hostname=>cadena,       
        port=>int,              
        tls=>0|1,               
        username=>cadena,       
        password=>cadena,       
        resource=>cadena,       
        register=>0|1,          
        connectiontype=>cadena, 
        connecttimeout=>cadena, 
        connectattempts=>int,   
        connectsleep=>int,      
        processtimeout=>int)

Bucle interno genérico para manejar la conexión al servidor, la llamada a Process y la reconexión si se pierde la conexión. Hay cinco callbacks disponibles que se llaman en varios lugares:

onconnect - cuando el cliente ha
            establecido una conexión.
onauth - cuando se establece la conexión
         y el usuario ha sido
         autenticado. Esencialmente,
         es cuando puedes empezar a
         hacer cosas como Cliente.
         Como enviar presencia, obtener
         tu lista de contactos, etc...
 onprocess - este es el bucle más
             interno y por lo tanto se
             llama con mucha frecuencia.
             Ten mucho, mucho cuidado con
             lo que pones aquí, ya que
             puede afectar *DRÁSTICAMENTE*
             al rendimiento.
 ondisconnect - cuando el cliente
                se desconecta del
                servidor.
 onexit - cuando la función se rinde
          intentando conectar y
          sale.

Los argumentos se pasan directamente a la función Connect, excepto por connectattempts y connectsleep. connectattempts es el número de veces que el Componente intentará conectarse antes de rendirse. -1 significa intentar siempre. El valor predeterminado es -1. connectsleep es el número de segundos que se esperará entre cada intento de conexión.

Si especifica register=>1, el Cliente intentará registrar la cuenta especificada por usted, si no existe.

Process

Process(entero)

Toma el período de tiempo de espera como argumento. Si no se especifica tiempo de espera, la función se bloquea hasta que se recibe un paquete. De lo contrario, espera ese número de segundos y luego sale para que su programa pueda continuar haciendo cosas útiles. NOTA: Esto es importante para las GUI. Necesita dejar tiempo para procesar los comandos de la GUI, incluso si está esperando paquetes. Los siguientes son los posibles valores de retorno y lo que significan:

  1   - Estado ok, datos recibidos.
  0   - Estado ok, no se recibieron datos.
undef - Estado no ok, detener el procesamiento.

IMPORTANTE: Debe comprobar la salida de cada Process. Si obtiene un undef, la conexión se ha roto y debe actuar en consecuencia.

Disconnect

Disconnect()

Cierra la conexión al servidor.

Connected

Connected()

Devuelve 1 si el Transporte está conectado al servidor y 0 si no.
