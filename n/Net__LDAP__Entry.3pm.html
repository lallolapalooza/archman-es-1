Net::LDAP::Entry(3) Documentación de Perl aportada por el usuario Net::LDAP::Entry(3)

NOMBRE

Net::LDAP::Entry - Un objeto de entrada LDAP

SINOPSIS

use Net::LDAP;
$ldap = Net::LDAP->new ( $host );
$mesg = $ldap->search ( @search_args );
my $max = $mesg->count;
for ( $i = 0 ; $i < $max ; $i++ ) {
  my $entry = $mesg->entry ( $i );
  foreach my $attr ( $entry->attributes ) {
    print join( "\n ", $attr, $entry->get_value( $attr ) ), "\n";
  }
}
# o
use Net::LDAP::Entry;
$entry = Net::LDAP::Entry->new;
$entry->dn($dn);
$entry->add (
  attr1 => 'valor1',
  attr2 => [ qw(valor1 valor2) ]
);
$entry->delete ( 'sin_interes' );
$entry->replace (
  attr1 => 'nuevovalor',
  attr2 => [ qw(nuevos valores) ]
);
$entry->update ( $ldap ); # actualizar servidor de directorio
$entry2 = $entry->clone; # copia la entrada
# nueva sintaxis alternativa
$entry = Net::LDAP::Entry->new ( $dn,
  attr1 => 'valor1',
  attr2 => [ qw(valor1 valor2) ]
)->add(
  attr3   => 'valor'
)->update( $ldap );

DESCRIPCIÓN

El objeto Net::LDAP::Entry representa una única entrada en el directorio. Es un contenedor para pares de atributos-valores.

Un objeto Net::LDAP::Entry se puede usar en dos situaciones. La primera y probablemente más común es en el resultado de una búsqueda en el servidor de directorio.

La otra es cuando se crea un nuevo objeto localmente y luego se envía un único comando al servidor de directorio para añadir, modificar o reemplazar una entrada. Las entradas para este propósito también se pueden crear leyendo un archivo LDIF con el módulo Net::LDAP::LDIF.

CONSTRUCTORES

new ( )
Crea un nuevo objeto de entrada con el tipo de cambio establecido a 'add'. Opcionalmente, puedes proporcionar un DN y una lista de argumentos pasados al método add. 
Net::LDAP::Entry->new()
# o
Net::LDAP::Entry->new( $dn )
# o
Net::LDAP::Entry->new( $dn ,
 objectClass => [qw( top posixAccount )] , uid => 'admin'
)
clone ( )
Devuelve una copia del objeto Net::LDAP::Entry.

MÉTODOS

add ( ATTR => VALOR, ... )
Añade más atributos o valores a la entrada y devuelve la propia entrada. Cada "VALOR" debe ser una cadena si solo se desea un valor en el atributo, o una referencia a un array de cadenas si se desean múltiples valores. Los valores proporcionados se añadirán a los valores que ya existen para los atributos dados. 
$entry->add ( 'sn' => 'Barr' );
$entry->add ( 'street' => [ '1 some road','nowhere' ] );

NOTA: estos cambios son locales al cliente y no aparecerán en el servidor de directorio hasta que se llame al método "update". Como "add" devuelve la entrada, puedes escribir algo como.

$entry->add ( 'sn' => 'Barr' )->update( $ldap );
attributes ( OPCIONES )
Devuelve una lista de atributos en esta entrada
nooptions => 1
Devuelve una lista de los nombres de atributos excluyendo cualquier opción. Por ejemplo, para la entrada 
name: Graham Barr
name;en-us: Bob
jpegPhoto;binary: **datos binarios**

entonces

@valores = $entry->attributes;
print "predeterminado: @valores\n";
@valores = $entry->attributes ( nooptions => 1 );
print "sin opciones: @valores\n";

mostrará

predeterminado: name name;en-us jpegPhoto;binary
sin opciones: name jpegPhoto
changetype ( )
Devuelve el tipo de operación que se realizará cuando se llame al método update.
changetype ( TIPO )
Establece el tipo de operación que se realizará cuando se llame al método update a "TIPO". Devuelve la propia entrada.

Los valores posibles para "TIPO" son

add
El método update llamará al método add en el objeto cliente, lo que resultará en que la entrada se añada al servidor de directorio.
delete
El método update llamará al método delete en el objeto cliente, lo que resultará en que la entrada se elimine del servidor de directorio. 
$entry->delete->update( $ldap )
modify
El método update llamará al método modify en el objeto cliente, lo que resultará en que cualquier cambio realizado localmente se aplique a la entrada en el servidor de directorio.
moddn/modrdn
El método update llamará al método moddn en el objeto cliente, lo que resultará en que cualquier cambio de DN realizado localmente se aplique a la entrada en el servidor de directorio. Estos cambios de DN se especifican estableciendo los atributos de entrada newrdn, deleteoldrdn y (opcionalmente) newsuperior.
delete ( )
Elimina la entrada del servidor en la próxima llamada a "update".
delete ( ATTR => [ VALOR, ... ], ... )
Elimina los valores de los atributos dados de la entrada. Los valores son referencias a arrays; pasar una referencia a un array vacío es lo mismo que pasar "undef", y resultará en que el atributo completo se elimine. Por ejemplo: 
$entry->delete ( 'mail' => [ 'foo.bar@example.com' ] );
$entry->delete ( 'description' => [ ], 'streetAddress' => [ ] );

NOTA: estos cambios son locales al cliente y no aparecerán en el servidor de directorio hasta que se llame al método "update".

dn ( )
Obtiene el DN de la entrada.
dn ( DN )
Establece el DN para la entrada y devuelve el valor anterior.

NOTA: estos cambios son locales al cliente y no aparecerán en el servidor de directorio hasta que se llame al método "update".

ldif ( OPCION => VALOR, ... )
Devuelve la entrada como una cadena LDIF. Las opciones posibles son todas las opciones que permite "new" en Net::LDAP::LDIF, con dos tratadas especialmente:
change => VALOR
Si se le da un valor verdadero, el LDIF se generará como un registro de cambio. Si es falso, el LDIF generado representará el contenido de la entrada. Si no se especifica, será verdadero por defecto si la entrada tiene cambios y falso si no se han aplicado cambios a la entrada.
version => VALOR
Sin importar el valor que se pase, se ignorará y se tratará como si se hubiera dado 0.
dump ( [ FILEHANDLE ] )
Vuelca la entrada al filehandle dado.

Este método está destinado a fines de depuración y no trata los atributos binarios de forma especial. Tampoco maneja correctamente las entradas resultantes de registros de cambios LDIF.

Ver Net::LDAP::LDIF sobre cómo generar salida LDIF.

Si se omite "FILEHANDLE" se usa por defecto "STDOUT".

exists ( ATTR )
Devuelve "TRUE" si la entrada tiene un atributo llamado "ATTR".
get_value ( ATTR, OPCIONES )
Obtiene los valores para el atributo "ATTR". En contexto de lista devuelve todos los valores para el atributo dado, o la lista vacía si el atributo no existe. En contexto escalar devuelve el primer valor para el atributo o undef

NAME

Net::LDAP::Entry ‐ An LDAP entry

SYNOPSIS

  use Net::LDAP;
  use Net::LDAP::Entry;

  my $entry = Net::LDAP::Entry->new(
    dn = > 'cn=Graham Barr,dc=example,dc=com',
    attrs = > [
      'cn' = > 'Graham Barr',
      'mail' = > [ 'graham@example.com', 'grahamb@bar.com' ],
      'uid' = > 'gbarr',
    ],
  );

  # Get an attribute value
  my $cn = $entry->get_value( 'cn' ); # returns 'Graham Barr'

  # Get all values for an attribute
  my @mail = $entry->get_value( 'mail', no_options = > 1 ); # returns ('graham@example.com', 'grahamb@bar.com')

  # Add a new attribute
  $entry->add( 'department' = > 'Sales' );

  # Replace an existing attribute
  $entry->replace( 'mail' = > 'new_email@example.com' );

  # Delete an attribute
  $entry->delete( 'uid' );

DESCRIPTION

Net::LDAP::Entry is an object that represents a single entry in an LDAP directory. It contains the Distinguished Name (DN) of the entry and a hash reference of the entries attributes.

The attributes are stored as a hash reference where the keys are the attribute names and the values are references to arrays of attribute values.

  # An entry like:
  #   dn: cn=Graham Barr,dc=example,dc=com
  #   cn: Graham Barr
  #   mail: graham@example.com
  #   mail: grahamb@bar.com
  #   uid: gbarr
  #
  # would be represented internally as:
  #
  # dn => 'cn=Graham Barr,dc=example,dc=com',
  # attrs => {
  #   'cn'   => [ 'Graham Barr' ],
  #   'mail' => [ 'graham@example.com', 'grahamb@bar.com' ],
  #   'uid'  => [ 'gbarr' ],
  # }

CONSTRUCTORS

new ( DN [, OPTIONS ] )
Creates a new Net::LDAP::Entry object.
new ( ATTRHASH )
Creates a new Net::LDAP::Entry object from a hash reference of attributes. The DN must be supplied as one of the keys in the hash, keyed as “dn”.

The valid OPTIONS are:

dn => DN
The Distinguished Name of the entry.
attrs => ATTRHASH
A hash reference containing the attributes for the entry. The keys are attribute names and the values are either a single attribute value or a reference to an array of attribute values.

METHODS

add ( ATTR => VALUE, ... )
Adds one or more attributes to the entry. If an attribute already exists, the new values will be appended to the list of existing values.
delete ( ATTR => VALUE, ... )
delete ( ATTR )
Deletes one or more values from an attribute. If only the attribute name is provided, the entire attribute is deleted. If values are provided, only those specific values are removed.
dn ( [ NEWDN ] )
Returns the DN of the entry. If NEWDN is provided, the DN of the entry is changed.
get ( ATTR [, OPTIONS ] )
Returns a reference to an array containing all the values for the given attribute, or "undef" if the attribute does not exist.
get_value ( ATTR [, OPTIONS ] )
Returns the value of an attribute. If the attribute has multiple values, only the first value is returned, unless the asref option is used. If the attribute does not exist, "undef" is returned.
alloptions => 1
The result will be a hash reference. The keys of the hash will be the options and the hash value will be the values for those attributes. For example if an entry had: 
name: Graham Barr
name;en-us: Bob

Then a get for attribute "name" with alloptions set to a true value

$ref = $entry->get_value ( 'name', alloptions => 1 );

will return a hash reference that would be like

{
  ''       => [ 'Graham Barr' ],
  ';en-us' => [ 'Bob' ]
}

If alloptions is not set or is set to false only the attribute values for the exactly matching name are returned.

nooptions => 1
Instead of only returning the values of the exactly matching attribute name, get the attribute values of all attributes with the base name given. I.e. in the example above, calling 
@array = $entry->get_value ( 'name', nooptions => 1 );

will yield

( 'Graham Barr', 'Bob' )

The name of this option has neen chosen for consistency with the equally named option in the attributes method.

asref => 1
The result will be a reference to an array containing all the values for the attribute, or "undef" if the attribute does not exist. 
$scalar = $entry->get_value ( 'name' );

$scalar will be the first value for the "name" attribute, or "undef" if the entry does not contain a "name" attribute.

$ref = $entry->get_value ( 'name', asref => 1 );

$ref will be a reference to an array, which will have all the values for the "name" attribute. If the entry does not have an attribute called "name" then $ref will be "undef".

NOTE: In the interest of performance the array references returned by "get_value" may be references to structures held inside the entry object. These values and their contents should NOT be modified directly.

replace ( ATTR => VALUE, ... )
Similar to "add", except that the values given will replace any values that already exist for the given attributes.

NOTE: these changes are local to the client and will not appear on the directory server until the "update" method is called.

update ( CLIENT [, OPTIONS ] )
Update the directory server with any changes that have been made locally to the attributes of this entry. This means any calls that have been made to add, replace or delete since the last call to changetype or update was made.

This method can also be used to modify the DN of the entry on the server, by specifying moddn or modrdn as the changetype, and setting the entry attributes newrdn, deleteoldrdn, and (optionally) newsuperior.

"CLIENT" is a "Net::LDAP" object where the update will be sent to.

"OPTIONS" may be options to the "Net::LDAP" actions on CLIENT corresponding to the entry's changetype.

The result will be an object of type Net::LDAP::Message as returned by the add, modify or delete method called on CLIENT.

Alternatively "CLIENT" can also be a "Net::LDAP::LDIF" object, that must be an LDIF file opened for writing.

In this case, the entry, together with any "OPTIONS" is passed as arguments to the "write_entry" method of the "CLIENT" object.

Here too, the result is an object class "Net::LDAP::Message". On error, the error code is "LDAP_OTHER" with the LDIF error message in the error text.
