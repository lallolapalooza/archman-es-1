NetworkManager-dispatcher(8) Servicios de gestión de red NetworkManager-dispatcher(8)

Nombre

NetworkManager-dispatcher - Disparar scripts de usuario para NetworkManager

Sintaxis

NetworkManager [OPCIONES...]

Descripción

El servicio NetworkManager-dispatcher es un servicio D-Bus activado que ejecuta scripts de usuario en respuesta a ciertos cambios en NetworkManager.

NetworkManager-dispatcher ejecutará scripts en la carpeta /etc/NetworkManager/dispatcher.d o subdirectorios en orden alfabético cuando ocurran eventos de red. Los archivos en /etc tienen prioridad sobre los identificados en /usr/lib. Cada script debe ser un archivo ejecutable regular propiedad de root. Además, no debe ser escribible por grupo o otros, y no debe tener el atributo setuid.

Cada script recibe dos argumentos: el primero es el nombre de la interfaz de la cual se realizó la operación, y el segundo es la acción. Para las acciones de dispositivos, la interfaz es el nombre de la interfaz de red adecuada para la configuración de IP. Por lo tanto, puede ser VPN_IP_IFACE, DEVICE_IP_IFACE o DEVICE_IFACE, según corresponda. Para la acción de hostname, el nombre del dispositivo es siempre "none". Para las acciones de connectivity-change y dns-change, el nombre del dispositivo es vacío.

Las acciones son:

pre-up

La interfaz está conectada a la red pero aún no está completamente activada. Los scripts que actúan en este evento deben estar colocados o enlazados en la carpeta /etc/NetworkManager/dispatcher.d/pre-up.d, y NetworkManager esperará a que el script se ejecute completamente antes de indicar a las aplicaciones que la interfaz está completamente activada.

up

La interfaz ha sido activada.

pre-down

La interfaz será desactivada pero aún no se ha desconectado de la red. Los scripts que actúan en este evento deben estar colocados o enlazados en la carpeta /etc/NetworkManager/dispatcher.d/pre-down.d, y NetworkManager esperará a que el script se ejecute completamente antes de desconectar la interfaz de su red. Nota: este evento no se emite en casos de desconexión forzada, como cuando el operador pierde conexión o una señal de red queda en el umbral. Solo se emite cuando hay oportunidad de manejar limpiamente una desconexión de red.

down

La interfaz ha sido desactivada.

vpn-pre-up

La conexión VPN está conectada a la red pero aún no está completamente activada. Los scripts que actúan en este evento deben estar colocados o enlazados en la carpeta /etc/NetworkManager/dispatcher.d/pre-up.d, y NetworkManager esperará a que el script se ejecute completamente antes de indicar a las aplicaciones que la conexión VPN está completamente activada.

vpn-up

Se ha activado una conexión VPN.

vpn-pre-down

La conexión VPN será desactivada pero aún no se ha desconectado de la red. Los scripts que actúan en este evento deben estar colocados o enlazados en la carpeta /etc/NetworkManager/dispatcher.d/pre-down.d, y NetworkManager esperará a que el script se ejecute completamente antes de desconectar la conexión VPN de su red. Nota: este evento no se emite en casos de desconexión forzada, como cuando la conexión VPN se termina inesperadamente o cuando se pierde la conectividad general. Solo se emite cuando hay oportunidad de manejar limpiamente una desconexión de conexión VPN.

vpn-down

Se ha desactivado una conexión VPN.

hostname

El nombre del sistema ha sido actualizado. Usa gethostname(2) para recuperarlo. El nombre de la interfaz (primer argumento) está vacío y no se establece ninguna variable de entorno para esta acción.

dhcp4-change

La concesión DHCPv4 ha cambiado (renovación, reaprovisionamiento, etc.).

dhcp6-change

La concesión DHCPv6 ha cambiado (renovación, reaprovisionamiento, etc.).

connectivity-change

El estado de conectividad de la red ha cambiado (sin conexión, conectado, etc.).

reapply

La conexión se ha reaplicado en el dispositivo.

dns-change

La configuración de DNS ha cambiado. Esta acción se dispara incluso si NetworkManager está configurado para no gestionar resolv.conf (por ejemplo, mediante dns=none). En tal caso, el script de disparo puede descubrir la configuración de DNS proporcionada por las conexiones actuales mirando al archivo /run/NetworkManager/resolv.conf.

device-add

Esta acción se llama cuando una conexión de tipo genérico tiene la propiedad generic.device-handler establecida. La propiedad indica el nombre de un script de disparo a ejecutar en la carpeta /etc/NetworkManager/dispatcher.d/device. Nota: a diferencia de otras acciones, solo se ejecutará un script.

El script debe realizar cualquier acción necesaria para crear la interfaz para la conexión de tipo genérico. En caso de éxito, devuelve 0. En caso de error, devuelve un valor no cero. El script puede devolver valores para NetworkManager escribiendo en la salida estándar; cada línea debe contener un nombre de clave seguido de '=' y el valor de la clave. Las claves actualmente entendidas son:

IFINDEX

Indica el índice de la interfaz creada por el script. Esta clave es obligatoria si el script tiene éxito; si no está definida, el activo fallará. La clave se ignora en caso de fallo del script.

ERROR

Indica un mensaje de error que explica el motivo del fallo del script. Se ignora cuando el script tiene éxito.

Como el servicio de disparo captura la salida estándar para analizar estas claves, cualquier cosa escrita en la salida estándar no aparecerá en el registro del servicio de disparo. Usa la salida de error para imprimir mensajes al registro (por ejemplo, para depuración). Solo se consideran los primeros 8 KiB de la salida estándar y, de ellos, solo las primeras 64 líneas; el resto se ignora.

device-delete

Esta acción es la opuesta a device-add y se llama para eliminar la interfaz de una conexión de tipo genérico. Todos los aspectos descritos para device-add también se aplican a esta acción, con la excepción de que la clave IFINDEX se ignora. No es necesario eliminar el enlace del kernel en el manejador ya que NetworkManager ya lo hace; por lo tanto, la acción es útil para cualquier limpieza adicional necesaria.

El entorno contiene más información sobre la interfaz y la conexión. Las siguientes variables están disponibles para usar en los scripts de disparo:

NM_DISPATCHER_ACTION

La acción de disparo como "up" o "dhcp4-change", idéntica al primer argumento de la línea de comandos. Desde NetworkManager 1.12.0.

CONNECTION_UUID

El UUID de la configuración de la conexión.

CONNECTION_ID

El nombre (ID) de la configuración de la conexión.

CONNECTION_DBUS_PATH

La ruta de D-Bus de NetworkManager para la conexión.

CONNECTION_FILENAME

El nombre del archivo de configuración de la conexión (si existe).

CONNECTION_EXTERNAL

Si es "1", indica que la conexión describe una configuración de red creada fuera de NetworkManager.

DEVICE_IFACE

El nombre de la interfaz de control de la interfaz del dispositivo. Dependiendo del tipo del dispositivo, difiere de DEVICE_IP_IFACE. Por ejemplo, para dispositivos ADSL, podría ser "atm0" o para dispositivos WWAN, podría ser "ttyUSB0".

DEVICE_IP_IFACE

El nombre de la interfaz IP del dispositivo. Esta es la interfaz de red en la cual se configurarán direcciones IP y rutas.

IP4_ADDRESS_N

La dirección IPv4 en formato "dirección/prefijo gateway", donde N es un número de 0 a (# direcciones IPv4 - 1). El elemento gateway en esta variable se considera obsoleto, usa IP4_GATEWAY en su lugar.

IP4_NUM_ADDRESSES

La variable contiene el número de direcciones IPv4 que el script puede esperar.

IP4_GATEWAY

La dirección IPv4 de la puerta de enlace en notación tradicional de números y puntos.

IP4_ROUTE_N

La ruta IPv4 en formato "dirección/prefijo siguiente-salto métrica", donde N es un número de 0 a (# rutas IPv4 - 1).

IP4_NUM_ROUTES

La variable contiene el número de rutas IPv4 que el script puede esperar.

IP4_NAMESERVERS

La variable contiene una lista separada por espacios de los servidores DNS activos.

NAME

NetworkManager-dispatcher - NetworkManager dispatcher script handling

SYNOPSIS

/etc/NetworkManager/dispatcher.d/*

DESCRIPTION

The NetworkManager dispatcher is a helper utility that is run whenever NetworkManager changes network state. It allows administrators to run scripts in response to network events.

Scripts are placed in the /etc/NetworkManager/dispatcher.d/ directory. They must be executable. The scripts are executed in alphabetical order.

The dispatcher calls scripts with two arguments:

$1
The action being performed. Possible actions are: prestart, poststart, up, predown, down, hostname, dhcp4-change, dhcp6-change, carrier, vpn-prestart, vpn-startup, vpn-down.
$2
The interface name the action applies to.

The dispatcher exports several environment variables to scripts:

USERCTL
This variable is set to yes if the connection is user-controlled, no otherwise.
NM_CONTROLLED
This variable is set to yes if the device is managed by NetworkManager, no otherwise.
DEVICE_TYPE
The type of the device. For example: eth, wlan, tun.

For events related to IP configuration, the following variables are exported:

IP4_<name>
The IPv4 configuration parameters. These correspond to the DHCP client options or static configuration. For example, IP4_ADDRESS_NUM, IP4_ADDRESS_1, IP4_NETMASK_1, IP4_GATEWAY, IP4_DNS, IP4_DOMAIN, IP4_SEARCH.

IP4_<name> variables are available as well, but they are not exported by default. They are exported only if the connection is configured to use them.

IP4_ADDR_GEN_MODE

The IPv4 address generation mode.

IP4_ROUTE_NUM and IP4_ROUTE_i

The number of static routes and their parameters.

IP6_<name>

The IPv6 configuration parameters. These correspond to the DHCPv6 client options or static configuration. For example, IP6_ADDRESS_NUM, IP6_ADDRESS_0, IP6_PREFIX_0, IP6_GATEWAY, IP6_DNS.

IP6_ADDR_GEN_MODE

The IPv6 address generation mode.

IP6_ROUTE_NUM and IP6_ROUTE_i

The number of static IPv6 routes and their parameters.

IP4_NAMESERVERS

A space-separated list of IPv4 DNS servers.

IP6_NAMESERVERS

A space-separated list of IPv6 DNS servers.

IP4_DOMAINS

The variable contains a space-separated list of the search domains.

DHCP4_<dhcp-option-name>

If the connection used DHCP for address configuration, the received DHCP configuration is passed in the environment using standard DHCP option names, prefixed with "DHCP4_", like "DHCP4_HOST_NAME=foobar".

IP6_<name> and DHCP6_<name>

The same variables as for IPv4 are available for IPv6, but the prefixes are IP6_ and DHCP6_ instead.

CONNECTIVITY_STATE

The network connectivity state, which can take the values defined by the NMConnectivityState type, from the org.freedesktop.NetworkManager D-Bus API: UNKNOWN, NONE, PORTAL, LIMITED or FULL. Note: this variable will only be set for connectivity-change actions.

In case of VPN, VPN_IP_IFACE is set, and IP4_*, IP6_* variables with VPN prefix are exported too, like VPN_IP4_ADDRESS_0, VPN_IP4_NUM_ADDRESSES.

The content of the user setting for the connection being activated is also passed via environment variables. Each key is stored in a variable with name CONNECTION_USER_ concatenated with the encoding of the key name. The encoding works as follows:

•lowercase letters become uppercase
•uppercase letters are prefixed with an underscore
•numbers do not change
•a dot is replaced with a double underscore
•any other character is encoded with an underscore followed by its 3-digit octal representation

For example, key test.foo-Bar2 is stored in a variable named CONNECTION_USER_TEST__FOO_055_BAR2.

Dispatcher scripts are run one at a time, but asynchronously from the main NetworkManager process, and will be killed if they run for too long. If your script might take arbitrarily long to complete, you should spawn a child process and have the parent return immediately. Scripts that are symbolic links pointing inside the /etc/NetworkManager/dispatcher.d/no-wait.d/ directory are run immediately, without waiting for the termination of previous scripts, and in parallel. Also beware that once a script is queued, it will always be run, even if a later event renders it obsolete. (Eg, if an interface goes up, and then back down again quickly, it is possible that one or more "up" scripts will be run after the interface has gone down.)
