NOMBRE

Net::Server::Proto - Capa de compatibilidad para protocolos de Net::Server

SINOPSIS

NOTA: Desde Net::Server 2.005, el valor por defecto para ipv es IPv* significando que si no se pasa un host o se pasa un hostname, se asignarán todos los tipos de socket disponibles. Puedes forzar IPv4 solo añadiendo un ipv => 4 en cualquiera de las seis formas que se permiten.
NOTA: Para IPv6, Net::Server intentará primero usar el módulo listado en el archivo de configuración server_config_ipv6_package, luego Net::Server::ipv6_package, luego IO::Socket::IP, luego IO::Socket::INET6 (que es obsoleto).
# Net::Server::Proto y sus módulos acompañantes no son intencionados para usarse fuera del ámbito de Net::Server.
# Así, aquí es como lo usas. Esto es solo para cualquiera que desee extender los protocolos para incluir algunos otros (por ejemplo, un protocolo de base de datos).
use Net::Server::Proto;
my @info = Net::Server::Proto->parse_info(
    $port,            # puerto a conectar
    $default_host,    # host a usar si no se encuentra en el puerto
    $default_proto,   # protocolo a usar si no se encuentra en el puerto
    $default_ipv,     # IPv6 o IPv4 por defecto si no se encuentra en el puerto
    $server_obj,      # objeto Net::Server
);
my @raw_info = Net::Server::Proto->get_addr_info($host, $port, $proto);
# devuelve un arrayref de ips resueltas, puertos y valores de ipv
my $sock = Net::Server::Proto->object({
    port  => $port,
    host  => $host,
    proto => $proto,
    ipv   => $ipv, # * (IPv*) si false (por defecto false)
}, $server);
# Net::Server::Proto intentará interfaciar con módulos subclases llamados similar a Net::Server::Proto::TCP
# Cada módulo subclase se carga por Net::Server::Proto cuando sea necesario.
use Net::Server::Proto::TCP; # o UDP o UNIX etc
# Devuelve un objeto que es una subclase de IO::Socket
# En este punto el objeto no está conectado.
# El método puede recolectar cualquier información adicional que necesite del objeto servidor.
my $sock = Net::Server::Proto::TCP->object({
    port  => $port,
    host  => $host,
    proto => $proto,
    ipv   => 6, # IPv6 - por defecto es * - también puede ser '4'
}, $server);
# Log que se va a hacer una conexión.
# Usa las funcionalidades del objeto pasado Net::Server.
$sock->log_connect( $server );
# Realmente bind a puerto o archivo de socket. Esto se realiza típicamente llamando al método configure del superclase IO::Socket.
$sock->connect();
# Permite rebind a un archivo de socket ya abierto. Suele hacerlo con un fdopen usando la superclase IO::Socket.
$sock->reconnect();
### Devuelve un identificador único para este sock que puede usarse al re-conectar.
my $str = $sock->hup_string();
# Devuelve el protocolo que se está usando por este módulo.
my $proto = $sock->NS_proto();

DESCRIPCIÓN

Net::Server::Proto es un módulo intermediario que devuelve objetos estilo IO::Socket vinculados a su propio conjunto de clases (es decir, Net::Server::Proto::TCP, Net::Server::Proto::UNIX).

Solo tres o cuatro protocolos vienen pre-instalados con Net::Server. TCP, UDP, UNIX, UNIXDGRAM, y SSLEAY. TCP es una implementación de SOCK_STREAM sobre un socket INET. UDP es una implementación de SOCK_DGRAM sobre un socket INET. UNIX usa un archivo de socket estilo UNIX con el protocolo SOCK_STREAM. UNIXGRAM usa un archivo de socket estilo UNIX con el protocolo SOCK_DGRAM. SSLEAY es realmente solo una capa encima de TCP pero usa Net::SSLeay para leer y escribir desde el flujo.

El protocolo que se pasa a Net::Server puede ser el nombre de otro módulo que contiene las implementaciones de protocolo. Si se pasa un protocolo como MyServer::MyTCP, el socket se vinculará a esa clase. Si se pasa Net::Server::Proto::TCP, se obtiene esa clase. Si se pasa una palabra sin mayúsculas, como tcp, udp, unix, unixdgram o ssleay, se convertirá a mayúsculas y se añadirá al final de "Net::Server::Proto::" (es decir, tcp = Net::Server::Proto::TCP).

MÉTODOS

Los nombres de protocolos utilizados por Net::Server::Proto deben ser subclases de IO::Socket. Estas clases también deben contener, como mínimo, los siguientes métodos:

object
Devuelve un objeto que es una subclase de IO::Socket. En este punto el objeto no está conectado. El método puede recolectar cualquier información adicional que necesite del objeto servidor. Los argumentos son default_host, port, y un objeto Net::Server estilo.
log_connect
Registra que se va a hacer una conexión. Usa las funcionalidades del objeto pasado Net::Server. Esto debería ser una cadena informativa explicando qué propiedades se están usando.
connect
Realmente vincula a un puerto o archivo de socket. Esto se realiza típicamente llamando al método configure de la superclase IO::Socket.
reconnect
Permite re-vincular a un archivo de socket ya abierto. Suele hacerlo con un fdopen usando la superclase IO::Socket.
hup_string
Devuelve un identificador único para este socket que puede usarse al re-conectar. Esto se hace para permitir pasar información incluyendo el descriptor de archivo de los sockets abiertos a través del %ENV durante un exec. Esta cadena debe ser siempre la misma según los parámetros de configuración.
NS_port
Protocolo de Net::Server. Devuelve el puerto que se está usando por este módulo. Si el tipo subyacente es UNIX, el puerto realmente será la ruta al archivo de socket UNIX.
NS_host
Protocolo de Net::Server. Devuelve el protocolo que se está usando por este módulo. Esto no tiene que ser un protocolo registrado o conocido.
NS_proto
Protocolo de Net::Server. Devuelve el protocolo que se está usando por este módulo. Esto no tiene que ser un protocolo registrado o conocido.
show
Similar a log_connect, pero simplemente muestra una lista de las propiedades que se encontraron. Puede usarse en cualquier momento.

HOST

El nombre de host puede ser vacío, '*', una dirección IPv4, una dirección IPv6, un nombre de host o un nombre de host con especificaciones de IPv*.

host => "127.0.0.1",  # una dirección IPv4
host => "::1",        # una dirección IPv6
host => 'localhost',  # direcciones devueltas por localhost (por defecto IPv* - IPv4 y/o IPv6)
host => 'localhost/IPv*',  # mismo
ipv  => '*',
host => 'localhost',  # mismo
ipv  => 6,
host => 'localhost',  # direcciones devueltas por localhost (IPv6)
ipv  => 'IPv4 IPv6',
host => 'localhost',  # direcciones devueltas por localhost (requiere IPv6 y IPv4)
host => '*',          # cualquier interfaz local (por defecto IPv*)
ipv  => '*',
host => '*',          # cualquier interfaz local (IPv6 o IPv4)
host => '*/IPv*',     # mismo

IPV

Además de poder especificar IPV como un parámetro separado, el ipv también puede pasarse como parte del host, parte del puerto, parte del protocolo o especificarse mediante $ENV{'IPV'}. La prioridad del orden es la siguiente:

1) Dirección IPv4 o IPv6 explícita - gana
2) valor de ipv especificado en el puerto
3) valor de ipv especificado en el host
4) valor de ipv especificado en el protocolo
5) valor de ipv especificado en los valores por defecto
6) valor de ipv especificado en $ENV{'IPV'}
7) por defecto es IPv*

PUERTO

El puerto es el argumento más importante pasado a las clases de módulos y a Net::Server::Proto en sí mismo. Para puertos de tipo TCP, UDP o SSLEAY, la forma general es generalmente host:port/protocol, [host]:port/protocol, host|port|protocol, host/port, o port. Si host es una dirección numérica de IPv6, debe estar entre corchetes para evitar ambigüedad en el análisis de un número de puerto, por ejemplo: "[::1]:80". Separar con espacios, comas o pipes también es permitido, por ejemplo "::1, 80". Para sockets UNIX, la forma general es generalmente socket_file|unix o socket_file.

Para ayudar a superar la ambigüedad del análisis, también es posible pasar el puerto como un hashref (o como un array de hashrefs) de información como:

port => {
    host  => "localhost",
    ipv   => 6, # podría también pasar IPv6 (* es por defecto)
    port  => 20203,
    proto => 'tcp',
}

Si un hashref no incluye host, ipv, o proto, se usará el valor por defecto proporcionado por la configuración general.

NOMBRE

Net::Server::Proto - Parsear información de protocolo para Net::Server

SINTAXIS

    use Net::Server::Proto;

    my @info = Net::Server::Proto->parse_info(
        string $port,
        string $def_host,
        string $def_proto,
        int $def_ipv
    );

DESCRIPCIÓN

El módulo Net::Server::Proto devuelve una lista de objetos correspondientes a los sockets creados. Para sockets Unix y INET, la lista típicamente contiene solo un elemento, pero puede devolver múltiples objetos cuando se permiten múltiples familias de protocolo o cuando un nombre de host resuelve a múltiples direcciones de bind locales. Esto es especialmente cierto cuando se pasa un valor de ipv de '*', permitiendo la resolución de nombres de host.

Puedes ver qué parseó Net::Server::Proto observando los logs y viendo qué dijo log_connect. También podrías incluir un hook post_bind similar al siguiente para depurar qué sucedió:

    sub post_bind_hook {
        my $self = shift;
        foreach my $sock ( @{ $self->{server}->{sock } }){
            $self->log(2, $sock->show);
        }
    }

MÉTODOS

No hay métodos publicos exportados.

HOST

El campo host se extrae de la cadena $port. Si no se proporciona, o si se pasa un nombre de host que no se puede resolver, se usaría el valor de $def_host.

Si se especifican múltiples direcciones ipv, el host se resuelve para cada una de ellas.

IPV

El campo ipv determina si se crea un socket IPv4, IPv6 o ambos. Si se especifica ipv4, solo se creará un socket IPv4. Si se especifica ipv6, solo se creará un socket IPv6. Si se especifica ipv*, se intentarán crear ambos. Si no se especifica nada, el valor se tomará de la variable de entorno IPV, que por defecto es ipv*.

PORT

El campo port es el número de puerto o la ruta del socket Unix.
