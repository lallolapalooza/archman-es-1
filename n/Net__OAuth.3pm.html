Net::OAuth(3) Documentación de Contribución de Usuario de Perl Net::OAuth(3)

NOMBRE

Net::OAuth - OAuth 1.0 para Perl

SINOPSIS

# Ejemplo de Servidor Web (Dancer)
# Este ejemplo está simplificado para fines ilustrativos, consulta el código completo en /demo
# Ten en cuenta que client_id es la Clave del Consumidor y client_secret es el Secreto del Consumidor
use Dancer;
use Net::OAuth::Client;
sub client {
      Net::OAuth::Client->new(
              config->{client_id},
              config->{client_secret},
              site => 'https://www.google.com/',
              request_token_path => '/accounts/OAuthGetRequestToken?scope=https%3A%2F%2Fwww.google.com%2Fm8%2Ffeeds%2F',
              authorize_path => '/accounts/OAuthAuthorizeToken',
              access_token_path => '/accounts/OAuthGetAccessToken',
              callback => uri_for("/auth/google/callback"),
              session => \&session,
      );
}
# Envía al usuario a autorizar con el proveedor del servicio
get '/auth/google' => sub {
      redirect client->authorize_url;
};
# El usuario ha regresado con el token y el verificador añadidos a la URL.
get '/auth/google/callback' => sub {
      # Usa el código de autorización para obtener el token de acceso
      my $access_token =  client->get_access_token(params->{oauth_token}, params->{oauth_verifier});
      # Usa el token de acceso para obtener un recurso protegido
      my $response = $access_token->get('/m8/feeds/contacts/default/full');
      # Haz algo con dicho recurso...
      if ($response->is_success) {
        return "¡Yay, funcionó: " . $response->decoded_content;
      }
      else {
        return "Error: " . $response->status_line;
      }
};
dance;

IMPORTANTE

Net::OAuth proporciona una API de bajo nivel para leer y escribir mensajes OAuth.

Probablemente deberías empezar con Net::OAuth::Client.

RESUMEN

OAuth es

"Un protocolo abierto para permitir la autenticación segura de APIs de una manera simple y estándar desde aplicaciones de escritorio y web."

En términos prácticos, OAuth es un mecanismo para que un Consumidor solicite recursos protegidos de un Proveedor de Servicio en nombre de un usuario.

Por favor, consulta la especificación de OAuth: http://oauth.net/documentation/spec

Net::OAuth proporciona:

  • clases que encapsulan mensajes OAuth (solicitudes y respuestas).
  • firma de mensajes
  • serialización y análisis de mensajes.
  • solicitudes de 2 patas (también conocidas como solicitudes sin token, también conocidas como solicitudes de consumidor), ver "SOLICITUDES DE CONSUMIDOR"

Net::OAuth no proporciona:

  • encapsulación de Consumidor o Proveedor de Servicio
  • almacenamiento/gestión de tokens/nonces/claves

DESCRIPCIÓN

MENSAJES OAUTH

Un mensaje OAuth es un conjunto de pares clave-valor. Se soportan los siguientes tipos de mensajes:

Solicitudes

  • Token de Solicitud (Net::OAuth::RequestTokenRequest)
  • Token de Acceso (Net::OAuth::AccessTokenRequest)
  • Autenticación de Usuario (Net::OAuth::UserAuthRequest)
  • Recurso Protegido (Net::OAuth::ProtectedResourceRequest)
  • Solicitud de Consumidor (Net::OAuth::ConsumerRequest) (solicitud de 2 patas / sin token)

Respuestas

  • Token de Solicitud (Net::OAuth::RequestTokenResponse)
  • Token de Acceso (Net::OAuth:AccessTokenResponse)
  • Autenticación de Usuario (Net::OAuth::UserAuthResponse)

Cada tipo de mensaje OAuth tiene uno o más parámetros requeridos, cero o más parámetros opcionales, y la mayoría permiten parámetros arbitrarios.

Todas las solicitudes OAuth deben ser firmadas por el Consumidor. Las respuestas del Proveedor de Servicio, sin embargo, no se firman.

Para crear un mensaje, la forma más fácil es usar los métodos de fábrica (Net::OAuth->request, Net::OAuth->response, Net::OAuth->message). Las siguientes invocaciones de métodos son todas equivalentes:

$request = Net::OAuth->request('user authentication')->new(%params);
$request = Net::OAuth->request('user_auth')->new(%params);
$request = Net::OAuth->request('UserAuth')->new(%params);
$request = Net::OAuth->message('UserAuthRequest')->new(%params);

La forma más verbosa es usar la clase directamente:

use Net::OAuth::UserAuthRequest;
$request = Net::OAuth::UserAuthRequest->new(%params);

También puedes crear un mensaje deserializándolo desde una cabecera de Autorización, URL, hash de consulta, o cuerpo POST

$request = Net::OAuth->request('protected resource')->from_authorization_header($ENV{HTTP_AUTHORIZATION}, %api_params);
$request = Net::OAuth->request('protected resource')->from_url($url, %api_params);
$request = Net::OAuth->request('protected resource')->from_hash({$q->Vars}, %api_params); # CGI
$request = Net::OAuth->request('protected resource')->from_hash($c->request->params, %api_params); # Catalyst
$response = Net::OAuth->response('request token')->from_post_body($response_content, %api_params);

Ten en cuenta que los métodos de deserialización (a diferencia de new()) esperan que los parámetros del protocolo OAuth estén prefijados con 'oauth_', como esperarías en un mensaje OAuth válido.

Antes de enviar una solicitud, el Consumidor debe primero firmarla:

$request->sign;

Al recibir una solicitud, el Proveedor de Servicio debe primero verificar la firma:

die "La verificación de la firma falló" unless $request->verify;

Al enviar un mensaje, el último paso es serializarlo y enviarlo a donde sea necesario. Los siguientes métodos de serialización están disponibles:

$response->to_post_body # un cuerpo POST application/x-www-form-urlencoded
$request->to_url # la cadena de consulta de una URL
$request->to_authorization_header # el valor de una cabecera HTTP Authorization
$request->to_hash # un hash que podría ser usado para alguna otra serialización

PARÁMETROS API vs PARÁMETROS DEL MENSAJE

Net::OAuth define 'parámetros del mensaje' como parámetros que son parte del mensaje OAuth transmitido. Estos incluyen cualquier parámetro de protocolo (prefijado con 'oauth_' en el mensaje), y cualquier parámetro adicional del mensaje (el hash extra_params).

'Parámetros de API' son parámetros requeridos para construir un objeto de mensaje que no se transmiten con el mensaje, por ejemplo, consumer_secret, token_secret, request_url, request_method.

Hay varios métodos para inspeccionar una clase de mensaje para ver qué parámetros están definidos:

$request->required_message_params;
$request->optional_message_params;
$request->all_message_params;
$request->required_api_params;
$request->optional_api_params;
$request->all_api_params;
$request->all_params;

Por ejemplo:

use Net::OAuth;
use Data::Dumper;
print Dumper(Net::OAuth->request("protected resource")->required_message_params);
$VAR1 = [
         'consumer_key',
         'signature_method',
         'timestamp',
         'nonce',
         'token'
       ];

ACCESO A LOS PARÁMETROS

Todos los parámetros se pueden obtener/establecer usando métodos accesores. Por ejemplo:

my $consumer_key = $request->consumer_key;
$request->request_method('POST');

EL PARÁMETRO REQUEST_URL

Cualquier parámetro de consulta en la request_url se elimina y se añade al hash extra_params al generar la firma.

Por ejemplo, las siguientes solicitudes son prácticamente equivalentes:

 my $request = Net::OAuth->request('Request Token')->new(
  %params,
  request_url => 'https://photos.example.net/request_token',
  extra_params => {
   foo => 'bar'
  },
);
 my $request = Net::OAuth->request('Request Token')->new(
  %params,
  request_url => 'https://photos.example.net/request_token?foo=bar',
 );

Llamar a $request->request_url todavía devolverá lo que sea que hayas establecido originalmente. Si quieres obtener la request_url con los parámetros de consulta eliminados, puedes hacer:

my $url = $request->normalized_request_url;

MÉTODOS DE FIRMA

Se soportan los siguientes métodos de firma:

  • PLAINTEXT
  • HMAC-SHA1
  • HMAC-SHA256
  • RSA
Net::OAuth 0.31 manual page

NAME

Net::OAuth - Object oriented interface to OAuth

SYNOPSIS

use Net::OAuth;
my $request = Net::OAuth->request('request token')->new(
        consumer_key => 'dpf43f3p2l4k3l03',
        consumer_secret => 'kd94hf93k423kf44',
        signature_method => 'HMAC-SHA1',
);
$request->sign;

my $response = Net::OAuth->response('request token')->from_post_body($body);

IMPORTANT

This module has a dependency on Digest::SHA, which is not a core Perl module. You may need to install this module explicitly.

cpanm Digest::SHA

ABSTRACT

Object oriented interface to OAuth.

DESCRIPTION

This module provides an object-oriented interface to the OAuth protocol. It allows you to construct OAuth messages, sign them, and verify signatures.

The module is broken down into several classes:

  • Net::OAuth::Message: Base class for all OAuth messages.
  • Net::OAuth::Request: Base class for requests.
  • Net::OAuth::Response: Base class for responses.
  • Net::OAuth::ConsumerRequest: Represents a request made by a consumer.
  • Net::OAuth::ServiceProviderRequest: Represents a request made by a service provider.
  • Net::OAuth::RequestTokenRequest: Request for a request token.
  • Net::OAuth::AccessTokenRequest: Request for an access token.
  • Net::OAuth::Authorize: Authorize a request token.
  • Net::OAuth::Signature: Handles signature generation and verification.

Signature Methods

The signature method is determined by the value of the signature_method parameter that is passed to the message constructor.

If an unknown signature method is specified, the signing/verification will throw an exception.

PLAINTEXT SIGNATURES

This method is a trivial signature which adds no security. Not recommended.

HMAC-SHA1 SIGNATURES

This method is available if you have Digest::SHA installed. This is by far the most commonly used method.

HMAC-SHA256 SIGNATURES

This method is available if you have Digest::SHA installed.

RSA-SHA1 SIGNATURES

To use RSA-SHA1 signatures, pass in a Crypt::OpenSSL::RSA object (or any object that can do $o->sign($str) and/or $o->verify($str, $sig))

E.g.

Consumer:

use Crypt::OpenSSL::RSA;
use File::Slurp;
$keystring = read_file('private_key.pem');
$private_key = Crypt::OpenSSL::RSA->new_private_key($keystring);
$request = Net::OAuth->request('request token')->new(%params);
$request->sign($private_key);

Service Provider:

use Crypt::OpenSSL::RSA;
use File::Slurp;
$keystring = read_file('public_key.pem');
$public_key = Crypt::OpenSSL::RSA->new_public_key($keystring);
$request = Net::OAuth->request('request token')->new(%params);
if (!$request->verify($public_key)) {
       die "Signature verification failed";
}

Note that you can pass the key in as a parameter called 'signature_key' to the message constructor, rather than passing it to the sign/verify method, if you like.

CONSUMER REQUESTS

To send a request without including a token, use a Consumer Request:

my $request = Net::OAuth->request('consumer')->new(
        consumer_key => 'dpf43f3p2l4k3l03',
        consumer_secret => 'kd94hf93k423kf44',
        request_url => 'http://provider.example.net/profile',
        request_method => 'GET',
        signature_method => 'HMAC-SHA1',
        timestamp => '1191242096',
        nonce => 'kllo9940pd9333jh',
);
$request->sign;

See Net::OAuth::ConsumerRequest

I18N

Per the OAuth spec, when making the signature Net::OAuth first encodes parameters to UTF-8. This means that any parameters you pass to Net::OAuth, if they might be outside of ASCII character set, should be run through Encode::decode() (or an equivalent PerlIO layer) first to decode them to Perl's internal character structure.

OAUTH 1.0A

Background:

http://mojodna.net/2009/05/20/an-idiots-guide-to-oauth-10a.html

http://oauth.googlecode.com/svn/spec/core/1.0a/drafts/3/oauth-core-1_0a.html

Net::OAuth defaults to OAuth 1.0 spec compliance, and supports OAuth 1.0 Rev A with an optional switch:

use Net::OAuth
$Net::OAuth::PROTOCOL_VERSION = Net::OAuth::PROTOCOL_VERSION_1_0A;

It is recommended that any new projects use this switch if possible, and existing projects move to supporting this switch as soon as possible. Probably the easiest way for existing projects to do this is to turn on the switch and run your test suite. The Net::OAuth constructor will throw an exception where the new protocol parameters (callback, callback_confirmed, verifier) are missing.

Internally, the Net::OAuth::Message constructor checks $Net::OAuth::PROTOCOL_VERSION and attempts to load the equivalent subclass in the Net::OAuth::V1_0A:: namespace. So if you instantiate a Net::OAuth::RequestTokenRequest object, you will end up with a Net::OAuth::V1_0A::RequestTokenRequest (a subclass of Net::OAuth::RequestTokenRequest) if the protocol version is set to PROTOCOL_VERSION_1_0A. You can also select a 1.0a subclass on a per-message basis by passing

protocol_version => Net::OAuth::PROTOCOL_VERSION_1_0A

in the API parameters hash.

If you are not sure whether the entity you are communicating with is 1.0A compliant, you can try instantiating a 1.0A message first and then fall back to 1.0 if that fails:

use Net::OAuth
$Net::OAuth::PROTOCOL_VERSION = Net::OAuth::PROTOCOL_VERSION_1_0A;
my $is_oauth_1_0 = 0;
my $response = eval{Net::OAuth->response('request token')->from_post_body($res->content)};
if ($@) {
    if ($@ =~ /Missing required parameter 'callback_confirmed'/) {
        # fall back to OAuth 1.0
        $response = Net::OAuth->response('request token')->from_post_body(
            $res->content,
            protocol_version => Net::OAuth::PROTOCOL_VERSION_1_0
        );
        $is_oauth_1_0 = 1; # from now on treat the server as OAuth 1.0 compliant
    }
    else {
        die $@;
    }
}

At some point in the future, Net::OAuth will default to Net::OAuth::PROTOCOL_VERSION_1_0A.
