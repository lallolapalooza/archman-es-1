NOMBRE

Net::DNS::SEC::Tools::rollmgr - Comunícate con el gestor de rotación de DNSSEC-Tools.

SINOPSIS

use Net::DNS::SEC::Tools::rollmgr;
$dir = rollmgr_dir();
$idfile = rollmgr_idfile();
$id = rollmgr_getid();
rollmgr_dropid();
rollmgr_rmid();
rollmgr_cmdint();
$runflag = rollmgr_running();
rollmgr_halt();
rollmgr_phasemsg('long');
rollmgr_channel(1);
($cmd,$data) = rollmgr_getcmd();
$ret = rollmgr_verifycmd($cmd);
rollmgr_sendcmd(CHANNEL_CLOSE,ROLLCMD_ROLLZSK,"example.com");
rollmgr_sendcmd(CHANNEL_WAIT,ROLLCMD_ROLLZSK,"example.com");
($retcode, $respmsg) = rollmgr_getresp();
$descr = rollmgr_get_phase('KSK', $phasecnt);

DESCRIPCIÓN

El módulo Net::DNS::SEC::Tools::rollmgr proporciona métodos estándar e independientes de la plataforma para que un programa se comunique con el gestor de rotación rollerd de DNSSEC-Tools. Aquí se describen dos interfaces: interfaces generales e interfaces de comunicación.

INTERFACES GENERALES

Las interfaces para el módulo Net::DNS::SEC::Tools::rollmgr se enumeran a continuación.

rollmgr_dir()
Esta rutina devuelve el directorio de rollerd.
rollmgr_idfile()
Esta rutina devuelve el archivo de identificación de rollerd.
rollmgr_getid()
Esta rutina devuelve el ID de proceso de rollerd. Si se pasa un valor distinto de cero como argumento, el archivo de identificación se dejará abierto y accesible a través del manejador de archivos PIDFILE. Consulte la sección ADVERTENCIAS más abajo.

Valores de retorno:

En caso de éxito, se devuelve la primera parte del contenido del archivo
    (hasta 80 caracteres).
Se devuelve -1 si el archivo de identificación no existe.
rollmgr_dropid()
Esta interfaz asegura que no se esté ejecutando otra instancia de rollerd y luego crea un archivo de identificación para referencia futura.

Valores de retorno:

 1 - el archivo de identificación se creó con éxito para este proceso
 0 - otro proceso ya está actuando como rollerd
-1 - no se pudo crear el archivo de identificación
rollmgr_rmid()
Esta interfaz elimina el archivo de identificación de rollerd.

Valores de retorno:

 1 - el archivo de identificación se eliminó con éxito
 0 - no existe ningún archivo de identificación
-1 - el proceso que llama no es rollerd
-2 - no se pudo eliminar el archivo de identificación
rollmgr_cmdint()
Esta rutina informa a rollerd que se ha enviado un comando a través de rollmgr_sendcmd().

Valores de retorno:

-1 - se encontró un ID de proceso no válido para rollerd
Cualquier otro valor indica el número de procesos que fueron
señalados.
(Esto solo debería ser 1.)
rollmgr_running()
Esta rutina determina si rollerd está en ejecución y devuelve un valor que indica el estado.

Valores de retorno:

 1 - rollerd está en ejecución.
 0 - El proceso listado en el archivo de ID de proceso de
     rollerd no está en ejecución.
-1 - No se pudo obtener el ID de proceso de rollerd.
rollmgr_halt()
Esta rutina informa a rollerd que debe cerrarse.

En la implementación actual, se devuelve el código de retorno del comando kill().

-1 - se encontró un ID de proceso no válido para rollerd
Cualquier otro valor indica el número de procesos que fueron
señalados.
(Esto solo debería ser 1.)
rollmgr_loadzone(ctlprog,opts,zone)
Esta rutina informa a un servidor de nombres que recargue el archivo de zona de una zona. El argumento $ctlprog es el comando que se ejecutará para controlar el servidor de nombres. Si esta es una cadena vacía, entonces se utilizará el valor predeterminado para DNSSEC-Tools. El argumento $opts es un conjunto de opciones que se pasarán a ctlprog. El argumento $zone es el nombre de la zona que se recargará.

La línea de comandos que se ejecutará se construye en este formato:

<$zone> <$opts> reload <$zone>

Este formato asume que se utilizará el comando rndc para señalar al servidor de nombres.

El valor de retorno será el código de retorno de la ejecución de $ctlprog.

rollmgr_phasemsg()
Esta rutina establece la longitud del mensaje de fase. de los mensajes de registro relacionados con fases utilizados por rollerd. Los niveles válidos son "long" y "short", siendo "long" el valor predeterminado.

La longitud del mensaje largo significa que se incluirá una descripción de la fase con algunos mensajes de registro. Por ejemplo, la forma larga de un mensaje sobre la fase 3 de rotación de ZSK será: "Fase 3 de ZSK (Esperando a que caduquen los datos de la zona antigua en las cachés)".

La longitud del mensaje corto significa que no se incluirá una descripción de la fase con algunos mensajes de registro. Por ejemplo, la forma corta de un mensaje sobre la fase 3 de rotación de ZSK será: "Fase 3 de ZSK".

Valores de retorno:

1 - se estableció la longitud del mensaje de fase
0 - se especificó una longitud de mensaje de fase no válida

INTERFACES DE COMUNICACIÓN DE ROLLERD

rollmgr_channel(serverflag)
Esta interfaz configura un canal persistente para la comunicación con rollerd. Si serverflag es verdadero, se crea el lado del servidor del canal. Si serverflag es falso, se crea el lado del cliente del canal.

Actualmente, la conexión solo se puede establecer con localhost. Esto puede cambiarse para permitir conexiones remotas, si se considera necesario.

Valores de retorno:

 1 - Canal de comunicación establecido con éxito.
 0 - No se pudo conectar al servidor.
-1 - No se pudo crear un socket Unix.
-2 - No se pudo enlazar al socket Unix. (solo servidor)
-3 - No se pudieron cambiar los permisos del socket Unix. (solo servidor)
-4 - No se pudo escuchar en el socket Unix. (solo servidor)
-5 - El nombre del socket era más largo de lo permitido para un socket Unix.
rollmgr_queuecmd(cmdname, value)
Esta interfaz recuerda internamente un comando y su valor opcional para su procesamiento posterior. Consulte rollmgr_getcmd() a continuación para obtener más detalles.
rollmgr_getcmd()
rollmgr_getcmd() procesa los comandos que deben ser gestionados. Si hay comandos almacenados internamente en cola a través de la función rollmgr_queuecmd(), se procesan primero. Después de eso, recupera un comando enviado a través del canal de comunicación de rollerd por un programa cliente. El comando y los datos del comando se envían en cada mensaje.

El comando y los datos del comando se devuelven al llamador.

rollmgr_sendcmd(closeflag,cmd,data)
rollmgr_sendcmd() envía un comando a rollerd. El comando debe ser uno de los comandos de la tabla siguiente. Esta interfaz crea un canal de comunicación con rollerd y envía el mensaje. El canal no se cierra, en caso de que el llamador desee recibir una respuesta de rollerd.

Los comandos disponibles y sus datos requeridos son:

comando             datos           propósito
-------             -----           -------
ROLLCMD_DISPLAY     1/0             iniciar/detener

NAME

rollmgr(3pm) — interface to rollerd

SYNOPSIS

    use Net::DNS::SEC::Tools::rollmgr;

DESCRIPTION

The rollmgr module provides a Perl interface to the rollerd daemon. Using this module, a client program can send commands to rollerd and receive responses. It is intended to be used to control rollerd, and to query its status.

The module communicates with rollerd by opening a communication channel to it. This is done by calling the function rollmgr_init(). This function returns a file descriptor that is used for subsequent communications.

Thereafter, commands are sent using rollmgr_sendcmd() and responses are received using rollmgr_getresp(). When communication is finished, the channel is closed using rollmgr_close().

It is possible to verify that a command is valid before sending it using rollmgr_verifycmd().

The module also provides a function, rollmgr_get_phase(), which returns a description of a particular rollover phase.

There are two files used by rollerd to store its state: id.db and rollrec.db. The former stores keys and the latter stores zone information. The id file is stored in the directory specified by the environment variable $ROLLMGR_IDDIR, or if not set, in /var/db/dnssec-tools. The rollrec file is stored in the directory specified by the environment variable $ROLLMGR_ROLLRECDIR, or if not set, in /var/db/dnssec-tools.

In addition to these, there is a default set of commands that can be sent to rollerd. These are:

ROLLCMD_DSPUB zone-name
a DS record has been published
ROLLCMD_DSPUBALL none
DS records published for all zones in KSK rollover phase 5
ROLLCMD_GETSTATUS none
currently unused
ROLLCMD_LOGFILE log filename
change the log file
ROLLCMD_LOGLEVEL log level
set a new logging level
ROLLCMD_LOGMSG log message
add a message to the log
ROLLCMD_LOGTZ timezone
set timezone for log messages
ROLLCMD_MERGERRFS rollrec files
merge rollrec files with the current rollrec file
ROLLCMD_PHASEMSG long/short
set long or short phase messages
ROLLCMD_QUEUELIST none
returns the names and next event time of zones in the "soon queue" (experimental)
ROLLCMD_QUEUESTATUS none
returns information about the state of soon-queue processing (experimental)
ROLLCMD_ROLLALL none
resume rollover for all suspended zones
ROLLCMD_ROLLALLZSKS none
force all zones to start ZSK rollover
ROLLCMD_ROLLKSK zone-name
force a zone to start KSK rollover
ROLLCMD_ROLLREC rollrec-name
change rollerd's rollrec file
ROLLCMD_ROLLZONE zone name
restart rollover for a suspended zone
ROLLCMD_ROLLZSK zone-name
force a zone to start ZSK rollover
ROLLCMD_RUNQUEUE none
rollerd runs through its queue
ROLLCMD_SHUTDOWN none
stop rollerd
ROLLCMD_SIGNZONE zone
sign a zone (no rollover)
ROLLCMD_SIGNZONEs all or active
sign all or active zones
ROLLCMD_SKIPALL none
suspend all rollovers
ROLLCMD_SKIPZONE zone name
suspend rollover for a rolling zone
ROLLCMD_SLEEPTIME seconds-count
set rollerd's sleep time
ROLLCMD_SPLITRRF rollrec-name,

GENERAL INTERFACES

rollmgr_init()
Initialises communications with rollerd. It opens a connection to the daemon and returns a file descriptor that should be used for all subsequent communications. If the connection fails, it returns undef.

This function takes an optional argument, closeflag. If closeflag is set to CHANNEL_CLOSE (or a true value), the channel will be closed automatically when the next command is sent. If closeflag is set to CHANNEL_WAIT (or a false value), the channel will remain open until rollmgr_close() is called.

rollmgr_close()
Closes the communication channel to rollerd. This function takes no arguments.

ROLLERD COMMUNICATIONS INTERFACES

rollmgr_sendcmd(fd, cmd, args, closeflag)
Sends a command to rollerd via the communication channel represented by file descriptor fd.

cmd is the command string (e.g., "ROLLCMD_SHUTDOWN").

args is a reference to an array of strings representing the arguments to the command. If there are no arguments, this should be an empty array reference.

closeflag determines whether the communication channel is closed after the command is sent. If closeflag is set to CHANNEL_CLOSE (or a true value), the channel will be closed. If closeflag is set to CHANNEL_WAIT (or a false value), the channel will remain open. Note that this is the same value as used in rollmgr_init().

The data aren't checked for validity by rollmgr_sendcmd(); validity checking is a responsibility of rollerd.

If the caller does not need a response from rollerd, then closeflag should be set to CHANNEL_CLOSE; if a response is required then closeflag should be CHANNEL_WAIT. These values are boolean values, and the constants aren't required.

On success, 1 is returned. If an invalid command is given, 0 is returned.

rollmgr_getresp()
After executing a client command sent via rollmgr_sendcmd(), rollerd will send a response to the client. rollmgr_getresp() allows the client to retrieve the response.

A return code and a response string are returned, in that order. Both are specific to the command sent.

rollmgr_verifycmd(cmd)
rollmgr_verifycmd() verifies that cmd is a valid command for rollerd. 1 is returned for a valid command; 0 is returned for an invalid command.

1 is returned for a valid command; 0 is returned for an invalid command.

rollmgr_get_phase(phasetype, phasenum)
rollmgr_get_phase() returns a description of a particular phase for a particular type of rollover. phasetype specifies the type of rollover, and may be "KSK" or "ZSK". phasenum specifies the phase number whose description is desired. This must be an integer between 0 and 7 (KSK) or 0 and 4 (ZSK). If an invalid phase type or phase number is specified, an empty string is returned.

WARNINGS

1. rollmgr_getid() attempts to exclusively lock the id file. Set a timer if this matters to you.

2. rollmgr_getid() has a nice little race condition. We should lock the file prior to opening it, but we can't do so without it being open.
