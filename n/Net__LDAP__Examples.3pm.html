Net::LDAP::Examples(3) Documentación de Perl contribuida por el usuario Net::LDAP::Examples(3)

NOMBRE

Net::LDAP::Examples - PERL LDAP de Ejemplo

DESCRIPCIÓN

Los siguientes ejemplos son, por supuesto, código PERL, que funcionan con los módulos Net::LDAP.

La intención de este documento es dar al lector un punto de partida de copiar y pegar para hacer funcionar una aplicación LDAP.

A continuación encontrará fragmentos de código que deberían funcionar tal cual, con solo una pequeña cantidad de trabajo para corregir cualquier asignación de variable y especificidad de LDAP, por ejemplo, la sintaxis del Nombre Distinguido, relacionada con la propia implementación del usuario.

El Procedimiento de Operación Estándar que se sigue aquí es:

1 Paquete - use Net::LDAP
2 Inicialización - new
3 Vinculación - bind
4 Operación - add modify moddn search
4.1 Procesamiento - mostrar datos de una búsqueda
5 Error - mostrar información de error
6 Desvinculación - unbind

Consulte cada uno de estos para obtener un fragmento de código que satisfaga sus necesidades.

Lo que no se cubre en estos ejemplos en este momento:

Métodos abandon y compare
Subrutinas de callback

OPERACIÓN - Generar una BÚSQUEDA

sub LDAPsearch
{
  my ($ldap,$cadenaBusqueda,$attrs,$base) = @_;
  # si no pasan una base... la establecen por ellos
  if (!$base ) { $base = "o=miCompañia, c=miPais"; }
  # si no pasan un array de atributos...
  # establecen algo para ellos
  if (!$attrs ) { $attrs = [ 'cn','mail' ]; }
  my $result = $ldap->search ( base    => "$base",
                               scope   => "sub",
                               filter  => "$cadenaBusqueda",
                               attrs   =>  $attrs
                             );

}

my @Attrs = ( );               # solicitar que se devuelvan todos los atributos disponibles.
                               #
my $result = LDAPsearch ( $ldap, "sn=*", \@Attrs );

PROCESAMIENTO - Mostrar Resultados de BÚSQUEDA

#------------
#
# Acceder a los datos como si estuvieran en una estructura
# es decir, usando el método "as_struct"
#
my $href = $result->as_struct;
# obtener un array de los nombres de DN
my @arrayOfDNs  = keys %$href;        # usar hashes de DN
# procesar cada DN usándolo como clave
foreach ( @arrayOfDNs ) {
  print $_, "\n";
  my $valref = $$href{$_};
  # obtener un array de los nombres de atributos
  # pasados para este DN.
  my @arrayOfAttrs = sort keys %$valref; #usar hashes de Attr
  my $attrName;
  foreach $attrName (@arrayOfAttrs) {
    # saltar cualquier dato binario: ¡qué asco!
    next if ( $attrName =~ /;binary$/ );
    # obtener el valor del atributo (puntero) usando el
    # nombre del atributo como hash
    my $attrVal =  @$valref{$attrName};
    print "\t $attrName: @$attrVal \n";
  }
  print "#-------------------------------\n";
  # Fin de ese DN
}
#
# fin del método as_struct
#
#--------
#------------
#
# manejar cada uno de los resultados de forma independiente
# ... es decir, usando el método de recorrido
#
my @entries = $result->entries;
my $entr;
foreach $entr ( @entries ) {
  print "DN: ", $entr->dn, "\n";
  my $attr;
  foreach $attr ( sort $entr->attributes ) {
    # saltar binarios que no podemos manejar
    next if ( $attr =~ /;binary$/ );
    print "  $attr : ", $entr->get_value ( $attr ) ,"\n";
  }
  print "#-------------------------------\n";
}
#
# fin del método de recorrido
#------------

sub LDAPmodifyUsingHash
{
  my ($ldap, $dn, $loQueCambiar ) = @_;
  my $result = $ldap->modify ( $dn,
                               replace => { %$loQueCambiar }
                             );
  return $result;
}

#
#   MODIFICAR usando una LISTA ARRAY

sub LDAPmodifyUsingArrayList
{
  my ($ldap, $dn, $loQueCambiar ) = @_;
  my $result = $ldap->modify ( $dn,
                               changes => [
                                 replace => @$loQueCambiar
                               ]
                             );
  return $result;
}
#######################################
#
#   MODIFICAR usando un ARRAY

my @ArrayReemplazo = ( 'palabraClave', "xxxxxxxxxx" ,

sub LDAPmodifyUsingArray
{
  my ($ldap, $dn, $loQueCambiar ) = @_;
  my $result = $ldap->modify ( $dn,
                               changes => [
                                 replace => [ @$loQueCambiar ]
                               ]
                             );
  return $result;
}
#######################################
#
#   MODIFICAR un registro existente usando 'Changes'
#    (o combinación de añadir/eliminar/reemplazar)
#
my @cambios;
my @arrayReemplazo;
my @arrayEliminar;
my @arrayAñadir;
push @arrayAñadir, 'cn', "yo mismo";
push @arrayReemplazo, 'sn', '!@#$%^&*()__+Hola Qué Tal';
push @arrayReemplazo, 'cn', "yo mismo yo";
push @arrayEliminar, 'cn', "yo mismo";
if ( $#arrayReemplazo > 0 ) {
  push @cambios, 'replace';
  push @cambios, \@arrayReemplazo;
}
if ( $#arrayEliminar > 0 ) {
  push @cambios, 'delete';
  push @cambios, \@arrayEliminar;
}
if ( $#arrayAñadir > 0 ) {
  push @cambios, 'add';
  push @cambios, \@arrayAñadir;
}
$result = LDAPmodify ( $ldap, $dn, \@cambios );
sub LDAPmodify
{
  my ($ldap, $dn, $loQueCambiar) = @_;
  my $result = $ldap->modify ( $dn,
                               changes => [
                                 @$loQueCambiar
                               ]
                             );
  return $result;
}

OPERACIÓN - Cambiar el RDN

my $nuevoRDN = "cn=Joseph Usuario";
my $result = LDAPrdnChange ( $ldap, $dn, $nuevoRDN, "archivo" );
sub LDAPrdnChange
{
  my ($ldap,$dn,$loQueCambiar,$accion) = @_;
  my $rama;
  #
  # si se selecciona la acción de archivo, mover esta
  # entrada a otro lugar del directorio.
  #
  if ( $accion =~ /archivo/i )  {
    $rama = "ou=nuevaRama, o=miCompañia, c=miPais";
  }
  #
  # usar 'deleteoldrdn' para evitar obtener
  # multivalores en el atributo de NOMBRE.
  # en la mayoría de los casos sería el atributo 'CN'
  #
  my $result = $ldap->moddn ( $dn,
                              newrdn => $loQueCambiar,
                              deleteoldrdn => '1',
                              newsuperior => $rama
                            );
  return $result;
}

NAME

Net::LDAP::Examples - Examples of Net::LDAP usage

DESCRIPTION

This document contains a number of code snippets demonstrating common tasks using the Net::LDAP Perl module.

CODE

The following code demonstrates how to create a new entry in your LDAP server.

The following code snippet demonstrates how to create a new entry in your LDAP server.

First, initialize a new LDAP object.

use Net::LDAP;
my $ldap = Net::LDAP->new( "ldap.mycompany.com", port => 389, onerror => \'die\' );
#
# bind to the server
#
my $mesg = $ldap->bind ( );
#
# if the bind fails then die
#
if ( $mesg->code ) {
  die "\n\n\tERROR:", $mesg->error, "\n";
}

Then, create a reference to an anonymous array that contains the Distinguished Name or DN, and the attributes that you want to add to the entry.

my $CreateArray = [
  "cn=Jane User",
  "uid=0000001",
  "sn=User",
  'mail=JaneUser@mycompany.com'
];
#
# create the  new DN to look like this
# " cn=Jo User + uid=0000001 , ou=bailiwick, o=mycompany, c=mycountry "
#
# NOTE: this DN  MUST be changed to meet your implementation
#
my $NewDN = "@$CreateArray[0]+".
            "@$CreateArray[1],ou=bailiwick,o=mycompany,c=mycountry";
LDAPentryCreate($ldap, $NewDN, $CreateArray);
#
# CreateArray is a reference to an anonymous array
# you have to dereference it in the  subroutine it's
# passed to.
#
sub LDAPentryCreate
{
   my ($ldap, $dn, $whatToCreate) = @_;
   my $result = $ldap->add ( $dn, attrs => [ @$whatToCreate ] );
   return $result;
}

LDAP SCHEMA RETRIEVAL

The following code snippet shows how to retrieve schema information.

The first procedure is to initialize a new LDAP object using the same procedures as listed at the beginning of this document.

The second procedure is to bind to your directory server. Some servers may require authentication to retrieve the schema from the directory server. This procedure is listed at the beginning of this document too.

After a successful bind you are ready to retrieve the schema information. You do this by initializing a schema object.

$schema = $ldap->schema ( );

In this case Net::LDAP will attempt to determine the dn under which the schema can be found. First it will look for the attribute "subschemaSubentry" in the root DSE. If that cannot be found then it will default to the assumption of "cn=schema"

Alternatively you can specify the dn where the schema is to be found with

$schema = $ldap->schema ( dn => $dn );

Once we have a dn to search for, Net::LDAP will fetch the schema entry with

$mesg = $self->search ( base   => $dn,
                                      scope  => 'base',
                                      filter => '(objectClass=subschema)',
                                    );

Once the schema object has been initialized, schema methods are used to retrieve the data. There are a number of ways this can be done. Information on the schema methods can be found in the Net::LDAP::Schema pod documentation.

The following is a code snippet showing how to get and display information about returned attributes.

#
# Get the attributes
#
@attributes = $schema->all_attributes ( );
#
# Display the attributes
#
foreach $ar ( @attributes ) {
  print "attributeType: ", $ar->{name}, "\n";
  #
  # Print all the details
  #
  foreach $key ( keys %{$ar} ) {
    print join ( "\n\t\t", "\t$key:",
                 ref ( $ar->{$key} ) ? @{$ar->{$key}} : $ar->{$key}
               ), "\n";
  }
}

The process is the basically the same for getting objectClass information. Where schema->all_attributes() is used, substitute schema->all_objectclasses(). From that point on the process is the same for both objectClasses and attributes.
