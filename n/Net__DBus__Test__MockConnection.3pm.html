NOMBRE

Net::DBus::Test::MockConnection - Simula una conexión al bus para pruebas unitarias

SINOPSIS

use Net::DBus;
my $bus = Net::DBus->test
# Registrar un servicio y el objeto a probar
use MyObject
my $service = $bus->export_service("org.example.MyService");
my $object = MyObject->new($service);
# Adquirir el servicio y hacer pruebas
my $remote_service = $bus->get_service('org.example.MyService');
my $remote_object = $service->get_object("/org/example/MyObjct");
# Esto recorre la conexión simulada, invocando finalmente 'testSomething' en el $object anterior.
$remote_object->testSomething()

DESCRIPCIÓN

Este objeto proporciona una implementación falsa de Net::DBus::Binding::Connection, lo que permite simular un bus de mensajes puramente 'en memoria'. Esto está destinado a facilitar la creación de pruebas unitarias para servicios que de otro modo necesitarían llamar a otros objetos en un bus de mensajes real. Se utiliza como complemento del módulo Net::DBus::Test::MockObject, que es cómo se deben proporcionar objetos falsos en el bus falso.

MÉTODOS

mi $con = Net::DBus::Test::MockConnection->new()
Crea una nueva instancia de objeto de conexión simulada. Normalmente no es necesario crear instancias de este objeto directamente; en su lugar, se puede utilizar el método "test" del objeto Net::DBus para obtener un manejador de un bus de prueba.
$con->send($message)
Envía un mensaje a través de la conexión simulada. Si el mensaje es una llamada a método, se dirigirá directamente a cualquier objeto simulado correspondiente registrado. Si el mensaje es un error o un retorno de método, estará disponible como valor de retorno para el método "send_with_reply_and_block". Si el mensaje es una señal, se pondrá en cola para ser procesado por el método "dispatch".
$bus->request_name($service_name)
Finge enviar una solicitud al bus registrando el nombre conocido especificado en el parámetro $service_name. En realidad, esto es solo una operación nula que da la impresión de que el nombre se registró correctamente.
mi $reply = $con->send_with_reply_and_block($msg)
Envía un mensaje a través de la conexión simulada y espera una respuesta. El $msg debe ser una instancia de "Net::DBus::Binding::Message::MethodCall" y la respuesta $reply será una instancia de "Net::DBus::Binding::Message::MethodReturn". También es posible que se lance un error, siendo el error lanzado bendecido en la clase "Net::DBus::Error".
$con->dispatch;
Procesa cualquier mensaje pendiente en la cola de entrada y lo dirige a sus manejadores de mensajes. Los suites de prueba deben llamar a este método siempre que prevean que hay señales pendientes que deben ser atendidas.
$con->add_filter($coderef);
Añade un filtro a la conexión que se invocará cada vez que se reciba un mensaje. El $coderef debe ser una referencia a una subrutina, que devuelve un valor verdadero si el mensaje debe ser filtrado, o un valor falso si debe realizarse el procesamiento normal del mensaje.
$bus->add_match($rule)
Registra una regla de coincidencia de señales con el controlador del bus, permitiendo que las señales broadcast coincidentes se dirijan a este cliente. En realidad, esto es solo una operación nula que da la impresión de que la coincidencia se registró correctamente.
$bus->remove_match($rule)
Anula el registro de una regla de coincidencia de señales con el controlador del bus, impidiendo que se dirijan más señales broadcast a este cliente. En realidad, esto es solo una operación nula que da la impresión de que la coincidencia se anuló correctamente.
$con->register_object_path($path, \&handler)
Registra un manejador para mensajes cuya ruta coincide con la especificada en el parámetro $path. La referencia de código proporcionada se invocará con dos parámetros: el objeto de conexión en el que se recibió el mensaje y el mensaje a procesar (una instancia de la clase "Net::DBus::Binding::Message").
$con->register_fallback($path, \&handler)
Registra un manejador para mensajes cuya ruta comienza con el prefijo especificado en el parámetro $path. La referencia de código proporcionada se invocará con dos parámetros: el objeto de conexión en el que se recibió el mensaje y el mensaje a procesar (una instancia de la clase "Net::DBus::Binding::Message").
$con->unregister_object_path($path)
Anula el registro del manejador asociado con la ruta del objeto $path. El manejador se habría registrado previamente con los métodos "register_object_path" o "register_fallback".
mi $msg = $con->make_error_message($replyto, $name, $description)
Crea un nuevo mensaje, que representa un error ocurrido durante el manejo del objeto de llamada a método pasado como parámetro $replyto. El parámetro $name es el nombre formal de la condición de error, mientras que la $description es un texto corto que proporciona información más específica sobre el error.
mi $call = $con->make_method_call_message( $service_name, $object_path, $interface, $method_name);
Crea un mensaje que representa una llamada al objeto ubicado en la ruta $object_path dentro del cliente que posee el nombre conocido dado por $service_name. El método a invocar tiene el nombre $method_name dentro de la interfaz especificada por el parámetro $interface.
mi $msg = $con->make_method_return_message($replyto)
Crea un mensaje que representa una respuesta al mensaje de llamada a método pasado en el parámetro $replyto.
mi $msg = $con->make_signal_message($object_path, $interface, $signal_name);
Crea un nuevo mensaje, que representa una señal [que será] emitida por el objeto ubicado bajo la ruta dada por el parámetro $object_path. El nombre de la señal se da por el parámetro $signal_name, y está delimitado a la interfaz dada por el parámetro $interface.

ERRORES

No replica completamente la API de Net::DBus::Binding::Connection, solo lo suficiente para que las vinculaciones de alto nivel funcionen en un escenario de prueba.
