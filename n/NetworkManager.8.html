NETWORKMANAGER(8) Demonios de gestión de red NETWORKMANAGER(8)

NOMBRE

NetworkManager - demonio de gestión de red

SINOPSIS

NetworkManager [OPCIONES...]

DESCRIPCIÓN

El demonio NetworkManager intenta que la configuración y operación de la red sean lo más sencillas y automáticas posible, gestionando la conexión de red principal y otras interfaces de red, como dispositivos Ethernet, Wi-Fi y banda ancha móvil. NetworkManager conectará cualquier dispositivo de red cuando una conexión para ese dispositivo esté disponible, a menos que ese comportamiento esté deshabilitado. La información sobre la red se exporta a través de una interfaz D-Bus a cualquier aplicación interesada, proporcionando una rica API con la que inspeccionar y controlar la configuración y operación de la red.

SCRIPTS DE DESPACHADOR

El servicio NetworkManager-dispatcher puede ejecutar scripts para el usuario en respuesta a eventos de red. Consulte el manual de NetworkManager-dispatcher(8).

OPCIONES

Se entienden las siguientes opciones:

--version | -V

Muestra la versión del software NetworkManager y sale.

--help | -h

Muestra las opciones disponibles de NetworkManager y sale.

--no-daemon | -n

No se demoniza.

--debug | -d

No se demoniza y dirige la salida del registro a la terminal de control además de syslog.

--pid-file | -p

Especifica la ubicación de un archivo PID. El archivo PID se utiliza para almacenar el PID del proceso en ejecución y evita ejecutar múltiples instancias.

--state-file

Especifica el archivo para almacenar el estado de NetworkManager de forma persistente. Si no se especifica, se utiliza el valor predeterminado de /var/lib/NetworkManager/NetworkManager.state.

--config

Especifica el archivo de configuración para establecer varias opciones para NetworkManager. Si no se especifica, se utiliza el valor predeterminado de /etc/NetworkManager/NetworkManager.conf con una opción de reserva al antiguo 'nm-system-settings.conf' si se encuentra en el mismo directorio. Consulte NetworkManager.conf(5) para más información sobre el archivo de configuración.

--configure-and-quit [initrd]

Sale después de que todos los dispositivos alcancen un estado estable. El parámetro opcional initrd habilita el modo en el que no quedan procesos en ejecución después de que NetworkManager se detiene, lo cual es útil para ejecutarse desde un disco RAM inicial al arrancar temprano.

--plugins

Lista los plugins utilizados para gestionar la configuración de conexión a nivel de sistema. Esta lista tiene preferencia sobre los plugins especificados en el archivo de configuración. Consulte la opción main.plugins en NetworkManager.conf(5) para ver las opciones soportadas.

--log-level

Establece cuánta información envía NetworkManager al destino del registro (generalmente la instalación "daemon" de syslog). Por predeterminado, solo se registran los mensajes informativos, de advertencia y de error. Consulte la sección sobre registro en NetworkManager.conf(5) para más información.

--log-domains

Una lista separada por comas que especifica qué operaciones se registran en el destino del registro (generalmente syslog). Por defecto, la mayoría de los dominios están habilitados para el registro. Consulte la sección sobre registro en NetworkManager.conf(5) para más información.

--print-config

Muestra la configuración de NetworkManager en la salida estándar y sale. Consulte NetworkManager.conf(5). Esto no incluye los perfiles de conexión. Vélos con nmcli connection.

Esto lee los archivos de configuración del disco. Si NetworkManager se está ejecutando actualmente, asegúrese de que tenga la misma configuración cargada.

PROPIEDADES UDEV

El gestor de dispositivos udev(7) se utiliza para el descubrimiento de dispositivos de red. La siguiente propiedad influye en cómo NetworkManager gestiona los dispositivos:

NM_UNMANAGED

Si se establece en "1" o "true", el dispositivo se configura como no administrado por NetworkManager. Tenga en cuenta que el usuario aún puede anular explícitamente esta configuración mediante métodos como nmcli device set "$DEVICE" managed yes o "device*.managed=1" en NetworkManager.conf.

ID_NET_MANAGED_BY

Si NM_UNMANAGED está establecido, esto no tiene efecto. De lo contrario, si el atributo se establece en algo distinto de "org.freedesktop.NetworkManager", el dispositivo no es administrado.

NM_AUTO_DEFAULT_LINK_LOCAL_ONLY

Si se establece en "1" o "true", las conexiones generadas automáticamente "Conexión por cable N" solo habilitarán el direccionamiento de enlace local para IPv4 e IPv6. Esto puede ser útil en dispositivos Thunderbolt o dispositivos USB de host a host.

ID_NET_AUTO_LINK_LOCAL_ONLY

Se respeta y se trata igual que si se hubiera establecido NM_AUTO_DEFAULT_LINK_LOCAL_ONLY.

ID_NET_DHCP_BROADCAST

Si se establece en "1" o "true", utiliza solicitudes de difusión para ofertas DHCPv4. Esto puede tener sentido para dispositivos que no pueden manejar mensajes unicast hasta que se configuran.

SEÑALES

El proceso NetworkManager maneja las siguientes señales:

SIGHUP

La señal provoca una recarga de la configuración de NetworkManager. Tenga en cuenta que no todos los parámetros de configuración se pueden cambiar en tiempo de ejecución y, por lo tanto, algunos cambios solo se aplicarán después del próximo reinicio del demonio. Un SIGHUP también implica acciones de recarga adicionales, como realizar una actualización de DNS y reiniciar el plugin de DNS. Esto último puede ser útil, por ejemplo, al usar el plugin dnsmasq y cambiar su configuración en /etc/NetworkManager/dnsmasq.d. Sin embargo, también significa que se interrumpirá brevemente la resolución de nombres. En el futuro, pueden añadirse más acciones. Un SIGHUP significa actualizar la configuración de NetworkManager y recargar todo lo que esté soportado. Tenga en cuenta que esto no recarga las conexiones desde el disco. Para eso existe una API D-Bus y la acción reload de nmcli.

SIGUSR1

La señal fuerza una reescritura de la configuración de DNS. A diferencia de SIGHUP, esto no reinicia el plugin de DNS y no interrumpirá la resolución de nombres. Cuando NetworkManager no está gestionando DNS, la señal fuerza un reinicio de las operaciones que dependen de la configuración de DNS (como la resolución del nombre de host del sistema mediante DNS inverso, o la resolución de pares de WireGuard); por lo tanto, se puede usar para indicar a NetworkManager que el contenido de resolv.conf ha sido cambiado externamente. En el futuro, pueden añadirse acciones adicionales. Un SIGUSR1 significa escribir datos como resolv.conf, o refrescar una caché. Es un subconjunto de lo que se hace para SIGHUP sin recargar la configuración desde el disco.

SIGUSR2

La señal no tiene efecto en este momento, pero está reservada para uso futuro.

Una alternativa a una señal para recargar la configuración es la llamada D-Bus Reload. Permite una selección más granular de lo que se recarga, solo retorna después de que la recarga se completa, y está protegida por PolicyKit.

DEPURACIÓN

NetworkManager solo configura su sistema. Por lo tanto, cuando la configuración de su red no funciona como se esperaba, el primer paso es examinar su sistema para comprender qué está configurado realmente y si es correcto. El segundo paso es averiguar cómo hacer que NetworkManager haga lo correcto.

Por ejemplo, puede intentar hacer ping a hosts (por dirección IP o nombre DNS), ver ip link show, ip address show y ip route show, y mirar /etc/resolv.conf para problemas de resolución de nombres. También examine los perfiles de conexión que ha configurado en NetworkManager (nmcli connection y nmcli connection show "$PROFILE") y las interfaces configuradas (nmcli device).

Si eso no es suficiente, examine los archivos de registro de NetworkManager. NetworkManager registra en syslog, por lo que, dependiendo de la configuración de su sistema, puede llamar a journalctl para obtener los registros. Por defecto, los registros de NetworkManager no son verborrágicos y, por lo tanto, no son muy

/VAR/LIB/NETWORKMANAGER/SECRET_KEY AND /ETC/MACHINE-ID

La identidad de una máquina es importante, ya que varias configuraciones dependen de ella. Por ejemplo, ipv6.addr-gen-mode=stable y ethernet.cloned-mac-address=stable generan identificadores hasheando la identidad de la máquina. Ver también la propiedad de conexión connection.stable-id, que es una semilla por perfil que se hashea con la identidad de la máquina para generar estas direcciones e identificadores.

Si copia y restaura una máquina, probablemente debería preservar la identidad de la máquina. En ese caso, preserve los archivos /var/lib/NetworkManager/secret_key y /etc/machine-id. Por otro lado, si clona una máquina virtual, probablemente querrá que la clonación tenga una identidad diferente. Ya existen herramientas en Linux para manejar /etc/machine-id (ver machine-id(5)).

La identidad de la máquina se determina mediante /var/lib/NetworkManager/secret_key. Si este archivo no existe, NetworkManager creará un archivo con contenido aleatorio. Para generar una nueva identidad, simplemente elimine el archivo y, después de reiniciar, se creará un nuevo archivo. El archivo debe ser de solo lectura para root y debe contener al menos 16 bytes que se utilizarán para sembrar los diversos lugares donde se utilizan identificadores estables.

A partir de la versión 1.16.0, NetworkManager soporta una versión 2 de claves secretas. Para dicha clave, /var/lib/NetworkManager/secret_key comienza con "nm-v2:" en ASCII seguido de al menos 32 bytes de datos aleatorios. Además, las versiones recientes de NetworkManager siempre crean dichas claves secretas cuando el archivo aún no existe. Con la clave secreta versión 2, /etc/machine-id también se hashea como parte de la generación de direcciones e identificadores. La ventaja es que puede mantener /var/lib/NetworkManager/secret_key estable, y solo necesita generar /etc/machine-id cuando clona una VM.
