NOMBRE

Net::LDAP::Control::ProxyAuth - Objeto de control de autorización de proxy LDAPv3

SINOPSIS

use Net::LDAP;
use Net::LDAP::Control::ProxyAuth;
$ldap = Net::LDAP->new( "ldap.mydomain.eg" );
$auth = Net::LDAP::Control::ProxyAuth->new( authzID => 'dn:cn=me,ou=people,o=myorg.com' );
@args = ( base     => "cn=subnets,cn=sites,cn=configuration,$BASE_DN",
          scope    => "subtree",
          filter   => "(objectClass=subnet)",
          callback => \&process_entry, # Llamar a esta subrutina para cada entrada
          control  => [ $auth ],
);
while (1) {
  # Realizar búsqueda
  my $mesg = $ldap->search( @args );
  # Continuar solo con LDAP_SUCCESS
  $mesg->code and last;
}

DESCRIPCIÓN

"Net::LDAP::Control::ProxyAuth" proporciona una interfaz para la creación y manipulación de objetos que representan el "Control de Autorización de Proxy" según se describe en la RFC 4370.

Permite que un cliente se vincule a un servidor LDAP con su propia identidad, pero para realizar operaciones en nombre de otro usuario, el "authzID".

Con la excepción de cualquier extensión que cause un cambio en la autenticación, autorización o confidencialidad de los datos, un único "Control de Autorización de Proxy" puede incluirse en cualquier operación de búsqueda, comparación, modificación, adición, eliminación, moddn o extendida.

Según lo requerido por la RFC, la criticidad de este control se establece automáticamente en TRUE para proteger a los clientes de enviar solicitudes con identidades distintas a las que pretenden.

ARGUMENTOS DEL CONSTRUCTOR

Además de los argumentos del constructor descritos en Net::LDAP::Control, se proporcionan los siguientes.

authzID
El authzID requerido. Esta es la identidad que solicitamos que utilicen las operaciones.
proxyDN
En versiones tempranas de los borradores de la RFC 4370, draft-weltman-ldapv3-proxy-XX.txt, el valor en el control y, por lo tanto, el argumento del constructor era un DN y se llamaba "proxyDN". Cumplía el mismo propósito que "authzID" en las versiones recientes del control de "proxyAuthorization".

Tenga en cuenta: Desafortunadamente, el OID y la codificación del "Control de Autorización de Proxy" cambiaron significativamente entre las versiones tempranas de draft-weltman-ldapv3-proxy-XX.txt y la RFC final. Net::LDAP::Control::ProxyAuth intenta hacer frente a esa situación y cambia el OID y la codificación utilizados según el argumento del constructor.

Con "proxyDN" como argumento del constructor, se utilizan el OID y la codificación antiguos, mientras que con "authzID" como argumento del constructor, se utilizan el nuevo OID y la codificación. Utilizando esta lógica, los servidores que admitan cualquiera de los OID pueden ser manejados correctamente.

MÉTODOS

Al igual que con Net::LDAP::Control, cada argumento del constructor descrito anteriormente también está disponible como un método en el objeto que devolverá el valor actual del atributo si se llama sin argumento, y establecerá un nuevo valor para el atributo si se llama con un argumento.
