NEXT(3perl) Perl Programmers Reference Guide NEXT(3perl)

NOMBRE

NEXT - Proporciona una pseudoclase NEXT (et al) que permite la redespachado de métodos

SINOPSIS

use NEXT;
package P;
sub P::method   { print "$_[0]: P method\n";   $_[0]->NEXT::method() }
sub P::DESTROY  { print "$_[0]: P dtor\n";     $_[0]->NEXT::DESTROY() }
package Q;
use base qw( P );
sub Q::AUTOLOAD { print "$_[0]: Q AUTOLOAD\n"; $_[0]->NEXT::AUTOLOAD() }
sub Q::DESTROY  { print "$_[0]: Q dtor\n";     $_[0]->NEXT::DESTROY() }
package R;
sub R::method   { print "$_[0]: R method\n";   $_[0]->NEXT::method() }
sub R::AUTOLOAD { print "$_[0]: R AUTOLOAD\n"; $_[0]->NEXT::AUTOLOAD() }
sub R::DESTROY  { print "$_[0]: R dtor\n";     $_[0]->NEXT::DESTROY() }
package S;
use base qw( Q R );
sub S::method   { print "$_[0]: S method\n";   $_[0]->NEXT::method() }
sub S::AUTOLOAD { print "$_[0]: S AUTOLOAD\n"; $_[0]->NEXT::AUTOLOAD() }
sub S::DESTROY  { print "$_[0]: S dtor\n";     $_[0]->NEXT::DESTROY() }
package main;
my $obj = bless {}, "S";
$obj->method();             # Llama a S::method, P::method, R::method
$obj->missing_method(); # Llama a S::AUTOLOAD, Q::AUTOLOAD, R::AUTOLOAD
# La limpieza llama a S::DESTROY, Q::DESTROY, P::DESTROY, R::DESTROY

DESCRIPCIÓN

El módulo "NEXT" añade una pseudoclase llamada "NEXT" a cualquier programa que lo utilice. Si un método "m" llama a "$self->NEXT::m()", la llamada a "m" se redespacha como si el método llamante no se hubiera encontrado originalmente.

Nota: antes de usar este módulo, deberías mirar next::method https://metacpan.org/pod/mro#next::method en el módulo mro principal. "mro" es un módulo principal desde Perl 5.9.5.

En otras palabras, una llamada a "$self->NEXT::m()" reanuda la búsqueda en profundidad, de izquierda a derecha, de la jerarquía de clases de $self que resultó en la llamada original a "m".

Ten en cuenta que esto no es lo mismo que "$self->SUPER::m()", que inicia un nuevo despacho que se limita a buscar en los ancestros de la clase actual. "$self->NEXT::m()" puede retroceder más allá de la clase actual - para buscar un método adecuado en otros ancestros de $self - mientras que "$self->SUPER::m()" no puede.

Un uso típico sería en los destructores de una jerarquía de clases, como se ilustra en la SINOPIS anterior. Cada clase en la jerarquía tiene un método DESTROY que realiza una acción específica de la clase y luego redespacha la llamada hacia arriba en la jerarquía. Como resultado, cuando se destruye un objeto de la clase S, se llaman los destructores de *todos* sus superclases (en orden de profundidad, de izquierda a derecha).

Otro uso típico del redespachado sería en métodos "AUTOLOAD". Si un método de este tipo determinara que no podía manejar una llamada particular, podría optar por redespachar esa llamada, con la esperanza de que algún otro "AUTOLOAD" (por encima de él, o a su izquierda) lo hiciera mejor.

Por defecto, si un intento de redespachado no encuentra otro método en otra parte de la jerarquía de clases del objeto, simplemente se rinde y no hace nada (pero véase "Forzar redespachado"). Esta amable aceptación también es diferente del comportamiento (generalmente molesto) de "SUPER", que lanza una excepción si no puede redespachar.

Ten en cuenta que es un error fatal para cualquier método (incluido "AUTOLOAD") intentar redespachar cualquier método que no tenga el mismo nombre. Por ejemplo:

sub S::oops { print "oops!\n"; $_[0]->NEXT::other_method() }

Forzar redespachado

Es posible hacer que "NEXT" redespache de forma más exigente (es decir, como lo hace "SUPER"), de modo que el redespachado lance una excepción si no puede encontrar un método "siguiente" al que llamar.

Para hacer esto, simplemente invoca el redespachado como:

$self->NEXT::ACTUAL::method();

en lugar de:

$self->NEXT::method();

El "ACTUAL" le dice a "NEXT" que debe haber realmente un método siguiente que llamar, o lanzará una excepción.

"NEXT::ACTUAL" se usa más comúnmente en métodos "AUTOLOAD", como un medio para rechazar una solicitud de "AUTOLOAD", pero preservando la semántica normal de excepción si falla:

sub AUTOLOAD {
        if ($AUTOLOAD =~ /foo|bar/) {
                # manejar aquí
        }
        else {  # intentar en otro lugar
                shift()->NEXT::ACTUAL::AUTOLOAD(@_);
        }
}

Al usar "NEXT::ACTUAL", si no hay otro "AUTOLOAD" que maneje la llamada al método, se lanzará una excepción (como suele suceder en ausencia de un "AUTOLOAD" adecuado).

Evitar repeticiones

Si se utiliza el redespachado de "NEXT" en los métodos de una jerarquía de clases en forma de "diamante":

#     A   B
#    / \ /
#   C   D
#    \ /
#     E
use NEXT;
package A;                 
sub foo { print "llamado A::foo\n"; shift->NEXT::foo() }
package B;                 
sub foo { print "llamado B::foo\n"; shift->NEXT::foo() }
package C; @ISA = qw( A );
sub foo { print "llamado C::foo\n"; shift->NEXT::foo() }
package D; @ISA = qw(A B);
sub foo { print "llamado D::foo\n"; shift->NEXT::foo() }
package E; @ISA = qw(C D);
sub foo { print "llamado E::foo\n"; shift->NEXT::foo() }
E->foo();

entonces las clases derivadas pueden heredar (o volver a heredar) métodos de la superclase a través de dos o más caminos distintos (por ejemplo, en la forma en que "E" hereda "A::foo" dos veces - a través de "C" y "D"). En tales casos, una secuencia de redespachados de "NEXT" invocará el método heredado múltiples veces tantas veces como se herede. Por ejemplo, el código anterior imprime:

llamado E::foo
llamado C::foo
llamado A::foo
llamado D::foo
llamado A::foo
llamado B::foo

(es decir, "A::foo" se llama dos veces).

En algunos casos, este puede ser el efecto deseado dentro de una jerarquía de diamantes, pero en otros (por ejemplo, para destructores) puede ser más apropiado llamar a cada método solo una vez durante una secuencia de redespachados.

Para cubrir tales casos, puedes redespachar métodos a través de:

$self->NEXT::DISTINCT::method();

en lugar de:

$self->NEXT::method();

Esto hace que el redespachador visite cada método "method" distinto solo una vez. Es decir, que salte cualquier clase en la jerarquía que ya haya visitado durante el redespachado. Así, por ejemplo, si el ejemplo anterior se reescribiera:

package A;                 
sub foo { print "llamado A::foo\n"; shift->NEXT::DISTINCT::foo() }
package B;                 
sub foo { print "llamado B::foo\n"; shift->NEXT::DISTINCT::foo() }
package C; @ISA = qw( A );
sub foo { print "llamado C::foo\n"; shift->NEXT::DISTINCT::foo() }
package D; @ISA = qw(A B);
sub foo { print "llamado D::foo\n"; shift->NEXT::DISTINCT::foo() }
package E; @ISA = qw(C D);
sub foo { print "llamado E::foo\n"; shift->NEXT::DISTINCT::foo() }
E->foo();

entonces imprimiría:

llamado E::foo
llamado C::foo
llamado A::foo
llamado D::foo
llamado B::foo

y omitiría la segunda llamada a "A::foo" (ya que no sería distinta de la primera llamada a "A::foo").

Nota que también puedes usar:

$self->NEXT::DISTINCT::ACTUAL::method();

o:

$self->NEXT::ACTUAL::DISTINCT::method();

para obtener tanto la invocación única *como* la excepción si falla.

Nota que, por compatibilidad histórica, también puedes usar "NEXT::UNSEEN" en lugar de "NEXT::DIST

NEXT(3perl) — Manual de Perl

NAME

NEXT - Invocando múltiples versiones de un método con una sola llamada

SYNOPSIS

    use NEXT;
    $obj->NEXT::method(@args);
    $obj->EVERY::method(@args);
    $obj->EVERY::LAST::method(@args);

DESCRIPTION

El módulo "NEXT" proporciona dos pseudo-clases, "NEXT" y "EVERY", que le permiten invocar explícitamente versiones de métodos heredados por un objeto. Esto es particularmente útil en contextos como la herencia múltiple o la delegación de objetos donde el comportamiento estándar de búsqueda de métodos de Perl puede no ser el deseado.

Invocando una versión específica de un método

Si desea invocar un método específico en la jerarquía de herencia de un objeto, en lugar de confiar en el orden predeterminado de Perl de buscar el método más específico primero, puede usar la pseudo-clase "NEXT".

Por ejemplo, si tiene:

    package A;
    sub foo { print "A" }
    package B;
    @ISA = qw(A);
    sub foo { print "B" }
    package C;
    @ISA = qw(B);
    sub foo { print "C" }
    package main;
    my $obj = C->new;
    $obj->foo;           # imprime "C"
    $obj->NEXT::foo;     # imprime "B"
    $obj->NEXT::NEXT::foo; # imprime "A"

La llamada "$obj->NEXT::foo" invoca la versión del método "foo" en la clase inmediatamente superior en la jerarquía de herencia de "$obj". Cada uso adicional de "NEXT::" avanza un nivel más en la jerarquía, invocando la versión del método de esa clase padre.

Esto le permite anular un método en una clase derivada y aún así llamar explícitamente a las implementaciones de las clases base o padre.

Invocando todas las versiones de un método con una sola llamada

Otra pseudo-clase que "NEXT" proporciona es "EVERY". Su comportamiento es considerablemente más simple que el de la familia "NEXT". Una llamada a:

$obj->EVERY::foo();

llama a *cada* método llamado "foo" que el objeto en $obj ha heredado. Es decir:

use NEXT;
package A; @ISA = qw(B D X);
sub foo { print "A::foo " }
package B; @ISA = qw(D X);
sub foo { print "B::foo " }
package X; @ISA = qw(D);
sub foo { print "X::foo " }
package D;
sub foo { print "D::foo " }
package main;
my $obj = bless {}, 'A';
$obj->EVERY::foo();        # imprime" A::foo B::foo X::foo D::foo

Prefijar una llamada a método con "EVERY::" hace que todos los métodos en la jerarquía del objeto con ese nombre sean invocados. Como ilustra el ejemplo anterior, no se llaman en el orden habitual de Perl de "izquierda-más-profundidad-primero". En su lugar, se llaman "amplitud-primero-según-dependencia".

Eso significa que el árbol de herencia del objeto se recorre en amplitud y el orden resultante de las clases se utiliza como la secuencia en la que se llaman los métodos. Sin embargo, esa secuencia se modifica imponiendo la regla de que el método apropiado de una clase derivada debe llamarse antes que el mismo método de cualquier clase ancestral. Por eso, en el ejemplo anterior, "X::foo" se llama antes que "D::foo", aunque "D" venga antes que "X" en @B::ISA.

En general, no hay necesidad de preocuparse por el orden de las llamadas. Serán de izquierda a derecha, en amplitud, el más derivado primero. Esto funciona perfectamente para la mayoría de los métodos heredados (incluidos los destructores), pero es inapropiado para algunos tipos de métodos (como constructores, clonadores, depuradores e inicializadores) donde es más apropiado que se llamen primero los métodos menos derivados (ya que los métodos más derivados pueden depender del comportamiento de sus "ancestros"). En ese caso, en lugar de usar la pseudo-clase "EVERY":

$obj->EVERY::foo();        # imprime" A::foo B::foo X::foo D::foo

puede usar la pseudo-clase "EVERY::LAST":

$obj->EVERY::LAST::foo();  # imprime" D::foo X::foo B::foo A::foo

que invierte el orden de la llamada al método.

Sea cual sea la versión utilizada, los métodos reales se llaman en el mismo contexto (lista, escalar o vacío) que la llamada original a través de "EVERY", y devuelven:

  • Un hash de referencias a arrays en contexto de lista. Cada entrada del hash tiene el nombre completo del método calificado como clave y una referencia a un array que contiene los valores de retorno del método en contexto de lista como su valor.
  • Una referencia a un hash de valores escalares en contexto escalar. Cada entrada del hash tiene el nombre completo del método calificado como clave y los valores de retorno del método en contexto escalar como su valor.
  • Nada en contexto vacío (obviamente).

Usando métodos "EVERY"

La forma típica de usar una llamada "EVERY" es envolverla en otro método base, que todas las clases heredan. Por ejemplo, para asegurar que se llame a cada destructor que un objeto hereda (en lugar de solo al primero en orden de izquierda-más-profundidad):

package Base;
sub DESTROY { $_[0]->EVERY::Destroy }
package Derived1; 
use base 'Base';
sub Destroy {...}
package Derived2; 
use base 'Base', 'Derived1';
sub Destroy {...}

etcétera. Cada clase derivada que necesita su propio comportamiento de limpieza simplemente agrega su propio método "Destroy" ( *no* un método "DESTROY"), que la llamada a "EVERY::LAST::Destroy" en el destructor heredado captura correctamente.

Del mismo modo, para crear una jerarquía de clases en la que se invoque cada inicializador heredado por un nuevo objeto:

package Base;
sub new {
        my ($class, %args) = @_;
        my $obj = bless {}, $class;
        $obj->EVERY::LAST::Init(\%args);
}
package Derived1; 
use base 'Base';
sub Init {
        my ($argsref) = @_;
        ...
}
package Derived2; 
use base 'Base', 'Derived1';
sub Init {
        my ($argsref) = @_;
        ...
}

etcétera. Cada clase derivada que necesita un comportamiento de inicialización adicional simplemente agrega su propio método "Init" ( *no* un método "new"), que la llamada a "EVERY::LAST::Init" en el constructor heredado captura correctamente.

ERRORES E IRRITACIONES

Al ser un módulo, no una parte integral del intérprete, "NEXT" tiene que adivinar dónde se encontró la llamada circundante en la secuencia de búsqueda de métodos. En presencia de patrones de herencia de diamante, a veces adivina incorrectamente.

También es demasiado lento (a pesar del caché).
