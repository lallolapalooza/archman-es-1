Net::DBus::Exporter(3) Documentación de Perl contribuida por el usuario Net::DBus::Exporter(3)

NOMBRE

Net::DBus::Exporter - Exportar métodos y señales de objetos al bus

SINOPSIS

# Define un nuevo paquete para el objeto que vamos a
# exportar
package Demo::HelloWorld;
# Especifica la interfaz principal proporcionada por nuestro objeto
use Net::DBus::Exporter qw(org.example.demo.Greeter);
# Vamos a ser un objeto DBus
use base qw(Net::DBus::Object);
# Asegura que solo los métodos explícitamente exportados puedan ser invocados
dbus_strict_exports;
# Exporta una señal 'Greeting' que acepta un parámetro de cadena
dbus_signal("Greeting", ["string"]);
# Exporta 'Hello' como un método que acepta un solo parámetro de cadena
# y devuelve un solo valor de cadena
dbus_method("Hello", ["string"], ["string"]);
# Exporta 'Goodbye' como un método que acepta un solo parámetro de cadena
# y devuelve una sola cadena, pero lo coloca en la interfaz
# 'org.example.demo.Farewell'
dbus_method("Goodbye", ["string"], ["string"], "org.example.demo.Farewell");

DESCRIPCIÓN

El módulo "Net::DBus::Exporter" se utiliza para exportar métodos y señales definidos en un objeto al bus de mensajes. Dado que Perl es un lenguaje de tipado débil, no es posible determinar automáticamente la información de tipo correcta para los métodos que se van a exportar. Por lo tanto, al crear una subclase de Net::DBus::Object, este paquete proporcionará la información de tipo para los métodos y señales.

Al importar este paquete, se puede suministrar un argumento opcional para especificar el nombre de la interfaz predeterminada a asociar con los métodos y señales para los que no se especifica una interfaz explícita. Por lo tanto, en el caso común de objetos que solo proporcionan una única interfaz, esto elimina la necesidad de repetir el nombre de la interfaz en cada método exportado.

TIPOS ESCALARES

Al especificar tipos de datos escalares para parámetros y valores de retorno, se deben utilizar las siguientes constantes de cadena para denotar el tipo de dato. Cuando los valores correspondientes a estos tipos se (des)serializan, se representan como el tipo de dato ESCALAR de Perl (ver perldata).

"string"
Una cadena de caracteres UTF-8
"int16"
Un entero con signo de 16 bits
"uint16"
Un entero sin signo de 16 bits
"int32"
Un entero con signo de 32 bits
"uint32"
Un entero sin signo de 32 bits
"int64"
Un entero con signo de 64 bits. NOTA: este tipo no es compatible con muchas compilaciones de Perl en plataformas de 32 bits, por lo que si se utiliza, es probable que sus datos se trunquen a 32 bits.
"uint64"
Un entero sin signo de 64 bits. NOTA: este tipo no es compatible con muchas compilaciones de Perl en plataformas de 32 bits, por lo que si se utiliza, es probable que sus datos se trunquen a 32 bits.
"byte"
Un solo byte de 8 bits
"bool"
Un valor booleano
"double"
Un punto flotante de doble precisión IEEE

TIPOS COMPUESTOS

Al especificar tipos de datos compuestos para parámetros y valores de retorno, se debe usar una referencia a un array, siendo el primer elemento el nombre del tipo compuesto.

["array", TIPO-ARRAY]
Un array de valores, cuyo tipo es "TIPO-ARRAY". El "TIPO-ARRAY" puede ser un nombre de tipo escalar o un tipo compuesto anidado. Cuando los valores correspondientes al tipo array se (des)serializan, se representan como el tipo de dato ARRAY de Perl (ver perldata). Si, por ejemplo, un método se declarara para tener un solo parámetro con el tipo ["array", "string"], entonces al llamar al método se proporcionaría una referencia a un array de cadenas: 
$object->hello(["John", "Doe"])
["dict", TIPO-CLAVE, TIPO-VALOR]
Un diccionario de valores, más comúnmente conocido como tabla hash. El "TIPO-CLAVE" es el nombre del tipo de dato escalar utilizado para las claves del diccionario. El "TIPO-VALOR" es el nombre del tipo de dato escalar o compuesto utilizado para los valores del diccionario. Cuando los valores correspondientes al tipo dict se (des)serializan, se representan como el tipo de dato HASH de Perl (ver perldata). Si, por ejemplo, un método se declarara para tener un solo parámetro con el tipo ["dict", "string", "string"], entonces al llamar al método se proporcionaría una referencia a un hash de cadenas, 
$object->hello({forename => "John", surname => "Doe"});
["struct", TIPO-VALOR-1, TIPO-VALOR-2]
Una estructura de valores, que se puede pensar como una variación del tipo array donde los elementos pueden variar. Muchos lenguajes tienen un nombre explícito asociado con cada valor, pero dado que Perl no tiene una representación nativa de estructuras, estas se representan mediante el tipo de dato LISTA. Si, por ejemplo, un método se declarara para tener un solo parámetro con el tipo ["struct", "string", "string"], correspondiente a la estructura C 
struct {
  char *forename;
  char *surname;
} name;

entonces, al llamar al método se proporcionaría una referencia a un array con los valores ordenados para que coincidan con la estructura

$object->hello(["John", "Doe"]);

TIPOS MÁGICOS

Al especificar datos de introspección para un servicio exportado, hay un par de los llamados tipos "mágicos". Los parámetros declarados como tipos mágicos no son visibles para los clientes, sino que sus valores son proporcionados automáticamente por los enlaces del lado del servidor. Un uso de los tipos mágicos es pasar un parámetro adicional con el nombre único del llamador que invoca el método.

"caller"
El valor pasado es el nombre único del llamador del método. Los nombres únicos son cadenas asignadas automáticamente a las conexiones de cliente por el demonio del bus, por ejemplo ':1.15'
"serial"
El valor pasado es un entero dentro del alcance de un llamador, que se incrementa en cada llamada al método.

ANOTACIONES

Al exportar métodos, señales y propiedades, además de la información central de tipado de datos, son posibles una serie de anotaciones de metadatos. Estas se especifican pasando una referencia a un hash con las claves deseadas como último parámetro al definir la exportación. Actualmente se admiten las siguientes anotaciones

no_return
Indica que este método no devuelve ningún valor, y por lo tanto, no se debe enviar ningún mensaje de respuesta por la red, informando igualmente a los clientes que no esperen / aguarden un mensaje de respuesta
deprecated
Indica que se desaconseja el uso de este método/señal/propiedad, y que puede desaparecer por completo en una futura versión. Los clientes normalmente imprimirán un mensaje de advertencia cuando se utilice un método/señal/propiedad obsoleto.
param_names
Un array de cadenas que especifican nombres para los parámetros de entrada del método o señal. Si se omite, no se asignarán nombres.
return_names
Un array de cadenas que especifican nombres para los parámetros de retorno del método. Si se omite, no se asignarán nombres.
strict_exceptions
Las excepciones lanzadas por este método que no sean de tipo Net::DBus::Error no serán capturadas ni convertidas a errores D-Bus. Serán relanzadas y continuarán subiendo por la pila hasta que algo más las capture (o el proceso muera).

MÉTODOS

dbus_method($name, $params, $returns, [\%annotations]);
dbus_method($name, $params, $returns, $interface, [\%annotations]);
Exporta un método llamado $name, teniendo parámetros cuyos tipos se definen por $params

Net::DBus::Exporter(3pm) - Arch Linux man pages

NAME

Net::DBus::Exporter - Introspection data generation for DBus objects

SYNOPSIS

 use Net::DBus::Exporter;
 use base qw(Net::DBus::Object);

 sub Example::Method { ... }
 dbus_method("Example::Method", [param_types], [return_types]);

 sub Example::Property { ... }
 dbus_property("Example::Property", $type, $access);

 sub Example::Signal { ... }
 dbus_signal("Example::Signal", [param_types]);

 dbus_no_strict_exports();

DESCRIPTION

This module is intended for use by subclasses of Net::DBus::Object. It provides the necessary functionality to export methods, properties, and signals from a DBus object, so that they can be discovered and invoked by other applications using DBus introspection.

When a class inherits from Net::DBus::Object, it automatically gains the ability to export these items. The dbus_method, dbus_property, and dbus_signal functions are exported into the caller's namespace, allowing them to be called directly.

By default, only methods, properties, and signals which have been explicitly exported using these functions will be visible via DBus introspection. See dbus_no_strict_exports() for details on how to alter this behaviour.

SCALAR TYPES

The following scalar type strings are supported:

string
Corresponds to DBus type s
boolean
Corresponds to DBus type b
byte
Corresponds to DBus type y
int16
Corresponds to DBus type n
uint16
Corresponds to DBus type q
int32
Corresponds to DBus type i
uint32
Corresponds to DBus type u
int64
Corresponds to DBus type x
uint64
Corresponds to DBus type t
double
Corresponds to DBus type d
object_path
Corresponds to DBus type o
signature
Corresponds to DBus type g
unix_fd
Corresponds to DBus type h

COMPOUND TYPES

array
The element type is specified as the next element in the array. For example, an array of strings is specified as ['array', 'string'].
dict
The key and value types are specified as the next two elements in the array. For example, a dictionary mapping strings to 32-bit integers is specified as ['dict', 'string', 'int32'].
struct
The element types are specified as the next elements in the array. For example, a struct containing a string and an integer is specified as ['struct', 'string', 'int32'].

MAGIC TYPES

There are two magic types that can be used in place of a normal type string:

variant
Corresponds to DBus type v. This can hold any valid DBus type, and the type is encoded within the value itself.
any
A convenience type that is equivalent to variant. It is recommended to use variant when specifying types to the DBus daemon, as any is purely a Perl-level convenience.

ANNOTATIONS

The dbus_method, dbus_property, and dbus_signal functions all accept an optional fourth argument which is a hash reference of annotations. These are stored as metadata associated with the exported item, and are visible via DBus introspection.

The following annotations are recognised by Net::DBus::Exporter itself:

deprecated
If set to true, this indicates that the method/property/signal is deprecated and should not be used.
no_return
If set to true, this indicates that the method does not return any values, even if the $returns parameter specifies some. This is useful for methods that perform an action but don't need to report success or failure via a return value.
param_names
An array reference of strings, giving names to the input parameters for a method or signal. These names are visible via DBus introspection.
return_names
An array reference of strings, giving names to the return values for a method. These names are visible via DBus introspection.

Any other keys in the annotation hash will be passed through uninterpreted, and will be visible via DBus introspection.

METHODS

dbus_method($name, $params, $returns, [\%attributes]);
dbus_method($name, $params, $returns, $interface, [\%attributes]);
Exports a method called $name, which accepts parameters whose types are defined by $params, and returning values whose types are defined by $returns. If the $interface parameter is provided, then the method is associated with that interface, otherwise the default interface for the calling package is used. The value for the $params parameter should be an array reference with each element defining the data type of a parameter to the method. Likewise, the $returns parameter should be an array reference with each element defining the data type of a return value. If it not possible to export a method which accepts a variable number of parameters, or returns a variable number of values.
dbus_no_strict_exports();
If a object is using the Exporter to generate DBus introspection data, the default behaviour is to only allow invocation of methods which have been explicitly exported.

To allow clients to access methods which have not been explicitly exported, call "dbus_no_strict_exports". NB, doing this may be a security risk if you have methods considered to be "private" for internal use only. As such this method should not normally be used. It is here only to allow switching export behaviour to match earlier releases.

dbus_property($name, $type, $access, [\%attributes]);
dbus_property($name, $type, $access, $interface, [\%attributes]);
Exports a property called $name, whose data type is $type. If the $interface parameter is provided, then the property is associated with that interface, otherwise the default interface for the calling package is used.
dbus_signal($name, $params, [\%attributes]);
dbus_signal($name, $params, $interface, [\%attributes]);
Exports a signal called $name, having parameters whose types are defined by $params. If the $interface parameter is provided, then the signal is associated with that interface, otherwise the default interface for the calling package is used. The value for the $params parameter should be an array reference with each element defining the data type of a parameter to the signal. Signals do not have return values. It not possible to export a signal which has a variable number of parameters.

EXAMPLES

No parameters, no return values
A method which simply prints "Hello World" each time its called 
sub Hello {
    my $self = shift;
    print "Hello World\n";
}
dbus_method("Hello", [], []);
One string parameter, returning an boolean value
A method which accepts a process name, issues the killall command on it, and returns a boolean value to indicate whether it was successful. 
sub KillAll {
    my $self = shift;
    my $processname = shift;
    my $ret  = system("killall $processname");
    return $ret == 0 ? 1 : 0;
}
dbus_method("KillAll", ["string"], ["bool"]);
One list of strings parameter, returning a dictionary
A method which accepts a list of files names, stats them, and returns a dictionary containing the last modification times. 
sub LastModified {
   my $self = shift;
   my $files = shift;
   my %mods;
   foreach my $file (@{$files}) {
      $mods{$file} = (stat $file)[9];
   }
   return \%mods;
}
dbus_method("LastModified", ["array", "string"], ["dict", "string", "int32"]);
Annotating methods with metdata
A method which is targeted for removal, and also does not return any value 
sub PlayMP3 {
    my $self = shift;
    my $track = shift;
    system "mpg123 $track &";
}
dbus_method("PlayMP3", ["string"], [], { deprecated => 1, no_return => 1 });

Or giving names to input parameters:

sub PlayMP3 {
    my $self = shift;
    my $track = shift;
    system "mpg123 $track &";
}
dbus_method("PlayMP3", ["string"], [], { param_names => ["track"] });

NOMBRE

Net::DBus::Exporter - Generación de datos de introspección para objetos DBus

SINOPSIS

 use Net::DBus::Exporter;
 use base qw(Net::DBus::Object);

 sub Ejemplo::Metodo { ... }
 dbus_method("Ejemplo::Metodo", [tipos_parametros], [tipos_retorno]);

 sub Ejemplo::Propiedad { ... }
 dbus_property("Ejemplo::Propiedad", $tipo, $acceso);

 sub Ejemplo::Senal { ... }
 dbus_signal("Ejemplo::Senal", [tipos_parametros]);

 dbus_no_strict_exports();

DESCRIPCION

Este módulo está destinado a ser utilizado por subclases de Net::DBus::Object. Proporciona la funcionalidad necesaria para exportar métodos, propiedades y señales desde un objeto DBus, de modo que puedan ser descubiertos e invocados por otras aplicaciones utilizando la introspección DBus.

Cuando una clase hereda de Net::DBus::Object, automáticamente adquiere la capacidad de exportar estos elementos. Las funciones dbus_method, dbus_property y dbus_signal se exportan en el espacio de nombres del llamador, lo que permite llamarlas directamente.

Por defecto, solo los métodos, propiedades y señales que se hayan exportado explícitamente utilizando estas funciones serán visibles a través de la introspección DBus. Consulte dbus_no_strict_exports() para obtener detalles sobre cómo modificar este comportamiento.

TIPOS ESCALARES

Se admiten las siguientes cadenas de tipos escalares:

cadena
Corresponde al tipo DBus s
booleano
Corresponde al tipo DBus b
byte
Corresponde al tipo DBus y
entero16
Corresponde al tipo DBus n
entero_sin_signo16
Corresponde al tipo DBus q
entero32
Corresponde al tipo DBus i
entero_sin_signo32
Corresponde al tipo DBus u
entero64
Corresponde al tipo DBus x
entero_sin_signo64
Corresponde al tipo DBus t
doble
Corresponde al tipo DBus d
ruta_objeto
Corresponde al tipo DBus o
firma
Corresponde al tipo DBus g
unix_fd
Corresponde al tipo DBus h

TIPOS COMPUESTOS

array
El tipo de elemento se especifica como el siguiente elemento en el array. Por ejemplo, un array de cadenas se especifica como ['array', 'cadena'].
diccionario
Los tipos de clave y valor se especifican como los dos siguientes elementos en el array. Por ejemplo, un diccionario que mapea cadenas a enteros de 32 bits se especifica como ['diccionario', 'cadena', 'entero32'].
estructura
Los tipos de elementos se especifican como los siguientes elementos en el array. Por ejemplo, una estructura que contiene una cadena y un entero se especifica como ['estructura', 'cadena', 'entero32'].

TIPOS MÁGICOS

Hay dos tipos mágicos que se pueden usar en lugar de una cadena de tipo normal:

variante
Corresponde al tipo DBus v. Puede contener cualquier tipo DBus válido, y el tipo se codifica dentro del propio valor.
cualquiera
Un tipo de conveniencia equivalente a variante. Se recomienda usar variante al especificar tipos al demonio DBus, ya que cualquiera es puramente una conveniencia a nivel de Perl.

ANOTACIONES

Las funciones dbus_method, dbus_property y dbus_signal aceptan un cuarto argumento opcional que es una referencia de hash de anotaciones. Estas se almacenan como metadatos asociados con el elemento exportado y son visibles a través de la introspección DBus.

Las siguientes anotaciones son reconocidas por el propio Net::DBus::Exporter:

deprecado
Si se establece en verdadero, esto indica que el método/propiedad/señal está obsoleto y no debe usarse.
sin_retorno
Si se establece en verdadero, esto indica que el método no devuelve ningún valor, incluso si el parámetro $returns especifica alguno. Esto es útil para métodos que realizan una acción pero no necesitan informar el éxito o el fracaso a través de un valor de retorno.
nombres_parametros
Una referencia de array de cadenas, que asigna nombres a los parámetros de entrada para un método o señal. Estos nombres son visibles a través de la introspección DBus.
nombres_retorno
Una referencia de array de cadenas, que asigna nombres a los valores de retorno de un método. Estos nombres son visibles a través de la introspección DBus.

Cualquier otra clave en el hash de anotaciones se pasará sin interpretación y será visible a través de la introspección DBus.

MÉTODOS

dbus_metodo($nombre, $parametros, $retornos, [\%atributos]);
dbus_metodo($nombre, $parametros, $retornos, $interfaz, [\%atributos]);
Exporta un método llamado $nombre, que acepta parámetros cuyos tipos están definidos por $parametros, y devuelve valores cuyos tipos están definidos por $retornos. Si se proporciona el parámetro $interfaz, entonces el método se asocia con esa interfaz, de lo contrario se utiliza la interfaz predeterminada para el paquete que llama. El valor para el parámetro $parametros debe ser una referencia de array con cada elemento que define el tipo de dato de un parámetro para el método. Del mismo modo, el parámetro $retornos debe ser una referencia de array con cada elemento que define el tipo de dato de un valor de retorno. No es posible exportar un método que acepte un número variable de parámetros, o devuelva un número variable de valores.
dbus_no_strict_exports();
Si un objeto está utilizando el Exportador para generar datos de introspección DBus, el comportamiento predeterminado es permitir solo la invocación de métodos que se hayan exportado explícitamente.

Para permitir que los clientes accedan a métodos que no se han exportado explícitamente, llame a "dbus_no_strict_exports". N.B., hacer esto puede ser un riesgo de seguridad si tiene métodos considerados "privados" solo para uso interno. Como tal, este método normalmente no debe usarse. Solo está aquí para permitir cambiar el comportamiento de exportación para que coincida con versiones anteriores.

dbus_propiedad($nombre, $tipo, $acceso, [\%atributos]);
dbus_propiedad($nombre, $tipo, $acceso, $interfaz, [\%atributos]);
Exporta una propiedad llamada $nombre, cuyo tipo de dato es $tipo. Si se proporciona el parámetro $interfaz, entonces la propiedad se asocia con esa interfaz, de lo contrario se utiliza la interfaz predeterminada para el paquete que llama.
dbus_senal($nombre, $parametros, [\%atributos]);
dbus_senal($nombre, $parametros, $interfaz, [\%atributos]);
Exporta una señal llamada $nombre, con parámetros cuyos tipos están definidos por $parametros. Si se proporciona el parámetro $interfaz, entonces la señal se asocia con esa interfaz, de lo contrario se utiliza la interfaz predeterminada para el paquete que llama. El valor para el parámetro $parametros debe ser una referencia de array con cada elemento que define el tipo de dato de un parámetro para la señal. Las señales no tienen valores de retorno. No es posible exportar una señal que tenga un número variable de parámetros.

EJEMPLOS

Sin parámetros, sin valores de retorno
Un método que simplemente imprime "Hola Mundo" cada vez que se llama. 
sub Hola {
    my $self = shift;
    print "Hola Mundo\n";
}
dbus_method("Hola", [], []);
Un parámetro de cadena, devolviendo un valor booleano
Un método que acepta un nombre de proceso, ejecuta el comando killall sobre él y devuelve un valor booleano para indicar si tuvo éxito. 
sub MatarTodo {
    my $self = shift;
    my $nombreproceso = shift;
    my $ret  = system("killall $nombreproceso");
    return $ret == 0 ? 1 : 0;
}
dbus_method("MatarTodo", ["cadena"], ["booleano"]);
Un parámetro de lista de cadenas, devolviendo un diccionario
Un método que acepta una lista de nombres de archivos, los analiza y devuelve un diccionario que contiene los tiempos de la última modificación. 
sub UltimaModificacion {
   my $self = shift;
   my $archivos = shift;
   my %modificaciones;
   foreach my $archivo (@{$archivos}) {
      $modificaciones{$archivo} = (stat $archivo)[9];
   }
   return \%modificaciones;
}
dbus_method("UltimaModificacion", ["array", "cadena"], ["diccionario", "cadena", "entero32"]);
Anotando métodos con metadatos
Un método que está marcado para su eliminación y tampoco devuelve ningún valor. 
sub ReproducirMP3 {
    my $self = shift;
    my $pista = shift;
    system "mpg123 $pista &";
}
dbus_method("ReproducirMP3", ["cadena"], [], { deprecado => 1, sin_retorno => 1 });

O asignando nombres a los parámetros de entrada:

sub ReproducirMP3 {
    my $self = shift;
    my $pista = shift;
    system "mpg123 $pista &";
}
dbus_method("ReproducirMP3", ["cadena"], [], { nombres_parametros => ["pista"] });
