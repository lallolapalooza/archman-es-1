NOMBRE

Net::DNS::Packet - Paquete del protocolo DNS

SINOPSIS

use Net::DNS::Packet;
$consulta = Net::DNS::Packet->new( 'ejemplo.com', 'MX', 'IN' );
$respuesta = $resolver->send( $consulta );

DESCRIPCIÓN

Un objeto Net::DNS::Packet representa un paquete del protocolo DNS.

MÉTODOS

new

$paquete = Net::DNS::Packet->new( 'ejemplo.com' );
$paquete = Net::DNS::Packet->new( 'ejemplo.com', 'MX', 'IN' );
$paquete = Net::DNS::Packet->new();

Si se pasa un dominio, tipo y clase, new() crea un objeto Net::DNS::Packet adecuado para realizar una consulta DNS para la información especificada. El tipo y clase pueden ser omitidos; por defecto, el tipo es A y la clase es IN.

Si se llama con un argumento vacío, new() crea un paquete vacío.

decode

$paquete = Net::DNS::Packet->decode( \$datos );
$paquete = Net::DNS::Packet->decode( \$datos, 1 );        # depurar
$paquete = Net::DNS::Packet->new( \$datos ... );

Se crea un nuevo objeto de paquete decodificando los datos del paquete DNS contenidos en el valor escalar referenciado por el primer argumento. El argumento booleano opcional habilita la salida de depuración.

Devuelve undef si no se puede crear el objeto de paquete.

Los errores de decodificación, incluyendo corrupción o truncamiento de datos, se recopilan en la variable $@ ($EVAL_ERROR).

( $paquete, $longitud ) = Net::DNS::Packet->decode( \$datos );

Si se llama en contexto de array, devuelve un objeto de paquete y el número de octetos decodificados correctamente.

Nota: El número de RRs en cada sección del paquete puede diferir del valor correspondiente en la cabecera si los datos han sido truncados o corruptos durante la transmisión.

encode

$datos = $paquete->encode;
$datos = $paquete->encode( $tamaño );

Devuelve los datos del paquete en formato binario, adecuado para enviar como consulta o solicitud de actualización a un servidor de nombres.

Se puede especificar el tamaño utilizando un argumento no nulo opcional.

header

$cabecera = $paquete->header;

Método constructor que devuelve un objeto Net::DNS::Header que representa la sección de cabecera del paquete.

edns

$version = $paquete->edns->version;
$UDPsize = $paquete->edns->size;

Función auxiliar que proporciona acceso al RR de extensión EDNS del protocolo.

reply

$respuesta = $consulta->reply( $UDPmax );

Método constructor que devuelve un nuevo paquete de respuesta.

El argumento UDPsize opcional indica el tamaño máximo del paquete UDP que puede ser reensamblado por la pila de red local, y se anuncia en respuesta a una consulta EDNS.

question, zone

@pregunta = $paquete->question;

Devuelve una lista de objetos Net::DNS::Question que representan la sección de pregunta del paquete.

En paquetes de actualización dinámica, esta sección se conoce como zone() y especifica la zona DNS a actualizar.

answer, pre, prerequisite

@respuesta = $paquete->answer;

Devuelve una lista de objetos Net::DNS::RR que representan la sección de respuesta del paquete.

En paquetes de actualización dinámica, esta sección se conoce como pre() o prerequisite() y especifica los RRs o RRsets que deben o no deben preexistir.

authority, update

@autoridad = $paquete->authority;

Devuelve una lista de objetos Net::DNS::RR que representan la sección de autoridad del paquete.

En paquetes de actualización dinámica, esta sección se conoce como update() y especifica los RRs o RRsets a agregar o eliminar.

additional

@adicional = $paquete->additional;

Devuelve una lista de objetos Net::DNS::RR que representan la sección adicional del paquete.

print

$paquete->print;

Imprime el paquete completo al archivo de salida actual utilizando el formato maestro impuesto por RFC1035.

string

print $paquete->string;

Devuelve una representación de cadena del paquete.

from

print "paquete recibido desde ", $paquete->from, "\n";

Devuelve la dirección IP desde la cual se recibió este paquete. Este método devolverá undef para paquetes creados por el usuario.

size

print "tamaño del paquete: ", $paquete->size, " octetos\n";

Devuelve el tamaño del paquete en octetos tal como se recibió de un servidor de nombres. Este método devolverá undef para paquetes creados por el usuario (use length($paquete->data) en su lugar).

push

$ancount = $paquete->push( prereq => $rr );
$nscount = $paquete->push( update => $rr );
$arcount = $paquete->push( additional => $rr );
$nscount = $paquete->push( update => $rr1, $rr2, $rr3 );
$nscount = $paquete->push( update => @rr );

Agrega RRs a la sección especificada del paquete.

Devuelve el número de registros de recursos en la sección especificada.

Los nombres de sección pueden abreviarse a los primeros tres caracteres.

unique_push

$ancount = $paquete->unique_push( prereq => $rr );
$nscount = $paquete->unique_push( update => $rr );
$arcount = $paquete->unique_push( additional => $rr );
$nscount = $paquete->unique_push( update => $rr1, $rr2, $rr3 );
$nscount = $paquete->unique_push( update => @rr );

Agrega RRs a la sección especificada del paquete, siempre que los RRs no estén ya presentes en la misma sección.

Devuelve el número de registros de recursos en la sección especificada.

Los nombres de sección pueden abreviarse a los primeros tres caracteres.

pop

my $rr = $paquete->pop( 'pre' );
my $rr = $paquete->pop( 'update' );
my $rr = $paquete->pop( 'additional' );

Elimina un RR de una sección específica del paquete.

sign_tsig

$consulta = Net::DNS::Packet->new( 'www.ejemplo.com', 'A' );
$consulta->sign_tsig(
        $archivo_clave,
        fudge => 60
        );
$respuesta = $res->send( $consulta );
$respuesta->verify( $consulta ) || die $respuesta->verifyerr;

Agrega un registro TSIG a un objeto Net::DNS::Packet, que se utilizará para firmar el paquete (ver RFC 2845).

El registro TSIG puede personalizarse mediante argumentos adicionales en el método sign_tsig() o mediante los métodos correspondientes de Net::DNS::RR::TSIG.

Si deseas crear un registro TSIG con un algoritmo no estándar, tendrás que crearlo tú mismo. En todos los casos, el nombre del registro TSIG debe identificar única y exclusivamente la clave compartida entre las partes, y el nombre del algoritmo debe identificar la función de firma a utilizar con la clave especificada.

$tsig = Net::DNS::RR->new(
        name            => 'tsig.ejemplo',
        type            => 'TSIG',
        algorithm       => 'algoritmo-personalizado',
        key             => '<texto de clave base64>',
        sig_function    => sub {
                                  my ($clave, $datos) = @_;
                                        ...
                                }
        );
$consulta->sign_tsig( $tsig );

La respuesta a una solicitud entrante se firma mediante el registro TSIG previamente especificado.

Net::DNS::Packet(3pm) — Arch Linux man pages

NAME

Net::DNS::Packet - DNS packet object

SYNOPSIS

    use Net::DNS;
    
    # Create a query packet
    my $query = Net::DNS::Packet::new( 'example.com', 'A', 'IN' );
    
    # Send query and receive reply
    my $reply = $socket->send($query);
    
    # Create a query packet with specific options
    my $query = Net::DNS::Packet->new(
        qw( example.com A IN ),
        {
            id => 1234,
            qr => 0, # Query
            aa => 0, # Not authoritative
            tc => 0, # Not truncated
            rd => 1, # Recursion desired
            ra => 0, # Recursion available
            ad => 0, # Authenticated data
            cd => 0, # Checking disabled
            rcode => 0 # No error
        }
    );
    
    # Add additional records
    $query->push( answer => rr_add('mail.example.com. MX 10 mail.example.com.') );
    
    # Send query
    my $reply = $server->send($query);
    
    # Check reply status
    if ( $reply->header->rcode == NOERROR ) {
        for my $rr ($reply->answer) {
            print $rr->string, "\n";
        }
    }
    
    # Packet creation with various RRs
    my $packet = Net::DNS::Packet->new('test.example.com');
    $packet->push(question => Net::DNS::Question->new('test.example.com', 'A'));
    $packet->push(answer => Net::DNS::RR::A->new('test.example.com', 3600, '1.2.3.4'));
    $packet->push(authority => Net::DNS::RR::NS->new('example.com', 3600, 'ns1.example.com'));
    $packet->push(additional => Net::DNS::RR::AAAA->new('test.example.com', 3600, '::1'));
    
    # TSIG signing
    $packet->sign_tsig( $key_file );
    
    # SIG(0) signing
    $packet->sign_sig0( $key_file );
    
    # Verification
    if ( $reply->verify($query) ) {
        # signature is valid
    } else {
        # signature is invalid
        warn $reply->verifyerr;
    }
    
    # Truncation
    my $truncated_packet = $packet->truncate(512);

DESCRIPTION

The Net::DNS::Packet class is the fundamental object used to represent a DNS packet. This class handles the creation, parsing, and manipulation of DNS packets according to RFC1035 and related standards.

A packet object contains a header, zero or more questions, zero or more answer resource records (RRs), zero or more authority RRs, and zero or more additional RRs.

Methods are provided to create packet objects from scratch, parse them from wire format, and to access and modify their various components.

Packet objects also provide methods for cryptographic signing and verification, including support for TSIG and SIG(0) as described in RFC2845 and RFC2931 respectively.

METHODS

new

    $packet = Net::DNS::Packet->new( $name, $type, $class, \%options );
    $packet = Net::DNS::Packet->new( \$data, \%options );
    $packet = Net::DNS::Packet->new( $query, \%options );

Creates a new packet object. The arguments determine the type of packet created:

  • $name, $type, $class: Creates a new query packet with the specified name, type, and class. If $class is omitted, 'IN' is assumed. If $type is omitted, 'A' is assumed. If $name is omitted, an empty string is assumed.

  • \$data: Parses a DNS packet from the scalar reference containing the raw packet data.

  • $query: Creates a reply packet based on the provided query packet. The header ID, flags, and question section are copied from the query.

Additional options can be provided in the \%options hash. These include:

id
Sets the packet identifier.
qr
Sets the Query/Response flag (0 for query, 1 for response).
aa
Sets the Authoritative Answer flag.
tc
Sets the TrunCation flag.
rd
Sets the Recursion Desired flag.
ra
Sets the Recursion Available flag.
ad
Sets the Authenticated Data flag.
cd
Sets the Checking Disabled flag.
rcode
Sets the Response Code.

The default values for the flags correspond to a standard DNS query.

push

$packet->push( section => $rr, ... );

Adds one or more resource records ($rr) to the specified section of the packet. The section can be one of question, answer, authority, or additional.

Example:

$packet->push( answer => rr_add('mail.example.com. MX 10 mail.example.com.') );
$packet->push( authority => Net::DNS::RR::SOA->new(...) );

header

$packet->header;

Returns the Net::DNS::Header object associated with the packet.

question

$packet->question;

Returns an array reference containing the questions in the packet. There should typically be at most one question.

answer

$packet->answer;

Returns an array reference containing the answer RRs in the packet.

authority

$packet->authority;

Returns an array reference containing the authority RRs in the packet.

additional

$packet->additional;

Returns an array reference containing the additional RRs in the packet.

tsigrr

$packet->tsigrr;

Returns the TSIG RR from the additional records section, or undefined if no TSIG RR is present.

sign_tsig

$response = $request->sign_tsig( $key, @options );

Signs the packet using the specified TSIG key. The key can be either a filename containing the key, or a Net::DNS::RR::TSIG object.

If the packet is a query, it is transformed into a response, signed, and returned. If the packet is already a response, it is signed in place and returned.

The @options argument can be used to specify TSIG options such as `fudge` and `algo`.

$response = $request->reply;
$response->sign_tsig( $request, @options );

Multi-packet transactions are signed by chaining the sign_tsig() calls together as follows:

$opaque = $packet1->sign_tsig( 'Kexample.+165+13281.private' );
$opaque = $packet2->sign_tsig( $opaque );
$opaque = $packet3->sign_tsig( $opaque );

The opaque intermediate object references returned during multi-packet signing are not intended to be accessed by the end-user application. Any such access is expressly forbidden.

Note that a TSIG record is added to every packet; this implementation does not support the suppressed signature scheme described in RFC2845.

verify and verifyerr

$reply->verify($query) || die $reply->verifyerr;

Verify TSIG signature of a reply to the corresponding query.

$opaque  = $packet1->verify( $query ) || die $packet1->verifyerr;
$opaque  = $packet2->verify( $opaque );
$verifed = $packet3->verify( $opaque ) || die $packet3->verifyerr;

Verify TSIG signature of a multi-packet reply to the corresponding query.

The opaque intermediate object references returned by verify() at each stage will be undefined (Boolean false) if verification fails. Testing at every stage is not necessary, which produces a BADSIG error on the final packet in the absence of more specific information. Access to the objects themselves, if they exist, is expressly forbidden.

sign_sig0

SIG0 support is provided through the Net::DNS::RR::SIG class. The requisite cryptographic components are not integrated into Net::DNS but reside in the Net::DNS::SEC distribution available from CPAN.

$update = Net::DNS::Update->new('example.com');
$update->push( update => rr_add('foo.example.com A 10.1.2.3'));
$update->sign_sig0('Kexample.com+003+25317.private');

Execution will be terminated if Net::DNS::SEC is not available.

verify SIG0

$packet->verify( $keyrr )               || die $packet->verifyerr;
$packet->verify( [$keyrr, ...] )        || die $packet->verifyerr;

Verify SIG0 packet signature against one or more specified KEY RRs.

sigrr

$sigrr = $packet->sigrr() || die 'unsigned packet';

The sigrr method returns the signature RR from a signed packet or undefined if the signature is absent.

truncate

The truncate method takes a maximum length as argument and then tries to truncate the packet and set the TC bit according to the rules of RFC2181 Section 9.

The smallest length limit that is honoured is 512 octets.
