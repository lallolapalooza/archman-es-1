NDBM_File(3perl) Guía de Referencia del Programador de Perl NDBM_File(3perl)

NOMBRE

NDBM_File - Acceso enlazado a archivos ndbm

SINOPSIS

use Fcntl;   # Para O_RDWR, O_CREAT, etc.
use NDBM_File;
tie(%h, 'NDBM_File', 'nombre_archivo', O_RDWR|O_CREAT, 0666)
  or die "No se pudo enlazar el archivo NDBM 'nombre_archivo': $!, abortando";
# Ahora lee y modifica el hash
$h{nuevaclave} = nuevovalor;
print $h{clavevieja};
...
untie %h;

DESCRIPCIÓN

"NDBM_File" establece una conexión entre una variable hash de Perl y un archivo en formato NDBM_File;. Puedes manipular los datos del archivo como si estuvieran en un hash de Perl, pero cuando tu programa finalice, los datos permanecerán en el archivo, para ser utilizados la próxima vez que se ejecute tu programa.

Utiliza "NDBM_File" con la función incorporada de Perl "tie" para establecer la conexión entre la variable y el archivo. Los argumentos para "tie" deben ser:

1.
La variable hash que deseas enlazar.
2.
La cadena "NDBM_File". (Esto le dice a Perl que utilice el paquete "NDBM_File" para realizar las funciones del hash.)
3.
El nombre del archivo al que quieres enlazar el hash.
4.
Flags. Usa uno de los siguientes:
"O_RDONLY"
Acceso de solo lectura a los datos del archivo.
"O_WRONLY"
Acceso de solo escritura a los datos del archivo.
"O_RDWR"
Acceso de lectura y escritura.

Si deseas crear el archivo si no existe, añade "O_CREAT" a cualquiera de estas opciones, como en el ejemplo. Si omites "O_CREAT" y el archivo no existe, la llamada a "tie" fallará.

5.
Los permisos predeterminados a usar si se crea un archivo nuevo. Los permisos reales se modificarán según la umask del usuario, por lo que probablemente deberías usar 0666 aquí. (Ver "umask" en perlfunc.)

DIAGNÓSTICOS

En caso de fallo, la llamada a "tie" devuelve un valor indefinido y probablemente establece $! para contener la razón por la que el archivo no pudo ser enlazado.

"ndbm store devolvió -1, errno 22, clave "..." en ..."

Esta advertencia se emite cuando intentas almacenar una clave o un valor demasiado largo. Significa que el cambio no se registró en la base de datos. Ver BUGS AND WARNINGS abajo.

SEGURIDAD Y PORTABILIDAD

No aceptes archivos NDBM de fuentes no confiables.

En los sistemas Linux modernos, estos suelen ser archivos GDBM, que no son portátiles entre plataformas.

La documentación de GDBM no implica que los archivos de fuentes no confiables puedan usarse de forma segura con "libgdbm".

Los sistemas que no usan compatibilidad GDBM para soporte ndbm utilizarán una biblioteca específica de la plataforma, posiblemente heredada de sistemas BSD, donde puede ser seguro o no usar un archivo no confiable.

Un archivo maliciosamente creado podría hacer que perl se bloquee o incluso exponer una vulnerabilidad de seguridad.

BUGS Y ADVERTENCIAS

Existen varios límites en el tamaño de los datos que puedes almacenar en el archivo NDBM. El más importante es que la longitud de una clave, más la longitud de su valor asociado, no puede exceder los 1008 bytes.

Ver "tie" en perlfunc, perldbmfilter, Fcntl
