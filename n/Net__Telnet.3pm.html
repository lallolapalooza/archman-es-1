NOMBRE

Net::Telnet - interactuar con el puerto TELNET u otros puertos TCP

SINOPSIS

"use Net::Telnet ();"

ver secciones MÉTODOS o EJEMPLOS abajo

DESCRIPCIÓN

Net::Telnet te permite establecer conexiones cliente a un puerto TCP y realizar E/S de red, especialmente a un puerto que usa el protocolo TELNET. Se proporcionan métodos de E/S simples como print, get y getline. Se proporcionan funciones interactivas más sofisticadas porque conectarse a un puerto TELNET implica en última instancia la comunicación con un programa diseñado para la interacción humana. Estas funciones interactivas incluyen la capacidad de especificar un tiempo de espera y esperar a que aparezcan patrones en el flujo de entrada, como el prompt de una shell. El soporte IPv6 está disponible al usar perl 5.14 o posterior, ver family().

Otras razones para usar este módulo que no sean estrictamente con un puerto TELNET son:

  • No estás familiarizado con los sockets y quieres una forma sencilla de establecer conexiones cliente a servicios TCP.
  • Quieres poder especificar tu propio tiempo de espera al conectar, leer o escribir.
  • Te estás comunicando con un programa interactivo al otro lado de un socket o pipe y quieres esperar a que aparezcan ciertos patrones.

Aquí tienes un ejemplo que imprime quién está conectado a un host remoto. Además de un nombre de usuario y contraseña, también debes conocer el prompt de shell del usuario, que para este ejemplo es "bash$ "

use Net::Telnet ();
$t = new Net::Telnet (Timeout => 10,
                      Prompt => '/bash\$ $/');
$t->open($host);
$t->login($username, $passwd);
@lines = $t->cmd("who");
print @lines;

Consulta la sección EJEMPLOS para ver más ejemplos.

Las preguntas de uso deben dirigirse al grupo de discusión perlmonks.org. Los errores se pueden ver o reportar en cpan.org en la página de Net::Telnet.

Qué saber antes de usar

  • Toda la salida se vacía mientras toda la entrada se almacena en búfer. Cada objeto contiene su propio búfer de entrada.
  • El separador de registros de salida para print() y cmd() se establece en "\n" por defecto, para que no tengas que añadir un salto de línea a todos tus comandos. Para evitar imprimir un salto de línea final "\n", usa put() o establece el output_record_separator a "".
  • Los métodos login() y cmd() utilizan la configuración de prompt en el objeto para determinar cuándo se ha completado un inicio de sesión o un comando remoto. Esos métodos fallarán con un tiempo de espera si no estableces el prompt correctamente.
  • Usa una combinación de print() y waitfor() como alternativa a login() o cmd() cuando no hagan lo que quieres.
  • Los errores como los tiempos de espera se manejan de acuerdo con la acción del modo de error. La acción predeterminada es imprimir un mensaje de error en la salida estándar y que el programa muera. Consulta el método errmode() para obtener más información.
  • Al construir el argumento del operador de coincidencia para prompt() o waitfor(), siempre usa comillas simples en lugar de comillas dobles para evitar la interpretación inesperada de barras invertidas (por ejemplo, '/bash\$ $/'). Si estás construyendo una ruta de archivo tipo DOS, necesitarás usar cuatro barras invertidas para representar una (por ejemplo, '/c:\\\\users\\\\bill>$/i').

    Por supuesto, no olvides los metacaracteres de expresiones regulares como ".", "[" o "$". Solo necesitarás una barra invertida para escaparlos. Los metacaracteres de anclaje "^" y "$" se refieren a posiciones en el búfer de entrada. Para evitar que coincida con caracteres leídos que parecen un prompt, es una buena idea terminar tu patrón de prompt con el anclaje "$". De esa manera, el prompt solo coincidirá si es lo último leído.

  • En el flujo de entrada, cada secuencia de retorno de carro y avance de línea (es decir, "\015\012" o CR LF) se convierte en "\n". En el flujo de salida, cada ocurrencia de "\n" se convierte en una secuencia de CR LF. Consulta binmode() para cambiar el comportamiento. Los protocolos TCP típicamente usan la secuencia ASCII, retorno de carro y avance de línea para designar un salto de línea.
  • El tiempo de espera al establecer una conexión está deshabilitado para máquinas que no admiten la función alarm(). Notablemente, estas incluyen las máquinas MS-Windows.
  • Necesitarás estar ejecutando al menos la versión 5.002 de Perl para usar este módulo. Este módulo no requiere ninguna biblioteca que no venga ya con una distribución estándar de Perl.

    Si tienes instaladas las bibliotecas IO:: (vienen estándar con perl5.004 y posteriores), entonces IO::Socket::INET se usa como clase base, de lo contrario se usa FileHandle.

Depuración

El error de uso típico causa un error de tiempo de espera porque has hecho suposiciones incorrectas sobre lo que el lado remoto realmente envía. La forma más fácil de conciliar lo que envía el lado remoto con tus expectativas es usar input_log() o dump_log().

dump_log() te permite ver los datos que se envían desde el lado remoto antes de que se realice cualquier traducción, mientras que input_log() te muestra los resultados después de la traducción. La traducción incluye la conversión de caracteres de fin de línea, la eliminación y respuesta a comandos del protocolo TELNET en el flujo de datos.

Estilo de Parámetros Nombrados

Se admiten dos estilos diferentes de parámetros nombrados. Este documento solo muestra el estilo IO:::

Net::Telnet->new(Timeout => 20);

sin embargo, el estilo de opción guión también está permitido:

Net::Telnet->new(-timeout => 20);

Conectando a una Máquina Remota MS-Windows

Por defecto, MS-Windows no viene con un servidor TELNET. Sin embargo, hay servidores TELNET de terceros disponibles. Desafortunadamente, muchos de estos servidores afirman falsamente ser un servidor TELNET. Esto es especialmente cierto para el llamado "Servidor Telnet de Microsoft" que viene instalado con algunas versiones más nuevas de MS-Windows.

Cuando un servidor TELNET acepta una conexión por primera vez, debe usar los caracteres de control ASCII retorno de carro y avance de línea para iniciar una nueva línea (ver RFC854). Un servidor como el "Servidor Telnet de Microsoft" que no hace esto, no es un servidor TELNET. Estos servidores envían secuencias de escape de terminal ANSI para posicionarse en una columna en una línea posterior e incluso para posicionarse mientras escriben caracteres adyacentes. Peor aún, al enviar salida, estos servidores reenvían la salida del comando enviada previamente en un intento equivocado de mostrar una pantalla de terminal completa.

Conectar Net::Telnet a uno de estos servidores TELNET falsos hace que tu trabajo de analizar la salida de comandos sea muy difícil. Es mejor reemplazar un servidor TELNET falso con un servidor TELNET real. Los mejores servidores TELNET para MS-Windows te permiten evitar los escapes ANSI desactivando algo que algunos de ellos llaman modo consola.

binmode - alternar traducción de saltos de línea
$mode = $obj->binmode;
$prev = $obj->binmode($mode);

Este método controla si las secuencias de retorno de carro y salto de línea (CR LF o, más específicamente, "\015\012") se traducen o no. Por defecto, se traducen (es decir, binmode es 0).

Si no se proporciona ningún argumento, se devuelve el modo actual.

Si $mode es 1, binmode está activado y no se realiza la traducción de saltos de línea.

Si $mode es 0, binmode está desactivado y se realiza la traducción de saltos de línea. En el flujo de entrada, cada secuencia CR LF se convierte en "\n" y en el flujo de salida, cada ocurrencia de "\n" se convierte en una secuencia CR LF.

Tenga en cuenta que la entrada siempre se almacena en búfer. Cambiar binmode no afecta a lo que ya se ha leído en el búfer. La salida no se almacena en búfer y el cambio de binmode tendrá un efecto inmediato.

break - enviar carácter de interrupción TELNET
$ok = $obj->break;

Este método envía el carácter de interrupción TELNET. Este carácter se proporciona porque es una señal fuera del conjunto de caracteres ASCII que actualmente tiene un significado local dentro de muchos sistemas. Está destinado a indicar que se ha pulsado la tecla Break o la tecla Attention.

Este método devuelve 1 si tiene éxito, o realiza la acción del modo de error si falla.

buffer - referencia escalar al búfer de entrada del objeto
$ref = $obj->buffer;

Este método devuelve una referencia escalar al búfer de entrada para $obj. Los datos en el búfer de entrada son datos que se han leído del lado remoto pero que aún no han sido leídos por el usuario. Las modificaciones en el búfer de entrada se devuelven en una lectura posterior.

buffer_empty - descarta todos los datos en el búfer de entrada del objeto
$obj->buffer_empty;

Este método elimina todos los datos del búfer de entrada para $obj.

close - cerrar objeto
$ok = $obj->close;

Este método cierra el socket, archivo o tubería asociado con el objeto. Siempre devuelve un valor de 1.

cmd - emitir comando y recuperar salida
$ok = $obj->cmd($string);
$ok = $obj->cmd(String   => $string,
                [Output  => $ref,]
                [Cmd_remove_mode => $mode,]
                [Errmode => $mode,]
                [Input_record_separator => $chars,]
                [Ors     => $chars,]
                [Output_record_separator => $chars,]
                [Prompt  => $match,]
                [Rs      => $chars,]
                [Timeout => $secs,]);
@output = $obj->cmd($string);
@output = $obj->cmd(String   => $string,
                    [Output  => $ref,]
                    [Cmd_remove_mode => $mode,]
                    [Errmode => $mode,]
                    [Input_record_separator => $chars,]
                    [Ors     => $chars,]
                    [Output_record_separator => $chars,]
                    [Prompt  => $match,]
                    [Rs      => $chars,]
                    [Timeout => $secs,]);

Este método envía el comando $string y lee los caracteres enviados de vuelta por el comando hasta e incluyendo el prompt coincidente. Se asume que el programa al que se está enviando es algún tipo de intérprete de prompts de comandos, como un shell.

Al comando $string se le añade automáticamente el separador de registros de salida, que por defecto es "\n". Esto es similar a que alguien escriba un comando y pulse la tecla Intro. Establezca el output_record_separator para cambiar este comportamiento.

En un contexto escalar, los caracteres leídos del lado remoto se descartan y se devuelve 1 si tiene éxito. En caso de tiempo de espera, fin de archivo u otros fallos, se realiza la acción del modo de error. Consulte errmode().

En un contexto de lista, solo se devuelve la salida generada por el comando, una línea por elemento. En otras palabras, se devuelven todos los caracteres entre la cadena de comando repetida y el prompt. Si el comando no genera ninguna salida, se devuelve una lista que contiene un elemento, la cadena vacía. Esto es para que la lista indique verdadero en un contexto booleano. En caso de tiempo de espera, fin de archivo u otros fallos, se realiza la acción del modo de error. Consulte errmode().

Los caracteres que coincidieron con el prompt pueden recuperarse utilizando last_prompt().

Muchos intérpretes de comandos repiten el comando enviado. En la mayoría de las situaciones, este método elimina la primera línea devuelta desde el lado remoto (es decir, el comando repetido). Consulte cmd_remove_mode() para un mayor control sobre esta característica.

Utilice dump_log() para depurar cuando este método sigue dando tiempos de espera y usted no cree que deba hacerlo.

Considere el uso de una combinación de print() y waitfor() como alternativa a este método cuando no haga lo que desea, por ejemplo, si el comando que envía solicita entrada.

El parámetro con nombre Output proporciona un método alternativo para recibir la salida del comando. Si pasa una referencia escalar, toda la salida (incluso si contiene varias líneas) se devuelve en el escalar referenciado. Si pasa una referencia a un array o hash, las líneas de salida se devuelven en el array o hash referenciado. Puede utilizar input_record_separator() para cambiar la noción de lo que separa una línea.

Se proporcionan parámetros con nombre opcionales para anular la configuración actual de cmd_remove_mode, errmode, input_record_separator, ors, output_record_separator, prompt, rs y timeout. Rs es sinónimo de input_record_separator y ors es sinónimo de output_record_separator.

cmd_remove_mode - alternar la eliminación de comandos repetidos
$mode = $obj->cmd_remove_mode;
$prev = $obj->cmd_remove_mode($mode);

Este método controla cómo tratar los comandos repetidos en la salida devuelta por cmd(). Normalmente, cuando envía un comando al lado remoto, la primera línea de salida devuelta es el comando repetido. Utilice este modo para eliminar la primera línea de salida devuelta normalmente por cmd().

Si no se proporciona ningún argumento, se devuelve el modo actual.

Si $mode es 0, entonces las líneas de salida del comando devueltas por cmd() no se eliminan. Si $mode es un entero positivo, entonces las primeras $mode líneas de la salida del comando se eliminan.

auto_accept - accept or reject echo offer
$obj->auto_accept;
$obj->auto_accept($bool);

This method gets or sets the default behavior of the object regarding echo offers from the remote side. It defaults to true (accepts the offer).

When called without arguments, it returns the current setting.

When called with a boolean argument, it sets the object's behavior to accept (1 or true) or reject (0 or false) echo offers, and returns the previous setting.

It is important to note that this setting is for the default behavior. Individual calls to the following methods can override this setting:

cmd()
get()
getline()
getlines()
waitfor()
prompt()

By default, $mode is set to "auto". Auto means that whether or not the first line of command output is stripped, depends on whether or not the remote side offered to echo. By default, Net::Telnet always accepts an offer to echo by the remote side. You can change the default to reject such an offer using option_accept().

A warning is printed to STDERR when attempting to set this attribute to something that is not "auto" or a non-negative integer.

dump_log - log all I/O in dump format
$fh = $obj->dump_log;
$fh = $obj->dump_log($fh);
$fh = $obj->dump_log($tiefh);
$fh = $obj->dump_log($filename);

This method starts or stops dump format logging of all the object's input and output. The dump format shows the blocks read and written in a hexadecimal and printable character format. This method is useful when debugging, however you might want to first try input_log() as it's more readable.

If no argument is given, the log filehandle is returned. A returned empty string indicates logging is off.

To stop logging, use an empty string as an argument. The stopped filehandle is not closed.

If an open filehandle is given, it is used for logging and returned. Otherwise, the argument is assumed to be the name of a file, the filename is opened for logging and a filehandle to it is returned. If the filehandle is not already opened or the filename can't be opened for writing, the error mode action is performed. The filehandle can be a tied filehandle.

eof - end of file indicator
$eof = $obj->eof;

This method returns 1 if end of file has been read, otherwise it returns an empty string. Because the input is buffered this isn't the same thing as $obj has closed. In other words $obj can be closed but there still can be stuff in the buffer to be read. Under this condition you can still read but you won't be able to write.

errmode - define action to be performed on error
$mode = $obj->errmode;
$prev = $obj->errmode($mode);

This method gets or sets the action used when errors are encountered using the object. The first calling sequence returns the current error mode. The second calling sequence sets it to $mode and returns the previous mode. Valid values for $mode are "die" (the default), "return", a coderef, or an arrayref.

When mode is "die" and an error is encountered using the object, then an error message is printed to standard error and the program dies.

When mode is "return" then the method generating the error places an error message in the object and returns an undefined value in a scalar context and an empty list in list context. The error message may be obtained using errmsg().

When mode is a coderef, then when an error is encountered coderef is called with the error message as its first argument. Using this mode you may have your own subroutine handle errors. If coderef itself returns then the method generating the error returns undefined or an empty list depending on context.

When mode is an arrayref, the first element of the array must be a coderef. Any elements that follow are the arguments to coderef. When an error is encountered, the coderef is called with its arguments. Using this mode you may have your own subroutine handle errors. If the coderef itself returns then the method generating the error returns undefined or an empty list depending on context.

A warning is printed to STDERR when attempting to set this attribute to something that is not "die", "return", a coderef, or an arrayref whose first element isn't a coderef.

errmsg - most recent error message
$msg = $obj->errmsg;
$prev = $obj->errmsg(@msgs);

The first calling sequence returns the error message associated with the object. The empty string is returned if no error has been encountered yet. The second calling sequence sets the error message for the object to the concatenation of @msgs and returns the previous error message. Normally, error messages are set internally by a method when an error is encountered.

error - perform the error mode action
$obj->error(@msgs);

This method concatenates @msgs into a string and places it in the object as the error message. Also see errmsg(). It then performs the error mode action. Also see errmode().

If the error mode doesn't cause the program to die, then an undefined value or an empty list is returned depending on the context.

This method is primarily used by this class or a sub-class to perform the user requested action when an error is encountered.

family - IP address family for remote host
$family = $obj->family;
$prev   = $obj->family($family);

This method designates which IP address family host() refers to, i.e. IPv4 or IPv6. IPv6 support is available when using perl 5.14 or later. With no argument it returns the current value set in the object. With an argument it sets the current address family to $family and returns the previous address family. Valid values are "ipv4", "ipv6", or "any". When "any", the host() can be a hostname or IP address for either IPv4 or IPv6. After connecting, you can use sockfamily() to determine which IP address family was used.

The default value is "ipv4".

The error mode action is performed when attempting to set this attribute to something that isn't "ipv4", "ipv6", or "any". It is also performed when attempting to set it to "ipv6" when the Socket module is less than version 1.94 or IPv6 is not supported in the OS as indicated by Socket::AF_INET6 not being defined.

fhopen - use already open filehandle for I/O
$ok = $obj->fhopen($fh);

This method associates the open filehandle $fh with $obj for further I/O. Filehandle $fh must already be opened.

Suppose you want to use the features of this module to do I/O to something other than a TCP port, for example STDIN or a filehandle opened to read from a process. Instead of opening the object for I/O to a TCP port by using open() or new(), call this method instead.

The value 1 is returned success, the error mode action is performed on failure.

get - read block of data
$data = $obj->get([Binmode    => $mode,]
                  [Errmode    => $errmode,]
                  [Telnetmode => $mode,]
                  [Timeout    => $secs,]);

This method reads a block of data from the object and returns it along with any buffered data. If no buffered data is available to return, it will wait for data to read using the timeout specified in the object. You can override that timeout using $secs. Also see timeout(). If buffered data is available to return, it also checks for a block of data that can be immediately read.

On eof an undefined value is returned. On time-out or other failures, the error mode action is performed. To distinguish between eof or an error occurring when the error mode is not set to "die", use eof().

Optional named parameters are provided to override the current settings of binmode, errmode, telnetmode, and timeout.

getline - read next line
$line = $obj->getline([Binmode    => $mode,]
                      [Errmode    => $errmode,]
                      [Input_record_separator => $chars,]
                      [Rs         => $chars,]
                      [Telnetmode => $mode,]
                      [Timeout    => $secs,]);

This method reads and returns the next line of data from the object. You can use input_record_separator() to change the notion of what separates a line. The default is "\n". If a line isn't immediately available, this method blocks waiting for a line or a time-out.

On eof an undefined value is returned. On time-out or other failures, the error mode action is performed. To distinguish between eof or an error occurring when the error mode is not set to "die", use eof().

Optional named parameters are provided to override the current settings of binmode, errmode, input_record_separator, rs, telnetmode, and timeout. Rs is synonymous with input_record_separator.

getlines - read all lines
@lines = $obj->getlines([Binmode    => $mode,]
                       [Errmode    => $errmode,]
                       [Telnetmode => $mode,]
                       [Timeout    => $secs,]);

This method reads all lines from the object until eof is encountered, and returns them as a list. If no lines are available, it will wait for data to read using the timeout specified in the object. You can override that timeout using $secs. Also see timeout().

On eof an empty list is returned. On time-out or other failures, the error mode action is performed. To distinguish between eof or an error occurring when the error mode is not set to "die", use eof().

Optional named parameters are provided to override the current settings of binmode, errmode, telnetmode, and timeout.

El delimitador de registro de salida por defecto es "\n", así que no se necesita añadir un newline a todas tus comandos. Para evitar imprimir el delimitador de registro, usa put() o establece el delimitador de registro en una cadena vacía.

Sin argumento, este método devuelve el delimitador de registro actual definido en el objeto. Con un argumento, establece el delimitador de registro en $chars y devuelve el valor anterior.

peerhost - dirección IP del otro lado de la conexión de socket
$ipaddr = $obj->peerhost;

Este método devuelve una cadena que es la dirección IPv4 o IPv6 del socket remoto (es decir, es la dirección IP del host()). Devuelve "" cuando no está conectado.

peerport - puerto TCP del otro lado de la conexión de socket
$port = $obj->peerport;

Este método devuelve el número de puerto que el socket remoto está asociado. Es el mismo que el número del puerto port() cuando está conectado. Devuelve "" cuando no está conectado.

port - puerto remoto
$port = $obj->port;
$prev = $obj->port($port);

Este método designa el puerto TCP remoto para open(). Sin argumento, devuelve el número actual del puerto. Con un argumento, establece el número actual del puerto en $port y devuelve el número anterior. Si $port es un nombre de servicio TCP, se convierte primero a número de puerto usando la función perl getservbyname().

El valor por defecto es 23.

Se ejecuta la acción de modo de error cuando intentas establecer este atributo con algo que no sea un número positivo o un nombre válido de servicio TCP.

print - escribir en el objeto
$ok = $obj->print(@list);

Este método escribe @list seguido de output_record_separator al objeto abierto y devuelve 1 si todos los datos fueron correctamente escritos. En caso de timeout o fallo, se ejecuta la acción de modo de error. Ver errmode().

Por defecto, el output_record_separator() está establecido en "\n", por lo que todos tus comandos se muestran con un newline al final. En la mayoría de los casos, tu salida está siendo leída por unintérprete de comandos que no acepta un comando hasta que se lea una newline. Esto es similar a presionar la tecla de retorno después de teclear un comando. Para evitar imprimir un trailing "\n" usa put() o establece el output_record_separator en una cadena vacía.

En caso de fallo, es posible que algún dato haya sido escrito. Si deseas recuperar de un timeout de print, usa print_length() para determinar cuánto se escribió antes del fallo.

También puedes usar el separador de campo para imprimir un string entre los elementos de la lista. Ver output_field_separator().

print_length - número de bytes escritos por print
$num = $obj->print_length;

Este devuelve el número de bytes correctamente escritos por la más reciente print() o put().

prompt - patrón para encontrar un aviso
$matchop = $obj->prompt;
$prev = $obj->prompt($matchop);

Este método establece el patrón usado para encontrar un aviso en el flujo de entrada. Debe ser una cadena representando un operador de coincidencia válida en Perl. Los métodos login() y cmd() intentan leer hasta que coincida con el patrón que hayas elegido. Si el patrón que hayas elegido no coincide con lo que envía el lado remoto, fallarán con un error de timeout.

Sin argumento, devuelve el patrón establecido en el objeto. Con un argumento, establece el patrón en $matchop y devuelve el valor anterior.

El patrón por defecto es '/[\$%#>] $/'

Usa siempre comillas simples, no comillas dobles, para construir $matchop (ejemplo: '/bash\$ $/'). Si construyes un camino de archivo similar a DOS, necesitarás cuatro backslashes para representar uno (ejemplo: '/c:\\\\users\\\\bill>$/i').

De hecho, no olvides sobre los caracteres metáfóricos de regex como ".", "[", o "$". Solo necesitarás un solo backslash para escapar them. Las metáforas de carácter de inicio y fin "^" y "$" refieren a posiciones en el buffer de entrada.

Se ejecuta la acción de modo de error cuando intentas establecer este atributo con un operador de coincidencia que faltó su delimitador inicial.

put - escribir en el objeto
$ok = $obj->put($string);
$ok = $obj->put(String      => $string,
                [Binmode    => $mode,]
                [Errmode    => $errmode,]
                [Telnetmode => $mode,]
                [Timeout    => $secs,]);

Este método escribe $string al objeto abierto y devuelve 1 si todos los datos fueron correctamente escritos. Este método es similar a print() excepto que no escribe el delimitador de salida "\n" por defecto. En caso de timeout o fallo, se ejecuta la acción de modo de error. Ver errmode().

En caso de fallo, es posible que algún dato haya sido escrito. Si deseas recuperar de un timeout de put, usa print_length() para determinar cuánto se escribió antes del fallo.

Se proporcionan parámetros nombrados opcionales para sobreescalar las configuraciones actuales de binmode, errmode, telnetmode y timeout.

rs - delimitador de línea de entrada
$chars = $obj->rs;
$prev = $obj->rs($chars);

Este método es equivalente a input_record_separator().

sockfamily - familia de direcciones IP del socket local conectado
$sockfamily = $obj->sockfamily;

Este método devuelve la familia de direcciones IP que open() utilizó para conectarse correctamente. Es más útil cuando la familia family() solicitada para open() era "any". Los valores devueltos pueden ser "ipv4", "ipv6", o "" (cuando no está conectado).

sockhost - Dirección IP de este extremo de la conexión de socket
$ipaddr = $obj->sockhost;

Este método devuelve una cadena que es la dirección IPv4 o IPv6 a la que está enlazado el socket local. Devuelve "" cuando no está conectado.

$port = $obj->sockport;

Este método devuelve el número de puerto al que está enlazado el socket local. Devuelve "" cuando no está conectado.

telnetmode - desactivar/activar interpretación de comandos telnet
$mode = $obj->telnetmode;
$prev = $obj->telnetmode($mode);

Este método controla si los comandos TELNET en el flujo de datos se reconocen y manejan o no. El protocolo TELNET utiliza ciertas secuencias de caracteres enviadas en el flujo de datos para controlar la sesión. Si el puerto al que te conectas no está utilizando el protocolo TELNET, entonces deberías desactivar este modo. El valor predeterminado es *activado*.

Si no se proporciona ningún argumento, se devuelve el modo actual.

Si $mode es 0, entonces el modo telnet está desactivado. Si * $mode es 1, entonces el modo telnet está activado.

timed_out - indicador de tiempo de espera
$boolean = $obj->timed_out;
$prev = $obj->timed_out($boolean);

Este método indica si una lectura, escritura o apertura previa del método se agotó. Recuerda que el agotamiento del tiempo de espera es en sí mismo un error. Para poder invocar timed_out() después de un error de tiempo de espera, tendrías que cambiar el modo de error predeterminado a algo diferente de "die". Ver errmode().

Sin argumento, este método devuelve 1 si el método anterior se agotó. Con un argumento, establece el indicador. Normalmente, solo los métodos internos establecen este indicador.

timeout - intervalo de tiempo de espera de E/S
$secs = $obj->timeout;
$prev = $obj->timeout($secs);

Este método establece el intervalo de tiempo de espera utilizado al realizar E/S o al conectarse a un puerto. Cuando un método no se completa dentro del intervalo de tiempo de espera, se produce un error y se realiza la acción del modo de error.

Un tiempo de espera puede expresarse como un valor relativo o absoluto. Si $secs es mayor o igual que el momento en que comenzó el programa, según lo determinado por $^T, entonces es un valor de tiempo absoluto para cuando ocurre el tiempo de espera. La función perl time() puede usarse para obtener un valor de tiempo absoluto. Para un valor de tiempo de espera relativo menor que $^T, el tiempo de espera ocurre * $secs desde que el método comienza.

Si $secs es 0, entonces el tiempo de espera ocurre si los datos no se pueden leer o escribir inmediatamente. Usa el valor indefinido para desactivar completamente el tiempo de espera.

Sin argumento, este método devuelve el tiempo de espera establecido en el objeto. Con un argumento, establece el tiempo de espera a $secs y devuelve el valor anterior. El valor de tiempo de espera predeterminado es 10 segundos.

Se imprime una advertencia en STDERR al intentar establecer este atributo a algo que no es "undef" o un entero no negativo.

waitfor - esperar un patrón en la entrada
$ok = $obj->waitfor($matchop);
$ok = $obj->waitfor([Match      => $matchop,]
                    [String     => $string,]
                    [Binmode    => $mode,]
                    [Errmode    => $errmode,]
                    [Telnetmode => $mode,]
                    [Timeout    => $secs,]);

($prematch, $match) = $obj->waitfor([Match      => $matchop,]
                                    [String     => $string,]
                                    [Binmode    => $mode,]
                                    [Errmode    => $errmode,]
                                    [Telnetmode => $mode,]
                                    [Timeout    => $secs,]);

Este método lee hasta que se encuentra una coincidencia de patrón o una cadena en el flujo de entrada. Todos los caracteres antes y después de la coincidencia se eliminan del flujo de entrada.

En un contexto de lista, los caracteres antes de la coincidencia y los caracteres coincidentes se devuelven en $prematch y * $match. En un contexto escalar, los caracteres coincidentes y todos los caracteres anteriores se descartan y se devuelve 1 en caso de éxito. En caso de tiempo de espera, fin de archivo (eof) u otros fallos, tanto en contexto de lista como escalar, se realiza la acción del modo de error. Ver errmode().

Puedes especificar más de un patrón o cadena simplemente proporcionando varios parámetros nombrados de *Match* y/o *String*. Un $matchop debe ser una cadena que represente un operador de coincidencia de patrones Perl válido. El * $string es solo una subcadena que se encontrará en el flujo de entrada.

Usa dump_log() para depurar cuando este método sigue agotándose y crees que no debería.

Para evitar la interpretación inesperada de barras invertidas, siempre usa comillas simples en lugar de comillas dobles para construir un argumento de operador de coincidencia para prompt() y waitfor() (por ejemplo, '/bash\$ $/'). Si estás construyendo una ruta de archivo tipo DOS, necesitarás usar cuatro barras invertidas para representar una (por ejemplo, '/c:\\\\users\\\\bill>$/i').

Por supuesto, no te olvides de los metacaracteres de expresiones regulares como ".", "[", o "$". Solo necesitarás una barra invertida para citarlos. Los metacaracteres de anclaje "^" y "$" se refieren a posiciones en el búfer de entrada.

Se proporcionan parámetros nombrados opcionales para anular la configuración actual de binmode, errmode, telnetmode y timeout.

Establecer prompt() para que coincida con el prompt del shell de un usuario puede ser complicado. Este ejemplo inicia sesión sin conocer el prompt del shell y luego lo establece para que coincida con prompt(). Requiere /usr/bin/env y /bin/sh en el host remoto.

my $host = 'your_destination_host_here';
my $user = 'your_username_here';
my $passwd = 'your_password_here';
my ($t, @output);
## Crear un objeto Net::Telnet.
use Net::Telnet ();
$t = new Net::Telnet (Timeout  => 10);
## Conectarse e iniciar sesión.
$t->open($host);
$t->waitfor('/login: ?$/i');
$t->print($user);
$t->waitfor('/password: ?$/i');
$t->print($passwd);
## Cambiar a un shell conocido, usando un prompt conocido.
$t->prompt('/<xPROMPTx> $/');
$t->errmode("return");
$t->cmd("exec /usr/bin/env 'PS1=<xPROMPTx> ' /bin/sh -i")

$t->errmode("die");
## Ahora puedes hacer cmd() todo lo que quieras.
@output = $t->cmd("uname -a");

NAME

Net::Telnet - Perl extension for the Telnet protocol

SYNOPSIS

  use Net::Telnet;

  # Create a new object
  my $telnet = new Net::Telnet (
        -Host       => "some.host.name",
        -Port       => 23,
        -Timeout    => 10,
        -Telnetmode => 1,
        -Prompt     => '/#\s?$/',
  );

  # Login
  my ($login, $passwd) = $telnet->login("someuser", "somepassword");
  print "Login status: $login $passwd\n";

  # Execute commands
  my @lines = $telnet->cmd("ls -l");
  print @lines;

  # Log off
  $telnet->close;

DESCRIPTION

This module provides a Perl interface to the Telnet protocol. It allows you to write Perl programs that can connect to remote Telnet servers, log in, and execute commands. The module handles the Telnet protocol negotiations automatically, so you don't have to worry about the details.

The module can also be used to interact with local programs by using the spawn subroutine, which starts a program and associates a filehandle with its standard input/output. This is useful for automating tasks that involve interactive command-line programs.

Creates a new Net::Telnet object. The following options can be passed as a hash:
-Host
The hostname or IP address of the Telnet server to connect to.
-Port
The port number to connect to. Defaults to 23 (the standard Telnet port).
-Timeout
The number of seconds to wait for a response from the server before giving up. Defaults to 10 seconds.

The following example demonstrates how to use Net::Telnet to connect to a remote host, log in, and execute a command.

## Main program.
{
    my $host = "some.host.name";
    my $user = "someuser";
    my $passwd = "somepassword";
    my $prompt = '/#\s?$/';
    my ($buf, $match, $lines);

    use Net::Telnet;
    my $telnet = new Net::Telnet (
        -Host    => $host,
        -Port    => 23,
        -Timeout => 10,
        -Telnetmode => 1,
        -Prompt  => $prompt
    ) or die "Could not create Telnet object\n";

    $telnet->errmode("return");

    ## Login.
    ($buf, $match) = $telnet->login($user, $passwd);
    if (!defined $buf && !defined $match) {
        die "Login failed: ", $telnet->lastline;
    }
    print "Login banner:\n$buf\n";
    print "Password prompt:\n$match\n";

    ## Execute a command.
    $lines = $telnet->cmd("ls -l");
    if (!defined $lines) {
        die "Command failed: ", $telnet->lastline;
    }
    print "Command output:\n@$lines\n";

    ## Log off.
    $telnet->close;
    exit;
} # end main program

You can also use Net::Telnet to interact with local programs. This example changes a user's login password. It introduces the spawn() subroutine to start a program and associate a filehandle with its standard I/O. Because the passwd program always prompts for passwords on its controlling terminal, the IO::Pty module is used to create a new pseudo terminal for use by passwd. The Net::Telnet object reads and writes to that pseudo terminal. To use the code below, substitute "changeme" with the actual old and new passwords.

## Main program. {
  

   my ($pty, $passwd);
  

   my $oldpw = "changeme";
  

   my $newpw = "changeme";


    ## Start passwd program.
    $pty = spawn("passwd");
    ## Create a Net::Telnet object to perform I/O on passwd's tty.
    use Net::Telnet;
    $passwd = new Net::Telnet (-fhopen => $pty,
                               -timeout => 2,
                               -output_record_separator => "\r",
                               -telnetmode => 0,
                               -cmd_remove_mode => 1);
    $passwd->errmode("return");
    ## Send existing password.
    $passwd->waitfor('/password: ?$/i')
        or die "no old password prompt: ", $passwd->lastline;
    $passwd->print($oldpw);
    ## Send new password.
    $passwd->waitfor('/new (\w+\s)?password: ?$/i')
        or die "bad old password: ", $passwd->lastline;
    $passwd->print($newpw);
    ## Send new password verification.
    $passwd->waitfor('/new (\w+\s)?password: ?$/i')
        or die "bad new password: ", $passwd->lastline;
    $passwd->print($newpw);
    ## Display success or failure.
    $passwd->waitfor('/(changed|updated)/')
        or die "bad new password: ", $passwd->lastline;
    print $passwd->lastline;
    $passwd->close;
    exit;
} # end main program


sub spawn {
  

   my (@cmd) = @_;
  

   my ($pid, $pty, $tty,
    $tty_fd);


    ## Create a new pseudo terminal.
    use IO::Pty ();
    $pty = new IO::Pty
        or die $!;
    ## Execute the program in another process.
    unless ($pid = fork) {  # child process
        die "problem spawning program: $!\n" unless defined $pid;
        ## Disassociate process from its controlling terminal.
        use POSIX ();
        POSIX::setsid()
            or die "setsid failed: $!";
        ## Associate process with a new controlling terminal.
        $pty->make_slave_controlling_terminal;
        $tty = $pty->slave;
        $tty_fd = $tty->fileno;
        close $pty;
        ## Make standard I/O use the new controlling terminal.
        open STDIN, "<&$tty_fd" or die $!;
        open STDOUT, ">&$tty_fd" or die $!;
        open STDERR, ">&STDOUT" or die $!;
        close $tty;
        ## Execute requested program.
        exec @cmd
            or die "problem executing $cmd[0]\n";
    } # end child process
    $pty;
} # end sub spawn


Here is an example that uses the openssh program to connect to a
    remote host. It uses the spawn() subroutine, from
    the password changing example above, to start the ssh program and then read
    and write to it via a Net::Telnet object. This example turns off ssh host
    key checking, which reduces your ability to know when someone on the network
    is impersonating the remote host. To use the code below, substitute
    "changeme" with the actual host, user, password, and command
    prompt.


## Main program.
{
    my $host = "changeme";
    my $user = "changeme";
    my $passwd = "changeme";
    my $prompt = '/changeme\$ $/';
    my ($buf, $match, $pty, $ssh, @lines);
    ## Start ssh program.
    $pty = spawn("ssh",
                 "-l", $user,
                 "-e", "none",
                 "-F", "/dev/null",
                 "-o", "PreferredAuthentications=password",
                 "-o", "NumberOfPasswordPrompts=1",
                 "-o", "StrictHostKeyChecking=no",
                 "-o", "UserKnownHostsFile=/dev/null",
                 $host);
    ## Create a Net::Telnet object to perform I/O on ssh's tty.
    use Net::Telnet;
    $ssh = new Net::Telnet (-fhopen => $pty,
                            -prompt => $prompt,
                            -telnetmode => 0,
                            -output_record_separator => "\r",
                            -cmd_remove_mode => 1);
    ## Wait for the password prompt and send password.
    $ssh->waitfor(-match => '/password: ?$/i',
                  -errmode => "return")
        or die "problem connecting to \"$host\": ", $ssh->lastline;
    $ssh->print($passwd);
    ## Wait for the shell prompt.
    (undef, $match) = $ssh->waitfor(-match => $ssh->prompt,
                                    -match => '/^Permission denied/m',
                                    -errmode => "return")
        or return $ssh->error("login failed: expected shell prompt ",
                              "doesn't match actual\n");
    return $ssh->error("login failed: bad login-name or password\n")
        if $match =~ /^Permission denied/m;
    ## Run commands on remote host.
    print $ssh->cmd("hostname");
    print $ssh->cmd("uptime");
    $ssh->close;
    exit;
} # end main program

sub cmd_unixlong {
    my ($obj, $cmd) = @_;
    my ($line, $pos);
    my $max_tty_line = 254;
    ## Start a Bourne shell.
    $obj->cmd(-string => "/usr/bin/env " .
              "'PS1=<xPROMPTx> ' 'PS2=<xPROMPTx> ' /bin/sh -i",
              -prompt => '/<xPROMPTx> $/')
        or return;
    ## Break-up the one large command line and send as shorter lines.
    $pos = 0;
    while (1) {
        $line = substr $cmd, $pos, $max_tty_line;
        $pos += length $line;
        last unless $pos < length $cmd;
        ## Send the line with continuation char.
        $obj->cmd(-string => "$line\\",
                  -prompt => '/<xPROMPTx> $/')
            or return;
    }
    ## Send the last line and return the output.
    $obj->cmd("$line ; exit");
} # end sub cmd_unixlong
