Judy(3) Manual de funciones de biblioteca Judy(3)

NOMBRE

Matrices Judy - Funciones de biblioteca C para crear y acceder a matrices dinámicas

SINOPSIS

Judy1  - mapea un Índice (palabra) a un bit
JudyL  - mapea un Índice (palabra) a un Valor (palabra/puntero)
JudySL - mapea un Índice (cadena terminada en nulo) a un Valor
JudyHS - mapea un Índice (arreglo de bytes) de Longitud a un Valor

DESCRIPCIÓN

La familia de funciones Judy soporta matrices completamente dinámicas. Estas matrices pueden ser indexadas por una palabra de 32 o 64 bits (dependiendo del tamaño de palabra del procesador), una cadena terminada en nulo o un arreglo de bytes más longitud. Una matriz dinámica (poblada de forma dispersa) también puede considerarse una función de mapeo o memoria asociativa.

Un Word_t es un typedef unsigned long int en Judy.h y debe tener el mismo tamaño que sizeof(void *), es decir, un puntero.

Funciones Judy1: Índice es un Word_t y Valor es solo un bit o simplemente una bandera de que el Índice está presente o ausente en la matriz. Esto puede considerarse como un enorme mapa de bits.

Funciones JudyL: Índice es un Word_t y Valor es un Word_t. Esto hace que JudyL sea un mapeador puro de palabra a palabra/puntero. JudySL y JudyHL se basan en esta propiedad de JudyL.

Funciones JudySL: Índice es una cadena terminada en nulo y Valor es un Word_t.

Funciones JudyHS: Índice es un arreglo de bytes de longitud: Longitud. Valor es un Word_t. Esta nueva adición (mayo de 2004) a Judy es un híbrido que utiliza las mejores características de los métodos de hashing y Judy. El autor cree que JudyHS es un buen reemplazo para un método de hashing cuando el redimensionamiento de la tabla hash se realiza durante el crecimiento de la población. Un método hash correctamente ajustado con un tamaño de tabla hash *estático* y población es inmejorable en velocidad. Sin embargo, JudyHS funcionará mejor que un método hash con poblaciones más pequeñas y más grandes que el tamaño óptimo de la tabla hash. JudyHS no tiene un caso de rendimiento degenerado donde se pueda explotar el conocimiento del algoritmo hash. (Es decir, JudyHS no utiliza una lista enlazada para manejar colisiones hash, utiliza un árbol de arreglos JudyL y un tamaño de tabla hash virtual de 4 mil millones).

Las matrices Judy son eficientes tanto en velocidad como en memoria, sin necesidad de ajustes o configuración, en una amplia gama de tipos de conjuntos de índices (secuenciales, periódicos, agrupados, aleatorios). La velocidad y el uso de memoria de Judy suelen ser mejores que otros modelos de almacenamiento de datos como skiplists, listas enlazadas, árboles binarios, ternarios, b-trees, o incluso hashing, y mejora con conjuntos de datos muy grandes.

Una matriz Judy se crea simplemente definiendo un puntero nulo y luego almacenando (insertando) el primer elemento en la matriz bajo ese puntero. La memoria utilizada por una matriz Judy es casi proporcional a la población (número de elementos).

Judy tiene dos Interfaces de Programación de Aplicaciones (APIs): una interfaz de macros de C y una interfaz de llamadas a funciones. Debido a que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de usar las funciones de Judy.

Dado que una matriz Judy inicial (vacía) se representa mediante un puntero nulo, es posible construir una matriz de matrices Judy. En otras palabras, los Valores de una matriz Judy (excepto Judy1) pueden ser punteros a otras matrices Judy. Esto hace que sea muy sencillo construir una matriz con un número arbitrario de dimensiones o tamaños de Índice. (JudySL y JudyHS se implementan utilizando JudyL de esta manera).

ERRORES

Se dedicó mucho pensamiento (y tiempo) a hacer que el manejo de errores en Judy fuera simple, al tiempo que se mantenía la flexibilidad y la capacidad. El manejo de errores es un tema muy aburrido, incluso para escribir sobre él. Así que lea esta breve sección y utilice el segundo método recomendado. Genera el código más rápido, utiliza la menor cantidad de memoria y requiere que escriba código adicional solo para las funciones de inserción/eliminación. Además, es compatible con los otros dos métodos. Este método es para código de producción que puede querer manejar fallas de malloc() de manera diferente a la predeterminada de Judy. Si el método predeterminado de Judy para manejar fallas de malloc() está bien, entonces use el primer método.

Hay *dos (2)* categorías de retornos de error de Judy, (o para cualquier ADT dinámico):

1) Errores de programación del usuario (bugs) como corrupción de memoria o punteros inválidos.
2) Falta de memoria (falla de malloc()) al Insertar (Set) o Eliminar (Unset) al modificar una matriz Judy. No todas las llamadas a insertar y eliminar llaman a malloc(), por lo que pueden tener éxito incluso cuando una llamada a malloc() fallaría.

Hay aproximadamente *tres (3)* métodos para manejar errores al usar las macros:

1) MÉTODO DE MANEJO DE ERRORES PREDETERMINADO

El valor predeterminado es imprimir mensajes de error en stderr, por ejemplo:

Archivo 'TuArchivoC.c', línea 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Esto indica que ocurrió un error en la función JudyLIns() en la línea 321. La línea 1234 es la línea en 'TuArchivoC.c' donde falló la llamada JLI(). JU_ERRNO_* == 2 es igual a JU_ERRNO_NOMEM (como se define en el archivo Judy.h). El número de ID indica el número de línea de origen en la función donde se originó el error. Su programa luego termina con un exit(1);. Por defecto, ambas categorías de retornos de error de Judy se imprimen de esta manera. (El 'ID == 321' es para los más persistentes que desean más detalles o para depurar Judy en sí).

2) DESACTIVAR EL MANEJO DE ERRORES DE MACRO

Cuando su programa está "libre de errores", los únicos errores devueltos deberían ser fallas de malloc(). Por lo tanto, todos los retornos de error pueden tratarse como una falla de malloc(). Usando la siguiente definición #define, se desactiva todo el testeo e impresión de errores. Se necesita agregar código adicional al código que puede tener fallas de malloc(). Judy fue diseñada para dejar los mismos datos en la matriz antes de la llamada si ocurre una falla de malloc(). (Durante las pruebas de Judy, encontramos muy pocos malloc()/SOs que estaban libres de errores después de una falla de malloc(). A veces tardaba semanas en descubrirse porque la mayoría de los sistemas entran en un frenesí de paginación antes de quedarse sin memoria).

#define JUDYERROR_NOTEST 1
(en el código de su programa), o 
cc -DJUDYERROR_NOTEST archivo_fuente -lJudy

2) Disable Macro Error Handling

The Judy.h header file defines the JUDYERROR macro to handle error returns from the Judy macro APIs. The default definition for the JUDYERROR macro is as follows:

#ifndef JUDYERROR_NOTEST
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
        "JU_ERRNO_* == %d, ID == %d\n",                               \
        CallerFile, CallerLine,                                       \
        JudyFunc, JudyErrno, JudyErrID);                              \
    exit(1);                                                              \
}
#endif /* JUDYERROR_NOTEST */

The Judy macro APIs call the JUDYERROR macro when an error occurs. The JUDYERROR macro prints error information to stderr and then exits the program with exit code 1. This default error handling method should be used only when you are not testing for error conditions within your application.

In the following example of Judy macro API method two, the JUDYERROR macro is defined to do nothing when JUDYERROR_NOTEST is defined. This allows your code to continue execution and handle errors itself. 

#define JUDYERROR_NOTEST
#include <Judy.h>

In the next example of Judy macro API method two, the JUDYERROR macro is defined to do nothing when JUDYERROR_NOTEST is defined. This allows your code to continue execution and handle errors itself.

JLI(PValue, PLArray, Index);
if (PValue == PJERR) goto out_of_memory_handling;
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) goto out_of_memory_handling;
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;
Note: Without 'JUDYERROR_NOTEST' defined, the 'goto out_of_memory_handling' will never be executed and will be optimized out by the compiler. The default method will be used -- Macro will print error information if an error occurs as explained above.

With 'JUDYERROR_NOTEST' defined, the 'goto out_of_memory_handling' will be executed when an error occurs -- which should only happen when malloc() fails.

3) User-Specified JUDYERROR() Macro Method

The JUDYERROR() macro (in Judy.h) provides flexibility for handling error returns as needed to suit your program while still using the Judy array macros instead of function calls. You can use a different JUDYERROR() macro to suit your needs. The following example is a possible alternative to the default. It is used to distinguish between the two types of errors (described above), and explicitly test for the remaining JU_ERRNO_NOMEM errors possible in your program.

// This is an example of Judy macro API to continue when out of memory 
// and print and exit(1) when any other error occurs.
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // needed for fprintf()
// This is the macro that the Judy macro APIs use for return codes of -1:
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! a malloc() failure */         \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST not defined
This error handling macro must be included before the #include <Judy.h> statement in your program.
