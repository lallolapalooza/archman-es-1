Judy(3) Manual de funciones de biblioteca Judy(3)

NOMBRE

Arreglos Judy - Funciones de biblioteca C para crear y acceder a arreglos dinámicos

SINOPSIS

Judy1  - mapea un Índice (palabra) a un bit
JudyL  - mapea un Índice (palabra) a un Valor (palabra/puntero)
JudySL - mapea un Índice (cadena terminada en nulo) a un Valor
JudyHS - mapea un Índice (arreglo de bytes) de Longitud a un Valor

DESCRIPCIÓN

La familia de funciones Judy soporta arreglos completamente dinámicos. Estos arreglos pueden ser indexados por una palabra de 32 o 64 bits (dependiendo del tamaño de palabra del procesador), una cadena terminada en nulo o un arreglo de bytes más una longitud. Un arreglo dinámico (poblado de forma dispersa) también puede ser pensado como una función de mapeo o memoria asociativa.

Una Word_t es un typedef unsigned long int en Judy.h y debe tener el mismo tamaño que sizeof(void *), es decir, un puntero.

Funciones Judy1: El Índice es una Word_t y el Valor es solo un bit o simplemente un indicador de que el Índice está presente o ausente en el arreglo. Esto puede ser visto como un enorme mapa de bits.

Funciones JudyL: El Índice es una Word_t y el Valor es una Word_t. Esto hace que JudyL sea un mapeo puro de palabra a palabra/puntero. JudySL y JudyHL se basan en esta propiedad de JudyL.

Funciones JudySL: El Índice es una cadena terminada en nulo y el Valor es una Word_t.

Funciones JudyHS: El Índice es un arreglo de bytes de longitud: Longitud. El Valor es una Word_t. Esta nueva adición (mayo de 2004) a Judy es un híbrido que utiliza las mejores características de la hash y los métodos Judy. El autor cree que JudyHS es un buen reemplazo para un método de hash cuando el redimensionamiento de la tabla hash se realiza durante el crecimiento de la población. Un método hash correctamente ajustado con un tamaño de tabla hash estático y población es inmejorable en velocidad. Sin embargo, JudyHS funcionará mejor que un método hash con poblaciones menores y mayores que el tamaño óptimo de la tabla hash. JudyHS no tiene un caso de rendimiento degenerado donde se pueda explotar el conocimiento del algoritmo hash. (Es decir, JudyHS no utiliza una lista enlazada para manejar colisiones de hash, utiliza un árbol de arreglos JudyL y un tamaño de tabla hash virtual de 4 mil millones).

Los arreglos Judy son eficientes tanto en velocidad como en memoria, sin necesidad de ajustes o configuración, a través de una amplia gama de tipos de conjuntos de índices (secuenciales, periódicos, agrupados, aleatorios). La velocidad y el uso de memoria de Judy son típicamente mejores que otros modelos de almacenamiento de datos como listas de saltos, listas enlazadas, árboles binarios, ternarios, b-árboles, o incluso hashing, y mejoran con conjuntos de datos muy grandes.

Un arreglo Judy se crea simplemente definiendo un puntero nulo y luego almacenando (insertando) el primer elemento en el arreglo bajo ese puntero. La memoria utilizada por un arreglo Judy es casi proporcional a la población (número de elementos).

Judy tiene dos Interfaces de Programación de Aplicaciones (APIs): una interfaz de macros C y una interfaz de llamadas a funciones. Dado que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de usar las funciones Judy.

Dado que un arreglo Judy inicial (vacío) se representa mediante un puntero nulo, es posible construir un arreglo de arreglos Judy. En otras palabras, los Valores de un arreglo Judy (excepto Judy1) pueden ser punteros a otros arreglos Judy. Esto hace que sea muy simple construir un arreglo con un número arbitrario de dimensiones o tamaños de Índice. (JudySL y JudyHS se implementan utilizando JudyL de esta manera).

ERRORES

Se puso mucho pensamiento (y tiempo) en hacer que el manejo de errores en Judy fuera simple, manteniendo la flexibilidad y la capacidad. El manejo de errores es un tema muy aburrido, incluso para escribir sobre él. Así que lea esta breve sección y utilice el segundo método recomendado. Genera el código más rápido, utiliza la menor cantidad de memoria y requiere que escriba código adicional solo para las funciones de inserción/eliminación. Además, es compatible con los otros dos métodos. Este método es para código de producción que puede querer manejar fallos de malloc() de manera diferente al predeterminado de Judy. Si el método predeterminado de Judy para manejar fallos de malloc() es aceptable, entonces use el primer método.

Hay dos (2) categorías de retornos de error de Judy, (o para cualquier ADT dinámico):

1) Errores de programación del usuario (bugs) como corrupción de memoria o punteros inválidos.
2) Falta de memoria (fallo de malloc()) con la Inserción (Set) o Eliminación (Unset) al modificar un arreglo Judy. No todas las llamadas a inserción y eliminación llaman a malloc(), por lo que pueden tener éxito incluso cuando una llamada a malloc() fallaría.

Hay aproximadamente tres (3) métodos para manejar errores al usar las macros:

1) MÉTODO PREDETERMINADO DE MANEJO DE ERRORES

El valor predeterminado es imprimir mensajes de error en stderr, por ejemplo:

Archivo 'TuArchivoC.c', línea 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Esto indica que ocurrió un error en la función JudyLIns() en la línea 321. La línea 1234 es la línea en 'TuArchivoC.c' donde falló la llamada JLI(). JU_ERRNO_* == 2 es igual a JU_ERRNO_NOMEM (como se define en el archivo Judy.h). El número ID indica el número de línea de origen en la función donde se originó el error. Su programa luego termina con un exit(1);. Por defecto, ambas categorías de retornos de error de Judy se imprimen de esta manera. (El 'ID == 321' es para los más obstinados que quieren más detalles o para depurar el propio Judy).

2) DESHABILITAR EL MANEJO DE ERRORES DE MACRO

Cuando su programa está "libre de errores", los únicos errores devueltos deben ser fallos de malloc(). Por lo tanto, todos los retornos de error pueden tratarse como un fallo de malloc(). Al usar el siguiente #define, se desactiva toda la prueba e impresión de errores. Se debe agregar código adicional al código que puede tener fallos de malloc(). Judy fue diseñado para dejar los mismos datos en el arreglo antes de la llamada si ocurre un fallo de malloc(). (Durante las pruebas de Judy, encontramos muy pocos sistemas malloc()/OS que estuvieran libres de errores después de un fallo de malloc(). A veces tardaba semanas en descubrirse porque la mayoría de los sistemas entran en un frenesí de paginación antes de quedarse sin memoria).

#define JUDYERROR_NOTEST 1
(en el código de su programa), o 
cc -DJUDYERROR_NOTEST archivo_fuente -lJudy
(en la línea de comandos). 
// Este es un ejemplo de cómo programar
usando el método dos (2). 
JLI(PValue, PLArray, Index);
if (PValue == PJERR) goto out_of_memory_handling
; 
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;
Nota: Sin 'JUDYERROR_NOTEST' definido, el 'goto out_of_memory_handling' nunca se ejecutará y será optimizado por el compilador. Se usará el método predeterminado -- La macro imprimirá información de error si ocurre un error como se explicó anteriormente.

Con 'JUDYERROR_NOTEST' definido, el 'goto out_of_memory_handling' se ejecutará cuando ocurra un error -- lo cual solo debería suceder cuando malloc()

falle.

3) Método de Macro JUDYERROR() Especificado por el

Usuario

La macro JUDYERROR() (en Judy.h) proporciona flexibilidad para manejar los códigos de retorno de error según sea necesario para adaptarse a su programa mientras sigue usando las macros de arrays de Judy en lugar de llamadas a funciones. Puede usar una macro JUDYERROR() diferente para adaptarse a sus necesidades. El siguiente ejemplo es una posible alternativa a la predeterminada. Se utiliza para distinguir entre los dos tipos de errores (descritos anteriormente), y probar explícitamente los errores JU_ERRNO_NOMEM restantes posibles en su

programa. 
// Este es un ejemplo de la API de macros de Judy para continuar cuando se queda sin memoria
// e imprimir y exit(1) cuando ocurra cualquier otro
error. 
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // necesario para
fprintf() 
// Esta es la macro que las APIs de macros de Judy usan para códigos de retorno de
-1: 
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un fallo de malloc() */       \
    {                                                                     \
        (void) fprintf(stderr, "Archivo '%s', línea %d: %s(), "           \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST no definido
Esta macro de manejo de errores debe incluirse antes de la #include <Judy.h> en su
programa.
