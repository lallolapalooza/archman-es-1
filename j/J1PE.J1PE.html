Judy(3) Manual de funciones de biblioteca Judy(3)

NOMBRE

Arrays Judy - Funciones de biblioteca C para crear y acceder a arrays dinámicos

SINOPSIS

Judy1 - mapea un Índice (palabra) a un bit
JudyL - mapea un Índice (palabra) a un Valor (palabra/puntero)
JudySL - mapea un Índice (cadena terminada en nulo) a un Valor
JudyHS - mapea un Índice (array de bytes) de Longitud a un Valor

DESCRIPCIÓN

La familia de funciones Judy soporta arrays completamente dinámicos. Estos arrays pueden ser indexados por una palabra de 32 o 64 bits (dependiendo del tamaño de palabra del procesador), una cadena terminada en nulo o un array de bytes más longitud. Un array dinámico (escasamente poblado) también puede ser pensado como una función de mapeo o memoria asociativa.

Un Word_t es un typedef unsigned long int en Judy.h y debe ser del mismo tamaño que sizeof(void *), es decir, un puntero.

Funciones Judy1: Índice es un Word_t y Valor es solo un bit o simplemente una bandera de que el Índice está presente o ausente en el array. Esto puede ser pensado como un enorme bitmap.

Funciones JudyL: Índice es un Word_t y Valor es un Word_t. Esto hace de JudyL un mapeador puro palabra a palabra/puntero. JudySL y JudyHL se basan en esta propiedad de JudyL.

Funciones JudySL: Índice es una cadena terminada en nulo y Valor es un Word_t.

Funciones JudyHS: Índice es un array de bytes de longitud: Longitud. Valor es un Word_t. Esta nueva adición (mayo de 2004) a Judy es un híbrido que utiliza las mejores características de los métodos de hashing y Judy. El autor cree que JudyHS es un buen reemplazo para un método de hashing cuando el redimensionamiento de la tabla hash se realiza durante el crecimiento de la población. Un método hash correctamente ajustado con un tamaño de tabla hash **estático** y población es inmejorable en velocidad. Sin embargo, JudyHS funcionará mejor que un método hash con poblaciones más pequeñas y más grandes que el tamaño óptimo de la tabla hash. JudyHS no tiene un caso de rendimiento degenerado donde se pueda explotar el conocimiento del algoritmo hash. (Es decir, JudyHS no usa una lista enlazada para manejar colisiones hash, utiliza un árbol de arrays JudyL y un tamaño de tabla hash virtual de 4 mil millones).

Los arrays Judy son eficientes en velocidad y eficientes en memoria, sin necesidad de ajuste o configuración, en una amplia gama de tipos de conjuntos de índices (secuenciales, periódicos, agrupados, aleatorios). La velocidad y el uso de memoria de Judy suelen ser mejores que otros modelos de almacenamiento de datos como skiplists, listas enlazadas, árboles binarios, ternarios, b-trees, o incluso hashing, y mejora con conjuntos de datos muy grandes.

Un array Judy se crea simplemente definiendo un puntero nulo y luego almacenando (insertando) el primer elemento en el array bajo ese puntero. La memoria utilizada por un array Judy es casi proporcional a la población (número de elementos).

Judy tiene dos Interfaces de Programación de Aplicaciones (APIs): una interfaz de macros C y una interfaz de llamadas a funciones. Debido a que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de usar las funciones Judy.

Dado que un array Judy inicial (vacío) se representa por un puntero nulo, es posible construir un array de arrays Judy. En otras palabras, los Valores de un array Judy (excepto Judy1) pueden ser punteros a otros arrays Judy. Esto hace que sea muy simple construir un array con un número arbitrario de dimensiones o tamaños de Índice. (JudySL y JudyHS se implementan usando JudyL de esta manera).

ERRORES

Se puso mucho pensamiento (y tiempo) en hacer que el manejo de errores en Judy fuera simple, manteniendo la flexibilidad y la capacidad. El manejo de errores es un tema muy aburrido incluso para escribir. Así que lea esta corta sección y use el segundo método recomendado. Genera el código más rápido, usa la menor cantidad de memoria y requiere que escriba código adicional solo para las funciones de inserción/eliminación. Además, es compatible con los otros dos métodos. Este método es para código de producción que puede querer manejar fallas de malloc() de manera diferente a la predeterminada de Judy. Si el método predeterminado de Judy para manejar fallas de malloc() está bien, entonces use el primer método.

Hay *dos (2)* categorías de retornos de error de Judy (o para cualquier ADT dinámico):

1) Errores de programación del usuario (bugs) como corrupción de memoria o punteros inválidos.
2) Falta de memoria (fallo de malloc()) con Inserción (Set) o Eliminación (Unset) al modificar un array Judy. No todas las llamadas a inserción y eliminación llaman a malloc(), por lo que pueden tener éxito incluso cuando una llamada a malloc() fallaría.

Hay aproximadamente *tres (3)* métodos para manejar errores al usar las macros:

1) MÉTODO DE MANEJO DE ERRORES PREDETERMINADO

El predeterminado es imprimir mensajes de error en stderr, por ejemplo:

Archivo 'TuArchivoC.c', línea 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Esto indica que ocurrió un error en la función JudyLIns() en la línea 321. La línea 1234 es la línea en 'TuArchivoC.c' donde falló la llamada JLI(). JU_ERRNO_* == 2 es igual a JU_ERRNO_NOMEM (como se define en el archivo Judy.h). El número ID indica el número de línea de origen en la función donde se originó el error. Su programa luego termina con un exit(1);. Por defecto, ambas categorías de retornos de error de Judy se imprimen de esta manera. (El 'ID == 321' es para los más obstinados que quieren más detalles o para depurar Judy en sí).


2) DESACTIVAR EL MANEJO DE ERRORES DE MACRO

Cuando su programa está "libre de errores", los únicos errores devueltos deben ser fallos de malloc(). Por lo tanto, todos los retornos de error pueden tratarse como un fallo de malloc(). Al usar el siguiente #define, se desactiva todo el control e impresión de errores. Se necesita agregar código adicional al código que puede tener fallos de malloc(). Judy fue diseñado para dejar los mismos datos en el array antes de la llamada si ocurre un fallo de malloc(). (Durante las pruebas de Judy, encontramos muy pocos malloc()/SOs que estuvieran libres de errores después de un fallo de malloc(). A veces se tardaba semanas en descubrirlo porque la mayoría de los sistemas entran en un frenesí de paginación antes de quedarse sin memoria).

#define JUDYERROR_NOTEST 1
(en el código de su programa), o 
cc -DJUDYERROR_NOTEST archivo_fuente -lJudy
(en la línea de comandos).

Note: Without 'JUDYERROR_NOTEST' defined, the 'goto out_of_memory_handling' will never be executed and will be optimized out by the compiler. The default method will be used -- Macro will print error information if an error occurs as explained above.

With 'JUDYERROR_NOTEST' defined, the 'goto out_of_memory_handling' will be executed when an error occurs -- which should only happen when malloc() fails.

3) Método de Macro JUDYERROR() Especificado por el Usuario

La macro JUDYERROR() (en Judy.h) proporciona flexibilidad para manejar los valores de retorno de error según sea necesario para adaptarse a su programa, pero aún así utilizando las macros de la matriz Judy en lugar de llamadas a funciones. Puede usar una macro JUDYERROR() diferente para satisfacer sus necesidades. El siguiente ejemplo es una posible alternativa a la predeterminada. Se utiliza para distinguir entre los dos tipos de errores (descritos anteriormente) y para probar explícitamente los errores restantes de JU_ERRNO_NOMEM posibles en su programa.

// This is an example of Judy macro API to continue when out of memory 
// and print and exit(1) when any other error occurs.
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // needed for fprintf()
// This is the macro that the Judy macro APIs use for return codes of -1:
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! a malloc() failure */         \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST not defined
Esta macro de manejo de errores debe incluirse antes de la declaración #include <Judy.h> en su programa.
