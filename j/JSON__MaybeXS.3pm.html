DESCRIPCIÓ

N

Este módulo primero comprueba si Cpanel::JSON::XS o JSON::XS (al menos en la versión 3.0) ya está cargado, en cuyo caso usa ese módulo. De lo contrario, intenta cargar Cpanel::JSON::XS, luego JSON::XS, y luego JSON::PP en orden, y usa el primer módulo que encuentre o lanza un

error.

Luego exporta las funciones "encode_json" y "decode_json" del módulo cargado, junto con una constante "JSON" que devuelve el nombre de la clase sobre la que llamar "new"

.

Si estás escribiendo código nuevo en lugar de reemplazar el uso de JSON.pm, podrías querer pasar opciones como argumentos del constructor en lugar de llamar a mutadores, así que proporcionamos nuestro propio método "new"

que lo
soporta.

EXPORTACION

ES

"encode_json", "decode_json" y "JSON" se exportan por defecto; "is_bool" se exporta bajo

petición.

Para importar solo algunos símbolos, especifícalos en la línea "u

se": 
use JSON::MaybeXS qw(encode_json decode_json is_bool); # solo funciones
use JSON::MaybeXS qw(JSON); # solo la constante
JSON

Para importar todos los símbolos disponibles sensatos ("encode_json", "decode_json" y "is_bool"), usa ":all

": 
use JSON::MaybeXS ':
all';

Para importar todos los símbolos, incluyendo aquellos necesarios por aplicaciones antiguas que usan JSON::

PP: 
use JSON::MaybeXS ':
legacy';

Esto importa los símbolos "to_json" y "from_json" así como todo lo que hay en ":all". NOTA: Esto es para soportar código antiguo que hace un uso extensivo de "to_json" y "from_json" y que aún no estás en posición de refactorizar. NO uses esta etiqueta de importación en código nuevo, para evitar los horrores inquietantes de obtener el soporte UTF-8 sutilmente mal. Consulta la documentación de JSON para más

detalles.

Con JSON::PP, JSON::XS y Cpanel::JSON::XS se requiere que llames a mutadores para establecer opciones,

como: 
my $json = $class->new->utf8(1)->pretty(1)
;

Dado que esto es un poco irritante y notablemente poco perlish, también

ofrecemos:

;

que funciona equivalente a lo anterior (y en la tradición habitual aceptará un hashref en lugar de un hash, si así lo deseas)

.

El objeto resultante es bendecido en el backend subyacente, que ofrece (al menos) los métodos "encode" y "dec

o
de
".

ybeXS".

Si está utilizando un objeto devuelto por este módulo como un atributo de Moo(se), este código de restricción de

INST
ALA
CIÓN

Durante la

instalación,

Makefile.PL intentará determinar si tiene un compilador funcional disponible y, por lo tanto, si es capaz de ejecutar código XS. Si es así, Cpanel::JSON::XS se añadirá a la lista de prerrequisitos, a menos que JSON::XS ya esté instalado en una versión suficientemente alta. JSON::XS también puede actualizarse para corregir cualquier problema de incompatibilidad. Dado que ejecutar código XS no es obligatorio y JSON::PP (que está en el núcleo de perl) se utiliza como backend de respaldo, este módulo es seguro de usar en un conjunto de código que esté empaquetado (fatpacked) o instalado en un entorno con recursos

restringidos.

También puede evitar que se instalen dependencias XS

estableciendo

"PUREPERL_ONLY=1" en las opciones de Makefile.PL (o en la variable de entorno "PERL_MM_OPT"), o usando los indicadores "--pp" o "--pureperl" con el

cliente
cpanminus.
