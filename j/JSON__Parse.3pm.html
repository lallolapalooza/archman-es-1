NOMBRE

JSON::Parse - Parsear JSON

SINTAXIS

use JSON::Parse 'parse_json';

# Mismo efecto que $perl = ['dorado', 'vellocino'];

Convertir JSON en Perl.

DESCRIPCIÓN

Un módulo para parsear JSON. (JSON significa "Notación de Objetos de JavaScript" y está especificado en "RFC 8259".)

JSON::Parse ofrece la función `parse_json`, que toma una cadena que contiene JSON y devuelve una estructura equivalente en Perl. También ofrece la validación de JSON mediante `valid_json`, que devuelve verdadero o falso según si el JSON es correcto o no, y `assert_valid_json`, que produce un error fatal descrito si el JSON es inválido. Una función `read_json` lee JSON desde un archivo, y hay una versión más segura de `parse_json` llamada `parse_json_safe` que no lanza excepciones.

También hay métodos `new` y `parse` para casos especiales de parseo, que crean un objeto de parseo JSON y lo ejecutan en texto. Consulte "MÉTODOS".

JSON::Parse solo acepta UTF-8 como entrada. Consulte "Solo UTF-8" y "Tratamiento de Unicode".

parse_json

use JSON::Parse 'parse_json';
my $perl = parse_json ('{"x":1, "y":2}');

Esta función convierte JSON en una estructura Perl, ya sea una referencia a un array, una referencia a un hash o un escalar.

Si el primer argumento no contiene una cadena JSON completa válida, "parse_json" lanza un error fatal. Se produce un error fatal si la entrada es un valor indefinido, una cadena vacía o una cadena con solo espacios en blanco.

Si el argumento contiene JSON válido, el valor devuelto es una referencia a un hash, una referencia a un array o un escalar. Si la cadena JSON es un objeto serializado, se devuelve una referencia a un hash:

use JSON::Parse ':all';
my $perl = parse_json ('{"a":1, "b":2}');
print ref $perl, "\n";

produce la siguiente salida:

HASH

(Este ejemplo está incluido como hash.pl https://fastapi.metacpan.org/source/BKB/JSON-Parse-0.62/examples/hash.pl en la distribución.)

Si la cadena JSON es un array serializado, se devuelve una referencia a un array:

use JSON::Parse ':all';
my $perl = parse_json ('["a", "b", "c"]');
print ref $perl, "\n";

produce la siguiente salida:

ARRAY

(Este ejemplo está incluido como array.pl https://fastapi.metacpan.org/source/BKB/JSON-Parse-0.62/examples/array.pl en la distribución.)

En otros casos, se devuelve un escalar.

La función `parse_json_safe` ofrece una versión de esta función con varias características de seguridad habilitadas. El método `parse` es equivalente a esta.

El comportamiento de permitir un escalar se añadió en la versión 0.32 de este módulo. Esto lo pone en línea con la nueva especificación de JSON. El comportamiento de desactivar entradas vacías fue cambiado en la versión 0.49.

parse_json_safe

Esto es casi lo mismo que `parse_json`, pero tiene las siguientes diferencias:

No lanza excepciones
Si el JSON es inválido, se imprime una advertencia y se devuelve el valor indefinido, como si se llamara a `parse_json` de esta manera: 
eval {
    $out = parse_json ($json);
};
if ($@) {
    carp $@;
    $out = undef;
}
Detecta colisiones de claves
Esto activa el parámetro `detect_collisions`, así que si el JSON contiene nombres no únicos, se imprime una advertencia y se devuelve el valor indefinido. Consulte "Colisiones de claves" para una explicación de qué es una colisión de clave.
Los valores booleanos no son de solo lectura
Esto activa el parámetro `copy_literals`, así que los valores JSON true, false y null se copian. Estos valores pueden ser modificados, pero no se convertirán de nuevo en "true" y "false" por JSON::Create.
Los errores se reportan mediante carp
Los errores de parseo se reportan mediante `carp` de Carp, así que el número de línea del error se refiere a la línea del llamador.

Como sugiere el nombre, este es un módulo de seguridad primero. El módulo `parse_json`.

🎲 Esta función fue añadida en la versión 0.38.

read_json

use JSON::Parse 'read_json';
my $p = read_json ('nombre_archivo');

Esto es exactamente lo mismo que `parse_json` excepto que lee JSON desde un archivo en lugar de una cadena. El archivo debe estar en formato UTF-8 y se abre como un archivo de caracteres usando `:encoding(utf8)` (ver PerlIO::encoding y perluniintro). El resultado se marca como cadena de caracteres.

El método equivalente es `read`.

Esta es una función de conveniencia escrita en Perl. Si desea un mejor rendimiento, puede leer el archivo por sí mismo utilizando otro módulo.

Esto fue renombrado de `json_file_to_perl` en la versión 0.59. El nombre antiguo también seguirá funcionando indefinidamente.

valid_json

use JSON::Parse 'valid_json';
if (valid_json ($json)) {
    # hacer algo
}

`valid_json` devuelve 1 si el argumento es JSON válido y 0 en caso contrario. Se ejecuta varias veces más rápido que `parse_json`. Esta ganancia de velocidad se obtiene porque descarta los datos de entrada después de leerlos, en lugar de almacenarlos en variables Perl.

No proporciona los errores reales que causaron la invalidez. Use `assert_valid_json` para obtener mensajes de error cuando el JSON es inválido.

No puede detectar claves duplicadas en objetos JSON, ya que no almacena valores. Consulte "Colisiones de claves" para más información sobre cómo este módulo maneja nombres no únicos en el JSON.

Mapeo de JSON a

Perl

Los elementos JSON se mapean a Perl de la siguiente

manera:

Números

JSON

Los números JSON se convierten en números de Perl, ya sea enteros o números de punto flotante de doble precisión, o posiblemente cadenas que contienen el número si el análisis de un número por los métodos habituales falla de alguna

manera.

JSON no permite ceros a la izquierda, como 0123, o signos más a la izquierda, como +100, en números, por lo que estos causan un error "Unexpected character". JSON tampoco permite números de la forma 1., pero sí permite cosas como 0e0 o 1E999999. En la medida de lo posibl

e, estos son acepta
dos por JSON::Parse.

Cadenas

JSON

Las cadenas JSON se convierten en cadenas de Perl. Los caracteres de escape JSON como "\t" para el carácter de tabulación (ver sección 2.5 de "RFC 8259") se mapean al carácter ASCII

equivalente.

Manejo de

Unicode

Las entradas deben estar en formato UTF-8. Ver "Solo

UTF-8".

Además, JSON::Parse rechaza UTF-8 que codifica no caracteres como "U+FFFF" y caracteres mal formados como mitades incompletas de pares

sustitutos.

Los puntos de codificación Unicode en la entrada de la forma "\u3000" se convierten en los bytes UTF-8

equivalentes.

Los pares sustitutos de la forma "\uD834\uDD1E" también se manejan. Si la segunda mitad del par sustituto falta, se lanza un error "Unexpected character" o "Unexpected end of input". Si la segunda mitad del par sustituto está presente pero contiene un valor imposible, se lanza un error "Not surrogate

pair".

Si la entrada de "parse_json" está marcada como caracteres Unicode, las cadenas de salida estarán marcadas como caracteres Unicode. Si la entrada no está marcada como caracteres Unicode, las cadenas de salida no estarán marcadas como caracteres Unicode.

0x80.

caracteres:

Los objetos JSON se convierten en hashes de Perl. Los miembros del objeto JSON se convierten en pares clave-valor en el hash de Perl. La parte de cadena de cada miembro del objeto se convierte en la clave del hash de Perl. La parte de valor de cada miembro se mapea al valor del hash de

RESTRICCIONE

S

Este módulo impone las siguientes restricciones en su

entrada.
Solo
JSON
JSON::Parse es un analizador estricto. Solo acepta entrada que cumple exactamente con los criterios de "RFC 8259". Eso significa, por ejemplo, que JSON::Parse no acepta comillas simples (') en lugar de comillas dobles ("), o números con ceros a la izquierda, como 0123. JSON::Parse no acepta caracteres de control (0x00 - 0x1F) en cadenas, comas faltantes entre elementos de array o hash como "["a" "b"]", o comas finales como "["a","b","c",]". Tampoco acepta no espacios en blanco finales, como el segundo "]" en "["a"]]".

Puede que encuentres útil "JSON::Repair" de los

mismos autores que JSON::Parse si necesitas pro
cesar texto tipo JSON con tolerancia a errores.
Sin análisis
incremental
JSON::Parse no analiza de forma incremental. Solo analiza cadenas JSON completamente formadas que incluyen todos los corchetes de apertura y cierre. Esta es una parte inherente del diseño del módulo. El análisis incremental al estilo de XML::Parser requeriría algún tipo de estructura de devolución de llamada para lidiar con los elementos de las estructuras parcialmente digeridas, pero JSON::Parse nunca fue diseñado para hacer esto; simplemente convierte lo que ve en una estructura Perl. Las afirmaciones de ofrecer análisis JSON incremental en la documentación de otros módulos deberían verificarse
diligentemente.
Solo
UTF-8
JSON::Parse solo analiza el formato UTF-8. Si la entrada está en una codificación Unicode diferente a UTF-8, convierte la entrada antes de entregársela a este módulo. Por ejemplo, para el formato UTF-16, 
use Encode 'decode';

;

o, para un archivo, usa ":encoding" (ver PerlIO::encoding y

perluniintro): 
open my $input, "<:encoding(UTF-16)",
'some-json-file';

JSON::Parse no intenta determinar la naturaleza del flujo de octetos usando marcadores BOM. Un marcador BOM en la entrada consiste en los bytes 0xFE y 0xFF, ambos de los cuales son inválidos como UTF-8, y por lo tanto causarán un error

fatal.

Esta restricción a UTF-8 aplica independientemente de si Perl piensa que la cadena de entrada es una cadena de caracteres o una cadena de bytes. La entrada no UTF-8 causará un error "Unexpected

character".

La especificación más reciente para JSON, "RFC 8259", lo especifica como un formato solo

UTF-8.

JSON::Parse no acepta no caracteres Uni

code (U+FFFF, UFDDO, etc.), UTF-8 que r
epresente puntos de código de pares sus
titutos, o bytes fuera del rango de pun

PRUEBA

S

Código de pruebas

interno

El módulo incorpora pruebas extensas relacionadas con la producción de mensajes de error y la validación de la entrada. Parte del código de pruebas se incluye con el módulo en el subdirectorio /t/ de la

distribución.

Hay código de pruebas más extenso en el repositorio de git. Esto no se incluye en la distribución de CPAN. Un script, randomjson.pl https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/randomjson.pl, genera una cantidad determinada de bytes de JSON aleatorio y comprueba que la validación byte a byte de la entrada del módulo es correcta. Lo hace tomando un fragmento válido, luego añadiendo cada byte posible del 0 al 255 para ver si el módulo lo identifica correctamente como válido o inválido en ese punto, luego elige aleatoriamente uno de los bytes válidos y lo añade al fragmento, y continúa el proceso hasta que se forma una entrada JSON válida completa. El módulo ha pasado aproximadamente mil millones de repeticiones de esta

prueba.

Esta configuración depende de un archivo C, json-random-test.c https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/json-random-test.c, que no está en la distribución de CPAN, y también requiere que Json3.xs https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/Json3.xs sea editado para hacer que la macro "TESTRANDOM" sea verdadera (descomente la línea 7 del archivo). El código de pruebas usa setjmp/longjmp de C, por lo que no se garantiza que funcione en todos los sistemas operativos y está comentado para las versiones de

CPAN.

También existe una versión en C puro llamada random-test.c https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/random-test.c . Esta aplica exactamente las mismas pruebas y no requiere Perl en

absoluto.

Si le interesa probar su propio analizador JSON, las salidas generadas por randomjson.pl https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/randomjson.pl son un buen punto de partida. Por defecto produce salida UTF-8, que se ve bastante horrible ya que tiende a producir largas cadenas de basura UTF-8. (Esto es porque elige aleatoriamente entre 256 bytes y el marcador de fin de cadena """ solo tiene una probabilidad de 1/256 de ser elegido, por lo que las cadenas tienden a ser largas y desordenadas). Puede modificar los internos de JSON::Parse estableciendo MAXBYTE en json-common.c a 0x80, recompilando (puede ignorar las advertencias del compilador), y ejecutando randomjson.pl de nuevo para obtener solo cosas JSON aleatorias en ASCII. Esto romp

e la funcionalidad UTF-8 de JSON::Parse, as
í que por favor no instale esa versión.

Suite de pruebas de análisis

JSON

JSON::Parse versión 0.58 pasa la mayor parte de la Suite de pruebas de análisis JSON, con la excepción de que JSON::Parse rechaza varias entradas UTF-8 erróneas, por ejemplo, JSON::Parse lanzará un error para puntos de código no caracteres como Unicode U+FFFF y U+10FFFF. Este analizador solo acepta UTF-8 válido como entrada. Véase "Solo

UTF-8".

En nuestra opinión, sería un deservicio para los usuarios de este módulo permitir bytes que contienen fragmentos inútiles, como partes incompletas de pares sustitutos, o caracteres inválidos, solo porque la especificación JSON no exige explícitamente rechazar este tipo de entradas basura. Por favor, vea la función "daft_test" en el archivo xt/JPXT.pm para ver exactamente cuáles de estos elementos de la suite de pruebas no cumplimos. Observamos que este comentario de Douglas Crockford, el inventor de JSON, del analizador JSON https://github.com/douglascrockford/JSON-c/blob/master/utf8_decode.c#L38-L43, fechado en 2005, está de acuerdo con nuestra opinión en este

punto.

JSON::Parse versión 0.58 también introdujo "get_max_depth"

y "set_max_depth" para prevenir los errores de desbo
rdamiento de pila causados por algunas entradas muy a
nidadas, como las de la Suite de pruebas de análisis JSON.
