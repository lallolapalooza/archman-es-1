DESCRIPCIÓ

N

Este módulo es una envoltura delgada para módulos compatibles con JSON::XS con algunas características adicionales. Todos los módulos de backend convierten una estructura de datos de Perl a un texto JSON y viceversa. Este módulo usa JSON::XS de forma predeterminada, y cuando JSON::XS no está disponible, recurre a JSON::PP, que está en el núcleo de Perl desde la versión 5.14. Si JSON::PP tampoco está disponible, este módulo recurre a JSON::backportPP (que en realidad es JSON::PP en un archivo .pm diferente) incluido en la misma distribución que este módulo. También puede especificar explícitamente usar Cpanel::JSON::XS, un fork de JSON::XS por Reini

Urban.

Todos estos módulos de backend tienen ligeras incompatibilidades entre ellos, incluyendo características adicionales que otr

os módulos no soportan, pero siempre que use solo características comunes (las más importantes se describen más abajo), l
a migración de un backend a otro debería ser bastante fácil. Para más detalles, consulte cada módulo de backend que use.

ELECCIÓN DEL

BACKEND

Este módulo respeta una variable de entorno llamada "PERL_JSON_BACKEND" cuando decide qué módulo de backend usar. Si esta variable de entorno no está definida, intenta cargar JSON::XS, y si JSON::XS no está disponible, recurre a JSON::PP, y luego a JSON::backportPP si JSON::PP tampoco está

disponible.

Si no quiere que nunca recurra a módulos de Perl puro, defina la variable así («export» puede ser «setenv», «set» y similares, dependiendo de su entorno)

OPCIONALES

Hay algunas opciones que puede definir cuando «use»a este módulo. Estas opciones históricas se mantienen solo por compatibilidad con versiones anteriores y no deberían usarse en una nueva

-support_by_
pp 
BEGIN { $ENV{PERL_JSON_BACKEND} = 'JSON::XS' }

use JSON -support_by_pp;

my $json = JSON->new;
# escape_slash es solo para JSON::PP.

Con esta opción, este módulo carga su backend de Perl puro junto con su backend XS (si está disponible), y permite que el backend XS vigile si define una bandera que solo soporta JSON::PP. Cuando lo hace, el objeto JSON::XS interno se reemplaza con un objeto JSON::PP recién creado con la configuración copiada del objeto XS, de modo que pueda usar las banderas de JSON::PP (y sus métodos más lentos «decode»/«encode» ) a partir de ese momento. En otras palabras, esto no es algo que le permita engancharse a JSON::XS para cambiar su comportamiento manteniendo su velocidad. Los objetos JSON::XS y JSON::PP son bastante diferentes (el objeto JSON::XS es una referencia a escalar bendecida, mientras que el objeto JSON::PP es una referencia a hash bendecida), y no pueden compartir sus

internos.

Para evitar una sobrecarga innecesaria (al copiar configuraciones), se le aconseja no usar esta opción y simplemente usar JSON::PP explícitamente cuando necesite características de

JSON::
PP.
-convert_blessed_universa

use JSON -convert_blessed_universally;
my $json = JSON->new->allow_nonref->convert_blessed;
my $object = bless {foo => 'bar'}, 'Foo';
$json->encode($object); # => {"foo":
"bar"}

Los módulos de backend compatibles con JSON::XS no codifican objetos bendecidos de forma predeterminada (excepto sus valores booleanos, que típicamente son objetos JSON::PP::Boolean bendecidos). Si necesita codificar una estructura de datos que pueda contener objetos, normalmente necesita examinar la estructura y reemplazar los objetos con valores alternativos no bendecidos, o habilitar «convert_blessed» y proporcionar un método «TO_JSON» para cada clase (base) de los objetos que puedan encontrarse en la estructura, para permitir que los métodos reemplacen los objetos con cualquier valor escalar que los métodos

devuelvan.

Si necesita serializar estructuras de datos que puedan contener objetos arbitrarios, probablemente sea mejor usar otros serializadores (como Sereal o Storable, por ejemplo), pero si realmente quiere usar este módulo para ese propósito, la opción «-convert_blessed_universally» puede ayudar, la cual ajusta el método «encode» del backend para instalar el método «UNIVERSAL::TO_JSON» (localmente) antes de codificar, de modo que todos los objetos que no tengan su propio método «TO_JSON» puedan recurrir al método en el espacio de nombres «UNIVERSAL». Tenga en cuenta que aún necesita habilitar la bandera «convert_blessed» para realmente codificar objetos en una estructura de datos, y el método «UNIVERSAL::TO_JSON» instalado por esta opción solo convierte referencias a hash/array bendecidas en su clon no bendecido (incluyendo claves/valores privados que no se supone que se expongan). Otras referencias bendecidas se convertirán en

null.

laxed

$json = $json->laxed([$enable])

$enabled = $json->get_laxed

Si $enable es verdadero (o falta), entonces "decode" aceptará algunas extensiones a la sintaxis JSON normal (ver abajo). "encode" no se verá afectado de ninguna manera. ¡Tenga en cuenta que esta opción hace que acepte textos JSON inválidos como si fueran válidos!. Sugiero usar esta opción solo para analizar archivos específicos de la aplicación escritos por humanos (archivos de configuración, archivos de recursos, etc.)

Si $enable es falso (el valor por defecto), entonces "decode" solo aceptará textos JSON válidos.

Las extensiones actualmente aceptadas son:

  • los elementos de lista pueden tener una coma final

    JSON separa los elementos de la matriz y los pares clave-valor con comas. Esto puede ser molesto si escribe textos JSON manualmente y desea poder agregar elementos rápidamente, por lo que esta extensión acepta comas al final de dichos elementos, no solo entre ellos:

    [
   1,
   2, <- esta coma no está permitida normalmente
]
{
   "k1": "v1",
   "k2": "v2", <- esta coma no está permitida normalmente
}
  • comentarios estilo shell '#'.

    Dondequiera que JSON permita espacios en blanco, se permiten adicionalmente comentarios estilo shell. Se terminan con el primer carácter de retorno de carro o salto de línea, después del cual se permiten más espacios en blanco y comentarios.

    [
   1, # este comentario no está permitido en JSON
      # ni este...
]

canonical

$json = $json->canonical([$enable])

$enabled = $json->get_canonical

Si $enable es verdadero (o falta), entonces el método "encode" generará objetos JSON ordenando sus claves. Esto agrega una sobrecarga comparativamente alta.

Si $enable es falso, entonces el método "encode" generará pares clave-valor en el orden en que Perl los almacena (lo que probablemente cambiará entre ejecuciones del mismo script, y puede cambiar incluso dentro de la misma ejecución a partir de 5.18).

Esta opción es útil si desea que la misma estructura de datos se codifique como el mismo texto JSON (dadas las mismas configuraciones generales). Si está deshabilitada, el mismo hash podría codificarse de manera diferente incluso si contiene los mismos datos, ya que los pares clave-valor no tienen un orden inherente en Perl.

Esta configuración no tiene efecto al decodificar textos JSON.

Esta configuración actualmente no tiene efecto en hashes ligados.

allow_nonref

$json = $json->allow_nonref([$enable])

$enabled = $json->get_allow_nonref

A diferencia de otras opciones booleanas, esta opción está habilitada por defecto a partir de la versión 4.0.

Si $enable es verdadero (o falta), entonces el método "encode" puede convertir un no-referencia en su valor JSON de cadena, número o nulo correspondiente, lo que es una extensión de RFC4627. Del mismo modo, "decode" aceptará esos valores JSON en lugar de fallar.

Si $enable es falso, entonces el método "encode" fallará si no se le pasa un referencia de array o referencia de hash, ya que los textos JSON deben ser un objeto o una matriz. Del mismo modo, "decode" fallará si se le da algo que no sea un objeto o matriz JSON.

Ejemplo, codificar un escalar de Perl como valor JSON con "allow_nonref" habilitado, lo que resulta en un texto JSON inválido:

JSON->new->allow_nonref->encode ("Hello, World!")
=> "Hello, World!"

allow_unknown

$json = $json->allow_unknown ([$enable])

$enabled = $json->get_allow_unknown

Si $enable es verdadero (o falta), entonces "encode" no lanzará una excepción cuando encuentre valores que no puede representar en JSON (por ejemplo, manejadores de archivos), sino que codificará un valor JSON "null". Tenga en cuenta que los objetos bendecidos no se incluyen aquí y se manejan por separado con c<allow_blessed>.

Si $enable es falso (el valor por defecto), entonces "encode" lanzará una excepción cuando encuentre algo que no pueda codificar como JSON.

Esta opción no afecta a "decode" de ninguna manera, y se recomienda dejarla desactivada a menos que conozca a su interlocutor.

allow_blessed

$json = $json->allow_blessed([$enable])

$enabled = $json->get_allow_blessed

Ver "SERIALIZACIÓN DE OBJETOS" para más detalles.

Si $enable es verdadero (o falta), entonces el método "encode" no fallará cuando encuentre una referencia bendecida que no pueda convertir de otra manera. En su lugar, se codifica un valor JSON "null" en lugar del objeto.

Si $enable es falso (el valor por defecto), entonces "encode" lanzará una excepción cuando encuentre un objeto bendecido que no pueda convertir de otra manera.

Esta configuración no tiene efecto en "decode".

convert_blessed

$json = $json->convert_blessed([$enable])

$enabled = $json->get_convert_blessed

Ver "SERIALIZACIÓN DE OBJETOS" para más detalles.

Si $enable es verdadero (o falta), entonces "encode", al encontrar un objeto bendecido, verificará la disponibilidad del método "TO_JSON" en la clase del objeto. Si se encuentra, se llamará en contexto escalar y el escalar resultante se codificará en lugar del objeto.

El método "TO_JSON" puede llamar a `die` de forma segura si lo desea. Si "TO_JSON" devuelve otros objetos bendecidos, estos se manejarán de la misma manera. "TO_JSON" debe tener cuidado de no causar un ciclo de recursión sin fin (== caída) en este caso. El nombre de "TO_JSON" fue elegido porque otros métodos llamados por el núcleo de Perl (== no por el usuario del objeto) suelen estar en mayúsculas y para evitar colisiones con cualquier función o método "to_json".

Si $enable es falso (el valor por defecto), entonces "encode" no considerará este tipo de conversión.

Esta configuración no tiene efecto en "decode".

allow_tags (desde la versión 3.0)

$json = $json->allow_tags([$enable])
$enabled = $json->get_allow_tags

Ver "SERIALIZACIÓN DE OBJETOS" para más detalles.

Si $enable es verdadero (o falta), entonces "encode", al encontrar un objeto bendecido, verificará la disponibilidad del método "FREEZE" en la clase del objeto. Si se encuentra, se utilizará para serializar el objeto en un valor JSON no estándar etiquetado (que los decodificadores JSON no pueden decodificar).

También hace que "decode" analice esos valores JSON etiquetados y los deserialice a través de una llamada al método "THAW".

Si $enable es falso (el valor por defecto), entonces "encode" no considerará este tipo de conversión, y los valores JSON etiquetados causarán un error de análisis en "decode", como si las etiquetas no fueran parte de la gramática.

boolean_values (desde la versión 4.0)

$json->boolean_values([$false, $true])
($false,  $true) = $json->get_boolean_values

Por defecto, los booleanos JSON se decodificarán como objetos sobrecargados $JSON::false y $JSON::true.

Con este método puedes especificar tus propios valores booleanos para la decodificación: en la decodificación, el "false" JSON se decodificará como una copia de $false, y el "true" JSON se decodificará como $true ("copia" aquí es lo mismo que asignar un valor a otra variable, es decir, "$copy = $false").

Esto es útil cuando desea pasar una estructura de datos decodificada directamente a otros serializadores como YAML, Data::MessagePack y similares.

Tenga en cuenta que esto solo funciona cuando se "decode". Puede establecer objetos booleanos incompatibles (como booleanos), pero cuando se "encode" una estructura de datos con dichos objetos booleanos, aún necesita habilitar "convert_blessed" (y agregar un método "TO_JSON" si es necesario).

Llamar a este método sin ningún argumento restablecerá los booleanos a sus valores predeterminados.

"get_boolean_values" devolverá ambos valores $false y $true, o la lista vacía cuando estén establecidos en los valores predeterminados.

filter_json_object

$json = $json->filter_json_object([$coderef])

Cuando se especifica $coderef, se llamará desde "decode" cada vez que decodifique un objeto JSON. El único argumento es una referencia al hash recién creado. Si el código de referencia devuelve un solo escalar (que no tiene por qué ser una referencia), este valor (o más bien una copia del mismo) se insertará en la estructura de datos deserializada. SERIALIZACIÓN DE OBJETOS

Como JSON no puede representar directamente objetos Perl, tienes que elegir entre una representación pura de JSON (sin capacidad de deserialización automática de objetos) o una extensión no estándar de la sintaxis JSON, los valores etiquetados.

SERIALIZACIÓN

Lo que ocurre cuando este módulo encuentra un objeto Perl depende de las configuraciones "allow_blessed", "convert_blessed" y "allow_tags", que se utilizan en este orden:

1. "allow_tags" está habilitado y el objeto tiene un método "FREEZE".
En este caso, "JSON" crea un valor etiquetado de JSON, utilizando una extensión no estándar de la sintaxis JSON. Esto se logra invocando el método "FREEZE" del objeto, con el primer argumento siendo el objeto a serializar y el segundo argumento siendo la constante string "JSON" para distinguirlo de otros serializadores.

El método "FREEZE" puede devolver cualquier número de valores (es decir, cero o más). Estos valores y el nombre de la clase/objeto del objeto se codificarán como un valor etiquetado de JSON en el siguiente formato:

("clase")[VALORES_DEVUELTOS...]

por ejemplo:

("URI")["http://www.google.com/"]
("MyDate")[2013,10,29]
("ImageData::JPEG")["Z3...VlCg=="]

Por ejemplo, el método hipotético "My::Object""FREEZE" podría usar los miembros "type" e "id" del objeto para codificar el objeto:

sub My::Object::FREEZE {
   my ($self, $serialiser) = @_;
   ($self->{type}, $self->{id})
}
2. "convert_blessed" está habilitado y el objeto tiene un método "TO_JSON".
En este caso, el método "TO_JSON" del objeto se invoca en contexto escalar. Debe devolver un escalar único que pueda ser directamente codificado en JSON. Este escalar reemplaza el objeto en el texto JSON.

Por ejemplo, el siguiente método "TO_JSON" convertirá todos los objetos URI en cadenas JSON cuando se serialicen. La pérdida de que estos valores originalmente fueran objetos URI es irrelevante.

sub URI::TO_JSON {
   my ($uri) = @_;
   $uri->as_string
}
3. "allow_blessed" está habilitado.
El objeto se serializa como un valor JSON nulo.
4. Ninguno de los anteriores.
Si ninguna de las configuraciones está habilitada o los respectivos métodos no existen, este módulo lanza una excepción.

DESERIALIZACIÓN

Para la deserialización hay dos casos a considerar: o se ha utilizado una etiquetación no estándar, en cuyo caso "allow_tags" decide, o el objeto no puede ser deserializado automáticamente, en cuyo caso se puede usar postprocessing o los callbacks "filter_json_object" o "filter_json_single_key_object" para obtener objetos reales a partir de tu JSON.

Esta sección solo considera el caso de valores etiquetados: se encuentra un objeto JSON etiquetado durante la deserialización y "allow_tags" está deshabilitado, lo que resulta en un error (como si los valores etiquetados no estuvieran en la gramática).

Si "allow_tags" está habilitado, este módulo buscará el método "THAW" de la clase/espacio usado durante la serialización (no intentará cargar el espacio como un módulo Perl). Si no existe tal método, la deserialización fallará con un error.

De otro modo, se invoca el método "THAW" con el nombre de la clase como el primer argumento, la constante string "JSON" como el segundo argumento, y todos los valores de la lista JSON (los valores originales devueltos por el método "FREEZE") como argumentos restantes.

El método debe devolver el objeto. Aunque técnicamente puedes devolver cualquier escalar Perl, tal vez tengas que habilitar la opción "allow_nonref" para que funcione en todos los casos, así es mejor devolver una referencia bendecida real.

Como ejemplo, implementamos un método "THAW" que regenera el "My::Object" a partir del ejemplo de "FREEZE":

sub My::Object::THAW {
   my ($class, $serialiser, $type, $id) = @_;
   $class->new (type => $type, id => $id)
}

NOTAS SOBRE LOS FLAGS DE CODIFICACIÓN/CODIGOS

Esta sección se tomó de JSON::XS.

El lector interesado podría haber visto varios flags que indican los códigos o encadenamientos - "utf8", "latin1" y "ascii". Hay cierta confusión sobre lo que hacen estos, así que aquí hay una comparación breve:

"utf8" controla si el texto JSON generado por "encode" (y esperado por "decode") está codificado en UTF-8 o no, mientras que "latin1" y "ascii" solo controlan si "encode" escapa los valores de caracteres fuera del rango de su conjunto de códigos. Ninguno de estos flags se contradicen entre sí, aunque algunas combinaciones son menos sensatas que otras.

Se ha tenido cuidado para que todos los flags sean simétricos con respecto a "encode" y "decode", es decir, los textos codificados con cualquier combinación de estos flags se decodificarán correctamente cuando se usen los mismos flags - en general, si usas diferentes configuraciones de flag durante la codificación vs. la decodificación, probablemente haya un error en algún lugar.

A continuación se presenta una discusión detallada de estos flags. Nota que un conjunto de códigos es simplemente un conjunto abstracto de pares de código de carácter, mientras que una codificación toma esos números de código y los *codifica*, en nuestro caso a octetos. Unicode es (entre otros) un conjunto de códigos, UTF-8 es una codificación, y ISO-8859-1 (= latin 1) y ASCII son ambos conjuntos de códigos y codificaciones simultáneamente, lo que puede ser confuso.

"utf8" flag disabled
Cuando "utf8" está deshabilitado (por defecto), "encode"/"decode" generan y esperan strings Unicode, es decir, los caracteres con valores ordinales altos (> 255) se codifican así, y también se decodifican como tales, sin cambios, excepto por la "(re-)interpretación" de ellos como puntos de código Unicode o caracteres Unicode respectivamente (para Perl, estos son lo mismo, a menos que hagas algo curioso/extraño/impresionante).

Esto es útil cuando quieres hacer la codificación tú mismo (por ejemplo, cuando quieres tener texto JSON codificado en UTF-16) o cuando otra capa hace la codificación por ti (por ejemplo, al imprimir a una terminal usando un archivo que codifica transparentemente a UTF-8, no quieres codificar tus datos primero como UTF-8 y luego codificarlo de nuevo por Perl).

Cuando "utf8" está habilitado, "encode"/"decode" codificarán todos los caracteres usando la secuencia de múltiples bytes UTF-8 correspondiente, y esperan que tus cadenas de entrada estén codificadas como UTF-8, es decir, ningún carácter de la cadena de entrada debe tener un valor > 255, ya que UTF-8 no lo permite.

El flag "utf8" se comporta así entre dos modos: deshabilitado significa que obtendrás una cadena Unicode en Perl, habilitado significa que obtendrás una cadena UTF-8 codificada en octetos/binaria en Perl.

Cuando se habilitan los flags "latin1" o "ascii", "encode" escapa los caracteres con valores ordinales > 255 (> 127 con "ascii") y codifica los caracteres restantes según el flag "utf8".

Si "utf8" está deshabilitado, el resultado también se codificará correctamente en esos conjuntos de códigos (ya que ambos son subconjuntos válidos de Unicode, por lo que una cadena Unicode con todos los valores de carácter < 256 es lo mismo que una cadena ISO-8859-1, y una cadena Unicode con todos los valores de carácter < 128 es lo mismo que una cadena ASCII en Perl).
