DESCRIPCIÓ

N

La familia de funciones Judy soporta arrays totalmente dinámicos. Estos arrays pueden ser indexados por una palabra de 32 o 64 bits (dependiendo del tamaño de la palabra del procesador), una cadena terminada en nulo o un arreglo de bytes más longitud. Un array dinámico (poblado de forma dispersa) también puede ser pensado como una función de asignación o memoria asoci

ativa.

Un Word_t es un typedef unsigned long int en Judy.h y debe ser del mismo tamaño que sizeof(void *) es decir, un

puntero.

Funciones Judy1: El Índice es un Word_t y el Valor es simplemente un bit o simplemente una bandera que indica si el Índice está presente o ausente del array. Esto puede ser pensado como un enorme mapa de

bits.

Funciones JudyL: El Índice es un Word_t y el Valor es un Word_t. Esto hace que JudyL sea un asignador puro de palabra a palabra/puntero. JudySL y JudyHL se basan en esta propiedad de JudyL

.

Funciones JudySL: El Índice es una cadena terminada en nulo y el Valor es un Word_t

.

Funciones JudyHS: El Índice es un arreglo de bytes de longitud: Length. El Valor es un Word_t. Esta nueva adición (Mayo 2004) a Judy es un híbrido que usa las mejores características de los métodos de hashing y Judy. El autor cree que JudyHS es un buen reemplazo para un método de hashing cuando el redimensionamiento de la tabla hash se realiza durante el crecimiento de la población. Un método de hashing correctamente ajustado con un tamaño de tabla hash estático y población es insuperable en velocidad. Sin embargo, JudyHS funcionará mejor que un método de hashing con poblaciones más pequeñas y más grandes que el tamaño óptimo de la tabla hash. JudyHS no tiene un caso de rendimiento degenerado donde el conocimiento del algoritmo de hashing pueda ser explotado. (Es decir, JudyHS no usa una lista enlazada para manejar colisiones de hash, usa un árbol de arrays JudyL y un tamaño de tabla hash virtual de 4 mil millones)

.

Los arrays Judy son tanto rápidos como eficientes en memoria, sin necesidad de ajustes o configuración, a través de una amplia gama de tipos de conjuntos de índices (secuenciales, periódicos, agrupados, aleatorios). La velocidad y el uso de memoria de Judy son típicamente mejores que otros modelos de almacenamiento de datos como skiplists, listas enlazadas, binarios, ternarios, b-trees, o incluso hashing, y mejoran con conjuntos de datos muy

grandes.

Un array Judy se crea simplemente definiendo un puntero nulo y luego almacenando (insertando) el primer elemento en el array bajo ese puntero. La memoria usada por un array Judy es casi proporcional a la población (número de elementos)

.

Judy tiene dos Interfaces de Programación de Aplicaciones (APIs): una interfaz de macros C, y una interfaz de llamadas a funciones. Debido a que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de usar las funciones

Judy.

Dado que un array Judy inicial (vacío) está representado por un puntero nulo, es posible construir un array de arrays Judy. En otras palabras, los Valores de un array Judy (excepto Judy1) pueden ser punteros a otros arrays Judy. Esto hace que sea muy simple construir un array con un número arbitrario de dimensiones o tamaños de Índice. (JudySL y JudyHS se

implementan usando J
udyL de esta manera).

ERRORE

S

Se dedicó mucho pensamiento (y tiempo) a hacer que el manejo de errores en Judy fuera simple, manteniendo flexibilidad y capacidad. El manejo de errores es un tema muy aburrido incluso para escribir. Así que lea esta sección corta y use el segundo método recomendado. Genera el código más rápido, usa la menor cantidad de memoria y requiere que escriba código adicional solo para las funciones de inserción/borrado. Además es compatible con los otros dos métodos. Este método es para código de producción que puede querer manejar fallos de malloc() de manera diferente a la predeterminada de Judy. Si el método predeterminado de Judy para manejar fallos de malloc() es aceptable, entonces use el primer

método.

Hay dos (2) categorías de retornos de error de Judy (o para cualquier ADT dinámico)

:

1) Errores de programación del usuario (bugs) como corrupción de memoria o punteros inválidos.
2) Memoria agotada (fallo de malloc()) con Insertar (Set) o Eliminar (Unset) al modificar un array Judy. No todas las llamadas a insertar y eliminar llaman a malloc(), así que pueden tener éxito incluso cuando una llamada a malloc() fallaría.

Hay aproximadamente tres (3) métodos para manejar erro

res cuando se
usan las macros:

1) Método de Manejo de Errores

Predeterminado

El predeterminado es imprimir mensajes de error en stderr, por

ejemplo: 
File 'YourCfile.c', line 1234: JudyLIns(), JU_ERRNO_* == 2, ID ==
321 Esto indica que ocurrió un error en la función JudyLIns() en la línea 321. La línea 1234 es la línea en 'YourCfile.c' donde la llamada JLI() falló. JU_ERRNO_* == 2 es igual a JU_ERRNO_NOMEM (como está definido en el archivo Judy.h). El número ID indica el número de línea de origen en la función donde se originó el error. Su programa entonces termina con un exit(1);. Por defecto, ambas categorías de retornos de error de Judy se imprimen de esta manera. (El 'ID == 321' es para los obstinados que quieren más detalle o para depurar el propio Judy.)

2) Deshabilitar el Manejo de Errores de

Macro

Cuando su programa está "libre de bugs", los únicos errores devueltos deberían ser fallos de malloc(). Por lo tanto, todos los retornos de error pueden ser tratados como un fallo de malloc(). Usando el siguiente #define, toda la prueba e impresión de errores se desactiva. Se necesita agregar código adicional al código que puede tener fallos de malloc(). Judy fue diseñado para dejar los mismos datos en el array antes de la llamada si un fallo de malloc() ocurre. (Durante las pruebas de Judy, encontramos muy pocos malloc()/sistemas operativos que estaban libres de bugs después de un fallo de malloc(). A veces tomó semanas para descubrirlo porque la mayoría de los sistemas entran en un frenesí de paginación antes de agotar la memoria)

. 
#define JUDYERROR_NOTEST 1
(en su código de programa), o 
cc -DJUDYERROR_NOTEST sourcefile -lJudy
(en su línea de comandos). 
// Este es un ejemplo de cómo programar umétodo de llamada dos (2).
JLI(PValue, PLArray, Index);
if (PValue == PJERR) ir a out_of_memory_handling;
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) ir a out_of_memory_handling;
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) ir a out_of_memory_handling;
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) ir a out_of_memory_handling;
Nota: Sin 'JUDYERROR_NOTEST' definido, el 'goto out_of_memory_handling' nunca se ejecutará y será optimizado por el compilador. El método predeterminado se usará -- la Macro imprimirá información de error si ocurre un error, como se explicó anteriormente.

Con 'JUDYERROR_NOTEST' definido, el 'goto out_of_memory_handling' se ejecutará cuando ocurra un error -- lo cual solo debería suceder cuando malloc() falla.

3) Método de Macro JUDYERROR() Especificado por el Usuario

La macro JUDYERROR() (en Judy.h) proporciona flexibilidad para manejar los códigos de retorno de error según sea necesario para adaptarse a su programa, mientras sigue utilizando las macros de matriz Judy en lugar de llamadas a funciones. Puede usar una macro JUDYERROR() diferente para satisfacer sus necesidades. El siguiente ejemplo es una posible alternativa a la predeterminada. Se utiliza para distinguir entre los dos tipos de errores (descritos anteriormente) y comprobar explícitamente los errores JU_ERRNO_NOMEM restantes posibles en su programa.

// Este es un ejemplo de la API de macros de Judy para continuar cuando no hay memoria
// e imprimir y salir(1) cuando ocurre cualquier otro error.
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // necesario para fprintf()
// Esta es la macro que las APIs de macros de Judy usan para los códigos de retorno de -1:
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un fallo de malloc() */         \
    {                                                                     \
        (void) fprintf(stderr, "Archivo '%s', línea %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST no está definido
Esta macro de manejo de errores debe incluirse antes de la declaración #include <Judy.h> en su programa.
