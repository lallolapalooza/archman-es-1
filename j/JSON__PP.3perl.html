JSON::PP(3perl) Guía de Referencia del Programador de Perl JSON::PP(3perl)

NOMBRE

JSON::PP - Módulo puramente en Perl compatible con JSON::XS.

SINOPSIS

use JSON::PP;
# funciones exportadas, fallan al error
# y esperan/generan UTF-8
$texto_json_codificado = encode_json $referencia_hash_o_array_perl;
$referencia_hash_o_array_perl = decode_json $texto_json_codificado;
# Interfaz OO
$json = JSON::PP->new->ascii->pretty->allow_nonref;

$texto_json_formateado = $json->encode( $escalar_perl );
$escalar_perl = $json->decode( $texto_json );

# Nota que JSON versión 2.0 y superior usarán automáticamente
# JSON::XS o JSON::PP, así que deberías poder simplemente:

use JSON;

DESCRIPCIÓN

JSON::PP es un decodificador/codificador JSON puramente en Perl, y (casi) compatible con el mucho más rápido JSON::XS escrito por Marc Lehmann en C. JSON::PP funciona como un módulo de respaldo cuando usas el módulo JSON sin haber instalado JSON::XS.

Debido a esta característica de respaldo de JSON.pm, JSON::PP intenta no ser más amigable con JavaScript que JSON::XS (es decir, no escapar caracteres extra como U+2028 y U+2029, etc.), para que no pierdas esa amigabilidad con JavaScript silenciosamente cuando usas JSON.pm e instalas JSON::XS por velocidad o por accidente. Si necesitas un módulo puramente en Perl compatible con RFC7159 y amigable con JavaScript, prueba JSON::Tiny, que deriva del framework web Mojolicious y es también más pequeño y rápido que JSON::PP.

JSON::PP ha estado en el núcleo de Perl desde Perl 5.14, principalmente para que los módulos de la toolchain de CPAN analicen META.json.

INTERFAZ FUNCIONAL

Esta sección se toma casi textualmente de JSON::XS. "encode_json" y "decode_json" se exportan por defecto.

encode_json

$texto_json = encode_json $escalar_perl

Convierte la estructura de datos Perl dada a una cadena binaria codificada en UTF-8 (es decir, la cadena contiene solo octetos). Falla si hay un error.

Esta llamada a función es funcionalmente idéntica a:

$texto_json = JSON::PP->new->utf8->encode($escalar_perl)

Excepto por ser más rápida.

decode_json

$escalar_perl = decode_json $texto_json

Lo opuesto a "encode_json": espera una cadena UTF-8 (binaria) y trata de analizarla como texto JSON codificado en UTF-8, devolviendo la referencia resultante. Falla si hay un error.

Esta llamada a función es funcionalmente idéntica a:

$escalar_perl = JSON::PP->new->utf8->decode($texto_json)

Excepto por ser más rápida.

JSON::PP::is_bool

$es_booleano = JSON::PP::is_bool($escalar)

Devuelve verdadero si el escalar pasado representa JSON::PP::true o JSON::PP::false, dos constantes que actúan como 1 y 0 respectivamente y también se usan para representar "true" y "false" de JSON en cadenas Perl.

En perl 5.36 y superior, también devolverá verdadero cuando se le dé uno de los valores booleanos estándar de perl, como el resultado de una comparación.

Ver MAPPING, abajo, para más información sobre cómo se mapean los valores JSON a Perl.

INTERFAZ ORIENTADA A OBJETOS

Esta sección también se toma de JSON::XS.

La interfaz orientada a objetos te permite configurar tu propio estilo de codificación o decodificación, dentro de los límites de los formatos soportados.

new

$json = JSON::PP->new

Crea un nuevo objeto JSON::PP que puede ser usado para decodificar/codificar cadenas JSON. Todas las banderas booleanas descritas abajo están por defecto deshabilitadas (con la excepción de "allow_nonref", que por defecto está habilitada desde la versión 4.0).

Los mutadores para las banderas devuelven el objeto JSON::PP de nuevo y por lo tanto las llamadas pueden encadenarse:

my $json = JSON::PP->new->utf8->space_after->encode({a => [1,2]})
=> {"a": [1, 2]}

ascii

$json = $json->ascii([$habilitar])

$habilitado = $json->get_ascii

Si $habilitar es verdadero (o ausente), entonces el método "encode" no generará caracteres fuera del rango de código 0..127 (que es ASCII). Cualquier carácter Unicode fuera de ese rango será escapado usando ya sea un simple \uXXXX (caracteres BMP) o una secuencia de escape doble \uHHHH\uLLLLL, según RFC4627. El texto JSON codificado resultante puede ser tratado como una cadena Unicode nativa, una cadena codificada en ASCII, codificada en latin1 o codificada en UTF-8, o cualquier otro superconjunto de ASCII.

Si $habilitar es falso, entonces el método "encode" no escapará caracteres Unicode a menos que sea requerido por la sintaxis JSON u otras banderas. Esto resulta en un formato más rápido y compacto.

Ver también la sección NOTAS SOBRE LAS BANDERAS DE CODIFICACIÓN/JUEGO DE CARACTERES más adelante en este documento.

El uso principal de esta bandera es producir textos JSON que puedan ser transmitidos a través de un canal de 7 bits, ya que los textos JSON codificados no contendrán caracteres de 8 bits.

JSON::PP->new->ascii(1)->encode([chr 0x10401])
=> ["\ud801\udc01"]

latin1

$json = $json->latin1([$habilitar])

$habilitado = $json->get_latin1

Si $habilitar es verdadero (o ausente), entonces el método "encode" codificará el texto JSON resultante como latin1 (o iso-8859-1), escapando cualquier carácter fuera del rango de código 0..255. La cadena resultante puede ser tratada como un texto JSON codificado en latin1 o una cadena Unicode nativa. El método "decode" no se verá afectado de ninguna manera por esta bandera, ya que "decode" por defecto espera Unicode, que es un superconjunto estricto de latin1.

Si $habilitar es falso, entonces el método "encode" no escapará caracteres Unicode a menos que sea requerido por la sintaxis JSON u otras banderas.

Ver también la sección NOTAS SOBRE LAS BANDERAS DE CODIFICACIÓN/JUEGO DE CARACTERES más adelante en este documento.

El uso principal de esta bandera es codificar eficientemente datos binarios como texto JSON, ya que la mayoría de los octetos no serán escapados, resultando en un tamaño codificado menor. La desventaja es que el texto JSON resultante está codificado en latin1 (y debe ser tratado correctamente como tal al almacenar y transferir), una codificación rara para JSON. Por lo tanto, es más útil cuando deseas almacenar estructuras de datos que se sabe que contienen datos binarios de manera eficiente en archivos o bases de datos, no cuando te comunicas con otros codificadores/decodificadores JSON.

JSON::PP->new->latin1->encode (["\x{89}\x{abc}"]
=> ["\x{89}\\u0abc"]    # (sintaxis perl, U+abc escapado, U+89 no)

utf8

$json = $json->utf8([$habilitar])

$habilitado = $json->get_utf8

Si $habilitar es verdadero (o ausente), entonces el método "encode" codificará el resultado JSON en UTF-8, como lo requieren muchos protocolos, mientras que el método "decode" espera recibir una cadena codificada en UTF-8. Ten en cuenta que las cadenas codificadas en UTF-8 no contienen caracteres fuera del rango 0..255, por lo tanto, son útiles para E/S de bytes/binarias. En versiones futuras, habilitar esta opción podría habilitar la autodetección de las familias de codificación UTF-16 y UTF-32, como se describe en RFC4627.

Si $habilitar es falso, entonces el método "encode" devolverá la cadena JSON como una cadena Unicode (no codificada), mientras que "decode" espera una cadena Unicode. Cualquier decodificación o codificación (por ejemplo, a UTF-8 o UTF-16) debe ser hecha por ti mismo, por ejemplo, usando el módulo Encode.

Ver también la sección NOTAS SOBRE LAS BANDERAS DE CODIFICACIÓN/JUEGO DE CARACTERES más adelante en este documento.

Ejemplo, salida JSON codificado en UTF-16BE:

use Encode;
$texto_json = encode "UTF-16BE"

space_after

$json = $json->space_after([$enable])

$enabled = $json->get_space_after

Si $enable es verdadero (o ausente), entonces el método "encode" generará un espacio después de los dos puntos y las comas que separan los elementos de un objeto o array. Esto genera un texto JSON más legible, pero ligeramente más grande.

Si $enable es falso, entonces no se generarán espacios adicionales, resultando en un texto JSON más compacto.

JSON::PP->new->space_after->encode([1,{"a"=>2}])
=> [1, {"a": 2}]
JSON::PP->new->encode([1,{"a"=>2}])
=> [1,{"a":2}]

space_before

$json = $json->space_before([$enable])

$enabled = $json->get_space_before

Si $enable es verdadero (o ausente), entonces el método "encode" generará un espacio antes de los dos puntos que separan las claves de los valores en un objeto JSON. Esto genera un texto JSON más legible, pero ligeramente más grande.

Si $enable es falso, entonces no se generará espacio adicional, resultando en un texto JSON más compacto.

JSON::PP->new->space_before->encode({"a"=>1})
=> {"a" : 1}
JSON::PP->new->encode({"a"=>1})
=> {"a":1}

allow_nonref

$json = $json->allow_nonref([$enable])

$enabled = $json->get_allow_nonref

Si $enable es verdadero (o ausente), entonces el método "encode" aceptará escalares Perl que no sean referencias (es decir, un número, una cadena, un booleano, etc.) como la estructura de datos superior. El resultado de la codificación será el valor JSON correspondiente.

Si $enable es falso, entonces el método "encode" requiere que la estructura de datos superior sea una referencia (un hash, un array, un escalar codificado, etc.). Si se pasa un escalar no referenciado, se producirá un error (croak).

Esta bandera está habilitada por defecto desde la versión 4.0.

JSON::PP->new->allow_nonref->encode(123)
=> 123
JSON::PP->new->allow_nonref->encode("hello")
=> "hello"
JSON::PP->new->allow_nonref->encode(undef)
=> null
JSON::PP->new->encode(123)
# ... croaks en error: not a reference

allow_unknown

$json = $json->allow_unknown([$enable])

$enabled = $json->get_allow_unknown

Si $enable es verdadero (o ausente), entonces el método "decode" aceptará estructuras de datos Perl desconocidas (por ejemplo, código Perl dentro de una cadena, que se evalúa como código Perl). Esto es una característica de seguridad y puede ser muy peligroso.

Si $enable es falso, entonces el método "decode" no permitirá este tipo de estructuras de datos, y se producirá un error.

JSON::PP->new->allow_unknown->decode(q{"\e[System])"})
=> ... # lo que sea que evalúe q{'[System]'})

allow_fragile

$json = $json->allow_fragile([$enable])

$enabled = $json->get_allow_fragile

Si $enable es verdadero (o ausente), entonces el método "decode" aceptará JSON que no cumpla estrictamente con las especificaciones JSON (por ejemplo, permitirá números sin comillas, cadenas sin comillas, etc.).

Si $enable es falso, entonces el método "decode" requerirá que la entrada cumpla estrictamente con la especificación JSON. Si la entrada no es válida, se producirá un error.

canonical

$json = $json->canonical([$enable])

$enabled = $json->get_canonical

Si $enable es verdadero (o ausente), entonces el método "encode" generará un texto JSON canónico. Esto significa que las claves de los objetos se ordenarán alfabéticamente, y se evitarán los espacios en blanco innecesarios.

Si $enable es falso, entonces el método "encode" no garantizará un formato canónico. Las claves de los objetos se codificarán en el orden en que se encuentren en el hash de Perl, y se aplicarán las banderas de espaciado según corresponda.

my $hash = {b => 2, a => 1};
JSON::PP->new->canonical->encode($hash)
=> {"a":1,"b":2}
JSON::PP->new->encode($hash)
=> {"b":2,"a":1}

pretty

$json = $json->pretty([$enable])

$enabled = $json->get_pretty

Si $enable es verdadero (o ausente), entonces el método "encode" generará un texto JSON formateado con indentación y saltos de línea para mejorar la legibilidad. Esto es funcionalmente equivalente a habilitar "space_after" y "space_before", y añadir indentación a los niveles anidados.

Si $enable es falso, entonces el método "encode" generará un texto JSON compacto, sin formato adicional para legibilidad.

my $data = {a => [1, 2], b => {c => 3}};
JSON::PP->new->pretty->encode($data)
=> {
   "a": [
      1,
      2
   ],
   "b": {
      "c": 3
   }
}
JSON::PP->new->encode($data)
=> {"a":[1,2],"b":{"c":3}}

indent

$json = $json->indent($string)

$string = $json->get_indent

Establece la cadena de indentación que se usará cuando se habilite la bandera "pretty". Por defecto, es un espacio.

JSON::PP->new->pretty->indent("\t")->encode({a=>[1]})
=> {
    "a": [
        1
    ]
}

encode

$json_text = $json->encode( $perl_scalar )

Codifica la estructura de datos Perl dada en una cadena JSON. La salida será binaria si la bandera utf8 está habilitada, de lo contrario será una cadena Unicode.

decode

$perl_scalar = $json->decode( $json_text )

Decodifica la cadena JSON dada en una estructura de datos Perl. Si la bandera utf8 está habilitada, la entrada se espera como UTF-8 binario; de lo contrario, se espera como una cadena Unicode.

CODING/CODESET FLAG NOTES

Las banderas ascii, latin1 y utf8 controlan la forma en que JSON::PP maneja la codificación de caracteres al codificar y decodificar.

Cuando utf8 está habilitado (que es el comportamiento predeterminado en la interfaz funcional y en la interfaz OO si no se especifica lo contrario), tanto la codificación como la decodificación trabajan con cadenas binarias codificadas en UTF-8.

Cuando utf8 está deshabilitado, el módulo espera y produce cadenas Unicode nativas. Esto significa que si necesitas trabajar con datos que no están en UTF-8 (por ejemplo, datos de entrada de un archivo que no está en UTF-8), debes decodificarlos manualmente a Unicode antes de pasarlos a decode, y codificarlos manualmente desde Unicode a la codificación deseada después de obtener la salida de encode.

La bandera ascii hace que todos los caracteres no ASCII se escapen como secuencias \uXXXX. Esto es útil para la transmisión a través de canales que solo admiten ASCII.

La bandera latin1 hace que la salida sea una cadena codificada en latin1. Esto es eficiente para datos binarios pero menos común para el intercambio JSON.

La elección correcta de estas banderas depende de tus necesidades específicas de I/O y del formato esperado por el sistema con el que te intercambias.

MAPPING

JSON::PP mapea los tipos de datos JSON a tipos de datos Perl de la siguiente manera:

Objeto JSON
Se mapea a una referencia a un hash de Perl. Las claves de los objetos JSON deben ser cadenas. Estas se conservan como cadenas en Perl.
Array JSON
Se mapea a una referencia a un array de Perl.
Cadena JSON
Se mapea a una cadena escalar de Perl. Las cadenas JSON se manejan como Unicode internamente.
Número JSON
Se mapea a un número escalar de Perl (entero o de punto flotante según sea apropiado).
Valor JSON true
Se mapea a la constante JSON::PP::true.
Valor JSON false
Se mapea a la constante JSON::PP::false.
Valor JSON null
Se mapea al valor escalar undef de Perl.

Las constantes JSON::PP::true y JSON::PP::false actúan como 1 y 0 respectivamente, permitiendo su uso en contextos numéricos y booleanos.

Para la codificación, se aplican las siguientes reglas inversas:

Referencia a hash de Perl
Se codifica como un objeto JSON. Las claves del hash deben ser cadenas; de lo contrario, se producirá un error.
Referencia a array de Perl
Se codifica como un array JSON.
Cadena escalar de Perl
Se codifica como una cadena JSON. Si la bandera utf8 está deshabilitada, y la cadena contiene caracteres no ASCII, se debe codificar manualmente a UTF-8 antes de pasarla a encode, o se producirá un error.
Número escalar de Perl
Se codifica como un número JSON.
Constante JSON::PP::true
Se codifica como el valor JSON true.
Constante JSON::PP::false
Se codifica como el valor JSON false.
Valor escalar undef de Perl
Se codifica como el valor JSON null.

Otros tipos escalares de Perl (como referencias a código, etc.) generalmente no se pueden codificar y producirán un error a menos que se deshabilite el chequeo de tipos o se implemente un manejador personalizado (que no es soportado directamente por JSON::PP).

El

TO_JSON

$json = $json->convert_blessed([$enable])
$enabled = $json->get_convert_blessed

If $enable is true (or missing), then "encode", when it encounters a blessed object, will check for the availability of the "TO_JSON" method on the object's class. If found, it will be called and its return value will be used as the JSON representation of the object.

The "TO_JSON" method may safely call die if it wants. If "TO_JSON" returns other blessed objects, those will be handled in the same way. "TO_JSON" must take care of not causing an endless recursion cycle (== crash) in this case. The name of "TO_JSON" was chosen because other methods called by the Perl core (== not by the user of the object) are usually in upper case letters and to avoid collisions with any "to_json" function or method.

If $enable is false (the default), then "encode" will not consider this type of conversion.

This setting has no effect on "decode".

allow_tags

$json = $json->allow_tags([$enable])
$enabled = $json->get_allow_tags

See "OBJECT SERIALISATION" for details.

If $enable is true (or missing), then "encode", upon encountering a blessed object, will check for the availability of the "FREEZE" method on the object's class. If found, it will be used to serialise the object into a nonstandard tagged JSON value (that JSON decoders cannot decode).

It also causes "decode" to parse such tagged JSON values and deserialise them via a call to the "THAW" method.

If $enable is false (the default), then "encode" will not consider this type of conversion, and tagged JSON values will cause a parse error in "decode", as if tags were not part of the grammar.

boolean_values

$json->boolean_values([$false, $true])
($false,  $true) = $json->get_boolean_values

By default, JSON booleans will be decoded as overloaded $JSON::PP::false and $JSON::PP::true objects.

With this method you can specify your own boolean values for decoding - on decode, JSON "false" will be decoded as a copy of $false, and JSON "true" will be decoded as $true ("copy" here is the same thing as assigning a value to another variable, i.e. "$copy = $false").

This is useful when you want to pass a decoded data structure directly to other serialisers like YAML, Data::MessagePack and so on.

Note that this works only when you "decode". You can set incompatible boolean objects (like boolean), but when you "encode" a data structure with such boolean objects, you still need to enable "convert_blessed" (and add a "TO_JSON" method if necessary).

Calling this method without any arguments will reset the booleans to their default values.

"get_boolean_values" will return both $false and $true values, or the empty list when they are set to the default.

core_bools

$json->core_bools([$enable]);

If $enable is true (or missing), then "decode", will produce standard perl boolean values. Equivalent to calling:

$json->boolean_values(!!1, !!0)

"get_core_bools" will return true if this has been set. On perl 5.36, it will also return true if the boolean values have been set to perl's core booleans using the "boolean_values" method.

The methods "unblessed_bool" and "get_unblessed_bool" are provided as aliases for compatibility with Cpanel::JSON::XS.

filter_json_object

$json = $json->filter_json_object([$coderef])

When $coderef is specified, it will be called from "decode" each time it decodes a JSON object. The only argument is a reference to the newly-created hash. If the code references returns a single scalar (which need not be a reference), this value (or rather a copy of it) is inserted into the deserialised data structure. If it returns an empty list (NOTE: not "undef", which is a valid scalar), the original deserialised hash will be inserted. This setting can slow down decoding considerably.

When $coderef is omitted or undefined, any existing callback will be removed and "decode" will not change the deserialised hash in any way.

Example, convert all JSON objects into the integer 5:

my $js = JSON::PP->new->filter_json_object(sub { 5 });
# returns [5]
$js->decode('[{}]');
# returns 5
$js->decode('{"a":1, "b":2}');

filter_json_single_key_object

$json = $json->filter_json_single_key_object($key [=> $coderef])

Works remotely similar to "filter_json_object", but is only called for JSON objects having a single key named $key.

This $coderef is called before the one specified via "filter_json_object", if any. It gets passed the single value in the JSON object. If it returns a single value, it will be inserted into the data structure. If it returns nothing (not even "undef" but the empty list), the callback from "filter_json_object" will be called next, as if no single-key callback were specified.

If $coderef is omitted or undefined, the corresponding callback will be disabled. There can only ever be one callback for a given key.

As this callback gets called less often then the "filter_json_object" one, decoding speed will not usually suffer as much. Therefore, single-key objects make excellent targets to serialise Perl objects into, especially as single-key JSON objects are as close to the type-tagged value concept as JSON gets (it's basically an ID/VALUE tuple). Of course, JSON does not support this in any way, so you need to make sure your data never looks like a serialised Perl hash.

Typical names for the single object key are "__class_whatever__", or "$__dollars_are_rarely_used__$" or "}ugly_brace_placement", or even things like "__class_md5sum(classname)__", to reduce the risk of clashing with real hashes.

JSON::PP

max_depth

$json = $json->max_depth([$maximum_nesting_depth])

$max_depth = $json->get_max_depth

Sets the maximum nesting level (default 512) accepted while encoding or decoding. If a higher nesting level is detected in JSON text or a Perl data structure, then the encoder and decoder will stop and croak at that point.

Nesting level is defined by number of hash- or arrayrefs that the encoder needs to traverse to reach a given point or the number of "{" or "[" characters without their matching closing parenthesis crossed to reach a given character in a string.

Setting the maximum depth to one disallows any nesting, so that ensures that the object is only a single hash/object or array.

If no argument is given, the highest possible setting will be used, which is rarely useful.

See "SECURITY CONSIDERATIONS" in JSON::XS for more info on why this is useful.

If no argument is given, the limit check will be deactivated (same as when 0 is specified).

Los escalares simples de Perl (cualquier escalar que no sea una referencia) son los objetos más difíciles de codificar: JSON::PP codificará los escalares indefinidos como valores "null" JSON, los escalares que hayan sido usados por última vez en un contexto de cadena antes de la codificación como cadenas JSON, y cualquier otra cosa como valor numérico:

Puedes forzar el tipo a ser una cadena JSON convirtiéndola a cadena:

"$x";        # convertida a cadena

Puedes forzar el tipo a ser un número JSON convirtiéndolo a número:


my $x = "3"; # alguna variable que contiene una cadena
$x += 0;     # conviértelo a número, asegurando que se volcará como número
$x *= 1;     # lo mismo, la elección es tuya.



Actualmente no puedes forzar el tipo de otras maneras menos oscuras.


Desde la versión 2.91_01, JSON::PP utiliza una lógica de detección de números diferente que convierte un escalar que puede convertirse en un número de forma segura. La nueva lógica es ligeramente más rápida y tiende a ayudar a las personas que usan perls más antiguos o que desean codificar estructuras de datos complejas. Sin embargo, esto puede dar como resultado un texto JSON diferente al que codifica JSON::XS (y por lo tanto puede romper pruebas que comparan textos JSON completos). Si necesita el comportamiento anterior por compatibilidad o para un control más fino, establezca la variable de entorno PERL_JSON_PP_USE_B en verdadero antes de usar "use" JSON::PP (o JSON::pm).


Tenga en cuenta que la precisión numérica tiene el mismo significado que en Perl (por lo que la conversión de binario a decimal sigue las mismas reglas que en Perl, que pueden diferir de otros lenguajes). Además, su intérprete de perl puede exponer extensiones a los números de punto flotante de su plataforma, como infinitos o NaN, estos no se pueden representar en JSON y es un error pasarlos.


JSON::PP (y JSON::XS) confían en lo que usted pasa al método "encode" (o a la función "encode_json") como una estructura de datos limpia y validada con valores que solo pueden representarse como valores JSON válidos, porque no proviene de una fuente de datos externa (a diferencia de los textos JSON que usted pasa a "decode" o "decode_json", que JSON::PP considera contaminados y en los que no confía). Dado que JSON::PP no sabe exactamente qué quiere usted y los consumidores de sus textos JSON que sean los valores inesperados (es posible que desee convertirlos en nulos, o convertirlos a cadenas con o sin normalización (la representación de cadenas de infinitos/NaN puede variar según las plataformas), o fallar sin conversión), le recomendamos que haga lo que usted y sus consumidores necesiten antes de codificar, y que tampoco convierta a números valores que puedan comenzar con valores que parezcan un número (incluidos infinitos/NaN), sin validar.

SERIALIZACIÓN DE OBJETOS

Como JSON no puede representar objetos Perl directamente, debe elegir entre una representación JSON pura (sin la capacidad de deserializar el objeto automáticamente de nuevo) y una extensión no estándar de la sintaxis JSON, los valores etiquetados.

SERIALIZACIÓN

Lo que sucede cuando "JSON::PP" encuentra un objeto Perl depende de las configuraciones "allow_blessed", "convert_blessed", "allow_tags" y "allow_bignum", que se usan en este orden:

1. Se habilita "allow_tags" y el objeto tiene un método "FREEZE".
En este caso, "JSON::PP" crea un valor JSON etiquetado, utilizando una extensión no estándar de la sintaxis JSON.

Esto funciona invocando el método "FREEZE" en el objeto, con el primer argumento siendo el objeto a serializar, y el segundo argumento siendo la cadena constante "JSON" para distinguirlo de otros serializadores.

El método "FREEZE" puede devolver cualquier número de valores (es decir, cero o más). Estos valores y el nombre del paquete/clase del objeto se codificarán como un valor JSON etiquetado en el siguiente formato:

("nombre_clase")[valores_retornados_por_FREEZE...]

por ejemplo:

("URI")["http://www.google.com/"]
("MiFecha")[2013,10,29]
("ImagenData::JPEG")["Z3...VlCg=="]

Por ejemplo, el método hipotético "FREEZE" de "Mi::Objeto" podría usar los miembros "tipo" e "id" del objeto para codificar el objeto:

sub Mi::Objeto::FREEZE {
   my ($self, $serializador) = @_;
   ($self->{tipo}, $self->{id})
}
2. Se habilita "convert_blessed" y el objeto tiene un método "TO_JSON".
En este caso, se invoca el método "TO_JSON" del objeto en contexto escalar. Debe devolver un único escalar que pueda codificarse directamente en JSON. Este escalar reemplaza al objeto en el texto JSON.

Por ejemplo, el siguiente método "TO_JSON" convertirá todos los objetos URI a cadenas JSON cuando se serialicen. El hecho de que estos valores fueran originalmente objetos URI se pierde.

sub URI::TO_JSON {
   my ($uri) = @_;
   $uri->as_string
}
3. Se habilita "allow_bignum" y el objeto es un "Math::BigInt" o "Math::BigFloat".
El objeto se serializará como un valor numérico JSON.
4. Se habilita "allow_blessed".
El objeto se serializará como un valor nulo JSON.
5. Ninguna de las anteriores
Si ninguna de las configuraciones está habilitada o faltan los métodos respectivos, "JSON::PP" lanza una excepción.

DESERIALIZACIÓN

Para la deserialización, solo hay dos casos a considerar: o se utilizó etiquetado no estándar, en cuyo caso "allow_tags" decide, o los objetos no se pueden deserializar automáticamente, en cuyo caso puede usar postprocesamiento o las devoluciones de llamada "filter_json_object" o "filter_json_single_key_object" para obtener objetos reales de su JSON.

Esta sección solo considera el caso de valor etiquetado: se encuentra un objeto JSON etiquetado durante la decodificación y "allow_tags" está deshabilitado, se producirá un error de análisis (como si los valores etiquetados no fueran parte de la gramática).

Si "allow_tags" está habilitado, "JSON::PP" buscará el método "THAW" del paquete/nombre de clase utilizado durante la serialización (no intentará cargar el paquete como un módulo Perl). Si no existe dicho método, la decodificación fallará con un error.

De lo contrario, se invoca el método "THAW" con el nombre de la clase como primer argumento, la cadena constante "JSON" como segundo argumento, y todos los valores de la matriz JSON (los valores devueltos originalmente por el método "FREEZE") como argumentos restantes.

El método debe devolver el objeto. Aunque técnicamente puede devolver cualquier escalar de Perl, es posible que deba habilitar la configuración "allow_nonref" para que esto funcione en todos los casos, por lo que es mejor devolver una referencia bendecida real.

Como ejemplo, implementemos una función "THAW" que regenere el "Mi::Objeto" del ejemplo anterior de "FREEZE":

sub Mi::Objeto::THAW {
   my ($clase, $serializador, $tipo, $id) = @_;
   $clase->new (tipo => $tipo, id => $id)
}

NOTAS SOBRE LAS BANDERA DE CODIFICACIÓN/CÓDIGOS

Esta sección está tomada de JSON::XS.

El lector interesado puede haber visto una serie de banderas que significan codificaciones o juegos de caracteres: "utf8", "latin1" y "ascii". Parece haber cierta confusión sobre lo que hacen, así que aquí hay una breve comparación:

"utf8" controla si el texto JSON creado por "encode" (y esperado por "decode") está codificado en UTF-8 o no, mientras que "latin1" y "ascii" solo controlan si "encode" escapa los valores de caracteres fuera de su respectivo rango de códigos. Ninguna de estas banderas entra en conflicto entre sí, aunque algunas combinaciones tienen menos sentido que otras.

Se ha tenido cuidado para hacer que todas las banderas sean simétricas con respecto a "encode" y "decode", es decir, los textos codificados con cualquier combinación de estos valores de bandera se decodificarán correctamente cuando se utilicen las mismas banderas; en general, si utiliza diferentes configuraciones de bandera al codificar frente a al decodificar, es probable que tenga un error en alguna parte.

A continuación, se presenta una discusión detallada de estas banderas. Tenga en cuenta que un "juego de caracteres" es simplemente un conjunto abstracto de pares de caracteres-puntos de código, mientras que una codificación toma esos números de puntos de código y los *codifica*, en nuestro caso en octetos. Unicode es (entre otras cosas) un juego de caracteres, UTF-8 es una codificación, e ISO-8859-1 (= latin 1) y ASCII son tanto juegos de caracteres como codificaciones al mismo tiempo, lo que puede ser confuso.

Bandera "utf8" deshabilitada
Cuando "utf8" está deshabilitada (por defecto), entonces "encode"/"decode" generan y esperan cadenas Unicode, es decir, los caracteres con valores Unicode altos (> 255) se codificarán como tales caracteres, y de manera similar, dichos caracteres se decodificarán tal cual, no se les harán cambios, excepto "(re-)interpretarlos" como puntos de código Unicode o caracteres Unicode, respectivamente (para Perl, estas son las mismas cosas en las cadenas a menos que hagas cosas raras/extrañas/tontas).

Esto es útil cuando desea hacer la codificación usted mismo (por ejemplo, cuando desea tener textos JSON codificados en UTF-16) o cuando alguna otra capa se encarga de la codificación por usted (por ejemplo, cuando la prioridad

El argumento opcional "encode" se puede llamar con las banderas "utf8", "latin1" y "ascii". Estas banderas son para controlar la forma en que se representan los caracteres que no se encuentran en el conjunto de caracteres básico de 7 bits.

"utf8" flag disabled (default)
With the "utf8" flag disabled (the default), you will get a Unicode string in Perl. The JSON encoder will encode this Unicode string into a UTF-8-encoded string. All characters will be represented using their Unicode code points.

Note that if you are printing to a terminal using a filehandle that transparently encodes to UTF-8 you certainly do NOT want to UTF-8 encode your data first and have Perl encode it another time).

"utf8" flag enabled
If the "utf8"-flag is enabled, "encode"/"decode" will encode all characters using the corresponding UTF-8 multi-byte sequence, and will expect your input strings to be encoded as UTF-8, that is, no "character" of the input string must have any value > 255, as UTF-8 does not allow that.

The "utf8" flag therefore switches between two modes: disabled means you will get a Unicode string in Perl, enabled means you get an UTF-8 encoded octet/binary string in Perl.

"latin1" or "ascii" flags enabled
With "latin1" (or "ascii") enabled, "encode" will escape characters with ordinal values > 255 (> 127 with "ascii") and encode the remaining characters as specified by the "utf8" flag.

If "utf8" is disabled, then the result is also correctly encoded in those character sets (as both are proper subsets of Unicode, meaning that a Unicode string with all character values < 256 is the same thing as a ISO-8859-1 string, and a Unicode string with all character values < 128 is the same thing as an ASCII string in Perl).

If "utf8" is enabled, you still get a correct UTF-8-encoded string, regardless of these flags, just some more characters will be escaped using "\uXXXX" then before.

Note that ISO-8859-1-encoded strings are not compatible with UTF-8 encoding, while ASCII-encoded strings are. That is because the ISO-8859-1 encoding is NOT a subset of UTF-8 (despite the ISO-8859-1 codeset being a subset of Unicode), while ASCII is.

Surprisingly, "decode" will ignore these flags and so treat all input values as governed by the "utf8" flag. If it is disabled, this allows you to decode ISO-8859-1- and ASCII-encoded strings, as both strict subsets of Unicode. If it is enabled, you can correctly decode UTF-8 encoded strings.

So neither "latin1" nor "ascii" are incompatible with the "utf8" flag - they only govern when the JSON output engine escapes a character or not.

The main use for "latin1" is to relatively efficiently store binary data as JSON, at the expense of breaking compatibility with most JSON decoders.

The main use for "ascii" is to force the output to not contain characters with values > 127, which means you can interpret the resulting string as UTF-8, ISO-8859-1, ASCII, KOI8-R or most about any character set and 8-bit-encoding, and still get the same data structure back. This is useful when your channel for JSON transfer is not 8-bit clean or the encoding might be mangled in between (e.g. in mail), and works because ASCII is a proper subset of most 8-bit and multibyte encodings in use in the world.
