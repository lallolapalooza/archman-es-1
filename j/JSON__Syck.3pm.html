JSON::Syck(3) Documentación de Perl contribuida por el usuario JSON::Syck(3)

NOMBRE

JSON::Syck - JSON es YAML (¡pero considera usar JSON::XS en su lugar!)

SINOPSIS

use JSON::Syck; # no exporta por defecto 
my $data = JSON::Syck::Load($json);
my $json = JSON::Syck::Dump($data);
# $file puede ser un objeto IO o un nombre de archivo
my $data = JSON::Syck::LoadFile($file);
JSON::Syck::DumpFile($file, $data);
# Volcar en un buffer preexistente
my $json;
JSON::Syck::DumpInto(\$json, $data);

DESCRIPCIÓN

JSON::Syck es una implementación de syck de análisis y generación de JSON. Dado que JSON es YAML (http://redhanded.hobix.com/inspect/yamlIsJson.html), usar syck te proporciona un analizador y volcador rápido y eficiente en memoria para la representación de datos JSON.

Sin embargo, desde entonces ha surgido un módulo más nuevo, JSON::XS. Es más flexible, eficiente y robusto, por lo que te pedimos que consideres usarlo en lugar de este módulo.

DIFERENCIA CON JSON

Es posible que desees conocer la diferencia entre el módulo JSON y este.

Dado que JSON es un módulo pure-perl y JSON::Syck se basa en libsyck, se supone que JSON::Syck es muy rápido y eficiente en memoria. Ver la tabla de benchmark de chansen en http://idisk.mac.com/christian.hansen/Public/perl/serialize.pl

JSON.pm viene con docenas de formas de hacer lo mismo y muchas opciones, mientras que JSON::Syck no. Solo hay "Load" y "Dump".

Ah, y JSON::Syck no usa nombres de métodos camelCase :-)

REFERENCIAS

REFERENCIA ESCALAR

Por ahora, cuando pasas una referencia escalar a JSON::Syck, se desreferencia para obtener el valor escalar real.

JSON::Syck genera una excepción cuando pasas referencias circulares.

Si deseas serializar elementos autorreferenciales, deberías usar YAML, que los admite.

REFERENCIA A SUBRUTINA

Cuando pasas una referencia a una subrutina, JSON::Syck la vuelca como null.

INDICADORES UTF-8

Por defecto, este módulo no toca ningún indicador utf-8 establecido en las cadenas, y asume que se pasan y emiten bytes UTF-8.

Sin embargo, cuando estableces $JSON::Syck::ImplicitUnicode a 1, este módulo decodifica correctamente binarios UTF-8 y establece el indicador UTF-8 en todas partes, como en:

JSON (bytes UTF-8)   => Perl (indicado UTF-8)
JSON (indicado UTF-8) => Perl (indicado UTF-8)
Perl (bytes UTF-8)   => JSON (indicado UTF-8)
Perl (indicado UTF-8) => JSON (indicado UTF-8)

Por defecto, JSON::Syck::Dump solo recorrerá hasta 512 niveles de una estructura de datos para evitar un bucle infinito cuando se le presenta una referencia circular.

Sin embargo, puedes establecer $JSON::Syck::MaxLevels a un valor mayor si tienes estructuras muy complejas.

Desafortunadamente, no hay una forma implícita de volcar datos estructurados de Perl con indicador UTF-8 a JSON codificado en utf-8. Para hacer esto, simplemente usa el módulo Encode, por ejemplo:

use Encode;
use JSON::Syck qw(Dump);
my $json = encode_utf8( Dump($data) );

Alternativamente, puedes usar Encode::JavaScript::UCS para codificar cadenas Unicode como en formato %uXXXX.

use Encode;
use Encode::JavaScript::UCS;
use JSON::Syck qw(Dump);
my $json_unicode_escaped = encode( 'JavaScript-UCS', Dump($data) );

COMILLAS

Según la especificación JSON, todas las cadenas JSON deben ir entre comillas dobles. Sin embargo, al incrustar JavaScript en atributos HTML, puede ser más conveniente usar comillas simples.

Establecer $JSON::Syck::SingleQuote a 1 hará que tanto "Dump" como "Load" esperen literales de cadena entre comillas simples.

ERRORES

Volcar en variables enlazadas (o otras variables mágicas) con "DumpInto" podría no funcionar correctamente en todos los casos.

Al volcar con "DumpFile", algunos espacios podrían ser incorrectos y $JSON::Syck::SingleQuote podría ser manejado incorrectamente.
