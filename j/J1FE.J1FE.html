DESCRIPCIÓ

N

La familia de funciones Judy soporta arreglos totalmente dinámicos. Estos arreglos pueden ser indexados por una palabra de 32 o 64 bits (dependiendo del tamaño de la palabra del procesador), una cadena terminada en nulo o un arreglo de bytes más longitud. Un arreglo dinámico (poblado de forma dispersa) también puede ser pensado como una función de asignación o memoria asoci

ativa.

Un Word_t es un typedef unsigned long int en Judy.h y debe ser del mismo tamaño que sizeof(void *) I.E. un

puntero.

Funciones Judy1: El Índice es un Word_t y el Valor es simplemente un bit o simplemente un indicador que el Índice está presente o ausente del arreglo. Esto puede ser pensado como un enorme mapa de

bits.

Funciones JudyL: El Índice es un Word_t y el Valor es un Word_t. Esto hace que JudyL sea un asignador puro de palabra a palabra/puntero. JudySL y JudyHL están basados en esta propiedad de JudyL

.

Funciones JudySL: El Índice es una cadena terminada en nulo y el Valor es un Word_t

.

Funciones JudyHS: El Índice es un arreglo de bytes de longitud: Longitud. El Valor es un Word_t. Esta nueva adición (Mayo 2004) a Judy es un híbrido que usa las mejores características de los métodos de hashing y Judy. El autor cree que JudyHS es un buen reemplazo para un método de hashing cuando el redimensionamiento de la tabla hash se realiza durante el crecimiento de la población. Un método de hashing correctamente ajustado con un tamaño de tabla hash estático y población es imbatible en velocidad. Sin embargo, JudyHS tendrá un mejor rendimiento que un método de hashing con poblaciones más pequeñas y más grandes que el tamaño óptimo de la tabla hash. JudyHS no tiene un caso de rendimiento degenerado donde el conocimiento del algoritmo hash pueda ser explotado. (I.E. JudyHS no usa una lista enlazada para manejar colisiones hash, usa un árbol de arreglos JudyL y un tamaño de tabla hash virtual de 4 mil millones)

.

Los arreglos Judy son tanto eficientes en velocidad como en memoria, sin requerir ajustes ni configuración, a través de una amplia gama de tipos de conjuntos de índices (secuenciales, periódicos, agrupados, aleatorios). La velocidad y el uso de memoria de Judy son típicamente mejores que otros modelos de almacenamiento de datos como listas de saltos, listas enlazadas, binarias, ternarias, b-trees, o incluso hashing, y mejoran con conjuntos de datos muy

grandes.

Un arreglo Judy es creado simplemente definiendo un puntero nulo y luego almacenando (insertando) el primer elemento en el arreglo bajo ese puntero. La memoria usada por un arreglo Judy es casi proporcional a la población (número de elementos)

.

Judy tiene dos Interfaces de Programación de Aplicaciones (APIs): una interfaz de macro C, y una interfaz de llamada a función. Debido a que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de usar las funciones

Judy.

Dado que un arreglo Judy inicial (vacío) es representado por un puntero nulo, es posible construir un arreglo de arreglos Judy. En otras palabras, los Valores de un arreglo Judy (excepto Judy1) pueden ser punteros a otros arreglos Judy. Esto hace que sea muy simple construir un arreglo con un número arbitrario de dimensiones o tamaños de Índice. (JudySL y JudyHS están

implementados usando
JudyL de esta manera).

ERRORE

S

Se dedicó mucho pensamiento (y tiempo) a hacer que el manejo de errores en Judy sea simple, mientras se mantiene la flexibilidad y capacidad. El manejo de errores es un tema muy aburrido incluso para escribir. Así que lea esta sección corta y use el segundo método recomendado. Genera el código más rápido, usa la menor cantidad de memoria y requiere que escriba código extra solo para las funciones de insertar/borrar. Además es compatible con los otros dos métodos. Este método es para código de producción que puede querer manejar fallos de malloc() de manera diferente al valor por defecto de Judy. Si el método por defecto de Judy para manejar fallos de malloc() es aceptable, entonces use el primer

método.

Hay dos (2) categorías de devoluciones de error de Judy (o para cualquier ADT dinámico)

:

1) Errores de programación del usuario (bugs) como corrupción de memoria o punteros inválidos.
2) Memoria agotada (fallo de malloc()) con Insertar (Set) o Borrar (Unset) al modificar un arreglo Judy. No todas las llamadas a insertar y borrar llaman a malloc(), así que pueden tener éxito incluso cuando una llamada a malloc() fallaría.

Hay aproximadamente tres (3) métodos para manejar

errores al u
sar las macros:

1) Método por Defecto de Manejo de

Errores

El valor por defecto es imprimir mensajes de error a stderr, por

ejemplo: 
File 'YourCfile.c', line 1234: JudyLIns(), JU_ERRNO_* == 2, ID ==
321 Esto indica que un error ocurrió en la función JudyLIns() en la línea 321. La línea 1234 es la línea en 'YourCfile.c' donde la llamada JLI() falló. JU_ERRNO_* == 2 es igual a JU_ERRNO_NOMEM (como está definido en el archivo Judy.h). El número ID indica el número de línea de origen en la función donde el error se originó. Su programa luego termina con un exit(1);. Por defecto, ambas categorías de devoluciones de error de Judy son impresas de esta manera. (El 'ID == 321' es para los obstinados que quieren más detalle o para depurar el propio Judy).

2) Deshabilitar el Manejo de Errores de

Macro

Cuando su programa está "libre de bugs", los únicos errores devueltos deberían ser fallos de malloc(). Por lo tanto todas las devoluciones de error pueden ser tratadas como un fallo de malloc(). Usando el siguiente #define, todas las pruebas e impresiones de errores son desactivadas. Se necesita agregar código adicional al código que puede tener fallos de malloc(). Judy fue diseñado para dejar los mismos datos en el arreglo antes de la llamada si un fallo de malloc() ocurre. (Durante las pruebas de Judy, encontramos muy pocos malloc()/SOs que estaban libres de bugs después de un fallo de malloc(). A veces tomó semanas descubrirlo porque la mayoría de los sistemas entran en un frenesí de paginación antes de quedarse sin memoria)

. 
#define JUDYERROR_NOTEST 1
(en el código de su programa), o 
cc -DJUDYERROR_NOTEST sourcefile -lJudy
(en su línea de comandos). 
// Este es un ejemplo de cómo programar usando el método dos (2)
. 
JLI(PValue, PLArray, Index);
if (PValue == PJERR) goto out_of_memory_handling
; 
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;
Nota: Sin 'JUDYERROR_NOTEST' definido, el 'goto out_of_memory_handling' nunca se ejecutará y será optimizado por el compilador. Se usará el método predeterminado -- La macro imprimirá información de error si ocurre un error como se explicó anteriormente.

Con 'JUDYERROR_NOTEST' definido, el 'goto out_of_memory_handling' se ejecutará cuando ocurra un error -- lo que solo debería suceder cuando malloc()

fa
lle.

3) Método de Macro JUDYERROR() Especificado por el

Usuario

La macro JUDYERROR() (en Judy.h) proporciona flexibilidad para manejar los retornos de error según sea necesario para adaptarse a su programa, mientras aún usa las macros de arrays de Judy en lugar de llamadas a funciones. Puede usar una macro JUDYERROR() diferente para adaptarse a sus necesidades. El siguiente ejemplo es una posible alternativa a la predeterminada. Se usa para distinguir entre los dos tipos de errores (descritos anteriormente) y probar explícitamente los errores restantes JU_ERRNO_NOMEM posibles en su

programa. 
// Este es un ejemplo de la API de macros de Judy para continuar cuando no hay memoria
// e imprimir y exit(1) cuando ocurra cualquier otro
error. 
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // necesario para
fprintf() 
// Esta es la macro que las APIs de macros de Judy usan para códigos de retorno de
-1: 
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un fallo de malloc() */       \
    {                                                                     \
        (void) fprintf(stderr, "Archivo '%s', línea %d: %s(), "           \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST no definido
Esta macro de manejo de errores debe incluirse antes de la #include <Judy.h> en su
programa.
