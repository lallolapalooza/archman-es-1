Judy(3) Library Functions Manual Judy(3)

NOMBRE

Judy arrays - Funciones de la biblioteca C para crear y acceder a matrices dinámicas

SINOPSIS

Judy1  - mapea un Índice (palabra) a un bit
JudyL  - mapea un Índice (palabra) a un Valor (palabra/puntero)
JudySL - mapea un Índice (cadena terminada en nulo) a un Valor
JudyHS - mapea un Índice (array de bytes) de Longitud a un Valor

DESCRIPCIÓN

La familia de funciones Judy soporta matrices dinámicas completas. Estas matrices pueden ser indexadas por una palabra de 32 o 64 bits (dependiendo del tamaño de palabra del procesador), una cadena terminada en nulo o un array de bytes más longitud. Una matriz dinámica (poblada de forma dispersa) también puede ser considerada como una función de mapeo o memoria asociativa.

Un Word_t es un typedef unsigned long int en Judy.h y debe tener el mismo tamaño que sizeof(void *), es decir, un puntero.

Funciones Judy1: El Índice es un Word_t y el Valor es solo un bit o simplemente una bandera que indica si el Índice está presente o ausente en la matriz. Esto puede considerarse como un mapa de bits enorme.

Funciones JudyL: El Índice es un Word_t y el Valor es un Word_t. Esto convierte a JudyL en un mapeador puro de palabra a palabra/puntero. JudySL y JudyHL se basan en esta propiedad de JudyL.

Funciones JudySL: El Índice es una cadena terminada en nulo y el Valor es un Word_t.

Funciones JudyHS: El Índice es un array de bytes de longitud: Length. El Valor es un Word_t. Esta nueva adición (mayo de 2004) a Judy es un híbrido que utiliza las mejores características de los métodos de hash y Judy. El autor cree que JudyHS es un buen reemplazo para un método de hash cuando el redimensionamiento de la tabla hash se realiza durante el crecimiento de la población. Un método hash correctamente ajustado con un tamaño de tabla hash estático y población es inmejorable en velocidad. Sin embargo, JudyHS funcionará mejor que un método de hash con poblaciones menores y mayores que el tamaño óptimo de la tabla hash. JudyHS no tiene un caso de rendimiento degenerado donde se pueda explotar el conocimiento del algoritmo hash. (Es decir, JudyHS no utiliza una lista enlazada para manejar colisiones de hash, utiliza un árbol de matrices JudyL y un tamaño de tabla hash virtual de 4 mil millones).

Las matrices Judy son eficientes en velocidad y eficientes en memoria, sin necesidad de ajustes ni configuración, en una amplia gama de tipos de conjuntos de índices (secuenciales, periódicos, agrupados, aleatorios). La velocidad y el uso de memoria de Judy suelen ser mejores que otros modelos de almacenamiento de datos como listas de saltos, listas enlazadas, árboles binarios, ternarios, b-árboles, o incluso hashing, y mejoran con conjuntos de datos muy grandes.

Una matriz Judy se crea simplemente definiendo un puntero nulo y luego almacenando (insertando) el primer elemento en la matriz bajo ese puntero. La memoria utilizada por una matriz Judy es casi proporcional a la población (número de elementos).

Judy tiene dos interfaces de Programa de Aplicación (APIs): una interfaz de macros C y una interfaz de llamadas a funciones. Dado que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de usar las funciones Judy.

Dado que una matriz Judy inicial (vacía) se representa por un puntero nulo, es posible construir una matriz de matrices Judy. En otras palabras, los Valores de una matriz Judy (excepto Judy1) pueden ser punteros a otras matrices Judy. Esto hace que sea muy sencillo construir una matriz con un número arbitrario de dimensiones o tamaños de Índice. (JudySL y JudyHS se implementan utilizando JudyL de esta manera).

ERRORES

Se dedicó mucho pensamiento (y tiempo) a hacer que el manejo de errores en Judy fuera simple, manteniendo la flexibilidad y la capacidad. El manejo de errores es un tema muy aburrido incluso para escribir sobre él. Así que lea esta breve sección y utilice el segundo método recomendado. Genera el código más rápido, utiliza la menor cantidad de memoria y requiere que escriba código adicional solo para las funciones de inserción/eliminación. Además, es compatible con los otros dos métodos. Este método es para código de producción que puede querer manejar fallos de malloc() de manera diferente al predeterminado de Judy. Si el método predeterminado de Judy para manejar fallos de malloc() está bien, entonces use el primer método.

Hay dos (2) categorías de retornos de error de Judy, (o para cualquier ADT dinámico):

1) Errores de programación del usuario (bugs) como corrupción de memoria o punteros inválidos.
2) Falta de memoria (fallo de malloc()) con Inserción (Set) o Eliminación (Unset) al modificar una matriz Judy. No todas las llamadas a inserción y eliminación llaman a malloc(), por lo que pueden tener éxito incluso cuando una llamada a malloc() fallaría.

Hay aproximadamente tres (3) métodos para manejar errores al usar las macros:

1) Método de Manejo de Errores Predeterminado

La opción predeterminada es imprimir mensajes de error en stderr, por ejemplo:

File 'YourCfile.c', line 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Esto indica que ocurrió un error en la función JudyLIns() en la línea 321. La línea 1234 es la línea en 'YourCfile.c' donde falló la llamada JLI(). JU_ERRNO_* == 2 es igual a JU_ERRNO_NOMEM (como se define en el archivo Judy.h). El número ID indica el número de línea de origen en la función donde se originó el error. Su programa luego termina con un exit(1);. Por defecto, ambas categorías de retornos de error de Judy se imprimen de esta manera. (El 'ID == 321' es para los más tercos que quieren más detalles o para depurar Judy en sí).

2) Deshabilitar el Manejo de Errores de las Macros

Cuando su programa está "libre de errores", los únicos errores devueltos deberían ser fallos de malloc(). Por lo tanto, todos los retornos de error pueden tratarse como un fallo de malloc(). Al usar el siguiente #define, se desactiva toda la prueba e impresión de errores. Es necesario agregar código adicional al código que puede tener fallos de malloc(). Judy fue diseñada para dejar los mismos datos en la matriz antes de la llamada si ocurre un fallo de malloc(). (Durante las pruebas de Judy, encontramos muy pocos malloc()/sistemas operativos que estuvieran libres de errores después de un fallo de malloc(). A veces, se necesitaban semanas para descubrirlo porque la mayoría de los sistemas entran en un frenesí de paginación antes de quedarse sin memoria).
