Judy(3) Manual de Funciones de Biblioteca Judy(3)

NOMBRE

Arrays Judy - Funciones de biblioteca C para crear y acceder a arrays dinámicos

SINOPSIS

Judy1  - mapea un Index (palabra) a un bit
JudyL  - mapea un Index (palabra) a un Value (palabra/puntero)
JudySL - mapea un Index (cadena terminada en nulo) a un Value
JudyHS - mapea un Index (array de bytes) de Length a un Value

DESCRIPCIÓN

La familia de funciones Judy soporta arrays completamente dinámicos. Estos arrays pueden ser indexados por una palabra de 32 o 64 bits (dependiendo del tamaño de palabra del procesador), una cadena terminada en nulo o un array de bytes más longitud. Un array dinámico (escasamente poblado) también puede ser pensado como una función de mapeo o memoria asociativa.

Un Word_t es un typedef unsigned long int en Judy.h y debe ser del mismo tamaño que sizeof(void *), es decir, un puntero.

Funciones Judy1: Index es un Word_t y Value es solo un bit o simplemente un indicador de que Index está presente o ausente del array. Esto puede ser pensado como un enorme mapa de bits.

Funciones JudyL: Index es un Word_t y Value es un Word_t. Esto hace de JudyL un mapeador puro de palabra a palabra/puntero. JudySL y JudyHL se basan en esta propiedad de JudyL.

Funciones JudySL: Index es una cadena terminada en nulo y Value es un Word_t.

Funciones JudyHS: Index es un array de bytes de longitud: Length. Value es un Word_t. Esta nueva adición (mayo de 2004) a Judy es un híbrido que utiliza las mejores características de la codificación hash y los métodos de Judy. El autor cree que JudyHS es un buen reemplazo para un método de codificación hash cuando el redimensionamiento de la tabla hash se realiza durante el crecimiento de la población. Un método hash correctamente ajustado con un tamaño de tabla hash estático y población es inmejorable en velocidad. Sin embargo, JudyHS funcionará mejor que un método hash con poblaciones menores y mayores que el tamaño óptimo de la tabla hash. JudyHS no tiene un caso de rendimiento degenerado donde se pueda explotar el conocimiento del algoritmo hash. (Es decir, JudyHS no utiliza una lista enlazada para manejar colisiones hash, utiliza un árbol de arrays JudyL y un tamaño de tabla hash virtual de 4 mil millones).

Los arrays Judy son tanto eficientes en velocidad como en memoria, sin necesidad de ajustes o configuración, en una amplia gama de tipos de conjuntos de índices (secuencial, periódico, agrupado, aleatorio). La velocidad y el uso de memoria de Judy suelen ser mejores que otros modelos de almacenamiento de datos como skiplists, listas enlazadas, árboles binarios, ternarios, b-trees, o incluso la codificación hash, y mejoran con conjuntos de datos muy grandes.

Un array Judy se crea simplemente definiendo un puntero nulo y luego almacenando (insertando) el primer elemento en el array bajo ese puntero. La memoria utilizada por un array Judy es casi proporcional a la población (número de elementos).

Judy tiene dos Interfaces de Programación de Aplicaciones (APIs): una interfaz de macros C y una interfaz de llamadas a funciones. Dado que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de utilizar las funciones de Judy.

Dado que un array Judy inicial (vacío) se representa con un puntero nulo, es posible construir un array de arrays Judy. En otras palabras, los Values de un array Judy (excepto Judy1) pueden ser punteros a otros arrays Judy. Esto hace que sea muy sencillo construir un array con un número arbitrario de dimensiones o tamaños de Index. (JudySL y JudyHS se implementan utilizando JudyL de esta manera).

ERRORES

Se dedicó mucho pensamiento (y tiempo) a hacer que el manejo de errores en Judy fuera simple, manteniendo la flexibilidad y capacidad. El manejo de errores es un tema muy aburrido incluso para escribir. Así que lea esta breve sección y utilice el segundo método recomendado. Genera el código más rápido, utiliza la menor cantidad de memoria y requiere que usted escriba código adicional solo para las funciones de inserción/eliminación. Además, es compatible con los otros dos métodos. Este método es para código de producción que puede querer manejar fallos de malloc() de manera diferente al predeterminado de Judy. Si el método predeterminado de Judy para manejar fallos de malloc() es aceptable, utilice el primer método.

Hay dos (2) categorías de retornos de error de Judy, (o para cualquier ADT dinámico):

1) Errores de programación del usuario (bugs) como corrupción de memoria o punteros inválidos.
2) Falta de memoria (fallo de malloc()) al Insertar (Set) o Eliminar (Unset) al modificar un array Judy. No todas las llamadas a insertar y eliminar llaman a malloc(), por lo que pueden tener éxito incluso cuando una llamada a malloc() fallaría.

Hay aproximadamente tres (3) métodos para manejar errores al usar las macros:

1) MÉTODO DE MANEJO DE ERRORES PREDETERMINADO

El valor predeterminado es imprimir mensajes de error en stderr, por ejemplo:

Archivo 'TuArchivoC.c', línea 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Esto indica que ocurrió un error en la función JudyLIns() en la línea 321. La línea 1234 es la línea en 'TuArchivoC.c' donde falló la llamada JLI(). JU_ERRNO_* == 2 es igual a JU_ERRNO_NOMEM (como se define en el archivo Judy.h). El número de ID indica el número de línea de origen en la función donde se originó el error. Su programa luego termina con un exit(1);. Por defecto, ambas categorías de retornos de error de Judy se imprimen de esta manera. (El 'ID == 321' es para los obstinados que quieren más detalle o para depurar Judy en sí misma).


2) DESACTIVAR EL MANEJO DE ERRORES DE MACRO

Cuando su programa está "libre de errores", los únicos errores devueltos deberían ser fallos de malloc(). Por lo tanto, todos los retornos de error pueden tratarse como un fallo de malloc(). Usando el siguiente #define, se desactivan todas las pruebas e impresiones de errores. Se necesita agregar código adicional al código que puede tener fallos de malloc(). Judy fue diseñada para dejar los mismos datos en el array antes de la llamada si ocurre un fallo de malloc(). (Durante las pruebas de Judy, encontramos muy pocos malloc()/SO que estuvieran libres de errores después de un fallo de malloc(). A veces tardaba semanas en descubrirse porque la mayoría de los sistemas entran en un frenesí de paginación antes de quedarse sin memoria).

3) Método de Macro JUDYERROR() Especificado por el

Usuario

La macro JUDYERROR() (en Judy.h) proporciona flexibilidad para manejar los códigos de retorno de error según sea necesario para adaptarse a su programa mientras aún utiliza las macros de la matriz Judy en lugar de llamadas a funciones. Puede usar una macro JUDYERROR() diferente para adaptarse a sus necesidades. El siguiente ejemplo es una posible alternativa a la por defecto. Se utiliza para distinguir entre los dos tipos de errores (descritos arriba), y probar explícitamente los errores JU_ERRNO_NOMEM restantes posibles en su

programa. 
// Este es un ejemplo de la API de macros de Judy para continuar cuando se queda sin memoria
// e imprimir y exit(1) cuando ocurra cualquier otro
error. 
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // necesario para
fprintf() 
// Esta es la macro que las APIs de macros de Judy usan para los códigos de retorno de
-1: 
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un fallo de malloc() */       \
    {                                                                     \
        (void) fprintf(stderr, "Archivo '%s', línea %d: %s(), "           \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST no definido
Esta macro de manejo de errores debe incluirse antes de la #include <Judy.h> en su
programa.
