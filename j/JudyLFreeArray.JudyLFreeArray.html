DESCRIPCIÓN

Existe un macro equivalente para cada llamada a función. Dado que las formas de macro son a veces más rápidas y tienen una interfaz de manejo de errores más simple que las funciones equivalentes, son la forma preferida de llamar a las funciones JudyL. Véase JudyL(3) para más información. Las definiciones de las llamadas a funciones se incluyen aquí por completitud.

Una de las dificultades al usar las llamadas a funciones JudyL radica en determinar si se debe pasar un puntero o la dirección de un puntero. Dado que las funciones que modifican el array JudyL también deben modificar el puntero al array JudyL, se debe pasar la dirección del puntero en lugar del puntero mismo. Esto a menudo conduce a errores programáticos difíciles de depurar. En la práctica, los macros permiten al compilador detectar errores de programación cuando se pasan punteros en lugar de direcciones de punteros.

Las llamadas a funciones JudyL tienen un parámetro adicional más allá de los especificados en las llamadas a macro. Este parámetro es o bien un puntero a una estructura de error, o NULL (en cuyo caso la información detallada del error no se devuelve).

En las siguientes descripciones, las funciones se describen en términos de cómo las macros las usan (solo en el caso de #define JUDYERROR_NOTEST 1). Este es el uso sugerido de los macros después de que su programa haya sido completamente depurado. Cuando el JUDYERROR_NOTEST macro no se especifica, se declara una estructura de error para almacenar la información de error devuelta por las funciones JudyL cuando ocurre un error.

NAME

JudyLFreeArray - free JudyL array memory

SYNOPSIS

#include <Judy.h>

Word_t *
JudyLFreeArray(Word_t *judySLArray);

DESCRIPTION

JudyLFreeArray frees the memory used by the JudyL array pointed to by judySLArray.

The Judy array library can be used to implement sparse arrays efficiently. Its main characteristic is that it is a data structure that dynamically grows and shrinks. This implies that it may allocate and deallocate memory dynamically. If a Judy array is not freed, then the memory allocated for it will be leaked.

The JudyL array library supports 64-bit indexing and 64-bit values.

A Judy array is defined as a pointer to a Word_t (unsigned 64-bit integer). The values stored in the array are pointers to Word_t (64-bit integer) or pointers to void.

The Judy array library requires that the values stored in the array be pointers. If you want to store integer values, you must allocate memory for these values and store a pointer to this memory in the Judy array.

The void pointer type is used to store the values in the Judy array. This allows the Judy array to store pointers to any type of object. The return type from most Judy array functions is PPvoid_t (pointer to pointer to void), so that the values stored in the array can be pointers to other objects, which is a typical usage, or cast to a Word_t * when a pointer to a Value is required instead of a pointer to a pointer.

The JudyL array library uses the following types:

Word_t

typedef unsigned long Word_t;

PJudyL

typedef Word_t *PJudyL;

PPJudyL

typedef Word_t **PPJudyL;

Pvoid_t

typedef void *Pvoid_t;

PPvoid_t

typedef void **PPvoid_t;

Pcvoid_t

typedef const void *Pcvoid_t;

Value

typedef Word_t Value;

The void pointer type can be passed by value to functions that take Pcvoid_t (constant Pvoid_t), and also by address to functions that take PPvoid_t.

The return type from most JudyL functions is PPvoid_t so that the values stored in the array can be pointers to other objects, which is a typical usage, or cast to a Word_t * when a pointer to a Value is required instead of a pointer to a pointer.
