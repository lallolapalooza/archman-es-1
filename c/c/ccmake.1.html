NOMBRE

ccmake - Referencia de línea de comandos de diálogo ncurses de CMake

SINOPSIS

ccmake [<opciones>] -B <ruta-a-construcción> [-S <ruta-a-origen>]
ccmake [<opciones>] <ruta-a-origen | ruta-a-construcción-existente>

DESCRIPCIÓN

El ejecutable ccmake es la interfaz ncurses de CMake. Los ajustes de configuración del proyecto se pueden especificar interactivamente a través de esta GUI. Las instrucciones breves se proporcionan en la parte inferior de la terminal cuando el programa se está ejecutando.

CMake es un generador de sistemas de compilación multiplataforma. Los proyectos especifican sus procesos de compilación con archivos de lista de CMake independientes de la plataforma incluidos en cada directorio de un árbol de origen con el nombre CMakeLists.txt. Los usuarios compilan un proyecto utilizando CMake para generar un sistema de compilación para una herramienta nativa en su plataforma.

OPCIONES

-S <ruta-a-origen>
Ruta al directorio raíz del proyecto CMake a compilar.
-B <ruta-a-construcción>
Ruta al directorio que CMake utilizará como raíz del directorio de compilación.

Si el directorio no existe, CMake lo creará.

-C <caché-inicial>
Precargar un script para poblar la caché.

Cuando CMake se ejecuta por primera vez en un árbol de compilación vacío, crea un archivo CMakeCache.txt y lo puebla con configuraciones personalizables para el proyecto. Esta opción se puede utilizar para especificar un archivo desde el que cargar entradas de caché antes de la primera pasada por los archivos de lista de CMake del proyecto. Las entradas cargadas tienen prioridad sobre los valores predeterminados del proyecto. El archivo proporcionado debe ser un script de CMake que contenga comandos set() <#command:set> que utilicen la opción CACHE, no un archivo en formato de caché.

Las referencias a CMAKE_SOURCE_DIR <#variable:CMAKE_SOURCE_DIR> y CMAKE_BINARY_DIR <#variable:CMAKE_BINARY_DIR> dentro del script se evalúan como el directorio de origen y de compilación de nivel superior.

-D <var>:<tipo>=<valor>, -D <var>=<valor>
Crear o actualizar una entrada de CACHE de CMake.

Cuando CMake se ejecuta por primera vez en un árbol de compilación vacío, crea un archivo CMakeCache.txt y lo puebla con configuraciones personalizables para el proyecto. Esta opción se puede utilizar para especificar una configuración que tenga prioridad sobre el valor predeterminado del proyecto. La opción se puede repetir para tantas entradas de CACHE como se desee.

Si se proporciona la parte :<tipo>, debe ser uno de los tipos especificados en la documentación del comando set() <#command:set> para su firma de CACHE. Si se omite la parte :<tipo>, la entrada se creará sin tipo si no existe ya con uno. Si un comando en el proyecto establece el tipo en PATH o FILEPATH, entonces el <valor> se convertirá en una ruta absoluta.

Esta opción también se puede proporcionar como un solo argumento: -D<var>:<tipo>=<valor> o -D<var>=<valor>.

Es importante tener en cuenta que el orden de los argumentos -C y -D es significativo. Se ejecutarán en el orden en que se enumeran, y el último argumento tendrá prioridad sobre los anteriores. Por ejemplo, si especifica -DCMAKE_BUILD_TYPE=Debug, seguido de un argumento -C con un archivo que llama:

set(CMAKE_BUILD_TYPE "Release" CACHE STRING "" FORCE)

entonces el argumento -C tendrá prioridad, y CMAKE_BUILD_TYPE se establecerá en Release. Sin embargo, si el argumento -D viene después del argumento -C, se establecerá en Debug.

Si una llamada set(... CACHE ...) en el archivo -C no utiliza FORCE, y un argumento -D establece la misma variable, el argumento -D tendrá prioridad independientemente del orden debido a la naturaleza de las llamadas set(... CACHE ...) no FORCE.

-U <expresión-de-glob>
Eliminar entradas coincidentes de la CACHE de CMake.

Esta opción se puede utilizar para eliminar una o más variables del archivo CMakeCache.txt, se admiten expresiones de glob utilizando * y ?. La opción se puede repetir para tantas entradas de CACHE como se desee.

Úselo con cuidado, puede hacer que su CMakeCache.txt no funcione.

-G <nombre-generador>
Especificar un generador de sistemas de compilación.

CMake puede admitir varios sistemas de compilación nativos en plataformas específicas. Un generador es responsable de generar un sistema de compilación particular. Los nombres de generador posibles se especifican en el manual de cmake-generators(7) <#manual:cmake-generators(7)>.

Si no se especifica, CMake verifica la variable de entorno CMAKE_GENERATOR <#envvar:CMAKE_GENERATOR> y, de lo contrario, recurre a una selección predeterminada incorporada.

-T <especificación-conjunto-de-herramientas>
Especificación del conjunto de herramientas para el generador, si es compatible.

Algunos generadores de CMake admiten una especificación de conjunto de herramientas para indicar al sistema de compilación nativo cómo elegir un compilador. Consulte la variable CMAKE_GENERATOR_TOOLSET <#variable:CMAKE_GENERATOR_TOOLSET> para obtener más detalles.

-A <nombre-plataforma>
Especificar el nombre de la plataforma si es compatible con el generador.

Algunos generadores de CMake admiten un nombre de plataforma que se proporciona al sistema de compilación nativo para elegir un compilador o SDK. Consulte la variable CMAKE_GENERATOR_PLATFORM <#variable:CMAKE_GENERATOR_PLATFORM> para obtener más detalles.

--toolchain <ruta-al-archivo>
Añadido en la versión 3.21.

Especifica el archivo de toolchain de compilación cruzada, equivalente a establecer la variable CMAKE_TOOLCHAIN_FILE <#variable:CMAKE_TOOLCHAIN_FILE>. Las rutas relativas se interpretan como relativas al directorio de compilación y, si no se encuentran, relativas al directorio de origen.

--install-prefix <directorio>
Añadido en la versión 3.21.

Especifica el directorio de instalación, utilizado por la variable CMAKE_INSTALL_PREFIX <#variable:CMAKE_INSTALL_PREFIX>. Debe ser una ruta absoluta.

--project-file <nombre-archivo-proyecto>
Añadido en la versión 4.0.

Especifica un nombre de archivo de proyecto alternativo.

Esto determina el archivo de nivel superior procesado por CMake al configurar un proyecto, y el archivo procesado por add_subdirectory() <#command:add_subdirectory>.

Por defecto, este es CMakeLists.txt. Si se establece en cualquier otra cosa, CMakeLists.txt se utilizará como recurso de respaldo siempre que el archivo especificado no se encuentre dentro de un subdirectorio del proyecto.

Nota:

Esta función está destinada al uso temporal por parte de los desarrolladores durante una transición incremental y no para la publicación de un producto final. CMake siempre emitirá una advertencia cuando el archivo del proyecto sea algo distinto de CMakeLists.txt.
