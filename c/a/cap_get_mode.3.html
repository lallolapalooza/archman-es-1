Pour être de manière significative sécurisée, cependant, les ensembles de capacités devraient être répliqués por todos los hilos dentro de un programa común porque los hilos no están aislados en memoria. Como solución temporal para esto, libcap se empaqueta con una biblioteca separada de llamadas al sistema con semántica POSIX: libpsx. Si su programa usa hilos POSIX, para lograr una manipulación de capacidades con semántica POSIX significativa, debe vincular su programa con:

ld ... -lcap $(pkg-config --libs --cflags libpsx)

o,

gcc ... -lcap $(pkg-config --libs --cflags libpsx)

Cuando se vincula de esta manera, debido a la magia del enlazador, libcap usa psx_syscall(3) y psx_syscall6(3) para realizar llamadas al sistema de configuración de estado. Notablemente, esto también asegura que cap_prctlw() pueda usarse para asegurar que los bits de control del proceso se compartan en todos los hilos de un solo proceso.

capgetp() y capsetp()

La biblioteca también soporta las funciones obsoletas:

int capgetp(pid_t pid, cap_t cap_d);

int capsetp(pid_t pid, cap_t cap_d);

capgetp() intenta obtener las capacidades de algún otro proceso; almacenando las capacidades en un cap_dpreasignado. Vea cap_init() para información sobre cómo asignar un conjunto de capacidades vacío. Esta función está obsoleta; debería usar cap_get_pid().

capsetp() intenta establecer las capacidades del proceso que llama o de algún otro proceso(s), pid. Note que establecer capacidades de otro proceso solo es posible en kernels más antiguos que no proporcionan soporte VFS para establecer capacidades de archivos. Vea capset(2) para información sobre qué kernels proporcionan dicho soporte.

Si pid es positivo, se refiere a un proceso específico; si es cero, se refiere al proceso que llama; -1 se refiere a todos los procesos distintos del proceso que llama y del proceso '1' (típicamente init(8)); otros valores negativos se refieren al grupo de procesos -pid .

Para usar esta función, el kernel debe soportarla y el proceso que llama debe tener CAP_SETPCAP activado en su conjunto de capacidades Efectivas. Las capacidades establecidas en el/los proceso(s) objetivo son las contenidas en cap_d.

Los kernels que soportan capacidades del sistema de archivos redefinen la semántica de CAP_SETPCAP y en tales sistemas, capsetp() siempre fallará para cualquier objetivo distinto del proceso que llama. capsetp() devuelve cero para éxito, y -1 para fallo.

En kernels donde es (era) soportado, capsetp() debe usarse con cuidado. Existía principalmente para superar la falta temprana de soporte para capacidades en los sistemas de archivos soportados por Linux. Note que en kernels más antiguos donde capsetp() podía usarse para establecer las capacidades de otro proceso, los únicos procesos que tenían CAP_SETPCAP disponible por defecto eran procesos iniciados como hilos del kernel. (Típicamente esto incluye init(8), kflushd y kswapd.) Se necesitaba una recompilación del kernel para modificar este valor por defecto.

EJEMPLO

El segmento de código siguiente activa las capacidades efectivas CAP_FOWNER y CAP_SETFCAP para el llamador:

    ...
    cap_t caps;
    const cap_value_t cap_list[2] = {CAP_FOWNER, CAP_SETFCAP};
    if (!CAP_IS_SUPPORTED(CAP_SETFCAP))
        /* handle error */
    caps = cap_get_proc();
    if (caps == NULL)
        /* handle error */;
    if (cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET) == -1)
        /* handle error */;
    if (cap_set_proc(caps) == -1)
        /* handle error */;
    if (cap_free(caps) == -1)
        /* handle error */;
    ...

Alternativamente, para descartar completamente el privilegio en un programa lanzado con setuid-root pero que quiere ejecutarse con un ID de usuario específico, etc., de tal manera que ni él ni ninguno de sus hijos puedan adquirir privilegio de nuevo:

    ...
    uid_t nobody = 65534;
    const gid_t groups[] = {65534};
    if (cap_setgroups(groups[0], 1, groups) != 0)
        /* handle error */;
    if (cap_setuid(nobody) != 0)
        /* handle error */;
    /*
     * privilege is still available here
     */
    if (cap_set_mode(CAP_MODE_NOPRIV) != 0)
        /* handle error */
    ...

Note, la secuencia anterior puede ser realizada por la herramienta capsh de la siguiente manera:

sudo capsh --user=nobody --mode=NOPRIV --print

donde --print muestra el estado de privilegio resultante.
