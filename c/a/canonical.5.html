CANONICAL(5) Manual de formatos de archivo CANONICAL(5)

NOMBRE

canonical - Formato de tabla canónica de Postfix

SINOPSIS

postmap /etc/postfix/canonical
postmap -q "cadena" /etc/postfix/canonical
postmap -q - /etc/postfix/canonical <archivo_entrada

DESCRIPCIÓN


La tabla opcional canonical(5) especifica un mapeo de direcciones para direcciones locales y no locales. El mapeo es utilizado por el demonio cleanup(8), antes de que el correo se almacene en la cola. El mapeo de direcciones es recursivo.

Normalmente, la tabla canonical(5) se especifica como un archivo de texto que sirve como entrada para el comando postmap(1). El resultado, un archivo indexado en formato dbm o db, se utiliza para búsquedas rápidas por el sistema de correo. Ejecute el comando "postmap /etc/postfix/canonical" para reconstruir un archivo indexado después de cambiar el archivo de texto correspondiente.

Cuando la tabla se proporciona a través de otros medios como NIS, LDAP o SQL, se realizan las mismas búsquedas que para los archivos indexados ordinarios.

Alternativamente, la tabla puede proporcionarse como un mapa de expresiones regulares donde los patrones se dan como expresiones regulares, o las búsquedas pueden dirigirse a un servidor basado en TCP. En esos casos, las búsquedas se realizan de una manera ligeramente diferente, como se describe a continuación en "TABLAS DE EXPRESIONES REGULARES" o "TABLAS BASADAS EN TCP".

Por defecto, el mapeo canonical(5) afecta tanto a las direcciones de encabezado del mensaje (es decir, direcciones que aparecen dentro de los mensajes) como a las direcciones del sobre del mensaje (por ejemplo, las direcciones que se utilizan en los comandos del protocolo SMTP). Esto se controla con el parámetro canonical_classes.

NOTA: Las versiones 2.2 y posteriores de Postfix reescriben los encabezados de los mensajes de los clientes SMTP remotos solo si el cliente coincide con local_header_rewrite_clients, o si el parámetro de configuración remote_header_rewrite_domain especifica un valor no vacío. Para obtener el comportamiento anterior a Postfix 2.2, especifique "local_header_rewrite_clients = static:all".

Típicamente, uno usaría la tabla canonical(5) para reemplazar nombres de usuario por Nombre.Apellido, o para limpiar direcciones producidas por sistemas de correo heredados.

El mapeo canonical(5) no debe confundirse con el soporte de alias virtual o con el alias local. Para cambiar el destino pero no los encabezados, use el mapa virtual(5) o aliases(5) en su lugar.

PLEGADO DE MAYÚSCULAS

La cadena de búsqueda se pliega a minúsculas antes de la búsqueda en la base de datos. A partir de Postfix 2.3, la cadena de búsqueda no se pliega con tipos de base de datos como regexp: o pcre: cuyos campos de búsqueda pueden coincidir tanto con mayúsculas como con minúsculas.

FORMATO DE TABLA

El formato de entrada para el comando postmap(1) es el siguiente:

patrón dirección
Cuando patrón coincide con una dirección de correo, reemplácela por la dirección correspondiente.
líneas en blanco y comentarios
Se ignoran las líneas vacías y las líneas que solo contienen espacios en blanco, al igual que las líneas cuyo primer carácter que no es un espacio en blanco es un `#'.
texto de varias líneas
Una línea lógica comienza con texto que no es un espacio en blanco. Una línea que comienza con un espacio en blanco continúa una línea lógica.

ORDEN DE BÚSQUEDA DE TABLA

Con búsquedas en archivos indexados como DB o DBM, o en tablas de red como NIS, LDAP o SQL, cada consulta de usuario@dominio produce una secuencia de patrones de consulta como se describe a continuación.

Cada patrón de consulta se envía a cada tabla de búsqueda especificada antes de intentar el siguiente patrón de consulta, hasta que se encuentre una coincidencia.

usuario@dominio dirección
Reemplace usuario@dominio por dirección. Esta forma tiene la mayor precedencia.

Esto es útil para limpiar direcciones producidas por sistemas de correo heredados. También se puede utilizar para producir direcciones de estilo Nombre.Apellido, pero vea a continuación para una solución más sencilla.

usuario dirección
Reemplace usuario@sitio por dirección cuando sitio sea igual a $myorigin, cuando sitio esté listado en $mydestination, o cuando esté listado en $inet_interfaces o $proxy_interfaces.

Esta forma es útil para reemplazar nombres de usuario por Nombre.Apellido.

@dominio dirección
Reemplace otras direcciones en dominio por dirección. Esta forma tiene la menor precedencia.

Nota: @dominio es un comodín. Cuando esta forma se aplica a las direcciones del destinatario, el servidor SMTP de Postfix acepta el correo para cualquier destinatario en dominio, independientemente de si ese destinatario existe. Esto puede convertir su sistema de correo en una fuente de retrodispersión: Postfix primero acepta el correo para destinatarios inexistentes y luego intenta devolver ese correo como "no entregable" a la dirección del remitente, a menudo falsificada.

Para evitar la retrodispersión con correos para un dominio comodín, reemplace el mapeo comodín por mapeos explícitos 1:1, o agregue una restricción reject_unverified_recipient para ese dominio:

    smtpd_recipient_restrictions =
    ...
    reject_unauth_destination
    check_recipient_access
        inline:{example.com=reject_unverified_recipient}
unverified_recipient_reject_code = 550

En el ejemplo anterior, Postfix puede ponerse en contacto con un servidor remoto si el destinatario se reescribe a una dirección remota.

REESCRITURA DE DIRECCIÓN DE RESULTADO

El resultado de la búsqueda está sujeto a reescritura de direcciones:

  • Cuando el resultado tiene la forma @otrodominio, el resultado se convierte en el mismo usuario en otrodominio.
  • Cuando "append_at_myorigin=yes", agregue "@$myorigin" a las direcciones sin "@dominio".
  • Cuando "append_dot_mydomain=yes", agregue ".$mydomain" a las direcciones sin ".dominio".

EXTENSIÓN DE DIRECCIÓN

Cuando la parte local de una dirección de correo contiene el delimitador de destinatario opcional (por ejemplo, usuario+foo@dominio), el orden de búsqueda se convierte en: usuario+foo@dominio, usuario@dominio, usuario+foo, usuario, y @dominio.

El parámetro propagate_unmatched_extensions controla si una extensión de dirección no coincidente (+foo) se propaga al resultado de la búsqueda de tabla.

TABLAS DE EXPRESIONES REGULARES

Esta sección describe cómo cambian las búsquedas de tabla cuando la tabla se presenta en forma de expresiones regulares. Para una descripción de la sintaxis de la tabla de búsqueda de expresiones regulares, consulte regexp_table(5) o pcre_table(5).

Cada patrón es una expresión regular que se aplica a la dirección completa que se está buscando. Por lo tanto, las direcciones de correo usuario@dominio no se dividen en sus partes constituyentes usuario y @dominio, ni usuario+foo se divide en usuario y foo.

Los patrones se aplican en el orden especificado en la tabla, hasta que se encuentra un patrón que coincide con la cadena de búsqueda.

Los resultados son los mismos que con las búsquedas en archivos indexados, con la adición de que las subcadenas entre paréntesis del patrón pueden interpolarse como $1, $2 y así sucesivamente.

TABLAS BASADAS EN TCP

Esta sección describe cómo cambian las búsquedas de tabla cuando las búsquedas se dirigen a un servidor basado en TCP. Para una descripción del protocolo de búsqueda cliente/servidor TCP, consulte tcp_ta

ble(5)Esta función no está disponible hasta y hasta la versión 2.4 de Postfix.

Cada operación de búsqueda utiliza la dirección completa una vez. Por lo tanto, user@domain las direcciones de correo no se dividen en sus user y @domain partes constituyentes, ni user+foo se divide en user y foo.

Los resultados son los mismos que con las búsquedas en archivos indexados.

ERRORES


El formato de tabla no entiende las convenciones de comillas.

PARÁMETROS DE CONFIGURACIÓN

Los siguientes main.cf parámetros son especialmente relevantes. El texto a continuación proporciona solo un resumen de parámetros. Vea postconf(5) para más detalles, incluyendo ejemplos.

canonical_classes (envelope_sender, envelope_recipient, header_sender, header_recipient)
Qué direcciones están sujetas al mapeo de direcciones canonical_maps.
canonical_maps (vacío)
Tablas de búsqueda de mapeo de direcciones opcionales para encabezados y sobres de mensajes.
recipient_canonical_maps (vacío)
Tablas de búsqueda de mapeo de direcciones opcionales para las direcciones de destinatario del sobre y del encabezado.
sender_canonical_maps (vacío)
Tablas de búsqueda de mapeo de direcciones opcionales para las direcciones de remitente del sobre y del encabezado.
propagate_unmatched_extensions (canonical, virtual)
Qué tablas de búsqueda de direcciones copían una extensión de dirección de la clave de búsqueda al resultado de la búsqueda.

Otros parámetros de interés:

inet_interfaces (all)
Las direcciones de interfaz de red local en las que este sistema de correo recibe correo.
local_header_rewrite_clients (permit_inet_interfaces)
Reescribir o añadir encabezados de mensajes en el correo de estos clientes, actualizando direcciones incompletas con el nombre de dominio en $myorigin o $mydomain, y añadiendo encabezados faltantes.
proxy_interfaces (vacío)
Las direcciones de interfaz de red remotas en las que este sistema de correo recibe correo por medio de un proxy o una unidad de traducción de direcciones de red.
masquerade_classes (envelope_sender, header_sender, header_recipient)
Qué direcciones están sujetas al enmascaramiento de direcciones.
masquerade_domains (vacío)
Lista opcional de dominios cuya estructura de subdominio se eliminará en las direcciones de correo electrónico.
masquerade_exceptions (vacío)
Lista opcional de nombres de usuario que no están sujetos al enmascaramiento de direcciones, incluso cuando sus direcciones coinciden con $masquerade_domains.
mydestination ($myhostname, localhost.$mydomain, localhost)
La lista de dominios que se entregan a través del transporte de entrega de correo $local_transport.
myorigin ($myhostname)
El nombre de dominio del que parece provenir el correo publicado localmente, y al que se entrega el correo publicado localmente.
owner_request_special (yes)
Habilita un tratamiento especial para las entradas owner-listname en el aliases(5) archivo, y no divide las direcciones owner-listname y listname-request en sus partes locales cuando el recipient_delimiter está establecido en "-".
remote_header_rewrite_domain (vacío)
Reescribir o añadir encabezados de mensajes en el correo de clientes remotos si el valor del parámetro remote_header_rewrite_domain no está vacío, actualizando direcciones incompletas con el dominio especificado en el parámetro remote_header_rewrite_domain, y añadiendo encabezados faltantes.
