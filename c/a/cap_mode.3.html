NOMBRE

cap_get_proc, cap_set_proc, capgetp, cap_get_bound, cap_drop_bound, cap_get_ambient, cap_set_ambient, cap_reset_ambient, cap_get_secbits, cap_set_secbits, cap_get_mode, cap_set_mode, cap_mode_name, cap_get_pid, cap_setuid, cap_prctl, cap_prctlw, cap_setgroups - manipulación de capacidades en procesos

SINOPSIS

#include <sys/capability.h>
cap_t cap_get_proc(void);
int cap_set_proc(cap_t cap_p);
int cap_get_bound(cap_value_t cap);
CAP_IS_SUPPORTED(cap_value_t cap);
int cap_drop_bound(cap_value_t cap);
int cap_get_ambient(cap_value_t cap);
int cap_set_ambient(cap_value_t cap, cap_flag_value_t value);
int cap_reset_ambient(void);
CAP_AMBIENT_SUPPORTED();
unsigned cap_get_secbits(void);
int cap_set_secbits(unsigned bits);
cap_mode_t cap_get_mode(void);
const char *cap_mode_name(cap_mode_t mode);
int cap_prctl(long int pr_cmd, long int arg1, long int arg2,
	      long int arg3, long int arg4, long int arg5);
int cap_prctlw(long int pr_cmd, long int arg1, long int arg2,
	       long int arg3, long int arg4, long int arg5);
int cap_set_mode(cap_mode_t mode);
#include <sys/types.h>
cap_t cap_get_pid(pid_t pid);
int cap_setuid(uid_t uid);
int cap_setgroups(gid_t gid, size_t ngroups, const gid_t groups);

Enlazar con -lcap.

DESCRIPCIÓN

cap_get_proc() asigna un estado de capacidades en el almacenamiento de trabajo, establece su estado al del proceso que llama, y devuelve un puntero a este estado de capacidades recién creado. El llamador debe liberar cualquier memoria liberable, cuando el estado de capacidades en el almacenamiento de trabajo ya no sea necesario, llamando a cap_free() con el cap_t como argumento.

cap_set_proc() establece los valores para todos los indicadores de capacidades a las capacidades de estado identificadas por cap_p. El nuevo estado de capacidades del proceso se determinará completamente por el contenido de cap_p tras el retorno exitoso de esta función. Si algún indicador en cap_p se establece para alguna capacidad no permitida actualmente para el proceso que llama, la función fallará, y el estado de capacidades del proceso permanecerá sin cambios.

cap_get_pid() devuelve un cap_t, ver cap_init(3), con las capacidades de proceso del proceso conocido por el llamador como pid. Si pid es 0, se devuelven las capacidades del proceso que llama. Esta información también puede obtenerse del archivo /proc/<pid>/status. (Las entradas de ese archivo se pueden traducir con el comando capsh --decode=XXX). Cuando el llamador opera dentro de un espacio de nombres (CLONE_NEWPID), el argumento numérico pid se interpreta en el rango de ese espacio de nombres. Como tal, la idea del llamador del pid de destino puede diferir de la del proceso de destino cuando operan en diferentes espacios de nombres de pid. Ver pid_namespaces(7) para detalles. Además, el valor cap_t devuelto contiene las capacidades que el pid de destino cree tener. Si el destino opera en un espacio de nombres (CLONE_NEWUSER), el privilegio a nivel de sistema de esas capacidades del espacio de nombres de usuario puede ser sustancialmente reducido. Ver user_namespaces(7) para detalles.

cap_get_bound() con un cap como argumento devuelve el valor actual de este indicador de capacidad del conjunto de límites en efecto para el proceso que llama. Esta operación no requiere privilegios. Tenga en cuenta que se proporciona una función macro CAP_IS_SUPPORTED(cap_value_t cap) que se evalúa como verdadera (1) si el sistema soporta la capacidad especificada, cap. Si el sistema no soporta la capacidad, esta función devuelve 0. Esta macro funciona probando una condición de error con cap_get_bound().

cap_drop_bound() se puede usar para bajar la capacidad especificada del conjunto de límites, cap. Para completarse con éxito, el conjunto de capacidades efectivas predominante debe tener CAP_SETPCAP elevado.

cap_get_ambient() devuelve el valor predominante de la capacidad ambiental especificada, o -1 si la capacidad no es soportada por el kernel en ejecución. Una macro CAP_AMBIENT_SUPPORTED() utiliza esta función para determinar si las capacidades ambientales son soportadas por el kernel.

cap_set_ambient() establece la capacidad ambiental especificada a un valor específico. Para elevar una capacidad ambiental específica, los indicadores heredables y permitidos del proceso que llama deben contener el valor de capacidad especificado. Los bits ambientales elevados solo se conservarán mientras esto siga siendo cierto para los indicadores heredables y permitidos.

cap_reset_ambient() restablece todas las capacidades ambientales del proceso que llama a su valor más bajo. Tenga en cuenta que el conjunto ambiental está destinado a operar en un entorno heredado donde la aplicación tiene una conciencia limitada de las capacidades en general. Al ejecutar un archivo, con capacidades de sistema de archivos asociadas, el kernel restablecerá implícitamente el conjunto ambiental del proceso. Además, los cambios en el conjunto heredable por el código del programa sin arreglar explícitamente el conjunto ambiental también pueden reducir los bits ambientales.

cap_get_secbits() devuelve los bits seguros del proceso que llama. Estos bits afectan la forma en que el proceso que llama implementa cosas como la corrección de setuid-root y las capacidades ambientales.

cap_set_secbits() intenta modificar los bits seguros del proceso que llama. Tenga en cuenta que CAP_SETPCAP debe estar en el conjunto de capacidades efectivas para que esto sea efectivo. Algunas configuraciones bloquean los sub-estados de los bits seguros, por lo que los intentos de establecer valores pueden ser denegados por el kernel incluso cuando la capacidad CAP_SETPCAP está elevada.

Para ayudar a gestionar la complejidad de los bits seguros, libcap proporciona un concepto combinado de bits seguros y conjunto de capacidades llamado modo libcap. cap_get_mode() intenta resumir el entorno de seguridad predominante en forma de un valor numérico de cap_mode_t. Una representación textual del modo se puede obtener a través de la función cap_mode_name(). La gran mayoría de las combinaciones de estos valores no están bien definidas en términos de un modo libcap, y para estos estados cap_get_mode() devuelve (cap_mode_t)0 que cap_get_name() identifica como ``UNCERTAIN''. Los modos soportados son: CAP_MODE_NOPRIV, CAP_MODE_HYBRID, CAP_MODE_PURE1E y CAP_MODE_PURE1E_INIT.

cap_prctl() se puede usar para leer el estado a través de la llamada al sistema prctl().

cap_prctlw() se puede usar para escribir el estado a través de la llamada al sistema prctl().

cap_set_mode() se puede usar para establecer el modo deseado. Se requiere la capacidad permitida CAP_SETPCAP para que esta función tenga éxito.

cap_setuid() es una función de conveniencia para la llamada al sistema setuid(2). Donde cap_setuid() se organiza para que la capacidad efectiva correcta se eleve para realizar la llamada al sistema, y también se organiza para preservar la disponibilidad de capacidades permitidas después de que el uid haya cambiado. Después de esta llamada, todas las capacidades efectivas se reducen.

cap_setgroups() es una función de conveniencia para realizar ambas llamadas setgid(2) y setgroups(2) en una sola llamada. La llamada cap_setgroups() eleva la capacidad efectiva correcta durante la llamada, y vacía el conjunto de capacidades efectivas antes de devolver.

VALOR DE RETORNO

Las funciones cap_get_proc() y cap_get_pid() devuelven un valor no nulo en caso de éxito, y nulo en caso de fallo.

La función cap_get_bound() devuelve -1 si la capacidad solicitada es desconocida, de lo contrario, el valor de retorno refleja el estado actual de esa capacidad en el conjunto de límites predominante. Tenga en cuenta que una función macro,

Todas las funciones de configuración como cap_set_proc() y cap_drop_bound() devuelven cero para el éxito, y -1 en caso de fallo.

En caso de fallo, errno se establece en EINVAL, EPERM o ENOMEM.

CONFORMIDAD CON

cap_set_proc() y cap_get_proc() se especifican en el borrador de especificación POSIX.1e retirado. cap_get_pid() es una extensión de Linux.

NOTAS

Ni glibc ni el kernel de Linux respetan las semánticas POSIX para establecer capacidades y bits seguros en presencia de pthreads. Es decir, cambiar los conjuntos de capacidades, por defecto, solo afecta al hilo en ejecución. Para ser significativamente seguro, sin embargo, los conjuntos de capacidades deben ser reflejados por un

hilos dentro de un programa común porque los hilos no están aislados en memoria. Como solución para esto, libcap se empaqueta con una biblioteca separada de llamadas al sistema con semántica POSIX: libpsx. Si su programa usa hilos POSIX, para lograr una manipulación de capacidades con semántica POSIX significativa, debe vincular su programa con:

ld ... -lcap $(pkg-config --libs --cflags libpsx)

o,

gcc ... -lcap $(pkg-config --libs --cflags libpsx)

Al vincularse de esta manera, debido a la magia del enlazador, libcap usa psx_syscall(3) y psx_syscall6(3) para realizar llamadas al sistema de configuración de estado. Notablemente, esto también asegura que cap_prctlw() pueda usarse para asegurar que los bits de control del proceso se compartan en todos los hilos de un solo proceso.

capgetp() y capsetp()

La biblioteca también soporta las funciones obsoletas:

int capgetp(pid_t pid, cap_t cap_d);

int capsetp(pid_t pid, cap_t cap_d);

capgetp() intenta obtener las capacidades de algún otro proceso; almacenando las capacidades en un cap_dpreasignado. Vea cap_init() para información sobre cómo asignar un conjunto de capacidades vacío. Esta función está obsoleta; debería usar cap_get_pid().

capsetp() intenta establecer las capacidades del proceso que llama o de algún otro proceso(s), pid. Nótese que establecer las capacidades de otro proceso solo es posible en núcleos antiguos que no proporcionan soporte VFS para establecer capacidades de archivos. Vea capset(2) para información sobre qué núcleos proporcionan dicho soporte.

Si pid es positivo, se refiere a un proceso específico; si es cero, se refiere al proceso que llama; -1 se refiere a todos los procesos distintos del proceso que llama y del proceso '1' (típicamente init(8)); otros valores negativos se refieren al grupo de procesos -pid .

Para usar esta función, el núcleo debe soportarla y el proceso que llama debe tener CAP_SETPCAP activado en su conjunto de capacidades Efectivas. Las capacidades establecidas en el proceso(s) destino son las contenidas en cap_d.

Los núcleos que soportan capacidades de sistema de archivos redefinen la semántica de CAP_SETPCAP y en tales sistemas, capsetp() siempre fallará para cualquier destino que no sea igual al proceso que llama. capsetp() devuelve cero para éxito, y -1 para fallo.

En núcleos donde esto es (era) soportado, capsetp() debe usarse con cuidado. Existía principalmente para superar una falta temprana de soporte para capacidades en los sistemas de archivos soportados por Linux. Nótese que en núcleos antiguos donde capsetp() podía usarse para establecer las capacidades de otro proceso, los únicos procesos que tenían CAP_SETPCAP disponible por defecto eran los procesos iniciados como hilos del núcleo. (Típicamente esto incluye init(8), kflushd y kswapd.) Se necesitaba una recompilación del núcleo para modificar este comportamiento por defecto.

EJEMPLO

El segmento de código siguiente activa las capacidades efectivas CAP_FOWNER y CAP_SETFCAP para el llamante:

    ...
    cap_t caps;
    const cap_value_t cap_list[2] = {CAP_FOWNER, CAP_SETFCAP};
    if (!CAP_IS_SUPPORTED(CAP_SETFCAP))
        /* handle error */
    caps = cap_get_proc();
    if (caps == NULL)
        /* handle error */;
    if (cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET) == -1)
        /* handle error */;
    if (cap_set_proc(caps) == -1)
        /* handle error */;
    if (cap_free(caps) == -1)
        /* handle error */;
    ...

Alternativamente, para eliminar completamente los privilegios en un programa lanzado con setuid-root pero que desea ejecutarse con un ID de usuario específico, etc., de tal manera que ni él ni ninguno de sus hijos puedan adquirir privilegios de nuevo:

    ...
    uid_t nobody = 65534;
    const gid_t groups[] = {65534};
    if (cap_setgroups(groups[0], 1, groups) != 0)
        /* handle error */;
    if (cap_setuid(nobody) != 0)
        /* handle error */;
    /*
     * privilege is still available here
     */
    if (cap_set_mode(CAP_MODE_NOPRIV) != 0)
        /* handle error */
    ...

Nótese que la secuencia anterior puede ser realizada por la herramienta capsh de la siguiente manera:

sudo capsh --user=nobody --mode=NOPRIV --print

donde --print muestra el estado de privilegio resultante.
