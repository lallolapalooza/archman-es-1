OR
IA

El formato IAB para las variantes heredables de las capacidades se desarrolló primero como la sintaxis de configuración

para el módulo

pam_cap.so de Linux-PAM en libcap-2.29. Se introdujo para extender la simpl

e

lista separada por comas de las capacidades Inheritable del proceso, que el módulo podía otorgar a un árbol de procesos autenticado, para incluir límites aplicados en el vector Bounding y para introducir soporte para el vector Ambient de bits de capacidad. Aunque los vectores Inheritable y Bounding fueron anticipados por el borrador POSIX.1e que introdujo las capacidades, el vector Ambient es una invención de Linux, e incompatible con el modelo de capacidades de archivo POSIX.1e. Como tal, se consideró que intentar fusionar los 5 vectores de capacidades en una sola representación de texto no iba a funcionar. En su lugar,

la

sintaxis de configuración de pam_cap.

so

se generalizó en todo un conjunto de funciones de libcap para agrupar juntas las tres capacidades heredables de forma nativa: la tupla IAB. El soporte para esto debutó en

libcap-2.33.
