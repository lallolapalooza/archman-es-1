cap_get_secbits(3)

Paquete: libcap

Licencias: BSD-3-Clause OR GPL-2.0-only

CAP_GET_PROC(3) Manual del Programador de Linux CAP_GET_PROC(3)

NOMBRE

cap_get_proc, cap_set_proc, capgetp, cap_get_bound, cap_drop_bound, cap_get_ambient, cap_set_ambient, cap_reset_ambient, cap_get_secbits, cap_set_secbits, cap_get_mode, cap_set_mode, cap_mode_name, cap_get_pid, cap_setuid, cap_prctl, cap_prctlw, cap_setgroups - manipulación de capacidades en procesos

SINOPSIS

#include <sys/capability.h>
cap_t cap_get_proc(void);
int cap_set_proc(cap_t cap_p);
int cap_get_bound(cap_value_t cap);
CAP_IS_SUPPORTED(cap_value_t cap);
int cap_drop_bound(cap_value_t cap);
int cap_get_ambient(cap_value_t cap);
int cap_set_ambient(cap_value_t cap, cap_flag_value_t value);
int cap_reset_ambient(void);
CAP_AMBIENT_SUPPORTED();
unsigned cap_get_secbits(void);
int cap_set_secbits(unsigned bits);
cap_mode_t cap_get_mode(void);
const char *cap_mode_name(cap_mode_t mode);
int cap_prctl(long int pr_cmd, long int arg1, long int arg2,
	      long int arg3, long int arg4, long int arg5);
int cap_prctlw(long int pr_cmd, long int arg1, long int arg2,
	       long int arg3, long int arg4, long int arg5);
int cap_set_mode(cap_mode_t mode);
#include <sys/types.h>
cap_t cap_get_pid(pid_t pid);
int cap_setuid(uid_t uid);
int cap_setgroups(gid_t gid, size_t ngroups, const gid_t groups);

Enlazar con -lcap.

DESCRIPCIÓN

cap_get_proc() asigna un estado de capacidades en el almacenamiento de trabajo, establece su estado al del proceso que llama, y devuelve un puntero a este estado de capacidades recién creado. El llamador debe liberar cualquier memoria que pueda liberarse, cuando el estado de capacidades en el almacenamiento de trabajo ya no sea necesario, llamando a cap_free() con el cap_t como argumento.

cap_set_proc() establece los valores para todos los indicadores de capacidades para todas las capacidades al estado de capacidades identificado por cap_p. El nuevo estado de capacidades del proceso estará completamente determinado por el contenido de cap_p tras el retorno exitoso de esta función. Si algún indicador en cap_p está establecido para alguna capacidad que actualmente no esté permitida para el proceso que llama, la función fallará, y el estado de capacidades del proceso permanecerá sin cambios.

cap_get_pid() devuelve un cap_t, ver cap_init(3), con las capacidades del proceso conocido por el llamador como pid. Si pid es 0, entonces se devuelven las capacidades del proceso que llama. Esta información también se puede obtener del archivo /proc/<pid>/status . (Las entradas en ese archivo pueden traducirse con la línea de comandos capsh --decode=XXX .) Cuando el llamador está operando dentro de un espacio de nombres (CLONE_NEWPID), el argumento numérico pid se interpreta en el rango de ese espacio de nombres. Como tal, la idea del llamador del pid objetivo puede diferir de la del proceso objetivo cuando están operando en diferentes espacios de nombres de pid. Ver pid_namespaces(7) para detalles. Además, el valor cap_t devuelto contiene las capacidades que el pid objetivo cree que tiene. Si el objetivo está operando en un espacio de nombres (CLONE_NEWUSER), el privilegio general del sistema de esas capacidades del espacio de nombres de usuario puede estar sustancialmente reducido. Ver user_namespaces(7) para detalles.

cap_get_bound() con un cap como argumento devuelve el valor actual de este indicador de capacidad del conjunto límite en vigor para el proceso que llama. Esta operación no requiere privilegios. Nótese, una macro función CAP_IS_SUPPORTED(cap_value_t cap) se proporciona que evalúa a verdadero (1) si el sistema soporta la capacidad especificada, cap. Si el sistema no soporta la capacidad, esta función devuelve 0. Esta macro funciona probando una condición de error con cap_get_bound().

cap_drop_bound() puede usarse para bajar la capacidad del conjunto límite especificada, cap. Para completarse exitosamente, el conjunto de capacidades vigente efectivo debe tener un CAP_SETPCAPelevado.

cap_get_ambient() devuelve el valor vigente de la capacidad ambiental especificada, o -1 si el kernel en ejecución no soporta la capacidad. Una macro CAP_AMBIENT_SUPPORTED() usa esta función para determinar si el kernel soporta capacidades ambientales.

cap_set_ambient() establece la capacidad ambiental especificada a un valor específico. Para elevar una capacidad ambiental específica, los indicadores heredable y permitido del proceso que llama deben contener el valor de capacidad especificado. Los bits ambientales elevados solo se retendrán mientras esto siga siendo cierto para los indicadores heredable y permitido.

cap_reset_ambient() restablece todas las capacidades ambientales del proceso que llama a su valor bajado. Nótese, el conjunto ambiental está destinado a operar en un entorno heredado donde la aplicación tiene un conocimiento limitado de las capacidades en general. Al ejecutar un archivo, con capacidades de sistema de archivos asociadas, el kernel restablecerá implícitamente el conjunto ambiental del proceso. Además, los cambios en el conjunto heredable por el código del programa sin restablecer explícitamente el conjunto ambiental también pueden bajar bits ambientales.

cap_get_secbits() devuelve los securebits del proceso que llama. Estos bits afectan la manera en que el proceso que llama implementa cosas como la corrección setuid-root y las capacidades ambientales.

cap_set_secbits() intenta modificar los securebits del proceso que llama. Nótese que CAP_SETPCAP debe estar en el conjunto de capacidades efectivas para que esto sea efectivo. Algunos ajustes bloquean los subestados de los securebits, por lo que los intentos de establecer valores pueden ser denegados por el kernel incluso cuando la capacidad CAP_SETPCAP está elevada.

Para ayudar a manejar la complejidad de los securebits, libcap proporciona un concepto combinado de securebit y conjunto de capacidades llamado modo de libcap. cap_get_mode() intenta resumir el entorno de seguridad vigente en la forma de un valor numérico cap_mode_t . Una representación de texto del modo se puede obtener a través de la función cap_mode_name() . La gran mayoría de las combinaciones de estos valores no están bien definidas en términos de un modo de libcap, y para estos estados cap_get_mode() devuelve (cap_mode_t)0 que cap_get_name() identifica como ``UNCERTAIN''. Los modos soportados son: CAP_MODE_NOPRIV, CAP_MODE_HYBRID, CAP_MODE_PURE1E y CAP_MODE_PURE1E_INIT.

cap_prctl() puede usarse para leer estado a través de la llamada al sistema prctl() .

cap_prctlw() puede usarse para escribir estado a través de la llamada al sistema prctl() .

cap_set_mode() puede usarse para establecer el modo deseado. Se requiere la capacidad permitida CAP_SETPCAP para que esta función tenga éxito.

cap_setuid() es una función de conveniencia para la llamada al sistema setuid(2) . Donde cap_setuid() organiza que la capacidad efectiva correcta sea elevada para realizar la llamada al sistema, y también organiza preservar la disponibilidad de las capacidades permitidas después de que el uid haya cambiado. Tras esta llamada, todas las capacidades efectivas se bajan.

cap_setgroups() es una función de conveniencia para realizar las llamadas setgid(2) y setgroups(2) en una sola llamada. La llamada cap_setgroups() eleva la capacidad efectiva correcta durante la duración de la llamada, y vacía el conjunto de capacidades efectivas antes de retornar.

VALOR DE RETORNO

Las funciones cap_get_proc() y cap_get_pid() devuelven un valor no-NULL en éxito, y NULL en fallo.

La función cap_get_bound() devuelve -1 si la capacidad solicitada es desconocida, de lo contrario el valor de retorno refleja el estado actual de esa capacidad en el conjunto límite vigente. Nótese, una macro función,

Todas las funciones de configuración como cap_set_proc() y cap_drop_bound() devuelven cero para éxito, y -1 en fallo.

En caso de fallo, errno se establece a EINVAL, EPERM, o ENOMEM.

CONFORMIDAD

cap_set_proc() y cap_get_proc() están especificados en el borrador retirado de especificación POSIX.1e. cap_get_pid() es una extensión de Linux.

NOTAS

Ni glibc, ni el kernel de Linux honran la semántica POSIX para establecer capacidades y securebits en presencia de pthreads. Es decir, cambiar los conjuntos de capacidades, por defecto, solo afecta al hilo en ejecución. Para ser significativamente seguro, sin embargo, los conjuntos de capacidades deberían reflejarseed by all threads within a common program because threads are not memory isolated. As a workaround for this, libcap is packaged with a separate POSIX semantics system call library: libpsx. If your program uses POSIX threads, to achieve meaningful POSIX semantics capability manipulation, you should link your program with:

ld ... -lcap $(pkg-config --libs --cflags libpsx)

or,

gcc ... -lcap $(pkg-config --libs --cflags libpsx)

When linked this way, due to linker magic, libcap uses psx_syscall(3) and psx_syscall6(3) to perform state setting system calls. Notably, this also ensures that cap_prctlw() can be used to ensure process control bits are shared over all threads of a single process.

capgetp() and capsetp()

The library also supports the deprecated functions:

int capgetp(pid_t pid, cap_t cap_d);

int capsetp(pid_t pid, cap_t cap_d);

capgetp() intenta obtener las capacidades de algún otro proceso; almacenando las capacidades en un cap_dpreasignado. Véase cap_init() para información sobre cómo asignar un conjunto de capacidades vacío. Esta función está obsoleta; debería usar cap_get_pid().

capsetp() intenta establecer las capacidades del proceso que llama o de algún otro proceso, pid. Nótese que establecer las capacidades de otro proceso solo es posible en núcleos antiguos que no proporcionan soporte VFS para establecer capacidades de archivo. Véase capset(2) para información sobre qué núcleos proporcionan dicho soporte.

Si pid es positivo, se refiere a un proceso específico; si es cero, se refiere al proceso que llama; -1 se refiere a todos los procesos distintos del proceso que llama y del proceso '1' (típicamente init(8)); otros valores negativos se refieren al grupo de procesos -pid .

Para poder usar esta función, el núcleo debe soportarla y el proceso que llama debe tener CAP_SETPCAP activado en su conjunto de capacidades efectivas. Las capacidades establecidas en el proceso(s) destino son las contenidas en cap_d.

Los núcleos que soportan capacidades de sistema de archivos redefinen la semántica de CAP_SETPCAP y en dichos sistemas, capsetp() siempre fallará para cualquier destino distinto del proceso que llama. capsetp() devuelve cero en caso de éxito, y -1 en caso de fallo.

En los núcleos donde era (fue) soportada, capsetp() debería usarse con cuidado. Existía principalmente para superar una falta temprana de soporte para capacidades en los sistemas de archivos soportados por Linux. Nótese que en núcleos antiguos donde capsetp() podía usarse para establecer las capacidades de otro proceso, los únicos procesos que tenían CAP_SETPCAP disponible por defecto eran los procesos iniciados como hilos del núcleo. (Típicamente esto incluye init(8), kflushd y kswapd.) Se necesitaba una recompilación del núcleo para modificar este valor por defecto.

EJEMPLO

El segmento de código siguiente activa las CAP_FOWNER y CAP_SETFCAP capacidades efectivas para el llamante:

    ...
    cap_t caps;
    const cap_value_t cap_list[2] = {CAP_FOWNER, CAP_SETFCAP};
    if (!CAP_IS_SUPPORTED(CAP_SETFCAP))
        /* handle error */
    caps = cap_get_proc();
    if (caps == NULL)
        /* handle error */;
    if (cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET) == -1)
        /* handle error */;
    if (cap_set_proc(caps) == -1)
        /* handle error */;
    if (cap_free(caps) == -1)
        /* handle error */;
    ...

Alternativamente, para descartar completamente los privilegios en un programa lanzado con setuid-root pero que quiere ejecutarse con un ID de usuario específico, etc., de tal manera que ni él ni ninguno de sus hijos puedan adquirir privilegios de nuevo:

    ...
    uid_t nobody = 65534;
    const gid_t groups[] = {65534};
    if (cap_setgroups(groups[0], 1, groups) != 0)
        /* handle error */;
    if (cap_setuid(nobody) != 0)
        /* handle error */;
    /*
     * privilege is still available here
     */
    if (cap_set_mode(CAP_MODE_NOPRIV) != 0)
        /* handle error */
    ...

Nótese que la secuencia anterior puede realizarse con la capsh herramienta de la siguiente manera:

sudo capsh --user=nobody --mode=NOPRIV --print

donde --print muestra el estado de privilegio resultante.
