CARGO-FIX(1) Manual de Comandos Generales CARGO-FIX(1)

NOMBRE

cargo-fix — Corrige automáticamente las advertencias de lint reportadas por rustc

SINOPSIS

cargo fix [opciones]

DESCRIPCIÓN

Este subcomando de Cargo tomará automáticamente las sugerencias de rustc de diagnósticos como advertencias y las aplicará a tu código fuente. Esto está destinado a ayudar a automatizar tareas que rustc ya sabe cómo decirte que corrijas.

Ejecutar cargo fix ejecutará internamente cargo-check(1). Cualquier advertencia aplicable a tu crate será corregida automáticamente (si es posible) y todas las advertencias restantes se mostrarán cuando el proceso de verificación termine. Por ejemplo, si deseas aplicar todas las correcciones al paquete actual, puedes ejecutar:

cargo fix

que se comporta igual que cargo check --all-targets.

cargo fix solo es capaz de corregir código que normalmente se compila con cargo check. Si el código está habilitado condicionalmente con características opcionales, necesitarás habilitar esas características para que ese código sea analizado:

cargo fix --features foo

De manera similar, otras expresiones cfg como el código específico de la plataforma necesitarán pasar --target para corregir el código para el objetivo dado.

cargo fix --target x86_64-pc-windows-gnu

Si encuentras algún problema con cargo fix o tienes alguna pregunta o solicitud de características, no dudes en presentar un problema en https://github.com/rust-lang/cargo.

Migración de edición

El subcomando cargo fix también se puede usar para migrar un paquete de una edición https://doc.rust-lang.org/edition-guide/editions/transitioning-an-existing-project-to-a-new-edition.html a la siguiente. El procedimiento general es:

1.Ejecutar cargo fix --edition. Considera también usar la bandera --all-features si tu proyecto tiene múltiples características. También podrías querer ejecutar cargo fix --edition varias veces con diferentes --target banderas si tu proyecto tiene código específico de la plataforma restringido por atributos cfg .
2.Modificar Cargo.toml para establecer el campo edition https://doc.rust-lang.org/cargo/reference/manifest.html#the-edition-field a la nueva edición.
3.Ejecutar las pruebas de tu proyecto para verificar que todo siga funcionando. Si se emiten nuevas advertencias, podrías considerar ejecutar cargo fix de nuevo (sin la bandera --edition ) para aplicar cualquier sugerencia dada por el compilador.

¡Y con suerte eso es todo! Solo ten en cuenta las advertencias mencionadas anteriormente de que cargo fix no puede actualizar código para características inactivas o expresiones cfg . Además, en algunos casos raros el compilador no puede migrar automáticamente todo el código a la nueva edición, y esto puede requerir cambios manuales después de compilar con la nueva edición.

OPCIONES

Opciones de corrección

--broken-code

Corregir el código incluso si ya tiene errores del compilador. Esto es útil si cargo fix falla al aplicar los cambios. Aplicará los cambios y dejará el código roto en el directorio de trabajo para que lo examines y corrijas manualmente.

--edition

Aplicar cambios que actualizarán el código a la siguiente edición. Esto no actualizará la edición en el manifiesto Cargo.toml , que debe actualizarse manualmente después de que cargo fix --edition haya terminado.

--edition-idioms

Aplicar sugerencias que actualizarán el código al estilo preferido para la edición actual.

--allow-no-vcs

Corregir el código incluso si no se detectó un VCS.

--allow-dirty

Corregir el código incluso si el directorio de trabajo tiene cambios (incluyendo cambios en staged).

--allow-staged

Corregir el código incluso si el directorio de trabajo tiene cambios en staged.

Selección de paquetes

De manera predeterminada, cuando no se dan opciones de selección de paquetes, los paquetes seleccionados dependen del archivo de manifiesto seleccionado (basado en el directorio de trabajo actual si no se da --manifest-path ). Si el manifiesto es la raíz de un espacio de trabajo, se seleccionan los miembros predeterminados del espacio de trabajo; de lo contrario, solo se selecciona el paquete definido por el manifiesto.

Los miembros predeterminados de un espacio de trabajo pueden establecerse explícitamente con la clave workspace.default-members en el manifiesto raíz. Si esto no está establecido, un espacio de trabajo virtual incluirá todos los miembros del espacio de trabajo (equivalente a pasar --workspace), y un espacio de trabajo no virtual incluirá solo el crate raíz mismo.

-p spec…, --package spec…

Corregir solo los paquetes especificados. Ver cargo-pkgid(1) para el formato SPEC. Esta bandera puede especificarse múltiples veces y soporta patrones glob comunes de Unix como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón.

--workspace

Corregir todos los miembros en el espacio de trabajo.

--all

Alias obsoleto para --workspace.

--exclude SPEC…

Excluir los paquetes especificados. Debe usarse en conjunto con la bandera --workspace . Esta bandera puede especificarse múltiples veces y soporta patrones glob comunes de Unix como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón.

Selección de objetivos

Cuando no se dan opciones de selección de objetivos, cargo fix corregirá todos los objetivos (se implica--all-targets ). Los binarios se omiten si tienen required-features que faltan.

Pasar banderas de selección de objetivos corregirá solo los objetivos especificados.

Ten en cuenta que las banderas --bin, --example, --test y --bench también soportan patrones glob comunes de Unix como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón glob.

--lib

Corregir la biblioteca del paquete.

--bin nombre…

Corregir el binario especificado. Esta bandera puede especificarse múltiples veces y soporta patrones glob comunes de Unix.

--bins

Corregir todos los objetivos binarios.

--example nombre…

Corregir el ejemplo especificado. Esta bandera puede especificarse múltiples veces y soporta patrones glob comunes de Unix.

--examples

Corregir todos los objetivos de ejemplo.

--test nombre…

Corregir la prueba de integración especificada. Esta bandera puede especificarse múltiples veces y soporta patrones glob comunes de Unix.

--tests

Corregir todos los objetivos que tienen la bandera de manifiesto test = true establecida. De manera predeterminada esto incluye la biblioteca y los binarios construidos como unittests, y pruebas de integración. Ten en cuenta que esto también construirá cualquier dependencia requerida, por lo que el objetivo lib puede construirse dos veces (una vez como unittest, y una vez como dependencia para binarios, pruebas de integración, etc.). Los objetivos pueden habilitarse o deshabilitarse estableciendo la bandera test en la configuración del manifiesto para el objetivo.

--bench nombre…

Corregir el benchmark especificado. Esta bandera puede especificarse múltiples veces y soporta patrones glob comunes de Unix.

--benches

Corregir todos los objetivos que tienen la bandera de manifiesto bench = true establecida. De manera predeterminada esto incluye la biblioteca y los binarios construidos como benchmarques et les cibles de benchmark. Notez que cela construira également toutes les dépendances requises, de sorte que la cible lib puisse être construite deux fois (une fois comme benchmark, et une fois comme dépendance pour les binaires, benchmarks, etc.). Les cibles peuvent être activées ou désactivées en définissant le champ bench dans les paramètres du
