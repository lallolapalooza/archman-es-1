DESCRIPCIÓ

N

El soporte y uso de las capacidades de Linux pueden explorarse y restringirse con esta herramienta. Esta herr

amienta proporciona un envoltorio práctico para ciertos tipos de pruebas de capacidades y creación de en
tornos. También proporciona algunas funciones de depuración útiles para resumir el estado de las capacidades.

Establece las capacidades vigentes del proceso en las especificadas por conjunto-de-capacidades. Donde conjunto-de-capacidades es una representación textual de un `Conjunto' de capacidades según cap_text_form

efectivo.

Es decir, busca el UID y el GID del usuario con getpwuid(3) y sus membresías de grupo con getgrouplist(3) y los establece todos usando cap_setuid(3) y cap_setgroups(3). Tras este comando, las capacidades efectivas se borrarán, pero el conjunto permitido no, de modo que el programa en ejecución sigue siendo
privilegiado.

--keep=<0|
1>
En un modo de capacidades no puro, el kernel proporciona privilegios liberales al superusuario. Sin embargo, normalmente, cuando el superusuario cambia su UID a un usuario de menor privilegio, se pierden las capacidades. Para estas situaciones, el kernel puede permitir al proceso retener sus capacidades después de una llamada al sistema setuid(2). Esta característica se conoce como soporte de keep-caps. La forma de activarlo usando este programa es con este argumento. Establecer el valor a 1 hará que keep-caps esté activo. Establecerlo a 0 hará que keep-caps se desactive para el proceso actual. En todos los casos, keep-caps se desactiva cuando se realiza un exec(). Vea --secbits y--mode para formas de desactivar esta
característica.
--secbits=
N
Establece los bits de seguridad para el programa. Esto se hace usando la operación PR_SET_SECUREBITS de prctl(2). La lista de bits compatibles y su significado se puede encontrar en el archivo de cabecera <sys/secbits.h>. El programa listará estos bits mediante el comando --print. El argumento se expresa como una máscara de bits numérica, en cualquiera de los formatos permitidos por strtoul(3). Una alternativa a este manipulación de bits está incrustada en los argumentos de línea de comandos --mode*
.

El propósito de este comando es apoyar la exploración de la forma en que los procesos son asesinables ante cambios de capacidades. Vea el comando --killit. Solo puede haber un fork activo a la
vez.

1.
