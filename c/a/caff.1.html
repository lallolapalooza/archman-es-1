NOMBRE

caff -- CA - Dispara y Olvida

SINOPSIS

caff [-eERS] [-m sí|preguntar-sí|preguntar-no|no] [-u tu_id_clave] id_clave [id_clave ..]
caff [-eERS] [-m sí|preguntar-sí|preguntar-no|no] [-u tu_id_clave] [id_clave ..] </ruta/a/ksp-anotado.txt

DESCRIPCIÓN

CA Fire and Forget es un script que te ayuda en la firma de claves. Toma una lista de ids de clave en la línea de comandos, las descarga de un servidor de claves y llama a GnuPG para que puedas firmarlas. Luego envía por correo cada clave a todas sus direcciones de correo electrónico, incluyendo solo la UID que enviamos en cada correo, eliminando todas las firmas excepto las propias y las hechas por ti. La clave enviada por correo se cifra con ella misma como medio para verificar que la clave pertenece al destinatario.

La lista de claves a firmar también puede proporcionarse a través de la entrada estándar de caff, como contenido con formato de gpgparticipants(1). Solo se considerarán para firmar las claves para las que las casillas "Fingerprint OK" y "ID OK" estén marcadas (es decir, marcadas con una "x"). Además, la cabecera de entrada debe incluir al menos una línea de suma de verificación, y todas las casillas de suma de verificación deben estar marcadas como verificadas (con una "x").

OPCIONES

-e, --export-old
Exportar firmas antiguas. El valor predeterminado es preguntar al usuario por cada firma antigua.
-E, --no-export-old
No exportar firmas antiguas. El valor predeterminado es preguntar al usuario por cada firma antigua.
-m, --mail sí|preguntar-sí|preguntar-no|no
Si enviar correo después de firmar. El valor predeterminado es preguntar, para cada uid, con un valor predeterminado de sí.
-R, --no-download
No recuperar la clave a firmar de un servidor de claves.
-S, --no-sign
No firmar las claves.
-u tu_id_clave, --local-user tu_id_clave
Seleccionar la clave que se utiliza para firmar, en caso de que tengas más de una clave. Para firmar con múltiples claves a la vez, separa los ids de clave con comas. Esta opción requiere que las claves estén definidas a través de la variable keyid en el archivo de configuración.
--key-file archivo
Importar claves desde el archivo. Se puede suministrar más de una vez.
--keys-from-gnupg
Intentar importar claves desde tus anillos de claves GnuPG estándar.
--debug
Habilitar mensajes de depuración.

AMBIENTE

HOME
El directorio principal predeterminado.
GNUPGBIN
El binario gpg. Predeterminado: "gpg".
GNUPGHOME
El directorio de trabajo predeterminado para gpg. Predeterminado: "$HOME/.gnupg".

ARCHIVOS

$HOME/.caffrc - archivo de configuración
$HOME/.caff/keys/yyyy-mm-dd/ - claves procesadas
$HOME/.caff/gnupghome/ - directorio de trabajo de caff para gpg
$HOME/.caff/gnupghome/gpg.conf - configuración de gpg (ver NOTAS abajo)
opciones útiles incluyen use-agent, keyserver, keyserver-options, default-cert-level, etc.

OPCIONES DE ARCHIVO DE CONFIGURACIÓN

El archivo de configuración es un script de perl que establece valores en el hash %CONFIG. El archivo se genera cuando no existe.

Ejemplo:

$CONFIG{'owner'} = q{Peter Palfrader};
$CONFIG{'email'} = q{peter@palfrader.org};
$CONFIG{'keyid'} = [ qw{DE7AAF6E94C09C7F 62AF4031C82E0039} ];

Configuración básica requerida

owner [cadena]
Tu nombre. REQUERIDO.
email [cadena]
Tu dirección de correo electrónico, utilizada en las líneas From:. REQUERIDO.
keyid [lista de ids de clave]
Una lista de tus claves. Esto se utiliza para determinar qué firmas mantener en el paso de eliminación. Si seleccionas una clave usando -u debe estar en esta lista. REQUERIDO.

Configuración general

caffhome [cadena]
Directorio base para los archivos que almacena caff. Predeterminado: $HOME/.caff/.
colors [hash]
Cómo colorear los mensajes de salida. Consulta la documentación de "Term::ANSIColor" para ver la lista de colores soportados; la salida coloreada puede ser deshabilitada estableciendo esta opción a un hash vacío {}. Predeterminado: 
{ error => 'bold bright_red'
, warn => 'bright_red'
, notice => 'bold'
, info => ''
, success => 'green' # usado en combinación con 'notice' e 'info'
, fail => 'yellow'   # usado en combinación con 'notice' e 'info'
}

Configuración de GnuPG

gpg [cadena]
Ruta al binario GnuPG. Predeterminado: El valor de la variable de entorno GNUPGBIN si está definida, de lo contrario "gpg".
secret-keyring [cadena]
Ruta a tu anillo de claves secreto (GnuPG < 2.1), o al GnuPGHOME del agente que gestiona el material de clave secreta (GnuPG >= 2.1). Predeterminado: $HOME/.gnupg/secring.gpg. Si el valor no es un directorio con GnuPG >= 2.1, se considera el directorio padre (es decir, $HOME/.gnupg por defecto).
also-encrypt-to [id de clave, o lista de ids de clave]
Ids de clave adicionales a las que cifrar mensajes. Predeterminado: ninguno.
gpg-sign-type [cadena]
El prefijo del comando "sign" utilizado para hacer la firma desde la shell de gpg. Puede establecerse a una combinación de "l" (local), "nr" (no revocable) o "t" (confiable) para hacer una firma del tipo dado. Ver gpg(1) para más detalles. Predeterminado: "" (es decir, hacer una firma regular y exportable).
gpg-sign-args [cadena]
Comandos adicionales para pasar a gpg después del comando "sign". Predeterminado: ninguno.

Configuración de importación de claves

no-download [booleano]
Si es verdadero, entonces omite el paso de obtener claves del servidor de claves. Predeterminado: 0.
key-files [lista de archivos]
Una lista de archivos que contienen claves a importar.

Configuración de firma

no-sign [booleano]
Si es verdadero, entonces omite el paso de firma. Predeterminado: 0.
ask-sign [booleano]
Si es verdadero, pregunta por cada clave si debe ser firmada. Predeterminado: 1.

Configuración de envío de correo

mail-type [string]
Determina cómo se envían los correos. Puede ser "normal" o "encrypted". Predeterminado: "encrypted".
mail-from [string]
La dirección de correo electrónico utilizada en la línea From: del correo. Se utiliza la configuración email por defecto si no se establece ninguna.
mail-subject [string]
El asunto del correo electrónico. Predeterminado: "Your Signed OpenPGP Key".

Configuración de la interfaz de usuario

ask-yes [booleano]
Si es verdadero, responde automáticamente "sí" a las preguntas de confirmación. Predeterminado: 0.
ask-no [booleano]
Si es verdadero, responde automáticamente "no" a las preguntas de confirmación. Predeterminado: 0.

NOTAS

Este script es una herramienta de ayuda para firmar claves, no una herramienta de administración de claves.

El archivo gpg.conf que se crea en el directorio de trabajo de caff se configura de la siguiente manera:

keyserver hkp://keys.openpgp.org
keyserver-options auto-key-retrieve,trust-model=perfect
# Para GnuPG 2.1 y posteriores
default-cert-level=3

Si estás firmando claves para otros, entonces necesitas activar las firmas locales:

$CONFIG{'gpg-sign-type'} = q{l};

La línea keyserver-options se puede ajustar para usar un servidor de claves específico:

$CONFIG{'keyserver-options'} = q{keyserver-options ca.pool.sks-keyservers.net};

Por defecto, la firma se hace con el estilo de firma más simple posible (no local, exportable y verificable). Para generar una firma local, necesitarás la opción gpg-sign-type:

$CONFIG{'gpg-sign-type'} = q{l};

Si deseas que caff envíe las claves firmadas a tu propio correo electrónico, entonces necesitas añadir tu clave a also-encrypt-to.

Para que el cifrado de la clave firmada funcione, tu clave debe estar disponible para GnuPG, ya sea en el anillo de claves por defecto o a través de la opción secret-keyring.

EJEMPLO

Para firmar la clave de Peter Palfrader (keyid DE7AAF6E94C09C7F) usando tu propia clave (keyid 62AF4031C82E0039) y enviarla por correo a todas las direcciones de correo de Peter:

caff -u 62AF4031C82E0039 DE7AAF6E94C09C7F

O bien, puedes leer las claves a firmar desde un archivo:

caff -u 62AF4031C82E0039 < /path/to/file.txt

Para firmar solo localmente y no enviar por correo:

caff -u 62AF4031C82E0039 -m no DE7AAF6E94C09C7F

CONFIGURATION FILE OPTIONS

The configuration file is expected to be $HOME/.caff/caffrc. If it does not exist, it is created. The configuration file is a perl data structure, which is loaded using do().

Signing options

pause-before-signing [boolean]
Si es verdadero, entonces pausa antes de continuar al paso de firma. Esto es útil para la firma sin conexión. Por defecto: 0.
export-sig-age [segundos]
No exportar UIDs por defecto, cuya firma más reciente tenga una antigüedad mayor a este valor. Por defecto: 24*60*60 (es decir, un día).
local-user [id de clave, o lista de ids de clave]
Selecciona la clave que se utilizará para firmar, en caso de que tengas más de una clave. Con múltiples ids de clave, firma con cada clave por turno.
also-lsign-in-gnupghome [auto|ask|no]
Si firmar localmente las UIDs en el GnuPGHOME del usuario, además de las firmas de caff en su propio GnuPGHOME. Dichas firmas no son exportables. Esto puede ser útil cuando el destinatario olvida subir las firmas que caff envió (o si también no son exportables), ya que proporciona una forma de mantener un registro de qué UIDs fueron verificadas. Sin embargo, ten en cuenta que las firmas locales no se eliminarán una vez que el destinatario complete la carga y el firmante actualice su llavero.

Si el valor no es no y si gpg-sign-type contiene "l", cada firma (local) simplemente se exporta del propio GnuPGHOME de caff al del usuario. De lo contrario, si el valor es auto, cada UID firmada en el propio GnuPGHOME de caff se firma automáticamente localmente en el del usuario, utilizando el mismo nivel de certificación; esto requiere un gpg-agent(1) que funcione. Si es ask, se le pregunta al usuario qué UIDs firmar localmente. Por defecto: no.

show-photos [booleano]
Si es verdadero, entonces antes de firmar una clave, gpg mostrará las fotos adjuntas a ella, si las hay. (El visor de fotos se puede especificar con la opción "photo-viewer" en el GnuPGHOME de caff.) Por defecto: 0.

Configuración de correo

mail [yes|ask-yes|ask-no|no]
Si enviar correos. Esta es una opción cuádruple, con la que puedes establecer el comportamiento: yes siempre envía, no nunca envía; ask-yes y ask-no pregunta, por cada uid, con los valores por defecto correspondientes para la pregunta. Por defecto: ask-yes.

En cualquier caso, los mensajes también se escriben en $CONFIG{'caffhome'}/keys/

mail-cant-encrypt [yes|ask-yes|ask-no|no]
El valor de esta opción se considera en lugar del de mail para claves de destinatario sin capacidad de cifrado. Por defecto, toma el valor de mail.
mail-subject [cadena]
Establece el valor del campo de encabezado "Subject:". %k se expandirá al ID de clave largo de la clave firmada. Por defecto: "Tu clave PGP firmada 0x%k".
mail-template [cadena]
Plantilla de correo electrónico que se utiliza como texto del cuerpo para el correo enviado en lugar del texto predeterminado si se especifica. Las siguientes variables de perl se pueden usar en la plantilla:
{owner} [cadena]
Tu nombre tal como se especifica en la configuración owner.
{key} [cadena]
El id de clave que firmaste.
{@uids} [array]
Las UIDs para las cuales se incluyen firmas en el correo.

Ten en cuenta que probablemente deberías personalizar la plantilla si tienes la intención de enviar firmas no exportables (es decir, si gpg-sign-type contiene "l"), ya que la carga de dichas firmas no tiene sentido y requieren la opción de importación "import-local-sigs" que no está configurada por defecto.

reply-to [cadena]
Añade un encabezado Reply-To: a los mensajes enviados. Por defecto: ninguno.
bcc [cadena]
Dirección a la que se enviarán copias ocultas al enviar correo. Por defecto: ninguna.
mailer-send [array]
Parámetros para pasar a Mail::Mailer. Por defecto: ninguno. Se desaconseja encarecidamente el establecimiento de esta opción: soluciona tu MTA local en su lugar.

Esto podría ser, por ejemplo:

$CONFIG{'mailer-send'} =  [ 'smtp', Server => 'mail.server', Auth => ['user', 'pass'] ];

para usar el cliente SMTP de perl, o

$CONFIG{'mailer-send'} =  [ 'sendmail', '-f', $CONFIG{'email'}, '-it' ];

para pasar argumentos al programa sendmail. Para especificar un binario de sendmail, puedes establecer la variable de entorno "PERL_MAILERS" de la siguiente manera:

$ENV{'PERL_MAILERS'} = 'sendmail:/path/to/sendmail_compatible_mta';

Para más información, consulta Mail::Mailer(3pm).

NOTAS

Como se mencionó anteriormente, caff utiliza su propio GnuPGHOME y archivo de configuración de GnuPG. De hecho, solo necesita su propio llavero para el trabajo de firma, pero sería inseguro reutilizar el mismo archivo de configuración de GnuPG porque el usuario podría haber configurado una opción en $HOME/.gnupg/gpg.conf que rompería caff.

Por lo tanto, las opciones de GnuPG que están destinadas a ser utilizadas con caff, como "keyserver" o "cert-digest-algo", deben colocarse en $HOME/.caff/gnupghome/gpg.conf en su lugar. Si este archivo no existe, las opciones de GnuPG encontradas en $HOME/.gnupg/gpg.conf que se sabe que son seguras (y útiles) para caff, se pasan a gpg(1) como opciones de línea de comandos.
