CATOPEN(3P) Manual del programador POSIX CATOPEN(3P)

PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

catopen — abrir un catálogo de mensajes

SINOPSIS

#include <nl_types.h>
nl_catd catopen(const char *name, int oflag);

DESCRIPCIÓN

La función catopen() abrirá un catálogo de mensajes y devolverá un descriptor de catálogo de mensajes. El argumento name especifica el nombre del catálogo de mensajes que se va a abrir. Si name contiene un '/', entonces name especifica una ruta para el catálogo de mensajes. De lo contrario, la variable de entorno NLSPATH se usará con name sustituido por la especificación de conversión %N (consulte el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 8, Variables de entorno); si NLSPATH existe en el entorno cuando el proceso se inicia, entonces si el proceso tiene privilegios apropiados, el comportamiento de catopen() no está definido. Si NLSPATH no existe en el entorno, o si no se puede encontrar un catálogo de mensajes en ninguno de los componentes especificados por NLSPATH, se utilizará una ruta predeterminada definida por la implementación. Esto puede verse afectado por la configuración de LC_MESSAGES si el valor de oflag es NL_CAT_LOCALE, o por la variable de entorno LANG si oflag es 0.

Un descriptor de catálogo de mensajes permanecerá válido en un proceso hasta que ese proceso lo cierre, o hasta una llamada exitosa a una de las funciones exec. Un cambio en la configuración de la categoría LC_MESSAGES puede invalidar catálogos abiertos existentes.

Si se utiliza un descriptor de archivo para implementar los descriptores de catálogo de mensajes, se establecerá la bandera FD_CLOEXEC; consulte <fcntl.h>.

Si el valor del argumento oflag es 0, la variable de entorno LANG se utiliza para localizar el catálogo sin tener en cuenta la categoría LC_MESSAGES. Si el argumento oflag es NL_CAT_LOCALE, la categoría LC_MESSAGES se utiliza para localizar el catálogo de mensajes (consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización).

VALOR DE RETORNO

Tras una finalización exitosa, catopen() devolverá un descriptor de catálogo de mensajes para su uso en llamadas posteriores a catgets() y catclose(). De lo contrario, catopen() devolverá (nl_catd) -1 y establecerá errno para indicar el error.

ERRORES

La función catopen() puede fallar si:

EACCES
Se deniega el permiso de búsqueda para el componente del prefijo de ruta del catálogo de mensajes o se deniega el permiso de lectura para el catálogo de mensajes.
EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.
ENAMETOOLONG

La longitud de un componente de una ruta es mayor que {NAME_MAX}.
ENAMETOOLONG

La longitud de una ruta excede {PATH_MAX}, o la resolución de una ruta simbólica produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
ENFILE
Hay demasiados archivos abiertos actualmente en el sistema.
ENOENT
El catálogo de mensajes no existe o el argumento name apunta a una cadena vacía.
ENOMEM
No hay suficiente espacio de almacenamiento disponible.
ENOTDIR
Un componente del prefijo de ruta de los nombres de catálogo de mensajes es un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o la ruta del catálogo de mensajes contiene al menos un carácter que no es <<barra>> y termina con uno o más <<barras>> finales y el último componente de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.

USO DE APLICACIONES

Algunas implementaciones de catopen() utilizan malloc() para asignar espacio para áreas de búfer internas. La función catopen() puede fallar si no hay suficiente espacio de almacenamiento disponible para alojar estos búferes.

Las aplicaciones que cumplen deben asumir que los descriptores de catálogo de mensajes no son válidos después de una llamada a una de las funciones exec.

Los desarrolladores de aplicaciones deben tener en cuenta que las directrices para la ubicación de los catálogos de mensajes aún no se han desarrollado. Por lo tanto, deben tener cuidado de evitar conflictos con catálogos utilizados por otras aplicaciones y utilidades estándar.

Para asegurarse de que los mensajes producidos por una aplicación que se ejecuta con privilegios apropiados no puedan ser utilizados por un atacante que establezca un valor inesperado para NLSPATH en el entorno para confundir a un administrador del sistema, dichas aplicaciones deben utilizar rutas que contengan un '/' para obtener un comportamiento definido al usar catopen() para abrir un catálogo de mensajes.
