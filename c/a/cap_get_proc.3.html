L'appelant doit libérer toute mémoire libérable lorsque l'état de capacités dans la mémoire de travail n'est plus requis, en appelant cap_free() avec le cap_t comme argument. cap_set_proc() définit les valeurs de tous les indicateurs de capacités pour toutes les capacités de l'état de

Si un indicateur dans cap_p est défini pour une capacité actuellement non autorisée pour le processus appelant, la fonction échouera et l'état de capacités du processus restera inchangé. cap_get_pid() renvoie un cap_t, voir cap_init(3), avec les capacités du processus connu de l'appelant sous le nom de pid. Lorsque l'appelant opère dans un espace de noms ( CLONE_NEWPID), l'argument numérique pid est interprétédans la plage de cet espace de noms. De plus, la valeur cap_t renvoyée contient les capacités que la pid cible pense avoir. Si la cible opère dans un espace de noms ( CLONE_NEWUSER), le privilège global de ces capacités d'espace de noms utilisateur peut être considérablement réduit. C'est-à-dire que la modification des ensembles de capacités n'affecte par défaut que le thread en cours d'exécution. Pour être significativement sûr, cependant, les ensembles de capacités doivent être répliqués por todos los hilos dentro de un programa común porque los hilos no están aislados en memoria. capgetp() y

capsetp()

La biblioteca también soporta las funciones

obsoletas:

int capgetp(pid_t pid, cap_t cap_d)

;

int capsetp(pid_t pid, cap_t cap_d)

;

capgetp() intenta obtener las capacidades de algún otro proceso; almacenando las capacidades en un cap_d preasignado. Vea cap_init() para información sobre cómo asignar un conjunto de capacidades vacío. Esta función está obsoleta; debería usar cap_get_p

id().

capsetp() intenta configurar las capacidades del proceso que llama o de algún otro proceso(s), pid. Tenga en cuenta que configurar las capacidades de otro proceso solo es posible en núcleos más antiguos que no proporcionan soporte VFS para configurar capacidades de archivos. Vea capset(2) para información sobre qué núcleos proporcionan dicho

soporte.

Si pid es positivo, se refiere a un proceso específico; si es cero, se refiere al proceso que llama; -1 se refiere a todos los procesos distintos del proceso que llama y del proceso '1' (típicamente init(8)); otros valores negativos se refieren al grupo de procesos

-pid.

Para usar esta función, el núcleo debe soportarla y el proceso que llama debe tener CAP_SETPCAP activado en su conjunto de capacidades Efectivas. Las capacidades configuradas en el(los) proceso(s) objetivo son las contenidas en cap_d

.

Los núcleos que soportan capacidades del sistema de archivos redefinen la semántica de CAP_SETPCAP y en tales sistemas, capsetp() siempre fallará para cualquier objetivo distinto del proceso que llama. capsetp() devuelve cero si tiene éxito, y -1 en caso de

fallo.

En núcleos donde era (fue) soportado, capsetp() debe usarse con cuidado. Existía principalmente para superar una falta temprana de soporte para capacidades en los sistemas de archivos soportados por Linux. Tenga en cuenta que en núcleos más antiguos donde capsetp() podía usarse para configurar las capacidades de otro proceso, los únicos procesos que tenían CAP_SETPCAP disponible por defecto eran procesos iniciados como hilos del núcleo. (Típicamente esto incluye a init(8), kflushd y kswapd.) Se necesitaba una
