DESCRIPCIÓN

Estas funciones principales operan sobre un estado de capacidades almacenado en memoria de trabajo e intentan completar la API de espacio de usuario POSIX.1e (borrador) para el privilegio basado en capacidades.

Un cap_t contiene información sobre las capacidades en cada uno de los tres conjuntos: Permitted (Permitidas), Inheritable (Heredables) y Effective (Efectivas). Cada capacidad en un conjunto puede estar limpia (deshabilitada, 0) o establecida (habilitada, 1).

Estas funciones trabajan con los siguientes tipos de datos:

cap_value_t
identifica una capacidad, como CAP_CHOWN.
cap_flag_t
identifica uno de los tres indicadores asociados con una capacidad (es decir, identifica uno de los tres conjuntos de capacidades). Los valores válidos para este tipo son CAP_EFFECTIVE, CAP_INHERITABLE o CAP_PERMITTED.
cap_flag_value_t
identifica la configuración de un indicador de capacidad particular (es decir, el valor de una capacidad en un conjunto). Los valores válidos para este tipo son CAP_CLEAR(0) o CAP_SET(1).

VALOR DE RETORNO

El valor de retorno es generalmente específico de la función individual llamada. En caso de fallo, errno se establece adecuadamente.

CONFORMIDAD

Estas funciones son según la especificación del borrador POSIX.1e retirado. Las siguientes funciones son extensiones de Linux: cap_clear_flag(), cap_drop_bound(), cap_fill(), cap_fill_flag(), cap_from_name(), cap_get_ambient(), cap_get_bound(), cap_get_mode(), cap_get_nsowner(), cap_get_secbits(), cap_mode_name(), cap_proc_root(), cap_prctl(), cap_prctlw(), cap_reset_ambient(), cap_setgroups(), cap_setuid(), cap_set_ambient(), cap_set_mode(), cap_set_nsowner(), cap_set_secbits(), cap_to_name() y cap_compare().

Una extensión de Linux, IAB, de vectores de capacidades de tuplas Inheritable (Heredable), Bounding (Límite) y Ambient (Ambiental) también es soportada por libcap. Esas funciones se describen en una página de manual complementaria: cap_iab(3). Además, para manejar la complejidad de lanzar un subproceso, libcap soporta la abstracción: cap_launch(3).

Además de la API de libcap con el prefijo cap_ , la biblioteca también proporciona prototipos para las llamadas al sistema de Linux que proporcionan la API nativa para las capacidades de los procesos. Estos prototipos son:

int capget(cap_user_header_t header, cap_user_data_t data);
int capset(cap_user_header_t header, const cap_user_data_t data);

Además, libcap proporciona una función de configuración,

void cap_set_syscall(
        long int (*new_syscall)(long int, long int, long int, long int),
        long int (*new_syscall6)(long int,
                                 long int, long int, long int,
                                 long int, long int, long int));

que puede usarse para redirigir su uso de capset() y otras llamadas al sistema que escriben estado gestionado por el kernel. Esto es especialmente útil al soportar semánticas POSIX para el estado de seguridad. Cuando un programa se enlaza contra libpsx(3) como se describe en esa página de manual, esta función se usa para conectar libcap a las llamadas al sistema con semántica POSIX.
