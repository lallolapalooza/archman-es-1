NAME

cargo-yank 1

Yank a published crate from the index

SYNOPSIS

cargo yank [OPTIONS] CRATE@VERSION

cargo yank [OPTIONS] CRATE@VERSION --undo

DESCRIPTION

This command removes a specific version of a published crate from the index. This means that new projects will not be able to depend on this version, but existing projects that depend on it will still be able to compile. This is useful for removing crates that have security vulnerabilities or are fundamentally broken.

To un-yank a crate version (making it available to new projects again), use the --undo flag.

This command requires that you are logged in via cargo login.

This command requires that the crate is published to the default registry, crates.io. You cannot yank crates from other registries.

When a crate version is yanked, it is removed from the default registry (crates.io). If you need to yank a crate from a different registry, you will need to specify the registry with the --registry option.

To determine which versions are yanked, you can use the cargo search --limit 1000 foo command. Yanked versions will have a yanked field set to true.

The cargo yank command requires the crate name and version to be specified as an argument. The version can be specified with or without the crate name. If the crate name is not specified, then the crate name is inferred from the current directory's Cargo.toml file.

You can specify the crate name and version as follows:

cargo yank my-crate@1.0.0

You can also specify the crate name and version separated by a space:

cargo yank my-crate 1.0.0

If the crate name is not specified, then the crate name is inferred from the current directory's Cargo.toml file.

You can also specify the registry to use with the --registry option.

For more information on publishing crates, see the cargo-publish(1) man page.

For more information on yanking crates, see the yank section of the Cargo book.

For more information on Cargo configuration, see the cargo-config(5) man page.

OPTIONS

--index URL

The URL of the registry index to use. Defaults to the index URL specified in the registry configuration. This option is only available on the nightly channel https://doc.rust-lang.org/book/appendix-07-nightly-rust.html and requires the -Z unstable-options flag to enable.

--registry NAME

The registry to use. Defaults to "default". See cargo-login(1) for more information.

--undo

Un-yank the specified version. This makes the version available to new projects again.

-C PATH

Changes the current working directory before executing any specified operations. This affects things like where cargo looks by default for the project manifest (Cargo.toml), as well as the directories searched for discovering .cargo/config.toml, for example. This option must appear before the command name, for example cargo -C path/to/my-project build.

This option is only available on the nightly channel https://doc.rust-lang.org/book/appendix-07-nightly-rust.html and requires the -Z unstable-options flag to enable (see #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Prints help information.

-Z flag

Unstable (nightly-only) flags to Cargo. Run cargo -Z help for details.

ENVIRONMENT

See the reference https://doc.rust-lang.org/cargo/reference/environment-variables.html for details on environment variables that Cargo reads.

EXIT STATUS

•0: Cargo succeeded.
•101: Cargo failed to complete.

EXAMPLES

cargo yank foo@1.0.7
