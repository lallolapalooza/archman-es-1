de proceso heredables de forma simple: Inh, Amb y Bound. Esta tupla IAB de 3 componentes de vectores de capacidades, capturada en el tipo cap_iab_t, se combinan para pasar capacidades de un proceso a otro a través de llamadas al sistema execve(2). Las reglas de convolución que usan la tupla IAB son un conjunto de reglas de respaldo cuando el archivo ejecutado no tiene file-capabilities configuradas. El kernel impone algunas restri

cciones

con respecto a los tres componentes de una tupla IAB y el indicador de capacidad de proceso Permitted. Son: el vector Inh ( CAP_IAB_INH) es completamente igual al indicadorInheritable del proceso en todo momento; el vector Amb ( CAP_IAB_AMB) no contiene más valores decapacidad que la intersección del vector Inh y el indicador Permitted del proceso; y el vector Bound (o bloqueado) ( CAP_IAB_BOUND) es el complemento a dos del vector de límitesdel proceso. En algunos entornos, se considera deseable heredar

capacidades

de forma simple. Es decir, pasar capacidades, independientemente del estado del binario ejecutado, del padre al hijo a través de llamadas al sistema exec*. Las capacidades sobrevivientes se convierten en el indicador Permitted para el proceso post-exec. Este método de herencia difiere significativamente de la herencia por acuerdo entre un proceso pre-exec* y un ejecutable con capacidades de archivo otorgadas del mecanismo de capacidades tradicional (POSIX.1e). Las reglas de convolución para la herencia de estilo

HISTORI

A

El formato IAB para las variantes heredables de capacidades se desarrolló primero como la sintaxis de configuración para el módulo pam_cap.so de Linux-PAM en libcap-2.29. Se introdujo para extender la lista simple separada por comas de capacidades Inheritables del proceso, que el módulo podía otorgar a un árbol de procesos autenticado, para incluir límites aplicados al vector Bounding y introducir soporte para el vector Ambient de bits de capacidad. Aunque

los

vectores Inheritable y Bounding fueron anticipados por el borrador POSIX.1e que introdujo las capacidades, el vector Ambient es una invención de Linux, e incompatible con el modelo de capacidades de archivo POSIX.1e. Como tal, se consideró que intentar fusionar todos los 5 vectores de capacidades en una representación de texto no iba a funcionar. En su lugar, la sintaxis de configuración de pam_cap.so se generalizó en todo un conjunto de funciones de libcap para agrupar juntas las tres capa

cidades heredables de forma simple: la tupla IAB.
El soporte para esto debutó en libcap-2.33. INFORME DE
