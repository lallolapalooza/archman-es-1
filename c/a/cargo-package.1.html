NOMBRE

cargo-package — Ensambla el paquete local en un archivo distribuible

SINOPSIS

cargo package [opciones]

DESCRIPCIÓN

Este comando creará un archivo .crate distribuible y comprimido con el código fuente del paquete en el directorio actual. El archivo resultante se almacenará en el directorio target/package. Esto realiza los siguientes pasos:

1.Carga y verifica el espacio de trabajo actual, realizando algunas comprobaciones básicas.
•Las dependencias de ruta no están permitidas a menos que tengan una clave de versión. Cargo ignorará la clave de ruta para dependencias en paquetes publicados. Las dev-dependencies no tienen esta restricción.
2.Crea el archivo .crate comprimido.
•El archivo Cargo.toml original se reescribe y normaliza.
•Las secciones [patch], [replace] y [workspace] se eliminan del manifiesto.
•Cargo.lock siempre se incluye. Cuando falta, se generará un nuevo archivo de bloqueo a menos que se use la opción --exclude-lockfile. cargo-install(1) utilizará el archivo de bloqueo empaquetado si se usa la opción --locked.
•Se incluye un archivo .cargo_vcs_info.json que contiene información sobre el hash del checkout actual del VCS si está disponible, así como una bandera si el árbol de trabajo está modificado.
•Los enlaces simbólicos se aplanan a sus archivos de destino.
•Los archivos y directorios se incluyen o excluyen según las reglas mencionadas en los campos [include] y [exclude] https://doc.rust-lang.org/cargo/reference/manifest.html#the-exclude-and-include-fields.
3.Extrae el archivo .crate y lo compila para verificar que se pueda compilar.
•Esto recompilará tu paquete desde cero para asegurar que se pueda compilar desde un estado limpio. La opción --no-verify se puede usar para omitir este paso.
4.Verifica que los scripts de compilación no hayan modificado ningún archivo fuente.

La lista de archivos incluidos se puede controlar con los campos include y exclude en el manifiesto.

Consulte la referencia https://doc.rust-lang.org/cargo/reference/publishing.html para más detalles sobre empaquetado y publicación.

formato de .cargo_vcs_info.json

Generará un .cargo_vcs_info.json en el siguiente formato

{
 "git": {
   "sha1": "aac20b6e7e543e6dd4118b246c77225e3a3a1302",
   "dirty": true
 },
 "path_in_vcs": ""
}

dirty indica que el árbol de trabajo de Git estaba modificado cuando se compiló el paquete.

path_in_vcs se establecerá en una ruta relativa al repositorio para paquetes en subdirectorios del repositorio de control de versiones.

La compatibilidad de este archivo se mantiene bajo la misma política que la salida JSON de cargo-metadata(1).

Tenga en cuenta que este archivo proporciona una instantánea del mejor esfuerzo de la información del VCS. Sin embargo, no se garantiza la procedencia del paquete. No hay garantía de que el código fuente en el archivo tar coincida con la información del VCS.

OPCIONES

Opciones de Paquete

-l, --list

Imprime los archivos incluidos en un paquete sin crear uno.

--no-verify

No verifiques el contenido compilándolo.

--no-metadata

Ignora las advertencias sobre la falta de metadatos utilizables por humanos (como la descripción o la licencia).

--allow-dirty

Permite empaquetar directorios de trabajo con cambios no confirmados en el VCS.

--exclude-lockfile

No incluya el archivo de bloqueo al empaquetar.

Esta opción no es para uso general. Algunas herramientas pueden esperar que haya un archivo de bloqueo presente (por ejemplo, cargo install --locked). Considere otras opciones antes de usar esta.

--index índice

La URL del índice del registro a usar.

--registry registro

Nombre del registro para el cual empaquetar; consulte cargo publish --help para más detalles sobre la configuración de nombres de registro. Los paquetes no se publicarán en este registro, pero si estamos empaquetando varios crates interdependientes, se generarán archivos de bloqueo asumiendo que las dependencias se publicarán en este registro.

--message-format fmt

Especifica el formato del mensaje de salida. Actualmente, solo funciona con --list y afecta al formato de la lista de archivos. Esto no es estable y requiere -Zunstable-options. Formatos de salida válidos:
•human (predeterminado): Muestra en un formato de archivo por línea.
•json: Emite información legible por máquina en formato JSON sobre cada paquete. Un paquete por línea JSON (JSON delimitado por nueva línea). 
{
  /* El Especificador de ID del Paquete. */
  "id": "path+file:///home/foo#0.0.0",
  /* Archivos de este paquete */
  "files" {
    /* Ruta relativa en el archivo de archivo. */
    "Cargo.toml.orig": {
      /* De dónde proviene el archivo.
         - "generate" para archivos que se generan durante el empaquetado
         - "copy" para archivos que se copian desde otra ubicación.
      */
      "kind": "copy",
      /* Para el tipo "copy",
         es una ruta absoluta al contenido real del archivo.
         Para el tipo "generate",
         es el archivo original en el que se basa el generado.
      */
      "path": "/home/foo/Cargo.toml"
    },
    "Cargo.toml": {
      "kind": "generate",
      "path": "/home/foo/Cargo.toml"
    },
    "src/main.rs": {
      "kind": "copy",
      "path": "/home/foo/src/main.rs"
    }
  }
}

Selección de Paquete

Por defecto, cuando no se proporcionan opciones de selección de paquetes, los paquetes seleccionados dependen del archivo de manifiesto seleccionado (basado en el directorio de trabajo actual si no se proporciona --manifest-path). Si el manifiesto es la raíz de un espacio de trabajo, se seleccionan los miembros predeterminados del espacio de trabajo, de lo contrario, solo se seleccionará el paquete definido por el manifiesto.

Los miembros predeterminados de un espacio de trabajo se pueden establecer explícitamente con la clave workspace.default-members en el manifiesto raíz. Si esto no está configurado, un espacio de trabajo virtual incluirá todos los miembros del espacio de trabajo (equivalente a pasar --workspace), y un espacio de trabajo no virtual incluirá solo el crate raíz.

-p espec…, --package espec…

Empaqueta solo los paquetes especificados. Consulte cargo-pkgid(1) para el formato SPEC. Esta opción se puede especificar varias veces y admite patrones de glob de Unix comunes como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente los patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón.

--workspace

Empaqueta todos los miembros del espacio de trabajo.

--exclude ESPEC…

Excluye los paquetes especificados. Debe usarse en conjunción con la opción --workspace. Esta opción se puede especificar varias veces y admite patrones de glob de Unix comunes como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente los patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón.

NAME

cargo-package - Compile a local package and produce a .crate file

SYNOPSIS


cargo package [OPTIONS... ]

DESCRIPTION

This command compiles the current package and creates a compressed tarball (crates.io format, a .crate file). This is useful for checking how your package will look when published, or for distributing your package manually.

The created .crate file will be located in the target/package directory.

OPTIONS

All the generic cargo(1) options are available:

  • —allow-dirty
  • —bin <NAME>
  • —jobs <NUM>, -j <NUM>
  • —manifest-path <PATH>
  • —no-default-features
  • —features <FEATURES>
  • —all-features
  • —target <TRIPLE>
  • —release, -r
  • —profile <PROFILE_NAME>
  • —ignore-rust-version
  • —timely-exit
  • —help

See cargo(1) for more information about these options.

ENVIRONMENT

See cargo(1) for information on environment variables.

EXIT STATUS

Exit status is 0 if the package was compiled successfully, and non-zero otherwise.

EXAMPLES

1.Create a compressed .crate file of the current package: 
cargo package
