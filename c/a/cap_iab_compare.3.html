Esta tupla IAB de tres vectores de capacidades, capturada en el tipo cap_iab_t se combinan para pasar capacidades de un proceso a otro a través de execve(2) llamadas al sistema. Las reglas de convolución que utilizan la tupla IAB son un conjunto de reglas de respaldo cuando el archivo ejecutado no tiene file-capabilities. El kernel impone algunas restriccion

es con

respecto a los tres componentes de una tupla IAB y el indicador de capacidades de proceso Permitted. Son: el vector Inh ( CAP_IAB_INH) es completamente igual al indicador Inheritabledel proceso en todo momento; el vector Amb ( CAP_IAB_AMB) no contiene más valores de capacidad quela intersección del vector Inh y el indicador Permitted para el proceso; y el vector Bound (o blocked) vector ( CAP_IAB_BOUND) es el complemento a dos del vector de límitesdel proceso. En algunos entornos, se considera deseable heredar

capacidades

de forma ingenua. Es decir, pasar capacidades, independientemente del estado del binario ejecutado, del padre al hijo a través de exec* llamadas al sistema. Las capacidades sobrevivientes se convierten en el indicador Permitted para el proceso post-exec. Este método de herencia difiere significativamente de la herencia por acuerdo entre un proceso pre-exec* y un ejecutable con capacidades de archivo otorgadas del mecanismo de capacidades tradicional (POSIX.1e). HISTORIA El formato IAB para las variantes heredables de las capacidades se desarrolló por primera vez como la sintaxis de configuración para el módulo pam_cap.so de Linux-PAM en libcap-2.29. Se introdujo para extender la lista simple separada por comas de capacidades Inheritable del proceso, que el módulo podía otorgar a un árbol de procesos autenticado, para incluir límites aplicados al vector Bounding y introducir soporte para el vector Ambient de bits de

capacidad.

Aunque los vectores Inheritable y Bounding fueron anticipados por el borrador POSIX.1e que introdujo las capacidades, el vector Ambient es una invención de Linux, e incompatible con el modelo de capacidades de archivo POSIX.1e. Como tal, se pensó que intentar fusionar los 5 vectores de capacidades en una representación de texto no iba a funcionar. En su lugar, la sintaxis de configuración de pam_cap.so se generalizó en un conjunto completo de funciones de libcap para agrupar las tres

capacidades heredables de forma ingenua: la tupla IAB.
El soporte para esto debutó en libcap-2.33. INFORME DE
