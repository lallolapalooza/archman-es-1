Descripción detallada

Estas funciones proporcionan las rutinas básicas de libcaca para la inicialización de la visualización, la recuperación de información del sistema y la configuración.

Documentación de funciones

__extern caca_display_t * caca_create_display (caca_canvas_t * cv)

Crea un contexto gráfico utilizando características dependientes del dispositivo (ncurses para terminales, una ventana X11, una ventana de comando DOS...) que se adjunta a un lienzo de libcaca. Todo lo que se dibuje en el lienzo de caca puede ser visualizado por el controlador de libcaca.

Si no se proporciona ningún lienzo de caca, se crea uno nuevo. Su identificador se puede recuperar usando caca_get_canvas() y se destruye automáticamente cuando se llama a caca_free_display().

Tenga en cuenta que para lograr la máxima compatibilidad con Unicode, el código de inicialización del controlador puede cambiar temporalmente la configuración regional LC_CTYPE global del programa usando setlocale(). Se recomienda no llamar a funciones dependientes de LC_CTYPE desde otros hilos durante la llamada a caca_create_display(). La configuración regional se restaura cuando la función devuelve.

Ver también caca_create_display_with_driver().

Si ocurre un error, se devuelve NULL y se establece errno en consecuencia:

  • ENOMEM No hay suficiente memoria.
  • ENODEV No se pudo inicializar el dispositivo gráfico.

Parámetros

cv El lienzo de caca o NULL para crear un lienzo automáticamente.

Devuelve

El contexto gráfico de caca o NULL si ocurrió un error.

Referencias caca_create_display_with_driver().

__extern caca_display_t * caca_create_display_with_driver (caca_canvas_t * cv, char const * driver)

Crea un contexto gráfico utilizando características dependientes del dispositivo (ncurses para terminales, una ventana X11, una ventana de comando DOS...) que se adjunta a un lienzo de libcaca. Todo lo que se dibuje en el lienzo de caca puede ser visualizado por el controlador de libcaca.

Si no se proporciona ningún lienzo de caca, se crea uno nuevo. Su identificador se puede recuperar usando caca_get_canvas() y se destruye automáticamente cuando se llama a caca_free_display().

Si no se proporciona ningún nombre de controlador, libcaca intentará autodetectar el mejor controlador de salida que pueda.

Ver también caca_create_display().

Si ocurre un error, se devuelve NULL y se establece errno en consecuencia:

  • ENOMEM No hay suficiente memoria.
  • ENODEV No se pudo inicializar el dispositivo gráfico.

Parámetros

cv El lienzo de caca o NULL para crear un lienzo automáticamente.
driver Una cadena que describe el controlador de salida deseado o NULL para elegir automáticamente el mejor controlador.

Devuelve

El contexto gráfico de caca o NULL si ocurrió un error.

Referencias caca_create_canvas(), caca_free_canvas(), caca_manage_canvas() y caca_unmanage_canvas().

Referenciado por caca_create_display().

__extern char const *const * caca_get_display_driver_list (void )

Devuelve una lista de los controladores de visualización disponibles. La lista es un array de cadenas terminado en NULL, que intercala una cadena que contiene el valor interno para el controlador de visualización, y una cadena que contiene la descripción en lenguaje natural para ese controlador.

Esta función nunca falla.

Devuelve

Un array de cadenas.

__extern int caca_free_display (caca_display_t * dp)

Desconecta un contexto gráfico de su backend de caca y lo destruye. El lienzo de libcaca continúa existiendo y otros contextos gráficos pueden adjuntarse a él posteriormente.

Si el lienzo de caca fue creado automáticamente por caca_create_display(), se destruye automáticamente y cualquier identificador hacia él se vuelve inválido.

Esta función nunca falla.

Parámetros

dp El contexto gráfico de libcaca.

Devuelve

Esta función siempre devuelve 0.

Referencias caca_free_canvas() y caca_unmanage_canvas().

__extern int caca_set_display_time (caca_display_t * dp, int delay)

Establece el retardo de refresco de la pantalla.

El retardo se expresa en microsegundos. Un valor de 0 desactiva el retardo (el bucle de evento se ejecutará tan rápido como sea posible).
