CA.PL(1ssl) OpenSSL CA.PL(1ssl)

NOMBRE

CA.pl - interfaz más amigable para los programas de certificados de OpenSSL

SINOPSIS

CA.pl -? | -h | -help

CA.pl -newcert | -newreq | -newreq-nodes | -xsign | -sign | -signCA | -signcert | -crl | -newca [-extra-cmd parámetro]

CA.pl -pkcs12 [nombre_certificado]

CA.pl -verify archivo_certificado ...

CA.pl -revoke archivo_certificado [razón]

DESCRIPCIÓN

El CA.pl script es un script de perl que proporciona los argumentos de línea de comandos relevantes para el openssl(1) comando para algunas operaciones comunes de certificados. Está destinado a simplificar el proceso de creación y gestión de certificados mediante el uso de algunas opciones simples.

El script está destinado a ser una interfaz de usuario simple para el openssl(1) programa para su uso por un principiante. Su comportamiento no siempre es el deseado. Para un mayor control sobre el comportamiento de los comandos de certificados, llame al openssl(1) comando directamente.

La mayoría de los nombres de archivo mencionados a continuación pueden modificarse editando el CA.pl script.

En algunos entornos puede no ser posible ejecutar el CA.pl script directamente (por ejemplo, Win32) y la ubicación del archivo de configuración predeterminada puede ser incorrecta. En este caso, el comando:

perl -S CA.pl

puede usarse y la variable de entorno OPENSSL_CONF puede establecerse para que apunte a la ruta correcta del archivo de configuración.

OPCIONES

-?, -h, -help
Imprime un mensaje de uso.
-newcert
Crea un nuevo certificado autofirmado. La clave privada se escribe en el archivo newkey.pem y la solicitud se escribe en el archivo newreq.pem. Invoca openssl-req(1).
-newreq
Crea una nueva solicitud de certificado. La clave privada se escribe en el archivo newkey.pem y la solicitud se escribe en el archivo newreq.pem. openssl-req(1) se ejecuta internamente.
-newreq-nodes
Es como -newreq excepto que la clave privada no estará encriptada. openssl-req(1).
-newca
Crea una nueva jerarquía de CA para usar con el ca programa (o las opciones -signcert y -xsign ). Se le solicita al usuario que ingrese el nombre de archivo de los certificados de la CA (que también debe contener la clave privada) o, al presionar ENTER, se le solicitarán los detalles de la CA. Se crean los archivos y directorios relevantes en un directorio llamado demoCA en el directorio actual. Usa openssl-req(1) y openssl-ca(1).

Si el directorio demoCA ya existe, el comando -newca no lo sobrescribirá y no hará nada. Esto puede ocurrir si una llamada anterior con la opción -newca terminó anormalmente. Para obtener el comportamiento correcto, elimine el directorio si ya existe.

-pkcs12
Crea un archivo PKCS#12 que contiene el certificado del usuario, la clave privada y el certificado de la CA. Espera que el certificado del usuario y la clave privada estén en el archivo newcert.pem y que el certificado de la CA esté en el archivo demoCA/cacert.pem, crea un archivo newcert.p12. Este comando puede llamarse después de la opción -sign . El archivo PKCS#12 puede importarse directamente en un navegador. Si hay un argumento adicional en la línea de comandos, se usará como el "nombre amigable" para el certificado (que normalmente se muestra en la lista del navegador), de lo contrario se usa el nombre "My Certificate". Delega el trabajo a openssl-pkcs12(1).
-sign, -signcert, -xsign
Llama al comando openssl-ca(1) para firmar una solicitud de certificado. Espera que la solicitud esté en el archivo newreq.pem. El nuevo certificado se escribe en el archivo newcert.pem excepto en el caso de la opción -xsign en la que se escribe en la salida estándar.
-signCA
Esta opción es igual a la opción -sign excepto que usa la sección del archivo de configuración v3_ca y por lo tanto hace que la solicitud firmada sea un certificado de CA válido. Esto es útil al crear una CA intermedia a partir de una CA raíz. Los parámetros adicionales se pasan a openssl-ca(1).
-signcert
Esta opción es igual a -sign excepto que espera que haya un certificado autofirmado en el archivo newreq.pem. Los parámetros adicionales se pasan a openssl-x509(1) y openssl-ca(1).
-crl
Genera un CRL. Ejecuta openssl-ca(1).
-revoke archivo_certificado [razón]
Revoca el certificado contenido en el archivo_certificadoespecificado. Se puede especificar una razón opcional, y debe ser una de las siguientes: unspecified, keyCompromise, CACompromise, affiliationChanged, superseded, cessationOfOperation, certificateHoldo removeFromCRL. Aprovecha openssl-ca(1).
-verify
Verifica certificados contra el certificado de la CA para demoCA. Si no se especifican certificados en la línea de comandos, intenta verificar el archivo newcert.pem. Invoca openssl-verify(1).
-extra-cmd parámetro
Para cada opción extra-cmd, pasa el parámetro al openssl(1) subcomando con el mismo nombre que cmd, si ese subcomando es invocado. Por ejemplo, si se invoca openssl-req(1) , el parámetro dado con -extra-req se le pasará. Para parámetros de múltiples palabras, repita la opción o ponga entre comillas los parámetros para que parezcan una sola palabra a su shell. Consulte la documentación de cada comando para más información.

EJEMPLOS

Crear una jerarquía de CA:

CA.pl -newca

Ejemplo completo de creación de certificado: crear una CA, crear una solicitud, firmar la solicitud y finalmente crear un archivo PKCS#12 que la contenga.

CA.pl -newca
CA.pl -newreq
CA.pl -sign
CA.pl -pkcs12 "My Test Certificate"

ENTORNO

La variable de entorno OPENSSL puede usarse para especificar el nombre del programa OpenSSL. Puede ser una ruta completa o relativa.

La variable de entorno OPENSSL_CONFIG puede usarse para especificar una opción de configuración y un valor para los comandos req y ca invocados por este script. Su valor debe ser la opción y la ruta, como en "-config /path/to/conf-file".
