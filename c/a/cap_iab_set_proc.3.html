Este IAB tupla de 3 elementos de vectores de capacidades, capturada en el tipo cap_iab_t se combinan para pasar capacidades de un proceso a otro a través de execve(2) llamadas al sistema. Las reglas de convolución que usan la tupla IAB son un conjunto de reglas de respaldo cuando el archivo ejecutado no tiene file-capabilities configuradas. El kernel impone algunas restricciones con

Estas son: el vector Inh ( CAP_IAB_INH) es completamente igual al indicador Inheritabledel proceso en todo momento; el vector Amb ( CAP_IAB_AMB) no contiene más valores de capacidadesque la intersección del vector Inh y el indicador Permitted para el proceso; y el vector Bound (o blocked) vector ( CAP_IAB_BOUND) es el complemento a dos del vector boundingdel proceso. En algunos entornos, se considera deseable heredar

capacidades

de forma simple. Es decir, pasar capacidades, independientemente del estado del binario ejecutado, del padre al hijo a través de exec* llamadas al sistema. Las capacidades sobrevivientes se convierten en el indicador Permitted para el proceso post-exec. Este método de herencia difiere significativamente de la herencia por handshake entre un proceso pre-exec* y un ejecutable dotado de file-capability del mecanismo de capacidades tradicional (POSIX.1e). HISTORI

A

El formato IAB para las variantes heredables de capacidades fue desarrollado primero como la sintaxis de configuración para el pam_cap.so módulo Linux-PAM en libcap-2.29. Se introdució para extender la lista simple separada por comas de capacidades Inheritable del proceso, que el módulo podía otorgar a un árbol de procesos autenticado, para incluir límites aplicados en el vector Bounding y introducir soporte para el vector Ambient de bits de capacidad.

Aunque

los vectores Inheritable y Bounding fueron anticipados por el borrador POSIX.1e que introdujo las capacidades, el vector Ambient es una invención de Linux, e incompatible con el modelo de capacidades de archivo POSIX.1e. Como tal, se sintió que intentar fusionar todos los 5 vectores de capacidades en una representación de texto no iba a funcionar. En su lugar, la sintaxis de configuración de pam_cap.so se generalizó en un conjunto completo de funciones de libcap para agrupar juntas las

tres capacidades heredables de forma simple: la tupl
a IAB. El soporte para esto debutó en libcap-2.33. INFORME
