cargo-remove(1)

Paquete: rust

CARGO-REMOVE(1) Manual de Comandos Generales CARGO-REMOVE(1)

NOMBRE

cargo-remove — Eliminar dependencias de un archivo manifest de Cargo.toml

SINOPSIS

cargo remove [opciones] dependencia…

DESCRIPCIÓN

Elimina una o más dependencias de un archivo manifest de Cargo.toml.

OPCIONES

Opciones de sección

--dev

Eliminar como una dependencia de desarrollo https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#development-dependencies.

--build

Eliminar como una dependencia de compilación https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#build-dependencies.

--target objetivo

Eliminar como una dependencia para la plataforma objetivo dada https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#platform-specific-dependencies.

Para evitar expansiones inesperadas del shell, puede usar comillas alrededor de cada objetivo, por ejemplo, --target 'cfg(unix)'.

Opciones Misceláneas

--dry-run

No escribir realmente en el manifest.

Opciones de Visualización

-v, --verbose

Usar salida detallada. Se puede especificar dos veces para una salida “muy detallada” que incluye salida adicional como advertencias de dependencia y salida de script de compilación. También se puede especificar con el valor de configuración term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

No imprimir mensajes de registro de cargo. También se puede especificar con el valor de configuración term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color cuándo

Controlar cuándo se usa la salida con color. Valores válidos:
•auto (por defecto): Detectar automáticamente si el soporte de color está disponible en la terminal.
•always: Mostrar siempre colores.
•never: Nunca mostrar colores.

También se puede especificar con el valor de configuración term.color https://doc.rust-lang.org/cargo/reference/config.html.

Opciones de Manifest

--manifest-path ruta

Ruta al archivo Cargo.toml. Por defecto, Cargo busca el archivo Cargo.toml en el directorio actual o en cualquier directorio padre.

--locked

Asegura que se usan exactamente las mismas dependencias y versiones que cuando se generó originalmente el archivo Cargo.lock existente. Cargo saldrá con un error cuando ocurra alguno de los siguientes escenarios:
•Falta el archivo de bloqueo.
•Cargo intentó cambiar el archivo de bloqueo debido a una resolución de dependencia diferente.

Se puede usar en entornos donde se desean compilaciones deterministas, como en pipelines de CI.

--offline

Evita que Cargo acceda a la red por cualquier motivo. Sin esta bandera, Cargo se detendrá con un error si necesita acceder a la red y esta no está disponible. Con esta bandera, Cargo intentará proceder sin la red si es posible.

Tenga cuidado, ya que esto puede dar como resultado una resolución de dependencias diferente a la del modo en línea. Cargo se limitará a las crates que se descarguen localmente, incluso si podría haber una versión más nueva como se indica en la copia local del índice. Consulte el comando cargo-fetch(1) para descargar las dependencias antes de desconectarse.

También se puede especificar con el valor de configuración net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Equivalente a especificar tanto --locked como --offline.

--lockfile-path RUTA

Cambia la ruta del archivo de bloqueo desde el valor predeterminado (<workspace_root>/Cargo.lock) a RUTA. RUTA debe terminar con Cargo.lock (por ejemplo, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Tenga en cuenta que proporcionar --lockfile-path ignorará el archivo de bloqueo existente en la ruta predeterminada, y en su lugar utilizará el archivo de bloqueo de RUTA, o escribirá un nuevo archivo de bloqueo en la RUTA proporcionada si no existe. Esta bandera se puede usar para ejecutar la mayoría de los comandos en directorios de solo lectura, escribiendo el archivo de bloqueo en la RUTA proporcionada.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla (consulte #14421 https://github.com/rust-lang/cargo/issues/14421).

Selección de Paquetes

-p espec…, --package espec…

Paquete del cual eliminar.

Opciones Comunes

+toolchain

Si Cargo ha sido instalado con rustup, y el primer argumento para cargo comienza con +, será interpretado como un nombre de toolchain de rustup (como +stable o +nightly). Consulte la documentación de rustup https://rust-lang.github.io/rustup/overrides.html para más información sobre cómo funcionan las anulaciones de toolchain.

--config CLAVE=VALOR o RUTA

Anula un valor de configuración de Cargo. El argumento debe estar en sintaxis TOML de CLAVE=VALOR, o proporcionarse como una ruta a un archivo de configuración adicional. Esta bandera se puede especificar múltiples veces. Consulte la sección de anulaciones de línea de comandos https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides para más información.

-C RUTA

Cambia el directorio de trabajo actual antes de ejecutar cualquier operación especificada. Esto afecta a dónde busca cargo por defecto el manifest del proyecto (Cargo.toml), así como a los directorios buscados para descubrir .cargo/config.toml, por ejemplo. Esta opción debe aparecer antes del nombre del comando, por ejemplo cargo -C ruta/a/mi-proyecto build.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla (consulte #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Imprime información de ayuda.

-Z bandera

Banderas inestables (solo nightly) para Cargo. Ejecute cargo -Z help para obtener detalles.

ENTORNO

Consulte la referencia https://doc.rust-lang.org/cargo/reference/environment-variables.html para obtener detalles sobre las variables de entorno que lee Cargo.
