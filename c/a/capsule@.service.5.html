NOMBRE

capsule@.service - Gestor de unidades del sistema para el gestor de servicios de cápsula

SINOPSIS

capsule@NOMBRE.service

DESCRIPCIÓN

Los gestores de servicios para cápsulas se ejecutan en unidades del sistema capsule@NOMBRE.service, con el nombre de la cápsula como identificador de instancia. Las cápsulas son una forma de ejecutar instancias adicionales del gestor de servicios, bajo IDs de usuario dinámicos, es decir, UIDs que se asignan cuando se inicia el gestor de servicios de la cápsula y se liberan cuando se detiene.

En muchos aspectos, capsule@.service es similar al gestor de servicios user@.service por usuario, pero hay algunas distinciones importantes:

•El gestor de servicios de cápsula utiliza DynamicUser= (ver systemd.exec(5)) para asignar un nuevo UID dinámicamente en la invocación. El nombre de usuario se genera automáticamente a partir del nombre de la cápsula, anteponiendo "c-". El UID se libera cuando el servicio termina. El gestor de servicios de usuario, por otro lado, opera bajo un ID de usuario asignado estáticamente que debe existir previamente, antes de que se invoque el gestor de servicios de usuario.
•Los gestores de servicios de usuario se registran con pam(8), los gestores de servicios de cápsula no.
•Los gestores de servicios de usuario suelen leer su configuración desde un directorio $HOME en /home/, los gestores de servicios de cápsula desde un directorio $HOME en /var/lib/capsules/.
•Los gestores de servicios de usuario están contenidos colectivamente en la unidad user.slice, los gestores de servicios de cápsula en capsule.slice. Ver también systemd.special(7).
•Los gestores de servicios de usuario inician el objetivo predeterminado de unidades de usuario user unit default.target inicialmente. Los gestores de servicios de cápsula invocan en su lugar el objetivo de unidades de usuario capsule@.target.

El gestor de servicios capsule@.service y el broker de bus de la cápsula son accesibles a través del modificador --capsule= de systemctl(1), systemd-run(1) y busctl(1).

Se pueden iniciar nuevas cápsulas mediante un simple comando systemctl start capsule@NOMBRE.service, y detenerlas con systemctl stop capsule@NOMBRE.service. Iniciar una cápsula creará implícitamente un directorio de inicio /var/lib/capsules/NOMBRE/, si no existe. Se creará un directorio de tiempo de ejecución como /run/capsules/NOMBRE/. Para eliminar estos recursos, utilice systemctl clean capsule@NOMBRE.service, por ejemplo con el modificador --what=all.

La unidad capsule@.service invoca un proceso gestor de servicios systemd --user. Esto significa que los archivos de unidad se buscarán según las mismas reglas que para los gestores de servicios de usuario normales, por ejemplo, en /var/lib/capsules/NOMBRE/.config/systemd/user/.

Los nombres de cápsula pueden ser elegidos libremente por el usuario, sin embargo, deben ser adecuados como nombres de archivo UNIX (es decir, 255 caracteres como máximo y no contener "/"), y cuando se les antepone "c-", deben ser adecuados como nombre de usuario que cumpla estrictas reglas POSIX, ver Sintaxis de Nombres de Usuario/Grupo[1] para más detalles.

Añadido en la versión 256.

EJEMPLOS

Ejemplo 1. Crear una nueva cápsula, invocar dos programas en ella (uno interactivamente), terminarla y limpiar todo 

# systemctl start capsule@tatze.service
# systemd-run --capsule=tatze --unit=sleeptest.service sleep 999
# systemctl --capsule=tatze status sleeptest.service
# systemd-run -t --capsule=tatze bash
# systemctl --capsule=tatze stop sleeptest.service
# systemctl stop capsule@tatze.service
# systemctl clean --all capsule@tatze.service
