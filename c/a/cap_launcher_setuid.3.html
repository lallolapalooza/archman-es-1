cap_launcher_setuid(3)

Paquete: libcap

Licencias: BSD-3-Clause OR GPL-2.0-only

CAP_LAUNCH(3) Manual del programador de Linux CAP_LAUNCH(3)

NOMBRE

cap_new_launcher, cap_func_launcher, cap_launcher_callback, cap_launcher_set_mode, cap_launcher_set_iab, cap_launcher_set_chroot, cap_launch, cap_launcher_setuid, cap_launcher_setgroups - funcionalidad de lanzamiento de libcap

SINOPSIS

#include <sys/capability.h>
cap_launch_t cap_new_launcher(const char *arg0, const char *const *argv,
    const char *const *envp);
cap_launch_t cap_func_launcher(int (callback_fn)(void *detail));
int cap_launcher_callback(cap_launch_t attr,
    int (callback_fn)(void *detail));
int cap_launcher_set_mode(cap_launch_t attr, cap_mode_t flavor);
cap_iab_t cap_launcher_set_iab(cap_launch_t attr, cap_iab_t iab);
int cap_launcher_set_chroot(cap_launch_t attr, const char *chroot);
#include <sys/types.h>
pid_t cap_launch(cap_launch_t attr, void *detail);
int cap_launcher_setuid(cap_launch_t attr, uid_t uid);
int cap_launcher_setgroups(cap_launch_t attr, gid_t gid,
    int ngroups, const gid_t *groups);

Enlazar con -lcap.

DESCRIPCIÓN

Un lanzador proporciona un mecanismo para que el código ejecute una función de devolución de llamada y/o un programa ejecutable en un entorno con un contexto de seguridad modificado. Esencialmente, proporciona un mecanismo para que un programa fork(2) un nuevo contexto del programa principal, manipule las capacidades y otro estado privilegiado en ese proceso fork(2)ado antes de (opcionalmente) execve(2) un nuevo programa. Cuando la aplicación se enlaza con -lpsx, se necesita este soporte para ejecutar de manera robusta el código lanzado sin modificar el privilegio de toda la aplicación principal (que respeta las semánticas POSIX).

Un lanzador se define mediante una de estas dos funciones: cap_new_launcher() o cap_func_launcher(). El valor de retorno es de tipo opaco cap_launch_t; un valor de retorno NULL implica que ha ocurrido un error.

Una vez definido, un valor cap_launch_t puede ser utilizado con cap_launch() para ejecutar ese lanzador. En tales casos, un valor de retorno no negativo indica éxito: cero significa éxito sin invocar un programa; un valor distinto de cero es igual al ID de proceso (pid_t) del programa recién lanzado.

Un cap_launch_t ocupa memoria asignada y debe liberarse con cap_free(3). Antes de ser cap_free(3)do, un valor cap_value_t puede ser reutilizado para múltiples lanzamientos independientes. El argumento detail de cap_launch(), junto con la función de devolución de llamada del lanzador, puede usarse para personalizar la invocación del lanzamiento. Se debe tener cuidado para aprovechar la memoria compartida personalizada (ver mmap(2)) o algún otro mecanismo IPC para devolver valores al programa principal a través de detail, ya que la devolución de llamada y cualquier ejecución posterior del programa ocurrirán fuera del proceso principal de la aplicación llamante. Un ejemplo de esto sería asignar detalle de la siguiente manera:

   const char *args[] = { "echo", "hola", NULL };
   cap_launch_t cmd = cap_new_launcher("/usr/bin/echo", args, NULL);
   int *detail = mmap(NULL, sizeof(int), PROT_READ | PROT_WRITE,
                      MAP_SHARED | MAP_ANONYMOUS, -1, 0);
   cap_launcher_callback(cmd, &answer_detail_fn);
   *detail = 41;
   pid_t pid = cap_launch(cmd, detail);
   printf("la devolución de llamada del lanzador estableció el detalle en %d\n", *detail);
   munmap(detail, sizeof(int));

A menos que sea modificado por la función de devolución de llamada, el código lanzado se ejecutará con la capacidad y el contexto de seguridad de la aplicación.

Si la función de devolución de llamada devuelve algo distinto de cero, cap_launch() se abortará. Si los detalles del fallo son importantes para el llamador, deben comunicarse a través del argumento detail.

Las siguientes funciones pueden ser utilizadas para instruir al lanzador a modificar el estado de seguridad del programa invocado sin alterar el estado del programa llamante. Dichas modificaciones deben realizarse antes de llamar a cap_launch() si se desea que tengan el efecto deseado. Además, solo se invocan después de que cualquier devolución de llamada instalada haya completado. Por ejemplo, se pueden soltar o modificar capacidades, solo para ejecutar un archivo.

Las siguientes funciones instruyen al lanzador para realizar tareas comunes de este tipo (tenga en cuenta que algunas requieren bits de capacidad permitidos para tener éxito):

cap_launcher_callback() puede ser utilizado para instalar o reemplazar la función de devolución de llamada actualmente instalada del lanzador.

cap_launcher_set_mode() puede ser utilizado para asegurar que el modo libcap del programa lanzado sea el deseado.

cap_launcher_set_iab() Esta función devuelve el cap_iab_t previamente asociado con el lanzador. Llamar a esta función con un valor IAB de NULL configurará el lanzador para no establecer un valor IAB (el valor predeterminado). Ver cap_iab(3) para detalles sobre el conjunto IAB. Tenga en cuenta que el lanzador se asocia directamente con el valor iab proporcionado, y no hace una copia de él. Este valor iab se bloquea al lanzador y no puede modificarse mientras está asociado con el lanzador. Establézcalo con NULL para recuperar el control sobre la memoria asociada con ese valor IAB, de lo contrario, el valor IAB será cap_free(3)'d cuando lo sea el lanzador.

cap_launcher_set_chroot() Esta función hace que el programa ejecutable lanzado se invoque dentro de un directorio root de chroot.

cap_launcher_setuid() Esta función hace que el programa ejecutable lanzado se invoque con el identificador de usuario especificado (uid_t).

cap_launcher_setgroups() Esta función hace que el programa ejecutable lanzado se invoque con los identificadores de grupo primario y suplementario especificados.

Tenga en cuenta que si alguna de las mejoras del lanzador realizadas por las funciones anteriores no surte efecto (típicamente por falta de privilegio suficiente), el lanzamiento fallará y devolverá -1.

ERRORES

Un retorno de NULL para un cap_launch_t debe considerarse un error.

cap_launch() devuelve -1 en caso de error.

En todos estos casos, un valor de retorno de 0 implica éxito. En otros casos, consulte errno(3) para más detalles.

HISTORIA

La familia de funciones cap_launch() se introdujo en libcap 2.33. Aborda principalmente una complejidad con las aplicaciones pthreads(7) enlazadas con -lpsx que utilizan capacidades pero también respetan las semánticas POSIX.

El uso de -lcap y -lpthread juntos sin el soporte de semánticas POSIX de -lpsx introduce una sutil clase de exposición a escalada de privilegios. (Ver https://sites.google.com/site/fullycapable/who-ordered-libpsx para una explicación.)
