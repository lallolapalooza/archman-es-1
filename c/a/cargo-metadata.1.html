CARGO-METADATA(1) Manual de Comandos Generales CARGO-METADATA(1)

NOMBRE

cargo-metadata — Metadatos legibles por máquina sobre el paquete actual

SINOPSIS

cargo metadata [opciones]

DESCRIPCIÓN

Emite JSON en stdout que contiene información sobre los miembros del espacio de trabajo y las dependencias resueltas del paquete actual.

El formato de salida está sujeto a cambios en versiones futuras de Cargo. Se recomienda incluir el indicador --format-version para hacer que tu código sea resistente al futuro y asegurar que la salida esté en el formato que esperas. Para más sobre las expectativas, véase "Compatibilidad".

Véase el crate cargo_metadata https://crates.io/crates/cargo_metadata para una API de Rust para leer los metadatos.

FORMATO DE SALIDA

Compatibilidad

Dentro de la misma versión de formato de salida, la compatibilidad se mantiene, excepto en algunos escenarios. La siguiente es una lista no exhaustiva de cambios que no se consideran incompatibles:

•Añadir nuevos campos — Se añadirán nuevos campos cuando sea necesario. Reservar esto permite a Cargo evolucionar sin aumentar la versión del formato demasiado a menudo.
•Añadir nuevos valores para campos tipo enumeración — Igual que añadir nuevos campos. Mantiene los metadatos evolucionando sin estancamiento.
•Cambiar representaciones opacas — Las representaciones internas de algunos campos son detalles de implementación. Por ejemplo, los campos relacionados con "Source ID" se tratan como identificadores opacos para diferenciar paquetes o fuentes. Los consumidores no deberían depender de esas representaciones a menos que se especifique.

--locked

Asegura que se utilizan exactamente las mismas dependencias y versiones que cuando se generó el archivo Cargo.lock existente. Cargo saldrá con un error cuando surja alguno de los siguientes escenarios:
•Falta el archivo de bloqueo.
•Cargo intentó cambiar el archivo de bloqueo debido a una resolución de dependencias diferente.

Puede utilizarse en entornos donde se deseen compilaciones deterministas, como en canalizaciones de CI.

--offline

Impide que Cargo acceda a la red por cualquier motivo. Sin esta bandera, Cargo se detendrá con un error si necesita acceder a la red y esta no está disponible. Con esta bandera, Cargo intentará continuar sin la red si es posible.

Tenga en cuenta que esto puede resultar en una resolución de dependencias diferente a la del modo en línea. Cargo se limitará a los crat de los que se hayan descargado localmente, incluso si pudiera haber una versión más reciente según lo indicado en la copia local del índice. Consulte el comando cargo-fetch(1) para descargar dependencias antes de pasar a modo sin conexión.

También se puede especificar con el valor de configuración net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Equivalente a especificar tanto --locked como --offline.

--lockfile-path RUTA

Cambia la ruta del archivo de bloqueo de la predeterminada (<workspace_root>/Cargo.lock) a RUTA. RUTA debe terminar en Cargo.lock (por ejemplo, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Tenga en cuenta que proporcionar --lockfile-path ignorará el archivo de bloqueo existente en la ruta predeterminada, y en su lugar utilizará el archivo de bloqueo de RUTA, o escribirá un nuevo archivo de bloqueo en la RUTA proporcionada si no existe. Esta bandera se puede usar para ejecutar la mayoría de los comandos en directorios de solo lectura, escribiendo el archivo de bloqueo en la RUTA proporcionada.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla (ver #14421 https://github.com/rust-lang/cargo/issues/14421).

Opciones Comunes

+toolchain

Si Cargo se ha instalado con rustup, y el primer argumento de cargo comienza con +, se interpretará como un nombre de toolchain de rustup (como +stable o +nightly). Consulte la documentación de rustup https://rust-lang.github.io/rustup/overrides.html para obtener más información sobre cómo funcionan las anulaciones de toolchain.

--config CLAVE=VALOR o RUTA

Anula un valor de configuración de Cargo. El argumento debe estar en sintaxis TOML de CLAVE=VALOR, o proporcionarse como una ruta a un archivo de configuración adicional. Esta bandera se puede especificar varias veces. Consulte la sección de anulaciones de línea de comandos https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides para obtener más información.

-C RUTA

Cambia el directorio de trabajo actual antes de realizar cualquier operación especificada. Esto afecta a dónde busca Cargo por defecto el manifiesto del proyecto (Cargo.toml), así como a los directorios en los que se busca para descubrir .cargo/config.toml, por ejemplo. Esta opción debe aparecer antes del nombre del comando, por ejemplo cargo -C path/to/my-project build.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla (ver #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Imprime la información de ayuda.

-Z flag

Flags inestables (solo para nightly) para Cargo. Ejecute cargo -Z help para obtener detalles.
