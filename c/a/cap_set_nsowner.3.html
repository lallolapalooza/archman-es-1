cap_set_nsowner(3)

Paquete: libcap

Licencias: BSD-3-Clause OR GPL-2.0-only

CAP_GET_FILE(3) Manual del programador de Linux CAP_GET_FILE(3)

NOMBRE

cap_get_file, cap_set_file, cap_get_fd, cap_set_fd, cap_get_nsowner, cap_set_nsowner - manipulación de capacidades en archivos

SINOPSIS

#include <sys/capability.h>
cap_t cap_get_file(const char *path_p);
int cap_set_file(const char *path_p, cap_t cap_p);
cap_t cap_get_fd(int fd);
int cap_set_fd(int fd, cap_t caps);
uid_t cap_get_nsowner(cap_t caps);
int cap_set_nsowner(cap_t caps, uid_t rootuid);

Enlazar con -lcap.

DESCRIPCIÓN

cap_get_file() y cap_get_fd() asignan un estado de capacidad en el área de trabajo y lo establecen para representar el estado de capacidad del nombre de ruta apuntado por path_p o el archivo abierto en el descriptor fd. Estas funciones devuelven un puntero al estado de capacidad recién creado. Los efectos de leer el estado de capacidad de cualquier archivo que no sea un archivo regular son indefinidos. El llamador debe liberar cualquier memoria liberable, cuando el estado de capacidad en el área de trabajo ya no sea necesario, llamando a cap_free() con la cap_t utilizada como argumento.

cap_set_file() y cap_set_fd() establecen los valores de todas las banderas de capacidad para todas las capacidades para el nombre de ruta apuntado por path_p o el archivo abierto en el descriptor fd, con el estado de capacidad identificado por cap_p. El nuevo estado de capacidad del archivo está completamente determinado por el contenido de cap_p. Un valor NULL para cap_p se utiliza para indicar que las capacidades del archivo deben eliminarse. Para que estas funciones tengan éxito, el proceso llamador debe tener la capacidad CAP_SETFCAP en su conjunto efectivo y, o bien, el ID de usuario efectivo del proceso debe coincidir con el propietario del archivo, o bien, el proceso llamador debe tener la capacidad CAP_FOWNER en su conjunto de capacidades efectivo. Los efectos de escribir el estado de capacidad en cualquier tipo de archivo que no sea un archivo regular son indefinidos.

Un conjunto de capacidades mantenido en memoria puede asociarse con el ID de usuario root en uso en un espacio de nombres de usuario específico. Es posible obtener y establecer este valor (en la copia de memoria) con cap_get_nsowner() y cap_set_nsowner() respectivamente. El ID de usuario root es ignorado por la biblioteca libcap en todos los casos excepto cuando la capacidad se escribe en un archivo. Solo si el valor no es cero, la biblioteca intentará incluirlo en el conjunto de capacidades del archivo escrito.

VALOR DE RETORNO

cap_get_file() y cap_get_fd() devuelven un valor no NULL en caso de éxito, y NULL en caso de fallo.

cap_set_file() y cap_set_fd() devuelven cero en caso de éxito, y -1 en caso de fallo.

En caso de fallo, errno se establece en EACCES, EBADFD, ENAMETOOLONG, ENOENT, ENOMEM, ENOTDIR, EPERM, o EROFS.

CONFORMIDAD

Estas funciones están especificadas por la especificación borrador retirada de POSIX.1e.

NOTAS

El soporte para capacidades de archivo se proporciona en Linux desde la versión 2.6.24.

En Linux, el conjunto Efectivo del archivo es un solo bit. Si está habilitado, entonces todas las capacidades Permitidas se habilitan en el conjunto Efectivo del proceso llamador cuando el archivo se ejecuta; de lo contrario, no se habilitan capacidades en el conjunto Efectivo del proceso después de un execve(2). Debido a que el conjunto Efectivo del archivo es un solo bit, si alguna capacidad está habilitada en el conjunto Efectivo de la cap_t dada a cap_set_file() o cap_set_fd(), entonces todas las capacidades cuya bandera Permiida o Hereditaria esté habilitada también deben tener la bandera Efectiva habilitada. Por el contrario, si la bandera Efectiva está habilitada en un archivo, entonces la cap_t devuelta por cap_get_file() y cap_get_fd() tendrá la bandera Efectiva habilitada para cada capacidad que tenga la bandera Permitida o Hereditaria habilitada.
