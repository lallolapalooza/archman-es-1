NOMBRE

castxml - Salida XML del Árbol de Sintaxis Abstracta de la familia C

SINOPSIS

castxml ( <castxml-opt> | <clang-opt> | <src> )...

DESCRIPCIÓN

Analiza archivos fuente de la familia C y opcionalmente escribe un subconjunto del Árbol de Sintaxis Abstracta (AST) en una representación XML.

OPCIONES

Las siguientes opciones de línea de comandos son interpretadas por castxml. Las opciones restantes se pasan al compilador Clang interno.

--castxml-cc-<id> <cc>, --castxml-cc-<id> "(" <cc> <cc-opt>... ")"
Configura el preprocesador interno de Clang y la plataforma de destino para que coincidan con los de la orden del compilador dada. El <id> nombra un compilador de referencia con el cual el comando dado es compatible. Debe ser uno de:
  • gnu: C++ del Conjunto de Compiladores GNU (g++)
  • gnu-c: C del Conjunto de Compiladores GNU (gcc)
  • msvc: Microsoft Visual C++ (cl)
  • msvc-c: Microsoft Visual C (cl)

<cc> nombra un compilador (p. ej., /usr/bin/gcc o cl) y <cc-opt>... especifica opciones que pueden afectar su destino (p. ej., -m32). La plataforma de destino detectada del compilador dado puede ser anulada por una opción separada de Clang -target. El nivel estándar del lenguaje detectado del compilador dado puede ser anulado por una opción separada de Clang -std=.

--castxml-output=<v>
Escribe la salida XML en <src>.xml o en el archivo nombrado por -o. El <v> especifica el número de versión del formato “épico” a generar, y debe ser 1.
--castxml-gccxml
Genera salida XML en un formato cercano al de gccxml. Escribe la salida en <src>.xml o en el archivo nombrado por -o. El formato gccxml no soporta modos de lenguaje de Clang que no sean -std=c++98 o -std=c89. Este formato de salida puede ser usado con los modos de lenguaje -std=c++11, -std=c++14, -std=c99 y -std=c11, pero la salida no contendrá constructores de movimiento implícitos ni operadores de asignación de movimiento, y puede contener elementos <Unimplemented/> en construcciones no c++98.
--castxml-start <name>[,<name>]...
Inicia el recorrido del AST en la(s) declaración(es) con el(los) nombre(s) calificado(s) dado(s). Se pueden especificar múltiples nombres como una lista separada por comas o repitiendo la opción.
-help, --help
Imprime la información de uso de castxml y del compilador interno de Clang.
-o <file>
Si se genera salida (p. ej., a través de --castxml-output=<v>), escribe la salida en <file>. Se puede especificar como máximo un archivo <src> como entrada.
--version
Imprime la información de versión de castxml y del compilador interno de Clang.

Las versiones de lanzamiento de CastXML utilizan el formato:

<major>.<minor>.<patch>[-rc<n>][-<id>]

donde el componente <patch> es menor que 20000000, <n> es un número opcional de candidato a lanzamiento, y <id> puede contener texto arbitrario (en caso de desarrollo entre versiones de parche).

Las versiones de desarrollo de CastXML utilizan el formato:

<major>.<minor>.<date>[-<id>]

donde el componente <date> tiene el formato CCYYMMDD y <id> puede contener texto arbitrario. Esto representa el desarrollo a partir de una fecha particular después del lanzamiento de características <major>.<minor>.

VERSIONES DE FORMATO DE SALIDA

Con --castxml-output=<v>

La etiqueta del elemento raíz XML será del tipo:

<CastXML format="1.4.0">
  • El primer componente es el número de versión del formato épico dado a la bandera --castxml-output=<v>, y actualmente siempre debe ser 1.
  • El segundo componente es el número de versión del formato mayor y se incrementa cuando se agrega un nuevo elemento XML o para otros cambios importantes. Los clientes necesitarán actualizarse.
  • El tercer componente es el número de versión del formato menor y se incrementa cada vez que se agrega un nuevo atributo XML a un elemento existente o se corrige un error menor en la salida XML de un elemento o atributo existente (los clientes deberían funcionar sin cambios a menos que quieran la nueva información).

PREPROCESAMIENTO

CastXML preprocesa los archivos fuente utilizando un compilador Clang interno y sus propias macros predefinidas para la plataforma de destino por defecto. La opción --castxml-cc-<id> cambia las macros predefinidas para que coincidan con las detectadas del comando del compilador dado. En cualquier caso, CastXML siempre agrega las siguientes macros predefinidas:

__castxml_major__
Definida con el número de versión mayor de CastXML en decimal.
__castxml_minor__
Definida con el número de versión menor de CastXML en decimal.
__castxml_patch__
Definida con el número de versión de parche de CastXML en decimal.
__castxml_check(major,minor,patch)
Definida como una expresión constante que codifica los tres componentes de versión para comparación con __castxml__. La codificación real no está especificada.
__castxml__
Definida como una expresión constante que codifica los componentes de versión de CastXML:
__castxml_check(__castxml_major__,__castxml_minor__,__castxml_patch__)
__castxml_clang_major__
Definida con el valor de __clang_major__ del Clang interno.
__castxml_clang_minor__
Definida con el valor de __clang_minor__ del Clang interno.
__castxml_clang_patchlevel__
Definida con el valor de __clang_patchlevel__ del Clang interno.

Los archivos fuente pueden usar estas para identificar la herramienta que realmente está realizando el preprocesamiento, incluso cuando --castxml-cc-<id> cambia las macros predefinidas.

PREGUNTAS FRECUENTES

¿Por qué los cuerpos de las funciones C++ no se vuelcan en XML?

Esta característica no se ha implementado porque el proyecto principal para el cual se escribió CastXML

n no necesitaba cuerpos de funciones.

¿Por qué no veo plantillas en la salida?

Esta característica no se ha implementado porque el proyecto principal para el que se escribió CastXML no necesitaba plantillas no instanciadas. Las instanciaciones de plantillas sí se incluirán. Por ejemplo:

template <class T> struct foo {};
typedef foo<int>::foo foo_int;

instanciará foo<int>, que se incluirá en la salida. Sin embargo, no habrá ningún lugar que enumere explícitamente el conjunto de tipos utilizados para la instanciación, aparte del nombre. Esto se debe a que la forma correcta de hacerlo es volcar también las plantillas y referenciarlas desde las instanciaciones con los argumentos de plantilla enumerados. Dado que las características están vinculadas, deberían implementarse juntas.
