Paquete: rust

CARGO-BENCH(1) Manual de comandos generales CARGO-BENCH(1)

NOMBRE

cargo-bench — Ejecuta benchmarks de un paquete

SINOPSIS

cargo bench [opciones] [nombre-del-bench] [-- opciones-del-bench]

DESCRIPCIÓN

Compila y ejecuta benchmarks.

El argumento de filtrado de benchmarks nombre-del-bench y todos los argumentos posteriores a los dos guiones (--) se pasan a los binarios de benchmark y, por lo tanto, a libtest (el framework de pruebas unitarias y microbenchmarking incorporado de rustc). Si pasas argumentos tanto a Cargo como al binario, los que van antes de -- van al binario, y los que van después van a Cargo. Para obtener detalles sobre los argumentos de libtest, consulta la salida de cargo bench -- --help y el capítulo del libro de rustc sobre cómo funcionan las pruebas en https://doc.rust-lang.org/rustc/tests/index.html.

Por ejemplo, esto ejecutará solo el benchmark llamado foo (y omitirá otros benchmarks con nombres similares como foobar):

cargo bench -- foo --exact

Los benchmarks se compilan con la opción --test de rustc, que crea un ejecutable especial enlazando tu código con libtest. El ejecutable ejecuta automáticamente todas las funciones anotadas con el atributo #[bench]. Cargo pasa el flag --bench al sistema de pruebas para indicarle que ejecute solo benchmarks, independientemente de si el sistema es libtest o un sistema personalizado.

El sistema de pruebas libtest puede ser deshabilitado estableciendo harness = false en la configuración del manifiesto del target, en cuyo caso tu código deberá proporcionar su propia función main para manejar la ejecución de benchmarks.

Nota: El atributo #[bench] https://doc.rust-lang.org/nightly/unstable-book/library-features/test.html actualmente no es estable y solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html. Hay algunos paquetes disponibles en crates.io https://crates.io/keywords/benchmark que pueden ayudar a ejecutar benchmarks en el canal estable, como Criterion https://crates.io/crates/criterion.

Por defecto, cargo bench utiliza el perfil bench https://doc.rust-lang.org/cargo/reference/profiles.html#bench, que habilita optimizaciones y deshabilita información de depuración. Si necesitas depurar un benchmark, puedes usar la opción de línea de comandos --profile=dev para cambiar al perfil dev. Luego puedes ejecutar el benchmark habilitado para depuración dentro de un depurador.

Directorio de trabajo de los benchmarks

El directorio de trabajo de cada benchmark se establece en el directorio raíz del paquete al que pertenece el benchmark. Establecer el directorio de trabajo de los benchmarks en el directorio raíz del paquete hace posible que los benchmarks accedan de forma fiable a los archivos del paquete usando rutas relativas, independientemente de desde dónde se ejecutó cargo bench.

OPCIONES

Opciones de Benchmark

--no-run

Compila, pero no ejecutes los benchmarks.

--no-fail-fast

Ejecuta todos los benchmarks independientemente de fallos. Sin esta opción, Cargo saldrá después del primer ejecutable fallido. El sistema de pruebas de Rust ejecutará todos los benchmarks dentro del ejecutable hasta su finalización; esta opción solo se aplica al ejecutable en su conjunto.

Selección de Paquetes

Por defecto, cuando no se dan opciones de selección de paquetes, los paquetes seleccionados dependen del archivo de manifiesto seleccionado (basado en el directorio de trabajo actual si no se da --manifest-path). Si el manifiesto es la raíz de un espacio de trabajo, se seleccionan los miembros por defecto del espacio de trabajo; de lo contrario, solo se seleccionará el paquete definido por el manifiesto.

Los miembros por defecto de un espacio de trabajo se pueden establecer explícitamente con la clave workspace.default-members en el manifiesto raíz. Si esto no está configurado, un espacio de trabajo virtual incluirá todos los miembros del espacio de trabajo (equivalente a pasar --workspace), y un espacio de trabajo no virtual incluirá solo la crate raíz.

-p espec…, --package espec…

Ejecuta benchmarks solo de los paquetes especificados. Consulta cargo-pkgid(1) para el formato SPEC. Esta opción se puede especificar múltiples veces y soporta patrones glob de Unix comunes como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente los patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón.

--workspace

Ejecuta benchmarks de todos los miembros del espacio de trabajo.

--all

Alias obsoleto para --workspace.

--exclude SPEC…

Excluye los paquetes especificados. Debe usarse junto con la opción --workspace. Esta opción se puede especificar múltiples veces y soporta patrones glob de Unix comunes como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente los patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón.

Selección de Objetivos

Cuando no se dan opciones de selección de objetivos, cargo bench compilará los siguientes objetivos de los paquetes seleccionados:

•lib — se usa para enlazar con binarios y benchmarks
•bins (solo si se compilan objetivos de benchmark y se requieren características)
•lib como benchmark
•bins como benchmarks
•objetivos de benchmark

El comportamiento por defecto puede cambiarse estableciendo el flag bench para el objetivo en la configuración del manifiesto. Establecer ejemplos como bench = true compilará y ejecutará el ejemplo como un benchmark, reemplazando la función main del ejemplo con el sistema de pruebas libtest.

Establecer objetivos como bench = false evitará que sean ejecutados como benchmarks por defecto. Las opciones de selección de objetivos que toman un objetivo por nombre (como --example foo) ignoran el flag bench y siempre ejecutarán el benchmark del objetivo dado.

Consulta Configuración de un objetivo https://doc.rust-lang.org/cargo/reference/cargo-targets.html#configuring-a-target para más información sobre configuraciones por objetivo.

Los objetivos binarios se compilan automáticamente si hay una prueba de integración o un benchmark seleccionado para ejecutar. Esto permite que una prueba de integración ejecute el binario para ejercitar y probar su comportamiento. La variable de entorno CARGO_BIN_EXE_<nombre> https://doc.rust-lang.org/cargo/reference/environment-variables.html#environment-variables-cargo-sets-for-crates se establece cuando se compila la prueba de integración para que pueda usar el macro env https://doc.rust-lang.org/std/macro.env.html para localizar el ejecutable.

Pasar opciones de selección de objetivos ejecutará benchmarks solo de los objetivos especificados.

Ten en cuenta que los flags --bin, --example, --test y --bench también soportan patrones glob de Unix comunes como *, ? y []. Sin embargo, para evitar que tu shell expanda accidentalmente los patrones glob antes de que Cargo los maneje, debes usar comillas simples o dobles alrededor de cada patrón glob.

--lib

Ejecuta benchmarks de la biblioteca del paquete.

--bin nombre…

Ejecuta benchmarks del binario especificado. Esta opción se puede especificar múltiples veces y soporta patrones glob de Unix.

--example nombre…

Ejecuta benchmarks del ejemplo especificado. Esta opción se puede especificar múltiples veces y soporta patrones glob de Unix.

--test nombre…

Ejecuta benchmarks de la prueba de integración especificada. Esta opción se puede especificar múltiples veces y soporta patrones glob de Unix.

--bench nombre…

Ejecuta benchmarks del benchmark especificado. Esta opción se puede especificar múltiples veces y soporta patrones glob de Unix.

--all-targets

Benchmark todos los objetivos (lib, binarios, ejemplos, pruebas, benchmarks) en el paquete o paquetes seleccionados.

--target triple

Benchmark para la arquitectura objetivo dada.

Selección de Perfil

--profile nombre

Ejecuta benchmarks usando el perfil especificado.

Opciones Específicas_del_Perfil

--cfg cfg-spec

Configura atributos condicionales para el compilador. Consulta Atributos condicionales https://doc.rust-lang.org/reference/attributes/cfg.html para más información.

--panic panic-strategy

Configura la estrategia de pánico para el código compilado. Las opciones son unwind (por defecto) y abort.

Opciones de Manifiesto

-m path, --manifest-path path

Ruta al archivo Cargo.toml. Por defecto, Cargo busca Cargo.toml en el directorio actual y en sus directorios padres.

--locked

No actualices el archivo Cargo.lock. Verifica que el archivo Cargo.lock esté actualizado, pero no lo modifiques.

--frozen

No actualices los archivos Cargo.lock ni Cargo.lock. Verifica que el archivo Cargo.lock esté actualizado, pero no lo modifiques. Si es necesario, saldrá con un error.

Opciones Comunes

-v, --verbose

Usa verbosidad extendida.

-q, --quiet

Menos mensajes de salida.

--color auto|always|never

Controla cuándo se colorea la salida.

-h, --help

Imprime ayuda sobre la opción.

--Z option

Opciones de compilación inestables (experimental).

EJEMPLOS

Ejecuta todos los benchmarks en el proyecto actual:

cargo bench

Ejecuta solo el benchmark `my_benchmark`:

cargo bench -- my_benchmark

Compila los benchmarks para el target `wasm32-unknown-unknown`, pero no los ejecutes:

cargo bench --target wasm32-unknown-unknown --no-run

Ejecuta solo el benchmark `foo` y pasa la opción `--nocapture` al sistema de pruebas libtest:

cargo bench -- foo -- --nocapture

Ejecuta benchmarks para todos los miembros de un espacio de trabajo:

cargo bench --workspace

AMBIENTE

Consulta https://doc.rust-lang.org/cargo/reference/environment-variables.html para la lista de variables de entorno que Cargo establece para los crates y los comandos.

ESTADO_DE_SALIDA

El estado de salida de cargo bench es 0 si todos los benchmarks se compilaron y ejecutaron correctamente. Si algún benchmark falla (con o sin la opción --no-fail-fast), el estado de salida será distinto de 0.
