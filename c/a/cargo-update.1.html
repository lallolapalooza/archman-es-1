CARGO-UPDATE(1) Manual de comandos generales CARGO-UPDATE(1)

NOMBRE

cargo-update — Actualiza dependencias según lo registrado en el archivo de bloqueo local

SINOPSIS

cargo update [opciones] espec

DESCRIPCIÓN

Este comando actualizará las dependencias en el archivo Cargo.lock a la última versión. Si el archivo Cargo.lock no existe, se creará con las últimas versiones disponibles.

OPCIONES

Opciones de actualización

espec…

Actualiza solo los paquetes especificados. Esta bandera puede especificarse varias veces. Consulte cargo-pkgid(1) para conocer el formato ESPEC.

Si se especifican paquetes con espec, se realizará una actualización conservadora del archivo de bloqueo. Esto significa que solo se actualizará la dependencia especificada por ESPEC. Sus dependencias transitivas se actualizarán solo si ESPEC no se puede actualizar sin actualizar las dependencias. Todas las demás dependencias permanecerán bloqueadas en sus versiones registradas actualmente.

Si no se especifica espec, se actualizan todas las dependencias.

--recursive

Cuando se usa con espec, las dependencias de espec también se fuerzan a actualizar. No se puede usar con --precise.

--precise preciso

Cuando se usa con espec, permite especificar un número de versión específico al que establecer el paquete. Si el paquete proviene de un repositorio git, esta puede ser una revisión git (como un hash SHA o una etiqueta).

Aunque no se recomienda, puede especificar una versión marcada (yanked) de un paquete. Cuando sea posible, intente usar otras versiones compatibles con SemVer no marcadas o busque ayuda de los mantenedores del paquete.

También se puede especificar una versión pre-release compatible incluso cuando el requisito de versión en Cargo.toml no contiene ningún identificador pre-release (solo en la versión nightly).

--breaking directorio

Actualiza espec a la última versión SemVer-breaking.

Los requisitos de versión se modificarán para permitir esta actualización.

Esto solo se aplica a las dependencias cuando

•El paquete es una dependencia de un miembro del espacio de trabajo
•La dependencia no tiene nombre
•Hay disponible una versión SemVer incompatible
•Se utiliza el "operador SemVer" (^ que es el predeterminado)

Esta opción no es estable y solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla. Consulte https://github.com/rust-lang/cargo/issues/12425 para obtener más información.

-w, --workspace

Intenta actualizar solo los paquetes definidos en el espacio de trabajo. Otros paquetes se actualizan solo si ya existen en el archivo de bloqueo. Esta opción es útil para actualizar Cargo.lock después de haber cambiado los números de versión en Cargo.toml.

--dry-run

Muestra lo que se actualizaría, pero en realidad no escribe el archivo de bloqueo.

Opciones de visualización

-v, --verbose

Usa salida detallada. Puede especificarse dos veces para obtener una salida "muy detallada" que incluye información adicional como advertencias de dependencias y salida de scripts de compilación. También se puede especificar con el valor de configuración term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

No imprime mensajes de registro de cargo. También se puede especificar con el valor de configuración term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color cuándo

Controla cuándo se utiliza la salida con color. Valores válidos:
•auto (predeterminado): Detecta automáticamente si el soporte de color está disponible en la terminal.
•always: Siempre muestra colores.
•never: Nunca muestra colores.

También se puede especificar con el valor de configuración term.color https://doc.rust-lang.org/cargo/reference/config.html.

Opciones de manifiesto

--manifest-path ruta

Ruta al archivo Cargo.toml. Por defecto, Cargo busca el archivo Cargo.toml en el directorio actual o en cualquier directorio padre.

--ignore-rust-version

Ignora la especificación rust-version en los paquetes.

--locked

Afirma que se utilizan exactamente las mismas dependencias y versiones que cuando se generó originalmente el archivo Cargo.lock existente. Cargo saldrá con un error cuando surja alguno de los siguientes escenarios:
•Falta el archivo de bloqueo.
•Cargo intentó cambiar el archivo de bloqueo debido a una resolución de dependencias diferente.

Puede usarse en entornos donde se desean compilaciones deterministas, como en pipelines de CI.

--offline

Impide que Cargo acceda a la red por cualquier motivo. Sin esta bandera, Cargo se detendrá con un error si necesita acceder a la red y esta no está disponible. Con esta bandera, Cargo intentará continuar sin la red si es posible.

Tenga cuidado, ya que esto puede resultar en una resolución de dependencias diferente a la del modo en línea. Cargo se limitará a las crates que se descargan localmente, incluso si podría haber una versión más reciente como se indica en la copia local del índice. Consulte el comando cargo-fetch(1) para descargar dependencias antes de desconectarse.

También se puede especificar con el valor de configuración net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Equivalente a especificar tanto --locked como --offline.

--lockfile-path RUTA

Cambia la ruta del archivo de bloqueo de la predeterminada (<workspace_root>/Cargo.lock) a RUTA. RUTA debe terminar con Cargo.lock (por ejemplo, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Tenga en cuenta que proporcionar --lockfile-path ignorará el archivo de bloqueo existente en la ruta predeterminada y, en su lugar, utilizará el archivo de bloqueo de RUTA o escribirá un nuevo archivo de bloqueo en la RUTA proporcionada si no existe. Esta bandera se puede utilizar para ejecutar la mayoría de los comandos en directorios de solo lectura, escribiendo el archivo de bloqueo en la RUTA proporcionada.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla (consulte #14421 https://github.com/rust-lang/cargo/issues/14421).

Opciones comunes

+toolchain

Si Cargo se ha instalado con rustup, y el primer argumento de cargo comienza con +, se interpretará como un nombre de toolchain de rustup (como +stable o +nightly). Consulte la documentación de rustup https://rust-lang.github.io/rustup/overrides.html para obtener más información sobre cómo funcionan las anulaciones de toolchain.

--config CLAVE=VALOR o RUTA

Anula un valor de configuración de Cargo. El argumento debe estar en la sintaxis TOML de CLAVE=VALOR, o proporcionarse como una ruta a un archivo de configuración adicional. Esta bandera se puede especificar varias veces. Consulte la sección de anulaciones de línea de comandos h
