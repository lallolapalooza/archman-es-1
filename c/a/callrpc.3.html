rpc(3) Manual de Funciones de Biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS Y DESCRIPCIÓN

Estas rutinas permiten a los programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de distribución para realizar el servicio solicitado y luego envía una respuesta. Finalmente, la llamada al procedimiento retorna al cliente.

Para utilizar estas rutinas, incluya el archivo de cabecera <rpc/rpc.h>.

Los prototipos a continuación hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consulte los archivos de cabecera para las declaraciones de los tipos AUTH, CLIENT, SVCXPRT y XDR.

void auth_destroy(AUTH *auth);
Una macro que destruye la información de autenticación asociada con auth. La destrucción generalmente implica la desasignación de estructuras de datos privadas. El uso de auth no está definido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y devuelve un manejador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación predeterminada utilizada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y devuelve un manejador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a un array contado de grupos a los que pertenece el usuario. Es fácil suplantar a un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnum y procnum en la máquina, host. El parámetro in es la dirección del(los) argumento(s) del procedimiento, y out es la dirección donde colocar el(los) resultado(s); inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento. Esta rutina devuelve cero si tiene éxito, o el valor de enum clnt_stat convertido a entero si falla. La rutina clnt_perrno() es útil para traducir estados de error a mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina utiliza UDP/IP como transporte; consulte clntudp_create() para conocer las restricciones. No tiene control sobre los tiempos de espera o la autenticación con esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similar a callrpc(), excepto que el mensaje de llamada se transmite a todas las redes de difusión conectadas localmente. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es el mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto se decodifica allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() devuelve cero, clnt_broadcast() espera más respuestas; de lo contrario, retorna con el estado apropiado.
Advertencia: los sockets de difusión tienen un tamaño limitado a la unidad de transferencia máxima del enlace de datos. Para ethernet, este valor es de 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Una macro que llama al procedimiento remoto procnum asociado con el manejador de cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección del(los) argumento(s) del procedimiento, y out es la dirección donde colocar el(los) resultado(s); inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento; tout es el tiempo permitido para que regresen los resultados.
clnt_destroy(CLIENT *clnt);
Una macro que destruye el manejador RPC del cliente. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluyendo clnt mismo. El uso de clnt no está definido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanece abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte se utilizará. Los valores actualmente admitidos para este campo son “udp” y “tcp”. Se establecen tiempos de espera predeterminados, pero se pueden modificar utilizando clnt_control().
Advertencia: usar UDP tiene sus inconvenientes. Dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que aceptan argumentos grandes o devuelven resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Una macro utilizada para cambiar o recuperar diversa información sobre un objeto cliente. req indica el tipo de operación, y info es un puntero a la información. Tanto para UDP como para TCP, los valores admitidos de req y sus tipos de argumento y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo de espera total
CLGET_TIMEOUT  struct timeval // obtener tiempo de espera total

Nota: si establece el tiempo de espera usando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() será ignorado en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener la dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer el tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener el tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que "RPC UDP" espera a que el servidor responda antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los resultados de una llamada RPC. El parámetro out es la dirección de los resultados, y outproc es la rutina XDR que describe los resultados. Esta rutina devuelve uno si los resultados se liberaron exitosamente, y cero en caso contrario.

SVCXPRT *svcraw_create(void)
;
Esta rutina crea un transporte de servicio RPC de juguete, al cual retorna un puntero. El transporte es realmente un búfer dentro del espacio de direcciones del proceso, por lo que el cliente RPC correspondiente debe vivir en el mismo espacio de direcciones; véase clntraw_create(). Esta rutina permite la simulación de RPC y la adquisición de sobrecostos de RPC (co
mo tiempos de ida y vuelta), sin ninguna interf
erencia del kernel. Esta rutina retorna NULL si falla. 
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size)
;
Esta rutina crea un transporte de servicio RPC basado en TCP/IP, al cual retorna un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto TCP local, entonces esta rutina lo enlaza a un puerto arbitrario.
