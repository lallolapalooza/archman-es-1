SINOPSI

S 
use Capture::Tiny ':all';
# capturar desde un comando externo
($stdout, $stderr, $exit) = capture {
  system( $cmd, @args );
};
# capturar desde código arbitrario (Perl o externo)
($stdout, $stderr, @result) = capture {
  # tu código aquí
};
# capturar salida parcial o combinada
$stdout = capture_stdout { ... };
$stderr = capture_stderr { ... };
$merged = capture_merged { ... };
# bifurcar (tee) la salida
($stdout, $stderr) = tee {
  # tu código aquí
};
$stdout = tee_stdout { ... };
$stderr = tee_stderr { ... };
$merged = tee_merged { ...
}
;

DESCRIPCIÓ

N

Capture::Tiny proporciona una forma simple y portable de capturar casi cualquier cosa enviada a STDOUT o STDERR, independientemente de si proviene de Perl, de códig

o XS o de un programa externo. Opcionalmente, la salida puede ser bifurcada (tee) para que sea capturada mientras se pasa a los manejadores de archivo originales. Sí
, incluso funciona en Windows (generalmente). Deja de adivinar cuál de una docena de módulos de captura usar en una situación particular y simplemente usa este uno.

US

O

Las siguientes funciones están disponibles. Ninguna se exporta por

defecto.

captur

e 
($stdout, $stderr, @result) = capture \&
$stdout = capture
\&

La función "capture" toma una referencia de código y devuelve lo que se envía a STDOUT y STDERR, así como cualquier valor de retorno de la referencia de código. En contexto escalar, devuelve solo STDOUT. Si no se recibió salida para un manejador de archivo, devuelve una cadena vacía para ese manejador de archivo. Independientemente del contexto de llamada, toda la salida es capturada -- nada se pasa a los manejadores de archivo

existentes.

Está prototipada para tomar una referencia a subrutina como argumento. Por lo tanto, se puede llamar en forma de

bloque: 
($stdout, $stderr) = capture {
  # tu código aquí ...
}
;

Ten en cuenta que el coderef se evalúa en contexto de lista. Si deseas forzar el contexto escalar en el valor de retorno, debes usar la palabra clave

"scalar". 
($stdout, $stderr, $count) = capture {
  my @list = qw/one two three/;
  return scalar @list; # $count será 3
}
;

Ten en cuenta también que dentro del coderef, la variable @_ estará vacía. Así que no uses argumentos de una subrutina circundante sin copiarlos a una matriz

primero: 
sub wont_work {
  my ($stdout, $stderr) = capture { do_stuff( @_ ) };    # INCORRECTO
  ...
}
sub will_work {
  my @args = @_;
  my ($stdout, $stderr) = capture { do_stuff( @args ) }; # CORRECTO
  ...
}

Las capturas se realizan normalmente en un manejador de archivo temporal anónimo. Para capturar a través de un archivo con nombre (p. ej., para monitorear externamente una captura de larga duración), proporciona manejadores de archivo personalizados como una lista final de pares de

opciones: 
my $out_fh = IO::File->new("out.txt", "w+");
my $err_fh = IO::File->new("err.txt", "w+");
capture { ... } stdout => $out_fh, stderr =>
$err_fh;

Los manejadores de archivo deben ser de lectura/escritura y buscables. Modificar los archivos o manejadores de archivo durante una operación de captura dará resultados impredecibles. Las capas de IO existentes en ellos pueden ser modificadas por la

captura.

Cuando se llama en contexto de vacío, "capture" ahorra memoria y tiempo al no le

er de vuelta desde los
manejadores de captura.

t

\&

es capturado. STDE
RR no es capturado.

capture_stder

r 
($stderr, @result) = capture_stderr \&
$stderr = capture_stderr
\&

La función "capture_stderr" funciona igual que "capture" excepto que solo STDERR

es capturado. STDO
UT no es capturado.

capture_merge

d 
($merged, @result) = capture_merged \&
$merged = capture_merged
\&

La función "capture_merged" funciona igual que "capture" excepto que STDOUT y STDERR se combinan. (Técnicamente, STDERR se redirige al mismo manejador de captura que STDOUT antes de ejecutar la función.

)

Precaución: La salida de STDOUT y STDERR en el

resultado combinado no está garantizada que
esté en el orden correcto debido al buffering.

te

e 
($stdout, $stderr, @result) = tee \&
$stdout = tee
\&

La función "tee" funciona igual que "capture", excepto que la salida es capturada y también pasada al STDOUT y STDERR

originales.

Cuando se llama en contexto de vacío, "tee" ahorra memoria y tiempo al no leer de vuelta desde los manejadores de captura, excepto

cuando el STDOUT o STDERR originales estaban
atados (tied) o abiertos a un manejador escalar.

tee_stdou

t 
($stdout, @result) = tee_stdout \&
$stdout = tee_stdout
\&

La función "tee_stdout" funciona igual que "tee" excepto que solo STDOUT es bifurcado (tee). STDERR

no es bifurcado (la salida v
a a STDERR como de costumbre).

tee_stder

r 
($stderr, @result) = tee_stderr \&
$stderr = tee_stderr
\&

La función "tee_stderr" funciona igual que "tee" excepto que solo STDERR es bifurcado (tee). STDOUT

no es bifurcado (la salida v
a a STDOUT como de costumbre).

tee_merge

d 
($merged, @result) = tee_merged \&
$merged = tee_merged
\&

La función "tee_merged" funciona igual que "capture_merged" excepto que la salida es capturada y también pasada a

STDOUT.

Precaución: La salida de STDOUT y S

TDERR en el resultado combinado no
está garantizada que esté en el
orden correcto debido al buffering.

LIMITACIONE

S

Portabilida

d

La portabilidad es un objetivo, no una garantía. "tee" requiere fork, excepto en Windows donde se usa "system(1, @cmd)" en su lugar. Aún no se ha probado en plataformas particularmente exóticas. Consulta la Matriz de CPAN Testers http://matrix.cpantesters.org/?dist=Capture-Tiny para

ver los resultados de
las pruebas por plataforma.

Capas

PerlIO

Capture::Tiny hace todo lo posible para preservar las capas PerlIO como ':utf8' o ':crlf' al capturar (solo para Perl 5.8.1+). Las capas deben aplicarse a STDOUT o STDERR antes de la llamada a "capture" o "tee". Esto puede no funcionar para manejado

res de archivo atad
os (tied) (ver abajo).

Modificación de manejadores de archivo antes de

capturar

En general, deberías hacer poca o ninguna manipulación de los manejadores de archivo de E/S estándar antes de usar Capture::Tiny. En particular, cerrar, reabrir, localizar o atar (tie) manejadores de archivo estándar antes de capturar puede causar una variedad de comportamientos inesperados, indeseados y/o poco fiables, como se describe a continuación. Capture::Tiny hace todo lo posible para compensar estas situaciones, pero los resultados pueden no ser los que

deseas.

Manejadores de archivo

cerrados

Capture::Tiny funcionará incluso si STDIN, STDOUT o STDERR estáne habían estado cerrados previamente. Sin embargo, como se reabrirán para capturar o hacer tee de la salida, cualquier código dentro del bloque capturado que dependa de encontrarlos cerrados, por supuesto, no los encontrará cerrados. Si estaban cerrados al principio, Capture::Tiny los cerrará de nuevo cuando termine el bloque de

captura.

Tenga en cuenta que esta reapertura ocurrirá incluso para STDIN o un manejador de archivos que no se esté capturando, para asegurar que el manejador de archivos utilizado para la captura no esté abierto al descriptor de archivo 0, ya que esto causa problemas en varias

plataformas.

Antes de Perl 5.12, un STDIN cerrado combinado con PERL_UNICODE=D filtra manejadores de archivos y también rompe tee() por razones no diagnosticadas. Así que no haga

eso.

Manejadores de archivos

localizados

Si el código localiza cualquiera de los manejadores de archivos estándar de Perl antes de capturar, la captura afectará a los manejadores de archivos localizados y no a los originales. Las llamadas al sistema externas no se ven afectadas por localizar un manejador de archivos en Perl y continuarán enviando la salida a los manejadores de archivos originales (que por lo tanto no serán capturados)

.

Manejadores de archivos

escalares

Si STDOUT o STDERR se reabren a manejadores de archivos escalares antes de la llamada a "capture" o "tee", entonces Capture::Tiny sobrescribirá el manejador de archivos de salida durante la duración de la "capture" o "tee" y luego, para "tee", enviará la salida capturada al manejador de archivos de salida después de que la captura esté completa. (Requiere Perl 5.

8)

Capture::Tiny intenta preservar la semántica de STDIN abierto a una referencia escalar, pero tenga en cuenta que los procesos externos no podrán leer de un manejador así. Capture::Tiny intenta asegurar que los procesos externos leerán del dispositivo nulo en su lugar, pero esto no está

garantizado.

Manejadores de archivos de salida

atados

Si STDOUT o STDERR están atados antes de la llamada a "capture" o "tee", entonces Capture::Tiny intentará sobrescribir la atadura durante la duración de la "capture" o "tee" y luego enviará la salida capturada al manejador de archivos atado después de que la captura esté completa. (Requiere Perl 5.

8)

Capture::Tiny puede no tener éxito al reenviar datos codificados en UTF-8 a un STDOUT o STDERR atado. Los caracteres pueden aparecer como bytes. Si el manejador de archivos atado está basado en Tie::StdHandle, entonces Capture::Tiny intentará determinar capas apropiadas como ":utf8" a partir del manejador de archivos subyacente y hará lo

correcto.

Manejador de archivos de entrada

atado

Capture::Tiny intenta preservar la semántica de STDIN atado, pero esto requiere Perl 5.8 y no es del todo predecible. Los procesos externos no podrán leer de un manejador

así.

A menos que tener STDIN atado sea crucial, puede ser más seguro localizar STDIN al

capturar: 
my ($out, $err) = do { local *STDIN; capture { ... }
}
;

Modificar manejadores de archivos durante una

captura

Intentar modificar STDIN, STDOUT o STDERR durante "capture" o "tee" casi con certeza causará problemas. No haga

eso.

Hacer fork dentro de una

captura

Los forks no son portables. El comportamiento de los manejadores de archivos durante un fork lo es aún menos. Si Capture::Tiny detecta que se ha producido un fork dentro de una captura, tomará un atajo en el proceso hijo y devolverá cadenas vacías para las capturas. También pueden ocurrir otros problemas en el hijo o el padre. No se recomienda hacer fork en un bloque de

captura.

Usando

hilos

Los manejadores de archivos son globales. Mezclar E/S y capturas en diferentes hilos sin coordinación causará problemas. Además, los hilos están oficialmente

desalentados.

Renunciando a privilegios durante una

captura

Si renuncia a privilegios durante una captura,

los archivos temporales creados para facili
tar la captura pueden no ser limpiados después.

Sin soporte para Perl 5.8.

0

Simplemente es demasiado defectuoso

en cuanto a capas y UTF-8. Se rec
omienda Perl 5.8.1 o posterior.

Soporte limitado para Perl 5.

6

Perl 5.6 es anterior a

PerlIO. Los datos UTF-
8 pueden no ser captura
dos correctamente.

ENTORN

O

PERL_CAPTURE_TINY_TIMEOU

T

Capture::Tiny usa subprocesos internamente para "tee". Por defecto, Capture::Tiny agotará el tiempo de espera con un error si tales subprocesos no están listos para recibir datos dentro de 30 segundos (o lo que sea el valor de $Capture::Tiny::TIMEOUT). Se puede especificar un tiempo de espera alternativo estableciendo la variable de entorno "PERL_CAPTURE_TINY_TIMEOUT". Establecerla en cero desactivará los tiempos de espera. NOTA, esto no agota el tiempo de espera de la referencia de código que se está captu

rando -- esto solo evita que Capture::Tin
y cuelgue su proceso esperando a que sus pro
cesos hijos estén listos para continuar.

TAMBIÉN

Este módulo fue inspirado por IO::CaptureOutput, que proporciona funcionalidad similar sin la capacidad de hacer tee de la salida y con código y API más complicados. IO::CaptureOutput no maneja capas ni la mayoría de los casos inusuales descritos en la sección "LIMITACIONES" y yo ya no lo

recomiendo.

Hay muchos otros módulos de CPAN que proporcionan algún tipo de captura de salida, aunque con varias limitaciones que los hacen apropiados solo en circunstancias particulares. Probablemente me falte alguno. La larga lista se proporciona para mostrar por qué sentí que Capture::Tiny era

necesario.
