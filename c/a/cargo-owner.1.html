NOMBRE

cargo-owner — Gestiona los propietarios de un crate en el registro

SINOPSIS

cargo owner [opciones] --add login [crate]
cargo owner [opciones] --remove login [crate]
cargo owner [opciones] --list [crate]

DESCRIPCIÓN

Este comando modificará los propietarios de un crate en el registro. Los propietarios de un crate pueden subir nuevas versiones y retirar (yank) versiones antiguas. Los propietarios que no son equipos también pueden modificar el conjunto de propietarios, ¡así que ten cuidado!

Este comando requiere que estés autenticado con la opción --token o usando cargo-login(1).

Si no se especifica el nombre del crate, se usará el nombre del paquete del directorio actual.

Consulta la referencia https://doc.rust-lang.org/cargo/reference/publishing.html#cargo-owner para más información sobre propietarios y publicación.

OPCIONES

Opciones de Owner

-a, --add login…

Invita al usuario o equipo dado como propietario.

-r, --remove login…

Elimina al usuario o equipo dado como propietario.

-l, --list

Lista los propietarios de un crate.

--token token

Token de API a usar al autenticarse. Esto anula el token almacenado en el archivo de credenciales (que es creado por cargo-login(1)).

Configuración de Cargo https://doc.rust-lang.org/cargo/reference/config.html Se pueden usar variables de entorno para anular los tokens almacenados en el archivo de credenciales. El token para crates.io puede especificarse con la variable de entorno CARGO_REGISTRY_TOKEN . Los tokens para otros registros pueden especificarse con variables de entorno de la forma CARGO_REGISTRIES_NAME_TOKEN donde NAME es el nombre del registro en mayúsculas.

--index index

La URL del índice del registro a usar.

--registry registry

Nombre del registro a usar. Los nombres de registro se definen en los archivos de Configuración de Cargo archivos https://doc.rust-lang.org/cargo/reference/config.html. Si no se especifica, se usa el registro predeterminado, que está definido por la clave de configuración registry.default que por defecto es crates-io.

Opciones de Visualización

-v, --verbose

Usa salida detallada. Puede especificarse dos veces para una salida “muy detallada” que incluye salida extra como advertencias de dependencias y salida de scripts de compilación. También puede especificarse con el valor de configuración term.verbose valor de configuración https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

No imprime mensajes de registro de cargo. También puede especificarse con el valor de configuración term.quiet valor de configuración https://doc.rust-lang.org/cargo/reference/config.html.

--color cuándo

Controla cuándo se usa la salida con color. Valores válidos:
•auto (predeterminado): Detecta automáticamente si hay soporte de color disponible en la terminal.
•always: Siempre muestra colores.
•never: Nunca muestra colores.

También puede especificarse con el valor de configuración term.color valor de configuración https://doc.rust-lang.org/cargo/reference/config.html.

Opciones Comunes

+toolchain

Si Cargo ha sido instalado con rustup, y el primer argumento a cargo comienza con +, se interpretará como un nombre de toolchain de rustup (como +stable o +nightly). Consulta la documentación de rustup https://rust-lang.github.io/rustup/overrides.html para más información sobre cómo funcionan las anulaciones de toolchain.

--config KEY=VALUE o PATH

Anula un valor de configuración de Cargo. El argumento debe estar en sintaxis TOML de KEY=VALUE, o proporcionarse como una ruta a un archivo de configuración extra. Esta bandera puede especificarse múltiples veces. Consulta la sección de anulaciones por línea de comandos https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides para más información.

-C PATH

Cambia el directorio de trabajo actual antes de ejecutar cualquier operación especificada. Esto afecta cosas como dónde busca cargo por defecto el manifiesto del proyecto (Cargo.toml), así como los directorios buscados para descubrir .cargo/config.toml, por ejemplo. Esta opción debe aparecer antes del nombre del comando, por ejemplo cargo -C path/to/my-project build.

Esta opción solo está disponible en el canal nightly canal https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarse (ver #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Imprime información de ayuda.

-Z flag

Banderas inestables (solo nightly) para Cargo. Ejecuta cargo -Z help para detalles.

ENTORNO

Consulta la referencia https://doc.rust-lang.org/cargo/reference/environment-variables.html para detalles sobre las variables de entorno que lee Cargo.

ESTADO DE SALIDA

•0: Cargo tuvo éxito.
•101: Cargo falló al completarse.

EJEMPLOS

1.Listar los propietarios de un paquete: 
cargo owner --list foo
2.Invitar a un propietario a un paquete: 
cargo owner --add username foo
3.Eliminar a un propietario de un paquete: 
cargo owner --remove username foo

    SINAPSIS

    cargo owner [opciones] [subcomando]

    DESCRIPCIÓN

    Gestiona los propietarios de los crates en crates.io.

    OPCIONES

    --help
    Muestra la ayuda para este subcomando.
    -i, --index URL
    La URL del registro de crates. Por defecto, se utiliza el registro configurado en el archivo .cargo/config.toml, o crates.io si no se especifica ninguno.
    -g, --git-index-url URL
    La URL del repositorio Git del índice de crates. Por defecto, se utiliza el registro configurado en el archivo .cargo/config.toml, o crates.io si no se especifica ninguno.
    -k, --kerberos
    Utiliza Kerberos para la autenticación. Solo para el índice basado en Git.
    --token-auth TOKEN
    Utiliza el token de autenticación proporcionado para la autenticación con el registro. Esto es útil para la automatización o si no deseas iniciar sesión con cargo login.
    -v, --verbose
    Utiliza información detallada de registro. (Para la mayoría de los comandos de Cargo, esto solo es necesario para la depuración. Para cargo owner, se muestra el nombre de usuario al que se está apuntando.)
    -q, --quiet
    No muestra mensajes de registro.
    --color when
    Controla cuándo se utiliza el color en la salida. Las opciones son auto, always, never.
    --frozen
    Requiere que el archivo Cargo.lock esté actualizado o ausente.
    --locked
    Requiere que el archivo Cargo.lock esté presente y actualizado.
    --offline
    Simula que no hay acceso a la red.

    ENTORNO

    Para obtener información sobre el entorno de configuración de Cargo, consulta la documentación de cargo help environment.

    ESTADO DE SALIDA

    El código de salida de cargo owner es 0 si la operación fue exitosa, o un valor distinto de cero en caso contrario.

    EJEMPLOS

    Para añadir un propietario a un crate:

    cargo owner --add github_user_name

    Para añadir un equipo propietario a un crate:

    cargo owner --add github:rust-lang:team_name

    Para eliminar un propietario de un crate:

    cargo owner --remove github_user_name

    Para listar los propietarios de un crate:

    cargo owner --list

    Para listar los propietarios de un crate específico:

    cargo owner --crate my_crate --list
