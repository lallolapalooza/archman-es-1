NOMBRE

CALL - invocar un procedimiento

SINOPSIS

CALL nombre ( [ argumento ] [, ...] )

DESCRIPCIÓN

CALL ejecuta un procedimiento.

Si el procedimiento tiene parámetros de salida, se devolverá una fila de resultado, que contendrá los valores de esos parámetros.

PARÁMETROS

nombre

El nombre (opcionalmente calificado por esquema) del procedimiento.

argumento

Una expresión de argumento para la llamada al procedimiento.

Los argumentos pueden incluir nombres de parámetros, usando la sintaxis nombre => valor. Esto funciona igual que en las llamadas a funciones ordinarias; ver la Sección 4.3 para más detalles.

Se deben proporcionar argumentos para todos los parámetros del procedimiento que carezcan de valores predeterminados, incluidos los parámetros OUT. Sin embargo, los argumentos que coinciden con los parámetros OUT no se evalúan, por lo que es habitual simplemente escribir NULL para ellos. (Escribir algo diferente para un parámetro OUT podría causar problemas de compatibilidad con versiones futuras de PostgreSQL.)

NOTAS

El usuario debe tener el privilegio EXECUTE sobre el procedimiento para poder invocarlo.

Para llamar a una función (no a un procedimiento), usa SELECT en su lugar.

Si se ejecuta CALL dentro de un bloque de transacción, el procedimiento llamado no puede ejecutar sentencias de control de transacción. Las sentencias de control de transacción solo están permitidas si CALL se ejecuta en su propia transacción.

PL/pgSQL maneja los parámetros de salida en los comandos CALL de manera diferente; ver la Sección 41.6.3.

EJEMPLOS

CALL do_db_maintenance();

COMPATIBILIDAD

CALL cumple con el estándar SQL, excepto por el manejo de parámetros de salida. El estándar dice que los usuarios deben escribir variables para recibir los valores de los parámetros de salida.
