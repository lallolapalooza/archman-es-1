NOMBRE

cargo-logout — Eliminar un token de API del registro localmente

SINOPSIS

cargo logout [opciones]

DESCRIPCIÓN

Este comando ejecutará un proveedor de credenciales para eliminar un token guardado.

Para el proveedor de credenciales predeterminado cargo:token, las credenciales se almacenan en $CARGO_HOME/credentials.toml donde $CARGO_HOME por defecto es .cargo en tu directorio de usuario.

Si un registro tiene un proveedor de credenciales especificado, se utilizará. De lo contrario, se intentarán los proveedores del valor de configuración registry.global-credential-providers, comenzando desde el final de la lista.

Si no se especifica --registry, se eliminarán las credenciales para el registro predeterminado (configurado por registry.default https://doc.rust-lang.org/cargo/reference/config.html#registrydefault, que por defecto es https://crates.io/).

Esto no revocará el token en el servidor. Si necesitas revocar el token, visita el sitio web del registro y sigue sus instrucciones (ver https://crates.io/me para revocar el token para https://crates.io/).

OPCIONES

Opciones de Logout

--registry registro

Nombre del registro a utilizar. Los nombres de los registros se definen en los archivos de configuración de Cargo https://doc.rust-lang.org/cargo/reference/config.html. Si no se especifica, se utiliza el registro predeterminado, que se define por la clave de configuración registry.default, que por defecto es crates-io.

Opciones de Visualización

-v, --verbose

Utiliza salida detallada. Se puede especificar dos veces para una salida “muy detallada” que incluye información adicional como advertencias de dependencias y salida de scripts de compilación. También se puede especificar con el valor de configuración term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

No imprimir mensajes de registro de cargo. También se puede especificar con el valor de configuración term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color cuándo

Controla cuándo se utiliza la salida en color. Valores válidos:
•auto (predeterminado): Detecta automáticamente si el soporte de color está disponible en la terminal.
•always: Muestra siempre colores.
•never: Nunca muestra colores.

También se puede especificar con el valor de configuración term.color https://doc.rust-lang.org/cargo/reference/config.html.

Opciones Comunes

+toolchain

Si Cargo se ha instalado con rustup, y el primer argumento para cargo comienza con +, se interpretará como un nombre de toolchain de rustup (como +stable o +nightly). Consulta la documentación de rustup https://rust-lang.github.io/rustup/overrides.html para más información sobre cómo funcionan las anulaciones de toolchain.

--config CLAVE=VALOR o RUTA

Anula un valor de configuración de Cargo. El argumento debe estar en sintaxis TOML de CLAVE=VALOR, o proporcionarse como una ruta a un archivo de configuración adicional. Esta opción se puede especificar múltiples veces. Consulta la sección de anulaciones de línea de comandos https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides para más información.

-C RUTA

Cambia el directorio de trabajo actual antes de ejecutar cualquier operación especificada. Esto afecta a dónde busca cargo por defecto el manifiesto del proyecto (Cargo.toml), así como a los directorios buscados para descubrir .cargo/config.toml, por ejemplo. Esta opción debe aparecer antes del nombre del comando, por ejemplo cargo -C ruta/a/mi-proyecto build.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarse (ver #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Imprime información de ayuda.

-Z bandera

Banderas inestables (solo para nightly) para Cargo. Ejecuta cargo -Z help para obtener detalles.

MEDIO AMBIENTE

Consulta la referencia https://doc.rust-lang.org/cargo/reference/environment-variables.html para obtener detalles sobre las variables de entorno que Cargo lee.

ESTADO DE SALIDA

•0: Cargo tuvo éxito.
•101: Cargo no pudo completarse.

EJEMPLOS

1.Eliminar el token del registro predeterminado: 
cargo logout
2.Eliminar el token para un registro específico: 
cargo logout --registry mi-registro
