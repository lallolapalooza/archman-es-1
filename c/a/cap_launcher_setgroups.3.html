cap_launcher_setgroups(3)

Paquete: libcap

Licencias: BSD-3-Clause OR GPL-2.0-only

CAP_LAUNCH(3) Manual del Programador de Linux CAP_LAUNCH(3)

NOMBRE

cap_new_launcher, cap_func_launcher, cap_launcher_callback, cap_launcher_set_mode, cap_launcher_set_iab, cap_launcher_set_chroot, cap_launch, cap_launcher_setuid, cap_launcher_setgroups - Funcionalidad de lanzamiento de libcap

SINOPSIS

#include <sys/capability.h>
cap_launch_t cap_new_launcher(const char *arg0, const char *const *argv,
    const char *const *envp);
cap_launch_t cap_func_launcher(int (callback_fn)(void *detail));
int cap_launcher_callback(cap_launch_t attr,
    int (callback_fn)(void *detail));
int cap_launcher_set_mode(cap_launch_t attr, cap_mode_t flavor);
cap_iab_t cap_launcher_set_iab(cap_launch_t attr, cap_iab_t iab);
int cap_launcher_set_chroot(cap_launch_t attr, const char *chroot);
#include <sys/types.h>
pid_t cap_launch(cap_launch_t attr, void *detail);
int cap_launcher_setuid(cap_launch_t attr, uid_t uid);
int cap_launcher_setgroups(cap_launch_t attr, gid_t gid,
    int ngroups, const gid_t *groups);

Enlazar con -lcap.

DESCRIPCIÓN

Un lanzador proporciona un mecanismo para que el código ejecute una función de retorno de llamada y/o un ejecutable de programa en un entorno con un contexto de seguridad modificado. Esencialmente, proporciona un mecanismo para que un programa fork(2) un nuevo contexto a partir del del programa principal, manipule las capacidades y otro estado privilegiado en ese fork(2)proceso antes de (opcionalmente) execve(2)un nuevo programa. Cuando la aplicación se enlaza con -lpsx este soporte es necesario para ejecutar de forma robusta el código lanzado sin modificar el privilegio de toda la aplicación principal (que respeta la semántica POSIX).

Un lanzador se define con una de estas dos funciones: cap_new_launcher() o cap_func_launcher(). El valor de retorno es de un tipo opaco cap_launch_t un valor de retorno de NULL implica que ha ocurrido un error.

Una vez definido, un valor cap_launch_t puede usarse con cap_launch() para ejecutar ese lanzador. En tales casos, un valor de retorno no negativo indica éxito: cero significa éxito sin que se haya invocado un programa; no cero es igual al ID del proceso (pid_t) del programa recién lanzado.

Un cap_launch_t ocupa memoria asignada y debe liberarse con cap_free(3). Antes de ser cap_free(3)d, un cap_value_t valor puede reutilizarse para múltiples lanzamientos independientes. El argumento detail de cap_launch(), en conjunto con la función de retorno de llamada del lanzador, puede usarse para personalizar la invocación del lanzamiento. Se debe tener cuidado de aprovechar la memoria compartida personalizada (ver mmap(2)) u otra IPC para devolver valores al programa principal a través de detail ya que la llamada de retorno y cualquier ejecución posterior del programa ocurrirán fuera del proceso principal de la aplicación que llama. Un ejemplo de esto sería asignar detail de la siguiente manera:

   const char *args[] = { "echo", "hello", NULL };
   cap_launch_t cmd = cap_new_launcher("/usr/bin/echo", args, NULL);
   int *detail = mmap(NULL, sizeof(int), PROT_READ | PROT_WRITE,
                      MAP_SHARED | MAP_ANONYMOUS, -1, 0);
   cap_launcher_callback(cmd, &answer_detail_fn);
   *detail = 41;
   pid_t pid = cap_launch(cmd, detail);
   printf("launcher callback set detail to %d\n", *detail);
   munmap(detail, sizeof(int));

A menos que la función de retorno de llamada lo modifique, el código lanzado se ejecutará con las capacidades y el otro contexto de seguridad de la aplicación.

Si la función de retorno de llamada devuelve algo distinto de cero, un cap_launch() se abortará. Si el detalle del fallo es importante para el llamante, debe comunicarse a través del detail argumento.

Las siguientes funciones pueden usarse para instruir al lanzador para modificar el estado de seguridad del programa invocado sin alterar el estado del programa que llama. Dichas modificaciones deben realizarse antes de llamar a cap_launch() si deben tener el efecto deseado. Además, solo se invocan después de que cualquier retorno de llamada instalado haya finalizado. Por ejemplo, se pueden eliminar o modificar capacidades, solo para ejecutar un archivo.

Las siguientes funciones instruyen al lanzador para realizar algunas tareas comunes de este tipo (nota: algunas requieren bits de capacidad permitidos para tener éxito):

cap_launcher_callback() puede usarse para instalar o reemplazar la función de retorno de llamada actualmente instalada del lanzador.

cap_launcher_set_mode() puede usarse para asegurar que el modo de libcap del programa lanzado sea el deseado.

cap_launcher_set_iab() Esta función devuelve el cap_iab_t previamente asociado con el lanzador. Llamar a esta función con un valor IAB de NULL configurará el lanzador para no establecer un valor IAB (el valor predeterminado). Ver cap_iab(3) para detalles sobre el conjunto IAB. Nota, el lanzador se asocia directamente con el valor iab proporcionado, y no hace una copia del mismo. Este valor iab está bloqueado en el lanzador y no puede modificarse mientras esté asociado con el lanzador. Establézcalo con NULL para recuperar el control sobre la memoria asociada con ese valor IAB, de lo contrario el valor IAB será cap_free()d cuando el lanzador lo sea.

cap_launcher_set_chroot() Esta función hace que el ejecutable del programa lanzado sea invocado dentro de un chroot root directorio.

cap_launcher_setuid() Esta función hace que el ejecutable del programa lanzado sea invocado con el identificador de usuario especificado (uid_t).

cap_launcher_setgroups() Esta función hace que el ejecutable del programa lanzado sea invocado con los IDs de grupo primario y suplementario especificados.

Nota, si alguna de las mejoras del lanzador realizadas por las funciones anteriores no surte efecto (típicamente por falta de privilegio suficiente), el lanzamiento fallará y devolverá -1.

ERRORES

Un retorno de NULL para un cap_launch_t debe considerarse un error.

cap_launch() devuelve -1 en caso de error.

En todos estos casos un valor de retorno de 0 implica éxito. En otros casos, consulte errno(3) para más detalles.

HISTORIA

La cap_launch() familia de funciones se introdujo en libcap 2.33. Aborda principalmente una complejidad con -lpsx enlazada pthreads(7) aplicaciones que usan capacidades pero también respetan la semántica POSIX.

Usar -lcap y -lpthread juntos sin el soporte de semántica POSIX de -lpsx introduce una clase sutil de exposición a la escalada de privilegios. (Ver https://sites.google.com/site/fullycapable/who-ordered-libpsx para una explicación.)
