CARGO-VENDOR(1) General Commands Manual CARGO-VENDOR(1)

NOMBRE

cargo-vendor — Envía todas las dependencias localmente

SINOPSIS

cargo vendor [opciones] [ruta]

DESCRIPCIÓN

Este subcomando de cargo enviará todas las dependencias de crates.io y git al directorio especificado en <ruta>. Después de que este comando se complete, el directorio de envío especificado por <ruta> contendrá todas las fuentes remotas de las dependencias especificadas. Se pueden especificar manifiestos adicionales más allá del predeterminado con la opción -s.

La configuración necesaria para utilizar las fuentes enviadas se imprimirá en la salida estándar después de que cargo vendor complete el proceso de envío. Deberá agregarla o redirigirla a su archivo de configuración de Cargo, que suele ser .cargo/config.toml localmente para el paquete actual.

Cargo trata las fuentes enviadas como de solo lectura, al igual que lo hace con las fuentes del registro y de git. Si tiene la intención de modificar un crate de una fuente remota, use [patch] o una dependencia path que apunte a una copia local de ese crate. Cargo manejará correctamente el crate en reconstrucciones incrementales, ya que sabe que ya no es una dependencia de solo lectura.

OPCIONES

Opciones de envío

-s manifiesto, --sync manifiesto

Especifica un manifiesto Cargo.toml adicional para espacios de trabajo que también deben ser enviados y sincronizados a la salida. Se puede especificar varias veces.

--no-delete

No elimine el directorio “vendor” al enviar, sino que conserve todo el contenido existente del directorio de envío.

--respect-source-config

En lugar de ignorar la configuración [source] por defecto en .cargo/config.toml, léala y úsela al descargar crates de crates.io, por ejemplo.

--versioned-dirs

Normalmente, las versiones solo se agregan para desambiguar múltiples versiones del mismo paquete. Esta opción hace que todos los directorios en el directorio “vendor” sean versionados, lo que facilita el seguimiento del historial de paquetes enviados con el tiempo y puede ayudar al rendimiento de reenviar cuando solo un subconjunto de los paquetes ha cambiado.

Opciones de manifiesto

--manifest-path ruta

Ruta al archivo Cargo.toml. Por defecto, Cargo busca el archivo Cargo.toml en el directorio actual o en cualquier directorio padre.

--locked

Afirma que se utilizan exactamente las mismas dependencias y versiones que cuando se generó el archivo Cargo.lock existente. Cargo saldrá con un error cuando surja cualquiera de los siguientes escenarios:
•El archivo de bloqueo falta.
•Cargo intentó cambiar el archivo de bloqueo debido a una resolución de dependencias diferente.

Puede usarse en entornos donde se desean compilaciones deterministas, como en tuberías de CI.

--offline

Impide que Cargo acceda a la red por cualquier motivo. Sin esta bandera, Cargo se detendrá con un error si necesita acceder a la red y la red no está disponible. Con esta bandera, Cargo intentará continuar sin la red si es posible.

Tenga en cuenta que esto puede resultar en una resolución de dependencias diferente a la del modo en línea. Cargo se limitará a los crates que se descargan localmente, incluso si puede haber una versión más reciente indicada en la copia local del índice. Consulte el comando cargo-fetch(1) para descargar dependencias antes de desconectarse.

También se puede especificar con el valor de configuración net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Equivalente a especificar tanto --locked como --offline.

--lockfile-path RUTA

Cambia la ruta del archivo de bloqueo desde el valor predeterminado (<workspace_root>/Cargo.lock) a RUTA. RUTA debe terminar en Cargo.lock (por ejemplo, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Tenga en cuenta que proporcionar --lockfile-path ignorará el archivo de bloqueo existente en la ruta predeterminada, y en su lugar usará el archivo de bloqueo de RUTA o escribirá un nuevo archivo de bloqueo en RUTA proporcionado si no existe. Esta bandera se puede usar para ejecutar la mayoría de los comandos en directorios de solo lectura, escribiendo el archivo de bloqueo en RUTA proporcionado.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla (ver #14421 https://github.com/rust-lang/cargo/issues/14421).

Opciones de visualización

-v, --verbose

Usa salida detallada. Se puede especificar dos veces para obtener una salida “muy detallada” que incluye salida adicional como advertencias de dependencias y salida de scripts de compilación. También se puede especificar con el valor de configuración term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

No imprima mensajes de registro de cargo. También se puede especificar con el valor de configuración term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color cuándo

Controla cuándo se utiliza la salida en color. Valores válidos:
•auto (predeterminado): Detecta automáticamente si el soporte de color está disponible en la terminal.
•always: Muestra siempre colores.
•never: Nunca muestra colores.

También se puede especificar con el valor de configuración term.color https://doc.rust-lang.org/cargo/reference/config.html.

Opciones comunes

+toolchain

Si Cargo se ha instalado con rustup, y el primer argumento de cargo comienza con +, se interpretará como un nombre de toolchain de rustup (como +stable o +nightly). Consulte la documentación de rustup https://rust-lang.github.io/rustup/overrides.html para obtener más información sobre cómo funcionan las anulaciones de toolchain.

--config CLAVE=VALOR o RUTA

Anula un valor de configuración de Cargo. El argumento debe estar en la sintaxis TOML de CLAVE=VALOR, o proporcionarse como una ruta a un archivo de configuración adicional. Esta bandera se puede especificar varias veces. Consulte la sección de anulaciones de línea de comandos https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides para obtener más información.

-C RUTA

Cambia el directorio de trabajo actual antes de ejecutar cualquier operación especificada. Esto afecta a dónde busca Cargo por defecto el manifiesto del proyecto (Cargo.toml), así como a los directorios que se buscan para descubrir .cargo/config.toml, por ejemplo. Esta opción debe aparecer antes del nombre del comando, por ejemplo cargo -C ruta/a/mi-proyecto build.

Esta opción solo está disponible en el canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html y requiere la bandera -Z unstable-options para habilitarla (ver #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Imprime información de ayuda.

-Z bandera

Banderas inestables (solo nightly) para Cargo. Ejecute cargo -Z help para obtener detalles.

EJEMPLOS

Ejemplo 1

Envía todas las dependencias del proyecto actual al directorio `vendor`:

cargo vendor vendor

CONFIGURACIÓN

La siguiente sección describe cómo configurar el archivo .cargo/config.toml para utilizar las fuentes enviadas, que se imprimen en la salida estándar después de la ejecución de cargo-vendor.

```toml [source.crates-io] replace-with = "vendored-sources" [source.rename-crates-io] replace-with = "vendored-sources" [source.vendored-sources] directory = "vendor" ```

EJEMPLOS

1.Proveer todas las dependencias en una carpeta local “vendor” 
cargo vendor
2.Proveer todas las dependencias en una carpeta local “third-party/vendor” 
cargo vendor third-party/vendor
3.Proveer el espacio de trabajo actual así como otro en “vendor” 
cargo vendor -s ../ruta/a/Cargo.toml
4.Proveer y redirigir las configuraciones necesarias de vendor a un archivo de configuración. 
cargo vendor > ruta/a/mi/cargo/config.toml
