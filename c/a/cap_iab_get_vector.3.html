Esta tupla IAB de 3 elementos de vectores de capacidades, capturada en el tipo cap_iab_t, se combinan para pasar capacidades de un proceso a otro a través de execve(2) llamadas al sistema. Las reglas de convolución que utilizan la tupla IAB son un conjunto de reglas de respaldo cuando el archivo ejecutado no tiene capacidades de archivo configuradas. El kernel impone algunas restricciones con respe

cto a

los tres componentes de una tupla IAB y el indicador de capacidades de proceso Permitted. Son: el vector Inh ( CAP_IAB_INH) es completamente igual al indicador Inheritable del proceso entodo momento; el vector Amb ( CAP_IAB_AMB) no contiene más valores de capacidad que la interseccióndel vector Inh y el indicador Permitted para el proceso; y el vector Bound (o bloqueado) ( CAP_IAB_BOUND) es el complemento a dos del vector de límites del proceso. En algunosentornos, se considera deseable heredar capacidades de forma simple.

Es

decir, pasar capacidades, independientemente del estado del binario ejecutado, del padre al hijo a través de llamadas al sistema exec*. Las capacidades que sobreviven se convierten en el indicador Permitted para el proceso posterior a exec. Este método de herencia difiere significativamente de la herencia por intercambio entre un proceso pre-exec* y un ejecutable con capacidades de archivo otorgadas del mecanismo de capacidades tradicional (POSIX.1e). Las reglas de convolución para la herencia de estilo IAB son: I'=I; A'=A&

P'=A&I&P.

Donde P, etc., son los valores pre-exec y P', etc., son los valores post-exec. Con un entendimiento de estas reglas de convolución, podemos explicar

Se introdujo para extender la lista simple separada por comas de capacidades Inheritable del proceso, que el módulo podía otorgar a un árbol de procesos autenticado, para incluir límites aplicados en el vector Bounding y introducir soporte para el vector Ambient de bits

Aunque los vectores Inheritable y Bounding fueron anticipados por el borrador POSIX.1e que introdujo las capacidades, el vector Ambient es una invención de Linux e incompatible con el modelo de capacidades de archivo POSIX.1e. Como tal, se consideró que intentar fusionar los 5 vectores de capacidades en una representación de texto no iba a funcionar. En su lugar, la sintaxis de configuración de pam_cap.so se generalizó en un conjunto completo de funciones de libcap para agrupar las t
