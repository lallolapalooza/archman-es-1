cap_get_pid(3)

CAP_GET_PROC(3) Manual del Programador de Linux CAP_GET_PROC(3)

NOMBRE

cap_get_proc, cap_set_proc, capgetp, cap_get_bound, cap_drop_bound, cap_get_ambient, cap_set_ambient, cap_reset_ambient, cap_get_secbits, cap_set_secbits, cap_get_mode, cap_set_mode, cap_mode_name, cap_get_pid, cap_setuid, cap_prctl, cap_prctlw, cap_setgroups - manipulación de capacidades en procesos

SINOPSIS

#include <sys/capability.h>
cap_t cap_get_proc(void);
int cap_set_proc(cap_t cap_p);
int cap_get_bound(cap_value_t cap);
CAP_IS_SUPPORTED(cap_value_t cap);
int cap_drop_bound(cap_value_t cap);
int cap_get_ambient(cap_value_t cap);
int cap_set_ambient(cap_value_t cap, cap_flag_value_t value);
int cap_reset_ambient(void);
CAP_AMBIENT_SUPPORTED();
unsigned cap_get_secbits(void);
int cap_set_secbits(unsigned bits);
cap_mode_t cap_get_mode(void);
const char *cap_mode_name(cap_mode_t mode);
int cap_prctl(long int pr_cmd, long int arg1, long int arg2,
	      long int arg3, long int arg4, long int arg5);
int cap_prctlw(long int pr_cmd, long int arg1, long int arg2,
	       long int arg3, long int arg4, long int arg5);
int cap_set_mode(cap_mode_t mode);
#include <sys/types.h>
cap_t cap_get_pid(pid_t pid);
int cap_setuid(uid_t uid);
int cap_setgroups(gid_t gid, size_t ngroups, const gid_t groups);

Enlazar con -lcap.

DESCRIPCIÓN

cap_get_proc() asigna un estado de capacidad en el área de trabajo, establece su estado al del proceso que realiza la llamada y devuelve un puntero a este estado de capacidad recién creado. El llamante debe liberar cualquier memoria liberable, cuando el estado de capacidad en el área de trabajo ya no sea necesario, llamando a cap_free() con el argumento cap_t.

cap_set_proc() establece los valores para todos los indicadores de capacidad a todos los bits de capacidad del estado de capacidad identificado por cap_p. El nuevo estado de capacidad del proceso estará completamente determinado por el contenido de cap_p tras el retorno exitoso de esta función. Si algún indicador en cap_p está establecido para cualquier capacidad que actualmente no esté permitida para el proceso que realiza la llamada, la función fallará y el estado de capacidad del proceso permanecerá sin cambios.

cap_get_pid() devuelve un cap_t, véase cap_init(3), con las capacidades de proceso del proceso conocido por el llamante como pid. Si pid es 0, entonces se devuelven las capacidades del proceso que realiza la llamada. Esta información también se puede obtener del archivo /proc/<pid>/status. (Las entradas de ese archivo se pueden traducir con el comando capsh --decode=XXX). Cuando el llamante opera dentro de un espacio de nombres (CLONE_NEWPID), el argumento numérico pid se interpreta en el rango de ese espacio de nombres. Por lo tanto, la idea del llamante del pid de destino puede diferir de la del proceso de destino cuando operan en diferentes espacios de nombres de pid. Consulte pid_namespaces(7) para obtener detalles. Además, el cap_t devuelto contiene las capacidades que el pid de destino cree que tiene. Si el destino opera en un espacio de nombres (CLONE_NEWUSER), el privilegio a nivel de sistema de esas capacidades de espacio de nombres de usuario puede reducirse sustancialmente. Consulte user_namespaces(7) para obtener detalles.

cap_get_bound() con un argumento cap devuelve el valor actual de este indicador de capacidad del conjunto de límites en efecto para el proceso que realiza la llamada. Esta operación no requiere privilegios. Nota, se proporciona una función macro CAP_IS_SUPPORTED(cap_value_t cap) que se evalúa como verdadero (1) si el sistema admite la capacidad especificada, cap. Si el sistema no admite la capacidad, esta función devuelve 0. Esta macro funciona probando una condición de error con cap_get_bound().

cap_drop_bound() se puede usar para reducir la capacidad especificada del conjunto de límites, cap. Para que se complete exitosamente, el conjunto de capacidades efectivas predominante debe tener un CAP_SETPCAP elevado.

cap_get_ambient() devuelve el valor predominante de la capacidad ambiental especificada, o -1 si la capacidad no es compatible con el kernel en ejecución. Una macro CAP_AMBIENT_SUPPORTED() utiliza esta función para determinar si las capacidades ambientales son compatibles con el kernel.

cap_set_ambient() establece la capacidad ambiental especificada a un valor específico. Para elevar una capacidad ambiental específica, los indicadores heredables y permitidos del proceso que realiza la llamada deben contener el valor de capacidad especificado. Los bits ambientales elevados solo se conservarán mientras esto sea cierto para los indicadores heredables y permitidos.

cap_reset_ambient() restablece todas las capacidades ambientales para el proceso que realiza la llamada a su valor reducido. Nota, el conjunto ambiental está diseñado para operar en un entorno heredado donde la aplicación tiene una conciencia limitada de las capacidades en general. Al ejecutar un archivo, con capacidades de sistema de archivos asociadas, el kernel restablecerá implícitamente el conjunto ambiental del proceso. Además, los cambios en el conjunto heredable por el código del programa sin ajustar explícitamente el conjunto ambiental también pueden reducir los bits ambientales.

cap_get_secbits() devuelve los securebits del proceso que realiza la llamada. Estos bits afectan la forma en que el proceso que realiza la llamada implementa cosas como la corrección de setuid-root y las capacidades ambientales.

cap_set_secbits() intenta modificar los securebits del proceso que realiza la llamada. Nota: se debe tener CAP_SETPCAP en el conjunto de capacidades efectivas para que esto sea efectivo. Algunas configuraciones bloquean los sub-estados de los securebits, por lo que los intentos de establecer valores pueden ser denegados por el kernel incluso cuando la capacidad CAP_SETPCAP está elevada.

Para ayudar a gestionar la complejidad de los securebits, libcap proporciona un concepto combinado de securebit y conjunto de capacidades llamado modo libcap. cap_get_mode() intenta resumir el entorno de seguridad predominante en forma de un valor numérico cap_mode_t. Se puede obtener una representación textual del modo a través de la función cap_mode_name(). La gran mayoría de las combinaciones de estos valores no están bien definidas en términos de un modo libcap, y para estos estados cap_get_mode() devuelve (cap_mode_t)0, que cap_get_name() identifica como ``UNCERTAIN''. Los modos admitidos son: CAP_MODE_NOPRIV, CAP_MODE_HYBRID, CAP_MODE_PURE1E y CAP_MODE_PURE1E_INIT.

cap_prctl() se puede usar para leer el estado a través de la llamada al sistema prctl().

cap_prctlw() se puede usar para escribir el estado a través de la llamada al sistema prctl().

cap_set_mode() se puede usar para establecer el modo deseado. Se requiere la capacidad permitida CAP_SETPCAP para que esta función tenga éxito.

cap_setuid() es una función de conveniencia para la llamada al sistema setuid(2). Donde cap_setuid() se encarga de que la capacidad efectiva correcta se eleve para realizar la llamada al sistema, y también se encarga de preservar la disponibilidad de las capacidades permitidas después de que el uid haya cambiado. Después de esta llamada, todas las capacidades efectivas se reducen.

cap_setgroups() es una función de conveniencia para realizar las llamadas setgid(2) y setgroups(2) en una sola llamada. La llamada cap_setgroups() eleva la capacidad efectiva correcta durante la llamada, y vacía el conjunto de capacidades efectivas antes de devolver.

VALOR DE RETORNO

Las funciones cap_get_proc() y cap_get_pid() devuelven un valor no NULL en caso de éxito, y NULL en caso de fallo.

La función cap_get_bound() devuelve -1 si la capacidad solicitada es desconocida, de lo contrario el valor de retorno refleja el estado actual de esa capacidad en el conjunto de límites predominante. Nota, una función macro,

Todas las funciones de configuración como cap_set_proc() y cap_drop_bound() devuelven cero en caso de éxito y -1 en caso de fallo.

En caso de fallo, errno se establece en EINVAL, EPERM o ENOMEM.

CONFORMIDAD

cap_set_proc() y cap_get_proc() están especificadas en el borrador de especificación retirado de POSIX.1e. cap_get_pid() es una extensión de Linux.

La biblioteca también soporta las funciones

capgetp() intenta obtener las capacidades de algún otro proceso; almacenando las capacidades en un cap_d preasignado. Vea cap_init() para información sobre cómo asignar un conjunto de capacidades vacío. Esta función está obsoleta; debería usar cap_get_p

capsetp() intenta configurar las capacidades del proceso que llama o de algún otro u otros procesos, pid. Tenga en cuenta que configurar las capacidades de otro proceso solo es posible en kernels más antiguos que no proporcionan soporte VFS para configurar capacidades de archivos. Vea capset(2) para información sobre qué kernels proporcionan dicho

soporte.

Si pid es positivo, se refiere a un proceso específico; si es cero, se refiere al proceso que llama; -1 se refiere a todos los procesos distintos al proceso que llama y al proceso '1' (típicamente init(8)); otros valores negativos se refieren al grupo de procesos

-pid.

Para usar esta función, el kernel debe soportarla y el proceso que llama debe tener CAP_SETPCAP activado en su conjunto de capacidades efectivas. Las capacidades configuradas en el proceso(s) objetivo son las contenidas en cap_d

.

Los kernels que soportan capacidades del sistema de archivos redefinen la semántica de CAP_SETPCAP y en tales sistemas, capsetp() siempre fallará para cualquier objetivo distinto al proceso que llama. capsetp() devuelve cero para éxito, y -1 para

fallo.

En kernels donde esto es (era) soportado, capsetp() debe usarse con cuidado. Existía principalmente para superar una falta temprana de soporte para capacidades en los sistemas de archivos soportados por Linux. Tenga en cuenta que en kernels más antiguos donde capsetp() podía usarse para configurar las capacidades de otro proceso, los únicos procesos que tenían CAP_SETPCAP disponible para ellos por defecto eran procesos iniciados como hilos del kernel. (Típicamente esto incluye init(8), kflushd y kswapd.) Se necesitaba una

recompilación del kern

llamante: 
    ...
    cap_t caps;
    const cap_value_t cap_list[2] = {CAP_FOWNER, CAP_SETFCAP};
    if (!CAP_IS_SUPPORTED(CAP_SETFCAP))
        /* handle error */
    caps = cap_get_proc();
    if (caps == NULL)
        /* handle error */;
    if (cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET) == -1)
        /* handle error */;
    if (cap_set_proc(caps) == -1)
        /* handle error */;
    if (cap_free(caps) == -1)
        /* handle error */;
    ..
