cap_launcher_set_mode(3)

CAP_LAUNCH(3) Manual del programador de Linux CAP_LAUNCH(3)

NOMBRE

cap_new_launcher, cap_func_launcher, cap_launcher_callback, cap_launcher_set_mode, cap_launcher_set_iab, cap_launcher_set_chroot, cap_launch, cap_launcher_setuid, cap_launcher_setgroups - funcionalidad de lanzamiento de libcap

SINOPSIS

#include <sys/capability.h>
cap_launch_t cap_new_launcher(const char *arg0, const char *const *argv,
    const char *const *envp);
cap_launch_t cap_func_launcher(int (callback_fn)(void *detail));
int cap_launcher_callback(cap_launch_t attr,
    int (callback_fn)(void *detail));
int cap_launcher_set_mode(cap_launch_t attr, cap_mode_t flavor);
cap_iab_t cap_launcher_set_iab(cap_launch_t attr, cap_iab_t iab);
int cap_launcher_set_chroot(cap_launch_t attr, const char *chroot);
#include <sys/types.h>
pid_t cap_launch(cap_launch_t attr, void *detail);
int cap_launcher_setuid(cap_launch_t attr, uid_t uid);
int cap_launcher_setgroups(cap_launch_t attr, gid_t gid,
    int ngroups, const gid_t *groups);

Enlace con -lcap.

DESCRIPCIÓN

Un lanzador proporciona un mecanismo para que el código ejecute una función de devolución de llamada y/o un programa ejecutable en un entorno con un contexto de seguridad modificado. Esencialmente, proporciona un mecanismo para que un programa fork(2) un nuevo contexto desde el del programa principal manipule la capacidad y otro estado privilegiado en ese proceso fork(2)do antes de (opcionalmente) execve(2) un nuevo programa. Cuando la aplicación se enlaza con -lpsx se necesita este soporte para ejecutar de manera robusta el código lanzado sin modificar el privilegio de toda la aplicación principal (que respeta la semántica POSIX).

Un lanzador se define por una de estas dos funciones: cap_new_launcher() o cap_func_launcher(). El valor de retorno siendo de tipo opaco cap_launch_t, un valor de retorno NULL implica que ha ocurrido un error.

Una vez definido, se puede usar un valor de cap_launch_t con cap_launch() para ejecutar ese lanzador. En tales casos, un valor de retorno no negativo indica éxito: cero significa éxito sin que se haya invocado ningún programa; un valor distinto de cero es igual al ID de proceso (pid_t) del programa recién lanzado.

Un cap_launch_t ocupa memoria asignada y debe liberarse con cap_free(3). Antes de ser cap_free(3)d un valor de cap_value_t puede reutilizarse para múltiples lanzamientos independientes. El argumento detail a cap_launch(), junto con la función de devolución de llamada del lanzador, se puede utilizar para personalizar la invocación del lanzamiento. Se debe tener cuidado al utilizar memoria compartida personalizada (ver mmap(2)) o algún otro IPC para devolver valores al programa principal a través de detail, ya que la devolución de llamada y cualquier ejecución de programa posterior ocurrirán fuera del proceso principal de la aplicación llamante. Un ejemplo de esto sería asignar detalle de la siguiente manera:

   const char *args[] = { "echo", "hello", NULL };
   cap_launch_t cmd = cap_new_launcher("/usr/bin/echo", args, NULL);
   int *detail = mmap(NULL, sizeof(int), PROT_READ | PROT_WRITE,
                      MAP_SHARED | MAP_ANONYMOUS, -1, 0);
   cap_launcher_callback(cmd, &answer_detail_fn);
   *detail = 41;
   pid_t pid = cap_launch(cmd, detail);
   printf("launcher callback set detail to %d\n", *detail);
   munmap(detail, sizeof(int));

A menos que sea modificado por la función de devolución de llamada, el código lanzado se ejecutará con el contexto de seguridad y capacidades de la aplicación.

Si la función de devolución de llamada devuelve algo distinto de cero, se abortará cap_launch(). Si el detalle del fallo es importante para el llamante, debe comunicarse a través del argumento detail.

Las siguientes funciones se pueden utilizar para instruir al lanzador a modificar el estado de seguridad del programa invocado sin alterar el estado del programa llamante. Dichas modificaciones deben realizarse antes de llamar a cap_launch() si van a tener el efecto deseado. Además, solo se invocan después de que cualquier devolución de llamada instalada haya completado. Por ejemplo, se pueden eliminar o modificar capacidades, *justo* para ejecutar un archivo.

Las siguientes funciones instruyen al lanzador para realizar algunas tareas comunes de este tipo (tenga en cuenta que algunas requieren bits de capacidad permitidos para tener éxito):

cap_launcher_callback() se puede utilizar para instalar o reemplazar la función de devolución de llamada actualmente instalada del lanzador.

cap_launcher_set_mode() se puede utilizar para asegurar que el modo libcap del programa lanzado sea el deseado.

cap_launcher_set_iab() Esta función devuelve el cap_iab_t previamente asociado con el lanzador. Llamar a esta función con un valor IAB de NULL configurará el lanzador para no establecer un valor IAB (el valor predeterminado). Ver cap_iab(3) para detalles sobre el conjunto IAB. Tenga en cuenta que el lanzador se asocia directamente con el valor *iab* proporcionado y no crea una copia de él. Este valor iab está bloqueado al lanzador y no se puede modificar mientras está asociado con el lanzador. Establecerlo a NULL para recuperar el control sobre la memoria asociada con ese valor IAB, de lo contrario, el valor IAB se liberará con cap_free() cuando el lanzador sea liberado.

cap_launcher_set_chroot() Esta función hace que el programa ejecutable lanzado se invoque dentro de un directorio raíz de chroot *root*.

cap_launcher_setuid() Esta función hace que el programa ejecutable lanzado se invoque con el identificador de usuario especificado (*uid_t*).

cap_launcher_setgroups() Esta función hace que el programa ejecutable lanzado se invoque con los identificadores de grupo primario y suplementarios especificados.

Tenga en cuenta que si alguna de las mejoras del lanzador realizadas por las funciones anteriores no surte efecto (normalmente por falta de privilegio suficiente), el lanzamiento fallará y devolverá -1.

ERRORES

Un retorno de NULL para un cap_launch_t debe considerarse un error.

cap_launch() devuelve -1 en caso de error.

En todos estos casos, un valor de retorno de 0 implica éxito. En otros casos, consulte errno(3) para obtener más detalles.

HISTORIA

La familia de funciones cap_launch() se introdujo en libcap 2.33. Aborda principalmente una complejidad con las aplicaciones pthreads(7) enlazadas con -lpsx que usan capacidades pero también respetan la semántica POSIX.

Usar -lcap y -lpthread juntos sin el soporte de semántica POSIX de -lpsx introduce una sutil clase de exposición a la escalada de privilegios. (Ver https://sites.google.com/site/fullycapable/who-ordered-libpsx para una explicación.)
