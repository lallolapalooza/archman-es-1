C'est-à-dire que la modification des ensembles de capacités, par défaut, n'affecte que le thread en cours d'exécution. Pour être significativement sécurisé, cependant, les ensembles de capacités doivent être répliquésd by all threads within a common program because threads are not memory isolated. As a workaround for this, libcap is packaged with a separate POSIX semantics system call library: libpsx. If your program uses POSIX threads, to achieve meaningful POSIX semantics capability manipulation, you should link your program with:

ld ... -lcap $(pkg-config --libs --cflags libpsx)

or,

gcc ... -lcap $(pkg-config --libs --cflags libpsx)

When linked this way, due to linker magic, libcap uses psx_syscall(3) and psx_syscall6(3) to perform state setting system calls. Notably, this also ensures that cap_prctlw() can be used to ensure process control bits are shared over all threads of a single process.

capgetp() y capsetp()

La biblioteca también soporta las funciones obsoletas:

int capgetp(pid_t pid, cap_t cap_d);

int capsetp(pid_t pid, cap_t cap_d);

capgetp() intenta obtener las capacidades de otro proceso; almacenando las capacidades en un cap_d preasignado. Ver cap_init() para información sobre cómo asignar un conjunto de capacidades vacío. Esta función está obsoleta; deberías usar cap_get_pid().

capsetp() intenta establecer las capacidades del proceso que llama o de otro(s) proceso(s), pid. Nota que establecer las capacidades de otro proceso solo es posible en kernels más antiguos que no proporcionan soporte VFS para establecer capacidades de archivo. Ver capset(2) para información sobre qué kernels proporcionan dicho soporte.

Si pid es positivo se refiere a un proceso específico; si es cero, se refiere al proceso que llama; -1 se refiere a todos los procesos excepto al que llama y al proceso '1' (típicamente init(8)); otros valores negativos se refieren al grupo de procesos -pid.

Para usar esta función, el kernel debe soportarla y el proceso que llama debe tener CAP_SETPCAP levantado en su conjunto de capacidades Efectivas. Las capacidades establecidas en el(los) proceso(s) objetivo son las contenidas en cap_d.

Los kernels que soportan capacidades de sistema de archivos redefinen la semántica de CAP_SETPCAP y en tales sistemas, capsetp() siempre fallará para cualquier objetivo distinto al proceso que llama. capsetp() devuelve cero en caso de éxito, y -1 en caso de fallo.

En kernels donde estaba (o está) soportado, capsetp() debe usarse con cuidado. Existía, principalmente, para superar una falta temprana de soporte para capacidades en los sistemas de archivos soportados por Linux. Nota que en kernels más antiguos donde capsetp() podía usarse para establecer las capacidades de otro proceso, los únicos procesos que tenían CAP_SETPCAP disponible por defecto eran los procesos iniciados como hilos del kernel. (Típicamente esto incluye init(8), kflushd y kswapd.) Se necesitaba una recompilación del kernel para modificar este comportamiento por defecto.

EJEMPLO

El segmento de código a continuación levanta las capacidades efectivas CAP_FOWNER y CAP_SETFCAP para el llamador:

    ...
    cap_t caps;
    const cap_value_t cap_list[2] = {CAP_FOWNER, CAP_SETFCAP};
    if (!CAP_IS_SUPPORTED(CAP_SETFCAP))
        /* manejar error */
    caps = cap_get_proc();
    if (caps == NULL)
        /* manejar error */;
    if (cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET) == -1)
        /* manejar error */;
    if (cap_set_proc(caps) == -1)
        /* manejar error */;
    if (cap_free(caps) == -1)
        /* manejar error */;
    ...

Alternativamente, para soltar completamente el privilegio en un programa lanzado como setuid-root pero que quiere ejecutarse como un ID de usuario específico, etc., de tal manera que ni él ni ninguno de sus hijos puedan adquirir privilegios de nuevo:

    ...
    uid_t nobody = 65534;
    const gid_t groups[] = {65534};
    if (cap_setgroups(groups[0], 1, groups) != 0)
        /* manejar error */;
    if (cap_setuid(nobody) != 0)
        /* manejar error */;
    /*
     * el privilegio todavía está disponible aquí
     */
    if (cap_set_mode(CAP_MODE_NOPRIV) != 0)
        /* manejar error */
    ...

Nota, la secuencia anterior puede ser realizada por la herramienta capsh de la siguiente manera:

sudo capsh --user=nobody --mode=NOPRIV --print

donde --print muestra el estado de privilegio resultante.
