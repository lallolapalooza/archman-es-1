CERTMAP.CONF(5) Manual de formatos de archivo CERTMAP.CONF(5)

NOMBRE

certmap.conf - Archivo de configuración para la autenticación de cliente TLS en 389 Directory Server.

SINOPSIS

/etc/dirsrv/config/certmap.conf

DESCRIPCIÓN

certmap.conf

Este archivo configura cómo se mapea un certificado a una entrada LDAP. Consulte la documentación para obtener más información sobre este archivo: https://access.redhat.com/documentation/en-us/red_hat_directory_server/10/html/configuration_command_and_file_reference/configuration_file_reference#certmap_conf

SINTAXIS

El formato de este archivo es el siguiente:
certmap <nombre> <issuerDN>
<nombre>:<prop1> [<val1>]
<nombre>:<prop2> [<val2>]

Notas:


1. El mapeo se puede definir por emisor de un certificado. Si no existe un mapeo
para un 'issuerDN' particular, el servidor utiliza el mapeo predeterminado.
default.


2. Debe haber una entrada para <nombre>=default y issuerDN
"default".
Este mapeo es el mapeo predeterminado.


3. '#' se puede usar para comentar una línea.


4. DNComps y FilterComps se utilizan para formar el DN base y el filtro responsable de
realizar una búsqueda LDAP al mapear el certificado a una entrada de usuario.

OPCIONES

DNComps
El parámetro DNComps determina cómo el Servidor de Directorio genera el DN base utilizado para buscar un usuario en el directorio. Esta configuración acepta una lista separada por comas de atributos para formar un DN. Sin embargo, el orden de los atributos en el parámetro DNComps debe coincidir con el orden en el asunto del certificado. Por ejemplo, si el asunto de su certificado es "e=nombre_usuario@ejemplo.com,cn=nombre_usuario,o=Example Inc.,c=US", y desea que el Servidor de Directorio utilice "cn=nombre_usuario,o=Example Inc.,c=US" como DN base al buscar al usuario, establezca el parámetro DNComps en "cn, o, c".

Comente o no establezca este parámetro si el campo de asunto del certificado coincide exactamente con el DN del usuario en el Servidor de Directorio o si desea utilizar la configuración del parámetro CmapLdapAttr.

Si el valor está vacío, buscará en todo el árbol LDAP utilizando el parámetro FilterComps.

FilterComps
Este parámetro establece qué atributos del campo de asunto del certificado utiliza el Servidor de Directorio para generar el filtro de búsqueda para localizar al usuario.

Establezca este parámetro en una lista separada por comas de atributos utilizados en el asunto del certificado. El Servidor de Directorio utilizará estos atributos en una operación AND en el filtro.

Nota: Los asuntos de certificado utilizan el atributo e para la dirección de correo electrónico, que no existe en el esquema predeterminado del Servidor de Directorio. Por esta razón, el Servidor de Directorio mapea automáticamente este atributo al atributo mail. Esto significa que si utiliza el atributo mail en el parámetro FilterComps, el Servidor de Directorio lee el valor del atributo e del asunto del certificado.

Por ejemplo, si el asunto de un certificado es "e=nombre_usuario@ejemplo.com,cn=nombre_usuario,dc=ejemplo,dc=com,o=Example Inc.,c=US" y desea generar dinámicamente el filtro "(&(mail=usuario@dominio)(cn=nombre_usuario))", establezca el parámetro FilterComps en "mail, cn".

Si el parámetro está comentado o establecido en un valor vacío, se utilizará el filtro (objectclass=*).

verifycert
El Servidor de Directorio siempre verifica si el certificado ha sido emitido por una Autoridad de Certificación (CA) de confianza. Sin embargo, si además establece el parámetro verifycert en "on", el Servidor de Directorio verificará adicionalmente que el certificado coincida con el certificado con formato Distinguished Encoding Rules (DER) almacenado en el atributo binario userCertificate del usuario.

Si no establece este parámetro, verifycert estará deshabilitado.

CmapLdapAttr
Si sus entradas de usuario contienen un atributo que almacena el DN del asunto del certificado del usuario, establezca CmapLdapAttr en este nombre de atributo. El Servidor de Directorio utilizará este atributo y el DN del asunto para localizar al usuario. En este caso, no se genera ningún filtro basado en los atributos del parámetro FilterComps.

EJEMPLOS

certmap default default
default:DNComps cn, o, c
#default:FilterComps e, uid
#default:verifycert on
#default:CmapLdapAttr certSubjectDN

certmap example o=Example Inc.,c=US
example:DNComps
