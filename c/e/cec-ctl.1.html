CEC-CTL(1) Comandos de usuario CEC-CTL(1)

NOMBRE

cec-ctl - Una aplicación para controlar dispositivos cec

SINOPSIS

cec-ctl [-h] [-d <dev>[muchas otras opciones]

DESCRIPCIÓN

La herramienta cec-ctl se utiliza para controlar dispositivos cec. Es capaz de controlar casi cualquier aspecto de dichos dispositivos, cubriendo toda la API de CEC.

La forma más fácil de probar rápidamente un adaptador CEC de una salida HDMI es:

cec-ctl -d/dev/cecX --playback -S

Esto es lo que usarías si la salida HDMI de tu dispositivo soporta CEC: tu dispositivo reproducirá vídeo, por lo que es un dispositivo de reproducción CEC.

Y para una entrada HDMI:

cec-ctl -d/dev/cecX --tv -S

Esto es lo que usarías si tu dispositivo tiene una entrada HDMI, es decir, actúa como un televisor.

Ambos comandos configuran el adaptador CEC y muestran la topología de CEC. Las opciones '--playback' y '--tv' configuran tu dispositivo, no se refieren al dispositivo con el que vas a comunicarte.

Para poner una pantalla en espera (standby) usa:

cec-ctl -d/dev/cecX --to 0 --standby

Para despertar la pantalla:

cec-ctl -d/dev/cecX --to 0 --image-view-on

Para cambiar el televisor a nuestra salida HDMI (reemplaza la dirección física con la que reportó cec-ctl -d/dev/cecX):

cec-ctl -d/dev/cecX --to 0 --active-source phys-addr=1.0.0.0

En lugar de '-d/dev/cecX' también puedes escribir '-dX'. Y en lugar de '--to 0' también puedes escribir '-t0'.

OPCIONES

-A, --list-devices
Lista todos los dispositivos cec.
-d, --device <dev>
Usa el dispositivo <dev> como dispositivo CEC. Si <dev> es un número, entonces se usa /dev/cec<dev>.
-D, --driver <drv>
Usa un dispositivo cec que tenga el nombre de controlador <drv>, tal como lo devuelve el ioctl CEC_ADAP_G_CAPS. Esta opción se puede combinar con -a para identificar de forma única un dispositivo CEC sin tener que depender del número de nodo del dispositivo.
-a, --adapter <adap-name>
Usa un dispositivo cec que tenga el nombre de adaptador <adap-name>, tal como lo devuelve el ioctl CEC_ADAP_G_CAPS. Esta opción se puede combinar con -D para identificar de forma única un dispositivo CEC sin depender del número de nodo del dispositivo.
-v, --verbose
Activa el informe detallado (verbose).
--version
Muestra la información de la versión.
-w, --wall-clock
Muestra las marcas de tiempo como hora del reloj de pared. Esto también activa el informe detallado.
-h, --help
Imprime el mensaje de ayuda.
-p, --phys-addr <addr>
Usa esta dirección física. La dirección puede ser un número (p. ej. 0 o 0x11b1) o formateada como a.b.c.d donde cada componente es un valor hexadecimal de 0-f (p. ej. 0.0.0.0 o 1.1.b.1).
-e, --phys-addr-from-edid <path>
Analiza el archivo EDID dado (en formato binario sin procesar) y extrae la dirección física. Si el archivo EDID no existe o no contiene una dirección física, invalida la dirección física.
-E, --phys-addr-from-edid-poll <path>
Analiza el archivo EDID dado (en formato binario sin procesar) y extrae la dirección física. Si el archivo EDID no existe o no contiene una dirección física, invalida la dirección física. Sondea los cambios en este archivo EDID cada 100 ms y, si cambia, actualiza la dirección física.

Esto proporciona una forma para que los dongles USB CEC de Pulse-Eight (o similares) se enteren de los eventos de desconexión y reconexión de HDMI.

El sondeo ocurre en segundo plano mientras cec-ctl procesa otras acciones solicitadas (es decir, transmitiendo mensajes, esperando respuestas, etc.) y cuando todo eso está terminado, cec-ctl seguirá sondeando hasta que el usuario mate a cec-ctl (Ctrl-C).

-o, --osd-name <name>
Usa este nombre OSD. La longitud máxima es de 14 caracteres.
-V, --vendor-id <id>
Usa este ID de proveedor. El ID de proveedor es un número de 0x0 a 0xffffff.
-x, --physical-address
Muestra la dirección física. Si es inválida, la dirección física se reportará como f.f.f.f. Útil para scripts, p. ej.: la=`cec-ctl -s -x`
-l, --logical-address
Muestra la primera dirección lógica configurada o nada si el dispositivo está sin configurar. Útil para scripts, p. ej.: la=`cec-ctl -s -l`
-L, --logical-addresses
Muestra todas las direcciones lógicas configuradas o nada si el dispositivo está sin configurar. Útil para scripts, p. ej.: las=`cec-ctl -s -L`
-C, --clear
Borra todas las direcciones lógicas, dejando el dispositivo CEC sin configurar.
-n, --no-reply
Por defecto, al enviar un mensaje CEC que espera una respuesta, esta utilidad esperará esa respuesta. Con esta opción, simplemente la enviará sin esperar la respuesta. Esta opción se aplica a los mensajes que siguen a esta opción. Actúa como un interruptor (toggle), así que después de especificarla una segunda vez, los mensajes siguientes volverán a esperar una respuesta.
-N, --non-blocking
Transmite mensajes en modo no bloqueante.
-t, --to <la>
Envía el mensaje a la dirección lógica dada (0-15).
-f, --from <la>
Envía el mensaje desde la dirección lógica dada. Solo es necesario usar esta opción si se han reclamado múltiples direcciones lógicas. Por defecto se usará la primera dirección lógica asignada.
-r, --show-raw
Muestra el mensaje CEC sin procesar en hexadecimal.
-s, --skip-info
Omite la sección de salida de Información del Controlador.
-S, --show-topology
Muestra la topología de CEC, detectando qué otros dispositivos CEC hay en el bus de CEC.
-P, --poll
Envía un mensaje de sondeo (poll).
-T, --trace
Traza todos los ioctls llamados. Útil para depurar.
--cec-version-1.4
Usa la versión 1.4 de CEC en lugar de la 2.0 (la predeterminada).
--allow-unreg-fallback
Permite el retroceso a No Registrado (Unregistered) si todas las direcciones lógicas están reclamadas. Por defecto, el adaptador permanecerá sin configurar.
--no-rc-passthrough
Desactiva el paso (passthrough) de RC. Por defecto, los mensajes CEC del mando a distancia se reenvían como pulsaciones de teclas de entrada (el CEC_LOG_ADDRS_FL_ALLOW_RC_PASSTHRU se establece al llamar al CEC_ADAP_S_LOG_ADDRS ioctl), pero esto se puede bloquear usando esta opción.
--reply-to-followers
La respuesta se enviará también a los seguidores (followers). Por defecto, la respuesta solo irá al seguidor que inició el mensaje CEC. Pero si tienes otros seguidores ejecutándose también, al dar esta opción también recibirán la respuesta.
--timeout <ms>
Establece el tiempo de espera de respuesta en milisegundos (el valor predeterminado es 1000 ms).
--tv
Configura el adaptador CEC como un televisor.
--record
Configura el adaptador CEC como un dispositivo de grabación y reproducción.
--tuner
Configura el adaptador CEC como un dispositivo sintonizador (tuner).
--playback
Configura el adaptador CEC como un dispositivo de reproducción.
--audio
Configura el adaptador CEC como un dispositivo de sistema de audio.
--processor
Configura el adaptador CEC como un dispositivo procesador.
--switch
Configura el adaptador CEC como un conmutador CEC puro.
--cdc-only
Configura el adaptador CEC como un dispositivo solo CDC.
--unregistered
Configura el adaptador CEC como un dispositivo no registrado.
--feat-record-tv-screen
Indica la función de Grabar Pantalla de TV.
--feat-set-osd-string
Indica la función de Establecer Cadena OSD.
--feat-deck-control
Indica la función de Control de Deck.
--feat-set-audio-rate
Indica la función de Establecer Tasa de Audio.
--feat-sink-has-arc-tx
Indica la función ARC Tx del receptor.
--feat-source-has-arc-rx
Indica la función ARC Rx de la fuente.
--rc-tv-profile-1
Indica el Perfil de TV de Control Remoto 1.
--rc-tv-profile-2
Indica el Perfil de TV de Control Remoto 2.
--rc-tv-profile-3
Indica el Perfil de TV de Control Remoto 3.
--rc-tv-profile-4
Indica el Perfil de TV de Control Remoto 4.
--rc-src-dev-root
Indica que la fuente de Control Remoto tiene un Menú Raíz de Dispositivo.
--rc-src-dev-setup
Indica que la fuente de Control Remoto tiene un Menú de Configuración de Dispositivo.
--rc-src-contents
Indica que la fuente de Control Remoto tiene un Menú de Contenidos.
--rc-src-media-top
Indica que la fuente de Control Remoto tiene un Menú Principal de Medios.
--rc-src-media-context
Indica que la fuente de Control Remoto tiene un Menú de Contexto de Medios.
-m, --monitor
Inicia la monitorización del tráfico CEC. Esto monitorizará mensajes de difusión, mensajes dirigidos a este adaptador CEC y mensajes transmitidos por este adaptador CEC. Los mensajes dirigidos entre otros dispositivos CEC no son monitorizados. Esta opción requiere privilegios de root.
-M, --monitor-all
Inicia la monitorización de todo el tráfico CEC. Esto monitorizará todos los mensajes CEC, incluidos los mensajes dirigidos entre otros dispositivos CEC. Esta opción requiere privilegios de root. No todos los dispositivos CEC soportan este modo de monitorización. Volverá al modo de monitorización regular si no es compatible.
--monitor-pin
Inicia la monitorización y análisis de las transiciones de pines CEC de bajo nivel. Esto solo es posible si el dispositivo tiene la capacidad CEC_CAP_MONITOR_PIN. Esta opción requiere privilegios de root. Cuando está en modo de monitorización de pines, todas las transiciones de pines CEC de 0->1 y 1->0 son monitorizadas y analizadas. Esto es efectivamente un analizador de bus CEC de bajo costo.
--monitor-time <secs>
Monitoriza durante el número dado de segundos y luego sale. El valor por defecto (0) es monitorizar indefinidamente.
--ignore <la>,<opcode>
Ignora mensajes de la dirección lógica <la> y del código de operación <opcode> durante la monitorización. Se puede usar "all" para <la> o <opcode> para coincidir con todas las direcciones lógicas u códigos de operación. Para ignorar mensajes de sondeo, usa "poll" como <opcode>.
--store-pin <to>
Almacena los eventos de pines CEC en el archivo dado. Esto se puede leer y analizar posteriormente a través de la opción --analyze-pin. Usa - para escribir a stdout en lugar de a un archivo.
--analyze-pin <from>
Lee y analiza los eventos de pines CEC desde el archivo dado. Usa - para leer desde stdin en lugar de desde un archivo.
--test-reliability <secs>
Esta opción prueba la fiabilidad de CEC transmitiendo <Give Physical Addr> hasta <secs> segundos (o indefinidamente si <secs> es 0) y verifica si la respuesta es siempre la misma. Dado que la respuesta es un mensaje de difusión, en la práctica nunca se Nackea y, por lo tanto, los errores de bits debidos a una mala calidad de la señal CEC se mostrarán claramente. El mensaje se enviará a la dirección lógica especificada por --to.
--test-standby-wakeup-cycle [polls=<n>][,sleep=<secs>][,hpd-may-be-low=<0/1>]
Esta opción prueba el comportamiento del ciclo de espera/activación de la pantalla. Sondea hasta <n> veces (por defecto 15), esperando un cambio de estado. Si eso falla, espera <secs> segundos (por defecto 10) antes de reintentar esto. Si <hpd-may-be-low> es 1, entonces se permite que HPD esté bajo cuando está en espera.
--stress-test-standby-wakeup-cycle cnt=<count>[,polls=<n>][,max-sleep=<maxsecs>][,min-sleep=<minsecs>][,seed=<seed>][,repeats=<reps>][,sleep-before-on=<secs1>][,sleep-before-off=<secs2>][,hpd-may-be-low=<0/1>]
Esta opción realiza una prueba de estrés para una pantalla: alterna la pantalla <count> veces dentro y fuera de la espera utilizando los comandos CEC Standby e Image View On. Si <count> es 0, entonces nunca se detiene. Sondea hasta <n> veces (por defecto 30), esperando un cambio de estado. Si <maxsecs> no es cero (0 es el valor por defecto), entonces duerme durante un número aleatorio de segundos entre <minsecs> (0 es el valor por defecto) y <maxsecs> antes de cada mensaje <Standby> o <Image View On>. Si se especifica <seed>, entonces se establece la semilla del generador aleatorio a ese valor en lugar de usar la hora actual como semilla. Si se especifica <reps>, entonces se repiten <Image View On> y <Standby> hasta <reps> veces. Tenga en cuenta que esta prueba debería funcionar sin repeticiones. Si se necesita un valor <reps> no nulo para pasar esta prueba, entonces eso indica un problema. Si se especifica <secs1>, entonces duerme durante <secs1> segundos antes de transmitir <Image View On>. Si se especifica <secs2>, entonces duerme durante <secs2> segundos antes de transmitir <Standby>. Si <hpd-may-be-low> es 1, entonces se permite que HPD esté bajo cuando está en espera.
--stress-test-random-standby-wakeup-cycle cnt=<count>[,max-sleep=<maxsecs>][,min-sleep=<minsecs>][,seed=<seed>][,hpd-may-be-low=<0/1>]
Esta opción realiza una prueba de estrés para una pantalla: alterna la pantalla <count> veces dentro y fuera de la espera utilizando los comandos CEC Standby e Image View On. Después de cada comando, espera entre <minsecs> (el valor por defecto es 0) y <maxsecs> (el valor por defecto es 10) segundos. Esta prueba no verifica si la pantalla alcanzó el nuevo estado, esta prueba está destinada a verificar si la pantalla puede manejar comandos de cambio de estado mientras aún se está en transición a un nuevo estado. Después de cada 10 ciclos intenta activar correctamente la pantalla y verifica si funciona. Si no, esta prueba falla. Si <count> es 0, entonces nunca se detiene. Si se especifica <seed>, entonces se establece la semilla del generador aleatorio a ese valor en lugar de usar la hora actual como semilla. Si <hpd-may-be-low> es 1, entonces se permite que HPD esté bajo cuando está en espera.
