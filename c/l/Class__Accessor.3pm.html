Class::Accessor(3) Documentación de Perl aportada por el usuario Class::Accessor(3)

NOMBRE

Class::Accessor - Generación automática de accessors

SINOPSIS

package Foo;
use base qw(Class::Accessor);
Foo->follow_best_practice;
Foo->mk_accessors(qw(name role salary));
# o si prefieres una interfaz similar a Moose...
package Foo;
use Class::Accessor "antlers";
has name => ( is => "rw", isa => "Str" );
has role => ( is => "rw", isa => "Str" );
has salary => ( is => "rw", isa => "Num" );
# ¡Mientras tanto, en un fragmento de código cercano!
# Class::Accessor proporciona new().
my $mp = Foo->new({ name => "Marty", role => "JAPH" });
my $job = $mp->role;  # obtiene $mp->{role}
$mp->salary(400000);  # establece $mp->{salary} = 400000 # Ojalá
# como mi @info = @{$mp}{qw(name role)}
my @info = $mp->get(qw(name role));
# $mp->{salary} = 400000
$mp->set('salary', 400000);

DESCRIPCIÓN

Este módulo genera automáticamente accessors/mutators para tu clase.

La mayoría de las veces, escribir accessors es un ejercicio de copiar y pegar. Normalmente terminas con una serie de métodos como este:

  sub name {
      my $self = shift;
      if(@_) {
          $self->{name} = $_[0];
      }
      return $self->{name};
  }
  sub salary {
      my $self = shift;
      if(@_) {
          $self->{salary} = $_[0];
      }
      return $self->{salary};
  }
# etc...

Uno por cada pieza de datos en tu objeto. Aunque algunos serán únicos, haciendo comprobaciones de valores y trucos de almacenamiento especiales, la mayoría serán simplemente ejercicios de repetición. No solo es un Mal Estilo tener un montón de código repetitivo, sino que tampoco es perezoso, que es la verdadera tragedia.

Si haces que tu módulo sea una subclase de Class::Accessor y declaras tus campos de accessor con mk_accessors() entonces te encontrarás con un conjunto de accessors generados automáticamente que incluso ¡pueden ser personalizados!

La configuración básica es muy simple:

package Foo;
use base qw(Class::Accessor);
Foo->mk_accessors( qw(far bar car) );

Listo. Foo ahora tiene simples far(), bar() y car() accessors definidos.

Alternativamente, si quieres seguir las directrices de mejores prácticas de Damian, puedes usar:

package Foo;
use base qw(Class::Accessor);
Foo->follow_best_practice;
Foo->mk_accessors( qw(far bar car) );

Nota: debes llamar a "follow_best_practice" antes de llamar a "mk_accessors".

Similar a Moose

Por demanda popular ahora tenemos una interfaz simple similar a Moose. ¡Ahora puedes hacer:

package Foo;
use Class::Accessor "antlers";
has far => ( is => "rw" );
has bar => ( is => "rw" );
has car => ( is => "rw" );

Actualmente solo se soporta el atributo "is" .

CONSTRUCTOR

Class::Accessor proporciona un constructor básico, "new". Genera un objeto basado en hash y puede ser llamado como método de clase o como método de objeto.

new

my $obj = Foo->new;
my $obj = $other_obj->new;
my $obj = Foo->new(\%fields);
my $obj = $other_obj->new(\%fields);

Toma un hash opcional %fields que es usado para inicializar el objeto (útil si usas accessors de solo lectura). Los campos del hash corresponden a los nombres de tus accessors, así que...

package Foo;
use base qw(Class::Accessor);
Foo->mk_accessors('foo');
my $obj = Foo->new({ foo => 42 });
print $obj->foo;    # 42

sin embargo %fields puede contener cualquier cosa, new() los meterá todos en tu objeto.

CREANDO ACCESSORS

follow_best_practice

En el libro Perl Best Practices de Damian, él recomienda métodos separados de get y set con los prefijos set_ y get_ para hacer explícito lo que pretendes hacer. Si quieres crear esos métodos de accessor en lugar de los predeterminados, llama a:

__PACKAGE__->follow_best_practice

antes de que llames a cualquiera de los métodos de creación de accessors.

accessor_name_for / mutator_name_for

Puede que tengas tus propias ideas locas para los nombres de los accessors, así que puedes hacerlas realidad sobreescribiendo "accessor_name_for" y "mutator_name_for" en tu subclase. (Copié esa idea de Class::DBI.)

mk_accessors

__PACKAGE__->mk_accessors(@fields);

Esto crea métodos accessor/mutator para cada campo nombrado dado en @fields. Para cada campo en @fields generará dos accessors. Uno llamado "field()" y el otro llamado "_field_accessor()". Por ejemplo:

# Genera foo(), _foo_accessor(), bar() y _bar_accessor().
__PACKAGE__->mk_accessors(qw(foo bar));

Ver "Overriding autogenerated accessors" en CAVEATS AND TRICKS para más detalles.

mk_ro_accessors

__PACKAGE__->mk_ro_accessors(@read_only_fields);

Igual que mk_accessors() excepto que generará accessors de solo lectura (es decir, accessors verdaderos). Si intentas establecer un valor con estos accessors lanzará una excepción. Solo usa get() y no set().

package Foo;
use base qw(Class::Accessor);
Foo->mk_ro_accessors(qw(foo bar));
# ¡Asumamos que tenemos un objeto $foo de la clase Foo...
print $foo->foo;  # ok, imprime lo que sea el valor de $foo->{foo}
$foo->foo(42);    # ¡BOOM!  Tú, travieso.

mk_wo_accessors

__PACKAGE__->mk_wo_accessors(@write_only_fields);

Igual que mk_accessors() excepto que generará accessors de solo escritura (es decir, mutators). Si intentas leer un valor con estos accessors lanzará una excepción. Solo usa set() y no get().

NOTA No estoy del todo seguro de por qué esto es útil, pero estoy seguro de que alguien lo necesitará. Si has encontrado un uso, házmelo saber. Ahora mismo está aquí por ortogonalidad y porque es fácil de implementar.

package Foo;
use base qw(Class::Accessor);
Foo->mk_wo_accessors(qw(foo bar));
# ¡Asumamos que tenemos un objeto $foo de la clase Foo...
$foo->foo(42);      # OK.  Establece $self->{foo} = 42
print $foo->foo;    # ¡BOOM!  No se puede leer desde este accessor.

¡Moose!

Si prefieres una interfaz similar a Moose para crear accessors, puedes usar "has" importando este módulo así:

use Class::Accessor "antlers";

o

use Class::Accessor "moose-like";

Luego puedes declarar accessors así:

has alpha => ( is => "rw", isa => "Str" );
has beta  => ( is => "ro", isa => "Str" );
has gamma => ( is => "wo", isa => "Str" );

Actualmente solo se soporta el atributo "is" . Y nuestro "is" también soporta el valor "wo" para hacer un accessor de solo escritura.

Si estás usando la interfaz similar a Moose entonces deberías usar "extends" en lugar de modificar tu @ISA directamente. Básicamente, reemplaza

@ISA = qw/Foo Bar/;

con

extends(qw/Foo Bar/);

DETALLES

Un accessor generado por Class::Accessor se parece a esto:

# Tu foo puede variar.
sub foo {
    my($self) = shift;
    if(@_) {    # set
        return $self->set('foo', @_);
    }
    else {
        return $self->get('foo');
    }
}

Muy simple. Lo único que hace es determinar si quieres establecer un valor o obtener un valor y llama al método apropiado. Class::Accessor proporciona por defecto get() y set() métodos que tu clase puede sobreescribir. Se detallan más adelante.

Modificando el comportamiento del accessor

En lugar de modificar realmente el accessor, es mucho más sensato simplemente sobreescribir los dos métodos clave que el accessor llama. Es decir set() y get().

Si -realmente- quieres, puedes sobreescribir make_accessor().

set

$obj->set($key, $value);
$obj->set($key, @values);

set() define cómo generalmente uno almacena datos en el objeto.

sobreescribe este método para cambiar cómo se almacenan los datos por tus accessors.

get

$value  = $obj->get($key);
@values = $obj->get(@keys);

get() define cómo se recuperan los datos de tus objetos.

sobreescribe este método para cambiar cómo se recuperan.

make_accessor

$accessor = __PACKAGE__->make_accessor($field);

Genera una referencia a subrutina que actúa como un accessor para el campo dado $field. Llama a get() y set().

Si deseas cambiar el comportamiento de tus accessors, intenta sobreescribir get() y set() antes de empezar a manipular make_accessor().

make_ro_accessor

$read_only_accessor = __PACKAGE__->make_ro_accessor($field);

Genera una referencia a subrutina que actúa como un accessor de solo lectura para el campo dado $field. Solo llama a get().

Sobreescribe get() para cambiar el comportamiento de tus accessors.

make_wo_accessor

$write_only_accessor = __PACKAGE__->make_wo_accessor($field);

Genera una referencia a subrutina que actúa como un accessor de solo escritura (mutador) para el campo dado $field. Solo llama a set().

Sobreescribe set() para cambiar el comportamiento de tus accessors.

EXCEPCIONES

Si algo sale mal, Class::Accessor emitirá una advertencia o morirá llamando a Carp::carp o Carp::croak. Si no te gusta esto, puedes sobreescribir _carp() y _croak() en tu subclase y hacer lo que quieras.

EFICIENCIA

Class::Accessor no emplea un cargador automático (autoloader), por lo que es mucho más rápido de lo que crees. Sus métodos generados no tienen ninguna penalización especial sobre los que escribirías tú mismo.

Class::Accessor::Fast es más rápido que los métodos escritos por un programador promedio (donde "promedio" se basa en el código de ejemplo de Schwern).

Class::Accessor es más lento que el promedio, pero más flexible.

Class::Accessor::Faster es incluso más rápido que Class::Accessor::Fast. Usa un array internamente, no un hash. Esta podría ser una característica buena o mala dependiendo de tu punto de vista.

El acceso directo a hash es, por supuesto, mucho más rápido que todos estos, pero no proporciona encapsulamiento.

Por supuesto, no es tan simple como decir "Class::Accessor es más lento que el promedio". Estos son benchmarks para un accessor simple. Si tus accessors hacen algún tipo de trabajo complicado (como comunicarse con una base de datos o escribir en un archivo) el tiempo dedicado a hacer ese trabajo ahogará rápidamente el tiempo dedicado solo a llamar al accessor. En ese caso, Class::Accessor y los que escribas tendrán aproximadamente la misma velocidad.

EJEMPLOS

Aquí hay un ejemplo de cómo generar un accessor para cada campo público de tu clase.

package Altoids;
use base qw(Class::Accessor Class::Fields);
use fields qw(curiously strong mints);
Altoids->mk_accessors( Altoids->show_fields('Public') );
sub new {
    my $proto = shift;
    my $class = ref $proto || $proto;
    return fields::new($class);
}
my Altoids $tin = Altoids->new;
$tin->curiously('Curiouser and curiouser');
print $tin->{curiously};    # prints 'Curiouser and curiouser'
# Subclassing works, too.
package Mint::Snuff;
use base qw(Altoids);
my Mint::Snuff $pouch = Mint::Snuff->new;
$pouch->strong('Blow your head off!');
print $pouch->{strong};     # prints 'Blow your head off!'

Aquí hay un ejemplo sencillo de cómo alterar el comportamiento de tus accessors.

package Foo;
use base qw(Class::Accessor);
Foo->mk_accessors(qw(this that up down));
sub get {
    my $self = shift;
    # Note every time someone gets some data.
    print STDERR "Getting @_\n";
    $self->SUPER::get(@_);
}
sub set {
    my ($self, $key) = splice(@_, 0, 2);
    # Note every time someone sets some data.
    print STDERR "Setting $key to @_\n";
    $self->SUPER::set($key, @_);
}

ADVERTENCIAS Y TRUCOS

Class::Accessor tiene que hacer algo de magia interna para hacer su trabajo rápida y eficientemente. Debido a esto, hay algunos trucos y trampas que uno debe conocer.

Oye, nada es perfecto.

No hagas un campo llamado DESTROY

Esto es malo. Dado que DESTROY es un método mágico, sería malo para nosotros definir un accessor usando ese nombre. Class::Accessor emitirá una advertencia si intentas usarlo con un campo llamado "DESTROY".

Sobreescribiendo accessors autogenerados

Puede que quieras sobreescribir el accessor autogenerado con el tuyo, pero hacer que tu accessor personalizado llame al predeterminado. Por ejemplo, tal vez quieras tener un accessor que verifique su entrada. Normalmente, uno esperaría que esto funcionara:

package Foo;
use base qw(Class::Accessor);
Foo->mk_accessors(qw(email this that whatever));
# Only accept addresses which look valid.
sub email {
    my($self) = shift;
    my($email) = @_;
    if( @_ ) {  # Setting
        require Email::Valid;
        unless( Email::Valid->address($email) ) {
            carp("$email doesn't look like a valid address.");
            return;
        }
    }
    return $self->SUPER::email(@_);
}

Hay un problema sutil en el último ejemplo, y está en esta línea:

return $self->SUPER::email(@_);

Si miramos cómo se definió Foo, llamó a mk_accessors() que metió email() directamente en el espacio de nombres de Foo. ¡No *existe* SUPER::email() al que delegar! Dos formas de solucionarlo... la primera es hacer una clase base "pura" para Foo. Esta clase pura generará los accessors y proporcionará la superclase necesaria para que Foo la use:

package Pure::Organic::Foo;
use base qw(Class::Accessor);
Pure::Organic::Foo->mk_accessors(qw(email this that whatever));
package Foo;
use base qw(Pure::Organic::Foo);

Y ahora Foo::email() puede sobreescribir el Pure::Organic::Foo::email() generado y usarlo como SUPER::email().

Esta es probablemente la solución más obvia para todos menos para mí. En su lugar, lo primero que me hizo sentido fue que mk_accessors() definiera un alias de email(), _email_accessor(). Usando esta solución, Foo::email() se escribiría con:

return $self->_email_accessor(@_);

en lugar del esperado SUPER::email().
