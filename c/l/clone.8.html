CLONE(8) Manual de NUT CLONE(8)

NOMBRE

clone - Clona un SAI, tratando su salida como si fuera un SAI (con soporte para INSTCMD de apagado)

SINOPSIS

clone -h

clone -a NOMBRE_SAI [OPCIONES]


Nota

Esta página del manual solo documenta las características específicas del controlador clone. Para obtener información sobre el controlador principal, consulte nutupsdrv(8).

DESCRIPCIÓN

Este controlador, que se sitúa sobre el archivo de socket UNIX local (o la tubería con nombre de Windows) de otro controlador, permite a los usuarios agrupar clientes a una salida particular de un dispositivo y tratar esta salida como si fuera un SAI normal.

A diferencia del controlador clone-outlet(8), este controlador representa un dispositivo gestionable que puede utilizarse tanto para la monitorización como para el apagado de ordenadores cliente y salidas de SAI/ePDU (admite el envío de comandos instantáneos relevantes durante el tiempo de ejecución).

A diferencia de dummy-ups(8), este controlador no requiere un servidor de datos upsd en ejecución ni utiliza el protocolo NUT de red para comunicarse con el controlador "real" (que puede ser remoto en caso del modo repetidor dummy-ups).

Este controlador no crea un dispositivo virtual completamente nuevo, sino que reemplaza o extiende algunas de las lecturas originales informadas por el controlador "real" utilizando información de la salida especificada, y transmite todas las demás lecturas tal como estaban.

Los clientes remotos como upsmon pueden MONITORIZAR la entrada del dispositivo presentada por el servidor de datos con este controlador (y el controlador "real") en ejecución y publicada.

Una implementación más grande con uno o más dispositivos de menor prioridad recopilados en una salida gestionable de un SAI o ePDU probablemente vería varios controladores configurados en el sistema capaces de interactuar con el SAI y ejecutar el servidor de datos NUT upsd(8) (y probablemente alimentados por otra salida):

•un controlador "real" que se comunica con el SAI;
•un controlador clone que se comunica con el controlador "real" y emite el apagado (o ciclo de encendido/apagado) de la salida basándose en umbrales relativamente altos para la carga restante de la batería y/o el tiempo de ejecución del SAI real (o comandos instantáneos explícitos), con tales operaciones primero estableciendo los temporizadores respectivos para la salida en el controlador "real", y la bandera "FSD" entre los estados del estado del SAI virtual;
•posiblemente un controlador clone-outlet que es de solo lectura e interpreta los valores del temporizador de salida como disparadores para las banderas "FSD" o "OFF" informadas entre los estados del estado del SAI virtual.

Con este enfoque, los sistemas de menor prioridad recopilados en dicha salida ejecutarían el cliente NUT upsmon(8) para MONITORIZAR el SAI virtual presentado por el controlador clone-outlet de solo lectura y se apagarían tan pronto como se activara la bandera "FSD" (bastante pronto, basándose en los umbrales de carga y/o tiempo de ejecución configurados para ese controlador), permitiendo que los dispositivos de mayor prioridad (incluyendo probablemente el servidor NUT) disfruten de una mayor vida útil con batería.

El controlador clone responsable de los cambios de estado de la salida de la toma de corriente normalmente no se monitorizaría directamente (por ejemplo, para evitar solicitudes de apagado directo desafortunadas de esos clientes), aunque puede serlo (en lugar de clone-outlet) en redes suficientemente confiables.

ARGUMENTOS ADICIONALES

Este controlador admite las siguientes configuraciones:

port=nombre_controlador-nombre_dispositivo

Requerido. La configuración estándar del puerto del controlador NUT, aquí proporciona el nombre del archivo de socket UNIX local (o la tubería con nombre de Windows) para la conexión al controlador del dispositivo "real".

load.off=comando

Recomendado. Establece el comando en el controlador SAI "real" que se utilizará para apagar la salida. Necesita tanto load.off como load.on para poder apagar y encender la salida. De lo contrario, apagar los clientes alimentados por una salida es una vía de un solo sentido (ver IMPORTANTE).

load.on=comando

Recomendado. Establece el comando en el controlador SAI "real" que se utilizará para encender la salida. Necesita tanto load.off como load.on para poder apagar y encender la salida. De lo contrario, apagar los clientes alimentados por una salida es una vía de un solo sentido (ver IMPORTANTE).

load.status=valor

Recomendado. Establece la variable en el controlador SAI "real" que se utilizará para indicar el estado de la salida (es decir, encendida/apagada). Si no se especifica, el controlador clone intentará hacer un seguimiento del estado de la salida, pero esto es menos confiable.

offdelay=num

Establece el temporizador (en segundos) antes de que la salida se apague después de que se cumpla la condición de apagado (OB LB) para esta salida o se emita un comando de apagado. Por defecto son 120 segundos.

ondelay=num

Establece el temporizador (en segundos) para que la salida se encienda en caso de que la energía regrese después de que la salida se haya apagado. Por defecto son 30 segundos.

mincharge=valor

Establece el nivel de carga restante de la batería cuando el SAI clone cambia a LB (porcentaje).

minruntime=valor

Establece el tiempo de ejecución restante de la batería cuando el SAI clone cambia a LB (segundos).

IMPLEMENTACIÓN

La especificación del puerto en el ups.conf(5) debe hacer referencia al socket del controlador local (o a la tubería con nombre de Windows) que utiliza el controlador del SAI "real". Por ejemplo:

  [realups]
     driver = usbhid-ups
     port = auto
  [clone-outlet-1]
     driver = clone
     port = usbhid-ups-realups
     load.on = outlet.1.load.on
     load.off = outlet.1.load.off
     load.status = outlet.1.status
     desc = "Salida 1 del SAI Real"
     [...]

Este controlador admite comandos instantáneos para iniciar un apagado forzado para upsmon o clientes similares que MONITORIZAN este dispositivo SAI virtual, si el estado de la salida está actualmente *encendido* y aún no se ha iniciado ningún otro apagado (estableciendo el temporizador de apagado del SAI virtual a offdelay y emitiendo un FSD a través de ups.status):

•shutdown.return — volver a encender la salida después de ondelay;
•shutdown.stayoff — mantener la salida *apagada*.

Tales comandos se propagan al controlador "real" utilizando el protocolo de socket NUT (usando nombres de comando especificados en las opciones de configuración del controlador load.off y load.on), si los temporizadores de apagado o inicio están establecidos en ese momento, o si el dispositivo "real" no está "en línea" y su carga de batería o tiempo de ejecución conocidos están por debajo de los umbrales "bajos" configurados.

El estado de la salida se determina utilizando el nombre especificado por la opción del controlador load.status si está establecido, o simplemente se asume por la última operación de apagado/inicio completada (usando un número de salida desconocido).

El controlador no admite una operación de apagado de dispositivo NUT común como tal (clone -k simplemente imprime un error y se retira).

Este controlador también admite el establecimiento de ciertas variables NUT en tiempo de ejecución:

•battery.charge.low — consulte mincharge en las opciones del controlador;
•battery.runtime.low — consulte minruntime en las opciones del controlador.

En comparación con las lecturas del controlador "real", este controlador también agrega (o sobrescribe) los siguientes puntos de datos: ups.delay.shutdown, ups.delay.start, ups.timer.shutdown y ups.timer.start. Hace un seguimiento de los valores de battery.charge y battery.runtime del controlador "real" (lecturas actuales) para decidir el apagado automático de la salida más adelante.

IMPORTANTE

A diferencia de un SAI real, no debe configurar un modo primario de upsmon para este controlador. Cuando un primario de upsmon(8) ve las banderas OB LB y le dice al servidor de datos upsd(8) que está bien iniciar la secuencia de apagado, el servidor fijará el estado FSD, y no será posible reiniciar los sistemas conectados sin reiniciar el servidor upsd.

AS

El UPS clon seguirá el estado del controlador del UPS real. Solo puede hacer que el UPS clon se apague antes que el controlador del UPS real, no después. Si el controlador del UPS real inicia un apagado, el controlador del UPS clon seguirá

inmediatamente.

Tenga en cuenta que los comandos para apagar/reiniciar una toma en los controladores del UPS real no se ven afectados, por lo que si le indica al controlador del UPS real que apague la toma del controlador del UPS clon, sus clientes perderán la alimentación sin previo

aviso.

Si utiliza marcos de gestión de servicios como systemd o SMF para gestionar las dependencias entre instancias de controladores y

otras unidades, entonces es posible que deba configurar dependencias especiales (por ejemplo, con archivos de fragmentos "d
rop-in" de systemd) para encolar sus controladores clon para que se inicien después de los controladores del dispositivo "real".
