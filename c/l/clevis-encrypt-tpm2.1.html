Paquete: clevis

CLEVIS-ENCRYPT-TPM(1)   CLEVIS-ENCRYPT-TPM(1)

NOMBRE

clevis-encrypt-tpm2 - Cifra usando un chip TPM2.0 con política de vinculación

SINOPSIS

clevis encrypt tpm2 CONFIG < PT > JWE

DESCRIPCIÓN

El comando clevis encrypt tpm2 cifra datos usando un chip Trusted Platform Module 2.0 (TPM2). Su único argumento es el objeto de configuración JSON.

Al usar el pin tpm2, creamos una clave nueva, criptográficamente fuerte y aleatoria. Esta clave se cifra utilizando el chip TPM2. Luego, en el momento del descifrado, la clave se descifra de nuevo utilizando el chip TPM2.

$ clevis encrypt tpm2 '{}' < PT > JWE

El pin tiene valores predeterminados razonables para su configuración, pero se pueden elegir diferentes algoritmos de jerarquía, hash y clave si los predeterminados no son adecuados:

$ clevis encrypt tpm2 '{"hash":"sha1","key":"rsa"}' < PT > JWE

Para descifrar los datos, simplemente proporcione el texto cifrado (JWE):

$ clevis decrypt < JWE > PT

Tenga en cuenta que, al igual que otros pines, no se utiliza configuración para el descifrado, esto se debe a que clevis almacena las claves pública y privada para desbloquear el objeto cifrado con TPM2 en el JWE, lo que permite a clevis obtener esa información de allí.

El pin también admite el sellado de datos a un estado de registros de configuración de plataforma (PCR). De esta manera, los datos solo se pueden desbloquear si los valores hash de los PCR coinciden con la política utilizada al sellar.

Por ejemplo, para sellar los datos al PCR con los índices 0 y 1 para el banco SHA1:

$ clevis encrypt tpm2 '{"pcr_bank":"sha1","pcr_ids":"0,1"}' < PT > JWE

Los valores de resumen de PCR se obtienen de los valores hash actuales para los PCR, pero también se puede proporcionar un resumen si los datos deben sellarse con valores diferentes a los actuales, pasando el hash binario codificado en base64:

$ clevis encrypt tpm2 '{"pcr_ids":"0","pcr_digest":"xy7J5svCtqlfM03d1lE5gdoA8MI"}' < PT > JWE

MODELO DE AMENAZA

El modelo de seguridad de Clevis se basa en el hecho de que un atacante no podrá acceder tanto a los datos cifrados como a la clave de descifrado.

Para la mayoría de los pines de Clevis, la clave de descifrado no se almacena localmente, por lo que la política de descifrado solo se satisface si la clave de descifrado es accesible de forma remota. Podría almacenarse, por ejemplo, en un servidor remoto o en un dispositivo de autenticación hardware que deba conectarse a la máquina.

El pin tpm2 es diferente en este aspecto, ya que una clave es envuelta por un chip TPM2 que está siempre presente en la máquina. Esto no significa que no haya casos de uso para este pin, pero es importante entender el hecho de que un atacante que tiene acceso tanto a los datos cifrados como al chip TPM2 local podrá descifrar los datos.

CONFIGURACIÓN

Este comando utiliza las siguientes propiedades de configuración:

•hash (cadena) : Algoritmo hash utilizado en el cálculo del nombre del objeto (predeterminado: sha256) 
Debe ser uno de los siguientes:
•sha1
•sha256
•sha384
•sha512
•sm3_256
•key (cadena) : Tipo de algoritmo para la clave generada (predeterminado: ecc) 
Debe ser uno de los siguientes:
•rsa
•keyedhash
•ecc
•symcipher
•pcr_bank (cadena) : Banco de algoritmos PCR a utilizar para la política (predeterminado: sha1) 
Debe ser uno de los siguientes:
•sha1
•sha256
•pcr_ids (cadena) : Lista separada por comas de los PCR utilizados para la política. Si no está presente, no se utiliza ninguna política.
•pcr_digest (cadena) : Resúmenes de hash binario de PCR codificados en base64. Si no están presentes, los valores de hash se obtienen.
