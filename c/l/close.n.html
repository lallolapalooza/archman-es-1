close(n)

Paquete: tcl

Licencias: TCL

close(n) Comandos integrados de Tcl close(n)

NOMBRE

close - Cierra un canal abierto

SINOPSIS

close channelId ?r(ead)|w(rite)?

DESCRIPCIÓN

Cierra o medio-cierra el canal dado por channelId.

ChannelId debe ser un identificador de un canal abierto, como un canal estándar de Tcl (stdin, stdout o stderr), el valor de retorno de una invocación de open o socket, o el resultado de un comando de creación de canal proporcionado por una extensión de Tcl.

La forma de un solo argumento es un simple "cierre completo": toda la salida en búfer se vacía al dispositivo de salida del canal, cualquier entrada en búfer se descarta, el archivo o dispositivo subyacente se cierra y channelId queda inutilizable.

Si el canal está bloqueado, el comando no regresa hasta que se vacía toda la salida. Si el canal no está bloqueado y hay salida sin vaciar, el canal permanece abierto y el comando regresa inmediatamente; la salida se vaciará en segundo plano y el canal se cerrará cuando se complete todo el vaciado.

Si channelId es un canal bloqueado para una tubería de comandos, entonces close espera a que los procesos hijos completen.

Si el canal es compartido entre intérpretes, entonces close deja channelId inutilizable en el intérprete invocador pero no tiene ningún otro efecto hasta que todos los intérpretes que comparten el canal lo hayan cerrado. Cuando el último intérprete en el que está registrado el canal invoca close, ocurren las acciones de limpieza descritas anteriormente. Vea el comando interp para una descripción del uso compartido de canales.

Los canales se cierran automáticamente cuando se destruye un intérprete y cuando el proceso finaliza. A partir de la versión 8.6 (TIP#398), los canales no bloqueantes ya no se cambian a modo bloqueante al salir; esto garantiza una salida oportuna incluso cuando el par o un canal de comunicación está bloqueado. Para asegurar el vaciado adecuado de canales no bloqueantes bloqueados al salir, ahora se debe (a) cambiarlos activamente de nuevo a bloqueantes o (b) usar la variable de entorno TCL_FLUSH_NONBLOCKING_ON_EXIT, que cuando se establece y no es igual a "0" restaura el comportamiento anterior.

El comando devuelve una cadena vacía y puede generar un error si ocurre un error al vaciar la salida. Si un comando en una tubería de comandos creada con open devuelve un error, close genera un error (similar al comando exec).

La forma de dos argumentos es un "medio-cierre": dado un canal bidireccional como un socket o una tubería de comandos y una dirección (posiblemente abreviada), cierra solo la subcorriente en esa dirección. Esto significa un shutdown() en un socket y un close() de un extremo de una tubería para una tubería de comandos. Luego, la estructura de datos del canal a nivel de Tcl se mantiene o se libera dependiendo de si la otra dirección todavía está abierta.

Un cierre de un solo argumento en un canal bidireccional ya medio-cerrado se define como que simplemente "termina el trabajo". Un medio-cierre en un extremo ya cerrado, o en un canal unidireccional del lado incorrecto, genera un error.

En el caso de una tubería de comandos, la tarea de recoger al hijo recae en el último cierre o medio-cierre, que por lo tanto puede informar un error de salida anormal.

Actualmente, solo los sockets y las tuberías de comandos admiten el medio-cierre. Una extensión futura permitirá que los canales reflejados y apilados lo hagan.

EJEMPLO

Esto ilustra cómo puedes usar Tcl para asegurarte de que los archivos se cierren incluso cuando ocurren errores, combinando catch, close y return:

proc withOpenFile {filename channelVar script} {
    upvar 1 $channelVar chan
    set chan [open $filename]
    catch {
        uplevel 1 $script
    } result options
    close $chan
    return -options $options $result
}
