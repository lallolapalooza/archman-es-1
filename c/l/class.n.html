variable varName ?init? ?config?
Define una variable específica del objeto llamada varName. Todas las variables específicas del objeto están automáticamente disponibles en los métodos de clase. No necesitan declararse con nada como el comando global .

Si se especifica la cadena opcional init , se utiliza como el valor inicial de la variable cuando se crea un nuevo objeto. La inicialización fuerza a la variable a ser un valor escalar simple; las variables no inicializadas, por otro lado, pueden establecerse dentro del constructor y usarse como matrices.

El script opcional config solo está permitido para variables públicas. Si se especifica, este fragmento de código se ejecuta cada vez que una variable pública es modificada por el método incorporado "configure". El script config también puede especificarse fuera de la definición de la clase usando el comando configbody .

common varName ?init?
Declara una variable común llamada varName. Las variables comunes residen en el espacio de nombres de la clase y son compartidas por todos los objetos que pertenecen a la clase. Son exactamente como las variables globales, excepto que no necesitan declararse con el comando habitual global . Están automáticamente visibles en todos los métodos y procedimientos de la clase.

Si se especifica la cadena opcional init , se utiliza como el valor inicial de la variable. La inicialización fuerza a la variable a ser un valor escalar simple; las variables no inicializadas, por otro lado, pueden establecerse con los comandos posteriores set y array y usarse como matrices.

Una vez que se ha definido un miembro de datos común, puede establecerse usando los comandos set y array dentro de la definición de la clase. Esto permite que los miembros de datos comunes se inicialicen como matrices. Por ejemplo:

itcl::class Foo {
    common boolean
    set boolean(true) 1
    set boolean(false) 0
}

Tenga en cuenta que si los miembros de datos comunes se inicializan dentro del constructor, se inicializan una y otra vez cada vez que se crean nuevos objetos.

public command ?arg arg ...?
protected command ?arg arg ...?
private command ?arg arg ...?
Estos comandos se utilizan para establecer el nivel de protección de los miembros de la clase que se crean cuando se evalúa command . El command es usualmente method, proc, variable ocommon, y los argrestantes completan la definición del miembro. Sin embargo, command también puede ser un script que contenga muchas definiciones de miembros diferentes, y el nivel de protección se aplicará a todos los miembros que se creen.

USO DE LA CLASE

Una vez que se ha definido una clase, el nombre de la clase puede usarse como un comando para crear nuevos objetos que pertenezcan a la clase.

className objName ?args...?
Crea un nuevo objeto en la clase className con el nombre objName. Los argumentos restantes se pasan al constructor de la clase más específica. Este a su vez pasa argumentos a los constructores de las clases base antes de invocar su propio cuerpo de comandos. Si la construcción es exitosa, se crea un comando llamado objName en el contexto del espacio de nombres actual, y objName se devuelve como el resultado de esta operación. Si se encuentra un error durante la construcción, los destructores se invocan automáticamente para liberar cualquier recurso que haya sido asignado, el objeto se elimina y se devuelve un error.

Si objName contiene la cadena "#auto", esa cadena se reemplaza con un nombre generado automáticamente. Los nombres tienen la forma className<number>, donde la parte className se modifica para comenzar con una letra minúscula. En la clase "Toaster", por ejemplo, la especificación "#auto" produciría nombres como toaster0, toaster1, etc. Tenga en cuenta que "#auto" también puede estar incrustado dentro de un nombre de objeto:

fileselectiondialog .foo.bar.#auto -background red

Esto generaría un objeto llamado ".foo.bar.fileselectiondialog0".

USO DEL OBJETO

Una vez que se ha creado un objeto, el nombre del objeto puede usarse como un comando para invocar métodos que operan sobre el objeto.

objName method ?args...?
Invoca un método llamado method en un objeto llamado objName. Los argumentos restantes se pasan a la lista de argumentos del método. El nombre del método puede ser "constructor", "destructor", cualquier nombre de método que aparezca en la definición de la clase, o cualquiera de los siguientes métodos incorporados.

MÉTODOS INCORPORADOS

objName cget option
Proporciona acceso a las variables públicas como opciones de configuración. Esto imita el comportamiento de la operación habitual "cget" para widgets de Tk. El argumento option es una cadena de la forma "-varName", y este método devuelve el valor actual de la variable pública varName.
objName configure ?option? ?value option value ...?
Proporciona acceso a las variables públicas como opciones de configuración. Esto imita el comportamiento de la operación habitual "configure" para widgets de Tk. Sin argumentos, este método devuelve una lista de listas que describen todas las variables públicas. Cada lista tiene tres elementos: el nombre de la variable, su valor inicial y su valor actual.

Si se especifica una única option de la forma "-varName", entonces este método devuelve la información para esa única variable.

De lo contrario, los argumentos se tratan como pares de option/value asignando nuevos valores a las variables públicas. A cada variable se le asigna su nuevo valor, y si tiene algún código "config" asociado con ella, se ejecuta en el contexto de la clase donde fue definida. Si el código "config" genera un error, la variable se restablece a su valor anterior, y el método configure devuelve un error.

objName isa className
Devuelve un valor distinto de cero si el className dado se puede encontrar en la herencia del objeto, y cero en caso contrario.
objName info option ?args...?
Devuelve información relacionada con un objeto particular llamado objName, o con su definición de clase. El parámetro option incluye las siguientes cosas, así como las opciones reconocidas por el comando habitual de Tcl "info":
objName info class
Devuelve el nombre de la clase más específica para el objeto objName.
objName info inherit
Devuelve la lista de clases base tal como fueron definidas en el comando "inherit", o una cadena vacía si esta clase no tiene clases base.
objName info heritage
Devuelve el nombre de la clase actual y la lista completa de clases base en el orden en que se recorren para la búsqueda de miembros y la destrucción de objetos.
objName info function ?cmdName? ?-protection? ?-type? ?-name? ?-args? ?-body?
Sin argumentos, este comando devuelve una lista de todos los métodos y procedimientos de la clase. Si se especifica cmdName , devuelve información para un método o procedimiento específico. Si no se especifican banderas, este comando devuelve una lista con los siguientes elementos: el nivel de protección, el tipo (método/procedimiento), el nombre calificado, la lista de argumentos y el cuerpo. Las banderas pueden usarse para solicitar elementos específicos de esta lista.
objName info variable ?varName? ?-protection? ?-type? ?-name? ?-init? ?-value? ?-config? ?-scope?
Sin argumentos, este comando devuelve una lista de todas las variables específicas del objeto y miembros de datos comunes. Si se especifica varName , devuelve información para un miembro de datos específico. Las banderas pueden especificarse con varName en un orden arbitrario. El resultado es una lista de la información específica en exactamente el mismo orden en que se especifican las banderas.

Si no se dan banderas, este comando devuelve una lista como si se hubieran especificado las siguientes banderas:

-protection -type -name -init -value ?-config?

El resultado -config solo está presente si varName es una variable pública. Contiene el código que se ejecuta en la inicialización de varName. La bandera -scope da el contexto del espacio de nombres de varName. Con esto, la variable puede ser accedida desde fuera del objeto como cualquier otra variable. Es similar al resultado del comando itcl::scope .

ENCADENAMIENTO DE MÉTODOS/PROCEDIMIENTOS

A veces una clase base tiene un método o procedimiento que es redefinido con el mismo nombre en una clase derivada. Esta es una forma de hacer que la clase derivada maneje las mismas operaciones que la clase base, pero con su propio comportamiento especializado. Por ejemplo, supongamos que tenemos una clase Toaster que se ve así:

itcl::class Toaster {
    variable crumbs 0
    method toast {nslices} {
        if {$crumbs > 50} {
            error "== FIRE! FIRE! =="
        }
        set crumbs [expr {$crumbs+4*$nslices}]
    }
    method clean {} {
        set crumbs 0
    }
}

Podríamos crear otra clase como SmartToaster que redefine el método "toast"

CHAINING METHODS/PROCS

If we want to access the base class method, we can qualify it with the base class name, to avoid ambiguity:

itcl::class SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [Toaster::toast $nslices]
    }
}

Instead of hard-coding the base class name, we can use the "chain" command like this:

itcl::class SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [chain $nslices]
    }
}

The chain command searches through the class hierarchy for a slightly more generic (base class) implementation of a method or proc, and invokes it with the specified arguments. It starts at the current class context and searches through base classes in the order that they are reported by the "info heritage" command. If another implementation is not found, this command does nothing and returns the null string.

AUTO-LOADING

Class definitions need not be loaded explicitly; they can be loaded as needed by the usual Tcl auto-loading facility. Each directory containing class definition files should have an accompanying "tclIndex" file. Each line in this file identifies a Tcl procedure or [incr Tcl] class definition and the file where the definition can be found.

For example, suppose a directory contains the definitions for classes "Toaster" and "SmartToaster". Then the "tclIndex" file for this directory would look like:

# Tcl autoload index file, version 2.0 for [incr Tcl]
# This file is generated by the "auto_mkindex" command
# and sourced to set up indexing information for one or
# more commands.  Typically each line is a command that
# sets an element in the auto_index array, where the
# element name is the name of a command and the value is
# a script that loads the command.
set auto_index(::Toaster) "source $dir/Toaster.itcl"
set auto_index(::SmartToaster) "source $dir/SmartToaster.itcl"

The auto_mkindex command is used to automatically generate "tclIndex" files.

The auto-loader must be made aware of this directory by appending the directory name to the "auto_path" variable. When this is in place, classes will be auto-loaded as needed when used in an application.

C PROCEDURES

C procedures can be integrated into an [incr Tcl] class definition to implement methods, procs, and the "config" code for public variables. Any body that starts with "@" is treated as the symbolic name for a C procedure.

Symbolic names are established by registering procedures via Itcl_RegisterC(). This is usually done in the Tcl_AppInit() procedure, which is automatically called when the interpreter starts up. In the following example, the procedure My_FooCmd() is registered with the symbolic name "foo". This procedure can be referenced in the body command as "@foo".

int
Tcl_AppInit(interp)
    Tcl_Interp *interp;     /* Interpreter for application. */
{
    if (Itcl_Init(interp) == TCL_ERROR) {
        return TCL_ERROR;
    }
    if (Itcl_RegisterC(interp, "foo", My_FooCmd) != TCL_OK) {
        return TCL_ERROR;
    }
}

C procedures are implemented just like ordinary Tcl commands. See the CrtCommand man page for details. Within the procedure, class data members can be accessed like ordinary variables using Tcl_SetVar(), Tcl_GetVar(), Tcl_TraceVar(), etc. Class methods and procs can be executed like ordinary commands using Tcl_Eval(). [incr Tcl] makes this possible by automatically setting up the context before executing the C procedure.

This scheme provides a natural migration path for code development. Classes can be developed quickly using Tcl code to implement the bodies. An entire application can be built and tested. When necessary, individual bodies can be implemented with C code to improve performance.
