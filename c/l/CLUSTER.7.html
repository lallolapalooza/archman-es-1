NOMBRE

CLUSTER - agrupa una tabla según un índice

SINOPSIS

CLUSTER [ ( opción [, ...] ) ] [ nombre_tabla [ USING nombre_índice ] ]
donde opción puede ser una de:
    VERBOSE [ booleano ]

DESCRIPCIÓN

CLUSTER le indica a PostgreSQL que agrupe la tabla especificada por nombre_tabla basándose en el índice especificado por nombre_índice. El índice debe haber sido definido previamente en nombre_tabla.

Cuando una tabla se agrupa, se reordena físicamente según la información del índice. El agrupamiento es una operación única: cuando la tabla se actualiza posteriormente, los cambios no se agrupan. Es decir, no se intenta almacenar las filas nuevas o actualizadas según su orden de índice. (Si se desea, se puede reagrupar periódicamente ejecutando el comando de nuevo. Además, establecer el parámetro de almacenamiento fillfactor de la tabla en menos del 100% puede ayudar a conservar el orden de agrupamiento durante las actualizaciones, ya que las filas actualizadas se mantienen en la misma página si hay suficiente espacio disponible en ella.)

Cuando una tabla se agrupa, PostgreSQL recuerda con qué índice se agrupó. La forma CLUSTER nombre_tabla reagrupa la tabla usando el mismo índice que antes. También puede usar las formas CLUSTER o SET WITHOUT CLUSTER de ALTER TABLE para establecer el índice que se usará para futuras operaciones de agrupamiento, o para borrar cualquier configuración anterior.

CLUSTER sin un nombre_tabla reagrupa todas las tablas previamente agrupadas en la base de datos actual para las que el usuario que llama tiene privilegios. Esta forma de CLUSTER no puede ejecutarse dentro de un bloque de transacción.

Cuando una tabla se está agrupando, se adquiere sobre ella un bloqueo ACCESS EXCLUSIVE. Esto impide que cualquier otra operación de la base de datos (tanto lecturas como escrituras) opere sobre la tabla hasta que CLUSTER termine.

PARÁMETROS

nombre_tabla

El nombre (posiblemente calificado por esquema) de una tabla.

nombre_índice

El nombre de un índice.

VERBOSE

Imprime un informe de progreso a nivel INFO a medida que se agrupa cada tabla.

booleano

Especifica si la opción seleccionada debe activarse o desactivarse. Puede escribir TRUE, ON o 1 para habilitar la opción, y FALSE, OFF o 0 para deshabilitarla. El valor booleano también puede omitirse, en cuyo caso se asume TRUE.

NOTAS

Para agrupar una tabla, se debe tener el privilegio MAINTAIN sobre la tabla.

En los casos en que accede a filas individuales aleatoriamente dentro de una tabla, el orden real de los datos en la tabla no es importante. Sin embargo, si tiende a acceder a algunos datos más que a otros, y existe un índice que los agrupa, se beneficiará de usar CLUSTER. Si está solicitando un rango de valores indexados de una tabla, o un único valor indexado que tiene múltiples filas que coinciden, CLUSTER ayudará porque una vez que el índice identifica la página de la tabla para la primera fila que coincide, todas las demás filas que coinciden probablemente ya están en la misma página de la tabla, y así ahorra accesos al disco y acelera la consulta.

CLUSTER puede reordenar la tabla usando un escaneo de índice sobre el índice especificado, o (si el índice es un b-tree) un escaneo secuencial seguido de una ordenación. Intentará elegir el método que sea más rápido, basándose en los parámetros de coste del planificador y la información estadística disponible.

Mientras CLUSTER se está ejecutando, el search_path se cambia temporalmente a pg_catalog, pg_temp.

Cuando se usa un escaneo de índice, se crea una copia temporal de la tabla que contiene los datos de la tabla en el orden del índice. También se crean copias temporales de cada índice de la tabla. Por lo tanto, necesita espacio libre en disco al menos igual a la suma del tamaño de la tabla y los tamaños de los índices.

Cuando se usa un escaneo secuencial y una ordenación, también se crea un archivo de ordenación temporal, de modo que el requisito máximo de espacio temporal es tanto como el doble del tamaño de la tabla, más los tamaños de los índices. Este método suele ser más rápido que el método de escaneo de índice, pero si el requisito de espacio en disco es inaceptable, puede deshabilitar esta opción estableciendo temporalmente enable_sort a off.

Es recomendable establecer maintenance_work_mem en un valor razonablemente grande (pero no más que la cantidad de RAM que puede dedicar a la operación CLUSTER ) antes de agrupar.

Debido a que el planificador registra estadísticas sobre el orden de las tablas, es recomendable ejecutar ANALYZE sobre la tabla recién agrupada. De lo contrario, el planificador podría tomar malas decisiones sobre los planes de consulta.

Debido a que CLUSTER recuerda qué índices están agrupados, se pueden agrupar manualmente las tablas que se desean agrupar la primera vez, y luego configurar un script de mantenimiento periódico que ejecute CLUSTER sin ningún parámetro, de modo que las tablas deseadas se reagrupen periódicamente.

Cada backend que ejecute CLUSTER informará de su progreso en la vista pg_stat_progress_cluster. Consulte la Sección 27.4.2 para más detalles.

Agrupar una tabla particionada agrupa cada una de sus particiones usando la partición del índice particionado especificado. Al agrupar una tabla particionada, el índice no puede omitirse. CLUSTER sobre una tabla particionada no puede ejecutarse dentro de un bloque de transacción.

EJEMPLOS

Agrupar la tabla employees sobre la base de su índice employees_ind:

CLUSTER employees USING employees_ind;

Agrupar la tabla employees usando el mismo índice que se usó antes:

CLUSTER employees;

Agrupar todas las tablas de la base de datos que hayan sido agrupadas previamente:

CLUSTER;

COMPATIBILIDAD

No existe la sentencia CLUSTER en el estándar SQL.

La siguiente sintaxis se usaba antes de PostgreSQL 17 y todavía es compatible:

CLUSTER [ VERBOSE ] [ nombre_tabla [ USING nombre_índice ] ]

La siguiente sintaxis se usaba antes de PostgreSQL 8.3 y todavía es compatible:

CLUSTER nombre_índice ON nombre_tabla
