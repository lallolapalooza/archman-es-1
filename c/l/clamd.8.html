NOMBRE

clamd - un demonio antivirus

SINOPSIS

clamd [opciones]

DESCRIPCIÓN

El demonio escucha las conexiones entrantes en sockets Unix y/o TCP y escanea archivos o directorios bajo demanda. Lee la configuración desde /etc/clamav/clamd.conf.

COMANDOS

Se recomienda prefijar los comandos de clamd con la letra z (ej. zSCAN) para indicar que el comando será delimitado por un carácter NULL y que clamd continuará leyendo los datos del comando hasta que se lea un carácter NULL. El delimitador nulo asegura que el comando completo y su argumento completo serán procesados como un solo comando. Alternativamente, los comandos pueden prefijarse con la letra n (ej. nSCAN) para usar un carácter de nueva línea como delimitador. Las respuestas de clamd honrarán el terminador solicitado a su vez. Si clamd no reconoce el comando, o el comando no sigue los requisitos especificados a continuación, responderá con un mensaje de error y cerrará la conexión.

Clamd reconoce los siguientes comandos:

PING
Comprueba el estado del servidor. Debería responder con "PONG".
VERSION
Imprime las versiones del programa y las bases de datos.
RELOAD
Recarga las bases de datos de virus.
SHUTDOWN
Realiza una salida limpia.
SCAN archivo/directorio
Escanea un archivo o un directorio (recursivamente) con soporte para archivos habilitado (si no está deshabilitado en clamd.conf). Se requiere una ruta completa.
CONTSCAN archivo/directorio
Escanea un archivo o directorio (recursivamente) con soporte para archivos habilitado y no detiene el escaneo cuando se encuentra un virus.
MULTISCAN archivo/directorio
Escanea un archivo de forma estándar o escanea un directorio (recursivamente) utilizando múltiples hilos (para hacer el escaneo más rápido en máquinas SMP).
ALLMATCHSCAN archivo/directorio
ALLMATCHSCAN funciona igual que SCAN, excepto que configura un modo en el que el escaneo continúa después de encontrar una coincidencia dentro de un archivo.
INSTREAM
Es obligatorio prefijar este comando con n o z.

Escanea un flujo de datos. El flujo se envía a clamd en fragmentos, después de INSTREAM, en el mismo socket en el que se envió el comando. Esto evita la sobrecarga de establecer nuevas conexiones TCP y problemas con NAT. El formato del fragmento es: '<longitud><datos>' donde <longitud> es el tamaño de los datos siguientes en bytes expresado como un entero sin signo de 4 bytes en orden de bytes de red y <datos> son los datos reales del fragmento. La transmisión se termina enviando un fragmento de longitud cero. Nota: no exceda StreamMaxLength como se define en clamd.conf, de lo contrario, clamd responderá con INSTREAM size limit exceeded y cerrará la conexión.

FILDES
Es obligatorio terminar este comando con nueva línea, o prefijarlo con n o z.

Este comando solo funciona en sockets de dominio UNIX. Escanea un descriptor de archivo. Después de emitir un comando FILDES, se enviará un paquete posterior al estilo rfc2292/bsd4.4 (con al menos un carácter de relleno) a clamd que contendrá el descriptor de archivo a escanear dentro de los datos auxiliares. Alternativamente, el descriptor de archivo puede enviarse en el mismo paquete, incluido el carácter adicional.

STATS
Es obligatorio terminar este comando con nueva línea, o prefijarlo con n o z, se recomienda usar solo el prefijo z.

Responde con estadísticas sobre la cola de escaneo, el contenido de la cola de escaneo y el uso de memoria. El formato exacto de la respuesta está sujeto a cambios en futuras versiones.

IDSESSION, END
Es obligatorio prefijar este comando con n o z, y todos los comandos dentro de IDSESSION deben prefijarse.

Inicia/finaliza una sesión de clamd. Dentro de una sesión, se pueden enviar múltiples comandos SCAN, INSTREAM, FILDES, VERSION, STATS en el mismo socket sin abrir nuevas conexiones. Las respuestas de clamd tendrán el formato '<id>: <respuesta>' donde <id> es el número de solicitud (en ASCII, comenzando desde 1) y <respuesta> es la respuesta usual de clamd. Las líneas de respuesta tendrán el mismo delimitador que tenía el comando correspondiente. Clamd procesará los comandos de forma asíncrona y responderá tan pronto como haya terminado de procesar.

Clamd requiere que los clientes lean todas las respuestas que envía, antes de enviar más comandos para evitar bloqueos de send(). La forma recomendada de implementar un cliente que utiliza IDSESSION es con sockets no bloqueantes y un bucle select()/poll(): siempre que send() se bloquee, duerma en select/poll hasta que puedas escribir más datos o leer más respuestas. Tenga en cuenta que el uso de sockets no bloqueantes sin el bucle select/poll y alternando recv()/send() no cumple con los requisitos de clamd.

Si clamd detecta que un cliente se ha bloqueado, cerrará la conexión. Tenga en cuenta que clamd también puede cerrar una conexión IDSESSION si no sigue los requisitos del protocolo. El cliente puede usar el comando PING para mantener la conexión activa.

VERSIONCOMMANDS
Es obligatorio prefijar este comando con n o z. Se recomienda usar nVERSIONCOMMANDS.

Imprime las versiones del programa y las bases de datos, seguido de "| COMMANDS:" y una lista de comandos soportados separados por espacios. Clamd <0.95 reconocerá esto como el comando VERSION y responderá solo con su versión, sin la lista de comandos.

Este comando se puede usar como una forma fácil de comprobar la compatibilidad con IDSESSION, por ejemplo.

COMANDOS OBSOLETOS
STREAM
Escanea flujo - con este comando clamd devolverá el "PORT número" al que debes conectarte y enviar datos para escanear. (OBSOLETO, usa INSTREAM en su lugar)
COMANDOS NO SOPORTADOS
SESSION, END
Inicia/finaliza una sesión de clamd que te permitirá ejecutar múltiples comandos por sesión TCP. (usa IDSESSION en su lugar)

OPCIONES

-h, --help
Muestra la información de ayuda y sale.
-V, --version
Muestra el número de versión y sale.
-F, --foreground
Ejecuta en primer plano; no te desvincules.
--debug
Habilita el modo de depuración.
-c ARCHIVO, --config-file=ARCHIVO
Lee la configuración desde ARCHIVO.
--fail-if-cvd-older-than=dias
Devuelve un código de error distinto de cero si la base de datos de virus es más antigua que el número especificado de días.
--datadir=DIRECTORIO
Carga las firmas desde DIRECTORIO.
-p ARCHIVO, --pid=ARCHIVO
Escribe el PID del demonio en ARCHIVO.
--cvdcertsdir=DIR
Especifica un directorio que contiene la CA raíz necesaria para verificar las firmas digitales CVD desvinculadas. Si no se proporciona, clamd buscará en el directorio predeterminado.
