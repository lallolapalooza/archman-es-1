Descripción detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es avanzado y complicado. No necesita esto a menos que realmente sepa lo que está haciendo. La mayoría de las aplicaciones no necesitarán esto.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han visto limitadas a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivo de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que no es proporcionado directamente por PhysicsFS: quizás algún formato propietario que solo su aplicación necesita entender.

Internamente, todo el soporte de archivos integrado usa esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver es el código fuente de PhysicsFS mismo.

Un archivador se agrega al sistema con PHYSFS_registerArchiver(), y luego estará disponible para uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser manejado con su archivador, se le dará el control según corresponda.

Estos métodos tratan con manejadores de directorios. Usted tiene una instancia de su archivador, y este genera un manejador único y opaco para cada archivo abierto en su openArchive() método. Dado que el tiempo de vida de un Archiver (no un archivo) es generalmente todo el tiempo de vida del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el archivador mismo; la aplicación puede simplemente usar algunas variables estáticas si es necesario.

Los enlaces simbólicos siempre deben ser seguidos (excepto en stat()); PhysicsFS usará el stat() método para verificar enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de regresar. PhysicsFS pasará estos errores de vuelta a la aplicación sin modificar en la mayoría de los casos.

Seguridad de hilos: PHYSFS_Archiver las implementaciones no están garantizadas para ser seguras en hilos en sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro en hilos; como tal, su PHYSFS_Archiver puede asumir que el bloqueo es manejado por usted siempre que el PHYSFS_Io que devuelve de PHYSFS_open* no cambie ninguno de su estado de Archiver, ya que el PHYSFS_Io no será protegido tan agresivamente.

Documentación de campos

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluyendo el PHYSFS_Io original y el (opaque) mismo, si aplica. La implementación puede asumir que no será llamado si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, por lo que puede disponer de él al regresar del callback. (dirname) está en notación independiente de plataforma. Si tiene un fallo, llame a PHYSFS_SetErrorCode() con cualquier código que parezca apropiado y regrese PHYSFS_ENUM_ERROR. Si el callback regresa PHYSFS_ENUM_ERROR, por favor llame a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego regrese PHYSFS_ENUM_ERROR también. No llame al callback de nuevo en ninguna circunstancia. Si el callback regresa PHYSFS_ENUM_STOP, detenga la enumeración y regrese PHYSFS_ENUM_STOP también. No llame al callback de nuevo en ninguna circunstancia. No establezca un código de error en este caso. Los callbacks solo se supone que regresan un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene comportamiento indefinido. Mientras el callback haya regresado PHYSFS_ENUM_OK y no haya experimentado ningún error de su propio, siga enumerando hasta que termine y luego regrese PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate regresa cero o no-cero (éxito o fallo), así que tenga en cuenta que este puntero de función regresa valores diferentes.

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Esto se usa para identificar su archivo, y se regresa en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivo. Si la aplicación está intentando hacer múltiples directorios, PhysicsFS los dividirá en múltiples llamadas antes de pasarlos a su controlador. Si el archivo es de solo lectura, esta operación debería fallar. Regrese no-cero en éxito, cero en fallo. Este nombre de archivo está en notación independiente de plataforma. En caso de fallo, llame a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivo para agregar. Si el archivo no existe, debería ser creado. El offset de escritura debería ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de plataforma. Regresa NULL en fallo, y llama a PHYSFS_setErrorCode(). Regresa no-NULL en éxito. El puntero regresado será pasado como el parámetro "opaque" para llamadas posteriores de archivo.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int *claimed)

Abre un archivo proporcionado por (io). Aquí es donde se asignan recursos y se analizan datos al montar un archivo. (name) es un nombre de archivo asociado con (io), pero no necesariamente mapea a nada, mucho menos a un nombre de archivo real. Este nombre posiblemente sin significado está en notación dependiente de plataforma. (forWrite) es no-cero si esto va a ser usado para el directorio de escritura, y cero si esto va a ser usado para un elemento dela ruta de búsqueda. (claimed) debe establecerse en 1 si este es definitivamente un archivo que su implementación de archivador puede manejar, incluso si falla. Usamos esto para decidir si debemos dejar de intentar otros archivadores si usted falla al abrirlo. Por ejemplo: el archivador .zip establecerá esto en 1 para algo que tiene una firma de archivo .zip, incluso si falló porque el archivo también estaba truncado. No tiene sentido intentar otros archivadores aquí, ¡ya intentamos manejarlo con la implementación apropiada!. Devuelva NULL en caso de fallo y establezca (claimed) apropiadamente. Si ningún archivador abrió el archivo o estableció (claimed), PHYSFS_mount() reportará PHYSFS_ERR_UNSUPPORTED. De lo contrario, reportará el error del archivador que reclamó los datos a través de (claimed). Devuelva no-NULL en éxito. El puntero devuelto se pasará como el parámetro "opaque" para llamadas posteriores.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Abra un archivo en este archivo para lectura. Este nombre de archivo, (fnm), está en notación independiente de la plataforma. Falla si el archivo no existe. Devuelve NULL en caso de fallo, y llama a PHYSFS_setErrorCode(). Devuelve no-NULL en éxito. El puntero devuelto se pasará como el parámetro "opaque" para llamadas posteriores a archivos.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Abra un archivo en este archivo para escritura. Si el archivo no existe, debe ser creado. Si existe, debe ser truncado a cero bytes. El desplazamiento de escritura debe ser el inicio del archivo. Si el archivo es de solo lectura, esta operación debe fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo, y llama a PHYSFS_setErrorCode(). Devuelve no-NULL en éxito. El puntero devuelto se pasará como el parámetro "opaque" para llamadas posteriores de archivos.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Elimine un archivo o directorio en el archivo. Esta misma llamada se usa tanto para archivos como para directorios; no hay una llamada separada rmdir(). Los directorios solo deben eliminarse si están vacíos. Si el archivo es de solo lectura, esta operación debe fallar.

Devuelva distinto de cero en éxito, cero en fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llame a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtenga metadatos básicos del archivo. En éxito, complete todos los campos en (stat), usando valores predeterminados razonables para los campos que aplican a su archivo.

Devuelve distinto de cero en éxito, cero en fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llame a PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Información de compatibilidad binaria. Esto debe establecerse en cero en este momento. Las versiones futuras de esta estructura incrementarán este campo, para que sepamos qué soporta una implementación dada. Presumiblemente seguiremos soportando versiones más antiguas a medida que ofrezcamos nuevas características, aunque.
