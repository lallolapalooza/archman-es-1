NOMBRE

clevis-encrypt-sss - Cifra usando una política de Compartición de Secretos de Shamir

SINOPSIS

clevis encrypt sss CONFIG [-y] < PT > JWE

DESCRIPCIÓN

El comando clevis encrypt sss cifra usando una política de Compartición de Secretos de Shamir. Su único argumento es el objeto de configuración JSON.

La Compartición de Secretos de Shamir (SSS) proporciona una forma de mezclar pines para crear políticas sofisticadas de desbloqueo y alta disponibilidad. SSS es un esquema de umbral. Crea una clave y la divide en un número de fragmentos. Cada fragmento se cifra usando otro pin (posiblemente incluso SSS recursivamente). Además, defines el umbral t. Si al menos t fragmentos pueden ser descifrados, entonces la clave de cifrado se puede recuperar y el descifrado puede tener éxito.

Por ejemplo, creemos una configuración de alta disponibilidad usando Tang:

$ cfg='{"t":1,"pins":{"tang":[{"url":...},{"url":...}]}}'
$ clevis encrypt sss "$cfg" < PT > JWE

En esta política, declaramos que tenemos un umbral de 1, pero que hay múltiples fragmentos de clave cifrados usando diferentes servidores Tang. Dado que nuestro umbral es 1, siempre que uno de los servidores Tang esté disponible, el descifrado tendrá éxito. Como siempre, el descifrado es simplemente:

$ clevis decrypt < JWE > PT

CONFIGURACIÓN

Este comando utiliza las siguientes propiedades de configuración:

•t (entero) : Número de pines requeridos para el descifrado (REQUERIDO)
•pins (objeto) : Pines utilizados para cifrar fragmentos (REQUERIDO)

El formato de la propiedad pins es el siguiente:

{PIN:CFG,...} O {PIN:[CFG,CFG,...],...}

Cuando se usa la versión de lista del formato, múltiples pines de ese tipo recibirán fragmentos de clave.

OPCIONES

•-y : Responde automáticamente sí a todas las preguntas. Para el pin tang, omitirá la verificación de confianza del anuncio, lo que puede ser útil en despliegues automatizados: 
$ cfg='{"t":1,"pins":{"tang":[{"url":...},{"url":...}]}}'
$ clevis encrypt sss "$cfg" -y < PT > JWE

VER TAMBIÉN
