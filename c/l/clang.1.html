NOMBRE

clang - el compilador C, C++ y Objective-C de Clang

SINOPSIS

clang [opciones] nombre_archivo ...

DESCRIPCIÓN

clang es un compilador C, C++ y Objective-C que abarca preprocesamiento, análisis sintáctico, optimización, generación de código, ensamblado y enlazado. Dependiendo de la configuración del modo de alto nivel que se pase, Clang se detendrá antes de realizar un enlace completo. Si bien Clang está altamente integrado, es importante comprender las etapas de compilación para entender cómo invocarlo. Estas etapas son:

Controlador
El ejecutable de clang es en realidad un pequeño controlador que gestiona la ejecución general de otras herramientas como el compilador, el ensamblador y el enlazador. Normalmente no necesitas interactuar con el controlador, sino que lo utilizas de forma transparente para ejecutar las otras herramientas.
Preprocesamiento
Esta etapa se encarga de la tokenización del archivo fuente de entrada, la expansión de macros, la expansión de #include y el manejo de otras directivas del preprocesador. La salida de esta etapa suele ser un archivo ".i" (para C), ".ii" (para C++), ".mi" (para Objective-C) o ".mii" (para Objective-C++).
Análisis sintáctico y análisis semántico
Esta etapa analiza el archivo de entrada, traduciendo los tokens del preprocesador en un árbol de análisis. Una vez en forma de árbol de análisis, aplica análisis semántico para calcular tipos para las expresiones y determinar si el código está bien formado. Esta etapa es responsable de generar la mayoría de las advertencias del compilador, así como los errores de análisis. La salida de esta etapa es un "Árbol de Sintaxis Abstracta" (AST).
Generación y optimización de código
Esta etapa traduce un AST a código intermedio de bajo nivel (conocido como "LLVM IR") y, en última instancia, a código máquina. Esta fase es responsable de optimizar el código generado y de manejar la generación de código específica del objetivo. La salida de esta etapa suele ser un archivo ".s" o archivo de "ensamblado".

Clang también admite el uso de un ensamblador integrado, en el que el generador de código produce directamente archivos objeto. Esto evita la sobrecarga de generar el archivo ".s" y de llamar al ensamblador del objetivo.

Ensamblador
Esta etapa ejecuta el ensamblador del objetivo para traducir la salida del compilador en un archivo objeto del objetivo. La salida de esta etapa suele ser un archivo ".o" o archivo "objeto".
Enlazador
Esta etapa ejecuta el enlazador del objetivo para fusionar múltiples archivos objeto en un ejecutable o una biblioteca dinámica. La salida de esta etapa suele ser un archivo "a.out", ".dylib" o ".so".

Analizador Estático de Clang

El Analizador Estático de Clang es una herramienta que escanea el código fuente para intentar encontrar errores mediante el análisis de código. Esta herramienta utiliza muchas partes de Clang y está integrada en el mismo controlador. Consulta <https://clang-analyzer.llvm.org> para obtener más detalles sobre cómo usar el analizador estático.

NAME

clang - C, C++, and Objective-C compiler

SYNOPSIS

clang [options] [input...]

DESCRIPTION

clang is a C, C++, and Objective-C compiler that has been developed with the goals of providing a modern, high-performance compiler infrastructure and a friendly front-end for developing C-family languages.

This document describes the command-line options supported by clang. Most of these options are standard across C compilers, but some are specific to Clang and LLVM.

General Options

-target <target triple>
Select the target architecture to compile for. A target triple is a string which specifies the architecture, vendor, and operating system. For example, -target x86_64-pc-linux-gnu specifies the x86_64 architecture, the PC vendor, and the GNU/Linux operating system. If this option is not specified, the target is determined by the compiler's default settings, which depend on the host system.
-c
Compile or assemble the source files, but do not link. Produce an object file (typically ending in .o) for each input file.
-emit-llvm
Output LLVM bitcode instead of executable code. This option is useful for debugging and for use with other LLVM tools.
-o <output file>
Place the output into the specified file. If this option is omitted, the default behavior depends on the type of output generated. For example, if compiling a single source file to an executable, the output is placed in a file named a.out.
-x <language>
Treat the following input files as having the specified language. Valid languages include c, c++, objective-c, objective-c++, cuda, and assembler. If this option is not specified, the language is determined from the file extension.
-shared
Produce a shared object which can then be linked with other objects to form an executable.
-static
Only use static libraries when linking.
-save-temps
Do not delete temporary files produced during compilation. The default names of these files are based on the source file name and the stage of compilation.
-fpregrouped-expressions
Enable the grouping of expressions in the C language.
-fsyntax-only
Do not perform any optimization or code generation. Simply run the frontend jobs and report errors or warnings.
-fdebuginfo
Produce debugging information consistent with the target's ABI (Application Binary Interface). This option is equivalent to -g.
-g
Produce debugging information consistent with the target's ABI (Application Binary Interface). This option is equivalent to -fdebuginfo.
-gsplit-dwarf
Produce split dwarf debugging information. Debugging information is placed in a separate file, which can reduce the size of the executable file.
-gno-split-dwarf
Disable the generation of split dwarf debugging information.
-Werror
Treat all warnings as errors.
-Wno-error
Do not treat warnings as errors.

-fkeep-system-includes
Usable only with -E. Do not copy the preprocessed content of "system" headers to the output; instead, preserve the #include directive. This can greatly reduce the volume of text produced by -E which can be helpful when trying to produce a "small" reproduceable test case.

This option does not guarantee reproduceability, however. If the including source defines preprocessor symbols that influence the behavior of system headers (for example, _XOPEN_SOURCE) the operation of -E will remove that definition and thus can change the semantics of the included header. Also, using a different version of the system headers (especially a different version of the STL) may result in different behavior. Always verify the preprocessed file by compiling it separately.

ENVIRONMENT

TMPDIR, TEMP, TMP
These environment variables are checked, in order, for the location to write temporary files used during the compilation process.
CPATH
This environment variable specifies additional (non-system) header search paths to be used to find included header files. These paths are searched after paths specified with the -I<directory> option, but before any system header search paths. Paths are delimited by the platform dependent delimiter as used in the PATH environment variable. Empty entries in the delimited path list, including those at the beginning or end of the list, are treated as specifying the compiler's current working directory.
C_INCLUDE_PATH, OBJC_INCLUDE_PATH, CPLUS_INCLUDE_PATH, OBJCPLUS_INCLUDE_PATH
These environment variables specify additional system header file search paths to be used when processing the corresponding language. Search paths are delimited as for the CPATH environment variable.
MACOSX_DEPLOYMENT_TARGET
If -mmacos-version-min is unspecified, the default deployment target is read from this environment variable. This option only affects Darwin targets.
