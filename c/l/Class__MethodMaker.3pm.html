DESCRIPCIÓ

N

Este módulo resuelve el problema de tener que escribir continuamente métodos accesores para tus objetos que realicen tareas

estándar.

El argumento de 'use' es un arrayref, como pares cuyas "claves" son los nombres de los tipos de métodos genéricos generados por MethodMaker y cuyos "valores" le indican al generador de métodos qué métodos

crear.

Para anular cualquier método generado, basta con asegurarse de que el método anulador esté definido cuando se llame a Class::MethodMaker. Ten en cuenta que la palabra clave "use" introduce un bloque "BEGIN", por lo que puede que necesites definir (o al menos declarar) tu método anulador en un bloque "BE

GIN".

Uso

Simple

Una clase simple hecha con "Class::MethodMaker" se ve

así: 
package MyClass;
use Class::MethodMaker
  [ scalar => [qw/ name /],
    new    => [qw/ new  /],
  ]
;

Esto crea una clase, de la cual se pueden crear nuevas instancias usando "new", cada una con un único componente escalar llamado "name". Name puede consultarse y (re)establecerse usando los métodos "name", "name_reset" y "name_isset"

$m->name(undef);

print defined $n ? "->$n<-" : "*undef*";     # *undef*
print $m->name_isset ? "true" : "false";     # true
$m->name_reset;
$n = $m->name;
print defined $n ? "->$n<-" : "*undef*";     # *undef*

Los tipos de componentes disponibles son scalar, array, hash. También se proporcionan ciertas utilidades que no son de tipo de datos: new, para constructores, deep_copy y copy para copias de objetos, y abstract para crear métodos

abstractos.

Cada uno de los componentes acepta opciones comunes. Estas incluyen -static, para datos por clase en lugar de por instancia, -type, para restringir los datos almacenados a ciertos tipos (por ejemplo, objetos de una clase determina

da), -forward para reenviar (proxy) métodos dados a los componentes, -default/-default_ctor para establecer valores predeterminados para los componentes, -tie_class para asociar (tie) el almacenamiento de un tipo de datos a un
a clase dada, -read_cb/-store_cb para llamar funciones definidas por el usuario en la lectura/almacenamiento (sin la sobrecarga/complejidad de las asociaciones (ties); y permitiendo callbacks en clases asociadas (tie) existentes).

Uso

Detallado

"Class::MethodMaker" instala componentes en una clase, por medio de métodos que interrogan y modifican esos componentes. Un componente, a veces referido en otra documentación como un slot (ranura), es un grupo de uno o más atributos (variables) que están asociados con una instancia de una clase (a veces llamada un objeto), o ocasionalmente una clase misma (a menudo referida como un componente estático). Un componente está destinado a ser una unidad cohesiva de datos que normalmente solo debería ser interrogada o establecida a través de los métodos

proporcionados.

Dada una instancia de una clase donde cada instancia representa un coche, ejemplos de componentes son el "make" (marca) y "model" (modelo) (cada uno de los cuales sería un simple escalar, una cadena de texto), el motor (un simple escalar, una instancia de Engine::Combustion), y las ruedas (un array de instancias de Wheel). Ten en cuenta que las ruedas forman un componente, un array. Por supuesto, el implementador podría en su lugar elegir usar cuatro componentes, cada uno siendo un escalar de

rueda.

Para que se creen los componentes, el uso principal de Class::MethodMaker es especificar el tipo (estructura de datos) y el nombre de cada componente al método import de Class::

MethodMaker 
package MyClass;
use Class::MethodMaker
  [ scalar => 'name',
    new    => [qw/ new /],
  ]
;

En este ejemplo, import se llama implícitamente a través de la sentencia "use". Los componentes se instalan en el paquete vigente donde se llama a import. El argumento a import está organizado como pares, donde el primero de cada par es el tipo de la estructura de datos, el segundo son los argumentos para esa estructura de datos; en el caso más simple, el nombre de un componente a instalar usando esa estructura de datos. El segundo del par debe ser un arrayref si no es un nombre

simple.

Las estructuras de datos pueden repetirse en la

llamada: 
use Class::MethodMaker
  [ scalar => 'name1',
    new    => [qw/ new /],
    scalar => 'name2',
  ]
;

Es un error intentar instalar dos o más componentes con el mismo nombre dos

veces.

Se pueden dar opciones a las estructuras de datos para modificar la naturaleza y el comportamiento de los componentes creados. Algunas opciones son comunes a todas las estructuras de datos (por ejemplo, "static") mientras que algunas son específicas de sus respectivas estructuras de datos. La sintaxis de las opciones se detalla a continuación. En resumen, las opciones se proporcionan mediante hashrefs de nombre de opción a valor de opción. Las opciones y los nombres de componentes son sensibles al orden; las opciones que aparecen después de un componente no afectan a ese componente. Las opciones solo se aplican a la estructura de datos a la que se especifican. Las opciones booleanas (por ejemplo, static) pueden abreviarse como -option para establecer, !option para quitar, sin un

hashref. 
use Class::MethodMaker
  [ scalar => [+{ -type => 'File::stat' }, qw/ -static name /],
    new    => 'new',
  ]
;

También hay métodos que no son de estructura de datos que pueden ser creados por Class::MethodMaker. "new" es un ejemplo de uno de tales valores; en su lugar, causa que se cree un método "new" estándar para la clase que llama. La sintaxis de argumentos y opciones sigue siendo la misma, pero muchas opciones claramente no se aplican (por ejemplo, "type" para "new

"
).

Interacción con

Superclases

Básicamente, "Class::MethodMaker" no tiene en cuenta las jerarquías de clases. Si eliges instalar un componente x en una clase B que es una subclase de una clase A que ya tiene un componente x, entonces los métodos que abordan x en B simplemente anularán los de la clase A de la manera habitual. "Class::MethodMaker" no toma ninguna acción espe

cial para esta situación. E
sta es una característica.
