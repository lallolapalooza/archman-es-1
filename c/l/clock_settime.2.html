DESCRIPCIÓ

N

La función clock_getres() encuentra la resolución (precisión) del reloj especificado clockid y, si res no es NULL, la almacena en la struct timespec a la que apunta res. La resolución de los relojes depende de la implementación y no puede ser configurada por un proceso en particular. Si el valor de tiempo al que apunta el argumento tp de clock_settime() no es un múltiplo de res, entonces se trunca a un múltiplo de res

.

Las funciones clock_gettime() y clock_settime() recuperan y establecen el tiempo del reloj especificado clockid

.

Los res y tp argumentos son estructuras timespec

(3).

El clockid argumento es el identificador del reloj particular sobre el cual actuar. Un reloj puede ser de todo el sistema y por lo tanto visible para todos los procesos, o por proceso si mide el tiempo solo dentro de un

proceso.

Todas las implementaciones soportan el reloj de tiempo real de todo el sistema, el cual es identificado por CLOCK_REALTIME. Su tiempo representa segundos y nanosegundos desde la Época. Cuando su tiempo es cambiado, los temporizadores para un intervalo relativo no se ven afectados, pero los temporizadores para un punto absoluto en el tiempo sí lo

están.

Pueden implementarse más relojes. La interpretación de los valores de tiempo correspondientes y el efecto en los temporizadores no está

especificado.

Versiones suficientemente recientes de glibc y el núcleo Linux soportan los siguientes

relojes:
CLOCK_REALTI

Un reloj de todo el sistema ajustable que mide tiempo real (es decir, tiempo de reloj de pared). Establecer este reloj requiere privilegios apropiados. RETORNO

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0. En caso de error, devuelven -1 y la variable errno se establece para indicar el error.

ERRORES

EACCES
clock_settime() no tiene permisos de escritura para el dispositivo de reloj POSIX dinámico indicado.
EFAULT
tp apunta fuera del espacio de direcciones accesible.
EINVAL
El clockid especificado es inválido por una de dos razones. O el valor positivo fijo estilo System-V está fuera de rango, o el ID de reloj dinámico no se refiere a una instancia válida de un objeto de reloj.
EINVAL
(clock_settime()): tp.tv_sec es negativo o tp.tv_nsec está fuera del rango [0, 999.999.999].
EINVAL
El clockid especificado en una llamada a clock_settime() no es un reloj que se pueda establecer.
EINVAL (desde Linux 4.3)
Una llamada a clock_settime() con un clockid de CLOCK_REALTIME intentó establecer la hora a un valor inferior al valor actual del reloj CLOCK_MONOTONIC.
ENODEV
El dispositivo extraíble en caliente (como USB, por ejemplo) representado por un clk_id dinámico ha desaparecido después de que su dispositivo de caracteres fuera abierto.
ENOTSUP
La operación no está soportada por el dispositivo de reloj POSIX dinámico especificado.
EOVERFLOW
La marca de tiempo no cabría en el rango de time_t. Esto puede ocurrir si un ejecutable con time_t de 32 bits se ejecuta en un kernel de 64 bits cuando la hora es 2038-01-19 03:14:08 UTC o posterior. Sin embargo, cuando la hora del sistema está fuera del rango de time_t en otras situaciones, el comportamiento es indefinido.
EPERM
clock_settime() no tiene permisos para establecer el reloj indicado.

VERSIÓNES

POSIX.1 especifica lo siguiente:

Establecer el valor del reloj CLOCK_REALTIME mediante clock_settime() no tendrá ningún efecto en los hilos que estén bloqueados esperando un servicio de tiempo relativo basado en este reloj, incluida la función nanosleep(); ni en la expiración de temporizadores relativos basados en este reloj. En consecuencia, estos servicios de tiempo expirarán cuando transcurra el intervalo relativo solicitado, independientemente del valor nuevo o antiguo del reloj.

Según POSIX.1-2001, un proceso con "privilegios apropiados" puede establecer los relojes CLOCK_PROCESS_CPUTIME_ID y CLOCK_THREAD_CPUTIME_ID utilizando clock_settime(). En Linux, estos relojes no son configurables (es decir, ningún proceso tiene "privilegios apropiados").

Diferencias entre la biblioteca C y el kernel

En algunas arquitecturas, una implementación de clock_gettime() se proporciona en el vdso(7).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SUSv2. Linux 2.6.

En los sistemas POSIX donde estas funciones están disponibles, el símbolo _POSIX_TIMERS se define en <unistd.h> con un valor mayor que 0. POSIX.1-2008 hace que estas funciones sean obligatorias.

Los símbolos _POSIX_MONOTONIC_CLOCK, _POSIX_CPUTIME, _POSIX_THREAD_CPUTIME indican que CLOCK_MONOTONIC, CLOCK_PROCESS_CPUTIME_ID, CLOCK_THREAD_CPUTIME_ID están disponibles. (Véase también sysconf(3)).

POSIX.1-2024 hizo obligatorio CLOCK_MONOTONIC.

Nota histórica para sistemas SMP

Antes de que Linux añadiera soporte en el kernel para CLOCK_PROCESS_CPUTIME_ID y CLOCK_THREAD_CPUTIME_ID, glibc implementó estos relojes en muchas plataformas utilizando registros de temporizador de las CPU (TSC en i386, AR.ITC en Itanium). Estos registros pueden diferir entre CPU y, como consecuencia, estos relojes pueden devolver resultados erróneos si un proceso se migra a otra CPU.

Si las CPU en un sistema SMP tienen fuentes de reloj diferentes, entonces no hay forma de mantener una correlación entre los registros del temporizador, ya que cada CPU funcionará a una frecuencia ligeramente diferente. Si este es el caso, entonces clock_getcpuclockid(0) devolverá ENOENT para significar esta condición. Los dos relojes solo serán útiles si se puede garantizar que un proceso permanece en una CPU determinada.

Los procesadores de un sistema SMP no arrancan todos exactamente al mismo tiempo y, por lo tanto, los registros del temporizador suelen tener un desfase. Algunas arquitecturas incluyen código que intenta limitar estos desfases al arrancar. Sin embargo, el código no puede garantizar la sintonización precisa de los desfases. glibc no contiene disposiciones para tratar estos desfases (a diferencia del Kernel de Linux). Típicamente, estos desfases son pequeños y, por lo tanto, los efectos pueden ser insignificantes en la mayoría de los casos.

Desde glibc 2.4, las funciones envoltorio para las llamadas al sistema descritas en esta página evitan los problemas mencionados anteriormente empleando la implementación del kernel de CLOCK_PROCESS_CPUTIME_ID y CLOCK_THREAD_CPUTIME_ID, en sistemas que proporcionan dicha implementación (es decir, Linux 2.6.12 y posteriores).

Fuente del programa

/* clock_times.c
   Licenciado bajo la Licencia Pública General de GNU v2 o posterior.
*/
#define _XOPEN_SOURCE 600
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <time.h>
#define SECS_IN_DAY (24 * 60 * 60)
static void
displayClock(clockid_t clock, const char *name, bool showRes)
{
    long             days;
    struct timespec  ts;
    if (clock_gettime(clock, &ts) == -1) {
        perror("clock_gettime");
        exit(EXIT_FAILURE);
    }
    printf("%-15s: %10jd.%03ld (", name,
           (intmax_t) ts.tv_sec, ts.tv_nsec / 1000000);
    days = ts.tv_sec / SECS_IN_DAY;
    if (days > 0)
        printf("%ld days + ", days);
    printf("%2dh %2dm %2ds",
           (int) (ts.tv_sec % SECS_IN_DAY) / 3600,
           (int) (ts.tv_sec % 3600) / 60,
           (int) ts.tv_sec % 60);
    printf(")\n");
    if (clock_getres(clock, &ts) == -1) {
        perror("clock_getres");
        exit(EXIT_FAILURE);
    }
    if (showRes)
        printf("     resolución: %10jd.%09ld\n",
               (intmax_t) ts.tv_sec, ts.tv_nsec);
}
int
main(int argc, char *[])
{
    bool showRes = argc > 1;
    displayClock(CLOCK_REALTIME, "CLOCK_REALTIME", showRes);
#ifdef CLOCK_TAI
    displayClock(CLOCK_TAI, "CLOCK_TAI", showRes);
#endif
    displayClock(CLOCK_MONOTONIC, "CLOCK_MONOTONIC", showRes);
#ifdef CLOCK_BOOTTIME
    displayClock(CLOCK_BOOTTIME, "CLOCK_BOOTTIME", showRes);
#endif
    exit(EXIT_SUCCESS);
}
