clipboard(n) Comandos integrados de Tk clipboard(n)

NOMBRE

clipboard - Manipular el portapapeles de Tk

SINOPSIS

clipboard opción ?arg arg ...?

DESCRIPCIÓN

Este comando proporciona una interfaz Tcl al portapapeles de Tk, que almacena datos para su posterior recuperación mediante el mecanismo de selección (a través de la opción -selection CLIPBOARD). Para copiar datos al portapapeles, se debe llamar a clipboard clear, seguido de una secuencia de una o más llamadas a clipboard append. Para asegurar que el portapapeles se actualiza de forma atómica, todas las inserciones deben completarse antes de volver al bucle de eventos.

El primer argumento para clipboard determina el formato del resto de los argumentos y el comportamiento del comando. Las siguientes formas se admiten actualmente:

clipboard append ?-displayof window? ?-format format? ?-type type? ?--? data
Añade data al portapapeles en la pantalla de window en el formato dado por type con la representación dada por format y reclama la propiedad del portapapeles en la pantalla de window.

Type especifica la forma en la que se devolverá la selección (el “objetivo” deseado para la conversión, en la terminología ICCCM), y debe ser un nombre de átomo como STRING o FILE_NAME; consulte el Manual de Convenciones de Comunicación Inter-cliente para detalles completos. Type por defecto es STRING.

El argumento format especifica la representación que debe utilizarse para transmitir la selección al solicitante (la segunda columna de la Tabla 2 del ICCCM), y por defecto es STRING. Si format es STRING, la selección se transmite como caracteres ASCII de 8 bits. Si format es ATOM, entonces los data se dividen en campos separados por espacios en blanco; cada campo se convierte a su valor de átomo, y el valor de átomo de 32 bits se transmite en lugar del nombre del átomo. Para cualquier otro format, los data se dividen en campos separados por espacios en blanco y cada campo se convierte en un entero de 32 bits; se transmite una matriz de enteros al solicitante de la selección. Tenga en cuenta que las cadenas pasadas a clipboard append se concatenan antes de la conversión, por lo que el llamador debe tener cuidado de asegurar un espaciado adecuado entre los límites de las cadenas. Todos los elementos añadidos al portapapeles con el mismo type deben tener el mismo format.

El argumento format solo es necesario para la compatibilidad con solicitantes del portapapeles que no utilizan Tk. Si se utiliza el kit de herramientas Tk para recuperar la selección CLIPBOARD, el valor se vuelve a convertir en una cadena en el extremo solicitante, por lo que format es irrelevante.

Se puede especificar un argumento -- para marcar el final de las opciones: el siguiente argumento siempre se utilizará como data. Esta característica puede ser útil si, por ejemplo, data comienza con un -.

clipboard clear ?-displayof window?
Reclama la propiedad del portapapeles en la pantalla de window y elimina cualquier contenido anterior. Window por defecto es “.”. Devuelve una cadena vacía.
clipboard get ?-displayof window? ?-type type?
Recupera datos del portapapeles en la pantalla de window. Window por defecto es “.”. Type especifica la forma en la que se deben devolver los datos y debe ser un nombre de átomo como STRING o FILE_NAME. Type por defecto es STRING. Este comando es equivalente a “selection get -selection CLIPBOARD”.

Tenga en cuenta que en los sistemas X11 modernos, el tipo más útil a recuperar para cadenas transferidas no es STRING, sino UTF8_STRING.

EJEMPLOS

Obtener el contenido actual del portapapeles.

if {[catch {clipboard get} contents]} {
    # No había contenido en el portapapeles
}

Establecer el portapapeles para que contenga una cadena fija.

clipboard clear
clipboard append "una cadena fija"

Puede introducir datos personalizados en el portapapeles utilizando la opción personalizada -type. Esto no es necesariamente portable, pero puede ser muy útil. El método de pasar scripts Tcl de esta manera es efectivo, pero debe mezclarse con intérpretes seguros en código de producción.

# Este es un serializador de canvas muy simple;
# produce un script que recrea el/los elemento(s) al ejecutarse
proc getItemConfig {canvas tag} {
   set script {}
   foreach item [$canvas find withtag $tag] {
      append script {$canvas create } [$canvas type $item]
      append script { } [$canvas coords $item] { }
      foreach config [$canvas itemconf $item] {
         lassign $config name - - - value
         append script [list $name $value] { }
      }
      append script \n
   }
   return [string trim $script]
}
# Configurar una vinculación en un canvas para cortar y pegar un elemento
set c [canvas .c]
pack $c
$c create text 150 30 -text "¡cúrtame y pégame!"
bind $c <<Cut>> {
   clipboard clear
   clipboard append -type TkCanvasItem \
         [getItemConfig %W current]
   # Eliminar porque es un corte, no una copia.
   %W delete current
}
bind $c <<Paste>> {
   catch {
      set canvas %W
      eval [clipboard get -type TkCanvasItem]
   }
}
