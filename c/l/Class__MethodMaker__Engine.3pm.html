Los métodos no-estructura-de-datos sí forman parte de la API pública, pero no se llaman directamente: en su lugar, se llaman a través de la interfaz "use"/"import" , igual que los m

Esto se llama implícitamente como parte de una declaración

Una lista de renombres personalizados. Es un hashref del nombre del método al renombre. El nombre del método es el nombre genérico (es decir, presentando un "*" para reemplazar con el nombre del componente). El renombre es el valor con el que renombrar. Puede contener él mismo un "*" para reemplazar con el nombre del componente. Si el renombre es undef, el método no se instala. Para métodos que no se instalarían por defecto, use un valor de renombre que sea el mismo que el nombre del método.

Componentes no-estructura-de-dato

s

ne

w 
use Class::MethodMaker
  [ new => 'new' ]
;

Crea un constructor

básico.

Toma como argumento una cadena única o una referencia a un array de cadenas. Para cada cadena, crea un método simple que crea y devuelve un objeto de la clase

apropiada.

El método generado puede ser llamado como un método de clase, como es habitual, o como un método de instancia, en cuyo caso se creará un nuevo objeto de la misma clase que la

instancia.

Opcione

s
-ha
sh
El constructor aceptará como argumentos una lista de pares, del nombre del componente al valor inicial. Para cada par, el componente nombrado es inicializado llamando al método del mismo nombre con el valor dado. Por ejemplo, 
package MyClass;
use Class::MethodMaker
  [ new    => [qw/ -hash new /],
    scalar => [qw/ b c /],
  ];
sub d {
  my $self = shift;
  $self->{d} = $_[0]
    if @_;
  return $self->{d};
}
package main;
# La declaración de abajo llama implícitamente a
# $m->b(1); $m->c(2); $m->d(3)
# sobre el m recién construido.
my $m = MyClass->new(b => 1, c => 2, d
=> 3);

Nótese que esto también puede llamar a métodos proporcionados por el usuario que tengan el nombre del

componente.

En lugar de una lista de pares, también se puede pasar un único hashref, que será expandido apropiadamente. Así que lo anterior es equivalente

a: 
my $m = MyClass->new({ b => 1, c => 2, d =>
3 });

Usuarios Avanzados: El renombrado de métodos de Class::MethodMaker es tenido en cuenta, así que incluso si el "*" método es renombrado o e

liminado, esto se
guirá funcionando.
-in
it
Esta opción hace que el método new llame a un método inicializador. El método es llamado "init" (original, ¿eh?) por defecto, pero a la opción se le puede dar un valor alternativo. Al método init se le pasan los argumentos que se pasaron al constructor, pero el método es invocado sobre la instancia recién construida. 
use Class::MethodMaker
  [ new => [qw/ -init new1 /, { -init => 'bob' } => 'init2'
]];

Construir con new1 implica una llamada implícita a "init", mientras que construir con new2 implica una llamada implícita a "bob" (en lugar de "init

").

Es responsabilidad del usuario asegurarse de que un método "init" (o con el nombre

que sea) está
definido.
-singlet
on
Crea un constructor básico que solo devuelve siempre una única instancia de la clase: es decir, después de la primera llamada, las llamadas repetidas a este constructor devuelven la misma instancia. Nótese que la instancia es
instanciada en el
momento de la prim
era llamada, no antes.

abstrac

t 
use Class::MethodMaker
  [ abstract => [ qw / foo bar baz / ] ]
;

Esto crea un número de métodos que morirán si son llamados.

Esto está pensado para soportar el uso de métodos abstr
actos, que deben ser sobreescritos en una subclase útil.

cop

y 
use Class::MethodMaker
  [ copy => [qw/ shallow -deep deep /] ]
;

Esto crea un método que produce una copia de sí mismo. La copia es por defecto una copia superficial (shallow); cualquier referencia será compartida por la instancia sobre la cual el método es llamado y el recién nacido devuelto. Se toma una opción, "-deep", que hace que el método cree copias profundas en su lugar (es decir, las referencias son copiadas recursivamente)

.

Nota de

Implementación:

Las copias profundas son realizadas usando el módulo "Storable" si está disponible, si no "Data::Dumper". El módulo "Storable" es probable que sea mucho más rápido. Sin embargo, esta nota de implementación no es una especificación de API: los detalles de implementación están abiertos a cambio en una versión futura a medida que se dispongan de formas más rápidas/mejores de realizar una copia

profunda.

Nótese que la copia profunda a

ctualmente no soporta la copia
de referencias a código,
ties u objetos basados en XS.
