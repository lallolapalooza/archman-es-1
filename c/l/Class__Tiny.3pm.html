Definición de

atributos

Define los atributos como una lista de argumentos de

importación: 
package Foo::Bar;
use Class::Tiny qw(
    name
    id
    height
    weight
)
;

Para cada atributo, se crea un accessor de lectura-escritura a menos que ya exista una subrutina con ese

nombre: 
$obj->name;               # getter
$obj->name( "John Doe" ); #
setter

Los nombres de los atributos deben ser identificadores de subrutina válidos o se lanzará una

excepción.

Puedes especificar valores predeterminados diferidos definiendo atributos con una referencia a hash. Las claves definen los nombres de los atributos y los valores son constantes o referencias a código que se evaluarán cuando se acceda al atributo por primera vez si no se ha establecido ningún valor. El objeto se pasa como argumento a una referencia a

código. 
package Foo::WithDefaults;
use Class::Tiny qw/name id/, {
    title     => 'Peon',
    skills    => sub { [] },
    hire_date => sub { $_[0]->_build_hire_date },
}
;

Al crear subclases, si existen varios accesores con el mismo nombre en clases diferentes, cualquier valor predeterminado (o la ausencia de uno) se determina por el orden estándar de resolución de

métodos.

Para crear tus propios accesores personalizados, simplemente predeclara el nombre del método antes de cargar Class::

Tiny: 
package Foo::Bar;
use subs 'id';
use Class::Tiny qw( name id );
sub id { ...
}

Incluso si predeclaras un nombre de método, debes incluirlo en la lista de atributos para que Class::Tiny lo registre como un atributo

válido.

Si estableces un valor predeterminado para un accessor personalizado, tu accessor necesitará recuperar el valor predeterminado y hacer algo con

él: 
package Foo::Bar;
use subs 'id';
use Class::Tiny qw( name ), { id => sub { int(rand(2*31)) } };
sub id {
    my $self = shift;
    if (@_) {
        return $self->{id} = shift;
    }
    elsif ( exists $self->{id} ) {
        return $self->{id};
    }
    else {
        my $defaults =
            Class::Tiny->get_all_attribute_defaults_for( ref $self );
        return $self->{id} = $defaults->{id}->();
    }
}

Class::Tiny::Object es tu clase

base

Si tu clase no hereda ya de alguna clase, entonces Class::Tiny::Object se añadirá a tu @ISA para proporcionar "new" y "DESTROY"

.

Si tu clase hereda de algo, entonces no se establece ninguna herencia adicional. Si la clase padre es subclase de Class::Tiny::Object, entonces todo está bien. Si no, entonces tendrás accesores establecidos pero sin constructor ni destructor. No hagas eso a menos que realmente tengas una necesidad especial por

ello.

Define las subclases como de costumbre. Es mejor definirlas con base, parent o superclass antes de definir los atributos con Class::Tiny para que el @ISA ya esté poblado en tiempo de

compilación: 
package Foo::Bar::More;
use parent 'Foo::Bar';
use Class::Tiny qw( shoe_size
)
;

Construcción de

objetos

Si tu clase hereda de Class::Tiny::Object (como debería si seguiste el consejo anterior), te proporciona el constructor

"new".

Los objetos se pueden crear con atributos dados como una referencia a hash o como una lista de pares

clave/valor: 
$obj = Foo::Bar->new( name => "David" );
$obj = Foo::Bar->new( { name => "David" } )
;

Si se pasa una referencia como un solo argumento, debe poder ser desreferenciada como un hash o se lanzará una

excepción.

Los atributos desconocidos en los argumentos del constructor se ignorarán. Antes de la versión 1.000, los atributos desconocidos eran un error, pero esto hacía más difícil para las personas crear subclases limpiamente de las clases de Class::Tiny, por lo que esta característica fue

eliminada.

Puedes definir un "BUILDARGS" método para cambiar cómo se manejan los argumentos de new. Recibirá los argumentos del constructor tal como se proporcionaron y debe devolver una referencia a hash de pares clave/valor (o de lo contrario lanzar una excepción)

. 
sub BUILDARGS {
   my $class = shift;
   my $name = shift || "John Doe";
   return { name => $name };
 };
 Foo::Bar->new( "David" );
 Foo::Bar->new(); # "John
Doe"

Los atributos desconocidos devueltos desde "BUILDARGS"

se igno
rarán.

BUIL

D

Si tu clase o cualquier superclase define un "BUILD" método, será llamado por el constructor desde la clase padre más lejana hasta la clase hija después de que el objeto haya sido

creado.

Se le pasan los argumentos del constructor como una referencia a hash. El valor de retorno se ignora. Usa "BUILD" para validación, comprobar atributos requeridos o establecer valores predeterminados que dependen de otros

atributos. 
sub BUILD {
    my ($self, $args) = @_;
    for my $req ( qw/name age/ ) {
        croak "$req attribute required" unless defined $self->$req;
    }
    croak "Age must be non-negative" if $self->age < 0;
    $self->msg( "Hello " . $self->name );
}

La referencia de argumentos es una copia, por lo que eliminar elementos no afectará a los datos en el original (pero los cambios se pasarán a otros métodos BUILD en @IS

A
).

DEMOLIS

H

Class::Tiny proporciona un "DESTROY" método. Si tu clase o cualquier superclase define un "DEMOLISH" método, serán llamados desde la clase hija hasta la clase padre más lejana durante la destrucción del objeto. Se le proporciona un único argumento booleano que indica si Perl está en destrucción global. Los valores de retorno se ignoran. Los errores se capturan y se

relanzan. 
sub DEMOLISH {
    my ($self, $global_destruct) = @_;
    $self->cleanup();
}
