DESCRIPCIÓ

N

Si la bandera TIMER_ABSTIME no está establecida en el argumento flags, la función clock_nanosleep() hará que el hilo actual sea suspendido de la ejecución hasta que se haya transcurrido el intervalo de tiempo especificado por el argumento rqtp, o hasta que se entregue una señal al hilo llamante y su acción sea invocar una función de captura de señales, o hasta que el proceso sea terminado. El reloj utilizado para medir el tiempo será el reloj especificado por clock_id

.

Si la bandera TIMER_ABSTIME está establecida en el argumento flags, la función clock_nanosleep() hará que el hilo actual sea suspendido de la ejecución hasta que el valor de tiempo del reloj especificado por clock_id alcance el tiempo absoluto especificado por el argumento rqtp, o hasta que se entregue una señal al hilo llamante y su acción sea invocar una función de captura de señales, o hasta que el proceso sea terminado. Si, en el momento de la llamada, el valor de tiempo especificado por rqtp es menor o igual que el valor de tiempo del reloj especificado, entonces clock_nanosleep() retornará inmediatamente y el proceso llamante no será

suspendido.

El tiempo de suspensión causado por esta función puede ser mayor que el solicitado porque el valor del argumento se redondea hacia arriba a un múltiplo entero de la resolución de suspensión, o debido a la planificación de otra actividad por parte del sistema. Pero, excepto en el caso de ser interrumpido por una señal, el tiempo de suspensión para la función relativa clock_nanosleep() (es decir, con la bandera TIMER_ABSTIME no establecida) no será menor que el intervalo de tiempo especificado por rqtp, según lo medido por el reloj correspondiente. La suspensión para la función absoluta clock_nanosleep() (es decir, con la bandera TIMER_ABSTIME establecida) estará en efecto al menos hasta que el valor del reloj correspondiente alcance el tiempo absoluto especificado por rqtp, excepto en el caso de ser interrumpido por una

señal.

El uso de la función clock_nanosleep() no tendrá efecto sobre la acción o el bloqueo de ninguna

señal.

La función clock_nanosleep() fallará si el argumento clock_id se refiere al reloj de tiempo de CPU del hilo llamante. No está especificado si se permiten valores de clock_id de otros relo

jes de tie
mpo de CPU.

JUSTIFICACIÓ

N

La función nanosleep() especifica que el reloj CLOCK_REALTIME de todo el sistema se utiliza para medir el tiempo transcurrido para este servicio de tiempo. Sin embargo, con la introducción del reloj monótono CLOCK_MONOTONIC se necesita una nueva función de suspensión relativa para permitir que una aplicación aproveche las características especiales de este

reloj.

Hay muchas aplicaciones en las que un proceso necesita ser suspendido y luego activado múltiples veces de manera periódica; por ejemplo, para consultar el estado de un dispositivo no interrumpible o para refrescar un dispositivo de visualización. Para estos casos, se sabe que la activación periódica precisa no puede lograrse con una llamada a la función relativa sleep() o nanosleep(). Supóngase, por ejemplo, un proceso periódico que se activa en el tiempo T0, se ejecuta durante un tiempo, y luego quiere suspenderse hasta el tiempo T0+T, siendo el período T. Si este proceso quiere usar la función nanosleep(), primero debe llamar a clock_gettime() para obtener el tiempo actual, luego calcular la diferencia entre el tiempo actual y T0+T y, finalmente, llamar a nanosleep() usando el intervalo calculado. Sin embargo, el proceso podría ser preemtado por un proceso diferente entre las dos llamadas a la función, y en este caso el intervalo calculado sería incorrecto; el proceso se despertaría más tarde de lo deseado. Este problema no ocurriría con la función absoluta clock_nanosleep(), ya que solo sería necesaria una llamada a la función para suspender el proceso hasta el tiempo deseado. En otros casos, sin embargo, se necesita una suspensión relativa, y por eso se requieren ambas funcionalidades

.

Aunque es posible implementar procesos periódicos usando la interfaz de temporizadores, esta implementación requeriría el uso de señales y la reserva de algunos números de señal. En este sentido, las razones para incluir una versión absoluta de la función clock_nanosleep() en POSIX.1‐2008 son las mismas que para la inclusión de la nanosleep() re

lativa.

También es posible implementar procesos periódicos precisos usando pthread_cond_timedwait(), en la cual se especifica un tiempo de espera absoluto que entra en efecto si la variable de condición involucrada nunca es señalada. Sin embargo, el uso de esta interfaz es antinatural e implica realizar otras operaciones sobre mutex y variables de condición que conllevan una sobrecarga innecesaria. Además, pthread_cond_timedwait() no está disponible en implementaciones que no soportan

hilos.

Aunque la interfaz de las versiones relativa y absoluta del nuevo servicio de suspensión de alta resolución es la misma función clock_nanosleep(), el argumento rmtp solo se usa en la suspensión relativa. Este argumento es necesario en la función relativa clock_nanosleep() para reemitir la llamada a la función si es interrumpida por una señal, pero no es necesario en la llamada a la función absoluta clock_nanosleep(); si la llamada es interrumpida por una señal, la función absoluta clock_nanosleep() puede ser invocada de nuevo con el mismo argumento rqtp usado en la

llamada
interrumpida.
