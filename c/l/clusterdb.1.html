Paquete: postgresql-libs

Licencias: PostgreSQL

CLUSTERDB(1) Documentación de PostgreSQL 18.1 CLUSTERDB(1)

NOMBRE

clusterdb - agrupa en clúster una base de datos PostgreSQL

SINOPSIS

clusterdb [opción-conexión...] [opción...] [ --table | -t tabla ]... [basededatos | -a | --all]

DESCRIPCIÓN

clusterdb es una utilidad para reagrupar tablas en una base de datos PostgreSQL. Busca tablas que previamente han sido agrupadas y las agrupa de nuevo en el mismo índice que se utilizó por última vez. Las tablas que nunca han sido agrupadas no se ven afectadas.

clusterdb es un envoltorio alrededor del comando SQL CLUSTER(7). No hay una diferencia efectiva entre agrupar bases de datos a través de esta utilidad y a través de otros métodos para acceder al servidor.

OPCIONES

clusterdb acepta los siguientes argumentos de línea de comandos:

-a
--all

Agrupa en clúster todas las bases de datos.

[-d] basededatos
[--dbname=]basededatos

Especifica el nombre de la base de datos a agrupar, cuando -a/--all no se usa. Si no se especifica, el nombre de la base de datos se lee de la variable de entorno PGDATABASE. Si esta no está configurada, se utiliza el nombre de usuario especificado para la conexión. La basededatos puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos en conflicto.

-e
--echo

Muestra los comandos que clusterdb genera y envía al servidor.

-q
--quiet

No muestra mensajes de progreso.

-t tabla
--table=tabla

Agrupa solo la tabla. Se pueden agrupar varias tablas escribiendo múltiples interruptores -t.

-v
--verbose

Imprime información detallada durante el procesamiento.

-V
--version

Imprime la versión de clusterdb y sale.

-?
--help

Muestra ayuda sobre los argumentos de la línea de comandos de clusterdb y sale.

clusterdb también acepta los siguientes argumentos de línea de comandos para parámetros de conexión:

-h host
--host=host

Especifica el nombre del host de la máquina en la que se ejecuta el servidor. Si el valor comienza con una barra, se usa como el directorio para el socket de dominio Unix.

-p puerto
--port=puerto

Especifica el puerto TCP o la extensión del archivo de socket de dominio Unix local en el que el servidor está escuchando las conexiones.

-U nombreusuario
--username=nombreusuario

Nombre de usuario para conectarse.

-w
--no-password

Nunca solicita una contraseña. Si el servidor requiere autenticación de contraseña y una contraseña no está disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.

-W
--password

Fuerza a clusterdb a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que clusterdb solicitará automáticamente una contraseña si el servidor la requiere. Sin embargo, clusterdb desperdiciará un intento de conexión al descubrir que el servidor quiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

--dbname=basededatos

Cuando se usa -a/--all, conéctese a esta base de datos para recopilar la lista de bases de datos a agrupar. Si no se especifica, se utilizará la base de datos postgres, o si esta no existe, se utilizará template1. Esta puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos en conflicto. Además, los parámetros de la cadena de conexión distintos del nombre de la base de datos se reutilizarán al conectarse a otras bases de datos.

AMBIENTE

PGDATABASE
PGHOST
PGPORT
PGUSER

Parámetros de conexión predeterminados

PG_COLOR

Especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son siempre, auto y nunca.

Esta utilidad, como la mayoría de las otras utilidades de PostgreSQL, también utiliza las variables de entorno admitidas por libpq (ver Sección 32.15).

DIAGNÓSTICOS

En caso de dificultad, consulte CLUSTER(7) y psql(1) para discutir posibles problemas y mensajes de error. El servidor de base de datos debe estar en ejecución en el host de destino. Además, se aplicarán cualquier configuración de conexión predeterminada y variables de entorno utilizadas por la biblioteca front-end libpq.

EJEMPLOS

Para agrupar la base de datos test:

$ clusterdb test

Para agrupar una sola tabla foo en una base de datos llamada xyzzy:

$ clusterdb --table=foo xyzzy
