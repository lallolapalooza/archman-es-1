  CLIENT INTERFACE
  clnt_create
  3
  lib
  rpc.h
  
    
      This routine creates an RPC client handle for the remote program
      prognum, version versnum. The client uses the transport
      protocol specified by the first four characters of
      type. Currently, supported transports include
      "udp" and "tcp". The
      remote machine is named by host. If host is NULL, then the
      local machine is assumed. The parameters sendsz and
      recvsz specify the size of the send and receive buffers,
      respectively; zero values choose suitable defaults. This routine returns
      NULL if it fails. The global variable
      rpc_createerr contains the error code.

      Take the same arguments as clnt_perrno(), but instead of sending a

      supported by clnt_perrno() is to be used. Note: unlike
      clnt_sperror() and clnt_spcreateerror(),
      clnt_sperrno() returns pointer to static data, but the result will
      not get overwritten on each call.

  CLIENT INTERFACE
  clntraw_create
  3
  lib
  rpc.h
  
    
      This routine creates a toy RPC client for the remote program
      prognum, version versnum. The
      transport used to pass messages to the service is actually a buffer within
      the process's address space, so the corresponding RPC server should live in
      the same address space; see svcraw_create(). This allows
      simulation of RPC and acquisition of RPC overheads, such as round trip
      times, without any kernel interference. This routine returns NULL if it
      fails.
    
  





  CLIENT INTERFACE
  clnttcp_create
  3
  lib
  rpc.h
  
    
      This routine creates an RPC client for the remote program
      prognum, version versnum; the
      client uses TCP/IP as a transport. The remote program is located at
      Internet address *addr. If
      addr->sin_port is zero, then it is set to the actual
      port that the remote program is listening on (the remote
      portmap service is consulted for this information). The
      parameter sockp is a socket; if it is
      RPC_ANYSOCK, then this routine opens a new one and sets
      sockp. Since TCP-based RPC uses buffered I/O, the user
      may specify the size of the send and receive buffers with the parameters
      sendsz and recvsz; values of zero
      choose suitable defaults. This routine returns NULL if it fails.
    
  





  CLIENT INTERFACE
  clntudp_create
  3
  lib
  rpc.h
  
    
      This routine creates an RPC client for the remote program
      prognum, version versnum; the
      client uses use UDP/IP as a transport. The remote program is located at
      Internet address addr. If
      addr->sin_port is zero, then it is set to actual
      port that the remote program is listening on (the remote
      portmap service is consulted for this information). The
      parameter sockp is a socket; if it is
      RPC_ANYSOCK, then this routine opens a new one and sets
      sockp. The UDP transport resends the call message in
      intervals of wait time until a response is received or
      until the call times out. The total time for the call to time out is
      specified by clnt_call().
    
    
      Warning: since UDP-based RPC messages can hold only up to 8 Kbytes of
      encoded data, this transport cannot be used for procedures that take large
      arguments or return huge results.
    
  





  CLIENT INTERFACE
  clntudp_bufcreate
  3
  lib
  rpc.h
  
    
      This routine creates an RPC client for the remote program
      prognum, on versnum; the client
      uses use UDP/IP as a transport. The remote program is located at Internet
      address addr. If addr->sin_port
      is zero, then it is set to actual port that the remote program is listening
      on (the remote portmap service is consulted for this
      information). The parameter sockp is a socket; if it
      is RPC_ANYSOCK, then this routine opens a new one and sets
      sockp. The UDP transport resends the call message in
      intervals of wait time until a response is received or
      until the call times out. The total time for the call to time out is
      specified by clnt_call().
    
    
      This allows the user to specify the maximum packet size for sending and
      receiving UDP-based RPC messages.

struct rpc_createerr rpc_createerr;



  

  
Una variable global cuyo valor se establece en cualquier rutina de creación
      de cliente RPC que no tenga éxito. Utilice la rutina clnt_pcreateerror()
      para imprimir la razón por la cual.




void svc_destroy(SVCXPRT *xprt);



  

  
Una macro que destruye el manejador de transporte del servicio RPC,
      xprt. La destrucción generalmente implica la desasignación de
      estructuras de datos privadas, incluido xprt en sí. El uso de
      xprt no está definido después de llamar a esta rutina.




fd_set svc_fdset;



  

  
Una variable global que refleja la máscara de bits del descriptor de archivo
      de lectura del lado del servicio RPC; es adecuada como parámetro para la
      llamada al sistema select(2). Esto solo es de interés si un
      implementador de servicio realiza su propio procesamiento de eventos asíncronos,
      en lugar de llamar a svc_run(). Esta variable es de solo lectura (¡no
      pase su dirección a select(2)!), sin embargo, puede cambiar
      después de las llamadas a svc_getreqset() o a cualquier rutina de
      creación.




int svc_fds;



  

  
Similar a svc_fdset, pero limitado a 32 descriptores de archivo. Esta
      interfaz está obsoleta por svc_fdset.




svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);



  

  
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando
      decodificó los argumentos de un procedimiento de servicio utilizando
      svc_getargs(). Esta rutina devuelve 1 si los resultados se liberaron
      correctamente y cero en caso contrario.




svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);



  

  
Una macro que decodifica los argumentos de una solicitud RPC asociada con el
      manejador de transporte del servicio RPC, xprt. El parámetro
      in es la dirección donde se colocarán los argumentos;
      inproc es la rutina XDR utilizada para decodificar los argumentos.
      Esta rutina devuelve uno si la decodificación tiene éxito y cero en caso
      contrario.




struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);



  

  
La forma aprobada de obtener la dirección de red del llamador de un
      procedimiento asociado con el manejador de transporte del servicio RPC,
      xprt.




void svc_getreqset(fd_set *rdfds);



  

  
Esta rutina solo es de interés si un implementador de servicio no llama a
      svc_run(), sino que implementa procesamiento de eventos asíncronos
      personalizado. Se llama cuando la llamada al sistema select(2) ha
      determinado que ha llegado una solicitud RPC en alguno(s) socket(s) RPC;
      rdfds es la máscara de bits resultante del descriptor de archivo
      de lectura. La rutina regresa cuando todos los sockets asociados con el
      valor de rdfds han sido atendidos.




void svc_getreq(int rdfds);



  

  
Similar a svc_getreqset(), pero limitada a 32 descriptores de archivo.
      Esta interfaz está obsoleta por svc_getreqset().




bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);



  

  
Asocia prognum y versnum con el procedimiento de despacho del
      servicio, dispatch. Si protocol es cero, el servicio no se
      registra con el servicio portmap. Si protocol no es cero,
      entonces se establece una asignación del triple
      [prognum,versnum,protocol] a xprt->xp_port
      con el servicio portmap local (generalmente
      protocol es cero, IPPROTO_UDP o IPPROTO_TCP). El
      procedimiento dispatch tiene el siguiente formato:

  

  

    

    
dispatch(struct svc_req *request, SVCXPRT *xprt);


    

  

  

  
La rutina svc_register() devuelve uno si tiene éxito, y cero en caso
      contrario.




void svc_run(void);



  

  
Esta rutina nunca regresa. Espera a que lleguen solicitudes RPC y llama al
      procedimiento de servicio apropiado usando svc_getreq() cuando
      llega una. Este procedimiento generalmente está esperando a que una llamada
      al sistema select(2) regrese.




bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);



  

  
Llamada por la rutina de despacho de un servicio RPC para enviar los
      resultados de una llamada a procedimiento remoto. El parámetro
      xprt es el manejador de transporte asociado con la solicitud;
      outproc es la rutina XDR que se utiliza para codificar los
      resultados; y out es la dirección de los resultados. Esta rutina
      devuelve uno si tiene éxito, cero en caso contrario.




void svc_unregister(unsigned long prognum, unsigned long versnum);



  

  
Elimina todas las asignaciones del doble [prognum,versnum] a
      rutinas de despacho, y del triple
      [prognum,versnum,*] a número de puerto.




void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);



  

  
Llamada por una rutina de despacho de servicio que se niega a realizar una
      llamada a procedimiento remoto debido a un error de autenticación.




void svcerr_decode(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio que no puede decodificar
      correctamente sus parámetros. Véase también svc_getargs().




void svcerr_noproc(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio que no implementa el número
      de procedimiento que solicita el llamador.




void svcerr_noprog(SVCXPRT *xprt);



  

  
Llamada cuando el programa deseado no está registrado con el paquete RPC.
      Los implementadores de servicio generalmente no necesitan esta rutina.




void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);



  

  
Llamada cuando la versión deseada de un programa no está registrada con el
      paquete RPC. Los implementadores de servicio generalmente no necesitan
      esta rutina.




void svcerr_systemerr(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio cuando detecta un error del
      sistema no cubierto por ningún protocolo particular. Por ejemplo, si un
      servicio ya no puede asignar almacenamiento, puede llamar a esta rutina.




void svcerr_weakauth(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio que se niega a realizar una
      llamada a procedimiento remoto debido a parámetros de autenticación
      insuficientes. La rutina llama a svcerr_auth(xprt, AUTH_TOOWEAK).




SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);



  

  
Crea un servicio sobre cualquier descriptor de archivo abierto. Típicamente,
      este descriptor de archivo es un socket conectado para un protocolo de
      flujo como TCP. sendsize y recvsize indican los tamaños de los
      buffers de envío y recepción. Si son cero, se elige un valor predeterminado
      razonable.




SVCXPRT *svcraw_create(void);



  

  
Esta rutina crea un transporte de servicio RPC de juguete, al que devuelve
      un puntero. El transporte es realmente un buffer dentro del espacio de
      direcciones del proceso, por lo que el cliente RPC correspondiente debe
      residir en el mismo espacio de direcciones; véase clntraw_create().
      Esta rutina permite simular RPC y adquirir sobrecargas RPC (como tiempos
      de ida y vuelta), sin ninguna interferencia del kernel. Esta rutina devuelve
      NULL si falla.




SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);



  

  
Esta rutina crea un transporte de servicio RPC basado en TCP/IP, al que
      devuelve un puntero. El transporte está asociado con el socket
      sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo
      socket. Si el socket no está enlazado a un puerto TCP local, esta rutina
      lo enlaza a un puerto arbitrario. Al finalizar, xprt->xp_sock
      es el descriptor del socket de transporte y xprt->xp_port es el
      número de puerto del transporte. Esta rutina devuelve NULL si falla. Dado
      que RPC basado en TCP utiliza E/S con búfer, los usuarios pueden especificar
      el tamaño de los búferes; valores de cero eligen valores predeterminados adecuados.




SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);



  

  
Esta rutina crea un transporte de servicio RPC basado en UDP/IP, al que
      devuelve un puntero. El transporte está asociado con el socket
      sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo
      socket. Si el socket no está enlazado a un puerto UDP local, esta rutina
      lo enlaza a un puerto arbitrario. Al finalizar, xprt->xp_sock
      es el descriptor del socket de transporte y xprt->xp_port es el
      número de puerto del transporte. Esta rutina devuelve NULL si falla.

  

  
Esto permite al usuario especificar el tamaño máximo de paquete para enviar
      y recibir mensajes RPC basados en UDP.




SVCXPRT *svcudp_create(int sock);



  

  
Esta llamada es equivalente a svcudp_bufcreate(sock,SZ,SZ) para
      algún tamaño predeterminado SZ.
