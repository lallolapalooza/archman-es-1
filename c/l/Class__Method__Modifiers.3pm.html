SINOPSI

S 
package Child;
use parent 'MyParent';
use Class::Method::Modifiers;
sub new_method { }
before 'old_method' => sub {
    carp "old_method is deprecated, use new_method";
};
around 'other_method' => sub {
    my $orig = shift;
    my $ret = $orig->(@_);
    return $ret =~ /\d/ ? $ret : lc $ret;
};
after 'private', 'protected' => sub {
    debug "finished calling a dangerous method";
};
use Class::Method::Modifiers qw(fresh);
fresh 'not_in_hierarchy' => sub {
    warn "freshly added method\n";
}
;

DESCRIPCIÓ

N

Los modificadores de método son una característica conveniente del mundo CLOS (Sistema de Objetos de Lisp Común)

.

En su forma más básica, un modificador de método es simplemente un método que llama a "$self->SUPER::foo(@_)". Yo, por mi parte, tengo problemas para recordar esa invocación exacta, por lo que mis clases rara vez reenvían a sus clases base. ¡Muy

mal!

"Class::Method::Modifiers" proporciona tres modificadores: "before", "around", y "after". "before" y "after" se ejecutan justo antes y después del método que modifican, pero no pueden realmente afectar a ese método original. "around" se ejecuta en lugar del método original, con un gancho para llamar fácilmente a ese método original. Consulte la sección "MODIFICADORES" para obtener más detalles sobre cómo funcionan los modificadores

particulares.

Un beneficio claro de usar "Class::Method::Modifiers" es que puedes definir múltiples modificadores en un solo espacio de nombres. Estos modificadores separados no necesitan conocerse entre sí. Esto hace que el diseño de arriba hacia abajo sea fácil. Ten una clase base que proporcione los métodos esqueleto de cada operación, y ten plugins que modifiquen esos métodos para concretar los detalles

específicos.

Las clases padre no necesitan conocer "Class::Method::Modifiers". Esto significa que deberías poder modificar métodos en cualquier subclase. Consulte Term::VT102::ZeroBased para ver un ejemplo de subclaseo con "Class::Method::Mo

difiers".

En resumen, "Class::Method::Modifiers" resuelve el problema de asegurarse de que llamas a "$self->SUPER::foo(@_)", y proporciona una interfaz más limpia para

ello.

A partir de la versión 1.00, "Class::Method::Modifiers" es más rápido en algunos casos que Moose. Consulte benchmark/method_modifiers.pl en la distribución de

Moose.

"Class::Method::Modifiers" también proporciona un tipo de "modificador" adicional, "fresh"; véa

se más
abajo.

MODIFICADORE

S

Todos los modificadores te permiten modificar uno o múltiples métodos a la vez. Los nombres de múltiples métodos pueden proporcionarse como una lista o como una referencia a un arreglo.

Ejemplos: 
before 'method' => sub { ... };
before 'method1', 'method2' => sub { ... };
before [ 'method1', 'method2' ] => sub { ... }
;

before method(s) => sub { ... }

;

"before" se llama antes del método que está modificando. Su valor de retorno se ignora por completo. Recibe el mismo @_ que el método que está modificando habría recibido. Puedes modificar el @_ que el método original recibirá cambiando $_[0] y compañía (o cambiando cualquier cosa den

tro de una referencia). ¡E
sta es una característica!

after method(s) => sub { ... }

;

"after" se llama después del método que está modificando. Su valor de retorno se ignora por completo. Recibe el mismo @_ que el método que está modificando recibió, en su mayoría. El método original puede modificar @_ (como cambiando $_[0] o referencias) y "after" verá la versión modificada. Si no te gusta este comportamiento, especifica tanto un "before" como un "after", y copia el @_ durante el "before" para que "after"

lo
use.

around method(s) => sub { ... }

;

"around" se llama en lugar del método que está modificando. El método que estás sobrescribiendo se pasa como el primer argumento (llamado $orig por convención). Ten cuidado con los valores de retorno contextuales de $orig

.

Puedes usar "around"

para:
Pasar a $orig un @_
diferente 
around 'method' => sub {
    my $orig = shift;
    my $self = shift;
    $orig->($self, reverse
@_);
};
Manipular el valor de retorno de
$orig 
around 'method' => sub {
    my $orig = shift;
    ucfirst $orig->(@_)
;
};
Evitar llamar a $orig --
condicionalmente 
around 'method' => sub {
my $orig = shift;
return $orig->(@_) i
f time() % 2; retur
n "no dice, captain"; };

fresh method(s) => sub { ... }

;

(Disponible desde la versión 2.

00)

A diferencia de los otros modificadores, este no modifica un método existente. Ordinariamente, "fresh" simplemente instala la referencia al código como un método en la clase apropiada; pero si la jerarquía de clases ya contiene un método con el mismo nombre, se lanza una excepción. La idea de este "modificador" es aumentar la seguridad al subclasear. Supón que estás escribiendo una subclase de una clase Some::Base y añadiendo un nuevo

método: 
package My::Subclass;
use base 'Some::Base';
sub foo { ...
}

Si una versión posterior de Some::Base también añade un nuevo método llamado "foo", tu método eclipsará ese método. Alternativamente, puedes usar "fresh" para instalar el método adicional en tu

subclase: 
package My::Subclass;
use base 'Some::Base';
use Class::Method::Modifiers 'fresh';
fresh 'foo' => sub { ... }
;

Ahora, actualizar Some::Base a una versión con un método "foo" conflictivo causará que se lance una excepción; ver ese error te dará la oportunidad de arreglar el problema (quizás eligiendo un nombre de método diferente en tu subclase, o algo similar)

.

Crear métodos nuevos con "install_modifier" (véase más abajo) proporciona una forma de obtener beneficios de seguridad similares al añadir parches locales (monkeypatches) a clases existentes; consulta http://aaroncrane.co.uk/talks/monkey_patching_subclassing/

.

Por razones de compatibilidad de la API, esta función solo se exporta cuando la pides específicamente, o para ":al

l
".

install_modifier $package, $type, @names, sub { ...

}

"install_modifier" es como "before", "after", "around", y "fresh" pero también te permite seleccionar dinámicamente el tipo de modificador ('before', 'after', 'around', 'fresh') y el paquete en el que se instalan los modificadores de método. Este nivel experto función se exporta solo cuando la solicitas específicamente, o para ":a

l
l"
.

NOTA

S

Los tres modificadores normales; "before", "after" y "around"; se exportan en tu espacio de nombres de forma predeterminada. Puedes usar "use Class::Method::Modifiers ()" para evitar modificar tu espacio de nombres. Puede que robe más características de Moose, a saber "super", "override", "inner", "augment" y lo que sea que la gente de Moose invente a

continuación.

Ten en cuenta que la sintaxis y la semántica de estos modificadores se toman directamente de Moose (las implementaciones, sin embargo, no)

.

Class::Trigger comparte algunas similitudes con "Class::Method::Modifiers", e incluso tienen cierta superposición de propósito; ambos pueden usarse para implementar aplicaciones altamente enchufables. La diferencia es que Class::Trigger proporciona un mecanismo para permitir fácilmente que las clases padre invoquen ganchos definidos por otro código. "Class::Method::Modifiers" proporciona una forma segura de sobrescribir/aumentar métodos, y la clase padre no necesita saber nada al

respecto.

Al añadir "before" o "after" modificadores, el método envoltorio será un método lvalue si la subrutina envuelta lo es, y la asignación al método se propagará al método envuelto como se espera. Para "around" modificadores, es la subrutina del modi

ficador la que determ
ina si el método envolto
rio es un método lvalue.

ADVERTENCI

AS

Es un error modificar un método que no existe en la jerarquía de herencia de tu clase. Si esto ocurre, se lanzará una excepción cuando se defina el

modificador.

Aún no funciona bien con "caller". Hay algunas "TODO" pruebas para esto. ¡No te hagas ilusiones, sin

embargo!

Aplicar modificadores a métodos lvalue de array no está completamente soportado. Intentar asignar a un método lvalue de array al que se le ha aplicado un "after" modificador resultará en un error. Los métodos lvalue de arr

ay no están bien soportados por perl
en general, y deberían evitarse.
