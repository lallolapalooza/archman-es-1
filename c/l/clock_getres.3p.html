CLOCK_GETRES(3P) Manual del Programador POSIX CLOCK_GETRES(3P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

clock_getres, clock_gettime, clock_settime — funciones de reloj y temporizador

SINOPSIS

#include <time.h>
int clock_getres(clockid_t clock_id, struct timespec *res);
int clock_gettime(clockid_t clock_id, struct timespec *tp);
int clock_settime(clockid_t clock_id, const struct timespec *tp);

DESCRIPCIÓN

La función clock_getres() devolverá la resolución de cualquier reloj. Las resoluciones de los relojes dependen de la implementación y no pueden ser establecidas por un proceso. Si el argumento res no es NULL, la resolución del reloj especificado se almacenará en la ubicación apuntada por res. Si res es NULL, no se devolverá la resolución del reloj. Si el argumento time de clock_settime() no es un múltiplo de res, el valor se truncará a un múltiplo de res.

La función clock_gettime() devolverá el valor actual tp para el reloj especificado, clock_id.

La función clock_settime() establecerá el reloj especificado, clock_id, al valor especificado por tp. Los valores de tiempo que se encuentren entre dos múltiplos enteros no negativos consecutivos de la resolución del reloj especificado se truncarán al múltiplo inferior de la resolución.

Un reloj puede ser global del sistema (es decir, visible para todos los procesos) o por proceso (midiendo tiempo que solo tiene sentido dentro de un proceso). Todas las implementaciones deben admitir un clock_id de CLOCK_REALTIME tal como se define en <time.h>. Este reloj representa el reloj que mide el tiempo real del sistema. Para este reloj, los valores devueltos por clock_gettime() y especificados por clock_settime() representan la cantidad de tiempo (en segundos y nanosegundos) transcurrido desde la Época. Una implementación también puede admitir relojes adicionales. La interpretación de los valores de tiempo para estos relojes no está especificada.

Si el valor del reloj CLOCK_REALTIME se establece mediante clock_settime(), el nuevo valor del reloj se utilizará para determinar el tiempo de expiración de los servicios de tiempo absoluto basados en el reloj CLOCK_REALTIME. Esto se aplica al momento en que expiran los temporizadores absolutos armados. Si el tiempo absoluto solicitado en la invocación de dicho servicio de tiempo es anterior al nuevo valor del reloj, el servicio de tiempo expirará inmediatamente como si el reloj hubiera alcanzado el tiempo solicitado normalmente.

Establecer el valor del reloj CLOCK_REALTIME mediante clock_settime() no tendrá ningún efecto en los hilos que estén bloqueados esperando un servicio de tiempo relativo basado en este reloj, incluida la función nanosleep(); ni en la expiración de temporizadores relativos basados en este reloj. En consecuencia, estos servicios de tiempo expirarán cuando transcurra el intervalo relativo solicitado, independientemente del valor nuevo o antiguo del reloj.

Si se admite la opción Reloj Monótono, todas las implementaciones admitirán un clock_id de CLOCK_MONOTONIC definido en <time.h>. Este reloj representa el reloj monótono del sistema. Para este reloj, el valor devuelto por clock_gettime() representa la cantidad de tiempo (en segundos y nanosegundos) transcurrido desde un punto no especificado en el pasado (por ejemplo, la hora de inicio del sistema o la Época). Este punto no cambia después de la hora de inicio del sistema. El valor del reloj CLOCK_MONOTONIC no se puede establecer mediante clock_settime(). Esta función fallará si se invoca con un argumento clock_id de CLOCK_MONOTONIC.

El efecto de establecer un reloj mediante clock_settime() en temporizadores por proceso armados asociados con un reloj distinto de CLOCK_REALTIME depende de la implementación.

Si el valor del reloj CLOCK_REALTIME se establece mediante clock_settime(), el nuevo valor del reloj se utilizará para determinar el momento en que el sistema despertará a un hilo bloqueado en una llamada clock_nanosleep() absoluta basada en el reloj CLOCK_REALTIME. Si el tiempo absoluto solicitado en la invocación de dicho servicio de tiempo es anterior al nuevo valor del reloj, la llamada retornará inmediatamente como si el reloj hubiera alcanzado el tiempo solicitado normalmente.

Establecer el valor del reloj CLOCK_REALTIME mediante clock_settime() no tendrá ningún efecto en ningún hilo que esté bloqueado en una llamada clock_nanosleep() relativa. En consecuencia, la llamada retornará cuando transcurra el intervalo relativo solicitado, independientemente del valor nuevo o antiguo del reloj.

Los privilegios apropiados para establecer un reloj determinado dependen de la implementación.

Si _POSIX_CPUTIME está definido, las implementaciones admitirán valores de ID de reloj obtenidos invocando clock_getcpuclockid(), que representan el reloj de tiempo de CPU de un proceso dado. Las implementaciones también admitirán el valor especial clockid_t CLOCK_PROCESS_CPUTIME_ID, que representa el reloj de tiempo de CPU del proceso que llama al invocar una de las funciones clock_*() o timer_*(). Para estos IDs de reloj, los valores devueltos por clock_gettime() y especificados por clock_settime() representan la cantidad de tiempo de ejecución del proceso asociado con el reloj. Cambiar el valor de un reloj de tiempo de CPU mediante clock_settime() no tendrá ningún efecto en el comportamiento de la política de programación de servidor esporádico (ver Políticas de Programación).

Si _POSIX_THREAD_CPUTIME está definido, las implementaciones admitirán valores de ID de reloj obtenidos invocando pthread_getcpuclockid(), que representan el reloj de tiempo de CPU de un hilo dado. Las implementaciones también admitirán el valor especial clockid_t CLOCK_THREAD_CPUTIME_ID, que representa el reloj de tiempo de CPU del hilo que llama al invocar una de las funciones clock_*() o timer_*(). Para estos IDs de reloj, los valores devueltos por clock_gettime() y especificados por clock_settime() representarán la cantidad de tiempo de ejecución del hilo asociado con el reloj. Cambiar el valor de un reloj de tiempo de CPU mediante clock_settime() no tendrá ningún efecto en el comportamiento de la política de programación de servidor esporádico (ver Políticas de Programación).

VALOR DE RETORNO

Un valor de retorno de 0 indicará que la llamada tuvo éxito. Un valor de retorno de -1 indicará que ocurrió un error, y errno se establecerá para indicar el error.

ERRORES

Las funciones clock_getres(), clock_gettime() y clock_settime() fallarán si:

EINVAL
El argumento clock_id no especifica un reloj conocido.

La función clock_gettime() fallará si:

EOVERFLOW
El número de segundos no cabe en un objeto de tipo time_t.

La función clock_settime() fallará si:

EINVAL
El argumento tp de clock_settime() está fuera del rango para el ID de reloj dado.
EINVAL
El argumento tp especificó un valor de nanosegundo menor que cero o mayor o igual a 1000 millones.
EINVAL
El valor del argumento clock_id es CLOCK_MONOTONIC.

La función clock_settime() puede fallar si:

EPERM
El proceso solicitante no tiene los privilegios apropiados para establecer el reloj especificado.

USO POR LA APLICACIÓN

Tenga en cuenta que el valor absoluto del reloj monótono no tiene sentido (porque su origen es arbitrario), y por lo tanto no hay necesidad de establecerlo. Además, las aplicaciones en tiempo real pueden confiar en el hecho de que el valor de este reloj nunca se establece y, por lo tanto, que los intervalos de tiempo medidos con

este reloj no se verá afectado por las llamadas a clock_settime().
