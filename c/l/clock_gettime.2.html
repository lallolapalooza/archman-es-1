DESCRIPCIÓ

N

La función clock_getres() encuentra la resolución (precisión) del reloj especificado clockid y, si res no es NULL, la almacena en la struct timespec a la que apunta res. La resolución de los relojes depende de la implementación y no puede ser configurada por un proceso en particular. Si el valor de tiempo al que apunta el argumento tp de clock_settime() no es un múltiplo de res, entonces se trunca a un múltiplo de res

.

Las funciones clock_gettime() y clock_settime() recuperan y establecen el tiempo del reloj especificado clockid

.

Los res y tp argumentos son estructuras timespec

(3).

El clockid argumento es el identificador del reloj particular sobre el que actuar. Un reloj puede ser de todo el sistema y por lo tanto visible para todos los procesos, o por proceso si mide el tiempo solo dentro de un solo

proceso.

Todas las implementaciones soportan el reloj de tiempo real de todo el sistema, que es identificado por CLOCK_REALTIME. Su tiempo representa segundos y nanosegundos desde la Época. Cuando su tiempo es cambiado, los temporizadores para un intervalo relativo no se ven afectados, pero los temporizadores para un punto absoluto en el tiempo sí lo

están.

Pueden implementarse más relojes. La interpretación de los valores de tiempo correspondientes y el efecto en los temporizadores no está

especificado.

Versiones suficientemente recientes de glibc y el kernel de Linux soportan los siguientes

relojes:
CLOCK_REALTI
ME
Un reloj de todo el sistema configurable que mide el tiempo real (es decir, tiempo de reloj de pared). Establecer este reloj requiere privilegios adecuados. Este reloj se ve afectado por saltos discontinuos en el tiempo del sistema (por ejemplo, si el administrador del sistema cambia manualmente el reloj), y por ajustes de frecuencia realizados por NTP y aplicaciones similares a través de adjtime(3), adjtimex(2), clock_adjtime(2), y ntp_adjtime(3). Este reloj normalmente cuenta el número de segundos desde 1970-01-01 00:00:00 Hora Universal Coordinada (UTC) excepto que ignora los segundos bisiestos; cerca de un segundo bisiesto típicamente es ajustado por NTP para mantenerse aproximadamente en sincronía con
UTC.
CLOCK_REALTIME_ALARM (desde Linux 3.0; específico de
Linux)
Como CLOCK_REALTIME, pero no configurable. Ver timer_create(2) para más
detalles.

Linux)
Una versión más rápida pero menos precisa de CLOCK_REALTIME. Este reloj no es configurable. Úsalo cuando necesites marcas de tiempo muy rápidas, pero no de gran precisión. Requiere soporte por arquitectura, y probablemente también soporte de arquitectura para esta bandera en el vdso(
7).

Linux)
Un reloj de todo el sistema no configurable derivado del tiempo de reloj de pared pero contando segundos bisiestos. Este reloj no experimenta discontinuidades ni ajustes de frecuencia causados por la inserción de segundos bisiestos como CLOCK_REALTIME

Establecer el valor del reloj CLOCK_REALTIME a través de clock_settime() no debe tener efecto sobre los hilos que están bloqueados esperando un servicio de tiempo relativo basado en este reloj, incluyendo la función nanosleep(); ni sobre la expiración de temporizadores relativos basados en este reloj. Nota histórica para sistemas

SMP

Antes de que Linux añadiera soporte en el kernel para CLOCK_PROCESS_CPUTIME_ID y CLOCK_THREAD_CPUTIME_ID, glibc implementaba estos relojes en muchas plataformas usando registros de temporizador de las CPUs (TSC en i386, AR.ITC en Itanium). Estos registros pueden diferir entre CPUs y como consecuencia estos relojes pueden devolver resultados falsos si un proceso es migrado a otra

CPU.

Si las CPUs en un sistema SMP tienen diferentes fuentes de reloj, entonces no hay forma de mantener una correlación entre los registros de temporizador ya que cada CPU se ejecutará a una frecuencia ligeramente diferente. Si ese es el caso, entonces clock_getcpuclockid(0) devolverá ENOENT para indicar esta condición. Los dos relojes serán útiles solo si se puede asegurar que un proceso permanece en una CPU

determinada.

Los procesadores en un sistema SMP no arrancan todos exactamente al mismo tiempo y por lo tanto los registros de temporizador típicamente se ejecutan con un desfase. Algunas arquitecturas incluyen código que intenta limitar estos desfases en el arranque. Sin embargo, el código no puede garantizar ajustar con precisión los desfases. glibc no contiene disposiciones para lidiar con estos desfases (a diferencia del Kernel de Linux). Típicamente estos desfases son pequeños y por lo tanto los efectos pueden ser despreciables en la mayoría de los

casos.

Desde glibc 2.4, las funciones envoltorio para las llamadas al sistema descritas en esta página evitan los problemas mencionados anteriormente empleando la implementación en el kernel de CLOCK_PROCESS_CPUTIME_ID y CLOCK_THREAD_CPUTIME_ID, en sistemas que propo

rcionan tal implemen
tación (es decir, Linux
2.6.12 y posteriores).

/* clock_times.c
   Licensed under GNU General Public License v2 or later.
*/
#define _XOPEN_SOURCE 600
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <time.h>
#define SECS_IN_DAY (24 * 60 * 60)
static void
displayClock(clockid_t clock, const char *name, bool showRes)
{
    long             days;
    struct timespec  ts;
    if (clock_gettime(clock, &ts) == -1) {
        perror("clock_gettime");
        exit(EXIT_FAILURE);
    }
    printf("%-15s: %10jd.%03ld (", name,
           (intmax_t) ts.tv_sec, ts.tv_nsec / 1000000);
    days = ts.tv_sec / SECS_IN_DAY;
    if (days > 0)
        printf("%ld días + ", days);
    printf("%2dh %2dm %2ds",
           (int) (ts.tv_sec % SECS_IN_DAY) / 3600,
           (int) (ts.tv_sec % 3600) / 60,
           (int) ts.tv_sec % 60);
    printf(")\n");
    if (clock_getres(clock, &ts) == -1) {
        perror("clock_getres");
        exit(EXIT_FAILURE);
    }
    if (showRes)
        printf("     resolución: %10jd.%09ld\n",
               (intmax_t) ts.tv_sec, ts.tv_nsec);
}
int
main(int argc, char *[])
{
    bool showRes = argc > 1;
    displayClock(CLOCK_REALTIME, "CLOCK_REALTIME", showRes);
#ifdef CLOCK_TAI
    displayClock(CLOCK_TAI, "CLOCK_TAI", showRes);
#endif
    displayClock(CLOCK_MONOTONIC, "CLOCK_MONOTONIC", showRes);
#ifdef CLOCK_BOOTTIME
    displayClock(CLOCK_BOOTTIME, "CLOCK_BOOTTIME", showRes);
#endif
    exit(EXIT_SUCCESS)
;
}
