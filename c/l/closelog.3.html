syslog(3) Manual de Funciones de Biblioteca syslog(3)

NOMBRE

closelog, openlog, syslog, vsyslog - enviar mensajes al registrador del sistema

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <syslog.h>
void openlog(const char *ident, int option, int facility);
void syslog(int priority, const char *format, ...);
void closelog(void);
void vsyslog(int priority, const char *format, va_list ap);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

vsyslog():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE

DESCRIPCIÓN

openlog()

openlog() abre una conexión con el registrador del sistema para un programa.

La cadena a la que apunta ident se antepone a cada mensaje, y normalmente se establece con el nombre del programa. Si ident es NULL, se usa el nombre del programa. (POSIX.1-2008 no especifica el comportamiento cuando ident es NULL.)

El argumento option especifica banderas que controlan la operación de openlog() y las llamadas posteriores a syslog(). El argumento facility establece un valor por defecto que se usará si no se especifica ninguno en las llamadas posteriores a syslog(). Los valores que pueden especificarse para option y facility se describen más abajo.

El uso de openlog() es opcional; será llamado automáticamente por syslog() si es necesario, en cuyo caso ident tendrá NULL como valor por defecto.

syslog() y vsyslog()

syslog() genera un mensaje de registro, que será distribuido por syslogd(8).

El argumento priority se forma combinando mediante OR un valor de facility y un valor de level (descritos más abajo). Si no se combina mediante OR ningún valor de facility en priority, se usa el valor por defecto establecido por openlog() o, si no hubo una llamada previa a openlog(), se emplea LOG_USER como valor por defecto.

Los argumentos restantes son un format, como en printf(3), y cualquier argumento requerido por el format, excepto que la secuencia de dos caracteres %m será reemplazada por la cadena de mensaje de error strerror(errno). La cadena de formato no necesita incluir un carácter de salto de línea final.

La función vsyslog() realiza la misma tarea que syslog() con la diferencia de que toma un conjunto de argumentos que han sido obtenidos usando las macros de lista de argumentos variables stdarg(3) .

closelog()

closelog() cierra el descriptor de archivo que se está usando para escribir en el registrador del sistema. El uso de closelog() es opcional.

Valores para option

El argumento option de openlog() es una máscara de bits construida combinando mediante OR cualquiera de los siguientes valores:

LOG_CONS
Escribir directamente en la consola del sistema si hay un error al enviar al registrador del sistema.
LOG_NDELAY
Abrir la conexión inmediatamente (normalmente, la conexión se abre cuando se registra el primer mensaje). Esto puede ser útil, por ejemplo, si un posterior chroot(2) haría que la ruta de acceso usada internamente por la funcionalidad de registro fuera inaccesible.
LOG_NOWAIT
No esperar a los procesos hijos que puedan haber sido creados mientras se registraba el mensaje. (La biblioteca C de GNU no crea un proceso hijo, así que esta opción no tiene efecto en Linux.)
LOG_ODELAY
Lo contrario de LOG_NDELAY; la apertura de la conexión se retrasa hasta que se llama a syslog(). (Este es el valor por defecto, y no necesita especificarse.)
LOG_PERROR
(No está en POSIX.1-2001 ni en POSIX.1-2008.) Registrar también el mensaje en stderr.
LOG_PID
Incluir el PID del llamador con cada mensaje.

Valores para facility

El argumento facility se usa para especificar qué tipo de programa está registrando el mensaje. Esto permite que el archivo de configuración especifique que los mensajes de diferentes instalaciones se manejarán de forma diferente.

LOG_AUTH
mensajes de seguridad/autorización
LOG_AUTHPRIV
mensajes de seguridad/autorización (privados)
LOG_CRON
demonio de reloj (cron y at)
LOG_DAEMON
demonios del sistema sin valor de instalación separado
LOG_FTP
demonio ftp
LOG_KERN
mensajes del núcleo (estos no pueden ser generados por procesos de usuario)
LOG_LOCAL0 a través de LOG_LOCAL7
reservados para uso local
LOG_LPR
subsistema de impresora de línea
LOG_MAIL
subsistema de correo
LOG_NEWS
subsistema de noticias USENET
LOG_SYSLOG
mensajes generados internamente por syslogd(8)
LOG_USER (por defecto)
mensajes genéricos a nivel de usuario
LOG_UUCP
subsistema UUCP

Valores para level

Esto determina la importancia del mensaje. Los niveles son, en orden de importancia decreciente:

LOG_EMERG
el sistema es inutilizable
LOG_ALERT
se debe tomar acción inmediatamente
LOG_CRIT
condiciones críticas
LOG_ERR
condiciones de error
LOG_WARNING
condiciones de advertencia
LOG_NOTICE
condición normal, pero significativa
LOG_INFO
mensaje informativo
LOG_DEBUG
mensaje de nivel de depuración

La función setlogmask(3) puede usarse para restringir el registro a niveles específicos solamente.

HISTORIA

syslog()
4.2BSD, SUSv2, POSIX.1-2001.
openlog()
closelog()
4.3BSD, SUSv2, POSIX.1-2001.
vsyslog()
4.3BSD-Reno.

POSIX.1-2001 especifica únicamente los valores LOG_USER y LOG_LOCAL* para facility. Sin embargo, con la excepción de LOG_AUTHPRIV y LOG_FTP, los otros valores de facility aparecen en la mayoría de los sistemas UNIX.

El valor LOG_PERROR para option no está especificado por POSIX.1-2001 ni por POSIX.1-2008, pero está disponible en la mayoría de las versiones de UNIX.

NOTAS

El argumento ident en la llamada de openlog() probablemente se almacena tal cual. Por lo tanto, si se cambia la cadena a la que apunta, es posible que syslog() comience a anteponer la cadena modificada, y si la cadena a la que apunta deja de existir, el resultado es indefinido. Lo más portable es usar una cadena constante.

Nunca pase una cadena con datos proporcionados por el usuario como formato; use en su lugar lo siguiente:


syslog(priority, "%s", string);

VÉASE TAMBIÉN
