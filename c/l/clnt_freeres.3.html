rpc(3) Manual de Funciones de Biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS Y DESCRIPCIÓN

Estas rutinas permiten a los programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de despacho para realizar el servicio solicitado, y luego envía de vuelta una respuesta. Finalmente, la llamada al procedimiento retorna al cliente.

Para hacer uso de estas rutinas, incluya el archivo de cabecera <rpc/rpc.h>.

Los prototipos siguientes hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Vea los archivos de cabecera para las declaraciones de los AUTH, CLIENT, SVCXPRT, y XDR tipos.

void auth_destroy(AUTH *auth);
Una macro que destruye la información de autenticación asociada con auth. La destrucción generalmente implica la desasignación de estructuras de datos privadas. El uso de auth es indefinido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y retorna un identificador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación predeterminada utilizada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y retorna un identificador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario del usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a un array contado de grupos a los que el usuario pertenece. Es fácil suplantar a un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnum, y procnum en la máquina, host. El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección de dónde colocar el/los resultado(s); inproc se usa para codificar los parámetros del procedimiento, y outproc se usa para decodificar los resultados del procedimiento. Esta rutina retorna cero si tiene éxito, o el valor de enum clnt_stat convertido a un entero si falla. La rutina clnt_perrno() es útil para traducir estados de fallo en mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina usa UDP/IP como transporte; vea clntudp_create() para las restricciones. Usted no tiene control de los tiempos de espera o de la autenticación usando esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Como callrpc(), excepto que el mensaje de llamada se transmite a todas las redes de difusión localmente conectadas. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es lo mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto es decodificada allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() retorna cero, clnt_broadcast() espera más respuestas; de lo contrario retorna con el estado apropiado.
Advertencia: los sockets de difusión están limitados en tamaño a la unidad máxima de transferencia del enlace de datos. Para ethernet, este valor es de 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Una macro que llama al procedimiento remoto procnum asociado con el identificador de cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección de dónde colocar el/los resultado(s); inproc se usa para codificar los parámetros del procedimiento, y outproc se usa para decodificar los resultados del procedimiento; tout es el tiempo permitido para que los resultados regresen.
clnt_destroy(CLIENT *clnt);
Una macro que destruye el identificador RPC del cliente. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluyendo clnt mismo. El uso de clnt es indefinido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanecerá abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte usar. Los valores soportados actualmente para este campo son “udp” y “tcp”. Los tiempos de espera predeterminados están establecidos, pero pueden modificarse usando clnt_control().
Advertencia: usar UDP tiene sus deficiencias. Dado que los mensajes RPC basados en UDP pueden contener solo hasta 8 Kbytes de datos codificados, este transporte no puede usarse para procedimientos que toman argumentos grandes o retornan resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Una macro usada para cambiar o recuperar varios tipos de información sobre un objeto cliente. req indica el tipo de operación, y info es un puntero a la información. Tanto para UDP como para TCP, los valores soportados de req y sus tipos de argumentos y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo de espera total
CLGET_TIMEOUT  struct timeval // obtener tiempo de espera total

Nota: si usted establece el tiempo de espera usando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() será ignorado en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener la dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer el tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener el tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que "UDP RPC" espera para que el servidor responda antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los resultados de una llamada RPC. El parámetro out es la dirección de los resultados, y outproc es la rutina XDR que describe los resultados. Esta rutina retorna uno si los resultados fueron liberados exitosamente, y cero en caso contrario.
void clnt_geterr(CLIENT *clnt, struct rpc_err *errp);
Una macro que copia la estructura del error del manejador del cliente a la estructura en la dirección errp.
void clnt_pcreateerror(const char *s);
Imprime un mensaje en el error estándar indicando por qué no se pudo crear un manejador de cliente RPC. Al mensaje se le antepone la cadena s y dos puntos. Se usa cuando una llamada a clnt_create(), clntraw_create(), clnttcp_create(), o clntudp_create() falla.
void clnt_perrno(enum clnt_stat stat);
Imprime un mensaje en el error estándar correspondiente a la condición indicada por stat. Se usa después de callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Imprime un mensaje en el error estándar indicando por qué falló una llamada RPC; clnt es el manejador utilizado para hacer la llamada. Al mensaje se le antepone la cadena s y dos puntos. Se usa después de clnt_call().
char *clnt_spcreateerror(const char *s);
Igual que clnt_pcreateerror(), excepto que devuelve una cadena en lugar de imprimir en el error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescribe en cada llamada.
char *clnt_sperrno(enum clnt_stat stat);
Toma los mismos argumentos que clnt_perrno(), pero en lugar de enviar un mensaje al error estándar indicando por qué falló una llamada RPC, devuelve un puntero a una cadena que contiene el mensaje. La cadena termina con un NUEVO SALTO DE LÍNEA.
clnt_sperrno() se usa en lugar de clnt_perrno() si el programa no tiene un error estándar (como un programa que se ejecuta como servidor probablemente no lo tiene), o si el programador no quiere que el mensaje se emita con printf(3), o si se va a usar un formato de mensaje diferente al soportado por clnt_perrno(). Nota: a diferencia de clnt_sperror() y clnt_spcreateerror(), clnt_sperrno() devuelve un puntero a datos estáticos, pero el resultado no se sobrescribirá en cada llamada.
char *clnt_sperror(CLIENT *rpch, const char *s);
Igual que clnt_perror(), excepto que (igual que clnt_sperrno()) devuelve una cadena en lugar de imprimir en el error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescribe en cada llamada.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Esta rutina crea un cliente RPC de juguete para el programa remoto prognum, versión versnum. El transporte utilizado para pasar mensajes al servicio es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el servidor RPC correspondiente debe vivir en el mismo espacio de direcciones; ver svcraw_create(). Esto permite la simulación de RPC y la obtención de sobrecostos de RPC, como tiempos de ida y vuelta, sin ninguna interferencia del kernel. Esta rutina devuelve NULL si falla.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente usa TCP/IP como transporte. El programa remoto se encuentra en la dirección de Internet *addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta al servicio remoto portmap para esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. Dado que el RPC basado en TCP usa E/S con búfer, el usuario puede especificar el tamaño de los búferes de envío y recepción con los parámetros sendsz y recvsz; los valores de cero eligen valores predeterminados adecuados. Esta rutina devuelve NULL si falla.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente usa UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta al servicio remoto portmap para esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de la llamada en intervalos de tiempo de wait hasta que se recibe una respuesta o hasta que la llamada expira. El tiempo total para que la llamada expire lo especifica clnt_call().
Advertencia: dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede usar para procedimientos que tomen argumentos grandes o devuelvan resultados enormes.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Esta rutina crea un cliente RPC para el programa remoto prognum, en versnum; el cliente usa UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta al servicio remoto portmap para esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de la llamada en intervalos de tiempo de wait hasta que se recibe una respuesta o hasta que la llamada expira. El tiempo total para que la llamada expire lo especifica clnt_call().
Esto permite al usuario especificar el tamaño máximo de paquete para enviar y recibir mensajes RPC basados en UDP.
void get_myaddress(struct sockaddr_in *addr);
Introduce la dirección IP de la máquina en *addr, sin consultar las rutinas de biblioteca que tratan /etc/hosts. El número de puerto se establece siempre en htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Una interfaz de usuario para el servicio portmap , que devuelve una lista de las asignaciones actuales de programa RPC a puerto en el host ubicado en la dirección IP *addr. Esta rutina puede devolver NULL. El comando rpcinfo -p usa esta rutina.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Una interfaz de usuario para el servicio portmap , que devuelve el número de puerto en el que espera un servicio que soporta el número de programa prognum, versión versnum, y habla el protocolo de transporte asociado con protocol. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Un valor de retorno de cero significa que la asignación no existe o que el sistema RPC falló al contactar al servicio remoto portmap . En este último caso, la variable global rpc_createerr contiene el estado del RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Una interfaz de usuario para el servicio portmap , que instruye a portmap en el host en la dirección IP *addr para que haga una llamada RPC en su nombre a un procedimiento en ese host. El parámetro *portp se modificará al número de puerto del programa si el procedimiento tiene éxito. Las definiciones de otros parámetros se discuten en callrpc() y clnt_call(). Este procedimiento debe usarse para un "ping" y nada más. Ver también clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);
Una interfaz de usuario para el servicio portmap , que establece una asignación entre la tripleta [prognum,versnum,protocol] y port en el servicio portmap de la máquina. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Esta rutina devuelve uno si tiene éxito, cero en caso contrario. Se hace automáticamente por svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Una interfaz de usuario para el servicio portmap , que destruye todas las asignaciones entre la tripleta [prognum,versnum,*] y puertos en el servicio portmap de la máquina. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Registra el procedimiento procname con el paquete de servicio RPC. Si llega una solicitud para el programa prognum, versión versnum, y procedimiento procnum, procname se llama con un puntero a su(s) parámetro(s); procname debería devolver un puntero a su(s) resultado(s) estático(s); inproc se usa para decodificar los parámetros mientras outproc se usa para codificar los resultados. Esta rutina devuelve cero si el registro tuvo éxito, -1 en caso contrario.
Advertencia: los procedimientos remotos registrados en esta forma se acceden usando el transporte UDP/IPdeporte; ver svcudp_create () para las restriccione

void xprt_register(SVCXPRT *xprt);
Después de que se crean los manejadores de transporte de servicio RPC, estos deben registrarse con el paquete de servicio RPC. Esta rutina modifica la variable global svc_fds. Los implementadores de servicios generalmente no necesitan esta rutina.
void xprt_unregister(SVCXPRT *xprt);
Antes de que se destruya un manejador de transporte de servicio RPC, este debe desregistrarse con el paquete de servicio RPC. Esta rutina modifica la variable global svc_fds. Los implementadores de servicios generalmente no necesitan esta rutina.
