clnt_create()






Este comando crea un mango de cliente RPC genérico para el programa remoto
prognum, versión versnum; el cliente usa un transporte
definido por el usuario. El programa remoto se encuentra en la dirección de Internet
*addr. Si addr->sin_port es cero, entonces se establece
en el puerto real en el que el programa remoto está escuchando (se consulta al
servicio portmap remoto para esta información). El parámetro sockp
es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece
sockp. La llamada usa el transporte especificado por el parámetro
type. El parámetro timeout especifica el tiempo de espera
para las llamadas, mientras que el parámetro udptimesout especifica
el número de retransmisiones para las llamadas UDP. Esta rutina devuelve NULL si falla.




void clnt_pcreateerror(const char *s);






Imprime un mensaje en el error estándar indicando por qué no se pudo crear un
mango RPC de cliente. El mensaje va precedido por la cadena s y dos
puntos. Se usa cuando falla una llamada a clnt_create(),
clntraw_create(), clnttcp_create() o clntudp_create().




void clnt_perrno(enum clnt_stat stat);






Imprime un mensaje en el error estándar correspondiente a la condición indicada
por stat. Se usa después de callrpc().




clnt_perror(CLIENT *clnt, const char *s);






Imprime un mensaje en el error estándar indicando por qué falló una llamada RPC;
clnt es el mango utilizado para realizar la llamada. El mensaje va precedido
por la cadena s y dos puntos. Se usa después de clnt_call().




char *clnt_spcreateerror(const char *s);






Similar a clnt_pcreateerror(), excepto que devuelve una cadena en lugar
de imprimir en el error estándar.




Errores: devuelve un puntero a datos estáticos que se sobrescribe en cada
llamada.




char *clnt_sperrno(enum clnt_stat stat);






Toma los mismos argumentos que clnt_perrno(), pero en lugar de enviar un
mensaje al error estándar indicando por qué falló una llamada RPC, devuelve un
puntero a una cadena que contiene el mensaje. La cadena termina con una nueva
línea.




clnt_sperrno() se usa en lugar de clnt_perrno() si el
programa no tiene un error estándar (como es muy probable que no lo tenga un
programa que se ejecuta como servidor), o si el programador no desea que el
mensaje se imprima con printf(3), o si se va a usar un formato de mensaje
diferente al admitido por clnt_perrno(). Nota: a diferencia de
clnt_sperror() y clnt_spcreateerror(),
clnt_sperrno() devuelve un puntero a datos estáticos, pero el resultado
no se sobrescribirá en cada llamada.




char *clnt_sperror(CLIENT *rpch, const char *s);






Similar a clnt_perror(), excepto que (como clnt_sperrno())
devuelve una cadena en lugar de imprimir en el error estándar.




Errores: devuelve un puntero a datos estáticos que se sobrescribe en cada
llamada.




CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);






Esta rutina crea un cliente RPC de juguete para el programa remoto
prognum, versión versnum. El transporte utilizado para pasar
mensajes al servicio es en realidad un búfer dentro del espacio de direcciones
del proceso, por lo que el servidor RPC correspondiente debe residir en el mismo
espacio de direcciones; consulte svcraw_create(). Esto permite la
simulación de RPC y la adquisición de sobrecargas de RPC, como los tiempos de
ida y vuelta, sin ninguna intervención del kernel. Esta rutina devuelve NULL si
falla.




CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);






Esta rutina crea un cliente RPC para el programa remoto prognum,
versión versnum; el cliente utiliza TCP/IP como transporte. El programa remoto
se encuentra en la dirección de Internet *addr. Si
addr->sin_port es cero, entonces se establece en el puerto real en el que
el programa remoto está escuchando (se consulta al servicio portmap remoto
para esta información). El parámetro sockp es un socket; si es
RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece
sockp. Dado que RPC basado en TCP utiliza E/S con búfer, el usuario puede
especificar el tamaño de los búferes de envío y recepción con los parámetros
sendsz y recvsz; los valores de cero eligen valores predeterminados
adecuados. Esta rutina devuelve NULL si falla.




CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);






Esta rutina crea un cliente RPC para el programa remoto prognum,
versión versnum; el cliente utiliza UDP/IP como transporte. El programa remoto
se encuentra en la dirección de Internet addr. Si
addr->sin_port es cero, entonces se establece en el puerto real en el que
el programa remoto está escuchando (se consulta al servicio portmap remoto
para esta información). El parámetro sockp es un socket; si es
RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece
sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de
tiempo wait hasta que se recibe una respuesta o hasta que la llamada
expira. El tiempo total para que la llamada expire se especifica mediante
clnt_call().




Advertencia: dado que los mensajes RPC basados en UDP solo pueden contener hasta 8
Kbytes de datos codificados, este transporte no se puede utilizar para
procedimientos que aceptan argumentos grandes o devuelven resultados enormes.




CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);






Esta rutina crea un cliente RPC para el programa remoto prognum,
en versnum; el cliente utiliza UDP/IP como transporte. El programa remoto
se encuentra en la dirección de Internet addr. Si
addr->sin_port es cero, entonces se establece en el puerto real en el que
el programa remoto está escuchando (se consulta al servicio portmap remoto
para esta información). El parámetro sockp es un socket; si es
RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece
sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de
tiempo wait hasta que se recibe una respuesta o hasta que la llamada
expira. El tiempo total para que la llamada expire se especifica mediante
clnt_call().




Esto permite al usuario especificar el tamaño máximo del paquete para enviar y
recibir mensajes RPC basados en UDP.




void get_myaddress(struct sockaddr_in *addr);






Coloca la dirección IP de la máquina en *addr, sin consultar las
rutinas de la biblioteca que manejan /etc/hosts. El número de puerto
siempre se establece en htons(PMAPPORT).




struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);






Una interfaz de usuario para el servicio portmap, que devuelve una lista
de las asignaciones actuales de programa RPC a puerto en el host ubicado en la
dirección IP *addr. Esta rutina puede devolver NULL. El comando
rpcinfo -p utiliza esta rutina.




unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);






Una interfaz de usuario para el servicio portmap, que devuelve el número
de puerto en el que espera un servicio que admita el número de programa
prognum, versión versnum y que hable el protocolo de transporte
asociado con protocol. El valor de protocol es muy probablemente
IPPROTO_UDP o IPPROTO_TCP. Un valor de retorno de cero
significa que la asignación no existe o que el sistema RPC no pudo contactar con
el servicio portmap remoto. En este último caso, la variable global
rpc_createerr contiene el estado RPC.




enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);






Una interfaz de usuario para el servicio portmap, que instruye al
portmap en el host de la dirección IP *addr para que realice una llamada RPC
en su nombre a un procedimiento en ese host. El parámetro *portp se modificará
al número de puerto del programa si el procedimiento tiene éxito. Las definiciones de
otros parámetros se discuten en callrpc() y
clnt_call(). Este procedimiento debe usarse para un
"ping" y nada más. Consulte también
clnt_broadcast().




bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);






Una interfaz de usuario para el servicio portmap, que establece una
asignación entre el triple [prognum,versnum,protocol]
y port en el servicio portmap de la máquina. El valor de
protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP.
Esta rutina devuelve uno si tiene éxito, cero en caso contrario. Se realiza
automáticamente mediante svc_register().




bool_t pmap_unset(unsigned long prognum, unsigned long versnum);






Una interfaz de usuario para el servicio portmap, que destruye todas las
asignaciones entre el triple [prognum,versnum,*] y
los puertos en el servicio portmap de la máquina. Esta rutina devuelve
uno si tiene éxito, cero en caso contrario.




int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);






Registra el procedimiento procname con el paquete de servicios RPC. Si
llega una solicitud para el programa prognum, versión versnum y
procedimiento procnum, se llama a procname con un puntero a sus
parámetros; procname debe devolver un puntero a sus resultados estáticos;
inproc se usa para decodificar los parámetros mientras que outproc
se usa para codificar los resultados. Esta rutina devuelve cero si el registro
tuvo éxito, -1 en caso contrario.




Advertencia: los procedimientos remotos registrados de esta forma se acceden
utilizando el transporte UDP/IP




port; ver svcudp_create() para restricciones.


struct rpc_createerr rpc_createerr;



  

  
Una variable global cuyo valor se establece por cualquier rutina de creación de cliente RPC que no tenga éxito. Utilice la rutina clnt_pcreateerror() para imprimir la razón por la cual.




void svc_destroy(SVCXPRT *xprt);



  

  
Una macro que destruye el manejador de transporte del servicio RPC, xprt. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluyendo xprt en sí. El uso de xprt no está definido después de llamar a esta rutina.




fd_set svc_fdset;



  

  
Una variable global que refleja la máscara de bits del descriptor de archivo de lectura del lado del servicio RPC; es adecuada como parámetro para la llamada al sistema select(2). Esto solo es de interés si un implementador de servicio realiza su propio procesamiento de eventos asíncronos, en lugar de llamar a svc_run(). Esta variable es de solo lectura (¡no pase su dirección a select(2)!), sin embargo, puede cambiar después de las llamadas a svc_getreqset() o a cualquier rutina de creación.




int svc_fds;



  

  
Similar a svc_fdset, pero limitado a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_fdset.




svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);



  

  
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los argumentos a un procedimiento de servicio usando svc_getargs(). Esta rutina devuelve 1 si los resultados se liberaron con éxito y cero en caso contrario.




svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);



  

  
Una macro que decodifica los argumentos de una solicitud RPC asociada con el manejador de transporte del servicio RPC, xprt. El parámetro in es la dirección donde se colocarán los argumentos; inproc es la rutina XDR utilizada para decodificar los argumentos. Esta rutina devuelve uno si la decodificación tiene éxito y cero en caso contrario.




struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);



  

  
La forma aprobada de obtener la dirección de red del llamador de un procedimiento asociado con el manejador de transporte del servicio RPC, xprt.




void svc_getreqset(fd_set *rdfds);



  

  
Esta rutina solo es de interés si un implementador de servicio no llama a svc_run(), sino que implementa un procesamiento de eventos asíncronos personalizado. Se llama cuando la llamada al sistema select(2) ha determinado que ha llegado una solicitud RPC en uno o más sockets RPC; rdfds es la máscara de bits resultante del descriptor de archivo de lectura. La rutina devuelve cuando todos los sockets asociados con el valor de rdfds han sido atendidos.




void svc_getreq(int rdfds);



  

  
Similar a svc_getreqset(), pero limitado a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_getreqset().




bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);



  

  
Asocia prognum y versnum con el procedimiento de despacho del servicio, dispatch. Si protocol es cero, el servicio no se registra con el servicio portmap. Si protocol no es cero, entonces se establece un mapeo del triple [prognum,versnum,protocol] a xprt->xp_port con el servicio portmap local (generalmente protocol es cero, IPPROTO_UDP o IPPROTO_TCP). El procedimiento dispatch tiene la siguiente forma:

  

  

    

    
dispatch(struct svc_req *request, SVCXPRT *xprt);


    

  

  

  
La rutina svc_register() devuelve uno si tiene éxito y cero en caso contrario.




void svc_run(void);



  

  
Esta rutina nunca devuelve. Espera a que lleguen las solicitudes RPC y llama al procedimiento de servicio apropiado usando svc_getreq() cuando llega una. Este procedimiento generalmente está esperando que una llamada al sistema select(2) devuelva.




bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);



  

  
Llamada por la rutina de despacho de un servicio RPC para enviar los resultados de una llamada a un procedimiento remoto. El parámetro xprt es el manejador de transporte asociado con la solicitud; outproc es la rutina XDR que se utiliza para codificar los resultados; y out es la dirección de los resultados. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.




void svc_unregister(unsigned long prognum, unsigned long versnum);



  

  
Elimina todos los mapeos del doble [prognum,versnum] a las rutinas de despacho, y del triple [prognum,versnum,*] al número de puerto.




void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);



  

  
Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a un procedimiento remoto debido a un error de autenticación.




void svcerr_decode(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio que no puede decodificar sus parámetros con éxito. Ver también svc_getargs().




void svcerr_noproc(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio que no implementa el número de procedimiento que solicita el llamador.




void svcerr_noprog(SVCXPRT *xprt);



  

  
Se llama cuando el programa deseado no está registrado con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.




void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);



  

  
Se llama cuando la versión deseada de un programa no está registrada con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.




void svcerr_systemerr(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio cuando detecta un error del sistema no cubierto por ningún protocolo particular. Por ejemplo, si un servicio ya no puede asignar almacenamiento, puede llamar a esta rutina.




void svcerr_weakauth(SVCXPRT *xprt);



  

  
Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a un procedimiento remoto debido a parámetros de autenticación insuficientes. La rutina llama a svcerr_auth(xprt, AUTH_TOOWEAK).




SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);



  

  
Crea un servicio sobre cualquier descriptor de archivo abierto. Típicamente, este descriptor de archivo es un socket conectado para un protocolo de transmisión como TCP. sendsize y recvsize indican los tamaños para los búferes de envío y recepción. Si son cero, se elige un valor predeterminado razonable.




SVCXPRT *svcraw_create(void);



  

  
Esta rutina crea un transporte de servicio RPC de juguete, al que devuelve un puntero. El transporte es realmente un búfer dentro del espacio de direcciones del proceso, por lo que el cliente RPC correspondiente debería residir en el mismo espacio de direcciones; ver clntraw_create(). Esta rutina permite simular RPC y adquirir sobrecargas RPC (como tiempos de ida y vuelta), sin ninguna interferencia del kernel. Esta rutina devuelve NULL si falla.




SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);



  

  
Esta rutina crea un transporte de servicio RPC basado en TCP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto TCP local, esta rutina lo enlaza a un puerto arbitrario. Al finalizar, xprt->xp_sock es el descriptor del socket del transporte, y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla. Dado que RPC basado en TCP utiliza E/S en búfer, los usuarios pueden especificar el tamaño de los búferes; los valores cero eligen valores predeterminados adecuados.




SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);



  

  
Esta rutina crea un transporte de servicio RPC basado en UDP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto UDP local, esta rutina lo enlaza a un puerto arbitrario. Al finalizar, xprt->xp_sock es el descriptor del socket del transporte, y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla.

  

  
Esto permite al usuario especificar el tamaño máximo de paquete para enviar y recibir mensajes RPC basados en UDP.




SVCXPRT *svcudp_create(int sock);



  

  
Esta llamada es equivalente a svcudp_bufcreate(sock,SZ,SZ) para algún tamaño predeterminado SZ.
