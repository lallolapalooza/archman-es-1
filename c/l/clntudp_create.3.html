rpc(3) Manual de Funciones de Biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS Y DESCRIPCIÓN

Estas rutinas permiten a los programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de despacho para realizar el servicio solicitado, y luego envía una respuesta de vuelta. Finalmente, la llamada al procedimiento retorna al cliente.

Para hacer uso de estas rutinas, incluya el archivo de cabecera <rpc/rpc.h>.

Los prototipos siguientes hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Vea los archivos de cabecera para las declaraciones de los tipos AUTH, CLIENT, SVCXPRT, y XDR .

void auth_destroy(AUTH *auth);
Un macro que destruye la información de autenticación asociada con auth. La destrucción usualmente implica la desasignación de estructuras de datos privadas. El uso de auth es indefinido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y retorna un identificador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación por defecto usada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y retorna un identificador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario del usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a un array contado de grupos a los que pertenece el usuario. Es fácil suplantar a un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnumy procnum en la máquina, host. El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección donde colocar los resultados; inproc se usa para codificar los parámetros del procedimiento, y outproc se usa para decodificar los resultados del procedimiento. Esta rutina retorna cero si tiene éxito, o el valor de enum clnt_stat convertido a entero si falla. La rutina clnt_perrno() es útil para traducir estados de fallo en mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina usa UDP/IP como transporte; vea clntudp_create() para las restricciones. Usted no tiene control sobre los tiempos de espera o la autenticación usando esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Como callrpc(), excepto que el mensaje de llamada se transmite por difusión a todas las redes de difusión conectadas localmente. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es lo mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto se decodifica allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() retorna cero, clnt_broadcast() espera más respuestas; de lo contrario retorna con el estado apropiado.
Advertencia: los sockets de difusión están limitados en tamaño a la unidad máxima de transferencia del enlace de datos. Para ethernet, este valor es de 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Un macro que llama al procedimiento remoto procnum asociado con el identificador de cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección donde colocar los resultados; inproc se usa para codificar los parámetros del procedimiento, y outproc se usa para decodificar los resultados del procedimiento; tout es el tiempo permitido para que los resultados regresen.
clnt_destroy(CLIENT *clnt);
Un macro que destruye el identificador RPC del cliente. La destrucción usualmente implica la desasignación de estructuras de datos privadas, incluyendo clnt mismo. El uso de clnt es indefinido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanece abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte usar. Los valores soportados actualmente para este campo son “udp” y “tcp”. Los tiempos de espera por defecto están establecidos, pero pueden modificarse usando clnt_control().
Advertencia: usar UDP tiene sus deficiencias. Dado que los mensajes RPC basados en UDP pueden contener solo hasta 8 Kbytes de datos codificados, este transporte no puede usarse para procedimientos que tomen argumentos grandes o retornen resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Un macro usado para cambiar o recuperar varios tipos de información sobre un objeto cliente. req indica el tipo de operación, y info es un puntero a la información. Tanto para UDP como para TCP, los valores soportados de req y sus tipos de argumentos y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo de espera total
CLGET_TIMEOUT  struct timeval // obtener tiempo de espera total

Nota: si usted establece el tiempo de espera usando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() será ignorado en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener la dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer el tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener el tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que "UDP RPC" espera a que el servidor responda antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Un macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los resultados de una llamada RPC. El parámetro out es la dirección de los resultados, y outproc es la rutina XDR que describe los resultados. Esta rutina retorna uno si los resultados fueron liberados exitosamente, y cero en caso contrario.

struct rpc_createerr rpc_createerr;



  

  
Una variable global cuyo valor es establecido por cualquier rutina de creación de cliente RPC que no tenga éxito. Utilice la rutina clnt_pcreateerror() para imprimir la razón.




void svc_destroy(SVCXPRT *xprt);



  

  
Una macro que destruye el manejador de transporte del servicio RPC, xprt. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluido el propio xprt. El uso de xprt no está definido después de llamar a esta rutina.




fd_set svc_fdset;



  

  
Una variable global que refleja la máscara de bits del descriptor de archivo de lectura del lado del servicio RPC; es adecuada como parámetro para la llamada del sistema select(2). Esto solo es de interés si un implementador de servicio realiza su propio procesamiento de eventos asíncrono, en lugar de llamar a svc_run(). Esta variable es de solo lectura (¡no pase su dirección a select(2)!), sin embargo, puede cambiar después de las llamadas a svc_getreqset() o a cualquier rutina de creación.




int svc_fds;



  

  
Similar a svc_fdset, pero limitado a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_fdset.




svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);



  

  
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los argumentos de un procedimiento de servicio utilizando svc_getargs(). Esta rutina devuelve 1 si los resultados se liberaron correctamente y cero en caso contrario.




svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);



  

  
Una macro que decodifica los argumentos de una solicitud RPC asociada con el manejador de transporte del servicio RPC, xprt. El parámetro in es la dirección donde se colocarán los argumentos; inproc es la rutina XDR utilizada para decodificar los argumentos. Esta rutina devuelve uno si la decodificación tiene éxito y cero en caso contrario.




struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);



  

  
La forma aprobada de obtener la dirección de red del llamador de un procedimiento asociado con el manejador de transporte del servicio RPC, xprt.




void svc_getreqset(fd_set *rdfds);



  

  
Esta rutina solo es de interés si un implementador de servicio no llama a svc_run(), sino que implementa su propio procesamiento de eventos asíncronos. Se llama cuando la llamada del sistema select(2) ha determinado que ha llegado una solicitud RPC en algún(os) socket(s) RPC; rdfds es la máscara de bits resultante del descriptor de archivo de lectura. La rutina devuelve cuando todos los sockets asociados con el valor de rdfds han sido atendidos.




void svc_getreq(int rdfds);



  

  
Similar a svc_getreqset(), pero limitada a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_getreqset().




bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);



  

  
Asocia prognum y versnum con el procedimiento de despacho de servicio, dispatch. Si protocol es cero, el servicio no se registra con el servicio portmap. Si protocol es distinto de cero, entonces se establece un mapeo del triple [prognum,versnum,protocol] a xprt->xp_port con el servicio local portmap (generalmente protocol es cero, IPPROTO_UDP o IPPROTO_TCP). El procedimiento dispatch tiene la siguiente forma:

  

  

    

    
dispatch(struct svc_req *request, SVCXPRT *xprt);


    

  

  

  
La rutina svc_register() devuelve uno si tiene éxito y cero en caso contrario.




void svc_run(void);



  

  
Esta rutina nunca devuelve. Espera a que lleguen solicitudes RPC y llama al procedimiento de servicio apropiado usando svc_getreq() cuando llega una. Este procedimiento generalmente está esperando que una llamada del sistema select(2) devuelva.




bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);



  

  
Llamado por la rutina de despacho de un servicio RPC para enviar los resultados de una llamada a procedimiento remoto. El parámetro xprt es el manejador de transporte asociado con la solicitud; outproc es la rutina XDR que se utiliza para codificar los resultados; y out es la dirección de los resultados. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.




void svc_unregister(unsigned long prognum, unsigned long versnum);



  

  
Elimina todos los mapeos del doble [prognum,versnum] a los procedimientos de despacho, y del triple [prognum,versnum,*] al número de puerto.




void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);



  

  
Llamado por una rutina de despacho de servicio que se niega a realizar una llamada a procedimiento remoto debido a un error de autenticación.




void svcerr_decode(SVCXPRT *xprt);



  

  
Llamado por una rutina de despacho de servicio que no puede decodificar sus parámetros correctamente. Ver también svc_getargs().




void svcerr_noproc(SVCXPRT *xprt);



  

  
Llamado por una rutina de despacho de servicio que no implementa el número de procedimiento que solicita el llamador.




void svcerr_noprog(SVCXPRT *xprt);



  

  
Llamado cuando el programa deseado no está registrado con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.




void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);



  

  
Llamado cuando la versión deseada de un programa no está registrada con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.




void svcerr_systemerr(SVCXPRT *xprt);



  

  
Llamado por una rutina de despacho de servicio cuando detecta un error del sistema que no está cubierto por ningún protocolo particular. Por ejemplo, si un servicio ya no puede asignar almacenamiento, puede llamar a esta rutina.




void svcerr_weakauth(SVCXPRT *xprt);



  

  
Llamado por una rutina de despacho de servicio que se niega a realizar una llamada a procedimiento remoto debido a parámetros de autenticación insuficientes. La rutina llama a svcerr_auth(xprt, AUTH_TOOWEAK).




SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);



  

  
Crea un servicio sobre cualquier descriptor de archivo abierto. Típicamente, este descriptor de archivo es un socket conectado para un protocolo de flujo como TCP. sendsize y recvsize indican los tamaños de los búferes de envío y recepción. Si son cero, se elige un valor predeterminado razonable.




SVCXPRT *svcraw_create(void);



  

  
Esta rutina crea un transporte de servicio RPC de juguete, al que devuelve un puntero. El transporte es realmente un búfer dentro del espacio de direcciones del proceso, por lo que el cliente RPC correspondiente debería residir en el mismo espacio de direcciones; ver clntraw_create(). Esta rutina permite simular RPC y adquirir sobrecargas RPC (como tiempos de ida y vuelta), sin ninguna interferencia del kernel. Esta rutina devuelve NULL si falla.




SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);



  

  
Esta rutina crea un transporte de servicio RPC basado en TCP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto TCP local, esta rutina lo enlaza a un puerto arbitrario. Al finalizar, xprt->xp_sock es el descriptor del socket del transporte y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla. Dado que RPC basado en TCP utiliza E/S con búfer, los usuarios pueden especificar el tamaño de los búferes; los valores cero eligen valores predeterminados adecuados.




SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);



  

  
Esta rutina crea un transporte de servicio RPC basado en UDP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto UDP local, esta rutina lo enlaza a un puerto arbitrario. Al finalizar, xprt->xp_sock es el descriptor del socket del transporte y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla.

  

  
Esto permite al usuario especificar el tamaño máximo del paquete para enviar y recibir mensajes RPC basados en UDP.




SVCXPRT *svcudp_create(int sock);



  

  
Esta llamada es equivalente a svcudp_bufcreate(sock,SZ,SZ) para algún tamaño predeterminado SZ.




bool_t xdr_accepted_reply(XDR *xdrs, struct accepted_reply *ar);

void xprt_register(SVCXPRT *xprt);



  

  
Después de que se creen los manejadores de transporte del servicio RPC, estos deben registrarse
      con el paquete de servicio RPC. Esta rutina modifica la variable global svc_fds. Los implementadores de servicios normalmente no necesitan esta
      rutina.




void xprt_unregister(SVCXPRT *xprt);



  

  
Antes de que se destruya un manejador de transporte del servicio RPC, este debe anular su registro
      con el paquete de servicio RPC. Esta rutina modifica la variable global svc_fds. Los implementadores de servicios normalmente no necesitan esta
      rutina.
