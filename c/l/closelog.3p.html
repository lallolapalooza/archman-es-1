CLOSELOG(3P) Manual de Programador POSIX CLOSELOG(3P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

closelog, openlog, setlogmask, syslog — controlar el registro del sistema

SINOPSIS

#include <syslog.h>
void closelog(void);
void openlog(const char *ident, int logopt, int facility);
int setlogmask(int maskpri);
void syslog(int priority, const char *message, ... /* arguments */);

DESCRIPCIÓN

La función syslog() envía un mensaje a un mecanismo de registro definido por la implementación, que puede registrarlo en un registro del sistema definido por la implementación, escribirlo en la consola del sistema, reenviarlo a una lista de usuarios o reenviarlo al mecanismo de registro de otro host a través de la red. El mensaje registrado incluirá una cabecera de mensaje y un cuerpo de mensaje. La cabecera del mensaje contendrá al menos una marca de tiempo y una cadena de etiqueta.

El cuerpo del mensaje se genera a partir de message y los argumentos siguientes de la misma manera que si fueran argumentos para printf(), excepto que la especificación de conversión adicional %m se reconocerá; no convertirá argumentos, provocará la salida de la cadena del mensaje de error asociada con el valor de errno en la entrada a syslog(), y puede mezclarse con especificaciones de argumento de la forma "%n$". Si una especificación de conversión completa con el carácter especificador de conversión m no es solo %m, el comportamiento es indefinido. Puede agregarse un salto de línea final si es necesario.

Los valores del argumento priority se forman combinando un valor de nivel de severidad y una instalación opcional. Si no se especifica ninguna instalación, se utiliza la instalación predeterminada actual.

Los valores posibles del nivel de severidad incluyen:

LOG_EMERG
Una condición de pánico.
LOG_ALERT
Una condición que debe corregirse inmediatamente, como una base de datos del sistema corrupta.
LOG_CRIT
Condiciones críticas, como errores graves de dispositivo.
LOG_ERR
Errores.
LOG_WARNING

Mensajes de advertencia.
LOG_NOTICE
Condiciones que no son de error, pero que pueden requerir un manejo especial.
LOG_INFO
Mensajes informativos.
LOG_DEBUG
Mensajes que contienen información normalmente útil solo cuando se depura un programa.

La instalación indica la aplicación o componente del sistema que genera el mensaje. Los valores posibles de instalación incluyen:

LOG_USER
Mensajes generados por procesos arbitrarios. Esta es la instalación predeterminada si no se especifica ninguna.
LOG_LOCAL0
Reservado para uso local.
LOG_LOCAL1
Reservado para uso local.
LOG_LOCAL2
Reservado para uso local.
LOG_LOCAL3
Reservado para uso local.
LOG_LOCAL4
Reservado para uso local.
LOG_LOCAL5
Reservado para uso local.
LOG_LOCAL6
Reservado para uso local.
LOG_LOCAL7
Reservado para uso local.

La función openlog() establece atributos del proceso que afectan a las llamadas posteriores a syslog(). El argumento ident es una cadena que se antepone a cada mensaje. El argumento logopt indica opciones de registro. Los valores de logopt se construyen mediante una OR inclusiva a nivel de bits de cero o más de los siguientes:

LOG_PID
Registrar el ID del proceso con cada mensaje. Esto es útil para identificar procesos específicos.
LOG_CONS
Escribir mensajes en la consola del sistema si no se pueden enviar al mecanismo de registro. La función syslog() asegura que el proceso no adquiera la consola como terminal de control en el proceso de escritura del mensaje.
LOG_NDELAY
Abrir la conexión al mecanismo de registro inmediatamente. Normalmente, la apertura se retrasa hasta que se registra el primer mensaje. Esto es útil para programas que necesitan gestionar el orden en que se asignan los descriptores de archivo.
LOG_ODELAY
Retrasar la apertura hasta que se llame a syslog().
LOG_NOWAIT
No esperar a los procesos hijos que puedan haber sido creados durante el proceso de registro del mensaje. Esta opción debe ser utilizada por procesos que habilitan la notificación de terminación de hijos usando SIGCHLD, ya que syslog() puede bloquearse esperando a un hijo cuyo estado de salida ya se ha recopilado.

El argumento facility codifica una instalación predeterminada que se asignará a todos los mensajes que no tengan una instalación explícita ya codificada. La instalación predeterminada inicial es LOG_USER.

Las funciones openlog() y syslog() pueden asignar un descriptor de archivo. No es necesario llamar a openlog() antes de llamar a syslog().

La función closelog() cerrará cualquier descriptor de archivo abierto asignado por llamadas anteriores a openlog() o syslog().

La función setlogmask() establecerá la máscara de prioridad de registro para el proceso actual en maskpri y devolverá la máscara anterior. Si el argumento maskpri es 0, la máscara de registro actual no se modificará. Las llamadas realizadas por el proceso actual a syslog() con una prioridad que no esté establecida en maskpri serán rechazadas. La máscara de registro predeterminada permite registrar todas las prioridades. No es necesario llamar a openlog() antes de llamar a setlogmask().

Las constantes simbólicas para usar como valores de los argumentos logopt, facility, priority y maskpri están definidas en la cabecera <syslog.h>.

VALOR DE RETORNO

La función setlogmask() devolverá la máscara de prioridad de registro anterior. Las funciones closelog(), openlog() y syslog() no devolverán ningún valor.

ERRORES

No se definen errores.

Las siguientes secciones son informativas.

EJEMPLOS

Usando openlog()

El siguiente ejemplo hace que las llamadas posteriores a syslog() registren el ID del proceso con cada mensaje y que escriban mensajes en la consola del sistema si no se pueden enviar al mecanismo de registro.

#include <syslog.h>
char *ident = "Demo de proceso";
int logopt = LOG_PID | LOG_CONS;
int facility = LOG_USER;
...
openlog(ident, logopt, facility);

Usando setlogmask()

El siguiente ejemplo hace que las llamadas posteriores a syslog() acepten mensajes de error y rechacen todos los demás mensajes.

#include <syslog.h>
int result;
int mask = LOG_MASK (LOG_ERR);
...
result = setlogmask(mask);

Usando syslog

Th

El siguiente ejemplo envía el mensaje "Thisisamessage" a la utilidad de registro predeterminada, marcando el mensaje como un mensaje de error generado por procesos aleatorios.

#include <syslog.h>
char *message = "This is a message";
int priority = LOG_ERR | LOG_USER;
...
syslog(priority, message);
