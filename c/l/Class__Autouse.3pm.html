Si ninguna de las anteriores es suficiente, se puede dar una referencia CODE a Class::Autouse. Cualquier intento de llamar a un método en una clase inexistente lanzará cada callback registrado hasta que uno devuelva

Dado que sobrescribir UNIVERSAL::AUTOLOAD solo puede hacerse una vez en una aplicación Perl dada, esta característica permite compartir UNIVERSAL::AUTOLOAD. Por favor, usa esto en lugar de implementar tu propio UNIVERSAL::

Ejemplo de

callback

Cualquier uso de una clase como Foo::Wrapper autogenera esa clase como un proxy alrededor de

Foo. 
use Class::Autouse sub {
    my ($class) = @_;
    if ($class =~ /(^.*)::Wrapper/) {
        my $wrapped_class = $1;
        eval "package $class; use Class::AutoloadCAN;";
        die $@ if $@;
        no strict 'refs';
        *{$class . '::new' } = sub {
            my $class = shift;
            my $proxy = $wrapped_class->new(@_);
            my $self = bless({proxy => $proxy},$class);
            return $self;
        };
        *{$class . '::CAN' } = sub {
            my ($obj,$method) = @_;
            my $delegate = $wrapped_class->can($method);
            return unless $delegate;
            my $delegator = sub {
                my $self = shift;
                if (ref($self)) {
                    return $self->{proxy}->$method(@_);
                }
                else {
                    return $wrapped_class->$method(@_);
                }
            };
            return *{ $class . '::' . $method } = $delegator;
        };
        return 1;
    }
    return;
};
package Foo;
sub new { my $class = shift; bless({@_},$class); }
sub class_method { 123 }
sub instance_method {
    my ($self,$v) = @_;
    return $v * $self->some_property
}
sub some_property { shift->{some_property} }
package main;
my $x = Foo::Wrapper->new(
    some_property => 111,
);
print $x->some_property,"\n";
print $x->instance_method(5),"\n";
print Foo::Wrapper->class_method,"\n";

azúcar sintáctico

Este método está proporcionado para soportar "azúcar sintáctico": permitir al desarrollador poner cosas en Perl que no parecen Perl regular. Hay varias maneras de hacer esto en Perl. Las estrategias que requieren sobreescribir UNIVERSAL::AUTOLOAD pueden usar esta interfaz en su lugar para compartir ese método con el supercargador, y con los generadores de clases.

Cuando Perl no puede encontrar un subrutina/método, y todos los cargadores de clases están agotados, las devoluciones de llamada registradas vía sugar() son llamadas. Las devoluciones de llamada reciben el nombre de la clase, el nombre del método, y los parámetros de la llamada.

Si la devolución de llamada no devuelve nada, Class::Autouse continuará iterando a través de otras devoluciones de llamada. La primera devolución de llamada que devuelva un valor verdadero terminará la iteración. Se espera que ese valor sea una referencia a código CODE que responderá a la llamada AUTOLOAD.

Nota: La(s) devolución(es) de llamada de azúcar solo serán disparadas por UNIVERSAL::AUTOLOAD después de que todos los demás intentos de cargar la clase estén hechos, y después de intentos de usar AUTOLOAD regular para manejar la llamada al método. Nunca es disparada por isa() o can(). Se disparará repetidamente para la misma clase. Para generar clases, usa la referencia CODE regular de soporte en autouse().

Ejemplo de Azúcar Sintáctico

use Class::Autouse;
Class::Autouse->sugar(
    sub {
        my $caller = caller(1);
        my ($class,$method,@params) = @_;
        shift @params;
        my @words = ($method,$class,@params);
        my $sentence = join(" ",@words);
        return sub { $sentence };
    }
);
$x = trolls have big ugly hairy feet;
print $x,"\n";
# trolls have big ugly hairy feet

mod_perl

El mecanismo que "Class::Autouse" usa no es compatible con mod_perl. En particular con módulos de recarga como Apache::Reload. "Class::Autouse" detecta la presencia de mod_perl y actúa normalmente, pero siempre cargará todas las clases inmediatamente, equivalente a tener el modo de desarrollo habilitado.

Esto es realmente beneficioso, ya que bajo mod_perl las clases deberían ser precargadas en el proceso padre de mod_perl de todos modos, para evitar que tengan que ser cargadas por las clases hijas de Apache. También ahorra GRANDES cantidades de memoria.

Ten en cuenta que las clases generadas dinámicamente y las clases cargadas vía regex NO PUEDEN ser precargadas automáticamente antes de bifurcar procesos hijos. Aún serán cargadas bajo demanda, a menudo en el proceso hijo. Ver prefork abajo.

prefork

Al igual que con mod_perl, "Class::Autouse" es compatible con el módulo prefork, y todos los módulos cargados automáticamente específicamente serán cargados antes de bifurcar correctamente, cuando lo solicite prefork.

Dado que los módulos generados vía callback o regex no pueden ser cargados automáticamente por prefork de una manera genérica, se aconseja usar prefork directamente para cargar/generar clases cuando se usa mod_perl.

Optimizaciones de Rendimiento

:nostat
Descrito arriba, esta opción es útil cuando el módulo en cuestión está en un disco remoto.
:noprebless
Cuando se establece, Class::Autouse presume que los objetos que ya están bendecidos (blessed) tienen su clase cargada.

Esto es cierto en la mayoría de los casos, pero fallará si el desarrollador pretende reconstruir objetos serializados desde Data::Dumper, FreezeThaw o sus primos, y ha configurado Class::Autouse para cargar las clases involucradas justo a tiempo (just-in-time).

:staticisa
Cuando se establece, presume que @ISA no cambiará para una clase una vez que esté cargada. El bisabuelo de una clase recibirá las implementaciones originales de can/isa que son más rápidas que aquellas que Class::Autouse instala en UNIVERSAL. Es un ajuste de rendimiento útil en la mayoría de los casos, pero se deja desactivado por defecto para prevenir errores oscuros.

El Depurador Interno

Class::Autouse proporciona un depurador interno, que puede ser usado para depurar cualquier caso límite extraño que puedas encontrar al usarlo.

Si la variable $Class::Autouse::DEBUG es verdadera cuando "Class::Autouse" es cargado por primera vez, la depuración será compilada. Esta depuración imprime salida como la siguiente a STDOUT.

Class::Autouse::autouse_recursive( 'Foo' )
    Class::Autouse::_recursive( 'Foo', 'load' )
        Class::Autouse::load( 'Foo' )
        Class::Autouse::_children( 'Foo' )
        Class::Autouse::load( 'Foo::Bar' )
            Class::Autouse::_file_exists( 'Foo/Bar.pm' )
            Class::Autouse::load -> Loading in Foo/Bar.pm
        Class::Autouse::load( 'Foo::More' )
            etc...

Ten en cuenta que porque esto es optimizado fuera si no se usa, ya no puedes (desde 1.20) habilitar la depuración en tiempo de ejecución. Esta decisión se tomó para eliminar un gran número de bifurcaciones innecesarias y acelerar la carga.

MÉTODOS

autouse $class, ...

El método autouse establece una o más clases para ser cargadas según se requiera.

load $class

El método load carga una o más clases en memoria. Esto es funcionalmente equivalente a usar require para cargar la lista de clases, excepto que load detectará y eliminará el gancho de autocarga de una clase previamente autoused, mientras que use ignora efectivamente la clase, y no la carga.

devel

El método devel establece el modo de desarrollo activado (argumento de 1) o desactivado (argumento de 0).

Si alguna clase ha sido previamente autouse'd y no cargada cuando este método es llamado, serán cargadas inmediatamente.

superloader

El método superloader activa el super cargador.

Ten en cuenta que una vez que has activado el superloader, no puede ser desactivado. Esto se debe a que el código que podría estar dependiendo de que esté ahí no podría autocargar sus clases cuando otra pieza de código decide que ya no lo quiere, y desactiva el superloader.

class_exists $class

Método útil cuando se hacen el tipo de trabajos que "Class::Autouse" hace. Dado un nombre de clase, devolverá verdadero si la clase puede ser cargada ( es decir, en @INC ), falso si la clase no puede ser cargada, y undef si el nombre de la clase es inválido.

Ten en cuenta que esto no carga realmente la clase, solo prueba para ver si puede ser cargada. La carga aún puede fallar. Para un conjunto más completo de métodos de esta naturaleza, ver Class::Inspector.

autouse_recursive $class

Igual que el método "autouse" , pero autousa recursivamente.

load_recursive $class

Igual que el método "load" , pero carga recursivamente. Genial para verificar que un gran árbol de clases que podría no cargarse siempre se cargue correctamente.
