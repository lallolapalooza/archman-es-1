NOMBRE

clevis-luks-bind - Vincula un dispositivo LUKS usando la política especificada

SINOPSIS

clevis luks bind [-f] [-y] -d DEV [-t TKN_ID] [-s SLT] [-k KEY] [-e EXISTING_TOKEN_ID] PIN CFG

DESCRIPCIÓN

El comando clevis luks bind vincula un dispositivo LUKS usando la política especificada. Esto se logra con un comando simple:

$ clevis luks bind -d /dev/sda tang '{"url":...}'

Este comando realiza cuatro pasos:

1.Crea una nueva clave con la misma entropía que la clave maestra LUKS — los bits de entropía máximos son 256.
2.Cifra la nueva clave con Clevis.
3.Almacena el JWE de Clevis en la cabecera LUKS.
4.Habilita la nueva clave para su uso con LUKS.

Este disco ahora se puede desbloquear con su contraseña existente, así como con la política de Clevis. Además, deberá habilitar uno o más de los desbloqueadores LUKS de Clevis. Consulte clevis-luks-unlockers(7).

OPCIONES

•-f : No solicitar la inicialización de LUKSMeta
•-y : Responder automáticamente sí a todas las preguntas. Al usar tang, omite la verificación de confianza del anuncio, lo que puede ser útil en implementaciones automatizadas.
•-d DEV : El dispositivo LUKS en el que realizar la vinculación.
•-s SLT : La ranura LUKSMeta a utilizar para el almacenamiento de metadatos.
•-t TKN_ID : El ID del token LUKS a utilizar; solo disponible para LUKS2.
•-k KEY : Lee de forma no interactiva la contraseña LUKS desde el archivo KEY.
•-k - : Lee de forma no interactiva la contraseña LUKS desde la entrada estándar.
•-e E_TKN_ID : ID del token LUKS para la contraseña existente; solo disponible para LUKS2. Este parámetro permite proporcionar un token configurado en LUKS2 que contiene la contraseña existente para este dispositivo, de modo que clevis no solicite la contraseña existente.

ADVERTENCIAS

Este comando no cambia la clave maestra LUKS. Esto implica que si crea una imagen cifrada con LUKS para usar en un entorno de Máquina Virtual o Nube, todas las instancias que ejecuten esta imagen compartirán una clave maestra. Esto es extremadamente peligroso y debe evitarse a toda costa.

Esta no es una limitación de Clevis, sino un principio de diseño de LUKS. Si desea tener volúmenes raíz cifrados en la nube, deberá asegurarse de realizar el método de instalación del SO para cada instancia en la nube. Las imágenes no se pueden compartir sin compartir también una clave maestra.
