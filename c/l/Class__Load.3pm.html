DESCRIPCIÓ

N

"require EXPR" solo acepta nombres de módulos del estilo "Class/Name.pm", no "Class::Name". ¡Qué frustrante! Para eso, proporcionamos "load_class 'Class

::Name'".

A menudo es útil probar si un módulo puede cargarse, en lugar de lanzar un error cuando no está disponible. Para eso, proporcionamos "try_load_class 'Clas

s::Name'".

Finalmente, a veces necesitamos saber si una clase particular ha sido cargada. Preguntar %INC es una opción, pero eso no detectará paquetes internos ni ninguna clase cuyo nombre de archivo no corresponda al nombre del paquete. Para eso, proporcionamos "is_class_loaded

'Class:
:Name'".

Esto usa una serie de heurísticas para determinar si la clase "Class::Name" está cargada. Estas heurísticas fueron tomadas de la antigua implementación en perl puro de Class::

Al igual que "load_class", puedes pasar un "-version" en %options. Si la versión no es suficiente, e

Esto intenta cargar la primera clase cargable en la lista de clases dadas. Cada nombre de clase puede ir seguido de una referencia a hash de

opciones.

Si alguna de las clases se carga y pasa la comprobación opcional de versión, ese nombre de clase será devuelto. Si ninguna de las clases puede ser cargada (o ninguna pasa su comprobación de versión), entonces se lanzará un

error.

Si, al intentar cargar una clase, falla al c

load_optional_class Class::Name, \%options ->

0|1

"load_optional_class" es mucho como "try_load_class", pero también es mucho como "load_class"

.

Si la clase existe, y funciona, entonces devolverá 1. Si especificas una versión en %options, entonces la comprobación de versión debe tener éxito o devolverá

0.

Si la clase no existe, y parece que tampoco existe en disco, devolverá

0.

Si la clase existe en disco, pero cargarla desde disco resulta en un error (ej.: un error de sintaxis), entonces hará un "croak" con ese

error.

Esto es útil para usar si quieres un sistema de módulos de respaldo, es

decir: 
my $class = load_optional_class($foo) ? $foo :
$default;

De esa manera, si $foo existe, pero no puede ser cargado debido

a un error, no obtendrás
el comportamiento de que
simplemente no exista.

ADVERTENCI

AS

Debido a algunas de las heurísticas que este módulo usa para inferir si un módulo ha sido cargado, pueden ocurrir algunos positivos falsos en las comprobaciones de "is_class_loaded" (que también se realizan internamente en otras interfaces) -- si una clase ha comenzado a ser cargada pero luego muere, puede parecer que ya ha sido cargada, lo que puede hacer que otras cosas tom

en la decisión incorrecta. Module::Runtime no tiene este problema, pero tampoco hace algunas cosas que este módulo hace
-- por ejemplo, manejar con elegancia paquetes que han sido definidos en línea en el mismo archivo que otro paquete.
