NOMBRE

CREATE_DATABASE - crea una nueva base de datos

SINOPSIS

CREATE DATABASE name
    [ WITH ] [ OWNER [=] user_name ]
           [ TEMPLATE [=] template ]
           [ ENCODING [=] encoding ]
           [ STRATEGY [=] strategy ]
           [ LOCALE [=] locale ]
           [ LC_COLLATE [=] lc_collate ]
           [ LC_CTYPE [=] lc_ctype ]
           [ BUILTIN_LOCALE [=] builtin_locale ]
           [ ICU_LOCALE [=] icu_locale ]
           [ ICU_RULES [=] icu_rules ]
           [ LOCALE_PROVIDER [=] locale_provider ]
           [ COLLATION_VERSION = collation_version ]
           [ TABLESPACE [=] tablespace_name ]
           [ ALLOW_CONNECTIONS [=] allowconn ]
           [ CONNECTION LIMIT [=] connlimit ]
           [ IS_TEMPLATE [=] istemplate ]
           [ OID [=] oid ]

DESCRIPCIÓN

CREATE DATABASE crea una nueva base de datos de PostgreSQL.

Para crear una base de datos, debes ser superusuario o tener el privilegio especial CREATEDB. Ver CREATE ROLE (CREATE_ROLE(7)).

Por defecto, la nueva base de datos se creará clonando la base de datos del sistema estándar template1. Se puede especificar una plantilla diferente escribiendo TEMPLATE name. En particular, escribiendo TEMPLATE template0, puedes crear una base de datos prístina (una donde no existen objetos definidos por el usuario y donde los objetos del sistema no han sido alterados) que contiene solo los objetos estándar predefinidos por tu versión de PostgreSQL. Esto es útil si deseas evitar copiar cualquier objeto local de la instalación que pueda haber sido añadido a template1.

PARÁMETROS

name

El nombre de la base de datos a crear.

user_name

El nombre de rol del usuario que será propietario de la nueva base de datos, o DEFAULT para usar el valor por defecto (es decir, el usuario que ejecuta el comando). Para crear una base de datos propiedad de otro rol, debes poder hacer SET ROLE a ese rol.

template

El nombre de la plantilla a partir de la cual crear la nueva base de datos, o DEFAULT para usar la plantilla por defecto (template1).

encoding

La codificación de conjunto de caracteres a usar en la nueva base de datos. Especifica una constante de cadena (por ejemplo, 'SQL_ASCII'), o un número de codificación entero, o DEFAULT para usar la codificación por defecto (es decir, la codificación de la plantilla de la base de datos). Los conjuntos de caracteres soportados por el servidor PostgreSQL se describen en la Sección 23.3.1. Ver más abajo para restricciones adicionales.

strategy

La estrategia a usar al crear la nueva base de datos. Si se usa la estrategia WAL_LOG, la base de datos se copiará bloque por bloque y cada bloque se escribirá por separado en el registro de escritura previa (write-ahead log). Esta es la estrategia más eficiente en los casos donde la base de datos plantilla es pequeña, y por lo tanto es la por defecto. La estrategia más antigua FILE_COPY también está disponible. Esta estrategia escribe un registro pequeño en el registro de escritura previa por cada tablespace usado por la base de datos destino. Cada uno de esos registros representa la copia de un directorio completo a una nueva ubicación a nivel del sistema de archivos. Aunque esto reduce sustancialmente el volumen del registro de escritura previa, especialmente si la base de datos plantilla es grande, también fuerza al sistema a realizar un checkpoint tanto antes como después de la creación de la nueva base de datos. En algunas situaciones, esto puede tener un impacto negativo perceptible en el rendimiento general del sistema. La estrategia FILE_COPY se ve afectada por la configuración file_copy_method.

locale

Establece el orden de clasificación (collation) por defecto y la clasificación de caracteres en la nueva base de datos. La clasificación afecta al orden de clasificación aplicado a las cadenas, por ejemplo, en consultas con ORDER BY, así como al orden usado en los índices sobre columnas de texto. La clasificación de caracteres afecta a la categorización de caracteres, por ejemplo, minúscula, mayúscula y dígito. También establece los aspectos asociados del entorno del sistema operativo, LC_COLLATE y LC_CTYPE. El valor por defecto es la misma configuración que la de la base de datos plantilla. Ver la Sección 23.2.2.3.1 y la Sección 23.2.2.3.2 para más detalles.

Puede ser anulado configurando lc_collate, lc_ctype, builtin_locale, o icu_locale individualmente.

Si locale_provider es builtin, entonces locale o builtin_locale debe ser especificado y establecido a C, C.UTF-8, o PG_UNICODE_FAST.


Consejo
Las otras configuraciones de configuración regional (locale) lc_messages, lc_monetary, lc_numeric y lc_time no están fijas por base de datos y no son establecidas por este comando. Si deseas hacerlas el valor por defecto para una base de datos específica, puedes usar ALTER DATABASE ... SET.

lc_collate

Establece LC_COLLATE en el entorno del sistema operativo del servidor de base de datos. El valor por defecto es la configuración de locale si se especifica, de lo contrario, la misma configuración que la de la base de datos plantilla. Ver más abajo para restricciones adicionales.

Si locale_provider es libc, también establece el orden de clasificación por defecto a usar en la nueva base de datos, anulando la configuración locale.

lc_ctype

Establece LC_CTYPE en el entorno del sistema operativo del servidor de base de datos. El valor por defecto es la configuración de locale si se especifica, de lo contrario, la misma configuración que la de la base de datos plantilla. Ver más abajo para restricciones adicionales.

Si locale_provider es libc, también establece la clasificación de caracteres por defecto a usar en la nueva base de datos, anulando la configuración locale.

builtin_locale

Especifica la configuración regional (locale) del proveedor builtin para el orden de clasificación por defecto y la clasificación de caracteres de la base de datos, anulando la configuración locale. El proveedor de configuración regional debe ser builtin. El valor por defecto es la configuración de locale si se especifica; de lo contrario, la misma configuración que la de la plantilla de la base de datos.

Las configuraciones regionales disponibles para el proveedor builtin son C, C.UTF-8 y PG_UNICODE_FAST.

icu_locale

Especifica la configuración regional (locale) de ICU (ver la Sección 23.2.2.3.2) para el orden de clasificación por defecto y la clasificación de caracteres de la base de datos, anulando la configuración locale. El proveedor de configuración regional debe ser ICU. El valor por defecto es la configuración de locale si se especifica; de lo contrario, la misma configuración que la de la base de datos plantilla.

icu_rules

Especifica reglas de clasificación adicionales para personalizar el comportamiento de la clasificación por defecto de esta base de datos. Esto es soportado solo para ICU. Ver la Sección 23.2.3.4 para más detalles.

locale_provider

Especifica el proveedor a usar para la clasificación por defecto en esta base de datos. Los valores posibles son builtin, icu (si el servidor fue compilado con soporte de ICU) o libc. Por defecto, el proveedor es el mismo que el de la template. Ver la Sección 23.1.4 para más detalles.

collation_version

Especifica la cadena de versión de clasificación a almacenar con la base de datos. Normalmente, esto debería omitirse, lo que hará que la versión se calcule a partir de la versión real de la clasificación de la base de datos proporcionada por el sistema operativo. Esta opción está destinada a ser usada por pg_upgrade para copiar la versión de una instalación existente.

Ver también ALTER DATABASE (ALTER_DATABASE(7)) para cómo manejar discrepancias en la versión de clasificación de la base de datos.

tablespace_name

El nombre del tablespace que se asociará con la nueva base de datos, o DEFAULT para usar el tablespace de la base de datos plantilla. Este tablespace será el tablespace por defecto usado para los objetos creados en esta base de datos. Ver CREATE TABLESPACE (CREATE_TABLESPACE(7)) para más información.

allowconn

Si es false, entonces nadie puede conectarse a esta base de datos. El valor por defecto es true, permitiendo conexiones (excepto como lo restrinjan otros mecanismos, como GRANT/REVOKE CONNECT).

connlimit

Cuántas conexiones concurrentes se pueden hacer a esta base de datos. -1 (el valor por defecto) significa sin límite.

istemplate

Si es true, entonces esta base de datos puede ser clonada por cualquier usuario con privilegios CREATEDB; si es false (el valor por defecto), entonces solo los superusuarios o el propietario de la base de datos pueden clonarla.

oid

El identificador de objeto a usar para la nueva base de datos. Si este parámetro no se especifica, PostgreSQL elegirá un OID adecuado automáticamente. Este parámetro está destinado principalmente al uso interno por pg_upgrade, y solo pg_upgrade puede especificar un valor menor que 16384.

NOTA

S

CREATE DATABASE no puede ejecutarse dentro de un bloque de

transacción.

Los errores del tipo «could not initialize database directory» (no se pudo inicializar el directorio de la base de datos) suelen estar relacionados con permisos insuficientes en el directorio de datos, un disco lleno u otros problemas del sistema de

archivos.

Utilice DROP DATABASE para eliminar una base de

datos.

El programa createdb(1) es un programa envoltorio de este comando, proporcionado por

comodidad.

Los parámetros de configuración a nivel de base de datos (establecidos mediante ALTER DATABASE) y los permisos a nivel de base de datos (establecidos mediante GRANT) no se copian desde la base de datos

plantilla.

Aunque es posible copiar una base de datos distinta de template1 especificando su nombre como plantilla, esto no está (todavía) concebido como una utilidad «COPY DATABASE» de propósito general. La limitación principal es que no pueden haber otras sesiones conectadas a la base de datos plantilla mientras se está copiando. CREATE DATABASE fallará si existe alguna otra conexión cuando se inicie; de lo contrario, se bloquearán las nuevas conexiones a la base de datos plantilla hasta que CREATE DATABASE finalice. Consulte la Sección 22.3 para más

información.

La codificación de caracteres especificada para la nueva base de datos debe ser compatible con la configuración de configuración regional elegida (LC_COLLATE y LC_CTYPE). Si la configuración regional es C (o POSIX, que es equivalente), se permiten todas las codificaciones, pero con otras configuraciones regionales solo hay una codificación que funcionará correctamente. (En Windows, sin embargo, la codificación UTF-8 puede usarse con cualquier configuración regional.) CREATE DATABASE permitirá a los superusuarios especificar la codificación SQL_ASCII independientemente de la configuración regional, pero esta opción está obsoleta y puede provocar un comportamiento anómalo de las funciones de cadenas de caracteres si se almacenan en la base de datos datos que no son compatibles con la codificación de la configuración

regional.

La codificación y la configuración regional deben coincidir con las de la base de datos plantilla, excepto cuando se usa template0 como plantilla. Esto se debe a que otras bases de datos podrían contener datos que no coincidan con la codificación especificada, o podrían contener índices cuya ordenación está afectada por LC_COLLATE y LC_CTYPE. Copiar tales datos resultaría en una base de datos corrupta según la nueva configuración. template0, sin embargo, se sabe que no contiene datos ni índices que se vieran

afectados.

Actualmente no existe una opción para usar una configuración regional de la base de datos con comparaciones no deterministas (consulte CREATE COLLATION para una explicación). Si esto es necesario, habría que usar colaciones por

columna.

La opción CONNECTION LIMIT solo se aplica de forma aproximada; si dos nuevas sesiones comienzan casi al

mismo tiempo cuando solo queda un «hueco» de conexión para la base de datos, es posible que ambas fallen
. Además, el límite no se aplica a los superusuarios ni a los procesos de trabajadores en segundo plano.
