DESCRIPCIÓ

N

CREATE VIEW define una vista de una consulta. La vista no se materializa físicamente. En su lugar, la consulta se ejecuta cada vez que la vista se referencia en una

consulta.

CREATE OR REPLACE VIEW es similar, pero si ya existe una vista con el mismo nombre, se reemplaza. La nueva consulta debe generar las mismas columnas que generó la consulta de la vista existente (es decir, los mismos nombres de columna en el mismo orden y con los mismos tipos de datos), pero puede añadir columnas adicionales al final de la lista. Los cálculos que dan lugar a las columnas de salida pueden ser completamente

diferentes.

Si se proporciona un nombre de esquema (por ejemplo, CREATE VIEW myschema.myview ...) entonces la vista se crea en el esquema especificado. De lo contrario, se crea

en el esquema actual. Las vistas temporales existen en un esquema especial, por lo que no se puede proporcionar un nombre de esquema al crear una vista temporal. El n
ombre de la vista debe ser distinto del nombre de cualquier otra relación (tabla, secuencia, índice, vista, vista materializada o tabla externa) en el mismo esquema.

S

TEMPORARY o

TEMP
Si se especifica, la vista se crea como una vista temporal. Las vistas temporales se eliminan automáticamente al final de la sesión actual. Las relaciones permanentes existentes con el mismo nombre no son visibles para la sesión actual mientras la vista temporal existe, a menos que se referencien con nombres calificados por esquema.

Esta opción controla el comportamiento de las vistas actualizables automáticamente. Cuando se especifica esta opción, los comandos INSERT, UPDATE y MERGE en la vista se verificarán para asegurar que las nuevas filas satisfacen la condición que define la vista (es decir, las nuevas filas se verifican para asegurar que son visibles a través de la vista). Si no lo son, la actualización será rechazada. Si no se especifica la CHECK OPTION, los comandos INSERT, UPDATE y MERGE en la vista pueden crear filas que no son visibles a través de la vista. Se admiten las siguientes opciones de verificación:

LOCA

L
Las nuevas filas solo se verifican contra las condiciones definidas directamente en la propia vista. No se verifican las condiciones definidas en las vistas base subyacentes (a menos que también especifiquen la CHECK OPTION)
.

CASCADE

D
Las nuevas filas se verifican contra las condiciones de la vista y todas las vistas base subyacentes. Si se especifica la CHECK OPTION y no se especifica ni LOCAL ni CASCADED, entonces se asume
CASCADED.

La CHECK OPTION no puede utilizarse con vistas

RECURSIVE.

Tenga en cuenta que la CHECK OPTION solo se admite en vistas que son actualizables automáticamente y que no tienen disparadores INSTEAD OF ni reglas INSTEAD. Si se define una vista actualizable automáticamente sobre una vista base que tiene disparadores INSTEAD OF, entonces puede utilizarse la LOCAL CHECK OPTION para verificar las condiciones en la vista actualizable automáticamente, pero no se verificarán las condiciones en la vista base con disparadores INSTEAD OF (una opción de verificación en cascada no se propagará a una vista actualizable mediante disparadores, y cualquier opción de verificación definida directamente en una vista actualizable mediante disparadores será ignorada). Si la vista o alguna de sus relaciones base tiene una regla INSTEAD que cause que el INSERT o UPDATE sea reescrito, entonces todas las opciones de verificación serán ignoradas en la consulta reescrita, incluyendo cualquier verificación de vistas actualizables automáticamente definidas sobre la relación con la regla INSTEAD. NOTA

S

Utilice la DROP VIEW para eliminar

vistas.

Tenga cuidado de que los nombres y tipos de las columnas de la vista se asignen de la manera que desee. Por

ejemplo: 
CREATE VIEW vi
sta AS SELECT
'Hello World';

es una mala práctica porque el nombre de la columna por defecto es ?column?; además, el tipo de datos de la columna por defecto es text, lo que puede no ser lo que deseaba. Un estilo mejor para un literal de cadena en el resultado de una vista es algo

como: 
CREATE VIEW vista A
S SELECT text 'Hel
lo World' AS hello;

Por defecto, el acceso a las relaciones base subyacentes referenciadas en la vista está determinado por los permisos del propietario de la vista. En algunos casos, esto puede utilizarse para proporcionar un acceso seguro pero restringido a las tablas subyacentes. Sin embargo, no todas las vistas están protegidas contra manipulaciones; véase la Sección 39.5 para más

detalles.

Si la vista tiene la propiedad security_invoker establecida en true, el acceso a las relaciones base subyacentes está determinado por los permisos del usuario que ejecuta la consulta, en lugar del propietario de la vista. Por lo tanto, el usuario de una vista con invocador de seguridad debe tener los permisos relevantes en la vista y sus relaciones base

subyacentes.

Si alguna de las relaciones base subyacentes es una vista con invocador de seguridad, se tratará como si se hubiera accedido directamente desde la consulta original. Por lo tanto, una vista con invocador de seguridad siempre verificará sus relaciones base subyacentes utilizando los permisos del usuario actual, incluso si se accede desde una vista sin la propiedad security_invoker

.

Si alguna de las relaciones base subyacentes tiene habilitada la seguridad a nivel de fila, entonces por defecto se aplican las políticas de seguridad a nivel de fila del propietario de la vista, y el acceso a cualquier relación adicional referenciada por esas políticas está determinado por los permisos del propietario de la vista. Sin embargo, si la vista tiene security_invoker establecida en true, entonces se utilizan las políticas y permisos del usuario que invoca, como si las relaciones base se hubieran referenciado directamente desde la consulta utilizando la

vista.

Las funciones llamadas en la vista se tratan igual que si se hubieran llamado directamente desde la consulta utilizando la vista. Por lo tanto, el usuario de una vista debe tener permisos para llamar a todas las funciones utilizadas por la vista. Las funciones en la vista se ejecutan con los privilegios del usuario que ejecuta la consulta o del propietario de la función, dependiendo de si las funciones están definidas como SECURITY INVOKER o SECURITY DEFINER. Así, por ejemplo, llamar a CURRENT_USER directamente en una vista siempre devolverá al usuario que invoca, no al propietario de la vista. Esto no se ve afectado por la configuración security_invoker de la vista, y por lo tanto una vista con security_invoker establecida en false no es equivalente a una función SECURITY DEFINER y esos conceptos no deben confundirse

.

El usuario que crea o reemplaza una vista debe tener privilegios USAGE en cualquier esquema al que se haga referencia en la consulta de la vista, para poder buscar los objetos referenciados en esos esquemas. Sin embargo, ten en cuenta que esta búsqueda solo ocurre cuando la vista se crea o se reemplaza. Por lo tanto, el usuario de la vista solo requiere el privilegio USAGE en el esquema que contiene la vista, no en los esquemas referenciados en la consulta de la vista, incluso para una vista con invocador de

seguridad.

Cuando CREATE OR REPLACE VIEW se usa en una vista existente, solo se cambia la regla SELECT que define la vista, junto con cualquier parámetro WITH ( ... ) y su CHECK OPTION. Otras propiedades de la vista, incluyendo la propiedad, los permisos y las reglas que no sean SELECT, permanecen sin cambios. Debes ser propietario de la vista para reemplazarla (esto incluye ser miembro del rol propietario)

.

Vistas

actualizables

Las vistas simples son automáticamente actualizables: el sistema permitirá INSERT, UPDATE, DELETE, y MERGE para usarse en la vista de la misma manera que en una tabla normal. Una vista es automáticamente actualizable si satisface todas las siguientes

condiciones:
•La vista debe tener exactamente una entrada en su lista FROM, que debe ser una tabla u otra vista
actualizable.
•La definición de la vista no debe contener cláusulas WITH, DISTINCT, GROUP BY, HAVING, LIMIT u OFFSET en el nivel
superior.
•La definición de la vista no debe contener operaciones de conjunto (UNION, INTERSECT o EXCEPT) en el nivel
superior.
•La lista de selección de la vista no debe contener agregados, funciones de ventana ni funciones que devuelvan
conjuntos.

Una vista automáticamente actualizable puede contener una mezcla de columnas actualizables y no actualizables. Una columna es actualizable si es una referencia simple a una columna actualizable de la relación base subyacente; de lo contrario, la columna es de solo lectura, y se generará un error si un INSERT, UPDATE, o MERGE intenta asignarle un

valor.

Si la vista es automáticamente actualizable, el sistema convertirá cualquier INSERT, UPDATE, DELETE, o MERGE en la vista en la sentencia correspondiente en la relación base subyacente. Las sentencias INSERT que tienen una cláusula ON CONFLICT UPDATE son totalmente

soportadas.

Si una vista automáticamente actualizable contiene una condición WHERE, la condición restringe qué filas de la relación base están disponibles para ser modificadas por UPDATE, DELETE, y MERGE en la vista. Sin embargo, un UPDATE o MERGE puede cambiar una fila de modo que ya no satisfaga la condición WHERE, y por lo tanto ya no sea visible a través de la vista. De manera similar, un INSERT o MERGE puede potencialmente insertar filas de la relación base que no satisfagan la condición WHERE y que por lo tanto no sean visibles a través de la vista (ON CONFLICT UPDATE puede afectar de manera similar a una fila existente no visible a través de la vista). La CHECK OPTION puede usarse para evitar que INSERT, UPDATE, y MERGE creen tales filas que no son visibles a través de la

vista.

Si una vista automáticamente actualizable está marcada con la propiedad security_barrier, entonces todas las condiciones WHERE de la vista (y cualquier condición que use operadores marcados como LEAKPROOF) siempre se evaluarán antes que cualquier condición que un usuario de la vista haya añadido. Consulta la Sección 39.5 para más detalles. Ten en cuenta que, debido a esto, las filas que no se devuelven finalmente (porque no pasan las condiciones WHERE del usuario) pueden terminar siendo bloqueadas. EXPLAIN puede usarse para ver qué condiciones se aplican a nivel de relación (y por lo tanto no bloquean filas) y cuáles

no.

Una vista más compleja que no satisface todas estas condiciones es de solo lectura por defecto: el sistema no permitirá un INSERT, UPDATE, DELETE, o MERGE en la vista. Puedes obtener el efecto de una vista actualizable creando disparadores INSTEAD OF en la vista, que deben convertir los intentos de inserción, etc. en la vista en acciones apropiadas en otras tablas. Para más información consulta CREATE TRIGGER (CREATE_TRIGGER(7)). Otra posibilidad es crear reglas (consulta CREATE RULE (CREATE_RULE(7))), pero en la práctica los disparadores son más fáciles de entender y usar correctamente. Ten en cuenta también que MERGE no está soportado en relaciones con

reglas.

Ten en cuenta que el usuario que realiza la inserción, actualización o eliminación en la vista debe tener el privilegio correspondiente de inserción, actualización o eli

minación en la vista. Además, por defecto, el propietario de la vista debe tener los privilegios relevantes en las relaciones base subyacentes, mientras que el usuario q
ue realiza la actualización no necesita ningún permiso en las relaciones base subyacentes (consulta la Sección 39.5). Sin embargo, si la vista tiene security_invoker esta
blecido en true, el usuario que realiza la actualización, en lugar del propietario de la vista, debe tener los privilegios relevantes en las relaciones base subyacentes.

EJEMPLO

S

Crea una vista que consista en todas las películas de

comedia: 
CREATE VIEW comedies AS
SELECT * FROM films
WHERE kind = 'Comedy';

Esto creará una vista que contiene las columnas que están en la tabla film en el momento de la creación de la vista. Aunque se usó * para crear la vista, las columnas añadidas posteriormente a la tabla no formarán parte de la

vista.

Crea una vista con LOCAL CHECK

OPTION: 
CREATE VIEW universal_comedies AS
    SEL
ECT * FROM comedies WHERE classifi
cation = 'U' WITH LOCAL CHECK OPTION;

Esto creará una vista basada en la vista comedies, mostrando solo películas con kind = 'Comedy' y classification = 'U'. Cualquier intento de INSERT o UPDATE de una fila en la vista será rechazado si la nueva fila no tiene classification = 'U', pero el kind de la película no será

verificado.

Crea una vista con CASCADED CHECK

OPTION: 
CREATE VIEW pg_comedies AS
    SELECT *
FROM comedies WHERE classificatio
n = 'PG' WITH CASCADED CHECK OPTION;

Esto creará una vista que verifica tanto el kind como la classification de las filas

nuevas.

Crea una vista con una mezcla de columnas actualizables y no

actualizables: 
CREATE VIEW comedies AS
    SELECT f.*,
           country_code_to_name(f.country_code)
AS country, (SELECT avg(r.rating) FROM user_ratings r
WHERE r.film_id = f.id) AS avg_rating FROM films f WHERE f.kind = 'Comedy';

Esta vista soportará INSERT, UPDATE y DELETE. Todas las columnas de la tabla films serán actualizables, mientras que las columnas calculadas country y avg_rating serán de solo

lectura.

100:

(n) AS VALUES (1) UNION ALL SE
LECT n+1 FROM nums_1_100 WHERE n < 100;
