crypt — formato de almacenamiento para

frases de contraseña con hash
y métodos de hash disponibles

DESCRIPCIÓ

N

Los métodos de hash implementados por crypt(3) están diseñados únicamente para procesar frases de contraseña de usuarios para su almacenamiento y autenticación; no son adecuados para su uso como hashes criptográficos de propósito

general.

El hash de frases de contraseña no es un sustituto de frases de contraseña fuertes. Un atacante con acceso a las frases de contraseña con hash siempre puede adivinar y comprobar posibles frases de contraseña en texto claro. Sin embargo, con un método de hash fuerte, la adivinación será demasiado lenta para que el atacante descubra una frase de contraseña

fuerte.

La mayoría de los métodos de hash utilizan una "sal" (salt) para perturbar la función de hash, de modo que la misma frase de contraseña puede producir muchos hashes posibles. Los métodos más nuevos aceptan cadenas de sal más largas. La sal debe elegirse aleatoriamente para cada usuario. La sal derrota una serie de

ataques:
  1. No es posible hacer el hash de una frase de contraseña una sola vez y luego probarla contra el hash almacenado de cada cuenta; el cálculo del hash debe repetirse para cada
    2. cuenta.
  2. No es posible saber si dos cuentas usan la misma frase de contraseña sin adivinar con éxito una de las
    3. frases.
  3. Las tablas de hashes precalculados de frases de contr
    4. aseña de uso común deben tener una entrada para cada
sal posible, lo que las hace imprácticamente grandes.

La mayoría de los métodos de hash también están diseñados deliberadamente para ser lentos; utilizan muchas iteraciones de una primitiva criptográfica subyacente para aumentar el costo de cada intento. Los métodos de hash más nuevos permiten ajustar el número de iteraciones, usando el parámetro de "coste de procesamiento" de crypt_gensalt(3). Para métodos de hash resistentes a la memoria como yescrypt, este parámetro también ajusta la cantidad de memoria necesaria para calcular un has

h. Que esto sea configurable hace posible mantener los ataques de adivinación de
contraseñas contra los hashes lentos y costosos a medida que el hardware mejora.

FORMATO DE FRASES DE CONTRASEÑA CON

HASH

Todos los métodos de hash soportados por crypt(3) producen una frase de contraseña con hash que consta de cuatro componentes: prefijo, opciones, sal, y hash. El prefijo controla qué método de hash se va a usar, y es la cadena apropiada para pasar a crypt_gensalt(3) para seleccionar ese método. El contenido de opciones, sal, y hash depende del método. Dependiendo del método, los componentes prefijo y opciones pueden estar

vacíos.

El argumento setting de crypt(3) debe comenzar con los tres primeros componentes de una frase de contraseña con hash válida, pero cualquier cosa después de eso se ignora. Esto hace que la autenticación sea simple: hacer el hash de la frase de contraseña de entrada usando la frase de contraseña con hash almacenada como configuración, y luego comparar el resultado con la frase de contraseña con hash

almacenada.

Las frases de contraseña con hash son siempre completamente ASCII imprimible, y no contienen ningún espacio en blanco ni los caracteres ‘:’, ‘;’, ‘*’, ‘!’, o ‘\’. (Estos caracteres se usan como delimitadores y marcadores especiales en los archivos passwd(5) y shadow(5).

)

La sintaxis de cada componente de una frase de contraseña con hash depende del método de hash. Los caracteres ‘$’ suelen delimitar componentes, y la sal y el hash suelen codificarse como numerales en base 64. Los detalles de esta codificación base-64 varían entre los métodos de hash. La codificación común "base64" especificada por RFC 4648 generalmente no se

us
a.

Esta es una lista de todos los métodos de hash soportados por crypt(3), aproximadamente en orden decreciente de fortaleza. Muchos de los métodos más antiguos ahora se consideran demasiado débiles para usarlos en frases de contraseña nuevas. El formato de la frase de contraseña con hash se expresa con expresiones regulares extendidas (ver regex(7)) y no muestra la división en prefijo, opciones, sal y

hash.

yescryp

t

yescrypt es un esquema escalable de hash de frases de contraseña diseñado por Solar Designer, que está basado en el scrypt de Colin Percival. Mientras que la fortaleza de yescrypt contra ataques de adivinación de contraseñas proviene del diseño de su algoritmo, su seguridad criptográfica está garantizada por su uso de SHA-256 en la capa exterior. La función de hash SHA-256 ha sido publicada por el NIST en FIPS PUB 180-2 (y sus revisiones posteriores como FIPS PUB 180-4) y por la IETF como RFC 4634 (y posteriormente RFC 6234). scrypt

scrypt es una función de derivación de clave basada en contraseña creada por Colin Percival, originalmente para el servicio de copias de seguridad en línea Tarsnap. El algoritmo fue diseñado específicamente para hacer costoso realizar ataques personalizados a gran escala con hardware, requiriendo una gran cantidad de memoria. En 2016, el algoritmo scrypt fue publicado por IETF como RFC 7914.

Originalmente desarrollado por Niels Provos y David Mazieres para OpenBSD y también compatible con versiones recientes de FreeBSD y NetBSD, en Solaris 10 y posteriores, y en varias distribuciones GNU/*/Linux.
