DESCRIPCIÓ

N

El archivo de configuración de CRI-O especifica todas las opciones de configuración disponibles y los indicadores de línea de comandos para el daemon crio(8) OCI Kubernetes Container Runtime ⟨./crio.8.md⟩, pero en un formato TOML que puede ser más fácil de modificar y

versionar.

CRI-O admite la recarga parcial de la configuración durante el tiempo de ejecución, lo que se puede hacer enviando SIGHUP al proceso en ejecución. Las opciones actualmente admitidas en crio.conf están marcadas explícitamente con 'This option supports live configuration

reload'.

El archivo containers-registries.conf(5) también se puede recargar enviando SIGHUP al proceso c

rio.

El crio.conf predeter

minado se encuentra en
/etc/crio/crio.conf.

O

El formato TOML ⟨https://github.com/toml-lang/toml⟩ se utiliza como la codificación del archivo de configuración. Cada opción y subtabla listada aquí está anidada bajo una tabla global "crio". No se utilizan opciones sueltas. El formato de TOML se puede simplificar

a:

CRIO

CRI-O lee sus valores predeterminados de almacenamiento desde el archivo containers-storage.conf(5) ubicado en /etc/containers/storage.conf. Modifique esta configuración de almacenamiento si desea cambiar los valores predeterminados del sistema. Si desea modificar el almacenamiento solo para CRI-O, puede cambiar las opciones de configuración de almacenamiento

aquí.

root="/var/lib/containers/storage" Ruta al "directorio raíz". CRI-O almacena todos sus datos, incluidas las imágenes de contenedores, en este

directorio.

runroot="/run/containers/storage" Ruta al "directorio de ejecución". CRI-O almacena todo su estado en este

directorio.

storage_driver="overlay" Controlador de almacenamiento utilizado para gestionar el almacenamiento de imágenes y contenedores. Consulte containers-storage.conf(5) para ver todos los controladores de almacenamiento

disponibles.

storage_option=[] Lista para pasar opciones al controlador de almacenamiento. Consulte containers-storage.conf(5) para ver todas las opciones de almacenamiento

disponibles.

log_dir="/var/log/crio/pods" El directorio de registro predeterminado donde irán todos los registros a menos que lo especifique directamente el kubelet. El directorio de registro especificado debe ser un directorio

absoluto.

version_file="/run/crio/version" Ubicación para que CRI-O coloque el archivo de versión temporal. Se utiliza para verificar si crio wipe debe borrar los contenedores, lo que siempre debe ocurrir en un reinicio del

nodo

version_file_persist="" Ubicación para que CRI-O coloque el archivo de versión persistente. Se utiliza para verificar si crio wipe debe borrar las imágenes, lo que solo debe ocurrir cuando CRI-O haya sido

actualizado

imagestore="" Almacena las imágenes recién extraídas en la ruta especificada, en lugar de la ruta proporcionada por

--root.

internal_wipe=true Esta opción está actualmente OBSOLETA y se eliminará en el futuro. Indica si CRI-O debe borrar los contenedores después de un reinicio y las imágenes después de una actualización cuando se inicia el servidor. Si se establece en false, uno debe ejecutar crio wipe para borrar los contenedores y las imágenes en estas

situaciones.

internal_repair=true InternalRepair indica si CRI-O debe verificar si el almacenamiento de contenedores e imágenes se corrompió después de un reinicio repentino. Si es así, CRI-O también intenta reparar el

almacenamiento.

clean_shutdown_file="/var/lib/crio/clean.shutdown" Ubicación para que CRI-O coloque el archivo de apagado limpio. Se utiliza para verif

icar si crio tuvo tiempo de sincronizarse antes de apagarse. Si n
o se encuentra, crio wipe borrará el directorio de almacenamiento.

"io.kubernetes.cri-o.ShmSize" para configurar el tamaño de /dev/shm. "io.kubernetes.cri-o.UnifiedCgroup.$CTR_NAME" para configurar el bloque unificado de cgroup v2 para un contenedor. "io.containers.trace-syscall" para rastrear llamadas al sistema a través del gancho B

PF de seccomp de OCI. "io.kubernetes.cri-o.seccompNotifierAction" para habilitar la función de notificador de seccomp. "io.kubernetes.cri-o.umask" para establecer el umask para el proceso de inicialización del contenedor. "io.kubernetes.cri.rdt-class" para establecer la clase RDT de un contenedor "seccomp-profile.kubernetes.cri-o.io" para establecer el perfil de seccom
p para: - un contenedor específico utilizando: "seccomp-profile.kubernetes.cri-o.io/" - un pod completo utilizando: "seccomp-profile.kubernetes.cri-o.io/POD" Tenga en cuenta que la anotación funciona en contenedores así como en imágenes. "io.kubernetes.cri-o.DisableFIPS" para deshabilitar el modo FIPS para un pod dentro de un clúster de Kubernetes con FIPS habilitado.

Uso de la función de notificador de

seccomp:

Esta función puede ayudarle a depurar problemas relacionados con seccomp, por ejemplo, si las llamadas al sistema bloqueadas (errores de permiso denegado) tienen un impacto negativo en la carga de

trabajo.

Para poder usar esta función, configure un runtime que tenga la anotación "io.kubernetes.cri-o.seccompNotifierAction" en el array allowed_annotations

.

También requiere al menos runc 1.1.0 o crun 0.19 que soporten la función de

notificador.

Si todo está configurado, CRI-O modificará los perfiles de seccomp elegidos para los contenedores si la anotación "io.kubernetes.cri-o.seccompNotifierAction" está establecida en el sandbox del Pod. CRI-O recibirá entonces una notificación si un contenedor está usando una llamada al sistema bloqueada y terminará la carga de trabajo después de un tiempo de espera de 5 segundos si el valor es "io.kubernetes.cri-o.seccompNotifierAction=stop"

.

Esto también significa que se pueden capturar múltiples llamadas al sistema durante ese período, mientras que el tiempo de espera se restablecerá una vez que se haya descubierto una nueva llamada al

sistema.

Esto también significa que el "restartPolicy" del Pod debe establecerse en "Never", de lo contrario, el kubelet reiniciará el contenedor

inmediatamente.

Tenga en cuenta que CRI-O no puede recibir una notificación si u

na llamada al sistema se bloquea basándose en el defaultActio
n de seccomp, lo cual es una limitación general del runtime.

auto_reload_registries=false Si es true, CRI-O recargará automáticamente el registro espejo cuando haya una actualización en el archivo 'registries.conf.d' directory. El valor predeterminado se establece en

short_name_mode="enforcing" Esta opción describe el modo de nombre corto. Los valores válidos son "enforcing" y "disabled", y el valor predeterminado es "enforcing
