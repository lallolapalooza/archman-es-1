SINOPSI

S

cryptsetup open --type <device_type> [<options>] <device> <name>

DESCRIPCIÓ

N

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

El tipo de dispositivo puede ser plain, luks (por defecto), luks1, luks2, loopaes o tcrypt

.

Por compatibilidad con versiones anteriores, existen alias del comando

open:

create (orden de argumentos <name> <device>): open --type plain
plainOpen: open --type plain
luksOpen: open --type luks
loopaesOpen: open --type loopaes
tcryptOpen: open --type tcrypt
bitlkOpen: open --type

bitlk

<options> son específicas del tipo y se describen a continuación para cada tipo de dispositivo. Para create, el orden de las opciones <name> y <device> está invertido por razones históricas; todos los demás alias usan el orden estándar <device> <name>

.

PLAI

N

open --type plain <device> <name> --cipher <spec> --key-size <bits> --hash <alg>
plainOpen <device> <name> (sintaxis antigua)
create <name> <device> (sintaxis

OBSOLETA)

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

Siempre debe especificar las opciones --cipher, --key-size y (si no se usa un archivo de clave o un anillo de claves) también --hash para evitar incompatibilidades, ya que los valores predeterminados pueden diferir en versiones anteriores de

cryptsetup.

El formato plain también permite recuperar una clave de volumen de un anillo de claves del kernel especificado por --volume-key-keyring. La clave en el anillo de claves del kernel debe configurarse antes de emitir los comandos de cryptsetup, ya que cryptsetup no sube ninguna clave al anillo en el modo plain. Para comandos posteriores (como resize), el usuario debe asegurarse de que la clave en el anillo no haya cambiado. De lo contrario, recargar la clave puede causar corrupción de datos después de un cambio de clave

inesperado.

<options> pueden ser [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring]

.

EJEMPLOS

:

Para mapear el dispositivo cifrado /dev/sda10 al dispositivo descifrado /dev/mapper/e1, puede

usar:

cryptsetup open --type plain --cipher aes-cbc-essiv:sha256 --key-size 256 --hash sha256 /dev/sda10

e1

El dispositivo descifrado puede usarse entonces como un dispositivo de bloques normal para montar un sistema de

archivos.

Para mapear un dispositivo con una clave de volumen en el anillo de claves preconfigurado trusted o encrypted, debe especificar el anillo con la clave y eliminar la especificación de hash, por ejemplo, para usar %trusted:m

ykey:

cryptsetup open --type plain /dev/sda10 e1 --volume-key-keyring=%trusted:mykey --cipher aes-xts-plain64 --key-size

256

Tenga en cuenta que el tamaño de l

a clave debe coincidir con la
clave preconfigurada en el anillo.

Abre el dispositivo LUKS <device> y configura un mapeo <name> después de la verificación exitosa de la frase de paso

proporcionada.

Primero, se busca la frase de paso en los tokens LUKS2 no protegidos por PIN. Si no existe dicho token (o falla al desbloquear el keyslot) y la frase de paso no se proporciona mediante --key-file, el comando solicita la frase de paso de forma

interactiva.

Si existe un token LUKS2 válido pero requiere un PIN para desbloquear el keyslot asignado, no se usa a menos que se agregue una de las siguientes opciones: --token-only, --token-type donde type coincide con el token protegido por PIN deseado, o --token-id con id coincidente con el token protegido por

PIN.

eout, --verify-passphrase, --persistent, --volume-key-keyring, --link-vk-to-keyring, --external-tokens-path].

Abre el loop-AES <device> y configura un mapeo <name>

Si el archivo de clave está cifrado con GnuPG, debe usar --key-file=- y descifrarlo antes de usarlo, por ejemplo, así: gpg --decrypt <keyfile> | cryptsetup loopaesOpen --ke

La extensión loop-AES no puede usar la entrada directa del archivo de clave en la terminal real porque las claves están separadas por fin de línea, y solo se leería parte del archivo de claves múltiples. Si lo necesita en un script, simplemente use la redirección de tubería: echo $keyfile | cryptsetup loopaesOpen --key-fil

e=- <device> <name>.

Use --keyfile-size para especificar la longitud de clave adecuada si es

necesario.

Use --offset para especificar el desplazamiento del dispositivo. Tenga en cuenta que las unidades deben especificarse en términos de sectores de 512

bytes.

Use --skip para especificar el desplazamiento IV. Si el dispositivo original usaba un desplazamiento pero no lo usaba en los cálculos de sector IV, debe usar explícitamente --skip 0 además del parámetro de

desplazamiento.

Use --hash para anular la función de hash predeterminada para el hash de la frase de paso (de lo contrario, se detecta según el tamaño de la clave)

.

La opción --key-file permite una combinación del contenido del archivo con la frase de paso. La opción --key-file se puede repetir. Tenga en cuenta que el uso de archivos de clave difiere de la lógica de archivos de clave de

original.

La opción --allow-discards no se puede combinar con la opción --tcrypt-hidden. Para el mapeo normal, puede causar la destrucción del volumen oculto (el volumen oculto aparece como espacio no utilizado para el volumen exterior, por lo que este espacio puede ser descartado)

.

--persistente

Si se usa con dispositivos LUKS2 y comandos de activación como abrir o actualizar, las marcas de activación especificadas se escriben de forma persistente en los metadatos y se utilizan automáticamente la próxima vez, incluso para la activación normal. (No es necesario usar cryptab u otros archivos de configuración del sistema).

Si necesita eliminar una marca persistente, use --persistente sin la marca que desea eliminar (por ejemplo, para deshabilitar la marca de descarga almacenada de forma persistente, use --persistente sin --permitir_descargas).

Solo --permitir_descargas, --rendimiento-mismo_cpu_cifrado, --rendimiento-enviar_desde_cpus_cifrado, --rendimiento-no_cola_trabajo_lectura, --rendimiento-no_cola_trabajo_escritura y --integridad-no_journal se pueden almacenar de forma persistente.

--solo-lectura, -r

Configurar un mapeo de solo lectura.

--actualizar

Actualiza un dispositivo activo con un nuevo conjunto de parámetros. Consulte cryptsetup-refresh(8) para más detalles.

--tamano-sector bytes

Establece el tamaño del sector de cifrado para su uso con el tipo de dispositivo plano. Debe ser una potencia de dos y estar en el rango de 512 - 4096 bytes. El tamaño del sector de cifrado predeterminado es de 512 bytes.

Aumentar el tamaño del sector de 512 a 4096 bytes puede mejorar el rendimiento en la mayoría de los dispositivos de almacenamiento modernos y con algunos aceleradores de cifrado de hardware.

Tenga en cuenta que usar un tamaño de sector mayor que el tamaño del sector físico del dispositivo de almacenamiento subyacente puede provocar corrupción de datos durante fallos de energía inesperados. Un fallo de energía durante las operaciones de escritura puede dar lugar a una finalización parcial de la escritura del sector de cifrado, dejando los datos cifrados en un estado inconsistente que no se puede descifrar correctamente.

--serializar-memoria-difícil-pbkdf

Utiliza un bloqueo global para serializar la desbloqueo de las ranuras de claves que utilizan PBKDF de memoria difícil.

Esto es una solución alternativa para una situación específica en la que se activan varios dispositivos en paralelo y el sistema, en lugar de informar de falta de memoria, comienza a detener incondicionalmente los procesos que utilizan el asesino de falta de memoria.

¡NO USE este modificador hasta que esté implementando el entorno de arranque con activación paralela de dispositivos!

--compartido

Crea un mapeo adicional para un dispositivo de texto cifrado común. Se admiten mapeos arbitrarios. Esta opción solo es relevante para el tipo de dispositivo plano. Utilice --desplazamiento, --tamaño y --saltar para especificar el área mapeada.

--tamano, -b <número de sectores de 512 bytes>

Establece el tamaño del dispositivo en sectores de 512 bytes. Solo utilizable con el tipo de dispositivo plano.

--saltar, -p <número de sectores de 512 bytes>

Desplazamiento de inicio utilizado en el cálculo de IV en sectores de 512 bytes (cuántos sectores de los datos cifrados omitir al principio). Esta opción solo es relevante con los tipos de dispositivo plano o loopaes.

Por lo tanto, si --desplazamiento n, y --saltar s, el sector n (el primer sector del dispositivo cifrado) obtendrá un número de sector de s para el cálculo del IV.

--tcrypt-copia-seguridad, --tcrypt-oculto, --tcrypt-sistema

Especifica qué encabezado TrueCrypt en disco se utilizará para abrir el dispositivo. Consulte la sección TCRYPT de cryptsetup(8) para más información.

El uso de un dispositivo cifrado por el sistema con la opción --tcrypt-sistema requiere configuraciones específicas para funcionar como se espera.

TrueCrypt/VeraCrypt admite el cifrado completo del sistema (solo una tabla de particiones no está cifrada) o el cifrado de partición del sistema (solo una partición del sistema está cifrada). El encabezado de metadatos contiene el desplazamiento y el tamaño del área cifrada. Cryptsetup necesita conocer el desplazamiento específico de la partición para calcular los parámetros de cifrado. Para mapear correctamente una partición, debe especificar un dispositivo de partición real para que cryptsetup pueda calcular este desplazamiento.

Si bien puede usar un dispositivo completo como parámetro (/dev/sdb), siempre prefiera especificar la partición que desea mapear (/dev/sdb1), ya que solo el modo de partición del sistema se puede detectar de esta manera.

Para mapear imágenes (almacenadas en un archivo), puede usar la opción adicional --encabezado con el dispositivo de partición real. Si se usa --encabezado (y es diferente de la imagen de datos), cryptsetup espera que la imagen de datos contenga una instantánea de la partición de datos solamente.

Si --encabezado no se utiliza (o apunta a la misma imagen), cryptsetup espera que la imagen contenga un disco completo (incluida la tabla de particiones). Esto puede mapear un área cifrada completa que no es directamente montable como un sistema de archivos. Prefiera crear un dispositivo loop con particiones (losetup -P, consulte la página man de losetup(8)) y usar una partición real (/dev/loopXp1) como parámetro del dispositivo.

--probar-contrasena

No active el dispositivo, solo verifique la contraseña. El nombre del mapeo del dispositivo no es obligatorio si se usa esta opción.

--tiempo-espera, -t segundos

El número de segundos a esperar antes de un tiempo de espera en la entrada de contraseña a través de la terminal. Es relevante cada vez que se solicita una contraseña. No tiene ningún efecto si se usa junto con --archivo-clave.

Esta opción es útil cuando el sistema no debe detenerse si el usuario no introduce una contraseña, por ejemplo, durante el arranque. El valor predeterminado es 0 segundos, lo que significa esperar indefinidamente.

--id-token

Especifica qué token usar y permite que el aviso de PIN del token tenga prioridad sobre el aviso interactivo de contraseña de la ranura de claves. Si se omite, se comprobarán todos los tokens disponibles (no protegidos por PIN) antes de continuar con el aviso de contraseña.

--solo-token

No continúe con la acción si el desbloqueo de la ranura de claves basado en token falló. Sin la opción, la acción solicita una contraseña para continuar.

Permite que los tokens de LUKS2 protegidos por PIN tengan prioridad sobre el aviso interactivo de contraseña de la ranura de claves.

--tipo-token tipo

Restringe los tokens elegibles para la operación a un tipo de token específico. Principalmente útil cuando no se especifica --id-token.

Permite que los tokens de tipo de LUKS2 protegidos por PIN tengan prioridad sobre el aviso interactivo de contraseña de la ranura de claves.

--intentos, -T

Cuántas veces se intentará introducir la contraseña. El valor predeterminado es 3 intentos.

--tipo tipo

Especifica el tipo de dispositivo requerido, para más información, lea la sección ACCIONES BÁSICAS de cryptsetup(8).

--desvinculado

Permitido solo junto con el parámetro --probar-contrasena, permite probar la contraseña de una ranura de claves LUKS2 desvinculada. De lo contrario, la contraseña de una ranura de claves desvinculada solo se puede probar cuando se selecciona una ranura de claves específica a través del parámetro --ranura-clave.

--uso

Mostrar ayuda de opciones cortas.

--veracrypt

Esta opción se ignora ya que el modo compatible con VeraCrypt es compatible de forma predeterminada.

--veracrypt-pim, --veracrypt-consultar-pim

Utiliza un Multiplicador de Iteración Personal (PIM) personalizado para el dispositivo VeraCrypt. Consulte la sección TCRYPT de cryptsetup(8) para más información.

--verificar-contrasena, -y

Al solicitar interactivamente una contraseña, solicítela dos veces y quejarse si ambas entradas no coinciden. Se recomienda al crear un mapeo de tipo plano por primera vez. Ignorado al introducir desde un archivo o stdin.

--version, -V

Mostrar la versión del programa.

--archivo-clave-volumen archivo, --archivo-clave-maestra archivo (alias OBSOLETO)

Utiliza una clave de volumen almacenada en un archivo.

Esto permite abrir los tipos de dispositivo luks y bitlk sin proporcionar una contraseña.

Para dispositivos en re-cifrado, la opción puede usarse dos veces para especificar tanto la clave de volumen antigua como la nueva. Al usar la opción dos veces, asegúrese de emparejar cada opción --archivo-clave-volumen con el parámetro respectivo --tamano-clave también.

--keyring-clave-volumen <descripción de clave>

Utiliza una clave de volumen almacenada en un keyring. Esto permite abrir los tipos de dispositivo luks y plano sin proporcionar una contraseña.

Para LUKS, la clave y el tipo asociado deben ser legibles desde el espacio de usuario para que el hash de la clave del volumen pueda verificarse antes de la activación. Para dispositivos en re-cifrado, la opción se puede usar dos veces para especificar ambas claves de volumen, antigua y nueva.

Para el tipo PLANO, el usuario debe asegurarse de que la clave en el keyring no ha cambiado desde la activación. De lo contrario, la recarga de la clave puede causar corrupción de datos después de un cambio de clave inesperado.

La <descripción de clave> utiliza la sintaxis compatible con keyctl. Puede ser un ID de clave numérico o un nombre de cadena en el formato %<tipo de clave>:<nombre de clave>. Consulte también la sección IDENTIFICADORES DE CLAVE de keyctl(1). Cuando no se especifica un prefijo %<tipo de clave>:, asumimos que el tipo de clave es usuario (tipo predeterminado).
