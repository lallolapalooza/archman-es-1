CREATE_TABLE_AS - define una

nueva tabla a partir de los
resultados de una consulta

SINOPSI

S 
CREATE [ [ GLOBAL | LOCAL ] { TEMPORARY | TEMP } | UNLOGGED ] TABLE [ IF NOT EXISTS ] table_name
    [ (column_name [, ...] ) ]
    [ USING method ]
    [ WITH ( storage_parameter [= value] [, ... ] ) | WITHOUT OIDS ]
    [ ON COMMIT { PRESERVE ROWS | DELETE ROWS | DROP } ]
    [ TABLESPACE tablespace_name ]
    AS query
    [ WIT
H [ NO
] DATA ]

DESCRIPCIÓ

N

CREATE TABLE AS crea una tabla y la llena con datos calculados por un comando SELECT. Las columnas de la tabla tienen los nombres y los tipos de datos asociados a las columnas de salida del SELECT (excepto que puede anular los nombres de las columnas proporcionando una lista explícita de nuevos nombres de columnas)

.

CREATE TABLE AS tiene cierta similitud con la creación de una vista, pero en realidad es bastante diferente: crea una nueva tabla y evalúa la consulta solo una vez para llenar la nueva tabla inicialmente. La nueva tabla no rastreará los cambios posteriores en las tablas de origen de la consulta. En contraste, una vista re-evalúa su declaración SELECT definitoria cada vez que se

consulta.

CREATE TABLE AS requiere el privilegio CREAT

E en el esquema ut
ilizado para la tabla.

PARÁMETRO

S

GLOBAL o

LOCAL
Ignorado por compatibilidad. El uso de estas palabras clave está obsoleto; consulte CREATE TABLE (CREATE_TABLE(7)) para más
detalles.

TEMPORARY o

TEMP
Si se especifica, la tabla se crea como una tabla temporal. Consulte CREATE TABLE (CREATE_TABLE(7)) para más
detalles.

UNLOGGE

D
Si se especifica, la tabla se crea como una tabla no registrada (unlogged). Consulte CREATE TABLE (CREATE_TABLE(7)) para más
detalles.

IF NOT

EXISTS
No lance un error si ya existe una relación con el mismo nombre; simplemente emita un aviso y deje la tabla sin
modificar.

table_nam

e
El nombre (opcionalmente calificado por esquema) de la tabla a ser
creada.

column_nam

e
El nombre de una columna en la nueva tabla. Si no se proporcionan los nombres de las columnas, se toman de los nombres de las columnas de salida de la
consulta.

USING metho

d
Esta cláusula opcional especifica el método de acceso a la tabla a usar para almacenar el contenido de la nueva tabla; el método debe ser un método de acceso de tipo TABLE. Vea el Capítulo 62 para más información. Si esta opción no se especifica, se elige el método de acceso a la tabla predeterminado para la nueva tabla. Vea default_table_access_method para más
información.

WITH ( storage_parameter [= value] [, ... ]

)
Esta cláusula especifica parámetros de almacenamiento opcionales para la nueva tabla; vea Parámetros de almacenamiento en la documentación de CREATE TABLE (CREATE_TABLE(7)) para más información. Por compatibilidad con versiones anteriores, la cláusula WITH para una tabla también puede incluir OIDS=FALSE para especificar que las filas de la nueva tabla no deben contener OIDs (identificadores de objetos), OIDS=TRUE ya no es
compatible.

WITHOUT

OIDS
Esta es una sintaxis compatible con versiones anteriores para declarar una tabla WITHOUT OIDS, crear una tabla WITH OIDS ya no es
compatible.

ON

COMMIT
El comportamiento de las tablas temporales al final de un bloque de transacción se puede controlar usando ON COMMIT. Las tres opciones son:

PRESERVE

ROWS
No se toma ninguna acción especial al final de las transacciones. Este es el comportamiento
predeterminado.

DELETE

ROWS
Todas las filas en la tabla temporal serán borradas al final de cada bloque de transacción. Esencialmente, un TRUNCATE automático se realiza en cada
commit.

DRO

P
La tabla temporal será elimin
ada (dropped) al final del
bloque de transacción actual.

TABLESPACE tablespace_nam

e
El tablespace_name es el nombre del tablespace en el que se creará la nueva tabla. Si no se especifica, se consulta default_tablespace, o temp_tablespaces si la tabla es
temporal.

quer

y
Un SELECT, TABLE, o VALUES command, o un EXECUTE command que ejecuta una consulta preparada SELECT, TABLE, o VALUES
.

WITH [ NO ]

DATA
Esta cláusula especifica si los datos producidos por la consulta
deben ser copiados a la nueva tabla. Si no, solo se copia la es
tructura de la tabla. El valor predeterminado es copiar los datos.

NOTA

S

Este comando es funcionalmente similar a SELECT INTO (SELECT_INTO(7)), pero se prefiere ya que es menos probable que se confunda con otros usos de la sintaxis SELECT INTO. Además, CREATE TABLE AS ofrece un subconjunto de la funcionalidad ofrecida por SELECT

IN
TO.

EJEMPLO

S

Cree una nueva tabla films_recent que conste solo de entradas recientes de la tabla

films: 
CREATE TABLE films_recent AS
SELECT * FROM films WHER
E date_prod >= '2002-01-01';

Para copiar una tabla completamente, la forma corta usando el comando TABLE también se puede

usar: 
CREATE TABLE
films2 AS
TABLE films;

Cree una nueva tabla temporal films_recent, que consta solo de entradas recientes de la tabla films, usando una sentencia preparada. La nueva tabla será eliminada en el

commit: 
PREPARE recentfilms(date) AS
  SELECT *
FROM films WHERE date_prod > $1; CREATE
TEMP TABLE films_recent ON COMMIT DROP
AS EXECUTE recentfilms('2002-01-01');

COMPATIBILIDA

D

CREATE TABLE AS se ajusta al estándar SQL. Lo siguiente son extensiones no

estándar:
•El estándar requiere paréntesis alrededor de la cláusula de subconsulta; en PostgreSQL, estos paréntesis son
opcionales.
•En el estándar, la cláusula WITH [ NO ] DATA es requerida; en PostgreSQL es
opcional.
•PostgreSQL maneja las tablas temporales de una manera bastante diferente al estándar; vea CREATE TABLE (CREATE_TABLE(7)) para más
detalles.
•La cláusula WITH es una extensión de PostgreSQL; los parámetros de almacenamiento no están en el
estándar.
•El concepto de tablespaces de PostgreSQL
no es parte del estándar. Por lo tanto,
la cláusula TABLESPACE es una extensión.
