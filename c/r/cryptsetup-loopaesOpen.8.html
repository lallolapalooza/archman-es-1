N

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

El tipo de dispositivo puede ser plain, luks (por defecto), luks1, luks2, loopaes o tcrypt

open:

luksOpen: open --type luks
loopaesOpen: open --type loopaes
tcryptOpen: open --type tcrypt
bitlkOpen: open --type

bitlk

<options> son específicas del tipo y se describen más abajo para cada tipo de dispositivo. Para create, el orden de las opciones <name> y <device> está invertido por razones históricas; todos los demás alias usan el orden estándar <device> <name>

.

OBSOLETA)

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

Deberías especificar siempre las opciones --cipher, --key-size y (si no se usa un archivo de clave o un anillo de claves) también --hash para evitar incompatibilidades, ya que los valores por defecto pueden diferir en versiones antiguas de

cryptsetup.

El formato plain también permite obtener una clave de volumen de un anillo de claves del kernel especificado por --volume-key-keyring. La clave en el anillo de claves del kernel debe configurarse antes de emitir comandos de cryptsetup, ya que cryptsetup no sube ninguna clave al anillo en modo plain. Para comandos posteriores (como resize), el usuario debe asegurarse de que la clave en el anillo no haya cambiado. De lo contrario, recargar la clave puede causar corrupción de datos después de un cambio inesperado de

clave.

<options> pueden ser [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring]

.

e1

archivos.

open

open <device> <name>

Opens the specified <device> and sets up a mapped device <name>. The device must be already formatted (e.g. with luksFormat).

A passphrase is required for LUKS, tcrypt, plain, and loopaes devices. The passphrase is read from the user's terminal unless the --key-file option is specified.

The device can be a block device (e.g. /dev/sda1) or a file container.

Additional options are available for specific device types:

  • luksOpen (LUKS1, LUKS2, LUKS1 with integrity)
  • tcryptOpen (TrueCrypt, VeraCrypt)
  • plainOpen (non-encrypted device)
  • loopAESOpen (old loopAES format)
  • integrityOpen (data integrity only)
  • veracryptOpen (VeraCrypt mode)
  • FileVault2 (FileVault2 compatible)

The options can be one or more of [--key-file, --keyfile-offset, --keyfile-size, --key-size, --readonly, --test-passphrase, --allow-discards, --volume-key-file, --tries, --timeout, --verify-passphrase].

FileVault2

open --type fvault2 <device> <name>
fvault2Open <device> <name> (old syntax)

Opens the FVAULT2 (a FileVault2 compatible) <device> and sets up a mapping <name>.

<options> can be [--key-file, --keyfile-offset, --keyfile-size, --key-size, --readonly, --test-passphrase, --allow-discards --volume-key-file, --tries, --timeout, --verify-passphrase].

OPTIONS

--allow-discards

Allow the use of discard (TRIM) requests for the device. This is also not supported for LUKS2 devices with data integrity protection.

WARNING: This command can have a negative security impact because it can make filesystem-level operations visible on the physical device. For example, information leaking filesystem type, used space, etc., may be extractable from the physical device if the discarded blocks can be located later. If in doubt, do not use it.

A kernel version of 3.1 or later is needed. For earlier kernels, this option is ignored.

--batch-mode, -q

Suppresses all confirmation questions. Use with care!

If the --verify-passphrase option is not specified, this option also switches off the passphrase verification.

--cipher, -c <cipher-spec>

Set the cipher specification string for the plain device type.

For the tcrypt device type, it restricts checked cipher chains when looking for the header.

cryptsetup --help shows the compiled-in defaults.

If a hash is part of the cipher specification, then it is used as part of the IV generation. For example, ESSIV needs a hash function, while "plain64" does not and hence none is specified.

For XTS mode, you can optionally set a key size of 512 bits with the -s option. Key size for XTS mode is twice that for other modes for the same security level.

--debug or --debug-json

Run in debug mode with full diagnostic logs. Debug output lines are always prefixed by #.

If --debug-json is used, additional LUKS2 JSON data structures are printed.

--device-size size[units]

Instead of the real device size, use the specified value. Usable only with plain device type.

If no unit suffix is specified, the size is in bytes.

Unit suffix can be S for 512 byte sectors, K/M/G/T (or KiB, MiB, GiB, TiB) for units with 1024 base or KB/MB/GB/TB for 1000 base (SI scale).

--disable-external-tokens

Disable loading of plugins for external LUKS2 tokens.

--disable-keyring

Do not load the volume key in the kernel keyring; store it directly in the dm-crypt target instead. This option is supported only for the LUKS2 type.

--disable-locks

Disable lock protection for metadata on disk. This option is valid only for LUKS2 and is ignored for other formats.

WARNING: Do not use this option unless you run cryptsetup in a restricted environment where locking is impossible to perform (where /run directory cannot be used).

--disable-veracrypt

This option can be used to disable VeraCrypt compatible mode (only TrueCrypt devices are recognized). See the TCRYPT section in cryptsetup(8) for more info.

--external-tokens-path <absolute path>

Override the system directory path where cryptsetup searches for external token handlers (or token plugins). It must be an absolute path (starting with '/' character).

--hash, -h <hash-spec>

Specifies the passphrase hash. Applies to plain and loopaes device types only.

For the tcrypt device type, it restricts the checked PBKDF2 variants when looking for the header.

--header <device or file storing the LUKS header>

Specify a detached (separated) metadata device or file where the header is stored.

WARNING: There is no check whether the ciphertext device specified actually belongs to the header given. In fact, you can specify an arbitrary device as the ciphertext device with the --header option. Use with care.

--help, -?

Show help text and default parameters.

--iv-large-sectors

Count Initialization Vector (IV) in larger sector size (if set) instead of 512-byte sectors. This option can be used only with the plain device type.

This option does not have any performance or security impact; use it only for accessing incompatible existing disk images from other systems that require this option.

--key-description text

Set the key description in the keyring that will be used for passphrase retrieval.

--key-file, -d file

Read the passphrase from the file.

If the name given is "-", then the passphrase will be read from stdin. In this case, reading will not stop at newline characters.

With plain device type, the passphrase obtained via --key-file option is passed directly in dm-crypt. Unlike the interactive mode (stdin), where the digest of the passphrase is passed in dm-crypt instead.

See section NOTES ON PASSPHRASE PROCESSING in cryptsetup(8) for more information.

--keyfile-offset value

Skip value bytes at the beginning of the key file.

--keyfile-size, -l value

Read a maximum of value bytes from the key file. The default is to read the whole file up to the compiled-in maximum that can be queried with --help. Supplying more data than the compiled-in maximum aborts the operation.

This option is useful to cut trailing newlines, for example. If --keyfile-offset is also given, the size count starts after the offset.

--key-size, -s bits

Sets key size in bits. The argument has to be a multiple of 8. The possible key sizes are limited by the cipher and mode used.

See /proc/crypto for more information. Note that the key size in /proc/crypto is stated in bytes.

This option can be used for plain and luks devices. For LUKS2 devices in reencryption, you may use the parameter twice to specify both old and new volume key sizes. Each --key-size option corresponds to the respective --volume-key-file parameter (also allowed to be used up to two times).

--key-slot, -S <0-N>

This option selects a specific keyslot to compare the passphrase against. If the given passphrase would only matches a different keyslot, the operation fails.

The maximum number of keyslots depends on the LUKS version. LUKS1 can have up to 8 keyslots. LUKS2 can have up to 32 keyslots based on keyslot area size and key size, but a valid keyslot ID can always be between 0 and 31 for LUKS2.

--link-vk-to-keyring <keyring description>::<key description>

Link the volume key in a keyring with the specified key name. The volume key is linked only if the requested action is successfully finished (with --test-passphrase, the verified volume key is linked in a keyring without taking further action).

The <keyring description> string has to contain the existing kernel keyring description. The keyring name may be optionally prefixed with "%:" or "%keyring:" type descriptions. Or, the keyring may also be specified directly by numeric key id. Also, special keyring notations starting with "@" may be used to select existing predefined kernel keyrings.

The string "::" is a delimiter used to separate the keyring description and key description.

<key description> part describes key type and key name of volume key linked in the keyring described in <keyring description>. The type may be specified by adding a "%<type_name>:" prefix in front of the key name. If the type is missing, the default user type is applied. If the key of the same name and type already exists (already linked in the keyring), it will get replaced in the process.

See also the KEY IDENTIFIERS section of keyctl(1).

--offset, -o <number of 512 byte sectors>

Start offset in the backend device in 512-byte sectors. This option is only relevant with plain or loopaes device types.

--perf-high_priority

Set dm-crypt workqueues and the writer thread to high priority. This improves throughput and latency of dm-crypt while degrading the general responsiveness of the system.

This option is available only for low-level dm-crypt performance tuning, use only if you need a change to the default dm-crypt behaviour. Needs kernel 6.10 or later.

--perf-no_read_workqueue, --perf-no_write_workqueue

Bypass dm-crypt internal workqueue and process read or write requests synchronously.

These options are available only for low-level dm-crypt performance tuning, use only if you need a change to the default dm-crypt behaviour. Needs kernel 5.9 or later.

--perf-same_cpu_crypt

Perform encryption using the same CPU on which that IO was submitted. The default is to use an unbound workqueue so that encryption work is automatically balanced between available CPUs.

This option is available only for low-level dm-crypt performance tuning, use only if you need a change to the default dm-crypt behaviour.

--perf-submit_from_crypt_cpus

Disable offloading writes to a separate thread after encryption. There are some situations where offloading write bios from the encryption threads to a single thread degrades performance significantly. The default is to offload write bios to the same thread.

This option is available only for low-level dm-crypt performance tuning, use only if you need a change

A la configuración predeterminada de dm-crypt.

--persistent

Si se usa con dispositivos LUKS2 y comandos de activación como open o refresh, las marcas de activación especificadas se escriben de forma persistente en los metadatos y se utilizan automáticamente la próxima vez, incluso para la activación normal. (No es necesario usar cryptab u otros archivos de configuración del sistema).

Si necesita eliminar una marca persistente, use --persistent sin la marca que desea eliminar (por ejemplo, para deshabilitar la marca de descarte almacenada de forma persistente, use --persistent sin --allow-discards).

Solo se pueden almacenar de forma persistente --allow-discards, --perf-same_cpu_crypt, --perf-submit_from_crypt_cpus, --perf-no_read_workqueue, --perf-no_write_workqueue y --integrity-no-journal.

--readonly, -r

Configura un mapeo de solo lectura.

--refresh

Actualiza un dispositivo activo con un nuevo conjunto de parámetros. Consulte cryptsetup-refresh(8) para más detalles.

--sector-size bytes

Establece el tamaño del sector de cifrado para su uso con el tipo de dispositivo plain. Debe ser una potencia de dos y estar en el rango de 512 a 4096 bytes. El tamaño predeterminado del sector de cifrado es 512 bytes.

Aumentar el tamaño del sector de 512 a 4096 bytes puede proporcionar un mejor rendimiento en la mayoría de los dispositivos de almacenamiento modernos y con algunos aceleradores de cifrado de hardware.

Tenga en cuenta que usar un tamaño de sector mayor que el tamaño físico del sector del dispositivo de almacenamiento subyacente puede provocar corrupción de datos durante fallos de alimentación inesperados. Un fallo de alimentación durante las operaciones de escritura puede resultar en una finalización parcial de la escritura del sector de cifrado, dejando los datos cifrados en un estado inconsistente que no se puede descifrar correctamente.

--serialize-memory-hard-pbkdf

Utiliza un bloqueo global para serializar la activación de las ranuras de claves que utilizan PBKDF con uso intensivo de memoria.

Esto es una solución alternativa para una situación específica en la que se activan varios dispositivos en paralelo y el sistema, en lugar de informar de falta de memoria, comienza a detener incondicionalmente los procesos que utilizan el asesino de falta de memoria (out-of-memory killer).

¡NO UTILICE este interruptor hasta que esté implementando el entorno de arranque con activación de dispositivos en paralelo!

--shared

Crea un mapeo adicional para un dispositivo de texto cifrado común. Se admiten mapeos arbitrarios. Esta opción solo es relevante para el tipo de dispositivo plain. Utilice --offset, --size y --skip para especificar el área mapeada.

--size, -b <número de sectores de 512 bytes>

Establece el tamaño del dispositivo en sectores de 512 bytes. Solo utilizable con el tipo de dispositivo plain.

--skip, -p <número de sectores de 512 bytes>

Desplazamiento de inicio utilizado en el cálculo de IV en sectores de 512 bytes (cuántos sectores de los datos cifrados omitir al principio). Esta opción solo es relevante con los tipos de dispositivo plain o loopaes.

Por lo tanto, si --offset n, y --skip s, el sector n (el primer sector del dispositivo cifrado) obtendrá un número de sector de s para el cálculo del IV.

--tcrypt-backup, --tcrypt-hidden, --tcrypt-system

Especifica qué encabezado de disco TrueCrypt se utilizará para abrir el dispositivo. Consulte la sección TCRYPT en cryptsetup(8) para más información.

Usar un dispositivo cifrado por el sistema con la opción --tcrypt-system requiere configuraciones específicas para funcionar como se espera.

TrueCrypt/VeraCrypt admite el cifrado completo del sistema (solo la tabla de particiones no está cifrada) o el cifrado de particiones del sistema (solo una partición del sistema está cifrada). El encabezado de metadatos contiene el desplazamiento y el tamaño del área cifrada. Cryptsetup necesita conocer el desplazamiento específico de la partición para calcular los parámetros de cifrado. Para mapear correctamente una partición, debe especificar un dispositivo de partición real para que cryptsetup pueda calcular este desplazamiento.

Si bien puede usar un dispositivo completo como parámetro (/dev/sdb), prefiera siempre especificar la partición que desea mapear (/dev/sdb1), ya que solo de esta manera se puede detectar el modo de partición del sistema.

Para mapear imágenes (almacenadas en un archivo), puede usar la opción adicional --header con el dispositivo de partición real. Si se usa --header (y es diferente de la imagen de datos), cryptsetup espera que la imagen de datos contenga una instantánea solo de la partición de datos.

Si no se usa --header (o apunta a la misma imagen), cryptsetup espera que la imagen contenga un disco completo (incluida la tabla de particiones). Esto puede mapear un área cifrada completa que no es directamente montable como un sistema de archivos. Prefiera crear un dispositivo loop con particiones (losetup -P, consulte la página man de losetup(8)) y use una partición real (/dev/loopXp1) como parámetro del dispositivo.

--test-passphrase

No active el dispositivo, solo verifique la contraseña. El nombre del mapeo del dispositivo no es obligatorio si se utiliza esta opción.

--timeout, -t segundos

El número de segundos a esperar antes de un tiempo de espera en la entrada de contraseña a través de la terminal. Es relevante cada vez que se solicita una contraseña. No tiene ningún efecto si se usa junto con --key-file.

Esta opción es útil cuando el sistema no debe detenerse si el usuario no introduce una contraseña, por ejemplo, durante el arranque. El valor predeterminado es 0 segundos, lo que significa esperar indefinidamente.

--token-id

Especifica qué token usar y permite que la solicitud del PIN del token tenga prioridad sobre la solicitud interactiva de contraseña de la ranura de clave. Si se omite, se comprobarán todos los tokens disponibles (no protegidos por PIN) antes de continuar con la solicitud de contraseña.

--token-only

No continúe con la acción si la desbloqueo de la ranura de clave basada en token falló. Sin la opción, la acción solicita una contraseña para continuar.

Permite que los tokens LUKS2 protegidos por PIN tengan prioridad sobre la solicitud interactiva de contraseña de la ranura de clave.

--token-type tipo

Restringe los tokens elegibles para la operación a un tipo de token específico. Mayormente útil cuando no se especifica --token-id.

Permite que los tokens LUKS2 de tipo tipo protegidos por PIN tengan prioridad sobre la solicitud interactiva de contraseña de la ranura de clave.

--tries, -T

Cuántas veces se debe reintentar la entrada de la contraseña. El valor predeterminado es 3 intentos.

--type tipo

Especifica el tipo de dispositivo requerido, para más información, lea la sección BASIC ACTIONS en cryptsetup(8).

--unbound

Permitido solo junto con el parámetro --test-passphrase, permite probar la contraseña de una ranura de clave LUKS2 no enlazada. De lo contrario, una contraseña de ranura de clave no enlazada solo se puede probar cuando se selecciona una ranura de clave específica a través del parámetro --key-slot.

--usage

Muestra ayuda breve de opciones.

--veracrypt

Esta opción se ignora ya que el modo compatible con VeraCrypt es compatible de forma predeterminada.

--veracrypt-pim, --veracrypt-query-pim

Utiliza un Multiplicador de Iteración Personal (PIM) personalizado para el dispositivo VeraCrypt. Consulte la sección TCRYPT en cryptsetup(8) para más información.

--verify-passphrase, -y

Al solicitar interactivamente una contraseña, solicítela dos veces y quejarse si ambas entradas no coinciden. Recomendado al crear un mapeo de tipo plain por primera vez. Ignorado en la entrada desde un archivo o stdin.

--version, -V

Muestra la versión del programa.

--volume-key-file archivo, --master-key-file archivo (alias OBSOLETO)

Utiliza una clave de volumen almacenada en un archivo.

Esto permite abrir tipos de dispositivo luks y bitlk sin proporcionar una contraseña.

Para dispositivos en proceso de reencriptación, la opción puede usarse dos veces para especificar tanto la clave de volumen antigua como la nueva. Al usar la opción dos veces, asegúrese de emparejar cada opción --volume-key-file con el parámetro --key-size respectivo también.

--volume-key-keyring <descripción de clave>

Utiliza una clave de volumen almacenada en un keyring. Esto permite abrir tipos de dispositivo luks y plain sin proporcionar una contraseña.

Para LUKS, la clave y el tipo asociado deben ser legibles desde el espacio de usuario para que el resumen de la clave de volumen pueda ser verificado antes de la activación. Para dispositivos en proceso de reencriptación, la opción puede usarse dos veces para especificar tanto la clave de volumen antigua como la nueva.

Para el tipo PLAIN, el usuario debe asegurarse de que la clave en el keyring no ha cambiado desde la activación. De lo contrario, la recarga de la clave puede causar corrupción de datos después de un cambio inesperado de clave.

La <descripción de clave> utiliza la sintaxis compatible con keyctl. Puede ser un ID de clave numérico o un nombre de cadena en el formato %<tipo de clave>:<nombre de clave>. Consulte también la sección IDENTIFICADORES DE CLAVE de keyctl(1). Cuando no se especifica ningún prefijo %<tipo de clave>:, asumimos que el tipo de clave es user (tipo predeterminado).
