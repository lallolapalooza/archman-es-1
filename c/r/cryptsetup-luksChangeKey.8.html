cryptsetup-luksChange

Key - cambiar una fr
ase de paso existente

SINOPSI

S

cryptsetup luksChangeKey [<opciones>] <dispositivo> [<nuevo archivo de clave>]

DESCRIPCIÓ

N

Cambia una frase de paso existente. La frase de paso que se va a cambiar debe proporcionarse de forma interactiva o mediante --key-file. La nueva frase de paso puede proporcionarse de forma interactiva o en un archivo dado como argumento

posicional.

Si se especifica un ranura de clave (mediante --key-slot), debe proporcionarse la frase de paso para esa ranura de clave, y la nueva frase de paso sobrescribirá la ranura de clave especificada. Si no se especifica ninguna ranura de clave y aún hay una ranura de clave libre, la nueva frase de paso se colocará en una ranura de clave libre antes de que se elimine la ranura de clave que contiene la frase de paso antigua. Si no hay ninguna ranura de clave libre, la ranura de clave con la frase de paso antigua se sobrescribe

directamente.

ADVERTENCIA: Si se sobrescribe una ranura de clave, un fallo del medio durante esta operación puede hacer que la sobrescritura falle después de que la frase de paso antigua haya sido borrada, haciendo que el contenedor LUKS sea inaccesible. LUKS2 mitiga esto nunca sobrescribiendo el área de ranuras de clave existente siempre que haya espacio libre en el área de ranuras de clave al menos para una ranura de clave LUKS2

más.

Si necesita usar tanto luksChangeKey como reencrypt (por ejemplo, para recuperarse de una fuga de clave), debe usarlos en ese orden para evitar la fuga de la nueva clave de

volumen.

Algunos parámetros solo son efectivos si se usan con el formato LUKS2 que soporta parámetros por ranura de clave. Para LUKS1, el tipo de PBKDF y el algoritmo de hash son siempre los mismos para todas las ranuras de

clave.

<opciones> puede ser [--key-file, --keyfile-offset, --keyfile-size, --new-keyfile-offset, --iter-time, --pbkdf, --pbkdf-force-iterations, --pbkdf-memory, --pbkdf-parallel

, --new-keyfile-size, --key-slot, --force-password, --hash, --header, --disable-
locks, --type, --keyslot-cipher, --keyslot-key-size, --timeout, --verify-passphrase].

--pbkdf <especificación de

PBKDF>
Establecer el algoritmo de Función de Derivación de Clave Basada en Contraseña (PBKDF) para la ranura de clave LUKS. El PBKDF puede ser: pbkdf2 (para PBKDF2 según RFC2898), argon2i para Argon2i o argon2id para Argon2id (consulte Argon2 https://www.cryptolux.org/index.php/Argon2 para más información).

Para LUKS1, solo se acepta PBKDF2 (no es necesario usar esta opción). El PBKDF predeterminado para LUKS2 se establece en tiempo de compilación y está disponible en la salida de cryptsetup -

-help.

Un PBKDF se usa para aumentar el coste de los ataques de diccionario y de fuerza bruta para las frases de paso de las ranuras de clave. Los parámetros pueden ser tiempo, memoria y coste

paralelo.

Para PBKDF2, solo se aplica el coste de tiempo (número de iteraciones). Para Argon2i/id, también hay coste de memoria (memoria requerida durante el proceso de derivación de la clave) y coste paralelo (número de hilos que se ejecutan en paralelo durante la derivación de la

clave.

Tenga en cuenta que aumentar el coste de memoria también aumenta el tiempo, por lo que los valores finales de los parámetros se miden con una prueba de rendimiento. La prueba de rendimiento intenta encontrar el tiempo de iteración (--iter-time) con el coste de memoria requerido --pbkdf-memory. Si no es posible, el coste de memoria también se reduce. El coste paralelo --pbkdf-parallel es constante y se comprueba contra los núcleos de CPU

disponibles.

Puede ver todos los parámetros de PBKDF para una ranura de clave LUKS2 particular con el comando cryptsetup-luks

Dump(8).

Si no desea usar la prueba de rendimiento y desea especificar todos los parámetros directamente, use --pbkdf-force-iterations con --pbkdf-memory y --pbkdf-parallel. Esto anulará los valores sin realizar pruebas de rendimiento. Tenga en cuenta que puede causar un tiempo de desbloqueo extremadamente largo o causar condiciones de falta de memoria con terminación incondicional del proceso. Úselo solo en casos específicos, por ejemplo, si sabe que el dispositivo formateado se usará en algún sistema integrado

pequeño.

PBKDF MÍNIMO Y MÁXIMO COSTS: Para PBKDF2, el recuento mínimo de iteraciones es 1000 y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). No se admiten costes de memoria y paralelismo para PBKDF2. Para Argon2i y Argon2id, el recuento mínimo de iteraciones (coste de CPU) es 4, y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). El coste mínimo de memoria es 32 KiB y el máximo es 4 GiB. Si el parámetro de coste de memoria se calcula mediante benchmark (no se especifica con un parámetro), está siempre en el rango de 64 MiB a 1 GiB. Un coste de memoria superior a 1GiB (hasta el máximo de 4GiB) solo se puede configurar con el parámetro --pbkdf-memory. El coste de paralelismo mínimo es 1 y el máximo 4 (si hay suficientes núcleos de CPU disponibles, de lo contrario se reduce según los núcleos de CPU disponibles)

.

ADVERTENCIA: Aumentar los costes computacionales de PBKDF por encima de los límites mencionados proporciona una mejora de seguridad adicional despreciable. Aunque los costes elevados aumentan significativamente la sobrecarga de fuerza bruta, ofrecen una protección despreciable contra ataques de diccionario. El aumento marginal del coste para procesar un diccionario completo sigue siendo fundamentalmente

insuficiente.

Los límites de PBKDF codificados representan compromisos diseñados entre seguridad criptográfica y usabilidad operativa. LUKS mantiene la portabilidad y debe usarse dentro de un tiempo razonable en sistemas con recursos

limitados.

Cryptsetup restringe deliberadamente los parámetros de coste máximo de memoria (4 GiB) y de paralelismo (4) debido a limitaciones arquitectónicas (como sistemas integrados y heredados)

.

El coste de memoria de PBKDF exige una asignación real de RAM física con operaciones de escritura intensivas que deben permanecer en la RAM física. Cualquier uso de swap resulta en una deg

radación inaceptable del rendimiento. La gestión de memoria a menudo sobrecarga asignaciones más allá de la memoria física disponible, esperando que la mayor parte de la memoria asignada
permanezca sin usar. En tales situaciones, como PBKDF siempre usa toda la memoria asignada, frecuentemente causa fallos de agotamiento de memoria que abortan las operaciones de cryptsetup.

--pbkdf-memory númer

Establece el coste de memoria para PBKDF (para Argon2i/id, el número representa kilobytes). Tenga en cuenta que es el valor máximo; el benchmark de PBKDF o la memoria física disponible pueden reducirlo. Esta opción no está disponible para

o
Establece el coste de paralelismo para PBKDF (número de hilos, hasta 4). Tenga en cuenta que es el valor máximo; se reduce automáticamente si el número de CPU en línea es menor. Esta opción no está disponible para
PBKDF2.

--timeout, -t segundo

s
El número de segundos a esperar antes de que se produzca un tiempo de espera en la entrada de la frase de contraseña a través de la terminal. Es relevante cada vez que se solicita una frase de contraseña. No tiene efecto si se usa junto con --key-file.

Esta opción es útil cuando el sistema no debe bloquearse si el usuario no introduce una frase de contraseña, p. ej., durante el arranque. El valor predeterminado es 0 segundos, lo que significa esperar

indefinidamente
