cryptsetup luksAddKey [<opciones>] <dispositivo> [<archivo clave con la nueva clave>]

DESCRIPCIÓ

N

Añade un slot de clave protegido por una nueva frase de paso. Debe proporcionarse una frase de paso existente de forma interactiva, mediante --key-file o un token LUKS2 (plugin). Como alternativa a la frase de paso existente, el usuario puede pasar directamente la clave del volumen (mediante --volume-key-file o --volume-key-keyring). La nueva frase de paso que se añadirá puede especificarse de forma interactiva, leerse del archivo dado como argumento posicional (también mediante el parámetro --new-keyfile) o mediante un token

LUKS2.

La opción --unbound crea un nuevo slot de clave LUKS2 no vinculado. Un slot de clave no vinculado almacena una clave independiente que no puede usarse para la activación del dispositivo. Se genera una nueva clave aleatoria si no pasa una nueva clave mediante la opción --volume-key-file. No se requiere la frase de paso existente para ningún slot de clave

activo.

Algunos parámetros solo son efectivos si se usan con el formato LUKS2 que admite parámetros por slot de clave. Para LUKS1, el tipo de PBKDF y el algoritmo de hash son siempre los mismos para todos los slots de

clave.

<opciones> puede ser [--key-file, --keyfile-offset, --keyfile-size, --new-keyfile, --new-keyfile-offset, --new-keyfile-size, --key-slot, --new-key-slot, --volume-key-file, --volume-key-keyring, --force-password, --hash, --header, --disable-locks, --iter-tim

e, --pbkdf, --pbkdf-force-iterations, --pbkdf-memory, --pbkdf-parallel, --unbound, --type, --keyslot-cipher, --keyslot-key-size
, --key-size, --timeout, --token-id, --token-type, --token-only, --new-token-id, --verify-passphrase, --external-tokens-path].

PBKDF>
Establece la función de derivación de clave basada en contraseña (PBKDF) para el ranura de claves de LUKS. El PBKDF puede ser: pbkdf2 (para PBKDF2 según RFC2898), argon2i para Argon2i o argon2id para Argon2id (ver Argon2 https://www.cryptolux.org/index.php/Argon2 para más información).

Para LUKS1, solo se acepta PBKDF2 (no es necesario usar esta opción). El PBKDF predeterminado para LUKS2 se establece en tiempo de compilación y está disponible en la salida de cryptsetup -

-help.

Se utiliza un PBKDF para aumentar el costo de los ataques de diccionario y de fuerza bruta contra las contraseñas de las ranuras de claves. Los parámetros pueden ser tiempo, memoria y costo

paralelo.

Para PBKDF2, solo se aplica el costo de tiempo (número de iteraciones). Para Argon2i/id, también existe un costo de memoria (memoria requerida durante el proceso de derivación de la clave) y un costo paralelo (número de hilos que se ejecutan en paralelo durante la derivación de la

clave.

Tenga en cuenta que aumentar el costo de memoria también aumenta el tiempo, por lo que los valores finales de los parámetros se miden mediante una prueba de rendimiento. La prueba de rendimiento intenta encontrar el tiempo de iteración (--iter-time) con el costo de memoria requerido --pbkdf-memory. Si no es posible, el costo de memoria también se reduce. El costo paralelo --pbkdf-parallel es constante y se comprueba contra los núcleos de CPU

disponibles.

Puede ver todos los parámetros de PBKDF para una ranura de claves LUKS2 particular con el comando cryptsetup-luks

Dump(8).

Si no desea usar la prueba de rendimiento y desea especificar todos los parámetros directamente, use --pbkdf-force-iterations con --pbkdf-memory y --pbkdf-parallel. Esto anulará los valores sin realizar la prueba de rendimiento. Tenga en cuenta que puede causar un tiempo de desbloqueo extremadamente largo o causar condiciones de falta de memoria con terminación incondicional del proceso. Úselo solo en casos específicos, por ejemplo, si sabe que el dispositivo formateado se usará en algún sistema embebido

pequeño.

COSTOS MÍNIMOS Y MÁXIMOS DE PBKDF: Para PBKDF2, el número mínimo de iteraciones es 1000 y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). Los costos de memoria y paralelo no son compatibles con PBKDF2. Para Argon2i y Argon2id, el número mínimo de iteraciones (costo de CPU) es 4, y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). El costo de memoria mínimo es 32 KiB y el máximo es 4 GiB. Si el parámetro de costo de memoria se determina mediante la prueba de rendimiento (no se especifica mediante un parámetro), se encuentra siempre en el rango de 64 MiB a 1 GiB. Un costo de memoria superior a 1GiB (hasta el máximo de 4GiB) solo se puede configurar mediante el parámetro --pbkdf-memory. El costo paralelo mínimo es 1 y el máximo es 4 (si hay suficientes núcleos de CPU disponibles, de lo contrario, se reduce según los núcleos de CPU disponibles)

.

ADVERTENCIA: Aumentar los costos computacionales de PBKDF por encima de los límites mencionados proporciona una mejora de seguridad adicional despreciable. Aunque los costos elevados aumentan significativamente la sobrecarga de la fuerza bruta, ofrecen una protección despreciable contra los ataques de diccionario. El aumento marginal del costo para procesar un diccionario completo sigue siendo fundamentalmente

insuficiente.

Los límites de PBKDF codificados representan compensaciones diseñadas entre la seguridad criptográfica y la usabilidad operativa. LUKS mantiene la portabilidad y debe usarse dentro de un tiempo razonable en sistemas con recursos

limitados.

Cryptsetup restringe deliberadamente los parámetros de costo de memoria máximo (4 GiB) y de costo paralelo (4) debido a limitaciones arquitectónicas (como sistemas embebidos y sistemas heredados)

.

El costo de memoria de PBKDF requiere una asignación real de RAM física con operaciones de escritura intensivas que deben permanecer en la RAM física. Cualquier uso de swap resulta en una

degradación inaceptable del rendimiento. La gestión de memoria a menudo sobrecarga las asignaciones más allá de la memoria física disponible, esperando que la mayor parte de la memoria
asignada permanezca sin usar. En tales situaciones, como PBKDF siempre usa toda la memoria asignada, a menudo provoca fallos de falta de memoria que abortan las operaciones de cryptsetup.

--volume-key-keyring <descripción de la

clave>
Usa una clave de volumen almacenada en un llavero (keyring). Esto permite abrir tipos de dispositivo luks y plain sin proporcionar una frase de contraseña.

Para LUKS, la clave y el tipo asociado deben ser legibles desde el espacio de usuario para que el resumen de la clave del volumen pueda verificarse antes de la activación. Para dispositivos en recifrado, la opción puede usarse dos veces para especificar tanto la clave antigua como la nueva del

volumen.

Para el tipo PLAIN, el usuario debe asegurarse de que la clave en el llavero no ha cambiado desde la activación. De lo contrario, recargar la clave puede causar corrupción de datos después de un cambio inesperado de la

clave.

La <descripción de la clave> usa una sintaxis compatible con keyctl. Puede ser un ID de clave numérico o un nombre de cadena en el formato %<tipo de clave>:<nombre de clave>. Vea también la sección IDENTIFICADORES DE CLAVE de keyctl(1). Cuando no se especifica el prefijo %<tipo de clave> :, asumimos que el tipo de clave es user (ti
