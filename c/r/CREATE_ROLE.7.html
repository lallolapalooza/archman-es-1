CREATE

ROLE

añade un nuevo rol a un clúster de bases de datos de PostgreSQL. Un rol es una entidad que puede ser propietaria de objetos de base de datos y tener privilegios de base de datos; un rol puede considerarse un “usuario”, un “grupo”, o ambos, dependiendo de cómo se utilice. Consulte el Capítulo 21 y el Capítulo 20 para obtener información sobre la gestión de usuarios y la autenticación. Debe tener el privilegio CREATEROLE o ser un superusuario de la base de datos para usar este

comando.

Tenga en cuenta que los roles se definen a nivel de clúster de base de datos, y por lo tanto son válidos en todas las bases de datos del

clúster.

Durante la creación de un rol es posible asignar inmediatamente el rol recién creado como miembro de un rol existente, y también asignar roles existentes como miembros del rol recién creado. Las reglas sobre qué opciones de membresía inicial están habilitadas se describen más abajo en las cláusulas IN ROLE, ROLE y ADMIN. El comando GRAN

tiene un control de opciones detallado durante la creación de la membresía, y la capacidad de modificar estas opciones después de que el nuevo rol

haya sido creado.

ALTER

ROLE

para cambiar los atributos de un rol, y DROP ROLE para eliminar un rol. Todos los atributos especificados por CREATE ROL puede ser modificado por ALTER ROLE posteriores.

La forma preferida de añadir y eliminar miembros de roles que se están utilizando como grupos es usar GRANT y REVOKE.

La cláusula VALID UNTIL define un tiempo de expiración para una contraseña, no para el rol en sí. En particular, el tiempo de expiración no se aplica al iniciar sesión utilizando un método de autenticación que no se base en contraseñas.

Los atributos de rol definidos aquí no son heredables, es decir, ser miembro de un rol con, por ejemplo, CREATEDB no permitirá al miembro crear nuevas bases de datos incluso si la concesión de membresía tiene la opción INHERIT. Por supuesto, si la concesión de membresía tiene la opción SET, el rol miembro podría SET ROLE al rol createdb y luego crear una nueva base de datos.

Las concesiones de membresía creadas por las cláusulas IN ROLE, ROLE y ADMIN tienen al rol que ejecuta este comando como el concedente.

El atributo INHERIT es el valor predeterminado por razones de compatibilidad con versiones anteriores: en versiones anteriores de PostgreSQL, los usuarios siempre tenían acceso a todos los privilegios de los grupos de los que eran miembros. Sin embargo, NOINHERIT proporciona una coincidencia más cercana con la semántica especificada en el estándar SQL.

PostgreSQL incluye un programa createuser(1) que tiene la misma funcionalidad que CREATE ROLE (de hecho, llama a este comando) pero se puede ejecutar desde el shell de comandos.

La opción CONNECTION LIMIT solo se aplica aproximadamente; si dos nuevas sesiones comienzan al mismo tiempo cuando solo queda un "ranura" de conexión para el rol, es posible que ambas fallen. Además, el límite nunca se aplica a los superusuarios.

Se debe tener cuidado al especificar una contraseña sin cifrar con este comando. La contraseña se transmitirá al servidor en texto plano, y también podría registrarse en el historial de comandos del cliente o en el registro del servidor. El comando createuser(1), sin embargo, transmite la contraseña cifrada. Además, psql(1) contiene un comando \password que se puede utilizar para cambiar la contraseña de forma segura más tarde.

EJEMPLOS

Crear un rol que pueda iniciar sesión, pero no darle una contraseña:

CREATE ROLE jonathan LOGIN;

Crear un rol con una contraseña:

CREATE USER davide WITH PASSWORD 'jw8s0F4';

(CREATE USER es lo mismo que CREATE ROLE excepto que implica LOGIN.)

Crear un rol con una contraseña que sea válida hasta el final de 2004. Después de que pase un segundo en 2005, la contraseña ya no es válida.

CREATE ROLE miriam WITH LOGIN PASSWORD 'jw8s0F4' VALID UNTIL '2005-01-01';

Crear un rol que pueda crear bases de datos y gestionar roles:

CREATE ROLE admin WITH CREATEDB CREATEROLE;

COMPATIBILIDAD

La sentencia CREATE ROLE está en el estándar SQL, pero el estándar solo requiere la sintaxis

CREATE ROLE nombre [ WITH ADMIN nombre_rol ]

Múltiples administradores iniciales, y todas las demás opciones de CREATE ROLE, son extensiones de PostgreSQL.

El estándar SQL define los conceptos de usuarios y roles, pero los considera conceptos distintos y deja que todos los comandos que definen usuarios sean especificados por cada implementación de base de datos. En PostgreSQL hemos optado por unificar usuarios y roles en un solo tipo de entidad. Por lo tanto, los roles tienen muchos más atributos opcionales que en el estándar.

El comportamiento especificado por el estándar SQL se aproxima más creando usuarios del estándar SQL como roles de PostgreSQL con la opción NOINHERIT, y roles del estándar SQL como roles de PostgreSQL con la opción INHERIT.

La cláusula USER tiene el mismo comportamiento que ROLE pero ha sido obsoleta:

USER nombre_rol [, ...]

La cláusula IN GROUP tiene el mismo comportamiento que IN ROLE pero ha sido obsoleta:

IN GROUP nombre_rol [, ...]
