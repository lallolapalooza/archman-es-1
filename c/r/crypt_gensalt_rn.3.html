NOMBRE

crypt_gensalt, crypt_gensalt_rn, crypt_gensalt_ra — codificar ajustes para el hash de frases de paso

BIBLIOTECA

Biblioteca Crypt (libcrypt, -lcrypt)

SINOPSIS

#include <crypt.h>

char *
crypt_gensalt(const char *prefix, unsigned long count, const char *rbytes, int nrbytes);

char *
crypt_gensalt_rn(const char * prefix, unsigned long count, const char *rbytes, int nrbytes, char * output, int output_size);

char *
crypt_gensalt_ra(const char *prefix, unsigned long count, const char *rbytes, int nrbytes);

DESCRIPCIÓN

Las funciones crypt_gensalt, crypt_gensalt_rny crypt_gensalt_ra compilan una cadena para usarla como el argumento ajuste de crypt, crypt_r, crypt_rny crypt_ra. prefix selecciona el método de hash a usar. count controla el costo de procesamiento del hash; el rango válido y el significado exacto de count dependen del método de hash, pero números más grandes corresponden a hashes más costosos en términos de tiempo de CPU y posiblemente de uso de memoria. rbytes debe apuntar a nrbytes bytes aleatorios criptográficamente para usar como "sal".

Si prefix es un puntero nulo, se seleccionará el mejor método de hash disponible. (PRECAUCIÓN: si prefix es una cadena vacía, se seleccionará el método de hash "tradicional" basado en DES; este método es inaceptablemente débil según los estándares modernos.) Si count es 0, se seleccionará un costo bajo predeterminado. Si rbytes es un puntero nulo, se obtendrá del sistema operativo un número apropiado de bytes aleatorios, y nrbytes se ignora.

Véase crypt(5) para otras cadenas que pueden usarse como prefix, y valores válidos de count para cada una.

VALORES DE RETORNO

crypt_gensalt, crypt_gensalt_rny crypt_gensalt_ra devuelven un puntero a una cadena de ajuste codificada. Esta cadena será completamente ASCII imprimible, y no contendrá espacios en blanco ni los caracteres ‘:’, ‘;’, ‘*’, ‘!’, o ‘\’. Véase crypt(5) para más detalles sobre el formato de esta cadena. En caso de error, devuelven un puntero nulo y establecen errno a un código de error apropiado. Cuando las funciones tienen éxito, el valor de errno es indeterminado y no debe confiarse en él.

crypt_gensalt coloca su resultado en un área de almacenamiento estático, que será sobrescrita por llamadas subsecuentes a crypt_gensalt. No es seguro llamar a crypt_gensalt desde múltiples hilos simultáneamente. Tampoco se recomienda usar el puntero devuelto como argumento para otra llamada a crypt_gensalt, ya que algunas implementaciones, incluyendo versiones anteriores de libxcrypt, pueden sobrescribir el búfer de salida estático subyacente antes de calcular el ajuste. Sin embargo, es seguro pasar la cadena devuelta por crypt_gensalt directamente a crypt sin copiarla; cada función tiene su propio área de almacenamiento estático.

crypt_gensalt_rn coloca su resultado en el búfer output proporcionado, que tiene output_size bytes de almacenamiento disponibles. output_size debe ser mayor o igual a CRYPT_GENSALT_OUTPUT_SIZE. Tampoco se recomienda usar el puntero devuelto como argumento para otra llamada a crypt_gensalt_rn usando el mismo búfer output para llamadas subsecuentes, ya que algunas implementaciones, incluyendo versiones anteriores de libxcrypt, pueden sobrescribir el búfer proporcionado antes de calcular el ajuste.

crypt_gensalt_ra asigna memoria para su resultado usando malloc(3). Debe liberarse con free(3) después de usarlo.

En caso de error, además de devolver un puntero nulo, crypt_gensalt y crypt_gensalt_rn escribirán una cadena de ajuste inválida en su búfer de salida, si hay suficiente espacio; esta cadena comenzará con un ‘*’ y no será igual a prefix.

ERRORES

EINVAL
prefix es inválido o no es soportado por esta implementación; count es inválido para el prefijo solicitado; la entrada nrbytes es insuficiente para la sal válida más pequeña con el prefijo solicitado.
ERANGE
solo para crypt_gensalt_rn : output_size es demasiado pequeño para contener la cadena de ajuste compilada.
ENOMEM
Fallo al asignar memoria de trabajo interna.
solo para crypt_gensalt_ra : fallo al asignar memoria para la cadena de ajuste compilada.
ENOSYS, EACCES, EIO, etc.
Fallo al obtener bytes aleatorios del sistema operativo. Esto solo puede ocurrir cuando rbytes es un puntero nulo.

MACROS DE PRUEBA DE CARACTERÍSTICAS

Las siguientes macros están definidas por <crypt.h>:

CRYPT_GENSALT_IMPLEMENTS_DEFAULT_PREFIX
Se puede especificar un puntero nulo como argumento prefix .
CRYPT_GENSALT_IMPLEMENTS_AUTO_ENTROPY
Se puede especificar un puntero nulo como argumento rbytes .

NOTAS DE PORTABILIDAD

Las funciones crypt_gensalt, crypt_gensalt_rny crypt_gensalt_ra no son parte de ningún estándar. Se originan en el proyecto Openwall. Una función con el nombre crypt_gensalt también existe en Solaris 10 y versiones posteriores, pero su prototipo y semántica difieren.

Las características de prefijo predeterminado y entropía automática están disponibles desde la versión 4.0.0 de libxcrypt. El software portable puede usar macros de prueba de características para averiguar si se pueden usar punteros nulos para los argumentos prefix y rbytes.

El conjunto de métodos de hash compatibles varía considerablemente de un sistema a otro.
