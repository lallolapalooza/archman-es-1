DESCRIPCIÓ

N

OpenSSL puede usarse de forma segura en aplicaciones multiproceso siempre que el soporte para la API de hilos del sistema operativo subyacente esté integrado. Actualmente, OpenSSL soporta las API de pthread y Windows. OpenSSL también puede compilarse sin ningún soporte multiproceso, por ejemplo en plataformas que no proporcionan soporte de hilos o que proporcionan una API de hilos que aún no es soportada por

OpenSSL.

Se proporcionan las siguientes funciones

multiproceso:
  • CRYPTO_THREAD_run_once() puede usarse para realizar una inicialización única. El argumento once debe ser un puntero a un objeto estático de tipo CRYPTO_ONCE que fue inicializado estáticamente al valor CRYPTO_ONCE_STATIC_INIT. El argumento init es un puntero a una función que realiza la inicialización deseada exactamente una vez. En particular, esto puede usarse para asignar bloqueos de manera segura para hilos, que luego pueden usarse con las funciones de bloqueo
    • siguientes.
  • CRYPTO_THREAD_lock_new() asigna, inicializa y devuelve un nuevo bloqueo de lectura/escritu
    • ra.
  • CRYPTO_THREAD_read_lock() bloquea el bloqueo proporcionado para
    • lectura.
  • CRYPTO_THREAD_write_lock() bloquea el bloqueo proporcionado para
    • escritura.
  • CRYPTO_THREAD_unlock() desbloquea el bloqueo previamente bloque
    • ado.
  • CRYPTO_THREAD_lock_free() libera el bloqueo proporcionado. Si el argumento es NULL, no se hace
    • nada.
  • CRYPTO_atomic_add() añade atómicamente amount a *val y devuelve el resultado de la operación en *ret. lock será bloqueado, a menos que las operaciones atómicas estén soportadas en la plataforma específica. Debido a esto, si una variable es modificada por CRYPTO_atomic_add() entonces CRYPTO_atomic_add() debe ser la única forma en que la variable es modificada. Si las operaciones atómicas no están soportadas y lock es NULL, entonces la función
    • fallará.
  • CRYPTO_atomic_add64() añade atómicamente op a *val y devuelve el resultado de la operación en *ret. lock será bloqueado, a menos que las operaciones atómicas estén soportadas en la plataforma específica. Debido a esto, si una variable es modificada por CRYPTO_atomic_add64() entonces CRYPTO_atomic_add64() debe ser la única forma en que la variable es modificada. Si las operaciones atómicas no están soportadas y lock es NULL, entonces la función
    • fallará.
  • CRYPTO_atomic_and() realiza un y bit a bit atómico de op y *val y almacena el resultado de vuelta en *val. También devuelve el resultado de la operación en *ret. lock será bloqueado, a menos que las operaciones atómicas estén soportadas en la plataforma específica. Debido a esto, si una variable es modificada por CRYPTO_atomic_and() o leída por CRYPTO_atomic_load() entonces CRYPTO_atomic_and() debe ser la única forma en que la variable es modificada. Si las operaciones atómicas no están soportadas y lock es NULL, entonces la función
    • fallará.
  • CRYPTO_atomic_or() realiza un o bit a bit atómico de op y *val y almacena el resultado de vuelta en *val. También devuelve el resultado de la operación en *ret. lock será bloqueado, a menos que las operaciones atómicas estén soportadas en la plataforma específica. Debido a esto, si una variable es modificada por CRYPTO_atomic_or() o leída por CRYPTO_atomic_load() entonces CRYPTO_atomic_or() debe ser la única forma en que la variable es modificada. Si las operaciones atómicas no están soportadas y lock es NULL, entonces la función
    • fallará.
  • CRYPTO_atomic_load() carga atómicamente el contenido de *val en *ret. lock será bloqueado, a menos que las operaciones atómicas estén soportadas en la plataforma específica. Debido a esto, si una variable es modificada por CRYPTO_atomic_or() o leída por CRYPTO_atomic_load() entonces CRYPTO_atomic_load() debe ser la única forma en que la variable es leída. Si las operaciones atómicas no están soportadas y lock es NULL, entonces la función
    • fallará.
  • CRYPTO_atomic_store() almacena atómicamente el contenido de val en *dst. lock será bloqueado, a menos que las operaciones atómicas estén soportadas en la plataforma
    • específica.
  • CRYPTO_atomic_load_int() funciona de manera idéntica a CRYPTO_atomic_load() pero opera en un valor int en lugar de un valor uint64_t
    • .
  • OSSL_set_max_threads() establece el número máximo de hilos a ser usados por el pool de hilos. Si el argumento es 0, el pooling de hilos está deshabilitado. OpenSSL no creará ningún hilo y los hilos existentes en el pool de hilos serán terminados. El conteo máximo de hilos es un límite, no un objetivo. Los hilos no serán creados a menos que (y hasta que) haya demanda. El polling de hilos está deshabilitado por defecto. Para habilitar el threading debes llamar a OSSL_set_max_threads() explícitamente. Bajo ninguna circunstancia esto se hace por
    • ti.
  • OSSL_get_thread_support_flags() determina con qué funcionalidad de pool de hilos OpenSSL está compilado y es capaz de soportar en el entorno de ejecución actual. OSSL_THREAD_SUPPORT_FLAG_THREAD_POOL indica que la funcionalidad base del pool de hilos está disponible, y OSSL_THREAD_SUPPORT_FLAG_DEFAULT_SPAWN indica que el modelo por defecto del pool de hilos está disponible. El modelo por d
    • efecto del pool de hilos es actualmente el único modelo dis
ponible, por lo tanto ambas banderas deben estar estableci
das para que la funcionalidad del pool de hilos sea usada.

RETORNO

CRYPTO_THREAD_run_once() devuelve 1 en éxito, o 0 en

error.

CRYPTO_THREAD_lock_new() devuelve el bloqueo asignado, o NULL en

error.

CRYPTO_THREAD_lock_free() no devuelve ningún

valor.

OSSL_set_max_threads() devuelve 1 en éxito y 0 en fallo. Devuelve fallo si el pooling de hilos gestionado por OpenSSL no está soportado (por ejemplo, si no está soportado en la plataforma actual, o porque OpenSSL no está compilado con el soporte necesario)

.

OSSL_get_max_threads() devuelve el número máximo de hilos actualmente permitidos para ser usados por el pool de hilos. Si el pooling de hilos está deshabilitado o no está disponible, devuelve

0.

OSSL_get_thread_support_flags() devuelve cero o más valores OSSL_THREAD_SUPPORT_FLAG

.

Las otras funcione

s devuelven 1 en éx
ito, o 0 en error.

NOTA

S

En plataformas Windows los tipos y funciones CRYPTO_THREAD_* en el encabezado <openssl/crypto.h> dependen de algunos de los tipos comúnmente disponibles al incluir <windows.h>. Es probable que el desarrollador de la aplicación requiera control sobre cuándo se incluye este último, comúnmente como uno de los primeros encabezados incluidos. Por lo tanto, se define como responsabilidad del desarrollador de la aplicación incluir <windows.h> antes de <openssl/crypto.h> donde se requiera el uso de los tipos y funciones

CRYPTO_THREAD_*
.

EJEMPLO

S

Puedes averiguar si OpenSSL fue configurado con soporte para

hilos: 
#include <openssl/opensslconf.h>
#if defined(OPENSSL_THREADS)
    /* soporte para hilos habilitado */
#else
    /* sin soporte para hilos */
#endif

Este ejemplo inicializa y utiliza un bloqueo de forma

segura. 
#ifdef _WIN32
# include <windows.h>
#endif
#include <openssl/crypto.h>
static CRYPTO_ONCE once = CRYPTO_ONCE_STATIC_INIT;
static CRYPTO_RWLOCK *lock;
static void myinit(void)
{
    lock = CRYPTO_THREAD_lock_new();
}
static int mylock(void)
{
    if (!CRYPTO_THREAD_run_once(&once, void init) || lock == NULL)
        return 0;
    return CRYPTO_THREAD_write_lock(lock);
}
static int myunlock(void)
{
    return CRYPTO_THREAD_unlock(lock);
}
int serialized(void)
{
    int ret = 0;
    if (!mylock()) {
       /* No desbloquees a menos que el bloqueo se haya adquirido con éxito. */
       return 0;
    }
    /* Tu código aquí, ¡no devuelvas sin liberar el bloqueo! */
    ret = ... ;
    myunlock();
    return ret;
}

La finalización de los bloqueos es un tema avanzado, no cubierto en este ejemplo. Esto solo se puede hacer al salir del proc

eso o cuando una biblioteca cargada dinámicamente ya no está en uso y se descarga. La solución más simple es simplemente
"fugar" el bloqueo en las aplicaciones y no cargar/descargar repetidamente bibliotecas compartidas que asignan bloqueos.
