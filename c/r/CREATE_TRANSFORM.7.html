NOMBRE

CREATE_TRANSFORM - define una nueva transformación

SINOPSIS

CREATE [ OR REPLACE ] TRANSFORM FOR tipo_nombre LANGUAGE nombre_idioma (
    FROM SQL WITH FUNCTION nombre_funcion_from_sql [ (tipo_argumento [, ...]) ],
    TO SQL WITH FUNCTION nombre_funcion_to_sql [ (tipo_argumento [, ...]) ]
);

DESCRIPCIÓN

CREATE TRANSFORM define una nueva transformación. CREATE OR REPLACE TRANSFORM creará una nueva transformación o reemplazará una definición existente.

Una transformación especifica cómo adaptar un tipo de datos a un lenguaje procedural. Por ejemplo, al escribir una función en PL/Python usando el tipo hstore, PL/Python no tiene conocimiento previo de cómo presentar los valores hstore en el entorno de Python. Las implementaciones de lenguajes generalmente usan por defecto la representación de texto, pero eso es inconveniente cuando, por ejemplo, una matriz asociativa o una lista serían más apropiadas.

Una transformación especifica dos funciones:

•Una función "desde SQL" que convierte el tipo desde el entorno SQL al lenguaje. Esta función se invocará en los argumentos de una función escrita en el lenguaje.
•Una función "hacia SQL" que convierte el tipo desde el lenguaje al entorno SQL. Esta función se invocará en el valor de retorno de una función escrita en el lenguaje.

No es necesario proporcionar ambas funciones. Si una no se especifica, se utilizará el comportamiento predeterminado específico del lenguaje si es necesario. (Para evitar que una transformación en una dirección determinada ocurra en absoluto, también podrías escribir una función de transformación que siempre falle.)

Para poder crear una transformación, debes poseer y tener el privilegio USAGE sobre el tipo, tener el privilegio USAGE sobre el lenguaje, y poseer y tener el privilegio EXECUTE sobre las funciones desde SQL y hacia SQL, si se especifican.

PARÁMETROS

tipo_nombre

El nombre del tipo de datos de la transformación.

nombre_idioma

El nombre del lenguaje de la transformación.

nombre_funcion_from_sql[(tipo_argumento [, ...])]

El nombre de la función para convertir el tipo desde el entorno SQL al lenguaje. Debe tomar un argumento de tipo internal y devolver tipo internal. El argumento real será del tipo para la transformación, y la función debe estar codificada como si lo fuera. (Pero no está permitido declarar una función a nivel SQL que devuelva internal sin al menos un argumento de tipo internal.) El valor de retorno real será algo específico de la implementación del lenguaje. Si no se especifica una lista de argumentos, el nombre de la función debe ser único en su esquema.

nombre_funcion_to_sql[(tipo_argumento [, ...])]

El nombre de la función para convertir el tipo desde el lenguaje al entorno SQL. Debe tomar un argumento de tipo internal y devolver el tipo que es el tipo para la transformación. El valor del argumento real será algo específico de la implementación del lenguaje. Si no se especifica una lista de argumentos, el nombre de la función debe ser único en su esquema.

NOTAS

Usa DROP TRANSFORM para eliminar transformaciones.

EJEMPLOS

Para crear una transformación para el tipo hstore y el lenguaje plpython3u, primero configura el tipo y el lenguaje:

CREATE TYPE hstore ...;
CREATE EXTENSION plpython3u;

Luego crea las funciones necesarias:

CREATE FUNCTION hstore_to_plpython(val internal) RETURNS internal
LANGUAGE C STRICT IMMUTABLE
AS ...;
CREATE FUNCTION plpython_to_hstore(val internal) RETURNS hstore
LANGUAGE C STRICT IMMUTABLE
AS ...;

Y finalmente crea la transformación para conectarlos a todos:

CREATE TRANSFORM FOR hstore LANGUAGE plpython3u (
    FROM SQL WITH FUNCTION hstore_to_plpython(internal),
    TO SQL WITH FUNCTION plpython_to_hstore(internal)
);

En la práctica, estos comandos estarían encapsulados en una extensión.

La sección contrib contiene una serie de extensiones que proporcionan transformaciones, las cuales pueden servir como ejemplos del mundo real.

COMPATIBILIDAD

Esta forma de CREATE TRANSFORM es una extensión de PostgreSQL. Existe un comando CREATE TRANSFORM en el estándar SQL, pero es para adaptar tipos de datos a lenguajes cliente. Ese uso no es compatible con PostgreSQL.
