CREATE FOREIGN TABLE(7) Documentación de PostgreSQL 18.1 CREATE FOREIGN TABLE(7)

NOMBRE

CREATE_FOREIGN_TABLE - define una nueva tabla externa

SINOPSIS

CREATE FOREIGN TABLE [ IF NOT EXISTS ] table_name ( [
  { column_name data_type [ OPTIONS ( option 'value' [, ... ] ) ] [ COLLATE collation ] [ column_constraint [ ... ] ]
    | table_constraint
    | LIKE source_table [ like_option ... ] }
    [, ... ]
] )
[ INHERITS ( parent_table [, ... ] ) ]
  SERVER server_name
[ OPTIONS ( option 'value' [, ... ] ) ]
CREATE FOREIGN TABLE [ IF NOT EXISTS ] table_name
  PARTITION OF parent_table [ (
  { column_name [ WITH OPTIONS ] [ column_constraint [ ... ] ]
    | table_constraint }
    [, ... ]
) ]
{ FOR VALUES partition_bound_spec | DEFAULT }
  SERVER server_name
[ OPTIONS ( option 'value' [, ... ] ) ]
donde column_constraint es:
[ CONSTRAINT constraint_name ]
{ NOT NULL [ NO INHERIT ] |
  NULL |
  CHECK ( expression ) [ NO INHERIT ] |
  DEFAULT default_expr |
  GENERATED ALWAYS AS ( generation_expr ) [ STORED | VIRTUAL ] }
[ ENFORCED | NOT ENFORCED ]
y table_constraint es:
[ CONSTRAINT constraint_name ]
{  NOT NULL column_name [ NO INHERIT ] |
   CHECK ( expression ) [ NO INHERIT ] }
[ ENFORCED | NOT ENFORCED ]
y like_option es:
{ INCLUDING | EXCLUDING } { COMMENTS | CONSTRAINTS | DEFAULTS | GENERATED | STATISTICS | ALL }
y partition_bound_spec es:
IN ( partition_bound_expr [, ...] ) |
FROM ( { partition_bound_expr | MINVALUE | MAXVALUE } [, ...] )
  TO ( { partition_bound_expr | MINVALUE | MAXVALUE } [, ...] ) |
WITH ( MODULUS numeric_literal, REMAINDER numeric_literal )

DESCRIPCIÓN

CREATE FOREIGN TABLE crea una nueva tabla externa en la base de datos actual. La tabla será propiedad del usuario que emite el comando.

Si se proporciona un nombre de esquema (por ejemplo, CREATE FOREIGN TABLE myschema.mytable ...) entonces la tabla se crea en el esquema especificado. De lo contrario, se crea en el esquema actual. El nombre de la tabla externa debe ser distinto del nombre de cualquier otra relación (tabla, secuencia, índice, vista, vista materializada o tabla externa) en el mismo esquema.

CREATE FOREIGN TABLE también crea automáticamente un tipo de datos que representa el tipo compuesto correspondiente a una fila de la tabla externa. Por lo tanto, las tablas externas no pueden tener el mismo nombre que cualquier tipo de datos existente en el mismo esquema.

Si se especifica la cláusula PARTITION OF, la tabla se crea como una partición de parent_table con los límites especificados.

Para poder crear una tabla externa, debe tener el privilegio USAGE en el servidor externo, así como el privilegio USAGE en todos los tipos de datos de columna utilizados en la tabla.

PARÁMETROS

IF NOT EXISTS

No lanzar un error si ya existe una relación con el mismo nombre. En este caso se emite un aviso. Tenga en cuenta que no hay garantía de que la relación existente sea parecida a la que se habría creado.

table_name

El nombre (opcionalmente calificado por esquema) de la tabla a crear.

column_name

El nombre de una columna a crear en la nueva tabla.

data_type

El tipo de datos de la columna. Esto puede incluir especificadores de array. Para más información sobre los tipos de datos soportados por PostgreSQL, refiérase al Capítulo 8.

COLLATE collation

La cláusula COLLATE asigna una regla de clasificación (collation) a la columna (que debe ser de un tipo de datos clasificable). Si no se especifica, se usa la regla de clasificación por defecto del tipo de datos de la columna.

INHERITS ( parent_table [, ... ] )

La cláusula opcional INHERITS especifica una lista de tablas de las cuales la nueva tabla externa hereda automáticamente todas las columnas. Las tablas padre pueden ser tablas normales o tablas externas. Vea la forma similar de CREATE TABLE para más detalles.

PARTITION OF parent_table { FOR VALUES partition_bound_spec | DEFAULT }

Esta forma se puede usar para crear la tabla externa como partición de la tabla padre dada con los valores de límite de partición especificados. Vea la forma similar de CREATE TABLE para más detalles. Tenga en cuenta que actualmente no se permite crear la tabla externa como partición de la tabla padre si hay índices UNIQUE en la tabla padre. (Vea también ALTER TABLE ATTACH PARTITION.)

LIKE source_table [ like_option ... ]

La cláusula LIKE especifica una tabla de la cual la nueva tabla copia automáticamente todos los nombres de columnas, sus tipos de datos y sus restricciones de no nulidad.

A diferencia de INHERITS, la nueva tabla y la tabla original quedan completamente desacopladas después de que se complete la creación. Los cambios en la tabla original no se aplicarán a la nueva tabla, y no es posible incluir datos de la nueva tabla en búsquedas de la tabla original.

También a diferencia de INHERITS, las columnas y restricciones copiadas por LIKE no se fusionan con columnas y restricciones de nombre similar. Si se especifica el mismo nombre explícitamente o en otra cláusula LIKE, se señala un error.

Las cláusulas opcionales like_option especifican qué propiedades adicionales de la tabla original copiar. Especificar INCLUDING copia la propiedad, especificar EXCLUDING omite la propiedad. EXCLUDING es el valor por defecto. Si se hacen múltiples especificaciones para el mismo tipo de objeto, se usa la última. Las opciones disponibles son:

INCLUDING COMMENTS

Se copiarán los comentarios de las columnas y restricciones copiadas. El comportamiento por defecto es excluir comentarios, lo que resulta en que las columnas y restricciones copiadas en la nueva tabla no tengan comentarios.

INCLUDING CONSTRAINTS

Se copiarán las restricciones CHECK. No se hace distinción entre restricciones de columna y restricciones de tabla. Las restricciones de no nulidad siempre se copian a la nueva tabla.

INCLUDING DEFAULTS

Se copiarán las expresiones por defecto de las definiciones de columna copiadas. De lo contrario, las expresiones por defecto no se copian, lo que resulta en que las columnas copiadas en la nueva tabla tengan valores por defecto nulos. Tenga en cuenta que copiar valores por defecto que llaman funciones de modificación de base de datos, como nextval,

INCLUDING GENERATED

Se copiarán las expresiones de generación de las definiciones de columna copiadas. Por defecto, las nuevas columnas serán columnas base regulares.

INCLUDING STATISTICS

Se copian estadísticas extendidas a la nueva tabla.

INCLUDING ALL

INCLUDING ALL es una forma abreviada que selecciona todas las opciones individuales disponibles. (Podría ser útil escribir cláusulas EXCLUDING individuales después de INCLUDING ALL para seleccionar todas menos algunas opciones específicas.)

CONSTRAINT constraint_name

Un nombre opcional para una restricción de columna o de tabla. Si se viola la restricción, el nombre de la restricción está presente en los mensajes de error, por lo que se pueden usar nombres de restricciones como col must be positive para comunicar información útil sobre la restricciones a las aplicaciones cliente. (Se necesitan comillas dobles para especificar nombres de restricción que contengan espacios.) Si no se especifica un nombre de restricción, el sistema genera un nombre.

NOT NULL [ NO INHERIT ]

No se permite que la columna contenga valores nulos.

Una restricción marcada con NO INHERIT no se propagará a las tablas hijas.

NULL

Se permite que la columna contenga valores nulos. Este es el valor por defecto.

Esta cláusula se proporciona solo por compatibilidad con bases de datos SQL no estándar. Se desaconseja su uso en nuevas aplicaciones.

CHECK ( expression ) [ NO INHERIT ]

La cláusula CHECK especifica una expresión que produce un resultado booleano que se espera que cada fila en la tabla externa satisfaga; es decir, la expresión debería producir TRUE o UNKNOWN, nunca FALSE, para todas las filas en la tabla externa. Una restricción CHECK especificada como restricción de columna debería referenciar solo el valor de esa columna, mientras que una expresión que aparece en una restricción de tabla puede referenciar múltiples columnas.

Actualmente, las expresiones CHECK no pueden contener subconsultas ni referenciar variables que no sean columnas de la fila actual. Se puede referenciar la columna del sistema tableoid, pero no cualquier otra columna del sistema.

Una restricción marcada con NO INHERIT no se propagará a las tablas hijas.

DEFAULT default_expr

La cláusula DEFAULT asigna un valor de datos por defecto para la columna cuya definición de columna aparece. El valor es cualquier expresión libre de variables (no se permiten subconsultas ni referencias cruzadas a otras columnas en la tabla actual). El tipo de datos de la expresión predeterminada debe coincidir con el tipo de datos de la columna.

La expresión predeterminada se utilizará en cualquier operación de inserción que no especifique un valor para la columna. Si no hay un valor predeterminado para una columna, entonces el valor predeterminado es nulo.

GENERATED ALWAYS AS ( generation_expr ) [ STORED | VIRTUAL ]

Esta cláusula crea la columna como una columna generada. La columna no se puede escribir, y al leerla se devolverá el resultado de la expresión especificada.

Cuando se especifica VIRTUAL, la columna se calculará cuando se lea. (El envoltorio de datos externos la verá como un valor nulo en las filas nuevas y puede optar por almacenarla como un valor nulo o ignorarla por completo.) Cuando se especifica STORED, la columna se calculará al escribir. (El valor calculado se presentará al envoltorio de datos externos para su almacenamiento y debe devolverse al leer.) VIRTUAL es el valor predeterminado.

La expresión de generación puede referirse a otras columnas en la tabla, pero no a otras columnas generadas. Cualquier función y operador utilizados deben ser inmutables. No se permiten referencias a otras tablas.

server_name

El nombre de un servidor externo existente a utilizar para la tabla externa. Para obtener detalles sobre cómo definir un servidor, consulte CREATE SERVER (CREATE_SERVER(7)).

OPTIONS ( option 'value' [, ...] )

Opciones a asociar con la nueva tabla externa o una de sus columnas. Los nombres y valores de opciones permitidos son específicos de cada envoltorio de datos externos y se validan utilizando la función de validación del envoltorio de datos externos. No se permiten nombres de opciones duplicados (aunque está bien que una opción de tabla y una opción de columna tengan el mismo nombre).

NOTAS

Las restricciones en tablas externas (como las cláusulas CHECK o NOT NULL) no son aplicadas por el sistema central de PostgreSQL, y la mayoría de los envoltorios de datos externos tampoco intentan aplicarlas; es decir, simplemente se asume que la restricción se cumple. No tendría mucho sentido aplicarlas ya que solo se aplicarían a filas insertadas o actualizadas a través de la tabla externa, y no a filas modificadas por otros medios, como directamente en el servidor remoto. En su lugar, una restricción adjunta a una tabla externa debe representar una restricción que está siendo aplicada por el servidor remoto.

Algunos envoltorios de datos externos de propósito especial podrían ser el único mecanismo de acceso para los datos a los que acceden, y en ese caso podría ser apropiado que el propio envoltorio de datos externos realice la aplicación de restricciones. Pero no debe asumir que un envoltorio hace eso a menos que su documentación lo diga.

Aunque PostgreSQL no intenta aplicar restricciones en tablas externas, sí asume que son correctas con fines de optimización de consultas. Si hay filas visibles en la tabla externa que no cumplen una restricción declarada, las consultas sobre la tabla podrían producir errores o respuestas incorrectas. Es responsabilidad del usuario asegurarse de que la definición de la restricción coincida con la realidad.


Precaución

Cuando una tabla externa se utiliza como una partición de una tabla particionada, existe una restricción implícita de que su contenido debe cumplir la regla de partición. Nuevamente, es responsabilidad del usuario asegurarse de que eso sea cierto, lo cual se hace mejor instalando una restricción coincidente en el servidor remoto.

Dentro de una tabla particionada que contiene particiones de tablas externas, un UPDATE que cambia el valor de la clave de partición puede causar que una fila se mueva de una partición local a una partición de tabla externa, siempre que el envoltorio de datos externos admita el enrutamiento de tuplas. Sin embargo, actualmente no es posible mover una fila de una partición de tabla externa a otra partición. Un UPDATE que requiriera hacer eso fallará debido a la restricción de partición, asumiendo que esa es aplicada correctamente por el servidor remoto.

Consideraciones similares se aplican a las columnas generadas. Las columnas generadas almacenadas se calculan en la inserción o actualización en el servidor PostgreSQL local y se entregan al envoltorio de datos externos para escribirlas en el almacén de datos externo, pero no se garantiza que una consulta de la tabla externa devuelva valores para las columnas generadas almacenadas que sean consistentes con la expresión de generación. Nuevamente, esto podría resultar en resultados de consulta incorrectos.

EJEMPLOS

Crear la tabla externa films, que se accederá a través del servidor film_server:

CREATE FOREIGN TABLE films (
    code        char(5) NOT NULL,
    title       varchar(40) NOT NULL,
    did         integer NOT NULL,
    date_prod   date,
    kind        varchar(10),
    len         interval hour to minute
)
SERVER film_server;

Crear la tabla externa measurement_y2016m07, que se accederá a través del servidor server_07, como una partición de la tabla particionada por rango measurement:

CREATE FOREIGN TABLE measurement_y2016m07
    PARTITION OF measurement FOR VALUES FROM ('2016-07-01') TO ('2016-08-01')
    SERVER server_07;

COMPATIBILIDAD

El comando CREATE FOREIGN TABLE se ajusta en gran medida al estándar SQL; sin embargo, al igual que con CREATE TABLE, se permiten restricciones NULL y tablas externas de cero columnas. La capacidad de especificar valores predeterminados de columna también es una extensión de PostgreSQL. La herencia de tablas, en la forma definida por PostgreSQL, no es estándar. La cláusula LIKE, tal como se admite en este comando, no es estándar.
