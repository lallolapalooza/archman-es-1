NOMBRE

CREATE_LANGUAGE - definir un nuevo lenguaje procedural

SINOPSIS

CREATE [ OR REPLACE ] [ TRUSTED ] [ PROCEDURAL ] LANGUAGE nombre
    HANDLER controlador_llamada [ INLINE controlador_inline ] [ VALIDATOR funcion_validacion ]
CREATE [ OR REPLACE ] [ TRUSTED ] [ PROCEDURAL ] LANGUAGE nombre

DESCRIPCIÓN

CREATE LANGUAGE registra un nuevo lenguaje procedural en una base de datos PostgreSQL. Posteriormente, se pueden definir funciones y procedimientos en este nuevo lenguaje.

CREATE LANGUAGE asocia efectivamente el nombre del lenguaje con función(es) controladora(s) que son responsables de ejecutar funciones escritas en el lenguaje. Consulte el Capítulo 57 para obtener más información sobre los controladores de lenguaje.

CREATE OR REPLACE LANGUAGE creará un nuevo lenguaje o reemplazará una definición existente. Si el lenguaje ya existe, sus parámetros se actualizan de acuerdo con el comando, pero la propiedad y la configuración de permisos del lenguaje no cambian, y se asume que las funciones existentes escritas en el lenguaje siguen siendo válidas.

Se debe tener el privilegio de superusuario de PostgreSQL para registrar un nuevo lenguaje o cambiar los parámetros de un lenguaje existente. Sin embargo, una vez creado el lenguaje, es válido asignarle la propiedad a un no superusuario, quien puede entonces eliminarlo, cambiar sus permisos, renombrarlo o asignárselo a un nuevo propietario. (Sin embargo, no asigne la propiedad de las funciones C subyacentes a un no superusuario; eso crearía una ruta de escalada de privilegios para ese usuario).

La forma de CREATE LANGUAGE que no proporciona ninguna función controladora está obsoleta. Por compatibilidad con versiones anteriores de archivos de volcado, se interpreta como CREATE EXTENSION. Esto funcionará si el lenguaje ha sido empaquetado en una extensión del mismo nombre, que es la forma convencional de configurar lenguajes procedurales.

PARÁMETROS

TRUSTED

TRUSTED especifica que el lenguaje no otorga acceso a datos a los que el usuario no tendría acceso de otra manera. Si se omite esta palabra clave al registrar el lenguaje, solo los usuarios con el privilegio de superusuario de PostgreSQL pueden usar este lenguaje para crear nuevas funciones.

PROCEDURAL

Esta es una palabra de relleno.

nombre

El nombre del nuevo lenguaje procedural. El nombre debe ser único entre los lenguajes de la base de datos.

HANDLER controlador_llamada

controlador_llamada es el nombre de una función previamente registrada que se llamará para ejecutar las funciones del lenguaje procedural. El controlador de llamada para un lenguaje procedural debe estar escrito en un lenguaje compilado como C con la convención de llamada versión 1 y registrado con PostgreSQL como una función que no toma argumentos y devuelve el tipo language_handler, un tipo marcador de posición que simplemente se usa para identificar la función como un controlador de llamada.

INLINE controlador_inline

controlador_inline es el nombre de una función previamente registrada que se llamará para ejecutar un bloque de código anónimo (comando DO) en este lenguaje. Si no se especifica ninguna función controlador_inline, el lenguaje no admite bloques de código anónimos. La función controladora debe tomar un argumento de tipo internal, que será la representación interna del comando DO, y típicamente devolverá void. El valor de retorno del controlador se ignora.

VALIDATOR funcion_validacion

funcion_validacion es el nombre de una función previamente registrada que se llamará cuando se cree una nueva función en el lenguaje, para validar la nueva función. Si no se especifica ninguna función validadora, entonces no se verificará una nueva función cuando se cree. La función validadora debe tomar un argumento de tipo oid, que será el OID de la función que se va a crear, y típicamente devolverá void.

Una función validadora típicamente inspeccionaría el cuerpo de la función en busca de corrección sintáctica, pero también puede examinar otras propiedades de la función, por ejemplo, si el lenguaje no puede manejar ciertos tipos de argumentos. Para señalar un error, la función validadora debe usar la función ereport(). El valor de retorno de la función se ignora.

NOTAS

Utilice DROP LANGUAGE para eliminar lenguajes procedurales.

El catálogo del sistema pg_language (ver Sección 52.29) registra información sobre los lenguajes actualmente instalados. Además, el comando psql \dL lista los lenguajes instalados.

Para crear funciones en un lenguaje procedural, un usuario debe tener el privilegio USAGE para el lenguaje. Por defecto, USAGE se otorga a PUBLIC (es decir, a todos) para lenguajes confiables. Esto se puede revocar si se desea.

Los lenguajes procedurales son locales a bases de datos individuales. Sin embargo, un lenguaje puede instalarse en la base de datos template1, lo que hará que esté disponible automáticamente en todas las bases de datos creadas posteriormente.

EJEMPLOS

Una secuencia mínima para crear un nuevo lenguaje procedural es:

CREATE FUNCTION plsample_call_handler() RETURNS language_handler
    AS '$libdir/plsample'
    LANGUAGE C;
CREATE LANGUAGE plsample
    HANDLER plsample_call_handler;

Normalmente, eso se escribiría en el script de creación de una extensión, y los usuarios harían esto para instalar la extensión:

CREATE EXTENSION plsample;

COMPATIBILIDAD

CREATE LANGUAGE es una extensión de PostgreSQL.
