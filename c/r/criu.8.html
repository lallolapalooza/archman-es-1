NOMBRE

usuario



SINOPSI

S

DESCRIPCIÓ

N

criu es una herramienta para realizar puntos de control y restaurar aplicaciones en ejecución. Lo hace guardando su estado como una colección de archivos (véase el comando dump) y creando procesos equivalentes a partir de esos archivos (véase el comando restore). La operación de restauración puede realizarse en un momento posterior, en un sistema diferente, o ambas

cosas.

stats).

--allow-uprobes

Permitir
el volcado cuando está presente el vma de uprobes. Cuando se usa en el volcado, esta opción también es necesaria en la 
restauración.
Un vma de uprobes es creado automáticamente por el kernel una vez que se dispara un uprobe. Este mapeo no se elimina in
cluso una vez que el uprobe es borrado. Así que, incluso si un proceso tuvo uprobes adjuntos y estos son removidos al momento de volca
r el proceso, esta opción sigue siendo necesaria porque criu no tiene forma de saber si hay uprobes activos o no. Al usar esta opción 
en la restauración, asegúrese de que los uprobes (si los hay) activos en los procesos vol
cados sigan activos. De lo contrario, cuando la ejecución llegue a una ubicación con uprob
e en cualquiera de los procesos restaurados, a ese proceso se le enviará un SIGTRAP. Como 
ejemplo, digamos que un uprobe está establecido en la función foo en el ejecutable del proceso p_bar. Cada vez que la ejecución en p_bar llega a la función
foo, el uprobe se dispara. Si el uprobe se ha disparado al menos una vez, entonces el kernel habrá creado el vma de uprobes. Para volcar p_bar, esta opció
n es necesaria. Después de volcar, digamos que el uprobe es borrado. Ahora, al restaurar con esta opción, una vez que la ejecución llegue a la función foo
, se enviará SIGTRAP al p_bar restaurado. A menos que tenga un manejador de señales instalado para SIGTRAP, será terminado y generará un volcado de memoria

ARCHIVOS DE

CONFIGURACIÓN

Criu soporta el uso de archivos de configuración para evitar la necesidad de escribir cada opción en la línea de comandos, lo cual es útil especialmente con el uso repetido de las mismas opciones. Un archivo de configuración específico se puede pasar con la opción "--config file". Si no se pasa ningún archivo, se analizan los archivos de configuración por defecto /etc/criu/default.conf y $HOME/.criu/default.conf (si están presentes en el sistema). Si la variable de entorno CRIU_CONFIG_FILE está establecida, también se

analizará.

Las opciones pasadas a CRIU a través de CLI, RPC o archivo de configuración se evalúan en el siguiente

orden:
•apply_config(/etc/criu/default.
conf)
•apply_config($HOME/.criu/default.
conf)
•apply_config(CRIU_CONFIG_FILE
)
•apply_config(--config file
)
•apply_config(CLI) o apply_config(RPC
)
•apply_config(archivo de configuración RPC) (solo para modo
RPC)

El análisis del archivo de configuración por defecto se puede desactivar con "--no-default-config" si es necesario. Los archivos de configuración analizados se fusionan con las opciones de la línea de comandos, lo que permite anular opciones

booleanas.



Sintaxis del archivo de

configuración

Se admiten comentarios usando el signo '#'. El resto de la línea se ignora. Las opciones son las mismas que las opciones de la línea de comandos sin el prefijo '--', use una opción por línea (con el argumento correspondiente si aplica, dividido por espacios en blanco). Si es necesario, el argumento se puede proporcionar entre comillas dobles (esto solo debería ser necesario si el argumento contiene espacios en blanco). En el caso de que este tipo de argumento contenga también una comilla doble literal, se puede escapar usando el signo '\'. El uso de comandos no está permitido y todas las demás secuencias de escape se interpretan

literalmente.

Ejemplo de archivo de configuración para ilustrar la

sintaxis: 
$ cat ~/.criu/default.conf
tcp-established
work-dir "/
home/USERNAME/criu/my \"work\" directory" #this is a
comment no-restore-sibling # this is another comment



Configuarchivos de configuración en modo

RPC

No solo criu evalúa los archivos de configuración en modo CLI, sino que también evalúa los archivos de configuración en modo RPC. Al igual que en el modo CLI, los valores del archivo de configuración se evalúan primero. Esto significa que cualquier opción establecida mediante RPC sobrescribirá la configuración del archivo. El usuario puede así cambiar el comportamiento predeterminado de criu, pero no es posible cambiar la configuración que el cliente RPC ha establecido

explícitamente.

Sin embargo, el cliente RPC puede especificar un archivo de configuración adicional que se evaluará después de las opciones RPC (véase más arriba el orden de evaluación de las opciones). El cliente RPC puede especificar este archivo de configuración adicional mediante "req.opts.config_file = /path/to/file". Los valores de este archivo de configuración sobrescribirán todas las demás configuraciones de archivos o opciones RPC. Esto puede conducir a un comportamiento no deseado de criu y solo debe usarse con

cuidado.



SIN

ROOT

criu puede usarse sin root con la capacidad CAP_SYS_ADMIN o con la capacidad CAP_CHECKPOINT_RESTORE introducida en el kernel de Linux 5.9. CAP_CHECKPOINT_RESTORE es lo mínimo

necesario.

criu también necesita ya sea CAP_SYS_PTRACE o un valor de 0 en /proc/sys/kernel/yama/ptrace_scope

(véase

ptrace(2)) para poder interrumpir el proceso para el volcado. Ejecuta

r

criu como no root tiene muchas limitaciones y dependiendo del proceso a guardar y restaurar puede no ser posible. Además de CAP_CHECKPOINT_RESTORE, es posible dar

a

criu capacidades adicionales para habilitar funciones adicionales en modo no root. Actualment

e
criu puede beneficiarse de las siguientes capacidades adicionales:
•
CAP_NET_ADMIN
•
CAP_SYS_CHROOT
•
CAP_SETUID
•

CAP_SYS_RESOURCE Tenga en cuenta que para algunas operaciones, tener una capacidad en un namespace distinto del namespace init (es decir, el namespace root/predeterminado) no es suficiente. Por ejemplo, para leer enlaces simbólicos en proc/[pid]/map_files CRIU requiere CAP_CHECKPOINT_RESTORE en el namespace init; tener CAP_CHECKPOINT_RESTORE mientras se ejecuta en otro namespace de usuario (p. ej. en un contenedor) no permite a CRIU leer enlaces simbólicos en /proc/[pid]

/map_files.

Sin acceso a /proc/[pid]/map_files, el guardado/restauración de procesos que tienen archivos eliminados mapeados puede no ser

posible.

Independientemente de las capacidades, siempre es necesario usar "--unprivileged" para aceptar las limitaciones de criu en modo no

root.
