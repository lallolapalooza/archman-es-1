DESCRIPCIÓ

N

CREATE FUNCTION define una nueva función. CREATE OR REPLACE FUNCTION creará una nueva función o reemplazará una definición existente. Para poder definir una función, el usuario debe tener el privilegio USAGE sobre el

lenguaje.

Si se incluye un nombre de esquema, la función se crea en el esquema especificado. De lo contrario, se crea en el esquema actual. El nombre de la nueva función no debe coincidir con ninguna función o procedimiento existente con los mismos tipos de argumentos de entrada en el mismo esquema. Sin embargo, las funciones y procedimientos de diferentes tipos de argumentos pueden compartir un nombre (esto se llama sobrecarga)

.

Para reemplazar la definición actual de una función existente, use CREATE OR REPLACE FUNCTION. No es posible cambiar el nombre o los tipos de argumentos de una función de esta manera (si lo intentara, estaría creando en realidad una nueva función distinta). Además, CREATE OR REPLACE FUNCTION no le permitirá cambiar el tipo de retorno de una función existente. Para hacerlo, debe eliminar y recrear la función. (Al usar parámetros OUT, eso significa que no puede cambiar los tipos de ningún parámetro OUT excepto eliminando la función.

)

Cuando CREATE OR REPLACE FUNCTION se usa para reemplazar una función existente, la propiedad y los permisos de la función no cambian. Todas las demás propiedades de la función se asignan los valores especificados o implícitos en el comando. Debe ser propietario de la función para reemplazarla (esto incluye ser miembro del rol propietario)

.

Si elimina y luego recrea una función, la nueva función no es la misma entidad que la antigua; tendrá que eliminar las reglas, vistas, disparadores, etc. existentes que se refieran a la función antigua. Use CREATE OR REPLACE FUNCTION para cambiar una definición de función sin romper objetos que se refieran a la función. Además, ALTER FUNCTION se puede usar para cambiar la mayoría de las propiedades auxiliares de una función

existente.

El usuario que crea la función se convierte en el propietario de la

función.

Para poder crear una función, debe tener el privilegio USAGE sobre los tipos de argumentos y el tipo de

retorno.

Consulte la Sección 36.3 para

obtener más información sobre
la escritura de funciones.

IMMUTABLE
STABLE
VOLATIL

E
Estos atributos informan al optimizador de consultas sobre el comportamiento de la función. Se puede especificar como máximo una opción. Si ninguna de estas aparece, VOLATILE es la suposición predeterminada.

IMMUTABLE indica que la función no puede modificar la base de datos y siempre devuelve el mismo resultado cuando se le dan los mismos valores de argumento; es decir, no realiza búsquedas en la base de datos ni usa de otra manera información no directamente presente en su lista de argumentos. Si se da esta opción, cualquier llamada de la función con argumentos todos constantes puede reemplazarse inmediatamente con el valor de la

función.

STABLE indica que la función no puede modificar la base de datos y que dentro de un solo escaneo de tabla devolverá consistentemente el mismo resultado para los mismos valores de argumento, pero que su resultado podría cambiar entre sentencias SQL. Esta es la selección apropiada para funciones cuyos resultados dependen de búsquedas en la base de datos, variables de parámetro (como la zona horaria actual), etc. (No es apropiada para disparadores AFTER que deseen consultar filas modificadas por la actualmmand.) También ten en cuenta que la familia de funciones current_timestamp se califican como estables, ya que sus valores no cambian dentro de una

transacción.

VOLATILE indica que el valor de la función puede cambiar incluso dentro de un solo escaneo de tabla, por lo que no se pueden realizar optimizaciones. Relativamente pocas funciones de la base de datos son volátiles en este sentido; algunos ejemplos son random(), currval(), timeofday(). Pero ten en cuenta que cualquier función que tenga efectos secundarios debe clasificarse como volátil, aunque su resultado sea bastante predecible, para evitar que las llamadas se optimicen; un ejemplo es setval()

.

LEAKPROO

F
LEAKPROOF indica que la función no tiene efectos secundarios. No revela información sobre sus argumentos que no sea a través de su valor de retorno. Por ejemplo, una función que lanza un mensaje de error para algunos valores de argumento pero no para otros, o que incluye los valores de los argumentos en cualquier mensaje de error, no es a prueba de fugas (leakproof). Esto afecta a cómo el sistema ejecuta consultas contra vistas creadas con la opción security_barrier o tablas con seguridad a nivel de fila habilitada. El sistema hará cumplir las condiciones de las políticas de seguridad y las vistas de barrera de seguridad antes de cualquier condición proporcionada por el usuario de la consulta en sí que contenga funciones no a prueba de fugas, para evitar la exposición inadvertida de datos. Las funciones y operadores marcados como a prueba de fugas se consideran confiables y pueden ejecutarse antes de las condiciones de las políticas de seguridad y las vistas de barrera de seguridad. Además, las funciones que no toman argumentos o a las que no se les pasan argumentos desde la vista de barrera de seguridad o la tabla no tienen que estar marcadas como a prueba de fugas para ejecutarse antes de las condiciones de seguridad. Consulta CREATE VIEW (CREATE_VIEW(7)) y la Sección 39.5. Esta opción solo puede ser establecida por el
superusuario.

PARALLE

L
PARALLEL UNSAFE indica que la función no puede ejecutarse en modo paralelo; la presencia de una función de este tipo en una sentencia SQL fuerza un plan de ejecución serial. Este es el valor por defecto. PARALLEL RESTRICTED indica que la función puede ejecutarse en modo paralelo, pero solo en el proceso líder del grupo paralelo. PARALLEL SAFE indica que la función es segura para ejecutar en modo paralelo sin restricciones, incluyendo en procesos trabajadores paralelos.

Las funciones deben etiquetarse como paralelo inseguras si modifican cualquier estado de la base de datos, cambian el estado de la transacción (distinto del uso de una subtransacción para la recuperación de errores), acceden a secuencias (por ejemplo, llamando a currval) o realizan cambios persistentes en la configuración. Deben etiquetarse como paralelo restringidas si acceden a tablas temporales, estado de la conexión del cliente, cursores, se

ntencias preparadas o estado local diverso del backend que el sistema no puede sincronizar en modo paralelo (por ejemplo, setseed no puede ejecutarse que no sea por el líder del grupo porque un cambio hecho por otro proceso no se reflejaría en el líder). En general, si una función está etiquetada como segura cuando en realidad es restringida o insegura, o si está etiquetada como restringida cuando en realidad es insegura, puede lanzar errores o
producir respuestas incorrectas cuando se use en una consulta paralela. Las funciones en lenguaje C podrían en teoría exhibir un comportamiento totalmente indefinido si se etiquetan mal, ya que no hay forma de que el sistema se proteja contra código C arbitrario, pero en la mayoría de los casos el resultado no será peor que para cualquier otra función. En caso de duda, las funciones deben etiquetarse como UNSAFE, que es el valor por defecto.

SOBRECARG

A

PostgreSQL permite la sobrecarga de funciones; es decir, el mismo nombre puede usarse para varias funciones diferentes siempre que tengan tipos de argumento de entrada distintos. Ya sea que lo uses o no, esta capacidad implica precauciones de seguridad al llamar funciones en bases de datos donde algunos usuarios desconfían de otros usuarios; consulta la Sección 10.

3.

Dos funciones se consideran la misma si tienen los mismos nombres y tipos de argumento de entrada, ignorando cualquier parámetro OUT. Así que, por ejemplo, estas declaraciones entran en

conflicto:

CREATE FUNCTION foo(int, out text) .
.
.

Las funciones que tienen listas de tipos de argumento diferentes no se considerarán en conflicto en el momento de la creación, pero si se proporcionan valores por defecto podrían entrar en conflicto en el uso. Por ejemplo,

considera

.

NOTA

S

Se permite la sintaxis completa de tipos de SQL para declarar los argumentos de una función y su valor de retorno. Sin embargo, los modificadores de tipo entre paréntesis (por ejemplo, el campo de precisión para el tipo numeric) son descartados por CREATE FUNCTION. Así que, por ejemplo, CREATE FUNCTION foo (varchar(10)) ... es exactamente lo mismo que CREATE FUNCTION foo (varchar) ..

.

Al reemplazar una función existente con CREATE OR REPLACE FUNCTION, hay restricciones al cambiar los nombres de los parámetros. No puedes cambiar el nombre ya asignado a ningún parámetro de entrada (aunque puedes añadir nombres a parámetros que no los tenían antes). Si hay más de un parámetro de salida, no puedes cambiar los nombres de los parámetros de salida, porque eso cambiaría los nombres de las columnas del tipo compuesto anónimo que describe el resultado de la función. funcionar
