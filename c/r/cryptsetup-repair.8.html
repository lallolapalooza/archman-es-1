CRYPTSETUP-REPAIR(8) Comandos de mantenimiento CRYPTSETUP-REPAIR(8)

NOMBRE

cryptsetup-repair - repara los metadatos del dispositivo

SINOPSIS

cryptsetup repair [<opciones>] <dispositivo>

DESCRIPCIÓN

Intenta reparar los metadatos del dispositivo si es posible. Actualmente solo se admite para el tipo de dispositivo LUKS.

Este comando es útil para corregir algunas corrupciones conocidas y benignas de los metadatos LUKS. Solo se pueden corregir las corrupciones básicas de un ranura de clave (keyslot) no utilizada. Este comando solo cambiará la cabecera LUKS, no los datos de ninguna ranura de clave. Puede forzar la versión de LUKS añadiendo la opción --type.

También repara (actualiza) los metadatos de recifrado de LUKS2 añadiendo un resumen de metadatos que lo protege contra cambios maliciosos.

Si el recifrado de LUKS2 se interrumpió mientras se escribía el segmento de recifrado, el comando de reparación puede realizar la recuperación del recifrado para que el recifrado pueda continuar más tarde. La reparación del recifrado requiere la verificación de la ranura de clave de recifrado, por lo que se necesita una frase de contraseña o un archivo de clave.

ADVERTENCIA: Cree siempre una copia de seguridad binaria de la cabecera original antes de llamar a este comando.

Detección de corrupción de ranuras de clave LUKS

El comando de reparación también comprueba la corrupción detectable del contenido de la ranura de clave. La corrupción de una ranura de clave da como resultado una situación en la que una contraseña conocida ya no es aceptada. Puede ocurrir debido a un fallo del medio de almacenamiento o al sobrescribir el área de la ranura de clave con otros datos. Solo se pueden detectar ciertas corrupciones, generalmente solo un área de baja entropía (como bloques a cero).

La detección solo imprime advertencias. No modifica las ranuras de clave. También puede imprimir desplazamientos más específicos en el dispositivo para una inspección manual detallada.

Tenga en cuenta que la advertencia puede ser un falso positivo (no ocurrió ninguna corrupción real). A la inversa, si la ranura de clave está corrupta, no es posible la recuperación. Debe utilizar la copia de seguridad de la cabecera LUKS.

<opciones> puede ser [--timeout, --verify-passphrase, --disable-locks, --type, --header, --key-file, --keyfile-size, --keyfile-offset, --key-slot].

OPCIONES

--batch-mode, -q

Suprime todas las preguntas de confirmación. ¡Úselo con cuidado!

Si no se especifica la opción --verify-passphrase, esta opción también desactiva la verificación de la frase de contraseña.

--debug o --debug-json

Se ejecuta en modo de depuración con registros de diagnóstico completos. Las líneas de salida de depuración siempre están precedidas por #.

Si se usa --debug-json, se imprimen las estructuras de datos JSON adicionales de LUKS2.

--disable-locks

Desactiva la protección de bloqueo para los metadatos en disco. Esta opción solo es válida para LUKS2 y se ignora para otros formatos.

ADVERTENCIA: No use esta opción a menos que ejecute cryptsetup en un entorno restringido donde sea imposible realizar el bloqueo (donde no se pueda usar el directorio /run).

--header <dispositivo o archivo que almacena la cabecera LUKS>

Utiliza un dispositivo o archivo de metadatos desprendido (separado) donde se almacena la cabecera LUKS. Esta opción permite almacenar el texto cifrado y la cabecera LUKS en dispositivos diferentes.

Para los comandos que cambian la cabecera LUKS (por ejemplo, luksAddKey), especifique el dispositivo o archivo con la cabecera LUKS directamente como el dispositivo LUKS.

--help, -?

Muestra el texto de ayuda y los parámetros predeterminados.

--key-file, -d archivo

Lee la frase de contraseña del archivo.

Si el nombre dado es "-", la frase de contraseña se leerá de stdin. En este caso, la lectura no se detendrá en los caracteres de nueva línea.

Vea la sección NOTAS SOBRE EL PROCESAMIENTO DE FRASES DE CONTRASEÑA en cryptsetup(8) para más información.

--keyfile-offset valor

Omite valor bytes al principio del archivo de clave.

--keyfile-size, -l valor

Lee un máximo de valor bytes del archivo de clave. El valor predeterminado es leer el archivo completo hasta el máximo compilado que puede consultarse con --help. Si se proporcionan más datos que el máximo compilado, se aborta la operación.

Esta opción es útil, por ejemplo, para cortar las nuevas líneas finales. Si también se da --keyfile-offset, el recuento de tamaño comienza después del desplazamiento.

--key-slot, -S <0-N>

Para las operaciones de LUKS que añaden material de clave, esta opción le permite especificar qué ranura de clave se selecciona para la nueva clave.

El número máximo de ranuras de clave depende de la versión de LUKS. LUKS1 puede tener hasta 8 ranuras de clave. LUKS2 puede tener hasta 32 ranuras de clave basadas en el tamaño del área de la ranura de clave y el tamaño de la clave, pero un ID de ranura de clave válido siempre puede estar entre 0 y 31 para LUKS2.

--timeout, -t segundos

El número de segundos a esperar antes de que se produzca un tiempo de espera en la entrada de la frase de contraseña a través del terminal. Es relevante cada vez que se pide una frase de contraseña. No tiene efecto si se usa junto con --key-file.

Esta opción es útil cuando el sistema no debe bloquearse si el usuario no introduce una frase de contraseña, por ejemplo, durante el arranque. El valor predeterminado es 0 segundos, lo que significa esperar para siempre.

--type tipo

Especifica el tipo de dispositivo requerido, para más información, lea la SECCIÓN DE ACCIONES BÁSICAS en cryptsetup(8).

--usage

Muestra la ayuda corta de las opciones.

--verify-passphrase, -y

Al pedir interactivamente una frase de contraseña, la pide dos veces y se queja si ambas entradas no coinciden. Se ignora en la entrada desde un archivo o stdin.

--version, -V

Muestra la versión del programa.

INFORME DE ERRORES

Informe de errores en la lista de correo de cryptsetup <cryptsetup@lists.linux.dev> o en la sección de problemas del proyecto https://gitlab.com/cryptsetup/cryptsetup/-/issues/new.

Por favor, adjunte la salida del comando fallido con la opción --debug añadida.
