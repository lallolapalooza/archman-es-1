SINOPSI

S

cryptsetup token <add|remove|import|export|unassign> [<opciones>] <dispositivo>

DESCRIPCIÓ

N

La acción add crea un nuevo token de llavero para permitir la autoactivación del dispositivo. Para la autoactivación, la frase de paso debe almacenarse en el llavero con la descripción especificada. Normalmente, la frase de paso debería almacenarse en el llavero user o user-session. El comando token solo se admite para

LUKS2.

Para añadir un nuevo token de llavero, la opción --key-description es obligatoria. Además, un nuevo token se asigna al keyslot especificado con la opción --key-slot o a todos los keyslots activos si se omite la opción

--key-slot.

Para eliminar un token existente, especifique el ID del token que debe eliminarse con la opción

--token-id.

ADVERTENCIA: La acción token remove elimina cualquier tipo de token, no solo el tipo keyring del slot de token especificado por la opción

--token-id.

La acción import puede almacenar datos JSON arbitrarios válidos en el token LUKS2. Se puede pasar a través de la entrada estándar o de un archivo pasado en la opción --json-file. Si especifica --key-slot, un token importado con éxito también se asigna al

keyslot.

La acción export escribe el JSON del token solicitado en un archivo pasado con --json-file o en la salida

estándar.

La acción unassign elimina la unión del token al keyslot especificado. Tanto el token como el keyslot deben especificarse con los parámetros --token-id y

--key-slot.

Si se usa --token-id con la acción add o la acción import y ya existe un token con ese ID, la opción --token-replace puede reemplazar el token

existente.

<opciones> puede ser [--header, --token-id, --key-slot, --key-description, --disable-external-tokens, --

disable-locks, --disable-keyring, --json-file, --
token-replace, --unbound, --external tokens-path].

Desactiva la protección de bloqueo de los metadatos en disco. Esta opción solo es válida para LUKS2 y se ignora para otros formatos.

Anula la ruta del directorio del sistema donde cryptsetup busca manejadores de tokens externos (o plugins de token). Debe ser una ruta absoluta (que comienza con el carácter '/')

--header <dispositivo o archivo que almacena la cabecera

LUKS>
Usa un dispositivo o archivo de metadatos desprendido (separado) donde se almacena la cabecera LUKS. Esta opción permite almacenar el texto cifrado y la cabecera LUKS en diferentes dispositivos.

Para los comandos que cambian la cabecera LUKS (por ejemplo, luksAddKey), especifique el dispositivo o archivo con la

--key-description text

o
Establece la descripción de la clave en el llavero que se usará para la recuperación de la frase de

--key-slot, -S <0-N

>
Para las operaciones LUKS que añaden material de clave, esta opción le permite especificar qué keyslot se selecciona para la nueva clave.

El número máximo de keyslots depende de la versión de LUKS. LUKS1 puede tener hasta 8 keys

lots. LUKS2 puede tener hasta 32 keyslots basados en el tamaño del área de keyslot y el tam
año de la clave, pero un ID de keyslot válido siempre puede estar entre 0 y 31 para LUKS2.
