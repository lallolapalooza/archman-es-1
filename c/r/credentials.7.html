NOMBRE

credentials - identificadores de procesos

DESCRIPCIÓN

ID de proceso (PID)

Cada proceso tiene un identificador entero no negativo único que se asigna cuando el proceso se crea usando fork(2). Un proceso puede obtener su PID usando getpid(2). Un PID se representa usando el tipo pid_t (definido en <sys/types.h>).

Los PIDs se utilizan en una variedad de llamadas al sistema para identificar el proceso afectado por la llamada, por ejemplo: kill(2), ptrace(2), setpriority(2), setpgid(2), setsid(2), sigqueue(3), y waitpid(2).

El PID de un proceso se conserva a través de un execve(2).

ID de proceso padre (PPID)

El ID de proceso padre de un proceso identifica el proceso que creó este proceso usando fork(2). Un proceso puede obtener su PPID usando getppid(2). Un PPID se representa usando el tipo pid_t.

El PPID de un proceso se conserva a través de un execve(2).

ID de grupo de proceso y ID de sesión

Cada proceso tiene un ID de sesión y un ID de grupo de proceso, ambos representados usando el tipo pid_t. Un proceso puede obtener su ID de sesión usando getsid(2), y su ID de grupo de proceso usando getpgrp(2).

Un hijo creado por fork(2) hereda el ID de sesión y el ID de grupo de proceso de su padre. El ID de sesión y el ID de grupo de proceso de un proceso se conservan a través de un execve(2).

Las sesiones y los grupos de proceso son abstracciones concebidas para soportar el control de trabajos del shell. Un grupo de proceso (a veces llamado "trabajo") es una colección de procesos que comparten el mismo ID de grupo de proceso; el shell crea un nuevo grupo de proceso para los procesos usados para ejecutar un solo comando o una canalización (por ejemplo, los dos procesos creados para ejecutar el comando "ls | wc" se colocan en el mismo grupo de proceso). La pertenencia de un proceso a un grupo puede establecerse usando setpgid(2). El proceso cuyo ID de proceso es el mismo que su ID de grupo de proceso es el líder de grupo de proceso de ese grupo.

Una sesión es una colección de procesos que comparten el mismo ID de sesión. Todos los miembros de un grupo de proceso también tienen el mismo ID de sesión (es decir, todos los miembros de un grupo de proceso siempre pertenecen a la misma sesión, de modo que las sesiones y los grupos de proceso forman una jerarquía estricta de dos niveles de procesos). Se crea una nueva sesión cuando un proceso llama a setsid(2), lo que crea una nueva sesión cuyo ID de sesión es el mismo que el PID del proceso que llamó a setsid(2). El creador de la sesión se llama el líder de sesión.

Todos los procesos de una sesión comparten una terminal de control. La terminal de control se establece cuando el líder de sesión abre una terminal por primera vez (a menos que se especifique la bandera O_NOCTTY al llamar a open(2)). Una terminal puede ser la terminal de control de como máximo una sesión.

Como máximo uno de los trabajos de una sesión puede ser el trabajo de primer plano; los otros trabajos de la sesión son trabajos de segundo plano. Solo el trabajo de primer plano puede leer de la terminal; cuando un proceso en segundo plano intenta leer de la terminal, se envía a su grupo de proceso una señal SIGTTIN , que suspende el trabajo. Si se ha establecido la bandera TOSTOP para la terminal (ver termios(3)), entonces solo el trabajo de primer plano puede escribir en la terminal; las escrituras desde trabajos de segundo plano causan que se genere una señal SIGTTOU , que suspende el trabajo. Cuando se presionan teclas de terminal que generan una señal (como la tecla de interrupción , normalmente control-C), la señal se envía a los procesos del trabajo de primer plano.

Varias llamadas al sistema y funciones de biblioteca pueden operar en todos los miembros de un grupo de proceso, incluyendo kill(2), killpg(3), getpriority(2), setpriority(2), ioprio_get(2), ioprio_set(2), waitid(2), y waitpid(2). Ver también la discusión de las operaciones F_GETOWN, F_GETOWN_EX, F_SETOWN, y F_SETOWN_EX en fcntl(2).

Identificadores de usuario y de grupo

Cada proceso tiene varios IDs de usuario y de grupo asociados. Estos IDs son enteros, representados respectivamente usando los tipos uid_t y gid_t (definidos en <sys/types.h>).

En Linux, cada proceso tiene los siguientes identificadores de usuario y de grupo:

•
ID de usuario real y ID de grupo real. Estos IDs determinan quién es el dueño del proceso. Un proceso puede obtener su ID de usuario (grupo) real usando getuid(2) (getgid(2)).
•
ID de usuario efectivo y ID de grupo efectivo. El kernel usa estos IDs para determinar los permisos que el proceso tendrá al acceder a recursos compartidos como colas de mensajes, memoria compartida y semáforos. En la mayoría de los sistemas UNIX, estos IDs también determinan los permisos al acceder a archivos. Sin embargo, Linux usa los IDs del sistema de archivos descritos más abajo para esta tarea. Un proceso puede obtener su ID de usuario (grupo) efectivo usando geteuid(2) (getegid(2)).
•
ID de usuario estable (set-user-ID) guardado y ID de grupo estable (set-group-ID) guardado. Estos IDs se usan en programas con set-user-ID y set-group-ID para guardar una copia de los IDs efectivos correspondientes que se establecieron cuando se ejecutó el programa (ver execve(2)). Un programa con set-user-ID puede asumir y renunciar a privilegios alternando su ID de usuario efectivo entre los valores de su ID de usuario real y su ID de usuario estable guardado. Este alternamiento se realiza mediante llamadas a seteuid(2), setreuid(2), o setresuid(2). Un programa con set-group-ID realiza las tareas análogas usando setegid(2), setregid(2), o setresgid(2). Un proceso puede obtener su ID de usuario estable guardado (ID de grupo estable guardado) usando getresuid(2) (getresgid(2)).
•
ID de usuario del sistema de archivos y ID de grupo del sistema de archivos (específico de Linux). Estos IDs, en conjunto con los IDs de grupo suplementarios descritos más abajo, se usan para determinar los permisos de acceso a archivos; ver path_resolution(7) para más detalles. Cada vez que se cambia el ID de usuario (grupo) efectivo de un proceso, el kernel también cambia automáticamente el ID de usuario (grupo) del sistema de archivos al mismo valor. En consecuencia, los IDs del sistema de archivos normalmente tienen los mismos valores que los IDs efectivos correspondientes, y la semántica de las comprobaciones de permisos de archivos es así la misma en Linux como en otros sistemas UNIX. Los IDs del sistema de archivos pueden hacerse diferentes de los IDs efectivos llamando a setfsuid(2) y setfsgid(2).
•
IDs de grupo suplementarios. Este es un conjunto de IDs de grupo adicionales que se usan para comprobaciones de permisos al acceder a archivos y otros recursos compartidos. Antes de Linux 2.6.4, un proceso podía ser miembro de hasta 32 grupos suplementarios; desde Linux 2.6.4, un proceso puede ser miembro de hasta 65536 grupos suplementarios. La llamada sysconf(_SC_NGROUPS_MAX) puede usarse para determinar el número de grupos suplementarios de los que un proceso puede ser miembro. Un proceso puede obtener su conjunto de IDs de grupo suplementarios usando getgroups(2).

Un proceso hijo creado por >fork(2) hereda copias de los identificadores de usuario y de grupo de su proceso padre. Durante un execve(2), los identificadores de usuario y de grupo reales de un proceso y los identificadores de grupo suplementarios se conservan; los identificadores efectivos y de conjunto guardado pueden cambiar, como se describe en execve(2).

Además de los propósitos mencionados anteriormente, los identificadores de usuario de un proceso también se emplean en varios otros contextos:

•
al determinar los permisos para enviar señales (véase kill(2));
•
al determinar los permisos para establecer parámetros de planificación de procesos (valor de nice, política y prioridad de planificación en tiempo real, afinidad de CPU, prioridad de E/S) usando setpriority(2), sched_setaffinity(2), sched_setscheduler(2), sched_setparam(2), sched_setattr(2), y ioprio_set(2);
•
al comprobar los límites de recursos (véase getrlimit(2));
•
al comprobar el límite en el número de instancias de inotify que el proceso puede crear (véase inotify(7)).

Modificación de los identificadores de usuario y de grupo de un proceso

Sujeto a las reglas descritas en las páginas de manual correspondientes, un proceso puede usar las siguientes API para modificar sus identificadores de usuario y de grupo:

setuid(2)(setgid(2))
Modifica el identificador de usuario (grupo) real (y posiblemente efectivo y de conjunto guardado) del proceso.
seteuid(2)(setegid(2))
Modifica el identificador de usuario (grupo) efectivo del proceso.
setfsuid(2)(setfsgid(2))
Modifica el identificador de usuario (grupo) del sistema de archivos del proceso.
setreuid(2)(setregid(2))
Modifica los identificadores de usuario (grupo) real y efectivo (y posiblemente de conjunto guardado) del proceso.
setresuid(2)(setresgid(2))
Modifica los identificadores de usuario (grupo) real, efectivo y de conjunto guardado del proceso.
setgroups(2)
Modifica la lista de grupos suplementarios del proceso.

Cualquier cambio en el identificador de usuario (grupo) efectivo de un proceso se traslada automáticamente al identificador de usuario (grupo) del sistema de archivos del proceso. Los cambios en el identificador de usuario o de grupo efectivo de un proceso también pueden afectar al atributo "dumpable" (volcable) del proceso, como se describe en prctl(2).

Los cambios en los identificadores de usuario y de grupo de un proceso pueden afectar a las capacidades del proceso, como se describe en capabilities(7).

ESTÁNDARES

Los identificadores de proceso, los identificadores de proceso padre, los identificadores de grupo de proceso y los identificadores de sesión están especificados en POSIX.1. Los identificadores de usuario y de grupo reales, efectivos y de conjunto guardado, y los identificadores de grupo suplementarios, están especificados en POSIX.1.

Los identificadores de usuario y de grupo del sistema de archivos son una extensión de Linux.

NOTAS

Varios campos del archivo /proc/pid/status muestran las credenciales del proceso descritas anteriormente. Véase proc(5) para más información.

La especificación de hilos POSIX requiere que las credenciales sean compartidas por todos los hilos de un proceso. Sin embargo, a nivel de kernel, Linux mantiene credenciales de usuario y de grupo separadas para cada hilo. La implementación de hilos NPTL realiza un trabajo para asegurar que cualquier cambio en las credenciales de usuario o de grupo (por ejemplo, llamadas a setuid(2), setresuid(2)) se traslade a todos los hilos POSIX de un proceso. Véase nptl(7) para más detalles.
