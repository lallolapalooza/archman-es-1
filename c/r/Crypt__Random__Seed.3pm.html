SINOPSI

use Crypt::Random::Seed;
my $source = new Crypt::Random::Seed;
die "No strong sources exist" unless defined $source;
my $seed_string = $source->random_bytes(4);
my @seed_values = $source->random_values(4);
# Only non-blocking sources
my $nonblocking_source = Crypt::Random::Seed->new( NonBlocking=>1 );
# Blacklist sources (never choose the listed sources)
my $nowin32_source = Crypt::Random::Seed->new( Never=>['Win32'] );
# Whitelist sources (only choose from these sources)
my $devr_source = Crypt::Random::Seed->new( Only=>['TESHA2'] );
# Supply a custom source.
my $user_src = Crypt::Random::Seed->new( Source=>sub { myfunc(shift) } );
# Or supply a list of [name, sub, is_blocking, is_strong]
$user_src = Crypt::Random::Seed->new(
   Source=>['MyRandomFunction',sub {myfunc(shift)},0,1] );
# Given a source there are a few things we can do:
say "My randomness source is ", $source->name();
say "I am a blocking source" if $source->is_blocking();
say "I am a strong randomness source" if $source->is_strong()
say "Four 8-bit numbers:",
    join(",", map { ord $source->random_bytes(1) } 1..4);'
say "Four 32-bit numbers:", join(",", $source->random_values(4)
)
;

DESCRIPCIÓ

N

Un mecanismo sencillo para obtener aleatoriedad fuerte. El propósito principal de este módulo es proporcionar una forma sencilla de generar una semilla para un PRNG como Math::Random::ISAAC, para su uso en la generación de claves criptográficas, o como la semilla para un módulo aguas arriba como Bytes::Random::Secure. Se permiten indicadores para requerir fuentes no bloqueantes, así como un método muy sencillo para conectar una

fuente.

Las fuentes de aleatoriedad utilizadas son, en

orden:
Proporcionada por el
usuario.
Si el constructor se llama con un Source definido, entonces se utiliza. No se verifica contra otros indicadores (NonBlocking, Never, Only)
.
API de criptografía de
Win32.
Esto usará "CryptGenRandom" en Windows 2000 y "RtlGenRand" en Windows XP y versiones posteriores. Según MSDN, estos son CSPRNG bien sembrados (FIPS 186-2 o AES-CTR), por lo que no serán
bloqueantes.
EGD /
PRNGD.
Esto busca sockets que hablen el protocolo EGD http://egd.sourceforge.net/, incluyendo PRNGD http://prngd.sourceforge.net/. Estos son demonios de entropía en espacio de usuario que son comúnmente usados por OpenSSL, OpenSSH y GnuGP. Las ubicaciones buscadas son "/var/run/egd-pool", "/dev/egd-pool", "/etc/egd-pool", y "/etc/entropy". EGD es bloqueante, mientras que PRNGD no es bloqueante (como la API de Win32, es realmente un CSPRNG sembrado). Sin embargo, no hay forma de distinguirlos, así que lo tratamos como bloqueante. Si su SO soporta /dev/random, considere HAVEGED http://www.issihosts.com/haveged/ como una alternativa (un demonio del sistema que rellena /dev/random según sea necesario)
.
/dev/rando
m.
La fuente fuerte de aleatoriedad en la mayoría de los sistemas tipo UNIX. Cygwin usa esto, aunque se mapea a la API de Win32. En casi todos los sistemas esta es una fuente bloqueante de aleatoriedad -- si se agota la entropía estimada, se colgará hasta que entre más en el sistema. Si esto es un problema, lo que a menudo ocurre en dispositivos integrados, ejecutar una herramienta como HAVEGED http://www.issihosts.com/haveged/ ayudará
enormemente.
/dev/urando
m.
Una fuente no bloqueante de aleatoriedad que etiquetamos como débil, ya que continuará proporcionando salida incluso si la entropía real se ha
agotado.
TESHA
2.
Crypt::Random::TESHA2 es un módulo de Perl que genera bytes aleatorios de un pool de entropía alimentado con variaciones del temporizador/planificador. Se realizan mediciones y pruebas en la instalación para determinar si la fuente se considera fuerte o débil. Esto
es completamente en espacio de usuario portable, lo que es bueno para la facilidad de uso, pero realmente requiere la verificación del usuario de que está funcionando como se espera si esperamos que sea fuerte. El concepto es similar a Math::TrulyRandom aunque
actualizado a algo más cercano a lo que hace TrueRand 2.1 vs. la versión obsoleta 1 que implementa Math::TrulyRandom. Es muy lento y tiene una gran variabilidad de velocidad entre plataformas : he visto números que van desde 40 hasta 150,000 bits por segundo.

Una fuente también puede ser proporcionada en el constructor. Cada una de estas fuentes tendrá sus puntos debatibles sobre la fuerza percibida. Por ejemplo, ¿Por qué es /dev/urandom considerado débil mientras Win32 es fuerte? ¿Puede algún método de espacio de usuario como TrueRand o TESHA2 ser considerado

fuerte?

El alias 'Win32' puede ser usado en listas blancas y negras y coincidirá con ambas fuentes de Win32 "RtlGenRandom" y "CryptGenRandom". El alias 'TESHA2' puede ser usado de manera similar y coincide con las fuentes débiles y

fuertes. 
1) Tanto CryptGenRandom como RtlGenRandom son considerados fuertes por este
   paquete, aunque ambos son CSPRNG sembrados y por lo tanto deberían ser iguales a
   /dev/urandom en este aspecto. La función C
ryptGenRandom usada en Windows 2000 tiene algunos problemas conocidos por lo que debería considerarse más débil. 2) EGD es bloqueante, PRNGD no lo es. No podemos distinguirlos. Hay otros productos de
software que usan el mismo protocolo, y cada uno actuará de manera diferente. Por ejemplo, EGD mezcla entropía del sistema en cada solicitud, mientras que PRNGD mezcla en un horario basado en tiempo.

FUERZ

A

En teoría, un generador fuerte proporcionará entropía verdadera. Incluso si un tercero conociera un resultado anterior y todo el estado del generador en cualquier momento hasta cuando su valor fue devuelto, aún no podría predecir efectivamente el resultado del siguiente valor devuelto. Esto implica que el generador debe ser bloqueante para esperar entropía (por ejemplo, /dev/random) o pasar por algún proceso posiblemente costoso en tiempo para reunirla (TESHA2, EGD, el demonio HAVEGE rellenando /dev/random). Nota: fuerte en este contexto significa prácticamente fuerte, ya que la mayoría de las computadoras no tienen un generador de entropía de hardware verdadero. El objetivo es hacer que todo el conocimiento mal habido de los atacantes no les dé una mejor solución que si no tuvieran la

información.

Crear una medida de fuerza satisfactoria es problemático. La API de criptografía de Win32 es considerada "fuerte" por la mayoría de los clientes y cada otro módulo de Perl, sin embargo, es un CSPRNG bien sembrado según la documentación de MSDN, por lo que no es una fuerte fuente basada en la definición en el párrafo anterior. De manera similar, casi todas las fuentes consideran /dev/urandom débil, ya que una vez que se agota la entropía devuelve una función determinista basada en su estado (aunque una que no puede ser ejecutada en ninguna dirección desde un resultado devuelto si el estado interno no es conocido)

.

Debido a esta confusión, he eliminado la opción de configuración "Weak" que estaba presente en la versión 0.01. Ahora será ignorada. Debería poder usar una combinación de lista blanca, lista negra y el valor de retorno de "is_strong" de la fuente para decidir si esto satisface sus necesidades. En Win32, realmente solo tiene la elección entre Win32 y TESHA2. La primera es lo que la mayoría de la gente querrá, y se puede elegir incluso con conjunto no bloqueante. En la mayoría de los sistemas UNIX, "/dev/random" se elegirá para bloqueo y "/dev/urandom" para no bloqueo, lo cual es l

o que debería hacerse en
la mayoría de los casos.

BLOQUE

O

EGD y /dev/random son fuentes bloqueantes. Esto significa que si se agota su entropía estimada, se pausarán hasta que hayan recopilado más. Esto significa que su programa también se pausa. En estaciones de trabajo típicas esto puede ser de unos segundos o incluso minutos. En un servidor de red aislado esto puede causar un retraso de horas o días. EGD es proactivo a la hora de recopilar más entropía tan rápido como puede. Ejecutar una herramienta como el demonio HAVEGE o timer_entropyd puede hacer que /dev/random actúe como una fuente no bloqueante, ya que el demonio de entropía se despertará y rellenará el pool casi instantáneamente

.

Win32, PRNGD y /dev/urandom son fuentes no bloqueantes rápidas. Cuando se agota su entropía, utilizan un CSPRNG para seguir suministrando datos a alta velocidad. Sin embargo, esto significa que no se está suministrando entropía

adicional.

TESHA2 no bloquea, pero puede ser muy lento. /dev/random puede ser más rápido si se ejecuta en una máquina con mucha actividad. En

un servidor aislado, TESHA2 puede ser mucho más rápido. Tenga en cuenta también que las fuentes bloqueantes como EGD y /dev/r
andom intentan mantener pools de entropía razonablemente grandes, de modo que se pueden atender pequeñas solicitudes sin bloquear.

EN LA

PRÁCTICA

Utilice la opción predeterminada para obtener la mejor fuente conocida. Si sabe más sobre las fuentes disponibles, puede usar una lista blanca, una lista negra o una fuente personalizada. En general, para obtener la mejor fuente (típicamente Win32 o /dev/random)

: 
my $source = Crypt::Random::Seed->new()
;

Para obtener una buena fuente no bloqueante (Win32 o /dev/urandom)

: 
my $source = C
rypt::Random::
Seed->new(NonB
locking => 1);

El constructor sin argumentos encontrará la primera fuente disponible en su lista fija y devolverá un objeto que realiza los métodos definidos. Si no se pudieron encontrar fuentes (algo bastante inusual), entonces el valor devuelto será

undef.

Los parámetros opcionales se pasan como un hash y pueden

mezclarse.

NonBlocking =>

boolean

Solo se permitirán fuentes no bloqueantes. En la práctica, esto significa que EGD y /dev/random no se elegirán (excepto en FreeBSD donde es no bloqueante)

.

Only => [lista de

cadenas]

Toma una referencia a un array que contiene uno o más nombres de fuentes como cadenas. No se elegirá ninguna fuente cuyo nombre no coincida con una de estas cadenas. La cadena 'Win32' coincidirá con cualquiera de las fuentes de Win32, y 'TESHA2' coincidirá tanto con la versión fuerte como con la

débil.

Never => [lista de

cadenas]

Toma una referencia a un array que contiene uno o más nombres de fuentes como cadenas. No se elegirá ninguna fuente cuyo nombre coincida con una de estas cadenas. La cadena 'Win32' coincidirá con cualquiera de las fuentes de Win32, y 'TESHA2' coincidirá tanto con la versión fuerte como con la

débil.

}

Utiliza la subrutina anónima dada como generador. A la subrutina se le dará un entero (el argumento de "random_bytes") y debería devolver datos aleatorios en una cadena de la longitud dada. A los efectos de los demás métodos del objeto, el objeto devuelto tendrá el nombre 'User', y se considerará no bloqueante y no

fuerte.

Devuelve el nombre de texto de la fuente aleatoria. VÉASE

TAMBIÉN

La primera pregunta que uno puede hacerse es "¿Por qué otro módulo de este tipo?". Ninguno de los módulos de CPAN encaja del todo con mis necesidades, de ahí este. Algunas

alternativas:

Crypt::Random::

Source

Un sistema exhaustivo que utiliza múltiples plugins. Tiene una buena API, pero usa Any::Moose, lo que significa que estás cargando Moose o Mouse solo para leer unos bytes de /dev/rando

m. También tiene una cadena de dependencias muy larga, con del orden de 40 módulos instalados como prerrequisitos (dependiendo de si usas alguno de ellos en otros proyectos, por supue
sto). Por último, requiere al menos Perl 5.8, lo que puede o no importarte. Pero le importa a algunos otros desarrolladores de módulos que acaban con la restricción en sus módulos.

Crypt::

URandom

Un gran pequeño módulo que es casi lo que estaba buscando. Crypt::Random::Seed se comportará igual si se le da el

constructor: 
my $source = Crypt::Random::Seed->new(
   NonBlocking => 1,
   Only => [qw(/dev/random /dev/urandom Win32)]
);
croak "No randomness source available" unless defined
$source;

O puedes omitir el "Only" y tener T

ESHA2 como
respaldo.

Crypt::

Random

Requiere Math::Pari, lo que lo hace inaceptable en algunos entornos. Tiene más características (números

en intervalos de bigint arbitrarios o tamaños de bits). Crypt::Random::Seed está tomando un enfoque más
simple, solo manejando la devolución de octetos y dejando que los módulos aguas arriba manejen el resto.

Data::

Entropy

Un módulo interesante que contiene una encapsulación de fuente (por defecto usa el rand del sistema, pero tiene muchos plugins), un buen

CSPRNG (AES en modo contador), y el módulo Data::Entropy::Algorithms con muchas formas de obtener bits, ints, bigints, floats, bigflo
ats, barajados, y así sucesivamente. Desde mi perspectiva, el módulo de algoritmos es lo más destacado, con mucho código interesante.

arriba

para ayudarles: Bytes::Random::Secure,
Math::Random::ISAAC, Math::Random::Secure,
