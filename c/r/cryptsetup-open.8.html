SINOPSI

S

cryptsetup open --type <device_type> [<options>] <device> <name>

DESCRIPCIÓ

N

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

El tipo de dispositivo puede ser plain, luks (por defecto), luks1, luks2, loopaes o tcrypt

.

Por compatibilidad con versiones anteriores, existen alias del comando

open:

create (orden de argumentos <name> <device>): open --type plain
plainOpen: open --type plain
luksOpen: open --type luks
loopaesOpen: open --type loopaes
tcryptOpen: open --type tcrypt
bitlkOpen: open --type

bitlk

Las <options> son específicas del tipo y se describen a continuación para cada tipo de dispositivo. Para create, el orden de las opciones <name> y <device> está invertido por razones históricas; todos los demás alias usan el orden estándar <device> <name>

.

PLAI

N

open --type plain <device> <name> --cipher <spec> --key-size <bits> --hash <alg>
plainOpen <device> <name> (sintaxis antigua)
create <name> <device> (sintaxis

OBSOLETA)

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

Siempre debe especificar las opciones --cipher, --key-size y (si no se usa un archivo de clave o un llavero) también --hash para evitar incompatibilidades, ya que los valores predeterminados pueden diferir en versiones antiguas de

cryptsetup.

El formato plain también permite recuperar una clave de volumen de un llavero del kernel especificado por --volume-key-keyring. La clave en el llavero del kernel debe configurarse antes de emitir los comandos de cryptsetup, ya que cryptsetup no sube ninguna clave al llavero en modo plain. Para comandos posteriores (como resize), el usuario debe asegurarse de que la clave en el llavero no haya cambiado. De lo contrario, recargar la clave puede causar corrupción de datos después de un cambio inesperado de

clave.

Las <options> pueden ser [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring]

.

EJEMPLOS

:

Para mapear el dispositivo cifrado /dev/sda10 al dispositivo descifrado /dev/mapper/e1, puede

usar:

cryptsetup open --type plain --cipher aes-cbc-essiv:sha256 --key-size 256 --hash sha256 /dev/sda10

e1

El dispositivo descifrado puede usarse entonces como un dispositivo de bloque normal para montar un sistema de

archivos.

Para mapear un dispositivo con una clave de volumen en el llavero de confianza o cifrado preconfigurado, debe especificar el llavero con la clave y eliminar la especificación de hash, por ejemplo, para usar %trusted:m

ykey:

cryptsetup open --type plain /dev/sda10 e1 --volume-key-keyring=%trusted:mykey --cipher aes-xts-plain64 --key-size

256

Tenga en cuenta que el tamaño de l

a clave debe coincidir con la c
lave preconfigurada en el llavero.

LUK

S

open <device> <name>
open --type <luks1|luks2> <device> <name> (solicitud explícita de versión)
luksOpen <device> <name> (sintaxis

antigua)

Abre el dispositivo LUKS <device> y configura un mapeo <name> después de la verificación exitosa de la frase de paso

proporcionada.

Primero, se busca la frase de paso en los tokens LUKS2 no protegidos por PIN. Si no existe dicho token (o falla al desbloquear el keyslot) y la frase de paso no se proporciona mediante --key-file, el comando solicita la frase de paso de forma

interactiva.

Si existe un token LUKS2 válido pero requiere un PIN para desbloquear el keyslot asignado, no se usa a menos que se agregue una de las siguientes opciones: --token-only, --token-type donde type coincida con el token protegido por PIN deseado o --token-id con id coincidente con el token protegido por

PIN.

Las <options> pueden ser [--key-file, --keyfile-offset, --keyfile-size, --readonly, --test-passphrase, --allow-discards, --header, --key-slot, --volume-key-file, --token-id, --token-only, --token-type, --disable-external-tok

ens, --disable-keyring, --disable-locks, --type, --refresh, --serialize-memory-hard-pbkdf, --unbound, --tries, --ti
meout, --verify-passphrase, --persistent, --volume-key-keyring, --link-vk-to-keyring, --external-tokens-path].

Abre el loop-AES <device> y configura un mapeo <name>

Si lo necesita en un script, simplemente use la redirección de tubería: echo $keyfile | cryptsetup loopaesOpen --key-fil

necesario.

desplazamiento.

TrueCrypt y

tcryptOpen <device> <name> (sintaxis

antigua)

Abre el TCRYPT (compatible con TrueCrypt y VeraCrypt) <device> y configura un mapeo <name>

La opción --key-file permite una combinación del contenido del archivo con la frase de paso. La opción --key-file se puede repetir. Tenga en cuenta que el uso de archivos de clave difiere de la lógica de archivos de clave de

LUKS.

Si se usan las opciones --cipher o --hash, solo se verifican cadenas de cifrado o variantes de PBKDF2 con los algoritmos de hash especificados. Esto podría acelerar el desbloqueo del dispositivo (pero también revela cierta información sobre el contenedor)

Si usa --header en combinación con las opciones hidden o system, el archivo de cabecera debe contener cabeceras específicas en las mismas posiciones que el contenedor cifrado

original.

La opción --allow-discards no se puede combinar con la opción --tcrypt-hidden. Para el mapeo normal, puede causar la destrucción del volumen oculto (el volumen oculto aparece como espacio no utilizado para el volumen exterior, por lo que este espacio puede ser descartado)

--key-slot, -S <0-N

Esta opción selecciona un slot de clave específico para comparar la frase de paso. Si la frase de paso dada solo coincide con un slot de clave diferente, la operación falla.

Vincula la clave de volumen en un anillo de claves con el nombre de clave especificado. La clave de volumen se vincula solo si la acción solicitada se finaliza con éxito (con --test-passphrase, la clave de volumen verificada se vincula en un anillo de claves sin realizar ninguna acción adicional).

La cadena <keyring description> debe contener la descripción del anillo de claves del kernel existente. El nombre del anillo de claves puede opcionalmente tener el prefijo "%:" o "%keyring:" de descripciones de tipo. O, el anillo de claves también se puede especificar directamente por ID numérico de clave. También, se pueden usar notaciones especiales de anillo de claves que comienzan con "@" para seleccionar anillos de claves predefinidos existentes del

kernel.

La cadena "::" es un delimitador usado para separar la descripción del anillo de claves y la descripción de la

clave.

La parte <key description> describe el tipo de clave y el nombre de la clave de volumen vinculada en el anillo de claves descrito en <keyring description>. El tipo se puede especificar agregando un prefijo "%<type_name>:" delante del nombre de la clave. Si el tipo falta, se aplica el tipo predeterminado user. Si la clave del mismo nombre y tipo ya existe (ya está vinculada en el anillo de claves), será reemplazada en el

--sector-size byte

s
Establece el tamaño del sector de cifrado para usar con el tipo de dispositivo plain. Debe ser una potencia de dos y estar en el rango de 512 - 4096 bytes. El tamaño de sector de cifrado predeterminado es de 512 bytes.

--tcrypt-backup, --tcrypt-hidden, --tcrypt-syste

m
Especifica qué cabecera de TrueCrypt en disco se usará para abrir el dispositivo. Vea la sección TCRYPT en cryptsetup(8) para más información.

Usar un dispositivo cifrado por el sistema con la opción --tcrypt-system requiere configuraciones específicas para funcionar como se

espera.

TrueCrypt/VeraCrypt soporta cifrado completo del sistema (solo la tabla de particiones no está cifrada) o cifrado de la partición del sistema (solo una partición del sistema está cifrada). La cabecera de metadatos entonces contiene el desplazamiento y el tamaño del área cifrada. Cryptsetup necesita conocer el desplazamiento específico de la partición para calcular los parámetros de cifrado. Para mapear correctamente una partición, debe especificar un dispositivo de partición real para que cryptsetup pueda calcular este

desplazamiento.

Aunque puede usar un dispositivo completo como parámetro (/dev/sdb), siempre prefiera especificar la partición que desea mapear (/dev/sdb1), ya que solo el modo de partición del sistema puede detectarse de esta

manera.

Para mapear imágenes (almacenadas en un archivo), puede usar la opción adicional --header con el dispositivo de partición real. Si se usa --header (y es diferente de la imagen de datos), cryptsetup espera que la imagen de datos contenga solo una instantánea de la partición de

datos.

Si no se usa --header (o apunta a la misma imagen), cryptsetup espera que la imagen contenga un disco completo (incluyendo la tabla de particiones). Esto puede mapear un área cifrada completa que no es directamente montable como un sistema de archivos. Por favor, prefiera crear un dispositivo de bucle con particiones (losetup -P, vea la página del manual losetup(8)) y use una partición real (/d

ev/loopXp1) como pará
metro del dispositivo.
