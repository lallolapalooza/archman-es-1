NOMBRE

Crypt::CBC - Encripta datos con el modo de encadenamiento de bloques de cifrado

SINOPSIS

use Crypt::CBC;
$cipher = Crypt::CBC->new( -pass   => 'my secret password',
                           -cipher => 'Cipher::AES'
                          );
# one shot mode
$ciphertext = $cipher->encrypt("This data is hush hush");
$plaintext  = $cipher->decrypt($ciphertext);
# stream mode
$cipher->start('encrypting');
open(F,"./BIG_FILE");
while (read(F,$buffer,1024)) {
    print $cipher->crypt($buffer);
}
print $cipher->finish;
# do-it-yourself mode -- specify key && initialization vector yourself
$key    = Crypt::CBC->random_bytes(8);  # assuming a 8-byte block cipher
$iv     = Crypt::CBC->random_bytes(8);
$cipher = Crypt::CBC->new(-pbkdf       => 'none',
                          -header      => 'none',
                          -key         => $key,
                          -iv          => $iv);
$ciphertext = $cipher->encrypt("This data is hush hush");
$plaintext  = $cipher->decrypt($ciphertext);
# encrypting via a filehandle (requires Crypt::FileHandle>
$fh = Crypt::CBC->filehandle(-pass => 'secret');
open $fh,'>','encrypted.txt" or die $!
print $fh "This will be encrypted\n";
close $fh;

DESCRIPCIÓN

Este módulo es una implementación puramente en Perl del modo de encadenamiento de bloques de cifrado (CBC). En combinación con un cifrado de bloques como AES o Blowfish, puedes encriptar y desencriptar mensajes de longitud arbitraria. Los mensajes encriptados son compatibles con el formato de encriptación utilizado por el paquete OpenSSL .

Para usar este módulo, primero crearás un objeto cifrado Crypt::CBC con new(). En el momento de la creación del cifrado, especificas una clave de encriptación a usar y, opcionalmente, un algoritmo de encriptación de bloques. Luego llamarás al método start() para inicializar el proceso de encriptación o desencriptación, crypt() para encriptar o desencriptar uno o más bloques de datos, y por último, finish(), para rellenar y encriptar el bloque final. Para tu conveniencia, puedes llamar a los métodos encrypt() y decrypt() para operar sobre un valor de datos completo de una sola vez.

$cipher = Crypt::CBC->new( -pass   => 'my secret key',
                           -cipher => 'Cipher::AES',

Crypt::CBC requiere tres piezas de información para hacer su trabajo. Primero necesita el nombre del algoritmo de cifrado de bloques que encriptará o desencriptará los datos en bloques de longitud fija conocida como el "tamaño de bloque" del cifrado. Segundo, necesita una clave de encriptar/desencriptar para pasar al cifrado de bloques. Tercero, necesita un vector de inicialización (IV) que será usado para propagar información de un bloque encriptado al siguiente. Tanto la clave como el IV deben tener exactamente la misma longitud que el tamaño de bloque del cifrado elegido.

Crypt::CBC puede derivar la clave y el IV de una frase de contraseña que tú proporcionas, o puede permitirte especificar la clave y el IV reales manualmente. Además, tienes la opción de incrustar suficiente información para regenerar el IV en una cabecera corta que se emite al inicio del flujo encriptado, o generar un flujo de encriptación sin cabecera. En el primer caso, Crypt::CBC podrá desencriptar el flujo dado solo la clave original o la frase de contraseña. En el segundo caso, tendrás que proporcionar el IV original así como la clave/frase de contraseña.

La opción -cipher especifica qué algoritmo de cifrado de bloques usar para codificar cada sección del mensaje. Este argumento es opcionall y por defecto utilizará el algoritmo seguro Crypt::Cipher::AES. Puede utilizar cualquier algoritmo de cifrado por bloques compatible que tenga instalado. Actualmente, esto incluye Crypt::Cipher::AES, Crypt::DES, Crypt::DES_EDE3, Crypt::IDEA, Crypt::Blowfish, Crypt::CAST5 y Crypt::Rijndael. Puede referirse a ellos usando sus nombres completos ("Crypt::IDEA") o en forma abreviada ("IDEA")

.

Se recomienda especificar el algoritmo de derivación de clave "pbkdf2" cuando no se necesite compatibilidad con versiones anteriores de Crypt::CBC. Este algoritmo es deliberadamente costoso computacionalmente con el fin de hacer más difíciles los ataques basados en diccionarios. Como resultado, introduce un ligero retraso antes de que comience una operación de cifrado o

descifrado.

Métodos de
relleno

Use la opción 'padding' para cambiar el método de

relleno.

Cuando el último bloque de texto plano es más corto que el tamaño de bloque, debe ser rellenado. Los métodos de relleno incluyen: "standard" (es decir, PKCS#5), "oneandzeroes", "space", "rijndael_compat", "null", y

"none". 
standard: (por defecto) Seguro para binarios
   rellena con el número de bytes que deberían ser truncados. Así, si
   el tamaño de bloque es 8, entonces "0A0B0C" será rellenado con "05", resultando
   en "0A0B0C0505050505". Si el bloque final es un bloque completo de 8
   bytes, entonces se añade un bloque completo de "0808080808080808".
oneandzeroes: Seguro para binarios
   rellena con "80" seguido de tantos "00" como sean necesarios para llenar el
   bloque. Si el último bloque es un bloque completo y el tamaño de bloque es 8, se
   añadirá un bloque de "8000000000000000".
rijndael_compat: Seguro para binarios, con advertencias
   similar a oneandzeroes, excepto que no se realiza relleno si
   el último bloque es un bloque completo. Esto se proporciona para
   compatibilidad con el MODE_CBC incorporado de Crypt::Rijndael.
   Tenga en cuenta que la implementación de CBC de Crypt::Rijndael solo
   funciona con mensajes que son múltiplos pares de 16 bytes.
null: solo para texto
   rellena con tantos "00" como sean necesarios para llenar el bloque. Si el último
   bloque es un bloque completo y el tamaño de bloque es 8, se añadirá un bloque de
   "0000000000000000".
space: solo para texto
   igual que "null", pero con "20".
none:
   no se añade relleno. Útil para aplicaciones de propósito especial donde
   desea añadir un relleno
personalizado al mensaje.

Tanto el relleno standard como oneandzeroes son seguros para binarios. Los rellenos space y null se recomiendan solo para datos de texto. Qué tipo de relleno use depende de si desea comunicarse con una biblioteca externa (no Crypt::CBC). Si este es el caso, use cualquier método de relleno que sea compatible. También puede pasar una función de relleno personalizada. Para hacer esto, cree una función que tome los argumentos: $padded_block = function($block,$blocksize,$direction); donde $block es el bloque actual de datos, $blocksize es el tamaño al que rellenarlo, $direction es "e" para cifrar y "d" para descifrar,

y

Comparación

con Crypt
::Mode::CBC

Los módulos CryptX Crypt::Mode::CBC, Crypt::Mode::OFB, Crypt::Mode::CFB, y Crypt::Mode::CTR proporcionan implementaciones rápidas de los respectivos modos de encadenamiento de bloques (aproximadamente 5 veces la velocidad de Crypt::CBC). Crypt::CBC fue diseñado para cifrar y descifrar mensajes de una manera compatible con la función "enc" de OpenSSL. Por lo tanto, maneja la derivación de la clave y el IV a partir de una frase de paso usando las mismas convenciones que OpenSSL, y escribe una cabecera compatible con OpenSSL en el mensaje cifrado de una

manera que permite regenerar la clave y el IV durante el descifrado.

En contraste, los módulos CryptX no derivan automáticamente la clave y el IV a partir de una

frase de paso ni escriben una cabecera cifrada. Necesitará derivar y almacenar la clave y el
IV por otros medios (ej. con el módulo Crypt::KeyDerivation de CryptX, o con Crypt::PBKDF2).
