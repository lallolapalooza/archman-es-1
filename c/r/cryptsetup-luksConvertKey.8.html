CRYPTSETUP-LUKSCONVERTKEY(8) Comandos de mantenimiento CRYPTSETUP-LUKSCONVERTKEY(8)

NOMBRE

cryptsetup-luksConvertKey - convierte un slot de claves LUKS2 existente a nuevos parámetros PBKDF

SINOPSIS

cryptsetup luksConvertKey [<opciones>] <dispositivo>

DESCRIPCIÓN

Convierte un slot de claves LUKS2 existente a nuevos parámetros PBKDF. La frase de paso para el slot de claves a convertir debe proporcionarse de forma interactiva o mediante --key-file. Si no se especifican parámetros --pbkdf, se aplicarán los valores PBKDF predeterminados de LUKS2.

Si se especifica un slot de claves (mediante --key-slot), debe proporcionarse la frase de paso para ese slot de claves. Si no se especifica ningún slot de claves y aún hay un slot de claves libre, los nuevos parámetros se colocarán en un slot de claves libre antes de que el slot de claves que contiene los parámetros antiguos sea purgado. Si no hay un slot de claves libre, el slot de claves con los parámetros antiguos se sobrescribe directamente.

ADVERTENCIA: Si un slot de claves se sobrescribe, un fallo del medio durante esta operación puede hacer que la sobrescritura falle después de que los parámetros antiguos se hayan borrado, haciendo que el contenedor LUKS sea inaccesible.

<opciones> puede ser [--key-file, --keyfile-offset, --keyfile-size, --key-slot, --hash, --header, --disable-locks, --iter-time, --pbkdf, --pbkdf-force-iterations, --pbkdf-memory, --pbkdf-parallel, --keyslot-cipher, --keyslot-key-size, --timeout, --verify-passphrase].

OPCIONES

--batch-mode, -q

Suprime todas las preguntas de confirmación. ¡Úselo con cuidado!

Si no se especifica la opción --verify-passphrase, esta opción también desactiva la verificación de la frase de paso.

--debug o --debug-json

Se ejecuta en modo de depuración con registros de diagnóstico completos. Las líneas de salida de depuración siempre tienen el prefijo #.

Si se usa --debug-json, se imprimen estructuras de datos JSON adicionales de LUKS2.

--disable-locks

Desactiva la protección de bloqueo para los metadatos en disco. Esta opción solo es válida para LUKS2 y se ignora para otros formatos.

ADVERTENCIA: No use esta opción a menos que ejecute cryptsetup en un entorno restringido donde el bloqueo sea imposible de realizar (donde el directorio /run no se pueda usar).

--force-password

No usar la comprobación de calidad de contraseña para nuevas contraseñas LUKS.

Esta opción se ignora si cryptsetup se ha compilado sin soporte para la comprobación de calidad de contraseña.

Para más información sobre la comprobación de calidad de contraseña, consulte la página manual de pwquality.conf(5) y passwdqc.conf(5).

--hash, -h <especificación de hash>

El hash especificado se usa para PBKDF2 y el divisor AF.

--header <dispositivo o archivo que almacena la cabecera LUKS>

Usar un dispositivo o archivo de metadatos desprendido (separado) donde se almacena la cabecera LUKS. Esta opción permite almacenar el texto cifrado y la cabecera LUKS en dispositivos diferentes.

Para los comandos que cambian la cabecera LUKS (por ejemplo, luksAddKey), especifique el dispositivo o archivo con la cabecera LUKS directamente como el dispositivo LUKS.

--help, -?

Muestra el texto de ayuda y los parámetros predeterminados.

--iter-time, -i <número de milisegundos>

El número de milisegundos a gastar en el procesamiento de la frase de paso PBKDF. Especificar 0 como parámetro selecciona el valor predeterminado compilado.

--key-file, -d archivo

Leer la frase de paso del archivo.

Si el nombre dado es "-", la frase de paso se leerá de stdin. En este caso, la lectura no se detendrá en los caracteres de nueva línea.

Consulte la sección NOTAS SOBRE EL PROCESAMIENTO DE FRASES DE PASO en cryptsetup(8) para más información.

--keyfile-offset valor

Saltar valor bytes al principio del archivo de claves.

--keyfile-size, -l valor

Leer un máximo de valor bytes del archivo de claves. El predeterminado es leer el archivo completo hasta el máximo compilado que se puede consultar con --help. Proporcionar más datos que el máximo compilado aborta la operación.

Esta opción es útil para cortar nuevas líneas finales, por ejemplo. Si también se da --keyfile-offset, el recuento de tamaño comienza después del desplazamiento.

--key-slot, -S <0-N>

Para operaciones LUKS que añaden material de claves, esta opción permite especificar qué slot de claves se selecciona para la nueva clave.

El número máximo de slots de claves depende de la versión de LUKS. LUKS1 puede tener hasta 8 slots de claves. LUKS2 puede tener hasta 32 slots de claves basados en el tamaño del área del slot de claves y el tamaño de la clave, pero un ID de slot de claves válido siempre puede estar entre 0 y 31 para LUKS2.

--keyslot-cipher <especificación de cifrado>

Esta opción se puede usar para establecer un cifrado específico para el área del slot de claves LUKS2.

--keyslot-key-size <bits>

Esta opción se puede usar para establecer un tamaño de clave específico para el área del slot de claves LUKS2.

--new-keyfile-offset valor

Saltar valor bytes al inicio al añadir una nueva frase de paso desde el archivo de claves.

--new-keyfile-size valor

Leer un máximo de valor bytes al añadir una nueva frase de paso desde el archivo de claves. El predeterminado es leer el archivo completo hasta la longitud máxima compilada que se puede consultar con --help. Proporcionar más que el máximo compilado aborta la operación. Cuando también se da --new-keyfile-offset, la lectura comienza después del desplazamiento.

--pbkdf <especificación PBKDF>

Establecer el algoritmo de Función de Derivación de Claves Basada en Contraseña (PBKDF) para el slot de claves LUKS. El PBKDF puede ser: pbkdf2 (para PBKDF2 según RFC2898), argon2i para Argon2i o argon2id para Argon2id (ver Argon2 https://www.cryptolux.org/index.php/Argon2 para más información).

Para LUKS1, solo se acepta PBKDF2 (no hay necesidad de usar esta opción). El PBKDF predeterminado para LUKS2 se establece durante la compilación y está disponible en la salida de cryptsetup --help .

Un PBKDF se usa para aumentar el costo de los ataques de diccionario y fuerza bruta para las contraseñas de los slots de claves. Los parámetros pueden ser tiempo, memoria y costo paralelo.

Para PBKDF2, solo aplica el costo de tiempo (número de iteraciones). Para Argon2i/id, también hay costo de memoria (memoria requerida durante el proceso de derivación de la clave) y costo paralelo (número de hilos que se ejecutan en paralelo durante la derivación de la clave.

Tenga en cuenta que aumentar el costo de memoria también aumenta el tiempo, por lo que los valores finales de los parámetros se miden mediante una prueba de rendimiento. La prueba de rendimiento intenta encontrar el tiempo de iteración (--iter-time) con el costo de memoria requerido --pbkdf-memory. Si no es posible, el costo de memoria también se reduce. El costo paralelo --pbkdf-parallel es constante y se comprueba contra los núcleos de CPU disponibles.

Puede ver todos los parámetros PBKDF para un slot de claves LUKS2 en particular con el comando cryptsetup-luksDump(8) .

Si no desea usar la prueba de rendimiento y quiere especificar todos los parámetros directamente, use --pbkdf-force-iterations con --pbkdf-memory y --pbkdf-parallel. Esto anulará los valores sin realizar una prueba de rendimiento. Tenga en cuenta que puede causar un tiempo de desbloqueo extremadamente largo o causar condiciones de falta de memoria con terminación incondicional del proceso. Úselo solo en casos específicos, por ejemplo, si sabe que el dispositivo formateado se usará en algún sistema integrado pequeño.

COSTOS PBKDF MÍNIMOS Y MÁXIMOS: Para PBKDF2, el número mínimo de iteraciones es 1000 y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). Los costos de memoria y paralelo no son soportados para PBKDF2. Para Argon2i y Argon2id, el número mínimo de iteraciones (costo de CPU) es 4, y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). El costo de memoria mínimo es 32 KiB y el máximo es 4 GiB. Si el parámetro de costo de memoria se determina mediante una prueba de rendimiento (no especificado por un parámetro), siempre está en el rango de 64 MiB a 1 GiB. Un costo de memoria superior a 1GiB (hasta el máximo de 4GiB) solo se puede configurar mediante el parámetro --pbkdf-memory. El costo paralelo mínimo es 1 y el máximo 4 (si hay suficientes núcleos de CPU disponibles, de lo contrario se reduce por los núcleos de CPU disponibles).

ADVERTENCIA: Aumentar los costos computacionales de PBKDF por encima de los límites mencionados proporciona una seguridad adicional despreciableuridad. Aunque los costes elevados aumentan significativamente la sobrecarga de los ataques de fuerza bruta, ofrecen una protección insignificante contra los ataques de diccionario. El aumento marginal del coste para procesar un diccionario completo es fundamentalmente insuficiente.

Los límites de PBKDF codificados representan compromisos diseñados entre la seguridad criptográfica y la usabilidad operativa. LUKS mantiene la portabilidad y debe usarse dentro de un tiempo razonable en sistemas con recursos limitados.

Cryptsetup restringe deliberadamente los parámetros de coste máximo de memoria (4 GiB) y de coste paralelo (4) debido a limitaciones arquitectónicas (como sistemas integrados y sistemas heredados).

El coste de memoria de PBKDF exige la asignación de RAM física real con operaciones de escritura intensivas que deben permanecer en la RAM física. Cualquier uso de swap resulta en una degradación inaceptable del rendimiento. La gestión de la memoria a menudo sobrecompromete asignaciones más allá de la memoria física disponible, esperando que la mayor parte de la memoria asignada permanezca sin usar. En tales situaciones, como PBKDF siempre usa toda la memoria asignada, frecuentemente causa fallos de agotamiento de memoria que abortan las operaciones de cryptsetup.

--pbkdf-force-iterations número

Evita el benchmark de PBKDF y establece el coste de tiempo (iteraciones) directamente. Solo puede usarse para un dispositivo LUKS/LUKS2. Consulte la opción --pbkdf para más información.

--pbkdf-memory número

Establece el coste de memoria para PBKDF (para Argon2i/id, el número representa kilobytes). Tenga en cuenta que es el valor máximo; el benchmark de PBKDF o la memoria física disponible pueden disminuirlo. Esta opción no está disponible para PBKDF2.

--pbkdf-parallel número

Establece el coste paralelo para PBKDF (número de hilos, hasta 4). Tenga en cuenta que es el valor máximo; se reduce automáticamente si el número de CPU en línea es menor. Esta opción no está disponible para PBKDF2.

--timeout, -t segundos

El número de segundos a esperar antes de un tiempo de espera en la entrada de la frase de contraseña a través del terminal. Es relevante cada vez que se solicita una frase de contraseña. No tiene efecto si se usa junto con --key-file.

Esta opción es útil cuando el sistema no debe bloquearse si el usuario no introduce una frase de contraseña, por ejemplo, durante el arranque. El valor predeterminado es 0 segundos, lo que significa esperar indefinidamente.

--usage

Muestra la ayuda corta de las opciones.

--verify-passphrase, -y

Al pedir interactivamente una frase de contraseña, la pide dos veces y se queja si ambas entradas no coinciden. Se ignora en la entrada desde un archivo o stdin.

--version, -V

Muestra la versión del programa.
