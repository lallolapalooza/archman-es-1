DESCRIPCIÓ

N

Crystal es un lenguaje de programación con verifica

ción de tipos estática. Fue creado teniendo en c
uenta la belleza de Ruby y el rendimiento de C.

US

O

Puedes compilar y ejecutar un programa invocando al compilador con un solo nombre de

archivo: 
crystal
algun_pro
grama.cr

Los archivos de Crystal suelen terminar con la extensión .cr, aunque esto no es

obligatorio.

Alternativamente, puedes usar el comando

run: 
crystal ru
n algun_p
rograma.cr

Para crear un ejecutable, usa el comando

build: 
crystal bu
ild algun_p
rograma.cr

Esto creará un ejecutable llamado "algun_programa"

.

Ten en cuenta que, de forma predeterminada, los ejecutables generados no están completamente optimizados. Para activar las optimizaciones, usa el interruptor --r

elease: 
crystal build
--release alg
un_programa.cr

Asegúrate de usar siempre --release para ejecutables listos para producción y al realizar pruebas de

rendimiento.

Las optimizaciones no están activadas de forma predeterminada porque los tiempos de compilación son mucho más rápidos sin ellas y el rendimiento del programa sigue siendo bastante bueno sin ellas, lo que permite usar el comando crystal casi c

omo si fuera u
n intérprete.

Opciones

:

--cross-compil

e
Genera un archivo objeto para compilación cruzada e imprime el comando para construir el ejecutable. El archivo objeto debe copiarse al sistema de destino y el comando impreso debe ejecutarse allí. Este interruptor existe principalmente para portar el compilador a nuevas plataformas; si es posible, ejecute el compilador directamente en la plataforma de
destino.

-d, --debu

g
Genera la salida con símbolos de depuración simbólicos. Estos se leen al depurar el programa compilado con herramientas como lldb, gdb, valgrind, etc., y proporcionan mapeos al código fuente original para esas
herramientas.

--no-debu

g
Genera la salida sin ningún símbolo de depuración
simbólico.

-D FLAG, --define FLA

G
Define una bandilla en tiempo de compilación. Esto es útil para definir condicionalmente tipos, métodos o comandos basados en bandillas disponibles en tiempo de compilación. Las bandillas predeterminadas provienen del triple de destino dado con --target-triple o el del host de forma predeterminada, si no se proporciona
ninguna.

--emit [asm|llvm-bc|llvm-ir|obj

]
Lista separada por comas de tipos de salida para que el compilador emita. Puedes usar esto para ver el código intermedio LLVM (IR), el código intermedio LLVM (bitcode), el ensamblador y los archivos objeto
generados.

--x86-asm-syntax [a

tt|intel]
Selecciona el dialecto de ensamblador para --emit=asm. El predeterminado es att, que significa la sintaxis AT&T soportada por herramientas como el Ensamblador GNU. intel selecciona la sintaxis Intel, que es la preferida para herramientas de
Windows.

--frame-pointers [auto|always|non-leaf

]
Controla la preservación de los punteros de marco. El valor predeterminado, --frame-pointers=auto, preservará los punteros de marco en compilaciones de depuración e intentará omitirlos en compilaciones de versión final (ciertas plataformas requieren que permanezcan activados). --frame-pointers=always siempre los preservará, y non-leaf solo forzará su preservación en funciones no
hoja.

-f text|json, --format tex

t|json
Formato de salida. Por defecto es text. El formato json puede usarse para obtener una salida más amigable para los
analizadores.

--error-trac

e
Muestra el rastro completo del error. Deshabilitado de forma predeterminada, ya que el rastro completo suele hacer que los mensajes de error sean menos legibles y puede no proporcionar siempre información
relevante.

--l

l
Vuelca el archivo de ensamblador LLVM al directorio de
salida.

--link-flags FLAG

S
Pasa bandillas adicionales al enlazador. Aunque puedes especificar esas bandillas en el código fuente, esto es útil para pasar información específica del entorno directamente al enlazador, como rutas de bibliotecas no estándar o nombres. Para obtener más información sobre cómo especificar bandillas del enlazador en el código fuente, puedes leer la sección "Enlaces C" de la documentación disponible en el sitio web
oficial.

--mcpu CP

U
Especifica una CPU específica para la cual generar código. Esto pasará una bandilla -mcpu a LLVM y solo está destinado a usarse para compilación cruzada. Para obtener una lista de las CPU disponibles, pasa --mcpu help al compilar cualquier código fuente de Crystal. Pasar --mcpu native pasará el nombre de la CPU del host para ajustar el rendimiento para el
host.

--mattr CP

U
Sobrescribe o controla atributos específicos del destino, como si las operaciones SIMD están habilitadas o no. El conjunto de atributos predeterminado lo establece la CPU actual. Esto pasará una bandilla -mattr a LLVM y solo está destinado a usarse para compilación cruzada. Para obtener una lista de los atributos disponibles, invoca "llvm-as < /dev/null | llc -march=xyz
-mattr=help".

--mcmodel default|kernel|tiny|small|medium|larg

Genera documentación a partir de comentarios utilizando un subconjunto de markdown. La salida se guarda en formato html en la carpeta docs/ creada. Más información sobre las convenciones de documentación se puede encontrar en https://crystal-lang.org/docs/conventions/documenting_code.html.

Opciones:

--project-name NOMBRE

Establece el nombre del proyecto. El valor predeterminado se extrae de shard.yml si está disponible.

En caso de que no se pueda encontrar un valor predeterminado, esta opción es obligatoria.

--project-version VERSIÓN

Establece la versión del proyecto. El valor predeterminado se extrae del commit de git actual o de shard.yml si está disponible.

En caso de que no se pueda encontrar un valor predeterminado, esta opción es obligatoria.

--json-config-url URL

Establece la URL que apunta a un archivo de configuración (utilizado para descubrir versiones).

--source-refname REFNAME

Establece el nombre de referencia de la fuente (por ejemplo, etiqueta git, hash de commit). El valor predeterminado se extrae del commit de git actual si está disponible.

Si esta opción falta y no se puede determinar automáticamente, el generador no puede producir enlaces al código fuente.

--source-url-pattern URL

Establece el patrón de URL para los enlaces del código fuente. El valor predeterminado se extrae de los remotos de git ("origin" o el primero) si está disponible y el patrón de URL del proveedor es reconocido.

Si esta opción falta y no se puede determinar automáticamente, el generador no puede producir enlaces al código fuente.

-o DIRECTORIO, --output DIRECTORIO

Establece el directorio de salida (predeterminado: ./docs).

-b URL, --canonical-base-url URL

Indica la URL preferida con el elemento de enlace rel="canonical".

-b URL, --sitemap-base-url URL

Establece la URL base del sitemap. El sitemap solo se generará cuando se establezca esta opción.

--sitemap-priority PRIORIDAD

Establece la prioridad asignada a las entradas del sitemap (predeterminado: 1.0).

--sitemap-changefreq FRECUENCIA

Establece la frecuencia de cambio asignada a las entradas del sitemap (predeterminado: never).

OPTIMIZACIONE

S

El nivel de optimización especifica el esfuerzo de generación de código para producir código óptimo. Es una compensación entre el rendimiento de compilación (disminuye por cada nivel de optimización) y el rendimiento en tiempo de ejecución (aumenta por cada nivel de optimización)

.

Las compilaciones de producción generalmente deberían tener el nivel de optimización más alto. Se logran los mejores resultados con --release que también implica --single-modul

Define la ruta donde Crystal almacena en caché los resultados de compilación parciales para compilaciones subsiguientes más rápidas. Esta ruta también se usa para almacenar temporalmente los ejecutables cuando los programas Crystal se ejecutan con 'crystal run' en lugar de 'crystal

CRYSTAL_EXEC_PAT

H

Determina la ruta do

nde crystal busca s
ubcomandos externos.

CRYSTAL_LIBRARY_PAT

H

Define las rutas donde Crystal busca bibliotecas (binarias). Se pueden separar múltiples rutas con ":". Estas rutas se pasan al enlazador como -L

.

El patrón '$ORIGIN' al comienzo de la ruta se expande al directorio donde se encuentra el binario del compilador. Po

r ejemplo, '$ORIGIN/../lib/crystal' resuelve la ruta de la biblioteca estándar de forma genérica relativa a la ub
icación del compilador, independientemente de las rutas absolutas (asumiendo que la ubicación relativa es correcta).

CRYSTAL_PAT

H

Define las rutas donde Crystal busca los archivos fuente requeridos. Se pueden separar múltiples rutas con ":

".

El patrón '$ORIGIN' al comienzo de la ruta se expande al directorio donde se encuentra el binario del compilador. Por

ejemplo, '$ORIGIN/../share/crystal/src' resuelve la ruta de la biblioteca estándar de forma genérica relativa a la
ubicación del compilador, independientemente de las rutas absolutas (asumiendo que la ubicación relativa es correcta).

CRYSTAL_OPT

S

Define opciones para el compilador de Crystal a usar además de los argu

mentos de la línea de comandos. La sintaxis es idéntica a la de los arg
umentos de la línea de comandos. Esto es útil al usar Crystal en configu
raciones de compilación, por ejemplo 'CRYSTAL_OPTS=--debug make build'.
