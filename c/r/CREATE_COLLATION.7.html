NOMBRE

CREATE_COLLATION - define una nueva regla de ordenación (collation)

SINOPSIS

CREATE COLLATION [ IF NOT EXISTS ] nombre (
    [ LOCALE = locale, ]
    [ LC_COLLATE = lc_collate, ]
    [ LC_CTYPE = lc_ctype, ]
    [ PROVIDER = provider, ]
    [ DETERMINISTIC = boolean, ]
    [ RULES = rules, ]
    [ VERSION = version ]
)
CREATE COLLATION [ IF NOT EXISTS ] nombre FROM existing_collation

DESCRIPCIÓN

CREATE COLLATION define una nueva regla de ordenación utilizando la configuración de configuración regional (locale) del sistema operativo especificada, o copiando una regla de ordenación existente.

Para poder crear una regla de ordenación, debe tener el privilegio CREATE en el esquema de destino.

PARÁMETROS

IF NOT EXISTS

No lance un error si ya existe una regla de ordenación con el mismo nombre. En este caso se emite un aviso. Tenga en cuenta que no hay garantía de que la regla de ordenación existente sea similar a la que se habría creado.

nombre

El nombre de la regla de ordenación. El nombre de la regla de ordenación puede incluir el esquema. Si no lo hace, la regla de ordenación se define en el esquema actual. El nombre de la regla de ordenación debe ser único dentro de ese esquema. (Los catálogos del sistema pueden contener reglas de ordenación con el mismo nombre para otras codificaciones, pero se ignoran si la codificación de la base de datos no coincide.)

locale

El nombre de la configuración regional (locale) para esta regla de ordenación. Consulte la Sección 23.2.2.3.1 y la Sección 23.2.2.3.2 para más detalles.

Si provider es libc, esto es un atajo para establecer LC_COLLATE y LC_CTYPE a la vez. Si especifica locale, no puede especificar ninguno de esos parámetros.

Si provider es builtin, entonces locale debe especificarse y establecerse en C, C.UTF-8 o PG_UNICODE_FAST.

lc_collate

Si provider es libc, use la configuración regional (locale) del sistema operativo especificada para la categoría de configuración regional LC_COLLATE.

lc_ctype

Si provider es libc, use la configuración regional (locale) del sistema operativo especificada para la categoría de configuración regional LC_CTYPE.

provider

Especifica el proveedor a utilizar para los servicios de configuración regional asociados con esta regla de ordenación. Los valores posibles son builtin, icu (si el servidor se compiló con soporte ICU) o libc. libc es el valor predeterminado. Consulte la Sección 23.1.4 para más detalles.

DETERMINISTIC

Especifica si la regla de ordenación debe usar comparaciones deterministas. El valor predeterminado es true. Una comparación determinista considera que las cadenas que no son iguales a nivel de bytes son desiguales, incluso si se consideran lógicamente iguales por la comparación. PostgreSQL resuelve los empates utilizando una comparación a nivel de bytes. Una comparación no determinista puede hacer que la regla de ordenación sea, por ejemplo, insensible a mayúsculas/minúsculas o a acentos. Para ello, debe elegir una configuración LOCALE apropiada y establecer la regla de ordenación como no determinista aquí.

Las reglas de ordenación no deterministas solo se admiten con el proveedor ICU.

rules

Especifica reglas de ordenación adicionales para personalizar el comportamiento de la regla de ordenación. Esto solo es compatible con ICU. Consulte la Sección 23.2.3.4 para más detalles.

version

Especifica la cadena de versión a almacenar con la regla de ordenación. Normalmente, esto debe omitirse, lo que hará que la versión se calcule a partir de la versión real de la regla de ordenación proporcionada por el sistema operativo. Esta opción está destinada a ser utilizada por pg_upgrade para copiar la versión de una instalación existente.

Consulte también ALTER COLLATION (ALTER_COLLATION(7)) para saber cómo manejar las discrepancias en las versiones de las reglas de ordenación.

existing_collation

El nombre de una regla de ordenación existente a copiar. La nueva regla de ordenación tendrá las mismas propiedades que la existente, pero será un objeto independiente.

NOTAS

CREATE COLLATION toma un bloqueo SHARE ROW EXCLUSIVE, que es autoconflictivo, en el catálogo del sistema pg_collation, por lo que solo un CREATE COLLATION comando puede ejecutarse a la vez.

Utilice DROP COLLATION para eliminar reglas de ordenación definidas por el usuario.

Consulte la Sección 23.2.2.3 para más información sobre cómo crear reglas de ordenación.

Al usar el proveedor de reglas de ordenación libc, la configuración regional (locale) debe ser aplicable a la codificación de la base de datos actual. Consulte CREATE DATABASE (CREATE_DATABASE(7)) para las reglas precisas.

EJEMPLOS

Para crear una regla de ordenación a partir de la configuración regional del sistema operativo fr_FR.utf8 (suponiendo que la codificación de la base de datos actual es UTF8):

CREATE COLLATION french (locale = 'fr_FR.utf8');

Para crear una regla de ordenación utilizando el proveedor ICU con el orden de clasificación del directorio telefónico alemán:

CREATE COLLATION german_phonebook (provider = icu, locale = 'de-u-co-phonebk');

Para crear una regla de ordenación utilizando el proveedor ICU, basada en la configuración regional raíz de ICU, con reglas personalizadas:

CREATE COLLATION custom (provider = icu, locale = 'und', rules = '&V << w <<< W');

Consulte la Sección 23.2.3.4 para más detalles y ejemplos sobre la sintaxis de las reglas.

Para crear una regla de ordenación a partir de una existente:

CREATE COLLATION german FROM "de_DE";

Esto puede ser conveniente para poder usar nombres de reglas de ordenación independientes del sistema operativo en las aplicaciones.

COMPATIBILIDAD

Existe una sentencia CREATE COLLATION en el estándar SQL, pero está limitada a copiar una regla de ordenación existente. La sintaxis para crear una nueva regla de ordenación es una extensión de PostgreSQL.

VÉASE TAMBIÉN

ALTER COLLATION (ALTER_COLLATION(7)), DROP COLLATION (DROP_COLLATION(7))
