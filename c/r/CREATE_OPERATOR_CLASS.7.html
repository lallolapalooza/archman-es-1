SINOPSI

S 
CREATE OPERATOR CLASS name [ DEFAULT ] FOR TYPE data_type
  USING index_method [ FAMILY family_name ] AS
  {  OPERATOR strategy_number operator_name [ ( op_type, op_type ) ] [ FOR SEARCH | FOR ORDER BY sort_family_name ]
   | FUNCTION support_number [ ( op_type [ , op_type ] ) ] function_name ( argument_type [, ...] )
   | STORAGE storage_type
  } [, ...
]

DESCRIPCIÓ

N

CREATE OPERATOR CLASS crea una nueva clase de operador. Una clase de operador define cómo un tipo de datos particular puede usarse con un índice. La clase de operador especifica que ciertos operadores cumplirán roles o “estrategias” particulares para este tipo de datos y este método de índice. La clase de operador también especifica las funciones de soporte que usará el método de índice cuando se seleccione la clase de operador para una columna de índice. Todos los operadores y funciones usados por una clase de operador deben definirse antes de que se pueda crear la clase de

operador.

Si se proporciona un nombre de esquema, la clase de operador se crea en el esquema especificado. De lo contrario, se crea en el esquema actual. Dos clases de operador en el mismo esquema pueden tener el mismo nombre solo si son para diferentes métodos de

índice.

El usuario que define una clase de operador se convierte en su propietario. Actualmente, el usuario que la crea debe ser superusuario. (Esta restricción se hace porque una definición errónea de clase de operador podría confundir o incluso hacer caer el servidor.

)

CREATE OPERATOR CLASS actualmente no verifica si la definición de la clase de operador incluye todos los operadores y funciones requeridos por el método de índice, ni si los operadores y funciones forman un conjunto autoconsistente. Es responsabilidad del usuario definir una clase de operador

válida.

Las clases de operador relacionadas pueden agruparse en familias de operadores. Para añadir una nueva clase de operador a una familia existente, especifique la opción FAMILY en CREATE OPERATOR CLASS. Sin esta opción, la nueva clase se coloca en una familia con el mismo nombre que la nueva clase (creando esa familia si no existe ya)

.

Consulte la Secc

ión 36.16 para
más información.

S

nam

e
El nombre de la clase de operador a crear. El nombre puede estar calificado por
esquema.

DEFAUL

T
Si está presente, la clase de operador se convertirá en la clase de operador predeterminada para su tipo de datos. Como máximo una clase de operador puede ser la predeterminada para un tipo de datos y método de índice
específicos.

data_typ

e
El tipo de datos de la columna para el que es esta clase de
operador.

index_metho

d
El nombre del método de índice para el que es esta clase de
operador.

family_nam

e
El nombre de la familia de operadores existente a la que añadir esta clase de operador. Si no se especifica, se usa una familia con el mismo nombre que la clase de operador (creándola, si no existe ya)
.

strategy_numbe

r
El número de estrategia del método de índice para un operador asociado con la clase de
operador.

operator_nam

e
El nombre (opcionalmente calificado por esquema) de un operador asociado con la clase de
operador.

op_typ

e
En una cláusula OPERATOR, el tipo de datos del operando del operador, o NONE para indicar un operador de prefijo. Los tipos de datos del operando pueden omitirse en el caso normal en que son los mismos que el tipo de datos de la clase de operador.

En una cláusula FUNCTION, el tipo de datos del operando que la función está destinada a soportar, si es diferente de los tipos de datos de entrada de la función (para funciones de comparación B-tree y funciones hash) o el tipo de datos de la clase (para funciones de soporte de ordenación B-tree, funciones de imagen de igualdad B-tree, y todas las funciones en clases de operadores GiST, SP-GiST, GIN y BRIN). Estos valores predeterminados son correctos, y por lo tanto op_type no necesita especificarse en cláusulas FUNCTION, excepto en el caso de una función de soport

e de ordenación B-tree que está destinada a sop
ortar comparaciones entre tipos de datos diferentes.

sort_family_nam

e
El nombre (opcionalmente calificado por esquema) de una familia de operadores btree existente que describe el orden de ordenación asociado con un operador de ordenación.

Si no se especifica ni FOR SE

ARCH ni FOR ORDER BY, FOR SEA
RCH es el predeterminado.

support_numbe

r
El número de función de soporte del método de índice para una función asociada con la clase de
operador.

function_nam

e
El nombre (opcionalmente calificado por esquema) de una función que es una función de soporte de método de índice para la clase de
operador.

argument_typ

e
El tipo de datos del parámetro de la
función.

storage_typ

e
El tipo de datos realmente almacenado en el índice. Normalmente este es el mismo que el tipo de datos de la columna, pero algunos métodos de índice (actualmente GiST, GIN, SP-GiST y BRIN) permiten que sea diferente. La cláusula STORAGE debe omitirse a menos que el método de índice permita usar un tipo diferente. Si la columna data_type se especifica como anyarray, el storage_type puede declararse como anyelement para indicar que las entradas del índice son miembros del tipo de elemento que pertenece al tipo de array real para el que se crea cada índice
particular.

Las cláusulas OPERATOR, FUN

CTION y STORAGE pueden apare
cer en cualquier orden.

NOTA

S

Debido a que el mecanismo de índice no verifica los permisos de acceso en las funciones antes de usarlas, incluir una función u operador en una clase de operador equivale a conceder permiso de ejecución pública sobre ella. Esto generalmente no es un problema para los tipos de funciones que son útiles en una clase de

operador.

Los operadores no deberían definirse con funciones SQL. Una función S

QL probablemente se inlineará en la consulta de llamada, lo que impedirá
que el optimizador reconozca que la consulta coincide con un índice.

EJEMPLO

S

El siguiente comando de ejemplo define una clase de operador de índice GiST para el tipo de datos _int4 (array de int4). Consulte el módulo intarray para el ejemplo

completo. 
CREATE OPERATOR CLASS gist__int_ops
    DEFAULT FOR TYPE _int4 USING gist AS
        OPERATOR        3       &&,
        OPERATOR        6       = (anyarray, anyarray),
        OPERATOR        7
@>, OPERATOR 8 <@, OPERATOR 20 @@ (_int4, query_int), FUNCTION 1 g_int_consistent (internal, _int4, smallint, oid, internal),
FUNCTION 2 g_int_union (internal, internal), FUNCTION 3 g_int_compress (internal), FUNCTION 4 g_int_decompress (internal), FUNCTION
5 g_int_penalty (internal, internal, internal), FUNCTION 6 g_int_picksplit (internal, internal), FUNCTION 7 g_int_same (_int4, _int4, internal);
