CRYPTSETUP-REENCRYPT(8) Comandos de mantenimiento CRYPTSETUP-REENCRYPT(8)

NOMBRE

cryptsetup-reencrypt - Reencripta volúmenes encriptados LUKS in-situ

SINOPSIS

cryptsetup reencrypt [<opciones>] <dispositivo> o --active-name <nombre> [<nuevo_nombre>]

DESCRIPCIÓN

Ejecuta la reencriptación de un dispositivo LUKS.

Hay 3 modos básicos de operación:

• Reencriptación de dispositivo (reencrypt)
• Encriptación de dispositivo (reencrypt --encrypt/--new/-N)
• Desencriptación de dispositivo (reencrypt --decrypt)

<dispositivo> o --active-name <nombre> (solo LUKS2) es un parámetro obligatorio.

La acción reencrypt de cryptsetup puede usarse para cambiar parámetros de reencriptación, que de otra manera requerirían un cambio completo de datos en el disco (re-encriptación). La acción reencrypt reencripta los datos en el dispositivo LUKS in-situ.

Puedes regenerar la clave del volumen (la clave real utilizada en la encriptación en disco desbloqueada por contraseña), el cifrado, el modo de cifrado o el tamaño del sector de encriptación (solo LUKS2).

Si necesitas usar tanto luksChangeKey como reencrypt (por ejemplo, para recuperarse de una filtración), necesitas usarlos en ese orden para evitar filtrar la nueva clave del volumen.

El proceso de reencriptación puede ser interrumpido de forma segura por un usuario mediante la señal SIGINT (ctrl+c). Lo mismo se aplica a la señal SIGTERM (es decir, emitida por systemd durante el apagado del sistema).

Para el modo de encriptación in-situ, la acción reencrypt además toma todas las opciones disponibles para la acción luksFormat para la versión LUKS respectiva (ver la página del manual cryptsetup-luksFormat para más detalles). Ver cryptsetup-luksFormat(8).

Ten en cuenta que para el modo de encriptación y desencriptación, el dispositivo completo debe tratarse como no encriptado; no hay garantías de confidencialidad, ya que parte del dispositivo contiene texto plano.

ASEGÚRATE SIEMPRE DE TENER UNA COPIA DE SEGURIDAD FIABLE ANTES DE USAR ESTA ACCIÓN EN UN DISPOSITIVO LUKS.

<opciones> pueden ser [--batch-mode, --block-size, --cipher, --debug, --debug-json, --decrypt, --device-size, --disable-locks, --encrypt, --force-offline-reencrypt, --hash, --header, --hotzone-size, --iter-time, --init-only, --keep-key, --key-file, --key-size, --key-slot, --keyfile-offset, --keyfile-size, --tries, --timeout, --pbkdf, --pbkdf-force-iterations, --pbkdf-memory, --pbkdf-parallel, --progress-frequency, --progress-json, --reduce-device-size, --resilience, --resilience-hash, --resume-only, --sector-size, --use-directio, --use-random, --use-urandom, --use-fsync, --uuid, --verbose, --volume-key-file, --write-log].

REENCRIPTACION LUKS2

Con el parámetro <dispositivo>, cryptsetup busca el mapeo activo de <dispositivo> dm. Si no se detecta ningún mapeo activo, inicia la reencriptación LUKS2 sin conexión; de lo contrario, se produce la reencriptación en línea.

Para reanudar una reencriptación ya inicializada o interrumpida, simplemente ejecuta de nuevo el comando cryptsetup reencrypt para continuar la operación de reencriptación. La reencriptación puede reanudarse con diferentes --resilience o --hotzone-size, a menos que se utilice el modo de resiliencia de cambio de datos implícito: ya sea el modo de encriptación con la opción --reduce-device-size o el modo de desencriptación con la cabecera LUKS2 original exportada en el archivo --header.

Si el proceso de reencriptación se interrumpió abruptamente (fallo del proceso de reencriptación, fallo del sistema o apagado), puede requerir recuperación. La recuperación se ejecuta automáticamente en la siguiente activación (acción open) cuando sea necesario o explícitamente por el usuario (acción repair).

El parámetro opcional <nuevo_nombre> entra en vigor solo con la opción de encriptación, y activa el dispositivo <nuevo_nombre> inmediatamente después de que se complete la inicialización de la encriptación. Esto es útil cuando el dispositivo necesita estar listo lo antes posible y ser montado (usado) antes de que se complete la encriptación completa del área de datos.

REENCRIPTACION LUKS1

El directorio de trabajo actual debe ser escribible y los archivos temporales creados durante la reencriptación deben estar presentes. Durante la reencriptación, el dispositivo LUKS1 se marca como no disponible y debe estar sin conexión (sin mapeo dm-crypt o sistema de archivos montado).

ADVERTENCIA: El código de reencriptación LUKS1 no es resistente a fallos de hardware o del kernel durante la reencriptación (puedes perder tus datos en este caso).

OPCIONES

--align-payload <número de sectores de 512 bytes> (OBSOLETO, usar --offset)

Alinea la carga útil en un límite de valor sectores de 512 bytes.

Si no se especifica, cryptsetup intenta usar la información de topología proporcionada por el kernel para el dispositivo subyacente para obtener la alineación óptima. Si no está disponible (o el valor calculado es un múltiplo del valor predeterminado), los datos se alinean por defecto a un límite de 1MiB (es decir, 2048 sectores de 512 bytes).

Para una cabecera LUKS separada, esta opción especifica el desplazamiento en el dispositivo de datos. Ver también la opción --header.

Esta opción está OBSOLETA y tiene un impacto inesperado en el desplazamiento de datos y el tamaño del área de claves (para LUKS2) debido al complejo redondeo. Para un desplazamiento fijo del dispositivo de datos, usa la opción --offset en su lugar.

--batch-mode, -q

Suprime todas las preguntas de confirmación. ¡Usar con cuidado!

Si no se especifica la opción --verify-passphrase, esta opción también desactiva la verificación de la contraseña.

--block-size valor (solo LUKS1)

Usa un tamaño de bloque de reencriptación de valor en MiB.

Los valores pueden estar entre 1 y 64 MiB.

--cipher, -c <espec-cifrado>

LUKS2: Establece la cadena de especificación del cifrado solo para el segmento de datos.

LUKS1: Establece la cadena de especificación del cifrado para el segmento de datos y las claves.

Se aplica el cifrado predeterminado si se omite la especificación del cifrado en modo de encriptación.

En modo de reencriptación, si no se solicita una nueva especificación de cifrado, el cifrado existente permanecerá. La única excepción es si el cifrado es "cipher_null", entonces se utiliza el cifrado predeterminado.

cryptsetup --help muestra los valores predeterminados compilados.

Si un hash forma parte de la especificación del cifrado, se usa como parte de la generación del IV. Por ejemplo, ESSIV necesita una función hash, mientras que "plain64" no la necesita y, por lo tanto, no se especifica ninguna.

Para el modo XTS, puedes establecer opcionalmente un tamaño de clave de 512 bits con la opción -s. El tamaño de clave para el modo XTS es el doble que para otros modos con el mismo nivel de seguridad.

--debug o --debug-json

Ejecuta en modo de depuración con registros de diagnóstico completos. Las líneas de salida de depuración siempre van precedidas de #.

Si se usa --debug-json, se imprimen estructuras de datos JSON adicionales de LUKS2.

--decrypt

Inicializa (y ejecuta) el modo de desencriptación de dispositivo.

--device-size tamaño[unidades]

En lugar del tamaño real del dispositivo, utiliza el valor especificado. Significa que solo el área especificada (desde el inicio del dispositivo hasta el tamaño especificado) se reencriptará.

LUKS2: Cuando se usa junto con --reduce-device-size, solo el valor inicial tamaño (--device-size parameter) de datos se desplaza hacia atrás mientras se encripta.

La suma de los valores de --device-size y --reduce-device-size no debe exceder el tamaño real del dispositivo.

ADVERTENCIA: Esta es una operación destructiva. Los datos más allá del límite de --device-size pueden perderse después de que la operación haya finalizado.

Si no se especifica un sufijo de unidad, el tamaño está en bytes.

El sufijo de unidad puede ser S para sectores de 512 bytes, K/M/G/T (o KiB, MiB, GiB, TiB) para unidades con base 1024 o KB/MB/GB/TB para base 1000 (escala SI).

--disable-blkid

Desactiva el uso de la biblioteca blkid para verificar y borrar firmas en el disco.

--disable-keyring

No cargue la clave del volumen en el keyring del kernel; almacénela directamente en el destino dm-crypt en su lugar. Esta opción solo es compatible con el tipo LUKS2.

--disable-locks

Desactiva la protección de bloqueo para metadatos en disco. Esta opción es válida solo para LUKS2 y se ignora para otros formatos.

Con los bloqueos desactivados, las imágenes LUKS2 en archivos pueden ser completamente (re)encriptadas o

offline sin la necesidad de privilegios de superusuario, siempre que los cifrados de bloque utilizados estén disponibles en el backend criptográfico.

ADVERTENCIA: No utilice esta opción a menos que ejecute cryptsetup en un entorno restringido donde el bloqueo sea imposible de realizar (donde el directorio /run no pueda ser utilizado).

--encrypt, --new, -N

Inicializa (y ejecuta) el dispositivo en modo de cifrado en el lugar.

--force-no-keyslots (solo LUKS2)

Fuerza la inicialización de la operación de re-cifrado con parámetros adicionales --volume-key-file, --new-volume-key-file, --volume-key-keyring o --new-volume-key-keyring. Esto resultaría en la eliminación de todas las ranuras de claves LUKS2 restantes que contienen la clave del volumen.

La ranura de clave LUKS2 con la nueva clave del volumen puede ser añadida después de que la operación de re-cifrado haya finalizado. Consulte el comando cryptsetup-luksAddKey(8).

ADVERTENCIA: ¡Úselo con extrema precaución! Si pierde la clave del volumen almacenada en un archivo o en un keyring del kernel antes de añadir la ranura de clave LUKS2 que contiene la nueva clave del volumen, el dispositivo se volverá inutilizable y todos los datos se perderán.

--force-offline-reencrypt (solo LUKS2)

Omite la detección automática de dispositivos activos y fuerza el re-cifrado sin conexión.

Esta opción es útil especialmente para el re-cifrado de imágenes LUKS2 puestas en archivos (la detección automática no es fiable en este escenario).

También puede ayudar en caso de que la detección automática de dispositivos activos en un dispositivo de datos particular no funcione o informe de errores.

ADVERTENCIA: ¡Úselo con extrema precaución! Esto puede destruir datos si el dispositivo está activado y/o en uso activo.

--force-password

No utilice la comprobación de calidad de contraseña para las nuevas contraseñas LUKS.

Esta opción se ignora si cryptsetup está compilado sin soporte de comprobación de calidad de contraseña.

Para más información sobre la comprobación de calidad de contraseña, consulte la página del manual de pwquality.conf(5) y passwdqc.conf(5).

--hash, -h <especificación-hash>

LUKS1: Especifica el hash utilizado en el esquema de configuración de clave LUKS1 y el resumen de la clave del volumen.

Si este parámetro no se especifica, el algoritmo de hash por defecto siempre se utiliza para una nueva cabecera de dispositivo LUKS1.

LUKS2: Se ignora a menos que el algoritmo pbkdf de la nueva ranura de clave se establezca en PBKDF2 (ver --pbkdf).

--header <dispositivo o archivo que almacena la cabecera LUKS>

Utiliza un dispositivo o archivo de metadatos separado (detached) donde se almacena la cabecera LUKS. Esta opción permite almacenar el texto cifrado y la cabecera LUKS en dispositivos diferentes.

Si se usa con la opción --encrypt/--new, el archivo de cabecera será creado (o sobrescrito). Úselo con cuidado.

LUKS2: Para el modo de descifrado, la opción puede ser usada para exportar la cabecera LUKS2 original a un archivo separado. El archivo futuro pasado no debe existir en el momento de inicializar la operación de descifrado. Esto libera espacio en la cabeza del dispositivo de datos para que los datos puedan ser movidos a la ubicación original de la cabecera LUKS2. Más tarde, la operación de descifrado continúa como si se hubiera pasado una cabecera separada normal.

ADVERTENCIA: ¡Nunca coloque un archivo de cabecera exportado en un sistema de archivos encima del dispositivo que está a punto de descifrar! Causaría un punto muerto.

--help, -?

Muestra el texto de ayuda y los parámetros por defecto.

--hotzone-size tamaño (solo LUKS2)

Esta opción se puede utilizar para establecer un límite superior en el tamaño del área de re-cifrado (zona activa). El *tamaño* puede especificarse con un sufijo de unidad (por ejemplo, 50M). Tenga en cuenta que el tamaño real de la zona activa puede ser menor que el <tamaño> especificado debido a otras limitaciones (espacio libre en el área de ranuras de claves o memoria disponible).

Con el modo de descifrado para dispositivos con cabecera LUKS2 ubicada en la cabeza del dispositivo de datos, la opción especifica cuán grande es el primer segmento de datos movido desde el puntero de desplazamiento de datos original.

--init-only (solo LUKS2)

Inicializa la operación de re-cifrado (cualquier modo) en los metadatos LUKS2 solamente y sale. Si ya hay alguna operación de re-cifrado inicializada en los metadatos, el comando con el parámetro --init-only fallará.

--iter-time, -i <número de milisegundos>

El número de milisegundos a dedicar al procesamiento de la frase de contraseña PBKDF para la nueva cabecera LUKS.

--keep-key

LUKS2: No cambie la clave de volumen efectiva y cambie otros parámetros si se solicitan.

LUKS1: Solo re-cifra la cabecera y las ranuras de claves LUKS1. Omite el re-cifrado de datos en el lugar.

--key-file, -d archivo

Lee la frase de contraseña del archivo.

Si el nombre dado es "-", entonces la frase de contraseña se leerá desde stdin. En este caso, la lectura no se detendrá en los caracteres de nueva línea.

La opción --key-file solo se puede usar si hay solo una ranura de clave activa, o alternativamente, también si se especifica la opción --key-slot (entonces todas las demás ranuras de clave se deshabilitarán en el nuevo dispositivo LUKS).

Si esta opción no se usa, cryptsetup pedirá las frases de contraseña de todas las ranuras de clave activas.

--keyfile-offset valor

Omite *valor* bytes al principio del archivo de clave.

--keyfile-size, -l valor

Lee un máximo de *valor* bytes del archivo de clave. El valor por defecto es leer el archivo completo hasta el máximo compilado que se puede consultar con --help. Proporcionar más datos que el máximo compilado aborta la operación.

Esta opción es útil para cortar saltos de línea finales, por ejemplo. Si también se proporciona --keyfile-offset, el conteo del tamaño comienza después del desplazamiento.

--key-size, -s bits

LUKS2: Proporciona el tamaño de clave actual en *bits*. El argumento debe ser un múltiplo de 8. Útil al especificar el tamaño de la clave de volumen actual cuando no hay ninguna ranura de clave activa.

LUKS1: Ver --new-key-size.

--key-slot, -S <0-N>

Para operaciones LUKS que añaden material de clave, esta opción le permite especificar qué ranura de clave se selecciona para la nueva clave.

Para el modo de re-cifrado, selecciona una ranura de clave específica (y frase de contraseña) que se puede utilizar para desbloquear la nueva clave del volumen. Si se utiliza, todas las demás ranuras de clave se eliminarán después de que la operación de re-cifrado haya finalizado.

El número máximo de ranuras de clave depende de la versión de LUKS. LUKS1 puede tener hasta 8 ranuras de clave. LUKS2 puede tener hasta 32 ranuras de clave basándose en el tamaño del área de ranuras y el tamaño de la clave, pero una ID de ranura de clave válida siempre puede estar entre 0 y 31 para LUKS2.

--keyslot-cipher <especificación-cifrado>

Esta opción se puede utilizar para establecer un cifrado de clave específico para el área de ranuras de claves LUKS2.

--keyslot-key-size <bits>

Esta opción se puede utilizar para establecer un tamaño de clave específico para el área de ranuras de claves LUKS2.

--label <etiqueta>, --subsystem <subsistema>

Establece la descripción de etiqueta y subsistema para el dispositivo LUKS2. Estos son similares a las etiquetas de sistema de archivos. La etiqueta y el subsistema son campos opcionales y pueden ser utilizados posteriormente en scripts udev para activar acciones de usuario una vez que se detecta el dispositivo marcado con estas etiquetas.

--luks2-keyslots-size tamaño

Esta opción se puede utilizar para establecer un tamaño específico del área binaria de ranuras de claves LUKS2 (el material de clave se cifra allí). El valor debe estar alineado a un múltiplo de 4096 bytes con un tamaño máximo de 128 MB. El *tamaño* puede especificarse con un sufijo de unidad (por ejemplo, 128k).

--luks2-metadata-size tamaño

Esta opción se puede utilizar para ampliar el área de metadatos (JSON) de LUKS2. El tamaño incluye 4096 bytes para metadatos binarios (el área JSON utilizable es menor que el área binaria). Según la especificación LUKS2, solo los siguientes valores son válidos: 16, 32, 64, 128, 256, 512, 1024, 2048 y 4096 kB. El *tamaño* puede especificarse con un sufijo de unidad (por ejemplo, 128k).

--new-key-size bits

Establece el nuevo tamaño de clave en *bits*. El argumento debe ser un múltiplo de 8. Los tamaños de clave posibles están limitados por el nuevo cifrado y modo utilizados en el re-cifrado.

Consulte /proc/crypto para más información. Tenga en cuenta que el tamaño de clave en /proc/crypto se indica en bytes.

LUKS1: Si está aumentando el tamaño de la clave, debe haber suficiente espacio en la cabecera LUKS para las ranuras de clave ampliadas (el desplazamiento de datos debe ser lo suficientemente grande), o el re-cifrado no puede realizarse.

Si no hay suficiente espacio para las ranuras de clave con el nuevo tamaño de clave, puede reducir destructivamente el dispositivo con la opción --reduce-device-size.

--new-volume-key-file archivo

Utiliza (establece) la nueva clave de volumen almacenada en un archivo. La opción debe emparejarse con el parámetro --new-key-size al inicializar la operación de re-cifrado.

ADVERTENCIA: Si crea su propia clave de volumen, debe asegurarse de hacerlo correctamente. De lo contrario, puede terminar con una clave de volumen de baja entropía o parcialmente predecible, lo que comprometerá la seguridad.

--new-volume-key-keyring <descripción de clave>

Utiliza (establece) la nueva clave de volumen almacenada en un keyring.

El tamaño de la clave almacenada en un keyring debe ser compatible con el nuevo cifrado utilizado en la operación de re-cifrado. Consulte /proc/crypto para más información. Tenga en cuenta que el tamaño de clave en /proc/crypto se indica en bytes.

La *<descripción de clave>* utiliza sintaxis compatible con keyctl. Puede ser un ID de clave numérico o un nombre de cadena en el formato *%<tipo de clave>:<nombre de clave>*. Vea también la sección IDENTIFICADORES DE CLAVE de keyctl(1). Cuando no se especifica un prefijo *%<tipo de clave>:*, asumimos que el tipo de clave es *user* (tipo por defecto).

ADVERTENCIA: Si crea su propia clave de volumen, debe asegurarse de hacerlo correctamente. De lo contrario, puede terminar con una clave de volumen de baja entropía o parcialmente predecible, lo que comprometerá la seguridad.

--offset, -o <número de sectores de 512 bytes>

Desplazamiento de inicio en el dispositivo backend en sectores de 512 bytes. Esta opción solo es relevante para el modo de cifrado.

La opción --offset establece el desplazamiento de datos (payload) del dispositivo de datos y debe estar alineado a sectores de 4096 bytes (debe ser un múltiplo de 8). Esta opción no se puede combinar con la opción --align-payload.

--pbkdf <especificación-PBKDF>

Establece la función de derivación de clave basada en contraseña (PBKDF) para la ranura de clave LUKS. El PBKDF puede be: pbkdf2 (para PBKDF2 según RFC2898), argon2i para Argon2i o argon2id para Argon2id (ver Argon2 https://www.cryptolux.org/index.php/Argon2 para más información).

Para LUKS1, solo se acepta PBKDF2 (no es necesario usar esta opción). El PBKDF por defecto para LUKS2 se establece en tiempo de compilación y está disponible en la salida de cryptsetup --help.

Un PBKDF se utiliza para aumentar el coste de los ataques de diccionario y fuerza bruta para las contraseñas de las ranuras de clave. Los parámetros pueden ser coste de tiempo, memoria y coste paralelo.

Para PBKDF2, solo se aplica el coste de tiempo (número de iteraciones). Para Argon2i/id, también existe el coste de memoria (memoria requerida durante el proceso de derivación de clave) y el coste paralelo (número de hilos que se ejecutan en paralelo durante la derivación de clave).

Tenga en cuenta que aumentar el coste de memoria también aumenta el tiempo, por lo que los valores finales de los parámetros se miden mediante una prueba de referencia. La prueba de referencia intenta encontrar el tiempo de iteración (--iter-time) con el coste de memoria requerido --pbkdf-memory. Si no es posible, el coste de memoria también se reduce. El coste paralelo --pbkdf-parallel es constante y se compara con los núcleos de CPU disponibles.

Puede ver todos los parámetros PBKDF para una ranura de clave LUKS2 particular con el comando cryptsetup-luksDump(8).

Si no desea utilizar la prueba de referencia y desea especificar todos los parámetros directamente, use --pbkdf-force-iterations con --pbkdf-memory y --pbkdf-parallel. Esto anulará los valores sin realizar una prueba de referencia. Tenga en cuenta que puede causar tiempos de desbloqueo extremadamente largos o condiciones de falta de memoria con terminación incondicional del proceso. Úselo solo en casos específicos, por ejemplo, si sabe que el dispositivo formateado se utilizará en algún sistema integrado pequeño.

COSTES MÍNIMOS Y MÁXIMOS DE PBKDF: Para **PBKDF2**, el número mínimo de iteraciones es 1000 y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). Los costes de memoria y paralelo no son compatibles con PBKDF2. Para **Argon2i** y **Argon2id**, el número mínimo de iteraciones (coste de CPU) es 4 y el máximo es 4294967295 (máximo para un entero sin signo de 32 bits). El coste de memoria mínimo es 32 KiB y el máximo es 4 GiB. Si el parámetro de coste de memoria se evalúa mediante prueba de referencia (no especificado por un parámetro), siempre está en el rango de 64 MiB a 1 GiB. El coste de memoria superior a 1 GiB (hasta el máximo de 4 GiB) solo se puede configurar mediante el parámetro --pbkdf-memory. El coste paralelo mínimo es 1 y el máximo es 4 (si hay suficientes núcleos de CPU disponibles, de lo contrario, se reduce según los núcleos de CPU disponibles).

ADVERTENCIA: Aumentar los costes computacionales de PBKDF por encima de los límites mencionados proporciona una mejora de seguridad adicional insignificante. Si bien los costes elevados aumentan significativamente la sobrecarga de la fuerza bruta, ofrecen una protección insignificante contra los ataques de diccionario. El aumento marginal del coste para procesar un diccionario completo sigue siendo fundamentalmente insuficiente.

Los límites de PBKDF codificados representan compromisos de ingeniería entre la seguridad criptográfica y la usabilidad operativa. LUKS mantiene la portabilidad y debe utilizarse dentro de un tiempo razonable en sistemas con recursos limitados.

Cryptsetup restringe deliberadamente los parámetros máximos de coste de memoria (4 GiB) y coste paralelo (4) debido a limitaciones arquitectónicas (como sistemas integrados y heredados).

El coste de memoria de PBKDF exige la asignación real de RAM física con operaciones de escritura intensivas que deben permanecer en la RAM física. Cualquier uso de intercambio resulta en una degradación inaceptable del rendimiento. La gestión de memoria a menudo sobreasigna asignaciones más allá de la memoria física disponible, esperando que la mayor parte de la memoria asignada permanezca sin usar. En tales situaciones, dado que PBKDF siempre utiliza toda la memoria asignada, frecuentemente causa errores de falta de memoria que abortan las operaciones de cryptsetup.

--pbkdf-force-iterations número

Evita la prueba de referencia de PBKDF y establece el coste de tiempo (iteraciones) directamente. Solo se puede usar para un dispositivo LUKS/LUKS2. Ver --pbkdf opción para más información.

--pbkdf-memory número

Establece el coste de memoria para PBKDF (para Argon2i/id, el número representa kilobytes). Tenga en cuenta que es el valor máximo; la prueba de referencia de PBKDF o la memoria física disponible pueden disminuirlo. Esta opción no está disponible para PBKDF2.

--pbkdf-parallel número

Establece el coste paralelo para PBKDF (número de hilos, hasta 4). Tenga en cuenta que es el valor máximo; se reduce automáticamente si el número de núcleos de CPU en línea es menor. Esta opción no está disponible para PBKDF2.

--progress-frequency segundos

Imprime una línea separada cada segundos con el progreso de la reencriptación.

--progress-json

Imprime datos de progreso en formato JSON, lo cual es adecuado principalmente para el procesamiento por máquinas. Imprime una línea separada cada medio segundo (o según el valor de --progress-frequency). La salida JSON se ve como sigue durante el progreso (excepto que es una única línea compacta): 
{
  "device":"/dev/sda",      // dispositivo o archivo subyacente
  "device_bytes":"8192",    // bytes de E/S hasta ahora
  "device_size":"44040192", // bytes totales de E/S restantes
  "speed":"126877696",      // velocidad calculada en bytes por segundo (basada en el progreso hasta ahora)
  "eta_ms":"2520012",       // tiempo estimado para finalizar una operación en milisegundos
  "time_ms":"5561235"       // tiempo total invertido en la operación de E/S en milisegundos
}

Nota sobre los números en la salida JSON: Debido a las limitaciones del analizador JSON, todos los números se representan en formato de cadena debido a la necesidad de enteros sin signo de 64 bits completos.

--reduce-device-size tamaño

Esto significa que los últimos tamaño sectores del dispositivo original se perderán, y los datos se desplazarán efectivamente por el número especificado de sectores.

Podría ser útil si agregó espacio a la partición subyacente o al volumen lógico (de modo que los últimos tamaño sectores no contengan datos).

Para el sufijo de unidades, consulte la descripción del parámetro --device-size.

ADVERTENCIA: Esta es una operación destructiva y no se puede revertir. Úselo con extrema precaución: los sistemas de archivos sobrescritos accidentalmente suelen ser irrecuperables.

LUKS2: Inicializa la reencriptación LUKS2 con reducción del tamaño del dispositivo de datos (actualmente, solo se admite el modo de encriptación). Los últimos tamaño sectores del dispositivo de texto plano original se utilizan para almacenar temporalmente el primer segmento de datos original. El primer segmento de datos anterior se reemplaza con la cabecera LUKS2 (la mitad del valor tamaño), y los datos de texto plano se desplazan hacia atrás (de nuevo, la mitad del valor tamaño) mientras se encriptan.

El tamaño mínimo recomendado es el doble del tamaño de cabecera LUKS2 por defecto (--reduce-device-size 32M) para el modo de encriptación.

La suma de los valores de --device-size y --reduce-device-size no debe exceder el tamaño real del dispositivo.

LUKS1: Amplía el desplazamiento de datos al valor especificado reduciendo el tamaño del dispositivo.

No puede reducir el dispositivo en más de 64 MiB (131072 sectores).

--resilience modo (solo LUKS2)

El modo de resiliencia de reencriptación puede ser uno de checksum, journal o none.

checksum: modo por defecto, donde se almacenan sumas de verificación individuales de los sectores de la zona activa cifrada, por lo que el proceso de recuperación puede detectar qué sectores ya han sido re encriptados. Requiere que la escritura de sectores del dispositivo sea atómica.

journal: La zona activa se registra en el área binaria (por lo que los datos se escriben dos veces).

none: Modo de rendimiento. No hay protección, y la única forma segura de interrumpir la reencriptación es similar a una utilidad de reencriptación sin conexión antigua.

Los modos de resiliencia se pueden cambiar a menos que se utilice el modo datashift para la inicialización de la operación (encriptación con la opción --reduce-device-size).

--resilience-hash hash (solo LUKS2)

El algoritmo de hash se utiliza solo con "--resilience checksum". El hash por defecto es sha256. Con otros modos de resiliencia, el parámetro de hash se ignora.

--resume-only (solo LUKS2)

Reanuda la operación de reencriptación (cualquier modo) que ya está descrita en los metadatos de LUKS2. Si no se ha inicializado ninguna operación de reencriptación, el comando con el parámetro --resume-only falla. Útil para reanudar la operación de reencriptación sin activar accidentalmente una nueva operación de reencriptación.

--sector-size bytes (solo LUKS2)

Reencripta el dispositivo con un nuevo tamaño de sector de encriptación forzado.

ADVERTENCIA: Aumentar el tamaño del sector de encriptación puede dañar el sistema de archivos alojado. No ejecute la reencriptación con --force-offline-reencrypt si no está seguro con qué tamaño de bloque se formateó el sistema de archivos.

Tenga en cuenta que usar un tamaño de sector mayor que el tamaño de sector físico del dispositivo de almacenamiento subyacente puede provocar corrupción de datos durante fallos de energía inesperados. Un fallo de energía durante las operaciones de escritura puede resultar en la finalización parcial de la escritura del sector de encriptación, dejando los datos encriptados en un estado inconsistente que no se puede descifrar correctamente.

--timeout, -t segundos

El número de segundos a esperar antes de que se produzca un tiempo de espera en la entrada de la frase de paso a través de la terminal. Es relevante cada vez que se solicita una frase de paso. No tiene ningún efecto si se usa junto con --key-file.

Esta opción es útil cuando el sistema no debe bloquearse si el usuario no introduce una frase de paso, por ejemplo, durante el arranque. El valor por defecto es 0 segundos, lo que significa esperar indefinidamente.

--token-id

Inicialización de reencriptación LUKS2: Especifica qué ranuras de clave (asociadas con el token seleccionado) usar para la reencriptación LUKS2. Si la operación de reencriptación cambia la clave de volumen efectiva, solo las ranuras de clave asociadas con el token y desbloqueadas correctamente estarán disponibles después de que finalice la operación de reencriptación.

Reanudación de reencriptación LUKS2: Especifica qué token usar y permite que el aviso de PIN del token tenga prioridad sobre el aviso interactivo de la frase de paso de la ranura de clave. Si se omite, se comprobarán todos los tokens disponibles (no protegidos por PIN) antes de continuar con el aviso de la frase de paso.

--token-only

Inicialización de reencriptación LUKS2: Especifica que se utilizarán todas las ranuras de clave asociadas con cualquier token para la reencriptación LUKS2. Si la operación de reencriptación cambia la clave de volumen efectiva, solo las ranuras de clave asociadas con cualquier token estarán disponibles después de que finalice la operación de reencriptación.

Reanudación de reencriptación LUKS2: No continúe con la acción si el desbloqueo de la ranura de clave basado en token falló. Sin la opción, la acción solicita una frase de paso para continuar.

cryptsetup reencrypt --encrypt --type luks2 --reduce-device-size 32m /dev/plaintext_devic

cryptsetup reencrypt --encrypt --type luks2 --device-size 1g --reduce-device-size 32m /dev/plaintext_devic
