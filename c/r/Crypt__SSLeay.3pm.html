NOMBRE

Crypt::SSLeay - Soporte de OpenSSL para LWP

ADVERTENCIA HEARTBLEED

"perl Makefile.PL" mostrará una advertencia si considera que su OpenSSL podría ser vulnerable al error Heartbleed https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2014-0160. Por supuesto, puede proceder a instalar el módulo, pero debe ser consciente de que su sistema podría estar expuesto a una vulnerabilidad extremadamente grave. Esta es solo una heurística basada en la versión reportada por OpenSSL. Es completamente posible que su distribución haya publicado realmente una biblioteca parcheada, por lo que si tiene dudas, debería investigar más a fondo.

SINOPSIS

use Net::SSL;
use LWP::UserAgent;
my $ua  = LWP::UserAgent->new(
    ssl_opts => { verify_hostname => 0 },
);
my $response = $ua->get('https://www.example.com/');
print $response->content, "\n";

DESCRIPCIÓN

Este módulo de Perl proporciona soporte para el protocolo HTTPS bajo LWP, para permitir que un objeto LWP::UserAgent realice peticiones GET, HEAD y POST sobre conexiones de socket cifradas. Por favor, consulte LWP para obtener más información sobre las peticiones POST.

El paquete "Crypt::SSLeay" proporciona "Net::SSL", que, si se solicita, es cargado por "LWP::Protocol::https" para peticiones https y proporciona el enlace SSL necesario.

Esta distribución también hace disponibles los siguientes módulos obsoletos:

Crypt::SSLeay::CTX
Crypt::SSLeay::Conn
Crypt::SSLeay::X509

¿NECESITA Crypt::SSLeay?

A partir de la versión 6.02 de LWP, el soporte de "https" se desacopló en LWP::Protocol::https. Este módulo especifica como una de sus prerrequisitos IO::Socket::SSL, el cual es utilizado automáticamente por LWP::UserAgent a menos que esta preferencia se anule por separado. "IO::Socket::SSL" es una implementación más completa y, crucialmente, permite la verificación del nombre de host. "Crypt::SSLeay" no soporta esto. En este punto, "Crypt::SSLeay" se mantiene para soportar software existente que ya depende de él. Sin embargo, es posible que su software no dependa realmente de "Crypt::SSLeay", sino solo de la capacidad de la clase "LWP::UserAgent" para comunicarse con sitios a través de SSL/TLS.

Si está usando la versión "LWP" 6.02 o posterior, y por lo tanto ha instalado "LWP::Protocol::https" y sus dependencias, y no usa explícitamente "use" "Net::SSL" antes de cargar "LWP::UserAgent", o anula la clase de socket predeterminada, probablemente esté usando "IO::Socket::SSL" y no realmente necesite "Crypt::SSLeay".

Si tiene tanto "Crypt::SSLeay" como "IO::Socket::SSL" instalados, y desea forzar a "LWP::UserAgent" a usar "Crypt::SSLeay", puede usar:

use Net::HTTPS;
$Net::HTTPS::SSL_SOCKET_CLASS = 'Net::SSL';
use LWP::UserAgent;

o

local $ENV{PERL_NET_HTTPS_SSL_SOCKET_CLASS} = 'Net::SSL';
use LWP::UserAgent;

o

use Net::SSL;
use LWP::UserAgent;

VARIABLES DE ENTORNO

Especificar la clase de socket SSL
$ENV{PERL_NET_HTTPS_SSL_SOCKET_CLASS} se puede usar para instruir a "LWP::UserAgent" para que use "Net::SSL" para el soporte HTTPS en lugar de "IO::Socket::SSL".
Soporte de proxy
$ENV{HTTPS_PROXY} = 'http://proxy_hostname_or_ip:port';
Autenticación básica del proxy
$ENV{HTTPS_PROXY_USERNAME} = 'username';
$ENV{HTTPS_PROXY_PASSWORD} = 'password';
Diagnóstico y depuración de SSL
$ENV{HTTPS_DEBUG} = 1;
Versión SSL predeterminada
$ENV{HTTPS_VERSION} = '3';
Soporte de certificado de cliente
$ENV{HTTPS_CERT_FILE} = 'certs/notacacert.pem';
$ENV{HTTPS_KEY_FILE}  = 'certs/notacakeynopass.pem';
Verificación de pares de certificados CA
$ENV{HTTPS_CA_FILE}   = 'certs/ca-bundle.crt';
$ENV{HTTPS_CA_DIR}    = 'certs/';
Soporte de certificado PKCS12 de cliente
$ENV{HTTPS_PKCS12_FILE}     = 'certs/pkcs12.pkcs12';
$ENV{HTTPS_PKCS12_PASSWORD} = 'PKCS12_PASSWORD';

INSTALACIÓN

OpenSSL

Debe tener OpenSSL instalado antes de compilar este módulo. Puede obtener el paquete más reciente de OpenSSL desde https://www.openssl.org/source/. Ya no soportamos versiones de OpenSSL anteriores al año 2000.

Si está compilando OpenSSL desde el código fuente, por favor siga las instrucciones incluidas en el paquete de código fuente.

Crypt::SSLeay vía Makefile.PL

"Makefile.PL" acepta los siguientes argumentos de línea de comandos:

"incpath"
Ruta a los encabezados de OpenSSL. También se puede especificar mediante $ENV{OPENSSL_INCLUDE}. Si se proporciona el argumento de línea de comandos, anula cualquier valor especificado a través de la variable de entorno. Por supuesto, puede ignorar tanto el argumento de línea de comandos como la variable de entorno, y simplemente agregar la ruta a la variable de entorno específica de su compilador, como "CPATH" o "INCLUDE" etc.
"libpath"
Ruta a las bibliotecas de OpenSSL. También se puede especificar mediante $ENV{OPENSSL_LIB}. Si se proporciona el argumento de línea de comandos, anula cualquier valor especificado por la variable de entorno. Por supuesto, puede ignorar tanto el argumento de línea de comandos como la variable de entorno y simplemente agregar la ruta a la variable de entorno específica de su compilador, como "LIBRARY_PATH" o "LIB" etc.
"live-tests"
Use "--live-tests" para solicitar pruebas que intenten conectarse a un sitio web externo, y "--no-live_tests" para evitar que se ejecuten dichas pruebas. Si ejecuta "Makefile.PL" interactivamente, y este argumento no se especifica en la línea de comandos, se le pedirá un valor.

El valor predeterminado es falso.

"static"
Booleano. El valor predeterminado es falso. POR HACER: ¿Funciona?
"verbose"
Booleano. El valor predeterminado es falso. Si pasa "--verbose" en la línea de comandos, tanto las instancias de "Devel::CheckLib" como de "ExtUtils::CBuilder" se configurarán para mostrar lo que están haciendo.

Si todo se compila correctamente, pero obtiene fallos durante las pruebas, asegúrese de que "LD_LIBRARY_PATH" apunte a la ubicación donde se encuentran las bibliotecas compartidas correctas.

Si está usando una compilación personalizada de OpenSSL, por favor tenga en cuenta que "Crypt::SSLeay" debe compilarse usando el mismo compilador y herramientas de construcción utilizados para compilar "perl" y OpenSSL. Esto puede ser más problemático en Windows. Si está usando Active State Perl, instale el paquete MinGW distribuido por ellos, y construya OpenSSL con él antes de intentar construir este módulo. Si ha compilado su propio Perl usando herramientas o IDEs del Microsoft SDK, asegúrese de compilar OpenSSL usando las mismas herramientas.

Dependiendo de su SO, pueden estar disponibles paquetes de OpenSSL precompilados. Para obtener las cabeceras requeridas y las bibliotecas de importación, puede que necesite instalar una versión de desarrollo del paquete de la biblioteca OpenSSL de su sistema operativo. La clave es que "Crypt::SSLeay" hace llamadas a la biblioteca OpenSSL, y cómo hacerlo está especificado en los archivos de cabecera C que vienen con la biblioteca. Algunos sistemas separan los archivos de cabecera en un paquete distinto del de las bibliotecas. Una vez que el programa ha sido compilado, ya no necesita las cabeceras.

Crypt::SSLeay

La última versión de Crypt::SSLeay se puede encontrar en su mirror CPAN más cercano, así como en https://metacpan.org/pod/Crypt::SSLeay.

Una vez que la haya descargado, "Crypt::SSLeay" se instala fácilmente usando el proceso de compilación estándar:

$ perl Makefile.PL
$ make
$ make test
$ make install

o

$ cpanm Crypt::SSLeay

Si tiene las cabeceras y bibliotecas de OpenSSL en ubicaciones no estándar, puede usar

$ perl Makefile.PL --incpath=... --libpath=...

Si desea usar "cpanm" con esas ubicaciones personalizadas, puede hacer

$ OPENSSL_INCLUDE=... OPENSSL_LIB=... cpanm Crypt::SSLeay

Por ejemplo, en OS X (Mac) con Homebrew:

$ brew install openssl
$ OPENSSL_INCLUDE=$(brew --prefix openssl)/include OPENSSL_LIB=$(brew --prefix openssl)/lib cpanm Crypt::SSLeay

o, en Windows,

> set OPENSSL_INCLUDE=...
> set OPENSSL_LIB=...
> cpanm Crypt::SSLeay

Si está en Windows, y usando una distribución MinGW incluida con ActiveState Perl o Strawberry Perl, usaría "dmake" en lugar de "make". Si está usando las herramientas de compilación de Microsoft, usaría "nmake".

Para instalaciones no atendidas (por lotes), para estar absolutamente seguro de que Makefile.PL no solicite preguntas en STDIN, establezca la variable de entorno "PERL_MM_USE_DEFAULT=1" como con cualquier módulo CPAN compilado usando ExtUtils::MakeMaker.

VMS

No tengo ninguna experiencia con VMS. Si las cabeceras y bibliotecas de OpenSSL no están en las ubicaciones estándar que su sistema de compilación busca por defecto, configure las cosas para que lo estén. Si tiene instrucciones genéricas sobre cómo hacerlo, por favor abra un ticket en RT con la información para que pueda añadirla a este documento.

SOPORTE DE PROXY

LWP::UserAgent y Crypt::SSLeay tienen sus propias versiones de soporte de proxy. Por favor lea estas secciones para ver cuál es la apropiada.

Soporte de proxy de LWP::UserAgent

"LWP::UserAgent" tiene sus propios métodos de proxy que pueden funcionarle y probablemente sean incompatibles con "Crypt::SSLeay" soporte de proxy. Para usar "LWP::UserAgent" soporte de proxy, pruebe algo como:

my $ua = LWP::UserAgent->new;
$ua->proxy([qw( https http )], "$proxy_ip:$proxy_port");

En el momento de escribir esto, libwww v5.6 parece hacer proxy de peticiones https bien con un servidor Apache mod_proxy . Envía una línea como:

GET https://www.example.com HTTP/1.1

al servidor proxy, que no es la petición "CONNECT" que algunos proxies esperarían, así que esto puede no funcionar con otros servidores proxy que no sean mod_proxy. El método "CONNECT" es usado por el soporte de proxy interno de "Crypt::SSLeay".

Soporte de proxy de Crypt::SSLeay

Para el soporte de proxy nativo de "Crypt::SSLeay" de peticiones https, necesita establecer la variable de entorno "HTTPS_PROXY" a su servidor proxy y puerto, como en:

# proxy support
$ENV{HTTPS_PROXY} = 'http://proxy_hostname_or_ip:port';
$ENV{HTTPS_PROXY} = '127.0.0.1:8080';

El uso de la variable de entorno "HTTPS_PROXY" de esta manera es similar al uso de "LWP::UserAgent-"env_proxy()> , pero llamar a ese método probablemente sobrescribirá o romperá el soporte de "Crypt::SSLeay" , así que no mezcle los dos.

Las credenciales de autenticación básica para el servidor proxy pueden proporcionarse de esta manera:

# proxy_basic_auth
$ENV{HTTPS_PROXY_USERNAME} = 'username';
$ENV{HTTPS_PROXY_PASSWORD} = 'password';

Para un ejemplo de scripting LWP con soporte de proxy nativo de "Crypt::SSLeay" , por favor mire el script eg/lwp-ssl-test en la distribución de "Crypt::SSLeay" .

SOPORTE DE CERTIFICADO DE CLIENTE

Se admiten certificados de cliente. Los archivos de certificado y clave privada codificados en PEM pueden usarse así:

$ENV{HTTPS_CERT_FILE} = 'certs/notacacert.pem';
$ENV{HTTPS_KEY_FILE}  = 'certs/notacakeynopass.pem';

Puede probar sus archivos con el programa eg/net-ssl-test , incluido en la distribución, emitiendo un comando como:

perl eg/net-ssl-test -cert=certs/notacacert.pem \
    -key=certs/notacakeynopass.pem -d GET $HOST_NAME

Además, si le gustaría decirle al cliente dónde está el archivo de la CA, puede establecer estas variables.

$ENV{HTTPS_CA_FILE} = "some_file";
$ENV{HTTPS_CA_DIR}  = "some_dir";

Tenga en cuenta que, si se especifica, $ENV{HTTPS_CA_FILE} debe apuntar al archivo de certificado real. Es decir, $ENV{HTTPS_CA_DIR} es *no* la ruta donde $ENV{HTTPS_CA_FILE}" está ubicado.

Para que los certificados en $ENV{HTTPS_CA_DIR} sean detectados, siga las instrucciones en http://www.openssl.org/docs/ssl/SSL_CTX_load_verify_locations.html

No hay un archivo de certificado CA de muestra en este momento para pruebas, pero puede configurar eg/net-ssl-test para usar su certificado CA con la opción -CAfile.

Creación de un certificado de prueba

Para crear certificados de prueba simples con OpenSSL, puede ejecutar el siguiente comando:

openssl req -config /usr/local/openssl/openssl.cnf \
    -new -days 365 -newkey rsa:1024 -x509 \
    -keyout notacakey.pem -out notacacert.pem

Para eliminar la frase de contraseña del archivo de clave, ejecute:

openssl rsa -in notacakey.pem -out notacakeynopass.pem

Soporte PKCS12

Las directivas para habilitar el uso de certificados PKCS12 son:

$ENV{HTTPS_PKCS12_FILE}     = 'certs/pkcs12.pkcs12';
$ENV{HTTPS_PKCS12_PASSWORD} = 'PKCS12_PASSWORD';

El uso de este tipo de certificado tiene prioridad sobre las configuraciones de certificado anteriores descritas.

Versiones SSL

"Crypt::SSLeay" se esfuerza mucho por conectarse a cualquier servidor web SSL, acomodando servidores que son defectuosos, antiguos o simplemente no cumplen con los estándares. Con este fin, este módulo intentará conexiones SSL en este orden:

SSL v23
debería permitir que los servidores v2 y v3 elijan su mejor tipo
SSL v3
mejor tipo de conexión
SSL v2
tipo de conexión antiguo

Desafortunadamente, algunos servidores parecen no manejar una reconexión a SSL v3 después de un intento fallido de conexión SSL v23, así que puede establecer antes de usar LWP o Net::SSL:

$ENV{HTTPS_VERSION} = 3;

para forzar primero una conexión SSL versión 3. En este momento, solo se intentará una conexión SSL versión 2 después de esto, ya que el orden de intento de conexión no cambia con esta configuración.
