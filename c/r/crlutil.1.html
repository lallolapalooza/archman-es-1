CRLUTIL(1) Herramientas de seguridad NSS CRLUTIL(1)

NOMBRE

crlutil - Listar, generar, modificar o eliminar CRLs dentro del(los) archivo(s) de la base de datos de seguridad NSS y listar, crear, modificar o eliminar entradas de certificados en una CRL particular.

SINOPSIS

crlutil [opciones] [[argumentos]]

ESTADO

Esta documentación aún está en progreso. Por favor, contribuya a la revisión inicial en el bug 836477 de Mozilla NSS[1]

DESCRIPCIÓN

La Herramienta de Gestión de Listas de Revocación de Certificados (CRL), crlutil, es una utilidad de línea de comandos que puede listar, generar, modificar o eliminar CRLs dentro del(los) archivo(s) de la base de datos de seguridad NSS y listar, crear, modificar o eliminar entradas de certificados en una CRL particular.

El proceso de gestión de claves y certificados generalmente comienza creando claves en la base de datos de claves, luego generando y gestionando certificados en la base de datos de certificados (ver la herramienta certutil) y continúa con la expiración o revocación de certificados.

Este documento discute la gestión de listas de revocación de certificados. Para obtener información sobre la gestión de bases de datos de módulos de seguridad, consulte Uso de la Herramienta de Base de Datos de Módulos de Seguridad. Para obtener información sobre la gestión de bases de datos de certificados y claves, consulte Uso de la Herramienta de Base de Datos de Certificados.

Para ejecutar la Herramienta de Gestión de Listas de Revocación de Certificados, escriba el comando

crlutil opción [argumentos]

donde las opciones y argumentos son combinaciones de las opciones y argumentos enumerados en la siguiente sección. Cada comando toma una opción. Cada opción puede tomar cero o más argumentos. Para ver una cadena de uso, ejecute el comando sin opciones, o con la opción -H.

OPCIONES Y ARGUMENTOS

Opciones

Las opciones especifican una acción. Los argumentos de las opciones modifican una acción. Las opciones y argumentos para el comando crlutil se definen de la siguiente manera:

-D

Elimina la Lista de Revocación de Certificados de la base de datos de certificados.

-E

Borra todas las CRLs del tipo especificado de la base de datos de certificados.

-G

Crea una nueva Lista de Revocación de Certificados (CRL).

-I

Importa una CRL a la base de datos de certificados.

-L

Lista las CRLs existentes ubicadas en el archivo de la base de datos de certificados.

-M

Modifica una CRL existente que puede estar en la base de datos de certificados o en un archivo arbitrario. Si está en un archivo, debe estar codificada en formato codificado ASN.1.

-S

Muestra el contenido de un archivo CRL que no está almacenado en la base de datos.

Argumentos

Los argumentos de las opciones modifican una acción.

-a

Utiliza formato ASCII o permite el uso de formato ASCII para entrada y salida. Este formato sigue la RFC #1113.

-B

Omite las comprobaciones de firma de la CA.

-c crl-gen-file

Especifica el archivo de script que se utilizará para controlar la generación/modificación de CRL. Consulte el formato de archivo crl-cript-file a continuación. Si se utilizan las opciones -M|-G y no se especifica -c crl-script-file, crlutil leerá los datos del script desde la entrada estándar.

-d directorio

Especifica el directorio de la base de datos que contiene los archivos de la base de datos de certificados y claves. En Unix, la Herramienta de Base de Datos de Certificados por defecto es $HOME/.netscape (es decir, ~/.netscape). En Windows NT, el valor predeterminado es el directorio actual.

Los archivos de la base de datos NSS deben residir en el mismo directorio.

-f archivo-contraseña

Especifica un archivo que proporcionará automáticamente la contraseña para incluir en un certificado o para acceder a una base de datos de certificados. Este es un archivo de texto plano que contiene una contraseña. Asegúrese de evitar el acceso no autorizado a este archivo.

-i archivo-crl

Especifica el archivo que contiene la CRL a importar o mostrar.

-l nombre-algoritmo

Especifica un algoritmo de firma específico. Lista de algoritmos posibles: MD2 | MD4 | MD5 | SHA1 | SHA256 | SHA384 | SHA512

-n apodo

Especifica el apodo de un certificado o clave para listar, crear, agregar a una base de datos, modificar o validar. Encierre el apodo entre comillas si contiene espacios.

-o archivo-salida

Especifica el nombre del archivo de salida para la nueva CRL. Encierre el nombre del archivo de salida entre comillas si contiene espacios. Si este argumento no se utiliza, el destino de salida por defecto es la salida estándar.

-P prefijo-db

Especifica el prefijo utilizado en los archivos de la base de datos de seguridad NSS (por ejemplo, my_cert8.db y my_key3.db). Esta opción se proporciona como un caso especial. No se recomienda cambiar los nombres de las bases de datos de certificados y claves.

-t tipo-crl

Especifica el tipo de CRL. Los tipos posibles son: 0 - SEC_KRL_TYPE, 1 - SEC_CRL_TYPE. Esta opción está obsoleta.

-u url

Especifica la URL.

-w cadena-pwd

Proporciona la contraseña de la base de datos en la línea de comandos.

-Z algoritmo

Especifica el algoritmo hash a utilizar para firmar la CRL.

SINTAXIS DEL SCRIPT DE GENERACIÓN DE CRL

El archivo de script de generación de CRL tiene la siguiente sintaxis:

* Las líneas con comentarios deben tener # como primer símbolo de la línea.

* Establece los campos de la CRL "esta actualización" o "próxima actualización":

update=AAAA MM DD hh mm ss Z nextupdate=AAAA MM DD hh mm ss Z

El campo "próxima actualización" es opcional. La hora debe estar en formato GeneralizedTime (AAAA MM DD hh mm ss Z). Por ejemplo: 20050204153000Z

* Agrega una extensión a una CRL o a una entrada de certificado de CRL:

addext nombre-extension crítico/no-crítico [arg1[arg2 ...]]

Donde:

nombre-extension: valor de cadena del nombre de extensiones conocidas. crítico/no-crítico: es 1 si la extensión es crítica y 0 en caso contrario. arg1, arg2: parámetros específicos del tipo de extensión.

addext utiliza el rango que se estableció previamente con addcert e instalará una extensión en cada entrada de certificado dentro del rango.

* Agrega una o más entradas de certificado a la CRL:

addcert rango fecha

rango: dos valores enteros separados por un guión: rango de certificados que se agregarán con este comando. Se usa un guión como delimitador. Solo se agregará un certificado si no hay delimitador. fecha: fecha de revocación de un certificado. La fecha debe representarse en formato GeneralizedTime (AAAA MM DD hh mm ss Z).

* Elimina una o más entradas de certificado de la CRL

rmcert rango

Donde:

rango: dos valores enteros separados por un guión: rango de certificados que se agregarán con este comando. Se usa un guión como delimitador. Solo se agregará un certificado si no hay delimitador.

* Cambia el rango de una o más entradas de certificado en la CRL

range nuevo-rango

Donde:

nuevo-rango: dos valores enteros separados por un guión: rango de certificados que se agregarán con este comando. Se usa un guión como delimitador. Solo se agregará un certificado si no hay delimitador.

Extensiones Implementadas

Las extensiones definidas para CRL proporcionan métodos para asociar atributos adicionales con CRLs o sus entradas. Para más información consulte la RFC #3280.

* Agrega la extensión Identificador de Clave de Autoridad:

La extensión Identificador de Clave de Autoridad proporciona un medio para identificar la clave pública correspondiente a la clave privada utilizada para firmar una CRL.

authKeyId crítico [id-clave | dn cert-serial]

Donde:

authKeyIdent: identifica el nombre de una extensión. crítico: valor de 1 o 0. Debe establecerse en 1 si esta extensión es crítica o 0 en caso contrario. id-clave: identificador de clave representado en cadena de octetos. dn:: es el nombre distinguido de la CA. cert-serial: número de serie del certificado de autoridad.

* Agrega la extensión Nombre Alternativo del Emisor:

La extensión nombres alternativos del emisor permite asociar identidades adicionales con el emisor de la CRL. Las opciones definidas incluyen un nombre rfc822 (dirección de correo electrónico), un nombre DNS, una dirección IP y una URI.

issuerAltNames no-crítico lista-nombres

Donde:

subjAltNames: identifica el nombre de la extensión. Debe establecerse en 0 ya que esta es una extensión no crítica. lista-nombres: lista de nombres separados por comas.
