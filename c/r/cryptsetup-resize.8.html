CRYPTSETUP-RESIZE(8) Comandos de mantenimiento CRYPTSETUP-RESIZE(8)

NOMBRE

cryptsetup-resize - redimensionar un mapeo activo

SINOPSIS

cryptsetup resize [<opciones>] <nombre>

DESCRIPCIÓN

Redimensiona un mapeo activo <nombre>.

Si no se especifica --size (en sectores de 512 bytes) o --device-size, el tamaño se calcula a partir del dispositivo subyacente. Para LUKS, es el tamaño del dispositivo subyacente sin el área reservada para la cabecera LUKS (ver el desplazamiento del payload de datos en el comando luksDump). Para un dispositivo crypt plano, se utiliza todo el tamaño del dispositivo.

Tenga en cuenta que esto no cambia la geometría del dispositivo bruto; solo cambia cuántos sectores del dispositivo bruto se representan en el dispositivo mapeado.

Si cryptsetup detectó una clave de volumen para el dispositivo activo cargada en el servicio de keyring del kernel, la acción de redimensionamiento primero intentaría recuperar la clave utilizando un token. Solo si falló, pediría una contraseña para desbloquear una ranura de clave (LUKS) o para derivar nuevamente una clave de volumen (modo plano). El keyring del kernel se utiliza por defecto para dispositivos LUKS2.

<opciones> pueden ser [--size, --device-size, --token-id, --token-only, --token-type, --key-slot, --key-file, --keyfile-size, --keyfile-offset, --timeout, --disable-external-tokens, --disable-locks, --disable-keyring, --volume-key-keyring, --verify-passphrase, --timeout, --external-tokens-path].

OPCIONES

--batch-mode, -q

Suprime todas las preguntas de confirmación. ¡Usar con precaución!

Si la opción --verify-passphrase no se especifica, esta opción también desactiva la verificación de la contraseña.

--debug o --debug-json

Ejecutar en modo de depuración con registros de diagnóstico completos. Las líneas de salida de depuración siempre van precedidas por #.

Si se utiliza --debug-json, se imprimen estructuras de datos JSON adicionales de LUKS2.

--device-size tamaño[unidades]

Establece el nuevo tamaño del dispositivo. Si no se especifica, se utiliza el tamaño real del dispositivo.

Si no se especifica sufijo de unidad, el tamaño está en bytes.

El sufijo de unidad puede ser S para sectores de 512 bytes, K/M/G/T (o KiB, MiB, GiB, TiB) para unidades con base 1024 o KB/MB/GB/TB para base 1000 (escala SI).

--disable-external-tokens

Desactiva la carga de plugins para tokens externos de LUKS2.

--disable-keyring

No cargar la clave de volumen en el keyring del kernel; almacenarla directamente en el destino dm-crypt. Esta opción solo es compatible con el tipo LUKS2.

--disable-locks

Desactiva la protección de bloqueo para metadatos en disco. Esta opción solo es válida para LUKS2 y se ignora para otros formatos.

ADVERTENCIA: No utilice esta opción a menos que ejecute cryptsetup en un entorno restringido donde el bloqueo sea imposible de realizar (donde el directorio /run no se pueda utilizar).

--external-tokens-path <ruta absoluta>

Anula la ruta del directorio del sistema donde cryptsetup busca manejadores de tokens externos (o plugins de tokens). Debe ser una ruta absoluta (que comience con el carácter '/').

--header <dispositivo o archivo que almacena la cabecera LUKS>

Utiliza un dispositivo o archivo de metadatos separado (detached) donde se almacena la cabecera LUKS. Esta opción permite almacenar el cifrado y la cabecera LUKS en dispositivos diferentes.

Para comandos que modifican la cabecera LUKS (por ejemplo, luksAddKey), especifique directamente el dispositivo o archivo con la cabecera LUKS como el dispositivo LUKS.

--help, -?

Muestra el texto de ayuda y los parámetros por defecto.

--key-description texto

Establece la descripción de la clave en el keyring que se utilizará para la recuperación de la contraseña.

--key-file, -d archivo

Lee la contraseña desde el archivo.

Si el nombre dado es "-", entonces la contraseña se leerá desde stdin. En este caso, la lectura no se detendrá en los caracteres de nueva línea.

Consulte la sección NOTAS SOBRE EL PROCESAMIENTO DE CONTRASEÑAS en cryptsetup(8) para más información.

--keyfile-offset valor

Omite valor bytes al principio del archivo de clave.

--keyfile-size, -l valor

Lee un máximo de valor bytes del archivo de clave. El valor por defecto es leer el archivo completo hasta el máximo compilado que se puede consultar con --help. Proporcionar más datos de los que permite el máximo compilado aborta la operación.

Esta opción es útil para cortar saltos de línea finales, por ejemplo. Si también se proporciona --keyfile-offset, el conteo de tamaño comienza después del desplazamiento.

--key-slot, -S <0-N>

Para operaciones LUKS que añaden material de clave, esta opción permite especificar qué ranura de clave se selecciona para la nueva clave.

El número máximo de ranuras de clave depende de la versión de LUKS. LUKS1 puede tener hasta 8 ranuras de clave. LUKS2 puede tener hasta 32 ranuras de clave basándose en el tamaño del área de ranura de clave y el tamaño de la clave, pero un ID de ranura de clave válido siempre puede estar entre 0 y 31 para LUKS2.

--size, -b <número de sectores de 512 bytes>

Establece el tamaño del dispositivo en sectores de 512 bytes.

--timeout, -t segundos

El número de segundos a esperar antes de un tiempo de espera en la entrada de contraseña a través de terminal. Es relevante cada vez que se solicita una contraseña. No tiene efecto si se usa junto con --key-file.

Esta opción es útil cuando el sistema no debe detenerse si el usuario no introduce una contraseña, por ejemplo, durante el arranque. El valor por defecto es 0 segundos, lo que significa esperar indefinidamente.

--token-id

Especifica qué token usar y permite que la solicitud de PIN del token tenga prioridad sobre la solicitud interactiva de contraseña de la ranura de clave. Si se omite, se comprobarán todos los tokens disponibles (no protegidos por PIN) antes de continuar con la solicitud de contraseña.

--token-only

No continuar con la acción si el desbloqueo de la ranura de clave basado en token falló. Sin esta opción, la acción solicita una contraseña para continuar.

Permite que los tokens LUKS2 protegidos por PIN tengan prioridad sobre la solicitud interactiva de contraseña de la ranura de clave.

--token-type tipo

Restringe los tokens elegibles para la operación a un tipo de token específico. Principalmente útil cuando no se especifica --token-id.

Permite que los tokens de tipo LUKS2 protegidos por PIN tengan prioridad sobre la solicitud interactiva de contraseña de la ranura de clave.

--usage

Muestra ayuda sobre opciones cortas.

--verify-passphrase, -y

Al solicitar interactivamente una contraseña, la solicita dos veces y se queja si ambas entradas no coinciden. Ignorado en la entrada desde archivo o stdin.

--version, -V

Muestra la versión del programa.

--volume-key-keyring <descripción de clave>

Utiliza una clave de volumen almacenada en un keyring. Esto permite abrir dispositivos de tipo luks y plain sin proporcionar una contraseña.

Para LUKS, la clave y el tipo asociado deben ser legibles desde el espacio de usuario para que el resumen de la clave de volumen pueda ser verificado antes de la activación. Para dispositivos en proceso de re-cifrado, la opción puede usarse dos veces para especificar ambas claves de volumen, la antigua y la nueva.

Para el tipo PLAIN, el usuario debe asegurarse de que la clave en el keyring no ha cambiado desde la activación. De lo contrario, la recarga de la clave puede causar corrupción de datos después de un cambio de clave inesperado.

La <descripción de clave> utiliza la sintaxis compatible con keyctl. Puede ser un ID de clave numérico o un nombre de cadena en el formato %<tipo de clave>:<nombre de clave>. Consulte también la sección IDENTIFICADORES DE CLAVE de keyctl(1). Cuando no se especifica el prefijo %<tipo de clave>:, asumimos que el tipo de clave es user (tipo por defecto).
