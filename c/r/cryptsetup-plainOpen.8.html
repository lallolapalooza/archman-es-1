SINOPSI

S

cryptsetup open --type <device_type> [<options>] <device> <name>

DESCRIPCIÓ

N

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

El tipo de dispositivo puede ser plain, luks (predeterminado), luks1, luks2, loopaes o tcrypt

.

Por compatibilidad con versiones anteriores, existen alias del comando

open:

create (orden de argumentos <name> <device>): open --type plain
plainOpen: open --type plain
luksOpen: open --type luks
loopaesOpen: open --type loopaes
tcryptOpen: open --type tcrypt
bitlkOpen: open --type

bitlk

<options> son específicas del tipo y se describen a continuación para cada tipo de dispositivo. Para create, el orden de las opciones <name> y <device> está invertido por razones históricas; todos los demás alias usan el orden estándar <device> <name>

.

PLAI

N

open --type plain <device> <name> --cipher <spec> --key-size <bits> --hash <alg>
plainOpen <device> <name> (sintaxis antigua)
create <name> <device> (sintaxis

OBSOLETA)

Abre (crea un mapeo con) <name> respaldado por el dispositivo <device>

.

Debes especificar siempre las opciones --cipher, --key-size y (si no se usa un archivo de clave o un llavero) también --hash para evitar incompatibilidades, ya que los valores predeterminados pueden diferir en versiones antiguas de

cryptsetup.

El formato plain también permite obtener una clave de volumen de un llavero del kernel especificado por --volume-key-keyring. La clave en el llavero del kernel debe configurarse antes de emitir los comandos de cryptsetup, ya que cryptsetup no sube ninguna clave al llavero en modo plain. Para comandos posteriores (como resize), el usuario debe asegurarse de que la clave en el llavero no cambie. De lo contrario, recargar la clave puede causar corrupción de datos después de un cambio inesperado de

clave.

<options> pueden ser [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring]

.

EJEMPLOS

:

Para mapear el dispositivo cifrado /dev/sda10 al dispositivo descifrado /dev/mapper/e1, puedes

usar:

cryptsetup open --type plain --cipher aes-cbc-essiv:sha256 --key-size 256 --hash sha256 /dev/sda10

e1

El dispositivo descifrado puede usarse entonces como un dispositivo de bloques normal para montar un sistema de

archivos.

Para mapear un dispositivo con una clave de volumen en el llavero de claves preconfigurado de confianza o cifrado, debes especificar el llavero con la clave y eliminar la especificación de hash, por ejemplo, para usar %trusted:m

ykey:

cryptsetup open --type plain /dev/sda10 e1 --volume-key-keyring=%trusted:mykey --cipher aes-xts-plain64 --key-size

256

Ten en cuenta que el tamaño de la

clave debe coincidir con la clave
preconfigurada en el llavero.

LUK

S

open <device> <name>
open --type <luks1|luks2> <device> <name> (solicitud explícita de versión)

Abre el dispositivo LUKS <device> y configura un mapeo <name> después de verificar con éxito la frase de paso

proporcionada.

Primero, se busca la frase de paso en los tokens LUKS2 no protegidos por PIN. Si no existe un token de este tipo (o falla al desbloquear el slot de clave) y la frase de paso no se proporciona mediante --key-file, el comando solicita la frase de paso de forma

interactiva.

Si existe un token LUKS2 válido pero requiere un PIN para desbloquear el slot de clave asignado, no se usa a menos que se agregue una de las siguientes opciones: --token-only, --token-type donde type coincida con el token protegido por PIN deseado, o --token-id con id coincidiendo con el token protegido por

PIN.

<options> pueden ser [--key-file, --keyfile-offset, --keyfile-size, --readonly, --test-passphrase, --allow-discards, --header, --key-slot, --volume-key-file, --token-id, --token-only, --token-type, --disable-external-token

eout, --verify-passphrase, --persistent, --volume-key-keyring, --link-vk-to-keyring, --external-tokens-path].
