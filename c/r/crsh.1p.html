NOMBRE

crsh - Herramienta de administración de clúster

VERSIÓN

Esta documentación es para la versión: 4.16

SINOPSIS

crsh [-a '<comando>'] [-K <segundos>] [-q] [-c '<nombre_archivo>'] [-x <cols>] [-C '<nombre_archivo>'] [--debug [[...] || <ENTERO>]] [-d] [-e '<[usuario@]<host>[:puerto]>'] [--fillscreen] [-f '<fuente>'] [-h] [-L '[etiqueta]'] [-H] [-o '<CADENA>'] [-p <puerto>] [-Q] [-y <filas>] [-s] [-r '<nombre_archivo>'] [-t '<CADENA>'] [-g] [-T '<título>'] [-u] [-?] [-A] [-l '<nombre_usuario>'] [-v]

DESCRIPCIÓN

El comando abre una consola de administración y un xterm a todos los hosts especificados. Cualquier texto escrito en la consola de administración se replica en todas las ventanas. Todas las ventanas también pueden ser escritas directamente.

Esta herramienta está destinada (pero no limitada) a la administración de clústeres donde la misma configuración o comandos deben ejecutarse en cada nodo dentro del clúster. Realizar estos comandos simultáneamente a través de esta herramienta asegura que todos los nodos se mantengan sincronizados.

Las conexiones se abren utilizando rsh, que debe estar correctamente instalado y configurado.

Se debe tener especial cuidado al editar archivos, ya que las líneas no necesariamente estarán en el mismo orden; asumir que la línea 5 es la misma en todos los servidores y modificarla es peligroso. Es mejor buscar la línea específica a modificar y verificar que todas las terminales sean las esperadas antes de confirmar los cambios.

Notas Adicionales

Por favor, consulte también "BUGS CONOCIDOS".

  • La línea punteada en cualquier submenú es una "desprendible", es decir, haz clic en ella y el submenú se convertirá en su propia ventana.
  • Desmarcar un nombre de host en el submenú Hosts desconectará el host de la ventana de control del clúster, por lo que cualquier texto escrito en la consola no se enviará a ese host. Volver a seleccionarlo lo conectará de nuevo.
  • Si las barras de menú de su gestor de ventanas están oscurecidas por ventanas de terminal, consulte las opciones "screen_reserve_XXXXX" en el archivo $HOME/.clusterssh/config (ver "ARCHIVOS").
  • Si las terminales se superponen demasiado, consulte las opciones "terminal_reserve_XXXXX" en el archivo $HOME/.clusterssh/config (ver "ARCHIVOS").
  • Al usar ClusterSSH en un gran número de sistemas para conectarse a un único sistema utilizando una utilidad SSH (por ejemplo, emite un comando para copiar un archivo usando scp desde las computadoras remotas a un único host) y cuando estas conexiones requieren autenticación (es decir, autenticará con una contraseña), el demonio sshd en esa ubicación puede rechazar conexiones después de que se supere el límite "MaxStartups" en sshd_config. (Si este valor no está establecido, por defecto es 10). Este es un comportamiento esperado; sshd usa este mecanismo para prevenir ataques de DoS de fuentes no autenticadas. Por favor, ajuste sshd_config y recargue el demonio SSH, o considere usar el mecanismo ~/.ssh/authorized_keys para la autenticación si encuentra este problema.
  • Si las ventanas del cliente no se abren, intente ejecutar:

    "crsh -e {nombre de host único}"

    Esto probará los mecanismos utilizados para abrir ventanas a los hosts. Esto podría deberse a la opción de terminal "-xrm" que habilita "AllowSendEvents" (algunas terminales no requieren esta opción, otras terminales tienen un método diferente para habilitarla - consulte la documentación de su terminal) o a la configuración de "rsh".

OPCIONES

Algunas de estas opciones también pueden definirse dentro del archivo de configuración. Las opciones por defecto se muestran según corresponda.

--action '<comando>', -a '<comando>'
Ejecuta el comando en cada sesión, por ejemplo, "-a 'vi /etc/hosts'" para entrar directamente en una sesión de vi.
--autoclose <segundos>, -K <segundos>
Número de segundos a esperar antes de cerrar las ventanas de terminal finalizadas.
--autoquit, -q
Activa/desactiva la salida automática después de que la última ventana del cliente se haya cerrado (anulando el archivo de configuración).
--cluster-file '<nombre_archivo>', -c '<nombre_archivo>'
Usa el archivo proporcionado como archivo de clúster adicional (ver también "ARCHIVOS").
--cols <cols>, -x <cols>

--config-file '<nombre_archivo>', -C '<nombre_archivo>'
Usa el archivo proporcionado como archivo de configuración adicional (ver también "ARCHIVOS").
--debug [[...] || <ENTERO>]
Habilita la depuración. Se puede proporcionar un nivel o repetir la opción varias veces. El nivel máximo es 9.
--dump-config, -d
Volca la configuración actual en el mismo formato utilizado por el archivo $HOME/.clusterssh/config.
--evaluate '<[usuario@]<host>[:puerto]>', -e '<[usuario@]<host>[:puerto]>'
Muestra y evalúa los argumentos de terminal y conexión para mostrar cualquier error potencial. Se requiere el <nombre_host> para ayudar a la evaluación.
--fillscreen
Redimensiona las ventanas de terminal para llenar toda la pantalla disponible
--font '<fuente>', -f '<fuente>'
Especifica la fuente a usar en las ventanas de terminal. Usa la notación estándar de fuentes X como "5x8".
--help, -h
Muestra texto de ayuda básico y sale
--list '[etiqueta]', -L '[etiqueta]'
Lista las etiquetas de clúster disponibles. La etiqueta es opcional. Si se proporciona una etiqueta, se listan los hosts para esa etiqueta. NOTA: el formato de la salida cambia al usar la opción "--quiet" o "-Q".
--man, -H
Muestra el texto de ayuda completo (la página del manual) y sale
--options '<CADENA>', -o '<CADENA>'
Especifica los argumentos que se pasarán a ssh al establecer la conexión. NOTA: las opciones para ssh normalmente deberían incluirse en el archivo de configuración de ssh; ver "ssh_config" y $HOME/.ssh/config para más detalles.

Por defecto: -x -o ConnectTimeout=10

--port <puerto>, -p <puerto>
Especifica un puerto alternativo para las conexiones.
--quiet, -Q
No emite texto adicional al usar algunas opciones
--rows <filas>, -y <filas>
Número de filas
--show-history, -s
Muestra el historial dentro de la ventana de la consola.
--tag-file '<nombre_archivo>', -r '<nombre_archivo>'
Usa el archivo proporcionado como archivo de etiquetas adicional (ver también "ARCHIVOS")
--term-args '<CADENA>', -t '<CADENA>'
Especifica los argumentos que se pasarán a las terminales que se estén utilizando.
