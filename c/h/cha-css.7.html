CSS en Chawan

Este documento describe las características CSS soportadas por Chawan, así como sus extensiones propietarias y desviaciones de los estándares.

Si descubre una desviación que no está cubierta por este documento, por favor abra un ticket en https://todo.sr.ht/~bptato/chawan.

Propiedades estándar

Una lista de propiedades estándar soportadas, con notas sobre valores no implementados:

  • background-color (ver color)
  • background-image (solo muestra marcadores de posición)
  • border-collapse
  • border-*-style, border-*-color, border-*-width (pero ver borders)
  • border-spacing
  • bottom
  • box-sizing
  • caption-side
  • clear
  • color (valores hexadecimales y funciones rgb, rgba, hsl, hsla)
  • content (cadena, (no-)open/close-quote, counter())
  • counter-increment
  • counter-reset
  • counter-set
  • display (block, inline-block, list-item, table, table-*, flex, inline-flex, flow-root)
  • flex-basis (pero content no soportado)
  • flex-direction
  • flex-grow
  • flex-shrink
  • flex-wrap
  • float
  • font-size (ignorado; solo para compatibilidad con JS)
  • font-style (oblique interpretado como italic)
  • font-weight (propiedades numéricas > 500 interpretadas como bold, otras como regular)
  • height
  • left
  • list-style-position
  • list-style-type (pero sin estilos de lista personalizados)
  • margin-bottom
  • margin-left
  • margin-right
  • margin-top
  • max-height
  • max-width
  • min-height
  • min-width
  • opacity (poco elegante; solo funciona con opacity: 0)
  • overflow-x (ver más abajo sobre barras de desplazamiento)
  • overflow-y (ver más abajo sobre barras de desplazamiento)
  • padding-bottom
  • padding-left
  • padding-right
  • padding-top
  • position (ver más abajo para sticky y fixed)
  • quotes
  • right
  • text-align
  • text-decoration (none, underline, overline, line-through)
  • text-transform
  • top
  • vertical-align
  • visibility
  • white-space
  • width
  • word-break
  • z-index

Shorthands:

  • all
  • margin
  • padding
  • border, border-style, border-color, border-width (pero ver borders)
  • background (solo color y url; otros componentes se omiten)
  • list-style (list-style-image se omite)
  • flex
  • flex-flow
  • overflow

Las variables (la función var() ) están completamente soportadas.

Los valores de tipos <length> o <color> soportan completamente expresiones calc() .

Selectores

Se soportan todos los tipos de selectores de CSS 2.1, excepto los espacios de nombres.

Se soportan las siguientes pseudo-clases estándar: :first-child, :last-child, :only-child, :hover, :root, :nth-child(), :nth-last-child(), :checked, :focus, :is(), :not(), :where(), :lang(), :link, :target, :disabled.

:visited se analiza, pero por ahora no se hace coincidir.

:defined, :hosty :host() se hacen coincidir para compatibilidad; sin embargo, los elementos personalizados y el shadow DOM aún no están soportados.

Los pseudo-elementos estándar ::before, ::aftery ::marker están soportados. ::backdrop se analiza para compatibilidad, pero aún no está soportado.

Reglas @

Se soportan las siguientes reglas que comienzan con el signo @ .

@media

Las características de medios grid, hover, prefers-color-scheme, scripting, widthy height están completamente soportadas.

Las características color, color-indexy monochrome están soportadas, pero solo consideran el número de colores de texto soportados (que puede diferir del número de colores en imágenes Sixel/Kitty).

@import

Se soporta la importación a capas.

@import combinado con consultas de medios aún no está soportado.

@layer

@layer está completamente soportado. (Creo.)

Extensiones propietarias

  • text-align acepta los valores -cha-center, -cha-lefty -cha-right para soportar los elementos HTML <center>, <div align=left> y <div align=right> . (Análogo a -moz-center etc.)
  • Las propiedades con un valor <color> aceptan la función -cha-ansi(), que mapea a colores específicos del terminal ("ANSI"). La función toma uno de los siguientes:
  • Un entero de 8 bits, que indica un valor de color establecido por la función de color indexado de XTerm.
  • Una de las cadenas "black", "red", "green", "yellow", "blue", "magenta", "cyan", "white" para un color ANSI, posiblemente prefijada por la cadena "bright-" para indicar un valor de 16 colores de aixterm.
  • text-decoration acepta la palabra clave -cha-reverse, que establece el parámetro de vídeo invertido en el texto. (Esto es utilizado por la hoja de estilo del UA para resaltar texto en etiquetas <code> .)
  • text-transform acepta la palabra clave -cha-half-width, que tiene el efecto opuesto a full-width.

Esto se puede usar en hojas de estilo de usuario para comprimir texto ruby que distraiga: rt{text-transform: -cha-half-width}. Los caracteres sin contrapartes de ancho medio se dejan intactos, excepto que el hiragana se trata como katakana.

  • Las propiedades -cha-colspan y -cha-rowspan tienen el mismo efecto que los atributos colspan y rowspan en las tablas.
  • Las pseudo-clases :-cha-first-node y :-cha-last-node se aplican a elementos que no tienen nodo hermano anterior/subsiguiente que sea un nodo de elemento o un nodo de texto con contenido que no sea solo espacios en blanco. (Modeladas después de :-moz-first-node y :-moz-last-node.)
  • Si buffer.mark-links está establecido, el pseudo-elemento ::-cha-link-marker se generará en todos los elementos de ancla.
  • En el modo de pistas (por defecto, la tecla f ) los marcadores se implementan generando ::-cha-link-hint en todos los elementos aplicables. Así que puedes cambiar el fondo del marcador en tu user-style cha-css(7) — Chawan Manual

    CSS in Chawan

    7

    A number of CSS properties and media features are supported, usually with modifications to better fit the display model inherent to projecting the web to a cell-based screen.

    Custom properties

    Custom properties are supported, and can be used for themeing the user agent style sheet. For example, you can add

    ::-cha-link-hint { background: gainsboro }

    to your user-style to set the background of link hints to gainsboro. Note that these properties are prefixed with -cha-, and are only available as custom properties.

    Media features

    •
    The -cha-content-type media feature can be used to filter documents for their content type. For example, you can add
    @media (-cha-content-type: "text/markdown") { body { width: 80ch } }

    to your user-style to set the body width of all markdown documents to 80 characters. (The string is matched case-insensitively.)

    Rendering quirks

    These are willful violations of the standard, usually made to better fit the display model inherent to projecting the web to a cell-based screen.

    User agent style sheet

    The user agent style sheet is a combination of the styles suggested by the HTML standard and a CSS port of w3m’s rendering. In general, faithfulness to w3m is preferred over the standard’s suggestions, unless w3m’s rendering breaks on existing websites.

    Link colors differ depending on the terminal’s color scheme.

    Sizing and positioning

    Layout is performed on a finite canvas of coordinates represented by a 32-bit fixed-point number with 6 bits of precision. After layout, these positions are divided by the cell width and/or height, with the fractional part truncated. (This is subject to change.)

    In case of Kitty images, the fractional part is preserved, and is used as an in-cell offset.

    The lengths 1em and 1ch compute to the cell height and cell width respectively.

    In outer inline boxes (inline-block, inline-flex) and list-item boxes, margins and padding that are smaller than one cell (on the respective axis) are ignored. This does not apply to blockified inline boxes.

    When calculating clip boxes (overflow: hidden or clip), the clip box’s offset is floored, and its size is ceiled to the nearest cell’s boundaries. This means that “width: 1px; overflow: hidden” will still display the first character of a text box.

    Scroll bars

    Chawan does not have scroll bars, as they would complicate on-page navigation and would not work in dump mode. Instead, the “overflow-x/y” properties are handled as follows.

    1.
    If overflow is auto or scroll, and the intrinsic minimum size of the box is greater than its specified size, then the former overrides the latter.
    2.
    Content that spills out of a scroll container on the X axis is displayed, while content that spills out of a scroll container on the Y axis is clipped.

    position: fixed, position: sticky

    To keep the document model static, these do not change their position based on the viewport’s scroll status. Instead:

    • position: sticky is treated as position: static, except it also behaves as an absolute position container.
    • position: fixed is placed at the bottom of the document.

    Right now, position: fixed is always positioned at the bottom of the root element’s margin box. This breaks on pages that overflow it (e.g. by setting height: 100% on the root element), so it will be moved to the bottom of its overflow box in the future.

    Color correction

    Some authors only specify one of the foreground or the background color, assuming a black-on-white canvas. The display.minimum-contrast option adjusts the foreground color so that text remains readable even if the terminal background does not match this expectation. (The exact algorithm is unspecified and subject to change.)

    To avoid breaking spoiler mechanisms that rely on “black on black” text, color correction is not invoked on cells that have an RGB color (typically specified by the author.)

    Borders

    CSS borders are difficult to accurately display on a cell-based display. So while the functionality exists, it has some limitations:

    • On tables, borders are always collapsed, even when border-collapse is set to separate.
    • With border-collapse: separate, the spacing between cells is the largest of border-spacing times two and the cell width.
    • border-*-width is interpreted as a binary value: a width of 0 results in no border, while any other width results in a border of a single type. If the width is smaller than one cell (in the respective direction), the rest is subtracted from the margin (if there is any margin).
    • box-sizing: border-box actually sets the padding box size, so that borders rounded up to the cell size do not accidentally take all space from the actual content. (That in turn would cause problems if a child box set overflow: hidden, etc.)
