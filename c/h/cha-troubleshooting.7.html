Solución de problemas Chawan

Este documento enumera los problemas comunes que puedes encontrar al usar Chawan.

Si encuentras un problema no descrito en este documento, por favor abre un ticket en https://todo.sr.ht/~bptato/chawan.

¿No compila?

Por favor, abre un ticket. No olvides incluir el error de compilación y tu sistema operativo (y su versión).

¿Se cierra inesperadamente?

Por favor, abre un ticket que describa cómo reproducir el cierre inesperado. No olvides incluir el mensaje de error que ves después de que tu buffer desaparece.

Si no ves un mensaje de error, intenta: cha example.org -o start.console-buffer=false 2>err.log. Luego, revisa el contenido de err.log después del cierre inesperado.

Si *aún* no ves un mensaje de error, no hay problema, solo informa que no pudiste obtener un mensaje de error.

¿No puedo seleccionar/copiar texto con el ratón?

Haz clic derecho -> seleccionar texto, luego clic derecho -> copiar selección. (También puedes hacer doble clic y arrastrar el ratón hacia la izquierda/derecha para seleccionar.)

Si Chawan se queja de xsel, instálalo o edita external.copy-cmd y external.paste-cmd a tu gusto.

También puedes deshabilitar temporalmente el seguimiento del ratón manteniendo presionada la tecla Shift, o permanentemente configurando en config.toml:

[input]
use-mouse = false

¿Me prometieron imágenes pero no veo nada?

La razón más común es que no agregaste lo siguiente a config.toml:

[buffer]
images = true

La segunda razón más común es que tu terminal no soporta ni Sixel ni imágenes de Kitty.

Otras razones se enumeran en cha-image(7)

¿Por qué tengo colores extraños/incorrectos/feos?

Por defecto, las capacidades de visualización de Chawan se limitan a lo que informa tu terminal. En particular:

  • Si la variable de entorno $COLORTERM no está establecida, puede recurrir a colores de 8 bits o ANSI. Asegúrate de exportarla como COLORTERM=truecolor.
  • Si no responde a la consulta del color de fondo, entonces la corrección del contraste de color de Chawan probablemente funcionará mal. Puedes corregir esto usando las opciones display.default-background-color y display.default-foreground-color.

Ver Display en cha-config(5) para más detalles.

Configuré mi $PAGER a cha y ahora las páginas man son ilegibles.

La mayoría de las implementaciones de man imprimen páginas de manual formateadas por defecto, las cuales Chawan *puede* parsear si se pasan a través de la entrada estándar.

Desafortunadamente, mandoc nos pasa el documento formateado como un *archivo*, lo cual Chawan interpreta razonablemente como texto plano sin formato.

En este punto, tienes dos opciones:

  • export PAGER='cha -T text/x-ansi' y verás que man funciona inesperadamente como se esperaba.
  • alias man=mancha y verás que man funciona inesperadamente mejor de lo esperado.

Idealmente, deberías hacer ambas cosas, para lidiar con casos como git help que llama directamente a man.

Todavía queda un problema con esta solución: algunos programas intentarán llamar a $PAGER sin expansión de shell, rompiendo el truco de -T text/x-ansi. Para solucionar esto, coloca un script en algún lugar de tu PATH:

#!/bin/sh
exec cha -T text/x-ansi "$@"

y export PAGER=pcha (o como sea que hayas llamado al script).

¿Cómo veo archivos de texto con ajuste de línea?

Por defecto, los archivos de texto no se ajustan automáticamente, por lo que ver archivos de texto plano que no fueron correctamente ajustados por los autores es algo molesto.

Una solución es añadir esto a la sección [page] de tu configuración:

' f' = "pager.externFilterSource('fmt')"

y luego presiona <espacio> f para ver una versión con ajuste de línea del archivo de texto actual. (Esto asume que tu sistema tiene un programa fmt - si no, fold -s puede ser una alternativa.)

Para ajustar automáticamente siempre, puedes añadir esto a tu estilo de usuario:

plaintext { white-space: pre-wrap }

Para hacer lo mismo para texto HTML y ANSI, usa plaintext, pre.

¿Por qué $WEBSITE se ve horrible?

Normalmente, esto se debe a que utiliza algunas características CSS que aún no están implementadas en Chawan. El infractor más común es grid.

Hay tres formas de lidiar con esto:

1.
Si el contenido del sitio web es mayormente texto, instala rdrview. Luego, enlaza el siguiente comando a una tecla de tu elección en la configuración (por ejemplo, <espacio> r):

' r' = "pager.externFilterSource('rdrview -Hu \"$CHA_URL\"')"

Esto no soluciona el problema central, pero de todos modos mejorará significativamente tu experiencia de lectura.

2.
Quejate aquí, y espera hasta que el problema desaparezca. Ayuda si puedes reducir el problema a un ejemplo mínimo reproducible (idealmente un fragmento HTML pequeño).
3.
Escribe un parche para solucionar el problema y envíalo aquí.

¡Las características interactivas de $WEBSITE no funcionan!

Algunas posibles soluciones:

  • Iniciar sesión en sitios web requiere cookies. Algunos sitios web también requieren compartir cookies entre dominios. Por razones de seguridad, Chawan no permite nada de esto por defecto, por lo que tendrás que jugar con la configuración del sitio para solucionarlo. Ver para más detalles.
  • Establece el valor de siteconf referer-from a verdadero; esto hará que Chawan envíe una cabecera Referer al navegar a otras URL desde la URL objetivo.
  • Habilita JavaScript. Si algo se rompió, escribe M-c M-c para verificar la consola del navegador, luego sigue el paso 3. de la respuesta anterior.

¡Las áreas de texto descartan mis ediciones cuando escribo C-c en mi editor!

Esto es un error en tu shell: https://people.freebsd.org/~cracauer/homepage-mirror/sigint.html

Wh

en Chawan ejecuta un editor de texto externo, simplemente pasa el $EDITOR comando a la shell, y luego examina su wait estado para determinar si tu editor terminó correctamente. Esto funciona si el editor nunca recibe una señal, o si tu shell implementa WCE.

Sin embargo, si el editor (por ejemplo, nvi) captura SIGINT en C-c, y la shell informa que el programa fue terminado por una señal (WUE), entonces Chawan descartará tus cambios (ya que cree que el programa se ha bloqueado).

La solución más fácil es eliminar la shell de la ecuación usando exec:

[external]
editor = 'exec vi +%d'

Cuando abro Chawan desde aerc, ¡imprime basura en el campo de búsqueda!

Esto debería estar corregido en la última versión de aerc. Por favor, actualiza aerc.

mancha no funciona en NixOS?

NixOS incluye un parche defectuoso en el paquete que hace que mancha no encuentre páginas de manual en algunas configuraciones. Sospecho que es completamente innecesario, así que si esto te molesta, envía un PR a NixOS para eliminar el parche.
