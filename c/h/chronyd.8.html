DESCRIPCIÓ

N

chronyd es un demonio para la sincronización del reloj del sistema. Puede sincronizar el reloj con servidores NTP, relojes de referencia (por ejemplo, un receptor GPS) y entrada manual usando un reloj de pulsera y el teclado a través de chronyc. También puede funcionar como servidor y par NTPv4 (RFC 5905) para proporcionar un servicio de tiempo a otros ordenadores de la

red.

Si no se especifican directivas de configuración en la línea de comandos, chronyd las leerá de un archivo de configuración. La ubicación predeterminada compilada en el archivo es /etc/chrony

.conf.

Los mensajes informativos, la

s advertencias y los erro
res se registrarán en syslog.

OPCIONE

S

-

4
Con esta opción, los nombres de host se resolverán solo a direcciones IPv4 y solo se crearán sockets
IPv4.

-

6
Con esta opción, los nombres de host se resolverán solo a direcciones IPv6 y solo se crearán sockets
IPv6.

-f archiv

o
Esta opción se puede usar para especificar una ubicación alternativa para el archivo de configuración. El valor predeterminado compilado es /etc/chrony
.conf.

-

n
Cuando se ejecuta en este modo, el programa no se separará de la
terminal.

-

d
Cuando se ejecuta en este modo, el programa no se separará de la terminal, y todos los mensajes se escribirán en la terminal en lugar de en syslog. Si chronyd se compiló con soporte de depuración habilitado, esta opción se puede usar dos veces para habilitar los mensajes de
depuración.

-l archiv

o
Esta opción habilita la escritura de mensajes de registro en un archivo en lugar de en syslog o la
terminal.

-L nive

l
Esta opción especifica el nivel mínimo de gravedad de los mensajes que se escribirán en el archivo de registro, syslog o la terminal. Se pueden especificar los siguientes niveles: -1 (depuración, si se compiló con soporte de depuración habilitado), 0 (informativo), 1 (advertencia), 2 (error no fatal) y 3 (error fatal). El valor predeterminado es
0.

-

p
Cuando se ejecuta en este modo, chronyd imprimirá la configuración y saldrá. No se separará de la terminal. Esta opción se puede usar para verificar la sintaxis de la configuración y obtener la configuración completa, incluso si está dividida en varios archivos y leída por la include o la directiva co
nfdir.

-

q
Cuando se ejecuta en este modo, chronyd establecerá el reloj del sistema una vez y saldrá. No se separará de la
terminal.

-

Q
Esta opción es similar a la opción -q, excepto que solo imprime el desfase sin realizar ninguna corrección del reloj y deshabilita los puertos del servidor para permitir que chronyd se inicie sin privilegios de root, asumiendo que la configuración no tiene ninguna directiva que los requiera (por ejemplo, refclock, hwtimestamp, rtcfile, etc)
.

-

r
Esta opción intentará recargar y luego eliminar los archivos que contienen historiales de muestras para cada uno de los servidores y relojes de referencia que se están usando. Se espera que los archivos estén en el directorio especificado por la directiva dumpdir en el archivo de configuración. Esta opción es útil si desea detener y reiniciar chronyd brevemente por cualquier motivo, por ejemplo, para instalar una nueva versión. Sin embargo, solo debe usarse en sistemas donde el kernel puede mantener la compensación del reloj mientras no está bajo el control de chronyd (es decir, Linux, FreeBSD, NetBSD, illumos y macOS 10.13 o posterior)
.

-

R
Cuando se usa esta opción, la directiva initstepslew y la directiva makestep usada con un límite positivo serán ignoradas. Esta opción es útil al reiniciar chronyd y se puede usar en combinación con la opción
-r.

-

s
Esta opción establecerá el reloj del sistema a partir del reloj de tiempo real (RTC) del ordenador o a la última hora de modificación del archivo especificado por la directiva driftfile. Los relojes de tiempo real solo son compatibles en Linux.

Si se usa en combinación con la opción -r, chronyd intentará preservar las muestras antiguas después de establecer el reloj del sistema a partir del RTC. Esto se puede usar para permitir que chronyd realice un promedio a largo plazo de la tasa de ganancia o pérdida a través de los reinicios del sistema, y es útil para sistemas con acceso intermitente a la red que se apagan cuando no están en uso. Para que esto funcione bien, depende de que chronyd haya podido determinar estadísticas precisas para la diferencia entre el RTC y el reloj del sistema la última vez que el ordenador estuvo

encendido.

Si la última hora de modificación del archivo de deriva es posterior tanto a la hora actual como a la hora del RTC, la hora del sistema se establecerá en ella para restaurar la hora cuando chronyd se detuvo anteriormente. Esto es útil en ordenadores que

no tienen RTC o el RTC está roto
(por ejemplo, no tiene batería).

-t tiempo de

espera
Esta opción establece un tiempo de espera (en segundos) después del cual chronyd saldrá. Si el reloj no está sincronizado, saldrá con un estado distinto de cero. Esto es útil con la opción -q o la opción -Q para acortar el tiempo máximo de espera de mediciones, o con la opción -r para limitar el tiempo en que chronyd está en ejecución, pero aún permitirle ajustar la frecuencia del reloj del
sistema.

-u usuari

o
Esta opción establece el nombre del usuario del sistema al que chronyd cambiará después del inicio para abandonar los privilegios de root. Anula la directiva user. El valor predeterminado compilado es chrony.

En Linux, chronyd necesita ser compilado con soporte para la biblioteca libcap. En macOS, FreeBSD, NetBSD e illumos chronyd se divide en dos procesos. El proceso hijo retiene los privilegios de root, pero solo

puede realizar un rango muy limitado de llama
das al sistema privilegiadas en nombre del padre.

-

U
Esta opción deshabilita una verificación de privilegios de root para permitir que chronyd se inicie bajo un usuario no root, asumiendo que el proceso tendrá todas las capacidades (por ejemplo, proporcionadas por el gestor de servicios) y acceso a todos los archivos, directorios y dispositivos necesarios para funcionar correctamente en la configuración especificada. Tenga en cuenta que pueden ser necesarias diferentes capacidades con diferentes configuraciones y diferentes versiones del kernel de Linux. No se recomienda iniciar chronyd bajo un usuario no root cuando la configuración no se conoce, o al menos está limitada a directivas
específicas.

-F nive

l
Esta opción configura los filtros de llamadas al sistema cargados por los procesos de chronyd si se compiló con soporte para la función de computación segura (seccomp) de Linux. Se definen tres niveles: 0, 1, 2. Los filtros están deshabilitados en el nivel 0. En los niveles 1 y 2, chronyd será terminado si hace una llamada al sistema que está bloqueada por los filtros. El nivel se puede especificar como un número negativo para activar la señal SIGSYS en lugar de SIGKILL, lo que puede ser útil para la depuración. El valor predeterminado es 0.

En el nivel 1, los filtros permiten solo llamadas al sistema seleccionadas que normalmente se espera que sean hechas por chronyd. Otras llamadas al sistema están bloqueadas. Este nivel solo se recomienda si se sabe que funciona en la versión del sistema donde chrony está instalado. Los filtros también necesitan permitir las llamadas al sistema hechas por las bibliotecas que chronyd está usando (por ejemplo, libc), pero diferentes versiones o implementaciones de las bibliotecas pueden hacer diferentes llamadas al sistema. Si a los filtros les falta una llamada al sistema, chronyd podría ser terminado incluso en operación

normal.

En el nivel 2, los filtros bloquean solo un pequeño número de llamadas al sistema específicas (por ejemplo, fork y exec). Este enfoque debería evitar falsos positivos, pero la protección del sistema contra un proceso chronyd comprometido es mucho más

limitada.

Los filtros no se pueden habilitar con la directiva ma

ilonc
hange.

-P priorida

d
En Linux, FreeBSD, NetBSD e illumos esta opción seleccionará el planificador de tiempo real SCHED_FIFO en la prioridad especificada (que debe estar entre 0 y 100). En macOS, esta opción debe tener un valor de 0 para deshabilitar la política de restricción de tiempo del hilo o 1 para habilitar la política. Otros sistemas no admiten esta opción. El valor predeterminado es
0.

-

m
Esta opción bloqueará chronyd en la RAM para que nunca sea paginado fuera. Este modo solo es compatible en Linux, FreeBSD, NetBSD y illumos
.

-

x
Esta opción desactiva el control del reloj del sistema. chronyd no intentará realizar ningún ajuste del reloj. Asumirá que el reloj funciona libremente y seguirá rastreando su desfase y frecuencia respecto al tiempo verdadero estimado. Esta opción permite que chronyd se inicie sin la capacidad de ajustar o establecer el reloj del sistema (por ejemplo, en algunos contenedores) para operar como un servidor
NTP.

-v, --versio

n
Con esta opción chronyd imprimirá el número de versión en la terminal y
saldrá.

-h, --hel

p
Con esta opción chronyd imprimirá un mensaje de
ayuda en la te
rminal y saldrá.

VARIABLES DE

ENTORNO

LISTEN_FD

S
En los sistemas Linux, el gestor de servicios systemd puede pasar descriptores de archivo de sockets pre-inicializados a chronyd. El gestor de servicios asigna y enlaza los descriptores de archivo, y pasa una copia a cada instancia del servicio generada. Esto permite reinicios del servicio sin tiempo de inactividad, ya que los s
ockets almacenan en búfer las peticiones de los clientes hasta que el servicio puede manejarlas. El gesto
r de servicios establece la variable de entorno LISTEN_FDS a el número de descriptores de archivo pasados.
