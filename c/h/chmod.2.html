DESCRIPCIÓ

N

Las llamadas al sistema chmod() y fchmod() cambian los bits de modo de un archivo. (El modo del archivo consiste en los bits de permisos del archivo más los bits set-user-ID, set-group-ID y sticky.) Estas llamadas al sistema difieren únicamente en la forma en que se especifica el

archivo:
•
chmod() cambia el modo del archivo especificado cuya ruta de acceso se da en path, la cual es desreferenciada si es un enlace
simbólico.
•
fchmod() cambia el modo del archivo al que se refiere el descriptor de archivo abierto fd
.

El nuevo modo del archivo se especifica en mode, que es una máscara de bits creada mediante la operación OR de cero o más de los

siguientes:
S_ISUID
(04000)
set-user-ID (establece el ID de usuario efectivo del proceso al execve(
2))
S_ISGID
(02000)
set-group-ID (establece el ID de grupo efectivo del proceso al execve(2); bloqueo obligatorio, como se describe en fcntl(2); tomar el grupo de un archivo nuevo del directorio padre, como se describe en chown(2) y mkdir(2)) S_ISVTX (
01000)
bit sticky (indicador de borrado restringido, como se
describe en

El UID efectivo del proceso que llama debe coincidir con el propietario del archivo, o el proceso debe ser privilegiado (en Linux:
debe
tener la

capacidad CAP_FOWNER). Si el proceso que llama no es privilegiado (en Linux: no tiene

la

capacidad CAP_FSETID), y el grupo del archivo no coincide con el ID de grupo efectivo del proceso ni con ninguno de sus IDs de grupo suplementarios, el bit S_ISGID será desactivado, pero esto no causará que se devuelva un error. Como medida de seguridad, dependiendo del sistema de archivos, los bits de ejecución set-user-ID y set-group-ID pueden ser desactivados si un archivo es escrito. (En Linux, esto ocurre si el proceso que escribe no tiene

la

capacidad CAP_FSETID.) En algunos sistemas de archivos, solo el superusuario puede establecer el bit sticky, que puede tener un significado especial. Para el bit sticky, y para los bits set-user-ID y set-group-ID en directorios, véase inode(7). En los sistemas de archivos NFS, restringir los permisos influirá inmediatamente en los archivos ya abiertos, porque el control de acceso se realiza en el servidor, pero los archivos abiertos son mantenidos por el cliente. Ampliar los permisos puede retrasarse para otros clientes si el almacenamiento en caché de

atributos está habilitado en ellos.
