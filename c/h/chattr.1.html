utos de un archivo en un si

SINOPSI

DESCRIPCIÓ

N

chattr cambia los atributos de un archivo en un sistema de archivos de

Linux.

El formato de un modo simbólico es +-=[aAcCdDeFijmPs

StTux].

El operador '+' hace que los atributos seleccionados se añadan a los atributos existentes de los archivos; '-' hace que se eliminen; y ''=' hace que sean los únicos atributos que los archivos

tengan.

Las letras 'aAcCdDeFijmPsStTux' seleccionan los nuevos atributos para los archivos: solo añadir (a), no actualizar atime (A), comprimido (c), no copiar al escribir (C), no volcar (d), actualizaciones de directorio síncronas (D), formato extent (e), búsquedas de directorio sin distinguir mayúsculas de minúsculas (F), inmutable (i), registro de datos (j), no comprimir (m), jerarquía de proyecto (P), borrado seguro (s), actualizaciones síncronas (S), no fusionar la cola (t), parte superior de la jerarquía de directorios (T), no borrable (u), y acceso directo para archivos (x)

.

Los siguientes atributos son de solo lectura, y pueden ser listados por lsattr(1) pero no modificados por chattr: cifrado (E), directorio indexado (I), datos en línea (N), y verity (V)

.

No todos los indicadores son soportados o utilizados por todos los sistemas de archivos; consulte las páginas man específicas del sistema de archivos como btrfs(5), ext4(5), mkfs.f2fs(8), y xfs(5) para más detalles espec

íficos del siste
ma de archivos.

ATRIBUTO

S
a
Un archivo con el atributo 'a' establecido solo puede ser abierto en modo de adición para escritura. Solo el superusuario o un proceso que posea la capacidad CAP_LINUX_IMMUTABLE puede establecer o borrar este
atributo.
A
Cuando se accede a un archivo con el atributo 'A' establecido, su registro atime no es modificado. Esto evita una cierta cantidad de E/S de disco para sistemas
portátiles.
c
Un archivo con el atributo 'c' establecido es comprimido automáticamente en el disco por el kernel. Una lectura de este archivo devuelve datos sin comprimir. Una escritura a este archivo comprime los datos antes de almacenarlos en el disco. Nota: por favor asegúrese de leer la sección de errores y limitaciones al final de este documento. (Nota: Para btrfs, si el indicador 'c' está establecido, entonces el indicador 'C' no puede establecerse. También entra en conflicto con la opción de montaje de btrfs
'nodatasum')
C
Un archivo con el atributo 'C' establecido no estará sujeto a actualizaciones de copiar al escribir. Este indicador solo es soportado en sistemas de archivos que realizan copiar al escribir. (Nota: Para btrfs, el indicador 'C' debería establecerse en archivos nuevos o vacíos. Si se establece en un archivo que ya tiene bloques de datos, es indeterminado cuándo los bloques asignados al archivo serán completamente estables. Si el indicador 'C' está establecido en un directorio, no tendrá ningún efecto en el directorio, pero los archivos nuevos creados en ese directorio tendrán el atributo No_COW establecido. Si el indicador 'C' está establecido, entonces el indicador 'c' no puede establecerse.
)
d
Un archivo con el atributo 'd' establecido no es candidato para la copia de seguridad cuando se ejecuta el programa dump(8)
.
D
Cuando se modifica un directorio con el atributo 'D' establecido, los cambios son escritos síncronamente al disco; esto es equivalente a la opción de montaje 'dirsync' aplicada a un subconjunto de los
archivos.
e
El atributo 'e' indica que el archivo está usando extents para mapear los bloques en disco. No puede ser eliminado usando chattr(
1).
E
Un archivo, directorio o enlace simbólico con el atributo 'E' establecido es cifrado por el sistema de archivos. Este atributo no puede ser establecido ni borrado usando chattr(1), aunque puede ser mostrado por lsattr(
1).
F
Un directorio con el atributo 'F' establecido indica que todas las búsquedas de rutas dentro de ese directorio se realizan de una manera que no distingue entre mayúsculas y minúsculas. Este atributo solo puede ser cambiado en directorios vacíos en sistemas de archivos con la característica casefold
habilitada.
i
Un archivo con el atributo 'i' no puede ser modificado: no puede ser eliminado ni renombrado, no se puede crear ningún enlace a este archivo, la mayoría de los metadatos del archivo no pueden ser modificados, y el archivo no puede ser abierto en modo de escritura. Solo el superusuario o un proceso que posea la capacidad CAP_LINUX_IMMUTABLE puede establecer o borrar este
atributo.
I
El atributo 'I' es usado por el código htree para indicar que un directorio está siendo indexado usando árboles con hash. No puede ser establecido ni borrado usando chattr(1), aunque puede ser mostrado por lsattr(
1).
j
Un archivo con el atributo 'j' tiene todos sus datos escritos en el registro de ext3 o ext4 antes de ser escritos en el archivo mismo, si el sistema de archivos está montado con las opciones "data=ordered" o "data=writeback" y el sistema de archivos tiene un registro. Cuando el sistema de archivos está montado con la opción "data=journal" todos los datos del archivo ya están registrados y este atributo no tiene ningún efecto. Solo el superusuario o un proceso que posea la capacidad CAP_SYS_RESOURCE puede establecer o borrar este
atributo.
m
Un archivo con el atributo 'm' está excluido de la compresión en sistemas de archivos que soportan compresión por
archivo.
N
Un archivo con el atributo 'N' establecido indica que el archivo tiene datos almacenados en línea, dentro del propio inodo. No puede ser establecido ni borrado usando chattr(1), aunque puede ser mostrado por lsattr(
1).
P
Un directorio con el atributo 'P' establecido impondrá una estructura jerárquica para los identificadores de proyecto. Esto significa que los archivos y directorios creados en el directorio heredarán el identificador de proyecto del directorio, las operaciones de renombrado están restringidas de modo que cuando un archivo o directorio es movido a otro directorio, los identificadores de proyecto deben coincidir. Además, un enlace duro a un archivo solo puede ser creado cuando el identificador de proyecto del archivo y el directorio de destino
coinciden.
s
Cuando se elimina un archivo con el atributo 's' establecido, sus bloques son puestos a cero y escritos de vuelta al disco. Nota: por favor asegúrese de leer la sección de errores y limitaciones al final de este
documento.
S
Cuando se modifica un archivo con el atributo 'S' establecido, los cambios son escritos síncronamente al disco; esto es equivalente a la opción de montaje 'sync' aplicada a un subconjunto de los
archivos.
t
Un archivo con el atributo 't' no tendrá un fragmento de bloque parcialnt at the end of the file merged with other files (for those file systems which support tail-merging). This is necessary for applications such as LILO which read the file system directly, and which don't understand tail-merged files. Note: As of this writing, the ext2, ext3, and ext4 file systems do not support
tail-merging.
T
A directory with the 'T' attribute will be deemed to be the top of directory hierarchies for the purposes of the Orlov block allocator. This is a hint to the block allocator used by ext3 and ext4 that the subdirectories under this directory are not related, and thus should be spread apart for allocation purposes. For example it is a very good idea to set the 'T' attribute on the /home directory, so that /home/john and /home/mary are placed into separate block groups. For directories where this attribute is not set, the Orlov block allocator will try to group subdirectories closer together where
possible.
u
When a file with the 'u' attribute set is deleted, its contents are saved. This allows the user to ask for its undeletion. Note: please make sure to read the bugs and limitations section at the end of this
document.
x
A file with the 'x' requests the use of direct access (dax) mode, if the kernel supports DAX. This can be overridden by the 'dax=never' mount option. For more information see the kernel documentation for dax: https://www.kernel.org/doc/htm
l/latest/filesy
stems/dax.html.
If the attribute is set on an existing directory, it will be inherited by all files and subdirectories that are s
ubsequently created in the directory. If an existing directory has contained some files and subdirectories,
modifying the attribute on the parent directory doesn't change the attributes on these files and subdirectories.
V
A file with the 'V' attribute set has fs-verity enabled. It cannot be written to, and the file system will automatically verify all data read from it against a cryptographic hash that covers the entire file's contents, e.g. via a Merkle tree. This makes it possible to efficiently authenticate the file. This attribute may not be set or cleared using chattr(1), although it can be displayed by lsat
tr
(1
).

BUGS AND

LIMITATIONS

The 'c', 's', and 'u' attributes are not honored by the ext2, ext3, and ext4 file systems as implemented in the current mainline Linux kernels. Setting 'a' and 'i' attributes will not affect the ability to write to already existing file

descriptors.

The 'j' option is only useful for ext3 and ext4 file

systems.

The 'D' option is only

useful on Linux kern
el 2.5.19 and later.
