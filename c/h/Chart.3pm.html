N

Chart te ayuda a crear imágenes PNG y JPG con visualizaciones de datos numéricos. Esta página te da un resumen de cómo usarlo. Para una documentación más detallada y mucho código de ejemplo, visita por favor el Chart::

Todos los diferentes tipos de gráficos (Points, Lines, Bars, LinesPoints, Composite, StackedBars, Pie, Pareto, HorizontalBars, Split, ErrorBars, Direction y Mountain hasta ahora) son clases por sí mismas, cada una heredando un montón de métodos de la clase Chart::Base. Obteniendo un

El método new puede ser llamado sin argumentos, en cuyo caso devuelve un objeto con el tamaño de imagen predeterminado (400x300 píxeles), o puedes especificar el ancho y el alto de la imagen. Simplemente recuerda reemplazar type con el tipo de gráfico que quieras. Por

devolvería un objeto Chart::Bars que contiene una imagen de 600x

Enviando la imagen a un
archivo
Invocar el método png hace que el gráfico sea trazado y guardado en un archivo. Toma el nombre del archivo de salida y una referencia a los datos como argumentos. Por ejemplo, 
$obj->png ("foo.png", \@data)
;

trazaría los datos en @data, y luego guardaría la imagen en foo.png. Por supuesto, esto plantea la cuestión "¿Cómo debería ser @data?". Bueno, al igual que GIFgraph, @data debería contener referencias a arreglos de datos, con la primera referencia de arreglo apuntando a un arreglo de etiquetas de marcas x.

Por ejemplo, 
@data = ( [ 'foo', 'bar', 'junk' ],
      [ 30.2,  23.5,  92.1
] );

configuraría un gráfico con un conjunto de datos, y tres puntos de datos en ese conjunto. En general, el arreglo @data debería verse

algo como 
@data = ( \@x_tick_labels, \@dataset1, ... , \@dataset_n
);

API basada en

columnas

Podrías preguntar, "Pero, ¿qué pasa si solo quiero añadir unos puntos al gráfico, y luego mostrarlo, sin todas esas referencias a referencias?". Bueno, amigo, la solución es simple. Tomando prestada la idea de add_pt del módulo Graph de Matt Kruse, simplemente haces unas cuantas llamadas al método add_pt,

así: 
$obj->add_pt ('foo', 30, 25);
$obj->add_pt ('bar', 16, 32)
;

O, si quieres poder añadir conjuntos de datos completos, simplemente usa el método

add_dataset: 
$obj->add_dataset ('foo', 'bar');
$obj->add_dataset (30, 16);
$obj->add_dataset (25, 32)
;

Estos métodos comprueban que los puntos y conjuntos de datos que estás añadiendo sean del mismo tamaño que los que ya están allí. Así que, si tienes dos conjuntos de datos almacenados actualmente, e intentas añadir un punto de datos con tres valores diferentes, emitirá un carp (según el módulo Carp) con un mensaje de error. De manera similar, si intentas añadir un conjunto de datos con 4 puntos de datos, y todos los otros conjuntos de datos tienen 3 puntos de datos, emitirá un carp con un mensaje de

error.

No olvides, al usar esta API, que trato el primer conjunto de datos como una serie de etiquetas de marcas x. Así que, en los ejemplos anteriores, el gráfico tendría dos marcas x, etiquetadas 'foo' y 'bar', cada una con dos puntos de datos. Pie y ErrorBars lo manejan de manera diferente, mira la documentación para ver cómo

funciona.
Añadiendo un archivo de
datos
También puedes añadir un archivo de datos completo a un objeto de gráfico. Simplemente usa el método add_datafile(). 
$obj->add_datafile('file', 'set' o
'pt');

file puede ser el nombre del archivo de datos o un filehandle. 'set' o 'pt' es el tipo del archivo de datos. Si el parámetro es 'set', entonces cada línea en el archivo de datos tiene que ser un conjunto de datos completo. El valor del conjunto tiene que estar separado por espacios en blanco. Por ejemplo, el archivo

Si el parámetro es 'pt', una línea tiene que incluir todos los valores de un punto de datos separados por espacios en blanco.

Soporte de

Imagemap

Chart también puede devolver la información de posicionamiento de píxeles para que puedas crear mapas de imagen a partir de los pngs que genera Chart. Simplemente establece la opción 'imagemap' a 'true' antes de generar el png, y luego llama al método imagemap_dump() después para recuperar la información. Se te devolverá una estructura de datos casi idéntica al array @data descrito arriba para pasar los datos a

Chart. 
$imagemap_data = $obj->imagemap_dump ()
;

En lugar de valores de datos individuales, se te pasarán referencias a arrays de información de píxeles. Para los gráficos Bars, HorizontalBars y StackedBars, los arrays contendrán dos pares x-y (especificando la esquina superior izquierda y la esquina inferior derecha de la barra),

así: 
( $x1, $y1, $x2, $y2 ) = @{ $imagemap_data->[$dataset][$datapoint] }
;

Para Lines, Points, ErrorBars, Split y LinesPoints, los arrays contendrán un solo par x-y (especificando el centro del punto),

así: 
( $x, $y ) = @{ $imagemap_data->[$dataset][$datapoint] }
;

Se aplican algunas advertencias. En primer lugar, GD trata la esquina superior izquierda del png como el punto (0,0), por lo que los valores positivos de y se miden desde la parte superior del png, no desde la parte inferior. Segundo, estos valores probablemente contendrán valores decimales largos. GD, por supuesto, tiene que truncarlos a valores de píxel individuales. Dado que no sé cómo lo hace GD, no puedo truncarlo de la misma manera que él lo hace. En el peor de los casos, esto resultará en un error de un píxel en tu mapa de imagen. Si esto es realmente un problema, tu única opción es experimentar con ello, o contactar a Lincoln Stein y preguntarle. Tercero, por favor recuerda que el dataset 0 estará vacío, ya que ese es el lugar en el array @data para las e

tiquetas d
e los punto
s de datos.

Este módulo está actualmente bajo una reconstrucción completa, que tendrá lugar en dos fases. Primero: reescribir toda la funcionalidad dentro de una arquitectura modular y un sistema jerárquico de propiedades.
