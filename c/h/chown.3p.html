DESCRIPCIÓ

N

La función chown() cambiará la propiedad de usuario y de grupo de un

archivo.

El argumento path apunta a una ruta de acceso que nombra un archivo. El ID de usuario y el ID de grupo del archivo nombrado se establecerán a los valores numéricos contenidos en owner y group, respectivamente

.

Solo los procesos con un ID de usuario efectivo igual al ID de usuario del archivo o con privilegios apropiados pueden cambiar la propiedad de un archivo. Si _POSIX_CHOWN_RESTRICTED está en efecto para path

:
*
Cambiar el ID de usuario está restringido a los procesos con privilegios
apropiados.
*
Cambiar el ID de grupo está permitido a un proceso con un ID de usuario efectivo igual al ID de usuario del archivo, pero sin privilegios apropiados, si y solo si owner es igual al ID de usuario del archivo o (uid_t)-1 y group es igual ya sea al ID de grupo efectivo del pr
oceso que llama o a uno de sus
IDs de grupo suplementarios.

Si el archivo especificado es un archivo regular, uno o más de los bits S_IXUSR, S_IXGRP o S_IXOTH del modo del archivo están establecidos, y el proceso no tiene privilegios apropiados, los bits de ID de usuario establecido (S_ISUID) y de ID de grupo establecido (S_ISGID) del modo del archivo se borrarán al retornar con éxito de chown(). Si el archivo especificado es un archivo regular, uno o más de los bits S_IXUSR, S_IXGRP o S_IXOTH del modo del archivo están establecidos, y el proceso tiene privilegios apropiados, es definido por la implementación si los bits de ID de usuario establecido y de ID de grupo establecido se alteran. Si la función chown() se invoca con éxito en un archivo que no es un archivo regular y uno o más de los bits S_IXUSR, S_IXGRP o S_IXOTH del modo del archivo están establecidos, los bits de ID de usuario establecido y de ID de grupo establecido pueden

borrarse.

Si owner o group se especifican como (uid_t)-1 o (gid_t)-1, respectivamente, el ID correspondiente del archivo no se

cambiará.

Al completarse con éxito, chown() marcará para actualización la marca de tiempo del último cambio de estado del archivo, excepto que si owner es (uid_t)-1 y group es (gid_t)-1, la marca de tiempo del cambio de estado del archivo no necesita ser marcada para

actualización.

La función fchownat() será equivalente a las funciones chown() y lchown() excepto en el caso en que path especifique una ruta relativa. En este caso, el archivo a cambiar se determina relativo al directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción de archivo abierto asociada con el descriptor de archivo no es O_SEARCH, la función comprobará si se permiten búsquedas en directorios usando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la

comprobación.

USO EN

APLICACIONES

Aunque chown() puede ser usada en algunas implementaciones por el propietario del archivo para cambiar el propietario y el grupo a cualquier valor deseado, el único uso portable de esta función es para cambiar el grupo de un archivo al grupo efectivo GID del proceso que ll

ama o a un miembro de
su conjunto de grupos.

JUSTIFICACIÓ

N

System III y System V permiten a un usuario ceder archivos; es decir, el propietario de un archivo puede cambiar su ID de usuario a cualquier valor. Este es un problema serio para implementaciones que pretenden cumplir con las regulaciones de seguridad gubernamentales. Version 7 y 4.3 BSD permiten únicamente al superusuario cambiar el ID de usuario de un archivo. Algunas agencias gubernamentales (generalmente no las que se ocupan directamente de la seguridad) consideran esta limitación demasiado restrictiva. Este volumen de POSIX.1‐2017 usa may (puede) para permitir implementaciones seguras sin desprobar System

V.

System III y System V permiten al propietario de un archivo cambiar el ID de grupo a cualquier valor. Version 7 permite únicamente al superusuario cambiar el ID de grupo de un archivo. 4.3 BSD permite al propietario cambiar el ID de grupo de un archivo a su ID de grupo efectivo o a cualquiera de los grupos en la lista de IDs de grupo suplementarios, pero a ningún

otro.

El estándar POSIX.1‐1990 requiere que la función chown() invocada por un proceso privilegiado no apropiado limpie los bits S_ISGID y S_ISUID para archivos regulares, y permite que se limpien para otros tipos de archivos. Esto es para que los cambios en la accesibilidad no causen accidentalmente que los archivos se conviertan en agujeros de seguridad. Desafortunadamente, requerir que estos bits se limpien en archivos de datos no ejecutables también limpia el bit de bloqueo obligatorio de archivos (compartido con S_ISGID), que es una extensión en muchas implementaciones (apareció por primera vez en System V). Estos bits solo deberían requerirse que se limpien en archivos regulares que tengan uno o más de sus bits de ejecución

establecidos.

El propósito de la función fchownat() es permitir cambiar la propiedad de archivos en directorios distintos del directorio de trabajo actual sin exposición a condiciones de carrera. Cualquier parte de la ruta de un archivo podría cambiarse en paralelo a una llamada a chown() o lchown(), resultando en un comportamiento no especificado. Al abrir un descriptor de archivo para el directorio de destino y usar la función fchownat() se puede garantizar que el archivo modif

icado está ubicado de forma
relativa al directorio deseado.
