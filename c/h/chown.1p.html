DESCRIPCIÓ

N

La utilidad chown establecerá el ID de usuario del archivo nombrado por cada operando archivo al ID de usuario especificado por el operando propietario

.

Para cada operando archivo, o, si se usa la opción -R, cada archivo encontrado al recorrer los árboles de directorios especificados por los operandos archivo, la utilidad chown realizará acciones equivalentes a la función chown() definida en el volumen de Interfaces del Sistema de POSIX.1‐2017, llamada con los siguientes

argumentos:
1
.
El operando archivo se utilizará como el argumento ruta
.
2
.
El ID de usuario indicado por la porción propietario del primer operando se utilizará como el argumento propietari
o.
3
.
Si se proporciona la porción grupo del primer operando, el ID de grupo indicado por ella se utilizará como el argumento grupo; de lo contrario, la prop
iedad del grupo
no se cambiará.

A menos que chown sea invocado por un proceso con privilegios apropiados, los bits set-user-ID y set-group-ID de un archivo regular

se borrarán al completarse con éxito; los bits set-user-ID
y set-group-ID de otros tipos de archivo pueden borrarse.

OPCIONE

S

La utilidad chown deberá cumplir con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis d

e Utilidades.

Las siguientes opciones deberán ser soportadas por la

implementación:
-
h
Para cada operando archivo que nombre un archivo de tipo enlace simbólico, chown intentará establecer el ID de usuario del enlace simbólico. Si se especificó un ID de grupo, para cada operando archivo que nombre un archivo de tipo enlace simbólico, chown intentará establecer el ID de grupo del enlace
simbólico.
-
H
Si se especifica la opción -R y se especifica en la línea de comandos un enlace simbólico que referencie un archivo de tipo directorio, chown cambiará el ID de usuario (y el ID de grupo, si se especifica) del directorio referenciado por el enlace simbólico y de todos los archivos en la jerarquía de archivos por debajo de
él.
-
L
Si se especifica la opción -R y se especifica en la línea de comandos o se encuentra durante el recorrido de una jerarquía de archivos un enlace simbólico que referencie un archivo de tipo directorio, chown cambiará el ID de usuario (y el ID de grupo, si se especifica) del directorio referenciado por el enlace simbólico y de todos los archivos en la jerarquía de archivos por debajo de
él.
-
P
Si se especifica la opción -R y se especifica en la línea de comandos o se encuentra durante el recorrido de una jerarquía de archivos un enlace simbólico, chown cambiará el ID de propietario (y el ID de grupo, si se especifica) del enlace simbólico. La utilidad chown no seguirá el enlace simbólico a ninguna otra parte de la jerarquía de
archivos.
-
R
Cambiar recursivamente los IDs de usuario y de grupo de los archivos. Para cada operando archivo que nombre un directorio, chown cambiará el ID de usuario (y el ID de grupo, si se especifica) del directorio y de todos los archivos en la jerarquía de archivos por debajo de él. A menos que se especifique una opción -H, -L, o -P, no está especificado cuál de e
stas opciones se u
sará por defecto.

Especificar más de una de las opciones mutuamente excluyentes -H, -L, y -P no se considerará un error. La última opción especif

icada determinará el co
mportamiento de la utilidad.

JUSTIFICACIÓ

N

Las versiones de System V y BSD utilizan códigos de estado de salida diferentes. Algunas implementaciones utilizaban el estado de salida como un recuento del número de errores que ocurrieron; esta práctica no es viable ya que puede desbordar el rango de valores de estado de salida válidos. Estos se enmascaran especificando solo 0 y >0 como valores de

salida.

La funcionalidad de chown se describe sustancialmente mediante referencias a funciones en el volumen de Interfaces del Sistema de POSIX.1‐2017. De esta manera, no se requiere duplicación de esfuerzo para describir las interacciones de permisos, múltiples grupos,

etc.

El método de 4.3 BSD de especificar tanto el propietario como el grupo fue incluido en este volumen de POSIX.1‐2017

porque:
*
Hay casos en los que la condición final deseada no podría lograrse usando las utilidades chgrp y chown (que solo cambiaban el ID de usuario). (Si el propietario actual no es miembro del grupo deseado y el propietario deseado no es miembro del grupo actual, la función chown() podría fallar a menos que tanto el propietario como el grupo se cambien al mismo tiempo.
)
*
Incluso si pudieran cambiarse de forma independiente, en los casos en lo
s que ambos se están cambiando, hay una penalización de rendimien
to del 100% causada por verse obligado a invocar ambas utilidades.

La sintaxis de BSD user[.group] se cambió a user[:group] en este volumen de POSIX.1‐2017 porque el <punto> es un carácter válido en los nombres de inicio de sesión (como se especifica en el volumen de Definiciones Básicas de POSIX.1‐2017, los nombres de inicio de sesión consisten en caracteres del conjunto de caracteres de nombres de archivo portables). El carácter <dos puntos> se eligió como reemplazo del carácter <punto> porque nunca se permitiría como carácter en un nombre de usuario o nombre de grupo en implementaciones

históricas.

La opción -R es considerada por algunos observadores como una salida indeseable del enfoque histórico de las herramientas del sistema UNIX; dado que ya existe una herramienta, find, para recorrer directorios recursivamente, no pareció haber una buena razón para requerir que otras herramientas tuvieran que duplicar esa funcionalidad. Sin embargo, la opción -R fue considerada una comodidad importante para el usuario, es mucho más eficiente que generar un p

roceso separado para cada elemento de la jerarquí
a de directorios, y está en un amplio uso histórico.
