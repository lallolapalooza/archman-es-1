Devuelve -1 si el canal no fue abierto para el modo en cuestión. chan pipe Crea una tubería (pipe) independiente cuyos canales de lectura y escritura se devuelven como una lista de 2 elementos, siendo el primer elemento el lado de lectura y el segundo el lado de escritura. Puede ser útil, por ejemplo, para redirigir por separado stderr y stdout de un subproceso. Para hacer esto, crea un proceso con los operadores de redirección "2>@" o ">@" hacia el lado de escritura de una tubería, y luego ciérralo inmediatamente en el padre. chan push channelId cmdPrefix
Añade una nueva transformación en la parte superior del canal channelId. El argumento cmdPrefix describe una lista de una o más palabras que representan un manejador que se usará para implementar la transformación. El prefijo de comando debe proporcionar la API descrita en la página del manual transchan . El resultado de este subcomando es un manejador de la transformación. Tenga en cuenta que es importante asegurarse de que la transformación sea capaz de soportar el modo de canal con el que se usa o esto puede hacer que el canal no sea ni legible ni escribible.
chan puts ?-nonewline? ?channelId? string
Escribe string en el canal nombrado channelId seguido de un carácter de nueva línea. Se escribe un carácter de nueva línea final a menos que se proporcione el indicador opcional -nonewline . Si channelId se omite, la cadena se escribe en el canal de salida estándar, stdout.

Los caracteres de nueva línea en la salida son traducidos por chan puts a secuencias de fin de línea específicas de la plataforma de acuerdo con el valor configurado actualmente de la opción -translation para el canal (por ejemplo, en las PC las nuevas líneas se reemplazan normalmente con secuencias de retorno de carro y salto de línea; vea chan configure arriba para detalles).

Tcl almacena la salida internamente, por lo que los caracteres escritos con chan puts pueden no aparecer inmediatamente en el archivo o dispositivo de salida; Tcl normalmente retrasará la salida hasta que el búfer esté lleno o el canal se cierre. Puede forzar que la salida aparezca inmediatamente con el comando chan flush

. Cuando el búfer de salida se llena, el comando chan puts normalmente se bloqueará hasta que todos los datos almacenados en el búfer hayan sido aceptados para su salida por el sistema operativo. Si channelId está en modo no bloqueante, entonces el comando chan puts no se bloqueará incluso si el sistema operativo no puede aceptar los datos. En su lugar, Tcl continúa almacenando los datos en el búfer y los escribe en segundo plano tan rápido como el archivo o dispositivo subyacente pueda aceptarlos. La aplicación debe usar el bucle de eventos de Tcl para que la salida no bloqueante funcione; de lo contrario, Tcl nunca se entera de que el archivo o dispositivo está listo para más datos de salida. Es posible que se almacenen en el búfer una cantidad arbitrariamente grande de datos para un canal en modo no bloqueante, lo que podría consumir una gran cantidad de memoria. Para evitar desperdiciar memoria, la E/S no bloqueante normalmente debe usarse de una manera impulsada por eventos con el comando chan event (no invoque chan puts a menos que haya recibido recientemente una notificación a través de un evento de archivo de que el canal está listo para más datos de salida).

chan read channelId ?numChars?
chan read ?-nonewline? channelId
En la primera forma, el resultado serán los próximos numChars caracteres leídos del canal nombrado channelId; si numChars se omite, se leen todos los caracteres hasta el punto en que el canal señalara un fallo (ya sea una condición de fin de archivo, bloqueo u otro error). En la segunda forma (es decir, cuando numChars se ha omitido) el indicador -nonewline puede darse para indicar que cualquier nueva línea final en la cadena que se ha leído debe ser recortada.

Si channelId está en modo no bloqueante, chan read puede no leer tantos caracteres como se solicita: una vez que se ha leído toda la entrada disponible, el comando devolverá los datos que están disponibles en lugar de bloquearse esperando más entrada. Si el canal está configurado para usar una codificación de varios bytes, entonces puede que en realidad queden algunos bytes en los búferes internos que no forman un carácter completo. Estos bytes no serán devueltos hasta que haya disponible un carácter completo o se alcance el fin de archivo. El interruptor -nonewline se ignora si el comando retorna antes de alcanzar el final del archivo.

Chan read traduce las secuencias de fin de línea en la entrada en caracteres de nueva línea de acuerdo con la opción -translation para el canal (vea chan configure arriba para una discusión sobre las formas en que chan configure alterará la entrada).

Al leer de un puerto serie, la mayoría de las aplicaciones deberían configurar el canal del puerto serie para que sea no bloqueante, así:

chan configure channelId -blocking 0.

Luego chan read se comporta mucho como se describió arriba. Tenga en cuenta que la mayoría de los puertos serie son relativamente lentos; es completamente posible recibir un evento legible por cada carácter leído de ellos. Se debe tener cuidado al usar chan read en puertos serie bloqueantes:

chan read channelId numChars
En esta forma chan read se bloquea hasta que numChars hayan sido recibidos del puerto serie.
chan read channelId
En esta forma chan read se bloquea hasta la recepción del carácter de fin de archivo, vea chan configure -eofchar. Si no se ha configurado ningún carácter de fin de archivo para el canal, entonces chan read se bloqueará para siempre.
chan seek channelId offset ?origin?
Establece la posición de acceso actual dentro del flujo de datos subyacente para el canal nombrado channelId para que sea offset bytes relativos a origin. Offset debe ser un entero (que puede ser negativo) y origin debe ser uno de los siguientes:
start
La nueva posición de acceso será offset bytes desde el inicio del archivo o dispositivo subyacente.
current
La nueva posición de acceso será offset bytes desde la posición de acceso actual; un offset negativo mueve la posición de acceso hacia atrás en el archivo o dispositivo subyacente.
end
La nueva posición de acceso será offset bytes desde el final del archivo o dispositivo. Un offset negativo coloca la posición de acceso antes del fin de archivo, y un offset positivo coloca la posición de acceso después del fin de archivo.

El argumento origin por defecto es start.

Chan seek vacía toda la salida almacenada en el búfer para el canal antes de que el comando retorne, incluso si el canal está en modo no bloqueante. También descarta cualquier entrada almacenada en el búfer y no leída. Este comando retorna una cadena vacía. Se produce un error si este comando se aplica a canales cuyo archivo o dispositivo subyacente no soporta el posicionamiento.

Tenga en cuenta que los valores offset son desplazamientos en bytes, no desplazamientos en caracteres. Tanto chan seek como chan tell operan en términos de bytes, no de caracteres, a diferencia de chan read.

chan tell channelId
Retorna un número que indica la posición de acceso actual dentro del flujo de datos subyacente para el canal nombrado channelId. Este valor retornado es un desplazamiento en bytes que puede pasarse a chan seek para establecer el canal en una posición particular. Tenga en cuenta que este valor está en términos de bytes, no de caracteres como chan read. El valor retornado es -1 para canales que no soportan el posicionamiento.
chan truncate channelId ?length?
Establece la longitud en bytes del flujo de datos subyacente para el canal nombrado channelId para que sea length (o el desplazamiento en bytes actual dentro del flujo de datos subyacente si length se omite). El canal se vacía antes de la truncación.

EJEMPLOS

EJEMPLOS SIMPLES DE OPERACIÓN DE CANAL

Instruir a Tcl para que siempre envíe la salida a stdout inmediatamente, esté o no en un terminal:

fconfigure stdout -buffering none

En el siguiente ejemplo se abre un archivo usando la codificación CP1252, que es común en Windows, se busca una cadena, se reescribe esa parte y se trunca el archivo dos líneas después.

set f [open somefile.txt r+]
chan configure $f -encoding cp1252
set offset 0
# Buscar la cadena "FOOBAR" en el archivo
while {[chan gets $f line] >= 0} {
    set idx [string first FOOBAR $line]
    if {$idx >= 0} {
        # Se encontró; reescribir la línea
        chan seek $f [expr {$offset + $idx}]
        chan puts -nonewline $f BARFOO
        # Saltar al final de la siguiente línea y truncar
        chan gets $f
        chan gets $f
        chan truncate $f
        # Dejar de buscar en el archivo ahora
        break
    }
    # Guardar el desplazamiento del inicio de la siguiente línea para más tarde
    set offset [chan tell $f]
}
chan close $f
