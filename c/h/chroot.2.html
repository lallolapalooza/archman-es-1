chroot(2) Manual de llamadas al sistema chroot(2)

NOMBRE

chroot - cambiar el directorio raíz

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int chroot(const char *path);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

chroot():

    Desde glibc 2.2.2:
        _XOPEN_SOURCE && ! (_POSIX_C_SOURCE >= 200112L)
            || /* Desde glibc 2.20: */ _DEFAULT_SOURCE
            || /* glibc <= 2.19: */ _BSD_SOURCE
    Antes de glibc 2.2.2:
        ninguno

DESCRIPCIÓN

chroot() cambia el directorio raíz del proceso que llama al especificado en path. Este directorio se usará para los nombres de ruta que comiencen con /. El directorio raíz es heredado por todos los hijos del proceso que llama.

Solo un proceso privilegiado (Linux: uno con la capacidad CAP_SYS_CHROOT en su espacio de nombres de usuario) puede llamar a chroot().

Esta llamada cambia un ingrediente en el proceso de resolución de rutas y no hace nada más. En particular, no está destinada a ser utilizada para ningún tipo de propósito de seguridad, ni para aislar completamente un proceso ni para restringir las llamadas al sistema del sistema de archivos. En el pasado, chroot() ha sido utilizada por daemons para restringirse a sí mismos antes de pasar rutas suministradas por usuarios no confiables a llamadas al sistema como open(2). Sin embargo, si una carpeta se mueve fuera del directorio chroot, un atacante puede explotar eso para salir también del directorio chroot. La forma más fácil de hacerlo es chdir(2) al directorio que se va a mover, esperar a que sea movido, y luego abrir una ruta como ../..etc/passwd.

Una variación ligeramente más compleja también funciona bajo ciertas circunstancias si chdir(2) no está permitido. Si un daemon permite especificar un "directorio chroot", eso generalmente significa que si desea evitar que los usuarios remotos accedan a archivos fuera del directorio chroot, debe asegurarse de que las carpetas nunca se muevan fuera de él.

Esta llamada no cambia el directorio de trabajo actual, por lo que después de la llamada '.' puede estar fuera del árbol anclado en '/'. En particular, el superusuario puede escapar de una "jaula chroot" haciendo:


mkdir foo;
chroot foo;
cd ..;

Esta llamada no cierra los descriptores de archivo abiertos, y dichos descriptores de archivo pueden permitir el acceso a archivos fuera del árbol chroot.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

Dependiendo del sistema de archivos, pueden producirse otros errores. Los errores más generales se enumeran a continuación:

EACCES
Se niega el permiso de búsqueda en un componente del prefijo de ruta (ver también path_resolution(7)).
EFAULT
path apunta fuera de su espacio de direcciones accesible.
EIO
Se produjo un error de E/S.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
ENAMETOOLONG
path es demasiado largo.
ENOENT
El archivo no existe.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOTDIR
Un componente de path no es un directorio.
EPERM
El llamador no tiene privilegios suficientes.

ESTÁNDARES

Ninguno.

HISTORIA

SVr4, 4.4BSD, SUSv2 (marcado como LEGACY). Esta función no forma parte de POSIX.1-2001.

NOTAS

Un proceso hijo creado a través de fork(2) hereda el directorio raíz de su padre. El directorio raíz se deja sin cambios por execve(2).

El enlace simbólico mágico, /proc/pid/root, se puede utilizar para descubrir el directorio raíz de un proceso; ver proc(5) para más detalles.

FreeBSD tiene una llamada al sistema más robusta, jail().
