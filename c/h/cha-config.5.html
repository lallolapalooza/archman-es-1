Configuración de Chawan

Chawan admite la configuración de varias opciones como asignaciones de teclas, hojas de estilo de usuario, preferencias de sitio, etc. El formato de configuración es similar a toml, con las siguientes excepciones:

  • Las tablas en línea pueden abarcar varias líneas.
  • Las tablas regulares ([table]) y las tablas en línea (table = {}) tienen semánticas diferentes. La primera es aditiva, lo que significa que los valores antiguos no se eliminan. La segunda es destructiva y borra todas las definiciones en la tabla especificada.
  • [[table-array]] es azúcar sintáctico para [table-array.n], donde n es el número de arrays de tablas declarados. Por ejemplo, puede declarar siteconfs anónimos usando la sintaxis [[siteconf]].

La ruta canónica del archivo de configuración es ~/.chawan/config.toml, pero la ruta de búsqueda también tiene en cuenta los basedirs de XDG:

1.
archivo de configuración especificado a través de la opción -C -> usar ese
2.
$CHA_DIR está definido -> usar $CHA_DIR/config.toml
3.
${XDG_CONFIG_HOME:-~/.config}/chawan/config.toml existe -> usar ese
4.
~/.chawan/config.toml existe -> usar ese

Consulte la sección de manejo de rutas para detalles sobre cómo se puede acceder al directorio de configuración.

Inicio

Las opciones de inicio deben colocarse en la sección [start] .

A continuación se muestra una lista de opciones de inicio:

Nombre Valor Predeterminado Función
visual-home url “about:chawan” Página que se abre cuando se llama a Chawan con la opción -V y no se pasan otras páginas como argumentos.
startup-script Código JavaScript ““ Script que Chawan ejecuta al inicio. Las páginas no se cargarán hasta que esta función salga. (Sin embargo, tenga en cuenta que las funciones asíncronas como setTimeout no bloquean la carga.)
headless booleano / “dump” false Cuando se establece en true o “dump”, el navegador no toma entrada; en su lugar, imprime una versión renderizada de todos los búferes en orden y luego sale. La diferencia entre true y “dump” es que true primero espera a que todos los scripts y solicitudes de red se completen, mientras que “dump” no lo hace. Esto significa que true puede no salir nunca cuando el scripting está habilitado (p. ej., si un script establece setInterval.) Canalizar cha hacia un programa externo o pasar la opción -d tiene el mismo efecto que establecer esta opción en “dump”.
console-buffer booleano true Si Chawan debe abrir un búfer de consola en modo no headless. Advertencia: esto solo es útil para depuración. Deshabilitar esta opción sin redirigir manualmente la salida de error estándar hará que los mensajes de error aparezcan aleatoriamente en su pantalla.

Búfer

Las opciones de búfer deben colocarse en la sección [buffer] .

Estas opciones son globales para todos los búferes. Para un filtrado más granular, use [[siteconf]].

Ejemplo:

[buffer]
# mostrar imágenes en todos los sitios web
images = true
# deshabilitar CSS del sitio web
styling = false
# Especificar estilos de usuario.
user-style = '''
/* puede importar estilos UA externos así: */
@import 'user.css';
/* o simplemente insertar el estilo en línea como sigue. */
/* hacer cumplir la text-decoration predeterminada para enlaces (es decir, subrayado). */
a[href] { text-decoration: revert !important }
@media (monochrome) { /* solo en el modo de color "monochrome" (o -M) */
	/* deshabilitar el estilo UA de fuente en negrita (no se necesita important aquí) */
	a[href]:hover { font-weight: initial }
	/* ...e italizar la fuente al pasar el cursor en su lugar.
	 * aquí usamos important porque no queremos que los sitios web
	 * sobrescriban el valor. */
	a[href]:hover { font-style: italic !important }
}
'''
# Puede *establecer* scripting en true aquí, pero recomiendo encarecidamente usar
# [[siteconf]] para habilitarlo por sitio en su lugar.

A continuación se muestra una lista de opciones de búfer:

Nombre Valor Predeterminado Función
styling booleano true Habilitar/deshabilitar las hojas de estilo del autor. Tenga en cuenta que deshabilitar esto no afecta a los estilos de usuario.
scripting booleano / “app” false Habilitar/deshabilitar JavaScript en todos los búferes. "app" también habilita las APIs de JavaScript que se pueden usar para identificar usuarios (p. ej., consultar el tamaño de la ventana). Esto puede lograr una mejor compatibilidad con los sitios web que se comportan como aplicaciones, a costa de una privacidad reducida. Por razones de seguridad, se anima a los usuarios a habilitar JavaScript selectivamente con [[siteconf]] en lugar de usar esta configuración.
images booleano false Habilitar/deshabilitar la visualización de imágenes en línea.
cookie booleano / “save” false Habilitar/deshabilitar cookies en los sitios. Si se especifica la cadena “save”, las cookies también se guardan en external.cookie-file. true todavía lee cookies.txt, pero no lo modifica. En Chawan, cada sitio web obtiene un almacén de cookies separado, por lo que los sitios web que dependen de cookies entre sitios pueden no funcionar como se espera. Puede usar la [[siteconf]] configuración "share-cookie-jar" para ajustar este comportamiento para sitios específicos.
referer-from booleano false Habilitar/deshabilitar la cabecera “Referer”. Por defecto es false. Por razones de privacidad, se anima a los usuarios a dejar esta opción deshabilitada, habilitándola solo para sitios específicos en [[siteconf]].
autofocus booleano false Cuando se establece en true, los elementos con un atributo “autofocus” reciben el foco automáticamente después de que se carga el búfer. Si el scripting está habilitado, esto también permite que los scripts establezcan el foco en elementos.
meta-refresh “never” / “always” / “ask” “ask” Si se deben respetar o no las etiquetas meta http-equiv=refresh . “never” las deshabilita completamente, “always” las acepta automáticamente todas, “ask” muestra un menú emergente.
history booleano true Si el historial de navegación debe guardarse en el disco.
mark-links booleano false Agrega marcadores numéricos antes de los enlaces. En el modo headless/dump, esto también imprime una lista de URL después de la página.
user-style cadena ““ Una hoja de estilo de usuario aplicada a todos los búferes. Las hojas de estilo externas se pueden importar usando la sintaxis @import 'file.css'; . Las rutas son relativas al directorio de configuración. El @import anidado no está soportado todavía.

Búsqueda

Las opciones de búsqueda deben colocarse en la sección [search] .

A continuación se muestra una lista de opciones de búsqueda:

Nombre Valor Predeterminado Función
wrap booleano true Si las búsquedas en la página debería envolver el documento.
ignorar-mayúsculas “auto” / booleano “auto” Cuando se establece en true, las búsquedas en todo el documento no distinguen mayúsculas de minúsculas por defecto. Cuando se establece en “auto”, las búsquedas solo distinguen mayúsculas de minúsculas cuando el término de búsqueda incluye una letra mayúscula. Nota: esto también se puede anular en línea en la barra de búsqueda (estilo vim), con las secuencias de escape \c (ignorar mayúsculas) y \C (mayúsculas estrictas). Consulte el modo de búsqueda para más detalles.)

Codificación

Las opciones de codificación deben colocarse en la sección [encoding] .

A continuación se muestra una lista de opciones de codificación:

Nombre Valor Predeterminado Función
document-charset matriz de etiquetas de juego de caracteres [“utf-8”, “sjis”, “euc-jp”, “latin2”] Lista de juegos de caracteres para cargar documentos. Se enumeran todos los juegos de caracteres listados hasta que el documento se ha decodificado sin errores. En HTML, las etiquetas meta y el BOM pueden anular esto con un juego de caracteres diferente, siempre que el juego de caracteres especificado pueda decodificar el documento correctamente.
display-charset cadena “auto” Juego de caracteres para la entrada de teclado y la visualización de documentos. También se utiliza en modo volcado. (Esto significa que, por ejemplo,cha -I EUC-JP -O UTF-8 a > b es aproximadamente equivalente a iconv -f EUC-JP -t UTF-8.)

Externo

Las opciones externas deben colocarse en la sección [external] .

A continuación se muestra una lista de opciones externas:

Nombre Valor Predeterminado Función
tmpdir ruta {generalmente /tmp/cha-tmp-user} Directorio utilizado para guardar archivos temporales.
editor comando de shell {generalmente $EDITOR} Comando del editor externo. %s se sustituye por el nombre del archivo, %d por el número de línea.
mailcap matriz de rutas {ver la documentación de mailcap} Ruta de búsqueda para archivos mailcap. (Consulte cha-mailcap(5) para más detalles.) Los directorios especificados primero tienen mayor precedencia.
mime-types matriz de rutas {ver la documentación de mime.types} Ruta de búsqueda para archivos mime.types. (Consulte cha-mime.types(5) para más detalles.)
auto-mailcap ruta “auto.mailcap” Archivo mailcap para entradas que se ejecutan automáticamente. El prompt “Abrir como” también guarda entradas en este archivo.
cgi-dir matriz de rutas {ver la documentación de CGI local} Ruta de búsqueda para scripts CGI locales. (Consulte cha-localcgi(5) para más detalles.)
urimethodmap matriz de rutas {ver la documentación de urimethodmap} Ruta de búsqueda para archivos urimethodmap. (Consulte cha-urimethodmap(5) para más detalles.)
w3m-cgi-compat booleano false Habilita la compatibilidad de CGI local con w3m. En resumen, redirige file:///cgi-bin/* y file:///$LIB/cgi-bin/* a cgi-bin:*. Para más detalles, consulte cha-localcgi(5).
download-dir ruta {igual que tmpdir} Ruta para rellenar previamente en los prompts “Guardar en:”.
show-download-panel booleano true Si about:downloads debe mostrarse después de iniciar una descarga.
copy-cmd comando de shell “xsel -bi” Comando a usar para operaciones de “copiar al portapapeles”.
paste-cmd comando de shell “xsel -bo” Comando a usar para operaciones de “leer del portapapeles”.
bookmark ruta “bookmark.md” Ruta al archivo bookmark.md. (El archivo al que apunta debe tener una extensión .md, para que su tipo pueda deducirse correctamente.)
history-file ruta “history.uri” Ruta al archivo de historial.
history-size número 100 Longitud máxima del archivo de historial.
cookie-file ruta “cookies.txt” Ruta al archivo de cookies. El formato es equivalente al formato “cookies.txt” de curl, excepto que se antepone una parte “jar@” para las cookies que pertenecen a un jar diferente al del dominio. Las cookies de este archivo se usan si “buffer.cookie” (o su equivalente en siteconf) está establecido en true o "save". Esto significa que true establece el archivo de cookies en modo de solo lectura.

Entrada

Las opciones de entrada deben colocarse en la sección [input] .

Nombre Valor Predeterminado Función
vi-numeric-prefix booleano true Si se deben aceptar prefijos numéricos estilo vi para los comandos. Solo se aplica a las asociaciones de teclas definidas en [page].
use-mouse booleano true Si se permite a Chawan interceptar clics del ratón. La implementación actual imita a w3m.
osc52-copy booleano / “auto” auto Si Chawan debe usar la secuencia de escape OSC 52 para copiar al portapapeles directamente a través del terminal. Cuando está disponible, OSC 52 anula external.copy-cmd. Cuando se establece en “auto” (el valor predeterminado), Chawan intenta detectar si OSC 52 está disponible al inicio.
bracketed-paste booleano true Si Chawan debe solicitar el pegado entre corchetes. Cuando es true, el terminal (esperemos) marcará el texto pegado con secuencias de escape, lo que a) asegura que pegar un carácter de salto de línea en el editor de línea no envíe el editor, y b) permite a Chawan interceptar el texto pegado en el visor, cargándolo automáticamente en la barra de URL del navegador.
wheel-scroll número 5 Número de líneas a desplazar para un evento de rueda del ratón.
side-wheel-scroll número 5 Número de columnas a desplazar para un evento de rueda lateral del ratón.
link-hint-chars cadena abcdefghijklmnoprstuvxyz Una cadena de caracteres a usar en toggleLinkHints. Se acepta cualquier punto de código Unicode, y se ordenan como se especifica en esta opción.

Ejemplos:

[input]
vi-numeric-prefix = true
[page]
# Aquí, la función de flecha se llamará con el prefijo numerado de vi si
# se introdujo uno, y sin argumento en caso contrario.
# El prefijo numérico nunca puede ser cero, por lo que es seguro probar
# si es undefined usando el operador ternario.
G = 'n => n ? pager.gotoLine(n) : pager.cursorLastLine()'

Red

Las opciones de red deben colocarse en la sección [network] .

Nombre Valor Predeterminado Función
max-redirect número 10 Número máximo de redirecciones a seguir.
max-net-connections número 12 Número máximo de conexiones de red simultáneas permitidas en un búfer. Las conexiones adicionales se retienen hasta que el número vuelve a estar por debajo del umbral.
prepend-scheme cadena “https://” Anteponer esto a las URL pasadas a Chawan sin un esquema. Tenga en cuenta que los archivos locales (esquemafile: ) siempre se comprobarán primero; solo si esto falla, Chawan reintentará la solicitud con prepend-scheme establecido como el esquema.
proxy URL sin establecer Especificar un proxy para todas las solicitudes de red que hace Chawan. Actualmente, se aceptan los formatos http://user:pass@domain y socks5://user:pass@domain . (A diferencia de curl, socks5h es un alias de socks5, y las solicitudes DNS siempre se canalizan.) Puede ser anulado por siteconf.
default-headers tabla {omitido} Especificar una lista de cabeceras predeterminadas para todas las solicitudes de red HTTP(S). Puede ser anulado por siteconf.
allow-http-from-file booleano false ADVERTENCIA: piénselo dos veces antes de habilitar esto. Permite HTTP y HPeticiones TTPS desde el archivo: y esquemas de flujo: . Esto es una muy mala idea en general, porque permite que archivos locales hagan ping a servidores remotos (una funcionalidad comúnmente abusada por los correos electrónicos HTML para rastrear la actividad de tu bandeja de entrada). Por otro lado, permite cargar imágenes en correos electrónicos HTML si no te importan las implicaciones de privacidad.

Pantalla

Las opciones de pantalla deben colocarse en la [display] sección.

A continuación se muestra una lista de opciones de pantalla:

Nombre Valor Predeterminado Función
color-mode “monochrome” / “ansi” / “eight-bit” / “true-color” / “auto” “auto” Establece el modo de color. “auto” para detección automática, “monochrome” para negro sobre blanco, “ansi” para colores ansi, “eight-bit” para modo de 256 colores y “true-color” para colores reales.
format-mode “auto” / [“bold”, “italic”, “underline”, “reverse”, “strike”, “overline”, “blink”] “auto” Especifica los modos de formato de salida. Acepta la cadena “auto” o un array de atributos específicos. Un array vacío ([]) desactiva el formato por completo.
no-format-mode [“bold”, “italic”, “underline”, “reverse”, “strike”, “overline”, “blink”] “overline” Desactiva modos de formato específicos.
image-mode “auto” / “none” / “sixel” / “kitty” “auto” Especifica el modo de salida de imágenes. “sixel” usa sixels para la salida, “kitty” usa el protocolo de visualización de imágenes de Kitty, “none” desactiva la visualización de imágenes por completo. “auto” intenta detectar el soporte de sixel o kitty, y recurre a “none” cuando ninguno de los dos está disponible. Esta es la configuración predeterminada, pero también debes habilitar buffer.images para que las imágenes funcionen.
sixel-colors “auto” / 2..65535 “auto” Solo se aplica cuando display.image-mode="sixel". Establecer un número anula el número de registros de color sixel informados por el terminal.
alt-screen “auto” / booleano “auto” Habilita/deshabilita la pantalla alternativa.
highlight-color color “cyan” Establece el color de resaltado para la búsqueda incremental y las marcas. Se aceptan tanto valores hexadecimales como nombres de colores CSS. En modo monocromo, esta configuración se ignora; en su lugar, se usa vídeo invertido.
highlight-marks booleano true Habilita/deshabilita el resaltado de marcas.
double-width-ambiguous booleano false Asume que el terminal muestra los caracteres de la categoría Ambigua del Este Asiático como caracteres de doble ancho. Útil cuando, por ejemplo, ○ ocupa dos celdas.
minimum-contrast número 100 Especifica la diferencia mínima entre la luminancia (Y) del fondo y el primer plano. -1 desactiva esta función (es decir, permite letras negras sobre fondo negro, etc.).
force-clear booleano false Fuerza que la pantalla se borre por completo cada vez que se vuelve a dibujar.
set-title booleano true Establece el título de la ventana del emulador de terminal como el de la página actual.
default-background-color “auto” / color “auto” Anula el color de fondo asumido del terminal. “auto” deja la detección del color de fondo a Chawan.
default-foreground-color “auto” / color “auto” Establece el color de primer plano asumido del terminal. “auto” deja la detección del color de primer plano a Chawan.
query-da1 bool true Habilita/deshabilita la consulta de Atributos Primarios del Dispositivo y, con ello, toda la consulta “dinámica” del terminal. No alteres este valor a menos que Chawan te lo indique; la salida se verá horrible.
columns, lines, pixels-per-column, pixels-per-line número 80, 24, 9, 18 Valores de reserva para el número de columnas, líneas, píxeles por columna y píxeles por línea en los casos en que no se puedan determinar automáticamente. (Por ejemplo, estos valores se utilizan en el modo de volcado.)
force-columns, force-lines, force-pixels-per-column, force-pixels-per-line booleano false Fuerza el establecimiento de columnas, líneas, píxeles por columna o píxeles por línea a los valores de reserva proporcionados arriba.

Omnirule

La barra omni (abierta de forma predeterminada con C-l) se puede usar para realizar búsquedas utilizando omni-rules. Estas deben especificarse como subclaves de la tabla [omnirule]. (La subclave en sí misma se ignora; puedes usar cualquier cosa siempre que no entre en conflicto con otras claves.)

Ejemplos:

# Buscar usando DuckDuckGo Lite.
# (Esta regla está incluida en la configuración predeterminada, aunque C-k invoca
# la búsqueda de Brave.)
[omnirule.ddg]
match = '^ddg:'
substitute-url = '(x) => "https://lite.duckduckgo.com/lite/?kp=-1&kd=-1&q=" + encodeURIComponent(x.split(":").slice(1).join(":"))'
# Para usar la regla anterior, abre la barra de URL con C-k, bórrala con
# C-u, y escribe ddg:palabraclave.
# Alternativamente, también puedes redefinir C-k así:
[page]
'C-k' = '() => pager.load("ddg:")'
# Buscar usando Wikipedia, al estilo de Firefox.
# La sintaxis [[omnirule]] introduce una omnirule anónima; es
# equivalente a la nombrada.
[[omnirule]]
match = '^@wikipedia'
substitute-url = '(x) => "https://en.wikipedia.org/wiki/Special:Search?search=" + encodeURIComponent(x.replace(/@wikipedia/, ""))'

Como se mencionó anteriormente, la configuración predeterminada incluye algunas reglas integradas, seleccionadas según la preferencia del mantenedor y el criterio mínimo de que deben funcionar sin cookies y JavaScript. Actualmente, estas son:

  • ddg: - DuckDuckGo Lite.
  • br: - Brave Search.
  • wk: - Wikipedia en inglés.
  • wd: - Wikitionary en inglés.
  • mo: - Mojeek.

Opciones de Omnirule:

Nombre Valor Función
match regex Expresión regular utilizada para hacer coincidir la cadena de entrada. Ten en cuenta que los sitios web pasados como argumentos también se comparan. Nota: las regex se manejan de acuerdo con las reglas de manejo de regex del modo de coincidencia.
substitute-url Función JavaScript Una función JavaScript a la que Chawan pasará la cadena de entrada. Si se devuelve una nueva cadena, se analizará en lugar de la antigua.

Siteconf

Se pueden especificar opciones de configuración para sitios individuales. Las entradas deben especificarse como subclaves de la tabla [siteconf]. (La subclave en sí misma se ignora; puedes usar cualquier cosa siempre que no entre en conflicto con otras claves.)

La mayoría de las opciones de siteconf también se pueden especificar globalmente; consulta el campo “overrides”.

Ejemplos:

# Habilitar cookies en el sitio naranja para iniciar sesión.
[siteconf.hn]
url = 'https://news\.ycombinator\.com/.*'
cookie = true
# Redirigir npr.org a text.npr.org.
[siteconf.npr]
host = '(www\.)?npr\.org'
rewrite-url = '''
(x) => {
	x.host = "text.npr.org";
	const s = x.pathname.split('/');
	x.pathname = s.at(s.length > 2 ? -2 : 1);
	/* No es necesario devolver; los objetos URL se pasan por referencia. */
}
'''
# Permitir el uso compartido de cookies en los dominios *sr.ht.
[siteconf.sr-ht]
host = '(.*\.)?sr\.ht' # ya sea 'something.sr.ht' o 'sr.ht'
cookie = true # habilitar cookies (solo lectura; usa "save" para persistirlas)
share-cookie-jar = 'sr.ht' # usar el almacén de cookies de 'sr.ht' para todos los hosts coincidentes
# Usar el tema "vector" en Wikipedia.
# La sintaxis [[siteconf]] introduce una siteconf anónima; es
# equivalente a las anteriores.
[[siteconf]]
url = '^https?://[a-z]+\.wikipedia\.org/wiki/(?!.*useskin=.*)'
rewrite-url = 'x => x.searchParams.append("useskin", "vector")'
# Hacer que imgur nos envíe imágenes.
[siteconf.imgur]
host = '(i\.)?imgur\.com'
default-headers = {
	User-Agent = "Mozilla/5.0 chawan",
	Accept = "*/*",
	Accept-Encod{
	"ing": "gzip, deflate",
	"Accept-Language": "en;q=1.0",
	"Pragma": "no-cache",
	"Cache-Control": "no-cache"
}
```

Atajos de teclado

Los atajos de teclado deben colocarse en estas secciones:

  • para interacción con el paginador: [page]
  • para edición de línea: [line]

Los atajos de teclado se configuran usando la sintaxis

'<keybinding>' = '<action>'

Donde <keybinding> es una combinación de caracteres unicode con o sin modificadores. Los modificadores son los prefijos C- y M-, que añaden control o escape a la combinación de teclas respectivamente (básicamente haciendo M- lo mismo que C-[). Los modificadores se pueden escapar con la barra invertida \.

<action> es un comando definido en la sección [cmd], o una expresión de JavaScript. Aquí solo describimos las acciones predefinidas en la configuración predeterminada; para una descripción de la API, por favor consulte:

La documentación de la API en cha-api(7).

Ejemplos:

# mostrar cambio de URL al presionar Control, Escape y j
'C-M-j' = 'load'
# ir a la primera línea de la página al presionar g dos veces sin un número previo
# o a la línea cuando se da un número previo.
'gg' = 'gotoLineOrStart'
# también se aceptan funciones y expresiones de JS. Lo siguiente reemplaza el
# motor de búsqueda predeterminado con DuckDuckGo Lite.
# (Ver api.md para una lista de funciones disponibles, y una discusión sobre cómo
# agregar tus propios comandos "con espacio de nombres" como el anterior.)
'C-k' = '() => pager.load("ddg:")'

Manejo de Expresiones Regulares

Las expresiones regulares se manejan actualmente utilizando la biblioteca libregexp de QuickJS. Esto significa que todas las expresiones regulares funcionan como en JavaScript.

Hay dos modos diferentes de preprocesamiento de expresiones regulares en Chawan: modo "búsqueda" y modo "coincidencia". El modo de coincidencia se utiliza para las configuraciones (es decir, en todos los valores de este documento descritos como "regex"). El modo de búsqueda se utiliza para la función de búsqueda en página (utilizando searchForward/isearchForward, etc.).

Modo de Coincidencia

Se asume que las expresiones regulares son coincidencias exactas, excepto cuando comienzan con un signo de intercalación (^) o terminan con un signo de dólar ($) no escapado.

En otras palabras, ocurren las siguientes transformaciones:

^abcd -> ^abcd (sin cambios, solo se coincide el principio)
efgh$ -> efgh$ (sin cambios, solo se coincide el final)
^ijkl$ -> ^ijkl$ (sin cambios, se coincide toda la línea)
mnop -> ^mnop$ (cambiado a coincidencia exacta, se coincide toda la línea)

El modo de coincidencia no tiene forma de activar indicadores de expresiones regulares de JavaScript como i.

Modo de Búsqueda

Para la búsqueda en página, las transformaciones anteriores no se aplican; la búsqueda /abcd busca la cadena abcd dentro de todas las líneas.

El modo de búsqueda también tiene otras transformaciones de conveniencia (estas no funcionan en el modo de coincidencia):

  • La cadena \c (barra invertida + c minúscula) dentro de una expresión regular en modo de búsqueda habilita la coincidencia sin distinción entre mayúsculas y minúsculas.
  • Por el contrario, \C (barra invertida + C mayúscula) deshabilita la coincidencia sin distinción entre mayúsculas y minúsculas. (Útil si tiene ignore-case establecido en true, que es el valor predeterminado).
  • \< y \> se convierten en \b (como en vi, grep, etc.)

Al igual que el modo de coincidencia, el modo de búsqueda opera en líneas individuales. Esto significa que los patrones de búsqueda no coinciden con texto que se extiende a lo largo de varias líneas.

Manejo de Rutas

Las reglas para el manejo de rutas son similares a como la shell maneja las cadenas.

  • Se utiliza la expansión de tilde para determinar el directorio de inicio del usuario. Así, por ejemplo, ~/whatever funciona.
  • Las variables de entorno se pueden usar como $ENV_VAR.
  • Las rutas relativas son relativas al directorio de configuración de Chawan (es decir, $CHA_DIR).

Algunas variables de entorno también son exportadas por Chawan:

  • $CHA_BIN_DIR: el directorio donde reside el binario cha. Los enlaces simbólicos se resuelven automáticamente para determinar esta ruta.
  • $CHA_LIBEXEC_DIR: el directorio para todos los ejecutables que Chawan utiliza para operar. Por defecto, este es $CHA_BIN_DIR/../libexec/chawan.
  • $CHA_DIR: el directorio de configuración. (Este también puede ser establecido por el usuario; ver la sección superior para más detalles).
  • $CHA_DATA_DIR: si el archivo de configuración utiliza los directorios base XDG, este es ${XDG_DATA_HOME:-$HOME/.local/share}/chawan. De lo contrario, es el mismo que $CHA_DIR.
•
Excepción: si $CHA_DIR se establece antes de que se invoque cha, entonces $CHA_DATA_DIR también se lee. Esto es para que las invocaciones anidadas funcionen en configuraciones con directorios base XDG.

Tipos de Palabras

Los comandos del paginador basados en palabras pueden operar con diferentes definiciones de palabras. Actualmente, estas son:

  • Palabras w3m
  • Palabras vi
  • Palabras grandes

Palabra w3m

Una palabra w3m es una secuencia de caracteres alfanuméricos. Los símbolos se tratan de la misma manera que los espacios en blanco.

Palabra vi

Una palabra vi es una secuencia de caracteres de la misma categoría de caracteres. Actualmente, las categorías de caracteres son caracteres alfanuméricos, símbolos, letras han, hiragana, katakana y hangul.

Las palabras vi pueden estar separadas por espacios en blanco; sin embargo, las palabras vi de diferentes categorías no tienen por qué estar separadas por espacios en blanco. Por ejemplo, la siguiente secuencia de caracteres contiene dos palabras:

hello[]+{}@`!

Palabra Grande

Una palabra grande es una secuencia de caracteres que no son espacios en blanco.

Es esencialmente lo mismo que una palabra w3m, pero con símbolos definidos como no espacios en blanco.
