chronyc es un programa de interfaz de línea de comandos que puede usarse para

monitorizar

el rendimiento de chronyd y para cambiar varios parámetros de funcionamiento mientras se está ejecutando. Si no se especifican comandos en la línea de

comandos,

chronyc esperará la entrada del usuario. El prompt chronyc> se mostrará cuando se ejecute desde una terminal. Si la entrada o la salida de chronyc se redirigen desde o hacia un archivo, el prompt no se

mostrará.

Hay dos formas en que chronyc puede acceder a chronyd. Una es el Protocolo de Internet (IPv4 o IPv6) y la otra es un socket de dominio Unix, al que se puede acceder localmente como root o como el usuario chrony. Por defecto, chronyc intenta primero conectarse al socket de dominio Unix. La ruta predeterminada compilada es /var/run/chrony/chronyd.sock. Si eso falla (por ejemplo, porque chronyc se está ejecutando como un usuario no root), intentará conectarse a 127.0.0.1 y luego a ::

1.

Solo se permiten los siguientes comandos de monitorización, que no afectan el comportamiento de chronyd, desde la red: activity, manual list, rtcdata, smoothing, sourcename, sources, sourcestats, tracking, waitsync. El conjunto de hosts desde los que chronyd aceptará estos comandos se puede configurar con la directiva cmdallow en el archivo de configuración de chronyd o con el comando cmdallow en chronyc. Por defecto, los comandos solo se aceptan desde localhost (127.0.0.1 o ::1)

.

Todos los demás comandos solo se permiten a través del socket de dominio Unix. Cuando se envían a través de la red, chronyd responderá con un error ‘Not authorised’ (No autorizado), incluso si proviene de

localhost.

Tener acceso completo a chronyd a través de chronyc es más o menos equivalente a poder modificar el archivo de configuración de chronyd y r

einic
iarlo.

Esto muestra la ‘frecuencia residual’ para la fuente de referencia actualmente seleccionada. Esto refleja cualquier diferencia entre lo que las mediciones de la fuente de referencia indican que debería ser la frecuencia y la frecuencia que se está utilizando actualmente.

La razón por la que esto no siempre es cero es que se aplica un procedimiento de suavizado a la frecuencia. Cada vez que se obtiene una medición de la fuente de referencia y se calcula una nueva f

recuencia residual, la precisión estimada de esta residual se compara con la precisión estimada (ver ‘desviación’ más adelante) del valor de frecuencia existente. Se calcula un promedio ponderado
para la nueva frecuencia, con pesos que dependen de estas precisiones. Si las mediciones de la fuente de referencia siguen una tendencia consistente, la residual se reducirá a cero con el tiempo.

makestep, makestep umbral límit

Normalmente chronyd hará que el sistema corrija gradualmente cualquier desfase horario, ralentizando o acelerando el reloj según sea necesario. En ciertas situaciones, el reloj del sistema podría estar tan desviado que este proceso de ajuste gradual tardaría mucho tiempo en corregir el reloj del sistema.

El comando makestep puede usarse en esta situación. Hay dos formas del comando. La primera forma no tiene parámetros. Le dice a chronyd que cancele cualquier corrección restante que se estuviera aplicando mediante ajuste gradual y salte el reloj del sistema por la cantidad equivalente, haciéndolo correcto

inmediatamente.

La segunda forma configura el salto automático, de manera similar a la directiva makestep. Tiene dos parámetros, umbral de salto (en segundos) y número de actualizaciones futuras del reloj para las cuales el umbral estará activo. Esto puede usarse con el comando burst para realizar rápidamente una nueva medición y corregir el reloj mediante un salto si es necesario, sin esperar a que chronyd complete la medición y actualice el

reloj.

El comando waitsync espera a que chronyd se sincronice.

Se pueden especificar hasta cuatro argumentos opcionales. El primero es el número máximo de intentos antes de abandonar y devolver un código de error distinto de cero. Cuando se especifica 0, o no hay argumentos, el número de intentos no estará

El cuarto argumento es el intervalo especificado en segundos en el que se repite la comprobación. El intervalo es de 10 segundos por

burst bueno/max [máscara/dirección-enmascarada], burst bueno/max [dirección-enmascarada/bits-enmascarados], burst bueno/max [dirección]

El comando **burst** indica a **chronyd** que realice un conjunto de mediciones a cada una de sus fuentes NTP durante un corto período de tiempo (en lugar de las mediciones periódicas habituales que realiza). Después de tal ráfaga, **chronyd** volverá al estado anterior para cada fuente. Este podría ser en línea, si la fuente se estaba midiendo periódicamente de forma normal, o fuera de línea, si la fuente se había indicado como fuera de línea. (Una fuente puede cambiarse entre los estados en línea y fuera de línea con los comandos **online** y **offline**).

Los argumentos *máscara* y *dirección-enmascarada* son opcionales, en cuyo caso **chronyd** iniciará una ráfaga para todas sus fuentes definidas actualmente.

Los argumentos tienen el siguiente significado y formato:

bueno

Define el número de mediciones buenas que **chronyd** deseará obtener de cada fuente. Una medición es buena si pasa ciertas pruebas, por ejemplo, el tiempo de ida y vuelta a la fuente debe ser aceptable. (Esto permite a **chronyd** rechazar mediciones que probablemente sean falsas).

max

Define el número máximo de mediciones que **chronyd** intentará realizar, incluso si no se ha obtenido el número requerido de mediciones buenas.

máscara

Esta es una dirección IP con la que se enmascarará la dirección IP de cada una de las fuentes de **chronyd**.

dirección-enmascarada

Esta es una dirección IP. Si la dirección IP enmascarada de una fuente coincide con este valor, entonces el comando burst se aplica a esa fuente.

bits-enmascarados

Esto se puede usar con *dirección-enmascarada* para notación CIDR, que es una alternativa más corta a la forma con máscara.

dirección

Esta es una dirección IP o un nombre de host. El comando burst se aplica solo a esa fuente.

Si no se proporcionan argumentos *máscara* o *dirección-enmascarada*, se corresponderá cada fuente.

Un ejemplo de la forma de dos argumentos del comando es:

burst 2/10

Esto hará que **chronyd** intente obtener dos mediciones buenas de cada fuente, deteniéndose después de obtener dos, pero en ningún caso intentará más de diez sondeos a la fuente.

NTP hardware TX timestamps

El número de respuestas NTP (en modo intercalado) que incluyeron una marca de tiempo de transmisión capturada por la NIC.

smoothing

El comando smoothing muestra el estado actual del suavizado de tiempo del servidor NTP, que se puede habilitar con la directiva smoothtime. A continuación, se muestra un ejemplo de la salida. 
Active         : Yes
Offset         : +1.000268817 seconds
Frequency      : -0.142859 ppm
Wander         : -0.010000 ppm per second
Last update    : 17.8 seconds ago
Remaining time : 19988.4 seconds

Los campos se explican de la siguiente manera:

Active

Esto muestra si el suavizado de tiempo del servidor está actualmente activo. Los valores posibles son Yes y No. Si la opción leaponly se incluye en la directiva smoothtime, se mostrará (leap second only) en la línea.

Offset

Este es el desplazamiento actual aplicado a la hora enviada a los clientes NTP. Un valor positivo significa que los clientes están recibiendo una hora que está adelantada respecto a la hora real.

Frequency

El desplazamiento de frecuencia actual del tiempo servido. Un valor negativo significa que el tiempo observado por los clientes se está ejecutando más lento que el tiempo real.

Wander

La deriva de frecuencia actual del tiempo servido. Un valor negativo significa que el tiempo observado por los clientes se está ralentizando.

Last update

Este campo muestra cuánto tiempo hace que se actualizó el proceso de suavizado de tiempo, por ejemplo, chronyd acumuló una nueva medición.

Remaining time

El tiempo que tardaría el proceso de suavizado en llegar a un desplazamiento y frecuencia cero si no hubiera más actualizaciones.

El comando smoothtime se puede utilizar para activar o restablecer el proceso de suavizado de tiempo del servidor si está configurado con la directiva smoothtime.
