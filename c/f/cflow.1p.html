CFLOW(1P) Manual del Programador POSIX CFLOW(1P)

PROLOG

Esta página del manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

cflow — genera un grafo de flujo en lenguaje C (DESARROLLO)

SINOPSIS

cflow [-r] [-d num] [-D name[=def]]... [-i incl] [-I dir]...
    [-U dir]... file...

DESCRIPCIÓN

La utilidad cflow analizará una colección de archivos de objetos o archivos fuente de ensamblador, lenguaje C, lexo yacc , e intentará construir un grafo, escrito en la salida estándar, que represente las referencias externas.

OPCIONES

La utilidad cflow deberá cumplir con el Volumen de Definiciones Básicas de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades, excepto que el orden de las opciones -D, -Iy -U (que son idénticas a su interpretación por c99) es significativo.

Se deberán soportar las siguientes opciones:

-dnum
Indica la profundidad a la que se corta el grafo de flujo. La aplicación deberá asegurar que el argumento num sea un entero decimal. Por defecto, este es un número muy grande (típicamente mayor que 32000). Los intentos de establecer la profundidad de corte en un entero no positivo serán ignorados.
-iincl
Aumenta el número de símbolos incluidos. El argumento de opción incl es uno de los siguientes caracteres:
x
Incluye símbolos de datos externos y estáticos. Por defecto, solo se incluirán funciones en el grafo de flujo.
_
(Guion bajo) Incluye nombres que comienzan con un <guion bajo>. Por defecto, se excluirán estas funciones (y datos si se usa -i x ).
-r
Invierte la relación llamante:llamado, produciendo un listado invertido que muestra los llamantes de cada función. El listado también se ordenará alfabéticamente por el llamado.

OPERANDOS

Se soporta el siguiente operando:

file
La ruta de un archivo para el cual se debe generar un grafo. Los nombres de archivo con el sufijo .l se considerarán entrada de lex , .y como entrada de yacc , .c como entrada de c99 , y .i como la salida de c99 -E. Dichos archivos se procesarán de manera apropiada, determinada por su sufijo.

Los archivos con el sufijo .s (convencionalmente código fuente de ensamblador) pueden tener información más limitada extraída de ellos.

STDIN

No se usa.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos de objetos o archivos fuente de ensamblador, lenguaje C, lexo yacc .

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de cflow:

LANG
Proporciona un valor por defecto para las variables de internacionalización que no están definidas o son nulas. (Vea el Volumen de Definiciones Básicas de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización usadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determina la configuración regional para el ordenamiento de la salida cuando se usa la opción -r .
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en oposición a multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la configuración regional que debe usarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Por defecto.

STDOUT

El grafo de flujo escrito en la salida estándar se formateará de la siguiente manera:

"%d %s:%s\n", <número de referencia>, <global>, <definición>

Cada línea de salida comienza con un número de referencia (es decir, línea), seguido de una indentación de al menos una posición de columna por nivel. Esto es seguido por el nombre del global, un <dos puntos>, y su definición. Normalmente, los globales son solo funciones no definidas como externas o que comienzan con un <guion bajo>; vea la sección OPCIONES para la opción de inclusión -i . Para la información extraída de código fuente en lenguaje C, la definición consiste en una declaración de tipo abstracto (por ejemplo, char *) y, delimitada por ángulos, el nombre del archivo fuente y el número de línea donde se encontró la definición. Las definiciones extraídas de archivos de objetos indican el nombre del archivo y el contador de ubicación bajo el cual apareció el símbolo (por ejemplo, text).

Una vez que se ha escrito una definición de un nombre, las referencias subsecuentes a ese nombre contendrán solo el número de referencia de la línea donde se puede encontrar la definición. Para referencias no definidas, solo se escribirá "<>" .

STDERR

La salida de error estándar se usará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Por defecto.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Los archivos producidos por lex y yacc causan el reordenamiento de las declaraciones de números de línea, y esto puede confundir a cflow. Para obtener resultados correctos, la entrada de yacc o lex debe dirigirse a cflow.

EJEMPLOS

Dado lo siguiente en file.c:

int i;
int f();
int g();
int h();
int
main()
{
    f();
    g();
    f();
}
int
f()
{
    i = h();
}

El comando:

cflow -i x file.c

produce la salida:

1 main: int(), <file.c 6>
2    f: int(), <file.c 13>
3        h: <>        i: int, <file.c 1>
5    g: <>
