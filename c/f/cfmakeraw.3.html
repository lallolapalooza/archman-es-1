DESCRIPCIÓ

N

Las funciones termios describen una interfaz de terminal general que se proporciona para controlar puertos de comunicaciones

asíncronas.

La estructura

termios

Muchas de las funciones descritas aquí tienen un termios_p argumento que es un puntero a una estructura termios. Esta estructura contiene al menos los siguientes

miembros: 


tcflag_t c_iflag;      /* modos de entrada */
tcflag_t c_oflag;      /* modos de salida */
tcflag_t c_cflag;      /* modos de control */
tcflag_t c_lflag;      /* modos locales */
cc_t     c_cc[NCCS];   /* caracteres especiales
*/

Los valores que pueden asignarse a estos campos se describen a continuación. En el caso de los cuatro primeros campos de máscara de bits, las definiciones de algunos de los indicadores asociados que pueden establecerse se exponen solo si se define una macro de prueba de características específica (ver feature_test_macros(7)), como se indica entre corchetes ("[]")

.

En las descripciones siguientes, "no en POSIX" significa que el valor no está especificado en POSIX.1-2001, y "XSI" significa que el valor está especificado en POSIX.1-2001 como parte de la extensión

XSI.

NAME

cfgetospeed, cfsetospeed, cfgetispeed, cfsetispeed, cfsetspeed - obtener y establecer velocidades de módem de terminal

SYNOPSIS

#include <termios.h>

speed_t cfgetospeed(const struct termios *termios_p);
int cfsetospeed(struct termios *termios_p, speed_t speed);

speed_t cfgetispeed(const struct termios *termios_p);
int cfsetispeed(struct termios *termios_p, speed_t speed);

int cfsetspeed(struct termios *termios_p, speed_t speed);

DESCRIPTION

La estructura termios, definida en <termios.h>, contiene información sobre los atributos de un terminal. Las funciones descritas aquí manipulan las velocidades de módem (baud rates) de esta estructura.

cfgetospeed() devuelve la velocidad de salida del módem almacenada en la estructura termios apuntada por termios_p.

cfsetospeed() establece la velocidad de salida del módem almacenada en la estructura termios apuntada por termios_p a speed, que debe ser una de estas constantes:

B0
B50
B75
B110
B134
B150
B200
B300
B600
B1200
B1800
B2400
B4800
B9600
B19200
B38400
B57600
B115200
B230400
B460800
B500000
B576000
B921600
B1000000
B1152000
B1500000
B2000000

Estas constantes son compatibles adicionalmente en la arquitectura SPARC:

B76800
B153600
B307200
B614400

Estas constantes son compatibles adicionalmente en arquitecturas que no son SPARC:

B2500000
B3000000
B3500000
B4000000

Debido a diferencias entre arquitecturas, las aplicaciones portables deberían comprobar si una constante Bnnn particular está definida antes de usarla.

La velocidad cero, B0, se utiliza para terminar la conexión. Si se especifica B0, las líneas de control del módem ya no se afirmarán. Normalmente, esto desconectará la línea. CBAUDEX es una máscara para las velocidades más allá de las definidas en POSIX.1 (57600 y superiores). Por lo tanto, B57600 & CBAUDEX no es cero.

Establecer la velocidad del módem a un valor distinto de las constantes Bnnn es posible a través de la llamada ioctl(2) TCSETS2; véase ioctl_tty(2).

cfgetispeed() devuelve la velocidad de entrada del módem almacenada en la estructura termios.

cfsetispeed() establece la velocidad de entrada del módem almacenada en la estructura termios a speed, que debe ser especificada como una de las constantes Bnnn listadas anteriormente para cfsetospeed(). Si la velocidad de entrada se establece a la constante literal 0 (no la constante simbólica B0), la velocidad de entrada será igual a la velocidad de salida.

cfsetspeed() es una extensión de 4.4BSD. Toma los mismos argumentos que cfsetispeed(), y establece tanto la velocidad de entrada como la de salida.

RETURN VALUE

cfgetispeed() devuelve la velocidad de entrada del módem almacenada en la estructura termios.

cfgetospeed() devuelve la velocidad de salida del módem almacenada en la estructura termios.

Todas las demás funciones devuelven:

0
en caso de éxito.
-1
en caso de fallo y establecen errno para indicar el error.

Tenga en cuenta que tcsetattr() devuelve éxito si cualquiera de los cambios solicitados pudo llevarse a cabo con éxito. Por lo tanto, al realizar múltiples cambios, puede ser necesario seguir esta llamada con una llamada posterior a tcgetattr() para comprobar que todos los cambios se han realizado correctamente.

NOTES

UNIX V7 y varios sistemas posteriores tienen una lista de velocidades de módem donde después de los valores B0 hasta B9600 se encuentran las dos constantes EXTA, EXTB ("External A" y "External B"). Muchos sistemas extienden la lista con velocidades mucho más altas.

El efecto de una duración distinta de cero con tcsendbreak() varía. SunOS especifica una pausa de duración * N segundos, donde N es al menos 0.25 y no más de 0.5. Linux, AIX, DU, Tru64 envían una pausa de duración milisegundos. FreeBSD y NetBSD y HP-UX y MacOS ignoran el valor de duración. Bajo Solaris y UnixWare, tcsendbreak() con una duración distinta de cero se comporta como tcdrain().

BUGS

En la arquitectura Alpha antes de Linux 4.16 (y glibc antes de glibc 2.28), el valor XTABS era diferente de TAB3 y, como resultado, el código de disciplina de línea N_TTY del controlador de terminal lo ignoraba (porque no era parte de la máscara TABDLY).
