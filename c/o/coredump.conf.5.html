El archivo de configuración principal se carga desde uno de los directorios listados en orden de prioridad, y solo se usa el primer archivo encontrado: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La versión del archivo proporcionada por el proveedor contiene entradas comentadas que muestran los valores predeterminados como guía para el administrador. También se pueden crear anulaciones locales creando *drop-ins*, como se describe a continuación. El archivo de configuración principal también se puede editar para este propósito (o una copia en /etc/ si se distribuye bajo /usr/), sin embargo, se recomienda usar *drop-ins* para la configuración local en lugar de modificar el archivo de configuración principal. Además del archivo de configuración principal, se leen fragmentos de configuración *drop-in* desde /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/ y

/etc/systemd/*.

Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en cuál de los subdirectorios se encuentren. Cuando varios archivos especifican la misma opción, para las opciones que aceptan un solo valor, la entrada en el archivo ordenado al final tiene prioridad, y para las opciones que aceptan una lista de valores, las entradas se recopilan a medida que ocurren en los archivos ordenados. Cuando los paquetes necesitan personalizar la configuración, pueden instalar *drop-ins* bajo /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración

instalados

por los paquetes del proveedor. Se deben usar *drop-ins* para anular los *drop-ins* de los paquetes, ya que el archivo de configuración principal tiene una prioridad más baja. Se recomienda prefijar todos los nombres de archivo en esos subdirectorios con un número de dos dígitos y un guion, para simplificar el ordenamiento. Esto también define un concepto de prioridades de *drop-in* para permitir a los proveedores del sistema operativo distribuir *drop-ins* dentro de un rango específico inferior al rango utilizado por los usuarios. Esto debería reducir el riesgo de que los *drop-ins* de los paquetes anulen accidentalmente los *drop-ins* definidos por los usuarios. Se recomienda usar el rango 10-40 para los *drop-ins* en /usr/ y el rango 60-90 para los *drop-ins* en /etc/ y /run/, para asegurarse de que los *drop-ins* locales y transitorios tengan prioridad sobre los *drop-ins* distribuidos por el proveedor del sistema operativo.
