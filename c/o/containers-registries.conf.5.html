Alias de nombres

cortos

El uso de registros de búsqueda no calificados implica una ambigüedad, ya que no está claro de qué registro puede extraerse una imagen determinada, referenciada por un nombre corto. Como

se

mencionó en la nota al final de esta página de manual, el uso de nombres cortos conlleva el riesgo de tropezar con espacios de nombres de registros secuestrados. Si los registros de búsqueda no calificados están configurados como ["registry1.com", "registry2.com"] un atacante puede secuestrar un espacio de nombres de registry1.com de modo que una imagen pueda extraerse de registry1.com en lugar del registro de origen

previsto

registry2.com. Aunque se recomienda encarecidamente usar siempre referencias de imagen completamente calificadas, es posible que los despliegues existentes que utilizan nombres cortos no se puedan cambiar fácilmente. Para sortear la ambigüedad mencionada, se pueden configurar los llamados alias de nombres cortos que apuntan a

una

referencia de imagen completamente calificada. Los alias de nombres cortos se pueden configurar en la tabla [aliases] en la forma de "name"="value" con el name del lado izquierdo siendo el nombre corto (por ejemplo, "image") y el [[11]] value del lado derecho siendo la referencia de imagen completamente calificada (por ejemplo, "registry.com/namespace/image"). Tenga en cuenta que ni "name" ni "value" pueden incluir una etiqueta o un resumen (digest). Además, "name" debe ser un nombre corto

y

por lo tanto no puede incluir un dominio de registro ni referirse a localhost. Al extraer un nombre corto, se utilizará la tabla de alias configurada para resolver el nombre corto. Si se encuentra un alias coincidente, se utilizará sin consultar más la lista de registros de búsqueda no calificados. Si no se encuentra ningún alias coincidente, el comportamiento se puede

controlar

a través de la opción short-name-mode como se describe a continuación. Tenga en cuenta que las etiquetas y los resúmenes (digests) se eliminan de un nombre corto especificado por el usuario para la resolución de alias. Por lo tanto, "image", "image:tag" y "image@digest" resuelven todos al mismo

alias

(es decir, "image"). Las etiquetas y los resúmenes eliminados se añaden posteriormente al alias resuelto. Tenga

en cuenta además que los archivos de configuración de incorporación automática (ver containers-registries.conf.d(5)
) pueden anular alias en el orden de carga específico de los archivos. Si el "value" de un alias está vacío (es

decir, ""), el alias será

borrado.

Sin embargo, un "name" determinado solo puede especificarse una vez en un único archivo de configuración. Alias

RIESGO DE USAR NOMBRES DE IMAGEN NO

CALIFICADOS

Recomendamos usar siempre nombres de imagen completamente calificados que incluyan el servidor de registro (nombre DNS completo), el espacio de nombres, el nombre de la imagen y la etiqueta (por ejemplo, registry.redhat.io/ubi8/ubi:latest). Al usar nombres cortos, siempre existe un riesgo inherente de que la imagen que se está extrayendo pueda ser falsificada. Por ejemplo, un usuario quiere extraer una imagen llamada foobar de un registro y espera que provenga de myregistry.com. Si myregistry.com no es el primero en la lista de búsqueda, un atacante podría colocar una imagen [[98]] foobar diferente en un registro anterior en la lista de búsqueda. El usuario extraería y ejecutaría accidentalmente la imagen y el código del atacante en lugar del contenido previsto. Recomendamos añadir solo registros en los que se confíe completamente, es decir, registros que no permitan a usuarios desconocidos o anónimos crear cuentas con nombres arbitrarios. Esto evitará que una imagen sea falsificada, secuestrada o hecha insegura de otra manera. Si es necesario usar uno de estos registros, debe añadirse al final de la

lista.

Se recomienda usar imágenes completamente calificadas paraulling como el registro de destino es inequívoco. La e

xtracción por digest (es decir, quay.io/repository/name
@digest) elimina aún más la ambigüedad de las etiquetas.
