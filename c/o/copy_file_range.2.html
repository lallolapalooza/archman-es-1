copy_file_range(2) Manual de llamadas al sistema copy_file_range(2)

NOMBRE

copy_file_range - Copia un rango de datos de un archivo a otro

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE
#define _FILE_OFFSET_BITS 64
#include <unistd.h>
ssize_t copy_file_range(int fd_in, off_t *_Nullable off_in,
                        int fd_out, off_t *_Nullable off_out,
                        size_t size, unsigned int flags);

DESCRIPCIÓN

La llamada al sistema copy_file_range() realiza una copia dentro del kernel entre dos descriptores de archivo sin el costo adicional de transferir datos del kernel al espacio de usuario y luego de vuelta al kernel. Copia hasta size bytes de datos desde el descriptor de archivo fuente fd_in al descriptor de archivo destino fd_out, sobrescribiendo cualquier dato que exista dentro del rango solicitado del archivo destino.

Las siguientes semánticas se aplican a off_in, y declaraciones similares se aplican a off_out:

•
Si off_in es NULL, entonces se leen bytes de fd_in a partir del desplazamiento del archivo, y el desplazamiento del archivo se ajusta por el número de bytes copiados.
•
Si off_in no es NULL, entonces off_in debe apuntar a un búfer que especifica el desplazamiento de inicio donde se leerán los bytes de fd_in. El desplazamiento del archivo de fd_in no se modifica, pero off_in se ajusta apropiadamente.

fd_in y fd_out pueden referirse al mismo archivo. Si se refieren al mismo archivo, entonces no se permite que los rangos de origen y destino se superpongan.

El argumento flags se proporciona para permitir extensiones futuras y actualmente debe establecerse en 0.

VALOR DE RETORNO

Al completarse con éxito, copy_file_range() devolverá el número de bytes copiados entre archivos. Esto podría ser menor que el tamaño solicitado originalmente. Si el desplazamiento del archivo de fd_in está en el final del archivo o más allá, no se copian bytes y copy_file_range() devuelve cero.

En caso de error, copy_file_range() devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
Uno o más descriptores de archivo no son válidos.
EBADF
fd_in no está abierto para lectura; o fd_out no está abierto para escritura.
EBADF
El flag O_APPEND está establecido para la descripción del archivo abierto (ver open(2)) al que se refiere el descriptor de archivo fd_out.
EFBIG
Se intentó escribir en una posición más allá del desplazamiento máximo del archivo que el kernel puede soportar.
EFBIG
Se intentó escribir un rango que excede el tamaño máximo de archivo permitido. El tamaño máximo de archivo difiere entre las implementaciones del sistema de archivos y puede ser diferente del desplazamiento máximo de archivo permitido.
EFBIG
Se intentó escribir más allá del límite de recursos de tamaño de archivo del proceso. Esto también puede hacer que el proceso reciba una señal SIGXFSZ.
EINVAL
El argumento flags no es 0.
EINVAL
fd_in y fd_out se refieren al mismo archivo y los rangos de origen y destino se superponen.
EINVAL
Ya sea fd_in o fd_out no es un archivo regular.
EIO
Ocurrió un error de E/S de bajo nivel durante la copia.
EISDIR
Ya sea fd_in o fd_out se refiere a un directorio.
ENOMEM
Sin memoria.
ENOSPC
No hay suficiente espacio en el sistema de archivos destino para completar la copia.
EOPNOTSUPP (desde Linux 5.19)
El sistema de archivos no soporta esta operación.
EOVERFLOW
El rango de origen o destino solicitado es demasiado grande para ser representado en los tipos de datos especificados.
EPERM
fd_out se refiere a un archivo inmutable.
ETXTBSY
Ya sea fd_in o fd_out se refiere a un archivo de swap activo.
EXDEV (antes de Linux 5.3)
Los archivos a los que se refieren fd_in y fd_out no están en el mismo sistema de archivos.
EXDEV (desde Linux 5.19)
Los archivos a los que se refieren fd_in y fd_out no están en el mismo sistema de archivos, y los sistemas de archivos de origen y destino no son del mismo tipo, o no soportan copias entre sistemas de archivos.

VERSIONES

Se realizó una refactorización importante de la implementación del kernel en Linux 5.3. Las áreas de la API que no estaban claramente definidas se aclararon y los límites de la API se verifican de manera mucho más estricta que en kernels anteriores.

Desde Linux 5.19, las copias entre sistemas de archivos se pueden lograr cuando ambos sistemas de archivos son del mismo tipo, y ese sistema de archivos implementa soporte para ello. Consulte BUGS para ver el comportamiento anterior a Linux 5.19.

Las aplicaciones deben apuntar al comportamiento y los requisitos de Linux 5.19, que también se incluyeron en versiones estables anteriores del kernel.

ESTANDARES

Linux, GNU.

HISTORIA

Linux 4.5, pero glibc 2.27 proporciona una emulación en el espacio de usuario cuando no está disponible.

NOTAS

Si fd_in es un archivo disperso (sparse file), entonces copy_file_range() puede expandir cualquier agujero existente en el rango solicitado. Los usuarios pueden beneficiarse de llamar a copy_file_range() en un bucle, y usar las operaciones lseek(2) SEEK_DATA y SEEK_HOLE para encontrar las ubicaciones de los segmentos de datos.

copy_file_range() brinda a los sistemas de archivos una oportunidad de implementar técnicas de "aceleración de copia", como el uso de reflinks (es decir, dos o más inodos que comparten punteros a los mismos bloques de disco copy-on-write) o copia del lado del servidor (en el caso de NFS).

_FILE_OFFSET_BITS debe definirse como 64 en el código que utiliza off_in u off_out no nulos o que toma la dirección de copy_file_range, si el código está destinado a ser portable a plataformas x86 y ARM de 32 bits tradicionales donde el ancho de off_t tiene un valor predeterminado de 32 bits.

BUGS

En Linux 5.3 a Linux 5.18, las copias entre sistemas de archivos se implementaron en el kernel, si la operación no era soportada por sistemas de archivos individuales. Sin embargo, en algunos sistemas de archivos virtuales, la llamada falló al copiar, a pesar de informar éxito.

copy_file_range(2) - Arch Linux man pages

NAME

copy_file_range - Copiar datos entre dos descriptores de archivo

LIBRARY

Biblioteca C estándar (libc, -lc)

SYNOPSIS

#include <fcntl.h>

ssize_t copy_file_range(int fd_in, off64_t *off_in, int fd_out, off64_t *off_out, size_t len, unsigned int flags);

DESCRIPTION

La llamada al sistema copy_file_range copia hasta len bytes de datos de un rango en el archivo especificado por fd_in a un rango en el archivo especificado por fd_out. El rango de origen se especifica por el valor al que apunta off_in, y el rango de destino se especifica por el valor al que apunta off_out.

Si off_in es NULL, la copia comienza en la posición actual del puntero de archivo en fd_in. Si off_out es NULL, la copia comienza en la posición actual del puntero de archivo en fd_out.

Si off_in no es NULL, el puntero de archivo en fd_in no se modifica después de la llamada. Si off_in es NULL, el puntero de archivo en fd_in se actualiza para reflejar el número de bytes leídos.

Si off_out no es NULL, el puntero de archivo en fd_out no se modifica después de la llamada. Si off_out es NULL, el puntero de archivo en fd_out se actualiza para reflejar el número de bytes escritos.

El argumento flags actualmente no se utiliza y debe establecerse en 0.

Si off_in y off_out son NULL, los descriptores de archivo deben ser capaces de buscar (es decir, no ser un descriptor de archivo de tubería).

Los archivos de origen y destino deben ser del mismo tipo de sistema de archivos. Si son diferentes, se devuelve un error EXDEV.

El comportamiento de copy_file_range cuando los archivos de origen y destino se superponen no está definido.

El número de bytes copiados puede ser menor que len. Esto puede ocurrir si se alcanza el final del archivo de origen antes de que se copien len bytes, o si se interrumpe una llamada al sistema por una señal.

Si se utiliza la operación copy_file_range entre dos archivos en el mismo sistema de archivos, es posible que el kernel la optimice para evitar la copia de datos en el espacio de usuario y, en su lugar, realice la copia a nivel de kernel. Esto puede resultar en una operación mucho más rápida.

RETURN VALUE

En caso de éxito, copy_file_range devuelve el número de bytes copiados. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORS

EAGAIN, EWOULDBLOCK
No se pudieron reservar recursos suficientes para realizar la operación.
EBADF
fd_in o fd_out no es un descriptor de archivo válido.
EFBIG
Se escribió más allá del tamaño permitido del archivo de destino.
EINTR
La operación fue interrumpida por una señal antes de que se hubieran copiado bytes.
EINVAL
len es 0, o flags contiene un valor no válido.
EISDIR
Uno de los descriptores de archivo especifica un directorio.
EMFILE
Se ha abierto demasiados descriptores de archivo en el proceso.
ENOSPC
No hay espacio en el dispositivo para escribir los datos.
ENOTDIR
fd_in o fd_out se refiere a un descriptor de archivo en un directorio.
ENOTSUP
La operación no es compatible con los sistemas de archivos subyacentes.
EOVERFLOW
Se ha producido un desbordamiento de archivo.
EROFS
El archivo de destino es de solo lectura.
SDK
Se intentó copiar entre dos sistemas de archivos diferentes.
SYMLINK
Se encontró un enlace simbólico de forma recursiva.
UNKNOWN_LIBC
Error desconocido.

VERSIONS

La llamada al sistema copy_file_range se introdujo en el kernel de Linux 4.5.

STANDARDS

Esta llamada al sistema es específica de Linux.

HISTORY

La llamada al sistema copy_file_range fue implementada por Dave Kleikomb.

NOTES

Para copiar archivos, considere usar sendfile, que está optimizado para transferencias de red, o splice, que puede usarse para mover datos entre descriptores de archivo y tuberías.

La operación copy_file_range es idempotente si los punteros de archivo no se mueven. Si se llama varias veces con los mismos argumentos, se copiarán los mismos datos una y otra vez.

Esta función es útil para implementar operaciones de copia de archivos eficientes sin necesidad de montar un sistema de archivos. Por ejemplo, se puede usar para copiar archivos entre diferentes particiones o discos.

BUGS

No se conocen errores en la implementación actual.

EXAMPLES

El siguiente programa copia el contenido de un archivo a otro:

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <unistd.h>

int main(int argc, char *argv[]) {
    int fd_in, fd_out;
    struct stat stat;
    off_t size;
    ssize_t ret;

    if (argc != 3) {
        fprintf(stderr, "Uso: %s <origen> <destino>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    fd_in = open(argv[1], O_RDONLY);
    if (fd_in == -1) {
        perror("open (argv[1])");
        exit(EXIT_FAILURE);
    }

    if (fstat(fd_in, &stat) == -1) {
        perror("fstat");
        exit(EXIT_FAILURE);
    }
    size = stat.st_size;

    fd_out = open(argv[2], O_CREAT | O_WRONLY | O_TRUNC, 0644);
    if (fd_out == -1) {
        perror("open (argv[2])");
        exit(EXIT_FAILURE);
    }

    do {
        ret = copy_file_range(fd_in, NULL, fd_out, NULL, size, 0);
        if (ret == -1) {
            perror("copy_file_range");
            exit(EXIT_FAILURE);
        }
        size -= ret;
    } while (size > 0 && ret > 0);

    close(fd_in);
    close(fd_out);

    exit(EXIT_SUCCESS);
}
