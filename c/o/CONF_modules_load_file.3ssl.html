DESCRIPCIÓ

N

La función CONF_get1_default_config_file() determina la ruta de nombre de archivo de configuración predeterminada de la siguiente manera. Si la variable de entorno OPENSSL_CONF está establecida, se devuelve su valor. De lo contrario, la función devuelve la ruta obtenida usando X509_get_default_cert_area(3) con el nombre de archivo "openssl.cnf" añadido. El llamador es responsable de liberar cualquier cadena

devuelta.

La función CONF_modules_load_file_ex() configura OpenSSL usando el contexto de biblioteca libctx, el archivo filename y el nombre de aplicación appname. Si filename es NULL, se usa el archivo de configuración estándar de OpenSSL determinado al llamar a CONF_get1_default_config_file(). Si appname es NULL, se usa el nombre de aplicación estándar de OpenSSL openssl_conf. El comportamiento se puede personalizar usando flags. Tenga en cuenta que la supresión de errores se puede anular con config_diagnostics como se describe en config(

5).

CONF_modules_load_file() es lo mismo que CONF_modules_load_file_ex() pero tiene un contexto de biblioteca

NULL.

CONF_modules_load() es idéntico a CONF_modules_load_file() excepto que lee la información de configuración desde cn

f
.

NOTA

S

Actualmente se reconocen los siguientes flags

:

Si CONF_MFLAGS_IGNORE_ERRORS está establecido, se ignoran los errores devueltos por módulos de configuración individuales. Si no está establecido, el primer error de módulo se considera fatal y no se cargan más

módulos.

Normalmente, cualquier error de módulos añadirá información de error a la cola de errores. Si CONF_MFLAGS_SILENT está establecido, no se añade información de

error.

Si CONF_MFLAGS_IGNORE_RETURN_CODES está establecido, la función devuelve éxito incondicionalmente. Esto se usa de forma predeterminada en OPENSSL_init_crypto(3) para ignorar cualquier error en el archivo de configuración predeterminado del sistema, ya que es demasiado arriesgado que todas las aplicaciones OpenSSL fallen al iniciar cuando hay problemas potencialmente menores en el archivo. Las aplicaciones que llaman a CONF_modules_load_file_ex explícitamente generalmente no deben establecer este

flag.

Si CONF_MFLAGS_NO_DSO está establecido, se deshabilita la carga de módulos de configuración desde

DSOs.

CONF_MFLAGS_IGNORE_MISSING_FILE, si está establecido, hará que CONF_load_modules_file() ignore los archivos de configuración faltantes. Normalmente, un archivo de configuración faltante devuelve un

error.

CONF_MFLAGS_DEFAULT_SECTION, si está establecido y appname no es NULL, usará la sección predeterminada a la que apunta openssl_conf si appname no

existe.

Al usar CONF_modules_load_file_ex() con flags apropiados, una aplicación puede personalizar la configuración de la aplicación para que se adapte mejor a sus necesidades. En algunos casos, el uso de un archivo de configuración es opcional y su ausencia no es un error: en este caso CONF_MFLAGS_IGNORE_MISSING_FILE se

establecería.

Los errores durante la configuración también pueden ser manejados de manera diferente por diferentes aplicaciones. Por ejemplo, en algunos casos un error simplemente puede imprimir un mensaje de advertencia y la aplicación continúa. En otros casos, una aplicación podría considerar un error en el archivo de configuración como fatal y salir

inmediatamente.

Las aplicaciones pueden usar la función CONF_modules_load() si desean cargar un archivo de configuración por s

í mismas y tener un control más fino
sobre cómo se tratan los errores.

VALOR DE

RETORNO

Estas funciones devuelven 1 para éxito y un valor cero o negativo para fallo.

Si los errores de los módulos no se ignoran, el código de retorno reflejará
el valor de retorno del módulo que falló (esto siempre será cero o negativo).

EJEMPLO

S

Cargar un archivo de configuración e imprimir cualquier error y salir (archivo faltante considerado fatal)

: 
if (CONF_modules_load_file_ex(libctx, NULL, NULL, 0) <= 0) {
    fprintf(stderr, "FATAL: error loading configuration file\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}

Cargar el archivo de configuración predeterminado usando la sección indicada por "myapp", tolerar archivos faltantes, pero salir en otros

errores: 
if (CONF_modules_load_file_ex(NULL, NULL, "myapp",
                              CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
    fprintf(stderr, "FATAL: error loading configuration file\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}

Cargar un archivo de configuración y sección personalizados, solo imprimir advertencias en caso de error, ignorar archivo de configuración

faltante: 
if (CONF_modules_load_file_ex(NULL, "/something/app.cnf", "myapp",
                              CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
    fprintf(stderr, "WARNING: error loading configuration file\n");
    ERR_print_errors_fp(stderr);
}

Cargar y analizar el archivo de configuración manualmente, manejo personalizado de

errores: 
FILE *fp;
CONF *cnf = NULL;
long eline;
fp = fopen("/somepath/app.cnf", "r");
if (fp == NULL) {
    fprintf(stderr, "Error opening configuration file\n");
    /* Other missing configuration file behaviour */
} else {
    cnf = NCONF_new_ex(libctx, NULL);
    if (NCONF_load_fp(cnf, fp, &eline) == 0) {
        fprintf(stderr, "Error on line %ld of configuration file\n", eline);
        ERR_print_errors_fp(stderr);
        /* Other malformed configuration file behaviour */
    } else if (CONF_modules_load(cnf, "appname", 0) <= 0) {
        fprintf(stderr, "Error configuring application\n");
        ERR_print_errors_fp(stderr);
        /* Other configuration error behaviour */
    }
    fclose(fp);
    NCONF_free(cnf);
}
