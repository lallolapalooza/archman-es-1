DESCRIPCIÓ

N

"Config::Tiny" es una clase de Perl para leer y escribir archivos de configuración de estilo .ini con el menor código posible, reduciendo el tiempo de carga y la sobrecarga de

memoria.

La mayoría de las veces se acepta que las aplicaciones de Perl usan mucha memoria y

módulos.

La familia de módulos *::Tiny está específicamente destinada a proporcionar una alternativa ultraligera a los módulos

estándar.

Este módulo está diseñado principalmente para leer archivos escritos por humanos, y cualquier cosa que escribamos no debería necesitar tener documentación/comentarios. Si necesitas algo con más potencia, pasa a Config::Simple, Config::General o uno de los muchos otros módulos "Config::

*".

Por último, Config::Tiny no conserva tus comentarios, espacios en blanco, ni el orden de tu archivo de

configuración.

Consulta Config::Tiny::Ordered (y posi

blemente otros) para la conservación de
l orden de las entradas en el archivo.

SINTAXIS DEL ARCHIVO DE

CONFIGURACIÓN

Los archivos tienen el mismo formato que los archivos "*.ini" de MS Windows. Por

ejemplo: 
[section]
var1=value1
var2=value2

Pero consulta también SINTAXIS DE ARREGLO justo

debajo.

Si una propiedad está fuera de una sección al principio de un archivo, se asignará a la "sección raíz", disponible en "$Config->{_}

".

Las líneas que comienzan con '#' o ';' se consideran comentarios y se ignoran, al igual que las líneas en

blanco.

Al escribir de vuelta en el archivo de configuración, todos los comentarios, los espacios en blanco personali

zados y el orden de los elementos de tu archivo de configuración se descartan. Si necesitas conservar los ele
mentos humanos de una configuración al escribir de vuelta, actualiza a algo mejor, este módulo no es para ti.

SINTAXIS DE

ARREGLO

Sintaxis

básica

A partir de la versión 2.30, este módulo soporta el caso de una clave que tiene un arreglo de

valores.

Datos de ejemplo (copiados de t/test.conf)

: 
root=something
[section]
greetings[]=Hello
one=two
Foo=Bar
greetings[]=World!
this=Your Mother!
blank=
[Section Two]
something else=blah
 remove =
whitespace

Observa específicamente que el nombre de la clave greetings tiene el par de corchetes vacíos [] como sufijo. Esto le indica al código que no debe sobrescribir el 1er valor con el 2do valor, sino empujar estos valores a una pila llamada

'greetings'.

Observa también que podrías haber

usado: 
[section]
greetings[]=Hello
greetings[]=World!
one=two
Foo=Bar
this=Your Mother!
blank=

Claramente, las 2 líneas que usan greetings[] no tienen que estar una al lado de la

otra.

Si usas, por ejemplo, Data::Dumper::Concise para darte una función (no método) Dumper(), entonces 'say Dumper($Config)' la salida se verá

así: 
bless( {
  "Section Two" => {
     remove => "whitespace",
     "something else" => "blah",
   },
   _ => {
     root => "something",
   },
   section => {
     Foo => "Bar",
     blank => "",
     greetings => [
       "Hello",
       "World!",
     ],
     one => "two",
     this => "Your Mother!",
   },
 }, 'Config::Tiny'
)

Puedes ver esta estructura en t/02.main.t a partir de la línea 45. Observa también que los nombres de las claves se reportan en orden alfabético (por el módulo Data::Dumper::Concise) a pesar del orden diferente en la configuración de estas claves, y que el resultado de la sintaxis de arreglo es que greetings tiene un arreglo como

valor.

Para acceder a estos valores, usa código como

este: 
Dumper($Config);
Dumper($Config->{section});
Dumper($Config->{sect
ion}->{greetings}); Dumper($Config->{section}->{greetings}->[0]);
Dumper($Config->{section}->{greetings}->[1]); Dumper(ref $Config);

Advertenci

a

$Config es un valor bendecido (blessed), lo que significa que se accede de manera diferente a si fuera una referencia a hash. La última podría accederse

como: 
Dumper($$Config{section}{greetings}); # ¡No hagas esto para valores
bendecidos!

Finalmente, si es una referencia a hash en lugar de un valor bendecido, también podrías usar, como

arriba: 
Dumper($Config->{section}->{greetings}); # ¡No hagas esto para valores
bendecidos!

Mi (Ron Savage) preferencia personal para las refe

rencias a hash es la que no tiene los feos caracte
res '->', pero eso requiere que dupliques el carác
ter inicial $ (¡lo cual espero que hayas notado!).

También puedes recuperar el mensaje de error desde la variable $Config

new([$config]

)

Aquí, los [] indican un parámetro

opcional.

El constructor "new" crea y devuelve un objeto "Config::

Tiny".

Esto normalmente será una configuración nueva y vacía, pero también puedes pasar aquí una referencia a hash que será convertida en un objeto de esta clase. Esta referencia a hash debe tener una estructura adecuada para un archivo de configuración, es decir, un hash de hashes donde la clave "_" se trata de manera esp

ecial como la
sección raíz.

read($filename, [$encoding]

)

Aquí, los [] indican un parámetro

opcional.

El constructor "read" lee un archivo de configuración, $filename, y devuelve un nuevo objeto "Config::Tiny" que contiene las propiedades en el

archivo.

$encoding puede usarse para indicar la codificación del archivo, por ejemplo 'utf8' o 'encoding(iso-8859-1)

'.

No añadas un prefijo a $encoding, como '<' o '<:

'.

Devuelve el objeto en caso de éxito, o "undef" en caso de

error.

Cuando "read" falla, "Config::Tiny" establece un mensaje de error internamente que puedes recuperar vía "Config::Tiny->errstr". Aunque en algunos casos un "read" fallido también establecerá la variable de error del sistema operativo $!, no todos los errores lo hacen y no deberías confiar en usar la variable $!

.

Consulta t/0

4.utf8.t y t/
04.utf8.txt.

ADVERTENCI

AS

Algunos casos límite en los encabezados de sección no están soportados y, además, pueden no detectarse al escribir el archivo de

configuración.

Específicamente, los encabezados de sección con espacios iniciales, espac

ios finales o saltos de línea en cualquier parte del encabezado, no se esc
ribirán correctamente en el archivo y pueden causar corrupción del mismo.
