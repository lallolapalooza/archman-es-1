Descripción

detallada

Las clases de elementos en Coin son los contenedores de la información de estado durante los recorridos de acciones de los grafos de

escena.

Un elemento generalmente corresponde a un elemento de información, o a veces a un grupo de valores de información relacionados. Los elementos funcionan como una pila que se apila y se desapila a medida que la acción entra y sale de los nodos SoSeparator, y la acción siempre inspeccionará solo la parte superior de la pila cuando necesite conocer un

valor.

Los elementos son detalles de implementación internos del funcionamiento de los nodos y las acciones, y no es algo de lo que haya que preocuparse antes de escribir sus propios nodos de extensión. Escribir elementos de extensión está aún más alejado del uso común de Open Inventor, pero es totalmente posible para el desarrollador experimentado de Open Inventor. Las clases de

elementos

Los elementos son en su mayoría internos de Coin, a menos que cree nuevos nodos de extensión sobre Coin. En ese caso, probablemente necesitará conocerlos.
Los elementos son parte del diseño del recorrido del grafo de escena en Coin.
Funciona así: cualquier acción de recorrido instancia y mantiene una única instancia de SoState durante el recorrido. La instancia de SoState utiliza objetos SoElement como "unidades de memoria" para llevar un registro de el estado actual de cualquier característica de los nodos del grafo de escena.
Como ejemplo, considere el nodo SoPointSize: cuando el nodo SoPointSize es recorrido por, por ejemplo, una SoGLRenderAction, empujará un SoPointSizeElement a la pila SoState de la SoGLRenderAction. Más tarde, cuando un nodo SoPointSet aparece en el grafo de escena, solicitará el valor actual del tamaño del punto a la SoState leyendo el valor de su SoPointSizeElement.
Los nodos SoSeparator empujan y desempujan elementos de la pila de estado, por lo que cualquier cosa que cambie el estado debajo de un nodo SoSeparator no influirá en nada por encima del SoSeparator

.

Para obtener más información sobre los fundamentos teóricos de este diseño de recorrido, debería considerar leer la literatura disponible sobre el llamado "patrón Visitor". Recomendamos "Design Patterns", de Gamma, Helm, Johnson, Vlissides (también conocido como el "Gang Of Four"). Este libro utiliza de hecho el mecanismo de recorrido de la API de Inventor como estudio de caso para explicar el patrón Visitor.
Para extender la biblioteca Coin con sus propias clases, le recomendamos encarecidamente que se familiarice con el excelente libro The Inventor Toolmaker (ISBN 0-201-62493-1), que describe las tareas involucradas en detalle. Este libro fue escrito por los diseñadores originales de Inventor de SGI y explica muchas de las ideas de diseño subyacentes, además de tener muchos ejemplos prácticos sobre cómo extender el conjunto de herramientas Coin de maneras que son fieles a las ideas de diseño fundamentales. (The Inventor Toolmaker también está disponible en la biblioteca en línea de SGI, sin costo. Vea Descargar The Inventor Toolmaker.) Leer el código fuente de las clases incorporadas en Coin también debería resultar muy

útil.

Y una pequeña aplicación de prueba independiente que pone en uso el nuevo

elemento: 
// [lstextures.cpp]
//
// El propósito de este archivo es crear una pequeña "herramienta" envolvente
// alrededor del elemento de extensión TextureFilenameElement, solo para
// mostrar código de ejemplo sobre cómo hacer uso de un elemento personalizado
// definido por el usuario.
//
// El código es el siguiente:
//
// Inicializamos el elemento, lo habilitamos para la SoCallbackAction, leemos
// un archivo de grafo de escena, establecemos callbacks en SoTexture2 y todos
// los nodos de forma, y aplicamos la SoCallbackAction. Los callbacks imprimirán
// entonces la información del nombre de archivo de la textura desde el
// TextureFilenameElement cada vez que se encuentre un nodo interesante.
//
//
// Código por Peder Blekken <pederb@sim.no>. Limpio, integrado en la
// distribución de Coin y comentado por Morten Eriksen
// <mortene@sim.no>. Copyright (C) Kongsberg Oil & Gas Technologies.
#include <Inventor/SoDB.h>
#include <Inventor/SoInput.h>
#include <Inventor/actions/SoCallbackAction.h>
#include <Inventor/nodes/SoSeparator.h>
#include <Inventor/nodes/SoTexture2.h>
#include <Inventor/nodes/SoShape.h>
#include <Inventor/misc/SoState.h>
#include <cstdio>
#include "texturefilenameelement.h"
SoCallbackAction::Response
pre_tex2_cb(void * data, SoCallbackAction * action, const SoNode * node)
{
  const SbString & filename = ((SoTexture2 *)node)->filename.getValue();
  TextureFilenameElement::set(action->getState(), (SoNode *)node, filename);
  (void)fprintf(stdout, "=> New texture: %s\n",
                filename.getLength() == 0 ?
                "<inlined>" : filename.getString());
  return SoCallbackAction::CONTINUE;
}
SoCallbackAction::Response
pre_shape_cb(void * data, SoCallbackAction * action, const SoNode * node)
{
  const SbString & filename =
    TextureFilenameElement::get(action->getState());
  (void)fprintf(stdout, "   Texturemap on %s: %s\n",
                node->getTypeId().getName().getString(),
                filename.getLength() == 0 ?
                "<inlined>" : filename.getString());
  return SoCallbackAction::CONTINUE;
}
void
usage(const char * appname)
{
  (void)fprintf(stderr, "\n\tUso: %s <modelfile.iv>\n\n", appname);
  (void)fprintf(stderr,
                "\tLista todos los nombres de archivo de textura en el archivo de modelo,\n"
                "\ty en qué nodos de forma se utilizan.\n\n"
                "\tEl propósito de esta utilidad de ejemplo es simplemente\n"
                "\tmostrar cómo crear y usar un elemento de extensión para\n"
                "\tel recorrido del grafo de escena.\n\n");
}
int
main(int argc, char ** argv)
{
  if (argc != 2) {
    usage(argv[0]);
    exit(1);
  }
  SoDB::init();
  TextureFilenameElement::initClass();
  SO_ENABLE(SoCallbackAction, TextureFilenameElement);
  SoInput input;
  if (!input.openFile(argv[1])) {
    (void)fprintf(stderr, "ERROR: no se pudo abrir el archivo \"%s\".\n", argv[1]);
    exit(1);
  }
  SoSeparator * root = SoDB::readAll(&input);
  if (root) {
    root->ref();
    SoCallbackAction cbaction;
    cbaction.addPreCallback(SoTexture2::getClassTypeId(), pre_tex2_cb, NULL);
    cbaction.addPreCallback(SoShape::getClassTypeId(), pre_shape_cb, NULL);
    cbaction.apply(root);
    root->unref();
    return 0;
  }
  return 1;
}
