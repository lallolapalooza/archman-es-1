/etc/containerd/config.toml(5) Manual de formatos de archivo /etc/containerd/config.toml(5)

NOMBRE

containerd-config.toml - archivo de configuración para containerd

SINOPSIS

El archivo config.toml es un archivo de configuración para el demonio containerd. El archivo debe colocarse en /etc/containerd/config.toml o especificarse con la opción --config de containerd para ser utilizado por el demonio. Si el archivo no existe en la ubicación apropiada o no se proporciona a través de la opción --config, containerd utiliza sus ajustes de configuración predeterminados, que se pueden mostrar con el comando containerd config(1).

DESCRIPCIÓN

El archivo TOML utilizado para configurar los ajustes del demonio containerd tiene una breve lista de ajustes globales seguida de una serie de secciones para áreas específicas de la configuración del demonio. También hay una sección para plugins que permite que cada plugin de containerd tenga un área para configuración y ajustes específicos del plugin.

FORMATO

version
El campo version en el archivo de configuración especifica la versión de la configuración. Si no se especifica ningún número de versión dentro del archivo de configuración, se asume que es una configuración de versión 1 y se analiza como tal. Por favor, use version = 2 para habilitar la configuración de versión 2, ya que la versión 1 ha sido obsoleta.
root
El directorio raíz para la metadatos de containerd. (Predeterminado: "/var/lib/containerd")
state
El directorio de estado para containerd (Predeterminado: "/run/containerd")
plugin_dir
El directorio para que se almacenen los plugins dinámicos
[grpc]
Sección para los ajustes del escuchador de sockets gRPC. Contiene las siguientes propiedades:
  • address (Predeterminado: "/run/containerd/containerd.sock")
  • tcp_address
  • tcp_tls_cert
  • tcp_tls_key
  • uid (Predeterminado: 0)
  • gid (Predeterminado: 0)
  • max_recv_message_size
  • max_send_message_size
[ttrpc]
Sección para ajustes de TTRPC. Contiene las propiedades:
  • address (Predeterminado: "")
  • uid (Predeterminado: 0)
  • gid (Predeterminado: 0)
[debug]
Sección para habilitar y configurar un escuchador de socket de depuración. Contiene cuatro propiedades:
  • address (Predeterminado: "/run/containerd/debug.sock")
  • uid (Predeterminado: 0)
  • gid (Predeterminado: 0)
  • level (Predeterminado: "info") establece el nivel de registro de depuración. Los niveles admitidos son: "trace", "debug", "info", "warn", "error", "fatal", "panic"
  • format (Predeterminado: "text") establece el formato de registro. Los formatos admitidos son "text" y "json"
[metrics]
Sección para habilitar y configurar un escuchador de métricas. Contiene dos propiedades:
  • address (Predeterminado: "") El punto final de métricas no escucha por defecto
  • grpc_histogram (Predeterminado: false) Activa o desactiva las métricas de histograma gRPC
disabled_plugins
Los plugins deshabilitados son los IDs de los plugins que se deben deshabilitar. Los plugins deshabilitados no se inicializarán ni se iniciarán.
required_plugins
Los plugins requeridos son los IDs de los plugins necesarios. Containerd sale si algún plugin requerido no existe o falla al inicializarse o iniciarse.
[plugins]
La sección de plugins contiene opciones de configuración expuestas por los plugins instalados. Los siguientes plugins están habilitados por defecto y sus ajustes se muestran a continuación. Los plugins que no están habilitados por defecto proporcionarán su propia documentación de valores de configuración.
  • [plugins."io.containerd.monitor.v1.cgroups"] tiene una opción no_prometheus (Predeterminado: false)
  • [plugins."io.containerd.service.v1.diff-service"] tiene una opción default, una lista por defecto establecida en ["walking"]
  • [plugins."io.containerd.gc.v1.scheduler"] tiene varias opciones que realizan ajustes avanzados para el programador:
  • pause_threshold es la cantidad máxima de tiempo que debe programarse la GC (Predeterminado: 0.02),
  • deletion_threshold garantiza que la GC se programe después de n número de eliminaciones (Predeterminado: 0 [no activado]),
  • mutation_threshold garantiza que la GC se programe después de n número de mutaciones de base de datos (Predeterminado: 100),
  • schedule_delay define el retraso después del evento de activación antes de programar una GC (Predeterminado "0ms" [inmediato]),
  • startup_delay define el retraso después del inicio antes de programar una GC (Predeterminado "100ms")
•
[plugins."io.containerd.runtime.v2.task"] especifica opciones para configurar el shim de tiempo de ejecución:
  • platforms especifica la lista de plataformas admitidas
  • sched_core La programación de núcleos es una característica que permite que solo las tareas confiables se ejecuten concurrentemente en CPUs que comparten recursos de cómputo (por ejemplo, hyperthreads en un núcleo). (Predeterminado: false)
•
[plugins."io.containerd.service.v1.tasks-service"] tiene opciones de rendimiento:
  • blockio_config_file (solo Linux) especifica la ruta a las definiciones de clase de blockio (Predeterminado: ""). Controla la prioridad del planificador de E/S y la limitación del ancho de banda. Consulte la configuración de blockio ⟨https://github.com/intel/goresctrl/blob/main/doc/blockio.md#configuration⟩ para conocer los detalles del formato del archivo.
  • rdt_config_file (solo Linux) especifica la ruta a una configuración utilizada para configurar RDT (Predeterminado: ""). Habilita el soporte para Intel RDT, una tecnología para la gestión del ancho de banda de caché y memoria. Consulte la configuración de RDT ⟨https://github.com/intel/goresctrl/blob/main/doc/rdt.md#configuration⟩ para conocer los detalles del formato del archivo.
•
[plugins."io.containerd.grpc.v1.cri".containerd] contiene opciones para el plugin CRI y nodos secundarios para opciones de CRI:
•
default_runtime_name (Predeterminado: "runc") especifica el nombre de tiempo de ejecución predeterminado
  • [plugins."io.containerd.grpc.v1.cri".containerd.runtimes] uno o más tiempos de ejecución de contenedores, cada uno con un nombre único
  • [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.] un tiempo de ejecución llamado <runtime>
  • [plugins."io.containerd.grpc.v1.cri".containerd.runtimes..options] opciones para el <runtime> con nombre, lo más importante:
•
BinaryName especifica la ruta al tiempo de ejecución real que será invocado por el shim, por ejemplo, "/usr/bin/runc"
oom_score
La puntuación de "out of memory" (OOM) aplicada al proceso del demonio containerd (Predeterminado: 0)
[cgroup]
Sección para ajustes específicos de cgroup de Linux
•
path (Predeterminado: "") Especifica una ruta de cgroup personalizada para los contenedores creados
[proxy_plugins]
Los plugins proxy configuran plugins con los que se comunica a través de gRPC
  • type (Predeterminado: "")
  • address (Predeterminado: "")
time
Los tiempos de espera en segundos para varios eventos de containerd (Predeterminado: 0, que significa ilimitado). Tiempos de espera disponibles:
  • container_create
  • container_delete
  • container_start
  • container_stop
  • container_kill
  • container_pause
  • container_resume
  • image_pull
  • image_remove
  • image_list
  • mount_create
  • mount_delete
  • snapshot_list
  • snapshot_create
  • snapshot_remove
  • snapshot_view
  • content_read
  • content_write
  • content_digest
  • content_copy
  • task_create
  • task_delete
  • task_exec_start
  • task_start
  • task_stop
  • task_kill
  • task_pause
  • task_resume
  • task_check
  • task_list
  • gc_run

CONFIGURACIÓN DE LA NUBE DE PROVEEDORES

containerd se puede configurar para registrarse con un servicio de nube de proveedores. Esto permite que containerd obtenga información de configuración de un servicio externo. Por ejemplo, puede usar esto para obtener una configuración de red o de almacenamiento personalizada de un proveedor de nube específico.

Los ajustes de la nube de proveedores se encuentran en la sección [providers.cloud].

[providers.cloud]
  # La dirección del servicio de nube de proveedores.
  address = ""

El campo address especifica la dirección del servicio de nube de proveedores. Si este campo está vacío, la nube de proveedores está deshabilitada.

Cuando la nube de proveedores está habilitada, containerd intenta conectarse al servicio de nube de proveedores especificado y obtener la información de configuración. La información de configuración específica obtenida del servicio de nube de proveedores dependerá de la implementación del servicio.

VER EJEMPLO

Los usuarios pueden ejecutar containerd config(1) para ver un ejemplo de archivo de configuración con todos los ajustes disponibles y sus valores predeterminados.

salidas
Tiempos de espera especificados como una duración
imports
Imports es una lista de archivos de configuración adicionales a incluir. Esto permite dividir el archivo de configuración principal y mantener algunas secciones por separado (por ejemplo, los proveedores pueden mantener una configuración de ejecución personalizada en un archivo separado sin modificar el principal config.toml). Los archivos importados sobrescribirán campos simples como int o string (si no están vacíos) y añadirán array y map campos. Los archivos importados también están versionados, y la versión no puede ser mayor que la de la configuración principal.

stream_processors

  • acepta (Predeterminado: "[]") Acepta tipos de medios específicos
  • devuelve (Predeterminado: "") Devuelve el tipo de medio
  • path (Predeterminado: "") Ruta o nombre del binario
  • args (Predeterminado: "[]") Argumentos para el binario

EJEMPLOS

Configuración Completa

El siguiente es un ejemplo de configuración config.toml predeterminada completa:

version = 2
root = "/var/lib/containerd"
state = "/run/containerd"
oom_score = 0
imports = ["/etc/containerd/runtime_*.toml", "./debug.toml"]
[grpc]
  address = "/run/containerd/containerd.sock"
  uid = 0
  gid = 0
[debug]
  address = "/run/containerd/debug.sock"
  uid = 0
  gid = 0
  level = "info"
[metrics]
  address = ""
  grpc_histogram = false
[cgroup]
  path = ""
[plugins]
  [plugins."io.containerd.monitor.v1.cgroups"]
    no_prometheus = false
  [plugins."io.containerd.service.v1.diff-service"]
    default = ["walking"]
  [plugins."io.containerd.gc.v1.scheduler"]
    pause_threshold = 0.02
    deletion_threshold = 0
    mutation_threshold = 100
    schedule_delay = 0
    startup_delay = "100ms"
  [plugins."io.containerd.runtime.v2.task"]
    platforms = ["linux/amd64"]
    sched_core = true
  [plugins."io.containerd.service.v1.tasks-service"]
    blockio_config_file = ""
    rdt_config_file = ""

Múltiples Entornos de ejecución

El siguiente es un ejemplo de configuración parcial con dos entornos de ejecución:

[plugins]
  [plugins."io.containerd.grpc.v1.cri"]
    [plugins."io.containerd.grpc.v1.cri".containerd]
      default_runtime_name = "runc"
      [plugins."io.containerd.grpc.v1.cri".containerd.runtimes]
        [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]
          privileged_without_host_devices = false
          runtime_type = "io.containerd.runc.v2"
          [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc.options]
            BinaryName = "/usr/bin/runc"
        [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.other]
          privileged_without_host_devices = false
          runtime_type = "io.containerd.runc.v2"
          [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.other.options]
            BinaryName = "/usr/bin/path-to-runtime"

Lo anterior crea dos configuraciones de entorno de ejecución con nombre - denominadas runc y other - y establece el entorno de ejecución predeterminado como runc. Lo anterior se usa únicamente para entornos de ejecución invocados a través de CRI. Para usar el entorno de ejecución no predeterminado "other" en este ejemplo, una especificación incluirá el manejador de entorno de ejecución denominado "other" para especificar el deseo de usar la configuración de entorno de ejecución con nombre.

La especificación CRI incluye un ⟨https://github.com/kubernetes/cri-api/blob/de5f1318aede866435308f39cb432618a15f104e/pkg/apis/runtime/v1/api.proto#L476⟩, que hará referencia al entorno de ejecución con nombre.

Es importante tener en cuenta la convención de nombres. Los entornos de ejecución están bajo [plugins."io.containerd.grpc.v1.cri".containerd.runtimes], con cada entorno de ejecución dado un nombre único, por ejemplo [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]. Además, cada entorno de ejecución puede tener opciones específicas del shim bajo [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.<runtime>.options], por ejemplo, [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc.options].

El io.containerd.runc.v2 entorno de ejecución se usa para ejecutar entornos de ejecución compatibles con OCI en Linux, como runc. En el ejemplo anterior, el runtime_type campo especifica el shim a usar (io.containerd.runc.v2) mientras que el BinaryName campo es una opción específica del shim que especifica la ruta al entorno de ejecución OCI.

Para la configuración de ejemplo denominada "runc", el shim lanzará /usr/bin/runc como el entorno de ejecución OCI. Para la configuración de ejemplo denominada "other", el shim lanzará /usr/bin/path-to-runtime en su lugar.
