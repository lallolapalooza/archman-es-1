containers-auth.json(5) Manual de formatos de archivo containers-auth.json(5)

NOMBRE

containers-auth.json - sintaxis del archivo de autenticación de registro

DESCRIPCIÓN

Un archivo en formato JSON que controla la autenticación contra registros de imágenes de contenedores. El archivo principal (lectura/escritura) se almacena en ${XDG_RUNTIME_DIR}/containers/auth.json en Linux; en Windows y macOS, en $HOME/.config/containers/auth.json.

Al buscar las credenciales para un registro, los siguientes archivos se leerán en secuencia hasta encontrar las credenciales válidas: primero se lee el archivo principal (lectura/escritura), o la anulación explícita mediante una opción de la aplicación llamante. Si las credenciales no están presentes allí, la búsqueda continúa en ${XDG_CONFIG_HOME}/containers/auth.json (generalmente ~/.config/containers/auth.json), $HOME/.docker/config.json, $HOME/.dockercfg.

Excepto por el archivo principal (lectura/escritura), otros archivos son de solo lectura a menos que el usuario, utilizando una opción de la aplicación llamante, lo señale explícitamente como una anulación.

FORMATO

El archivo auth.json almacena, o hace referencia a, credenciales que permiten al usuario autenticarse en registros de imágenes de contenedores. Se gestiona principalmente mediante un comando login de una herramienta de contenedores como podman login, buildah login o skopeo login.

Cada entrada contiene un solo nombre de host (por ejemplo, docker.io) o un espacio de nombres (por ejemplo, quay.io/user/image) como clave, y credenciales en forma de una cadena codificada en base64 como valor de auth. La cadena codificada en base64 contiene una concatenación del nombre de usuario, dos puntos y la contraseña.

Al verificar las credenciales disponibles, el repositorio relevante se compara con las claves disponibles en su orden jerárquico, yendo de lo más específico a lo menos específico. Por ejemplo, una extracción de imagen para my-registry.local/namespace/user/image:latest resultará en una búsqueda en auth.json en el siguiente orden:

  • my-registry.local/namespace/user/image
  • my-registry.local/namespace/user
  • my-registry.local/namespace
  • my-registry.local

De esta manera, es posible configurar múltiples credenciales para un solo registro que se pueden distinguir por su ruta.

El siguiente ejemplo muestra los valores que se encuentran en auth.json después de que el usuario inició sesión en sus cuentas en quay.io y docker.io:

{
	"auths": {
		"docker.io": {
			"auth": "erfi7sYi89234xJUqaqxgmzcnQ2rRFWM5aJX0EC="
		},
		"quay.io": {
			"auth": "juQAqGmz5eR1ipzx8Evn6KGdw8fEa1w5MWczmgY="
		}
	}
}

Este ejemplo demuestra cómo usar múltiples rutas para un solo registro, mientras se conserva una opción de respaldo para my-registry.local:

{
	"auths": {
		"my-registry.local/foo/bar/image": {
			"auth": "…"
		},
		"my-registry.local/foo": {
			"auth": "…"
		},
		"my-registry.local": {
			"auth": "…"
		},
	}
}

Una entrada se puede eliminar utilizando un comando logout de una herramienta de contenedores como podman logout o buildah logout.

Además, se pueden configurar ayudantes de credenciales para registros específicos, y el software de ayudante de credenciales puede usarse para gestionar las credenciales de manera más segura que almacenando solo credenciales codificadas en base64 en auth.json.

Cuando se utiliza el ayudante de credenciales en una plataforma Linux, el archivo auth.json contendría claves que especifican el dominio del registro y valores que especifican el sufijo del programa a utilizar (es decir, todo lo que sigue a docker-credential-). Por ejemplo:

{
    "auths": {
        "localhost:5001": {}
    },
    "credHelpers": {
		"registry.example.com": "secretservice"
	}
}

Para obtener más información sobre los ayudantes de credenciales, consulte el proyecto GitHub docker-credential-helpers ⟨https://github.com/docker/docker-credential-helpers/releases⟩.
