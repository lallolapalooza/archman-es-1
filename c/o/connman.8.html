CONNMAN(8) Manual del Administrador del Sistema CONNMAN(8)

NOMBRE

ConnMan - demonio de gestión de red

SINOPSIS

connmand [--version|--help]

connmand [-c archivo] [-d archivo[,...]] [-i interfaz[,...]] [-I interfaz[,...]] [-W driver[,...]] [-p plugin[,...]] [-P plugin[,...]] [-n] [-r]

DESCRIPCIÓN

El ConnMan proporciona un demonio para gestionar las conexiones a Internet dentro de dispositivos que ejecutan el sistema operativo Linux. El Gestor de Conexiones está diseñado para ser ligero y utilizar la menor cantidad de recursos posible. Es un sistema completamente modular que puede extenderse, mediante plugins, para soportar todo tipo de tecnologías cableadas o inalámbricas. Además, los métodos de configuración, como DHCP y la resolución de nombres de dominio, se implementan utilizando plugins. El enfoque de plugins permite una fácil adaptación y modificación para diversos casos de uso.

OPCIONES

Se soportan las siguientes opciones:

-v, --version
Imprime la versión del software ConnMan y sale.
-h, --help
Imprime las opciones disponibles de ConnMan y sale.
-c archivo, --config=archivo
Especifica el archivo de configuración para establecer varios ajustes para ConnMan. Si no se especifica, se utiliza el valor predeterminado de /etc/connman/main.conf. Consulte connman.conf(5) para obtener más información sobre el archivo de configuración. El uso del archivo de configuración es opcional y se utilizan valores predeterminados razonables si el archivo de configuración falta.
-d [archivo[,...]], --debug[=archivo[,...]]
Establece cuánta información envía ConnMan al destino del registro (generalmente la instalación "daemon" de syslog). Si se omiten las opciones de archivo, se imprimen las informaciones de depuración de todos los archivos fuente. Si se presentan opciones de archivo, entonces solo se imprimen las depuraciones de ese archivo fuente. Ejemplo:


connmand --debug=src/service.c,plugins/wifi.c

-i interfaz[,...], --device=interfaz[,...]
Gestionar solo estas interfaces de red. Por defecto, se gestionan todas las interfaces de red.
-I interfaz[,...], --nodevice=interfaz[,...]
Nunca gestionar estas interfaces de red. La opción puede ser un patrón que contenga caracteres "*" y "?".
-p plugin[,...], --plugin=plugin[,...]
Cargar solo estos plugins. La opción puede ser un patrón que contenga caracteres "*" y "?".
-P plugin[,...], --noplugin=plugin[,...]
Nunca cargar estos plugins. La opción puede ser un patrón que contenga caracteres "*" y "?".
-W driver[,...], --wifi=driver[,...]
Controlador WiFi que deben usar WiFi/Supplicant. Si se omite esta bandera, se utiliza el valor "nl80211,wext" por defecto.
-n, --nobacktrace
No imprimir información de rastreo.
-n, --nodaemon
No demonizar. Esto es útil para depuración y dirige la salida del registro al terminal de control además de syslog.
-r, --nodnsproxy
No actuar como proxy DNS ni dar soporte a la resolución DNS externa. Dependiendo de cómo se compile ConnMan, por defecto dirigirá todo el tráfico DNS a sí mismo estableciendo el servidor de nombres en 127.0.0.1 en el archivo resolv.conf(5) o dejará la gestión DNS a una entidad externa, como systemd-resolved. Si esto no es deseado y desea que todos los programas llamen directamente a algún servidor DNS, entonces puede usar la opción --nodnsproxy. ConnMan entonces descubre el servidor DNS y el dominio de búsqueda al inicio y los establece en resolv.conf(5). Si se utiliza esta opción, ConnMan no puede almacenar en caché las consultas DNS porque el tráfico DNS no pasa por ConnMan y eso puede causar algo de tráfico de red adicional.
