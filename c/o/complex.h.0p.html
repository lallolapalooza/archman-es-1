JUSTIFICACIÓ

N

La elección de I en lugar de i para la unidad imaginaria cede al uso generalizado del identificador i para otros propósitos. La aplicación puede usar un identificador diferente, digamos j, para la unidad imaginaria siguiendo la inclusión del encabezado <complex.h>

con: 
#undef I
#
define j _I
maginary_I

Un sufijo I para designar constantes imaginarias no es necesario, ya que la multiplicación por I proporciona una notación suficientemente conveniente y más generalmente útil para los términos imaginarios. El tipo real correspondiente para la unidad imaginaria es float, de modo que el uso de I por conveniencia algorítmica o notacional no resultará en la ampliación de

tipos.

En sistemas con tipos imaginarios, la aplicación tiene la capacidad de controlar si el uso de la macro I introduce un tipo imaginario, definiendo explícitamente I como _Imaginary_I o _Complex_I. Deshabilitar los tipos imaginarios es útil para algunas aplicaciones destinadas a ejecutarse en implementaciones sin soporte para tales

tipos.

La macro _Imaginary_I proporciona una prueba para saber si los tipos imaginarios son

soportados.

La función cis() (cos(x) + I*sin(x)) fue considerada pero rechazada porque su implementación es fácil y directa, aunque algun

as implementaciones podrían calcular el seno
y el coseno de manera más eficiente en conjunto.
