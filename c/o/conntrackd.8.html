DESCRIPCIÓ

N

conntrackd es el demonio de espacio de usuario para el sistema de seguimiento de conexiones de netfilter. Este demonio sincroniza los estados de seguimiento de conexiones entre varios cortafuegos réplica. Así, conntrackd puede usarse para desplegar cortafuegos con estado altamente

disponibles.

El demonio admite configuraciones Prima

rio-Copia y Multiprimario y también pued
e usarse como colector de estadísticas.

DEPENDENCIA

S

Este demonio requiere una versión del kernel de Linux >= 2.6.18. El seguimiento de la ventana de TCP requiere >= 2.6.22, de lo contrario tiene que desactivarlo. Los asistentes (helpers) están totalmente soportados desde >= 2.6.25; sin embargo, si usa una versión anterior, dependiendo del asistente del protocolo y su configuración (por ejemplo, si su configuración realiza ajustes de secuencias NAT o no), su conexión asistida puede recuperarse

correctamente.

Hay varias coincidencias (matches) de iptables con estado no soportadas, como recent, connbytes y las coincidencias de cuota, que recopilan información interna para operar. Dado que esa información no pertenece al dominio del sistema de seguimiento de conexiones, las conexiones afectadas por esas coincidencias pueden no recuperarse completamente durante la toma de

control.

El demonio requiere una versión del kernel de Linux >= 2.6.26 para soportar el filtrado de eventos en el espa

cio del kernel. De lo contrario, todo el filtrado de eventos se realiza en el espacio de usuario con la sobrec
arga correspondiente. Si no está usando la cláusula Filter en el archivo de configuración, ignore este aviso.

INTEGRACIÓN CON

SYSTEMD

A partir de la versión 1.4.4, conntrackd incluye integración con systemd(1) para usar un archivo de unidad de Type=notify y sop

orte de w
atchdog.

INCOMPATIBILIDADE

S

Durante el desarrollo de la versión 0.9.9, se introdujeron algunos cambios importantes en el formato del mensaje de replicación. Por lo tanto, conntrackd >= 0.9.9 no funcionará adecuadamente con conntrackd <= 0.9.

8.

Esto no debería ser un problema si usa

la misma versión de conntrackd en to
dos los nodos réplica del cortafuegos.
