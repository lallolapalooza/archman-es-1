DESCRIPCIÓ

N

Este módulo abre un archivo de configuración y analiza su contenido por usted. El método new requiere un parámetro que debe ser un nombre de archivo. El método getall devuelve un hash que contiene todas las opciones y sus valores asociados de su archivo de

configuración.

El formato de los archivos de configuración soportado por Config::General está inspirado en el conocido formato de configuración de Apache; de hecho, este módulo es 100% compatible con las configuraciones de Apache, pero también puede usar simplemente pares simples de
nombre/valor en sus archivos de

configuración.

Además de las capacidades de un archivo de configuración de A

pache, soporta algunas mejoras como documentos aquí (her
e-documents), comentarios estilo C u opciones multilínea.

Esta opción toma un parámetro obligatorio, que debe ser una referencia a un hash.

La referencia a hash proporcionada necesita definir variables para las cuales desea establecer valores preestablecidos. Cada variable que haya definido en esta referencia a hash y que aparezca en su archivo de configuración, hará que esta variable se establezca en los valores preestablecidos a los que se refiere el valor en el archivo de

                STRONG   => 1,

} );

En este ejemplo estamos definiendo una variable llamada "Mode" que puede contener uno o más de "CLEAR", "STRONG" y "UNSECURE" como

UNSECURE

indefinidas.

%config = (
            Mode => {
                      CLEAR    => 1,
                      UNSECURE => "32bit",
                      STRONG   => undef,
                    }
);

Este método permite al usuario (o, al "mantenedor" del archivo de configuración de su aplicación) establecer múltiples valores predefinidos para una

opción.

Tenga en cuenta que todas las apariciones de esas variables serán manejadas de esta manera, no hay forma de distinguir entre variables en diferentes ámbitos. Eso significa que si "Mode" también apareciera dentro de un bloque con nombre, también se analizaría de esta

Si necesitas múltiples bloques con el mismo nombre, entonces tienes que nombrar cada bloque. Esto funciona mucho como la configuración de Apache. Si el módulo encuentra un bloque con nombre, creará un hashref con la parte izquierda del bloque con nombre como clave que contiene uno o más hashrefs con la parte derecha del bloque como clave que contiene todo dentro del bloque (¡que a su vez puede estar anidado!). Como un ejemplo dice más que mil

palabras:

# dado el siguiente ejemplo
<Directory /usr/frisco>
Limit Deny
Options ExecCgi Index
</Directory>
<Directory /usr/frik>
Limit DenyAll
Options None
</Directory

>

#

obtendrás: 
$VAR1 = {
         'Directory' => {
                         '/usr/frik' => {
                                         'Options' => 'None',
                                         'Limit' => 'DenyAll'
                                        },
                         '/usr/frisco' => {
                                           'Options' => 'ExecCgi Index',
                                           'Limit' => 'Deny'
                                          }
                        }
        }
;

No puedes tener más de un bloque con nombre con el mismo

nombre porque se almacenará en un hashref y por lo tan
to se sobrescribirá si un bloque aparece una vez más.

BLOQUES

El comportamiento normal de Config::General es buscar espacios en blanco en los nombres de bloque para decidir si es un bloque con nombre o simplemente un bloque

simple.

A veces puedes necesitar nombres de bloque que tengan espacios en blanco en sus

nombres.

Con bloques con nombre esto no es un problema, ya que el módulo solo busca el primer espacio en

blanco: 
<person hugo gera>
</person> ">se analizaría

como: 
$VAR1 = {
         'person' => {
                      'hugo gera' => {
                                     },
                     }
        }
;

El problema ocurre si quieres tener un bloque simple que contenga espacios en

blanco: 
<hugo gera>
</hugo
gera>

Esto se analizaría como un bloque con nombre, que no es lo que querías. En este caso particular, puedes usar comillas para indicar que no es un bloque con

OPCIONES IDÉNTICAS

(ARREGLOS)

Puedes tener más de una línea de la misma opción con diferentes valores.

Ejemplo: 
log  log1
log  log2
log
log2

Obtendrás un escalar si la opción apareció solo una vez o un arreglo si apareció más de una vez. Si esperas múltiples opciones idénticas, entonces podrías necesitar verificar si una opción apareció más de una

vez: 
$allowed = $hash{jonas}->{tablestructure}->{allowed};
if (ref($allowed) eq "ARRAY") {
  @ALLOWED = @{$allowed};
  else {
    @ALLOWED = ($allowed);
  }
}

Lo mismo aplica para bloques y bloques con nombre también (se describen con más detalle más abajo). Por ejemplo, si tienes la siguiente

configuración: 
<dir blah>
 user max
</dir>
<dir blah>
 user hannes
</dir>

entonces terminarías con una estructura de datos como

esta: 
$VAR1 = {
         'dir' => {
                   'blah' => [
                              {
                               'user' => 'max'
                              },
                              {
                               'user' => 'hannes'
                              }
                             ]
                  }
        }
;

Como puedes ver, los dos bloques idénticos se almacenan en un hash que contiene un arreglo(-referencia) de

hashes.

Bajo algunas condiciones raras podrías no querer este comportamiento con bloques (y bloques con nombre también). Si quieres obtener un solo hash con el contenido de ambos bloques idénticos, entonces necesitas activar el parámetro de new() -MergeDuplicateBlocks (ver arriba). La estructura analizada del ejemplo anterior se vería entonces

así: 
$VAR1 = {
         'dir' => {
                   'blah' => {
                              'user' => [
                                         'max',
                                         'hannes'
                                        ]
                             }
                  }
        }
;

Como puedes ver, solo hay un hash "dir->{blah}" que contiene múltiples entradas "user". Como también puedes ver, activar -MergeDuplicateBlocks no afecta a las opciones escalares (es decir "option = value"). De hecho, puedes ajustar la fusión de bloques y opciones duplicados de forma independiente entre

sí.

Si no quieres permitir más de una opción idéntica, puedes desactivarlo estableciendo el indicador AllowMultiOptions en el método new() a "no". Si está desactivado, ¡Config::General se quejará de las opciones que ocurren múltiples veces con nombres

idénticos!

INCLUSIONE

S

Puedes incluir un archivo externo en cualquier posición de tu archivo de configuración usando la siguiente sentencia en tu archivo de

configuración: 
<<include externalconfig.rc>
>

Si activaste -UseApacheInclude (ver new()), entonces también puedes usar la siguiente sentencia para incluir un archivo

externo: 
include externalconfig.
rc

Este archivo se insertará en la posición donde se encontró como si el contenido de este archivo estuviera directamente en esta

posición.

También puedes incluir archivos recursivamente, así que un archivo incluido puede incluir otro y así sucesivamente. Ten cuidado de no cargar recursivamente el mismo archivo, terminarás con un mensaje de error como "demasiados archivos abiertos en el sistema!

".

Por defecto, los archivos incluidos con una ruta relativa se abrirán desde el directorio de trabajo actual. Bajo algunas circunstancias podría ser posible abrir archivos incluidos desde el directorio donde reside el archivo de configuración. Necesitas activar la opción -IncludeRelative (ver new()) si quieres eso. Un

ejemplo: 
my $conf = Config::General(
 -ConfigFile => "/etc/crypt.d/server.cfg"
 -IncludeRelative => 1
)
;

/etc/crypt.d/server.

cfg: 
<<include acl.cfg>
>

En este ejemplo Config::General intentará incluir acl.cfg desde /etc/cryp

t.d: 
/etc/crypt.d/acl.
cfg

El comportamiento por defecto (si -IncludeRelative no está establecido!) será abrir simplemente acl.cfg, dondequiera que esté, es decir, si hiciste un chdir("/usr/local/etc"), entonces Config::General

incluirá: 
/usr/local/etc/acl.
cfg

Las sentencias de inclusión pueden ser insensibles a mayúsculas/minúsculas (añadido en la versión 1.25)

.

Las sentencias de inclusión se ignorarán dentro de comentarios C y documentos

aquí.

Por defecto, un archivo de configuración solo se incluirá la primera vez que se referencia. Si deseas incluir un archivo en múltiples lugares, establece /-IncludeAgain a true. Pero ten cuidado: esto puede llevar a bucles infinitos, ¡así que asegúrate de no incluir el mismo archivo desde dentro de sí

mismo!

Ejemplo

: 
# main.cfg
<object billy>
 class=Some::Class
<printers>
 include printers.cfg
</printers>
# ...
</object>
 <object bob>
  class=Another::Class
 <printers>
 include printers.cfg
 </printers>
 # ...
</object>

Ahora "printers.cfg" será incluido en ambos objetos "billy" y "bob"

.

Tendrás que tener cuidado de no incluir

un archivo recursivamente. El com
portamiento en este caso es indefinido.

COMENTARIO

S

Un comentario comienza con el signo de número #, puede haber cualquier número de espacios y/o tabulaciones delante del

#.

Un comentario también puede ocurrir después de una sentencia de configuración.

Ejemplo: 
username = max  # this is the
comment

Si quieres comentar un bloque grande puedes usar comentarios de estilo C. Un /* señala el inicio de un bloque de comentario y el */ señala el final del bloque de comentario.

Ejemplo: 
user  = max # valid option
db    = tothemax
/*
user  = andors
db    = toand
*/

En este ejemplo, las segundas opciones de user y db serán ignoradas. Por favor ten en cuenta que si el Módulo encuentra una cadena /* que es el inicio de un bloque de comentario, pero no hay un bloque final coincidente, ¡ignorará todo el resto del archivo de

configuración!

NOTA: Si necesitas que el carácter # (signo de número) permanezca en el valor de la opción, puedes usar una barra invertida delante de él para escaparlo.

Ejemplo: 
bgcolor =
\#ffffcc

En este ejemplo, el valor de $config{bgcolor} será "#ffffcc", Config::General no tratará el signo de número como el inicio de un comentario debido a la barra invertida

inicial.

¡Dentro de los documentos

aquí NO se requiere esca
par los signos de número!

COMPLEMENTOS DEL

ANALIZADOR

Puedes alterar el comportamiento del analizador proporcionando cierres que se llamarán en ciertos puntos de enganche durante el procesamiento y análisis del archivo de

configuración.

El enfoque general funciona

así: 
sub ck {
  my($file, $base) = @_;
  print "_open() tries $file ... ";
  if ($file =~ /blah/) {
    print "ignored\n";
    return (0);
  } else {
    print "allowed\n";
    return (1, @_);
  }
}

my %c = ParseConfig(
                    -IncludeGlob      => 1,
                    -UseApacheInclude => 1,
                    -ConfigFile       => shift,
                    -Plug             => { pre_open => *ck }
                   )
;

Salida

: 
_open() intenta cfg ... permitido
_open() intenta x/*.conf ... permitido
_open() intenta x/1.conf ... permitido
_open() intenta x/2.conf ... permitido
_open() intenta x/blah.conf ...
ignorado

archivo.

El procesamiento general continúa como de costumbre si el primer valor del array devuelto es verdadero. El segundo valor de ese array depende del tipo de gancho que se esté

llamando.
