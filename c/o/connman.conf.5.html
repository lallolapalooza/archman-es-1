NOMBRE

main.conf - Archivo de configuración de ConnMan

SINOPSIS

/etc/connman/main.conf

DESCRIPCIÓN

main.conf es un archivo de configuración para ConnMan. El archivo de configuración es opcional pero puede usarse para configurar varios aspectos del comportamiento de ConnMan. La ubicación del archivo puede cambiarse mediante el argumento --config= de connman(8).

FORMATO DEL ARCHIVO

El archivo de configuración consta de secciones (grupos) de pares clave-valor. Las líneas que comienzan con '#' y las líneas en blanco se consideran comentarios. Las secciones se inician con una línea de encabezado que contiene la sección entre '[' y ']', y terminan implícitamente al inicio de la siguiente sección o al final del archivo. Cada par clave-valor debe estar contenido en una sección.

A continuación se describe las secciones y las claves disponibles:

[General]

Esta es la única sección obligatoria del archivo de configuración.

InputRequestTimeout=seg
Establece el tiempo de espera para la solicitud de entrada. Predeterminado: 120 segundos. La solicitud de entradas como la contraseña caducará después de una cierta cantidad de tiempo. Use esta configuración para aumentar el valor en caso de diferentes diseños de interfaz de usuario.
BrowserLaunchTimeout=seg
Establece el tiempo de espera para el lanzamiento del navegador. Predeterminado: 300 segundos. La solicitud para lanzar un navegador para páginas de portal caducará después de una cierta cantidad de tiempo. Use esta configuración para aumentar el valor en caso de diferentes diseños de interfaz de usuario.
BackgroundScanning=true | false
Habilita el escaneo en segundo plano. Predeterminado: true. Si el wifi está desconectado, el escaneo en segundo plano seguirá un mecanismo simple de retroceso de 3s hasta 5 minutos. Luego, se mantendrá en 5 minutos a menos que el usuario solicite explícitamente un escaneo a través de una llamada D-Bus. En ese caso, el mecanismo comenzará de nuevo desde 3s. Esta característica también activa el escaneo en segundo plano mientras está conectado, lo cual es necesario para la itinerancia en wifi. Cuando BackgroundScanning es false, ConnMan no realizará ningún escaneo independientemente de si el wifi está conectado o no, a menos que lo solicite el usuario a través de una llamada D-Bus.
UseGatewaysAsTimeservers=true| false
Asume que las pasarelas del servicio también funcionan como servidores de hora. Predeterminado: false.
FallbackTimeservers=servidor[,...]
Lista de servidores de hora de respaldo separados por ",". Estos servidores de hora se utilizan para la sincronización NTP cuando no hay servidores de hora establecidos por el usuario o por el servicio, y cuando UseGatewaysAsTimeservers = false. Estos pueden contener una combinación mixta de nombres de dominio completamente calificados, direcciones IPv4 e IPv6.
FallbackNameservers=servidor[,...]
Lista de servidores de nombres de respaldo separados por "," que se agregan a la lista de servidores de nombres proporcionados por el servicio. Las entradas del servidor de nombres deben estar en formato numérico, se ignoran los nombres de host.
DefaultAutoConnectTechnologies=tecnología[,...]
Lista de tecnologías que se marcan como autoconectables por defecto, separadas por comas ",". El valor predeterminado para esta entrada cuando está vacía es ethernet,wifi,cellular. Los servicios que se conectan automáticamente deben haber sido configurados y guardados en el almacenamiento de antemano.
DefaultFavoriteTechnologies=tecnología[,...]
Lista de tecnologías que se marcan como favoritas por defecto, separadas por comas ",". El valor predeterminado para esta entrada cuando está vacía es ethernet. Se conecta a servicios de esta tecnología incluso si no están configurados y guardados en el almacenamiento.
AlwaysConnectedTechnologies=tecnología[,...]
Lista de tecnologías que siempre están conectadas independientemente de la configuración PreferredTechnologies (AutoConnect = true). El valor predeterminado está vacío y esta característica está deshabilitada a menos que se habilite explícitamente en el archivo de configuración.
PreferredTechnologies=tecnología[,...]
Lista de tecnologías preferidas, desde la más preferida hasta la menos preferida, separadas por comas ",". Se intentarán los servicios del tipo de tecnología listada uno por uno en el orden dado, hasta que uno de ellos se conecte o se prueben todos. Un servicio de un tipo de tecnología preferida en estado 'ready' obtendrá la ruta predeterminada cuando se compare con otro tipo preferido más abajo en la lista en estado 'ready' o con un tipo no preferido; un servicio de un tipo de tecnología preferida en estado 'online' obtendrá la ruta predeterminada cuando se compare con un tipo no preferido o un tipo preferido más abajo en la lista.
NetworkInterfaceBlacklist=interfaz[,...]
Lista de interfaces de red en lista negra separadas por ",". Las interfaces encontradas se compararán con la lista y no serán gestionadas por connman si sus primeros caracteres coinciden con alguna de las entradas de la lista. El valor predeterminado es vmnet,vboxnet,virbr,ifb,ve-,vb-,ham,veth.
AllowHostnameUpdates=true | false
Permite a connman cambiar el nombre de host del sistema. Esto puede ocurrir, por ejemplo, si recibimos la opción de nombre de host de DHCP. El valor predeterminado es true.
AllowDomainnameUpdates=true | false
Permite a connman cambiar el nombre de dominio del sistema. Esto puede ocurrir, por ejemplo, si recibimos la opción de nombre de dominio de DHCP. El valor predeterminado es true.
SingleConnectedTechnology=true | false
Mantiene solo una tecnología conectada a la vez. Cuando el usuario conecta un nuevo servicio o se encuentra uno mejor según PreferredTechnologies, se mantiene conectado el nuevo servicio y se desconectan todos los demás servicios conectados anteriormente. Con esta configuración, no importa si los servicios conectados anteriormente están en estado 'online' o 'ready', el servicio recién conectado será el único que permanecerá conectado. Un servicio conectado por el usuario se utilizará hasta que salga de la cobertura de red. Con esta configuración habilitada, las aplicaciones notarán más interrupciones de red de lo normal. Tenga en cuenta que esta opción no se puede usar con VPN. El valor predeterminado es false.
TetheringTechnologies=tecnología[,...]
Lista de tecnologías que tienen permitido habilitar la conexión compartida separadas por ",". El valor predeterminado es wifi,bluetooth,gadget. Solo las tecnologías listadas aquí se utilizan para la conexión compartida. Si se desea compartir la conexión ethernet, agregue "ethernet" en la lista. TENGA EN CUENTA que si la conexión compartida ethernet está habilitada, se iniciará un servidor DHCP en todas las interfaces ethernet. La conexión compartida ethernet nunca debe conectarse a una red corporativa o doméstica, ya que interrumpirá el funcionamiento normal de esas redes. Debido a esto, ethernet no se comparte por defecto. No active la conexión compartida ethernet a menos que realmente sepa lo que está haciendo.
PersistentTetheringMode=true | false
Restaura el estado anterior de la conexión compartida al volver del modo offline, al reactivar una tecnología y después de reinicios y reinicios. El valor predeterminado es false.
Enable6to4=true | false
Habilita automáticamente Anycast 6to4 si es posible. No se recomienda, ya que el uso de 6to4 generalmente provocará una grave degradación de la calidad de la conexión. Consulte RFC6343. El valor predeterminado es false (como se recomienda en RFC6343.
VendorClassID=cadena
Establece la opción DHCP 60 (Vendor Class ID) a la cadena dada. Esta opción puede ser utilizada por los servidores DHCP para identificar clientes específicos sin tener que depender de rangos de direcciones MAC, etc.
EnableOnlineCheck=true | false
Habilita o deshabilita el uso de HTTP GET como una verificación de estado en línea. Cuando un servicio está en estado READY y se selecciona como predeterminado, ConnMan emitirá una solicitud HTTP GET para verificar que la conectividad de extremo a extremo sea exitosa. Solo entonces el servicio se transicionará al estado ONLINE. Si esta configuración es falsa, el servicio predeterminado permanecerá en el estado READY. El valor predeterminado es true.

NOTA: EnableOnlineCheck está obsoleto; por favor, utiliza OnlineCheckMode con un modo de one-shot o none.

OnlineCheckMode=modo
Esto indica el modo de verificación de alcance a Internet basado en HTTP "en línea" y reemplaza y obsolece EnableOnlineCheck. Los valores posibles para modo son none, one-shot y continuous. El valor predeterminado de modo es one-shot.

En el modo none, no hay verificaciones de alcance a Internet basadas en HTTP "en línea". Cualquier servicio conectado y el estado del gestor terminarán en el estado "ready" y no progresarán a "online".

En el modo one-shot, hay una única verificación de alcance a Internet basada en HTTP "en línea" para el servicio predeterminado. Cuando la verificación tiene éxito, el servicio asociado y el estado del gestor terminarán en el estado "online". Cuando la verificación falla, las verificaciones posteriores se reprogramarán según OnlineCheckIntervalStyle, OnlineCheckInitialInterval y OnlineCheckMaxInterval y continuarán indefinidamente hasta que una tenga éxito o hasta que el servicio se desconecte.

En el modo continuous, hay continuas verificaciones de alcance a Internet basadas en HTTP "en línea" para el servicio predeterminado. Al igual que en el modo "one-shot", cuando la primera verificación tiene éxito, el servicio asociado y el estado del gestor terminarán en el estado "online". A partir de entonces, las verificaciones posteriores se programarán según OnlineCheckIntervalStyle y OnlineCheckMaxInterval. Cuando la verificación falla, las verificaciones posteriores se reprogramarán según OnlineCheckIntervalStyle, OnlineCheckInitialInterval y OnlineCheckMaxInterval. Cuando se cumpla OnlineCheckFailuresThreshold, si está disponible, el servicio y el estado del gestor se degradarán a "ready" y el servicio tendrá su propiedad "Error" establecida en "online-check-failed", mientras que las verificaciones posteriores continuarán. Mientras tanto, si está disponible, otro servicio puede ser promovido a servicio predeterminado y se iniciarán verificaciones en línea para él. Cuando se cumpla OnlineCheckSuccessesThreshold, si está disponible, la propiedad "Error" del servicio se borrará y el estado del servicio se promoverá a "online", lo que podría hacer que vuelva a ser el servicio predeterminado.

OnlineCheckIPv4URL=url,OnlineCheckIPv6URL=url
URLs (IPv4 e IPv6 respectivamente) utilizadas durante la verificación de estado en línea. Consulte el README para obtener información más detallada. Los valores predeterminados son http://ipv4.connman.net/online/status.html y http://ipv6.connman.net/online/status.html respectivamente.
OnlineCheckConnectTimeout=secs[.milliseconds]
El tiempo, en segundos decimales (por ejemplo, 12.3), para esperar una conexión TCP exitosa al host asociado con OnlineCheckIPv4URL u OnlineCheckIPv6URL (ver arriba). Las conexiones que tarden más que OnlineCheckConnectTimeout se abortarán. El valor predeterminado es cero ('0'), lo que indica que no se utilizará ningún tiempo de espera de conexión explícito, dejando el tiempo de espera a cargo del sistema operativo subyacente y la pila de red.
OnlineCheckInitialInterval=intervalo,OnlineCheckMaxInterval=intervalo
Rango de intervalos entre dos solicitudes de verificación en línea. Consulte el README para obtener información más detallada. Los valores predeterminados son 1 y 12 respectivamente.
OnlineCheckIntervalStyle=fibonacci | geometric
El estilo o la función de serie matemática utilizada para calcular el tiempo real, en segundos, entre dos verificaciones de alcance a Internet basadas en HTTP de "ready" a "online". El valor puede ser "geometric" o "fibonacci", con un valor predeterminado de "geometric".

El estilo o función "geometric" simplemente toma el cuadrado del intervalo de verificación en línea (consulte OnlineCheckInitialInterval y OnlineCheckMaxInterval arriba). Por ejemplo, con un intervalo de verificación de 6, el tiempo, en segundos, es 36 (6^2) segundos.

El estilo o función "fibonacci" toma el valor de la secuencia de Fibonacci en el intervalo de verificación en línea. Por ejemplo, con un intervalo de verificación de 6, el tiempo, en segundos, es 8 segundos.

La serie y el estilo "fibonacci" son más agresivos en la tasa de verificación hasta 12 pasos (su punto de equivalencia con "geometric" a 144 segundos) que "geometric", pero se retiran mucho más agresivamente después de ese punto, alcanzando una hora en el intervalo 19, que "geometric" no alcanza hasta el intervalo 60.

EnableOnlineToReadyTransition=true | false
Además de la configuración de EnableOnlineCheck, habilita o deshabilita el uso de HTTP GET para detectar la pérdida de conectividad de extremo a extremo. Si esta configuración es falsa, cuando el servicio predeterminado transicione al estado ONLINE, la solicitud HTTP GET ya no se llamará hasta el próximo ciclo, iniciado por una transición del servicio predeterminado al estado DISCONNECT. Si esta configuración es verdadera, la solicitud HTTP GET se seguirá llamando para garantizar que la conectividad de extremo a extremo siga siendo exitosa. Si no es así, el servicio predeterminado transicionará al estado READY, permitiendo que otro servicio se convierta en el predeterminado, en su reemplazo. El valor predeterminado es false.

NOTA: EnableOnlineToReadyTransition está obsoleto; por favor, utiliza OnlineCheckMode con un modo de continuous o none.

OnlineCheckFailuresThreshold=fallos
Cuando OnlineCheckMode es "continuous", este es el número de verificaciones fallidas consecutivas de alcance a Internet basadas en HTTP de "ready" a "online" que se permitirán antes de marcar un servicio como "fallido" desde la perspectiva del alcance, clasificándolo con una prioridad menor que otros servicios que no están marcados de esa manera.

Valores más bajos pueden resultar en ciclado de servicios de red de mayor frecuencia, mientras que valores más altos pueden resultar en un período de tiempo más largo antes de fallar desde un servicio no accesible a Internet a uno que podría serlo.

Consulte OnlineCheckIntervalStyle, OnlineCheckInitialInterval y OnlineCheckMaxInterval para otros valores que influyen en el tiempo de transición de falla/recuperación del servicio de red. El valor predeterminado es 6.

OnlineCheckSuccessesThreshold=exitos
Cuando OnlineCheckMode es "continuous", este es el número de verificaciones exitosas consecutivas de alcance a Internet basadas en HTTP de "ready" a "online" que deben cumplirse antes de borrar un servicio como "fallido" desde la perspectiva del alcance y permitirle que transicione nuevamente al estado "online", permitiéndole clasificarse nuevamente con una prioridad mayor en relación con otros servicios de red.

Valores más bajos pueden resultar en ciclado de servicios de red de mayor frecuencia, mientras que valores más altos pueden resultar en un período de tiempo más largo antes de transicionar de regreso a un servicio de red más preferido y accesible a Internet.

Consulte OnlineCheckIntervalStyle, OnlineCheckInitialInterval y OnlineCheckMaxInterval para otros valores que influyen en el tiempo de transición de falla/recuperación del servicio de red.

El valor predeterminado es 6.

AutoConnectRoamingServices=true | false
Conecta automáticamente servicios de itinerancia. No se recomienda a menos que sepa que no tendrá ningún problema de facturación. El valor predeterminado es false.
AddressConflictDetection=true | false
Habilita o deshabilita la implementación de la detección de conflictos de direcciones IPv4 según RFC5227. ConnMan enviará paquetes ARP de sondeo para ver si una dirección IPv4 ya está en uso antes de asignar la dirección a una interfaz. Si ocurre un conflicto de direcciones para una dirección configurada estáticamente, se elegirá una dirección IPv4LL en su lugar (según RFC3927). Si ocurre un conflicto de direcciones para una dirección ofrecida a través de DHCP, ConnMan enviará un DHCP DECLINE una vez y para el segundo conflicto recurrirá a encontrar una dirección IPv4LL. El valor predeterminado es false.
Localtime=cadena
Ruta al archivo localtime. Por defecto es /etc/localtime.
RegdomFollowsTimezone=true | false
Habilita que el regdomain se cambie junto con los cambios de zona horaria. Con esta opción establecida en true, cada vez que cambie la zona horaria, se leerá el primer código de país ISO3166 presente de /usr/share/zoneinfo/zone1970.tab y se establecerá como valor de regdom. El valor predeterminado es false.
ResolvConf=cadena
Ruta al archivo resolv.conf. Si el archivo no existe, pero los directorios intermedios existen, se creará. Si esta opción no está configurada, intentará escribir en /run/connman/reso
connman.conf(5) - Arch manual pages

NAME

connman.conf

configuration file for connman

SYNOPSIS

/etc/connman/main.conf
/etc/connman.conf

DESCRIPTION

Connman is a network configuration daemon, designed to provide network management on embedded systems. It aims to be simple, fast, and modern. It can be configured by setting different options in the connman.conf file.

The configuration file is divided into sections, enclosed in square brackets [section]. The first section is [General], which is mandatory. All other sections are optional and specific to certain technologies.

The configuration file supports C-style comments (‘/* ... */’) and shell-style comments (‘# ...’ and ‘// ...’).

The configuration file can be placed in /etc/connman/main.conf or /etc/connman.conf. If both files exist, the settings from /etc/connman/main.conf are merged with the settings from /etc/connman.conf, with the latter taking precedence.

FILE FORMAT

The configuration file is a simple key-value pair format, where each line represents a configuration option.

The format is:

[section]
key = value

Where [section] is the name of the section, and key and value are the configuration option and its corresponding value.

The following options are available in the [General] section:

AllowHostnameUpdates
If set to true (default), Connman will update the system's hostname and domain name based on the network information received. If set to false, these updates will be disabled.
AllowDomainnameUpdates
Similar to AllowHostnameUpdates, but specifically controls updates to the domain name. If set to true (default), the domain name will be updated. If set to false, it will not.
Hostname
Sets a static hostname to be used by Connman. If this option is set, AllowHostnameUpdates will be ignored.
Domainname
Sets a static domain name to be used by Connman. If this option is set, AllowDomainnameUpdates will be ignored.
TetheringTechnologies
Specifies which technologies are allowed for tethering. The value is a comma-separated list of technologies. Possible values include ethernet, wifi, bluetooth, and gadget (for USB tethering).
FallbackResolvConf
Specifies a file to be used as a fallback for DNS name resolution if Connman is unable to update /etc/resolv.conf. By default, Connman tries to update /etc/resolv.conf with DNS information obtained from the network. If this fails (e.g., if /run/connman does not exist or is not writable), Connman will use the file specified by FallbackResolvConf. If set to /dev/null, no fallback is used. The default is /etc/resolv.conf.

EXAMPLE

The following example configuration disables hostname updates and enables ethernet tethering.

[General]
AllowHostnameUpdates = false
AllowDomainnameUpdates = false
TetheringTechnologies = ethernet,wifi,bluetooth,gadget
