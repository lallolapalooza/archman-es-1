DESCRIPCIÓN

El

Aunque puede usarse para gestionar directamente el almacenamiento de capas de sistema de archivos, imágenes y contenedores, sus casos de uso principales se centran en la resolución de problemas y la consulta del estado del almacenamiento que está siendo gestionado por otros procesos. En términos conceptuales, una

capa

completa de sistema de archivos está compuesta por un sistema de archivos de contenedor y algo de información de gestión. Otras capas, hijas de esa capa, comparten por defecto su contenido, pero cualquier cambio hecho al contenido de las hijas no se refleja en la madre. Esta disposición está destinada a ahorrar espacio en disco: al almacenar la capa hija solo como un conjunto de cambios relativos a su madre, el contenido de la madre no debería necesitar duplicarse para cada una de las hijas de la madre. Por supuesto, cada hija puede tener sus propias hijas. El contenido de las capas madres no debería modificarse. Una imagen es una referencia a una capa

particular,

An junto con algo de información de gestión. Presumiblemente, la imagen apunta a una capa que ha sido modificada, posiblemente en múltiples pasos, desde alguna capa madre de propósito general, de modo que sea adecuada para ejecutar una aplicación destinada. Múltiples imágenes pueden referenciar una sola capa, diferenciándose solo en la información de gestión adicional que portan. El contenido de las imágenes debe considerarse de solo lectura. Un contenedor es esencialmente una capa que es una hija de una capa a

la

que se hace referencia mediante una imagen (en otras palabras, un [[49]] contenedor se instancia a partir de una imagen), junto con algo de información de gestión. No tienen hijas y sus capas no pueden ser referenciadas directamente por imágenes. Esto asegura que los cambios en el contenido de la capa de un contenedor no afecten a otras imágenes o capas, por lo que se consideran escribibles. A todas las capas, imágenes y contenedores se les puede adjuntar metadatos

que

containers-storage gestiona. images, and Generalmente no se espera que estos metadatos sean grandes, ya que se almacenan en caché en memoria. A las imágenes y contenedores también se les pueden adjuntar elementos de datos

con

nombres arbitrarios. Generalmente, estos datos pueden ser más grandes que los metadatos, y no se mantienen en memoria a menos que se estén recuperando o escribiendo. Se espera que las firmas que puedan usarse para verificar el

contenido

de una imagen se almacenen como elementos de datos para esa imagen, junto con cualquier dato de configuración de plantilla que se recomiende usar en contenedores que se deriven de la imagen. También se espera que la configuración en tiempo de ejecución de un contenedor se almacene como datos de elementos. SUBCOMANDOS Las características
