NOMBRE

cockpit-ws - Servicio web de Cockpit

SINOPSIS

cockpit-ws [--help] [--port PUERTO] [--address DIRECCIÓN] [--no-tls] [--for-tls-proxy] [--local-ssh] [--local-session PUENTE]

DESCRIPCIÓN

El programa cockpit-ws es el componente de servicio web utilizado para la comunicación entre la aplicación del navegador y varias herramientas y servicios de configuración como cockpit-bridge(1).

Los usuarios o administradores nunca deberían necesitar iniciar este programa, ya que se inicia automáticamente al arrancar mediante systemd(1), a través de cockpit-tls(8).

SEGURIDAD DE TRANSPORTE

Normalmente, cockpit-ws se ejecuta detrás del proxy de terminación TLS cockpit-tls y solo maneja HTTP sin cifrar por sí mismo. Pero para compatibilidad con versiones anteriores, también puede manejar conexiones TLS por sí mismo cuando se ejecuta directamente. Para obtener detalles sobre cómo configurar certificados, consulte la documentación de cockpit-tls(8).

TIEMPO DE ESPERA

Cuando se inicia a través de systemd(1), cockpit-ws se cerrará después de 90 segundos si nadie inicia sesión, o después de que el último usuario se desconecte.

OPCIONES

--help

Muestra las opciones de ayuda.

--port PUERTO

Sirve las solicitudes HTTP en el PUERTO en lugar del puerto 9090. Normalmente, Cockpit se inicia bajo demanda por activación de socket de systemd, y esta opción no tiene efecto. Actualice la directiva ListenStream del archivo cockpit.socket de la manera habitual de systemd.

--address DIRECCIÓN

Enlace a la DIRECCIÓN en lugar de enlazar a todas las direcciones disponibles. Normalmente, Cockpit se inicia bajo demanda por activación de socket de systemd, y esta opción no tiene efecto. En ese caso, actualice la directiva ListenStream en el archivo cockpit.socket de la manera habitual de systemd.

--no-tls

No usar TLS.

--for-tls-proxy

Indica a cockpit-ws que se está ejecutando detrás de un proxy inverso local que realiza la terminación TLS. Entonces, Cockpit incluye URL https:// en el encabezado Content-Security-Policy predeterminado y acepta solo orígenes https://, en lugar de http: por defecto. Sin embargo, si se establece Origins en el archivo de configuración cockpit.conf(5), esto anulará este valor predeterminado.

--local-ssh

Normalmente, cockpit-ws utiliza cockpit-session y PAM para autenticar al usuario e iniciar una sesión de usuario. Con esta opción habilitada, autenticará a través de SSH en 127.0.0.1 puerto 22.

--local-session PUENTE

Omite toda la autenticación y cockpit-session, y ejecuta el cockpit-bridge especificado en PUENTE en la sesión local. Si el PUENTE se especifica como -, espera un puente ya en ejecución que esté conectado a la entrada y salida estándar de este proceso cockpit-ws. Esto permite que el servidor web se ejecute como cualquier usuario no privilegiado en una sesión ya en curso.

Este modo implica --no-tls, por lo tanto, debe usar URL http:// con esto.


Advertencia
Si usa esto, debe aislar el puerto TCP abierto de alguna manera (por ejemplo, en un espacio de nombres de red), de lo contrario, todos los demás usuarios (¡o incluso máquinas remotas si el puerto no solo está escuchando en localhost!) podrán acceder a la sesión.

ENTORNO

El proceso cockpit-ws utilizará la variable de entorno XDG_CONFIG_DIRS de la especificación XDG basedir[1] para encontrar su archivo de configuración cockpit.conf(5).

Además, la variable de entorno XDG_DATA_DIRS de la especificación XDG basedir[1] puede usarse para anular la ubicación desde donde se sirven los archivos estáticos. Estos son los archivos que se sirven a un usuario que no ha iniciado sesión.
