NOMBRE

containers-storage-zstd-chunked - Información sobre zstd:chunked

DESCRIPCIÓN

El formato tradicional para las capas de imágenes de contenedores es application/vnd.oci.image.layer.v1.tar+gzip ⟨https://github.com/opencontainers/image-spec/blob/main/layer.md#gzip-media-types⟩. Más recientemente, el estándar se amplió con zstd: application/vnd.oci.image.layer.v1.tar+zstd ⟨https://github.com/opencontainers/image-spec/blob/main/layer.md#zstd-media-types⟩ que es un formato de compresión más moderno y eficiente.

zstd:chunked es una variante del tipo de medio application/vnd.oci.image.layer.v1.tar+zstd que utiliza tramas saltables de zstd ⟨https://github.com/facebook/zstd/blob/dev/doc/zstd_compression_format.md#skippable-frames⟩ para incluir metadatos adicionales (especialmente una "tabla de contenidos") que incluye el SHA-256 y los desplazamientos de fragmentos individuales de archivos. Además, los fragmentos se comprimen por separado. Esto permite a un cliente descargar dinámicamente solo el contenido que aún no tiene utilizando solicitudes de rango HTTP.

En el momento de escribir esto, el soporte para esto está habilitado por defecto en el código.

Puede habilitar o deshabilitar explícitamente zstd:chunked con los siguientes cambios en containers-storage.conf:

[storage.options.pull_options]
enable_partial_images = "true" | "false"

Tenga en cuenta que el valor de este campo debe ser un booleano de tipo cadena ("string bool"), no un booleano nativo de TOML.

IMPLEMENTACIÓN

Cada capa tiene una clave asociada de "big data" llamada chunked-manifest-cache que es un formato binario personalizado adecuado para mmap() que contiene metadatos de índice para cada capa con el resumen sha256 completo de cada archivo más sus "fragmentos" (según lo calculado por zstd:chunked).

Cuando se extrae cualquier imagen, se escanean todas las demás capas existentes utilizando chunked-manifest-cache para ver si contienen un archivo con un resumen coincidente. Si se encuentra uno, el otro archivo se enlaza de forma dura (hardlink) si use_hardlinks = "true", de lo contrario, se enlaza de forma de referencia (reflink) (si es compatible con el sistema de archivos, o se realiza una copia física completa). Hay un intento de mejor esfuerzo para habilitar fsverity en el archivo si está configurado (ver ⟨https://github.com/containers/storage/issues/2017⟩).

Para obtener más información, en este momento el archivo con más información es pkg/chunked/internal/compression.go ⟨https://github.com/containers/storage/blob/39d469c34c96db67062e25954bc9d18f2bf6dae3/pkg/chunked/internal/compression.go⟩. Lo anterior es un enlace permanente para estabilidad, pero asegúrese de comprobar si hay cambios más recientes también.

ESTANDARIZACIÓN

En este momento, el formato no está oficialmente estandarizado ni documentado más allá de los comentarios y el código en la implementación de referencia.
