COMP_CTX_new(3ssl)

Paquete: openssl

Licencias: Apache-2.0

COMP_CTX_NEW(3ssl) OpenSSL COMP_CTX_NEW(3ssl)

NOMBRE

COMP_CTX_new, COMP_CTX_get_method, COMP_CTX_get_type, COMP_get_type, COMP_get_name, COMP_CTX_free, COMP_compress_block, COMP_expand_block, COMP_zlib, COMP_zlib_oneshot, COMP_brotli, COMP_brotli_oneshot, COMP_zstd, COMP_zstd_oneshot, BIO_f_zlib, BIO_f_brotli, BIO_f_zstd - Soporte de compresión

SINOPSIS

#include <openssl/comp.h>
COMP_CTX *COMP_CTX_new(COMP_METHOD *meth);
void COMP_CTX_free(COMP_CTX *ctx);
const COMP_METHOD *COMP_CTX_get_method(const COMP_CTX *ctx);
int COMP_CTX_get_type(const COMP_CTX* comp);
int COMP_get_type(const COMP_METHOD *meth);
const char *COMP_get_name(const COMP_METHOD *meth);
int COMP_compress_block(COMP_CTX *ctx, unsigned char *out, int olen,
                        unsigned char *in, int ilen);
int COMP_expand_block(COMP_CTX *ctx, unsigned char *out, int olen,
                      unsigned char *in, int ilen);
COMP_METHOD *COMP_zlib(void);
COMP_METHOD *COMP_zlib_oneshot(void);
COMP_METHOD *COMP_brotli(void);
COMP_METHOD *COMP_brotli_oneshot(void);
COMP_METHOD *COMP_zstd(void);
COMP_METHOD *COMP_zstd_oneshot(void);
const BIO_METHOD *BIO_f_zlib(void);
const BIO_METHOD *BIO_f_brotli(void);
const BIO_METHOD *BIO_f_zstd(void);

DESCRIPCIÓN

Estas funciones proporcionan soporte de compresión para OpenSSL. La compresión se utiliza dentro de la biblioteca OpenSSL para admitir la compresión de registros y certificados TLS.

COMP_CTX_new() se utiliza para crear una nueva estructura COMP_CTX utilizada para comprimir datos.

COMP_CTX_free() se utiliza para liberar el COMP_CTXdevuelto. Si el argumento es NULL, no se hace nada.

COMP_CTX_get_method() devuelve el COMP_METHOD del dado ctx.

COMP_CTX_get_type() y COMP_get_type() devuelven el NID para el COMP_CTX y el COMP_METHOD, respectivamente. COMP_get_name() devuelve el nombre del algoritmo del COMP_METHODdado.

COMP_compress_block() comprime ilen bytes del búfer in en el búfer out de tamaño olen utilizando el algoritmo especificado por ctx.

COMP_expand_block() expande ilen bytes del búfer in en el búfer out de tamaño olen utilizando el algoritmo especificado por ctx.

Los métodos (COMP_METHOD) pueden especificarse mediante una de estas funciones. Estas funciones estarán disponibles incluso si su algoritmo de compresión correspondiente no está configurado en la biblioteca OpenSSL. En tal caso, se devolverá NULL.

  • COMP_zlib() devuelve un COMP_METHOD para compresión ZLIB basada en flujo.
  • COMP_zlib_oneshot() devuelve un COMP_METHOD para compresión ZLIB de un solo disparo.
  • COMP_brotli() devuelve un COMP_METHOD para compresión Brotli basada en flujo.
  • COMP_brotli_oneshot() devuelve un COMP_METHOD para compresión Brotli de un solo disparo.
  • COMP_zstd() devuelve un COMP_METHOD para compresión Zstandard basada en flujo.
  • COMP_zstd_oneshot() devuelve un COMP_METHOD para compresión Zstandard de un solo disparo.

BIO_f_zlib(), BIO_f_brotli() BIO_f_zstd() cada uno devuelve un BIO_METHOD que puede utilizarse para crear un BIO mediante BIO_new(3) para leer y escribir archivos o flujos comprimidos. Las funciones solo están disponibles si el algoritmo correspondiente está compilado en la biblioteca OpenSSL. Puede devolverse NULL si el algoritmo falla al cargarse dinámicamente.

NOTAS

Al comprimir datos no comprimibles, la salida puede ser mayor que la entrada. Debe tenerse cuidado de dimensionar los búferes de salida de manera apropiada tanto para la compresión como para la expansión.

El soporte de compresión y los algoritmos de compresión deben estar habilitados y compilados en la biblioteca antes de su uso. Consulte el archivo INSTALL.md al configurar OpenSSL.

ZLIB puede encontrarse en https://zlib.net

Brotli puede encontrarse en https://github.com/google/brotli.

Zstandard puede encontrarse en https://github.com/facebook/zstd.

No se recomienda la compresión de registros SSL/TLS, ya que se ha demostrado que conduce al ataque CRIME https://en.wikipedia.org/wiki/CRIME. Está deshabilitada de forma predeterminada y puede habilitarse limpiando la opción SSL_OP_NO_COMPRESSION y estableciendo el nivel de seguridad según corresponda. Consulte la documentación de las funciones SSL_CTX_set_options(3) y SSL_set_options(3) .

La compresión también se utiliza para admitir la compresión de certificados como se describe en RFC8879 https://datatracker.ietf.org/doc/html/rfc8879. Puede deshabilitarse mediante las opciones SSL_OP_NO_TX_CERTIFICATE_COMPRESSION y SSL_OP_NO_RX_CERTIFICATE_COMPRESSION de las funciones SSL_CTX_set_options(3) o SSL_set_options(3) .

COMP_zlib(), COMP_brotli() y COMP_zstd() son métodos de compresión basados en flujo. El estado interno (incluido el diccionario de compresión) se mantiene entre llamadas. Si se devuelve un error, el flujo está corrupto y debe cerrarse.

COMP_zlib_oneshot(), COMP_brotli_oneshot() y COMP_zstd_oneshot() no están basados en flujo. Estos métodos no mantienen estado entre llamadas. Un error en una llamada no afecta las llamadas futuras.

VALORES DE RETORNO

COMP_CTX_new() devuelve un COMP_CTX en caso de éxito, o NULL en caso de fallo.

COMP_CTX_get_method(), COMP_zlib(), COMP_zlib_oneshot(), COMP_brotli(), COMP_brotli_oneshot(), COMP_zstd(), y COMP_zstd_oneshot() devuelven un COMP_METHOD en caso de éxito, o NULL en caso de fallo.

COMP_CTX_get_type() y COMP_get_type() devuelven un valor NID. En caso de fallo, se devuelve NID_undef.

COMP_compress_block() y COMP_expand_block() devuelven el número de bytes almacenados en el búfer de salida out. Este puede ser 0. En caso de fallo, se devuelve -1.

COMP_get_name() devuelve un const char * que no debe liberarse en caso de éxito, o NULL en caso de fallo.

BIO_f_zlib(), BIO_f_brotli() y BIO_f_zstd() devuelven NULL en caso de error, y un BIO_METHOD en caso de éxito.

VÉASE TAMBIÉN

BIO_new(3), SSL_CTX_set_options(3), SSL_set_options(3)

HISTORIA

Las funciones de Brotli y Zstandard se añadieron en OpenSSL 3.2.
