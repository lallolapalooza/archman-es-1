Config::Grammar(3) Documentación de Perl aportada por el usuario Config::Grammar(3)

NOMBRE

Config::Grammar - Un analizador de configuración basado en gramática y fácil de usar

SINOPSIS

use Config::Grammar;
my $args = { encoding => 'utf8' }; # el segundo parámetro de parse() es opcional
my $parser = Config::Grammar->new(\%grammar);
my $cfg = $parser->parse('app.cfg', $args) or die "ERROR: $parser->{err}\n";
my $pod = $parser->makepod();
my $ex = $parser->maketmpl('TOP','SubNode');
my $minex = $parser->maketmplmin('TOP','SubNode');

DESCRIPCIÓN

Config::Grammar es un módulo para analizar archivos de configuración. El segundo parámetro opcional del método parse() puede usarse para especificar la codificación del archivo al abrirlo (consulte la documentación del pragma use open de Perl).

La configuración puede constar de secciones de múltiples niveles con asignaciones y datos tabulares. Los datos analizados se devolverán como un hash que contiene toda la configuración. Config::Grammar utiliza una gramática que se proporciona al crear un objeto Config::Grammar para analizar el archivo de configuración y devolver mensajes de error útiles en caso de errores de sintaxis. Usando el método makepod puede generar documentación del formato del archivo de configuración.

El método maketmpl puede generar un archivo de configuración de plantilla. Si su gramática contiene coincidencias de expresiones regulares, la plantilla no será muy útil, ya que Config::Grammar no es lo suficientemente inteligente para proporcionarle datos de plantilla sensatos basados en expresiones regulares. La función relacionada maketmplmin genera una plantilla de configuración mínima sin ejemplos, expresiones regulares o comentarios, y así permite a un usuario experimentado completar los datos de configuración de manera más eficiente.

Definición de la gramática

La gramática es un hash de hashes de múltiples niveles, que sigue la estructura de la configuración. Cada sección o variable está representada por un hash con la misma estructura. Cada hash contiene claves especiales que comienzan con un guion bajo, como '_sections', '_vars', '_sub' o '_re', para denotar metadatos con información sobre esa sección o variable. Otras claves se usan para estructurar el hash según la misma estructura de anidamiento de la configuración en sí. El hash inicial dado como parámetro a 'new' contiene la "sección raíz".

Claves especiales de sección

_sections
Arreglo que contiene la lista de subsecciones de esta sección. Cada subsección debe estar representada por un sub-hash en este hash con el mismo nombre de la subsección.

La subsección también puede ser una expresión regular denotada por la sintaxis '/re/', donde re es la expresión regular. En caso de usarse una expresión regular, debe incluirse en este hash un sub-hash nombrado con el mismo '/re/'.

_vars
Arreglo que contiene la lista de variables (asignaciones) en esta sección. De manera análoga a las secciones, se pueden usar expresiones regulares.
_mandatory
Arreglo que contiene la lista de secciones y variables obligatorias.
_inherited
Arreglo que contiene la lista de variables a las que se les debe asignar el mismo valor que en la sección padre si no se especifica nada aquí.
_table
Hash que contiene la gramática de la tabla (consulte Claves especiales de tabla). Si no se especifica, no se permite ninguna tabla en esta sección. La gramática de las columnas se especifica mediante sub-hashes nombrados con el número de columna.
_text
La sección contiene texto de formato libre. Solo se interpretarán secciones y @includes , el resto se añadirá al hash devuelto bajo '_text' como cadena.

_text es una referencia a hash que puede contener una clave _re y una clave _re_error que se usarán para examinar el texto... si el hash está vacío, se aceptará todo el texto.

_order
Si se define, se colocará un elemento '_order' en cada hash que contenga las secciones con un número que determine el orden en que se definieron las secciones.
_doc
Describe de qué trata esta sección.
_sub
Un puntero a función. Se llama para cada instancia de esta sección, con el nombre real de la sección pasado como su primer argumento. Esto probablemente solo sea útil para las secciones de expresiones regulares. Si la función devuelve un valor definido, se asume que la prueba no fue exitosa y se genera un error con la cadena devuelta como contenido.

Claves especiales de variable

_re
Expresión regular con la que se comprobará el valor.
_re_error
Cadena que contiene el error devuelto en caso de que la expresión regular no coincida (si no se especifica, se devolverá un mensaje genérico de 'error de sintaxis').
_sub
Un puntero a función. Se llama para cada valor, con el valor pasado como su primer argumento. Si la función devuelve un valor definido, se asume que la prueba no fue exitosa y se genera un error con la cadena devuelta como contenido.

Si la clave '_varlist' (ver arriba) está definida en esta sección, la función '_sub' también recibirá una referencia a arreglo como segundo argumento. El arreglo contiene una lista de esas variables ya definidas en la misma sección. Esto se puede usar para hacer cumplir el orden de las variables.

_default
Un valor predeterminado que se asignará a la variable si no se especifica ni se hereda ninguno.
_doc
Descripción de la variable.
_example
Un ejemplo de una línea para el contenido de esta variable.

Claves especiales de tabla

_columns
Número de columnas. Si no se especifica, no se hará cumplir.
_key
Si se define, el número de columna especificado se usará como clave en un hash dentro del hash devuelto. Si no se define, el hash devuelto contendrá un elemento '_table' con el contenido de la tabla como arreglo. Las filas de las tablas se almacenan como arreglos.
_sub
funcionan de manera análoga a la descripción en la sección anterior.
_doc
describe el contenido de la columna.
_example
ejemplo para el contenido de esta columna.

Claves especiales de texto

_re
Expresión regular con la que se comprobará el texto (todo como una sola línea).
_re_error
Cadena que contiene el error devuelto en caso de que la expresión regular no coincida (si no se especifica, se devolverá un mensaje genérico de 'error de sintaxis').
_sub
funcionan de manera análoga a la descripción en la sección anterior.
_doc
Ídem.
_example
Ejemplo potencialmente multilínea para el contenido de esta sección de texto.

Sintaxis de la configuración

Sintaxis general

'#' denota un comentario hasta el final de la línea, se permiten líneas vacías y el espacio al principio y al final de las líneas se recorta.

'\' al final de la línea marca una línea continuada en la siguiente línea. Se insertará un espacio único entre las líneas concatenadas.

'@include nombre_archivo' se usa para incluir otro archivo. La inclusión funciona de forma relativa al directorio donde se encuentra el archivo principal.

'@define a algún valor' reemplazará todas las apariciones de 'a' en el texto siguiente con 'algún valor'.

Los campos en tablas que contienen espacios en blanco pueden encerrarse en "'" o """. Los espacios en blanco también se pueden escapar con "\". Se permiten comillas dentro de comillas, pero también deben escaparse con una barra invertida.

Secciones

Config::Grammar soporta configuraciones jerárquicas a través de secciones, cuya sintaxis es la siguiente:

Nivel 1
*** nombre de sección ***
Nivel 2
+ nombre de sección
Nivel 3
++ nombre de sección
Nivel n, n>1
+..+ nombre de sección (el número de '+' determina el nivel)

Asignaciones

Las asignaciones toman la forma: 'variable = valor', donde el valor puede ser cualquier cadena (puede contener espacios en blanco y caracteres especiales). Los espacios antes y después del signo de igualdad son opcionales.

Datos tabulares

Los datos se interpretan como una o más columnas separadas por espacios.

Código

use Data::Dumper;
use Config::Grammar;
my $RE_IP       = '\d+\.\d+\.\d+\.\d+';
my $RE_MAC      = '[0-9a-f]{2}(?::[0-9a-f]{2}){5}';
my $RE_HOST     = '\S+';
my $parser = Config::Grammar->new({
  _sections => [ 'network', 'hosts' ],
  network => {
     _vars     => [ 'dns' ],
     _sections => [ "/$RE_IP/" ],
     dns       => {
        _doc => "dirección del servidor dns",
        _example => "ns1.oetiker.xs",
        _re => $RE_HOST,
        _re_error =>
           'dns debe ser un nombre de host o una dirección ip',
        },
     "/$RE_IP/" => {
        _doc    => "Dirección IP",
        _example => '10.2.3.2',
        _vars   => [ 'netmask', 'gateway' ],
        netmask => {
           _doc => "Máscara de red",
           _example => "255.255.255.0",
           _re => $RE_IP,
           _re_error =>
              'la máscara de red debe ser una dirección ip con puntos'
           },
        gateway => {
           _doc => "Dirección de la puerta de enlace predeterminada en notación IP",
           _example => "10.22.12.1",
           _re => $RE_IP,
           _re_error =>
              'la puerta de enlace debe ser una dirección ip con puntos' },
        },
     },
  hosts => {
     _doc => "Detalles sobre los hosts",
     _table  => {
         _doc => "Descripción de todos los hosts",
        _key => 0,
        _columns => 3,
        0 => {
           _doc => "Dirección Ethernet",
           _example => "0:3:3:d:a:3:dd:a:cd",
           _re => $RE_MAC,
           _re_error =>
              'la primera columna debe ser una dirección mac ethernet',
           },
        1 => {
           _doc => "Dirección IP",
           _example => "10.11.23.1",
           _re => $RE_IP,
           _re_error =>
              'la segunda columna debe ser una dirección ip con puntos',
           },
        2 => {
           _doc => "Nombre de host",
           _example => "tardis",
            },
        },
     },
  });
my $args = { encoding => 'utf8' }; # el segundo parámetro de parse() es opcional
my $cfg = $parser->parse('test.cfg', $args) or
  die "ERROR: $parser->{err}\n";
print Dumper($cfg);
print $parser->makepod;

  dns      = 192.168.7.87

+ 192.168.7.64

  00:50:fe:bc:65:12     192.168.7.98    isg.ee.hades
