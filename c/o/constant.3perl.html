constant(3perl) Guía de referencia del programador de Perl constant(3perl)

NOMBRE

constant - pragma de Perl para declarar constantes

SINOPSIS

use constant PI    => 4 * atan2(1, 1);
use constant DEBUG => 0;
print "Pi equals ", PI, "...\n" if DEBUG;
use constant {
    SEC   => 0,
    MIN   => 1,
    HOUR  => 2,
    MDAY  => 3,
    MON   => 4,
    YEAR  => 5,
    WDAY  => 6,
    YDAY  => 7,
    ISDST => 8,
};
use constant WEEKDAYS => qw(
    Sunday Monday Tuesday Wednesday Thursday Friday Saturday
);
print "Today is ", (WEEKDAYS)[ (localtime)[WDAY] ], ".\n";

DESCRIPCIÓN

Este pragma permite declarar constantes en tiempo de compilación.

Cuando se declara una constante como "PI" usando el método mostrado arriba, cada máquina en la que se ejecute su script puede tener tantos dígitos de precisión como pueda usar. Además, su programa será más fácil de leer, más probable de mantener (y mantener correctamente), y mucho menos probable que envíe una sonda espacial al planeta equivocado porque nadie notó la única ecuación en la que escribió 3.14195.

Cuando una constante se usa en una expresión, Perl la reemplaza con su valor en tiempo de compilación, y puede optimizar aún más la expresión. En particular, cualquier código en un bloque "if (CONSTANT)" será optimizado si la constante es falsa.

NOTAS

Al igual que con todas las directivas de "use", la definición de una constante ocurre en tiempo de compilación. Por lo tanto, probablemente no sea correcto poner una declaración de constante dentro de una declaración condicional (como "if ($foo) { use constant ... }").

Las constantes definidas usando este módulo no pueden ser interpoladas en cadenas como las variables. Sin embargo, la concatenación funciona bien:

print "Pi equals PI...\n";        # INCORRECTO: no expande "PI"
print "Pi equals ".PI."...\n";    # correcto

A pesar de que una referencia puede ser declarada como una constante, la referencia puede apuntar a datos que pueden ser modificados, como muestra este código.

use constant ARRAY => [ 1,2,3,4 ];
print ARRAY->[1];
ARRAY->[1] = " ser cambiado";
print ARRAY->[1];

Las constantes pertenecen al paquete en el que se definen. Para referirse a una constante definida en otro paquete, especifique el nombre completo del paquete, como en "Some::Package::CONSTANT". Los módulos pueden exportar constantes y también pueden ser llamadas como métodos de clase o de instancia, es decir, como "Some::Package->CONSTANT" o como "$obj->CONSTANT" donde $obj es una instancia de "Some::Package". Las subclases pueden definir sus propias constantes para anular las de su clase base.

A partir de la versión 1.32 de este módulo, las constantes se pueden definir en paquetes distintos al del llamador, incluyendo el nombre del paquete en el nombre de la constante:

use constant "OtherPackage::FWIBBLE" => 7865;
constant->import("Other::FWOBBLE",$value); # dinámicamente en tiempo de ejecución

El uso de mayúsculas para los nombres de las constantes es solo una convención, aunque se recomienda para que las constantes destaquen y para ayudar a evitar colisiones con otras palabras clave, palabras reservadas y nombres de subrutinas. Los nombres de las constantes deben comenzar con una letra o un guion bajo. Los nombres que comienzan con un doble guion bajo están reservados. Algunas malas elecciones de nombres generarán advertencias, si las advertencias están habilitadas en tiempo de compilación.

Listar constantes

Las constantes pueden ser listas de más (o menos) de un valor. Una constante sin valores se evalúa como "undef" en contexto escalar. Tenga en cuenta que las constantes con más de un valor no devuelven su último valor en contexto escalar como uno podría esperar. Actualmente devuelven el número de valores, pero esto puede cambiar en el futuro. No utilice constantes con múltiples valores en contexto escalar.

NOTA: Esto implica que la expresión que define el valor de una constante se evalúa en contexto de lista. Esto puede producir sorpresas:

use constant TIMESTAMP => localtime;                # INCORRECTO!
use constant TIMESTAMP => scalar localtime;         # correcto

La primera línea anterior define "TIMESTAMP" como una lista de 9 elementos, como la devuelve localtime() en contexto de lista. Para establecerla a la cadena devuelta por localtime() en contexto escalar, se requiere la palabra clave "scalar" explícita.

Las constantes de lista son listas, no matrices. Para indexarlas o cortarlas, deben colocarse entre paréntesis.

my @workdays = WEEKDAYS[1 .. 5];            # INCORRECTO!
my @workdays = (WEEKDAYS)[1 .. 5];          # correcto

Definir múltiples constantes a la vez

En lugar de escribir múltiples sentencias "use constant", puede definir múltiples constantes en una sola sentencia proporcionando, en lugar del nombre de la constante, una referencia a un hash donde las claves son los nombres de las constantes a definir. Obviamente, todas las constantes definidas usando este método deben tener un único valor.

use constant {
    FOO => "A single value",
    BAR => "This", "won't", "work!",        # Error!
};

Esta es una limitación fundamental de la forma en que se construyen los hashes en Perl. Los mensajes de error que se producen cuando esto sucede suelen ser bastante crípticos; en el peor de los casos, puede que no haya ninguno, y solo más tarde descubrirá que algo está roto.

Al definir múltiples constantes, no puede usar los valores de otras constantes definidas en la misma declaración. Esto se debe a que el paquete llamador no conoce ninguna constante dentro de ese grupo hasta *después* de que finaliza la sentencia "use".

use constant {
    BITMASK => 0xAFBAEBA8,
    NEGMASK => ~BITMASK,                    # Error!
};

Constantes mágicas

Los valores y referencias mágicas pueden convertirse en constantes en tiempo de compilación, permitiendo cosas geniales como esta. (Estos números de error no son del todo portátiles, lamentablemente).

use constant E2BIG => ($! = 7);
print   E2BIG, "\n";        # algo como "Arg list too long"
print 0+E2BIG, "\n";        # "7"

No puede producir una constante enlazada proporcionando un escalar enlazado como valor. Sin embargo, las referencias a variables enlazadas se pueden usar como constantes sin ningún problema.

NOTAS TÉCNICAS

En la implementación actual, las constantes escalares son en realidad subrutinas en línea. A partir de la versión 5.004 de Perl, la constante escalar apropiada se inserta directamente en lugar de algunas llamadas a subrutinas, ahorrando así la sobrecarga de una llamada a subrutina. Consulte "Constant Functions" en perlsub para obtener detalles sobre cómo y cuándo ocurre esto.

En el raro caso en que necesite descubrir en tiempo de ejecución si una constante particular ha sido declarada a través de este módulo, puede usar esta función para examinar el hash %constant::declared. Si el nombre de constante dado no incluye un nombre de paquete, se usa el paquete actual.

sub declared ($) {
    use constant 1.01;              # ¡no omitir esto!
    my $name = shift;
    $name =~ s/^::/main::/;
    my $pkg = caller;
    my $full_name = $name =~ /::/ ? $name : "${pkg}::$name";
    $constant::declared{$full_name};
}

ADVERTENCIAS

Las constantes de lista no se insertan en línea a menos que esté usando Perl v5.20 o superior. En v5.20 o superior, todavía no son de solo lectura, pero eso puede cambiar en versiones futuras.

No es posible tener una subrutina o una palabra clave con el mismo nombre que una constante en el mismo paquete. Esto es probablemente algo bueno.

Una constante con un nombre en la lista "STDIN STDOUT STDERR ARGV ARGVOUT ENV INC SIG" no está permitida en ningún lugar que no sea el paquete "main::", por razones técnicas.

constant(3perl) - Perl 5.42.0 documentation

NAME

constant - create symbolic constants

SYNOPSIS

  use constant PI => 4;
  use constant {
      WIDTH  => 10,
      HEIGHT => 20,
  };
  print PI;
  print WIDTH * HEIGHT;

DESCRIPTION

The constant pragma provides a way to define symbolic constants in Perl. These constants are essentially subroutines that return a fixed value.

Constants are defined using the use constant declaration, which takes a name and a value.

  use constant NAME => VALUE;

The NAME will be the name of the subroutine created, and VALUE will be the value returned by that subroutine whenever it is called.

For example:

  use constant DEBUG => 1;
  if (DEBUG) {
      print "Debugging is enabled\n";
  }

You can also define multiple constants at once:

  use constant {
      NAME1 => VALUE1,
      NAME2 => VALUE2,
      ...
  };

For example:

  use constant {
      LOG_LEVEL => 'info',
      MAX_RETRIES => 3,
  };

Constants defined this way are constants within the lexical scope they are declared. This means they are not visible outside the block in which they are declared unless explicitly exported.

Constants can be exported using the standard Perl export mechanism.

  our @ISA = qw(Exporter);
  our %EXPORT_TAGS = (DEFAULT => [qw(PI ANOTHER_CONST)]);
  our @EXPORT_OK = qw(PI ANOTHER_CONST);

  use constant PI => 4;
  use constant ANOTHER_CONST => 'hello';
  ...

The values can be any valid Perl expression that evaluates to a scalar.

  use constant MAX_VAL => 2**31 - 1;
  use constant ARRAY_REF => [1, 2, 3];
  use constant HASH_REF => { a => 1, b => 2 };

Note that constants are implemented as subroutines. This means that they are called like subroutines. For example, to access an element in an array or hash defined as a constant:

  use constant MY_ARRAY => [10, 20, 30];
  print MY_ARRAY->[1]; # Prints 20
  print MY_ARRAY->();   # Prints the whole array reference

  use constant MY_HASH => { name => 'Perl', version => '5.36' };
  print MY_HASH->{name}; # Prints 'Perl'
  print MY_HASH->();    # Prints the whole hash reference

However, a common shortcut is to use the bareword form for array and hash access, just as you would with array and hash variables.

  use constant MY_ARRAY => [10, 20, 30];
  print MY_ARRAY[1]; # Prints 20

  use constant MY_HASH => { name => 'Perl', version => '5.36' };
  print MY_HASH{name}; # Prints 'Perl'

This shortcut works because Perl implicitly calls the constant subroutine when it sees the bareword array/hash access syntax.

NOTES

Constants are evaluated only once when the file is compiled. This means that constants cannot depend on runtime values (e.g., command line arguments, environment variables).

Constants are not variables. You cannot assign a new value to a constant.

  use constant PI => 3.14;
  PI = 4; # This will cause a compile-time error

The constant pragma should be used instead of defining your own subroutines for constants whenever possible, as it can lead to more efficient code.

TECHNICAL NOTES

Constants are implemented as subroutines. When you write

  use constant PI => 3.14;

Perl essentially generates code equivalent to:

  sub PI () { 3.14 }

The empty parentheses () indicate that the subroutine takes no arguments. This is important for performance, as it allows Perl to optimize the call.

When you use a constant in a context where it looks like a bareword string literal (e.g., as a hash key or in a string context), Perl will automatically quote it as a string. To prevent this, you need to explicitly call the constant subroutine.

  use constant FOO => 'bar';
  my %hash = ( FOO => 1 ); # This creates a hash with key "FOO"
  my %hash2 = ( FOO() => 1 ); # This creates a hash with key "bar"

You can also use the non-lexical scope modifier + to explicitly call the subroutine:

  my %hash3 = (+FOO => 1); # This creates a hash with key "bar"

The same applies to contexts where barewords are automatically quoted, like in method calls or certain string interpolations.

CAVEATS

You can get into trouble if you use constants in a context which automatically quotes barewords (as is true for any subroutine call). For example, you can't say $hash{CONSTANT} because "CONSTANT" will be interpreted as a string. Use $hash{CONSTANT()} or $hash{+CONSTANT} to prevent the bareword quoting mechanism from kicking in. Similarly, since the "=>" operator quotes a bareword immediately to its left, you have to say "CONSTANT() => 'value'" (or simply use a comma in place of the big arrow) instead of "CONSTANT => 'value'".
