- Las clases de impresión vectorizada son para renderizar a dispositivos vectoriales en lugar de dispositivos rasterizados.

Descripción Detallada

Las clases de impresión vectorizada son para renderizar a dispositivos vectoriales en lugar de dispositivos rasterizados.

Puede utilizar esto, por ejemplo, para generar imágenes escalables en PostScript para imprimir en lugar de imágenes rasterizadas que se pixelarán cuando las escale.

Ver más abajo para Una visión general de HardCopy. Una visión general de HardCopy

La API principal para el soporte de HardCopy en Coin es la clase abstracta SoVectorizeAction. SoVectorizeAction extraerá geometría de un grafo de escena de Inventor y proyectará la geometría en una página especificada. Dado que PostScript y otros formatos de archivo basados en vectores no admiten el búfer z ni el recorte de profundidad, toda la geometría se renderiza utilizando un simple algoritmo de pintor (la geometría se ordena según la distancia a la cámara).

SoVectorizePSAction hereda de SoVectorizeAction y generará un archivo PostScript.

Los polígonos texturizados no son compatibles, ya que no lo son por los formatos de archivo vectoriales, al menos no son compatibles en PostScript. El sombreado Gouraud no es compatible en el lenguaje PostScript (al menos no para V2.0), pero se implementa una aproximación utilizando un algoritmo que divide el triángulo en varios triángulos pequeños (con sombreado plano). La calidad del sombreado Gouraud (el número de subtriángulos) se controla mediante un valor épsilon. La función de sombreado Gouraud está escrita por Frederic Delhoume (delhoume (at) ilog.fr) y es software libre (dominio público).

El uso típico de SoVectorizePSAction se muestra en el siguiente fragmento de código:

SoVectorizePSAction * ps = new SoVectorizePSAction;
SoVectorOutput * out = ps->getOutput();
if (!out->openFile("output.ps")) {
  return -1; // no se pudo abrir el archivo de salida
}
// para habilitar el sombreado Gouraud. 0.1 es un buen valor épsilon
// ps->setGouraudThreshold(0.1f);
// limpiar a fondo blanco. Realmente no es necesario si
// quieres un fondo blanco
ps->setBackgroundColor(TRUE, SbColor(1.0f, 1.0f, 1.0f));
// seleccionar orientación LANDSCAPE o PORTRAIT
ps->setOrientation(SoVectorizeAction::LANDSCAPE);
// empezar a crear una nueva página (página A4, con un borde de 10 mm).
ps->beginPage(SbVec2f(10.0f, 10.0f), SbVec2f(190.0f, 277.0f));
// También hay enumeraciones para A0-A10. Ejemplo:
// ps->beginStandardPage(SoVectorizeAction::A4, 10.0f);
// calibrar para que el texto, las líneas, los puntos y las imágenes tengan el
// mismo tamaño en el archivo PostScript que en el monitor.
ps->calibrate(viewer->getViewportRegion());
// aplicar la acción en el grafo de escena del visor. Recuerda usar
// el grafo de escena de SoSceneManager para que la cámara esté incluida.
ps->apply(viewer->getSceneManager()->getSceneGraph());
// esto creará el archivo PostScript
ps->endPage();
// cerrar archivo
out->closeFile();
delete ps;

También es posible tener varias vistas y/o capas en una página. Esto es útil si su aplicación tiene varias capas de geometría, por ejemplo, algunas anotaciones en 2D encima de un grafo de escena 3D. Para crear varias capas, se pueden utilizar las funciones beginViewport() y endViewport().
