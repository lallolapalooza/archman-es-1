NOMBRE

containers-certs.d - Directorio para almacenar configuraciones TLS personalizadas de registros de contenedores

DESCRIPCIÓN

Una configuración TLS personalizada para un registro de contenedores se puede configurar creando un directorio bajo $HOME/.config/containers/certs.d o /etc/containers/certs.d. El nombre del directorio debe corresponder al host[:puerto] del registro (p.ej., mi-registro.com:5000).

La presencia o ausencia de la parte del puerto debe coincidir exactamente con el uso del puerto en las referencias de imagen, p.ej. para afectar a podman pull registry.example/foo, usa un directorio llamado registry.example, no registry.example:443. registry.example:443 afectaría a podman pull registry.example:443/foo.

Estructura del directorio

Un directorio de certificados puede contener uno o más archivos con las siguientes extensiones:

  • Los archivos *.crt con estas extensiones se interpretarán como certificados CA
  • Los archivos *.cert con estas extensiones se interpretarán como certificados de cliente
  • Los archivos *.key con estas extensiones se interpretarán como claves de cliente

Tenga en cuenta que el par certificado-clave de cliente se seleccionará por el nombre del archivo (p.ej., cliente.{cert,key}). Una configuración ejemplar para un registro que se ejecuta en my-registry.com:5000 podría verse así:

/etc/containers/certs.d/    <- Directorio de certificados
└── my-registry.com:5000    <- Nombre de host[:puerto]
   ├── client.cert          <- Certificado de cliente
   ├── client.key           <- Clave de cliente
   └── ca.crt               <- Autoridad certificadora que firmó el certificado del registro
