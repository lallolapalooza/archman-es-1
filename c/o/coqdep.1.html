NOMBRE

coqdep - calcula dependencias intermódulos para programas Coq

SINOPSIS

coqdep [ -I directorio ] [ -coqlib directorio ] [ -i ] [ -slash ] archivo ... directorio ...

DESCRIPCIÓN

coqdep calcula dependencias intermódulos para programas Coq, y imprime las dependencias en la salida estándar en un formato legible por make. Cuando se proporciona un directorio como argumento, este se explora recursivamente.

Las dependencias de los módulos Coq se calculan examinando los comandos Require (Require, Require Export, Require Import, posiblemente restringidos por una cláusula From), los comandos Declare ML Module, los comandos Add LoadPath y los comandos Load. Las dependencias relativas a módulos de la biblioteca Coq no se imprimen, a menos que se proporcione -boot.

OPCIONES

-f archivo
Lee nombres de archivo y opciones -I, -R y -Q desde un archivo _CoqProject.
-I/-Q/-R opciones
Tienen el mismo efecto en la ruta de carga y los nombres de los módulos que para otros comandos Coq (coqtop, coqc).
-coqlib directorio
Indica dónde se encuentra la biblioteca Coq. El valor predeterminado se determinó en el momento de la instalación, y por lo tanto, esta opción no debería usarse en circunstancias normales.
-exclude-dir dir
Omite el subdirectorio dir durante la búsqueda de -R/-Q.
-sort
Imprime el nombre de archivo dado ordenado por dependencias.
-vos
Imprime las dependencias de los archivos .vos (este no es el valor predeterminado, ya que rompe el modo Coq de dune).
-boot
Para desarrolladores de Coq, imprime las dependencias sobre los archivos de la biblioteca Coq (omitido por defecto).
-noinit
Actualmente sin efecto.
-vos
Incluye dependencias sobre archivos .vos.
-dyndep (opt|byte|both|no|var)
Establece cómo se imprimen las dependencias sobre módulos ML.
-m meta
Resuelve nombres de plugins usando el archivo meta.
-w w1,...,wn
Configura la visualización de advertencias como para coqc.

ESTADO DE SALIDA

1
No se puede encontrar un archivo proporcionado en la línea de comandos, o no se puede abrir algún archivo, o hay un error de sintaxis en uno de los comandos reconocidos por coqdep.
0
En todos los demás casos. En particular, cuando no se puede encontrar una dependencia o se encuentra una opción inválida, coqdep imprime una advertencia y sale con estado 0.

VER TAMBIÉN

ocamlc(1), coqc(1), make(1)

NOTAS

Los analizadores léxicos (para Coq y OCaml) manejan correctamente los comentarios anidados y las cadenas de texto.

El tratamiento de los enlaces simbólicos es primitivo.

Si dos archivos tienen el mismo nombre, en dos directorios diferentes, se imprime una advertencia en la salida de error estándar.

No hay forma de limitar el alcance de la búsqueda recursiva de directorios.

EJEMPLOS

Considere los archivos (en el mismo directorio):

a.mllib, X.v, Y.v, y Z.v
donde
  • a.mllib contiene los nombres de módulo `B' y `C';
  • Y.v contiene el comando `Require Foo.X';
  • Z.v contiene los comandos `From Foo Require X' y `Declare ML Module "a"'.

Para obtener las dependencias de los archivos Coq:

example% coqdep -I . -Q . Foo *.v
X.vo X.glob X.v.beautified X.required_vo: X.v
Y.vo Y.glob Y.v.beautified Y.required_vo: Y.v X.vo
Z.vo Z.glob Z.v.beautified Z.required_vo: Z.v X.vo ./a.cma ./a.cmxs

ERRORES

Por favor, informe cualquier error en https://github.com/coq/coq/issues.
