NOMBRE

Convert::BinHex - extraer datos de archivos BinHex de Macintosh

ADVERTENCIA ALPHA: este código se encuentra actualmente en su versión Alpha. Las cosas pueden cambiar drásticamente hasta que la interfaz se defina: si tienes sugerencias o objeciones, ¡háglas saber ahora!

SINOPSIS

Funciones simples:

use Convert::BinHex qw(binhex_crc macbinary_crc);
# Calcular el CRC estilo HQX7 para los datos, inyectando el CRC antiguo si se desea:
$crc = binhex_crc($data, $crc);
# Calcular el CRC estilo MacBinary-II para los datos:
$crc = macbinary_crc($data, $crc);

Hex a bin, interfaz de bajo nivel. La conversión se realiza realmente a través de un objeto ("Convert::BinHex::Hex2Bin") que mantiene el estado interno de la conversión:

# Crear y usar un objeto "traductor":
my $H2B = Convert::BinHex->hex2bin;    # obtener un objeto convertidor
while (<STDIN>) {
    print $STDOUT $H2B->next($_);        # convertir algo más de entrada
}
print $STDOUT $H2B->done;              # sin más entrada: finalizar

Hex a bin, interfaz OO. Las siguientes operaciones deben realizarse en el orden mostrado.

# Leer datos por partes:
$HQX = Convert::BinHex->open(FH=>\*STDIN) || die "open: $!";
$HQX->read_header;                  # leer información de la cabecera
@data = $HQX->read_data;            # leer todos los datos
@rsrc = $HQX->read_resource;        # leer todos los recursos

Bin a hex, interfaz de bajo nivel. La conversión se realiza realmente a través de un objeto ("Convert::BinHex::Bin2Hex") que mantiene el estado interno de la conversión:

# Crear y usar un objeto "traductor":
my $B2H = Convert::BinHex->bin2hex;    # obtener un objeto convertidor
while (<STDIN>) {
    print $STDOUT $B2H->next($_);        # convertir algo más de entrada
}
print $STDOUT $B2H->done;              # sin más entrada: finalizar

Bin a hex, interfaz de archivo. Sí, puedes convertir a BinHex así como desde él.

# Crear un nuevo objeto vacío:
my $HQX = Convert::BinHex->new;
# Establecer atributos de la cabecera:
$HQX->filename("logo.gif");
$HQX->type("GIFA");
$HQX->creator("CNVS");
# Proporcionarle los forks de datos y recursos (cualquiera de los dos puede faltar):
$HQX->data(Path => "/ruta/a/datos");       # aquí, los datos están en disco
$HQX->resource(Data => $resourcefork);     # aquí, el recurso está en memoria
# Salida como un flujo BinHex, completo con el comentario inicial:
$HQX->encode(\*STDOUT);

¡¡¡PLANIFICADO!!! Bin a hex, interfaz "CAP". Gracias a Ken Lunde por sugerir esto.

# Crear un nuevo objeto vacío desde un árbol CAP:
my $HQX = Convert::BinHex->from_cap("/ruta/a/raiz/archivo");
$HQX->encode(\*STDOUT);

DESCRIPCIÓN

BinHex es un formato utilizado por Macintosh para transportar archivos Mac de forma segura a través del correo electrónico, como flujos de datos de 7 bits, de líneas cortas y semicomprimidos. Este módulo proporciona un medio para convertir esos flujos de datos de vuelta a datos binarios.

FORMATO

(Parte del texto tomado de la RFC-1741.) Los archivos en Macintosh consisten en dos partes, llamadas forks:

Fork de datos (Data fork)
Los datos reales incluidos en el archivo. El fork de datos es típicamente la única parte significativa de un archivo Macintosh en un sistema informático no Macintosh. Por ejemplo, si un usuario de Macintosh quiere enviar un archivo de datos a un usuario de un IBM-PC, ella solo enviaría el fork de datos.
Fork de recursos (Resource fork)
Contiene una colección de pares de atributos/valores arbitrarios, incluyendo segmentos de programa, mapas de bits de iconos y valores paramétricos.

La información adicional sobre los archivos Macintosh es almacenada por el Finder en un archivo oculto, llamado "Desktop Database" (Base de Datos de Escritorio).

Debido a las complicaciones de almacenar diferentes partes de un archivo Macintosh en un sistema de archivos no Macintosh que solo maneja datos consecutivos en una parte, es común convertir el archivo Macintosh a algún otro formato antes de transferirlo a través de la red. El formato BinHex comprime esos datos en ASCII transmisible de la siguiente manera:

1.
El archivo se emite como un flujo de bytes que consiste en algo de información básica de cabecera (nombre de archivo, tipo, creador), luego el fork de datos, luego el fork de recursos.
2.
El flujo de bytes se comprime buscando series de bytes duplicados y representándolos usando una secuencia de escape binaria especial (por supuesto, cualquier ocurrencia del carácter de escape también debe escaparse).
3.
El flujo comprimido se codifica a través de la "hemiola 6/8" común a base64 y uuencode: cada grupo de tres bytes de 8 bits (24 bits) se divide en cuatro números de 6 bits, que se usan como índices en un "alfabeto" ASCII. (Asumo que los bytes sobrantes se rellenan con ceros; la documentación es escasa).

FUNCIONES

Cálculo de CRC

macbinary_crc DATOS, SEMILLA
Calcula el CRC estilo MacBinary-II para los DATOS dados, con el CRC inicializado a la SEMILLA. Normalmente, se comienza con una SEMILLA de 0, y se inyecta el CRC anterior como la SEMILLA si estás manejando muchos datos un trozo a la vez. Es decir: 
$crc = 0;
while (<STDIN>) {
    $crc = macbinary_crc($_, $crc);
}

Nota: Extraído de la utilidad mcvert (Doug Moore, abril de '87), usando un algoritmo de "matriz mágica" de Jim Van Verth para mayor eficiencia. Convertido a Perl5 por Eryq. Sin probar.

binhex_crc DATOS, SEMILLA
Calcula el CRC estilo HQX para los DATOS dados, con el CRC inicializado a la SEMILLA. Normalmente, se comienza con una SEMILLA de 0, y se inyecta el CRC anterior como la SEMILLA si estás manejando muchos datos un trozo a la vez. Es decir: 
$crc = 0;
while (<STDIN>) {
    $crc = binhex_crc($_, $crc);
}

Nota: Extraído de la utilidad mcvert (Doug Moore, abril de '87), usando un algoritmo de "matriz mágica" de Jim Van Verth para mayor eficiencia. Convertido a Perl5 por Eryq.

INTERFAZ OO

Conversión

bin2hex
Método de clase, constructor. Devuelve un objeto convertidor. Solo crea una nueva instancia de "Convert::BinHex::Bin2Hex"; consulta esa clase para más detalles.
hex2bin
Método de clase, constructor. Devuelve un objeto convertidor. Solo crea una nueva instancia de "Convert::BinHex::Hex2Bin"; consulta esa clase para más detalles.

Construcción

new PARAMHASH
Método de clase, constructor. Devuelve un manejador sobre una entidad convertible a BinHex. En general, los forks de datos y recursos para dicha entidad se almacenan en formato nativo (binario).

Los parámetros en el PARAMHASH son los mismos que los nombres de los métodos orientados a cabecera, y pueden usarse para establecer atributos:

$HQX = new Convert::BinHex filename => "icon.gif",
                           type    => "GIFB",
                           creator => "CNVS";
open PARAMHASH
Método de clase, constructor. Devuelve un manejador sobre un nuevo flujo BinHex, para su análisis. Los parámetros son:
Data
Entrada de un flujo HEX desde los datos dados. Puede ser un escalar, o una referencia a un arreglo de escalares.
Expr
Entrada de un flujo HEX desde cualquier expresión open()válida. Será abierta y puesta en modo binario, y el manejador de archivo se cerrará ya sea en un close() o cuando el objeto sea destruido.
FH
Entrada de un flujo HEX desde el manejador de archivo dado.
NoComment
Si es verdadero, el analizador no debe intentar omitir un comentario inicial "(This file...)"t; comentario. Eso significa que los primeros caracteres no blancos encontrados deben ser los datos codificados en binhex.

Obtener/establecer información de cabecera

creator [VALOR]
Método de instancia. Obtener/establecer el creador del archivo. Esta es una cadena de cuatro caracteres (aunque no sé si está garantizado que sea ASCII imprimible!) que sirve como parte de la versión de Macintosh de un "content-type" MIME.

Por ejemplo, un documento creado por "Canvas" podría tener como creador "CNVS".

data [PARAMHASH]
Método de instancia. Obtener/establecer el data fork. Cualquier argumento se pasa al new() método de "Convert::BinHex::Fork".
filename [VALOR]
Método de instancia. Obtener/establecer el nombre del archivo.
flags [VALOR]
Método de instancia. Devuelve los flags, como un entero. Usa enmascaramiento de bits para obtener los valores que necesites.
header_as_string
Devuelve una versión en cadena de la cabecera que podrías usar con fines de registro/depuración. Se ve así: 
X-HQX-Software: BinHex 4.0 (Convert::BinHex 1.102)
X-HQX-Filename: Something_new.eps
X-HQX-Version: 0
X-HQX-Type: EPSF
X-HQX-Creator: ART5
X-HQX-Data-Length: 49731
X-HQX-Rsrc-Length: 23096

Como algunos de vosotros habréis adivinado, esto es al estilo RFC-822, y puede colocarse fácilmente en medio de una cabecera de correo, o dividirse en líneas, etc.

requires [VALOR]
Método de instancia. Obtener/establecer la versión de software requerida para convertir este archivo, tal como se extrajo del comentario que precedía a los datos binhex'eados; por ejemplo: 
(This file must be converted with BinHex 4.0)

En este caso, después de analizar el comentario, el código:

$HQX->requires;

devolvería "4.0".

resource [PARAMHASH]
Método de instancia. Obtener/establecer el resource fork. Cualquier argumento se pasa al new() método de "Convert::BinHex::Fork".
type [VALOR]
Método de instancia. Obtener/establecer el tipo del archivo. Esta es una cadena de cuatro caracteres (aunque no sé si está garantizado que sea ASCII imprimible!) que sirve como parte de la versión de Macintosh de un "content-type" MIME.

Por ejemplo, un archivo GIF89a podría tener como tipo "GF89".

version [VALOR]
Método de instancia. Obtener/establecer la versión, como un entero.

Decodificar, a nivel alto

read_comment
Método de instancia. Salta el comentario inicial en el archivo, que tiene la forma: 
(This file must be converted with BinHex 4.0)

Según la RFC-1741, este comentario debe preceder inmediatamente a los datos BinHex, y cualquier texto anterior a él será ignorado.

No necesitas invocar este método tú mismo; read_header() lo hará por ti. Después de la llamada, el número de versión en el comentario es accesible a través del requires() método.

read_header
Método de instancia. Lee la cabecera del archivo BinHex. ¡Debes hacer esto primero!
read_data [NBYTES]
Método de instancia. Lee información del data fork. Úsalo en un contexto de array para absorber todos los datos en un array de escalares: 
@data = $HQX->read_data;

O úsalo en un contexto escalar para obtener los datos por partes:

while (defined($data = $HQX->read_data)) {
   # haz cosas con $data
}

El NBYTES a leer por defecto es 2048.

read_resource [NBYTES]
Método de instancia. Lee todo/algunos datos del resource fork. Ver read_data() para el uso.

Codificar, a nivel alto

encode OUT
Codifica el objeto como un flujo BinHex hacia el manejador de salida OUT dado. OUT puede ser un filehandle, o cualquier objeto bendito que responda a un print() mensaje.

El comentario inicial se emite, usando el requires() atributo.

SUBMÓDULOS

Convert::BinHex::Bin2Hex

Un convertidor de BINario a HEX. Este tipo de conversión requiere una cierta cantidad de información de estado; no se puede hacer simplemente llamando a una función simple repetidamente. Úsalo así:

# Crea y usa un objeto "traductor":
my $B2H = Convert::BinHex->bin2hex;    # obtén un objeto convertidor
while (<STDIN>) {
    print STDOUT $B2H->next($_);          # convierte algo más de entrada
}
print STDOUT $B2H->done;               # no más entrada: termina
# Reutiliza el objeto:
$B2H->rewind;                 # ¡listo para más acción!
while (<MOREIN>) { ...

En cada iteración, next() (y done()) puede devolver tanto una cadena no vacía de tamaño decente (indicando que hay más datos convertidos listos para ti) o una cadena vacía (indicando que el convertidor está esperando a acumular más entrada en sus buffers privados antes de entregarte más cosas para la salida.

Ten en cuenta que done() siempre convierte y te entrega lo que queda.

Puede que este haya sido un buen enfoque. Puede que no. Algún día, el convertidor puede permitirte darle un objeto que responda a read(), o un FileHandle, y hará todo el desagradable rellenado de buffers por su cuenta, sirviéndote cosas línea por línea:

# Algún día, quizás...
my $B2H = Convert::BinHex->bin2hex(\*STDIN);
while (defined($_ = $B2H->getline)) {
    print STDOUT $_;
}

En cada iteración, next() (y done()) puede devolver tanto una cadena no vacía de tamaño decente (indicando que hay más datos convertidos listos para ti) o una cadena vacía (indicando que el convertidor está esperando a acumular más entrada en sus buffers privados antes de entregarte más cosas para la salida.

Ten en cuenta que done() siempre convierte y te entrega lo que queda.

Ten en cuenta que este convertidor no no encuentra el comentario inicial de "BinHex version". Tienes que saltártelo tú mismo. Solo maneja datos entre la apertura y el cierre ":".

Convert::BinHex::Fork

Un fork en un archivo Macintosh.

# Cómo obtenerlos...
$data_fork = $HQX->data;      # obtén el data fork
$rsrc_fork = $HQX->resource;  # obtén el resource fork
# Crea un nuevo fork:
$FORK = Convert::BinHex::Fork->new(Path => "/tmp/file.data");
$FORK = Convert::BinHex::Fork->new(Data => $scalar);
$FORK = Convert::BinHex::Fork->new(Data => \@array_of_scalars);
# Obtén/establece la longitud del data fork:
$len = $FORK->length;
$FORK->length(170);        # ¡esto anula el valor REAL: ten cuidado!
# Obtén/establece la ruta a los datos subyacentes (si está en un archivo de disco):
$path = $FORK->path;
$FORK->path("/tmp/file.data");
# Obtén/establece los datos en memoria, que pueden ser un escalar o una referencia a array:
$data = $FORK->data;
$FORK->data($scalar);
$FORK->data(\@array_of_scalars);
# Obtén/establece el CRC:
$crc = $FORK->crc;
$FORK->crc($crc);

Problemas de diseño

BinHex necesita un analizador con estado
A diferencia de sus primos base64 y uuencode, el formato BinHex no es propicio para ser analizado línea por línea. Parece no haber garantía de que las líneas contengan 4n caracteres codificados... e incluso si la hay, el algoritmo de compresión de BinHex interfiere: incluso cuando puedes decodificar una línea a la vez, no puedes necesariamente descomprimir una línea a la vez.

Por ejemplo: una línea decodificada que termine con el byte "\x90" (el carácter de escape o "marca" ) es ambigua: dependiendo del siguiente byte decodificado, podría significar un "\x90" literal (si el siguiente byte es un "\x00"), o podría significar n-1 repeticiones más del carácter anterior (si el siguiente byte es algún no cero "n").

Por esta razón, un analizador BinHex debe ser algo con estado: no puedes tener código como este:

#### ¡NO! #### ¡NO! #### ¡NO! #### ¡NO! #### ¡NO! ####
while (<STDIN>) {            # lee HEX
    print hexbin($_);          # convierte y escribe BIN
}

a menos que algo esté sucediendo "detrás de escena" para llevar la cuenta de lo que se hizo la última vez. Lo peligroso, sin embargo, es que este enfoque parecerá funcionarrk, si solo lo pruebas en archivos BinHex que no usan compresión y que tienen 4n caracteres HEX en cada

línea.
