NOMBRE

Constraint — La clase de widget Constraint

SINOPSIS

#include <Xm/Xm.h>

DESCRIPCIÓN

Los widgets Constraint mantienen datos de estado adicionales para cada hijo. Por ejemplo, se pueden especificar restricciones definidas por el cliente sobre la geometría del hijo.

Cuando un widget compuesto con restricciones define recursos de restricción, todos los hijos de ese widget heredan todos esos recursos como propios. Estos recursos de restricción se establecen y leen igual que cualquier otro recurso definido para el hijo. Esta herencia de recursos se extiende exactamente una generación hacia abajo, lo que significa que solo los hijos de primera generación de un widget compuesto con restricciones heredan los recursos de restricción del widget padre.

Debido a que los recursos de restricción son definidos por los widgets padre y no por los hijos, los widgets hijos nunca usan directamente los datos del recurso de restricción. En su lugar, los padres usan los datos del recurso de restricción para adjuntar datos específicos del hijo a los hijos.

Clases

Constraint hereda comportamiento y recursos de Composite y Core.

El puntero de clase es constraintWidgetClass.

El nombre de la clase es Constraint.

Nuevos recursos

Constraint no define nuevos recursos.

Recursos heredados

Constraint hereda comportamiento y recursos de Composite y Core. La siguiente tabla define un conjunto de recursos de widget usados por el programador para especificar datos. El programador también puede establecer los valores de los recursos de las clases heredadas para establecer atributos para este widget. Para referirse a un recurso por nombre o por clase en un archivo .Xdefaults , elimine el prefijo " XmN " o " XmC " y use las letras restantes. Para especificar uno de los valores definidos para un recurso en un archivo .Xdefaults , elimine el prefijo Xm y use las letras restantes (en minúsculas o mayúsculas, pero incluyendo cualquier guion bajo entre palabras). Los códigos en la columna de acceso indican si el recurso dado se puede establecer en el momento de la creación (C), establecer usando XtSetValues (S), recuperar usando XtGetValues (G), o no es aplicable (N/A).
