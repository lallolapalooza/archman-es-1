NOMBRE

cockpit-tls - Proxy TLS para el servicio web de Cockpit

SINOPSIS

cockpit-tls [--help] [--port PUERTO] [--no-tls] [--idle-timeout SEGUNDOS]

DESCRIPCIÓN

El programa cockpit-tls es un proxy HTTP de terminación TLS para cockpit-ws(8). Gestiona un conjunto de instancias aisladas de cockpit-ws, una por certificado de cliente TLS, más una para TLS sin certificado de cliente y otra para HTTP sin cifrar. Con ello, una sesión no puede interferir con otra a través de posibles vulnerabilidades de seguridad.

Los usuarios o administradores nunca deberían necesitar iniciar este programa, ya que se inicia automáticamente por systemd(1) mediante activación por socket.

SEGURIDAD DEL TRANSPORTE

Para especificar el certificado TLS que debe usar el servicio web, simplemente coloque un archivo con la extensión .cert en el directorio /etc/cockpit/ws-certs.d o debajo de $XDG_CONFIG_DIRS si está configurado (ver cockpit.conf(5)[1]). Si hay varios archivos en este directorio, se elegirá el de mayor prioridad después de ordenarlos.

El archivo .cert debe contener al menos dos bloques PEM estilo OpenSSL. Primero uno o más bloques BEGIN CERTIFICATE para el certificado del servidor y las autoridades de certificación intermedias, y un segundo bloque que contenga un BEGIN PRIVATE KEY o similar. La clave no debe estar cifrada.

Si no hay ningún certificado TLS, se genera automáticamente un certificado autofirmado usando sscg (si está disponible) o openssl y se almacena en el archivo 0-self-signed.cert.

Al inscribirse en un dominio FreeIPA, se solicita un certificado SSL al servidor IPA y se almacena en 10-ipa.cert.

Para comprobar qué certificado usará cockpit-ws, ejecute el siguiente comando.

$ sudo /usr/libexec/cockpit-certificate-ensure --check

O, en sistemas basados en Debian:

$ sudo /usr/lib/cockpit/cockpit-certificate-ensure --check

Si utiliza certmonger para gestionar certificados, el siguiente comando puede usarse para generar un par certificado/clave:

CERT_FILE=/etc/cockpit/ws-certs.d/50-certmonger.crt
KEY_FILE=/etc/cockpit/ws-certs.d/50-certmonger.key
getcert request -f ${CERT_FILE} -k ${KEY_FILE} -D $(hostname --fqdn)

OPCIONES

--help

Muestra las opciones de ayuda.

--port PUERTO

Sirve las solicitudes HTTP en PUERTO en lugar del puerto 9090. Normalmente, Cockpit se inicia bajo demanda mediante la activación por socket de systemd, y esta opción no tiene ningún efecto. Actualice la directiva ListenStream del archivo cockpit.socket de la forma habitual de systemd.

--no-tls

No utilice TLS. No se leerán los certificados y se denegarán las conexiones https. Entonces cockpit-tls solo gestionará una única instancia de cockpit-ws, y por lo tanto no hará nada diferente a ejecutar cockpit-ws --no-tls directamente. Úselo solo para depuración o pruebas.

--idle-timeout SEGUNDOS

Si es mayor que 0, salga si no ha habido conexiones durante el número dado de segundos, es decir, el servidor está inactivo. Si no se proporciona, el valor predeterminado es 90.

ENTORNO

El programa cockpit-tls espera que la variable de entorno RUNTIME_DIRECTORY esté configurada como un directorio vacío (preferiblemente en /run/) al que solo pueda acceder el usuario del sistema bajo el cual se está ejecutando. Esto contiene los sockets Unix para comunicarse con las instancias de cockpit-ws y, en el futuro, información de estado sobre los certificados de cliente. Esta variable normalmente la establece la unidad systemd cockpit.service.

Además, cockpit-tls utilizará la variable de entorno XDG_CONFIG_DIRS de la especificación XDG basedir[2] para encontrar sus certificados y el archivo de configuración cockpit.conf(5).
