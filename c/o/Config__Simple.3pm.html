RESUME

N

Leer y escribir archivos de configuración es una de las tareas más frecuentes en cualquier diseño de software. Config::Simple es la biblioteca que le ayuda con

ello.

Config::Simple es una clase que representa un objeto de archivo de configuración. Soporta varias s

intaxis de archivos de configuración e intenta identificar la sintaxis del archivo automáticament
e. La biblioteca soporta el análisis, la actualización y la creación de archivos de configuración.

ACERCA DE LOS ARCHIVOS DE

CONFIGURACIÓN

Mantener variables configurables en el código fuente de su programa es feo, realmente. Y para las personas sin mucha experiencia en programación, configurar sus programas es como realizar magia negra. Además, si necesita acceder a estos valores desde múltiples archivos, quiere que sus programas sean capaces de actualizar archivos de configuración o quiere proporcionar una interfaz de usuario más amigable para sus archivos de configuración, simplemente tiene que almacenarlos en un archivo externo. Ahí es donde entra en juego Config::Simple, haciendo que sea muy fácil leer y escribir archivos de

configuración.

Si nunca ha usado archivos de configuración antes, aquí hay un breve resumen de varias sintaxis para elegir. De lo contrario, puede saltar a "ESTILO DE

PROGRAMACIÓN".

ARCHIVO DE CONFIGURACIÓN

SIMPLE

La sintaxis simple es lo que necesita para la mayoría de sus proyectos. Estos son, como el nombre afirma, los más simples. El archivo consiste en pares clave/valor, delimitados únicamente por espacio en blanco. Las claves (variables) deben ser estrictamente alfanuméricas con guiones (-) posibles. Los valores pueden contener cualquier texto arbitrario. Aquí hay un ejemplo de un archivo de configuración de este

tipo: 
Alias     /exec
TempFile
/usr/tmp

Los comentarios comienzan con un signo de alm

ohadilla ('#') y no pueden compartir la mism
a línea con otros datos de configuración.

SINTAXIS SIMILAR A

HTTP

Este formato de separar pares clave/valor es utilizado por los mensajes HTTP. Cada clave/valor está separada por un punto y coma (:). Las claves son cadenas alfanuméricas con guiones ('-') posibles. Los valores pueden ser cualquier texto

arbitrario:

ARCHIVO

INI

Estos archivos de configuración son más nativos de los sistemas Win32. Los datos están organizados en bloques. Cada par clave/valor está delimitado con un signo igual (=). Los bloques se declaran en sus propias líneas encerrados en '[' y ']

': 
[BLOQUE1]
CLAVE1=VALOR1
CLAVE2=VALOR2
[BLOQUE2]
CLAVE1=VALOR1
CLAVE2=VALOR2

tipo.

ESTILO DE

PROGRAMACIÓN

La mayoría de los programas simplemente necesitan poder leer ajustes de un archivo de configuración y asignarlos a un hash. Si eso es todo lo que necesita, puede simplemente usar su import_from() - método de clase con el nombre del archivo de configuración y una referencia a un hash existente (posiblemente vacío)

: 
Config::Simple->import_from('myconf.cfg', \%Config)
;

Ahora su hash %Config contiene todos los pares clave/valor del archivo de configuración. Las claves de un hash son nombres de variables dentro de su archivo de configuración, y los valores son sus respectivos valores. Si "myconf.cfg" era un archivo ini tradicional, las claves del hash consisten en el nombre del bloque y la variable delimitados por un punto, como "bloque.

variable".

Si eso es todo lo que necesita, puede detenerse aquí. De lo contrario, siga leyendo. Config::Simple ofrece mucho

más.

LEYENDO EL ARCHIVO DE

CONFIGURACIÓN

Para poder usar más características de la biblioteca, necesitará usar su interfaz de

objetos: 
$cfg = new Config::Simple('app.cfg')
;

La línea anterior lee y analiza el archivo de configuración en consecuencia. Intenta adivinar qué sintaxis se usa pasando el archivo a el método guess_syntax(). Alternativamente, puede crear un objeto vacío, y solo entonces leer el archivo de

configuración: 
$cfg = new Config::Simple();
$cfg->read('app.cfg')
;

Como en el primer ejemplo, read() también llama al método guess_syntax() en el

archivo.

Si, por alguna razón, falla en adivinar la sintaxis correctamente (lo cual es menos probable), puede intentar depurar usando su método guess_syntax(). Espera un manejador de archivo para un archivo de configuración y devuelve el nombre de una sintaxis. El valor de retorno es uno de "ini", "simple" o

"http". 
open(FH, "app.cfg");
printf("Este archivo usa la sintaxis '%s'\n", $cfg->guess_syntax(\*FH)
)
;

ACCEDIENDO A

VALORES

Después de leer el archivo de configuración con éxito, puede usar el método param() para acceder a los valores de configuración. Por

ejemplo: 
$user = $cfg->param("User")
;

devolverá el valor de "User" tanto de un archivo de configuración simple, como de una configuración con estilo http, así como de archivos ini simplificados. Para acceder al valor de un archivo ini tradicional, considere la siguiente

sintaxis: 
$user = $cfg->param("mysql.user")
;

Lo anterior devuelve el valor de "user" de dentro del bloque "[mysql]". Observe el uso del punto "." para delimitar los nombres de bloque y

clave.

Config::Simple también soporta el método vars(), que, dependiendo del contexto usado, devuelve todos los valores ya sea como hashref o como

hash: 
my %Config = $cfg->vars();
print "Nombre de usuario: $Config{User}";
# Si era un archivo ini tradicional:
print "Nombre de usuario: $Config{'mysql.user'}
";

Si llama a vars() en contexto escalar, terminará con una referencia a un

hash: 
my $Config = $cfg->vars();
print "Nombre de usuario: $Config->{User}
";

Si sabe lo que está haciendo, también tiene la opción de importar todos los nombres del archivo de configuración a su espacio de nombres actual como variables globales. Todos los nombres de bloque/clave estarán en mayúsculas y se convertirán en nombres de variables válidos de Perl; es decir, todos los puntos (separador bloque-clave) y otros caracteres '\W' se sustituirán con un guion bajo

'_': 
$cfg = new Config::Simple('app.cfg');
$cfg->import_names();
# o, con una sola línea:
Config::Simple->new('app.cfg')->import_names();

print STDERR "El modo de depuración está activado" if $MODO_DEPURACION
;

En el ejemplo anterior, si había un variable 'mode' under '[debug]' block, it will be now accessible via $DEBUG_MODE, as opposed to $cfg->param('debug.mode')

;

import_names() by default imports the values to its caller's name space. Optionally, you can specify where to import the values by passing the name of the name space as the first argument. It also prevents potential name

collisions: 
Config::Simple->new('app.cfg')->import_names('CFG');
print STDERR "Debugging mode is on" if $CFG::
DEBUG_MODE;

If all you want is to import values from a configuration file, the above syntax may still seem longer than necessary. That's why Config::Simple supports import_from() - class method, which is called with the name of the configuration file. It will call import_names() for

you: 
Config::Simple->import_from('app.cfg')
;

The above line imports all the variables into the caller's name space. It's similar to calling import_names() on an object. If you pass a string as the second argument, it will treat it as the alternative name space to import the names into. As we already showed in the very first example, you can also pass a reference to an existing hash as the second argument. In this case, that hash will be modified with the values of the configuration

file. 
# import into $CFG name space:
Config::Simple->import_from('app.cfg', 'CFG');
# import into %Config hash:
Config::Simple->import_from('app.cfg', \%Config)
;

The above line imports all the values to 'CFG' name space. import_from() returns underlying Config::Simple object (which you may not even need anymore)

: 
$cfg = Config::Simple->import
_from('app.cfg', \my %Config)
; $cfg->write('app.cfg.bak');

ACTUALIZANDO LOS

VALORES

Los valores de configuración, una vez leídos en Config::Simple, pueden actualizarse desde dentro de su programa utilizando el mismo método param() utilizado para acceder a ellos. Por

ejemplo: 
$cfg->param("User", "sherzodR")
;

La línea anterior cambia el valor de "User" a "sherzodR". La sintaxis similar es aplicable para archivos ini

también: 
$cfg->param("mysql.user", "sherzodR")
;

Si la clave que intenta actualizar no existe, se creará. Por ejemplo, para añadir un nuevo bloque "[session]" a su archivo ini, asumiendo que este bloque no existe

ya: 
$cfg->param("session.life", "+1M")
;

También puede eliminar valores llamando al método delete() con el nombre de la

variable: 
$cfg->delete('mysql.us
er'); # elimina 'user'
bajo el bloque [mysql]

GUARDANDO/ESCRIBIENDO ARCHIVOS DE

CONFIGURACIÓN

Las actualizaciones anteriores a los valores de configuración son operaciones en memoria. No se reflejan en el archivo mismo. Para modificar los archivos en consecuencia, necesita llamar a "write()" o "save()" en el

objeto: 
$cfg->write()
;

La línea anterior escribe las modificaciones en el archivo de configuración. Alternativamente, puede pasar un nombre a write() o save() para indicar el nombre del archivo a crear en lugar de modificar el archivo de configuración

existente: 
$cfg->write("app.cfg.bak")
;

Si desea que los cambios se guarden en todo momento, puede activar el modo "autosave" pasando un valor verdadero a $cfg->autosave(). Se asegurará de que antes de que su programa termine, todos los valores de configuración se escriban de vuelta en su

archivo: 
$cfg = new Config::
Simple('aff.cfg');
$cfg->autosave(1);

CREANDO ARCHIVOS DE

CONFIGURACIÓN

Ocasionalmente, sus programas pueden querer crear sus propios archivos de configuración al vuelo, posiblemente desde una entrada del usuario. Para crear un archivo de configuración desde cero usando Config::Simple, simplemente cree un objeto de archivo de configuración vacío y defina su sintaxis. Puede hacerlo pasando la opción "syntax" a new(), o llamando al método syntax(). Luego juegue con el método param() como lo haría normalmente. Cuando termine, llame al método write() con el nombre del archivo de

configuración: 
$cfg = new Config::Simple(syntax=>'ini');
# o también podría hacer:
# $cfg->autosave('ini')
$cfg->param("mysql.dsn", "DBI:mysql:db;host=handalak.com");
$cfg->param("mysql.user", "sherzodr");
$cfg->param("mysql.pass", 'marley01');
$cfg->param("site.title", 'sherzodR "The Geek"');
$cfg->write("new.cfg")
;

Esto crea un archivo "new.cfg" con el siguiente

contenido: 
; Config::Simple 4.43
; Sat Mar  8 00:32:49 2003
[site]
title=sherzodR "The Geek"
[mysql]
pass=marley01
dsn=DBI:mysql:db;host=handalak.com
user=sherzodr

¿Bonito, verdad? Las palabras clave de sintaxis soport

adas son "ini", "simple" o "http". Actualmente no
hay soporte para crear archivos ini simplificados.

MÚLTIPLES

¿Alguna vez ha querido definir un arreglo de valores en su única variable de configuración? ¡Yo sí! Por eso Config::Simple también soporta esta característica elegante. Simplemente separe sus valores con una

coma: 
Files hp.cgi, template.html, styles.
css

Ahora el método param() devuelve un arreglo de

valores: 
@files = $cfg->param("Files");
unlink $_ for
@files;

Si quiere que una coma sea parte de un valor, encierre el/los valor(es) en comillas

dobles: 
CVSFiles "hp.cgi,v", "template.html,v", "styles.css,
v"

En caso de que quiera que alguno de los valores contenga una comilla literal ("), puede escaparla con una barra

invertida:

INTERFAZ

TIE

Si el estilo OO le intimida, y import_from() es demasiado simple para usted, Config::Simple también soporta la interfaz tie(). Esta interfaz le permite hacer tie() a un hash Perl ordinario con el archivo de configuración. Desde ese punto en adelante, puede usar la variable como un hash Perl

ordinario. 
tie %Config, "Config::Simple", 'app.cfg';
# Usando %Config como un hash ordinario
print "Username is '$Config{User}'\n";
$Config{User} =
'sherzodR';

La diferencia entre "import_from($file, \%Hash)" es que todos los cambios que haga al hash después de hacer tie(), también se reflejarán en el objeto de archivo de configuración. Si autosave() estaba activado, también se escribirán de vuelta al

archivo: 
tie %Config, "Config::Simple", "app.cfg";
tied(%Config)->autosave(1)
;

Para acceder al método proporcionado en la sintaxis OO, necesita obtener el objeto Config::Simple subyacente. Puede hacerlo con la función tied()

: 
tied(%Config)->write()
;

ADVERTENCIA: la interfaz tie

es experimental y no está bi
en probada todavía. Avíse
me si encuentra un problema.

DIVERSO

S

SENSIBILIDAD A MAYÚSCULAS/MINÚSCUL

AS

Por defecto, las claves y valores del archivo de configuración distinguen entre mayúsculas y minúsculas. Lo que significa que $cfg->param("User") y $cfg->param("user") se refieren a dos valores diferentes. Pero es posible forzar a Config::Simple a ignorar los casos por completo activando el interruptor "-lc" mientras carga la

biblioteca: 
use Config::Simple ('-lc')
;

ADVERTENCIA: Si llama a write() o save(), mientras trabaja en el modo "-lc", toda la información de mayúsculas/minúsculas del arch

ivo original se perderá. Así que ú
selo si sabe lo que está haciendo.

USANDO

COMILLAS

Algunas personas sugieren que si los valores consisten en cadenas no alfanuméricas, deberían encerrarse en comillas dobles. ¡Bueno, dígaselo a ellos! Aunque Config::Simple ya soporta analizar tales archivos de configuración, no sigue esta regla al escribirlos. Si realmente necesita que genere tales archivos de configuración compatibles, el interruptor "-strict" es lo que

necesita: 
use Config::Simple
'-strict';

Ahora, cuando escriba los datos de configuración de vuelta a los archivos, si los valo

res contienen cualquier cadena no alfanumérica, serán comillados en consecuencia. Todas
las comillas dobles que sean parte del valor serán escapadas con una barra invertida.

MANEJO DE

EXCEPCIONES

Config::Simple no cree en morir tan fácilmente (a menos que lo insulte usando sintaxis incorrecta). Deja la decisión al programador que implementa la biblioteca. Puede usar su método de clase error() para acceder al mensaje de error subyacente. Los métodos que requieren que verifique sus valores de retorno son read() y write(). Si pasa un nombre de archivo a new(), también necesitará verificar su valor de retorno. Devuelven cualquier valor verdadero indicando éxito, undef en caso

contrario: 
# el siguiente new() siempre devuelve true:
$cfg = new Config::Simple();
# read() puede fallar:
$cfg->read('app.cfg') or die $cfg->error();
# el
siguiente new() puede fallar: $cfg = new Config::Simple('app.cfg') or die Config::Simple->error(); # import_from() llama a read(), así que puede
fallar: Config::Simple->import_from('app.cfg', \%Config) or die Config::Simple->error(); # write() puede fallar: $cfg->write() or die $cfg->erro
r(); # tie() puede fallar, ya que llama a new() con un nombre de archivo tie %Config, "Config::Simple", 'app.cfg' or die Config::Simple->error();
