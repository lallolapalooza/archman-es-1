DESCRIPCIÓ

N

Esta página documenta la sintaxis de los archivos de configuración de OpenSSL, tal como son analizados por NCONF_load(3) y funciones relacionadas. Este formato es utilizado por muchos de los comandos de OpenSSL, y para inicializar las bibliotecas cuando son utilizadas por cualquier

aplicación.

La primera parte describe la sintaxis general de los archivos de configuración, y las secciones posteriores describen la semántica de los módulos individuales. Otros módulos se describen en fips_config(5) y x509v3_config(5). La sintaxis para definir valores ASN.1 se describe en ASN1_generat

e_nco
nf(3).

SINTAXI

S

Un archivo de configuración es una serie de líneas. Las líneas en blanco y el espacio en blanco entre los elementos de una línea no tienen significado. Un comentario comienza con un carácter #; el resto de la línea se ignora. Si el # es el primer carácter no espaciador en una línea, toda la línea se

ignora.

Directiva

s

Se pueden usar dos directivas para controlar el análisis de los archivos de configuración: .include y .prag

ma.

Por compatibilidad con versiones anteriores de OpenSSL, un signo igual después de la directiva se ignorará. Las versiones anteriores lo tratarán como una asignación, por lo que se debe tener cuidado si la diferencia en la semántica es

importante.

Un archivo puede incluir otros archivos usando la sintaxis de

inclusión: 
.include [=]
nombre_de_ruta

Si nombre_de_ruta es un nombre de archivo simple, ese archivo se incluye directamente en ese punto. Los archivos incluidos pueden tener declaraciones .include que especifiquen otros archivos. Si nombre_de_ruta es un directorio, todos los archivos dentro de ese directorio que tengan una extensión ".cnf" o ".conf" serán incluidos. (Esto solo está disponible en sistemas con soporte de E/S POSIX.) Cualquier subdirectorio encontrado dentro del nombre_de_ruta se ignora. De manera similar, si un archivo se abre mientras se escanea un directorio, y ese archivo tiene una directiva .include que especifica un directorio, ese también se

ignora.

Como regla general, el nombre_de_ruta debe ser una ruta absoluta; esto se puede hacer cumplir con las pragmas abspath y includedir, descritos más abajo. La variable de entorno OPENSSL_CONF_INCLUDE, si existe, se antepone a todos los nombres de ruta relativos. Si el nombre de ruta sigue siendo relativo, se interpreta basándose en el directorio de trabajo

actual.

Para requerir que todas las inclusiones de archivos especifiquen rutas absolutas, use la siguiente

directiva: 
.pragma [=] abspath:
valor

El comportamiento predeterminado, donde el valor es false o off, es permitir rutas relativas. Para requerir que todos los nombres de ruta de .include sean rutas absolutas, use un valor de true o on

.

En estos archivos, el signo de dólar, $, se usa para referenciar una variable, como se describe más abajo. Sin embargo, en algunas plataformas, es común tratar $ como un carácter regular en los nombres de símbolos. Se puede admitir este comportamiento con la siguiente

directiva: 
.pragma [=] dollarid:
valor

El comportamiento predeterminado, donde el valor es false o off, es tratar el signo de dólar como indicador de un nombre de variable; "foo$bar" se interpreta como "foo" seguido de la expansión de la variable "bar". Si el valor es true o on, entonces "foo$bar" es un solo nombre de siete caracteres y las expansiones de variables deben especificarse usando llaves o

paréntesis. 
.pragma [=] includedir:
valor

Si se especifica un nombre de ruta relativo en la directiva .include, y la variable de entorno OPENSSL_CONF_INCLUDE no existe, entonces el valor del pragma includedir, si existe, se

antepone al
nombre de ruta.

Configuracion

es

Un archivo de configuración está dividido en un número de secciones. Una sección comienza con el nombre de la sección entre corchetes y termina cuando comienza una nueva sección, o al final del archivo. El nombre de la sección puede consistir en caracteres alfanuméricos y guiones bajos. El espacio en blanco entre el nombre y los corchetes se

elimina.

La primera sección de un archivo de configuración es especial y se conoce como la sección predeterminada. Esta sección generalmente no tiene nombre y se extiende desde el inicio del archivo hasta la primera sección con nombre. Cuando se busca un nombre, primero se busca en la sección actual o con nombre, y luego en la sección predeterminada si es

necesario.

El entorno se mapea a una sección llamada ENV

.

Dentro de una sección hay una serie de asignaciones de nombre/valor, descritas con más detalle a continuación. Como recordatorio, los corchetes que se muestran en este ejemplo son obligatorios, no

opcionales: 
[ sección ]
nombre1 = Este es el valor1
nombre2 = Otro valor
...
[ nuevasección ]
nombre1 = Nuevo valor1
nombre3 = Valor
3

El nombre puede contener cualquier carácter alfanumérico así como algunos símbolos de puntuación como . , ; y _. El espacio en blanco después del nombre y antes del signo igual se

ignora.

Si un nombre se repite en la misma sección, todos los valores excepto el último se ignoran. En ciertas circunstancias, como con los DN de certificado, el mismo campo puede aparecer varias veces. Para soportar esto, comandos como openssl-req(1) ignoran cualquier texto inicial que esté precedido por un punto. Por

ejemplo: 
1.OU = Primera OU
2.OU = Segunda
OU

El valor consiste en la cadena que sigue al carácter = hasta el final de la línea, con cualquier espacio en blanco inicial y final

eliminado.

La cadena de valor sufre expansión de variables. El texto $var o "${var}" inserta el valor de la variable con nombre de la sección actual. Para usar un valor de otra sección, use $sección::nombre o "${sección::nombre}". Usando $ENV::nombre, se sustituirá el valor de la variable de entorno

especificada.

Las variables deben definirse antes de que se referencie su valor, de lo contrario se señala un error y el archivo no se cargará. Esto se puede evitar especificando un valor predeterminado en la sección predeterminada antes de que se use la

variable.

Cualquier configuración de nombre/valor en una sección ENV está disponible para el archivo de configuración, pero no se propaga al

entorno.

Es un error si el valor resulta ser más largo que

64k.

Es posible escapar ciertos caracteres usando una sola comilla ' o doble comilla " alrededor del valor, o usando una barra invertida \ antes del carácter. Haciendo que el último carácter de una línea sea una \, una cadena de valor puede extenderse a través de múltiples líneas. Además, las secuencias \n, \r, \b y \t son

reconocidas.

Las reglas de expansión y escape descritas anteriormente que se aplican al valor también se aplican al nombre de ruta de la directiv

a .
incl
ude.

CONFIGURACIÓN DE LA BIBLIOTECA

OPENSSL

Las secciones siguientes usan el término informal módulo para referirse a una parte de la funcionalidad de OpenSSL. Esto no es lo mismo que el término formal módulo FIPS, por

ejemplo.

La configuración de OpenSSL busca el valor de openssl_conf en la sección predeterminada y toma ese como el nombre de una sección que especifica cómo configurar cualquier módulo en la biblioteca. No es un error dejar cualquier módulo en su configuración predeterminada. Una aplicación puede especificar un nombre diferente llamando a CONF_modules_load_file(), por ejemplo,

directamente.

OpenSSL también busca el valor de config_diagnostics. Si esto existe y tiene un valor numérico distinto de cero, cualquier indicador de supresión de errores pasado a CONF_modules_load() será ignorado. Esto es útil para diagnosticar configuraciones incorrectas, pero su uso en producción requiere consideraciones adicionales. Con esta opción habilitada, un error de configuración impedirá completamente el acceso a un servicio. Sin esta opción y en presencia de un error de configuración, se permitirá el acceso pero la configuración deseada no será

usada. 
# Estos deben estar en la sección predeterminadan
config_diagnostics = 1
openssl_conf = openssl_init
[openssl_init]
oid_section = oids
providers = providers
alg_section = evp_properties
ssl_conf = ssl_configuration
engines = engines
random = random
[oids]
... nuevos oid aquí ...
[providers]
... configuración de proveedores aquí ...
[evp_properties]
... propiedades EVP aquí ...
[ssl_configuration]
... propiedades de configuración SSL/TLS aquí ...
[engines]
... configuración de motores aquí ...
[random]
... configuración aleatoria aquí ..
.

La frase "en la sección de inicialización" se refiere a la sección identificada por el openssl_conf u otro nombre (dado como openssl_init en el ejemplo anterior). Los ejemplos siguientes asumen que la configuración anterior se utiliza para especificar las secciones

individuales.

Las asignaciones nombre/valor en esta sección nombran cada una un proveedor y apuntan a la sección de configuración para ese proveedor. La sección específica del proveedor se utiliza para especificar cómo cargar el módulo, activarlo y establecer otros

Configuración

SSL

El nombre ssl_conf en la sección de inicialización nombra la sección que contiene la lista de configuraciones SSL/TLS. Al igual que con los proveedores, cada nombre en esta sección identifica una sección con la configuración para ese nombre. Por

ejemplo: 
[ssl_configuration]
server = server_tls_config
client = client_tls_config
system_default = tls_system_default
[server_tls_config]
... configuración para servidores SSL/TLS ...
[client_tls_config]
... configuración para clientes SSL/TLS ..
.

El nombre de configuración system_default tiene un significado especial. Si existe, se aplica cada vez que se crea un objeto SSL_CTX. Por ejemplo, para imponer versiones mínimas de protocolo TLS y DTLS en todo el

sistema: 
[tls_system_default]
MinProtocol = TLSv1.2
MinProtocol = DTLSv1.
2

El protocolo TLS mínimo se aplica a los objetos SSL_CTX que son basados en TLS, y el protocolo DTLS mínimo a aquellos que son basados en DTLS. Lo mismo se aplica también a las versiones máximas establecidas con MaxProtocol

.

Cada sección de configuración consta de pares nombre/valor que son analizados por SSL_CONF_cmd(3), que será llamada por SSL_CTX_config() o SSL_config(), según corresponda. Tenga en cuenta que cualquier carácter antes de un punto inicial en la sección de configuración se ignora, de modo que el mismo comando puede usarse varias veces. Esto probablemente sea más útil para cargar diferentes tipos de claves, como se muestra

aquí: 
[server_tls_config]
RSA.Certif
icate = server-rsa.pem ECDSA.
Certificate = server-ecdsa.pem

HISTORI

A

Una API no documentada, NCONF_WIN32(), usaba un conjunto ligeramente diferente de reglas de análisis que estaban destinadas a adaptarse a la plataforma Microsoft Windows. Específicamente, el carácter de barra invertida no era un carácter de escape y podía usarse en ruta

s de archivo, solo se reconocía el carácter de comilla doble, y los comentarios comenzaban con punto y coma. Esta funci
ón quedó obsoleta en OpenSSL 3.0; las aplicaciones con archivos de configuración que usen esa sintaxis deberán modificarse.
