NOMBRE

containers-transports - descripción de transportes compatibles para copiar y almacenar imágenes de contenedores

DESCRIPCIÓN

Las herramientas que utilizan la biblioteca containers/image, incluyendo skopeo(1), buildah(1), podman(1), comparten una sintaxis común para referenciar imágenes de contenedores en varias ubicaciones. La forma general de la sintaxis es transporte:detalles, donde los detalles dependen del transporte especificado, los cuales se documentan a continuación.

La semántica de los nombres de imagen depende en última instancia del entorno donde se evalúan. Por ejemplo: si se evalúan en un servidor remoto, los nombres de imagen podrían referirse a rutas en ese servidor; las rutas relativas son relativas al directorio actual del consumidor de la imagen.

containers-storage:[[especificador-almacenamiento]]{id-imagen|referencia-docker[@id-imagen]}

Una imagen ubicada en un almacenamiento de contenedores local. El formato de referencia-docker se describe en detalle en el transporte docker.

El especificador-almacenamiento permite referenciar ubicaciones de almacenamiento en el sistema de archivos y tiene el formato [[driver@]root[+run-root][:opciones]] donde el driver opcional se refiere al driver de almacenamiento (por ejemplo, overlay o btrfs) y donde root es una ruta absoluta al directorio raíz del almacenamiento. El run-root opcional puede usarse para especificar el directorio de ejecución del almacenamiento donde se almacena todo el contenido temporal escribible. Las opciones opcionales son una lista separada por comas de opciones específicas del driver. Consulte containers-storage.conf(5) para obtener más información sobre los drivers y las opciones compatibles.

dir:ruta

Un directorio local existente ruta que almacena el manifiesto, los archivos tar de capas y las firmas como archivos individuales. Este es un formato no estandarizado, principalmente útil para depuración o inspección no invasiva de contenedores.

docker://referencia-docker

Una imagen en un registro que implementa la "API HTTP V2 del Registro Docker". Por defecto, utiliza el estado de autorización en $XDG_RUNTIME_DIR/containers/auth.json, que se establece usando podman-login(1). Si el estado de autorización no se encuentra allí, se comprueba $HOME/.docker/config.json, que se establece usando docker-login(1). containers-registries.conf(5) permite además configurar varios ajustes de un registro.

Tenga en cuenta que una referencia-docker tiene el siguiente formato: nombre[:etiqueta | @digesto]. Si bien el transporte docker no admite una etiqueta y un digesto al mismo tiempo, algunos formatos como containers-storage sí lo hacen. Los digestos también se pueden usar en un destino de imagen siempre que el manifiesto coincida con el digesto proporcionado.

El transporte docker admite el envío de imágenes sin etiqueta ni digesto a un registro cuando el nombre de la imagen se sufija con @@unknown-digest@@. El formato de referencia nombre@@unknown-digest@@ no se puede usar con una referencia que tenga una etiqueta o digesto. El digesto de las imágenes se puede explorar con skopeo-inspect(1).

Si nombre no contiene una barra, se trata como docker.io/library/nombre. De lo contrario, se verifica el componente anterior a la primera barra para ver si se reconoce como un nombre-host ⟨es decir, contiene un `.` o un `:`, o el componente es exactamente `localhost`⟩. Si el primer componente de nombre no se reconoce como nombre-host[:puerto], nombre se trata como docker.io/nombre.

docker-archive:ruta[:{referencia-docker|@indice-origen}]

Una imagen almacenada en un archivo con formato docker-save(1).

A menos que una herramienta documente explícitamente lo contrario, una escritura a un destino docker-archive: sobrescribe completamente ruta, reemplazándola con la única imagen proporcionada.

La ruta puede referirse a un flujo, por ejemplo, docker-archive:/dev/stdin.

referencia-docker no debe contener un digesto. Alternativamente, para leer archivos, @indice-origen es un índice basado en cero en el manifiesto del archivo (para acceder a imágenes sin etiqueta). Si no se especifica ni referencia-docker ni @_indice_origen_ al leer un archivo, el archivo debe contener exactamente una imagen.

docker-daemon:referencia-docker|algo:digesto

Una imagen almacenada en el almacenamiento interno del demonio de docker. La imagen debe especificarse como una referencia-docker o en un formato alternativo algo:digesto cuando se usa como fuente de imagen. El algo:digesto se refiere al ID de imagen informado por docker-inspect(1).

oci:ruta[:{referencia|@indice-origen}]

Una imagen en una estructura de directorio que cumple con la "Open Container Image Layout Specification" en ruta.

El valor ruta termina en el primer carácter :; cualquier carácter : posterior no son separadores, sino parte de referencia. La referencia se utiliza para establecer o coincidir con la anotación org.opencontainers.image.ref.name en el índice de nivel superior. Para leer imágenes, @indice-origen es un índice basado en cero en el manifiesto (para acceder a imágenes sin etiqueta). Si no se especifica referencia ni @_indice_origen_ al leer una imagen, la ruta debe contener exactamente una imagen.

oci-archive:ruta[:referencia]

Una imagen en un archivo tar(1) con contenido compatible con la "Open Container Image Layout Specification" en ruta.

A menos que una herramienta documente explícitamente lo contrario, una escritura a un destino oci-archive: sobrescribe completamente ruta, reemplazándola con la única imagen proporcionada.

El valor ruta termina en el primer carácter :; cualquier carácter : posterior no son separadores, sino parte de referencia. La referencia se utiliza para establecer o coincidir con la anotación org.opencontainers.image.ref.name en el índice de nivel superior. Si no se especifica referencia al leer un archivo, el archivo debe contener exactamente una imagen.

sif:ruta

Una imagen que utiliza el formato de imagen Singularity en ruta.

Solo se admite la lectura de imágenes, y no todos los scripts se pueden representar en el formato OCI.

Ejemplos

Los siguientes ejemplos demuestran cómo se pueden usar algunos de los transportes de contenedores. Los ejemplos utilizan skopeo-copy(1) para copiar imágenes de contenedores.

Copiar una imagen de un registro a otro:

$ skopeo copy docker://docker.io/library/alpine:latest docker://localhost:5000/alpine:latest

Copiar una imagen de un demonio Docker en ejecución a un directorio en el diseño OCI:

$ mkdir alpine-oci
$ skopeo copy docker-daemon:alpine:latest oci:alpine-oci
$ tree alpine-oci

Copiar una imagen de un registro al almacenamiento local:

$ skopeo copy docker://docker.io/library/alpine:latest containers-storage:alpine:latest
