Infla el contenido completo de $input y escribe los datos descomprimidos en $output. Los parámetros $input y $output pueden ser escalares o referencias a

escalares.

Devuelve "Z_OK" si es exitoso y "Z_STREAM_END" si se ha alcanzado con éxito el final de los datos

Si la opción "ConsumeInput" se ha establecido en true cuando se creó el objeto "Compress::Raw::Zlib::Inflate", el parámetro $input es modificado por "inflate". Al completarse, contendrá lo que queda del búfer de entrada después de la inflación. En la práctica, esto significa que cuando el estado de retorno es "Z_OK", el parámetro $input contendrá una cadena vacía, y cuando el estado de retorno es "Z_STREAM_END", el parámetro $input contendrá lo que (si hay algo) estaba almacenado en el búfer de entrada después del flujo de datos

deflado.

Esta característica es útil al procesar un formato de archivo que encapsula un flujo de datos comprimido (p. ej., gzip, zip) y hay datos útiles inmediatamente después del flujo de

deflación.

Si la opción "AppendOutput" se establece en true en el constructor de este objeto, los datos descomprimidos se añadirán a $output. Si es false, $output se truncará antes de que se escriba en él cualquier dato

descomprimido.

explicación.

Antes de la versión 1.2.0, zlib asumía que había al menos un byte final inmediatamente después del flujo de datos comprimido cuando realizaba la descompresión. Por ejemplo, tanto gzip (RFC 1950) como zip definen datos finales que siguen al flujo de datos

comprimido.

El siguiente ejemplo muestra cómo usar la opción "LimitOutput". Observe el uso de dos bucles anidados en este caso. El bucle exterior lee los datos de la fuente de entrada - STDIN y el bucle interior llama repetidamente a "inflate" hasta que $input se agota, obtenemos un error, o se alcanza el final del flujo. Un punto que vale la pena recordar es que al usar la opción "LimitOutput" también se establece "ConsumeInput" - esto hace que el código siguiente sea mucho más

simple. 
  use strict ;
  use warnings ;
  use Compress::Raw::Zlib;
  my $x = new Compress::Raw::Zlib::Inflate(LimitOutput => 1)
     or die "Cannot create a inflation stream\n" ;
  my $input = '' ;
  binmode STDIN;
  binmode STDOUT;
  my ($output, $status) ;
OUTER:
  while (read(STDIN, $input, 4096))
  {
      do
      {
          $status = $x->inflate($input, $output) ;
          print $output ;
          last OUTER
              unless $status == Z_OK || $status == Z_BUF_ERROR ;
      }
      while length $input;
  }
  die "inflation failed\n"
      unless $status == Z_STREAM_END
;

VERIFICACIÓN

zlib proporciona dos funciones para calcular sumas de verificación. Para la interfaz de Perl, el orden de los dos parámetros en ambas funciones ha sido invertido. Esto permite realizar tanto cálculos de suma de verificación en curso como cálculos

puntuales. 
$crc = adler32($buffer [,$crc]) ;
$crc = crc32($buffer [,$crc])
;

Los parámetros de buffer pueden ser tanto un escalar como una referencia a un

escalar.

La opción

LimitOutput.

Por defecto "$i->inflate($input, $output)" descomprimirá todos los datos en $input y escribirá todos los datos descomprimidos que ha generado en $output. Esto hace que la interfaz de "inflate" sea mucho más simple - si el método ha descomprimido $input con éxito todos los datos comprimidos en $input habrán sido procesados. Así que si está leyendo de una fuente de entrada y descomprimiendo a medida que avanza, el código se parecerá a algo como

esto 
use strict ;
use warnings ;
use Compress::Raw::Zlib;
my $x = new Compress::Raw::Zlib::Inflate()
   or die "Cannot create a inflation stream\n" ;
my $input = '' ;
my ($output, $status) ;
while (read(STDIN, $input, 4096))
{
    $status = $x->inflate($input, $output) ;
    print $output ;
    last if $status != Z_OK ;
}
die "inflation failed\n"
    unless $status == Z_STREAM_END
;

Los puntos a tener en cuenta

son
  • El bucle de procesamiento principal en el código maneja la lectura de datos comprimidos desde
    • STDIN.
  • El código de estado devuelto desde "inflate" solo provocará la terminación del bucle de procesamiento principal si no es "Z_OK". Cuando "LimitOutput" no se ha utilizado, el estado "Z_OK" significa que se ha alcanzado el final del flujo de datos comprimidos o que ha habido un error en la
    • descompresión.
  • Después de la llamada a "inflate" todos los datos descomprimidos en $input habrán sido procesados. Esto significa que la llamada posterior a "read" puede sobrescribir su con
    • tenido sin
ningún problema.

Para la mayoría de los casos de uso, el comportamiento descrito anteriormente es aceptable (este módulo y su predecesor, "Compress::Zlib", lo han utilizado durante más de 10 años sin ningún problema), pero en unos pocos casos de uso muy específicos, la cantidad de memoria requerida para $output puede ser prohibitivamente grande. Por ejemplo, si el flujo de datos comprimidos contiene el mismo patrón repetido miles de veces, un flujo de datos comprimidos relativamente pequeño puede descomprimirse en cientos de megabytes. Recuerde que "inflate" seguirá asignando memoria hasta que todos los datos descomprimidos se hayan escrito en el búfer de salida - el tamaño de $output es

ilimitado.

La opción "LimitOutput" está diseñada para ayudar con este caso de

uso.

La principal diferencia en su código al utilizar "LimitOutput" es tener que lidiar con los casos en los que el parámetro $input todavía contiene algunos datos sin comprimir que "inflate" aún no ha procesado. El código de estado devuelto desde "inflate" será "Z_OK" si se produjo la descompresión y "Z_BUF_ERROR" si el búfer de salida está

lleno.

A continuación se muestra el código típico que muestra cómo utilizar "LimitOutput"

. 
  use strict ;
  use warnings ;
  use Compress::Raw::Zlib;
  my $x = new Compress::Raw::Zlib::Inflate(LimitOutput => 1)
     or die "Cannot create a inflation stream\n" ;
  my $input = '' ;
  binmode STDIN;
  binmode STDOUT;
  my ($output, $status) ;
OUTER:
  while (read(STDIN, $input, 4096))
  {
      do
      {
          $status = $x->inflate($input, $output) ;
          print $output ;
          last OUTER
              unless $status == Z_OK || $status == Z_BUF_ERROR ;
      }
      while length $input;
  }
  die "inflation failed\n"
      unless $status == Z_STREAM_END
;

Puntos a tener en cuenta esta

vez:
  • Ahora hay dos bucles anidados en el código: el bucle externo para leer los datos comprimidos desde STDIN, como antes; y el bucle interno para llevar a cabo la
    • descompresión.
  • Hay dos puntos de salida del bucle interno de descompresión.

    Primero, cuando "inflate" ha devuelto un estado distinto de "Z_OK" o "Z_BUF_ERROR". Esto significa que o bien se ha alcanzado el final del flujo de datos comprimidos ("Z_STREAM_END") o hay un error en los datos comprimidos. En cualquiera de estos casos no tiene sentido continuar leyendo los datos comprimidos, por lo que ambos bucles se

    terminan.

    El segundo punto de salida comprueba si queda algún dato en el búfer de entrada, $input - recuerde que la opción "ConsumeInput" se activa automáticamente cuando se utiliza "LimitOutput". Cuando se ha agotado el búfer de entrada, el bucle externo puede ejecutarse de nuevo y sobrescribir el ahora vacío $i
