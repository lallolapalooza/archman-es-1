DESCRIPCIÓN

Las funciones son un sistema bastante extensible para analizar varios archivos de configuración en tiempo de ejecución de una aplicación. El flujo del archivo de configuración se divide en las siguientes fases:

1.
Registro de manejadores.
2.
Lectura de los archivos de configuración para los requisitos de análisis previo a MIB.
3.
Lectura y análisis de los archivos MIB de texto.
4.
Lectura de los archivos de configuración para las directivas de configuración.
5.
Opcionalmente, volver a leer los archivos de configuración en una fecha futura.

La idea es que la aplicación que llama pueda registrar manejadores para ciertos tokens especificados en ciertos archivos de configuración con nombre. La read_configs() función puede ser llamada para buscar todos los archivos de configuración relevantes, comparar la primera palabra de cada línea con la lista de tokens registrados y pasar el resto de la línea al manejador registrado correspondiente.

REGISTRO DE UN MANEJADOR

register_config_handler()
Registra una rutina manejadora de configuración, que debe ser llamada para procesar las directivas de configuración que comienzan con el token especificado. Por ejemplo:
register_config_handler("snmp", "exampleToken", example_handler, NULL, "ARG1 [ARG2]");
registraría la example_handler() función para que sea llamada cada vez que la primera palabra de una línea en el snmp.conf archivo(s) de configuración coincida con "exampleToken".
Llamar a los manejadores correspondientes para procesar las directivas del archivo de configuración es responsabilidad de read_configs() (ver abajo).
register_const_config_handler()
Similar a la register_config_handler() función, pero la rutina analizadora está explícitamente restringida a no modificar la cadena que está siendo analizada.
register_prenetsnmp_mib_handler()
Similar a la register_config_handler() función, pero la rutina manejadora registrada será llamada antes de que se lean los MIBs de texto. Esto se usa típicamente para tokens que afectarán la configuración del analizador MIB, y normalmente solo se usará dentro de la propia biblioteca SNMP.
register_mib_handlers()
Rutina de inicialización para registrar los manejadores de configuración de la biblioteca SNMP interna.
unregister_config_handler()
Elimina el manejador de configuración registrado para el filePrefix y tokenespecificados.
unregister_all_config_handlers()
Elimina todos los manejadores de configuración registrados.

Manejadores de token

Las funciones manejadoras deben tener la siguiente firma:

void handler(const char *token, char *line);
o
void handler(const char *token, const char *line); br (si se registró usando register_const_config_handler)

La función será llamada con dos argumentos, el primero siendo el token que desencadenó la llamada a esta función (es decir, el token usado al registrar el manejador), y el segundo siendo el resto de la línea del archivo de configuración (es decir, todo lo que sigue al espacio en blanco que sigue al token coincidente).

Liberación de manejadores

Si la función manejadora de token asigna recursos dinámicamente al procesar una entrada de configuración, entonces estos pueden necesitar ser liberados antes de volver a leer los archivos de configuración. Si el cuarto parámetro ( releaser ) pasado a register_config_handler no es NULL, entonces esto especifica una función a ser llamada antes de volver a leer la configuración archivos. Esta función debe liberar cualquier recurso asignado por la función manejadora de token y restablecer su noción de la configuración a su valor predeterminado. La función manejadora de token puede entonces ser llamada de nuevo de forma segura. No se pasan argumentos al manejador de liberación de recursos.
Tenga en cuenta que esta función no se llama cuando el manejador es desregistrado individualmente (pero sí se llama como parte de unregister_all_config_handlers() ).

Manejadores de aplicación

register_app_config_handler()
register_app_prenetsnmp_mib_handler()
unregister_app_config_handler()
Estas funciones son análogas a register_config_handler(), register_prenetsnmp_mib_handler() y unregister_config_handler() pero no requieren el argumento tipo de archivo (que es rellenado por la aplicación). Se pretende que los módulos MIB escritos para el agente usen estas funciones para permitir que el agente tenga más control sobre qué archivos de configuración se leen (típicamente los snmpd.conf ).

LECTURA DE ARCHIVOS DE CONFIGURACIÓN

read_premib_configs()
read_configs()
Estas rutinas procesan los archivos de configuración encontrados en la ruta de búsqueda de configuración (ver más abajo). Para cada entrada, se llama al manejador registrado para ese token de configuración.

read_premib_configs() se ejecuta antes de que se lean los archivos MIB, y procesa aquellos tokens de configuración registrados usando register_prenetsnmp_mib_handler() (o register_app_prenetsnmp_mib_handler() ). Todas las demás entradas son ignoradas.

read_configs() se ejecuta después de que se hayan leído los archivos MIB, y procesa aquellos tokens de configuración registrados usando register_config_handler() (o register_app_config_handler() ). Si encuentra un token de configuración para el cual no se ha registrado ningún manejador (ya sea pre- o post-mib), mostrará un mensaje de advertencia, y continuará procesando con la siguiente línea del archivo de configuración.

RUTA DE BÚSQUEDA DE CONFIGURACIÓN

Los archivos de configuración a leer se encuentran buscando en una lista de directorios de configuración archivos con nombres apropiados. En cada uno de esos directorios, la biblioteca buscará archivos llamados snmp.conf, snmp.local.conf, app.conf, app.local.conf,
(donde app es el filePrefix específico de la aplicación usado para registrar manejadores de configuración). No es necesario que alguno o todos estos archivos estén presentes en cada directorio. Los archivos faltantes se omitirán silenciosamente.
La idea detrás de los dos sufijos diferentes es que el primer archivo puede ser compartido (mediante rdist o un montaje NFS) en un gran número de máquinas y el segundo archivo puede usarse para configurar ajustes locales para una máquina en particular.

La lista por defecto de directorios a buscar es /etc/snmp, seguido de /usr/share/snmp, seguido de /usr/lib/snmp, seguido de $HOME/.snmp. Esta lista puede cambiarse estableciendo la variable de entorno SNMPCONFPATH como una lista de directorios a buscar (separados por dos puntos).

init_snmp()

El modo normal de operación sería registrar los manejadores de configuración específicos de la aplicación, y luego invocar init_snmp(). Esto llamaría a las rutinas listadas arriba para registrar los manejadores de configuración internos de la biblioteca, procesar cualquier token de configuración registrado con register_prenetsnmp_mib_handler(), leer los archivos MIB textuales usando init_mib(), y finalmente analizar los tokens del archivo de configuración registrados con register_config_handler().

Si se usa la función init_snmp() , ninguna de estas funciones necesita ser llamada explícitamente por la aplicación.

CADENAS DE AYUDA Y ERRORES

El parámetro usageLine pasado a register_config_handler() y llamadas similares, se usa para mostrar información de ayuda cuando se llama a la función read_config_print_usage() . Esta función es usada por todas las aplicaciones cuando se pasa el flag -H en la línea de comandos. Imprime un resumen de todas las líneas del archivo de configuración, y los archivos asociados, que el sistema de configuración entiende. El parámetro usageLine debe ser una lista de argumentos esperados después del token, y no una descripción extensa (que debería ir en una página de manual en su lugar). El prefijo lead se antepondrá a cada línea que la función imprima en stderr, donde muestra su salida.

La función init_snmp() debe ser llamada antes de que se llame a la función read_config_print_usage() , para que la biblioteca pueda registrar sus directivas de archivo de configuración también para que la función read_config_print_usage() las muestre.

FUNCIONES DE MANEJO DE ERRORES

Las dos funciones config_pwarn() y config_perror() toman una cadena de error como argumento y la imprimen en stderr junto con el archivo y el número de línea que causó el error. Una llamada a la segunda función también forzará a read_configs() a eventualmente retornar con un código de error que indica a su función llamante que debe abortar la operación de la aplicación.

VARIABLES DE ENTORNO

SNMPCONFPATH
Una lista de directorios separados por dos puntos en los que buscar archivos de configuración. Por defecto:
/etc/snmp:/usr/share/snmp:/usr/lib/snmp:$HOME/.snmp
