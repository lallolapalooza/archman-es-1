Convert::UUlib - decodificar datos c

odificados con uu/xx/b64/mime/yenc/
etc. de un número masivo de archivos

SINOPSI

S 
use Convert::UUlib ':all';

# leer todos los archivos nombrados en la línea de comandos y decodificarlos
# en el directorio ACTUAL. Ver abajo un ejemplo más largo.
LoadFile $_ for @ARGV;
for my $uu (GetFileList) {
   if ($uu->state & FILE_OK) {
     $uu->decode;
     print $uu->filename, "\n";
   }
}

DESCRIPCIÓ

N

Este módulo comenzó como una interfaz para la biblioteca uulib/uudeview de Frank Pilhofer que puede usarse para decodificar todo tipo de mensajes binarios de usenet (y otros)

.

Después de que el proyecto original fuera abandonado, la biblioteca fue continuamente corregida y mejorada en este módulo, con un enfoque principal en correcciones de seguridad, corrección y velocidad (esto no significa que esta biblioteca se considere segura con datos no confiables, pero ciertamente es más segura que la uudeview original)

.

Lea el archivo doc/library.pdf de la distribución para información detall

ada sobre la biblioteca C utilizada en esta interfaz, y el resto de este
documento y especialmente el programa decodificador no trivial al final.

Establece (o consulta) el FileNameCallback, que se llama siempre que la biblioteca de decodificación no puede encontrar un nombre de archivo y quiere extraer un nombre de archivo de la línea de asunto de una publicación. El callback será llamado con dos argumentos, la línea de asunto y el candidato actual para el nombre de archivo. El último argumento puede ser "undef", lo que significa que no se pudo encontrar ningún nombre de archivo (y probablemente no existe ninguno, por lo que es seguro también devolver "undef" en este caso). Si no devuelve nada (¡ni siquiera "undef"!), entonces no ocurre nada, así que este es un callback sin operación:

   return
(); }

DECODIFICADOR DE EJEMPLO

GRANDE

El flujo de trabajo general para la decodificación es el

siguiente:
1. Configurar las opciones con "SetOption" o
"SetXXXCallback".
2. Cargar todos los archivos de origen con
"LoadFile".
3. Opcionalmente
"Smerge".
4. Iterar sobre todos los elementos de "GetFileList" (es decir, los archivos resultantes)
.
5. "CleanUp" para eliminar archivos y liberar
elementos.

Lo que sigue es el archivo "example-decoder" de la distribución que ilustra el flujo de trabajo anterior en un ejemplo no

trivial.

SOPORTE

PERLMULTICORE

Este módulo soporta el estándar perlmulticore (ver http://perlmulticore.schmorp.de/ para más información) para las siguientes funciones - generalmente estas son funciones que acceden al disco y/o usan una cantidad considerable de tiempo de

CPU: 
LoadFile
$item->decode
$item->decode_temp
$item->remove_temp
$item->
info

El intérprete de perl será readquirido/liberado en cada invocación de callback, por lo que por razones de rendimiento, se deben evitar los callbacks si eso es

costoso.

Versiones futuras podrían

habilitar el soporte multi
core para más funciones.

ERRORES Y

LIMITACIONES

La biblioteca original uulib que usa este módulo fue escrita en una época en la que la memoria principal se medía en megabytes y los desbordamientos de búfer como un problema de seguridad no existían. Aunque se han aplicado muchas correcciones de seguridad a lo largo de los años (incluyendo algunos mecanismos de defensa en profundidad que pueden proteger contra muchos errores aún no detectados), usar esta biblioteca para fines de seguridad requiere

cuidado.

Del mismo modo, los tamaños de archivo cuando se escribió la biblioteca uulib eran diminutos en comparación con los de hoy, así que no esperes que esta biblioteca maneje archivos mayores de

2GB.

Por último, este módulo usa una interfaz muy "al estilo C", lo que significa que no te protege de puntos inválidos como podrías esperar de módulos "más al estilo perl" - por ejemplo, acceder a un objeto de elemento de archivo después de llamar a "CleanUp" probablemente resultará en f

allos, corrupción de
memoria, o algo peor.
