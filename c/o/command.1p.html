USO DE LA

APLICACIÓN

El orden de búsqueda de comandos permite que las funciones anulen a los incorporados regulares y a las búsquedas en la ruta. Esta utilidad es necesaria para permitir que funciones que tienen el mismo nombre que una utilidad llamen a la utilidad (en lugar de una llamada recursiva a la función)

.

La ruta predeterminada del sistema está disponible usando getconf; sin embargo, dado que getconf puede necesitar que PATH esté configurado antes de que pueda ser llamado él mismo, se puede usar lo

siguiente: 
command
-p getc
onf PATH

Hay algunas ventajas en suprimir las características especiales de los incorporados especiales en ocasiones. Por

ejemplo: 
command exec > unwritable-fi
l
e

no causa que un script no interactivo se aborte, de modo que el estado de salida puede ser verificado por el

script.

Las utilidades command, env, nohup, time, y xargs se han especificado para usar el código de salida 127 si ocurre un error, de modo que las aplicaciones puedan distinguir "no se pudo encontrar una utilidad" de "la utilidad invocada terminó con una indicación de error". El valor 127 se eligió porque no se usa comúnmente para otros significados; la mayoría de las utilidades usan valores pequeños para "condiciones de error normales" y los valores por encima de 128 pueden confundirse con la terminación debido a la recepción de una señal. El valor 126 se eligió de una manera similar para indicar que la utilidad pudo ser encontrada, pero no invocada. Algunos scripts producen mensajes de error significativos que diferencian los casos 126 y 127. La distinción entre los códigos de salida 126 y 127 se basa en la práctica de KornShell que usa 127 cuando todos los intentos de ejecutar la utilidad fallan con [ENOENT], y usa 126 cuando cualquier intento de ejecutar la utilidad falla por cualquier otra

razón.

Dado que las opciones -v y -V de command producen salida en relación con el entorno de ejecución del shell actual, command generalmente se proporciona como un incorporado regular del shell. Si se llama en un subshell o en un entorno de ejecución de utilidad separado, como uno de los

siguientes: 
(PATH=foo com
mand -v) noh
up command -v

no produce necesariamente resultados correctos. Por ejemplo, cuando se llama con nohup o con una función exec, en un entorno de ejecución de utilidad separado, la mayoría de las implementaciones no pueden identificar alias, funciones o incorporados

especiales.

Se podrían encontrar dos tipos de incorporados regulares en un sistema y estos son descritos separadamente por command. La descripción de la búsqueda de comandos en Sección 2.9.1.1, Búsqueda y Ejecución de Comandos permite que una utilidad estándar sea implementada como un incorporado regular siempre que se encuentre en el lugar apropiado en una búsqueda en la PATH. Así, por ejemplo, command -v true podría producir /bin/true o alguna ruta de nombre de archivo similar. Podrían existir otras utilidades definidas por la implementación que no están definidas por este volumen de POSIX.1‐2017 solo como incorporados y no tener una ruta de nombre de archivo asociada con ellas. Estas producen salida identificada como incorporados (regulares). Las aplicaciones que encuentran estas no pueden contar con ejecutarlas, usarlas con nohup, anularlas con un PATH difer

ente,
etc.

JUSTIFICACIÓ

N

Dado que command es una utilidad incorporada regular, siempre se encuentra antes de la búsqueda en la

PATH.

No hay nada en la descripción de command que implique que la línea de comandos se analice de manera diferente a la de cualquier otro comando simple. Por

ejemplo: 
command a | b ;
c

no se analiza de ninguna manera especial que cause que '|' o ';' se traten de otra manera que no sea como un operador de tubería o <punto y coma> o que impida la búsqueda de funciones en b o c

.

La utilidad command es algo similar al comando incorporado builtin de la shell de la Octava Edición, pero dado que command también va al sistema de archivos para buscar utilidades, el nombre builtin no sería

intuitivo.

La utilidad command es más probable que se proporcione como un incorporado regular. No está listada como un incorporado especial por las siguientes

razones:
*
La eliminación de funciones exportables hizo innecesaria la precedencia especial de un incorporado
especial.
*
Un incorporado especial tiene propiedades especiales (ver Sección 2.14, Utilidades Incorporadas Especiales) que eran inapropiadas pa
ra invocar otras utilidades. P
or ejemplo, dos comandos como: 
date > unwritable-fil
e 
command date > unwritable-fi
l
e

tendrían resultados completamente diferentes; en un script no interactivo, el primero

continuaría ejecutando el siguiente comando, el segundo se abortaría. Introducir es
ta diferencia semántica junto con la supresión de funciones se vio como no intuitivo.

La opción -p está presente porque es útil poder asegurar una búsqueda de ruta segura que encuentre todas las utilidades estándar. Esta búsqueda podría no ser idéntica a la que ocurre a través de una de las funciones exec (definidas en el volumen de Interfaces del Sistema de POSIX.1‐2017) cuando PATH no está establecido. Al menos, esta característica es necesaria para permitir que el script acceda a la versión correcta de getconf de modo que el valor de la ruta predeterminada pueda ser recuperado con

precisión.

Las opciones command -v y -V se agregaron para satisfacer requisitos de los usuarios que actualmente se logran con tres utilidades históricas diferentes: type en la shell de System V, whence en la KornShell, y which en la C shell. Dado que no hay un acuerdo histórico sobre cómo y qué lograr aquí, la utilidad command de POSIX se mejoró y las utilidades históricas se dejaron sin modificar. La C shell which simplemente realiza una búsqueda de ruta. La KornShell whence es más elaborada—además de las categorías requeridas por POSIX, también informa sobre alias rastreados, alias exportados y funciones no

definidas.

El formato de salida de -V se dejó mayormente sin especificar porque los usuarios humanos son su única audiencia. No se deben escribir aplicaciones que se preocupen por esta información; pueden usar la salida de -v para diferenciar entre varios tipos de comandos, pero la información adicional que puede ser emitida por el -V más detallado no es necesaria y no debe ser arbitrariamente restringida e

n su nivel de detalle o localización po
r razones de análisis de aplicaciones.
