NOMBRE

composefs-dump - formato textual de archivo para el contenido de composefs

DESCRIPCIÓN

Tanto los comandos composefs-info como mkcompose admiten la generación/consumo de descripciones textuales del contenido de una imagen composefs. Esto se puede utilizar para inspeccionar o modificar una imagen, o para generar una imagen sin tener que tener un directorio local con los archivos dentro.

El formato del archivo es muy simple, con un archivo por línea, primero con 11 campos fijos, seguidos de un número variable de atributos extendidos para el archivo. Se recomienda, pero no es obligatorio, incluir un salto de línea final para el último archivo.

Los campos están separados por un solo espacio y las líneas por un solo salto de línea. Los atributos extendidos usan además '=' para separar la clave del valor. Por lo tanto, todos estos caracteres, así como los caracteres no imprimibles, se escapan en los campos ('=' solo en campos xattr). Además, las barras invertidas deben escaparse ya que se utilizan como mecanismo de escape.

Los escapes tienen la forma \xXY, que escapa un solo byte usando dos dígitos hexadecimales. Por ejemplo, \x00 es el byte cero y \xff es el byte 255. Opcionalmente, se admiten estos escapes personalizados:

*\\*
: barra invertida.

\n
: salto de línea.

\r
: retorno de carro.

\t
: tabulación

Los campos opcionales que no se establecen contienen '-', y si un campo realmente tiene ese valor particular, se escapa.

Los campos fijos en una línea son (todos los números en base 10 a menos que se especifique lo contrario):

RUTA
La ruta completa y absoluta del archivo en la imagen. Cualquier directorio utilizado como prefijo en la ruta debe haber estado en el archivo antes de esta línea.
TAMAÑO
El tamaño del archivo. Esto se ignora para los directorios.
MODO
El campo stat st_mode del archivo en octal, que incluye tanto los permisos como el tipo de archivo.

Adicionalmente, si el archivo es un enlace duro, entonces este campo comenzará con un solo carácter '@', y el campo PAYLOAD apuntará al archivo de destino. Tenga en cuenta que todos los demás campos se completan típicamente para un enlace duro como el destino, pero para la generación de un nuevo archivo, ignoramos todos los campos excepto el payload.

NLINK
El campo stat st_nlink.
UID
El UID del propietario.
GID
El GID del propietario.
RDEV
El campo stat st_rdev.
MTIME
El tiempo de modificación en segundos y nanosegundos desde la época unix, separados por '.'. Tenga en cuenta que no es un flotante, "1.1" significa un segundo y un nanosegundo.
PAYLOAD
El payload del archivo. Para enlaces simbólicos, esto significa los destinos del enlace simbólico. Para archivos regulares, esta es la ruta relativa para los archivos de respaldo. Para enlaces duros (ver MODO), esta es la ruta de otro archivo en este archivo del cual es un enlace duro.
CONTENIDO
Los archivos pequeños pueden incrustar el contenido real en la imagen composefs. Esto contiene una versión escapada del contenido. Debe coincidir con el tamaño especificado en TAMAÑO.
DIGEST
Un digest fs-verity para el archivo (solo se usa para archivos regulares y no si CONTENIDO está establecido) que se validará contra los archivos de respaldo cuando se utilice.

Después de los campos fijos viene el xattrs, escapados y separados por espacios en la forma CLAVE=VALOR. Tenga en cuenta que '=' debe escaparse en CLAVE.
