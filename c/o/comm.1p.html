COMM(1P) Manual del Programador POSIX COMM(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

comm — selecciona o rechaza líneas comunes a dos archivos

SINOPSIS

comm [-123] archivo1 archivo2

DESCRIPCIÓN

La utilidad comm leerá archivo1 y archivo2, que deben estar ordenados según la secuencia de ordenamiento actual, y producirá tres columnas de texto como salida: líneas solo en archivo1, líneas solo en archivo2 y líneas en ambos archivos.

Si las líneas en ambos archivos no están ordenadas de acuerdo con la secuencia de ordenamiento de la configuración regional actual, los resultados no están especificados.

Si la secuencia de ordenamiento de la configuración regional actual no tiene un ordenamiento total de todos los caracteres (consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 7.3.2, LC_COLLATE) y cualquier línea de los archivos de entrada se ordena por igual pero no es idéntica, comm debe tratarlas como líneas diferentes pero puede tratarlas como si fueran iguales. Si las trata como diferentes, comm debe esperar que se ordenen según una comparación adicional byte a byte utilizando la secuencia de ordenamiento para la configuración regional POSIX y si no están ordenadas de esta manera, la salida de comm puede identificar dichas líneas como únicas para archivo1 y únicas para archivo2 en lugar de estar en ambos archivos.

OPCIONES

La utilidad comm se ajustará a las Directrices de Sintaxis de Utilidades del volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2.

Se admitirán las siguientes opciones:

-1
Suprimir la columna de salida de líneas únicas de archivo1.
-2
Suprimir la columna de salida de líneas únicas de archivo2.
-3
Suprimir la columna de salida de líneas duplicadas en archivo1 y archivo2.

OPERANDOS

Se admitirán los siguientes operandos:

archivo1
Una ruta del primer archivo a comparar. Si archivo1 es '-', se utilizará la entrada estándar.
archivo2
Una ruta del segundo archivo a comparar. Si archivo2 es '-', se utilizará la entrada estándar.

Si tanto archivo1 como archivo2 se refieren a la entrada estándar o al mismo archivo especial FIFO, archivo especial de bloque o archivo especial de carácter, los resultados no están definidos.

ENTRADA ESTÁNDAR

La entrada estándar solo se utilizará si uno de los operandos archivo1 o archivo2 se refiere a la entrada estándar. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de comm:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén definidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determina la configuración regional para la secuencia de ordenamiento que se espera que comm haya utilizado cuando se ordenaron los archivos de entrada.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La utilidad comm producirá una salida dependiendo de las opciones seleccionadas. Si se seleccionan todas las opciones -1, -2 y -3, comm no escribirá nada en la salida estándar.

Si la opción -1 no se selecciona, las líneas contenidas solo en archivo1 se escribirán utilizando el formato:

"%s\n", <línea en archivo1>

Si la opción -2 no se selecciona, las líneas contenidas solo en archivo2 se escribirán utilizando el formato:

"%s%s\n", <prefijo>, <línea en archivo2>

donde la cadena <prefijo> es la siguiente:

<tab>
La opción -1 no está seleccionada.
cadena nula
La opción -1 está seleccionada.

Si la opción -3 no se selecciona, las líneas contenidas en ambos archivos se escribirán utilizando el formato:

"%s%s\n", <prefijo>, <línea en ambos>

donde la cadena <prefijo> es la siguiente:

<tab><tab>
Ni la opción -1 ni la opción -2 están seleccionadas.
<tab>
Se selecciona exactamente una de las opciones -1 y -2.
cadena nula
Se seleccionan ambas opciones -1 y -2.

Si los archivos de entrada se ordenaron de acuerdo con la secuencia de ordenamiento de la configuración regional actual, las líneas escritas estarán en la secuencia de ordenamiento de la configuración regional actual. Si los archivos de entrada contenían líneas que se ordenaron por igual pero no eran idénticas y dentro de cada archivo esas líneas se ordenaron según una comparación adicional byte a byte utilizando la secuencia de ordenamiento para la configuración regional POSIX, y comm las trató como líneas diferentes, entonces las líneas escritas que se ordenan por igual pero no son idénticas deben ordenarse según una comparación adicional byte a byte utilizando la secuencia de ordenamiento para la configuración regional POSIX.

SALIDA ESTÁNDAR DE ERROR

La salida estándar de error solo se utilizará para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Todos los archivos de entrada se emitieron correctamente según lo especificado.
>0
Ocurrió un error.

CONSECUENCIAS DE LOS ERRORES

En la configuración regional POSIX cada byte es un carácter válido de un solo byte, y por lo tanto se evita este

problema.

Si la secuencia de ordenación de la configuración regional actual no tiene un orden total de todos los caracteres, esto puede afectar al comportamiento de comm de las siguientes

maneras:
*
Si comm trata las líneas como iguales solo si son idénticas, algunas líneas pueden identificarse erróneamente como únicas tanto en file1 como en file
2.
*
Si comm trata las líneas como iguales si tienen el mismo peso en la ordenación y una línea de file1 tiene el mismo peso en la ordenación que una línea de file2 pero no es idéntica a ella, una de las líneas se identifica erróneamente com
o presente en ambos archivos y la otra
no se escribe en la salida en absoluto.

Tales problemas se pueden evitar forzando el uso de la configuración regional POSIX; por ejemplo, lo siguiente identifica líneas en ambos file1 y file2

: 
LC_ALL=POSIX sort file1 > file1.posix
LC_AL
L=POSIX sort file2 > file2.posix LC_ALL=PO
SIX comm -12 file1.posix file2.posix | sort

El sort final reordena la salida de comm de acuerdo con la secuencia de ordenación de la configuración regional original. Hacer esto podría

ser difícil si se genera más de una columna y no se pueden ignorar los <espacios en blanco> iniciales.

FUTURAS

Una versión futura de este estándar podría requerir que si alguna línea de los archivos de entrada tiene el mismo peso en la ordenación pero no es idéntica, entonces comm las trate como líneas diferentes y espere que estén ordenadas de acuerdo con una comparación adicional byte a byte usando la secuencia de ordenación para la configuración regional

POSIX.

Una versión futura de este estándar podría requerir que si los archivos de entrada contuvieran alguna línea que tuviera el mismo peso en la ordenación pero no fuera idéntica y dentro de cada arch

ivo esas líneas estuvieran ordenadas de acuerdo con una comparación adicional byte a byte usando la secuencia de ordenación para la configuración regional POSIX, entonces las líneas escritas que t
engan el mismo peso en la ordenación pero no sean idénticas se ordenen de acuerdo con una comparación adicional byte a byte usando la secuencia de ordenación para la configuración regional POSIX.
