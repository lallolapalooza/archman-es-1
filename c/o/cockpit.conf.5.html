NOMBRE

cockpit.conf - Archivo de configuración de Cockpit

DESCRIPCIÓN

Cockpit puede configurarse a través de /etc/cockpit/cockpit.conf. Si $XDG_CONFIG_DIRS está configurado, entonces se usa la primera ruta que contenga ../cockpit/cockpit.conf. Se buscan otros archivos y directorios de configuración de la misma manera.

Este archivo no es obligatorio y puede ser necesario crearlo manualmente. El archivo tiene una sintaxis de archivo INI y, por lo tanto, contiene pares clave/valor, agrupados en secciones temáticas. Consulte los ejemplos a continuación para obtener más detalles.

Nota: El puerto en el que escucha cockpit no se puede cambiar en este archivo. Para cambiar el puerto, cambie el archivo systemd cockpit.socket.

WEBSERVICE

Origins

Por defecto, cockpit no aceptará conexiones websocket crossdomain. Utilice esta configuración para permitir el acceso desde dominios alternativos. Los orígenes deben incluir el esquema, el host y el puerto, si es necesario. Se permiten comodines y expresiones glob. 
[WebService]
Origins = https://somedomain1.com https://somedomain2.com:9090 https://*.somedomain3.com

ProtocolHeader

Configure cockpit para que examine el contenido de esta cabecera para determinar si una conexión está utilizando TLS. Esto solo debe usarse cuando cockpit está detrás de un proxy inverso, y se debe tener cuidado para asegurar que las solicitudes entrantes no puedan establecer esta cabecera. 
[WebService]
ProtocolHeader = X-Forwarded-Proto

ForwardedForHeader

Configure cockpit para que examine el contenido de esta cabecera para determinar el origen real de una conexión. Esto solo debe usarse cuando cockpit está detrás de un proxy inverso, y se debe tener cuidado para asegurar que las solicitudes entrantes no puedan establecer esta cabecera. 
[WebService]
ForwardedForHeader = X-Forwarded-For

LoginTitle

Establece el título del navegador para la pantalla de inicio de sesión.

LoginTo

Cuando se establece en true, la opción Conectar a en la pantalla de inicio de sesión es visible y permite iniciar sesión en otro servidor. Cuando se establece en false, los inicios de sesión remotos directos están deshabilitados. Si esta opción no se especifica, se detectará automáticamente según si el paquete cockpit-bridge está instalado y el programa ssh está disponible.

Si cockpit-ws está expuesto a Internet y también tiene acceso a una red interna privada, se recomienda establecer explícitamente LoginTo=false. Esto evita que atacantes remotos no autenticados escaneen la red interna en busca de máquinas existentes y puertos abiertos.

RequireHost

Cuando se establece en true, cockpit requerirá que los usuarios utilicen la opción Conectar a para especificar el host al que iniciar sesión.

AllowMultiHost

Cuando se establece en true, cockpit permitirá a los usuarios conectarse a varios hosts en una sola sesión. El valor predeterminado depende del sistema operativo.

Al conectarse a varios servidores, JavaScript se ejecuta sin aislamiento. Todos los sistemas serán vulnerables a posibles ataques de otros hosts conectados. Habilite esta opción solo cuando todos los hosts sean de confianza.

MaxStartups

Igual que la opción de configuración de sshd con el mismo nombre. Especifica el número máximo de intentos de inicio de sesión concurrentes permitidos. Las conexiones adicionales se descartarán hasta que la autenticación tenga éxito o las conexiones se cierren. El valor predeterminado es 10.

Alternativamente, se puede habilitar el descarte temprano aleatorio especificando los tres valores separados por dos puntos start:rate:full (por ejemplo, "10:30:60"). Cockpit comenzará a rechazar los intentos de autenticación con una probabilidad de rate/100 (30%) si actualmente hay start (10) conexiones no autenticadas. La probabilidad aumenta linealmente y se rechazan todos los intentos de conexión si el número de conexiones no autenticadas alcanza full (60).

AllowUnencrypted

Si es true, cockpit aceptará conexiones HTTP no cifradas. De lo contrario, redirigirá todas las conexiones HTTP a HTTPS. Las excepciones son las conexiones desde localhost y para ciertas URLs (como /ping). El valor predeterminado es false.

UrlRoot

La URL raíz donde se servirá cockpit. Cuando se proporciona, cockpit esperará que todas las solicitudes sean prefijadas con la URL dada. Esto es principalmente útil cuando se utiliza cockpit detrás de un proxy inverso, como nginx. /cockpit/ y /cockpit+ son reservados y no deben usarse. Por ejemplo, /cockpit-new/ está bien. /cockpit/ y /cockpit+new/ no lo están.

ClientCertAuthentication

Si es true, habilita los certificados de cliente TLS para autenticar usuarios. Comúnmente, estos son proporcionados por una tarjeta inteligente, pero es igualmente posible importar certificados directamente en el navegador web. Consulte la sección Autenticación de certificados/tarjetas inteligentes[1] de la guía de Cockpit para obtener más detalles.

Shell

La URL relativa del componente de nivel superior a mostrar en Cockpit una vez iniciado sesión. El valor predeterminado es /shell/index.html

LOG

Fatal

El tipo de mensajes de registro en el puente a tratar como fatales. Separe múltiples valores con espacios. Los valores relevantes son: criticals y warnings.

OAUTH

Cockpit puede configurarse para soportar el flujo de autorización OAuth de concesión implícita[2]. Cuando tiene éxito, el token oauth resultante se pasará a cockpit-ws usando el esquema de autenticación Bearer. Para que un inicio de sesión sea exitoso, cockpit también necesitará estar configurado para verificar y permitir tokens Bearer.

URL

Esta es la URL a la que cockpit redirigirá el navegador de los usuarios cuando necesite obtener un token oauth. Cockpit agregará un parámetro redirect_uri a la URL con la ubicación a la que el proveedor oauth debe redirigir una vez que se haya obtenido un token.

ErrorParam

Cuando un proveedor oauth redirige a un usuario de vuelta a cockpit, busque este parámetro en la cadena de consulta o en la parte del fragmento de la URL para encontrar un mensaje de error. Cuando no se proporciona, el valor predeterminado será error_description

TokenParam

Cuando un proveedor oauth redirige a un usuario de vuelta a cockpit, busque este parámetro en la cadena de consulta o en la parte del fragmento de la URL para encontrar el token de acceso. Cuando no se proporciona, el valor predeterminado será access_token

SESIÓN

Banner

El contenido del archivo especificado (comúnmente /etc/issue) se muestra en la página de inicio de sesión. Por defecto, no se muestra ningún banner.

IdleTimeout

Tiempo en minutos después del cual la sesión expira y el usuario es desconectado si no se ha realizado ninguna acción del usuario en el tiempo especificado. Este tiempo de espera de inactividad solo se aplica a los inicios de sesión interactivos con contraseña. Con métodos de autenticación no interactivos como Kerberos, OAuth o inicio de sesión con certificado, el navegador no puede olvidar las credenciales, y por lo tanto, los cierres de sesión automáticos no son útiles para proteger las credenciales de sesiones olvidadas. Establecer en 0 para deshabilitar el tiempo de espera de la sesión. 
[Session]
IdleTimeout=15
Cuando no se especifica, no hay tiempo de espera de inactividad por defecto.

WarnBeforeConnecting

Si advertir antes de conectarse a hosts remotos desde el Shell. El valor predeterminado es true. 
[Session]
WarnBeforeConnecting=false
