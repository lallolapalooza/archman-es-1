coin250 - Nuevas características en Coin v2.5.0

Este es un breve resumen de las nuevas características en Coin v2.5.0, agrupadas por categoría de característica.

Soporte de datos geográficos

Los nodos de Soporte de Datos Geográficos se basan en parte en GeoVRML (http://www.geovrml.org/), y en parte en nuestros propios nodos UTM que se encuentran en la biblioteca SmallChange.

Los nodos de Soporte de Datos Geográficos hacen posible crear, por ejemplo, modelos que abarcan todo el globo en los que puedes navegar sin tener problemas de precisión de punto flotante ("el temblor"). Sin embargo, se necesita cierta ayuda del código de la aplicación para esto; no es una solución completamente automática.

Nodos nuevos:

  • SoGeoOrigin
  • SoGeoLocation
  • SoGeoSeparator
  • SoGeoCoordinate

Además de los nodos nuevos, SoCamera y sus nodos derivados han sido actualizados para soportar el nodo SoGeoOrigin.

El soporte de sistemas de coordenadas en los nodos anteriores es actualmente un poco deficiente (solo se soportan unos pocos sistemas/zonas), pero esto mejorará con el tiempo. No se necesitarán cambios en la API para extender esto, por lo que los lanzamientos de nivel de parche serían suficientes para agregar más sistemas de coordenadas.

Los homólogos VRML2 de los nodos anteriores, que serían una subparte de la implementación de la extensión GeoVRML, aún no están en desarrollo, pero podrían aparecer para la próxima versión principal, ya que gran parte de la implementación será compartida.

Nota: Los nodos SoGeo* anteriores hacen obsoletos los nodos UTM* en la biblioteca SmallChange (para cualquiera que los use), por lo que el soporte para esos nodos eventualmente será obsoleto y eliminado. Sin embargo, no se eliminarán de la noche a la mañana, pero para los nuevos usuarios: evite comenzar a usar los nodos UTM* a toda costa para evitar tener que perder tiempo en una migración más adelante.

Soporte genérico de shaders GLSL

El soporte de shaders se implementa a través de un conjunto de nuevos nodos de shaders, más o menos compatibles con las extensiones TGS correspondientes. Además de GLSL, Coin también soporta shaders ARB y Cg (si la biblioteca Cg está instalada). Sin embargo, solo recomendaremos el uso del lenguaje de shaders GLSL y nos centraremos en él.

Nodos nuevos:

  • SoShaderProgram
  • SoVertexShader
  • SoFragmentShader
  • SoGeometryShader

Consulte también la página Shaders en Coin para obtener más información.

Funcionalidad genérica de renderizado de sombras

Se ha agregado soporte para renderizar sombras a Coin a través de un conjunto de nodos basados en shaders. La técnica utilizada es la técnica de Mapas de Sombras de Varianza (http://www.punkuser.net/vsm/).

Nodos nuevos:

  • SoShadowGroup
  • SoShadowCulling
  • SoShadowStyle

Uso de objetos de buffer de vértices (VBO)

Muchos nodos han tenido su código de renderizado optimizado para el uso de VBO, lo que produce grandes aumentos de rendimiento. Sin embargo, esto no está habilitado universalmente: es necesario organizar los grafos de escena de maneras específicas para que se utilicen los VBO.

Consulte la página Renderizado VBO en Coin para obtener una descripción detallada.

Clases relevantes:

  • SoVertexProperty
  • SoReorganizeAction

Colección expandida de clases Sb*

El mismo razonamiento que para las clases Sb* se aplica a las clases de campo.

Nuevas clases Sb*:
SbBox2i32, SbBox3i32, SbBox3d, SbVec2b, SbVec2ub, SbVec2us, SbVec2i32, SbVec2ui32, SbVec3b, SbVec3ub, SbVec3us, SbVec3i32, SbVec3ui32, SbVec4b, SbVec4ub, SbVec4s, SbVec4us, SbVec4i32, SbVec4ui32, SbXfBox3d

Nota: También puede encontrar una buena cantidad de estas clases en TGS Inventor, por lo que este también fue un movimiento de compatibilidad con TGS.

Colección expandida de clases de campo

La misma razón exacta que para las clases Sb* se aplica a las clases de campo.

Nuevas clases de campo:
SoSFBox2s, SoSFBox2i32, SoSFBox2d, SoSFBox2d, SoSFBox3i32, SoSFBox3d, SoSFColorRGBA, SoSFDouble, SoSFVec2b, SoSFVec2i32, SoSFVec2d, SoSFVec3b, SoSFVec3i32, SoSFVec4b, SoSFVec4ub, SoSFVec4s, SoSFVec4us, SoSFVec4i32, SoSFVec4ui32, SoSFVec4d, SoMFColorRGBA, SoMFDouble, SoMFVec2b, SoMFVec2s, SoMFVec2i32, SoMFVec2d, SoMFVec3b, SoMFVec3s, SoMFVec3i32, SoMFVec4b, SoMFVec4ub, SoMFVec4s, SoMFVec4us, SoMFVec4i32, SoMFVec4ui32, SoMFVec4d

Nodo SoFrustumCamera

Este nodo se agrega para hacer posible la configuración de una cámara personalizada con control total sobre el volumen de visión. SoFrustumCamera es básicamente un mapeo del método glFrustum() de OpenGL.

El uso típico de SoFrustumCamera es en un entorno CAVE o MultiPipe, donde a menudo es necesario configurar cámaras basadas en la configuración de las diferentes pantallas.

Misceláneo

A continuación, se presenta una lista no exhaustiva de otros ajustes y detalles más menores.

SoSearchAction en nodos SoFile

Para facilitar el control sobre si un nodo SoFile debe recorrer sus hijos durante un recorrido SoSearchAction, se han agregado dos métodos estáticos a SoFile.

Funciones nuevas:

  • SoFile::setSearchOK() [estático]
  • SoFile::getSearchOK() [estático]

Biblioteca de información de tipos plantilla SbTypeInfo<T>

Para aquellos que escriben código genérico utilizando plantillas C++, se ha agregado una biblioteca de información de tipos plantilla para los tipos primitivos de Coin, de modo que pueda usar relaciones de tipos para poblar una plantilla en lugar de necesitar parámetros de plantilla para todos los tipos cambiantes de la plantilla, o puede escribir código genérico sobre atributos de tipo como el número de dimensiones de una clase SbVec. SbTypeInfo<T> se encuentra en Inventor/SbTypeInfo.h.

Proyectos de Visual Studio

Los proyectos de Visual Studio se han dividido en proyectos para compilar, instalar y desinstalar por separado el SDK de Coin, y para la generación de documentos. Esto se hizo principalmente para poder compilar sin realizar automáticamente el procedimiento de instalación al mismo tiempo, sino también para ofrecer otros objetivos suplementarios más adelante, como el proyecto de generación de documentación...
