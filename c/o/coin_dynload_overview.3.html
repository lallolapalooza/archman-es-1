coin_dynload_overview - Carga dinámica de nodos de extensión

Cuando Coin intenta obtener un objeto de tipo de nodo (SoType) para una clase basada en el nombre de cadena del tipo de nodo, si ningún tipo de nodo de este tipo ha sido inicializado todavía, buscará en el sistema de archivos una extensión de nodo cargable dinámicamente con ese nombre dado. Esto puede ser completamente deshabilitado estableciendo la variable de entorno COIN_NO_SOTYPE_DYNLOAD a un valor entero positivo, nuevo desde Coin v2.5.0.

En UNIX, las extensiones de nodos son archivos .so regulares. En Win32, las extensiones de nodos se construyen como DLLs. En sistemas Mac OS X, las extensiones de nodos se construyen como archivos .dylib. (Nota: Las extensiones de nodos deben construirse usando la bandera "-dynamiclib", no "-bundle".)

Es opcional si los objetos cargables dinámicamente deben ser nombrados con o sin el prefijo "lib". Ambos esquemas funcionarán.

La gente normalmente no programa de una manera que instancie nuevos nodos a través del objeto SoType de la clase del nodo, pero esa es la forma en que se crean los nodos cuando se cargan archivos de modelo. Esto significa que para todas las aplicaciones de Coin que cargan archivos de modelo, las extensiones de nodos personalizadas serán automáticamente soportadas para los archivos de modelo sin que usted tenga que modificar su código fuente y reconstruir las aplicaciones.

Vea ftp://ftp.coin3d.org/pub/coin/src/dynloadsample.tar.gz para un ejemplo usando dos extensiones de nodos cargables dinámicamente. Usted solo usa un visor examinador para ver las dos extensiones de nodos en acción.

Solo un conjunto limitado de compiladores C++ es soportado hasta ahora. Esto se debe a que, para inicializar la extensión del nodo, es necesario saber algo sobre cómo el compilador C++ manipula el símbolo initClass. Si no sabemos eso, no hay forma de localizar el método initClass en la biblioteca, lo que significa que la extensión del nodo no puede darse a conocer al sistema de tipos.

Si su compilador C++ no es soportado, el archivo fuente para agregar soporte para un nuevo compilador es src/misc/cppmangle.icc. Es bastante trivial agregar soporte para nuevos compiladores, pero si no entiende cómo, solo pregúntenos al respecto. Los parches con soporte para nuevos compiladores son, por supuesto, muy bienvenidos.
