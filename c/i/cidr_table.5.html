CIDR_TABLE(5) Manual de formatos de archivo CIDR_TABLE(5)

NOMBRE

cidr_table - formato de las tablas CIDR de Postfix

SINOPSIS

postmap -q "cadena" cidr:/etc/postfix/nombre_archivo
postmap -q - cidr:/etc/postfix/nombre_archivo <archivo_entrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas de consulta opcionales. Estas tablas suelen estar en formato dbm o db. Alternativamente, las tablas de consulta se pueden especificar en formato CIDR (Classless Inter-Domain Routing). En este caso, cada entrada se compara con una lista de patrones. Cuando se encuentra una coincidencia, se devuelve el resultado correspondiente y se termina la búsqueda.

Para saber qué tipos de tablas de consulta admite su sistema Postfix, utilice el comando "postconf -m".

Para probar tablas de consulta, utilice el comando "postmap -q" como se describe en la SINOPSIS.

FORMATO DE LA TABLA

La forma general de una tabla CIDR de Postfix es:

patron resultado
Cuando una cadena de búsqueda coincide con el patron especificado, utilice el valor de resultado correspondiente. El patron debe estar en formato de red/prefijo o de dirección_de_red (consulte la SINTAXIS DE PATRONES DE DIRECCIÓN a continuación).
!patron resultado
Cuando una cadena de búsqueda no coincide con el patron especificado, utilice el valor de resultado especificado. El patron debe estar en formato de red/prefijo o de dirección_de_red (consulte la SINTAXIS DE PATRONES DE DIRECCIÓN a continuación).

Esta característica está disponible en Postfix 3.2 y versiones posteriores.

si patron
finsi
Cuando una cadena de búsqueda coincide con el patron especificado, haga coincidir esa cadena de búsqueda con los patrones entre si y finsi. El patron debe estar en formato de red/prefijo o de dirección_de_red (consulte la SINTAXIS DE PATRONES DE DIRECCIÓN a continuación). Los bloques si..finsi pueden anidarse.

Nota: no anteponga espacios en blanco al texto entre si..finsi.

Esta característica está disponible en Postfix 3.2 y versiones posteriores.

si !patron
finsi
Cuando una cadena de búsqueda no coincide con el patron especificado, haga coincidir esa cadena de búsqueda con los patrones entre si y finsi. El patron debe estar en formato de red/prefijo o de dirección_de_red (consulte la SINTAXIS DE PATRONES DE DIRECCIÓN a continuación). Los bloques si..finsi pueden anidarse.

Nota: no anteponga espacios en blanco al texto entre si..finsi.

Esta característica está disponible en Postfix 3.2 y versiones posteriores.

líneas en blanco y comentarios
Se ignoran las líneas vacías y las líneas que solo contienen espacios en blanco, así como las líneas cuyo primer carácter que no es espacio en blanco es un `#'.
texto multilínea
Una línea lógica comienza con texto que no son espacios en blanco. Una línea que comienza con espacios en blanco continúa una línea lógica.

ORDEN DE BÚSQUEDA DE LA TABLA

Los patrones se aplican en el orden especificado en la tabla, hasta que se encuentre un patrón que coincida con la cadena de búsqueda.

SINTAXIS DE PATRONES DE DIRECCIÓN

Las tablas CIDR de Postfix se basan en patrones. Un patrón es una dirección_de_red que requiere una coincidencia exacta, o una dirección_de_red/longitud_de_prefijo donde la parte de longitud_de_prefijo especifica la longitud del prefijo de la dirección_de_red que debe coincidir (los otros bits en la parte de dirección_de_red deben ser cero).

Una dirección de red IPv4 es una secuencia de cuatro octetos decimales separados por ".", y una dirección de red IPv6 es una secuencia de tres a ocho pares de octetos hexadecimales separados por ":" o "::", donde este último es una abreviatura de una secuencia de uno o más pares de octetos todos ceros. El patrón 0.0.0.0/0 coincide con todas las direcciones IPv4, y ::/0 coincide con todas las direcciones IPv6. La soporte IPv6 está disponible en Postfix 2.2 y versiones posteriores.

Antes de que se realicen las comparaciones, las claves de búsqueda y las entradas de la tabla se convierten de cadena a binario. Por lo tanto, los patrones IPv6 coincidirán independientemente de los ceros iniciales (un cero inicial en un octeto de dirección IPv4 indica notación octal).

Nota: la información de la dirección puede encerrarse entre "[]", pero esta forma no es obligatoria.

ESPECIFICACIÓN EN LÍNEA

El contenido de una tabla puede especificarse en el nombre de la tabla (Postfix 3.7 y versiones posteriores). La sintaxis básica es:

main.cf:
    parámetro = .. cidr:{ { regla-1 }, { regla-2 } .. } ..
master.cf:
    .. -o { parámetro = .. cidr:{ { regla-1 }, { regla-2 } .. } .. } ..

Postfix expande recursivamente cualquier instancia de $nombre_parámetro en el valor del parámetro anterior, ignora los espacios en blanco después de '{' y antes de '}', y escribe cada regla como una línea de texto en un archivo en memoria:

archivo en memoria:
    regla-1
    regla-2
    ..

Postfix analiza el resultado como si fuera un archivo en /etc/postfix.

Nota: si una regla contiene $, especifique $$ para evitar que Postfix intente realizar la expansión de $nombre al evaluar un valor de parámetro.

EJEMPLO MAPA DE ACCESO SMTPD

/etc/postfix/main.cf:
    smtpd_client_restrictions = ... cidr:/etc/postfix/client.cidr ...
/etc/postfix/client.cidr:
    # El orden de las reglas importa. Coloque las entradas de lista blanca
    # más específicas antes que las entradas de lista negra más generales.
    192.168.1.1             OK
    192.168.0.0/16          REJECT
    2001:db8::1             OK
    2001:db8::/32           REJECT
