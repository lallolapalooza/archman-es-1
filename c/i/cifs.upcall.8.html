DESCRIPCIÓ

N

Esta herramienta es parte del conjunto de utilidades

cifs-utils.

cifs.upcall es un programa auxiliar de espacio de usuario para el sistema de archivos cliente CIFS de Linux. Hay una serie de actividades que el kernel no puede realizar fácilmente por sí mismo. Este programa es un programa de llamada que realiza estas cosas para el kernel y luego devuelve el

resultado.

cifs.upcall generalmente está destinado a ejecutarse cuando el kernel llama a request-key(8) para un tipo de clave en particula

r. Aunque se puede ejecutar directamente desde la línea de coma
ndos, generalmente no está destinado a ejecutarse de esa manera.

--no-env-probe
|-E
Normalmente, cifs.upcall explorará el espacio de variables de entorno del proceso que inició la llamada para obtener el valor de $KRB5CCNAME. Esto puede ayudar al programa a encontrar cachés de credenciales en ubicaciones que no son las predeterminadas. Si se establece esta opción, el programa no hará esto y dependerá de encontrar cachés de credenciales en las ubicaciones predeterminadas especificadas en krb5.conf. Tenga en cuenta que esto nunca se realiza cuando el uid es 0. La ubicación predeterminada de la caché de credenciales siempre se utiliza cuando el uid es 0, independientemente de la configuración de la variable de entorno en el
proceso.

--keytab=|-K=/ruta/a/key

Esta opción permite a los administradores especificar un archivo keytab para usar. Cuando un usuario no tiene una caché de credenciales ya establecida, cifs.upcall intentará usar este keytab para obtenerlas. El valor predeterminado es el keytab de todo el sistema /etc/krb5.k
eytab.
--trust-dns|
-t
Con las llamadas de krb5, el nombre utilizado como la parte del host del principal de servicio es predeterminadamente la parte del nombre de host del UNC. Esta opción permite al programa de llamada realizar una resolución inversa de la dirección de red del servidor para obtener el nombre de host.

Esto es menos seguro que no confiar en DNS. Al usar esta opción, es posible que un atacante pueda controlar el DNS y engañar al cliente para que m

onte un servidor completamente diferente. Es preferible agregar principales de servidor al KDC para cada nombre de host posible, pero esta opción
existe para los casos en que eso no es posible. El valor predeterminado es no confiar en las búsquedas inversas de nombre de host de esta manera.
--legacy-uid
|-l
Tradicionalmente, el kernel ha enviado solo un único parámetro uid= a la llamada para la llamada SPNEGO que se utiliza para determinar qué caché de credenciales de usuario usar. Este parámetro está afectado por la opción de montaje uid=, que también gobierna la propiedad de los archivos en el montaje.

Los kernels más nuevos también envían una opción creduid=, que contiene qué uid cree que posee realmente las credenciales que está buscando. En el m

omento del montaje, esto generalmente se establece en el uid real del usuario que realiza el montaje. Para los montajes multisesión, se establece en
el fsuid del usuario de montaje. Establezca esta opción si desea que cifs.upcall use el parámetro uid= más antiguo en lugar del parámetro creduid=.

CONFIGURACIÓN PARA

KEYCTL

cifs.upcall está diseñado para ser llamado desde el kernel a través del programa de llamada request-key. Esto requiere que se le indique a request-key dónde y cómo llamar a este programa. El programa actual cifs.upcall maneja dos tipos de claves

diferentes:
cifs.
spnego
Este tipo de clave es para obtener claves de sesión de
kerberos
dns_resolv
er
Este tipo de clave es para resolver nombres de host en direcciones IP. El soporte para este tipo de clave eventualmente puede quedar obsoleto (vea a continuación).

Para que este programa sea útil para CIFS

, deberá configurar entradas para ellos e
n request-key.conf(5). Aquí hay un ejempl
o de una entrada para cada tipo de clave: 
#OPERACIÓN  TIPO           D C PROGRAMA ARG1 ARG2...
#==
======= ============= = = =============================
=== create cifs.spnego * * /usr/bin/cifs.upcall %
k create dns_resolver * * /usr/bin/cifs.upcall %k

Vea request-key.conf(5) para más información sobre cada

campo.

El paquete keyutils también ha comenzado a incluir un programa de manejo de dns_resolver que es preferido sobre el que está en cifs.upcall. Si está usando una versión de keyutils igual o mayor que 1.5, debería usar key.dns_resolver para manejar el tipo de clave dns_resolver en lugar de cifs.upcall. Vea key.
