cvtsudoers(1)

Paquete: sudo

Licencias: custom

CVTSUDOERS(1) Manual de Comandos Generales CVTSUDOERS(1)

NOMBRE

cvtsudoers — convierte entre formatos de archivo sudoers

SINOPSIS

cvtsudoers [-ehMpV] [-b dn] [-c archivo_conf] [-d tipos_predet] [-f formato_salida] [-i formato_entrada] [-I incremento] [-l archivo_log] [-m filtro] [-o archivo_salida] [-O punto_inicio] [-P relleno] [-s secciones] [archivo_entrada ...]

DESCRIPCIÓN

La utilidad cvtsudoers acepta una o más políticas de seguridad en formato sudoers o LDIF como entrada, y genera una única política del formato especificado como salida. El formato de entrada predeterminado es sudoers. El formato de salida predeterminado es LDIF. Solo es posible convertir un archivo de política que sea sintácticamente correcto.

Si no se especifica ningún archivo_entrada, o si es ‘-’, la política se lee desde la entrada estándar. Los archivos de entrada pueden ir opcionalmente precedidos por un nombre de host seguido de dos puntos (‘:’) para hacer que las reglas de política sean específicas de un host al fusionar múltiples archivos. Por defecto, el resultado se escribe en la salida estándar.

Las opciones son las siguientes:

-b dn, --base=dn
El DN base (nombre distinguido) que se utilizará al realizar consultas LDAP. Normalmente, tiene la forma “ou=SUDOers,dc=mi-dominio,dc=com” para el dominio mi-dominio.com. Si esta opción no se especifica, se utilizará el valor de la variable de entorno SUDOERS_BASE. Solo es necesario al convertir al formato LDIF.
-c archivo_conf, --config=archivo_conf
Especifica la ruta al archivo de configuración. Predeterminado: /etc/cvtsudoers.conf.
-d tipos_predet, --defaults=tipos_predet
Convierte solo las entradas Defaults de los tipos especificados. Se pueden especificar uno o más tipos de Defaults, separados por una coma (‘,’). Los tipos compatibles son:
all
Todas las entradas Defaults.
global
Entradas Defaults globales que se aplican independientemente del usuario, el usuario de ejecución, el host o el comando.
user
Entradas Defaults por usuario.
runas
Entradas Defaults por usuario de ejecución.
host
Entradas Defaults por host.
command
Entradas Defaults por comando.

Consulte la sección Defaults en sudoers(5) para obtener más información.

Si la opción -d no se especifica, se convertirán todas las entradas Defaults.

-e, --expand-aliases
Expande los alias en archivo_entrada. Los alias se conservan por defecto cuando el formato de salida formato_salida es JSON o sudoers.
-f formato_salida, --output-format=formato_salida
Especifica el formato de salida (sin distinción de mayúsculas y minúsculas). Los siguientes formatos son compatibles:
CSV
Los archivos CSV (valor separado por comas) suelen ser utilizados por hojas de cálculo y generadores de informes. Consulte la sección Formato de salida CSV para más detalles.
JSON
Los archivos JSON (JavaScript Object Notation) suelen ser más fáciles de consumir para aplicaciones de terceros que el formato tradicional de sudoers. Los diversos valores tienen tipos explícitos que eliminan gran parte de la ambigüedad del formato de sudoers. Consulte la sección Formato de salida JSON para más detalles.
LDIF
Los archivos LDIF (LDAP Data Interchange Format) se pueden importar a un servidor LDAP para su uso con sudoers.ldap(5).

La conversión a LDIF tiene las siguientes limitaciones:

  • Las líneas de Defaults específicas de comando, host, usuario de ejecución y usuario no se pueden traducir ya que no tienen un equivalente en el esquema LDAP de sudoers.
  • Los alias de comando, host, usuario de ejecución y usuario no son compatibles con el esquema LDAP de sudoers, por lo que se expanden durante la conversión.
sudoers
Formato tradicional de sudoers. Se reconstruirá un nuevo archivo sudoers a partir del archivo de entrada analizado. Los comentarios no se conservan y los datos de cualquier archivo incluido se mostrarán en línea.
--group-file=archivo
Cuando también se especifica la opción -M, realiza consultas de grupo utilizando archivo en lugar de la base de datos de grupos del sistema.
-h, --help
Muestra un breve mensaje de ayuda en la salida estándar y sale.
-i formato_entrada, --input-format=formato_entrada
Especifica el formato de entrada. Los siguientes formatos son compatibles:
LDIF
Los archivos LDIF (LDAP Data Interchange Format) se pueden exportar desde un servidor LDAP para convertir políticas de seguridad utilizadas por sudoers.ldap(5). Si se especifica un DN base (nombre distinguido), solo se procesarán los objetos sudoRole que coincidan con el DN base. No todas las sudoOptions especificadas en un sudoRole se pueden traducir de LDIF a formato sudoers.
sudoers
Formato tradicional de sudoers. Este es el formato de entrada predeterminado.
-I incremento, --increment=incremento
Al generar salida LDIF, incrementa cada atributo sudoOrder en el número especificado. El valor predeterminado es un incremento de 1.
-l archivo_log, --logfile=archivo_log
Registra las advertencias de conversión en archivo_log en lugar de en el error estándar. Esto es especialmente útil al fusionar múltiples archivos sudoers, lo que puede generar un gran número de advertencias.
-m filtro, --match=filtro
Solo muestra las reglas que coinciden con el filtro especificado. Una expresión de filtro se compone de uno o más pares clave = valor, separados por una coma (‘,’). La clave puede ser “cmnd” (o “cmd”), “host”, “group”, o “user”. Por ejemplo, usuario = operador o host = www. Una mayúscula Cmnd_Alias, ="#Host_alias">Host_alias, o User_Alias puede especificarse como "cmnd", "host" o "user".

Una regla de sudoers coincidente también puede incluir usuarios, grupos y hosts que no forman parte del filtro. Esto puede ocurrir cuando una regla incluye múltiples usuarios, grupos o hosts. Para eliminar cualquier usuario, grupo o host no coincidente de las reglas, se puede usar la opción -p.

Por defecto, las bases de datos de contraseñas y grupos no se consultan al coincidir con el filtro, por lo que los usuarios y grupos no necesitan estar presentes en el sistema local (ver la opción -M). Solo se mostrarán los alias a los que hagan referencia las reglas de política filtradas.

-M, --match-local
Cuando también se especifica la opción -m, se utiliza la información de la base de datos de contraseñas y grupos al coincidir usuarios y grupos en el filtro. Solo los usuarios y grupos en el filtro que existan en el sistema local coincidirán, y los grupos de un usuario se agregarán automáticamente al filtro. Si -M no se especifica no, los usuarios y grupos en el filtro no necesitan existir en el sistema local, pero todos los grupos utilizados para la coincidencia deben figurar explícitamente en el filtro.
-o archivo_salida, --output=archivo_salida
Escribe la salida convertida en archivo_salida. Si no se especifica ningún archivo_salida, o si es '-', la política de sudoers convertida se escribirá en la salida estándar.
-O punto_inicio, --order-start=punto_inicio
Al generar la salida LDIF, se utiliza el número especificado por punto_inicio en el atributo sudoOrder del primer objeto sudoRole. Los objetos sudoRole subsiguientes utilizan un valor de sudoOrder generado sumando un incremento, ver la opción -I para más detalles. Por defecto, el punto de inicio es 1. Un punto de inicio de 0 deshabilitará la generación de atributos sudoOrder en el archivo LDIF resultante.
--passwd-file=archivo
Cuando también se especifica la opción -M, se realizan consultas de contraseñas utilizando archivo en lugar de la base de datos de contraseñas del sistema.
-p, --prune-matches
Cuando también se especifica la opción -m, cvtsudoers eliminará usuarios, grupos y hosts no coincidentes de las entradas coincidentes.
-P relleno, --padding=relleno
Al generar la salida LDIF, se construye el valor inicial de sudoOrder concatenando orden_inicio y incremento, rellenando el incremento con ceros hasta que consista en relleno dígitos. Por ejemplo, si orden_inicio es 1027, relleno es 3, y incremento es 1, el valor de sudoOrder para la primera entrada será 1027000, seguido de 1027001, 1027002, etc. Si el número de entradas sudoRole es mayor de lo que permitiría el relleno, cvtsudoers saldrá con un error. Por defecto, no se realiza relleno.
-s secciones, --suppress=secciones
Suprime la salida de secciones específicas de la política de seguridad. Se pueden especificar uno o más nombres de sección, separados por una coma (','). Los nombres de sección soportados son: defaults, aliases y privileges (que se puede abreviar como privs).
-V, --version
Imprime las versiones de la gramática de cvtsudoers y sudoers y sale.

Fusionar múltiples archivos

Cuando se especifican varios archivos de entrada, cvtsudoers intentará fusionarlos en un único archivo de política. Se asume que los nombres de usuario y grupo son consistentes entre los archivos de política que se van a fusionar. Por ejemplo, el usuario "bob" en un host es el mismo que el usuario "bob" en otro host.

Al fusionar archivos de política, es posible prefijar el nombre del archivo de entrada con un nombre de host, separado por dos puntos (':'). Cuando se fusionan los archivos, el nombre de host se utilizará para restringir las reglas de política a ese host específico siempre que sea posible.

El proceso de fusión se realiza de la siguiente manera:

  • Cada archivo de entrada se analiza en estructuras de datos internas de sudoers.
  • Los alias se fusionan y se renombra según sea necesario para evitar conflictos. En caso de conflicto, el primer alias encontrado se deja tal cual y los alias subsiguientes del mismo nombre se renombra con un sufijo numérico separado por un guion bajo ('_'). Por ejemplo, si hay dos alias diferentes llamados SERVERS, el primero se deja tal cual y el segundo se renombra SERVERS_1. Las referencias al alias renombrado también se actualizan en el archivo de política. Los alias duplicados (aquellos con contenido idéntico) se eliminan.
  • La configuración de Defaults se fusiona y se eliminan los duplicados. Si hay conflictos en la configuración de Defaults, se emite una advertencia por cada conflicto. Si se especifica un nombre de host con el archivo de entrada, cvtsudoers cambiará la configuración global de Defaults en ese archivo para que sea específica del host. Se emite una advertencia para la configuración de Defaults específica de comando, usuario o runas que no se pueda hacer específica del host.
  • Las reglas por usuario se fusionan y se eliminan los duplicados. Si se especifica un nombre de host con el archivo de entrada, cvtsudoers cambiará las reglas que especifican un nombre de host de ALL al nombre de host asociado con el archivo de política que se está fusionando. La fusión de reglas es actualmente bastante simplista, pero se mejorará en una versión posterior.

Es posible fusionar archivos de política con formatos diferentes.

Formato de salida CSV

Los archivos CSV (valores separados por comas) son utilizados a menudo por hojas de cálculo y generadores de informes. Para la salida CSV, cvtsudoers comilla doblemente las cadenas que contienen comas. Por cada carácter de comillas doble literal presente dentro de la cadena, se emiten dos comillas dobles. Este método de comillar comas es compatible con la mayoría de los programas de hoja de cálculo.

Existen tres secciones posibles en la salida CSV de cvtsudoers, cada una separada por una línea en blanco:

defaults
Esta sección incluye cualquier configuración de Defaults en sudoers. La sección de defaults comienza con el siguiente encabezado: 
defaults_type,binding,name,operator,value

Los campos son los siguientes:

defaults_type
El tipo de configuración de Defaults; uno de defaults, defaults_command, defaults_host, defaults_runas, o defaults_user.
binding
Para defaults_command, defaults_host, defaults_runas y defaults_user este es el valor que debe coincidir para que la configuración se aplique.
name
El nombre de la configuración de Defaults.
operator
El operador determina cómo se aplica el valor a la configuración. Puede ser ‘=’ (asignación), ‘+=’ (agregar), o ‘-=’ (eliminar).
value
El valor de la configuración, usualmente una cadena o, para configuraciones utilizadas en un contexto booleano, true o false.
aliases
Esta sección incluye cualquier entrada de Cmnd_Alias, Host_Alias, Runas_Alias o User_Alias de sudoers. La sección de aliases comienza con el siguiente encabezado: 
alias_type,alias_name,members

Los campos son los siguientes:

alias_type
El tipo de alias; uno de Cmnd_Alias, Host_Alias, Runas_Alias, o User_Alias.
alias_name
El nombre del alias; una cadena que comienza con una letra mayúscula y que consiste en letras mayúsculas, dígitos o guiones bajos.
members
Una lista separada por comas de los miembros pertenecientes al alias. Debido al uso de comas, members está rodeado por comillas dobles si contiene más de un miembro.
rules
Esta sección incluye las reglas de sudoers que otorgan privilegios. La sección de rules comienza con el siguiente encabezado: 
rule,user,host,runusers,rungroups,options,command

Los campos son los siguientes:

rule
Este campo indica una entrada de rule de sudoers.
user
El usuario al que se aplica la regla. También puede ser un grupo de Unix (precedido por un carácter ‘%’), un grupo no-Unix (precedido por ‘%:’) o un netgroup (precedido por un carácter ‘+’) o un User_Alias. Si se establece en el valor especial ALL, coincidirá con cualquier usuario.
host
El host al que se aplica la regla. También puede ser un netgroup (precedido por un carácter ‘+’) o un Host_Alias. Si se establece en el valor especial ALL, coincidirá con cualquier host.
runusers
Una lista opcional separada por comas de usuarios (o Runas_Alias) con los que se puede ejecutar el comando. Si contiene más de un miembro, el valor está rodeado por comillas dobles. Si se establece en el valor especial ALL, coincidirá con cualquier usuario. Si está vacío, se asume el usuario root.
rungroups
Una lista opcional separada por comas de grupos (o Runas_Alias) con los que se puede ejecutar el comando. Si contiene más de un miembro, el valor está rodeado por comillas dobles. Si se establece en el valor especial ALL, coincidirá con cualquier grupo. Si está vacío, se utiliza el grupo del runuser.
options
Una lista opcional de configuraciones de Defaults para aplicar al comando. Cualquier entrada Tag_Spec en sudoers se convierte en options.
commands
Una lista de comandos, con argumentos opcionales, que el usuario tiene permitido ejecutar. Si se establece en el valor especial ALL, coincidirá con cualquier comando.

Por ejemplo, la siguiente entrada de sudoers:

millert ALL = (ALL : ALL) NOPASSWD: ALL, !/usr/bin/id

se convierte en:

rule,millert,ALL,ALL,ALL,"!authenticate","ALL,!/usr/bin/id"

EJEMPLOS

Convertir /etc/sudoers a formato LDIF (LDAP Data Interchange Format) donde el archivo ldap.conf utiliza una sudoers_base de my-domain,dc=com, almacenando el resultado en sudoers.ldif:

$ cvtsudoers -b ou=SUDOers,dc=my-domain,dc=com -o sudoers.ldif \
             /etc/sudoers

Convertir /etc/sudoers a formato JSON, almacenando el resultado en sudoers.json:

$ cvtsudoers -f json -o sudoers.json /etc/sudoers

Analizar /etc/sudoers y mostrar solo las reglas que coinciden con el usuario ambrose en el host hastur:

$ cvtsudoers -f sudoers -m user=ambrose,host=hastur /etc/sudoers

Igual que el anterior, pero expandir alias y eliminar cualquier usuario y host no coincidentes de las entradas expandidas.

$ cvtsudoers -ep -f sudoers -m user=ambrose,host=hastur /etc/sudoers

Convertir sudoers.ldif de LDIF a formato sudoers tradicional:

$ cvtsudoers -i ldif -f sudoers -o sudoers.new sudoers.ldif

Fusionar un archivo sudoers global con dos archivos de política específicos de host de los hosts “xyzzy” y “plugh”:

$ cvtsudoers -f sudoers -o sudoers.merged sudoers \
    xyzzy:sudoers.xyzzy plugh:sudoers.plugh
