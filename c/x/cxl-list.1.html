cxl-list - Lista los obje

tos CXL de la plataforma
y sus atributos en json.

SINOPSI

S 
cxl list [<opciones>
]

Recorre la jerarquía de dispositivos compatibles con CXL en el sistema y lista todas las instancias de dispositivo junto con algunas de sus atributos

principales.

Se pueden especificar opciones para limitar la salida a objetos específicos. Cuando se especifica un solo tipo de objeto, el objeto json devuelto es un array de solo esos objetos; cuando se especifican varios tipos de objeto, el objeto devuelto puede ser un array de arrays, donde el array interno se nombra según el tipo de objeto dado. Los arrays de nivel superior se omiten cuando los objetos pueden anidarse bajo un tipo de objeto superior en la jerarquía. Los posibles nombres de arrays de nivel superior y sus propiedades de anidamiento

son:

"anon

memdevs"
(dispositivos de memoria deshabilitados) no se
anidan

"buses

"
no se
anidan

"ports

"
se anidan bajo
buses

"endpoints

"
se anidan bajo puertos o buses (si los puertos no se
emiten)

"memdevs

"
se anidan bajo endpoints o puertos (si los endpoints no se emiten) o buses (si los endpoints y los puertos no se
emiten)

"root

decoders"
se anidan bajo

emiten)

"endpoint

decoders"
se anidan bajo endpoints, o puertos (si los endpoints no se emiten) o buses (si los endpoints y los puertos no se
emiten)

Los filtros pueden especificarse como un solo identificador, una cadena entrecomillada separada por espacios, o una lista separada por comas. Cuando se especifican varios identificadores de filtro dentro de una cadena de filtro, como "-m mem0,mem1,mem2", se combinan como un filtro OR. Cuando se especifican varios tipos de cadenas de filtro, como "-m mem0,mem1,mem2 -p port10", se combinan como un filtro AND. Por lo tanto, "-m mem0,mem1,mem2 -p port10" solo listaría los objetos que están debajo de port10 Y mapean mem0, mem1, O mem2. (filtro OR). Cuando se especifican varios tipos de cadenas de filtro, como "-m mem0,mem1,mem2 -p port10", se combinan como un filtro AND. Por lo tanto, "-m mem0,mem1,mem2 -p port10" solo listaría los objetos que están debajo de port10 Y mapean mem0, mem1, O

mem2.

Dado que muchas consultas de topología buscan responder preguntas relativas a un memdev dado, los buses, puertos, endpoints y decodificadores pueden filtrarse por uno o más memdevs. Por

ejemplo: 
# cxl list -P -p switch,endpoint -m mem0
[
  {
    "port":"port1",
    "host":"ACPI0016:00",
    "endpoints:port1":[
      {
        "endpoint":"endpoint2",
        "host":"mem0"
      }
    ]
  }
]

Además, al aprovisionar nuevas configuraciones de intercalado, es útil saber qué memdevs pueden ser referenciados por un decodificador dado, como un decodificador raíz, o mapeados por un puerto dado si los decodificadores no están

configurados. 
# cxl list -Mu -d decoder0.0
{
  "memdev":"m
em0", "pmem_size":"256.00 MiB (268.44 MB)
", "serial":"0", "host":"0000:35:00.0" }

Tenga en cuenta que para los filtros -m/--memdev=, -p/--port= y -e/--endpoint=, se puede sustituir el nombre del dispositivo host por el identificador del objeto CXL. Para -m/--memdev= este es un nombre de dispositivo PCI de endpoint de la forma "DDDD:bb:dd.f" (D: Dominio b: Bus d: Dispositivo f: Función) (ver /sys/bus/pci/devices), para -p/--port= este es un nombre de dispositivo PCI de puerto de switch ascendente de la forma "DDDD:bb:dd.f", o un nombre de bus PCI de la forma "pciDDDD:bb", y para -e/--endpoint= el dispositivo host es el nombre del objeto de dispositivo de memoria CXL de la forma

"memX".

La opción --human, además de reformatear algunos campos e

n cadenas más amigables para el usuario, también desempaq
ueta el array para reducir el número de líneas de salida.

OPCIONE

S

-m,

--memdev=
Especifica nombre(s) de dispositivo de memoria CXL ("mem0"), id(s) de dispositivo ("0"), y/o nombre(s) de dispositivo host ("0000:35:00.0") para filtrar el listado. Por
ejemplo: 
# cxl list -M --memdev="0 mem3 5"
[
  {
    "memdev":"mem0",
    "pmem_size":268435456,
    "serial":0
  },
  {
    "memdev":"mem3",
    "pmem_size":268435456,
    "ram_size":268435456,
    "serial":2
  },
  {
    "memdev":"mem5",
    "pmem_size":268435456,
    "ram_size":268435456,
    "serial":4
  }
]

-s,

--serial=
Especifica número(s) de serie de dispositivo de memoria CXL para filtrar el
listado

-M,

--memdevs
Incluye dispositivos de memoria CXL en el
listado

-i,

--idle
Incluye dispositivos inactivos (no habilitados / de tamaño cero) en el
listado

-H,

--health
Incluye información de salud en el listado de memdev. Ejemplo de
listado: 
# cxl list -m mem0 -H
[
  {
    "memdev":"mem0",
    "pmem_size":268435456,
    "ram_size":268435456,
    "health":{
      "maintenance_needed":true,
      "performance_degraded":true,
      "hw_replacement_needed":true,
      "media_normal":false,
      "media_not_ready":false,
      "media_persistence_lost":false,
      "media_data_lost":true,
      "media_powerloss_persistence_loss":false,
      "media_shutdown_persistence_loss":false,
      "media_persistence_loss_imminent":false,
      "media_powerloss_data_loss":false,
      "media_shutdown_data_loss":false,
      "media_data_loss_imminent":false,
      "ext_life_used":"normal",
      "ext_temperature":"critical",
      "ext_corrected_volatile":"warning",
      "ext_corrected_persistent":"normal",
      "life_used_percent":15,
      "temperature":25,
      "dirty_shutdowns":10,
      "volatile_errors":20,
      "pmem_errors":30
    }
  }
]

-I,

--partition
Incluye información de partición en el listado de memdev. Ejemplo de
listado: 
# cxl list -m mem0 -I
[
  {
    "memdev":"mem0",
    "ram_size":273535729664,
    "partition_info":{

      "active_persistent_size":0,
      "next_volatile_size":0,
      "next_persistent_size":0,
    }
  }
]

-A,

--alert-config
Incluye la configuración de alertas en el listado de memdev. Ejemplo de
listado: 
# cxl list -m mem0 -A
[
  {
    "memdev":"mem0",
    "pmem_size":0,
    "ram_size":273535729664,
    "alert_config":{

      "dev_over_temperature_prog_warn_threshold_valid":false,
      "dev_under_temperature_prog_warn_threshold_valid":false,
      "corrected_volatile_mem_err_prog_warn_threshold_valid":true,
      "corrected_pmem_err_prog_warn_threshold_valid":false,
      "life_used_prog_warn_threshold_writable":false,
      "dev_over_temperature_prog_warn_threshold_writable":false,
      "dev_under_temperature_prog_warn_threshold_writable":false,

      "corrected_volatile_mem_err_prog_warn_threshold":0,
      "corrected_pmem_err_prog_warn_threshold":0
    },
  }
]

-B,

--buses
Incluir objeto(s) de bus / raíz CXL en el listado. Normalmente, en los sistemas ACPI el objeto de bus es un singleton asociado con el dispositivo ACPI0017, pero hay escenarios de prueba en los que puede haber múltiples jerarquías de memoria
CXL. 
# cxl list -B
[
  {
    "bus":"root3",
    "provider":"cxl_test"
  },
  {
    "bus":"root0",
    "provider":"ACPI.CXL"
  }
]

-b,

--bus=
Especificar nombre(s) de dispositivo raíz CXL, id(s) de dispositivo y/o nombre(s) de proveedor de bus CXL para filtrar el listado. Los nombres de proveedor soportados son "ACPI.CXL" y
"cxl_test".

-P,

--ports
Incluir objetos de puerto (puertos raíz CXL / PCIe + puertos Upstream de Switch) en el
listado.

-p,

--port=
Especificar nombre(s) de dispositivo de puerto CXL ("port2"), id(s) de dispositivo ("2"), nombre(s) de dispositivo host ("pci0000:34"), y/o nombre(s) de tipo de puerto para filtrar el listado. Los nombres de tipo de puerto soportados son "root" y "switch". Tenga en cuenta que un objeto de bus también es un puerto, por lo que las siguientes dos sintaxis son
equivalentes: 
# cxl list -B
# cxl list
-P -p root -S 
...donde el '-S/--single' es necesario ya que los puertos descendientes siempre
  se incluyen en un listado de puertos
y '-S/--single' se detiene después de listar el bus. Además, los objetos de endpoint son puertos, por lo que los s
iguientes comandos son equivalentes, y no se requiere '-S/--single' ya que los puertos de endpoint son terminales: 
# cxl list -E
# cxl list -
P -p endpoint 
De forma predeterminada,
solo se listan los pue
rtos 'switch', es decir, 
# cxl list -
P # cxl list
-P -p switch 
...son
equiva
lentes.

-S,

--single
Especificar si el listado debe emitir todos los objetos que son descendientes de un puerto que coincide con el filtro de puerto, o solo los descendientes directos de los puertos individuales que coinciden con el filtro. De forma predeterminada se listan todos los objetos
descendientes.

-E,

--endpoints
Incluir objetos de endpoint (decodificadores de dispositivo de memoria CXL) en el
listado. 
# cxl list -E
[
  {
    "endpoint":"endpoint2",
    "host":"mem0"
  }
]

-e,

--endpoint
Especificar nombre(s) de dispositivo de endpoint CXL, o id(s) de dispositivo para filtrar el/los endpoint(s) emitido(s)
.

-D,

--decoders
Incluir objetos de decodificador (instancias de capacidad de decodificación de memoria CXL en buses, puertos y endpoints) en el
listado.

-d,

--decoder
Especificar nombre(s) de dispositivo de decodificador CXL, id(s) de dispositivo, o nombre(s) de tipo de decodificador para filtrar el/los decodificador(es) emitido(s). El formato para un nombre de decodificador es "decoder<port_id>.<instance_id>". Los nombres de tipo de decodificador posibles son "root", "switch" o "endpoint", similar a la sintaxis del filtro de
puerto.

-T,

--targets
Ampliar los listados de decodificadores con información de puerto de destino downstream, los listados de puertos y buses con la información del puerto downstream, y/o las regiones con información de
mapeo. 
# cxl list -BTu -b ACPI.CXL
{
  "bus":"root0",
  "provider":"ACPI.CXL",
  "nr_dports":1,
  "dports":[
    {
      "dport":"ACPI0016:00",
      "alias":"pci0000:34",
      "id":"0"
    }
  ]
}

-R,

--regions
Incluir objetos de región en el
listado.

-X,

--dax
Añadir información DAX a los listados de
regiones 
# cxl list -RXu
{
  "region":"region4",
  "resource":"0xf010000000",
  "size":"512.00 MiB (536.87 MB)",
  "interleave_ways":2,
  "interleave_granularity":4096,
  "decode_state":"commit",
  "daxregion":{
    "id":4,
    "size":"512.00 MiB (536.87 MB)",
    "align":2097152,
    "devices":[
      {
        "chardev":"dax4.0",
        "size":"512.00 MiB (536.87 MB)",
        "target_node":0,
        "align":2097152,
        "mode":"system-ram",
        "online_memblocks":0,
        "total_memblocks":4
      }
    ]
  }
}

-r,

--region
Especificar nombre(s) de dispositivo de región CXL, o id(s) de dispositivo, para filtrar el
listado.

-v,

--verbose
Aumentar el nivel de detalle de la salida. Esto se puede especificar varias veces para ser aún más detallado en la salida informativa y diversa, y puede usarse para anular banderas omitidas para mostrar información específica. Tenga en cuenta que cxl list --verbose --verbose es equivalente a cxl list -vv.
•-v Habilita --memdevs, --regions, --buses, --ports, --decoders, y
--targets.
•-vv Todo lo que proporciona -v, más incluir dispositivos deshabilitados con
--idle.
•-vvv Todo lo que proporciona -vv, más habil
itar --health
y --partition.

--debu

g
Si la herramienta cxl se compiló con la depuración habilitada, activar los mensajes de
depuración.

-u,

--human
De forma predeterminada, el comando emitirá datos enteros sin procesar fáciles de leer para máquinas.
En su lugar, con esta bandera, los números que representan el tamaño de almacenamiento se formatearán c
omo cadenas legibles para humanos con unidades, y otros campos se convertirán a cadenas hexadecimales.
