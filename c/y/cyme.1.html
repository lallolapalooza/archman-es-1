cyme(1) Manual de Comandos Generales cyme(1)

NOMBRE

cyme - Listar buses y dispositivos USB del sistema. Un moderno lsusb multiplataforma

SINOPSIS

cyme [-l|--lsusb] [-t|--tree] [-d|--vidpid] [-s|--show] [-D|--device] [--filter-name] [--filter-serial] [--filter-class] [-v|--verbose]... [-b|--blocks] [--bus-blocks] [--config-blocks] [--interface-blocks] [--endpoint-blocks] [--block-operation] [-m|--more] [--sort-devices] [--sort-buses] [--group-devices] [--hide-buses] [--hide-hubs] [--list-root-hubs] [--decimal] [--no-padding] [--color] [--encoding] [--icon] [--headings] [--json] [--from-json] [-F|--force-libusb] [-c|--config] [-z|--debug]... [--mask-serials] [--system-profiler] [-h|--help] [-V|--version] [subcomandos]

DESCRIPCIÓN

Listar buses y dispositivos USB del sistema. Un moderno lsusb multiplataforma.

OPCIONES

-l, --lsusb
Intenta mantener la compatibilidad con la salida de lsusb.
-t, --tree
Volcar la jerarquía de dispositivos USB como un árbol.
-d, --vidpid <VIDPID>
Mostrar solo dispositivos con los números de ID de vendedor y producto especificados (en hexadecimal) en el formato VID:[PID].
-s, --show <SHOW>
Mostrar solo dispositivos con los números de dispositivo y/o bus especificados (en decimal) en el formato [[bus]:][devnum].
-D, --device <DEVICE>
Selecciona qué dispositivo examinará lsusb; proporcionado como una ruta de estilo Linux /dev/bus/usb/BBB/DDD.
--filter-name <FILTER_NAME>
Filtrar por cadena contenida en el nombre.
--filter-serial <FILTER_SERIAL>
Filtrar por cadena contenida en el número de serie.
--filter-class <FILTER_CLASS>
Filtrar por código de clase USB.

Posibles valores:

  • use-interface-descriptor: La clase del dispositivo no está especificada, se usan descriptores de interfaz para determinar los controladores necesarios.
  • audio: Altavoz, micrófono, tarjeta de sonido, MIDI.
  • cdc-communications: La interfaz serie moderna; aparece como un puerto UART/RS232 en la mayoría de los sistemas.
  • hid: Dispositivo de Interfaz Humana; controladores de juegos, teclados, ratones, etc. También se usa comúnmente como interfaz de datos de dispositivo en lugar de crear algo desde cero.
  • physical: Joystick de retroalimentación de fuerza.
  • image: Dispositivo de imagen fija; escáneres, cámaras.
  • printer: Impresora láser, impresora de inyección de tinta, máquina CNC.
  • mass-storage: Dispositivos de almacenamiento masivo (MSD): unidad flash USB, lector de tarjetas de memoria, reproductor de audio digital, cámara digital, unidad externa.
  • hub: Hub USB de alta velocidad.
  • cdc-data: Se usa junto con la clase 02h (Comunicaciones y Control CDC) anterior.
  • smart-card: Lector de tarjetas inteligentes USB.
  • content-security: Lector de huellas dactilares.
  • video: Cámara web.
  • personal-healthcare: Monitor de pulso (reloj).
  • audio-video: Cámara web, TV.
  • billboard: Describe los modos alternativos USB-C compatibles con el dispositivo.
  • usb-type-c-bridge: Una interfaz para exponer y configurar las capacidades USB Type-C de los conectores en Hubs USB o Adaptadores de Modo Alternativo.
  • bdp: Esta clase base se define para dispositivos que cumplen con la "Especificación de Dispositivo BDP USB de VESA" que se encuentra en el sitio web de VESA. Esta especificación define el conjunto utilizable de valores de SubClase y Protocolo. Los valores fuera de esta especificación definida están reservados. Estos códigos de clase solo se pueden usar en Descriptores de Interfaz.
  • mctp: Esta clase base se define para dispositivos que cumplen con "MCTP sobre USB" que se encuentra en el sitio web de DMTF como DSP0283. Esta especificación define el conjunto utilizable de valores de SubClase y Protocolo. Los valores fuera de esta especificación definida están reservados. Estos códigos de clase solo se pueden usar en Descriptores de Interfaz.
  • i3c-device: Una interfaz para exponer y configurar la función I3C dentro de un dispositivo USB para permitir la interacción entre el software del host y el dispositivo I3C, para impulsar transacciones hacia/desde dispositivos de destino en el bus I3C.
  • diagnostic: Equipo de rastreo y depuración.
  • wireless-controller: Controladores inalámbricos: adaptadores Bluetooth, Microsoft RNDIS.
  • miscellaneous: Esta clase base se define para definiciones de dispositivos varios. Algunos SubClase y Protocolos coincidentes se definen en el sitio web de USB-IF.
  • application-specific-interface: Esta clase base se define para que los dispositivos cumplan con varias especificaciones de clase que se encuentran en el sitio web de USB-IF.
  • vendor-specific-class: Esta clase base se define para que los vendedores la utilicen como prefieran.
-v, --verbose
Nivel de verbosidad (repetir proporciona la cuenta): 1 imprime las configuraciones del dispositivo; 2 imprime las interfaces; 3 imprime los endpoints de la interfaz; 4 imprime todo y más bloques.
-b, --blocks <BLOCKS>...
Especifica los bloques que se mostrarán para cada dispositivo y en qué orden. Proporcione el argumento varias veces o use CSV para especificar múltiples bloques.

[predeterminado: número-de-bus,número-de-dispositivo,icono,id-vendedor,id-producto,nombre,serie,velocidad]

Posibles valores:

  • bus-number: Número del bus al que está conectado el dispositivo.
  • device-number: Número de dispositivo emitido por el bus.
  • branch-position: Posición del dispositivo en la rama principal.
  • port-path: Ruta del puerto estilo Linux.
  • sys-path: Ruta del sistema (syspath) informada por udev de Linux.
  • driver: Controlador informado por udev de Linux cargado para el dispositivo.
  • icon: Icono basado en VID/PID.
  • vendor-id: Identificador único del vendedor - comprado a USB IF.
  • product-id: Identificador de producto único del vendedor.
  • vid-pid: Identificador único del vendedor y identificador de producto como una cadena formateada "vid:pid" como lsusb.
  • name: El nombre del dispositivo tal como se informa en el descriptor o usando usb_ids si es Nulo.
  • manufacturer: El fabricante del dispositivo tal como se proporciona en el descriptor o usando usb_ids si es Nulo.
  • product-name: El nombre del producto del dispositivo tal como se informa mediante la búsqueda de vidpid de usb_ids.
  • vendor-name: El nombre del vendedor del dispositivo tal como se informa mediante la búsqueda de vid de usb_ids.
  • serial: Cadena de número de serie del dispositivo tal como se informa en el descriptor.
  • speed: Velocidad admitida del dispositivo anunciado.
  • negotiated-speed: Velocidad negociada del dispositivo tal como está conectado.
  • tree-positions: Posición a lo largo de todas las ramas de vuelta al dispositivo troncal.
  • bus-power: Solo en system_profiler de macOS - ¡corriente del bus real en mA, no potencia!
  • bus-power-used: Solo en system_profiler de macOS - ¡corriente del bus real utilizada en mA, no potencia!
  • extra-current-used: Solo en system_profiler de macOS - ¡corriente del bus real utilizada en mA, no potencia!
  • bcd-device: La versión del dispositivo.
  • bcd-usb: La versión USB compatible.
  • base-class: Enumeración de la clase base de la interfaz proporcionada por USB IF - solo disponible cuando se usa libusb.
  • sub-class: Valor de subclase de la interfaz proporcionada por USB IF - solo disponible cuando se usa libusb.
  • protocol: Valor de protocolo para la interfaz proporcionada por USB IF - solo disponible cuando se usa libusb.
  • uid-class: Nombre de clase del repositorio de IDs USB.
  • uid-sub-class: Nombre de subclase del repositorio de IDs USB.
  • uid-protocol: Nombre de protocolo del repositorio de IDs USB.
  • class: Enumeración completa del Código de Clase USB basada en el trío BaseClass/SubClass/Protocol.
  • base-value: Clase base como valor numérico en lugar de enumeración.
  • last-event: Última vez que se vio el dispositivo.
  • event-icon: Icono del evento.
--bus-blocks <BUS_BLOCKS>...
Especifica los bloques que se mostrarán para cada bus y en qué orden. Proporcione el argumento varias veces o use CSV para especificar múltiples bloques.

[predeterminado: ruta-del-puerto,nombre,controlador-host,dispositivo-controlador-host]

Posibles valores:

  • bus-number: Identificador numérico del bus del sistema.
  • icon: Icono basado en VID/PID.
  • name: Nombre interno del bus del sistema basado en
root-hub: device-name: Nombre del dispositivo Root Hub host-controller: provider-name: Nombre del proveedor del bus interno del host vendor: Nombre del proveedor del Host Controller PCI de pci.ids device: Nombre del dispositivo del Host Controller PCI de pci.ids pci-vendor: ID del proveedor PCI (VID) pci-device: ID del dispositivo PCI (PID) pci-revision: ID de revisión PCI port-path: Ruta del puerto estilo syspath al bus, aplicable solo en Linux config-blocks: name: Nombre del descriptor de cadena number: Número de configuración, bConfigurationValue; valor para establecer para habilitar la configuración num-interfaces: Interfaces disponibles para esta configuración attributes: Atributos de la configuración, bmAttributes icon-attributes: Representación de icono de bmAttributes max-power: Consumo máximo de corriente en mA interface-blocks: name: Nombre del descriptor de cadena number: Número de interfaz port-path: Ruta del puerto de la interfaz (solo aplicable en Linux) base-class: Clase base enum de la interfaz proporcionada por USB IF sub-class: Valor de sub-clase de la interfaz proporcionada por USB IF protocol: Valor de protocolo para la interfaz proporcionada por USB IF alt-setting: Las interfaces pueden tener el mismo número pero una configuración alternativa definida aquí driver: Controlador obtenido de udev (solo Linux) sys-path: syspath obtenido de udev (solo Linux) dev-path: Las rutas de dispositivo /dev/ para la interfaz si existen (solo Linux) mount-paths: Rutas de montaje para interfaces MSD en formato partition_no:mount_path (solo Linux) num-endpoints: Una interfaz puede tener muchos endpoints icon: Icono basado en BaseClass/SubCode/Protocol uid-class: Nombre de la clase del repositorio de IDs USB uid-sub-class: Nombre de la sub-clase del repositorio de IDs USB uid-protocol: Nombre del protocolo del repositorio de IDs USB class: Código de clase USB completamente definido basado en el triplete BaseClass/SubClass/Protocol base-value: Clase base como valor numérico en lugar de enum endpoint-blocks: number: Número de endpoint en la interfaz direction: Dirección de los datos hacia el endpoint transfer-type: Tipo de transferencia de datos que acepta el endpoint sync-type: Tipo de sincronización (modo Iso) usage-type: Tipo de uso (modo Iso) max-packet-size: Tamaño máximo de paquete en bytes que el endpoint puede enviar/recibir interval: Intervalo para la transferencia de datos del endpoint. Valor en recuentos de fotogramas. Ignorado para Endpoints de Bulk y Control. Isochronous debe ser igual a 1 y el campo puede variar de 1 a 255 para endpoints de interrupción block-operation: add: Agregar nuevos bloques a los bloques existentes, ignorando duplicados append: Adjuntar nuevos bloques al final de los bloques existentes new: Reemplazar todos los bloques por unos nuevos prepend: Anteponer nuevos bloques al inicio de los bloques existentes remove: Eliminar bloques coincidentes de los bloques existentes m: Mostrar más bloques por defecto en cada verbosidad solo funciona si no se suministran --blocks,--x--blocks como argumentos o en la configuración sort-devices: device-number: Ordenar por número de dispositivo del bus branch-position: Ordenar por posición en la rama principal no-sort: Sin ordenar; el orden en que se analizó sort-buses: Ordenar dispositivos por número de bus. Si se utiliza cualquier otro ordenamiento de dispositivos que no sea sin ordenamiento, esto sucede automáticamente group-devices: no-group: Sin agrupamiento bus: Agrupar en buses con información del bus como encabezado - como un árbol plano hide-buses: Ocultar buses vacíos al imprimir el árbol; aquellos sin dispositivos hide-hubs: Ocultar hubs vacíos al imprimir el árbol; aquellos sin dispositivos. Al listar, ocultará los hubs independientemente de si están vacíos o no list-root-hubs: Mostrar root hubs al listar; solo Linux decimal: Mostrar valores base16 como base10 decimal en su lugar no-padding: Desactivar el relleno para alinear bloques - hará que los encabezados se desalineen color: auto: Mostrar colores si la salida va a una consola interactiva always: Aplicar siempre la coloración a la salida never: Nunca aplicar la coloración a la salida encoding: glyphs: Usar caracteres del área de uso privado UTF-8, como los utilizados por NerdFont para mostrar iconos de glifos utf8: Usar solo caracteres UTF-8 estándar para la salida; sin iconos de glifos del área de uso privado ascii: Usar solo caracteres ASCII para la salida; 0x00 - 0x7F (127 caracteres) icon: auto: Mostrar bloques de iconos si la [`Encoding`] admite iconos coincidentes en la [`icon::IconTheme`] always: Imprimir siempre bloques de iconos si se incluyen en los bloques configurados never: Nunca imprimir bloques de iconos headings: Mostrar encabezados de bloque json: Salida en formato json después de aplicar la ordenación, los filtros y la configuración del árbol; sin -tree será un volcado plano de dispositivos from-json: Leer desde la salida json en lugar de perfilar el sistema F: Forzar el perfilador libusb puro en macOS en lugar de combinar la salida de system_profiler No tiene efecto en otras plataformas o al usar nusb c: Ruta al archivo de configuración del usuario para usar iconos personalizados, colores y configuraciones predeterminadas z: Activar información de depuración. Alternativamente, se puede usar el entorno RUST_LOG: INFO, DEBUG, TRACE mask-serials: no-mask: Sin enmascaramiento hide: Ocultar con el carácter '*' scramble: Enmascarar aleatorizando los caracteres existentes replace: Enmascarar reemplazando la longitud con caracteres aleatorios system-profiler: Usar el comando system_profiler en macOS para obtener datos USB Si no se usa nusb, este es el valor predeterminado para macOS, combinando con los datos de libusb para una salida detallada. nusb accede directamente a IOKit, por lo que no usa system_profiler por defecto h: Imprimir ayuda (ver un resumen con '-h') V: Imprimir versión SUBCOMMANDS: cyme-watch(1): Vigilar la conexión y desconexión de dispositivos USB cyme-help(1): Imprimir este mensaje o la ayuda de los subcomandos dados VERSION: v2.2.8 AUTHORS: John Whittington <john@jbrengineering.co.uk> e class="foot"> cyme 2.2.8
