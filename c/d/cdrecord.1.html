CDRECORD(1) COMANDOS DE USUARIO de Schily´s CDRECORD(1)

NOMBRE

cdrecord - graba CD, DVD o BluRay de audio o datos

SINOPSIS

cdrecord [ opciones generales ][ dev=dispositivo ][ opciones de pista ] pista1...pistan

DESCRIPCIÓN

Cdrecord se utiliza para grabar CDs de datos o audio en grabadoras de CD Orange Book, para escribir medios DVD en una grabadora de DVD o para escribir medios BluRay en una grabadora BluRay.

Nomenclatura de dispositivos

La mayoría de los usuarios no necesitan preocuparse por la nomenclatura de dispositivos en absoluto. Si no se especificó ninguna opción dev=, cdrecord implementa la compatibilidad con objetivo automático y encuentra automáticamente la unidad si hay exactamente una unidad tipo CD-ROM disponible en el sistema. En caso de que existan varias unidades tipo CD-ROM en el sistema, se puede obtener una lista de posibles parámetros de nombre de dispositivo con cdrecord -scanbus o del ejemplo de objetivo de la salida de cdrecord dev=help, y luego el parámetro dev= se puede establecer basándose en la lista de dispositivos.

El parámetro dispositivo de la opción dev= que se explica a continuación se refiere a la notación estándar de SCSI CAM para bus scsi/objetivo/lun de la grabadora de CD/DVD/BluRay. Si existe un archivo /etc/default/cdrecord, el parámetro de la opción dev= también puede ser una etiqueta de nombre de unidad en dicho archivo (ver sección ARCHIVOS).

Restricciones para ejecutar cdrecord

En sistemas compatibles con SVr4, cdrecord utiliza la clase de tiempo real para obtener la máxima prioridad de planificación posible (superior a todos los procesos del kernel). En sistemas con planificación de tiempo real POSIX, cdrecord también utiliza la planificación de tiempo real, pero puede que no sea capaz de obtener una prioridad superior a todos los procesos del kernel.

Para poder utilizar el subsistema de transporte SCSI del SO, ejecutar con la máxima prioridad y bloquearse en memoria principal, cdrecord necesita ejecutarse como root, necesita estar instalado como suid root o debe ser llamado a través de un mecanismo de privilegios de grano fino, como el mecanismo de privileges(5) de Solaris a través de exec_attr(4) o el mecanismo de capabilities(7) de Linux a través de setcap(8) para permitir que cdrecord sea utilizado por un usuario ordinario.

Mapeo archivo a pista

En el modo *Track At Once* (Pista a la vez), cada *pista* corresponde a un solo archivo que contiene los datos preparados para esa pista. Si el argumento es `-', se utiliza la entrada estándar para esa pista. Solo se puede tomar una pista de *stdin*. En los otros modos de escritura, la relación directa archivo-pista puede no estar implementada. En modo -clone, un solo archivo contiene todos los datos para todo el disco. Para permitir la escritura de DVD en plataformas que no implementan soporte para archivos grandes, cdrecord concatena todos los argumentos de archivo en una sola pista al escribir en medios DVD.

OPCIONES GENERALES

Las opciones generales deben ir antes de cualquier nombre de archivo de pista u opción de pista.

Opciones informativas

-help
muestra información de la versión de cdrecord en la salida estándar.
-version
Imprime información de la versión y sale.
-v
Incrementa el nivel de verbosidad general en uno. Se utiliza, por ejemplo, para mostrar el progreso del proceso de escritura.

Opciones de modo de escritura de medios

-dummy
La opción -dummy modifica la estrategia de escritura actual. La grabadora de CD/DVD/BluRay pasará por todos los pasos del proceso de grabación, pero el láser se apagará durante este procedimiento. Se recomienda realizar varias pruebas antes de escribir realmente en un Compact Disc o Digital Versatile Disk, si el tiempo y la respuesta de carga del sistema actual aún no se conocen.

La opción -dummy no funciona con todos los medios y modos de escritura. Los medios DVD+ y BluRay no admiten escrituras dummy y la mayoría de las grabadoras de CD no admiten escrituras dummy en modo raw.

-multi
Permite crear CD multisesión o DVD multiborde. Esta bandera debe estar presente en todas las sesiones de un disco multisesión o multiborde, a menos que se desee crear una sesión en un CD que será la última sesión en el medio CD.

Para medios CD, la fijación se realizará de manera que permita a la grabadora de CD/DVD/BluRay adjuntar sesiones adicionales más tarde. Esto se hace generando una TOC con un enlace al siguiente área del programa. El medio generado de esta manera no es 100% compatible con los CD fabricados (excepto para CDplus). Úselo solo para grabar CD multisesión. Si esta opción está presente, el tipo de pista predeterminado es CD-ROM XA modo 2 forma 1 y el tamaño del sector es de 2048 bytes. Los subencabezados de sector XA serán creados por la unidad. Las unidades de *Sony* no tienen soporte de hardware para CD-ROM XA modo 2 forma 1. Debe especificar la opción -data para crear discos multisesión en estas unidades. Si desea grabar un disco multisesión en modo SAO, debe forzar los sectores CD-ROM incluyendo la opción -data. No todas las unidades permiten CD multisesión en modo SAO.

Para medios DVD, -multi cambia el modo de escritura a grabación de paquetes incremental. Actualmente no hay forma de evitar la capacidad de adjuntar sesiones adicionales y actualmente solo hay soporte para medios DVD-R/DVD-RW. Para reutilizar un DVD-RW que se haya escrito previamente en modo de grabación de paquetes incremental para modos de escritura diferentes, primero debe borrar completamente el medio.

-dao
-sao
Establece el modo de escritura SAO (Session At Once), que generalmente se denomina modo Disk At Once. Actualmente, esto solo funciona con unidades MMC que admiten el modo Session At Once. Tenga en cuenta que cdrecord necesita conocer el tamaño de cada pista con anticipación para este modo (consulte la opción mkisofs -print-size y la sección EJEMPLOS para obtener más información).

Hay varias grabadoras de CD con firmware defectuoso que dan como resultado discos rotos al grabar en modo TAO o SAO. Si encuentra algún problema con la disposición de un disco o con el contenido del subcanal (por ejemplo, tiempos incorrectos en la pantalla al reproducir el CD) y su unidad admite la escritura en modo -raw96r o -raw16, debería intentarlo.

-tao
Establece el modo de escritura TAO (Track At Once). Este es el modo de escritura predeterminado en versiones anteriores de cdrecord. Con la mayoría de las unidades, este modo de escritura es necesario para la grabación multisesión.

Hay varias grabadoras de CD con firmware defectuoso que dan como resultado discos rotos al grabar en modo TAO o SAO. Si encuentra algún problema con la disposición de un disco o con el contenido del subcanal (por ejemplo, tiempos incorrectos en la pantalla al reproducir el CD) y su unidad admite la escritura en modo -raw96r o -raw16, debería intentarlo.

Opciones funcionales de Cdrecord

-abort
Intenta enviar una secuencia de abortar a la unidad. Si solo usa cdrecord, esto nunca debería ser necesario; pero otro software puede dejar una unidad en una condición inutilizable. Llamar a cdrecord -reset puede ser necesario si una escritura anterior se interrumpió y el software no le dijo a la unidad que no continuará escribiendo.
-atip
Recupera e imprime la información ATIP (Absolute Time In Pre-groove) de un CD/DVD/BluRay grabable o un medio reescribible de CD/DVD/BluRay. Con esta opción, cdrecord intentará recuperar la información ATIP. Si la unidad real no soporta leer la información ATIP, puede ser que solo se muestre un conjunto reducido de información o incluso nada. Solo un número limitado de unidades compatibles con MMC soportan leer la información ATIP.

Si cdrecord puede recuperar el tiempo de inicio de lead-in para la primera sesión, intentará decodificar e imprimir la información del fabricante de los medios. Los medios DVD no tienen información ATIP pero hay información pregrabada equivalente que se lee e imprime.

Permite al usuario seleccionar manualmente un controlador para el dispositivo. La razón de la existencia de la opción driver=nombre es permitir a los usuarios usar cdrecord con unidades que son similares a las unidades soportadas pero no conocidas directamente por cdrecord. Todas las unidades fabricadas después de 1997 deberían ser compatibles con el estándar MMC y por lo tanto soportadas por uno de los controladores MMC. Es muy poco probable que cdrecord no pueda encontrar el controlador correcto automáticamente. Use esta opción con extrema precaución. Si se usa un controlador incorrecto para un dispositivo, la posibilidad de crear discos corruptos es alta. El problema mínimo relacionado con un controlador incorrecto es que -speed o -dummy no funcionarán.

Dirección SCSI general
El dispositivo de destino al que se refiere la opción dev= es la notación estándar SCSI CAM para scsibus/target/lun del grabador de CD/DVD/BluRay. La comunicación en SunOS se realiza con el controlador general SCSI scg. Otros sistemas operativos están usando una simulación de biblioteca de este controlador. La sintaxis posible es: dev= scsibus,target,lun o dev= target,lun. En el último caso, el CD/DVD/BluRay-grabador debe estar conectado al bus SCSI predeterminado de la máquina. Scsibus, target y lun son números enteros. Algunos sistemas operativos o implementaciones de transporte SCSI pueden requerir especificar un nombre de archivo adicional. En este caso, la sintaxis correcta para el dispositivo es: dev= nombredispositivo:scsibus,target,lun o dev= nombredispositivo:target,lun. Si el nombre del nodo de dispositivo que se ha especificado en dicho sistema se refiere exactamente a un dispositivo SCSI, se puede usar una abreviatura en la forma dev= nombredispositivo:@ o dev= nombredispositivo:@,lun en lugar de dev= nombredispositivo:scsibus,target,lu

n.

Para acceder a dispositivos SCSI remotos, debe anteponer al nombre del dispositivo SCSI un indicador de dispositivo remoto. Transportes SCSI alternativos
Cdrecord está completamente basado en comandos SCSI, pero esto no es un problema, ya que todos los grabadores de CD/DVD/BluRay jamás fabricados usan comandos SCSI para la comunicación. Incluso las unidades ATAPI son simplemente unidades SCSI que inherentemente usan la interfaz de paquetes ATA como capa de transporte de comandos SCSI integrada en el transporte IDE (ATA). Replicación de un CD-ROM/DVD-ROM/BD-ROM simple

Para copiar un disco simple, primero lee la copia maestra usando:


readcd dev=1,0 f=somefile

Luego escribe el disco usando:


cdrecord dev=2,0 -v somefile

Replicación de un CD-ROM en modo clon

Para copiar un CD en modo clon, primero lee el CD maestro usando:


readcd dev=1,0 -clone f=somefile

o (en caso de que el CD contenga muchos sectores que no se pueden leer intencionalmente) llamando a:


readcd dev=1,0 -clone -nocorr f=somefile

Esto creará los archivos somefile y somefile.toc. Luego, graba el CD usando:


cdrecord dev=2,0 -raw96r -clone -v somefile

Creación de un CD de audio

Para grabar un CD-DA (audio) puro a velocidad simple, con cada pista contenida en archivos llamados track01.cdaudio, track02.cdaudio, etc.:


cdrecord -v speed=1 dev=2,0 -dao -audio track*.cdaudio

Para verificar si estará bien usar doble velocidad para el ejemplo anterior, usa la opción de escritura ficticia:


cdrecord -v -dummy speed=2 dev=2,0 -dao -audio track*.cdaudio

Creación de un CD mixto de audio-datos

Para grabar un CD de modo mixto con un sistema de archivos ISO-9660 desde cdimage.raw en la primera pista, y las otras pistas sean pistas de audio de los archivos track01.cdaudio, track02.cdaudio, etc.:


cdrecord -v dev=2,0 -dao cdimage.raw -audio track*.cdaudio

Para grabar un disco puro a doble velocidad, utilizando datos del archivo cdimage.raw:


cdrecord -v speed=2 dev=2,0 -dao cdimage.raw

Para crear una imagen para un sistema de archivos ISO-9660 con extensiones Rock Ridge:


mkisofs -R -o cdimage.raw /home/joerg/master/tree

Para verificar el archivo resultante antes de grabarlo en el disco en Solaris:


mount -r -F fbk -o type=hsfs /dev/fbk0:cdimage.raw /mnt

Solaris 9 o posterior viene con una variante de la idea original de fbk llamada lofi. El comando para la variante lofi es:

mount -r -F hsfs ` lofiadm -a /tmp/cdimage.raw ` /mnt

Tenga en cuenta que lofiadm necesita nombres de ruta absolutos.

En Linux:


mount cdimage.raw -r -t iso9660 -o loop /mnt

Continúe con:
ls -lR /mnt
umount /mnt

Si la velocidad general del sistema es suficiente y la estructura del sistema de archivos no es demasiado compleja, cdrecord se ejecutará sin crear una imagen del sistema de archivos ISO-9660. Simplemente ejecute la canalización:


mkisofs -R /master/tree | cdrecord -v -dao fs=6m speed=2 dev=2,0 -

El tamaño mínimo de FIFO recomendado para ejecutar esta canalización es de 4 MBytes. Dado que el tamaño de FIFO predeterminado es de 4 MB, la opción fs= solo necesita estar presente si desea usar un tamaño de FIFO diferente. Si su sistema está cargado, también debe ejecutar mkisofs en la clase de tiempo real. Para aumentar la prioridad de mkisofs, reemplace el comando

priocntl -e -c RT -p 59 mkisofs -R /master/tree

nice --18 mkisofs -R /master/tree

Cdrecord se ejecuta con prioridad 59 en Solaris, usted debe ejecutar mkisofs con una prioridad no mayor a 58. En otros sistemas, debe ejecutar mkisofs con una prioridad no menor a nice --18.

mkisofs -R /master/tree | cdrecord -v -dao speed=2 dev=2,0 tsize=XXXs -

Si esta variable de entorno está establecida, cdrecord te permitirá escribir a la velocidad DMA completa que el sistema soporta. No hay reserva de DMA para leer los datos que se van a escribir desde el disco. Esto creará un alto potencial de desbordamiento de búfer. Usar con precaución.

Si esta variable de entorno está establecida al valor any, cdrecord permite escribir a cualquier velocidad, aunque pueda fallar más tarde con un desbordamiento de búfer.

RSH
Si el entorno RSH está presente, la conexión remota no se creará a través de rcmd(3) sino llamando al programa apuntado por RSH. Usa por ejemplo RSH=/usr/bin/ssh para crear una conexión de shell segura.

Tenga en cuenta que esto obliga a cdrecord a crear una tubería al programa rsh(1) y desactiva que cdrecord acceda directamente al socket de red al servidor remoto. Esto hace imposible establecer parámetros de rendimiento y ralentiza la conexión en comparación con una conexión rcmd(3) iniciada por root.

RSCSI
Si el entorno RSCSI está presente, el servidor SCSI remoto no será el programa /opt/schily/sbin/rscsi sino el programa apuntado por RSCSI. Tenga en cuenta que el nombre del programa del servidor SCSI remoto será ignorado si inicia sesión con una cuenta que se ha creado con un programa de servidor SCSI remoto como shell de inicio de sesión.

DESCRIPTION

This section describes the various commands supported by the tool.

AUDIO
This command specifies that the current track contains audio data.

This command is a shorthand for TRACK 1 AUDIO.

CDG
This command specifies that the current track contains Karaoke CD+G data.

This command is a shorthand for TRACK 1 CDG.

CDI/2336
This command specifies that the current track contains CD-I Mode 2 data with 2336 bytes per sector.
CDI/2352
This command specifies that the current track contains CD-I Mode 2 data with 2352 bytes per sector.
DATA
This command specifies that the current track contains data.

This command is a shorthand for TRACK 1 MODE1/2352.

INDEX index-number mm:ss:ff
This command is used to specify the start of a sub-track within the current track.

The first parameter is the index number, which must be between 0 and 99. The second parameter specifies the time offset in minutes, seconds, and frames.

The INDEX command must appear after a TRACK command but before the next TRACK command.

ISRC isrc-string
This command is used to specify the International Standard Recording Code (ISRC) for a track.

The ISRC code must be 12 characters in length. The first two characters are characters that are from the two character country code. The next three characters are alphanumeric and describe the studio code. The next two characters are the last two digits from the recording year. The last 5 characters are digits that form a serial number that is unique for the same studio and year.

If cdrecord specific CUE extensions are permitted, the four fields of the ISRC may be separated by a minus sign.

If the ISRC command is used, it must appear after a TRACK command but before any INDEX command.

MESSAGE message-string
This command is used to specify the text of a message for a disk that includes CD-Text enhancements.

The parameter is the text of a message. If the string contains any spaces, it must be enclosed in quotation marks.

If the MESSAGE command appears before any TRACK command, the string parameter will be encoded as the message of the entire disk. If the MESSAGE command appears after a TRACK command, the string parameter will be encoded as the message of the current track.

This command is only accepted if the cdrecord specific CUE extensions are permitted.

MODE1/2048
This command specifies that the current track contains CD-ROM Mode 1 data (cooked), with 2048 bytes per sector.
MODE1/2352
This command specifies that the current track contains CD-ROM Mode 1 data (raw), with 2352 bytes per sector.
MODE2/2336
This command specifies that the current track contains CD-ROM XA Mode 2 data with 2336 bytes per sector.
MODE2/2352
This command specifies that the current track contains CD-ROM XA Mode 2 data with 2352 bytes per sector.
PERFORMER performer-string
This command is used to specify the name of a performer for a disk that includes CD-Text enhancements.

The parameter is the name of the performer. If the string contains any spaces, it must be enclosed in quotation marks.

If the PERFORMER command appears before any TRACK command, the string parameter will be encoded as the performer of the entire disk. If the PERFORMER command appears after a TRACK command, the string parameter will be encoded as the performer of the current track.

POSTGAP mm:ss:ff
This command is used to specify the length of a postgap at the end of a track. The postgap data is generated internally by cdrecord. No data is consumed from the current data file.

The parameter specifies the postgap length in minutes, seconds and frames.

The POSTGAP command must appear after all INDEX commands for the current track. Only one POSTGAP command is allowed per track.

PREGAP mm:ss:ff
This command is used to specify the length of a pregap at the beginning of a track. The pregap data is generated internally by cdrecord. No data is consumed from the current data file.

The parameter specifies the pregap length in minutes, seconds and frames.

The PREGAP command must appear after a TRACK command but before any INDEX command. Only one PREGAP command is allowed per track.

REM comment
This command is used to put comments into a CUE file.

The text that appears in the line after a REM command is usually ignored. There is an exception: The special comment REM CDRTOOLS is used to enable cdrecord specific CUE extensions in the parser.

SONGWRITER songwriter-string
This command is used to specify the name of a songwriter for a disk that includes CD-Text enhancements.

The parameter is the name of a songwriter. If the string contains any spaces, it must be enclosed in quotation marks.

If the SONGWRITER command appears before any TRACK command, the string parameter will be encoded as the songwriter of the entire disk. If the SONGWRITER command appears after a TRACK command, the string parameter will be encoded as the songwriter of the current track.

TITLE title-string
This command is used to specify a title for a disk that includes CD-Text enhancements.

The parameter is the title for a track or for the disk. If the string contains any spaces, it must be enclosed in quotation marks.

If the TITLE command appears before any TRACK command, the string parameter will be encoded as the title of the entire disk. If the TITLE command appears after a TRACK command, the string parameter will be encoded as the title of the current track.

TRACK number datatype
This command is used to start a new TRACK.

The first parameter is a track number in the range 1-99.

The second parameter specifies the track data type.

The following datatypes are permitted:

AUDIO

NOTES

Not all options described in this manual may be supported by the OpenSource variant of cdrecord. Cdrecord issues a warning if an attempt is made to use an option that has been disabled in the OpenSource variant.

On Solaris before Solaris 10 Update 1, you need to stop the volume management if you like to use the USCSI fallback SCSI transport code. Even things like cdrecord -scanbus will not work if the volume management is running.

Disks made in Track At Once mode are not suitable as a master for direct mass production by CD-manufacturers. You will need the disk at once option to record such disks. Nevertheless the disks made in Track At Once will normally be read in all CD-players. Some old audio CD-players however may produce a two second click between two audio tracks.

The minimal size of a track is 4 seconds or 300 sectors. If you write smaller tracks, the CD-recorder will add dummy blocks. This is not an error, even though the SCSI-error message looks this way.

Cdrecord has been tested on an upgraded Philips CDD-521 recorder at single and double speed on a SparcStation 20/502 with no problems, slower computer systems should work also. The newer Philips/HP/Plasmon/Grundig drives as well as Yamaha CDR-100 and CDR-102 work also. The Plasmon RF-4100 works, but has not been tested in multi-session. A Philips CDD-521 that has not been upgraded will not work. The Sony CDU-924 has been tested, but does not support XA-mode2 in hardware. The Sony therefore cannot create conforming multi-session disks. The Ricoh RO-1420C works, but some people seem to have problems to use them with speed=2, try speed=0 in this case.

The Yamaha CDR-400 and all new SCSI-3/mmc conforming drives are supported in single and multi-session.

You should run several tests in all supported speeds of your drive with the -dummy option turned on if you are using cdrecord on an unknown system. Writing a CD is a real-time process. NFS will not always deliver constantly the needed data rates. If you want to use cdrecord with CD-images that are located on a NFS mounted filesystem, be sure that the FIFO size is big enough. The author used cdrecord with medium load on a SS20/502 and even at quad speed on a Sparcstation-2 which was heavily loaded, but it is recommended to leave the system as lightly loaded as possible while writing a CD. If you want to make sure that buffer underruns are not caused by your source disk, you may use the command

cdrecord -dummy dev=2,0 padsize=600m /dev/null

to create a disk that is entirely made of dummy data. Cdrecord needs to run as root to get access to the /dev/scg? device nodes and to be able to lock itself into memory.

If you don't want to allow users to become root on your system, cdrecord may safely be installed suid root. This allows all users or a group of users with no root privileges to use cdrecord. Cdrecord in this case checks if the real user would have been able to read the specified files. To give all users access to use cdrecord, enter:

chown root /opt/schily/bin/cdrecord
chmod 4711 /opt/schily/bin/cdrecord

To give a restricted group of users access to cdrecord enter:

chown root /opt/schily/bin/cdrecord
chgrp cdburners /opt/schily/bin/cdrecord
chmod 4710 /opt/schily/bin/cdrecord

and add a group cdburners on your system.

Never give write permissions for non root users to the /dev/scg? devices unless you would allow anybody to read/write/format all your disks.

You should not connect old drives that do not support disconnect/reconnect to either the SCSI bus that is connected to the CD-recorder or the source disk.

NOTAS

Algunos CD-ROMs de HP no son capaces de leer sesiones que no sean la última sesión grabada en un CD-ROM.

Muchos sistemas operativos no son capaces de leer más de una única pista de datos, o necesitan software especial para hacerlo.

Más información sobre el conjunto de comandos SCSI de un grabador de CD de HP se puede encontrar en:

http://www.hp.com/isgsupport/cdr/index.html

Si tiene más información o manuales de comandos SCSI para grabadoras de CD/DVD/BluRay actualmente no soportadas, póngase en contacto con el autor.

El grabador de CD Philips CDD 521 (incluso en la versión actualizada) tiene varios errores de firmware. Algunos de ellos le obligarán a reiniciar el dispositivo o a reiniciar la máquina.

Al usar cdrecord con el driver genérico SCSI de Linux, debe tener en cuenta que cdrecord usa una capa que intenta emular la funcionalidad del driver scg sobre las unidades del sistema operativo local. Desafortunadamente, el driver sg en Linux tiene varios defectos:

•
No puede ver si un comando SCSI no se pudo enviar en absoluto.
•
No puede obtener el byte de estado SCSI. Por esta razón, Cdrecord no puede informar de fallos en comandos SCSI en algunas situaciones.
•
No puede obtener la cuenta DMA real de la transferencia. Cdrecord no puede decirle si hay un recuento residual de DMA.
•
No puede obtener el número de bytes válidos en los datos de autocomprobación. Cdrecord no puede decirle si el dispositivo no transfiere ningún dato de autocomprobación.
•
Obtiene muy pocos datos en la autocomprobación (CCS/SCSI-2/SCSI-3 necesita >= 18).

El porcentaje de FIFO se calcula justo después de que un bloque de datos se haya escrito en la grabadora de CD/DVD/BluRay. Por esta razón, nunca habrá una relación de llenado del FIFO del 100% mientras el FIFO esté en modo de streaming.

DIAGNÓSTICOS

Tiene 9 segundos para escribir ^C para abortar cdrecord después de ver el mensaje:

Comenzando a grabar CD a velocidad %d en modo %s para sesión %s.

Un mensaje de error típico para un comando SCSI se ve así:

cdrecord: I/O error. test unit ready: scsi sendcmd: no error
CDB:  00 20 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: 70 00 05 00 00 00 00 0A 00 00 00 00 25 00 00 00 00 00
Sense Key: 0x5 Illegal Request, Segment 0
Sense Code: 0x25 Qual 0x00 (logical unit not supported) Fru 0x0
Sense flags: Blk 0 (not valid)
cmd finished after 0.002s timeout 40s

La primera línea proporciona información sobre el transporte del comando. El texto después de los dos puntos da el texto de error para la llamada al sistema desde la vista del kernel. Normalmente es: I/O error a menos que ocurran otros problemas. Las siguientes palabras contienen una breve descripción del comando SCSI que falla. El resto de la línea indica si hubo algún problema con el transporte del comando a través del bus SCSI. fatal error significa que no fue posible transportar el comando (es decir, no hay dispositivo presente en la dirección SCSI solicitada).

La segunda línea imprime el bloque descriptivo del comando SCSI para el comando fallido.

La tercera línea da información sobre el código de estado SCSI devuelto por el comando, si el transporte del comando tiene éxito. Esta es información de error del dispositivo SCSI.

La cuarta línea es un volcado hexadecimal de la información de autocomprobación para el comando.

La quinta línea es el texto de error para la clave de autocomprobación si está disponible, seguido del número de segmento que solo es válido si el comando fue un comando de copia. Si el mensaje de error no está directamente relacionado con el comando actual, se añade el texto deferred error.

La sexta línea es el texto de error para el código de autocomprobación y el cualificador de autocomprobación si están disponibles. Si se conoce el tipo de dispositivo, los datos de autocomprobación se decodifican de tablas en scsierrs.c. El texto va seguido del valor de error para una unidad reemplazable por el fabricante (Fru).

La séptima línea imprime el número de bloque relacionado con el comando fallido y el texto de varios indicadores de error. El número de bloque puede no ser válido.

La octava línea informa del tiempo de espera establecido para este comando y el tiempo que realmente necesitó para completarse.

El siguiente mensaje no es un error:

Track 01: Total bytes read/written: 2048/2048 (1 sectors).
cdrecord: I/O error. flush cache: scsi sendcmd: no error
CDB:  35 00 00 00 00 00 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: F0 00 05 80 00 00 27 0A 00 00 00 00 B5 00 00 00 00 00
Sense Key: 0x5 Illegal Request, Segment 0
Sense Code: 0xB5 Qual 0x00 (dummy data blocks added) Fru 0x0
Sense flags: Blk -2147483609 (valid)
cmd finished after 0.002s timeout 40s

Como cdrecord depende de las interfaces proporcionadas por el sistema operativo subyacente, la estabilidad de las interfaces ofrecidas por cdrecord depende de la estabilidad de la interfaz de las interfaces del sistema operativo. Las interfaces modificadas en el sistema operativo pueden forzar la modificación de las interfaces en cdrecord.
