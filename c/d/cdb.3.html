DESCRIPCIÓ

N

cdb es una biblioteca para crear y acceder a archivos de Base de Datos Constante (Constant DataBase). El archivo almacena pares (clave,valor) y se utiliza para encontrar rápidamente un valor basado en una clave dada. Los archivos Cdb son archivos de creación única, es decir, una vez creados, el archivo no puede ser actualizado, sino recreado desde cero; por esto es por lo que la base de datos se llama constante. El archivo Cdb está optimizado para un acceso rápido. El formato de dicho archivo se describe en la página de manual cdb(5). Esta página de manual corresponde a la versión 0.81 del paquete tinycdb

.

La biblioteca define dos interfaces no entrelazadas: para consultar datos de un archivo cdb existente (modo de solo lectura) y para crear dicho archivo (casi de solo escritura). Estrictamente hablando, esos modos permiten también un conjunto muy limitado de operaciones opuestas (es decir, en modo de consulta, es posible actualizar el valor de una clave)

.

Todas las rutinas en esta biblioteca son seguras para hilos (thread-safe) ya que no se usan datos globales, excepto la variable errno para la indicación de

errores.

Los archivos de datos cdb pueden moverse entre sistemas de f

orma segura, ya que el formato
no depende de la arquitectura.

MODO DE

CONSULTA

Hay dos modos de consulta disponibles. El primero usa una estructura que representa una base de datos cdb, al igual que la estructura FILE en la biblioteca stdio, y el otro trabaja con un descriptor de archivo plano. El primer modo es más sofisticado y flexible, y generalmente algo más rápido. Usa mmap(2) internamente. Este modo puede parecer más "natural" u orientado a objetos en comparación con el

segundo.

Las siguientes rutinas funcionan con cualquier

modo: 
unsigned cdb_unpack(buf)
   const unsigned char buf[4
];
rutina auxiliar para convertir un entero de 32 bits de la representación interna al formato de la máquina. Puede usarse para manejar enteros de la aplicación de una manera portátil. No hay retorno de
error.

Modo de Consulta

1

Todas las operaciones de consulta en el primer modo tratan con una estructura de datos común, struct cdb, asociada con un descriptor de archivo abierto. Esta estructura es opaca para la

aplicación.

Las siguientes rutinas existen para acceder a la base de datos cdb

: 
int cdb_init(cdbp, fd)
   struct cdb *cdbp;
   int fd
;
inicializa la estructura dada por el puntero cdbp y la asocia con el descriptor de archivo abierto fd. La asignación de memoria para la estructura en sí, si es necesaria, y la operación de apertura del archivo deben ser realizadas por la aplicación. El archivo fd debe estar abierto al menos en modo de solo lectura, y debe ser seekable (permitir búsqueda). La rutina devuelve 0 en éxito o un valor negativo en
error. 
void cdb_free(cdbp)
   struct cdb *cdbp
;
libera los recursos internos mantenidos por la estructura. Note que esta rutina no cierra un
archivo. 
int cdb_fileno(cdbp)
  const struct cdb *cdbp
;
devuelve el descriptor de archivo asociado con cdb (como fue pasado a cdb_init())

int cdb_read(cdbp, buf, len, pos)
int cdb_readdata(cdbp, buf, len, pos)
int cdb_readkey(cdbp, buf, len, pos)
   const struct cdb *cdbp;
   void *buf;
   unsigned len;
   unsigned pos
;
lee datos de un archivo cdb, comenzando en la posición pos de longitud len, colocando el resultado en buf. Esta rutina puede usarse para obtener el valor actual encontrado por cdb_find() u otras rutinas que devuelven la posición y longitud de un dato. Devuelve 0 en éxito o un valor negativo en error. Las rutinas cdb_readdata() y cdb_readkey() son atajos para leer el dato actual (por ejemplo, después de cdb_find()) y la clave respectivamente, usando cdb_rea

const void *cdb_get(cdbp, len, pos)
const void *cdb_getdata(cdbp)

   const struct cdb *cdbp;
   unsigned len;
   unsigned pos

Internamente, la biblioteca cdb usa una región de memoria mapeada (memory-mmaped) para acceder a la base de datos en disco. cdb_get() permite acceder a la memoria interna de una manera similar a cdb_read() pero sin copia extra ni asignación de búfer. Devuelve un puntero a los datos reales en éxito o NULL en error (la posición apunta fuera de la base de datos). Las rutinas cdb_getdata() y cdb_getkey() son atajos para acceder al dato actual (por ejemplo, después de cdb_find()) y a la clave respectivamente, usando cdb_get
(). 
int cdb_find(cdbp, key, klen)
unsigned cdb_datapos(cdbp)
unsigned cdb_datalen(cdbp)
unsigned cdb_keypos(cdbp)

   struct cdb *cdbp;
   const void *key;
   unsigned klen
;
intenta encontrar una clave dada por los parámetros (key,klen). Si la clave existe en la base de datos, la rutina devuelve 1 y coloca la posición y longitud del valor asociado con esta clave en campos internos dentro de la estructura cdbp, para ser accesibles por las rutinas cdb_datapos(cdbp) y cdb_datalen(cdbp). Si la clave no está en la base de datos, cdb_find() devuelve 0. En caso de error, se devuelve un valor negativo. Los punteros de datos (disponibles vía cdb_datapos() y cdb_datalen()) se actualizan solo en caso de búsqueda exitosa. Note que usando cdb_find() es posible buscar solo el primer registro con una clave
dada. 
int cdb_findinit(cdbfp, cdbp, key, klen)
int cdb_findnext(cdbfp)
  struct cdb_find *cdbfp;
  const struct cdb *cdbp;
  const void *key;
  unsigned klen
;
rutinas de búsqueda secuencial que usan una estructura separada. Es posible tener más de un registro con la misma clave en una base de datos, y estas rutinas permiten enumerarlos todos. cdb_findinit() inicializa la estructura de búsqueda a la que apunta cdbfp. Devolverá un valor negativo en error o un valor no negativo en éxito. cdb_findnext() intenta encontrar la siguiente clave coincidente (la primera cuando se llama justo después de cdb_findinit()), estableciendo la posición y longitud del valor en la estructura cdbfp. Devolverá un valor positivo si la clave dada fue encontrada, 0 si no hay más claves de ese tipo, o un valor negativo en error. Para acceder a la posición y longitud del valor después de una llamada exitosa a cdb_findnext() (cuando devolvió un resultado positivo), use las rutinas cdb_datapos(cdbp) y cdb_datalen(cdbp). Es un error continuar usando cdb_findnext() después de que devolvió 0 o una condición de error (cdb_findinit() debe ser llamada de nuevo). Los punteros de datos actuales (disponibles vía cdb_datapos() y cdb_datalen()) se actualizan solo en caso de búsqueda
exitosa. 
void cdb_seqinit(cptr, cdbp)
int cdb_seqnext(cptr, cdbp)
  unsigned *cptr;
  struct cdb *cdbp
;
enumeración secuencial de todos los registros almacenados en un archivo cdb. cdb_seqinit() inicializa el puntero de acceso al dato actual cptr para que apunte antes del primer registro en un archivo cdb. cdb_seqnext() actualiza los punteros de datos en cdbp para que apunten al siguiente registro y actualiza cptr, devolviendo un valor positivo en éxito, 0 en condición de fin de datos y un valor negativo en error. El registro actual estará disponible después de una operación exitosa usando cdb_datapos(cdbp) y cdb_datalen(cdbp) (para el dato) y cdb_keypos(cdbp) y cdb_keylen(cdbp) (para la clave del registro). Los punteros de d
atos se actualizan solo en
caso de operación exitosa.

Modo de Consulta

2

En este modo, uno necesita abrir un archivo cdb usando una de las llamadas al sistema estándar (tales como open(2)) para obtener un descriptor de archivo, y luego pasar ese descriptor de archivo a las rutinas cdb. Los métodos disponibles para consultar una base de datos cdb usando solo un descriptor de archivo

incluyen: 
int cdb_seek(fd, key, klen, dlenp)
  int fd;
  const void *key;
  unsigned klen;
  unsigned *dlenp
;
busca en una base de datos cdb (como la apuntada por el descriptor de archivo fd) una clave dada por (key, klen), y posiciona el puntero del archivo al inicio del dato asociado con esa clave si es encontrada, de modo que la siguiente operación de lectura desde este descriptor de archivo leerá ese valor, y coloca la longitud del valor, en bytes, en la variable a la que apunta dlenp. Devuelve un valor positivo si la operación fue exitosa, 0 si la clave no fue encontrada, o un valor negativo en error. Para leer los datos de un archivo cdb, se puede usar la rutina cdb_bread() descrita a
continuación.pre>int cdb_bread(fd, buf, len) int fd; void *buf; int len;
lee datos de un archivo (tal como lo indica el fd descriptor de archivo) y coloca len bytes de este archivo en un buffer apuntado por buf. Devuelve 0 si se leyeron exactamente len bytes, o un valor negativo en caso de error o fin de archivo. Esta rutina ignora errores de interrupción (EINTR). Establece la variable errno a EIO en caso de condición de fin de archivo (cuando hay menos de len bytes dispon
ibles par
a leer).

Nota

s

Tenga en cuenta que el valor de cualquier clave dada puede ser actualizado en lugar por otro valor del mismo tamaño, escribiendo en el archivo en la posición encontrada por cdb_find() o cdb_seek(). Sin embargo, uno debe ser muy cuidadoso al hacerlo, ya que la operación de escritura puede no tener éxito en caso de, por ejemplo, una falla de energía, dejando así datos

corruptos. Cuando la base de datos es (re)creada, se puede garantizar que no se escribir
án datos incorrectos en la base de datos, pero no con la actualización en el lugar. Tenga e
n cuenta también que no es posible actualizar ninguna clave o cambiar la longitud del valor.

MODO DE

CREACIÓN

El archivo de base de datos cdb generalmente debe crearse en dos pasos: primero, se crea un archivo temporal y se escribe en el disco, y segundo, ese archivo temporal se renombra a un lugar permanente. La llamada Unix rename(2) es una operación atómica, elimina el archivo de destino si existe Y renombra otro archivo en un solo paso. De esta manera se garantiza que los lectores no verán una base de datos incompleta. Para prevenir múltiples actualizaciones simultáneas, también se puede usar

bloqueo.

Todas las rutinas utilizadas para crear la base de datos cdb trabajan con el objeto struct cdb_make que es opaco para la aplicación. La aplicación puede asumir que struct cdb_make tiene al menos los mismos miembros que los publicados en struct cdb a

rriba. 
int cdb_make_start(cdbmp, fd)
   struct cdb_make *cdbmp;
   int fd
;
inicializa la estructura para crear una base de datos. El archivo fd debe estar abierto para lectura-escritura y debe ser buscable. Devuelve 0 en éxito o un valor negativo en
error. 
int cdb_make_add(cdbmp, key, klen, val, vlen)
   struct cdb_make *cdbmp;
   const void *key, *val;
   unsigned klen, vlen
;
agrega un registro con clave (key,klen) y valor (val,vlen) a una base de datos. Devuelve 0 en éxito o un valor negativo en error. Tenga en cuenta que esta rutina no verifica si la clave dada ya existe, pero cdb_find() no verá un segundo registro con la misma clave. No es posible continuar construyendo una base de datos si cdb_make_add() devolvió un indicador de
error. 
int cdb_make_finish(cdbmp)
   struct cdb_make *cdbmp
;
finaliza el archivo de la base de datos, construyendo todos los índices necesarios y libera las estructuras de memoria. No cierra el descriptor de archivo. Devuelve 0 en éxito o un valor negativo en
error. 
int cdb_make_exists(cdbmp, key, klen)
   struct cdb_make *cdbmp;
   const void *key;
   unsigned klen
;
Esta rutina intenta encontrar la clave dada por (key,klen) en una base de datos aún no completa. Puede ralentizar significativamente todo el proceso, y actualmente vuelca el buffer interno al disco en cada llamada con una clave cuyo valor hash ya existe en la db. Devuelve 0 si tal clave no existe, 1 si existe, o un valor negativo en error. Tenga en cuenta que el archivo de la base de datos debe estar abierto para lectura-escritura (no solo escritura) para usar esta rutina. Si cdb_make_exists() devolvió un error, puede no ser posible continuar construyendo la base de
datos. 
int cdb_make_find(cdbmp, key, klen, mode)
   struct cdb_make *cdbmp;
   const void *key;
   unsigned klen;
   int mode
;
Esta rutina intenta encontrar la clave dada por (key,klen) en la base de datos que se está creando. Si la clave dada ya existe, se realizará una acción especificada por mode:
CDB_FI
ND
verifica si el registro dado ya está en la base de
datos.
CDB_FIND_REM
OVE
elimina todos los registros coincidentes reescribiendo el archivo de la base de datos en
consecuencia.
CDB_FIND_FIL
L0
rellena todos los registros coincidentes con ceros y los elimina del índice para que los registros en cuestión no se puedan encontrar con cdb_find(). Esto es más rápido que CDB_FIND_REMOVE, pero deja "huecos" de ceros en la base
de datos. Los registros insertados más r
ecientemente, si coinciden, siempre se eliminan.

Si no se encontraron claves coincidentes, la rutina devuelve 0. En caso de que se haya encontrado/eliminado al menos un registro, se devolverá un valor positivo. En caso de error, se devolverá un valor negativo y errno se establecerá apropiadamente. Cuando cdb_make_find() devolvió un valor negativo en caso de error, no es posible continuar construyendo la base de

datos.

cdb_make_exists() es lo mismo que llamar a cdb_make_find() con mode estableci

do en CD
B_FIND. 
int cdb_make_put(cdbmp, key, klen, val, vlen, mode)
   struct cdb_make *cdbmp;
   const void *key, *val;
   unsigned klen, vlen;
   int mode
;
Esta es una combinación de las rutinas cdb_make_exists() y cdb_make_add(). El argumento mode controla cómo se tratarán las claves repetidas (ya existentes):
CDB_PUT_A
DD
no se realizará ninguna verificación de duplicados. Este modo es el mismo que hace la rutina cdb_make_a
dd().
CDB_PUT_REPL
ACE
Si la clave ya existe, se eliminará de la base de datos antes de agregar el nuevo par clave,valor. Esto requiere mover datos en el archivo y puede ser bastante lento si el archivo es grande. Todos los registros antiguos coincidentes se eliminarán de esta manera. Esto es lo mismo que llamar a cdb_make_find() con el argumento de modo CDB_FIND_REMOVE seguido de una llamada a cdb_make_a
dd().
CDB_PUT_REPLA
CE0
Si la clave ya existe y no es el último registro en el archivo, el registro antiguo se pondrá a ceros antes de agregar el nuevo par clave,valor. Esto es mucho más rápido que CDB_PUT_REPLACE, pero algunos datos extra aún estarán presentes en el archivo. Los datos -- el registro antiguo -- no serán accesibles por búsquedas normales, pero aparecerán en un recorrido secuencial de la base de datos. Esto es lo mismo que llamar a cdb_make_find() con el argumento de modo CDB_FIND_FILL0 seguido de cdb_make_a
dd().
CDB_PUT_INSE
RT
agrega el par clave,valor solo si tal clave no existe en la base de datos. Tenga en cuenta que como la consulta (ver modo de consulta arriba) encontrará el primer registro agregado, este modo es algo inútil (pero permite reducir el tamaño de la base de datos en caso de claves repetidas). Esto es lo mismo que llamar a cdb_make_exists(), seguido de cdb_make_add() si la clave no fue
encontrada.
CDB_PUT_WA
RN
agrega el par clave,valor incondicionalmente, pero también verifica si esta clave ya existe. Esto es equivalente a llamar a cdb_make_exists() para verificar la existencia de la clave dada, seguido incondicionalmente por cdb_make
_ad
d().

Si ocurrió algún error durante las operaciones, la rutina devolverá un entero negativo y establecerá la variable global errno para indicar la razón del fallo. En caso de operación exitosa y sin duplicados encontrados, la rutina devolverá 0. Si se encontraron o eliminaron duplicados (lo cual, en el caso del modo CDB_PUT_INSERT, indica que el nuevo registro no fue agregado), la rutina devolverá un valor positivo. Si ocurrió un error y cdb_make_put() devolvió un error negativo, no es posible continuar el proceso de construcción de la base de

datos.

Al igual que con cdb_make_exists() y cdb_make_find(), el uso de esta rutina con cualquier modo que no sea CDB_PUT_ADD puede ralentizar significativamente el proceso de creación de la base de datos, especialmente cuando mode es igual a CDB_PUT_REPLACE

0

   unsigned num;
