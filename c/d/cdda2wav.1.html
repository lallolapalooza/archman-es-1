CDDA2WAV(1) General Commands Manual CDDA2WAV(1)

NOMBRE

cdda2wav - extrae datos de audio de CD a archivos de sonido con verificación de datos adicional

SINOPSIS

cdda2wav [ opciones ][ dev=dispositivo ] [archivos o directorios]

DESCRIPCIÓN

cdda2wav puede recuperar pistas de audio de unidades CDROM capaces de leer datos de audio digitalmente a través de SCSI (CDDA).

Como cdda2wav implementa estrategias para sortear defectos típicos de los CD de audio, lee muchos discos que no pueden ser leídos por otro software. Como cdda2wav puede usar libparanoia (ver la opción -paranoia abajo) para verificar los datos leídos del medio, entrega una calidad superior incluso si el medio está polvoriento, rayado o si ocurren otros problemas.

Como cdda2wav puede ser dirigido a escribir los datos de audio a stdout, escribe toda su información de salida a stderr por defecto. Ver la opción out-fd=descriptor abajo.

Configuración predeterminada

Cdda2wav por defecto lee la primera pista de audio del medio y el nivel de verbosidad predeterminado se establece en -vtoc,summary,sectors,titles y cdda2wav por defecto escribe archivos *.inf. Para extraer todas las pistas de audio con verificación de calidad, se recomienda llamar:

cdda2wav -vall cddb=0 speed=4 -paranoia paraopts=proof -B

Para obtener pistas sobre cómo especificar parámetros mejores manualmente, consulte la descripción de paraopts= abajo.

Nomenclatura del dispositivo

La mayoría de los usuarios no necesitan preocuparse por la nomenclatura de dispositivos. Si no se especificó la opción dev=, cdda2wav implementa soporte de objetivo automático y encuentra automáticamente la unidad cuando solo hay un tipo de unidad CD-ROM disponible en el sistema. Cuando existen más de una unidad de tipo CD-ROM, una lista de posibles parámetros de nombres de dispositivo puede recuperarse con cdda2wav -scanbus o del ejemplo de objetivo de la salida de cdda2wav dev=help, entonces el parámetro dev= puede ser establecido basándose en la lista de dispositivos.

El parámetro dispositivo para la opción dev= explicada abajo se refiere a la notación estándar de SCSI CAM para busscsi/objetivo/lun de la Grabadora de CD/DVD/BluRay. Si existe un archivo /etc/default/cdrecord, el parámetro para la opción dev= también puede ser una etiqueta de nombre de unidad en dicho archivo (ver sección ARCHIVOS).

-paranoia
use the paranoia library as a filter on top of cdda2wav's routines for reading. In paranoia mode, the latency time for the -interactive mode and with a read ahead buffer size of 150..300 sectors, is increased to typically 5..10 seconds. This is due to the paranoia code reading everything at least twice and having to empty the cache RAM of the CD-ROM drive.

The size of the read ahead area must be larger than the size of the RAM of the drive in order to allow libparanoia to empty the cache RAM in the drive. As the size of the read ahead area in former times was a constant compiled into the libparanoia code, the extract quality with using libparanoia was no longer sufficient with drives built after year 2000. See readahead= parameter to the paraopts= option below.

If the paranoia mode is used, cdda2wav displays some quality statistics for each extracted track. The following items appear in the list:

Value Description
rderr Number of hard read errors
skip Number of sectors skipped due to exhausted retries
atom Number of intra sector jitters (frame jitters) detected
edge Number of jitters between sectors detected
drop Number of dropped bytes fixed
dup Number of duplicate bytes fixed
drift Number of drifts detected
c2 Number of sectors with C2 errors
reads Number of readahead blocks read and percentage to track size
overlap Number of dynamic overlap size raises

The quality indicators in detail:

rderr
The number of failed low level read requests. Each read appears for sectors-per-request sectors. The sectors-per-request size is typically less than the read ahead size.
skip
The number of sectors that have been skipped because the read error retry count was exhausted and no successful read was possible.
atom
The number of jitters that have been detected inside sectors. This should never happen, but whenever a non-correctable C2 error occurs, the drive could lose streaming. Increasing the read ahead buffer size may reduce the results from atom errors.
edge
The number of jitters that have been detected at the edges of sectors. This could be caused by sector positioning errors. Increasing the read ahead buffer size may reduce the results from edge errors.
drop
The number of dropped samples. This could be caused by sector positioning errors. Increasing the read ahead buffer size may reduce the results from edge errors.
dup
Duplicated samples could be caused by sector positioning errors like dripped samples. Increasing the read ahead buffer size may reduce the results from edge errors.
drift
This is the amount of drifts detected when checking the overlap area.
c2
The number of sectors with C2 errors seen when reading the last track. As the paranoia code tends to read bad parts of the disk many times, this number usually is above the number that would appear when the disk is just read once in a linear way. Use paraopts=disable,c2check to see a number that represents the state of the medium.
reads
The number of read ahead blocks read for the last track by the upper layer and the percentage of the amount of data read compared to the size of the track. This percentage is typically 200% because the paranoia code reads all data at least twice. If there is a lot of overlap and a lof of read problems, this percentage raises.
overlap
The number the overlap size has been raised. This happens when the overlap size is below the maximum overlap size and errors in the overlap area are detected.

DISCUSIÓ

N

cdda2wav es capaz de leer partes de un CD de audio o un CDROM multimedia (que contiene partes de audio) directamente de forma digital. Estas partes se pueden escribir en un archivo, una tubería (pipe) o en un dispositivo de

sonido.

cdda2wav significa CDDA a WAV (donde CDDA significa compact disc digital audio (disco compacto de audio digital) y WAV es un formato de muestra de sonido introducido por MS Windows). Permite copiar datos de audio CDDA desde la unidad CDROM a un archivo en WAV u otros

formatos.

Algunas versiones de cdda2wav pueden intentar obtener prioridades de programación de tiempo real más altas para garantizar una operación fluida (sin interrupciones). Estas prioridades están disponibles para los superusuarios y son más altas que las de los procesos 'normales'. Así, se minimizan los

retrasos.

Si solo tiene un CDROM y está cargado con un CD de audio, puede invocar simplemente cdda2wav y creará el archivo de sonido audio.wav grabando toda la pista comenzando con la pista 1 en estéreo a 16 bits con una frecuencia de muestreo de 44100 Hz, si su sistema de archivos tiene suficiente espacio libre. De lo contrario, el tiempo de grabación será limitado. Para más detalles, consulte los archivos README y README.INS

TALL.

Si tiene más de una unidad de tipo CD-ROM en el sistema, necesita especificar la opción

de

J'ai rencontré des problèmes avec des fréquences d'échantillonnage très basses (stéréo <= 1575 Hz, mono <= 3675 Hz) en essayant de les jouer avec des lecteurs WAV standard pour sound blaster (peut-être ne sont-ils pas légaux dans le format [[75]] WAV). La plupart des graveurs CD insistent pour des échantillons audio dans un format bigendian. Maintenant cdda2wav supporte l'option -E endianess pour contrôler l'endianness des échantillons écrits. Si votre matériel est assez rapide pour exécuter cdda2wav sans interruption

et

votre lecteur CD est l'un des 'parfaits', vous gagnerez en vitesse en désactivant tous les échantillonnages de recouvrement avec l'option -P 0. Un réglage fin supplémentaire peut être fait avec l'option -n sectors. Vous pouvez spécifier combien de secteurs doivent être demandés en une fois. Cdda2wav supporte les pipes. Utilisez un nom de fichier - pour faire envoyer

les

échantillons de cdda2wav vers la sortie standard. La conversion vers d'autres formats sonores est possible en

utilisant

le programme sox (il ne devrait plus être nécessaire d'utiliser sox -x pour changer l'ordre des octets des échantillons ; voir l'option -E pour changer l'ordre des octets de sortie). Si vous voulez échantillonner plus d'une piste dans

différents

fichiers en une seule fois, cela est actuellement possible avec l'option -B. Lorsque le temps d'enregistrement dépasse la limite de piste, un nouveau fichier sera ouvert pour la pist

e suivante. FICHIERS Cdda2wav peu
t générer beaucoup de fichiers à

Plusieurs fichiers peuvent être écrits lorsquel'option de copie en masse ( -B) est utilisée. Des noms de fichiers individuelspeuvent être donnés comme arguments. Si le nombre de noms de fichiers donnés est suffisant pour couvrir toutes les pistes audio incluses, les noms de fichiers seront utilisés tels quels. Sinon, s'il y a moins de noms de fichiers

que de fichiers nécessaires pour écrire les pistes incluses, la partie du nom de fichier avant l'extension es
t étendue avec '_dd' où dd représente le numéro de piste courant. Fichiers Cddb et Cdindex : Si cdda2wav détecte des

informations de titre cd-extra

ou

cd-text (album/piste), alors les fichiers .cddb, .cdindex et .cdtext sont générés sauf s'ils sont supprimés par l'option -H. Ils contiennent des entrées convenablement formatées pour la soumission aux bases de données de titres de pistes de CD audio sur Internet. Les systèmes CDINDEX et CDDB(tm) sont actuellement supportés. Pour

plus d'informations veuillez visiter www.musicbrainz.org et www.freedb.
com. Fichiers Inf : Les fichiers inf décrivent les fichiers d'échantillons

la

partie du CD audio dont ils ont été extraits. Ils sont un moyen de transférer des informations à un programme de gravure de CD comme cdrecord. Par exemple, si le CD audio d'origine avait la pré-accentuation activée, et que cdda2wav -T a supprimé la pré-accentuation, alors le fichier inf n'a pas la pré-accentuation définie (puisque le fichier audio ne l'a plus), tandis que les fic

hiers .cddb et .cdindex ont la pré-accentuation dé
