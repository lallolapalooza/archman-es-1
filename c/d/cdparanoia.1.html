CDPARANOIA(1) Manual de Comandos Generales CDPARANOIA(1)

NOMBRE

cdparanoia 10.2 (Paranoia release III) - una utilidad de lectura de CD de audio que incluye características adicionales de verificación de datos

SINOPSIS

cdparanoia [opciones] intervalo [archivo_salida]

DESCRIPCIÓN

cdparanoia recupera pistas de audio de unidades de CDROM capaces de CDDA. Los datos se pueden guardar en un archivo o dirigir a la salida estándar en formato WAV, AIFF, AIFF-C o crudo. La mayoría de las marcas de unidades de CDROM ATAPI, SCSI y varias propietarias son compatibles; cdparanoia puede determinar si la unidad de destino es capaz de CDDA.

Además de la lectura simple, cdparanoia agrega verificación de datos extra robusta, sincronización, manejo de errores y capacidad de reconstrucción de rayones.

OPCIONES

-A --analyze-drive
Ejecuta y registra un análisis completo del almacenamiento en caché, la temporización y el comportamiento de lectura de la unidad; verifica que cdparanoia esté modelando correctamente la caché y el comportamiento de lectura de una unidad específica. Implica -vQL.
-v --verbose
Sea absurdamente detallado sobre el proceso de auto-detección y lectura. Bueno para configuración y depuración.
-q --quiet
No imprima ninguna información de progreso o error durante el proceso de lectura.
-e --stderr-progress
Forzar la salida de información de progreso a stderr (para scripts envolventes).
-l --log-summary [archivo]
Guarda el resumen del resultado en un archivo, el nombre de archivo predeterminado es cdparanoia.log.
-L --log-debug [archivo]
Guarda la auto-detección detallada del dispositivo y la salida de depuración en un archivo, el nombre de archivo predeterminado es cdparanoia.log.
-V --version
Imprime la versión del programa y sale.
-Q --query
Realiza la auto-detección de la unidad de CDROM, consulta e imprime la tabla de contenidos del CDROM, y luego sale.
-s --search-for-drive
Fuerza una búsqueda completa de una unidad de CDROM, incluso si existe el enlace /dev/cdrom.
-h --help
Imprime un breve resumen del uso y las opciones de cdparanoia.
-p --output-raw
Salida de datos sin encabezado como datos crudos PCM de 16 bits con muestras intercaladas en el orden de bytes del host. Para forzar el orden de bytes little o big endian, use -r o -R como se describe a continuación.
-r --output-raw-little-endian
Salida de datos sin encabezado como datos crudos PCM de 16 bits con muestras intercaladas en orden de bytes LSB primero.
-R --output-raw-big-endian
Salida de datos sin encabezado como datos crudos PCM de 16 bits con muestras intercaladas en orden de bytes MSB primero.
-w --output-wav
Salida de datos en formato WAV RIFF de Micro$oft (tenga en cuenta que los datos WAV siempre están en orden de bytes LSB primero).
-f --output-aiff
Salida de datos en formato AIFF de Apple (tenga en cuenta que los datos AIFF siempre están en orden de bytes MSB primero).
-a --output-aifc
Salida de datos en formato AIFF-C de Apple sin comprimir (tenga en cuenta que los datos AIFF-C siempre están en orden de bytes MSB primero).
-B --batch

Bandera de salida por lotes estilo Cdda2wav; cdparanoia dividirá la salida en múltiples archivos en los límites de las pistas. Los nombres de archivo de salida se anteponen con 'track#'.

-c --force-cdrom-little-endian
Algunas unidades de CDROM informan incorrectamente su orden de bytes (o no lo informan en absoluto); es posible que cdparanoia adivine mal. Use -c para forzar a cdparanoia a tratar la unidad como un dispositivo little endian.
-C --force-cdrom-big-endian
Como lo anterior, pero fuerza a cdparanoia a tratar la unidad como un dispositivo big endian.
-n --force-default-sectors n
Fuerza al backend de la interfaz a realizar lecturas atómicas de n sectores por lectura. Este número puede ser engañoso; el kernel a menudo dividirá las solicitudes de lectura en lecturas atómicas múltiples (el código Paranoia automatizado es consciente de esto) o permitirá lecturas solo dentro de un rango de tamaño restringido. Esta opción generalmente no debe usarse.
-d --force-cdrom-device dispositivo
Fuerza al backend de la interfaz a leer desde dispositivo en lugar de la primera unidad de CDROM legible que encuentra. Esto se puede usar para especificar dispositivos de cualquier tipo de interfaz válida (ATAPI, SCSI o propietaria).
-k --force-cooked-device dispositivo
Esta opción fuerza el uso de la antigua interfaz de kernel 'ioctl cocinado' con el dispositivo cdrom especificado. La interfaz 'ioctl cocinado' es obsoleta en Linux 2.6 si es que existe. -k no se puede usar con -d o -g.
-g --force-generic-device dispositivo
Esta opción fuerza el uso de la antigua interfaz 'scsi genérico' (sg) con el dispositivo scsi genérico especificado. -g no se puede usar con -k. -g puede usarse con -d para establecer explícitamente tanto el dispositivo cdrom SCSI como el genérico (sg) por separado. Esta opción solo es útil en configuraciones SCSI obsoletas y cuando se usa el controlador scsi genérico (sg).
-S --force-read-speed número
Use esta opción explícitamente para establecer la velocidad de lectura de la unidad de CD (donde sea compatible). Esto puede reducir los subtiempos en máquinas con discos lentos o con poca memoria.
-t --toc-offset número
Use esta opción para forzar el desplazamiento de todo el direccionamiento LBA del disco por la cantidad dada; el valor se agrega a los desplazamientos de inicio en la TOC. Esto se puede usar para desplazar los límites de las pistas para todo el disco manualmente en granularidad de sector. La siguiente opción hace algo similar...
-T --toc-bias
Algunas unidades (generalmente Toshibas aleatorias) informan los valores reales de compensación de inicio de pista en la TOC, pero luego tratan el inicio de la pista 1 índice 1 como sector 0 para todas las operaciones de lectura. Esto resulta en que cada pista parece comenzar demasiado tarde (perdiendo un poco del principio y capturando un poco de la siguiente pista). -T tiene en cuenta este comportamiento. Tenga en cuenta que esta opción hará que cdparanoia intente leer sectores antes o más allá del área de datos de usuario conocida del disco, lo que resultará en errores de lectura en los bordes del disco en la mayoría de las unidades y posiblemente incluso bloqueos graves en algún hardware defectuoso.
-O --sample-offset número
Use esta opción para forzar el desplazamiento de la posición de muestra de salida de todo el disco por la cantidad dada; esto se puede usar para desplazar los límites de las pistas para todo el disco manualmente en granularidad de muestra. Tenga en cuenta que esto hará que cdparanoia intente leer sectores parciales antes o más allá del área de datos de usuario conocida del disco, lo que probablemente causará errores de lectura en la mayoría de las unidades y posiblemente incluso bloqueos graves en algún hardware defectuoso.
-Z --disable-paranoia
Deshabilita todas las características de verificación y corrección de datos. Al usar -Z, cdparanoia lee los datos exactamente como lo haría cdda2wav con una configuración de superposición de cero. Esta opción implica que -Y está activo.
-z --never-skip[=max_retries]
No acepte ningún salto; reintente para siempre si es necesario. Se puede especificar un número máximo opcional de reintentos; para comparar, el valor predeterminado sin -z es actualmente 20.
-Y --disable-extra-paranoia
Deshabilita la verificación de datos intra-lectura; solo se realiza la verificación de superposición en los límites de lectura. Puede fallar si ocurren errores en el área de superposición intentada. No recomendado.
-X --abort-on-skip
Si la lectura se salta debido a datos imperfectos, un rayón, etc., aborta

CARAS SONRIENTES DE SALIDA


:-)
Operación normal, baja/nula fluctuación (jitter)

:-|
Operación normal, fluctuación considerable

:-/
Deriva de lectura

:-P
Pérdida no notificada de flujo en operación de lectura atómica

8-|
Se encuentran problemas de lectura en el mismo punto durante la releectura; difícil de corregir

:-0
Error de transporte SCSI/ATAPI

:-(
Se detectó un arañazo

;-(
Se abandonó el intento de realizar una corrección

8-X
Lectura abortada debido a un error conocido e incorregible

:^D
Extracción finalizada

SÍMBOLOS DE LA BARRA DE PROGRESO

<espacio>
No se necesitan correcciones

-
Se requiere corrección de fluctuación (jitter)

+
Pérdida no notificada de flujo/otro error en la lectura

!
Se encontraron errores después de la corrección de la etapa 1; la unidad está cometiendo el mismo error a través de múltiples releecturas, y cdparanoia tiene problemas para detectarlos.

e
Error de transporte SCSI/ATAPI (corregido)

V
Error/salto no corregido

ARGUMENTO DE INTERVALO (SPAN)

El argumento de intervalo especifica qué pista, pistas o subsecciones de pistas leer. Este argumento es obligatorio. NOTA: A menos que el intervalo sea un número simple, generalmente es una buena idea entrecomillar el argumento de intervalo para protegerlo del shell.

El argumento de intervalo puede ser un número de pista simple o una especificación de desplazamiento/intervalo. La sintaxis de un desplazamiento/intervalo tiene aproximadamente la forma:

1[ww:xx:yy.zz]-2[aa:bb:cc.dd]

Aquí, 1 y 2 son números de pista; los números entre corchetes proporcionan un desplazamiento de mayor resolución dentro de una pista particular. [aa:bb:cc.dd] está en formato horas/minutos/segundos/sectores. Los campos en cero no es necesario especificarlos: [::20], [:20], [20], [20.], etc, se interpretarían como veinte segundos, [10:] serían diez minutos, [.30] serían treinta sectores (75 sectores por segundo).

Cuando se proporciona un solo desplazamiento, se interpreta como un desplazamiento de inicio y la extracción continuará hasta el final de la pista. Si un solo desplazamiento está precedido o seguido de un guion, el desplazamiento faltante implícito se toma como el inicio o el final del disco, respectivamente. Así:

1:[20.35]
Especifica la extracción desde la pista 1, segundo 20, sector 35 hasta el final de la pista 1.
1:[20.35]-
Especifica la extracción desde 1[20.35] hasta el final del disco
-2
Especifica la extracción desde el principio del disco hasta (e incluyendo) la pista 2
-2:[30.35]
Especifica la extracción desde el principio del disco hasta 2:[30.35]
2-4
Especifica la extracción desde el principio de la pista 2 hasta el final de la pista 4.

De nuevo, no olvide proteger los corchetes y los guiones precedentes del shell.

EJEMPLOS

Algunos ejemplos, protegidos del shell:

Solo consultar con búsqueda exhaustiva de una unidad y reporte completo de autosense:


cdparanoia -vsQ

Extraer un disco completo, poniendo cada pista en un archivo separado:


cdparanoia -B

Extraer desde la pista 1, tiempo 0:30.12 hasta 1:10.00:


cdparanoia "1[:30.12]-1[1:10]"

Extraer desde el principio del disco hasta la pista 3:


cdparanoia -- "-3"

El "--" anterior es para distinguir "-3" de un indicador de opción.

SALIDA

El argumento de archivo de salida es opcional; si no se especifica, cdparanoia enviará las muestras a uno de cdda.wav, cdda.aifc, o cdda.raw dependiendo de si se usa -w, -a, -r o -R (-w es el valor predeterminado implícito). El argumento de archivo de salida de - especifica la salida estándar; todos los formatos de datos pueden ser canalizados (piped).

AGRADECIMIENTOS

Joerg Schilling también ha contribuido con experiencia en SCSI a través de su biblioteca genérica de transporte SCSI.
