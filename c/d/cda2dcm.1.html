NOMBRE

cda2dcm - Encapsula un archivo CDA en el formato de archivo DICOM

SINOPSIS

cda2dcm [opciones] cdafile-in dcmfile-out

DESCRIPCIÓN

La utilidad cda2dcm lee un archivo CDA (cdafile-in), lo convierte en una instancia SOP de Almacenamiento CDA Encapsulado de DICOM y almacena los datos convertidos en un archivo de salida (dcmfile-out).

PARÁMETROS

cdafile-in   Nombre del archivo de entrada CDA a encapsular
dcmfile-out  Nombre del archivo de salida DICOM ("-" para stdout)

OPCIONES

opciones generales

  -h   --help
         imprime este texto de ayuda y termina
       --version
         imprime la información de versión y termina
       --arguments
         imprime los argumentos de la línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprime advertencias ni errores
  -v   --verbose
         modo detallado, imprime detalles del procesamiento
  -d   --debug
         modo de depuración, imprime información de depuración
  -ll  --log-level  [l]evel: constante de cadena
         (fatal, error, warn, info, debug, trace)
         usa el nivel l para el registrador
  -lc  --log-config  [f]ilename: cadena
         usa el archivo de configuración f para el registrador

opciones de documento DICOM

título del documento:
  +t   --title  [t]itle: cadena (predeterminado: vacío)
         título del documento
  +cn  --concept-name  [CSD] [CV] [CM]: cadena (predeterminado: vacío)
         representación codificada del título del documento definida por el
         esquema de codificación CSD, el valor de código CV y el significado del código CM
datos del paciente:
  +pn  --patient-name  [n]ame: cadena
         nombre del paciente en sintaxis PN de DICOM
  +pi  --patient-id  [i]d: cadena
         identificador del paciente
  +pb  --patient-birthdate  [d]ate: cadena (AAAAMMDD)
         fecha de nacimiento del paciente
  +ps  --patient-sex  [s]ex: cadena (M, F u O)
         sexo del paciente
estudio y serie:
  +sg  --generate
         genera nuevos UID de estudio y serie (predeterminado)
  +st  --study-from  [f]ilename: cadena
         lee datos de paciente/estudio desde un archivo DICOM
  +se  --series-from  [f]ilename: cadena
         lee datos de paciente/estudio/serie desde un archivo DICOM
número de instancia:
  +i1  --instance-one
         usa el número de instancia 1 (predeterminado, no con +se)
  +ii  --instance-inc
         incrementa el número de instancia (solo con +se)
  +is  --instance-set [i]nstance number: entero
         usa el número de instancia i
anotación incrustada:
  +an  --annotation-yes
         el documento contiene datos de identificación del paciente (predeterminado)
  -an  --annotation-no
         el documento no contiene datos de identificación del paciente
anular datos del archivo CDA:
  -ov  --no-override
         los datos de paciente y documento CDA deben coincidir con la información de estudio,
         serie o ingresada manualmente (predeterminado)
  +ov  --override
         los datos obtenidos del archivo CDA serán sobrescritos
         por la información de estudio, serie o ingresada manualmente

opciones de procesamiento

otras opciones de procesamiento:
  -k   --key  [k]ey: gggg,eeee="str", ruta o nombre de diccionario="str"
         añade un atributo adicional

opciones de salida

formato del archivo de salida:
  +F   --write-file
         escribe el formato de archivo (predeterminado)
  -F   --write-dataset
         escribe el conjunto de datos sin información de metadatos del archivo
codificación de longitud de grupo:
  +g=  --group-length-recalc
         recalcula las longitudes de grupo si están presentes (predeterminado)
  +g   --group-length-create
         escribe siempre con elementos de longitud de grupo
  -g   --group-length-remove
         escribe siempre sin elementos de longitud de grupo
codificación de longitud en secuencias e ítems:
  +e   --length-explicit
         escribe con longitudes explícitas (predeterminado)
  -e   --length-undefined
         escribe con longitudes indefinidas
relleno al final del conjunto de datos (no con --write-dataset):
  -p   --padding-off
         sin relleno (implícito si --write-dataset)
  +p   --padding-create  [f]ile-pad [i]tem-pad: entero
         alinea el archivo en múltiplos de f bytes
         y los ítems en múltiplos de i bytes

NOTAS

Fuentes de atributos

La aplicación puede recibir alguna entrada adicional para rellenar atributos obligatorios (y opcionales) en el nuevo archivo DICOM, como información de paciente, estudio y serie:

  • La opción --key puede usarse para añadir más atributos al archivo de salida DICOM.
  • También es posible especificar secuencias, ítems y atributos anidados usando la opción --key . En estos casos, debe usarse una notación especial de "ruta". Los detalles sobre esta notación de ruta se encuentran en la documentación de dcmodify.
  • La opción --key puede aparecer más de una vez.
  • La parte del valor (después del '=') puede estar ausente, lo que hace que el atributo se establezca con longitud cero.
  • Tenga en cuenta que la opción --key se aplica al final, justo antes de guardar el archivo DICOM, por lo que no hay ninguna comprobación de valores.

REGISTRO

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de registro), en syslog (Unix) o en el registro de eventos (Windows), puede usarse la opción --log-config . Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basados en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo inicial '+' o '-' respectivamente. Normalmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comando usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

CÓDIGOS DE SALIDA

La utilidad cda2dcm usa los siguientes códigos de salida al terminar. Esto permite al usuario comprobar la razón por la que terminó la aplicación.

general

EXITCODE_NO_ERROR                 0
EXITCODE_COMMANDLINE_SYNTAX_ERROR 1
EXITCODE_MEMORY_EXHAUSTED         4

errores de archivo de entrada

EXITCODE_CANNOT_READ_INPUT_FILE   20
EXITCODE_NO_INPUT_FILES           21
EXITCODE_INVALID_INPUT_FILE       22

errores de archivo de salida

EXITCODE_CANNOT_WRITE_OUTPUT_FILE 40

ENTORNO

El cda2dcm utilidad intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell de Unix, en la que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.
