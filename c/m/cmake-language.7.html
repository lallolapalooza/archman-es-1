Argumento No Citado


Un argumento no citado no está delimitado por ninguna sintaxis de
    citación. No puede contener ningún espacio en blanco, (, ), #,
    " o \, excepto cuando se escapa con una barra invertida:


argumento_no_citado ::= elemento_no_citado+ | argumento_no_citado_legacy
elemento_no_citado  ::= <cualquier carácter excepto espacio en blanco o uno de '()#"\'> |
                      secuencia_de_escape
argumento_no_citado_legacy   ::= <ver nota en el texto>


El contenido de un argumento no citado consiste en todo el texto en un
    bloque contiguo de caracteres permitidos o escapados. Tanto las secuencias de
    escape como las referencias a variables se evalúan. El valor resultante se divide
    de la misma manera en la que las listas se dividen en elementos. Cada elemento
    no vacío se proporciona a la invocación del comando como un argumento. Por lo
    tanto, un argumento no citado puede ser proporcionado a una invocación de
    comando como cero o más argumentos.


Por ejemplo:






foreach(arg
    SinEspacio
    Espacio\Escapado
    Esto;Divide;En;Cinco;Argumentos
    PuntoYComa\Escapado
    )
  message("${arg}")
endforeach()






Nota:




Para soportar código CMake heredado, los argumentos no citados también
  pueden contener cadenas con comillas dobles ("...", posiblemente
  envolviendo espacios horizontales), y referencias a variables de estilo Make
  ($(MAKEVAR)).

Las comillas dobles no escapadas deben equilibrarse, no pueden aparecer
    al principio de un argumento no citado y se tratan como parte del contenido.
    Por ejemplo, los argumentos no citados -Da="b c",
    -Da=$(v) y a" "b"c"d se interpretan literalmente. En su
    lugar, pueden escribirse como argumentos citados
    "-Da=\"b c\"", "-Da=$(v)" y
    "a\" \"b\"c\"d", respectivamente.


Las referencias de estilo Make se tratan literalmente como parte del
    contenido y no sufren expansión de variables. Se tratan como parte de un solo
    argumento (en lugar de argumentos separados $, (, MAKEVAR y
    )).


La producción anterior "argumento_no_citado_legacy" representa
    tales argumentos. No recomendamos usar argumentos no citados heredados en nuevo
    código. En su lugar, use un Argumento Citado o un Argumento entre Corchetes para
    representar el contenido.










Secuencias de Escape


Una secuencia de escape es un \ seguido de un
  carácter:


secuencia_de_escape  ::= secuencia_de_escape_identidad | secuencia_de_escape_codificada | secuencia_de_escape_punto_y_coma
secuencia_de_escape_identidad  ::= '\' <coincide con '[^A-Za-z0-9;]'>
secuencia_de_escape_codificada   ::= '\t' | '\r' | '\n'
secuencia_de_escape_punto_y_coma ::= '\;'


Un \ seguido de un carácter no alfanumérico simplemente codifica
    el carácter literal sin interpretarlo como sintaxis. Un \t,
    \r o \n codifica un carácter de pestaña, retorno de carro o
    nueva línea, respectivamente. Un \; fuera de cualquier Referencia a
    Variable codifica a sí mismo, pero puede usarse en un Argumento No Citado para
    codificar el ; sin dividir el valor del argumento sobre él. Un \;
    dentro de Referencias a Variables codifica el carácter literal ;. (Véase
    también la documentación de la política CMP0053 <#policy:CMP0053>
    para consideraciones históricas.)






Referencias a Variables


Una referencia a variable tiene la forma
    ${<variable>} y se evalúa dentro de un Argumento Citado o un
    Argumento No Citado. Una referencia a variable es reemplazada por el valor de
    la variable o entrada de caché especificada, o si ninguna está establecida, por
    la cadena vacía. Las referencias a variable pueden anidarse y se evalúan desde
    adentro hacia afuera, por ejemplo ${outer_${inner_variable}_variable}.


Las referencias a variable literal pueden consistir en caracteres
    alfanuméricos, los caracteres /_.+- y Secuencias de Escape. Las
    referencias anidadas pueden usarse para evaluar variables de cualquier nombre.
    Véase también la documentación de la política CMP0053 <#policy:CMP0053>
    para consideraciones históricas y las razones por las que el $ también es
    técnicamente permitido pero se desalienta.


La sección de Variables documenta el alcance de los nombres de
    variables y cómo se establecen sus valores.


Una referencia a variable de entorno tiene la forma
    $ENV{<variable>}. Véase la sección de Variables de Entorno para
    más información.


Una referencia a variable de caché tiene la forma
    $CACHE{<variable>}, y se reemplaza por el valor de la entrada de
    caché especificada sin comprobar si existe una variable normal del mismo nombre.
    Si la entrada de caché no existe, se reemplaza por la cadena vacía.
    Véase CACHE <#variable:CACHE> para más información.


El comando if() <#command:if> tiene una sintaxis especial
    de condición que permite referencias a variables en la forma corta
    <variable> en lugar de ${<variable>}. Sin embargo,
    las variables de entorno siempre deben referirse como
    $ENV{<variable>}.






Comentarios


Un comentario comienza con un carácter # que no está dentro
    de un Argumento entre Corchetes, un Argumento Citado, o escapado con \
    como parte de un Argumento No Citado. Hay dos tipos de comentarios: un
    Comentario entre Corchetes y un Comentario de Línea.






Comentario entre Corchetes


Un # inmediatamente seguido de un bracket_open forma un
    comentario entre corchetes que consiste en toda la envolvente de corchetes:


comentario_entre_corchetes ::= '#' argumento_entre_corchetes


Por ejemplo:






#[[Este es un comentario entre corchetes.
Funciona hasta el cierre de corchete.]]
message("Primer Argumento\n" #[[Comentario entre corchetes]] "Segundo Argumento")






Nota:




Las versiones de CMake anteriores a 3.0 no soportan comentarios
  entre corchetes. Interpretan la apertura # como el inicio de un
  Comentario de Línea.








Comentario de Línea


Un # no inmediatamente seguido de un bracket_open forma
    un comentario de línea que funciona hasta el final de la línea:


comentario_de_linia ::= '#' <cualquier texto que no comience en un bracket_open
                 y no contenga un nueva_linia>


Por ejemplo:






# Este es un comentario de línea.
message("Primer Argumento\n" # Este es un comentario de línea :)
        "Segundo Argumento") # Este es un comentario de línea.












ESTRUCTURAS DE CONTROL




Bloques Condicionales


Los comandos if() <#command:if>/elseif()
    <#command:elseif>/else() <#command:else>/endif()
    <#command:endif> delimitan bloques de código para ser ejecutados
    condicionalmente.






Bucles


Los comandos foreach() <#command:foreach>/endforeach()
    <#command:endforeach> y while()
    <#command:while>/endwhile() <#command:endwhile> delimitan bloques de
    código para ser ejecutados en un bucle. Dentro de tales bloques el comando
    break() <#command:break> puede usarse para terminar el bucle
    prematuramente, mientras que el comando continue() <#command:continue>
    puede usarse para comenzar con la siguiente iteración inmediatamente.






Definiciones de Comando


Los comandos macro() <#command:macro>/endmacro()
    <#command:endmacro>, y function()
    <#command:function>/endfunction() <#command:endfunction> delimitan
    bloques de código para ser registrados para una invocación posterior como
    comandos.








VARIABLES


Las variables son la unidad básica de almacenamiento en el Lenguaje
    de CMake. Sus valores siempre son de tipo cadena, aunque algunos comandos pueden
    interpretar las cadenas como valores de otros tipos. Los comandos set()
    <#command:set> y unset() <#command:unset> establecen explícitamente
    o desestablecen una variable, pero otros comandos tienen semánticas que modifican
    las variables también. Los nombres de variable son sensibles a mayúsculas y
    minúsculas y pueden consistir en casi cualquier texto, pero recomendamos
    mantenerse con nombres que consistan únicamente en caracteres alfanuméricos más
    _ y -.


Las variables tienen alcance dinámico. Cada variable "set" o
    "unset" crea un enlace en el alcance actual:





  
Alcance de Bloque

  
El comando block() <#command:block> puede crear un nuevo alcance
      para los enlaces de variables.

  
Alcance de Función

  
Las Definiciones de Comando creadas por el comando function()
      <#command:function> crean comandos que, cuando se invocan, procesan los
      comandos registrados en un nuevo alcance de enlace de variables. Una variable
      "set" o "unset" se vincula en este alcance y es visible
      para la función actual y cualquier llamada anidada dentro de ella, pero no
      después de que la función devuelva.

  
Alcance de Directorio

  
Cada uno de los Directorios en un árbol de fuentes tiene su propia varivinculaciones.
      Antes de procesar el archivo CMakeLists.txt de un directorio, CMake
      copia todas las vinculaciones de variables actualmente definidas en el
      directorio padre, si las hay, para inicializar el nuevo ámbito de directorio.
      Los Scripts de CMake, cuando se procesan con cmake -P <#cmdoption-cmake-P>,
      vinculan variables en un ámbito de "directorio".
    
Una variable "set" o "unset" que no esté dentro de una
        llamada a función se vincula al ámbito de directorio actual.

  

  
Caché
    Persistente

  
CMake almacena un conjunto separado de variables "caché" o "entradas de
      caché", cuyos valores persisten a través de múltiples ejecuciones dentro
      del árbol de construcción del proyecto. Las entradas de caché tienen un
      ámbito de vinculación aislado que solo se modifica mediante solicitud
      explícita, como mediante la opción CACHE del comando set()
      <#command:set> y el comando unset() <#command:unset>.






Al evaluar Referencias de Variables, CMake primero busca en la
    pila de llamadas de función, si existe, una vinculación y luego recurre a
    la vinculación en el ámbito de directorio actual, si existe. Si se encuentra
    una vinculación "set", se utiliza su valor. Si se encuentra una vinculación
    "unset" o no se encuentra ninguna vinculación, CMake luego busca una entrada
    de caché. Si se encuentra una entrada de caché, se utiliza su valor. De lo
    contrario, la referencia de variable evalúa a una cadena vacía. La sintaxis
    $CACHE{VAR} puede usarse para realizar búsquedas directas de entradas
    de caché.


El manual cmake-variables(7) <#manual:cmake-variables(7)>
    documenta las muchas variables que proporciona CMake o tienen significado
    para CMake cuando se establecen por el código del proyecto.

VARIABLES
    DEL ENTORNO


Las variables del entorno son como las variables ordinarias, con
    las siguientes diferencias:





  
Ámbito

  
Las variables del entorno tienen ámbito global en un proceso de CMake.
      Nunca se almacenan en caché.

  
Referencias

  
Las Referencias de Variable tienen la forma $ENV{<variable>},
      utilizando el operador ENV <#variable:ENV>.

  
Inicialización

  
Los valores iniciales de las variables del entorno de CMake son los del
      proceso llamante. Los valores pueden cambiarse utilizando los comandos
      set() <#command:set> y unset() <#command:unset>.
      Estos comandos solo afectan al proceso de CMake en ejecución, no al
      entorno del sistema en general. Los valores modificados no se escriben
      de nuevo en el proceso llamante y no son vistos por los procesos de
      construcción o prueba subsiguientes.
      
Vea la herramienta de línea de comandos cmake -E env
        <#cmdoption-cmake-E-arg-env> para ejecutar un comando en un entorno
        modificado.

  

  
Inspección

  
Vea la herramienta de línea de comandos cmake -E environment
      <#cmdoption-cmake-E-arg-environment> para mostrar todas las variables
      del entorno actuales.






El manual cmake-env-variables(7)
    <#manual:cmake-env-variables(7)> documenta las variables del entorno que
    tienen un significado especial para CMake.






LISTAS


Aunque todos los valores en CMake se almacenan como cadenas, una
    cadena puede tratarse como una lista en ciertos contextos, como durante la
    evaluación de un Argumento sin comillas. En tales contextos, una cadena se
    divide en elementos de lista dividiendo por caracteres ; que no
    sigan un número desigual de caracteres [ y ] y no estén
    inmediatamente precedidos por un \. La secuencia \; no divide
    un valor, sino que se reemplaza por ; en el elemento resultante.


Una lista de elementos se representa como una cadena concatenando
    los elementos separados por ;. Por ejemplo, el comando set()
    <#command:set> almacena múltiples valores en la variable de destino como
    una lista:






set(srcs a.c b.c c.c) # establece "srcs" en "a.c;b.c;c.c"






Las listas están destinadas para casos de uso simples, como una
    lista de archivos de fuente, y no deben usarse para tareas de procesamiento
    de datos complejos. La mayoría de los comandos que construyen listas no
    escapifican caracteres ; en los elementos de la lista, lo que aplanar
    listas anidadas:






set(x a "b;c") # establece "x" en "a;b;c", no "a;b\;c"






En general, las listas no soportan elementos que contengan
    caracteres ;. Para evitar problemas, considere los siguientes
    consejos:




    
  
  • Las interfaces de muchos comandos, variables y propiedades de CMake
      aceptan listas separadas por comas. Evite pasar listas con elementos que
      contengan comas a estas interfaces a menos que documenten soporte directo
      o alguna manera de escapar o codificar comas.
    • 
  
  • Al construir una lista, sustituya un marcador de posición no utilizado
      de otro modo por ; en los elementos. Luego sustituya ; por
      el marcador de posición al procesar elementos de lista. Por ejemplo, el
      siguiente código utiliza | en lugar de caracteres ;:
    • 







set(mylist a "b|c")
foreach(entry IN LISTS mylist)
  string(REPLACE "|" ";" entry "${entry}")
  # use "${entry}" normalmente
endforeach()






La opción LIST_SEPARATOR del módulo ExternalProject
    <#module:ExternalProject> es un ejemplo de una interfaz construida
    utilizando este enfoque.


    
  
  • En listas de generator expressions
      <#manual:cmake-generator-expressions(7)>, utilice la expresión
      generadora $<SEMICOLON> <#genex:SEMICOLON>.
    • 
  
  • En llamadas a comandos, utilice la sintaxis de Argumento con comillas
      siempre que sea posible. El comando llamado recibirá el contenido del
      argumento con las comas conservadas. Un Argumento sin comillas se dividirá
      en comas.
    • 
  
  • En implementaciones de function() <#command:function>, evite
      ARGV y ARGN, que no distinguen comas en valores de aquellas
      que separan valores. En su lugar, prefiera usar argumentos posicionales
      nombrados y las variables ARGC y ARGV#. Al usar
      cmake_parse_arguments() <#command:cmake_parse_arguments> para
      analizar argumentos, prefiera su firma PARSE_ARGV, que usa las
      variables ARGV#.
      
    Nota que este enfoque no se aplica a implementaciones de
        macro() <#command:macro> porque se refieren a argumentos
        usando marcadores de posición, no variables reales.
