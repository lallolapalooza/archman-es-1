DESCRIPCIÓ

N

Estas macros se utilizan para crear y acceder a mensajes de control (también llamados datos auxiliares) que no forman parte de la carga útil del socket. Esta información de control puede incluir la interfaz en la que se recibió el paquete, varios campos de cabecera poco utilizados, una descripción extendida de errores, un conjunto de descriptores de archivo o credenciales UNIX. Por ejemplo, los mensajes de control se pueden usar para enviar campos de cabecera adicionales, como las opciones IP. Los datos auxiliares se envían llamando a sendmsg(2) y se reciben llamando a recvmsg(2). Consulte sus páginas de manual para obtener más

información.

Los datos auxiliares son una secuencia de estructuras cmsghdr con datos adjuntos. Consulte las páginas de manual de los protocolos específicos para conocer los tipos de mensajes de control disponibles. El tamaño máximo del búfer auxiliar permitido por socket se puede configurar usando /proc/sys/net/core/optmem_max; consulte socket(

7).

La estructura cmsghdr se define como

sigue: 


struct cmsghdr {
    size_t cmsg_len;    /* Recuento de bytes de datos, incluyendo la cabecera
                           (el tipo es socklen_t en POSIX) */
    int    cmsg_level;  /* Protocolo de origen */
    int    cmsg_type;   /* Tipo específico del protocolo */
/* seguido de
   unsigned char cmsg_data[]; */
}
;

La secuencia de estructuras cmsghdr nunca debe ser accedida directamente. En su lugar, use únicamente las siguientes

macros:
CMSG_FIRSTHD
R()
devuelve un puntero al primer cmsghdr en el búfer de datos auxiliares asociado con el msghdr pasado. Devuelve NULL si no hay suficiente espacio para un cmsghdr en el
búfer.
CMSG_NXTHDR
()
devuelve el siguiente cmsghdr válido después del cmsghdr pasado. Devuelve NULL cuando
no queda suficiente
espacio en el búfer.
Al inicializar un búfer que contendrá una serie de estructuras cmsghdr (p. ej., para ser enviadas con sendmsg(2)), ese búfer debe inicializarse primero a cero para garantizar el correcto funcionamiento de CMSG_NX
THD
R().
CMSG_ALIG
N(),
dado un longitud, la devuelve incluyendo la alineación requerida. Esta es una expresión
constante.
CMSG_SPACE
()
devuelve el número de bytes que ocupa un elemento auxiliar con una carga útil de la longitud de datos pasada. Esta es una expresión
constante.
CMSG_DATA
()
devuelve un puntero a la porción de datos de un cmsghdr. No se puede asumir que el puntero devuelto esté alineado adecuadamente para acceder a tipos de datos de carga útiles arbitrarios. Las aplicaciones no deben convertirlo a un tipo de puntero que coincida con la carga útil, sino que deben usar memcpy(3) para copiar datos hacia o desde un objeto declarado
adecuadamente.
CMSG_LEN
()
devuelve el valor a almacenar en el miembro cmsg_len de la estructura cmsghdr, teniendo en cuenta cualquier alineación necesaria. Tom
a la longitud de datos como argume
nto. Esta es una expresión constante.

Para crear datos auxiliares, primero inicialice el miembro msg_controllen de la msghdr con la longitud del búfer del mensaje de control. Use CMSG_FIRSTHDR() en la msghdr para obtener el primer mensaje de control y CMSG_NXTHDR() para obtener todos los siguientes. En cada mensaje de control, inicialice cmsg_len (con CMSG_LEN()), los otros campos de cabecera cmsghdr y la porción de datos usando CMSG_DATA(). Finalmente, el campo msg_controllen de la msghdr debe establecerse en la suma de los CMSG_SPACE() de la longitud de todos los mensajes de control en el búfer. Para obtener más información sobre la msghdr, consulte recvms

g(
2).

VERSIONE

S

Para la portabilidad, los datos auxiliares deben ser accedidos usando únicamente las macros descritas

aquí.

En Linux, CMSG_LEN(), CMSG_DATA() y CMSG_ALIGN() son expresiones constantes (asumiendo que su argumento es constante), lo que significa que estos

valores pueden usarse para declarar el tamaño de var
iables globales. Sin embargo, esto puede no ser portable.

HISTORI

A

Este modelo de datos auxiliares se ajusta al borrador POSIX.1g, 4.4BSD-Lite, la API avanzada IPv6 descrita en la RFC 2292 y

SUSv2.

CMSG_SPACE() y CMSG_LEN() se incluirán en la próxima versión de POSIX (Edición

EJEMPLO

S

Este código busca la opción IP_TTL en un búfer auxiliar

recibido: 


struct msghdr msgh;
struct cmsghdr *cmsg;
int received_ttl;
/* Recibir datos auxiliares en msgh */
for (cmsg = CMSG_FIRSTHDR(&msgh); cmsg != NULL;
        cmsg = CMSG_NXTHDR(&msgh, cmsg)) {
    if (cmsg->cmsg_level == IPPROTO_IP
            && cmsg->cmsg_type == IP_TTL) {
        memcpy(&receive_ttl, CMSG_DATA(cmsg), sizeof(received_ttl));
        break;
    }
}
if (cmsg == NULL) {
    /* Error: IP_TTL no está habilitado, búfer pequeño o error de E/S */
}

};

                   para asegurar que esté alineado adecuadamente */
