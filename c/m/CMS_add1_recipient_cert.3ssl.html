CMS_add1_recipient_cert(3ssl)

Paquete: openssl

Licencias: Apache-2.0

CMS_ADD1_RECIPIENT_CERT(3ssl) OpenSSL CMS_ADD1_RECIPIENT_CERT(3ssl)

NOMBRE

CMS_add1_recipient, CMS_add1_recipient_cert, CMS_add0_recipient_key - añadir destinatarios a una estructura de datos de datos cifrados CMS

SINOPSIS

#include <openssl/cms.h>
CMS_RecipientInfo *CMS_add1_recipient(CMS_ContentInfo *cms, X509 *recip,
                                      EVP_PKEY *originatorPrivKey,
                                      X509 *originator, unsigned int flags);
CMS_RecipientInfo *CMS_add1_recipient_cert(CMS_ContentInfo *cms,
                                           X509 *recip, unsigned int flags);
CMS_RecipientInfo *CMS_add0_recipient_key(CMS_ContentInfo *cms, int nid,
                                          unsigned char *key, size_t keylen,
                                          unsigned char *id, size_t idlen,
                                          ASN1_GENERALIZEDTIME *date,
                                          ASN1_OBJECT *otherTypeId,
                                          ASN1_TYPE *otherType);

DESCRIPCIÓN

CMS_add1_recipient() añade el destinatario recip y proporciona la clave privada del originador originatorPrivKey y el certificado del originador originator a CMS_ContentInfo. Los campos relacionados con el originador son relevantes solo en caso de que se utilice el método de acuerdo de clave para proporcionar la clave compartida.

CMS_add1_recipient_cert() añade el destinatario recip a la estructura de datos cifrados CMS_ContentInfo cms como una estructura KeyTransRecipientInfo o KEMRecipientInfo, o como una estructura KeyAgreeRecipientInfo con una clave efímera.

CMS_add0_recipient_key() añade la clave simétrica key de longitud keylen utilizando el algoritmo de envoltura nid, el identificador id de longitud idlen y los valores opcionales date, otherTypeId y otherType a la estructura de datos cifrados CMS_ContentInfo cms como una estructura KEKRecipientInfo.

La estructura CMS_ContentInfo debe obtenerse de una llamada inicial a CMS_encrypt() con la bandera CMS_PARTIAL establecida.

NOTAS

El propósito principal de esta función es proporcionar un control más fino sobre una estructura de datos cifrados CMS donde la función más simple CMS_encrypt() no es apropiada. Por ejemplo, si se necesita añadir una o más estructuras KEKRecipientInfo. También se pueden añadir nuevos atributos utilizando la estructura CMS_RecipientInfo devuelta y las funciones de utilidad de atributos de CMS.

OpenSSL identificará por defecto los certificados de destinatario utilizando el nombre del emisor y el número de serie. Si se establece CMS_USE_KEYID, utilizará el valor del identificador de clave del sujeto en su lugar. Se produce un error si todos los certificados de destinatario no tienen una extensión de identificador de clave del sujeto.

Actualmente, solo se admiten algoritmos de envoltura de clave basados en AES para nid, específicamente: NID_id_aes128_wrap, NID_id_aes192_wrap y NID_id_aes256_wrap. Si nid se establece en NID_undef, se utilizará un algoritmo de envoltura AES coherente con keylen.

VALORES DE RETORNO

CMS_add1_recipient_cert() y CMS_add0_recipient_key() devuelven un puntero interno a la estructura CMS_RecipientInfo recién añadida o NULL si ocurre un error.

VER TAMBIÉN

ERR_get_error(3), CMS_decrypt(3), CMS_final(3),

HISTORIAL

CMS_add1_recipient_cert y CMS_add0_recipient_key se añadieron en OpenSSL 3.0.
