CMS_add1_signer(3ssl)

Paquete: openssl

Licencias: Apache-2.0

CMS_ADD1_SIGNER(3ssl) OpenSSL CMS_ADD1_SIGNER(3ssl)

NOMBRE

CMS_add1_signer, CMS_SignerInfo_sign - añadir un firmante a una estructura de datos firmada CMS_ContentInfo

SINOPSIS

#include <openssl/cms.h>
CMS_SignerInfo *CMS_add1_signer(CMS_ContentInfo *cms, X509 *signcert,
                               EVP_PKEY *pkey, const EVP_MD *md,
                               unsigned int flags);
int CMS_SignerInfo_sign(CMS_SignerInfo *si);

DESCRIPCIÓN

CMS_add1_signer() añade un firmante con el certificado signcert y la clave privada pkey usando el resumen de mensaje md a la estructura de datos firmada CMS_ContentInfo cms.

La estructura CMS_ContentInfo debe obtenerse de una llamada inicial a CMS_sign() con la bandera CMS_PARTIAL activada o en el caso de re-firmar una estructura CMS_ContentInfo SignedData válida.

Si el parámetro md es NULL se utilizará el resumen predeterminado para el algoritmo de clave pública.

A menos que la bandera CMS_REUSE_DIGEST esté activada, la estructura CMS_ContentInfo devuelta no está completa y debe ser finalizada ya sea por transmisión (si es aplicable) o por una llamada a CMS_final().

La función CMS_SignerInfo_sign() firma explícitamente una estructura CMS_SignerInfo, su uso principal es cuando las banderas CMS_REUSE_DIGEST y CMS_PARTIAL están ambas activadas.

NOTAS

El propósito principal de CMS_add1_signer() es proporcionar un control más fino sobre una estructura de datos firmada CMS donde la función más simple CMS_sign() no sea apropiada por defecto. Por ejemplo, si se necesitan múltiples firmantes o algoritmos de resumen no predeterminados. También se pueden añadir nuevos atributos usando la estructura CMS_SignerInfo devuelta y las funciones de utilidad de atributos CMS o las funciones de solicitud de recibo firmado CMS.

Cualquiera de las siguientes banderas (combinadas mediante OR) puede pasarse en el parámetro flags.

Si se activa CMS_REUSE_DIGEST, se intentará copiar el valor del resumen del contenido de la estructura CMS_ContentInfo: para añadir un firmante a una estructura existente. Ocurre un error si no se encuentra un valor de resumen coincidente para copiar. La estructura CMS_ContentInfo devuelta será válida y finalizada cuando se active esta bandera.

Si se activa CMS_PARTIAL además de CMS_REUSE_DIGEST, la estructura CMS_SignerInfo no se finalizará, por lo que se podrán añadir atributos adicionales. En este caso, se necesita una llamada explícita a CMS_SignerInfo_sign() para finalizarla.

Si se activa CMS_NOCERTS, el certificado del firmante no se incluirá en la estructura CMS_ContentInfo, aunque el certificado del firmante debe seguir suministrándose en el parámetro signcert. Esto puede reducir el tamaño de la firma si el certificado del firmante se puede obtener por otros medios: por ejemplo, un mensaje firmado previamente.

La estructura SignedData incluye varios CMS signedAttributes, incluyendo la hora de la firma, el tipo de contenido CMS y la lista de algoritmos de cifrado compatibles en un atributo SMIMECapabilities. Si se activa CMS_NOATTR, no se utilizarán atributos firmados. Si se activa CMS_NOSMIMECAP, se omitirá SMIMECapabilities. Si se activa CMS_NO_SIGNING_TIME, se omitirá la hora de la firma.

OpenSSL identificará por defecto los certificados de firma usando el nombre del emisor y el número de serie. Si se activa CMS_USE_KEYID, utilizará en su lugar el valor del identificador de clave del sujeto. Se producirá un error si el certificado de firma no tiene una extensión de identificador de clave del sujeto.

Si está presente, el atributo SMIMECapabilities indica soporte para los siguientes algoritmos en orden de preferencia: AES de 256 bits, Gost R3411-94, Gost 28147-89, AES de 192 bits, AES de 128 bits, triple DES, RC2 de 128 bits, RC2 de 64 bits, DES y RC2 de 40 bits. Si alguno de estos algoritmos no está disponible, no se incluirá: por ejemplo, los algoritmos GOST no se incluirán si el motor GOST no está cargado.

CMS_add1_signer() devuelve un puntero interno a la estructura CMS_SignerInfo recién añadida, que puede utilizarse para establecer atributos adicionales antes de que se finalice.

VALORES DE RETORNO

CMS_add1_signer() devuelve un puntero interno a la estructura CMS_SignerInfo recién añadida o NULL si ocurre un error.

CMS_SignerInfo_sign() devuelve 1 si tiene éxito, 0 si falla.
