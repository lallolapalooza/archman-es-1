CMSG(3) Manual de Funciones de Biblioteca CMSG(3)

NOMBRE

CMSG_ALIGN, CMSG_SPACE, CMSG_NXTHDR, CMSG_FIRSTHDR - acceder a datos auxiliares

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/socket.h>
struct cmsghdr *CMSG_FIRSTHDR(struct msghdr *msgh);
struct cmsghdr *CMSG_NXTHDR(struct msghdr *msgh,
                            struct cmsghdr *cmsg);
size_t CMSG_ALIGN(size_t length);
size_t CMSG_SPACE(size_t length);
size_t CMSG_LEN(size_t length);
unsigned char *CMSG_DATA(struct cmsghdr *cmsg);

DESCRIPCIÓN

Estas macros se utilizan para crear y acceder a mensajes de control (también llamados datos auxiliares) que no forman parte de la carga útil del socket. Esta información de control puede incluir la interfaz en la que se recibió el paquete, varios campos de encabezado raramente utilizados, una descripción de error extendida, un conjunto de descriptores de archivo o credenciales UNIX. Por ejemplo, los mensajes de control se pueden usar para enviar campos de encabezado adicionales como las opciones IP. Los datos auxiliares se envían llamando a sendmsg(2) y se reciben llamando a recvmsg(2). Consulte sus páginas de manual para obtener más información.

Los datos auxiliares son una secuencia de cmsghdr estructuras con datos adjuntos. Consulte las páginas de manual específicas del protocolo para ver los tipos de mensajes de control disponibles. El tamaño máximo del búfer auxiliar permitido por socket se puede establecer usando /proc/sys/net/core/optmem_max; véase socket(7).

La cmsghdr estructura se define como sigue:


struct cmsghdr {
    size_t cmsg_len;    /* Recuento de bytes de datos, incluyendo el encabezado
                           (el tipo es socklen_t en POSIX) */
    int    cmsg_level;  /* Protocolo de origen */
    int    cmsg_type;   /* Tipo específico del protocolo */
/* seguido por
   unsigned char cmsg_data[]; */
};

La secuencia de cmsghdr estructuras nunca debe ser accedida directamente. En su lugar, utilice solo las siguientes macros:

CMSG_FIRSTHDR()
devuelve un puntero al primer cmsghdr en el búfer de datos auxiliares asociado con el msghdrpasado. Devuelve NULL si no hay suficiente espacio para un cmsghdr en el búfer.
CMSG_NXTHDR()
devuelve el siguiente cmsghdr válido después del cmsghdrpasado. Devuelve NULL cuando no queda suficiente espacio en el búfer.
Al inicializar un búfer que contendrá una serie de cmsghdr estructuras (p. ej., para ser enviadas con sendmsg(2)), ese búfer debe inicializarse primero a cero para asegurar el correcto funcionamiento de CMSG_NXTHDR().
CMSG_ALIGN(),
dada una longitud, la devuelve incluyendo la alineación requerida. Esta es una expresión constante.
CMSG_SPACE()
devuelve el número de bytes que ocupa un elemento auxiliar con una carga útil de la longitud de datos pasada. Esta es una expresión constante.
CMSG_DATA()
devuelve un puntero a la porción de datos de un cmsghdr. No se puede asumir que el puntero devuelto esté alineado adecuadamente para acceder a tipos de datos de carga útiles arbitrarios. Las aplicaciones no deben convertirlo a un tipo de puntero que coincida con la carga útil, sino que deben usar memcpy(3) para copiar datos hacia o desde un objeto declarado adecuadamente.
CMSG_LEN()
devuelve el valor a almacenar en el miembro cmsg_len de la cmsghdr estructura, teniendo en cuenta cualquier alineación necesaria. Toma la longitud de datos como argumento. Esta es una expresión constante.

Para crear datos auxiliares, primero inicialice el miembro msg_controllen del msghdr con la longitud del búfer del mensaje de control. Use CMSG_FIRSTHDR() en el msghdr para obtener el primer mensaje de control y CMSG_NXTHDR() para obtener todos los siguientes. En cada mensaje de control, inicialice cmsg_len (con CMSG_LEN()), los otros campos de encabezado cmsghdr y la porción de datos usando CMSG_DATA(). Finalmente, el campo msg_controllen del msghdr debe establecerse a la suma de CMSG_SPACE() de la longitud de todos los mensajes de control en el búfer. Para más información sobre el msghdr, véase recvmsg(2).

VERSIONES

Para la portabilidad, los datos auxiliares deben ser accedidos usando solo las macros descritas aquí.

En Linux, CMSG_LEN(), CMSG_DATA(), y CMSG_ALIGN() son expresiones constantes (asumiendo que su argumento es constante), lo que significa que estos valores pueden usarse para declarar el tamaño de variables globales. Sin embargo, esto puede no ser portable.

HISTORIA

Este modelo de datos auxiliares se conforma al borrador POSIX.1g, 4.4BSD-Lite, la API avanzada IPv6 descrita en RFC 2292 y SUSv2.

CMSG_SPACE() y CMSG_LEN() se incluirán en la próxima versión de POSIX (Edición 8).

EJEMPLOS

Este código busca la opción IP_TTL en un búfer auxiliar recibido:


struct msghdr msgh;
struct cmsghdr *cmsg;
int received_ttl;
/* Recibir datos auxiliares en msgh */
for (cmsg = CMSG_FIRSTHDR(&msgh); cmsg != NULL;
        cmsg = CMSG_NXTHDR(&msgh, cmsg)) {
    if (cmsg->cmsg_level == IPPROTO_IP
            && cmsg->cmsg_type == IP_TTL) {
        memcpy(&receive_ttl, CMSG_DATA(cmsg), sizeof(received_ttl));
        break;
    }
}
if (cmsg == NULL) {
    /* Error: IP_TTL no está habilitado, búfer pequeño o error de E/S */
}

El código siguiente pasa un array de descriptores de archivo a través de un socket de dominio UNIX usando SCM_RIGHTS:


struct msghdr msg = { 0 };
struct cmsghdr *cmsg;
int myfds[NUM_FD];  /* Contiene los descriptores de archivo a pasar */
char iobuf[1];
struct iovec io = {
    .iov_base = iobuf,
    .iov_len = sizeof(iobuf)
};
union {         /* Búfer de datos auxiliares, envuelto en una unión
                   para asegurar que esté alineado adecuadamente */
    char buf[CMSG_SPACE(sizeof(myfds))];
    struct cmsghdr align;
} u;
msg.msg_iov = &
msg.msg_iovlen = 1;
msg.msg_control = u.buf;
msg.msg_controllen = sizeof(u.buf);
cmsg = CMSG_FIRSTHDR(&msg);
cmsg->cmsg_level = SOL_SOCKET;
cmsg->cmsg_type = SCM_RIGHTS;
cmsg->cmsg_len = CMSG_LEN(sizeof(myfds));
memcpy(CMSG_DATA(cmsg), myfds, sizeof(myfds));

Para un ejemplo de código completo que muestre el paso de descriptores de archivo a través de un socket de dominio UNIX, véase seccomp_unotify(2).
