CMS_decrypt(3ssl)

Paquete: openssl

Licencias: Apache-2.0

CMS_DECRYPT(3ssl) OpenSSL CMS_DECRYPT(3ssl)

NOMBRE

CMS_decrypt, CMS_decrypt_set1_pkey_and_peer, CMS_decrypt_set1_pkey, CMS_decrypt_set1_password - descifra el contenido de una estructura CMS envelopedData

SINOPSIS

#include <openssl/cms.h>
int CMS_decrypt(CMS_ContentInfo *cms, EVP_PKEY *pkey, X509 *cert,
                BIO *dcont, BIO *out, unsigned int flags);
int CMS_decrypt_set1_pkey_and_peer(CMS_ContentInfo *cms,
                EVP_PKEY *pk, X509 *cert, X509 *peer);
int CMS_decrypt_set1_pkey(CMS_ContentInfo *cms, EVP_PKEY *pk, X509 *cert);
int CMS_decrypt_set1_password(CMS_ContentInfo *cms,
                              unsigned char *pass, ossl_ssize_t passlen);

DESCRIPCIÓN

CMS_decrypt() extrae el contenido descifrado de una estructura CMS EnvelopedData o AuthEnvelopedData. Utiliza CMS_decrypt_set1_pkey() para descifrar el contenido con la clave privada del destinatario pkey si pkey no es NULL. En este caso, se recomienda proporcionar el certificado asociado en cert - ver las NOTAS más abajo. out es un BIO en el que escribir el contenido y flags es un conjunto opcional de banderas. Si pkey es NULL, la función asume que el descifrado ya se realizó (por ejemplo, usando CMS_decrypt_set1_pkey() o CMS_decrypt_set1_password()) y solo proporciona el contenido a menos que cert, dcont, y out también sean NULL. El parámetro dcont se usa en el raro caso en que el contenido cifrado esté separado. Normalmente se establecerá en NULL.

CMS_decrypt_set1_pkey_and_peer() descifra la estructura CMS_ContentInfo cms usando la clave privada pkey, el certificado correspondiente cert, que se recomienda pero puede ser NULL, y el (opcional) certificado del originador peer. En caso de éxito, también registra en cms la clave de descifrado pkey, y luego debe ser seguido por "CMS_decrypt(cms, NULL, NULL, dcont, out, flags)". Esta llamada desasigna cualquier clave de descifrado almacenada en cms.

CMS_decrypt_set1_pkey() es lo mismo que CMS_decrypt_set1_pkey_and_peer() con peer siendo NULL.

CMS_decrypt_set1_password() descifra la estructura CMS_ContentInfo cms usando el secreto pass de longitud passlen. En caso de éxito, también registra en cms la clave de descifrado utilizada, y luego debe ser seguido por "CMS_decrypt(cms, NULL, NULL, dcont, out, flags)". Esta llamada desasigna cualquier clave de descifrado almacenada en cms.

NOTAS

Aunque el certificado del destinatario no es necesario para descifrar los datos, se necesita para localizar al destinatario apropiado (de los posibles varios) en la estructura CMS.

Si cert se establece en NULL, se prueban todos los destinatarios posibles. Este caso, sin embargo, es problemático. Para frustrar el ataque MMA (ataque de Bleichenbacher contra el relleno RSA PKCS #1 v1.5) se prueban todos los destinatarios, tengan éxito o no. Si ningún destinatario tiene éxito, se utiliza una clave simétrica aleatoria para descifrar el contenido: esto normalmente producirá basura y puede (pero no se garantiza que) devolver finalmente solo un error de relleno. Si CMS_decrypt() simplemente devolviera un error cuando todas las claves cifradas de los destinatarios fallaran al descifrar, un atacante podría usar esto en un ataque de temporización. Si se establece la bandera especial CMS_DEBUG_DECRYPT entonces el comportamiento anterior se modifica y se devuelve un error si ninguna clave cifrada de destinatario puede descifrarse sin generar una clave de cifrado de contenido aleatoria. Las aplicaciones deben usar esta bandera con extrema precaución especialmente en pasarelas automatizadas, ya que puede dejarlas abiertas al ataque.

Es posible determinar la clave correcta del destinatario por otros medios (por ejemplo, buscándolas en una base de datos) y establecerlas en la estructura CMS de antemano usando las funciones utilitarias de CMS como CMS_set1_pkey(), o usar CMS_decrypt_set1_password() si el destinatario tiene una clave simétrica. En estos casos, tanto cert como pkey deben establecerse en NULL.

Para procesar tipos KEKRecipientInfo CMS_set1_key() o CMS_RecipientInfo_set0_key() y CMS_RecipientInfo_decrypt() deben llamarse antes que CMS_decrypt() y cert y pkey establecidos en NULL.

Las siguientes banderas pueden pasarse en el parámetro flags .

Si la bandera CMS_TEXT está establecida, se eliminan las cabeceras MIME para el tipo "text/plain" del contenido. Si el contenido no es de tipo "text/plain" se devuelve un error.

VALORES DE RETORNO

CMS_decrypt(), CMS_decrypt_set1_pkey_and_peer(), CMS_decrypt_set1_pkey(), y CMS_decrypt_set1_password() devuelven 1 para éxito o 0 para fallo. El error se puede obtener de ERR_get_error(3).

ERRORES

La parte set1_ de estos nombres de función es engañosa y debería leerse mejor: with_.

La falta de procesamiento en un solo pase y la necesidad de mantener todos los datos en memoria, como se menciona en CMS_verify() también se aplica a CMS_decrypt().

VER TAMBIÉN

ERR_get_error(3), CMS_encrypt(3)

HISTORIA
