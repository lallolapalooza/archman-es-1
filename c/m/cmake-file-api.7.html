NOMBRE

cmake-file-api - API basada en archivos de CMake

INTRODUCCIÓN

CMake proporciona una API basada en archivos que los clientes pueden usar para obtener información semántica sobre los sistemas de compilación que genera CMake. Los clientes pueden usar la API escribiendo archivos de consulta en una ubicación específica de un árbol de compilación para solicitar cero o más Tipos de Objeto. Cuando CMake genera el sistema de compilación en ese árbol de compilación, leerá los archivos de consulta y escribirá archivos de respuesta para que el cliente los lea.

La API basada en archivos utiliza un <build>/.cmake/api/ directorio en la parte superior de un árbol de compilación. La API está versionada para soportar cambios en la disposición de los archivos dentro del directorio de la API. La versionación de la disposición de los archivos de la API es ortogonal a la versionación de los Tipos de Objeto utilizados en las respuestas. Esta versión de CMake soporta solo una versión de la API, API v1.

Añadido en la versión 3.27: Los proyectos también pueden enviar consultas para la ejecución actual usando el cmake_file_api() <#command:cmake_file_api> comando.

API V1

API v1 se alberga en el <build>/.cmake/api/v1/ directorio. Tiene los siguientes subdirectorios:

query/
Contiene los archivos de consulta escritos por los clientes. Estos pueden ser Archivos de Consulta Compartidos Sin Estado v1, Archivos de Consulta Sin Estado del Cliente v1, o Archivos de Consulta Con Estado del Cliente v1.
reply/
Contiene los archivos de respuesta escritos por CMake cuando se ejecuta para generar un sistema de compilación. Los clientes pueden leer los archivos de respuesta solo cuando son referenciados por un índice de respuesta:
index-*.json
Un Archivo de Índice de Respuesta v1 escrito cuando CMake genera un sistema de compilación.
error-*.json
Añadido en la versión 4.1.

Un Índice de Error de Respuesta v1 escrito cuando CMake falla al generar un sistema de compilación debido a un error.

Los clientes pueden buscar y leer un índice de respuesta en cualquier momento. Los clientes pueden opcionalmente crear el reply/ directorio en cualquier momento y monitorearlo para la aparición de un nuevo índice de respuesta. CMake es propietario de todos los archivos de respuesta. Los clientes nunca deben eliminarlos.

Añadido en la versión 3.31: Los usuarios pueden añadir archivos de consulta a api/v1/query dentro del CMAKE_CONFIG_DIR <#envvar:CMAKE_CONFIG_DIR> para crear consultas de usuario para todos los proyectos de CMake.

v1 Archivos de Consulta Compartidos Sin Estado

Los archivos de consulta compartidos sin estado permiten a los clientes compartir solicitudes de versiones principales de los Tipos de Objeto y obtener todas las versiones solicitadas reconocidas por el CMake que se ejecuta.

Los clientes pueden crear solicitudes compartidas creando archivos vacíos en el v1/query/ directorio. La forma es:

<build>/.cmake/api/v1/query/<kind>-v<major>

donde <kind> es uno de los Tipos de Objeto, -v es literal, y <major> es el número de versión principal.

Los archivos de esta forma son consultas compartidas sin estado no propiedad de ningún cliente específico. Una vez creados, no deben eliminarse sin coordinación externa del cliente o intervención humana.

v1 Archivos de Consulta Sin Estado del Cliente

Los archivos de consulta sin estado del cliente permiten a los clientes crear solicitudes propiedad de ellos para versiones principales de los Tipos de Objeto y obtener todas las versiones solicitadas reconocidas por el CMake que se ejecuta.

Los clientes pueden crear solicitudes propiedad de ellos creando archivos vacíos en subdirectorios de consulta específicos del cliente. La forma es:

<build>/.cmake/api/v1/query/client-<client>/<kind>-v<major>

donde client- es literal, <client> es una cadena que identifica de manera única al cliente, <kind> es uno de los Tipos de Objeto, -v es literal, y <major> es el número de versión principal. Cada cliente debe elegir un identificador <client> único a través de sus propios medios.

Los archivos de esta forma son consultas sin estado propiedad del cliente <client>. El cliente propietario puede eliminarlos en cualquier momento.

v1 Archivos de Consulta Con Estado del Cliente

Los archivos de consulta con estado permiten a los clientes solicitar una lista de versiones de cada uno de los Tipos de Objeto y obtener solo la versión más reciente reconocida por el CMake que se ejecuta.

Los clientes pueden crear consultas con estado propiedad de ellos creando query.json archivos en subdirectorios de consulta específicos del cliente. La forma es:

<build>/.cmake/api/v1/query/client-<client>/query.json

donde client- es literal, <client> es una cadena que identifica de manera única al cliente, y query.json es literal. Cada cliente debe elegir un identificador <client> único a través de sus propios medios.

Esto puede usarse para evitar pedirle a CMake que genere múltiples versiones de objeto innecesariamente. Archivo de índice de respuesta v1

CMake escribe un index-*.json archivo en el v1/reply/ directorio cuando genera con éxito un sistema de compilación. Los clientes deben leer primero el archivo de índice de respuesta y pueden leer otros archivos de respuesta v1 solo siguiendo referencias. La forma del nombre del archivo de índice de respuesta es:

<build>/.cmake/api/v1/reply/index-<unspecified>.json

donde index- es literal y <unspecified> es un nombre no especificado seleccionado por CMake. Siempre que se genera un nuevo archivo de índice, se le da un nuevo nombre y se elimina el anterior. Durante el breve tiempo entre estos pasos puede haber múltiples archivos de índice presentes; el que tiene el nombre más grande en orden lexicográfico es el archivo de índice actual.

      es un entero sin signo, índice basado en cero en el backtraceGraph
      member's nodes array.






Este campo se añadió en la versión 2.6 del codemodel.



  
precompileHeaders

  
Miembro opcional que está presente cuando target_precompile_headers()
      <#command:target_precompile_headers> u otras invocaciones de comando
      establecen PRECOMPILE_HEADERS <#prop_tgt:PRECOMPILE_HEADERS> en el
      objetivo. El valor es un array JSON con una entrada para cada cabecera. Cada
      entrada es un objeto JSON con los siguientes miembros:







  
header

  
Ruta completa al archivo de cabecera de precompilación.

  
backtrace

  
Miembro opcional que está presente cuando hay disponible un backtrace del lenguaje CMake hacia
      target_precompile_headers()
      <#command:target_precompile_headers> u otra invocación de comando
      que añadió esta cabecera precompilada. El valor es un entero sin
      signo, índice basado en cero en el backtraceGraph member's nodes
      array.






Este campo se añadió en la versión 2.1 del codemodel.



  
defines

  
Miembro opcional que está presente cuando hay definiciones de preprocesador.
      El valor es un array JSON con una entrada para cada definición. Cada entrada es
      un objeto JSON con los siguientes miembros:







  
define

  
Una cadena que especifica la definición del preprocesador en el formato
      <name>[=<value>], por ejemplo, DEF o DEF=1.

  
backtrace

  
Miembro opcional que está presente cuando hay disponible un backtrace del lenguaje CMake hacia
      target_compile_definitions()
      <#command:target_compile_definitions> u otra invocación de comando
      que añadió esta definición del preprocesador. El valor es un
      entero sin signo, índice basado en cero en el backtraceGraph member's
      nodes array.







  
sysroot

  
Miembro opcional que está presente cuando la CMAKE_SYSROOT_COMPILE
      <#variable:CMAKE_SYSROOT_COMPILE> o CMAKE_SYSROOT
      <#variable:CMAKE_SYSROOT> variable is defined. The value is a JSON
      object with one member:







  
path

  
Una cadena que especifica la ruta absoluta al sysroot, representada con
      barras inclinadas hacia adelante.









  
backtraceGraph

  
Un "backtrace graph" de la versión 2 del "codemodel" cuyos nodos
      son referenciados desde backtrace members elsewhere in this
      "target" object.










"codemodel" version 2 "backtrace graph"


The backtraceGraph member of a "codemodel"
    version 2 "directory" object, or "codemodel" version 2
    "target" object is a JSON object describing a graph of backtraces.
    Its nodes are referenced from backtrace members elsewhere in the
    containing object. The backtrace graph object members are:





  
nodes

  
Un array JSON que lista los nodos en el backtrace grafo. Cada entrada es un objeto JSON con los miembros:







  
file

  
Un entero sin signo, índice basado en 0 en la traza de retorno files
    array.

  
line

  
Un miembro opcional presente cuando el nodo representa una línea dentro del archivo. El valor es un número de línea entero sin signo basado en 1.

  
command

  
Un miembro opcional presente cuando el nodo representa una invocación de comando dentro del archivo. El valor es un entero sin signo, índice basado en 0 en la traza de retorno commands array.

  
parent

  
Un miembro opcional presente cuando el nodo no es la base de la pila de llamadas. El valor es un entero sin signo, índice basado en 0 de otra entrada en la traza de retorno nodes array.







  
commands

  
Un array JSON que enumera los nombres de comandos referenciados por los nodos de la traza de retorno. Cada entrada es una cadena que especifica un nombre de comando.

  
files

  
Un array JSON que enumera los archivos de lenguaje CMake referenciados por los nodos de la traza de retorno. Cada entrada es una cadena que especifica la ruta a un archivo, representada con barras diagonales hacia adelante. Si el archivo está dentro del directorio de código fuente de nivel superior, la ruta se especifica relativa a ese directorio. De lo contrario, la ruta es absoluta.

Tipo de objeto "cmakeFiles"


El tipo de objeto cmakeFiles enumera los archivos utilizados por CMake al configurar y generar el sistema de compilación. Estos incluyen los archivos
    CMakeLists.txt así como los archivos .cmake incluidos.


Solo hay una versión mayor del objeto cmakeFiles , la versión 1.


Añadido en la versión 4.1: La respuesta del tipo de objeto cmakeFiles se describe en forma legible por máquina por este esquema JSON.






"cmakeFiles" versión 1


cmakeFiles objeto versión 1 es un objeto JSON:






{
  "kind": "cmakeFiles",
  "version": { "major": 1, "minor": 1 },
  "paths": {
    "build": "/path/to/top-level-build-dir",
    "source": "/path/to/top-level-source-dir"
  },
  "inputs": [
    {
      "path": "CMakeLists.txt"
    },
    {
      "isGenerated": true,
      "path": "/path/to/top-level-build-dir/.../CMakeSystem.cmake"
    },
    {
      "isExternal": true,
      "path": "/path/to/external/third-party/module.cmake"
    },
    {
      "isCMake": true,
      "isExternal": true,
      "path": "/path/to/cmake/Modules/CMakeGenericSystem.cmake"
    }
  ],
  "globsDependent": [
    {
      "expression": "src/*.cxx",
      "recurse": true,
      "files": [
        "src/foo.cxx",
        "src/bar.cxx"
      ]
    }
  ]
}






Los miembros específicos de los objetos cmakeFiles son:





  
paths

  
Un objeto JSON que contiene los miembros:







  
source

  
Una cadena que especifica la ruta absoluta al directorio de código fuente de nivel superior, representada con barras diagonales hacia adelante.

  
build

  
Una cadena que especifica la ruta absoluta al directorio de compilación de nivel superior, representada con barras diagonales hacia adelante.







  
inputs

  
Un array JSON cuyas entradas son cada una un objeto JSON que especifica un archivo de entrada utilizado por CMake al configurar y generar el sistema de compilación. Los miembros de cada entrada son:







  
path

  
Una cadena que especifica la ruta a un archivo de entrada para CMake, representada con barras diagonales hacia adelante. Si el archivo está dentro del directorio de código fuente de nivel superior, la ruta se especifica relativa a ese directorio. De lo contrario, la ruta es absoluta.

  
isGenerated

  
Miembro opcional que está presente con el valor booleano true si la ruta especifica un archivo que está bajo el directorio de compilación de nivel superior y la compilación es fuera de origen (out-of-source). Este miembro no está disponible en compilaciones dentro de origen (in-source).

  
isExternal

  
Miembro opcional que está presente con el valor booleano true si la ruta especifica un archivo que no está bajo los directorios de código fuente o compilación de nivel superior.

  
isCMake

  
Miembro opcional que está presente con el valor booleano true si la ruta especifica un archivo en la instalación de CMake.







  
globsDependent

  
Miembro opcional que está presente cuando el proyecto llama a file(GLOB)
      <#glob> o file(GLOB_RECURSE) <#glob-recurse> con la opción
      CONFIGURE_DEPENDS . El valor es un array JSON de objetos JSON, cada uno especificando una expresión de globbing y la lista de rutas que coincidió. Si la expresión de globbing ya no coincide con la misma lista de rutas, CMake considera que el sistema de compilación está desactualizado.
    
Este campo se añadió en la versión 1.1 de cmakeFiles .

    
El Los miembros de cada entrada son:

  







  
expression

  
Una cadena que especifica la expresión de globbing.

  
recurse

  
Miembro opcional que está presente con el valor booleano true si la
      entrada corresponde a una file(GLOB_RECURSE) <#glob-recurse>
      llamada. De lo contrario, la entrada corresponde a una file(GLOB) <#glob>
      llamada.

  
listDirectories

  
Miembro opcional que está presente con el valor booleano true si
      file(GLOB) <#glob> fue llamado sin LIST_DIRECTORIES
      false o file(GLOB_RECURSE) <#glob-recurse> fue llamado
      con LIST_DIRECTORIES true.

  
followSymlinks

  
Miembro opcional que está presente con el valor booleano true si
      file(GLOB) <#glob> fue llamado con la opción FOLLOW_SYMLINKS
      .

  
relative

  
Miembro opcional que está presente si file(GLOB) <#glob> fue
      llamado con la opción RELATIVE <path> . El valor es una cadena
      que contiene la <path> dada.

  
paths

  
Un array JSON de cadenas que especifica las rutas coincidentes con la llamada a
      file(GLOB) <#glob> o file(GLOB_RECURSE)
      <#glob-recurse>.

Miembro opcional que está presente cuando la

version

  
Miembro opcional que está presente cuando la

      <#variable:CMAKE_<LANG>_COMPILER_VERSION> variable está definida

target

  
Miembro opcional que está presente cuando la
      CMAKE_<LANG>_COMPILER_TARGET
      <#variable:CMAKE_<LANG>_COMPILER_TARGET> variable está definida

      objetivo de compilación cruzada del compilador.

  
implicit

  
Un objeto JSON que contiene los miembros:

      <#variable:CMAKE_<LANG>_IMPLICIT_INCLUDE_DIRECTORIES> variable

linkDirectories

  
Miembro opcional que está presente cuando la
      CMAKE_<LANG>_IMPLICIT_LINK_DIRECTORIES
      <#variable:CMAKE_<LANG>_IMPLICIT_LINK_DIRECTORIES> variable está

linkFrameworkDirectories

linkLibraries

      <#variable:CMAKE_<LANG>_IMPLICIT_LINK_LIBRARIES> variable está

      JSON donde cada cadena contiene una ruta a una biblioteca de enlace implícita para el

sourceFileExtensions
