cmake-cxxmodules - Referencia de soporte de Módulos C++ en

CMake

Añadido en la versión 3.

28.

C++ 20 introdujo el concepto de "módulos" en el lenguaje. El diseño requiere que los sistemas de compilación ordenen las compilaciones entre sí para satisfacer las sentencias import de forma fiable. La implementación de CMake le pide al compilador que escanee los archivos fuente en busca de dependencias de módulos durante la compilaci

ón, recopila los resultados del escaneo para inferir restricciones de ordenación, y le indic
a a la herramienta de compilación cómo actualizar dinámicamente el grafo de compilación.

ESTRATEGIA DE

COMPILACIÓN

Con los módulos C++, compilar un conjunto de fuentes C++ ya no es trivialmente paralelo. Es decir, cualquier fuente dada puede requerir primero la compilación de otro archivo fuente para proporcionar un "CMI" (interfaz de módulo compilado) o "BMI" (interfaz de módulo binario) que los compiladores de C++ usan para satisfacer las sentencias import en otras fuentes. Con los encabezados, las fuentes podían compartir sus declaraciones para que cualquier consumidor pudiera compilar de forma independiente. Con los módulos, las declaraciones se generan ahora en estos archivos BMI por el compilador durante la compilación basándose en el contenido del archivo fuente y sus sentencias e

xport.

El orden necesario para la compilación requiere la resolución en tiempo de compilación del orden, porque el orden está controlado por el contenido de las fuentes. Esto significa que el orden necesita extraerse de la fuente durante la compilación para evitar regenerar el grafo de compilación a través de una fase de configuración y generación por cada cambio en la fuente para obtener una compilación

correcta.

La estrategia general es usar un "escáner" para extraer la información de dependencia de ordenación y actualizar el grafo de compilación con nuevas aristas entre aristas existentes, tomando los resultados del escaneo por fuente (representados por archivos P1689R5 https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2022/p1689r5.html ) y "recopilando" las dependencias dentro de un objetivo y con los módulos producidos por objetivos visibles para el objetivo. La tarea principal es generar archivos de "mapa de módulos" para pasar a cada regla de compilación con las rutas a los BMI necesarios para satisfacer las sentencias import. El recopilador también tiene tareas de usar la información en tiempo de compilación para completar información, incluyendo reglas de instalación para las unidades de interfaz de módulo, sus BMI, y propiedades para cualquier objetivo exportado con módulos

C++.

Nota

:
CMake se está enfocando en compilaciones correctas antes de mirar mejoras de rendimiento. Hay tácticas conocidas dentro de la estrategia elegida qu
e pueden ofrecer mejoras en el rendimiento de la compilación. Sin embargo, se están posponiendo hasta que tengamos un modelo funcional contra el cual
compararlas. También es importante notar que una táctica útil en una situación (p. ej., compilaciones limpias) puede no ser eficiente en una situ
ación diferente (p. ej., compilaciones incrementales). Encontrar un equilibrio y ofrecer controles para seleccionar las tácticas es trabajo futuro.

ESCANEO

Si las fuentes se escanean o no para el uso de módulos C++ depende de las siguientes consultas. Se usa la primera consulta que proporcione una respuesta de

sí/no.
  • Si el archivo fuente pertenece a un conjunto de archivos de tipo CXX_MODULES, se
    • escaneará.
  • Si el objetivo no usa al menos C++ 20, no se
    • escaneará.
  • Si el archivo fuente no es del lenguaje CXX, no se
    • escaneará.
  • Si la propiedad de archivo fuente CXX_SCAN_FOR_MODULES <#prop_sf:CXX_SCAN_FOR_MODULES> está establecida, se usará su
    • valor.
  • Si la propiedad de objetivo CXX_SCAN_FOR_MODULES <#prop_tgt:CXX_SCAN_FOR_MODULES> está establecida, se usará su valor. Establezca la variable CMAKE_CXX_SCAN_FOR_MODULES <#variable:CMAKE_CXX_SCAN_FOR_MODULES> para inicializar esta propiedad en todos los objetivos a medida que se
    • crean.
  • De lo contrario, el archivo fuente se escaneará si el compilador y el generador soportan el escaneo. Vea la política CMP0155 <#
