dat
version
Versión de los datos del archivo de fragmento a generar, un entero. Actualmente la única versión admitida es 1.
callbacks
Una lista de cadenas de comandos para que los Callbacks manejen los datos de instrumentación recopilados. Cada vez que se ejecuten estos callbacks, se añadirá la ruta completa a un archivo de índice v1 a los argumentos incluidos en la cadena.
hooks
Una lista de cadenas que especifican cuándo debe ocurrir la indexación automáticamente. Estos son los intervalos en los que se deben recopilar los datos de instrumentación e invocar a los Callbacks del usuario para manejar los datos. Los elementos de esta lista deben ser uno de los siguientes:
  • postGenerate
  • preBuild (llamado cuando se invoca ninja o make)
  • postBuild (llamado cuando ninja o make se completa)
  • preCMakeBuild (llamado cuando se invoca cmake --build)
  • postCMakeBuild (llamado cuando cmake --build se completa)
  • postCMakeInstall
  • postCTest

preBuild y postBuild no son compatibles cuando se utilizan los generadores MSYS Makefiles <#generator:MSYS Makefiles> o FASTBuild <#generator:FASTBuild>. Además, no se activarán cuando la herramienta de compilación sea invocada por cmake --build.

options
Una lista de cadenas utilizada para habilitar ciertos comportamientos opcionales, incluida la recopilación de datos adicionales específicos. Los elementos de esta lista deben ser uno de los siguientes:
staticSystemInformation
Habilita la recopilación de información estática sobre la máquina host desde la que se está ejecutando CMake. Estos datos se recopilan durante la indexación y se incluyen en el archivo de índice v1 generado.
dynamicSystemInformation
Habilita la recopilación de información dinámica sobre la máquina host desde la que se está ejecutando CMake. Los datos se recopilan para cada archivo de fragmento v1 generado por CMake, e incluyen información de antes y después de la ejecución del comando.
cdashSubmit
Habilita la inclusión de datos de instrumentación en CDash. Esto no habilita automáticamente dynamicSystemInformation, pero es, por lo demás, equivalente a tener habilitada la variable de entorno CTEST_USE_INSTRUMENTATION <#envvar:CTEST_USE_INSTRUMENTATION>.
cdashVerbose
Habilita la inclusión de los comandos completos sin truncar en los datos enviados a CDash. Equivalente a tener habilitada la variable de entorno CTEST_USE_VERBOSE_INSTRUMENTATION <#envvar:CTEST_USE_VERBOSE_INSTRUMENTATION>.
trace
Habilita la generación de un Archivo de Rastreo de Google durante la Indexación para visualizar datos de los Archivos de Fragmento v1 recopilados.

Los callbacks listados se invocarán durante los hooks especificados como mínimo. Cuando hay varios archivos de consulta, los callbacks, hooks y options entre ellos se fusionarán. Por lo tanto, si algún archivo de consulta incluye algún hook, cada callback de todos los archivos de consulta se ejecutará en cada hook de todos los archivos de consulta. Además, si algún archivo de consulta solicita datos opcionales utilizando el campo options, los datos relacionados estarán presentes en todos los archivos de fragmento. Los callbacks escritos por el usuario deben poder manejar la presencia de estos datos opcionales, ya que pueden ser solicitados por una consulta no relacionada.

Ejemplo:

{
  "version": 1,
  "callbacks": [
    "/usr/bin/python callback.py",
    "/usr/bin/cmake -P callback.cmake arg",
  ],
  "hooks": [
    "postCMakeBuild",
    "postCMakeInstall"
  ],
  "options": [
    "staticSystemInformation",
    "dynamicSystemInformation",
    "cdashSubmit",
    "trace"
  ]
}

En este ejemplo, después de cada invocación de cmake --build o cmake --install, se generará un archivo de índice index-<timestamp>.json en <build>/.cmake/instrumentation/v1/data/index que contendrá una lista de archivos de fragmentos de datos creados desde la indexación anterior. Los comandos /usr/bin/python callback.py index-<timestamp>.json y /usr/bin/cmake -P callback.cmake arg index-<timestamp>.json se ejecutarán en ese orden. El archivo de índice contendrá los datos de staticSystemInformation y cada archivo de fragmento listado en el índice contendrá los datos de dynamicSystemInformation. Además, el archivo de índice contendrá la ruta al Archivo de Rastreo de Google generado. Una vez que ambos callbacks hayan completado, el archivo de índice y los archivos de datos listados por él (incluidos los archivos de fragmento, pero no el archivo de rastreo) se eliminarán del árbol de compilación del proyecto. Los datos de instrumentación estarán presentes en los archivos XML enviados a CDash, pero con cadenas de comandos truncadas porque cdashVerbose no estaba habilitado.

DATOS V1

La versión de los datos especifica el contenido de los archivos de salida generados por la API de instrumentación de CMake como parte de la Recopilación de Datos y la Indexación. Se creará un nuevo número de versión cada vez que se elimine o reformatee un dato incluido previamente de tal manera que los scripts escritos para analizar estos datos puedan volverse incompatibles con el nuevo formato. Hay cuatro tipos de archivos de datos generados: el Archivo de Fragmento v1, el Archivo de Índice v1, el Archivo de Contenido de CMake v1 y el Archivo de Rastreo de Google. Al usar la API v1, estos archivos residen en <build>/.cmake/instrumentation/v1/data/ dentro del árbol de compilación del proyecto.

Archivo de Fragmento v1

Los archivos de fragmento se generan para cada comando de compilación, enlace y personalizado invocado como parte del paso de compilación o instalación de CMake y contienen datos de instrumentación sobre el comando ejecutado. Además, se crean archivos de fragmento para lo siguiente:

  • El paso de configuración de CMake
  • El paso de generación de CMake
  • El paso de compilación completo (ejecutado con cmake --build)
  • El paso de instalación completo (ejecutado con cmake --install)
  • Cada invocación de ctest
  • Cada prueba individual ejecutada por ctest.

Estos archivos permanecen en el árbol de compilación hasta después de que ocurra la Indexación y se ejecuten los Callbacks especificados por el usuario.
