Paquetes de archivo de

configuración

Un paquete de archivo de configuración es un conjunto de archivos proporcionados por los proyectos originales (upstreams) para que los proyectos dependientes (downstreams) los usen. CMake busca en varias ubicaciones archivos de configuración de paquetes, como se describe en la documentación de find_package() <#command:find_package>. La forma más sencilla para que un usuario de CMake le diga a cmake(1) <#manual:cmake(1)> que busque en un prefijo no estándar para un paquete es establecer la variable de caché CMAKE_PREFIX_PATH

.

Los paquetes de archivo de configuración son proporcionados por los proveedores originales como parte de los paquetes de desarrollo, es decir, pertenecen junto con los archivos de cabecera y cualquier otro archivo proporcionado para ayudar a los proyectos dependientes a usar el

paquete.

Un conjunto de variables que proporcionan información sobre el estado del paquete también se establecen automáticamente al usar un paquete de archivo de configuración. La variable <PackageName>_FOUND se establece en verdadero o falso, dependiendo de si el paquete fue encontrado. La variable de caché <PackageName>_DIR se establece en l

a ubicación del archivo de
configuración del paquete.

Paquetes de módulo de

búsqueda

Un módulo de búsqueda es un archivo con un conjunto de reglas para encontrar las piezas requeridas de una dependencia, principalmente archivos de cabecera y bibliotecas. Normalmente, un módulo de búsqueda es necesario cuando el proyecto original no está construido con CMake, o no es lo suficientemente consciente de CMake como para proporcionar de otro modo un archivo de configuración de paquete. A diferencia de un archivo de configuración de paquete, no se distribuye con el proyecto original, sino que es usado por el proyecto dependiente para encontrar los archivos adivinando sus ubicaciones con pistas específicas de la

plataforma.

A diferencia del caso de un archivo de configuración de paquete proporcionado por el proyecto original, no hay un único punto de referencia que identifique que el paquete ha sido encontrado, por lo que la variable <PackageName>_FOUND no es establecida automáticamente por el comando find_package() <#command:find_package>. Sin embargo, se puede esperar que se establezca por convención y debería ser establecida por el autor del módulo de búsqueda. De manera similar, no existe una variable <PackageName>_DIR, pero cada uno de los artefactos, como las ubicaciones de las bibliotecas y las ubicaciones de los archivos de cabecera, proporciona una variable de caché

separada.

reubicables

Un paquete reubicable no debe referenciar rutas absolutas de archivos en la máquina donde se compila el paquete que no existirán en las máquinas donde el paquete pueda

instalarse.

Los paquetes creados por install(EXPORT) <#export> están diseñados para ser reubicables, usando rutas relativas a la ubicación del propio paquete. Al definir la interfaz de un objetivo para EXPORT, tenga en cuenta que los directorios de inclusión deben especificarse como rutas relativas que sean relativas al CMAKE_INSTALL_PREFIX <#variable:CMAKE_INSTALL_PREFIX>

  # Wrong, not rel

# Ok, relocatable: $<INSTALL_INTERFACE:include/TgtName> )

La $<INSTALL_PREFIX> expresión generadora <#manual:cmake-generator-expressions(7)> puede usarse como un marcador de posición para el prefijo de instalación sin que resulte en un paquete no reubicable. Esto es necesario si se usan expresiones generadoras

complejas:

  # Ok, relocatable:
  $<INSTALL_INTERFACE:$<$<CONFIG:Debug>:$<INSTALL_PREFIX>/include/TgtName>
>
)

Esto también se aplica a rutas que referencian dependencias externas. No es aconsejable poblar propiedades que puedan contener rutas, como INTERFACE_INCLUDE_DIRECTORIES <#prop_tgt:INTERFACE_INCLUDE_DIRECTORIES> y INTERFACE_LINK_LIBRARIES <#prop_tgt:INTERFACE_LINK_LIBRARIES>, con rutas relevantes para las dependencias. Por ejemplo, este código puede no funcionar bien para un paquete

reubicable:

  ${Foo_LIBRARIES} ${Bar_LIBRARIES}
  )

  "$<INSTALL_INTERFACE:${Foo_INCLUDE_DIRS};${Bar_INCLUDE_DIRS}>"
)

reubicación.

Idealmente, tales dependencias deberían usarse a través de sus propios objetivos IMPORTED <#imported-targets> que tengan su propia IMPORTED_LOCATION <#prop_tgt:IMPORTED_LOCATION> y propiedades de requisitos de uso como INTERFACE_INCLUDE_DIRECTORIES <#prop_tgt:INTERFACE_INCLUDE_DIRECTORIES> pobladas adecuadamente. Esos objetivos importados pueden luego usarse con el comando target_link_libraries() <#command:target_link_libraries> para ClimbingStats

ion.cmake).

El comando find_package() <#command:find_package> busca los dos registros de paquetes como dos de los pasos de búsqueda especificados en su documentación. Si tiene los permisos suficientes, también elimina entradas obsoletas del registro de paquetes que referencian directorios que no existen o que no contienen un archivo de configuración de paquete

coincidente.

Registro de paquetes de

usuario

El Registro de paquetes de usuario se almacena en una ubicación por usuario. El comando export(PACKAGE) <#package> puede usarse para registrar un árbol de compilación de proyecto en el registro de paquetes de usuario. Propiedad del Registro de

Paquetes

Las entradas del registro de paquetes son individualmente propiedad de las instalaciones del proyecto al que hacen referencia. Un instalador de paquetes es responsable de añadir su propia entrada y el desinstalador correspondiente es responsable de

eliminarla.

El export(PACKAGE) <#package> comando puebla el registro de paquetes de usuario con la ubicación de un árbol de compilación de proyecto. Los árboles de compilación tienden a ser eliminados por los desarrolladores y no tienen un evento de "desinstalación" que pueda desencadenar la eliminación de sus entradas. Para mantener los registros limpios, el find_package() <#command:find_package> comando elimina automáticamente las entradas obsoletas que encuentra si tiene suficientes permisos. CMake no proporciona ninguna interfaz para eliminar una entrada que referencia un árbol de compilación existente una vez que export(PACKAGE) <#package> ha sido invocado. Sin embargo, si el proyecto elimina su a

a la ubicación será considerada obsoleta.
