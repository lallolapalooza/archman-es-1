DESCRIPCIÓ

N

La función CMS_get0_RecipientInfos() devuelve todas las estructuras CMS_RecipientInfo asociadas con una estructura CMS

EnvelopedData.

CMS_RecipientInfo_type() devuelve el tipo de la estructura CMS_RecipientInfo ri. Actualmente devolverá CMS_RECIPINFO_TRANS, CMS_RECIPINFO_AGREE, CMS_RECIPINFO_KEK, CMS_RECIPINFO_PASS, CMS_RECIPINFO_KEM, o CMS_RECIPINFO_OTHER

.

CMS_RecipientInfo_ktri_get0_signer_id() recupera el identificador de certificado del destinatario asociado con una estructura CMS_RecipientInfo específica ri, que debe ser de tipo CMS_RECIPINFO_TRANS. Se establecerá el identificador de clave en keyid o tanto el nombre del emisor como el número de serie en issuer y sno

.

CMS_RecipientInfo_ktri_cert_cmp() compara el certificado cert contra la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_TRANS. Devuelve cero si la comparación es exitosa y distinto de cero si no lo

es.

CMS_RecipientInfo_set0_pkey() asocia la clave privada pkey con la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_TRANS

.

CMS_RecipientInfo_kari_set0_pkey_and_peer() asocia la clave privada pkey y el certificado del par peer con la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_AGREE

.

CMS_RecipientInfo_kari_set0_pkey() asocia la clave privada pkey con la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_AGREE

.

CMS_RecipientInfo_kari_get0_ctx() devuelve el EVP_CIPHER_CTX para la clave de cifrado de claves, permitiendo al llamador especificar el cifrado de envoltura de claves. La estructura CMS_RecipientInfo ri debe ser de tipo CMS_RECIPINFO_AGREE

.

CMS_RecipientInfo_kekri_get0_id() recupera la información de la clave desde la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_KEK. Cualquiera de los parámetros restantes puede ser NULL si la aplicación no está interesada en el valor de un campo. Donde un campo es opcional y ausente, se escribirá NULL en el parámetro correspondiente. El campo keyEncryptionAlgorithm se escribe en palg, el campo keyIdentifier se escribe en pid, el campo date si está presente se escribe en pdate, si el campo other está presente los componentes keyAttrId y keyAttr se escriben en los parámetros potherid y pothertype

.

CMS_RecipientInfo_kekri_id_cmp() compara el ID en los parámetros id y idlen contra el keyIdentifier de la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_KEK. Devuelve cero si la comparación es exitosa y distinto de cero si no lo

es.

CMS_RecipientInfo_set0_key() asocia la clave simétrica key de longitud keylen con la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_KEK

.

CMS_RecipientInfo_kemri_cert_cmp() compara el certificado cert contra la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_KEM. Devuelve cero si la comparación es exitosa y distinto de cero si no lo

es.

CMS_RecipientInfo_kemri_set0_pkey() asocia la clave privada pkey con la estructura CMS_RecipientInfo ri, que debe ser de tipo CMS_RECIPINFO_KEM

.

CMS_RecipientInfo_kemri_get0_ctx() devuelve el EVP_CIPHER_CTX para la clave de cifrado de claves, permitiendo al llamador especificar el cifrado de envoltura de claves. La estructura CMS_RecipientInfo ri debe ser de tipo CMS_RECIPINFO_KEM

.

CMS_RecipientInfo_kemri_get0_kdf_alg() devuelve el X509_ALGOR para el KDF del RecipientInfo, permitiendo al llamador especificar el algoritmo KDF. La estructura CMS_RecipientInfo ri debe ser de tipo CMS_RECIPINFO_KEM. Si el llamador no especifica un algoritmo KDF, se usará HKDF-

SHA256.

CMS_RecipientInfo_kemri_set_ukm() establece el material de claveo de usuario (UKM) opcional del RecipientInfo. El UKM se codifica, junto con otra información, en el parámetro OSSL_KDF_PARAM_INFO del KDF del RecipientInfo. La estructura CMS_RecipientInfo ri debe ser de tipo CMS_RECIPINFO_KEM

.

CMS_RecipientInfo_decrypt() intenta descifrar la estructura CMS_RecipientInfo ri en la estructura cms. Debe haberse asociado primero una clave con la

estructura.

CMS_RecipientInfo_encrypt() intenta cifrar la estructura CMS_RecipientInfo ri en la estructura cms. Debe haberse asociado primero una clave con la estructura y la clave de cifrado de contenido debe estar disponible: por ejemplo, mediante una llamada previa a CMS_RecipientI

nfo_dec
rypt().

NOTA

S

El propósito principal de estas funciones es permitir que una aplicación busque claves de destinatario usando cualquier técnica apropiada cuando el método más simple de CMS_decrypt() no es

apropiado.

En el uso típico, una aplicación recuperará todas las estructuras CMS_RecipientInfo usando CMS_get0_RecipientInfos() y comprobará el tipo de cada una usando CMS_RecipientInfo_type(). Dependiendo del tipo, la estructura CMS_RecipientInfo puede ignorarse o recuperarse su información de identificador de clave usando una función apropiada. Luego, si la clave secreta o privada correspondiente puede obtenerse por cualquier medio apropiado, puede asociarse con la estructura y llamarse a CMS_RecipientInfo_decrypt(). Si tiene éxito, puede llamarse a CMS_decrypt() con una clave NULL para descifrar el contenido

enveloped.

La función CMS_RecipientInfo_encrypt() puede usarse para añadir un nuevo destinatario a una estructura de datos enveloped existente. Típicamente una aplicación primero descifrará una estructura CMS_RecipientInfo apropiada para hacer disponible la clave de cifrado de contenido, luego añadirá un nuevo destinatario usando una función como CMS_add1_recipient_cert() y finalmente cifrará la clave de cifrado de contenido usando CMS_RecipientI

nfo_enc
rypt().

RETORNO

CMS_get0_RecipientInfos() devuelves todas las estructuras CMS_RecipientInfo, o NULL si ocurre un

error.

CMS_RecipientInfo_ktri_get0_signer_id(), CMS_RecipientInfo_set0_pkey(), CMS_RecipientInfo_kekri_get0_id(), CMS_RecipientInfo_set0_key(), CMS_RecipientInfo_kemri_set0_pkey(), CMS_RecipientInfo_kemri_set_ukm(), CMS_RecipientInfo_decrypt() y CMS_RecipientInfo_encrypt() devuelven 1 en caso de éxito o 0 si ocurre un

error.

CMS_RecipientInfo_ktri_cert_cmp(), CMS_RecipientInfo_kemri_cert_cmp() y CMS_RecipientInfo_kekri_cmp() devuelven 0 para una comparación exitosa y distinto de cero en caso

contrario.

CMS_RecipientInfo_kemri_get0_ctx() y CMS_RecipientInfo_kari_get0_ctx devuelven el EVP_CIPHER_CTX de RecipientInfo o NULL si ocurrió un

error.

CMS_RecipientInfo_kemri_get0_kdf_alg() devuelve el X509_ALGOR del KDF de RecipientInfo o NULL si ocurrió un

error.

Cualquier error se puede obtener desde ERR_get_

error
(3).
