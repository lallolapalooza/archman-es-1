DESCRIPCIÓ

N

CMS_sign_ex() crea y devuelve una estructura CMS SignedData. signcert es el certificado con el que firmar, pkey es la clave privada correspondiente. certs es un conjunto opcional adicional de certificados para incluir en la estructura CMS (por ejemplo, cualquier CA intermedia en la cadena). El contexto de la biblioteca libctx y la consulta de propiedad propq se utilizan al recuperar algoritmos de los proveedores. Cualquiera o todos de estos parámetros pueden ser NULL, véase NOTAS más

abajo.

Los datos a firmar se leen desde el BIO data

.

flags es un conjunto opcional de

indicadores.

CMS_sign() es similar a CMS_sign_ex() pero utiliza valores predeterminados de NULL para el contexto de la biblioteca libctx y la consulta de propiedad pro

p
q.

NOTA

S

Cualquiera de los siguientes indicadores (combinados con OR) puede pasarse en el parámetro flags

.

Muchos clientes S/MIME esperan que el contenido firmado incluya encabezados MIME válidos. Si el indicador CMS_TEXT está establecido, se anteponen a los datos encabezados MIME para el tipo text/plain

.

Si CMS_NOCERTS está establecido, el certificado del firmante no se incluirá en la estructura CMS_ContentInfo; sin embargo, el certificado del firmante debe proporcionarse aún en el parámetro signcert. Esto puede reducir el tamaño de la firma si el certificado del firmante puede obtenerse por otros medios: por ejemplo, un mensaje firmado

previamente.

Los datos que se firman se incluyen en la estructura CMS_ContentInfo, a menos que CMS_DETACHED esté establecido, en cuyo caso se omiten. Esto se utiliza para firmas CMS_ContentInfo desprendidas, que se usan, por ejemplo, en mensajes firmados en texto plano

S/MIME.

Normalmente, el contenido proporcionado se traduce al formato canónico MIME (según lo requieren las especificaciones S/MIME). Si CMS_BINARY está establecido, no se produce ninguna traducción. Esta opción debe utilizarse si los datos proporcionados están en formato binario; de lo contrario, la traducción los

corromperá.

La estructura SignedData incluye varios signedAttributes CMS, incluyendo la hora de firma, el tipo de contenido CMS y la lista de cifradores admitidos en un atributo SMIMECapabilities. Si CMS_NOATTR está establecido, no se utilizarán signedAttributes en absoluto. Si CMS_NOSMIMECAP está establecido, se omitirán las SMIMECapabilities. Si CMS_NO_SIGNING_TIME está establecido, se omitirá la hora de

firma.

Si está presente, el atributo SMIMECapabilities indica soporte para los siguientes algoritmos en orden de preferencia: AES de 256 bits, Gost R3411-94, Gost 28147-89, AES de 192 bits, AES de 128 bits, triple DES, RC2 de 128 bits, RC2 de 64 bits, DES y RC2 de 40 bits. Si alguno de estos algoritmos no está disponible, no se incluirá: por ejemplo, los algoritmos GOST no se incluirán si el MOTOR GOST no está

cargado.

OpenSSL identificará por defecto los certificados de firma mediante el nombre del emisor y el número de serie. Si CMS_USE_KEYID está establecido, utilizará el valor del identificador de clave del sujeto. Se produce un error si el certificado de firma no tiene la extensión de identificador de clave del

sujeto.

Si los indicadores CMS_STREAM está establecido, la estructura CMS_ContentInfo devuelta solo se inicializa para estar lista para realizar la operación de firma. Sin embargo, la firma no se realiza y los datos a firmar no se leen del parámetro data. La firma se difiere hasta después de que se hayan escrito los datos. De esta manera, los datos pueden firmarse en una sola

pasada.

Si el indicador CMS_PARTIAL está establecido, se emite una estructura CMS_ContentInfo parcial a la que se pueden añadir firmantes y capacidades adicionales antes de la

finalización.

Si el indicador CMS_STREAM está establecido, la estructura CMS_ContentInfo devuelta no está completa y emitir su contenido mediante una función que no finalice correctamente la estructura CMS_ContentInfo producirá resultados

impredecibles.

Varias funciones, incluyendo SMIME_write_CMS(), i2d_CMS_bio_stream(), PEM_write_bio_CMS_stream(), finalizan la estructura. Alternativamente, la finalización puede realizarse obteniendo el ASN1 de streaming BIO directamente mediante BIO_new_C

MS().

Si se especifica un firmante, utilizará el resumen predeterminado para el algoritmo de firma. Este es SHA256 tanto para claves RSA como

DSA.

Si signcert y pkey son NULL, se emite una estructura CMS solo de

certificados.

La función CMS_sign() es una función básica de firma CMS cuya salida será adecuada para muchos propósitos. Para un control más fino del formato de salida, los parámetros certs, signcert y pkey pueden ser todos NULL y el indicador CMS_PARTIAL establecido. Luego, uno o más firmantes pueden añadirse mediante la función CMS_add1_signer(), pueden usarse resúmenes no predeterminados y añadirse atributos personalizados. CMS_final() debe entonces llamarse para finaliza

r la estructura si el strea
ming no está habilitado.

HISTORIA

L

El indicador CMS_STREAM solo está soportado para datos desprendidos en OpenSSL 0.9.8; está soportado para datos incrustados en OpenSSL 1.0.0 y versiones

posteriores.

El método CMS_sign_ex() se añadió en OpenSSL 3.

0.

Desde OpenSSL 3.2, CMS_sign_ex() y CMS_sign() ignoran cualquier certificado duplicado en su argumento certs y ya no

lanzan un er
ror por ellos.
