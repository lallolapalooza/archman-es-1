CMS_encrypt(3ssl)

Paquete: openssl

Licencias: Apache-2.0

CMS_ENCRYPT(3ssl) OpenSSL CMS_ENCRYPT(3ssl)

NOMBRE

CMS_encrypt_ex, CMS_encrypt - crear una estructura envelopedData de CMS

SINOPSIS

#include <openssl/cms.h>
CMS_ContentInfo *CMS_encrypt_ex(STACK_OF(X509) *certs, BIO *in,
                                const EVP_CIPHER *cipher, unsigned int flags,
                                OSSL_LIB_CTX *libctx, const char *propq);
CMS_ContentInfo *CMS_encrypt(STACK_OF(X509) *certs, BIO *in,
                             const EVP_CIPHER *cipher, unsigned int flags);

DESCRIPCIÓN

CMS_encrypt_ex() crea y devuelve una estructura CMS EnvelopedData o AuthEnvelopedData. certs es una lista de certificados de destinatario. in es el contenido a cifrar. cipher es el cifrado simétrico a utilizar. flags es un conjunto opcional de indicadores. El contexto de biblioteca libctx y la consulta de propiedades propq se utilizan internamente al recuperar algoritmos de los proveedores.

Esta función solo admite certificados que lleven claves RSA, Diffie-Hellman o EC.

EVP_des_ede3_cbc() (triple DES) es el algoritmo preferido para el uso de S/MIME porque la mayoría de los clientes lo admitirán.

El algoritmo pasado en el parámetro cipher debe admitir la codificación ASN1 de sus parámetros. Si el modo del cifrado es GCM, se utiliza una estructura AuthEnvelopedData que contiene el MAC. De lo contrario, se utiliza una estructura EnvelopedData. Actualmente, las variantes AES con modo GCM son los únicos algoritmos AEAD admitidos.

Muchos navegadores implementan una opción de "firmar y cifrar" que es simplemente un envelopedData S/MIME que contiene un mensaje firmado S/MIME. Esto se puede producir fácilmente almacenando el mensaje firmado S/MIME en un BIO de memoria y pasándolo a CMS_encrypt().

Los siguientes indicadores se pueden pasar en el parámetro flags.

Si se establece el indicador CMS_TEXT, se anteponen encabezados MIME de tipo text/plain a los datos.

Normalmente, el contenido suministrado se traduce al formato canónico MIME (según lo exigen las especificaciones S/MIME) si se establece CMS_BINARY, no se realiza ninguna traducción. Esta opción debe usarse si los datos suministrados están en formato binario, de lo contrario, la traducción los corromperá. Si se establece CMS_BINARY, se ignora CMS_TEXT.

OpenSSL, por defecto, identificará los certificados de destinatario utilizando el nombre del emisor y el número de serie. Si se establece CMS_USE_KEYID, utilizará el valor del identificador de clave del sujeto en su lugar. Se produce un error si todos los certificados de destinatario no tienen una extensión de identificador de clave del sujeto.

Si se establece el indicador CMS_STREAM, se devuelve una estructura CMS_ContentInfo parcial adecuada para E/S en streaming: no se leen datos del BIO in.

Si se establece el indicador CMS_PARTIAL, se devuelve una estructura CMS_ContentInfo parcial a la que se pueden agregar destinatarios y atributos adicionales antes de la finalización.

Los datos que se cifran se incluyen en la estructura CMS_ContentInfo, a menos que se establezca CMS_DETACHED, en cuyo caso se omiten. Esto rara vez se usa en la práctica y no es compatible con SMIME_write_CMS().

Si se establece el indicador CMS_STREAM, la estructura CMS_ContentInfo devuelta no está completa y la salida de su contenido a través de una función que no finaliza correctamente la estructura CMS_ContentInfo dará resultados impredecibles.

Varias funciones, incluidas SMIME_write_CMS(), i2d_CMS_bio_stream(), PEM_write_bio_CMS_stream(), finalizan la estructura. Alternativamente, la finalización se puede realizar obteniendo directamente el BIO ASN1 de streaming usando BIO_new_CMS().

Los destinatarios especificados en certs utilizan una estructura CMS KeyTransRecipientInfo. KEKRecipientInfo también es compatible utilizando el indicador CMS_PARTIAL y CMS_add0_recipient_key(). KEMRecipientInfo también es compatible utilizando el indicador CMS_PARTIAL y CMS_add1_recipient().

El parámetro certs puede ser NULL si se establece CMS_PARTIAL y los destinatarios se agregan más tarde usando CMS_add1_recipient() o CMS_add1_recipient_cert() con CMS_add0_recipient_key().

CMS_encrypt() es similar a CMS_encrypt_ex() pero utiliza valores predeterminados de NULL para el contexto de biblioteca libctx y la consulta de propiedades propq.

VALORES DEVUELTOS

CMS_encrypt_ex() y CMS_encrypt() devuelven una estructura CMS_ContentInfo o NULL si ocurrió un error. El error se puede obtener de ERR_get_error(3).

VER TAMBIÉN

ERR_get_error(3), CMS_decrypt(3)

HISTORIAL

La función CMS_encrypt_ex() se agregó en OpenSSL 3.0.

El indicador CMS_STREAM se admitió por primera vez en OpenSSL 1.0.0.
