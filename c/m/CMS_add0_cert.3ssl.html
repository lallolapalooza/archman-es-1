CMS_add0_cert(3ssl)

Paquete: openssl

Licencias: Apache-2.0

CMS_ADD0_CERT(3ssl) OpenSSL CMS_ADD0_CERT(3ssl)

NOMBRE

CMS_add0_cert, CMS_add1_cert, CMS_get1_certs, CMS_add0_crl, CMS_add1_crl, CMS_get1_crls - Funciones de utilidad para certificados y CRLs de CMS

SINOPSIS

#include <openssl/cms.h>
int CMS_add0_cert(CMS_ContentInfo *cms, X509 *cert);
int CMS_add1_cert(CMS_ContentInfo *cms, X509 *cert);
STACK_OF(X509) *CMS_get1_certs(CMS_ContentInfo *cms);
int CMS_add0_crl(CMS_ContentInfo *cms, X509_CRL *crl);
int CMS_add1_crl(CMS_ContentInfo *cms, X509_CRL *crl);
STACK_OF(X509_CRL) *CMS_get1_crls(CMS_ContentInfo *cms);

DESCRIPCIÓN

CMS_add0_cert() y CMS_add1_cert() añaden el certificado cert a cms a menos que ya esté presente. Esto es utilizado por CMS_sign_ex(3) y CMS_sign(3) y puede ser utilizado antes de llamar a CMS_verify(3) para ayudar a la construcción de la cadena en la validación del certificado. Como el 0 implica, CMS_add0_cert() añade cert internamente a cms y en caso de éxito no debe ser liberado por el llamador. En contraste, el llamador de CMS_add1_cert() debe liberar cert. cms debe ser de tipo datos firmados o datos envueltos (autenticados). Para datos firmados, un certificado de este tipo puede ser utilizado al firmar o verificar para rellenar el certificado del firmante o para proporcionar un certificado CA adicional que pueda ser necesario para la construcción de la cadena en la validación del certificado.

CMS_get1_certs() devuelve todos los certificados en cms.

CMS_add0_crl() y CMS_add1_crl() añaden la CRL crl a cms. cms debe ser de tipo datos firmados o datos envueltos (autenticados). Para datos firmados, una CRL de este tipo puede ser utilizada en la validación del certificado con CMS_verify(3). Puede ser proporcionada tanto para su inclusión al firmar un mensaje CMS como al verificar un mensaje CMS firmado.

CMS_get1_crls() devuelve todas las CRLs en cms.

NOTAS

La estructura CMS_ContentInfo cms debe ser de tipo datos firmados o datos envueltos o datos envueltos autenticados o se devolverá un error.

Para datos firmados, los certificados y CRLs se añaden a los campos certificates y crls de la estructura SignedData. Para datos envueltos se añaden a OriginatorInfo.

VALORES DE RETORNO

CMS_add0_cert(), CMS_add1_cert() y CMS_add0_crl() y CMS_add1_crl() devuelven 1 para éxito y 0 para fallo.

CMS_get1_certs() y CMS_get1_crls() devuelven la STACK de certificados o CRLs o NULL si no hay ninguno o ocurre un error. Además de falta de memoria, el único error que ocurrirá en la práctica es si el tipo de cms es inválido.

VER TAMBIÉN

ERR_get_error(3), CMS_sign(3), CMS_sign_ex(3), CMS_verify(3), CMS_encrypt(3)

HISTORIAL

CMS_add0_cert() y CMS_add1_cert() han sido cambiadas en OpenSSL 3.2 para no lanzar un error si un certificado a añadir ya está presente.
