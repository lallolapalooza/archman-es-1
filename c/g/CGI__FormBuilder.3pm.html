Campos

campo.
Inteligencia

escribir.

Integrada
Validación completa con expresiones regulares para campos, incluso incluyendo la generación de código
JavaScript.
Soporte de
Plantillas
Soporte conectable para motores de plantillas externos, como "HTML::Template", "Text::Template", "Template Toolkit", y "CGI::Fast

REFERENCIA

S

Esto realmente no debería estar aquí, pero desafortunadamente mucha gente se confunde con las referencias en Perl. No te confundas, no son tan complicadas. Cuando tomas una referencia, básicamente estás convirtiendo algo en un valor escalar. Más o menos. Tienes que hacer esto si quieres pasar arrays intactos a funciones en Perl

5.

Una referencia se toma precediendo a la variable con una barra invertida (\). En nuestros ejemplos anteriores, viste algo similar a

esto: 
my @fields = ('name', 'email');   # same as = qw(name email)
my $form = CGI::FormBuilder->new(fields => \@fields)
;

Aquí, "\@fields" es una referencia. Específicamente, es una referencia de array, o "arrayref" para

abreviar.

De manera similar, podemos hacer lo mismo con

hashes: 
my %validate = (
    name  => 'NAME';
    email => 'EMAIL',
);
my $form = CGI::FormBuilder->new( ... validate => \%validate)
;

Aquí, "\%validate" es una referencia de hash, o

"hashref".

Básicamente, si no entiendes las referencias y tienes dificultades para comprenderlas, puedes intentar esta regla simple: Cada vez que pases un array o un hash a una función, debes precederlo con una barra invertida. Normalmente eso es cierto para los módulos de

CPAN.

Finalmente, hay dos tipos más de referencias: arrayrefs anónimos y hashrefs anónimos. Estos se crean con "[]" y "{}", respectivamente. Así que, para nuestros propósitos no hay una diferencia real entre este

código: 
my @fields = qw(name email);
my %validate = (name => 'NAME', email => 'EMAIL');
my $form = CGI::FormBuilder->new(
                fields   => \@fields,
                validate => \%validate
           )
;

Y este

código: 
my $form = CGI::FormBuilder->new(
                fields   => [ qw(name email) ],
                validate => { name => 'NAME', email => 'EMAIL' }
           )
;

Excepto que el último no requiere que primero creemos @fields y %validate

vari
ables.
