CGI::Carp(3) Documentación de Perl aportada por el usuario CGI::Carp(3)

NOMBRE

CGI::Carp - Rutinas CGI para escribir en el registro de errores del HTTPD (u otro)

SINOPSIS

use CGI::Carp;
croak "¡Nos vamos de aquí!";
confess "¡Fue mi culpa: $!";
carp "¡Fue tu culpa!";
warn "Estoy confundido";
die  "Me estoy muriendo.\n";
use CGI::Carp qw(cluck);
cluck "No haría eso si fuera tú";
use CGI::Carp qw(fatalsToBrowser);
die "Los mensajes de error fatales ahora se envían al navegador";

DESCRIPCIÓN

Los scripts CGI tienen el mal hábito de dejar mensajes de advertencia en los registros de errores que no tienen marca de tiempo ni están completamente identificados. Rastrear el script que causó el error es un dolor. Esto lo soluciona. Reemplace el

use Carp;

habitual por

use CGI::Carp

Las llamadas estándar warn(), die (), croak(), confess() y carp() serán reemplazadas por funciones que escriben mensajes con marca de tiempo en el registro de errores del servidor HTTP.

Por ejemplo:

[Fri Nov 17 21:40:43 1995] test.pl: Estoy confundido en test.pl línea 3.
[Fri Nov 17 21:40:43 1995] test.pl: Se recibió un mensaje de error: Permiso denegado.
[Fri Nov 17 21:40:43 1995] test.pl: Me estoy muriendo.

REDIRIGIENDO MENSAJES DE ERROR

Por defecto, los mensajes de error se envían a STDERR. La mayoría de los servidores HTTPD dirigen STDERR al registro de errores del servidor. Algunas aplicaciones pueden desear mantener registros de errores privados, distintos del registro de errores del servidor, o pueden desear dirigir los mensajes de error a STDOUT para que el navegador los reciba.

La función carpout() se proporciona para este propósito. Dado que carpout() no se exporta por defecto, debe importarlo explícitamente diciendo

use CGI::Carp qw(carpout);

La función carpout() requiere un argumento, una referencia a un manejador de archivos abierto para escribir errores. Debe llamarse en un bloque "BEGIN" en la parte superior de la aplicación CGI para que se capturen los errores del compilador. Ejemplo:

BEGIN {
  use CGI::Carp qw(carpout);
  open(LOG, ">>/usr/local/cgi-logs/mycgi-log") or
    die("No se puede abrir mycgi-log: $!\n");
  carpout(LOG);
}

carpout() no maneja el bloqueo de archivos en el registro por usted en este punto. Además, tenga en cuenta que carpout() no funciona con manejadores de archivos en memoria, aunque se agradecería un parche para abordar eso.

El STDERR real no se cierra -- se mueve a CGI::Carp::SAVEERR. Algunos servidores, al tratar con scripts CGI, cierran su conexión con el navegador cuando el script cierra STDOUT y STDERR. CGI::Carp::SAVEERR está ahí para evitar que esto suceda prematuramente.

Puede pasar manejadores de archivos a carpout() de varias maneras. La forma "correcta" según Tom Christiansen es pasar una referencia a un GLOB de manejador de archivos:

carpout(\*LOG);

Esto parece extraño para los mortales, sin embargo, por lo que las siguientes sintaxis también son aceptadas:

carpout(LOG);
carpout(main::LOG);
carpout(main'LOG);
carpout(\LOG);
carpout(\'main::LOG');
... y así sucesivamente

FileHandle y otros objetos también funcionan.

El uso de carpout() no es ideal para el rendimiento, por lo que se recomienda para fines de depuración o para aplicaciones de uso moderado. Una versión futura de este módulo puede retrasar la redirección de STDERR hasta que se llame a uno de los métodos de CGI::Carp para evitar la penalización de rendimiento.

HACIENDO QUE LOS ERRORES DE PERL APAREZCAN EN LA VENTANA DEL NAVEGADOR

Si desea enviar errores fatales (die, confess) al navegador, importe la subrutina especial "fatalsToBrowser":

use CGI::Carp qw(fatalsToBrowser);
die "Error grave aquí";

Los errores fatales ahora se reflejarán en el navegador así como en el registro. CGI::Carp se encarga de enviar una cabecera HTTP mínima al navegador para que incluso los errores que ocurren en la fase temprana de compilación sean visibles. Los errores no fatales seguirán dirigiéndose solo al archivo de registro (a menos que se redirijan con carpout).

Tenga en cuenta que fatalsToBrowser puede no funcionar bien con mod_perl versión 2.0 y superior.

Cambiando el mensaje predeterminado

Por defecto, el mensaje de error del software va seguido de una nota para contactar al Webmaster por correo electrónico con la hora y fecha del error. Si este mensaje no le gusta, puede cambiarlo usando la rutina set_message() . Esta no se importa por defecto; debe importarla en la línea use() :

use CGI::Carp qw(fatalsToBrowser set_message);
set_message("¡No es un error, es una característica!");

También puede pasar una referencia de código para crear un mensaje de error personalizado. En tiempo de ejecución, su código será llamado con el texto del mensaje de error que causó la muerte del script. Ejemplo:

use CGI::Carp qw(fatalsToBrowser set_message);
BEGIN {
   sub handle_errors {
      my $msg = shift;
      print "<h1>Oh dios</h1>";
      print "<p>Se recibió un error: $msg</p>";
  }
  set_message(\&handle_errors);
}

Para interceptar correctamente los errores en tiempo de compilación, debe llamar a set_message() desde dentro de un bloque BEGIN{}.

HACIENDO MÁS QUE IMPRIMIR UN MENSAJE EN CASO DE ERRORES DE PERL

Si fatalsToBrowser en conjunto con set_message no le proporciona toda la funcionalidad que necesita, puede ir un paso más allá especificando una función que se ejecute cada vez que un script llame a "die", tenga un error de sintaxis, o muera inesperadamente en tiempo de ejecución con una línea como "undef->explode();".

use CGI::Carp qw(set_die_handler);
BEGIN {
   sub handle_errors {
      my $msg = shift;
      print "content-type: text/html\n\n";
      print "<h1>Oh dios</h1>";
      print "<p>Se recibió un error: $msg</p>";
      #proceder a enviar un correo electrónico a un administrador del sistema,
      #escribir un mensaje detallado al navegador y/o a un registro,
      #etc....
  }
  set_die_handler(\&handle_errors);
}

Tenga en cuenta que si usa set_die_handler(), debe manejar el envío de cabeceras HTML al navegador usted mismo si está imprimiendo un mensaje.

Si usa set_die_handler(), muy probablemente interferirá con el comportamiento de fatalsToBrowser, por lo que debe usar uno u otro, no ambos.

Usar set_die_handler() establece SIG{__DIE__} (como hace fatalsToBrowser), y solo hay un SIG{__DIE__}. Esto significa que si intenta establecer SIG{__DIE__} usted mismo, puede interferir con la funcionalidad de este módulo, o este módulo puede interferir con la funcionalidad de su módulo.

SUPRIMIENDO ERRORES DE PERL QUE APARECEN EN LA VENTANA DEL NAVEGADOR

Un problema que a veces se encuentra al usar fatalsToBrowser es cuando se realiza un die() dentro de un cuerpo o expresión "eval" . Aunque el soporte de fatalsToBrower toma precauciones para evitar esto, aún puede obtener el mensaje de error impreso en STDOUT. Esto puede tener algunos efectos indeseables cuando el propósito del eval es determinar cuál de varios algoritmos se va a usar.

Al establecer $CGI::Carp::TO_BROWSER en 0 puede suprimir la impresión de los mensajes "die" pero sin toda la complejidad de usar "set_die_handler". Puede localizar este efecto dentro de los cuerpos de "eval" si esto es deseable: Por ejemplo:

eval {
  local $CGI::Carp::TO_BROWSER = 0;
  die "Los mensajes de error fatales no se envían al navegador"
}
# $@ contendrá el mensaje de error

HACIENDO QUE LAS ADVERTENCIAS APAREZCAN COMO COMENTARIOS HTML

También es posible hacer que los errores no fatales aparezcan como comentarios HTML incrustados en la salida de su programa. Para habilitar esta característica, exporte la nueva subrutina "warningsToBrowser". Dado que enviar advertencias al navegador antes de que se hayan enviado las cabeceras HTTP causaría un error, cualquier advertencia se almacena en un búfer interno hasta que llame al warningsToBrowser() subrutina con un argumento verdadero:

use CGI::Carp qw(fatalsToBrowser warningsToBrowser);
use CGI qw(:standard);
print header();
warningsToBrowser(1);

También puede pasar un argumento falso a warningsToBrowser() para evitar que se envíen advertencias al navegador mientras imprime algún contenido donde no se permiten comentarios HTML:

warningsToBrowser(0);    # desactivar advertencias
print "<script type=\"text/javascript\"><!--\n";
print_some_javascript_code();
print "//--></script>\n";
warningsToBrowser(1);    # reactivar advertencias

Nota: En este sentido warningsToBrowser() difiere fundamentalmente de fatalsToBrowser(), ¡al que nunca debe llamar usted mismo!

ANULANDO EL NOMBRE DEL PROGRAMA

CGI::Carp incluye el nombre del programa que generó el error o la advertencia en los mensajes escritos en el registro y en la ventana del navegador. A veces, Perl puede confundirse sobre cuál era el nombre real del programa ejecutado. En estos casos, puede anular el nombre del programa que CGI::Carp usará para todos los mensajes.

La forma rápida de hacerlo es decirle a CGI::Carp el nombre del programa en su declaración use. Puede hacerlo añadiendo "name=cgi_carp_log_name" a su declaración "use". Por ejemplo:

use CGI::Carp qw(name=cgi_carp_log_name);

. Si desea cambiar el nombre del programa a mitad del programa, puede usar la set_progname() función en su lugar. No se exporta de forma predeterminada, debe importarla explícitamente diciendo

use CGI::Carp qw(set_progname);

Una vez que haya hecho eso, puede cambiar el nombre registrado del programa en cualquier momento llamando a

set_progname(new_program_name);

Puede restablecer el programa al valor predeterminado llamando a

set_progname(undef);

Tenga en cuenta que esta anulación no ocurre hasta después de que el programa se haya compilado, por lo que cualquier error en tiempo de compilación seguirá apareciendo con el nombre del programa no anulado

DESACTIVANDO LAS MARCAS DE TIEMPO EN LOS MENSAJES

Si su servidor web añade automáticamente una marca de tiempo a cada línea de registro, puede que no necesite que CGI::Carp añada la suya. Puede desactivar las marcas de tiempo importando "noTimestamp":

use CGI::Carp qw(noTimestamp);

Alternativamente, puede establecer $CGI::Carp::NO_TIMESTAMP a 1.

Tenga en cuenta que el nombre del programa sigue incluyéndose automáticamente en el mensaje.

OBTENIENDO LA RUTA COMPLETA DEL SCRIPT EN LOS MENSAJES

Establezca $CGI::Carp::FULL_PATH a 1.
