Documentación de la función/subrutina

subrutina cgees (character jobvs, character sort, external select, integer n, complex, dimension( lda, * ) a, integer lda, integer sdim, complex, dimension( * ) w, complex, dimension( ldvs, * ) vs, integer ldvs, complex, dimension( * ) work, integer lwork, real, dimension( * ) rwork, logical, dimension( * ) bwork, integer info)

CGEES calcula los valores propios, la forma de Schur y, opcionalmente, la matriz de vectores de Schur para matrices GE

Propósito:

!>
!> CGEES calcula para una matriz compleja no simétrica A de tamaño N por N,
!> los valores propios, la forma de Schur T y, opcionalmente, la matriz de
!> vectores de Schur Z. Esto da la factorización de Schur A = Z*T*(Z**H).
!>
!> Opcionalmente, también ordena los valores propios en la diagonal de
!> la forma de Schur para que los valores propios seleccionados estén en la
!> parte superior izquierda. Las columnas principales de Z forman entonces una
!> base ortonormal para el subespacio invariante correspondiente a los
!> valores propios seleccionados.
!>
!> Una matriz compleja está en forma de Schur si es triangular superior.
!>

Parámetros

JOBVS 
!>          JOBVS es CHARACTER*1
!>          = 'N': los vectores de Schur no se calculan;
!>          = 'V': los vectores de Schur se calculan.
!>

SORT

!>          SORT es CHARACTER*1
!>          Especifica si se deben ordenar o no los valores propios en la
!>          diagonal de la forma de Schur.
!>          = 'N': los valores propios no se ordenan:
!>          = 'S': los valores propios se ordenan (ver SELECT).
!>

SELECT

!>          SELECT es una FUNCIÓN LOGICA de un argumento COMPLEX
!>          SELECT debe declararse EXTERNAL en la subrutina que llama.
!>          Si SORT = 'S', SELECT se utiliza para seleccionar los valores
!>          propios a ordenar en la parte superior izquierda de la forma de
!>          Schur.
!>          SI SORT = 'N', SELECT no se referencia.
!>          El valor propio W(j) se selecciona si SELECT(W(j)) es verdadero.
!>

N

!>          N es INTEGER
!>          El orden de la matriz A. N >= 0.
!>

A

!>          A es un array COMPLEX, de dimensión (LDA,N)
!>          En la entrada, la matriz A de tamaño N por N.
!>          En la salida, A ha sido sobrescrita por su forma de Schur T.
!>

LDA

!>          LDA es INTEGER
!>          La dimensión principal del array A. LDA >= max(1,N).
!>

SDIM

!>          SDIM es INTEGER
!>          Si SORT = 'N', SDIM = 0.
!>          Si SORT = 'S', SDIM = número de valores propios para los que
!>                         SELECT es verdadero.
!>

W

!>          W es un array COMPLEX, de dimensión (N)
!>          W contiene los valores propios calculados, en el mismo orden en
!>          que aparecen en la diagonal de la forma de Schur de salida T.
!>

VS

!>          VS es un array COMPLEX, de dimensión (LDVS,N)
!>          Si JOBVS = 'V', VS contiene la matriz unitaria Z de vectores de
!>          Schur.
!>          Si JOBVS = 'N', VS no se referencia.
!>

LDVS

!>          LDVS es INTEGER
!>          La dimensión principal del array VS. LDVS >= 1; si
!>          JOBVS = 'V', LDVS >= N.
!>

WORK

!>          WORK es un array COMPLEX, de dimensión (MAX(1,LWORK))
!>          En la salida, si INFO = 0, WORK(1) devuelve el LWORK óptimo.
!>

LWORK

!>          LWORK es INTEGER
!>          La dimensión del array WORK. LWORK >= max(1,2*N).
!>          Para un buen rendimiento, LWORK debe ser generalmente mayor.
!>
!>          Si LWORK = -1, entonces se asume una consulta de espacio de
!>          trabajo; la rutina solo calcula el tamaño óptimo del array WORK,
!>          devuelve este valor como la primera entrada del array WORK y
!>          XERBLA no emite ningún mensaje de error relacionado con LWORK.
!>

RWORK

!>          RWORK es un array REAL, de dimensión (N)
!>

BWORK

!>          BWORK es un array LOGICAL, de dimensión (N)
!>          No se referencia si SORT = 'N'.
!>

INFO

!>          INFO es INTEGER
!>          = 0: finalización exitosa
!>          < 0: si INFO = -i, el argumento i tenía un valor ilegal.
!>          > 0: si INFO = i, y i es
!>               <= N: el algoritmo QR falló en calcular todos los
!>                      valores propios; los elementos 1:ILO-1 y i+1:N de W
!>                      contienen los valores propios que han convergido;
!>                      si JOBVS = 'V', VS contiene la matriz que
!>                      reduce A a su forma de Schur parcialmente
!>                      convergida.
!>               = N+1: los valores propios no pudieron ser reordenados
!>                      porque algunos valores propios estaban
!>                      demasiado cerca para separarse (el problema es
!>                      muy mal condicionado);
!>               = N+2: después de reordenar, la precisión cambió los
!>                      valores de algunos valores propios complejos de
!>                      modo que los valores propios principales en la
!>                      forma de Schur ya no satisfacen
!>                      SELECT = .TRUE.. Esto también podría ser causado
!>                      por subdesbordamiento debido al escalado.
!>
