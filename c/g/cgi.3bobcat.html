DESCRIPCIÓ

N

La clase CGI ofrece una interfaz para los datos enviados por formularios web. Los datos se envían a un script que los maneja utilizando una <form action="/ruta/al/script/formulario">. Muy a menudo esto es de hecho un script, como un script de Perl, pero no es necesario usar un lenguaje de scripting. La clase CGI permite a los programadores de C++ procesar el formulario mediante un ejecutable, lo que generalmente resulta en un procesamiento más rápido y en beneficios en tiempo de construcción gracias a la seguridad de tipos ofrecida por C++. La clase CGI maneja automáticamente los datos enviados mediante el método GET, así como los datos enviados mediante el POST

método.

Por defecto, el constructor de la clase escribe las líneas de encabezado habituales de Content-type en el flujo de salida estándar. Cualquier salida (html) adicional de una página de respuesta debe ser proporcionada por otro código. Por lo tanto, un programa que procesa un formulario subido tendrá una organización comparable a la siguiente configuración

básica: 
    // asumir que los includes y los espacios de nombres std/FBB fueron definidos
    int main()
    {
        CGI cgi;
        cout << "<html><body>\n";
        if (parametersOK(cgi))
        {
            process(cgi);
            generateReplyPage();
        }
        else
            generateErrorPage();
        cout << "</body></html>\n;
}

Cuando se detectan errores en los datos del formulario recibidos, se escribe un mensaje de error en el flujo de salida estándar y se lanza una excepción FB

B::Exce
ption.

CONSTRUCTORE

o
CGI(bool defaultEscape = true, char const *header = "Content-type: text/html", std::ostream &out = std::cout):
El constructor por defecto escribe el encabezado de tipo de contenido estándar en el flujo de salida estándar y usará std::cout para la salida. Especificar 0 como encabezado suprime la salida de la línea Content-type. De lo contrario, la línea de tipo de contenido también es seguida por dos combinaciones de caracteres \r\n. Por defecto, todos los caracteres en las variables del formulario recuperadas son escapados. Los operadores de inserción sobrecargados (ver más abajo) pueden usarse para modificar el conjunto por defecto de caracteres a escapar. La barra invertida se usa como carácter de escape. El prefijo de escape no se usa si el valor defaultEscape se especifica como false y si no se realizaron inserciones en el objeto
C

SOBRECARGADOS

Nota: los siguientes tres operadores de inserción, que definen conjuntos de caracteres que deben ser escapados, solo pueden usarse antes de llamar a cualquiera de los miembros param, begin o end. Tan pronto como uno de estos tres últimos miembros ha sido llamado, el conjunto de caracteres a escapar queda fijo y los intentos de modificar ese conjunto se ignoran silenciosamente

o
char const *operator[](std::string const &key) const:
El operador de índice devuelve el valor de la variable de entorno especificada como índice. Se devuelve 0 si la variable especificada en key no está
definida.
o
CGI &operator<<(std::string const &accept):
Las acciones de este miembro se suprimen una vez que se ha llamado a param, begin o end (ver más abajo)
.
El operador de inserción puede usarse para ajustar finamente el conjunto de caracteres que son escapados en las cadenas devueltas por param (ver más abajo). Dependiendo del valor del parámetro defaultEscape del constructor, los caracteres insertados en el objeto CGI serán o no escapados con una barra
invertida.
Si el parámetro defaultEscape del constructor fue especificado como true, entonces el operador de inserción puede usarse para definir un conjunto de caracteres que no son
escapados.
Si defaultEscape fue especificado como false, entonces el operador de inserción definirá un conjunto de caracteres que serán escap
ados.
La propia barra invertida siempre es escapada y una solicitud de usarla sin escapar es ignorada
silenciosamente.
La cadena accept puede especificarse como un conjunto de caracteres de expresión regular, sin los corchetes cuadrados circundantes habituales. Por ejemplo, una inserción como cgi << "-a-z0-9" define el conjunto que consiste en el guion, las letras minúsculas y los
dígitos.
Se pueden usar caracteres individuales, rangos de caracteres (usando el guion para especificar un rango) y todas las clases de caracteres estándar ([:alnum:], [:alpha:], [:cntrl:], [:digit:], [:graph:], [:lower:], [:print:], [:punct:], [:space:], [:upper:], y [:xdigit:]) para especificar un conjunto de caracteres. Además de estas clases de caracteres estándar, la clase [:cgi:] puede usarse para definir el conjunto que consiste en los caracteres " ’ ` ; y \
.
Tenga en cuenta que las clases de caracteres estándar y [:cgi:] sí requieren corchetes
cuadrados.
Cuando se realiza una serie de inserciones, se usa la unión de los conjuntos definidos por estas
inserciones.
Nota: usar comillas simples sin escapar, comillas dobles, caracteres de acento grave y punto y coma en programas CGI puede ser arriesgado y no es
aconsejable.
o

Devuelve el método que se utilizó cuando se envió el formulario (ya sea CGI::GET o CGI::POST)

o
std::vector<std::string> const &param(std::string const &variable):
Devuelve el valor de la variable de formulario especificada por el argumento de la función. Se devuelve un vector vacío si la variable no fue proporcionada por los datos del
formulario.
Si la misma variable fue especificada múltiples veces o si su valor se extiende sobre múltiples líneas (solo con multipart/form-data) entonces el vector contiene múltiples
cadenas.
Con los métodos GET y POST que no usan campos de entrada multipart/form-data que se extienden sobre múltiples líneas se almacenan en una sola cadena, usando combinaciones \r\n entre esas
líneas.
Cuando se suben archivos los vectores contienen conjuntos de cuatro cadenas. La primera cadena proporciona el nombre de ruta del archivo subido; la segunda cadena proporciona el nombre de archivo especificado en el propio formulario (así que es el nombre del archivo en la ubicación remota); la tercera cadena muestra el tipo de contenido especificado por el navegador remoto (por ejemplo, application/octet-stream), la cuarta cadena contiene OK si el archivo fue subido con éxito y truncated si el archivo fue truncado. Los archivos existentes no serán sobrescritos. Al subir un archivo debe encontrarse un nombre de archivo utilizable dentro de 100
intentos.
o
std::string param1(std::string const &variable) const:
Devuelve el primer elemento del vector<string> devuelto por el miembro param o una cadena vacía si variable no fue definida por el formulario
recibido.
o
std::string const &query() const:
Devuelve la cadena de consulta (query-string) enviada con formularios CGI::GET o CGI::POST (si el formulario POSTed especificó ENCTYPE="multipart/form-data" la cadena de consulta está vacía)
.
o
report():
El miembro report devuelve silenciosamente si no se encontraron errores mientras se procesaban los datos del formulario. De lo contrario, el archivo html generado por el programa CGI muestra una línea que comienza con FBB::CGI, seguida del informe de
estado.
Los siguientes mensajes de informe de estado están actualmente
definidos:
Content-Disposition not recognized in:, que es seguido por la línea donde se esperaba el Content-Disposition. Esto puede ocurrir cuando se procesa datos multipar
t/form.
Invalid multipart/form-data. Este mensaje puede generarse al leer líneas mientras se procesan datos multipar
t/form.
GET/POST REQUEST_METHOD not found. Este mensaje se muestra si el programa no pudo encontrar el tipo REQUEST_METHOD del formulario (es decir, GET o POST
).
Invalid CONTENT_LENGHT in POSTed form. Este mensaje se muestra si el encabezado content-length tiene un valor
incorrecto.
Content-Type not found for file-field, seguido por el nombre del campo del archivo. Este mensaje se muestra si no se encontró ninguna especificación Content-Type en un formulario
subido.
Can’t open a file to write an uploaded file. Este mensaje indica que el programa CGI no pudo abrir un archivo para escribir un archivo subido. Esto puede ser causado por un disco o partición llena o por permisos de escritura
incorrectos.
multipart/form-data: no end-boundary found. Este mensaje se muestra si faltaba el límite final (end-boundary) en un formulario multipart/form-da
ta.
o

Este miembro se puede usar para cambiar el tamaño máximo de los archivos subidos. Su valor por defecto es 100Mb. void showParam(CGI::MapStringVector::value_type const &mapValue)
{
    cout << "Param: " << mapValue.first << ’\n’;
    for (auto &str: mapValue.second)
        cout << "    " << CGI::dos2unix(str) << "\n"
            "    ";
    cout << ’\n’;
}
int main(int argc, char **argv)
try
{
    Arg &arg = Arg::initialize("evhm:", argc, argv);
    // usage and version are in the source archive in .../cgi/driver
    // arg.versionHelp(usage, version, 2);
    ifstream in(arg[0]);
    string line;
    while (getline(in, line))
    {
        size_t pos = line.find(’=’);
        if (pos == string::npos)
            continue;
                            // set environment vars simulating
                            // a GET form
        if (setenv(line.substr(0, pos).c_str(),
               line.substr(pos + 1).c_str(), true) == 0)
        {
            if (arg.option(’e’))
                cout << line.substr(0, pos).c_str() << ’=’ <<
                       line.substr(pos + 1).c_str() << ’\n’;
        }
        else
            cout << "FAILED: setenv " << line << ’\n’;
    }
    CGI cgi(false);             // chars are not escaped
    cgi << arg[1];
    if (arg.option(&line, ’m’))
        cgi.setMaxUploadSize(stoul(line), *line.rbegin());
    cout << "Max upload size (b): " << cgi.maxUploadSize() << ’\n’;
    CGI::Method method = cgi.method();
    cout << "To escape:\n" <<
            cgi << "\n"
            "Method: " << (method == CGI::GET ? "GET" : "POST") <<
            ’\n’;
    cout << "Query string: " << cgi.query() << ’\n’;
    cout << "Submit string: `" << cgi.param1("submit") << "’\n";
    for (auto &mapElement: cgi)
        showParam(mapElement);
    cout << "END OF PROGRAM\n";
}
