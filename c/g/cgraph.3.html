NODO

S

Un nodo se creacreado asignando un nombre de cadena único o un ID entero definido por el programador, y está representado por un objeto interno único. (La igualdad de nodos puede comprobarse por comparación de punteros.)

agnode busca en un grafo o subgrafo un nodo con el nombre dado, y lo devuelve si se encuentra. agidnode permite a un programador especificar el nodo por un ID entero único. agsubnode realiza una operación similar en un nodo existente y un subgrafo.

agfstnode y agnxtnode recorren listas de nodos. agprvnode y aglstnode son simétricos pero recorren hacia atrás. La secuencia por defecto es el orden de creación (marca de tiempo del objeto.) agdelnode elimina un nodo de un grafo o subgrafo.

ARISTAS

Una arista abstracta tiene dos nodos extremos llamados cola y cabeza, donde todas las aristas salientes del mismo nodo lo tienen como valor de cola, y de manera similar todas las aristas entrantes lo tienen como cabeza. En un grafo no dirigido, cabeza y cola son intercambiables. Si un grafo tiene multi-aristas entre el mismo par de nodos, el nombre de cadena de la arista actúa como clave secundaria.

agedge busca en un grafo o subgrafo una arista entre los extremos dados (con un nombre de selector de multi-arista opcional) y la devuelve si se encuentra o se crea. Nótese que, en grafos no dirigidos, una búsqueda prueba ambas ordenaciones de los nodos de cola y cabeza. Si el nombre es NULL, entonces se genera un valor interno anónimo. agidedge permite a un programador crear una arista dando su ID entero único. agsubedge realiza una operación similar en una arista existente y un subgrafo. agfstin, agnxtin, agfstout, y agnxtout visitan listas de aristas entrantes y salientes dirigidas, y ordinariamente se aplican solo en grafos dirigidos. agfstedge y agnxtedge visitan todas las aristas incidentes a un nodo. agtail y aghead obtienen el extremo de una arista. agdeledge elimina una arista de un grafo o subgrafo.

Nótese que una arista abstracta tiene dos representaciones concretas distintas: como arista entrante y como arista saliente. En particular, el puntero como arista saliente es diferente del puntero como arista entrante. La función ageqedge canonicaliza los punteros antes de hacer una comparación y por lo tanto puede usarse para probar la igualdad de aristas. El sentido de una arista puede invertirse usando agopp.

ATRIBUTOS INTERNOS

Los valores definidos por el programador pueden adjuntarse dinámicamente a grafos, subgrafos, nodos y aristas. Tales valores son o bien datos de cadena de caracteres (para E/S) o bien registros binarios sin interpretar (para implementar algoritmos eficientemente).

ATRIBUTOS DE CADENA

Los atributos de cadena se manejan automáticamente al leer y escribir archivos de grafos. Un atributo de cadena se identifica por nombre y por una entrada de tabla de símbolos interna (Agsym_t) creada por Libcgraph. Los atributos de nodos, aristas y grafos (con sus subgrafos) tienen espacios de nombres separados. El contenido de un Agsym_t tiene un char* name para el nombre del atributo, un campo char* defval para el valor por defecto del atributo, y un campo int id que contiene el índice del valor específico del atributo para un objeto en el arreglo de valores de atributos del objeto.

agattr crea o busca atributos. kind puede ser AGRAPH, AGNODE, o AGEDGE. Si value es (char*)0), la petición es buscar un atributo existente del tipo y nombre dados. De lo contrario, si el atributo ya existe, su valor por defecto para crear nuevos objetos se establece al valor dado; si no existe, se crea un nuevo atributo con el valor por defecto dado, y el valor por defecto se aplica a todos los objetos preexistentes del tipo dado. Si g es NULL, el valor por defecto se establece para todos los grafos creados posteriormente. agattrsym es una función auxiliar que busca un atributo para un objeto de grafo dado como argumento. agnxtattr permite recorrer la lista de atributos de un tipo dado. Si se pasa NULL como argumento obtiene el primer atributo; de lo contrario devuelve el siguiente en sucesión o devuelve NULL al final de la lista. agget y agset permiten obtener y actualizar un atributo de cadena para un objeto tomando el nombre del atributo como argumento. agxget y agxset hacen esto pero con una entrada de tabla de símbolos de atributo como argumento (para evitar el costo de la búsqueda de la cadena). Nótese que agset fallará a menos que el atributo se haya definido primero usando agattr. agsafeset es una función de conveniencia que asegura que el atributo dado esté declarado antes de establecerlo localmente en un objeto.

A veces es conveniente copiar todos los atributos de un objeto a otro. Esto puede hacerse usando agcopyattr. Esto falla y devuelve distinto de cero si los objetos de argumento son de tipos diferentes, o si todos los atributos del objeto fuente no han sido declarados para el objeto destino.

CADENAS

Libcgraph realiza su propia gestión de almacenamiento de cadenas como cadenas con conteo de referencias. El llamador no necesita asignar almacenamiento dinámicamente.

agstrdup devuelve un puntero a una copia con conteo de referencias de la cadena de argumento, creando una si es necesario. agstrbind devuelve un puntero a una cadena con conteo de referencias si existe, o NULL si no. Todos los usos de cadenas de cgraph necesitan ser liberados usando agstrfree para mantener correctamente el conteo de referencias.

El analizador de cgraph maneja cadenas tipo HTML. Estas deberían ser indistinguibles de otras cadenas para la mayoría de los propósitos. Para crear una cadena tipo HTML, use agstrdup_html. La función aghtmlstr puede usarse para consultar si una cadena es una cadena ordinaria o una cadena tipo HTML.

agstrcanon devuelve un puntero a una versión de la cadena de entrada canonicalizada para salida para su posterior re-análisis. Esto incluye el entrecomillado de caracteres especiales y palabras clave. La aplicación pasa un búfer como segundo argumento. Nótese que el búfer puede no ser usado; si la cadena de entrada está en forma canónica, la función simplemente devolverá un puntero a ella. La cadena de entrada debe haber sido creada usando agstrdup o agstrdup_html.

REGISTROS

Los registros sin interpretar pueden adjuntarse a grafos, subgrafos, nodos y aristas para operaciones eficientes sobre valores como marcas, pesos, conteos y punteros necesitados por algoritmos. Los programadores de aplicaciones definen los campos de estos registros, pero deben declararse con un encabezado común como se muestra abajo.

typedef struct {
    Agrec_t        header;
    /* los campos definidos por el programador siguen */
} user_data_t;

Los registros son creados y gestionados por Libcgraph. Un programador debe adjuntarlos explícitamente a los objetos en un grafo, ya sea a objetos individuales uno a la vez vía agbindrec, o a todos los objetos de la misma clase en un grafo vía aginit. (Nótese que para grafos, aginit se aplica recursivamente al grafo y sus subgrafos si rec_size es negativo (del rec_size real).) El argumento name de un registro distingue varios tipos de registros, y es definido por el programador (Libcgraph reserva el prefijo _ag). Si size es 0, la llamada a agbindrec es simplemente una búsqueda. La función aggetrec también puede usarse para búsqueda. agdelrec elimina un registro con nombre de un objeto. agclean hace lo mismo para todos los objetos de la misma clase en un grafo entero.

Internamente, los registros se mantienen en listas enlazadas circulares adjuntadas a objetos de grafo. Para permitir referenciar datos dependientes de la aplicación sin llamadas a funciones o búsqueda, Libcgraph permite establecer y bloquear el puntero de lista de un grafo, nodo o arista en un registro particular. Este puntero puede obtenerse con la macro AGDATA(obj). Un cast, generalmente dentro de una macro o función inline, se aplica usualmente para convertir el puntero de lista a un tipo apropiado definido por el programador.

Para controlar el establecimiento de este puntero, el indicador move_to_front puede ser TRUE o FALSE. Si move_to_front es TRUE, el registro será bloqueado en la cabeza de la lista, de modo que pueda ser accedido directamente por AGDATA(obj). El bloqueo puede ser posteriormente liberado o restablecido por una llamada a aggetrec.

DISCIPLINAS

(Esta sección no está destinada a usuarios ocasionales.) Las disciplinas definidas por el programador personalizan ciertos recursos - espacio de nombres de IDs y E/S - necesitados por Libcgraph. Un struct de disciplina (o NULL) se pasa en el momento de la creación del grafo.

struct Agdisc_s {            /* disciplina del usuario */
    Agiddisc_t            *id;
    Agiodisc_t            *io;
} ;

Se proporciona una disciplina por defecto cuando se da NULL para cualquiera de estos campos.

DISCIPLINA DE ID

Una disciplina de asignador de ID permite a un cliente controlar la asignación de IDs (valores enteros sin interpretar) a objetos, y posiblemente cómo se mapean a y desde cadenas.

struct Agiddisc_s {             /* asignador de ID de objetos */
    void *(*open) (Agraph_t * g, Agdisc_t*);       /* asociado con un grafo */
    long (*map) (void *state, int objtype, char *str, unsigned long *id, int createflag);
    long (*alloc) (void *state, int objtype, unsigned long id);
    void (*free) (void *state, int objtype, unsigned long id);
    char *(*print) (void *state, int objtype, unsigned long id);
    void (*close) (void *state);
};

open permite a la disciplina de ID inicializar cualquier estructura de datos que mantenga por grafo individual. Su valor de retorno se pasa entonces como primer argumento (void *state) a todas las llamadas subsecuentes al gestor de ID.

alloc informa al gestor de ID que Libcgraph está intentando crear un objeto con un ID específico que fue dado por un cliente. El gestor de ID debería devolver TRUE (distinto de cero) si el ID puede ser asignado, o FALSE (lo que aborta la operación).

free se llama para informar al gestor de ID que el objeto etiquetado con el ID dado está a punto de dejar de existir.

map se llama para crear o buscar IDs por nombre de cadena (si es soportado por el gestor de ID). Devolver TRUE (distinto de cero) en todos los casos significa que la petición tuvo éxito (con un ID válido almacenado a través de result. Hay cuatro casos:

•
name != NULL y createflag == 1: Esto solicita mapear una cadena (p.ej. un nombre en un archivo de grafo) a un nuevo ID. Si el gestor de ID puede cumplir, entonces almacena el resultado y devuelve TRUE. Entonces también es responsable de poder print el ID de nuevo como cadena. De lo contrario el gestor de ID puede devolver FALSE pero debe implementar lo siguiente (al menos para que la lectura y escritura de archivos de grafo funcionen):
•
name == NULL y createflag == 1: El gestor de IDs crea un ID nuevo único de su propia elección. Aunque puede devolver FALSE si no soporta objetos anónimos, esto es fuertemente desalentado (para soportar "nombres locales" en archivos de grafo.)
•
name != NULL y createflag == 0: Esta es una sonda de espacio de nombres. Si el nombre fue previamente mapeado a un ID asignado por el gestor de IDs, entonces el gestor debe devolver este ID. De lo contrario, el gestor de IDs puede devolver FALSE, o puede almacenar cualquier ID no asignado en result. (Esto es conveniente, por ejemplo, si se sabe que los nombres son cadenas de dígitos que se convierten directamente en valores enteros.)
•
name == NULL y createflag == 0: prohibido.

print está permitido devolver un puntero a un búfer estático; un llamador debe copiar su valor si necesita que persista más allá de llamadas posteriores. NULL debe ser devuelto por los gestores de IDs que no mapean nombres.

Las map y alloc llamadas no pasan un puntero al objeto recién asignado. Si un cliente necesita instalar punteros de objetos en una tabla de manejadores, puede obtenerlos a través de callbacks de nuevo objeto.

DISCIPLINA DE E/S

La disciplina de E/S proporciona una abstracción para la lectura y escritura de grafos.

struct Agiodisc_s {
    int        (*fread)(void *chan, char *buf, int bufsize);
    int        (*putstr)(void *chan, char *str);
    int        (*flush)(void *chan);    /* sync */
} ;

Normalmente, la FILE estructura y sus funciones relacionadas se usan para E/S. Sin embargo, a veces una aplicación puede necesitar usar un tipo de fuente de caracteres totalmente diferente. El estado o información de flujo asociado es proporcionado por el argumento chan a agread o agwrite. La función de disciplina fread y putstr proporcionan las funciones correspondientes para leer y escribir.

CALLBACKS

Un Agcbdisc_t define callbacks a ser invocados por Libcgraph al inicializar, modificar u finalizar objetos de grafo. Las disciplinas se mantienen en una pila. Libcgraph llama automáticamente a los métodos en la pila, de arriba hacia abajo. Los callbacks se instalan con agpushdisc, se desinstalan con agpopdisc, y pueden mantenerse pendientes o liberarse a través de agcallbacks.

OBJETOS GENÉRICOS

agroot toma cualquier objeto de grafo (grafo, subgrafo, nodo, arista) y devuelve el grafo raíz en el que vive. agraphof hace lo mismo, excepto que es la función identidad en grafos y subgrafos. Note que no hay una función para devolver el subgrafo más pequeño que contiene un objeto, en parte porque esto no está bien definido ya que los nodos y aristas pueden estar en subgrafos incomparables.

agcontains(g,obj) devuelve distinto de cero si obj es un miembro del (sub)grafo g. agdelete(g,obj) es equivalente a agclose, agdelnode, y agdeledge para obj siendo un grafo, nodo o arista, respectivamente. Devuelve -1 si obj no pertenece a g.

AGDATA, AGID, y AGTYPE son macros que devuelven los campos especificados del objeto argumento. El primero está descrito en la sección RECORDS arriba. El segundo devuelve el ID entero único asociado con el objeto. El último devuelve AGRAPH, AGNODE, AGEDGE dependiendo del tipo del objeto.

agnameof devuelve un descriptor de cadena para el objeto. Devuelve el nombre del nodo o grafo, y la clave de una arista. agobjkind es un sinónimo para AGTYPE.

INFORME DE ERRORES

La biblioteca proporciona una variedad de mecanismos para controlar el informe de errores y advertencias. Actualmente, hay básicamente dos tipos de mensajes: advertencias y errores. Un mensaje solo se escribe si su tipo tiene una prioridad más alta que un mínimo controlado por el programador, que es AGWARN por defecto. El programador puede establecer este valor usando agseterr, que devuelve el valor anterior. Llamar a agseterr(AGMAX) desactiva la escritura de mensajes.

La función agerr es el punto de entrada principal para reportar una anomalía. El primer argumento indica el tipo de mensaje. Usualmente, el primer argumento es AGWARN o AGERR para indicar advertencias y errores, respectivamente. A veces información de contexto adicional solo está disponible en funciones que llaman a la función donde el error es realmente capturado. En este caso, la función llamadora puede indicar que está continuando el error actual usando AGPREV como primer argumento. Los argumentos restantes de agerr son los mismos que los argumentos de printf.

Las funciones agwarningf y agerrorf son atajos para agerr(AGWARN,...) y agerr(AGERR,...), respectivamente.

Algunas aplicaciones desean controlar directamente la escritura de mensajes. Tal aplicación puede usar la función agseterrf para registrar la función que la biblioteca debe llamar para escribir realmente el mensaje. La función de error anterior es devuelta. Por defecto, el mensaje se escribe en stderr.

Los errores no escritos se almacenan en un archivo de registro. El último error registrado puede ser recuperado llamando a aglasterr. A menos que la impresión de mensajes de error haya sido completamente desactivada por una llamada a agseterr(AGMAX), el error estándar no debe estar orientado a anchura, incluso si se proporciona una función de impresión de error proporcionada por el usuario.

La función agerrors devuelve distinto de cero si se han reportado errores.

#include <cgraph.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>
typedef struct {
  Agrec_t hdr;
  int x;
  int y;
  int z;
} mydata;
int main(int argc, char **argv) {
  Agraph_t *g;
    mydata      *p;
  if ((g = agread(stdin, NULL))) {
    int cnt = 0;
    Agsym_t *attr = NULL;
    while ((attr = agnxtattr(g, AGNODE, attr))) {
      cnt++;
    }
    printf("The graph %s has %d attributes\n", agnameof(g), cnt);
    // make the graph have a node color attribute, default is blue
    attr = agattr_text(g, AGNODE, "color", "blue");
    // create a new graph of the same kind as g
    Agraph_t *h = agopen("tmp", g->desc, NULL);
    // this is a way of counting all the edges of the graph
    cnt = 0;
    for (Agnode_t *v = agfstnode(g); v != NULL; v = agnxtnode(g, v)) {
      for (Agedge_t *e = agfstout(g, v); e != NULL; e = agnxtout(g, e)) {
        cnt++;
      }
    }
    // attach records to edges
    for (Agnode_t *v = agfstnode(g); v != NULL; v = agnxtnode(g, v)) {
      for (Agedge_t *e = agfstout(g, v); e != NULL; e = agnxtout(g, e)) {
        p = (mydata *)agbindrec(e, "mydata", sizeof(mydata), true);
        p->x = 27; // meaningless data access example
        ((mydata *)(AGDATA(e)))->y = 999; // another example
      }
    }
  }
  return 0;
}

ERRORES

Es difícil cambiar los extremos de las aristas, eliminar atributos de cadena o modificar claves de aristas. La solución alternativa es crear un nuevo objeto y copiar el contenido de uno antiguo (pero el nuevo objeto obviamente tiene un ID diferente, dirección interna y marca de tiempo de creación de objeto).

La API carece de funciones convenientes para sustituir el ordenamiento de nodos y aristas definido por el programador, pero en principio esto puede ser soportado.
