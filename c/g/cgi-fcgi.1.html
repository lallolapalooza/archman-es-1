cgi-fcgi(1)

Paquete: fcgi

Licencias: custom

() ()
NOMBRE
cgi-fcgi - puente de CGI a FastCGI

SINOPIS
cgi-fcgi -f ruta_cmd
cgi-fcgi -bind -connect nombre_conexion
cgi-fcgi -start -connect nombre_conexion ruta_app [nServidores]
cgi-fcgi -connect nombre_conexion ruta_app [nServidores]

DESCRIPCIÓN
cgi-fcgi es un programa CGI/1.1 que se comunica con una
aplicación FastCGI ya en ejecución para responder a una
solicitud HTTP. cgi-fcgi también es capaz de iniciar una
aplicación FastCGI.


Cuando invoca cgi-fcgi como


cgi-fcgi -f ruta_cmd


entonces cgi-fcgi abre el archivo en ruta_cmd y lee sus
argumentos de ese archivo. cgi-fcgi omitirá las líneas
que comiencen con el carácter de comentario #. La primera
línea no comentada debe contener argumentos válidos en
una de las otras tres formas.


La forma -f de cgi-fcgi está diseñada para sistemas Unix
cuyas llamadas al sistema de la familia exec(2) admiten la ejecución de
archivos intérpretes de comandos. Por ejemplo, si un archivo con
permiso de ejecución contiene el texto


#! /bin/cgi-fcgi -f
-connect /httpd/root/sock/app /httpd/root/bin/app


el efecto es el mismo que ejecutar


/bin/cgi-fcgi -connect /httpd/root/sock/app /httpd/root/bin/app


Cuando invoca cgi-fcgi como


cgi-fcgi -bind -connect nombre_conexion


el argumento nombre_conexion es el nombre de ruta de un socket de escucha
de dominio Unix o un par host:puerto. Si nombre_conexion contiene
dos puntos, se asume que es host:puerto. cgi-fcgi realiza
un connect(2) usando nombre_conexion. Si la conexión tiene éxito, cgi-fcgi
reenvía las variables de entorno CGI y los datos de stdin a la
aplicación FastCGI, y reenvía los datos de stdout y stderr de
la aplicación a stdout de cgi-fcgi (probablemente conectado a
un servidor web). Cuando la aplicación FastCGI señala el fin de
su respuesta, cgi-fcgi vacía sus búferes y
sale, y el servidor web completa la respuesta http.


Cuando invoca cgi-fcgi como


cgi-fcgi -start -connect nombre_conexion ruta_app [nServidores]


entonces cgi-fcgi realiza la función de iniciar uno o más
procesos de aplicación FastCGI. El argumento nombre_conexion especifica
ya sea el nombre de ruta del socket de escucha de dominio Unix que
cgi-fcgi creará, o es "localhost:NNN" donde NNN es el número de puerto
del socket de escucha TCP/IP que cgi-fcgi creará
en la máquina local. (cgi-fcgi no creará procesos
en máquinas remotas.) Después de que cgi-fcgi crea el socket de escucha,
se bifurca nServidores copias de un proceso ejecutando el archivo ejecutable
ruta_app. Si se omite nServidores, el efecto es como si el valor "1"
hubiera sido especificado. Los procesos comparten el único socket de escucha.


Cuando invoca cgi-fcgi como


cgi-fcgi -connect nombre_conexion ruta_app [nServidores]


cgi-fcgi realiza -bind y luego, si es necesario, realiza -start
y repite el -bind. Es decir, cgi-fcgi primero opera como si
el comando hubiera sido


cgi-fcgi -bind -connect nombre_conexion


Si la conexión falla, cgi-fcgi intenta


cgi-fcgi -start -connect nombre_conexion ruta_app [nServidores]


y finalmente reintenta


cgi-fcgi -bind -connect nombre_conexion


En esta forma, cgi-fcgi no admite conexiones TCP/IP.

VARIABLES DE ENTORNO
Las habituales de CGI, pero no son interpretadas por cgi-fcgi.

VER TAMBIÉN
FGCI_accept(3)

ERRORES
cgi-fcgi no genera respuestas HTTP útiles en caso de error,
y no genera ninguna respuesta en absoluto cuando se ejecuta como start-fcgi.


En sistemas Digital UNIX 3.0 la implementación de sockets de dominio Unix
no funciona cuando dichos sockets se almacenan en sistemas de archivos NFS.
Síntoma: cgi-fcgi puede volcar el núcleo o puede salir con
estado 38. Solución: almacenar los sockets en sistemas de archivos locales
(normalmente /tmp funciona) o usar TCP/IP.


En sistemas AIX la implementación de sockets de escucha
no admite el intercambio de sockets, y las bibliotecas estándar de aplicaciones
FastCGI no pueden sincronizar el acceso a los sockets de escucha de AIX.
Solución: No usar el argumento nServidores en AIX.
