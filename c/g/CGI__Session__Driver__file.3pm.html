CGI::Session::Driver::file(3) Documentación de Perl aportada por el usuario CGI::Session::Driver::file(3)

NOMBRE

CGI::Session::Driver::file - Driver por defecto de CGI::Session

SINOPSIS

$s = CGI::Session->new();
$s = CGI::Session->new("driver:file", $sid);
$s = CGI::Session->new("driver:file", $sid, {Directory=>'/tmp'});

DESCRIPCIÓN

Cuando se crea un objeto CGI::Session sin especificar explícitamente el driver, se asumirá file. El driver file almacenará los datos de la sesión en archivos planos, donde cada sesión se guardará en un archivo separado.

Las convenciones de nombres de los archivos de sesión se definen mediante la variable global $CGI::Session::Driver::file::FileName. El valor por defecto de esta variable es cgisess_%s, donde %s se reemplazará con el ID de sesión correspondiente. Si desea establecer su propia plantilla FileName, hágalo antes de solicitar el objeto de sesión:

use CGI::Session::Driver::file; # Esta línea es obligatoria.
# Pasa el tiempo...
$CGI::Session::Driver::file::FileName = "%s.dat";
$s = CGI::Session->new();

Para compatibilidad con versiones anteriores (3.x), también puede usar el nombre de variable $CGI::Session::File::FileName, que anulará la anterior.

ARGUMENTOS DEL DRIVER

Si desea especificar un directorio de sesiones, use la opción Directory, que indica la ubicación del directorio donde se guardarán los IDs de sesión. Si Directory no está configurada, se utilizará por defecto lo que devuelva File::Spec->tmpdir(). Por lo tanto, las tres líneas en la sección SYNOPSIS de este manual producen el mismo resultado en una máquina UNIX.

Si el Directory especificado no existe, se creará toda la jerarquía de directorios necesaria.

Por defecto, las sesiones se crean con una umask de 0660. Si desea cambiar la umask de una sesión, pase una opción UMask con una representación octal de la umask que desee para dicha sesión.

NOTAS

Si su sistema operativo no soporta flock, debe comprender los riesgos de operar sin bloquear los archivos de sesión. Dado que las sesiones tienden a ser utilizadas en entornos donde pueden ocurrir condiciones de competencia debido al acceso concurrente a los archivos por parte de diferentes procesos, el bloqueo se considera una práctica buena y muy necesaria. Si aun así desea utilizar este driver pero no quiere usar flock, configure $CGI::Session::Driver::file::NoFlock a 1 o pase "NoFlock => 1" y este driver operará sin bloqueos.
