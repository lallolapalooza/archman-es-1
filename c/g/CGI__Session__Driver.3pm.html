DESCRIPCIÓ

N

CGI::Session::Driver es una clase base para todos los controladores nativos de CGI::Sessio

n. También documenta las especificaciones de los controladores para aquellos que deseen escribi

QUÉ ES UN

CONTROLADOR

Un controlador es un fragmento de código que ayuda a la biblioteca CGI::Session a comunicarse con motores de bases de datos específicos, o mecanismos de almacenamiento. Para ser más preciso, un controlador es un archivo .pm que hereda de CGI::Session::Driver y define los métodos retrieve(), store() y remove

().

PLAN

O

La mejor manera de aprender las especificaciones es mirar el plano de un

controlador: 
package CGI::Session::Driver::your_driver_name;
use strict;
use base qw( CGI::Session::Driver CGI::Session::ErrorHandler );
sub init {
    my ($self) = @_;
    # opcional
}
sub DESTROY {
    my ($self) = @_;
    # opcional
}
sub store {
    my ($self, $sid, $datastr) = @_;
    # Almacenar $datastr, que es una cadena de datos ya serializada.
}
sub retrieve {
    my ($self, $sid) = @_;
    # Devolver $datastr, que fue almacenado previamente usando el método store() de arriba.
    # Devolver $datastr si $sid fue encontrado. Devolver 0 o "" si $sid no existe
    }
sub remove {
    my ($self, $sid) = @_;
    # Eliminar el almacenamiento asociado con $sid. Devolver cualquier valor verdadero indicando éxito,
    # o undef en caso de fallo.
}
sub traverse {
    my ($self, $coderef) = @_;
    # ejecutar $coderef para cada id de sesión pasando el id de sesión como el primer y único
    # argumento
}
1;

Todos los atributos pasados como segundo argumento a los métodos new() o load() de CGI::Session se convertirán automáticamente en atributos del objeto del controlador. Por ejemplo, si el objeto de sesión se inicializó como

sigue: 
$s = CGI::Session->new("driver:your_driver_name", undef, {Directory=>'/tmp/sessions'})
;

Puedes acceder al valor de 'Directory' desde dentro de tu controlador

así: 
sub store {
    my ($self, $sid, $datastr) = @_;
    my $dir = $self->{Directory};   # <-- en este ejemplo será '/tmp/sessions'
}

Opcionalmente, puedes definir el método init() dentro de tu controlador para realizar una inicialización global específica del controlador. El método init() será invocado solo una vez durante el ciclo de vida de tu controlador, que es el mismo que el ciclo de vida de un objeto de

sesión.

Para ejemplos de init() consulta el código fuent

de CGI::Session.

MÉTODO

S

Esta sección lista y describe todos los métodos del controlador. Todos los métodos del controlador recibirán el objeto del controlador ($self) como primer argumento. Los métodos que pertenecen a una sesión individual (como retrieve(), store() y remove()) también recibirán el id de sesión ($sid) como segundo

argumento.

La siguiente lista describe cada método del controlador, incluyendo su lista de argumentos y en qué paso de la vida de la sesión serán invocados. Entender esto puede ayudar a los autores de

controladores.
retrieve($self,
$sid)
Se llama cada vez que se solicita una sesión específica ya sea a través de la sintaxis "CGI::Session->new()" o "CGI::Session->load()". El método debe intentar recuperar los datos asociados con $sid y devolverlos. En caso de que no se puedan recuperar datos para $sid, se debe devolver 0 (cero) o "". Solo se debe devolver undef para señalar un error. El mensaje de error debe establecerse mediante set_error(), que puede heredarse de CGI::Session::ErrorHandler.

Consejo: set_error() siempre devuelve unde

f. Úsalo en tu
beneficio.
store($self, $sid,
$datastr)
Se llama cada vez que los datos de sesión modificados deben almacenarse de nuevo en disco. Esto sucede cada vez que se llama a CGI::Session->flush() en una sesión modificada. Dado que CGI::Session->DESTROY() llama a flush(), store() se solicita cada vez que un objeto de sesión va a ser terminado.

store() se llama tanto para almacenar nuevas sesiones como para actualizar sesiones ya almacenadas. Es trabajo del autor del controlador averiguar qué operación necesita ser

realizada.

$datastr, que se pasa como tercer argumento, representa los datos de sesión ya serializados que necesitan ser

guardados.

store() puede devolver cualquier valor verdadero indicando éxito o undef en caso de fallo. El mensaje de error debe pasarse a set_err

or
()
remove($self,
$sid)
Se llama cada vez que los datos de sesión deben ser eliminados, lo cual es cuando se llama a CGI::Session->delete(). Debe devolver cualquier valor verdadero indicando éxito, undef en caso de fallo. El mensaje de error debe registrarse en set_erro
r().
traverse($self,
\&coderef)
Se llama solo desde dentro de CGI::Session->find(). El trabajo de traverse() es llamar a \&coderef para cada sesión almacenada en disco pasando el id de la sesión como el primer y único argumento: $coderef->( $sid
)
init($sel
f)
Opcional. Se llama cada vez que el objeto del controlador va a ser inicializado, lo cual sucede solo una vez durante el ciclo de vida del objeto CGI::Session. Aquí puedes hacer una inicialización a nivel de controlador, como abrir una conexión a un servidor de base de
datos.
DESTROY($sel
f)
Opcional. Perl llama automáticamente a este método en los objetos justo antes d
e que sean terminados. Esto le da a tu controlador la oportunidad de cerr
ar conexiones de base de datos o cerrar manejadores de archivos abiertos.
