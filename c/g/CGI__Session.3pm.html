CGI::Session(3) Documentación de Perl aportada por el usuario CGI::Session(3)

NOMBRE

CGI::Session - datos de sesión persistentes en aplicaciones CGI

SINOPSIS

# Inicialización del objeto:
use CGI::Session;
$session = CGI::Session->new();
$CGISESSID = $session->id();
# Enviar la cabecera HTTP adecuada con cookies:
print $session->header();
# Almacenar datos en la sesión:
$session->param('f_name', 'Sherzod');
# o
$session->param(-name=>'l_name', -value=>'Ruzmetov');
# Volcar los datos de la memoria al controlador de almacenamiento al menos antes de que tu
# programa termine, ya que el volcado automático puede ser poco fiable.
$session->flush();
# Recuperar datos:
my $f_name = $session->param('f_name');
# o
my $l_name = $session->param(-name=>'l_name');
# Borrar un determinado parámetro de sesión:
$session->clear(["l_name", "f_name"]);
# Expirar el indicador '_is_logged_in' después de 10 minutos de inactividad:
$session->expire('is_logged_in', '+10m')
# Expirar la propia sesión después de 1 hora de inactividad:
$session->expire('+1h');
# Eliminar la sesión para siempre:
$session->delete();
$session->flush(); # La práctica recomendada dice usar flush() después de delete().

DESCRIPCIÓN

CGI::Session proporciona un sistema de gestión de sesiones fácil, fiable y modular a través de peticiones HTTP.

MÉTODOS

A continuación se muestra una descripción general de todos los métodos disponibles accesibles a través del objeto CGI::Session.

new()

new( $sid )

new( $query )

new( $dsn, $query||$sid )

new( $dsn, $query||$sid, \%dsn_args )

new( $dsn, $query||$sid, \%dsn_args, \%session_params )

Constructor. Devuelve un nuevo objeto de sesión, o undef en caso de fallo. El mensaje de error es accesible a través de errstr() - método de clase. Si se llama sobre una sesión ya inicializada, volverá a inicializar la sesión basándose en el objeto ya configurado. Esto solo es útil después de una llamada a load().

Puede aceptar hasta tres argumentos, $dsn - Nombre de la Fuente de Datos, $query||$sid - objeto de consulta O una cadena que representa el id de sesión, y finalmente, \%dsn_args, argumentos usados por los componentes de $dsn .

Si se llama sin ningún argumento, $dsn por defecto es driver:file;serializer:default;id:md5, $query||$sid por defecto es "CGI->new()", y "\%dsn_args" por defecto es undef.

Si se llama con un solo argumento, se tratará ya sea como un objeto $query , o como $sid, dependiendo de su tipo. Si el argumento es una cadena, new() lo tratará como un id de sesión e intentará recuperar la sesión del almacén de datos. Si falla, creará un nuevo id de sesión, que será accesible a través del método id() . Si el argumento es un objeto, se llamarán a los métodos cookie() y param() sobre ese objeto para recuperar un $sid potencial y recuperarlo del almacén de datos. Si falla, new() creará un nuevo id de sesión, que será accesible a través del método id() . name() definirá el nombre del parámetro de consulta y/o el nombre de la cookie a solicitar, por defecto es CGISESSID.

Si se llama con dos argumentos, el primero se tratará como $dsn, y el segundo se tratará como $query o $sid o undef, dependiendo de su tipo. Algunos ejemplos de esta sintaxis son:

$s = CGI::Session->new("driver:mysql", undef);
$s = CGI::Session->new("driver:sqlite", $sid);
$s = CGI::Session->new("driver:db_file", $query);
$s = CGI::Session->new("serializer:storable;id:incr", $sid);
# etc...

Brevemente, new() devolverá un objeto de sesión inicializado con un id válido, mientras que load() puede devolver un objeto de sesión vacío con un id indefinido.

Se proporcionan pruebas (t/new_with_undef.t y t/load_with_undef.t) para aclarar el resultado de llamar a new() y load() con undef, o con un objeto CGI inicializado con un CGISESSID indefinido o falso.

Se recomienda encarecidamente ejecutar el antiguo 'make test TEST_FILES=t/new_with_undef.t TEST_VERBOSE=1' o el moderno 'prove -v t/new_with_undef.t', tanto para new*.t como para load*.t, y examinar la salida.

Se admiten los siguientes componentes de la fuente de datos:

  • driver - Controlador de CGI::Session. Los controladores disponibles son file, db_file, mysql y sqlite. Se aceptan controladores de terceros. Para las especificaciones del controlador, considere CGI::Session::Driver
  • serializer - Serializador a utilizar para codificar la estructura de datos antes de guardarla en el disco. Los serializadores disponibles son storable, freezethaw y default. El serializador por defecto usará Data::Dumper.
  • id - Generador de ID a usar cuando se crea una nueva sesión. El generador de ID disponible es md5

Por ejemplo, para que CGI::Session almacene sus datos usando DB_File y serialice los datos usando FreezeThaw:

$s = CGI::Session->new("driver:DB_File;serializer:FreezeThaw", undef);

Si se llama con tres argumentos, los dos primeros se tratarán como en el ejemplo anterior, y el tercer argumento será "\%dsn_args", que se pasará a los componentes de $dsn (es decir, los generadores de controlador, serializador e id) con fines de inicialización. Dado que todos los componentes de $dsn deben inicializarse a algún valor por defecto, este tercer argumento no debería ser necesario para que la mayoría de los controladores funcionen correctamente.

Si se llama con cuatro argumentos, los tres primeros coinciden con los ejemplos anteriores. El cuarto argumento debe ser una referencia a un hash con los parámetros que se utilizarán por el objeto CGI::Session. (ver \%session_params arriba)

name - Nombre a usar para el nombre del parámetro de cookie/consulta. Por defecto es CGISESSID. Esto puede ser alterado o accedido por el "name" accessor.

load()

load( $query||$sid )

load( $dsn, $query||$sid )

load( $dsn, $query, \%dsn_args )

load( $dsn, $query, \%dsn_args, \%session_params )

Acepta los mismos argumentos que new(), y también devuelve un nuevo objeto de sesión, o undef en caso de fallo. La diferencia es que new() puede crear una nueva sesión si detecta sesiones caducadas y no existentes, pero load() no lo hace.

load() es útil para detectar sesiones caducadas o no existentes sin forzar a la biblioteca a crear nuevas sesiones. Así que ahora puedes hacer algo como esto:

$s = CGI::Session->load() or die CGI::Session->errstr();
if ( $s->is_expired ) {
    print $s->header(),
        $cgi->start_html(),
        $cgi->p("Your session timed out! Refresh the screen to start new session!")
        $cgi->end_html();
    exit(0);
}
if ( $s->is_empty ) {
    $s = $s->new() or die $s->errstr;
}

Nota: Todas las sesiones caducadas están vacías, pero no todas las sesiones vacías están caducadas.

Se proporcionan pruebas (t/new_with_undef.t y t/load_with_undef.t) para aclarar el resultado de llamar a new() y load() con undef, o con un objeto CGI inicializado con un CGISESSID indefinido o falso.

id()

Devuelve el ID efectivo para una sesión. Dado que el ID efectivo y el ID reclamado pueden diferir, el ID de sesión válido siempre debe recuperarse usando este método.

param($name)

param(-name=>$name)

Usado en cualquiera de las sintaxis anteriores, devuelve un parámetro de sesión establecido en $name o undef si no existe. Si se llama en un método eliminado param() emitirá una advertencia pero el valor devuelto no está definido.

param($name, $value)

param(-name=>$name, -value=>$value)

Usado en cualquiera de las sintaxis anteriores, asigna un nuevo valor al parámetro $name , que luego puede recuperarse con la sintaxis param() previamente introducida. $value puede ser un escalar, una referencia a un array o una referencia a un hash.

Los intentos de establecer nombres de parámetros que comiencen con _SESSION_ generarán una advertencia y se devolverá undef.

param_hashref()

Obsoleto. Usa dataref() en su lugar.

dataref()

Devuelve una referencia a la tabla de datos de la sesión:

$params = $s->dataref();
$sid = $params->{_SESSION_ID};
$name= $params->{name};
# etc...

Útil para tener todos los datos de la sesión en una referencia a un hash, pero demasiado arriesgado para actualizar.

save_param()

save_param($query)

save_param($query, \@list)

Guarda los parámetros de la consulta en el objeto de sesión. En otras palabras, es lo mismo que llamar a param($name, $value) para cada parámetro de consulta devuelto por "$query->param()". El primer argumento, si está presente, debe ser un objeto CGI o cualquier objeto que pueda proporcionar el método param() . Si es undef, se establece por defecto en el valor de retorno de query(), que devuelve "CGI->new". Si el segundo argumento está presente y es una referencia a un array, solo se almacenarán en la sesión esos parámetros de consulta que se encuentren en el array. undef es un marcador de posición válido para cualquier argumento para forzar el comportamiento por defecto.

load_param()

load_param($query)

load_param($query, \@list)

Carga los parámetros de la sesión en un objeto de consulta. El primer argumento, si está presente, debe ser un objeto de consulta, o cualquier otro objeto que pueda proporcionar el método param() . Si el segundo argumento está presente y es una referencia a un array, solo se cargarán en el objeto de consulta los parámetros que se encuentren en ese array.

clear()

clear('field')

clear(\@list)

Elimina parámetros del objeto de sesión.

Sin parámetros, se eliminan todos los campos. Si se pasa un único parámetro o una referencia a un array, solo se eliminan los parámetros nombrados.

flush()

Sincroniza los datos en memoria con la copia serializada por el controlador. Llama a flush() si necesitas acceder a la sesión desde fuera del objeto de sesión actual. Deberías llamar a flush() en algún momento antes de que tu programa termine.

Como último recurso, CGI::Session llamará automáticamente a flush por ti justo antes de que el programa termine o de que el objeto de sesión salga del ámbito. Se ha demostrado que el vaciado automático no es fiable, y en algunos casos ahora es necesario en lugares que funcionaban con CGI::Session 3.x.

Se recomienda llamar siempre explícitamente a flush() en la sesión antes de que el programa termine. Para mayor seguridad, llámalo inmediatamente después de cada actualización importante de la sesión.

Ver también "A Warning about Auto-flushing"

atime()

Método de solo lectura. Devuelve el último tiempo de acceso de la sesión en segundos desde la época. Este tiempo se usa internamente al expirar automáticamente sesiones y/o parámetros de sesión.

ctime()

Método de solo lectura. Devuelve el tiempo en que la sesión fue creada por primera vez en segundos desde la época.

expire()

expire($time)

expire($param, $time)

Establece el intervalo de expiración relativo a atime().

Si se usa sin argumentos, devuelve el intervalo de expiración si alguna vez se estableció. Si nunca se estableció una expiración, devuelve undef. Por compatibilidad con versiones anteriores, un método llamado etime() hace lo mismo.

La segunda forma establece un tiempo de expiración. Este valor se comprueba cuando se solicita recuperar una sesión almacenada previamente, y si su intervalo de expiración ha pasado, será eliminada del disco inmediatamente. Pasar 0 cancela la expiración.

Usando la tercera sintaxis puedes establecer el intervalo de expiración para un parámetro de sesión en particular, digamos ~logged-in. Esto haría que la biblioteca llame a clear() en el parámetro cuando su tiempo haya pasado. Ten en cuenta que solo tiene sentido establecer este valor en algo anterior a cuando expire toda la sesión. Pasar 0 cancela la expiración.

Todos los valores de tiempo deben darse en forma de segundos. Las siguientes palabras clave también se admiten para tu comodidad:

+-----------+---------------+
|   alias   |   significado |
+-----------+---------------+
|     s     |   Segundo     |
|     m     |   Minuto      |
|     h     |   Hora        |
|     d     |   Día         |
|     w     |   Semana      |
|     M     |   Mes         |
|     y     |   Año         |
+-----------+---------------+

Ejemplos:

$session->expire("2h");                # expira en dos horas
$session->expire(0);                   # cancela la expiración
$session->expire("~logged-in", "10m"); # expira el parámetro '~logged-in' después de 10 minutos de inactividad

Nota: todos los tiempos de expiración son relativos al último tiempo de acceso de la sesión, no a su tiempo de creación. Para expirar una sesión inmediatamente, llama a delete(). Para expirar un parámetro de sesión específico inmediatamente, llama a clear([$name]).

is_new()

Devuelve true solo para una sesión completamente nueva.

is_expired()

Comprueba si la sesión inicializada usando load() debe expirar. Este método solo funciona en sesiones inicializadas con load():

$s = CGI::Session->load() or die CGI::Session->errstr;
if ( $s->is_expired ) {
    die "Your session expired. Please refresh";
}
if ( $s->is_empty ) {
    $s = $s->new() or die $s->errstr;
}

is_empty()

Devuelve true para sesiones que están vacías. Es la forma preferida de comprobar si la sesión solicitada se cargó correctamente o no:

$s = CGI::Session->load($sid);
if ( $s->is_empty ) {
    $s = $s->new();
}

En realidad, el código anterior no es más que un desperdicio. El mismo efecto podría haberse logrado diciendo:

$s = CGI::Session->new( $sid );

is_empty() es útil solo si quisieras capturar solicitudes de sesiones expiradas, y crear una nueva sesión después. Ver is_expired() para un ejemplo.

ip_match()

Devuelve true si $ENV{REMOTE_ADDR} coincide con la dirección remota almacenada en la sesión.

Si tienes una aplicación donde estés seguro de que las IP de tus usuarios son constantes durante una sesión, puedes considerar habilitar una opción para realizar esta comprobación:

use CGI::Session '-ip_match';

Normalmente no llamas a ip_match() directamente, sino usando el método anterior. Es útil solo si quieres llamarlo dentro de una referencia a código pasada al find() método.

delete()

Establece el estado del objeto como "eliminado". Las solicitudes de lectura/escritura posteriores en el mismo objeto fallarán. Para eliminarlo físicamente del almacén de datos necesitas llamar a flush(). CGI::Session intenta hacer esto automáticamente cuando el objeto está siendo destruido (generalmente cuando el script termina), pero ver "A Warning about Auto-flushing".

find( \&code )

find( $dsn, \&code )

find( $dsn, \&code, \%dsn_args )

Característica experimental. Ejecuta \&code para cada objeto de sesión almacenado en disco, pasando el objeto CGI::Session inicializado como el primer argumento de \&code. Útil para propósitos de mantenimiento, como para eliminar sesiones expiradas. La siguiente línea, por ejemplo, eliminará sesiones ya expiradas, pero que aún están en disco:

La siguiente línea, por ejemplo, eliminará sesiones ya expiradas, pero que aún están en disco:

CGI::Session->find( sub {} );

Observa que el \&code anterior no tenía que hacer nada, porque load(), que se llama para inicializar sesiones dentro de find(), eliminará automáticamente las sesiones expiradas. El siguiente ejemplo eliminará todos los objetos que tengan 10 o más días de antigüedad:

CGI::Session->find( \&purge );
sub purge {
    my ($session) = @_;
    next if $session->is_empty;    # <-- ¿ya expirada?!
    if ( ($session->ctime + 3600*240) <= time() ) {
        $session->delete();
        $session->flush(); # La práctica recomendada dice usar flush() después de delete().
    }
}

Usa: 
binmode STDIN, ":encoding(utf8)";.
Por supuesto, el
programa puede recibir entrada de otras fuentes, por
ejemplo, archivos de plantilla HTML, no solo STDIN.
Use: 
binmode STDOUT, ":encoding(utf8)";
When using CGI.pm, you can use $q->charset('UTF-8'). This is the same as passing 'UTF-8' to CGI's C<header()> method.
Alternately, when using CGI::Session, you can use $session->header(charset => 'utf-8'), which will be
passed to the query object's C<header()> method. Clearly this is preferable when the query object might not be
of type CGI.
See L</header()> for a fuller discussion of the use of the C<header()> method in conjunction with cookies.
