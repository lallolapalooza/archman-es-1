DESCRIPCIÓ

N

CGI::Fast es una subclase del objeto CGI creado por CGI.pm. Está especializada para funcionar con el módulo FCGI, que acelera enormemente los scripts CGI al convertirlos en procesos de servidor persistentes. Los scripts que realizan procesos de inicialización costosos en tiempo, como cargar grandes módulos o abrir conexiones persistentes a bases de datos, verán grandes mejoras de

rendimiento.

Ten en cuenta que, dado que CGI::Fast se basa en CGI.pm, ya no se recomienda como forma de escribir aplicaciones web en Perl. Consulta https://metacpan.org/pod/CGI#CGI.pm-HAS-BEEN-REMOVED-F

ROM-THE-PERL-CORE para
más información sobre esto

ESCRIBIENDO SCRIPTS PERL

FASTCGI

Los scripts FastCGI son persistentes: una o más copias del script se inician cuando el servidor se inicializa y permanecen hasta que el servidor se detiene o mueren de forma natural. Después de realizar la inicialización única que necesiten, el script entra en un bucle esperando conexiones entrantes, procesando la solicitud y esperando

más.

Un script FastCGI típico se verá

así: 
#!perl
use CGI::Fast;
do_some_initialization();
while ($q = CGI::Fast->new) {
    process_request($q);
}

Cada vez que hay una nueva solicitud, CGI::Fast devuelve un objeto CGI a tu bucle. El resto del tiempo tu script espera en la llamada a new(). Cuando el servidor solicita que tu script se termine, new() devolverá undef. Por supuesto, puedes salir antes si lo eliges. Se generará una nueva versión del script para reemplazarla (esto puede ser necesario para evitar fugas de memoria de Perl en scripts de larga duración)

.

El modo de objeto CGI por defecto de CGI.pm también funciona. Solo modifica el bucle de esta

manera: 
while (CGI::Fast->new) {
    process_request();
}

Las llamadas a header(), start_form(), etc. operarán toda

s sobre la s
olicitud actual.

INSTALANDO SCRIPTS

FASTCGI

Consulta la documentación del kit de desarrollo de FastCGI para detalles completos. En el servidor Apache, se debe añadir la siguiente línea a srm.

conf: 
AddType application/x-httpd-fcgi .
fcgi

Los scripts FastCGI deben terminar en la extensión .fcgi. Por cada script que instales, debes añadir algo como lo siguiente a srm.

conf: 
FastCgiServer /usr/etc/httpd/fcgi-bin/file_upload.fcgi -processes
2

Esto instruye a Apache para lanz

ar dos copias de file_upload.fc
gi en el momento del inicio.

INVOCACIÓN DE SERVIDOR FASTCGI

EXTERNO

FastCGI soporta un mecanismo de transporte TCP/IP que permite que los scripts FastCGI se ejecuten fuera del servidor web, quizás en una máquina remota. Para configurar el servidor web para que se conecte a un servidor FastCGI externo, añadirías lo siguiente a tu srm.

conf: 
FastCgiExternalServer /usr/etc/httpd/fcgi-bin/file_upload.fcgi -host sputnik:
8888

Dos variables de entorno afectan cómo se crea el objeto "CGI::Fast", permitiendo que "CGI::Fast" se use como un servidor FastCGI externo. (Consulta la documentación de "FCGI" para "FCGI::OpenSocket" para más información.

)

Puedes establecer estas como variables ENV o como importaciones en la sentencia use CGI::Fast. Si las variables ENV están establecidas, estas tendrán prioridad, por lo que puedes sobrescribir las sentencias de importación desde la línea de comandos,

etc.
FCGI_SOCKET_PATH /
socket_path
La dirección (TCP/IP) o la ruta (Dominio UNIX) del socket al que el script FastCGI externo debe enlazar y escuchar conexiones entrantes del servidor
web.
FCGI_SOCKET_PERM /
socket_perm
Permisos para el socket de Dominio
UNIX.
FCGI_LISTEN_QUEUE /
listen_queue
Longitud máxima de la c
ola de conexiones pendi
entes, por defecto 100.

Por

ejemplo: 
use CGI::Fast
    socket_path  => "sputnik:8888",
    listen_queue => "50"
;
use CGI qw/ :standard /;
do_some_initialization();
while ($q = CGI::Fast->new) {
    process_request($q);
}

O

: 
use CGI::Fast;
use CGI qw/ :standard /;
do_some_initialization();
$ENV{FCGI_SOCKET_PATH} = "sputnik:8888";
$ENV{FCGI_LISTEN_QUEUE} = 50;
while ($q = CGI::Fast->new) {
    process_request($q);
}

Ten en cuenta la importancia de tener use CGI después de use CGI::Fast, ya que esto evitará que cualquier pragma de importación de CGI sea sobrescrita por CGI::Fast. Puedes usar CGI::Fast como un reemplazo directo de esta

manera:

MANEJOS DE

ARCHIVOS

FCGI usa por defecto STDOUT y STDERR como sus manejadores de archivo de salida; esto puede llevar a una redirección inesperada de la salida si migras scripts de CGI.pm a CGI::Fast. Para evitar esto puedes usar el método file_handles, que debes hacer antes de la primera llamada a CGI::Fast->new. Por ejemplo, usando IO::

Handle: 
CGI::Fast->file_handles({
    fcgi_output_file_handle => IO::Handle->new,
    fcgi_error_file_handle  => IO::Handle->new,
});
while (CGI::Fast->new) {
    ..
}

Sobrescribir STDIN usando la clave "fcgi_input_file_handle" también es posible, sin embargo, h

acerlo probablemente romperá al
menos las solicitudes POST.
