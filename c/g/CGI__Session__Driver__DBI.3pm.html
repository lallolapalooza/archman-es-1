CGI::Session::Driver::DBI(3) Documentación de Perl contribuida por el usuario CGI::Session::Driver::DBI(3)

NOMBRE

CGI::Session::Driver::DBI - Clase base para controladores CGI::Session relacionados con DBI nativos

SINOPSIS

require CGI::Session::Driver::DBI;
@ISA = qw( CGI::Session::Driver::DBI );

DESCRIPCIÓN

En la mayoría de los casos, puedes crear un nuevo controlador CGI::Session impulsado por DBI simplemente creando un archivo de controlador vacío que hereda de CGI::Session::Driver::DBI. Eso es exactamente lo que hace sqlite. La única razón por la que esta clase no es adecuada como controlador válido es que su nombre no está en minúsculas. ¡Soy serio!

NOTAS

CGI::Session::Driver::DBI define el método init(), que pone el manejador DBI a disposición de los controladores en el atributo de objeto Handle independientemente de los argumentos \%dsn_args que se utilizaran al crear el objeto de sesión. Si su controlador requiere una inicialización no estándar, debe redefinir el método init() en su archivo .pm, pero asegúrese de establecer el atributo de objeto 'Handle' al manejador de base de datos (devuelto por DBI->connect(...)) si desea heredar alguno de los métodos de CGI::Session::Driver::DBI.

ALMACENAMIENTO

Antes de poder utilizar cualquier controlador de sesión basado en DBI, debe asegurarse de que se haya creado una tabla de base de datos compatible para que CGI::Session funcione. El siguiente comando producirá los requisitos mínimos en la mayoría de las bases de datos SQL:

CREATE TABLE sessions (
    id CHAR(32) NOT NULL PRIMARY KEY,
    a_session TEXT NOT NULL
);

Su tabla de sesiones puede definir columnas adicionales, pero las dos anteriores son obligatorias. El nombre de la tabla de sesiones se espera que sea sessions por defecto. Puede usar un nombre diferente si lo desea. Para hacerlo, debe pasar TableName como parte de sus argumentos \%dsn_args:

$s = CGI::Session->new('driver:sqlite', undef, {TableName=>'my_sessions'});
$s = CGI::Session->new('driver:mysql', undef,
{
    TableName=>'my_sessions',
    DataSource=>'dbi:mysql:shopping_cart'.
});

Para usar nombres de columna diferentes, cambie la declaración de 'create table' y luego simplemente haga esto:

$s = CGI::Session->new('driver:pg', undef,
{
    TableName=>'session',
    IdColName=>'my_id',
    DataColName=>'my_data',
    DataSource=>'dbi:pg:dbname=project',
});

o

$s = CGI::Session->new('driver:pg', undef,
{
    TableName=>'session',
    IdColName=>'my_id',
    DataColName=>'my_data',
    Handle=>$dbh,
});

ARGUMENTOS DEL CONTROLADOR

Se admiten los siguientes argumentos del controlador:

DataSource
Primer argumento que se pasará a DBI->connect(). Si el controlador establece la conexión a la base de datos por sí mismo, también se desconectará explícitamente de la base de datos cuando el objeto del controlador sea DESTROYed.
User
Usuario con privilegios para conectarse a la base de datos definida en DataSource.
Password
Contraseña del User con privilegios para conectarse a la base de datos definida en DataSource.
Handle
Un objeto de manejador de base de datos DBI existente. El manejador se puede crear bajo demanda proporcionando una referencia de subrutina como argumento, como <sub{DBI-"connect"}>. De esta manera, la conexión a la base de datos solo se crea si realmente se necesita. Esto puede ser útil cuando se combina con un complemento de framework como CGI::Application::Plugin::Session, que también crea un objeto CGI::Session bajo demanda.

Handle anulará todos los argumentos anteriores, si los hay.

TableName
Nombre de la tabla en la que se almacenarán los datos de la sesión.
