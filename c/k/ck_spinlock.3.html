DESCRIPCIÓ

N

Una familia de implementaciones de bloqueos de espera activa (spinlock). La implementación ck_spinlock_t es simplemente un envoltorio alrededor de la implementación de intercambio-y-obtener (ck_spinlock_fas_t). La tabla siguiente proporciona un resumen de las implementaciones

actuales. 
|            Espacio de nombres | Algoritmo                   | Tipo          | Restricciones            | Justo   |
´----------------------|-----------------------------|---------------|-------------------------|--------'
  ck_spinlock_anderson   Anderson                      Matriz        | Número fijo de hilos     | Sí
       ck_spinlock
_cas Comparar-e-Intercambiar Centralizado | Ninguna | No ck_spinlock_clh Craig, Landin y Hagersten Cola | Requisitos de vida útil | Sí ck_spinlock_dec Decremento (núcleo Linux) Centralizado | Concurrencia UINT_MAX | No ck_spinlock_fas Obtener-y-guardar Centr
alizado | Ninguna | No ck_spinlock_hclh CLH Jerárquico Cola | Requisitos de vida útil | Sí * ck_spinlock_mcs Mellor-Crummey y Scott Cola | Ninguna | Sí ck_spinlock_ticket Ticket Centralizado | Ninguna | Sí

* CLH Jerárquico solo ofrece justicia débil para los hilos a través de nodos de

clúster.

Si la contención es baja y no hay un requisito estricto de libertad de inanición, se recomienda un bloqueo centralizado codicioso (injusto). Si la contención es alta y no hay un requisito de libertad de inanición, se recomienda un bloqueo centralizado codicioso utilizado con un mecanismo de retroceso exponencial. Si la contención es generalmente baja y hay un requisito estricto de libertad de inanición, se recomienda el bloqueo de ticket. Si la contención es alta y hay un requisito estricto de libertad de inanición, se recomienda el bloqueo de cola de Craig, Landin y Hagersten, a menos que sea necesaria la asignación en la pila o el factor NUMA sea alto, en cuyo caso se recomienda el bloqueo de Mellor-Crummey y Scott. Si no puede permitirse el uso de espacio O(n) de los bloqueos de matriz o cola pero aún requiere justicia bajo alta contención, se recomienda el bloqueo de ticket con retroceso proporcional. Si el factor NUMA es alto pero prefiere un bloqueo codicioso, entonces consulte ck_coh

EJEMPL

O 
#include <ck_spinlock.h>
#include <stdbool.h>

/*
 * Alternativamente, el mutex puede inicializarse en tiempo de ejecución con
 * ck_spinlock_init(&mutex).
 */
ck_spinlock_t mutex = CK_SPINLOCK_INITIALIZER;

void
example(void)
{

        ck_spinlock_lock(&mutex);
        /*
         * Sección crítica.
         */
        ck_spinlock_unlock(&mutex);

        ck_spinlock_lock_eb(&mutex);
        /*
         * Sección crítica.
         */
        ck_spinlock_unlock(&mutex);

        if (ck_spinlock_trylock(&mutex) == true) {
                /*
                 * Sección crítica.
                 */
                ck_spinlock_unlock(&mutex);
}
}
