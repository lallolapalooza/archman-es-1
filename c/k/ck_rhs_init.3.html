Paquete: libck

Licencias: BSD, Apache, Custom

CK_RHS_INIT(3) Manual de Funciones de Librería CK_RHS_INIT(3)

NOMBRE

ck_rhs_init — inicializa un conjunto de hash

LIBRERÍA

Concurrency Kit (libck, -lck)

SINOPSIS

#include <ck_rhs.h>

typedef unsigned long
ck_rhs_hash_cb_t(const void *key, unsigned long seed);

typedef bool
ck_rhs_compare_cb_t(const void *c1, const void *c2);

bool
ck_rhs_init(ck_rhs_t *hs, unsigned int mode, ck_rhs_hash_cb_t *hash_function, ck_rhs_compare_cb_t *compare, struct ck_malloc *allocator, unsigned long capacity, unsigned long seed);

DESCRIPCIÓN

La función ck_rhs_init() inicializa el conjunto de hash al que apunta el puntero hs.

El argumento mode especifica el tipo de pares clave-valor que se almacenarán en el conjunto de hash, así como el modelo de acceso concurrente esperado. El valor de mode consiste en un campo de bits de uno de los siguientes:

CK_RHS_MODE_OBJECT
El conjunto de hash está destinado a almacenar punteros a objetos. Esto proporciona una pista de que solo se necesitan CK_MD_VMA_BITS para codificar el argumento clave. Cualquier bit de puntero no utilizado se aprovecha para optimizaciones internas.
CK_RHS_MODE_DIRECT
El conjunto de hash está destinado a almacenar directamente valores clave y que todos los bits de la clave se utilizan para codificar valores.
CK_RHS_MODE_READ_MOSTLY
Optimiza las operaciones de lectura sobre poner/eliminar.

El modelo de acceso concurrente se especifica mediante:

CK_RHS_MODE_SPMC
El conjunto de hash debe permitir lectores concurrentes en presencia de un único escritor.
CK_RHS_MODE_MPMC
El conjunto de hash debe permitir lectores concurrentes en presencia de escritores concurrentes. Esto actualmente no es compatible.

El desarrollador es libre de especificar indicaciones de carga de trabajo adicionales. Estas indicaciones son:

El argumento hash_function es un puntero obligatorio a una función hash especificada por el usuario. Una función hash especificada por el usuario toma dos argumentos. El argumento key es un puntero a una clave. El argumento seed es la semilla inicial asociada con el conjunto de hash. Esta semilla inicial es especificada por el usuario en ck_rhs_init(3).

El argumento compare es un puntero opcional a una función de comparación de claves especificada por el usuario. Si se especifica NULL en este argumento, se utilizará la igualdad de punteros para determinar la igualdad de claves. Una función de comparación especificada por el usuario toma dos argumentos que representan punteros a los objetos que se comparan por igualdad. Se espera que devuelva verdadero si las claves son de igual valor y falso en caso contrario.

El argumento allocator es un puntero a una estructura que contiene punteros a funciones malloc y free que definen respectivamente las funciones de asignación y destrucción de memoria que serán utilizadas por el conjunto de hash que se está inicializando.

El argumento capacity representa el número inicial de claves que se espera que contenga el conjunto de hash. Este argumento es simplemente una pista y la implementación subyacente es libre de asignar más o menos memoria de la necesaria para contener el número de entradas que especifica capacity.

El argumento seed especifica la semilla inicial utilizada por la función hash subyacente. El usuario es libre de elegir el valor de su elección.

VALORES DE RETORNO

Tras la finalización exitosa, ck_rhs_init() devuelve un valor de true y, en caso contrario, devuelve un valor de false para indicar un error.

ERRORES

El comportamiento de ck_rhs_init() no está definido si hs no es un puntero a un objeto ck_rhs_t.
