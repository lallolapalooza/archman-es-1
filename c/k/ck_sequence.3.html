ck_sequence(3) Manual de funciones de biblioteca ck_sequence(3)

NOMBRE

ck_sequence_init, ck_sequence_read_begin, ck_sequence_read_retry, ck_sequence_write_begin, ck_sequence_write_end — bloqueos de secuencia

BIBLIOTECA

Concurrency Kit (libck, -lck)

SINOPSIS

#include <ck_sequence.h>

ck_sequence_t seqlock = CK_SEQUENCE_INITIALIZER;


void
ck_sequence_init(ck_sequence_t *sq);

unsigned int
ck_sequence_read_begin(const ck_sequence_t *sq);

bool
ck_sequence_read_retry(const ck_sequence_t *sq, unsigned int version);

void
ck_sequence_write_begin(ck_sequence_t *sq);

void
ck_sequence_write_end(ck_sequence_t *sq);

DESCRIPCIÓN

Se recomienda usar ck_sequence cuando una pequeña cantidad de datos que no se puede acceder atómicamente debe sincronizarse con los lectores de una manera que no bloquee a ningún escritor. Los lectores pueden ejecutar sus secciones críticas del lado de lectura sin ninguna operación atómica. Un ck_sequence_t debe inicializarse antes de su uso. Puede inicializarse utilizando un inicializador estático (CK_SEQUENCE_INITIALIZER) o mediante ck_sequence_init(). Antes de que los lectores intenten leer datos que puedan ser modificados concurrentemente, primero deben guardar el valor de retorno de ck_sequence_read_begin(). Mientras o después de que un lector haya completado la copia de los datos asociados con un ck_sequence_t, debe pasar el valor de retorno anterior de ck_sequence_read_begin() a ck_sequence_read_retry(). Si ck_sequence_read_retry() devuelve verdadero, entonces la copia de los datos puede ser inconsistente y el proceso de lectura debe repetirse. Los escritores deben confiar en sus propios primitivos de sincronización. Una vez que un escritor ha entrado en su respectiva sección crítica, debe llamar a ck_sequence_write_begin() para señalar la intención de actualizar los datos protegidos por el ck_sequence_t. Antes de que el escritor salga de su sección crítica, debe ejecutar ck_sequence_write_end() para indicar que las actualizaciones han dejado los objetos respectivos en un estado consistente.

EJEMPLO

#include <ck_sequence.h>
#include <stdlib.h>

static struct example {
	int a;
	int b;
	int c;
} global;

static ck_sequence_t seqlock = CK_SEQUENCE_INITIALIZER;

void
reader(void)
{
	struct example copy;
	unsigned int version;

	/*
	 * Intenta leer la estructura de datos. Si la estructura
	 * ha sido modificada entre ck_sequence_read_begin y
	 * ck_sequence_read_retry, entonces intenta otra lectura ya
	 * que los datos pueden estar en un estado inconsistente.
	 */
	do {
		version = ck_sequence_read_begin(&seqlock);
		copy = global;
	} while (ck_sequence_read_retry(&seqlock, version));

	/*
	 * Lo anterior también puede expresarse usando CK_SEQUENCE_READ.
	 * Generalmente se recomienda usar solo ck_sequence_read_retry
	 * si deseas detectar una escritura conflictiva en alguna
	 * granularidad superior.
	 */
	CK_SEQUENCE_READ(&seqlock, &version) {
		copy = global;
	}

	return;
}

void
writer(void)
{

	for (;;) {
		ck_sequence_write_begin(&seqlock);
		global.a = rand();
		global.b = global.a + global.b;
		global.c = global.b + global.c;
		ck_sequence_write_end(&seqlock);
	}

	return;
}
