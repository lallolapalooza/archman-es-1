DESCRIPCIÓ

N

Estas macros implementan envoltorios de elisión de bloqueo para una interfaz de bloqueo de un solo argumento especificada por el usuario. Los envoltorios intentarán elidir la adquisición del bloqueo, permitiendo la ejecución concurrente de secciones críticas que no emiten operaciones de memoria conflictivas. Si algún hilo ha elidido con éxito la adquisición de un bloqueo, las operaciones de memoria conflictivas revertirán cualquier efecto secundario de la sección crítica y forzarán a todos los hilos a reintentar la adquisición del bloqueo

periódicamente.

CK_ELIDE_LOCK(), CK_ELIDE_UNLOCK(), CK_ELIDE_LOCK_ADAPTIVE(), y las macros CK_ELIDE_UNLOCK_ADAPTIVE() requieren un CK_ELIDE_PROTOTYPE() previo con el mismo NAME. Se intenta la elisión si la función LOCK_PREDICATE devuelve false. Si LOCK_PREDICATE devuelve true, entonces la elisión se aborta y LOCK_FUNCTION se ejecuta en su lugar. Si algún hilo está en una sección crítica elidida, LOCK_FUNCTION debe forzar su reversión a través de una operación de memoria conflictiva. La función UNLOCK_PREDICATE debe devolver true si el bloqueo es adquirido por el llamador, lo que significa que el bloqueo no fue elidido con éxito. Si UNLOCK_PREDICATE devuelve true, entonces UNLOCK_FUNCTION se ejecuta. Si RTM no es compatible (no hay macro CK_F_PR_RTM), entonces CK_ELIDE_LOCK() y CK_ELIDE_LOCK_ADAPTIVE() llamarán inmediatamente a LOCK_FUNCTION(). CK_ELIDE_UNLOCK() y CK_ELIDE_UNLOCK_ADAPTIVE() llamarán inmediatamente a UNLOCK_FUNCT

ION().

CK_ELIDE_TRYLOCK() requiere un CK_ELIDE_TRYLOCK_PROTOTYPE() previo con el mismo nombre. Se intenta la elisión si la función LOCK_PREDICATE devuelve false. Si LOCK_PREDICATE devuelve true o si la elisión falla, entonces la operación se aborta. Si RTM no es compatible (no hay macro CK_F_PR_RTM), entonces CK_ELIDE_TRYLOCK() llamará inmediatamente a TRYLOCK_FUNCT

ION().

CK_ELIDE_LOCK_ADAPTIVE() y CK_ELIDE_UNLOCK_ADAPTIVE() adaptarán el comportamiento de elisión asociado con las operaciones de bloqueo de acuerdo con el comportamiento en tiempo de ejecución del programa. Este comportamiento está definido por el puntero a la estructura ck_elide_config pasado a CK_ELIDE_LOCK_ADAPTIVE(). Se debe pasar una estructura ck_elide_stat local a hilo tanto a CK_ELIDE_LOCK_ADAPTIVE() como a CK_ELIDE_UNLOCK_ADAPTIVE(). Se espera que esta estructura sea única para diferentes cargas de trabajo, no puede reutilizarse en adquisiciones recursivas y debe coincidir con el tiempo de vida del bloqueo con el que está asociada. Es seguro mezclar llamadas adaptativas con llamadas de mejor

esfuerzo.

Tanto ck_spinlock.h como ck_rwlock.h definen envoltorios ck_elide bajo los espacios de nombres ck_spinlock y ck_rwlock,

respectivamente
.

EJEMPLO

S

Este ejemplo utiliza las instalaciones integradas de elisión de bloqueo en ck_rwlock y

ck_spinlock. 
#include <ck_rwlock.h>
#include <ck_spinlock.h>

static ck_rwlock_t rw = CK_RWLOCK_INITIALIZER;
static struct ck_elide_config rw_config =
    CK_ELIDE_CONFIG_DEFAULT_INITIALIZER;
static __thread ck_elide_stat_t rw_stat =
    CK_ELIDE_STAT_INITIALIZER;

static ck_spinlock_t spinlock = CK_SPINLOCK_INITIALIZER;
static struct ck_elide_config spinlock_config =
    CK_ELIDE_CONFIG_DEFAULT_INITIALIZER;
static __thread ck_elide_stat_t spinlock_stat =
    CK_ELIDE_STAT_INITIALIZER;

void
function(void)
{

	/* Bloquear-desbloquear el bloqueo del lado de escritura de manera débil y de mejor esfuerzo. */
	CK_ELIDE_LOCK(ck_rwlock_write, &rw);
	CK_ELIDE_UNLOCK(ck_rwlock_write, &rw);

	/* Intentar adquirir el bloqueo del lado de escritura. */
	if (CK_ELIDE_TRYLOCK(ck_rwlock_write, &rw) == true)
		CK_ELIDE_UNLOCK(ck_rwlock_write, &rw);

	/* Bloquear-desbloquear el bloqueo del lado de lectura de manera débil y de mejor esfuerzo. */
	CK_ELIDE_LOCK(ck_rwlock_read, &rw);
	CK_ELIDE_UNLOCK(ck_rwlock_read, &rw);

	/* Intentar adquirir el bloqueo del lado de lectura. */
	if (CK_ELIDE_TRYLOCK(ck_rwlock_read, &rw) == true)
		CK_ELIDE_UNLOCK(ck_rwlock_read, &rw);

	/* Bloquear-desbloquear el bloqueo del lado de escritura de manera adaptativa. */
	CK_ELIDE_LOCK_ADAPTIVE(ck_rwlock_write, &rw_stat,
	    &rw_config, &rw);
	CK_ELIDE_UNLOCK_ADAPTIVE(ck_rwlock_write, &rw_stat,
	    &rw_config, &rw);

	/* Bloquear-desbloquear el bloqueo del lado de lectura de manera adaptativa. */
	CK_ELIDE_LOCK_ADAPTIVE(ck_rwlock_read, &rw_stat,
	    &rw_config, &rw);
	CK_ELIDE_UNLOCK_ADAPTIVE(ck_rwlock_read, &rw_stat,
	    &rw_config, &rw);

	/* Bloquear-desbloquear el spinlock de manera débil y de mejor esfuerzo. */
	CK_ELIDE_LOCK(ck_spinlock, &spinlock);
	CK_ELIDE_UNLOCK(ck_spinlock, &spinlock);

	/* Intentar adquirir el bloqueo. */
	if (CK_ELIDE_TRYLOCK(ck_spinlock, &lock) == true)
		CK_ELIDE_UNLOCK(ck_spinlock, &spinlock);

	/* Bloquear-desbloquear el spinlock de manera adaptativa. */
	CK_ELIDE_LOCK_ADAPTIVE(ck_spinlock, &spinlock_stat,
	    &spinlock_config, &spinlock);
	CK_ELIDE_UNLOCK_ADAPTIVE(ck_spinlock, &spinlock_stat,
	    &spinlock_config, &spinlock);
}

En este ejemplo, a las funciones de bloqueo definidas por el usuario se les proporciona una implementación de elisión.

/* Asuma que lock_t ha sido definido previamente. */
#include <ck_elide.h>

/*
 * Esta función devuelve verdadero si el bloqueo no está disponible en el momento
 * en que fue llamada o falso si el bloqueo está disponible.
 */
bool is_locked(lock_t *);

/*
 * Esta función adquiere el bloqueo suministrado.
 */
void lock(lock_t *);

/*
 * Esta función libera el bloqueo.
 */
void unlock(lock_t *);

CK_ELIDE_PROTOTYPE(my_lock, lock_t, is_locked, lock, is_locked, unlock)

static lock_t lock;

void
function(void)
{

	CK_ELIDE_LOCK(my_lock, &lock);
	CK_ELIDE_UNLOCK(my_lock, &lock);
}
