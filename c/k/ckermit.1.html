KERMIT(1) Manual de Comandos Generales KERMIT(1)

NOMBRE

kermit - C‐Kermit 9.0: software de comunicaciones interactivo y scriptable independiente de transporte y plataforma.

Este documento está destinado a proporcionar al principiante la información suficiente para hacer un uso básico (si no avanzado) de C‐Kermit 9.0. Aunque puede ser bastante largo para una página de manual de Unix, sigue siendo mucho más corto que el manual de C‐Kermit, al cual se debe consultar para temas avanzados como personalización, conjuntos de caracteres, scripting, etc. También intentamos proporcionar una descripción estructural clara de las muchas capacidades, áreas funcionales, estados y modos de C‐Kermit y su interrelación, que debería ser útil tanto para principiantes como para veteranos, así como para aquellos que actualizan a la versión 9.0 desde versiones anteriores.

Este documento también está disponible como página web en:

http://www.columbia.edu/kermit/ckututor.html

DESCRIPCIÓN

C‐Kermit es un paquete de software de comunicaciones de propósito general del Proyecto Kermit en la Universidad de Columbia que:

•	Es portable a muchas plataformas, tanto Unix como no Unix.
•	Puede establecer conexiones tanto seriales como de red.
•	Puede realizar sesiones de terminal interactivas a través de su conexión.
•	Puede transferir archivos de texto o binarios a través de la misma conexión.
•	Puede convertir conjuntos de caracteres en la sesión de terminal.
•	Puede convertir conjuntos de caracteres durante la transferencia de archivos de texto.
•	Es personalizable en cada aspecto de su operación.

C‐Kermit es un programa de módem, un cliente Telnet, un cliente Rlogin, un cliente FTP, un cliente HTTP y, en plataformas seleccionadas, también un cliente X.25. Puede establecer sus propias conexiones seguras a Internet usando métodos de seguridad aprobados por la IETF, incluyendo Kerberos IV, Kerberos V, SSL/TLS y SRP, y también puede establecer conexiones SSH a través de su aplicación cliente SSH externa. Puede ser el socio de transferencia de archivos o cliente/servidor de extremo lejano de su cliente Kermit de escritorio. También puede aceptar conexiones entrantes por marcado y de red. Incluso puede instalarse como un servicio de Internet en su propio socket TCP estándar, 1649 [RFC2839, RFC2840].

Y quizás lo más importante, todo lo que puedes hacer "a mano" (interactivamente) con C‐Kermit, puede ser "scripteado" (automatizado) usando su lenguaje de programación de scripts incorporado, independiente de plataforma y transporte, que resulta ser idéntico a su lenguaje de comandos interactivo.

Esta página de manual ofrece una visión general de C‐Kermit 9.0 para Unix ("Unix" es una familia de sistemas operativos que incluye AIX, DG/UX, FreeBSD, HP‐UX, IRIX, Linux, Mac OS X, NetBSD, OpenBSD, Open Server, Open Unix, QNX, Solaris, SunOS, System V R3, System V R4, Tru64 Unix, Unixware, Xenix, y muchos otros). Para una cobertura exhaustiva, por favor consulta el manual publicado de C‐Kermit y sus suplementos (ver DOCUMENTACIÓN más abajo). Para más información sobre C‐Kermit, software Kermit para otras plataformas y manuales Kermit, visita el sitio web del Proyecto Kermit:


http://www.columbia.edu/kermit/

Esta es una página de manual más larga que el promedio, y aun así apenas araña la superficie. No te desanimes. C‐Kermit es un paquete grande y complejo, que ha evolucionado a lo largo de décadas de práctica y experiencia, pero eso no significa que sea difícil de aprender o usar. Sus funciones más comúnmente usadas se explican aquí con referencias a información adicional en otros lugares.

SINOPSIS

kermit [ nombre_de_archivo ] [ opciones ] [ {=,--,+} texto ] ]

o:

kermit URL

Si el primer argumento de la línea de comandos es el nombre de un archivo, se ejecutan comandos en modo interactivo desde el archivo. El argumento '=' (o "--") le dice a Kermit que no analice el resto de la línea de comandos, sino que haga disponibles las palabras que siguen a '=' como \%1, \%2, ... \%9. El argumento "+" es como "=" pero para uso en "scripts kerbang" (explicados más abajo). Un segundo formato de línea de comandos permite que el único argumento sea una URL de Telnet, FTP, HTTP o IKSD.

Orden de ejecución:


1.
El archivo de comandos (si existe).

2.
El archivo de inicialización, si existe, a menos que se suprima con -Y.

3.
El archivo de personalización (si es ejecutado por el archivo de inicialización).

4.
La URL de la línea de comandos (si existe, y de ser así, la ejecución se detiene aquí).

5.
Opciones de la línea de comandos (si existen).

6.
Comandos interactivos.

Algunas opciones de la línea de comandos pueden causar acciones (como -s para enviar un archivo); otras solo establecen parámetros. Si se incluyen opciones de acción en la línea de comandos, Kermit sale al terminar a menos que también se le dé la opción -S ("stay" / permanecer). Si no se dan opciones de acción, ningún archivo de inicialización o de comandos contenía un comando EXIT o QUIT, y no ocurrieron errores fatales, Kermit emite su prompt y espera que escribas comandos.

Ten en cuenta que C‐Kermit puede ser compilado con características seleccionadas deshabilitadas, y también que ciertas características no están disponibles en todas las plataformas. Por ejemplo, C‐Kermit no puede compilarse con soporte TCP/IP en una plataforma que no tenga archivos de cabecera y bibliotecas TCP/IP (e incluso si Kermit incluye soporte TCP/IP, no puede usarse para establecer conexiones TCP/IP en una computadora que no tenga instalado un stack TCP/IP). Si tu versión de C‐Kermit carece de una característica mencionada aquí, usa su comando SHOW FEATURES para ver qué podría haber sido excluido.

C‐Kermit tiene tres tipos de comandos: opciones de línea de comandos regulares de una sola letra, opciones de línea de comandos de formato extendido, y comandos interactivos.

Como la mayoría de los comandos Unix, a C‐Kermit se le pueden dar opciones en la línea de comandos. Pero C‐Kermit también puede usarse interactivamente dándole comandos compuestos por palabras, que son más intuitivos que las crípticas opciones de la línea de comandos, y más flexibles también. En otras palabras, no tienes que usar las opciones de la línea de comandos de C‐Kermit, pero están disponibles si quieres. (Por la misma razón, tampoco tienes que usar sus comandos interactivos ‐‐ puedes usar cualquiera de los dos o ambos en cualquier combinación.)

C‐Kermit generalmente se instala en el PATH como "kermit", y por lo tanto se invoca escribiendo la palabra "kermit" (en minúsculas) en el prompt del shell, y luego presionando la tecla Return o Enter. Si deseas incluir opciones de la línea de comandos, ponlas después de la palabra "kermit" pero antes de presionar Return o Enter, separadas por espacios, por ejemplo:


$ kermit -s ckermit.tar.gz

('$' es el prompt del shell; "kermit -s ckermit.tar.gz" es lo que escribes, seguido de Return o Enter.)

OPCIONES

Aquí hay una lista de las opciones de línea de comandos de una sola letra de C‐Kermit, que comienzan con un guion simple (-), en orden ASCII ("alfabético"). El caso alfabético es significativo (-A no es lo mismo que -a). Las opciones de acción están etiquetadas como "ACCIÓN".

-0
(dígito cero) Estado de Conexión 100% transparente para operación "en medio": 8 bits, sin paridad, sin carácter de escape, todo pasa a través.
-8
(dígito ocho) La conexión es de 8 bits limpia (esto es el valor por defecto en C‐Kermit 8.0 y posteriores). Equivalente al comando EIGHTBIT, que a su vez es un atajo para SET TERMINAL BYTESIZE 8, SET COMMAND BYTESIZE 8, SET PARITY NONE.
-9 arg
(dígito nueve) Establece una conexión a un servidor FTP. Equivalente al comando FTP OPEN. Argumento: dirección‐IP‐o‐nombre‐de‐host[:puerto‐TCP‐opcional]. NOTA: C‐Kermit también tiene una personalidad de línea de comandos FTP separada, con sintaxis de línea de comandos regular similar a FTP. Más sobre esto más abajo.
-A
Kermit debe iniciarse como un servicio de Internet (IKSD) (solo desde inetd.conf).
-B
Kermit se está ejecutando en Lote o en Segundo Plano (sin terminal de control). Para usarse en caso de que Kermit no detecte automáticamente su estado en segundo plano. Equivalente a el comando SET BACKGROUND ON.
-C arg
Comandos a ejecutar en modo interactivo. Argumento: Comandos separados por comas, listados entre comillas dobles.
-D arg
Retraso antes de comenzar a enviar en modo remoto. Equivalente al comando SET DELAY . Argumento: Número de segundos.
-E
Salir automáticamente cuando la conexión se cierre. Equivalente a SET EXIT ON-DISCONNECT ON.
-F arg
Usar una conexión TCP abierta. Argumento: Descriptor de archivo numérico de una conexión TCP abierta. Ver también: -j, -J.
-G arg
(ACCIÓN) Obtener archivo(s) del servidor, enviar el contenido a la salida estándar, que normalmente se redirigiría a otro proceso. Argumento: Especificación de archivo remoto, entre comillas si contiene metacaracteres. Ver también: -g, -k.
-H
Suprimir el Herald de inicio del programa y el saludo.
-I
Indicar a Kermit que tiene una conexión confiable, para forzar el uso del streaming donde normalmente no se usaría. Equivalente al comando SET RELIABLE ON .
-J arg
(ACCIÓN) "Ser como Telnet". Como -j pero implica -E. Argumento: Nombre de host/dirección IP opcionalmente seguido de servicio. NOTA: C‐Kermit también tiene una personalidad de línea de comandos Telnet separada, con una sintaxis de línea de comandos regular similar a Telnet. Más sobre esto más abajo.
-L
Descenso recursivo de directorios para archivos en la opción -s.
-M arg
Mi nombre de usuario (para usar con Telnet, Rlogin, FTP, etc). Equivalente al comando SET LOGIN USER. Argumento: Cadena de nombre de usuario.
-O
(ACCIÓN) (Letra O mayúscula) Ser un servidor por Un solo comando. Ver también: -x.
-P
No convertir los nombres (Ruta) de archivo de los archivos transferidos. Equivalente a SET FILE NAMES LITERAL.
-Q
Configuración rápida del protocolo Kermit. Equivalente al comando FAST. Esta es la configuración predeterminada en C‐Kermit 7.0 y versiones posteriores.
-R
Solo remoto (esto solo hace que IF REMOTE sea verdadero).
-S
Permanecer (entrar en el analizador de comandos después de las opciones de acción).
-T
Forzar el modo Texto para la transferencia de archivos; implica -V. Equivalente a SET TRANSFER MODE MANUAL, SET FILE TYPE TEXT.
-V
Desactivar el cambio automático de texto/binario por archivo. Equivalente a SET TRANSFER MODE MANUAL.
-Y
Omitir (no ejecutar) el archivo de inicialización.
-a arg
Nombre como (As‐name) para archivo(s) en -s, -r o -g. Argumento: Cadena de nombre como (nombre de archivo alternativo). Al recibir archivos, esto puede ser un nombre de directorio.
-b arg
Velocidad para el dispositivo serie. Equivalente a SET SPEED. Argumento: Bits numéricos por segundo para conexiones serie.
-c
(ACCIÓN) Entrar en el estado de Conexión antes de transferir archivos.
-d
Crear un archivo debug.log con información de depuración detallada (un segundo -d agrega marcas de tiempo). Equivalente a LOG DEBUG pero surte efecto antes.
-e arg
Longitud máxima para los paquetes de transferencia de archivos Kermit entrantes. Equivalente a SET RECEIVE PACKET-LENGTH. Argumento: Longitud en bytes.
-f
(ACCIÓN) Enviar un comando FINISH a un servidor Kermit.
-g arg
Obtener archivo(s) de un servidor Kermit. Argumento: Especificación de archivo en la otra computadora, entre comillas si contiene metacaracteres. Equivalente a GET. Ver también: -a, -G, -r.
-h
(ACCIÓN) Imprimir el texto de Ayuda para las opciones de línea de comandos de una sola letra (redirigir a través de 'more' para evitar el desplazamiento).
-i
Forzar el modo binario (Imagen) para la transferencia de archivos; implica -V. Equivalente a SET TRANSFER MODE MANUAL, SET FILE TYPE BINARY.
-j arg
Establecer una conexión TCP/IP. Argumento: Nombre de host/dirección IP y nombre de servicio o número opcional. Equivalente al comando TELNET. Ver también: -J, -F.
-k
(ACCIÓN) Recibir archivo(s) a la salida estándar, que normalmente se redirigiría a otro proceso. Ver también: -r, -G.
-l arg
(Letra L minúscula) Establecer una conexión en el dispositivo de comunicación serie dado. Equivalente al comando SET LINE (SET PORT). Argumento: Nombre del dispositivo serie, p. ej. /dev/ttyS0.
-m arg
Tipo de módem para usar con el dispositivo -l. Equivalente al comando SET MODEM TYPE . Argumento: Nombre del módem como en el comando SET MODEM TYPE, p. ej. "usrobotics".
-n
(ACCIÓN) Entrar en el estado de Conexión después de transferir archivos (histórico).
-p arg
Paridad. Equivalente al comando SET PARITY. Argumento: Uno de los siguientes: e(ven), o(dd), m(ark), n(one), s(pace).
-q
Silencioso (suprime la mayoría de los mensajes). Equivalente a SET QUIET ON.
-r
(ACCIÓN) Recibir archivo(s). Equivalente al comando RECEIVE. Argumento: (ninguno, pero ver -a)
-s arg
Enviar archivo(s). Argumento: Una o más especificaciones de archivo locales. Equivalente al comando SEND. Ver también: -a.
-t
(Histórico) Xon (Ctrl-Q) Carácter de retorno de línea para conexiones dúplex parcial (usado en conexiones serie linemode con mainframes antiguos). Equivalente a SET DUPLEX HALF, SET HANDSHAKE XON.
-v arg
Tamaño de ventana para el protocolo Kermit (ignorado cuando se usa streaming). Equivalente a SET WINDOW-SIZE. Argumento: Número, 1 a 32.
-w
Los archivos entrantes Sobrescriben los archivos existentes. Equivalente a SET FILE COLLISION OVERWRITE.
-x
(ACCIÓN) Entrar en modo servidor. Equivalente al comando SERVER. Ver también: -O.
-y arg
Archivo de inicialización alternativo. Argumento: Nombre de archivo.
-z
Forzar el comportamiento en primer plano. Para usar en caso de que Kermit no detecte automáticamente su estado en primer plano. Equivalente al comando SET BACKGROUND OFF .

Opciones de línea de comandos extendidas (necesarias porque las de una sola letra están casi agotadas) comienzan con dos guiones (--), con palabras en lugar de letras simples como nombres de opción. Si una opción extendida toma un argumento, este se separa de la palabra de opción por dos puntos (:). Las opciones extendidas incluyen:


--bannerfile:filename
Archivo a mostrar al inicio o al iniciar sesión en IKSD.

--cdfile:filename
Archivo a enviar para mostrar al cliente cuando el servidor cambia de directorio (el nombre de archivo es relativo al directorio al que se cambia).

--cdmessage:{on,off}
Habilitar/deshabilitar la función de mensaje CD del servidor.

--help
Imprime el mensaje de uso para las opciones extendidas.

--helpfile:filename
Designa un archivo que contiene texto personalizado para reemplazar el comando HELP de nivel superior.

--nointerrupts
Desactiva las interrupciones del teclado.

--noperms
Desactiva el atributo de Permisos de archivo del protocolo Kermit, para evitar la transmisión de los permisos de archivo (protección) del emisor al receptor.

--version
(ACCIÓN) C‐Kermit imprime su número de versión.

Además de varias otras opciones exclusivas de IKSD descritas en:


http://www.columbia.edu/kermit/iksd.html

Consulte la sección de transferencia de archivos para ejemplos de invocación de la línea de comandos.

LENGUAJE DE COMANDOS

El lenguaje de comandos interactivo de C‐Kermit es el tema de un libro de 622 páginas y otras varias cientos de páginas de actualizaciones, demasiado para una página de manual. Pero no es difícil empezar. En el símbolo del sistema, simplemente escriba "kermit" para obtener el símbolo de comandos interactivo de C‐Kermit:

  $ kermit
  (/current/directory) C-Kermit>

Comience escribiendo "help" (y luego presione la tecla Intro o Enter) para obtener una visión general de nivel superior, léalas y continúe desde ahí. Su segundo comando probablemente debería ser "intro" (introducción). Note que el símbolo muestra su directorio actual (a menos que le indique a Kermit que le pregunte con algo diferente).

Los comandos interactivos se componen principalmente de palabras en inglés normales, generalmente en forma de oraciones imperativas, como:


send oofa.txt

que le indica a Kermit que envíe (transfiera) el archivo cuyo nombre es oofa.txt, o:


set transfer mode automatic

que establece el "modo de transferencia" de Kermit en "automático" (lo que eso signifique).

Mientras escribe comandos, puede abreviar, pedir ayuda (presionando la tecla "?" en cualquier lugar de un comando), completar palabras clave o nombres de archivo (con las teclas Tab o Esc), y editar su escritura con Retroceso o Suprimir, Ctrl-W, Ctrl-U, etc. También puede recuperar comandos anteriores, guardar su historial de comandos, y quién sabe qué más. Use el comando INTRO para detalles.

C‐Kermit tiene cientos de comandos, y pueden emitirse en una infinidad de variedades y combinaciones, incluyendo comandos para:

•	Establecer conexiones (SET LINE, DIAL, TELNET, SSH, FTP, ...)
•	Romper conexiones (HANGUP, CLOSE)
•	Transfarchivos de transferencia (SEND, GET, RECEIVE, MOVE, RESEND, ...)
•	Establecer preferencias (SET)
•	Mostrar preferencias (SHOW)
•	Gestionar archivos locales (CD, DELETE, MKDIR, DIR, RENAME, TYPE, ...)
•	Gestionar archivos remotos (RCD, RDEL, RMKDIR, RDIR, ...)
•	Usar archivos locales (FOPEN, FCLOSE, FREAD, FWRITE)
•	Programación (TAKE, DEFINE, IF, FOR, WHILE, SWITCH, DECLARE, ...)
•	Interactuar con el usuario (ECHO, ASK, ...)
•	Interactuar con un ordenador remoto (INPUT, OUTPUT, ...)
•	Interactuar con programas locales (RUN, EXEC, PTY, ...)
•	Registrar cosas (LOG SESSION, LOG PACKETS, LOG DEBUG, ...)
Y por supuesto QUIT o EXIT para salir y HELP para obtener ayuda, y para los programadores: bucles, toma de decisiones, variables, matrices, matrices asociativas, aritmética de enteros y de punto flotante, macros, funciones integradas y definidas por el usuario, manipulación de cadenas, coincidencia de patrones, estructura de bloques, ámbito, recursión, y todo lo demás. Para obtener una lista de todos los comandos de C‐Kermit, escriba un signo de interrogación (?) en el símbolo del sistema. Para obtener una descripción de cualquier comando, escriba HELP seguido del nombre del comando, por ejemplo:


help send

El carácter de interrupción de comandos es Ctrl-C (mantenga presionada la tecla Ctrl y presione la tecla C).

El "carácter de escape" del lenguaje de comandos, utilizado para introducir nombres de variables, invocaciones de funciones, etc., es la barra invertida (. Si necesita incluir una barra invertida literal en un comando, escriba dos de ellas, p. ej.:


get c:\k95\k95custom.ini

Comando Archivos, Macros y Scripts

Un archivo que contiene comandos de Kermit se denomina archivo de comandos de Kermit o script de Kermit. Se puede ejecutar con el comando TAKE de Kermit:


(/current/dir) C-Kermit> take commandfile

(donde "commandfile" es el nombre del archivo de comandos). Por favor, no conecte un archivo de comandos a la entrada estándar de Kermit (lo cual podría funcionar o no); si tiene comandos de Kermit en un archivo, indique a Kermit que ejecute (TAKE) el archivo.

Solo en Unix, un archivo de comandos de Kermit también se puede ejecutar directamente incluyendo una línea "kerbang" como la primera línea del archivo:


#!/usr/local/bin/kermit +

Es decir, una línea superior que comienza con "#!", seguida inmediatamente por la ruta completa del ejecutable de Kermit y luego, si el script de Kermit va a recibir argumentos en la línea de comandos, un espacio y un signo más. El archivo de script también debe tener permiso de ejecución:


chmod +x commandfile

Excepto por la parte " +", esto es exactamente lo mismo que haría para un script de shell, un script de Perl, etc. Aquí hay un script de ejemplo simple pero inútil que devuelve sus argumentos (hasta tres de ellos):


#!/usr/local/bin/kermit +
if defined \%1 echo "Argument 1: \%1"
if defined \%2 echo "Argument 2: \%2"
if defined \%3 echo "Argument 3: \%3"
if defined \%4 echo "etc..."
exit

Si este archivo está almacenado en su directorio actual como "commandfile", entonces:


./commandfile one two three four five

imprimirá:


Argument 1: one
Argument 2: two
Argument 3: three
etc...

Esto ilustra la estructura básica de un script de Kermit independiente: la "línea kerbang", luego algunos comandos. Debería terminar con "exit" a menos que desee que aparezca el símbolo de Kermit cuando haya terminado. \%1 es el primer argumento, \%2 el segundo, y así sucesivamente.

También puede crear sus propios comandos definiendo macros con nombre compuestas por otros comandos de Kermit (o macros). Por ejemplo:

  define mydelete {
      local trash
      assign trash \v(home)trashcan/
      if not defined \%1 end 1 "Delete what?"
      if wild \%1 {
          end 1 "Deleting multiple files is too scary"
      }
      if not exist \%1 end 1 "I can't find \%1"
      if not directory \m(trash) {
          mkdir \m(trash)
          if fail end 1 "No trash can"
      }
      rename /list \%1 \m(trash)
  }
  define myundelete {
      local trash
      assign trash \v(home)trashcan/
      if not defined \%1 end 1 "Undelete what?"
      if wild \%1 {
          end 1 "Undeleting multiple files is too hard"
      }
      if not directory \m(trash) end 1 "No trash can"
      if not exist \m(trash)\%1 {
          end 1 "I can't find \%1 in trash can"
      }
      rename /list \m(trash)\%1 .
  }
Estas macros de ejemplo no son exactamente de calidad de producción (no manejan nombres de archivo que incluyen segmentos de ruta, no manejan múltiples archivos, etc.), pero entiende la idea: puede pasar argumentos a las macros, y estas pueden verificarlos y tomar otro tipo de decisiones. Si pone las líneas anteriores en su archivo de inicialización o personalización (explicado más abajo), tendrá los comandos MYDELETE y MYUNDELETE disponibles cada vez que inicie Kermit, al menos siempre que no suprima la ejecución del archivo de inicialización. (Ejercicio para el lector: Haga que estas macros sean generalmente útiles: elimine limitaciones, agregue visualización de la papelera, exploración, vaciado, etc.)

Los scripts Kerbang se ejecutan sin el archivo de inicialización. Esto es para mantenerlos portables y también para que se inicien más rápido. Si desea escribir scripts Kerbang que dependan del archivo de inicialización, incluya el comando


take \v(home).kermrc

en el lugar deseado del script. Por cierto, \v(xxx) es una variable integrada (xxx es el nombre de la variable, "home" en este caso). Para ver qué variables integradas están disponibles, escriba "show variables" en el símbolo de C‐Kermit. Para ver qué más puede mostrar, escriba "show ?". \m(xxx) es una variable definida por el usuario (estrictamente hablando, es una macro utilizada como variable).

Comando Lista

C‐Kermit tiene más de 200 comandos de nivel superior, y algunos de estos, como SET, se ramifican en cientos de subcomandos propios, por lo que no es práctico describirlos todos aquí. En cambio, aquí hay una lista concisa de los comandos de nivel superior más utilizados, agrupados por categoría. Para aprender sobre cada comando, escriba "help" seguido del nombre del comando, p. ej. "help set". Términos como Estado de comando y Estado de conexión se explican en las secciones siguientes.

Los campos opcionales se muestran en [ corchetes ]. "filename" significa el nombre de un solo archivo. filespec significa una especificación de archivo que puede contener caracteres comodín como '*' para coincidir con grupos de archivos. options son (opciones) interruptores como /PAGE, /NOPAGE, /QUIET, etc, listados en el texto de AYUDA de cada comando. Ejemplo:

  send /recursive /larger:10000 /after:-1week /except:*.txt *

que se puede leer como "enviar todos los archivos en este directorio y todos los que estén debajo de él que sean mayores de 10000 bytes, no más de una semana de antigüedad, y cuyos nombres no terminen con ".txt".

ARCHIVO DE INICIALIZACIÓN

En su configuración predeterminada, C-Kermit ejecuta comandos desde un archivo llamado .kermrc en su directorio de inicio cuando se inicia, a menos que se le proporcione la opción de línea de comandos -Y o -y. Las configuraciones personalizadas podrían sustituir un archivo de inicialización compartido en todo el sistema. El comando SHOW FILE indica qué archivo de inicialización, si lo hubo, se utilizó. El archivo de inicialización estándar "encadena" a un archivo de personalización individual, .mykermc, en el directorio de inicio, en el cual cada usuario puede establecer sus propias preferencias, definir macros, etc.

Dado que la ejecución del archivo de inicialización (al menos el estándar) hace que C-Kermit tarde más en iniciarse, puede ser mejor no tener un archivo de inicialización, especialmente ahora que la configuración de inicio predeterminada de Kermit está bien adaptada a la computación y redes modernas; en otras palabras, ya no tiene que hacer nada especial para que las transferencias de Kermit sean rápidas. Por lo tanto, en lugar de tener un archivo de inicialización que se ejecuta cada vez que se inicia Kermit, podría considerar crear uno o más scripts kerbang (con nombres distintos de .kermrc) que NO incluyan un comando "exit", e invocarlos cuando necesite la configuración, las definiciones de macros y/o las acciones de script que contienen, e invocar C-Kermit directamente cuando no los necesite.

Dicho de otra manera... Todavía distribuimos el archivo de inicialización estándar ya que se presenta en el manual y la compatibilidad con versiones anteriores es importante para nosotros. Pero no hay ningún daño en no usarlo si no necesita lo que contiene (directorio de servicios, directorio de marcación, directorio de red y definiciones de macros asociadas). Por otro lado, si hay configuraciones o macros que desea que estén en efecto CADA VEZ que usa Kermit, el archivo de inicialización (o el archivo de personalización al que enlaza) es el lugar para ponerlos, porque ese es el único lugar donde Kermit los busca automáticamente cada vez que lo inicia.

MODOS DE OPERACIÓN

Se dice que Kermit está en modo Local si ha establecido una conexión con otra computadora, por ejemplo, marcándola o estableciendo una conexión Telnet con ella. La otra computadora es remota, por lo que si inicia otra copia de Kermit en la computadora remota, se dice que está en modo Remoto (siempre que no haya establecido ninguna conexión propia). El Kermit local comunica a través del dispositivo de comunicación o la conexión de red, actuando como conducto entre la computadora remota y su teclado y pantalla. El Kermit remoto es el socio de transferencia de archivos del Kermit local y comunica solo a través de su entrada y salida estándar.

En cualquier momento, un programa Kermit puede estar en cualquiera de los siguientes estados. Es importante saber cuáles son y cómo cambiar de uno a otro.

Estado de Comando
En este estado, Kermit lee comandos de:

• Tu teclado; o:
• Un archivo, o:
• Una definición de macro.

Puedes salir del estado de Comando de vuelta a Unix con el comando EXIT o QUIT (lo mismo). Puedes entrar al estado de Conexión con cualquiera de varios comandos (CONNECT, DIAL, TELNET, etc). Puedes entrar al estado de transferencia de archivos con comandos como SEND, RECEIVE y GET. Puedes entrar al estado de Servidor con el comando SERVER. El comando TAKE le dice a Kermit que lea y ejecute comandos de un archivo. El comando (quizás implícito) DO le dice a Kermit que lea y ejecute comandos de una definición de macro. Mientras está en el estado de Comando, puede interrumpir cualquier comando, macro o archivo de comandos escribiendo Ctrl-C (mantenga presionada la tecla Ctrl y presione la tecla C); esto normalmente lo devuelve al prompt.

Estado de Shell
Puede invocar un shell inferior o un comando externo desde el prompt de comandos de Kermit usando el comando PUSH, RUN (!), EDIT o BROWSE. Mientras el shell inferior o el comando está activo, Kermit está suspendido y no hace nada. Regrese al estado de Comando de Kermit saliendo del shell inferior o de la aplicación.
Estado de Conexión
En este estado, al que solo se puede acceder cuando está en modo Local (es decir, cuando Kermit ha establecido una conexión con otra computadora), Kermit actúa como un terminal para la computadora remota. Sus pulsaciones de teclas se envían a la computadora remota y los caracteres que llegan a través de la conexión de comunicación se muestran en su pantalla. A este estado se accede cuando se da un comando CONNECT, DIAL, TELNET, RLOGIN o IKSD. Puede volver al estado de comando cerrando la sesión de la computadora remota, o escribiendo:


Ctrl-\c

Es decir: Mantenga presionada la tecla Ctrl y presione la tecla de barra invertida, luego suelte la tecla Ctrl y presione la tecla C. Esto se llama escapar hacia atrás. También se proporcionan otros comandos de nivel de escape; escriba Ctrl-\? para obtener una lista. Por ejemplo, puede entrar en el estado de Shell con:


Ctrl-\!

Para enviar un Ctrl-\ al host mientras está en el estado de Conexión, escriba dos de ellos seguidos. Consulte HELP CONNECT y HELP SET ESCAPE para más información.

Estado de transferencia de archivos local
En este estado, Kermit está enviando y recibiendo paquetes entre las computadoras para transferir un archivo o realizar alguna otra tarea relacionada con archivos. Y al mismo tiempo, muestra su progreso en su pantalla y observa su teclado para detectar interrupciones. En este estado, se aceptan los siguientes comandos de una sola pulsación de tecla:
X
Interrumpe el archivo actual y pasa al siguiente (si lo hay).
Z
Interrumpe el archivo actual y omite el resto.
E
Como Z pero usa un protocolo "más fuerte" (use si X o Z no funcionan).
Ctrl-C
Interrumpe el modo de transferencia de archivos (use si Z o E no funcionan).
Kermit regresa a su estado anterior (Comando o Conexión) cuando la transferencia se completa o cuando se interrumpe con éxito por X, Z, E o Ctrl-C (mantenga presionada la tecla Ctrl y presione la tecla C).
Estado de transferencia de archivos remota
En este estado, Kermit está intercambiando paquetes de transferencia de archivos con su socio local a través de su entrada/salida estándar. Sale de este estado automáticamente cuando se completa la transferencia. En caso de que su Kermit local esté en modo Conexión y el remoto en modo Transferencia de archivos (en el que parece ignorar sus pulsaciones de teclas), generalmente puede devolverlo al modo Comando escribiendo tres Ctrl-C seguidos. Si eso no funciona, devuelva su Kermit local al modo Comando (Ctrl-\ C) y escriba "e-packet" y luego presione la tecla Return o Enter; esto fuerza un error fatal del protocolo Kermit.
Estado de Servidor Remoto
Esto es similar al estado de Transferencia de Archivos Remota, excepto que nunca regresa automáticamente al estado de Comando. Más bien, espera instrucciones adicionales del programa cliente; es decir, de su programa Kermit Local. Puede devolver el Servidor Remoto a su estado anterior emitiendo un comando "finish" al cliente, o si está en estado de Conexión, escribiendo tres Ctrl-C seguidos. Puede indicar al trabajo del servidor que cierre sesión y rompa la conexión emitiendo un comando "bye" al cliente.
Estado de Servidor Local
Como el estado de Servidor Remoto, pero en modo local, y por lo tanto con su pantalla de transferencia de archivos visible, y escuchando comandos de una sola tecla, como en el estado de Transferencia de Archivos Local. Generalmente, este estado se ingresa automáticamente cuando un programa Kermit remoto da un comando GET.

C-Kermit, Kermit 95 y MS-DOS Kermit pueden cambiar automáticamente del estado de Conexión al estado de Transferencia de Archivos Local cuando inicia una transferencia de archivos desde el

ordenador remoto iniciando Kermit y diciéndole que envíe o reciba un archivo, en cuyo caso, el estado de Conexión se reanuda automáticamente después de que la transferencia de archivos haya finalizado.

Tenga en cuenta que C‐Kermit no es un emulador de terminal. Es una aplicación de comunicaciones que se ejecuta en una ventana de terminal (por ejemplo, consola o Xterm). La emulación específica, como VT100, VT220, Consola de Linux o Xterm, la proporciona la ventana de terminal en la que está ejecutando C‐Kermit. Kermit 95 y MS‐DOS Kermit, por otro lado, son emuladores de terminal reales. ¿Por qué C‐Kermit no es un emulador de terminal? HAGA CLIC AQUÍ para leer sobre ello.

ESTABLECIENDO CONEXIONES

A continuación se explica cómo establecer diferentes tipos de conexiones usando comandos interactivos de Kermit (como se indicó anteriormente, también puede establecer conexiones con opciones de línea de comandos). Tenga en cuenta que no tiene que establecer conexiones con Kermit. También puede usarse en el extremo remoto de una conexión como socio de transferencia y gestión de archivos remotos de su software de comunicaciones local.

Estableciendo una conexión Telnet
En el símbolo de comandos de C‐Kermit, simplemente escriba: 
  telnet foo.bar.com

(sustituyendo el nombre de host o la dirección deseados). También puede incluir un número de puerto:

  telnet xyzcorp.com 3000 ;

Si la conexión es exitosa, Kermit entra automáticamente en el estado de Conexión. Cuando cierra la sesión en el host remoto, Kermit regresa automáticamente a su símbolo. Más información: HELP TELNET, HELP SET TELNET, HELP SET TELOPT. Vea también la sección IKSD más abajo.

Estableciendo una conexión Rlogin
Esto es igual que Telnet, excepto que tiene que ser root para hacerlo porque Rlogin usa un puerto TCP privilegiado: 
  rlogin foo.bar.com

Más información: HELP RLOGIN.

Estableciendo una conexión SSH
A diferencia de Telnet y Rlogin, las conexiones SSH no están integradas, sino que se manejan ejecutando su cliente SSH externo a través de un pseudoterminal. Usar C‐Kermit para controlar el cliente SSH le da todas las características de Kermit (transferencia de archivos, conversión de conjuntos de caracteres, scripting, etc.) sobre SSH.


ssh foo.bar.com

Más información: HELP SSH, HELP SET SSH.

Marcando con un Módem
Si es un módem externo, asegúrese de que esté conectado a un puerto serie utilizable en su computadora con un cable de módem regular (directo) y al enchufe telefónico con un cable telefónico, y que esté encendido. Luego use estos comandos: 
  set modem type usrobotics  ; U otro tipo soportado
  set line /dev/ttyS0        ; Especificar nombre de dispositivo
  set speed 57600            ; U otra velocidad deseada
  set flow rts/cts           ; La mayoría de los módems modernos soportan esto
  set dial method tone       ; (o pulse)
  dial 7654321               ; Marcar el número deseado

Escriba "set modem type ?" para obtener una lista de los tipos de módem soportados. Si omite el comando SET MODEM TYPE, el tipo predeterminado es "generic‐high‐speed", que debería funcionar para la mayoría de los módems modernos con conjunto de comandos AT. Si la línea está ocupada, Kermit vuelve a marcar automáticamente. Si la llamada no tiene éxito, use "set dial display on" e inténtelo de nuevo para ver qué sucede. Si la llamada tiene éxito, Kermit entra automáticamente en el estado de Conexión y regresa automáticamente a su símbolo cuando cierra la sesión en el equipo remoto o la conexión se pierde de otro modo.

También puede marcar desde un módem al que se puede acceder por Telnet, por ejemplo, a un servidor de terminal inverso. En este caso, la secuencia de comandos es:

  set host ts.xxx.com 2000   ; Servidor de terminal y puerto
  set modem type usrobotics  ; U otro tipo soportado
  set dial method tone       ; (o pulse)
  dial 7654321               ; Marcar el número deseado

Si el servidor de terminal soporta la Opción de Puerto COM de Telnet, RFC 2217, también puede dar comandos relacionados con el puerto serie como SET SPEED, SET PARITY, etc., y Kermit los retransmite al servidor de terminal usando el protocolo especificado en la RFC.

Más información: HELP SET MODEM, HELP SET LINE, HELP SET SPEED, HELP SET FLOW, HELP DIAL, HELP SET DIAL, HELP SET MODEM, HELP SET CARRIER-WATCH, SHOW COMMUNICATIONS, SHOW MODEM, SHOW DIAL.

Puerto serie directo
Conecte las dos computadoras, A y B, con un cable de módem nulo (o dos cables de módem interconectados con un adaptador de módem nulo o un eliminador de módem). Desde la Computadora A: 
  set modem type none   ; No hay módem
  set line /dev/ttyS0   ; Especificar nombre de dispositivo
  set carrier-watch off ; Si DTR y CD no están interconectados cruzadamente
  set speed 57600       ; U otra velocidad deseada
  set flow rts/cts      ; Si RTS y CTS están interconectados cruzadamente
  set parity even       ; (o "mark" o "space", si es necesario)
  set stop-bits 2       ; (rara vez necesario)
  set flow xon/xoff     ; Si no puede usar RTS/CTS
  connect               ; Entrar en el estado de Conexión (terminal)

Esto asume que la Computadora B está configurada para permitirle iniciar sesión. Si no lo está, puede ejecutar una copia de Kermit en la Computadora B y seguir aproximadamente las mismas instrucciones. Más información: Como arriba más HELP CONNECT.

Con módems o conexiones serie directas, también podría tener que "set parity even" (o "mark" o "space") si es una conexión de 7 bits.

De los tipos de conexión listados arriba, solo uno puede estar abierto a la vez. Sin embargo, cualquiera de estos puede estar abierto concurrentemente con una sesión FTP o HTTP. Cada tipo de conexión se puede personalizar en cualquier grado deseado, se puede crear un script, registrar, lo que se le ocurra. Consulte el manual.

NOTA: En plataformas seleccionadas, C‐Kermit también puede establecer conexiones X.25. Consulte el manual para más detalles.

TRANSFERIENDO ARCHIVOS CON KERMIT

Existe una creencia generalizada y persistente de que Kermit es un protocolo lento. Esto se debe a que, hasta hace poco, usaba una configuración conservadora por defecto para asegurarse de que las transferencias de archivos tuvieran éxito, en lugar de fallar porque sobrecargaban la conexión. Se necesitaban algunos comandos extra (o opciones de línea de comandos, como -Q) para que fuera rápido, pero a nadie le molestó averiguar sobre ellos. Además, para bailar tango se necesitan dos: la mayoría de las implementaciones del protocolo Kermit que no son del Proyecto Kermit realmente SON lentas. Los mejores socios de transferencia de archivos para C‐Kermit son: otra copia de C‐Kermit (7.0 o posterior) y Kermit 95. Estas combinaciones funcionan bien y funcionan rápido de forma predeterminada. MS‐DOS Kermit también es bueno, pero tiene que decirle que vaya rápido (dándole el comando FAST).

Además, los tres programas Kermit soportan "autodescarga" y "autocarga", lo que significa que cuando están en el estado de Conexión y llega un paquete Kermit desde el remoto, cambian automáticamente al modo de transferencia de archivos.

Y además, C‐Kermit y K95 también cambian automáticamente entre modo de texto y binario para cada archivo, por lo que no es necesario "set file type binary" ni "set file type text", ni preocuparse por que los archivos se corrompan porque se transfirieron en el modo incorrecto.

Todo lo que estas palabras suman es que ahora, cuando usa software Kermit actualizado del Proyecto Kermit, la transferencia de archivos no solo es rápida, es ridículamente fácil. Apenas tiene que dar comandos en absoluto.

Descargando archivos
Supongamos que tiene Kermit 95, C‐Kermit o MS‐DOS Kermit en su computadora de escritorio, con una conexión a una computadora Unix que tiene C‐Kermit instalado como "kermit". Para descargar un archivo (enviarlo desde Unix a su computadora de escritorio), simplemente escriba el siguiente comando en su símbolo de comandos de shell de Unix:


kermit -s oofa.txt

(donde oofa.txt es el nombre del archivo). Si desea enviar más de un archivo, puede poner tantos nombres de archivo como quiera en la línea de comandos, y pueden ser cualquier combinación de texto y binario:


kermit -s oofa.txt oofa.zip oofa.html oofa.tar.gz

y/o puede usar comodines para enviar grupos de archivos:


kermit -s oofa.*

Si desea enviar un archivo con un nombre asumido, use:


kermit -s friday.txt -a today.txt

Esto envía el archivo friday.txt pero le dice al Kermit receptor que su nombre es today.txt. En todos los casos, como se indicó, cuando la transferencia de archivos finaliza, su Kermit de escritorio regresa automáticamente al estado de Conexión. Sin preocupaciones sobre volver atrás, reconectar, cambiar de modo texto/binario. Casi demasiado fácil, ¿verdad?

Cargando archivos
Para cargar archivos (enviarlos desde su computadora de escritorio a la computadora Unix remota), haga lo mismo, pero use la opción -g (GET) en lugar de -s:


kermit -g oofa.txt

Esto hace que su Kermit local entre en modo servidor; luego el programa Kermit remoto solicita el archivo nombrado y el Kermit local lo envía y regresa automáticamente al estado de Conexión cuando termina.

Si desea cargar múltiples archivos, tiene que usar las reglas de comillas del shell, ya que estos no son archivos locales:

  kermit -g "oofa.txt oofa.zip oofa.html oofa.tar.gz"
  kermit -g "oofa.*"

Si desea cargar un archivo pero almacenarlo con un nombre diferente, use:


kermit -g friday.txt -a today.txt

Transferencias Kermit a la manera antigua
Si su software de comunicaciones de escritorio no soporta autocarga o autodescarga, o no incluye el modo servidor de Kermit, el procedimiento requiere más pasos.

Para descargar un archivo, escriba:


kermit -s filename

en el host como antes, pero si no sucede nada automáticamente en respuesta a este comando, tiene que cambiar su software de comunicaciones de escritorio al estado de Recepción de Kermit. Esto podría hacerse volviendo atrás usando caracteres de teclado o teclas de acceso rápido (Alt-x es típico) y/o con un comando (como RECEIVE) o un menú. Cuando la transferencia de archivos esté completa, tiene que volver al estado de Conexión, emulación de terminal o lo que sea que aplique a susoftware de comunicaciones de escritorio.

Para subir un archivo, escriba:


kermit -r

en el host (en lugar de "kermit -g"). Esto le indica a C‐Kermit que espere pasivamente a que un archivo comience a llegar. Luego, recupere la atención de su software de escritorio (Alt-x o lo que sea) y instrúyalo para que envíe el (los) archivo(s) deseado(s) con el protocolo Kermit. Cuando la transferencia termine, regrese a la pantalla de Conexión o Terminal.

Si la Transferencia de Archivos Falla
Aunque cada aspecto del funcionamiento de Kermit puede ser ajustado finamente, también existen tres comandos cortos y simples de "ajuste general" que puede usar para la solución de problemas:
FAST
Utilice ajustes de transferencia de archivos rápidos. Este ha sido el valor predeterminado desde C‐Kermit 7.0, ahora que la mayoría de las computadoras y conexiones modernas lo soportan. Si las transferencias fallan con ajustes rápidos, intente . . .
CAUTIOUS
Utilice ajustes cautelosos pero no paranoicos. Las transferencias de archivos, si funcionarán, irán a velocidad media. Si no, intente . . .
ROBUST
Utilice los ajustes más robustos, resilientes, conservadores, seguros y confiables. Las transferencias de archivos casi con certeza funcionarán, pero serán bastante lentas (por supuesto, este es un intercambio clásico; ROBUST era el ajuste predeterminado de C‐Kermit en las versiones 6.0 y anteriores, lo que hizo que todos pensaran que el protocolo Kermit era lento). Si ROBUST no hace el truco, intente de nuevo con SET PARITY SPACE primero, en caso de que no sea una conexión de 8 bits.

Obviamente, el éxito y el rendimiento de una transferencia de archivos también depende del socio de transferencia de archivos de C‐Kermit. Se recomiendan socios del Proyecto Kermit actualizados y reales porque contienen las mejores implementaciones del protocolo Kermit y porque podemos soportarlos en caso de problemas.

Si todavía tiene problemas, consulte el Capítulo 10 de Using C‐Kermit, o envíe un correo electrónico a kermit‐support@columbia.edu.

Características Avanzadas de Transferencia de Archivos de Kermit
Obviamente, hay mucho más en la transferencia de archivos con Kermit, incluyendo todo tipo de comandos interactivos, preferencias, opciones, registro, depuración, solución de problemas y cualquier otra cosa que pueda imaginar, pero eso es para lo que sirven el manual y las actualizaciones. (HELP WILDCARD).

Transferencia de Archivos No-Kermit
También puede usar C‐Kermit para transferir archivos con los protocolos de Internet FTP o HTTP; vea abajo.

En una conexión serial o Telnet regular donde la otra computadora no soporta el protocolo Kermit en absoluto, tiene varias opciones. Por ejemplo, si su software de comunicaciones de escritorio soporta Zmodem, use "rz" y "sz" en el host en lugar de Kermit. Pero si Kermit es su software de escritorio, y lo está usando para hacer llamadas o conexiones de red a otras computadoras que no soportan el protocolo Kermit (o que no tienen una buena implementación del mismo), entonces si su computadora también tiene programas externos X, Y o Zmodem que sean redirigibles, Kermit puede usarlos como protocolos externos. HELP SET PROTOCOL para detalles.

También puede capturar flujos de datos "crudos" de la otra computadora con LOG SESSION (HELP LOG y HELP SET SESSION-LOG para detalles), y puede subir archivos sin ningún protocolo en absoluto con TRANSMIT (HELP TRANSMIT, HELP SET TRANSMIT).

CLIENTES FTP Y HTTP INTEGRADOS DE KERMIT

El cliente FTP de Kermit es como el cliente FTP regular de Unix al que está acostumbrado, pero con algunas diferencias:

•
Tiene muchos más comandos y características.
•
Cada comando FTP debe ir precedido de "ftp", por ejemplo "ftp open", "ftp get", "ftp bye", etc (esto no es estrictamente cierto, pero hasta que esté más familiarizado con él, es mejor seguir esta regla).
•
Comandos como "cd", "directory", etc, se ejecutan localmente, no en el servidor. Use "ftp cd", "ftp dir", etc, para que actúen en el servidor.
•
Puede tener una sesión FTP y una sesión serial o Telnet regular de Kermit abiertas al mismo tiempo.
•
Las sesiones FTP pueden ser completamente automatizadas.

Pendiente de la publicación de la próxima edición del manual, el cliente FTP de Kermit está completamente documentado en el sitio web del Proyecto Kermit:


http://www.columbia.edu/kermit/ftpclient.html

También puede usar HELP FTP y HELP SET FTP para obtener descripciones de los comandos relacionados con FTP de Kermit.

El cliente HTTP es similar al de FTP, excepto que usted precede cada comando con HTTP en lugar de FTP: HTTP OPEN, HTTP GET, HTTP PUT, HTTP CLOSE, etc. Escriba HELP HTTP para detalles, o visite el sitio para ver los suplementos del manual. Las conexiones HTTP pueden estar abiertas al mismo tiempo que las conexiones seriales o Telnet regulares y las conexiones FTP. Así que Kermit puede gestionar hasta tres tipos de conexiones simultáneamente.

SERVICIO KERMIT DE INTERNET

C‐Kermit puede ser configurado y ejecutado como un servicio de Internet (llamado IKSD), similar a un servidor FTP (FTPD) excepto que usted puede (pero no necesita) interactuar con él directamente, además hace mucho más de lo que un servidor FTP puede hacer. El puerto TCP para IKSD es 1649. Usa el protocolo Telnet. C‐Kermit puede ser un Servidor Kermit de Internet, o puede ser un cliente de un IKSD. Puede hacer conexiones desde C‐Kermit a un IKSD con cualquiera de los siguientes comandos:

  telnet foo.bar.edu 1649
  telnet foo.bar.edu kermit   ; si "kermit" está listado en /etc/services
  iksd foo.bar.edu

El comando IKSD es equivalente a un comando TELNET que especifica el puerto 1649. Para más información sobre cómo hacer y usar conexiones a un IKSD, vea:


http://www.columbia.edu/kermit/cuiksd.html

También puede ejecutar un Servicio Kermit de Internet en su propia computadora (si usted es el administrador del sistema). Para instrucciones, vea:


http://www.columbia.edu/kermit/iksd.html

SEGURIDAD

Todos los métodos de redes TCP/IP integrados de C‐Kermit (Telnet, Rlogin, IKSD, FTP y HTTP) pueden ser asegurados por uno o más de los siguientes métodos aprobados por la IETF:

• MIT Kerberos IV
• MIT Kerberos V
• SSL/TLS
• Stanford SRP

Para instrucciones completas vea:


http://www.columbia.edu/kermit/security.html

Y como se mencionó anteriormente, también puede hacer conexiones SSH con C‐Kermit si ya tiene un cliente SSH instalado.

PERSONALIDADES ALTERNATIVAS DE LÍNEA DE COMANDOS

Cuando se invoca como "kermit" o cualquier otro nombre que no sea "ftp" o "telnet", C‐Kermit tiene las opciones de línea de comandos descritas arriba en la sección OPTIONS. Sin embargo, si invoca C‐Kermit como "telnet" o "ftp", cambia su personalidad de línea de comandos para que coincida. Esto puede hacerse (entre otras maneras) con enlaces simbólicos (symlinks). Por ejemplo, si quiere que C‐Kermit sea su cliente Telnet regular, o el asistente Telnet de su navegador Web, puede crear un enlace como el siguiente en un directorio que esté en su PATH por delante del programa telnet regular:


ln -s /usr/local/bin/kermit telnet

Ahora cuando usted da un comando "telnet", está invocando a Kermit en su lugar, pero con su personalidad de línea de comandos Telnet, así que por ejemplo:


telnet xyzcorp.com

Hace una conexión Telnet a xyzcorp.com, y Kermit sale automáticamente cuando la conexión se cierra (igual que el cliente Telnet regular). Escriba "telnet -h" para obtener una lista de las opciones de línea de comandos de la personalidad Telnet de Kermit, las cuales están destinadas a ser lo más compatibles posible con el cliente Telnet regular.

De manera similar para FTP:


ln -s /usr/local/bin/kermit ftp</

SYNOPSIS

kermit [options] [files ...]

DESCRIPTION

C-Kermit is a program for transferring files and connecting to remote computers via the Internet or other networks. It supports the Kermit file transfer protocol, as well as Telnet, FTP, and remote login (for connecting to remote computers). It can also perform a wide variety of other tasks, such as dialing remote computers, managing files, and running scripts.

When invoked without arguments, C-Kermit starts an interactive session, prompting you with:

kermit>

You can type "help" to get a list of commands, or "help" followed by a command name for detailed information about that command.

Most C-Kermit commands can also be entered directly on the command line with appropriate options. For example, to download a file via FTP, you could type:


ftp -h

to see its command-line options, and command lines just like you would give your regular FTP client:


ftp xyzcorp.com

but with additional options allowing an entire session to be specified on the command line. Finally, if Kermit's first command-line option is a Telnet, FTP, IKSD, or HTTP URL, Kermit automatically makes the appropriate kind of connection and, if indicated by the URL, takes the desired action:

kermit telnet:xyzcorp.com
Opens a Telnet session
kermit telnet://olga@xyzcorp.com
Ditto for user olga
kermit ftp://olga@xyzcorp.com/public/oofa.zip
Downloads a file
kermit kermit://kermit.columbia.edu/kermit/f/READ.ME
Ditto for IKSD
kermit iksd://kermit.columbia.edu/kermit/f/READ.ME
(This works too)
kermit http://www.columbia.edu/kermit/index.html
Grabs a web page
