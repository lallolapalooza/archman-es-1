CKPASSWD(8) Documentación de InterNetNews CKPASSWD(8)

NOMBRE

ckpasswd - autenticador de contraseñas de nnrpd

SINOPSIS

ckpasswd [-gs] [-d base de datos] [-f nombre de archivo] [-u nombre de usuario -p contraseña]

DESCRIPCIÓN

ckpasswd es el autenticador de contraseñas básico para nnrpd, adecuado para ser ejecutado desde una sección auth en readers.conf. Vea readers.conf(5) para más información sobre cómo configurar un autenticador de nnrpd.

ckpasswd acepta un nombre de usuario y una contraseña de nnrpd y le dice a nnrpd(8) si esa es la contraseña correcta para ese nombre de usuario. Por defecto, cuando no se le dan argumentos, intenta verificar la contraseña usando PAM si se encontró soporte para PAM cuando se compiló INN. En caso contrario, intenta verificar la contraseña contra el campo de contraseña devuelto por getpwnam(3). Tenga en cuenta que hoy en día la mayoría de los sistemas ya no hacen que las contraseñas reales estén disponibles a través de getpwnam(3) (algunos todavía lo hacen si y solo si el programa que llama a getpwnam(3) se está ejecutando como root).

Al usar PAM, ckpasswd se identifica como "nnrpd", no como "ckpasswd", y la configuración de PAM debe configurarse en consecuencia. Los detalles de la configuración de PAM son diferentes en diferentes sistemas operativos (e incluso diferentes distribuciones de Linux); consulte "EJEMPLOS" a continuación para obtener ayuda para comenzar, y busque una página de manual de pam(7) o pam.conf(4) en su sistema.

Al usar cualquier método que no sea PAM, ckpasswd espera que todas las contraseñas se almacenen cifradas por la función del sistema crypt(3) y llama a crypt(3) en la contraseña proporcionada antes de compararla con la contraseña esperada. Se puede usar cualquier algoritmo de hash de contraseñas compatible con su libc o libcrypt.

OPCIONES

-d base de datos
Leer contraseñas de una base de datos (formato ndbm, gdbm o dbm según lo que tenga su sistema) en lugar de usar getpwnam(3). ckpasswd espera que existan base de datos.dir y base de datos.pag y que sea una base de datos indexada por nombre de usuario con las contraseñas cifradas como valores.

Aunque INN no viene con un programa diseñado específicamente para crear tales bases de datos, en la mayoría de los sistemas es bastante fácil escribir un script de Perl para hacerlo. Algo como:

#!/usr/bin/perl
use NDBM_File;
use Fcntl;
tie (%db, 'NDBM_File', '/ruta/a/la/base/de/datos', O_RDWR|O_CREAT, 0640)
    or die "No se puede abrir /ruta/a/la/base/de/datos: $!\n";
$| = 1;
print "Nombre de usuario: ";
my $user = <STDIN>;
chomp $user;
print "Contraseña: ";
my $passwd = <STDIN>;
chomp $passwd;
my @alphabet = ('.', '/', 0..9, 'A'..'Z', 'a'..'z');
my $salt = join '', @alphabet[rand 64, rand 64];
$db{$user} = crypt ($passwd, $salt);
untie %db;

Tenga en cuenta que esto repetirá la contraseña al escribirla; hay mejoras obvias que se podrían hacer a esto, pero debería ser un punto de partida razonable. A veces, un programa como este estará disponible con el nombre dbmpasswd.

Esta opción no estará disponible en sistemas sin bibliotecas ndbm, gdbm o dbm.

-f nombre de archivo
Leer contraseñas del archivo dado en lugar de usar getpwnam(3). Cada línea del archivo debería parecerse a: 
nombredeusuario:$5$Hlb2yXPd$2nOO/QR9P1mnRFr/i6L9ybxbgSDXd4UlatKqbcY4eoB
joe:FCjOJnpOo50IE:Se utilizó un algoritmo de hash débil antiguo para Joe

Cada línea tiene al menos dos campos separados por dos puntos. El primer campo contiene el nombre de usuario; el segundo campo contiene una contraseña cifrada con la función crypt(3). Pueden aparecer dos puntos y datos adicionales después de la contraseña cifrada; esos datos serán ignorados por ckpasswd. Las líneas que comienzan con un signo de almohadilla ("#") se ignoran.

INN no viene con una utilidad para crear las contraseñas cifradas, pero OpenSSL puede hacerlo y también es un trabajo rápido con Perl (vea el script de una línea a continuación).

Una línea en nombre de archivo para el usuario "usuario" con la contraseña "contraseña" sería "usuario:" seguido de la salida del siguiente comando usando SHA-256 como esquema de hash:

% openssl passwd -5 contraseña
$5$UIhtJSBOaC0Ap3Vk$nbKgmykshoQ2HmvA3s/nI.X4uhhNHBKTYhBS3pYLjJ6

Vea la página de manual de openssl-passwd(1) para la lista de esquemas de hash que puede generar. Debe elegir uno que su función crypt(3) del sistema maneje (escriba "man 3 crypt" o "man 5 crypt" para encontrar los esquemas de hash compatibles).

En caso de que OpenSSL no esté instalado en su servidor, también puede usar el siguiente comando Perl que hace el mismo trabajo con SHA-256 (vea los detalles a continuación para configurar "SuSal" en un valor apropiado; 5 es el prefijo para SHA-256, que no espera ningún parámetro):

% perl -le 'print crypt("contraseña", q{$5$SuSal$})'
$5$SuSal$V5hqwFg1nhKb5as6md9KTe5b2NyavsMS6dBYVKfp5W7

Como Perl utiliza crypt(3), tiene acceso a todos los esquemas de hash disponibles en sus sistemas. Por ejemplo, si yescript es compatible, puede generar una contraseña cifrada con un argumento como "$y$j9T$SuSal$" a la función crypt de Perl , donde "y" es el prefijo para yescript, "j9T" los parámetros pasados a crypt_gensalt(3) para generar la contraseña cifrada (estos parámetros controlan la configuración de yescript, y corresponden en este ejemplo a la bandera "YESCRYPT_DEFAULTS", el sabor recomendado que tiene el valor "j" en 2023, con un factor de coste de 4096 como recuento de bloques y 32 como tamaño de bloque) y "SuSal" una cadena que debe elegirse al azar y ser diferente para cada usuario. La sintaxis y la longitud óptima de la sal dependen del esquema de hash (por ejemplo, una longitud múltiplo de 4 para yescript) y de las recomendaciones criptográficas (por ejemplo, al menos 32 bits aleatorios de longitud, siguiendo las recomendaciones de NIST SP 800-63B en 2023).

En resumen, en el siguiente comando, solo tiene que cambiar la contraseña "contraseña" y la cadena aleatoria "SuSal", diferente para **cada** usuario, y dejar el resto del comando tal cual:

% perl -le 'print crypt("contraseña", q{$y$j9T$SuSal$})'
$y$j9T$SuSal$X4tB48vKNDT6mK0vNOc7ppKPWvEsyMg5LwoQfO50r2A

Una sal aleatoria de 12 caracteres se puede obtener con el siguiente comando (el resultado corresponde a 72 bits aleatorios ya que cada carácter se selecciona en un rango de 6 bits de 64 caracteres posibles):

% perl -le 'print join("",
      (".", "/", 0..9, A..Z, a..z)[map {rand 64} (1..12)])'
k2W/17eJu58r
-g
Intentar buscar el grupo del sistema correspondiente al nombre de usuario y devolver una cadena como "usuario@grupo" para que coincida en readers.conf. Esta opción es incompatible con las opciones -d y -f.
-p contraseña
Usar contraseña como contraseña para la autenticación en lugar de leer una contraseña usando el protocolo de autenticación de nnrpd. Esta opción es útil solo para probar su sistema de autenticación (particularmente ya que implica poner una contraseña en la línea de comandos), y no funciona cuando ckpasswd es ejecutado por nnrpd. Si se proporciona esta opción, también se debe proporcionar -u.

ckpasswd(8) - Arch Linux Man Pages

NAME

ckpasswd - check a password against a password file

SYNOPSIS

ckpasswd [options] < input-file

DESCRIPTION

ckpasswd is a helper program intended to be used by servers that need to authenticate users, such as nnrpd(8). It reads a username and password from its standard input and checks them against a password file, printing an error message to standard error and exiting with a non-zero status on failure, or printing the username to standard output and exiting with status 0 on success.

ckpasswd can be configured to use various authentication methods. By default, it uses the standard C library functions to look up users and check passwords. This typically means checking against the system's user database (often managed by passwd(5) and shadow(5)).

It can also be configured to use PAM (Pluggable Authentication Modules) for authentication, allowing more flexible authentication methods.

OPTIONS

-f passwd-file
Use passwd-file instead of the system's default password and shadow files. This file should be in the format used by passwd(5). This option is primarily useful for testing or for servers that maintain their own password files.
-p
Check passwords against the system's password database, including the password information stored in the /etc/shadow or similar more restricted files. If you want to check passwords supplied to nnrpd(8) against system account passwords, you will probably have to use this option on most systems.

Most systems require special privileges to call getspnam(3), so in order to use this option you may need to make ckpasswd setgid to some group (like group "shadow") or even setuid root. ckpasswd has not been specifically audited for such uses! It is, however, a very small program that you should be able to check by hand for security.

This configuration is not recommended if it can be avoided, for serious security reasons. See "SECURITY CONSIDERATIONS" in readers.conf(5) for discussion.

-u username
Authenticate as username. This option is useful only for testing (so that you can test your authentication system easily) and does not work when ckpasswd is run by nnrpd. If this option is given, -p must also be given.

EXAMPLES

See readers.conf(5) for examples of nnrpd(8) authentication configuration that uses ckpasswd to check passwords.

An example PAM configuration for /etc/pam.conf that tells ckpasswd to check usernames and passwords against system accounts is:

nnrpd auth    required pam_unix.so
nnrpd account required pam_unix.so

Your system may want you to instead create a file named nnrpd in /etc/pam.d with lines like:

auth    required pam_unix.so
account required pam_unix.so

This is only the simplest configuration. You may be able to include common shared files, and you may want to stack other modules, either to allow different authentication methods or to apply restrictions like lists of users who can't authenticate using ckpasswd. The best guide is the documentation for your system and the other PAM configurations you're already using.

To test to make sure that ckpasswd is working correctly, you can run it manually and then give it the username (prefixed with "ClientAuthname:") and password (prefixed with "ClientPassword:") on standard input. For example:

(echo 'ClientAuthname: test' ; echo 'ClientPassword: testing') \
    | ckpasswd -f /path/to/passwd/file

will check a username of "test" and a password of "testing" against the username and passwords stored in /path/to/passwd/file. On success, ckpasswd will print "User:test" and exit with status 0. On failure, it will print some sort of error message and exit a non-zero status.
