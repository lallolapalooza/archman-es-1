NOMBRE

ck_hs_init — inicializar un conjunto hash

BIBLIOTECA

Concurrency Kit (libck, -lck)

SINOPSIS

#include <ck_hs.h>

typedef unsigned long
ck_hs_hash_cb_t(const void *key, unsigned long seed);

typedef bool
ck_hs_compare_cb_t(const void *c1, const void *c2);

bool
ck_hs_init(ck_hs_t *hs, unsigned int mode, ck_hs_hash_cb_t *hash_function, ck_hs_compare_cb_t *compare, struct ck_malloc *allocator, unsigned long capacity, unsigned long seed);

DESCRIPCIÓN

La ck_hs_init() función inicializa el conjunto hash al que apunta el puntero hs .

El argumento mode especifica el tipo de pares clave-valor que se almacenarán en el conjunto hash, así como el modelo de acceso concurrente esperado. El valor de mode consta de un campo de bits de uno de los siguientes:

CK_HS_MODE_OBJECT
El conjunto hash está destinado a almacenar punteros a objetos. Esto proporciona una pista de que solo son necesarios CK_MD_VMA_BITS para codificar el argumento clave. Cualquier bits de puntero no utilizados se aprovechan para optimizaciones internas.
CK_HS_MODE_DIRECT
El conjunto hash está destinado a almacenar directamente los valores de las claves y que todos los bits de la clave se utilizan para codificar valores.

El modelo de acceso concurrente se especifica mediante:

CK_HS_MODE_SPMC
El conjunto hash debería permitir lectores concurrentes en presencia de un solo escritor.
CK_HS_MODE_MPMC
El conjunto hash debería permitir lectores concurrentes en presencia de escritores concurrentes. Actualmente no está soportado.

El desarrollador es libre de especificar pistas adicionales de carga de trabajo. Estas pistas son una de:

CK_HS_MODE_DELETE
Se espera que el conjunto hash tenga una carga de trabajo con muchas eliminaciones. Al costo de aproximadamente un 13% más de uso de memoria, permite límites de sondeo más fuertes por ranura para combatir los efectos de la acumulación de marcadores de tumba.

El argumento hash_function es un puntero obligatorio a una función hash especificada por el usuario. Una función hash especificada por el usuario toma dos argumentos. El argumento key es un puntero a una clave. El argumento seed es la semilla inicial asociada con el conjunto hash. Esta semilla inicial es especificada por el usuario en ck_hs_init(3).

El argumento compare es un puntero opcional a una función de comparación de claves especificada por el usuario. Si se especifica NULL en este argumento, se utilizará la igualdad de punteros para determinar la igualdad de las claves. Una función de comparación especificada por el usuario toma dos argumentos que representan punteros a los objetos que se comparan para igualdad. Se espera que devuelva true si las claves son de igual valor y false en caso contrario.

El argumento allocator es un puntero a una estructura que contiene malloc y free punteros a funciones que definen respectivamente las funciones de asignación y destrucción de memoria que se utilizarán por el conjunto hash que se está inicializando.

El argumento capacity representa el número inicial de claves que se espera que contenga el conjunto hash. Este argumento es simplemente una pista y la implementación subyacente es libre de asignar más o menos memoria de la necesaria para contener el número de entradas capacity especifica.

El argumento seed especifica la semilla inicial utilizada por la función hash subyacente. El usuario es libre de elegir un valor de su elección.

VALORES DE RETORNO

Tras una finalización exitosa ck_hs_init() devuelve un valor de true y en caso contrario devuelve un valor de false para indicar un error.

ERRORES

El comportamiento de ck_hs_init() es indefinido si hs no es un puntero a un ck_hs_t objeto.
