NOMBRE

CPANPLUS::Shell::Default::Plugins::HOWTO -- documentación sobre cómo escribir tus propios plugins

SINOPSIS

package CPANPLUS::Shell::Default::Plugins::MyPlugin;
### devolver mapeo de comando => método
sub plugins { ( myplugin1 => 'mp1', myplugin2 => 'mp2' ) }
### método llamado cuando se emite el comando '/myplugin1'
sub mp1 { .... }
### método llamado cuando se emite el comando '/? myplugin1'
sub mp1_help { return "Texto de Ayuda" }

DESCRIPCIÓN

Este texto de pod explica cómo escribir tus propios plugins para "CPANPLUS::Shell::Default".

CÓMO

Registrar Módulos de Plugin

Los plugins se detectan utilizando "Module::Pluggable". Cada módulo en el espacio de nombres "CPANPLUS::Shell::Default::Plugins::*" se considera un plugin y se intenta cargar.

Por lo tanto, cualquier plugin debe declararse en ese espacio de nombres, en un archivo ".pm" correspondiente.

Registrar Comandos de Plugin

Para registrar cualquier comando de plugin, se debe devolver una lista de pares clave-valor mediante un método "plugins" en tu paquete. Las claves son los comandos que deseas registrar, los valores son los métodos en el paquete del plugin que deseas que se llamen cuando se emite el comando.

Por ejemplo, un plugin simple de 'Hola, Mundo!':

package CPANPLUS::Shell::Default::Plugins::HW;
sub plugins { return ( helloworld => 'hw' ) };
sub hw { print "Hello, world!\n" }

Cuando el usuario en el shell por defecto emite ahora el comando "/helloworld", este comando se enviará al plugin y se llamará a su método "hw"

Registrar Ayuda de Plugin

Para proporcionar información de uso para tu plugin, el usuario del shell por defecto puede escribir "/? COMANDO_DEL_PLUGIN". En ese caso, se llamará a la función "COMANDO_DEL_PLUGIN_help" en tu paquete de plugin.

Por ejemplo, extendiendo el ejemplo anterior, cuando un usuario llama "/? helloworld", se llamará a la función "hw_help", que podría verse así:

sub hw_help { "    /helloworld      # imprime "Hello, world!\n" "}

Si no proporcionas una función _help correspondiente a tus comandos, el shell por defecto lo manejará con gracia, pero el usuario se quedará sin información de uso sobre tus comandos, por lo que se considera indeseable omitir las funciones de ayuda.

Argumentos a Comandos de Plugin

Cualquier función de plugin recibirá los siguientes argumentos cuando se llame, todos ellos posicionales:

NombreDeClase -- El nombre de tu clase de plugin
Shell -- El objeto CPANPLUS::Shell::Default
Backend -- El objeto CPANPLUS::Backend
Comando -- El comando emitido por el usuario
Entrada -- La cadena de entrada del usuario
Opciones -- Un hashref de opciones proporcionadas por el usuario

Por ejemplo, el siguiente comando:

/helloworld bob --nofoo --bar=2 joe

Generaría los siguientes argumentos:

sub hw {
    my $class   = shift;    # CPANPLUS::Shell::Default::Plugins::HW
    my $shell   = shift;    # Objeto CPANPLUS::Shell::Default
    my $cb      = shift;    # Objeto CPANPLUS::Backend
    my $cmd     = shift;    # 'helloworld'
    my $input   = shift;    # 'bob joe'
    my $opts    = shift;    # { foo => 0, bar => 2 }
    ....
}
