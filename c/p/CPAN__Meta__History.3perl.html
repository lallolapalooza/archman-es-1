NOMBRE

CPAN::Meta::History - historial de cambios de la especificación de metadatos de CPAN

VERSIÓN

versión 2.150010

DESCRIPCIÓN

La especificación de metadatos de CPAN ha pasado por varias iteraciones. Originalmente se escribió en HTML y posteriormente se revisó a POD (aunque se publicó en HTML generado a partir de POD). Los campos se añadieron, eliminaron o cambiaron, a veces intencionadamente y a veces para reflejar el uso en el mundo real después del hecho.

Este documento reconstruye el historial de la especificación de metadatos de CPAN basándose en los registros de cambios, los mensajes de confirmación del repositorio y los archivos HTML publicados. En algunos casos, particularmente antes de la versión 1.2, la versión exacta en la que se introdujeron o cambiaron ciertos campos es inconsistente entre las fuentes. En caso de duda, los archivos HTML publicados para las versiones 1.0 a 1.4, tal como existían cuando se desarrolló la versión 2, se utilizan como fuente definitiva.

A partir de la versión 2, el documento de especificación forma parte de la distribución CPAN-Meta y se publicará en CPAN como CPAN::Meta::Spec.

En adelante, los números de versión de la especificación serán enteros y las partes decimales corresponderán a una fecha de lanzamiento de la biblioteca CPAN::Meta.

HISTORIAL

Versión 2

Abril de 2010

  • Se revisaron los ejemplos de especificación como estructuras de datos perl en lugar de YAML.
  • Se cambió la serialización de YAML a JSON.
  • Se especificaron los formatos permitidos para los números de versión.
  • Se reemplazaron 'requires', 'build_requires', 'configure_requires', 'recommends' y 'conflicts' con una nueva estructura de datos 'prereqs' dividida por *fase* (configuración, construcción, prueba, tiempo de ejecución, etc.) y *relación* (requiere, recomienda, sugiere, conflictos).
  • Se añadió soporte para la fase 'develop' para requisitos de mantenimiento de una lista de herramientas de desarrollo.
  • Se cambió 'license' a una lista y se revisó el conjunto de licencias válidas.
  • Se hizo obligatorio 'dynamic_config' para reducir la confusión.
  • Se cambió la subclave 'repository' de 'resources' a un hash que aclara el tipo de repositorio, la URL para navegar y la URL para la descarga.
  • Se cambió la subclave 'bugtracker' de 'resources' a un hash para recursos web o mailto.
  • Se cambió la especificación de 'optional_features':
  • Se añadió una guía formal de especificación y uso en lugar de un simple ejemplo.
  • Se cambió para usar la nueva estructura de datos prereqs en lugar de claves individuales.
  • Se aclaró el uso previsto de 'author' como lista de contactos generalizada.
  • Se añadió el campo 'release_status' para indicar el estado estable, en pruebas o inestable para proporcionar pistas a los indexadores.
  • Se añadió el campo 'description' para una descripción más larga de la distribución.
  • Se formalizó el uso de "x_" o "X_" para todas las claves personalizadas no listadas en la especificación oficial.

Versión 1.4

Junio de 2008

  • Se notó soporte explícito para 'perl' en los prerrequisitos.
  • Se añadió el tipo de prerrequisito 'configure_requires'.
  • Se cambió 'optional_features'.
  • Se corrigió el ejemplo para mostrar un mapa de mapas en lugar de una lista de mapas (aunque el texto descriptivo decía 'mapa' incluso en v1.3).
  • Se eliminaron 'requires_packages', 'requires_os' y 'excluded_os' como subclaves válidas.

Versión 1.3

Noviembre de 2006

  • Se añadió la subclave 'directory' a 'no_index' y se eliminó 'dir' para que coincidiera con el uso real en la práctica.
  • Se añadió una subclave 'repository' a 'resources'.

Versión 1.2

Agosto de 2005

  • Se reescribió y reestructuró la especificación en sintaxis POD.
  • Se hizo obligatorio el campo 'name'.
  • Se hizo obligatorio el campo 'generated_by'.
  • Se hizo obligatorio el campo 'license'.
  • Se añadieron especificaciones de rangos de versión para los prerrequisitos.
  • Se añadió el campo obligatorio 'abstract'.
  • Se añadió el campo obligatorio 'author'.
  • Se añadió el campo obligatorio 'meta-spec' para definir la 'version' (y la 'url') de la especificación de metadatos de CPAN utilizada para los metadatos.
  • Se añadió el campo 'provides'.
  • Se añadió el campo 'no_index' y se desaconsejó el campo 'private'. Las subclaves de 'no_index' incluyen 'file', 'dir', 'package' y 'namespace'.
  • Se añadió el campo 'keywords'.
  • Se añadió el campo 'resources' con las subclaves 'homepage', 'license' y 'bugtracker'.
  • Se añadió el campo 'optional_features' como alternativa bajo 'recommends'. Incluye 'description', 'requires', 'build_requires', 'conflicts', 'requires_packages', 'requires_os' y 'excluded_os' como subclaves válidas.
  • Se eliminó el campo 'license_uri'.

Versión 1.1

Mayo de 2003

  • Se hizo obligatorio el campo 'version'.
  • Se añadió el campo 'private'.
  • Se añadió el campo 'license_uri'.

Versión 1.0

Marzo de 2003

  • Lanzamiento original (solo en formato HTML).
  • Incluía 'name', 'version', 'license', 'distribution_type', 'requires', 'recommends', 'build_requires', 'conflicts', 'dynamic_config', 'generated_by'.
