Variables específicas del generador CPack Externo

CPACK_EXTERNAL_REQUESTED_VERSIONS
Esta variable se utiliza para solicitar una versión específica del generador CPack Externo. Es una lista de valores major.minor, separados por punto y coma.

Si esta variable se establece a un valor no vacío, el generador CPack Externo iterará a través de cada elemento de la lista para buscar una versión que sepa cómo generar. Las versiones solicitadas deben estar listadas en orden de preferencia descendente por el software cliente, ya que se generará la primera versión coincidente de la lista.

El generador sabe cómo generar la versión si tiene un generador versionado cuya versión principal coincide exactamente con la versión principal solicitada y cuya versión secundaria es mayor o igual a la versión secundaria solicitada. Por ejemplo, si CPACK_EXTERNAL_REQUESTED_VERSIONS contiene 1.0 y el generador CPack Externo sabe cómo generar 1.1, generará 1.1. Si el generador no sabe cómo generar una versión de la lista, la omite y mira la siguiente. Si no sabe cómo generar ninguna de las versiones solicitadas, se genera un error.

Si esta variable no está establecida o está vacía, el generador CPack Externo generará la versión principal y secundaria más alta que sepa cómo generar.

Si se encuentra una versión inválida en CPACK_EXTERNAL_REQUESTED_VERSIONS (una que no coincide con major.minor, donde major y minor son enteros), se ignora.

CPACK_EXTERNAL_ENABLE_STAGING
Esta variable puede establecerse en verdadero para habilitar la instalación opcional en un área de ensayo temporal que luego puede ser recogida y empaquetada por una herramienta de empaquetado externa. El directorio de nivel superior utilizado por CPack para la tarea de empaquetado actual se encuentra en CPACK_TOPLEVEL_DIRECTORY. Se limpia automáticamente en cada ejecución antes de que se inicie el empaquetado y puede usarse para archivos temporales personalizados requeridos por la herramienta de empaquetado externa. También contiene el área de ensayo CPACK_TEMPORARY_DIRECTORY en la que CPack realiza la instalación cuando se habilita el ensayo.
CPACK_EXTERNAL_PACKAGE_SCRIPT
Esta variable puede especificar opcionalmente la ruta completa a un archivo de script de CMake que se ejecutará como parte de la invocación de CPack. Se invoca después del ensayo (opcional) y puede ejecutar una herramienta de empaquetado externa. El script tiene acceso a las variables definidas por el archivo de configuración de CPack.

El generador CPack FreeBSD puede usarse para crear paquetes pkg(8) -- estos pueden usarse en FreeBSD, DragonflyBSD, NetBSD, OpenBSD, pero también en Linux o OSX, dependiendo de las herramientas de gestión de paquetes instaladas -- usando CPack <#module:CPack>.

El generador CPack FreeBSD es un generador de CPack <#module:CPack> y utiliza las variables CPACK_XXX usadas por CPack <#module:CPack>. Intenta reutilizar la información de empaquetado que ya puede estar especificada para paquetes Debian para el Generador CPack DEB <#cpack_gen:CPack DEB Generator>. También intenta reutilizar la información de empaquetado RPM cuando Debian no la especifica.

El generador CPack FreeBSD debería funcionar en cualquier host con libpkg instalado. Los paquetes que produce son específicos de la arquitectura y ABI del host.

El generador CPack FreeBSD establece metadatos de paquete a través de variables CPACK_FREEBSD_XXX. El generador CPack FreeBSD, a diferencia del generador CPack Deb, no soporta especialmente paquetes componentizados; se crea un único paquete a partir de todos los artefactos de software creados a través de CMake.

Todas las variables pueden establecerse específicamente para el empaquetado FreeBSD en el archivo CPackConfig o en CMakeLists.txt, pero la mayoría de ellas tienen valores predeterminados que utilizan configuraciones generales (por ejemplo, CMAKE_PROJECT_NAME <#variable:CMAKE_PROJECT_NAME>) o variables específicas de Debian cuando estas tienen sentido (por ejemplo, la página principal de un proyecto upstream generalmente no cambia por el sabor del empaquetado). Cuando no hay información de Debian a la que recurrir, pero el empaquetado RPM la tiene, se recurre a la información RPM (por ejemplo, licencia del paquete).

Instalador en

línea

Por defecto, este generador genera un instalador sin conexión. Esto significa que todos los archivos empaquetados están contenidos completamente en el ejecutable del

instalador.

En cambio, un instalador en línea descargará algunos o todos los componentes de un servidor

remoto.

La opción DOWNLOADED en el comando cpack_add_component() <#command:cpack_add_component> especifica que un componente debe ser descargado. Alternativamente, la opción ALL en el comando cpack_configure_downloads() <#command:cpack_configure_downloads> especifica que todos los componentes deben ser

descargados.

El comando cpack_ifw_add_repository() <#command:cpack_ifw_add_repository> y la variable CPACK_IFW_DOWNLOAD_ALL permiten una configuración más

específica.

Cuando hay componentes en línea, CPack los escribirá en archivos de archivo. La página de ayuda del módulo CPackComponent <#module:CPackComponent>, especialmente la sección sobre la función cpack_configure_downloads() <#command:cpack_configure_downloads>, exp

lica cómo hacer que estos archivos se
an accesibles desde una URL de descarga.

caso.

    • empaquetada.
  • Los enlaces simbólicos que apuntan a una ubicación a través de uno o
    • más enlaces simbólicos intermedios no se manejarán de forma diferent
e: si el enlace simbólico intermedio también está en una ruta reub
