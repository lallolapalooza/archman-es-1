DESCRIPCIÓN

La cpl_complete_word() función es parte de la biblioteca tecla (ver la página man libtecla(3)). Generalmente es llamada por debajo del telón por gl_get_line(3), pero también puede ser llamada por separado.

Dada una línea de entrada que contiene una palabra incompleta a ser completada, llama a una función de retorno proporcionada por el usuario (o a la función de retorno de completado de archivos proporcionada) para buscar todos los sufijos de completado posibles para esa palabra. Se espera que la función de retorno mire hacia atrás en la línea, empezando desde la posición del cursor especificada, para encontrar el inicio de la palabra a completar, y luego busque todos los completados posibles de esa palabra y los registre, uno a la vez, llamando a cpl_add_completion().

Las descripciones de las funciones de este módulo son las siguientes:

  WordCompletion *new_WordCompletion(void)

Esta función crea los recursos usados por la cpl_complete_word() función. En particular, mantiene la memoria usada para devolver los resultados de llamar a cpl_complete_word().

  WordCompletion *del_WordCompletion(WordCompletion *cpl)

Esta función borra los recursos que fueron devueltos por una llamada previa a new_WordCompletion(). Siempre devuelve NULL (es decir, un objeto borrado). No hace nada si el argumento cpl es NULL.

Las funciones de retorno que buscan completados posibles deberían definirse con el siguiente macro (que está definido en libtecla.h).

  #define CPL_MATCH_FN(fn) int (fn)(WordCompletion *cpl, \
                                    void *data, \
                                    const char *line, \
                                    int word_end)

Las funciones de este tipo son llamadas por cpl_complete_word(), y todos los argumentos de la función de retorno son aquellos que fueron pasados a dicha función. En particular, el line argumento contiene la línea de entrada que contiene la palabra a completar, y word_end es el índice del carácter que sigue al último carácter de la palabra incompleta dentro de esta cadena. Se espera que la función de retorno mire hacia atrás desde word_end para el inicio de la palabra incompleta. Lo que constituye el inicio de una palabra claramente depende de la aplicación, por lo que tiene sentido que la función de retorno asuma esta responsabilidad. Por ejemplo, la función incorporada de completado de nombres de archivo mira hacia atrás hasta que encuentra un espacio sin escapar, o el inicio de la línea. Una vez encontrado el inicio de la palabra, la función de retorno debería buscar todos los completados posibles de esta palabra, y registrar cada completado mediante llamadas separadas a cpl_add_completion(). Si la función de retorno necesita acceso a una tabla de símbolos específica de la aplicación, puede pasarla y cualquier otro dato que necesite, mediante el data argumento. Esto elimina cualquier necesidad de variables globales.

La función de retorno debería devolver 0 si no ocurren errores. En caso de fallo debería devolver 1, y registrar una descripción breve del error llamando a cpl_record_error().

  void cpl_record_error(WordCompletion *cpl,
                        const char *errmsg);

El último mensaje de error registrado mediante la llamada a cpl_record_error(), puede ser consultado posteriormente llamando a cpl_last_error(), como se describe más adelante.

  int cpl_add_completion(WordCompletion *cpl,
                         const char *line, int word_start,
                         int word_end, const char *suffix,
                         const char *type_suffix,
                         const char *cont_suffix);

La cpl_add_completion() función es llamada cero o más veces por la función de retorno de completado para registrar cada posible completado en el objeto WordCompletion especificado. Estos completados son devueltos posteriormente por cpl_complete_word(), como se describe más adelante. Los argumentos cpl, line, y word_end deberían ser aquellos que fueron pasados a la función de retorno. El word_start argumento debería ser el índice dentro de la cadena de la línea de entrada del inicio de la palabra que está siendo completada. Este debería ser igual a word_end si se está completando una cadena de longitud cero. El argumento suffix es la cadena que tendría que ser añadida a la palabra incompleta para completarla. Si esto necesita alguna cita (por ejemplo, la adición de barras invertidas antes de caracteres especiales) para ser válida dentro de la línea de entrada mostrada, esto debería ser incluido. Se asigna internamente una copia de la cadena de sufijo, por lo que no hay necesidad de mantener su copia de la cadena después de que cpl_add_completion() retorne.

Note que en el arreglo de posibles completados que la cpl_complete_word() función devuelve, el sufijo registrado por cpl_add_completion() es listado junto con la concatenación de este sufijo con la palabra que yace entre word_start y word_end en la línea de entrada.

El type_suffix argumento especifica una cadena opcional a ser añadida al completado si es mostrado como parte de una lista de completados por cpl_list_completions(). La intención es que esto indique al usuario el tipo de cada completado. Por ejemplo, la función de completado de archivos coloca un separador de directorio después de los completados que son directorios, para indicar su naturaleza al usuario. De manera similar, si el completado fuera una función, podría indicar esto al usuario configurando type_suffix a "()". Note que la cadena type_suffix no es copiada, así que si el argumento no es una cadena literal entre comillas, asegúrese de que la cadena permanezca válida al menos tanto tiempo como se necesiten los resultados de cpl_complete_word() .

El cont_suffix es un sufijo de continuación a añadir a la palabra completada en la línea de entrada si este es el único completado. Esto es algo que no es parte del completado en sí, pero que le da al usuario una indicación sobre cómo podría continuar para extender el token. Por ejemplo, la función de retorno de completado de archivos añade un separador de directorio si la palabra completada es un directorio. Si la palabra completada fuera un nombre de función, podría de manera similar ayudar al usuario haciendo que se añada un paréntesis de apertura.

NAME

cpl_complete_word, cpl_matches_destroy, cpl_last_error, cpl_recall_matches, cpl_list_completions - word completion functions

SYNOPSIS

#include <tecla.h>
CplMatches *cpl_complete_word(WordCompletion *cpl, int *token_start,
                              int *token_end, const char *line, int cursor,
                              CplMatchFn *match_fn, void *data);
void cpl_matches_destroy(WordCompletion *cpl, CplMatches *matches);
const char *cpl_last_error(WordCompletion *cpl);
CplMatches *cpl_recall_matches(WordCompletion *cpl);
int cpl_list_completions(CplMatches *result, FILE *fp,
                         int terminal_width);

DESCRIPTION

The gl_get_line(3) function, used for implementing command-line editing, uses the functions in this module to perform word completion. The WordCompletion object is created by calling new_WordCompletion(), and destroyed by calling del_WordCompletion().

If word completion is requested, the gl_get_line() function will call cpl_complete_word(). This function examines the arguments line and cursor, and determines the word that is being completed. It does this by searching backwards from the cursor position for the start of the word. The arguments token_start and token_end are pointers to integer variables, which will be set to the start and end positions of the word found. These arguments are optional, and can be set to NULL if you don't need this information.

The match_fn argument is the function pointer of the callback function which will lookup possible completions of the word, as described above, and the data argument provides a way for the application to pass arbitrary data to the callback function.

If no errors occur, the cpl_complete_word() function returns a pointer to a CplMatches container, as defined below. This container is allocated as part of the cpl object that was passed to cpl_complete_word(), and will thus change on each call which uses the same cpl argument.

  typedef struct {
    char *completion;        /* A matching completion */
                             /*  string */
    char *suffix;            /* The part of the */
                             /*  completion string which */
                             /*  would have to be */
                             /*  appended to complete the */
                             /*  original word. */
    const char *type_suffix; /* A suffix to be added when */
                             /*  listing completions, to */
                             /*  indicate the type of the */
                             /*  completion. */
  } CplMatch;
  typedef struct {
    char *suffix;            /* The common initial part */
                             /*  of all of the completion */
                             /*  suffixes. */
    const char *cont_suffix; /* Optional continuation */
                             /*  string to be appended to */
                             /*  the sole completion when */
                             /*  nmatch==1. */
    CplMatch *matches;       /* The array of possible */
                             /*  completion strings, */
                             /*  sorted into lexical */
                             /*  order. */
    int nmatch;              /* The number of elements in */
                             /*  the above matches[] */
                             /*  array. */
  } CplMatches;

If an error occurs during completion, cpl_complete_word() returns NULL. A description of the error can be acquired by calling the cpl_last_error() function.

  const char *cpl_last_error(WordCompletion *cpl);

The cpl_last_error() function returns a terse description of the error which occurred on the last call to cpl_complete_word() or cpl_add_completion().

  CplMatches *cpl_recall_matches(WordCompletion *cpl);

As a convenience, the return value of the last call to cpl_complete_word() can be recalled at a later time by calling cpl_recall_matches(). If cpl_complete_word() returned NULL, so will cpl_recall_matches().

  int cpl_list_completions(CplMatches *result, FILE *fp,
                           int terminal_width);

When the cpl_complete_word() function returns multiple possible completions, the cpl_list_completions() function can be called upon to list them, suitably arranged across the available width of the terminal. It arranges for the displayed columns of completions to all have the same width, set by the longest completion. It also appends the type_suffix strings that were recorded with each completion, thus indicating their types to the user.

The cpl_matches_destroy() function should be called to free the memory used by a CplMatches container. Note that this container is allocated as part of the WordCompletion object, so it should not be freed directly.

THE BUILT-IN FILENAME-COMPLETION CALLBACK

By default the gl_get_line(3) function, passes the following completion callback function to cpl_complete_word(). This function can also be used separately, either by sending it to cpl_complete_word(), or by calling it directly from your own completion callback function.

  CPL_MATCH_FN(cpl_file_completions);

Certain aspects of the behavior of this callback can be changed via its data argument. If you are happy with its default behavior you can pass NULL in this argument. Otherwise it should be a pointer to a CplFileConf object, previously allocated by calling new_CplFileConf().

  CplFileConf *new_CplFileConf(void);

CplFileConf objects encapsulate the configuration parameters of cpl_file_completions(). These parameters, which start out with default values, can be changed by calling the accessor functions described below.

By default, the cpl_file_completions() callback function searches backwards for the start of the filename being completed, looking for the first un-escaped space or the start of the input line. If you wish to specify a different location, call cfc_file_start() with the index at which the filename starts in the input line. Passing start_index=-1 re-enables the default behavior.

  void cfc_file_start(CplFileConf *cfc, int start_index);

By default, when cpl_file_completions() looks at a filename in the input line, each lone backslash in the input line is interpreted as being a special character which removes any special significance of the character which follows it, such as a space which should be taken as part of the filename rather than delimiting the start of the filename. These backslashes are thus ignored while looking for completions, and subsequently added before spaces, tabs and literal backslashes in the list of completions. To have unescaped backslashes treated as normal characters, call cfc_literal_escapes() with a non-zero value in its literal argument.

  void cfc_literal_escapes(CplFileConf *cfc, int literal);

By default, cpl_file_completions() reports all files who's names start with the prefix that is being completed. If you only want a selected subset of these files to be reported in the list of completions, you can arrange this by providing a callback function which takes the full pathname of a file, and returns 0 if the file should be ignored, or 1 if the file should be included in the list of completions. To register such a function for use by cpl_file_completions(), call cfc_set_check_fn(), and pass it a pointer to the function, together with a pointer to any data that you would like passed to this callback whenever it is called. Your callback can make its decisions based on any property of the file, such as the filename itself, whether the file is readable, writable or executable, or even based on what the file contains.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);
  void cfc_set_check_fn(CplFileConf *cfc,
                        CplCheckFn *chk_fn, void *chk_data);

The cpl_check_exe() function is a provided callback of the above type, for use with cpl_file_completions(). It returns non-zero if the filename that it is given represents a normal file that the user has execute permission to. You could use this to have cpl_file_completions() only list completions of executable files.

When you have finished with a CplFileConf variable, you can pass it to the del_CplFileConf() destructor function to reclaim its memory.

  CplFileConf *del_CplFileConf(CplFileConf *cfc);

THREAD SAFETY

In multi-threaded programs, you should use the libtecla_r.a version of the library. This uses POSIX reentrant functions where available (hence the _r suffix), and disables features that rely on non-reentrant system functions. In the case of this module, the only disabled feature is username completion in ~username/ expressions, in cpl_file_completions().

Using the libtecla_r.a version of the library, it is safe to use the facilities of this module in multiple threads, provided that each thread uses a separately allocated WordCompletion object. In other words, if two threads want to do word completion, they should each call new_WordCompletion() to allocate their own completion objects.
