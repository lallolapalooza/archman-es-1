distribution_type

Ejemplo:

distribution_type: module

(Spec 1.0) [opcional] {string} Qué tipo de contenido contiene esta distribución. La mayoría de las cosas en CPAN son "module"s (lo que también puede significar una colección de módulos), pero algunas cosas son "script"s.

Desafortunadamente, este campo es básicamente sin sentido, ya que muchas distribuciones son híbridos de varios tipos de cosas, o algo nuevo, o subjetivamente diferentes en enfoque dependiendo de quién las use. Herramientas como Module::Build y MakeMaker probablemente dejarán de generar este campo.

requires

Ejemplo:

requires:
  Data::Dumper: 0
  File::Find: 1.03

(Spec 1.0) [opcional] {map} Un mapeo YAML que indica los módulos de Perl que esta distribución requiere para su correcto funcionamiento. Las claves son los nombres de los módulos, y los valores son especificaciones de versión como se describe en "VERSION SPECIFICATIONS".

recommends

Ejemplo:

recommends:
  Data::Dumper: 0
  File::Find: 1.03

(Spec 1.0) [opcional] {map} Un mapeo YAML que indica los módulos de Perl que esta distribución recomienda para una operación mejorada. Las claves son los nombres de los módulos, y los valores son especificaciones de versión como se describe en "VERSION SPECIFICATIONS".

ALTERNATIVA: Puede ser deseable presentar al usuario qué características dependen de qué módulos para que pueda tomar una decisión informada sobre qué módulos recomendados instalar.

Ejemplo:

optional_features:
- foo:
    description: Proporciona la capacidad de hacer algo.
    requires:
      Data::Dumper: 0
      File::Find: 1.03
- bar:
    description: Esta característica no está disponible en esta plataforma.
    excludes_os: MSWin32

(Spec 1.1) [opcional] {map} Una secuencia YAML de nombres para características opcionales que están disponibles cuando se cumplen sus requisitos. Para cada característica se proporciona una descripción junto con cualquiera de "requires", "build_requires", "conflicts", "requires_packages", "requires_os", y "excludes_os" que tienen el mismo significado en este subcontexto como se describe en otra parte de este documento.

build_requires

Ejemplo:

build_requires:
  Data::Dumper: 0
  File::Find: 1.03

(Spec 1.0) [opcional] {map} Un mapeo YAML que indica los módulos de Perl requeridos para la construcción y/o prueba de esta distribución. Las claves son los nombres de los módulos, y los valores son especificaciones de versión como se describe en "VERSION SPECIFICATIONS". Estas dependencias no son requeridas después de que el módulo esté instalado.

conflicts

Ejemplo:

conflicts:
  Data::Dumper: 0
  File::Find: 1.03

(Spec 1.0) [opcional] {map} Un mapeo YAML que indica los módulos de Perl que no pueden estar instalados mientras esta distribución está instalada. Esta es una situación bastante poco común. Las claves para "conflicts" son los nombres de los módulos, y los valores son especificaciones de versión como se describe en "VERSION SPECIFICATIONS".

dynamic_config

Ejemplo:

dynamic_config: 0

(Spec 1.0) [opcional] {boolean} Un indicador booleano que indica si un Build.PL o Makefile.PL (o similar) debe ser ejecutado al construir esta distribución, o si puede ser construida, probada e instalada únicamente consultando su archivo de metadatos. La razón principal para establecer esto en un valor verdadero es que tu módulo realiza alguna configuración dinámica (hacer preguntas, detectar el entorno, etc.) como parte de su proceso de construcción/instalación.

Actualmente Module::Build no hace realmente nada con este indicador - probablemente dependerá de herramientas de nivel superior como CPAN para hacer algo útil con él. Potencialmente puede traer muchas mejoras de seguridad, empaquetado y conveniencia.

Si este campo se omite, por defecto es 1 (verdadero).

provides

Ejemplo:

provides:
  Foo::Bar:
    file: lib/Foo/Bar.pm
    version: 0.27_02
  Foo::Bar::Blah:
    file: lib/Foo/Bar/Blah.pm
  Foo::Bar::Baz:
    file: lib/Foo/Bar/Baz.pm
    version: 0.3

(Spec 1.1) [opcional] {map} Un mapeo YAML que describe todos los paquetes proporcionados por esta distribución. Esta información puede ser (y, en algunos casos, es) usada por mecanismos de distribución y automatización como PAUSE, CPAN y search.cpan.org para construir índices que dicen en qué distribución se pueden encontrar varios paquetes.

Cuando uses herramientas como Module::Build que pueden generar el mapeo "provides" para tu distribución automáticamente, asegúrate de examinar lo que genera para asegurarte de que tiene sentido - los indexadores usualmente confiarán en el campo "provides" si está presente, en lugar de escanear los archivos de la distribución para averiguar paquetes y versiones. Esto es bueno, porque significa que puedes usar el campo "provides" para decirle a los indexadores exactamente qué quieres que indexen sobre tu distribución, en lugar de depender de que esencialmente adivinen qué quieres que indexen.

no_index

Ejemplo:

no_index:
  file:
  - My/Module.pm
  directory:
  - My/Private
  package:
  - My::Module::Stuff
  namespace:
  - My::Module::Stuff

(Spec 1.1) [opcional] {map} Un mapeo YAML que describe cualquier archivo, directorio, paquete y espacio de nombres que son privados (es decir, artefactos de implementación) que no son de interés para herramientas de búsqueda e indexación. Esto es útil cuando no hay un campo "provides" presente.

Por ejemplo, http://search.cpan.org/ excluye los elementos listados en "no_index" al buscar POD, lo que significa que los archivos en estos directorios no serán convertidos a HTML y hechos públicos - lo cual es útil si tienes PODs de ejemplo o prueba que no quieres que el motor de búsqueda recorra.

file

(Spec 1.1) [opcional] Excluye cualquier archivo listado.

directory

(Spec 1.1) [opcional] Excluye cualquier cosa debajo del directorio(s) listado(s).

[Nota: ediciones anteriores de la especificación tenían "dir" en lugar de "directory", pero creo que MakeMaker y varios usuarios empezaron a usar "directory", así que por deferencia cambiamos a eso.]

package

(Spec 1.1) [opcional] Excluye el paquete(s) listado(s).

namespace

(Spec 1.1) [opcional] Excluye cualquier cosa debajo del espacio de nombres listado(s), pero no el espacio de nombres listado(s) en sí mismo.

ESPECIFICACIONES DE VERSIÓN

Algunos campos requieren una especificación de versión (ej. "requires", "recommends", "build_requires", etc.) para indicar la(s) versión(es) particular(es) de algún otro módulo que pueda ser requerido como prerrequisito. Esta sección detalla los formatos de especificación de versión que se admiten actualmente.

El formato más simple para una especificación de versión es simplemente el número de versión en sí, por ejemplo, 2.4. Esto significa que al menos la versión 2.4 debe estar presente. Para indicar que cualquier versión de un prerrequisito es aceptable, incluso si el prerrequisito no define una versión en absoluto, use la versión 0.

También puede usar los operadores < (menor que), <= (menor o igual), > (mayor que), >= (mayor o igual), == (igual), y != (distinto de). Por ejemplo, la especificación < 2.0 significa que cualquier versión del prerrequisito menor que 2.0 es adecuada.

Para situaciones más complicadas, las especificaciones de versión pueden combinarse con AND usando comas. La especificación >= 1.2, != 1.5, < 2.0 indica una versión que debe ser al menos 1.2, menor que 2.0, y distinta de 1.5.
