CPAN::Meta(3perl) Guía de Referencia para Programadores de Perl CPAN::Meta(3perl)

NOMBRE

CPAN::Meta - los metadatos de la distribución para una dist de CPAN

VERSIÓN

versión 2.150010

SINOPSIS

use v5.10;
use strict;
use warnings;
use CPAN::Meta;
use Module::Load;
my $meta = CPAN::Meta->load_file('META.json');
printf "probando requisitos para %s versión %s\n",
$meta->name,
$meta->version;
my $prereqs = $meta->effective_prereqs;
for my $phase ( qw/configure runtime build test/ ) {
    say "Requisitos para $phase:";
    my $reqs = $prereqs->requirements_for($phase, "requires");
    for my $module ( sort $reqs->required_modules ) {
        my $status;
        if ( eval { load $module unless $module eq 'perl'; 1 } ) {
            my $version = $module eq 'perl' ? $] : $module->VERSION;
            $status = $reqs->accepts_module($module, $version)
                    ? "$version ok" : "$version no ok";
        } else {
            $status = "faltante"
        };
        say "  $module ($status)";
    }
}

DESCRIPCIÓN

Las distribuciones de software publicadas en CPAN incluyen un META.json o, para distribuciones más antiguas, META.yml, que describe la distribución, su contenido y los requisitos para construir e instalar la distribución. La estructura de datos almacenada en el archivo META.json se describe en CPAN::Meta::Spec.

CPAN::Meta proporciona una clase simple para representar estos metadatos de la distribución (o distmeta), junto con algunos métodos útiles para interrogar esos datos.

La documentación siguiente es solo para los métodos del objeto CPAN::Meta. Para información sobre el significado de campos individuales, consulte la especificación.

MÉTODOS

new

my $meta = CPAN::Meta->new($distmeta_struct, \%options);

Devuelve un objeto CPAN::Meta válido o muere si la referencia hash de metadatos proporcionada no supera la validación. Los metadatos en formato antiguo se convertirán a la versión 2 si validan contra la especificación original declarada.

Acepta una referencia hash opcional de opciones. Las opciones válidas incluyen:

•
lazy_validation -- si es verdadero, new intentará convertir los metadatos dados a la versión 2 antes de intentar validarlos. Esto significa que cualquier error corregible será manejado por CPAN::Meta::Converter antes de la validación. (Tenga en cuenta que esto podría resultar en que datos opcionales inválidos sean descartados silenciosamente.) El valor por defecto es falso.

create

my $meta = CPAN::Meta->create($distmeta_struct, \%options);

Esto es lo mismo que new(), excepto que los campos "generated_by" y "meta-spec" se generarán si no se proporcionan. Esto significa que se asume que la estructura de metadatos sigue la última CPAN::Meta::Spec.

load_file

my $meta = CPAN::Meta->load_file($distmeta_file, \%options);

Dada una ruta de archivo a un archivo que contiene metadatos, este método deserializa el archivo de acuerdo con su sufijo y construye un nuevo objeto "CPAN::Meta" , igual que new(). Morirá si la versión deserializada no supera la validación contra su versión de especificación declarada.

Acepta las mismas opciones que new() pero "lazy_validation" tiene como valor por defecto true.

load_yaml_string

my $meta = CPAN::Meta->load_yaml_string($yaml, \%options);

Este método devuelve un nuevo objeto CPAN::Meta usando el primer documento en la cadena YAML dada. En otros aspectos es idéntico a load_file().

load_json_string

my $meta = CPAN::Meta->load_json_string($json, \%options);

Este método devuelve un nuevo objeto CPAN::Meta usando la estructura representada por la cadena JSON dada. En otros aspectos es idéntico a load_file().

load_string

my $meta = CPAN::Meta->load_string($string, \%options);

Si no sabe si una cadena contiene YAML o JSON, este método usará Parse::CPAN::Meta para adivinarlo. En otros aspectos es idéntico a load_file().

save

$meta->save($distmeta_file, \%options);

Serializa el objeto como JSON y lo escribe en el archivo dado. La única opción válida es "version", que tiene como valor por defecto '2'. En Perl 5.8.1 o posterior, el archivo se guarda con codificación UTF-8.

Para "version" 2 (o superior), el nombre de archivo debe terminar en '.json'. JSON::PP es el backend JSON por defecto. Usar otro backend JSON requiere JSON 2.5 o posterior y debe establecer $ENV{PERL_JSON_BACKEND} a un backend alternativo soportado como JSON::XS.

Para "version" menor que 2, el nombre de archivo debe terminar en '.yml'. Se usa CPAN::Meta::Converter para generar una estructura de metadatos más antigua, que se serializa a YAML. CPAN::Meta::YAML es el backend YAML por defecto. Puede establecer $ENV{PERL_YAML_BACKEND} a un backend alternativo soportado, aunque esto no se recomienda debido a incompatibilidades sutiles entre analizadores YAML en CPAN.

meta_spec_version

Este método devuelve la parte de versión de la entrada "meta_spec" en la estructura distmeta. Es equivalente a:

$meta->meta_spec->{version};

effective_prereqs

my $prereqs = $meta->effective_prereqs;
my $prereqs = $meta->effective_prereqs( \@feature_identifiers );

Este método devuelve un objeto CPAN::Meta::Prereqs que describe todos los prerequisitos para la distribución. Si se da una referencia a array de identificadores de características, los prerequisitos de las características identificadas se fusionan con los prerequisitos principales de la distribución antes de devolver el objeto CPAN::Meta::Prereqs.

should_index_file

... if $meta->should_index_file( $filename );

Este método devuelve true si el archivo dado debe ser indexado. Decide esto comprobando las claves "file" y "directory" en la propiedad "no_index" de la estructura distmeta. Tenga en cuenta que ni el formato de versión ni "release_status" son considerados.

$filename debe darse en formato unix.

should_index_package

... if $meta->should_index_package( $package );

Este método devuelve true si el paquete dado debe ser indexado. Decide esto comprobando las claves "package" y "namespace" en la propiedad "no_index" de la estructura distmeta. Tenga en cuenta que ni el formato de versión ni "release_status" son considerados.

features

my @feature_objects = $meta->features;

Este método devuelve una lista de objetos CPAN::Meta::Feature, uno por cada característica opcional descrita por los metadatos de la distribución.

feature

my $feature_object = $meta->feature( $identifier );

Este método devuelve un objeto CPAN::Meta::Feature para la característica opcional con el identificador dado. Si no existe ninguna característica con ese identificador, se se lanzará una excepción.

as_struct

my $copy = $meta->as_struct( \%options );

Este método devuelve una copia profunda de los metadatos del objeto como una referencia a hash sin bendecir (unblessed). Acepta una referencia a hash opcional de opciones. Si la referencia a hash contiene un "version" argumento, los metadatos copiados se convertirán a la versión de la especificación y se devolverán. Por ejemplo:

my $old_spec = $meta->as_struct( {version => "1.4"} );

as_string

my $string = $meta->as_string( \%options );

Este método devuelve una copia serializada de los metadatos del objeto como una cadena de caracteres. (Las cadenas no están codificadas en UTF-8.) Acepta una referencia a hash opcional de opciones. Si la referencia a hash contiene un "version" argumento, los metadatos copiados se convertirán a la versión de la especificación y se devolverán. Por ejemplo:

my $string = $meta->as_string( {version => "1.4"} );

Para "version" mayor o igual a 2, la cadena se serializará como JSON. Para "version" menor que 2, la cadena se serializará como YAML. En ambos casos, se siguen las mismas reglas que en el save() método para elegir un backend de serialización.

La estructura serializada incluirá una "x_serialization_backend" entrada que indica el paquete y la versión utilizados para serializar. Cualquier clave existente en el $meta objeto dado será sobrescrita.

DATOS DE CADENA

Los siguientes métodos devuelven un único valor, que es el valor de la entrada correspondiente en la estructura distmeta. Los valores deben ser o bien undef o cadenas.

  • abstract
  • description
  • dynamic_config
  • generated_by
  • name
  • release_status
  • version

DATOS DE LISTA

Estos métodos devuelven listas de valores de cadena, que podrían estar representados en la estructura distmeta como referencias a arrays o escalares:

  • authors
  • keywords
  • licenses

Los "authors" y "licenses" métodos también pueden ser llamados como "author" y "license", respectivamente, para coincidir con el nombre del campo en la estructura distmeta.

DATOS DE MAPA

Estos lectores devuelven referencias a hash de estructuras de datos arbitrarias sin bendecir, cada una descrita con más detalle en la especificación:

  • meta_spec
  • resources
  • provides
  • no_index
  • prereqs
  • optional_features

DATOS PERSONALIZADOS

Una lista de claves personalizadas está disponible desde el "custom_keys" método y las claves particulares pueden ser recuperadas con el "custom" método.

say $meta->custom($_) for $meta->custom_keys;

Si una clave personalizada se refiere a una estructura de datos, se devuelve una copia profunda (deep clone).
