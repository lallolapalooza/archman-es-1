DESCRIPCIÓ

N

La estructura de datos cpu_set_t representa un conjunto de CPU. Los conjuntos de CPU son utilizados por sched_setaffinity(2) y interfaces

similares.

El tipo de datos cpu_set_t está implementado como una máscara de bits. Sin embargo, la estructura de datos debe tratarse como opaca: toda manipulación de conjuntos de CPU debe hacerse mediante las macros descritas en esta

página.

Se proporcionan las siguientes macros para operar sobre el conjunto de CPU set

:
CPU_ZERO
()
Limpia set, de modo que no contenga ninguna
CPU.
CPU_SET
()
Añade la CPU cpu a set
.
CPU_CLR
()
Elimina la CPU cpu de set
.
CPU_ISSET
()
Comprueba si la CPU cpu es miembro de set
.
CPU_COUNT
()
Devuelve el número de CPU en se
t
.

Cuando se especifica un argumento cpu, este no debe producir efectos secundarios, ya que las macros anteriores pueden evaluar el argumento más de una

vez.

La primera CPU del sistema corresponde a un valor de cpu de 0, la siguiente CPU corresponde a un valor de cpu de 1, y así sucesivamente. No se deben hacer suposiciones sobre la disponibilidad de CPUs particulares, ni que el conjunto de CPUs sea contiguo, ya que las CPUs pueden desconectarse dinámicamente o estar ausentes por otras razones. La constante CPU_SETSIZE (actualmente 1024) especifica un valor mayor en uno que el número máximo de CPU que puede almacenarse en cpu_set_t

.

Las siguientes macros realizan operaciones lógicas sobre conjuntos de

CPU:
CPU_AND
()
Almacena la intersección de los conjuntos srcset1 y srcset2 en destset (que puede ser uno de los conjuntos de origen)
.
CPU_OR
()
Almacena la unión de los conjuntos srcset1 y srcset2 en destset (que puede ser uno de los conjuntos de origen)
.
CPU_XOR
()
Almacena el XOR de los conjuntos srcset1 y srcset2 en destset (que puede ser uno de los conjuntos de origen). El XOR significa el conjunto de CPUs que están en srcset1 o en srcset2, pero no en
ambos.
CPU_EQUAL
()
Comprueba si dos conjunt
os de CPU contienen exa
ctamente las mismas CPU.

Conjuntos de CPU de tamaño

dinámico

Dado que algunas aplicaciones pueden requerir la capacidad de dimensionar dinámicamente los conjuntos de CPU (p. ej., para asignar conjuntos más grandes que los definidos por el tipo de datos estándar cpu_set_t), glibc actualmente proporciona un conjunto de macros para soportar

esto.

Las siguientes macros se utilizan para asignar y desasignar conjuntos de

CPU:
CPU_ALLOC
()
Asigna un conjunto de CPU lo suficientemente grande como para contener las CPU en el rango de 0 a num_cpus-
1.
CPU_ALLOC_SIZ
E()
Devuelve el tamaño en bytes del conjunto de CPU que se necesitaría para contener las CPU en el rango de 0 a num_cpus-1. Esta macro proporciona el valor que puede usarse para el argumento setsize en las macros CPU_*_S() descritas a
continuación.
CPU_FREE
()
Libera un conjunto de CPU previamente asignado por CPU_AL

NOTA

S

Para duplicar un conjunto de CPU, use memcpy(

3).

Dado que los conjuntos de CPU son máscaras de bits asignadas en unidades de palabras largas, el número real de CPU en un conjunto de CPU asignado dinámicamente se redondeará al siguiente múltiplo de sizeof(unsigned long). Una aplicación debe considerar el contenido de estos bits extra como

indefinido.

A pesar de la similitud en el nombres, ten en cuenta que la constante CPU_SETSIZE indica el número de CPUs en el tipo de datos cpu_set_t (por lo tanto, es efectivamente un recuento de los bits en la máscara de bits), mientras que el argumento setsize de las macros CPU_*_S() es un tamaño en

bytes.

Los tipos de datos para los argumentos y los valores de retorno mostrados en la SINOPSIS son pistas

sobre lo que se espera en cada caso. Sin embargo, dado que estas interfaces se implementan como mac
ros, el compilador no capturará necesariamente todos los errores de tipo si violas las sugerencias.

ERRORE

S

En plataformas de 32 bits con glibc 2.8 y versiones anteriores, CPU_ALLOC() asigna el doble de espacio del necesario, y CPU_ALLOC_SIZE() devuelve un valor el doble de grande de lo que debería. Este error no debería afectar a la semántica de un programa, pero sí resulta en memoria

desperdiciada y una operación menos eficiente de las macros que operan sobre conj
untos de CPU asignados dinámicamente. Estos errores se corrigieron en glibc 2.9.

EJEMPLO

S

El siguiente programa demuestra el uso de algunas de las macros utilizadas para conjuntos de CPU asignados

dinámicamente. 
#define _GNU_SOURCE
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <assert.h>
int
main(int argc, char *argv[])
{
    cpu_set_t *cpusetp;
    size_t size, num_cpus;
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <num-cpus>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    num_cpus = atoi(argv[1]);
    cpusetp = CPU_ALLOC(num_cpus);
    if (cpusetp == NULL) {
        perror("CPU_ALLOC");
        exit(EXIT_FAILURE);
    }
    size = CPU_ALLOC_SIZE(num_cpus);
    CPU_ZERO_S(size, cpusetp);
    for (size_t cpu = 0; cpu < num_cpus; cpu += 2)
        CPU_SET_S(cpu, size, cpusetp);
    printf("CPU_COUNT() of set:    %d\n", CPU_COUNT_S(size, cpusetp));
    CPU_FREE(cpusetp);
    exit(EXIT_SUCCESS);
}
