CURLOPT_NOSIGNAL(3)

Paquete: curl

Licencias: MIT

CURLOPT_NOSIGNAL(3) Manual de funciones de biblioteca CURLOPT_NOSIGNAL(3)

NOMBRE

CURLOPT_NOSIGNAL - omitir todo el manejo de señales

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_NOSIGNAL, long onoff);

DESCRIPCIÓN

Si onoff es 1, libcurl no utiliza ninguna función que instale manejadores de señales o cualquier función que cause que se envíen señales al proceso. Esta opción está aquí para permitir que las aplicaciones Unix multihilo aún configuren/utilicen todas las opciones de tiempo de espera, etc., sin arriesgarse a recibir señales.

Si esta opción se establece y libcurl se ha compilado con el resolvedor de nombres estándar, los tiempos de espera no pueden ocurrir mientras se resuelve el nombre. Considere compilar libcurl con los backends de c-ares o de resolvedor con hilos para habilitar búsquedas DNS asíncronas, para habilitar tiempos de espera para la resolución de nombres sin el uso de señales.

Establecer CURLOPT_NOSIGNAL(3) en 1 hace que libcurl NO solicite al sistema que ignore las señales SIGPIPE, que de lo contrario son enviadas por el sistema al intentar enviar datos a un socket que está cerrado en el otro extremo. libcurl hace un esfuerzo para nunca causar que tales señales SIGPIPE se activen, pero algunos sistemas operativos no tienen forma de evitarlas e incluso en aquellos que las tienen, existen algunos casos extremos en los que aún pueden ocurrir, en contra de nuestro deseo.

PREDETERMINADO

0

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    curl_easy_setopt(curl, CURLOPT_NOSIGNAL, 1L);
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.10

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, ver libcurl-errors(3).
