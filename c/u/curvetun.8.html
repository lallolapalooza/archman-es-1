NOMBRE

curvetun - un túnel IP4/6 ligero curve25519

SINOPSIS

curvetun [opciones]

DESCRIPCIÓN

curvetun es un túnel IP de múltiples usuarios ligero y de alta velocidad basado en ECDH para Linux que se basa en epoll(2). curvetun utiliza la interfaz TUN/TAP de Linux y soporta {IPv4, IPv6} sobre {IPv4, IPv6} con UDP o TCP como protocolos de transporte.

Tiene un árbol de reenvío de paquetes integrado, por lo que se pueden manejar múltiples usuarios con diferentes IPs a través de un único dispositivo de túnel en el lado del servidor, y los flujos se programan para su procesamiento de manera eficiente en la CPU, al menos en el caso de TCP como protocolo de transporte.

Para la gestión de claves, se utiliza criptografía de clave pública basada en curvas elípticas y los paquetes se cifran de extremo a extremo mediante el cifrador de flujo simétrico Salsa20 y se autentican mediante el MAC Poly1305, donde las claves se han calculado previamente con el protocolo de acuerdo de claves ECDH Curve25519.

La criptografía se basa en la biblioteca de redes y criptografía “NaCl” de Daniel J. Bernstein. Por diseño, curvetun no proporciona ningún patrón particular o números de puerto predeterminados que brinden certeza de que la conexión de un flujo particular realmente está ejecutando curvetun.

Sin embargo, si necesita eludir la censura, puede intentar usar curvetun en combinación con obfsproxy o Telex de Tor. Además, curvetun también lo protege contra ataques de repetición y ataques man-in-the-middle DH. Adicionalmente, el registro de eventos de syslog en el lado del servidor también se puede deshabilitar para evitar revelar datos críticos de conexión del usuario.

OPCIONES

-d <tundev>, --dev <tundev>
Define el nombre del dispositivo de túnel que se está creando. Si esta opción no se establece, se utilizan los nombres predeterminados, curves{0,1,2,..} para un servidor curvetun, y curvec{0,1,2,...} para un cliente curvetun.
-p <num>, --port <num>
Define el puerto en el que debe escuchar el servidor curvetun. No hay un puerto predeterminado para curvetun, por lo que establecer esta opción para el arranque del servidor es obligatorio. Esta opción es solo para servidores.
-t <servidor>, --stun <servidor>
Si es necesario, esta opción habilita una búsqueda STUN para mostrar el mapeo de IP pública a puerto y para perforar un agujero en el firewall. En caso de que no esté seguro de qué servidor STUN usar, simplemente use ''--stun stunserver.org''.
-c[=alias], --client[=alias]
Inicia curvetun en modo cliente y se conecta al alias de conexión dado que se define en el archivo de configuración.
-k, --keygen
Genera un par de claves privada y pública. Esto debe hacerse inicialmente.
-x, --export
Exporta la combinación de usuario y clave a la salida estándar como una sola línea.
-C, --dumpc
Muestra todos los clientes conocidos que pueden conectarse al servidor curvetun local y sale.
-S, --dumps
Muestra todos los servidores conocidos a los que curvetun como cliente puede conectarse y sale.
-D, --nofork
No se bifurca como cliente o servidor al arrancar.
-s, --server
Inicia curvetun en modo servidor. Se necesitan parámetros adicionales, al menos se requiere la definición del puerto al que los clientes pueden conectarse.
-N, --no-logging
Deshabilita todo el registro de información de usuario de curvetun. Esta opción se puede usar para permitir que los usuarios de curvetun se conecten de forma más anónima. Esta opción es solo para servidores.
-u, --udp
Usa UDP como protocolo de transporte en lugar de TCP. Por defecto, TCP es el protocolo de transporte. Esta opción es solo para servidores.
-4, --ipv4
Define IPv4 como el protocolo de red subyacente que se utilizará en el dispositivo de túnel. IPv4 es el valor predeterminado. Esta opción es solo para servidores.
-6, --ipv6
Define IPv6 como el protocolo de red subyacente que se utilizará en el dispositivo de túnel. Esta opción es solo para servidores.
-v, --version
Muestra información de la versión y sale.
-h, --help
Muestra la ayuda al usuario y sale.

EJEMPLO DE USO

curvetun --server -4 -u -N --port 6666 --stun stunserver.org
Inicia curvetun en modo servidor con IPv4 como protocolo de red y UDP como protocolo de transporte. El servidor curvetun escucha las conexiones entrantes en el puerto 6666 y realiza una búsqueda STUN al arrancar en stunserver.org.
curvetun --client=ethz
Inicia curvetun en modo cliente y se conecta al alias de conexión definido ''ethz'' que está definido en el archivo de configuración de servidores de curvetun ~/.curvetun/servers.
curvetun --keygen
Genera pares de claves iniciales y los almacena en el directorio ~/.curvetun/.
curvetun --export
Exporta datos de usuario a la salida estándar para la configuración de un servidor curvetun.

CRIPOGRAFÍA

Los túneles IP cifrados se utilizan a menudo para crear redes privadas virtuales (VPN), donde partes de la red solo son accesibles a través de un medio inseguro o no confiable como Internet. Solo existen unas pocas utilidades de software para crear tales túneles, o VPNs. Dos representantes populares de dicho software son OpenVPN y VTUN.

Este último también introdujo las interfaces TUN/TAP en el kernel de Linux. VTUN solo tiene un módulo de cifrado bastante básico, que no se ajusta a las necesidades criptográficas actuales. Por defecto, se utiliza MD5 para crear claves de 128 bits para el cifrador simétrico BlowFish en modo ECB [1].

Aunque OpenSSL se utiliza tanto en VTUN como en OpenVPN, OpenVPN es mucho más rico en funciones en cuanto a cifradores y autenticación de usuarios. Sin embargo, permitir que las personas elijan cifradores o métodos de autenticación no es necesariamente algo bueno: los administradores podrían preferir la velocidad sobre la seguridad y, por lo tanto, elegir cifradores débiles, de modo que el sistema de comunicación sea tan bueno como sin cifrado alguno; podrían elegir contraseñas débiles para el cifrado simétrico o podrían configurar incorrectamente el sistema de comunicación al tener demasiada opción de cifradores y poca experiencia para elegir el correcto.

Además de los problemas de administración, también existen problemas de desarrollo de software. Las bibliotecas criptográficas como OpenSSL son un gran desastre y demasiado de bajo nivel y complejas para entenderlas o aplicarlas correctamente, por lo que forman una base adicional para las vulnerabilidades de dicho software.

En 2010, los criptógrafos Tanja Lange y Daniel J. Bernstein crearon y publicaron una biblioteca criptográfica para redes, llamada NaCl (pronunciado ''salt''). NaCl aborda problemas como los mencionados en OpenSSL y, en contraste con el uso bastante genérico de OpenSSL, fue creado con un fuerte enfoque en el cifrado autenticado de clave pública basado en criptografía de curva elíptica, que se utiliza en curvetun. Citando parcialmente a Daniel J. Bernstein:

"RSA es algo más antiguo que la criptografía de curva elíptica: RSA se introdujo en 1977, mientras que la criptografía de curva elíptica se introdujo en 1985. Sin embargo, RSA ha mostrado muchas más debilidades que la criptografía de curva elíptica. El nivel de seguridad efectivo de RSA se vio drásticamente reducido por el tamiz lineal a finales de la década de 1970, por el tamiz cuadrático y ECM en la década de 1980, y por el tamiz de cuerpos numéricos en la década de 1990. Como comparación, se han desarrollado algunos ataques contra curvas elípticas raras con estructuras algebraicas especiales, y la cantidad de potencia informática av

IEEE P1363 estandarizó la criptografía de curvas elípticas a finales de los años 1990, incluyendo una estricta lista de criterios de seguridad para curvas elípticas. NIST utilizó los criterios de IEEE P1363 para seleccionar quince curvas elípticas específicas en cinco niveles de seguridad diferentes. En 2005, la NSA emitió un nuevo estándar ''Suite B'', recomendando las curvas elípticas de NIST (en dos niveles de seguridad específicos) para toda la criptografía de clave pública y retirando las recomendaciones anteriores de RSA.

curvetun utiliza una curva elíptica particular, Curve25519, introducida en el siguiente artículo: Daniel J. Bernstein, ''Curve25519: new Diffie-Hellman speed records,'' páginas 207-228 en Proceedings of PKC 2006, editado por Moti Yung, Yevgeniy Dodis, Aggelos Kiayias, y Tal Malkin, Lecture Notes in Computer Science 3958, Springer, 2006, ISBN

3-540-33851-9.

Esta curva elíptica sigue todos los criterios de seguridad estándar de IEEE P1363. También sigue nuevas recomendaciones que logran ''inmunidad a canales laterales'' y ''seguridad contra twist'' mientras mejoran la velocidad. Lo que esto significa es que las implementaciones seguras de Curve25519 son considerablemente más simples y rápidas que las implementaciones seguras de, por ejemplo, NIST P-256; hay menos oportunidades para que los implementadores cometan errores que comprometan la seguridad, y los errores son más fáciles de detectar por parte de los

revisores.

Un atacante que gasta mil millones de dólares en chips de propósito especial para atacar Curve25519, usando los mejores ataques disponibles hoy, tiene aproximadamente 1 oportunidad en 1000000000000000000000000000 de romper Curve25519 después de un año de computación. Se podrían lograr niveles de seguridad similares con RSA de 3000 bits, pero el cifrado y la autenticación con RSA de 3000 bits no son casi lo suficientemente rápidos para manejar el tráfico del túnel y requerirían mucho más espacio en los paquetes de

red.

SETUP

HOWTO

Si no has ejecutado curvetun antes, necesitas hacer una configuración inicial una

vez.

Primero, asegúrate de que los relojes de los servidores y clientes se sincronicen periódicamente, por ejemplo, ejecutando un demonio NTP. Esto es necesario para proteger contra ataques de repetición. También, asegúrate de tener acceso de lectura y escritura a /dev/net/tun. ¡No debes ejecutar curvetun como root! Luego, después de haber asegurado esto, el primer paso es generar claves y archivos de configuración. Tanto en el cliente como en el servidor

haz:

curvetun

-k

Se te pide un nombre de usuario. Puedes usar una dirección de correo electrónico o lo que te convenga. Aquí, asumimos que has ingresado 'mysrv1' en el servidor y 'myclient1' en el lado del

cliente.

Ahora, todos los archivos necesarios han sido creados bajo ~/.curvetun. Los archivos incluyen “priv.key”, “pub.key”, “username”, “clients” y

“servers”.

“clients” y “servers” están vacíos al principio y necesitan ser llenados. El archivo “clients” está destinado al servidor, para que sepa qué clientes están permitidos conectarse. El archivo “servers” es para el cliente, donde puede seleccionar servidores curvetun a los que conectarse. Ambos archivos se mantienen muy simples, de modo que una sola línea de configuración por cliente o servidor es

suficiente.

El cliente necesita exportar sus datos de clave pública para el

servidor

curvetun

-x

donde imprime una cadena en el siguiente

formato:


myclient1;11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11
\_______/ \_____________________________________________________________________________________________/
nombre de usuario clave pública de 32 bytes para

'myclient1'

como:


server$ echo "myclient1;11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:11:" \
"11:11:11:11:11:11:11:11:11:11:11:11:11:11:11" >> ~/.curvetun/client

-C

que imprime todos los clientes analizados de ''~/.curvetun/clients''. Este proceso podría automatizarse fácilmente o programarse con, por ejemplo, Perl y

LDAP.

Ahora, el cliente ''myclient1'' es conocido por el servidor; eso completa la configuración del servidor. El siguiente paso es decirle al cliente dónde necesita conectarse al

servidor.

Asumimos en este ejemplo que el servidor del túnel tiene una dirección IP pública, por ejemplo 1.2.3.4, se ejecuta en el puerto 6666 y usa UDP como protocolo de transporte. En caso de que estés detrás de NAT, puedes usar la opción ''--stun'' de curvetun para iniciar el servidor, para obtener tu mapeo. Sin embargo, en este ejemplo continuamos con 1.2.3.4 y 6666,

UDP.

sigue:
