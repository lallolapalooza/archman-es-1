DESCRIPCIÓ

N

CUnit es un sistema para escribir, administrar y ejecutar pruebas unitarias en C. Utiliza un marco de trabajo si

mple para construir estructuras de pruebas y proporciona un conjunto rico de aserciones para probar tipos de da
tos comunes. CUnit se construye como una biblioteca estática que se enlaza con el código de pruebas del usuario.

ESTRUCTURA Y USO

GENERAL

CUnit es una combinación de un marco de trabajo independiente de la plataforma con varias interfaces de usuario. El marco de trabajo central proporciona soporte básico para gestionar un registro de pruebas, suites y casos de prueba. Las interfaces de usuario facilitan la interacción con el marco de trabajo para ejecutar pruebas y ver

resultados.

La organización jerárquica básica de CUnit se muestra

aquí:


Registro de Pruebas
|
-----------------------------
| |
Suite '1' . . . . Suite 'N'
| |
--------------- ---------------
| | | |
Prueba '11' ... Prueba '1M' Prueba 'N1' ... Prueba 'NM'

Los casos de prueba individuales se empaquetan en suites, que se registran en el registro de pruebas activo. Las suites pueden tener funciones de configuración y limpieza que se llaman automáticamente antes y después de ejecutar las pruebas de la suite. Todas las suites/pruebas en el registro pueden ejecutarse con una sola llamada a función, o se pueden ejecutar suites o pruebas

seleccionadas.

El uso típico de CUnit

es:

1. Escribir funciones para las pruebas (y la inicialización/limpieza de la suite si es necesario)

.

2. Inicializar el registro de pruebas utilizando CU_initialize_registry(

)

3. Añadir suites de prueba al registro utilizando CU_add_suite(

)

4. Añadir casos de prueba a las suites utilizando CU_add_test(

)
5. Ejecutar pruebas utilizando la interfaz deseada, por
ejemplo
CU_console_run_tests() para
usar la consol
a interactiva.

6. Limpiar el registro de pruebas utilizando CU_cleanup_registry(

)

Todos los nombres públicos en CUnit tienen el prefijo 'CU_'. Esto ayuda a minimizar conflictos con nombres en el código del usuario. Tenga en cuenta que las versiones anteriores de CUnit usaban diferentes nombres sin este prefijo. Los nombres de la API más antiguos están obsoletos pero aún se admiten. Para usar los nombres más antiguos, el código del usuario debe compilarse ahora con USE_DEPRECATED_CUN

ESCRITURA DE FUNCIONES DE

PRUEBA

Una "prueba" es una función C con la firma: void test_func(void). No hay restricciones en el contenido de una función de prueba, excepto que no debe modificar el marco de trabajo de CUnit (por ejemplo, añadir suites o pruebas, modificar el registro de pruebas o iniciar una ejecución de pruebas). Una función de prueba puede llamar a otras funciones (que tampoco pueden modificar el marco de trabajo). Registrar una prueba hará que su función se ejecute cuando la prueba se

ejecute.

CUnit proporciona un conjunto de aserciones para probar condiciones lógicas. El éxito o el fracaso de estas aserciones es rastreado por el marco de trabajo y se puede ver cuando una ejecución de pruebas está completa. Cada aserción prueba una sola condición lógica y falla si la condición se evalúa como CU_FALSE. En caso de fallo, la prueba continúa a menos que el usuario elija la versión 'xxx_FATAL' de una aserción. En ese caso, la función de prueba retorna

inmediatamente.

CUnit proporciona un conjunto de aserciones para probar condiciones lógicas. El éxito o el fracaso de estas aserciones es rastreado por el marco de trabajo y se puede ver cuando una ejecución de pruebas está

completa.

Cada aserción prueba una sola condición lógica y falla si la condición se evalúa como CU_FALSE. En caso de fallo, la función de prueba continúa a menos que el usuario elija la versión 'xxx_FATAL' de una aserción. En ese caso, la función de prueba se aborta y retorna inmediatamente. Las versiones FATAL de las aserciones deben usarse con precaución. No hay oportunidad para que la función de prueba se limpie a sí misma una vez que una aserción FATAL falla. La función de limpieza normal de la suite no se ve afectada, sin

embargo.

También hay "aserciones" especiales para registrar un éxito o fallo con el marco de trabajo sin realizar una prueba lógica. Estas son útiles para probar el flujo de control u otras condiciones que no requieren una prueba

lógica.

Otras funciones llamadas por una función de prueba registrada pueden usar libremente las aserciones de CUnit. Estas aserciones se contarán para la función que las llama. También pueden usar versiones FATAL de las aserciones: el fallo abortará la función de prueba original y toda su cadena de

llamadas.

EJECUTANDO

PRUEBAS

CUnit soporta la ejecución de todas las pruebas en todas las suites registradas, pero también se pueden ejecutar pruebas o suites individuales. Durante cada ejecución, el framework mantiene un registro del número de suites, pruebas y aserciones ejecutadas, aprobadas y fallidas. Tenga en cuenta que los resultados anteriores se borran cada vez que se inicia una ejecución de pruebas (incluso si falla)

.

Aunque CUnit proporciona funciones primitivas para ejecutar suites y pruebas, la mayoría de los usuarios querrán usar una de las interfaces de usuario. Estas interfaces manejan los detalles de la interacción con el framework y proporcionan la salida de detalles y resultados de las pruebas para el usuario. Para más información sobre las funciones primitivas, vea <CUnit/testRun.h>

.

Error

Por defecto, CUnit continúa ejecutando pruebas cuando ocurre un error del marco. En este contexto, las aserciones fallidas no se consideran "errores del marco".
