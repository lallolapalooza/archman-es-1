curl_ws_send(3)

Paquete: curl

Licencias: MIT

curl_ws_send(3) Manual de funciones de biblioteca curl_ws_send(3)

NOMBRE

curl_ws_send - enviar datos de WebSocket

SINOPSIS

#include <curl/curl.h>
CURLcode curl_ws_send(CURL *curl, const void *buffer, size_t buflen,
                      size_t *sent, curl_off_t fragsize,
                      unsigned int flags);

DESCRIPCIÓN

Envía el fragmento de mensaje específico a través de una conexión WebSocket establecida. buffer debe apuntar a una ubicación de memoria válida que contenga (al menos) buflen bytes de memoria de carga útil.

sent se establece en el número de bytes de carga útil realmente enviados. Si el valor de retorno es CURLE_OK pero sent es menor que el buflen dado, libcurl no pudo consumir la carga útil completa en una sola llamada. En este caso, la aplicación debe llamar a esta función nuevamente hasta que se procese toda la carga útil. buffer y buflen deben actualizarse en cada invocación posterior para apuntar solo a la parte restante de la carga útil.

fragsize siempre debe establecerse en cero a menos que se vaya a enviar un marco (enorme) usando múltiples llamadas con contenido parcial por llamada explícitamente. En ese caso, debe establecer el bit CURLWS_OFFSET y establecer el fragsize como se documenta en la sección sobre CURLWS_OFFSET a continuación.

flags debe contener al menos una bandera que indique el tipo de mensaje. Para enviar un mensaje fragmentado que consta de múltiples marcos, establezca adicionalmente el bit CURLWS_CONT en todos los marcos excepto en el último. El bit de tipo de mensaje apropiado debe establecerse en cada marco de un mensaje fragmentado sin excepción. Omitir el tipo de mensaje para los marcos de continuación de un mensaje fragmentado solo se admite por compatibilidad con versiones anteriores y no se recomienda en absoluto.

Para obtener más detalles sobre las banderas admitidas, consulte a continuación y en curl_ws_meta(3).

Si CURLWS_RAW_MODE está habilitado en CURLOPT_WS_OPTIONS(3), el argumento flags debe establecerse en 0.

Advertencia: si bien es posible invocar esta función desde una función de devolución de llamada, tal llamada bloquea en esta situación, por ejemplo, solo regresa después de que se hayan enviado todos los datos o se haya encontrado un error.

FLAGS

Admite todas las banderas documentadas en curl_ws_meta(3) y además las siguientes banderas.

CURLWS_OFFSET
Los datos proporcionados son solo un marco parcial y hay más por venir en una llamada posterior a curl_ws_send(). Al enviar solo una parte del marco de esta manera, el fragsize debe proporcionarse con el tamaño total esperado del marco en la primera llamada y debe ser cero en todas las llamadas posteriores.

PROTOCOLOS

Esta funcionalidad afecta solo a ws

EJEMPLO

#include <string.h> /* para strlen */
int main(void)
{
  const char *buffer = "PAYLOAD";
  size_t offset = 0;
  CURLcode res = CURLE_OK;
  CURL *curl = curl_easy_init();
  curl_easy_setopt(curl, CURLOPT_URL, "wss://example.com/");
  curl_easy_setopt(curl, CURLOPT_CONNECT_ONLY, 2L);
  /* iniciar conexión HTTPS y actualizar a WSS, luego devolver control */
  curl_easy_perform(curl);
  while(!res) {
    size_t sent;
    res = curl_ws_send(curl, buffer + offset, strlen(buffer) - offset, &sent,
                       0, CURLWS_TEXT);
    offset += sent;
    if(res == CURLE_OK) {
      if(offset == strlen(buffer))
        break; /* fin de envío */
    }
    if(res == CURLE_AGAIN)
      /* en una aplicación real: esperar al socket aquí, por ejemplo, usando select() */
      res = CURLE_OK;
  }
  curl_easy_cleanup(curl);
  return (int)res;
}

DISPONIBILIDAD

Añadido en curl 7.86.0

VALOR DE RETORNO

Esta función devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, cualquier valor no cero indica un error, ver libcurl-errors(3). Si CURLOPT_ERRORBUFFER(3) se estableció con curl_easy_setopt(3), puede haber un mensaje de error almacenado en el búfer de error cuando se devuelve un valor distinto de cero.

En lugar de bloquear, la función devuelve CURLE_AGAIN. El comportamiento correcto es entonces esperar a que el socket señale que está listo para leer antes de llamar a esta función nuevamente.

Cualquier otro valor distinto de cero indica un error. Consulte la página del manual de libcurl-errors(3) para obtener la lista completa con descripciones.
