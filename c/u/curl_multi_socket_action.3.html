curl_multi_socket_action(3)

Paquete: curl

Licencias: MIT

curl_multi_socket_action(3) Manual de funciones de biblioteca curl_multi_socket_action(3)

NOMBRE

curl_multi_socket_action - leer/escribir datos disponibles dada una acción

SINOPSIS

#include <curl/curl.h>
CURLMcode curl_multi_socket_action(CURLM *multi_handle,
                                   curl_socket_t sockfd,
                                   int ev_bitmask,
                                   int *running_handles);

DESCRIPCIÓN

Cuando la aplicación ha detectado actividad en un socket manejado por libcurl, debe llamar a curl_multi_socket_action(3) con el argumento sockfd establecido al socket con la acción. Cuando se conocen los eventos en un socket, se pueden pasar como una máscara de bits de eventos ev_bitmask estableciendo primero ev_bitmask a 0, y luego agregando mediante OR a nivel de bits (|) cualquier combinación de eventos a elegir entre CURL_CSELECT_IN, CURL_CSELECT_OUT o CURL_CSELECT_ERR. Cuando se desconocen los eventos en un socket, pase 0 en su lugar, y libcurl prueba el descriptor internamente. También es permisible pasar CURL_SOCKET_TIMEOUT al parámetro sockfd para iniciar todo el proceso o cuando ocurre un tiempo de espera.

Al regresar, running_handles apunta al número de manejadores fáciles en ejecución dentro del manejador múltiple. Cuando este número llega a cero, todas las transferencias están completas/terminadas. Cuando llamas a curl_multi_socket_action(3) en un socket específico y el contador disminuye en uno, NO significa necesariamente que este socket/transferencia exacto es el que se completó. Usa curl_multi_info_read(3) para averiguar qué manejador fácil se completó.

La función curl_multi_socket_action(3) informa a la aplicación sobre las actualizaciones en el estado del socket (descriptor de archivo) al no realizar ninguna llamada, o realizar una o varias llamadas a la función de devolución de llamada del socket establecida con la opción CURLMOPT_SOCKETFUNCTION(3) en curl_multi_setopt(3). Actualizan el estado con los cambios desde la última vez que se llamó a la función de devolución de llamada.

Obtenga el tiempo de espera de tiempo de espera estableciendo la opción CURLMOPT_TIMERFUNCTION(3) con curl_multi_setopt(3). Su aplicación es llamada entonces con información sobre cuánto tiempo esperar por acciones de socket como máximo antes de realizar la acción de tiempo de espera: llame a la función curl_multi_socket_action(3) con el argumento sockfd establecido a CURL_SOCKET_TIMEOUT. También puede usar la función curl_multi_timeout(3) para sondear el valor en cualquier momento, pero para un sistema basado en eventos, usar la función de devolución de llamada es mucho mejor que depender de sondear el valor de tiempo de espera.

Cuando esta función devuelve un error, el estado de todas las transferencias es incierto y no pueden continuarse. curl_multi_socket_action(3) no debe llamarse nuevamente en el mismo manejador múltiple después de que se haya devuelto un error, a menos que primero se eliminen todos los manejadores y se agreguen nuevos.

USO TÍPICO

1. Crear un manejador múltiple

2. Establecer la función de devolución de llamada del socket con CURLMOPT_SOCKETFUNCTION(3)

3. Establecer la función de devolución de llamada de tiempo de espera con CURLMOPT_TIMERFUNCTION(3), para saber qué valor de tiempo de espera usar al esperar actividades de socket.

4. Agregar manejadores fáciles con curl_multi_add_handle()

5. Proporcionar algún medio para gestionar los sockets que libcurl está utilizando, para que pueda verificar su actividad. Esto se puede hacer a través del código de su aplicación, o mediante una biblioteca externa como libevent o glib.

6. Llame a curl_multi_socket_action(..., CURL_SOCKET_TIMEOUT, 0, ...) para iniciar todo. Para que se llamen una o más funciones de devolución de llamada.

7. Espere actividad en cualquiera de los sockets de libcurl, utilice el valor de tiempo de espera que se le ha indicado a su función de devolución de llamada.

8. Cuando se detecte actividad, llame a curl_multi_socket_action() para el(los) socket(s) que tuvieron acción. Si no se detecta actividad y expira el tiempo de espera, llame a curl_multi_socket_action(3) con CURL_SOCKET_TIMEOUT.

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles

EJEMPLO

int main(void)
{
  /* a la biblioteca de eventos se le dice cuándo hay actividad en el socket 'fd',
     lo que traducimos en una llamada a curl_multi_socket_action() */
  int running = 0;
  int fd = 3; /* el descriptor que tuvo acción */
  int bitmask = 2; /* qué actividad ocurrió */
  CURLM *multi = curl_multi_init();
  CURLMcode mc = curl_multi_socket_action(multi, fd, bitmask, &running);
  if(mc)
    printf("error: %s\n", curl_multi_strerror(mc));
}

DISPONIBILIDAD

Añadido en curl 7.15.4

VALOR DE RETORNO

Esta función devuelve un CURLMcode que indica éxito o error.

CURLM_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, consulte libcurl-errors(3).
