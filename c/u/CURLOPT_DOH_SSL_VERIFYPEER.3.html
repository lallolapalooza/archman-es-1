CURLOPT_DOH_SSL_VERIFYPEER(3)

Paquete: curl

Licencias: MIT

CURLOPT_DOH_SSL_VERIFYPEER(3) Manual de funciones de la biblioteca CURLOPT_DOH_SSL_VERIFYPEER(3)

NOMBRE

CURLOPT_DOH_SSL_VERIFYPEER - verificar el certificado SSL de DoH

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_DOH_SSL_VERIFYPEER,
                          long verify);

DESCRIPCIÓN

Pase un valor `long` como parámetro, establecido a 1L para habilitar o 0L para deshabilitar.

Esta opción le indica a curl que verifique la autenticidad del certificado del servidor DoH (DNS-over-HTTPS). Un valor de 1 significa que curl verifica; 0 (cero) significa que no lo hace.

Esta opción es el equivalente DoH de CURLOPT_SSL_VERIFYPEER(3) y solo afecta a las solicitudes al servidor DoH.

Al negociar una conexión TLS o SSL, el servidor envía un certificado que indica su identidad. curl verifica si el certificado es auténtico, es decir, si puede confiar en que el servidor es quien dice ser el certificado. Esta confianza se basa en una cadena de firmas digitales, ancladas en los certificados de la autoridad de certificación (CA) que usted suministra. curl utiliza un conjunto predeterminado de certificados de CA (cuya ruta se determina en tiempo de compilación) y puede especificar certificados alternativos con la opción CURLOPT_CAINFO(3) o la opción CURLOPT_CAPATH(3).

Cuando CURLOPT_DOH_SSL_VERIFYPEER(3) está habilitado y la verificación falla al probar que el certificado es auténtico, la conexión falla. Cuando la opción es cero, la verificación del certificado del par tiene éxito independientemente.

Autenticar el certificado no es suficiente para estar seguro sobre el servidor. Por lo general, también querrá asegurarse de que el servidor es el servidor con el que pretende hablar. Utilice CURLOPT_DOH_SSL_VERIFYHOST(3) para eso. La comprobación de que el nombre de host en el certificado es válido para el nombre de host al que se está conectando se realiza de forma independiente de la opción CURLOPT_DOH_SSL_VERIFYPEER(3).

ADVERTENCIA: deshabilitar la verificación del certificado permite a los malos interceptar la comunicación sin que usted lo sepa. Deshabilitar la verificación hace que la comunicación sea insegura. Simplemente tener cifrado en una transferencia no es suficiente, ya que no puede estar seguro de que está comunicándose con el punto final correcto.

PREDETERMINADO

1

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos basados en TLS: HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Todos los backends TLS soportan esta opción.

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_DOH_URL,
                     "https://cloudflare-dns.com/dns-query");
    /* Deshabilitar la verificación del certificado del servidor DoH */
    curl_easy_setopt(curl, CURLOPT_DOH_SSL_VERIFYPEER, 0L);
    curl_easy_perform(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.76.0

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, cualquier valor distinto de cero indica un error; consulte libcurl-errors(3).
