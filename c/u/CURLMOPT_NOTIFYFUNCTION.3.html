CURLMOPT_NOTIFYFUNCTION(3)

Paquete: curl

Licencias: MIT

CURLMOPT_NOTIFYFUNCTION(3) Manual de funciones de la biblioteca CURLMOPT_NOTIFYFUNCTION(3)

NOMBRE

CURLMOPT_NOTIFYFUNCTION - callback que recibe notificaciones

SINOPSIS

#include <curl/curl.h>
void notify_callback(CURLM *multi,     /* handle multi */
                     unsigned int notification, /* tipo de notificación */
                     CURL *easy,       /* handle easy */
                     void *notifyp);   /* puntero privado de notificación */
CURLMcode curl_multi_setopt(CURLM *handle, CURLMOPT_NOTIFYFUNCTION, notify_callback);

DESCRIPCIÓN

Pase un puntero a su función de callback, la cual debe coincidir con el prototipo mostrado arriba.

Cuando el handle multi procesa transferencias, los cambios pueden ser observados recibiendo notificaciones sobre ellos. Esto puede eliminar la necesidad de interrogar constantemente al handle multi para observar dichos cambios y actuar sobre ellos.

Las notificaciones se recopilan y se envían a la función de callback de la aplicación en un momento apropiado.

El callback de notificación es diferente de otros callbacks en que puede utilizar más funciones API de libcurl. Aparte de curl_multi_perform(3), curl_multi_socket(3), curl_multi_socket_action(3), curl_multi_socket_all(3) y curl_multi_cleanup(3), puede llamar a todos los demás métodos en los handles multi y easy. Esto incluye añadir y eliminar handles easy del handle multi.

Esta función de callback puede ser invocada en cualquier momento al interactuar con libcurl. Esto puede suceder incluso después de que todas las transferencias hayan finalizado y también puede suceder durante una llamada a curl_multi_cleanup(3) cuando se cierran las conexiones en caché.

ARGUMENTOS DEL CALLBACK

multi identifica el handle multi que activó la notificación.

notification es el tipo de notificación, es decir, qué sucedió. Los siguientes tipos están disponibles en este momento. En el futuro, podrían añadirse nuevos.

CURLMNOTIFY_INFO_READ
Cuando está habilitado a través de curl_multi_notify_enable(3), esto informa a la aplicación de que hay nuevos mensajes para procesar a través de curl_multi_info_read(3).

Esta notificación ocurre cada vez que se añade un mensaje a una pila de mensajes vacía en el handle multi y no para adiciones subsiguientes. Se espera que la función de callback de notificación lea todos los mensajes disponibles, vaciando la pila, de modo que una adición posterior active la notificación nuevamente.

El handle easy pasado es un handle interno.

CURLMNOTIFY_EASY_DONE
Cuando está habilitado a través de curl_multi_notify_enable(3), esta notificación se activa cuando un handle easy ha finalizado. Esto sucede tanto para transferencias exitosas como fallidas.

El handle easy pasado es la transferencia que ha finalizado. Este puede ser un handle interno cuando se utilizan características como DoH u otras.

easy identifica la transferencia involucrada. Puede ser uno de los handles easy de la aplicación o un handle interno.

notifyp se establece con CURLMOPT_NOTIFYDATA(3).

POR DEFECTO

NULL (sin callback)

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles

EJEMPLO

struct priv {
  void *ours;
};
static void notify_cb(CURLM *multi, unsigned int notification,
                      CURL *easy, void *notifyp)
{
  struct priv *p = notifyp;
  printf("mi puntero: %p\n", p->ours);
  /* ... */
}
int main(void)
{
  struct priv setup;
  CURLM *multi = curl_multi_init();
  /* ... usar callback de socket y puntero personalizado */
  curl_multi_setopt(multi, CURLMOPT_NOTIFYFUNCTION, notify_cb);
  curl_multi_setopt(multi, CURLMOPT_NOTIFYDATA, &setup);
  curl_multi_notify_enable(multi, CURLMNOTIFY_INFO_READ);
}

DISPONIBILIDAD

Añadido en curl 8.17.0

VALOR DE RETORNO

Devuelve CURLM_OK.

VER TAMBIÉN

CURLMOPT_NOTIFYDATA(3), curl_multi_notify_disable(3), curl_multi_notify_enable(3), curl_multi_socket_action(3)
