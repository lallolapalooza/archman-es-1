curs_termcap(3X) Llamadas a la biblioteca curs_termcap(3X)

NOMBRE

PC, UP, BC, ospeed, tgetent, tgetflag, tgetnum, tgetstr, tgoto, tputs - emulación de curses de termcap

SINOPSIS

#include <curses.h>
#include <term.h>
char PC;
char * UP;
char * BC;
short ospeed;
int tgetent(char *bp, const char *name);
int tgetflag(const char *id);
int tgetnum(const char *id);
char *tgetstr(const char *id, char **area);
char *tgoto(const char *cap, int col, int row);
int tputs(const char *str, int affcnt, int (*putc)(int));

DESCRIPCIÓN

ncurses proporciona las variables y funciones anteriores como una capa de compatibilidad para programas que utilizan la biblioteca termcap. La API es la misma, pero el comportamiento se emula utilizando la base de datos terminfo. Por lo tanto, solo se puede utilizar para consultar las capacidades de las entradas de la base de datos de terminales para las cuales se ha compilado una entrada de terminfo.

Inicialización

tgetent carga la entrada de la base de datos de terminales para name; vea term(7). Esto debe hacerse antes de llamar a cualquiera de las otras funciones. Devuelve

1
en caso de éxito,
0
si no existe tal entrada (o si la entrada coincidente describe un terminal genérico, con información insuficiente para que las aplicaciones curses se ejecuten), y
-1
si la base de datos terminfo no se pudo encontrar.

Esta implementación difiere de las de las bibliotecas históricas de termcap.

  • ncurses ignora el puntero de búfer bp, al igual que otras implementaciones de termcap que cumplen partes de X/Open Curses ahora retiradas. La biblioteca termcap de BSD almacenaría una copia de la descripción del tipo de terminal en el área referenciada por este puntero. terminfo almacena las descripciones de los tipos de terminales en formato compilado, que no es lo mismo.
  • Los significados de los valores de retorno difieren. La biblioteca termcap de BSD no verifica si la descripción del tipo de terminal incluye la capacidad genérica (gn), ni si la descripción del tipo de terminal admite un cursor direccionable, una propiedad esencial para que cualquier implementación de curses funcione.

Recuperación de valores de capacidad

tgetflag informa la entrada booleana para id, o cero si no está disponible.

tgetnum obtiene la entrada numérica para id, o -1 si no está disponible.

tgetstr devuelve la entrada de cadena para id, o NULL si no está disponible. Use tputs para mostrar la cadena devuelta. El parámetro area se utiliza de la siguiente manera.

  • Se asume que es la dirección de un puntero a un búfer administrado por la aplicación que llama.
  • Sin embargo, ncurses verifica para asegurarse de que area no sea NULL, y también que el puntero de búfer resultante no sea NULL. Si alguna de las verificaciones falla, area se ignora.
  • Si las verificaciones tienen éxito, ncurses también copia el valor de retorno al búfer apuntado por area, y la biblioteca actualiza area para apuntar después del carácter nulo que termina este valor.
  • El valor de retorno en sí es una dirección en la descripción del tipo de terminal cargada en memoria.

Aplicación de capacidades de cadena

Las capacidades de cadena se pueden parametrizar; vea la subsección “Cadenas parametrizadas” en terminfo(5). tgoto aplica sus segundo y tercer argumentos a los marcadores de posición paramétricos en la capacidad almacenada en el primer argumento.

  • La capacidad puede contener especificaciones de relleno; vea la subsección “Retardos y Relleno” de terminfo(5). Por lo tanto, la salida de tgoto debe pasarse a tputs en lugar de alguna otra función de salida como printf(3).
  • Si bien se asume que tgoto se usa para la capacidad de posicionamiento del cursor de dos parámetros, las aplicaciones termcap también la usan para capacidades de un solo parámetro.
Hacer esto revela una peculiaridad en tgoto: la mayoría de los terminales de hardware usan el direccionamiento del cursor con la fila primero, pero los desarrolladores originales de la interfaz termcap eligieron poner el parámetro col (columna) primero. La función tgoto intercambia el orden de sus parámetros. Lo hace incluso para llamadas que requieren solo un parámetro. En ese caso, el primer parámetro es simplemente un marcador de posición.
•
Normalmente, la biblioteca ncurses se compila sin soporte completo de termcap. En ese caso, tgoto utiliza una versión interna de tparm(3X) (una función más capaz).
Debido a que utiliza tparm internamente, tgoto puede usar algunas características de terminfo, pero no todas. En particular, solo permite parámetros numéricos; tparm admite parámetros de cadena.
Sin embargo, tparm no es una característica de termcap, y las aplicaciones portátiles de termcap no deben depender de su disponibilidad.

tputs se describe en curs_terminfo(3X). Puede recuperar capacidades por código termcap o terminfo.

Variables globales

Las variables PC, UP y BC son establecidas por tgetent a los datos de la entrada terminfo para pad_char, cursor_up y backspace_if_not_bs, respectivamente. ncurses no utiliza UP. PC es utilizado por delay_output(3X). BC es utilizado por la emulación de tgoto. La variable ospeed es establecida por ncurses utilizando una codificación específica del sistema para indicar la velocidad de datos de la terminal.

Liberación de memoria

Las funciones termcap no proporcionan ningún medio para liberar memoria, porque las implementaciones heredadas de termcap solo usaban las áreas de búfer proporcionadas por el llamador a través de tgetent y tgetstr. Esos búferes no se utilizan en terminfo.

Por el contrario, terminfo asigna memoria. Utiliza setupterm(3X) para obtener los datos utilizados por tgetent y las funciones que recuperan los valores de capacidad. Se podría usar

del_curterm(cur_term);
para liberar esta memoria, pero hay una complicación adicional con ncurses. Utiliza un grupo de tamaño fijo de ubicaciones de almacenamiento, una por valor del parámetro de nombre de terminal dado a tgetent. El programa screen(1) se basa en esta disposición para mejorar su rendimiento.

Una aplicación que solo utiliza las funciones termcap, no la API superior curses, podría liberar la memoria usando del_curterm(3X), porque el grupo se libera mediante otras funciones; vea curs_memleaks(3X).

VALOR DE RETORNO

Los valores de retorno de tgetent, tgetflag, tgetname y tgetstr se documentan anteriormente.

tgoto devuelve NULL en caso de error. Las condiciones de error incluyen:

  • estado no inicializado (tgetent no se llamó correctamente),
  • cap es un puntero nulo,
  • cap se refiere a una capacidad cancelada,
  • cap es una capacidad con parámetros de valor de cadena (una característica exclusiva de terminfo), y
  • cap es una capacidad con más de dos parámetros.

Consulte curs_terminfo(3X) con respecto a tputs.
