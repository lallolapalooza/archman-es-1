CURLOPT_HTTPPROXYTUNNEL(3)

Paquete: curl

Licencias: MIT

CURLOPT_HTTPPROXYTUNNEL(3) Manual de funciones de biblioteca CURLOPT_HTTPPROXYTUNNEL(3)

NOMBRE

CURLOPT_HTTPPROXYTUNNEL - túnel a través de un proxy HTTP

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HTTPPROXYTUNNEL, long tunnel);

DESCRIPCIÓN

Establece el parámetro tunnel a 1L para que libcurl túnel todas las operaciones a través del proxy HTTP (establecido con CURLOPT_PROXY(3)). Hay una gran diferencia entre usar un proxy y túnel a través de él.

El tunneling significa que se envía una solicitud HTTP CONNECT al proxy, pidiéndole que se conecte a un host remoto en un número de puerto específico y luego el tráfico simplemente pasa a través del proxy. Los proxies tienden a incluir en una lista blanca números de puerto específicos que permiten solicitudes CONNECT y, a menudo, solo se permiten los puertos 80 y 443.

Para suprimir las cabeceras de respuesta CONNECT del proxy de las callbacks del usuario, utilice CURLOPT_SUPPRESS_CONNECT_HEADERS(3).

Los proxies HTTP generalmente solo pueden hablar HTTP (por razones obvias), lo que hace que libcurl convierta las solicitudes que no son HTTP a HTTP cuando se usa un proxy HTTP sin esta opción de túnel establecida. Por ejemplo, solicitar una URL FTP y especificar un proxy HTTP hace que libcurl envíe una URL FTP en una solicitud HTTP GET al proxy. Al hacer un túnel a través del proxy en su lugar, evita esa conversión (que de todos modos rara vez funciona a través del proxy).

PREDETERMINADO

0

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos admitidos

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "ftp://example.com/file.txt");
    curl_easy_setopt(curl, CURLOPT_PROXY, "http://127.0.0.1:80");
    curl_easy_setopt(curl, CURLOPT_HTTPPROXYTUNNEL, 1L);
    curl_easy_perform(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.3

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, consulte libcurl-errors(3).
