curl_ws_recv(3)

Paquete: curl

Licencias: MIT

curl_ws_recv(3) Manual de funciones de la biblioteca curl_ws_recv(3)

NOMBRE

curl_ws_recv - recibir datos de WebSocket

SINOPSIS

#include <curl/curl.h>
CURLcode curl_ws_recv(CURL *curl, void *buffer, size_t buflen,
                      size_t *recv, const struct curl_ws_frame **meta);

DESCRIPCIÓN

Recupera tanto como sea posible de un frame de WebSocket recibido en el buffer, pero no más de buflen bytes. recv se establece al número de bytes realmente almacenados.

Si la llamada a la función es exitosa, el puntero meta se establece para apuntar a una struct curl_ws_frame que contiene información sobre los datos recibidos. Esa estructura no debe ser liberada y su contenido no debe ser confiado una vez que se llama a otra función de WebSocket. Ver curl_ws_meta(3) para más detalles sobre esa estructura.

La aplicación debe comprobar meta->bytesleft para determinar si se ha recibido el frame completo. Si hay más carga pendiente, la aplicación debe llamar a esta función de nuevo con un buffer y buflen actualizados para reanudar la recepción. Esto puede suceder, por ejemplo, cuando los datos no caben en el buffer proporcionado o cuando todos los datos del frame no se han entregado a través de la red todavía.

Si la aplicación desea leer metadatos sin consumir carga útil, puede llamar a esta función con un buflen de cero. Establecer el buffer a un puntero NULL está permitido en este caso. Tenga en cuenta que los frames sin carga útil se consumen con esta acción.

Si el mensaje recibido consta de múltiples fragmentos, el bit CURLWS_CONT se establece en todos los frames excepto en el último. Las banderas apropiadas CURLWS_TEXT o CURLWS_BINARY se establecen en cada frame, independientemente de si es el primer fragmento, un fragmento intermedio o el fragmento final. La aplicación es responsable de reensamblar mensajes fragmentados. Se debe tener especial cuidado para manejar correctamente los frames de control (es decir, CLOSE, PING y PONG) que llegan entre fragmentos consecutivos de un mensaje TEXT o BINARY fragmentado. Ver curl_ws_meta(3) para más detalles sobre CURLWS_CONT.

El protocolo WebSocket consiste en mensajes que pueden ser entregados por el cable como uno o más frames - pero dado que un frame puede ser demasiado grande para ser almacenado en memoria, libcurl puede necesitar entregar frames parciales a la aplicación. Fragmentos, o trozos, de frames.

PROTOCOLOS

Esta funcionalidad afecta solo a ws

EJEMPLO

int main(void)
{
  char buffer[256];
  size_t offset = 0;
  CURLcode res = CURLE_OK;
  CURL *curl = curl_easy_init();
  curl_easy_setopt(curl, CURLOPT_URL, "wss://example.com/");
  curl_easy_setopt(curl, CURLOPT_CONNECT_ONLY, 2L);
  /* Inicia la conexión HTTPS y actualiza a WSS, luego devuelve el control */
  curl_easy_perform(curl);
  /* Nota: Este ejemplo descuida los mensajes fragmentados. (Bit CURLWS_CONT)
           Una aplicación real debe manejarlos apropiadamente. */
  while(!res) {
    size_t recv;
    const struct curl_ws_frame *meta;
    res = curl_ws_recv(curl, buffer + offset, sizeof(buffer) - offset, &recv,
                       &meta);
    offset += recv;
    if(res == CURLE_OK) {
      if(meta->bytesleft == 0)
        break; /* finalizada la recepción */
      if(meta->bytesleft > sizeof(buffer) - offset)
        res = CURLE_TOO_LARGE;
    }
    if(res == CURLE_AGAIN)
      /* en una aplicación real: esperar el socket aquí, p. ej. usando select() */
      res = CURLE_OK;
  }
  curl_easy_cleanup(curl);
  return (int)res;
}

DISPONIBILIDAD

Añadido en curl 7.86.0

VALOR DE RETORNO

Esta función devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica un error, ver libcurl-errors(3). Si CURLOPT_ERRORBUFFER(3) fue establecido con curl_easy_setopt(3) puede haber un mensaje de error almacenado en el buffer de error cuando se devuelve un valor distinto de cero.

Devuelve CURLE_GOT_NOTHING si la conexión asociada está cerrada.

En lugar de bloquear, la función devuelve CURLE_AGAIN. El comportamiento correcto es entonces esperar a que el socket señale que se puede leer antes de volver a llamar a esta función.

Cualquier otro valor de retorno distinto de cero indica un error. Ver la página del manual de libcurl-errors(3) para la lista completa con descripciones.

Devuelve CURLE_GOT_NOTHING si la conexión asociada está cerrada.
