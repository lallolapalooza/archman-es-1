DESCRIPCIÓ

N

Pase un long como parámetro, que se establece como una máscara de bits, para indicar a libcurl qué método(s) de autenticación desea que utilice al hablar con el servidor

remoto.

Los bits disponibles se enumeran a continuación. Si se establece más de un bit, libcurl primero consulta al host para ver qué métodos de autenticación admite y luego elige el mejor que usted le permita usar. Para algunos métodos, esto induce un viaje de red adicional. Establezca el nombre real y la contraseña con la opción CURLOPT_USERPWD(3) o con las opciones CURLOPT_USERNAME(3) y CURLOPT_PASSW

ORD(3).

Para la autenticación con un proxy, consulte CURLOPT_PROXYA

UTH(3).
CURLAUTH_BAS
IC
Autenticación HTTP Basic. Esta es la opción predeterminada, y el único método que está ampliamente en uso y es compatible prácticamente en todas partes. Este envía el nombre de usuario y la contraseña por la red en texto plano, fácilmente capturado por
otros.
CURLAUTH_DIG
EST
Autenticación HTTP Digest. La autenticación Digest está definida en RFC 2617 y es una forma más segura de realizar autenticación sobre redes públicas que el método Basic antiguo y
tradicional.
CURLAUTH_DIGEST
_IE
Autenticación HTTP Digest con un sabor IE. La autenticación Digest está definida en RFC 2617 y es una forma más segura de realizar autenticación sobre redes públicas que el método Basic antiguo y tradicional. El sabor IE es simplemente que libcurl usa una "peculiaridad" especial que IE se sabe que usó antes de la versión 7 y que algunos servidores requieren que el cliente
use.
CURLAUTH_BEA
RER
Autenticación con token Bearer HTTP, utilizada principalmente en el protocolo OAuth 2.0.

Puede establecer el token Bearer a usar con CURLOPT_XOAUT

H2_BEAR
ER(3).
CURLAUTH_NEGOTI
ATE
Autenticación HTTP Negotiate (SPNEGO). La autenticación Negotiate está definida en RFC 4559 y es la forma más segura de realizar autenticación sobre HTTP.

Necesita compilar libcurl con una bib

lioteca GSS-API adecuada o SS
PI en Windows para que esto funcione.
CURLAUTH_NT
LM
Autenticación HTTP NTLM. Un protocolo propietario inventado y utilizado por Microsoft. Utiliza un concepto de desafío-respuesta y hash similar a Digest, para evitar que la contraseña sea espiada.

NTLM utiliza algoritmos cri

ptográficos débiles y no s
e considera seguro.
CURLAUTH_NTLM
_WB
El soporte para esto se eliminó desde libcurl 8.8.0.

NTLM delegando al ayudante winbind. La autenticación es realizada por una aplicación binaria separada que se ejecuta cuando es necesaria. El nombre de la aplicación se especifica en tiempo de compilación pero típicamente es /usr/bin/ntlm_a

uth.

Tenga en cuenta que libcurl hace un fork cuando es necesario para ejecutar la aplicación winbind y la mata cuando termina, llamando a waitpid() para esperar su salida cuando termine. En sistemas operativos POSIX, matar el proceso provoca que se genere una señal SIGCHLD (independientemente de si CURLOPT_NOSIGNAL(3) está establecido), la cual debe ser manejada inteligentemente por la aplicación. En particular, la aplicación no debe llamar incondicionalmente a

wait() en su manejador de señal SIGCHLD para evitar estar sujeta a una condición de
carrera. Este comportamiento está sujeto a cambios en versiones futuras de libcurl.
CURLAUTH_A
NY
Esta es una macro de conveniencia que establece todos los bits y por lo tanto hace que libcurl elija cualquiera que encuentre adecuada. libcurl selecciona automáticamente la que encuentra más
segura.
CURLAUTH_ANYS
AFE
Esta es una macro de conveniencia que establece todos los bits excepto Basic y por lo tanto hace que libcurl elija cualquiera que encuentre adecuada. libcurl selecciona automáticamente la que encuentra más
segura.
CURLAUTH_ON
LY
Este es un símbolo meta. Haga OR con este valor junto con un valor de autenticación específico para forzar a libcurl a sondear por autenticación sin restricciones y si no, solo ese algoritmo de autenticación único es
aceptable.

GV4

EJEMPL

O 
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode ret;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    /* permitir cualquier autenticación que hable el servidor */
    curl_easy_setopt(curl, CURLOPT_HTTPAUTH, CURLAUTH_ANY);
    curl_easy_setopt(curl, CURLOPT_USERPWD, "james:bond");
    ret = curl_easy_perform(curl);
  }
}
