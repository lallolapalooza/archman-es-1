POE(3) Documentación de Perl contribuida por el usuario POE(3)

NOMBRE

Curses::UI::POE - Una subclase que hace que Curses::UI sea compatible con POE.

SINOPSIS

use Curses::UI::POE;
my $cui = new Curses::UI::POE inline_states => {
    _start => sub {
        $_[HEAP]->dialog("¡Hola!");
    },
    _stop => sub {
        $_[HEAP]->dialog("¡Adiós!");
    },
};
$cui->mainloop

INTRODUCCIÓN

Esta es una subclase para Curses::UI que le permite funcionar con POE. Está diseñada para integrarse simplemente sobre Curses::UI. Manteniendo la API igual y forzando a Curses::UI a manejar todos sus eventos a través de POE, en lugar de internamente. Esto te permite usar POE en segundo plano para cosas como clientes de red, sin que Curses::UI rompa la funcionalidad de tus programas.

ADICIONES

Esta es una lista de cambios distintos entre la API de Curses::UI y la API de Curses::UI::POE. Todas deberían ser adiciones no obstructivas, manteniendo a Curses::UI::POE como un reemplazo directo para Curses::UI.

Opciones del Constructor

inline_states
La opción del constructor inline_states permite la inserción de estados en línea en la sesión de control de Curses::UI::POE. Dado que Curses::UI::POE está implementado con una pequeña sesión, pensé que podría ser útil proporcionar la capacidad a la sesión de control para toda la interacción de POE para la interfaz.

Si bien los eventos de Curses::UI todavía se fuerzan sin problemas para usar POE, esto te permite usarlo para un poco más, como capturar respuestas de otro componente de POE que debería estar directamente conectado con la salida. (Ver el ejemplo del cliente IRC).

Sin embargo, en esta sesión de control, el heap se predefine como el objeto raíz Curses::UI, que es una referencia hash. En el objeto Curses::UI, todos los datos privados se indexan con una clave que comienza con "-". Por lo tanto, si deseas usar el heap para almacenar otros datos, simplemente no uses el prefijo de índice hash "-" para evitar conflictos.

TEMPORIZADORES

Los temporizadores no documentados de Curses::UI ($cui->timer) seguirán funcionando y se traducirán en retardos de POE. Sin embargo, sugeriría no usarlos, ya que las alarmas y los retardos internos de POE son mucho más robustos.

DIÁLOGOS

Los métodos de diálogo de Curses::UI::POE contienen su propio bucle de eventos en miniatura, similar a cómo funcionaban los métodos de diálogo de Curses::UI. Sin embargo, en lugar de bloquear y sondear en readkeys, incita su propio bucle de eventos POE en miniatura personalizado hasta que el diálogo se haya completado, y luego su resultado se devuelve según las especificaciones de Curses::UI.

MODALIDAD

Curses::UI::POE construye su propia estructura de modalidad interna. Esto permite a Curses::UI gestionarla y a POE emitir los eventos (esperemos que correctos). Para hacer esto, utiliza su propio bucle de eventos personalizado (más pequeño), que es reentrante en el POE::Loop en uso (en este caso, generalmente POE::Loop::Select). De esta manera, puede haber varias capas recursivas de bucles de eventos, forzando el enfoque en el widget modal actual, sin detener la ejecución de otras sesiones de POE.

VER TAMBIÉN

POE, Curses::UI. El uso de este módulo requiere la comprensión tanto del conjunto de widgets de Curses::UI como del Framework POE.
