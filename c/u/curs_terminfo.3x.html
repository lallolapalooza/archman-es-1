DESCRIPCIÓN

Estas funciones de bajo nivel deben ser llamadas por programas que trabajan directamente con la base de datos terminfo para manejar ciertas capacidades del terminal, como programar teclas de función. Para toda la demás funcionalidad, las funciones curses son más adecuadas y se recomienda su uso.

Ninguna de estas funciones utiliza (ni es consciente de) cadenas de caracteres multibyte como UTF-8.

  • Los nombres y códigos de capacidades usan el conjunto de caracteres portátiles de POSIX.
  • Los valores de cadena de capacidades no tienen codificación asociada; son cadenas de caracteres de 8 bits.

Inicialización

Inicialmente, se debe llamar a setupterm. Las funciones de alto nivel de curses initscr y newterm llaman a setupterm para inicializar el conjunto de bajo nivel de variables dependientes del terminal listadas en term_variables(3X).

Las aplicaciones pueden usar las capacidades del terminal ya sea directamente (a través de definiciones de encabezado) o mediante funciones especiales. Los archivos de encabezado curses.h y term.h deben incluirse (en ese orden) para obtener las definiciones de estas cadenas, números y banderas.

Las variables terminfo lines y columns son inicializadas por setupterm de la siguiente manera.

  • Si se ha llamado a use_env(FALSE), se utilizan los valores de lines y columns especificados en terminfo.
  • De lo contrario, si existen las variables de entorno LINES y COLUMNS, se utilizan sus valores. Si estas variables de entorno no existen y el programa se está ejecutando en una ventana, se utiliza el tamaño actual de la ventana. De lo contrario, si las variables de entorno no existen, se utilizan los valores de lines y columns especificados en la base de datos terminfo.

Las cadenas parametrizadas deben pasarse a través de tparm para instanciarlas. Todas las cadenas de terminfo (incluida la salida de tparm) deben enviarse al dispositivo terminal con tputs o putp. Llame a reset_shell_mode para restaurar los modos del terminal antes de salir; consulte curs_kernel(3X).

Los programas que usan direccionamiento de cursor deben

  • emitir enter_ca_mode al inicio y
  • emitir exit_ca_mode antes de salir.

Los programas que ejecutan subprocesos del shell deben

  • llamar a reset_shell_mode y emitir exit_ca_mode antes de llamar al shell y
  • emitir enter_ca_mode y llamar a reset_prog_mode después de volver del shell.

setupterm lee la base de datos terminfo, inicializando las estructuras terminfo, pero no configura las estructuras de virtualización de salida utilizadas por curses. Sus parámetros son los siguientes.

term
es el tipo de terminal, una cadena de caracteres. Si term es nulo, se lee la variable de entorno TERM.
filedes
es el descriptor de archivo utilizado para obtener y establecer los modos de E/S del terminal.
Las aplicaciones de nivel superior utilizan newterm(3X) para inicializar el terminal, pasando un *stream* de salida en lugar de un *descriptor*. En curses, ambos son lo mismo porque newterm llama a setupterm, pasando el descriptor de archivo derivado de su parámetro de stream de salida.
errret
apunta a una ubicación opcional donde se puede devolver un estado de error al llamador. Si errret no es nulo, entonces setupterm devuelve OK o ERR y almacena un valor de estado en el entero apuntado por errret. Un valor de retorno de OK combinado con el estado 1 en errret es lo normal.
Si se devuelve ERR, examine errret:
1
significa que el terminal es de copia impresa (hardcopy) y no se puede utilizar para aplicaciones curses.
setupterm determina si la entrada es de tipo copia impresa verificando la capacidad hardcopy (hc).
0
significa que el terminal no pudo ser encontrado, o que es un tipo genérico, con información insuficiente para que se ejecuten aplicaciones curses.
setupterm determina si la entrada es de tipo genérico verificando la capacidad generic_type (gn).
-1
significa que la base de datos terminfo no pudo ser encontrada.
Si errret es nulo, setupterm informa un mensaje de error al encontrar uno y sale. Por lo tanto, la llamada más simple es:
setupterm((char *)0, 1, (int *)0);
que usa todos los valores predeterminados y envía la salida a stdout.

El Estado del Terminal

setupterm almacena su información sobre el terminal en una estructura TERMINAL apuntada por la variable global cur_term. Si detecta un error, o decide que el terminal no es adecuado (copia impresa o genérico), descarta esta información, haciéndola no disponible para las aplicaciones.

Si setupterm se llama repetidamente para el mismo tipo de terminal, reutilizará la información. Mantiene solo una copia de las capacidades de un determinado terminal en memoria. Si se llama para diferentes tipos de terminal, setupterm asigna nuevo almacenamiento para cada conjunto de capacidades del terminal.
