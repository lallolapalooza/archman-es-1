CURLOPT_POST(3)

Paquete: curl

Licencias: MIT

CURLOPT_POST(3) Manual de funciones de biblioteca CURLOPT_POST(3)

NOMBRE

CURLOPT_POST - realizar una publicación HTTP

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_POST, long post);

DESCRIPCIÓN

Un parámetro establecido en 1 indica a libcurl que realice una publicación HTTP normal. Esto también hace que libcurl utilice una cabecera "Content-Type: application/x-www-form-urlencoded".

Utilice las opciones CURLOPT_POSTFIELDS(3) o CURLOPT_COPYPOSTFIELDS(3) para especificar los datos a publicar y CURLOPT_POSTFIELDSIZE(3) o CURLOPT_POSTFIELDSIZE_LARGE(3) para establecer el tamaño de los datos.

Opcionalmente, puede proporcionar datos para la publicación utilizando las opciones CURLOPT_READFUNCTION(3) y CURLOPT_READDATA(3), pero en ese caso debe asegurarse de no establecer CURLOPT_POSTFIELDS(3) en nada que no sea NULL. Al proporcionar datos con una función de devolución de llamada, debe transmitirlos mediante codificación de transferencia fragmentada o debe establecer el tamaño de los datos con las opciones CURLOPT_POSTFIELDSIZE(3) o CURLOPT_POSTFIELDSIZE_LARGE(3). Para habilitar la codificación fragmentada, simplemente pase la cabecera Transfer-Encoding apropiada, consulte el ejemplo post-callback.c.

Puede anular la cabecera POST Content-Type: predeterminada estableciendo la suya propia con CURLOPT_HTTPHEADER(3).

El uso de POST con HTTP 1.1 implica el uso de una cabecera "Expect: 100-continue". Puede deshabilitar esta cabecera con CURLOPT_HTTPHEADER(3) como de costumbre.

Si utiliza POST a un servidor HTTP 1.1, puede enviar datos sin conocer el tamaño antes de iniciar la publicación si utiliza la codificación fragmentada. Habilita esto añadiendo una cabecera como "Transfer-Encoding: chunked" con CURLOPT_HTTPHEADER(3). Con HTTP 1.0 o sin transferencia fragmentada, debe especificar el tamaño en la solicitud. (Desde la versión 7.66.0, libcurl utiliza automáticamente la codificación fragmentada para las publicaciones si el tamaño es desconocido).

Al establecer CURLOPT_POST(3) en 1, libcurl establece automáticamente CURLOPT_NOBODY(3) y CURLOPT_HTTPGET(3) en 0.

Si emite una solicitud POST y luego desea realizar una solicitud HEAD o GET utilizando el mismo manejador reutilizado, debe establecer explícitamente el nuevo tipo de solicitud utilizando CURLOPT_NOBODY(3) o CURLOPT_HTTPGET(3) o similar.

Al establecer CURLOPT_POST(3) en 0, libcurl restablece el tipo de solicitud al valor predeterminado para deshabilitar la publicación. Normalmente, eso significa que se restablece a GET. En su lugar, debe establecer explícitamente un nuevo tipo de solicitud, como se describe anteriormente.

PREDETERMINADO

0, deshabilitado

PROTOCOLOS

Esta funcionalidad afecta solo a http

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/foo.bin");
    curl_easy_setopt(curl, CURLOPT_POST, 1L);
    /* configurar la función de devolución de llamada de lectura con CURLOPT_READFUNCTION */
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.1

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo está bien, un valor distinto de cero indica que ocurrió un error, consulte libcurl-errors(3).
