curl_easy_pause(3)

Paquete: curl

Licencias: MIT

curl_easy_pause(3) Manual de Funciones de Biblioteca curl_easy_pause(3)

NOMBRE

curl_easy_pause - pausar y reanudar una conexión

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_pause(CURL *handle, int bitmask );

DESCRIPCIÓN

Usando esta función, puedes marcar explícitamente una conexión en ejecución para que sea pausada, y puedes reanudar una conexión que fue pausada previamente. A diferencia de la mayoría de las otras funciones de libcurl, curl_easy_pause(3) puede usarse desde dentro de callbacks.

Una conexión puede ser pausada usando esta función o dejando que el callback de lectura o el de escritura devuelva el código de retorno mágico apropiado (CURL_READFUNC_PAUSE y CURL_WRITEFUNC_PAUSE). Un callback de escritura que devuelve pausa le señala a la biblioteca que no pudo ocuparse de ningún dato en absoluto, y esos datos se entregan de nuevo al callback cuando la transferencia es reanudada.

Aunque pueda resultar tentador, ten cuidado y ten en cuenta que no puedes llamar a esta función desde otro hilo. Para reanudar, puedes por ejemplo llamar a ella desde el callback de progreso (CURLOPT_PROGRESSFUNCTION(3)).

Cuando esta función se llama para reanudar la recepción, el callback de escritura podría ser llamado antes de que esta función retorne para entregar contenido en caché. Cuando libcurl entrega tales datos en caché al callback de escritura, se entrega tan rápido como sea posible, lo que puede exceder el límite establecido en CURLOPT_MAX_RECV_SPEED_LARGE(3) etc.

El argumento handle identifica la transferencia que quieres pausar o reanudar.

Una transferencia pausada está excluida de las cancelaciones por baja velocidad a través de la opción CURLOPT_LOW_SPEED_LIMIT(3) y reanudar una transferencia restablece el período de tiempo requerido para cumplir con el límite de baja velocidad.

El argumento bitmask es un conjunto de bits que establece el nuevo estado de la conexión. Se pueden usar los siguientes bits:

CURLPAUSE_RECV
Pausar la recepción de datos. No se reciben datos en esta conexión hasta que esta función se llame de nuevo sin este bit establecido. Por lo tanto, el callback de escritura (CURLOPT_WRITEFUNCTION(3)) no es llamado.
CURLPAUSE_SEND
Pausar el envío de datos. No se envían datos en esta conexión hasta que esta función se llame de nuevo sin este bit establecido. Por lo tanto, el callback de lectura (CURLOPT_READFUNCTION(3)) no es llamado.
CURLPAUSE_ALL
Definición de conveniencia que pausa ambas direcciones.
CURLPAUSE_CONT
Definición de conveniencia que reanuda ambas direcciones.

LIMITACIONES

La pausa de transferencias no funciona con protocolos que funcionan sin conectividad de red, como FILE://. Intentar pausar tal transferencia, en cualquier dirección, podría causar problemas o errores.

MULTIPLEXADO

Cuando una conexión se usa de forma multiplexada, como para HTTP/2, y una de las transferencias sobre la conexión es pausada y las otras continúan fluyendo, libcurl podría terminar almacenando en búfer contenidos para la transferencia pausada. Tiene que hacer esto porque necesita drenar el socket para las otras transferencias y el tamaño de ventana ya anunciado para la transferencia pausada permite al servidor continuar enviando datos hasta esa cantidad de tamaño de ventana. Por defecto, libcurl anuncia un tamaño de ventana de 32 megabytes, lo que puede hacer que libcurl termine almacenando en búfer 32 megabytes de datos para un flujo pausado.

Cuando tal flujo pausado es reanudado de nuevo, cualquier dato almacenado en búfer se entrega primero.

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos soportados

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    /* pausar una transferencia en ambas direcciones */
    curl_easy_pause(curl, CURLPAUSE_RECV | CURLPAUSE_SEND);
  }
}

USO DE MEMORIA

Al pausar una transferencia de descarga devolviendo el código de retorno mágico desde un callback de escritura, los datos leídos ya están en los búferes internos de libcurl, por lo que debe mantenerlos en un búfer asignado hasta que la recepción sea reanudada de nuevo usando esta función.

Si los datos descargados están comprimidos y se solicita que se descompriman automáticamente durante la descarga, libcurl continúa descomprimiendo el fragmento descargado completo y almacena en caché los datos sin comprimir. Esto tiene el efecto secundario de que si descargas algo que está muy comprimido, puede resultar en una gran cantidad de datos que necesitan ser asignados para guardar los datos durante la pausa. Considera no usar la recepción pausada si permites que libcurl descomprima datos automáticamente.

Si la descarga se hace con HTTP/2 o HTTP/3, hay hasta una cantidad de datos del tamaño de la ventana de flujo que curl no puede detener sino que necesita almacenar en caché mientras la transferencia está pausada. Esto significa que si se usa un tamaño de ventana de 64 MB, libcurl podría terminar teniendo que almacenar en caché 64 MB de datos.

DISPONIBILIDAD

Añadido en curl 7.18.0

VALOR DE RETORNO

Esta función devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estaba bien, un valor distinto de cero significa que ocurrió un error, ver libcurl-errors(3). Si CURLOPT_ERRORBUFFER(3) fue establecido con curl_easy_setopt(3) puede haber un mensaje de error almacenado en el búfer de error cuando se devuelve un valor distinto de cero.
