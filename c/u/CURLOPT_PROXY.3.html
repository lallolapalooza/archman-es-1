CURLOPT_PROXY(3)

Paquete: curl

Licencias: MIT

CURLOPT_PROXY(3) Manual de funciones de la biblioteca CURLOPT_PROXY(3)

NOMBRE

CURLOPT_PROXY - proxy a utilizar

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_PROXY, char *proxy);

DESCRIPCIÓN

Establece el proxy a utilizar para las transferencias con este manejador fácil. El parámetro debe ser un char * a una cadena terminada por un carácter nulo que contenga el nombre de host o la dirección IP numérica con puntos. Una dirección IPv6 numérica debe escribirse entre [corchetes].

Para especificar el número de puerto en esta cadena, añada :[puerto] al final del nombre de host. El número de puerto del proxy puede especificarse opcionalmente (pero se desaconseja) con la opción separada CURLOPT_PROXYPORT(3). Si no se especifica, libcurl usa por defecto el puerto 1080 para los proxies.

La cadena del proxy puede ir precedida de [esquema]:// para especificar qué tipo de proxy se utiliza.

Usar esta opción varias veces hace que la última cadena establecida reemplace a las anteriores. Establézcala en NULL para desactivar su uso de nuevo.

La aplicación no tiene que conservar la cadena después de establecer esta opción.

http://
Proxy HTTP. Por defecto cuando no se especifica esquema ni tipo de proxy.
https://
Proxy HTTPS. (Añadido en 7.52.0 para OpenSSL y GnuTLS. Desde 7.87.0, también funciona con mbedTLS, Rustls, Schannel y wolfSSL.)

Esto usa HTTP/1 por defecto. Establecer CURLOPT_PROXYTYPE(3) a CURLPROXY_HTTPS2 permite a libcurl negociar usando HTTP/2 con el proxy.

socks4://
Proxy SOCKS4.
socks4a://
Proxy SOCKS4a. El proxy resuelve el nombre de host de la URL.
socks5://
Proxy SOCKS5.
socks5h://
Proxy SOCKS5. El proxy resuelve el nombre de host de la URL.

Sin un prefijo de esquema, CURLOPT_PROXYTYPE(3) puede usarse para especificar qué tipo de proxy identifica la cadena.

Cuando le indica a la biblioteca que use un proxy HTTP, libcurl convierte las operaciones en HTTP de forma transparente incluso si especifica una URL FTP etc. Esto puede tener un impacto en qué otras funciones de la biblioteca puede usar, como CURLOPT_QUOTE(3) y otras características específicas de FTP que no funcionan a menos que haga un túnel a través del proxy HTTP. Dicho túnel se activa con CURLOPT_HTTPPROXYTUNNEL(3).

Establecer la cadena del proxy a "" (una cadena vacía) desactiva explícitamente el uso de un proxy, incluso si hay una variable de entorno establecida para ello.

Los sockets de dominio Unix están soportados para los proxies socks desde la 7.84.0. Establezca localhost para la parte del host. p. ej. socks5h://localhost/path/to/socket.sock

Cuando establezca un nombre de host para usar, no asuma que haya un número de puerto particular ampliamente utilizado para los proxies. Especifíquelo.

Cuando se usa un proxy, el modo FTP activo establecido con CUROPT_FTPPORT(3), no puede usarse.

Hacer FTP a través de un proxy HTTP sin CURLOPT_HTTPPROXYTUNNEL(3) establecido hace que libcurl haga HTTP con una URL FTP a través del proxy. Para dichas transferencias, las opciones específicas comunes de FTP no funcionan, por ejemplo CURLOPT_USE_SSL(3).

Autenticación

El proxy también puede especificarse con sus credenciales asociadas como para las URLs ordinarias en el estilo: esquema://usuario:contraseña@nombrehost

Alternativamente, establézcalas usando CURLOPT_PROXYUSERNAME(3) y CURLOPT_PROXYPASSWORD(3).

Variables de entorno

libcurl respeta las variables de entorno de proxy llamadas http_proxy, ftp_proxy, sftp_proxy etc. Si están establecidas, libcurl usa el proxy especificado para ese esquema de URL. Para una URL "FTP://", se considera la ftp_proxy . all_proxy se usa si no se estableció un proxy específico del protocolo.

Si no_proxy (o NO_PROXY) está establecida, es el equivalente exacto de establecer la opción CURLOPT_NOPROXY(3) .

Las opciones CURLOPT_PROXY(3) y CURLOPT_NOPROXY(3) anulan las variables de entorno.

POR DEFECTO

NULL

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos soportados

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/file.txt");
    curl_easy_setopt(curl, CURLOPT_PROXY, "http://proxy:80");
    curl_easy_perform(curl);
  }
}

HISTORIAL

Desde la 7.14.1 los nombres de las variables de entorno de proxy pueden incluir el esquema del protocolo.

Desde la 7.21.7 la cadena del proxy soporta los protocolos socks como "esquemas".

Desde la 7.50.2, los esquemas no soportados en las cadenas de proxy hacen que libcurl devuelva un error.

DISPONIBILIDAD

Añadido en curl 7.1

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estaba bien, un valor distinto de cero significa que ocurrió un error, véase libcurl-errors(3).
