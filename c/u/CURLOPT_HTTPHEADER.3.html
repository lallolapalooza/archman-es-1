Paquete: curl

Licencias: MIT

CURLOPT_HTTPHEADER(3) Manuales de funciones de librería CURLOPT_HTTPHEADER(3)

NAME

CURLOPT_HTTPHEADER — conjunto de encabezados HTTP

SYNOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HTTPHEADER,
                          struct curl_slist *headers);

DESCRIPTION

Pasar un puntero a una lista enlazada de encabezados HTTP para pasar al servidor y/o al proxy en su solicitud HTTP. La misma lista puede usarse tanto para solicitudes de host como para solicitudes de proxy.

Cuando se utiliza dentro de una solicitud IMAP o SMTP para subir un correo MIME, la lista de encabezados dada establece los encabezados MIME de nivel de documento que se deben añadir al documento subido descrito por CURLOPT_MIMEPOST(3). Esto no afecta las subidas de correo crudo.

Cuando se utiliza con HTTP, esta opción puede añadir nuevos encabezados, reemplazar encabezados internos y eliminar encabezados internos.

La lista enlazada debe ser una lista válida de entradas struct curl_slist correctamente rellenas. Utilice curl_slist_append(3) para crear la lista y curl_slist_free_all(3) para liberarla nuevamente después de su uso.

Si proporciona un encabezado que de otro modo genera y utiliza libcurl internamente, su alternativa de encabezado se utilizará en su lugar. Si proporciona un encabezado sin contenido (sin datos en el lado derecho de la dos puntos) como en Accept:, el encabezado utilizado internamente se eliminará. Para añadir forzadamente un encabezado sin contenido (nada después de la dos puntos), utilice la forma name; (usando un punto y coma al final).

Hay excepciones cuando se suprimen los encabezados. El encabezado Connection: en HTTP/1.1 no puede ser sobrescrito. Puede proporcionar valores para él, pero si una solicitud requiere unos específicos, estos se añadirán siempre a los suyos.

Los encabezados incluidos en la lista enlazada no deben estar terminados por CRLF, ya que libcurl añade CRLF después de cada elemento de encabezado. El incumplimiento de esto podría resultar en un comportamiento extraño. libcurl pasa las cadenas literal que le da sin ningún filtro ni otras protecciones. Esto incluye espacios en blanco y caracteres de control.

La primera línea en una solicitud HTTP (que contiene el método, usualmente un GET o POST) no es un encabezado y no puede reemplazarse utilizando esta opción. Solo las líneas que siguen a la línea de solicitud son encabezados. Añadir esta línea del método en esta lista de encabezados solo causa que su solicitud envíe un encabezado inválido. Utilice CURLOPT_CUSTOMREQUEST(3) para cambiar el método.

Cuando esta opción se pasa a curl_easy_setopt(3), libcurl no copia toda la lista, por lo que debe mantenerla hasta que ya no use este handle para una transferencia antes de llamar a curl_slist_free_all(3) en la lista.

Utilizar esta opción varias veces hace que la última lista definida suprima las anteriores. Establezca en NULL para desactivar su uso nuevamente.

Los encabezados HTTP más comúnmente reemplazados tienen "atajos" en las opciones CURLOPT_COOKIE(3), CURLOPT_USERAGENT(3) y CURLOPT_REFERER(3). Recomendamos utilizar esos.

Existe una opción alternativa que establece o reemplaza encabezados solo para las solicitudes que se envían con CONNECT a un proxy: CURLOPT_PROXYHEADER(3). Utilice CURLOPT_HEADEROPT(3) para controlar el comportamiento.

ENCABEZADOS HTTP ESPECÍFICOS

Establecer algunos encabezados específicos hace que libcurl actúe de manera diferente.

Host:
El nombre de host especificado se utiliza para la coincidencia de cookies si el motor de cookies también está habilitado para esta transferencia. Si la solicitud se realiza sobre HTTP/2 o HTTP/3, el nombre de host personalizado se utiliza en el campo de encabezado ":authority" y Host: no se envía en absoluto por el cable.
Transfer-Encoding: chunked
Indica a libcurl que la subida se realice utilizando este codificado por bloques en lugar de proporcionar el campo Content-Length: en la solicitud.

ENCABEZADOS MIME ESPECÍFICOS

Cuando se utiliza para construir un correo MIME para IMAP o SMTP, los siguientes encabezados de nivel de documento pueden establecerse para sobrescribir los valores generados por libcurl:

Mime-Version:
Indica al analizador en el sitio de destino cómo interpretar el enmarcado MIME. Por defecto es "1.0" y normalmente no debería alterarse.
Content-Type:
Indica el tipo de estructura global del documento. Por defecto, libcurl lo establece en "multipart/mixed", que describe un documento compuesto por partes independientes. Cuando un correo MIME solo está compuesto por representaciones alternativas de los mismos datos (es decir: HTML y texto plano), este encabezado debe establecerse en "multipart/alternative". En todos los casos, el valor debe tener la forma "multipart/*" para respetar la estructura del documento y no puede incluir el parámetro "boundary=".

Otros encabezados específicos que no tienen un valor predeterminado de libcurl pero que son altamente deseados por los agentes de entrega de correo y los usuarios también deben incluirse. Estos son From:, To:, Date: y Subject: entre otros, y su presencia y valor generalmente se comprueban por las utilidades anti-spam.

PREOCUPACIONES DE SEGURIDAD

Por defecto, esta opción hace que libcurl envíe los encabezados dados en todas las solicitudes HTTP realizadas por este handle. Por lo tanto, debe utilizar esta opción con precaución si, por ejemplo, se conecta al sitio remoto utilizando un proxy y una solicitud CONNECT; debe considerar si ese proxy debería recibir también los encabezados. Podrían ser privados o de otro modo sensibles para fugas.

Utilice CURLOPT_HEADEROPT(3) para que los encabezados solo se envíen a donde usted intenda que se envíen.

Los encabezados personalizados se envían en todas las solicitudes realizadas por el handle fácil, lo que implica que si le dice a libcurl que siga las redirecciones (CURLOPT_FOLLOWLOCATION(3)), el mismo conjunto de encabezados personalizados se envía en la solicitud subsiguiente. Las redirecciones pueden ir a otros hosts y por lo tanto esos servidores reciben todo el contenido de sus encabezados personalizados.

A partir de la versión 7.58.0, libcurl impide específicamente que los encabezados "Authorization:" se envíen a otros hosts que no sean el primero utilizado, a menos que se permita específicamente con la opción CURLOPT_UNRESTRICTED_AUTH(3).

A partir de la versión 7.64.0, libcurl impide específicamente que los encabezados "Cookie:" se envíen a otros hosts que no sean el primero utilizado, a menos que se permita específicamente con la opción CURLOPT_UNRESTRICTED_AUTH(3).

DEFAULT

NULL

PROTOCOLS

Esta funcionalidad afecta a http, imap y smtp

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  struct curl_slist *list = NULL;
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* añadir este encabezado */
    list = curl_slist_append(list, "Shoesize: 10");
    /* eliminar este encabezado */
    list = curl_slist_append(list, "Accept:");
    /* cambiar este encabezado */
    list = curl_slist_append(list, "Host: example.net");
    curl_easy_setopt(curl, CURLOPT_HTTPHEADER, list);
    curl_easy_perform(curl);
    curl_slist_free_all(list); /* liberar la lista */
  }
}

DISPONIBILIDAD
