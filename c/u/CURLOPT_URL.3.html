DESCRIPCIÓ

N

Pase un puntero a la URL con la que trabajar. El parámetro debe ser un char * a una cadena terminada en nulo que debe estar codificada en URL en el siguiente

formato:

scheme://host:

port/path

Para una explicación más detallada del formato, consulte RFC

3986.

libcurl no valida la sintaxis ni usa la URL hasta que la transferencia se inicia. Incluso si establece un valor absurdo aquí, curl_easy_setopt(3) podría devolver CURLE_OK

.

Si la URL proporcionada carece de un nombre de esquema (como "http://" o "ftp://" etc), libcurl lo deduce en función de el host. Si el nombre de subdominio más externo coincide con DICT, FTP, IMAP, LDAP, POP3 o SMTP, se usa ese protocolo; de lo contrario, se usa HTTP. Desde la versión 7.45.0, la deducción se puede deshabilitar estableciendo un protocolo predeterminado, consulte CURLOPT_DEFAULT_PROTOCOL(3) para más

detalles.

Si el protocolo, ya sea el especificado por el esquema de la URL o deducido por libcurl a partir del nombre de host, no está soportado por libcurl, entonces se devuelve CURLE_UNSUPPORTED_PROTOCOL desde curl_easy_perform(3) o curl_multi_perform(3) cuando las llama. Use curl_version_info(3) para obtener información detallada sobre qué protocolos están soportados por la compilación de libcurl que está

utilizando.

Se puede usar CURLOPT_PROTOCOLS_STR(3) para limitar qué protocolos puede usar libcurl para esta transferencia, independientemente de lo que libcurl haya sido compilado para soportar. Esto puede ser útil si acepta la URL de una fuente externa y desea limitar la

accesibilidad.

La cadena de CURLOPT_URL(3) se ignora si se ha establecido CURLOPT_CURLU(3)

.

Debe establecerse CURLOPT_URL(3) o CURLOPT_CURLU(3) antes de que se inicie una

transferencia.

La aplicación no tiene que conservar la cadena después de establecer esta

opción.

Usar esta opción varias veces hace que la última cadena establecida reemplace a las anteriores. Establézcala en NULL para deshabilitar su uso de nuevo. Tenga en cuenta sin embargo que libcurl necesita que se establezca una URL para poder realizar una

transferencia.

El analizador utilizado para manejar la URL establecida con CURLOPT_URL(3) es el mismo que curl_url_s

et(3)
usa.

CODIFICACIÓ

N

Se espera que la cadena a la que apunta el argumento de CURLOPT_URL(3) sea generalmente una secuencia de caracteres que utiliza una codificación compatible con

ASCII.

Si libcurl está compilado con soporte IDN, la parte del nombre del servidor de la URL puede usar un "nombre internacional" utilizando la codificación actual (según la configuración regional) o UTF-8 (cuando se usa WinIDN; o una compilación Unicode de Windows usando libidn2)

.

Si libcurl está compilado sin soporte IDN, el nombre de

PREOCUPACIONES DE

SEGURIDAD

Las aplicaciones pueden encontrar a veces conveniente permitir que los usuarios especifiquen URLs para diversos fines y esa cadena terminaría alimentando esta

opción.

Obtener una URL de una parte externa no confiable trae varias preocupaciones de

seguridad:

Si tiene una aplicación que se ejecuta como o en una aplicación de servidor, obtener una URL sin filtrar puede engañar fácilmente a su aplicación para que acceda a un recurso local en lugar de uno remoto. Protegerse contra accesos a localhost es difícil cuando se aceptan URLs proporcionadas por el

usuario.

Dichas URLs personalizadas también pueden acceder a otros puertos de los que usted planeó, ya que los números de puerto son parte del formato de URL regular. La combinación de un host local y un número de puerto personalizado puede permitir que usuarios externos realicen trucos con sus servicios

locales.

Aceptar URLs externas también puede usar otros protocolos que http:// u otros comunes. Restrinja lo que acepta con CURLOPT_PROTOCOLS

_STR(3).

Las URLs proporcionadas por el usuario también pueden hacerse que apunten a sitios que redirigen más allá (posiblemente a otros protocolos también). Considere sus configuraciones de CURLOPT_FOLLOWLOCATION(3) y CURLOPT_REDIR_PR

OTOCOLS
_STR(3).
