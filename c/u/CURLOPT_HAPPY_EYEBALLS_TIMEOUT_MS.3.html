CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS(3)

Paquete: curl

Licencias: MIT

CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS(3) Manual de funciones de la biblioteca CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS(3)

NOMBRE

CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS - tiempo de los intentos de conexión

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS,
                          long timeout);

DESCRIPCIÓN

Happy eyeballs es un algoritmo que controla la conexión a un host que se resuelve a más de una dirección IP. Una configuración común es exponer una dirección IPv4 y otra IPv6 (dual-stack). Otros hosts ofrecen un rango de direcciones para una o ambas pilas.

Direcciones IP
Cuando curl se compila con soporte para IPv6, intenta conectarse primero a IPv6, cuando está disponible. Cuando falla, se inicia otro intento de conexión para la primera dirección IPv4 (de nuevo, si está disponible). Si eso falla, se usa la siguiente dirección IPv6, luego la siguiente IPv4, etc. Si solo hay direcciones para una pila, esas se prueban una tras otra.

Cuando no hay una respuesta positiva ni negativa a un intento, se inicia otro intento después de que haya pasado el timeout. Luego otro, después de que el timeout haya pasado de nuevo. Siempre que haya direcciones disponibles.

Cuando se han probado y fallado todas las direcciones, la transferencia falla. Todos los intentos se abortan después de que haya pasado CURLOPT_CONNECTTIMEOUT_MS(3), contado desde el primer intento en adelante.

El rango de valores útiles sugeridos para timeout es limitado. El RFC 6555 de Happy Eyeballs dice: "Se RECOMIENDA que los intentos de conexión se espacien entre 150 y 250 ms para equilibrar los factores humanos con la carga de la red." libcurl actualmente usa 200 ms por defecto. Firefox y Chrome actualmente usan 300 ms por defecto.

Como ejemplo, para un host que se resuelve a 'a1_v4, a2_v4, a3_v6, a4_v6', curl abre primero un socket a 'a3_v6'. Cuando este no responde, abre otro socket a 'a1_v4' después de 200ms. El primer socket permanece abierto y aún podría tener éxito. Cuando han pasado 200ms más, se abre un socket para 'a4_v6'. 200ms después, se prueba 'a2_v4'.

En este punto, hay 4 sockets abiertos (a menos que la red haya reportado algo). Eso tomó 3 veces el tiempo de espera de happy eyeballs, es decir, 600ms en la configuración predeterminada. Cuando cualquiera de esos cuatro reporte éxito, ese socket se usará para la transferencia y los otros tres se cerrarán.

Hay situaciones en las que los intentos de conexión fallan, pero la falla se considera inconclusa. El protocolo QUIC puede encontrar esto. Cuando un servidor QUIC se reinicia, puede enviar respuestas indicando que no está aceptando nuevas conexiones en este momento, pero quizás más tarde.

Tales fallas de intentos de conexión "inconclusas" provocan un reinicio del intento, con la misma dirección en un nuevo socket, cerrando el anterior. Repetidamente hasta que CURLOPT_CONNECTTIMEOUT_MS(3) se agote.

HTTPS
Cuando la conexión con el protocolo HTTPS a un host que puede hablar HTTP/3, HTTP/2 o HTTP/1.1, curl aplica una estrategia similar de happy eyeballs al intentar estas versiones.

Cuando HTTPS solo implica una conexión TCP, las versiones se negocian a través de ALPN, la extensión TLS, en una sola conexión. Dado que HTTP/3 se ejecuta sobre QUIC (que se ejecuta sobre UDP), requiere un intento de conexión separado.

El intento de HTTP/3 se inicia primero y, después de que expira el timeout, el intento de HTTP/2 (o 1.1) se inicia en paralelo.

POR DEFECTO

CURL_HET_DEFAULT (actualmente definido como 200L)

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles.

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS, 300L);
    curl_easy_perform(curl);
    /* siempre limpiar */
    curl_easy_cleanup(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.59.0

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode indicando éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, consulte libcurl-errors(3).
