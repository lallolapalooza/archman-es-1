curl_multi_perform(3)

Paquete: curl

Licencias: MIT

curl_multi_perform(3) Manual de Funciones de Biblioteca curl_multi_perform(3)

NOMBRE

curl_multi_perform - ejecuta todas las transferencias hasta que sea necesario bloquear

SINOPSIS

#include <curl/curl.h>
CURLMcode curl_multi_perform(CURLM *multi_handle, int *running_handles);

DESCRIPCIÓN

Esta función realiza transferencias en todos los manejadores añadidos que necesitan atención de forma no bloqueante. Los manejadores fáciles se han añadido previamente al manejador múltiple con curl_multi_add_handle(3).

Cuando una aplicación ha descubierto que hay datos disponibles para el manejador múltiple o ha transcurrido un tiempo de espera, la aplicación debe llamar a esta función para leer/escribir lo que haya para leer o escribir en ese momento, etc. curl_multi_perform(3) retorna tan pronto como las lecturas/escrituras se completan. Esta función no requiere que haya datos disponibles para leer o que se puedan escribir datos, se puede llamar por si acaso. Almacena el número de manejadores que todavía transfieren datos en el puntero entero del segundo argumento.

Si la cantidad de running_handles cambia desde la llamada anterior (o es menor que la cantidad de manejadores fáciles que has añadido al manejador múltiple), sabes que hay una o más transferencias menos "en ejecución". Entonces puedes llamar a curl_multi_info_read(3) para obtener información sobre cada transferencia individual completada, y esa información devuelta incluye CURLcode y más. Si un manejador añadido falla rápidamente, puede que nunca se cuente como un running_handle. Podrías usar curl_multi_info_read(3) para rastrear el estado real de los manejadores añadidos en ese caso.

Cuando running_handles se establece en cero (0) al retornar esta función, ya no hay transferencias en progreso.

Cuando esta función retorna un error, el estado de todas las transferencias es incierto y no pueden continuar. curl_multi_perform(3) no debe ser llamada de nuevo en el mismo manejador múltiple después de que se haya retornado un error, a menos que primero se eliminen todos los manejadores y se añadan nuevos.

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles

EJEMPLO

int main(void)
{
  int still_running;
  CURLM *multi = curl_multi_init();
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_multi_add_handle(multi, curl);
    do {
      CURLMcode mc = curl_multi_perform(multi, &still_running);
      if(!mc && still_running)
        /* esperar actividad, tiempo de espera o "nada" */
        mc = curl_multi_poll(multi, NULL, 0, 1000, NULL);
      if(mc) {
        fprintf(stderr, "curl_multi_poll() falló, código %d.\n", (int)mc);
        break;
      }
    /* si todavía hay transferencias, continuar el bucle */
    } while(still_running);
  }
}

DISPONIBILIDAD

Añadido en curl 7.9.6

VALOR DE RETORNO

Esta función devuelve un CURLMcode que indica éxito o error.

CURLM_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, ver libcurl-errors(3).

Esta función devuelve errores relacionados con toda la pila múltiple. Pueden haber ocurrido problemas en transferencias individuales incluso cuando esta función devuelve CURLM_OK. Usa curl_multi_info_read(3) para averiguar cómo resultaron las transferencias individuales.

USO TÍPICO

La mayoría de las aplicaciones usan curl_multi_poll(3) para hacer que libcurl espere actividad en cualquiera de las transferencias en curso. Tan pronto como uno o más descriptores de archivo tengan actividad o la función expire el tiempo de espera, la aplicación llama a curl_multi_perform(3).
