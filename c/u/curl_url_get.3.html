curl_url_get(3)

Paquete: curl

Licencias: MIT

curl_url_get(3) Manual de Funciones de Biblioteca curl_url_get(3)

NOMBRE

curl_url_get - extraer una parte de una URL

SINOPSIS

#include <curl/curl.h>
CURLUcode curl_url_get(const CURLU *url,
                       CURLUPart part,
                       char **content,
                       unsigned int flags);

DESCRIPCIÓN

Dada una URL de manejador url de un objeto URL, esta función extrae una pieza individual o la URL completa del mismo.

El argumento part especifica qué parte extraer (ver la lista a continuación) y content apunta a un 'char *' que se actualizará para apuntar a una cadena recién asignada con el contenido.

El argumento flags es una máscara de bits con características individuales.

El puntero de contenido devuelto debe liberarse con curl_free(3) después de su uso.

FLAGS

El argumento flags es cero, uno o más bits establecidos en una máscara de bits.

CURLU_DEFAULT_PORT
Si el manejador no tiene un puerto almacenado, esta opción hace que curl_url_get(3) devuelva el puerto por defecto para el esquema utilizado.
CURLU_DEFAULT_SCHEME
Si el manejador no tiene un esquema almacenado, esta opción hace que curl_url_get(3) devuelva el esquema por defecto en lugar de un error.
CURLU_NO_DEFAULT_PORT
Instruye a curl_url_get(3) para que no devuelva un número de puerto si coincide con el puerto por defecto para el esquema.
CURLU_URLDECODE
Solicita a curl_url_get(3) que decodifique la URL el contenido antes de devolverlo. No decodifica el esquema, el número de puerto ni la URL completa.

El componente de consulta también obtiene la conversión de signo más a espacio como un extra cuando este bit está activado.

Tenga en cuenta que esta decodificación de URL no tiene en cuenta la codificación de caracteres y usted recibe una cadena terminada en nulo con datos que podrían estar destinados a una codificación particular.

Si hay valores de bytes inferiores a 32 en la cadena decodificada, la operación de obtención devuelve un error en su lugar.

CURLU_URLENCODE
Si está activado, curl_url_get(3) codifica la URL el nombre de host cuando se recupera una URL completa. Si no está activado (por defecto), libcurl devuelve la URL con el nombre de host sin procesar para admitir que los nombres IDN aparezcan tal cual. Los nombres de host IDN suelen utilizar bytes no ASCII que de lo contrario se codifican con porcentaje.

Tenga en cuenta que incluso cuando no se solicita la codificación de URL, el '%' (byte 37) se codifica con URL para garantizar que el nombre de host siga siendo válido.

CURLU_PUNYCODE
Si está activado y CURLU_URLENCODE no está activado, y se solicita recuperar las partes CURLUPART_HOST o CURLUPART_URL, libcurl devuelve el nombre de host en su versión punycode si contiene algún octeto no ASCII (y es un nombre IDN).

Si libcurl está compilado sin capacidades IDN, usar este bit hace que curl_url_get(3) devuelva CURLUE_LACKS_IDN si el nombre de host contiene algo fuera del rango ASCII.

(Añadido en curl 7.88.0)

CURLU_PUNY2IDN
Si está activado y se solicita recuperar las partes CURLUPART_HOST o CURLUPART_URL, libcurl devuelve el nombre de host en su versión IDN (International Domain Name) UTF-8 si de lo contrario es una versión punycode. Si el nombre punycode no se puede convertir a IDN correctamente, libcurl devuelve CURLUE_BAD_HOSTNAME.

Si libcurl está compilado sin capacidades IDN, usar este bit hace que curl_url_get(3) devuelva CURLUE_LACKS_IDN si el nombre de host utiliza punycode.

(Añadido en curl 8.3.0)

CURLU_GET_EMPTY
Cuando se utiliza este flag en curl_url_get(), hace que la función devuelva partes de consulta y fragmentos vacías o cuando se utiliza en la URL completa. Por defecto, libcurl considera las partes vacías como inexistentes.

Una parte de consulta vacía es aquella en la que no hay nada después del signo de interrogación (antes del posible fragmento). Una parte de fragmento vacía es aquella en la que no hay nada después del signo de almohadilla.

(Añadido en curl 8.8.0)

CURLU_NO_GUESS_SCHEME
Cuando se utiliza este flag en curl_url_get(), trata el esquema como inexistente si se estableció como resultado de una suposición previa; cuando se utilizó CURLU_GUESS_SCHEME al analizar una URL.

Usar este flag al obtener CURLUPART_SCHEME si el esquema se estableció como resultado de una suposición hace que curl_url_get() devuelva CURLUE_NO_SCHEME.

Usar este flag al obtener CURLUPART_URL si el esquema se estableció como resultado de una suposición hace que curl_url_get() devuelva la URL completa sin el componente de esquema. Dicha URL solo se podrá analizar con curl_url_set() si se utiliza CURLU_GUESS_SCHEME.

(Añadido en curl 8.9.0)

PARTES

CURLUPART_URL
Cuando se solicita la URL completa, curl_url_get(3) devuelve una versión ligeramente limpiada de la URL completa utilizando todas las partes disponibles.

Aconsejamos usar la opción CURLU_PUNYCODE para obtener la URL lo más "normalizada" posible, ya que IDN permite que los nombres de host se escriban de muchas maneras diferentes que aún así terminan en la misma versión punycode.

Las consultas y fragmentos de longitud cero se excluyen de la URL a menos que se establezca CURLU_GET_EMPTY.

CURLUPART_SCHEME
El esquema no se puede decodificar con URL al obtenerlo.
CURLUPART_USER
CURLUPART_PASSWORD
CURLUPART_OPTIONS
El campo de opciones es un campo opcional que puede seguir a la contraseña en la parte de información del usuario. Solo se reconoce/utiliza al analizar URLs para los siguientes esquemas: pop3, smtp e imap. La API de URL aún permite a los usuarios establecer y obtener este campo independientemente del esquema cuando no se analizan URLs completas.
CURLUPART_HOST
El nombre de host. Si es una dirección numérica IPv6, el ID de zona no forma parte de él, sino que se proporciona por separado en CURLUPART_ZONEID. Las direcciones numéricas IPv6 se devuelven entre corchetes ([]).

Los nombres IPv6 se normalizan al establecerse, lo que debería hacerlos lo más cortos posible manteniendo una sintaxis correcta.

CURLUPART_ZONEID
Si el nombre de host es una dirección IPv6 numérica, este campo también puede estar establecido.
CURLUPART_PORT
Un puerto no se puede decodificar con URL al obtenerlo. Este número se devuelve en una cadena, al igual que todas las demás partes. Esa cadena garantiza que contendrá un número de puerto válido en ASCII utilizando base 10.
CURLUPART_PATH
La parte es siempre al menos una barra ('/') incluso si no se proporcionó ningún camino en la URL. Un camino de URL siempre comienza con una barra.
CURLUPART_QUERY
El signo de interrogación inicial que denota el comienzo de la parte de consulta es solo un delimitador. No forma parte del contenido de la consulta.

Una consulta no presente devuelve la parte como NULL.

Una consulta de longitud cero devuelve la parte como NULL, a menos que se establezca CURLU_GET_EMPTY.

La parte de consulta obtiene la conversión de signos más a espacio cuando se solicita decodificar la URL al obtenerla con el bit CURLU_URLDECODE.

CURLUPART_FRAGMENT
El signo de almohadilla inicial que denota el comienzo del fragmento es solo un delimitador. No forma parte del contenido del fragmento.

Una consulta no presente devuelve part como NULL.

Una consulta de longitud cero devuelve part como NULL a menos que CURLU_GET_EMPTY esté activado.

RETURN

On success, returns the CURLUcode value CURLE_OK (0). On failure, returns a non-zero error code.

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos soportados

EJEMPLO

int main(void)
{
  CURLUcode rc;
  CURLU *url = curl_url();
  rc = curl_url_set(url, CURLUPART_URL, "https://example.com", 0);
  if(!rc) {
    char *scheme;
    rc = curl_url_get(url, CURLUPART_SCHEME, &scheme, 0);
    if(!rc) {
      printf("the scheme is %s\n", scheme);
      curl_free(scheme);
    }
    curl_url_cleanup(url);
  }
}

DISPONIBILIDAD

Añadido en curl 7.62.0

VALOR DE RETORNO

Devuelve un valor de error CURLUcode, que es CURLUE_OK (0) si todo salió bien. Consulta la página de manual libcurl-errors(3) para la lista completa con descripciones.

Si esta función devuelve un error, no se devuelve ninguna parte de la URL.
