En définissant les options appropriées, l'application peut modifier le comportement de libcurl. Toutes les options sont définies avec une option suivie d'un paramètre. Ce paramètre peut être un long, un pointeur de fonction, un pointeur d'objet ou un curl_off_t, selon ce que l'option spécifique attend. Lisez ce manuel attentivement car de mauvaises valeurs d'entrée peuvent faire que libcurl se comporte mal. Vous ne pouvez définir qu'une option par appel de fonction. Une application typique utilise de nombreux appels curl_easy_setopt(3) dans la phase de configuration. L'argument handle est le

code

de retour d'un appel curl_easy_init(3) ou curl_easy_duphandle(3) . Les options définies avec cet appel

sont persistantes. Elles restent définies pour tous les transferts à venir effectués à l'aide de ce handle. Les options ne sont en aucun cas réinitialisées entre les transferts, donc si vous voulez des transferts ultérieurs avec des options différentes, vous devez les modifier entre les transferts. Esta función devuelve un CURLcode que indica éxito o

error.

CURLE_OK (0) significa que todo fue correcto, un valor distinto de cero significa que ocurrió un error, véase libcurl-errors(3). Si CURLOPT_ERRORBUFFER(3) fue establecido con curl_easy_setopt(3) puede haber un mensaje de error almacenado en el búfer de error cuando se devuelve un valor distinto de

cero.

Las cadenas pasadas a libcurl deben ser más cortas que 8000000 bytes, de lo contrario curl_easy_setopt(3) devuelve CURLE_BAD_FUNCTION_ARGUMENT (añadido en 7.65.0)

.

Se devuelve CURLE_BAD_FUNCTION_ARGUMENT cuando el argumento de una opción no es válido, como por ejemplo fuera de

rango.

Si intenta establecer una opción que libcurl no conoce, quizás porque la biblioteca es demasiado antigua para soportarla o la opción fue eliminada en una versión reciente, esta función devuelve CURLE_UNKNOWN_OPTION. Si el soporte para la opción fue deshabilitado en tiempo de compilación, devuelve CURLE_NOT_BUILT_I
