DESCRIPCIÓ

N

La biblioteca ncurses puede configurarse para soportar aplicaciones multihilo de una manera rudimentaria. Tal configuración produce un conjunto diferente de bibliotecas, denominadas libncursest, por ejemplo, ya que hacerlo altera la interfaz binaria de aplicación (ABI) de

ncurses.

En lugar de modificar la interfaz de programación (API) para que las funciones de ncurses esperen un argumento adicional que especifique un hilo, la biblioteca añade funciones, utilizables en cualquier configuración, que ocultan los mutexes (candados de exclusión mutua) necesarios para evitar el acceso concurrente a variables compartidas por múltiples hilos de

ejecución.

El soporte de hilos de ncurses requiere el uso de funciones para acceder a los miembros de la estructura WINDOW (ver curs_opaque(3X)). Además, convierte en funciones las variables globales comunes COLORS, COLOR_PAIRS, COLS, ESCDELAY, LINES, TABSIZE, curscr, newscr y ttytype, manteniéndolas como valores de solo lectura en la estructura S

CREEN.

Incluso esto no es suficiente para que una aplicación que utilice curses sea segura en hilos. Esperaríamos que una aplicación multihilo tuviera hilos que actualicen ventanas separadas (en el mismo dispositivo) y pantallas separadas (en diferentes dispositivos). Además, las aplicaciones esperan que algunas de las variables globales sean escribibles. Las funciones descritas aquí abordan estas situaciones

especiales.

Las variables globales ESCDELAY y TABSIZE son modificadas por algunas aplicaciones. Para modificarlas en cualquier configuración, use las funciones set_escdelay o set_tabsize. Otras variables globales no son modificables. get_escdelay recupera el valor de

ESCDELAY.

Las funciones use_window y use_screen proporcionan mutexes de granularidad gruesa para sus respectivos parámetros WINDOW y SCREEN; llaman a una función proporcionada por el usuario, le pasan un parámetro data, y devuelven el valor de la función proporcionada por el usuario a la

aplicación.
