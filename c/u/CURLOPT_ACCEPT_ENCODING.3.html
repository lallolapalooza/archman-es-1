CURLOPT_ACCEPT_ENCODING(3)

Paquete: curl

Licencias: MIT

CURLOPT_ACCEPT_ENCODING(3) Manual de Funciones de Biblioteca CURLOPT_ACCEPT_ENCODING(3)

NOMBRE

CURLOPT_ACCEPT_ENCODING - descompresión automática de descargas HTTP

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_ACCEPT_ENCODING, char *enc);

DESCRIPCIÓN

Pasa un puntero a cadena de caracteres especificando qué codificación te gustaría.

Establece el contenido de la cabecera Accept-Encoding: enviada en una solicitud HTTP y habilita la decodificación de una respuesta cuando se recibe una cabecera Content-Encoding:.

libcurl soporta potencialmente varias codificaciones comprimidas diferentes dependiendo de qué soporte tenga incorporado.

Para ayudar a las aplicaciones a no tener que preocuparse por los algoritmos específicos que soporta esta compilación particular de libcurl, libcurl permite establecer una cadena de longitud cero ("") para pedir que se utilice una cabecera Accept-Encoding: que contenga todas las codificaciones soportadas incorporadas.

Alternativamente, puedes especificar exactamente la codificación o la lista de codificaciones que deseas en la respuesta. Las siguientes codificaciones son soportadas: identity, que significa sin comprimir, deflate que solicita al servidor que comprima su respuesta usando el algoritmo zlib, gzip que solicita el algoritmo gzip, (desde curl 7.57.0) br que es brotli y (desde curl 7.72.0) zstd que es zstd. Proporciónalas en la cadena como una lista separada por comas de las codificaciones aceptadas, por ejemplo: "br, gzip, deflate".

Establece CURLOPT_ACCEPT_ENCODING(3) a NULL para deshabilitarlo explícitamente, lo que hace que libcurl no envíe una cabecera Accept-Encoding: y no descomprima automáticamente el contenido recibido.

También puedes optar por incluir solo la cabecera Accept-Encoding: en tu solicitud con CURLOPT_HTTPHEADER(3) pero entonces no hay descompresión automática al recibir datos.

Esto es una solicitud, no una orden; el servidor puede hacerlo o no. Esta opción debe establecerse (a cualquier valor distinto de NULL) o de lo contrario se ignorará cualquier codificación no solicitada realizada por el servidor.

Los servidores pueden responder con Content-Encoding incluso sin recibir un Accept-Encoding: en la solicitud. Los servidores pueden responder con un Content-Encoding diferente al solicitado en la solicitud.

Se supone que la Content-Length: que envían los servidores para una respuesta comprimida indica la longitud del contenido comprimido, por lo que cuando la descompresión automática está habilitada, puede no coincidir con la suma de bytes reportada por las devoluciones de llamada de escritura (aunque enviar la longitud del contenido no comprimido es un error común del servidor).

La aplicación no tiene que mantener la cadena disponible después de establecer esta opción.

Utilizar esta opción varias veces hace que la última cadena establecida anule las anteriores.

HISTORIA

Esta opción se llamaba CURLOPT_ENCODING antes de la versión 7.21.6

NOTAS

La versión específica de libcurl que estés utilizando debe haber sido compilada con zlib para poder descomprimir respuestas gzip y deflate, con la biblioteca brotli para descomprimir respuestas brotli y con la biblioteca zstd para descomprimir respuestas zstd.

POR DEFECTO

NULL

PROTOCOLOS

Esta funcionalidad afecta solo a http

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* habilita todas las compresiones incorporadas soportadas */
    curl_easy_setopt(curl, CURLOPT_ACCEPT_ENCODING, "");
    /* Realiza la solicitud */
    curl_easy_perform(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.21.6

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode indicando éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, ver libcurl-errors(3).
