CURLOPT_POSTFIELDS(3)

Paquete: curl

Licencias: MIT

CURLOPT_POSTFIELDS(3) Manual de funciones de biblioteca CURLOPT_POSTFIELDS(3)

NOMBRE

CURLOPT_POSTFIELDS - datos para enviar mediante POST al servidor

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_POSTFIELDS, char *postdata);

DESCRIPCIÓN

Pase un puntero a char como parámetro, apuntando al búfer de datos a usar en una operación POST de HTTP o una suscripción de MQTT. Los datos deben estar formateados y codificados de la manera que desea que el servidor los reciba. libcurl no los convierte ni codifica de ninguna manera. Por ejemplo, un servidor web puede asumir que estos datos están codificados en URL.

Los datos a los que se apunta NO son copiados por la biblioteca: como consecuencia, deben ser conservados por la aplicación que llama hasta que la transferencia asociada finalice. Este comportamiento se puede cambiar (para que libcurl copie los datos) utilizando en su lugar la opción CURLOPT_COPYPOSTFIELDS(3).

Este POST es del tipo normal application/x-www-form-urlencoded (y libcurl establece ese Content-Type por defecto cuando se usa esta opción), que es comúnmente usado por los formularios HTML. Cambie Content-Type con CURLOPT_HTTPHEADER(3).

Puede usar curl_easy_escape(3) para codificar sus datos en URL, si es necesario. Devuelve un puntero a una cadena codificada que puede ser pasada como postdata.

El uso de CURLOPT_POSTFIELDS(3) implica establecer CURLOPT_POST(3) a 1.

Si CURLOPT_POSTFIELDS(3) se establece explícitamente a NULL entonces libcurl obtiene los datos POST del callback de lectura. Para enviar un POST de longitud cero (vacío), establezca CURLOPT_POSTFIELDS(3) a una cadena vacía, o establezca CURLOPT_POST(3) a 1 y CURLOPT_POSTFIELDSIZE(3) a 0.

libcurl asume que esta opción apunta a una cadena terminada en nulo a menos que también establezca CURLOPT_POSTFIELDSIZE(3) para especificar la longitud de los datos proporcionados, lo cual es estrictamente requerido si desea enviar bytes nulos incluidos en los datos.

Usar POST con HTTP 1.1 implica el uso de una cabecera "Expect: 100-continue", y libcurl añade esa cabecera automáticamente si se sabe que el POST es mayor que 1 MB o si el tamaño esperado es desconocido. Puede deshabilitar esta cabecera con CURLOPT_HTTPHEADER(3) como de costumbre.

Para realizar publicaciones multipart/formdata, consulte la opción CURLOPT_MIMEPOST(3) combinada con curl_mime_init(3).

El uso de esta opción varias veces hace que el último puntero establecido anule los anteriores. Establézcala a NULL para deshabilitar su uso nuevamente.

POR DEFECTO

NULL

PROTOCOLOS

Esta funcionalidad afecta a http y mqtt

EJEMPLO

/* enviar un POST application/x-www-form-urlencoded */
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    const char *data = "datos a enviar";
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* tamaño de los datos POST si strlen() no es suficiente */
    curl_easy_setopt(curl, CURLOPT_POSTFIELDSIZE, 12L);
    /* pasar un puntero a los datos - libcurl no copia */
    curl_easy_setopt(curl, CURLOPT_POSTFIELDS, data);
    curl_easy_perform(curl);
  }
  /* enviar un POST application/json */
  curl = curl_easy_init();
  if(curl) {
    const char *json = "{\"nombre\": \"daniel\"}";
    struct curl_slist *slist1 = NULL;
    slist1 = curl_slist_append(slist1, "Content-Type: application/json");
    slist1 = curl_slist_append(slist1, "Accept: application/json");
    /* establecer cabeceras personalizadas */
    curl_easy_setopt(curl, CURLOPT_HTTPHEADER, slist1);
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* pasar un puntero a los datos - libcurl no copia */
    curl_easy_setopt(curl, CURLOPT_POSTFIELDS, json);
    curl_easy_perform(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.1

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, distinto de cero significa que ocurrió un error, ver libcurl-errors(3).
