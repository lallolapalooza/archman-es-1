CURLOPT_SSL_VERIFYHOST(3)

Paquete: curl

Licencias: MIT

CURLOPT_SSL_VERIFYHOST(3) Manual de funciones de la biblioteca CURLOPT_SSL_VERIFYHOST(3)

NOMBRE

CURLOPT_SSL_VERIFYHOST - verificar el nombre del certificado con el host

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_SSL_VERIFYHOST, long verify);

DESCRIPCIÓN

Pase un long establecido en 2L para que libcurl verifique el host en el certificado TLS del servidor.

Al negociar una conexión TLS, el servidor envía un certificado que indica su identidad.

Cuando CURLOPT_SSL_VERIFYHOST(3) está establecido en 1 o 2, el certificado del servidor debe indicar que se hizo para el nombre de host o dirección al que se conecta curl, o la conexión fallará. En pocas palabras, significa que debe tener el mismo nombre en el certificado que el que se utiliza en la URL con la que opera.

curl considera que el servidor es el previsto cuando el campo Common Name o un campo Subject Alternate Name en el certificado coincide con el nombre de host en la URL a la que le dijo a curl que se conecte.

Cuando el valor verify es 0, la conexión tiene éxito sin importar los nombres en el certificado. Use esa capacidad con precaución.

Esta opción controla la verificación de la identidad reclamada del certificado del servidor. Las opciones separadas CURLOPT_SSL_VERIFYPEER(3) habilitan/deshabilitan la verificación de que el certificado está firmado por una Autoridad Certificadora de confianza.

ADVERTENCIA: deshabilitar la verificación del certificado permite a los malos interceptar la comunicación sin que usted lo sepa. Deshabilitar la verificación hace que la comunicación no sea segura. Simplemente tener cifrado en una transferencia no es suficiente, ya que no puede estar seguro de que se está comunicando con el punto final correcto.

Cuando libcurl utiliza protocolos seguros, confía en las respuestas y permite, por ejemplo, que la información HSTS y Alt-Svc se almacene y se utilice posteriormente. Deshabilitar la verificación del certificado puede hacer que libcurl confíe y utilice dicha información de servidores maliciosos.

COINCIDENCIA

Un certificado puede tener el nombre como un comodín. El único asterisco (*) debe ser el carácter más a la izquierda y debe ir seguido de un punto. El comodín debe contener más de un punto, ya que no se puede establecer para un dominio de nivel superior.

Un certificado se puede establecer para una dirección IP numérica (IPv4 o IPv6), pero entonces debe ser de tipo Subject Alternate Name y su tipo debe identificar correctamente el campo como una dirección IP.

POR DEFECTO

2

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos basados en TLS: HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Todos los backends TLS soportan esta opción.

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* Establecer el valor por defecto: por favor, verificación estricta del nombre */
    curl_easy_setopt(curl, CURLOPT_SSL_VERIFYHOST, 2L);
    curl_easy_perform(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.8.1

HISTORIAL

En 7.28.0 y anteriores: el valor 1 se trataba como una opción de depuración de algún tipo, ya no soportada debido a que frecuentemente conducía a errores de programador.

Desde 7.28.1 hasta 7.65.3: establecerlo en 1 hacía que curl_easy_setopt(3) devolviera un error y dejara la bandera intacta.

Desde 7.66.0: libcurl trata 1 y 2 para esta opción de la misma manera.

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error; véase libcurl-errors(3).
