DESCRIPCIÓ

N

Pase un puntero a un struct curl_tlssessioninfo *. El puntero se inicializa para referirse a un struct curl_tlssessioninfo * que contiene un enum que indica la biblioteca SSL utilizada para el handshake y un puntero a la estructura de sesión TLS interna correspondiente de esta biblioteca SSL

subyacente.

Esta opción puede ser útil, por ejemplo, para extraer información del certificado en un formato conveniente para un procesamiento posterior, como la validación manual. Consulte la sección LIMITA

CIONES. 
struct curl_tlssessioninfo {

LIMITACIONE

S

Esta opción tiene algunas limitaciones que podrían hacerla insegura cuando se trata de la verificación manual de

certificados.

Esta opción solo recupera el primer puntero de sesión SSL en uso para su easy handle, sin embargo su easy handle puede tener más de una sesión SSL en uso si usa FTP sobre SSL. Esto se debe a que el protocolo FTP tiene un canal de control y un canal de datos, y uno o ambos pueden estar sobre SSL. Actualmente no hay forma de recuperar una segunda sesión SSL en uso asociada con un easy

handle.

Esta opción no ha sido probada exhaustivamente con protocolos de texto claro que pueden ser actualizados/degradados a/desde SSL: FTP, SMTP, POP3, IMAP cuando se usa con CURLOPT_USE_SSL(3). Aunque puede recuperar el puntero SSL, es posible que antes de que pueda hacerlo, los datos (incluyendo la autenticación) ya se hayan enviado sobre una conexión después de que esta fue

actualizada.

Renegociación. Si su biblioteca SSL permite la renegociación insegura o una renegociación de tal manera que se permite que el certificado cambie, esto puede ocurrir y el certificado puede cambiar, y los datos pueden continuar enviándose o recibiéndose después de la renegociación pero antes de que usted pueda obtener el puntero SSL (posiblemente) cambiado, con la información del certificado (posiblemente)

cambiada.

En lugar de usar esta opción para sondear cambios en el certificado, use CURLOPT_SSL_CTX_FUNCTION(3) para establecer una función de verificación, si está soportado. Eso es más seguro y no sufre de ninguno de los problemas

anteriores.

EJEMPL

O 
#include <curl/curl.h>
#include <openssl/ssl.h>
CURL *curl;
static size_t wf(void *ptr, size_t size, size_t nmemb, void *stream)
{
  const struct curl_tlssessioninfo *info = NULL;
  CURLcode res = curl_easy_getinfo(curl, CURLINFO_TLS_SSL_PTR, &info);
  if(info && !res) {
    if(CURLSSLBACKEND_OPENSSL == info->backend) {
      printf("OpenSSL ver. %s\n", SSL_get_version((SSL*)info->internals));
    }
  }
  return size * nmemb;
}
int main(int argc, char **argv)
{
  CURLcode res;
  curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_WRITEFUNCTION, wf);
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
  return res;
}
