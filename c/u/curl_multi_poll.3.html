curl_multi_poll(3)

Paquete: curl

Licencias: MIT

curl_multi_poll(3) Manual de funciones de biblioteca curl_multi_poll(3)

NOMBRE

curl_multi_poll - sondear todos los manejadores fáciles en un manejador múltiple

SINOPSIS

#include <curl/curl.h>
CURLMcode curl_multi_poll(CURLM *multi_handle,
                          struct curl_waitfd extra_fds[],
                          unsigned int extra_nfds,
                          int timeout_ms,
                          int *numfds);

DESCRIPCIÓN

curl_multi_poll(3) sondea todos los descriptores de archivo utilizados por los manejadores fáciles de curl contenidos en el conjunto de manejadores múltiples dado. Bloquea hasta que se detecta actividad en al menos uno de los manejadores o ha transcurrido el timeout_ms. Alternativamente, si el manejador múltiple tiene un tiempo de espera interno pendiente que tiene una fecha de caducidad más corta que timeout_ms, se utiliza ese tiempo más corto en su lugar para asegurar que la precisión del tiempo de espera se mantenga razonablemente.

La aplicación que llama puede pasar estructuras curl_waitfd adicionales que son similares a la estructura pollfd de poll(2) para ser esperadas en la misma llamada.

Al finalizar, si numfds no es NULL, se pobla con el número total de descriptores de archivo en los que ocurrieron eventos interesantes. Este número puede incluir tanto descriptores internos de libcurl como descriptores proporcionados en extra_fds.

La función curl_multi_wakeup(3) puede ser utilizada desde otro hilo para despertar a esta función y devolver más rápido. Este es uno de los detalles que hace que esta función sea diferente a curl_multi_wait(3) que no puede ser despertada de esta manera.

Si no se proporcionan descriptores de archivo adicionales y libcurl no tiene ningún descriptor de archivo que ofrecer para esperar, esta función espera durante timeout_ms milisegundos (o menos si un temporizador interno lo indica). Este es el otro detalle que hace que esta función sea diferente a curl_multi_wait(3).

Se recomienda utilizar esta función en lugar de select(3) al usar la interfaz múltiple para permitir que las aplicaciones eviten más fácilmente el problema común de los 1024 descriptores de archivo máximos.

curl_waitfd

struct curl_waitfd {
  curl_socket_t fd;
  short events;
  short revents;
};
CURL_WAIT_POLLIN
Bandera de bits para curl_waitfd.events que indica que el socket debe sondear eventos de lectura tales como nuevos datos recibidos.
CURL_WAIT_POLLPRI
Bandera de bits para curl_waitfd.events que indica que el socket debe sondear eventos de lectura de alta prioridad tales como datos fuera de banda.
CURL_WAIT_POLLOUT
Bandera de bits para curl_waitfd.events que indica que el socket debe sondear eventos de escritura tales como que el socket está listo para escribir sin bloquear.

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles

EJEMPLO

extern void handle_fd(int);
int main(void)
{
  CURL *easy_handle;
  CURLM *multi_handle;
  int still_running = 0;
  int myfd = 2; /* este es nuestro propio descriptor de archivo */
  multi_handle = curl_multi_init();
  easy_handle = curl_easy_init();
  /* añadir el manejador fácil individual */
  curl_multi_add_handle(multi_handle, easy_handle);
  do {
    CURLMcode mc;
    int numfds;
    mc = curl_multi_perform(multi_handle, &still_running);
    if(mc == CURLM_OK) {
      struct curl_waitfd myown;
      myown.fd = myfd;
      myown.events = CURL_WAIT_POLLIN; /* esperar entrada */
      myown.revents = 0; /* limpiarlo */
      /* esperar actividad en los descriptores de curl o en el nuestro,
         o tiempo de espera */
      mc = curl_multi_poll(multi_handle, &myown, 1, 1000, &numfds);
      if(myown.revents) {
        /* ¿recibió nuestro descriptor un evento? */
        handle_fd(myfd);
      }
    }
    if(mc != CURLM_OK) {
      fprintf(stderr, "curl_multi falló, código %d.\n", mc);
      break;
    }
  } while(still_running);
  curl_multi_remove_handle(multi_handle, easy_handle);
}

DISPONIBILIDAD

Añadido en curl 7.66.0

VALOR DE RETORNO

Esta función devuelve un CURLMcode que indica éxito o error.

CURLM_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, ver libcurl-errors(3).
