CURLOPT_AWS_SIGV4(3)

Paquete: curl

Licencias: MIT

CURLOPT_AWS_SIGV4(3) Manual de funciones de biblioteca CURLOPT_AWS_SIGV4(3)

NOMBRE

CURLOPT_AWS_SIGV4 - Firma V4

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_AWS_SIGV4, char *param);

DESCRIPCIÓN

Proporciona autenticación de firma V4 de AWS en la cabecera HTTP(S).

Pase un puntero a char que sea la colección de argumentos específicos que se utilizan para crear cabeceras de autenticación salientes. El formato de la opción param es:

proveedor1[:proveedor2[:region[:servicio]]]
proveedor1, proveedor2
Los argumentos de los proveedores se utilizan para generar algunos parámetros de autenticación como "Algorithm", "date", "request type" y "signed headers".
región
El argumento es un área geográfica de una colección de recursos. Se extrae del nombre de host especificado en la URL si se omite.
servicio
El argumento es una función proporcionada por una nube. Se extrae del nombre de host especificado en la URL si se omite.

NOTA: Esta llamada establece CURLOPT_HTTPAUTH(3) en CURLAUTH_AWS_SIGV4. Llamar a CURLOPT_HTTPAUTH(3) con CURLAUTH_AWS_SIGV4 es lo mismo que llamar a esta con "aws:amz" en el parámetro.

Ejemplo con "Test:Try", cuando curl usa el algoritmo, genera "TEST-HMAC-SHA256" para "Algorithm", "x-try-date" y "X-Try-Date" para "date", "test4_request" para "request type", "SignedHeaders=content-type;host;x-try-date" para "signed headers".

Si usa solo "test", en lugar de "test:try", test se utiliza para cada cadena generada.

Establecer CURLOPT_HTTPAUTH(3) con el bit CURLAUTH_AWS_SIGV4 activado es lo mismo que establecer esta opción con un parámetro "aws:amz".

La aplicación no tiene que mantener la cadena disponible después de establecer esta opción.

Usar esta opción múltiples veces hace que la última cadena establecida sobrescriba las anteriores. Establézcala a NULL para deshabilitar su uso nuevamente.

PREDETERMINADO

NULL

PROTOCOLOS

Esta funcionalidad afecta solo a http

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL,
                    "https://service.region.example.com/uri");
    curl_easy_setopt(curl, CURLOPT_AWS_SIGV4, "provider1:provider2");
    /* el servicio y la región también se pueden establecer en CURLOPT_AWS_SIGV4 */
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/uri");
    curl_easy_setopt(curl, CURLOPT_AWS_SIGV4,
                     "provider1:provider2:region:service");
    curl_easy_setopt(curl, CURLOPT_USERPWD, "MI_ACCESS_KEY:MI_SECRET_KEY");
    curl_easy_perform(curl);
  }
}

NOTAS

Esta opción anula otros tipos de autenticación que podría haber establecido en CURLOPT_HTTPAUTH(3), lo cual debe destacarse ya que hace que este método de autenticación sea especial. Este método no se puede combinar con otros tipos de autenticación.

Se utiliza una suma de verificación sha256 de la carga útil de la solicitud como entrada para el cálculo de la firma. Para solicitudes POST, esta es una suma de verificación de CURLOPT_POSTFIELDS(3) proporcionado. De lo contrario, es la suma de verificación de un búfer vacío. Para solicitudes como PUT, puede proporcionar su propia suma de verificación en una cabecera HTTP llamada x-provider2-content-sha256.

Para aws:s3, se agrega una cabecera x-amz-content-sha256 a cada solicitud si aún no está presente. Para solicitudes s3 con carga útil desconocida, esta cabecera toma el valor especial "UNSIGNED-PAYLOAD".

DISPONIBILIDAD

Agregado en curl 7.75.0

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un código CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, cualquier valor distinto de cero indica que ocurrió un error, consulte libcurl-errors(3).
