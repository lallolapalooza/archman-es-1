CUE2TOC(1) Manual de Comandos Generales CUE2TOC(1)

NOMBRE

cue2toc - convierte de formato CUE a formato TOC

SINOPSIS

cue2toc [-hnqv] [-o tocfile] [-w wavefile] [cuefile]

DESCRIPCIÓN

Cue2toc convierte cuefile de formato CUE a formato TOC y escribe el resultado en tocfile. Si se omite cuefile o tocfile o si se usa un solo guion "-" cue2toc lee de la entrada estándar y escribe en la salida estándar respectivamente.

Los archivos CUE son archivos de texto que describen la distribución de un CD-ROM y normalmente llevan la extensión ".cue".

Cdrdao es una aplicación de grabación de CD que tiene su propio formato nativo TOC para describir la distribución del disco. Aunque cdrdao tiene soporte directo para leer archivos CUE, actualmente está limitado solo a pistas de datos. Por lo tanto cue2toc's su utilidad principal radica en convertir archivos CUE que contienen pistas de audio.

La salida de datos CD-Text puede deshabilitarse con la opción -n .

Los archivos CUE a menudo vienen con archivos MP3, pero como cdrdao no soporta decodificarlos sobre la marcha, probablemente deben ser decodificados por otros medios antes de grabar el CD (por ejemplo, usando lame). Por esta razón, puede especificar un nombre de archivo con la opción -w para usarlo en todas las pistas de audio en lugar del que está en el archivo CUE. Por supuesto, esto solo es realmente útil si todas las pistas se basan en el mismo archivo. Sin embargo, este parece ser el caso bastante a menudo.

Cue2toc normalmente muestra mensajes de advertencia para comandos y constructos no soportados. La opción -q deshabilita estas advertencias.

OPCIONES

-h
imprime un mensaje de ayuda breve
-n
sin CD-Text; deshabilita la salida de información CD-Text
-o tocfile
escribe el resultado en tocfile en lugar de la salida estándar
-q
modo silencioso; no imprime advertencias
-v
imprime el número de versión
-w wavefile
usa wavefile para todas las pistas de audio

FORMATO CUE

A continuación se describe el formato CUE esperado por cue2toc. Para información sobre el formato TOC, consulte la página del manual cdrdao(1) .

Los archivos CUE consisten en comandos y sus argumentos que deben separarse entre sí por cualquier número de caracteres de espacio en blanco. El espacio, el tabulador horizontal, el salto de línea y el retorno de carro se reconocen como caracteres de espacio en blanco, excepto dentro de cadenas rodeadas por comillas dobles, donde son parte de la cadena. Los comandos no distinguen mayúsculas de minúsculas. Los datos CD-Text pueden tener como máximo 80 caracteres por elemento.

Los valores de código de tiempo se aceptan en las formas "X:X:X", "X:X" y "X" donde cada "X" debe consistir en como máximo dos dígitos y puede rellenarse con ceros a la izquierda. Se interpretan como "M:S:F", "S:F" y "F" respectivamente donde "M" significa "minutos" y debe estar en el rango 0 <= M <= 99, "S" significa "segundos" y debe estar en el rango 0 <= S <= 59, y "F" significa "fotogramas" y debe estar en el rango 0 <= F <= 74.

Los archivos CUE están divididos lógicamente en una sección global y una a 99 secciones de pista. Dentro de estas secciones se permiten los siguientes comandos:

Sección Global

REM anything_to_newline
CATALOG string
CDTEXTFILE string
TITLE string
PERFORMER string
SONGWRITER string
FILE string BINARY|MOTOROLA|AIFF|WAVE|MP3

REM
Opcional. Introduce un comentario. Cualquier cosa desde ahí hasta e incluyendo el siguiente carácter de salto de línea se ignora. Los comentarios pueden aparecer en cualquier lugar del archivo, pero no entre un comando y sus argumentos.
CATALOG
Opcional. El Número de Catálogo de Medios del disco. Debe tener exactamente 13 caracteres.
CDTEXTFILE
Opcional. Especifica un archivo externo que contiene datos CD-Text. Ignorado.
TITLE
Opcional. El título CD-Text del disco.
PERFORMER
Opcional. El intérprete CD-Text del disco.
SONGWRITER
Opcional. El compositor CD-Text del disco.
FILE
Requerido. El nombre y tipo del archivo a usar para todas las pistas siguientes. El string contiene el nombre del archivo seguido de uno de BINARY, MOTOROLA, AIFF, WAVE o MP3. Por lo que respecta a cue2toc , el tipo de archivo se ignora efectivamente. Sin embargo MOTOROLA, AIFF y MP3 causan la impresión de un mensaje de advertencia ya que estos tipos de archivo no pueden usarse directamente con cdrdao.

La primera aparición de un comando TRACK causa la salida de la sección global y la entrada a la sección de pista.

Sección de Pista

TRACK number mode
REM anything_to_newline
FLAGS [DCP] [4CH] [PRE] [SCMS]
ISRC string
TITLE string
PERFORMER string
SONGWRITER string
PREGAP timecode
INDEX number timecode
POSTGAP timecode
FILE string BINARY|MOTOROLA|AIFF|WAVE|MP3

TRACK
Requerido. Inicia una nueva definición de pista. El number se ignora. El mode debe ser uno de AUDIO, MODE1/2048, MODE1/2352, MODE2/2336 o MODE2/2352.
FLAGS
Opcional. Define los indicadores para esta pista. Debe ir seguido de uno o más de los siguientes comandos: DCP (copia digital permitida), 4CH (audio de cuatro canales), PRE (pre-énfasis habilitado) y SCMS (sistema de gestión de copias en serie). SCMS se ignora porque no hay una opción correspondiente en el formato TOC.
ISRC
Opcional. El Código Estándar Internacional de Grabación para esta pista. Debe tener exactamente 12 caracteres de longitud.
TITLE
Opcional. El título CD-Text de esta pista.
PERFORMER
Opcional. El intérprete CD-Text de esta pista.
SONWRITER
Opcional. El compositor CD-Text de esta pista.
PREGAP
Opcional. La longitud del pre-espacio de la pista a rellenar con datos de cero. Mutuamente excluyente con INDEX 0.
POSTGAP
Opcional. La longitud del post-espacio de la pista a rellenar con datos de cero.
INDEX
Opcional. El number debe estar en el rango 0 <= number <= 99. El número de índice 1 especifica el inicio de la pista. El número de índice 0 es el inicio del pre-espacio de la pista rellenado con datos del archivo, es decir, la diferencia entre el índice 0 y el índice 1 es la longitud del pre-espacio. El índice 0 es mutuamente excluyente con PREGAP. Los números de índice mayores que 1 especifican subíndices para esta pista y deben ser secuenciales.
FILE
Opcional en la sección de pista. La sintaxis es la misma que la descrita arriba y si aparece dentro de una especificación de pista, tiene efecto en la siguiente TRACK command.

LIMITACIONES

El comando CDTEXTFILE y el indicador SCMS no tienen equivalente en el formato TOC y se ignoran.

Los archivos CUE que contienen pistas de datos y que especifican un tiempo de inicio mayor que cero no pueden ser convertidos por cue2toc porque el formato TOC no proporciona ninguna forma de especificar un tiempo de inicio para las pistas de datos. Sin embargo, si el archivo CUE no contiene ninguna pista de audio, puedes intentar usar el archivo CUE directamente con cdrdao.

EJEMPLO

Supongamos que tenemos el siguiente archivo CUE "uwe.froehn.cue" que describe un CD de audio con datos CD-Text:

REM Example CUE file with audio tracks
CATALOG 1234567890123
TITLE "Der Berg ruft"
PERFORMER "Uwe Froehn"
FILE "uwe.froehn.mp3" MP3
TRACK 01 AUDIO
  TITLE "Meine Mama ist die Beste"
  PERFORMER "Uwe Froehn"
  SONGWRITER "Hansi Klabuster"
  REM two seconds pregap filled with audio data
  INDEX 00 00:00:00
  INDEX 01 00:02:00
  REM subindexes
  INDEX 02 00:35:17
  INDEX 03 01:12:44
TRACK 02 AUDIO
  TITLE "Hoch oben im Tal"
  SONGWRITER "Gabi Geil"
  REM no pregap
  INDEX 01 02:45:38
TRACK 03 AUDIO
  REM pregap with zero data
  PREGAP 00:4:47
  INDEX 01 07:58:74
  REM postgap with zero data
  POSTGAP 00:35:00

Dado que cdrdao no puede decodificar el archivo MP3 al vuelo, este paso debe llevarse a cabo manualmente, por ejemplo, usando lame:

lame --decode uwe.froehn.mp3 uwe.froehn.wav

Aunque el nombre de archivo aparece solo una vez en el archivo CUE de ejemplo, se escribe para cada pista en el archivo TOC, por lo que tendrías que editar manualmente muchas ocurrencias del nombre de archivo en el archivo TOC. Por esta razón, puedes especificar una cadena con la opción -w para que sea usada por cue2toc como el nombre de archivo para todas las pistas de audio. El comando

cue2toc -w uwe.froehn.wav -o uwe.froehn.toc uwe.froehn.cue

debería producir el archivo uwe.froehn.toc con el siguiente contenido:

CATALOG "1234567890123"
CD_DA
CD_TEXT {
    LANGUAGE_MAP {
        0 : EN
    }
    LANGUAGE 0 {
        TITLE "Der Berg ruft"
        PERFORMER "Uwe Froehn"
    }
}
TRACK AUDIO
    CD_TEXT {
        LANGUAGE 0 {
            TITLE "Meine Mama ist die Beste"
            PERFORMER "Uwe Froehn"
            SONGWRITER "Hansi Klabuster"
        }
    }
    AUDIOFILE "uwe.froehn.wav" 00:00:00 02:45:38
    START 00:02:00
    INDEX 00:35:17
    INDEX 01:12:44
TRACK AUDIO
    CD_TEXT {
        LANGUAGE 0 {
            TITLE "Hoch oben im Tal"
            SONGWRITER "Gabi Geil"
        }
    }
    AUDIOFILE "uwe.froehn.wav" 02:45:38 05:13:36
TRACK AUDIO
    PREGAP 00:04:47
    AUDIOFILE "uwe.froehn.wav" 07:58:74
    SILENCE 00:35:00

VER TAMBIÉN

cdrdao(1), lame(1)

ERRORES

Dado que cue2toc's definition of the CUE format is entirely based on a number of different CUE files the author came across there is a very high probability that it will not work correctly with all the other CUE files you might encounter. If this is the case for you please send the problematic CUE file along with the version number of cue2toc to <dermatsch@gmx.de>.
