CURLOPT_HEADERFUNCTION(3)

Paquete: curl

Licencias: MIT

CURLOPT_HEADERFUNCTION(3) Manual de funciones de la biblioteca CURLOPT_HEADERFUNCTION(3)

NOMBRE

CURLOPT_HEADERFUNCTION - función de devolución de llamada que recibe datos de cabecera

SINOPSIS

#include <curl/curl.h>
size_t header_callback(char *buffer,
                       size_t size,
                       size_t nitems,
                       void *userdata);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HEADERFUNCTION,
                          header_callback);

DESCRIPCIÓN

Pase un puntero a su función de devolución de llamada, que debe coincidir con el prototipo que se muestra arriba.

Esta función de devolución de llamada es invocada por libcurl tan pronto como ha recibido datos de cabecera. La devolución de llamada de cabecera se llama una vez por cada cabecera y solo se pasan líneas de cabecera completas a la devolución de llamada. Analizar cabeceras es fácil de hacer usando esta devolución de llamada. buffer apunta a los datos entregados, y el tamaño de esos datos es nitems; size es siempre 1. La línea de cabecera proporcionada no está terminada en nulo. No modifique el búfer proporcionado.

El puntero llamado userdata es el que configuró con la opción CURLOPT_HEADERDATA(3).

Su función de devolución de llamada debe devolver el número de bytes realmente procesados. Si esa cantidad difiere de la cantidad pasada a su función de devolución de llamada, señala una condición de error a la biblioteca. Esto provoca que la transferencia se aborte y la función de libcurl utilizada devuelva CURLE_WRITE_ERROR.

También puede abortar la transferencia devolviendo CURL_WRITEFUNC_ERROR. (7.87.0)

Una cabecera HTTP completa que se pasa a esta función puede tener hasta CURL_MAX_HTTP_HEADER (100 KB) bytes e incluye el terminador de línea final.

Si esta opción no está configurada, o si está configurada como NULL, pero CURLOPT_HEADERDATA(3) está configurada como cualquier cosa que no sea NULL, se utiliza en su lugar la función utilizada para aceptar los datos de respuesta. Esa es la función especificada con CURLOPT_WRITEFUNCTION(3), o si no está especificada o es NULL, la función de escritura de flujo predeterminada.

Es importante tener en cuenta que la función de devolución de llamada se invoca para las cabeceras de todas las respuestas recibidas después de iniciar una solicitud y no solo para la respuesta final. Esto incluye todas las respuestas que ocurren durante la negociación de autenticación. Si necesita operar solo en las cabeceras de la respuesta final, debe recopilar las cabeceras en la función de devolución de llamada usted mismo y usar las líneas de estado HTTP, por ejemplo, para delimitar los límites de la respuesta.

Para una transferencia HTTP, la línea de estado y la línea en blanco que precede al cuerpo de la respuesta se incluyen como cabeceras y se pasan a esta función.

Cuando un servidor envía una transferencia codificada en fragmentos (chunked), puede contener un tráiler. Ese tráiler es idéntico a una cabecera HTTP y si se recibe dicho tráiler, también se pasa a la aplicación utilizando esta función de devolución de llamada. Hay varias formas de detectarlo como un tráiler y no como una cabecera normal: 1) viene después del cuerpo de la respuesta. 2) viene después de la línea de cabecera final (CR LF) 3) una cabecera Trailer: entre las cabeceras de respuesta normales menciona qué cabecera(s) esperar en el tráiler.

Para protocolos no HTTP como FTP, POP3, IMAP y SMTP, esta función se llama con las respuestas del servidor a los comandos que envía libcurl.

Una forma más conveniente de obtener cabeceras HTTP podría ser usar curl_easy_header(3).

LIMITACIONES

libcurl no despliega "cabeceras plegadas" de HTTP (obsoletas desde RFC 7230). Una cabecera plegada es una cabecera que continúa en una línea posterior y comienza con un espacio en blanco. Dichos pliegues se pasan a la función de devolución de llamada de cabecera como separadas, aunque estrictamente son solo continuaciones de las líneas anteriores.

PREDETERMINADO

Ninguno.

PROTOCOLOS

Esta funcionalidad afecta a ftp, http, imap, pop3 y smtp

EJEMPLO

static size_t header_callback(char *buffer, size_t size,
                              size_t nitems, void *userdata)
{
  /* cabecera recibida son 'nitems' bytes en 'buffer' NO TERMINADO EN NULO */
  /* 'userdata' se establece con CURLOPT_HEADERDATA */
  return nitems;
}
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_HEADERFUNCTION, header_callback);
    curl_easy_perform(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.7.2

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, distinto de cero significa que ocurrió un error, consulte libcurl-errors(3).
