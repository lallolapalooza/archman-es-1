CURLOPT_SSL_VERIFYPEER(3)

Paquete: curl

Licencias: MIT

CURLOPT_SSL_VERIFYPEER(3) Manual de funciones de la biblioteca CURLOPT_SSL_VERIFYPEER(3)

NOMBRE

CURLOPT_SSL_VERIFYPEER - verificar el certificado SSL del par

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_SSL_VERIFYPEER, long verify);

DESCRIPCIÓN

Pase un long como parámetro para habilitar o deshabilitar.

Esta opción determina si curl verifica la autenticidad del certificado del par. Un valor de 1 significa que curl verifica; 0 (cero) significa que no.

Al negociar una conexión TLS o SSL, el servidor envía un certificado que indica su identidad. curl verifica si el certificado es auténtico, es decir, si puede confiar en que el servidor es quien dice ser el certificado. Esta confianza se basa en una cadena de firmas digitales, ancladas en certificados de autoridad certificadora (CA) que usted proporciona. curl utiliza un conjunto predeterminado de certificados de CA (la ruta para esto se determina en tiempo de compilación) y puede especificar certificados alternativos con la opción CURLOPT_CAINFO(3) o la opción CURLOPT_CAPATH(3).

Cuando CURLOPT_SSL_VERIFYPEER(3) está habilitado, y la verificación no logra demostrar que el certificado está firmado por una CA, la conexión falla.

Cuando esta opción está deshabilitada (establecida en cero), los certificados de CA no se cargan y la verificación del certificado del par se omite simplemente.

Autenticar el certificado no es suficiente para estar seguro del servidor. Normalmente, también querrá asegurarse de que el servidor es el servidor con el que pretende hablar. Utilice CURLOPT_SSL_VERIFYHOST(3) para eso. La comprobación de que el nombre del host en el certificado es válido para el nombre de host al que se está conectando se realiza de forma independiente de la opción CURLOPT_SSL_VERIFYPEER(3).

ADVERTENCIA: deshabilitar la verificación del certificado permite que los malos actores realicen ataques man-in-the-middle en la comunicación sin que usted lo sepa. Deshabilitar la verificación hace que la comunicación sea insegura. El simple hecho de tener cifrado en una transferencia no es suficiente, ya que no se puede estar seguro de que se está comunicando con el punto final correcto.

Cuando libcurl utiliza protocolos seguros, confía en las respuestas y permite, por ejemplo, que la información HSTS y Alt-Svc se almacene y se utilice posteriormente. Deshabilitar la verificación del certificado puede hacer que libcurl confíe y utilice dicha información de servidores maliciosos.

POR DEFECTO

1 - habilitado

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos basados en TLS: HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Todos los backends TLS soportan esta opción.

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* Establecer el valor predeterminado: ¡comprobación estricta del certificado por favor! */
    curl_easy_setopt(curl, CURLOPT_SSL_VERIFYPEER, 1L);
    curl_easy_perform(curl);
  }
}

DISPONIBILIDAD

Añadido en curl 7.4.2

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica un error, ver libcurl-errors(3).

VER TAMBIÉN
