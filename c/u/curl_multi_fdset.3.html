curl_multi_fdset(3)

Paquete: curl

Licencias: MIT

curl_multi_fdset(3) Manual de funciones de biblioteca curl_multi_fdset(3)

NOMBRE

curl_multi_fdset - extraer información de descriptores de archivo de un gestor multi

SINOPSIS

#include <curl/curl.h>
CURLMcode curl_multi_fdset(CURLM *multi_handle,
                           fd_set *read_fd_set,
                           fd_set *write_fd_set,
                           fd_set *exc_fd_set,
                           int *max_fd);

DESCRIPCIÓN

Esta función extrae información de descriptores de archivo de un multi_handle dado. libcurl devuelve sus conjuntos fd_set. La aplicación puede usarlos para hacer select(), pero asegúrate de hacerles FD_ZERO antes de llamar a esta función ya que curl_multi_fdset(3) solo agrega sus propios descriptores, no los pone a cero ni elimina otros. La función curl_multi_perform(3) debe llamarse tan pronto como uno de ellos esté listo para leer o escribir.

El argumento read_fd_set debe apuntar a un objeto de tipo fd_set que, al regresar, especifica los descriptores de archivo que se verificarán para estar listos para leer.

El argumento write_fd_set debe apuntar a un objeto de tipo fd_set que, al regresar, especifica los descriptores de archivo que se verificarán para estar listos para escribir.

El argumento exc_fd_set debe apuntar a un objeto de tipo fd_set que, al regresar, especifica los descriptores de archivo que se verificarán para condiciones de error.

Si libcurl no establece ningún descriptor de archivo, max_fd contiene -1 cuando esta función regresa. De lo contrario, contiene el número de descriptor más alto establecido por libcurl. Cuando libcurl devuelve -1 en max_fd, es porque libcurl está haciendo algo que no es posible que tu aplicación monitoree con un socket y, desafortunadamente, no puedes saber exactamente cuándo se completará la acción actual usando select(). Necesitas esperar un tiempo antes de proceder y llamar de todos modos a curl_multi_perform(3). ¿Cuánto tiempo esperar? A menos que curl_multi_timeout(3) te dé un número menor, sugerimos unos 100 milisegundos, pero puedes probarlo en tus propias condiciones para encontrar un valor adecuado.

Al usar select(), deberías usar curl_multi_timeout(3) para determinar cuánto tiempo esperar por actividad. Llama a curl_multi_perform(3) incluso si no se ha visto actividad en los fd_sets después de que expira el tiempo de espera, ya que de lo contrario los reintentos internos y los tiempos de espera pueden no funcionar como crees y quieres.

Si uno de los sockets utilizados por libcurl resulta ser más grande de lo que se puede establecer en un fd_set, lo que en sistemas POSIX significa que el descriptor de archivo es mayor que FD_SETSIZE, entonces libcurl intenta no establecerlo. Establecer un descriptor de archivo demasiado grande en un fd_set implica una escritura fuera de límites que puede provocar bloqueos o algo peor. El efecto de NO almacenarlo podría salvarte del bloqueo, pero hace que tu programa NO espere a sockets que debería esperar...

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos admitidos

EJEMPLO

int main(void)
{
  fd_set fdread;
  fd_set fdwrite;
  fd_set fdexcep;
  int maxfd;
  int rc;
  CURLMcode mc;
  struct timeval timeout = {1, 0};
  CURLM *multi = curl_multi_init();
  do {
    /* llamar a curl_multi_perform() */
    FD_ZERO(&fdread);
    FD_ZERO(&fdwrite);
    FD_ZERO(&fdexcep);
    /* obtener descriptores de archivo de las transferencias */
    mc = curl_multi_fdset(multi, &fdread, &fdwrite, &fdexcep, &maxfd);
    if(mc != CURLM_OK) {
      fprintf(stderr, "curl_multi_fdset() falló, código %d.\n", mc);
      break;
    }
    /* esperar actividad en uno de los sockets */
    rc = select(maxfd + 1, &fdread, &fdwrite, &fdexcep, &timeout);
  } while(!mc);
}

DISPONIBILIDAD

Añadido en curl 7.9.6

VALOR DE RETORNO

Esta función devuelve un CURLMcode que indica éxito o error.

CURLM_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error; ver libcurl-errors(3).
