DESCRIPCIÓ

N

Pase un puntero a su función de retorno de llamada, que debe coincidir con el prototipo mostrado

arriba.

Esta función de retorno de llamada es invocada por libcurl justo antes de la inicialización de una conexión SSL después de haber procesado todas las demás opciones relacionadas con SSL, para dar una última oportunidad a la aplicación de modificar el comportamiento de la inicialización SSL. El parámetro ssl_ctx es un puntero al SSL_CTX de la biblioteca SSL para OpenSSL o wolfSSL, un puntero a mbedtls_ssl_config para mbedTLS. Si se devuelve un error desde la retorno de llamada, no se intenta establecer una conexión y la operación de ejecución devuelve el código de error de la retorno de llamada. Establezca el argumento clientp pasado a esta retorno de llamada con la opción CURLOPT_SSL_CTX_

DATA(3).

Esta función se invoca para todas las conexiones nuevas realizadas a un servidor, durante la negociación SSL. Aunque ssl_ctx apunta a un objeto recién inicializado cada vez, el puntero puede seguir siendo el mismo que en una llamada

anterior.

Para usar esta retorno de llamada, es necesario un conocimiento no trivial de su biblioteca SSL. Por ejemplo, puede usar esta función para invocar retornos de llamada específicas de la biblioteca para añadir código de validación adicional para certificados, e incluso para cambiar la URI real de una solicitud

HTTPS.

Para OpenSSL, se admite la verificación asíncrona de certificados a través de SSL_set_retry_verify. Cuando SSL_set_retry_verify está establecido, la transferencia se pausa. Cuando la verificación deba continuar, llame a curl_easy_pause(3) para reanudar la transferencia. (Añadido en 8.3.0, Pausa añadida en 8.16.

0)

La retorno de llamada CURLOPT_SSL_CTX_FUNCTION(3) permite a la aplicación acceder y modificar detalles SSL en la conexión sin que libcurl sepa nada sobre ello, lo que posteriormente puede llevar a que libcurl reutilice sin saberlo conexiones SSL con diferentes propiedades. Para remediar esto, puede establecer CURLOPT_FORBID_REUSE(3) desde la función de retorno de

llamada.

Si está usando DNS sobre HTTPS (DoH) a través de CURLOPT_DOH_URL(3), esta retorno de llamada también se invoca para esas transferencias y el manejador de curl se establece como un manejador interno. Este comportamiento está sujeto a cambios. Recomendamos establecer CURLOPT_PRIVATE(3) en su manejador de curl para que pueda identificarlo correctamente en la retorno de llamada de contexto. Si tiene una razón para modificar el contexto SSL de DoH, por favor infórmenos en la lista de correo curl-library, porque estamos considerando eliminar esta

capacidad.

libcurl no garantiza la vida útil del objeto pasado una vez que esta función de retorno de llamada ha retornado. Su aplicación no debe asumir que puede seguir usando el contexto SSL o los datos derivados de él una vez que esta función ha

terminado.

Para compilaciones de libcurl que usan backends TLS que admiten el almacenamiento en caché de CA y CURLOPT_CA_CACHE_TIMEOUT(3) no está establecido a cero, se pueden realizar múltip

les llamadas a esta retorno de llamad
a con el mismo almacén de CA en memoria.

EJEMPL

O 
/* Específico de OpenSSL */
#include <openssl/ssl.h>
#include <curl/curl.h>
#include <stdio.h>
static CURLcode sslctx_function(CURL *curl, void *sslctx, void *pointer)
{
  X509_STORE *store;
  X509 *cert = NULL;
  BIO *bio;
  char *mypem = pointer;
  /* obtener un BIO */
  bio = BIO_new_mem_buf(mypem, -1);
  /* usarlo para leer el certificado con formato PEM de la memoria en una
   * estructura X509 que SSL pueda usar
   */
  PEM_read_bio_X509(bio, &cert, 0, NULL);
  if(!cert)
    printf("PEM_read_bio_X509 failed...\n");
  /* obtener un puntero al almacén de certificados X509 (que puede estar vacío) */
  store = SSL_CTX_get_cert_store((SSL_CTX *)sslctx);
  /* añadir nuestro certificado a este almacén */
  if(X509_STORE_add_cert(store, cert) == 0)
    printf("error adding certificate\n");
  /* disminuir los contadores de referencia */
  X509_free(cert);
  BIO_free(bio);
  /* todo listo para continuar */
  return CURLE_OK;
}
int main(void)
{
  CURL *ch;
  CURLcode rv;
  char *mypem = /* Certificado CA en formato PEM, reemplace los XXXs */
    "-----BEGIN CERTIFICATE-----\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "-----END CERTIFICATE-----\n";
  curl_global_init(CURL_GLOBAL_ALL);
  ch = curl_easy_init();
  curl_easy_setopt(ch, CURLOPT_SSLCERTTYPE, "PEM");
  curl_easy_setopt(ch, CURLOPT_SSL_VERIFYPEER, 1L);
  curl_easy_setopt(ch, CURLOPT_URL, "https://www.example.com/");
  curl_easy_setopt(ch, CURLOPT_SSL_CTX_FUNCTION, *sslctx_function);
  curl_easy_setopt(ch, CURLOPT_SSL_CTX_DATA, mypem);
  rv = curl_easy_perform(ch);
  if(!rv)
    printf("*** transfer succeeded ***\n");
  else
    printf("*** transfer failed ***\n");
  curl_easy_cleanup(ch);
  curl_global_cleanup();
  return rv;
}
