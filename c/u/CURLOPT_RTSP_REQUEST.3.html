DESCRIPCIÓ

N

Indica a libcurl qué tipo de solicitud RTSP realizar. Pase uno de los siguientes valores enum de RTSP como un long en el argumento request. Salvo que se indique lo contrario, los comandos requieren que el ID de sesión esté

inicializado.
CURL_RTSPREQ_OPTI
ONS
Se utiliza para recuperar los métodos disponibles del servidor. La aplicación es responsable de analizar y obedecer la respuesta. El ID de sesión no es necesario para este
método.
CURL_RTSPREQ_DESCR
IBE
Se utiliza para obtener la descripción de bajo nivel de un flujo. La aplicación debe indicar qué formatos entiende en la cabecera 'Accept:'. A menos que se establezca manualmente, libcurl añade automáticamente 'Accept: application/sdp'. Se añaden cabeceras de condición de tiempo a las solicitudes Describe si se utiliza la opción CURLOPT_TIMECONDITION(3). (El ID de sesión no es necesario para este
método)
CURL_RTSPREQ_ANNOU
NCE
Cuando es enviada por un cliente, este método cambia la descripción de la sesión. Por ejemplo, si un cliente está usando el servidor para grabar una reunión, el cliente puede usar Announce para informar al servidor de toda la meta-información sobre la sesión. ANNOUNCE actúa como un PUT o POST de HTTP, igual que CURL_RTSPREQ_SET_PARAME
TER
CURL_RTSPREQ_SE
TUP
Setup se utiliza para inicializar la capa de transporte de la sesión. La aplicación debe establecer las opciones de Transporte deseadas para una sesión utilizando la opción CURLOPT_RTSP_TRANSPORT(3) antes de llamar a setup. Si no hay un ID de sesión establecido actualmente con CURLOPT_RTSP_SESSION_ID(3), libcurl extrae y utiliza el ID de sesión en la respuesta a esta solicitud. El ID de sesión no es necesario para este
método.
CURL_RTSPREQ_P
LAY
Envía un comando Play al servidor. Utilice la opción CURLOPT_RANGE(3) para modificar el tiempo de reproducción (por ejemplo, npt=10-
15).
CURL_RTSPREQ_PA
USE
Envía un comando Pause al servidor. Utilice la opción CURLOPT_RANGE(3) con un único valor para indicar cuándo debe detenerse el flujo. (por ejemplo, npt=2
5)
CURL_RTSPREQ_TEARD
OWN
Este comando termina una sesión RTSP. Simplemente cerrar una conexión no termina la sesión RTSP, ya que es válido controlar una sesión RTSP sobre diferentes
conexiones.
CURL_RTSPREQ_GET_PARAME
TER
Recupera un parámetro del servidor. De forma predeterminada, libcurl añade una cabecera Content-Type: text/parameters en todas las solicitudes no vacías a menos que se establezca una personalizada. GET_PARAMETER actúa igual que un PUT o POST de HTTP (ver CURL_RTSPREQ_SET_PARAMETER). Las aplicaciones que deseen enviar un mensaje de latido (por ejemplo, en presencia de un tiempo de espera especificado por el servidor) deben enviar una solicitud GET_PARAMETER
vacía.
CURL_RTSPREQ_SET_PARAME
TER
Establece un parámetro en el servidor. De forma predeterminada, libcurl utiliza una cabecera *Content-Type: text/parameters* a menos que se establezca una personalizada. La interacción con SET_PARAMETER es muy similar a un PUT o POST de HTTP. Una aplicación puede usar CURLOPT_UPLOAD(3) con CURLOPT_READDATA(3) como un PUT de HTTP, o puede usar CURLOPT_POSTFIELDS(3) como un POST de HTTP. No se permiten transferencias chunked, por lo que la aplicación debe establecer CURLOPT_INFILESIZE(3) en el primer caso y CURLOPT_POSTFIELDSIZE(3) en el segundo. Además, no se usa POSTs multi-part en
RTSP.
CURL_RTSPREQ_REC
ORD
Se utiliza para decirle al servidor que grabe una sesión. Utilice la opción CURLOPT_RANGE(3) para modificar el tiempo de
grabación.
CURL_RTSPREQ_RECE
IVE
Esta es una solicitud especial porque no envía ningún dato al servidor
. La aplicación puede llamar a esta función para recibir datos R
TP intercalados. Retorna después de procesar un búfer de lectura
de datos para dar a la aplicación la oportunidad de ejecutarse.

EJEMPL

O 
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "rtsp://example.com/");
    /* ask for options */
    curl_easy_setopt(curl, CURLOPT_RTSP_REQUEST, CURL_RTSPREQ_OPTIONS);
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}
