DESCRIPCIÓN

Estas funciones manipulan las etiquetas de teclas de función suaves que algunos terminales de hardware admiten. Para aquellos terminales que no tienen etiquetas suaves, curses se hace cargo de la línea inferior de stdscr, reduciendo su tamaño vertical y el valor de LINES en uno. Por defecto, curses usa ocho etiquetas de hasta ocho caracteres cada una.

ncurses además admite un modo que comprende doce etiquetas de hasta cinco caracteres cada una, siguiendo una convención asociada con el teclado IBM PC/AT. ncurses simula este modo tomando hasta dos líneas en la parte inferior de la pantalla; no intenta usar ningún soporte de hardware para este modo.

Inicialización

slk_init debe ser llamada antes de initscr o newterm. Si initscr finalmente usa una línea de stdscr para emular las etiquetas suaves, entonces fmt determina cómo se organizan las etiquetas en la pantalla.

0
indica una disposición 3-2-3 de las etiquetas.
1
indica una disposición 4-4
2
indica el modo 4-4-4 similar a PC.
3
es de nuevo el modo 4-4-4 similar a PC, pero además se genera una línea de índice, ayudando al usuario a asociar cada etiqueta con su tecla de función numerada. LINES y el tamaño vertical de stdscr se reducen aún más.

Etiquetas

Rellene las etiquetas con cadenas normales (slk_set) o cadenas de caracteres anchos (slk_wset). Cada función toma tres parámetros.

labnum
es el número de etiqueta, de 1 a 8 (12 si fmt en slk_init es 2 o 3);
label
es la cadena a poner en la etiqueta, de hasta ocho (cinco si fmt en slk_init es 2 o 3) caracteres de longitud. Una cadena vacía o un puntero nulo configura una etiqueta en blanco.
align
es 0, 1, o 2, alineando label a la izquierda, al centro, o a la derecha, respectivamente, dentro de las celdas de 8 (5) caracteres que la alojan.

slk_label obtiene la cadena asignada al número de etiqueta labnum, con cualquier espacio en blanco inicial y final eliminado.

Actualizaciones de pantalla

slk_refresh y slk_noutrefresh afectan a las líneas de etiquetas de teclas suaves como wrefresh y wnoutrefresh lo hacen con la ventana de curses .

La slk_clear rutina borra las etiquetas suaves de la pantalla.

La slk_restore rutina restaura las etiquetas suaves en la pantalla después de que se haya realizado un slk_clear .

La slk_touch rutina fuerza a que todas las etiquetas suaves se emitan la próxima vez que se realice un slk_noutrefresh .

Atributos de vídeo

Las slk_attron, slk_attrset, slk_attroff, y slk_attr rutinas corresponden a attron, attrset, attroff, y attr_get, respectivamente. Tienen efecto solo si las etiquetas suaves están simuladas en la línea inferior de la pantalla. El resaltado por defecto para las etiquetas de teclas suaves es A_STANDOUT (como en curses de System V curses, que no documenta este hecho).

Colores

La slk_color rutina corresponde a color_set. Tiene efecto solo si las etiquetas suaves están simuladas en la línea inferior de la pantalla.

Debido a que slk_color acepta solo valores short (entero con signo de 16 bits), esta implementación proporciona extended_slk_color, que acepta un valor int de al menos 32 bits.

VALOR DE RETORNO

Las rutinas que devuelven un entero devuelven ERR en caso de fallo y OK (SVr4 especifica solo "un valor entero distinto de ERR") al completarse con éxito.

X/Open Curses no define condiciones de error.

En esta implementación

slk_attr
devuelve el atributo utilizado para las teclas suaves.
slk_attroff, slk_attron, slk_clear, slk_noutrefresh, slk_refresh, slk_touch
devuelven un error si el terminal o las teclas suaves no fueron inicializados.
slk_attrset
devuelve un error si el terminal o las teclas suaves no fueron inicializados.
slk_attr_set
devuelve un error si el terminal o las teclas suaves no fueron inicializados, o el par de colores está fuera del rango 0..COLOR_PAIRS-1.
slk_color
devuelve un error si el terminal o las teclas suaves no fueron inicializados, o el par de colores está fuera del rango 0..COLOR_PAIRS-1.
slk_init
devuelve un error si el parámetro de formato está fuera del rango 0..3.
slk_label
devuelve NULL en caso de error.
slk_set
devuelve un error si el terminal o las teclas suaves no fueron inicializados, o el labnum parámetro está fuera del rango de conteos de etiquetas, o si el parámetro de formato está fuera del rango 0..2, o si no se puede asignar memoria para las etiquetas.

NOTAS

La mayoría de las aplicaciones usarían slk_noutrefresh porque un wrefresh probablemente seguirá pronto.

EXTENSIONES

X/Open Curses documenta el opts argumento como reservado para uso futuro, diciendo que debe ser nulo. Esta implementación usa ese parámetro en ABI 6 para las funciones que tienen un parámetro de par de colores para admitir pares de colores extendidos.

Para las funciones que modifican el color, por ejemplo, slk_attr_set, si opts está establecido, se trata como un puntero a int, y se usa para establecer el par de colores en lugar del short parámetro pair.

PORTABILIDAD

X/Open Curses, Edición 4 describe estas funciones

DESCRIPCIÓN

El conjunto de funciones de curses(3X) para teclas blandas (SLK) es la implementación de ncurses para las teclas blandas, con algunas diferencias con respecto a las curses de SVr4:

•
X/Open añadió funciones como las funciones de manipulación de atributos de SVr4 slk_attron, slk_attroff y slk_attrset, pero que usan parámetros attr_t (en lugar de chtype), junto con un parámetro opts reservado.
Dos de estas nuevas funciones (a diferencia de las funciones SVr4) no tienen provisión para color: slk_attr_on y slk_attr_off.
La tercera función (slk_attr_set) tiene un parámetro de par de colores.
  • Añadió calificadores const a los parámetros (innecesariamente), y
  • Añadió slk_color.

Aunque slk_start se declara en el archivo de cabecera de curses, no fue documentado por SVr4, aparte de su presencia en una lista de símbolos de libtermlib.so.1. Leyendo el código fuente (es decir, Illumos):

•
slk_start tiene dos parámetros:
  • ng (número de grupos) y
  • gp (puntero a grupo).
  • Los grupos de teclas blandas son un array de ng enteros.
  • En SVr4, slk_init llama a slk_start pasando un nulo para gp. Para este caso, slk_start usa el número de grupos ng (3 para la disposición 3-2-3, 2 para la disposición 4-4) que slk_init proporcionó.
Si ng no es ni 2 ni 3, slk_start comprueba la capacidad de terminfo fln (label_format), interpretándola como una lista de números separados por comas, por ejemplo, "3,2,3" para la disposición 3-2-3.
Finalmente, si no hay capacidad fln, slk_start devuelve ERR.
•
Si a slk_start se le da un gp no nulo, copia los ng elementos del grupo de teclas blandas, hasta un máximo de 16.
Si hay más de 16 elementos, slk_start devuelve un error.
•
Los códigos de formato 2 y 3 para slk_init fueron añadidos por ncurses en 1996. PDCurses 2.4 añadió esta característica en 2001.

La función slk_attr fue añadida por ncurses en 1996.

X/Open Curses no especifica un límite para el número de colores y pares de colores que un terminal puede soportar. Sin embargo, en su uso de short para los parámetros, traslada el detalle de implementación de SVr4 para la base de datos de terminfo compilada, que utiliza números de 16 bits con signo. Esta implementación proporciona versiones extendidas de esas funciones que utilizan parámetros int, permitiendo a las aplicaciones utilizar números de color y par más grandes.
