DESCRIPCIÓ

N

El manejador de url sobre el que trabajar, pasado como primer argumento, debe ser un manejador creado previamente por curl_url(3) o curl_url_du

p(3).

Esta función establece o actualiza componentes individuales de la URL, o partes, contenidos en el objeto URL que identifica el

manejador.

El argumento part debe identificar la parte particular de la URL (ver lista abajo) a establecer o cambiar, con content apuntando a una cadena terminada en null con el nuevo contenido para esa parte de la URL. El contenido debe estar en la forma y codificación que se usaría en una URL: URL

codificada.

Cuando se establece una parte en el objeto URL que ya había sido establecida previamente, reemplaza los datos que fueron almacenados previamente para esa parte con el nuevo content

.

El llamador no tiene que mantener content después de una llamada exitosa ya que esta función copia el

contenido.

Establecer una parte a un puntero NULL elimina el contenido de esa parte del manejador C

URLU.

Esta función tiene un límite de longitud máxima de 8 MB para todas las cadenas de entrada proporcionadas. En el mundo real, campos excesivamente largos en URLs causan problemas incluso si esta función los

acepta.

Al establecer o actualizar el contenido de partes individuales de la URL, curl_url_set(3) podría aceptar datos que de otro modo no serían posibles de establecer en la cadena cuando se puebla como resultado de un análisis completo de URL. Tenga cuidado. Si se hace así, extraer una URL completa más adelante de tales componentes podría producir una URL

inválida.

El argumento flags es una máscara de bits

con característica
s independientes.

PARTE

S
CURLUPART_U
RL
Permite reemplazar la URL completa del manejador. Si el manejador ya está poblado con una URL, la nueva URL puede ser relativa a la anterior.

Al establecer exitosamente una nueva URL, relativa o absoluta, el contenido del manejador se reemplaza con los componentes de la URL recién

establecida.

Pase un puntero a una cadena terminada en null al parámetro url. La cadena debe apuntar a una URL "RFC 3986+" correctamente formateada o ser un puntero NULL. El analizador de URL solo entiende y analiza el subconjunto de URLs que son "jerárquicas" y por lo tanto contienen un separador :// - no las que son normalmente especificadas con solo un separador de dos

puntos.

Por defecto, esta API solo analiza URLs usando esquemas para protocolos que son soportados de forma incorporada. Para que libcurl analice URLs genéricamente incluso para esquemas que no conoce, el bit de flags CURLU_NON_SUPPORT_SCHEME debe ser establecido. De lo contrario, esta función devuelve CURLUE_UNSUPPORTED_SCHEME para esquemas de URL que no

reconoce.

A menos que CURLU_NO_AUTHORITY esté establecido, un nombre de host en blanco no está permitido en

la URL.

Cuando se establece (analiza) una URL completa, el componente del nombre de host se almacena decodificado

de URL.

Se considera bien establecer una URL en blanco ("") como una redirección, pero no como una URL normal. Por lo tanto, establecer una URL "" funciona bien si el manejador ya contiene una URL, de lo contrario, desencadena un

error.

longitud.

CURLUPART_PASSW

El campo de opciones es un campo opcional que puede seguir a la contraseña en la parte de información de usuario. Solo se reconoce/se usa al analizar URLs para los siguientes esquemas: pop3, smtp e imap. Sin embargo, esta función permite a los usuarios establecer este campo de forma
independiente.
CURLUPART_HO
ST
El nombre de host. Si es un Nombre de Dominio Internacional (IDN), la cadena debe entonces estar codificada como lo indica su configuración regional o UTF-8 (cuando se usa WinIDN). Si es una dirección IPv6 numérica entre corchetes, puede contener un id de zona (o puede usar CURLUPART_ZONEID).

Tenga en cuenta que si establece una dirección IPv6, se arruina y causa un error si también establece el flag

CURLU_URLENCODE.

CURLU_APPENDQU

Puede usarse al establecer el componente CURLUPART_QUERY. La nueva parte proporcionada se añade entonces al final de la consulta existente - y si la parte anterior no terminaba con un ampersand (&), un ampersand se inserta antes de la nueva parte añadida.

CURLU_NON_SUPPORT_SCH
EME
Si está establecido, permite a curl_url_set(3) establecer un esquema no soportado. Entonces, por supuesto, no puede saber si el esquema proporcionado es uno válido o
no.
CURLU_URLENC
ODE
Cuando está establecido, curl_url_set(3) codifica la parte de URL al entrar, excepto para scheme, port y URL.

Al establecer el componente de ruta con la codificación de URL habilitada, los siguientes caracteres se dejan como están si están

presentes: 
! $ & ' ( ) { } [ ] * + , ;
= : @

La parte de consulta se convierte de espacio a signo más antes de que se aplique la conversión de

URL.

Esta codificación de URL no tiene en cuenta el juego de caracteres y convierte la entrada de manera byte

a
byte.
CURLU_DEFAULT_SCH
EME
Si está establecido, permite establecer la URL sin un esquema y luego establece ese al esquema predeterminado: HTTPS. Anula la opción CURLU_GUESS_SCHEME si ambos están
establecidos.
CURLU_GUESS_SCH
EME
Si está establecido, permite establecer la URL sin un esquema y en su lugar "adivina" qué esquema estaba destinado basándose en el nombre de host. Si el nombre de subdominio más externo coincide con DICT, FTP, IMAP, LDAP, POP3 o SMTP, se usa ese esquema, de lo contrario elige HTTP. Entra en conflicto con la opción CURLU_DEFAULT_SCHEME que tiene prioridad si ambos están establecidos.

Si no se permite adivinar y no hay un esquema predeterminado establecido, al intentar analizar una URL sin un esquema se devuelve un

error.

Si el esquema termina establecido como resultado de la suposición, es decir, no está realmente presente en la URL analizada, se puede averiguar más tarde utilizando la bandera CURLU_NO_GUESS_SCHEME al obtener posteriormente la URL o el esquema con curl_url

_get
(3).
CURLU_AUTHORI
TY
Si se establece, omite las comprobaciones de autoridad. La RFC permite que esquemas individuales omitan la parte del host (normalmente la única parte obligatoria de la autoridad), pero libcurl no puede saber si esto está permitido para esquemas personalizados. Especificar la bandera permite secciones de autoridad vacías, de forma similar a como se maneja el esquema
file.
CURLU_PATH_AS
_IS
Cuando se establece para CURLUPART_URL, esto omite la normalización de la ruta. Es decir, el procedimiento donde libcurl de otro modo elimina secuencias de punto-diagonal y punto-punto, etc. La misma opción utilizada para las transferencias se llama CURLOPT_PATH_AS
_IS(3).
CURLU_ALLOW_SP
ACE
Si se establece, el analizador de URL permite espacios (ASCII 32) donde sea posible. La sintaxis de la URL normalmente no permite espacios en ningún lugar, pero deberían codificarse como %20 o '+'. Cuando se permiten espacios, aún no se permiten en el esquema. Cuando se usa y permite un espacio en una URL, se almacena tal cual a menos que CURLU_URLENCODE también esté establecida, lo que hace que libcurl codifique la URL el espacio antes de almacenarlo. Esto afecta a cómo se construye la URL cuando curl_url_get(3) se utiliza posteriormente para extraer la URL completa o partes individuales. (Añadido en 7.78.
0)
CURLU_DISALLOW_U
SER
Si se establece, el analizador de URL no acepta credenciales incrustadas para la CURLUPART_URL, y en su lugar devuelve CURLUE_USER_NOT_AL
LOWED
para ta
les URLs.
