curs_pad(3x)

Paquete: ncurses

Licencias: MIT-open-group

curs_pad(3X) Llamadas a biblioteca curs_pad(3X)

NOMBRE

newpad, subpad, prefresh, pnoutrefresh, pechochar, pecho_wchar - crear y mostrar *curses* pads

SINOPSIS

#include <curses.h>
WINDOW *newpad(int nlines, int ncols);
WINDOW *subpad(WINDOW *parent, int nlines, int ncols,
      int begin_y, int begin_x);
int prefresh(WINDOW *pad, int pminrow, int pmincol,
      int sminrow, int smincol, int smaxrow, int smaxcol);
int pnoutrefresh(WINDOW *pad, int pminrow, int pmincol,
      int sminrow, int smincol, int smaxrow, int smaxcol);
int pechochar(WINDOW *pad, chtype ch);
int pecho_wchar(WINDOW *pad, const cchar_t *wch);

DESCRIPCIÓN

Un *pad* de *curses* es como una ventana, excepto que no está restringido por el tamaño de la pantalla y no está necesariamente asociado con una parte particular de la pantalla. Los pads se pueden usar cuando se necesita una ventana grande, solo una parte de la cual debe ser visible en la pantalla. Los pads no se actualizan automáticamente mediante operaciones de desplazamiento o eco de entrada.

Los pads no se pueden actualizar con wrefresh(3X); use prefresh o pnoutrefresh en su lugar.

newpad

newpad crea y devuelve un puntero a una nueva estructura de datos de pad con el número dado de líneas, nlines, y columnas, ncols.

subpad

subpad crea y devuelve un puntero a una subventana dentro de un pad con el número dado de líneas, nlines, y columnas, ncols. A diferencia de subwin(3X), que usa coordenadas de pantalla, el nuevo pad se coloca en la posición (begin_y, begin_x) relativa a su padre. Por lo tanto, los cambios realizados en un pad pueden afectar a ambos. Al operar en un subpad, a menudo es necesario llamar touchwin(3X) o touchline(3X) en parent antes de llamar a prefresh.

prefresh, pnoutrefresh

prefresh y pnoutrefresh son análogos a wrefresh(3X) y wnoutrefresh(3X) excepto que operan en pads en lugar de ventanas. Requieren parámetros adicionales para indicar qué porciones del pad y de la pantalla están involucradas.

  • pminrow y pmincol especifican la esquina superior izquierda de una vista rectangular del pad.
  • sminrow, smincol, smaxrow y smaxcol especifican los vértices del rectángulo que se mostrará en la pantalla.

La esquina inferior derecha del rectángulo a mostrar en el pad se calcula a partir de las coordenadas de la pantalla, ya que los rectángulos deben ser del mismo tamaño. Ambos rectángulos deben estar completamente contenidos dentro de sus respectivas estructuras. *curses* trata los valores negativos de cualquiera de estos parámetros como cero.

pechochar

pechochar es funcionalmente equivalente a llamar a waddch(3X) seguido de prefresh. Sugiere al optimizador de *curses* que solo se está generando un solo carácter; se puede obtener un beneficio de rendimiento considerable. La ubicación del carácter ch escrito en el pad se utiliza para popular los argumentos de prefresh.

pecho_wchar

pecho_wchar es funcionalmente equivalente a llamar a wadd_wch(3X) seguido de prefresh. Sugiere al optimizador de *curses* que solo se está generando un solo carácter ancho; se puede obtener un beneficio de rendimiento considerable. La ubicación del carácter wch escrito en el pad se utiliza para popular los argumentos de prefresh.

VALOR DE RETORNO

Las funciones que devuelven un entero devuelven ERR en caso de fallo y OK (SVr4 solo especifica "un valor entero distinto de ERR") en caso de finalización exitosa.

Las funciones que devuelven punteros devuelven NULL en caso de error, y establecen errno a ENOMEM.

X/Open Curses no especifica condiciones de error. En esta implementación

prefresh y pnoutrefresh
devuelven un error si el puntero de ventana es nulo, o si la ventana no es realmente un pad o si el área a actualizar se extiende fuera de la pantalla o si las coordenadas mínimas son mayores que las máximas.
pechochar
devuelve un error si la ventana no es realmente un pad, y la llamada asociada a wechochar devuelve un error.
pecho_wchar
devuelve un error si la ventana no es realmente un pad, y la llamada asociada a wecho_wchar devuelve un error.

NOTAS

pechochar puede ser una macro.

PORTABILIDAD

El *curses* de BSD no tiene la característica de *pad*.

El *curses* de SVr2 (1986) proporcionó las funciones newpad y relacionadas, documentándolas en una sola línea cada una. SVr3 (1987) proporcionó una documentación más extensa.

La documentación no explica el término *pad*. Sin embargo, el sistema operativo del entorno de trabajo gráfico de Apollo *Aegis* admitía una característica gráfica de *pad*:

  • Estos pads gráficos podían ser mucho más grandes que la pantalla del ordenador.
  • La salida de solo lectura de un comando se podía desplazar hacia atrás para inspeccionar y seleccionar texto del pad.

Los dos usos pueden estar relacionados.

X/Open Curses, Issue 4 describe estas funciones, sin cambios significativos respecto a la documentación de SVr3. No describe ninguna condición de error. El comportamiento de subpad si la ventana padre no es un pad no está documentado, y no es verificado por las implementaciones de Unix del proveedor:

•
El *curses* de SVr4 establece una bandera en la estructura WINDOW en newpad que indica si la ventana es un *pad*.
Sin embargo, utiliza esta información solo en waddch (para decidir si debe llamar a wrefresh) y wscrl (para evitar desplazar un pad), y no verifica en wrefresh para asegurar que el pad se actualice correctamente.
•
El *xcurses* de Solaris verifica si una ventana es un pad en wnoutrefresh, devolviendo ERR en ese caso.
Sin embargo, solo establece la bandera para subventanas si la ventana padre es un pad. Su función newpad no establece esta información. En consecuencia, la verificación nunca fallará.
No realiza una verificación comparable en pnoutrefresh, aunque curiosamente, un comentario en el código fuente afirma que la falta de verificación fue una extensión de MKS.
•
El *curses* de NetBSD 7 establece una bandera en la estructura WINDOW para newpad y subpad, usando esto para ayudar en la distinción entre wnoutrefresh y pnoutrefresh.
No verifica el caso en que se crea una subventana en un pad usando subwin o derwin.
La función dupwin devuelve una ventana regular al duplicar un pad. Del mismo modo, getwin siempre devuelve una ventana, incluso si los datos guardados eran de un pad.

Esta implementación

  • establece una bandera en la estructura WINDOW para newpad y subpad,
  • permite que una llamada a subwin o derwin tenga éxito teniendo un padre pad forzando que la subventana sea un pad,
  • verifica en wnoutrefresh
