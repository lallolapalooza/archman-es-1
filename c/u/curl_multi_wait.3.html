curl_multi_wait(3)

Paquete: curl

Licencias: MIT

curl_multi_wait(3) Manual de funciones de la biblioteca curl_multi_wait(3)

NOMBRE

curl_multi_wait - esperar por eventos en todos los identificadores fáciles de un identificador múltiple

SINOPSIS

#include <curl/curl.h>
CURLMcode curl_multi_wait(CURLM *multi_handle,
                          struct curl_waitfd extra_fds[],
                          unsigned int extra_nfds,
                          int timeout_ms,
                          int *numfds);

DESCRIPCIÓN

curl_multi_wait(3) espera por eventos en todos los descriptores de archivo utilizados por los identificadores fáciles de curl contenidos en el conjunto de identificadores múltiples dado. Se bloquea hasta que se detecte actividad en al menos uno de los identificadores o haya transcurrido timeout_ms. Alternativamente, si el identificador múltiple tiene un tiempo de espera interno pendiente que expira antes que timeout_ms, se utiliza ese tiempo más corto para asegurar una precisión razonable del tiempo de espera.

La aplicación que llama puede pasar estructuras curl_waitfd adicionales, similares a la estructura pollfd de poll(2), para esperar en la misma llamada.

Al finalizar, si numfds no es NULL, se poblará con el número total de descriptores de archivo en los que ocurrieron eventos interesantes. Este número puede incluir tanto descriptores internos de libcurl como descriptores proporcionados en extra_fds.

Si no se proporcionan descriptores de archivo adicionales y libcurl no tiene ningún descriptor de archivo que ofrecer para esperar, esta función devuelve inmediatamente. (Considere usar curl_multi_poll(3) para evitar este comportamiento.)

Se recomienda usar esta función en lugar de select(3) al usar la interfaz múltiple para permitir que las aplicaciones esquiven más fácilmente el problema común de los 1024 descriptores de archivo máximos.

curl_waitfd

struct curl_waitfd {
  curl_socket_t fd;
  short events;
  short revents;
};
CURL_WAIT_POLLIN
Bandera de bits para curl_waitfd.events que indica que el socket debe esperar eventos de lectura, como datos nuevos recibidos.
CURL_WAIT_POLLPRI
Bandera de bits para curl_waitfd.events que indica que el socket debe esperar eventos de lectura de alta prioridad, como datos fuera de banda.
CURL_WAIT_POLLOUT
Bandera de bits para curl_waitfd.events que indica que el socket debe esperar eventos de escritura, como que el socket esté listo para escribir sin bloquearse.

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles

EJEMPLO

int main(void)
{
  CURL *easy;
  CURLM *multi = curl_multi_init();
  int still_running;
  easy = curl_easy_init();
  /* añadir el identificador fácil individual */
  curl_multi_add_handle(multi, easy);
  do {
    CURLMcode mc;
    int numfds;
    mc = curl_multi_perform(multi, &still_running);
    if(mc == CURLM_OK) {
      /* esperar actividad, tiempo de espera o "nada" */
      mc = curl_multi_wait(multi, NULL, 0, 1000, &numfds);
    }
    if(mc != CURLM_OK) {
      fprintf(stderr, "curl_multi falló, código %d.\n", mc);
      break;
    }
  } while(still_running);
  curl_multi_remove_handle(multi, easy);
}

DISPONIBILIDAD

Añadido en curl 7.28.0

VALOR DE RETORNO

Esta función devuelve un CURLMcode que indica éxito o error.

CURLM_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, consulte libcurl-errors(3).
