CURLOPT_INTERLEAVEFUNCTION(3)

Paquete: curl

Licencias: MIT

CURLOPT_INTERLEAVEFUNCTION(3) Manual de funciones de la biblioteca CURLOPT_INTERLEAVEFUNCTION(3)

NOMBRE

CURLOPT_INTERLEAVEFUNCTION - función de retorno de llamada para datos entrelazados RTSP

SINOPSIS

#include <curl/curl.h>
size_t interleave_callback(void *ptr, size_t size, size_t nmemb,
                           void *userdata);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_INTERLEAVEFUNCTION,
                          interleave_callback);

DESCRIPCIÓN

Pase un puntero a su función de retorno de llamada, que debe coincidir con el prototipo que se muestra arriba.

libcurl llama a esta función de retorno de llamada tan pronto como ha recibido datos RTP entrelazados. Esta función se llama para cada bloque de $ y, por lo tanto, contiene una unidad de protocolo de capa superior (por ejemplo, un paquete RTP). curl escribe la cabecera entrelazada, así como los datos incluidos para cada llamada. El primer byte es siempre un signo de dólar ASCII. Al signo de dólar le sigue un identificador de canal de un byte y luego una longitud entera de 2 bytes en orden de bytes de red. Consulte la RFC 2326, sección 10.12, para obtener más información sobre el comportamiento del entrelazado RTP. Si no se establece o se establece en NULL, curl utiliza la función de escritura predeterminada.

El RTP entrelazado presenta algunos desafíos para la aplicación cliente. Dado que los datos del flujo comparten la conexión de control RTSP, es fundamental dar servicio al RTP de manera oportuna. Si los datos RTP no se manejan rápidamente, el procesamiento de respuestas posteriores puede retrasarse de manera irrazonable y la conexión puede cerrarse. La aplicación puede usar CURL_RTSPREQ_RECEIVE para dar servicio a los datos RTP cuando no se desean solicitudes. Si la aplicación realiza una solicitud (por ejemplo, CURL_RTSPREQ_PAUSE), el manejador de respuestas procesa los datos RTP pendientes antes de marcar la solicitud como finalizada.

El CURLOPT_INTERLEAVEDATA(3) se pasa en el argumento userdata en la función de retorno de llamada.

Su función de retorno de llamada debe devolver el número de bytes que se han gestionado realmente. Si esa cantidad difiere de la cantidad pasada a su función de retorno de llamada, señala una condición de error a la biblioteca. Esto provoca la interrupción de la transferencia y la función de libcurl utilizada devuelve CURLE_WRITE_ERROR.

También puede abortar la transferencia devolviendo CURL_WRITEFUNC_ERROR. (7.87.0)

PREDETERMINADO

NULL, los datos entrelazados se pasan entonces a la función de escritura normal: CURLOPT_WRITEFUNCTION(3).

PROTOCOLOS

Esta funcionalidad solo afecta a rtsp

EJEMPLO

struct local {
  void *custom;
};
static size_t rtp_write(void *ptr, size_t size, size_t nmemb, void *userp)
{
  struct local *l = userp;
  printf("nuestro ptr: %p\n", l->custom);
  /* gestionar el paquete en 'ptr', luego devolver... */
  return size * nmemb;
}
int main(void)
{
  struct local rtp_data;
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_INTERLEAVEFUNCTION, rtp_write);
    curl_easy_setopt(curl, CURLOPT_INTERLEAVEDATA, &rtp_data);
  }
}

DISPONIBILIDAD

Añadido en curl 7.20.0

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero significa que ocurrió un error, consulte libcurl-errors(3).
