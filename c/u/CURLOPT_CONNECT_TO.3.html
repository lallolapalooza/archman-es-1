CURLOPT_CONNECT_TO(3)

Paquete: curl

Licencias: MIT

CURLOPT_CONNECT_TO(3) Manual de funciones de la biblioteca CURLOPT_CONNECT_TO(3)

NOMBRE

CURLOPT_CONNECT_TO - conectarse a otro host y puerto en su lugar

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_CONNECT_TO,
                          struct curl_slist *connect_to);

DESCRIPCIÓN

Pasa un puntero a una lista enlazada de cadenas con información de "conectar a" para usar al establecer conexiones de red con este manejador. La lista enlazada debe ser una lista completamente válida de estructuras struct curl_slist correctamente rellenadas. Use curl_slist_append(3) para crear la lista y curl_slist_free_all(3) para limpiar una lista completa.

Cada cadena individual debe escribirse utilizando el formato HOST:PUERTO:HOST-DE-CONEXIÓN:PUERTO-DE-CONEXIÓN donde HOST es el host de la solicitud, PUERTO es el puerto de la solicitud, HOST-DE-CONEXIÓN es el nombre de host al que conectarse y PUERTO-DE-CONEXIÓN es el puerto al que conectarse.

Se utiliza la primera cadena que coincide con el host y el puerto de la solicitud.

Se admiten direcciones IP numéricas con puntos para HOST y HOST-DE-CONEXIÓN. Una dirección IPv6 numérica debe escribirse entre corchetes.

Cualquiera de los cuatro valores puede estar vacío. Cuando HOST o PUERTO están vacíos, el host o el puerto siempre coinciden (el host o el puerto de la solicitud se ignoran). Cuando HOST-DE-CONEXIÓN o PUERTO-DE-CONEXIÓN están vacíos, la función de "conectar a" se desactiva para el host o el puerto, y se utilizan el host o el puerto de la solicitud para establecer la conexión de red.

Esta opción es adecuada para dirigir la solicitud a un servidor específico, por ejemplo, a un nodo de clúster específico en un clúster de servidores.

El host y el puerto de "conectar a" solo se utilizan para establecer la conexión de red. NO afectan al host y al puerto que se utilizan para TLS/SSL (por ejemplo, SNI, verificación de certificados) o para los protocolos de aplicación.

En contraste con CURLOPT_RESOLVE(3), la opción CURLOPT_CONNECT_TO(3) no pre-rellena la caché DNS y, por lo tanto, no afecta a las transferencias futuras de otros manejadores fáciles que se hayan añadido al mismo manejador múltiple.

El host y el puerto de "conectar a" se ignoran si son iguales al host y al puerto de la URL de la solicitud, ya que conectarse al host y al puerto de la URL de la solicitud es el comportamiento predeterminado.

Si se utiliza un proxy HTTP para una solicitud que tiene un host o puerto especial de "conectar a", y el host o puerto de "conectar a" difiere del host y puerto de la solicitud, el proxy HTTP se cambia automáticamente al modo túnel para esta solicitud específica. Esto es necesario ya que no es posible conectarse a un host o puerto específico en modo normal (sin túnel).

Cuando esta opción se pasa a curl_easy_setopt(3), libcurl no copia la lista, por lo que debe mantenerla hasta que ya no utilice este manejador para una transferencia antes de llamar a curl_slist_free_all(3) sobre la lista.

Usar esta opción varias veces hace que la última lista establecida sobrescriba las anteriores. Establézcala a NULL para desactivar su uso nuevamente.

PREDETERMINADO

NULL

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos compatibles

EJEMPLO

int main(void)
{
  CURL *curl;
  struct curl_slist *connect_to = NULL;
  connect_to = curl_slist_append(NULL, "example.com::server1.example.com:");
  curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_CONNECT_TO, connect_to);
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_perform(curl);
    /* siempre limpiar */
    curl_easy_cleanup(curl);
  }
  curl_slist_free_all(connect_to);
}

DISPONIBILIDAD

Añadido en curl 7.49.0

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, consulte libcurl-errors(3).
