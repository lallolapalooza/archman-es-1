CURLOPT_HTTP_VERSION(3)

Paquete: curl

Licencias: MIT

CURLOPT_HTTP_VERSION(3) Manual de funciones de la biblioteca CURLOPT_HTTP_VERSION(3)

NOMBRE

CURLOPT_HTTP_VERSION - versión del protocolo HTTP a usar

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HTTP_VERSION, long version);

DESCRIPCIÓN

Pase version un valor long*, configurado en uno de los valores descritos a continuación. Estos solicitan a libcurl que use las versiones HTTP específicas.

Tenga en cuenta que la versión HTTP es solo una solicitud. libcurl todavía prioriza la reutilización de conexiones existentes, por lo que podría reutilizar una conexión que usa una versión HTTP que usted no solicitó.

CURL_HTTP_VERSION_NONE
No nos importa qué versión use la biblioteca. libcurl usa lo que considere adecuado.
CURL_HTTP_VERSION_1_0
Forzar solicitudes HTTP 1.0.
CURL_HTTP_VERSION_1_1
Forzar solicitudes HTTP 1.1.
CURL_HTTP_VERSION_2_0
Intentar solicitudes HTTP 2. libcurl vuelve a HTTP 1.1 si no se puede negociar HTTP 2 con el servidor.

Cuando libcurl usa HTTP/2 sobre HTTPS, no insiste por sí mismo en TLS 1.2 o superior, aunque la especificación lo requiera. Un usuario puede agregar este requisito de versión con CURLOPT_SSLVERSION(3).

El alias CURL_HTTP_VERSION_2 se agregó para reflejar mejor el nombre real del protocolo.

CURL_HTTP_VERSION_2TLS
Intentar HTTP 2 sobre TLS (HTTPS) solamente. libcurl vuelve a HTTP 1.1 si no se puede negociar HTTP 2 con el servidor HTTPS. Para servidores HTTP de texto plano, libcurl usa 1.1.
CURL_HTTP_VERSION_2_PRIOR_KNOWLEDGE
Emitir solicitudes HTTP no TLS usando HTTP/2 sin la mejora HTTP/1.1. Requiere conocimiento previo de que el servidor admite HTTP/2 directamente. Las solicitudes HTTPS todavía usan HTTP/2 de la manera estándar con la versión de protocolo negociada en el apretón de manos TLS.

Desde la versión 8.10.0, si esta opción se establece para una solicitud HTTPS, el protocolo de capa de aplicación (ALPN) ofrecido al servidor es solo HTTP/2. Antes de eso, se ofrecían tanto HTTP/1.1 como HTTP/2.

CURL_HTTP_VERSION_3
(Añadido en 7.66.0) Esta opción hace que libcurl intente usar HTTP/3 con el host indicado en la URL, con retroceso a versiones HTTP anteriores si es necesario.
CURL_HTTP_VERSION_3ONLY
(Añadido en 7.88.0) Establecer esto hace que libcurl intente usar HTTP/3 directamente con el servidor indicado en la URL y no se degradará a una versión HTTP anterior si el servidor no admite HTTP/3.

POR OMISIÓN

Desde curl 8.13.0: CURL_HTTP_VERSION_NONE

Desde curl 7.62.0: CURL_HTTP_VERSION_2TLS

Antes de eso: CURL_HTTP_VERSION_1_1

PROTOCOLOS

Esta funcionalidad afecta solo a http

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode ret;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    curl_easy_setopt(curl, CURLOPT_HTTP_VERSION, CURL_HTTP_VERSION_2TLS);
    ret = curl_easy_perform(curl);
    if(ret == CURLE_HTTP_RETURNED_ERROR) {
      /* un problema de error de respuesta HTTP */
    }
  }
}

HISTORIAL

Los enums CURL_HTTP_VERSION_* se convirtieron en tipos long en la versión 8.13.0; antes de esta versión, se requería una conversión a long al pasarlos a curl_easy_setopt(3).

DISPONIBILIDAD

Añadido en curl 7.9.1

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica un error. Consulte libcurl-errors(3).

VER TAMBIÉN

CURLOPT_ALTSVC(3), CURLOPT_HTTP09_ALLOWED(3), CURLOPT_HTTP200ALIASES(3), CURLOPT_SSLVERSION(3)
