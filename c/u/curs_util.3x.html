DESCRIPCIÓN

unctrl

La rutina unctrl devuelve una cadena de caracteres que es una representación imprimible del carácter ch:

  • Los caracteres imprimibles se muestran tal cual, por ejemplo, una cadena de un solo carácter que contiene la tecla.
  • Los caracteres de control se muestran en la notación ^X.
  • Los caracteres de impresión se muestran tal cual.
  • DEL (carácter 127) se muestra como ^?.
  • Los valores superiores a 128 son caracteres meta (si la pantalla no se ha inicializado, o si meta(3X) se ha llamado con un parámetro TRUE), mostrados en la notación M-X, o se muestran tal cual. En este último caso, los valores pueden no ser imprimibles; esto sigue la especificación X/Open.

La rutina correspondiente wunctrl devuelve una representación imprimible de un carácter complejo wch.

Tanto en unctrl como en wunctrl, los atributos y el color asociados con el parámetro de carácter se ignoran.

keyname, key_name

La rutina keyname devuelve una cadena de caracteres correspondiente a la tecla c. Los códigos de tecla son diferentes de los códigos de carácter.

  • Los códigos de tecla inferiores a 256 son caracteres. Se muestran usando unctrl.
  • Los valores superiores a 256 pueden ser los códigos de las teclas de función. Se muestra el nombre de la tecla de función.
  • De lo contrario (si no hay un nombre correspondiente y la tecla no es un carácter), la función devuelve null, para denotar un error. X/Open también enumera un valor de retorno “CLAVE DESCONOCIDA”, que algunas implementaciones devuelven en lugar de null.

La rutina correspondiente key_name devuelve una cadena de caracteres multibyte correspondiente al valor de carácter ancho w. Las dos funciones (keyname y key_name) no devuelven el mismo conjunto de cadenas:

  • keyname devuelve null donde key_name mostraría un carácter meta.
  • key_name no devuelve el nombre de una tecla de función.

filter, nofilter

La rutina filter, si se usa, debe llamarse antes de que se invoquen initscr o newterm. Llamar a filter provoca estos cambios en la inicialización:

  • LINES se establece en 1;
  • las capacidades clear, cud1, cud, cup, cuu1, cuu, vpa se deshabilitan;
  • la capacidad ed se deshabilita si bce está configurada;
  • y la cadena home se establece en el valor de cr.

La rutina nofilter cancela el efecto de una llamada previa a filter. Eso permite al llamador inicializar una pantalla en un dispositivo diferente, utilizando un valor diferente de $TERM. La limitación surge porque la rutina filter modifica la copia en memoria de la información del terminal.

use_env

La rutina use_env, si se usa, debe llamarse antes de que se invoquen initscr o newterm (porque calculan el tamaño de la pantalla). Modifica la forma en que ncurses trata las variables de entorno al determinar el tamaño de la pantalla.

•
Normalmente ncurses busca primero en la base de datos del terminal el tamaño de la pantalla.
Si se llamó a use_env con FALSE como parámetro, se detiene aquí a menos que también se haya llamado a use_tioctl con TRUE como parámetro.
  • Luego solicita el tamaño de la pantalla a través de llamadas al sistema operativo. Si tiene éxito, anula los valores de la base de datos del terminal.
  • Finalmente (a menos que se haya llamado a use_env con un parámetro FALSE), ncurses examina las variables de entorno LINES o COLUMNS, utilizando un valor en ellas para anular los resultados del sistema operativo o de la base de datos del terminal.
curses también actualiza el tamaño de la pantalla en respuesta a SIGWINCH, a menos que se anule mediante las variables de entorno LINES o COLUMNS,

use_tioctl

La rutina use_tioctl, si se usa, debe llamarse antes de que se invoquen initscr o newterm (porque calculan el tamaño de la pantalla). Después de llamar a use_tioctl con TRUE como argumento, ncurses modifica el último paso en su cálculo del tamaño de la pantalla de la siguiente manera:

  • verifica si las variables de entorno LINES y COLUMNS están establecidas en un número mayor que cero.
  • para cada una, ncurses actualiza la variable de entorno correspondiente con el valor que ha obtenido a través de una llamada al sistema o de la base de datos del terminal.
  • ncurses vuelve a obtener el valor de las variables de entorno para que sigan siendo las variables de entorno las que establezcan el tamaño de la pantalla.

Las rutinas use_env y use_tioctl se combinan de la siguiente manera.

use_env use_tioctl Resumen
TRUE FALSE Este es el comportamiento predeterminado. ncurses utiliza llamadas al sistema operativo a menos que se anulen mediante las variables de entorno LINES o COLUMNS; predeterminado.
TRUE TRUE ncurses actualiza LINES y COLUMNS basándose en las llamadas al sistema operativo.
FALSE TRUE ncurses ignora LINES y COLUMNS, utilizando llamadas al sistema operativo para obtener el tamaño.

putwin, getwin

La rutina putwin escribe todos los datos asociados con la ventana (o pad) win en el archivo al que apunta filep. Esta información puede recuperarse posteriormente utilizando la función getwin.

La rutina getwin lee los datos relacionados con la ventana almacenados en el archivo por putwin. Luego, la rutina crea e inicializa una nueva ventana utilizando esos datos. Devuelve un puntero a la nueva ventana. Hay algunas advertencias:

  • los datos escritos son una copia de la estructura WINDOW y sus celdas de caracteres asociadas. El formato difiere entre las bibliotecas de caracteres anchos (ncursesw) y las no anchas (ncurses). Sin embargo, puede transferir datos entre ambas.
  • la ventana recuperada siempre se crea como una ventana de nivel superior (o pad), en lugar de una subventana.
  • las celdas de caracteres de la ventana contienen el valor del par de colores, pero no los números de color reales. Si las celdas en la ventana recuperada utilizan pares de colores que no se han creado en la aplicación utilizando init_pair, no se colorearán cuando se actualice la ventana.
