CURLOPT_PROXY_SSL_OPTIONS(3)

Paquete: curl

Licencias: MIT

CURLOPT_PROXY_SSL_OPTIONS(3) Manual de funciones de la biblioteca CURLOPT_PROXY_SSL_OPTIONS(3)

NOMBRE

CURLOPT_PROXY_SSL_OPTIONS - Opciones de comportamiento SSL del proxy HTTPS

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_PROXY_SSL_OPTIONS,
                          long bitmask);

DESCRIPCIÓN

Pase un long con una máscara de bits para informar a libcurl sobre comportamientos específicos de SSL. Bits disponibles:

CURLSSLOPT_ALLOW_BEAST
Indica a libcurl que no intente utilizar ninguna solución alternativa para una vulnerabilidad de seguridad en los protocolos SSL3 y TLS1.0. Si esta opción no se utiliza o esta máscara de bits se establece en 0, la capa SSL que utiliza libcurl puede usar una solución alternativa para esta vulnerabilidad, aunque esto podría causar problemas de interoperabilidad con algunas implementaciones SSL (más antiguas). ADVERTENCIA: evitar esta solución alternativa reduce la seguridad, y al establecer esta opción a 1 se solicita exactamente eso. Esta opción solo se admite para Secure Transport y OpenSSL.
CURLSSLOPT_NO_REVOKE
Indica a libcurl que deshabilite las comprobaciones de revocación de certificados para aquellos backends SSL donde existe dicho comportamiento. Esta opción solo se admite para Schannel (la biblioteca SSL nativa de Windows), con la excepción de la lista de bloqueo de Publicadores No Confiables de Windows, que parece que no se puede omitir.
CURLSSLOPT_NO_PARTIALCHAIN
Indica a libcurl que no acepte cadenas de certificados "parciales", lo que de lo contrario hace por defecto. Esta opción falla la verificación del certificado si la cadena termina con un certificado intermedio y no con un certificado raíz.

Funciona con OpenSSL y sus forks (LibreSSL, BoringSSL, etc.). (Añadido en 7.68.0)

Funciona con Schannel si el usuario especificó certificados para verificar al par. (Añadido en 8.15.0)

CURLSSLOPT_REVOKE_BEST_EFFORT
Indica a libcurl que ignore las comprobaciones de revocación de certificados en caso de puntos de distribución faltantes o sin conexión para aquellos backends SSL donde existe dicho comportamiento. Esta opción solo se admite para Schannel (la biblioteca SSL nativa de Windows). Si se combina con CURLSSLOPT_NO_REVOKE, esta última tiene prioridad. (Añadido en 7.70.0)
CURLSSLOPT_NATIVE_CA
Indica a libcurl que utilice el almacén de CA nativo del sistema operativo para la verificación de certificados. Esta opción es independiente de otras ubicaciones de certificados CA establecidas en tiempo de ejecución o en tiempo de compilación. Esas ubicaciones se buscan además del almacén de CA nativo.

Funciona con wolfSSL en Windows, Linux (Debian, Ubuntu, Gentoo, Fedora, RHEL), macOS, Android e iOS (añadido en 8.3.0); con GnuTLS (añadido en 8.5.0) y con OpenSSL y sus forks (LibreSSL, BoringSSL, etc.) en Windows (Añadido en 7.71.0).

CURLSSLOPT_AUTO_CLIENT_CERT
Indica a libcurl que localice y utilice automáticamente un certificado de cliente para la autenticación, cuando lo solicite el servidor. Esta opción solo se admite para Schannel (la biblioteca SSL nativa de Windows). Antes de la versión 7.77.0, este era el comportamiento predeterminado en libcurl con Schannel. Dado que el servidor puede solicitar cualquier certificado que admita la autenticación de cliente en el almacén de certificados del SO, esto podría ser una violación de la privacidad y ser inesperado. (Añadido en 7.77.0)

PREDETERMINADO

0

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos basados en TLS: HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Todos los backends TLS admiten esta opción.

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    curl_easy_setopt(curl, CURLOPT_PROXY, "https://proxy");
    /* debilitar TLS solo para usar con proxies tontos */
    curl_easy_setopt(curl, CURLOPT_PROXY_SSL_OPTIONS,
                     CURLSSLOPT_ALLOW_BEAST | CURLSSLOPT_NO_REVOKE);
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

HISTORIAL

Las macros CURLSSLOPT_* se convirtieron en tipos long en la versión 8.15.0; antes de esta versión, era necesario realizar una conversión a long al pasarlas a curl_easy_setopt(3).

DISPONIBILIDAD

Añadido en curl 7.52.0

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode indicando éxito o error.

CURLE_OK (0) significa que todo estuvo bien, un valor distinto de cero indica que ocurrió un error, ver libcurl-errors(3).
