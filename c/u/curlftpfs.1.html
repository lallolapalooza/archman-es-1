NOMBRE

curlftpfs - montar un host ftp como un directorio local

SINOPSIS

curlftpfs [opciones] host ruta

DESCRIPCIÓN

El programa curlftpfs es una herramienta para montar hosts remotos de ftp como directorios locales. Se conecta al servidor FTP host y mapea su estructura de directorios al directorio ruta.

curlftpfs utiliza libcurl para todas las funciones relacionadas con la transferencia. Vea libcurl(3) para detalles. La parte del sistema de archivos está implementada sobre FUSE. Vea http://fuse.sourceforge.net/ para detalles.

OPCIONES FTP

-h/--ayuda
Imprimir opciones de ayuda.
-v/--verboso
Hacer que libcurl imprima salida de depuración detallada.
-V/--version
Imprimir las versiones de curlftpfs, libcurl y fuse.
-o
Las opciones se especifican con una bandera -o seguida de una cadena de opciones separadas por comas.
cacert=<archivo>
(SSL) Pasar una cadena que nombra un archivo que contiene uno o más certificados para verificar al par.

Tenga en cuenta que esta opción se establece por defecto en la ruta del sistema donde se supone que está almacenado el paquete de certificados cacert de libcurl, según se estableció en el momento de la compilación.

capath=<directorio>
(SSL) Indica a curlftpfs que utilice el directorio de certificados especificado para verificar al par. Los certificados deben estar en formato PEM, y el directorio debe haber sido procesado usando la utilidad c_rehash suministrada con openssl. Usar capath puede permitir a curlftpfs realizar conexiones de manera mucho más eficiente que usar cacert si el archivo cacert contiene muchos certificados CA.
cert=<certificado>
(SSL) Indica a curlftpfs que utilice el archivo de certificado especificado. El formato por defecto es "PEM" y puede cambiarse con cert_type.
cert_type=<tipo>
(SSL) Indica a curlftpfs qué tipo de certificado contiene el certificado proporcionado. Se reconocen los tipos PEM, DER y ENG.
ciphers=<lista de cifrados>
(SSL) Especifica qué cifrados utilizar en la conexión. La lista debe ser sintácticamente correcta, consta de uno o más cadenas de cifrados separadas por dos puntos. Las comas o los espacios también son separadores aceptables, pero normalmente se utilizan los dos puntos. Los operadores válidos son ',', '-' y '+'. Ejemplos válidos de listas de cifrados incluyen 'RC4-SHA', 'SHA1+DES', 'TLSv1' y 'DEFAULT'. La lista por defecto se establece normalmente al compilar OpenSSL.

Lea más detalles sobre las listas de cifrados SSL en esta URL: http://www.openssl.org/docs/apps/ciphers.html

codepage=<nombre>
Establece la codificación que utiliza el servidor ftp para codificar los nombres de archivo.
connect_timeout=<segundos>
Tiempo máximo en segundos que se permite que la conexión al servidor tome. Esto solo limita la fase de conexión, una vez que curlftpfs se ha conectado, esta opción ya no es útil.
custom_list=<comando>
Comando utilizado por curlftpfs para listar archivos. El valor por defecto es "LIST -a", pero algunos servidores pueden requerir opciones adicionales, por ejemplo, "LIST -la".
disable_eprt
Indica a curlftpfs que desactive el uso de los comandos EPRT y LPRT al realizar transferencias FTP activas. Normalmente, curlftpfs primero intentará usar EPRT, luego LPRT, antes de usar PORT, pero con esta opción, usará PORT inmediatamente. EPRT y LPRT son extensiones al protocolo FTP original, pueden no funcionar en todos los servidores pero permiten más funcionalidad de una manera mejor que el comando tradicional PORT.
disable_epsv
Indica a curlftpfs que desactive el uso del comando EPSV al realizar transferencias FTP pasivas. Este es el comportamiento por defecto.
enable_epsv
Indica a curlftpfs que active el uso del comando EPSV al realizar transferencias FTP pasivas. Curlftpfs intentará primero usar EPSV antes que PASV.
engine=<nombre>
Selecciona el motor criptográfico OpenSSL a utilizar para las operaciones de cifrado. Use:
curl --engine list
para imprimir una lista de motores compatibles en tiempo de compilación. Tenga en cuenta que no todos (o ninguno) de los motores pueden estar disponibles en tiempo de ejecución.
ftpfs_debug
Hace que curlftpfs imprima mucha información de depuración. Útil solo en conjunción con la opción -d.
ftp_method=<método>
Controla qué método debe utilizar curlftpfs para acceder a un archivo en el servidor. El argumento método debe ser una de las siguientes alternativas:
multicwd
curlftpfs realiza una única operación CWD por cada parte de la ruta en la URL dada. Para jerarquías profundas, esto significa muchísimos comandos. Así es como RFC1738 dice que debe hacerse. Este es el comportamiento por defecto pero el más lento.
singlecwd
curlftpfs realiza un CWD con el directorio de destino completo y luego opera sobre el archivo "normalmente" (como en el caso de multicwd).
ftp_port=<dirección>
Invierte los roles de iniciador/oyente al conectarse con ftp. Este interruptor hace que curlftpfs utilice el comando PORT en lugar de PASV. En la práctica, PORT le indica al servidor que se conecte a la dirección y puerto especificados por el cliente, mientras que PASV le pide al servidor una dirección IP y un puerto al que conectarse. <dirección> debe ser una de las siguientes:
interfaz
es decir, "eth0" para especificar qué interfaz IP se utilizará
dirección IP
es decir, "192.168.10.1" para especificar un número IP exacto
nombre de host
es decir, "mi.dominio.host" para especificar una máquina
-
hace que curlftpfs elija la misma dirección IP que ya se está utilizando para la conexión de control

Desactiva el intento de usar el comando EPRT en lugar de PORT usando disable_eprt. EPRT es realmente PORT++.

httpproxy
Establece el tipo de proxy en HTTP. Este es el tipo por defecto.
interface=<nombre>
Pasa una cadena como parámetro. Esto establece el nombre de la interfaz a utilizar como interfaz de red saliente. El nombre puede ser un nombre de interfaz, una dirección IP o un nombre de host.
iocharset=<nombre>
Establece el conjunto de caracteres utilizado por el lado del cliente para la traducción de codificación a conjunto de caracteres. Por defecto: UTF8.
ipv4
Si libcurl es capaz de resolver una dirección a múltiples versiones de IP (lo cual es si es compatible con ipv6), esta opción indica a libcurl que resuelva los nombres a direcciones IPv4 únicamente.
ipv6
Si libcurl es capaz de resolver una dirección a múltiples versiones de IP (lo cual es si es compatible con ipv6), esta opción indica a libcurl que resuelva los nombres a direcciones IPv6 únicamente.
