CURLSHOPT_SHARE(3)

Paquete: curl

Licencias: MIT

CURLSHOPT_SHARE(3) Manual de funciones de biblioteca CURLSHOPT_SHARE(3)

NOMBRE

CURLSHOPT_SHARE - añadir datos para compartir

SINOPSIS

#include <curl/curl.h>
CURLSHcode curl_share_setopt(CURLSH *share, CURLSHOPT_SHARE, long type);

DESCRIPCIÓN

El parámetro type especifica qué datos específicos se deben compartir y mantener en el objeto de compartición creado con curl_share_init(3). El type proporcionado debe ser uno de los valores descritos a continuación. Puede configurar CURLSHOPT_SHARE(3) varias veces con argumentos de datos diferentes para que el objeto de compartición comparta múltiples tipos de datos. Anule un tipo volviendo a configurar CURLSHOPT_UNSHARE(3).

Si alguno de los datos va a ser compartido en múltiples hilos, también se deben configurar devoluciones de llamada de mutex. Consulte CURLSHOPT_LOCKFUNC(3) y CURLSHOPT_UNLOCKFUNC(3).

CURL_LOCK_DATA_COOKIE
Los datos de cookies se comparten entre los manejadores 'easy' que utilizan este objeto de compartición. Tenga en cuenta que esto no activa el manejo de cookies de un manejador 'easy'. Puede hacerlo por separado utilizando CURLOPT_COOKIEFILE(3), por ejemplo.

No se admite compartir cookies entre múltiples hilos concurrentes.

CURL_LOCK_DATA_DNS
Los hosts DNS cacheados se comparten entre los manejadores 'easy' que utilizan este objeto de compartición. Tenga en cuenta que cuando se utiliza la interfaz 'multi', todos los manejadores 'easy' añadidos al mismo manejador 'multi' comparten la caché DNS por defecto sin utilizar esta opción.
CURL_LOCK_DATA_SSL_SESSION
Las sesiones SSL se comparten entre los manejadores 'easy' que utilizan este objeto de compartición. Esto reduce el tiempo dedicado al apretón de manos SSL al reconectarse al mismo servidor.

Tenga en cuenta que cuando se utiliza la interfaz 'multi', todos los manejadores 'easy' añadidos al mismo manejador 'multi' comparten la caché de sesiones SSL por defecto sin utilizar esta opción.

CURL_LOCK_DATA_CONNECT
Coloca la caché de conexiones en el objeto de compartición y hace que todos los manejadores 'easy' que utilizan este objeto de compartición compartan la caché de conexiones.

No se admite compartir conexiones entre múltiples hilos concurrentes.

Las conexiones que se utilizan para la multiplexación HTTP/2 o HTTP/3 solo reciben transferencias adicionales si la conexión existente está en manos del mismo manejador 'multi' o 'easy'. libcurl no admite la multiplexación de flujos en diferentes hilos utilizando una conexión compartida.

Tenga en cuenta que cuando se utiliza la interfaz 'multi', todos los manejadores 'easy' añadidos al mismo manejador 'multi' comparten la caché de conexiones por defecto sin utilizar esta opción.

CURL_LOCK_DATA_PSL
La lista de dominios de nivel superior públicos (Public Suffix List) almacenada en el objeto de compartición se pone a disposición de todos los manejadores 'easy' vinculados al mismo. Dado que la lista de dominios de nivel superior públicos se actualiza periódicamente, esto evita actualizaciones en demasiados contextos diferentes.

Añadido en la versión 7.61.0.

Tenga en cuenta que cuando se utiliza la interfaz 'multi', todos los manejadores 'easy' añadidos al mismo manejador 'multi' comparten la caché de PSL por defecto sin utilizar esta opción.

CURL_LOCK_DATA_HSTS
La caché HSTS en memoria.

No se admite compartir el HSTS entre múltiples hilos concurrentes.

Añadido en la versión 7.88.0

PROTOCOLOS

Esta funcionalidad afecta a todos los protocolos soportados.

EJEMPLO

int main(void)
{
  CURLSHcode sh;
  CURLSH *share = curl_share_init();
  sh = curl_share_setopt(share, CURLSHOPT_SHARE, CURL_LOCK_DATA_COOKIE);
  if(sh)
    printf("Error: %s\n", curl_share_strerror(sh));
}

DISPONIBILIDAD

Añadido en curl 7.10.3

VALOR DE RETORNO

CURLSHE_OK (cero) significa que la opción se configuró correctamente, un valor distinto de cero indica que ocurrió un error. Consulte libcurl-errors(3) para ver la lista completa con descripciones.
