CURLOPT_POSTREDIR(3)

Paquete: curl

Licencias: MIT

CURLOPT_POSTREDIR(3) Manual de funciones de biblioteca CURLOPT_POSTREDIR(3)

NOMBRE

CURLOPT_POSTREDIR - cómo actuar ante una redirección de POST HTTP

SINOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_POSTREDIR,
                          long bitmask);

DESCRIPCIÓN

Pase una máscara de bits para controlar cómo libcurl actúa ante redirecciones después de que los POSTs obtengan una respuesta 301, 302 o 303. Un parámetro con el bit 0 establecido (valor CURL_REDIR_POST_301) indica a la biblioteca que respete el RFC 7231 (secciones 6.4.2 a 6.4.4) y no convierta las solicitudes POST en solicitudes GET al seguir una redirección 301. Establecer el bit 1 (valor CURL_REDIR_POST_302) hace que libcurl mantenga el método de solicitud después de una redirección 302, mientras que establecer el bit 2 (valor CURL_REDIR_POST_303) hace que libcurl mantenga el método de solicitud después de una redirección 303. El valor CURL_REDIR_POST_ALL es una definición de conveniencia que establece los tres bits.

El comportamiento no conforme a RFC es ubicuo en los navegadores web, por lo que la biblioteca realiza la conversión por defecto para mantener la coherencia. Sin embargo, un servidor puede requerir que un POST siga siendo un POST después de dicha redirección. Esta opción solo tiene sentido cuando se establece CURLOPT_FOLLOWLOCATION(3).

POR DEFECTO

0

PROTOCOLOS

Esta funcionalidad afecta solo a http

EJEMPLO

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* un ejemplo tonto de POST */
    curl_easy_setopt(curl, CURLOPT_POSTFIELDS, "data=true");
    /* example.com se redirige, así que le decimos a libcurl que envíe POST
       en los códigos de respuesta HTTP 301, 302 y 303 */
    curl_easy_setopt(curl, CURLOPT_POSTREDIR, CURL_REDIR_POST_ALL);
    curl_easy_perform(curl);
  }
}

HISTORIA

Esta opción se conocía como CURLOPT_POST301 hasta la versión 7.19.0, ya que solo admitía el 301 en ese momento. CURL_REDIR_POST_303 se agregó en la versión 7.26.0.

Las macros CURL_REDIR_* se convirtieron en tipos long en la versión 8.16.0; antes de esta versión, era necesario un casting a long al pasarlas a curl_easy_setopt(3).

DISPONIBILIDAD

Agregado en curl 7.19.1

VALOR DE RETORNO

curl_easy_setopt(3) devuelve un CURLcode que indica éxito o error.

CURLE_OK (0) significa que todo estuvo bien; un valor distinto de cero indica un error; consulte libcurl-errors(3).

VER TAMBIÉN
