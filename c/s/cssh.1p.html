DESCRIPCIÓ

N

El comando abre una consola de administración y un xterm para todos los hosts especificados. Cualquier texto escrito en la consola de administración se replica en todas las ventanas. También se puede escribir directamente en todas las

ventanas.

Esta herramienta está destinada para (pero no se limita a) la administración de clústeres donde la misma configuración o comandos deben ejecutarse en cada nodo dentro del clúster. Ejecutar estos comandos todos a la vez mediante esta herramienta asegura que todos los nodos se mantengan

sincronizados.

Las conexiones se abren usando ssh, que debe estar correctamente instalado y

configurado.

Se debe tener especial precaución al editar archivos, ya que las líneas no pueden estar necesariamente en el mismo orden; asumir que la línea 5 es la misma en todos los servidores y modificarla es peligroso. Es mejor buscar la línea específica a cambiar y verificar que todas las terminales están como se espera antes de que se confirmen los

cambios.

Tamaño inicial de las terminales a utilizar. NOTA: el número de líneas (24) se reducirá al redimensionar las terminales para la colocación en mosaico, no el número de caracteres (80).
terminal_title_opt = -T
Opción utilizada con "terminal" para establecer el título de la ventana
terminal_allow_send_events = -xrm '*.VT100.allowSendEvents:true'
Opción requerida por la terminal para permitir la recepción de XSendEvents
title = cssh
Título de las ventanas a utilizar tanto para la consola como para las terminales.
unmap_on_redraw = no
Indica a Tk que utilice la solicitud UnmapWindow antes de redibujar las ventanas de la terminal. Esto tiene el valor predeterminado de "no" ya que causa algunos problemas con el gestor de ventanas FVWM. Si experimenta problemas con los redibujados, puede establecerlo en "yes" para permitir que la ventana se desmapee antes de ser reposicionada.
use_all_a_records = 0
Si un nombre de host se resuelve a múltiples direcciones IP, establézcalo en 1 para conectarse a todas ellas, no solo a la primera encontrada. Ver también "--use-all-a-records"}
use_hotkeys = 1
Establecerlo en 0 deshabilitará todas las teclas de acceso rápido.
use_natural_sort = 0
Las ventanas normalmente se ordenarán alfabéticamente, es decir: host1, host11, host2. Establecer esto en 1 cambiará el orden de ordenación, es decir: host1, host2, host11. NOTA: Debe tener instalado el módulo perl Sort::Naturally.
user = $LOGNAME
Establece el usuario predeterminado para ejecutar comandos en los clientes.
window_tiling = 1
Realiza la colocación en mosaico de ventanas (establecer en 0 para deshabilitar)
window_tiling_direction = right
Dirección para la colocación en mosaico de ventanas, donde "right" significa empezar por la esquina superior izquierda y moverse hacia la derecha y luego hacia abajo, y cualquier otro valor significa empezar por la esquina inferior derecha y moverse hacia la izquierda y luego hacia arriba

NOTA: Los modificadores de atajos de teclado deben estar en la forma "Control", "Alt" o "Shift", por ejemplo, con la primera letra en mayúscula y el resto en minúscula. Las teclas también se pueden deshabilitar individualmente estableciéndolas en la palabra "null".

$HOME/.clusterssh/send_menu
Este archivo (opcional) contiene elementos para poblar el menú de envío. La entrada predeterminada podría escribirse como: 
<send_menu>
  <menu title="Usar Macros">
      <toggle/>
      <accelerator>ALT-p</accelerator>
  </menu>
  <menu title="Nombre de Host Remoto">
      <command>%s</command>
      <accelerator>ALT-n</accelerator>
  </menu>
  <menu title="Nombre de Host Local">
      <command>%s</command>
      <accelerator>ALT-l</accelerator>
  </menu>
  <menu title="Nombre de Usuario">
      <command>%u</command>
      <accelerator>ALT-u</accelerator>
  </menu>
  <menu title="Texto de Prueba">
      <command>echo "Versión de ClusterSSH: %v%n</command>
  </menu>
</send_menu>

Los submenús también se pueden especificar de la siguiente manera:

<send_menu>
  <menu title="Entradas Predeterminadas">
    <detach>yes</detach>
    <menu title="Nombre de Host">
        <command>%s</command>
        <accelerator>ALT-n</accelerator>
    </menu>
  </menu>
</send_menu>

Advertencias:

Actualmente no hay una comprobación estricta del formato de este archivo.
El formato del archivo puede cambiar en el futuro.
Si el archivo existe, la entrada predeterminada (Nombre de Host) no se añade.

Las siguientes macros de reemplazo están disponibles (nota: estas se pueden cambiar en el archivo de configuración):

%s
Parte del nombre de host de la cadena de conexión específica para cada cliente, sin nombre de usuario ni puerto.
%u
Parte del nombre de usuario de la cadena de conexión a cada cliente.
%h
Nombre de host del servidor desde donde se ejecuta cssh.
%n
Código de "RETORNO".

NOTA: requiere que XML::Simple esté instalado.

BUGS CONOCIDOS

Si tiene alguna idea sobre cómo solucionar los siguientes errores, póngase en contacto y/o proporcione un parche.

•
El cambio entre escritorios virtuales puede provocar un redibujado de todas las ventanas de terminal. Esto se debe a la falta de distinción dentro de Tk entre el cambio de escritorio y la minimización/maximización de ventanas. Hasta que Tk pueda distinguir entre los dos eventos, no hay solución (aparte de reescribir todo directamente en X).

SOLUCIÓN DE PROBLEMAS

Si tiene problemas para ejecutar cssh, primero intente:

"cssh -e [usuario@]<nombre_host>[:puerto]"

Esto realiza dos pruebas para confirmar que cssh puede funcionar correctamente con la configuración proporcionada dentro del archivo $HOME/.clusterssh/config (o los valores predeterminados internos).

1.
Probar que la ventana de la terminal funciona con las opciones proporcionadas.
2.
Probar que ssh funciona en un host con los argumentos configurados.

Opciones de configuración a tener en cuenta en ssh:

  • SSH no entiende - elimine la opción del archivo $HOME/.clusterssh/config
  • OpenSSH-3.8 utiliza túneles ssh no confiables - utilice en lugar de o utilice en $HOME/.ssh/ssh_config (si cambia las opciones predeterminadas de ssh de a )

Si necesita soporte, ejecute los siguientes comandos y cree una incidencia en: https://github.com/duncs/clusterssh/issues

"perl -V"

"perl -MX11::Protocol -e 'print $X11::Protocol::VERSION,$/'"

El uso de la opción de depuración (--debug) activará la salida de depuración. Repita la opción para aumentar la cantidad de depuración. Sin embargo, si es posible, utilice esta opción solo con un host a la vez, por ejemplo "cssh --debug <host>" debido a la cantidad de salida producida (tanto en la ventana principal como en las secundarias).
