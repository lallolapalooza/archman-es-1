CSEPDJVU(1) DjVuLibre-3.5 CSEPDJVU(1)

NOMBRE

csepdjvu - codificador DjVu para archivos de datos separados.

SINOPSIS

csepdjvu [opciones] [archivos_sep]... archivo_djvu_salida

DESCRIPCIÓN

Este programa crea un archivo DjVuDocument archivo_djvu_salida a partir de los archivos de datos separados archivos_sep. Puede leer datos separados de la entrada estándar cuando se le proporciona un solo guion en lugar de los nombres de los archivos de datos separados. Esta función está destinada a programas de preprocesamiento que envían datos separados a csepdjvu a través de una tubería.

Cada archivo de datos separado representa una o más imágenes de página. Cuando los argumentos del programa especifican varias páginas, todas las páginas se codifican y se guardan como un documento multipágina empaquetado. Cuando los argumentos del programa especifican una sola página, la página se codifica y se guarda como un archivo de una sola página.

OPCIONES

-d n
Especifica la información de resolución codificada en el archivo de salida, expresada en puntos por pulgada. La información de resolución codificada en los archivos DjVu determina cómo el decodificador escala la imagen en una pantalla determinada. Las resoluciones significativas van de 25 a 6000. El valor predeterminado es 300 ppp.
-q n,...,n
-q n+...+n
Especifica la calidad de codificación de la capa de fondo codificada con IW44. El argumento de la opción contiene varios enteros (uno por fragmento) separados por comas o signos más. Esta opción es similar a la opción -slice del programa c44. Consulte la página del manual de c44(1) para obtener detalles adicionales. La especificación de calidad predeterminada es -q 72,83,93,103.

Esta opción no se aplica a los fondos blancos uniformes que no se especificaron en los datos separados, sino que se solicitan según la especificación DjVu. Dichas imágenes de fondo siempre se obtienen con la resolución más baja posible y con una configuración de calidad estándar que garantiza la uniformidad del color.

-t
El programa csepdjvu interpreta ciertos comentarios en el archivo separado para construir una capa de texto oculta en el archivo DjVu. Esta capa registra la ubicación de cada palabra para fines de resaltado. Esta opción reduce el tamaño del archivo registrando simplemente la ubicación de cada línea.
-v
Muestra un breve mensaje describiendo cada página.
-vv
Muestra mensajes informativos extensos durante la codificación.

FORMATO DE ARCHIVO DE DATOS SEPARADOS

Cada archivo de datos separado contiene una concatenación de una o más imágenes de página separadas. Cada página se representa lógicamente mediante una imagen de primer plano con un color transparente y una imagen de fondo visible a través de los píxeles transparentes. Los datos para cada imagen de página separada son la concatenación de los siguientes bloques de datos:

  • Una imagen de primer plano codificada utilizando el "Formato RLE de color" o el "Formato RLE bitonal". Estos formatos se describen más adelante en esta sección.
  • Una imagen de fondo opcional codificada como "Portable Pixmap" ( PPM ). Este formato bien conocido se resume más adelante en esta sección. La ausencia de una imagen de fondo simplemente indica que se debe asumir un fondo blanco uniforme.
  • Un número arbitrario de líneas de comentarios que comienzan con el carácter "#" y terminan con un carácter de nueva línea. Las líneas de comentarios cuya primera palabra comienza con una letra mayúscula tienen significados especiales documentados más adelante en este documento.

Las dimensiones (ancho y alto) de la imagen de fondo deben obtenerse redondeando al alza el cociente de las dimensiones de la imagen de primer plano por un factor de reducción entero que va de 1 a 12. Suponga, por ejemplo, que el ancho del primer plano es 2507 y el factor de reducción es 3. El ancho de la imagen de fondo será la proporción entera (2507+2)/3.

Formato RLE de color

El formato RLE de color es un esquema simple de codificación de longitud de ejecución para imágenes en color con un número limitado de colores distintos. Los datos siempre comienzan con una cabecera de texto compuesta por los dos caracteres "R6", el número de columnas, el número de filas y el número de entradas de la paleta de colores. Todos los números se expresan en ASCII decimal. Estos cuatro elementos están separados por espacios en blanco (espacio, tabulación, retorno de carro o nueva línea) o por líneas de comentarios introducidas por el carácter "#". El último número va seguido de exactamente un carácter que suele ser un carácter de nueva línea.

La cabecera va seguida de la paleta de colores que contiene tres bytes por entrada de color. Los bytes representan los componentes rojo, verde y azul del color.

La paleta va seguida de una colección de enteros de cuatro bytes (bit más significativo primero) que representan secuencias de píxeles con un color idéntico. Los doce bits superiores de este entero indican el índice del color de la secuencia en la entrada de la paleta. Los veinte bits inferiores del entero indican la longitud de la secuencia. Los índices de color superiores a 0xff0 están reservados. El índice de color 0xfff se utiliza para secuencias transparentes. Cada fila se representa mediante una secuencia de secuencias cuyas longitudes suman el ancho de la imagen. Las filas se codifican comenzando por la fila superior y progresando hacia la fila inferior.

Formato RLE bitonal

El formato RLE bitonal es un esquema simple de codificación de longitud de ejecución para imágenes bitonales. Los datos siempre comienzan con una cabecera de texto compuesta por los dos caracteres "R4", el número de columnas y el número de filas. Todos los números se expresan en ASCII decimal. Estos tres elementos están separados por espacios en blanco (espacio, tabulación, retorno de carro o nueva línea) o por líneas de comentarios introducidas por el carácter "#". El último número va seguido de exactamente un carácter que suele ser un carácter de nueva línea.

El resto del archivo codifica una secuencia de números que representan las longitudes de secuencias alternas de píxeles transparentes y negros. Las líneas se codifican comenzando por la línea superior y progresando hacia la línea inferior. Cada línea comienza con una secuencia blanca. El decodificador sabe que una línea ha terminado cuando la suma de las longitudes de las secuencias de esa línea es igual al número de columnas de la imagen. Los números en el rango de 0 a 191 se representan mediante un solo byte en el rango de 0x00 a 0xbf. Los números en el rango de 192 a 16383 se representan mediante una secuencia de dos bytes: el primer byte, en el rango de 0xc0 a 0xff, codifica los seis bits más significativos del número, el segundo byte codifica los ocho bits restantes del número. Este esquema permite secuencias de longitud cero, que son útiles cuando una línea comienza con un píxel negro y cuando una secuencia muy larga (cuya longitud excede 16383) debe dividirse en secuencias más pequeñas.

Formato Portable Pixmap (PPM)

El formato Portable Pixmap es un formato bien conocido para representar imágenes en color. Consulte la página del manual de ppm(1) para obtener información completa.

Los datos siempre comienzan con una cabecera de texto compuesta por los dos caracteres "P6", el número de columnas, el número de filas y el valor máximo de un componente de color (generalmente 255). Todos los números se expresan en ASCII decimal. Estos tres elementos están separados por espacios en blanco (espacio, tabulación, retorno de carro o nueva línea) o por líneas de comentarios introducidas por el carácter "#". El último número va seguido de exactamente un carácter que suele ser un carácter de nueva línea.

El resto del archivo codifica todos los píxeles. Cada píxel se representa mediante tres bytes que representan el componente rojo, verde y azul del píxel. Los píxeles se ordenan de izquierda a derecha, de arriba a abajo.

Comentarios en archivos separados

Cada página va seguida de un número arbitrario de líneas de comentarios que comienzan con el carácter "#" y terminan con un carácter de nueva línea. Ciertas líneas de comentarios tienen significados especiales. En las siguientes construcciones, todas las cadenas están codificadas en UTF-8 y se representan al estilo de las cadenas Postscript, es decir, entre paréntesis y utilizando la sintaxis de escape de C

csepdjvu(1) — DjVuLibre

NAME

csepdjvu

convert DJVU to DJVU

SYNOPSIS

csepdjvu [-verbose] [-ignore] [-mode mode] [-encoding encoding] [-output output] [-force] [-map mapfile] [-map mapfile]… input.djvu

DESCRIPTION

The csepdjvu command is a front-end to djvutxt(1) and djvused(1) that creates DJVU file containing a hidden text layer and/or hyperlinks. It processes the DJVU file input.djvu and produces a new DJVU file according to the options specified below.

The conversion options from djvutxt(1) are passed directly to the djvutxt(1) program. These include:

  • -verbose: enables verbose output.
  • -ignore: ignores all errors during the text extraction.
  • -mode mode: specifies the text extraction mode. Possible values for mode are:
    • text (default): extracts only the text.
    • image: extracts the text and images.
    • color: extracts the text and color images.
    • mask: extracts the text and mask images.
    • all: extracts text, images, color images, and mask images.
  • -encoding encoding: specifies the character encoding for the output text. The default is UTF-8.

The options for generating hyperlinks and annotations are passed to djvused(1).

  • -output output: specifies the name of the output DJVU file. If not specified, the output file will be named input.djvu.c.
  • -force: overwrites the output file if it already exists.
  • -map mapfile: specifies a mapping file to be used for creating hyperlinks. The mapfile should contain a list of hyperlinks in the format specified in the SEPARATED DATA FILE FORMAT section below. Multiple -map options can be specified to include multiple mapping files.

OPTIONS

In addition to the options described in djvutxt(1) and djvused(1), csepdjvu recognizes the following options:

  • -verbose: enables verbose output.
  • -ignore: ignores all errors during the text extraction.
  • -mode mode: specifies the text extraction mode. Possible values for mode are:
    • text (default): extracts only the text.
    • image: extracts the text and images.
    • color: extracts the text and color images.
    • mask: extracts the text and mask images.
    • all: extracts text, images, color images, and mask images.
  • -encoding encoding: specifies the character encoding for the output text. The default is UTF-8.
  • -output output: specifies the name of the output DJVU file. If not specified, the output file will be named input.djvu.c.
  • -force: overwrites the output file if it already exists.
  • -map mapfile: specifies a mapping file to be used for creating hyperlinks. The mapfile should contain a list of hyperlinks in the format specified in the SEPARATED DATA FILE FORMAT section below. Multiple -map options can be specified to include multiple mapping files.

SEPARATED DATA FILE FORMAT

The mapping files specified with the -map option contain comments and data that describe how to associate text, hyperlinks, and document structure with the DJVU file. Comments start with a hash (#) character and are ignored by the parser. Lines can also contain backslash (\) escape sequences.

The following directives are recognized:

  • # T px:py dx:dy wxh+x+y (string)
    Such a comment line indicates that the piece of text string must be associated with an area of size wxh at position x,y relative to the lower left corner of the page. Integers px, and py represent the position of the current point on the text baseline before the text was drawn. The drawing operation then moves the current point by dx, and dy pixels. When such comments are present, csepdjvu produces a hidden text layer for the corresponding pages.
  • # L wxh+x+y (url)
    Such a comment line indicates that an hyperlink to url url should be associated with area of size wxh at position x,y. When such comments are present, csepdjvu produces pages with an annotation chunk containing the specified hyperlinks.
  • # B count (string) (#pageno)
    Such a comment line provides outline information for the document. An outline entry entitled string is associated with page pageno. Integer count indicates how many of the following outline entries must be attached to the current entry as subentries. When such comments are present in the first page csepdjvu produces an navigation chunk with the specified outline.
  • # P (string)
    Such a comment line provides a title string for the current page.
