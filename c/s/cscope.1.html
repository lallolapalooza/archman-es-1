Interfaz orientada a

líneas

La opción -l le permite usar cscope donde una interfaz orientada a pantalla no sería útil, por ejemplo, desde otro programa orientado a

pantalla.

cscope mostrará el prompt >> cuando esté listo para una línea de entrada que comienza con el número de campo (contando desde 0) seguido inmediatamente por el patrón de búsqueda, por ejemplo, ``lmain'' encuentra la definición de la función

main.

Si solo desea una búsqueda única, en lugar de la opción -l use las opciones -L y -num de patrón, y no obtendrá el prompt >>

.

Para -l, cscope emite el número de líneas de referencia cscope: 2

líneas

Para cada referencia encontrada, cscope emite una línea que consiste en el nombre del archivo, el nombre de la función, el número de línea y el texto de la línea, separados por espacios, por ejemplo, main.c main 161 main(argc,

argv)

Tenga en cuenta que el editor no es llamado para mostrar una sola referencia, a diferencia de la interfaz orientada a

pantalla.

Puede usar el comando c para alternar ignorar/usar mayúsculas y minúsculas al buscar. (Cuando se ignoran las mayúsculas y minúsculas, la búsqueda de ``FILE'' coincidirá con ``File'' y ``file''.

)

Puede usar el comando r para reconstruir la base de

datos.

No es necesario que la declaración de una función comience al principio de una línea. El tipo de retorno puede preceder al nombre de la función; cscope aún reconocerá la declaración. Las definiciones de funciones que se desvían de esta forma no serán reconocidas por cscope.

La columna "Function" de la salida de búsqueda para el campo de entrada de la opción de menú "Find functions called by this function:" solo mostrará la primera función llamada en la línea, es decir, para esta función


e()
{
return (f() + g());
}

la visualización sería


Functions called by this function: e
File Function Line
a.c f 3 return(f() + g());

Ocasionalmente, una definición o llamada de función puede no ser reconocida debido a llaves dentro de sentencias #if. De manera similar, el uso de una variable puede ser incorrectamente reconocido como una definición.

Un nombre typedef que precede a una sentencia de preprocesador será incorrectamente reconocido como una definición global, por ejemplo,


LDFILE *
#if AR16WR

Las sentencias de preprocesador también pueden impedir el reconocimiento de una definición global, por ejemplo,


char flag
#ifdef ALLOCATE_STORAGE
= -1
#endif
;

Una declaración de función dentro de una función es incorrectamente reconocida como una llamada a función, por ejemplo,


f()
{
void g();
}

es incorrectamente reconocida como una llamada a g.

cscope reconoce las clases C++ buscando la palabra clave `class`, pero no reconoce que `struct` también es una clase, por lo que no reconoce las definiciones de funciones miembro en línea en una estructura. Tampoco espera la palabra clave `class` en un typedef, por lo que reconoce incorrectamente X como una definición en


typedef class X * Y;

Tampoco reconoce las definiciones de funciones de operador


Bool Feature::operator==(const Feature & other)
{
...
}

Tampoco reconoce las definiciones de funciones con un argumento de puntero a función


ParseTable::Recognize(int startState, char *pattern,
