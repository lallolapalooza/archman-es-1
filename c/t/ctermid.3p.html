CTERMID(3P) Manual del Programador POSIX CTERMID(3P)

PRÓLOGO

Esta página de manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página de manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

ctermid — generar una ruta de acceso para el terminal de control

SINOPSIS

#include <stdio.h>
char *ctermid(char *s);

DESCRIPCIÓN

La ctermid() función generará una cadena que, cuando se utilice como una ruta de acceso, se refiera al terminal de control actual para el proceso actual. Si ctermid() devuelve una ruta de acceso, el acceso al archivo no está garantizado.

La ctermid() función no necesita ser segura para hilos si se llama con un parámetro NULL.

VALOR DE RETORNO

Si s es un puntero nulo, la cadena se generará en un área que puede ser estática, cuya dirección será devuelta. La aplicación no debe modificar la cadena devuelta. El puntero devuelto podría ser invalidado o el contenido de la cadena podría ser sobrescrito por una llamada posterior a ctermid(). El puntero devuelto también podría ser invalidado si el hilo que llama es terminado. Si s no es un puntero nulo, s se asume que apunta a un arreglo de caracteres de al menos L_ctermid bytes; la cadena se coloca en este arreglo y el valor de s será devuelto. La constante simbólica L_ctermid está definida en <stdio.h>, y debe tener un valor mayor que 0.

La ctermid() función devolverá una cadena vacía si la ruta de acceso que se referiría al terminal de control no puede ser determinada, o si la función no tiene éxito.

ERRORES

No se definen errores.

Las siguientes secciones son informativas.

EJEMPLOS

Determinando el Terminal de Control para el Proceso Actual

El siguiente ejemplo devuelve un puntero a una cadena que identifica el terminal de control para el proceso actual. La ruta de acceso para el terminal es almacenada en el arreglo apuntado por el ptr argumento, que tiene un tamaño de L_ctermid bytes, como lo indica el term argumento.

#include <stdio.h>
...
char term[L_ctermid];
char *ptr;
ptr = ctermid(term);

USO EN LA APLICACIÓN

La diferencia entre ctermid() y ttyname() es que ttyname() debe recibir un descriptor de archivo y devuelve una ruta del terminal asociado con ese descriptor de archivo, mientras que ctermid() devuelve una cadena (como "/dev/tty") que se refiere al terminal de control actual si se usa como una ruta de acceso.

RACIONAMIENTO

L_ctermid debe ser definida apropiadamente para una implementación dada y debe ser mayor que cero para que las declaraciones de arreglos que la usan sean aceptadas por el compilador. El valor incluye el byte nulo de terminación.

Las aplicaciones conformes que usan múltiples hilos no pueden llamar a ctermid() con NULL como el parámetro. Si s no es NULL, la ctermid() función genera una cadena que, cuando se usa como una ruta de acceso, se refiere al terminal de control actual para el proceso actual. Si s es NULL, el valor de retorno de ctermid() es indefinido.

No hay ninguna carga adicional para el programador—cambiar para usar una versión segura para hilos hipotética de ctermid() junto con la asignación de un búfer es más una carga que simplemente asignar un búfer. El código de la aplicación no debe asumir que la cadena devuelta es corta, ya que algunas implementaciones tienen más de dos componentes de ruta de acceso antes de llegar a un nombre de dispositivo lógico.
