Nombre

ctags - Genera archivos de etiquetas para código fuente

SINOPSIS

ctags [<opciones>] [<archivo(s)_fuente(s)>]
etags [<opciones>] [<archivo(s)_fuente(s)>]

DESCRIPCIÓN

Los programas ctags y etags (ver opción -e) (en adelante colectivamente denominados ctags, excepto cuando se distingan) generan un índice (o "etiqueta") para una variedad de objetos de lenguaje encontrados en archivo(s) fuente(s). Este archivo de etiquetas permite que estos elementos sean localizados rápida y fácilmente por un editor de texto u otras utilidades (herramientas cliente). Una etiqueta significa un objeto de lenguaje para el cual hay una entrada de índice disponible (o, alternativamente, la entrada de índice creada para dicho objeto).

Alternativamente, ctags puede generar un archivo de referencias cruzadas que lista, en forma legible por humanos, información sobre los diversos objetos de lenguaje encontrados en un conjunto de archivos fuente.

Los archivos de índice de etiquetas son compatibles con numerosos editores, los cuales permiten al usuario localizar el objeto asociado con un nombre que aparece en un archivo fuente y saltar al archivo y línea que definen el nombre. Consulte el manual de su editor favorito sobre cómo utilizar el comando ctags y los archivos de índice de etiquetas en el editor.

ctags es capaz de generar diferentes tipos de etiquetas para cada uno de los muchos idiomas diferentes. Para una lista completa de idiomas admitidos, los nombres por los que son reconocidos y los tipos de etiquetas que se generan para cada uno, consulte las opciones --list-languages y --list-kinds-full.

Esta página del manual describe Universal Ctags, una implementación de ctags derivada de Exuberant Ctags. Los principales cambios incompatibles entre Universal Ctags y Exuberant Ctags se enumeran en ctags-incompatibilities(7).

Una de las ventajas de Exuberant Ctags es que permite a un usuario definir un nuevo analizador desde la línea de comandos. La extensión de esta capacidad es una de las características principales de Universal Ctags. ctags-optlib(7) describe cómo se extiende esta capacidad.

Las características experimentales recién introducidas no se explican aquí. Si está interesado en tales características e internos de ctags, visite https://docs.ctags.io/.

INTERFAZ DE LÍNEA DE COMANDOS

A pesar de la gran cantidad de opciones disponibles, los valores predeterminados se establecen para que ctags se ejecute comúnmente sin opciones (por ejemplo, "ctags *" o "ctags -R"), lo que creará un archivo de etiquetas en el directorio actual para todos los archivos fuente reconocidos. Las opciones descritas a continuación se proporcionan meramente para permitir una personalización para satisfacer necesidades especiales.

Tenga en cuenta que los espacios que separan las opciones de una sola letra de sus parámetros son opcionales.

Tenga en cuenta también que los parámetros booleanos a las formas largas de las opciones (aquellas que comienzan con -- y que toman un parámetro [=(sí|no)]) pueden omitirse, en cuyo caso se implica =sí. (por ejemplo, --sort es equivalente a --sort=sí). Tenga en cuenta además que =1, =on y =true se consideran sinónimos de =sí, y que =0, =off y =false se consideran sinónimos de =no.

Algunas opciones se ignoran o solo son útiles cuando se ejecutan en modo etags (ver opción -e). Dichas opciones se indicarán.

<opciones> deben preceder a <archivo(s)_fuente(s)> siguiendo la convención estándar POSIX.

Las opciones que toman nombres de idiomas aceptarán esos nombres tanto en mayúsculas como en minúsculas. Consulte la opción --list-languages para obtener una lista completa de los nombres de idiomas integrados.

Letras y nombres

Algunas opciones toman banderas de una sola letra como parámetros (por ejemplo, la opción --kinds-<LANG>). Especificar solo letras ayuda a un usuario a crear una línea de comandos complicada rápidamente. Sin embargo, una línea de comandos que incluye secuencias de banderas de una sola letra se vuelve difícil de entender.

Universal Ctags acepta banderas con nombre largo además de dichas banderas de una sola letra. Las banderas con nombre largo y de una sola letra pueden mezclarse en un parámetro de opción rodeando cada nombre largo con llaves. Por lo tanto, como ejemplo, las siguientes tres notaciones para la opción --kinds-C tienen el mismo significado:

--kinds-C=+pLl
--kinds-C=+{prototype}{label}{local}
--kinds-C=+{prototype}L{local}

Tenga en cuenta que las llaves pueden ser meta-caracteres en su shell. Use comillas simples en tal caso.

Las opciones --list-... muestran banderas de una sola letra y banderas asociadas con nombre largo.

Opciones de lista

Universal Ctags introduce muchas opciones --list-... que proporcionan los datos internos de Universal Ctags (Ver "Opciones de listado"). Tanto los usuarios como las herramientas cliente pueden usar los datos. Las opciones --with-list-header y --machinable ajustan la salida de la mayoría de las opciones --list-....

La configuración predeterminada (--with-list-header=sí y --machinable=no) es para usar interactivamente desde una terminal. La cabecera que explica el significado de las columnas simplemente se agrega a la salida, y cada columna se alinea en todas las líneas. La línea de cabecera comienza con un carácter de almohadilla ('#').

Para scripting en una herramienta cliente, --with-list-header=no y --machinable=sí pueden ser útiles. La cabecera no se agrega a la salida, y cada columna se separa por tabulaciones.

Tenga en cuenta que el orden de las columnas cambiará en futuras versiones. Sin embargo, las etiquetas en la cabecera no cambiarán. Por lo tanto, al escanear la cabecera, una herramienta cliente puede encontrar el índice para la columna de destino.

OPCIONES

ctags tiene más opciones que las enumeradas aquí. Las opciones que comienzan con un guion bajo, como --_echo=<msg>, no se enumeran aquí. Son experimentales o para fines de depuración.

Notación: <foo> es para una cadena variable foo, [ ... ] para opcional, | para selección, y ( ... ) para agrupamiento. Por ejemplo --foo[=(sí|no)] significa --foo, --foo=sí, o --foo=no.
