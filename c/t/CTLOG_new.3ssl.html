CTLOG_new(3ssl)

Paquete: openssl

Licencias: Apache-2.0

CTLOG_NEW(3ssl) OpenSSL CTLOG_NEW(3ssl)

NOMBRE

CTLOG_new_ex, CTLOG_new, CTLOG_new_from_base64, CTLOG_new_from_base64_ex, CTLOG_free, CTLOG_get0_name, CTLOG_get0_log_id, CTLOG_get0_public_key - encapsula información sobre un registro de Transparencia de Certificados

SINOPSIS

#include <openssl/ct.h>
CTLOG *CTLOG_new_ex(EVP_PKEY *public_key, const char *name,
                    OSSL_LIB_CTX *libctx, const char *propq);
CTLOG *CTLOG_new(EVP_PKEY *public_key, const char *name);
int CTLOG_new_from_base64_ex(CTLOG **ct_log, const char *pkey_base64,
                             const char *name, OSSL_LIB_CTX *libctx,
                             const char *propq);
int CTLOG_new_from_base64(CTLOG ** ct_log,
                          const char *pkey_base64, const char *name);
void CTLOG_free(CTLOG *log);
const char *CTLOG_get0_name(const CTLOG *log);
void CTLOG_get0_log_id(const CTLOG *log, const uint8_t **log_id,
                       size_t *log_id_len);
EVP_PKEY *CTLOG_get0_public_key(const CTLOG *log);

DESCRIPCIÓN

CTLOG_new_ex() devuelve un nuevo CTLOG que representa el registro CT (Certificate Transparency) con la clave pública dada y lo asocia con el contexto de la biblioteca libctx y la cadena de consulta de propiedades propq. También se debe proporcionar un nombre que pueda utilizarse para ayudar a los usuarios a identificar este registro. La propiedad de la clave pública se transfiere.

CTLOG_new() hace lo mismo que CTLOG_new_ex() pero con el contexto de biblioteca predeterminado y la cadena de consulta de propiedades predeterminada.

CTLOG_new_from_base64_ex() también crea un nuevo CTLOG, pero toma la clave pública en formato DER codificado en base64 y establece el puntero ct_log para que apunte al nuevo CTLOG. La codificación base64 se decodificará y se analizará la clave pública. El CTLOG se asociará con el contexto de biblioteca dado libctx y la cadena de consulta de propiedades propq.

CTLOG_new_from_base64() hace lo mismo que CTLOG_new_from_base64_ex() excepto que se utilizan el contexto de biblioteca predeterminado y la cadena de consulta de propiedades predeterminada.

Independientemente de si se utiliza CTLOG_new() o CTLOG_new_from_base64(), es responsabilidad del llamante pasar el CTLOG a CTLOG_free() una vez que ya no sea necesario. Esto lo eliminará y, si fue creado por CTLOG_new(), el EVP_PKEY que se le pasó. Si el argumento para CTLOG_free() es NULL, no se hace nada.

CTLOG_get0_name() devuelve el nombre del registro, tal como se proporcionó al crear el CTLOG. La propiedad de la cadena permanece con el CTLOG.

CTLOG_get0_log_id() establece *log_id para que apunte a una cadena que contenga el LogID de ese registro (ver RFC 6962). Establece *log_id_len a la longitud de ese LogID. Para un registro CT v1, el LogID será un hash SHA-256 (es decir, de 32 bytes de longitud). La propiedad de la cadena permanece con el CTLOG.

CTLOG_get0_public_key() devuelve la clave pública del registro CT. La propiedad del EVP_PKEY permanece con el CTLOG.

VALORES DE RETORNO

CTLOG_new() devolverá NULL si ocurre un error.

CTLOG_new_from_base64() devolverá 1 en caso de éxito, 0 en caso contrario.

VER TAMBIÉN

ct(7)

HISTORIA

Las funciones CTLOG_new_ex() y CTLOG_new_from_base64_ex() se añadieron en OpenSSL 3.0. Todas las demás funciones se añadieron en OpenSSL 1.1.0.
