JUSTIFICACIÓ

N

La lista de opciones se redujo significativamente de la proporcionada por implementaciones históricas. La opción `-F` se omitió como redundante, ya que es la opción por omisión. La opción `-B` se omitió por ser de utilidad muy limitada. La opción `-t` se omitió ya que el reconocimiento de `typedefs` es ahora requerido para archivos fuente en C. La opción `-u` se omitió porque la función de actualización se consideró no solo ineficiente, sino también rara vez

necesaria.

Una propuesta temprana incluía una opción `-w` para suprimir diagnósticos de advertencia. Dado que no se pudieron describir los tipos de tales diagnósticos, la opción se omitió por no ser

útil.

El texto para `LC_CTYPE` sobre la compatibilidad con la configuración regional C reconoce que el estándar ISO C impone requisitos sobre la configuración regional utilizada para procesar código fuente en C. Esto podría ser fácilmente un superconjunto de la conocida como "la configuración regional C" por medio de extensiones de implementación, o una de unas pocas configuraciones regionales alternativas para sistemas que soportan diferentes conjuntos de caracteres. No se hace ninguna declaración para FORTRAN porque el estándar ANSI X3.9‐1978 (FORTRAN 77) no (aún) define un concepto similar de configuración regional. Sin embargo, una regla general en este volumen de POSIX.1‐2017 es que cada vez que las configuraciones regionales no coinciden (preparando un archivo para una configuración regional y procesándolo en otra), los resultados son

sospechosos.

La secuencia de colación del archivo de etiquetas no se ve afectada por `LC_COLLATE` porque normalmente no es usada por lectores humanos, sino solo por programas tales como `vi` para localizar la etiqueta dentro de los archivos fuente. El uso de la configuración regional POSIX elimina algunos de los problemas de coordinar configuraciones regionales entre el creador del archivo `ctags` y el lector del archivo

`vi`.

Históricamente, el archivo de etiquetas ha sido usado solo por `ex` y `vi`. Sin embargo, el formato del archivo de etiquetas ha sido publicado para animar a otros programas a usar las etiquetas de nuevas maneras. El formato permite usar patrones o números de línea para encontrar los identificadores porque el histórico `vi` reconoce cualquiera de los dos. La utilidad `ctags` no produce el formato usando números de línea porque no es útil después de cualquier cambio en el archivo fuente que añada o borre líneas. Los patrones de búsqueda documentados coinciden con la práctica histórica. Debe notarse que los caracteres literales iniciales <circunflejo> o finales <signo de dólar> en el patrón de búsqueda solo se comportarán correctamente si están anclados al principio de la línea o al final de la línea por un carácter adicional <circunflejo> o <signo de dólar>

.

Las implementaciones históricas también entienden los objetos usados por los lenguajes Pascal y a veces LISP, y entienden el código fuente en C producido por `lex` y `yacc`. La utilidad `ctags` no está requerida para acomodar estos lenguajes, aunque se anima a los implementadores a

hacerlo.

    NAME

    ctags — create tags files for use with programming editors

    SYNOPSIS

    ctags [option...] [file...]

    ctags [option...] [--options-file file...]

    DESCRIPTION

    The ctags program generates an index (a tags file) of language objects found in specified source files. A tags file is a text file that contains a list of tags (which typically name functions, variables, classes, etc.) and information about where each tag may be found within the source files. This file is used by editors and other tools to quickly locate the definition of a programming object. The default tags file is named tags. ctags may not recognize all of the languages supported by your compiler. Use the --list-languages option to see a list of the languages for which ctags has built-in support.

    OPTIONS

    Options are listed below, grouped by category.

    Selecting files

    -R[recurse]

    Recurse into directories. The optional argument recurse specifies the maximum depth of the directory recursion. If omitted, it defaults to infinite recursion. If the argument is a number, it specifies the maximum number of levels of directories to descend. A level of 0 means to only look at the files in the current directory. A level of 1 means to descend one level of directories, and so on. For example, -R is equivalent to -Rinfinity. -R2 means to recurse into directories down to two levels deep. The recursion is done by traversing all directories specified on the command line, and for each directory encountered, traversing its subdirectories.

    --exclude=pattern

    Do not process any file or directory whose name matches pattern. This option may be specified more than once. The pattern may use shell wildcards, but must be quoted to prevent shell expansion.

    --exclude-subdir=pattern

    Do not descend into any subdirectory whose name matches pattern. This option may be specified more than once. The pattern may use shell wildcards, but must be quoted to prevent shell expansion.

    --exclude-kinds[=kinds]

    Do not tag objects of the specified kinds. For example, if you do not want to tag functions, you would use --exclude-kinds=f. The default value for kinds is all kinds recognised by ctags. You can get a list of kinds recognised by ctags by running ctags --list-kinds. For example, use --exclude-kinds to exclude only functions, or use --exclude-kinds=f,p to exclude functions and procedure definitions.

    --exclude-kinds-from-file=file

    Do not tag objects of the specified kinds, which are listed in file. Each line in file may contain a language name, followed by a space, followed by a comma-separated list of kinds to exclude for that language. If the language name is omitted, the kinds are excluded for all languages.

    --kinds[=kinds]

    Tag only objects of the specified kinds. For example, use --kinds=f to tag only functions. The default value for kinds is all kinds recognised by ctags. You can get a list of kinds recognised by ctags by running ctags --list-kinds. For example, use --kinds to include only functions, or use --kinds=f,p to include only functions and procedure definitions.

    --kinds-from-file=file

    Tag only objects of the specified kinds, which are listed in file. Each line in file may contain a language name, followed by a space, followed by a comma-separated list of kinds to include for that language. If the language name is omitted, the kinds are included for all languages.

    --langmap=map[,map...]

    Specifies how file extensions are mapped to languages. A map is of the form lang:extensions, where extensions is a colon-separated list of file extensions. For example, use --langmap=c:c.h.cs,go:go,javascript:js.jsx to map C-like files to the C language, Go files to the Go language, and JavaScript files to the JavaScript language. If you specify a language for which ctags has no built-in support, then ctags will attempt to recognize files based upon the specified extensions.

    --list-excludes

    Print a list of the patterns which cause files and/or directories to be excluded, and exit.

    --list-kinds[=language]

    Print a list of the kinds of objects which ctags recognizes, possibly limited to the specified language, and exit. If language is omitted, then the kinds for all supported languages are printed.

    --list-languages

    Print a list of the languages for which ctags has built-in support, and exit.

    --recurse[=arg]

    Same as -R.

    -T

    Same as --no-ignore.

    --no-ignore

    Do not ignore files that have names ending in `.'. Do not ignore directories that begin with a dot. The default behaviour of ctags is to ignore files that begin with a dot (except for the current directory, `.') and directories that begin with a dot (except for the current directory, `.' and the parent directory, `..').

    Tag file format

    -o file
    --output-file=file

    Write the tags to file instead of the default tags file (which is named tags).

    -f file
    --tag-file=file

    Same as -o.

    --append[=flag]

    Append to the existing tags file instead of overwriting it. The default is to overwrite the tags file. If flag is given as no, then the tags file will be overwritten.

    --format=version

    Specifies the version of the tags file format to be written. The possible values for version are: 1: the original ctags format. 2: the extended ctags format, which includes the kind of the tag and the file in which it was found. 3: the emacs tags format. This is the default.

    --language-force=lang[,lang...]

    Treat all source files as being of the specified language(s). This is useful for those cases where a source file has an extension that is not recognized by ctags, or when you want to process files that do not have an extension. For example, use --language-force=c to treat all files as C source files.

    --sort[=flag]

    Specifies whether or not to sort the tags file. The default is to sort the file. The possible values for flag are: yes: sort the tags file alphabetically. no: do not sort the tags file. foldcase: sort the tags file case-insensitively.

    Miscellaneous options

    -h
    --help

    Print a usage message summarizing the options and exit.

    --options-file=file

    Read option parameters from file. This option may be specified more than once. Options read from later files override options read from earlier files.

    -V
    --version

    Print the version identification of ctags and exit.

    -v
    --verbose[=flag]

    Enable or disable verbosity. The default is to disable verbosity. If flag is given as yes, then verbosity is enabled. If flag is given as no, then verbosity is disabled. When verbosity is enabled, ctags prints the names of the files being processed.

    COMMAND LINE SYNTAX

    The syntax for invoking ctags is as follows: ctags [options] [file...] where options are any of the options listed in the preceding section, and file is the name of a source file. If no files are specified, ctags reads from the standard input. When no files are specified, ctags reads from the standard input and writes the tags to the standard output. When files are specified, ctags reads those files and writes the tags to a file named tags in the current directory.

    FILE SPECIFICATIONS

    A file specification is a pathname that specifies a file to be processed. If the file specification is a directory name, then ctags will recursively search that directory for source files. You may specify a list of files and/or directories on the command line. ctags will process all specified files and any source files found in the specified directories.

    TAG FILE FORMAT

    The tags file is a text file that contains a list of tags, one per line. Each line consists of the following fields: tagname file address [;kind] [;field...] where: tagname The name of the tag (e.g., a function name, variable name, etc.). file The name of the file in which the tag was found. address An address that tells the editor where to find the tag in the file. This is either a line number or a pattern to be searched for (using regular expression syntax). kind (optional) The kind of tag (e.g., function, variable, class, etc.). This field is only present if the --format=2 or --format=3 option is used. field (optional) Additional information about the tag, such as its signature or scope. This field is only present if the --format=2 or --format=3 option is used. The fields are separated by tab characters. The address field is interpreted by the editor. For example, if the address is a line number, the editor will go to that line. If the address is a pattern, the editor will search for that pattern.

    EXCLUSION

    ctags supports several ways to exclude files and/or directories from processing. --exclude=pattern: Excludes files and/or directories matching the given pattern. --exclude-subdir=pattern: Excludes subdirectories matching the given pattern from recursive searches. --exclude-kinds=kinds: Excludes tags of the specified kinds. --exclude-kinds-from-file=file: Excludes tags of the kinds specified in the given file. The default behavior is to ignore files beginning with a dot (`.') and directories beginning with a dot (`.'), except for the current directory (`.') and the parent directory (`..'). This behavior can be disabled using the --no-ignore option.

    IMPLEMENTATION DETAILS

    ctags uses regular expressions to identify tags. The syntax of these regular expressions is implementation-dependent. The default tags file format is Emacs tags format (version 3).

    MULTITHREADING

    ctags may use multiple threads to process multiple input files in parallel. This can significantly speed up the generation of tags files for large projects.

    SPECIFIC LANGUAGES

    ctags has built-in support for a wide variety of programming languages. The specific languages supported and the kinds of objects tagged may vary depending on the version of ctags. Use the --list-languages option to see a list of languages supported by your version of ctags. Use the --list-kinds=language option to see the kinds of objects that ctags recognizes for a specific language.

    DEPENDENCIES

    None.

    CHARACTER ENCODING

    ctags attempts to detect the character encoding of the source files and writes the tags file using the same encoding. If the encoding cannot be detected, UTF-8 is assumed.

    CUSTOMIZATION

    The behavior of ctags can be customized by using options specified on the command line or by using an options file. Options specified on the command line override options specified in an options file.

    ENVIRONMENT

    ctags does not use any environment variables.

    STDOUT

    When files are specified on the command line, the tags are written to the file named tags in the current directory. When no files are specified, the tags are written to the standard output.

    STDERR

    Error messages are written to the standard error.

    OUTPUT FILES

    The default output file is named tags. This can be changed using the --output-file option.

    EXTENDED DESCRIPTION

    This section provides a more detailed description of the ctags program. ctags is a powerful tool for generating tags files, which are used by many editors and programming tools to quickly navigate source code. It can recognize a wide variety of programming languages and can be configured to tag specific kinds of objects, such as functions, variables, classes, etc. The program works by scanning the specified source files and identifying language objects based on predefined patterns. These patterns are typically defined using regular expressions. The information extracted includes the name of the object, its location in the file (line number or pattern), and optionally its kind and other attributes. The generated tags file is typically sorted alphabetically by tag name, which allows for efficient searching by editors. The format of the tags file can be customized to suit different editor requirements.

    EXIT STATUS

    ctags exits with a status of 0 if the tags file was generated successfully. It exits with a non-zero status if an error occurred.

    CONSEQUENCES OF ERRORS

    If an error occurs during the generation of the tags file, ctags will print an error message to the standard error and exit with a non-zero status. The generated tags file may be incomplete or corrupted.

    APPLICATION USAGE

    The typical usage of ctags is to run it in the root directory of a project: $ ctags -R . This command will recursively scan all files in the current directory and its subdirectories, and create a tags file in the current directory. You can then use this tags file with your editor to navigate the code. For example, in Vim, you can use :tag tagname to jump to the definition of tagname.

    EXAMPLES

    Generate tags for all C files in the current directory and subdirectories:

    ctags -R

    Generate tags for a specific file:

    ctags main.c

    Generate tags and append them to an existing tags file:

    ctags --append foo.c bar.c

    Generate tags only for functions and classes:

    ctags --kinds=+f,c -R

    Generate tags, excluding files ending in .tmp:

    ctags --exclude='*.tmp' -R

    List supported languages:

    ctags --list-languages

    List kinds of objects for C language:

    ctags --list-kinds=c

    RATIONALE

    The ctags utility has been a standard tool for programmers for many years. It provides a simple and efficient way to create an index of source code, which greatly aids in code navigation and understanding. The program has evolved over time to support more languages and provide more features, while maintaining backward compatibility with existing tags file formats.

    FUTURE DIRECTIONS

    Future development of ctags may focus on improving language support, enhancing performance, and adding new features such as support for more complex code structures or integration with other development tools.
