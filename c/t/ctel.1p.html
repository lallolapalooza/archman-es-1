NOMBRE

ctel - Herramienta de administración de clústeres

VERSIÓN

Esta documentación es para la versión: 4.16

SINOPSIS

ctel [-K <segundos>] [-q] [-c '<nombre_de_archivo>'] [-x <columnas>] [-C '<nombre_de_archivo>'] [--debug [[...] || <ENTERO>]] [-d] [-e '<[usuario@]<host>[:puerto]>'] [--fillscreen] [-f '<fuente>'] [-h] [-L '[etiqueta]'] [-H] [-p <puerto>] [-Q] [-y <filas>] [-s] [-r '<nombre_de_archivo>'] [-t '<CADENA>'] [-g] [-T '<título>'] [-u] [-?] [-A] [-v]

RELACIONADO

Véase también las páginas de manual individuales de cada una de estas utilidades

ccon - Usa 'console' como método de comunicación
crsh - Usa 'rsh' como método de comunicación
csftp - Usa 'sftp' como método de comunicación
cssh - Usa 'ssh' como método de comunicación

DESCRIPCIÓN

El comando abre una consola de administración y un xterm a todos los hosts especificados. Cualquier texto escrito en la consola de administración se replica en todas las ventanas. También se puede escribir directamente en todas las ventanas.

Esta herramienta está destinada para (pero no se limita a) la administración de clústeres donde la misma configuración o los mismos comandos deben ejecutarse en cada nodo dentro del clúster. Ejecutar estos comandos todos a la vez mediante esta herramienta asegura que todos los nodos se mantengan sincronizados.

Las conexiones se abren usando telnet, que debe estar correctamente instalado y configurado.

Se debe tener especial precaución al editar archivos, ya que las líneas no están necesariamente en el mismo orden; asumir que la línea 5 es la misma en todos los servidores y modificarla es peligroso. Es mejor buscar la línea específica a cambiar y verificar que todas las terminales están como se espera antes de que se apliquen los cambios.

Notas adicionales

Véase también "ERRORES CONOCIDOS".

  • La línea punteada en cualquier submenú es un desprendible, es decir, haz clic en ella y el submenú se convierte en su propia ventana.
  • Desmarcar un nombre de host en el submenú de Hosts desconectará el host de la ventana de control del clúster, de modo que cualquier texto escrito en la consola no se envía a ese host. Volver a seleccionarlo lo reconectará.
  • Si las barras de menú de tu gestor de ventanas están ocultas por ventanas de terminal, consulta las "screen_reserve_XXXXX" opciones en el $HOME/.clusterssh/config archivo (véase "ARCHIVOS").
  • Si las terminales se superponen demasiado, consulta las "terminal_reserve_XXXXX" opciones en el $HOME/.clusterssh/config archivo (véase "ARCHIVOS").
  • Cuando se usa ClusterSSH en un gran número de sistemas para conectarse a un solo sistema usando una utilidad SSH (por ejemplo, emites un comando para copiar un archivo usando scp desde los equipos remotos a un solo host) y cuando estas conexiones requieren autenticación (es decir, vas a autenticarte con una contraseña), el demonio sshd en esa ubicación puede rechazar conexiones después de que se supere el límite "MaxStartups" en sshd_config (Si este valor no está establecido, el valor predeterminado es 10). Este es el comportamiento esperado; sshd usa este mecanismo para prevenir ataques DoS de fuentes no autenticadas. Por favor, ajusta sshd_config y recarga el demonio SSH, o considera usar el mecanismo ~/.ssh/authorized_keys para la autenticación si encuentras este problema.
  • Si las ventanas de cliente no se abren, intenta ejecutar:

    "ctel -e {nombre_de_host_único}"

    Esto probará los mecanismos usados para abrir ventanas a hosts. Esto podría deberse a la opción de terminal "-xrm" que habilita "AllowSendEvents" (algunas terminales no requieren esta opción, otras terminales tienen otro método para habilitarlo - consulta la documentación de tu terminal) o a la configuración de "telnet".

OPCIONES

Algunas de estas opciones también pueden definirse dentro del archivo de configuración. Las opciones predeterminadas se muestran según corresponda.

--autoclose <segundos>, -K <segundos>
Número de segundos a esperar antes de cerrar las ventanas de terminal terminadas.
--autoquit, -q
Alterna la salida automática después de que se haya cerrado la última ventana de cliente (anulando el archivo de configuración).
--cluster-file '<nombre_de_archivo>', -c '<nombre_de_archivo>'
Usa el archivo proporcionado como archivo de clúster adicional (véase también "ARCHIVOS").
--cols <columnas>, -x <columnas>
Número de columnas
--config-file '<nombre_de_archivo>', -C '<nombre_de_archivo>'
Usa el archivo proporcionado como archivo de configuración adicional (véase también "ARCHIVOS").
--debug [[...] || <ENTERO>]
Habilita la depuración. Se puede proporcionar un nivel o la opción puede repetirse varias veces. El nivel máximo es 9.
--dump-config, -d
Muestra la configuración actual en el mismo formato usado por el $HOME/.clusterssh/config archivo.
--evaluate '<[usuario@]<host>[:puerto]>', -e '<[usuario@]<host>[:puerto]>'
Muestra y evalúa los argumentos de terminal y conexión para mostrar cualquier error potencial. El <nombre_de_host> es necesario para ayudar en la evaluación.
--fillscreen
Redimensiona las ventanas de terminal para llenar toda la pantalla disponible
--font '<fuente>', -f '<fuente>'
Especifica la fuente a usar en las ventanas de terminal. Usa la notación estándar de fuentes X como "5x8".
--help, -h
Muestra el texto de ayuda básico y sale
--list '[etiqueta]', -L '[etiqueta]'
Lista las etiquetas de clúster disponibles. La etiqueta es opcional. Si se proporciona una etiqueta, se listan los hosts para esa etiqueta. NOTA: el formato de la salida cambia al usar la opción "--quiet" o "-Q".
--man, -H
Muestra el texto de ayuda completo (la página de manual) y sale
--port <puerto>, -p <puerto>
Especifica un puerto alternativo para las conexiones.
--quiet, -Q
No muestra texto adicional al usar algunas opciones
--rows <filas>, -y <filas>
Número de filas
--show-history, -s
Muestra el historial dentro de la ventana de consola.
--tag-file '<nombre_de_archivo>', -r '<nombre_de_archivo>'
Usa el archivo proporcionado como archivo de etiquetas adicional (véase también "ARCHIVOS")
--term-args '<CADENA>', -t '<CADENA>'
Especifica los argumentos a pasar a los terminales que se están usando.
--tile, -g
Alterna el mosaico de ventanas (anulando el archivo de configuración).
--title '<título>', -T '<título>'
Especifica la parte inicial del título usado en la consola y las ventanas de cliente.
--unique-servers, -u
Alterna la conexión a cada host solo una vez cuando un nombre de host ha sido especificado varias veces.
--usage, -?
Muestra la sinopsis y sale
--use-all-a-records, -A
Si un nombre de host se resuelve a múltiples direcciones IP, alterna si se debe o no conectarse a todos ellos, o solo al primero (véase también la entrada del archivo de configuración).
--version, -v
Muestra la información de la versión y sale.

ARGUMENTOS

Se admiten los siguientes argumentos:

[usuario@]<nombre_de_host>[:puerto] ...
Abre un xterm en el nombre de host dado y se conecta a la consola de administración. Se puede usar el número de puerto opcional si el servidor no está escuchando en el puerto estándar.
<etiqueta> ...
Abre una serie de xterms definidos por <etiqueta> en uno de los archivos de configuración suplementarios (véase "ARCHIVOS").

Nota: especificar un nombre de usuario en una etiqueta de clúster anulará cualquier nombre de usuario definido en el clúster.

EJEMPLOS

Abrir una sesión con 3 servidores
$ ctel server1 server2 server3
Abrir una sesión con un clúster de servidores identificado por la etiqueta 'farm1' y darle un título específico a la ventana de control, donde la etiqueta está definida en uno de los archivos de configuración predeterminados
$ ctel -T 'Web Farm Cluster 1' farm1
Conectarse a diferentes servidores usando diferentes nombres de usuario. NOTA: esto también se puede lograr configurando las opciones apropiadas en los archivos de configuración. No cierre la consola cuando el último terminal salga.
$ ctel user1@server1 admin@server2
Abrir un clúster definido en un archivo de configuración no predeterminado
$ ctel -c$HOME/cssh.extra_clusters db_cluster
Anular el puerto configurado/predeterminado para usar 2022 en su lugar
$ ctel -p 2022 server1 server2

ARCHIVOS

/etc/clusters, $HOME/.clusterssh/clusters
Estos archivos contienen una lista de mapeos de etiquetas a nombres de servidor. Cuando se usa cualquier nombre en la línea de comandos, se comprueba si es una etiqueta. Si es una etiqueta, la etiqueta se reemplaza con la lista de servidores. El formato es el siguiente:

<etiqueta> [usuario@]<servidor>[:puerto] [usuario@]<servidor>[:puerto] [...]

p. ej.

# Lista de servidores en live
live admin1@server1 admin2@server2:2022 server3 server4

Se ignoran todos los comentarios (marcados por una #) y las líneas en blanco. Las etiquetas pueden estar anidadas, pero tenga cuidado al usar etiquetas recursivas, ya que no se comprueba si lo son.

Los servidores pueden definirse usando macros de expansión:

"webservers websvr{a,b,c}"

se expandiría a

"webservers websvra websvrb websvrc"

y

"webservers websvr{6..9}"

se expandiría a

"webservers websvr6 websvr7 websvr8 websvr9"

Los archivos de clúster adicionales también pueden especificarse como una opción en la línea de comandos (véase "cluster-file") o en el archivo $HOME/.clusterssh/config del usuario (véase la opción de configuración "extra_cluster_file").

NOTA: la última etiqueta leída anula cualquier etiqueta preexistente con ese nombre.

NOTA: existe una etiqueta de clúster especial llamada "default" - cualquier etiqueta o host incluido dentro de esta etiqueta se abrirá automáticamente si no se especifica nada en la línea de comandos.

/etc/tags, $HOME/.clusterssh/tags
Muy similar a los archivos clusters pero la definición está invertida. El formato es:

<host> <etiqueta> [...]

Esto permite que un host se especifique como miembro de un número de etiquetas. Este formato puede ser más claro que usar los archivos clusters .

Se pueden especificar archivos de etiquetas adicionales como una opción (véase "tag-file") o dentro del archivo $HOME/.clusterssh/config del usuario (véase la opción de "extra_tag_file" configuración).

NOTA: Todas las etiquetas se añaden juntas

/etc/csshrc & $HOME/.clusterssh/config
Este archivo contiene anulaciones de configuración - los valores predeterminados son los marcados. Las opciones predeterminadas se anulan primero por el archivo global y luego por el archivo del usuario.

NOTA: los valores de las entradas no necesitan estar entre comillas a menos que sea necesario para pasar argumentos, p. ej.

"terminal_allow_send_events="-xrm '*.VT100.allowSendEvents:true'""

debería escribirse como

"terminal_allow_send_events=-xrm '*.VT100.allowSendEvents:true'"

auto_close = 5
Cierra la ventana de la terminal después de este número de segundos. Si se establece en 0, en su lugar esperará la entrada del usuario en cada ventana antes de cerrar. Véase también --autoclose y --no-autoclose
auto_quit = 1
Sale automáticamente después de que se cierre la última ventana del cliente. Establecer en 0 para deshabilitar. Véase también --autoquit
auto_wm_decoration_offsets = no
Habilita o deshabilita el algoritmo alternativo para calcular el posicionamiento de la terminal.
command_pre =
command_post =
Añade comandos adicionales alrededor del método de comunicación. Por ejemplo:

command_pre= . $HOME/virtualenvs/default/bin/active ; command_post= | ct

permitiría usar entornos virtuales de Python y luego canalizar toda la salida del shell a través de "chromaterm" para el resaltado de sintaxis. Nota: debe usar separadores/terminadores de comandos apropiados para mantener el significado de la tubería de comandos (como ";" y "|" entre comandos).

Estos no se procesan mediante el análisis de macros.

comms = telnet
Establece el método de comunicación predeterminado (inicialmente tomado del nombre del programa, pero puede anularse aquí).
console_position = <null>
Establece la posición inicial de la consola - si está vacío, deja que el gestor de ventanas decida. El formato es '+<x>+<y>', es decir, '+0+0' es la esquina superior izquierda de la pantalla, '+0-70' es el lado inferior izquierdo de la pantalla (más o menos).
external_command_mode = 0600
Bits de modo de archivo para external_command_pipe.
external_command_pipe = <null>
Define la ruta completa a un tubo de comandos externo al que se puede escribir para controlar algunos aspectos de ClusterSSH, como abrir sesiones a más clústeres.

Comandos:

"open <etiqueta|nombre_de_host>" - abre nuevas sesiones a la etiqueta o nombre de host proporcionado

"retile" - fuerza el reorganizado de ventanas

p. ej.: "echo 'open localhost'" /path/to/external_command_pipe >>

external_cluster_command = <null>
Define la ruta completa a un comando externo que se puede usar para resolver etiquetas a nombres de host. Este comando puede escribirse en cualquier lenguaje. El script debe aceptar una lista de etiquetas a resolver y producir una lista de hosts (separados por espacios en una sola línea). Cualquier etiqueta que no pueda resolverse debe devolverse sin cambios.

Un código de salida distinto de 0 se contará como un error, se imprimirá una advertencia y se ignorará la salida.

Si al comando externo se le da una opción "-L" debería producir una lista de etiquetas (separadas por espacios en una sola línea) que puede resolver

"extra_cluster_file = ~/clusters, $HOME/clus"

extra_tag_file = <null>
Define un archivo de etiquetas adicional en el formato de /etc/tags. Se pueden especificar múltiples archivos, separados por comas. Tanto ~ como $HOME son aceptables como referencia al directorio de inicio del usuario, por ejemplo

"extra_tag_file = ~/tags, $HOME/tags"
