DESCRIPCIÓ

N

ctlinnd envía un mensaje al canal de control de innd(8), el demonio principal de

InterNetNews.

En el modo de comportamiento normal, el mensaje se envía al servidor, que luego realiza la acción solicitada y envía de vuelta una respuesta con un mensaje de texto y un código de salida para ctlinnd. Si el servidor realizó el comando con éxito, ctlinnd imprimirá la respuesta en la salida estándar y saldrá con un estado de cero. Si el servidor no pudo realizar el comando, dirigirá a ctlinnd a salir con un estado de uno. Por defecto, ctlinnd esperará para siempre una respuesta de innd; esto se puede cambiar con el indicador

-t.

Los comandos "shutdown", "xabort" y "xexec" no generan una respuesta, ya que causan que innd salga. Después de estos comandos, ctlinnd siempre saldrá silen

ciosamente con un
estado de cero.

h
Imprime un resumen de comandos. Si se da un comando junto con el indicador -h, solo se dará el uso para ese
comando.

-t tiempo_de_e
spera
Especifica cuánto tiempo esperar la respuesta del servidor, para comandos distintos de "shutdown", "xabort" y "xexec". tiempo_de_espera es el número de segundos a esperar. Un valor de cero indica esperar para siempre, y un valor menor que cero indica no esperar en absoluto, sino salir inmediatamente con estado cero. Al esperar una respuesta, ctlinnd comprobará cada dos minutos para asegurarse de que el servidor sigue en ejecución, para hacer menos probable que ctlinnd simplemente se cuelgue.

El valor por defecto es cero, indicando que ctlinnd debe

esperar
para s
iempre.
