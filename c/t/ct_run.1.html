ct_run(1) Comandos de usuario ct_run(1)

NOMBRE

ct_run - Programa utilizado para iniciar Common Test desde la línea de comandos del sistema operativo

DESCRIPCIÓN

El programa ct_run se instala automáticamente con Erlang/OTP y la aplicación Common Test (para más información, véase la sección Instalación en la Guía del Usuario). El programa acepta diferentes indicadores de inicio. Algunos indicadores activan ct_run para iniciar Common Test y pasarle datos. Algunos indicadores inician un nodo Erlang preparado para ejecutar Common Test en un modo particular.

La función de interfaz ct:run_test/1, que corresponde al programa ct_run, se utiliza para iniciar Common Test desde el shell de Erlang (o un programa Erlang). Para más detalles, véase la página del manual de ct.

ct_run también acepta indicadores del emulador Erlang. Estos se utilizan cuando ct_run llama a erl para iniciar el nodo Erlang (esto hace posible añadir directorios a la ruta del servidor de código, cambiar la cookie en el nodo, iniciar más aplicaciones, etc.).

Con el indicador opcional -erl_args, las opciones de la línea de comandos de ct_run se pueden dividir en dos grupos:

•Un grupo que Common Test debe procesar (los que preceden a -erl_args).
•Un grupo que Common Test debe ignorar y pasar directamente al emulador (los que siguen a -erl_args).

Los indicadores que preceden a -erl_args y que Common Test no reconoce también se pasan al emulador sin cambios. Mediante -erl_args, el usuario puede especificar indicadores con el mismo nombre, pero con diferentes destinos, en la línea de comandos de ct_run.

Si los indicadores -pa o -pz se especifican en el grupo de opciones de Common Test (antes de -erl_args), los directorios relativos se convierten a absolutos y se reinsertan en la ruta de código por Common Test. Esto es para evitar problemas al cargar módulos de usuario cuando Common Test cambia el directorio de trabajo durante la ejecución de las pruebas. Sin embargo, Common Test ignora los indicadores -pa y -pz que siguen a -erl_args en la línea de comandos. Estos directorios se añaden a la ruta de código normalmente (es decir, en la forma especificada).

El estado de salida se establece antes de que el programa termine. El valor 0 indica un resultado de prueba exitoso, 1 indica uno o más casos de prueba fallidos o omitidos automáticamente, y 2 indica un fallo en la ejecución de la prueba.

Si se llama a ct_run con el indicador -help, imprime todos los indicadores de inicio válidos en stdout.

Ejecutar pruebas desde la línea de comandos

 ct_run -dir DirectorioPrueba1 DirectorioPrueba2 .. DirectorioPruebaN |
  [-dir DirectorioPrueba] -suite Suite1 Suite2 .. SuiteN
  [-group Grupos1 Grupos2 .. GruposN] [-case Caso1 Caso2 .. CasoN]
  [-step [config | keep_inactive]]
  [-config ArchivoConfig1 ArchivoConfig2 .. ArchivoConfigN]
  [-userconfig MóduloCallback1 CadenaConfig1 y MóduloCallback2
   CadenaConfig2 y .. MóduloCallbackN CadenaConfigN]
  [-decrypt_key Clave] | [-decrypt_file ArchivoClave]
  [-label Etiqueta]
  [-logdir DirectorioLog]
  [-logopts OpcionesLog]
  [-verbosity NivelVGen | [Categoría1 NivelV1 y
   Categoría2 NivelV2 y .. CategoríaN NivelVN]]
  [-silent_connections [TipoConexión1 TipoConexión2 .. TipoConexiónN]]
  [-stylesheet ArchivoCSS]
  [-cover ArchivoCfgCover]
  [-cover_stop Booleano]
  [-event_handler ManejadorEvento1 ManejadorEvento2 .. ManejadorEventoN] |
  [-event_handler_init ManejadorEvento1 ArgInicial1 y
   ManejadorEvento2 ArgInicial2 y .. ManejadorEventoN ArgInicialN]
  [-include DirectorioIncl1 DirectorioIncl2 .. DirectorioInclN]
  [-no_auto_compile]
  [-abort_if_missing_suites]
  [-multiply_timetraps Multiplicador]
  [-scale_timetraps]
  [-create_priv_dir auto_per_run | auto_per_tc | manual_per_tc]
  [-repeat N] |
  [-duration HHMMSS [-force_stop [skip_rest]]] |
  [-until [AAAAMM DD]HHMMSS [-force_stop [skip_rest]]]
  [-basic_html]
  [-no_esc_chars]
  [-keep_logs all | NLogs]
  [-ct_hooks MóduloCTH1 OpcionesCTH1 y MóduloCTH2 OpcionesCTH2 y ..
   MóduloCTHN OpcionesCTHN]
  [-ct_hooks_order test | config]
  [-exit_status ignore_config]
  [-help]

Ejecutar pruebas usando especificación de prueba

 ct_run -spec EspecificaciónPrueba1 EspecificaciónPrueba2 .. EspecificaciónPruebaN
  [-join_specs]
  [-config ArchivoConfig1 ArchivoConfig2 .. ArchivoConfigN]
  [-userconfig MóduloCallback1 CadenaConfig1 y MóduloCallback2
   CadenaConfig2 y .. y MóduloCallbackN CadenaConfigN]
  [-decrypt_key Clave] | [-decrypt_file ArchivoClave]
  [-label Etiqueta]
  [-logdir DirectorioLog]
  [-logopts OpcionesLog]
  [-verbosity NivelVGen | [Categoría1 NivelV1 y
   Categoría2 NivelV2 y .. CategoríaN NivelVN]]
  [-allow_user_terms]
  [-silent_connections [TipoConexión1 TipoConexión2 .. TipoConexiónN]]
  [-stylesheet ArchivoCSS]
  [-cover ArchivoCfgCover]
  [-cover_stop Booleano]
  [-event_handler ManejadorEvento1 ManejadorEvento2 .. ManejadorEventoN] |
  [-event_handler_init ManejadorEvento1 ArgInicial1 y
   ManejadorEvento2 ArgInicial2 y .. ManejadorEventoN ArgInicialN]
  [-include DirectorioIncl1 DirectorioIncl2 .. DirectorioInclN]
  [-no_auto_compile]
  [-abort_if_missing_suites]
  [-multiply_timetraps Multiplicador]
  [-scale_timetraps]
  [-create_priv_dir auto_per_run | auto_per_tc | manual_per_tc]
  [-repeat N] |
  [-duration HHMMSS [-force_stop [skip_rest]]] |
  [-until [AAAAMM DD]HHMMSS [-force_stop [skip_rest]]]
  [-basic_html]
  [-no_esc_chars]
  [-keep_logs all | NLogs]
  [-ct_hooks MóduloCTH1 OpcionesCTH1 y MóduloCTH2 OpcionesCTH2 y ..
   MóduloCTHN OpcionesCTHN]
  [-ct_hooks_order test | config]
  [-exit_status ignore_config]

Actualizar archivos índice HTML

 ct_run -refresh_logs [-logdir DirectorioLog] [-basic_html]
  [-keep_logs all | NLogs]

Ejecutar Common Test en modo interactivo

 ct_run -shell
  [-config ArchivoConfig1 ArchivoConfig2 ... ArchivoConfigN]
  [-userconfig MóduloCallback1 CadenaConfig1 y MóduloCallback2
   CadenaConfig2 y .. y MóduloCallbackN CadenaConfigN]
  [-decrypt_key Clave] | [-decrypt_file ArchivoClave]

Iniciar un nodo maestro de Common Test

 ct_run -ctmaster
