Almacenamiento de

anotaciones

Al igual que el analizador de Python almacena las decoraciones en el campo decorations, el analizador de GDScript almacena las anotaciones que comienzan con @ en el campo específico del lenguaje, annotations. Aunque el campo se activa explícitamente en los siguientes ejemplos, el campo está activado por

defecto.

"input.

gd" 
@export
var s =
"Hello" @master
func f(msg):
print(msg)

"output.tags" con "--options=NONE --sort=no --fields-GDScript=+{annotations} -o - input.

gd" 
s       input.gd        /^var
s = "Hello"$/;" v anno
tations:export f input.
gd /^func f(msg):$/;"
m annotations:master

Extracción de

func

Un objeto de lenguaje definido con la palabra clave func se etiqueta con el tipo method. Al igual que con las anotaciones, el analizador almacena las palabras clave que modifican func, como static, en el campo annotations

.

"input.

gd" 
func f(x):
        return
x static func f_s(x):
reutrn x remote func
f_r(x): return x

"output.tags" con "--options=NONE --sort=no --fields=+K --fields-GDScript=+{annotations} -o - input.

gd" 
f       input.gd        /^func f(x):$/;"
method f_s input.gd /^static
func f_s(x):$/;" method annotations:s
tatic f_r input.gd /^remote func
f_r(x):$/;" method annotations:remote

Etiquetado de clases definidas

implícitamente

"¡Un archivo es una clase!" en GDScript. Una clase se define implícitamente. Las funciones, variables, constantes y señales son partes de la clase, aunque la clase no tiene nombre por

defecto.

Si el extra específico del lenguaje, implicitClass, está activado, el analizador crea una etiqueta anónima para la clase. El analizador rellena los campos de ámbito de las etiquetas de todos los objetos de lenguaje definidos en el archivo con la etiqueta

anónima.

Veamos un ejemplo que demuestra el efecto del

extra.

Desactivando el

extra:

"input.

gd" 
func f(
x):
r
eturn x

"output.tags" con "--options=NONE --fields=+KZ --extras-GDScript=-{implicitClass} -o - input.

gd"

gd /^f
unc f(x):$/;"
method

Activando el

extra:

"input.

x):

Etiquetado del nombre especificado con

class_name

class_name es una palabra clave para dar un nombre a la clase definida implícitamente. Si implicitClass está desactivado, el analizador solo extrae el nombre que viene después de la palabra clave con el tipo class. Si implicitClass está activado, el analizador convierte la etiqueta anónima en una etiqueta no anónima con el nombre especificado. Al convertir, el analizador también actualiza los campos de ámbito de las otras etiquetas en el

archivo.

Desactivando el

extra:

"input.

gd" 
class_name
c func f(
x):
return x

"output.tags" con "--options=NONE --fields=+KZ --extras-GDScript=-{implicitClass} -o - input.

gd" 
c       input.gd        /^c
lass_name c$/;" class
f input.gd /^f
unc f(x):$/;" method

Activando el

extra:

"input.

gd" 
class_name
C func g(
x):
return x

"output.tags" con "--options=NONE --fields=+KZ --extras-GDScript=+{implicitClass} -o - input.

gd" 
C       input.gd        /
^class_name C$/;" c
lass g input.gd
/^func g(x):$/;"
method scope:class:C

Relleno del campo

inherits

La palabra clave extends especifica la superclase para la clase definida implícitamente. Si el extra implicitClass está activado, el analizador rellena el campo inherits de la etiqueta para la clase definida implícitamente con el nombre de la

superclase.

"input.

gd" 
extend
s B c
lass_
name C

gd"

ame C$/;" cl
ass inherits:B

.
