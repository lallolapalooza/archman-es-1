Nombre

ctags-lang-sql - La página del manual del analizador SQL para Universal Ctags

SINOPSIS

ctags ... [--extras={guest}] --languages=+SQL ...

DESCRIPCIÓN

El analizador SQL soporta varios dialectos SQL. PostgreSQL es uno de ellos.

PostgreSQL permite que las funciones definidas por el usuario se escriban en otros lenguajes (lenguajes procedimentales) además de SQL y C [PL].

El analizador SQL crea etiquetas para objetos de lenguaje en las funciones definidas por el usuario escritas en los lenguajes procedimentales si la extensión guest está habilitada.

El analizador SQL busca un token que siga a la palabra clave LANGUAGE en el código fuente para elegir un analizador huésped adecuado.

... LANGUAGE plpythonu AS '... user-defined function ' ...
... AS $$ user-defined function $$ LANGUAGE plv8 ...

En los ejemplos anteriores, plpythonu y plv8 son los nombres de lenguajes procedimentales. El analizador SQL elimina pl al principio y u al final del nombre antes de encontrar un analizador ctags. Para plpythonu y plv8, el analizador SQL extrae python y v8 como candidatos de analizadores huéspedes.

Para plpythonu, ctags puede ejecutar su analizador Python. ctags no tiene un analizador llamado v8. Sin embargo, el analizador de JavaScript en ctags tiene v8 como un alias. Por lo tanto, ctags puede ejecutar el analizador de JavaScript como el analizador huésped para plv8.

EJEMPLOS

Etiquetado de código que incluye una función definida por el usuario en un literal de cadena [GH3006]:

"input.sql"

CREATE OR REPLACE FUNCTION fun1() RETURNS VARCHAR AS '
DECLARE
        test1_var1 VARCHAR(64) := $$ABC$$;
        test1_var2 VARCHAR(64) := $xyz$XYZ$xyz$;
        test1_var3     INTEGER := 1;
BEGIN
        RETURN  TO_CHAR(test_var3, ''000'') || test1_var1 || test1_var2;
END;
' LANGUAGE plpgsql;

"output.tags" con "--options=NONE -o - --sort=no --extras=+{guest} input.sql"

fun1    input.sql       /^CREATE OR REPLACE FUNCTION fun1() RETURNS VARCHAR AS '$/;"    f       typeref:typename:VARCHAR
test1_var1      input.sql       /^      test1_var1 VARCHAR(64) := $$ABC$$;$/;"  v
test1_var2      input.sql       /^      test1_var2 VARCHAR(64) := $xyz$XYZ$xyz$;$/;"    v
test1_var3      input.sql       /^      test1_var3     INTEGER := 1;$/;"        v

Etiquetado de código que incluye una función definida por el usuario en una comilla de dólar [GH3006]:

"input.sql"

CREATE OR REPLACE FUNCTION fun2() RETURNS VARCHAR LANGUAGE plpgsql AS $$
DECLARE
        test2_var1 VARCHAR(64) := 'ABC2';
        test2_var2 VARCHAR(64) := 'XYZ2';
        test2_var3        INTEGER := 2;
BEGIN
        RETURN  TO_CHAR(test2_var3, '000') || test2_var1 || test2_var2;
END;
$$;

"output.tags" con "--options=NONE -o - --sort=no --extras=+{guest} input.sql"

fun2    input.sql       /^CREATE OR REPLACE FUNCTION fun2() RETURNS VARCHAR LANGUAGE plpgsql AS $\$$/;" f       typeref:typename:VARCHAR
test2_var1      input.sql       /^      test2_var1 VARCHAR(64) := 'ABC2';$/;"   v
test2_var2      input.sql       /^      test2_var2 VARCHAR(64) := 'XYZ2';$/;"   v
test2_var3      input.sql       /^      test2_var3        INTEGER := 2;$/;"     v

Etiquetado de código que incluye una función definida por el usuario escrita en JavaScript:

-- Derived from https://github.com/plv8/plv8/blob/r3.0alpha/sql/plv8.sql
CREATE FUNCTION test(keys text[], vals text[]) RETURNS text AS
$$
        var o = {};
        for (var i = 0; i < keys.length; i++)
                o[keys[i]] = vals[i];
        return JSON.stringify(o);
$$
LANGUAGE plv8 IMMUTABLE STRICT;

"output.tags" con "--options=NONE -o - --sort=no --extras=+{guest} input.sql"

test    input.sql       /^CREATE FUNCTION test(keys text[], vals text[]) RETURNS text AS$/;"    f
o       input.sql       /^      var o = {};$/;" v

BUGS CONOCIDOS

Las secuencias de escape ('') en un literal de cadena pueden confundir al analizador huésped.
