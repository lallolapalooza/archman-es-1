Nombre

ctags-lang-elm - Notas aleatorias sobre el etiquetado de código fuente de Elm con Ctags Universal

SINOPSIS

ctags ... --languages=+Elm ...
ctags ... --language-force=Elm ...
ctags ... --map-Elm=+.elm ...

DESCRIPCIÓN

El analizador de Elm es un analizador PEG que utiliza PackCC, que forma parte de la infraestructura de ctags. Debería procesar correctamente todas las sentencias de nivel superior, sin embargo, existe una limitación con las funciones incrustadas en bloques let/in. En su mayor parte estarán bien, pero a veces se omitirá una función en un bloque let/in.

EJEMPLOS

Importaciones

Los módulos importados se etiquetan y su rol es "imported", no "def". Los tipos, funciones, etc. que se exponen a través de un módulo importado tienen su rol como "exposed".

Los elementos expuestos se marcan como si estuvieran en el ámbito de su propio módulo, no en el módulo que realiza la importación.

"input.elm"

module SomeMod exposing (..)
import MyMod exposing
  ( map
  , Maybe
  , Result(..)
  , MyList(Empty)
  )

"output.tags" con "--options=NONE -o - --sort=no --extras=+r --fields=+r input.elm"

SomeMod input.elm       /^module SomeMod exposing (..)$/;"      m       roles:def
MyMod   input.elm       /^import MyMod exposing$/;"     m       roles:imported
map     input.elm       /^  ( map$/;"   f       module:MyMod    roles:exposed
Maybe   input.elm       /^  , Maybe$/;" t       module:MyMod    roles:exposed
Result  input.elm       /^  , Result(..)$/;"    t       module:MyMod    roles:exposed
MyList  input.elm       /^  , MyList(Empty)$/;" t       module:MyMod    roles:exposed
Empty   input.elm       /^  , MyList(Empty)$/;" c       type:MyMod.MyList       roles:exposed

Espacios de nombres

Los espacios de nombres se etiquetan y su rol es "def".

"input.elm"

module AMod exposing (..)
import MyImport as NSpace exposing (impFunc)

"output.tags" con "--options=NONE -o - --sort=no --extras=+r --fields=+r input.elm"

AMod    input.elm       /^module AMod exposing (..)$/;" m       roles:def
NSpace  input.elm       /^import MyImport as NSpace exposing (impFunc)$/;"      n       module:AMod     roles:def       moduleName:MyImport
MyImport        input.elm       /^import MyImport as NSpace exposing (impFunc)$/;"      m       roles:imported
impFunc input.elm       /^import MyImport as NSpace exposing (impFunc)$/;"      f       module:MyImport roles:exposed

Nombres de tipos

Los constructores de funciones de nivel superior tendrán nombres de tipo.

"input.elm"

funcA : Int -> Int
funcA a = a + 1
type B
    = B1Cons
      { x : Float
      , y : Float
      }
    | B2Cons String Integer
    | B3Cons

"output.tags" con "--options=NONE -o - --sort=no --extras=+r --fields=+r input.elm"

funcA   input.elm       /^funcA a = a + 1$/;"   f       typeref:typename:Int -> Int     roles:def
B       input.elm       /^type B$/;"    t       roles:def
B1Cons  input.elm       /^    = B1Cons$/;"      c       type:B  typeref:typename:{ x : Float , y : Float } -> B roles:def
B2Cons  input.elm       /^    | B2Cons String Integer$/;"       c       type:B  typeref:typename:String -> Integer -> B roles:def
B3Cons  input.elm       /^    | B3Cons$/;"      c       type:B  typeref:typename:B      roles:def

Listas de parámetros de función

Las listas de parámetros de función se pueden extraer en el campo de firma del archivo de etiquetas. No son realmente firmas de función, pero es el concepto más cercano disponible en ctags. Usa "--fields=+S".

funcA a1 a2 =
    a1 + a2

"output.tags" con "--sort=no --extras=+r --fields=+rS"

funcA       input.elm       /^funcA a1 a2 =$/;"     f       signature:a1 a2 roles:def

LIMITACIONES CONOCIDAS

El campo de firma de ctags se utiliza para las listas de parámetros de función, aunque no sea un campo ideal. Ver arriba.

Elm requiere que todas las sentencias del mismo nivel lógico tengan la misma indentación. Si hay indentación adicional, esa línea forma parte de la anterior. Por lo tanto, sin complicar demasiado el analizador PEG, tenemos las siguientes limitaciones...

A veces se omitirán las funciones en bloques let/in.

Las funciones en bloques let/in se marcarán como si estuvieran en el ámbito de su función externa, independientemente de la profundidad del bloque let/in.

Las funciones en bloques let/in no tendrán nombres de tipo.
