NOMBRE

ctwill, ctwill-refsort, ctwill-twinx - traduce CWEB a TeX con mini-índices

SINOPSIS

ctwill [opciones] archivo_web[.w] [{archivo_de_cambios[.ch]|-} [archivo_de_salida[.tex]]]

ctwill-refsort < archivo_de_índice.ref > archivo_de_índice.sref

ctwill-twinx archivo_de_salida.tex [archivo_de_salida.tex ...] > index.tex

DESCRIPCIÓN

El ctwill programa convierte un documento fuente CWEB en un archivo TeX que puede ser formateado e impreso de la manera habitual. Se encarga adecuadamente de los detalles tipográficos como la disposición de la página y el uso de la sangría, cursiva, negrita, etc., y proporciona una extensa información de índice cruzado que recopila automáticamente.

CWEB le permite preparar un único documento que contenga toda la información necesaria tanto para producir un programa C/C++ compilable como para producir un documento bien formateado que describa el programa con todo el detalle que el escritor desee. El usuario de CWEB debería estar familiarizado tanto con TeX como con C/C++.

USO

La línea de comandos debe tener uno, dos o tres nombres. El primero se toma como el archivo de entrada CWEB (y se .w agrega si no hay extensión). Si hay un segundo nombre, es un archivo de cambios (y se .ch agrega si no hay extensión). El archivo de cambios anula partes del archivo CWEB, como se describe en la documentación. Si hay un tercer nombre, anula el nombre por defecto del archivo de salida, que ordinariamente es el mismo que el nombre del archivo de entrada (pero en el directorio actual) con la extensión .tex. Si solo desea cambiar el nombre del archivo de salida, pero no tiene un archivo de cambios para aplicar, puede usar `-' como el segundo argumento.

ctwill es exactamente igual que cweave excepto que produce mucha mejor documentación, para lo cual debe trabajar mucho más duro. Debería ejecutar ctwill dos veces, una para arrancar el motor y otra para obtener respuestas decentes. Además, debe ejecutar la salida dos veces a través de TeX.

Después de tex foo tendrá una salida que se parece a páginas finales excepto que las entradas de los mini-índices no estarán ordenadas alfabéticamente. La primera ejecución produce un archivo extraño llamado foo.ref. Digamos ctwill-refsort < foo.ref > foo.sref y luego otra tex foo producirá una salida ordenada alfabéticamente.

El ctwill-twinx programa compila un índice maestro para un conjunto de programas relacionados que han sido procesados por ctwill (no por cweave, ¡tenga cuidado!). Los programas individuales deben definir sus nombres con una línea de la forma \def\title{NOMBRE}. Para su conveniencia, ctwill-twinx toma la primera "palabra" en \title y la convierte en forma de mayúsculas. Debería adaptar el archivo twinx-startup.tex para la primera página del índice maestro.

Los mini-índices listan identificadores que se usan pero no se definen en cada doble página. Al final de cada sección, ctwill le da a TeX una lista de identificadores usados en esa sección e información sobre dónde están definidos.

El significado actual de cada identificador es inicialmente \uninitialized. Luego ctwill lee el .aux archivo para su trabajo, si existe.

Antes de leer el .aux archivo, ctwill realmente busca un archivo llamado system.bux, que se leerá si está presente. Y después de foo.aux, una tercera posibilidad es foo.bux. La convención general es poner definiciones de procedimientos del sistema como printf en system.bux, y poner definiciones encontradas en archivos de cabecera específicos de foo en foo.bux. Al igual que los .aux archivos, .bux archivos deben contener solo @$ especificaciones.

El significado especificado por @$...@> generalmente tiene cuatro componentes: un identificador (seguido de espacio), un nombre de programa (encerrado en llaves), un número de sección (seguido de espacio), y una parte TeX.

Un modo especial proofmode se proporciona para que pueda verificar ctwill's conclusiones sobre referencias cruzadas. Ejecute ctwill con el indicador +P, y TeX producirá un documento especialmente formateado (sin mini-índices) en el que puede verificar que sus especificaciones son correctas.

Más detalles sobre cómo usar ctwill se pueden encontrar en las primeras secciones de su código fuente, respectivamente el archivo de cambios cweav-twill.ch aplicable al cweave.w fuente. Un ejemplo completo con todos los detalles se describe en Mini-Indexes for Literate Programs, páginas 225–245 de Knuth's Digital Typography.

DIFERENCIAS CON EL CTWILL ORIGINAL

La presente encarnación de ctwill y sus utilidades intenta ser un reemplazo directo del paquete original. Sin embargo, hay algunas diferencias que vale la pena notar:

•
Esta versión está basada en la versión más reciente de CWEB (4.8).
•
En TeX Live los programas de utilidades tienen el prefijo ctwill- y los archivos de macros con ct por razones técnicas.
•
Opciones --help, --quiet, --verbose, --version, e indicadores +c, -i, -oy +lX son nuevos en CWEBbin y TeX Live.
•
Opción +lX va acompañada de archivos de envoltura de ejemplo para ctwimac.tex y ctproofmac.tex con títulos traducidos para alemán (+ld).
•
Opción +lX también va acompañada de un pdfctwimac.tex extendido para la producción de salida PDF con hipervínculos activos (+lpdf).
•
ctwill en TeX Live opera silenciosamente por defecto; use la --verbose opción para obtener el comportamiento original.
•
La búsqueda de archivos con la variable de entorno CWEBINPUTS está extendida para permitir varios rutas separadas por dos puntos; véase ENTORNO más abajo.
•
Si está correctamente configurado, el programa principal ctwill está localizado con las "utilidades GNU gettext".

OPCIONES

Las opciones en la línea de comandos pueden ser desactivadas con `-' (si están activadas por defecto) o activadas con `+' (si están desactivadas por defecto). De hecho, las opciones se procesan de izquierda a derecha, así que una secuencia como --verbose -h solo mostrará la línea de banner (+b) y el informe de progreso (+p), pero omitirá el mensaje de éxito (-h).

•
+b: imprimir línea de banner en la terminal
•
+h: imprimir mensaje de éxito al completar
•
+p: imprimir mensajes de informe de progreso
•
+q/-q: atajo para -bhp; también --quiet (por defecto)
•
+v/-v: atajo para +bhp; también --verbose
•
+c: verificar si la salida temporal ha cambiado
•
-e: no encerrar material C/C++ en \PB{...}
•
-f: no forzar un salto de línea después de cada sentencia C/C++ en la salida
•
-i: suprimir la sangría de declaraciones de parámetros
•
-o: suprimir la separación de declaraciones y sentencias
•
-x: omitir índices, nombres de secciones, tabla de contenidos
•
+P: \input ctproofmac.tex en lugar de ctwimac.tex
•
+lX/-lX: usar macros para el lenguaje X tal como X{ctwimac|ctproofmac}.tex
•
+s: imprimir estadísticas de uso
•
+t: tratar nombre_de_tipo en una plantilla como typedef
•
--help: mostrar mensaje de ayuda y salir
•
--version: mostrar información de versión y salir

ENTORNO

La variable de entorno CWEBINPUTS se usa para buscar los archivos de entrada, o el valor por defecto del sistema si CWEBINPUTS no está definido. Vea tex(1) para los detalles de la búsqueda. Para evitar conflictos con otros programas que también usan el entorno CWEBINPUTS, puede ser más específico y usar CWEBINPUTS_cweb para requisitos especiales en CWEB.

NAME

ctwill

-- TeX/LaTeX document preparation system

SYNOPSIS

ctwill

‐?
ctwill [‐h | ‐?] [‐v] [‐V] [‐w] [‐l name] [‐p name] [‐o file] [‐k] [‐S] [‐f] [‐n] [‐t] [‐m] [‐d] [‐c] [‐r] [‐u] [‐L] [‐U] [‐H] [‐D] [‐C] [‐T] [‐R] [‐E] [‐B] [‐A] [‐M] [‐W] [‐i index] [‐N string] [‐q] [‐g] [‐z] [‐?]
ctwill [‐h] [‐?] [‐v] [‐V] [‐w] [‐l name] [‐p name] [‐o file] [‐k] [‐S] [‐f] [‐n] [‐t] [‐m] [‐d] [‐c] [‐r] [‐u] [‐L] [‐U] [‐H] [‐D] [‐C] [‐T] [‐R] [‐E] [‐B] [‐A] [‐M] [‐W] [‐i index] [‐N string] [‐q] [‐g] [‐z] [‐?] [webfile]

DESCRIPTION

The CWEB system is a combination of ctangle(1) and cweave(1). It supports C programs and TeX/LaTeX documents. The program ctwill(1) combines the functionality of ctangle(1) and cweave(1).

It processes a CWEB source file and produces a C source file and a TeX/LaTeX file. The C source file is produced by ctangle(1) and the TeX/LaTeX file is produced by cweave(1).

The CWEB source file contains interspersed C code and TeX documentation. The TeX documentation is typeset by cweave(1), and the C code is extracted by ctangle(1).

This version of CWEB is part of the Web2c TeX distribution.

USAGE

The basic usage is:

ctwill webfile

This will produce two files: webfile.c (C source code) and webfile.tex (TeX source code for documentation).

If you want to produce a LaTeX document, use the -L option:

ctwill ‐L webfile

This will produce webfile.c and webfile.ltx.

The ctwill program provides options to control the output of both ctangle(1) and cweave(1). The options are passed to the respective tools.

DIFFERENCES TO ORIGINAL CTWILL

This version of ctwill is a wrapper around the original ctangle(1) and cweave(1) programs, providing a unified interface. The original ctwill was a single program that performed both tangling and weaving.

The Web2c version of ctwill is integrated with the Web2c TeX distribution and uses its configuration files.

OPTIONS

The following options are available:

‐h, ‐?
Display a help message and exit.
‐v
Print the version information and exit.
‐V
Print the version information of CWEB and exit.
‐w
Switch to the original CWEB program. This is not typically used with ctwill.
‐l name
Set the language prefix. This is passed to cweave(1). For example, ‐lpdf tells cweave(1) to use the pdfctwimac.tex file.
‐p name
Set the proof prefix. This is passed to cweave(1). For example, ‐pD tells cweave(1) to use the dprooftwillmac.tex file.
‐o file
Specify the output file name. This is passed to both ctangle(1) and cweave(1). If not specified, the output file names are derived from the input file name (e.g., .c and .tex).
‐k
Keep intermediate files. This is passed to ctangle(1).
‐S
Produce a change file. This is passed to ctangle(1).
‐f
Expand macros. This is passed to ctangle(1).
‐n
Don't produce output. This is passed to ctangle(1).
‐t
Create a table of contents. This is passed to cweave(1).
‐m
Produce module documentation. This is passed to cweave(1).
‐d
Produce cross-references. This is passed to cweave(1).
‐c
Output C code comments. This is passed to cweave(1).
‐r
Produce raw TeX output. This is passed to cweave(1).
‐u
Use underline for section headings. This is passed to cweave(1).
‐L
Use LaTeX output. This is passed to cweave(1).
‐U
Use underline for chapter headings. This is passed to cweave(1).
‐H
Produce C header file. This is passed to ctangle(1).
‐D
Use C preprocessor defines. This is passed to ctangle(1).
‐C
Use C style comments. This is passed to ctangle(1).
‐T
Use TeX style comments. This is passed to ctangle(1).
‐R
Create raw output. This is passed to ctangle(1).
‐E
Expand macros. This is passed to ctangle(1).
‐B
Begin output. This is passed to ctangle(1).
‐A
Append output. This is passed to ctangle(1).
‐M
Produce module documentation. This is passed to ctangle(1).
‐W
Produce documentation. This is passed to ctangle(1).
‐i index
Create an index file. This is passed to ctangle(1).
‐N string
Set the name for the next section. This is passed to cweave(1).
‐q
Quiet mode. Suppress informational messages. This is passed to cweave(1).
‐g
Generate a grammar file. This is passed to ctangle(1).
‐z
Generate a zip file. This is passed to ctangle(1).

All options not starting with a dash are treated as CWEB source files. If no files are specified, the standard input is used.

ENVIRONMENT

The ctwill utility, like ctangle(1) and cweave(1), uses the environment variable TEXMFLOCALEDIR to configure the parent directory where the "GNU gettext utilities" search for translation catalogs.

These variables are preconfigured in TeX Live’s texmf.cnf.

FILES

The location of the files mentioned below varies from system to system. Use the kpsewhich utility to find their locations.

•
ctwimac.tex: The default TeX macros \input in the first line of the output file.
•
ctproofmac.tex: If ctwill is invoked with the +P option, it will change the first line of the output file to \input ctproofmac.tex.

In both cases you can request some prefix X with the +lX option, e.g., +ld will \input dctwimac.tex and +Pld will \input dctproofmac.tex. A special application is the use of option +lpdf that will \input pdfctwimac.tex for production of PDF output with active hyperlinks.

•
webfile.bux: Reference definitions to resolve from other modules.
•
system.bux: Reference definitions to resolve from C/C++ standard library header files like <stdio.h>.

Other auxiliary files with references are created automatically by ctwill and the actual index files are created by TeX.

•
cwebman.tex: The CWEB user manual, available in PDF from CTAN (https://ctan.org/pkg/cweb).
