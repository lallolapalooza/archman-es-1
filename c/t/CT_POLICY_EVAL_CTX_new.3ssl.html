CT_POLICY_EVAL_CTX_new(3ssl)

Paquete: openssl

Licencias: Apache-2.0

CT_POLICY_EVAL_CTX_NEW(3ssl) OpenSSL CT_POLICY_EVAL_CTX_NEW(3ssl)

NOMBRE

CT_POLICY_EVAL_CTX_new_ex, CT_POLICY_EVAL_CTX_new, CT_POLICY_EVAL_CTX_free, CT_POLICY_EVAL_CTX_get0_cert, CT_POLICY_EVAL_CTX_set1_cert, CT_POLICY_EVAL_CTX_get0_issuer, CT_POLICY_EVAL_CTX_set1_issuer, CT_POLICY_EVAL_CTX_get0_log_store, CT_POLICY_EVAL_CTX_set_shared_CTLOG_STORE, CT_POLICY_EVAL_CTX_get_time, CT_POLICY_EVAL_CTX_set_time - Encapsula los datos necesarios para evaluar si los SCT cumplen con una política de Certificate Transparency

SINOPSIS

#include <openssl/ct.h>
CT_POLICY_EVAL_CTX *CT_POLICY_EVAL_CTX_new_ex(OSSL_LIB_CTX *libctx,
                                              const char *propq);
CT_POLICY_EVAL_CTX *CT_POLICY_EVAL_CTX_new(void);
void CT_POLICY_EVAL_CTX_free(CT_POLICY_EVAL_CTX *ctx);
X509* CT_POLICY_EVAL_CTX_get0_cert(const CT_POLICY_EVAL_CTX *ctx);
int CT_POLICY_EVAL_CTX_set1_cert(CT_POLICY_EVAL_CTX *ctx, X509 *cert);
X509* CT_POLICY_EVAL_CTX_get0_issuer(const CT_POLICY_EVAL_CTX *ctx);
int CT_POLICY_EVAL_CTX_set1_issuer(CT_POLICY_EVAL_CTX *ctx, X509 *issuer);
const CTLOG_STORE *CT_POLICY_EVAL_CTX_get0_log_store(const CT_POLICY_EVAL_CTX *ctx);
void CT_POLICY_EVAL_CTX_set_shared_CTLOG_STORE(CT_POLICY_EVAL_CTX *ctx,
                                               CTLOG_STORE *log_store);
uint64_t CT_POLICY_EVAL_CTX_get_time(const CT_POLICY_EVAL_CTX *ctx);
void CT_POLICY_EVAL_CTX_set_time(CT_POLICY_EVAL_CTX *ctx, uint64_t time_in_ms);

DESCRIPCIÓN

Un CT_POLICY_EVAL_CTX es utilizado por funciones que evalúan si los Certificados de Tiempo Firmados (SCTs) cumplen con una política de Transparencia de Certificados (CT). Esta política puede ser, por ejemplo, que esté disponible al menos un SCT válido. Para determinar esto, la firma y la marca de tiempo de un SCT deben ser verificadas. Esto requiere:

  • la clave pública del log que emitió el SCT
  • el certificado para el cual se emitió el SCT
  • el certificado del emisor (si el SCT se emitió para un pre-certificado)
  • la hora actual

Los requisitos anteriores se cumplen utilizando los establecedores descritos a continuación.

CT_POLICY_EVAL_CTX_new_ex() crea un contexto de evaluación de política vacío y lo asocia con el contexto de biblioteca dado libctx y la cadena de consulta de propiedades propq.

CT_POLICY_EVAL_CTX_new() hace lo mismo que CT_POLICY_EVAL_CTX_new_ex() excepto que utiliza el contexto de biblioteca predeterminado y la cadena de consulta de propiedades.

El CT_POLICY_EVAL_CTX debe ser poblado utilizando:

  • CT_POLICY_EVAL_CTX_set1_cert() para proporcionar el certificado para el cual se emitieron los SCTs.

    Incrementa el contador de referencias del certificado.

  • CT_POLICY_EVAL_CTX_set1_issuer() para proporcionar el certificado del emisor.

    Incrementa el contador de referencias del certificado.

  • CT_POLICY_EVAL_CTX_set_shared_CTLOG_STORE() para proporcionar una lista de logs que son confiables como fuentes de SCTs.

    Mantiene un puntero a CTLOG_STORE, por lo que CTLOG_STORE debe sobrevivir a CT_POLICY_EVAL_CTX.

  • CT_POLICY_EVAL_CTX_set_time() para establecer la hora con la que se deben comparar los SCTs para determinar si son válidos.

    La marca de tiempo del SCT se comparará con esta hora para verificar si el SCT fue emitido en el futuro. RFC6962 establece que "los clientes TLS DEBEN rechazar SCTs cuya marca de tiempo esté en el futuro". Por defecto, se establecerá en 5 minutos en el futuro (por ejemplo, (time() + 300) * 1000), para permitir la deriva del reloj.

    La hora debe estar en milisegundos desde la Época Unix.

Cada establecedor tiene un capturador correspondiente para acceder al valor actual.

Cuando ya no sea necesario, se debe pasar CT_POLICY_EVAL_CTX_free() a CT_POLICY_EVAL_CTX_free() para eliminarlo. Si el argumento para CT_POLICY_EVAL_CTX_free() es NULL, no se hace nada.

NOTAS

Solo es necesario proporcionar el certificado del emisor si al menos uno de los SCTs fue emitido para un pre-certificado. Este será el caso de los SCTs incrustados en un certificado (es decir, los de una extensión X.509), pero puede que no sea el caso de los SCTs encontrados en la extensión SCT de TLS o en una respuesta OCSP.

VALORES DE RETORNO

CT_POLICY_EVAL_CTX_new_ex() y CT_POLICY_EVAL_CTX_new() devolverán NULL si malloc falla.
