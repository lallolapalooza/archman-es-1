DESCRIPCIÓ

N

Las funciones ctime(), gmtime() y localtime() toman todas un argumento de tipo de datos time_t, que representa tiempo de calendario. Cuando se interpreta como un valor de tiempo absoluto, representa el número de segundos transcurridos desde la Época, 1970-01-01 00:00:00 +0000 (UTC)

.

Las funciones asctime() y mktime() toman ambas un argumento que representa tiempo desglosado, que es una representación separada en año, mes, día,

etc.

El tiempo desglosado se almacena en la estructura tm, descrita en tm(3typ

e).

La llamada ctime(t) es equivalente a asctime(localtime(t)). Convierte el tiempo de calendario t en una cadena terminada en nulo de la

forma 


"Wed Jun 30 21:49:08
1993\n"

Las abreviaturas de los días de la semana son "Sun", "Mon", "Tue", "Wed", "Thu", "Fri" y "Sat". Las abreviaturas de los meses son "Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov" y "Dec". El valor de retorno apunta a una cadena asignada estáticamente que podría ser sobrescrita por llamadas posteriores a cualquiera de las funciones de fecha y hora. La función también establece las variables externas tzname, timezone y daylight como si llamara a tzset(3). La versión reentrante ctime_r() hace lo mismo, pero almacena la cadena en un búfer proporcionado por el usuario que debe tener espacio para al menos 26 bytes. No necesita establecer tzname, timezone y daylight

.

La función gmtime() convierte el tiempo de calendario timep a representación de tiempo desglosado, expresado en Hora Universal Coordinada (UTC). Puede devolver NULL cuando el año no cabe en un entero. El valor de retorno apunta a una estructura asignada estáticamente que podría ser sobrescrita por llamadas posteriores a cualquiera de las funciones de fecha y hora. La función gmtime_r() hace lo mismo, pero almacena los datos en una estructura proporcionada por el

usuario.

La función localtime() convierte el tiempo de calendario timep a representación de tiempo desglosado, expresado en relación con la zona horaria especificada por el usuario. La función también establece las variables externas tzname, timezone y daylight como si llamara a tzset(3). El valor de retorno apunta a una estructura asignada estáticamente que podría ser sobrescrita por llamadas posteriores a cualquiera de las funciones de fecha y hora. La función localtime_r() hace lo mismo, pero almacena los datos en una estructura proporcionada por el usuario. No necesita establecer tzname, timezone y daylight

.

La función asctime() convierte el valor de tiempo desglosado tm en una cadena terminada en nulo con el mismo formato que ctime(). El valor de retorno apunta a una cadena asignada estáticamente que podría ser sobrescrita por llamadas posteriores a cualquiera de las funciones de fecha y hora. La función asctime_r() hace lo mismo, pero almacena la cadena en un búfer proporcionado por el usuario que debe tener espacio para al menos 26

bytes.

La función mktime() convierte una estructura de tiempo desglosado, expresada como hora local, a representación de tiempo de calendario. La función ignora los valores proporcionados por el llamador en los campos tm_wday y tm_yday. El valor especificado en el campo tm_isdst informa a mktime() si el horario de verano (DST) está o no en efecto para el tiempo proporcionado en la estructura tm: un valor positivo significa que el DST está en efecto; cero significa que el DST no está en efecto; y un valor negativo significa que mktime() debe (usar información de zona horaria y bases de datos del sistema para) intentar determinar si el DST está en efecto en el tiempo especificado. Ver timegm(3) para un equivalente UTC de esta

función.

La función mktime() modifica los campos de la estructura tm de la siguiente manera: tm_wday y tm_yday se establecen a valores determinados a partir del contenido de los otros campos; si los miembros de la estructura están fuera de su intervalo válido, serán normalizados (de modo que, por ejemplo, 40 de octubre se cambia a 9 de noviembre); tm_isdst se establece (independientemente de su valor inicial) a un valor positivo o a 0, respectivamente, para indicar si el DST está o no en efecto en el tiempo especificado. La función también establece las variables externas tzname, timezone y daylight como si llamara a tzset(

3).

Si el tiempo desglosado especificado no puede ser representado como tiempo de calendario (segundos desde la Época), mktime() devuelve (time_t) -1 y no altera los miembros de

la estructura de
tiempo desglosado.

NAME

mktime - convert a broken-down time structure to a time value

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <time.h>

time_t mktime(struct tm *tm);

DESCRIPTION

The mktime() function converts the broken-down time represented by the structure pointed to by tm into a time_t value, which represents the number of seconds since the Epoch (00:00:00 UTC, January 1, 1970).

The structure tm must be filled with the desired components of the time, except for tm_wday and tm_yday, which are ignored, and tm_isdst. The value of tm_isdst is used to indicate whether DST is in effect. If tm_isdst is positive, DST is in effect. If it is zero, DST is not in effect. If it is negative, the code is allowed to, and should, figure out whether DST is in effect for the specified time.

After successfully calling mktime(), the fields tm_wday and tm_yday are set to the correct values, and tm_isdst is set to a positive value if DST is in effect, or 0 if it is not. If the system does not support DST, tm_isdst is set to 0.

The values of tm_sec, tm_min, tm_hour, tm_mday, and tm_mon can be outside their normal ranges and are normalized by the function. For example, if tm_mon is 13, it represents January of the next year. If tm_mday is 32, it represents the 1st of the next month. These values are processed correctly. The tm_year field should be the number of years since 1900.

The mktime() function uses the current setting of the TZ environment variable to determine the correct time zone and DST rules. If TZ is not set, the system's default time zone and DST rules are used.

The mktime() function is thread-safe only when used with glibc's default configuration. For thread-safe usage with other systems, use the reentrant functions localtime_r() and gmtime_r().

The `restrict` keyword is not specified by POSIX for ctime_r(); it is specific to glibc.

In many implementations, including glibc, a 0 in tm_mday is interpreted as meaning the last day of the preceding month.

According to POSIX.1, localtime() is required to behave as though tzset(3) was called, while localtime_r() does not have this requirement. For portable code, tzset(3) should be called before localtime_r().

CAVEATS

Thread safety

The four functions asctime(), ctime(), gmtime(), and localtime() return a pointer to static data and hence are not thread-safe. The thread-safe versions, asctime_r(), ctime_r(), gmtime_r(), and localtime_r(), are specified by SUSv2.

POSIX.1 says: "The asctime(), ctime(), gmtime(), and localtime() functions shall return values in one of two static objects: a broken-down time structure and an array of type char. Execution of any of the functions that return a pointer to one of these object types may overwrite the information in any object of the same type pointed to by the value returned from any previous call to any of them." This can occur in the glibc implementation.

mktime()

(time_t) -1 can represent a valid time (one second before the Epoch). To determine whether mktime() failed, one must use the tm->tm_wday field. See the example program in EXAMPLES.

The handling of a non-negative tm_isdst in mktime() is poorly specified, and passing a value that is incorrect for the time specified yields unspecified results. Since mktime() is one of the few functions that knows when DST is in effect, providing a correct value may be difficult. One workaround for this is to call mktime() twice, once with tm_isdst set to zero, and once with tm_isdst set to a positive value, and discarding the results from the call that changes it. If neither call changes tm_isdst then the time specified probably happens during a fall-back period where DST begins or ends, and both results are valid but represent two different times. If both calls change it, that could indicate a fall-forward transition, or some other reason why the time specified does not exist.

The specification of time zones and daylight saving time are up to regional governments, change often, and may include discontinuities beyond mktime's ability to document a result. For example, a change in the timezone definition may cause a clock time to be repeated or skipped without a corresponding DST change.

Program source: mktime.c

#include <err.h>
#include <errno.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#define is_signed(T)  ((T) -1 < 1)
static time_t my_mktime(struct tm *tp);
int
main(int argc, char *argv[])
{
    char       **p;
    time_t     t;
    struct tm  tm;
    if (argc != 8) {
        fprintf(stderr, "Usage: %s yyyy mm dd HH MM SS isdst\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    p = &argv[1];
    tm.tm_year  = atoi(*p++) - 1900;
    tm.tm_mon   = atoi(*p++) - 1;
    tm.tm_mday  = atoi(*p++);
    tm.tm_hour  = atoi(*p++);
    tm.tm_min   = atoi(*p++);
    tm.tm_sec   = atoi(*p++);
    tm.tm_isdst = atoi(*p++);
    errno = 0;
    tm.tm_wday = -1;
    t = my_mktime(&tm);
    if (tm.tm_wday == -1)
        err(EXIT_FAILURE, "mktime");
    if (errno == EINVAL || errno == ENOTUNIQ)
        warn("my_mktime");
    if (is_signed(time_t))
        printf("%jd\n", (intmax_t) t);
    else
        printf("%ju\n", (uintmax_t) t);
    exit(EXIT_SUCCESS);
}
static time_t
my_mktime(struct tm *tp)
{
    int            e, isdst;
    time_t         t;
    struct tm      tm;
    unsigned char  wday[sizeof(tp->tm_wday)];
    e = errno;
    tm = *tp;
    isdst = tp->tm_isdst;
    memcpy(wday, &tp->tm_wday, sizeof(wday));
    tp->tm_wday = -1;
    t = mktime(tp);
    if (tp->tm_wday == -1) {
        memcpy(&tp->tm_wday, wday, sizeof(wday));
        return -1;
    }
    if (isdst == -1)
        tm.tm_isdst = tp->tm_isdst;
    if (   tm.tm_sec   != tp->tm_sec
        || tm.tm_min   != tp->tm_min
        || tm.tm_hour  != tp->tm_hour
        || tm.tm_mday  != tp->tm_mday
        || tm.tm_mon   != tp->tm_mon
        || tm.tm_year  != tp->tm_year
        || tm.tm_isdst != tp->tm_isdst)
    {
        errno = EINVAL;
        return t;
    }
    if (isdst != -1)
        goto out;
    tm = *tp;
    tm.tm_isdst = !tm.tm_isdst;
    tm.tm_wday = -1;
    mktime(&tm);
    if (tm.tm_wday == -1)
        goto out;
    if (tm.tm_isdst != tp->tm_isdst) {
        errno = ENOTUNIQ;
        return t;
    }
out:
    errno = e;
    return t;
}
