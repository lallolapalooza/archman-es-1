Nombre

ctags-json-output - Salida JSON de ctags

SINÓPSIS

ctags --output-format=json ...

DESCRIPCIÓN

Universal Ctags soporta el formato de salida JSON https://www.json.org/ (estrictamente hablando, JSON Lines https://jsonlines.org/) si el ejecutable ctags está compilado con libjansson. La salida JSON se dirige a la salida estándar por defecto.

FORMATO

Cada línea JSON representa una etiqueta.

$ ctags --extras=+p --output-format=json --fields=-s input.py
{"_type": "ptag", "name": "JSON_OUTPUT_VERSION", "path": "1.0", "pattern": "in development"}
{"_type": "ptag", "name": "TAG_FILE_SORTED", "path": "1", "pattern": "0=unsorted, 1=sorted, 2=foldcase"}
...
{"_type": "tag", "name": "Klass", "path": "/tmp/input.py", "pattern": "/^class Klass:$/", "language": "Python", "kind": "class"}
{"_type": "tag", "name": "method", "path": "/tmp/input.py", "pattern": "/^    def method(self):$/", "language": "Python", "kind": "member", "scope": "Klass", "scopeKind": "class"}
...

Una clave que no empieza con _ se mapea a un campo de ctags. Las opciones "--output-format=json --list-fields" listan los campos.

Una clave que empieza con _ representa metainformación de la línea JSON. Actualmente, solo se utiliza la clave _type. Si el valor de la clave es tag, la línea JSON representa una etiqueta regular. Si el valor es ptag, la línea representa una pseudo-etiqueta.

El formato de salida puede cambiar en el futuro. La pseudo-etiqueta JSON_OUTPUT_VERSION proporciona un mecanismo para que las herramientas cliente manejen los cambios. La versión actual es "1.0". Una herramienta cliente puede extraer la versión con la clave path de la pseudo-etiqueta.

El formato de salida JSON es de diseño reciente y no tiene las limitaciones encontradas en el formato de archivo de etiquetas por defecto.

  • Los valores para la clave kind se representan con banderas de nombre largo. Aquí no hay letras únicas.
  • Los nombres de ámbito y los tipos de ámbito tienen claves distinguidas: scope y scopeKind. En el formato de archivo de etiquetas por defecto están combinados.

TIPO DE DATO UTILIZADO EN UN CAMPO

Los valores para la mayoría de las claves se representan en tipo de cadena JSON. Sin embargo, algunos de ellos se representan en tipo cadena, entero y/o booleano.

"--output-format=json --list-fields" las opciones muestran qué tipo de dato se utiliza en un campo JSON.

$ ctags --output-format=json --list-fields
#LETTER NAME           ENABLED LANGUAGE         JSTYPE FIXED DESCRIPTION
F       input          yes     NONE             s--    no    input file
...
P       pattern        yes     NONE             s-b    no    pattern
...
f       file           yes     NONE             --b    no    File-restricted scoping
...
e       end            no      NONE             -i-    no    end lines of various items
...

La columna JSTYPE muestra los tipos de datos.

's'
cadena
'i'
entero
'b'
booleano (true o false)

Como ejemplo, el valor para el campo pattern de ctags toma una cadena o un valor booleano.

VERSIONES

Cambio desde "0.0"

•
Nueva clave kindName para la pseudo-etiqueta TAG_ROLE_DESCRIPTION

Se añade kindName para almacenar el nombre del tipo en las pseudo-etiquetas TAG_ROLE_DESCRIPTION.

En 0.0, una pseudo-etiqueta "TAG_ROLE_DESCRIPTION" se imprimía así:

{"_type": "ptag", "name": "TAG_ROLE_DESCRIPTION",
                  "parserName": "LANG!KIND", }

En 1.0, se imprime así:

{"_type": "ptag", "name": "TAG_ROLE_DESCRIPTION",
                  "parserName": "LANG",
                  "kindName": "KIND",  }
