HTTP::Cache::Transparent(3) Documentación de Perl aportada por el usuario HTTP::Cache::Transparent(3)

NOMBRE

HTTP::Cache::Transparent - Caché el resultado de las solicitudes http get de forma persistente.

SINOPSIS

use LWP::Simple;
use HTTP::Cache::Transparent;
HTTP::Cache::Transparent::init( {
  BasePath => '/tmp/cache',
} );
my $data = get( 'http://www.sn.no' );

DESCRIPCIÓN

Una implementación de http get que mantiene una caché local de las páginas obtenidas para evitar obtener los mismos datos del servidor si no se han actualizado. La caché se almacena en disco y, por lo tanto, es persistente entre invocaciones.

Utiliza las cabeceras http If-Modified-Since y ETag para que el servidor decida si la versión en la caché está actualizada o no.

La caché se implementa modificando la clase LWP::UserAgent para que guarde en caché de forma transparente el resultado de todas las solicitudes que se pueden cachear.

INICIALIZACIÓN DE LA CACHÉ

HTTP::Cache::Transparent proporciona un método init que establece los parámetros de la caché y sobrecarga un método en LWP::UserAgent para activar la caché. Después de llamar a init, los métodos normales de LWP (LWP::Simple, así como los métodos más completos de LWP::Request) deberían utilizarse como de costumbre.

init
Inicializa la caché HTTP. Toma un solo parámetro que es un hashref que contiene argumentos con nombre para el objeto. 
 HTTP::Cache::Transparent::init( {
   # Directorio donde almacenar la caché.
   BasePath  => "/tmp/cache",
   # ¿Cuántas horas se deben conservar los elementos en la caché
   # después de que se solicitaron por última vez?
   # El valor por defecto es 8*24.
   MaxAge    => 8*24,
   # Imprimir mensajes de progreso en STDERR.
   # El valor por defecto es 0.
   Verbose   => 1,
   # Si se realiza una solicitud para una URL que ha sido solicitada
   # al servidor hace menos de NoUpdate segundos, la
   # respuesta se generará desde la caché sin
   # contactar al servidor.
   # El valor por defecto es 0.
   NoUpdate  => 15*60,
   # Cuando se descarga una URL y la respuesta indica que
   # ha sido modificada en comparación con el contenido de la caché,
   # la función de devolución de llamada ApproveContent se llama con HTTP::Response.
   # La función de devolución de llamada debe devolver verdadero si la respuesta debe usarse y
   # almacenarse en la caché, o falso si la respuesta debe descartarse
   # y usarse la respuesta de la caché en su lugar.
   # Este mecanismo se puede utilizar para solucionar problemas con servidores que devuelven errores
   # de forma intermitente. El valor por defecto es aceptar todas las respuestas.
   ApproveContent => sub { return $_[0]->is_success },
} );

El directorio donde se almacena la caché debe ser escribible. También debe contener solo archivos creados por HTTP::Cache::Transparent.

Inicialización desde la línea use
Una forma alternativa de inicializar HTTP::Cache::Transparent es proporcionar parámetros en la línea use. Esto le permite escribir 
use HTTP::Cache::Transparent ( BasePath => '/tmp/cache' );

que es exactamente equivalente a

use HTTP::Cache::Transparent;
HTTP::Cache::Transparent::init( BasePath => '/tmp/cache' );

La ventaja de usar este método es que puede hacer

perl -MHTTP::Cache::Transparent=BasePath,/tmp/cache myscript.pl

o incluso establecer la variable de entorno PERL5OPT

PERL5OPT=-MHTTP::Cache::Transparent=BasePath,/tmp/cache
myscript.pl

y hacer que todas las solicitudes http realizadas por myscript.pl pasen por la caché sin modificar myscript.pl

INSPECCIÓN DEL COMPORTAMIENTO DE LA CACHÉ

HTTP::Cache::Transparent inserta tres cabeceras especiales en el objeto HTTP::Response. Estas se pueden acceder a través del método HTTP::Response::header().

X-Cached
Esta cabecera se inserta y se establece en 1 si la respuesta se entrega desde la caché en lugar del servidor.
X-Content-Unchanged
Esta cabecera se inserta y se establece en 1 si el contenido devuelto es el mismo que el contenido devuelto la última vez que se solicitó esta URL. Esta cabecera siempre se inserta y se establece en 1 cuando la respuesta se entrega desde la caché.
X-No-Server-Contact
Esta cabecera se inserta y se establece en 1 si el contenido devuelto se ha entregado sin ningún contacto con el servidor externo, es decir, no se ha enviado ninguna solicitud GET HTTP condicional o incondicional, el contenido se ha entregado directamente desde la caché. Esto puede ser útil cuando se busca controlar la carga del servidor externo.

LIMITACIONES

Este módulo tiene una serie de limitaciones que debe tener en cuenta antes de usarlo.

  • No hay un límite superior para la cantidad de espacio en disco que requiere la caché. El único mecanismo de limitación es que los datos de las URL que no se han solicitado en las últimas MaxAge horas se eliminarán de la caché la próxima vez que el programa finalice.
  • Actualmente, solo se cachean las solicitudes get que almacenan el resultado en memoria (es decir, no usan la opción de almacenar el resultado directamente en un archivo o entregarlo a través de una función de devolución de llamada). Tengo la intención de eliminar esta limitación en una versión futura.
  • El soporte para Rangos es un poco primitivo. Crea un nuevo objeto en la caché para cada combinación única de URL y rango. Esto funcionará bien siempre que solicite los mismos rangos para una URL.
  • La caché no verifica ni almacena correctamente todas las cabeceras de la solicitud y respuesta HTTP. Por lo tanto, si solicita la misma URL repetidamente con diferentes conjuntos de cabeceras (cookies, accept-encoding, etc.), y estas cabeceras afectan la respuesta del servidor, la caché puede devolver la respuesta incorrecta.
  • HTTP::Cache::Transparent no ha sido probado con hilos y lo más probable es que no funcione si los utiliza.

FORMATO DE LA CACHÉ

La caché se almacena en disco como un archivo por objeto cacheado. El nombre del archivo es igual al md5sum de la URL y la cabecera Range, si existe. El archivo contiene un conjunto de pares clave/valor con metadatos (una entrada por línea) seguido de una línea en blanco y luego los datos reales devueltos por el servidor.

La fecha de última modificación del archivo de caché se establece en el momento en que el objeto de caché fue solicitado por última vez por un usuario.
