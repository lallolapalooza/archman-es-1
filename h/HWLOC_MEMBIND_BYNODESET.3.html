Descripción

detallada

El enlazado de memoria se puede realizar de tres

maneras:
  • asignación de memoria explícita gracias a hwloc_alloc_membind() y funciones similares: el enlazado tendrá efecto sobre la memoria asignada por estas
    • funciones.
  • enlazado de memoria implícito a través de la política de enlazado: hwloc_set_membind() y funciones similares solo definen la política actual del proceso, que se aplicará a las llamadas posteriores a malloc() y funciones
    • similares.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y funciones simil
    • ares, que mueven dato
s ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlazado de memoria en el sistema operativo actualmente en

uso.

Cuando la operación de enlazado solicitada no está disponible y se pasó el indicador HWLOC_MEMBIND_STRICT, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema sí soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria a nivel de hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA)

.

Si no se pasó HWLOC_MEMBIND_STRICT, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlazado más pequeño, etc.) cuando la operación solicitada no esté exactamente

soportada.

La forma más portable, que debería preferirse sobre las demás siempre que sea posible, es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para hacerlo, hwloc posiblemente tendrá que cambiar la política actual de enlazado de memoria para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política actual de enlazado de

memoria. 
hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0)
;

Cada función de enlazado de memoria de hwloc toma un argumento bitmap que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si se especifica el indicador HWLOC_MEMBIND_BYNODESET. Ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de bitmaps para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_n

odeset().

El enlazado de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlazado por conjunto de nodos debería preferirse siempre que sea

posible.

enum hwloc_membind_flags_

t

Indicadores de enlazado de memoria. Estos indicadores pueden usarse para refinar la política de enlazado. Todos los indicadores pueden combinarse lógicamente con OR, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos indicadores son mutuamente

excluyentes.

No todos los sistemas soportan todos los tipos de enlazado. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlazado de memoria en el sistema operativo actualmente en uso. Ver la sección 'Descripción detallada' de Enlazado de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este indicador es mutuamente excluyente con HWLOC_MEMBIND_
THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este indicador es mutuamente excluyente con HWLOC_MEMBIND_PROCE
SS.
HWLOC_MEMBIND_STRICT
Solicita enlazado estricto al SO. La func
ión fallará si el enlazado no pued
e garantizarse / aplicarse completamente.

Este indicador tiene significados ligeramente diferentes dependiendo con qué función se

use.
HWLOC_MEMBIND_MIGRATE
Migra memoria ya asignada. Si la memoria no puede migrarse y se pasó el indicador HWLOC_MEMBIND_STRICT, se devolverá un
error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlazado de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlazado de memoria también enlazan la aplicación a el/los CPU correspondiente(s). Usar este indicador hará que hwloc evite usar funciones del SO que podrían afectar potencialmente a los enlazados de CPU. Nótese, sin embargo, que usar NOCPUBIND puede reducir el soporte general de enlazado de memoria de hwloc. Específicamente: algunas de las funciones de enlazado de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usan con
NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento bitmap como un conjunto de nodos. El argume
nto bitmap se considera un conjunto de nodos si se da este in
dicador, o un conjunto de CPU en caso contrario por defecto.

El enlazado de memoria por conjunto de CPU no puede funcionar par

a nodos de memoria NUMA sin CPU. Por lo tanto, el enlazado po
r conjunto de nodos debería preferirse siempre que sea posible.

enum hwloc_membind_policy_

t

Política de enlace de memoria. Estas constantes se pueden utilizar para elegir la política de enlace. Solo se puede usar una política a la vez (es decir, los valores no se pueden combinar con OR)

.

No todos los sistemas soportan todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar el soporte real de la política de enlace de memoria en el sistema operativo actualmente en uso. Consulte la sección 'Descripción Detallada' de Enlace de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD), o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones de obtención de enlace de memoria (get membind). El argumento nodeset es
ignorado.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado debería ser usualmente hwloc_topology_get_topology_nodeset() para que el hilo que la toc
a pueda ejecutarse y asigna
r en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (en caso contrario)

.
HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre sistemas operativos, especialmente cuando (algunos de) los nodos solicitados están llenos. En Linux, por defecto, se usa la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona el flag estricto de hwloc, se usa en su lugar la política MPOL_BIND de
Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / round-robin. El diseño preciso de la memoria a través de múltiples nodos NUMA es específico del sistema operativo/sistema. El entrelazado puede ser útil cuando hilos distribuidos a través de los nodos NUMA especificados accederán todos al rango completo de memoria concurrentemente, ya que el entrelazado equilibrará entonces las referencias a la
memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / ponderada. El diseño preciso de la memoria a través de múltiples nodos NUMA es específico del sistema operativo/sistema. El entrelazado ponderado puede ser útil cuando hilos distribuidos a través de los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán todos al rango completo de memoria concurrentemente, ya que el entrelazado equilibrará entonces las referencias a la
memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página enlazada con esta política, la próxima vez que sea tocada (y solo la próxima vez), se mueve de su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia a la memoria (si necesita ser movida en absoluto)
.
HWLOC_MEMBIND_MIXED
Devuelto por las funciones get_membind() cuando múltiples hilos
o partes de un área de memoria tienen políticas de enlace d
e memoria diferentes. También se devuelve cuando el enlace
es desconocido porque los hooks de enlace están vacíos cuando la
topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

Consulta las CPUs cercanas al(los) nodo(s) NUMA físicos y la política de enlace de la memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamador) se rellena con el enlace del área de

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de enlace de memoria y los nodesets de las páginas en el rango de

Si HWLOC_MEMBIND_BYNODESET es especificado, set es considerado un nodeset. De lo contrario, es un

cpuset.
