topology, hwloc_pid_t pid, hwloc_cpuset_tset, int flags) Descripción Detallada
Algunos sistemas operativos solo admiten el enlazado de hilos o procesos a una sola PU. Otros permiten el enlazado a conjuntos más grandes como Núcleos completos o Paquetes o incluso conjuntos aleatorios de PUs individuales. En tales sistemas operativos, el planificador es libre de ejecutar la tarea en una de estas PUs, luego migrarla a otra PU, etc. A menudo es útil llamar a hwloc_bitmap_singlify()en el conjunto de CPU objetivo antes de pasarlo a la función de enlazado para evitar estas migraciones costosas. Vea la documentación de hwloc_bitmap_singlify()
para más detalles. Algunos sistemas operativos no proporcionan todos los mecanismos admitidos por hwloc para enlazar procesos, hilos, etc.hwloc_topology_get_support() puede usarse para consultar sobre el soporte real de enlazado de CPU en el sistema operativo actualmente utilizado.

Cuando la operación de enlazado solicitada no está disponible y se pasó

el

HWLOC_CPUBIND_STRICT indicador, la función devuelve -1. errno se establece en

ENOSYS

cuando no es posible enlazar el tipo solicitado de objetos procesos/hilos. errno se establece en EXDEV cuando el conjunto de CPU solicitado no puede aplicarse (por ejemplo, algunos sistemas solo permiten una CPU, y algunos otros sistemas solo permiten un nodo NUMA)

.

Si HWLOC_CPUBIND_STRICT no se pasó, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlazado más pequeño, etc.) cuando la operación solicitada no es exactamente compatible. La versión más portable que debería preferirse sobre las demás, siempre que sea posible, es la siguiente que simplemente enlaza el programa actual, asumiendo que es de un solo

hilo:

hwloc_set_cpubind(topology, set, 0), Si el programa puede ser multihilo, debería preferirse la siguiente para enlazar solo el hilo

actual:

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD)

T
Solicitar enlazado estricto del SO. De manera predeterminada, cuando los CPUs designados están todos ocupados mientras otros CPUs están inactivos, los sistemas operativos pueden ejecutar el hilo/proceso en esos otros CPUs en lugar de los CPUs designados, para dejarlos avanzar de todos modos. El enlazado estricto significa que el hilo/proceso _nunca_ se ejecutará en otros CPUs que los designados, incluso cuando estén ocupados con otras tareas y otros CPUs estén inactivos.
Not
a
Dependiendo del sistema operativo, el enlazado estricto puede no ser posible (por ejemplo, el SO no lo implementa) o no permitido (por ejemplo, por razones administrativas), y la función fallará en ese caso.

D

Evitar cualquier efecto en el enlazado de memoria. En algunos sistemas operativos, algunas funciones de enlazado de CPU también enlazarían la memoria en el nodo NUMA correspondiente. A menudo no es un problema para la aplicación, pero si lo es, establecer este indicador hará que hwloc evite usar funciones del SO que también enlazarían la memoria. Esto sin embargo reducirá el

soporte de enlazados de CPU, es decir, potencialmente devolver -1 con errno establecido en ENOSYS
en algunos
casos.
Este indicador solo tiene significado cuando se usa con funciones que establecen el enlazado de CPU. Se ignora cuando se usa con funciones que obtienen información de enlazado de CPU.
