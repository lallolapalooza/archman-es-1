DESCRIPCIÓ

N

Este módulo implementa un frasco de cookies minimalista para agente de usuario HTTP en conformidad con RFC 6265 http://tools.ietf.org/html/rfc6265

.

A diferencia del módulo HTTP::Cookies comúnmente utilizado, este módulo

no requiere el uso de objetos HTTP::Request y HTTP::Response. Un
adaptador compatible con LWP está disponible como HTTP::CookieJar::LWP.

my @cookies = $jar->cookies_for("http://www.example.com/foo/bar")

Dada una URL de petición, devuelve una lista de referencias a hash que representan las cookies que deben enviarse. Las referencias a hash son copias -- cambiar los valores no cambiará las cookies en el

frasco.

Las cookies establecidas como "secure" solo se devolverán si el esquema de la petición es "https". Las cookies caducadas no se

devolverán.

Las claves de una referencia a hash de cookie podrían

incluir:
  • name -- el nombre de la
    • cookie
  • value -- el valor de la
    • cookie
  • domain -- el nombre de dominio al que aplica la
    • cookie
  • path -- la ruta a la que aplica la
    • cookie
  • expires -- si está presente, cuándo caduca la cookie en segundos
    • epoch
  • secure -- si está presente, la cookie fue establecida como "Secur
    • e"
  • httponly -- si está presente, la cookie fue establecida como "HttpOnl
    • y"
  • hostonly -- si está presente, la cookie solo puede usarse con el dominio como
    • host
  • creation_time -- tiempo epoch cuando la cookie fue almacenada por primera
    • vez
  • last_access_time -- tiempo epoch c
    • uando la cookie fue accedida por úl
tima vez (es decir, "ahora")

Ten en cuenta que "httponly" significa que solo debe usarse en peticiones y no hacerse disponible vía Javascript, etc. Esto es bastante sin sentido para agentes de usuario

Perl.

Generalmente, los agentes de usuario deberían usar el método "cookie_header" en su

dump_cookie

s 
my @list = $jar->dump_cookies;
my @list = $jar->dump_cookies( { persistent => 1 } )
;

Devuelve una lista de cookies crudas en forma de cadena. Las cadenas se asemejan a lo que se recibiría de las cabeceras "Set-Cookie", pero con campos internos adicionales. La lista solo está destinada para uso con "load_cookies" para permitir la persistencia del frasco de

cookies.

Si se da como argumento una referencia a hash con una clave "persistent" verdadera, las cookies sin un tiempo "Expires" (es decir, "cookies de sesión") serán

omitidas.

Aquí hay un ejemplo trivial de guardar un archivo de frasco de cookies con Path::

Tiny: 
path("jar.txt")->spew( join "\n", $jar->dump_cookies
)
;

s

similares.

objeto:

LIMITACIONES Y

ADVERTENCIAS

RFC 6265 vs estándares

anteriores

Este módulo se adhiere lo más posible a las reglas de agente de usuario de RFC 6265. Por lo tanto, no maneja ni genera cabeceras "Set-Cookie2" y "Cookie2", implementa sufijos ".local", ni hace coincidencia de ruta

/dominio de acuerd
o con RFC's anteriores.

Nombres de dominio internacionalizado

s

Los nombres de dominio internacionalizado

s dados en las peticiones deben estar corr
ectamente codificados en forma ASCII.

Sufijos

públicos

Si Mozilla::PublicSuffix está instalado, los dominios de cookie serán verificados contra la lista de sufijos públicos. Las cookies de sufijo público solo se permiten como cookies

solo-hospedador
.

Cookies de

terceros

Según RFC 6265, una cookie puede ser aceptada solo si no tiene atributo "Domain" (en cuyo caso es "solo-hospedador") o si el atributo "Domain" es un sufijo de la URL de la petición. Esto prohíbe efectivament

e que el Sitio A establezca una cookie
para el Sitio B no relacionado, que es un
vector potencial de cookie de terceros.
