Documentación de tipos de enumeración

enum hwloc_allow_flags_e

Marcas a pasar a hwloc_topology_allow().

Enumerador

HWLOC_ALLOW_FLAG_ALL
Marca todos los objetos como permitidos en la topología. cpuset y nođeset pasados a hwloc_topology_allow() deben ser NULL.
HWLOC_ALLOW_FLAG_LOCAL_RESTRICTIONS
Solo permite objetos que estén disponibles para el proceso actual. La topología debe tener HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM para que el conjunto de recursos disponibles pueda ser recuperado del sistema operativo.

cpuset y nođeset pasados a hwloc_topology_allow() deben ser NULL.

HWLOC_ALLOW_FLAG_CUSTOM
Permite un conjunto personalizado de objetos, pasados a hwloc_topology_allow() como parámetros cpuset y/o nodeset.

enum hwloc_restrict_flags_e

Marcas a pasar a hwloc_topology_restrict().

Enumerador

HWLOC_RESTRICT_FLAG_REMOVE_CPULESS
Elimina todos los objetos que han quedado sin CPU. Por defecto, solo se eliminan los objetos que no contienen ninguna PU ni memoria. Esta marca no se puede usar con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_BYNODESET
Restringe por conjunto de nodos en lugar de por conjunto de CPU. Solo mantiene los objetos cuyo conjunto de nodos esté incluido o parcialmente incluido en el conjunto dado. Esta marca no se puede usar con HWLOC_RESTRICT_FLAG_REMOVE_CPULESS.
HWLOC_RESTRICT_FLAG_REMOVE_MEMLESS
Elimina todos los objetos que han quedado sin memoria. Por defecto, solo se eliminan los objetos que no contienen ninguna PU ni memoria. Esta marca solo se puede usar con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_ADAPT_MISC
Mueve objetos Misc a sus ancestros si sus padres son eliminados durante la restricción. Si esta marca no está establecida, los objetos Misc se eliminan cuando sus padres son eliminados.
HWLOC_RESTRICT_FLAG_ADAPT_IO
Mueve objetos de E/S a sus ancestros si sus padres son eliminados durante la restricción. Si esta marca no está establecida, los dispositivos y puentes de E/S se eliminan cuando sus padres son eliminados.

int hwloc_obj_add_other_obj_sets (hwloc_obj_t dst, hwloc_obj_t src)

Configura conjuntos de CPU/nodos de objetos aplicando un OR con los conjuntos de otro objeto. Para cada conjunto de CPU o de nodos definido en src, asigna el conjunto correspondiente en dst y le añade src mediante la operación OR de conjuntos.

Esta función es conveniente entre hwloc_topology_alloc_group_object() y hwloc_topology_insert_group_object(). Construye los conjuntos del nuevo Grupo que se insertará como un nuevo padre intermedio de varios objetos.

Devuelve

0 si tiene éxito.

-1 con errno establecido a ENOMEM si alguna reasignación interna falló.

hwloc_obj_t hwloc_topology_alloc_group_object (hwloc_topology_t topology)

Asigna un objeto Grupo para insertarlo más tarde con hwloc_topology_insert_group_object(). Esta función devuelve un nuevo objeto Grupo.

El llamador debe (al menos) inicializar sus conjuntos antes de insertar el objeto en la topología, ver hwloc_topology_insert_group_object(). O puede decidir no insertarlo y simplemente liberar el objeto grupo llamando a hwloc_topology_free_group_object().

Devuelve

El objeto asignado si tiene éxito.

NULL si falla.

Nota

Si se inserta con éxito mediante hwloc_topology_insert_group_object(), el objeto se liberará cuando se libere toda la topología. Si la inserción falla (por ejemplo, conjuntos de CPU y nodos NULL o vacíos), se libera antes de devolver el error.

int hwloc_topology_allow (hwloc_topology_t restrict topology, hwloc_const_cpuset_t cpuset, hwloc_const_nodeset_t nodeset, unsigned long flags)

Cambia los conjuntos de PUs y nodos NUMA permitidos en la topología. Esta función solo funciona si la marca HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED fue establecida en la topología. No modifica ningún objeto, solo cambia los conjuntos devueltos por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset().

Es especialmente útil al importar una topología desde otro proceso que se ejecuta en un Cgroup de Linux diferente.

flags debe establecerse a una de las marcas de hwloc_allow_flags_e.

Devuelve

0 si tiene éxito, -1 si falla.

Nota

La eliminación de objetos de una topología debería realizarse preferiblemente con hwloc_topology_restrict().

int hwloc_topology_free_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Libera un objeto de grupo asignado con hwloc_topology_alloc_group_object(). Esta función solo es útil si el objeto de grupo no se le dio a hwloc_topology_insert_group_object() como estaba previsto.

Nota

topology debe ser el mismo que se pasó previamente a hwloc_topology_alloc_group_object().

Devuelve

0 si tiene éxito.

-1 en caso de error, por ejemplo, si se proporciona una topología inválida.

hwloc_obj_t hwloc_topology_insert_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Añade más estructura a la topología insertando un Grupo intermedio. El llamador debe primero asignar un nuevo objeto Grupo con hwloc_topology_alloc_group_object(). Luego debe configurar al menos uno de sus conjuntos de CPU o nodos para especificar la ubicación final del Grupo en la topología. Entonces el objeto puede pasarse a esta función para su inserción real en la topología.

El caso de uso principal para esta función es agrupar un subconjunto de hermanos dentro de la lista de hijos debajo de un único padre. Por ejemplo, al agrupar 4 núcleos de un socket de 8 núcleos, la lista lógica de núcleos se reordenará para que los 4 agrupados sean consecutivos. Luego, si es necesario, se añade una nueva profundidad entre el padre y esos hijos, y el Grupo se inserta allí. Al final, los 4 núcleos agrupados son ahora hijos del Grupo, que los reemplaza como hijo del padre original.

En la práctica, los objetos agrupados se especifican a través de conjuntos de CPU (cpusets) y/o conjuntos de nodos (nodesets), por ejemplo, usando hwloc_obj_add_other_obj_sets() iterativamente. Por lo tanto, es posible agrupar objetos que no son hijos del mismo padre, por ejemplo, algunas PUs debajo de los 4 núcleos en el ejemplo anterior. Sin embargo, este caso general puede fallar si el Grupo esperado entra en conflicto con la jerarquía existente. Por ejemplo, si cada núcleo tiene dos PUs, no es posible insertar un Grupo que contenga una sola PU de cada núcleo.

Para especificar los objetos a agrupar, el campo cpuset o nodeset (o ambos, si son compatibles) debe establecerse en un mapa de bits no vacío. El complete_cpuset o complete_nodeset pueden establecerse en su lugar si se inserta con respecto a la topología completa (incluyendo objetos desautorizados, fuera de línea o desconocidos). Estos conjuntos no pueden ser más grandes que la topología actual, o de lo contrario se restringirían silenciosamente. El núcleo establecerá los otros conjuntos después de la inserción real.

El atributo de objeto subtype puede definirse con hwloc_obj_set_subtype() para mostrar algo diferente a 'Group' como nombre de tipo para este objeto en lstopo. Los pares personalizados de nombre-valor de información se pueden añadir con hwloc_obj_add_info() después de la inserción.

El atributo dont_merge del grupo puede establecerse en 1 para evitar que el núcleo de hwloc fusione este objeto con otro objeto jerárquicamente idéntico. Esto es útil cuando el Grupo en sí describe una característica importante que no puede exponerse en ningún otro lugar de la jerarquía.

El atributo kind del grupo puede establecerse en un valor alto como 0xffffffff para indicar a hwloc que este nuevo Grupo siempre debe descartarse en favor de cualquier Grupo existente con la misma localidad.

Nota

La inserción de un grupo añade información de localidad a la topología, por lo que los objetos existentes pueden reordenarse (incluyendo PUs y nodos NUMA), y sus índices lógicos pueden cambiar.

Si la inserción falla, el objeto de grupo de entrada se libera.

Si el objeto de grupo debe descartarse en lugar de insertarse, se puede pasar a hwloc_topology_free_group_object() en su lugar.

topology debe ser el mismo que se pasó previamente a hwloc_topology_alloc_group_object().

Devuelve

El objeto insertado si se insertó correctamente.

Un objeto existente si el Grupo se fusionó o descartó porque la topología ya contenía un objeto en la misma ubicación (el Grupo no añadió información jerárquica).

NULL si la inserción falló debido a conflictos de conjuntos en el árbol de topología.

NULL si los objetos de Grupo se filtran de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

NULL si el objeto se descartó porque no se inicializó ningún conjunto en el Grupo antes de la inserción, o todos estaban vacíos.

hwloc_obj_t hwloc_topology_insert_misc_object (hwloc_topology_t topology, hwloc_obj_t parent, const char *name)

Añade un objeto MISC como hoja de la topología. Se creará un nuevo objeto MISC y se insertará en la topología en la posición dada por parent. Se añade al final de la lista de hijos Misc existentes, sin añadir nunca ningún nivel jerárquico intermedio. Esto es útil para anotar la topología sin cambiar realmente la jerarquía.

name se supone que es único entre todos los objetos Misc de la topología. Se duplicará para configurar los atributos del nuevo objeto.

El nuevo objeto hoja no tendrá ningún cpuset.

El atributo de objeto subtype puede definirse con hwloc_obj_set_subtype() después de una inserción exitosa.

Devuelve

el objeto recién creado

NULL en caso de error.

NULL si los objetos Misc se filtran de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

Nota

Si name contiene caracteres no imprimibles, se eliminarán al exportar a XML, consulte hwloc_topology_export_xml() en hwloc/export.h.

int hwloc_topology_refresh (hwloc_topology_t topology)

Actualiza las estructuras internas después de modificar la topología. Modificar la topología (restringiéndola, añadiendo objetos, modificando estructuras como distancias o atributos de memoria, etc.) puede hacer que algunas cachés internas queden invalidadas. Estas cachés se actualizan automáticamente al acceder a ellas, pero esta actualización no es segura para hilos.

Esta función tampoco es segura para hilos, pero es una buena manera de finalizar una fase no segura para hilos de modificación de topología. Una vez realizada esta actualización, varios hilos pueden consultar concurrentemente la topología, objetos, distancias, atributos, etc.

Ver también Thread Safety

Devuelve

0 si tiene éxito.

-1 en caso de error, por ejemplo, si falló alguna reasignación interna.

int hwloc_topology_restrict (hwloc_topology_t restrict topology, hwloc_const_bitmap_t set, unsigned long flags)

Restringe la topología al conjunto de CPU o conjunto de nodos dado. La topología topology se modifica para eliminar todos los objetos que no están incluidos (o parcialmente incluidos) en el conjunto de CPU set. Todos los conjuntos de CPU y nodos de los objetos se restringen en consecuencia.

Por defecto, set es un conjunto de CPU. Esto significa que el conjunto de PUs en la topología se restringe. Una vez que se han eliminado algunas PUs, sus padres también pueden eliminarse recursivamente si se quedan sin hijos.

Si se pasa HWLOC_RESTRICT_FLAG_BYNODESET en flags, set se considera un conjunto de nodos en lugar de un conjunto de CPU. Esto significa que el conjunto de nodos NUMA en la topología se restringe (en lugar de las PUs). Una vez que se han eliminado algunos nodos NUMA, sus padres también pueden eliminarse recursivamente si se quedan sin hijos.

flags es un conjunto OR de hwloc_restrict_flags_e.

Nota

Restringir la topología elimina información de localidad, por lo que los objetos restantes pueden reordenarse (incluyendo PUs y nodos NUMA), y sus índices lógicos pueden cambiar.

Esta llamada no se puede revertir restringiendo de nuevo a un conjunto más grande. Una vez eliminados durante la restricción, los objetos no pueden recuperarse, excepto cargando otra topología con hwloc_topology_load().

Devuelve

0 si tiene éxito.

-1 con errno establecido en EINVAL si el conjunto de entrada es inválido. La topología no se modifica en este caso.

-1 con errno establecido en ENOMEM en caso de fallo al asignar datos internos. La topología se reinicializa en este caso. Debería ser destruida con hwloc_topology_destroy() o configurada y cargada de nuevo.
