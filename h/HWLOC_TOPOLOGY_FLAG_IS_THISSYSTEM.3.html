DESCRIPCIÓN DETALLADA

Varias funciones se pueden llamar opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

DOCUMENTACIÓN DEL TIPO DE ENUMERACIÓN

enum hwloc_topology_flags_e

Flags para ser establecidos en un contexto de topología antes de la carga. Los flags deben darse a hwloc_topology_set_flags(). También pueden ser devueltos por hwloc_topology_get_flags().

Enumerator

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detecta todo el sistema, ignora las reservas, incluye objetos no permitidos. Recopila todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignora Cgroup/Cpusets de Linux y recopila todos los procesadores y nodos de memoria. Sin embargo, las PU y los nodos NUMA desconectados aún se ignoran.

Cuando este flag no está establecido, las PU y los nodos NUMA que no están permitidos no se agregan a la topología. Los objetos padres (paquete, núcleo, caché, etc.) se agregan solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y al conjunto de nodos del objeto raíz.

Cuando este flag está establecido, los conjuntos reales de PU y nodos NUMA permitidos se dan por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y el conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, este flag debe establecerse nuevamente en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asume que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando, incluso si no es el backend específico del SO sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace realmente llamen a las llamadas del sistema específicas del SO y realicen el enlace, mientras que el backend XML proporcionaría de lo contrario ganchos vacíos que simplemente devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún así tener las funciones de enlace realizando el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtiene el conjunto de recursos permitidos del sistema operativo local, incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringe aplicando las restricciones del proceso actual, como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Este flag se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecido, ya que la topología cargada debe coincidir con la máquina subyacente de la que se obtendrán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importa el soporte de la topología importada. Al importar una topología XML de una máquina remota, el enlace se deshabilita por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits de características compatibles correspondientes informados por hwloc_topology_get_support().

El flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT realmente importa los bits de soporte de la máquina remota. También establece el flag imported_support en la estructura hwloc_topology_misc_support array. Si el XML importado no contenía información de soporte (el exportador hwloc es demasiado antiguo), este flag no se establece.

Tenga en cuenta que estas características compatibles solo son relevantes para la instalación de hwloc que exportó la topología XML (puede variar según el sistema operativo o cómo se compiló hwloc).

Tenga en cuenta que, sin embargo, establecer este flag no habilita el enlace para la topología hwloc importada localmente, solo informa lo que el hwloc remoto y la máquina soportan.

int hwloc_topology_set_all_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos. Si algunos tipos no admiten este filtrado, se ignoran silenciosamente.

Retorno

0 si la operación es exitosa, -1 si ocurre un error.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos de caché de CPU. Las cachés del lado de la memoria no están involucradas ya que no son cachés de CPU.

Retorno

0 si la operación es exitosa, -1 si ocurre un error.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Establece banderas OR'ed en la topología aún no cargada. Establece un conjunto OR'ed de hwloc_topology_flags_e en una topología que aún no ha sido cargada.

Si esta función se llama varias veces, la última invocación borrará y reemplazará el conjunto de banderas que se estableció previamente.

Por defecto, no se establecen banderas (0).

Las banderas establecidas en una topología se pueden recuperar con hwloc_topology_get_flags().

Retorno

0 si la operación es exitosa.

-1 si ocurre un error, por ejemplo, si las banderas no son válidas.

int hwloc_topology_set_icache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos de caché de instrucciones de CPU. Las cachés del lado de la memoria no están involucradas ya que no son cachés de CPU.

Retorno

0 si la operación es exitosa, -1 si ocurre un error.

int hwloc_topology_set_io_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos de E/S.

Retorno

0 si la operación es exitosa, -1 si ocurre un error.

int hwloc_topology_set_type_filter (hwloc_topology_t topology, hwloc_obj_type_t type, enum hwloc_type_filter_e filter)

Establece el filtrado para el tipo de objeto dado.

Retorno

0 si la operación es exitosa, -1 si ocurre un error.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Establece el puntero de datos de usuario específico de la topología. Cada topología puede almacenar un puntero de datos privado proporcionado por la aplicación. Se inicializa a NULL. hwloc nunca lo modificará.

Úselo como desee, después de hwloc_topology_init() y hasta hwloc_topolog_destroy().

Este puntero no se exporta a XML.
