DESCRIPCIÓ

N

Este módulo intenta hacer que el uso de plantillas HTML sea simple y natural. Extiende el HTML estándar con algunas nuevas etiquetas al estilo HTML - "<TMPL_VAR>" "<TMPL_LOOP>", "<TMPL_INCLUDE>", "<TMPL_IF>", "<TMPL_ELSE>" y "<TMPL_UNLESS>". El archivo escrito con HTML y estas nuevas etiquetas se llama plantilla. Generalmente se guarda separado de tu script - ¡posiblemente incluso creado por otra persona! Usando este módulo rellenas los valores de las variables, bucles y ramificaciones declarados en la plantilla. Esto te permite separar el diseño - el HTML - de los datos, que generas en el script de

Perl.

MOTIVACIÓ

N

Es cierto que hay una serie de paquetes por ahí para hacer plantillas HTML. Por un lado tienes cosas como HTML::Embperl que te permite mezclar libremente Perl con HTML. Por otro lado están las soluciones caseras de sustitución de variables. Esperemos que el módulo pueda encontrar un lugar entre las

dos.

Una ventaja de este módulo sobre una solución completa al estilo HTML::Embperl es que impone una división importante - diseño y programación. Al limitar al programador a solo usar variables simples y bucles en el HTML, la plantilla permanece accesible para diseñadores y otras personas que no saben Perl. El uso de sintaxis al estilo HTML va más allá para hacer que el formato sea comprensible para otros. En el futuro esta similitud podría usarse para extender los editores/analizadores HTML existentes para soportar HTML::

Template.

Una ventaja de este módulo sobre los esquemas caseros de reemplazo de etiquetas es el soporte para bucles. En mi trabajo a menudo se me pide producir tablas de datos en html. Producirlas usando plantillas HTML simplistas resulta en programas que contienen mucho HTML ya que el HTML en sí no puede representar bucles. La introducción de sentencias de bucle en el HTML simplifica esta situación considerablemente. El diseñador puede diseñar una sola fila y el programador puede rellenarla tantas veces como sea necesario - todo lo que deben acordar es los nombres de los

parámetros.

Por todo eso, creo que lo mejor de este módulo es que hace solo una cos

a y lo hace rápida y cuidadosamente. No intenta reemplazar Perl y HTML,
solo los aumenta para interactuar un poco mejor. Y es bastante rápido.

Caché
  • cache

    Si se establece a 1, el módulo almacenará en memoria las plantillas analizadas basándose en el parámetro filename, la fecha de modificación del archivo y las opciones pasadas a new(). Esto solo se aplica a plantillas abiertas con el parámetro filename especificado, no a plantillas scalarref o arrayref. La caché también mira los tiempos de modificación de cualquier archivo incluido usando etiquetas "<TMPL_INCLUDE>", pero de nuevo, solo si la plantilla se abre con el parámetro

    filename.

    Esto es principalmente útil en un entorno persistente como Apache/mod_perl. No tiene absolutamente ningún beneficio en un entorno CGI normal, ya que el script se descarga de la memoria después de cada solicitud. Para una caché que funcione en un entorno no persistente, ver la opción "shared_cache"

    abajo.

    Mis pruebas simplistas muestran que usar cache produce un aumento del 90% en el rendimiento bajo mod_perl. Cache por defecto

    es
    • 0.
  • shared_cache

    Si se establece a 1, el módulo almacenará su caché en memoria compartida usando el módulo IPC::SharedCache (disponible en CPAN). El efecto de esto será mantener una única copia compartida de cada plantilla analizada para que todas las instancias de HTML::Template en la misma máquina la usen. Esto puede ser una reducción significativa en el uso de memoria en un entorno con una sola máquina pero múltiples servidores. Como ejemplo, en uno de nuestros sistemas usamos 4MB de caché de plantillas y mantenemos 25 procesos httpd - ¡shared_cache resulta en un ahorro de casi 100MB! Por supuesto, se espera alguna reducción en la velocidad frente a la caché normal. Otra diferencia entre la caché normal y shared_cache es que shared_cache funcionará en un entorno no persistente (como CGI normal) - la caché normal es solo útil en un entorno persistente como

    Apache/mod_perl.

    Por defecto HTML::Template usa la clave IPC 'TMPL' como un segmento raíz compartido (0x4c504d54 en hex), pero esto se puede cambiar estableciendo el parámetro "ipc_key" de new() a otra clave de 4 caracteres o entero. Otras opciones que se pueden usar para afectar la caché de memoria compartida corresponden a las opciones de IPC::SharedCache - "ipc_mode", "ipc_segment_size" y "ipc_max_size". Ver IPC::SharedCache para una descripción de cómo funcionan - en la mayoría de los casos no deberías necesitar cambiarlos de sus valores por

    defecto.

  • filter

    Esta opción te permite especificar un filtro para tus archivos de plantilla. Un filtro es una subrutina que se llamará después de que HTML::Template lea tu archivo de plantilla pero antes de que comience a analizar las etiquetas de la

    plantilla.

    En el uso más simple, simplemente asignas una referencia de código al parámetro filter. Aquí hay un ejemplo que acepta plantillas con etiquetas que se parecen a "!!!ZAP_VAR FOO!!!" y las transforma en etiquetas de HTML::

    Template: 
    my $filter = sub {
    my $text_ref = shift;
    $$text_ref =~ s/!!!ZAP_(.*?)!!!/<TMPL_$1>/g;
};
# open zap.tmpl using the above filter
my $template = HTML::Template->new(
    filename => 'zap.tmpl',
    filter   => $filter,
    );

    filter   => {
        sub    => $filtro,
        format => 'array',

);

    mi $plantilla = HTML::Template->new(
    filename => 'zap.tmpl',
    filter   => [
        {
            sub    => \&descomprimir,
            format => 'scalar',
        },
        {
            sub    => \&eliminar_espacios,
            format => 'array',
        },

);

config

Un método de paquete que se utiliza para establecer/obtener las opciones de configuración predeterminadas globales. Por ejemplo, si deseas establecer el indicador "utf8" para que siempre esté activado para cada plantilla cargada por este proceso, harías:

HTML::Template->config(utf8 => 1);

O si quisieras verificar si el indicador "utf8" está activado o no, podrías hacer:

mi %config = HTML::Template->config;
si( $config{utf8} ) {
    ...
}

Cualquier opción de configuración que sea válida para new() es aceptable para ser pasada a este método.

param

param() puede ser llamado de varias maneras

1 - Para devolver una lista de parámetros en la plantilla :
mi @nombres_parametros = $self->param();
2 - Para devolver el valor establecido a un parámetro :
mi $valor = $self->param('PARAM');
3 - Para establecer el valor de un parámetro :
# Para TMPL_VARs simples:
$self->param(PARAM => 'valor');
# con una referencia a subrutina que se llama para obtener el valor
# del escalar. La sub recibirá el objeto plantilla como parámetro.
$self->param(PARAM => sub { return 'valor' });
# Y para TMPL_LOOPs:
$self->param(LOOP_PARAM => [{PARAM => VALOR_PARA_PRIMERA_PASADA}, {PARAM => VALOR_PARA_SEGUNDA_PASADA}]);
4 - Para establecer el valor de varios parámetros :
# Para TMPL_VARs simples:
$self->param(
    PARAM  => 'valor',
    PARAM2 => 'valor'
);
# Y con algunos TMPL_LOOPs:
$self->param(
    PARAM              => 'valor',
    PARAM2             => 'valor',
    LOOP_PARAM         => [{PARAM => VALOR_PARA_PRIMERA_PASADA}, {PARAM => VALOR_PARA_SEGUNDA_PASADA}],
    ANOTHER_LOOP_PARAM => [{PARAM => VALOR_PARA_PRIMERA_PASADA}, {PARAM => VALOR_PARA_SEGUNDA_PASADA}],
);
5 - Para establecer el valor de varios parámetros usando un hash-ref :
$self->param(
    {
        PARAM              => 'valor',
        PARAM2             => 'valor',
        LOOP_PARAM         => [{PARAM => VALOR_PARA_PRIMERA_PASADA}, {PARAM => VALOR_PARA_SEGUNDA_PASADA}],
        ANOTHER_LOOP_PARAM => [{PARAM => VALOR_PARA_PRIMERA_PASADA}, {PARAM => VALOR_PARA_SEGUNDA_PASADA}],
    }
);

Se produce un error si intentas establecer un valor que está contaminado (tainted) y la opción "force_untaint" está establecida.

clear_params

Establece todos los parámetros a undef. ¡Útil internamente, si es que en algún lugar!

output

output() devuelve el resultado final de la plantilla. En la mayoría de las situaciones querrás imprimir esto, como:

imprimir $plantilla->output();

Cuando se llama a output, cada ocurrencia de "<TMPL_VAR NAME=nombre>" se reemplaza con el valor asignado a "nombre" a través de param(). Si un parámetro con nombre no está establecido, simplemente se reemplaza por ''. Los "TMPL_LOOP" se evalúan una vez por conjunto de parámetros, acumulando la salida en cada pasada.

Llamar a output() garantiza no cambiar el estado del objeto HTML::Template, por si te lo preguntabas. Esta propiedad es principalmente importante para la implementación interna de los bucles.

Opcionalmente, puedes proporcionar un manejador de archivos para imprimir automáticamente a medida que se genera la plantilla. Esto puede mejorar el rendimiento y reducir el consumo de memoria. Ejemplo:

$plantilla->output(print_to => *STDOUT);

El valor de retorno no está definido cuando se usa la opción "print_to".

query

Este método te permite obtener información sobre la estructura de la plantilla. Puede ser llamado de varias maneras. El uso más simple de query es simplemente verificar si un nombre de parámetro existe en la plantilla, usando la opción "name":

si ($plantilla->query(name => 'foo')) {
    # haz algo si una variable de cualquier tipo llamada FOO está en la plantilla
}

Este mismo uso devuelve el tipo del parámetro. El tipo es el mismo que la etiqueta menos el 'TMPL_' inicial. Así, por ejemplo, un parámetro "TMPL_VAR" devuelve 'VAR' de query().

si ($plantilla->query(name => 'foo') eq 'VAR') {
    # haz algo si FOO existe y es un TMPL_VAR
}

Ten en cuenta que las variables asociadas con "TMPL_IF" y "TMPL_UNLESS" se identificarán como 'VAR' a menos que también se utilicen en un "TMPL_LOOP", en cuyo caso devolverán 'LOOP'.

query() también te permite obtener una lista de parámetros dentro de un bucle (y dentro de bucles dentro de bucles). Ejemplo de bucle:

<TMPL_LOOP NAME="EJEMPLO_LOOP">
  <TMPL_VAR NAME="BEE">
  <TMPL_VAR NAME="BOP">
  <TMPL_LOOP NAME="EJEMPLO_LOOP_INTERIOR">
    <TMPL_VAR NAME="BEE_INTERIOR">
    <TMPL_VAR NAME="BOP_INTERIOR">
  </TMPL_LOOP>
</TMPL_LOOP>

Y algunas llamadas a query:

# devuelve 'LOOP'
$tipo = $plantilla->query(name => 'EJEMPLO_LOOP');
# devuelve ('bop', 'bee', 'ejemplo_loop_interior')
@nombres_param = $plantilla->query(loop => 'EJEMPLO_LOOP');
# ambos devuelven 'VAR'
$tipo = $plantilla->query(name => ['EJEMPLO_LOOP', 'BEE']);
$tipo = $plantilla->query(name => ['EJEMPLO_LOOP', 'BOP']);
# y este devuelve 'LOOP'
$tipo = $plantilla->query(name => ['EJEMPLO_LOOP', 'EJEMPLO_LOOP_INTERIOR']);
# y finalmente, esto devuelve ('bee_interior', 'bop_interior')
@nombres_param_interior = $plantilla->query(loop => ['EJEMPLO_LOOP', 'EJEMPLO_LOOP_INTERIOR']);
# para nombres de parámetros inexistentes obtienes undef, esto devuelve undef.
$tipo = $plantilla->query(name => 'DWEAZLE_ZAPPA');
# llamar a loop en un nombre de parámetro que no es un bucle causará un error. Esto muere:
$tipo = $plantilla->query(loop => 'DWEAZLE_ZAPPA');

Como puedes ver arriba, la opción "loop" devuelve una lista de nombres de parámetros y tanto "name" como "loop" aceptan referencias a arrays para referirse a parámetros dentro de bucles. Es un error usar "loop" con un parámetro que no es un bucle.

Ten en cuenta que todos los nombres se devuelven en minúsculas y los tipos en mayúsculas.

Al igual que param(), query() sin argumentos devuelve todos los nombres de parámetros en la plantilla en el nivel superior.

VALORES PROCRASTINADOS

Como se mencionó anteriormente, tanto los valores de "TMPL_VAR" como los de "TMPL_LOOP" pueden ser referencias de código. Estas referencias de código solo se ejecutan si la variable o el bucle se usan en la plantilla. Esto es extremadamente útil si deseas hacer disponible una variable para los diseñadores de plantillas, pero su cálculo puede ser costoso, por lo que solo quieres hacerlo si es necesario.

Tal vez un ejemplo ayude a ilustrar. Supongamos que tienes una plantilla como esta:

<tmpl_if debemos_cuidar>
  <tmpl_if vida_universo_y_todo_lo_demas>
</tmpl_if>

Si el cálculo de "vida_universo_y_todo_lo_demas" es costoso, podemos envolver su cálculo en una referencia de código y HTML::Template solo ejecutará ese código si "debemos_cuidar" también es verdadero.

$tmpl->param(vida_universo_y_todo_lo_demas => sub { calcular_42() });

Tu referencia de código recibirá un único argumento, el objeto HTML::Template en uso. En el ejemplo anterior, si quisiéramos que calcular_42() tuviera este objeto, haríamos algo como esto:

$tmpl->param(vida_universo_y_todo_lo_demas => sub { calcular_42(shift) });

Este mismo enfoque se puede usar también para "TMPL_LOOP"s:

<tmpl_if debemos_cuidar>
  <tmpl_loop agujas_en_pajar>
    ¡Encontrada <tmpl_var __contador>!
  </tmpl_loop>
</tmpl_if>

Y en tu código Perl:

$tmpl->param(agujas_en_pajar => sub { encontrar_agujas() });

La única diferencia en el caso de "TMPL_LOOP" es que la subrutina debe devolver una referencia a un ARRAY, no solo un valor escalar.

Múltiples Llamadas

Es importante reconocer que si bien esta característica está diseñada para ahorrar tiempo de procesamiento cuando las cosas no son necesarias, si no tienes cuidado, puede aumentar el número de veces que realizas

rm tu cálculo. HTML::Template llama a tu referencia de código cada vez que parece que tu bucle en el plantilla, esto incluye las veces que podrías usar el bucle en un condicional ("TMPL_IF" o "TMPL_UNLESS"). Por

ejemplo: 
<tmpl_if nos importa>
  <tmpl_if agujas_en_pajar>
      <tmpl_loop agujas_en_pajar>
        ¡Encontrada <tmpl_var __counter>!
      </tmpl_loop>
  <tmpl_else>
    ¡No se encontraron agujas!
  </tmpl_if>
</tmpl_if>

Esto en realidad llamará a find_needles() dos veces, lo cual será incluso peor que lo que tenías antes. Una forma de solucionar esto es almacenar en caché el valor de retorno tú

mismo: 
my $agujas;
$tmpl->param(agujas_en_pajar => sub { defined $agujas ? $agujas : $agujas = find_needles()
}
)
;
