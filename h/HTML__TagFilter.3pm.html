DESCRIPCIÓ

N

HTML::TagFilter es una subclase de HTML::Parser con un único propósito: eliminará etiquetas y atributos html no deseados de un fragmento de texto. Puede actuar de una manera más o menos de granularidad fina: puede especificar etiquetas permitidas, atributos permitidos de cada etiqueta y valores permitidos para cada atributo con tanto detalle como

desee.

Las etiquetas que no están permitidas se eliminan. Las etiquetas que están permitidas se recortan para que solo contengan los atributos permitidos para cada etiqueta. Es posible permitir todos o ningún atributo de una etiqueta, o permitir todos o ningún valor para un atributo, y así

sucesivamente.

El filtro también se protegerá contra ataques de cross-site scripting y ofuscará cualquier dirección de correo mailto:email, a menos que usted le indique lo

contrario.

El propósito original de esto era filtrar la entrada del usuario. En ese contexto, a menudo descubrirá que con simplemente

usar: 
my $tf = new HTML::TagFilter;
put_in_database($tf->filter($my_text))
;

será suficiente. Sin embargo, también se puede utilizar para procesos de visualización (por ejemplo, traducción a texto plano) o limpieza (por ejemplo, eliminación de javascript antiguo). En esos casos, probablemente querrá anular el conjunto de reglas predeterminado con un pequeño número de reglas de

denegación. 
my $self = HTML::TagFilter->new(deny => {img => {'all'}});
print $tf->filter($my_text)
;

Eliminará todas las imágenes, por ejemplo, pero dejará todo lo demás

intacto.

nb (faq #1) el filtro solo elimina las etiquetas en sí: todo lo que hace con el texto que no forma parte de una etiqueta es escapar los <s y >s, para protegerse de falsos negativos y algunos ataques cross-site

comunes.

REGLAS

Crear el conjunto de reglas es bastante simple. Tiene tres

opciones:

usar las

predeterminadas

lo que producirá html seguro pero aún con formato

, sin tablas, javascript ni mucho más allá del
formato de texto en línea, enlaces e imágenes.

anular selectivamente las

predeterminadas

use los métodos allow_tags y deny_tags para pasar una o más configuraciones de etiquetas adicionales. Por

ejemplo: 
$self->allow_tags({ p => { class=> ['lurid','sombre','plain']} });
$self->deny_tags({ img => { all => [] })
;

significará que todos los atributos distintos de class="lurid|sombre|plain" serán el

iminados de las etiquetas <p>, pero las otras reglas predeterminadas permanecerán si
n cambios. Vea más abajo para obtener más información sobre cómo especificar reglas.

proporcionar su propia

configuración

Para anular completamente las predeterminadas, proporcione al constructor algunas

reglas: 
my $self = HTML::TagFilter->new( 
    allow=>{ p => { class=> ['lurid','sombre','plain']} }
)
;

En este caso, solo se aplicarán las reglas que usted proporcione: las predeterminadas se ignoran. Puede lograr lo mismo después de la construcción limpiando primero el conjunto de

reglas: 
my $self = HTML::TagFilter->new();
$self->clear_rules();
$self->allow_tags({ p => { align=> ['left','right','center']} })
;

Las versiones futuras tienen la intención de ofrecer un siste

ma de reglas más sofisticado, permitiéndole especificar c
ombinaciones de atributos, rangos para valores y, en gener
al, hacer coincidir los nombres de una manera más difusa.

CONFIGURACIÓN:

COMPORTAMIENTO

Actualmente hay siete interruptores que cambiarán el comportamiento del filtro. Se proporcionan en el momento de la construcción, junto con cualquier regla que desee especificar. Todos tienen el valor predeterminado

'off': 
my $tf = HTML::TagFilter->new(
  log_rejects => 1,
  strip_comments => 1,
  echo => 1,
  verbose => 1,
  skip_xss_protection => 1,
  skip_ltgt_entification => 1,
  skip_mailto_entification => 1,
)
;

log_reject

s

Establezca log en algo verdadero y el filtro mantendrá un registro detallado de todas las etiquetas que elimina. El registro se puede recuperar llamando a report(), que devolverá un resumen en contexto escalar y un AoH detallado en

lista.

ech

o

Establezca echo en 1, o cualquier cosa verdadera, y la salida del filtro se enviará directamente a STDOUT. De lo contrario, el filtro permanecerá en silencio hasta que llame a output

().

verbos

e

Establezca verbose en 1, o cualquier cosa verdadera, y los mensajes de error se emitirán en STDERR además de almacenarse para una llamada a error

().

strip_comment

s

Establezca strip_comments en 1 y los comentarios serán eliminados. Si no lo hace, no lo

serán.

skip_xss_protectio

n

A menos que establezca skip_xss_protection en 1, el filtro postprocesará parte de su salida para proteger contra ataques comunes de cross-site

scripting.

Convertirá en entidades cualquier < y > en texto que no sea etiqueta, convertirá en entidades las comillas en los valores de los atributos (el Parser las habrá decodificado) y eliminará los valores de los atributos vulnerables si no parecen ser urls adecuadas. De forma predeterminada, se verifican estos atributos: src, lowsrc, href, background y cite. Puede reemplazar esa lista (no ampliarla) en cualquier

momento: 
$self->xss_risky_attributes( qw(your list of attributes) )
;

skip_ltgt_entificatio

n

Desactiva la conversión en entidades de < y > incluso si la protección cross-site está

activada.

skip_mailto_entificatio

n

A menos que especifique lo contrario, cualquier mailto:url visto por el filtro se convertirá completamente en entidades html. <a href="mailto:wross@cpan.org">will</a> se convierte en <a href="mailto:%77%72%6F%73%73%40%63%70%61%6E%2E%6F%72%67">will</a>. Esto debería derrotar a la mayoría del software de recolección de correos electrónicos, pero tenga en cuenta que no tiene ningún efecto en el texto de su enlace, solo en su dirección. Enlaces como <a href="mailto:wross@cpan.org">wross@cpan.org</a> están solo parcialmente ocultados y deberían

evitarse.

REGLA

S

Cada elemento se prueba a medida que se encuentra, en dos

etapas:

filtro de

etiqueta

Solo comprueba si esta etiqueta está permitida, y bloquea todo el elemento si no lo está. Se aplica tanto a etiquetas de apertura como de

cierre.

filtro de

atributo

Cualquier etiqueta que pase el filtro de etiqueta permanecerá en el texto, pero el filtro de atributo eliminará de ella cualquier atributo que no esté permitido, o que tenga valores que no estén permitidos para esa combinación de etiqueta/atributo

.

formato de las

reglas

Hay dos tipos de reglas: permisos y denegaciones. Funcionan como se espera y pueden coexistir, pero no son del todo simétricas. Las reglas de denegación están destinadas a complementar las reglas de permiso, para que puedan proporcionar una especie de 'a menos que'

compuesto.

* Si hay alguna regla de 'permiso', entonces todo lo que no cumpla con ninguna de ellas se

elimina.

* Si existen reglas de 'denegación' (deny), entonces cualquier cosa que satisfaga alguna de ellas es

eliminada.

* Si existen tanto reglas de denegación como de permiso, entonces se elimina todo lo que satisfaga una regla de denegación o no satisfaga alguna de las reglas de

permiso.

* Si no hay ninguno de los dos tipos, eliminamos todo por si

acaso.

Las dos configuraciones más probables

son

1. un conjunto completo de reglas de permiso y quizás un par de reglas de denegación para eliminar molestias

personales.

2. ninguna regla de permiso en absoluto y un pequeño conjunto de reglas de denegación para eliminar etiquetas

particulares.

Las reglas se pasan como un

HoHoL: 
{ nombre de etiqueta->{nombre de atributo}->[lista de valores]
}

Hay tres palabras reservadas: 'any' y 'none' significan respectivamente 'se permite cualquier cosa' y 'no se permite nada', o si están en denegación: 'se elimina cualquier cosa' y 'no se elimina nada'. 'all' solo se usa en reglas de denegación e indica que la etiqueta completa debe ser eliminada: ver abajo para una explicación y algunas excusas

murmuradas.

Por

ejemplo: 
$self->allow_tags({ p => { any => [] })
;

Permitirá etiquetas <p> con cualquier atributo. Por claridad, puede acortarse

a: 
$self->allow_tags({ p => { 'any' })
;

pero ten en cuenta que obtendrás una advertencia sobre el número impar de elementos de hash si -w está activado, y en ausencia de => las comillas son necesarias.

Y 
$self->allow_tags({ p => { none => [] })
;

Permitirá que las etiquetas <p> permanezcan en el texto, pero todos los atributos serán eliminados. Las mismas reglas se aplican en todos los niveles de la jerarquía etiqueta/atributo/valor, así que puedes decir cosas

como: 
$self->allow_tags({ any => { align => [qw(left center right)] });
$self->allow_tags({ p => { align => ['any'] }
)
;

ejemplo

s

Para indicar que un destino de enlace está bien y no te importa qué valor

tome: 
$self->allow_tags({ a => { 'href' } })
;

Para limitar los valores que un atributo puede

tomar: 
$self->allow_tags({ a => { class => [qw(big small middling)] } })
;

Para limpiar todos los

permisos: 
$self->allow_tags({})
;

Para eliminar todos los onClick de los enlaces pero permitir todos los

targets: 
$self->allow_tags({ a => { onClick => ['none'], target => [], } })
;

Puedes combinar permisos y denegaciones para crear reglas 'a menos

que': 
$self->allow_tags({ a => { any => [] } });
$self->deny_tags({ a => { onClick => [] } })
;

Eliminará solo el atributo onClick de un enlace, permitiendo todo lo demás. Si este era tu úni

co propósito, podrías lograr lo mismo solo con la regla de denegación y un conjunto de permiso
s vacío, pero si hay otras cosas ocurriendo entonces probablemente necesites esta combinación.

orden de

aplicación

Las reglas de denegación se aplican primero. Primero eliminamos lo que especifiques en deny, luego eliminamos lo que no especifiques en allow, a menos que el conjunto de permisos esté vacío, en cuyo caso lo ignoramos. Si ambos conjuntos están vacíos, ninguna etiqueta

pasa.

(Preferimos errar por el lado d

e menos marcado, pero espero que
esto sea configurable pronto.)

peculiaridad

es

Solo una deliberada, hasta ahora. La principal asimetría entre las reglas de permiso y denegación es que

de 
allow_tags->{ p => {...}
}

se deduce que las etiquetas p están permitidas, pero lo contrario no es

cierto: 
deny_tags->{ p => {...}
}

no implica que las etiquetas p sean eliminadas, solo que los atributos relevantes son eliminados de ellas. Si quieres usar una regla de denegación para eliminar una etiqueta completa, tienes que decirlo

explícitamente: 
deny_tags->{ p => {'all'}
}

eliminará cada etiqueta <p>, mientras

que 
deny_tags->{ p => {'any'}
}

solo eliminará todos los atributos de las etiquetas <p

>. No es muy bonito, lo sé. Es probable que cambie, per
o probablemente no hasta que hayamos inventado un siste
ma para proporcionar reglas en un formato más legible.

CALLBACK

S

Se proporcionan varios puntos de activación para la conveniencia de las personas que quieren extender en lugar de reemplazar el comportamiento normal de un objeto tagfilter. Para usarlos, solo pasas una referencia de código con el nombre apropiado en el momento de la

construcción.

El ejemplo de abajo mantendrá una pila de etiquetas vistas y hará que el filtro repare el anidamiento de etiquetas, de modo que cualquier etiqueta sin cerrar se cierre aproximadamente en el lugar correcto, y cualquier etiqueta de cierre sin apertura se

omita: 
my $filter = HTML::TagFilter->new(
      on_start_document => sub {
              my ($self, $rawtext) = @_;
              $self->{_tag_stack} = [];
              return;
      },
      on_open_tag => sub {
              my ($self, $tag, $attributes, $sequence) = @_;
              push @{ $self->{_tag_stack} }, $$tag unless grep {$_ eq $$tag} qw(img br hr meta link);
              return;
      },
      on_close_tag => sub {
              my ($self, $tag) = @_;
              unless (@{ $self->{_tag_stack} } && grep {$_ eq $$tag} @{ $self->{_tag_stack} }) {
                      undef ${ $tag };
                      return;
              }
              my @unclosed;
              while (my $lasttag = pop @{ $self->{_tag_stack} })  {
                      return join '', map "</$_>", @unclosed if $lasttag eq $$tag;
                      push @unclosed, $lasttag;
              }
      },
      on_finish_document => sub {
              my ($self, $cleantext) = @_;
              return join '', map "</$_>", reverse @{ $self->{_tag_stack} };
      },
)
;

También puedes rellenar estos puntos de activación en una subclase: Si no se proporciona un método de callback, llamaremos al método de clase con el mismo nombre (punto de activación) en su lugar. En esta clase esos métodos no hacen nada, así que puedes sobreescribirlos selectivamente sin afectar la funcionalidad normal. Para cambiar todas las etiquetas <b> a etiquetas <strong>, por

ejemplo: 
sub on_open_tag {
      my ($self, $tag, $attributes, $sequence) = @_;
      $$tag = 'strong' if $$tag eq 'b';
}
sub on_close_tag {
      my ($self, $tag) = @_;
      $$tag = 'strong' if $$tag eq 'b';
}

Como puedes ver aquí, los valores de la etiqueta y el atributo se pasan como referencias de cadena: los cambios que hagas en el callback cambiarán la etiqueta

misma.

Los puntos de activación disponibles

son:

on_construct

()

Esto se llama durante la construcción de un nuevo objeto TagFilter, justo antes de que el objeto construido sea devuelto. No recibe argumentos aparte del objeto

tagfilter.

on_start_document ( $text

)

Esto es llamado por el método filter(), y recibe una referencia al texto que va a ser filtrado. Puedes cambiar el texto, o devolver cualquier valor que deba ser anteponido a la

salida.

on_open_tag ( $tagname, $attributes, $attribute_sequence

)

Esto es llamado por el método filter_start(), que es el verificador de etiquetas de apertura y únicas. Se le pasan las mismas variables que usa ese método: el nombre de la etiqueta, un hashref que contiene todos sus atributos y un listref que contiene los nombres de los atributos en

orden.

Junto con on_close_tag, este hook es muy útil para añadir funciones de limpieza de documentos como el cierre de etiquetas, o para un registro más sofisticado que el que tagfilter proporciona por sí

mismo.

on_process_text ( $text

)

Normalmente solo traducimos caracteres no permitidos en bloques de texto, pero este método recibe una referencia a la cadena de texto, así que puedes hacer lo que quieras con

ella.

Ten en cuenta que si solo quieres añadir más caracteres no permitidos, puedes simplemente subclasificar

character_map().

on_close_tag ( $text

)

Esto es llamado por el método filter_end(), que es el verificador de etiquetas de cierre. Se le pasa el nombre de la etiqueta de

cierre.

on_finish_document ( $text

)

Esto es llamado por el método output(). No recibe argumentos, o nos enredamos un poco con la sali

da, pero lo que sea que devuelvas será
añadido a la cadena de salida final.

MÉTODOS DE

FILTRADO

Estos componen la interfaz principal. Probablemente no necesitarás llamar a nada más que filter

().

$tf->filter($html)

;

Exactamente equivalente

a: 
$tf->parse($html);
$tf->output()
;

pero más útil, porque cabrá en un one-liner.

ej: 
print $tf->filter( $pages{$_} ) for keys
%pages;

Ten en cuenta que llamar a filter() borrará cualquier cosa que estuviera esperando en el búfer de salida, y borrará el búfer de nuevo cuando termine. Está pensado para ser una operación de un solo disparo y no coopera bien. Usa parse() y output() si quieres

encadenarlos.

parse($text)

;

El método parse hereda de HTML::Parser, pero la mayoría de sus métodos auxiliares se subclasifican aquí y la salida que normalmente imprimen se guarda para más tarde. Las otras opciones de configuración que HTML::Parser ofrece normalmente no se pasan en este momento, ni puedes sobreescribir las definiciones de manejadores en este

módulo.

output()

Esto devolverá y borrará el búfer de salida. Concluirá el procesamiento de tu texto, pero por supuesto puedes pasar una nueva pieza de texto al mismo objeto parser y comenzar de

nuevo.

report()

Si se llama en contexto de lista, devuelve el array de combinaciones de etiqueta/atributo/valor

rechazadas.

En contexto escalar devuelve un resumen más o menos legible. Devuelve () si el registro no está habilitado. Borra el

registro.

filter_start($tag, $attributes_hashref, $attribute_sequence_listref)

;

Este es el manejador para etiquetas de inicio de html: verifica la etiqueta contra el conjunto actual de reglas, luego verifica cada atributo y su valor. Cualquier texto que falle es eliminado: el resto se pasa a

output.

filter_end($tag)

;

Este es el manejador para las etiquetas de cierre html: comprueba la etiqueta contra el conjunto actual de reglas y la pasa a la salida si es

correcta.

clean_text($text)

;

Este es el manejador para el texto: cualquier cosa que no sea una etiqueta pasa por aquí antes de ser enviada a la salida. Por el momento, solo aplica una protección muy simple contra sitios cruzados: subclasificar este método es una forma fácil de modificar solo la parte de texto de su

página.

character_map($text)

;

Devuelve una referencia a un hash de {caracter_no_permitido => caracter_de_reemplazo} para su uso al limpiar bloques de

texto.

add_to_output($text)

;

El texto proporcionado se añade al búfer de salida (o se imprime inmediatamente, si la opción echo está activada)

.

logging($boolean)

;

Esto proporciona acceso de obtención o configuración al parámetro de configuración 'log'. Activar o desactivar el registro durante el análisis resultará, por supuesto, en informes

incompletos.

log_denied($refused_tag)

;

Si el registro está activado, este método añadirá la información de fallo propor

cionada al registro. La forma estándar para esto es una referencia a un hash que
contendrá algunas o todas estas claves: 'tag', 'attribute', 'value' y 'reason'.

COMPROBADORES DE

REGLAS

Compara etiquetas y atributos individuales contra el conjunto de reglas actualmente en vigor. Estos métodos simples son el núcleo de tagfilter: la mayor parte del resto es configuración, y los métodos de filtrado son realmente solo pegamento para conectar estas pruebas con el progreso de HTML::Parser a través de un

documento.

tag_ok($tag)

;

Devuelve verdadero si el nombre de etiqueta proporcionado está permitido en el texto. Si no, devuelve falso y registra el fallo con el motivo

'tag'.

attribute_ok($tag, $attribute)

;

Devuelve verdadero si ese atributo está permitido para esa etiqueta, y si se le permite tener el valor proporcionado. Si no, devuelve falso y registra el fallo con el motivo

'attribute'.

url_ok($tag, $attributes, $value)

;

Si la protección xss está activada, verificamos si este atributo es un cam

po de url, y si lo es, verificamos que la url sea una url (y no una etiqu
eta de script u otra maldad). Los fallos se registran con el motivo 'url'.

métodos de

configuración

La configuración del filtro se mantiene en un hash de hashes, al que aquí se suele referir como hohoho, ya que normalmente tiene al menos tres niveles. Estos métodos esperan recibir conjuntos de reglas completos o parciales en la forma simplificada descrita anteriormente y los fusionan en - o los colocan sobre - el conjunto

activo.

allow_tags($hashref

)

Toma una referencia a un hash de permisos y la añade a lo que ya tenemos, reemplazando a nivel de etiqueta donde ya se han definido reglas. En otras palabras, puede añadir una etiqueta al conjunto existente, pero para añadir un atributo a una etiqueta existente tiene que especificar el conjunto completo de permisos de

atributos.

Si no se envían reglas (por ejemplo, una referencia a un hash vacío, o nada en absoluto, o una referencia que no es a un hash), esto borra el conjunto de reglas de

permisos.

deny_tags($hashref

)

igual pero establece (o borra) reglas de

denegación.

has_rules()

Devuelve verdadero solo si se han definido reglas de permitir o

denegar.

has_allow_rules()

Devuelve verdadero si se han definido reglas de

permitir.

has_deny_rules()

Devuelve verdadero si se han definido reglas de

Borra el conjunto de reglas completo, listo para recibir un nuevo conjunto. Un filtro sin reglas eliminará *todo* el html del texto proporcionado, por

Devuelve el conjunto completo de permisos como un HoHoho. No se puede establecer de esta manera: es solo una función de utilidad por si quiere mostrar el conjunto de reglas, o obtener el conjunto completo para poder devolverlo a allow_tags en una forma

configuración

XSS

Los ataques de scripting entre sitios se inventan o se identifican todo el tiempo. Intentaremos mantenernos al día, pero usted puede ser más paranoico o estar más al día que nosotros: si es así, simplemente sobrescriba uno o más de estos

métodos.

xss_risky_attributes( @list_of_attributes )

;

Establece y devuelve una lista de atributos que se consideran urls, y que deben comprobarse para ver si están bien

formados.

La lista predeterminada es href, src, lowsrc, cite y background: cualquier valor proporcionado se utilizará para reemplazar (no para extender) esta

lista.

xss_permitted_protocols( @list_of_prefixes )

;

Establece y devuelve una lista de protocolos que son aceptables en atributos que consideramos urls (es decir, que están en la lista devuelta por "xss_risky_attri

butes").

La lista predeterminada es http, https, ftp y mailto. Cualquier valor proporcionado se utilizará para reemplazar (no para extender) esta lista. No incluya los dos

puntos.

xss_allow_local_links( $boolean )

;

Si este método devuelve un valor verdadero, entonces se aceptarán las direcciones que comienzan con '/' o '../' en los campos de

url.

Puede establecer este valor llamando al método con un parámetro, como es habitual. El valor predeterminado es

verdadero.

error()

Devuelve un informe de errores de utilidad actualmente dudosa. Si desea registrar mensajes de error en una subclase, llame a $self->_add_error(@messages)

.
