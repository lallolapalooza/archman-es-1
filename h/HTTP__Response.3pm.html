HTTP::Response(3) Documentación de Perl aportada por el usuario HTTP::Response(3)

SINÓPSIS

Los objetos de respuesta son devueltos por el método request() de "LWP::UserAgent":

# ...
$response = $ua->request($request);
if ($response->is_success) {
    print $response->decoded_content;
}
else {
    print STDERR $response->status_line, "\n";
}

DESCRIPCIÓN

"HTTP::Response" es la clase que encapsula las respuestas de estilo HTTP. Una respuesta consiste en una línea de respuesta, algunas cabeceras y un cuerpo de contenido. Tenga en cuenta que la biblioteca LWP utiliza respuestas de estilo HTTP incluso para esquemas de protocolo que no son HTTP. Las instancias de esta clase suelen ser creadas y devueltas por el método request() de un objeto "LWP::UserAgent".

"HTTP::Response" es una subclase de "HTTP::Message" y, por lo tanto, hereda sus métodos. Los siguientes métodos adicionales están disponibles:

$r = HTTP::Response->new( $code )
$r = HTTP::Response->new( $code, $msg )
$r = HTTP::Response->new( $code, $msg, $header )
$r = HTTP::Response->new( $code, $msg, $header, $content )
Construye un nuevo objeto "HTTP::Response" que describe una respuesta con el código de respuesta $code y un mensaje opcional $msg. El argumento opcional $header debe ser una referencia a un objeto "HTTP::Headers" o una referencia a un array plano de pares clave/valor. El argumento opcional $content debe ser una cadena de bytes. Los significados de estos argumentos se describen a continuación.
$r = HTTP::Response->parse( $str )
Esto construye un nuevo objeto de respuesta analizando la cadena dada.
$r->code
$r->code( $code )
Esto se utiliza para obtener/establecer el atributo de código. El código es un número de 3 dígitos que codifica el resultado general de una respuesta HTTP. El módulo "HTTP::Status" proporciona constantes que ofrecen nombres mnemotécnicos para el atributo de código.
$r->message
$r->message( $message )
Esto se utiliza para obtener/establecer el atributo de mensaje. El mensaje es una cadena corta, legible por humanos y de una sola línea que explica el código de respuesta.
$r->header( $field )
$r->header( $field => $value )
Esto se utiliza para obtener/establecer valores de cabecera y se hereda de "HTTP::Headers" a través de "HTTP::Message". Consulte HTTP::Headers para obtener detalles y otros métodos similares que se pueden utilizar para acceder a las cabeceras.
$r->content
$r->content( $bytes )
Esto se utiliza para obtener/establecer el contenido sin procesar y se hereda de la clase base "HTTP::Message". Consulte HTTP::Message para obtener detalles y otros métodos que se pueden utilizar para acceder al contenido.
$r->decoded_content( %options )
Esto devolverá el contenido después de decodificar cualquier "Content-Encoding" y conjuntos de caracteres. Consulte HTTP::Message para obtener detalles.
$r->request
$r->request( $request )
Esto se utiliza para obtener/establecer el atributo de solicitud. El atributo de solicitud es una referencia a la solicitud que causó esta respuesta. No necesariamente tiene que ser la misma solicitud pasada al método $ua->request(), ya que podría haber habido redirecciones y reintentos de autorización en el medio.
$r->previous
$r->previous( $response )
Esto se utiliza para obtener/establecer el atributo anterior. El atributo anterior se utiliza para encadenar respuestas. Obtiene cadenas de respuestas si la primera respuesta es una redirección o no autorizada. El valor es "undef" si esta es la primera respuesta de una cadena.

Tenga en cuenta que el método $r->redirects se proporciona como una forma más conveniente de acceder a la cadena de respuestas.

$r->status_line
Devuelve la cadena "<code> <message>". Si el atributo de mensaje no está establecido, se sustituye el nombre oficial de <code> (ver HTTP::Status).
$r->base
Devuelve la URI base para esta respuesta. El valor devuelto será una referencia a un objeto URI.

La URI base se obtiene de una de las siguientes fuentes (en orden de prioridad):

1.
Incrustada en el contenido del documento, por ejemplo, <BASE HREF="..."> en documentos HTML.
2.
Una cabecera "Content-Base:" en la respuesta.

Para compatibilidad con versiones anteriores de implementaciones HTTP, también buscaremos la cabecera "Base:".

3.
La URI utilizada para solicitar esta respuesta. Es posible que no sea la URI original que se pasó al método $ua->request(), ya que podríamos haber recibido algunas respuestas de redirección primero.

Si ninguna de estas fuentes proporciona una URI absoluta, se devuelve undef.

Nota: Versiones anteriores de HTTP::Response también consideraban una cabecera "Content-Location:", como decía la RFC 2616 https://www.rfc-editor.org/rfc/rfc2616. Pero esto nunca fue ampliamente implementado por los navegadores, y ahora la RFC 7231 https://www.rfc-editor.org/rfc/rfc7231 dice que ya no debe considerarse.

Cuando los módulos de protocolo LWP producen el objeto HTTP::Response, cualquier URI base incrustada en el documento (paso 1) ya habrá inicializado la cabecera "Content-Base:". (Ver "parse_head" en LWP::UserAgent). Esto significa que este método solo realiza los últimos 2 pasos (el contenido no siempre está disponible tampoco).

$r->filename
Devuelve un nombre de archivo para esta respuesta. Tenga en cuenta que la responsabilidad de realizar comprobaciones de sanidad en el nombre de archivo devuelto (por ejemplo, eliminar caracteres que no se pueden usar en el sistema de archivos de destino donde se utilizaría el nombre de archivo y desinfectarlo con fines de seguridad) recae en el llamador; lo único relacionado que hace este método es que intenta devolver un nombre de archivo simple sin segmentos de ruta previos.

El nombre de archivo se obtiene de una de las siguientes fuentes (en orden de prioridad):

1.
Una cabecera "Content-Disposition:" en la respuesta. La decodificación correcta de los nombres de archivo codificados RFC 2047 requiere los módulos "MIME::QuotedPrint" (para la codificación "Q"), "MIME::Base64" (para la codificación "B") y "Encode".
2.
Una cabecera "Content-Location:" en la respuesta.
3.
La URI utilizada para solicitar esta respuesta. Es posible que no sea la URI original que se pasó al método $ua->request(), ya que podríamos haber recibido algunas respuestas de redirección primero.

Si no se puede derivar un nombre de archivo de ninguna de estas fuentes, se devuelve undef.

$r->as_string
$r->as_string( $eol )
Devuelve una representación textual de la respuesta.
$r->is_info
$r->is_success
$r->is_redirect
$r->is_error
$r->is_client_error
$r->is_server_error
Estos métodos indican si la respuesta fue informativa, exitosa, una redirección o un error. Consulte HTTP::Status para conocer el significado de estos.
$r->error_as_HTML
Devuelve una cadena que contiene un documento HTML completo que indica qué error ocurrió. Este método solo debe llamarse cuando $r->is_error es VERDADERO.
$r->redirects
Devuelve la lista de respuestas de redirección que conducen a esta respuesta siguiendo la cadena $r->previous. El orden de la lista es de la más antigua a la más reciente.

En contexto escalar, devuelve el número de respuestas de redirección que conducen a esta.

$r->current_age
Calcula la "edad actual" de la respuesta según lo especificado en la sección 13.2.3 de la RFC 2616. La edad de una respuesta es el tiempo transcurrido desde que fue enviada por el servidor de origen. El valor devuelto es un número que representa la edad en segundos.
$r->freshness_lifetime( %opt )
/dt>
Calcula la "vida útil de frescura" de la respuesta según lo especificado en la sección 13.2.4 de RFC 2616. La "vida útil de frescura" es la longitud de tiempo entre la generación de una respuesta y su tiempo de expiración. El valor devuelto es el número de segundos hasta la expiración.

Si la respuesta no contiene una cabecera "Expires" ni una "Cache-Control", entonces esta función aplicará alguna heurística simple basada en la cabecera "Last-Modified" para determinar una vida útil adecuada. Las siguientes opciones podrían pasarse para controlar las heurísticas:

heuristic_expiry => $bool
Si se pasa como un valor FALSE, no aplique heurísticas y simplemente devuelva "undef" cuando falte "Expires" o "Cache-Control".
h_lastmod_fraction => $num
Este número representa la fracción de la diferencia desde la marca de tiempo "Last-Modified" para hacer el tiempo de expiración. El valor por defecto es 0.10, la configuración típica sugerida del 10% en RFC 2616.
h_min => $sec
Este es el límite inferior de la edad de expiración heurística a usar. El valor por defecto es 60 (1 minuto).
h_max => $sec
Este es el límite superior de la edad de expiración heurística a usar. El valor por defecto es 86400 (24 horas).
h_default => $sec
Esta es la edad de expiración a usar cuando no se aplica nada más. El valor por defecto es 3600 (1 hora) o "h_min" si es mayor.
$r->is_fresh( %opt )
Devuelve TRUE si la respuesta está fresca, basándose en los valores de freshness_lifetime() y current_age(). Si la respuesta ya no está fresca, entonces tiene que ser re-obtenida o re-validada por el servidor de origen.

Se pueden pasar opciones para controlar las heurísticas de expiración, vea la descripción de freshness_lifetime().

$r->fresh_until( %opt )
Devuelve el tiempo (segundos desde la época) cuando esta entidad ya no está fresca.

Se pueden pasar opciones para controlar las heurísticas de expiración, vea la descripción de freshness_lifetime().
