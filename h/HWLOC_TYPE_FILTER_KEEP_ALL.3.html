Descripción Detallada

Varias funciones pueden ser llamadas opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación de tipo enumerado

enum hwloc_topology_flags_e

Flags para ser establecidos en un contexto de topología antes de la carga. Los flags deben ser pasados a hwloc_topology_set_flags(). También pueden ser devueltos por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detectar todo el sistema, ignorar reservas, incluir objetos no permitidos. Recolectar todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignorar Cgroup/Cpusets de Linux y recolectar todos los procesadores y nodos de memoria. Sin embargo, las PU (Unidades de Procesamiento) y nodos NUMA fuera de línea todavía se ignoran.

Cuando este flag no está establecido, las PU y los nodos NUMA que no están permitidos no se añaden a la topología. Los objetos padres (paquete, núcleo, caché, etc.) se añaden solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y conjunto de nodos del objeto raíz.

Cuando este flag está establecido, los conjuntos reales de PU y nodos NUMA permitidos son dados por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, este flag debe ser establecido nuevamente en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asumir que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando, incluso si no es el backend específico del SO sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace llamen realmente a las llamadas del sistema específicas del SO y realmente hagan el enlace, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que simplemente devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto puede ser utilizado por razones de eficiencia para detectar la topología una vez, guardarla en un archivo XML, y recargarla rápidamente más tarde a través del backend XML, pero aún así teniendo las funciones de enlace realmente haciendo el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtener el conjunto de recursos permitidos del sistema operativo local incluso si la topología fue cargada desde XML o descripción sintética. Si la topología fue cargada desde XML o de una cadena sintética, restringerla aplicando las restricciones del proceso actual, como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente de la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Este flag se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecido, ya que la topología cargada debe coincidir con la máquina subyacente de la que se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importar soporte de la topología importada. Al importar una topología XML de una máquina remota, el enlace está deshabilitado por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits de características compatibles correspondientes informados por hwloc_topology_get_support().

El flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT en realidad importa bits de soporte de la máquina remota. También establece el flag imported_support en el array struct hwloc_topology_misc_support. Si el XML importado no contenía ninguna información de soporte (el exportador hwloc es demasiado antiguo), este flag no se establece.

Tenga en cuenta que estas características compatibles solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar según el sistema operativo o cómo se compiló hwloc).

Tenga en cuenta que establecer este flag, sin embargo, no habilita el enlace para la topología hwloc importada localmente, solo informa lo que el hwloc remoto y la máquina soportan.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considerar recursos fuera del enlace de CPU del proceso. Si el enlace del proceso está limitado a un subconjunto de núcleos, ignorar los otros núcleos durante la detección de topología.

Esto es útil cuando se detecta la topología para un subproceso o un proceso hijo que está limitado a un subconjunto de la máquina, y se desea que la topología refleje solo los recursos accesibles para ese proceso.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considerar recursos fuera del enlace de memoria del proceso. Si el enlace de memoria del proceso está limitado a un subconjunto de nodos NUMA, ignorar los otros nodos NUMA durante la detección de topología.

Esto es útil cuando se detecta la topología para un subproceso o un proceso hijo que está limitado a un subconjunto de memoria de la máquina, y se desea que la topología refleje solo los recursos de memoria accesibles para ese proceso.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
No cambiar el enlace de CPU del proceso actual. Por defecto, las funciones de enlace (como hwloc_set_cpubind()) pueden cambiar el enlace de CPU del proceso actual al intentar establecer el enlace de CPU de un objeto de destino. Este flag deshabilita este cambio.

Por ejemplo, si se llama a hwloc_set_cpubind() con un hilo específico, el enlace de CPU de ese hilo se establecerá, pero el enlace de CPU del proceso padre no se modificará. Sin este flag, el enlace de CPU del proceso padre también podría modificarse para incluir el hilo enlazado, dependiendo del sistema operativo.

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
No detectar ni publicar distancias de latencia entre objetos de memoria. La detección de distancias de latencia puede ser costosa en algunos sistemas.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
No detectar ni publicar atributos de memoria (como tipos de memoria, tamaños, etc.) en objetos de memoria (nodos NUMA, cachés). La detección de atributos de memoria puede ser costosa en algunos sistemas.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
No detectar ni publicar grupos de CPU (CPU kinds) que representan diferentes tipos de CPUs dentro del mismo paquete o nodo NUMA. La detección de grupos de CPU puede ser costosa en algunos sistemas.

enum hwloc_type_filter_e

Filtros para tipos de objetos de topología.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Mantener todos los objetos del tipo especificado. Este es el comportamiento por defecto.
HWLOC_TYPE_FILTER_KEEP_NONE
No mantener ningún objeto del tipo especificado. Todos los objetos de este tipo serán ignorados durante la detección de topología.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Mantener solo los objetos del tipo especificado que son necesarios para definir la estructura de la topología. Por ejemplo, para los objetos de caché, esto mantendría solo las cachés de nivel superior (L3, por ejemplo) si el nivel de caché es más profundo, pero omitiría las cachés de nivel inferior (L1, L2) que están dentro de ellas.
HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Mantener solo los objetos del tipo especificado que se consideran "importantes" por defecto. Por ejemplo, esto podría mantener los paquetes, los núcleos y los nodos NUMA, pero ignorar las cachés de nivel inferior (L1, L2) o los dispositivos de E/S.

Flags

enum hwloc_topology_flags_e

Flags for topology discovery. These flags may be passed to hwloc_topology_set_flags() to modify the discovery process.

Some flags are relevant only to specific backends. For example, flags related to binding are ignored if the operating system does not support binding.

Enumerator

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
When importing topology from an XML file, also import the support information from the file. If this flag is not set, the support information is ignored and the support structure (see hwloc_topology_get_support()) is populated with the support of the importing system. If this flag is set, the support information is imported from the XML file and the support structure describes the support of the system that exported the XML file. This flag is ignored if the topology is not imported from an XML file.
HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Declare that the topology is for the current system. This flag is set by default when loading the topology. It should be unset if the topology is loaded from an XML file or a synthetic description, or if hwloc is used in a restricted environment (e.g. chroot) where it may not be able to detect the system's actual configuration.
HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED
If this flag is set, hwloc will assume that the system is the current system, even if it's not directly detectable. This is useful for various use cases, for example, when hwloc is run inside a virtual machine that tries to simulate a different machine. For instance, if a virtual machine is configured to use CPU 0-7, and the host system only exposes CPU 0-3, hwloc might query the host rather than the virtual machine. Setting this flag will force hwloc to consider the virtual machine's CPU configuration. This flag implies HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM.
HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM
Do not restrict discovery to the current process's CPU binding. By default, some backends (like x86) restrict discovery to the set of logical processors that the current thread is allowed to run on. This flag disables this restriction. It should be used carefully as it may lead to discovering resources that are not accessible by the current process.
HWLOC_TOPOLOGY_FLAG_GROUP_CPUBINDING
Group objects according to the process CPU binding. This flag is only relevant when HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM is set. It enables grouping CPU objects together according to the CPU binding of the current process.
HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Do not consider resources outside of the process CPU binding. If the binding of the process is limited to a subset of cores, ignore the other cores during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag especially tells the x86 backend to never temporarily rebind a thread on any excluded core. This is useful on Windows because such temporary rebinding can change the process binding. Another use-case is to avoid cores that would not be able to perform the hwloc discovery anytime soon because they are busy executing some high-priority real-time tasks.

If process CPU binding is not supported, the thread CPU binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Do not consider resources outside of the process memory binding. If the binding of the process is limited to a subset of NUMA nodes, ignore the other NUMA nodes during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag is meant to be used together with HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING when both cores and NUMA nodes should be ignored outside of the process binding.

If process memory binding is not supported, the thread memory binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Do not ever modify the process or thread binding during discovery. This flag disables all hwloc discovery steps that require a change of the process or thread binding. This currently only affects the x86 backend which gets entirely disabled.

This is useful when hwloc_topology_load() is called while the application also creates additional threads or modifies the binding.

This flag is also a strict way to make sure the process binding will not change to due thread binding changes on Windows (see HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignore distances. Ignore distance information from the operating systems (and from XML) and hence do not use distances for grouping.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignore memory attributes and tiers. Ignore memory attribues from the operating systems (and from XML) Hence also do not try to build memory tiers.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignore CPU Kinds. Ignore CPU kind information from the operating systems (and from XML).

enum hwloc_type_filter_e

Type filtering flags. By default, most objects are kept (HWLOC_TYPE_FILTER_KEEP_ALL). Instruction caches, memory-side caches, I/O and Misc objects are ignored by default (HWLOC_TYPE_FILTER_KEEP_NONE). Group levels are ignored unless they bring structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Note that group objects are also ignored individually (without the entire level) when they do not bring structure.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Keep all objects of this type. Cannot be set for HWLOC_OBJ_GROUP (groups are designed only to add more structure to the topology).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignore all objects of this type. The bottom-level type HWLOC_OBJ_PU, the HWLOC_OBJ_NUMANODE type, and the top-level type HWLOC_OBJ_MACHINE may not be ignored.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Only ignore objects if their entire level does not bring any structure. Keep the entire level of objects if at least one of these objects adds structure to the topology. An object brings structure when it has multiple children and it is not the only child of its parent.

If all objects in the level are the only child of their parent, and if none of them has multiple children, the entire level is removed.

Cannot be set for I/O and Misc objects since the topology structure does not matter there.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Only keep likely-important objects of the given type. It is only useful for I/O object types. For HWLOC_OBJ_PCI_DEVICE and HWLOC_OBJ_OS_DEVICE, it means that only objects of major/common kinds are kept (storage, network, OpenFabrics, CUDA, OpenCL, RSMI, NVML, and displays). Also, only OS devices directly attached on PCI (e.g. no USB) are reported. For HWLOC_OBJ_BRIDGE, it means that bridges are kept only if they have children.

This flag equivalent to HWLOC_TYPE_FILTER_KEEP_ALL for Normal, Memory and Misc types since they are likely important.

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Retrieve the topology support. Each flag indicates whether a feature is supported. If set to 0, the feature is not supported. If set to 1, the feature is supported, but the corresponding call may still fail in some corner cases.

These features are also listed by hwloc-info --support

The reported features are what the current topology supports on the current machine. If the topology was exported to XML from another machine and later imported here, support still describes what is supported for this imported topology after import. By default, binding will be reported as unsupported in this case (see HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

Topology flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT may be used to report the supported features of the original remote machine instead. If it was successfully imported, imported_support will be set in the struct hwloc_topology_misc_support array.

Returns

A pointer to a support structure.

Note

The function cannot return NULL.

The returned pointer should not be freed, it belongs to the hwloc library.

This function may be called before or after hwloc_topology_load() but the support structure only contains valid information after.

Detailed Description

Estas funciones establecen varios tipos de filtros para la topología de hardware descubierta, o establecen un puntero de datos privado asociado con la topología.

Los filtros son particularmente útiles para ignorar objetos que no son de interés, reduciendo así el tamaño de la topología y el tiempo de procesamiento de algoritmos de topología.

El filter es un valor de la enumeración hwloc_type_filter_e. Los valores posibles son:

HWLOC_TYPE_FILTER_KEEP_ALL
No filtrar ningún tipo de objeto.
HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Solo mantener los objetos considerados importantes por hwloc. Actualmente, esto significa procesadores, cachés L1/L2/L3, y dispositivos PCI. Esto es usualmente lo más cercano a HWLOC_TYPE_FILTER_KEEP_ALL, pero puede excluir ciertos objetos no esenciales para obtener una vista más limpia de la topología.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Solo mantener los objetos que forman la estructura de interconexión del sistema (procesadores, cachés, puentes, nodos NUMA). Excluir dispositivos de E/S y otros objetos que no estructuren las unidades de cálculo.
HWLOC_TYPE_FILTER_SHALLOW
Solo mantener los objetos en el nivel más superficial que sea suficiente para representar la estructura principal del sistema. Usualmente, esto significa solo procesadores, nodos NUMA, y posiblemente cachés L1. Todos los objetos de nivel inferior, como cachés más profundos y dispositivos de E/S, se excluyen.
'hwloc_type_filter_e'

Establecer el filtrado para todos los tipos de objetos. Si algunos tipos no soportan este filtrado, se ignoran silenciosamente.

Retorna

0 si tiene éxito, -1 si hay error.
