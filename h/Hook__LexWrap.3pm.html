DESCRIPCIÓ

N

Hook::LexWrap le permite instalar un pre-envoltorio o un post-envoltorio (o ambos) alrededor de una subrutina existente. A diferencia de otros módulos que proporcionan esta capacidad (por ejemplo, Hook::PreAndPost y Hook::WrapSub), Hook::LexWrap implementa los envoltorios de tal manera que la función "caller" estándar funciona correctamente dentro de la subrutina

envuelta.

Para instalar un pre-envoltorio,

escribe: 
     use Hook::LexWrap;
     wrap 'subroutine_name', pre => \&
#or: wrap *subroutine_name,  pre => \&some_other_sub
;

El primer argumento de "wrap" es una cadena que contiene el nombre de la subrutina a envolver (o el typeglob que la contiene, o una referencia a ella). El nombre de la subrutina puede estar calificado, y la subrutina ya debe estar definida. El segundo argumento indica el tipo de envoltorio que se aplica y debe ser 'pre' o 'post'. El tercer argumento debe ser una referencia a una subrutina que implementa el

envoltorio.

Para instalar un post-envoltorio,

escribe: 
     wrap 'subroutine_name', post => \&
#or: wrap *subroutine_name,  post => \&yet_another_sub
;

Para instalar ambos a la

vez: 
wrap 'subroutine_name',
     pre  => \&some_other_sub,
     post => \&yet_another_sub
;

o

: 
wrap *subroutine_name,
     post => \&yet_another_sub,  # el orden en que se
     pre  => \&   # especifican los envoltorios no
importa

Una vez instalados, los pre-envoltorios y post-envoltorios se llamarán antes y después de la subrutina misma, y recibirán la misma lista de

argumentos.

Los pre-envoltorios, los post-envoltorios y la subrutina original también ven los mismos (¡correctos!) valores de "caller" y "wantarray"

.

Valores de retorno de cortocircuito y de circuito

largo

Los pre-envoltorios y post-envoltorios reciben ambos un argumento extra en sus arreglos @_. Ese argumento extra se añade al final de la lista de argumentos original (es decir, siempre se puede acceder a él como $_[-1]) y actúa como un marcador de posición para el valor de retorno de la subrutina

original.

En un pre-envoltorio, $_[-1] es -- por razones obvias -- "undef". Sin embargo, $_[-1]] se le puede asignar un valor en un pre-envoltorio, en cuyo caso Hook::LexWrap asume que la subrutina original ha sido "preemptada", y que ni ella, ni el post-envoltorio correspondiente, ni ningún envoltorio que se haya aplicado antes de que se instalara el pre-envoltorio que la preempta, necesita ejecutarse. Tenga en cuenta que cualquier post-envoltorio que se haya instalado después de que se instalara el pre-envoltorio que la preempta seguirá siendo llamado antes de que la llamada a la subrutina original

regrese.

En un post-envoltorio, $_[-1] contiene el valor de retorno producido por la subrutina envuelta. En un contexto de retorno escalar, este valor es el valor de retorno escalar. En un contexto de retorno de lista, este valor es una referencia al arreglo de valores de retorno. $_[-1] se le puede asignar un valor en un post-envoltorio, y esto cambia el valor de retorno en

consecuencia.

El acceso a los argumentos y al valor de retorno es útil para implementar técnicas como la

memorización: 
my %cache;
wrap fibonacci =>
        pre  => sub { $_[-1] = $cache{$_[0]} if $cache{$_[0]} },
        post => sub { $cache{$_[0]} = $_[-1] }
;

o para convertir argumentos y valores de retorno de una manera

consistente: 
# set_temp espera y devuelve grados Fahrenheit,
# pero queremos usar Celsius
wrap set_temp =>
        pre   => sub { splice @_, 0, 1, $_[0] * 1.8 + 32 },
        post  => sub { $_[-1] = ($_[0] - 32) / 1.8
}
;

Envoltorios con ámbito

léxico

Normalmente, cualquier envoltorio instalado por "wrap" permanece unido a la subrutina hasta que se indefina. Sin embargo, es posible hacer que envoltorios específicos estén ligados léxicamente, de modo que operen solo hasta el final del ámbito en el que se crean (o hasta algún otro punto específico en el código)

.

Si "wrap" se llama en un contexto no

nulo: 
my $lexical = wrap 'sub_name', pre =>
\&

devuelve un objeto especial correspondiente al envoltorio particular que se está colocando alrededor de la subrutina original. Cuando ese objeto se destruye -- cuando su variable contenedora sale del ámbito, o cuando su recuento de referencias cae a cero de otra manera (por ejemplo, "undef $lexical"), o cuando se destruye explícitamente ("$lexical->DESTROY") -- el envoltorio correspondiente se elimina de alrededor de la subrutina orig

inal. Nótese, sin embargo, que todos los demás
envoltorios alrededor de la subrutina se conservan.

Envoltorios

anónimos

Si la subrutina a envolver se pasa como una referencia (en lugar de por nombre o por typeglob), "wrap" no instala los envoltorios alrededor de la subrutina original. En su lugar, genera una nueva subrutina que actúa como si fuera la original con esos envoltorios alrededor. Luego devuelve una referencia a esa nueva subrutina. Solo las llamadas a la original a través de esa referencia envuelta invocan los envoltorios. Las llamadas directas por nombre a la original, o las llamadas a través de otra referencia, no lo

hacen.

Si la original es posteriormente envuelta por nombre, la referencia a la subrutina envuelta anónimamente no ve esos envoltorios. En otras palabras, los envoltorios instalados a través de una referencia a subrutina son completamente independientes de los instalados a través del nombre de la subrutina (o typeglob)

.

Por

ejemplo: 
sub original { print "ray" }
# Envolver anónimamente...
my $anon_wrapped = wrap \&original, pre => sub { print "do..." }
; # Mostrar efectos... original(); # imprime "ray" $anon_wrapped->(); # imprime "do..ray" # Envolver n
o anónimamente... wrap *original, pre => sub { print "fa.." }, post => sub { print "..mi" }; # Mostrar
efectos... original(); # ahora imprime "fa..ray..mi" $anon_wrapped->(); # todavía imprime "do...ray"

DIAGNÓSTICO

S
"Can't wrap non-existent subroutine
%s"
Se intentó envolver una subrutina que no estaba definida en el punto de
envoltura.
"'pre' value is not a subroutine
reference"
El valor pasado a "wrap" después de la marca 'pre' no era una referencia a subrutina. Típicamente, alguien olvidó el "sub" en la subrutina anónima: 
wrap 'subname', pre => { your_code_here()
};

y Perl interpretó el últ

imo argumento como un
constructor de hash.
"'post' value is not a subroutine
reference"
El valor pasado a "wrap" después de la marca 'post' no era una referencia a
subrutina.
"Uselessly wrapped subroutine reference in void context" (solo
advertencia)
Cuando la subrutina a envolver se pasa como una referencia a subrutina, "wrap" no instala el envoltorio alrededor de la original, sino que devuelve una referencia a una subrutina que envuelve la original (ver "Envolventes anónimas").

Sin embargo, no tiene

sentido hacer esto s
i no capturas la
referencia a la
subrutina resultante.
