Descripción

detallada

El enlace de memoria se puede realizar de tres

maneras:
  • asignación de memoria explícita gracias a hwloc_alloc_membind() y sus funciones relacionadas: el enlace tendrá efecto sobre la memoria asignada por estas
    • funciones.
  • enlace de memoria implícito a través de la política de enlace: hwloc_set_membind() y sus funciones relacionadas solo definen la política actual del proceso, que se aplicará a las llamadas subsecuentes a malloc() y sus funciones
    • relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y sus funciones relac
    • ionadas, que mueven da
tos ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente en

uso.

Cuando la operación de enlace solicitada no está disponible y se pasó el indicador HWLOC_MEMBIND_STRICT, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria de forma individual por hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA)

.

Si no se pasó HWLOC_MEMBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, un conjunto de enlace más pequeño, etc.) cuando la operación solicitada no esté soportada

exactamente.

La forma más portable, que debería preferirse sobre las demás siempre que sea posible, es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para hacerlo, hwloc posiblemente tendrá que cambiar la política de enlace de memoria actual para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política de enlace de memoria

actual. 
hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0)
;

Cada función de enlace de memoria de hwloc toma un argumento de mapa de bits que es por defecto un conjunto de CPU, o un conjunto de nodos de memoria NUMA si se especifica el indicador HWLOC_MEMBIND_BYNODESET. Ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de mapas de bits para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_n

odeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea

posible.

enum hwloc_membind_flags_

t

Indicadores de enlace de memoria. Estos indicadores pueden usarse para refinar la política de enlace. Todos los indicadores pueden combinarse lógicamente con OR, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos indicadores son mutuamente

excluyentes.

No todos los sistemas soportan todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente en uso. Ver la sección 'Descripción detallada' de Enlace de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este indicador es mutuamente excluyente con HWLOC_MEMBIND_
THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este indicador es mutuamente excluyente con HWLOC_MEMBIND_PROCE
SS.
HWLOC_MEMBIND_STRICT
Solicita enlace estricto al SO. La funci
ón fallará si el enlace no puede s
er garantizado / completamente aplicado.

Este indicador tiene significados ligeramente diferentes dependiendo de con qué función se

use.
HWLOC_MEMBIND_MIGRATE
Migra memoria ya asignada. Si la memoria no puede ser migrada y se pasó el indicador HWLOC_MEMBIND_STRICT, se devolverá un
error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlace de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlace de memoria también enlazan la aplicación a la(s) CPU correspondiente(s). Usar este indicador hará que hwloc evite usar funciones del SO que podrían afectar los enlaces de CPU. Sin embargo, ten en cuenta que usar NOCPUBIND puede reducir el soporte general de enlace de memoria de hwloc. Específicamente: algunas de las funciones de enlace de memoria de hwloc pueden fallar con errno establecido a ENOSYS cuando se usan con
NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento de mapa de bits como un conjunto de nodos. El
argumento de mapa de bits se considera un conjunto de nodos si se da e
ste indicador, o un conjunto de CPU en caso contrario por defecto.

El enlace de memoria por conjunto de CPU no puede funcionar para

nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por c
onjunto de nodos debería preferirse siempre que sea posible.

enum hwloc_m hwloc

hwloc_membind_policy_t

Política de enlace de memoria. Estas constantes se pueden usar para elegir la política de enlace. Solo se puede usar una política a la vez (es decir, los valores no se pueden combinar con OR).

No todos los sistemas admiten todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar sobre el soporte real de la política de enlace de memoria en el sistema operativo actualmente en uso. Consulte la sección 'Descripción detallada' de Enlace de memoria para obtener una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD) o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones get membind. El argumento nodeset se ignora.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado generalmente debería ser hwloc_topology_get_topology_nodeset() para que el hilo que toca pueda ejecutarse y asignar en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (de lo contrario).

HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre los sistemas operativos, especialmente cuando los nodos solicitados (algunos o todos) están llenos. En Linux, por defecto, se utiliza la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona la bandera estricta de hwloc, se utiliza la política MPOL_BIND de Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / circular. La disposición precisa de la memoria en múltiples nodos NUMA es específica del sistema operativo/sistema. La intercalación puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados accederán a todo el rango de memoria simultáneamente, ya que la intercalación equilibrará entonces las referencias de memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / ponderada. La disposición precisa de la memoria en múltiples nodos NUMA es específica del sistema operativo/sistema. La intercalación ponderada puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán a todo el rango de memoria simultáneamente, ya que la intercalación equilibrará entonces las referencias de memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página enlazada con esta política, la próxima vez que se toque (y solo la próxima vez), se moverá de su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia de memoria (si es que necesita moverse).
HWLOC_MEMBIND_MIXED
Devuelto por las funciones get_membind() cuando múltiples hilos o partes de un área de memoria tienen políticas de enlace de memoria diferentes. También se devuelve cuando el enlace es desconocido porque los ganchos de enlace están vacíos cuando la topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

Documentación de funciones

void * hwloc_alloc (hwloc_topology_t topology, size_t len)

Asigna algo de memoria. Esto es equivalente a malloc(), excepto que intenta asignar memoria alineada por página del sistema operativo.

Retorna

un puntero al área asignada, o NULL en caso de error.

Nota

La memoria asignada debe liberarse con hwloc_free().

void * hwloc_alloc_membind (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Asigna algo de memoria en los nodos de memoria NUMA especificados por set.

Retorna

un puntero al área asignada.

NULL con errno establecido a ENOSYS si la acción no es compatible y se proporciona HWLOC_MEMBIND_STRICT.

NULL con errno establecido a EXDEV si el enlace no se puede forzar y se proporciona HWLOC_MEMBIND_STRICT.

NULL con errno establecido a ENOMEM si la asignación de memoria falló incluso antes de intentar el enlace.

Si se especifica HWLOC_MEMBIND_BYNODESET, set se considera un nodeset. De lo contrario, es un cpuset.

Nota

La memoria asignada debe liberarse con hwloc_free().

void * hwloc_alloc_membind_policy (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags) [inline]

Asigna algo de memoria en los nodos de memoria NUMA especificados por set. Primero, intenta asignar correctamente con hwloc_alloc_membind(). En caso de fallo, la política de enlace de memoria del proceso o hilo actual se cambia con hwloc_set_membind() antes de asignar memoria. Por lo tanto, esta función funciona en más casos, a costa de cambiar el estado actual (posiblemente afectando futuras asignaciones que no especificarían ninguna política).

Si se especifica HWLOC_MEMBIND_BYNODESET, set se considera un nodeset. De lo contrario, es un cpuset.

Retorna

un puntero al área asignada, o NULL en caso de error.

int hwloc_free (hwloc_topology_t topology, void * addr, size_t len)

Libera memoria que fue previamente asignada por hwloc_alloc() o hwloc_alloc_membind().

Retorna

0 en caso de éxito, -1 en caso de error.

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Consulta las CPUs cercanas al(los) nodo(s) NUMA físico(s) y la política de enlace de el área de memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamante) se rellena con el enlace del área de memoria.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de enlace de memoria y los nodesets de las páginas en el rango de direcciones.

Si se especifica HWLOC_MEMBIND_STRICT, primero se comprueba si todas las páginas objetivo tienen la misma política de enlace de memoria y el mismo nodeset. Si no es así, se devuelve -1 y errno se establece a EXDEV. Si son idénticos en todas las páginas, set y policy se devuelven en set y policy, respectivamente.

Si HWLOC_MEMBIND_STRICT no se especifica, se calcula la unión de todos los nodos NUMA que contienen páginas en el rango de direcciones. Si todas las páginas en el objetivo tienen la misma política, se devuelve en policy. De lo contrario, policy se establece a HWLOC_MEMBIND_MIXED.

Si se especifica HWLOC_MEMBIND_BYNODESET, set se considera un nodeset. De lo contrario, es un cpuset.

Si se especifican otros flags, se devuelve -1 y errno se establece a EINVAL.

Retorna

0 en caso de éxito.

-1 con errno establecido a EINVAL si len es 0.

int hwloc_get_area_memlocation (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, int flags)

Obtiene los nodos NUMA donde se asigna físicamente la memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamante) se rellena según los nodos NUMA donde se asignan físicamente las páginas del área de memoria. Si aún no se ha asignado ninguna página, set puede estar vacío.

Si las páginas se extienden a múltiples nodos, no se especifica si se extienden equitativamente, o si la mayoría de ellas están en un solo nodo, etc.

El sistema operativo puede mover páginas de memoria de un procesador a otro en cualquier momento según su enlace, por lo que esta función puede devolver algo que ya está obsoleto.
