DESCRIPCIÓ

N

Este módulo implementa un hash ordenado, lo que significa que asocia claves con valores como un hash de Perl, pero mantiene las claves en un orden consistente. Debido a que está implementado como un objeto y se manipula con llamadas a métodos, es mucho más lento que un hash de Perl. Este es el costo de mantener el

orden.

Sin embargo, en comparación con otras implementaciones de hash ordenado, Hash::Ordered está optimizado para obtener y establecer elementos individuales y gene

ralmente es más rápido también en la mayoría de las otras tarea
s. Para detalles específicos, ver Hash::Ordered::Benchmarks.

ADVERTENCI

AS

Eliminación y modificación del orden con push, pop,

etc.

Esto puede ser costoso, ya que la lista ordenada de claves tiene que ser actualizada. Para hashes pequeños con no más de 25 claves, las claves se encuentran y se extraen con búsqueda lineal. Como optimización para hashes más grandes, el primer cambio en la lista ordenada de claves construirá un índice a la lista de claves. A partir de ahí, las claves eliminadas se marcarán con un registro "tombstone" (tumba). Las tumbas se recogerán como basura siempre que el número de tumbas supere el número de claves

válidas.

Estos detalles de implementación internos en gran medida no deberían preocuparle. Lo importante a tener en cuenta

es:

MOTIVACIÓ

N

Durante mucho tiempo, usé Tie::IxHash para hashes ordenados, pero me frustré con las cosas que le faltaban, como una forma barata de copiar un objeto IxHash o un iterador conveniente cuando no se usa la interfaz atada. Al mirar su implementación, parecía más compleja de lo que creía que necesitaba, con un nivel extra de indirección que ralentiza el acceso a los

datos.

Dada esa frustración, comencé a experimentar con lo más simple que creía que podría funcionar para un hash ordenado: un hash de pares clave-valor y un array con el orden de las

claves.

Mientras trabajaba en esto, también comencé a buscar otros módulos que hicieran cosas similares. Lo que encontré se dividió ampliamente en dos campamentos: módulos basados en tie (incluso si ofrecían una interfaz OO), y módulos OO puros. A todos les faltaban características que consideraba necesarias o parecían excesivamente complejos en su implementación o

API.

Hash::Ordered intenta encontrar el punto dulce con una implementación simple, una eficiencia razonablemente buena para la mayoría de las operaciones comunes y una API rica e

intuitiva.

Después de conversar con Mario Roy sobre el uso potencial de Hash::Ordered con MCE, optimicé la

eliminación de hashes más grandes y proporcioné una interfaz atada para compatibilidad. Las sug
erencias y comentarios de Mario sobre la optimización fueron bastante valiosos. ¡Gracias, Mario!

TAMBIÉN

Esta sección describe otros módulos de hash ordenado que encontré en CPAN. Para resultados de pruebas de rendimiento, consulte Hash::Ordered::

Benchmarks.

Módulos

tie

Los siguientes módulos ofrecen algún tipo de interfaz tie. No me gustan los ties, en general, por la indirección extra involucrada sobre una llamada directa a un método. Aun así, puede convertir cualquier interfaz atada en una OO más rápida con "tied"

: 
tied( %tied_hash )->FETCH($key)
;

Tie::Hash::Indexed está implementado en XS y por lo tanto parece prometedor si el Perl puro no es un criterio; generalmente falla las pruebas en Perl 5.18 y versiones superiores debido al cambio de aleatorización de hashes. A pesar de ser XS, es más lento que Hash::Ordered en todo excepto en la creación y

eliminación.

Tie::IxHash probablemente es el más conocido e incluye una API OO. Dados los problemas de rendimiento que tiene, "bien conocido" es la única razón real para

usarlo.

Los demás módulos siguientes tienen diseños/limitaciones muy específicos y no encontré ninguno de ellos adecuado para uso

general:
  • Tie::Array::AsHash — elementos de array separados por un separador; solo API
    • tie
  • Tie::Hash::Array — ordenado alfabéticamente; solo API
    • tie
  • Tie::InsertOrderHash — ordenado por inserción; solo API
    • tie
  • Tie::LLHash — implementación de lista enlazada; bastante
    • lento
  • Tie::StoredOrderHa
    • sh — ordenado por

Otros módulos de hash

ordenado

Otros módulos se mantienen con una API orientada a objetos, con una amplia variedad de enfoques de

implementación.

Array::AsHash es esencialmente una implementación inversa de Hash::Ordered. Mantiene los pares en un array y usa un hash para indexar en el array. Esta indirección ya haría que las operaciones tipo hash fueran más lentas, pero la implementación específica lo hace aún peor, con abstracciones y llamadas a funciones que hacen que obtener o establecer elementos individuales sea hasta 10 veces más lento que Hash::

Ordered.

Sin embargo, "Array::AsHash" toma una referencia a array para inicializar, lo cual es muy rápido y puede devolver la lista de pares más rápido también. Si en su mayoría crea y lista hashes ordenados muy grandes y rara vez toca entradas individuales, creo que esto podría ser algo a considerar con mucha

cautela.

Los demás módulos siguientes tienen restricciones o implementaciones particularmente complicadas (a menudo dependiendo de "tie") y por lo tanto no pensé que ninguno de ellos fuera realmente adecuado para su

uso:
  • Array::Assign — arrays con acceso por nombre; claves
    • restringidas

    • internos
  • Data::Pairs — array de referencias a hash clave-valor; permite claves
    • duplicadas
  • Data::OMap — array de referencias a hash clave-valor; sin claves
    • duplicadas
