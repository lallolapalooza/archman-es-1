Tablas hash y funciones hash.

Las tablas hash son tablas de asociación hasheadas, con modificación en el lugar. Dado que la mayoría de las operaciones en una tabla hash modifican su entrada, se usan más comúnmente en código imperativo. La búsqueda del valor asociado a una clave (ver Hashtbl.find , Hashtbl.find_opt ) es normalmente muy rápida, a menudo más rápida que la búsqueda equivalente en Map .

Los functores Hashtbl.Make y Hashtbl.MakeSeeded se pueden usar cuando el rendimiento o la flexibilidad son clave. El usuario proporciona funciones personalizadas de igualdad y hash para el tipo de clave, y obtiene un tipo de tabla hash personalizada para este tipo particular de clave.

Advertencia: una tabla hash es tan buena como su función hash. Una mala función hash convertirá la tabla en una lista de asociación degenerada, con búsqueda de tiempo lineal en lugar de tiempo constante.

La tabla hash polimórfica Hashtbl.t es útil en casos más simples o en entornos interactivos. Utiliza la función hash polimórfica Hashtbl.hash definida en el runtime de OCaml (en el momento de escribir esto, es SipHash), así como la igualdad polimórfica (=) .

Ver Hashtbl.examples .

Alerta unsynchronized_access. Los accesos no sincronizados a las tablas hash son un error de programación.

Accesos no sincronizados

Los accesos no sincronizados a una tabla hash pueden llevar a un estado inválido de la tabla hash. Por lo tanto, los accesos concurrentes a las tablas hash deben estar sincronizados (por ejemplo, con un Mutex.t ).

Interfaz genérica

type (!'a, !'b) t

El tipo de tablas hash desde el tipo 'a al tipo 'b .

val create : ?random:bool -> int -> ('a, 'b) t

Hashtbl.create n crea una tabla hash nueva y vacía, con un tamaño inicial mayor o igual al tamaño sugerido n . Para obtener mejores resultados, n debe ser del orden del número esperado de elementos que habrá en la tabla. La tabla crece según sea necesario, por lo que n es solo una suposición inicial. Si n es muy pequeño o negativo, se ignora y se usa un tamaño pequeño por defecto.

El parámetro opcional ~random (un booleano) controla si la organización interna de la tabla hash se aleatoriza en cada ejecución de Hashtbl.create o si es determinista en todas las ejecuciones.

Una tabla hash que se crea con ~random establecido a false utiliza una función hash fija ( Hashtbl.hash ) para distribuir las claves entre los cubos. Como consecuencia, las colisiones entre claves ocurren de forma determinista. En aplicaciones orientadas a la web u otras aplicaciones sensibles a la seguridad, los patrones de colisión deterministas pueden ser explotados por un usuario malintencionado para crear un ataque de denegación de servicio: el atacante envía entradas diseñadas para crear muchas colisiones en la tabla, ralentizando la aplicación.

Una tabla hash que se crea con ~random establecido a true utiliza la función hash sembrada Hashtbl.seeded_hash con una semilla elegida aleatoriamente en el momento de la creación de la tabla hash. De hecho, la función hash utilizada se selecciona aleatoriamente entre 2^{30} funciones hash diferentes. Todas estas funciones hash tienen patrones de colisión diferentes, lo que hace ineficaz el ataque de denegación de servicio descrito anteriormente. Sin embargo, debido a la aleatorización, enumerar todos los elementos de la tabla hash usando Hashtbl.fold o Hashtbl.iter ya no es determinista: los elementos se enumeran en órdenes diferentes en ejecuciones distintas del programa.

Si no se proporciona ningún parámetro ~random , las tablas hash se crean por defecto en modo no aleatorio. Este valor por defecto puede cambiarse programáticamente llamando a Hashtbl.randomize o estableciendo el flag R en la variable de entorno OCAMLRUNPARAM .

Antes de 4.00 el parámetro ~random no estaba presente y todas las tablas hash se creaban en modo no aleatorio.

Vacía una tabla hash. Use reset en lugar de clear para reducir el tamaño de la tabla de cubos a su tamaño inicial.

val reset : ('a, 'b) t -> unit

Vacía una tabla hash y reduce el tamaño de la tabla de cubos a su tamaño inicial.

val copy : ('a, 'b) t -> ('a, 'b) t

Devuelve una copia de la tabla hash dada.

val add : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.add tbl key data agrega una vinculación de key a data en la tabla tbl .

Advertencia: Las vinculaciones anteriores para key no se eliminan, sino que simplemente se ocultan. Es decir, después de realizar Hashtbl.remove tbl key , la vinculación anterior para key , si existe, se restaura. (Mismo comportamiento que con las listas de asociación.)

Si desea el comportamiento clásico de reemplazo de elementos, vea Hashtbl.replace .

val find : ('a, 'b) t -> 'a -> 'b

Hashtbl.find tbl x devuelve la vinculación actual de x en tbl , o lanza Not_found si no existe tal vinculación.

val find_opt : ('a, 'b) t -> 'a -> 'b option

Hashtbl.find_opt tbl x devuelve la vinculación actual de x en tbl , o None si no existe tal vinculación.

Desde 4.05

val find_all : ('a, 'b) t -> 'a -> 'b list

Hashtbl.find_all tbl x devuelve la lista de todos los datos asociados a x en tbl . La vinculación actual se devuelve primero, luego las vinculaciones anteriores, en orden inverso de introducción en la tabla.

val mem : ('a, 'b) t -> 'a -> bool

Hashtbl.mem tbl x verifica si x está vinculado en tbl .

val remove : ('a, 'b) t -> 'a -> unit

Hashtbl.remove tbl x elimina la vinculación actual de x en tbl , restaurando la vinculación anterior si existe. No hace nada si x no está vinculado en tbl .

val replace : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.replace tbl key data reemplaza la vinculación actual de key en tbl por una vinculación de key a data . Si key no está vinculado en tbl , se agrega una vinculación de key a data a tbl . Esto es funcionalmente equivalente a Hashtbl.remove tbl key seguido de Hashtbl.add tbl key data .

val iter : ('a -> 'b -> unit) -> ('a, 'b) t -> unit

Hashtbl.iter f tbl aplica f a todas las vinculaciones en la tabla tbl . f recibe la clave como primer argumento, y el valor asociado como segundo argumento. Cada vinculación se presenta exactamente una vez a f .

El orden en el que se pasan las vinculaciones a f no está especificado. Sin embargo, si la tabla contiene varias vinculaciones para la misma clave, se pasan a f en orden inverso de introducción, es decir, la vinculación más reciente se pasa primero.

Si la tabla hash se creó en modo no aleatorio, el orden en el que se enumeran las vinculaciones es reproducible entre ejecuciones sucesivas del programa, e incluso entre versiones menores de OCaml. Para tablas hash aleatorizadas, el orden de enumeración es completamente aleatorio.

El comportamiento no está especificado si la tabla hash es modificada por f durante la iteración.

val filter_map_inplace : ('a -> 'b -> 'b option) -> ('a, 'b) t -> unit

Hashtbl.filter_map_inplace f tbl aplica f a todas las vinculaciones en la tabla tbl y actualiza cada vinculación dependiendo del resultado de f . Si f devuelve None , la vinculación se descarta. Si devuelve Some new_val , la vinculación se actualiza para asociar la clave con new_val .

Otros comentarios para Hashtbl.iter también aplican.

val hash_param : int -> int -> 'a ->

int

Hashtbl.hash_param meaningful total x calcula un valor hash para x , con las mismas propiedades que para hash . Los dos parámetros enteros adicionales meaningful y total proporcionan un control más preciso sobre el hash. El hashing realiza un recorrido en amplitud, de izquierda a derecha de la estructura x , deteniéndose después de haber encontrado meaningful nodos significativos, o total nodos (significativos o no). Si total especificado por el usuario excede cierto valor, actualmente 256, se limita a ese valor. Los nodos significativos son: enteros; números de punto flotante; cadenas de caracteres; caracteres; booleanos; y constructores constantes. Valores más grandes de meaningful y total significan que se tienen en cuenta más nodos para calcular el valor hash final, y por lo tanto es menos probable que ocurran colisiones. Sin embargo, el hashing tarda más. Los parámetros meaningful y total gobiernan el compromiso entre precisión y velocidad. Como elecciones por defecto, Hashtbl.hash y Hashtbl. seeded_hash toman meaningful = 10
