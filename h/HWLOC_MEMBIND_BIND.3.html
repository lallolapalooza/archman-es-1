Descripción

detallada

El enlace de memoria se puede realizar de tres

maneras:
  • asignación de memoria explícita gracias a hwloc_alloc_membind() y sus funciones relacionadas: el enlace tendrá efecto sobre la memoria asignada por estas
    • funciones.
  • enlace de memoria implícito a través de la política de enlace: hwloc_set_membind() y sus funciones relacionadas solo definen la política actual del proceso, que se aplicará a las llamadas posteriores a malloc() y sus funciones
    • relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y sus funciones relac
    • ionadas, que mueven da
tos ya asignados.

No todos los sistemas operativos admiten las tres formas. hwloc_topology_get_support() se puede utilizar para consultar el soporte real de enlace de memoria en el sistema operativo utilizado

actualmente.

Cuando la operación de enlace solicitada no está disponible y se pasó el indicador HWLOC_MEMBIND_STRICT, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no admita la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria de forma individual por hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA)

.

Si no se pasó HWLOC_MEMBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, un conjunto de enlace más pequeño, etc.) cuando la operación solicitada no es exactamente

compatible.

La forma más portátil, que debería preferirse sobre las demás siempre que sea posible, es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para ello, hwloc posiblemente tendrá que cambiar la política de enlace de memoria actual para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política de enlace de memoria

actual. 
hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0)
;

Cada función de enlace de memoria de hwloc toma un argumento de mapa de bits que es un conjunto de CPU de forma predeterminada, o un conjunto de nodos de memoria NUMA si se especifica el indicador HWLOC_MEMBIND_BYNODESET. Ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API del mapa de bits para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_n

odeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea

posible.

enum hwloc_membind_flags_

t

Indicadores de enlace de memoria. Estos indicadores se pueden usar para refinar la política de enlace. Todos los indicadores se pueden combinar lógicamente con OR, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos indicadores son mutuamente

excluyentes.

No todos los sistemas admiten todos los tipos de enlace. hwloc_topology_get_support() se puede utilizar para consultar el soporte real de enlace de memoria en el sistema operativo utilizado actualmente. Ver la sección 'Descripción detallada' de Enlace de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este indicador es mutuamente excluyente con HWLOC_MEMBIND_
THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este indicador es mutuamente excluyente con HWLOC_MEMBIND_PROCE
SS.
HWLOC_MEMBIND_STRICT
Solicita enlace estricto al SO. La func
ión fallará si el enlace no se pu
ede garantizar / aplicar completamente.

Este indicador tiene significados ligeramente diferentes dependiendo de con qué función se

use.
HWLOC_MEMBIND_MIGRATE
Migra la memoria asignada existente. Si la memoria no se puede migrar y se pasó el indicador HWLOC_MEMBIND_STRICT, se devolverá un
error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlace de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlace de memoria también enlazan la aplicación a la(s) CPU correspondiente(s). Usar este indicador hará que hwloc evite usar funciones del SO que podrían afectar los enlaces de CPU. Sin embargo, tenga en cuenta que usar NOCPUBIND puede reducir el soporte general de enlace de memoria de hwloc. Específicamente: algunas de las funciones de enlace de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usa con
NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento del mapa de bits como un conjunto de nodos. El arg
umento del mapa de bits se considera un conjunto de nodos si se da este i
ndicador, o un conjunto de CPU de forma predeterminada en caso contrario.

El enlace de memoria por conjunto de CPU no puede funcionar para

nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por c
onjunto de nodos debería preferirse siempre que sea posible.

enum hwloc_membind_policy_

t

Política de asignación de memoria. Estas constantes se pueden usar para elegir la política de asignación. Solo se puede usar una política a la vez (es decir, los valores no se pueden combinar con OR)

.

No todos los sistemas admiten todos los tipos de asignación. hwloc_topology_get_support() se puede usar para consultar el soporte real de la política de asignación de memoria en el sistema operativo actualmente en uso. Consulte la sección 'Descripción Detallada' de Asignación de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD), o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones de obtención de membind. El argumento nodeset es
ignorado.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado generalmente debería ser hwloc_topology_get_topology_nodeset() para que el hilo que la t
oca pueda ejecutarse y asignars
e en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (en caso contrario)

.
HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre sistemas operativos, especialmente cuando (algunos de) los nodos solicitados están llenos. En Linux, de forma predeterminada, se usa la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona el flag estricto de hwloc, se usa en su lugar la política MPOL_BIND de
Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / round-robin. La disposición precisa de la memoria en múltiples nodos NUMA depende del sistema operativo/sistema. El intercalado puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados accederán todos al rango completo de memoria de forma concurrente, ya que el intercalado equilibrará entonces las referencias de
memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / ponderada. La disposición precisa de la memoria en múltiples nodos NUMA depende del sistema operativo/sistema. El intercalado ponderado puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán todos al rango completo de memoria de forma concurrente, ya que el intercalado equilibrará entonces las referencias de
memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página vinculada con esta política, la próxima vez que sea tocada (y solo la próxima vez), se mueve desde su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia de memoria (si necesita ser movida en absoluto)
.
HWLOC_MEMBIND_MIXED
Devuelto por las funciones get_membind() cuando múltiples hilos
o partes de un área de memoria tienen políticas de asignación
de memoria diferentes. También se devuelve cuando la asignación
es desconocida porque los hooks de asignación están vacíos cuan
do la topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

Consulta las CPUs cerca del(los) nodo(s) NUMA físicos y la política de asignación de la memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamador) se rellena con la asignación del área de

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags proporcionados como de las políticas de asignación de memoria y los nodesets de las páginas en el rango de

direcciones.

Si HWLOC_MEMBIND_STRICT es especificado, las páginas de destino se verifican primero para ver si todas tienen la misma política de asignación de memoria y nodeset. Si no lo tienen, se devuelve -1 y errno se establece a EXDEV. Si son idénticas en todas las páginas, el set y la política se devuelven en set y policy, respectivamente

Si HWLOC_MEMBIND_STRICT no es especificado, se calcula la unión de todos los nodo(s) NUMA que contienen páginas en el rango de direcciones. Si todas las páginas en el destino tienen la misma política, se devuelve en policy. De lo contrario, policy se establece a HWLOC_MEMBIND_MIXED

.

Si HWLOC_MEMBIND_BYNODESET es especificado, set es considerado un nodeset. De lo contrario, es un

cpuset.
