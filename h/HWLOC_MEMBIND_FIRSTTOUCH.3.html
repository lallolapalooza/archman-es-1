Descripción detallada

La vinculación de memoria se puede realizar de tres maneras:

  • asignación explícita de memoria gracias a hwloc_alloc_membind() y funciones similares: la vinculación tendrá efecto sobre la memoria asignada por estas funciones.
  • vinculación de memoria implícita a través de una política de vinculación: hwloc_set_membind() y funciones similares solo definen la política actual del proceso, que se aplicará a las llamadas subsiguientes a malloc() y funciones similares.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y funciones similares, que mueven datos ya asignados.

No todos los sistemas operativos admiten las tres maneras. hwloc_topology_get_support() se puede usar para consultar el soporte real de vinculación de memoria en el sistema operativo actualmente en uso.

Cuando la operación de vinculación solicitada no está disponible y se pasó la bandera HWLOC_MEMBIND_STRICT, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema admita la acción o política especificada (por ejemplo, algunos sistemas solo permiten vincular memoria por hilo, mientras que otros solo permiten vincular memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no se pueda aplicar (por ejemplo, algunos sistemas solo permiten vincular memoria a un único nodo NUMA).

Si no se pasó HWLOC_MEMBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, un conjunto de vinculación más pequeño, etc.) cuando la operación solicitada no se admite exactamente.

La forma más portable que se prefiere sobre las demás siempre que sea posible es la siguiente. Asigna algo de memoria con la esperanza de que se vincule al conjunto especificado. Para hacer esto, hwloc podría necesitar cambiar la política de vinculación de memoria actual para realmente lograr que la memoria se vincule, si el SO no proporciona ninguna otra forma de simplemente asignar memoria vinculada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política de vinculación de memoria actual.

hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0);

Cada función de vinculación de memoria de hwloc toma un argumento de mapa de bits que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si se especifica la bandera HWLOC_MEMBIND_BYNODESET. Consulte Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de mapas de bits para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_nodeset().

La vinculación de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, se debe preferir la vinculación por conjunto de nodos siempre que sea posible.

Documentación del tipo de enumeración

enum hwloc_membind_flags_t

Indicadores de vinculación de memoria. Estos indicadores se pueden usar para refinar la política de vinculación. Todos los indicadores se pueden combinar lógicamente, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos indicadores son mutuamente excluyentes.

No todos los sistemas admiten todos los tipos de vinculación. hwloc_topology_get_support() puede usarse para consultar el soporte real de vinculación de memoria en el sistema operativo actualmente en uso. Consulte la sección 'Descripción detallada' de Vinculación de memoria para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este indicador es mutuamente excluyente con HWLOC_MEMBIND_THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este indicador es mutuamente excluyente con HWLOC_MEMBIND_PROCESS.
HWLOC_MEMBIND_STRICT
Solicita vinculación estricta del SO. La función fallará si la vinculación no se puede garantizar / aplicar completamente.

Este indicador tiene significados ligeramente diferentes dependiendo de la función con la que se use.

HWLOC_MEMBIND_MIGRATE
Migra la memoria asignada existente. Si la memoria no se puede migrar y se pasa el indicador HWLOC_MEMBIND_STRICT, se devolverá un error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto en la vinculación de CPU. En algunos sistemas operativos, algunas funciones subyacentes de vinculación de memoria también vinculan la aplicación a las CPU correspondientes. El uso de este indicador hará que hwloc evite usar funciones del SO que puedan afectar potencialmente las vinculaciones de CPU. Tenga en cuenta, sin embargo, que el uso de NOCPUBIND puede reducir el soporte general de vinculación de memoria de hwloc. Específicamente: algunas de las funciones de vinculación de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usan con NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento del mapa de bits como un conjunto de nodos. El argumento del mapa de bits se considera un conjunto de nodos si se da este indicador, o un conjunto de CPU por defecto en caso contrario.

La vinculación de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, se debe preferir la vinculación por conjunto de nodos siempre que sea posible.

No todos los sistemas soportan todos los tipos de enlazamiento. hwloc_topology_get_support() puede usarse para consultar el soporte real de la política de enlazamiento de memoria en el sistema operativo actualmente en uso. Véase la sección 'Descripción Detallada' de Enlazamiento de memoria para una descripción de los errores que pueden

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD), o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones de obtención de membind. El argumento nodeset es
ignorado.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado debería ser usualmente hwloc_topology_get_topology_nodeset() para que el hilo que la toc

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (en caso contrario)

.
HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre sistemas operativos, especialmente cuando (algunos de) los nodos solicitados están llenos. En Linux, por defecto, se usa la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona el flag estricto de hwloc, se usa en su lugar la política MPOL_BIND de
Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / round-robin. El diseño preciso de la memoria a través de múltiples nodos NUMA es específico del SO/sistema. El entrelazado puede ser útil cuando los hilos distribuidos a través de los nodos NUMA especificados accederán todos al rango completo de memoria simultáneamente, ya que el entrelazado equilibrará entonces las referencias a la
memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / ponderada. El diseño preciso de la memoria a través de múltiples nodos NUMA es específico del SO/sistema. El entrelazado ponderado puede ser útil cuando los hilos distribuidos a través de los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán todos al rango completo de memoria simultáneamente, ya que el entrelazado equilibrará entonces las referencias a la
memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página enlazada con esta política, la próxima vez que sea tocada (y solo la próxima vez), se mueve desde su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia a la memoria (si necesita ser movida en absoluto)

HWLOC_MEMBIND_MIXED
Devuelto por las funciones get_membind() cuando múltiples hilos o p

Consulta la política de enlace de memoria predeterminada y la localidad física del proceso o hilo actual. El bitmap set (previamente asignado por el llamante) se rellena con el enlace de memoria del proceso o

hilo.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de enlace de memoria y nodesets actuales en el objetivo

Pasar el flag HWLOC_MEMBIND_PROCESS especifica que el objetivo de la consulta son las políticas y nodesets actuales para todos los hilos en el proceso actual. Pasar HWLOC_MEMBIND_THREAD especifica que el objetivo de la consulta es la política y nodeset actuales solo para el hilo que invoca esta

Si no se pasa ninguno de estos flags (que es el método más portátil), se asume que el proceso es de un solo hilo. Esto permite que hwloc use funciones del SO basadas en el proceso o funciones del SO basadas en el hilo, dependiendo de cuáles estén

disponibles.

HWLOC_MEMBIND_STRICT solo tiene significado cuando también se especifica HWLOC_MEMBIND_PROCESS. En este caso, hwloc verificará las políticas y nodesets de memoria predeterminados para todos los hilos en el proceso. Si no son idénticos, se devuelve -1 y errno se establece a EXDEV.
