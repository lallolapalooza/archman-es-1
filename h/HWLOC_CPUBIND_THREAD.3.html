Algunos sistemas operativos solo admiten el enlazamiento de hilos o procesos a una sola PU. Otros permiten el enlazamiento a conjuntos más grandes como Núcleos completos o Paquetes o incluso conjuntos aleatorios de PUs individuales. En tales sistemas operativos, el planificador es libre de ejecutar la tarea en una de estas PU, luego migrarla a otra PU, etc. A menudo es útil llamar a hwloc_bitmap_singlify()en el conjunto de CPU de destino antes de pasarlo a la función de enlazamiento para evitar estas migraciones costosas. Consulte la documentación de hwloc_bitmap_singlify()
para más detalles. Algunos sistemas operativos no proporcionan todos los mecanismos admitidos por hwloc para enlazar procesos, hilos, etc.hwloc_topology_get_support() puede usarse para consultar sobre el soporte real de enlazamiento de CPU en el sistema operativo actualmente utilizado.

Cuando la operación de enlazamiento solicitada no está disponible y se pasó

la

HWLOC_CPUBIND_STRICT bandera, la función devuelve -1. errno se establece en

ENOSYS

cuando no es posible enlazar el tipo solicitado de objetos procesos/hilos. errno se establece en EXDEV cuando el conjunto de CPU solicitado no puede aplicarse (por ejemplo, algunos sistemas solo permiten una CPU, y algunos otros sistemas solo permiten un nodo NUMA)

.

Si HWLOC_CPUBIND_STRICT no se pasó, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlazamiento más pequeño, etc.) cuando la operación solicitada no es exactamente compatible. La versión más portable que debería preferirse sobre las demás, siempre que sea posible, es la siguiente que simplemente enlaza el programa actual, asumiendo que es de un solo

hilo:

hwloc_set_cpubind(topology, set, 0), Si el programa puede ser multihilo, debería preferirse la siguiente para enlazar solo el hilo

actual:

HWLOC_CPUBIND_STRIC
T
Solicitar enlazamiento estricto al SO. De manera predeterminada, cuando los CPU designados están todos ocupados mientras otros CPU están inactivos, los sistemas operativos pueden ejecutar el hilo/proceso en esos otros CPU en lugar de los CPU designados, para permitirles progresar de todos modos. El enlazamiento estricto significa que el hilo/proceso _nunca_ se ejecutará en otros CPU que los designados, incluso cuando estén ocupados con otras tareas y otros CPU estén inactivos.
Not
a
Dependiendo del sistema operativo, el enlazamiento estricto puede no ser posible (por ejemplo, el SO no lo implementa) o no permitido (por ejemplo, por razones administrativas), y la función fallará en ese caso.

Obtener la última CPU física donde se ejecutó el proceso o hilo actual. El conjunto de CPU set (previamente asignado por el llamador) se llena con la lista de PUs en las que el proceso o hilo (según flags) se ejecutó por última

vez.

El sistema operativo puede mover algunas tareas de un procesador a otro en cualquier momento según su enlazamiento, por lo que esta función puede devolver algo que ya esactualizado.

Las banderas pueden incluir cualquiera de HWLOC_CPUBIND_PROCESS o HWLOC_CPUBIND_THREAD para especificar si la consulta debe ser para todo el proceso (unión de todos los CPUs en los que se ejecutan todos los hilos) o solo para el hilo actual. Si el proceso es de un solo hilo, las banderas pueden establecerse en cero para permitir que hwloc utilice el método disponible en el sistema operativo subyacente.

Retorna

0 en caso de éxito, -1 en caso de error.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtener la unión física actual del proceso pid. El conjunto de CPUs set (previously asignado por el llamante) se llena con la lista de PUs a los que el proceso fue unido por última vez.

Retorna

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

Como un caso especial en Linux, si se proporciona un tid (ID de hilo) en lugar de un pid (ID de proceso) y se pasa HWLOC_CPUBIND_THREAD en las banderas, se devuelve la unión para ese hilo específico.

En sistemas no Linux, HWLOC_CPUBIND_THREAD no se puede usar en banderas.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtener el último CPU físico en el que se ejecutó un proceso. El conjunto de CPUs set (previously asignado por el llamante) se llena con la lista de PUs en las que el proceso se ejecutó por última vez.

El sistema operativo puede mover algunas tareas de un procesador a otro en cualquier momento según su unión, por lo que esta función puede devolver algo que ya está desactualizado.

Retorna

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

En sistemas no Linux, HWLOC_CPUBIND_THREAD no se puede usar en banderas.
