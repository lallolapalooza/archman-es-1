NOMBRE

HTML::Element - Clase para objetos que representan elementos HTML

VERSIÓN

Este documento describe la versión 5.07 de HTML::Element, publicada el 31 de agosto de 2017 como parte de HTML-Tree.

SINOPSIS

use HTML::Element;
$a = HTML::Element->new('a', href => 'http://www.perl.com/');
$a->push_content("The Perl Homepage");
$tag = $a->tag;
print "$tag starts out as:",  $a->starttag, "\n";
print "$tag ends as:",  $a->endtag, "\n";
print "$tag\'s href attribute is: ", $a->attr('href'), "\n";
$links_r = $a->extract_links();
print "Hey, I found ", scalar(@$links_r), " links.\n";
print "And that, as HTML, is: ", $a->as_HTML, "\n";
$a = $a->delete;

DESCRIPCIÓN

(Esta clase es parte de la distribución HTML::Tree.)

Los objetos de la clase HTML::Element pueden usarse para representar elementos de árboles de documentos HTML. Estos objetos tienen atributos, notablemente atributos que designan el padre de cada elemento y su contenido. El contenido es una lista de segmentos de texto y otros objetos HTML::Element. Un árbol con objetos HTML::Element como nodos puede representar el árbol de sintaxis de un documento HTML.

CÓMO REPRESENTAMOS LOS ÁRBOLES

Considere este documento HTML:

<html lang='en-US'>
  <head>
    <title>Stuff</title>
    <meta name='author' content='Jojo'>
  </head>
  <body>
   <h1>I like potatoes!</h1>
  </body>
</html>

Construir un árbol de sintaxis a partir de él crea una estructura de árbol en memoria que podría diagramarse así:

              html (lang='en-US')
               / \
             /     \
           /         \
         head        body
        /\               \
      /    \               \
    /        \               \
  title     meta              h1
   |       (name='author',     |
"Stuff"    content='Jojo')    "I like potatoes"

Esta es la forma tradicional de diagramar un árbol, con la "raíz" en la parte superior, y es este tipo de diagrama que la gente tiene en mente cuando dicen, por ejemplo, que "el elemento meta está debajo del elemento head en lugar de debajo del elemento body". (Lo mismo se dice con "dentro" en lugar de "debajo" -- el uso de "dentro" tiene más sentido cuando estás mirando el código fuente HTML.)

Otra forma de representar el árbol anterior es con sangría:

html (attributes: lang='en-US')
  head
    title
      "Stuff"
    meta (attributes: name='author' content='Jojo')
  body
    h1
      "I like potatoes"

Por cierto, el diagramado con sangría funciona mucho mejor para árboles muy grandes, y es más fácil de generar para un programa. El "$tree->dump" método usa sangría exactamente de esa manera.

Sin importar cómo diagrames el árbol, se almacena igual en memoria -- es una red de objetos, cada uno de los cuales tiene atributos así:

element #1:  _tag: 'html'
             _parent: none
             _content: [element #2, element #5]
             lang: 'en-US'
element #2:  _tag: 'head'
             _parent: element #1
             _content: [element #3, element #4]
element #3:  _tag: 'title'
             _parent: element #2
             _content: [text segment "Stuff"]
element #4   _tag: 'meta'
             _parent: element #2
             _content: none
             name: author
             content: Jojo
element #5   _tag: 'body'
             _parent: element #1
             _content: [element #6]
element #6   _tag: 'h1'
             _parent: element #5
             _content: [text segment "I like potatoes"]

La "arborescencia" de la estructura de árbol que estos elementos componen no es un aspecto de ningún objeto particular, sino que surge de los atributos de relación (_parent y _content) de estos objetos-elemento y de cómo los usas para ir de un elemento a otro.

Aunque podrías acceder al contenido de un árbol escribiendo código que diga "accede al atributo 'src' del primer hijo de la raíz, séptimo hijo de ese, tercer hijo", es más probable que tengas que escanear el contenido de un árbol, buscando los nodos, o tipos de nodos, con los que quieras hacer algo. La forma más directa de recorrer un árbol es "recorrerlo"; se proporciona un método de HTML::Element ("$h->traverse") para este propósito; y varios otros métodos de HTML::Element se basan en él.

(Para todo lo que siempre quisiste saber sobre árboles, y más, consulta Algoritmos + Estructuras de Datos = Programas de Niklaus Wirth o El Arte de la Programación de Computadoras, Volumen 1 de Donald Knuth.)

Referencias Débiles

Resumen TL;DR: "use HTML::TreeBuilder 5 -weak;" y olvídate del "delete" método (excepto para podar un nodo de un árbol).

Debido a que HTML::Element almacena una referencia al elemento padre, el recolector de basura por conteo de referencias de Perl no funciona correctamente con árboles HTML::Element. A partir de la versión 5.00, HTML::Element usa referencias débiles (si están disponibles) para prevenir ese problema. Las referencias débiles se introdujeron en Perl 5.6.0, pero también necesitas una versión de Scalar::Util que proporcione la "weaken" función.

Las referencias débiles están habilitadas por defecto. Si quieres estar seguro de que se están usando, puedes decir "use HTML::Element 5 -weak;". Debes incluir el número de versión; las versiones anteriores de HTML::Element ignoraban por completo la lista de importación.

Para deshabilitar las referencias débiles, puedes decir "use HTML::Element -noweak;". Esta es una configuración global. Esta característica está obsoleta y se proporciona solo como una solución rápida para código roto. Si tu código no funciona correctamente con referencias débiles, deberías arreglarlo inmediatamente, ya que las referencias débiles pueden volverse obligatorias en una versión futura. Generalmente, todo lo que necesitas hacer es mantener una referencia a la raíz del árbol hasta que termines de trabajar con él.

Debido a que HTML::TreeBuilder es una subclase de HTML::Element, también puedes importar "-weak" o "-noweak" desde HTML::TreeBuilder: por ejemplo "use HTML::TreeBuilder: 5 -weak;".

MÉTODOS BÁSICOS

new

$h = HTML::Element->new('tag', 'attrname' => 'value', ... );

Este método constructor devuelve un nuevo objeto HTML::Element. El nombre de la etiqueta es un argumento obligatorio; se forzará a minúsculas. Opcionalmente, puedes especificar otros atributos iniciales al momento de crear el objeto.

attr

$value = $h->attr('attr');
$old_value = $h->attr('attr', $new_value);

Devuelve (opcionalmente establece) el valor del atributo dado de $h. El nombre del atributo (pero no el valor, si se proporciona) se fuerza a minúsculas. Si intentas leer el valor de un atributo que no está presente para este elemento, el valor de retorno es undef. Si estableces un nuevo valor, se devuelve el valor antiguo de ese atributo.

Si se proporcionan métodos para acceder a un atributo (como "$h->tag" para "_tag", "$h->content_list", etc. más abajo), usa esos en lugar de llamar a attr "$h->attr", ya sea para leer o establecer.

Ten en cuenta que establecer un atributo a "undef" (a diferencia de "", la cadena vacía) realmente borra el atributo.

tag

$tagname = $h->tag();
$h->tag('tagname');

Devuelve (opcionalmente establece) el nombre de la etiqueta (también conocido como identificador genérico) para el elemento $h. Al establecerlo, el nombre de la etiqueta siempre se convierte a minúsculas.

Hay cuatro tipos de "pseudo-elementos" que aparecen como objetos HTML::Element:

Pseudocomentarioo-elementos
Estos son objetos de elemento con un "$h->tag" valor de "~comment", y el contenido del comentario se almacena en el atributo "text" ("$h->attr("text")"). Por ejemplo, al analizar este código con HTML::TreeBuilder... 
<!-- I like Pie.
   Pie is good
-->

produce un objeto HTML::Element con estos atributos:

"_tag",
"~comment",
"text",
" I like Pie.\n     Pie is good\n  "
Pseudo-elementos de declaración
Las declaraciones (rara vez se encuentran) se representan como objetos HTML::Element con un nombre de etiqueta de "~declaration", y el contenido en el atributo "text". Por ejemplo, esto: 
<!DOCTYPE foo>

produce un elemento cuyos atributos incluyen:

"_tag", "~declaration", "text", "DOCTYPE foo"
Pseudo-elementos de instrucción de procesamiento
Las PI (rara vez se encuentran) se representan como objetos HTML::Element con un nombre de etiqueta de "~pi", y el contenido en el atributo "text". Por ejemplo, esto: 
<?stuff foo?>

produce un elemento cuyos atributos incluyen:

"_tag", "~pi", "text", "stuff foo?"

(asumiendo una versión reciente de HTML::Parser)

Pseudo-elementos ~literal
Estos objetos no son producidos actualmente por HTML::TreeBuilder, pero pueden ser usados para representar un "super-literal" -- es decir, un literal que quieres que sea inmune al escapado. (Sí, acabo de inventar ese término.)

Es decir, esto es útil si quieres insertar código en un árbol que planeas volcar con "as_HTML", donde quieres, por alguna razón, suprimir "as_HTML"'s comportamiento normal de escapar con ampersand los segmentos de texto.

Por ejemplo, esto:

my $literal = HTML::Element->new('~literal',
  'text' => 'x < 4 & y > 7'
);
my $span = HTML::Element->new('span');
$span->push_content($literal);
print $span->as_HTML;

imprime esto:

<span>x < 4 & y > 7</span>

Mientras que esto:

my $span = HTML::Element->new('span');
$span->push_content('x < 4 & y > 7');
  # normal text segment
print $span->as_HTML;

imprime esto:

<span>x & 4 & y & 7</span>

A menos que estés insertando mucho código pre-cocinado en árboles existentes, y volcándolos de nuevo, no es probable que encuentres "~literal" pseudo-elementos útiles.

parent

$parent = $h->parent();
$h->parent($new_parent);

Devuelve (opcionalmente establece) el padre (alias "contenedor") de este elemento. El padre debe ser undef, o debe ser otro elemento.

Tú no debes usar esto para establecer directamente el padre de un elemento. En su lugar usa cualquiera de los otros métodos bajo "Métodos de Modificación de Estructura", más abajo.

Ten en cuenta que not($h->parent) es una prueba simple de si $h es la raíz de su subárbol.

content_list

@content = $h->content_list();
$num_children = $h->content_list();

Devuelve una lista de los nodos hijos de este elemento -- es decir, qué nodos (elementos o segmentos de texto) están dentro/debajo de este elemento. (Ten en cuenta que esta puede ser una lista vacía.)

En un contexto escalar, devuelve el número de elementos, como podrías esperar.

content

$content_array_ref = $h->content(); # may return undef

Este método algo obsoleto devuelve el contenido de este elemento; pero a diferencia de content_list, devuelve o bien undef (que debes entender que significa sin contenido), o una referencia al arreglo de elementos de contenido, cada uno de los cuales es o bien un segmento de texto ( una cadena, es decir, un valor escalar definido no-referencia), o un objeto HTML::Element. Ten en cuenta que incluso si se devuelve un arrayref, puede ser una referencia a un arreglo vacío.

Aunque el código antiguo puede continuar usándolo libremente "$h->content", el código nuevo debería usar "$h->content_list" en casi todos los casos concebibles. Es mi experiencia que en la mayoría de los casos esto conduce a código más simple de todos modos, ya que significa que se puede decir:

@children = $h->content_list;

en lugar del inelegante:

@children = @{$h->content || []};

Si usas "$h->content" (o "$h->content_array_ref"), no debes usar la referencia que devuelve (asumiendo que devolvió una referencia, y no undef) para establecer o cambiar directamente el contenido de un elemento o segmento de texto! En su lugar usa content_refs_list o cualquiera de los otros métodos bajo "Métodos de Modificación de Estructura", más abajo.

content_array_ref

$content_array_ref = $h->content_array_ref(); # never undef

Esto es como "content" (con todas sus advertencias y obsolescencia) excepto que está garantizado devolver una referencia a un arreglo. Es decir, si el nodo dado no tiene "_content" atributo, el "content" método devolvería ese undef, pero "content_array_ref" establecería el valor de "_content" del nodo dado a "[]" (una referencia a un nuevo arreglo vacío), y lo devolvería.

content_refs_list

@content_refs = $h->content_refs_list;

Devuelve una lista de referencias escalares a cada elemento de la lista de contenido de $h. Esto es útil en caso de que quieras editar in-situ algún segmento de texto grande sin tener que obtener una copia del valor actual de ese segmento, modificar esa copia, y luego usar "splice_content" para reemplazar el viejo con el nuevo. En su lugar, aquí puedes editar in-situ:

foreach my $item_r ($h->content_refs_list) {
    next if ref $$item_r;
    $$item_r =~ s/honour/honor/g;
}

Tú podrías lograr actualmente el mismo efecto con:

foreach my $item (@{ $h->content_array_ref }) {
    # deprecated!
    next if ref $item;
    $item =~ s/honour/honor/g;
}

...excepto que usar el valor de retorno de "$h->content" o "$h->content_array_ref" para hacer eso está obsoleto, y podría dejar de funcionar en el futuro.

implicit

$is_implicit = $h->implicit();
$h->implicit($make_implicit);

Devuelve (opcionalmente establece) el atributo "_implicit". Este atributo es un indicador que se usa para señalar que el elemento no estaba originalmente presente en la fuente, sino que fue añadido al árbol de análisis (por HTML::TreeBuilder, por ejemplo) para cumplir con las reglas de la estructura de HTML.

pos

$pos = $h->pos();
$h->pos($element);

Devuelve (y opcionalmente establece) el puntero "_pos" (por "posición actual" pos) de $h. Este atributo es un puntero usado durante algunas operaciones de análisis, cuyo valor es el elemento HTML::Element que en o bajo $h está actualmente "abierto", donde "$h->insert_element(NEW)" insertará realmente un nuevo elemento.

(Esto no tiene nada que ver con la función de Perl llamada "pos", para controlar dónde comienza el emparejamiento de expresiones regulares.)

Si estableces "$h->pos($element)", asegúrate de que $element es o bien $h, o un elemento bajo $h.

Si has estado modificando el árbol bajo $h y ya no estás seguro de si "$h->pos" es válido, puedes hacer cumplir la validez con:

$h->pos(undef) unless $h->pos->is_inside($h);

all_attr

%attr = $h->all_attr();

Devuelve todos los atributos y valores de este elemento, como pares clave-valor. Esto incluirá cualquier atributo "interno" (es decir, los que no estaban presentes en el elemento original, y que no serán representados si/llamas a "$h->as_HTML"). Los atributos internos se distinguen por el hecho de que el primer carácter de su clave (¡no valor! ¡clave!) es un guion bajo ("_").

Ejemplo de salida de "$h->all_attr()" : "'_parent', "[object_value]" , '_tag', 'em', 'lang', 'en-US', '_content', "[array-ref value].

all_attr_names

@names = $h->all_attr_names();
$num_attrs = $h->all_attr_names();

Como "all_attr", pero solo devuelve los nombres de los atributos. En contexto escalar, devuelve el número de atributos.

Ejemplo de salida de "$h->all_attr_names()" : "'_parent', '_tag', 'lang', '_content', ".

all_external_attr

%attr = $h->all_external_attr();

Como "all_attr", excepto que los atributos internos no están presentes.

all_external_attr_names

@names = $h->all_external_attr_names();
$num_attrs = $h->all_external_attr_names();

Normaliza el contenido de $h -- es decir, concatena cualquier segmento de texto adyacente. (Cualquier segmento de texto indefinido se convierte en cadena vacía.) Ten en cuenta que esto no recursa en los descendientes de $h.

delete_ignorable_whitespace

$h->delete_ignorable_whitespace()

Esto recorre por debajo de $h y elimina cualquier segmento de texto que sea espacio en blanco ignorables. No debes usar esto si $h está bajo un "<pre>" elemento.

insert_element

$h->insert_element($element, $implicit);

Inserta (vía push_content) un nuevo elemento bajo el elemento en "$h->pos()". Luego actualiza "$h->pos()" para que apunte al elemento insertado, a menos que $element sea un elemento prototípicamente vacío como "<br>", "<hr>", "<img>", etc. El nuevo "$h->pos()" es devuelto. Este método es útil solo si tu tarea particular del árbol implica establecer "$h->pos()".

MÉTODOS DE VOLCADO

dump

$h->dump()
$h->dump(*FH)  ; # o *FH{IO} o $fh_obj

Imprime el elemento y todos sus hijos en STDOUT (o en un identificador de archivo especificado), en un formato útil solo para depurar. La estructura del documento se muestra mediante sangría (sin etiquetas de cierre).

as_HTML

$s = $h->as_HTML();
$s = $h->as_HTML($entities);
$s = $h->as_HTML($entities, $indent_char);
$s = $h->as_HTML($entities, $indent_char, \%optional_end_tags);

Devuelve una cadena que representa en HTML el elemento y sus descendientes. El argumento opcional $entities especifica una cadena de las entidades a codificar. Para compatibilidad con versiones anteriores, especifica '<>&' aquí. Si se omite o es undef, todos los caracteres no seguros se codifican como entidades HTML. Ver HTML::Entities para detalles. Si se pasa una cadena vacía, no se codifica ninguna entidad.

Si $indent_char se especifica y está definido, el HTML a ser emitido se sangra, usando la cadena que especifiques (a la que probablemente deberías establecer como "\t", o algún número de espacios, si la especificas).

Si "\%optional_end_tags" se especifica y está definido, debería ser una referencia a un hash que contenga un valor verdadero para cada nombre de etiqueta cuya etiqueta de cierre es opcional. Por defecto es "\%HTML::Element::optionalEndTag", que es un alias de %HTML::Tagset::optionalEndTag, que, al momento de escribir esto, contiene valores verdaderos para "p, li, dt, dd". Un valor útil para pasar es un hashref vacío, "{}", lo que significa que ninguna etiqueta de cierre es opcional para este volcado. De lo contrario, considera posiblemente copiar %HTML::Tagset::optionalEndTag a un hash propio, agregando o eliminando valores como desees, y pasando una referencia a ese hash.

as_text

$s = $h->as_text();
$s = $h->as_text(skip_dels => 1);

Devuelve una cadena que consiste solo en las partes de texto de los descendientes del elemento. Cualquier espacio en blanco dentro del elemento se incluye sin cambios, pero el espacio en blanco que no está en el árbol nunca se agrega. Pero recuerda que el espacio en blanco puede ser ignorado o compactado por HTML::TreeBuilder durante el análisis (dependiendo del valor de los atributos "ignore_ignorable_whitespace" y "no_space_compacting" ). También, dado que el espacio en blanco nunca se agrega durante el análisis,

HTML::TreeBuilder->new_from_content("<p>a</p><p>b</p>")
                 ->as_text;

devuelve "ab", no "a b" o "a\nb".

El texto bajo "<script>" o "<style>" elementos nunca se incluye en lo que se devuelve. Si "skip_dels" es verdadero, entonces el contenido de texto bajo "<del>" nodos no se incluye en lo que se devuelve.

as_trimmed_text

$s = $h->as_trimmed_text(...);
$s = $h->as_trimmed_text(extra_chars => '\xA0'); # eliminar &
$s = $h->as_text_trimmed(...); # alias

Esto es igual que as_text(...) excepto que el espacio en blanco inicial y final se elimina, y cualquier espacio en blanco interno se colapsa.

Esto no eliminará espacios no separadores, espacios Unicode, ni ningún otro espacio en blanco no ASCII a menos que proporciones los caracteres extra como un argumento de cadena (por ejemplo, "$h->as_trimmed_text(extra_chars => '\xA0')"). "extra_chars" puede ser cualquier cadena que pueda aparecer dentro de una clase de caracteres, incluyendo rangos como "a-z", clases de caracteres POSIX como "[:alpha:]", y escapes de clases de caracteres como "\p{Zs}".

as_XML

$s = $h->as_XML()

Devuelve una cadena que representa en XML el elemento y sus descendientes.

El XML no está sangrado.

as_Lisp_form

$s = $h->as_Lisp_form();

Devuelve una cadena que representa el elemento y sus descendientes como una forma Lisp. Los caracteres no seguros se codifican como escapes octales.

La forma Lisp está sangrada, y contiene atributos externos ("href", etc.) así como atributos internos ("_tag", "_content", "_implicit", etc.), excepto "_parent", que se omite.

Ejemplo de salida actual para un elemento dado:

("_tag" "img" "border" "0" "src" "pie.png" "usemap" "#main.map")

format

$s = $h->format; # usar HTML::FormatText
$s = $h->format($formatter);

Da formato a la salida de texto. Por defecto es HTML::FormatText.

Toma un segundo argumento que es una referencia a un formateador.

starttag

$start = $h->starttag();
$start = $h->starttag($entities);

Devuelve una cadena que representa la etiqueta de apertura completa para el elemento. Es decir, "<" inicial, nombre de la etiqueta, atributos, y ">" final. Todos los valores están rodeados por comillas dobles, y los caracteres apropiados se codifican. Si $entities se omite o es undef, todos los caracteres no seguros se codifican como entidades HTML. Ver HTML::Entities para detalles. Si especificas algún valor para $entities, recuerda incluir el carácter de comilla doble en él. (Las versiones anteriores de este módulo se comportaban básicamente como si '&">' fuera especificado para $entities.) Si $entities es una cadena vacía, no se escapa ninguna entidad.

starttag_XML

$start = $h->starttag_XML();

Devuelve una cadena que representa la etiqueta de apertura completa para el elemento.

endtag

$end = $h->endtag();

Devuelve una cadena que representa la etiqueta de cierre completa para este elemento. Es decir, "</", nombre de la etiqueta, y ">".

endtag_XML

$end = $h->endtag_XML();

Devuelve una cadena que representa la etiqueta de cierre completa para este elemento. Es decir, "</", nombre de la etiqueta, y ">".

MÉTODOS ESTRUCTURALES SECUNDARIOS

Todos estos métodos involucran algún aspecto estructural del árbol; ya sea que reportan algún aspecto de la estructura del árbol, o involucran un recorrido hacia abajo del árbol, o un caminado hacia arriba del árbol.

is_inside

$inside = $h->is_inside('tag', $element, ...);

Devuelve verdadero si el $h elemento está, o está contenido en algún lugar dentro de un elemento que sea cualquiera de los listados, o cuyo nombre de etiqueta sea cualquiera de los nombres de etiqueta listados. Puedes usar cualquier mezcla de elementos y nombres de etiqueta.

is_empty

$empty = $h->is_empty();

Devuelve verdadero si $h no tiene contenido, es decir, no tiene elementos ni segmentos de texto bajo él. En otras palabras, esto devuelve verdadero si $h es un nodo hoja, también conocido como nodo terminal. No confundas este sentido de "vacío" con otro sentido que puede tener en la terminología SGML/HTML/XML, que significa que el elemento en cuestión es de el tipo (como el de HTML ="Li">"<hr>", "<br>", "<img>", etc.) que no pueden tener ningún contenido.

Es decir, un elemento "<p>" en particular puede no tener contenido, de modo que $that_p_element->is_empty será verdadero -- aunque el elemento "<p>" prototípico no esté "vacío" (no en el sentido en que lo está el elemento "<hr>" prototípico).

Si crees que esto podría dar lugar a código potencialmente confuso, considera simplemente usar el equivalente exacto y más claro: not($h->content_list).

pindex

$index = $h->pindex();

Devuelve el índice del elemento en el arreglo de contenidos de su padre, de modo que $h sería igual a

$h->parent->content->[$h->pindex]
# o
($h->parent->content_list)[$h->pindex]

asumiendo que $h no es la raíz. Si el elemento $h es la raíz, entonces "$h->pindex" devuelve "undef".

left

$element = $h->left();
@elements = $h->left();

En contexto escalar: devuelve el nodo que es el hermano izquierdo inmediato de $h. Si $h es el hijo más a la izquierda (o el único) de su padre (o no tiene padre), entonces esto devuelve undef.

En contexto de lista: devuelve todos los nodos que son hermanos izquierdos de $h (empezando por el más a la izquierda). Si $h es el hijo más a la izquierda (o el único) de su padre (o no tiene padre), entonces esto devuelve una lista vacía.

(Ver también "$h->preinsert(LIST)".)

right

$element = $h->right();
@elements = $h->right();

En contexto escalar: devuelve el nodo que es el hermano derecho inmediato de $h. Si $h es el hijo más a la derecha (o el único) de su padre (o no tiene padre), entonces esto devuelve "undef".

En contexto de lista: devuelve todos los nodos que son hermanos derechos de $h, empezando por el más a la izquierda. Si $h es el hijo más a la derecha (o el único) de su padre (o no tiene padre), entonces esto devuelve una lista vacía.

(Ver también "$h->postinsert(LIST)".)

address

$address = $h->address();
$element_or_text = $h->address($address);

La primera forma (sin parámetro) devuelve una cadena que representa la ubicación de $h en el árbol del cual es miembro. La dirección consiste en números unidos por un '.', comenzando con '0', y seguido por los pindexes de los nodos en el árbol que son ancestros de $h, empezando desde la parte superior.

Así que si la manera de llegar a un nodo empezando en la raíz es ir al hijo 2 de la raíz, luego al hijo 10 de ese, y luego al hijo 0 de ese, y entonces has llegado -- entonces la dirección de ese nodo es "0.2.10.0".

Como un caso un tanto especial, la dirección de la raíz es simplemente "0".

Preveo que esto se usará principalmente para depuración, pero puedes encontrar tus propios usos para ello.

$element_or_text = $h->address($address);

Esta forma devuelve el nodo (ya sea elemento o segmento de texto) en la dirección dada en el árbol del cual $h es parte. (Es decir, la dirección se resuelve empezando desde "$h->root".)

Si no hay ningún nodo en la dirección dada, esto devuelve "undef".

Puedes especificar "direccionamiento relativo" (es decir, que el indexado debe empezar desde $h y no desde "$h->root") haciendo que la dirección empiece con un punto -- por ejemplo, "$h->address(".3.2")" mirará al hijo 3 de $h, y al hijo 2 de ese.

depth

$depth = $h->depth();

Devuelve un número que expresa la profundidad de $hdentro de su árbol, es decir, cuántos pasos está de la raíz. Si $h no tiene padre (es decir, es la raíz), su profundidad es 0.

root

$root = $h->root();

Devuelve el elemento que es la parte superior del árbol de $h. Si $h es la raíz, esto simplemente devuelve $h. (Si quieres probar si $h es la raíz, en lugar de preguntar cuál es su raíz, simplemente prueba not($h->parent).)

lineage

@lineage = $h->lineage();

Devuelve la lista de ancestros de $h, empezando con su padre, y luego el padre de ese padre, y así sucesivamente, hasta la raíz. Si $h es la raíz, esto devuelve una lista vacía.

Si simplemente quieres un conteo del número de elementos en el linaje de $h, usa "$h->depth".

lineage_tag_names

@names = $h->lineage_tag_names();

Devuelve la lista de los nombres de etiqueta de los ancestros de $h, empezando con su padre, y el padre de ese padre, y así sucesivamente, hasta la raíz. Si $h es la raíz, esto devuelve una lista vacía. Ejemplo de salida: "('em', 'td', 'tr', 'table', 'body', 'html')"

Equivalente a:

map { $_->tag } $h->lineage;

descendants

@descendants = $h->descendants();

En contexto de lista, devuelve la lista de todos los elementos descendientes de $h, listados en pre-orden (es decir, un elemento aparece antes que sus elementos-contenido). Los segmentos de texto NO aparecen en la lista. En contexto escalar, devuelve un conteo de todos esos elementos.

descendents

Esto es simplemente un alias al método "descendants" , para la gente que no sabe deletrear.

find_by_tag_name

@elements = $h->find_by_tag_name('tag', ...);
$first_match = $h->find_by_tag_name('tag', ...);

En contexto de lista, devuelve una lista de elementos en o bajo $h que tienen cualquiera de los nombres de etiqueta especificados. En contexto escalar, devuelve el primer elemento (en el recorrido en pre-orden del árbol) encontrado, o undef si no hay ninguno.

find

Esto es simplemente un alias a "find_by_tag_name". (Hubo una vez la intención de crear toda una familia de métodos find_*, pero entonces "look_down" llenó ese nicho, así que resultó que no había mucha razón para la verbosidad del nombre "find_by_tag_name".)

find_by_attribute

@elements = $h->find_by_attribute('attribute', 'value');
$first_match = $h->find_by_attribute('attribute', 'value');

En un contexto de lista, devuelve una lista de elementos en o bajo $h que tienen el atributo especificado, y tienen el valor dado para ese atributo. En un contexto escalar, devuelve el primer elemento (en el recorrido en pre-orden del árbol) encontrado, o undef si no hay ninguno.

Este método está obsoleto en favor del método más expresivo "look_down" , que el código nuevo debería usar en su lugar.

look_down

@elements = $h->look_down( ...criterios... );
$first_match = $h->look_down( ...criterios... );

Esto empieza en $h y busca a través de sus descendientes elementos (en pre-orden), buscando elementos que coincidan con los criterios que especifiques. En contexto de lista, devuelve todos los elementos que coinciden con todos los criterios dados; en contexto escalar, devuelve el primer elemento así (o undef, si nada coincidió).

Hay tres tipos de criterios que puedes especificar:

(nombre_attr, valor_attr)
Esto significa que estás buscando un elemento con ese valor para ese atributo. Ejemplo: "alt", "pix!". Considera que puedes buscar en valores de atributos internos también: "_tag", "p".
(nombre_attr, qr/.../)
Esto significa que estás buscando un elemento cuyo valor para ese atributo coincida con el objeto Regexp especificado.
un coderef
Esto significa que estás buscando elementos donde coderef->(cada_elemento) devuelve verdadero. Ejemplo: 
my @wide_pix_images = $h->look_down(
  _tag => "img",
  alt  => "pix!",
  sub { $_[0]->attr('width') > 350 }
);

Ten en cuenta que "(nombre_attr, valor_attr)" y "(nombre_attr, qr/.../)" los criterios son casi siempre más rápidos que los criterios coderef, así que deberían ponerse antes que ellos en tu lista de criterios. Es decir, en el ejemplo de arriba, la sub ref se llama solo para elementos que ya han pasado el criterio de tener un atributo "_tag" con valor "img", y un atributo "alt" con valor "pix!". Si el coderef estuviera primero, se llamaría en cada elemento, y entonces los elementos que pasen ese criterio (es decir, elementos para los cuales el coderef devolvió verdadero) serían verificados para sus atributos "_tag" y "alt".

Ten en cuenta que la comparación de valores de atributos de cadena contra la cadena valor en "(nombre_attr, valor_attr)" ¡es INsensible a mayúsculas! Un criterio de "('align', 'right')" coincidirá con un elemento cuyo valor de "align" es "RIGHT", o "right" o "rIGhT", etc.

Nótese también que "look_down" considera que "" (cadena vacía) y undef son cosas diferentes, en los valores de los atributos. Así que esto:

$h->look_down("alt", "")

encontrará elementos con un atributo "alt", pero donde el valor del atributo "alt" es "". Pero esto:

$h->look_down("alt", undef)

es lo mismo que:

$h->look_down(sub { !defined($_[0]->attr('alt')) } )

Es decir, encuentra elementos que no tienen un atributo "alt" en absoluto (o que sí tienen un atributo "alt", pero con un valor de undef -- lo cual normalmente no es posible).

Nótese que cuando se dan varios criterios, esto significa que se buscan elementos que coinciden con todos sus criterios, no solo con alguno de ellos. En otras palabras, hay un "y" implícito, no un "o". Así que si quisieras expresar que quieres encontrar elementos con un atributo "name" con el valor "foo" o con un atributo "id" con el valor "baz", tendrías que hacerlo así:

@them = $h->look_down(
  sub {
    # los lc son para ignorar mayúsculas/minúsculas
    lc($_[0]->attr('name')) eq 'foo'
    or lc($_[0]->attr('id')) eq 'baz'
  }
);

Los criterios de referencia a subrutina (coderef) son más expresivos que los criterios "(attr_name, attr_value)" y "(attr_name, qr/.../)" , y todos los criterios "(attr_name, attr_value)" y "(attr_name, qr/.../)" podrían expresarse en términos de referencias a subrutina. Sin embargo, "(attr_name, attr_value)" y "(attr_name, qr/.../)" son una abreviatura conveniente. (De hecho, "look_down" en sí mismo es básicamente una "abreviatura" también, ya que cualquier cosa que puedas hacer con "look_down" podrías hacerla recorriendo el árbol, ya sea con el método "traverse" o con una rutina propia. Sin embargo, "look_down" a menudo permite un código muy conciso y claro.)

look_up

@elements = $h->look_up( ...criterios... );
$first_match = $h->look_up( ...criterios... );

Esto es idéntico a "$h->look_down", excepto que mientras que "$h->look_down" básicamente recorre la lista:

($h, $h->descendants)

"$h->look_up" en cambio recorre la lista

($h, $h->lineage)

Así que, por ejemplo, esto devuelve todos los ancestros de $h (posiblemente incluyendo $h mismo) que son elementos "<td>" con un atributo "align" con un valor de "right" (o "RIGHT", etc.):

$h->look_up("_tag", "td", "align", "right");

traverse

$h->traverse(...opciones...)

La extensa discusión sobre el método innecesario y confuso de HTML::Element "traverse" se ha movido a un archivo separado: HTML::Element::traverse

attr_get_i

@values = $h->attr_get_i('atributo');
$first_value = $h->attr_get_i('atributo');

En contexto de lista, devuelve una lista que consiste en los valores del atributo dado para $h y para todos sus ancestros empezando desde $h y subiendo. Los nodos sin dicho atributo se omiten. ("attr_get_i" significa "obtener atributo, con herencia".) En contexto escalar, devuelve el primer valor, o undef si no hay ninguno.

Considere un documento que consiste en:

<html lang='i-klingon'>
  <head><title>Pati Pata</title></head>
  <body>
    <h1 lang='la'>Stuff</h1>
    <p lang='es-MX' align='center'>
      Foo bar baz <cite>Quux</cite>.
    </p>
    <p>Hooboy.</p>
  </body>
</html>

Si $h es el elemento "<cite>" , "$h->attr_get_i("lang")" en contexto de lista devolverá la lista "('es-MX', 'i-klingon')". En contexto escalar, devolverá el valor 'es-MX'.

Si llamas con múltiples nombres de atributo...

@values = $h->attr_get_i('a1', 'a2', 'a3');
$first_value = $h->attr_get_i('a1', 'a2', 'a3');

...en contexto de lista, esto devolverá una lista que consiste en los valores de estos atributos que existen en $h y sus ancestros. En contexto escalar, esto devuelve el primer valor (es decir, el valor del primer atributo existente del primer elemento que tenga cualquiera de los atributos listados). Así que, en el ejemplo de arriba,

$h->attr_get_i('lang', 'align');

devolverá:

 ('es-MX', 'center', 'i-klingon') # en contexto de lista
o
 'es-MX' # en contexto escalar.

Pero nótese que esto:

$h->attr_get_i('align', 'lang');

devolverá:

 ('center', 'es-MX', 'i-klingon') # en contexto de lista
o
 'center' # en contexto escalar.

tagname_map

$hash_ref = $h->tagname_map();

Recorre $h y todos sus descendientes, y crea un hash (del que se devuelve una referencia) donde cada entrada consiste en una clave que es un nombre de etiqueta, y un valor que es una referencia a una lista de todos los elementos que tienen ese nombre de etiqueta. Es decir, este método devuelve:

{
  # A través de $h y todos los descendientes...
  'a'   => [ ...lista de todos los elementos <a>   ... ],
  'em'  => [ ...lista de todos los elementos <em>  ... ],
  'img' => [ ...lista de todos los elementos <img> ... ],
}

(Hay entradas en el hash solo para aquellos nombres de etiqueta que ocurren en/debajo de $h -- así que si no hay elementos "<img>" , no habrá ninguna entrada "img" en la referencia al hash devuelta.)

Ejemplo de uso:

my $map_r = $h->tagname_map();
my @heading_tags = sort grep m/^h\d$/s, keys %$map_r;
if(@heading_tags) {
  print "Heading levels used: @heading_tags\n";
} else {
  print "No headings.\n"
}

extract_links

$links_array_ref = $h->extract_links();
$links_array_ref = $h->extract_links(@tiposDeseados);

Devuelve los enlaces encontrados al recorrer el elemento y todos sus hijos y buscar atributos (como "href" en un elemento "<a>" , o "src" en un elemento "<img>" ) cuyos valores representan enlaces. El valor de retorno es una referencia a un array. Cada elemento del array es una referencia a un array con cuatro elementos: el valor del enlace, el elemento que tiene el atributo con ese valor de enlace, y el nombre de ese atributo, y el nombre de etiqueta de ese elemento. (Ejemplo: "['http://www.suck.com/'," $elem_obj ", 'href', 'a']".) Puede que uses o no el elemento en sí mismo -- para algunos propósitos, puedes usar solo el valor del enlace.

Puedes especificar que quieres extraer enlaces solo de algunos tipos de elementos (en lugar del valor por defecto, que es extraer enlaces de todos los tipos de elementos conocidos que tienen atributos cuyos valores representan enlaces). Por ejemplo, si quieres extraer enlaces solo de elementos "<a>" y elementos "<img>" , podrías codificarlo así:

for (@{  $e->extract_links('a', 'img')  }) {
    my($link, $element, $attr, $tag) = @$_;
    print
      "Hey, there's a $tag that links to ",
      $link, ", in its $attr attribute, at ",
      $element->address(), ".\n";
}

simplify_pres

$h->simplify_pres();

En los fragmentos de texto bajo elementos PRE que están en/debajo de $h, esta rutina normaliza todos los saltos de línea, y expande todas las tabulaciones.

Es decir, si lees un archivo con líneas delimitadas por "\cm\cj", el texto bajo las áreas PRE tendrá "\cm\cj"en lugar de "\n". Llamar a "$h->simplify_pres" en un árbol así convertirá "\cm\cj"en "\n".

Las tabulaciones se expanden al número de espacios necesario para llegar a la siguiente columna 8 -- la forma habitual de expandirlas.

same_as

$equal = $h->same_as($i)

Devuelve verdadero si $h y $i son ambos elementos que representan el mismo árbol de elementos, cada uno con el mismo nombre de etiqueta, con los mismos atributos explícitos (es decir, sin contar atributos cuyos nombres empiezan con "_"), y con el mismo contenido (texto, comentarios, etc.).

La igualdad de los elementos descendientes se prueba, recursivamente, con "$child1->same_as($child_2)", y la igualdad de los segmentos de texto se prueba con "$segment1 eq $segment2".

new_from_lol

$h = HTML::Element->new_from_lol($array_ref);
@elements = HTML::Element->new_from_lol($array_ref, ...);

Construye recursivamente un árbol de nodos, basado en la estructura de datos (no cíclica) representada por cada $array_ref, donde esto es una referencia a un array de arrays (de arrays (de arrays (etc.)).

En cada referencia a array en esa estructura, los diferentes tipos de valores se tratan de la siguiente manera:

  • Referencias a array

    Las referencias a array se consideran que designan un subárbol que representa los hijos del nodo construido a partir de la referencia a array actual.

  • Referencias a hash

    Las referencias a hash se consideran que contienen pares atributo-valor a añadir al elemento que se va a

    new_from_lol

    HTML::Element->new_from_lol( ARGF [, $arg2, ... ] )

    Creates and returns a new element, possibly the root of a treelet of elements, from the specified structure. This structure must be a reference to an array, and its first element must be a string (the tag name), and all other elements must be either strings, array references, or hash references.

    Here's how the structure is interpreted:

    • The first element of the array reference MUST be a string, and will be taken as the tag name of the element to be constructed.

    • If any element after the first is a hash reference, it will be treated as the attributes of the element to be constructed. Any subsequent hash references will be ignored. If there are multiple hash references, only the first will be used.

    • Text segments

      Text segments at the start of any arrayref will be considered to specify the name of the element to be constructed from the current arrayref; all other text segments will be considered to specify text segments as children for the current arrayref.

    • Elements

      Existing element objects are either inserted into the treelet constructed, or clones of them are. That is, when the lol-tree is being traversed and elements constructed based what's in it, if an existing element object is found, if it has no parent, then it is added directly to the treelet constructed; but if it has a parent, then "$that_node->clone" is added to the treelet at the appropriate place.

    An example will hopefully make this more obvious:

    my $h = HTML::Element->new_from_lol(
  ['html',
    ['head',
      [ 'title', 'I like stuff!' ],
    ],
    ['body',
      {'lang', 'en-JP', _implicit => 1},
      'stuff',
      ['p', 'um, p < 4!', {'class' => 'par123'}],
      ['div', {foo => 'bar'}, '123'],
    ]
  ]
);
$h->dump;

    Will print this:

    <html> @0
  <head> @0.0
    <title> @0.0.0
      "I like stuff!"
  <body lang="en-JP"> @0.1 (IMPLICIT)
    "stuff"
    <p class="par123"> @0.1.1
      "um, p < 4!"
    <div foo="bar"> @0.1.2
      "123"

    And printing $h->as_HTML will give something like:

    <html><head><title>I like stuff!</title></head>
<body lang="en-JP">stuff<p class="par123">um, p &lt; 4!
<div foo="bar">123</div></body></html>

    You can even do fancy things with "map":

    $body->push_content(
  # push_content implicitly calls new_from_lol on arrayrefs...
  ['br'],
  ['blockquote',
    ['h2', 'Pictures!'],
    map ['p', $_],
    $body2->look_down("_tag", "img"),
      # images, to be copied from that other tree.
  ],
  # and more stuff:
  ['ul',
    map ['li', ['a', {'href'=>"$_.png"}, $_ ] ],
    qw(Peaches Apples Pears Mangos)
  ],
);

    In scalar context, you must supply exactly one arrayref. In list context, you can pass a list of arrayrefs, and new_from_lol will return a list of elements, one for each arrayref.

    @elements = HTML::Element->new_from_lol(
  ['hr'],
  ['p', 'And there, on the door, was a hook!'],
);
 # constructs two elements.

    objectify_text

    $h->objectify_text();

    This turns any text nodes under $h from mere text segments (strings) into real objects, pseudo-elements with a tag-name of "~text", and the actual text content in an attribute called "text". (For a discussion of pseudo-elements, see the "tag" method, far above.) This method is provided because, for some purposes, it is convenient or necessary to be able, for a given text node, to ask what element is its parent; and clearly this is not possible if a node is just a text string.

    Note that these "~text" objects are not recognized as text nodes by methods like "as_text". Presumably you will want to call "$h->objectify_text", perform whatever task that you needed that for, and then call "$h->deobjectify_text" before calling anything like "$h->as_text".

    deobjectify_text

    $h->deobjectify_text();

    This undoes the effect of "$h->objectify_text". That is, it takes any "~text" pseudo-elements in the tree at/under $h, and deletes each one, replacing each with the content of its "text" attribute.

    Note that if $h itself is a "~text" pseudo-element, it will be destroyed -- a condition you may need to treat specially in your calling code (since it means you can't very well do anything with $h after that). So that you can detect that condition, if $h is itself a "~text" pseudo-element, then this method returns the value of the "text" attribute, which should be a defined value; in all other cases, it returns undef.

    (This method assumes that no "~text" pseudo-element has any children.)

    number_lists

    $h->number_lists();

    For every UL, OL, DIR, and MENU element at/under $h, this sets a "_bullet" attribute for every child LI element. For LI children of an OL, the "_bullet" attribute's value will be something like "4.", "d.", "D.", "IV.", or "iv.", depending on the OL element's "type" attribute. LI children of a UL, DIR, or MENU get their "_bullet" attribute set to "*". There should be no other LIs (i.e., except as children of OL, UL, DIR, or MENU elements), and if there are, they are unaffected.

    has_insane_linkage

    $h->has_insane_linkage

    This method is for testing whether this element or the elements under it have linkage attributes (_parent and _content) whose values are deeply aberrant: if there are undefs in a content list; if an element appears in the content lists of more than one element; if the _parent attribute of an element doesn't match its actual parent; or if an element appears as its own descendant (i.e., if there is a cyclicity in the tree).

    This returns empty list (or false, in scalar context) if the subtree's linkage methods are sane; otherwise it returns two items (or true, in scalar context): the element where the error occurred, and a string describing the error.

    This method is provided is mainly for debugging and troubleshooting -- it should be quite impossible for any document constructed via HTML::TreeBuilder to parse into a non-sane tree (since it's not the content of the tree per se that's in question, but whether the tree in memory was properly constructed); and it should be impossible for you to produce an insane tree just thru reasonable use of normal documented structure-modifying methods. But if you're constructing your own trees, and your program is going into infinite loops as during calls to traverse() or any of the secondary structural methods, as part of debugging, consider calling "has_insane_linkage" on the tree.

    element_class

    $classname = $h->element_class();

    This method returns the class which will be used for new elements. It defaults to HTML::Element, but can be overridden by subclassing or esoteric means best left to those will will read the source and then not complain when those esoteric means change. (Just subclass.)

Use_Weak_Refs

$enabled = HTML::Element->Use_Weak_Refs;
HTML::Element->Use_Weak_Refs( $enabled );

This method allows you to check whether weak reference support is enabled, and to enable or disable it. For details, see "Weak References". $enabled is true if weak references are enabled.

You should not switch this in the middle of your program, and you probably shouldn't use it at all. Existing trees are not affected by this method (until you start modifying nodes in them).

Throws an exception if you attempt to enable weak references and your Perl or Scalar::Util does not support them.

Disabling weak reference support is deprecated.

BUGS

* If you want to free the memory associated with a tree built of HTML::Element nodes, and you have disabled weak references, then you will have to delete it explicitly using the "delete" method. See "Weak References".

* There's almost nothing to stop you from making a "tree" with cyclicities (loops) in it, which could, for example, make the traverse method go into an infinite loop. So don't make cyclicities! (If all you're doing is parsing HTML files, and looking at the resulting trees, this will never be a problem for you.)

* There's no way to represent comments or processing directives in a tree with HTML::Elements. Not yet, at least.

* There's (currently) nothing to stop you from using an undefined value as a text segment. If you're running under "perl -w", however, this may make HTML::Element's code produce a slew of warnings.

NOTAS SOBRE SUBCLASES

You are welcome to derive subclasses from HTML::Element, but you should be aware that the code in HTML::Element makes certain assumptions about elements (and I'm using "element" to mean ONLY an object of class HTML::Element, or of a subclass of HTML::Element):

* The value of an element's _parent attribute must either be undef or otherwise false, or must be an element.

* The value of an element's _content attribute must either be undef or otherwise false, or a reference to an (unblessed) array. The array may be empty; but if it has items, they must ALL be either mere strings (text segments), or elements.

* The value of an element's _tag attribute should, at least, be a string of printable characters.

Además, ten en cuenta estas reglas:

* No rompas la encapsulación de los objetos. Es decir, accede a su contenido solo a través de $obj->attr o métodos más específicos.

* Deberías pensar dos veces antes de sobrescribir completamente alguno de los métodos que proporciona HTML::Element. (Sobrescribir con un método que llama al método de la superclase no está tan mal, sin embargo).
