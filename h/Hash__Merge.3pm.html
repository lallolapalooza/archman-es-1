SINOPSI

S 
my %a = (
    'foo'    => 1,
    'bar'    => [qw( a b e )],
    'querty' => { 'bob' => 'alice' },
);
my %b = (
    'foo'    => 2,
    'bar'    => [qw(c d)],
    'querty' => { 'ted' => 'margeret' },
);

my %c = %{ merge( \%a, \%b ) };

Hash::Merge::set_behavior('RIGHT_PRECEDENT');

# Esto es lo mismo que arriba

Hash::Merge::add_behavior_spec(
    {   'SCALAR' => {
            'SCALAR' => sub { $_[1] },
            'ARRAY'  => sub { [ $_[0], @{ $_[1] } ] },
            'HASH'   => sub { $_[1] },
        },
        'ARRAY' => {
            'SCALAR' => sub { $_[1] },
            'ARRAY'  => sub { [ @{ $_[0] }, @{ $_[1] } ] },
            'HASH'   => sub { $_[1] },
        },
        'HASH' => {
            'SCALAR' => sub { $_[1] },
            'ARRAY'  => sub { [ values %{ $_[0] }, @{ $_[1] } ] },
            'HASH'   => sub { Hash::Merge::_merge_hashes( $_[0], $_[1] ) },
        },
    },
    'Mi comportamiento',
);

# También existe una interfaz orientada a objetos.

my $merger = Hash::Merge->new('LEFT_PRECEDENT');
my %c = %{ $merger->merge( \%a, \%b ) };

# Todos los cambios de comportamiento (p. ej. $merge->set_behavior(...)), llamados en un objeto, siguen siendo específicos de ese objeto
# El comportamiento heredado de "Configuración global" solo se respeta cuando new se llama como una función no orientada a objetos.
# reutilizar el comportamiento especificado globalmente
my $merger = Hash::Merge->new();
$merger->add_behavior_spec(Hash::Merge::get_behavior_spec("Mi comportamiento"), "Mi comportamiento");
my %c = %{ $merger->merge( \%a, \%b ) };
# reutilizar el comportamiento especificado externamente
use Hash::Merge::Extra ();
my $merger = Hash::Merge->new();
$merger->add_behavior_spec(Hash::Merge::Extra::L_REPLACE, "L_REPLACE");
my %c = %{ $merger->merge( \%a, \%b )
}
;

DESCRIPCIÓ

N

Hash::Merge fusiona dos hashes arbitrariamente profundos en un único hash. Es decir, en cualquier nivel, añadirá pares clave-valor no conflictivos de un hash al otro, y sigue un conjunto de reglas específicas cuando hay conflictos entre clave y valor (como se describe a continuación). El hash se recorre de forma recursiva, de modo que los hashes anidados profundamente que están en el mismo nivel se fusionarán cuando se fusionen los hashes padre. Tenga en cuenta que los hashes autorreferentes o las referencias recursivas no son manejados bien por este

método.

Los valores en los hashes se consideran que son referencias ARRAY, referencias HASH, o de lo contrario se tratan como SCALAR. Por defecto, los datos pasados a la función de fusión se clonan usando el módulo Clone; sin embargo, si es necesario, este comportamiento se puede cambiar para usar tantos de los valores originales como sea posible. (Vea "set_clone_beha

vior").

Debido a que hay varias formas posibles en las que uno puede querer fusionar valores cuando las claves están en conflicto, Hash::Merge proporciona varios métodos predefinidos para su comodidad, así como una forma de definir los suyos propios. Estos son (actualmente)

:
Precedencia
izquierda
Este es el comportamiento por defecto.

Los valores enterrados en el hash izquierdo nunca se perderán; se intentará añadir cualquier valor que pueda ser añadido desde el hash

derecho. 
my $merge = Hash::Merge->new();
my $merge = Hash::Merge
->new('LEFT_PRECEDENT'); $merge->set_behavior('LEFT_PR
ECEDENT'); Hash::Merge::set_behavior('LEFT_PRECEDENT');
Precedencia
derecha
Igual que la Precedencia izquierda, pero con los valores del hash derecho nunca perdidos 
my $merge = Hash::Merge->new('RIGHT_PRECEDENT
'); $merge->set_behavior('RIGHT_PRECEDENT');
Hash::Merge::set_behavior('RIGHT_PRECEDENT');
Precedencia de
almacenamiento
Si las claves en conflicto tienen dos medios de almacenamiento diferentes, el medio 'más grande' ganará; los arrays se prefieren sobre los escalares, y los hashes sobre cualquiera de los dos. El otro medio intentará ser ajustado en el otro, pero si esto no es posible, los datos se descartan. 
my $merge = Hash::Merge->new('STORAGE_PRECEDENT
'); $merge->set_behavior('STORAGE_PRECEDENT');
Hash::Merge::set_behavior('STORAGE_PRECEDENT');
Precedencia de
retención
No se perderán datos; los escalares se unirán con los arrays, y los escalares y arrays se 'hashearán' para ajustarlos en un hash. 
my $merge = Hash::Merge->new('RETAINME
NT_PRECEDENT'); $merge->set_behavior(
'RETAINMENT_PRECEDENT'); Hash::Merge:
:set_behavior('RETAINMENT_PRECEDENT');

Las descripciones específicas de cómo funcionan estas se detallan a

continuación.
merge ( <hashref>, <hashref>
)
Fusiona dos hashes según las reglas especificadas. Devuelve una referencia al nuevo
hash.
_hashify( <scalar>|<arrayref> ) -- FUNCIÓN
INTERNA
Devuelve una referencia a un hash creado a partir del escalar o la referencia al array, donde, para el valor escalar, o cada elemento del array, hay una clave y su valor igual a ese valor específico. Por ejemplo, si pasa el escalar '3', el hash será { 3 =>
3 }.
_merge_hashes( <hashref>, <hashref> ) -- FUNCIÓN
INTERNA
Realmente hace la evaluación clave por clave de dos hashes y devuelve el nuevo hash fusionado. Tenga en cuenta que esto llama recursivamente a "merge
".
set_clone_behavior( <scalar>
)
Establece cómo se maneja la clonación de datos por Hash::Merge. Si esto es verdadero, los datos se clonarán; si es falso, se usarán los datos originales siempre que sea posible. Por defecto, la clonación está activada (establecida en verdadero)
.
get_clone_behavior(
)
Devuelve el comportamiento actual para la clonación de
datos.
set_behavior( <scalar>
)
Especifica qué comportamiento integrado de fusión se desea. El escalar debe ser uno de los dados a
continuación.
get_behavior(
)
Devuelve el comportamiento que está actualmente en uso por Hash::
Merge.
specify_behavior( <hashref>, [<name>] )
[obsoleto]
Alias para "add_behavior
_spec".
add_behavior_spec( <hashref>, [<name>
] )
Añade una especificación de comportamiento de fusión personalizada para Hash::Merge. Esto debe ser un hashref definido con (al menos) 3 claves, SCALAR, ARRAY y HASH; cada una de esas claves debe tener otro hashref con (al menos) las mismas 3 claves definidas. Además, los valores en esos hashes deben ser referencias a código. Estos serán llamados con dos argumentos, los valores izquierdo y derecho para la fusión. Su referencia a código debe devolver un escalar o una referencia a array o hash según su comportamiento planeado. Si es necesario, use las funciones _hashify y _merge_hashes como funciones auxiliares para estas. Por ejemplo, si quiere añadir el SCALAR izquierdo al ARRAY derecho, puede hacer que su especificación de comportamiento incluya: 
%spec = ( ...SCALAR => { ARRAY => sub { [ $_[0], @$_[1] ] }, ... }
} );

Tenga en cuenta que puede importar _hashi

fy y _merge_hashes al espacio de nombres
de su programa con la etiqueta 'custom'.
get_behavior_spec( [<name>
] )
Devuelve una especificación de comportamiento de fusión definida previamente. Si el nombre no se especifica, se aplica el mismo valor por defecto que en add_behavior_spec.

Si no se conoce ningú

n nombre que se refie
ra a una especificaci
ón de comportamiento,
no se devuelve nada.

COMPORTAMIENTOS

INTEGRADOS

Aquí están los detalles sobre cómo se llaman los comportamientos internos actuales y qué hace cada uno. Asuma que el valor izquierdo se da como $a, y el derecho como $b (estos son escalares o referencias

apropiadas) 
TIPO IZQUIERDO    TIPO DERECHO    LEFT_PRECEDENT       RIGHT_PRECEDENT
 SCALAR       SCALAR        $a                   $b
 SCALAR       ARRAY         $a                   ( $a, @$b )
 SCALAR       HASH          $a                   %$b
 ARRAY        SCALAR        ( @$a, $b )          $b
 ARRAY        ARRAY         ( @$a, @$b )         ( @$a, @$b )
 ARRAY        HASH          ( @$a, values %$b )  %$b 
 HASH         SCALAR        %$a                  $b
 HASH         ARRAY         %$a                  ( values %$a, @$b )
 HASH         HASH          merge( %$a, %$b )    merge( %$a, %$b )
TIPO IZTIPO    TIPO CORRECTO    PRECEDENCIA DE ALMACENAMIENTO    PRECEDENCIA DE RETENCIÓN
 ESCALAR       ESCALAR        $a                   ( $a ,$b )
 ESCALAR       ARREGLO        ( $a, @$b )          ( $a, @$b )
 ESCALAR       HASH           %$b                  merge( hashify( $a ), %$b )
 ARREGLO       ESCALAR        ( @$a, $b )          ( @$a, $b )
 ARREGLO       ARREGLO        ( @$a, @$b )         ( @$a, @$b )
 ARREGLO       HASH           %$b                  merge( hashify( @$a ), %$b )
 HASH          ESCALAR        %$a                  merge( %$a, hashify( $b ) )
 HASH          ARREGLO        %$a                  merge( %$a, hashify( @$b ) )
 HASH          HASH           merge( %$a, %$b )    merge( %$a, %$b
)

(*) ten en cuenta que merg

e llama a _merge_hashes, h
ashify llama a _hashify.
