DESCRIPCION DETALLADA

Las plataformas con memoria heterogénea requieren formas de decidir si un buffer debe asignarse en memoria 'rápida' (como HBM), memoria 'normal' (DDR) o incluso memoria 'lenta' pero de gran capacidad (no volátil). Estos nodos de memoria se denominan 'Destinos' (Targets), mientras que la CPU que accede a ellos se denomina 'Iniciador' (Initiator). El rendimiento del acceso depende de su localidad (plataformas NUMA) así como del rendimiento intrínseco de los destinos (plataformas heterogéneas).

Los siguientes atributos describen el rendimiento de los accesos a memoria desde un Iniciador a un Destino de memoria, por ejemplo, su latencia o ancho de banda. Los iniciadores que realizan estos accesos a memoria suelen ser algunas PUs o Cores (descritos como un conjunto de CPUs). Por lo tanto, un Core puede elegir dónde asignar un buffer de memoria comparando los atributos de diferentes nodos de memoria objetivo cercanos.

También hay algunos atributos que son de ámbito general. Su valor no depende de un iniciador específico que realice un acceso. La Capacidad del nodo de memoria es un ejemplo de tal atributo sin iniciador.

Una forma de usar esta API es comenzar con un conjunto de CPUs que describa los Cores donde está enlazado un programa. El mejor nodo NUMA de destino para asignar memoria en este programa en estos Cores puede obtenerse pasando este conjunto de CPUs como iniciador a hwloc_memattr_get_best_target() con el atributo de memoria relevante. Por ejemplo, si el código está limitado por la latencia, utilice el atributo Latencia.

Un enfoque más flexible consiste en obtener la lista de nodos NUMA locales pasando este conjunto de CPUs a hwloc_get_local_numanode_objs(). Los valores de los atributos para estos nodos, si los hay, pueden obtenerse luego con hwloc_memattr_get_value() y compararse manualmente con los criterios deseados.

Los atributos de memoria también se utilizan internamente para construir Niveles de Memoria (Memory Tiers) que proporcionan una forma sencilla de distinguir los nodos NUMA de diferentes tipos, como se explica en Memoria Heterogénea.

Además de los niveles, hwloc define un conjunto de nodos 'predeterminados' desde donde se deben realizar las asignaciones de memoria normal (ver hwloc_topology_get_default_nodeset()). Esto también es útil para dividir la máquina en un conjunto de dominios NUMA no superpuestos, por ejemplo, para enlazar tareas por dominio.

Ver también

Hay un ejemplo disponible en doc/examples/memory-attributes.c en el árbol de fuentes.

Nota

La API también admite objetos específicos como iniciadores, pero actualmente no es utilizada internamente por hwloc. Los usuarios pueden, por ejemplo, usarla para proporcionar valores de rendimiento personalizados para accesos a memoria del host realizados por GPUs.

La interfaz en realidad también acepta destinos que no son nodos NUMA.

Documentación del Típo de Enumeración

enum hwloc_local_numanode_flag_e

Banderas para seleccionar nodos NUMA de destino.

Enumerador

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Selecciona nodos NUMA cuya localidad es mayor que el conjunto de CPUs dado. Por ejemplo, si se proporciona una PU individual (o su conjunto de CPUs) en initiator, selecciona todos los nodos cercanos al paquete que contiene esta PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Selecciona nodos NUMA cuya localidad es menor que el conjunto de CPUs dado. Por ejemplo, si se proporciona un paquete (o su conjunto de CPUs) en initiator, también selecciona nodos que solo están conectados a la mitad de ese paquete.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Selecciona nodos NUMA cuya localidad intersecta el conjunto de CPUs dado. Esto incluye localidades mayores y menores, así como localidades que están parcialmente incluidas. Por ejemplo, si la localidad es un núcleo de ambos paquetes, un nodo NUMA local a un paquete no es ni mayor ni menor que esta localidad, pero sí la intersecta.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Selecciona todos los nodos NUMA de la topología. Se ignora el iniciador initiator.

Descripción de la API

Las funciones presentadas en esta sección permiten consultar y manipular atributos de memoria.

int hwloc_memattr_get_obj_value (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t obj, struct hwloc_location * initiator, unsigned long flags, hwloc_uint64_t * value)

Devuelve un valor de atributo para un objeto dado del topología. Si el atributo no está relacionado con un iniciador específico (no tiene el flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR), el campo initiator se ignora y puede ser NULL.

obj no puede ser NULL. Si attribute es HWLOC_MEMATTR_ID_CAPACITY, obj debe ser un nodo NUMA. Si es HWLOC_MEMATTR_ID_LOCALITY, obj debe tener un conjunto de CPUs.

flags debe ser 0 por ahora.

Devuelve

0 en caso de éxito.

-1 en caso de error, por ejemplo con errno establecido a EINVAL si los flags no son válidos o si no existe tal atributo.

Nota

El iniciador initiator debe ser de tipo HWLOC_LOCATION_TYPE_CPUSET al referirse a accesos realizados por núcleos de CPU. HWLOC_LOCATION_TYPE_OBJECT no se utiliza actualmente internamente por hwloc, pero los usuarios pueden, por ejemplo, utilizarlo para proporcionar información personalizada sobre accesos a memoria del host realizados por GPUs.

int hwloc_memattr_get_by_name (hwloc_topology_t topology, const char * name, hwloc_memattr_id_t * id)

Devuelve el identificador del atributo de memoria con el nombre dado.

Devuelve

0 en caso de éxito.

-1 con errno establecido a EINVAL si no existe tal atributo.

int hwloc_memattr_get_initiators (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, unsigned long flags, unsigned * nr, struct hwloc_location * initiators, hwloc_uint64_t * values)

Devuelve los iniciadores que tienen valores para un atributo dado para un nodo NUMA de destino específico. Devuelve los iniciadores para el atributo y nodo de destino dados en el array initiators. Si values no es NULL, los valores del atributo correspondientes se almacenan en el array al que apunta.

En la entrada, nr apunta al número de iniciadores que pueden ser almacenados en el array initiators (y values). En la salida, nr apunta al número de iniciadores (y valores) que se encontraron realmente, incluso si algunos de ellos no pudieron ser almacenados en el array. Los iniciadores que no pudieron ser almacenados se ignoran, pero la función aún devuelve éxito (0). El llamador puede averiguarlo comparando el valor apuntado por nr antes y después de la llamada a la función.

Los iniciadores devueltos no deben ser modificados ni liberados, pertenecen a la topología.

target_node no puede ser NULL.

flags debe ser 0 por ahora.

Si el atributo no se relaciona con un iniciador específico (no tiene el flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR), no se devuelve ningún iniciador.

Devuelve

0 en caso de éxito o -1 en caso de error.

Nota

Esta función está pensada para herramientas y depuración (listar información interna) en lugar de para consultas de aplicaciones. Las aplicaciones deberían seleccionar nodos NUMA útiles con hwloc_get_local_numanode_objs() y luego mirar sus valores de atributo para algunos iniciadores relevantes.

int hwloc_memattr_get_targets (hwloc_topology_t topology, hwloc_memattr_id_t attribute, struct hwloc_location * initiator, unsigned long flags, unsigned * nr, hwloc_obj_t * targets, hwloc_uint64_t * values)

Devuelve los nodos NUMA de destino que tienen algunos valores para un atributo dado. Devuelve los destinos para el atributo dado en el array targets (para el iniciador dado si lo hay). Si values no es NULL, los valores del atributo correspondientes se almacenan en el array al que apunta.

En la entrada, nr apunta al número de destinos que pueden ser almacenados en el array targets (y values). En la salida, nr apunta al número de destinos (y valores) que se encontraron realmente, incluso si algunos de ellos no pudieron ser almacenados en el array. Los destinos que no pudieron ser almacenados se ignoran, pero la función aún devuelve éxito (0). El llamador puede averiguarlo comparando el valor apuntado por nr antes y después de la llamada a la función.

Los destinos devueltos no deben ser modificados ni liberados, pertenecen a la topología.

El argumento initiator se ignora si el atributo no se relaciona con un iniciador específico (no tiene el flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR). De lo contrario, initiator puede ser no NULL para reportar solo destinos que tienen un valor para ese iniciador.

flags debe ser 0 por ahora.

0 en caso de éxito o -1 en caso de error.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags)

Devuelve el conjunto de nodos NUMA por defecto. En máquinas con memoria heterogénea, algunos nodos NUMA se consideran los nodos por defecto, es decir, de dónde deben hacerse las asignaciones básicas. Estos suelen ser nodos DRAM.

Otros nodos pueden estar reservados para usos específicos (memoria de dispositivos de E/S, por ejemplo, memoria de GPU), memoria pequeña pero de alto rendimiento (HBM), memoria grande pero lenta (NVM), etc. Los búferes no deberían asignarse normalmente desde allí a menos que se requiera explícitamente.

Esta función rellena nodeset con los bits de los nodos NUMA considerados por defecto.

Se garantiza que estos nodos tienen conjuntos de CPU que no se intersecan, es decir, los núcleos ya no pueden tener múltiples nodos NUMA locales. Por lo tanto, esto puede usarse para iterar sobre la plataforma dividida en localidades NUMA separadas, por ejemplo, para enlazar una tarea por dominio NUMA.

Cualquier núcleo que tuviera algún nodo NUMA local en la topología inicial todavía debería tener uno en el conjunto de nodos por defecto. Los casos extremos en los que esto sería incorrecto consisten en plataformas asimétricas con nodos DRAM faltantes, o topologías que ya se restringieron a menos nodos NUMA.

El conjunto de nodos devuelto puede pasarse a hwloc_topology_restrict() con HWLOC_RESTRICT_FLAG_BYNODESET para eliminar todos los nodos no predeterminados de la topología. La topología resultante será más fácil de usar al iterar sobre nodos NUMA (ahora homogéneos).

Las heurísticas para encontrar nodos predeterminados se basan en los niveles de memoria y los subtipos (ver Memoria Heterogénea) así como la suposición de que los proveedores de hardware listan los nodos predeterminados primero en las tablas de hardware.

flags debe ser 0 por ahora.

Devuelve

0 en caso de éxito.

-1 en caso de error.

Nota

El conjunto de nodos devuelto generalmente contiene todos los nodos de un solo nivel de memoria, probablemente el DRAM.

El conjunto de nodos devuelto está incluido en la lista de nodos disponibles devuelta por hwloc_topology_get_topology_nodeset(). Es estrictamente menor si la máquina tiene memoria heterogénea.

Las heurísticas pueden devolver un conjunto subóptimo de nodos si hwloc no pudo adivinar los tipos de memoria y/o si algunos nodos predeterminados se eliminaron previamente de la topología (por ejemplo, con hwloc_topology_restrict()).
