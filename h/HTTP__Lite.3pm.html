HTTP::Lite(3) Documentación de Perl aportada por el usuario HTTP::Lite(3)

NOMBRE

HTTP::Lite - Implementación ligera de HTTP

SINOPSIS

use HTTP::Lite;
$http = HTTP::Lite->new;
$req = $http->request("http://www.cpan.org/") 
    or die "No se pudo obtener el documento: $!";
print $http->body();

DESCRIPCIÓN

Nota: deberías mirar HTTP::Tiny o LWP antes de usar este módulo.

HTTP::Lite es una implementación independiente y ligera de HTTP/1.1 para Perl. No pretende ser un reemplazo del módulo LWP, que tiene todas las funcionalidades. En su lugar, está diseñado para situaciones en las que es deseable instalar el mínimo número de módulos para lograr soporte HTTP, o donde LWP no es una buena opción debido a la sobrecarga de CPU, como en procesadores más lentos. HTTP::Lite es también significativamente más rápido que LWP.

HTTP::Lite es ideal para programas CGI (o mod_perl) o para incluirlo en la redistribución con paquetes más grandes donde solo se necesitan las funcionalidades de HTTP GET y POST.

HTTP::Lite soporta operaciones básicas POST y GET solamente. A partir de la versión 0.2.1, HTTP::Lite soporta HTTP/1.1 y cumple con la cabecera Host, necesaria para el hosting virtual basado en nombre. Adicionalmente, HTTP::Lite ahora soporta Proxies.

A partir de la versión 2.0.0, HTTP::Lite soporta una función de retrollamada (callback) para permitir el procesamiento de datos de la solicitud a medida que llegan. Esto es útil para manejar archivos muy grandes sin consumir memoria.

Si requiere más funcionalidad, como FTP o HTTPS, por favor consulte libwwwperl (LWP). LWP es un paquete significativamente mejor y más completo que HTTP::Lite, y debería usarse en lugar de HTTP::Lite siempre que sea posible.

CONSTRUCTOR

new
Este es el constructor para HTTP::Lite. Actualmente no toma argumentos. Una versión futura de HTTP::Lite podría aceptar parámetros.

MÉTODOS

request ( $url, $data_callback, $cbargs )
Inicia una solicitud a la URL especificada.

Devuelve undef si se encuentra un error de E/S, de lo contrario, se devolverá el código de estado HTTP. Los códigos de estado de la serie 200 representan éxito, 300 errores temporales, 400 errores permanentes y 500 errores del servidor.

Consulte http://www.w3.org/Protocols/HTTP/HTRESP.html para obtener información detallada sobre los códigos de estado HTTP.

El parámetro $data_callback, si se usa, es una forma de filtrar los datos a medida que se reciben o de manejar transferencias grandes. Debe ser una referencia a una función, y se le pasará: una referencia a la instancia de la solicitud HTTP que realiza la retrollamada, una referencia al bloque actual de datos a punto de agregarse al cuerpo, y el parámetro $cbargs (que puede ser cualquier cosa). Debe devolver una referencia a los datos que se agregarán al cuerpo del documento, o undef.

Si se usa set_callback, $data_callback y $cbargs no se utilizan. $cbargs puede ser un escalar o una referencia.

La retrollamada de datos se llama así:
&$data_callback( $self, $dataref, $cbargs )

Un ejemplo de uso para guardar un documento en un archivo es:

# Escribe los datos en el manejador de archivo $cbargs
sub savetofile {
  my ($self,$phase,$dataref,$cbargs) = @_;
  print $cbargs $$dataref;
  return undef;
}
$url = "$testpath/bigbinary.dat";
open OUT, '>','bigbinary.dat';
$res = $http->request($url, \&savetofile, OUT);
close OUT;
set_callback ( $functionref, $dataref )
En varias etapas de la solicitud, se pueden usar retrollamadas para modificar el comportamiento o para monitorizar el estado de la solicitud. Estas funcionan como el parámetro $data_callback de request(), pero son más versátiles. Usar set_callback deshabilita $data_callback en request()

Las retrollamadas se llaman así:
callback ( $self, $phase, $dataref, $cbargs )

Las fases actuales son:

connect - se ha establecido la conexión y se están transmitiendo las cabeceras.
content-length - el valor de retorno se utiliza como content-length. Si es undef,
          y se usó prepare_post(), el content length se calcula.
done-headers - se han enviado todas las cabeceras
content - se devuelve el valor de retorno como contenido y se envía al cliente.  Devolver
          undef para usar el contenido interno definido por prepare_post().
content-done - el contenido se ha transmitido con éxito.
data - se ha recibido un bloque de datos.  Los datos están referenciados por
          $dataref.  El valor de retorno se desreferencia y reemplaza el
          contenido proporcionado.  Devolver undef para evitar usar memoria para
          documentos grandes.
done - La solicitud ha finalizado.
prepare_post ( $hashref )
Toma una referencia a un array asociativo de variables de formulario POST a cargar. Crea el cuerpo HTTP y establece el método a POST.
http11_mode ( 0 | 1 )
Activa o desactiva el soporte HTTP/1.1. Esto está desactivado por defecto debido a servidores HTTP/1.1 defectuosos. Use 1 para habilitar el soporte HTTP/1.1.
add_req_header ( $header, $value )
get_req_header ( $header )
delete_req_header ( $header )
Añade, elimina u obtiene una o varias cabeceras HTTP para la solicitud. Estas funciones le permiten anular cualquier cabecera. Actualmente, Host, User-Agent, Content-Type, Accept y Connection están predefinidas por el módulo HTTP::Lite. No puede anular Host, Connection o Accept.

Si llama a add_req_header() con $value establecido a "undef", entonces la cabecera no se añadirá.

Para proporcionar autenticación o autorización (proxy), usaría:

use HTTP::Lite;
use MIME::Base64;
$http = HTTP::Lite->new;
$encoded = encode_base64('username:password');
$http->add_req_header("Authorization", $encoded);

NOTA: La implementación actual le limita a una sola instancia de cada cabecera.

body
Devuelve el cuerpo del documento devuelto por el servidor remoto.
headers_array
Devuelve un array de las cabeceras HTTP devueltas por el servidor remoto.
headers_string
Devuelve una representación en cadena de las cabeceras HTTP devueltas por el servidor remoto.
get_header ( $header )
Devuelve un array de valores para la cabecera solicitada.

NOTA: Las solicitudes HTTP no se limitan a una sola instancia de cada cabecera. Como resultado, puede haber más de una entrada para cada cabecera.

protocol
Devuelve el identificador del protocolo HTTP, tal como lo informa el servidor remoto. Generalmente será HTTP/1.0 o HTTP/1.1.
proxy ( $proxy_server )
La URL o nombre de host del proxy a usar para la próxima solicitud.
status
Devuelve el código de estado HTTP devuelto por el servidor. Esto también se informa como el valor de retorno de request().
status_message
Devuelve la descripción textual del código de estado tal como la devuelve el servidor. La cadena de estado no tiene que adherirse a ningún formato particular, aunque la mayoría de los servidores HTTP utilizan un conjunto estándar de descripciones.
reset
Debe llamar a esto antes de reutilizar un manejador HTTP::Lite, de lo contrario, los resultados no están definidos.
lo

cal_addr ( $ip )

Selecciona explícitamente la dirección IP local. 0.0.0.0 (por defecto) deja que el sistema elija.
local_port ( $port )
Selecciona explícitamente el puerto local. 0 (por defecto y recomendado) deja que el sistema elija.
method ( $method )
Establece explícitamente el método. Usar prepare_post o reset anula esta configuración. Las opciones habituales son GET, POST, PUT, HEAD

EJEMPLOS

# Obtiene e imprime las cabeceras y el cuerpo de la página principal de CPAN
use HTTP::Lite;
$http = HTTP::Lite->new;
$req = $http->request("http://www.cpan.org/")
    or die "No se puede obtener el documento: $!";
die "La solicitud falló ($req): ".$http->status_message()
  if $req ne "200";
@headers = $http->headers_array();
$body = $http->body();
foreach $header (@headers)
{
  print "$header$CRLF";
}
print "$CRLF";
print "$body$CRLF";
# Envía una consulta a través de POST al motor de búsqueda USENET de dejanews
use HTTP::Lite;
$http = HTTP::Lite->new;
%vars = (
         "QRY" => "perl",
         "ST" => "MS",
         "svcclass" => "dncurrent",
         "DBS" => "2"
        );
$http->prepare_post(\%vars);
$req = $http->request("http://www.deja.com/dnquery.xp")
  or die "No se puede obtener el documento: $!";
print "req: $req\n";
print $http->body();

NO IMPLEMENTADO

- FTP
- HTTPS (SSL)
- Autenticación/Autorización/Autorización de proxy
  no están soportados directamente y requieren MIME::Base64.
- Las redirecciones (Location) no se siguen automáticamente
- Los POST multipart/form-data no están soportados directamente (necesarios
  para cargas de archivos).

ERRORES

Algunos servidores HTTP/1.1 defectuosos envían tamaños de fragmento incorrectos al transferir archivos. El modo HTTP/1.1 está ahora deshabilitado por defecto.

VER TAMBIÉN

Este módulo (HTTP::Lite) casi con seguridad no es el mejor módulo para tus necesidades.

Para la mayoría de los usos, HTTP::Tiny es una buena opción. Si necesitas más funciones, entonces mira LWP.
