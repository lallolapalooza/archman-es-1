HTTP::Daemon(3) Documentación aportada por el usuario HTTP::Daemon(3)

NOMBRE

HTTP::Daemon - Una clase de servidor http simple

VERSIÓN

versión 6.16

SINOPSIS

use HTTP::Daemon;
use HTTP::Status;
my $d = HTTP::Daemon->new || die;
print "Please contact me at: <URL:", $d->url, ">\n";
while (my $c = $d->accept) {
    while (my $r = $c->get_request) {
    if ($r->method eq 'GET' and $r->uri->path eq "/xyzzy") {
            # remember, this is *not* recommended practice :-)
        $c->send_file_response("/etc/passwd");
    }
    else {
        $c->send_error(RC_FORBIDDEN)
    }
    }
    $c->close;
    undef($c);
}

DESCRIPCIÓN

Las instancias de la "HTTP::Daemon" clase son servidores HTTP/1.1 que escuchan en un socket las peticiones entrantes. El "HTTP::Daemon" es una subclase de "IO::Socket::IP", por lo que también puedes realizar operaciones de socket directamente sobre él.

Ten en cuenta que "HTTP::Daemon" solía ser una subclase de "IO::Socket::INET". Para soportar IPv6, cambió la clase padre a "IO::Socket::IP" en la versión 6.05. Ver "SOPORTE IPv6" para más detalles.

El método accept() retornará cuando haya disponible una conexión de un cliente. El valor retornado será un objeto "HTTP::Daemon::ClientConn" que es otra subclase de "IO::Socket::IP" . Llamar al método get_request() en este objeto leerá datos del cliente y retornará un objeto "HTTP::Request" . El objeto ClientConn también provee métodos para enviar de vuelta varias respuestas.

Este demonio HTTP no hace fork(2) por ti. Tu aplicación, es decir, el usuario de "HTTP::Daemon" es responsable de hacer el fork si eso es deseable. Ten en cuenta también que el usuario es responsable de generar respuestas que se ajusten al protocolo HTTP/1.1.

Los siguientes métodos de "HTTP::Daemon" son nuevos (o mejorados) en relación con la clase base "IO::Socket::IP" :

$d = HTTP::Daemon->new
$d = HTTP::Daemon->new( %opts )
El método constructor toma los mismos argumentos que el "IO::Socket::IP" constructor, pero a diferencia de su clase base, también puede ser llamado sin ningún argumento. El demonio entonces configurará una cola de escucha de 5 conexiones y asignará un número de puerto aleatorio.

Un servidor que quiera enlazarse a una dirección específica en el puerto HTTP estándar será construido así:

$d = HTTP::Daemon->new(
         LocalAddr => 'www.thisplace.com',
         LocalPort => 80,
     );

Ver IO::Socket::IP para una descripción de otros argumentos que pueden usarse para configurar el demonio durante la construcción.

$c = $d->accept
$c = $d->accept( $pkg )
($c, $peer_addr) = $d->accept
Este método funciona igual que el provisto por la clase base, pero retorna por defecto una referencia a "HTTP::Daemon::ClientConn" . Si se provee un nombre de paquete como argumento, entonces el objeto retornado será bendecido (blessed) en la clase dada. Probablemente sea una buena idea hacer que esa clase sea una subclase de "HTTP::Daemon::ClientConn".

El método accept retornará "undef" si los tiempos de espera (timeouts) han sido habilitados y no se hace ninguna conexión dentro del tiempo dado. El método timeout() está descrito en IO::Socket::IP.

En contexto de lista tanto el objeto cliente como la dirección del par serán retornados; ver la descripción del método accept de IO::Socket para más detalles.

$d->url
Retorna una cadena URL que puede usarse para acceder a la raíz del servidor.
$d->product_tokens
Retorna el nombre que este servidor usará para identificarse. Esta es la cadena que se envía con la cabecera de respuesta "Server" . La razón principal para tener este método es que las subclases pueden sobreescribirlo si quieren usar otro nombre de producto.

El valor por defecto es la cadena "libwww-perl-daemon/#.##" donde "#.##" es reemplazado con el número de versión de este módulo.

El "HTTP::Daemon::ClientConn" es una subclase de "IO::Socket::IP". Las instancias de esta clase son retornadas por el método accept() de"HTTP::Daemon"

. Los siguientes métodos son provistos:
$c->get_request
$c->get_request( $headers_only ) Este método lee datos del cliente y los convierte en un objeto "HTTP::Request" el cual es retornado. Retorna "undef" si la lectura falla. Si falla, entonces el objeto "HTTP::Daemon::ClientConn" ($c) debería ser descartado, y no deberías intentar llamar a este método de nuevo en él. El método$c ->reason podría darte alguna información sobre por qué$c

->get_request falló. El método get_request() normalmente no retornará hasta que la petición completa haya sido recibida del cliente. Esto podría no ser lo que quieras si la petición es la subida de un archivo grande (y con transferencia chunked HTTP puede incluso soportar mensajes de petición infinitos - subiendo audio en vivo por ejemplo). Si pasas un valor VERDADERO (TRUE) como argumento $headers_only , entonces get_request() retornará inmediatamente después de analizar las cabeceras de la petición y serás responsable de leer el resto del contenido de la petición. Si vas a llamar a$c

->get_request de nuevo en la misma conexión es mejor que leas el número correcto de bytes.
$c->read_buffer
$c->read_buffer( $new_value ) Los bytes leídos por$c ->get_request, pero no usados, son colocados en el buffer de lectura. La próxima vez que $c->get_request sea llamado, consumirá los bytes en este buffer antes de leer más datos de la conexión de red misma. El buffer de lectura es inválido después de que $c->get_request haya fallado.

Si manejas la lectura del contenido de la petición tú mismo necesitas vaciar este buffer antes de leer más y necesitas colocar bytes no consumidos aquí. También necesitas este buffer si implementas servicios como 101 Switching Protocols.

Este método siempre retorna el contenido viejo del buffer y puede opcionalmente reemplazar el contenido del buffer si le pasas un argumento.

$c->reason
Cuando $c->get_request retorna "undef" puedes obtener una cadena corta describiendo por qué sucedió llamando a $c->reason.
$c->proto_ge( $proto )
Retorna VERDADERO (TRUE) si el cliente anunció un protocolo con número de versión mayor o igual al argumento dado. El argumento $proto puede ser una cadena como "HTTP/1.1" o simplemente "1.1".
$c->antique_client
Retorna VERDADERO (TRUE) si el cliente habla el protocolo HTTP/0.9. No se debe retornar código de estado ni cabeceras a un cliente así. Esto debería ser igual a !$c->proto_ge("HTTP/1.0").
$c->head_request
Retorna VERDADERO (TRUE) si la última petición fue una petición "HEAD" . No se debe generar cuerpo de contenido para estas peticiones.
$c->force_last_request
Asegura que $c->get_request no intente leer más peticiones de esta conexión. Si generas una respuesta que no es autodelimitada, entonces deberías señalar este hecho llamando a este método.

Este atributo se activa automáticamente si el cliente anuncia el protocolo HTTP/1.0 o inferior y no incluye una cabecera "Connection: Keep-Alive". También se activa automáticamente cuando los clientes HTTP/1.1 o superiores envían la cabecera de petición "Connection: close".

NAME

HTTP::Daemon - A simple HTTP server class

VERSION

6.16

SYNOPSIS

 use HTTP::Daemon;

 my $d = HTTP::Daemon->new(
     LocalAddr => 'localhost',
     LocalPort => 8080,
     ReuseAddr => 1,
 ) || die;

 print "Please go to http://", $d->host, ":", $d->port, "\n";

 my $c;
 while ($c = $d->accept) {
     print "Accepted connection from: ", $c->peer_addr, "\n";
     # Handle the request
     my $req = $c->get_request;
     if ($req) {
         print "Request: ", $req->method, " ", $req->url, "\n";
         # Send a response
         my $res = HTTP::Response->new(200);
         $res->header('Content-Type' => 'text/plain');
         $res->content("Hello, World!\n");
         $c->send_response($res);
     }
     $c->close;
 }

DESCRIPTION

The HTTP::Daemon class provides a simple interface for writing HTTP servers. It is a subclass of IO::Socket::IP.

$d->new( [\%attr] )
Creates a new HTTP::Daemon object. The following attributes can be passed in the optional hash reference:
    LocalAddr:   The local address to bind to. Defaults to any local address.
    LocalPort:   The local port to bind to. Defaults to 8080.
    ReuseAddr:   Set the SO_REUSEADDR socket option. Defaults to 0 (false).
    Timeout:     The timeout for accept() calls. Defaults to undef (no timeout).
    Host:        The name of the host for the 'Location' and 'Server' headers.
                 If not specified, the daemon will try to figure it out.
    ParsePost:   If set to true, then POST requests will be parsed and
                 the arguments will be made available through the
                 $request->content argument.
                 Defaults to false.
    HostLookup:  If set to false, then the daemon will not try to lookup
                 the host name of the client. Defaults to true.
    Listen:      The maximum number of pending connections allowed.
                 Defaults to 5.

The object returned is a generic socket object that accepts connections. The accept method returns a new socket object for each accepted connection. The methods described below are available for these connection objects.

$c->get_request( [\%attr] )
Read the next request from the client connection $c. Returns an HTTP::Request object or undef if an error occurred or the connection was closed.
$c->send_status_line()
$c->send_status_line( $code )
$c->send_status_line( $code, $mess )
$c->send_status_line( $code, $mess, $proto )
Send the status line back to the client. If $code is omitted 200 is assumed. If $mess is omitted, then a message corresponding to $code is inserted. If $proto is missing the content of the $HTTP::Daemon::PROTO variable is used.
$c->send_crlf
Send the CRLF sequence to the client.
$c->send_basic_header
$c->send_basic_header( $code )
$c->send_basic_header( $code, $mess )
$c->send_basic_header( $code, $mess, $proto )
Send the status line and the "Date:" and "Server:" headers back to the client. This header is assumed to be continued and does not end with an empty CRLF line.

See the description of send_status_line() for the description of the accepted arguments.

$c->send_header( $field, $value )
$c->send_header( $field1, $value1, $field2, $value2, ... )
Send one or more header lines.
$c->send_response( $res )
Write an "HTTP::Response" object to the client as a response. We try hard to make sure that the response is self-delimiting so that the connection can stay persistent for further request/response exchanges.

The content attribute of the "HTTP::Response" object can be a normal string or a subroutine reference. If it is a subroutine, then whatever this callback routine returns is written back to the client as the response content. The routine will be called until it returns an undefined or empty value. If the client is HTTP/1.1 aware then we will use chunked transfer encoding for the response.

$c->send_redirect( $loc )
$c->send_redirect( $loc, $code )
$c->send_redirect( $loc, $code, $entity_body )
Send a redirect response back to the client. The location ($loc) can be an absolute or relative URL. The $code must be one of the redirect status codes, and defaults to "301 Moved Permanently"
$c->send_error
$c->send_error( $code )
$c->send_error( $code, $error_message )
Send an error response back to the client. If the $code is missing a "Bad Request" error is reported. The $error_message is a string that is incorporated in the body of the HTML entity.
$c->send_file_response( $filename )
Send back a response with the specified $filename as content. If the file is a directory we try to generate an HTML index of it.
$c->send_file( $filename )
$c->send_file( $fd )
Copy the file to the client. The file can be a string (which will be interpreted as a filename) or a reference to an "IO::Handle" or glob.
$d->daemon
Return a reference to the corresponding "HTTP::Daemon" object.

IPv6 SUPPORT

Since version 6.05, "HTTP::Daemon" is a subclass of "IO::Socket::IP" rather than "IO::Socket::INET", so that it supports IPv6.

For some reasons, you may want to force "HTTP::Daemon" to listen on IPv4 addresses only. Then pass "Family" argument to "HTTP::Daemon->new":

use HTTP::Daemon;
use Socket 'AF_INET';
my $d = HTTP::Daemon->new(Family => AF_INET);
