DESCRIPCIÓ

N

Los objetos de la clase "HTML::Parser" reconocerán el marcado y lo separarán del texto plano (alias contenido de datos) en documentos HTML. A medida que se reconocen diferentes tipos de marcado y texto, se invocan los manejadores de eventos correspondientes

.

"HTML::Parser" no es un analizador SGML genérico. Hemos intentado hacerlo capaz de tratar el HTML que realmente "existe allá fuera", y normalmente analiza lo más cerca posible de la forma en que lo hacen los navegadores web populares en lugar de seguir estrictamente una de las muchas especificaciones HTML del W3C. Donde hay desacuerdo, a menudo existe una opción que puede habilitar para obtener el comportamiento

oficial.

El documento a analizar puede suministrarse en trozos arbitrarios. Esto hace posible el análisis en tiempo real a medida que se reciben documentos desde la

red.

Si el análisis dirigido por eventos no le parece adecuado para su aplicación, podría querer usar "HTML::PullParser". Esta es una subclase de "HTML::Parser" que permite u

na estructura de prog
rama más convencional.

Dado que XML distingue mayúsculas de minúsculas, el caso del tagname no se cambia cuando "xml_mode" está habilitado. Lo mismo ocurre si el atributo "case_sensitive" está

establecido.

El tipo de declaración de los elementos de declaración también se pasa como tagname, aunque eso es un poco extraño. De hecho, en la implementación actual, tagname es idéntico a "token0" excepto que el nombre

BUGS

Las secciones <style> y <script> no terminan con el primer "</", sino que necesitan la etiqueta de cierre completa correspondiente. El comportamiento estándar no es realmente práctico.

Cuando la opción strict_comment está habilitada, todavía reconocemos comentarios donde hay algo más que espacios en blanco entre los marcadores de comillas dobles pares e impares.

Una vez que se ha establecido $p->boolean_attribute_value, no hay forma de restaurar el comportamiento predeterminado.

Actualmente no hay forma de obtener ambos caracteres de comillas en el mismo argspec literal.

Las etiquetas vacías, por ejemplo "<>" y "</>", no se reconocen. SGML les permite repetir la etiqueta de inicio anterior o cerrar la etiqueta de inicio anterior respectivamente.

Las etiquetas NET, por ejemplo "code/.../", no se reconocen. Esto es una taquigrafía de SGML para "<code>...</code>".

Las etiquetas de inicio o fin incompletas, por ejemplo "<tt<b>...</b</tt>", no se reconocen.

DIAGNÓSTICOS

Los siguientes mensajes pueden ser producidos por HTML::Parser. La notación en esta lista es la misma que se usa en perldiag:

No es una referencia a un hash
(F) El objeto bendecido o subclase de HTML::Parser no es un hash como lo requieren los métodos de HTML::Parser.
Firma incorrecta en el objeto de estado del analizador en %p
(F) El elemento _hparser_xs_state no se refiere a una estructura de estado válida. Algo debe haber cambiado el valor interno almacenado en este elemento hash, o la memoria ha sido sobrescrita.
El elemento _hparser_xs_state no es una referencia
(F) El elemento _hparser_xs_state ha sido destruido.
No se puede encontrar el elemento '_hparser_xs_state' en el hash de HTML::Parser
(F) El elemento _hparser_xs_state falta en el hash del analizador. Fue eliminado o no se creó cuando se creó el objeto.
La versión de API %s no es compatible con HTML::Parser %s
(F) La opción del constructor 'api_version' con un argumento mayor o igual a 4 está reservada para extensiones futuras.
Opción de constructor incorrecta '%s'
(F) Se pasó una clave de opción de constructor desconocida a los métodos new() o init().
No se permite el bucle de análisis
(F) Un manejador invocó el método parse() o parse_file(). Esto no está permitido.
Las secciones marcadas no son compatibles
(F) Se invocó el método $p->marked_sections() en un módulo HTML::Parser que fue compilado sin soporte para secciones marcadas.
Atributo booleano desconocido (%d)
(F) Algo está mal con la lógica interna que configuró alias para atributos booleanos.
Solo se permiten referencias de código o de array como manejador
(F) El segundo argumento para $p->handler debe ser una referencia a una subrutina, luego el nombre de una subrutina o método, o una referencia a un array.
Sin manejador para eventos %s
(F) El primer argumento para $p->handler debe ser un nombre de evento válido; es decir, uno de "start", "end", "text", "process", "declaration" o "comment".
Identificador no reconocido %s en argspec
(F) El identificador no es un nombre de argspec conocido. Utilice uno de los nombres mencionados en la sección de argspec anterior.
Cadena literal más larga que 255 caracteres en argspec
(F) La implementación actual limita la longitud de los literales en un argspec a 255 caracteres. Haga el literal más corto.
Barra invertida reservada para cadena literal en argspec
(F) El carácter de barra invertida \" no está permitido en literales de argspec. Está reservado para permitir el escape dentro de un literal en una versión posterior.
Cadena literal no terminada en argspec
(F) No se encontró el carácter de comillas de terminación para un literal.
Argspec incorrecto (%s)
(F) Solo se permiten nombres de identificadores, literales, espacios y comas en los argspecs.
Falta separador de coma en argspec
(F) Los identificadores en un argspec deben separarse con ",".
El análisis de UTF-8 no decodificado dará como resultado basura al decodificar entidades
(W) El primer fragmento analizado parece contener UTF-8 no decodificado y uno o más argspecs que decodifican entidades se utilizan para los manejadores de devolución de llamada.

El resultado de la decodificación será una mezcla de caracteres codificados y decodificados para cualquier entidad que se expanda a caracteres con códigos superiores a 127. Esto no es bueno.

La solución recomendada es aplicar Encode::decode_utf8() a los datos antes de alimentarlos a $p->parse(). Para $p->parse_file() pase un archivo que se haya abierto en modo ":utf8".

La solución alternativa es habilitar el modo "utf8_mode" y no decodificar antes de pasar cadenas a $p->parse(). El analizador puede procesar UTF-8 sin decodificar en bruto de manera sensata si el "utf8_mode" está habilitado, o si se evitan los argspecs "attr", @attr o "dtext".

Análisis de cadena decodificada con selección de endian incorrecta
(W) El primer carácter del documento es U+FFFE. Este no es un carácter Unicode legal, sino un "BOM" con bytes intercambiados. El resultado del análisis probablemente será basura.
Análisis de UTF-32 no decodificado
(W) El analizador encontró la firma "BOM" de Unicode UTF-32 al principio del documento. El resultado del análisis probablemente será basura.
Análisis de UTF-16 no decodificado
(W) El analizador encontró la firma "BOM" de Unicode UTF-16 al principio del documento. El resultado del análisis probablemente será basura.
