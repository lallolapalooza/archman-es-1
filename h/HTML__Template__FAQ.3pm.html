HTML::Template::FAQ - Preguntas frecuentes sobre HTML::Template

SINOPSIS

En interés de una mayor comprensión, he comenzado una sección de preguntas frecuentes en la documentación de perl. Por favor, mírela antes de enviarme un correo electrónico.

PREGUNTAS FRECUENTES

¿Hay algún lugar para discutir HTML::Template y/o conseguir ayuda?

Hay una lista de correo para discutir HTML::Template en html-template-users@lists.sourceforge.net. Únete en:

http://lists.sourceforge.net/lists/listinfo/html-template-users

Si solo quieres recibir un correo electrónico cuando haya nuevas versiones disponibles, puedes unirte a la lista de anuncios aquí:

http://lists.sourceforge.net/lists/listinfo/html-template-announce

¿Hay un archivo buscable para la lista de correo?

Sí, puedes encontrar un archivo de la lista de SourceForge aquí:

http://dir.gmane.org/gmane.comp.lang.perl.modules.html-template

¡Quiero soporte para <TMPL_XXX>! ¿Qué me dices?

Quizás. Definitivamente animo a la gente a discutir sus ideas para HTML::Template en la lista de correo. Por favor, prepárate para explicarme cómo la nueva etiqueta encaja con la misión de HTML::Template de proporcionar un sistema rápido y ligero para usar plantillas HTML.

NOTA: Ofrecerse a programar dicha adición y proporcionarla en forma de parche a la versión más reciente de HTML::Template tendrá definitivamente un efecto suavizador en los posibles oponentes.

Encontré un error, ¿puedes arreglarlo?

Eso depende. ¿Me enviaste la VERSIÓN de HTML::Template, un script de prueba y una plantilla de prueba? Si es así, entonces casi con certeza.

Si te sientes realmente aventurero, HTML::Template está disponible públicamente en GitHub (https://github.com/mpeters/html-template). Por favor, siéntete libre de hacer un fork y enviarme una solicitud de incorporación (pull request) con cualquier cambio que tengas.

¡Las <TMPL_VAR> de la plantilla principal no funcionan dentro de un <TMPL_LOOP>! ¿Por qué?

Este es el comportamiento esperado. "<TMPL_LOOP>" introduce un ámbito separado para las "<TMPL_VAR>" al igual que una llamada a subrutina en Perl introduce un ámbito separado para las variables "my" .

Si quieres que tus "<TMPL_VAR>"sean globales, puedes establecer la opción "global_vars" cuando llames a new(). Mira arriba para la documentación de la opción "global_vars" de new() .

¿Cómo puedo precargar mis plantillas usando cache-mode y mod_perl?

Añade algo como esto a tu startup.pl:

use HTML::Template;
use File::Find;
print STDERR "Pre-loading HTML Templates...\n";
find(
    sub {
        return unless /\.tmpl$/;
        HTML::Template->new(
            filename => "$File::Find::dir/$_",
            cache    => 1,
        );
    },
    '/path/to/templates',
    '/another/path/to/templates/'
);

Ten en cuenta que necesitarás modificar la línea "return unless" para especificar la extensión que usas para tus archivos de plantilla - yo uso .tmpl, como puedes ver. También necesitarás especificar la ruta a tus archivos de plantilla.

Un problema potencial: la /path/to/templates/ debe ser EXACTAMENTE la misma ruta que usas cuando llamas a "HTML::Template->new()". De lo contrario, la caché no sabrá que son el mismo archivo y cargará una nueva copia - en lugar de obtener una mejora de velocidad, duplicarás tu uso de memoria. Para averiguar si esto está sucediendo, establece "cache_debug =" 1> en el código de tu aplicación y busca mensajes "CACHE MISS" en los registros.

¿Qué caracteres están permitidos en los nombres TMPL_*?

Números, letras, '.', '/', '+', '-' y '_'.

¿Cómo puedo ejecutar un programa desde dentro de mi plantilla?

Respuesta corta: no puedes. Respuesta larga: no deberías, ya que esto viola el concepto fundamental detrás de HTML::Template - que el diseño y el código deben estar separados.

Pero, inevitablemente, algunas personas aún quieren hacerlo. Si esa descripción te corresponde, deberías echar un vistazo a HTML::Template::Expr. Usando HTML::Template::Expr debería ser fácil escribir una función run_program() . Luego puedes hacer cosas terribles como:

<tmpl_var expr="run_program('foo.pl')">

Solo, por favor, no me lo cuentes. Me siento lo suficientemente culpable solo por haber escrito HTML::Template::Expr en primer lugar.

¿Cuál es la mejor manera de crear un elemento de formulario <select> usando HTML::Template?

Hay mucho desacuerdo sobre este tema. Mi preferencia personal es usar las excelentes funciones popup_menu() y scrolling_list() de CGI.pm para rellenar una única variable "<tmpl_var select_foo>" .

Para algunas personas esto huele a mezclar HTML y código de una manera que esperaban que HTML::Template les ayudara a evitar. A ellos les diría que HTML es una violación del principio de separar el diseño de la programación. No hay una separación clara entre los elementos programáticos de las etiquetas "<form>" y el diseño de las etiquetas "<form>" . Tendrás que trazar la línea en algún lugar - claramente el diseñador no puede estar completamente a cargo de la creación de formularios.

Es un acto de equilibrio y tienes que sopesar los pros y los contras de cada lado. Ciertamente es posible producir un elemento "<select>" completamente dentro de la plantilla. Lo que terminas teniendo es un nido de ratas de bucles y condicionales. Alternativamente, puedes renunciar a cierta cantidad de flexibilidad a cambio de simplificar enormemente tus plantillas. Generalmente elijo esta última opción.

Otra opción es investigar HTML::FillInForm, que algunos han reportado éxito usando para resolver este problema.
