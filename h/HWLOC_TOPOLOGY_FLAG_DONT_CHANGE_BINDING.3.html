Descripción detallada

Varias funciones pueden llamarse opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo debe realizarse la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación del tipo enumeración

enum hwloc_topology_flags_e

Banderas que deben establecerse en un contexto de topología antes de la carga. Las banderas deben pasarse a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detectar todo el sistema, ignorar las reservas, incluir objetos no permitidos. Recopilar todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignorar Cgroup/Cpusets de Linux y recopilar todos los procesadores y nodos de memoria. Sin embargo, las UPs (unidades de procesamiento) y los nodos NUMA fuera de línea siguen siendo ignorados.

Cuando esta bandera no está establecida, las UPs y los nodos NUMA que no están permitidos no se añaden a la topología. Los objetos padre (paquete, núcleo, caché, etc.) se añaden solo si algunos de sus hijos están permitidos. Todas las UPs y los nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al cpuset y nodeset del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de UPs y nodos NUMA permitidos son dados por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el cpuset y nodeset del objeto raíz.

Si la topología actual se exporta a XML y se vuelve a importar más tarde, esta bandera debe establecerse de nuevo en la topología reimportada para que los recursos no permitidos también sean reimportados.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asumir que el backend seleccionado proporciona la topología del sistema en el que nos encontramos. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología del sistema en el que nos encontramos, incluso si no es el backend específico del OS sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace (binding) llamen realmente a las llamadas al sistema específicas del OS y realicen el enlace, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que solo devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto puede usarse por razones de eficiencia para detectar la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero teniendo aún así las funciones de enlace realmente realizando el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtener el conjunto de recursos permitidos del sistema operativo local incluso si la topología fue cargada desde XML o una descripción sintética. Si la topología fue cargada desde XML o desde una cadena sintética, restringirla aplicando las restricciones del proceso actual como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente de donde se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importar soporte de la topología importada. Al importar una topología XML de una máquina remota, el enlace está deshabilitado por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Este deshabilitado también se marca poniendo ceros en los bits de características soportadas correspondientes reportados por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT realmente importa los bits de soporte de la máquina remota. También establece la bandera imported_support en el array de la struct hwloc_topology_misc_support . Si el XML importado no contenía información de soporte (el hwloc exportador es demasiado antiguo), esta bandera no se establece.

Nótese que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar con el sistema operativo, o con cómo se compiló hwloc).

Nótese que establecer esta bandera sin embargo no habilita el enlace para la topología de hwloc importada localmente, solo reporta lo que el hwloc remoto y la máquina soportan.

Detailed Description

int hwloc_topology_set_all_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all object types. If some types do not support this filtering, they are silently ignored.

Returns

0 on success, -1 on error.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all CPU cache object types. Memory-side caches are not involved since they are not CPU caches.

Returns

0 on success, -1 on error.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Set OR'ed flags to non-yet-loaded topology. Set a OR'ed set of hwloc_topology_flags_e onto a topology that was not yet loaded.

If this function is called multiple times, the last invocation will erase and replace the set of flags that was previously set.

By default, no flags are set (0).

The flags set in a topology may be retrieved with hwloc_topology_get_flags().

Returns

0 on success.

-1 on error, for instance if flags are invalid.

int hwloc_topology_set_icache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all CPU instruction cache object types. Memory-side caches are not involved since they are not CPU caches.

Returns

0 on success, -1 on error.

int hwloc_topology_set_io_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all I/O object types.

Returns

0 on success, -1 on error.

int hwloc_topology_set_type_filter (hwloc_topology_t topology, hwloc_obj_type_t type, enum hwloc_type_filter_e filter)

Set the filtering for the given object type.

Returns

0 on success, -1 on error.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Set the topology-specific userdata pointer. Each topology may store one application-given private data pointer. It is initialized to NULL. hwloc will never modify it.

Use it as you wish, after hwloc_topology_init() and until hwloc_topolog_destroy().

This pointer is not exported to XML.
