HTTP::Server::Simple(3) Documentación de Perl aportada por el usuario HTTP::Server::Simple(3)

NOMBRE

HTTP::Server::Simple - Servidor HTTP ligero

SINOPSIS

use warnings;
use strict;

use HTTP::Server::Simple;

my $server = HTTP::Server::Simple->new();
$server->run();

Sin embargo, normalmente subclasificarás el módulo HTTP::Server::Simple::CGI (ver HTTP::Server::Simple::CGI);

package Your::Web::Server;
use base qw(HTTP::Server::Simple::CGI);

sub handle_request {
    my ($self, $cgi) = @_;
    #... hacer algo, imprimir la salida en el manejador de
    # archivos seleccionado por defecto...
}

1;

DESCRIPCIÓN

Este es un servidor HTTP independiente y sencillo. Por defecto, no usa hilos ni hace fork. Sin embargo, actúa como un frontend sencillo que puede usarse para construir una aplicación web independiente o para convertir un CGI en una.

Es posible usar las clases de Net::Server para crear servidores con fork, con pre-fork y otros tipos de servidores más complicados; ver "net_server".

Por defecto, el servidor captura algunas señales:

HUP
Cuando "kill -HUP" al servidor, este deja que la solicitud actual termine de procesarse y luego usa el método "restart" para re-ejecutarse a sí mismo. Tenga en cuenta que para proporcionar el reinicio con SIGHUP, HTTP::Server::Simple establece un manejador de SIGHUP durante la inicialización. Si su código de manejo de solicitudes hace fork, debe asegurarse de restablecerlo o sucederán cosas inesperadas si alguien envía un HUP a todos los procesos en ejecución generados por su aplicación (por ejemplo, con "kill -HUP <script>")
PIPE
Si el servidor detecta una tubería rota al escribir la salida al cliente, ignora la señal. De lo contrario, un cliente que cierre la conexión antes de tiempo podría matar al servidor.

EJEMPLO

#!/usr/bin/perl
{
package MyWebServer;

use HTTP::Server::Simple::CGI;
use base qw(HTTP::Server::Simple::CGI);

my %dispatch = (
    '/hello' => \&resp_hello,
    # ...
);

sub handle_request {
    my $self = shift;
    my $cgi  = shift;

    my $path = $cgi->path_info();
    my $handler = $dispatch{$path};

    if (ref($handler) eq "CODE") {
        print "HTTP/1.0 200 OK\r\n";
        $handler->($cgi);

    } else {
        print "HTTP/1.0 404 Not found\r\n";
        print $cgi->header,
              $cgi->start_html('Not found'),
              $cgi->h1('Not found'),
              $cgi->end_html;
    }
}

sub resp_hello {
    my $cgi  = shift;   # objeto CGI.pm
    return if !ref $cgi;

    my $who = $cgi->param('name');

    print $cgi->header,
          $cgi->start_html("Hello"),
          $cgi->h1("Hello $who!"),
          $cgi->end_html;
}

} 

# iniciar el servidor en el puerto 8080
my $pid = MyWebServer->new(8080)->background();
print "Use 'kill $pid' to stop server.\n";

MÉTODOS

HTTP::Server::Simple->new($port, $family)

Llamada a la API para iniciar un nuevo servidor. No comienza a escuchar realmente hasta que llames a "->run()". Si se omite, $port tiene el valor por defecto 8080, y $family tiene el valor por defecto Socket::AF_INET. El dominio alternativo es Socket::AF_INET6.

lookup_localhost

Busca la dirección IP del host local y la devuelve. Para la mayoría de los hosts, esta es 127.0.0.1, o posiblemente "::1".

port [NÚMERO]

Acepta un número de puerto opcional en el que este servidor debe escuchar.

Devuelve el puerto de este servidor. (Por defecto 8080)

family [NÚMERO]

Acepta una familia de direcciones opcional para que este servidor use. Los valores válidos son Socket::AF_INET y Socket::AF_INET6. Todos los demás valores se cambian silenciosamente a Socket::AF_INET para compatibilidad con versiones anteriores del módulo.

Devuelve la familia de direcciones del socket de escucha actual. (Por defecto Socket::AF_INET.)

host [dirección]

Acepta una dirección de host opcional a la que este servidor debe vincularse.

Devuelve la dirección vinculada de este servidor (si la hay). Por defecto es "undef" (vincular a todas las interfaces).

background [ARGUMENTOS]

Ejecuta el servidor en segundo plano y devuelve el ID del proceso del proceso iniciado. Cualquier argumento se pasará a "run".

run [ARGUMENTOS]

Ejecuta el servidor. Si todo va bien, esto nunca volverá, pero comenzará a escuchar peticiones "HTTP" . Cualquier argumento pasado aquí se pasará a la implementación subyacente de Net::Server, si se usa una (ver "net_server").

net_server

Método anulable por el usuario. Si lo estableces en una subclase de Net::Server, esa subclase se usa para el método "run" . De lo contrario, se usa una implementación mínima por defecto.

restart

Reinicia el servidor. Normalmente lo llama una señal HUP, no directamente.

stdio_handle [MANEJADOR DE ARCHIVOS]

Cuando se llama con un argumento, establece el socket del servidor en ese argumento.

Devuelve el socket del servidor; solo debe usar esto para llamadas relacionadas con el socket como "getsockname". Si todo lo que quiere es leer o escribir en el socket, debe usar "stdin_handle" y "stdout_handle" para obtener explícitamente los manejadores de archivos de entrada y salida.

stdin_handle

Devuelve un manejador de archivos usado para la entrada desde el cliente. Por defecto, devuelve lo que se estableció con "stdio_handle", pero una subclase podría hacer algo interesante aquí.

stdout_handle

Devuelve un manejador de archivos usado para la salida al cliente. Por defecto, devuelve lo que se estableció con "stdio_handle", pero una subclase podría hacer algo interesante aquí.
