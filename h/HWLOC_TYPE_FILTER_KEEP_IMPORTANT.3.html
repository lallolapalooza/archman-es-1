Descripción detallada

Varias funciones pueden ser llamadas opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo debe realizarse la detección, por ejemplo, para ignorar ciertos tipos de objetos, definir una topología sintética, etc.

Documentación de tipos de enumeración

enum hwloc_topology_flags_e

Banderas que deben establecerse en un contexto de topología antes de cargar. Las banderas deben pasarse a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detecta todo el sistema, ignora las reservas, incluye objetos no permitidos. Reúne todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignora Cgroup/Cpusets de Linux y reúne todos los procesadores y nodos de memoria. Sin embargo, las PU y los nodos NUMA fuera de línea todavía se ignoran.

Cuando esta bandera no está establecida, las PU y los nodos NUMA que no están permitidos no se agregan a la topología. Los objetos padres (paquete, núcleo, caché, etc.) se agregan solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y conjunto de nodos del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de PU y nodos NUMA permitidos se proporcionan mediante hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, esta bandera debe establecerse nuevamente en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Supone que el backend seleccionado proporciona la topología del sistema en el que se está ejecutando. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología del sistema en el que se está ejecutando, incluso si no es el backend específico del sistema operativo, sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace llamen realmente a las llamadas del sistema específicas del sistema operativo y realicen realmente el enlace, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que simplemente devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto puede usarse por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún así teniendo funciones de enlace que realmente realizan el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtiene el conjunto de recursos permitidos del sistema operativo local incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringe aplicando las restricciones del proceso actual, como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente de la que se obtienen las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES produciría el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importa el soporte de la topología importada. Al importar una topología XML de una máquina remota, el enlace está deshabilitado por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits de soporte correspondientes informados por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT en realidad importa los bits de soporte de la máquina remota. También establece la bandera imported_support en la matriz de struct hwloc_topology_misc_support. Si el XML importado no contenía información de soporte (el exportador de hwloc es demasiado antiguo), esta bandera no se establece.

Tenga en cuenta que estas características admitidas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar según el sistema operativo o según cómo se compiló hwloc).

Tenga en cuenta que el establecimiento de esta bandera, sin embargo, no habilita el enlace para la topología hwloc importada localmente; solo informa lo que el hwloc y la máquina remotos admiten.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considere recursos fuera del enlace de CPU del proceso. Si el enlace del proceso se limita a un subconjunto de núcleos, ignore los otros núcleos durante

la detección de topología.

Esto puede ser útil si la aplicación se ejecuta dentro de un entorno restringido (como un cgroup) y no necesita ver o usar los recursos fuera de esa restricción.

Al establecer la variable de entorno HWLOC_RESTRICT_TO_CPUBINDING, se obtiene el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considere recursos fuera del enlace de memoria del proceso. Si el enlace de memoria del proceso se limita a un subconjunto de nodos NUMA, ignore los otros nodos NUMA durante la detección de topología.

Esto puede ser útil si la aplicación se ejecuta dentro de un entorno restringido (como un cgroup) y no necesita ver o usar los recursos fuera de esa restricción.

Al establecer la variable de entorno HWLOC_RESTRICT_TO_MEMBINDING, se obtiene el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
No cambiar el enlace de CPU o memoria del proceso actual durante la detección. Por defecto, hwloc puede cambiar el enlace del proceso durante la detección para obtener información precisa sobre la topología (por ejemplo, para explorar cachés). Establecer esta bandera evita que hwloc cambie el enlace.

Establecer la variable de entorno HWLOC_DONT_CHANGE_BINDING también tendrá el mismo efecto.

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
No busque ni exponga distancias entre objetos de memoria. Por defecto, hwloc busca y expone las latencias de acceso a la memoria entre los objetos de procesamiento y los objetos de memoria.

Al establecer la variable de entorno HWLOC_NO_DISTANCES, se obtiene el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
No busque ni exponga atributos de memoria como la cantidad de memoria, la ubicación, etc. Por defecto, hwloc busca y expone atributos de memoria. Esto es principalmente útil para topologías sintéticas.

Al establecer la variable de entorno HWLOC_NO_MEMATTRS, se obtiene el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
No busque ni exponga grupos de CPU (es decir, la agrupación de PUs dentro de paquetes, núcleos o cachés). Por defecto, hwloc agrupa las PUs.

Al establecer la variable de entorno HWLOC_NO_CPUKINDS, se obtiene el mismo comportamiento.

enum hwloc_type_filter_e

Los filtros de tipo de objeto se utilizan para controlar qué tipos de objetos se conservan en el árbol de topología. Se aplican a los tipos de objetos individuales, a todos los tipos de caché, a todos los tipos de caché de instrucción o a todos los tipos de E/S.

Los filtros de tipo de objeto se pueden aplicar a un tipo específico utilizando hwloc_topology_set_type_filter(). Los filtros se devuelven mediante hwloc_topology_get_type_filter().

HWLOC_TYPE_FILTER_KEEP_ALL
Todos los objetos del tipo dado se conservarán en el árbol de topología. Este es el valor predeterminado.

HWLOC_TYPE_FILTER_KEEP_NONE
Todos los objetos del tipo dado se ignorarán y no se añadirán al árbol de topología.

HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Se conservarán los objetos del tipo dado que sean necesarios para describir la estructura del sistema. Por ejemplo, si se filtran los núcleos, los paquetes que los contienen aún se conservarán si contienen algún otro objeto que no esté filtrado (como cachés o PU).

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Se conservarán los objetos del tipo dado que se consideren importantes. Por ejemplo, se conservarán las PU y los nodos NUMA, pero no las cachés intermedias (L1/L2) si sus objetos padre (núcleos/paquetes) ya proporcionan suficiente información sobre la estructura del sistema. La importancia se determina internamente por hwloc y se basa en el nivel y el tipo de objeto.

Las funciones hwloc_topology_set_all_types_filter(), hwloc_topology_set_cache_types_filter(), hwloc_topology_set_icache_types_filter() y hwloc_topology_set_io_types_filter() permiten aplicar un filtro a todos los tipos de objetos de un dominio específico (todos, cachés, cachés de instrucción o E/S).

El uso de estos filtros puede reducir la cantidad de información de topología devuelta y, por lo tanto, mejorar el rendimiento de las aplicaciones que no necesitan detalles completos de la topología.

La topología resultante es idéntica a la que generaría una llamada a hwloc_topology_restrict() , pero este indicador también evita que hwloc toque otros recursos durante el descubrimiento.

Este indicador le indica específicamente al backend x86 que nunca reenlace temporalmente un hilo en ningún núcleo excluido. Esto es útil en Windows porque dicho reenlace temporal puede cambiar el enlace del proceso. Otro caso de uso es evitar núcleos que no podrían realizar el descubrimiento de hwloc en un futuro cercano porque están ocupados ejecutando algunas tareas de tiempo real de alta prioridad.

Si el enlace de CPU del proceso no está soportado, se considera en su lugar el enlace de CPU del hilo si está soportado, o el indicador se ignora.

Este indicador requiere HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también, ya que se requiere soporte de enlace.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considerar recursos fuera del enlace de memoria del proceso. Si el enlace del proceso está limitado a un subconjunto de nodos NUMA, ignorar los otros nodos NUMA durante el descubrimiento.

La topología resultante es idéntica a la que generaría una llamada a hwloc_topology_restrict() , pero este indicador también evita que hwloc toque otros recursos durante el descubrimiento.

Este indicador está destinado a usarse junto con HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING cuando tanto los núcleos como los nodos NUMA deberían ignorarse fuera del enlace del proceso.

Si el enlace de memoria del proceso no está soportado, se considera en su lugar el enlace de memoria del hilo si está soportado, o el indicador se ignora.

Este indicador requiere HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también, ya que se requiere soporte de enlace.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Nunca modificar el enlace del proceso o del hilo durante el descubrimiento. Este indicador deshabilita todos los pasos de descubrimiento de hwloc que requieren un cambio en el enlace del proceso o del hilo. Actualmente esto solo afecta al backend x86, que queda completamente deshabilitado.

Esto es útil cuando hwloc_topology_load() se llama mientras la aplicación también crea hilos adicionales o modifica el enlace.

Este indicador también es una forma estricta de asegurar que el enlace del proceso no cambiará debido a cambios en el enlace de hilos en Windows (ver HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignorar distancias. Ignorar la información de distancias de los sistemas operativos (y de XML) y por lo tanto no usar distancias para el agrupamiento.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignorar atributos y niveles de memoria. Ignorar los atributos de memoria de los sistemas operativos (y de XML). Por lo tanto, tampoco intentar construir niveles de memoria.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignorar tipos de CPU. Ignorar la información de tipos de CPU de los sistemas operativos (y de XML).

enum hwloc_type_filter_e

Indicadores de filtrado de tipos. De forma predeterminada, la mayoría de los objetos se conservan (HWLOC_TYPE_FILTER_KEEP_ALL). Las cachés de instrucciones, las cachés del lado de la memoria, y los objetos de E/S y Misc se ignoran de forma predeterminada (HWLOC_TYPE_FILTER_KEEP_NONE). Los niveles de grupo se ignoran a menos que aporten estructura (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Tenga en cuenta que los objetos de grupo también se ignoran individualmente (sin ignorar el nivel completo) cuando no aportan estructura.

Enumerador

HWLOC_TYPE_FILTER_KEEP_ALL
Conservar todos los objetos de este tipo. No se puede establecer para HWLOC_OBJ_GROUP (los grupos están diseñados solo para añadir más estructura a la topología).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignorar todos los objetos de este tipo. El tipo de nivel inferior HWLOC_OBJ_PU, el tipo HWLOC_OBJ_NUMANODE , y el tipo de nivel superior HWLOC_OBJ_MACHINE no pueden ignorarse.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Solo ignorar objetos si su nivel completo no aporta ninguna estructura. Conservar el nivel completo de objetos si al menos uno de estos objetos añade estructura a la topología. Un objeto aporta estructura cuando tiene múltiples hijos y no es el único hijo de su padre.

Si todos los objetos en el nivel son el único hijo de su padre, y si ninguno de ellos tiene múltiples hijos, el nivel completo se elimina.

No se puede establecer para objetos de E/S y Misc ya que la estructura de la topología no importa allí.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Solo conservar objetos probablemente importantes del tipo dado. Solo es útil para tipos de objetos de E/S. Para HWLOC_OBJ_PCI_DEVICE y HWLOC_OBJ_OS_DEVICE, significa que solo se conservan objetos de tipos principales/comunes (almacenamiento, red, OpenFabrics, CUDA, OpenCL, RSMI, NVML y pantallas). Además, solo se reportan dispositivos del SO directamente conectados a PCI (p. ej., no USB). Para HWLOC_OBJ_BRIDGE, significa que los puentes se conservan solo si tienen hijos.

Este indicador es equivalente a HWLOC_TYPE_FILTER_KEEP_ALL para tipos Normal, Memoria y Misc, ya que probablemente son importantes.

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Recuperar el soporte de la topología. Cada indicador indica si una característica está soportada. Si está establecido a 0, la característica no está soportada. Si está establecido a 1, la característica está soportada, pero la llamada correspondiente aún puede fallar en algunos casos extremos.

Estas características también son listadas por hwloc-info --support

Las características reportadas son las que la topología actual soporta en la máquina actual. Si la topología fue exportada a XML desde otra máquina e importada aquí posteriormente, el soporte aún describe lo que está soportado para esta topología importada después de la importación. De forma predeterminada, el enlace será reportado como no soportado en este caso (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

El indicador de topología HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT puede usarse para reportar las características soportadas de la máquina remota original en su lugar. Si se importó exitosamente, imported_support será establecido en el array hwloc_topology_misc_support de la estructura.

Devuelve

Un puntero a una estructura de soporte.

Nota

La función no puede devolver NULL.

El puntero devuelto no debe ser liberado, pertenece a la biblioteca hwloc.

Esta función puede llamarse antes o después de hwloc_topology_load() pero la estructura de soporte solo contiene información válida después.
