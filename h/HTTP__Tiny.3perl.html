HTTP::Tiny(3perl) Guía del programador de Perl HTTP::Tiny(3perl)

NOMBRE

HTTP::Tiny - Un cliente HTTP/1.1 pequeño, simple y correcto

VERSIÓN

version 0.090

SINOPSIS

use HTTP::Tiny;
my $response = HTTP::Tiny->new->get('http://example.com/');
die "¡Falló!\n" unless $response->{success};
print "$response->{status} $response->{reason}\n";
while (my ($k, $v) = each %{$response->{headers}}) {
    for (ref $v eq 'ARRAY' ? @$v : $v) {
        print "$k: $_\n";
    }
}
print $response->{content} if length $response->{content};

DESCRIPCIÓN

Este es un cliente HTTP/1.1 muy simple, diseñado para realizar peticiones sencillas sin la sobrecarga de un framework grande como LWP::UserAgent.

Es más correcto y completo que HTTP::Lite. Soporta proxies y redirecciones. También se reanuda correctamente después de EINTR.

Si IO::Socket::IP 0.25 o posterior está instalado, HTTP::Tiny lo usará en lugar de IO::Socket::INET para un soporte transparente tanto para IPv4 como para IPv6.

El soporte de cookies requiere HTTP::CookieJar o una clase equivalente.

MÉTODOS

new

$http = HTTP::Tiny->new( %atributos );

Este constructor devuelve un nuevo objeto HTTP::Tiny. Los atributos válidos incluyen:

  • "agent" — Una cadena de cadena de agente de usuario (por defecto es 'HTTP-Tiny/$VERSION'). Si "agent" — termina en un espacio, se añade la cadena de agente de usuario por defecto.
  • "cookie_jar" — Una instancia de HTTP::CookieJar — o una clase equivalente que soporte los métodos "add" y "cookie_header"
  • "default_headers" — Un hashref de cabeceras por defecto a aplicar a las peticiones
  • "local_address" — La dirección IP local a la que vincularse
  • "keep_alive" — Si se reutiliza la última conexión (si es para el mismo esquema, host y puerto) (por defecto es 1)
  • "max_redirect" — Número máximo de redirecciones permitidas (por defecto es 5)
  • "max_size" — Tamaño máximo de la respuesta en bytes (solo cuando no se usa una devolución de llamada de datos). Si se define, las peticiones con respuestas mayores que este valor devolverán un código de estado 599.
  • "http_proxy" — URL de un servidor proxy a usar para conexiones HTTP (el valor por defecto es $ENV{http_proxy} — si está establecido)
  • "https_proxy" — URL de un servidor proxy a usar para conexiones HTTPS (el valor por defecto es $ENV{https_proxy} — si está establecido)
  • "proxy" — URL de un servidor proxy genérico para conexiones HTTP y HTTPS (el valor por defecto es $ENV{all_proxy} — si está establecido)
  • "no_proxy" — Lista de sufijos de dominio que no deben ser proxy. Debe ser una cadena separada por comas o una referencia a un array. (por defecto es $ENV{no_proxy} —)
  • "timeout" — Tiempo de espera de la petición en segundos (por defecto es 60). Si la apertura, lectura o escritura de un socket tarda más que el tiempo de espera, el código de estado de la respuesta será 599.
  • "verify_SSL" — Un booleano que indica si se debe validar el certificado TLS/SSL de una conexión "https" — (por defecto es true). Cambiado de false a true en la versión 0.083.
  • "SSL_options" — Un hashref de opciones "SSL_*" — para pasar a IO::Socket::SSL
  • $ENV{PERL_HTTP_TINY_SSL_INSECURE_BY_DEFAULT} - Cambia el comportamiento de verificación de certificados por defecto a no comprobar la identidad del servidor si se establece en 1. Solo efectivo si "verify_SSL" no está establecido. Añadido en la versión 0.083.

Existe un método de acceso/mutador para cada atributo.

Pasar un "undef" explícito para "proxy", "http_proxy" o "https_proxy" evitará obtener los proxies correspondientes del entorno.

Los errores durante la ejecución de la petición darán como resultado un código de estado pseudo-HTTP de 599 y una razón de "Internal Exception". El campo contenido en la respuesta contendrá el texto del error.

El parámetro "keep_alive" habilita una conexión persistente, pero solo a un esquema, host y puerto de destino único. Si algún atributo relevante para la conexión se modifica a través del acceso, o si el ID del proceso o el ID del hilo cambian, la conexión persistente se cerrará. Si desea conexiones persistentes a través de múltiples destinos, utilice varios objetos HTTP::Tiny.

Consulte "SOPORTE TLS/SSL" para más información sobre los atributos "verify_SSL" y "SSL_options".

get|head|put|post|patch|delete

$response = $http->get($url);
$response = $http->get($url, \%options);
$response = $http->head($url);

Estos métodos son atajos para llamar a request() para el método dado. La URL debe tener los caracteres inseguros escapados y los nombres de dominio internacionales codificados. Consulte request() para ver las opciones válidas y una descripción de la respuesta.

El campo "success" de la respuesta será verdadero si el código de estado es 2XX.

post_form

$response = $http->post_form($url, $form_data);
$response = $http->post_form($url, $form_data, \%options);

Este método ejecuta una petición "POST" y envía los pares clave/valor de un hash o referencia a array de datos de formulario a la URL dada con un "content-type" de "application/x-www-form-urlencoded". Si los datos se proporcionan como una referencia a array, se preserva el orden; si se proporcionan como una referencia a hash, los términos se ordenan por clave para mayor consistencia. Consulte la documentación del método "www_form_urlencode" para obtener detalles sobre la codificación.

La URL debe tener los caracteres inseguros escapados y los nombres de dominio internacionales codificados. Consulte request() para ver las opciones válidas y una descripción de la respuesta. Cualquier cabecera "content-type" o contenido en el hashref de opciones será ignorado.

El campo "success" de la respuesta será verdadero si el código de estado es 2XX.

mirror

$response = $http->mirror($url, $file, \%options)
if ( $response->{success} ) {
    print "$file está actualizado\n";
}

Ejecuta una petición "GET" para la URL y guarda el cuerpo de la respuesta en el nombre de archivo proporcionado. La URL debe tener los caracteres inseguros escapados y los nombres de dominio internacionales codificados. Si el archivo ya existe, la petición incluirá una cabecera "If-Modified-Since" con la marca de tiempo de modificación del archivo. Puede especificar usted mismo una cabecera "If-Modified-Since" diferente en el hash "$options->{headers}".

El campo "success" de la respuesta será verdadero si el código de estado es 2XX o si el código de estado es 304 (no modificado).

Si el archivo fue modificado y la respuesta del servidor incluye una cabecera "Last-Modified" formateada correctamente, la hora de modificación del archivo se actualizará en consecuencia.

SOPORTE

TLS/SSL

Las conexiones directas "https" se admiten solo si IO::Socket::SSL 1.56 o superior y Net::SSLeay 1.49 o superior están instalados. Ocurrirá un error si no están instaladas versiones lo suficientemente nuevas de estos módulos o si el cifrado TLS falla. También puede usar la función utilitaria HTTP::Tiny::can_ssl() que devuelve un booleano para ver si los módulos requeridos están

instalados.

Se puede realizar una conexión "https" a través de un proxy "http" que soporte el comando CONNECT (es decir, RFC 2817). No se puede usar un proxy para "https" a través de un proxy que a su vez requiera "https" para

comunicarse.

La verificación se realiza comprobando que la conexión TLS/SSL tiene un certificado válido correspondiente al nombre de host de la conexión y que el certificado ha sido verificado por una CA. Asumiendo que confía en la CA, esto protegerá contra ataques de máquina en el medio http://en.wikipedia.org/wiki/Machine-in-the-middle_attack

confianza.

certificados.
