N

"Hash::Util" y "Hash::Util::FieldHash" contienen funciones especiales para manipular hashes que realmente no justifican una palabra

clave.

"Hash::Util" contiene un conjunto de funciones que soportan hashes restringidos. Estas se describen en este documento. "Hash::Util::FieldHash" contiene un conjunto de funciones (no relacionadas) que soportan el uso de hashes en clases inside-out, descritas en Hash::Util::

FieldHash.

Por defecto "Hash::Util" no exporta

nada.

Hashes

restringidos

La versión 5.8.0 introduce la capacidad de restringir un hash a un conjunto determinado de claves. No se pueden añadir claves fuera de este conjunto. También introduce la capacidad de bloquear una clave individual para que no pueda ser eliminada y la capacidad de asegurar que un valor individual no pueda ser

cambiado.

Esto está destinado a reemplazar en gran medida los pseudo-hashes

obsoletos.

Restringe el conjunto de claves del %hash dado a @keys. Si @keys no se proporciona, lo restringe a su conjunto de claves actual. perlrun.

El primer conjunto de estadísticas proporciona información estadística resumida, incluida la puntuación de calidad traducida a "Good", "Poor" y "Bad", (puntuación<=1.05, puntuación<=1.2, puntuación>1.2). Consulte la documentación en bucket_stats() para más

Los dos conjuntos de gráficos de barras proporcionan estadísticas e una indicación visual del rendimiento del

hash.

El primero proporciona datos sobre las longitudes de las cadenas de cubos y ofrece una idea de cuánto trabajo tomará una búsqueda *fallo*. En este caso, tenemos que inspeccionar cada elemento de un cubo antes de poder estar seguros de que el elemento no está en la lista. El rendimiento para una inserción es equivalente a este caso, al igual que un borrado donde el elemento no está en el

hash.

El segundo proporciona datos sobre cuántas claves hay en cada profundidad de la cadena, y da una idea de cuánto trabajo tomará una búsqueda *acierto*. El rendimiento para una actualización o borrado de un elemento en el hash es equivalente a este

caso.

Tenga en cuenta que estas estadísticas son solo resumen. El rendimiento real dependerá de las ratios reales de aciertos/fallos al acceder al hash. Si le preocupan las ratios de aciertos, se recomienda "sobredimensionar" su hash usando

algo como:

$k;

hash_traversal_m
ask
A partir de Perl 5.18, cada hash tiene su propio orden de recorrido, y este orden cambia cada vez que se inserta un nuevo elemento en el hash. Esta funcionalidad se proporciona manteniendo una máscara de entero sin signo (U32) que se hace xor con el id de cubo real durante un recorrido de los cubos del hash usando keys(), values() o each().

Puede usar esta subrutina para obtener y establecer la máscara de recorrido para un hash específico. Establecer la máscara garantiza que un hash dado producirá el mismo orden de claves. Tenga en cuenta que esto no garantiza que dos hashes produzcan el mismo orden de claves para la misma semilla de hash y máscara de recorrido; los elemen

tos que colisionan en un mismo cubo pueden tener difer
entes órdenes independientemente de esta configuración.
