Descripción

detallada

El enlace de memoria se puede realizar de tres

maneras:
  • asignación de memoria explícita gracias a hwloc_alloc_membind() y afines: el enlace tendrá efecto sobre la memoria asignada por estas
    • funciones.
  • enlace de memoria implícito a través de la política de enlace: hwloc_set_membind() y afines solo definen la política actual del proceso, que se aplicará a las llamadas posteriores a malloc() y
    • afines.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y afine
    • s, que mueven dat
os ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente en

uso.

Cuando la operación de enlace solicitada no está disponible y se pasó el flag HWLOC_MEMBIND_STRICT, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema sí soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria a nivel de hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA)

.

Si no se pasó HWLOC_MEMBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlace más pequeño, etc.) cuando la operación solicitada no esté exactamente

soportada.

La forma más portable, que debería preferirse sobre las demás siempre que sea posible, es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para ello, hwloc posiblemente tenga que cambiar la política actual de enlace de memoria para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política actual de enlace de

memoria. 
hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0)
;

Cada función de enlace de memoria de hwloc toma un argumento bitmap que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si se especifica el flag HWLOC_MEMBIND_BYNODESET. Véase Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de bitmaps para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_n

odeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea

posible.

enum hwloc_membind_flags_

t

Flags de enlace de memoria. Estos flags pueden usarse para refinar la política de enlace. Todos los flags pueden combinarse lógicamente con OR, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos flags son mutuamente

excluyentes.

No todos los sistemas soportan todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente en uso. Véase la sección 'Descripción detallada' de Enlace de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este flag es mutuamente excluyente con HWLOC_MEMBIND_
THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este flag es mutuamente excluyente con HWLOC_MEMBIND_PROCE
SS.
HWLOC_MEMBIND_STRICT
Solicita enlace estricto al SO. La func
ión fallará si el enlace no puede
garantizarse / aplicarse completamente.

Este flag tiene significados ligeramente diferentes dependiendo con qué función se

use.
HWLOC_MEMBIND_MIGRATE
Migra la memoria ya asignada. Si la memoria no puede migrarse y se pasó el flag HWLOC_MEMBIND_STRICT, se devolverá un
error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlace de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlace de memoria también enlazan la aplicación a la(s) CPU(s) correspondiente(s). Usar este flag hará que hwloc evite usar funciones del SO que podrían afectar a los enlaces de CPU. Nótese, sin embargo, que usar NOCPUBIND puede reducir el soporte general de enlace de memoria de hwloc. Específicamente: algunas de las funciones de enlace de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usan con
NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento bitmap como un conjunto de nodos. El argument
o bitmap se considera un conjunto de nodos si se da este flag
, o un conjunto de CPU (cpuset) por defecto en caso contrario.

El enlace de memoria por conjunto de CPU no puede funcionar para

nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por c
onjunto de nodos debería preferirse siempre que sea posible.

enum hwloc_membind_policy_

t

Política de enlace de memoria. Estas constantes se pueden usar para elegir la política de enlace. Solo se puede usar una política a la vez (es decir, los valores no se pueden combinar con OR)

.

No todos los sistemas admiten todos los tipos de enlace. hwloc_topology_get_support() se puede usar para consultar la compatibilidad real con la política de enlace de memoria en el sistema operativo utilizado actualmente. Consulte la sección 'Descripción Detallada' de Enlace de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD), o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones de obtención de enlace de memoria. El argumento nodeset se
ignora.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado generalmente debería ser hwloc_topology_get_topology_nodeset() para que el hilo que t
oca pueda ejecutarse y asignar
en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (en caso contrario)

.
HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre sistemas operativos, especialmente cuando (algunos de) los nodos solicitados están llenos. En Linux, de forma predeterminada, se utiliza la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona el indicador de estricto de hwloc, se utiliza en su lugar la política MPOL_BIND de
Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / round-robin. La disposición precisa de la memoria en múltiples nodos NUMA es específica del sistema operativo/sistema. El intercalado puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados accederán todos al rango completo de memoria simultáneamente, ya que el intercalado equilibrará entonces las referencias de
memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / ponderada. La disposición precisa de la memoria en múltiples nodos NUMA es específica del sistema operativo/sistema. El intercalado ponderado puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán todos al rango completo de memoria simultáneamente, ya que el intercalado equilibrará entonces las referencias de
memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página vinculada con esta política, la próxima vez que sea tocada (y solo la próxima vez), se mueve de su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia de memoria (si es necesario moverla)
.
HWLOC_MEMBIND_MIXED
Devuelto por las funciones get_membind() cuando múltiples hil
os o partes de un área de memoria tienen políticas de enlace
de memoria diferentes. También se devuelve cuando el enlace es
desconocido porque los ganchos de enlace están vacíos cuando
la topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

DESCRIPTION

These functions manage the memory binding of memory allocators, processes, or the current thread. This binding specifies which NUMA node(s) memory allocations should be made on. The available policies are described in hwloc(7).

hwloc_set_area_membind

Bind the already-allocated memory identified by (addr, len) to the NUMA node(s) specified by set. If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

Returns

0 on success or if len is 0.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.

hwloc_set_membind

Set the default memory binding policy of the current process or thread to prefer the NUMA node(s) specified by set. If neither HWLOC_MEMBIND_PROCESS nor HWLOC_MEMBIND_THREAD is specified, the current process is assumed to be single-threaded. This is the most portable form as it permits hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.

hwloc_get_membind

Query the default memory binding policy and physical locality of the current process or thread. The bitmap set (previously allocated by the caller) is filled with the process or thread memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the current process. Passing HWLOC_MEMBIND_THREAD specifies that the query target is the current policy and nodeset for only the thread invoking this function.

If neither of these flags are passed (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

HWLOC_MEMBIND_STRICT is only meaningful when HWLOC_MEMBIND_PROCESS is also specified. In this case, hwloc will check the default memory policies and nodesets for all threads in the process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, if HWLOC_MEMBIND_PROCESS is specified (and HWLOC_MEMBIND_STRICT is not specified), the default set from each thread is logically OR'ed together. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

In the HWLOC_MEMBIND_THREAD case (or when neither HWLOC_MEMBIND_PROCESS or HWLOC_MEMBIND_THREAD is specified), there is only one set and policy; they are returned in set and policy, respectively.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

hwloc_get_proc_membind

Query the default memory binding policy and physical locality of the specified process. The bitmap set (previously allocated by the caller) is filled with the process memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the specified process. If HWLOC_MEMBIND_PROCESS is not specified (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

Note that it does not make sense to pass HWLOC_MEMBIND_THREAD to this function.

If HWLOC_MEMBIND_STRICT is specified, hwloc will check the default memory policies and nodesets for all threads in the specified process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, set is set to the logical OR of all threads' default set. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.

Note
