HTML::Element::traverse(3pm) Documentación de Perl contribuida por el usuario HTML::Element::traverse(3pm)

NOMBRE

HTML::Element::traverse - discusión del método traverse de HTML::Element

VERSIÓN

Este documento describe la versión 5.07 de HTML::Element::traverse, publicada el 31 de agosto de 2017 como parte de HTML-Tree.

SINOPSIS

# $element->traverse es innecesario y oscuro.
#   No lo uses en código nuevo.

DESCRIPCIÓN

"HTML::Element" proporciona un método "traverse" que recorre el árbol y llama a callbacks definidos por el usuario para cada nodo, en preorden o postorden. Sin embargo, el uso del método es bastante superfluo: si deseas visitar recursivamente cada nodo del árbol, casi siempre es más sencillo escribir una subrutina que haga exactamente eso, que empaquetar el código preorden y/o postorden en callbacks para el método "traverse".

EJEMPLOS

Supongamos que quieres recorrer en/debajo de un nodo $tree y asignar a los elementos un atributo 'id' a menos que ya lo tengan.

Puedes usar el método "traverse":

{
  my $counter = 'x0000';
  $start_node->traverse(
    [ # Callbacks;
      # callback en preorden:
      sub {
        my $x = $_[0];
        $x->attr('id', $counter++) unless defined $x->attr('id');
        return HTML::Element::OK; # seguir recorriendo
      },
      # callback en postorden:
      undef
    ],
    1, # no llamar a los callbacks para nodos de texto
  );
}

o puedes simplemente ser simple y claro (y no tener que entender el formato de llamada de "traverse") escribiendo una subrutina que recorra el árbol llamándose a sí misma:

{
  my $counter = 'x0000';
  sub give_id {
    my $x = $_[0];
    $x->attr('id', $counter++) unless defined $x->attr('id');
    foreach my $c ($x->content_list) {
      give_id($c) if ref $c; # ignorar nodos de texto
    }
  };
  give_id($start_node);
}

¿Ves? ¿No es eso agradable y claro?

Pero, si realmente necesitas saberlo:

EL MÉTODO TRAVERSE

El método traverse() es un método de objeto general para recorrer un árbol o subárbol y llamar a callbacks especificados por el usuario. Acepta las siguientes sintaxis:

$h->traverse(\&callback)
o $h->traverse(\&callback, $ignore_text)
o $h->traverse( [\&pre_callback,\&post_callback] , $ignore_text)

Todas estas significan recorrer el elemento y todos sus hijos. Es decir, este método comienza en el nodo $h, visita $h en "preorden", recorre sus hijos, y luego visitará $h en "postorden". "Visitar" significa que se llama a la rutina callback, con estos argumentos:

$_[0] : el nodo (elemento o segmento de texto),
$_[1] : un flag de inicio, y
$_[2] : la profundidad

Si se proporciona el parámetro $ignore_text y es verdadero, entonces la llamada en preorden *no* ocurrirá para el contenido de texto.

El flag de inicio es 1 cuando entramos en un nodo (es decir, en llamadas en preorden) y 0 cuando salimos del nodo (en llamadas en postorden).

Sin embargo, ten en cuenta que las llamadas en postorden no ocurren para nodos que son segmentos de texto o que son elementos prototípicamente vacíos (como "br", "hr", etc.).

Si visitamos nodos de texto (es decir, a menos que se proporcione $ignore_text y sea verdadero), entonces cuando se visiten nodos de texto, también pasaremos dos argumentos adicionales al callback:

$_[3] : el elemento que es el padre
         de este nodo de texto
$_[4] : el índice de este nodo de texto
         en la lista de contenido de su padre

Ten en cuenta que puedes especificar que la rutina en preorden sea diferente de la rutina en postorden:

$h->traverse( [\&pre_callback,\&post_callback], ...);

También puedes especificar que no se realicen llamadas en postorden, proporcionando un valor falso como rutina de postorden:

$h->traverse([ \&pre_callback,0 ], ...);

Y de manera similar para suprimir llamadas en preorden:

$h->traverse([ 0,\&post_callback ], ...);

Ten en cuenta que estas dos sintaxis especifican la misma operación:

$h->traverse([\&foo,\&foo], ...);
$h->traverse( \&foo       , ...);

Los valores de retorno de las llamadas a tus rutinas en preorden o postorden son significativos y se utilizan para controlar la recursión en el árbol.

Estos son los valores que puedes retornar, listados en orden descendente de mi estimación de su utilidad:

HTML::Element::OK, 1, o cualquier otro valor verdadero
...para seguir recorriendo.

Ten en cuenta que "HTML::Element::OK" et al son constantes. Así que si estás ejecutando bajo "use strict" (como espero que lo estés), y dices: "return HTML::Element::PRUEN" el compilador marcará esto como un error (un bareword no permitido, específicamente), mientras que si escribes PRUNE correctamente, el compilador no se quejará.

undef, 0, '0', '', o HTML::Element::PRUNE
...para bloquear el recorrido dentro del contenido del elemento actual. (Esto se ignora si se recibe de un callback en postorden, ya que para entonces la recursión ya ha ocurrido.) Si esto es retornado por un callback en preorden, no ocurrirá ningún callback en postorden para el nodo actual. (Recuerda que si tu callback sale con solo "return;", está retornando undef -- al menos en contexto escalar, y "traverse" siempre llama a tus callbacks en contexto escalar.)
HTML::Element::ABORT
...para abortar todo el recorrido inmediatamente. Esto a menudo es útil cuando estás buscando solo el primer nodo en el árbol que cumpla algún criterio tuyo.
HTML::Element::PRUNE_UP
...para abortar el recorrido continuado hacia este nodo y su nodo padre. No ocurrirá ningún callback en postorden para el nodo actual ni para el nodo padre.
HTML::Element::PRUNE_SOFTLY
Como PRUNE, excepto que la llamada en postorden para el nodo actual no se bloquea.

Casi todas las tareas relacionadas con la extracción de información de un árbol se pueden expresar en términos de operaciones de recorrido (generalmente en un solo paso, y prestando atención generalmente solo al preorden, o solo al postorden), u operaciones basadas en el recorrido. (De hecho, muchos de los otros métodos de esta clase son básicamente llamadas a traverse() con argumentos particulares.)

El código fuente de HTML::Element y HTML::TreeBuilder contienen varios ejemplos del uso del método "traverse" para recopilar información sobre el contenido de árboles y subárboles.

(Nota: no debes cambiar la estructura de un árbol *mientras* lo estás recorriendo.)

[Fin de la documentación para el método traverse()]

Recorrer con Rutinas Anónimas Recursivas

Ahora, si has estado leyendo demasiado *Estructura e Interpretación de Programas de Computadora*, quizás incluso quieras una lambda recursiva. Adelante:

{
  my $counter = 'x0000';
  my $give_id;
  $give_id = sub {
    my $x = $_[0];
    $x->attr('id', $counter++) unless defined $x->attr('id');
    foreach my $c ($x->content_list) {
      $give_id->($c) if ref $c; # ignorar nodos de texto
    }
  };
  $give_id->($start_node);
  undef $give_id;
}

Es un poco loco, y *aún* es más conciso que una llamada al método "traverse".

Se deja como ejercicio al lector descubrir cómo hacer lo mismo sin usar un símbolo $give_id en absoluto.

También se deja como ejercicio al lector t

o averiguar por qué indefino $give_id, arriba; y por qué pude lograr el mismo efecto con cualquiera de:

 $give_id = 'I like pie!';
# o...
 $give_id = [];
# o incluso;
 $give_id = sub { print "Mmmm pie!\n" };

Pero no:

 $give_id = sub { print "I'm $give_id and I like pie!\n" };
# ni...
 $give_id = \$give_id;
# ni...
 $give_id = { 'pie' => \$give_id, 'mode' => 'a la' };

Haciendo Cosas Recursivas Iterativamente

Tenga en cuenta que a veces puede ver una implementación iterativa de el recorrido en pre-orden, así:

{
  my @to_do = ($tree); # nodo inicial
  while(@to_do) {
    my $this = shift @to_do;
    # "Visitar" el nodo:
    $this->attr('id', $counter++)
     unless defined $this->attr('id');
    unshift @to_do, grep ref $_, $this->content_list;
     # Poner los hijos en la pila -- serán visitados a continuación
  }
}

Esto puede bajo ciertas circunstancias ser más eficiente que simplemente una rutina recursiva normal, pero a costa de ser bastante oscuro. Gana eficiencia al evitar la sobrecarga de la llamada a funciones, pero como hay varios despachos de métodos sin importar cómo lo haga (a "attr" y "content_list"), la sobrecarga para una simple llamada a función es insignificante.

Poda y Cosas Varias

El "traverse" método sí tiene las características bastante elegantes de las señales "ABORT", "PRUNE_UP" y "PRUNE_SOFTLY" . Ninguna de estas puede ser implementada totalmente de manera directa con rutinas recursivas, pero es bastante posible. "ABORT"-el comportamiento similar puede implementarse ya sea usando retorno no local con "eval"/"die":

my $died_on; # si necesita saber dónde...
sub thing {
  ... visita $_[0]...
  ... tal vez establecer $died_on a $_[0] y die "ABORT_TRAV" ...
  ... de lo contrario llamar a thing($child) para cada hijo...
  ...cualquier visita post-orden $_[0]...
}
eval { thing($node) };
if($@) {
  if($@ =~ m<^ABORT_TRAV>) {
    ...murió (abortó) en $died_on...
  } else {
    die $@; # ocurrió un error REAL
  }
}

o simplemente puede hacerlo con banderas:

my($abort_flag, $died_on);
sub thing {
  ... visita $_[0]...
  ... tal vez establecer $abort_flag = 1; $died_on = $_[0]; return;
  foreach my $c ($_[0]->content_list) {
    thing($c);
    return if $abort_flag;
  }
  ...cualquier visita post-orden $_[0]...
  return;
}
$abort_flag = $died_on = undef;
thing($node);
...si $abort_flag está definido, murió en $died_on
