NOMBRE

WML — El formato de archivo de meta-lenguaje de widgets para crear compiladores uil

DESCRIPCIÓN

La facilidad de meta-lenguaje de widgets (WML) se utiliza para generar los componentes del compilador del lenguaje de interfaz de usuario (UIL) que pueden cambiar según el conjunto de widgets. Usando WML, puedes añadir soporte en UIL para nuevos widgets al conjunto de widgets Motif o para un conjunto de widgets completamente nuevo.

Archivo

Los archivos WML son archivos ASCII que puedes modificar con cualquier editor de texto estándar. Son accedidos en el directorio tools/wml por WML. Por convención, los archivos WML tienen el sufijo .wml. El conjunto de widgets Motif se describe en el archivo motif.wml. Este es también el archivo WML por defecto al usar la facilidad WML.

Al añadir nuevos widgets o cambiar características de widgets, debes empezar con una copia del archivo motif.wml. Si estás creando un nuevo conjunto de widgets para usar con UIL, debes empezar desde cero. En cualquier caso, el archivo motif.wml es un buen ejemplo de la sintaxis de WML, y debes familiarizarte con él antes de escribir tu propio archivo WML.

Los archivos WML tienen una sintaxis simple, similar en estructura a UIL. Está compuesto por los siguientes elementos:

•
Comentarios
•
Definiciones de Tipos de Datos
•
Definiciones de Conjuntos de Caracteres
•
Definiciones de Conjuntos de Enumeraciones
•
Definiciones de Listas de Control
•
Definiciones de Clases
•
Definiciones de Hijos
•
Definiciones de Recursos

Puedes usar espacios, tabulaciones o saltos de línea en cualquier lugar de la sintaxis, siempre y cuando no dividas palabras clave o cadenas, excepto que los comentarios terminan en un salto de línea. El orden de los elementos no es importante para la sintaxis.

Esta descripción utiliza las siguientes convenciones adicionales para describir la sintaxis del meta-lenguaje de widgets:

[  ]
Indica elementos opcionales.
...
Indica dónde un elemento de sintaxis puede repetirse.
|
Indica una elección entre múltiples elementos.

Comentarios

Puedes incluir comentarios en el archivo WML. Los comentarios tienen la siguiente sintaxis:

[cualquier.elemento]!cualquier.comentario

Los comentarios comienzan con un signo de exclamación y se extienden hasta el final de la línea. Un comentario puede comenzar en una línea propia o seguir a cualquier parte de otro elemento. Un comentario no cambia el significado de ningún otro elemento. Por ejemplo:

!Este es un comentario
!  que abarca dos líneas.
DataType    !Este es un comentario después del código.

Definiciones de Tipos de Datos

Las definiciones de tipos de datos registran todos los tipos de datos de recursos utilizados en el archivo. Debes registrar todos los tipos de datos utilizados en tu archivo WML. Las definiciones de tipos de datos tienen la siguiente sintaxis:

DataType
     cualquier.tipodato [{ InternalLiteral = nombre.interno |
          DocName = "cadena"; [...]}];
     [...]

Una definición de tipo de datos comienza con la palabra clave DataType. Después de la palabra clave DataType hay una lista de tipos de datos que pueden ser modificados adicionalmente con

InternalLiteral
Esto fuerza el valor de la definición del literal de la tabla de símbolos interna del nombre del tipo de datos. Este modificador solo se usa para sortear definiciones de tablas de símbolos codificadas en el compilador UIL. Rara vez debe usarse.
DocName
Esto proporciona una cadena arbitraria para usar en la documentación. Esta cadena tiene como objetivo proporcionar un nombre diferente para el tipo de datos para su uso en la documentación, o un solo nombre para el tipo de datos si el tipo de datos tiene alias.

Por ejemplo:

DataType OddNumber {DocName="OddNumber";};
         NewString;

Definiciones de Conjuntos de Caracteres

Las definiciones de conjuntos de caracteres registran el nombre del Toolkit Motif y otra información para los nombres de conjuntos de caracteres utilizados en UIL. Las definiciones de conjuntos de caracteres tienen la siguiente sintaxis:

CharacterSet
     cualquier.conjunto.caracter
          { [ FontListElementTag | XmStringCharsetName ] = "cadena";
               [ Alias = "cadena" ...; |
               Direction = [ LeftToRight | RightToLeft ]; |
               ParseDirection = [ LeftToRight | RightToLeft ]; |
               CharacterSize = [ OneByte | TwoByte ]; ]
               [ ... ] };
     [ ... ]

Una definición de conjunto de caracteres comienza con la palabra clave CharacterSet. Después de la palabra clave CharacterSet hay una lista de conjuntos de caracteres que pueden ser modificados adicionalmente con

FontListElementTag | XmStringCharsetName
Especifica el nombre del conjunto de caracteres, que se convertirá en el componente de conjunto de caracteres de un segmento de cadena compuesta creado usando este conjunto de caracteres. Este modificador es obligatorio.
Alias
Especifica uno o más alias para el nombre del conjunto de caracteres. Cada alias puede ser utilizado dentro de UIL para referirse al mismo conjunto de caracteres.
Direction
Especifica la dirección de un segmento de cadena compuesta creado usando este conjunto de caracteres. El valor por defecto es LeftToRight.
ParseDirection
Especifica la dirección en la que se analiza una cadena de entrada cuando se crea un segmento de cadena compuesta usando este conjunto de caracteres. El valor por defecto es el que se especifica en Direction.
CharacterSize
Especifica el número de bytes en cada carácter de un segmento de cadena compuesta creado usando este conjunto de caracteres. El valor por defecto es OneByte.

Por ejemplo:

CharacterSet
  iso_latin1
    { XmStringCharsetName = "ISO8859-1";
      Alias = "ISOLatin1"; };
  iso_hebrew_lr
    { XmStringCharsetName = "ISO8859-8";
      Alias = "iso_latin8_lr";
      Direction = RightToLeft;
      ParseDirection = LeftToRight; };
  ksc_korean
    { XmStringCharsetName = "KSC5601.1987-0";
      CharacterSize = TwoByte; };

Definiciones de Conjuntos de Enumeraciones

Las definiciones de conjuntos de enumeraciones registran las constantes nombradas utilizadas en el Toolkit Motif para especificar algunos valores de recursos. Las definiciones de conjuntos de enumeraciones tienen la siguiente sintaxis:

EnumerationSet
     nombre.recurso: tipo.recurso
          { nombre.valor.enum; [ ... ] };

Una definición de conjunto de enumeraciones comienza con la palabra clave EnumerationSet. Para cada conjunto de enumeraciones definido, se lista el nombre y el tipo del recurso. El nombre del recurso es el nombre del recurso del Toolkit Motif, con el prefijo XmN eliminado y con la letra inicial en mayúscula. Por ejemplo, el nombre del recurso del Toolkit Motif XmNrowColumnType es RowColumnType. El tipo de recurso es el tipo de datos para el recurso; para la mayoría de los recursos, este es integer. Después del nombre y tipo del recurso hay una lista de nombres de valores de enumeración que pueden usarse como configuraciones para el recurso. Estos nombres son los mismos que los del Toolkit Motif.

Por ejemplo:

EnumerationSet
  RowColumnType: integer
    { XmWORK_AREA; XmMENU_BAR; XmMENU_POPUP;
      XmMENU_PULLDOWN; XmMENU_OPTION; };

Los conjuntos de enumeraciones también admiten valores booleanos.

UIL Grammar

UIL (User Interface Language) is a declarative language used to describe the user interface for an application. The UIL compiler translates a UIL source file into a binary file that can be used by an application at runtime.

This document describes the UIL grammar. The UIL grammar is divided into the following sections:

  • Data Type Definitions

  • Control List Definitions

  • Class Definitions

  • Child Definitions

  • Resource Definitions

Data Type Definitions

Data type definitions describe the types that can be used in UIL files. There should be a data type definition for each new data type that is referenced in the class definitions. Data type definitions have the following syntax:

DataType data.type.name: type
     [{[
     Alias = alias; |
     InternalLiteral = internal.name; |
     [...]
     ]}];

Data type definitions start with the DataType keyword. For each data type defined, the name of the data type and the base UIL data type it is derived from are listed. Each data type definition can be further modified with the keywords described in the following list.

Alias
This indicates alternate names for the data type for use in a UIL specification.
InternalLiteral
This forces the value of the internal symbol table literal definition of the data type name. This modifier is only used to get around symbol table definitions hard coded into the UIL compiler. It should rarely be used.

The following example defines two new data types, OddNumber and NewString.

DataType
     OddNumber: Integer
          {
          Alias = Integer;
          };
     NewString: String
          {
          Alias = String;
          };

Control List Definitions

Control list definitions are named lists of controls. These lists can be referenced elsewhere in a uil file using the Controls keyword within a class definition. Control list definitions have the following

ControlList
     any.control.list [{ any.control; [...]}];

A control list definition starts with the ControlList keyword. Following the ControlList keyword are any number of control list definitions. Control list definitions are made up of a control list name followed by the set of controls it represents. For example:

ControlList
        Buttons {PushButton;
                 RadioButton;
                 CascadeButton;
                 NewCascadebutton;};

Each control specified in the control list must be defined as a class in the file.

Class Definitions

Class definitions describe a particular widget class including its position in the class hierarchy, toolkit convenience function, resources, and controls. There should be one class definition for each widget or gadget in the widget set you want to support in UIL. Class definitions have the following syntax:

Class class.name: MetaClass | Widget | Gadget
     [{[
     SuperClass = class.name; |
     ParentClass = parent.class.name; |
     InternalLiteral = internal.name; |
     Alias = alias; |
     ConvenienceFunction = convenience.function; |
     WidgetClass = widget.class; |
     DocName = "string"; |
     DialogClass = True | False; |
     Resources { any.resource.name [{
               Default = new.default.value; |
               Exclude = True |
               False;
               [...]} ];
          [...]}; |
     Controls { any.control.name; [...]};
     Children { any.child.name; [...] };
     [...]
     ]}];

Class definitions start with the Class keyword. For each class defined, the name of the class and whether the class is a metaclass, widget, or gadget is listed. Each class definition can be further modified with the keywords described in the following list.

SuperClass
This indicates the name of the parent class. Only the root of the hierarchy does not specify a SuperClass.
ParentClass
This indicates the name of the widget's automatically created parent class if one exists. This allows resources for that automatically created class to be used in instances of this class. For example, XmBulletinBoardDialog creates both an XmBulletinBoard and an XmDialogShell. To access the resources of the XmDialogShell parent class it must be specified here.
InternalLiteral
This forces the value of the internal symbol table literal definition of the class name. This modifier is only used to get around symbol table definitions hard coded into the UIL compiler. It should rarely be used.
Alias
This indicates alternate names for the class for use in a UIL specification.
ConvenienceFunction
This indicates the name of the creation convenience function for this class. All widget and gadget classes must have a ConvenienceFunction.
WidgetClass
This indicates the associated widget class of gadget type classes. Presently, nothing is done with this value.
DocName
This defines an arbitrary string for use in the documentation. Presently, nothing is done with this value.
DialogClass
This indicates whether the class is a dialog class. Presently, nothing is done with this value.
Resources
This lists the resources of the widget class. This keyword can be further modified with
Default
This specifies a new default value for this resource. Resource default values are usually set in the resource definition. If an inherited resource's default value is changed by the class, the new default value should be noted here.
Exclude
This specifies whether an inherited resource should be excluded from the resource list of the class. Exclude is False by default.
Children
This lists the names of the automatically created children of this class, so that those children can be accessed in the UIL file.
Controls
This lists the controls that the widget class allows. The controls can be other classes or a control list from the control list definition.

The following example uses the examples from the data type definitions and control list definitions above.

Class
     TopLevelWidget: MetaClass
          {
          Resources
               {
               XtbNfirstResource;
               XtbNsecondResource;
               };
          };
     NewWidget: Widget
          {
          SuperClass = TopLevelWidget;
          ConvenienceFunction =
              XtbCreateNewWidget;
          Resources
               {
               XtbNnewResource;
               XtbNfirstResource
                  {Default="XtbNEW_VALUE";};
               XtbNsecondResource
                  {Exclude=True;};
               };
          Controls
               {
               NewWidget;
               Buttons;
               };
          };

Child Definitions

Child definitions register the classes of automatically created children. Automatically created children are referenced elsewhere in a uil file using the Children keyword within a class definition. Child definitions have the following syntax:

Child child.name : class.name; [...]

Where child.name is the name of the automatically created child and class.name is the name of the class of that child.

Resource Definitions

Resource definitions describe a particular resource including its type, and default value. There should be a resource definition for each new resource referenced in the class definitions. Resource definitions have the following syntax:

Resource
     resource.name: Argument | Reason | Constraint | SubResource
          [{[
          Type = type;
          [ResourceLiteral = resource.literal; ]
          [InternalLiteral = internal.name; ]
          [Alias = alias; ]
          [Related = related; ]
          [Default = default; ]
          [DocName = doc.name; ]
          [...]}]
     [...]

Resource definitions start with the Resource keyword. For each resource definition, the name of the resource and whether the resource is an argument, reason, constraint or subresource is listed.

Argument
Indicates a standard resource
Reason
Indicates a callback resource
Constraint
Indicates a constraint resource
SubResource
Presently, nothing is done with this value

The resource definition can be further modified with the following keywords:

Type
This indicates the data type of the resource. It must be listed in the data type definition.
ResourceLiteral
This indicates the keyword used in the UIL file to reference the resource. In Motif, the resource name is the same as the ResourceLiteral.
InternalLiteral
This forces the value of the internal symbol table literal definition of the resource name. This modifier is only used to get around symbol table definitions hard coded into the UIL compiler. It should rarely be used.
Alias
This indicates alternate names for the resource for use in a UIL specification.
Related
This is a special purpose field that allows resources that act as a counter for the current resources to be related to the resource. UIL automatically sets the value of this related resource to the number of items in the compiled instance of type resource.name.
Default
This indicates the default value of the resource.
DocName
This defines an arbitrary string for use in the documentation. Presently, nothing is done with this value.

          { Type = OddNumber;
            Default = "XtbOLD_VALUE";};

          { Type = NewString;
            Default = "XtbNEW_STRING"; };

NAME

WML - Widget Markup Language

DESCRIPTION

The Widget Markup Language (WML) is a tag-based markup language used for describing the structure and content of web pages. It is similar to HTML but is designed to be more lightweight and efficient, especially for mobile devices.

WML pages consist of cards, which are the basic units of content. Cards can contain text, images, links, and input fields. Cards are organized into decks, which are collections of related cards.

WML also supports dynamic content through the use of WMLScript, a scripting language that allows for client-side computation and interaction.

Here is a simple example of a WML page:

<?xml version="1.0"?>
<!DOCTYPE wml PUBLIC "-//WAPFORUM//DTD WML 1.3//EN"
    "http://www.wapforum.org/ Sitemap/wml13.dtd">

<wml>
    <card id="card1" title="Welcome">
        <p>Hello, World!</p>
        <a href="#card2">Go to next card</a>
    </card>

    <card id="card2" title="Second Card">
        <p>This is the second card.</p>
        <do type="accept" label="Go back">
            <prev/>
        </do>
    </card>
</wml>

The WML_ODD_NUMBER constant is likely related to some internal functionality or configuration within the WML processing system, but its specific purpose is not detailed in this general description.
