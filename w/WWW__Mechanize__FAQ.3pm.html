JavaScript

Tengo esta página web que tiene JavaScript, y mi programa Mech no funciona.

Eso es porque WWW::Mechanize no opera sobre JavaScript. Sólo entiende las partes HTML de la página.

Pensé que Mech debía funcionar como un navegador web.

Casi lo hace, pero no soporta JavaScript.

Añadí algunos intentos básicos para recoger URLs en llamadas a "window.open()" y devolverlas en "$mech->links". Funcionan a veces.

Dado que JavaScript es completamente visible para el cliente, no puede ser utilizado para impedir que un scraper siga enlaces. Pero puede hacer la vida difícil. Si quieres hacer scraping de páginas específicas, entonces una solución siempre es posible.

Un uso típico de JavaScript es realizar comprobaciones de argumentos antes de enviar datos al servidor. La URL que buscas probablemente esté enterrada en la función JavaScript. Haz una coincidencia con expresiones regulares en "$mech->content()" para encontrar el enlace que quieres y obténlo directamente con "$mech->get" (esto asume que sabes de antemano lo que buscas).

En casos más difíciles, JavaScript se utiliza para modificar URLs para satisfacer las necesidades de algún middleware. En este caso, necesitas averiguar qué está haciendo JavaScript (¿por qué estas URLs son siempre tan largas?). Probablemente hay alguna función con uno o más argumentos que calcula la nueva URL. Paso uno: usando tu navegador favorito, obtén las URLs antes y después y guárdalas en archivos. Edita cada archivo, convirtiendo los separadores de argumentos ('?', '&' o ';') en saltos de línea. Ahora es fácil usar diff o comm para averiguar qué hizo JavaScript con la URL. Paso 2 - encuentra la llamada a la función que creó la URL - necesitarás analizar e interpretar su lista de argumentos. El depurador de JavaScript en la extensión Firebug para Firefox ayuda con el análisis. En este punto, es bastante trivial escribir tu propia función que emule el JavaScript para las páginas que deseas procesar.

Aquí hay otro enfoque que responde a la pregunta: "Funciona en Firefox, ¿pero por qué no en Mech?" Todo lo que el servidor web sabe sobre el cliente está presente en la solicitud HTTP. Si dos solicitudes son idénticas, los resultados deben ser idénticos. Así que la pregunta real es: "¿Qué es diferente entre la solicitud de mech y la solicitud de Firefox?"

La extensión de Firefox "Tamper Data" es una herramienta eficaz para examinar las cabeceras de las solicitudes al servidor. Compárala con lo que envía LWP. Una vez que ambas sean idénticas, la acción del servidor debería ser la misma.

Digo "debería", porque esto es una simplificación - algunos valores son naturalmente únicos, por ejemplo, un SessionID, pero si un SessionID está presente, eso es probablemente suficiente, aunque el valor será diferente entre la solicitud LWP y la solicitud de Firefox. El servidor podría usar la sesión para almacenar información problemática, pero ese no es el primer lugar donde buscar (y es muy poco probable que sea relevante cuando solicitas la página de inicio de sesión de tu sitio).

Generalmente, el problema se encuentra en argumentos de POSTDATA faltantes o incorrectos, Cookies, User-Agents, Accept, etc. Si estás usando mech, entonces las redirecciones y las cookies no deberían ser un problema, pero se enumeran aquí para mayor completitud. Si te faltan cabeceras, se puede usar "$mech->add_header" para añadir las cabeceras que necesites.

¿Qué módulos funcionan como Mechanize y tienen soporte JavaScript?

En ningún orden particular: Gtk2::WebKit::Mechanize, WWW::Mechanize::Firefox, WWW::Mechanize::Chrome, WWW::Scripter, WWW::Selenium

¿Cómo hago X?

¿Puedo hacer [tal cosa] con WWW::Mechanize?

Si es posible con LWP::UserAgent, entonces sí. WWW::Mechanize es una subclase de LWP::UserAgent, por lo que toda la maravillosa magia de esa clase se hereda.

¿Cómo uso WWW::Mechanize a través de un servidor proxy?

Ver la documentación en LWP::UserAgent sobre cómo usar el proxy. Versión corta:

$mech->proxy(['http', 'ftp'], 'http://proxy.example.com:8000/');

o obtener las especificaciones del entorno:

$mech->env_proxy();
# Entorno configurado así:
gopher_proxy=http://proxy.my.place/
wais_proxy=http://proxy.my.place/
no_proxy="localhost,my.domain"
export gopher_proxy wais_proxy no_proxy

¿Cómo puedo ver qué campos hay en los formularios?

Usa la utilidad mech-dump, opcionalmente instalada con Mechanize.

$ mech-dump --forms http://search.cpan.org
Dumping forms
GET http://search.cpan.org/search
  query=
  mode=all                        (option)  [*all|module|dist|author]
  <NONAME>=CPAN Search            (submit)

¿Cómo consigo que Mech maneje la autenticación?

use MIME::Base64;
my $agent = WWW::Mechanize->new();
my @args = (
    Authorization => "Basic " .
        MIME::Base64::encode( USER . ':' . PASS )
);
$agent->credentials( ADDRESS, REALM, USER, PASS );
$agent->get( URL, @args );

Si quieres usar las credenciales para todas las solicitudes futuras, también puedes usar el método default_header() de LWP::UserAgent en lugar de los argumentos adicionales para get()

$mech->default_header(
    Authorization => 'Basic ' . encode_base64( USER . ':' . PASSWORD ) );

¿Cómo puedo hacer que WWW::Mechanize ejecute este JavaScript?

No puedes. JavaScript está completamente basado en el cliente, y WWW::Mechanize es un cliente que no entiende JavaScript. Ver la parte superior de esta FAQ.

¿Cómo marco una casilla de verificación que no tiene un valor definido?

Establece su valor a "on".

$mech->field( my_checkbox => 'on' );

¿Cómo manejo los frames?

No los tratas como frames, per se, sino como enlaces. Extráelos con

my @frame_links = $mech->find_link( tag => "frame" );

Preguntas frecuentes

¿Cómo obtengo las cabeceras HTTP y sus valores?

Todos los métodos de HTTP::Headers funcionan en un objeto HTTP::Response que es devuelto por los métodos get(), reload(), "response()/res()", click(), submit_form() y request().

my $mech = WWW::Mechanize->new( autocheck => 1 );
$mech->get( 'http://my.site.com' );
my $response = $mech->response();
for my $key ( $response->header_field_names() ) {
    print $key, " : ", $response->header( $key ), "\n";
}

¿Cómo habilito keep-alive?

Dado que WWW::Mechanize es una subclase de LWP::UserAgent, puedes usar el mismo mecanismo para habilitar keep-alive:

use LWP::ConnCache;
...
$mech->conn_cache(LWP::ConnCache->new);

¿Cómo puedo cambiar/especificar el parámetro de acción de un formulario HTML?

Puedes acceder a la acción del formulario utilizando el objeto HTML::Form devuelto por uno de los métodos de especificación de formularios.

Usando "$mech->form_number($number)":

my $mech = WWW::mechanize->new;
$mech->get('http://someurlhere.com');
# Accede al formulario usando su índice basado en cero por orden DOM
$mech->form_number(0)->action('http://newAction'); # URL ABSOLUTA

Usando "$mech->form_name($number)":

my $mech = WWW::mechanize->new;
$mech->get('http://someurlhere.com');
# Accede al formulario usando su índice basado en cero por orden DOM
$mech->form_name('trgForm')->action('http://newAction'); # URL ABSOLUTA

¿Cómo guardo una imagen? ¿Cómo guardo un archivo tarball grande?

Una imagen es solo contenido. Obtienes la imagen y la guardas.

$mech->get( 'photo.jpg' );
$mech->save_content( '/path/to/my/directory/photo.jpg' );

También puedes guardar cualquier contenido directamente en disco usando la bandera ":content_file" para get(), que es parte de LWP::UserAgent.

$mech->get( 'http://www.cpan.org/src/stable.tar.gz',
            ':content_file' => 'stable.tar.gz' );

¿Cómo elijo un valor específico de una lista "<select>"?

Encuentra el "HTML::Form::ListInput" en la página.

my ($listbox) = $mech->find_all_inputs( name => 'listbox' );

Luego crea un hash para la búsqueda:

my %name_lookup;
@name_lookup{ $listbox->value_names } = $listbox->possible_values;
my $value = $name_lookup{ 'Nombre que quiero' };

Si tienes nombres duplicados, este método no funcionará, y tendrás que iterar sobre "$listbox->value_names" y "$listbox->possible_values" en paralelo hasta que encuentres un nombre coincidente.

¿Cómo hago que Mech no siga las redirecciones?

Usas la funcionalidad de LWP::UserAgent, no de Mech en sí.

$mech->requests_redirectable( [] );

O puedes establecer "max_redirect":

$mech->max_redirect( 0 );

Ambas opciones también se pueden establecer en el constructor. Mech no las entiende, por lo que las pasará al constructor de LWP::UserAgent.

¿Por qué no funciona esto? Depurando tu programa Mechanize

Mi programa de Mech no funciona, pero funciona en el navegador.

Mechanize actúa como un navegador, pero aparentemente algo que estás haciendo no coincide con el comportamiento del navegador. Quizás está esperando un cliente web específico, o quizás no estás manejando un campo correctamente. Por alguna razón, tu problema de Mech no está haciendo exactamente lo que hace el navegador, y cuando encuentres eso, tendrás la respuesta.

Mi programa de Mech obtiene estos errores 500.

Un error 500 del servidor web indica que el programa del lado del servidor falló. Probablemente el programa del servidor web esperaba ciertas entradas que no proporcionaste, y en lugar de manejarlo correctamente, el programa falló.

Cualquiera que sea la causa del error 500, si funciona en el navegador, pero no en tu programa de Mech, no estás actuando como el navegador. Ver la pregunta anterior.

¿Por qué mi programa no maneja este formulario correctamente?

Ejecuta mech-dump en tu página y mira lo que dice.

mech-dump es una herramienta de diagnóstico maravillosa para averiguar qué formularios y campos hay en la página.
Digamos que estás rastreando CNN.com, obtendrías esto:

  invocationType=search/top      (oculto de solo lectura)
  sites=web                      (radio)    [*web/The Web ??|cnn/CNN.com ??]
  query=                         (texto)
  <NONAME>=Search                (enviar)
POST http://cgi.money.cnn.com/servlets/quote_redirect
  query=                         (texto)

Cuatro formularios, incluido el primero duplicado al final. Todos los campos, todos sus valores predeterminados, generados amablemente por el método "dump" de HTML::Form.

Si quieres ejecutar mech-dump en algo que no se presta a una rápida obtención de URL, entonces usa el método save_content() para escribir el HTML en un archivo y ejecuta mech-dump en el archivo.

¿Por qué las URL https:// no funcionan?

Necesitas tener instalado IO::Socket::SSL o Crypt::SSLeay.

¿Por qué las URL file:// a archivos con un signo de interrogación en el nombre no funcionan?

Si tienes un archivo local llamado "how-are-you?", la URL de ese archivo es "file:how-are-you%3f". Esto se debe a que URI::file debe estar codificado en URL, al igual que cualquier URL que apunte a algún lugar en Internet debe estarlo si contiene caracteres reservados como "?", "/" o "@". Esto está especificado en RFC 3986. Consulta URI::Escape para ver una lista completa de caracteres reservados.

¿Por qué obtengo "Input 'fieldname' is readonly"?

Estás intentando cambiar el valor de un campo oculto y tienes activadas las advertencias.

Primero, asegúrate de que realmente quieres cambiar el campo que estás cambiando y que no tienes un error de escritura. Normalmente, las variables ocultas son establecidas por el sitio en el que estás trabajando por alguna razón. Si cambias el valor, podrías estar rompiendo alguna funcionalidad al simularla.

Si realmente quieres cambiar un valor oculto, haz los cambios en un ámbito donde las advertencias estén desactivadas:

{
local $^W = 0;
$agent->field( name => $value );
}

Intenté [hacer tal cosa] y obtuve este error extraño.

¿Estás revisando tus errores?

¿Estás seguro?

¿Estás verificando que tu acción tuvo éxito después de cada acción?

¿Estás seguro?

Por ejemplo, si intentas esto:

$mech->get( "http://my.site.com" );
$mech->follow_link( "foo" );

y la llamada "get" falla por alguna razón, entonces los internos de Mech no serán utilizables para "follow_link" y obtendrás un error extraño. **Debes**, después de cada acción que obtenga o publique una página, verificar que Mech tuvo éxito, o todas las apuestas están perdidas.

$mech->get( "http://my.site.com" );
die "Ni siquiera puedo obtener la página de inicio: ", $mech->response->status_line
    unless $mech->success;
$mech->follow_link( "foo" );
die "El enlace foo falló: ", $mech->response->status_line
    unless $mech->success;

¿Cómo averiguo por qué "$mech->get($url)" no funciona?

Hay muchas razones por las que un get() puede fallar. El servidor puede llevarte a un lugar inesperado. Puede generar redirecciones que no se manejan correctamente. Puedes tener tiempos de espera. Los servidores están caídos más a menudo de lo que piensas, etc., etc., etc. Un par de lugares para empezar:

1 Revisa "$mech->status()" después de cada llamada
2 Revisa la URL con "$mech->uri()" para ver dónde terminaste
3 Intenta depurar con "LWP::ConsoleLogger".

Si las cosas son realmente extrañas, activa la depuración con "use LWP::ConsoleLogger::Everywhere;". Simplemente colócalo en el programa principal. Esto hace que LWP imprima un rastreo del tráfico HTTP entre el cliente y el servidor y se puede usar para averiguar qué está sucediendo a nivel de protocolo.

WWW::Mechanize::FAQ - Frequently Asked Questions about WWW::Mechanize

VERSION

2.70

How to get help with WWW::Mechanize

If you have a question about WWW::Mechanize, or are having trouble with it, the best place to start is by reading the rest of the documentation. If you still can't figure it out, then please email me.

Be sure to include the following information:

  • The version of WWW::Mechanize you are using.
  • The version of Perl you are using.
  • The output of the uname -a command.
  • A short, self-contained, runnable example that demonstrates the problem.
  • A clear and concise description of the problem.

The more information you provide, the easier it will be for me to help you.

JavaScript

WWW::Mechanize does not execute JavaScript. If you need to interact with web pages that require JavaScript, you will need to use a different tool, such as Selenium or Playwright.

How do I do X?

I got an error message!

It's always a good idea to check for errors after performing an action. WWW::Mechanize provides a way to do this with the "$mech->current_response()->is_success" method, which returns true if the request was successful, and false otherwise. You can also check the status code directly with "$mech->current_response()->status".

If an error occurs, you should log it. The following code snippet demonstrates how to do this:

my $response = $mech->get( $url );
unless ( $response->is_success ) {
    warn "Failed to get $url: " . $response->status_message;
    # Log the error, email yourself, etc.
}

It's also a good idea to have a "catch-all" case in your code to handle unexpected situations. This is especially important for automated processing.

sub process_page {
    my $mech = shift;

    # ... process the page ...

    # If we get here and don't know what to do, bail out.
    die "I don't know how to process this page: " . $mech->uri;
}

Since errors can be transient, it's useful to email yourself the following information when an error occurs:

  • Where processing is taking place
  • An error message
  • $mech->uri
  • $mech->content

You can also save the content of the page with "$mech->save_content( 'filename.html' );".

I submitted a form, but the server ignored everything! I got an empty form back!

This is usually because the server-side code is not correctly detecting that the form has been submitted. PHP programmers, for example, often use the same file to display the form and process its arguments. They check if certain arguments have been passed to decide whether to display the form or process the input.

If your form is not setting the parameter (e.g., the submit button) that the web application is using to detect the submission, the application will not process your input. Try using "$mech->click()" instead of "$mech->submit()", or vice-versa.

I've logged in to the server, but I get 500 errors when I try to get to protected content.

Some websites use distributed databases for processing. It can take a few seconds for login/session information to propagate to all servers. Human users, with their slower reaction times, don't notice this, but a Perl script can outrun the server. Try adding a sleep(5) between logging in and performing other actions. The optimal delay must be determined experimentally.

Mech is a big memory pig! I'm running out of RAM!

WWW::Mechanize keeps a history of every page and its state. It actually keeps a clone of the full WWW::Mechanize object at every step.

You can limit this history size with the "stack_depth" parameter in the new() constructor. If you set stack_depth to 0, WWW::Mechanize will not keep any history.

How do I find all the links in a sub-section of a page?

To find all links between two specific parts of content on a page, you need to modify the content to remove everything else. This is a bit unorthodox, but it works.

my $html = $mech->content;
$html =~ s/.*(\n[^n]+foo.*bar[^\n]+).*/$1/ms;
$mech->update_html( $html );
$mech->dump_links;
