NOMBRE

WWW::Mechanize - Navegación web útil en un objeto Perl

VERSIÓN

versión 2.20

SINOPSIS

WWW::Mechanize soporta la realización de una secuencia de cargas de páginas incluyendo el seguimiento de enlaces y el envío de formularios. Cada página cargada se analiza y se extraen sus enlaces y formularios. Se puede seleccionar un enlace o un formulario, se pueden rellenar los campos del formulario y se puede cargar la página siguiente. Mech también almacena un historial de las URL visitadas, que se puede consultar y volver a visitar.

use WWW::Mechanize ();
my $mech = WWW::Mechanize->new();
$mech->get( $url );
$mech->follow_link( n => 3 );
$mech->follow_link( text_regex => qr/descargar esto/i );
$mech->follow_link( url => 'http://host.com/index.html' );
$mech->submit_form(
    form_number => 3,
    fields      => {
        username    => 'mungo',
        password    => 'perdido-y-solo',
    }
);
$mech->submit_form(
    form_name => 'buscar',
    fields    => { query  => 'olla de oro', },
    button    => 'Buscar Ahora'
);
# Habilita el procesamiento estricto de formularios para detectar errores tipográficos y campos de formulario inexistentes.
my $strict_mech = WWW::Mechanize->new( strict_forms => 1);
$strict_mech->get( $url );
# Esta llamada al método fallará, ahorrándote mucho tiempo buscando el error.
$strict_mech->submit_form(
    form_number => 3,
    fields      => {
        usernaem     => 'mungo',           # error tipográfico en el nombre del campo
        password     => 'perdido-y-solo',
        extra_field  => 123,               # el campo no existe
    }
);

DESCRIPCIÓN

"WWW::Mechanize", o Mech para abreviar, es un módulo de Perl para la navegación web programática con estado, utilizado para automatizar la interacción con sitios web.

Las características incluyen:

  • Todos los métodos HTTP
  • Soporte de alto nivel para hipervínculos y formularios HTML, sin necesidad de analizar HTML tú mismo
  • Soporte SSL
  • Cookies automáticas
  • Encabezados HTTP personalizados
  • Manejo automático de redirecciones
  • Proxies
  • Autenticación HTTP

Mech es muy adecuado para usar en pruebas de aplicaciones web. Si usas uno de los módulos Test::*, como Test::HTML::Lint, puedes verificar el contenido cargado y usarlo como entrada para una llamada de prueba.

use Test::More;
like( $mech->content(), qr/$esperado/, "Contenido esperado obtenido" );

Cada carga de página almacena su URL en una pila de historial que puedes recorrer.

$mech->back();

Si quieres un control más fino sobre la carga de páginas, puedes usar estos métodos. follow_link() y submit_form() son solo envolturas de alto nivel para ellos.

$mech->find_link( n => $numero );
$mech->form_number( $numero );
$mech->form_name( $nombre );
$mech->field( $nombre, $valor );
$mech->set_fields( %valores_campo );
$mech->set_visible( @criterios );
$mech->click( $boton );

WWW::Mechanize es una subclase adecuada de LWP::UserAgent y también puedes usar cualquiera de los métodos de LWP::UserAgent.

$mech->add_header($nombre => $valor);

Ten en cuenta que Mech NO soporta JavaScript, necesitas software adicional para eso. Consulta "JavaScript" en WWW::Mechanize::FAQ para más información.

CONSTRUCTOR Y ARRANQUE

new()

Crea y devuelve un nuevo objeto WWW::Mechanize, en adelante denominado el "agente".

my $mech = WWW::Mechanize->new()

El constructor de WWW::Mechanize sobrescribe dos de los parámetros del constructor de LWP::UserAgent:

agent => 'WWW-Mechanize/#.##'
cookie_jar => {}    # un objeto HTTP::Cookies vacío, solo en memoria

Puedes sobrescribir estas sobrescrituras pasando parámetros al constructor, como en:

my $mech = WWW::Mechanize->new( agent => 'wonderbot 1.01' );

Si no quieres ninguna de las sobrecargas de un gestor de cookies, o no quieres que tu bot acepte cookies, debes deshabilitarlo explícitamente, así:

my $mech = WWW::Mechanize->new( cookie_jar => undef );

Aquí están los parámetros que WWW::Mechanize reconoce. Estos no incluyen parámetros que LWP::UserAgent reconoce.

  • "autocheck => [0|1]"

    Comprueba cada solicitud realizada para ver si fue exitosa. Esto te ahorra la molestia de comprobarlo tú mismo. Cualquier error encontrado es un error, no una advertencia.

    El valor predeterminado está ACTIVADO, a menos que se esté subclasificando, en cuyo caso está DESACTIVADO. Esto significa que las instancias independientes de WWW::Mechanize tienen autocheck activado, lo cual es protector para la gran mayoría de usuarios de Mech que no se molestan en comprobar el valor de retorno de get() y post() y no pueden averiguar por qué su código falla. Sin embargo, si WWW::Mechanize se subclasea, como para Test::WWW::Mechanize o Test::WWW::Mechanize::Catalyst, esto puede no ser un valor predeterminado apropiado, por lo que está desactivado.

  • "noproxy => [0|1]"

    Desactiva la llamada automática a la función "env_proxy" de LWP::UserAgent.

    Esto debe desactivarse explícitamente si estás usando Crypt::SSLeay para acceder a un sitio https a través de un servidor proxy. Nota: aún necesitas configurar tu variable de entorno HTTPS_PROXY según corresponda.

  • "onwarn => \&func"

    Referencia a una función compatible con "warn", como "Carp::carp", que se llama cuando se necesita mostrar una advertencia.

    Si se establece en "undef", nunca se mostrarán advertencias. Sin embargo, probablemente sea mejor usar el método "quiet" para controlar ese comportamiento.

    Si este valor no se pasa, Mech utiliza "Carp::carp" si Carp está instalado, o "CORE::warn" si no.

  • "onerror => \&func"

    Referencia a una función compatible con "die", como "Carp::croak", que se llama cuando hay un error fatal.

    Si se establece en "undef", nunca se mostrarán errores.

    Si este valor no se pasa, Mech utiliza "Carp::croak" si Carp está instalado, o "CORE::die" si no.

  • "quiet => [0|1]"

    No te quejes de las advertencias. Establecer "quiet => 1" es lo mismo que llamar a "$mech->quiet(1)". El valor por defecto es desactivado.

  • &qu

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

ot;stack_depth => $value"

Establece la profundidad de la pila de páginas que realiza un seguimiento de todas las páginas descargadas. El valor predeterminado es un tamaño de pila prácticamente infinito. Si la pila está consumiendo tu memoria, entonces establece este valor a un número menor, como 5 o 10. Establecer esto a cero significa que Mech no conservará historial.

Además, WWW::Mechanize te permite habilitar globalmente el modo estricto y detallado para el manejo de formularios, lo que se hace con HTML::Form.

  • "strict_forms => [0|1]"

    Establece globalmente el indicador estricto de HTML::Form, que hace que la presentación del formulario falle si alguno de los campos pasados no existe en el formulario, y/o un valor no existe en un elemento select. Esto aún se puede deshabilitar en llamadas individuales a submit_form().

    El valor predeterminado está desactivado.

  • "verbose_forms => [0|1]"

    Establece globalmente el indicador detallado de HTML::Form, que hace que la presentación del formulario advierta sobre cualquier construcción de formulario HTML defectuosa encontrada. Esto no se puede deshabilitar más adelante.

    El valor predeterminado está desactivado.

  • "marked_sections => [0|1]"

    Establece globalmente el indicador de secciones marcadas de HTML::Parser, que hace que las secciones "CDATA[[" de HTML sean respetadas. Esto no se puede deshabilitar más adelante.

    El valor predeterminado está activado.

Para admitir formularios, el constructor de WWW::Mechanize agrega POST a la lista "requests_redirectable" del agente (ver también LWP::UserAgent.)

$mech->agent_alias( $alias )

Establece la cadena del agente de usuario a la versión expandida de una tabla de cadenas de agente de usuario reales. $alias puede ser uno de los siguientes:

  • Windows IE 6
  • Windows Mozilla
  • Mac Safari
  • Mac Mozilla
  • Linux Mozilla
  • Linux Konqueror

luego se reemplazará por una más interesante. Por ejemplo,

$mech->agent_alias( 'Windows IE 6' );

establece tu Agente de Usuario a

Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)

La lista de alias válidos se puede obtener de known_agent_aliases(). La lista actual es:

  • Windows IE 6
  • Windows Mozilla
  • Mac Safari
  • Mac Mozilla
  • Linux Mozilla
  • Linux Konqueror

$mech->known_agent_aliases()

Devuelve una lista de todos los alias de agente que Mech conoce. Esto también se puede llamar como un método de paquete o clase.

@aliases = WWW::Mechanize::known_agent_aliases();
@aliases = WWW::Mechanize->known_agent_aliases();
@aliases = $mech->known_agent_aliases();

MÉTODOS DE OBTENCIÓN DE PÁGINAS

$mech->get( $uri )

Dada una URL/URI, la obtiene. Devuelve un objeto HTTP::Response. $uri puede ser una cadena de URL bien formada, un objeto URI o un objeto WWW::Mechanize::Link.

Los resultados se almacenan internamente en el objeto agente, pero tú no lo sabes. Simplemente usa los accesores que se enumeran a continuación. Acceder a los internos está obsoleto y sujeto a cambios en el futuro.

get() es una versión sobrecargada y bien comportada del método en LWP::UserAgent. Esto te permite hacer cosas como

$mech->get( $uri, ':content_file' => $filename );

y puedes estar seguro de que los parámetros se filtrarán adecuadamente. Consulta "get" en LWP::UserAgent para más detalles.

NOTA: El archivo en ":content_file" contendrá el contenido sin procesar de la respuesta. Si el contenido de la respuesta está codificado (por ejemplo, codificado en gzip), el archivo también estará codificado. Usa $mech->save_content si necesitas el contenido decodificado.

NOTA: Debido a que ":content_file" hace que el contenido de la página se almacene en un archivo en lugar de en el objeto de respuesta, algunas funciones de Mech que esperan que esté allí no funcionarán como se espera. Úsalo con precaución.

Aquí hay una lista no completa de métodos que no funcionan como se espera con ":content_file": forms() , current_form() , links() , title() , content(...) , text() , todos los métodos de manejo de contenido, todos los métodos de enlaces, todos los métodos de imágenes, todos los métodos de formularios, todos los métodos de campos, save_content(...) , dump_links(...) , dump_images(...) , dump_forms(...) , dump_text(...)

$mech->post( $uri, content => $content )

Envía un POST de $content a $uri. Devuelve un objeto HTTP::Response. $uri puede ser una cadena de URI bien formada, un objeto URI o un objeto WWW::Mechanize::Link.

$mech->put( $uri, content => $content )

Envía un PUT de $content a $uri. Devuelve un objeto HTTP::Response. $uri puede ser una cadena de URI bien formada, un objeto URI o un objeto WWW::Mechanize::Link.

my $res = $mech->put( $uri );
my $res = $mech->put( $uri , $field_name => $value, ... );

$mech->head ($uri )

Realiza una solicitud HEAD a $uri. Devuelve un objeto HTTP::Response. $uri puede ser una cadena de URI bien formada, un objeto URI o un objeto WWW::Mechanize::Link.

$mech->delete ($uri )

Realiza una solicitud DELETE a $uri. Devuelve un objeto HTTP::Response. $uri puede ser una cadena de URI bien formada, un objeto URI o un objeto WWW::Mechanize::Link.

$mech->reload()

Actúa como el botón de recargar en un navegador: repite la solicitud actual. El historial (según el método back()) no se modifica.

Devuelve el objeto HTTP::Response de la recarga, o "undef" si no hay una solicitud actual.

$mech->back()

El equivalente a presionar el botón "atrás" en un navegador. Regresa a la página anterior. No irá más allá de la primera página. (Realmente, ¿qué haría si pudiera?)

Devuelve verdadero si pudo retroceder, o falso si no.

$mech->clear_history()

Esto elimina todas las entradas del historial y devuelve verdadero.

$mech->history_count()

Esto devuelve el número de elementos en el historial del navegador. Este número *incluye* la solicitud realizada más recientemente.

$mech->history($n)

Esto devuelve el *n*-ésimo elemento del historial. El elemento 0 es la solicitud y respuesta más recientes, sobre las cuales actuarían métodos como find_link(). El elemento 1 es el estado al que regresarías si llamaras a back().

El valor máximo útil para $n es "$mech->history_count - 1". Las solicitudes más allá de ese límite devolverán "undef".

Los elementos del historial se devuelven como referencias de hash, con el formato:

{ req => $http_request, res => $http_response }

MÉTODOS DE ESTADO

$mech->success()

Devuelve un booleano que indica si la última solicitud fue exitosa. Si aún no ha habido una operación, devuelve falso.

Esta es una función de conveniencia que envuelve "$mech->res->is_success".

$mech->uri()

Devuelve la URI actual como un objeto URI. Este objeto se convierte en cadena a la URI misma.

$mech->response() / $mech->res()

Devuelven la respuesta actual como un objeto HTTP::Response.

Sinónimo de "$mech->response()".

$mech->status()

Devuelve el código de estado HTTP de la respuesta. Es un número de 3 dígitos como 200 para OK, 404 para no encontrado, etc.

$mech->ct() / $mech->content_type()

Devuelve el tipo de contenido de la respuesta.

$mech->base()

Devuelve la URI base para la respuesta actual

$mech->forms()

Cuando se llama en contexto de lista, devuelve una lista de los formularios encontrados en la última página obtenida. En un contexto escalar, devuelve una referencia a un array con esos formularios. Los formularios devueltos son todos objetos HTML::Form.

$mech->current_form()

Devuelve el formulario actual como un objeto HTML::Form.

$mech->links()

Cuando se llama en un contexto de lista, devuelve una lista de los enlaces encontrados en la última página obtenida. En un contexto escalar, devuelve una referencia a un array con esos enlaces. Cada enlace es un objeto WWW::Mechanize::Link.

$mech->is_html()

Devuelve verdadero/falso sobre si nuestro contenido es HTML, según las cabeceras HTTP.

$mech->title()

Devuelve el contenido de la etiqueta "<TITLE>", tal como lo analiza HTML::HeadParser. Devuelve "undef" si el contenido no es HTML.

$mech->redirects()

Método de conveniencia para obtener las redirecciones de la respuesta HTTP más reciente.

Tenga en cuenta que también puede usar is_redirect para ver si la respuesta más reciente fue una redirección, de la siguiente manera.

$mech->get($url);
do_stuff() if $mech->res->is_redirect;

MÉTODOS DE MANEJO DE CONTENIDO

$mech->content(...)

Devuelve el contenido que el mech utiliza internamente para la última página obtenida. Normalmente, esto es lo mismo que "$mech->response()->decoded_content()", pero esto puede diferir para documentos HTML si "update_html" está sobrecargado (en cuyo caso se devolverá el valor pasado a la implementación de la clase base), y/o se pasan argumentos adicionales con nombre a content():

$mech->content( format => 'text' )
Devuelve una versión solo de texto de la página, con todo el marcado HTML eliminado. Esta función requiere que HTML::TreeBuilder versión 5 o superior esté instalado, o se producirá un error fatal. Esto solo funciona si el contenido es HTML.
$mech->content( base_href => [$base_href|undef] )
Devuelve el documento HTML, modificado para contener un marcado "<base href="$base_href">" en la cabecera. $base_href es "$mech->base()" si no se especifica. Esto es útil para pasar el HTML a, por ejemplo, HTML::Display. Esto solo funciona si el contenido es HTML.
$mech->content( raw => 1 )
Devuelve "$self->response()->content()", es decir, el contenido bruto de la respuesta.
$mech->content( decoded_by_headers => 1 )
Devuelve el contenido después de aplicar todas las cabeceras "Content-Encoding" pero sin manipulación adicional.
$mech->content( charset => $charset )
Devuelve "$self->response()->decoded_content(charset => $charset)" (ver HTTP::Response para más detalles).

Para mantener la compatibilidad hacia atrás, los parámetros adicionales se ignorarán a menos que se especifique ninguno de "raw | decoded_by_headers | charset" y el texto sea HTML, en cuyo caso se activará un error.

Una instancia nueva de WWW::Mechanize devolverá "undef" cuando se llame a "$mech->content()", ya que no hay contenido presente antes de que se haya realizado una solicitud.

$mech->text()

Devuelve el texto del contenido HTML actual. Si el contenido no es HTML, $mech fallará.

El texto se extrae analizando el contenido, y luego el texto extraído se almacena en caché, así que no se preocupe por el rendimiento de llamar a esto repetidamente.

MÉTODOS DE ENLACES

$mech->links()

Enumera todos los enlaces de la página actual. Cada enlace es un objeto WWW::Mechanize::Link. En contexto de lista, devuelve una lista de todos los enlaces. En contexto escalar, devuelve una referencia de array de todos los enlaces.

$mech->follow_link(...)

Sigue un enlace específico en la página. Especifica la coincidencia a encontrar utilizando los mismos parámetros que utiliza find_link().

Aquí hay algunos ejemplos:

  • 3er enlace llamado "download" 
    $mech->follow_link( text => 'download', n => 3 );
  • primer enlace donde la URL contiene "download", sin distinción de mayúsculas y minúsculas: 
    $mech->follow_link( url_regex => qr/download/i );

    o

    $mech->follow_link( url_regex => qr/(?i:download)/ );
  • 3er enlace de la página 
    $mech->follow_link( n => 3 );
  • el enlace con la url 
    $mech->follow_link( url => '/other/page' );

    o

    $mech->follow_link( url => 'http://example.com/page' );

Devuelve el resultado del método "GET" (un objeto HTTP::Response) si se encontró un enlace.

Si la página no tiene enlaces o no se pudo encontrar el enlace especificado, devuelve "undef". Si "autocheck" está habilitado, se lanzará una excepción en su lugar.

$mech->find_link( ... )

Encuentra un enlace en la página actualmente obtenida. Devuelve un objeto WWW::Mechanize::Link que describe el enlace. (Probablemente te interesará más la propiedad url()). Si no logra encontrar un enlace, devuelve "undef".

Puedes tomar la parte de la URL y pasarla al método get(). Si ese es tu plan, podrías usar directamente el método follow_link(), ya que hace el get() por ti automáticamente.

Tenga en cuenta que las etiquetas "<FRAME SRC="...">" se analizan del HTML y se tratan como enlaces, por lo que este método funciona con ellas.

Puede seleccionar qué enlace encontrar pasando uno o más de estos pares clave/valor:

  • "text => 'cadena'," y "text_regex => qr/expresión regular/,"

    "text" compara el texto del enlace con cadena, que debe ser una coincidencia exacta. Para seleccionar un enlace con el texto exactamente "download", use

    $mech->find_link( text => 'download' );

    "text_regex" compara el texto del enlace con expresión regular. Para seleccionar un enlace con texto que contenga "download" en cualquier parte, sin distinción de mayúsculas y minúsculas, use

    $mech->find_link( text_regex => qr/download/i );

    Tenga en cuenta que el texto extraído de los enlaces de la página se recorta. Por ejemplo, "<a> foo </a>" se almacena como 'foo', y la búsqueda de espacios al principio o al final fallará.

  • "url => 'cadena'," y "url_regex => qr/expresión regular/,"

    Compara la URL del enlace con cadena o expresión regular, según corresponda. La URL puede ser una URL relativa, como foo/bar.html, dependiendo de cómo esté codificada en la página.

  • "url_abs => cadena" y "url_abs_regex => expresión regular"

    Compara la URL absoluta del enlace con cadena o expresión regular, según corresponda. La URL será una URL absoluta, incluso si es relativa en la página.

  • "name => cadena" y "name_regex => expresión regular"

    Compara el nombre del enlace con cadena o expresión regular, según corresponda.

  • "rel => cadena" y "rel_regex => expresión regular"

    Compara el rel del enlace con cadena o expresión regular, según corresponda. Esto se puede usar para encontrar hojas de estilo, favicons o enlaces que el autor de la página no quiere que los bots sigan.

  • "id => cadena" y "id_regex => expresión regular"

    Compara el atributo 'id' del enlace con cadena o expresión regular, según corresponda.

  • "class => cadena" y "class_regex => expresión regular"

    Compara el atributo 'class' del enlace con cadena o expresión regular, según corresponda.

  • "tag => cadena" y "tag_regex => expresión regular"

    Compara la etiqueta de la que proviene el enlace con cadena o expresión regular, según corresponda. La "tag_regex" es probablemente más útil para verificar más de una etiqueta, como en:

    $mech->find_link( tag_regex => qr/^(a|frame)$/ );

    Las etiquetas y atributos que se miran se definen a continuación.

Si no se especifica "n", se establece por defecto en 1. Por lo tanto, si no especifica ningún parámetro, este método por defecto encontrará el primer enlace de la página.

Tenga en cuenta que puede especificar varios parámetros de texto o URL, que se combinarán con un operador Y (AND). Por ejemplo, para encontrar el primer enlace con el texto "News" y con "cnn.com"

" en la URL, usa:

$mech->find_link( text => 'News', url_regex => qr/cnn\.com/ );

El valor de retorno es una referencia a un array que contiene un objeto WWW::Mechanize::Link por cada enlace en "$self->content".

Los enlaces provienen de lo siguiente:

"<a href=...>"
"<area href=...>"
"<frame src=...>"
"<iframe src=...>"
"<link href=...>"
"<meta content=...>"

$mech->find_all_links( ... )

Devuelve todos los enlaces de la página actual que coinciden con los criterios. El método para especificar los criterios de enlace es el mismo que en find_link(). Cada uno de los enlaces devueltos es un objeto WWW::Mechanize::Link.

En contexto de lista, find_all_links() devuelve una lista de los enlaces. De lo contrario, devuelve una referencia a la lista de enlaces.

find_all_links() sin parámetros devuelve todos los enlaces de la página.

$mech->find_all_inputs( ... criterios ... )

find_all_inputs() devuelve un array de todos los controles de entrada en el formulario actual cuyas propiedades coinciden con todas las expresiones regulares pasadas. Los controles devueltos descienden de HTML::Form::Input. Ver "INPUTS" en HTML::Form para detalles.

Si no se pasan criterios, se devolverán todas las entradas.

Si no hay una página actual, no hay un formulario en la página actual, o no hay controles de envío en el formulario actual, el retorno será un array vacío.

Puedes usar una expresión regular o una cadena literal:

# obtener todos los controles textarea cuyos nombres comiencen con "customer"
my @customer_text_inputs = $mech->find_all_inputs(
    type       => 'textarea',
    name_regex => qr/^customer/,
);
# obtener todos los controles de texto o textarea llamados "customer"
my @customer_text_inputs = $mech->find_all_inputs(
    type_regex => qr/^(text|textarea)$/,
    name       => 'customer',
);

$mech->find_all_submits( ... criterios ... )

MÉTODOS DE IMAGEN

$mech->images

Lista todas las imágenes en la página actual. Cada imagen es un objeto WWW::Mechanize::Image. En contexto de lista, devuelve una lista de todas las imágenes. En contexto escalar, devuelve una referencia a un array de todas las imágenes.

$mech->find_image()

Encuentra una imagen en la página actual. Devuelve un objeto WWW::Mechanize::Image que describe la imagen. Si no logra encontrar una imagen, devuelve "undef".

Puedes seleccionar qué imagen encontrar pasando uno o más de los siguientes pares clave/valor:

  • "alt => 'cadena'" y "alt_regex => qr/regex/"

    "alt" compara el atributo ALT de la imagen con cadena, que debe ser una coincidencia exacta. Para seleccionar una imagen con una etiqueta ALT que sea exactamente "download", usa

    $mech->find_image( alt => 'download' );

    "alt_regex" compara el atributo ALT de la imagen con una expresión regular. Para seleccionar una imagen con un atributo ALT que contenga "download" en cualquier parte, sin importar mayúsculas o minúsculas, usa

    $mech->find_image( alt_regex => qr/download/i );
  • "url => 'cadena'" y "url_regex => qr/regex/"

    Compara la URL de la imagen con cadena o regex, según corresponda. La URL puede ser una URL relativa, como foo/bar.html, dependiendo de cómo esté codificada en la página.

  • "url_abs => cadena" y "url_abs_regex => regex"

    Compara la URL absoluta de la imagen con cadena o regex, según corresponda. La URL será una URL absoluta, incluso si es relativa en la página.

  • "tag => cadena" y "tag_regex => regex"

    Compara la etiqueta de la que proviene la imagen con cadena o regex, según corresponda. El "tag_regex" es probablemente más útil para verificar más de una etiqueta, como en:

    $mech->find_image( tag_regex => qr/^(img|input)$/ );

    Las etiquetas admitidas son "<img>" y "<input>".

  • "id => cadena" y "id_regex => regex"

    "id" compara el atributo id de la imagen con cadena, que debe ser una coincidencia exacta. Para seleccionar una imagen con el id exacto "download-image", usa

    $mech->find_image( id => 'download-image' );

    "id_regex" compara el atributo id de la imagen con una expresión regular. Para seleccionar la primera imagen con un id que contenga "download" en cualquier parte, usa

    $mech->find_image( id_regex => qr/download/ );
  • "classs => cadena" y "class_regex => regex"

    "class" compara el atributo class de la imagen con cadena, que debe ser una coincidencia exacta. Para seleccionar una imagen con la clase exacta "img-fuid", usa

    $mech->find_image( class => 'img-fluid' );

    Para seleccionar una imagen con el atributo class "rounded float-left", usa

    $mech->find_image( class => 'rounded float-left' );

    Ten en cuenta que las clases deben coincidir como una cadena completa, en el orden exacto en que aparecen en el código fuente del sitio web.

    "class_regex" compara el atributo class de la imagen con una expresión regular. Úsala si deseas un nombre de clase parcial, o si una imagen tiene varias clases, pero solo te importa una.

    Para seleccionar la primera imagen con la clase "rounded", donde hay varias imágenes que también pueden tener la clase "float-left" o "float-right", usa

    $mech->find_image( class_regex => qr/\brounded\b/ );

    Seleccionar una imagen con varias clases donde no te importa el orden en que aparecen en el código fuente del sitio web no es compatible actualmente.

Si no se especifica "n", por defecto es 1. Por lo tanto, si no especificas ningún parámetro, este método por defecto buscará la primera imagen en la página.

Ten en cuenta que puedes especificar varios parámetros ALT o URL, que se combinarán lógicamente con AND. Por ejemplo, para encontrar la primera imagen con el texto ALT "News" y con "cnn.com" en la URL, usa:

$mech->find_image( image => 'News', url_regex => qr/cnn\.com/ );

El valor de retorno es una referencia a un array que contiene un objeto WWW::Mechanize::Image por cada imagen en "$mech->content".

$mech->find_all_images( ... )

Devuelve todas las imágenes de la página actual que coinciden con los criterios. El método para especificar los criterios de imagen es el mismo que en find_image(). Cada una de las imágenes devueltas es un objeto WWW::Mechanize::Image.

En contexto de lista, find_all_images() devuelve una lista de las imágenes. De lo contrario, devuelve una referencia a la lista de imágenes.

find_all_images() sin parámetros devuelve todas las imágenes de la página.

MÉTODOS DE FORMULARIO

Estos métodos te permiten trabajar con los formularios de una página. La idea es elegir un formulario con el que trabajarás más tarde usando los métodos de campo a continuación.

$mech->forms

Lista todos los formularios de la página actual. Cada formulario es un objeto HTML::Form. En contexto de lista, devuelve una lista de todos los formularios. En contexto escalar, devuelve una referencia a un array de todos los formularios.

$mech->form_number($number)

Selecciona el número-ésimo formulario de la página como el objetivo para llamadas posteriores a field() y click(). También devuelve el formulario que fue seleccionado.

Si se encuentra, el formulario se devuelve como un objeto HTML::Form y se establece internamente para su uso posterior con los métodos de formulario de Mech, como field() y click(). Cuando se llama en un contexto de lista, el número del formulario encontrado también se devuelve como un segundo valor.

Emite una advertencia y devuelve "undef" si no se encuentra ningún formulario.

El primer formulario es el número 1, no cero.

$mech->form_action( $action )

Selecciona un formulario por acción, usando una expresión regular que contiene $action. Si hay más de un formulario en la página que coincide con esa acción, se utiliza el primero y se genera una advertencia.

Si se encuentra, el formulario se devuelve como un objeto HTML::Form y se establece internamente para su uso posterior con los métodos de formulario de Mech, como field() y click().

Devuelve "undef" si no se encuentra ningún formulario.

$mech->form_name( $name [, \%args ] )

Selecciona un formulario por nombre.

Por defecto, el fi

formulario devuelto. my $form = $mech->form_name("order_form"); Si desea la segunda, tercera o enésima coincidencia, pase una referencia de hash de argumentos opcional como parámetro final con una clave "n" para elegir qué instancia desea. La numeración comienza en 1. my $third_product_form = $mech->form_name("buy_now", { n => 3 }); Si el parámetro "n" no se pasa, y hay más de un formulario en la página con ese nombre, entonces se utiliza el primero y se genera una advertencia. $mech->form_id( $id [, \%args ] )

Selecciona un formulario por ID.

Por defecto, se devolverá el primer formulario que tenga este ID.

my $form = $mech->form_id("order_form");

La numeración comienza en 1.

my $third_product_form = $mech->form_id("buy_now", { n => 3 });

Si el parámetro "n" no se pasa, y hay más de un formulario en la página con ese ID, entonces se utiliza el primero y se genera una advertencia.

$mech->all_forms_with_fields( @fields )

Selecciona un formulario pasando una lista de nombres de campos que debe contener. Se devuelven todos los formularios coincidentes (quizás ninguno) como una lista de objetos HTML::Form.

$mech->form_with_fields( @fields, [ \%args ] )

MÉTODOS DE CAMPO

Estos métodos le permiten establecer los valores de los campos en un formulario determinado.

$mech->field( $name, $value, $number )

$mech->field( $name, \@values, $number )

$mech->field( $name, \@file_upload_values, $number )

Dado el nombre de un campo, establece su valor al valor especificado. Esto se aplica al formulario actual (establecido por el método form_name() o form_number() o por defecto al primer formulario de la página).

Si el campo es de tipo "file", su valor debe ser una referencia de array. Ejemplo:

$mech->field( $file_input, ['/tmp/file.txt'] );

Ejemplos de valores para entradas de tipo "file", seguidos de una explicación de lo que significa cada índice:

# 0: ruta del archivo      1: nombre del archivo    3: encabezados
['/tmp/file.txt']
['/tmp/file.txt', 'filename.txt']
['/tmp/file.txt', 'filename.txt', @headers]
['/tmp/file.txt', 'filename.txt', Content => 'some content']
[undef,           'filename.txt', Content => 'content here']

El índice 0 es la ruta del archivo que se leerá del disco. El índice 1 es el nombre del archivo que se utilizará en el cuerpo de la solicitud HTTP; si no se proporciona, se utiliza la ruta del archivo (índice 0) en su lugar. Si se utiliza Content => 'content here' como se muestra, entonces la ruta del archivo se ignorará.

El parámetro opcional $number se utiliza para distinguir entre dos campos con el mismo nombre. Los campos se numeran a partir de 1.

$mech->select($name, $new_or_additional_single_value)

$mech->select($name, $new_or_additional_single_value, $number)

$mech->select($name, \%new_single_value_by_number)

$mech->select($name, \@new_list_of_values)

$mech->select($name, \%new_list_of_values_by_number)

Dado el nombre de un campo "select", establece su valor al valor especificado.

# seleccionar 'foo'
$mech->select($name, 'foo');

El parámetro opcional $number se utiliza para distinguir entre dos campos con el mismo nombre. Los campos se numeran a partir de 1. Tenga en cuenta que esto solo funciona para seleccionar valores simples, no para seleccionar varios valores a la vez.

# seleccionar el segundo campo con el nombre 'foo'
$mech->select($name, 'foo', 2);

Si el campo no es "<select multiple>" y el $value es una referencia de array, solo se establecerá el **primer** valor. [Nota: hasta la versión 1.05_03, la documentación afirmaba que solo se establecería el último valor, pero esto era incorrecto.]

# seleccionar 'bar'
$mech->select($name, ['bar', 'ignored', 'ignored']);

Pasar $value como una referencia de hash con una clave "n" selecciona un elemento por número.

# seleccionar el tercer valor
$mech->select($name, {n => 3});

La numeración comienza en 1. Esto se aplica al formulario actual.

Si tiene un campo con "<select multiple>" y pasa un solo $value, entonces $value se agregará a la lista de campos seleccionados, sin borrar los demás.

# agregar 'bar' a la lista de valores seleccionados
$mech->select($name, 'bar');

Sin embargo, si pasa una referencia de array, todos los valores previamente seleccionados se borrarán y se reemplazarán con todos los valores dentro de la referencia de array.

# reemplazar la selección con 'foo' y 'bar'
$mech->select($name, ['foo', 'bar']);

Esto también funciona al seleccionar por números, en cuyo caso el valor de la clave "n" será una referencia de array de los números de valor con los que desea reemplazar la selección.

# reemplazar la selección con el segundo y cuarto elemento
$mech->select($name, {n => [2, 4]});

Para agregar varios valores adicionales a la lista de campos seleccionados sin borrar, llame a "select" en la forma simple de $value con cada valor individual en un bucle.

# agregar todos los valores del array a la selección
$mech->select($name, $_) for @additional_values;

Devuelve verdadero si el valor se establece correctamente. En caso de fallo, devuelve falso y llama a "$self->warn()" con un mensaje de error.

$mech->set_fields( $name => $value ... )

$mech->set_fields( $name => \@value_and_instance_number )

$mech->set_fields( $name => \$value_instance_number )

$mech->set_fields( $name => \@file_upload )

Este método establece varios campos del formulario actual. Toma una lista de pares de nombre y valor de campo. Si hay más de un campo con el mismo nombre, se establece el primero que se encuentra. Si desea seleccionar cuál de los campos duplicados establecer, use un valor que sea un array anónimo que tenga el valor del campo y su número como los 2 elementos.

# establecer el segundo campo $name a 'foo'
$mech->set_fields( $name => [ 'foo', 2 ] );

Añadimos una cabecera "Referer", así como una cabecera para indicar que podemos aceptar contenido codificado con gzip, si Compress::Zlib está instalado.

$mech->_make_request()

Método de conveniencia para facilitar que las subclases como WWW::Mechanize::Cached intercepten la solicitud.

$mech->_reset_page()

Restablece los campos internos que rastrean el contenido analizado de la página.

$mech->_extract_links()

Extrae enlaces del contenido de una página web y rellena la propiedad "{links}" con objetos WWW::Mechanize::Link.

$mech->_push_page_stack()

El agente mantiene una pila de páginas visitadas, que puede descargar cuando necesita retroceder (BACK) y así sucesivamente.

La página actual debe insertarse en la pila antes de obtener una nueva página, y la pila debe descargarse cuando ocurre BACK.

Ninguno de estos métodos toma argumentos, solo operan en el objeto $mech.

warn( @mensajes )

Método de advertencia centralizado, para diagnósticos y problemas no fatales. Por defecto, llama a "CORE::warn", pero puede ser anulado estableciendo "onwarn" en el constructor.

die( @mensajes )

Método de error centralizado. Por defecto, llama a "CORE::die", pero puede ser anulado estableciendo "onerror" en el constructor.

MEJORES PRÁCTICAS

La configuración predeterminada puede ponerlo en marcha rápidamente, pero hay ajustes que puede cambiar para facilitarle la vida.

autocheck
"autocheck" puede ahorrarle la sobrecarga de verificar los códigos de estado de éxito. Puede que se quede corto a medida que sus necesidades se vuelvan más sofisticadas, pero es una opción segura para empezar. 
my $agent = WWW::Mechanize->new( autocheck => 1 );
cookie_jar
Se recomienda instalar Mozilla::PublicSuffix y usar HTTP::CookieJar::LWP como su gestor de cookies. HTTP::CookieJar::LWP proporciona un mejor modelo de seguridad que coincide con el de los navegadores web actuales cuando se instala Mozilla::PublicSuffix. 
use HTTP::CookieJar::LWP ();
my $jar = HTTP::CookieJar::LWP->new;
my $agent = WWW::Mechanize->new( cookie_jar => $jar );
protocols_allowed
Esta opción se hereda directamente de LWP::UserAgent. Puede usarse para permitir protocolos arbitrarios. 
my $agent = WWW::Mechanize->new(
    protocols_allowed => [ 'http', 'https' ]
);

Esto evitará que siga inadvertidamente URL como "file:///etc/passwd".

protocols_forbidden
Esta opción también se hereda directamente de LWP::UserAgent. Puede usarse para denegar protocolos arbitrarios. 
my $agent = WWW::Mechanize->new(
    protocols_forbidden => [ 'file', 'mailto', 'ssh', ]
);

Esto evitará que siga inadvertidamente URL como "file:///etc/passwd".

strict_forms
Considere activar la opción "strict_forms" al crear un nuevo Mech. Esto realizará una útil comprobación de cordura en los campos del formulario cada vez que envíe uno, lo que puede ahorrarle mucho tiempo de depuración. 
my $agent = WWW::Mechanize->new( strict_forms => 1 );

Si no desea tener esta opción de forma global, aún puede activarla para formularios individuales.

$agent->submit_form( fields => { foo => 'bar' } , strict_forms => 1 );
