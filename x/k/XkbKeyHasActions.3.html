NOMBRE

XkbKeyHasActions - Determina si la tecla correspondiente a keycode tiene alguna acción asociada.

SINOPSIS

int XkbKeyHasActions (XkbDescPtr xkb, KeyCode keycode);

ARGUMENTOS

xkb
Descripción Xkb de interés.
keycode
Keycode de interés.

DESCRIPCIÓN

Una acción de tecla define el efecto que las pulsaciones y liberaciones de teclas tienen sobre el estado interno del servidor. Por ejemplo, la acción de tecla esperada asociada con la pulsación de la tecla Shift es establecer el modificador Shift. Hay cero o una acción de tecla asociada con cada keysym enlazado a cada tecla.

Así como la lista completa de símbolos de tecla para la asignación del teclado se mantiene en el campo syms del mapa del cliente, la lista completa de acciones de tecla para la asignación del teclado se mantiene en el array acts del mapa del servidor. El tamaño total de acts se especifica por size_acts, y el número de entradas se especifica por num_acts.

El array key_acts, indexado por keycode, describe las acciones asociadas con una tecla. El array key_acts tiene min_key_code entradas no utilizadas al principio para permitir la indexación directa utilizando un keycode. Si una entrada de key_acts es cero, significa que la tecla no tiene ninguna acción asociada con ella. Si una entrada no es cero, la entrada representa un índice en el campo acts del mapa del servidor, de manera similar a como el campo offset de una estructura KeySymMapRec es un índice en el campo syms del mapa del cliente.

La razón por la que el campo acts es una lista lineal de XkbActions es para reducir el consumo de memoria asociado con un keymap. Dado que Xkb permite que teclas individuales tengan múltiples niveles de shift y un número diferente de grupos por tecla, una única matriz bidimensional de KeySyms sería potencialmente muy grande y dispersa. En su lugar, Xkb proporciona una pequeña matriz bidimensional de XkbActions para cada tecla. Para almacenar todas estas matrices individuales, Xkb concatena cada matriz en el campo acts del mapa del servidor.

Las estructuras de acción de tecla consisten solo en campos de tipo char o unsigned char. Esto se hace para optimizar la transferencia de datos cuando el servidor envía bytes a través de la red. Si los campos son algo distinto de bytes, el servidor tiene que revisar todas las acciones y cambiar el orden de los campos que no sean de bytes. Dado que consisten únicamente en bytes, simplemente puede copiarlos.

XkbKeyHasActions devuelve True si la tecla correspondiente a keycode tiene alguna acción asociada; de lo contrario, devuelve False.

VALORES DE RETORNO

True
La función XkbKeyHasActions devolverá True si la tecla correspondiente a keycode tiene alguna acción asociada.
False
La función XkbKeyHasActions devolverá False si la tecla correspondiente a keycode no tiene ninguna acción asociada.

ESTRUCTURAS

La estructura KeySymMapRec se define de la siguiente manera:

    #define XkbNumKbdGroups             4
    #define XkbMaxKbdGroup              (XkbNumKbdGroups-1)
    typedef struct {                    /* map to keysyms for a single keycode */
        unsigned char       kt_index[XkbNumKbdGroups];  /* key type index for each group */
        unsigned char       group_info; /* # of groups and out of range group handling */
        unsigned char       width;      /* max # of shift levels for key */
        unsigned short      offset;     /* index to keysym table in syms array */
} XkbSymMapRec, *XkbSymMapPtr;
