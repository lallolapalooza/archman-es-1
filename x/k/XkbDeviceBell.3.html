XkbDeviceBell(3) FUNCIONES XKB XkbDeviceBell(3)

NOMBRE

XkbDeviceBell - Hace sonar la campana en un dispositivo de extensión de entrada X o en el teclado predeterminado

SINOPSIS

Bool XkbDeviceBell (Display *display, Window window, unsigned int device_spec, unsigned int bell_class, unsigned int bell_id, int percent, Atom name);

ARGUMENTOS

display
conexión al servidor X
window
ventana para la que se genera la campana, o None
device_spec
ID del dispositivo, o XkbUseCoreKbd
bell_class
clase de campana de la extensión de entrada X de la campana a hacer sonar
bell_id
ID de campana de la extensión de entrada X de la campana a hacer sonar
percent
volumen de la campana, de -100 a 100 inclusive
name
un nombre para la campana, o NULL

DESCRIPCIÓN

El protocolo central de X solo permite a las aplicaciones hacer sonar explícitamente la campana del sistema con una duración, tono y volumen determinados. Xkb extiende esta capacidad al permitir que los clientes asocien nombres simbólicos a las campanas, deshabiliten las campanas audibles y reciban un evento cada vez que suene la campana del teclado. Para los propósitos de este documento, la campana audible se define como la campana del sistema, o la campana predeterminada del teclado, en contraposición a cualquier otro sonido audible generado en otra parte del sistema. Puede solicitar recibir eventos XkbBellNotify cuando cualquier cliente haga sonar cualquiera de los siguientes:

  • La campana predeterminada
  • Cualquier campana en un dispositivo de entrada que pueda especificarse mediante un par bell_class y bell_id
  • Cualquier campana especificada solo por un nombre arbitrario. (Esto es, desde el punto de vista del servidor, simplemente un nombre, y no está conectado a ningún dispositivo físico generador de sonido. Alguna aplicación cliente debe generar el sonido, o la retroalimentación visual, si la hay, que se asocia con el nombre).

    También puede solicitar recibir eventos XkbBellNotify cuando el servidor haga sonar la campana predeterminada o si algún cliente ha solicitado eventos solo (sin que suene la campana) para cualquiera de los tipos de campana enumerados anteriormente.

    Puede deshabilitar las campanas audibles de forma global. Por ejemplo, un cliente que reemplace la campana del teclado con alguna otra señal audible podría querer desactivar el control AudibleBell para evitar que el servidor también genere un sonido y evitar la cacofonía. Si deshabilita las campanas audibles y solicita recibir eventos XkbBellNotify, puede generar una retroalimentación diferente a la de la campana predeterminada.

    Sin embargo, puede anular el control AudibleBell llamando a una de las funciones que fuerzan el sonar de una campana a pesar de la configuración del control AudibleBell - XkbForceDeviceBell o XkbForceBell. En este caso, el servidor no genera un evento de campana.

    Al igual que algunos teclados pueden producir clics para indicar cuándo se presiona o repite una tecla, Xkb puede proporcionar retroalimentación para los controles utilizando códigos de pitido especiales. El control AccessXFeedback se utiliza para configurar los tipos específicos de operaciones que generan retroalimentación.

    Nombres de campana

    Puede asociar un nombre a un acto de hacer sonar una campana convirtiendo el nombre en un Atom y luego usando este nombre al llamar a las funciones enumeradas en este capítulo. Si se genera un evento como resultado, el nombre se pasa a todos los demás clientes interesados en recibir eventos XkbBellNotify. Tenga en cuenta que estos son nombres arbitrarios y que no hay ninguna vinculación con ningún sonido. Cualquier sonido u otros efectos (como campanas visuales en la pantalla) deben ser generados por una aplicación cliente al recibir el evento de campana que contiene el nombre. No hay un nombre predeterminado para la campana predeterminada del teclado. El servidor genera algunas campanas predefinidas para los controles AccessX. Estas campanas con nombre se muestran en la Tabla 1; el nombre se incluye en cualquier evento de campana enviado a los clientes que hayan solicitado recibir eventos XkbBellNotify.

    Campanas Audibles

    Usando Xkb, puede generar eventos de campana que no necesariamente hagan sonar la campana del sistema. Esto es útil si necesita usar un servidor de audio en lugar del pitido del sistema. Por ejemplo, cuando un cliente de audio se inicia, podría deshabilitar la campana audible (la campana del sistema) y luego escuchar los eventos XkbBellNotify. Cuando recibe un evento XkbBellNotify, el cliente de audio podría enviar una solicitud a un servidor de audio para reproducir un sonido.

    Puede controlar la función de campanas audibles pasando XkbAudibleBellMask a XkbChangeEnabledControls. Si activa XkbAudibleBellMask, el servidor hace sonar la campana del sistema cuando ocurre un evento de campana. Esto es lo predeterminado. Si desactiva XkbAudibleBellMask y ocurre un evento de campana, el servidor no hace sonar la campana del sistema a menos que llame a XkbForceDeviceBell o XkbForceBell.

    Las campanas audibles también forman parte de los controles de reinicio automático por cliente.

    Funciones de Campana

    Utilice las funciones descritas en esta sección para hacer sonar campanas y generar eventos de campana.

    La extensión de entrada tiene dos tipos de retroalimentación que pueden generar campanas: retroalimentación de campana y retroalimentación de teclado. Algunas de las funciones de esta sección tienen parámetros bell_class y bell_id; configúrelos de la siguiente manera: Establezca bell_class en BellFeedbackClass o KbdFeedbackClass. Un dispositivo puede tener más de una retroalimentación de cada tipo; establezca bell_id en la retroalimentación de campana particular del tipo bell_class.

XkbDeviceBell(3) — libX11 1.8.12

NAME

XkbDeviceBell - ring a device-specific bell

SYNOPSIS

#include <X11/extensions/XKB.h>
Bool XkbDeviceBell(
    Display *display,
    int     device_spec,
    int     bell_class,
    int     bell_id,
    int     percent,
    Atom    name
);

ARGUMENTS

o display
Specifies the connection to the X server.
o device_spec
Specifies the device for which the bell is to be rung. This may be one of the physical device identifiers returned by XkbGetKbdDeviceIds or XkbUseCoreKbd or XkbUseCorePtr.
o bell_class
Specifies the class of the bell feedback to be activated. Valid values are XkbAudibleBellClass, XkbKbdFeedbackClass, and XkbPointerFeedbackClass.
o bell_id
Specifies the identifier for the bell within the specified bell_class. For XkbAudibleBellClass, this is always XkbAudibleBell. For XkbKbdFeedbackClass, it is an index into the keyboard bell list. For XkbPointerFeedbackClass, it is an index into the pointer feedback list.
o percent
Specifies the volume for the bell. A value of 0 indicates the minimum volume, and 100 indicates the maximum volume. A negative value means use the default volume.
o name
An atom identifying the client requesting the bell. This is used internally by the Xkb extension and is used to correlate bell events with the clients that requested them.

DESCRIPTION

The Xkb extension provides several functions for controlling and monitoring bell and keyboard feedback. For each bell type, there is a corresponding function to request that the bell be rung.

The following table summarizes the functions for ringing bells:

XkbAudibleBell
Rings the audible bell on the core keyboard device.
XkbPerDeviceBell
Rings the audible bell on the specified device.
XkbBell
Rings the audible bell on the specified device, allowing explicit specification of bell parameters.
XkbForceDeviceBell
Rings the audible bell on the specified device, bypassing any event masking.
XkbForceBell
Rings the audible bell on the core keyboard device, bypassing any event masking.

The following table summarizes the functions for controlling bell feedback:

Function Controls XkbAudibleBell XkbPerDeviceBell
XkbBell On or Off Yes Yes
XkbBellEvent On or Off No Yes
XkbDeviceForceBell On or Off Yes No
XkbForceBell On or Off Yes No

Set percent to be the volume relative to the base volume for the keyboard as described for .I XBell.

Note that bell_class and bell_id indicate the bell to physically ring. name is simply an arbitrary moniker for the client application's use.

To determine the current feedback settings of an extension input device, use XGetFeedbackControl. See the X input extension documentation for more information on XGetFeedbackControl and related data structures.

If a compatible keyboard extension is not present in the X server, XkbDeviceBell immediately returns False. Otherwise, XkbDeviceBell rings the bell as specified for the display and keyboard device and returns True. If you have disabled the audible bell, the server does not ring the system bell, although it does generate a XkbBellNotify event.

You can call XkbDeviceBell without first initializing the keyboard extension.

STRUCTURES

Xkb generates XkbBellNotify events for all bells except for those resulting from calls to XkbForceDeviceBell and XkbForceBell. To receive XkbBellNotify events under all possible conditions, pass XkbBellNotifyMask in both the bits_to_change and values_for_bits parameters to XkbSelectEvents.

The XkbBellNotify event has no event details. It is either selected or it is not. However, you can call XkbSelectEventDetails using XkbBellNotify as the event_type and specifying XkbAllBellEventsMask in bits_to_change and values_for_bits. This has the same effect as a call to XkbSelectEvents.

The structure for the XkbBellNotify event type contains:

   typedef struct _XkbBellNotify {
       int            type;        /* Xkb extension base event code */
       unsigned long  serial;      /* X server serial number for event */
       Bool           send_event;  /* True => synthetically generated */
       Display *      display;     /* server connection where event generated */
       Time           time;        /* server time when event generated */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* Xkb device ID, will not be XkbUseCoreKbd */
       int            percent;     /* requested volume as % of max */
       int            pitch;       /* requested pitch in Hz */
       int            duration;    /* requested duration in microseconds */
       unsigned int   bell_class;  /* X input extension feedback class */
       unsigned int   bell_id;     /* X input extension feedback ID */
       Atom           name;        /* "name" of requested bell */
       Window         window;      /* window associated with event */
       Bool           event_only;  /* False -> the server did not produce a beep */
   } XkbBellNotifyEvent;
If your application needs to generate visual bell feedback on the screen when it receives a bell event, use the window ID in the XkbBellNotifyEvent, if present.
