XkbGetKeyboardByName(3) FUNCIONES XKB XkbGetKeyboardByName(3)

NOMBRE

XkbGetKeyboardByName - Construir una nueva descripción de teclado a partir de un conjunto de componentes con nombre, y opcionalmente hacer que el servidor utilice la descripción resultante para reemplazar una activa

SINOPSIS

XkbDescPtr XkbGetKeyboardByName (Display *dpy, unsigned int device_spec, XkbComponentNamesPtr names, unsigned int want, unsigned int need, Bool load);

ARGUMENTOS

dpy
conexión al servidor X
device_spec
ID del dispositivo, o XkbUseCoreKbd
names
nombres de los componentes a obtener
want
estructuras deseadas en el registro devuelto
need
estructuras obligatorias en el registro devuelto
load
True => cargar en device_spec

DESCRIPCIÓN

Un cliente puede solicitar que el servidor obtenga uno o más componentes de su base de datos y utilice esos componentes para construir una nueva descripción de teclado del servidor. La nueva descripción del teclado puede construirse desde cero, o puede construirse comenzando con la descripción del teclado actual para un dispositivo particular. Una vez que la descripción del teclado está construida, toda o parte de ella puede ser devuelta al cliente. Las partes devueltas al cliente no necesitan incluir todas las partes utilizadas para construir la descripción. En el momento en que solicita al servidor que construya una nueva descripción de teclado, un cliente también puede solicitar que el servidor utilice la nueva descripción internamente para reemplazar la descripción de teclado actual para un dispositivo específico, en cuyo caso el comportamiento del dispositivo cambia en consecuencia.

Para construir una nueva descripción de teclado a partir de un conjunto de componentes con nombre, y opcionalmente hacer que el servidor utilice la descripción resultante para reemplazar una activa, utilice XkbGetKeyboardByName.

names contiene un conjunto de expresiones que describen los componentes del teclado que el servidor debe utilizar para construir la nueva descripción del teclado. want y need son campos de bits que describen las partes de la descripción del teclado resultante que deben estar presentes en el XkbDescRec devuelto.

Los campos individuales en names son expresiones de componentes compuestas por nombres de componentes de teclado (sin comodines como se puede usar en XkbListComponents), el nombre especial del componente símbolo `%', y los caracteres operadores especiales `+' y `|'. Una expresión de componente se analiza de izquierda a derecha, de la siguiente manera:

  • El nombre especial del componente "computed" puede usarse en expresiones de componentes de keycodes y se refiere a un componente que consiste en un conjunto de keycodes calculados automáticamente por el servidor según sea necesario.
  • El nombre especial del componente "canonical" puede usarse en expresiones de componentes de tipos y se refiere a un componente parcial que define los cuatro tipos de teclas estándar: ALPHABETIC, ONE_LEVEL, TWO_LEVEL, y KEYPAD.
  • El nombre especial del componente `%' se refiere a la descripción del teclado para el dispositivo especificado en device_spec o el componente de nombres del keymap. Si se especifica un componente de nombres del keymap que no comienza con `+' o `|' y no contiene `%', entonces `%' se refiere a la descripción generada por el componente de nombres del keymap. De lo contrario, se refiere a la descripción del teclado para device_spec.
  • El operador `+' especifica que el siguiente componente debe anular la descripción actualmente ensamblada; cualquier definición que esté presente en ambos componentes se toma del segundo.
  • El operador `|' especifica que el siguiente componente especificado debe aumentar la descripción actualmente ensamblada; cualquier definición que esté presente en ambos componentes se toma del primero.
  • Si la expresión del componente comienza con un operador, se implica un `%' inicial.
  • Si aparecen caracteres desconocidos o ilegales en cualquier lugar de la expresión, toda la expresión es inválida y se ignora.

    Por ejemplo, si names->symbols contuviera la expresión " +de ", especifica que el miembro predeterminado de la clase de símbolos "de" debe aplicarse al mapeo de teclado actual, anulando cualquier definición existente (también podría escribirse " +de(default) ").

    Aquí hay un ejemplo un poco más complejo: la expresión "acme(ascii)+de(basic)|iso9995-3" construye un mapeo alemán (de) para el teclado ASCII proporcionado por el proveedor "acme". La nueva definición comienza con los símbolos para el teclado ASCII de Acme (acme(ascii)), los anula con definiciones para el teclado alemán básico (de(basic)), y luego aplica las definiciones del teclado predeterminado iso9995-3 (iso9995-3) a cualquier tecla o grupo de teclas no definido (la parte tres del estándar iso9995 define un conjunto común de enlaces para el grupo secundario, pero permite que los diseños nacionales anulen esas definiciones cuando sea necesario).

    NOTA La interpretación de los componentes de expresión anteriores (acme, ascii, de, basic, iso9995-3) no está definida por Xkb; solo las operaciones y su ordenación lo están.

    Tenga en cuenta que la presencia de un componente de nombres de keymap que no contiene `%` (explícito o implícito por el hecho de que una expresión comience con un operador) indica una descripción que es independiente de la descripción del teclado para el dispositivo especificado en device_spec. Lo mismo ocurre con las solicitudes en las que el componente de nombres del keymap está vacío y los otros cinco componentes de nombres contienen expresiones vacías de referencias a `%'. Las solicitudes de esta forma le permiten tratar con definiciones de teclado independientes de cualquier dispositivo real.

    El servidor analiza todos los campos no NULL en names y los utiliza para construir una descripción del teclado. Sin embargo, antes de analizar las expresiones en names, el servidor realiza una operación OR bit a bit de los bits en want y need y examina el resultado en relación con las expresiones en names. La Tabla 1 identifica los componentes que se requieren para cada uno de los bits posibles en want o need. Si un componente requerido no se ha especificado en la estructura names (el campo correspondiente es NULL), el servidor sustituye la expresión ""%"", lo que resulta en que los valores del componente se tomen de device_spec. Además, si load es True, el servidor modifica names si es necesario (de nuevo utilizando una entrada "%") para garantizar que todos los siguientes campos no sean NULL: types, keycodes, symbols, y compat.

XkbGetKeyboardByName(3) — Xorg Manual
Xorg Manual

NAME

XkbGetKeyboardByName — build a new keyboard description from the server database

SYNOPSIS

#include <X11/Xlib.h>
#include <X11/XKBlib.h>
XkbDescPtr XkbGetKeyboardByName (
    Display *dpy,
    const char *deviceName,
    const char *type,
    unsigned int need,
    unsigned int want,
    Bool load
);

The constants need and want are bitmasks composed of the following values:

XkbGBN_TypesMask
XkbGBN_ClientSymbolsMask
XkbGBN_ServerSymbolsMask
XkbGBN_CompatMapMask
XkbGBN_GeometryMask
XkbGBN_KeyNamesMask
XkbGBN_IndicatorMapMask
XkbAllComponentsMask
corresponds to all components

ARGUMENTS

dpy
Specifies a connection to the X server.
deviceName
If non-NULL, specifies the name of the keyboard to be built. deviceName can be a keyboard name, a device name, or a file name. If deviceName is NULL, Xkb determines the keyboard to be built based on the current keyboard description for the specified device_spec (see below).
type
If non-NULL, specifies the type of keyboard description to be built. type can be the name of a symbolic keyboard type (e.g. “PC” or “Mac”) or the name of a file containing a keyboard description. If type is NULL, Xkb determines the type of the keyboard based on the current keyboard description for the specified device_spec.
need
A bitmask specifying which components Xkb must be able to resolve from the server database. If any of the required components cannot be resolved, XkbGetKeyboardByName returns NULL.
want
A bitmask specifying which components Xkb should attempt to resolve from the server database, but that are not mandatory. If Xkb is unable to resolve any of these components, XkbGetKeyboardByName still succeeds.
load
If True, the server updates its keyboard description for the specified device to match the result of the keyboard description just built. If False, the server’s description for the device is not updated. In all cases, the components specified by want and need from the just-built keyboard description are returned.

DESCRIPTION

XkbGetKeyboardByName builds a new keyboard description by querying the server’s Xkb database. The resulting keyboard description is returned as an XkbDescRec structure.

The deviceName argument specifies the name of the keyboard layout to be retrieved. The type argument specifies the type of the keyboard (e.g., "PC", "Mac"). If either of these arguments is NULL, Xkb will attempt to infer the name and type from the current keyboard settings on the specified display.

The need argument specifies components that are mandatory for the keyboard description. If any component specified in need cannot be resolved by the server, XkbGetKeyboardByName fails and returns NULL.

want specifies a set of keyboard components that the server should attempt to resolve, but that are not mandatory. If the server is unable to resolve any of these components, XkbGetKeyboardByName still succeeds. Bits specified in want that are also specified in need have no effect in the context of want.

If load is True, the server updates its keyboard description for device_spec to match the result of the keyboard description just built. If load is False, the server's description for device device_spec is not updated. In all cases, the parts specified by want and need from the just-built keyboard description are returned.

The names structure in an XkbDescRec keyboard description record contains one field for each of the five component types used to build a keyboard description. When a keyboard description is built from a set of database components, the corresponding fields in this names structure are set to match the expressions used to build the component.

Building a New Keyboard Description from the Server Database

The information returned to the client in the XkbDescRec is essentially the result of a series of calls to extract information from a fictitious device whose description matches the one just built. There is no way to determine which components specified in want (but not in need) were actually fetched, other than breaking the call into successive calls to XkbGetKeyboardByName and specifying individual components.

XkbGetKeyboardByName always sets min_key_code and max_key_code in the returned XkbDescRec structure.

XkbGetKeyboardByName is synchronous; it sends the request to the server to build a new keyboard description and waits for the reply. If successful, the return value is non-NULL. XkbGetKeyboardByName generates a BadMatch protocol error if errors are encountered when building the keyboard description.

STRUCTURES

The complete description of an Xkb keyboard is given by an XkbDescRec. The component structures in the XkbDescRec represent the major Xkb components outlined in Figure 1.1.

typedef struct {
   struct _XDisplay * display;      /* connection to X server */
   unsigned short     flags;        /* private to Xkb, do not modify */
   unsigned short     device_spec;  /* device of interest */
   KeyCode            min_key_code; /* minimum keycode for device */
   KeyCode            max_key_code; /* maximum keycode for device */
   XkbControlsPtr     ctrls;        /* controls */
   XkbServerMapPtr    server;       /* server keymap */
   XkbClientMapPtr    map;          /* client keymap */
   XkbIndicatorPtr    indicators;   /* indicator map */
   XkbNamesPtr        names;        /* names for all components */
   XkbCompatMapPtr    compat;       /* compatibility map */
   XkbGeometryPtr     geom;         /* physical geometry of keyboard */
} XkbDescRec, *XkbDescPtr;
The display field points to an X display structure. The flags field is private to the library: modifying flags may yield unpredictable results. The device_spec field specifies the device identifier of the keyboard input device, or XkbUseCoreKeyboard, which specifies the core keyboard device. The min_key_code and max_key_code fields specify the least and greatest keycode that can be returned by the keyboard.

Each structure component has a corresponding mask bit that is used in function calls to indicate that the structure should be manipulated in some manner, such as allocating it or freeing it. These masks and their relationships to the fields in the XkbDescRec are shown in Table 3.

Table 3 Mask Bits for XkbDescRec

XkbIndicatorMapMask indicators (1L<<3)
XkbNamesMask names (1L<<4)
XkbCompatMapMask compat (1L<<5)
XkbGeometryMask geom (1L<<6)
XkbAllComponentsMask All Fields (0x7f)

DIAGNOSTICS

BadMatch
A compatible version of Xkb was not available in the server or an argument has correct type and range, but is otherwise invalid
