XkbForceBell(3) XKB FUNCTIONS XkbForceBell(3)

NOMBRE

XkbForceBell - Anula la configuración de preferencia del usuario para que las campanas audibles suenen en el teclado predeterminado.

SINOPSIS

Bool XkbForceBell (Display *display, int percent);

ARGUMENTOS

display
conexión al servidor X
percent
volumen de la campana, que puede variar entre -100 y 100 inclusive

DESCRIPCIÓN

El protocolo central de X solo permite a las aplicaciones hacer sonar explícitamente la campana del sistema con una duración, tono y volumen dados. Xkb extiende esta capacidad permitiendo a los clientes adjuntar nombres simbólicos a las campanas, deshabilitar las campanas audibles y recibir un evento cada vez que se hace sonar la campana del teclado. Para los propósitos de este documento, la campana audible se define como la campana del sistema, o la campana predeterminada del teclado, en contraposición a cualquier otro sonido audible generado en otra parte del sistema. Puede solicitar recibir eventos XkbBellNotify cada vez que cualquier cliente haga sonar alguna de las siguientes opciones:

  • La campana predeterminada
  • Cualquier campana en un dispositivo de entrada que pueda especificarse mediante un par bell_class y bell_id
  • Cualquier campana especificada solo por un nombre arbitrario. (Esto es, desde el punto de vista del servidor, solo un nombre, y no está conectado con ningún dispositivo físico que genere sonido. Alguna aplicación cliente debe generar el sonido, o retroalimentación visual, si la hay, que esté asociada con el nombre.)

También puede solicitar recibir eventos XkbBellNotify cuando el servidor hace sonar la campana predeterminada o si algún cliente ha solicitado solo eventos (sin que suene la campana) para cualquiera de los tipos de campana enumerados anteriormente.

Puede deshabilitar las campanas audibles de forma global. Por ejemplo, un cliente que reemplaza la campana del teclado con alguna otra señal audible podría querer desactivar el control AudibleBell para evitar que el servidor genere también un sonido y así evitar la cacofonía. Si deshabilita las campanas audibles y solicita recibir eventos XkbBellNotify, puede generar una retroalimentación diferente a la campana predeterminada.

Sin embargo, puede anular el control AudibleBell llamando a una de las funciones que fuerzan el sonido de una campana a pesar de la configuración del control AudibleBell - XkbForceDeviceBell o XkbForceBell. En este caso, el servidor no genera un evento de campana.

Así como algunos teclados pueden producir clics de tecla para indicar cuándo se presiona o repite una tecla, Xkb puede proporcionar retroalimentación para los controles utilizando códigos de pitido especiales. El control AccessXFeedback se utiliza para configurar los tipos específicos de operaciones que generan retroalimentación.

Nombres de campanas

Puede asociar un nombre a un acto de hacer sonar una campana convirtiendo el nombre en un Atom y luego usando este nombre cuando llame a las funciones enumeradas en este capítulo. Si se genera un evento como resultado, el nombre se pasa a todos los demás clientes interesados en recibir eventos XkbBellNotify. Tenga en cuenta que estos son nombres arbitrarios y que no hay ninguna vinculación con ningún sonido. Cualquier sonido u otros efectos (como campanas visuales en la pantalla) deben ser generados por una aplicación cliente al recibir el evento de campana que contiene el nombre. No hay un nombre predeterminado para la campana predeterminada del teclado. El servidor genera algunas campanas predefinidas para los controles AccessX. Estas campanas nombradas se muestran en la Tabla 1; el nombre se incluye en cualquier evento de campana enviado a los clientes que hayan solicitado recibir eventos XkbBellNotify.

Campanas Audibles

Usando Xkb, puede generar eventos de campana que no necesariamente hagan sonar la campana del sistema. Esto es útil si necesita usar un servidor de audio en lugar del pitido del sistema. Por ejemplo, cuando se inicia un cliente de audio, podría deshabilitar la campana audible (la campana del sistema) y luego escuchar los eventos XkbBellNotify. Cuando recibe un evento XkbBellNotify, el cliente de audio podría enviar una solicitud a un servidor de audio para reproducir un sonido.

Puede controlar la función de campanas audibles pasando XkbAudibleBellMask a XkbChangeEnabledControls. Si establece XkbAudibleBellMask activado, el servidor hace sonar la campana del sistema cuando ocurre un evento de campana. Esto es lo predeterminado. Si establece XkbAudibleBellMask desactivado y ocurre un evento de campana, el servidor no hace sonar la campana del sistema a menos que llame a XkbForceDeviceBell o XkbForceBell.

Las campanas audibles también forman parte de los controles de restablecimiento automático por cliente.

Funciones de Campana

Utilice las funciones descritas en esta sección para hacer sonar campanas y generar eventos de campana.

La extensión de entrada tiene dos tipos de retroalimentaciones que pueden generar campanas: retroalimentación de campana y retroalimentación de teclado. Algunas de las funciones de esta sección tienen parámetros bell_class y bell_id; configúrelos de la siguiente manera: Establezca bell_class en BellFeedbackClass o KbdFeedbackClass. Un dispositivo puede tener más de una retroalimentación de cada tipo; establezca bell_id en la retroalimentación de campana particular del tipo bell_class.

Si no hay una extensión de teclado compatible presente en el servidor X, XkbForceBell llama a XBell con el display y el percent especificados y devuelve False. De lo contrario, XkbForceBell llama a XkbForceDeviceBell con el display y el percent especificados, device_spec =XkbUseCoreKbd, bell_class = XkbDfltXIClass, bell_id = XkbDfltXIId, window = None, y name = NULL, y devuelve lo que devuelve XkbForceDeviceBell.

XkbForceBell no causa un evento XkbBellNotify.

Puede llamar a XkbBell sin inicializar primero la extensión del teclado.

VALORES DE RETORNO

False
La función XkbForceBell devuelve False cuando no hay una extensión de teclado compatible presente en el servidor X.

ESTRUCTURAS

Xkb genera eventos XkbBellNotify para todas las campanas, excepto aquellas que resultan de llamadas a XkbForceDeviceBell y XkbForceBell. Para recibir eventos XkbBellNotify bajo todas las condiciones posibles, pase XkbBellNotifyMask tanto en los parámetros bits_to_change como values_for_bits a XkbSelectEvents.

El evento XkbBellNotify no tiene detalles de evento. Se selecciona o no se selecciona. Sin embargo, puede llamar a XkbSelectEventDetails usando XkbBellNotify como event_type y especificando XkbAllBellEventsMask en bits_to_change y values_for_bits. Esto tiene el mismo efecto que una llamada a XkbSelectEvents.

La estructura para el tipo de evento XkbBellNotify contiene:

   typedef struct _XkbBellNotify {
       int            type;        /* Código base del evento de extensión Xkb */
       unsigned long  serial;      /* Número de serie del servidor X para el evento */
       Bool           send_event;  /* True => generado sintéticamente */
       Display *      display;     /* Conexión del servidor donde se generó el evento */
       Time           time;        /* Tiempo del servidor cuando se generó el evento */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* ID del dispositivo Xkb, no será XkbUseCoreKbd */
       int            percent;     /* Volumen solicitado como % del máximo */
       int            pitch;       /* Tono solicitado en Hz */
       int            duration;    /* Duración solicitada en microsegundos */
       unsigned int   bell_class;  /* Clase de retroalimentación de extensión de entrada X */
       unsigned int   bell_id;     /* ID de retroalimentación de extensión de entrada X */
       Atom           name;        /* "Nombre" de la campana solicitada */
       Window         window;      /* Ventana asociada con el evento */
       Bool           event_only;  /* False -> el servidor no produjo un pitido */
   } XkbBellNotifyEvent;
Si su aplicación necesita generar retroalimentación visual de campana en la pantalla cuando recibe un evento de campana, utilice el ID de ventana en XkbBellNotifyEvent, si está presente.
