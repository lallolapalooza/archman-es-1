XkbForceDeviceBell(3) FUNCIONES DE XKB XkbForceDeviceBell(3)

NOMBRE

XkbForceDeviceBell - Hace sonar la campana en cualquier teclado, anulando la configuración de preferencias del usuario para campanas audibles

SINOPSIS

Bool XkbForceDeviceBell (Display *display, Window window, unsigned int device_spec, unsigned int bell_class, unsigned int bell_id, int percent);

ARGUMENTOS

display
conexión con el servidor X
window
ventana de eventos, o None
device_spec
ID del dispositivo, o XkbUseCoreKbd
bell_class
clase de extensión de entrada de la campana a hacer sonar
bell_id
ID de extensión de entrada de la campana a hacer sonar
percent
volumen relativo, que puede variar entre -100 y 100 inclusive

DESCRIPCIÓN

El protocolo central de X solo permite a las aplicaciones hacer sonar explícitamente la campana del sistema con una duración, tono y volumen dados. Xkb extiende esta capacidad al permitir a los clientes asociar nombres simbólicos a las campanas, deshabilitar campanas audibles y recibir un evento cada vez que suena la campana del teclado. Para los propósitos de este documento, la campana *audible* se define como la campana del sistema, o la campana predeterminada del teclado, en contraposición a cualquier otro sonido audible generado en otra parte del sistema. Puede solicitar recibir eventos XkbBellNotify cuando cualquier cliente haga sonar cualquiera de los siguientes:

  • La campana predeterminada
  • Cualquier campana en un dispositivo de entrada que se pueda especificar mediante un par bell_class y bell_id
  • Cualquier campana especificada solo por un nombre arbitrario. (Esto es, desde el punto de vista del servidor, meramente un nombre, y no está conectado con ningún dispositivo físico generador de sonido. Alguna aplicación cliente debe generar el sonido, o la retroalimentación visual, si la hay, que se asocia con el nombre).

También puede solicitar recibir eventos XkbBellNotify cuando el servidor haga sonar la campana predeterminada o si algún cliente ha solicitado eventos solamente (sin que suene la campana) para cualquiera de los tipos de campana enumerados anteriormente.

Puede deshabilitar las campanas audibles a nivel global. Por ejemplo, un cliente que reemplace la campana del teclado con alguna otra señal audible podría querer desactivar el control AudibleBell para evitar que el servidor también genere un sonido y así evitar la cacofonía. Si deshabilita las campanas audibles y solicita recibir eventos XkbBellNotify, puede generar una retroalimentación diferente de la campana predeterminada.

Sin embargo, puede anular el control AudibleBell llamando a una de las funciones que fuerzan el sonido de una campana a pesar de la configuración del control AudibleBell: XkbForceDeviceBell o XkbForceBell. En este caso, el servidor no genera un evento de campana.

Al igual que algunos teclados pueden producir clics de teclas para indicar cuándo se presiona o se repite una tecla, Xkb puede proporcionar retroalimentación para los controles utilizando códigos de sonido especiales. El control AccessXFeedback se utiliza para configurar los tipos específicos de operaciones que generan retroalimentación.

Nombres de Campanas

Puede asociar un nombre a un acto de hacer sonar una campana convirtiendo el nombre en un Átomo y luego usando este nombre al llamar a las funciones listadas en este capítulo. Si se genera un evento como resultado, el nombre se pasa a todos los demás clientes interesados en recibir eventos XkbBellNotify. Tenga en cuenta que estos son nombres arbitrarios y que no hay ninguna vinculación con sonidos. Cualquier sonido u otros efectos (como campanas visuales en la pantalla) deben ser generados por una aplicación cliente al recibir el evento de campana que contiene el nombre. No hay un nombre predeterminado para la campana predeterminada del teclado. El servidor genera algunas campanas predefinidas para los controles AccessX. Campanas Audibles

Usando Xkb, puede generar eventos de campana que no necesariamente hagan sonar la campana del sistema. Esto es útil si necesita usar un servidor de audio en lugar del pitido del sistema. Por ejemplo, cuando se inicia un cliente de audio, podría deshabilitar la campana audible (la campana del sistema) y luego escuchar los eventos XkbBellNotify. Cuando recibe un evento XkbBellNotify, el cliente de audio podría enviar una solicitud a un servidor de audio para reproducir un sonido.

Puede controlar la función de campanas audibles pasando XkbAudibleBellMask a XkbChangeEnabledControls. Si activa XkbAudibleBellMask, el servidor hace sonar la campana del sistema cuando ocurre un evento de campana. Este es el valor predeterminado. Si desactiva XkbAudibleBellMask y ocurre un evento de campana, el servidor no hace sonar la campana del sistema a menos que llame a XkbForceDeviceBell o XkbForceBell.

Las campanas audibles también forman parte de los controles de restablecimiento automático por cliente.

Funciones de Campana

Utilice las funciones descritas en esta sección para hacer sonar campanas y generar eventos de campana.

La extensión de entrada tiene dos tipos de retroalimentación que pueden generar campanas: retroalimentación de campana y retroalimentación de teclado. Algunas de las funciones en esta sección tienen parámetros bell_class y bell_id; configúrelos de la siguiente manera: Establezca bell_class en BellFeedbackClass o KbdFeedbackClass. Un dispositivo puede tener más de una retroalimentación de cada tipo; establezca bell_id en la campana particular de retroalimentación del tipo bell_class.

Si no hay una extensión de teclado compatible presente en el servidor X, XkbForceDeviceBell devuelve False inmediatamente. De lo contrario, XkbForceDeviceBell hace sonar la campana según lo especificado para la pantalla y el dispositivo de teclado, y devuelve True. Establezca percent para que sea el volumen relativo al volumen base del teclado, como se describe para XBell.

No hay un parámetro de nombre para este argumento.

XkbForceDeviceBell(3) — libX11 1.8.12

NAME

XkbForceDeviceBell, XkbForceBell - Force an Xkb bell

SYNOPSIS

#include <X11/extensions/XkbTypes.h>

Bool XkbForceDeviceBell(
    Display *display,
    int device_num,
    int bell_class,
    int bell_id,
    int percent
);
Bool XkbForceBell(
    Display *display,
    int percent
);

ARGUMENTS

display
Specifies the connection to the X server.
device_num
Specifies the Xkb device ID for the bell to be forced. This may be an Xkb device ID or XkbUseCoreKbd. If XkbUseCoreKbd is passed, the core keyboard bell is sounded. Otherwise, the bell for the specified device is sounded.
bell_class
Specifies the class of the bell feedback to be sounded. This must be one of the valid XkbBellClass values.
bell_id
Specifies the identifier of the bell feedback to be sounded. This is typically an integer index into the list of bells of the specified bell_class.
percent
Specifies the volume for the bell, from 0 to 100, where 0 is silent and 100 is the maximum volume. Values outside this range are clamped to the nearest valid value.

DESCRIPTION

The XkbForceDeviceBell function forces a bell to ring on a specific Xkb device. The device_num argument determines which device bell is sounded. If XkbUseCoreKbd is passed, the core keyboard bell is sounded. Otherwise, the bell associated with the specified device is sounded.

The bell_class and bell_id arguments specify the particular bell feedback to be sounded. These arguments are typically obtained from the XkbControlsDescription or XkbIndicatorMap arrays.

The percent argument specifies the desired volume of the bell, ranging from 0 (silent) to 100 (maximum volume). Values outside this range will be clamped to the nearest valid value.

The XkbForceBell function is a convenience function that is equivalent to calling XkbForceDeviceBell with device_num set to XkbUseCoreKbd and bell_class and bell_id set to appropriate default values.

Neither XkbForceDeviceBell nor XkbForceBell generate an XkbBellNotify event. If you need to be notified when a bell rings, you must select for XkbBellNotify events using XkbSelectEvents or XkbSelectEventDetails.

Note that the percent argument is optional for XkbForceBell.

You can call XkbForceDeviceBell without first initializing the keyboard extension.

STRUCTURES

Xkb generates XkbBellNotify events for all bells except for those resulting from calls to XkbForceDeviceBell and XkbForceBell. To receive XkbBellNotify events under all possible conditions, pass XkbBellNotifyMask in both the bits_to_change and values_for_bits parameters to XkbSelectEvents.

The XkbBellNotify event has no event details. It is either selected or it is not. However, you can call XkbSelectEventDetails using XkbBellNotify as the event_type and specifying XkbAllBellEventsMask in bits_to_change and values_for_bits. This has the same effect as a call to XkbSelectEvents.

The structure for the XkbBellNotify event type contains:

   typedef struct _XkbBellNotify {
       int            type;        /* Xkb extension base event code */
       unsigned long  serial;      /* X server serial number for event */
       Bool           send_event;  /* True => synthetically generated */
       Display *      display;     /* server connection where event generated */
       Time           time;        /* server time when event generated */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* Xkb device ID, will not be XkbUseCoreKbd */
       int            percent;     /* requested volume as % of max */
       int            pitch;       /* requested pitch in Hz */
       int            duration;    /* requested duration in microseconds */
       unsigned int   bell_class;  /* X input extension feedback class */
       unsigned int   bell_id;     /* X input extension feedback ID */
       Atom           name;        /* "name" of requested bell */
       Window         window;      /* window associated with event */
       Bool           event_only;  /* False -> the server did not produce a beep */
   } XkbBellNotifyEvent;
If your application needs to generate visual bell feedback on the screen when it receives a bell event, use the window ID in the XkbBellNotifyEvent, if present.
