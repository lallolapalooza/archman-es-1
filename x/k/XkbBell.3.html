XkbBell(3) FUNCIONES XKB XkbBell(3)

NOMBRE

XkbBell - Toca el timbre en el teclado predeterminado

SINOPSIS

Bool XkbBell (Display *display, Window window, int percent, Atom name);

ARGUMENTOS

display
conexión al servidor X
window
ventana de eventos, o None
percent
volumen relativo, que puede variar de -100 a 100 inclusive
name
un nombre de timbre, o NULL

DESCRIPCIÓN

El protocolo X principal solo permite a las aplicaciones hacer sonar explícitamente el timbre del sistema con una duración, tono y volumen dados. Xkb amplía esta capacidad al permitir a los clientes adjuntar nombres simbólicos a los timbres, deshabilitar los timbres audibles y recibir un evento cada vez que se toca el timbre del teclado. A efectos de este documento, el timbre *audible* se define como el timbre del sistema, o el timbre del teclado predeterminado, en contraposición a cualquier otro sonido audible generado en otra parte del sistema. Puede solicitar recibir eventos XkbBellNotify cuando cualquier cliente toque cualquiera de los siguientes timbres:

  • El timbre predeterminado
  • Cualquier timbre en un dispositivo de entrada que pueda especificarse mediante un par bell_class y bell_id
  • Cualquier timbre especificado solo por un nombre arbitrario. (Este es, desde el punto de vista del servidor, simplemente un nombre y no está conectado a ningún dispositivo generador de sonido físico. Alguna aplicación cliente debe generar el sonido, o la retroalimentación visual, si la hay, que se asocia con el nombre).

También puede solicitar recibir eventos XkbBellNotify cuando el servidor toca el timbre predeterminado o si algún cliente ha solicitado eventos solo (sin que suene el timbre) para cualquiera de los tipos de timbre enumerados anteriormente.

Puede deshabilitar los timbres audibles a nivel global. Por ejemplo, un cliente que reemplace el timbre del teclado con alguna otra señal audible podría querer desactivar el control AudibleBell para evitar que el servidor también genere un sonido y evitar la cacofonía. Si deshabilita los timbres audibles y solicita recibir eventos XkbBellNotify, puede generar una retroalimentación diferente al timbre predeterminado.

Sin embargo, puede anular el control AudibleBell llamando a una de las funciones que fuerzan el sonido de un timbre a pesar de la configuración del control AudibleBell - XkbForceDeviceBell o XkbForceBell. En este caso, el servidor no genera un evento de timbre.

Al igual que algunos teclados pueden producir clics de teclas para indicar cuándo se presiona o se repite una tecla, Xkb puede proporcionar retroalimentación para los controles utilizando códigos de pitido especiales. El control AccessXFeedback se utiliza para configurar los tipos específicos de operaciones que generan retroalimentación.

Nombres de Timbre

Puede asociar un nombre a un acto de tocar un timbre convirtiendo el nombre en un Átomo y luego usando este nombre cuando llame a las funciones listadas en este capítulo. Si como resultado se genera un evento, el nombre se pasa luego a todos los demás clientes interesados en recibir eventos XkbBellNotify. Tenga en cuenta que estos son nombres arbitrarios y que no hay ninguna vinculación a sonidos. Cualquier sonido u otro efecto (como timbres visuales en la pantalla) debe ser generado por una aplicación cliente al recibir el evento de timbre que contiene el nombre. No hay un nombre predeterminado para el timbre del teclado predeterminado. El servidor genera algunos timbres predefinidos para los controles AccessX. Timbres audibles

Usando Xkb puede generar eventos de timbre que no necesariamente hagan sonar el timbre del sistema. Esto es útil si necesita usar un servidor de audio en lugar del pitido del sistema. Por ejemplo, cuando un cliente de audio se inicia, podría deshabilitar el timbre audible (el timbre del sistema) y luego escuchar eventos XkbBellNotify. Cuando recibe un evento XkbBellNotify, el cliente de audio podría enviar una solicitud a un servidor de audio para reproducir un sonido.

Puede controlar la función de timbres audibles pasando XkbAudibleBellMask a XkbChangeEnabledControls. Si establece XkbAudibleBellMask en activado, el servidor hace sonar el timbre del sistema cuando ocurre un evento de timbre. Este es el valor predeterminado. Si establece XkbAudibleBellMask en desactivado y ocurre un evento de timbre, el servidor no hace sonar el timbre del sistema a menos que llame a XkbForceDeviceBell o XkbForceBell.

Los timbres audibles también forman parte de los controles de restablecimiento automático por cliente.

Funciones de Timbre

Utilice las funciones descritas en esta sección para tocar timbres y generar eventos de timbre.

La extensión de entrada tiene dos tipos de retroalimentación que pueden generar timbres: retroalimentación de timbre y retroalimentación de teclado. Algunas de las funciones en esta sección tienen parámetros bell_class y bell_id; configúrelos de la siguiente manera: Establezca bell_class en BellFeedbackClass o KbdFeedbackClass. Un dispositivo puede tener más de una retroalimentación de cada tipo; establezca bell_id en la retroalimentación de timbre particular del tipo bell_class.

La Tabla 2 muestra las condiciones que provocan que suene un timbre o que se genere un XkbBellNotifyEvent cuando se llama a una función de timbre.

Si no hay una extensión de teclado compatible presente en el servidor X, XkbBell llama a XBell con los display y percent especificados, y devuelve False. De lo contrario, XkbBell llama a XkbDeviceBell con los display, window, percent, y name especificados, un device_spec de XkbUseCoreKbd, una bell_class de XkbDfltXIClass, y una bell_id de XkbDfltXIId, y devuelve True.

Si ha deshabilitado el timbre audible, el servidor no hace sonar el timbre del sistema, aunque genera un evento XkbBellNotify.

Puede llamar a XkbBell sin inicializar primero la extensión del teclado.

ESTRUCTURAS

Xkb genera eventos XkbBellNotify para todas las campanas, excepto para aquellas que resultan de llamadas a XkbForceDeviceBell y XkbForceBell. Para recibir eventos XkbBellNotify en todas las condiciones posibles, pase XkbBellNotifyMask en los parámetros bits_to_change y values_for_bits a XkbSelectEvents.

El evento XkbBellNotify no tiene detalles del evento. O se selecciona o no. Sin embargo, puede llamar a XkbSelectEventDetails usando XkbBellNotify como event_type y especificando XkbAllBellEventsMask en bits_to_change y values_for_bits. Esto tiene el mismo efecto que una llamada a XkbSelectEvents.

La estructura para el tipo de evento XkbBellNotify contiene:

   typedef struct _XkbBellNotify {
       int            type;        /* Código base de evento de extensión Xkb */
       unsigned long  serial;      /* Número de serie del servidor X para el evento */
       Bool           send_event;  /* True => generado sintéticamente */
       Display *      display;     /* Conexión del servidor donde se generó el evento */
       Time           time;        /* Hora del servidor cuando se generó el evento */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* ID del dispositivo Xkb, no será XkbUseCoreKbd */
       int            percent;     /* Volumen solicitado como % del máximo */
       int            pitch;       /* Tono solicitado en Hz */
       int            duration;    /* Duración solicitada en microsegundos */
       unsigned int   bell_class;  /* Clase de retroalimentación de extensión de entrada X */
       unsigned int   bell_id;     /* ID de retroalimentación de extensión de entrada X */
       Atom           name;        /* "nombre" de la campana solicitada */
       Window         window;      /* Ventana asociada con el evento */
       Bool           event_only;  /* False -> el servidor no produjo un pitido */
   } XkbBellNotifyEvent;
Si su aplicación necesita generar retroalimentación visual de campana en la pantalla cuando recibe un evento de campana, utilice el ID de ventana en el XkbBellNotifyEvent, si está presente.
