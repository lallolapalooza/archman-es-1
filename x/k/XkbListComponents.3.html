XkbListComponents(3) FUNCIONES DE XKB XkbListComponents(3)

NOMBRE

XkbListComponents - Lista de componentes para uno o más tipos de componentes

SINOPSIS

XkbComponentListPtr XkbListComponents (Display *dpy, unsigned int device_spec, XkbComponentNamesPtr ptrns, int *max_inout);

ARGUMENTOS

dpy
conexión al servidor X
device_spec
ID del dispositivo o XkbUseCoreKbd
ptrns
lista de patrones para los componentes de interés
max_inout
número máximo de nombres devueltos, número restante

DESCRIPCIÓN

Puedes pedirle al servidor una lista de componentes para uno o más tipos de componentes. La solicitud toma la forma de un conjunto de patrones, un patrón para cada uno de los tipos de componentes, incluido un patrón para la descripción completa del teclado. Para obtener esta lista, usa XkbListComponents.

XkbListComponents consulta al servidor una lista de nombres de componentes que coinciden con los patrones especificados en ptrns. Espera una respuesta y devuelve los nombres de componentes coincidentes en una estructura XkbComponentListRec. Cuando hayas terminado de usar la estructura, deberías liberarla usando XkbFreeComponentList. device_spec indica un dispositivo particular en el que el llamante está interesado. Se permite a un servidor (pero no se le exige) restringir su respuesta a porciones de la base de datos que sean relevantes para ese dispositivo en particular.

ptrns es un puntero a un XkbComponentNamesRec. Cada uno de los campos de ptrns contiene un patrón que nombra los componentes de interés. Cada uno de los patrones se compone de caracteres de la codificación Latin1 de ISO, pero solo puede contener paréntesis, los caracteres comodín `?' y `*', y caracteres permitidos en el nombre de una clase o miembro de componente. Un patrón puede ser NULL, en cuyo caso no se devuelven componentes de ese tipo. Las coincidencias de patrones con nombres de componentes distinguen entre mayúsculas y minúsculas. El comodín `?' coincide con cualquier carácter individual, excepto un paréntesis izquierdo o derecho; el comodín `*' coincide con cualquier número de caracteres, excepto un paréntesis izquierdo o derecho. Si una implementación permite caracteres adicionales en el nombre de una clase o miembro de componente distintos de los requeridos por la extensión Xkb, el resultado de comparar uno de los caracteres adicionales con cualquiera de los caracteres comodín depende de la implementación.

Si un patrón contiene caracteres ilegales, los caracteres ilegales se ignoran. El proceso de coincidencia se lleva a cabo como si los caracteres ilegales se hubieran omitido del patrón.

max_inout se utiliza para controlar la cantidad de datos que se pasan hacia y desde el servidor. En la entrada, especifica el número máximo de nombres a devolver (el número total de nombres en todas las categorías de componentes). Al regresar de XkbListComponents, max_inout contiene el número de nombres que coincidieron con la solicitud pero que no se devolvieron debido al límite.

Nombres de Componentes

Los nombres de componentes tienen el formato clase(miembro) donde clase describe un subconjunto de los componentes disponibles para un tipo particular y el miembro opcional identifica un componente específico de ese subconjunto. Por ejemplo, el nombre "atlantis(acme)" para un componente de símbolos podría especificar los símbolos utilizados para la distribución de teclado nacional de atlantis por el proveedor "acme." Cada clase tiene un miembro predeterminado opcional: las referencias que especifican una clase pero no un miembro se refieren al miembro predeterminado de la clase, si existe. Xkb no impone restricciones sobre la interpretación de los nombres de clase y miembro utilizados en los nombres de componentes.

Los nombres de clase y miembro se especifican ambos utilizando caracteres del conjunto de caracteres Latin-1. Las implementaciones de Xkb deben aceptar todos los caracteres alfanuméricos, el guion (`-') y el guion bajo (`_') en los nombres de clase o miembro, y no deben aceptar paréntesis, signos más, barras verticales, signos de porcentaje, asteriscos, signos de interrogación o espacios en blanco. El uso de otros caracteres depende de la implementación.

ESTRUCTURAS

Los patrones de nombres de componentes utilizados para describir la solicitud se pasan a XkbListComponents utilizando una estructura XkbComponentNamesRec. Esta estructura no tiene restricciones especiales de asignación ni interrelaciones con otras estructuras; asigne y libere esta estructura utilizando llamadas estándar a malloc y free o sus equivalentes:

    typedef struct _XkbComponentNames {
        char *         keymap;           /* nombres de keymap */
        char *         keycodes;         /* nombres de keycodes */
        char *         types;            /* nombres de types */
        char *         compat;           /* nombres de mapa de compatibilidad */
        char *         symbols;          /* nombres de símbolos */
        char *         geometry;         /* nombres de geometría */
    } XkbComponentNamesRec, *XkbComponentNamesPtr;

XkbListComponents devuelve un puntero a un XkbComponentListRec:

    typedef struct _XkbComponentList {
        int                      num_keymaps;  /* número de entradas en keymap */
        int                      num_keycodes; /* número de entradas en keycodes */
        int                      num_types;    /* número de entradas en types */
        int                      num_compat;   /* número de entradas en compat */
        int                      num_symbols;  /* número de entradas en symbols */
        int                      num_geometry; /* número de entradas en geometry;
        XkbComponentNamePtr      keymap;       /* nombres de keymap */
        XkbComponentNamePtr      keycodes;     /* nombres de keycodes */
        XkbComponentNamePtr      types;        /* nombres de types */
        XkbComponentNamePtr      compat;       /* nombres de mapa de compatibilidad */
        XkbComponentNamePtr      symbols;      /* nombres de símbolos */
        XkbComponentNamePtr      geometry;     /* nombres de geometría */
    } XkbComponentListRec, *XkbComponentListPtr;
    typedef struct _XkbComponentName {
        unsigned short           flags;        /* pistas sobre el nombre del componente */
        char *                   name;         /* nombre del componente */
    } XkbComponentNameRec, *XkbComponentNamePtr;

VER TAMBIÉN

XkbFreeComponentList(3)

NOTAS

Tenga en cuenta que la estructura utilizada para especificar patrones en la entrada es una XkbComponentNamesRec, y la utilizada para mantener los nombres de componentes individuales al regresar es una XkbComponentNameRec (sin `s' al final de Name).
