XkbGetKeyExplicitComponents(3)

Paquete: libx11

Licencias: MIT AND X11

XkbGetKeyExplicitComponents(3) FUNCIÓN XKB XkbGetKeyExplicitComponents(3)

NOMBRE

XkbGetKeyExplicitComponents - Obtener los componentes explícitos (el array explícito) para un subconjunto de las teclas de una descripción de teclado

SINOPSIS

Estado XkbGetKeyExplicitComponents (Display *dpy, unsigned int primero, unsigned int num, XkbDescPtr xkb);

ARGUMENTOS

dpy
conexión al servidor
primero
código de tecla de la primera tecla a obtener
num
número de teclas para las que obtener información explícita
xkb
descripción Xkb en la que poner los resultados

DESCRIPCIÓN

Cada vez que un cliente reasigna el teclado usando peticiones del protocolo principal, Xkb examina el mapa para determinar valores predeterminados probables para los componentes que no se pueden especificar usando el protocolo principal (ver Transformación de Mapeo de Teclado Principal a Mapeo de Teclado Xkb para más información sobre cómo Xkb elige los valores predeterminados).

¿NECESITAN AGREGARSE LAS CUATRO PÁGINAS DE "TRANSFORMACIÓN DE MAPEO DE TECLADO PRINCIPAL A MAPEO DE TECLADO XKB" AQUÍ?

Esta reasignación automática puede reemplazar definiciones solicitadas explícitamente por una aplicación, por lo que la descripción del teclado Xkb define una máscara de componentes explícitos para cada tecla. Cualquier aspecto de la reasignación automática enumerado en la máscara de componentes explícitos para una tecla no se cambia por el mapeo automático del teclado.

Las máscaras de componentes explícitos se guardan en el campo explícito del mapa del servidor, que es un array indexado por el código de tecla. Cada entrada en este array es una máscara que es una OR inclusiva a nivel de bits de los valores que se muestran en la Tabla 1.

Tabla 1 Máscaras de Componentes Explícitos
Bit en la Máscara Explícita Valor Protege Contra
ExplicitKeyType1 (1<<0) Determinación automática del tipo de tecla asociado al Grupo1.
ExplicitKeyType2 (1<<1) Determinación automática del tipo de tecla asociado al Grupo2.
ExplicitKeyType3 (1<<2) Determinación automática del tipo de tecla asociado al Grupo3.
ExplicitKeyType4 (1<<3) Determinación automática del tipo de tecla asociado al Grupo4.
ExplicitInterpret (1<<4) Aplicación de cualquiera de los campos de una interpretación de símbolos a la tecla en cuestión.
ExplicitAutoRepeat (1<<5) Determinación automática del estado de repetición automática para la tecla, según se especifica en una interpretación de símbolos.
ExplicitBehavior (1<<6) Asignación automática del comportamiento XkbKB_Lock a la tecla, si el flag XkbSI_LockingKey está establecido en una interpretación de símbolos.
ExplicitVModMap (1<<7) Determinación automática del mapa de modificadores virtuales para la tecla basándose en las acciones asignadas a la tecla y las interpretaciones de símbolos que coinciden con la tecla.

XkbGetKeyExplicitComponents envía una petición al servidor para obtener los componentes explícitos para num teclas en el teclado comenzando con la tecla primero. Espera una respuesta y devuelve los componentes explícitos en el array servidor->explícito de xkb. Si tiene éxito, XkbGetKeyExplicitComponents devuelve Success. El parámetro xkb debe ser un puntero a una descripción de teclado Xkb válida.

Si el mapa del servidor en el parámetro xkb no se ha asignado, XkbGetKeyExplicitComponents lo asigna y lo inicializa antes de obtener las acciones.

Si el servidor no tiene una versión compatible de Xkb, o la extensión Xkb no se ha inicializado correctamente, XkbGetKeyExplicitComponents devuelve BadMatch. Si num es menor que 1 o mayor que XkbMaxKeyCount, XkbGetKeyExplicitComponents devuelve BadValue. Si ocurren errores de asignación, XkbGetKeyExplicitComponents devuelve BadAlloc.

DIAGNÓSTICOS

BadAlloc
No se pudo asignar almacenamiento
BadMatch
No se disponía de una versión compatible de Xkb en el servidor o un argumento tiene el tipo y rango correctos, pero por lo demás es inválido
BadValue
Un argumento está fuera de rango
