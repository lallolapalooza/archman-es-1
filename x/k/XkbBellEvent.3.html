XkbBellEvent(3) FUNCIONES XKB XkbBellEvent(3)

NOMBRE

XkbBellEvent - Proporciona una función que inicia un evento de timbre para el teclado sin hacerlo sonar

SINOPSIS

Bool XkbBellEvent (Display *display, Window window, int percent, Atom name);

ARGUMENTOS

display
conexión con el servidor X
window
la ventana del evento, o None
percent
volumen relativo, que puede variar entre -100 y 100 inclusive
name
un nombre de timbre, o NULL

DESCRIPCIÓN

El protocolo X principal solo permite a las aplicaciones emitir explícitamente el timbre del sistema con una duración, tono y volumen dados. Xkb extiende esta capacidad al permitir que los clientes asocien nombres simbólicos a los timbres, deshabilitar timbres audibles y recibir un evento cada vez que suene el timbre del teclado. A efectos de este documento, el timbre audible se define como el timbre del sistema, o el timbre predeterminado del teclado, en contraposición a cualquier otro sonido audible generado en otro lugar del sistema. Puede solicitar recibir eventos XkbBellNotify cada vez que cualquier cliente haga sonar cualquiera de los siguientes:

  • El timbre predeterminado
  • Cualquier timbre en un dispositivo de entrada que pueda especificarse con un par bell_class y bell_id
  • Cualquier timbre especificado solo por un nombre arbitrario. (Este es, desde el punto de vista del servidor, simplemente un nombre, y no está conectado con ningún dispositivo físico generador de sonido. Alguna aplicación cliente debe generar el sonido, o la retroalimentación visual, si la hubiera, que esté asociada con el nombre).

    También puede solicitar recibir eventos XkbBellNotify cuando el servidor haga sonar el timbre predeterminado o si algún cliente ha solicitado eventos solo (sin que suene el timbre) para cualquiera de los tipos de timbre enumerados anteriormente.

    Puede deshabilitar los timbres audibles a nivel global. Por ejemplo, un cliente que reemplace el timbre del teclado con alguna otra señal audible podría querer desactivar el control AudibleBell para evitar que el servidor también genere un sonido y evitar la cacofonía. Si deshabilita los timbres audibles y solicita recibir eventos XkbBellNotify, puede generar una retroalimentación diferente al timbre predeterminado.

    Sin embargo, puede anular el control AudibleBell llamando a una de las funciones que fuerzan el sonido de un timbre a pesar de la configuración del control AudibleBell - XkbForceDeviceBell o XkbForceBell. En este caso, el servidor no genera un evento de timbre.

    Así como algunos teclados pueden producir clics de teclas para indicar cuándo se presiona o se repite una tecla, Xkb puede proporcionar retroalimentación para los controles mediante códigos de pitido especiales. El control AccessXFeedback se utiliza para configurar los tipos específicos de operaciones que generan retroalimentación.

    Nombres de Timbre

    Puede asociar un nombre a un acto de hacer sonar un timbre convirtiendo el nombre en un Atom y luego usando este nombre al llamar a las funciones que se describen en este capítulo. Si como resultado se genera un evento, el nombre se pasa a todos los demás clientes interesados en recibir eventos XkbBellNotify. Tenga en cuenta que estos son nombres arbitrarios y que no hay ninguna asociación con ningún sonido. Cualquier sonido u otros efectos (como timbres visuales en la pantalla) deben ser generados por una aplicación cliente al recibir el evento de timbre que contiene el nombre. No hay un nombre predeterminado para el timbre predeterminado del teclado. El servidor genera algunos timbres predefinidos para los controles AccessX. Estos timbres con nombre se muestran en la Tabla 1; el nombre se incluye en cualquier evento de timbre enviado a los clientes que hayan solicitado recibir eventos XkbBellNotify.

    Timbres Audibles

    Usando Xkb puede generar eventos de timbre que no necesariamente hagan sonar el timbre del sistema. Esto es útil si necesita usar un servidor de audio en lugar del pitido del sistema. Por ejemplo, cuando se inicia un cliente de audio, podría deshabilitar el timbre audible (el timbre del sistema) y luego escuchar los eventos XkbBellNotify. Cuando recibe un evento XkbBellNotify, el cliente de audio podría enviar una solicitud a un servidor de audio para reproducir un sonido.

    Puede controlar la función de timbres audibles pasando XkbAudibleBellMask a XkbChangeEnabledControls. Si establece XkbAudibleBellMask en activado, el servidor hace sonar el timbre del sistema cuando ocurre un evento de timbre. Este es el valor predeterminado. Si establece XkbAudibleBellMask en desactivado y ocurre un evento de timbre, el servidor no hace sonar el timbre del sistema a menos que llame a XkbForceDeviceBell o XkbForceBell.

    Los timbres audibles también forman parte de los controles de restablecimiento automático por cliente.

    Funciones de Timbre

    Utilice las funciones descritas en esta sección para hacer sonar timbres y generar eventos de timbre.

    La extensión de entrada tiene dos tipos de retroalimentaciones que pueden generar timbres: retroalimentación de timbre y retroalimentación de teclado. Algunas de las funciones de esta sección tienen parámetros bell_class y bell_id; configúrelos de la siguiente manera: Establezca bell_class en BellFeedbackClass o KbdFeedbackClass. Un dispositivo puede tener más de una retroalimentación de cada tipo; establezca bell_id en la retroalimentación de timbre particular del tipo bell_class.

XkbBellEvent(3)

NAME

XkbBellEvent - Generates a bell event

SYNOPSIS

        #include <X11/extensions/XKBbells.h>
        Bool XkbBellEvent(
            Display *           display,
            Window              window,
            int                 percent,
            Atom                name
        );

ARGUMENTS

o display
Specifies the connection to the X server.
o window
Specifies the window associated with the bell event.
o percent
Specifies the desired volume for the bell, as a percentage of the maximum volume.
o name
Specifies the name of the bell to be played.

DESCRIPTION

The function XkbBellEvent generates a bell event for the specified window and percent volume. The name parameter can be used to specify a particular bell to be played. If the keyboard extension is not available on the X server, XkbBellEvent immediately returns False.

Otherwise, XkbBellEvent calls XkbDeviceBellEvent with the specified display, window, percent, and name, a device_spec of XkbUseCoreKbd, a bell_class of XkbDfltXIClass, and a bell_id of XkbDfltXIId, and returns what XkbDeviceBellEvent returns.

XkbBellEvent generates a XkbBellNotify event.

You can call XkbBellEvent without first initializing the keyboard extension.

RETURN VALUES

False
The XkbBellEvent immediately returns False, if a compatible keyboard extension isn't present in the X server.

STRUCTURES

Xkb generates XkbBellNotify events for all bells except for those resulting from calls to XkbForceDeviceBell and XkbForceBell. To receive XkbBellNotify events under all possible conditions, pass XkbBellNotifyMask in both the bits_to_change and values_for_bits parameters to XkbSelectEvents.

The XkbBellNotify event has no event details. It is either selected or it is not. However, you can call XkbSelectEventDetails using XkbBellNotify as the event_type and specifying XkbAllBellEventsMask in bits_to_change and values_for_bits. This has the same effect as a call to XkbSelectEvents.

The structure for the XkbBellNotify event type contains:

   typedef struct _XkbBellNotify {
       int            type;        /* Xkb extension base event code */
       unsigned long  serial;      /* X server serial number for event */
       Bool           send_event;  /* True => synthetically generated */
       Display *      display;     /* server connection where event generated */
       Time           time;        /* server time when event generated */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* Xkb device ID, will not be XkbUseCoreKbd */
       int            percent;     /* requested volume as % of max */
       int            pitch;       /* requested pitch in Hz */
       int            duration;    /* requested duration in microseconds */
       unsigned int   bell_class;  /* X input extension feedback class */
       unsigned int   bell_id;     /* X input extension feedback ID */
       Atom           name;        /* "name" of requested bell */
       Window         window;      /* window associated with event */
       Bool           event_only;  /* False -> the server did not produce a beep */
   } XkbBellNotifyEvent;
If your application needs to generate visual bell feedback on the screen when it receives a bell event, use the window ID in the XkbBellNotifyEvent, if present.
