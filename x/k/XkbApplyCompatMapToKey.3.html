XkbApplyCompatMapToKey(3) FUNCIONES XKB XkbApplyCompatMapToKey(3)

NOMBRE

XkbApplyCompatMapToKey - Aplica el nuevo mapeo de compatibilidad a una tecla individual para actualizar su semántica.

SINOPSIS

Bool XkbApplyCompatMapToKey (XkbDescPtr xkb, KeyCode key, XkbChangesPtr changes);

ARGUMENTOS

xkb
descripción del teclado a actualizar
key
tecla a actualizar
changes
registra los cambios en la descripción del teclado Xkb

DESCRIPCIÓN

XkbApplyCompatMapToKey realiza esencialmente la operación descrita en la Transformación del Mapeo de Teclado Principal a Mapeo de Teclado Xkb para una tecla específica. Esto actualiza el comportamiento, las acciones, el estado de repetición y las asignaciones de modificadores virtuales de la tecla.

Transformación del Mapeo de Teclado Principal a Mapeo de Teclado Xkb

Cuando el servidor recibe una solicitud de mapeo de teclado del protocolo principal, se actualiza el mapa de teclado principal del servidor y luego se actualiza el mapa Xkb mantenido por el servidor. Dado que un cliente puede haber configurado explícitamente parte del mapeo de teclado Xkb en el servidor, esta regeneración automática del mapeo de teclado Xkb a partir del mapeo de teclado del protocolo principal no debe modificar ningún componente del mapeo de teclado Xkb que haya sido configurado explícitamente por un cliente. El cliente debe establecer controles de anulación explícitos para evitar que esto suceda (ver Componentes Explícitos - Evitar la reprogramación automática por el servidor). El mapeo principal-a-Xkb se realiza de la siguiente manera:

Componentes Explícitos - Evitar la Reprogramación Automática por el Servidor

Cada vez que un cliente reprograma el teclado utilizando solicitudes del protocolo principal, Xkb examina el mapa para determinar valores predeterminados probables para los componentes que no se pueden especificar utilizando el protocolo principal.

Esta reprogramación automática podría reemplazar las definiciones solicitadas explícitamente por una aplicación, por lo que la descripción del teclado Xkb define una máscara de componentes explícitos para cada tecla. Cualquier aspecto de la reprogramación automática enumerado en la máscara de componentes explícitos para una tecla no se modifica por el mapeo automático del teclado.

Las máscaras de componentes explícitos se mantienen en el campo explicit del mapa del servidor, que es un array indexado por keycode. Cada entrada en este array es una máscara que es una OR inclusiva a nivel de bits de los valores que se muestran en la Tabla 1.

Tabla 1 Máscaras de Componentes Explícitos
Bit en la Máscara Explícita Valor Protege contra
ExplicitKeyType1 (1<<0) Determinación automática del tipo de tecla asociado con el Grupo 1.
ExplicitKeyType2 (1<<1) Determinación automática del tipo de tecla asociado con el Grupo 2.
ExplicitKeyType3 (1<<2) Determinación automática del tipo de tecla asociado con el Grupo 3.
ExplicitKeyType4 (1<<3) Determinación automática del tipo de tecla asociado con el Grupo 4.
ExplicitInterpret (1<<4) Aplicación de cualquiera de los campos de una interpretación de símbolos a la tecla en cuestión.
ExplicitAutoRepeat (1<<5) Determinación automática del estado de repetición automática para la tecla, según lo especificado en una interpretación de símbolos.
ExplicitBehavior (1<<6) Asignación automática del comportamiento XkbKB_Lock a la tecla, si el indicador XkbSI_LockingKey está establecido en una interpretación de símbolos.
ExplicitVModMap (1<<7) Determinación automática del mapa de modificadores virtuales para la tecla basándose en las acciones asignadas a la tecla y las interpretaciones de símbolos que coinciden con la tecla.
1.
Mapear los símbolos de las teclas en el mapa de teclado principal a grupos y símbolos en las teclas del mapa de teclado Xkb. El mapeo de teclado principal tiene un ancho fijo, por lo que cada tecla en el mapeo principal tiene el mismo número de símbolos asociados. El mapeo Xkb permite asociar un número diferente de símbolos a cada tecla; esos símbolos pueden dividirse en un número diferente de grupos (1-4) para cada tecla. Para cada tecla, este proceso implica por lo tanto particionar el número fijo de símbolos del mapeo principal en un conjunto de grupos de longitud variable con un número variable de símbolos en cada grupo. Por ejemplo, si el mapa del protocolo principal tiene un ancho de cinco, la partición para una tecla podría resultar en un grupo con dos símbolos y otro con tres. Otra tecla podría resultar en dos grupos con dos símbolos más un tercer grupo con un símbolo. El mapa del protocolo principal requiere al menos dos símbolos en cada uno de los dos primeros grupos.
1a.
Para cada tecla cambiada, determinar el número de grupos representados en el nuevo mapa de teclado principal. Esto resulta en un recuento de grupos tentativo para cada tecla en el mapa Xkb.
1b.
Para cada tecla cambiada, determinar el número de símbolos en cada uno de los grupos encontrados en el paso 1a. Hay un control de anulación explícito asociado con cada uno de los cuatro grupos posibles para cada tecla Xkb, ExplicitKeyType1 hasta ExplicitKeyType4. Si no se establece ningún control de anulación explícito para un grupo, el número de símbolos utilizados para ese grupo del mapa principal es dos. Si se establece el control de anulación explícito para un grupo en la tecla, el número de símbolos utilizados para ese grupo Xkb del mapa principal es el ancho del grupo Xkb con una excepción: debido al requisito del protocolo principal de al menos dos símbolos en cada uno de los grupos uno y dos, el número de símbolos utilizados para los grupos uno y dos es el máximo de 2 o el ancho del grupo Xkb.
1c.
Para cada tecla cambiada, asignar los símbolos del mapa principal al grupo apropiado en la tecla. Si el número total de símbolos requeridos por el mapa Xkb para una tecla particular necesita más símbolos de los que contiene el mapa del protocolo principal, los símbolos adicionales se toman como keysyms NoSymbol añadidos al final del conjunto principal. Si el mapa principal contiene más símbolos de los que necesita el mapa Xkb, los símbolos finales en el mapa principal se descartan. En ausencia de una anulación explícita para el grupo uno o dos, los símbolos se asignan en orden por grupo; los primeros símbolos del mapa principal se asignan al grupo uno, en orden, seguidos por el grupo dos, y así sucesivamente. Por ejemplo, si el mapa principal contenía ocho símbolos por tecla, y un mapa Xkb particular contenía 2 símbolos para G1 y G2 y tres para G3, los símbolos se asignarían como (G es grupo, L es nivel de desplazamiento): 
              G1L1 G1L2 G2L1 G2L2 G3L1 G3L2 G3L3
Si se establece una anulación explícita para el grupo uno o dos, los símbolos se toman del conjunto principal en un orden algo diferente. Los primeros cuatro símbolos del conjunto principal se asignan a G1L1, G1L2, G2L1, G2L2, respectivamente. Si el grupo uno requiere más símbolos, se toman a continuación, y luego los símbolos adicionales necesarios por el grupo dos. Los símbolos de los grupos tres y cuatro se toman en secuencia completa después del grupo dos. Por ejemplo, una tecla con cuatro grupos y tres símbolos en cada grupo tomaría símbolos del conjunto principal en el siguiente orden: 
   G1L1 G1L2 G2L1 G2L2 G1L3 G2L3 G3L1 G3L2 G3L3 G4L1 G4L2 G4L3
Como se mencionó anteriormente, el mapa del protocolo principal requiere al menos dos símbolos en los grupos uno y dos. Debido a esto, si se establece un control de anulación explícito para una tecla Xkb y el grupo uno y / o el grupo dos tiene un ancho de uno, no es posible generar los símbolos tomados del conjunto del protocolo principal y asignados a la posición G1L2 y / o G2L2.
1d.
Para cada grupo en cada tecla cambiada, asignar un tipo de tecla apropiado para los símbolos del grupo.
1e.
Para cada tecla cambiada, eliminar cualquier grupo vacío o redundante.

En este punto, los grupos y sus símbolos asociados se han asignado a las definiciones de teclas correspondientes en el mapa Xkb.

2.
Aplicar interpretaciones de símbolos para modificar la operación de la tecla. Esta fase se omite por completo si el bit de control de anulación ExplicitInterpret está establecido en la máscara de controles explícitos para la tecla Xkb (ver Componentes Explícitos - Evitar la Reprogramación Automática por el Servidor).
2a.
Para cada símbolo en cada tecla cambiada, intentar hacer coincidir el símbolo y los modificadores del mapa Xkb con una interpretación de símbolos que describa cómo generar

XkbApplyCompatMapToKey(3) — XKB API — Arch manual pages

NAME

XkbApplyCompatMapToKey - apply compatibility map to a key

SYNOPSIS

#include <X11/extensions/XkbKeysym.h>
#include <X11/extensions/XKB.h>

Status XkbApplyCompatMapToKey(
    Display *dpy,
    RDBindingsRec *bindings,
    int key_code,
    XkbCompatMapRec *compat_map
);

ARGUMENTS

dpy
Specifies the connection to the X server.
bindings
Specifies the key bindings to be modified.
key_code
Specifies the keycode for the key to be modified.
compat_map
Specifies the compatibility map to apply.

DESCRIPTION

The function XkbApplyCompatMapToKey applies the specified compatibility map, compat_map, to the key specified by key_code using the bindings specified by bindings.

The compatibility map is used to determine the way that keysyms are interpreted by the X server. When a key is pressed, the server looks up the keysym associated with that key in the current keyboard layout. It then consults the compatibility map to determine how to interpret that keysym. This interpretation can affect various aspects of keyboard behavior, such as modifier key mapping, auto-repeat settings, and key behavior (e.g., setting a key to function as a lock key).

The process of applying a compatibility map involves the following steps:

2a.
For each symbol on the specified key, find the corresponding symbol interpretation in the compatibility map.
2b.
When a match is found in step 2a, apply the symbol interpretation to change the semantics associated with the symbol in the Xkb key map. If no match is found, apply a default interpretation.

The symbol interpretations used in step 2 are configurable and may be specified using XkbSymInterpretRec structures referenced by the sym_interpret field of an XkbCompatMapRec.

Symbol Interpretations - the XkbSymInterpretRec Structure

Symbol interpretations are used to guide the X server when it modifies the Xkb keymap in step 2. An initial set of symbol interpretations is loaded by the server when it starts. A client may add new ones using XkbSetCompatMap.

Symbol interpretations result in key semantics being set. When a symbol interpretation is applied, the following components of server key event processing may be modified for the particular key involved:

    Virtual modifier map
    Auto repeat
    Key behavior (may be set to XkbKB_Lock)
    Key action
The XkbSymInterpretRec structure specifies a symbol interpretation: 
typedef struct {
    KeySym        sym;         /* keysym of interest or NULL */
    unsigned char flags;       /* XkbSI_AutoRepeat, XkbSI_LockingKey */
    unsigned char match;       /* specifies how mods is interpreted */
    unsigned char mods;        /* modifier bits, correspond to eight real modifiers */
    unsigned char virtual_mod; /* 1 modifier to add to key virtual mod map */
    XkbAnyAction  act;         /* action to bind to symbol position on key */
} XkbSymInterpretRec,*XkbSymInterpretPtr;
If sym is not NULL, it limits the symbol interpretation to keys on which that particular keysym is selected by the modifiers matching the criteria specified by mods and match. If sym is NULL, the interpretation may be applied to any symbol selected on a key when the modifiers match the criteria specified by mods and match.

match must be one of the values shown in Table 2 and specifies how the real modifiers specified in mods are to be interpreted.

Table 2 Symbol Interpretation Match Criteria
Match Criteria Value Effect
XkbSI_NoneOf (0) None of the bits that are on in mods can be set, but other bits can be.
XkbSI_AnyOfOrNone (1) Zero or more of the bits that are on in mods can be set, as well as others.
XkbSI_AnyOf (2) One or more of the bits that are on in mods can be set, as well as any others.
XkbSI_AllOf (3) All of the bits that are on in mods must be set, but others may be set as well.
XkbSI_Exactly (4) All of the bits that are on in mods must be set, and no other bits may be set.

In addition to the above bits, match may contain the XkbSI_LevelOneOnly bit, in which case the modifier match criteria specified by mods and match applies only if sym is in level one of its group; otherwise, mods and match are ignored and the symbol matches a condition where no modifiers are set.

#define XkbSI_LevelOneOnly  (0x80)  /* use mods + match only if sym is level 1 */
If no matching symbol interpretation is found, the server uses a default interpretation where: 
    sym =           0
    flags =         XkbSI_AutoRepeat
    match =         XkbSI_AnyOfOrNone
    mods =          0
    virtual_mod =   XkbNoModifier
    act =           SA_NoAction
When a matching symbol interpretation is found in step 2a, the interpretation is applied to modify the Xkb map as follows.

The act field specifies a single action to be bound to the symbol position; any key event that selects the symbol causes the action to be taken. Valid actions are defined in Key Actions.

If the Xkb keyboard map for the key does not have its ExplicitVModMap control set, the XkbSI_LevelOneOnly bit and symbol position are examined. If the XkbSI_LevelOneOnly bit is not set in match or the symbol is in position G1L1, the virtual_mod field is examined. If virtual_mod is not XkbNoModifier, virtual_mod specifies a single virtual modifier to be added to the virtual modifier map for the key. virtual_mod is specified as an index in the range [0..15].

If the matching symbol is in position G1L1 of the key, two bits in the flags field potentially specify additional behavior modifications:

#define  XkbSI_AutoRepeat  (1<<0)  /* key repeats if sym is in position G1L1 */
#define  XkbSI_LockingKey  (1<<1)  /* set KB_Lock behavior if sym is in psn G1L1 */
If the Xkb keyboard map for the key does not have its ExplicitAutoRepeat control set, its auto repeat behavior is set based on the value of the XkbSI_AutoRepeat bit. If the XkbSI_AutoRepeat bit is set, the auto-repeat behavior of the key is turned on; otherwise, it is turned off.

If the Xkb keyboard map for the key does not have its ExplicitBehavior control set, its locking behavior is set based on the value of the XkbSI_LockingKey bit. If XkbSI_LockingKey is set, the key behavior is set to KB_Lock; otherwise, it is turned off.
