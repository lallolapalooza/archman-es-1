NOMBRE


Xrandr - Extensión X de redimensionamiento, rotación y reflexión.

ARGUMENTOS

display
Especifica la conexión con el servidor X.
screen
Especifica qué pantalla.
draw
Especifica la pantalla.
rotation
Especifica las posibles rotaciones o reflexiones de la pantalla.
current_rotation
Especifica las rotaciones y reflexión actuales de la pantalla.
timestamp
Especifica la marca de tiempo del servidor.
config_timestamp
Especifica la marca de tiempo de cuándo se configuró (o reconfiguró) la pantalla por última vez.
config
Especifica la configuración de pantalla que se está utilizando.
sizes
Especifica la matriz de tamaños admitidos.
rate
Especifica la frecuencia de actualización en Hz.

TIPOS DE DATOS

Rotaciones/Reflexiones

Puede ser cualquiera de:

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nuevo en el protocolo 1.0, para permitir la reflexión de la pantalla */
/∗ la reflexión se aplica después de la rotación */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base del evento */
    unsigned long serial;	/∗ # de la última solicitud procesada por el servidor */
    Bool send_event;		/∗ true si esto provino de una solicitud SendEvent */
    Display *display;		/∗ Pantalla de la que se leyó el evento */
    Window window;			/∗ ventana que seleccionó este evento */
    Window root;			/∗ Ventana raíz para la pantalla cambiada */
    Time timestamp;			/∗ cuándo ocurrió el cambio de pantalla */
    Time config_timestamp;	/∗ cuándo fue la última configuración cambiada */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La estructura XRRScreenSize contiene un tamaño raíz posible en píxeles y en milímetros.

Un XRRScreenChangeNotifyEvent se envía a un cliente que ha solicitado notificación cada vez que se cambia la configuración de la pantalla. Un cliente puede realizar esta solicitud llamando a XRRSelectInput, pasando la pantalla, la ventana raíz y la máscara RRScreenChangeNotifyMask.

XRRScreenConfiguration es un tipo de dato opaco que contiene la información de configuración para una pantalla.

Marcas de tiempo

Se incluyen marcas de tiempo y deben usarse para asegurar que el cliente está jugando con todas las cartas: la pantalla puede cambiar sus propiedades sobre la marcha y esto asegura que su conocimiento de la configuración esté actualizado. Esto es para ayudar con problemas cuando las pantallas puedan ser conectables en caliente en el futuro.

DESCRIPCIÓN

Xrandr es una biblioteca simple diseñada para interactuar con la extensión X de Redimensionamiento y Rotación. Esto permite a los clientes cambiar el tamaño y la rotación de la ventana raíz de una pantalla, junto con la capacidad de reflejar la pantalla sobre cualquier eje (si es compatible con la implementación). La rotación y la reflexión pueden ser implementadas por software y pueden resultar en un rendimiento más lento si la rotación y la reflexión se implementan de esta manera (como lo son todas las implementaciones en octubre de 2002).

La biblioteca Xrandr realiza un almacenamiento en caché mínimo para evitar viajes de ida y vuelta y proporcionar a los clientes información de uso frecuente. Consulte "The X Resize and Rotate Extension" para obtener una descripción detallada; tenga en cuenta también que el cambio de profundidad, como se describe en el documento, no está implementado y puede que nunca se implemente, ya que la memoria de pantalla está creciendo rápidamente y los kits de herramientas ya están comenzando a admitir la migración, mitigando la necesidad de cambiar de profundidad. Si se implementa en el futuro, esperamos hacerlo a través de una extensión compatible hacia arriba con la biblioteca/protocolo actual; la funcionalidad descrita aquí debería seguir funcionando.

La rotación y la reflexión y cómo interactúan pueden ser confusas. En Randr, el sistema de coordenadas se rota en sentido antihorario con respecto a la orientación normal. La reflexión es a lo largo del sistema de coordenadas del sistema de ventanas, no los ejes X e Y físicos de la pantalla, de modo que la rotación y la reflexión no interactúen. La otra forma de considerar la reflexión es tratarla como se especifica en la orientación "normal", antes de la rotación.

El evento XRRScreenChangeNotify se envía a los clientes que piden ser informados cada vez que cambian la configuración de la ventana raíz. Los cambios de configuración pueden incluir resolución, tamaño físico, orden de subpíxeles (ver XRender(3)) y rotación. Tenga en cuenta que los cambios en cualquiera o en todos estos podrían ocurrir debido a eventos externos (control del usuario en el servidor X, conexión en caliente de un monitor/panel plano diferente) y no son solo el resultado de una solicitud de protocolo/biblioteca al servidor X.

Además, para eliminar una posible condición de carrera, este evento puede generarse inmediatamente al seleccionar la notificación si la pantalla ha cambiado desde que el cliente de Xrandr se conectó al servidor X, para permitir un cambio de resolución de pantalla confiable cuando un usuario puede iniciar sesión y cambiar la configuración mientras uno o varios clientes se están iniciando.

Notificación de Xlib

Los clientes deben volver a llamar a Xlib usando XRRUpdateConfiguration cuando se generan eventos de notificación de cambio de configuración de pantalla (o ocurren cambios de configuración de la ventana raíz, para actualizar la vista de Xlib de la resolución, tamaño, rotación, reflexión o orden de subpíxeles. En general, los kits de herramientas realizarán esta operación en nombre de las aplicaciones; no queríamos cambiar los datos de la estructura de visualización a espaldas de los kits de herramientas, ya que en clientes multihilo, podrían ocurrir varias condiciones de carrera. Los kits de herramientas deberían proporcionar a los clientes algún mecanismo para la notificación de cambios de pantalla, por supuesto.

FUNCIONES

XRRQueryExtension:

Comprueba si la extensión RandR está disponible y, en caso afirmativo, devuelve el número base del evento y del error.

XRRQueryVersion:

Consulta la versión del protocolo RandR implementada por el servidor.

XRRGetScreenInfo:

Obtiene la configuración actual de la pantalla (resolución, rotación, etc.) para la pantalla especificada por `draw`.

XRRFreeScreenConfigInfo:

Libera la memoria asignada por XRRGetScreenInfo.

XRRSetScreenConfig:

Establece la configuración de la pantalla. Requiere una marca de tiempo válida para evitar condiciones de carrera.

XRRSetScreenConfigAndRate:

Establece la configuración de la pantalla y la frecuencia de actualización. Requiere una marca de tiempo válida.

XRRConfigRotations:

Devuelve las rotaciones admitidas para la configuración actual de la pantalla y la rotación actual.

XRRConfigTimes:

Devuelve la marca de tiempo de la configuración actual y la marca de tiempo de la última configuración.

XRRConfigSizes:

Devuelve los tamaños de pantalla admitidos para la configuración actual y el número de tamaños.

XRRConfigRates:

Devuelve las frecuencias de actualización admitidas para un tamaño de pantalla específico y el número de frecuencias.

XRRConfigCurrentConfiguration:

Devuelve la configuración de tamaño actual y la rotación actual de la pantalla.

XRRConfigCurrentRate:

Devuelve la frecuencia de actualización actual de la pantalla.

XRRRootToScreen:

Dado un identificador de ventana raíz, devuelve el número de pantalla asociado. Útil para determinar en qué pantalla se encuentra una ventana.

XRRSelectInput:

Permite a un cliente recibir notificaciones de cambios en la configuración de la pantalla (por ejemplo, cambios de resolución, rotación). Se requiere la máscara RRScreenChangeNotifyMask para recibir el evento RRScreenChangeNotifyEvent.

XRRUpdateConfiguration:

Procesa eventos relacionados con cambios en la configuración de la pantalla (como RRScreenChangeNotifyEvent o ConfigureNotify en la ventana raíz). Devuelve 1 si el evento es reconocido, 0 en caso contrario. Es importante llamar a esta función cuando se reciben dichos eventos para mantener la información de configuración actualizada dentro de Xlib.

Las siguientes funciones proporcionan una forma de consultar la información de la pantalla sin necesidad de obtener un `XRRScreenConfiguration` primero. Son seguras de llamar incluso si RandR no está implementado.

XRRRotations:

Devuelve las rotaciones posibles y la rotación actual para una pantalla específica en un servidor X determinado.

XRRSizes:

Devuelve los tamaños de pantalla admitidos y el número de tamaños para una pantalla específica en un servidor X determinado.

XRRRates:

Devuelve las frecuencias de actualización admitidas para un tamaño de pantalla específico en una pantalla determinada de un servidor X determinado.

XRRTimes:

Devuelve la marca de tiempo de la configuración actual y la marca de tiempo de la última configuración para una pantalla específica en un servidor X determinado.

VER TAMBIÉN

X(7), Xrender(3)

Hay dos clases de interfaces: aquellas que se pueden llamar de forma segura incluso si RandR no está implementado en una pantalla (para hacer que los modismos comunes no dependan del soporte del servidor) y aquellas que devolverán errores si la extensión no está presente.

XRRRotations devuelve tanto el conjunto de rotaciones/reflexiones posibles soportadas (como una máscara de bits) como el valor de la función, junto con la rotación/reflexión actual de la pantalla.

XRRSizes devuelve el tamaño y un puntero a los tamaños actuales soportados por la pantalla especificada. El primer tamaño especificado es el tamaño predeterminado del servidor. Si RandR no es compatible, devuelve 0 para el número de tamaños.

XRRRates devuelve un puntero a las tasas soportadas por el tamaño especificado. Si RandR no es compatible, devuelve 0 para el número de tasas.

XRRTimes devuelve la hora reportada por última vez por el servidor junto con la marca de tiempo del último cambio de configuración. Si la configuración ha cambiado desde que el cliente actualizó por última vez su vista de la hora del servidor, las solicitudes para cambiar la configuración fallarán hasta que el cliente tenga una marca de tiempo actualizada.

XRRRootToScreen devuelve el número de pantalla dado una ventana raíz (por ejemplo, de un XRRScreenChangeNotifyEvent).

El resto de las funciones fallarán si se aplican a pantallas que no implementan la extensión RandR. XRRSetScreenConfig establece el tamaño de la pantalla y la rotación y reflexión a los valores deseados en la pantalla especificada por draw, o devuelve un error BadValue. size_index especifica qué configuración de tamaño se utilizará, rotation especifica qué rotación o reflexión se utilizará (o se devuelve un error BadValue). La timestamp es utilizada por el servidor para asegurarse de que el cliente tiene información de configuración actualizada. Se devuelve un estado para indicar éxito o fracaso; un cliente debe actualizar su información de configuración si falla y volver a intentar la llamada (llamando a XRRGetScreenInfo).

XRRSetScreenConfigAndRate es similar a XRRSetScreenConfig pero también establece la tasa de refresco. Si la tasa especificada no es compatible, se devuelve un error BadValue.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, y XRRConfigCurrentRate se utilizan para obtener información de configuración específica de una configuración de pantalla.

XRRGetScreenInfo devuelve una configuración de pantalla para su uso posterior; la información es privada para la biblioteca. Llame a XRRFreeScreenConfigInfo para liberar esta información cuando haya terminado con ella. Fuerza un viaje de ida y vuelta al servidor.

Otras funciones incluyen: XRRQueryExtension que devuelve los códigos base de eventos y errores, XRRQueryVersion, que devuelve la versión actual de la extensión (esta información está almacenada en caché por la biblioteca).

RESTRICCIONES

Xrandr seguirá siendo compatible con versiones anteriores después del lanzamiento actual 1.0.
