XrmGetFileDatabase(3) XLIB FUNCTIONS XrmGetFileDatabase(3)

NOMBRE

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - recuperar y almacenar bases de datos de recursos

SINTAXIS

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *nombre_archivo);

void XrmPutFileDatabase(XrmDatabase base_datos, _Xconst char *db_almacenado);

XrmDatabase XrmGetStringDatabase(_Xconst char *datos);

const char *XrmLocaleOfDatabase(XrmDatabase base_datos);

XrmDatabase XrmGetDatabase(Display *display);

void XrmSetDatabase(Display *display, XrmDatabase base_datos);

void XrmDestroyDatabase(XrmDatabase base_datos);

ARGUMENTOS

nombre_archivo
Especifica el nombre del archivo de la base de datos de recursos.
base_datos
Especifica la base de datos que se va a utilizar.
db_almacenado
Especifica el nombre del archivo para la base de datos almacenada.
datos
Especifica el contenido de la base de datos usando una cadena de texto.
base_datos
Especifica la base de datos de recursos.
display
Especifica la conexión con el servidor X.

DESCRIPCIÓN

La función XrmGetFileDatabase abre el archivo especificado, crea una nueva base de datos de recursos y la carga con las especificaciones leídas del archivo especificado. El archivo especificado debe contener una secuencia de entradas en formato válido de ResourceLine (ver sección 15.1); la base de datos resultante de leer un archivo con sintaxis incorrecta es dependiente de la implementación. El archivo se analiza en la configuración regional actual y la base de datos se crea en la configuración regional actual. Si no puede abrir el archivo especificado, XrmGetFileDatabase devuelve NULL.

La función XrmPutFileDatabase almacena una copia de la base de datos especificada en el archivo especificado. El texto se escribe en el archivo como una secuencia de entradas en formato válido de ResourceLine (ver sección 15.1). El archivo se escribe en la configuración regional de la base de datos. Las entradas que contienen nombres de recursos que no están en la codificación de caracteres portátil del host o que contienen valores que no están en la codificación de la configuración regional de la base de datos, se escriben de una manera dependiente de la implementación. El orden en que se escriben las entradas es dependiente de la implementación. Se ignoran las entradas con tipos de representación distintos de "String".

La función XrmGetStringDatabase crea una nueva base de datos y almacena los recursos especificados en la cadena terminada en nulo especificada. XrmGetStringDatabase es similar a XrmGetFileDatabase excepto que lee la información de una cadena en lugar de un archivo. La cadena debe contener una secuencia de entradas en formato válido de ResourceLine (ver sección 15.1) terminada por un carácter nulo; la base de datos resultante de usar una cadena con sintaxis incorrecta es dependiente de la implementación. La cadena se analiza en la configuración regional actual y la base de datos se crea en la configuración regional actual.

Si database es NULL, XrmDestroyDatabase retorna inmediatamente.

La función XrmLocaleOfDatabase devuelve el nombre de la configuración regional vinculada a la base de datos especificada, como una cadena terminada en nulo. La cadena de nombre de configuración regional devuelta pertenece a Xlib y no debe ser modificada ni liberada por el cliente. A Xlib no se le permite liberar la cadena hasta que se destruya la base de datos. Hasta que la cadena sea liberada, no será modificada por Xlib.

La función XrmGetDatabase devuelve la base de datos asociada con la pantalla especificada. Devuelve NULL si aún no se ha establecido una base de datos.

La función XrmSetDatabase asocia la base de datos de recursos especificada (o NULL) con la pantalla especificada. La base de datos previamente asociada con la pantalla (si la hay) no se destruye. Una aplicación o toolkit puede encontrar esta función útil para retener una base de datos una vez que se ha construido.

SINTAXIS DE ARCHIVO

La sintaxis de un archivo de recursos es una secuencia de líneas de recursos terminadas por caracteres de nueva línea o el final del archivo. La sintaxis de una línea de recursos individual es:

ResourceLine	=	Comment | IncludeFile | ResourceSpec | <línea vacía>
Comment	=	"!" {<cualquier carácter excepto nulo o nueva línea>}
IncludeFile	=	"#" WhiteSpace "include" WhiteSpace FileName WhiteSpace
FileName	=	<nombre de archivo válido para el sistema operativo>
ResourceSpec	=	WhiteSpace ResourceName WhiteSpace ":" WhiteSpace Value
ResourceName	=	[Binding] {Component Binding} ComponentName
Binding	=	"." | "*"
WhiteSpace	=	{<espacio> | <tabulación horizontal>}
Component	=	"?" | ComponentName
ComponentName	=	NameChar {NameChar}
NameChar	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Value	=	{<cualquier carácter excepto nulo o nueva línea sin escapar>}

Los elementos separados por barra vertical (|) son alternativas. Las llaves ({...}) indican cero o más repeticiones de los elementos encerrados. Los corchetes ([...]) indican que el elemento encerrado es opcional. Las comillas ("...") se usan alrededor de caracteres literales.

Las líneas IncludeFile se interpretan reemplazando la línea con el contenido del archivo especificado. La palabra "include" debe estar en minúsculas. El nombre del archivo se interpreta en relación con el directorio del archivo en el que se produce la línea (por ejemplo, si el nombre del archivo no contiene directorio o contiene una especificación de directorio relativa).

Si un ResourceName contiene una secuencia contigua de dos o más caracteres de Binding, la secuencia se reemplazará con un solo carácter "." si la secuencia contiene solo caracteres "."; de lo contrario, la secuencia se reemplazará con un solo carácter "*".

Una base de datos de recursos nunca contiene más de una entrada para un ResourceName dado. Si un archivo de recursos contiene varias líneas con el mismo ResourceName, se utiliza la última línea del archivo.

Cualquier carácter de espacio en blanco antes o después del nombre o dos puntos en un ResourceSpec se ignora. Para permitir que un Value comience con un espacio en blanco, se reconoce la secuencia de dos caracteres "\" (barra invertida seguida de espacio) y se reemplaza por un carácter de espacio, y la secuencia de dos caracteres "\" (barra invertida seguida de tabulación horizontal) se reconoce y se reemplaza por un carácter de tabulación horizontal. Para permitir que un Value contenga caracteres de nueva línea incrustados, se reconoce la secuencia de dos caracteres "\n" y se reemplaza por un carácter de nueva línea. Para permitir que un Value se divida en varias líneas en un archivo de texto, se reconoce la secuencia de dos caracteres "\"" (barra invertida seguida de nueva línea) y se elimina del valor. Para permitir que un Value contenga códigos de carácter arbitrarios, se reconoce la secuencia de cuatro caracteres "\", donde cada n es un dígito en el rango de "0"-"7", y se reemplaza con un solo byte que contiene el valor octal especificado por la secuencia. Finalmente, se reconoce la secuencia de dos caracteres "\\" y se reemplaza por una sola barra invertida.
