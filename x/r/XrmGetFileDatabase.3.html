XrmGetFileDatabase(3) FUNCIONES DE XLIB XrmGetFileDatabase(3)

NOMBRE

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - recuperar y almacenar bases de datos de recursos

SINTAXIS

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *nombre_archivo);

void XrmPutFileDatabase(XrmDatabase base_de_datos, _Xconst char *db_almacenado);

XrmDatabase XrmGetStringDatabase(_Xconst char *datos);

const char *XrmLocaleOfDatabase(XrmDatabase base_de_datos);

XrmDatabase XrmGetDatabase(Display *display);

void XrmSetDatabase(Display *display, XrmDatabase base_de_datos);

void XrmDestroyDatabase(XrmDatabase base_de_datos);

ARGUMENTOS

nombre_archivo
Especifica el nombre del archivo de la base de datos de recursos.
base_de_datos
Especifica la base de datos que se va a utilizar.
db_almacenado
Especifica el nombre del archivo para la base de datos almacenada.
datos
Especifica el contenido de la base de datos utilizando una cadena.
base_de_datos
Especifica la base de datos de recursos.
display
Especifica la conexión con el servidor X.

DESCRIPCIÓN

La función XrmGetFileDatabase abre el archivo especificado, crea una nueva base de datos de recursos y la carga con las especificaciones leídas del archivo especificado. El archivo especificado debe contener una secuencia de entradas en formato válido de Línea de Recursos (ver sección 15.1); la base de datos resultante de leer un archivo con sintaxis incorrecta depende de la implementación. El archivo se analiza en la configuración regional actual y la base de datos se crea en la configuración regional actual. Si no puede abrir el archivo especificado, XrmGetFileDatabase devuelve NULL.

La función XrmPutFileDatabase almacena una copia de la base de datos especificada en el archivo especificado. El texto se escribe en el archivo como una secuencia de entradas en formato válido de Línea de Recursos (ver sección 15.1). El archivo se escribe en la configuración regional de la base de datos. Las entradas que contienen nombres de recursos que no están en la Codificación de Caracteres Portátil del Host o que contienen valores que no están en la codificación de la configuración regional de la base de datos, se escriben de manera dependiente de la implementación. El orden en que se escriben las entradas depende de la implementación. Las entradas con tipos de representación distintos de “String” se ignoran.

La función XrmGetStringDatabase crea una nueva base de datos y almacena los recursos especificados en la cadena terminada en nulo especificada. XrmGetStringDatabase es similar a XrmGetFileDatabase excepto que lee la información de una cadena en lugar de un archivo. La cadena debe contener una secuencia de entradas en formato válido de Línea de Recursos (ver sección 15.1) terminada por un carácter nulo; la base de datos resultante de usar una cadena con sintaxis incorrecta depende de la implementación. La cadena se analiza en la configuración regional actual y la base de datos se crea en la configuración regional actual.

Si base_de_datos es NULL, XrmDestroyDatabase devuelve inmediatamente.

La función XrmLocaleOfDatabase devuelve el nombre de la configuración regional vinculada a la base de datos especificada, como una cadena terminada en nulo. La cadena de nombre de configuración regional devuelta es propiedad de Xlib y no debe ser modificada ni liberada por el cliente. Xlib no tiene permiso para liberar la cadena hasta que la base de datos se destruya. Hasta que la cadena se libere, Xlib no la modificará.

La función XrmGetDatabase devuelve la base de datos asociada con la pantalla especificada. Devuelve NULL si aún no se ha establecido una base de datos.

La función XrmSetDatabase asocia la base de datos de recursos especificada (o NULL) con la pantalla especificada. La base de datos previamente asociada con la pantalla (si la hubo) no se destruye. Un cliente o kit de herramientas puede encontrar útil esta función para retener una base de datos una vez construida.

SINTAXIS DE ARCHIVO

La sintaxis de un archivo de recursos es una secuencia de líneas de recursos terminadas por caracteres de nueva línea o el final del archivo. La sintaxis de una línea de recursos individual es:

LineaRecurso	=	Comentario | ArchivoIncluido | EspecificacionRecurso | <línea vacía>
Comentario	=	"!" {<cualquier carácter excepto nulo o nueva línea>}
ArchivoIncluido	=	"#" EspacioBlanco "include" EspacioBlanco NombreArchivo EspacioBlanco
NombreArchivo	=	<nombre de archivo válido para el sistema operativo>
EspecificacionRecurso	=	EspacioBlanco NombreRecurso EspacioBlanco ":" EspacioBlanco Valor
NombreRecurso	=	[Vinculacion] {Componente Vinculacion} ComponenteNombre
Vinculacion	=	"." | "*"
EspacioBlanco	=	{<espacio> | <tabulador horizontal>}
Componente	=	"?" | ComponenteNombre
ComponenteNombre	=	CaracNombreChar {CaracNombreChar}
CaracNombreChar	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Valor	=	{<cualquier carácter excepto nulo o nueva línea sin escapar>}

Los elementos separados por barra vertical (|) son alternativas. Las llaves ({...}) indican cero o más repeticiones de los elementos encerrados. Los corchetes ([...]) indican que el elemento encerrado es opcional. Las comillas ("...") se utilizan alrededor de caracteres literales.

Las líneas de ArchivoIncluido se interpretan reemplazando la línea con el contenido del archivo especificado. La palabra “include” debe estar en minúsculas. El nombre del archivo se interpreta en relación con el directorio del archivo en el que se encuentra la línea (por ejemplo, si el nombre del archivo no contiene directorio o contiene una especificación de directorio relativa).

Si un NombreRecurso contiene una secuencia contigua de dos o más caracteres Vinculacion, la secuencia se reemplazará con un único carácter “.” si la secuencia contiene solo caracteres “.”; de lo contrario, la secuencia se reemplazará con un único carácter “*”.

Una base de datos de recursos nunca contiene más de una entrada para un dado NombreRecurso. Si un archivo de recursos contiene varias líneas con el mismo NombreRecurso, se utiliza la última línea del archivo.

Cualquier carácter de espacio en blanco antes o después del nombre o los dos puntos en una EspecificacionRecurso se ignora. Para permitir que un Valor comience con un espacio en blanco, se reconoce la secuencia de dos caracteres “\espacio” (barra invertida seguida de espacio) y se reemplaza por un carácter de espacio, y se reconoce la secuencia de dos caracteres “\tab” (barra invertida seguida de tabulador horizontal) y se reemplaza por un carácter de tabulador horizontal. Para permitir que un Valor contenga caracteres de nueva línea incrustados, se reconoce la secuencia de dos caracteres “\n” y se reemplaza por un carácter de nueva línea. Para permitir que un Valor se divida en múltiples líneas en un archivo de texto, se reconoce la secuencia de dos caracteres “\nueva línea” (barra invertida seguida de nueva línea) y se elimina del valor. Para permitir que un Valor contenga códigos de caracteres arbitrarios, se reconoce la secuencia de cuatro caracteres “\nnn”, donde cada n es un carácter dígito en el rango de “0”-“7”, y se reemplaza con un solo byte que contiene el valor octal especificado por la secuencia. Finalmente, se reconoce la secuencia de dos caracteres “\\” y se reemplaza por una sola barra invertida.

XrmGetFileDatabase

NOMBRE

XrmGetFileDatabase - Obtiene una base de datos de recursos de un archivo.

SINTAXIS

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(const char *filename);

ARGUMENTOS

filename
El nombre del archivo que contiene la base de datos de recursos.

DESCRIPCIÓN

La función XrmGetFileDatabase lee la base de datos de recursos especificada por filename y devuelve un puntero a la estructura XrmDatabase recién creada. Si ocurre un error durante la lectura del archivo, la función devuelve NULL.

La base de datos de recursos se utiliza para almacenar configuraciones y opciones para aplicaciones X. Permite a los usuarios personalizar el comportamiento de las aplicaciones sin necesidad de modificar su código fuente.

SINTAXIS DE ARCHIVO

El archivo especificado por filename debe estar en el formato de base de datos de recursos de X. Este formato es un archivo de texto plano donde cada línea define una entrada de recurso. Las entradas tienen el siguiente formato general:

NombreDelRecurso.NombreDelWidget: Valor
  • NombreDelRecurso: El nombre del recurso (por ejemplo, foregroundColor).
  • NombreDelWidget: El nombre del widget al que se aplica el recurso (por ejemplo, XTerm).
  • Valor: El valor del recurso.

Los comentarios en el archivo comienzan con un signo de exclamación (!).
