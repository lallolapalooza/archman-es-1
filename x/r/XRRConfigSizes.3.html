TIPOS DE DATOS

Rotaciones/Reflejos

Puede ser cualquiera de:

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nuevo en el protocolo 1.0, para permitir el reflejo de la pantalla */
/∗ el reflejo se aplica después de la rotación */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base del evento */
    unsigned long serial;	/∗ # de la última solicitud procesada por el servidor */
    Bool send_event;		/∗ true si esto provino de una solicitud SendEvent */
    Display *display;		/∗ Display del que se leyó el evento */
    Window window;			/∗ ventana que seleccionó este evento */
    Window root;			/∗ Ventana raíz para pantalla modificada */
    Time timestamp;			/∗ cuándo ocurrió el cambio de pantalla */
    Time config_timestamp;	/∗ cuándo fue el último cambio de configuración */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La estructura XRRScreenSize contiene un tamaño de raíz posible en píxeles y en milímetros.

Se envía un XRRScreenChangeNotifyEvent a un cliente que ha solicitado notificación cada vez que se cambia la configuración de la pantalla. Un cliente puede realizar esta solicitud llamando a XRRSelectInput, pasando la pantalla, la ventana raíz y la máscara RRScreenChangeNotifyMask.

XRRScreenConfiguration es un tipo de dato opaco que contiene la información de configuración para una pantalla.

Marcas de tiempo

Se incluyen marcas de tiempo y deben usarse para garantizar que el cliente está al día: la pantalla puede cambiar propiedades sobre la marcha y esto asegura que su conocimiento de la configuración esté actualizado. Esto es para ayudar con problemas cuando las pantallas pueden ser conectables en caliente en el futuro.

DESCRIPCIÓN

Xrandr es una biblioteca simple diseñada para interactuar con la Extensión de X para Redimensionar y Rotar. Esto permite a los clientes cambiar el tamaño y la rotación de la ventana raíz de una pantalla, junto con la capacidad de reflejar la pantalla sobre cualquier eje (si es compatible con la implementación). La rotación y el reflejo pueden ser implementados por software y pueden resultar en un rendimiento más lento si la rotación y el reflejo se implementan de esta manera (como lo son todas las implementaciones en octubre de 2002).

La biblioteca Xrandr realiza un almacenamiento en caché mínimo para evitar viajes de ida y vuelta y proporcionar a los clientes información de uso frecuente. Consulte "The X Resize and Rotate Extension" para obtener una descripción detallada; tenga en cuenta también que el cambio de profundidad, como se describe en el documento, no está implementado y puede (o no) ser implementado, ya que la memoria de visualización está creciendo rápidamente y los toolkits ya están comenzando a admitir la migración, mitigando la necesidad de cambiar la profundidad. Si se implementa en el futuro, esperamos hacerlo a través de una extensión compatible hacia atrás con la biblioteca/protocolo actual; la funcionalidad descrita aquí debería seguir funcionando.

La rotación y el reflejo y cómo interactúan pueden ser confusos. En Randr, el sistema de coordenadas se rota en sentido antihorario con respecto a la orientación normal. El reflejo se produce a lo largo del sistema de coordenadas del sistema de ventanas, no de los ejes X e Y físicos de la pantalla, de modo que la rotación y el reflejo no interactúan. La otra forma de considerar el reflejo es tratarlo como se especifica en la orientación "normal", antes de la rotación.

El evento XRRScreenChangeNotify se envía a los clientes que solicitan ser informados cada vez que cambia la configuración de la ventana raíz. Los cambios de configuración pueden incluir resolución, tamaño físico, orden de subpíxeles (ver XRender(3)) y rotación. Tenga en cuenta que los cambios en cualquiera o todos estos pueden ocurrir debido a eventos externos (control del usuario en el servidor X, conexión/desconexión de un monitor/panel plano diferente) y no son solo el resultado de una solicitud de protocolo/biblioteca al servidor X.

Además, para eliminar una posible condición de carrera, este evento puede generarse inmediatamente al seleccionar la notificación si la pantalla ha cambiado desde que el cliente de Xrandr se conectó al servidor X, para permitir un cambio de resolución de pantalla fiable cuando un usuario puede iniciar sesión y cambiar la configuración mientras uno o varios clientes se inician.

Notificación de Xlib

Los clientes deben volver a llamar a Xlib utilizando XRRUpdateConfiguration cuando se generen eventos de notificación de cambio de configuración de pantalla (o ocurran cambios de configuración de la ventana raíz, para actualizar la vista de Xlib de la resolución, tamaño, rotación, reflejo u orden de subpíxeles. En general, los toolkits realizarán esta operación en nombre de las aplicaciones; no queríamos cambiar los datos de la estructura de pantalla a espaldas de los toolkits, ya que en clientes multihilo, podrían ocurrir varias condiciones de carrera. Los toolkits deberían proporcionar a los clientes algún mecanismo de notificación de cambio de pantalla, por supuesto.

FUNCIONES

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Existen dos clases de interfaces: aquellas que se pueden llamar de forma segura incluso si RandR no se implementa en una pantalla (para hacer que los modismos comunes no dependan de que el servidor tenga soporte), y aquellas que devolverán errores si la extensión no está presente.

XRRRotations devuelve tanto el conjunto de rotaciones/reflexiones posibles compatibles (como una máscara de bits) como el valor de la función, junto con la rotación/reflexión actual de la pantalla.

XRRSizes devuelve el tamaño y un puntero a los tamaños actuales compatibles con la pantalla especificada. El primer tamaño especificado es el tamaño predeterminado del servidor. Si RandR no es compatible, devuelve 0 para el número de tamaños.

XRRRates devuelve un puntero a las tasas compatibles con el tamaño especificado. Si RandR no es compatible, devuelve 0 para el número de tasas.

XRRTimes devuelve la hora notificada por última vez por el servidor junto con la marca de tiempo del último cambio de configuración. Si la configuración ha cambiado desde la última vez que el cliente actualizó su vista de la hora del servidor, las solicitudes para cambiar la configuración fallarán hasta que el cliente tenga una marca de tiempo actualizada.

XRRRootToScreen devuelve el número de pantalla dado una ventana raíz (por ejemplo, de un XRRScreenChangeNotifyEvent).

El resto de las funciones fallarán si se aplican a pantallas que no implementan la extensión RandR. XRRSetScreenConfig establece el tamaño y la rotación/reflexión de la pantalla a los valores deseados en la pantalla especificada por draw, o devuelve un error BadValue. size_index especifica qué configuración de tamaño se va a utilizar, rotation especifica qué rotación o reflexión se va a utilizar (o se devuelve un error BadValue). La timestamp es utilizada por el servidor para asegurarse de que el cliente tiene información de configuración actualizada. El estado se devuelve para indicar éxito o fracaso; un cliente debe actualizar su información de configuración si falla y volver a intentar la llamada (llamando a XRRGetScreenInfo).

XRRSetScreenConfigAndRate es similar a XRRSetScreenConfig pero también establece la tasa de refresco. Si la tasa especificada no es compatible, se devuelve un error BadValue.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, y XRRConfigCurrentRate se utilizan para obtener información de configuración específica de una configuración de pantalla.

XRRGetScreenInfo devuelve una configuración de pantalla para su uso posterior; la información es privada de la biblioteca. Llame a XRRFreeScreenConfigInfo para liberar esta información cuando haya terminado con ella. Obliga a un viaje de ida y vuelta al servidor.

Otras funciones incluyen: XRRQueryExtension que devuelve los códigos base de eventos y errores, XRRQueryVersion, que devuelve la versión actual de la extensión (esta información es almacenada en caché por la biblioteca).

RESTRICCIONES

Xrandr seguirá siendo compatible con versiones anteriores después del lanzamiento actual 1.0.
