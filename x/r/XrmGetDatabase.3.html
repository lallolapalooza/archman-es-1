XrmGetFileDatabase(3) FUNCIONES XLIB XrmGetFileDatabase(3)

NOMBRE

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - recuperar y almacenar bases de datos de recursos

SINTAXIS

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *filename);

void XrmPutFileDatabase(XrmDatabase database, _Xconst char *stored_db);

XrmDatabase XrmGetStringDatabase(_Xconst char *data);

const char *XrmLocaleOfDatabase(XrmDatabase database);

XrmDatabase XrmGetDatabase(Display *display);

void XrmSetDatabase(Display *display, XrmDatabase database);

void XrmDestroyDatabase(XrmDatabase database);

ARGUMENTOS

filename
Especifica el nombre del archivo de la base de datos de recursos.
database
Especifica la base de datos que se va a utilizar.
stored_db
Especifica el nombre del archivo para la base de datos almacenada.
data
Especifica el contenido de la base de datos utilizando una cadena.
database
Especifica la base de datos de recursos.
display
Especifica la conexión con el servidor X.

DESCRIPCIÓN

La función XrmGetFileDatabase abre el archivo especificado, crea una nueva base de datos de recursos y la carga con las especificaciones leídas del archivo especificado. El archivo especificado debe contener una secuencia de entradas en formato ResourceLine válido (ver sección 15.1); la base de datos resultante de leer un archivo con sintaxis incorrecta es dependiente de la implementación. El archivo se analiza en la configuración regional actual y la base de datos se crea en la configuración regional actual. Si no puede abrir el archivo especificado, XrmGetFileDatabase devuelve NULL.

La función XrmPutFileDatabase almacena una copia de la base de datos especificada en el archivo especificado. El texto se escribe en el archivo como una secuencia de entradas en formato ResourceLine válido (ver sección 15.1). El archivo se escribe en la configuración regional de la base de datos. Las entradas que contienen nombres de recursos que no están en la Codificación de Caracteres Portátil del Host o que contienen valores que no están en la codificación de la configuración regional de la base de datos, se escriben de una manera dependiente de la implementación. El orden en que se escriben las entradas es dependiente de la implementación. Las entradas con tipos de representación distintos de “String” se ignoran.

La función XrmGetStringDatabase crea una nueva base de datos y almacena los recursos especificados en la cadena terminada en nulo especificada. XrmGetStringDatabase es similar a XrmGetFileDatabase excepto que lee la información de una cadena en lugar de un archivo. La cadena debe contener una secuencia de entradas en formato ResourceLine válido (ver sección 15.1) terminada por un carácter nulo; la base de datos resultante de usar una cadena con sintaxis incorrecta es dependiente de la implementación. La cadena se analiza en la configuración regional actual y la base de datos se crea en la configuración regional actual.

Si database es NULL, XrmDestroyDatabase devuelve inmediatamente.

La función XrmLocaleOfDatabase devuelve el nombre de la configuración regional asociada a la base de datos especificada, como una cadena terminada en nulo. La cadena de nombre de configuración regional devuelta es propiedad de Xlib y no debe ser modificada ni liberada por el cliente. Xlib no tiene permiso para liberar la cadena hasta que la base de datos sea destruida. Hasta que la cadena sea liberada, no será modificada por Xlib.

La función XrmGetDatabase devuelve la base de datos asociada con la pantalla especificada. Devuelve NULL si aún no se ha establecido una base de datos.

La función XrmSetDatabase asocia la base de datos de recursos especificada (o NULL) con la pantalla especificada. La base de datos previamente asociada con la pantalla (si la hay) no se destruye. Un cliente o toolkit puede encontrar útil esta función para retener una base de datos una vez que ha sido construida.

SINTAXIS DE ARCHIVO

La sintaxis de un archivo de recursos es una secuencia de líneas de recursos terminadas por caracteres de nueva línea o el final del archivo. La sintaxis de una línea de recursos individual es:

ResourceLine	=	Comment | IncludeFile | ResourceSpec | <empty line>
Comment	=	"!" {<any character except null or newline>}
IncludeFile	=	"#" WhiteSpace "include" WhiteSpace FileName WhiteSpace
FileName	=	<valid filename for operating system>
ResourceSpec	=	WhiteSpace ResourceName WhiteSpace ":" WhiteSpace Value
ResourceName	=	[Binding] {Component Binding} ComponentName
Binding	=	"." | "*"
WhiteSpace	=	{<space> | <horizontal tab>}
Component	=	"?" | ComponentName
ComponentName	=	NameChar {NameChar}
NameChar	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Value	=	{<any character except null or unescaped newline>}

Los elementos separados por barra vertical (|) son alternativas. Las llaves ({...}) indican cero o más repeticiones de los elementos contenidos. Los corchetes ([...]) indican que el elemento contenido es opcional. Las comillas ("...") se utilizan alrededor de caracteres literales.

Las líneas IncludeFile se interpretan reemplazando la línea con el contenido del archivo especificado. La palabra “include” debe estar en minúsculas. El nombre del archivo se interpreta en relación con el directorio del archivo en el que se encuentra la línea (por ejemplo, si el nombre del archivo no contiene un directorio o contiene una especificación de directorio relativa).

Si un ResourceName contiene una secuencia contigua de dos o más caracteres Binding, la secuencia se reemplazará con un único carácter “.” si la secuencia contiene solo caracteres “.”; de lo contrario, la secuencia se reemplazará con un único carácter “*”.

Una base de datos de recursos nunca contiene más de una entrada para un ResourceName dado. Si un archivo de recursos contiene varias líneas con el mismo ResourceName, se utiliza la última línea del archivo.

Los caracteres de espacio en blanco antes o después del nombre o los dos puntos en un ResourceSpec se ignoran. Para permitir que un Value comience con espacio en blanco, la secuencia de dos caracteres “\espacio” (barra invertida seguida de espacio) se reconoce y se reemplaza por un carácter de espacio, y la secuencia de dos caracteres “\tab” (barra invertida seguida de tabulación horizontal) se reconoce y se reemplaza por un carácter de tabulación horizontal. Para permitir que un Value contenga caracteres de nueva línea incrustados, la secuencia de dos caracteres “\n” se reconoce y se reemplaza por un carácter de nueva línea. Para permitir que un Value se divida en varias líneas en un archivo de texto, la secuencia de dos caracteres “\newline” (barra invertida seguida de nueva línea) se reconoce y se elimina del valor. Para permitir que un Value contenga códigos de caracteres arbitrarios, la secuencia de cuatro caracteres “\nnn”, donde cada n es un dígito en el rango “0”-“7”, se reconoce y se reemplaza con un solo byte que contiene el valor octal especificado por la secuencia. Finalmente, la secuencia de dos caracteres “\\” se reconoce y se reemplaza por una sola barra invertida.

NAME

XrmGetDatabase - Obtiene la base de datos del gestor de recursos

SYNTAX

    #include <X11/Xresource.h>

    XrmDatabase XrmGetDatabase(Display *display);

ARGUMENTS

display
Especifica la conexión con el servidor X.

DESCRIPTION

La función XrmGetDatabase devuelve un puntero a la base de datos de recursos completa para el servidor X especificado.

La base de datos de recursos se compone de:

  • La base de datos de recursos que se carga desde los archivos de configuración del sistema (por ejemplo, /etc/X11/app-defaults/).
  • La base de datos de recursos que se carga desde el archivo .Xresources o .Xdefaults en el directorio principal del usuario.
  • La base de datos de recursos que se carga desde las variables de entorno XENVIRONMENT.
  • Los recursos que se pasan en la línea de comandos o se establecen mediante programas.

La base de datos de recursos es una colección de pares de nombres de recursos y sus valores asociados. Estos recursos se utilizan para configurar el comportamiento y la apariencia de las aplicaciones X.

FILE SYNTAX

La sintaxis de los archivos de recursos es la siguiente:

    Widget.resource: value

Por ejemplo:

    XTerm.geometry: 80x24+0+0
    XTerm.foreground: white
    XTerm.background: black

Esto establece el tamaño y la posición de la ventana de XTerm, así como sus colores de primer plano y fondo.
