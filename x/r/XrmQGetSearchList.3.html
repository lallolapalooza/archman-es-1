NOMBRE

XrmGetResource, XrmQGetResource, XrmQGetSearchList, XrmQGetSearchResource - recuperar recursos de base de datos y listas de búsqueda

SINTAXIS

#include <X11/Xresource.h>

Bool XrmGetResource(XrmDatabase database, char *str_name, char *str_class, char **str_type_return, XrmValue *value_return);

Bool XrmQGetResource(XrmDatabase database, XrmNameList quark_name, XrmClassList quark_class, XrmRepresentation *quark_type_return, XrmValue *value_return);

typedef XrmHashTable *XrmSearchList;

Bool XrmQGetSearchList(XrmDatabase database, XrmNameList names, XrmClassList classes, XrmSearchList list_return, int list_length);

Bool XrmQGetSearchResource(XrmSearchList list, XrmName name, XrmClass class, XrmRepresentation *type_return, XrmValue *value_return);

DESCRIPCIÓN

Las funciones XrmGetResource y XrmQGetResource recuperan un recurso de la base de datos especificada. Ambas toman un par de nombre/clase completamente calificado, una representación de recurso de destino y la dirección de un valor (par tamaño/dirección). El valor y el tipo devuelto apuntan a la memoria de la base de datos; por lo tanto, no debe modificar los datos.

La base de datos solo libera o sobrescribe entradas en XrmPutResource, XrmQPutResource o XrmMergeDatabases. Un cliente que no esté almacenando nuevos valores en la base de datos o que no esté fusionando la base de datos debería estar seguro utilizando la dirección devuelta en cualquier momento hasta que salga. Si se encontró un recurso, tanto XrmGetResource como XrmQGetResource devuelven True; de lo contrario, devuelven False.

La función XrmQGetSearchList toma una lista de nombres y clases y devuelve una lista de niveles de base de datos donde puede ocurrir una coincidencia. La lista devuelta está en orden de mejor a peor y utiliza el mismo algoritmo que XrmGetResource para determinar la precedencia. Si list_return era lo suficientemente grande para la lista de búsqueda, XrmQGetSearchList devuelve True; de lo contrario, devuelve False.

El tamaño de la lista de búsqueda que el llamador debe asignar depende del número de niveles y comodines en los especificadores de recursos que se almacenan en la base de datos. La longitud en el peor de los casos es %3 sup n%, donde n es el número de componentes de nombre o clase en nombres o clases.

Al usar XrmQGetSearchList seguido de múltiples consultas para recursos con un prefijo de nombre y clase común, solo el prefijo común debe especificarse en la lista de nombre y clase para XrmQGetSearchList.

La función XrmQGetSearchResource busca en los niveles de base de datos especificados el recurso que está completamente identificado por el nombre y la clase especificados. La búsqueda se detiene con la primera coincidencia. XrmQGetSearchResource devuelve True si se encontró el recurso; de lo contrario, devuelve False.

Una llamada a XrmQGetSearchList con una lista de nombre y clase que contiene todos los componentes excepto el último de un nombre de recurso, seguida de una llamada a XrmQGetSearchResource con el nombre y la clase del último componente, devuelve la misma entrada de base de datos que XrmGetResource y XrmQGetResource con el nombre y la clase completamente calificados.

REGLAS DE COINCIDENCIA

El algoritmo para determinar qué entrada de base de datos de recursos coincide con una consulta dada es el corazón del gestor de recursos. Todas las consultas deben especificar completamente el nombre y la clase del recurso deseado (el uso de los caracteres “*” y “?” no está permitido). La biblioteca admite hasta 100 componentes en un nombre o clase completos. Los recursos se almacenan en la base de datos con nombres y clases parcialmente especificados, utilizando construcciones de coincidencia de patrones. Un asterisco (*) es una unión laxa y se utiliza para representar cualquier número de componentes intermedios, incluido ninguno. Un punto (.) es una unión estricta y se utiliza para separar componentes inmediatamente adyacentes. Un signo de interrogación (?) se utiliza para coincidir con cualquier nombre o clase de componente individual. Una entrada de base de datos no puede terminar en una unión laxa; se debe especificar el componente final (que no puede ser el carácter “?”). El algoritmo de búsqueda busca en la base de datos la entrada que coincide más estrechamente (es más específica) con el nombre y la clase completos que se consultan. Cuando más de una entrada de base de datos coincide con el nombre y la clase completos, se utilizan reglas de precedencia para seleccionar solo una.

El nombre y la clase completos se escanean de izquierda a derecha (desde el nivel más alto en la jerarquía hasta el más bajo), un componente a la vez. En cada nivel, se determina el componente y/o la unión correspondiente de cada entrada coincidente, y estos componentes y uniones coincidentes se comparan según las reglas de precedencia. Cada una de las reglas se aplica en cada nivel antes de pasar al siguiente nivel, hasta que una regla selecciona una sola entrada sobre todas las demás. Las reglas, en orden de precedencia, son:

1.
Una entrada que contiene un componente coincidente (ya sea nombre, clase o el carácter “?”) tiene precedencia sobre las entradas que eliden el nivel (es decir, las entradas que coinciden con el nivel en una unión laxa).
2.
Una entrada con un nombre coincidente tiene precedencia sobre las entradas con una clase coincidente y las entradas que coinciden usando el carácter “?”. Una entrada con una clase coincidente tiene precedencia sobre las entradas que coinciden usando el carácter “?”.
3.
Una entrada precedida por una unión estricta tiene precedencia sobre las entradas precedidas por una unión laxa.
