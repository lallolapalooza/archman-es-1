rate

TIPOS DE DATOS

Rotaciones/Reflejos

Puede ser cualquiera de:

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/* nuevo en el protocolo 1.0, para permitir el reflejo de pantalla */
/* el reflejo se aplica después de la rotación */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/* base del evento */
    unsigned long serial;	/* # de la última solicitud procesada por el servidor */
    Bool send_event;		/* true si esto provino de una solicitud SendEvent */
    Display *display;		/* Display desde el que se leyó el evento */
    Window window;			/* ventana que seleccionó este evento */
    Window root;			/* Ventana raíz para la pantalla cambiada */
    Time timestamp;			/* cuándo ocurrió el cambio de pantalla */
    Time config_timestamp;	/* cuándo fue el último cambio de configuración */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La estructura XRRScreenSize contiene un tamaño de raíz posible en píxeles y en milímetros.

Un XRRScreenChangeNotifyEvent se envía a un cliente que ha solicitado notificación cada vez que se cambia la configuración de la pantalla. Un cliente puede realizar esta solicitud llamando a XRRSelectInput, pasando el display, la ventana raíz y la máscara RRScreenChangeNotifyMask.

XRRScreenConfiguration es un tipo de dato opaco que contiene la información de configuración de una pantalla.

Marcas de tiempo

Se incluyen marcas de tiempo y deben usarse para asegurar que el cliente esté al día: la pantalla puede cambiar propiedades sobre la marcha y esto asegura que su conocimiento de la configuración esté actualizado. Esto es para ayudar con problemas cuando las pantallas pueden ser conectables en caliente en el futuro.

DESCRIPCIÓN

Xrandr es una biblioteca simple diseñada para interactuar con la Extensión de Redimensionamiento y Rotación de X. Esto permite a los clientes cambiar el tamaño y la rotación de la ventana raíz de una pantalla, junto con la capacidad de reflejar la pantalla sobre cualquier eje (si es compatible con la implementación). La rotación y el reflejo pueden implementarse por software y pueden resultar en un rendimiento más lento si la rotación y el reflejo se implementan de esta manera (como lo son todas las implementaciones en octubre de 2002).

La biblioteca Xrandr realiza un almacenamiento en caché mínimo para evitar viajes de ida y vuelta y proporcionar a los clientes información utilizada con frecuencia. Consulte "La Extensión de Redimensionamiento y Rotación de X" para obtener una descripción detallada; tenga en cuenta también que el cambio de profundidad, como se describe en el documento, no está implementado y puede (o no) implementarse en el futuro, ya que la memoria de pantalla está creciendo rápidamente y los toolkits ya están comenzando a admitir la migración, lo que mitiga la necesidad de cambio de profundidad. Si se implementa en el futuro, esperamos hacerlo a través de una extensión compatible hacia arriba de la biblioteca/protocolo actual; la funcionalidad descrita aquí debería seguir funcionando.

La rotación y el reflejo, y cómo interactúan, pueden ser confusos. En Randr, el sistema de coordenadas se rota en sentido antihorario con respecto a la orientación normal. El reflejo se realiza a lo largo del sistema de coordenadas del sistema de ventanas, no de los ejes X e Y físicos de la pantalla, de modo que la rotación y el reflejo no interactúan. La otra forma de considerar el reflejo es tratarlo como se especifica en la orientación "normal", antes de la rotación.

El evento XRRScreenChangeNotify se envía a los clientes que solicitan ser informados cada vez que cambian las configuraciones de la ventana raíz. Los cambios de configuración pueden incluir resolución, tamaño físico, orden de subpíxeles (ver XRender(3)) y rotación. Tenga en cuenta que los cambios en cualquiera o en todos estos podrían ocurrir debido a eventos externos (control del usuario en el servidor X, conexión de un monitor/panel plano diferente) y no son solo el resultado de una solicitud de protocolo/biblioteca al servidor X.

Además, para eliminar una posible condición de carrera, este evento puede generarse inmediatamente al seleccionar la notificación si la pantalla ha cambiado desde que el cliente de Xrandr se conectó al servidor X, para permitir cambios de resolución de pantalla fiables cuando un usuario puede iniciar sesión y cambiar la configuración mientras uno o varios clientes están en proceso de inicio.

Notificación de Xlib

Los clientes deben volver a llamar a Xlib usando XRRUpdateConfiguration cuando se generen eventos de notificación de cambio de configuración de pantalla (o ocurran cambios de configuración de la ventana raíz, para actualizar la vista de Xlib de la resolución, tamaño, rotación, reflejo u orden de subpíxeles. Generalmente, los toolkits realizarán esta operación en nombre de las aplicaciones; no queríamos cambiar los datos de la estructura de visualización a espaldas de los toolkits, ya que en clientes multihilo, podrían ocurrir varias condiciones de carrera. Los toolkits deben proporcionar a los clientes algún mecanismo para la notificación de cambios en la pantalla, por supuesto.

XRRConfigRotations(3)

Xrandr protocol extension

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
