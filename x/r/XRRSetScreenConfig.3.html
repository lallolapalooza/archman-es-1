TIPOS DE DATOS

Rotaciones/Reflejos

Puede ser cualquiera de:

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nuevo en el protocolo 1.0, para permitir el reflejo de la pantalla */
/∗ el reflejo se aplica después de la rotación */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base de eventos */
    unsigned long serial;	/∗ # de la última solicitud procesada por el servidor */
    Bool send_event;		/∗ verdadero si esto provino de una solicitud SendEvent */
    Display *display;		/∗ pantalla desde la que se leyó el evento */
    Window window;			/∗ ventana que seleccionó para este evento */
    Window root;			/∗ ventana raíz para la pantalla cambiada */
    Time timestamp;			/∗ cuándo ocurrió el cambio de pantalla */
    Time config_timestamp;	/∗ cuándo fue el último cambio de configuración */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La estructura XRRScreenSize contiene un tamaño de raíz posible en píxeles y en milímetros.

Se envía un XRRScreenChangeNotifyEvent a un cliente que ha solicitado notificación cada vez que se cambia la configuración de la pantalla. Un cliente puede realizar esta solicitud llamando a XRRSelectInput, pasando la pantalla, la ventana raíz y la máscara RRScreenChangeNotifyMask.

XRRScreenConfiguration es un tipo de dato opaco que contiene la información de configuración de una pantalla.

Marcas de tiempo

Se incluyen marcas de tiempo y deben usarse para asegurar que el cliente está jugando con toda la baraja: la pantalla puede cambiar propiedades sobre la marcha y esto asegura que su conocimiento de la configuración esté actualizado. Esto es para ayudar con problemas cuando las pantallas pueden ser conectables en caliente en el futuro.

DESCRIPCIÓN

Xrandr es una biblioteca simple diseñada para interactuar con la Extensión de Redimensionamiento y Rotación de X. Esto permite a los clientes cambiar el tamaño y la rotación de la ventana raíz de una pantalla, junto con la capacidad de reflejar la pantalla en cualquier eje (si es soportado por la implementación). La rotación y el reflejo pueden ser implementados por software y pueden resultar en un rendimiento más lento si la rotación y el reflejo se implementan de esta manera (como son todas las implementaciones a octubre de 2002).

La biblioteca Xrandr realiza un almacenamiento en caché mínimo para evitar viajes de ida y vuelta para proporcionar a los clientes información de uso frecuente. Consulte "The X Resize and Rotate Extension" para una descripción detallada; también tenga en cuenta que el cambio de profundidad, como se describe en el documento, no está implementado, y puede (o no) ser implementado en el futuro, ya que la memoria de pantalla está creciendo rápidamente y las toolkits ya están comenzando a soportar la migración, mitigando la necesidad de cambiar de profundidad. Si se implementa en el futuro, esperamos hacerlo a través de una extensión compatible hacia arriba con la biblioteca/protocolo actual; la funcionalidad descrita aquí debería seguir funcionando.

La rotación y el reflejo y cómo interactúan pueden ser confusos. En Randr, el sistema de coordenadas se rota en sentido antihorario relativo a la orientación normal. El reflejo es a lo largo del sistema de coordenadas del sistema de ventanas, no los ejes X e Y físicos de la pantalla, de modo que la rotación y el reflejo no interactúan. La otra forma de considerar el reflejo es tratarlo como se especifica en la orientación "normal", antes de la rotación.

El evento XRRScreenChangeNotify se envía a los clientes que solicitan ser informados cada vez que cambian la configuración de la ventana raíz. Los cambios de configuración pueden incluir resolución, tamaño físico, orden de subpíxeles (ver XRender(3)) y rotación. Tenga en cuenta que los cambios en cualquiera o todos estos pueden ocurrir debido a eventos externos (control del usuario en el servidor X, conexión/desconexión de un monitor/panel plano diferente) y no son solo el resultado de una solicitud de protocolo/biblioteca al servidor X.

Además, para eliminar una posible condición de carrera, este evento puede generarse inmediatamente al seleccionar la notificación si la pantalla ha cambiado desde que el cliente de Xrandr se conectó al servidor X, para habilitar cambios de resolución de pantalla confiables cuando un usuario puede iniciar sesión y cambiar la configuración mientras uno o varios clientes se inician.

Notificación de Xlib

Los clientes deben volver a llamar a Xlib usando XRRUpdateConfiguration cuando se generan eventos de notificación de cambio de configuración de pantalla (o ocurren cambios de configuración de la ventana raíz, para actualizar la vista de Xlib de la resolución, tamaño, rotación, reflejo u orden de subpíxeles. Generalmente, las toolkits realizarán esta operación en nombre de las aplicaciones; no queríamos cambiar los datos de la estructura de visualización a espaldas de las toolkits, ya que en clientes multihilo, podrían ocurrir varias condiciones de carrera. Las toolkits deben proporcionar a los clientes algún mecanismo para la notificación de cambios de pantalla, por supuesto.

XRRSetScreenConfig(3)

NAME

void XRRFreeScreenConfigInfo(XRRScreenConfigurationPtr config);

Window XRRRootToScreen(Display *display, Window root);

Bool XRRQueryExtension(Display *display, int *event_base_return, int *error_base_return);

Bool XRRQueryVersion(Display *display, int *major_version_return, int *minor_version_return);

Rotation XRRRotations(Display *display, RRCrtc crtc);

RRScreenSizePtr XRRSizes(Display *display, RRCrtc crtc, int *nsize_return);

int XRRRates(Display *display, RRCrtc crtc, RRScreenSizePtr size, int *nrate_return);

unsigned long XRRTimes(Display *display, RRCrtc crtc, unsigned long *timestamp_return);

Rotation XRRConfigRotations(XRRScreenConfigurationPtr config, Rotation *current_rotation);

RRScreenSizePtr XRRConfigSizes(XRRScreenConfigurationPtr config, int *nsize_return);

Rotation XRRConfigCurrentConfiguration(XRRScreenConfigurationPtr config, int *current_size_index);

unsigned long XRRConfigTimes(XRRScreenConfigurationPtr config, unsigned long *timestamp_return);

int XRRConfigRates(XRRScreenConfigurationPtr config, int *nrate_return);

int XRRConfigCurrentRate(XRRScreenConfigurationPtr config);

ARGUMENTS

display is the connection to the X server.

window is the window which is associated with the screen.

root is the root window of the screen.

crtc is the CRTC identifier for the screen.

size is the size identifier for the screen.

rotation is the rotation or reflection to be applied.

rate is the refresh rate to be applied.

timestamp is the timestamp of the last configuration change.

config is a screen configuration structure previously obtained with XRRGetScreenInfo.

event_base_return, error_base_return are pointers to integers where the event and error base codes are returned.

major_version_return, minor_version_return are pointers to integers where the major and minor version numbers of the RandR extension are returned.

nsize_return is a pointer to an integer where the number of available screen sizes is returned.

nrate_return is a pointer to an integer where the number of available refresh rates is returned.

current_rotation is a pointer to a Rotation value where the current rotation is returned.

current_size_index is a pointer to an integer where the current size index is returned.

timestamp_return is a pointer to an unsigned long where the last configuration change timestamp is returned.

DATATYPES

Rotation is a bitmask of possible rotations and reflections. Possible values are RR_Rotate_0, RR_Rotate_90, RR_Rotate_180, RR_Rotate_270, RR_Reflect_X, RR_Reflect_Y.

RRScreenSize is a structure representing a screen size. It contains width and height members.

RRScreenSizePtr is a pointer to an array of RRScreenSize structures.

RRCrtc is an opaque type representing a CRTC identifier.

XRRScreenConfigurationPtr is a pointer to an opaque structure holding screen configuration information.

Status is an integer return type. Success indicates success, any other value indicates an error.

DESCRIPTION

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
