NOMBRE

XrmGetResource, XrmQGetResource, XrmQGetSearchList, XrmQGetSearchResource - recuperar recursos de base de datos y listas de búsqueda

SINTAXIS

#include <X11/Xresource.h>

Bool XrmGetResource(XrmDatabase database, char *str_name, char *str_class, char **str_type_return, XrmValue *value_return);

Bool XrmQGetResource(XrmDatabase database, XrmNameList quark_name, XrmClassList quark_class, XrmRepresentation *quark_type_return, XrmValue *value_return);

typedef XrmHashTable *XrmSearchList;

Bool XrmQGetSearchList(XrmDatabase database, XrmNameList names, XrmClassList classes, XrmSearchList list_return, int list_length);

Bool XrmQGetSearchResource(XrmSearchList list, XrmName name, XrmClass class, XrmRepresentation *type_return, XrmValue *value_return);

ARGUMENTOS

Especifica la lista de búsqueda devuelta por XrmQGetSearchList.

Especifica el número de entradas (no el tamaño en bytes) asignadas para list_return.
lista-retorno
Devuelve una lista de búsqueda para uso posterior.
nombre
Especifica el nombre del recurso.
nombres
Especifica una lista de nombres de recursos.
clase-quark
Especifica la clase completamente cualificada del valor que se está recuperando (como un quark).
nombre-quark
Especifica el nombre completamente cualificado del valor que se está recuperando (como un quark).
tipo-quark-retorno
Devuelve la representación del tipo de destino (como un quark).

Especifica el nombre completamente cualificado del valor que se está recuperando (como una cadena).

Devuelve la representación del tipo de destino (como una cadena).
tipo-retorno
Devuelve el tipo de representación de los datos.
valor-retorno

DESCRIPCION

Las funciones XrmGetResource y XrmQGetResource recuperan un recurso de la base de datos especificada. Ambas toman un par de nombre/clase completamente cualificado, una representación de recurso de destino y la dirección de un valor (par tamaño/dirección). El valor y el tipo devuelto apuntan a la memoria de la base de datos; por lo tanto, no debe modificar los datos.

La base de datos solo libera o sobrescribe entradas en XrmPutResource, XrmQPutResource o XrmMergeDatabases. Un cliente que no está almacenando nuevos valores en la base de datos o que no está fusionando la base de datos debería estar seguro al usar la dirección pasada en cualquier momento hasta que salga. Si se encontró un recurso, tanto XrmGetResource como XrmQGetResource devuelven True; de lo contrario, devuelven False.

La función XrmQGetSearchList toma una lista de nombres y clases y devuelve una lista de niveles de base de datos donde podría ocurrir una coincidencia. La lista devuelta está en orden de mejor a peor y utiliza el mismo algoritmo que XrmGetResource para determinar la precedencia. Si list_return era lo suficientemente grande para la lista de búsqueda, XrmQGetSearchList devuelve True; de lo contrario, devuelve False.

El tamaño de la lista de búsqueda que el llamante debe asignar depende del número de niveles y comodines en los especificadores de recursos que se almacenan en la base de datos. La longitud del peor caso es %3 sup n%, donde *n* es el número de componentes de nombre o clase en nombres o clases.

Al usar XrmQGetSearchList seguido de múltiples sondeos de recursos con un prefijo común de nombre y clase, solo el prefijo común debe especificarse en la lista de nombre y clase para XrmQGetSearchList.

La función XrmQGetSearchResource busca en los niveles de base de datos especificados el recurso que está completamente identificado por el nombre y la clase especificados. La búsqueda se detiene con la primera coincidencia. XrmQGetSearchResource devuelve True si se encontró el recurso; de lo contrario, devuelve False.

Una llamada a XrmQGetSearchList con una lista de nombre y clase que contiene todos los componentes excepto el último de un nombre de recurso, seguida de una llamada a XrmQGetSearchResource con el último componente de nombre y clase, devuelve la misma entrada de base de datos que XrmGetResource y XrmQGetResource con el nombre y la clase completamente cualificados.

REGLAS DE COINCIDENCIA

El algoritmo para determinar qué entrada de la base de datos de recursos coincide con una consulta dada es el corazón del gestor de recursos. Todas las consultas deben especificar completamente el nombre y la clase del recurso deseado (no se permiten los caracteres “*” y “?”). La biblioteca admite hasta 100 componentes en un nombre o clase completa. Los recursos se almacenan en la base de datos con nombres y clases parcialmente especificados, utilizando construcciones de coincidencia de patrones. Un asterisco (*) es una vinculación suelta y se utiliza para representar cualquier número de componentes intermedios, incluido ninguno. Un punto (.) es una vinculación ajustada y se utiliza para separar componentes inmediatamente adyacentes. Un signo de interrogación (?) se utiliza para coincidir con cualquier nombre o clase de componente individual. Una entrada de base de datos no puede terminar con una vinculación suelta; se debe especificar el componente final (que no puede ser el carácter “?”). El algoritmo de búsqueda busca en la base de datos la entrada que coincide más estrechamente (es más específica para) el nombre y la clase completos que se consultan. Cuando más de una entrada de base de datos coincide con el nombre y la clase completos, se utilizan reglas de precedencia para seleccionar solo una.

El nombre y la clase completos se escanean de izquierda a derecha (del nivel más alto en la jerarquía al más bajo), un componente a la vez. En cada nivel, se determina el componente y/o la vinculación correspondiente de cada entrada coincidente, y estos componentes y vinculaciones coincidentes se comparan según las reglas de precedencia. Cada una de las reglas se aplica en cada nivel antes de pasar al siguiente nivel, hasta que una regla selecciona una única entrada sobre todas las demás. Las reglas, en orden de precedencia, son:

1.
Una entrada que contiene un componente coincidente (ya sea nombre, clase o el carácter “?”) tiene precedencia sobre las entradas que omiten el nivel (es decir, las entradas que coinciden con el nivel en una vinculación suelta).
2.
Una entrada con un nombre coincidente tiene precedencia sobre las entradas con una clase coincidente y las entradas que coinciden usando el carácter “?”. Una entrada con una clase coincidente tiene precedencia sobre las entradas que coinciden usando el carácter “?”.
3.
Una entrada precedida por una vinculación ajustada tiene precedencia sobre las entradas precedidas por una vinculación suelta.
