TIPOS DE DATOS

Rotaciones/Reflejos

Puede ser cualquiera de:

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nuevo en el protocolo 1.0, para permitir el reflejo de la pantalla */
/∗ el reflejo se aplica después de la rotación */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base de eventos */
    unsigned long serial;	/∗ # de la última petición procesada por el servidor */
    Bool send_event;		/∗ true si esto provino de una petición SendEvent */
    Display *display;		/∗ Pantalla desde la que se leyó el evento */
    Window window;			/∗ ventana que seleccionó este evento */
    Window root;			/∗ Ventana raíz para la pantalla cambiada */
    Time timestamp;			/∗ cuándo ocurrió el cambio de pantalla */
    Time config_timestamp;	/∗ cuándo fue el último cambio de configuración */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La estructura XRRScreenSize contiene un tamaño de raíz posible en píxeles y en milímetros.

Un XRRScreenChangeNotifyEvent se envía a un cliente que ha solicitado notificación cada vez que cambia la configuración de la pantalla. Un cliente puede realizar esta solicitud llamando a XRRSelectInput, pasando la pantalla, la ventana raíz y la máscara RRScreenChangeNotifyMask.

XRRScreenConfiguration es un tipo de dato opaco que contiene la información de configuración de una pantalla.

Marcas de tiempo

Se incluyen marcas de tiempo y deben usarse para asegurar que el cliente está al día: la pantalla puede cambiar propiedades sobre la marcha y esto asegura que su conocimiento de la configuración esté actualizado. Esto es para ayudar con problemas cuando las pantallas pueden ser conectables en caliente en el futuro.

DESCRIPCIÓN

Xrandr es una biblioteca simple diseñada para interactuar con la Extensión de Redimensionamiento y Rotación de X. Esto permite a los clientes cambiar el tamaño y la rotación de la ventana raíz de una pantalla, junto con la capacidad de reflejar la pantalla sobre cualquier eje (si es compatible con la implementación). La rotación y el reflejo pueden implementarse mediante software y pueden resultar en un rendimiento más lento si la rotación y el reflejo se implementan de esta manera (como son todas las implementaciones a octubre de 2002).

La biblioteca Xrandr realiza un almacenamiento en caché mínimo para evitar viajes de ida y vuelta y proporcionar a los clientes información utilizada con frecuencia. Consulte "The X Resize and Rotate Extension" para una descripción detallada; tenga en cuenta también que el cambio de profundidad, como se describe en el documento, no está implementado y puede que nunca se implemente, ya que la memoria de pantalla está creciendo rápidamente y los toolkits ya están empezando a soportar la migración, mitigando la necesidad de cambio de profundidad. Si se implementa en el futuro, esperamos hacerlo a través de una extensión compatible hacia arriba de la biblioteca/protocolo actual; la funcionalidad descrita aquí debería seguir funcionando.

La rotación y el reflejo y cómo interactúan pueden ser confusos. En Randr, el sistema de coordenadas se rota en sentido antihorario con respecto a la orientación normal. El reflejo se realiza a lo largo del sistema de coordenadas del sistema de ventanas, no de los ejes X e Y físicos de la pantalla, de modo que la rotación y el reflejo no interactúan. La otra forma de considerar el reflejo es tratarlo como se especifica en la orientación "normal", antes de la rotación.

El evento XRRScreenChangeNotify se envía a los clientes que solicitan ser informados cada vez que cambia la configuración de la ventana raíz. Los cambios de configuración pueden incluir resolución, tamaño físico, orden de subpíxeles (ver XRender(3)) y rotación. Tenga en cuenta que los cambios en cualquiera o todos estos pueden ocurrir debido a eventos externos (control del usuario en el servidor X, conexión en caliente de un monitor/panel plano diferente) y no son solo el resultado de una solicitud de protocolo/biblioteca al servidor X.

Además, para eliminar una posible condición de carrera, este evento puede generarse inmediatamente al seleccionar la notificación si la pantalla ha cambiado desde que el cliente de Xrandr se conectó al servidor X, para permitir un cambio de resolución de pantalla fiable cuando un usuario puede iniciar sesión y cambiar la configuración mientras uno o varios clientes se están iniciando.

Notificación de Xlib

Los clientes deben volver a llamar a Xlib usando XRRUpdateConfiguration cuando se generan eventos de notificación de cambio de configuración de pantalla (o ocurren cambios de configuración de la ventana raíz, para actualizar la vista de Xlib de la resolución, tamaño, rotación, reflejo u orden de subpíxeles. En general, los toolkits realizarán esta operación en nombre de las aplicaciones; no queríamos cambiar los datos de la estructura de visualización a espaldas de los toolkits, ya que en clientes multihilo, podrían ocurrir varias condiciones de carrera. Los toolkits deberían proporcionar a los clientes algún mecanismo de notificación de cambio de pantalla, por supuesto.

NAME

XRRQueryVersion — query the RandR extension version and capabilities

SYNTAX

C

#include <X11/extensions/Xrandr.h>

ARGUMENTS

display
Specifies the connection to the X server.
major_version_ptr
Pointer to the extension major version number.
minor_version_ptr
Pointer to the extension minor version number.
screen_ptr
Pointer to the screen number.
root_return
Pointer to the root window.
size_index
Specifies which size configuration is to be used.
rotation
Specifies which rotation or reflection is to be used.
timestamp
Used by the server to ensure the client has up to date configuration information.
draw
Specifies the connection to the X server.
event_base_return
Returns the RandR event base code.
error_base_return
Returns the RandR error base code.

DATATYPES

The RandR extension defines the following structure types:

RRScreenSize
Represents a screen size.
RRScreenConfiguration
Represents the current screen configuration.
RRCrtc
Represents a CRT controller.
RROutput
Represents an output device.
RRMode
Represents a display mode.

DESCRIPTION

The RandR (Resize, Rotate and Reflect) extension provides a mechanism for clients to query and modify the screen resolution, rotation, and reflection settings. It allows for dynamic changes to the display configuration without requiring a server restart.

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

FUNCTIONS

XRRQueryExtension returns the event and error base codes.

XRRQueryVersion returns the current version of the extension (this information is cached by the library).

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
