XmResolvePartOffsets(3)

Paquete: openmotif

Licencias: LGPL-2.1-or-later

NOMBRE

XmResolvePartOffsets — Una función que permite la escritura de aplicaciones y widgets compatibles hacia arriba

SINOPSIS

#include <Xm/Xm.h>
void XmResolvePartOffsets(
WidgetClass widget_class,
XmOffsetPtr * offset);

DESCRIPCIÓN

El uso de registros de desplazamiento requiere una variable global adicional por clase de widget. La variable consiste en un puntero a una matriz de desplazamientos dentro del registro del widget para cada parte de la estructura del widget. La función XmResolvePartOffsets asigna los registros de desplazamiento necesarios para que una aplicación garantice el acceso compatible hacia arriba a los registros de instancia de widgets por parte de aplicaciones y widgets. Estos registros de desplazamiento son utilizados por el widget para acceder a todas las variables del widget. Un widget necesita seguir los pasos descritos en los siguientes párrafos.

En lugar de crear una lista de recursos, el widget crea una lista de recursos de desplazamiento. Para lograr esto, se utiliza la estructura XmPartResource y la macro XmPartOffset. La estructura de datos XmPartResource se ve exactamente como una lista de recursos, pero en lugar de tener un entero para su desplazamiento, tiene dos `short`. Esta estructura se coloca en el registro de clase como si fuera una lista de recursos normal. En lugar de usar XtOffset para el desplazamiento, el widget usa XmPartOffset.

XmPartResource resources[] = {
  { BarNxyz, BarCXyz, XmRBoolean,
    sizeof(Boolean), XmPartOffset(Bar,xyz),
    XmRImmediate, (XtPointer)False }
};

En lugar de poner el tamaño del widget en el registro de clase, el widget pone el tamaño de la parte del widget en el mismo campo.

En lugar de poner XtVersion en el registro de clase, el widget pone XtVersionDontCheck en el registro de clase.

El widget define una variable, de tipo XmOffsetPtr, para apuntar al registro de desplazamiento. Esto puede ser parte del registro de clase del widget o una variable global separada.

En la inicialización de clase, el widget llama a XmResolvePartOffsets, pasándole un puntero para contener la dirección del registro de desplazamiento y el registro de clase. Esto realiza varias acciones:

•
Suma el tamaño de la superclase (que, por definición, ya ha sido inicializada) al campo del tamaño de la parte.
•
Asigna una matriz basada en el número de superclases.
•
Rellena los desplazamientos de todas las partes del widget con los valores apropiados, determinados al examinar los campos de tamaño de todos los registros de superclase.
•
Utiliza la matriz de desplazamientos de partes para modificar las entradas de desplazamiento en la lista de recursos para que sean desplazamientos reales, in situ.

El widget define una constante que será el índice de su estructura de parte en la matriz de desplazamientos. El valor debe ser 1 mayor que el índice de la superclase del widget. Las constantes definidas para todos los widgets Xm se pueden encontrar en XmP.h.

#define BarIndex (XmBulletinBIndex + 1)

En lugar de acceder directamente a los campos, el widget debe pasar siempre a través de la tabla de desplazamientos. La macro XmField te ayuda a acceder a estos campos. Dado que las macros XmPartOffset y XmField concatenan elementos, debes asegurarte de que no haya ningún espacio después del argumento de la parte. Por ejemplo, las siguientes macros no funcionan debido al espacio después del argumento de la parte (Label):

XmField(w, offset, Label, text, char *)
XmPartOffset(Label, text)

Por lo tanto, no debes tener ningún espacio después del argumento de la parte (Label), como se ilustra aquí:

XmField(w, offset, Label, text, char *)

Puedes definir macros para cada campo para facilitar esto. Supongamos un campo entero xyz:

#define BarXyz(w) (*(int *)(((char *) w) + \
        offset[BarIndex] + XtOffset(BarPart,xyz)))

Los parámetros para XmResolvePartOffsets son:

widget_class
Especifica el puntero de la clase de widget para el widget creado.
offset
Devuelve el registro de desplazamiento.
