XML::LibXML::PrettyPrint(3) Documentación de Perl de Contribución del Usuario XML::LibXML::PrettyPrint(3)

NOMBRE

XML::LibXML::PrettyPrint - agrega espacios en blanco agradables a un árbol DOM

SINOPSIS

my $document = XML::LibXML->new->parse_file('in.xml');
my $pp = XML::LibXML::PrettyPrint->new(indent_string => "  ");
$pp->pretty_print($document); # modificado in situ
print $document->toString;

DESCRIPCIÓN

Los archivos XML largos pueden ser abrumadores para que los humanos los lean. Por supuesto, XML está realmente diseñado para que las computadoras lo lean, no para las personas, pero hay momentos en los que los simples mortales necesitan leer y editar XML a mano. Por ejemplo, si su aplicación almacena su configuración en XML, o si necesita volcar algo de XML a STDOUT para fines de depuración.

El resaltado de sintaxis ayuda, pero para comprender realmente algo de XML, una indentación adecuada puede ser vital. De ahí "XML::LibXML::PrettyPrint": se puede aplicar a un árbol DOM de XML::LibXML para reformatearlo en un resultado más legible.

La impresión bonita de XML no es tan eficiente en términos de CPU como volcarla descuidadamente, por lo que a menos que esté bastante seguro de que un humano necesitará dar sentido a su XML, probablemente no debería usar este módulo.

Constructores

new(%options)
Construye un objeto de impresión bonita.

Opciones:

  • indent_string - La cadena que se utilizará para indentar cada línea. Por defecto es un solo carácter de tabulación. Se permite establecerlo en un carácter que no sea de espacio en blanco, pero se emitirá una advertencia.
  • new_line - La cadena que se utilizará para iniciar una nueva línea. Por defecto es "\n".
  • element - Un hashref de categorizaciones de elementos. Cada categorización es una referencia a una matriz de nombres de elementos o funciones de devolución de llamada. Los nombres de los elementos pueden usar la notación de Clark. 
    my $callback = sub {
  my $node = shift;
  return 1 if $node->hasAttribute('is_block');
  return undef;
};
my $pp = XML::LibXML::PrettyPrint->new(
    element => {
        inline   => [qw/span strong em b i a/],
        block    => [qw/p div body html head/, $callback],
        compact  => [qw/title caption li dd dt th td/],
        preserves_whitespace => [qw/pre script style/],
        }
    );

    Las devoluciones de llamada deben devolver 1 (verdadero), 0 (falso) o undef (no lo sé).

new_for_html(%options)
Construye un objeto de impresión bonita preconfigurado para ser adecuado para HTML y XHTML. Se admiten las opciones indent_string y new_line.

Métodos

Si solo necesita usar una configuración predeterminada (sin opciones pasadas al constructor, entonces puede llamar a estos como métodos de clase, a menos que se indique lo contrario).

strip_whitespace($node)
Elimina los espacios en blanco superfluos de un "XML::LibXML::Document" o "XML::LibXML::Element".

Los espacios en blanco justo antes, justo después o al principio/final dentro de un elemento en línea no se consideran superfluos. Las secuencias de múltiples caracteres de espacio en blanco se reemplazan con un solo espacio. Los espacios en blanco no se modifican dentro de un elemento que preserve los espacios en blanco.

El nodo se modifica in situ.

"indent($node, $level)"
Indenta el nodo a un cierto nivel de indentación, y sus hijos directos a "$level + 1", nietos a "$level + 2", etc. Típicamente, solo querría indentar el nodo raíz al nivel 0.

El nodo se modifica in situ.

Los elementos que conservan espacios en blanco no se modifican.

"pretty_print($node, $level)"
Elimina espacios en blanco e indenta. El nodo se modifica in situ y se devuelve.

Ejemplo de uso como método de clase:

print XML::LibXML::PrettyPrint
  ->pretty_print(XML::LibXML->new->parse_string($XML))
  ->toString;
indent_string($level)
Devuelve la cadena que se utilizaría para indentar algo a un nivel particular. Las clases descendientes podrían anular este método para hacer una indentación peculiar, como tener diferentes niveles de indentación.
"new_line"
Devuelve la cadena que se utilizaría para comenzar una nueva línea.
element_category($node)
Devuelve EL_INLINE, EL_BLOCK, EL_COMPACT o undef.
element_preserves_whitespace($node)
Booleano que indica si el contenido del elemento tiene espacios en blanco significativos que necesitan ser conservados.

Devuelve undef si $node no es un "XML::LibXML::Element".

Funciones

"print_xml $xml"
Dada una cadena XML o un objeto XML::LibXML::Node, la imprime de forma agradable.

Esta función no se exporta por defecto, pero se puede solicitar:

use XML::LibXML::PrettyPrint 0.001 qw(print_xml);

Úselo de esta manera:

print_xml '<foo> <bar> </bar> </foo>';
"IO::Handle::print_xml($handle, $xml)"
Parcialmente experimental, parcialmente mental. Puede habilitar esta función de esta manera: 
use XML::LibXML::PrettyPrint 0.001 qw(-io);

Y eso permitirá que cosas como esta funcionen:

open LOG, '>mylog.xml';
print_xml LOG '<foo> <bar> </bar> </foo>';
close LOG;
open my $log, '>otherlog.xml';
print_xml $log '<foo> <bar> </bar> </foo>';
close $log;
print_xml STDERR '<foo> <bar> </bar> </foo>';

Constantes

Estos se pueden exportar:

use XML::LibXML::PrettyPrint 0.001 qw(:constants);
"EL_BLOCK"
"EL_COMPACT"
"EL_INLINE"

CATEGORÍAS DE ELEMENTOS

Hay tres categorías de elementos: en línea, de bloque y compactos.

Para los elementos en línea, la presencia de espacios en blanco (aunque no la cantidad de espacios en blanco) es significativa justo antes del elemento, justo después del elemento o justo dentro del elemento.

En XHTML, considere la diferencia entre el elemento de bloque "<div>":

<div>Will</div><div>Carlton</div> <div>Ashley</div>

y el elemento en línea "<span>":

<span>Spider</span>-<span>Man</span> <span>lives</span>

El espacio o la falta de él entre los elementos "<div>" no importa en absoluto. La falta de espacios entre los dos primeros elementos "<span>" permite que se lean como una sola palabra (en este caso, con guiones), mientras que el espacio antes del tercer "<span>" separa la palabra "lives".

En términos de indentación, los elementos en línea no comienzan una nueva línea indentada, a menos que sean el primer elemento dentro de su bloque, o estén precedidos por un elemento de bloque o compacto.

Los elementos de bloque siempre comienzan una nueva línea y hacen que sus nodos hijos se indenteen al siguiente nivel.

Los elementos compactos están en algún punto intermedio. En cuanto a la eliminación de espacios en blanco, se tratan como elementos de bloque. En cuanto a la indentación, siempre comienzan una nueva línea, pero solo hacen que sus nodos hijos se indenteen al siguiente nivel si tienen descendientes de bloque. Si imaginamos que en HTML, "<ul>" es un elemento de bloque, "<i>" es un elemento en línea y "<li>" es un elemento compacto

XML::LibXML::PrettyPrint(3pm)

NAME

XML::LibXML::PrettyPrint - Pretty-print an XML document

SYNOPSIS

  use XML::LibXML::PrettyPrint;

  my $formatter = XML::LibLibXML::PrettyPrint->new(
    indent_string => "  ",
    newlines      => 1,
  );

  my $xml_string = $formatter->format_xml_string($xml_string);
  $formatter->format_xml_file($input_file, $output_file);
  $formatter->format_xml_node($node);

DESCRIPTION

This module allows you to pretty-print XML documents (adding indentation and newlines) using the XML::LibXML module.

It is designed to be used as a filter. You can:

Parse
Parse your XML document using XML::LibXML.
Format
Pass the resulting XML::LibXML::Node object or document to the pretty-printer.
Output
Serialize the pretty-printed XML to a string or file.

The formatter accepts the following constructor arguments:

indent_string
The string to use for indentation. Defaults to two spaces (" ").
new_lines
Whether to add newlines between elements. Defaults to 1 (true).
preserve_comments
Whether to preserve comments. Defaults to 1 (true).
indent_empty_elements
Whether to indent empty elements that contain only whitespace. Defaults to 0 (false).
element_indent_callback
A callback used to determine whether a given element should be indented. See ELEMENT CATEGORIES.
comment_indent_callback
A callback used to determine whether a given comment should be indented. See ELEMENT CATEGORIES.
pi_indent_callback
A callback used to determine whether a given processing instruction should be indented. See ELEMENT CATEGORIES.

The following methods are available:

new( %args )
Constructor.
format_xml_string( $xml_string )
Takes an XML string, parses it, pretty-prints it, and returns the pretty-printed XML string.
format_xml_file( $input_file, $output_file )
Takes an input XML filename, pretty-prints its contents, and writes the result to the output XML filename.
format_xml_node( $node )
Takes an XML::LibXML::Node object (or document), pretty-prints it in place, and returns the modified node.

ELEMENT CATEGORIES

By default, all elements are considered to be block elements. This means that they will always cause indentation.

However, you can override this default behaviour by passing callbacks to the constructor. These callbacks are invoked with the node name (for elements) or the content (for comments and PIs) and should return 1 if the node should be treated as a block element, or 0 if it should be treated as an inline element.

By default, all nodes are indented. For example:

<ul>
  <li>Will Smith - Will Smith</li>
  <li>Carlton Banks - Alfonso Ribeiro</li>
  <li>
    Vivian Banks:
    <ul>
      <li>Janet Hubert-Whitten (seasons 1-3)</li>
      <li>Daphne Maxwell Reid (seasons 3-6)</li>
    </ul>
  </li>
</ul>

The third "<li>" element is indented like a block element because it contains a block "<ul>" element. The other "<li>" elements do not have their contents indented, because they contain only inline content.

Elements default to being block, but you can specify particular elements as inline or compact by passing node names or callbacks to the constructor. Elements default to not preserving whitespace unless they have an "xml:space="preserve"" attribute, but again you can use the constructor to change this.

Comments and processing instructions default to being compact, but you can make particular comments or PIs inline or block by passing appropriate callbacks to the constructor. Whitespace within comments and PIs is always preserved. (There is rarely any reason to make comments and processing instructions block, but making them inline can occasionally be useful, as it will mean that the presence of whitespace just before or just after the comment is treated as significant.)

Text nodes are always inline.
