NOMBRE

XmDisplay — La clase del widget Display

SINOPSIS

#include <Xm/Display.h>

DESCRIPCIÓN

El objeto XmDisplay es utilizado por los widgets de Motif para almacenar información específica de una pantalla. También permite al toolkit acceder a cierta información en jerarquías de widgets que de otro modo estaría inaccesible. Cada cliente tiene un objeto XmDisplay por cada pantalla a la que accede.

Un objeto XmDisplay se crea automáticamente cuando la aplicación crea la primera ventana principal (shell) en una pantalla (generalmente logrado mediante una llamada a XtAppInitialize o XtAppCreateShell). No es necesario crear un objeto XmDisplay de ninguna otra manera. Una aplicación puede usar la función XmGetXmDisplay para obtener el ID del widget del objeto XmDisplay para una pantalla dada.

Una aplicación no puede proporcionar valores iniciales para los recursos de XmDisplay como argumentos en una llamada a cualquier función que cree widgets. La aplicación o el usuario pueden proporcionar valores iniciales en un archivo de recursos. Después de crear la primera ventana principal en la pantalla, la aplicación puede usar XmGetXmDisplay para obtener el ID del widget del objeto XmDisplay y luego llamar a XtSetValues para establecer los recursos de XmDisplay.

Los recursos de XmDisplay especifican el estilo del protocolo de arrastrar y soltar para un cliente que participa en transacciones de arrastrar y soltar. Los dos tipos básicos de protocolo son preregistro y dinámico. Cuando se utiliza un protocolo de preregistro, el toolkit maneja cualquier comunicación entre los clientes iniciadores y receptores y muestra los efectos visuales apropiados de arrastrar sobre y arrastrar debajo. Un cliente registra sus sitios de soltar por adelantado y esta información se almacena en una propiedad para cada ventana de nivel superior. Cuando el puntero de arrastre entra en una ventana de nivel superior, el iniciador lee la información del sitio de soltar. Un protocolo dinámico permite que los clientes de origen y destino comuniquen dinámicamente información de estado de arrastrar y soltar entre sí, y actualicen sus respectivos visuales en consecuencia. El toolkit proporciona información del sitio de soltar a medida que el puntero pasa sobre cualquier sitio de soltar dado. En este modo, un receptor puede proporcionar un procedimiento para generar sus propios efectos de arrastrar debajo.

Clases

Display hereda comportamiento y recursos de las clases Core, Composite, Shell, WMShell, VendorShell, TopLevelShell y ApplicationShell.

El puntero de clase es xmDisplayClass.

El nombre de la clase es XmDisplay.

Nuevos Recursos

La siguiente tabla define un conjunto de recursos de widgets utilizados por el programador para especificar datos. El programador también puede establecer los valores de los recursos para las clases heredadas para establecer atributos para este widget. Para referirse a un recurso por nombre o por clase en un archivo .Xdefaults, elimine el prefijo XmN o XmC y utilice las letras restantes. Para especificar uno de los valores definidos para un recurso en un archivo .Xdefaults, elimine el prefijo Xm y utilice las letras restantes (en minúsculas o mayúsculas, pero incluya los guiones bajos entre palabras). XmNdefaultButtonEmphasis
Especifica si se debe cambiar la apariencia del widget y el gadget PushButton que tienen el recurso XmNshowAsDefault establecido. Cuando el PushButton es el predeterminado, tiene un botón con relieve hacia afuera que está rodeado por otro borde con relieve hacia adentro. XmNdefaultButtonEmphasis tiene los siguientes valores posibles, que afectan al cursor de ubicación:
XmINTERNAL_HIGHLIGHT
Hace que el cursor de ubicación aparezca entre los dos bordes grabados para minimizar el espacio requerido.
XmEXTERNAL_HIGHLIGHT
Hace que el PushButton dibuje el cursor de ubicación fuera del segundo borde.
XmNdefaultVirtualBindings
Especifica los enlaces virtuales predeterminados para la pantalla. A continuación, se muestra un ejemplo de una especificación para el recurso defaultVirtualBindings en un archivo de recursos:

        osfLeft:       <Key>left, Ctrl<Key>H
XmNdragInitiatorProtocolStyle
Especifica los requisitos o preferencias del protocolo de arrastrar y soltar cuando el cliente es un iniciador. Los valores posibles son
XmDRAG_PREREGISTER
Como iniciador, este cliente no utiliza el protocolo dinámico y solo puede organizar efectos visuales con receptores que proporcionen información preregistrada.
XmDRAG_DYNAMIC
Como iniciador, este cliente no hace uso de ninguna información de sitio de arrastre preregistrada disponible por otros clientes, y solo puede organizar efectos visuales con receptores que utilizan el protocolo dinámico.
XmDRAG_NONE
Especifica que el arrastrar y soltar está deshabilitado para este cliente.
XmDRAG_DROP_ONLY
Como iniciador, este cliente no utiliza ni la información de sitio de arrastre preregistrada ni el protocolo dinámico. Admite el arrastre, y cada vez que el cursor está sobre un cliente que admite arrastrar y soltar, se proporciona una respuesta visual válida. No hay otros efectos visuales.
XmDRAG_PREFER_DYNAMIC
Como iniciador, este cliente puede admitir tanto los protocolos preregistrado como dinámico, pero prefiere utilizar los protocolos dinámicos siempre que sea posible para proporcionar una respuesta visual de arrastre bajo de alta calidad.
XmDRAG_PREFER_PREREGISTER
Como iniciador, este cliente puede admitir tanto los protocolos preregistrado como dinámico, pero prefiere utilizar el protocolo preregistrado siempre que sea posible para satisfacer las necesidades de rendimiento o para proporcionar una respuesta visual de arrastre constante.
XmDRAG_PREFER_RECEIVER
Indica que este cliente puede admitir tanto los protocolos preregistrado como dinámico, pero se deferirá a la preferencia del cliente receptor. Este valor solo es válido para el recurso XmNdragInitiatorProtocolStyle, y es su valor predeterminado.
XmNdragReceiverProtocolStyle
Especifica los requisitos o preferencias del protocolo de arrastrar y soltar cuando este cliente es un receptor. Los valores son
XmDRAG_PREREGISTER
Como receptor, este cliente preregistra la información del sitio de arrastre y no utiliza el protocolo dinámico. Solo puede organizar efectos visuales con iniciadores que hagan uso de la información preregistrada.
XmDRAG_DYNAMIC
Como receptor, este cliente utiliza el protocolo dinámico y no preregistra información del sitio de arrastre. Solo puede organizar efectos visuales con iniciadores que utilicen el protocolo dinámico.
XmDRAG_NONE
Especifica que el arrastrar y soltar está deshabilitado para este cliente.
XmDRAG_DROP_ONLY
Como receptor, este cliente no utiliza el protocolo dinámico ni preregistra información del sitio de arrastre. Admite soltar, y cuando se arrastra sobre este cliente, siempre se proporciona una respuesta válida, pero no hay otros efectos visuales.
XmDRAG_PREFER_DYNAMIC
Como receptor, este cliente puede admitir tanto los protocolos preregistrado como dinámico, pero prefiere utilizar el protocolo dinámico siempre que sea posible para proporcionar una respuesta visual de arrastre bajo de alta calidad.
XmDRAG_PREFER_PREREGISTER
Como receptor, este cliente puede admitir tanto los protocolos preregistrado como dinámico, pero prefiere utilizar el protocolo preregistrado siempre que sea posible para satisfacer las necesidades de rendimiento.
El valor predeterminado de este recurso depende de las capacidades de la pantalla. Si la pantalla admite la extensión de forma, lo que permite que el protocolo dinámico utilice cursores de arrastre de tamaño arbitrario, el valor predeterminado de este recurso es XmDRAG_PREFER_DYNAMIC; de lo contrario, el valor predeterminado es XmDRAG_PREFER_PREREGISTER.
El protocolo real utilizado entre un iniciador y un receptor se basa en el estilo del protocolo del receptor e iniciador. La matriz de decisión se describe en la siguiente tabla.

Resources

XmNactiveMenuHistory
Specifies whether to enable the active menu history feature. A value of True enables active menu history. A value of False disables it.
XmNclientPolicy
Specifies the protocol style for drag and drop transactions. This resource can take the following values:
XmDRAG_PRESERVE
Preserves the protocol style of the initiator or receiver. If the initiator and receiver cannot agree on a protocol style, the transaction fails.
XmDRAG_DROP_ONLY
Specifies that the receiver only supports drop transactions. This value is returned when the initiator and receiver cannot agree on a protocol style. For example, if one client requires dynamic mode and the other can only support preregister mode, or if either client explicitly specifies XmDRAG_DROP_ONLY.
XmDRAG_DYNAMIC
Specifies that the receiver supports dynamic drag and drop. This is the default protocol style. This means that the receiver supports both preregistered and dynamic modes.

El valor XmDRAG_NONE no aparece en la matriz. Cuando se especifica para el lado del iniciador o del receptor, XmDRAG_NONE implica que las transacciones de arrastrar y soltar no son compatibles. Un valor de XmDRAG_DROP_ONLY (Solo soltar) resulta cuando un iniciador y un receptor no pueden llegar a un acuerdo sobre los estilos de protocolo, es decir, un cliente requiere modo dinámico mientras que el otro solo puede admitir modo de preregistro, o si alguno de ellos ha especificado explícitamente XmDRAG_DROP_ONLY.
XmNdragStartCallback
Especifica la lista de devoluciones de llamada que se invocan cuando se llama a la función XmDragStart. El tipo de estructura cuya dirección se pasa a esta devolución de llamada es XmDragStartCallbackStruct. La razón de la devolución de llamada es XmCR_DRAG_START.
XmNenableBtn1Transfer
Especifica si las acciones de selección y transferencia están integradas en el Botón 1 y las acciones extendidas se activan en el Botón 2. Este recurso puede tomar los siguientes valores:
XmOFF
Deshabilita la integración y la activación de selección en el Botón 1.
XmBUTTON2_TRANSFER
Habilita la integración y la activación de selección en el Botón 1 y la transferencia en el Botón 2.
XmBUTTON2_ADJUST
Habilita la integración y la activación de selección en el Botón 1 y el ajuste en el Botón 2.
Este recurso afecta a las acciones de Text, TextField, List y Container.
XmNenableButtonTab
Especifica si la acción de la tecla <Tab> (acciones KNextField y KPrevField) se va a modificar. Un valor de True modifica la tecla para moverse como una tecla de flecha hasta que se alcance el límite de un grupo de pestañas. Luego, en el límite del grupo de pestañas, KNextField y KPrevField se moverán al siguiente o anterior grupo de pestañas, respectivamente. Un valor de False no causa modificación.
XmNenableDragIcon
Especifica qué conjunto de iconos se utilizará para los cursores predeterminados del sistema durante las operaciones de arrastrar y soltar. Un valor de False especifica que se utilizarán iconos de versiones anteriores de Motif, un valor de True especifica que se utilizarán iconos alternativos. Este recurso afecta tanto a los iconos de 16x16 como a los de 32x32 que son los predeterminados del sistema para cada uno de los objetos Screen asociados a esta pantalla.
XmNenableEtchedInMenu
Especifica el sombreado de los widgets y gadgets de botones en los menús cuando se activa el control. Un valor de True hace que el menú seleccionado se dibuje con la sombra grabada; este estilo de sombra es coherente con la apariencia seleccionada de otros widgets de botones fuera de los menús. Un valor de False hace que el menú seleccionado se dibuje con la sombra grabada hacia afuera. Este recurso afecta a las acciones de los widgets y gadgets PushButton, ToggleButton y CascadeButton cuando son hijos de Menu.
Cuando este recurso está establecido, el fondo de un botón en un menú utiliza el XmNselectColor (derivado de XmNselectPixel) cuando está armado como predeterminado. Un PushButton utiliza el XmNarmColor si está definido. Un ToggleButton utiliza el XmNselectColor si XmNindicatorOn es False y XmNfillOnSelect es True.
XmNenableToggleColor
Especifica cómo determinar el valor predeterminado del recurso XmNselectColor de ToggleButton y ToggleButtonGadget. Un valor de True hace que el valor predeterminado de XmNselectColor se establezca en el valor de XmNhighlightColor. Un valor de False hace que el valor predeterminado de XmNselectColor se establezca en el valor de XmNbackground. Este recurso solo afecta a la apariencia de los widgets y gadgets ToggleButton que están en modo XmONE_OF_MANY o XmONE_OF_MANY_ROUND. Además, XmNenableToggleColor solo influye en el valor predeterminado de XmNselectColor. Es decir, si el usuario o la aplicación establecen un valor para XmNselectColor, entonces XmNenableToggleColor se ignora.
XmNenableToggleVisual
Especifica la apariencia visual del widget y/o gadget ToggleButton. Este recurso afecta al valor predeterminado de los recursos XmNindicatorType y XmNindicatorOn de ToggleButton[Gadget]. Cuando el ToggleButton está en un RadioBox, un valor de True hace que XmONE_OF_MANY_ROUND (un círculo sombreado) sea el valor predeterminado. De lo contrario, cuando este recurso es True, el recurso ToggleButton XmNindicatorOn provoca un valor predeterminado de XmN_OF_MANY, que será un cuadrado sombreado con una marca de verificación (casilla de verificación).
Un valor de False causa lo siguiente:
XmONE_OF_MANY
Es un diamante sombreado.
XmN_OF_MANY
Es un cuadrado sombreado.
XmNenableUnselectableDrag
Especifica si es posible arrastrar desde Label y Scale. Un valor de True habilita el arrastre; un valor de False lo deshabilita.
XmNenableWarp
Especifica si se permite a una aplicación mover el puntero del usuario. Un valor de True habilita el movimiento del puntero, un valor de False no lo habilita.
XmNmotifVersion
Especifica la versión actual de Motif con la que se supone que debe comportarse la implementación actual. Por defecto, este recurso obtiene su valor de los valores de lanzamiento en Xm.h.
XmNnoFontCallback
Esta devolución de llamada se llama cada vez que una rendition intenta cargar una fuente o un conjunto de fuentes y falla. Esto puede ocurrir en la creación si la fuente se especifica como XmLOAD_IMMEDIATE o cuando se intenta renderizar un XmString utilizando una fuente especificada como XmLOAD_DEFERRED. Una aplicación puede hacer que esta devolución de llamada intente solucionar este problema llamando a XmRenditionUpdate en la rendition de entrada para proporcionar una fuente para que la utilice el widget. Esto se puede hacer proporcionando un nombre de fuente alternativo para cargar utilizando los recursos XmNfontName y XmNfontType o con una fuente ya cargada usando el recurso XmNfont. La razón de la devolución de llamada es XmCR_NO_FONT. Esta devolución de llamada utiliza la estructura XmDisplayCallbackStruct.
XmNnoRenditionCallback
Esta devolución de llamada se llama cada vez que se intenta renderizar un segmento con una etiqueta RENDITION que no coincide con ninguna rendición en una tabla de renderizado dada. La razón de la devolución de llamada es XmCR_NO_RENDITION. Esta devolución de llamada utiliza la estructura XmDisplayCallbackStruct.
Una aplicación puede hacer que esta devolución de llamada intente solucionar este problema creando una nueva rendition con la etiqueta dada y añadiéndola a render_table.
La XmNnoRenditionCallback debe liberar la tabla de renderizado pasada en el campo render_table de la estructura de devolución de llamada. Tenga en cuenta que la tabla se liberará automáticamente si se llama a la función XmRenderTableAddRenditions. La devolución de llamada NO debe liberar la tabla de renderizado modificada que se devuelve a Motif en el campo render_table. Si la aplicación desea manipular esta tabla de renderizado adicionalmente, debe hacer una copia con la función XmRenderTableCopy antes de devolver la llamada.
XmNuserData
Especifica un puntero de datos del cliente para las aplicaciones. Un recurso no utilizado internamente.

XmDisplay(3)

NAME

XmDisplay, XmScreen - Functions that deal with the Motif display and screen resources

SYNOPSIS

   #include <Xm/Xm.h>

DESCRIPTION

The Motif widget set allows applications to manage resources across multiple displays and screens. The widget set uses the concept of an XmDisplay object to represent a connection to a display. An XmDisplay object contains resources and information about a specific display connection. This includes information about the available screens, fonts, colors, and other display-specific resources.

The XmScreen object represents a screen within an XmDisplay object. It contains resources and information specific to a single screen, such as its root window, its visual information, and its depth.

Applications can obtain an XmDisplay object for the default display using XmGetXmDisplay. Applications can also obtain an XmScreen object for a specific screen within an XmDisplay object.

The following callback structures are defined:

A pointer to the following structure is passed to the XmNdragStartCallback callback:

typedef struct
{
        int reason;
        XEvent  *event;
        Widget widget;
        Boolean doit;
}XmDragStartCallbackStruct;
reason
Indicates why the callback was invoked
event
Points to the XEvent that triggered the callback
widget
Indicates the ID of the widget from which the drag was initiated.
doit
Is an IN/OUT member that allows the callback to determine whether to continue with the drag or cancel. Setting doit to False will cancel the drag. The default value is True.

A pointer to the following structure is passed to the XmNnoFontCallback and XmNnoRenditionCallback callbacks:

typedef struct
{
        int reason;
        XEvent *event;
        XmRendition rendition;
        char *font_name;
        XmRenderTable render_table;
        XmStringTag tag;
}XmDisplayCallbackStruct;
reason
Indicates why the callback was invoked.
event
Points to the XEvent that triggered the callback. It can be NULL.
rendition
Specifies the rendition with the missing font.
font_name
Specifies the name of the font or font set which could not be loaded.
render_table
Specifies the render table with the missing rendition.
tag
Specifies the tag of the missing rendition.

The following table describes the reasons for which the individual callback structure fields are valid.

Reason Valid Fields
XmCR_NO_FONT rendition, font_name
XmCR_NO_RENDITION render_table, tag
