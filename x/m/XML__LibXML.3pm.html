DESCRIPCIÓN

Este módulo es una interfaz a libxml2, que proporciona analizadores XML y HTML con interfaces DOM, SAX y XMLReader, un subconjunto grande de la interfaz DOM Layer 3 y una interfaz similar a XML::XPath para la API XPath de libxml2. El módulo está dividido en varios paquetes que no se describen en esta sección; a menos que se indique lo contrario, solo necesita "use XML::LibXML;" en sus programas.

Consulte XML::LibXML by Example (http://grantm.github.io/perl-libxml-by-example/) para un tutorial.

Para más información, consulte la siguiente documentación:

SOPORTE DE CODIFICACIONES EN XML::LIBXML

Recordemos que desde la versión 5.6.1, Perl distingue entre cadenas de caracteres (codificadas internamente en UTF-8) y los llamados datos binarios y, en consecuencia, les aplica semántica de caracteres o de bytes. Un escalar que representa una cadena de caracteres se distingue de una cadena de bytes por una bandera especial (UTF8). Consulte perlunicode para obtener detalles.

La API de XML::LibXML está diseñada para manejar muchas codificaciones de documentos XML de forma completamente transparente, de modo que la aplicación que utiliza XML::LibXML pueda ser completamente ignorante de la codificación de los documentos XML con los que trabaja. Por otro lado, funciones como "XML::LibXML::Document->setEncoding" dan al usuario control sobre la codificación del documento.

Para garantizar la transparencia y uniformidad mencionadas, la mayoría de las funciones de XML::LibXML que trabajan con árboles en memoria aceptan y devuelven datos como cadenas de caracteres (es decir, codificadas en UTF-8 con la bandera UTF8 activada) independientemente de la codificación original del documento; sin embargo, las funciones relacionadas con las operaciones de E/S (es decir, análisis y guardado) operan con datos binarios (en la codificación original del documento) respetando la declaración de codificación de los documentos XML.

A continuación, resumimos las reglas y principios básicos relacionados con la codificación:

1.
NO aplique capas PerlIO relacionadas con la codificación (":utf8" o :encoding(...)) a los manejadores de archivos que sean una entrada para los analizadores o una salida para un serializador de documentos XML (completos). Esto se debe a que la conversión de los datos hacia/desde la representación de caracteres interna la proporciona libxml2, que debe ser capaz de aplicar la codificación especificada por la declaración "<?xml version="1.0" encoding="..."?>". Aquí hay un ejemplo a seguir: 
use XML::LibXML;
# cargar
open my $fh, '<', 'file.xml';
binmode $fh; # eliminar todas las capas PerlIO posiblemente creadas por un pragma use open
$doc = XML::LibXML->load_xml(IO => $fh);
# guardar
open my $out, '>', 'out.xml';
binmode $out; # como arriba
$doc->toFH($out);
# o
print {$out} $doc->toString();
2.
Todas las funciones que trabajan con DOM aceptan y devuelven cadenas de caracteres (codificadas en UTF-8 con la bandera UTF8 activada). Por ejemplo: 
my $doc = XML::LibXML::Document->new('1.0',$some_encoding);
my $element = $doc->createElement($name);
$element->appendText($text);
$xml_fragment = $element->toString(); # devuelve una cadena de caracteres
$xml_document = $doc->toString(); # devuelve una cadena de bytes

donde $some_encoding es la codificación del documento que se utilizará al guardar el documento, y $name y $text contienen cadenas de caracteres (codificadas en UTF-8 con la bandera UTF8 activada). Tenga en cuenta que el método "toString" devuelve XML como una cadena de caracteres si se aplica a un nodo que no sea el nodo Documento, y una cadena de bytes que contiene la declaración apropiada

<?xml version="1.0" encoding="..."?>

si se aplica a un XML::LibXML::Document.

3.
Los métodos DOM también aceptan cadenas binarias en la codificación original del documento al que pertenece el nodo (se asume UTF-8 si el nodo no está adjunto a ningún documento). NO SE RECOMIENDA explotar esta característica, ya que se considera una mala práctica. 
my $doc = XML::LibXML::Document->new('1.0','iso-8859-2');
my $text = $doc->createTextNode($some_latin2_encoded_byte_string);
# FUNCIONA, ¡PERO NO SE RECOMIENDA!

NOTA: El soporte de libxml2 para muchas codificaciones se basa en la biblioteca iconv. La lista real de codificaciones compatibles puede variar de una plataforma a otra. Para probar si su plataforma funciona correctamente con la codificación de su idioma, construya un documento simple en la codificación particular e intente analizarlo con XML::LibXML para ver si el analizador produce algún error. Se han reportado bloqueos ocasionales en plataformas raras que vienen con una versión defectuosa de iconv.

SOPORTE DE HILOS

XML::LibXML desde la versión 1.67 soporta parcialmente Perl t

HILOS

>= 5.8.8. XML::LibXML se puede usar con hilos de dos maneras:

Por defecto, todas las clases de XML::LibXML usan el método de clase CLONE_SKIP para evitar que Perl copie objetos XML::LibXML::* cuando se inicia un nuevo hilo. En este modo, todos los objetos XML::LibXML::* son específicos del hilo. Esta es la forma más segura de trabajar con XML::LibXML en hilos.

Alternativamente, se puede usar

use threads;
use XML::LibXML qw(:threads_shared);

para indicar que todos los nodos y objetos del analizador de XML::LibXML deben ser compartidos entre el hilo principal y cualquier hilo iniciado desde él. Por ejemplo, en

my $doc = XML::LibXML->load_xml(location => $filename);
my $thr = threads->new(sub{
  # código que trabaja con $doc
  1;
});
$thr->join;

la variable $doc se refiere exactamente al mismo XML::LibXML::Document en el hilo iniciado que en el hilo principal.

Sin usar bloqueos de mutex, los hilos paralelos pueden leer el mismo documento (es decir, cualquier nodo que pertenezca al documento), analizar archivos y modificar diferentes documentos.

Sin embargo, si existe la posibilidad de que algunos de los hilos intenten modificar un documento (o incluso crear nuevos nodos basados en ese documento, por ejemplo, con "$doc->createElement") que otros hilos puedan estar leyendo al mismo tiempo, el usuario es responsable de crear un bloqueo de mutex y usarlo *tanto* en el hilo que modifica como en el hilo que lee:

my $doc = XML::LibXML->load_xml(location => $filename);
my $mutex : shared;
my $thr = threads->new(sub{
   lock $mutex;
   my $el = $doc->createElement('foo');
   # ...
  1;
});
{
  lock $mutex;
  my $root = $doc->documentElement;
  say $root->name;
}
$thr->join;

Tenga en cuenta que libxml2 utiliza diccionarios para almacenar cadenas cortas y estos diccionarios se mantienen en un nodo del documento. Sin bloqueos de mutex, en el ejemplo anterior podría suceder que el hilo modifique el diccionario mientras otros hilos intentan leer de él, lo que podría llevar fácilmente a un fallo.

INFORMACIÓN DE VERSIÓN

A veces es útil determinar para qué versión se compiló XML::LibXML. En la mayoría de los casos, esto es para depuración o para verificar si una instalación dada cumple con todas las funcionalidades del paquete. Las funciones XML::LibXML::LIBXML_DOTTED_VERSION y XML::LibXML::LIBXML_VERSION proporcionan esta información de versión. Ambas funciones simplemente pasan los valores de las macros del mismo nombre de libxml2. De manera similar, XML::LibXML::LIBXML_RUNTIME_VERSION devuelve la versión de libxml2 (generalmente enlazada dinámicamente) con la que se está ejecutando.

XML::LibXML::LIBXML_DOTTED_VERSION
$Version_String = XML::LibXML::LIBXML_DOTTED_VERSION;

Devuelve la cadena de versión de la versión de libxml2 para la que se compiló XML::LibXML. Será "2.6.2" para "libxml2 2.6.2".

XML::LibXML::LIBXML_VERSION
$Version_ID = XML::LibXML::LIBXML_VERSION;

Devuelve el ID de versión de la versión de libxml2 para la que se compiló XML::LibXML. Será "20602" para "libxml2 2.6.2". No mezcle este ID de versión con $XML::LibXML::VERSION. Este último contiene la versión de XML::LibXML en sí, mientras que el primero contiene la versión de libxml2 para la que se compiló XML::LibXML.

XML::LibXML::LIBXML_RUNTIME_VERSION
$DLL_Version = XML::LibXML::LIBXML_RUNTIME_VERSION;

Devuelve una cadena de versión de la libxml2 que está enlazada (generalmente dinámicamente) por XML::LibXML. Será "20602" para libxml2 lanzada como "2.6.2" y algo como "20602-CVS2032" para una compilación CVS de libxml2.

XML::LibXML emite una advertencia si la versión de libxml2 enlazada dinámicamente es inferior a la versión de libxml2 contra la que se compiló.

XML::LIBXML Y XML::GDOME

Nota: *LAS FUNCIONES DESCRITAS AQUÍ SON EXPERIMENTALES*

Aunque ambos módulos utilizan las capacidades XML de libxml2, la implementación DOM de ambos módulos no es compatible. Pero aun así es posible intercambiar nodos de un DOM a otro. El concepto de este intercambio es bastante similar a la función cloneNode(): el nodo en particular se copia a bajo nivel a la implementación DOM opuesta.

Dado que las implementaciones DOM no pueden coexistir dentro de un mismo documento, uno se ve obligado a copiar cada nodo que se utilizará. Dado que siempre se conservan dos nodos, esto puede tener un impacto considerable en el uso de memoria de una máquina.

XML::LibXML proporciona dos funciones para exportar o importar nodos GDOME: import_GDOME() y export_GDOME(). Ambas funciones tienen dos parámetros: el nodo y una bandera para importación recursiva. La bandera funciona igual que en cloneNode().

Las dos funciones permiten exportar e importar explícitamente nodos XML::GDOME; sin embargo, XML::LibXML también permite la importación transparente de nodos XML::GDOME en funciones como appendChild(), insertAfter() y similares. Mientras que los nodos nativos son adoptados automáticamente en la mayoría de las funciones, los nodos XML::GDOME siempre se clonan previamente. Por lo tanto, si el nodo original se modifica después de la operación, el nodo en el documento XML::LibXML no tendrá esta información.

import_GDOME
$libxmlnode = XML::LibXML->import_GDOME( $node, $deep );

Clona explícitamente un nodo XML::GDOME a un nodo XML::LibXML.

export_GDOME
$gdomenode = XML::LibXML->export_GDOME( $node, $deep );

Permite clonar un nodo XML::LibXML a un nodo XML::GDOME.

XML::LibXML(3pm)

XML::LibXML - Perl interface to the XML::LibXML library

NOMBRE

XML::LibXML - Perl interface to the XML::LibXML library

SINOPSIS

use XML::LibXML;
my $parser = XML::LibXML->new();
my $doc = $parser->parse_file('foo.xml');
print $doc->toString();

# or
use XML::LibXML qw(Parser);
my $parser = Parser->new();
my $doc = $parser->parse_string($xml_string);

DESCRIPCIÓN

This module is a Perl binding for the XML::LibXML library, which in turn is a Perl interface to the libxml2 library from Gnome. libxml2 is a widely used and high-performance XML parser.

The module provides a SAX parser and a DOM parser. The DOM parser is compliant with the DOM Level 3 Load and Save Recommendation.

The module also supports XPath queries.

SOPORTE DE CODIFICACIONES EN XML::LIBXML

XML::LibXML supports a variety of character encodings. The encodings that are supported depend on the libxml2 library. Generally, UTF-8, UTF-16, ISO-8859-1, and US-ASCII are supported.

When parsing XML documents, XML::LibXML will attempt to detect the encoding from the XML declaration (e.g., `<?xml version="1.0" encoding="UTF-8"?>`). If no encoding is declared, UTF-8 is assumed.

SOPORTE DE HILOS

XML::LibXML is thread-safe. You can use multiple XML::LibXML parsers in different threads concurrently.

INFORMACIÓN DE VERSIÓN

The module version is 2.0210.

EXPORTACIONES

By default, XML::LibXML exports nothing. However, it provides the following export tags:

ETIQUETAS DE EXPORTACIÓN

:all
Exports all symbols.
:parser
Exports the Parser class.
:reader
Exports the Reader class.
:xpath
Exports XPath related functions.

MÓDULOS RELACIONADOS

XML::LibXML::Reader, XML::LibXML::SAX, XML::LibXML::XPath

XML::LIBXML Y XML::GDOME

XML::LibXML can be used with XML::GDome, which provides a Perl interface to the Gnome DOM library. This allows you to use the powerful features of libxml2 for parsing and manipulating XML documents, and then use XML::GDome to work with the DOM tree.
