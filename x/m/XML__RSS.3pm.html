NOMBRE

XML::RSS - crea y actualiza archivos RSS

VERSIÓN

versión 1.65

 # ya hay 15 elementos o más

 while (@{$rss->{'items'}} >= 15)
 {
     shift (@{ $rss->{'items'} });
 }
 $rss->add_item(title => "MpegTV Player (mtv) 1.0.9.7",
                link  => "http://freshmeat.net/news/1999/06/21/930003958.html",
                mode  => 'insert'
                );
 # parsear una cadena en lugar de un archivo
 $rss->parse($string);
 # imprimir el título y el enlace de cada elemento RSS
 foreach my $item (@{$rss->{'items'}}) {
     print "título: $item->{'title'}\n";
     print "enlace: $item->{'link'}\n\n";
 }
 # sacar el archivo RSS 0.9 o 0.91 como RSS 1.0
 $rss->{output} = '1.0';
 print $rss->as_string;

DESCRIPCIÓN

Este módulo proporciona un marco básico para crear y mantener archivos RDF Site Summary (RSS). Esta distribución también contiene muchos ejemplos que te permiten generar HTML a partir de un RSS, convertir entre versiones 0.9, 0.91, 1.0 y 2.0, y otras cosas útiles. Esto puede ser útil si quieres incluir fuentes de noticias en tu sitio web de fuentes como Slashdot y Freshmeat o si quieres sindicar tu propio contenido.

XML::RSS actualmente soporta las versiones 0.9 http://www.rssboard.org/rss-0-9-0, 0.91 http://www.rssboard.org/rss-0-9-1, 1.0 http://web.resource.org/rss/1.0/, y 2.0 http://www.rssboard.org/rss-2-0 de RSS.

RSS fue desarrollado originalmente por Netscape como el formato para los canales Netscape Netcenter, sin embargo, muchos sitios web lo han adoptado desde entonces como un formato de sindicación simple. Con la llegada de RSS 1.0, los usuarios ahora pueden sindicar muchos tipos diferentes de contenido, incluyendo titulares de noticias, mensajes en hilo, catálogos de productos, etc.

Nota: Para parsear y generar fechas (como "pubDate" y "dc:date") se recomienda usar DateTime::Format::Mail y DateTime::Format::W3CDTF, que es lo que XML::RSS usa internamente y requiere. También debería ser posible pasar objetos DateTime que se formatearán en consecuencia. Por ejemplo:

use DateTime ();
my $dt = DateTime->from_epoch(epoch => 1_500_000_000);
$rss->channel(
    pubDate => $dt,
    .
    .
    .
);

MÉTODOS

XML::RSS->new(version=>$version, encoding=>$encoding, output=>$output, stylesheet=>$stylesheet_url, 'xml:base'=>$base)
Constructor para XML::RSS. Devuelve una referencia a un objeto XML::RSS. También puedes pasar la versión de RSS y la codificación XML a usar. La versión predeterminada (version) es 1.0. La codificación predeterminada (encoding) es UTF-8. También puedes especificar el formato de salida (output) independientemente de la versión de entrada. Esto es útil cuando quieres convertir RSS entre versiones. Los módulos XML::RSS convertirán entre cualquiera de los formatos. Si estableces <encode_output> XML::RSS se asegurará de codificar cualquier entidad en el RSS generado. Esto está activado por defecto ahora.

También puedes pasar una URL opcional a una hoja de estilos XSL que se puede usar para generar una "<?xsl-stylesheet ...

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Puede establecer "html_meta_tag" a una cadena que se convertirá en una meta-tag en la cabecera que permitirá a algunos navegadores renderizar el archivo RSS como HTML.

También puede establecer "encode_cb" a una referencia a una subrutina que codificará la salida de una manera personalizada. Esta subrutina acepta dos parámetros: una referencia al objeto derivado de "XML::RSS::Private::Output::Base" (que normalmente no debería preocuparle) y el texto a codificar. Debe devolver el texto a codificar. Si no se establece, el módulo codificará utilizando su rutina de codificación personalizada.

xml:base establecerá una propiedad "xml:base" según

http://www.w3.org/TR/xmlbase/

Tenga en cuenta que para codificar correctamente, debe manejar las secciones "CDATA" adecuadamente. Consulte el método _default_encode() de XML::RSS::Private::Output::Base para saber cómo hacerlo correctamente.

add_item (title=>$title, link=>$link, description=>$desc, mode=>$mode)
Añade un elemento al objeto XML::RSS. mode y description son opcionales. El mode por defecto es 'append', que añade el elemento al final de la lista. Para insertar un elemento, establezca el modo a insert.

Los elementos se almacenan en el array "@{$obj->{'items'}}" donde $obj es una referencia a un objeto XML::RSS.

Se puede especificar una categoría utilizando la clave 'category'. 'category' puede apuntar a una referencia de array de categorías:

$rss->add_item(
    title => "Foo&Bar",
    link => "http://www.my.tld/",
    category => ["OneCat", "TooCat", "3Kitties"],
);
as_string;
Devuelve una cadena que contiene el RSS para el objeto XML::RSS. Este método también codificará caracteres especiales en el proceso.
channel (title=>$title, link=>$link, description=>$desc, language=>$language, rating=>$rating, copyright=>$copyright, pubDate=>$pubDate, lastBuildDate=>$lastBuild, docs=>$docs, managingEditor=>$editor, webMaster=>$webMaster)
La información del canal es necesaria en RSS. El title no puede superar los 40 caracteres, el link los 500 y la description los 500 al generar RSS 0.9. title, link y description son necesarios para RSS 1.0. language es necesario para RSS 0.91. Los demás parámetros son opcionales para RSS 0.91 y 1.0.

Para recuperar los valores del canal, pase el nombre del valor (title, link o description) como primer y único argumento, de la siguiente manera:

$title = channel('title');

image (title=>$title, url=>$url, link=>$link, width=>$width, height=>$height, description=>$desc)
Añadir una imagen no es obligatorio. url es la URL de la imagen, link es la URL a la que enlaza la imagen. Los parámetros title, url y link son obligatorios si va a utilizar una imagen en su archivo RSS. Los elementos de imagen restantes se utilizan en RSS 0.91 o se importan opcionalmente en RSS 1.0 a través del espacio de nombres rss091.

El método para recuperar los valores de la imagen es el mismo que para channel().

parse ($string, \%options)
Analiza un Resumen del Sitio RDF que se pasa a parse() como primer parámetro. Devuelve la instancia del objeto para que se pueda decir "$rss->parse($string)->other_method()".

Consulte el método add_module() para obtener instrucciones sobre cómo añadir módulos automáticamente al analizar una cadena.

%options es una lista de opciones que especifican cómo se debe realizar el análisis. Las opciones disponibles son:

  • allow_multiple

    Acepta una referencia de array de nombres que indica qué elementos deben permitirse tener múltiples ocurrencias. Así, por ejemplo, para analizar feeds con múltiples inclusiones

    $rss->parse($xml, { allow_multiple => ['enclosure'] });
  • hashrefs_instead_of_strings

    Si es verdadero, algunos elementos (hasta ahora ""description"") se convertirán en referencias hash en lugar de cadenas (con una clave content que contendrá su contenido, si tienen atributos XML. Sin esta clave, los atributos se ignorarán y solo habrá una cadena. Por lo tanto, especificar esta opción puede romper la compatibilidad.

  • modules_as_arrays

    Esta opción, cuando es verdadera, analizará los pares clave-valor de los módulos como una referencia de array de referencias hash "{ el => $key_name, value => $value, }" para manejar elegantemente elementos duplicados (ver abajo). No afectará a los módulos conocidos como dc ("Dublin Core").

  • allow_empty

    Acepta una referencia de array de nombres que indica qué elementos se permiten vacíos. Así, por ejemplo, para analizar feeds con campos personalizados con el formato "<foo bar="1" baz="2" />" que no tienen contenido, solo atributos, añada:

    $rss->parse($xml, { allow_empty => ['foo'] });

    (Añadido en XML::RSS v 1.63.)

parsefile ($file, \%options)
Igual que parse() excepto que analiza un archivo en lugar de una cadena.

Consulte el método add_module() para obtener instrucciones sobre cómo añadir módulos automáticamente al analizar una cadena.

save ($file)
Guarda el RSS en un archivo especificado.
skipDays (day => $day)
Rellena el elemento skipDays con el día $day.
skipHours (hour => $hour)
Rellena el elemento skipHours con la hora $hour.
strict ($boolean)
Si se establece a 1, se adherirá a las longitudes especificadas por los requisitos de Netscape Netcenter. Se establece a 0 por defecto. Úselo si el archivo RSS que está generando es para Netcenter. strict solo funcionará para RSS 0.9 y 0.91. No lo use para RSS 1.0.
textinput (title=>$title, description=>$desc, name=>$name, link=>$link);
Este elemento RSS también es opcional. Usarlo permite a los usuarios enviar una consulta a un programa en un servidor web a través de un formulario HTML. name es el nombre del formulario HTML y link es la URL del programa. El contenido se envía utilizando el método GET.

El acceso a los valores de textinput es el mismo que para channel() y image().

add_module(prefix=>$prefix, uri=>$uri)
Añade una declaración de espacio de nombres de módulo al objeto XML::RSS, permitiéndole añadir modularidad fuera de los módulos estándar de RSS 1.0. Actualmente, los módulos estándar Dublin Core (dc) y Syndication (syn) están predefinidos para su conveniencia. El módulo Taxonomy (taxo) también está soportado internamente.

Los módulos se almacenan en el hash %{$obj->{'modules'}} donde $obj es una referencia a un objeto XML::RSS.

Si desea añadir automáticamente módulos que el analizador encuentra en los espacios de nombres, establezca la variable $XML::RSS::AUTO_ADD a un valor verdadero. Por defecto, el valor es falso. (N.B. AUTO_ADD solo actualiza el hash %{$obj->{'modules'}}. No proporciona los otros beneficios de usar add_module.)

MÓDULOS RSS 1.0

La modularización basada en espacios de nombres XML permite la extensibilidad compartimentada de RSS 1.0. Los únicos módulos que se distribuyen "listos para usar" con RSS 1.0 son Dublin Core (http://purl.org/rss/1.0/modules/dc/), Syndication (http://purl.org/rss/1.0/modules/syndication/) y Taxonomy (http://purl.org/rss/1.0/modules/taxonomy/). Consulte la documentación del módulo correspondiente para obtener más información.

Añadir elementos de estos módulos en XML::RSS es tan sencillo como añadir otros atributos como title, link y description. La única diferencia es la compartimentación de sus pares clave/valor en un hash de segundo nivel.

$rss->add_item (title=>$title, link=>$link, dc=>{ subject=>$subject, creator=>$creator, date=>$date });

Para los elementos del módulo Dublin Core, utilice la clave 'dc'. Para los elementos del módulo Syndication, 'syn'. Para los elementos del módulo Taxonomy, 'taxo'. Estos son los prefijos utilizados en el propio documento XML RSS. Se asocian con espacios de nombres basados en URI apropiados:

syn:  http://purl.org/rss/1.0/modules/syndication/
dc:   http://purl.org/dc/elements/1.1/
taxo: http://purl.org/rss/1.0/modules/taxonomy/

Las claves hash de Dublin Core ('dc') pueden apuntar a una referencia de array, que a su vez especificará múltiples claves de este tipo y las renderizará una tras otra. Por ejemplo:

$rss->add_item (
    title => $title,
    link => $link,
    dc => {
        subject=> ["Jungle", "Desert", "Swamp"],
        creator=>$creator,
        date=>$date
    },
);

Los elementos de Dublin Core pueden aparecer en channel, image, item(s) y textinput, aunque es poco común encontrarlos en image y textinput. Los elementos de Syndication se limitan al elemento channel. Los elementos de Taxonomy pueden aparecer en los elementos channel o item.

El acceso a los elementos del módulo después de analizar un documento RSS 1.0 utilizando XML::RSS se realiza a través del prefijo o de la URI del espacio de nombres para su conveniencia.

print $rss->{items}->[0]->{dc}->{subject};
o
print $rss->{items}->[0]->{'http://purl.org/dc/elements/1.1/'}->{subject};

XML::RSS también tiene soporte para la modularización "no estándar" de RSS 1.0 a nivel de channel, image, item y textinput. El análisis de un documento RSS captura cualquier elemento de otros espacios de nombres que pudiera aparecer. XML::RSS también permite la inclusión de espacios de nombres arbitrarios y elementos asociados al construir documentos RSS.

Custom Namespaces

For example, to add elements of a made-up "My" module, first declare the namespace by associating a prefix with a URI:

$rss->add_module(prefix=>'my', uri=>'http://purl.org/my/rss/module/');

Then proceed as usual:

$rss->add_item (title=>$title, link=>$link, my=>{ rating=>$rating });

You can also set the value of the module's prefix to an array reference of "{ el => , val => }" hash-references, in which case duplicate elements are possible:

$rss->add_item(title=>$title, link=>$link, my=> [
  {el => "rating", value => $rating1, }
  {el => "rating", value => $rating2, },
]

Non-standard namespaces are not, however, currently accessible via a simple prefix; access them via their namespace URL like so:

print $rss->{items}->[0]->{'http://purl.org/my/rss/module/'}->{rating};

XML::RSS will continue to provide built-in support for standard RSS 1.0 modules as they appear.

$rss->as_rss_0_9()

WARNING: this function is not an API function and should not be called directly. It is kept as is for backwards compatibility with legacy code. Use the following code instead:

$rss->{output} = "0.9";
my $text = $rss->as_string();
