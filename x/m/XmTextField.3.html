NOMBRE

XmTextField — La clase TextField

SINOPSIS

#include <Xm/Xm.h>

DESCRIPCIÓN

El widget TextField proporciona un editor de texto de una sola línea para personalizar interfaces tanto del usuario como programáticas. Se utiliza para la entrada de cadenas de una sola línea y para formularios de entrada con procedimientos de verificación. Proporciona a una aplicación un sistema de edición coherente para datos textuales.

TextField proporciona listas de llamadas separadas para verificar el movimiento del cursor de inserción, la modificación del texto y los cambios en el foco de entrada. Cada una de estas llamadas proporciona a la función de verificación la instancia del widget, el evento que causó la llamada y una estructura de datos específica para el tipo de verificación. A partir de esta información, la función puede verificar si la aplicación considera que este es un cambio de estado legítimo y puede indicar al widget si debe continuar con la acción.

La interfaz de usuario adapta un nuevo conjunto de acciones. Se han agregado enlaces de teclas para el movimiento del cursor de inserción, la eliminación, la inserción y la selección de texto.

TextField permite al usuario seleccionar regiones de texto. La selección se basa en el modelo especificado en el Inter-Client Communication Conventions Manual (ICCCM). TextField admite la selección primaria y secundaria.

TextField utiliza los rasgos XmQTnavigator, XmQTspecifyRenderTable y XmQTscrollFrame, y mantiene los rasgos XmQTaccessTextual y XmQTtransfer.

Si una aplicación o widget llama al método de rasgo setValue de XmQTaccessTextual, entonces XmTextField llamará a XmTextFieldSetString para establecer el valor de la cadena.

Comportamiento de transferencia de datos

TextField admite la transferencia de las selecciones primaria, secundaria y del portapapeles, y el arrastre de texto seleccionado desde el widget. TextField también puede ser el destino de las selecciones primaria, secundaria y del portapapeles, y admite la colocación de datos arrastrados sobre el widget.

Cuando se llaman los procedimientos XmNconvertCallback, el miembro location_data del miembro XmConvertCallbackStruct es NULL si el texto seleccionado se está transfiriendo. Si se está transfiriendo el texto completo, no el texto seleccionado, el valor de este miembro es el ID del widget TextField.

Como fuente de datos, TextField admite los siguientes destinos y conversiones asociadas de datos a estos destinos:

UTF8_STRING
El widget transfiere el texto seleccionado como tipo UTF8_STRING.
locale
Si el destino locale coincide con la configuración regional del widget, el widget transfiere el texto seleccionado en la codificación de la configuración regional.
COMPOUND_TEXT
El widget transfiere el texto seleccionado como tipo COMPOUND_TEXT.
STRING
El widget transfiere el texto seleccionado como tipo STRING.
TEXT
Si el texto seleccionado es completamente convertible a la codificación de la configuración regional, el widget transfiere el texto seleccionado en la codificación de la configuración regional. De lo contrario, el widget transfiere el texto seleccionado como tipo COMPOUND_TEXT.
DELETE
El widget elimina el texto seleccionado.
_MOTIF_CLIPBOARD_TARGETS
El widget transfiere, como tipo ATOM, una lista de los destinos a los que el widget puede convertir datos para colocarlos inmediatamente en el portapapeles. Estos incluyen los siguientes destinos:
•
UTF8_STRING
•
COMPOUND_TEXT
•
La codificación de la configuración regional, si el texto seleccionado es completamente convertible a la codificación de la configuración regional
•
STRING, si el texto seleccionado es completamente convertible a STRING
_MOTIF_EXPORT_TARGETS
El widget transfiere, como tipo ATOM, una lista de los destinos que se utilizarán como valor de XmNexportTargets del DragContext en una transferencia de arrastrar y soltar. Estos incluyen COMPOUND_TEXT, la codificación de la configuración regional, STRING, TEXT, UTF8_STRING, BACKGROUND y FOREGROUND.
_MOTIF_LOSE_SELECTION
El widget realiza las siguientes acciones:
•
Al perder la selección PRIMARY, anula el resaltado del texto seleccionado y llama a los procedimientos XmNlosePrimaryCallback.
•
Al perder la selección SECONDARY, elimina el resaltado de la selección secundaria.
•
Al perder la selección _MOTIF_DESTINATION, si el widget no tiene el foco, cambia el cursor para indicar que el widget ya no es el destino.

Como fuente de datos, TextField también admite los siguientes destinos estándar de Motif:

BACKGROUND
El widget transfiere XmNbackground como tipo PIXEL.
CLASS
El widget encuentra la primera ventana de nivel superior en la jerarquía de widgets que tiene una propiedad WM_CLASS y transfiere su contenido como texto en la configuración regional actual.
CLIENT_WINDOW
El widget encuentra la primera ventana de nivel superior en la jerarquía de widgets y transfiere su ventana como tipo WINDOW.
COLORMAP
El widget transfiere XmNcolormap como tipo COLORMAP.
FOREGROUND
El widget transfiere XmNforeground como tipo PIXEL.
NAME
El widget encuentra la primera ventana de nivel superior en la jerarquía de widgets que tiene una propiedad WM_NAME y transfiere su contenido como texto en la configuración regional actual.
TARGETS
El widget transfiere, como tipo ATOM, una lista de los destinos que admite. Estos incluyen los destinos estándar en esta lista. También incluyen COMPOUND_TEXT, la codificación de la configuración regional, STRING, TEXT y UTF8_STRING.
TIMESTAMP
El widget transfiere la marca de tiempo utilizada para adquirir la selección como tipo INTEGER.
_MOTIF_RENDER_TABLE
El widget transfiere XmNrenderTable si existe, o la tabla de renderizado de texto predeterminada, como tipo STRING.
_MOTIF_ENCODING_REGISTRY
El widget transfiere su registro de codificación como tipo STRING. El valor es una lista de elementos separados por NULL en forma de pares etiqueta-codificación. Este destino simboliza el destino de transferencia para el Registro de Codificación de Segmentos de Motif. Las aplicaciones y los widgets pueden usar este Registro para registrar formatos de codificación de texto para etiquetas de tabla de renderizado especificadas. Las aplicaciones acceden a este Registro llamando a XmRegisterSegmentEncoding y XmMapSegmentEncoding.

Como destino de datos, TextField elige un destino y solicita la conversión de la selección a ese destino. Si la codificación de la configuración regional está presente en la lista de destinos disponibles, TextField elige un destino solicitado de los destinos disponibles en el siguiente orden de preferencia:

1.
TEXT
1.
UTF8_STRING
2.
COMPOUND_TEXT
3.
La codificación de la configuración regional
4.
STRING

Si la codificación de la configuración regional no está presente en la lista de destinos disponibles, TextField elige un destino solicitado de los destinos disponibles en el siguiente orden de preferencia:

1.
UTF8_STRING
1.
COMPOUND_TEXT
2.
STRING

XmNactivateCallback
Especifica la lista de callbacks que se llama cuando el usuario invoca un evento que llama a la acción activate(). El tipo de la estructura cuya dirección se pasa a este callback es XmAnyCallbackStruct. La razón enviada por el callback es XmCR_ACTIVATE.
XmNblinkRate
Especifica la tasa de parpadeo del cursor de texto en milisegundos. El tiempo indicado en la tasa de parpadeo se refiere a la duración durante la cual el cursor está visible y la duración durante la cual el cursor está invisible (es decir, el tiempo que tardará en parpadear el cursor de inserción será dos veces la tasa de parpadeo). El cursor no parpadeará cuando la tasa de parpadeo se establezca en 0 (cero). El valor no debe ser negativo.
XmNcolumns
Especifica el ancho inicial de la ventana de texto como un número entero de caracteres. El ancho es igual al número de caracteres especificado por este recurso multiplicado por el ancho derivado de la fuente especificada. Si está disponible el valor de espacio em, se utiliza. Si no, se utiliza el ancho del dígito "0". Si tampoco está disponible, se utiliza el ancho máximo. Para fuentes proporcionales, el número real de caracteres que caben en una línea dada puede ser mayor que el valor especificado.
XmNcursorPosition
Indica la posición en el texto donde se ubicará el cursor de inserción actual. La posición se determina por el número de caracteres desde el principio del texto.
XmNcursorPositionVisible
Si el widget de texto tiene un XmPrintShell como uno de sus ancestros (es decir, el widget se creó en una conexión de servidor de impresión), el valor predeterminado es False; de lo contrario, es True.
XmNdestinationCallback
Especifica una lista de callbacks que se llaman cuando el widget es el destino de una operación de transferencia. El tipo de la estructura cuya dirección se pasa a estos callbacks es XmDestinationCallbackStruct. La razón es XmCR_OK.
XmNeditable
Cuando se establece en True, indica que el usuario puede editar la cadena de texto. Un valor falso prohibirá al usuario editar el texto.
Cuando se utiliza XmNeditable en un widget, este establece el sitio de arrastre a XmDROP_SITE_ACTIVE.
XmNfocusCallback
Especifica la lista de callbacks que se llaman cuando TextField acepta el foco de entrada. El tipo de la estructura cuya dirección se pasa a este callback es XmAnyCallbackStruct. La razón enviada por el callback es XmCR_FOCUS.
XmNfontList
Especifica la lista de fuentes que se utilizará para TextField. La lista de fuentes es una estructura obsoleta y se conserva solo por compatibilidad con versiones anteriores de Motif. Utilice la tabla de renderizado (XmNrenderTable) en lugar de las listas de fuentes siempre que sea posible. Si se especifican ambos, la tabla de renderizado tendrá prioridad. Si este valor es NULL en la inicialización, se busca en la jerarquía principal del widget un ancestro que contenga el rasgo XmQTspecifyRenderTable. Si se encuentra dicho ancestro, la lista de fuentes se inicializa al valor XmTEXT_RENDER_TABLE del widget ancestro. Si no se encuentra ningún ancestro, el valor predeterminado depende de la implementación.
TextField busca en la lista de fuentes la primera ocurrencia de un conjunto de fuentes que tenga una etiqueta XmFONTLIST_DEFAULT_TAG. Si no se encuentra un elemento predeterminado, se utiliza el primer conjunto de fuentes de la lista de fuentes. Si la lista no contiene ningún conjunto de fuentes, se utilizará la primera fuente de la lista de fuentes. Consulte XmFontList(3) para obtener más información sobre la estructura de la lista de fuentes.
XmNgainPrimaryCallback
Especifica la lista de callbacks que se llaman cuando el usuario invoca un evento que hace que el widget de texto obtenga la propiedad de la selección primaria. La razón del callback para este callback es XmCR_GAIN_PRIMARY.
XmNlosePrimaryCallback
Especifica la lista de callbacks que se llaman cuando el usuario invoca un evento que hace que el widget de texto pierda la propiedad de la selección primaria. La razón del callback para este callback es XmCR_LOSE_PRIMARY.
XmNlosingFocusCallback
Especifica la lista de callbacks que se llaman antes de que el widget TextField pierda el foco de entrada. El tipo de la estructura cuya dirección se pasa a este callback es XmTextVerifyCallbackStruct. La razón enviada por el callback es XmCR_LOSING_FOCUS.
XmNmarginHeight
Especifica la distancia entre el borde superior de la ventana del widget y el texto, y el borde inferior de la ventana del widget y el texto.
XmNmarginWidth
Especifica la distancia entre el borde izquierdo de la ventana del widget y el texto, y el borde derecho de la ventana del widget y el texto.
XmNmaxLength
Especifica la longitud máxima de la cadena de texto que se puede introducir en el texto desde el teclado. Este valor debe ser no negativo. Las cadenas que se introducen utilizando el recurso XmNvalue o la función XmTextFieldSetString ignoran este recurso.
XmNmodifyVerifyCallback
Especifica la lista de callbacks que se llama antes de que se elimine o inserte texto en TextField. El tipo de la estructura cuya dirección se pasa a este callback es XmTextVerifyCallbackStruct. La razón enviada por el callback es XmCR_MODIFYING_TEXT_VALUE. Cuando varios widgets TextField comparten la misma fuente, solo el widget que inicia el cambio de fuente generará el XmNmodifyVerifyCallback.
Si tanto XmNmodifyVerifyCallback como XmNmodifyVerifyCallbackWcs son listas de callbacks registradas, el/los procedimiento(s) en la lista XmNmodifyVerifyCallback siempre se ejecutan primero; y los datos resultantes, que pueden haber sido modificados, se pasan a las rutinas de callback de XmNmodifyVerifyCallbackWcs.

RESOURCES

XmNmodifyVerifyCallbackWcs
Especifica la lista de callbacks que se llaman antes de que se elimine o inserte texto en Text. El tipo de la estructura cuya dirección se pasa a este callback es XmTextVerifyCallbackStructWcs. La razón enviada por el callback es XmCR_MODIFYING_TEXT_VALUE. Cuando varios widgets TextField comparten la misma fuente, solo el widget que inicia el cambio de fuente generará XmNmodifyVerifyCallbackWcs.
Si tanto XmNmodifyVerifyCallback como XmNmodifyVerifyCallbackWcs son listas de callbacks registradas, el procedimiento (o procedimientos) en la lista XmNmodifyVerifyCallback se ejecuta siempre primero; y los datos resultantes, que pueden haber sido modificados, se pasan a las rutinas de callback XmNmodifyVerifyCallbackWcs.
XmNmotionVerifyCallback
Especifica la lista de callbacks que se llama antes de que el cursor de inserción se mueva a una nueva posición. El tipo de la estructura cuya dirección se pasa a este callback es XmTextVerifyCallbackStruct. La razón enviada por el callback es XmCR_MOVING_INSERT_CURSOR. Es posible que se generen varios XmNmotionVerifyCallback a partir de una sola acción.
XmNpendingDelete
Indica que el modo de eliminación pendiente está activado cuando el valor Booleano es True. La eliminación pendiente se define como la eliminación del texto seleccionado cuando se realiza una inserción.
XmNrenderTable
Especifica la tabla de renderizado que se utilizará para derivar un conjunto de fuentes o una fuente para mostrar texto. Si se especifican tanto una tabla de renderizado como una lista de fuentes, la tabla de renderizado tendrá prioridad. Si el valor de XmNrenderTable es NULL en la inicialización, se busca en la jerarquía padre del widget un ancestro que contenga el rasgo XmQTspecifyRenderTable. Si se encuentra dicho ancestro, la lista de fuentes se inicializa con el valor XmTEXT_RENDER_TABLE del widget ancestro. Si no se encuentra ningún ancestro de este tipo, el valor predeterminado depende de la implementación.
TextField busca en la tabla de renderizado la primera ocurrencia de una representación que tenga la etiqueta _MOTIF_DEFAULT_LOCALE. Si no se encuentra un elemento predeterminado, se utiliza la primera representación de la tabla. Consulte XmRenderTable(3) para obtener más información sobre la estructura de la tabla de renderizado.
XmNresizeWidth
Indica que el widget TextField intentará ajustar su ancho para acomodar todo el texto contenido en el widget cuando el valor Booleano sea True.
XmNselectionArray
Define las acciones para clics de ratón múltiples. Cada clic de ratón realizado dentro de un cierto tiempo después del clic anterior incrementará el índice en esta matriz y realizará la acción definida para ese índice. (Este tiempo de "múltiples clics" es especificado por el entorno operativo y varía entre diferentes sistemas. En general, suele establecerse en una fracción de segundo.) Las acciones posibles son
XmSELECT_POSITION
Restablece la posición del cursor de inserción
XmSELECT_WORD
Selecciona una palabra
XmSELECT_LINE
Selecciona una línea de texto
XmNselectionArrayCount
Especifica el número de acciones definidas en el recurso XmNselectionArray. El valor no debe ser negativo.
XmNselectThreshold
Especifica el número de píxeles de movimiento requeridos para seleccionar el siguiente carácter cuando la selección se realiza utilizando el modo de selección de arrastrar y soltar. El valor no debe ser negativo. Este recurso también especifica si se debe iniciar un arrastre y cuántos píxeles para iniciar un arrastre cuando Btn2Down y Btn1Down están integrados.
XmNvalue
Especifica el valor de cadena del widget TextField como un valor de datos char*. Mueve el cursor a la posición 0 a menos que se haya proporcionado explícitamente un valor de XmNcursorPosition en la lista de argumentos. Si XmNvalue y XmNvalueWcs están ambos definidos, el valor de XmNvalueWcs anula al de XmNvalue. XtGetValues devuelve una copia del valor del búfer interno y XtSetValues copia los valores de cadena en el búfer interno.
XmNvalueChangedCallback
Especifica la lista de callbacks que se llama después de que se elimina o inserta texto en TextField. El tipo de la estructura cuya dirección se pasa a este callback es XmAnyCallbackStruct. La razón enviada por el callback es XmCR_VALUE_CHANGED. El XmNvalueChangedCallback solo debe ocurrir en pares con un XmNmodifyVerifyCallback, asumiendo que el indicador doit en la estructura de callback de XmNmodifyVerifyCallback no está establecido en False.
XmNvalueWcs
Especifica el valor de cadena del widget TextField como un valor de datos wchar_t*. Mueve el cursor a la posición 0 a menos que se haya proporcionado explícitamente un valor de XmNcursorPosition en la lista de argumentos.
Este recurso no se puede especificar en un archivo de recursos.
Si XmNvalue y XmNvalueWcs están ambos definidos, el valor de XmNvalueWcs anula al de XmNvalue. XtGetValues devuelve una copia del valor del búfer interno codificado como una cadena de caracteres anchos. XtSetValues copia el valor de la cadena de caracteres anchos en el búfer interno.
XmNverifyBell
Especifica si sonará una campana cuando una acción se revierta durante un callback de verificación. El valor predeterminado depende del valor del recurso XmNaudibleWarning del ancestro VendorShell.

Información de Callback

Se pasa un puntero a la siguiente estructura a cada callback:

typedef struct
{
        int reason;
        XEvent * event;
} XmAnyCallbackStruct;
reason
Indica por qué se invocó el callback.
event
Punta a XEvent que activó el callback.

El widget TextField define una nueva estructura de callback para usar con callbacks de verificación. Tenga en cuenta que no todos los campos son relevantes para cada razón de callback. La aplicación debe primero mirar el campo reason y usar solo los miembros de la estructura que sean válidos para la razón particular. Los valores startPos, endPos y text en la estructura de callback XmTextVerifyCallbackStruct pueden ser modificados al recibir el callback, y estos cambios se reflejarán como el cambio hecho a la fuente del widget TextField. (Por ejemplo, todas las pulsaciones de teclas pueden convertirse en espacios o caracteres NUL cuando se ingresa una contraseña en un widget TextField.) El programador de la aplicación no debe sobrescribir el campo text, sino adjuntar datos a ese puntero.

Se pasa un puntero a la siguiente estructura a los callbacks para XmNlosingFocusCallback, XmNmodifyVerifyCallback y XmNmotionVerifyCallback.

typedef struct
{
        int reason;
        XEvent *event;
        Boolean doit;
        XmTextPosition currInsert, newInsert;
        XmTextPosition startPos, endPos;
        XmTextBlock text;
} XmTextVerifyCallbackStruct, *XmTextVerifyPtr;

Indica por qué se invocó el callback.
event
Punta a XEvent que activó el callback. Puede ser NULL. Por ejemplo, los cambios hechos al widget Text programáticamente no tienen un evento que pueda pasarse al callback asociado.
doit
Indica si la acción que invocó el callback se realizará. Establecer doit en False niega la acción. Tenga en cuenta que no todas las acciones pueden ser negadas. Por ejemplo, los callbacks de XmCR_LOSING_FOCUS pueden estar fuera del control del widget si son producidos por clics del ratón.
currInsert
Indica la posición actual del cursor de inserción.
newInsert
Indica la posición en la que el usuario intenta posicionar el cursor de inserción.
startPos
Indica la posición inicial del texto a modificar. Si el callback no es un callback de verificación de modificación, este valor es el mismo que currInsert.
endPos
Indica la posición final del texto a modificar. Si no se reemplaza ni se elimina texto, el valor es el mismo que startPos. Si el callback no es un callback de verificación de modificación, este valor es el mismo que currInsert.
text

Callback Reasons for Verification and Data Transfer Protocols

The following callback structure is passed to the XmNverificationCallback procedures:

typedef struct
{
        int reason;
        XEvent *event;
        Boolean doit;
        int currInsert;
        int newInsert;
        int startPos;
        int endPos;
        String text;
} XmVerificationCallbackStruct;
reason
Indicates why the callback was invoked.
event
Points to the XEvent that triggered the callback. It can be NULL.
doit
A Boolean that the callback procedure can set to False to prevent the modification or the move. It is set to True by default.
currInsert
The current insertion position.
newInsert
The new insertion position.
startPos
The starting position of the text that is being modified or deleted.
endPos
The ending position of the text that is being modified or deleted.
text
Points to the text to be inserted. This field is only valid for XmCR_MODIFYING_TEXT_VALUE.

The following table describes the reasons for which the individual verification callback structure fields are valid. Note that the event field will never be valid for XmCR_MOVING_INSERT_CURSOR.

Reason Valid Fields
XmCR_LOSING_FOCUS reason, event, doit
XmCR_MODIFYING_TEXT_VALUE reason, event, doit, currInsert, newInsert, startPos, endPos, text
XmCR_MOVING_INSERT_CURSOR reason, doit, currInsert, newInsert

A pointer to the following callback structure is passed to the XmNdestinationCallback procedures:

typedef struct
{
        int reason;
        XEvent *event;
        Atom selection;
        XtEnum operation;
        int flags;
        XtPointer transfer_id;
        XtPointer destination_data;
        XtPointer location_data;
        Time time;
} XmDestinationCallbackStruct;
reason
Indicates why the callback was invoked.
event
Points to the XEvent that triggered the callback. It can be NULL.
selection
Indicates the selection for which data transfer is being requested. Possible values are CLIPBOARD, PRIMARY, SECONDARY, and _MOTIF_DROP.
operation
Indicates the type of transfer operation requested.
•
When the selection is PRIMARY or SECONDARY, possible values are XmMOVE, XmCOPY, and XmLINK.
•
When the selection is CLIPBOARD, possible values are XmCOPY and XmLINK.
•
When the selection is _MOTIF_DROP, possible values are XmMOVE, XmCOPY, XmLINK, and XmOTHER. A value of XmOTHER means that the callback procedure must get further information from the XmDropProcCallbackStruct in the destination_data member.
flags
Indicates whether or not the destination widget is also the source of the data to be transferred. Following are the possible values:
XmCONVERTING_NONE
The destination widget is not the source of the data to be transferred.
XmCONVERTING_SAME
The destination widget is the source of the data to be transferred.
transfer_id
Serves as a unique ID to identify the transfer transaction.
destination_data
Contains information about the destination. When the selection is _MOTIF_DROP, the callback procedures are called by the drop site's XmNdropProc, and destination_data is a pointer to the XmDropProcCallbackStruct passed to the XmNdropProc procedure. When the selection is SECONDARY, destination_data is an Atom representing a target recommmended by the selection owner for use in converting the selection. Otherwise, destination_data is NULL.
location_data
Contains information about the location where data is to be transferred. The value is always NULL when the selection is CLIPBOARD. If the value is NULL, the data is to be inserted at the widget's cursor position. Otherwise, the value is a pointer to an XPoint structure containing the x and y coordinates at the location where the data is to be transferred. Once XmTransferDone procedures start to be called, location_data will no longer be stable.
time
Indicates the time when the transfer operation began.

Rutinas de Acción

Las rutinas de acción de XmTextField son:

activate():
Llama a las callbacks de XmNactivateCallback. Si el padre es un gestor, pasa el evento al padre.
backward-character(extend):
Mueve el cursor de inserción un carácter hacia la izquierda. Esta acción puede tener un comportamiento diferente en un entorno de idioma de derecha a izquierda.
Si se llama con el argumento extend, mueve el cursor de inserción como en el caso de no tener argumento y extiende la selección actual.
La acción backward-character() produce llamadas a los procedimientos de XmNmotionVerifyCallback con el valor de razón XmCR_MOVING_INSERT_CURSOR. Si se llama con el argumento extend, la acción backward-character() puede producir llamadas a los procedimientos de XmNgainPrimaryCallback. Consulte la descripción de la callback para obtener más información.
backward-word(extend):
Si esta acción se llama sin argumento, mueve el cursor de inserción al primer carácter que no sea espacio en blanco después del primer carácter de espacio en blanco a la izquierda o después del principio de la línea. Si el cursor de inserción ya está al principio de una palabra, mueve el cursor de inserción al principio de la palabra anterior. Esta acción puede tener un comportamiento diferente en una configuración regional que no sea la configuración regional C.
Si se llama con el argumento extend, mueve el cursor de inserción como en el caso de no tener argumento y extiende la selección actual.
La acción backward-word() produce llamadas a los procedimientos de XmNmotionVerifyCallback con el valor de razón XmCR_MOVING_INSERT_CURSOR. Si se llama con el argumento extend, la acción backward-word() puede producir llamadas a los procedimientos de XmNgainPrimaryCallback. Consulte la descripción de la callback para obtener más información.
beginning-of-line(extend):
Si esta acción se llama sin argumento, mueve el cursor de inserción al principio de la línea.
Si se llama con el argumento extend, mueve el cursor de inserción como en el caso de no tener argumento y extiende la selección actual.
La acción beginning-of-line() produce llamadas a las XmNmotionVerifyCallback con el valor de razón XmCR_MOVING_INSERT_CURSOR. Borra la selección actual reemplazando cada carácter excepto <Return> con un carácter de <espacio>.

Si este widget posee la selección primaria, esta acción copia la selección al portapapeles. Esta acción llama a los procedimientos de XmNconvertCallback, posiblemente varias veces, para la selección CLIPBOARD.

link-primary():
Coloca un enlace a la selección primaria justo antes del cursor de inserción. Esta acción llama a los procedimientos XmNdestinationCallback para la selección PRIMARY y la operación XmLINK. El widget TextField en sí no realiza ninguna transferencia; los procedimientos XmNdestinationCallback son responsables de insertar el enlace a la selección primaria y de tomar cualquier acción relacionada.
link-to():
Si existe una selección secundaria, esta acción coloca un enlace a la selección secundaria en la posición de inserción del componente de destino. Esta acción llama a los procedimientos XmNdestinationCallback del destino para la selección SECONDARY y la operación XmLINK.
Si no existe una selección secundaria, esta acción coloca un enlace a la selección primaria en la posición del puntero. Esta acción llama a los procedimientos XmNdestinationCallback para la selección PRIMARY y la operación XmLINK.
El widget TextField en sí no realiza ninguna transferencia; los procedimientos XmNdestinationCallback son responsables de insertar el enlace a la selección primaria o secundaria y de tomar cualquier acción relacionada.
move-destination():
Mueve el cursor de inserción a la posición del puntero sin cambiar ninguna selección actual existente. Si hay una selección actual, establece el widget como el widget de destino. Esto también mueve el foco del widget para que coincida con el cursor de inserción.
La acción move-destination() produce llamadas a los procedimientos XmNmotionVerifyCallback con el valor de razón XmCR_MOVING_INSERT_CURSOR.
move-to():
Si existe una selección secundaria, esta acción mueve la selección secundaria a la posición de inserción del componente de destino. Si la selección secundaria está en el widget de destino, y la selección secundaria y la selección primaria se superponen, el resultado no está definido. Esta acción llama a los procedimientos XmNdestinationCallback del destino para la selección SECONDARY y la operación XmCOPY. Los procedimientos XmNdestinationCallback del destino o el componente de destino invocan los procedimientos XmNconvertCallback del propietario de la selección, posiblemente varias veces, para la selección SECONDARY. Si la transferencia es exitosa, esta acción luego llama a los procedimientos XmNconvertCallback del propietario de la selección para la selección SECONDARY y el objetivo DELETE.
Si no existe una selección secundaria, esta acción mueve la selección primaria a la posición del puntero. Esta acción llama a los procedimientos XmNdestinationCallback para la selección PRIMARY y la operación XmMOVE. Llama a los procedimientos XmNconvertCallback del propietario de la selección, posiblemente varias veces, para la selección PRIMARY. Si la transferencia es exitosa, esta acción luego llama a los procedimientos XmNconvertCallback del propietario de la selección para la selección PRIMARY y el objetivo DELETE.

Comportamiento Adicional

Este widget tiene el siguiente comportamiento adicional:

<FocusIn>:
Dibuja el cursor de inserción como sólido y comienza a parpadear el cursor.
<FocusOut>:
Muestra el cursor de inserción como una viga en I punteada a menos que sea el widget de destino.
