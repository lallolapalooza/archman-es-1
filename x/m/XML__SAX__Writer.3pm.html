XML::SAX::Writer(3) Documentación de Perl aportada por el usuario XML::SAX::Writer(3)

NOMBRE

XML::SAX::Writer - Escritor XML SAX2

VERSIÓN

versión 0.57

SINOPSIS

use XML::SAX::Writer;
use XML::SAX::SomeDriver;
my $w = XML::SAX::Writer->new;
my $d = XML::SAX::SomeDriver->new(Handler => $w);
$d->parse('algunas opciones...');

DESCRIPCIÓN

¿Por qué otro escritor XML ?

Se necesitaba un nuevo escritor XML para igualar el esfuerzo SAX2 porque, como es natural, ningún escritor existente entendía SAX2. Mi primera intención había sido empezar a parchear XML::Handler::YAWriter, ya que previamente había sido mi escritor favorito en el mundo SAX1.

Sin embargo, cuanto más lo parcheaba, más me daba cuenta de que lo que pensaba que iba a ser un parche simple (principalmente añadir unos pocos manejadores de eventos y cambiar la sintaxis de atributos) se estaba convirtiendo en una reescritura debido a varias ideas que había estado recopilando por el camino. Además, no pude encontrar una manera elegante de hacerlo funcionar con SAX2 sin romper la compatibilidad con SAX1 que la gente probablemente todavía está usando. Por supuesto, hay maneras de hacer eso, pero la mayoría requieren interacción del usuario, que es algo que quería evitar.

Así que al final, hubo un nuevo escritor. Creo que de hecho es mejor así, ya que ayuda a mantener SAX1 y SAX2 separados.

MÉTODOS

  • new(%hash)

    Este es el constructor para este objeto. Toma una serie de parámetros, todos opcionales.

  • Output

    Este parámetro puede ser una de varias cosas. Si es un escalar simple, se interpreta como un nombre de archivo que se abrirá para escribir. Si es una referencia a un escalar, la salida se añadirá a este escalar. Si es una referencia a un array, la salida se añadirá a este array a medida que se genera. Si es un manejador de archivos, la salida se enviará a este manejador de archivos.

    Finalmente, es posible pasar un objeto para este parámetro, en cuyo caso se asume que es un objeto que implementa la interfaz del consumidor descrita más adelante en la documentación.

    Si este parámetro no se proporciona, la salida se envía a STDOUT.

    Tenga en cuenta que no hay forma de establecer una capa de codificación en los manejadores de archivos creados por este módulo; si esto es necesario, el código que llama debe primero abrir un manejador de archivos con la codificación apropiada establecida, y pasar ese manejador de archivos a este módulo.

  • Escape

    Esto debería ser una referencia a un hash donde las claves son secuencias de caracteres que deben ser escapadas y los valores son la forma escapada de la secuencia. Por defecto, este módulo escapará el ampersand (&), menor que (<), mayor que (>), comillas dobles (") y apóstrofe ('). Tenga en cuenta que algunos navegadores no soportan el escape &apos; utilizado para los apóstrofes, por lo que debe tener cuidado al generar XHTML.

    Si solo desea añadir entradas al hash Escape, puede copiar primero el contenido de %XML::SAX::Writer::DEFAULT_ESCAPE.

  • CommentEscape

    El contenido de los comentarios a menudo necesita ser escapado de manera diferente al otro contenido. Esta opción funciona exactamente como la anterior, excepto que por defecto solo escapa el doble guion (--) y que el contenido se puede copiar de %XML::SAX::Writer::COMMENT_ESCAPE.

  • EncodeFrom

    La codificación del conjunto de caracteres en la que se proporcionarán los datos entrantes. Por defecto es UTF-8, que también funciona para US-ASCII.

    Establezca esto en "undef" si no desea decodificar sus datos.

  • EncodeTo

    La codificación del conjunto de caracteres en la que se debe codificar la salida. De nuevo, por defecto es UTF-8.

    Establezca esto en "undef" si no desea codificar sus datos.

  • QuoteCharacter

    Establezca el carácter utilizado para citar atributos. Por defecto son comillas simples (') para compatibilidad hacia atrás.

LA INTERFAZ DEL CONSUMIDOR

XML::SAX::Writer puede recibir objetos consumidores enchufables que serán los encargados de escribir lo que este módulo formatea. Establecer un Consumidor se hace estableciendo la opción Output al objeto de su elección en lugar de a un array, escalar o manejador de archivos, como se hace más comúnmente (internamente, estos de hecho se mapean a clases Consumer y simplemente están disponibles como opciones para su conveniencia).

Si no entiende esto, no se preocupe. No lo necesita la mayor parte del tiempo.

Ese objeto puede ser de cualquier clase, pero debe tener dos métodos en su API. También se recomienda encarecidamente que herede de XML::SAX::Writer::ConsumerInterface para que no se rompa si esa interfaz evoluciona con el tiempo. Hay ejemplos al final del código de XML::SAX::Writer.

Los dos métodos que necesita implementar son:

  • output STRING

    (Requerido)

    Esto se llama cada vez que el Escritor quiere generar una cadena formateada en XML. La conversión de codificación, el escape de caracteres y el formato ya se han realizado. Depende del consumidor hacer lo que quiera con la cadena.

  • finalize()

    (Opcional)

    Esto se llama una vez que el documento se ha generado en su totalidad, durante el evento end_document. end_document de hecho devolverá lo que sea que devuelva finalize(), y eso a su vez debería ser devuelto por parse() para el analizador que se invocó. Podría ser útil si necesita proporcionar algún tipo de retroalimentación.

Aquí hay un ejemplo de un consumidor personalizado. Tenga en cuenta los signos de dólar extra ("$") delante de $self; la clase base está optimizada para el caso abrumadoramente común en el que solo se requiere un miembro de datos y $self es una referencia a ese miembro de datos.

package MyConsumer;
@ISA = qw( XML::SAX::Writer::ConsumerInterface );
use strict;
sub new {
    my $self = shift->SUPER::new( my $output );
    $$self = '';      # Nota el '$' extra
    return $self;
}
sub output {
    my $self = shift;
    $$self .= uc shift;
}
sub get_output {
    my $self = shift;
    return $$self;
}

Y aquí hay una forma de usarlo:

my $c = MyConsumer->new;
my $w = XML::SAX::Writer->new( Output => $c );
## ... enviar eventos a $w ...
print $c->get_output;

Si necesita almacenar más de un miembro de datos, pase una referencia a un array o hash:

my $self = shift->SUPER::new( {} );

y acceda a él como:

sub output {
    my $self = shift;
    $$self->{Output} .= uc shift;
}

LA INTERFAZ DEL CODIFICADOR

Se pueden enchufar codificadores para permitirle usar su objeto codificador favorito. Actualmente hay dos codificadores: Encode y NullEncoder. Necesitan implementar dos métodos, y pueden heredar de XML::SAX::Writer::NullConverter si así lo desean.

new DESDE_CODIFICACIÓN, A_CODIFICACIÓN
Crea un nuevo Codificador. Los argumentos son las codificaciones elegidas.
convert CADENA
Convierte esa cadena y la devuelve.

Tenga en cuenta que el valor de retorno del método convert no se comprueba. La salida puede truncarse si un carácter no se pudo convertir correctamente. Para evitar problemas, el codificador debe encargarse de los errores de codificación, por ejemplo, generando una excepción.

SALIDA PERSONALIZADA

Este módulo generalmente se usa para escribir XML —lo que hace la mayor parte del tiempo— pero al igual que el resto de SAX, se puede usar como un marco genérico para generar datos, lo opuesto a un analizador SAX no XML.

Por supuesto, hay un límite en lo que se puede abstraer, por lo que dependiendo de su formato, esto puede ser útil o no. Si lo es, necesitará conocer la siguiente API (y probablemente echar un vistazo dentro de "XML::SAX::Writer::XML", el Escritor por defecto).

init PARSER, OPCIONES
Este método es llamado por el analizador y se le pasan dos argumentos: el propio analizador y una referencia a las opciones que se le pasaron al constructor del escritor. El escritor puede entonces establecer cualquier opción que necesite del analizador (por ejemplo, para determinar si se deben generar espacios en blanco).

METHODS

init
Se llama antes de que comience la escritura, es una oportunidad para que la subclase realice alguna inicialización si la necesita.
setConverter
Se utiliza para establecer el convertidor adecuado para las codificaciones de caracteres. La implementación predeterminada debería ser suficiente, pero puede anularla. Debe establecer "$self->{Encoder}" en un objeto Encoder. Las subclases *deben* llamarlo.
setConsumer
Igual que arriba, excepto que es para el objeto Consumer y que debe establecer "$self->{Consumer}".
setEscaperRegex
Inicializará la expresión regular de escape "$self->{EscaperRegex}" según lo que se necesite.
escape STRING
Toma una cadena y la escapa correctamente.
setCommentEscaperRegex y escapeComment STRING
Estas funcionan exactamente igual que las dos anteriores, excepto que están destinadas a operar sobre el contenido de los comentarios, que a menudo tienen reglas de escape diferentes a las que se aplican al contenido regular.
