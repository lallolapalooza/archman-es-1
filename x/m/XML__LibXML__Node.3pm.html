DESCRIPCIÓN

XML::LibXML::Node define funciones comunes a todos los Tipos de Nodo. Nunca se debe crear un XML::LibXML::Node de forma independiente, sino como una instancia de una clase de nivel superior como XML::LibXML::Element o XML::LibXML::Text. La clase en sí solo debe proporcionar funcionalidad común. En XML::LibXML, cada nodo forma parte de un documento o de un fragmento de documento. Debido a esto, no existe un nodo sin padre. Esto puede causar confusión con nodos "no enlazados".

MÉTODOS

Muchas de las funciones listadas aquí están ampliamente documentadas en la especificación DOM Nivel 3 (http://www.w3.org/TR/DOM-Level-3-Core/). Por favor, consulte la especificación para obtener documentación detallada.

nodeName
$nombre = $nodo->nodeName;

Devuelve el nombre del nodo. Esta función es consciente de los espacios de nombres y devuelve el nombre completo del nodo actual ("prefijo:nombrelocal").

Desde la versión 1.62, esta función también devuelve los nombres DOM correctos para tipos de nodo con nombres constantes, a saber: #text, #cdata-section, #comment, #document, #document-fragment.

setNodeName
$nodo->setNodeName( $nuevoNombre );

En situaciones muy limitadas, es útil cambiar el nombre de un nodo. En la especificación DOM, esto debería lanzar un error. Esta función es consciente de los espacios de nombres.

isSameNode
$booleano = $nodo->isSameNode( $otro_nodo );

Devuelve VERDADERO (1) si los nodos dados se refieren a la misma estructura de nodo, de lo contrario devuelve FALSO (0).

isEqual
$booleano = $nodo->isEqual( $otro_nodo );

versión obsoleta de isSameNode().

NOTA: isEqual cambiará su comportamiento para seguir la especificación DOM

unique_key
$numero = $nodo->unique_key;

Esta función no está especificada para ningún nivel DOM. Devuelve una clave que está garantizada ser única para este nodo y que siempre será el mismo valor para este nodo. En otras palabras, dos objetos nodo devuelven la misma clave si y solo si isSameNode indica que son el mismo nodo.

El valor de clave devuelto es útil como clave en hashes.

nodeValue
$contenido = $nodo->nodeValue;

Si el nodo tiene algún contenido (como el almacenado en un "nodo de texto"), se puede solicitar a través de esta función.

NOTA: Los Nodos de Elemento no tienen contenido por definición. Para obtener el valor de texto de un Elemento, use textContent() en su lugar.

textContent
$contenido = $nodo->textContent;

esta función devuelve el contenido de todos los nodos de texto en los descendientes del nodo dado, según lo especificado en DOM.

nodeType
$tipo = $nodo->nodeType;

Devuelve un valor numérico que representa el tipo de nodo de este nodo. El módulo XML::LibXML exporta por defecto constantes para los tipos de nodo (ver la sección EXPORT en la página del manual de XML::LibXML).

unbindNode
$nodo->unbindNode();

Desenlaza el Nodo de sus hermanos y padre, pero no del Documento al que pertenece. Si el nodo no se inserta en el DOM después, se perderá después de que el programa termine. Desde una vista de bajo nivel, el nodo desenlazado se elimina del contexto en el que está y se inserta en un fragmento de documento (oculto).

removeChild
$nodenuevo = $nodo->removeChild( $nodenuevo );

Esto desenlazará el Nodo hijo de su padre $nodo. La función devuelve el nodo desenlazado. Si $nodenuevo no es un hijo del Nodo dado, la función fallará.

replaceChild
$nodoanterior = $nodo->replaceChild( $nodenuvo, $nodoanterior );

Reemplaza el $nodoanterior con el $nodenuvo. El $nodoanterior será desenlazado del Nodo. Esta función difiere de la especificación DOM L2 en el caso de que el nodo nuevo no sea parte del documento; el nodo será importado primero.

replaceNode
$nodo->replaceNode($nodenuvo);

Esta función es muy similar a replaceChild(), pero reemplaza el nodo en sí en lugar de un nodo hijo. Esto es útil si un nodo encontrado por cualquier función XPath debe ser reemplazado.

appendChild
$nodenuevo = $nodo->appendChild( $nodenuevo );

La función agregará el $nodenuevo al final de los hijos de $nodo. La función debería fallar si el nuevo nodo hijo ya es un hijo de $nodo. Esta función difiere de la especificación DOM L2 en el caso de que el nodo nuevo no sea parte del documento; el nodo será importado primero.

addChild
$nodenuevo = $nodo->addChild( $nodenuevo );

addChild
$node->addChild($newNode);

Esta función es bastante útil si se construyen documentos XML en memoria donde el orden y la propiedad ("ownerDocument") están asegurados.

addChild() utiliza la propia función xmlAddChild() de libxml2. Por lo tanto, debe usarse con especial cuidado: Si se agrega un nodo de texto a un nodo y el propio nodo o su último nodo hijo es también un nodo de texto, el nodo a agregar se fusionará con el ya disponible. El nodo actual se eliminará de la memoria después de esta acción. Como perl no es consciente de esta acción, la instancia de perl sigue estando disponible. XML::LibXML detectará la pérdida de un nodo y se negará a ejecutar cualquier función llamada sobre ese nodo.

my $t1 = $doc->createTextNode( "foo" );
 my $t2 = $doc->createTextNode( "bar" );
 $t1->addChild( $t2 );       # está BIEN
 my $val = $t2->nodeValue(); # fallará, el script morirá

Además, addChild() no verificará si el nodo agregado pertenece al mismo documento que el nodo al que se agregará. Esto podría generar documentos inconsistentes y, en casos peores, incluso violaciones de memoria, si uno no mantiene un registro de este problema.

Aunque esto suena como muchos problemas, addChild() es útil si un documento se construye a partir de un flujo, como ocurre a veces en los manejadores SAX o filtros.

Si no está seguro del origen de sus nodos, es mejor que se quede con appendChild(), ya que esta función es más fácil de usar en el sentido de ser más tolerante a errores.

addNewChild
$node = $parent->addNewChild( $nsURI, $name );

Similar a addChild(), esta función utiliza la funcionalidad de bajo nivel de libxml2 para proporcionar una interfaz más rápida para la construcción de DOM. addNewChild() utiliza xmlNewChild() para crear un nuevo nodo en un elemento padre dado.

addNewChild() tiene dos parámetros $nsURI y $name, donde $nsURI es una URI de espacio de nombres (opcional). $name es el nombre del elemento completamente calificado; addNewChild() determinará el prefijo correcto si es necesario.

La función devuelve el nodo recién creado.

Esta función es muy útil para la construcción de DOM, donde un nodo creado puede asociarse directamente con su padre. *NOTA*: esta función no forma parte de la especificación DOM y su uso limitará su código a XML::LibXML.

addSibling
$node->addSibling($newNode);

addSibling() permite agregar un nodo adicional al final de una lista de nodos, definida por el nodo dado.

cloneNode
$newnode =$node->cloneNode( $deep );

cloneNode crea una copia de $node. Cuando $deep se establece en 1 (verdadero), la función copiará todos los nodos hijos también. Si $deep es 0, solo se copiará el nodo actual. Tenga en cuenta que en el caso de elementos, los atributos se copian incluso si $deep es 0.

Tenga en cuenta que el comportamiento de esta función para $deep=0 ha cambiado en la versión 1.62 para ser consistente con la especificación DOM (en versiones anteriores, los atributos y la información del espacio de nombres no se copiaban para los elementos).

*NOTA*: cloneNode crea una copia del nodo seleccionado que incluye los *namespaces* definidos por el padre que están en uso por el nodo (o sus hijos) que se está clonando. Esto lo hace útil para extraer un fragmento de xml que pueda ser utilizado como un documento xml válido.

parentNode
$parentnode = $node->parentNode;

Simplemente devuelve el Nodo Padre del nodo actual.

nextSibling
$nextnode = $node->nextSibling();

Devuelve el siguiente hermano si existe.

nextNonBlankSibling
$nextnode = $node->nextNonBlankSibling();

Devuelve el siguiente hermano no vacío si existe (un nodo está vacío si es un nodo de Texto o CDATA que solo contiene espacios en blanco). Este método no está definido por DOM.

previousSibling
$prevnode = $node->previousSibling();

Análogamente a getNextSibling, la función devuelve el hermano anterior si existe.

previousNonBlankSibling
$prevnode = $node->previousNonBlankSibling();

Devuelve el hermano anterior no vacío si existe (un nodo está vacío si es un nodo de Texto o CDATA que solo contiene espacios en blanco). Este método no está definido por DOM.

hasChildNodes
$boolean = $node->hasChildNodes();

Si el nodo actual tiene nodos hijos, esta función devuelve VERDADERO (1), de lo contrario devuelve FALSO (0, no undef).

firstChild
$childnode = $node->firstChild;

Si un nodo tiene nodos hijos, esta función devolverá el primer nodo de la lista de hijos.

lastChild
$childnode = $node->lastChild;

Si el $node tiene nodos hijos, esta función devuelve el último nodo hijo.

ownerDocument
$documentnode = $node->ownerDocument;

A través de esta función siempre es posible acceder al documento al que está vinculado el nodo actual.

getOwner
$node = $node->getOwner;

Esta función devuelve el nodo con el que está asociado el nodo actual. En la mayoría de los casos, será un nodo de documento o un nodo de fragmento de documento.

setOwnerDocument
$node->setOwnerDocument( $doc );

Esta función vincula un nodo a otro DOM. Este método desvincula primero el nodo, si ya está vinculado a otro documento.

Esta función es la llamada opuesta a la función adoptNode() de XML::LibXML::Document. Debido a esto, tiene las mismas limitaciones con las Referencias de Entidad que adoptNode().

insertBefore
$node->insertBefore( $newNode, $refNode );

El método inserta $newNode antes de $refNode. Si $refNode es indefinido, $newNode se establecerá como el nuevo último hijo del nodo padre. Esta función difiere de la especificación L2 de DOM, en el caso de que el nuevo nodo no sea parte del documento, el nodo se importará primero, automáticamente.

$refNode debe pasarse a la función incluso si es indefinido:

$node->insertBefore( $newNode, undef ); # lo mismo que $node->appendChild( $newNode );
 $node->insertBefore( $newNode ); # incorrecto

Tenga en cuenta que el nodo de referencia debe ser un hijo directo del nodo en el que se llama a la función. Además, $newChild no puede ser un ancestro del nuevo nodo padre.

insertAfter
$node->insertAfter( $newNode, $refNode );

El método inserta $newNode después de $refNode. Si $refNode es indefinido, $newNode se establecerá como el nuevo último hijo del nodo padre.

Tenga en cuenta que $refNode debe pasarse explícitamente incluso si es indefinido.

findnodes
@nodes = $node->findnodes( $xpath_expression );

findnodes evalúa la expresión xpath (XPath 1.0) en el nodo actual y devuelve el conjunto de nodos resultante como un array. En contexto escalar, devuelve un objeto XML::LibXML::NodeList.

La expresión xpath puede pasarse como una cadena o como un objeto XML::LibXML::XPathExpression.

*NOTA SOBRE NAMESPACES Y XPATH*:

Un error común sobre XPath es asumir que las pruebas de nodos que consisten en un nombre de elemento sin prefijo coinciden con elementos en el espacio de nombres predeterminado. Esta suposición es incorrecta: según la especificación XPath, tales pruebas de nodos solo pueden coincidir con elementos que no están en ningún espacio de nombres (es decir, nulo).

Por lo tanto, por ejemplo, uno no puede coincidir con el elemento raíz de un documento XHTML con "$node->find('/html')" ya que '/html' solo coincidiría si el elemento raíz "<html>" no tuviera espacio de nombres, pero todos los elementos XHTML pertenecen al espacio de nombres http://www.w3.org/1999/xhtml. (Tenga en cuenta que las declaraciones de espacio de nombres "xmlns="..."" también pueden especificarse en una DTD, lo que empeora la situación, ya que el documento XML parece no tener un espacio de nombres predeterminado).

Existen varias formas posibles de tratar los espacios de nombres en XPath:

  • La forma recomendada es utilizar el módulo XML::LibXML::XPathContext para definir un contexto explícito para la evaluación de XPath, en el que se puede definir una asignación de prefijo a espacio de nombres independiente del documento. Por ejemplo: 
    my $xpc = XML::LibXML::XPathContext->new;
$xpc->registerNs('x', 'http://www.w3.org/1999/xhtml');
$xpc->find('/x:html',$node);
  • Otra posibilidad es utilizar prefijos declarados en el documento consultado (si se conocen). Si el documento declara un prefijo para el espacio de nombres en cuestión (y el nodo de contexto está en el ámbito de la declaración), "XML::LibXML" le permite usar el prefijo en la expresión XPath, por ejemplo: 
    $node->find('/x:html');
Ver también XML::LibXML::XPathContext->findnodes.

find
$result = $node->find( $xpath );

find evalúa la expresión XPath 1.0 usando el nodo actual como contexto de la expresión, y devuelve el resultado dependiendo del tipo de resultado que tuviera la expresión XPath. Por ejemplo, la expresión XPath "1 * 3 + 52" resulta en la devolución de un objeto XML::LibXML::Number. Otras expresiones podrían devolver un objeto XML::LibXML::Boolean o un objeto XML::LibXML::Literal (una cadena). Cada uno de esos objetos utiliza la característica de sobrecarga de Perl para "hacer lo correcto" en diferentes contextos.

La expresión xpath puede pasarse como una cadena o como un objeto XML::LibXML::XPathExpression.

Ver también XML::LibXML::XPathContext->find.

findvalue
print $node->findvalue( $xpath );

findvalue es exactamente equivalente a:

$node->find( $xpath )->to_literal;

Es decir, devuelve el valor literal de los resultados. Esto le permite asegurarse de que obtiene una cadena de su búsqueda, permitiendo ciertos atajos. Podría usarse como el equivalente de <xsl:value-of select="some_xpath"/> de XSLT.

Ver también XML::LibXML::XPathContext->findvalue.

La expresión xpath puede pasarse como una cadena o como un objeto XML::LibXML::XPathExpression.

exists
$bool = $node->exists( $xpath_expression );

Este método se comporta como findnodes, excepto que solo devuelve un valor booleano (1 si la expresión coincide con un nodo, 0 en caso contrario) y puede ser más rápido que findnodes, porque la evaluación XPath puede detenerse temprano en la primera coincidencia (esto es cierto para libxml2 >= 2.6.27).

Para expresiones XPath que no devuelven un conjunto de nodos, el método devuelve verdadero si el valor devuelto es un número distinto de cero o una cadena no vacía.

childNodes
@childnodes = $node->childNodes();

childNodes implementa una interfaz más intuitiva para los nodos hijos del nodo actual. Le permite pasar todos los hijos directamente a un "map" o "grep". Si esta función se llama en contexto escalar, se devolverá un objeto XML::LibXML::NodeList.

nonBlankChildNodes
@childnodes = $node->nonBlankChildNodes();

Esto es como childNodes, pero solo devuelve nodos no vacíos (donde un nodo está vacío si es un nodo de Texto o CDATA que consiste solo en espacios en blanco). Este método no está definido por DOM.

toString
$xmlstring = $node->toString($format,$docencoding);

Este método es similar al método "toString" de un XML::LibXML::Document pero para un solo nodo. Devuelve una cadena que consiste en la serialización XML del nodo dado y todos sus descendientes. A diferencia de "XML::LibXML::Document::toString", en este caso la cadena resultante es por defecto una cadena de caracteres (codificada en UTF-8 con el indicador UTF8 activado). Un indicador opcional $format controla la indentación, como en "XML::LibXML::Document::toString". Si el segundo indicador opcional $docencoding es verdadero, el resultado será una cadena de bytes en la codificación del documento (ver "XML::LibXML::Document::actualEncoding").

toStringC14N
$c14nstring = $node->toStringC14N();
$c14nstring = $node->toStringC14N($with_comments, $xpath_expression , $xpath_context);

La función es similar a toString(). En lugar de simplemente serializar el árbol del documento, lo transforma como se especifica en la Especificación XML-C14N (ver http://www.w3.org/TR/xml-c14n). Dicha transformación se conoce como canonización.

Si $with_comments es 0 o no está definido, el documento resultante no contendrá ningún comentario que exista en el documento original. Para incluir comentarios en el documento canonizado, $with_comments debe establecerse en 1.

El parámetro $xpath_expression define el conjunto de nodos que deben ser visibles en el documento resultante. Esto puede usarse para filtrar algunos nodos. Hay que tener en cuenta que solo los nodos que forman parte del conjunto de nodos se incluirán en el documento resultante. Sus nodos hijos no existirán en el documento resultante, a menos que formen parte del conjunto de nodos definido por la expresión xpath.

Si $xpath_expression se omite o está vacío, toStringC14N() incluirá todos los nodos en el subárbol dado, utilizando las siguientes expresiones XPath: con comentarios

(. | .//node() | .//@* | .//namespace::*)

y sin comentarios

(. | .//node() | .//@* | .//namespace::*)[not(self::comment())]

Un parámetro opcional $xpath_context puede usarse para pasar un objeto XML::LibXML::XPathContext que defina el contexto para la evaluación de $xpath_expression. Esto es útil para mapear prefijos de espacio de nombres utilizados en la expresión XPath a URIs de espacio de nombres. Sin embargo, tenga en cuenta que $node se utilizará como nodo de contexto para la evaluación, ¡no como nodo de contexto de $xpath_context!

toStringC14N_v1_1
$c14nstring = $node->toStringC14N_v1_1();
$c14nstring = $node->toStringC14N_v1_1($with_comments, $xpath_expression , $xpath_context);

Esta función se comporta como toStringC14N() excepto que utiliza la constante "XML_C14N_1_1" para canonizar utilizando la "especificación C14N 1.1".

toStringEC14N
$ec14nstring = $node->toStringEC14N();
$ec14nstring = $node->toStringEC14N($with_comments, $xpath_expression, $inclusive_prefix_list);
$ec14nstring = $node->toStringEC14N($with_comments, $xpath_expression, $xpath_context, $inclusive_prefix_list);

La función es similar a toStringC14N() pero sigue la Especificación XML-EXC-C14N (ver http://www.w3.org/TR/xml-exc-c14n) para la canonización exclusiva de XML.

Los argumentos $with_comments, $xpath_expression, $xpath_context son como en toStringC14N(). Se puede pasar una referencia ARRAY como último argumento $inclusive_prefix_list, listando prefijos de espacio de nombres que se manejarán de la manera descrita por la Recomendación de XML Canónico (es decir, se conservarán en la salida incluso si el espacio de nombres no se utiliza). Cfr. la especificación para más detalles.

Un alias para toString(). Esta función se renombró para ser más consistente con libxml2.

serialize_c14n
Un alias para toStringC14N().
serialize_exc_c14n
Un alias para toStringEC14N().
localname
$localname = $node->localname;

Devuelve el nombre local de una etiqueta. Esta es la parte detrás de los dos puntos.

prefix
$nameprefix = $node->prefix;

Devuelve el prefijo de una etiqueta. Esta es la parte antes de los dos puntos.

namespaceURI
$uri = $node->namespaceURI();

devuelve la URI del espacio de nombres actual.

hasAttributes
$boolean = $node->hasAttributes();

devuelve 1 (VERDADERO) si el nodo actual tiene algún atributo establecido, de lo contrario se devuelve 0 (FALSO).

attributes
@attributelist = $node->attributes();

Esta función devuelve todos los atributos y declaraciones de espacio de nombres asignados al nodo dado.

Dado que XML::LibXML no implementa declaraciones de espacio de nombres y atributos de la misma manera, se requiere probar qué tipo de nodo se está manejando al acceder al resultado de la función.

Si esta función se llama en contexto de array, los nodos de atributo se devuelven como un array. En contexto escalar, la función devolverá un objeto XML::LibXML::NamedNodeMap.

lookupNamespaceURI
$URI = $node->lookupNamespaceURI( $prefix );

Busca una URI de espacio de nombres por su prefijo comenzando en el nodo actual.

lookupNamespacePrefix
$prefix = $node->lookupNamespacePrefix( $URI );

Busca un prefijo de espacio de nombres por su URI comenzando en el nodo actual.

NOTA Solo las URI de espacio de nombres están destinadas a ser únicas. El prefijo solo está relacionado con el documento. Además, el documento podría tener más de un prefijo definido para un espacio de nombres.

normalize
$node->normalize;

Esta función normaliza nodos de texto adyacentes. Esta función no es tan estricta como la función xmlTextMerge() de libxml2, ya que no liberará un nodo que todavía está referenciado por la capa de perl.

NAME

XML::LibXML::Node - A node in an XML document

SYNOPSIS

  use XML::LibXML;
  my $dom = XML::LibXML->load_xml('file.xml');
  my $root_node = $dom->getDocumentElement;
  my $child_nodes = $root_node->childNodes;
  my $first_child = $child_nodes->[0];
  my $namespace_map = $root_node->getNamespaces;
  my $base_uri = $root_node->baseURI;
  $root_node->removeChildNodes;
  my $path = $root_node->nodePath;
  my $line = $root_node->line_number;

DESCRIPTION

This module provides methods for interacting with nodes within an XML::LibXML document. It allows you to retrieve information about the node, manipulate its children, and determine its position in the document.

METHODS

childNodes ()
@children = $node->childNodes;

Returns a list of the child nodes of the given node. The list contains objects of the appropriate XML::LibXML subclass (e.g. XML::LibXML::Element, XML::LibXML::Text, etc.).

This method is also available as an overloaded array operator, so you can just write:

  @children = $node->;
getNamespaces ( $node_only )
 %namespaces = $node->getNamespaces;
 %namespaces = $node->getNamespaces(1);

Returns a hash containing the namespaces declared for this node. The keys are the prefixes and the values are the URIs. If the default namespace is declared, the key will be an empty string.

If the argument $node_only is true, the method will only return namespaces declared directly on this node. Otherwise, it will return all namespaces in scope for this node.

Note: This will not return all namespaces that are in scope, but only the ones declared explicitly for that node.

Although getNamespaces is available for all nodes, it only makes sense if used with element nodes.

removeChildNodes
$node->removeChildNodes();

This function is not specified for any DOM level: It removes all childnodes from a node in a single step. Other than the libxml2 function itself (xmlFreeNodeList), this function will not immediately remove the nodes from the memory. This saves one from getting memory violations, if there are nodes still referred to from the Perl level.

baseURI ()
$strURI = $node->baseURI();

Searches for the base URL of the node. The method should work on both XML and HTML documents even if base mechanisms for these are completely different. It returns the base as defined in RFC 2396 sections "5.1.1. Base URI within Document Content" and "5.1.2. Base URI from the Encapsulating Entity". However it does not return the document base (5.1.3), use method "URI" of "XML::LibXML::Document" for this.

setBaseURI ($strURI)
$node->setBaseURI($strURI);

This method only does something useful for an element node in an XML document. It sets the xml:base attribute on the node to $strURI, which effectively sets the base URI of the node to the same value.

Note: For HTML documents this behaves as if the document was XML which may not be desired, since it does not effectively set the base URI of the node. See RFC 2396 appendix D for an example of how base URI can be specified in HTML.

nodePath
$node->nodePath();

This function is not specified for any DOM level: It returns a canonical structure based XPath for a given node.

line_number
$lineno = $node->line_number();

This function returns the line number where the tag was found during parsing. If a node is added to the document the line number is 0. Problems may occur, if a node from one document is passed to another one.

IMPORTANT: Due to limitations in the libxml2 library line numbers greater than 65535 will be returned as 65535. Please see http://bugzilla.gnome.org/show_bug.cgi?id=325533 for more details.

Note: line_number() is special to XML::LibXML and not part of the DOM specification.

If the line_numbers flag of the parser was not activated before parsing, line_number() will always return 0.
