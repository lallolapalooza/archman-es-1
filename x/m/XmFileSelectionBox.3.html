NOMBRE

XmFileSelectionBox — La clase del widget FileSelectionBox

SINOPSIS

#include <Xm/FileSB.h>

DESCRIPCIÓN

FileSelectionBox atraviesa directorios, visualiza los archivos y subdirectorios en ellos, y luego selecciona archivos.

Un FileSelectionBox tiene cinco áreas principales:

•
Un campo de entrada de texto para mostrar y editar una máscara de directorio utilizada para seleccionar los archivos que se mostrarán
•
Un campo de entrada de texto opcional para mostrar y editar una máscara de filtro utilizada para seleccionar los archivos que se mostrarán.
•
Una lista desplazable de nombres de archivo
•
Una lista desplazable de subdirectorios
•
Un campo de entrada de texto para mostrar y editar un nombre de archivo
•
Un grupo de botones pulsables, etiquetados como OK, Filter, Cancel y Help. La dirección de disposición de los botones depende del recurso XmNlayoutDirection.

####Se pueden agregar hijos adicionales al FileSelectionBox después de la creación. FileSelectionBox hereda la funcionalidad de disposición proporcionada por SelectionBox para cualquier hijo adicional. Para eliminar la lista de nombres de archivo, la lista de subdirectorios, o ambas, del FileSelectionBox después de la creación, desgestione los widgets apropiados y sus etiquetas. Los widgets de lista y etiqueta se obtienen mediante una llamada a la función XmFileSelectionBoxGetChild. Para eliminar la lista de directorios o la lista de archivos, desgestione el padre del widget de lista apropiado y desgestione la etiqueta correspondiente.

El usuario puede especificar recursos en un archivo de recursos para los widgets y gadgets creados automáticamente por FileSelectionBox. La siguiente lista identifica los nombres de estos widgets (o gadgets) y las áreas asociadas de FileSelectionBox:

La máscara de directorio es una cadena que especifica el directorio base a examinar y un patrón de búsqueda. Normalmente, la lista de directorios muestra los subdirectorios del directorio base, así como el directorio base mismo y su directorio padre. La lista de archivos normalmente muestra todos los archivos y/o subdirectorios en el directorio base que coinciden con el patrón de búsqueda.

Opcionalmente, la máscara del patrón de búsqueda y el directorio base se pueden mostrar en dos campos de texto separados. Esta opción está controlada por el recurso XmNpathMode. Usar esta visualización alternativa no cambia el significado de los recursos que controlan el contenido de estos campos: XmNdirectory, XmNdirMask, XmNpattern.

Un procedimiento especificado por el recurso XmNqualifySearchDataProc extrae el directorio base y el patrón de búsqueda de la máscara de directorio. Si la especificación del directorio está vacía, se utiliza el directorio de trabajo actual. Si el patrón de búsqueda está vacío, se utiliza un patrón que coincide con todos los archivos.

Una aplicación puede proporcionar su propia XmNqualifySearchDataProc, así como sus propios procedimientos para buscar subdirectorios y archivos. El XmNqualifySearchDataProc por defecto funciona de la siguiente manera: La máscara de directorio es una ruta de acceso que puede contener cero o más caracteres de *comodín* en su parte de directorio, su parte de archivo, o ambas. Los componentes del directorio de la máscara de directorio — hasta, pero sin incluir, el primer componente con un carácter de comodín — especifican el directorio a buscar, relativo al directorio de trabajo actual. Los componentes restantes especifican el patrón de búsqueda. Si la máscara de directorio está vacía o si su primer componente contiene un carácter de comodín, se busca el directorio de trabajo actual. Si ningún componente de la máscara de directorio contiene un carácter de comodín, la máscara de directorio completa es la especificación del directorio, y se buscan todos los archivos en ese directorio.

El usuario puede seleccionar un nuevo directorio para examinar desplazándose por la lista de directorios y seleccionando el directorio deseado o editando la máscara de directorio. Seleccionar un nuevo directorio de la lista de directorios no cambia el patrón de búsqueda. Un usuario puede seleccionar un nuevo patrón de búsqueda editando la máscara de directorio o, cuando el FileSelectionBox tiene la visualización opcional XmPATH_MODE_RELATIVE de XmNpathMode, el campo de texto del filtro. Hacer doble clic o presionar KActivate en un directorio de la lista de directorios inicia una búsqueda de archivos y subdirectorios en el nuevo directorio, utilizando el patrón de búsqueda actual.

El usuario puede seleccionar un archivo desplazándose por la lista de nombres de archivo y seleccionando el archivo deseado o ingresando el nombre del archivo directamente en el área de edición de texto. Seleccionar un archivo de la lista hace que ese nombre de archivo aparezca en el área de edición de texto de selección de archivo.

El usuario puede seleccionar un nuevo archivo tantas veces como desee. La aplicación no se notifica hasta que el usuario realiza una de las siguientes acciones:

•
Selecciona el botón pulsable OK
•
Presiona KActivate mientras el área de edición de texto de selección tiene el foco del teclado
•
Hace doble clic o presiona KActivate en un elemento de la lista de archivos

FileSelectionBox inicia una búsqueda de directorios y archivos cuando ocurre alguna de las siguientes acciones:

•
El FileSelectionBox se inicializa
•
Se utiliza la función XtSetValues para cambiar XmNdirMask, XmNdirectory, XmNpattern o XmNfileTypeMask
•
El usuario activa el botón pulsable Filter
•
El usuario hace doble clic o presiona KActivate en un elemento de la lista de directorios
•
La aplicación llama a XmFileSelectionDoSearch
•
El usuario presiona KActivate mientras el área de edición de texto de la máscara de directorio tiene el foco del teclado

Cuando se inicia una búsqueda de archivos, el FileSelectionBox toma las siguientes acciones:

•
Construye una estructura XmFileSelectionBoxCallbackStruct con valores apropiados para la acción que inició la búsqueda
•
Llama a XmNqualifySearchDataProc con la estructura de devolución de llamada como argumento de entrada de datos
•
Establece XmNdirectoryValid y XmNlistUpdated en False
•
Llama a XmNdirSearchProc con los datos cualificados devueltos por XmNqualifySearchDataProc

Si XmNdirectoryValid es True, el FileSelectionBox toma las siguientes acciones adicionales:

•
Establece XmNlistUpdated en False
•
Llama a XmNfileSearchProc con los datos cualificados devueltos por XmNqualifySearchDataProc (y posiblemente modificados por XmNdirSearchProc)
•
Si XmNlistUpdated es True y la lista de archivos está vacía, muestra XmNnoMatchString en la lista de archivos y borra la selección de texto y XmNdirSpec
•
Si XmNlistUpdated es True y la lista de archivos no está vacía, establece el texto de selección y XmNdirSpec en el *dir* cualificado devuelto por XmNqualifySearchDataProc (y posiblemente modificado por XmNdirSearchProc)
•
Establece la máscara de directorio de texto y XmNdirMask en la *máscara* cualificada devuelta por XmNqualifySearchDataProc (y posiblemente modificada por XmNdirSearchProc)
•
Establece XmNdirectory en el *dir* cualificado devuelto por XmNqualifySearchDataProc (y posiblemente modificado por XmNdirSearchProc)
•
Establece XmNpattern en el *patrón* cualificado devuelto por XmNqualifySearchDataProc (y posiblemente modificado por XmNdirSearchProc)

FileSelectionBox utiliza el rasgo XmQTactivatable.

NAME

XmFileSelectionBox — A widget that allows the user to select a file

DESCRIPTION

The XmFileSelectionBox widget provides a standard dialog for selecting files. It includes a text field for entering a file name, a list of files in the current directory, a text field for filtering the file list, and a list of directories in the current directory. The widget also provides text labels and buttons for OK, Cancel, and Help actions.

XmFileSelectionBox is a subclass of XmSelectionBox and adds functionality related to file system browsing. It automatically creates and manages a set of child widgets, including text fields, lists, labels, and buttons. These child widgets can be accessed by name.

The widget supports drag and drop operations. When the source of a data transfer is the directory list or file list, and if the corresponding search procedure (XmNdirSearchProc or XmNfileSearchProc) has its default value, the list supports the FILE and FILE_NAME targets. In these cases, XmFileSelectionBox adds an XmNconvertCallback procedure to the appropriate list. This procedure adds FILE and FILE_NAME to the TARGETS returned by the list and treats requests for conversion to these targets like requests for conversion to TEXT.

If an application changes XmNdirSearchProc or XmNfileSearchProc and wants to support the FILE and FILE_NAME targets on the corresponding list, it must provide its own support by adding a procedure to the list's XmNconvertCallback list.

XmNdirectory
Especifica el directorio base utilizado en combinación con XmNpattern para determinar los archivos y directorios que se mostrarán. El valor predeterminado se determina mediante XmNqualifySearchDataProc y depende de los valores iniciales de XmNdirMask, XmNdirectory y XmNpattern. Si el valor predeterminado es NULL o está vacío, se utiliza el directorio de trabajo actual.
XmNdirectoryValid
Especifica un atributo que solo es establecido por el procedimiento de búsqueda de directorios. El valor se establece en True si el directorio pasado al procedimiento de búsqueda de directorios se puede buscar realmente. Especifica el número de elementos en la lista de directorios. El valor no debe ser negativo.
XmNdirListLabelString

XmNdirMask

XmNdirSearchProc
Especifica un procedimiento de búsqueda de directorios para reemplazar el procedimiento de búsqueda de directorios predeterminado. El procedimiento de búsqueda de directorios predeterminado de FileSelectionBox satisface las necesidades de la mayoría de las aplicaciones. Dado que es imposible cubrir los requisitos de todas las aplicaciones, puede reemplazar el procedimiento de búsqueda predeterminado.
El procedimiento de búsqueda de directorios se llama con dos argumentos: el widget FileSelectionBox y un puntero a una estructura XmFileSelectionBoxCallbackStruct. La estructura de devolución de llamada es generada por XmNqualifySearchDataProc y contiene toda la información necesaria para realizar una búsqueda de directorios, incluida la máscara de directorio y un directorio base calificado y un patrón de búsqueda. Una vez llamado, depende de la rutina de búsqueda generar una nueva lista de directorios y actualizar el widget FileSelectionBox utilizando XtSetValues.
El procedimiento de búsqueda debe
t establece XmNdirectoryValid y XmNlistUpdated. Si genera una nueva lista de directorios, también debe establecer XmNdirListItems y XmNdirListItemCount.
Si el procedimiento de búsqueda no puede buscar en el directorio especificado, debe advertir al usuario y establecer XmNdirectoryValid y XmNlistUpdated en False, a menos que solicite y obtenga posteriormente un directorio válido. Si el directorio es válido pero es el mismo que el XmNdirectory actual, el procedimiento de búsqueda debe establecer XmNdirectoryValid en True, pero puede optar por no generar una nueva lista de directorios. En este caso, debe establecer XmNlistUpdated en False.
Si el procedimiento de búsqueda genera una nueva lista de directorios, debe establecer XmNdirListItems en la nueva lista de directorios y XmNdirListItemCount en el número de elementos de la lista. Si no hay directorios, establece XmNdirListItems en NULL y XmNdirListItemCount en 0 (cero). En cualquier caso, debe establecer XmNdirectoryValid y XmNlistUpdated en True.
El procedimiento de búsqueda normalmente no debe cambiar la estructura de retrollamada. Pero si el directorio original no es válido, el procedimiento de búsqueda puede obtener un nuevo directorio del usuario. En este caso, debe establecer el miembro dir de la estructura de retrollamada al nuevo directorio, llamar a XmNqualifySearchDataProc con la estructura de retrollamada como argumento de entrada y copiar los datos calificados devueltos por XmNqualifySearchDataProc en la estructura de retrollamada.

XmNfileSearchProc
Especifica un procedimiento de búsqueda de archivos para reemplazar el procedimiento de búsqueda de archivos predeterminado. El procedimiento de búsqueda de archivos predeterminado de FileSelectionBox satisface las necesidades de la mayoría de las aplicaciones. Dado que es imposible cubrir los requisitos de todas las aplicaciones, puede reemplazar el procedimiento de búsqueda predeterminado.
El procedimiento de búsqueda de archivos se llama con dos argumentos: el widget FileSelectionBox y un puntero a una estructura XmFileSelectionBoxCallbackStruct. La estructura de retrollamada es generada por XmNqualifySearchDataProc (y posiblemente modificada por XmNdirSearchProc). Se recomienda que el procedimiento de búsqueda siempre genere una nueva lista de archivos. XmFileSelectionBox, XmFileSelectionBoxWidgetClass - Un widget de cuadro de selección de archivos

SINOPSIS

#include <Xm/FileSB.h>

El widget de cuadro de selección de archivos se deriva del widget XmSelectionBox.

Clase descendiente:
XmFileSelectionBox
Instanciación:
Un usuario llama aXmCreateFileSelectionBox.

El widget XmFileSelectionBox proporciona una interfaz de usuario estándar para seleccionar archivos. Los cuadros de selección de archivos se utilizan comúnmente para permitir que los usuarios seleccionen un archivo para abrir o guardar.

El cuadro de selección de archivos consta de los siguientes elementos:

  • Un cuadro de texto y una etiqueta para el nombre del archivo.
  • Un cuadro de texto y una etiqueta para el patrón de máscara de archivo.
  • Un cuadro de texto y una etiqueta para el directorio.
  • Un cuadro de texto y una etiqueta para el texto de selección.
  • Un botón para "Filtrar".
  • Un botón para "Establecer directorios".
  • Una lista de directorios.
  • Una lista de archivos.
  • Una lista de valores predefinidos (opcional).
  • Una serie de botones de comando.

Los elementos del cuadro de selección de archivos se derivan de XmSelectionBox. El cuadro de selección de archivos también incluye una lista de directorios y una lista de archivos.

Las rutinas de acción de XmFileSelectionBox son:

SelectionBoxUpOrDown(Previous|Next|First|Last):
Si ni el texto de selección ni la máscara de directorio (filtro) tienen el foco, esta acción no hace nada.
Si el texto de selección tiene el foco, el término lista en la siguiente descripción se refiere a la lista de archivos y el término texto se refiere al texto de selección. Si la máscara de directorio tiene el foco, lista se refiere a la lista de directorios y texto se refiere al texto de la máscara de directorio.
Cuando se llama con un argumento de Previous, o 0 (cero) para compatibilidad, esta acción selecciona el elemento anterior en la lista y reemplaza el texto con ese elemento.
Cuando se llama con un argumento de Next, o 1 para compatibilidad, esta acción selecciona el elemento siguiente en la lista y reemplaza el texto con ese elemento.
Cuando se llama con un argumento de First, o 2 para compatibilidad, esta acción selecciona el primer elemento en la lista y reemplaza el texto con ese elemento.
Cuando se llama con un argumento de Last, o 3 para compatibilidad, esta acción selecciona el último elemento en la lista y reemplaza el texto con ese elemento.
SelectionBoxRestore():
Si ni el texto de selección ni la máscara de directorio (filtro) tienen el foco, esta acción no hace nada.
Si el texto de selección tiene el foco, esta acción reemplaza el texto de selección con el elemento seleccionado en la lista de archivos. Si no hay ningún elemento seleccionado en la lista de archivos, borra el texto de selección.
Si la máscara de directorio tiene el foco, esta acción reemplaza el texto de la máscara de directorio con una nueva máscara de directorio construida a partir de los recursos XmNdirectory y XmNpattern.

NAME

XmFileSelectionBox — A widget that allows users to select files from a file system.

SYNOPSIS

#include <Xm/FileSB.h>

A FileSelectionBox widget is created by calling:

widget = XmCreateFileSelectionBox(parent, name, arglist, argcount);

The FileSelectionBox widget includes the following child widgets:

    SelectionDialog (ScrolledWindow, Frame, WorkArea)
        DirectoryList (ScrolledWindow, List)
        FilterLabel (Label)
        FilterText (Text)
        FileList (ScrolledWindow, List)
        FileLabel (Label)
        SelectionLabel (Label)
        SelectionText (Text)
        DirectoryButton (PushButton)
        HelpButton (PushButton)
        OkButton (PushButton)
        CancelButton (PushButton)
        SetValueButton (PushButton)
        ListboxHeader (Label)

Callbacks are invoked with the following reason codes:

XmCR_OK
The user selected a file or directory and clicked the OK button.
XmCR_CANCEL
The user clicked the Cancel button.
XmCR_HELP
The user clicked the Help button.
XmCR_FILTER
The user modified the filter text.
XmCR_DIR_SPECIFIED
The user selected a directory from the directory list.
XmCR_VALUE_CHANGED
The value in the selection text field changed.
XmCR_APPLY
The user clicked the Apply button.
XmCR_NO_MATCH
No files matched the current filter.

DESCRIPTION

The XmFileSelectionBox widget provides a dialog box that allows users to select files from a file system. It displays a list of files and directories in the current directory, a text field for entering a file pattern, and a text field for displaying the selected file name. The widget also includes buttons for OK, Cancel, Help, Apply, and Set Value.

The XmFileSelectionBox widget is a subclass of the XmSelectionBox widget. It inherits all the resources and behavior of XmSelectionBox and adds specific functionality for file selection.

The widget automatically performs a file search based on the initial pattern and updates the file list accordingly. Users can change the current directory by selecting a directory from the directory list or by editing the directory text field.

When the user selects a file and clicks the OK button, the widget invokes callbacks with the reason XmCR_OK.

Virtual Bindings

The bindings for virtual keys are vendor specific. For information about bindings for virtual buttons and keys, see VirtualBindings(3).
