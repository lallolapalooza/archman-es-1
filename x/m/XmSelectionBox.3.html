NOMBRE

XmSelectionBox — La clase de widget SelectionBox

SINOPSIS

#include <Xm/SelectioB.h>

DESCRIPCIÓN

SelectionBox es un widget de diálogo general que permite al usuario seleccionar un elemento de una lista. Por defecto, un SelectionBox incluye lo siguiente:

•
Una lista desplazable de alternativas
•
Un campo de texto editable para la alternativa seleccionada
•
Etiquetas para la lista y el campo de texto
•
Tres o cuatro botones

Las etiquetas de los botones por defecto son OK, Cancel y Help. Por defecto se crea también un botón Apply; si el padre del SelectionBox es un DialogShell, se gestiona; de lo contrario, se deja de gestionar. Se pueden añadir hijos adicionales al SelectionBox después de la creación. El primer hijo se utiliza como área de trabajo. El valor de XmNchildPlacement determina si el área de trabajo se coloca encima o debajo del área de Texto, o encima o debajo del área de Lista. Los hijos adicionales se organizan de la siguiente manera:

Barra de menús
La primera barra de menús hija se coloca en la parte superior de la ventana. Se utiliza el rasgo XmQTmenuSystem para verificar que es la primera barra de menús hija.
Botones
Todos los widgets o gadgets XmPushButton, y sus subclases, se colocan después del botón OK en el orden de su creación (este orden se verifica utilizando el rasgo XmQTactivatable). La dirección de disposición de los botones depende del recurso XmNlayoutDirection.

El diseño de los hijos adicionales que no pertenecen a las categorías anteriores no está definido.

El usuario puede seleccionar un elemento de dos maneras: desplazándose por la lista y seleccionando el elemento deseado, o introduciendo el nombre del elemento directamente en el área de edición de texto. La selección de un elemento de la lista hace que el nombre de ese elemento aparezca en el área de edición de texto de selección.

El usuario puede seleccionar un nuevo elemento tantas veces como desee. El elemento no se selecciona realmente hasta que el usuario presiona el PushButton OK.

El valor por defecto para el recurso XmNcancelButton de XmBulletinBoard es el botón Cancelar, a menos que XmNdialogType sea XmDIALOG_COMMAND, en cuyo caso el valor por defecto es NULL. El valor por defecto para el recurso XmNdefaultButton de XmBulletinBoard es el botón OK, a menos que XmNdialogType sea XmDIALOG_COMMAND, en cuyo caso el valor por defecto es NULL.

Para SelectionBox y sus subclases, el valor por defecto para XmNinitialFocus es el área de edición de texto.

El usuario puede especificar recursos en un archivo de recursos para los widgets y gadgets creados automáticamente por SelectionBox. La siguiente lista identifica los nombres de estos widgets (o gadgets) y las áreas asociadas de SelectionBox:

XmSelectionBox - una caja de selección

Descripción

La caja de selección proporciona una forma de solicitar y recibir información del usuario. Contiene un campo de texto para que el usuario introduzca información y una lista de elementos entre los que el usuario puede seleccionar. También incluye botones para aceptar o cancelar la selección.

La caja de selección se compone de varios widgets subordinados, incluidos un widget XmBulletinBoard, un widget XmScrolledText, un widget XmList y varios widgets XmPushButton.

NAME

XmSelectionBox — SelectionBox widget

SYNOPSIS

#include <Xm/Selectio.h>

DESCRIPTION

The SelectionBox widget provides a standard dialog box for selecting a file or another item from a list. It includes a list widget, an optional text field for entering the selection, and optional OK, Cancel, Apply, and Help buttons. The SelectionBox widget can also include an optional filter text field and a filter button.

This widget is typically used to prompt the user for a selection, such as a filename. The SelectionBox widget is created by the XmCreateSelectionBox, XmCreateSelectionDialog, and XmCreatePromptDialog functions.

SELECTIONBOX CALLBACKS

The following callbacks can be used with the SelectionBox widget:

XmNokCallback
Called when the OK button is activated or when the user activates the OK action with a traversal key. The reason is XmCR_OK.
XmNcancelCallback
Called when the Cancel button is activated or when the user activates the Cancel action with a traversal key. The reason is XmCR_CANCEL.
XmNapplyCallback
Called when the Apply button is activated or when the user activates the Apply action with a traversal key. The reason is XmCR_APPLY.
XmNhelpCallback
Called when the Help button is activated or when the user activates the Help action with a traversal key. The reason is XmCR_HELP.
XmNnoMatchCallback
Called when the OK button is activated and the text field does not match an item in the list, and the XmNmustMatch resource is True. The reason is XmCR_NO_MATCH.
XmNvalueChangedCallback
Called when the value in the text field changes. The reason is XmCR_VALUE_CHANGED.
XmNfocusCallback
Called when the widget receives focus. The reason is XmCR_FOCUS.
XmNmapCallback
Called when the SelectionBox widget is mapped. The reason is XmCR_MAP.
XmNunmapCallback
Called when the SelectionBox widget is unmapped. The reason is XmCR_UNMAP.

SELECTIONBOX TRAVERSAL FUNCTIONS

The SelectionBox widget supports the following traversal functions:

When called with an argument of Previous, or -1 for compatibility, selects the previous item in the list and replaces the text with that item.
When called with an argument of Next, or 1 for compatibility, selects the next item in the list and replaces the text with that item.
When called with an argument of First, or 2 for compatibility, selects the first item in the list and replaces the text with that item.
When called with an argument of Last, or 3 for compatibility, selects the last item in the list and replaces the text with that item.
SelectionBoxRestore():
Replaces the text value with the list selection. If no item in the list is selected, clears the text.

Additional Behavior

The SelectionBox widget has the following additional behavior:

<Key><osfCancel>:
Calls the activate callbacks for the cancel button if it is sensitive. If no cancel button exists and the parent of the SelectionBox is a manager, passes the event to the parent.
<Key><osfActivate>:
Calls the activate callbacks for the button with the keyboard focus. If no button has the keyboard focus, calls the activate callbacks for the default button if it is sensitive. In a List widget or single-line Text widget, the List or Text action associated with <Key><osfActivate> is called before the SelectionBox actions associated with <Key><osfActivate>. In a multiline Text widget, any <Key><osfActivate> event except <Key><osfEnter> calls the Text action associated with <Key><osfActivate>, then the SelectionBox actions associated with <Key><osfActivate>. If no button has the focus, no default button exists, and the parent of the SelectionBox is a manager, passes the event to the parent.
<OK Button Activated>:
If XmNmustMatch is True and the text does not match an item in the file list, calls the XmNnoMatchCallback callbacks with reason XmCR_NO_MATCH. Otherwise, calls the XmNokCallback callbacks with reason XmCR_OK.
<Apply Button Activated>:
Calls the XmNapplyCallback callbacks with reason XmCR_APPLY.
<Cancel Button Activated>:
Calls the XmNcancelCallback callbacks with reason XmCR_CANCEL.
<Help Button Activated>:
Calls the XmNhelpCallback callbacks with reason XmCR_HELP.
<MapWindow>:
Calls the callbacks for XmNmapCallback if the SelectionBox is a child of a Dialog shell.
<UnmapWindow>:
