XML__LibXML__Simple(3pm)

XML::LibXML::Simple(3) Documentación de Perl contribuida por el usuario XML::LibXML::Simple(3)

NOMBRE

XML::LibXML::Simple - Clon de XML::LibXML de XML::Simple::XMLin()

HERENCIA

XML::LibXML::Simple
  es un Exporter

SINOPSIS

my $xml  = ...;  # nombre de archivo, fh, cadena o nodo XML::LibXML

Imperativo:

use XML::LibXML::Simple   qw(XMLin);
my $data = XMLin $xml, %options;

O la forma orientada a objetos:

use XML::LibXML::Simple   ();
my $xs   = XML::LibXML::Simple->new(%options);
my $data = $xs->XMLin($xml, %options);

DESCRIPCIÓN

Este módulo es una reescritura directa de XML::Simple (de Grant McLean) para utilizar el analizador XML::LibXML para estructuras XML, donde el original utiliza analizadores Perl o SAX simples.

Advertencia: este módulo se cree listo. Puedes meterte en serios problemas con esta inteligencia ("DWIMmery"). Lee la página manual completa al menos una vez antes de empezar a usarlo. Si tu XML está descrito en un esquema o WSDL, utiliza XML::Compile para código mantenible.

MÉTODOS

Constructores

XML::LibXML::Simple->new(%options)
Instancia un objeto, que puede ser usado para llamar a XMLin(). Puedes proporcionar %options a este constructor (para ser reutilizadas para cada llamada a XMLin) y con cada llamada a XMLin (para ser usadas una vez).

Para descripciones de las %options, consulta la sección "DETALLES" de esta página manual.

Traductores

$obj->XMLin($xmldata, %options)
Para $xmldata y descripciones de las %options, consulta la sección "DETALLES" de esta página manual.

FUNCIONES

Las funciones "XMLin" (exportada implícitamente) y "xml_in" (exportada bajo petición) simplemente llaman a "<XML::LibXML::Simple-"new->XMLin() >> con los parámetros proporcionados.

DETALLES

Parámetro $xmldata

Como primer parámetro a XMLin(), se debe proporcionar el mensaje XML a traducir a una estructura Perl. Elige una de las siguientes opciones:

Un nombre de archivo
Si el nombre de archivo no contiene componentes de directorio, XMLin() buscará el archivo en cada directorio de la ruta de búsqueda (ver OPCIONES abajo) y en el directorio actual. Ej: 
$data = XMLin('/etc/params.xml', %options);
Un guion (-)
Analiza desde STDIN. 
$data = XMLin('-', %options);
undef
[obsoleto] Si no hay especificador XML, XMLin() comprobará el directorio del script y cada uno de los directorios de SearchPath en busca de un archivo con el mismo nombre que el script pero con la extensión '.xml'. Nota: si deseas especificar opciones, debes especificar el valor 'undef'. Ej: 
$data = XMLin(undef, ForceArray => 1);

Esta característica está disponible por compatibilidad con versiones anteriores de XML::Simple, pero es muy sensible. Puedes accidentalmente dar con el archivo XML incorrecto como entrada. Por favor, no la uses: utiliza siempre un nombre de archivo explícito.

Una cadena de XML
Una cadena que contiene XML (reconocida por la presencia de los caracteres '<' y '>') se analizará directamente. Ej: 
$data = XMLin('<opt username="bob" password="flurp" />', %options);
Un objeto IO::Handle
En este caso, XML::LibXML::Parser leerá los datos XML directamente del archivo proporcionado. 
# $fh = IO::File->new('/etc/params.xml') or die;
open my $fh, '<:encoding(utf8)', '/etc/params.xml' or die;
$data = XMLin($fh, %options);
Un XML::LibXML::Document o ::Element
[No disponible en XML::Simple] Cuando ya tienes un nodo XML::LibXML previamente analizado, puedes pasarlo.

Parámetro %options

XML::LibXML::Simple soporta la mayoría de las opciones definidas por XML::Simple, por lo que la interfaz es bastante compatible. Se aplican cambios menores. Esta explicación está extraída de la página manual de XML::Simple.

  • echa un vistazo a "ForceArray" porque casi seguro querrás activarla
  • asegúrate de saber qué hace la opción "KeyAttr" y cuál es su valor por defecto, ya que de lo contrario podría sorprenderte.
  • los nombres de las opciones no distinguen entre mayúsculas y minúsculas, por lo que puedes usar las versiones con mayúsculas/minúsculas mostradas aquí; puedes añadir guiones bajos entre las palabras (ej: key_attr) si lo deseas.

En orden alfabético:

ContentKey => 'nombre_clave' # raramente usado
Cuando el contenido de texto se analiza como un valor de hash, esta opción te permite especificar un nombre para la clave del hash para anular el valor por defecto 'content'. Por ejemplo: 
XMLin('<opt one="1">Two</opt>', ContentKey => 'text')

se analizará como:

{ one => 1, text => 'Two' }

en lugar de:

{ one => 1, content => 'Two' }

También puedes prefijar el nombre de clave seleccionado con un carácter '-' para que XMLin() intente un poco más eliminar claves 'content' innecesarias después del plegado de arrays. Por ejemplo:

XMLin(
  '<opt><item name="one">First</item><item name="two">Second</item></opt>', 
  KeyAttr => {item => 'name'}, 
  ForceArray => [ 'item' ],
  ContentKey => '-content'
)

se analizará como:

{
   item => {
    one =>  'First'
    two =>  'Second'
  }
}

en lugar de esto (sin el '-'):

{
  item => {
    one => { content => 'First' }
    two => { content => 'Second' }
  }
}
ForceArray => 1 # importante
Esta opción debe establecerse a '1' para forzar que los elementos anidados se representen como arrays incluso cuando solo hay uno. Ej: con ForceArray activado, este XML: 
<opt>
  <name>value</name>
</opt>

se analizaría como esto:

{ name => [ 'value' ] }

en lugar de esto (el valor por defecto):

{ name => 'value' }

Esta opción es especialmente útil si la estructura de datos es probable que se vuelva a escribir como XML y el comportamiento por defecto de fusionar elementos anidados únicos en atributos no es deseable.

Si estás utilizando la característica de plegado de arrays, casi con seguridad deberías habilitar esta opción. Si no lo haces, los elementos anidados únicos no se analizarán como arrays y, por lo tanto, no serán candidatos para el plegado a un hash. (Dado que el valor por defecto de 'KeyAttr' habilita el plegado de arrays, el valor por defecto de esta opción también debería haber estado habilitado).

ForceArray => [ nombres ] # importante
Esta forma alternativa (y preferida) de la opción 'ForceArray' te permite especificar una lista de nombres de elementos que siempre se forzarán a una representación de array, en lugar del enfoque de 'todo o nada' anterior.

También es posible incluir expresiones regulares compiladas en la lista; cualquier nombre de elemento que coincida con el patrón se forzará a arrays. Si la lista contiene solo una expresión regular, entonces no es necesario encerrarla en un arrayref. Ej:

ForceArray => qr/_list
ForceContent => 1 # raramente usado
Cuando XMLin() analiza elementos que tienen contenido de texto, además de atributos, el contenido de texto debe representarse como un valor hash en lugar de un escalar simple. Esta opción le permite forzar que el contenido de texto siempre se analice como un valor hash, incluso cuando no hay atributos. Por ejemplo: 
XMLin('<opt><x>texto1</x><y a="2">texto2</y></opt>', ForceContent => 1)

se analizará como:

{
  x => {         content => 'texto1' },
  y => { a => 2, content => 'texto2' }
}

en lugar de:

{
  x => 'texto1',
  y => { 'a' => 2, 'content' => 'texto2' }
}
GroupTags => { etiqueta de agrupacion => etiqueta agrupada } # útil
Puede usar esta opción para eliminar niveles adicionales de indirección en su estructura de datos Perl. Por ejemplo, este XML: 
 <opt>
  <searchpath>
    <dir>/usr/bin</dir>
    <dir>/usr/local/bin</dir>
    <dir>/usr/X11/bin</dir>
  </searchpath>
</opt>

Normalmente se leería en una estructura como esta:

{
  searchpath => {
     dir => [ '/usr/bin', '/usr/local/bin', '/usr/X11/bin' ]
  }
}

Pero al leerlo con el valor apropiado para 'GroupTags':

my $opt = XMLin($xml, GroupTags => { searchpath => 'dir' });

Devolverá esta estructura más simple:

{
  searchpath => [ '/usr/bin', '/usr/local/bin', '/usr/X11/bin' ]
}

El elemento de agrupación ("<searchpath>" en el ejemplo) no debe contener ningún atributo o elemento que no sea el elemento agrupado.

Puede especificar múltiples mapeos de 'elemento de agrupación' a 'elemento agrupado' en el mismo hashref. Si esta opción se combina con "KeyAttr", el plegado de arreglos ocurrirá primero y luego se eliminarán los nombres de elementos agrupados.

HookNodes => CODIGO
Selecciona nodos del documento para aplicar trucos especiales. Introducido en [0.96], no disponible en XML::Simple.

Cuando se proporciona esta opción, el CODIGO se llamará una vez que el árbol DOM XML esté listo para ser transformado en Perl. Su CODIGO debe devolver ya sea "undef" (nada que hacer) o un HASH que mapea valores de unique_key (ver el método "unique_key" de XML::LibXML::Node) a referencias de CODIGO a ser llamadas.

Una vez que el traductor de XML a Perl llegue a un nodo seleccionado, llamará a su rutina específica para ese nodo. El nodo desencadenante encontrado es el único parámetro. Cuando devuelve "undef", el nodo no se encontrará en el resultado final. Puede devolver cualquier dato (incluso el nodo mismo) que se incluirá en el resultado final tal cual, bajo el nombre del nodo original.

Ejemplo:

my $out = XMLin $file, HookNodes => \&protect_html;
sub protect_html($$)
{   # $obj es el objeto XML::Compile::Simple instanciado
    # $xml es un XML::LibXML::Element a transformar
    my ($obj, $xml) = @_;
    my %hooks;    # recopila la tabla de hooks
    # realiza una búsqueda xpath para HTML
    my $xpc   = XML::LibXML::XPathContext->new($xml);
    my @nodes = $xpc->findNodes(...); #XXX
    @nodes or return undef;
    my $as_text = sub { $_[0]->toString(0) };  # como texto
    #  $as_node = sub { $_[0] };               # como nodo
    #  $skip    = sub { undef };               # en absoluto
    # el mismo comportamiento para todos los nodos xpath, en este ejemplo
    $hook{$_->unique_key} = $as_text
        for @nodes;

    \%hook;
}
KeepRoot => 1 # útil
En su intento de devolver una estructura de datos libre de detalles superfluos y niveles de indirección innecesarios, XMLin() normalmente descarta el nombre del elemento raíz. Establecer la opción 'KeepRoot' a '1' hará que se conserve el nombre del elemento raíz. Así que después de ejecutar este código: 
$config = XMLin('<config tempdir="/tmp" />', KeepRoot => 1)

Podrá hacer referencia a tempdir como "$config->{config}->{tempdir}" en lugar de la opción predeterminada "$config->{tempdir}".

KeyAttr => [ lista ] # importante
Esta opción controla la característica de 'plegado de arreglos' que traduce elementos anidados de un arreglo a un hash. También controla el 'desplegado' de hashes a arreglos.

Por ejemplo, este XML:

<opt>
  <user login="grep" fullname="Gary R Epstein" />
  <user login="stty" fullname="Simon T Tyson" />
</opt>

por defecto, se analizaría de la siguiente manera:

{
  user => [
     { login    => 'grep',
       fullname => 'Gary R Epstein'
     },
     { login    => 'stty',
       fullname => 'Simon T Tyson'
     }
  ]
}

Si se usara la opción 'KeyAttr => "login"' para especificar que el atributo 'login' es una clave, el mismo XML se analizaría como:

{
  user => {
     stty => { fullname => 'Simon T Tyson' },
     grep => { fullname => 'Gary R Epstein' }
  }
}

Los nombres de los atributos clave deben proporcionarse en un arrayref si hay más de uno. XMLin() intentará hacer coincidir los nombres de los atributos en el orden proporcionado.

Nota 1: El valor predeterminado para 'KeyAttr' es "['name', 'key', 'id']". Si no desea el plegado en la entrada o el desplegado en la salida, debe establecer esta opción a una lista vacía para deshabilitar la característica.

Nota 2: Si desea utilizar esta opción, también debe habilitar la opción "ForceArray". Sin 'ForceArray', un solo elemento anidado se convertirá en un escalar en lugar de un arreglo y, por lo tanto, no se plegará (ya que solo los arreglos se pliegan).

KeyAttr => { lista } # importante
Este método alternativo (y preferido) para especificar los atributos clave permite un control más detallado sobre qué elementos se pliegan y con qué atributos. Por ejemplo, la opción 'KeyAttr => { package => 'id' } hará que cualquier elemento de paquete se pliegue en el atributo 'id'. Ningún otro elemento que tenga un atributo 'id' se plegará en absoluto.

Dos variaciones adicionales son posibles anteponiendo un carácter '+' o un '-' al nombre del atributo:

La opción 'KeyAttr => { user => "+login" }' hará que este XML:

<opt>
  <user login="grep" fullname="Gary R Epstein" />
  <user login="stty" fullname="Simon T Tyson" />
</opt>

se analice en esta estructura de datos:

{
  user => {
     stty => {
        fullname => 'Simon T Tyson',
        login    => 'stty'
     },
     grep => {
        fullname => 'Gary R Epstein',
        login    => 'grep'
     }
  }
}

El '+' indica que el valor del atributo clave se copiará en lugar de moverse a la clave hash plegada.

Un prefijo '-' produciría este resultado:

{
  user => {
     stty => {
        fullname => 'Simon T Tyson',
        -login   => 'stty'
     },
     grep => {
        fullname => 'Gary R Epstein',
        -login    => 'grep'
     }
  }
}
NoAttr => 1 # útil
Cuando se usa con XMLin(), cualquier atributo en el XML será ignorado.
NormaliseSpace => 0 | 1 | 2 # útil
Esta opción controla cómo se maneja el espacio en blanco en el contenido de texto. Los valores reconocidos para la opción son:
"0"
(predeterminado) el espacio en blanco se pasa sin alterar (excepto, por supuesto, por la normalización del espacio en blanco en los valores de los atributos que exige la recomendación XML)
"1"
el espacio en blanco se normaliza en cualquier valor utilizado como clave hash (normalizar significa eliminar el espacio en blanco inicial y final y colapsar secuencias de caracteres de espacio en blanco a un solo espacio)
"2"
el espacio en blanco se normaliza en todo el contenido de texto

Nota: puede escribir esta opción con una 'z' si le resulta más natural.

Parser => OBJETO
Puede pasar su propio objeto XML::LibXML, en lugar de que se cree uno para usted. Esto es útil cuando necesita una configuración específica en ese objeto (ver XML::LibXML::Parser) o ha implementado su propia extensión a ese objeto.

El objeto parser creado internamente está configurado en modo seguro. Lea el manual de XML::LibXML::Parser sobre problemas de seguridad con ciertas configuraciones de parámetros. ¡El valor predeterminado no es seguro!

ParserOpts => HASH|ARRAY
Pase parámetros a la creación de un nuevo objeto parser interno. Puede anular las opciones que crearán un parser seguro. Puede ser más legible usar el parámetro "Parser".
SearchPath => [ lista ] # útil
Si pasa XMLin() un nombre de archivo, pero el nombre de archivo no incluye ningún componente de directorio, puede usar esta opción para especificar qué directorios deben buscarse para localizar el archivo. Podría usar esta opción para buscar primero en el directorio de inicio del usuario, luego en un directorio global como /etc.

Si se proporciona un nombre de archivo a XMLin() pero SearchPath no está definido, se asume que el archivo está en el directorio actual.

Si el primer parámetro para XMLin() no está definido, el SearchPath predeterminado contendrá solo el directorio en el que se encuentra el script. De lo contrario, el SearchPath predeterminado estará vacío.

SuppressEmpty => 1 | '' | undef
[0.99] Qué hacer con los elementos vacíos (sin atributos y sin contenido). El comportamiento predeterminado es representarlos como hashes vacíos. Establecer

NAME

XML::LibXML::Simple - Simple interface to XML::LibXML

INHERITANCE

XML::LibXML::Simple: Itself

SYNOPSIS

  use XML::LibXML::Simple;

  # Read XML from a file
  my $data = XMLin('input.xml');

  # Read XML from a string
  my $data = XMLin($string);

  # Get data as arrays instead of hashes
  my $data = XMLin($string, ForceArray => 1);

  # Get data as hashes instead of arrays
  my $data = XMLin($string, ForceArray => [qw(person)]);

  # Use a specific attribute as the key in nested structures
  my $data = XMLin($string, KeyAttr => 'id');

  # Control how empty elements are treated
  my $data = XMLin($string, Empty => 1); # Skip empty elements
  my $data = XMLin($string, Empty => 'undef'); # Represent empty as undef
  my $data = XMLin($string, Empty => ''); # Represent empty as empty string

  # Deal with elements that only have attributes
  my $data = XMLin($string, ValueAttr => [qw(value)]);

  # Expand namespace prefixes
  my $data = XMLin($string, NsExpand => 1);

  # Strip namespace prefixes (sloppy)
  my $data = XMLin($string, NsStrip => 1);

DESCRIPTION

This module provides a simple, almost identical interface to the popular XML::Simple module, but implemented on top of XML::LibXML. This allows for faster parsing and handling of larger XML documents.

The goal is to be compatible with XML::Simple wherever possible. Documentation and interface design are borrowed heavily from XML::Simple.

METHODS

None.

FUNCTIONS

Only the XMLin() function is exported by default.

XMLin

Takes a string containing XML, or a filename, and returns a Perl data structure (hash reference).

See the OPTIONS section below for how to control the parsing behavior.

DETAILS

OPTIONS

The XMLin() function accepts a hash of options that control how the XML is parsed and what data structure is returned.

ContentKey => string
Elements that have both attributes and text content are typically returned as a hashref with the attributes as keys. This option specifies the key name that will hold the text content. The default is "content".
Debug => 1
Turns on debugging output. Currently this just prints the XML being processed.
Empty => 1
This option to a true value (eg: 1) will cause empty elements to be skipped altogether. Setting the option to 'undef' or the empty string will cause empty elements to be represented as the undefined value or the empty string respectively.
ValueAttr => [ names ]
Use this option to deal with elements which always have a single attribute and no content. Eg:
<opt>
  <colour value="red" />
  <size   value="XXL" />
</opt>

Setting "ValueAttr => [ 'value' ]" will cause the above XML to parse to:

{
  colour => 'red',
  size   => 'XXL'
}

instead of this (the default):

{
  colour => { value => 'red' },
  size   => { value => 'XXL' }
}
NsExpand => 0 advised
When name-spaces are used, the default behavior is to include the prefix in the key name. However, this is very dangerous: the prefixes can be changed without a change of the XML message meaning. Therefore, you can better use this "NsExpand" option. The downside, however, is that the labels get very long.

Without this option:

<record xmlns:x="http://xyz">
  <x:field1>42</x:field1>
</record>
<record xmlns:y="http://xyz">
  <y:field1>42</y:field1>
</record>

translates into

{ 'x:field1' => 42 }
{ 'y:field1' => 42 }

but both source component have exactly the same meaning. When "NsExpand" is used, the result is:

{ '{http://xyz}field1' => 42 }
{ '{http://xyz}field1' => 42 }

Of course, addressing these fields is more work. It is advised to implement it like this:

my $ns = 'http://xyz';
$data->{"{$ns}field1"};
NsStrip => 0 sloppy coding
[not available in XML::Simple] Namespaces are really important to avoid name collissions, but they are a bit of a hassle. To do it correctly, use option "NsExpand". To do it sloppy, use "NsStrip". With this option set, the above example will return
{ field1 => 42 }
{ field1 => 42 }

EXAMPLES

When XMLin() reads the following very simple piece of XML:

<opt username="testuser" password="frodo"></opt>

it returns the following data structure:

{
  username => 'testuser',
  password => 'frodo'
}

The identical result could have been produced with this alternative XML:

<opt username="testuser" password="frodo" />

Or this (although see 'ForceArray' option for variations):

<opt>
  <username>testuser</username>
  <password>frodo</password>
</opt>

Repeated nested elements are represented as anonymous arrays:

<opt>
  <person firstname="Joe" lastname="Smith">
    <email>joe@smith.com</email>
    <email>jsmith@yahoo.com</email>
  </person>
  <person firstname="Bob" lastname="Smith">
    <email>bob@smith.com</email>
  </person>
</opt>
{
  person => [
    { email     => [ 'joe@smith.com', 'jsmith@yahoo.com' ],
      firstname => 'Joe',
      lastname  => 'Smith'
    },
    { email     => 'bob@smith.com',
      firstname => 'Bob',
      lastname  => 'Smith'
    }
  ]
}

Nested elements with a recognised key attribute are transformed (folded) from an array into a hash keyed on the value of that attribute (see the "KeyAttr" option):

<opt>
  <person key="jsmith" firstname="Joe" lastname="Smith" />
  <person key="tsmith" firstname="Tom" lastname="Smith" />
  <person key="jbloggs" firstname="Joe" lastname="Bloggs" />
</opt>
{
  person => {
     jbloggs => {
        firstname => 'Joe',
        lastname  => 'Bloggs'
     },
     tsmith  => {
        firstname => 'Tom',
        lastname  => 'Smith'
     },
     jsmith => {
        firstname => 'Joe',
        lastname => 'Smith'
     }
  }
}

The <anon> tag can be used to form anonymous arrays:

<opt>
  <head><anon>Col 1</anon><anon>Col 2</anon><anon>Col 3</anon></head>
  <data><anon>R1C1</anon><anon>R1C2</anon><anon>R1C3</anon></data>
  <data><anon>R2C1</anon><anon>R2C2</anon><anon>R2C3</anon></data>
  <data><anon>R3C1</anon><anon>R3C2</anon><anon>R3C3</anon></data>
</opt>
{
  head => [ [ 'Col 1', 'Col 2', 'Col 3' ] ],
  data => [ [ 'R1C1', 'R1C2', 'R1C3' ],
            [ 'R2C1', 'R2C2', 'R2C3' ],
            [ 'R3C1', 'R3C2', 'R3C3' ]
          ]
}

Anonymous arrays can be nested to arbirtrary levels and as a special case, if the surrounding tags for an XML document contain only an anonymous array the arrayref will be returned directly rather than the usual hashref:

<opt>
  <anon><anon>Col 1</anon><anon>Col 2</anon></anon>
  <anon><anon>R1C1</anon><anon>R1C2</anon></anon>
  <anon><anon>R2C1</anon><anon>R2C2</anon></anon>
</opt>
[
  [ 'Col 1', 'Col 2' ],
  [ 'R1C1', 'R1C2' ],
  [ 'R2C1', 'R2C2' ]
]

Elements which only contain text content will simply be represented as a scalar. Where an element has both attributes and text content, the element will be represented as a hashref with the text content in the 'content' key (see the "ContentKey" option):

<opt>
  <one>first</one>
  <two attr="value">second</two>
</opt>
{
  one => 'first',
  two => { attr => 'value', content => 'second' }
}

Mixed content (elements which contain both text content and nested elements) will be not be represented in a useful way - element order and significant whitespace will be lost. If you need to work with mixed content, then XML::Simple is not the right tool for your job - check out the next section.

Differences to XML::Simple

In general, the output and the options are equivalent, although this module has some differences with XML::Simple to be aware of.

only XMLin() is supported
If you want to write XML then use a schema (for instance with XML::Compile). Do not attempt to create XML by hand! If you still think you need it, then have a look at XMLout() as implemented by XML::Simple or any of a zillion template systems.
no "variables" option
IMO, you should use a templating system if you want variables filled-in in the input: it is not a task for this module.
ForceArray options
There are a few small differences in the result of the "forcearray" option, because XML::Simple seems to behave inconsequently.
hooks
XML::Simple does not support hooks.

SEE ALSO

XML::Compile for processing XML when a schema is available. When you have a schema, the data and structure of your message get validated.
