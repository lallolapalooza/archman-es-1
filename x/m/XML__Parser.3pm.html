NOMBRE

XML::Parser - Un módulo de Perl para analizar documentos XML

SINOPSIS

use XML::Parser;
$p1 = XML::Parser->new(Style => 'Debug');
$p1->parsefile('REC-xml-19980210.xml');
$p1->parse('<foo id="me">Hola Mundo</foo>');
# Alternativa
$p2 = XML::Parser->new(Handlers => {Start => \&handle_start,
                                   End   => \&handle_end,
                                   Char  => \&handle_char});
$p2->parse($socket);
# Otra alternativa
$p3 = XML::Parser->new(ErrorContext => 2);
$p3->setHandlers(Char    => \&text,
                 Default => \&other);
open(my $fh, 'xmlgenerator |');
$p3->parse($fh, ProtocolEncoding => 'ISO-8859-1');
close($fh);
$p3->parsefile('junk.xml', ErrorContext => 3);

DESCRIPCIÓN

Este módulo proporciona formas de analizar documentos XML. Está construido sobre XML::Parser::Expat, que es una interfaz de bajo nivel a la biblioteca expat de James Clark. Cada llamada a uno de los métodos de análisis crea una nueva instancia de XML::Parser::Expat que se utiliza luego para analizar el documento. Las opciones de Expat pueden proporcionarse al crear el objeto XML::Parser. Estas opciones se pasan luego al objeto Expat en cada llamada de análisis. También pueden darse como argumentos adicionales a los métodos de análisis, en cuyo caso anulan las opciones dadas en el momento de la creación de XML::Parser.

El comportamiento del analizador se controla mediante las opciones "STYLES" y/o "HANDLERS", o mediante el método "setHandlers". Todas ellas proporcionan mecanismos para que XML::Parser establezca los manejadores necesarios para XML::Parser::Expat. Si no se especifican ni "Style" ni "Handlers", el análisis simplemente verifica que el documento esté bien formado.

Cuando se llaman los manejadores subyacentes, reciben como primer parámetro el objeto *Expat*, no el objeto Parser.

MÉTODOS

new
Este es un método de clase, el constructor para XML::Parser. Las opciones se pasan como pares clave-valor. Las opciones reconocidas son:
  • Style

    Esta opción proporciona una forma sencilla de crear un estilo dado de analizador. Los estilos integrados son: "Debug", "Subs", "Tree", "Objects" y "Stream". Todos ellos están definidos en paquetes separados bajo "XML::Parser::Style::*", y puede encontrar más documentación para cada estilo tanto a continuación como en esos paquetes.

    Los estilos personalizados pueden proporcionarse dando un nombre de paquete completo que contenga al menos un '::'. Este paquete debería entonces tener subs definidas para cada manejador que desee instalar. Consulte "STYLES" a continuación para una discusión de cada estilo integrado.

  • Handlers

    Cuando se proporciona, esta opción debe ser un hash anónimo que contenga como claves el tipo de manejador y como valores una referencia a una subrutina para manejar ese tipo de evento. Todos los manejadores reciben como su primer parámetro la instancia de expat que está analizando el documento. Se puede encontrar más información sobre los manejadores en "HANDLERS". Cualquier manejador establecido aquí anula el manejador correspondiente establecido con la opción Style.

  • Pkg

    Algunos estilos harán referencia a subs definidas en este paquete. Si no se proporciona, se utiliza por defecto el paquete que llamó al constructor.

  • ErrorContext

    Esta es una opción de Expat. Cuando se define esta opción, los errores se informan en contexto. El valor debe ser el número de líneas a mostrar a cada lado de la línea en la que ocurrió el error.

  • ProtocolEncoding

    Esta es una opción de Expat. Establece el nombre de la codificación del protocolo. Por defecto es none. Las codificaciones integradas son: "UTF-8", "ISO-8859-1", "UTF-16" y "US-ASCII". Otras codificaciones pueden utilizarse si tienen mapas de codificación en uno de los directorios de la lista @Encoding_Path. Consulte "ENCODINGS" para obtener más información sobre los mapas de codificación. Establecer la codificación del protocolo anula cualquier codificación en la declaración XML.

  • Namespaces

    Esta es una opción de Expat. Si se establece en un valor verdadero, se realiza el procesamiento de espacios de nombres durante el análisis. Consulte "Namespaces" en XML::Parser::Expat para una discusión más detallada del procesamiento de espacios de nombres.

  • NoExpand

    Esta es una opción de Expat. Normalmente, el analizador intentará expandir las referencias a entidades definidas en el subconjunto interno. Si esta opción se establece en un valor verdadero y también se establece un manejador predeterminado, se llamará al manejador predeterminado cuando se vea una referencia a entidad en el texto. Esto no tiene ningún efecto si no se ha registrado un manejador predeterminado, y no tiene ningún efecto en la expansión de referencias a entidades dentro de valores de atributos.

  • Stream_Delimiter

    Esta es una opción de Expat. Toma un valor de cadena. Cuando esta cadena se encuentra sola en una línea mientras se analiza desde un flujo, el análisis se termina como si se hubiera encontrado un fin de archivo. El uso previsto es con un flujo de documentos xml en formato MIME multipart. La cadena no debe contener una nueva línea final.

  • ParseParamEnt

    Esta es una opción de Expat. A menos que standalone se establezca en "yes" en la declaración XML, establecer esto en un valor verdadero permite leer el DTD externo, y que las entidades de parámetros se analicen y expandan.

  • NoLWP

    Esta opción no tiene ningún efecto si los manejadores ExternEnt o ExternEntFin se establecen directamente. De lo contrario, si es verdadero, fuerza el uso de un manejador de entidades externas basado en archivos.

  • Non_Expat_Options

    Si se proporciona, debe ser un hash anónimo cuyas claves sean opciones que no deben pasarse a Expat. Esto solo debería ser de interés para quienes subclasen XML::Parser.

setHandlers(TYPE, HANDLER [, TYPE, HANDLER [...]])
Este método registra manejadores para varios eventos del analizador. Anula cualquier manejador anterior registrado a través de las opciones Style o Handler, o a través de llamadas anteriores a setHandlers. Al proporcionar un valor falso o indefinido como manejador, se puede anular el manejador existente.

Este método devuelve una lista de pares de tipo, manejador que corresponden a la entrada. Los manejadores devueltos son los que estaban en vigor antes de la llamada.

Consulte una descripción de los tipos de manejadores en "HANDLERS".

parse(SOURCE [, OPT => OPT_VALUE [...]])
El parámetro SOURCE debe ser una cadena que contenga todo el documento XML, o debe ser un IO::Handle abierto. Las opciones del constructor para XML::Parser::Expat dadas como pares clave-valor pueden seguir al parámetro SOURCE. Estas anulan, para esta llamada, cualquier opción o atributo pasado desde la instancia de XML::Parser.

Se lanza una llamada a 'die' si ocurre un error de análisis. De lo contrario, devolverá 1 o lo que sea devuelto por el manejador Final, si hay uno instalado. En otras palabras, lo que parse puede devolver depende del estilo.

parsestring
Esto es solo un alias para parse para compatibilidad con versiones anteriores.
parsefile(FILE [, OPT => OPT_VALUE [...]])
Abre FILE para lectura, luego llama a parse con el manejador abierto. El archivo se cierra sin importar cómo devuelva parse. Devuelve lo que devuelve parse.
parse_start([ OPT => OPT_VALUE [...]])
Crea y devuelve una nueva instancia de XML::Parser::ExpatNB. Se pueden proporcionar opciones de constructor. Si se ha proporcionado un manejador de inicialización, se llama antes de devolver el objeto ExpatNB. Los documentos se analizan realizando llamadas incrementales al método parse_more de este objeto, que toma una cadena. Una sola llamada al método parse_done de este objeto, que no toma argumentos, indica que el documento ha finalizado.

Si hay un manejador final instalado, es ejecutado por el método parse_done antes de devolverlo, y el método parse_done devuelve lo que sea que devuelva el manejador final.

-c

Enables character data events. That is, it causes the Char handler to be called for character data.

-d

Causes the Debug handler to be called. This is useful for debugging parsers.

-e

Enables external entity events. That is, it causes the ExternEnt handler to be called for external entities.

-n

Disables the default handler for external entities. This is useful if you want to provide your own handler for external entities and you don't want the default handler to be called as well.

-N

Disables the LWP-based handler for external entities. This is useful if you don't want to use LWP for handling external entities, or if you don't have LWP installed.

-o FILE

Specifies that all output should be written to FILE. By default, output is written to STDOUT.

-s

Enables start tag events. That is, it causes the Start handler to be called for start tags.

-S

Enables end tag events. That is, it causes the End handler to be called for end tags.

-t

Enables processing instruction events. That is, it causes the Proc handler to be called for processing instructions.

-x

Enables comment events. That is, it causes the Comment handler to be called for comments.

-X

Enables CDATA section events. That is, it causes the CdataStart and CdataEnd handlers to be called for CDATA sections.

HANDLERS

Expat is an event based parser. As the parser recognizes parts of the document (say the start or end tag for an XML element), then any handlers registered for that type of an event are called with suitable parameters. All handlers receive an instance of XML::Parser::Expat as their first argument. See "METHODS" in XML::Parser::Expat for a discussion of the methods that can be called on this object.

Init (Expat)

This is called just before the parsing of the document starts.

Final (Expat)

This is called just after parsing has finished, but only if no errors occurred during the parse. Parse returns what this returns.

Start (Expat, Element [, Attr, Val [,...]])

This event is generated when an XML start tag is recognized. Element is the name of the XML element type that is opened with the start tag. The Attr & Val pairs are generated for each attribute in the start tag.

End (Expat, Element)

This event is generated when an XML end tag is recognized. Note that an XML empty tag (<foo/>) generates both a start and an end event.

Char (Expat, String)

This event is generated when non-markup is recognized. The non-markup sequence of characters is in String. A single non-markup sequence of characters may generate multiple calls to this handler. Whatever the encoding of the string in the original document, this is given to the handler in UTF-8.

Proc (Expat, Target, Data)

This event is generated when a processing instruction is recognized.

Comment (Expat, Data)

This event is generated when a comment is recognized.

CdataStart (Expat)

This is called at the start of a CDATA section.

CdataEnd (Expat)

This is called at the end of a CDATA section.

Default (Expat, String)

This is called for any characters that don't have a registered handler. This includes both characters that are part of markup for which no events are generated (markup declarations) and characters that could generate events, but for which no handler has been registered.

Whatever the encoding in the original document, the string is returned to the handler in UTF-8.

Unparsed (Expat, Entity, Base, Sysid, Pubid, Notation)

This is called for a declaration of an unparsed entity. Entity is the name of the entity. Base is the base to be used for resolving a relative URI. Sysid is the system id. Pubid is the public id. Notation is the notation name. Base and Pubid may be undefined.

Notation (Expat, Notation, Base, Sysid, Pubid)

This is called for a declaration of notation. Notation is the notation name. Base is the base to be used for resolving a relative URI. Sysid is the system id. Pubid is the public id. Base, Sysid, and Pubid may all be undefined.

ExternEnt (Expat, Base, Sysid, Pubid)

This is called when an external entity is referenced. Base is the base to be used for resolving a relative URI. Sysid is the system id. Pubid is the public id. Base, and Pubid may be undefined.

This handler should either return a string, which represents the contents of the external entity, or return an open filehandle that can be read to obtain the contents of the external entity, or return undef, which indicates the external entity couldn't be found and will generate a parse error.

If an open filehandle is returned, it must be returned as either a glob (*FOO) or as a reference to a glob (e.g. an instance of IO::Handle).

A default handler is installed for this event. The default handler is XML::Parser::lwp_ext_ent_handler unless the NoLWP option was provided with a true value, otherwise XML::Parser::file_ext_ent_handler is the default handler for external entities. Even without the NoLWP option, if the URI or LWP modules are missing, the file based handler ends up being used after giving a warning on the first external entity reference.

The LWP external entity handler will use proxies defined in the environment (http_proxy, ftp_proxy, etc.).

Please note that the LWP external entity handler reads the entire entity into a string and returns it, where as the file handler opens a filehandle.

Also note that the file external entity handler will likely choke on absolute URIs or file names that don't fit the conventions of the local operating system.

The expat base method can be used to set a basename for relative pathnames. If no basename is given, or if the basename is itself a relative name, then it is relative to the current working directory.

ExternEntFin (Expat)

This is called after parsing an external entity. It's not called unless an ExternEnt handler is also set. There is a default handler installed that pairs with the default ExternEnt handler.

If you're going to install your own ExternEnt handler, then you should set (or unset) this handler too.

Entity (Expat, Name, Val, Sysid, Pubid, Ndata, IsParam)

This is called when an entity is declared. For internal entities, the Val parameter will contain the value and the remaining three parameters will be undefined. For external entities, the Val parameter will be undefined, the Sysid parameter will have the system id, the Pubid parameter will have the public id if it was provided (it will be undefined otherwise), the Ndata parameter will contain the notation for unparsed entities. If this is a parameter entity declaration, then the IsParam parameter is true.

Note that this handler and the Unparsed handler above overlap. If both are set, then this handler will not be called for unparsed entities.

Element (Expat, Name, Model)

The element handler is called when an element declaration is found. Name is the element name, and Model is the content model as an XML::Parser::Content object. See "XML::Parser::ContentModel Methods" in XML::Parser::Expat for methods available for this class.

Attlist (Expat, Elname, Attname, Type, Default, Fixed)

This handler is called for each attribute in an ATTLIST declaration. So an ATTLIST declaration that has multiple attributes will generate multiple calls to this handler. The Elname parameter is the name of the element with which the attribute is being associated. The Attname parameter is the name of the attribute. Type is the attribute type, given as a string. Default is the default value, which will either be "#REQUIRED", "#IMPLIED" or a quoted string (i.e. the returned string will begin and end with a quote character). If Fixed is true, then this is a fixed attribute.

Doctype (Expat, Name, Sysid, Pubid, Internal)

This handler is called for DOCTYPE declarations. Name is the document type name. Sysid is the system id of the document type, if it was provided, otherwise it's undefined. Pubid is the public id of the document type, which will be undefined if no public id was given. Internal is the internal subset, given as a string. If there was no internal subset, it will be undefined. Internal will contain all whitespace, comments, processing instructions, and declarations seen in the internal subset. The declarations will be there whether or not they have been processed by another handler (except for unparsed entities processed by the Unparsed handler). However, comments and processing instructions will not appear if they've been processed by their respective handlers.

* DoctypeFin (Parser)

This handler is called after parsing of the DOCTYPE declaration has finished, including any internal or external DTD declarations.

XMLDecl (Expat, Version, Encoding, Standalone)

This handler is called for xml declarations. Version is a string containing the version. Encoding is either undefined or contains an encoding string. Standalone will be either true, false, or undefined if the standalone attribute is yes, no, or not made respectively.

STYLES

Debug

This just prints out the document in outline form. Nothing special is returned by parse.

Pretty

This prints out the document in a more human-readable format.

XML

This prints out the document as XML. This is the default style.

STYLES

The parser can be instructed to return its results in several different styles. This is controlled by the Style option passed to the constructor.

Subs

Cada vez que un elemento comienza, se llama a un subrutina con ese nombre en el paquete especificado por la opción Pkg, con los mismos parámetros con los que se llama al manejador Start.

Cada vez que un elemento finaliza, se llama a una subrutina con ese nombre, al que se le ha añadido un guion bajo ("_"), con los mismos parámetros con los que se llama al manejador End.

parse no devuelve nada especial.

Tree

Parse devolverá un árbol de análisis para el documento. Cada nodo del árbol tiene la forma de un par etiqueta-contenido. Los nodos de texto se representan con una pseudoetiqueta "0" y la cadena que es su contenido. Para los elementos, el contenido es una referencia a un array. El primer elemento del array es una referencia a un hash (posiblemente vacío) que contiene los atributos. El resto del array es una secuencia de pares etiqueta-contenido que representan el contenido del elemento.

Por ejemplo, el resultado de analizar:

<foo><head id="a">Hello <em>there</em></head><bar>Howdy<ref/></bar>do</foo>

sería:

           Tag   Content
==================================================================
[foo, [{}, head, [{id => "a"}, 0, "Hello ",  em, [{}, 0, "there"]],
            bar, [         {}, 0, "Howdy",  ref, [{}]],
              0, "do"
      ]
]

El documento raíz "foo", tiene 3 hijos: un elemento "head", un elemento "bar" y el texto "do". Después del hash de atributos vacío, estos se representan en su contenido mediante 3 pares etiqueta-contenido.

Objects

Esto es similar al estilo Tree, excepto que se crea un objeto hash para cada elemento. El objeto correspondiente estará en la clase cuyo nombre se crea añadiendo "::" y el nombre del elemento al paquete establecido con la opción Pkg. El texto no marcado estará en la clase ::Characters. El contenido del objeto correspondiente estará en un array anónimo que es el valor de la propiedad Kids para ese objeto.

Stream

Este estilo también utiliza el paquete Pkg. Si ninguna de las subrutinas que este estilo busca está presente, entonces el efecto de analizar con este estilo es imprimir una copia canónica del documento sin comentarios ni declaraciones. Todas las subrutinas reciben como su primer parámetro la instancia de Expat para el documento que están analizando.

Busca las siguientes rutinas:

  • StartDocument

    Se llama al inicio del análisis.

  • StartTag

    Se llama para cada etiqueta de inicio con el tipo de elemento como segundo parámetro. La variable $_ contendrá una copia de la etiqueta y la variable %_ contendrá los valores de los atributos proporcionados para ese elemento.

  • EndTag

    Se llama para cada etiqueta de fin con el tipo de elemento como segundo parámetro. La variable $_ contendrá una copia de la etiqueta de fin.

  • Text

    Se llama justo antes de las etiquetas de inicio o fin con el texto acumulado no marcado en la variable $_.

  • PI

    Se llama para instrucciones de procesamiento. La variable $_ contendrá una copia de la PI y el objetivo y los datos se envían como segundo y tercer parámetros respectivamente.

  • EndDocument

    Se llama al concluir el análisis.

ENCODINGS

Los documentos XML pueden estar codificados en conjuntos de caracteres distintos de Unicode siempre que puedan mapearse al conjunto de caracteres Unicode. Expat tiene restricciones adicionales en las codificaciones. Lea el archivo de cabecera xmlparse.h en la distribución de expat para ver detalles sobre estas restricciones.

Expat tiene codificaciones incorporadas para: "UTF-8", "ISO-8859-1", "UTF-16" y "US-ASCII". Las codificaciones se establecen a través del atributo de codificación de la declaración XML o a través de la opción ProtocolEncoding para XML::Parser o XML::Parser::Expat.

Para codificaciones distintas de las incorporadas, expat llama a la función load_encoding en el paquete Expat con el nombre de la codificación. Esta función busca en la lista de rutas @XML::Parser::Expat::Encoding_Path un archivo que coincida con el nombre en minúsculas con una extensión '.enc'. El primero que encuentra, lo carga.

Si desea crear sus propios mapas de codificación, consulte el módulo XML::Encoding de CPAN.
