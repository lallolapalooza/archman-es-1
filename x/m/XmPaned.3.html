NOMBRE

XmPaned — La clase del widget Paned

SINOPSIS

#include <Xm/Paned.h>

DESCRIPCIÓN

El widget Paned gestiona los hijos en un formato de mosaico vertical u horizontal con cada hijo en un panel separado. Los paneles pueden ser redimensionados dinámicamente por el usuario utilizando "asas de control" que aparecen entre los paneles.

Los programadores de aplicaciones tienen control sobre si se muestran o no las asas y los separadores, el tamaño preferido de cada panel y qué panel se verá obligado a absorber las restricciones de tamaño impuestas por el padre del widget Paned.

Gestión de Geometría

El widget Paned generalmente redimensiona sus hijos a sus tamaños preferidos cuando se gestiona un nuevo hijo. Primero intentará redimensionarse para contener exactamente sus paneles. Si esto no es posible, buscará entre los hijos, de abajo hacia arriba (o de derecha a izquierda), un panel para redimensionar.

El widget Paned intentará honrar la solicitud de geometría de sus hijos. Primero intentará redimensionarse para satisfacer la solicitud y luego seguirá las reglas de diseño a continuación para satisfacer la solicitud. Solo si todos los paneles están en sus valores min/max se rechazará una solicitud de geometría. Si el recurso XmNallowResize es False para el hijo, todas las solicitudes de geometría serán denegadas,
por supuesto.

Consideraciones Especiales

Cuando un usuario redimensiona un panel con las asas, el widget Paned asume que este nuevo tamaño es el tamaño preferido tanto del panel de arriba como del de abajo, a menos que el recurso de restricción XmNresizeToPreferred sea True para ese panel.

Semántica de Diseño

Para hacer un uso efectivo del widget Paned, es útil conocer las reglas que utiliza para determinar qué hijo se redimensionará en cualquier situación dada. Hay tres reglas utilizadas para determinar qué hijo se redimensiona. Si bien estas reglas son siempre las mismas, los paneles que se buscan pueden cambiar dependiendo de lo que causó el cambio de diseño.

Reglas de Diseño

1. No permitir que un panel crezca más allá de su tamaño máximo o más pequeño que su tamaño mínimo. Además, no permitir que un panel sin asa se encoja por debajo de su tamaño preferido debido al movimiento de una empuñadura de otro panel.

2. No ajustar los paneles con XmNskipAdjust establecido.

3. No ajustar los paneles para que se alejen de su tamaño preferido, aunque mover uno más cerca de su tamaño preferido está bien.

Al buscar entre los hijos, el widget Paned busca paneles que cumplan todas las reglas y, si no tiene éxito, elimina la regla 3 y luego la 2. La regla 1 siempre se aplica.

Si la reestructuración se debe a un redimensionamiento o cambio en la gestión, los paneles se buscan de abajo hacia arriba. Si se necesita espacio por encima del asa actual, los paneles se buscan de abajo hacia arriba comenzando por el segundo panel por encima de la empuñadura que se movió. Si se necesita espacio por debajo del asa actual, los paneles se buscan de arriba hacia abajo comenzando por el segundo panel por debajo de la empuñadura que se movió. El widget Paned nunca envuelve el redimensionamiento de sus paneles. Por lo tanto, si se necesita espacio debajo del asa, ningún widget por encima del asa se redimensionará jamás.

Nota: Si la orientación es horizontal, sustituya "derecha" por "abajo" y "izquierda" por "arriba" en el párrafo anterior.

Redimensionamiento de Paneles

Cuando el widget Paned se redimensiona, debe determinar un nuevo tamaño para cada panel. Hay dos métodos para hacerlo. El widget Paned puede dar a cada panel su tamaño preferido y luego redimensionar los paneles para que encajen, o puede usar los tamaños actuales y luego redimensionar los paneles para que encajen. El recurso de restricción XmNresizeToPreferred permite a la aplicación indicar al widget Paned si debe consultar al hijo sobre su tamaño preferido (sujeto a XmNpreferredPaneSize) o usar el tamaño actual al recalcular las ubicaciones de los paneles después de que el widget Paned se haya redimensionado.

Todos los paneles asumen que deben redimensionarse a su tamaño preferido hasta que el widget Paned sea visible para el usuario.

Clases

Paned hereda comportamiento y recursos de las clases Core, Composite, Constraint y Xmmanager.

El puntero de clase de xmPanedWidgetClass.

El nombre de la clase es XmPaned.

XmNallowResize
Permite a una aplicación especificar si el widget Paned debe permitir que un panel solicite ser redimensionado. Este indicador solo tiene efecto después de que el widget Paned y sus hijos se hayan realizado. Si este indicador se establece en True, el widget Paned intenta cumplir las solicitudes para alterar la altura del panel. Si es False, no lo hace.

RESOURCES

The following resources are specific to the Paned widget. Application developers can refer to these resources when setting widget resources.

XmNpaneMaximum
Permite a una aplicación especificar el tamaño máximo al que se puede redimensionar un panel. Este valor debe ser mayor que el mínimo especificado.
XmNpaneMinimum
Permite a una aplicación especificar el tamaño mínimo al que se puede redimensionar un panel. Este valor debe ser mayor que 0 (cero).
XmNskipAdjust
Cuando se establece en True, este recurso booleano permite a una aplicación especificar que el widget Paned no debe redimensionar automáticamente este panel.
XmNpreferredPaneSize
Tamaño preferido del panel. Si este valor no está establecido, el widget paned consultará al hijo para obtener un tamaño preferido. Este recurso permite al usuario o a la aplicación proporcionar un nuevo tamaño preferido.
XmNresizeToPreferred
Especifica si se debe redimensionar cada panel a su tamaño preferido cuando se redimensiona la ventana Paned. Si es False, solo se redimensionarán a su tamaño preferido aquellos paneles que el usuario no haya redimensionado con las barras.
XmNshowSash
Si es True, muestra la barra debajo o a la derecha de este panel.

Rutinas de Acción

Las rutinas de acción de XmPaned son

Help():
Llama a las devoluciones de llamada para XmNhelpCallback si existen. Si no hay devoluciones de llamada de ayuda para este widget, esta acción llama a las devoluciones de llamada de ayuda del ancestro más cercano que las tenga.
NextTabGroup():
Mueve el foco del teclado al siguiente grupo de pestañas. Por defecto, cada panel y cada división son un grupo de pestañas.
PrevTabGroup():
Mueve el foco del teclado al grupo de pestañas anterior. Por defecto, cada panel y cada división son un grupo de pestañas.
SashAction(acción) o SashAction(Key,incremento,dirección):
La acción Start activa la colocación interactiva de los bordes del panel. La acción Move hace que la división siga la posición del puntero. Si uno de los paneles alcanza su tamaño mínimo o máximo, el ajuste continúa con el siguiente panel ajustable. La acción Commit finaliza el movimiento de la división.
Cuando la acción de la división es causada por un evento de teclado, la división con el foco del teclado se mueve de acuerdo con el incremento y la dirección especificados. DefaultIncr ajusta la división en una línea. LargeIncr ajusta la división en una región de vista. La dirección se especifica como Up, Down, Left o Right.
Tenga en cuenta que la rutina de acción SashAction no es una rutina de acción directa de XmPaned, sino más bien una acción del control Sash creado por XmPaned.

Comportamiento Adicional

Este widget tiene el siguiente comportamiento adicional:

<FocusIn>:
Mueve el foco del teclado a la división y la resalta.
<FocusOut>:
Anula el foco del teclado en la división y lo deselecciona.

Bindings Virtuales

Los bindings para las teclas virtuales son específicos del proveedor. Para obtener información sobre los bindings para botones y teclas virtuales, consulte VirtualBindings(3).
