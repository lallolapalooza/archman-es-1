NOMBRE

XmHierarchy — La clase del widget Hierarchy

SINOPSIS

#include <Xm/Hierarchy.h>

DESCRIPCIÓN

El widget Hierarchy no está destinado a ser instanciado en sí mismo, sino que debe usarse como clase base para cualquier widget que desee presentar una jerarquía de información al usuario que sea diferente de la jerarquía de instancias de widget real de la aplicación. Esta clase base se utiliza actualmente para dos widgets en el conjunto de widgets Motif, Tree y Outline, dando a estos dos widgets una API muy similar.

Nota: El widget Hierarchy asume que será totalmente responsable de mapear y desmapear sus hijos. Por lo tanto, ningún hijo de este widget debería modificar jamás su recurso mappedWhenManaged. Si un hijo modifica este recurso, el comportamiento no está definido.

Clases

Hierarchy hereda comportamiento, recursos y rasgos de las clases Core, Composite, Composite, Constraint y XmManager.

El puntero de clase es xmHierarchyWidgetClass.

El nombre de la clase es XmHierarchy.

XmNautoClose
Este recurso determina si la jerarquía debe restaurar automáticamente los hijos de un nodo padre cuando se vuelve a abrir el padre. Si autoClose es False, y la jerarquía está completamente expandida cuando se cierra el nodo raíz, entonces toda la jerarquía se mostrará expandida cuando se vuelva a abrir el nodo raíz. Si autoClose es True, los hijos del nodo raíz se cierran cuando se vuelve a abrir el nodo raíz.
XmNcloseFolderPixmap
Este recurso define un pixmap para la representación cerrada del pixmap de carpeta que se utilizará en todo el árbol. Puede ser un pixmap o un mapa de bits en color. Si el usuario no especifica un pixmap, se utilizará el mapa de bits predeterminado.

Este recurso define un pixmap para la representación abierta del pixmap de carpeta que se utilizará en todo el árbol. Puede ser un pixmap o un mapa de bits en color. Si el usuario no especifica un pixmap, se utilizará el mapa de bits de carpeta abierta predeterminado.
XmNnodeStateCallback
La lista de rutinas de devolución de llamada que se llaman cuando se hace clic en un botón de carpeta. Consulte "Rutina de devolución de llamada" para obtener más detalles.
XmNrefigureMode
Este recurso determina si Hierarchy debe ajustar los tamaños de los hijos después de una solicitud de geometría o redimensionamiento, o simplemente ignorar la solicitud. Este recurso es muy útil para mejorar el rendimiento de una aplicación que realiza un gran número de cambios de geometría a la vez.

RESOURCES

XmNinsertBefore
Especifica otro nodo que tiene el mismo parentNode. Este nodo se colocará inmediatamente antes de ese nodo en la jerarquía. Si este valor es NULL, el nodo se insertará al final de la lista. Este recurso permite reordenar los hijos de la jerarquía.
XmNnodeState
El estado de este nodo. Los valores aceptables son: XmOpen, XmClosed, XmAlwaysOpen y XmHidden. Se ha registrado un convertidor de tipos que puede convertir las siguientes cadenas: "open", "close", "alwaysOpen" y "hidden".
XmNparentNode
El padre jerárquico de este nodo. El nodo padre DEBE ser un widget hermano del nodo actual.

XmHierarchy(3)

NAME

XmHierarchy — A container widget that displays a hierarchy of nodes

SYNOPSIS

#include <Xm/Hierarchy.h>

A hierarchy widget is created by calling:

Widget hierarchy = XmCreateHierarchy(parent, name, arglist, argCount);

DESCRIPTION

The XmHierarchy widget is a container widget that displays a hierarchy of nodes. Each node in the hierarchy can either be a leaf node or a branch node. Branch nodes can be expanded or collapsed to show or hide their children. The hierarchy widget is typically used to display file systems, tree structures, or other hierarchical data.

The XmHierarchy widget provides a way to manage and display a tree-like structure of items. Each item, or node, in the hierarchy can contain other nodes, creating a hierarchical relationship. The widget allows users to interact with this hierarchy, typically by expanding and collapsing branches to view or hide child nodes.

Key features and concepts related to the XmHierarchy widget include:

  • Nodes: The fundamental units of the hierarchy. Nodes can be either leaf nodes (which have no children) or branch nodes (which can contain child nodes).

  • Hierarchy Structure: The arrangement of nodes in a parent-child relationship, forming a tree. A node can have a single parent (except for the root node, which has no parent) and multiple children.

  • Expansion/Collapse: Branch nodes can be in an expanded state (showing their children) or a collapsed state (hiding their children). This allows users to navigate and manage the visibility of information within the hierarchy.

  • Callbacks: The widget supports callback routines that are invoked in response to specific user actions or state changes within the hierarchy. For example, when a node's state changes (e.g., expanded or collapsed), a callback can be triggered.

  • Visual Representation: The XmHierarchy widget provides a visual representation of the tree structure, often using icons and lines to indicate the relationships between nodes and their states.

Callback Information

When a folder is clicked, the routines registered on the XmNnodeStateCallback list are passed a pointer to the following structure as client data:

typedef struct _XmHierarchyNodeStateData {
	Widget widget;
	XmHierarchyNodeState state;
} XmHierarchyNodeStateData;
widget
the child node of Hierarchy being opened or closed.
state
the current XmNnodeState (after the click) of the
node. Legal values are XmOpen, XmClosed, XmAlwaysOpen,
and XmHidden.

Children

The hierarchy maintains IconButtons for each node in the hierarchy. Setting openFolderPixmap or closeFolderPixmap is done through XtSetValues. IconButtons may only be manipulated by the Hierarchy.
