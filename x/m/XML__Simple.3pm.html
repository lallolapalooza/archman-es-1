NAME

XML::Simple - An API for simple XML files

SYNOPSIS

PLEASE DO NOT USE THIS MODULE IN NEW CODE. If you ignore this warning and use it anyway, the qw(:strict) mode will save you a little pain.

use XML::Simple qw(:strict);
my $ref = XMLin([<xml file or string>] [, <options>]);
my $xml = XMLout($hashref [, <options>]);

Or the object oriented way:

require XML::Simple qw(:strict);
my $xs = XML::Simple->new([<options>]);
my $ref = $xs->XMLin([<xml file or string>] [, <options>]);
my $xml = $xs->XMLout($hashref [, <options>]);

(or see "SAX SUPPORT" for 'the SAX way').

Note, in these examples, the square brackets are used to denote optional items not to imply items should be supplied in arrayrefs.

STATUS OF THIS MODULE

The use of this module in new code is strongly discouraged. Other modules are available which provide more straightforward and consistent interfaces. In particular, XML::LibXML is highly recommended and you can refer to Perl XML::LibXML by Example http://grantm.github.io/perl-libxml-by-example/ for a tutorial introduction.

XML::Twig is another excellent alternative.

The major problems with this module are the large number of options (some of which have unfortunate defaults) and the arbitrary ways in which these options interact - often producing unexpected results.

Patches with bug fixes and documentation fixes are welcome, but new features are unlikely to be added.

QUICK START

Say you have a script called foo and a file of configuration options called foo.xml containing the following:

<config logdir="/var/log/foo/" debugfile="/tmp/foo.debug">
  <server name="sahara" osname="solaris" osversion="2.6">
    <address>10.0.0.101</address>
    <address>10.0.1.101</address>
  </server>
  <server name="gobi" osname="irix" osversion="6.5">
    <address>10.0.0.102</address>
  </server>
  <server name="kalahari" osname="linux" osversion="2.0.34">
    <address>10.0.0.103</address>
    <address>10.0.1.103</address>
  </server>
</config>

The following lines of code in foo:

use XML::Simple qw(:strict);
my $config = XMLin(undef, KeyAttr => { server => 'name' }, ForceArray => [ 'server', 'address' ]);

will 'slurp' the configuration options into the hashref $config (because no filename or XML string was passed as the first argument to XMLin() the name and location of the XML file will be inferred from name and location of the script). You can dump out the contents of the hashref using Data::Dumper:

use Data::Dumper;
print Dumper($config);

which will produce something like this (formatting has been adjusted for brevity):

{
    'logdir'        => '/var/log/foo/',
    'debugfile'     => '/tmp/foo.debug',
    'server'        => {
        'sahara'        => {
            'osversion'     => '2.6',
            'osname'        => 'solaris',
            'address'       => [ '10.0.0.101', '10.0.1.101' ]
        },
        'gobi'          => {
            'osversion'     => '6.5',
            'osname'        => 'irix',
            'address'       => [ '10.0.0.102' ]
        },
        'kalahari'      => {
            'osversion'     => '2.0.34',
            'osname'        => 'linux',
            'address'       => [ '10.0.0.103', '10.0.1.103' ]
        }
    }
}

Your script could then access the name of the log directory like this:

print $config->{logdir};

similarly, the second address on the server 'kalahari' could be referenced as:

print $config->{server}->{kalahari}->{address}->[1];

Note: If the mapping between the output of Data::Dumper and the print statements above is not obvious to you, then please refer to the 'references' tutorial (AKA: "Mark's very short tutorial about references") at perlreftut.

In this example, the "ForceArray" option was used to list elements that might occur multiple times and should therefore be represented as arrayrefs (even when only one element is present).

The "KeyAttr" option was used to indicate that each "<server>" element has a unique identifier in the "name" attribute. This allows you to index directly to a particular server record using the name as a hash key (as shown above).

For simple requirements, that's really all there is to it. If you want to store your XML in a different directory or file, or pass it in as a string or even pass it in via some derivative of an IO::Handle, you'll need to check out "OPTIONS". If you want to turn off or tweak the array folding feature (that neat little transformation that produced $config->{server}) you'll find options for that as well.

If you want to generate XML (for example to write a modified version of $config back out as XML), check out XMLout().

If your needs are not so simple, this may not be the module for you. In that case, you might want to read "WHERE TO FROM HERE?".

DESCRIPTION

The XML::Simple module provides a simple API layer on top of an underlying XML parsing module (either XML::Parser or one of the SAX2 parser modules). Two functions are exported: XMLin() and XMLout(). Note: you can explicitly request the lower case versions of the function names: xml_in() and xml_out().

The simplest approach is to call these two functions directly, but an optional object oriented interface (see "OPTIONAL OO INTERFACE" below) allows them to be called as methods of an XML::Simple object. The object interface can also be used at either end of a SAX pipeline.

XMLin()

Parses XML formatted data and returns a reference to a data structure which contains the same information in a more readily accessible form. (Skip down to "EXAMPLES" below, for more sample code).

XMLin() accepts an optional XML specifier followed by zero or more 'name => value' option pairs. The XML specifier can be one of the following:

A filename
If the filename contains no directory components XMLin() will look for the file in each directory in the SearchPath (see "OPTIONS" below) or in the current directory if the SearchPath option is not defined. eg: 
$ref = XMLin('/etc/params.xml');

Note, the filename '-' can be used to parse from STDIN.

undef
If there is no XML specifier, XMLin() will check the script directory and each of the SearchPath directories for a file with the same name as the script but with the extension '.xml'. Note: if you wish to specify options, you must specify the value 'undef'. eg: 
$ref = XMLin(undef, ForceArray => 1);
A string of XML
A string containing XML (recognised by the presence of '<' and '>' characters) will be parsed directly. eg: 
$ref = XMLin('<opt username="bob" password="flurp" />');
An IO::Handle object
An IO::Handle object will be read to EOF and its contents parsed. eg: 
$fh = IO::File->new('/etc/params.xml');
$ref = XMLin($fh);

XMLout()

Takes a data structure (generally a hashref) and returns an XML encoding of that structure. If the resulting XML is parsed using XMLin(), it should return a data structure equivalent to the original (see caveats below).

SAX SUPPORT

XML::Simple can be used as a handler for SAX events. (See the "Handler" option and "SAX SUPPORT" for more details).

When translating hashes to XML, hash keys which have a leading '-' will be silently skipped. This is the approved method for marking elements of a data structure which should be ignored by "XMLout". (Note: If these items were not skipped the key names would be emitted as element or attribute names with a leading '-' which would not be valid XML).

Advertencias

Se requiere cierto cuidado al crear estructuras de datos que se pasarán a XMLout(). Las claves hash de la estructura de datos se codificarán como nombres de elementos XML o nombres de atributos. Por lo tanto, debe usar nombres de claves hash que cumplan con las reglas relativamente estrictas de nombres XML:

Los nombres en XML deben comenzar con una letra. Los caracteres restantes pueden ser letras, dígitos, guiones (-), guiones bajos (_) o puntos (.). También se permite incluir dos puntos (:) en un nombre de elemento, pero esto solo debe usarse cuando se trabaja con espacios de nombres (XML::Simple solo puede funcionar de manera útil con espacios de nombres cuando se combina con un Analizador SAX).

Puede usar otros signos de puntuación en los valores hash (pero no en las claves hash), sin embargo, XML::Simple no admite la exportación de datos binarios.

Si rompe estas reglas, la implementación actual de XMLout() simplemente emitirá XML no conforme que será rechazado si intenta leerlo nuevamente. (Una versión posterior de XML::Simple podría adoptar un enfoque más proactivo).

Tenga en cuenta también que, aunque puede anidar hash y matrices a niveles arbitrarios, las estructuras de datos circulares no son compatibles y harán que XMLout() falle.

Si desea 'transferir' estructuras de datos arbitrarias de Perl a XML y de vuelta a Perl, entonces probablemente debería deshabilitar el plegado de matrices (usando la opción KeyAttr) tanto con XMLout() como con XMLin(). Si aún no obtiene los resultados esperados, puede preferir usar XML::Dumper, que está diseñado exactamente para ese propósito.

Consulte "¿DÓNDE IR DESDE AQUÍ?" si XMLout() es demasiado simple para sus necesidades.

OPCIONES

XML::Simple admite una serie de opciones (de hecho, a medida que cada versión de XML::Simple agrega más opciones, la afirmación del módulo sobre el nombre 'Simple' se vuelve cada vez más tenue). Si se encuentra teniendo que especificar repetidamente las mismas opciones, puede que le interese investigar la "INTERFAZ OO OPCIONAL" a continuación.

Si no tiene ganas de leer la documentación, consulte "MODO ESTRICTO" para detectar automáticamente errores comunes.

Debido a que hay tantas opciones, es difícil para los usuarios nuevos saber cuáles son importantes, así que aquí están las dos que realmente necesita conocer:

  • consulte "ForceArray" porque casi con seguridad querrá activarla
  • asegúrese de saber qué hace la opción "KeyAttr" y cuál es su valor predeterminado porque de lo contrario podría sorprenderle (tenga en cuenta en particular que 'KeyAttr' afecta tanto a "XMLin" como a "XMLout")

Los encabezados de los nombres de las opciones a continuación tienen un 'comentario' final: un hash seguido de dos metadatos:

  • Las opciones están marcadas con 'in' si son reconocidas por XMLin() y 'out' si son reconocidas por XMLout().
  • Cada opción también está marcada para indicar si es: 
    'important'   - no use el módulo hasta que entienda este
'handy'       - puede omitir esto la primera vez
'advanced'    - puede omitir esto la segunda vez
'SAX only'    - no se preocupe por esto a menos que esté usando SAX (o
                alternativamente, si necesita esto, también necesita SAX)
'seldom used' - probablemente nunca usará esto a menos que haya sido la
                persona que solicitó la función

Las opciones se enumeran alfabéticamente:

Nota: los nombres de las opciones ya no distinguen entre mayúsculas y minúsculas, por lo que puede usar las versiones de mayúsculas y minúsculas mixtas que se muestran aquí; todo en minúsculas según lo requieren las versiones 2.03 y anteriores; o puede agregar guiones bajos entre las palabras (por ejemplo, key_attr).

AttrIndent => 1 # out - handy

Cuando esté utilizando XMLout(), habilite esta opción para que los atributos se impriman uno por línea con una sangría sensata en lugar de todos en una sola línea.

Cache => [ esquemas de caché ] # in - advanced

Debido a que cargar el módulo XML::Parser y analizar un archivo XML puede consumir una cantidad significativa de ciclos de CPU, a menudo es deseable almacenar en caché la salida de XMLin() para su reutilización posterior.

Al analizar desde un archivo con nombre, XML::Simple admite una serie de esquemas de caché. La opción 'Cache' se puede utilizar para especificar uno o más esquemas (usando una matriz anónima). Cada esquema se intentará en orden con la esperanza de encontrar una representación pre-analizada en caché del archivo XML. Si no se encuentra una copia en caché, se analizará el archivo y se utilizará el primer esquema de caché de la lista para guardar una copia de los resultados. Se han implementado los siguientes esquemas de caché:

storable
Utiliza Storable.pm para leer/escribir un archivo de caché con el mismo nombre que el archivo XML pero con la extensión .stor
memshare
Cuando un archivo se analiza por primera vez, se retiene una copia de la estructura de datos resultante en la memoria en el espacio de nombres del módulo XML::Simple. Las llamadas posteriores para analizar el mismo archivo devolverán una referencia a esta estructura. Esta versión en caché persistirá solo durante la vida del intérprete de Perl (que en el caso de mod_perl, por ejemplo, puede ser un tiempo considerable).

Debido a que cada llamador recibe una referencia a la misma estructura de datos, un cambio realizado por un llamador será visible para todos. Por esta razón, la referencia devuelta debe tratarse como de solo lectura.

memcopy
Este esquema funciona de manera idéntica a 'memshare' (anterior) excepto que cada llamador recibe una referencia a una nueva estructura de datos que es una copia de la versión en caché. Copiar la estructura de datos agregará una pequeña sobrecarga de procesamiento, por lo que este esquema solo debe usarse donde el llamador tenga la intención de modificar la estructura de datos (o desee protegerse de otros que puedan hacerlo). Este esquema utiliza Storable.pm para realizar la copia.

¡Advertencia! Los esquemas de caché basados en memoria comparan la marca de tiempo del archivo con el momento en que se analizó por última vez. Si el archivo se almacena en un sistema de archivos NFS (u otro recurso compartido de red) y el reloj del servidor de archivos no está exactamente sincronizado con el reloj donde se ejecuta su script, las actualizaciones del archivo XML de origen pueden parecer ignoradas.

ContentKey => 'nombre_clave' # in+out - seldom used

Cuando el contenido de texto se analiza en un valor hash, esta opción le permite especificar un nombre para la clave hash para anular el valor predeterminado 'content'. Así, por ejemplo:

XMLin('<opt one="1">Text</opt>', ContentKey => 'text')

se analizará en:

{ 'one' => 1, 'text' => 'Text' }

en lugar de:

{ 'one' => 1, 'content' => 'Text' }

XMLout() también respetará el valor de esta opción al convertir un hashref a XML.

También puede prefijar su nombre de clave seleccionado con un guion '-' para que XMLin() intente un poco más eliminar las claves 'content' innecesarias después del plegado de matrices. Por ejemplo:

XMLin(
  '<opt><item name="one">First</item><item name="two">Second</item></opt>',
  KeyAttr => {item => 'name'},
  ForceArray => [ 'item' ],
  ContentKey => '-content'
)

se analizará en:

{
  'item' => {
    'one' =>  'First'
    'two' =>  'Second'
  }
}

en lugar de esto (sin el '-'):

{
  'item' => {
    'one' => { 'content' => 'First' }
    'two' => { 'content' => 'Second' }
  }
}

DataHandler => referencia_codigo # in - SAX only

Cuando utiliza un objeto XML::Simple como manejador SAX, devolverá una estructura de datos de 'árbol simple' en el mismo formato que devolvería XMLin(). Si esta opción está configurada (a una referencia de subrutina), entonces cuando se construya el árbol, se llamará a la subrutina y se le pasarán dos argumentos: una referencia al objeto XML::Simple y una referencia al árbol de datos. El valor de retorno de la subrutina se devolverá al controlador SAX. (Ver "SAX SUPPORT" para más detalles).

ForceArray => 1 # in - important

Esta opción debe establecerse en '1' para forzar que los elementos anidados se representen como matrices, incluso cuando solo hay uno. Por ejemplo, con ForceArray habilitado, este XML:

<opt>
  <name>value</name>
</opt>

se analizará en esto:

{
  'name' => [
              'value'
            ]
}

en lugar de esto (el predeterminado):

{
  'name' => 'value'
}

Esta opción es especialmente útil si es probable que la estructura de datos se vuelva a escribir como XML y el comportamiento predeterminado de convertir elementos anidados individuales en atributos no es deseable.

Si está utilizando la función de plegado de matrices, casi con certeza debería habilitar esta opción. Si no lo hace, los elementos anidados individuales no se analizarán como matrices y, por lo tanto, no serán candidatos para el plegado a un hash. (Dado que el valor predeterminado de 'KeyAttr' e

nables el plegado de arreglos, el valor predeterminado de esta opción probablemente también debería haber estado habilitado - lo siento).

ForceArray => [ nombres ] # en - importante

Esta forma alternativa (y preferida) de la opción 'ForceArray' te permite especificar una lista de nombres de elementos que siempre se forzarán a una representación de arreglo, en lugar del enfoque de 'todo o nada' anterior.

También es posible (desde la versión 2.05) incluir expresiones regulares compiladas en la lista; cualquier nombre de elemento que coincida con el patrón se forzará a ser un arreglo. Si la lista contiene solo una expresión regular, no es necesario encerrarla en un arrayref. Por ejemplo:

ForceArray => qr/_list$/

ForceContent => 1 # en - raramente usado

Cuando XMLin() analiza elementos que tienen contenido de texto además de atributos, el contenido de texto debe representarse como un valor hash en lugar de un escalar simple. Esta opción te permite forzar que el contenido de texto siempre se analice como un valor hash, incluso cuando no hay atributos. Por ejemplo:

XMLin('<opt><x>texto1</x><y a="2">texto2</y></opt>', ForceContent => 1)

se analizará como:

{
  'x' => {           'content' => 'texto1' },
  'y' => { 'a' => 2, 'content' => 'texto2' }
}

en lugar de:

{
  'x' => 'texto1',
  'y' => { 'a' => 2, 'content' => 'texto2' }
}

GroupTags => { etiqueta de agrupación => etiqueta agrupada } # entrada/salida - útil

Puedes usar esta opción para eliminar niveles adicionales de indirección en tu estructura de datos Perl. Por ejemplo, este XML:

 <opt>
  <searchpath>
    <dir>/usr/bin</dir>
    <dir>/usr/local/bin</dir>
    <dir>/usr/X11/bin</dir>
  </searchpath>
</opt>

Normalmente se leería en una estructura como esta:

{
  searchpath => {
                  dir => [ '/usr/bin', '/usr/local/bin', '/usr/X11/bin' ]
                }
}

Pero al leerlo con el valor apropiado para 'GroupTags':

my $opt = XMLin($xml, GroupTags => { searchpath => 'dir' });

devolverá esta estructura más simple:

{
  searchpath => [ '/usr/bin', '/usr/local/bin', '/usr/X11/bin' ]
}

El elemento de agrupación ("<searchpath>" en el ejemplo) no debe contener ningún atributo ni elemento que no sea el elemento agrupado.

Puedes especificar múltiples mapeos de 'elemento de agrupación' a 'elemento agrupado' en el mismo hashref. Si esta opción se combina con "KeyAttr", el plegado de arreglos ocurrirá primero y luego se eliminarán los nombres de los elementos agrupados.

"XMLout" también utilizará los mapeos de grouptag para reintroducir las etiquetas alrededor de los elementos agrupados. Sin embargo, ten en cuenta que esto ocurrirá en todos los lugares donde ocurra el nombre de la 'etiqueta de agrupación'; probablemente no quieras usar el mismo nombre para elementos y atributos.

Handler => referencia a objeto # salida - solo SAX

Usa la opción 'Handler' para que XMLout() genere eventos SAX en lugar de devolver una cadena de XML. Para más detalles, consulta "SOPORTE SAX" más abajo.

Nota: la implementación actual de esta opción genera una cadena de XML y utiliza un analizador SAX para traducirla a eventos SAX. Las reglas de codificación normales se aplican aquí: tus datos deben estar codificados en UTF8 a menos que especifiques una codificación alternativa a través de la opción 'XMLDecl'; y para cuando los datos llegan al objeto handler, estarán en formato UTF8 independientemente de la codificación que proporciones. Una implementación futura de esta opción podría generar los eventos directamente.

KeepRoot => 1 # entrada/salida - útil

En su intento de devolver una estructura de datos libre de detalles superfluos y niveles innecesarios de indirección, XMLin() normalmente descarta el nombre del elemento raíz. Establecer la opción 'KeepRoot' a '1' hará que se conserve el nombre del elemento raíz. Así que después de ejecutar este código:

$config = XMLin('<config tempdir="/tmp" />', KeepRoot => 1)

podrás referenciar tempdir como "$config->{config}->{tempdir}" en lugar del predeterminado "$config->{tempdir}".

De manera similar, establecer la opción 'KeepRoot' a '1' le indicará a XMLout() que la estructura de datos ya contiene un nombre de elemento raíz y no es necesario agregar otro.

KeyAttr => [ lista ] # entrada/salida - importante

Esta opción controla la característica de 'plegado de arreglos' que traduce elementos anidados de un arreglo a un hash. También controla el 'desplegado' de hashes a arreglos.

Por ejemplo, este XML:

<opt>
  <user login="grep" fullname="Gary R Epstein" />
  <user login="stty" fullname="Simon T Tyson" />
</opt>

por defecto, se analizaría como esto:

{
  'user' => [
              {
                'login' => 'grep',
                'fullname' => 'Gary R Epstein'
              },
              {
                'login' => 'stty',
                'fullname' => 'Simon T Tyson'
              }
            ]
}

Si se usara la opción 'KeyAttr => "login"' para especificar que el atributo 'login' es una clave, el mismo XML se analizaría como:

{
  'user' => {
              'stty' => {
                          'fullname' => 'Simon T Tyson'
                        },
              'grep' => {
                          'fullname' => 'Gary R Epstein'
                        }
            }
}

Los nombres de los atributos clave deben proporcionarse en un arrayref si hay más de uno. XMLin() intentará hacer coincidir los nombres de los atributos en el orden proporcionado. XMLout() utilizará el primer nombre de atributo proporcionado al 'desplegar' un hash en un arreglo.

Nota 1: El valor predeterminado para 'KeyAttr' es ['name', 'key', 'id']. Si no deseas plegado en la entrada o desplegado en la salida, debes establecer esta opción a una lista vacía para deshabilitar la característica.

Nota 2: Si deseas usar esta opción, también debes habilitar la opción "ForceArray". Sin 'ForceArray', un solo elemento anidado se convertirá en un escalar en lugar de un arreglo y, por lo tanto, no se plegará (ya que solo los arreglos se pliegan).

KeyAttr => { lista } # entrada/salida - importante

Este método alternativo (y preferido) de especificar los atributos clave permite un control más detallado sobre qué elementos se pliegan y en qué atributos. Por ejemplo, la opción 'KeyAttr => { package => 'id' }' hará que cualquier elemento de paquete se pliegue en el atributo 'id'. Ningún otro elemento que tenga un atributo 'id' se plegará en absoluto.

Nota: XMLin() generará una advertencia (o un error fatal en "MODO ESTRICTO") si se utiliza esta sintaxis y se encuentra un elemento que no tiene el atributo clave especificado (por ejemplo, un elemento 'package' sin un atributo 'id', para usar el ejemplo anterior). Las advertencias se pueden suprimir con el pragmático léxico "no warnings;" o "no warnings 'XML::Simple';".

Dos variaciones adicionales son posibles prefijando un carácter '+' o '-' al nombre del atributo:

La opción 'KeyAttr => { user => "+login" }' hará que este XML:

<opt>
  <user login="grep" fullname="Gary R Epstein" />
  <user login="stty" fullname="Simon T Tyson" />
</opt>

se analice como esta estructura de datos:

{
  'user' => {
              'stty' => {
                          'fullname' => 'Simon T Tyson',
                          'login'    => 'stty'
                        },
              'grep' => {
                          'fullname' => 'Gary R Epstein',
                          'login'    => 'grep'
                        }
            }
}

El '+' indica que el valor del atributo clave se copiará en lugar de moverse a la clave hash plegada.

Un prefijo '-' produciría este resultado:

{
  'user' => {
              'stty' => {
                          'fullname' => 'Simon T Tyson',
                          '-login'    => 'stty'
                        },
              'grep' => {
                          'fullname' => 'Gary R Epstein',
                          '-login'    => 'grep'
                        }
            }
}

Como se describió anteriormente, "XMLout" ignorará las claves hash que comiencen con un '-'.

NoAttr => 1 # entrada/salida - útil

Cuando se usa con XMLout(), el XML generado no contendrá atributos. Todas las claves/valores hash se representarán como elementos anidados en su lugar.

Cuando se usa con XMLin(), se ignorarán todos los atributos en el XML.

Opciones

La mayoría de las opciones se pasan como pares de nombre-valor en un hashref al llamar a las rutinas de XMLin() o XMLout().

Variables => { name => value } # en - handy

Esta opción permite que las variables en el XML se expandan cuando se lee el archivo. (No hay facilidad para devolver los nombres de las variables si regeneras XML usando "XMLout").

Una 'variable' es cualquier texto de la forma "${name}" que ocurre en el valor de un atributo o en el contenido de texto de un elemento. Si 'name' coincide con una clave en el hashref proporcionado, "${name}" será reemplazado con el valor correspondiente del hashref. Si no se encuentra ninguna clave coincidente, la variable no se reemplazará. Los nombres deben coincidir con la expresión regular: "[\w.]+" (es decir, solo se permiten caracteres de 'palabra' y puntos).

VarAttr => 'attr_name' # en - handy

Además de las variables definidas usando "Variables", esta opción permite definir variables en el XML. Una definición de variable consiste en un elemento con un atributo llamado 'attr_name' (el valor de la opción "VarAttr"). El valor del atributo se usará como nombre de la variable y el contenido de texto del elemento se usará como valor. Una variable definida de esta manera reemplazará una variable definida usando la opción "Variables". Por ejemplo:

XMLin( '<opt>
          <dir name="prefix">/usr/local/apache</dir>
          <dir name="exec_prefix">${prefix}</dir>
          <dir name="bindir">${exec_prefix}/bin</dir>
        </opt>',
       VarAttr => 'name', ContentKey => '-content'
      );

produce la siguiente estructura de datos:

{
  dir => {
           prefix      => '/usr/local/apache',
           exec_prefix => '/usr/local/apache',
           bindir      => '/usr/local/apache/bin',
         }
}

XMLDecl => 1 or XMLDecl => 'string' # out - handy

Si desea que la salida de XMLout() comience con la declaración XML opcional, simplemente establezca la opción en '1'. La declaración XML predeterminada es:

<?xml version='1.0' standalone='yes'?>

Si desea otra cadena (por ejemplo, para declarar un valor de codificación), establezca el valor de esta opción en la cadena completa que requiera.

INTERFAZ POO OPCIONAL

La interfaz procedural es simple y conveniente, sin embargo, hay un par de razones por las que podría preferir la interfaz orientada a objetos (POO):

  • para definir un conjunto de valores predeterminados que se utilizarán en todas las llamadas posteriores a XMLin() o XMLout()
  • para anular métodos en XML::Simple y proporcionar un comportamiento personalizado

Los valores predeterminados para las opciones descritas anteriormente es poco probable que satisfagan a todos. La interfaz POO le permite anular efectivamente los valores predeterminados de XML::Simple con sus valores preferidos. Funciona de esta manera:

Primero cree un objeto analizador de XML::Simple con sus valores predeterminados preferidos:

my $xs = XML::Simple->new(ForceArray => 1, KeepRoot => 1);

luego llame a XMLin() o XMLout() como un método de ese objeto:

my $ref = $xs->XMLin($xml);
my $xml = $xs->XMLout($ref);

También puede especificar opciones al realizar las llamadas a los métodos y estos valores se fusionarán con los valores especificados cuando se creó el objeto. Los valores especificados en una llamada al método tienen precedencia.

Nota: cuando se llaman como métodos, las rutinas XMLin() y XMLout() pueden llamarse como xml_in() o xml_out(). Los nombres de los métodos son alias, por lo que la única diferencia es la estética.

Métodos de Análisis

Puede llamar explícitamente a uno de los siguientes métodos en lugar de depender de que el método xml_in() determine automáticamente si el objetivo a analizar es una cadena, un archivo o un manejador de archivos:

parse_string(text)
Funciona exactamente como el método xml_in() pero asume que el primer argumento es una cadena de XML (o una referencia a un escalar que contiene una cadena de XML).
parse_file(filename)
Funciona exactamente como el método xml_in() pero asume que el primer argumento es el nombre de un archivo que contiene XML.
parse_fh(file_handle)
Funciona exactamente como el método xml_in() pero asume que el primer argumento es un manejador de archivos del que se puede leer para obtener XML.

Métodos Hook

Puede crear su propia clase que herede de XML::Simple y anule ciertos comportamientos. Los siguientes métodos pueden proporcionar útiles 'hooks' en los que basar su comportamiento modificado. Puede encontrar otros métodos no documentados examinando el código fuente, pero estos pueden estar sujetos a cambios en futuras versiones.

new_xml_parser()
Este método se llamará cuando deba construirse un nuevo objeto XML::Parser (ya sea porque XML::SAX no está instalado o se prefiere XML::Parser).
handle_options(direction, name => value ...)
Este método se llamará cuando se llame a uno de los métodos de análisis o al método XMLout(). El argumento inicial será una cadena (ya sea 'in' o 'out') y los argumentos restantes serán pares nombre-valor.
default_config_file()
Calcula y devuelve el nombre del archivo que debe ser analizado si no se pasa ningún nombre de archivo a XMLin() (por defecto: "$0.xml").
build_simple_tree(filename, string)
Se llama desde XMLin() o cualquiera de los métodos de análisis. Toma un nombre de archivo como primer argumento o "undef" seguido de una 'cadena' como segundo argumento. Devuelve una estructura de datos de árbol simple. Podría anular este método para aplicar sus propias transformaciones antes de que la estructura de datos sea devuelta al llamador.
new_hashref()
Cuando se está construyendo la estructura de datos del 'árbol simple', este método se llamará para crear los hashrefs anónimos requeridos.
sorted_keys(name, hashref)
Se llama cuando XMLout() está traduciendo un hashref a XML. Esta rutina devuelve una lista de claves de hash en el orden en que los atributos/elementos correspondientes deben aparecer en la salida.
escape_value(string)
Se llama desde XMLout(), toma una cadena y devuelve una copia de la cadena con las reglas de escape de caracteres XML aplicadas.
escape_attr(string)
Se llama desde XMLout(), para manejar valores de atributos. Por defecto, simplemente llama a escape_value(), pero puede anular este método si desea que los atributos se escapen de manera diferente al contenido de texto.
numeric_escape(string)
Se llama desde escape_value(), para manejar caracteres no ASCII (dependiendo del valor de la opción NumericEscape).
copy_hash(hashref, extra_key => value, ...)
Se llama desde XMLout(), al 'desplegar' un hash de hashes en un array de hashes. Es posible que desee anular este método si está utilizando hashes enlazados y no desea que se desvinculen.

Métodos de Caché

XML::Simple implementa tres esquemas de caché ('storable', 'memshare' y 'memcopy'). Puede implementar un esquema de caché personalizado implementando dos métodos: uno para leer de la caché y otro para escribir en ella.

Por ejemplo, podría implementar un nuevo esquema 'dbm' que almacene estructuras de datos en caché utilizando el módulo MLDBM. Primero, agregaría un método cache_read_dbm() que aceptara un nombre de archivo para usarlo como clave de búsqueda y devolviera una estructura de datos en caso de éxito, o undef en caso de fallo. Luego, implementaría un método cache_read_dbm() que aceptara una estructura de datos y un nombre de archivo.

Usaría este esquema de caché especificando la opción:

Cache => [ 'dbm' ]

MODO ESTRICTO

Si importa las rutinas de XML::Simple de esta manera:

use XML::Simple qw(:strict);

los siguientes errores comunes se detectarán y se tratarán como errores fatales:

  • No establecer explícitamente la opción "KeyAttr": si no le apetece leer sobre esta opción, desactívela con: KeyAttr => [ ]
  • No establecer explícitamente la opción "ForceArray": si no le apetece leer sobre esta opción, configúrela en el modo más seguro con: ForceArray => 1
  • Establecer ForceArray en un array, pero no listar todos los elementos del hash KeyAttr.
>Error de datos - La clave Attr está configurada para decir { part => 'partnum' } pero el XML contiene uno o más elementos sin un atributo 'partnum' (o elemento anidado). Nota: si el modo estricto no está configurado pero "use warnings;" está en vigor, esta condición activa una advertencia.
  • Error de datos - como el anterior, pero hay valores no únicos en la clave atributo (ej: más de un elemento con el mismo partnum). Esto también activará una advertencia si el modo estricto no está habilitado.
  • Error de datos - como el anterior, pero el valor del atributo clave (ej: partnum) no es una cadena escalar (debido a elementos anidados, etc.). Esto también activará una advertencia si el modo estricto no está habilitado.

    • SOPORTE SAX

    Desde la versión 1.08_01, XML::Simple incluye soporte para SAX (la Simple API para XML) - específicamente SAX2.

    En una aplicación SAX típica, un analizador XML (o módulo 'driver' de SAX) genera eventos SAX (inicio de elemento, datos de caracteres, fin de elemento, etc.) a medida que analiza un documento XML y un módulo 'handler' procesa los eventos para extraer los datos requeridos. Este modelo simple permite algunas posibilidades interesantes y potentes:

    • Las aplicaciones escritas para la API SAX pueden extraer datos de documentos XML enormes sin la sobrecarga de memoria de una API DOM o de árbol.
    • La API SAX permite el intercambio plug and play de módulos analizadores sin tener que cambiar su código para adaptarse a la API de un nuevo módulo. Un número de analizadores SAX están disponibles con capacidades que van desde la portabilidad extrema hasta un rendimiento muy rápido.
    • Un módulo 'filter' de SAX puede implementar tanto una interfaz handler para recibir datos como una interfaz generadora para pasar datos modificados a un handler posterior. Los filtros se pueden encadenar en 'pipelines'.
    • Un módulo filtro podría dividir un flujo de datos para dirigir datos a dos o más handlers posteriores.
    • La generación de eventos SAX no es dominio exclusivo de los módulos de análisis de XML. Por ejemplo, un módulo podría extraer datos de una base de datos relacional usando DBI y pasarlos a un pipeline SAX para filtrado y formato.

    XML::Simple puede operar en cualquiera de los extremos de un pipeline SAX. Por ejemplo, puede tomar una estructura de datos en forma de hashref y pasarla a un pipeline SAX usando la opción 'Handler' en XMLout():

    use XML::Simple;
use Some::SAX::Filter;
use XML::SAX::Writer;
my $ref = {
             ....   # sus datos aquí
          };
my $writer = XML::SAX::Writer->new();
my $filter = Some::SAX::Filter->new(Handler => $writer);
my $simple = XML::Simple->new(Handler => $filter);
$simple->XMLout($ref);

    También puede colocar XML::Simple en el extremo opuesto del pipeline para aprovechar la simple estructura de datos de 'árbol' una vez que los datos relevantes se han aislado a través del filtrado:

    use XML::SAX;
use Some::SAX::Filter;
use XML::Simple;
my $simple = XML::Simple->new(ForceArray => 1, KeyAttr => ['partnum']);
my $filter = Some::SAX::Filter->new(Handler => $simple);
my $parser = XML::SAX::ParserFactory->parser(Handler => $filter);
my $ref = $parser->parse_uri('some_huge_file.xml');
print $ref->{part}->{'555-1234'};

    Puede construir un filtro utilizando un objeto XML::Simple como handler y configurando su opción DataHandler para que apunte a una rutina que tome el árbol resultante, lo modifique y lo envíe como eventos SAX a un handler posterior:

    my $writer = XML::SAX::Writer->new();
my $filter = XML::Simple->new(
               DataHandler => sub {
                                my $simple = shift;
                                my $data = shift;
                                # Modificar $data aquí
                                $simple->XMLout($data, Handler => $writer);
                              }
             );
my $parser = XML::SAX::ParserFactory->parser(Handler => $filter);
$parser->parse_uri($filename);

    Nota: En este último ejemplo, la opción 'Handler' se especificó en la llamada a XMLout() pero también podría haberse especificado en el constructor.

    ENTORNO

    Si no le importa qué módulo analizador usa XML::Simple, omita esta sección por completo (parece más complicado de lo que realmente es).

    XML::Simple usará por defecto un analizador SAX si hay uno disponible o XML::Parser si SAX no está disponible.

    Puede dictar qué módulo analizador se utiliza configurando la variable de entorno 'XML_SIMPLE_PREFERRED_PARSER' o la variable del paquete $XML::Simple::PREFERRED_PARSER para que contenga el nombre del módulo. Se utilizan las siguientes reglas:

    • La variable del paquete tiene prioridad sobre la variable de entorno si ambas están definidas. Para forzar que XML::Simple ignore la configuración del entorno y utilice sus reglas predeterminadas, puede establecer la variable del paquete en una cadena vacía.
    • Si el 'parser preferido' se establece en la cadena 'XML::Parser', entonces se utilizará XML::Parser (o XMLin() fallará si XML::Parser no está instalado).
    • Si el 'parser preferido' se establece en algún otro valor, se asume que es el nombre de un módulo analizador SAX y se pasa a XML::SAX::ParserFactory. Si XML::SAX no está instalado, o el módulo analizador solicitado no está instalado, entonces XMLin() fallará.
    • Si el 'parser preferido' no está definido en absoluto (el estado predeterminado normal), se intentará cargar XML::SAX. Si XML::SAX está instalado, se seleccionará un módulo analizador según las reglas normales de XML::SAX::ParserFactory (lo que normalmente significa el último analizador SAX instalado).
    • Si el 'parser preferido' no está definido y XML::SAX no está instalado, entonces se utilizará XML::Parser. XMLin() fallará si XML::Parser no está instalado.

    Nota: La distribución XML::SAX incluye un analizador XML escrito completamente en Perl. Es muy portable pero no muy rápido. Debería considerar instalar XML::LibXML o XML::SAX::Expat si están disponibles para su plataforma.

    MANEJO DE ERRORES

    El estándar XML es muy claro sobre el tema de los documentos no conformes. Un error al analizar cualquier elemento (por ejemplo, una etiqueta de cierre faltante) debe hacer que todo el documento sea rechazado. XML::Simple fallará con un mensaje apropiado si encuentra un error de análisis.

    Si fallar no es apropiado para su aplicación, debe organizar la llamada a XMLin() dentro de un bloque eval y buscar errores en $@. Por ejemplo:

    my $config = eval { XMLin() };
PopUpMessage($@) if($@);

    Nota, existe una idea errónea común de que el uso de eval ralentizará significativamente un script. Si bien eso puede ser cierto cuando el código que se evalúa está en una cadena, no es cierto para código como el ejemplo anterior.

    EJEMPLOS

    Cuando XMLin() lee el siguiente ejemplo muy simple de XML:

    <

    devuelve la siguiente estructura de datos:

    {
  'username' => 'testuser',
  'password' => 'frodo'
}

    El mismo resultado podría haberse producido con este XML alternativo:

    <

    O esto (aunque vea la opción 'ForceArray' para variaciones):

    <
  testuser
  frodo

    Los elementos anidados repetidos se representan como arrays anónimos:

    <
  
    joe@smith.com
    jsmith@yahoo.com
  
  
    bob@smith.com
  

{
  'person' => [
                {
                  'email' => [
                               'joe@smith.com',
                               'jsmith@yahoo.com'
                             ],
                  'firstname' => 'Joe',
                  'lastname' => 'Smith'
                },
                {
                  'email' => 'bob@smith.com',
                  'firstname' => 'Bob',
                  'lastname' => 'Smith'
                }
              ]
}

    Los elementos anidados con un atributo clave reconocido se transforman (se "pliegan") de un array a un hash indexado por el valor de ese atributo (vea la opción "KeyAttr"):

    <
  
  
  

{
  'person' => {
                'jbloggs' => {
                               'firstname' => 'Joe',
                               'lastname' => 'Bloggs'
                             },
                'tsmith' => {
                              'firstname' => 'Tom',
                              'lastname' => 'Smith'
                            },
                'jsmith' => {
                              'firstname' => 'Joe',
                              'lastname' => 'Smith'
                            }
              }
}

    La etiqueta se puede utilizar para formar arrays anónimos:

    <
  Col 1Col 2Col 3
  R1C1R1C2R1C3
  R2C1R2C2R2C3
  R3C1R3C2R3C3

{
  'head' => [
              [ 'Col 1', 'Col 2', 'Col 3' ]
            ],
  'data' => [
              [ 'R1C1', 'R1C2', 'R1C3' ],
              [ 'R2C1', 'R2C2', 'R2C3' ],
              [ 'R3C1', 'R3C2', 'R3C3' ]
            ]
}

    Los arrays anónimos pueden anidarse a niveles arbitrarios y, como caso especial, si las etiquetas circundantes para un documento XML contienen solo un array anónimo, el arrayref se devolverá directamente en lugar del usual hashref:

    <
  Col 1Col 2
  R1C1R1C2
  R2C1R2C2


    

    

    DESCRIPCIÓN
    

    Con XML::Simple, los elementos de una tabla
    o de una lista se representan como arrays de Perl. Por ejemplo:
    

    <table>
  <row>
    <col 1>1</col 1>
    <col 2>2</col 2>
  </row>
  <row>
    <col 1>3</col 1>
    <col 2>4</col 2>
  </row>
</table>

    

    se convierte en:
    

    {
  'table' => [
    {
      'row' => [
        { 'col 1' => '1', 'col 2' => '2' },
        { 'col 1' => '3', 'col 2' => '4' }
      ]
    }
  ]
}

    

    Si los elementos de una tabla o fila no tienen atributos, se
    simplifican como un array:
    

    <table>
  <row>
    <col 1>R1C1</col 1>
    <col 2>R1C2</col 2>
  </row>
  <row>
    <col 1>R2C1</col 1>
    <col 2>R2C2</col 2>
  </row>
</table>
    

    se convierte en:
    

    {
  'table' => [
    [ 'R1C1', 'R1C2' ],
    [ 'R2C1', 'R2C2' ]
  ]
}

    

    Los elementos que solo contienen contenido de texto se representarán
    simplemente como un escalar. Cuando un elemento tiene tanto atributos como
    contenido de texto, el elemento se representará como un hashref con el
    contenido de texto en la clave 'content' (ver la opción
    "ContentKey"):
    

    <opt>
  <one>first</one>
  <two attr="value">second</two>
</opt>
{
  'one' => 'first',
  'two' => { 'attr' => 'value', 'content' => 'second' }
}
    

    El contenido mixto (elementos que contienen tanto contenido de
    texto como elementos anidados) no se representará de manera útil: se
    perderá el orden de los elementos y los espacios en blanco significativos.
    Si necesita trabajar con contenido mixto, entonces XML::Simple no es la
    herramienta adecuada para su trabajo; consulte la siguiente sección.
    

    

    

    ¿A DÓNDE IR DESDE AQUÍ?
    

    XML::Simple puede presentar una API simple porque hace
    algunas suposiciones por usted. Estas incluyen:
    

      
  
    • No está interesado en el contenido de texto que consiste solo en espacios
    en blanco
      • 
  
    • No le importa que cuando las cosas se absorban en un hash, se pierda el
    orden
      • 
  
    • No desea un control detallado del formato del XML generado
      • 
  
    • Nunca usaría una clave de hash que no sea un nombre de elemento XML
    legal
      • 
  
    • No necesita ayuda para convertir entre diferentes codificaciones
      • 

    

    En un proyecto XML serio, probablemente superará estas
    suposiciones con bastante rapidez. Esta sección del documento solía ofrecer
    algún consejo sobre cómo elegir una opción más potente. Ese consejo se ha
    convertido ahora en el documento 'Preguntas Frecuentes de Perl-XML', que puede
    encontrar en:
    http://perl-xml.sourceforge.net/faq/
    

    El consejo de las preguntas frecuentes se reduce a una breve
    explicación de los analizadores basados en árboles frente a los basados en
    eventos y luego recomienda:
    

    Para el análisis basado en eventos, use SAX (no se proponga
    escribir código nuevo para la API de manejadores de XML::Parser, está
    obsoleta).
    

    Para el análisis basado en árboles, podría elegir entre el enfoque
    'Perlish' de XML::Twig y las implementaciones DOM más basadas en estándares,
    preferiblemente una con soporte XPath como XML::LibXML.
    

    

    

    VER TAMBIÉN
    

    XML::Simple requiere XML::Parser o XML::SAX.
    

    Para generar documentos con espacios de nombres, se requiere
    XML::NamespaceSupport.
    

    Las funciones opcionales de caché requieren Storable.
    

    Las respuestas a las preguntas frecuentes sobre XML::Simple se
    incluyen con esta distribución como: XML::Simple::FAQ
