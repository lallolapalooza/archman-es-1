NOMBRE

XmNotebook — La clase del widget Notebook

SINOPSIS

#include <Xm/Notebook.h>

DESCRIPCIÓN

Notebook es un widget gestor que organiza sus hijos en páginas, pestañas, áreas de estado y desplazadores de página para simular un cuaderno real. Apila sus hijos de página de modo que todos los hijos de página ocupen la misma área, como las páginas de un libro real. Notebook muestra elementos visuales que se asemejan al lomo de un libro y los bordes de otras páginas alrededor de la página que se muestra. Los hijos de pestaña simulan las pestañas del cuaderno. Las pestañas principales dividen Notebook en varias secciones, y las pestañas secundarias subdividen estas secciones. Los hijos del área de estado proporcionan información adicional sobre las páginas, como los números de página. El hijo del desplazador de página permite al usuario moverse de una página a otra. Notebook también proporciona desplazadores de pestañas para desplazar las pestañas principales y secundarias si no puede mostrar todas las pestañas dentro de sus bordes.

La aplicación crea páginas, pestañas, áreas de estado y el desplazador de página como hijos del widget Notebook. Notebook crea los desplazadores de pestañas cuando se crea el Notebook.

El recurso de restricción XmNnotebookChildType de Notebook determina si un widget hijo es una página, una pestaña, un área de estado o un desplazador de página. Cualquier widget de Motif puede ser una página de Notebook. Cuando la aplicación crea un hijo del widget Notebook sin establecer el tipo de hijo de restricción, el hijo se convierte en una página por defecto, a menos que tenga el rasgo XmQTactivatable, XmQTaccessTextual o XmQTnavigator. Los hijos con los rasgos XmQTactivatable, XmQTaccessTextual o XmQTnavigator se convierten en pestañas principales, áreas de estado y desplazadores de página, respectivamente.

Notebook utiliza los rasgos XmQTaccessTextual, XmQTactivatable, XmQTjoinSide y XmQTnavigator, e instala el rasgo XmQTscrollFrame.

La aplicación une una pestaña a una página creando un hijo de pestaña de Notebook y estableciendo la restricción XmNpageNumber al número de página de la página objetivo. Por el mismo método, un widget de área de estado puede unirse a una página. El hijo del desplazador de página, por otro lado, está asociado con el Notebook, no con una página específica. Por lo tanto, solo hay un desplazador de página válido para cada Notebook.

Páginas

Notebook solo muestra un hijo de tipo XmPAGE a la vez. Otros hijos de página se ocultan fuera de la pantalla. Cuando Notebook muestra una página en particular, posiciona la página mostrada anteriormente fuera de la pantalla y pone la nueva página en su lugar. La página se redimensiona para ajustarse a las dimensiones que Notebook ha asignado para mostrar páginas.

Números de Página

Notebook utiliza los recursos XmNcurrentPageNumber, XmNfirstPageNumber y XmNlastPageNumber para determinar la página actual y el rango de números de página disponibles. Solo se pueden mostrar aquellas páginas cuyos números de página estén dentro del rango. Otras páginas no se pueden mostrar hasta que el rango entre XmNfirstPageNumber y XmNlastPageNumber se cambie para incluirlas o hasta que los números de página se cambien a un número dentro del rango.

Si XmNfirstPageNumber y XmNlastPageNumber no son establecidos explícitamente por la aplicación, se establecen en 1 por defecto; Notebook establece XmNlastPageNumber al número de página más grande asignado por la aplicación posteriormente por defecto. Sin embargo, una vez que XmNlastPageNumber es establecido por la aplicación, Notebook ya no lo cambia, incluso cuando se gestiona una página con un número de página mayor.

El recurso de restricción XmNpageNumber se utiliza para especificar el número de página de un widget de página. Puede establecerse a cualquier entero. Para hijos de pestaña y área de estado, el recurso se utiliza para vincular el widget hijo a una página. Para el hijo del desplazador de página, el recurso no tiene significado y es ignorado por Notebook.

Cuando se gestiona una página sin número de página, Notebook le asigna el número de página no asignado más pequeño que no sea menor que el primer número de página y mayor que el último número de página asignado. Cuando se gestiona una pestaña o un área de estado sin número de página, al widget recién gestionado se le asigna el número de página de la página gestionada más recientemente, a menos que la página ya tenga el mismo tipo de hijo. Si la página ya tiene el mismo tipo de hijo, Notebook asigna al widget recién gestionado un número de página uno mayor que la página gestionada más recientemente; este nuevo número de página ahora está ocupado. Notebook puede generar un número de página por defecto mayor que XmNlastPageNumber, haciendo que esas páginas sean inaccesibles para el usuario.

Páginas Duplicadas y Vacías

Dado que una aplicación puede crear o cambiar números de página, es posible tener números de página duplicados y páginas vacías. Cuando se gestionan dos páginas con el mismo número de página, solo la página gestionada más recientemente puede mostrarse. Insertar una página con un número de página existente no genera una advertencia. El widget de página antiguo no se puede mostrar hasta que el widget de página nuevo se elimine de Notebook o hasta que el número de página del widget de página antiguo se cambie a algún otro número.

Una página vacía es un espacio de página donde no se inserta ninguna página. Las páginas vacías ocurren cuando una pestaña o un área de estado está asociada con un número de página que no tiene un widget de página coincidente. Las páginas vacías muestran el fondo en blanco de Notebook, a menos que la aplicación proporcione información visual a esta área vacía mientras procesa XmNpageChangedCallback.

Elementos Visuales de Notebook

Notebook dibuja líneas alrededor de dos lados de la página superior para simular los bordes de otras páginas que están detrás de la página superior. Los recursos XmNbackPagePlacement y XmNorientation determinan qué dos lados tienen las líneas dibujadas alrededor. Por defecto, se dibujan en los lados inferior y derecho de la página superior. La aplicación puede establecer recursos para controlar cuántas líneas se dibujan y cuán ancho es el área en la que se dibujan. Las aplicaciones también pueden elegir entre tres estilos de lomo visual que simulan el lomo de un Notebook. Se pueden dibujar lomos sólidos o en espiral por Notebook, o la aplicación puede proporcionar un pixmap que se tesela en el lomo.

Pestañas

Una pestaña principal o secundaria es un widget de Motif con el rasgo XmQTactivatable. Si se crea un widget sin el rasgo para una pestaña, Notebook no proporciona la devolución de llamada de activación de página. Como resultado, aunque la pestaña se muestre, no puede mover automáticamente la página asociada a la parte superior.

Las pestañas principales dividen las páginas de Notebook en secciones. Las pestañas secundarias subdividen estas secciones. Solo se muestran las pestañas secundarias asociadas con la sección actual, donde una sección consta del grupo de páginas entre la pestaña principal actual y la siguiente pestaña principal, incluida la pestaña principal actual pero sin incluir la página que contiene la siguiente pestaña principal. La excepción a esto es cuando no hay una pestaña principal precedente, en cuyo caso la sección comienza desde el valor XmNfirstPageNumber. Un usuario en una sección de pestaña principal no ve las pestañas secundarias en otras secciones. Sin embargo, todas las pestañas se utilizan en el cálculo del tamaño de Notebook.

A diferencia de las pestañas normales de cuaderno, las pestañas en Notebook no están unidas a una página física (un widget). Están, en cambio, unidas a una página lógica (un número de página). Por lo tanto, es posible tener una pestaña con una página vacía. Cuando una página con una pestaña se elimina de Notebook, la pestaña no se elimina porque todavía está vinculada a una página lógica. Destruir o desgestionar un widget de página solo borra la página y deja una página vacía. No arranca la página del Notebook. Para eliminar la pestaña, la aplicación debe destruirla o desgestionarla explícitamente.

Notebook admite el rasgo XmQTjoinSide. Un widget que tiene el rasgo XmQTjoinSide se puede agregar a Notebook como una pestaña Principal o Secundaria y aparecerá unido a su página asociada sin márgenes ni sombras entre ellos.

Áreas de Estado

Un área de estado es cualquier widget que se utiliza para describir la página asociada. Por ejemplo, el widget Label como hijo de área de estado puede contener una cadena simple o un pixmap que describe una página. Un widget de área de estado también se une a una página mediante el recurso de restricción de número de página. Por lo tanto, es posible tener múltiples widgets de área de estado para una página. Solo el widget de área de estado gestionado más recientemente para esa página puede mostrarse.

Otros para esa página no están desgestionados, pero sus tamaños se utilizan para calcular el tamaño del Cuaderno. Si no se proporciona ningún widget de área de estado, el Cuaderno muestra su fondo en blanco en el espacio reservado del área de estado. El Cuaderno no crea ningún widget de área de estado predeterminado.

Desplazadores de Página

El desplazador de página del Cuaderno es cualquier widget que la aplicación cree para desplazar páginas. Si la aplicación no crea uno al realizar el Cuaderno, el Cuaderno crea un widget SpinBox como desplazador de página predeterminado. Si la aplicación crea un nuevo desplazador de página, el desplazador de página predeterminado se destruye. Si la aplicación crea varios desplazadores de página, solo se puede mostrar y utilizar el último gestionado. Todos los demás quedan desgestionados.

El SpinBox desplazador de página predeterminado atenúa uno de los elementos visuales de flecha si la página actual es una página límite. Si la página actual es la primera página, la flecha anterior del SpinBox se atenúa. Si la página actual es la última página, la flecha siguiente del SpinBox se atenúa.

Desplazadores de Pestañas

Los desplazadores de pestañas son creados por el Cuaderno para desplazar pestañas principales y pestañas secundarias. Cuando se inicializa el Cuaderno, crea cuatro ArrowButtonGadgets para desplazarse a la siguiente pestaña principal, la pestaña principal anterior, la pestaña secundaria siguiente y la pestaña secundaria anterior. La aplicación no puede reemplazar estos desplazadores de pestañas. La aplicación puede cambiar todos los recursos de estos widgets excepto la posición y la dirección de la flecha. Los desplazadores de pestañas solo son visibles y están habilitados cuando no hay suficiente espacio para mostrar todas las pestañas principales o secundarias apropiadas para la página. Los desplazadores de pestañas también se atenúan cuando el desplazamiento no es apropiado. La siguiente tabla enumera los desplazadores de pestañas que se crean:

Cuando el usuario selecciona el desplazador de página, una pestaña principal o una pestaña secundaria, el valor de XmNcurrentPageNumber se cambia al número de página seleccionado y se invoca XmNpageChangedCallback. Después de que la aplicación regrese del callback, el Cuaderno muestra el último hijo de página cuyo número de página es igual al número de página actual. También muestra el último hijo de área de estado coincidente. Todas las demás páginas y áreas de estado se ocultan automáticamente. Las pestañas principales y secundarias que caben en los bordes del Cuaderno se muestran y se posicionan apropiadamente. Todas las demás pestañas también se ocultan. La aplicación también puede provocar un cambio de página llamando a XtSetValues en XmNcurrentPageNumber y luego llamando a XtCallCallbacks en XmNpageChangedCallback.

Orientación

El Cuaderno tiene ocho configuraciones visuales diferentes, según el valor de XmNbackPagePlacement y XmNorientation. Estos dos recursos determinan la colocación de las páginas traseras, el encuadernado, las pestañas principales, las pestañas secundarias, el área de estado y el desplazador de página. La ubicación del encuadernado está determinada por XmNorientation. Las pestañas principales siempre se colocan en el lado de la página trasera opuesto al encuadernado; las pestañas secundarias se colocan en el área de visualización de la página trasera que está visualmente conectada al encuadernado. Tanto las pestañas principales como las secundarias se ordenan de modo que los números de página a los que acceden aumenten a medida que se acercan a la esquina donde se encuentran las páginas traseras. El área de estado y el desplazador de página siempre se encuentran en la parte inferior del Cuaderno, dentro del marco. El desplazador de página siempre se coloca adyacente a un lado de la página trasera. Clases

Notebook hereda el comportamiento, los recursos y los rasgos de las clases Core, Composite, Constraint y XmManager.

El puntero de la clase es xmNotebookWidgetClass.

El nombre de la clase es XmNotebook.

Nuevos Recursos

La siguiente tabla define un conjunto de recursos de widgets utilizados por el programador para especificar datos. El programador también puede establecer los valores de los recursos para las clases heredadas para establecer atributos para este widget. NAME

XmNotebook widget, XmNotebook

SYNOPSIS

A notebook widget displays a collection of pages, each of which can contain other widgets. The notebook widget allows the user to select which page to view at any given time. Each page is identified by a tab that is displayed along one edge of the notebook widget. The user can select a page by clicking on its tab. The notebook widget provides a mechanism for traversing through the pages of the notebook using the keyboard.

#include <Xm/Notebook.h>

DESCRIPTION

The XmNotebook widget provides a multi-page notebook interface. The widget manages a collection of child widgets, where each child widget represents a page in the notebook. Only one page is visible at a time. The XmNotebook widget provides tabs or other mechanisms for switching between pages.

WIDGET CREATION

The XmNotebook widget is created by:

Widget notebook = XmCreateNotebook(parent, name, arglist, argcount);

Callback

A pointer to the following structure is passed to callbacks for XmNpageChangedCallback.

typedef struct
{
        int reason;
        XEvent *event;
        int page_number;
        Widget page_widget;
        int prev_page_number;
        Widget prev_page_widget;
} XmNotebookCallbackStruct;
reason
Specifies the reason for the callback.
event
Points to the XEvent that triggered the callback. It can be NULL.
page_number
Indicates the page number to be displayed.
page_widget
Indicates the page widget that has the new page number. It is NULL if no page widget with the page number is found.
prev_page_number
Indicates the page number of the currently displayed page. If the callback procedure is being called at widget initialization, this page number will be returned as XmUNSPECIFIED_PAGE_NUMBER.
prev_page_widget
Indicates the currently displayed page widget. If the callback procedure is being called at widget initialization, NULL will be returned.

Action Routines

Notebook action routines are described below:

TraverseTab(Home|End|Next|Previous)
Moves the focus on major or minor tabs.

Additional Behavior

The Notebook widget has the additional behavior described below:

<Tab>
Notebook intercepts tab group traversal when traversal is entering or leaving major or minor tabs. It does this to support major tabs and minor tabs as two separate tab groups when they are actually treated as one by traversal. If a minor tab has keyboard focus and a user or program action specifies XmTRAVERSE_PREV_TAB_GROUP, keyboard focus will go to a major tab. If a major tab has keyboard focus and a user or program action specifies XmTRAVERSE_NEXT_TAB_GROUP, keyboard focus will go to a minor tab.
