NOMBRE

XmContainer — La clase de widget Contenedor

SINOPSIS

#include <Xm/Container.h>

DESCRIPCIÓN

Container gestiona widgets hijos que tienen el rasgo ContainerItem. Estos widgets hijos pueden verse en varios formatos de diseño, seleccionarse usando diferentes tipos y técnicas de selección, y manipularse directamente por el usuario.

El Contenedor admite tres formatos o vistas diferentes. Se especifican a través del recurso XmNentryViewType:

•
XmLARGE_ICON
•
XmSMALL_ICON
•
XmANY_ICON

El Contenedor admite tres tipos de diseño diferentes. Se especifican mediante el recurso XmNlayoutType:

•
XmSPATIAL
•
XmOUTLINE
•
XmDETAIL

En el tipo de diseño XmSPATIAL, varios recursos adicionales (XmNspatialStyle, XmNspatialIncludeModel, XmNspatialSnapModel) controlan el posicionamiento de los elementos dentro del Contenedor; un programador de aplicaciones puede especificar estos recursos para que el Contenedor aplique estrictamente la posición de cada elemento o para que el Contenedor posicione los elementos de acuerdo con los recursos de restricción especificados para cada elemento. Sin embargo, el usuario puede alterar la posición de un elemento en el tipo de diseño XmSPATIAL dentro del Contenedor mediante manipulación directa; por ejemplo, presionando BTransfer sobre el elemento y luego arrastrando y soltando BTransfer sobre alguna ubicación dentro del Contenedor.

En el tipo de diseño XmOUTLINE, el Contenedor controla el posicionamiento de los elementos. Los elementos dentro del Contenedor pueden tener relaciones padre-hijo entre ellos. El recurso XmNentryParent de cada elemento puede especificar otro elemento en el mismo Contenedor como su padre; los elementos con un valor no NULL para XmNentryParent solo pueden mostrarse en el tipo de diseño XmOUTLINE. En el tipo de diseño XmOUTLINE, los elementos se posicionan en una configuración de árbol con líneas de conexión dibujadas para ilustrar las relaciones. Los elementos se posicionan de arriba a abajo en el orden especificado por XmNpositionIndex dentro de su padre. El Contenedor posiciona un PushButton junto a cada elemento que tiene una relación padre con otros elementos. El PushButton contiene un pixmap para ilustrar si los elementos hijos se muestran o no; el usuario puede activar el PushButton para alternar entre mostrar u ocultar los elementos hijos. La manipulación directa para alterar la posición del elemento no es compatible en el tipo de diseño XmOUTLINE. Tenga en cuenta que el recurso XmNtraversalOn de los PushButtons creados por Container se establece en False.

El tipo de diseño XmDETAIL es el mismo que XmOUTLINE, excepto que cada elemento también puede mostrar información adicional como filas en columnas con encabezados de columna especificados en los recursos XmNdetailColumnHeading. En cada fila de elementos, se muestra la información de detalle del elemento (consulte la página de referencia de XmIconGadget para obtener una descripción del recurso XmNentryDetail). Los elementos se posicionan de arriba a abajo en el orden especificado por XmNpositionIndex dentro del padre.

Selección

Cuando se selecciona un widget hijo del contenedor, el contenedor especifica que el elemento debe mostrar la información visual apropiada al usuario a través del rasgo ContainerItem. El programa de aplicación recibe notificaciones de cambios de selección a través de XmNselectionCallback.

El contenedor utiliza cuatro políticas de selección:

•
Única
•
Navegación
•
Múltiple
•
Extendida

En los modos de Selección Única y Navegación, solo se puede seleccionar un elemento a la vez. Presionar BSelect sobre un elemento lo selecciona y deselecciona cualquier otro elemento seleccionado. Presionar BSelect sobre un espacio vacío en el Contenedor deselecciona todos los elementos. En Navegación, arrastrar BSelect mueve la selección a medida que se mueve el puntero.

En los modos de Selección Múltiple y Selección Extendida, se puede seleccionar cualquier número de elementos al mismo tiempo. En Selección Múltiple, presionar y arrastrar BSelect o BExtend para especificar un elemento, un rango de elementos o un grupo de elementos no contiguos, alterna los estados de selección de esos elementos. En Selección Extendida, presionar y arrastrar BSelect para indicar un elemento, un rango de elementos o un grupo de elementos no contiguos selecciona esos elementos y deselecciona todos los demás. Presionar y arrastrar BExtend en Selección Extendida para indicar un elemento, un rango de elementos o un grupo no contiguo de elementos, alterna los estados de selección de esos elementos.

Varias técnicas están disponibles para indicar un elemento, un rango de elementos o un grupo de elementos no contiguos en los modos de Selección Múltiple y Selección Extendida.

En los tipos de diseño XmSPATIAL y XmOUTLINE, el recurso XmNselectionTechnique especifica las técnicas que se utilizarán para indicar elementos. La especificación predeterminada de XmTOUCH_OVER permite que se utilicen las técnicas Random-Swipe y Marquee cuando XmNlayoutStyle es XmSPATIAL. La especificación predeterminada de XmTOUCH_OVER permite que se utilicen las técnicas Range-Swipe, Range-Click y Marquee cuando XmNlayoutStyle es XmOUTLINE.

Los grupos de elementos no contiguos se pueden seleccionar utilizando la técnica Random-Swipe. En la técnica Random-Swipe, presionar BSelect (o BExtend) sobre un elemento y arrastrar BSelect sobre otros elementos selecciona todos esos elementos. Solo se seleccionan los elementos por los que pasó el puntero.

En la técnica Range-Swipe, el usuario presiona BSelect (o BExtend) sobre el primer elemento y suelta BSelect sobre el último elemento; todos los elementos dentro del rango entre el primer y el último elemento se seleccionan, independientemente de si el puntero pasó realmente por ellos o no. En la técnica Range-Click, el usuario presiona y suelta BSelect (o BExtend) sobre el primer elemento y luego presiona y suelta BExtend sobre el último elemento.

En la técnica Marquee, presionar BSelect (o BExtend) sobre un espacio en blanco dentro del Contenedor indica el punto de inicio de un rectángulo Marquee. Arrastrar BSelect dibuja un rectángulo Marquee (línea de goma) entre el punto de inicio y el puntero actual. Todos los elementos completamente dentro del rectángulo Marquee se seleccionan.

Especificar XmTOUCH_ONLY para XmNselectionTechnique impone la técnica Random-Swipe incluso cuando se presiona BSelect (o BExtend) sobre un espacio en blanco. De manera similar, especificar XmMARQUEE impone la técnica Marquee incluso cuando se presiona BSelect (o BExtend) sobre un elemento; dado que el elemento sobre el que ocurre la pulsación está solo parcialmente incluido en el rectángulo Marquee, no se selecciona. XmMARQUEE_EXTEND_START y XmMARQUEE_EXTEND_BOTH imponen la técnica Marquee y también hacen que el rectángulo se extienda automáticamente alrededor del primer elemento indicado y, para XmMARQUEE_EXTEND_BOTH, del último elemento.

En el tipo de diseño XmDETAIL, las técnicas Range-Swipe y Range-Click están disponibles para indicar un rango de elementos para selección.

Container utiliza los rasgos XmQTcontainerItem, XmQTscrollFrame y XmQTspecifyRenderTable y posee los rasgos XmQTcontainer y XmQTtransfer.

Comportamiento de transferencia de datos

Container admite la transferencia de elementos seleccionados desde el widget. Dependiendo del valor de XmNprimaryOwnership, Container también puede admitir la selección primaria.

Como fuente de datos, Container admite los siguientes objetivos y las conversiones asociadas de datos a estos objetivos:

local
Si el objetivo local coincide con la configuración regional del widget, el widget transfiere los elementos seleccionados en la codificación de la configuración regional. El valor de cada elemento transferido, excepto el último, incluye un separador final. El valor de cada elemento es el XmNlabelString del elemento.
COMPOUND_TEXT
El widget transfiere los elementos seleccionados como tipo COMPOUND_TEXT. El valor de cada elemento transferido, excepto el último, incluye un separador final. El valor de cada elemento es el XmNlabelString del elemento.
DELETE

>El widget elimina los elementos seleccionados.
PIXMAP
El widget transfiere una lista de los identificadores de pixmap de los elementos seleccionados como tipo DRAWABLE.
STRING
El widget transfiere los elementos seleccionados como tipo STRING. El valor de cada elemento transferido, excepto el último, incluye un separador final. Cada valor de elemento es el XmNlabelString del elemento.
TEXT
Si los elementos seleccionados son completamente convertibles a la codificación de la configuración regional, el widget transfiere los elementos seleccionados en la codificación de la configuración regional. De lo contrario, el widget transfiere los elementos seleccionados como tipo COMPOUND_TEXT. El valor de cada elemento transferido, excepto el último, incluye un separador final. Cada valor de elemento es el XmNlabelString del elemento.
_MOTIF_CLIPBOARD_TARGETS
El widget transfiere, como tipo ATOM, una lista de los objetivos que soporta para transferencia inmediata para la selección CLIPBOARD. Estos incluyen _MOTIF_COMPOUND_STRING y PIXMAP. Si los elementos seleccionados son completamente convertibles a STRING, estos también incluyen STRING; de lo contrario, también incluyen COMPOUND_TEXT y UTF8_STRING.
_MOTIF_COMPOUND_STRING
El widget transfiere los elementos seleccionados como una cadena compuesta en formato Byte Stream. El valor de cada elemento transferido, excepto el último, incluye un separador final. Cada valor de elemento es el XmNlabelString del elemento.
UTF8_STRING
El widget transfiere los elementos seleccionados como tipo UTF8_STRING. El valor de cada elemento transferido, excepto el último, incluye un separador final. Cada valor de elemento es el XmNlabelString del elemento.
_MOTIF_DEFERRED_CLIPBOARD_TARGETS
El widget transfiere, como tipo ATOM, una lista de los objetivos que soporta para transferencia diferida para la selección CLIPBOARD. Actualmente, este widget no proporciona objetivos para _MOTIF_DEFERRED_CLIPBOARD_TARGETS.
_MOTIF_DRAG_OFFSET
El widget transfiere una lista de dos números de 16 bits, de tipo INTEGER, que representan un desplazamiento x e y para un elemento que se está arrastrando. Este desplazamiento se calcula de tal manera que, si se sumara el desplazamiento a las coordenadas x e y en el sitio de entrega, y el pixmap arrastrado se colocara en esa posición, correspondería a la posición en la que el usuario esperaría que se colocara el pixmap, basándose en el icono de arrastre utilizado en el sitio de entrega.
_MOTIF_EXPORT_TARGETS
El widget transfiere, como tipo ATOM, una lista de los objetivos que se utilizarán como valor de XmNexportTargets del DragContext en una transferencia de arrastrar y soltar. Estos incluyen _MOTIF_COMPOUND_STRING, PIXMAP, COMPOUND_TEXT, la codificación de la configuración regional, STRING, TEXT, BACKGROUND, FOREGROUND y UTF8_STRING.

Como fuente de datos, Container también soporta los siguientes objetivos estándar de Motif:

BACKGROUND
El widget transfiere XmNbackground como tipo PIXEL.
CLASS
El widget encuentra la primera ventana principal en la jerarquía de widgets que tiene una propiedad WM_CLASS y transfiere su contenido como texto en la configuración regional actual.
CLIENT_WINDOW
El widget encuentra la primera ventana principal en la jerarquía de widgets y transfiere su ventana como tipo WINDOW.
COLORMAP
El widget transfiere XmNcolormap como tipo COLORMAP.
FOREGROUND
El widget transfiere XmNforeground como tipo PIXEL.
NAME
El widget encuentra la primera ventana principal en la jerarquía de widgets que tiene una propiedad WM_NAME y transfiere su contenido como texto en la configuración regional actual.
TARGETS
El widget transfiere, como tipo ATOM, una lista de los objetivos que soporta. Estos incluyen los objetivos estándar en esta lista. También incluyen _MOTIF_COMPOUND_STRING, PIXMAP, COMPOUND_TEXT, la codificación de la configuración regional, STRING, TEXT y UTF8_STRING.
TIMESTAMP
El widget transfiere la marca de tiempo utilizada para adquirir la selección como tipo INTEGER.
_MOTIF_RENDER_TABLE
El widget transfiere XmNrenderTable si existe, o la tabla de renderizado de texto predeterminada, como tipo STRING.
_MOTIF_ENCODING_REGISTRY
El widget transfiere su registro de codificación como tipo STRING. El valor es una lista de elementos separados por NULL con el formato de pares de etiqueta-codificación. Este objetivo simboliza el objetivo de transferencia para el Registro de Codificación de Segmentos de Motif. Los widgets y las aplicaciones pueden usar este Registro para registrar formatos de codificación de texto para etiquetas de tabla de renderizado especificadas. Las aplicaciones acceden a este Registro llamando a XmRegisterSegmentEncoding y XmMapSegmentEncoding.

Como destino de datos, Container solo soporta la entrega de elementos que se están arrastrando desde el mismo widget. Las subclases y los procedimientos XmNdestinationCallback son responsables de cualquier otra transferencia de datos al widget.

Clases

Container hereda el comportamiento, los recursos y los rasgos de las clases Core, Composite, Constraint y XmManager.

El puntero de clase es xmContainerWidgetClass.

El nombre de la clase es XmContainer.

XmNautomaticSelection
Indica si el Contenedor invoca devoluciones de llamada de selección cuando cada elemento es seleccionado (o alternado) o si las devoluciones de llamada de selección no se invocan hasta que el usuario haya completado las acciones de selección (por ejemplo, el usuario ha liberado el botón del ratón). Puede tener uno de los siguientes valores:
XmAUTO_SELECT
Realiza devoluciones de llamada de selección automáticamente cuando cada elemento es seleccionado o alternado. Este también puede ser el valor TRUE.
XmNO_AUTO_SELECT
Retrasa las devoluciones de llamada de selección hasta que el usuario haya terminado las acciones de selección. Este también puede ser el valor FALSE.
XmNcollapsedStatePixmap
Especifica el pixmap que se mostrará en un PushButton junto a un elemento del Contenedor con elementos hijos, cuando XmNoutlineButtonPolicy es XmOUTLINE_BUTTON_PRESENT. XmNcollapsedStatePixmap indica que los elementos hijos no se muestran. Si se establece en XmUNSPECIFIED_PIXMAP, se utiliza un pixmap predeterminado que muestra una flecha hacia arriba.
XmNconvertCallback
Especifica una lista de devoluciones de llamada que se invocarán cuando se solicite al Contenedor que convierta una selección. El tipo de la estructura cuya dirección se pasa a estas devoluciones de llamada es XmConvertCallbackStruct. La razón es XmCR_OK.
XmNdefaultActionCallback
Especifica una lista de devoluciones de llamada que se invocarán cuando el usuario haga doble clic en un elemento o presione <Enter> o <Return> sobre un elemento. La estructura de devolución de llamada es XmContainerSelectCallbackStruct. La razón es XmCR_DEFAULT_ACTION.
XmNdestinationCallback
Especifica una lista de devoluciones de llamada que se invocarán cuando el Contenedor sea el destino de una operación de transferencia. El tipo de la estructura cuya dirección se pasa a estas devoluciones de llamada es XmDestinationCallbackStruct. La razón es XmCR_OK.
XmNdetailColumnHeading
Especifica una tabla de XmStrings para mostrar como encabezados de columna. Si es NULL, o si XmNlayoutType no es XmDETAIL, no se muestra ningún encabezado.
XmNdetailColumnHeadingCount
Especifica un recuento de XmStrings en la tabla especificada para XmNdetailColumnHeading.
XmNdetailOrder
Especifica una matriz de Cardinals que indican qué información de detalle de columna, y en qué orden, cada hijo del Contenedor mostrará su información de detalle. Este recurso se ignora si XmNlayoutType no es XmDETAIL. Si es NULL, el comportamiento predeterminado está determinado por XmNdetailOrderCount.
XmNdetailOrderCount
Especifica un recuento de Cardinals en la matriz especificada para XmNdetailOrder. Si XmNdetailOrder es NULL y XmNdetailOrderCount no es 0, entonces cada hijo del Contenedor muestra su información de detalle en orden desde la columna 1 hasta la columna número XmNdetailOrderCount. Si XmNdetailOrderCount es 0, entonces se calcula un valor predeterminado a partir de la información de recuento de orden de detalle de cada elemento accedido a través del trait ContainerItem.
XmNdetailTabList
Indica una XmTabList que especifica el inicio de cada columna en la disposición XmDETAIL. Si este recurso se establece en NULL, entonces el Contenedor calcula una XmTabList. Este recurso se ignora si XmNlayoutType no es XmDETAIL.
XmNentryViewType
Especifica el tipo de vista para todos los hijos del Contenedor. El tipo de vista se especifica para cada elemento a través del trait ContainerItem. Puede tener uno de los siguientes valores:
XmANY_ICON
No se realiza ninguna especificación para los hijos del Contenedor. Los hijos utilizan sus propias especificaciones predeterminadas.
XmLARGE_ICON
El tipo de vista para todos los hijos es XmLARGE_ICON.
XmSMALL_ICON
El tipo de vista para todos los hijos es XmSMALL_ICON.
XmNexpandedStatePixmap
Especifica el pixmap que se mostrará en un PushButton junto a un elemento del Contenedor con elementos hijos, cuando XmNoutlineButtonPolicy es XmOUTLINE_BUTTON_PRESENT. XmNexpandedStatePixmap indica que los elementos hijos se muestran. Si se establece en XmUNSPECIFIED_PIXMAP, se utiliza un pixmap predeterminado que muestra una flecha hacia abajo.
XmNfontList
Especifica la lista de fuentes asociada con XmContainer. La lista de fuentes es una construcción obsoleta y ha sido reemplazada por la tabla de renderizado. Se incluye por compatibilidad con versiones anteriores de Motif y para aplicaciones que no admiten fácilmente tablas de renderizado. La lista de fuentes predeterminada se deriva de la tabla de renderizado predeterminada; y si se especifican tanto una lista de fuentes como una tabla de renderizado, la tabla de renderizado tiene prioridad.
XmNlargeCellHeight
Especifica la altura de una celda para el estilo espacial XmGRID o XmCELLS cuando XmNentryViewType es XmLARGE_ICON o XmANY_ICON.
XmNlargeCellWidth
Especifica el ancho de una celda para el estilo espacial XmGRID o XmCELLS cuando XmNentryViewType es XmLARGE_ICON o XmANY_ICON.
XmNlayoutType
Especifica la política para organizar los widgets hijos dentro del Contenedor. Puede tener uno de los siguientes valores:
XmDETAIL
Muestra los elementos de la misma manera que cuando el recurso es XmOUTLINE, excepto que cada elemento muestra información de detalle junto a él.
XmOUTLINE
Muestra los elementos en una configuración de árbol, en el orden XmNpositionIndex dentro del orden XmNentryParent, con líneas de conexión dibujadas para mostrar sus relaciones padre-hijo.
XmSPATIAL
Muestra
s items de acuerdo con XmNspatialStyle. Los items con valores XmNentryParent no se muestran.
XmNmarginHeight
Especifica el espaciado del margen en la parte superior e inferior del Contenedor.
XmNmarginWidth
Especifica el espaciado del margen en los lados izquierdo y derecho del Contenedor.
XmNoutlineButtonPolicy
Especifica si se deben mostrar o no botones para que los usuarios expandan y contemplen la visualización de los items. Puede tener uno de los siguientes valores:
XmOUTLINE_BUTTON_ABSENT
No mostrar los botones de esquema.
XmOUTLINE_BUTTON_PRESENT
Mostrar los botones de esquema.
XmNoutlineChangedCallback
Especifica una lista de callbacks para llamar cuando el XmNoutlineState de un item cambia. La estructura del callback es XmContainerOutlineCallbackStruct. La razón es XmCR_COLLAPSED o XmCR_EXPANDED, dependiendo del nuevo valor de XmNoutlineState.
XmNoutlineColumnWidth
Especifica el ancho de la primera columna mostrada cuando XmNlayoutType es XmDETAIL. Especifica el ancho preferido del Contenedor (sin los márgenes) cuando XmNlayoutType es XmOUTLINE. Si no se especifica, el Contenedor determinará un valor por defecto igual al espacio más ancho necesario para mostrar el pixmap de un item y el XmNoutlineIndentation.
XmNoutlineIndentation
Especifica la distancia de sangría para la visualización de los items hijos cuando XmNlayoutType es XmOUTLINE o XmDETAIL.
XmNoutlineLineStyle
Especifica si se deben dibujar líneas entre items con relaciones padre-hijo cuando XmNlayoutType es XmOUTLINE o XmDETAIL. Puede tener uno de los siguientes valores:
XmNO_LINE
No dibuja ninguna línea.
XmSINGLE
Dibuja una línea de un píxel de ancho.
XmNprimaryOwnership
Especifica si el Contenedor toma posesión de la selección principal cuando se realiza una selección dentro de él. Este recurso puede tomar los siguientes valores:
XmOWN_NEVER
Nunca toma posesión.
XmOWN_ALWAYS
Siempre toma posesión.
XmOWN_MULTIPLE
Solo toma posesión si se ha seleccionado más de un elemento.
XmOWN_POSSIBLE_MULTIPLE
Solo toma posesión si se puede seleccionar más de un elemento a la vez.
XmNrenderTable
Especifica la XmRenderTable que será heredada por todos los hijos del Contenedor. El valor por defecto depende de la implementación. Si se especifican tanto una tabla de renderizado como una lista de fuentes (fontlist), la tabla de renderizado tendrá precedencia.
XmNselectColor
Especifica un Píxel al que pueden acceder los hijos del Contenedor y que se utiliza para indicar que el hijo está en un estado seleccionado. Además de un valor de Píxel, se pueden especificar los siguientes valores simbólicos:
XmDEFAULT_SELECT_COLOR
Especifica un color entre el color de fondo y el color de sombra inferior.
XmREVERSED_GROUND_COLORS
Fuerza el color de selección al color de primer plano y hace que el color por defecto de cualquier texto renderizado sobre el color de selección sea el color de fondo.
HIGHLIGHT_COLOR
Fuerza el color de relleno a utilizar el color de resaltado.
XmNselectedObjectCount
Especifica el número de widgets en la lista de items seleccionados. El valor debe ser el número de items en XmNselectedObjects.
XmNselectedObjects
Una matriz de widgets que representa los items del Contenedor que están actualmente seleccionados, ya sea por el usuario o por la aplicación.

NAME

XmContainer - A widget that manages a collection of items, allowing users to select, manipulate, and view items in a graphical representation. (This is a conceptual description; see the specific items for actual functionality.)

SYNOPSIS

 #include <Xm/Xm.h>
 #include <Xm/Container.h>

DESCRIPTION

The XmContainer widget is a manager widget that provides a framework for displaying and interacting with a collection of items. It is designed to be used with other widgets, such as XmIconGadget, to represent individual items within the container. The XmContainer widget handles layout, selection, and user interaction for these items.

The specific behavior and appearance of the items managed by the XmContainer widget are determined by the types of child widgets and gadgets that are added to it. For example, using XmIconGadget children allows the container to display icons that users can select and manipulate.

The XmContainer widget supports various features for managing its children, including:

Layout Management
The container can automatically arrange its child items in a specified layout (e.g., grid, list). The XmContainerRelayout function can be used to trigger a layout update.
Selection Handling
Users can select one or more items within the container. The container manages the selection state of its children.
Traversal and Focus
The container supports keyboard traversal among its items, allowing users to navigate and interact with the items using the keyboard. It manages the input focus within the container.
Drag and Drop
The container can participate in drag and drop operations, allowing users to move or link items within the container or between different widgets.
Linking and Copying
The container provides functions for copying and linking items, which are often used in conjunction with drag and drop operations.

Virtual Bindings

The bindings for virtual keys are vendor specific. For information about bindings for virtual buttons and keys, see VirtualBindings(3).
