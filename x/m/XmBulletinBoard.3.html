NOMBRE

XmBulletinBoard — La clase de widget BulletinBoard

SINOPSIS

#include <Xm/BulletinB.h>

DESCRIPCIÓN

BulletinBoard es un widget compuesto que proporciona gestión de geometría simple para los widgets hijos. No fuerza el posicionamiento en sus hijos, pero puede configurarse para rechazar solicitudes de geometría que resulten en hijos superpuestos. BulletinBoard es el widget base para la mayoría de los widgets de diálogo y también se utiliza como un widget contenedor general.

Los diálogos modales y no modales se implementan como colecciones de widgets que incluyen un DialogShell, un hijo BulletinBoard (o subclase) del shell, y varios componentes de diálogo (botones, etiquetas, etc.) que son hijos de BulletinBoard. BulletinBoard define callbacks útiles para diálogos (focus, map, unmap), que están disponibles para uso de la aplicación. Si su padre es un DialogShell, BulletinBoard pasa información de título y modo de entrada (basada en el estilo del diálogo) al padre, que es responsable de la comunicación apropiada con el gestor de ventanas.

El valor predeterminado para XmNinitialFocus es el valor de XmNdefaultButton.

BulletinBoard utiliza el trait XmQTtakesDefault, y mantiene los traits XmQTdialogShellSavvy y XmQTspecifyRenderTable.

Clases

BulletinBoard hereda comportamiento, recursos y traits de las clases Core, Composite, Constraint y XmManager.

El puntero de clase es xmBulletinBoardWidgetClass.

El nombre de la clase es XmBulletinBoard.

El programador también puede establecer los valores de los recursos para las clases heredadas para configurar atributos para este widget. Para hacer referencia a un recurso por nombre o por clase en un archivo .Xdefaults, elimine el prefijo XmN o XmC y use las letras restantes. XmNallowOverlap
Controla la política de superposición de widgets hijos. Si este recurso es True, BulletinBoard permite solicitudes de geometría que resulten en hijos superpuestos.
XmNautoUnmanage
Controla si BulletinBoard se desactiva automáticamente después de que se activa un botón. Si este recurso es True en la inicialización y si el padre de BulletinBoard es un DialogShell, BulletinBoard agrega un callback a los hijos de tipo botón (PushButtons, PushButtonGadgets y DrawnButtons) que desactiva BulletinBoard cuando se activa un botón. Si este recurso es False en la inicialización o si el padre de BulletinBoard no es un DialogShell, BulletinBoard no se desactiva automáticamente. Para subclases de BulletinBoard con botones Apply o Help, la activación de esos botones no desactiva automáticamente BulletinBoard.
XmNbuttonFontList
Especifica la lista de fuentes utilizada para los descendientes de botones. Consulte el recurso XmNbuttonRenderTable.
XmNbuttonRenderTable
Especifica la tabla de renderizado utilizada para los descendientes de botones de BulletinBoard. Si este valor es NULL en la inicialización, se busca en la jerarquía padre del widget un ancestro que posea el trait XmQTspecifyRenderTable. Si se encuentra dicho ancestro, la tabla de renderizado se inicializa con el valor XmBUTTON_RENDER_TABLE del widget ancestro. Si no se encuentra ningún ancestro de este tipo, el valor predeterminado depende de la implementación. Consulte XmRenderTable(3) para obtener más información sobre la creación y estructura de una tabla de renderizado.
XmNcancelButton
Especifica el ID del widget del botón Cancel. Las subclases de BulletinBoard, que definen un botón Cancel, establecen este recurso. BulletinBoard no proporciona directamente ningún comportamiento para ese botón.
XmNdefaultButton
Especifica el ID del widget del botón predeterminado. Algunas subclases de BulletinBoard que definen un botón predeterminado, establecen este recurso. BulletinBoard define traducciones e instala aceleradores que activan ese botón cuando se presiona KActivate y el foco del teclado no está en otro botón.
XmNdefaultPosition
Controla la colocación de un DialogShell que administra un BulletinBoard. Si el BulletinBoard no está siendo administrado por un DialogShell, entonces este recurso no tiene efecto. Si XmNdefaultPosition es True, el DialogShell se centrará en el centro de su propio padre. Por ejemplo, si el padre del DialogShell es un ApplicationShell, entonces el centro del DialogShell estará en las mismas coordenadas que el centro del ApplicationShell. Si el DialogShell se vuelve no mapeado (pero permanece administrado) y luego se vuelve a mapear, este recurso no influye en la posición del DialogShell. Si este recurso es False, el DialogShell no se centra automáticamente.
XmNdialogStyle
Indica el estilo de diálogo asociado con BulletinBoard. Si el padre de BulletinBoard es un DialogShell, el XmNmwmInputMode del padre se establece según el valor de este recurso. Este recurso solo se puede establecer si BulletinBoard no está administrado. Los valores posibles para este recurso incluyen los siguientes:
XmDIALOG_SYSTEM_MODAL
Se utiliza para diálogos que deben responderse antes que cualquier otra interacción en cualquier aplicación.
XmDIALOG_PRIMARY_APPLICATION_MODAL
Se utiliza para diálogos que deben responderse antes que algunas otras interacciones en los ancestros del widget.
XmDIALOG_APPLICATION_MODAL
Se utiliza para diálogos que deben responderse antes que algunas otras interacciones en los ancestros del widget. Este valor es el mismo que XmDIALOG_PRIMARY_APPLICATION_MODAL y se mantiene por compatibilidad.
XmDIALOG_FULL_APPLICATION_MODAL
Se utiliza para diálogos que deben responderse antes que algunas otras interacciones en la misma aplicación.
XmDIALOG_MODELESS
Se utiliza para diálogos que no interrumpen la interacción de ninguna aplicación. Este es el valor predeterminado cuando el padre de BulletinBoard es un DialogShell.
XmDIALOG_WORK_AREA
Se utiliza para widgets BulletinBoard cuyos padres no son DialogShells. XmNdialogStyle se fuerza a tener este valor cuando el padre de BulletinBoard no es un DialogShell.
Publicar un diálogo modal en respuesta a un evento de botón presionado o tecla presionada (a través de acciones de traducción o callbacks) puede hacer que el evento de botón liberado o tecla liberada correspondiente se pierda. Por ejemplo, publicar un diálogo modal desde un XmNincrementCallback de XmScrollBar provocará la pérdida del evento de botón liberado, lo que hará que el XmScrollBar se incremente automáticamente de forma indefinida.
XmNdialogTitle
Especifica el título del diálogo. Si este recurso no es NULL, y el padre de BulletinBoard
d es una subclase de WMShell, BulletinBoard establece XmNtitle y XmNtitleEncoding de su padre. Si el único conjunto de caracteres en XmNdialogTitle es ISO8859-1, XmNtitle se establece a la cadena del título, y XmNtitleEncoding se establece a STRING. Si XmNdialogTitle contiene conjuntos de caracteres distintos de ISO8859-1, XmNtitle se establece a la cadena del título convertida a una cadena de texto compuesto, y XmNtitleEncoding se establece a COMPOUND_TEXT. La dirección del título se basa en XmNlayoutDirection recurso del widget.
XmNfocusCallback

XmNlabelFontList

XmNlabelRenderTable

XmNmapCallback
Especifica la lista de callbacks que se llaman solo cuando el padre de BulletinBoard es un DialogShell. En este caso, esta lista de callbacks se invoca cuando el widget BulletinBoard se mapea. La razón del callback es XmCR_MAP. Los DialogShells generalmente se mapean cuando el DialogShell se administra.
XmNmarginHeight
Especifica el espaciado mínimo en píxeles entre el borde superior o inferior de BulletinBoard y cualquier widget hijo.
XmNmarginWidth
Especifica el espaciado mínimo en píxeles entre el borde izquierdo o derecho de BulletinBoard y cualquier widget hijo.
XmNnoResize
Controla si se incluyen o no controles de redimensionamiento en el marco del gestor de ventanas alrededor del padre de BulletinBoard. Si este recurso se establece en True, mwm no incluye controles de redimensionamiento en el marco del gestor de ventanas que contiene al padre de BulletinBoard si el padre es una subclase de VendorShell. Si este recurso se establece en False, el marco del gestor de ventanas incluye controles de redimensionamiento. Otros controles proporcionados por mwm pueden incluirse o excluirse a través de los recursos mwm proporcionados por VendorShell.

Describe el estilo de dibujo de la sombra para BulletinBoard. Este recurso puede tener los siguientes valores:

XmSHADOW_OUT

XmSHADOW_ETCHED_OUT
Dibuja la sombra de BulletinBoard utilizando una línea doble que da el efecto de una línea saliendo de la ventana, similar al widget Separator.

Especifica la tabla de renderizado utilizada para los descendientes de texto de BulletinBoard. Si este valor es NULL en la inicialización, la jerarquía padre del widget se busca para encontrar un ancestro que posea el rasgo XmQTspecifyRenderTable. Si se encuentra dicho ancestro, la tabla de renderizado se inicializa al valor XmTEXT_RENDER_TABLE del widget ancestro. Si no se encuentra ningún ancestro de este tipo, el valor predeterminado depende de la implementación. Consulte XmRenderTable(3) para más información sobre la creación y estructura de una tabla de renderizado.
XmNtextTranslations
Agrega traducciones a cualquier widget Text o subclase de widget Text que se añada como hijo de BulletinBoard.
XmNunmapCallback
Especifica la lista de callbacks que se llaman solo cuando el padre de BulletinBoard es un DialogShell. En este caso, esta lista de callbacks se invoca cuando el widget BulletinBoard se desmapea. La razón del callback es XmCR_UNMAP. Los DialogShells generalmente se desmapean cuando el DialogShell se desadministra.

DESCRIPTION

The XmBulletinBoard widget is a general-purpose dialog widget. It is designed to allow the application to place controls within the widget at specific positions. The widget provides an area within which child widgets can be placed. The XmBulletinBoard widget supports the XmNallowOverlap, XmNbuttonCount, XmNbuttonFont, XmNcancelButton, XmNdefaultButton, XmNdialogStyle, XmNdialogTitle, XmNfocusCallback, XmNlabelFont, XmNlayoutCache, XmNmarginHeight, XmNmarginWidth, XmNmnemonicAlignment, XmNnoResize, XmNpopdownCallback, XmNpopupCallback, XmNresizePolicy, XmNshadowThickness, XmNstringDirection, XmNtextFont, XmNtitleFont, XmNworkWindow, XmNxmScrollBarThickness, XmNdepth, XmNdestroyCallback, XmNheight, XmNinitialResourcesPersistent, XmNmappedWhenManaged, XmNscreen, XmNsensitive, XmNtranslations, XmNwidth, XmNx, and XmNy resources.

The XmBulletinBoard widget supports the following callbacks: XmNfocusCallback, XmNmapCallback, XmNpopdownCallback, XmNpopupCallback, and XmNunmapCallback.

Callback Information

A pointer to the following structure is passed to each callback:

typedef struct
{
        int reason;
        XEvent * event;
} XmAnyCallbackStruct;
reason
Indicates why the callback was invoked
event
Points to the XEvent that triggered the callback

Additional Behavior

The XmBulletinBoard widget has the following additional behavior:

<Key><osfCancel>:
Calls the activate callbacks for the cancel button if it is sensitive. If no cancel button exists and if the parent of the BulletinBoard is a manager, passes the event to the parent.
<Key><osfActivate>:
Calls the activate callbacks for the button with the keyboard focus. If no button has the keyboard focus, calls the activate callbacks for the default button if it is sensitive. In a List widget or single-line Text widget, the List or Text action associated with <Key><osfActivate> is called before the BulletinBoard actions associated with <Key><osfActivate>.
In a multiline Text widget, any <Key><osfActivate> event except <Key><Enter> calls the Text action associated with <Key><osfActivate>, then the BulletinBoard actions associated with <Key><osfActivate>. If no button has the focus, no default button exists, and the parent of the BulletinBoard is a manager, passes the event to the parent.
<FocusIn>:
Calls the callbacks for XmNfocusCallback. When the focus policy is XmPOINTER, the callbacks are called when the pointer enters the window. When the focus policy is XmEXPLICIT, the callbacks are called when the user traverses to the widget.
<Map>:
Calls the callbacks for XmNmapCallback.
<Unmap>:
Calls the callbacks for XmNunmapCallback.
