NOMBRE

XmComboBox — La clase de widget ComboBox

SINOPSIS

#include <Xm/ComboBox.h>

DESCRIPCIÓN

XmComboBox combina las capacidades de un widget TextField de una sola línea y un widget List. Permite a los usuarios realizar operaciones como escribir y pegar información, y también proporciona una lista de opciones posibles que el usuario puede seleccionar para completar el campo de entrada TextField. La lista puede mostrarse en todo momento o puede ser desplegada por el usuario. Cuando la porción de lista del ComboBox está oculta, a los usuarios se les da una indicación visual (una flecha apuntando hacia abajo) junto al campo TextField. La posición de la flecha en relación con el campo TextField depende del recurso XmNlayoutDirection del widget. Esta versión del ComboBox se denomina ComboBox "desplegable". Los ComboBox desplegables son útiles cuando el espacio en pantalla es limitado, o cuando los usuarios completarán el campo de entrada de texto con más frecuencia escribiendo texto que seleccionando el texto del campo de entrada de la lista. El usuario puede acceder al ComboBox desplegable de una de las siguientes dos maneras:

•
Haciendo clic y soltando <Btn1> en la flecha apuntando hacia abajo, lo que muestra la lista, y la lista permanece visible. Una selección posterior de un elemento en la lista hará que el elemento aparezca en el campo de entrada de texto, y la lista se despublicará a sí misma.
•
Presionando <Btn1> en la flecha apuntando hacia abajo, arrastrándola a un elemento de la lista y luego soltándola allí, lo que selecciona ese elemento. La lista desaparece y el elemento seleccionado aparece en el campo de entrada de texto.

La aplicación proporciona una matriz de cadenas que llenan la lista. En el momento de la creación, se pueden pasar elementos de cadena al ComboBox a través de una lista de argumentos. Cada cadena se convierte en un elemento de la lista, siendo la primera cadena el elemento en la posición 1, la segunda cadena el elemento en la posición 2, y así sucesivamente. El tamaño de la lista se establece especificando el número de elementos que son visibles en la lista (XmNvisibleItemCount). Si el número de elementos en la lista excede el número de elementos visibles, aparecerá automáticamente una barra de desplazamiento vertical que permitirá al usuario desplazarse por un gran número de elementos.

ComboBox crea dos widgets hijos: un widget TextField para introducir texto y una ScrolledWindow que contiene una List para la lista de elementos. El nombre de la lista de elementos en sí es List, y el nombre del TextField es Text. La aplicación o el usuario pueden especificar valores de recursos para estos widgets en un archivo de recursos, y la aplicación puede usar XtNameToWidget (especificando "*List" para la lista de elementos o "*Text" para el widget TextField) para obtener los IDs de widget de los widgets descendientes. En el momento de la creación, ComboBox pasa valores de recursos apropiados en la lista de argumentos de creación, incluyendo XmNitems, a la lista de elementos. Tenga en cuenta que el resultado de proporcionar el recurso XmNdestroyCallback en la lista de argumentos de creación no está especificado. La aplicación debe usar la función XtAddCallback para agregar callbacks al widget apropiado (TextField o List) después de crearlo.

ComboBox fuerza los siguientes valores de recursos en su widget hijo List:

•
Si XmNcomboBoxType es XmCOMBO_BOX, XmNtraversalOn se fuerza a False.
•
XmNhighlightThickness se fuerza a 2 en un ComboBox desplegable y a 0 en otros tipos de ComboBoxes.
•
XmNborderWidth se fuerza a 0.
•
XmNnavigationType se fuerza a XmNONE.
•
XmNselectionPolicy se fuerza a XmBROWSE_SELECT.
•
XmNlistSizePolicy se fuerza a XmVARIABLE.
•
XmNspacing se fuerza a 0.
•
XmNvisualPolicy se fuerza a XmVARIABLE.
•
XmNselectedPositions se fuerza a NULL.
•
XmNselectedPositionsCount se fuerza a 0.

Cuando XmNcomboBoxType es XmDROP_DOWN_LIST, ComboBox fuerza los siguientes valores de recursos en su widget hijo TextField:

•
XmNeditable se fuerza a False.
•
XmNcursorPositionVisible se fuerza a False.
•
XmNshadowThickness se fuerza a 0.

Por el contrario, cuando XmNcomboBoxType es XmCOMBO_BOX o XmDROP_DOWN_COMBO_BOX, ComboBox fuerza los siguientes valores de recursos en su widget hijo TextField:

•
XmNeditable se fuerza a True.
•
XmNcursorPositionVisible se fuerza a True.
•
XmNeditMode se fuerza a XmSINGLE_LINE_EDIT.

ComboBox siempre fuerza los valores de los siguientes recursos en el TextField:

•
XmNnavigationType se fuerza a XmNONE.
•
XmNhighlightThickness se fuerza a 0.
•
XmNborderWidth se fuerza a 0.

ComboBox permite seleccionar un solo elemento de dos maneras: seleccionando el elemento deseado de la List o introduciendo texto en el TextField. ComboBox no selecciona automáticamente un elemento de la lista si el usuario escribe esa cadena en el TextField. Selecciona el elemento cuando el usuario presiona KActivate o mueve el foco. ComboBox admite el modelo de selección Browse Select de List (consulte la página de referencia de XmList para una descripción de este modelo), por lo que las selecciones son mutuamente excluyentes. Seleccionar un elemento de la lista hace que ese elemento se muestre en el TextField del ComboBox. Si la aplicación establece el recurso XmNvalue del TextField, esa cadena se muestra en el TextField. Si la aplicación no ha proporcionado ningún elemento en la lista, o si no hay una selección actual, el TextField está vacío.

El TextField en el widget ComboBox puede ser editable o no editable, dependiendo del valor del recurso XmNcomboBoxType.

Si el TextField es editable, el usuario puede escribir en él. Cuando el usuario presiona la tecla Enter, el ComboBox comparará la entrada escrita con los elementos de la List. Si hay una coincidencia exacta, se seleccionará el elemento coincidente de la List. Si la aplicación desea validar el texto introducido (por ejemplo, para asegurar que la selección escrita sea válida), puede hacerlo estableciendo XmNmodifyVerifyCallback en el widget TextField.

Si el TextField no es editable, escribir texto puede invocar un algoritmo de coincidencia que intentará que la entrada escrita coincida con los elementos de la lista. El algoritmo de coincidencia específico aplicado, que puede ser ninguno, está determinado por el valor del recurso XmNmatchBehavior en ComboBox, que puede ser XmNONE o XmQUICK_NAVIGATE. Un valor de XmNONE indica que no ocurrirá ningún algoritmo de coincidencia. Un valor de XmQUICK_NAVIGATE indica que cuando el widget List tenga el foco, se admitirá la navegación de un carácter. En este algoritmo, si el carácter escrito es el carácter inicial de algún elemento de la List, este algoritmo hace que ese elemento se navegue y se seleccione, y el elemento se muestra en el TextField. Escribir posteriormente el mismo carácter ciclará entre los elementos con el mismo primer carácter.

Independientemente del mecanismo de selección utilizado (ya sea seleccionado directamente de la List o escrito en el TextField), cuando se selecciona un elemento de la List, ese elemento se resalta en la List. Además, el elemento seleccionado se muestra en el TextField del ComboBox. Si el usuario realiza una acción que apartaría el foco de ComboBox, o selecciona un elemento de la List, se invocan los callbacks de XmNselectionCallback para notificar a la aplicación sobre el contenido actual del TextField (o la elección). La aplicación luego realizará la acción requerida basada en esos contenidos (o elección).

ComboBox utiliza el trait XmQTspecifyRenderTable y mantiene el trait XmQTaccessTextual.

El nombre de la clase es XmComboBox.

Especifica el grosor del rectángulo de resaltado.

Especifica los elementos de la lista. Si no está establecido, se utiliza el valor de la lista. Consulte la página man de XmList para obtener información más detallada.
XmNlist
El widget de lista.
XmNmarginWidth
Especifica el espaciado horizontal entre los widgets hijos y el borde del ComboBox.
XmNmarginHeight
Especifica el espaciado vertical entre los widgets hijos y el borde del ComboBox.
XmNmatchBehavior
Define el algoritmo de coincidencia aplicado para hacer coincidir el texto escrito por el usuario en el campo TextField con los elementos de la lista. Los valores actuales son XmNONE y XmQUICK_NAVIGATE, como sigue:
XmNONE
Indica que no hay ningún algoritmo de coincidencia asignado.
XmQUICK_NAVIGATE
Solo es válido para ComboBoxes no editables (valor del recurso XmNcomboBoxType XmDROP_DOWN_LIST). Este algoritmo admite navegación de 1 carácter cuando el widget List tiene el foco. Si el carácter escrito es el carácter inicial de algún elemento en la Lista, este algoritmo hace que ese elemento sea navegado y seleccionado. Escribir posteriormente el mismo carácter ciclará entre los elementos con el mismo primer carácter.
XmNpositionMode
Especifica cómo se deben interpretar el valor del recurso XmNselectedPosition y el campo item_position de la estructura de devolución de llamada. Tenga en cuenta que las funciones de conveniencia XmComboBoxDeletePos y XmComboBoxAddItem no se ven afectadas por este recurso y (al igual que XmList) siempre utilizan posiciones basadas en 1. Los valores válidos para este recurso son:
XmZERO_BASED
(Modo de compatibilidad con DtComboBox: predeterminado) XmNselectedPosition está en [0, itemcount-1]. El item_position en la XmComboBoxCallbackStruct es 0 si se seleccionó el primer elemento de la lista. Tenga en cuenta que también se devuelve 0 si no se seleccionó ningún elemento de la lista (es decir, se introdujo un nuevo elemento en el campo de texto).
XmONE_BASED
(Modo Motif) Tanto el valor del recurso como los campos de devolución de llamada están basados en 1. Esto es coherente con otros widgets Motif.
XmNrenderTable
Especifica la tabla de renderizado asociada a ComboBox. Esta tabla de renderizado se utiliza tanto en el campo TextField como en la Lista del ComboBox. Se utiliza junto con el recurso XmNvisibleItemCount de la Lista para determinar la altura del widget ComboBox.
Si este valor es NULL al inicializar, y si el padre del widget es XmBulletinBoard o sus subclases, VendorShell o sus subclases, o XmMenuShell, entonces el padre del widget proporciona la tabla de renderizado predeterminada asociada con el widget. Si se especifican tanto una tabla de renderizado como una lista de fuentes, la tabla de renderizado tendrá prioridad.
XmNselectedItem
Especifica una cadena compuesta que representa la selección actual del ComboBox. El elemento seleccionado es el contenido del campo de entrada de texto del ComboBox.
XmNselectedPosition
Si la selección en el ComboBox es un elemento de la lista, este es el índice del elemento seleccionado en la lista. Si no se selecciona ningún elemento de la lista, este valor es 0.
XmNselectionCallback
Especifica la lista de devoluciones de llamada que se llaman cuando se selecciona un elemento. El campo de razón en XmComboBoxCallbackStruct es XmCR_SELECT.
XmNtextField
El widget de campo de texto.
XmNvisibleItemCount
Especifica el número de elementos visibles en la lista. Esto anulará cualquier valor especificado para la lista. Consulte la página man de XmList para obtener información más detallada.

Información de Callback

Se pasa un puntero a la siguiente estructura a cada callback. La estructura de callback se define de la siguiente manera:

typedef struct
{
        int reason;
        XEvent *event;
        XmString item_or_text;
        int item_position;
} XmComboBoxCallbackStruct;
reason
Indica por qué se invocó el callback.
event
Punta a la XEvent que activó el callback. Puede ser NULL.
item_or_text
El contenido del campo de texto en el momento en que el evento causó el callback. El parámetro item_or_text apunta a un espacio de almacenamiento temporal que se reutiliza una vez finalizado el callback. Si una aplicación necesita guardar el elemento, debe copiar item_or_text en su propio espacio de datos.
item_position
La posición del elemento en el array 1-basado de XmNitems de la lista. Si es 0, significa que item_or_text no fue seleccionado de la Lista.

Rutinas de Acción

Las rutinas de acción de XmComboBox son las siguientes:

CBActivate():
Llama a los callbacks de XmNselectionCallback. Si XmNcomboBoxType es XmDROP_DOWN_COMBO_BOX o XmDROP_DOWN_LIST, descuelga la lista. Si el padre es un gestor, pasa el evento al padre.
CBArmAndDropDownList():
Si el puntero está dentro de la flecha hacia abajo, dibuja la sombra de la flecha en el estado seleccionado y luego publica la lista.
CBCancel():
Si XmNcomboBoxType es XmDROP_DOWN_COMBO_BOX o XmDROP_DOWN_LIST, descuelga la lista. Si el padre es un gestor, pasa el evento al padre.
CBDisarm():
Redibuja la flecha en un estado no seleccionado.
CBDropDownList():

NAME

XmComboBox - A widget that combines a text field and a list widget

SYNOPSIS

#include <Xm/ComboBox.h>

DESCRIPTION

The XmComboBox widget is a compound widget that combines a text field widget and a list widget. It provides a simple way to allow users to select an item from a list, and also to enter a custom value if the list does not contain the desired item.

The XmComboBox widget supports two types of behavior: drop-down and pop-up. In the drop-down style, the list is always visible below the text field. In the pop-up style, the list is hidden until the user clicks a button to display it.

The XmComboBox widget consists of the following child widgets:

XmTextField
The text field widget allows the user to enter or display the selected value.
XmList
The list widget displays the available items for selection.
XmPushButton (optional)
A button that, when clicked, displays or hides the list widget. This button is typically used in the pop-up style.

Callbacks

The XmComboBox widget defines the following callbacks:

XmNactivateCallback
Called when the user activates the widget, typically by pressing Enter in the text field or selecting an item from the list.
XmNcomboBoxCallback
Called when the ComboBox state changes, such as when the list is displayed or hidden, or when an item is selected.
XmNbrowseSelectionCallback
Called when the user browses through the list, selecting different items. This callback is typically used to provide immediate feedback as the user moves the selection cursor.
XmNdefaultActionCallback
Called when the user performs the default action on the widget, such as double-clicking an item in the list.
XmNmodifyTextCallback
Called when the text in the text field is modified. This callback can be used to validate or modify the input text.

Actions

The XmComboBox widget defines the following actions:

CBListAction(XmNtoggleDown):
If the list is not displayed, posts the list. If the list is displayed, it unposts the list.
CBListAction(ListBeginData):
Moves the location cursor to the first item in the list. In Normal Mode, this also deselects any current selection, selects the first item in the list, and calls the XmNbrowseSelectionCallback selection callback.
CBListAction(ListEndData):
Moves the location cursor to the last item in the list. In Normal Mode, this also deselects any current selection, selects the last item in the list, and calls the XmNbrowseSelectionCallback selection callback.
CBListAction(ListPrevPage):
Scrolls the list to the previous page, moving the location cursor to a new item. This action also selects the new item, deselects any current selection, and calls the XmNbrowseSelectionCallback callbacks. If the ComboBox is not a drop-down type, then this action does nothing.
CBListAction(ListNextPage):
Scrolls the list to the next page, moving the location cursor to a new item. This action also selects the new item, deselects any current selection, and calls the XmNbrowseSelectionCallback callbacks. If the ComboBox is not a drop-down type, then this action does nothing.
CBListAction(Up):
Moves the location cursor to the previous item in the list. This action also selects the previous item, deselects any current selection, and calls the XmNbrowseSelectionCallback callbacks. Note that, unlike the List ListPrevItem action, this action wraps around.
CBListAction(Down):
Moves the location cursor to the next item in the list. This action also selects the next item, deselects any current selection, and calls the XmNbrowseSelectionCallback callbacks. Note that, unlike the List ListNextItem action, this action wraps around.

Virtual Bindings

The bindings for virtual keys are vendor specific. For information about bindings for virtual buttons and keys, see VirtualBindings(3).

ERRORS/WARNINGS

The toolkit will display a warning if the application tries to set the value of XmNlist or the XmNtextField resource, which are read-only (marked G in the resource table).
