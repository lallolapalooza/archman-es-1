NOMBRE

XML::Simple::FAQ - Preguntas Frecuentes sobre XML::Simple

BÁSICOS

¿Para qué debería usar XML::Simple?

¡Para nada!

Es así de simple.

Elige un módulo mejor. Consulta XML::LibXML de Perl por ejemplo http://grantm.github.io/perl-libxml-by-example/ para una introducción amigable a XML::LibXML con muchos ejemplos.

¿Para qué se diseñó originalmente XML::Simple?

XML::Simple es un módulo de Perl que se desarrolló originalmente como una herramienta para leer y escribir datos de configuración en formato XML. Podrías usarlo para otros propósitos que impliquen almacenar y recuperar datos estructurados en XML, pero es probable que sea una experiencia frustrante.

¿Por qué almacenar datos de configuración en XML de todos modos?

Parecía una buena idea en su momento. Ahora, uso y recomiendo Config::General, que utiliza un formato similar al empleado por el servidor web Apache. Este es más fácil de leer que XML, al tiempo que permite conceptos avanzados como secciones anidadas.

En el momento en que se escribió XML::Simple, las ventajas de usar el formato XML para los datos de configuración se pensaban que incluían:

  • El uso de herramientas de análisis XML existentes requiere menos tiempo de desarrollo, es más fácil y robusto que desarrollar tu propio código de análisis de archivos de configuración
  • XML puede representar relaciones entre fragmentos de datos, como la anidación de secciones a niveles arbitrarios (no fácilmente factible con archivos .INI, por ejemplo)
  • XML es básicamente solo texto, por lo que puedes editar fácilmente un archivo de configuración (más fácil que editar el registro de Win32)
  • XML proporciona soluciones estándar para manejar conjuntos de caracteres y codificaciones más allá del ASCII básico (importante para la internacionalización)
  • Si es necesario cambiar el formato de tus archivos de configuración, hay muchas herramientas disponibles para realizar transformaciones en archivos XML
  • XML es un estándar abierto (el mundo no necesita más formatos de archivo binarios propietarios)
  • Dar el paso adicional de desarrollar un DTD permite validar el formato de los archivos de configuración antes de que tu programa los lea (no admitido directamente por XML::Simple)
  • La combinación de un DTD con un buen editor XML puede proporcionarte un editor de configuración gráfico con un esfuerzo de codificación mínimo

¿Para qué no es bueno XML::Simple?

La principal limitación de XML::Simple es que no funciona con "contenido mixto" (ver la siguiente pregunta). Si consideras que tus archivos XML contienen texto marcado en lugar de datos estructurados, probablemente deberías usar otro módulo.

Si tus documentos XML de origen cambian regularmente, es probable que experimentes fallos intermitentes. En particular, el no usar correctamente las opciones ForceArray y KeyAttr producirá código que funciona cuando obtienes una lista de elementos con el mismo nombre, pero falla cuando solo hay un elemento en la lista. Estos tipos de problemas se pueden evitar no usando XML::Simple en primer lugar.

Si estás trabajando con archivos XML muy grandes, el enfoque de XML::Simple de representar todo el archivo en memoria como una estructura de datos de "árbol" podría no ser adecuado.

¿Qué es el contenido mixto?

Considera este ejemplo XML:

<documento>
  <p>Este es contenido <em>mixto</em>.</p>
</documento>

Se dice que esto es contenido mixto, porque el elemento <p> contiene tanto datos de caracteres (contenido de texto) como elementos anidados.

Aquí tienes un poco más de XML:

<persona>
  <nombre>Joe</nombre>
  <apellido>Bloggs</apellido>
  <fecha_nacimiento>25-Abril-1969</fecha_nacimiento>
</persona>

Este segundo ejemplo generalmente no se considera contenido mixto. Los elementos <nombre>, <apellido> y <fecha_nacimiento> contienen solo datos de caracteres y el elemento <persona> contiene solo elementos anidados. (Nota: Estrictamente hablando, el espacio en blanco entre los elementos anidados son datos de caracteres, pero XML::Simple los ignora).

¿Por qué XML::Simple no maneja el contenido mixto?

Porque si lo hiciera, ¡ya no sería simple :-)

En serio, hay muchos módulos excelentes que te permiten trabajar con contenido mixto de diversas maneras. Manejar el contenido mixto correctamente no es fácil y, al ignorar estos problemas, XML::Simple puede presentar una API sin una curva de aprendizaje pronunciada.

¿Qué módulos de Perl manejan el contenido mixto?

Todos menos XML::Simple :-)

Si buscas una recomendación, te sugiero que consultes las Preguntas Frecuentes de Perl-XML en:

http://perl-xml.sourceforge.net/faq/

INSTALACIÓN

¿Cómo instalo XML::Simple?

Si estás ejecutando ActiveState Perl, o Strawberry Perl http://strawberryperl.com/, probablemente ya tengas XML::Simple y, por lo tanto, no necesites instalarlo en absoluto. Pero probablemente también tengas XML::LibXML, que es un módulo mucho mejor, así que simplemente úsalo.

Si necesitas instalar XML::Simple, primero deberás instalar un módulo analizador XML. Instala XML::Parser (que quizás ya tengas) o XML::SAX. Si instalas ambos, XML::SAX se usará por defecto.

Una vez que tengas un analizador instalado ...

En sistemas Unix, prueba:

perl -MCPAN -e 'install XML::Simple'

Si eso no funciona, descarga la última distribución desde ftp://ftp.cpan.org/pub/CPAN/authors/id/G/GR/GRANTM , descomprímela y ejecuta estos comandos:

perl Makefile.PL
make
make test
make install

En Win32, si tienes una compilación reciente de ActiveState Perl (618 o mejor), prueba este comando:

ppm install XML::Simple

Si eso no funciona, realmente solo necesitas el archivo Simple.pm, así que extráelo del archivo .tar.gz (por ejemplo: usando WinZIP) y guárdalo en el directorio \site\lib\XML bajo tu instalación de Perl (típicamente C:\Perl).

Estoy intentando instalar XML::Simple y 'make test' falla

¿Está el directorio donde descomprimiste XML::Simple montado desde un servidor de archivos usando NFS, SMB o algún otro sistema compartido de archivos en red? Si es así, eso puede causar errores en los siguientes scripts de prueba:

3_Storable.t
4_MemShare.t
5_MemCopy.t

El conjunto de pruebas está diseñado para ejercitar las condiciones límite de toda la funcionalidad de XML::Simple y estos tres scripts ejercitan las funciones de caché. Si a XML::Simple se le pide que analice un archivo del cual tiene una copia en caché de un análisis anterior, entonces compara la marca de tiempo del archivo XML con la marca de tiempo de la copia en caché. Si la copia en caché es *más reciente*, se usará. Si la copia en caché es más antigua o de la misma antigüedad, el archivo se volverá a analizar. Los scripts de prueba se confundirán con los sistemas de archivos en red si los relojes del sistema del cliente y del servidor no están sincronizados (hasta el segundo).

Si obtienes un error en uno de estos tres scripts de prueba, pero no planeas usar las opciones de caché (no están habilitadas por defecto), entonces procede y ejecuta 'make install'. Si planeas usar la caché, intenta descomprimir la distribución en un disco local y haz la compilación/prueba allí.

Probablemente no sea una buena idea usar las opciones de caché con sistemas de archivos en red en producción. Si el reloj del servidor de archivos está adelantado respecto al reloj local, XML::Simple volverá a analizar archivos cuando podría haber usado la copia en caché. Sin embargo, si el reloj local está adelantado respecto al reloj del servidor de archivos y un archivo se modifica inmediatamente después de ser puesto en caché, se usará la copia antigua en caché.

¿no se está ejecutando en un sistema de archivos de red? ¿Está ejecutando Win32? Si es así, puede que esté viendo un error en Win32 donde las escrituras en un archivo no afectan a su marca de tiempo de modificación.

Si ninguna de estas situaciones coincide con la suya, por favor, confirme que está ejecutando la última versión de XML::Simple y luego envíe el resultado de 'make test' a mi correo electrónico grantm@cpan.org

¿Por qué es tan lento XML::Simple?

Si descubre que XML::Simple es muy lento leyendo XML, la razón más probable es que tenga instalado XML::SAX pero ningún módulo de análisis SAX adicional. La distribución XML::SAX incluye un analizador XML escrito completamente en Perl. Esto es muy portátil pero no muy rápido. Para un mejor rendimiento, instale XML::SAX::Expat o XML::LibXML.

Uso

¿Cómo uso XML::Simple?

Si no sabe cómo usar XML::Simple, el mejor enfoque es aprender a usar XML::LibXML http://grantm.github.io/perl-libxml-by-example/ en su lugar. Deje de leer este documento y use ese en su lugar.

Si está decidido a usar XML::Simple, viene con documentación abundante, así que léala.

Hay tantas opciones, ¿cuáles necesito realmente conocer?

Aunque puede salir adelante sin usar ninguna opción, no debería ni siquiera considerar usar XML::Simple en producción hasta que sepa qué hacen estas dos opciones:

  • forcearray
  • keyattr

La razón por la que realmente necesita leer sobre ellas es que los valores predeterminados para estas opciones le harán tropezar si no lo hace. Aunque todos coinciden en que estos valores predeterminados no son ideales, no hay un amplio acuerdo sobre cómo deberían cambiarse. La respuesta, por lo tanto, es leer sobre ellas (ver más abajo) y seleccionar los valores que sean adecuados para usted.

¿De qué trata la opción forcearray?

Considere este XML en un archivo llamado ./person.xml:

<person>
  <first_name>Joe</first_name>
  <last_name>Bloggs</last_name>
  <hobbie>paracaidismo</hobbie>
  <hobbie>salto base</hobbie>
  <hobbie>tejido</hobbie>
</person>

Podría leerlo con esta línea:

my $person = XMLin('./person.xml');

Lo que le daría una estructura de datos como esta:

$person = {
  'first_name' => 'Joe',
  'last_name'  => 'Bloggs',
  'hobbie'     => [ 'paracaidismo', 'salto base', 'tejido' ]
};

Los elementos <first_name> y <last_name> se representan como valores escalares simples a los que podría referirse así:

print "$person->{first_name} $person->{last_name}\n";

Los elementos <hobbie> se representan como un array, ya que hay más de uno. Podría referirse al primero así:

print $person->{hobbie}->[0], "\n";

O a todos ellos así:

print join(', ', @{$person->{hobbie}} ), "\n";

El truco es que estas dos últimas líneas de código solo funcionarán para personas que tengan más de un pasatiempo. Si solo hay un elemento <hobbie>, se representará como un valor escalar simple (igual que <first_name> y <last_name>). Lo que podría llevarle a escribir código como este:

if(ref($person->{hobbie})) {
  print join(', ', @{$person->{hobbie}} ), "\n";
}
else {
  print $person->{hobbie}, "\n";
}

No haga eso.

Un enfoque alternativo es establecer la opción forcearray a un valor verdadero:

my $person = XMLin('./person.xml', forcearray => 1);

Lo que le dará una estructura de datos como esta:

$person = {
  'first_name' => [ 'Joe' ],
  'last_name'  => [ 'Bloggs' ],
  'hobbie'     => [ 'paracaidismo', 'salto base', 'tejido' ]
};

Entonces puede usar esta línea para referirse a toda la lista de pasatiempos, incluso si solo había uno:

print join(', ', @{$person->{hobbie}} ), "\n";

La desventaja de este enfoque es que los elementos <first_name> y <last_name> también siempre se representarán como arrays, aunque nunca habrá más de uno:

print "$person->{first_name}->[0] $person->{last_name}->[0]\n";

Esto podría estar bien si cambia el XML para usar atributos para cosas que siempre serán singulares y elementos anidados para cosas que pueden ser plurales:

<person first_name="Jane" last_name="Bloggs">
  <hobbie>mantenimiento de motocicletas</hobbie>
</person>

Por otro lado, si prefiere no usar atributos, podría especificar que cualquier elemento <hobbie> siempre debe representarse como arrays y que todos los demás elementos anidados deben ser valores escalares simples a menos que haya más de uno:

my $person = XMLin('./person.xml', forcearray => [ 'hobbie' ]);

La opción forcearray acepta una lista de nombres de elementos que siempre deben forzarse a una representación de array:

forcearray => [ qw(hobbie qualification childs_name) ]

Consulte la página del manual de XML::Simple para obtener más información.

¿De qué trata la opción keyattr?

Considere este ejemplo de XML:

<catalog>
  <part partnum="1842334" desc="Brida de alta presión" price="24.50" />
  <part partnum="9344675" desc="Junta roscada"      price="9.25" />
  <part partnum="5634896" desc="Arandela de baja tensión"   price="12.00" />
</catalog>

Podría cargarla con este código:

my $catalog = XMLin('./catalog.xml');

Lo que devolvería una estructura de datos como esta:

$catalog = {
    'part' => [
        {
          'partnum' => '1842334',
          'desc'    => 'Brida de alta presión',
          'price'   => '24.50'
        },
        {
          'partnum' => '9344675',
          'desc'    => 'Junta roscada',
          'price'   => '9.25'
        },
        {
          'partnum' => '5634896',
          'desc'    => 'Arandela de baja tensión',
          'price'   => '12.00'
        }
    ]
};

Entonces podría acceder a la descripción de la primera pieza del catálogo con este código:

print $catalog->{part}->[0]->{desc}, "\n";

Sin embargo, si quisiera acceder a la descripción de la pieza con el número de pieza "9344675", tendría que codificar un bucle como este:

foreach my $part (@{$catalog->{part}}) {
  if($part->{partnum} eq '9344675') {
    print $part->{desc}, "\n";
    last;
  }
}

El conocimiento de que cada elemento <part> tiene un atributo partnum único le permite eliminar esta búsqueda. Puede transmitir este conocimiento a XML::Simple de esta manera:

my $catalog = XMLin($xml, keyattr => ['partnum']);

Lo que devolverá una estructura de datos como esta:

$catalog = {
  'part' => {
    '5634896' => { 'desc' => 'Arandela de baja tensión',   'price' => '12.00' },
    '1842334' => { 'desc' => 'Brida de alta presión', 'price' => '24.50' },
    '9344675' => { 'desc' => 'Junta roscada',      'price' => '9.25'  }
  }
};

XML::Simple ha podido transformar $catalog->{part} de un arrayref a un hashref (con clave en partnum). Esta transformación se llama 'plegado de arrays'.

Mediante el uso del plegado de arrays, ahora puede indexar directamente a la descripción de la pieza que desea:

print $catalog->{part}->{9344675}->{desc}, "\n";

La opción 'keyattr' también habilita el plegado de arrays cuando la clave única está en un elemento anidado en lugar de un atributo. por ejemplo:

<catalog>
  <part>
    <partnum>1842334</partnum>
    <desc>Brida de alta presión</desc>
    <price>24.50</price>
  </part>
  <part>
    <partnum>9344675</partnum>
    <desc>Junta roscada</desc>
    <price>9.25</price>
  </part>
  <part>
    <partnum>5634896</partnum>
    <desc>Arandela de baja tensión</desc>
    <price>12.00</price>
  </part>
</catalog>

Consulte la página del manual de XML::Simple para obtener más información.

¿Entonces, cuál es el truco con 'keyattr'?

Una cosa a tener en cuenta es que puede obtener plegado de arrays incluso si no proporciona la opción keyattr. El valor predeterminado para esta opción es:

[ 'name', 'key', 'id']

Lo que significa que si sus elementos XML tienen un atributo (o elemento anidado) 'name', 'key' o 'id', entonces pueden ser plegados según esos valores. Esto significa que puede aprovechar el plegado de arrays simplemente eligiendo cuidadosamente los nombres de los atributos. Por otro lado, si realmente no desea ningún plegado de arrays, deberá establecer 'keyattr' a una lista vacía:

my $ref = XMLin($xml, keyattr => []);

Una segunda 'trampa' es que el plegado de arrays solo funciona en arrays. Eso puede parecer obvio, pero si solo hay un registro en su XML y no estableció la opción 'forcearray', entonces no se representará como un array y, en consecuencia, no se plegará en un hash. La moraleja es que si está utilizando el plegado de arrays, siempre debe activar la opción forcearray.

Probablemente también querrá ser lo más específico posible. Por ejemplo, la forma más segura de analizar el ejemplo de <catalog> anterior sería:

my $catalog = XMLin($xml, keyattr => { part => 'partnum'},
                          forcearray => ['part']);

Al usar el hashref para keyattr, puede especificar que solo los elementos <part> deben plegarse en el atributo 'partnum' (y que los elementos <part> no deben plegarse en ningún otro atributo).

Al proporcionar una lista de nombres de elementos para forcearray, se asegura de que el plegado funcionará incluso si solo hay un <part>. También se asegura de que si la clave única 'partnum' se proporciona en un elemento anidado, ese elemento tampoco se forzará a ser un array.

¿Cómo sé cómo debería verse mi estructura de datos?

'>¿Cómo sé cómo debe ser mi estructura de datos?

Las reglas son bastante sencillas:

  • cada elemento se representa como un hash
  • a menos que contenga solo texto, en cuyo caso será un valor escalar simple
  • o a menos que haya más de un elemento con el mismo nombre, en cuyo caso se representarán como un array
  • a menos que tenga activado el plegado de arrays, en cuyo caso se plegarán en un hash
  • los elementos vacíos (sin contenido de texto y sin atributos) se representarán como un hash vacío, una cadena vacía o undef, dependiendo del valor de la opción 'suppressempty'.

Si tiene alguna duda, utilice Data::Dumper, por ejemplo:

use XML::Simple;
use Data::Dumper;
my $ref = XMLin($xml);
print Dumper($ref);

Estoy recibiendo advertencias de 'Uso de valor no inicializado'

Probablemente esté intentando acceder a una clave de hash inexistente; intente usar Data::Dumper.

Estoy recibiendo un error de 'No es una referencia ARRAY'

Algo que esperaba que fuera un array no lo es. Las dos causas más probables son que olvidó usar 'forcearray' o que el array se plegó en un hash; intente usar Data::Dumper.

Estoy recibiendo un error de 'No existe tal campo de array'

Algo que esperaba que fuera un hash es en realidad un array. Quizás el plegado de arrays falló porque a un elemento le faltaba el atributo 'key'; intente usar Data::Dumper.

Estoy recibiendo un error de 'Fuera de memoria'

Algo en la estructura de datos no es como esperaba y Perl puede estar intentando autovivificar cosas sin éxito; intente usar Data::Dumper.

Si ya está usando Data::Dumper, intente llamar a Dumper() inmediatamente después de XMLin(), es decir, antes de intentar acceder a algo en la estructura de datos.

Mi orden de elementos se está desordenando

Si lee un archivo XML con XMLin() y luego lo vuelve a escribir con XMLout(), el orden de los elementos probablemente será diferente. (Sin embargo, si vuelve a leer el archivo con XMLin() obtendrá la misma estructura de datos Perl).

La reordenación ocurre porque XML::Simple utiliza hashrefs para almacenar sus datos y los hashes de Perl realmente no tienen ningún orden.

Es posible que una versión futura de XML::Simple utilice Tie::IxHash para almacenar los datos en hashrefs que conservan el orden. Sin embargo, esto no solucionará todos los casos de pérdida de orden de elementos.

Si su aplicación es realmente sensible al orden de los elementos, no utilice XML::Simple (y no ponga valores sensibles al orden en atributos).

XML::Simple convierte elementos anidados en atributos

Si lee un archivo XML con XMLin() y luego lo vuelve a escribir con XMLout(), algunos datos que originalmente se almacenaron en elementos anidados pueden terminar en atributos. (Sin embargo, si vuelve a leer el archivo con XMLin() obtendrá la misma estructura de datos Perl).

Hay varias formas de manejar esto:

  • use la opción 'forcearray' con XMLin()
  • use la opción 'noattr' con XMLout()
  • acostúmbrese
  • no use XML::Simple

¿Por qué XMLout() inserta elementos (o atributos) <name>?

Intente establecer keyattr => [].

Cuando llama a XMLin() para leer XML, la opción 'keyattr' controla si los arrays se 'pliegan' en hashes. De manera similar, cuando llama a XMLout(), la opción 'keyattr' controla si los hashes se 'despliegan' en arrays. Como se describió anteriormente, 'keyattr' está habilitado por defecto.

¿Por qué los elementos vacíos se representan como hashes vacíos?

Un elemento siempre se representa como un hash a menos que contenga solo texto, en cuyo caso se representa como una cadena escalar.

Si prefiere que los elementos vacíos se representen como cadenas vacías o como el valor indefinido, establezca la opción 'suppressempty' a '' o undef respectivamente.

¿Por qué está deprecado ParserOpts?

La opción "ParserOpts" es un remanente de la época en que XML::Simple solo funcionaba con la API de XML::Parser. Su valor se ignora por completo si está utilizando un analizador SAX, por lo que escribir código que dependiera de él le impediría aprovechar SAX.

Incluso si está utilizando XML::Parser, rara vez es necesario pasar opciones al objeto del analizador. Varias personas han escrito diciendo que usan esta opción para establecer la opción "ProtocolEncoding" de XML::Parser. No lo haga, ¡es incorrecto, Incorrecto, INCORRECTO! Corrija el documento XML para que esté bien formado y no tendrá problemas.

Habiendo dicho todo esto, mientras XML::Simple continúe admitiendo la API de XML::Parser, esta opción no se eliminará. Actualmente no hay planes para eliminar la compatibilidad con la API de XML::Parser.
