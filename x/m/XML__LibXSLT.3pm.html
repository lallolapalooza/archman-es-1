XML::LibXSLT(3) Documentación de Perl contribuida por el usuario XML::LibXSLT(3)

NOMBRE

XML::LibXSLT - Interfaz a la biblioteca libxslt de GNOME

SINOPSIS

use XML::LibXSLT;
use XML::LibXML;
my $xslt = XML::LibXSLT->new();
my $source = XML::LibXML->load_xml(location => 'foo.xml');
my $style_doc = XML::LibXML->load_xml(location=>'bar.xsl', no_cdata=>1);
my $stylesheet = $xslt->parse_stylesheet($style_doc);
my $results = $stylesheet->transform($source);
print $stylesheet->output_as_bytes($results);

DESCRIPCIÓN

Este módulo es una interfaz a libxslt del proyecto GNOME. Este es un motor XSLT extremadamente bueno, altamente compatible y también muy rápido. Tengo pruebas que demuestran que es más de dos veces más rápido que Sablotron.

OPCIONES

XML::LibXSLT tiene algunas opciones globales. Tenga en cuenta que estas probablemente no son seguras para hilos o incluso para bifurcaciones, así que configúrelas solo una vez por proceso. Cada una de estas opciones se puede llamar tanto como métodos de clase, como métodos de instancia. Sin embargo, sea cual sea la forma en que las llame, sigue configurando opciones globales.

Cada uno de los métodos de opción devuelve su valor anterior y puede ser llamado sin un parámetro para recuperar el valor actual.

max_depth
XML::LibXSLT->max_depth(1000);

Esta opción establece la profundidad máxima de recursión para una hoja de estilo. Consulte el final de la sección 5.4 de la especificación XSLT para más detalles sobre recursión y cómo detectarla. Si su hoja de estilo o archivo XML requiere una recursión seriamente profunda, esta es la forma de configurarla. El valor por defecto es 250.

max_vars
XML::LibXSLT->max_vars(100_000);

Esta opción establece el número máximo de variables para una hoja de estilo. Si su hoja de estilo o archivo XML requiere muchas variables, esta es la forma de aumentar su límite. El valor por defecto depende del sistema y puede variar.

debug_callback
XML::LibXSLT->debug_callback($subref);

Establece una función de devolución de llamada para mensajes de depuración. Si no configura esto, los mensajes de depuración serán ignorados.

register_function
XML::LibXSLT->register_function($uri, $name, $subref);
$stylesheet->register_function($uri, $name, $subref);

Registra una función de extensión XSLT mapeada a la URI dada. Por ejemplo:

XML::LibXSLT->register_function("urn:foo", "bar",
  sub { scalar localtime });

Registrará una función "bar" en el espacio de nombres "urn:foo" (que tiene que definir en su XSLT usando "xmlns:...") que devolverá la fecha y hora actuales como una cadena:

<xsl:stylesheet version="1.0"
  xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
  xmlns:foo="urn:foo">
<xsl:template match="/">
  La hora es: <xsl:value-of select="foo:bar()"/>
</xsl:template>
</xsl:stylesheet>

Los parámetros pueden estar en cualquier formato que desee. Si pasa una lista de nodos, será un objeto XML::LibXML::NodeList en su código perl, pero los valores ordinarios (cadenas, números y booleanos) serán escalares perl ordinarios. Si desea que sean valores "XML::LibXML::Literal", "XML::LibXML::Number" y "XML::LibXML::Number", entonces establezca la variable $XML::LibXSLT::USE_LIBXML_DATA_TYPES a un valor verdadero. Los valores de retorno pueden ser una lista de nodos o un valor simple: el código simplemente hará lo correcto. Pero solo se admite un único valor de retorno (una lista no se convierte en una lista de nodos).

register_element
$stylesheet->register_element($uri, $name, $subref)

Registra un elemento de extensión XSLT $name mapeado a la URI dada. Por ejemplo:

$stylesheet->register_element("urn:foo", "hello", sub {
        my $name = $_[2]->getAttribute( "name" );
        return XML::LibXML::Text->new( "Hello, $name!" );
});

Registrará un elemento "hello" en el espacio de nombres "urn:foo" que devuelve un nodo de texto "Hello, X!". Debe definir este espacio de nombres en su XSLT e incluir su prefijo en la lista "extension-element-prefixes":

<xsl:stylesheet version="1.0"
  xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
  xmlns:foo="urn:foo"
      extension-element-prefixes="foo">
<xsl:template match="/">
  <foo:hello name="bob"/>
</xsl:template>
</xsl:stylesheet>

La función de devolución de llamada recibe el nodo del documento de entrada como $_[1] y el nodo de la hoja de estilo como $_[2]. $_[0] está reservado para uso futuro.

API

Los siguientes métodos están disponibles en el nuevo objeto XML::LibXSLT:

parse_stylesheet($stylesheet_doc)
$stylesheet_doc aquí es un objeto XML::LibXML::Document (ver XML::LibXML) que representa un archivo XSLT. Este método devolverá un objeto XML::LibXSLT::Stylesheet, o undef en caso de fallo. Si el XSLT no es válido, se lanzará una excepción, así que envuelva la llamada a parse_stylesheet en un bloque eval{} para atraparla.

IMPORTANTE: $stylesheet_doc no debe contener secciones CDATA, de lo contrario, libxslt puede comportarse de forma errónea. La mejor manera de asegurarse de esto es cargar la hoja de estilo con la bandera no_cdata, por ejemplo:

my $stylesheet_doc = XML::LibXML->load_xml(location=>"some.xsl", no_cdata=>1);
parse_stylesheet_file($filename)
Exactamente lo mismo que lo anterior, pero analiza el nombre de archivo dado directamente.

Funciones de devolución de llamada de entrada

Para definir funciones de devolución de llamada de entrada específicas de XML::LibXSLT o XML::LibXSLT::Stylesheet, reutilice la API de funciones de devolución de llamada de entrada de XML::LibXML, como se describe en XML::LibXML::InputCallback(3).

input_callbacks($icb)
Habilita las funciones de devolución de llamada en $icb solo para este objeto XML::LibXSLT. $icb debe ser un objeto "XML::LibXML::InputCallback". Esto llamará a "init_callbacks" y "cleanup_callbacks" automáticamente durante el análisis o la transformación.

Funciones de devolución de llamada de seguridad

Para crear preferencias de seguridad para la transformación, consulte XML::LibXSLT::Security. Una vez que se hayan definido las preferencias de seguridad, puede aplicarlas a una instancia de XML::LibXSLT o XML::LibXSLT::Stylesheet utilizando el método security_callbacks().

XML::LibXSLT::Stylesheet

La API principal está en la hoja de estilo, aunque es bastante minimalista.

Una de las principales ventajas de XML::LibXSLT es que tiene un objeto de hoja de estilo genérico al que llama el método transform() pasando un documento para transformar. Esto le permite realizar múltiples transformaciones con una sola hoja de estilo sin requerir un repase.

transform(doc, %params)
my $results = $stylesheet->transform($doc, foo => "'bar'");
print $stylesheet->output_as_bytes($results);

Parámetros

\n

LibXSLT espera parámetros en formato XPath. Es decir, si desea\n pasar una cadena al motor XSLT, en realidad tiene que pasarla como una\n cadena entre comillas:

\n
$stylesheet->transform($doc, param => \"'string'\");
\n

¡Observe las comillas dentro de las comillas!

\n

Obviamente, esto no es muy divertido, por lo que puede facilitárselo usted mismo:

\n
$stylesheet->transform($doc, XML::LibXSLT::xpath_to_string(\n      param => \"string\"\n      ));
\n

La función de utilidad hace lo correcto con respecto a las cadenas\n en XPath, incluyendo cuando ya hay comillas incrustadas en su cadena.

XML::LibXSLT::Security

\n

Proporciona una interfaz al marco de seguridad de libxslt al\n permitir la definición de devoluciones de llamada que pueden restringir el acceso a diversos\n recursos (archivos o URL) durante una transformación.

\n

El marco de seguridad de libxslt permite definir devoluciones de llamada para ciertas\n acciones que una hoja de estilos puede intentar durante una transformación. Puede ser deseable restringir algunas de estas acciones (por ejemplo, escribir un\n nuevo archivo usando exsl:document). Las acciones que pueden ser restringidas son:

\n
\n
read_file
\n
Se llama cuando la hoja de estilos intenta abrir un archivo local (es decir, cuando se usa\n la función document()).
\n
write_file
\n
Se llama cuando se intenta escribir un archivo local (es decir, cuando se usa\n el elemento exsl:document).
\n
create_dir
\n
Se llama cuando se necesita crear un directorio para escribir un archivo.\n

NOTA: Por defecto, create_dir no está permitido. Para habilitarlo, se debe registrar una\n devolución de llamada.

\n
\n
read_net
\n
Se llama cuando la hoja de estilos intenta leer desde la red.
\n
write_net
\n
Se llama cuando la hoja de estilos intenta escribir en la red.
\n
\n
\n

Uso de XML::LibXSLT::Security

\n

La interfaz para este módulo es similar a\n XML::LibXML::InputCallback. Después de crear una nueva instancia, puede registrar\n devoluciones de llamada para cada una de las opciones de seguridad enumeradas anteriormente. Luego, aplica las\n preferencias de seguridad al objeto XML::LibXSLT o XML::LibXSLT::Stylesheet usando\n security_callbacks().

\n
my $security = XML::LibXSLT::Security->new();\n$security->register_callback( read_file  => $read_cb );\n$security->register_callback( write_file => $write_cb );\n$security->register_callback( create_dir => $create_cb );\n$security->register_callback( read_net   => $read_net_cb );\n$security->register_callback( write_net  => $write_net_cb );\n$xslt->security_callbacks( $security );\n-OR-\n$stylesheet->security_callbacks( $security );
\n

Las funciones de devolución de llamada registradas se llaman cuando se solicita acceso a un\n recurso. Si el acceso debe permitirse, la devolución de llamada debe\n devolver 1; si no, debe devolver 0. Las funciones de devolución de llamada deben aceptar los siguientes\n argumentos:

\n
\n
$tctxt
\n
Este es el contexto de transformación (XML::LibXSLT::TransformContext). Puede\n usarlo para obtener el objeto XML::LibXSLT::Stylesheet actual llamando a\n stylesheet().\n 
my $stylesheet = $tctxt->stylesheet();\n
\n

El objeto hoja de estilos se puede utilizar para compartir información contextual\n entre diferentes llamadas a las devoluciones de llamada de seguridad.

\n
\n
$value
\n
Este es el nombre del recurso (archivo o URI) que se ha solicitado.
\n
\n

Si una opción particular (excepto para\n \"create_dir\") no tiene una devolución de llamada registrada,\n entonces la hoja de estilos tendrá acceso completo para esa acción.

\n

BENCHMARK

\n

Se incluye en la distribución un script de benchmark simple, que\n tiene dos controladores: uno para LibXSLT y otro para Sablotron. El benchmark\n requiere los archivos de casos de prueba de la distribución XSLTMark que puede encontrar en\n http://www.datapower.com/XSLTMark/

\n

Coloque el directorio testcases en el directorio creado por esta\n distribución, y luego ejecute:

\n
perl benchmark.pl -h
\n

para obtener una lista de opciones.

\n

El benchmark requiere XML::XPath en este momento, pero espero eliminarlo\n pronto. También requiere Time::HiRes, que podría ser persuadido para eliminarlo,\n reemplazándolo con Benchmark.pm, pero aún no lo he hecho.

\n

Me encantaría obtener controladores para XML::XSLT y XML::Transformiix,\n si desea contribuir con ellos. También, si logra que esto funcione en Win32,\n me encantaría tener un controlador para MSXSLT a través de OLE, ¡para ver qué podemos hacer contra esos chicos de Redmond!

LIBRARY VERSIONS

XML::LibXSLT emite una advertencia si la versión en tiempo de ejecución de la biblioteca es inferior a la versión en tiempo de compilación.

XML::LibXSLT::LIBXSLT_VERSION()
Devuelve el número de versión de la biblioteca libxslt que se utilizó para compilar XML::LibXSLT como un entero. Por ejemplo, para libxslt-1.1.18, devolverá 10118.
XML::LibXSLT::LIBXSLT_DOTTED_VERSION()
Devuelve el número de versión de la biblioteca libxslt que se utilizó para compilar XML::LibXSLT como una cadena, por ejemplo, "1.1.18".
XML::LibXSLT::LIBXSLT_RUNTIME_VERSION()
Devuelve el número de versión de la biblioteca libxslt a la que está enlazada XML::LibXSLT en tiempo de ejecución (dinámica o estáticamente). Por ejemplo, para libxslt.so.1.1.18, devolverá 10118.
XML::LibXSLT::HAVE_EXLT()
Devuelve 1 si el módulo se compiló con libexslt, 0 en caso contrario.
