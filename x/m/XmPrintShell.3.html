XmPrintShell(library call) XmPrintShell(library call)

NOMBRE

XmPrintShell — clase de widget de shell utilizada para imprimir en Motif

SINOPSIS

#include <Xm/Print.h>
Boolean XmIsPrintShell(
Widget);

DESCRIPCIÓN

XmPrintShell proporciona al programador de aplicaciones Motif una API orientada a widgets Xt para algunos de los recursos de impresión X y un callback para impulsar la paginación.

XmPrintShell proporciona un callback simple para manejar la lógica de paginación y un conjunto de recursos para obtener y establecer atributos comunes de la impresora.

Si no se crea en una conexión XPrint, XmPrintShell se comporta como un shell de aplicación normal.

XmPrintShell también inicializa el mecanismo de manejo de eventos de extensión Xp, registrando un selector de extensión que llama a XpSelectInput y un despachador de eventos para eventos Xp de impresión y atributos, por lo que las aplicaciones pueden usar XtInsertEventTypeHandler para registrar su propio manejador con los eventos Xp.

Argumentos

No se proporciona ninguna función XmCreate, ya que se trata de un shell de nivel superior, creado muy probablemente a través de alguna rutina de creación de shell de Xt o XmPrintSetup.

Clases

XmPrintShell es una subclase de ApplicationShell; hereda comportamiento, recursos y rasgos de todas sus superclases. El puntero de clase es XmPrintShellWidgetClass.

XmNstartJobCallback
Especifica el callback que impulsa el inicio de la representación. Es seguro para una aplicación comenzar a renderizar después de que se haya activado este callback. XpStartJob debe ser llamado para activar este callback.
XmNendJobCallback
Especifica el callback que impulsa el final de la representación. Notifica al cliente que toda la representación ha sido procesada (ya sea en impresión a archivo o en cola normal). XpEndJob es llamado por el shell de impresión para activar este callback.
XmNpageSetupCallback
Especifica el callback que impulsa la disposición de la página. Es seguro para una aplicación comenzar a renderizar desde este callback incluso si el XmNstartJobCallback no se utiliza.
XmNminX, XmNminY, XmNmaxX, XmNmaxY
Especifican el área imprimible de la página en el contexto de impresión actual. XmPrintShell también mantiene un tamaño adecuado en todo momento actualizando su propia dimensión de widget cada vez que cambia un atributo, como la resolución u orientación. Se dimensiona en su rutina Initialize para que la aplicación pueda confiar en un tamaño adecuado antes de que se emita la primera llamada a StartPage.
XmNdefaultPixmapResolution
Indica la resolución en dpi (puntos por pulgada) de los archivos de imagen leídos y convertidos por Motif para los descendientes de widget de este shell. Se utiliza para determinar una relación de escala que se aplicará a los pixmaps creados a través de la conversión regular de pixmaps/iconos de los siguientes recursos de Widget:

XmLabel.label*Pixmap, XmIconG.*IconPixmap XmToggleB.selectPixmap, XmPushBG.armPixmap, XmIconG.*IconMask, XmMessageBox.symbolPixmap, XmContainer.*StatePixmap, ...

Excluyendo los recursos de pixmap que se utilizan para la teselación (XmNhighlightPixmap, XmNtopShadowPixmap, XmNbottomShadowPixmap, XmNbackgroundPixmap, ...)
XmNpdmNotificationCallback
Un callback que notifica a la aplicación sobre el estado del PDM (ver XmPrintPopupPDM). Se utiliza una estructura XmPrintShellCallbackStruct, con razón:
•
XmCR_PDM_NONE: no hay PDM disponible en esta pantalla para la selección nombrada (proporcionada en detalle)
•
XmCR_PDM_START_VXAUTH: el PDM no está autorizado para conectarse a la pantalla de video.
•
XmCR_PDM_START_PXAUTH: el PDM no está autorizado para conectarse a la pantalla de impresión.
•
XmCR_PDM_UP: el PDM está en funcionamiento
•
XmCR_PDM_OK: el PDM ha finalizado con estado OK
•
XmCR_PDM_CANCEL: el PDM ha finalizado con CANCELAR
•
XmCR_PDM_START_ERROR: el PDM no puede iniciarse debido a algún error (generalmente registrado)
•
XmCR_PDM_EXIT_ERROR: el PDM ha finalizado con un error

Información de Callback

Los callbacks XmNstartJobCallback, XmNendJobCallback, XmNpageSetupCallback y XmNpdmNotificationCallback operan sobre una XmPrintShellCallbackStruct, que se define de la siguiente manera:

typedef struct
{
    int     reason;  /* XmCR_START_JOB, XmCR_END_JOB,
                        XmCR_PAGE_SETUP, XmCR_PDM_* */
    XEvent  *event;
    XPContext print_context;
    Boolean last_page; /* in_out */
    XtPointer detail;
} XmPrintShellCallbackStruct;

Comportamiento Adicional

El campo last_page solo tiene significado cuando la razón es XmCR_PAGE_SETUP.

El callback de configuración de página se llama con last_page False para notificar a la aplicación que debe preparar su estado de diseño interno para la siguiente página. Típicamente, una aplicación basada en widgets cambiará el contenido de una Label que muestra el número de página, o desplazará el contenido del widget Text.

Cuando la aplicación ha procesado su última página, debe establecer el campo last_page en la estructura de callback a True. El callback se llamará una última vez después de eso con last_page False para notificar a la aplicación que puede limpiar de forma segura su estado interno (por ejemplo, destruir widgets).

No se debe realizar ningún dibujo dentro de la función de callback en la aplicación; este es un modelo de programación impulsado por eventos de exposición donde los widgets se renderizan a sí mismos desde sus métodos expose.

El shell de impresión llama a XpStartPage después del callback pageSetupCallback.

XmPrintShell(3)

NAME

XmPrintShell - The XmPrintShell widget is used to print widgets

SYNOPSIS

Structure definitions and callback structures:

#include <Xm/Print.h>

DESCRIPTION

The XmPrintShell widget is a subclass of VendorShell. It is used to print widgets. It is typically created by XmPrintSetup.

The XmPrintShell widget is used by the print manager to allow applications to manage the printing of their widgets to various output devices. The XmPrintShell widget is responsible for managing the print job, and for communicating with the printer server. Applications can use the XmPrintShell widget to set various print job attributes, such as the paper size, orientation, and resolution.

The XmPrintShell widget supports a number of callbacks that allow applications to customize the printing process. These callbacks are invoked at various stages of the print job, such as when a new page is started, or when the print job is completed.

The XmPrintShell widget also supports a number of resources that allow applications to control the appearance of the printed output. These resources include:

XmNdefaultPixmapResolution
This resource specifies the default resolution of pixmaps that are used in the printed output. The default value is 100 dpi. Pixmaps that are larger or smaller than the default resolution will be scaled automatically.
XmNprintShell
This resource specifies the widget that will be used to print the output. The default value is the XmPrintShell widget itself.
XmNprintCallback
This callback is invoked when the print job is completed. The callback function receives a pointer to a XmPrintJobCallbackStruct structure, which contains information about the print job.
XmNpageSetUpCallback
This callback is invoked when a new page is being set up for printing. The callback function receives a pointer to a XmPrintSetPageCBStruct structure, which contains information about the page being set up.
XmNprintShell
This resource specifies the widget that will be used to print the output. The default value is the XmPrintShell widget itself.

The XmPrintShell widget also supports the following notifications:

StartPageNotify
This notification is sent when a new page is being set up for printing.
XpEndPage
This notification is sent when a page has been printed.

The application can respond to these notifications by registering callbacks with the XmPrintShell widget. For example, an application can register a callback with StartPageNotify to perform any necessary setup for the new page, and register a callback with XpEndPage upon reception of StartPageNotify.

ERRORS/WARNINGS

XmPrintShell can generate the following warnings:

•
Not connected to a valid X Print Server: behavior undefined.
•
Attempt to set an invalid resolution on a printer: %s
•
Attempt to set an invalid orientation on a printer: %s

RETURN VALUE

Not applicable

Examples of XmNdefaultPixmapResolution usage:

•
An application reuses the same image sources it uses for the video interface, in XBM, XPM, PNG ot JPEG, to layout on its printed pages. In this case, scaling is seamless.
    ! icon.xpm is 30x30 pixels
    app*dialog.pushb.labelPixmap:icon.xpm
    ! print is 400dpi
    app.print*form.lab.labelPixmap:icon.xpm
    ! 120x120 pixels on the paper (auto scaling)
•
An application provides a new set of image files, for a given printer resolution (say 300). It doesn't want automatic scaling by the toolkit for that resolution, it wants scaling based on these 300dpi images for higher resolution. It creates its print shell inside using the name "printHiRes" and adds the following in its resource file:
    app.printHiRes.defaultPixmapResolution:300
    ! icon300.xpm is 120x120 pixels
    app.printHiRes*form.lab.labelPixmap:icon300.xpm
    ! 120x120 pixels on the paper (no scaling)

This way a printer resolution of 600 will result in a scale of a 300 dpi image by 2 (dpi=600 divided by base=300), while a printer resolution of 150 (using default print shell name "print") will use the 100 dpi icon scaled by 1.5 (dpi=150 divided by default base=100).
