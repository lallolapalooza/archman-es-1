BuildSAXBase(3) Documentación de Perl aportada por el usuario BuildSAXBase(3)

NOMBRE

XML::SAX::Base - Clase base para Controladores y Filtros SAX

SINOPSIS

package MiFiltro;
use XML::SAX::Base;
@ISA = ('XML::SAX::Base');

DESCRIPCIÓN

Este módulo tiene una tarea muy simple: ser una clase base para controladores y filtros PerlSAX. Su comportamiento por defecto es pasar la entrada directamente a la salida sin cambios. Puede ser útil usar este módulo como clase base para no tener que implementar, por ejemplo, la devolución de llamada characters().

Las principales ventajas que proporciona son la fácil distribución de eventos de la manera correcta (es decir, se encarga de verificar que el manejador haya implementado ese método, o haya definido un AUTOLOAD), y la garantía de que los filtros pasarán los eventos que no están implementando a los manejadores posteriores que aún podrían estar interesados en ellos.

ESCRIBIENDO CONTROLADORES Y FILTROS SAX

La Referencia de la API Perl Sax se encuentra en http://perl-xml.sourceforge.net/perl-sax/.

Escribir filtros SAX es tremendamente fácil: todo lo que necesitas hacer es heredar de este módulo y definir los eventos que quieres manejar. Una explicación más detallada se puede encontrar en http://www.xml.com/pub/a/2001/10/10/sax-filters.html.

Escribir controladores es igualmente simple. Lo único a lo que debes prestar atención es a NO llamar a los eventos tú mismo (esto se aplica también a los filtros). Por ejemplo:

package MiFiltro;
use base qw(XML::SAX::Base);
sub start_element {
  my $self = shift;
  my $data = shift;
  # hacer algo
  $self->{Handler}->start_element($data); # MAL
}

El ejemplo anterior funciona bien como precisamente eso: un ejemplo. Pero tiene varios defectos: 1) no comprueba si el manejador define start_element. Quizás no quiere ver ese evento, en cuyo caso no deberías lanzarlo (de lo contrario morirá). 2) no comprueba ContentHandler y luego Handler (es decir, no comprueba si el usuario no ha solicitado eventos en un manejador específico, y si no en el predeterminado), 3) si comprobara todo eso, no solo el código sería engorroso (ver el código fuente de este módulo para tener una idea) sino que probablemente tendría que comprobar DocumentHandler (en caso de que fuera SAX1) y AUTOLOADs potencialmente definidos en todos estos paquetes. Como puedes ver, eso sería bastante doloroso. En lugar de pasar por eso, simplemente recuerda usar código similar al siguiente:

package MiFiltro;
use base qw(XML::SAX::Base);
sub start_element {
  my $self = shift;
  my $data = shift;
  # hacer algo para filtrar
  $self->SUPER::start_element($data); # ¡BUENO (y fácil)!
}

De esta manera, una vez que hayas hecho tu trabajo, devuelves la pelota a XML::SAX::Base y ¡él se encarga de todos esos problemas por ti!

Ten en cuenta que el ejemplo anterior no se aplica solo a filtros; los controladores se beneficiarán de la misma característica.

MÉTODOS

Se definen varios métodos en esta clase con el propósito de la herencia. Algunos probablemente no necesiten ser sobrescritos (por ejemplo, parse_file), pero otros claramente deberían serlo (por ejemplo, parse). Las opciones para estos métodos se describen en la especificación PerlSAX2 disponible en http://cvs.sourceforge.net/cgi-bin/viewcvs.cgi/~checkout~/perl-xml/libxml-perl/doc/sax-2.0.html?rev=HEAD&content-type=text/html.

  • parse

    El método parse es el punto de entrada principal para analizar documentos. Internamente, el método parse detectará qué tipo de "cosa" estás analizando y llamará al método apropiado en tu clase de implementación. Aquí está la tabla de mapeo de lo que hay en las opciones Source (ver la especificación Perl SAX 2.0 para el significado de estos valores):

    Fuente Contiene           parse() llama
===============           =============
CharacterStream (*)       _parse_characterstream($stream, $options)
ByteStream                _parse_bytestream($stream, $options)
String                    _parse_string($string, $options)
SystemId                  _parse_systemid($string, $options)

    Sin embargo, ten en cuenta que estos métodos pueden no ser sensatos si tu clase de controlador no es para analizar XML. Un ejemplo podría ser un controlador DBI que genera XML/SAX a partir de una tabla de base de datos. Si ese es el caso, probablemente querrás escribir tu propio método parse().

    También ten en cuenta que la Fuente puede contener una entrada PublicId y una entrada Encoding. Para acceder a ellas, examina $options->{Source} tal como se pasa a tu método.

    (*) Un CharacterStream es un manejador de archivos que no necesita ninguna traducción de codificación. Esto se implementa como un manejador de archivos regular y solo funciona en Perl 5.7.2 o superior usando PerlIO. Para obtener un solo carácter, o un número de caracteres, de él, usa la función principal de Perl read(). Para obtener un solo byte (o un número de bytes), puedes usar sysread(). La codificación del stream debe estar en la entrada Encoding para la Fuente.

  • parse_file, parse_uri, parse_string

    Todas estas son variaciones de conveniencia de parse() y, de hecho, simplemente configuran las opciones antes de llamarla. Probablemente no necesites sobrescribir estas.

  • get_options

    Este es un método de conveniencia para obtener opciones al estilo SAX2, o de manera más genérica, ya sea como hashes o como hashrefs (devuelve un hashref). Probablemente querrás usar este método en tus propias implementaciones de parse() y new().

  • get_feature, set_feature

    Estas simplemente obtienen y establecen características, y lanzan las excepciones apropiadas definidas en la especificación si es necesario.

    Si tu subclase define características no definidas en esta, deberías sobrescribir estos métodos de manera que comprueben tus características primero, y luego llamen a los métodos de la clase base para las características no definidas por tu clase. Un ejemplo sería:

    sub get_feature {
    my $self = shift;
    my $feat = shift;
    if (exists $MY_FEATURES{$feat}) {
        # manejar la característica de varias maneras
    }
    else {
        return $self->SUPER::get_feature($feat);
    }
}

    Actualmente, esta parte no está implementada.

  • set_handler

    Este método toma un tipo de manejador (Handler, ContentHandler, etc.) y un objeto manejador como argumentos, y cambia el manejador actual para ese tipo de manejador, encargándose de restablecer el estado interno que necesita ser restablecido. Esto permite cambiar un manejador durante el análisis sin encontrar problemas (cambiarlo directamente en el objeto analizador probablemente cause problemas).

  • set_document_handler, set_content_handler, set_dtd_handler, set_lexical_handler, set_decl_handler, set_error_handler, set_entity_resolver

    Estos son solo envoltorios simples del método anterior, y toman un objeto manejador como argumento. Internamente, simplemente llaman a set_handler con los argumentos correctos.

  • get_handler

    Lo opuesto a set_handler, este método toma una cadena opcional que contiene un tipo de manejador (DTDHandler, ContentHandler, etc. 'Handler' se usa si no se pasa ningún tipo). Devuelve una referencia al objeto que implementa esa clase, o undef si ese tipo de manejador no está establecido para el controlador/filtro actual.

  • get_document_handler, get_content_handler, get_dtd_handler, get_lexical_handler, get_decl_handler, get_error_handler, get_entity_resolver

    Estos son solo envoltorios simples del método get_handler(), y no toman argumentos. Internamente, simplemente llaman a get_handler con el nombre de tipo de manejador correcto.

XML::SAX::BuildSAXBase(3pm)

NAME

XML::SAX::BuildSAXBase - A base class for SAX2 drivers and filters

SYNOPSIS

 use XML::SAX::Base;
 use XML::SAX::Builder;
 my $parser = XML::SAX::Builder->new(
  Handlers => {
   'http://xml.org/sax/handlers/LexicalHandler' => $lexical_handler,
   'http://xml.org/sax/handlers/DeclHandler' => $decl_handler,
  }
 );
 my $driver = MySAXDriver->new(
  Handlers => {
   'http://xml.org/sax/handlers/DocumentHandler' => $doc_handler,
  }
 );
 $parser->parse_uri( $driver, "http://example.com/doc.xml" );

DESCRIPTION

This module provides a base class for creating SAX drivers and filters under the XML::SAX distribution.

SAX2 is a standard API for parsing XML documents that allows applications to receive document information as a stream of events. SAX2 drivers are responsible for parsing an XML document and generating the SAX events. SAX2 filters are objects that sit between a driver and a handler, allowing you to modify or augment the SAX event stream.

This module aims to provide a convenient way to build both drivers and filters by providing default implementations for the SAX2 event handler methods.

WRITING SAX DRIVERS AND FILTERS

To write a SAX driver or filter, you typically subclass XML::SAX::Base. You then implement the methods defined by the various SAX2 event handler interfaces that you are interested in.

The SAX2 standard defines several handler interfaces, including:

  • XML::SAX::DocumentHandler: Basic document events (startDocument, endDocument, startElement, endElement, characters, ignorableWhitespace, processingInstruction, skippedEntity).
  • XML::SAX::DTDHandler: DTD events (notationDecl, unparsedEntityDecl).
  • XML::SAX::ErrorHandler: Error events (warning, error, fatalError).
  • XML::SAX::LexicalHandler: Lexical events (startDTD, endDTD, startEntity, endEntity, comment, startCDATA, endCDATA).
  • XML::SAX::DeclHandler: Declaration events (elementDecl, attributeDecl, internalEntityDecl, externalEntityDecl).

When you subclass XML::SAX::Base, you can optionally specify which handlers you want to implement. If you don't specify any, you'll get a generic driver that just passes events through.

To create a filter, you typically pass a reference to another handler object when you create your filter. The filter's methods will then call the corresponding methods on the referenced handler.

Example of a simple filter that counts the number of elements:

 package ElementCounter;
 use base qw(XML::SAX::Base);
 sub new {
  my ($class, $driver) = @_;
  my $self = $class->SUPER::new($driver);
  $self->{count} = 0;
  return $self;
 }
 sub startElement {
  my ($self, $element) = @_;
  $self->{count}++;
  # Pass the event on to the next handler
  $self->SUPER::startElement($element);
 }
 sub endElement {
  my ($self, $element) = @_;
  # Pass the event on to the next handler
  $self->SUPER::endElement($element);
 }
 sub count {
  my ($self) = @_;
  return $self->{count};
 }
 1;

Example of a simple driver that prints element names:

 package MySAXDriver;
 use base qw(XML::SAX::Base);
 sub startElement {
  my ($self, $element) = @_;
  print "Start Element: ", $element->{Name}, "\n";
  # Pass the event on to the next handler
  $self->SUPER::startElement($element);
 }
 sub endElement {
  my ($self, $element) = @_;
  print "End Element: ", $element->{Name}, "\n";
  # Pass the event on to the next handler
  $self->SUPER::endElement($element);
 }
 1;
