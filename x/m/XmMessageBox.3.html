NOMBRE

XmMessageBox — La clase de widget MessageBox

SINOPSIS

#include <Xm/MessageB.h>

DESCRIPCIÓN

MessageBox es una clase de diálogo utilizada para crear diálogos de mensaje simples. Se proporcionan diálogos de conveniencia basados en MessageBox para varias tareas de interacción comunes, que incluyen proporcionar información, hacer preguntas e informar errores.

Un diálogo MessageBox es típicamente transitorio por naturaleza, se muestra durante la duración de una sola interacción. MessageBox es una subclase de BulletinBoard y depende de ella para gran parte de su comportamiento general de diálogo.

El valor predeterminado para XmNinitialFocus es el valor de XmNdefaultButton.

Un MessageBox típico contiene un símbolo de mensaje, un mensaje y hasta tres botones de comando predeterminados: OK, Cancelar y Ayuda. Se distribuye con el símbolo y el mensaje en la parte superior y los botones de comando en la parte inferior. El botón Ayuda se posiciona al lado de los otros botones de comando. Puede localizar los símbolos y etiquetas de botones predeterminados para los diálogos de conveniencia de MessageBox.

El usuario puede especificar recursos en un archivo de recursos para los gadgets creados automáticamente que contienen el mapa de bits del símbolo de MessageBox y el separador. Los nombres de los gadgets son Symbol y Separator.

Un MessageBox también se puede personalizar creando y gestionando nuevos hijos que se agregan a los hijos de MessageBox creados automáticamente por los diálogos de conveniencia. En el caso de TemplateDialog, solo se crea el hijo separador de forma predeterminada. Si se especifican los recursos de devolución de llamada, cadena o símbolo de mapa de bits, se creará el hijo apropiado.

Los hijos adicionales se distribuyen de la siguiente manera:

•
El primer hijo MenuBar se coloca en la parte superior de la ventana. El rasgo XmQTmenuSystem se utiliza para verificar que es el primer hijo MenuBar.
•
Todos los widgets o gadgets se colocan después del botón OK en el orden de su creación (este orden se verifica utilizando el rasgo XmQTactivatable).
•
Un hijo que no está en las categorías anteriores se coloca encima de la fila de botones. Si existe una etiqueta de mensaje, el hijo se coloca debajo de la etiqueta. Si existe un mapa de bits de mensaje, pero falta una etiqueta de mensaje, el hijo se coloca en la misma fila que el mapa de bits. El hijo se comporta como un área de trabajo y crece o se encoge para llenar el espacio sobre la fila de botones. La distribución de varios hijos de área de trabajo no está definida.

Al inicializar, MessageBox busca los siguientes archivos de mapa de bits:

•
xm_error
•
xm_information
•
xm_question
•
xm_working
•
xm_warning

Consulte XmGetPixmap(3) para obtener una lista de las rutas que se buscan para estos archivos.

MessageBox utiliza los rasgos XmQTactivatable y XmQTmenuSystem.

Clases

MessageBox hereda comportamiento, recursos y rasgos de Core, Composite, Constraint, XmManager y XmBulletinBoard.

El puntero de clase es xmMessageBoxWidgetClass.

El nombre de la clase es XmMessageBox.

Especifica la lista de callbacks que se llama cuando el usuario hace clic en el botón de cancelar. La razón enviada por el callback es XmCR_CANCEL.
XmNcancelLabelString
Especifica la etiqueta de texto para el botón de cancelar. El valor predeterminado para este recurso depende de la configuración regional. En la configuración regional C, el valor predeterminado es Cancel.

XmDIALOG_QUESTION
Indica un QuestionDialog.
XmDIALOG_TEMPLATE
Indica un TemplateDialog. El TemplateDialog contiene solo un hijo separador. No tiene un símbolo de mensaje asociado.
XmDIALOG_WARNING
Indica un WarningDialog.
XmDIALOG_WORKING
Indica un WorkingDialog.
Si este recurso se cambia con XtSetValues, el mapa de bits del símbolo se modifica al nuevo XmNdialogType a menos que XmNsymbolPixmap también se esté estableciendo en la llamada a XtSetValues. Descripción

El widget XmMessageBox proporciona un conjunto de widgets predefinidos para mostrar mensajes. Estos widgets son un conjunto de XmBulletinBoard que incluye un área de mensaje (una etiqueta o un área de texto) y una línea de botones. El área de mensaje puede contener una etiqueta o un área de texto, y los botones son para OK, Cancelar y Ayuda. El área de mensaje puede tener un ícono opcional.

El widget XmMessageBox maneja la creación de los widgets hijos:

  • XmLabel o XmText para el mensaje.
  • XmSeparator para separar el área del mensaje de los botones.
  • XmFrame para cada botón.
  • XmPushButton para cada botón.

Los botones se crean y se configuran según los siguientes recursos:

  • XmNokLabelString: Etiqueta para el botón OK.
  • XmNokCallback: Callbacks para el botón OK.
  • XmNcancancelLabelString: Etiqueta para el botón Cancelar.
  • XmNcancelCallback: Callbacks para el botón Cancelar.
  • XmNhelpLabelString: Etiqueta para el botón Ayuda.
  • XmNhelpCallback: Callbacks para el botón Ayuda.

El widget XmMessageBox también admite los siguientes recursos para el ícono:

  • XmNsymbolPixmap: El pixmap para el ícono.
  • XmNsymbolType: El tipo de ícono (por ejemplo, error, advertencia, información).

Los recursos para el área del mensaje incluyen:

  • XmNmessageString: La cadena del mensaje.
  • XmNmessageAlignment: La alineación del mensaje.

El widget XmMessageBox hereda de XmBulletinBoard y, por lo tanto, admite todos los recursos de XmBulletinBoard, así como los recursos de XmManager y XmWidget.

Información de Callbacks

Se pasa un puntero a la siguiente estructura a cada callback:

typedef struct
{
        int reason;
        XEvent *event;
} XmAnyCallbackStruct;
reason
Indica por qué se invocó el callback
event
Punta al XEvent que activó el callback

Traducciones

XmMessageBox incluye las traducciones de XmManager.

Comportamiento Adicional

El widget XmMessageBox tiene el siguiente comportamiento adicional:

<Key><osfCancel>:
Llama a los callbacks de activación para el botón de cancelar si es sensible.
<Key><osfActivate>:
Llama a los callbacks de activación para el botón que tiene el foco del teclado. Si ningún botón tiene el foco del teclado, llama a los callbacks de activación para el botón predeterminado si es sensible.
<Ok Button Activated>:
Llama a los callbacks para XmNokCallback.
<Cancel Button Activated>:
Llama a los callbacks para XmNcancelCallback.
<Help Button Activated>:
Llama a los callbacks para XmNhelpCallback.
<FocusIn>:
Llama a los callbacks para XmNfocusCallback.
<Map>:
Llama a los callbacks de XmNmapCallback si el padre es un DialogShell.
<Unmap>:
Llama a los callbacks de XmNunmapCallback si el padre es un DialogShell.

Vinculaciones Virtuales

Las vinculaciones para teclas virtuales son específicas del proveedor. Para obtener información sobre las vinculaciones de botones y teclas virtuales, consulte VirtualBindings(3).
