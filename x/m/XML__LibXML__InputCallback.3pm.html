XML::LibXML::InputCallback(3) Documentación Perl aportada por el usuario XML::LibXML::InputCallback(3)

NOMBRE

XML::LibXML::InputCallback - Clase XML::LibXML para Callbacks de Entrada

SINOPSIS

use XML::LibXML;

DESCRIPCIÓN

Puede obtener resultados inesperados si intenta cargar documentos externos durante el análisis de libxml2 si la ubicación del recurso no es HTTP, FTP o una ubicación relativa, sino una ruta absoluta, por ejemplo. Para sortear esta limitación, puede agregar su propio manejador de entrada para abrir, leer y cerrar tipos particulares de ubicaciones o clases de URI. Usando estos manejadores de callback de entrada, puede manejar sus propios esquemas de URI personalizados, por ejemplo.

Los callbacks de entrada se utilizan cada vez que XML::LibXML tiene que obtener algo más que entidades analizadas externamente de algún lugar. Se implementan utilizando una pila de callbacks en la capa Perl, de forma análoga a la pila de callbacks nativa de libxml2.

La clase XML::LibXML::InputCallback registra transparentemente los callbacks de entrada para los procesos de análisis de libxml2.

¿Cómo funciona XML::LibXML::InputCallback?

La biblioteca libxml2 ofrece una implementación de callback solo como funciones globales. Para solucionar los problemas derivados de tener solo callbacks globales, por ejemplo, si la misma pila de callbacks global está siendo manipulada por diferentes aplicaciones que se ejecutan juntas en un solo entorno de servidor web Apache, XML::LibXML::InputCallback viene con una parte orientada a objetos y una parte orientada a funciones.

Usando la parte orientada a funciones, se puede manipular la pila de callbacks global de libxml2. Estas funciones pueden usarse como interfaz para los callbacks en la Capa C y XS. En la parte orientada a objetos, se implementan operaciones para trabajar con la pila de callbacks "pseudo-localizada". Actualmente, puede registrar y anular el registro de callbacks en la capa Perl e inicializarlos por cada analizador.

Grupos de Callbacks

Los callbacks de entrada de libxml2 vienen en grupos. Un grupo contiene un coincidor de URI (match), un constructor de flujo de datos (open), un lector de flujo de datos (read) y un destructor de flujo de datos (close). Los callbacks se pueden manipular solo por grupo.

El Proceso de Análisis

El proceso de análisis funciona en un flujo de datos XML, a lo largo del cual se pueden incrustar enlaces a otros recursos. Pueden ser enlaces a DTDs externas o XIncludes, por ejemplo. Estos recursos se identifican mediante URIs. La implementación de callback de libxml2 asume que un grupo de callbacks puede manejar una cierta cantidad de URIs y un cierto esquema de URI. Por defecto, se registran manejadores de callback para file://*, file:://*.gz, http://* y ftp://*.

Los grupos de callbacks en la pila de callbacks se procesan de arriba a abajo, lo que significa que los grupos de callbacks registrados más tarde se procesarán antes que los registrados anteriormente.

Mientras se analiza el flujo de datos, el analizador libxml2 verifica si un grupo de callbacks registrado manejará una URI; si no lo hará, la URI se interpretará como file://URI. Para manejar una URI, el callback match deberá devolver '1'. Si eso sucede, el manejo de la URI se pasará a ese grupo de callbacks. A continuación, la URI se pasará al callback open, que debería devolver una referencia al flujo de datos si abrió el archivo con éxito, '0' en caso contrario. Si la apertura del flujo fue exitosa, el callback read se llamará repetidamente hasta que devuelva una cadena vacía. Después del callback de lectura, se llamará al callback close para cerrar el flujo.

Organización de grupos de callbacks en XML::LibXML::InputCallback

Los grupos de callbacks se implementan como una pila (Array), cada entrada contiene una referencia a un array de los callbacks. Para la biblioteca libxml2, la implementación de callback de XML::LibXML::InputCallback aparece como un solo grupo de callbacks. Sin embargo, la implementación de Perl permite administrar diferentes pilas de callbacks por cada analizador libxml2.

Usando XML::LibXML::InputCallback

Después de la instanciación del objeto usando el constructor sin parámetros, puede registrar grupos de callbacks.

my $input_callbacks = XML::LibXML::InputCallback->new();
$input_callbacks->register_callbacks([ $match_cb1, $open_cb1,
                                       $read_cb1, $close_cb1 ] );
$input_callbacks->register_callbacks([ $match_cb2, $open_cb2,
                                       $read_cb2, $close_cb2 ] );
$input_callbacks->register_callbacks( [ $match_cb3, $open_cb3,
                                        $read_cb3, $close_cb3 ] );
$parser->input_callbacks( $input_callbacks );
$parser->parse_file( $some_xml_file );

¿Qué pasa con el antiguo sistema de callbacks anterior a XML::LibXML::InputCallback?

En las versiones de XML::LibXML anteriores a la 1.59, es decir, sin el módulo XML::LibXML::InputCallback, podía definir sus callbacks de forma global o local. Todavía puede hacerlo usando XML::LibXML::InputCallback y, además, ¡puede definir los callbacks por cada analizador!

Si utiliza la antigua interfaz de callbacks a través de callbacks globales, XML::LibXML::InputCallback los tratará con una prioridad menor que los registrados usando la nueva interfaz. Los callbacks globales no anularán los grupos de callbacks registrados usando la nueva interfaz. Los callbacks locales se adjuntan a una instancia de analizador específica, por lo tanto, se tratan con la máxima prioridad. Si el callback match del grupo de callbacks registrado como variable local es idéntico a uno de los grupos de callbacks registrados usando la nueva interfaz, ese grupo de callbacks será reemplazado.

Los usuarios de la antigua implementación de callbacks cuyo callback open devolvía una cadena simple, tendrán que adaptar su código para devolver una referencia a esa cadena después de actualizar a la versión >= 1.59. ¡El nuevo sistema de callbacks solo puede manejar que el callback open devuelva una referencia!

Reenvía el callback open de libxml2 a la función de callback correspondiente a nivel Perl.
_callback_read
Reenvía la solicitud de lectura a la función de callback correspondiente a nivel Perl y devuelve el resultado a libxml2.
_callback_close
Reenvía el callback close de libxml2 a la función de callback correspondiente a nivel Perl.

NAME

XML::LibXML::InputCallback - Handles custom URI input callbacks.

SYNOPSIS

  use XML::LibXML;

  # Define the four callback functions
  sub match_uri { ... }
  sub open_uri { ... }
  sub read_uri { ... }
  sub close_uri { ... }

  my $input_callbacks = XML::LibXML::InputCallback->new();
  $input_callbacks->register_callbacks([ \&match_uri, \&open_uri,
                                         \&read_uri, \&close_uri ] );

  my $parser = XML::LibXML::Parser->new();
  $parser->input_callbacks( $input_callbacks );

  # Parse a file or string that uses the custom URI scheme
  my $dom = $parser->parse_file( $some_uri_with_custom_scheme );
  my $dom = $parser->parse_string( $xml_string );

DESCRIPTION

XML::LibXML::InputCallback allows you to register custom callback functions that will be used by libxml2 to retrieve XML documents from URIs other than regular file paths or HTTP. This is useful for loading XML from databases, memory buffers, or other custom sources.

The callbacks are registered as a group. If any callback within the group fails or returns an error, all callbacks in that group will be unregistered and removed from the libxml2 callback stack.

INTERFACE DESCRIPTION

The following methods are available:

new()
Creates a new XML::LibXML::InputCallback object.
register_callbacks( $callbacks )
Registers a group of four callback functions. The callbacks must be provided as an array reference in the following order:
match_uri( $uri )
This function is called with the URI that libxml2 is trying to access. It should return true if this callback group should handle the URI, and false otherwise. It is used to determine which callback group to use for a given URI.
open_uri( $uri )
This function is called when the match_uri callback returned true. It should open the resource represented by the URI and return a filehandle-like object (an IO::Handle or similar) that can be read from. If an error occurs, it should return undef.
read_uri( $handle, $length )
This function is called to read data from the opened resource. It receives the handle returned by open_uri and the maximum number of bytes to read ($length). It should return the data read as a string. If the end of the resource is reached, it should return an empty string ('').
close_uri( $handle )
This function is called to close the resource. It receives the handle returned by open_uri and should perform any necessary cleanup, such as closing a file or freeing memory.

If any of these callbacks fail (return undef or throw an exception), the entire callback group will be removed from the parser. If multiple callback groups are defined, and they are defined in different callback groups, ALL of them will be deleted from the stack.

init_callbacks( $parser )
Initializes the callback system for the provided parser before starting a parsing process.
cleanup_callbacks()
Resets global variables and the libxml2 callback stack.
lib_init_callbacks()
Used internally for callback registration at C-level.
lib_cleanup_callbacks()
Used internally for callback resetting at the C-level.

EXAMPLE CALLBACKS

The following example is a purely fictitious example that uses a MyScheme::Handler object that responds to methods similar to an IO::Handle.

# Define the four callback functions
sub match_uri {
    my $uri = shift;
    return $uri =~ /^myscheme:/; # trigger our callback group at a 'myscheme' URIs
}
sub open_uri {
    my $uri = shift;
    my $handler = MyScheme::Handler->new($uri);
    return $handler;
}
# The returned $buffer will be parsed by the libxml2 parser
sub read_uri {
    my $handler = shift;
    my $length = shift;
    my $buffer;
    read($handler, $buffer, $length);
    return $buffer; # $buffer will be an empty string '' if read() is done
}
# Close the handle associated with the resource.
sub close_uri {
    my $handler = shift;
    close($handler);
}
# Register them with a instance of XML::LibXML::InputCallback
my $input_callbacks = XML::LibXML::InputCallback->new();
$input_callbacks->register_callbacks([ \&match_uri, \&open_uri,
                                       \&read_uri, \&close_uri ] );
# Register the callback group at a parser instance
$parser->input_callbacks( $input_callbacks );
# $some_xml_file will be parsed using our callbacks
$parser->parse_file( $some_xml_file );
