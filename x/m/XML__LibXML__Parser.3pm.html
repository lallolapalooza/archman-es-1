NOMBRE

XML::LibXML::Parser - Análisis de datos XML con XML::LibXML

SINOPSIS

use XML::LibXML '1.70';
# Constructor del analizador
$parser = XML::LibXML->new();
$parser = XML::LibXML->new(opcion=>valor, ...);
$parser = XML::LibXML->new({opcion=>valor, ...});
# Análisis de XML
$dom = XML::LibXML->load_xml(
    location => $archivo_o_url
    # opciones del analizador ...
  );
$dom = XML::LibXML->load_xml(
    string => $cadena_xml
    # opciones del analizador ...
  );
$dom = XML::LibXML->load_xml(
    string => (\$cadena_xml)
    # opciones del analizador ...
  );
$dom = XML::LibXML->load_xml({
    IO => $manejador_archivo_perl
    # opciones del analizador ...
  });
$dom = $parser->load_xml(...);
# Análisis de HTML
$dom = XML::LibXML->load_html(...);
$dom = $parser->load_html(...);
# Análisis de fragmentos XML bien formados
$fragmento = $parser->parse_balanced_chunk( $cadena_xml_wb, $codificacion );
# Procesamiento de XInclude
$parser->process_xincludes( $doc );
$parser->processXIncludes( $doc );
# Interfaces del analizador estilo antiguo
$doc = $parser->parse_file( $nombre_archivo_xml );
$doc = $parser->parse_fh( $fh_io );
$doc = $parser->parse_string( $cadena_xml );
$doc = $parser->parse_html_file( $archivo_html, \%opts );
$doc = $parser->parse_html_fh( $fh_io, \%opts );
$doc = $parser->parse_html_string( $cadena_html, \%opts );
# Analizador push
$parser->parse_chunk($cadena, $terminar);
$parser->init_push();
$parser->push(@datos);
$doc = $parser->finish_push( $recuperar );
# Establecer/consultar opciones del analizador
$parser->option_exists($nombre);
$parser->get_option($nombre);
$parser->set_option($nombre,$valor);
$parser->set_options({$nombre=>$valor,...});
# Catálogos XML
$parser->load_catalog( $archivo_catalogo );

ANÁLISIS

Un documento XML es leído en una estructura de datos, como un árbol DOM, por un programa llamado analizador. XML::LibXML actualmente proporciona cuatro interfaces de analizador diferentes:

  • Un Analizador DOM Pull
  • Un Analizador DOM Push
  • Un Analizador SAX
  • Un Analizador SAX basado en DOM.

Creación de una instancia del analizador

XML::LibXML proporciona una interfaz OO a las funciones del analizador libxml2. Por lo tanto, debe crear una instancia del analizador antes de poder analizar cualquier dato XML.

new
$parser = XML::LibXML->new();
$parser = XML::LibXML->new(opcion=>valor, ...);
$parser = XML::LibXML->new({opcion=>valor, ...});

Crea una nueva instancia de analizador XML y HTML. Cada instancia de analizador mantiene valores predeterminados para varias opciones del analizador. Opcionalmente, se puede pasar una referencia a hash o una lista de pares opcion => valor para establecer un conjunto predeterminado diferente de opciones. A menos que se especifique lo contrario, las opciones "load_ext_dtd" y "expand_entities" se establecen en 1. Consulte "Opciones del analizador" para obtener una lista de las opciones del analizador libxml2.

Analizador DOM

Una de las interfaces de analizador comunes de XML::LibXML es el analizador DOM. Este analizador lee datos XML en una estructura de datos similar a DOM, por lo que cada etiqueta puede ser accedida y transformada.

El analizador DOM de XML::LibXML no solo es capaz de analizar datos XML, sino también archivos HTML (estrictos). Hay tres formas de analizar documentos: como una cadena, como un manejador de archivos Perl o como un nombre de archivo/URL. El valor de retorno de cada uno es un objeto XML::LibXML::Document, que es un objeto DOM.

Todas las funciones que se enumeran a continuación lanzarán una excepción si el documento no es válido. Para evitar que esto cause la terminación de su programa, envuelva la llamada en un bloque eval{}

load_xml
$dom = XML::LibXML->load_xml(
    location => $archivo_o_url
    # opciones del analizador ...
  );
$dom = XML::LibXML->load_xml(
    string => $cadena_xml
    # opciones del analizador ...
  );
$dom = XML::LibXML->load_xml(
    string => (\$cadena_xml)
    # opciones del analizador ...
  );
$dom = XML::LibXML->load_xml({
    IO => $manejador_archivo_perl
    # opciones del analizador ...
  });
$dom = $parser->load_xml(...);

Esta función está disponible desde XML::LibXML 1.70. Proporciona una interfaz fácil de usar para el analizador XML que analiza el archivo (o URL no HTTPS) dado, la cadena o el flujo de entrada en un árbol DOM. Los argumentos se pueden pasar en una referencia HASH o como pares nombre => valor. La función se puede llamar como un método de clase o como un método de objeto. En ambos casos, internamente crea una nueva instancia del analizador pasando las opciones del analizador especificadas; si se llama como un método de objeto, clona el analizador original (preservando su configuración) y además aplica las opciones especificadas al nuevo analizador. Consulte el constructor "new" y "Opciones del analizador" para obtener más información.

Tenga en cuenta que, debido a una limitación en la biblioteca subyacente libxml2, esta llamada no reconoce las URL basadas en HTTPS. (Tratará una URL HTTPS como un nombre de archivo, probablemente lanzando una excepción de "No existe tal archivo o directorio").

load_html
$dom = XML::LibXML->load_html(...);
$dom = $parser->load_html(...);

Esta función está disponible desde XML::LibXML 1.70. Tiene el mismo uso que "load_xml", proporcionando una interfaz al analizador HTML. Consulte "load_xml" para obtener más información.

El análisis de HTML puede causar problemas, especialmente si se utiliza el ampersand ('&amp;'). Este es un problema común si se analizan códigos HTML que contienen enlaces a scripts CGI. Dichos enlaces hacen que el analizador lance errores. En tales casos, libxml2 aún analiza todo el documento como si no hubiera habido ningún error, pero el error hace que XML::LibXML detenga el proceso de análisis. Sin embargo, el documento no se pierde. Dichos documentos HTML deben analizarse utilizando el indicador recover. Por defecto, la recuperación está desactivada.

Las funciones descritas anteriormente están implementadas para analizar documentos bien formados. En algunos casos, un programa recibe XML bien equilibrado en lugar de documentos bien formados (por ejemplo, un fragmento XML de una base de datos). Con XML::LibXML no es necesario envolver dichos fragmentos en el código, ya que XML::LibXML es capaz incluso de analizar fragmentos XML bien equilibrados.

parse_balanced_chunk
$fragmento = $parser->parse_balanced_chunk( $cadena_xml_wb, $codificacion );

Esta función analiza una cadena XML bien equilibrada en un DocumentFragment de XML::LibXML. El primer argumento contiene la cadena de entrada, el segundo argumento opcional se puede usar para especificar la codificación de caracteres de la entrada (se asume UTF-8 por defecto).

parse_xml_chunk
Este es el nombre antiguo de parse_balanced_chunk(). Debido a que puede causar confusión con la interfaz del analizador push, esta función ya no debe utilizarse.

Por defecto, XML::LibXML no procesa las etiquetas XInclude dentro de un documento XML (ver la sección de opciones más abajo). XML::LibXML permite post-procesar un documento para expandir las etiquetas XInclude.

process_xincludes
$parser->process_xincludes( $doc );

Después de que un documento se analiza en una estructura DOM, es posible que desee expandir las etiquetas XInclude del documento. Esta función procesa la estructura del documento dada y expande todas las etiquetas XInclude (o lanza un error) utilizando las banderas y callbacks de la instancia del analizador dada.

Tenga en cuenta que el Árbol resultante contiene nodos adicionales (de tipo XML_XINCLUDE_START y XML_XINCLUDE_END) después de procesar con éxito el documento. Estos nodos indican dónde se incluyeron los datos en el árbol original. Si el documento se serializa, estos nodos adicionales no aparecerán.

Recuerde: ¡Un documento con XIncludes procesados difiere del documento original después de la serialización, ya que las etiquetas XInclude originales no se restaurarán!

Si la bandera del analizador "expand_xincludes" se establece en 1, no necesita post-procesar el documento analizado.

processXIncludes
$parser->processXIncludes( $doc );

NOTA IMPORTANTE: Esta documentación refleja las banderas del analizador disponibles en libxml2 2.7.3. Algunas opciones no tienen efecto si se utiliza una versión anterior de libxml2.

Cada una de las banderas enumeradas a continuación está etiquetada

/parser/
si se puede usar con un objeto analizador "XML::LibXML" (es decir, pasado a "XML::LibXML->new", "XML::LibXML->set_option", etc.)
/html/
si se puede pasar a los métodos "parse_html_*"
/reader/
si se puede usar con "XML::LibXML::Reader".

A menos que se especifique lo contrario, el valor predeterminado para las opciones de valor booleano es 0 (falso).

Las opciones disponibles son:

URI
/parser, html, reader/

En caso de analizar cadenas o manejadores de archivos, XML::LibXML no conoce la URI base del documento. Para que funcionen las referencias relativas, como XIncludes, es necesario establecer una URI base, que luego se utiliza para el documento analizado.

line_numbers
/parser, html, reader/

Si esta opción está activada, libxml2 almacenará el número de línea de cada nodo de elemento en el documento analizado. El número de línea se puede obtener utilizando el método line_number() de la clase "XML::LibXML::Node" (para nodos que no son elementos, esto puede reportar el número de línea del elemento contenedor). Los números de línea también se utilizan para informar las posiciones de los errores de validación.

IMPORTANTE: Debido a limitaciones en la biblioteca libxml2, los números de línea mayores que 65535 se devolverán como 65535. Desafortunadamente, esta es una historia larga y triste, por favor vea http://bugzilla.gnome.org/show_bug.cgi?id=325533 para más detalles.

encoding
/html/

codificación de caracteres de la entrada

recover
/parser, html, reader/

recuperarse de errores; los valores posibles son 0, 1 y 2

Un valor verdadero activa el modo de recuperación que permite analizar datos XML o HTML corruptos. El modo de recuperación permite al analizador devolver la porción analizada con éxito del documento de entrada. Esto es útil para documentos casi bien formados, donde, por ejemplo, falta una etiqueta de cierre en algún lugar. Aún así, XML::LibXML solo analizará hasta el primer error fatal (no recuperable), informando los errores de análisis recuperables como advertencias. Para suprimir incluso estas advertencias, use recover=>2.

Tenga en cuenta que la validación se desactiva automáticamente en modo de recuperación.

expand_entities
/parser, reader/

sustituir entidades; los valores posibles son 0 y 1; por defecto es 1

Tenga en cuenta que, aunque esta bandera deshabilita la sustitución de entidades, no evita que el analizador cargue entidades externas; cuando se deshabilita la sustitución de una entidad externa, la entidad se representará en el árbol de documentos como un nodo XML_ENTITY_REF_NODE cuyo subárbol será el contenido obtenido al analizar el recurso externo; aunque este anidamiento es visible desde el DOM, es transparente al modelo de datos XPath, por lo que es posible hacer coincidir nodos en una entidad no expandida con la misma expresión XPath que si la entidad se expandiera. Vea también ext_ent_handler.

ext_ent_handler
/parser/

Proporciona un manejador de entidades externas personalizado que se utilizará cuando expand_entities se establezca en 1. El valor posible es una referencia a una subrutina.

¡Esta función no funciona correctamente en libxml2 < 2.6.27!

La subrutina proporcionada se llama cada vez que el analizador necesita recuperar el contenido de una entidad externa. Se llama con dos argumentos: el ID del sistema (URI) y el ID público. El valor devuelto por la subrutina se analiza como el contenido de la entidad.

Este método se puede utilizar para deshabilitar completamente la carga de entidades, por ejemplo, para prevenir exploits del tipo descrito en (http://searchsecuritychannel.techtarget.com/generic/0,295582,sid97_gci1304703,00.html), donde un servicio es engañado para que exponga sus datos privados al hacerle analizar un archivo remoto (feed RSS) que contiene una referencia a una entidad a un archivo local (por ejemplo, "/etc/fstab").

Sin embargo, una solución más granular a este problema la proporcionan los resolutores de URL personalizados, como en

my $c = XML::LibXML::InputCallback->new();
sub match {   # acepta URIs file:/ excepto los catálogos XML en /etc/xml/
  my ($uri) = @_;
  return ($uri=~m{^file:/}
          and $uri !~ m{^file:///etc/xml/})
         ? 1 : 0;
}
$c->register_callbacks([ \&match, sub{}, sub{}, sub{} ]);
$parser->input_callbacks($c);
load_ext_dtd
/parser, reader/

cargar el subconjunto DTD externo al analizar; los valores posibles son 0 y 1. A menos que se especifique, XML::LibXML establece esta opción en 1.

Esta bandera también es necesaria para la validación DTD, para proporcionar atributos completos y para expandir entidades, independientemente de si el documento tiene un subconjunto interno. Por lo tanto, desactivar la carga de DTD externas deshabilitará la expansión de entidades, la validación y los atributos completos también en los subconjuntos internos.

complete_attributes
/parser, reader/

crear atributos DTD predeterminados; los valores posibles son 0 y 1

validation
/parser, reader/

validar con el DTD; los valores posibles son 0 y 1

suppress_errors
/parser, html, reader/

suprimir informes de errores; los valores posibles son 0 y 1

suppress_warnings
/parser, html, reader/

suprimir informes de advertencia; los valores posibles son 0 y 1

pedantic_parser
/parser, html, reader/

informes de errores pedantes; los valores posibles son 0 y 1

no_blanks
/parser, html, reader/

eliminar nodos en blanco; los valores posibles son 0 y 1

no_defdtd
/html/

no añadir un DOCTYPE predeterminado; los valores posibles son 0 y 1

el valor predeterminado es (0) añadir un DTD cuando el html de entrada carece de uno

expand_xinclude o xinclude
/parser, reader/

Implementar sustitución XInclude; los valores posibles son 0 y 1

Expande las etiquetas XInclude inmediatamente al analizar el documento. Tenga en cuenta que el analizador utilizará los resolutores de URI instalados a través de "XML::LibXML::InputCallback" para analizar el documento incluido (si lo hay).

no_xinclude_nodes
/parser, reader/

no generar nodos START/END de XINCLUDE; los valores posibles son 0 y 1

no_network
/parser, html, reader/

Prohibir el acceso a la red; los valores posibles son 0 y 1

Si se establece en verdadero, todos los intentos de obtener recursos no locales (como DTD o entidades externas) fallarán (a menos que se definan manejadores personalizados).

Puede ser necesario utilizar la bandera "recover" para procesar documentos que requieren dichos recursos mientras la red está desactivada.

clean_namespaces
/parser, reader/

eliminar declaraciones de espacios de nombres redundantes durante el análisis; los valores posibles son 0 y 1.

no_cdata
/parser, html, reader/

fusionar CDATA como nodos de texto; los valores posibles son 0 y 1

no_basefix
/parser, reader/

no corregir las URIs de XINCLUDE xml#base; los valores posibles son 0 y 1

huge
/parser, html, reader/

relajar cualquier límite codificado del analizador; los valores posibles son 0 y 1. A menos que se especifique, XML::LibXML establece esta opción en 0.

Nota: el valor predeterminado para esta opción se cambió para proteger contra ataques de denegación de servicio a través de ataques de expansión de entidades. Antes de habilitar la opción, asegúrese de haber tomado medidas alternativas para proteger su aplicación contra este tipo de ataque.

gdome
/parser/

¡ESTA OPCIÓN ES EXPERIMENTAL!

Aunque es bastante potente, la implementación DOM de XML::LibXML está incompleta con respecto a las especificaciones DOM de nivel 2 o nivel 3. XML::GDOME se basa también en libxml2 y proporciona una implementación DOM bastante completa envolviendo libgdome. Esta bandera le permite utilizar todas las opciones del analizador de XML::LibXML y la implementación DOM de XML::GDOME al mismo tiempo.

Para utilizar esta función, hay que instalar libgdome y configurar XML::LibXML para que utilice esta biblioteca. ¡Para esto necesita reconstruir XML::LibXML!

PARSER OPTIONS

For compatibility with XML::LibXML versions prior to 1.70, the following methods are also supported for querying and setting the corresponding parser options (if called without arguments, the methods return the current value of the corresponding parser options; with an argument sets the option to a given value):

$parser->validation();
$parser->recover();
$parser->pedantic_parser();
$parser->line_numbers();
$parser->load_ext_dtd();
$parser->complete_attributes();
$parser->expand_xinclude();
$parser->gdome_dom();
$parser->clean_namespaces();
$parser->no_network();

The following obsolete methods trigger parser options in some special way:

recover_silently
$parser->recover_silently(1);

If called without an argument, returns true if the current value of the "recover" parser option is 2 and returns false otherwise. With a true argument sets the "recover" parser option to 2; with a false argument sets the "recover" parser option to 0.

expand_entities
$parser->expand_entities(0);

Get/set the "expand_entities" option. If called with a true argument, also turns the "load_ext_dtd" option to 1.

keep_blanks
$parser->keep_blanks(0);

This is actually the opposite of the "no_blanks" parser option. If used without an argument retrieves negated value of "no_blanks". If used with an argument sets "no_blanks" to the opposite value.

base_uri
$parser->base_uri( $your_base_uri );

Get/set the "URI" option.

XML CATALOGS

"libxml2" supports XML catalogs. Catalogs are used to map remote resources to their local copies. Using catalogs can speed up parsing processes if many external resources from remote addresses are loaded into the parsed documents (such as DTDs or XIncludes).

Note that libxml2 has a global pool of loaded catalogs, so if you apply the method "load_catalog" to one parser instance, all parser instances will start using the catalog (in addition to other previously loaded catalogs).

Note also that catalogs are not used when a custom external entity handler is specified. At the current state it is not possible to make use of both types of resolving systems at the same time.

load_catalog
$parser->load_catalog( $catalog_file );

Loads the XML catalog file $catalog_file.

# Global external entity loader (similar to ext_ent_handler option
# but this works really globally, also in XML::LibXSLT include etc..)
XML::LibXML::externalEntityLoader(\&my_loader);

ERROR REPORTING

XML::LibXML throws exceptions during parsing, validation or XPath processing (and some other occasions). These errors can be caught by using eval blocks. The error is stored in $@. There are two implementations: the old one throws $@ which is just a message string, in the new one $@ is an object from the class XML::LibXML::Error; this class overrides the operator "" so that when printed, the object flattens to the usual error message.

XML::LibXML throws errors as they occur. This is a very common misunderstanding in the use of XML::LibXML. If the eval is omitted, XML::LibXML will always halt your script by "croaking" (see Carp man page for details).

Also note that an increasing number of functions throw errors if bad data is passed as arguments. If you cannot assure valid data passed to XML::LibXML you should eval these functions.

Note: since version 1.59, get_last_error() is no longer available in XML::LibXML for thread-safety reasons.
