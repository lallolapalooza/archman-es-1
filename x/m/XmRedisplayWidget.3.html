XmRedisplayWidget(3)

Paquete: openmotif

Licencias: LGPL-2.1-or-later

XmRedisplayWidget(llamada a biblioteca) XmRedisplayWidget(llamada a biblioteca)

NOMBRE

XmRedisplayWidget — Activa síncronamente el método expose de un widget para dibujar su contenido

SINOPSIS

#include <Xm/Xm.h>
voidXmRedisplayWidget(
Widgetwidget);

DESCRIPCIÓN

Esta función es una rutina de conveniencia que oculta los detalles internos de Xt al programador de aplicaciones llamando al método expose del widget dado con un evento Expose bien formado y una Región correspondiente al área total del widget. Si el widget no tiene un método Expose, la función no hace nada.

Esto se usa principalmente en el contexto de Impresión X si el modelo de programación elegido por la aplicación es síncrono; es decir, no depende de eventos de Impresión X para la gestión de la disposición de página, sino que quiere controlar completamente la secuencia de solicitudes de renderizado.

XmRedisplayWidget no borra la ventana del widget antes de llamar al método expose, ya que esto se maneja mediante llamadas a XpStartPage.

widget
El widget a redibujar.

VALOR DE RETORNO

Ninguno.

ERRORES/ADVERTENCIAS

No aplicable

EJEMPLOS

En lo siguiente, una aplicación simple quiere imprimir el contenido de un widget de texto multipágina (similar a dtpad).

PrintOKCallback(print_dialog...)
/*-------------*/
{
    pshell = XmPrintSetup (print_dialog, pbs->print_screen,
                                   "Print", NULL, 0);
    XpStartJob(XtDisplay(pshell), XPSpool);
    /**** aquí realizo el shell, obtengo su tamaño, creo mi widget
     jerarquía: un bulletin board, y luego un widget de texto,
     que relleno con el búfer del widget de texto de video */
    /* obtengo el número total de páginas a imprimir */
    XtVaGetValues(ptext, XmNrows, &prows,
                         XmNtotalLines, n_lines, NULL);
    n_pages = n_lines / prows;
    /***** ahora imprimo las páginas en un bucle */
    for (cur_page=0; cur_page != n_pages; cur_page++) {
               XpStartPage(XtDisplay(pshell), XtWindow(pshell), False);
               XmRedisplayWidget(ptext);  /* realizo el dibujo */
               XpEndPage(XtDisplay(pshell));
        XmTextScroll(ptext, prows);  /* me preparo para la siguiente página */
    }
    /***** he terminado */
    XpEndJob(XtDisplay(pshell));
}

Por supuesto, se podría cambiar el código anterior para incluirlo en una rama fork() para que el programa principal no se bloquee mientras se imprime. Otra forma de lograr un efecto de "impresión en segundo plano" es usar un proc de trabajo de Xt. Usando la misma aplicación de ejemplo, esto nos da:

Boolean
PrintOnePageWP(XtPointer npages) /* proc de trabajo */
/*-------------*/
{
    static int cur_page = 0;
    cur_page++;
    XpStartPage(XtDisplay(pshell), XtWindow(pshell), False);
    XmRedisplayWidget(ptext);  /* realizo el dibujo */
    XpEndPage(XtDisplay(pshell));
    XmTextScroll(ptext, prows);  /* me preparo para la siguiente página */
    if (cur_page == n_pages) { /***** he terminado */
        XpEndJob(XtDisplay(pshell));
        XtDestroyWidget(pshell);
        XtCloseDisplay(XtDisplay(pshell));
    }
    return (cur_page == n_pages);
}
PrintOKCallback(...)
/*-------------*/
{
    pshell = XmPrintSetup (widget, pbs->print_screen,
                                   "Print", NULL, 0);
    XpStartJob(XtDisplay(pshell), XPSpool);
    /**** aquí obtengo el tamaño del shell, creo mi jerarquía
          de widgets: un bulletin board, y luego un widget de texto,
                  que relleno con el búfer del widget de texto de video */
    /* obtengo el número total de páginas a imprimir */
    /* ... mismo código que el ejemplo anterior */
    /***** imprimo las páginas en segundo plano */
    XtAppAddWorkProc(app_context, PrintOnePageWP, n_pages);
}
