NOMBRE

XML::Stream - Crea una conexión de Flujo XML y analiza los datos de respuesta

SINAPSIS

XML::Stream es un intento de solidificar el uso de XML a través de flujos.

DESCRIPCIÓN

Este módulo proporciona al usuario métodos para conectarse a un servidor remoto, enviar un flujo de XML al servidor y recibir/analizar un flujo de XML desde el servidor. Se basa principalmente en el trabajo para el enrutador XML Etherx desarrollado por el Equipo de Desarrollo de Jabber. Para más información sobre este proyecto, visite http://xmpp.org/protocols/streams/.

XML::Stream le da al usuario la capacidad de definir una función de llamada central que se utilizará para manejar las etiquetas recibidas del servidor. Estas etiquetas se pasan en el formato definido en el momento de la instanciación. Cuando se ve la etiqueta de cierre de un objeto, el árbol se termina y se pasa a la función de llamada. Lo que el usuario haga con él a partir de ahí depende de él.

Para una descripción detallada de cómo funciona este módulo y de la estructura de datos que devuelve, consulte el código fuente de Stream.pm y la descripción detallada al final del archivo.

NOTA: El analizador que proporciona XML::Stream::Parser, al igual que la mayoría de los analizadores Perl, es síncrono. Si se encuentra en medio del análisis de un paquete y llama a una función de llamada definida por el usuario, el Analizador se bloquea hasta que su función de llamada finaliza. Esto significa que no puede estar operando en un paquete, enviar otro paquete y esperar una respuesta a ese paquete. Nunca le llegará. El uso de hilos podría resolver esto, pero como todos sabemos, los hilos en Perl aún no están a la altura. Este problema se volverá a abordar en el futuro.

MÉTODOS

new

new(
    debug      => cadena,
    debugfh    => FileHandle,
    debuglevel => 0|1|N,
    debugtime  => 0|1,
    style      => cadena)

Crea el objeto XML::Stream. debug debe establecerse en la ruta del archivo de registro de depuración donde se escribirá. Si se establece en "stdout", la depuración irá allí. Además, puede especificar un manejador de archivos existente usando debugfh.

debuglevel determina la cantidad de depuración a generar. 0 es la menor cantidad, 1 es un poco más, N es el límite que usted desea.

debugtime determina si se antepondrá una marca de tiempo a la entrada. style define la forma en que se devuelve la estructura de datos. Los dos estilos disponibles son:

tree - Formato de árbol de L<XML::Parser>
node - Formato de L<XML::Stream::Node>

Para más información, consulte las páginas del manual correspondientes.

Listen

Inicia el flujo escuchando en un puerto para que alguien se conecte y envíe la etiqueta de flujo de apertura, y luego envía una respuesta basada en si la cabecera recibida fue correcta para este flujo. El nombre del servidor, el puerto y el espacio de nombres son necesarios, de lo contrario, no sabremos dónde escuchar y qué espacio de nombres aceptar.

ConnectionAccept

Acepta una conexión entrante.

Respond

Si este es un socket de escucha, entonces necesitamos responder a la apertura de <stream:stream/>.

Connect

Inicia el flujo conectándose al servidor, enviando la etiqueta de flujo de apertura y luego esperando una respuesta y verificando que sea correcta para este flujo. El nombre del servidor, el puerto y el espacio de nombres son necesarios, de lo contrario, no sabremos a dónde enviar el flujo...

Connect(hostname=>cadena,       
        port=>entero, 
        to=>cadena,             
        from=>cadena,           
        myhostname=>cadena,     
        namespace=>cadena,      
        namespaces=>array,      
        connectiontype=>cadena, 
        ssl=>0|1,
        ssl_verify =>0x00|0x01|0x02|0x04,
        ssl_ca_path=>cadena,
        srv=>cadena)

Abre una conexión TCP al servidor especificado y envía la etiqueta XML Stream de apertura adecuada. Se requieren "hostname", "port" y "namespace". namespaces le permite usar objetos XML::Stream::Namespace.

"to" es necesario si desea que el atributo stream sea algo diferente al nombre de host al que se está conectando.

"from" es necesario si desea que el atributo stream from sea algo diferente al nombre de host desde el que se está conectando.

"myhostname" no debería ser necesario, pero si el módulo no puede determinar su nombre de host correctamente (verifique el registro de depuración), configúrelo en el valor correcto, o si desea que el otro lado del flujo piense que usted es otra persona. El tipo determina el tipo de conexión que se realiza:

"tcpip"    - TCP/IP (predeterminado)
"stdinout" - STDIN/STDOUT
"http"     - HTTP

HTTP reconoce los proxies si las variables de entorno http_proxy o https_proxy están configuradas.

"ssl" especifica si se debe usar un socket SSL para comunicaciones cifradas.

"ssl_verify" determina si se realiza la verificación del certificado del par. Consulte la documentación del parámetro SSL_verify_mode para IO::Socket::SSL-new()|IO::Socket::SSL>. El valor predeterminado es 0x01, lo que provoca la verificación del certificado del servidor y requiere que se establezca ssl_ca_path.

"ssl_ca_path" debe establecerse en la ruta a un directorio que contenga certificados CA hashados o a un solo archivo que contenga certificados CA concatenados. Este parámetro es obligatorio si ssl_verify se establece en cualquier valor distinto de 0x00 (sin verificación).

Si se especifica srv Y Net::DNS está instalado y se puede cargar, entonces se envía una consulta SRV a srv.hostname y los resultados se procesan para reemplazar el nombre de host y el puerto. Si la búsqueda falla o Net::DNS no se puede cargar, el nombre de host y el puerto se dejan sin cambios como predeterminados.

Esta función devuelve el mismo hash de GetRoot() a continuación. Asegúrese de obtener el SID (ID de sesión), ya que debe usarlo para llamar a la mayoría de las otras funciones aquí.

Process

Comprueba si hay datos en el socket y devuelve un código de estado dependiendo de si había datos o no. Si no se define un tiempo de espera en la llamada, se utiliza el tiempo de espera definido en Connect(). Si se utiliza un tiempo de espera de 0, la llamada se bloquea hasta que se reciben datos, de lo contrario, devuelve después del período de tiempo de espera.

Process(entero)

Espera a que haya datos disponibles en el socket. Si se especifica un tiempo de espera, la función Process espera ese período de tiempo antes de devolver nada. Si un período de tiempo de espera es

no especificado entonces la función se bloquea hasta que se reciben datos. La función devuelve un hash con los ids de sesión como clave y los valores de estado o los datos como valores del hash.

Toma los datos del servidor y devuelve una cadena.

SetXMLData

Toma una serie de argumentos y establece una porción de la estructura de datos especificada con esos datos. La función funciona en dos modos: "single" o "multiple". "single" indica que la función debe localizar la etiqueta actual que coincide con estos datos y sobrescribir su contenido con los datos proporcionados. "multiple" indica que se debe crear una nueva etiqueta incluso si existen otras.

type - single o multiple XMLTree - puntero al objeto de datos XML::Stream (árbol o nodo) tag - nombre de la etiqueta a crear/modificar (si está en blanco, asume que
se está trabajando con la etiqueta de nivel superior) data - CDATA a establecer para la etiqueta attribs - atributos a AGREGAR a la etiqueta

GetXMLData

Toma una serie de argumentos y devuelve varias estructuras de datos que coinciden con ellos.

type "existence" - devuelve 1 o 0 si la etiqueta existe en el nivel superior.

"value" - devuelve la CDATA de la etiqueta o el valor del atributo, dependiendo de lo que se busque. Ignora cualquier marcado de los datos y solo devuelve la CDATA sin procesar.

"value array" devuelve una matriz de cadenas que representan toda la CDATA en la etiqueta especificada. Ignora cualquier marcado de los datos y solo devuelve la CDATA sin procesar.

"tree" - devuelve una estructura de datos que representa el XML con la etiqueta especificada como etiqueta raíz. Depende del formato con el que se esté trabajando.

"tree array" devuelve una matriz de estructuras de datos, cada una con la etiqueta especificada como etiqueta raíz.

"child array" - devuelve una lista de todos los nodos hijos
sin incluir los nodos CDATA.

"attribs" - devuelve un hash con los atributos y
sus valores, para los elementos que coinciden con
los parámetros

"count" - devuelve el número de elementos que coinciden con
los argumentos

"tag" - devuelve la etiqueta raíz de este árbol.

XMLTree - puntero a la estructura de datos XML::Stream

"tag" - etiqueta de la que extraer datos. Si está en blanco, se accede a la etiqueta
de nivel superior. "attrib" - valor del atributo a recuperar. Ignorado para los tipos
"value array", "tree", "tree array". Si se empareja
con value, se puede utilizar para filtrar etiquetas basándose en
atributos y valores. "value" - solo válido si se proporciona un atributo. Se utiliza para
filtrar etiquetas que solo contienen este atributo.
Útil para buscar a través de múltiples etiquetas que todas
hacen referencia a diferentes espacios de nombres.

XML2Config

Toma un árbol de datos XML y lo convierte en un hash de hashes. Esto solo funciona para ciertos tipos de árboles XML como este:

<foo>
  <bar>1</bar>
  <x>
    <y>foo</y>
  </x>
  <z>5</z>
  <z>6</z>
</foo>

El hash resultante sería:

$hash{bar} = 1;
$hash{x}->{y} = "foo";
$hash{z}->[0] = 5;
$hash{z}->[1] = 6;

Bueno para archivos de configuración.

Config2XML

Toma un hash y produce una cadena XML a partir de él. Si el hash se ve así:

$hash{bar} = 1;
$hash{x}->{y} = "foo";
$hash{z}->[0] = 5;
$hash{z}->[1] = 6;

El XML resultante sería:

<foo>
  <bar>1</bar>
  <x>
    <y>foo</y>
  </x>
  <z>5</z>
  <z>6</z>
</foo>

Bueno para archivos de configuración.

UnescapeXML

Función simple para tomar una cadena escapada y devolverla a la normalidad.

NAME

XML::Stream - A stream-based XML parser

SYNOPSIS

use XML::Stream;
my $stream = XML::Stream->new();
$stream->Connect(hostname => "example.com", port => 5222, namespace => "example:stream");
while(defined(my $node = $stream->Process())) {
  # Process the $node
}
$stream->Disconnect();

DESCRIPTION

This module is designed to parse XML from a stream rather than loading the entire document into memory at once. It is particularly useful for protocols like XMPP (Jabber) that use XML streams.

The parser creates a stream of XML nodes. You can either process these nodes as they come in, or you can set up callbacks to handle specific types of nodes or events.

METHODS

new

Constructor for the XML::Stream object.

my $stream = XML::Stream->new();

Connect

Establishes a connection to an XML stream server.

Connect(hostname => $host, port => $port,
        namespace => $ns, [timeout => $time], [ssl_opts => \%opts]);
  • hostname: The hostname or IP address of the server.
  • port: The port number to connect to.
  • namespace: The default XML namespace for the stream.
  • timeout: Optional. The connection timeout in seconds. Defaults to 5.
  • ssl_opts: Optional. A hash reference of options to pass to IO::Socket::SSL if SSL/TLS is being used.

Returns true on success, or undef on failure. Call GetErrorCode() to get the error code if connection fails.

Disconnect

Closes the connection to the XML stream server.

Disconnect();

Process

Reads data from the stream and parses the next XML node. This method will block until data is available or the stream is closed.

my $node = $stream->Process();

Returns the next XML node as a data structure (e.g., a hash reference for elements with attributes and children) or undef if the stream has ended or an error occurred.

GetErrorCode

Returns the last error code encountered.

my $err = $stream->GetErrorCode();

ConstXMLNS

Return the namespace from the constant string.

GetRoot

Returns the hash of attributes for the root <stream:stream/> tag so that any attributes returned can be accessed. from and any xmlns:foobar might be important.

GetRoot(sid)

Returns the attributes that the stream:stream tag sent by the other end listed in a hash for the specified session.

GetSock

returns the Socket so that an outside function can access it if desired.

GetSock(sid)

Returns a pointer to the IO::Socket object for the specified session.

NewSID

Returns a session ID to send to an incoming stream in the return header. By default it just increments a counter and returns that, or you can define a function and set it using the SetCallBacks function.

SetCallBacks

Takes a hash with top level tags to look for as the keys and pointers to functions as the values.

SetCallBacks(node=>function, update=>function);

Sets the callback that should be called in various situations.

"node" is used to handle the data structures that are built for each top level tag. "update" is used for when Process is blocking waiting for data, but you want your original code to be updated.

VARIABLES

$NONBLOCKING

Tells the Parser to enter into a nonblocking state. This might cause some funky behavior since you can get nested callbacks while things are waiting. 1=on, 0=off(default).

EXAMPLES

simple example

use XML::Stream qw( Tree );
$stream = XML::Stream->new;
my $status = $stream->Connect(hostname => "jabber.org",
                              port => 5222,
                              namespace => "jabber:client");
if (!defined($status)) {
  print "ERROR: Could not connect to server\n";
  print "       (",$stream->GetErrorCode(),")\n";
  exit(0);
}
while($node = $stream->Process()) {
  # do something with $node
}
$stream->Disconnect();

Example using a handler

use XML::Stream qw( Tree );
$stream = XML::Stream->new;
$stream->SetCallBacks(node=>\&noder);
$stream->Connect(hostname => "jabber.org",
                 port => 5222,
                 namespace => "jabber:client",
                 timeout => undef) || die $!;
# Blocks here forever, noder is called for incoming
# packets when they arrive.
while(defined($stream->Process())) { }
print "ERROR: Stream died (",$stream->GetErrorCode(),")\n";
sub noder
{
  my $sid = shift;
  my $node = shift;
  # do something with $node
}
