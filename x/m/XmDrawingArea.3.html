NOMBRE

XmDrawingArea — Clase del widget DrawingArea

SINOPSIS

#include <Xm/DrawingA.h>

DESCRIPCIÓN

DrawingArea es un widget vacío que se adapta fácilmente a una variedad de propósitos. No realiza ningún dibujo y no define ningún comportamiento excepto la invocación de callbacks. Los callbacks notifican a la aplicación cuando se necesitan dibujar gráficos (eventos de exposición o redimensionamiento del widget) y cuando el widget recibe entrada del teclado o del ratón.

Las aplicaciones son responsables de definir la apariencia y el comportamiento según sea necesario en respuesta a los callbacks de DrawingArea.

DrawingArea es también un widget compuesto y una subclase de XmManager que admite una gestión mínima de la geometría para varios widgets o gadgets hijos.

DrawingArea utiliza el recurso XmNinitialFocus de XmManager para definir si DrawingArea recibirá el foco cuando se traverse hasta él, incluso si tiene hijos que se pueden trazar. Si XmNinitialFocus es NULL, DrawingArea solo recibe el foco si no tiene hijos que se puedan trazar. Si XmNinitialFocus no es NULL, entonces DrawingArea recibe el foco cuando se traza hasta él. En este último caso, la aplicación primero debe ser capaz de darse cuenta de que DrawingArea recibirá el foco, luego, según corresponda, deberá llamar a la función XmProcessTraversal para el hijo deseado, o navegar por los objetos gráficos privados de DrawingArea.

Los siguientes recursos no son utilizados actualmente por el widget DrawingArea: XmNshadowThickness, XmNtopShadowPixmap, XmNbottomShadowPixmap, XmNtopShadowColor y XmNbottomShadowColor

Comportamiento de transferencia de datos

DrawingArea no tiene conversión de clase de widget ni procedimiento de destino. Las subclases y los procedimientos XmNconvertCallback son responsables de cualquier conversión de selecciones. Las subclases y los procedimientos XmNdestinationCallback son responsables de cualquier transferencia de datos al widget.

Clases

DrawingArea hereda el comportamiento y los recursos de las clases Core, Composite, Constraint y XmManager.

El puntero de clase es xmDrawingAreaWidgetClass.

El nombre de la clase es XmDrawingArea.

Nuevos recursos

El programador también puede establecer los valores de los recursos para las clases heredadas para establecer atributos para este widget. Para hacer referencia a un recurso por nombre o por clase en un archivo .Xdefaults, elimine el prefijo XmN o XmC y utilice las letras restantes. CALLBACKS

XmNconvertCallback, XmNdestinationCallback, XmNexposeCallback, XmNinputCallback, y XmNresizeCallback

Un widget DrawingArea llama a las funciones de callback asociadas con estos recursos en las siguientes condiciones:

XmNconvertCallback
Se llama cuando se solicita una conversión de selección.
XmNdestinationCallback
Se llama cuando el widget es el destino de una operación de transferencia de datos.
XmNexposeCallback
Se llama cuando el widget recibe un evento de exposición. El evento de exposición se pasa al callback.
XmNinputCallback
Se llama cuando el widget recibe un evento de entrada de teclado o ratón. El evento se pasa al callback.
XmNresizeCallback
Se llama cuando el widget cambia de tamaño.

La estructura de datos pasada a cada callback es diferente y se documenta en la página de manual de la subclase o del widget específico.

TRAVERSAL

DrawingArea permite el recorrido a través de sus hijos que se pueden trazar. Si el DrawingArea tiene hijos que se pueden trazar, DrawingArea maneja el recorrido del foco entre ellos. Si el DrawingArea no tiene hijos que se puedan trazar, entonces el recorrido del foco va al DrawingArea y luego al siguiente widget en el orden de recorrido. Si el DrawingArea necesita ser capaz de obtener el foco cuando se traza hacia él, incluso si tiene hijos que se pueden trazar, la aplicación puede habilitar esto estableciendo el recurso XmNinitialFocus.

WIDGETS AND GADGETS

DrawingArea puede actuar como un padre para widgets o gadgets.

EJEMPLO

Para crear un widget DrawingArea:

Widget drawing_area;

drawing_area = XmCreateDrawingArea(parent, "drawing_area", NULL, 0);
XtManageChild(drawing_area);

Para crear un widget DrawingArea con recursos específicos:

Arg al[10];
int ac = 0;
Widget drawing_area;

XtSetArg(al[ac], XmNwidth, 200); ac++;
XtSetArg(al[ac], XmNheight, 200); ac++;
XtSetArg(al[ac], XmNmarginHeight, 5); ac++;
XtSetArg(al[ac], XmNmarginWidth, 5); ac++;
XtSetArg(al[ac], XmNexposeCallback, expose_callback); ac++;
XtSetArg(al[ac], XmNresizeCallback, resize_callback); ac++;
drawing_area = XmCreateDrawingArea(parent, "drawing_area", al, ac);
XtManageChild(drawing_area);

Este ejemplo crea un DrawingArea de 200x200 píxeles con márgenes de 5 píxeles y registra las funciones de callback expose_callback y resize_callback.

Información de Callback

Se pasa un puntero a la siguiente estructura a los procedimientos XmNexposeCallback, XmNinputCallback y XmNresizeCallback:

typedef struct
{
        int razón;
        XEvent * evento;
        Window ventana;
} XmDrawingAreaCallbackStruct;
razón
Indica por qué se invocó el callback.
evento
Apuntador al XEvent que desencadenó el callback. Es NULL para el XmNresizeCallback.
ventana
Se establece en la ventana del widget.

Se pasa un puntero a la siguiente estructura a los procedimientos XmNconvertCallback:

typedef struct
{
        int razón;
        XEvent *evento;
        Atom selección;
        Atom objetivo;
        XtPointer datos_origen;
        XtPointer datos_ubicación;
        int flags;
        XtPointer parm;
        int formato_parm;
        unsigned long longitud_parm;
        int estado;
        XtPointer valor;
        Atom tipo;
        int formato;
        unsigned long longitud;
} XmConvertCallbackStruct;
razón
Indica por qué se invocó el callback.
evento
Apuntador al XEvent que desencadenó el callback. Puede ser NULL.
selección
Indica la selección para la que se solicita la conversión. Los valores posibles son CLIPBOARD, PRIMARY, SECONDARY y _MOTIF_DROP.
objetivo
Indica el objetivo de la conversión.
datos_origen
Contiene información sobre el origen de la selección. Cuando la selección es _MOTIF_DROP, datos_origen es el DragContext. De lo contrario, es NULL.
datos_ubicación
Contiene información sobre la ubicación de los datos a convertir. Si el valor es NULL, los datos a transferir consisten en la selección actual del widget.
flags
Indica el estado de la conversión. Los siguientes son los valores posibles:
XmCONVERTING_NONE
Este flag no se utiliza actualmente.
XmCONVERTING_PARTIAL
El widget de destino pudo ser convertido, pero se perdió parte de los datos.
XmCONVERTING_SAME
El objetivo de la conversión es el origen de los datos a transferir.
XmCONVERTING_TRANSACT
Este flag no se utiliza actualmente.
parm
Contiene datos de parámetros para este objetivo. Si no existen datos de parámetros, el valor es NULL.
Cuando selección es CLIPBOARD y objetivo es _MOTIF_CLIPBOARD_TARGETS o _MOTIF_DEFERRED_CLIPBOARD_TARGETS, el valor es la operación solicitada (XmCOPY, XmMOVE o XmLINK).
formato_parm
Especifica si los datos en parm deben considerarse como una lista de cantidades char, short o long. Los valores posibles son 0 (cuando parm es NULL), 8 (cuando los datos en parm deben considerarse como una lista de chars), 16 (cuando los datos en parm deben considerarse como una lista de shorts) o 32 (cuando los datos en parm deben considerarse como una lista de longs). Tenga en cuenta que formato_parm simboliza un tipo de dato, no el número de bits en cada elemento de la lista. Por ejemplo, en algunas máquinas, un formato_parm de 32 significa que los datos en parm deben considerarse como una lista de cantidades de 64 bits, no de 32 bits.
longitud_parm
Especifica el número de elementos de datos en parm, donde cada elemento tiene el tamaño especificado por formato_parm. Cuando parm es NULL, el valor es 0.
estado
Miembro IN/OUT que especifica el estado de la conversión. El valor inicial es XmCONVERT_DEFAULT. El procedimiento de callback puede establecer este miembro en uno de los siguientes valores:
XmCONVERT_DEFAULT
Este valor significa que el procedimiento de conversión de la clase del widget, si existe, se llama después de que los procedimientos de callback regresan. Si el procedimiento de conversión de la clase del widget produce algún dato, este sobrescribe los datos proporcionados por los procedimientos de callback en el miembro valor.
XmCONVERT_MERGE
Este valor significa que el procedimiento de conversión de la clase del widget, si existe, se llama después de que los procedimientos de callback regresan. Si el procedimiento de conversión de la clase del widget produce algún dato, este se añade a los datos proporcionados por los procedimientos de callback en el miembro valor. Este valor está destinado a usarse con objetivos que resultan en listas de datos, como TARGETS.
XmCONVERT_DONE
Este valor significa que el procedimiento de callback ha completado exitosamente la conversión. El procedimiento de conversión de la clase del widget, si existe, no se llama después de que los procedimientos de callback regresan.
XmCONVERT_REFUSE
Este valor significa que el procedimiento de callback ha terminado el proceso de conversión sin completar la conversión solicitada. El procedimiento de conversión de la clase del widget, si existe, no se llama después de que los procedimientos de callback regresan.
valor
Un parámetro IN/OUT que contiene cualquier dato que el procedimiento de callback produce como resultado de la conversión. El valor inicial es NULL. Si el procedimiento de callback establece este miembro, debe asegurarse de que los miembros tipo, formato y longitud correspondan a los datos en valor. El procedimiento de callback es responsable de asignar, pero no de liberar, memoria cuando establece este miembro.
tipo
Un parámetro IN/OUT que indica el tipo de los datos en el miembro valor. El valor inicial es INTEGER.
formato
Un parámetro IN/OUT que especifica si los datos en valor deben considerarse como una lista de cantidades char, short o long. El valor inicial es 8. El procedimiento de callback puede establecer este miembro en 8 (para una lista de char), 16 (para una lista de short) o 32 (para una lista de long).
longitud
Miembro IN/OUT que especifica el número de elementos de datos en valor, donde cada elemento tiene el tamaño simbolizado por formato. El valor inicial es 0.

Se pasa un puntero a la siguiente estructura de callback a los procedimientos XmNdestinationCallback:

typedef struct
{
        int razón;
        XEvent *evento;
        Atom selección;
        XtEnum operación;
        int flags;
        XtPointer id_transferencia;
        XtPointer datos_destino;
        XtPointer datos_ubicación;
        Time tiempo;
} XmDestinationCallbackStruct;
razón
Indica por qué se invocó el callback.
evento
Apuntador al XEvent que desencadenó el callback. Puede ser NULL.
selección
Indica la selección para la que se solicita la transferencia de datos. Los valores posibles son CLIPBOARD, PRIMARY, SECONDARY y _MOTIF_DROP.
operación
Indica el tipo de operación de transferencia solicitada.
•
Cuando la selección es PRIMARY, los valores posibles son XmMOVE, XmCOPY y XmLINK.
•
Cuando la selección es SECONDARY o CLIPBOARD, los valores posibles son XmCOPY y XmLINK.
•
Cuando la selección es _MOTIF_DROP, los valores posibles son XmMOVE, XmCOPY, XmLINK y XmOTHER. Un valor de XmOTHER significa que el procedimiento de callback debe obtener más información de la XmDropProcCallbackStruct en el miembro datos_destino.
flags
Indica si el widget de destino es o no también el origen de los datos a transferir. Los siguientes son los valores posibles:
XmCONVERTING_NONE
El widget de destino no es el origen de los datos a transferir.
XmCONVERTING_SAME
El widget de destino es el origen de los datos a transferir.
id_transferencia
Sirve como un identificador único
e ID para identificar la transacción de transferencia.
destination_data
Contiene información sobre el destino. Cuando la selección es _MOTIF_DROP, los procedimientos de callback son llamados por el XmNdropProc del sitio de arrastre, y destination_data es un puntero a la estructura XmDropProcCallbackStruct pasada al procedimiento XmNdropProc. Cuando la selección es SECONDARY, destination_data es un Atom que representa un objetivo recomendado por el propietario de la selección para usarlo en la conversión de la selección. De lo contrario, destination_data es NULL.
location_data
Contiene información sobre la ubicación donde se transferirán los datos. El valor es siempre NULL cuando la selección es SECONDARY o CLIPBOARD. Si el valor es NULL, los datos se insertarán en la posición del cursor del widget. location_data solo es válido durante la duración de una transferencia. Una vez que los procedimientos XmTransferDone comiencen a ser llamados, location_data ya no será estable.
time
Indica el momento en que comenzó la operación de transferencia.

XmDrawingArea tiene las siguientes traducciones adicionales. Los nombres de teclas siguientes se enumeran en la sintaxis de la tabla de traducción de eventos de tecla estándar de X. Este formato es el utilizado por Motif para especificar las acciones del widget correspondientes a una tecla dada. Se proporciona una breve descripción general del formato en VirtualBindings(3). Para una descripción completa del formato, consulte la Documentación de Intrínsecos del Kit de Herramientas X.

<BtnDown>:
DrawingAreaInput()
<BtnUp>:
DrawingAreaInput()
<KeyDown>:
DrawingAreaInput() ManagerGadgetKeyInput()
<KeyUp>:
DrawingAreaInput()
