NOMBRE

XmScrolledWindow — La clase del widget ScrolledWindow

SINOPSIS

#include <Xm/ScrolledW.h>

DESCRIPCIÓN

El widget ScrolledWindow combina uno o dos widgets ScrollBar y un área de visualización para implementar una ventana visible sobre alguna otra (generalmente más grande) visualización de datos. La parte visible de la ventana se puede desplazar por la pantalla de datos más grande mediante el uso de las ScrollBars.

Para usar ScrolledWindow, una aplicación primero crea un widget ScrolledWindow, cualquier widget ScrollBar necesario y un widget capaz de mostrar cualquier dato deseado como área de trabajo de ScrolledWindow. ScrolledWindow posiciona el widget del área de trabajo y muestra las ScrollBars si se solicita. Cuando el usuario realiza alguna acción en la ScrollBar, la aplicación es notificada a través de la interfaz de callback normal de ScrollBar.

ScrolledWindow se puede configurar para operar automáticamente, de modo que realice todas las acciones de desplazamiento y visualización sin necesidad de intervención del programa de aplicación. También se puede configurar para proporcionar un marco de soporte mínimo en el que la aplicación es responsable de procesar toda la entrada del usuario y realizar todos los cambios visuales en los datos mostrados en respuesta a esa entrada.

Cuando ScrolledWindow realiza el desplazamiento automático, crea una ventana de recorte y crea automáticamente las barras de desplazamiento. Conceptualmente, esta ventana se convierte en la vista a través de la cual el usuario examina el área de datos subyacente más grande. La aplicación simplemente crea los datos deseados y luego los convierte en el área de trabajo de ScrolledWindow. Cuando el usuario mueve el deslizador para cambiar los datos mostrados, el espacio de trabajo se mueve debajo del área de visualización para que una nueva porción de los datos se vuelva visible.

A veces, es poco práctico para una aplicación crear un gran espacio de datos y simplemente mostrarlo a través de una pequeña ventana de recorte. Por ejemplo, en un editor de texto, crear un único área de datos que consistiera en un archivo grande implicaría una sobrecarga indeseable. La aplicación necesita usar un ScrolledWindow (una pequeña vista sobre datos más grandes), pero necesita ser notificada cuando el usuario desplaza la vista para poder traer más datos del almacenamiento y actualizar el área de visualización. Para estos casos, ScrolledWindow se puede configurar para que solo proporcione soporte de diseño visual. No se crea ninguna ventana de recorte, y la aplicación debe mantener los datos mostrados en el área de trabajo, así como responder a la entrada del usuario en las ScrollBars.

El usuario puede especificar recursos en un archivo de recursos para los widgets creados automáticamente que contienen las barras de desplazamiento horizontal y vertical y el área de recorte del widget ScrolledWindow. Los nombres de estos widgets son HorScrollBar, VertScrollBar y ClipWindow respectivamente, y se mantienen consistentes ya sea que sean creados por XmCreateScrolledList, XmCreateScrolledText o XmCreateScrolledWindow.

ScrolledWindow utiliza el rasgo XmQTnavigator y mantiene el rasgo XmQTscrollFrame.

Clases

ScrolledWindow hereda comportamiento, recursos y rasgos de Core, Composite, Constraint y XmManager.

El puntero de clase es xmScrolledWindowWidgetClass.

El nombre de la clase es XmScrolledWindow.

Indica si la operación de arrastre automático está habilitada (XmAUTO_DRAG_ENABLED) o deshabilitada (XmAUTO_DRAG_DISABLED). Por defecto, está habilitada.

XmNhorizontalScrollBar
Especifica el ID del widget de la barra de desplazamiento horizontal. Esta es creada automáticamente por ScrolledWindow cuando XmNscrollingPolicy se inicializa a XmAUTOMATIC; de lo contrario, el valor predeterminado es NULL.
XmNscrollBarDisplayPolicy
Controla la colocación automática de las barras de desplazamiento. Si se establece en XmAS_NEEDED y si XmNscrollingPolicy se establece en XmAUTOMATIC, las barras de desplazamiento se muestran solo si el área de trabajo excede el área de recorte en una o ambas dimensiones. Un valor de recurso de XmSTATIC hace que ScrolledWindow muestre las barras de desplazamiento siempre que estén gestionadas, independientemente de la relación entre la ventana de recorte y el área de trabajo. Este recurso debe ser XmSTATIC cuando XmNscrollingPolicy es XmAPPLICATION_DEFINED. El valor predeterminado es XmAS_NEEDED cuando XmNscrollingPolicy es XmAUTOMATIC, y XmSTATIC en caso contrario.
XmNscrollBarPlacement
Especifica el posicionamiento de las barras de desplazamiento en relación con la ventana de trabajo. Los valores son:
XmTOP_LEFT
La barra de desplazamiento horizontal se coloca encima de la ventana de trabajo; la barra de desplazamiento vertical se coloca a la izquierda.
XmBOTTOM_LEFT
La barra de desplazamiento horizontal se coloca debajo de la ventana de trabajo; la barra de desplazamiento vertical se coloca a la izquierda.
XmTOP_RIGHT
La barra de desplazamiento horizontal se coloca encima de la ventana de trabajo; la barra de desplazamiento vertical se coloca a la derecha.
XmBOTTOM_RIGHT
La barra de desplazamiento horizontal se coloca debajo de la ventana de trabajo; la barra de desplazamiento vertical se coloca a la derecha.
El valor predeterminado depende del valor del recurso XmNlayoutDirection del widget.
XmNscrolledWindowMarginHeight
Especifica la altura del margen en la parte superior e inferior de ScrolledWindow. Para utilizar la función de arrastre de desplazamiento automático de la instalación de arrastrar y soltar de Motif, un usuario debe poder mantener un icono de arrastre sobre el margen de una ventana desplazable. Aunque la operación de arrastrar y soltar funcionará con un tamaño de margen predeterminado de cero, un usuario puede tener dificultades para posicionar el icono con la precisión suficiente para utilizar la función fácilmente. El programador de la aplicación debe asegurarse de que los márgenes de la ventana tengan un tamaño adecuado, si se desea utilizar la función de arrastre de desplazamiento automático.
XmNscrolledWindowMarginWidth
Especifica el ancho del margen en los lados derecho e izquierdo de ScrolledWindow. Por favor, consulte la advertencia sobre el tamaño del margen predeterminado para el recurso XmNscrolledWindowMarginHeight, arriba.
XmNscrollingPolicy
Realiza el desplazamiento automático del área de trabajo sin interacción de la aplicación. Si el valor de este recurso es XmAUTOMATIC, ScrolledWindow crea automáticamente las barras de desplazamiento; adjunta callbacks a las barras de desplazamiento; establece la política visual en XmCONSTANT; y mueve automáticamente el área de trabajo a través de la ventana de recorte en respuesta a cualquier interacción del usuario con las barras de desplazamiento. Una aplicación también puede agregar sus propios callbacks a las barras de desplazamiento. Esto permite que la aplicación sea notificada de un evento de desplazamiento sin tener que realizar ningún procedimiento de diseño.
NOTA: Dado que ScrolledWindow agrega callbacks a las barras de desplazamiento, una aplicación no debe realizar un XtRemoveAllCallbacks en ninguno de los widgets de la barra de desplazamiento.
Cuando XmNscrollingPolicy se establece en XmAPPLICATION_DEFINED, la aplicación es responsable de todos los aspectos del desplazamiento. Las barras de desplazamiento deben ser creadas por la aplicación, y esta es responsable de realizar cualquier cambio visual en el área de trabajo en respuesta a la entrada del usuario.
Este recurso debe establecerse en la política deseada en el momento en que se crea ScrolledWindow. No se puede cambiar mediante SetValues.
XmNspacing
Especifica la distancia que separa las barras de desplazamiento de la ventana de trabajo.
XmNtraverseObscuredCallback
Especifica una lista de callbacks que se llama al navegar a un widget o gadget que está oscurecido debido a su posición en el área de trabajo en relación con la ubicación de la ventana de visualización de ScrolledWindow. Este recurso es válido solo cuando XmNscrollingPolicy es XmAUTOMATIC. Si este recurso es NULL, no se puede navegar a un widget oscurecido. La razón del callback es XmCR_OBSCURED_TRAVERSAL.
XmNverticalScrollBar
Especifica el ID del widget de la barra de desplazamiento vertical. Esta es creada automáticamente por ScrolledWindow cuando XmNscrollingPolicy se inicializa a XmAUTOMATIC; de lo contrario, el valor predeterminado es NULL.
XmNvisualPolicy
Amplía ScrolledWindow para que coincida con el tamaño del área de trabajo. También se puede utilizar como una ventana de visualización estática sobre un espacio de datos más grande. Si la política visual es XmVARIABLE, ScrolledWindow fuerza la barra de desplazamiento

XmNscrollingPolicy

Define el comportamiento del área de trabajo y de la ventana de visualización con respecto a los cambios de tamaño. Los valores posibles son:

XmCONSTANT
El área de trabajo puede crecer o encogerse según se solicite, pero una ventana de recorte fuerza a que el tamaño de la porción visible permanezca constante. El único momento en que el área de visualización puede crecer es en respuesta a un redimensionamiento del padre del ScrolledWindow. El valor predeterminado es XmCONSTANT cuando XmNscrollingPolicy es XmAUTOMATIC, y XmVARIABLE de lo contrario.
XmVARIABLE
Permite que el área de trabajo crezca o se encoja en cualquier momento y ajusta su diseño para acomodar el nuevo tamaño.
XmAUTOMATIC
Establece la política de visualización a XmSTATIC y permite que el área de trabajo crezca o se encoja en cualquier momento y ajusta su diseño para acomodar el nuevo tamaño. Cuando la política es XmCONSTANT, el área de trabajo crece o se encoge según se solicite, pero una ventana de recorte fuerza a que el tamaño de la porción visible permanezca constante. El único momento en que el área de visualización puede crecer es en respuesta a un redimensionamiento del padre del ScrolledWindow. El valor predeterminado es XmCONSTANT cuando XmNscrollingPolicy es XmAUTOMATIC, y XmVARIABLE de lo contrario.
NOTA: Este recurso debe establecerse en la política deseada en el momento en que se crea el ScrolledWindow. No se puede cambiar a través de SetValues.
XmNworkWindow
Especifica el ID del widget del área de visualización.

NAME

XmScrolledWindow - A window that manages its own scroll bars and viewable area

SYNOPSIS

#include <Xm/ScrolledW.h>

DESCRIPTION

The XmScrolledWindow widget is a composite widget that manages a scroll bar pair and a viewable area. The scroll bars control the portion of the viewable area that is visible through a viewport. The XmScrolledWindow widget provides automatic control over scroll bar behavior and management of the scroll bar connections and the work area.

The XmScrolledWindow widget supports the creation of scrolled windows with automatic or explicit management of scroll bars. Automatic management allows the widget to create and connect the scroll bars automatically. Explicit management allows the application to provide existing scroll bar widgets.

The XmScrolledWindow widget is a subclass of XmManager.

Callback Information

The application must use the ScrollBar callbacks to be notified of user input.

ScrolledWindow defines a callback structure for use with XmNtraverseObscuredCallback callbacks. The XmNtraverseObscuredCallback resource provides a mechanism for traversal to obscured widgets (or gadgets) due to their position in the work area of a ScrolledWindow. The XmNtraverseObscuredCallback routine has responsibility for adjusting the position of the work area such that the specified traversal destination widget is positioned within the viewport of the ScrolledWindow. A NULL XmNtraverseObscuredCallback resource causes obscured widgets within the ScrolledWindow to be nontraversable.

Traversal to an obscured widget or gadget requires these conditions to be met: the widget or gadget can be obscured only due to its position in the work area of a ScrolledWindow relative to the viewport; the viewport of the associated ScrolledWindow is fully visible, or can be made so by virtue of ancestral XmNtraverseObscuredCallback routines; and the XmNtraverseObscuredCallback resource must be non-NULL.

When ScrolledWindow widgets are nested, the XmNtraverseObscuredCallback routine for each ScrolledWindow that obscures the traversal destination is called in ascending order within the given hierarchy.

A pointer to the following structure is passed to callbacks for XmNtraverseObscuredCallback.

typedef struct
{
        int reason;
        XEvent *event:
        Widget traversal_destination;
        XmTraversalDirection direction;
} XmTraverseObscuredCallbackStruct;
reason
Indicates why the callback was invoked.
event
Points to the XEvent that triggered the callback.
traversal_destination
Specifies the widget or gadget to traverse to, which will be a descendant of the work window.
direction
Specifies the direction of traversal. See the description of the direction parameter in the XmProcessTraversal reference page for an explanation of the valid values.

Additional Behavior

This widget has the following additional behavior:

<Key><osfPageUp>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window up the height of the viewport. The distance scrolled may be reduced to provide some overlap. The actual distance scrolled depends on the XmNpageIncrement resource of the vertical ScrollBar.
<Key><osfPageDown>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window down the height of the viewport. The distance scrolled may be reduced to provide some overlap. The actual distance scrolled depends on the XmNpageIncrement resource of the vertical ScrollBar.
<Key><osfPageLeft>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window left the width of the viewport. The distance scrolled may be reduced to provide some overlap. The actual distance scrolled depends on the XmNpageIncrement resource of the horizontal ScrollBar.
<Key><osfPageRight>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window right the width of the viewport. The distance scrolled may be reduced to provide some overlap. The actual distance scrolled depends on the XmNpageIncrement resource of the horizontal ScrollBar.
<Key><osfBeginLine>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window horizontally to the edge corresponding to the horizontal ScrollBar's minimum value.
<Key><osfEndLine>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window horizontally to the edge corresponding to the horizontal ScrollBar's maximum value.
<Key><osfBeginData>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window vertically to the edge corresponding to the vertical ScrollBar's minimum value.
<Key><osfEndData>:
If XmNscrollingPolicy is XmAUTOMATIC, scrolls the window vertically to the edge corresponding to the vertical ScrollBar's maximum value.

Certain applications will want to replace the page bindings with ones that are specific to the content of the scrolled area.
