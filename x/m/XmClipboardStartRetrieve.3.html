Licencias: LGPL-2.1-or-later

NOMBRE

XmClipboardStartRetrieve — Una función del portapapeles que prepara la recuperación de datos del portapapeles

SINOPSIS

#include <Xm/CutPaste.h>
int XmClipboardStartRetrieve (display, window, timestamp)
        Display * display;
        Window  window;
        Time    timestamp;
(void)

DESCRIPCIÓN

XmClipboardStartRetrieve indica a las rutinas del portapapeles que la aplicación está lista para comenzar a copiar un elemento del portapapeles. El portapapeles se bloquea con esta rutina y permanece bloqueado hasta que se llama a XmClipboardEndRetrieve. Entre una llamada a XmClipboardStartRetrieve y una llamada a XmClipboardEndRetrieve, múltiples llamadas a XmClipboardRetrieve con el mismo nombre de formato resultan en la copia incremental de datos del portapapeles hasta que todos los datos en ese formato se hayan recuperado.

Un valor de retorno de XmClipboardTruncate de las llamadas a XmClipboardRetrieve indica que quedan más datos por copiar en el formato dado. Se recomienda que cualquier llamada a las funciones Inquire que la aplicación necesite hacer para completar la copia del portapapeles se realice entre la llamada a XmClipboardStartRetrieve y la primera llamada a XmClipboardRetrieve. De esta manera, la aplicación no necesita llamar a XmClipboardLock y XmClipboardUnlock.

display
Especifica un puntero a la estructura Display que se devolvió en una llamada anterior a XOpenDisplay o XtDisplay.
window
Especifica el ID de ventana de un widget que relaciona la ventana de la aplicación con el portapapeles. El ID de ventana del widget se puede obtener a través de XtWindow. La misma instancia de aplicación debe pasar el mismo ID de ventana a cada una de las funciones del portapapeles que llama.
timestamp
Especifica la hora del evento que desencadenó la copia. Se debe proporcionar una marca de tiempo válida; no es suficiente usar CurrentTime.

RETORNO

XmClipboardSuccess
La función se realiza con éxito.
XmClipboardLocked
La función falló porque el portapapeles estaba bloqueado por otra aplicación. La aplicación puede seguir llamando a la función nuevamente con los mismos parámetros hasta que el bloqueo desaparezca. Esto le da a la aplicación la oportunidad de preguntar si el usuario quiere seguir intentándolo o renunciar a la operación.
