NOMBRE

XmProcessTraversal — Una función que determina qué componente recibe los eventos del teclado cuando un widget tiene el foco

SINOPSIS

#include <Xm/Xm.h>
Boolean XmProcessTraversal(
Widget widget,
XmTraversalDirection direction);

DESCRIPCIÓN

XmProcessTraversal determina qué componente de una jerarquía recibe los eventos del teclado cuando la jerarquía que contiene el widget dado tiene el foco del teclado.

XmProcessTraversal cambia el foco solo cuando la política de foco del teclado de la jerarquía de widgets es explícita. Si el XmNkeyboardFocusPolicy del ancestro shell más cercano del widget dado no es XmEXPLICIT, XmProcessTraversal devuelve False sin realizar ningún cambio de foco.

widget
Especifica el ID del widget cuya jerarquía se va a recorrer.
direction
Especifica la dirección del recorrido.

DEFINICIONES

Para ser elegible para recibir el foco del teclado cuando la política de foco del teclado del shell (XmNkeyboardFocusPolicy) es XmEXPLICIT, un widget o gadget debe cumplir las siguientes condiciones:

•
El widget y sus ancestros no están en proceso de ser destruidos.
•
El widget y sus ancestros son *sensibles*. Un widget es sensible cuando sus recursos XmNsensitive y XmNancestorSensitive son ambos True.
•
El recurso XmNtraversalOn para el widget y sus ancestros es True.
•
El widget es visible. Esto significa que el widget y sus ancestros están gestionados, realizados y (excepto para gadgets) mapeados. Además, en general, alguna parte del área rectangular del widget no debe estar osurecida por los ancestros del widget. Si una aplicación desmapea un widget que tiene su recurso XmNmappedWhenManaged establecido en True, el resultado es indefinido.
En una ScrolledWindow con una XmNscrollingPolicy de XmAUTOMATIC, un widget que está oscurecido porque no está dentro de la ventana de recorte puede recibir foco si alguna parte del widget está dentro del área de trabajo y si una rutina XmNtraverseObscuredCallback puede hacer que el widget sea al menos parcialmente visible desplazando la ventana.

En general, solo los primitivos, gadgets y el área de dibujo son elegibles para recibir foco. La mayoría de los gestores no pueden recibir foco, incluso si cumplen todas estas condiciones.

La dirección del recorrido (direction) identifica el tipo de acción de recorrido a tomar. Las descripciones de estas acciones a continuación se refieren a widgets no grupales de tabulación recorribles y a grupos de tabulación recorribles.

•
Un widget no grupal de tabulación recorrible es un widget que no es un grupo de tabulación y que cumple todas las condiciones para recibir foco descritas anteriormente.
•
Un widget de grupo de tabulación recorrible es un widget de grupo de tabulación que cumple las mismas condiciones, excepto que un gestor que es un grupo de tabulación y cumple las otras condiciones es también elegible para el recorrido, siempre que contenga un descendiente que pueda recibir foco.

Un grupo de tabulación es un widget cuya XmNnavigationType es:

•
XmTAB_GROUP o XmSTICKY_TAB_GROUP, si la jerarquía (hasta el ancestro shell más cercano) que contiene el widget no tiene ningún widget cuya XmNnavigationType sea XmEXCLUSIVE_TAB_GROUP
•
XmEXCLUSIVE_TAB_GROUP o XmSTICKY_TAB_GROUP, si la jerarquía (hasta el ancestro shell más cercano) que contiene el widget tiene algún widget cuya XmNnavigationType sea XmEXCLUSIVE_TAB_GROUP

ACCIONES DE RECORRIDO

La jerarquía a recorrer es la que contiene el argumento widget. Esta jerarquía solo se recorre hasta el shell más cercano; XmProcessTraversal no mueve el foco de un shell a otro. Si el shell que contiene widget no tiene actualmente el foco, cualquier cambio que XmProcessTraversal realice en el elemento con foco dentro de ese shell no surtirá efecto hasta la próxima vez que el shell reciba el foco.

XmProcessTraversal inicia la acción de recorrido desde el widget de la jerarquía que actualmente tiene el foco del teclado o que tuvo el foco por última vez cuando el usuario se alejó de la jerarquía del shell.

El valor del argumento direction determina cuál de los tres tipos de acción de recorrido se tomará:

•
Recorrido a un widget no grupal de tabulación. Este tipo de recorrido solo es posible cuando el widget que actualmente tiene el foco no es un grupo de tabulación; de lo contrario, XmProcessTraversal devuelve False para estas acciones.
Estas acciones no mueven el foco de un grupo de tabulación a otro. Las acciones determinan primero el grupo de tabulación contenedor. Este es el grupo de tabulación que contiene el widget que actualmente tiene el foco. Las acciones solo recorren a un widget no grupal dentro del grupo de tabulación contenedor.
Un widget no grupal de tabulación es elegible para este tipo de recorrido si el widget es recorrible y no tiene ancestros de grupo de tabulación hasta el grupo de tabulación contenedor. Si el grupo de tabulación no contiene widgets no grupales de tabulación recorribles, XmProcessTraversal devuelve False.

En el widget más a la derecha en la fila inferior del grupo de tabulación, esta acción se repite al widget no grupal en el widget más a la izquierda en la fila superior.

NAME

XmProcessTraversal

traverses the widget hierarchy

SYNOPSIS

#include <Xm/Traversal.h>

void XmProcessTraversal (
    Widget widget,
    XmTraversalDirection direction
);

DESCRIPTION

The XmProcessTraversal function provides a mechanism for traversing the widget hierarchy. This function is primarily used by Motif internally to manage focus movement within and between widgets. Applications can call this function to implement custom traversal behaviors or to move focus programmatically.

The function takes two arguments:

widget
Specifies the widget that is the starting point for the traversal. This can be the widget that currently has focus, or any widget involved in the traversal action.
direction
Specifies the direction or type of traversal to perform. The possible values for direction are defined by the Xm/Traversal.h header file and are described below.

The behavior of XmProcessTraversal depends on the direction argument and the context of the widget. The function determines the current widget hierarchy and, if applicable, the containing tab group. The current widget hierarchy is the hierarchy whose root is the nearest ancestor shell of the widget that currently has focus. The containing tab group is the tab group that contains the widget that currently has focus.

If the nearest ancestor shell of widget has a XmNkeyboardFocusPolicy of XmEXPLICIT, XmProcessTraversal attempts to move focus to a traversable widget according to the specified direction. If the nearest ancestor shell of widget has a XmNkeyboardFocusPolicy of XmSYSTEM_DEFAULT, XmProcessTraversal is ignored.

The following values are possible for the direction argument:

•
XmTRAVERSE_DOWN—If the XmNnavigationType of the containing tab group is not XmEXCLUSIVE_TAB_GROUP, focus moves to the next traversable non-tab-group widget below the widget that currently has focus. In a left to right environment, at the bottom of the tab group this action wraps to the non-tab-group widget at the top and next toward the right. At the bottom widget in the rightmost column of the tab group this action wraps to the non-tab-group widget at the top widget in the leftmost column.
In a right to left environment, at the bottom of the tab group this action wraps to the non-tab-group widget at the top and next toward the left. At the bottom widget of the leftmost widget of the tab group this action wraps to the non-tab-group widget at the top widget of the rightmost column.
If the XmNnavigationType of the containing tab group is XmEXCLUSIVE_TAB_GROUP, focus moves to the next traversable non-tab-group widget in the tab group, proceeding in the order in which the widgets appear in their parents' XmNchildren lists. After the last widget in the tab group, this action wraps to the first non-tab-group widget.
•
XmTRAVERSE_UP—If the XmNnavigationType of the containing tab group is not XmEXCLUSIVE_TAB_GROUP, focus moves to the next traversable non-tab-group widget above the widget that currently has focus. In a left to right environment, at the top of the tab group this action wraps to the non-tab-group widget at the bottom and next toward the left. At the top widget of the leftmost column of the tab group this action wraps to the non-tab-group widget at the bottom widget of the rightmost column.
In a right to left environment, at the top of the tab group this action wraps to the non-tab-group widget at the bottom and next toward the right. At the top widget of the right most column of the tab group this action wraps to the non-tab-group widget at the bottom widget of the leftmost column.
If the XmNnavigationType of the containing tab group is XmEXCLUSIVE_TAB_GROUP, focus moves to the previous traversable non-tab-group widget in the tab group, proceeding in the reverse order in which the widgets appear in their parents' XmNchildren lists. After the first widget in the tab group, this action wraps to the last non-tab-group widget.
•
XmTRAVERSE_NEXT—Focus moves to the next traversable non-tab-group widget in the tab group, proceeding in the order in which the widgets appear in their parents' XmNchildren lists. After the last widget in the tab group, this action wraps to the first non-tab-group widget.
•
XmTRAVERSE_PREV—Focus moves to the previous traversable non-tab-group widget in the tab group, proceeding in the reverse order in which the widgets appear in their parents' XmNchildren lists. After the first widget in the tab group, this action wraps to the last non-tab-group widget.
•
XmTRAVERSE_HOME—If the XmNnavigationType of the containing tab group is not XmEXCLUSIVE_TAB_GROUP, focus moves to the first traversable non-tab-group widget at the initial focus of the tab group.
If the XmNnavigationType of the containing tab group is XmEXCLUSIVE_TAB_GROUP, focus moves to the first traversable non-tab-group widget in the tab group, according to the order in which the widgets appear in their parents' XmNchildren lists.
•
Traversal to a tab group. These actions first determine the current widget hierarchy and the containing tab group. The current widget hierarchy is the widget hierarchy whose root is the nearest shell ancestor of the widget that currently has focus. The containing tab group is is the tab group containing the widget that currently has focus. If the current widget hierarchy contains no traversable tab groups, XmProcessTraversal returns False.
Following are the possible values of the direction argument. If any tab group in the current widget hierarchy has an XmNnavigationType of XmEXCLUSIVE_TAB_GROUP, traversal of tab groups in the hierarchy proceeds to widgets in the order in which their XmNnavigationType resources were specified as XmEXCLUSIVE_TAB_GROUP or XmSTICKY_TAB_GROUP.:
•
XmTRAVERSE_NEXT_TAB_GROUP—Finds the hierarchy that contains widget, finds the active tab group (if any), and makes the next tab group the active tab group in the hierarchy.
•
XmTRAVERSE_PREV_TAB_GROUP—Finds the hierarchy that contains widget, finds the active tab group (if any), and makes the previous tab group the active tab group in the hierarchy.
•
Traversal to any widget. In this case the widget argument is the widget to which XmProcessTraversal tries to give focus. If the widget is not traversable, XmProcessTraversal returns False.
Following are the possible values of the direction argument:
•
XmTRAVERSE_CURRENT—Finds the hierarchy and the tab group that contain widget. If this tab group is not the active tab group, this action makes it the active tab group. If widget is an item in the active tab group, this action makes it the active item. If widget is the active tab group, this action makes the first traversable item in the tab group the active item.

CAUTIONS

Using XmProcessTraversal to traverse to MenuBars, Pulldown menu panes, or Popup menu panes is not supported.

XmProcessTraversal cannot be called recursively. In particular, an application cannot call this routine from an XmNfocusCallback or XmNlosingFocusCallback procedure.

RETURN

Returns True if the traversal action succeeded. Returns False if the XmNkeyboardFocusPolicy of the nearest shell ancestor of widget is not XmEXPLICIT, if the traversal action finds no traversable widget to receive focus, or if the call to the routine has invalid arguments.
