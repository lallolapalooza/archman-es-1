XML::Smart(3) Documentación de Perl aportada por el usuario XML::Smart(3)

NOMBRE

XML::Smart - Una forma inteligente, fácil y potente de acceder o crear XML a partir de archivos, datos y URLs.

VERSIÓN

Versión 1.79

SINOPSIS

Este módulo proporciona una forma fácil de acceder/crear datos XML. Está basado en un árbol HASH creado a partir de los datos XML, y permite el acceso dinámico a él a través de la sintaxis estándar de Perl para Hash y Array, sin necesidad de preocuparse necesariamente por con cuál estás trabajando. En otras palabras, cada punto del árbol funciona como un Hash y como un Array al mismo tiempo!

Este módulo proporciona adicionalmente recursos especiales como: búsqueda de nodos por atributo, selección de un valor de atributo en cada nodo múltiple, cambio del formato devuelto, y más.

El módulo también maneja automáticamente datos binarios (codificación/decodificación a/desde base64), CDATA (contenidos como con <etiquetas>) y Unicode. Puede ser utilizado para crear archivos XML, cargar XML desde la Web ( simplemente usando una URL como ruta de archivo) y tiene una forma fácil de enviar datos XML a través de sockets - simplemente añadiendo la longitud de los datos en la cabecera <?xml?>.

Puedes usar XML::Smart con XML::Parser, o con los 2 analizadores estándar de XML::Smart:

XML::Smart::Parser
XML::Smart::HTMLParser.

XML::Smart::HTMLParser puede ser utilizado para cargar/analizar datos XML malformados/defectuosos, o etiquetas HTML.

Tutorial y P.R.E.

Puedes encontrar algunos documentos adicionales sobre XML::Smart en:

XML::Smart::Tutorial - Tutorial y ejemplos para XML::Smart.
XML::Smart::FAQ - Preguntas frecuentes sobre XML::Smart.

USO

## Crear el objeto y cargar el archivo:
my $XML = XML::Smart->new('archivo.xml') ;

## Forzar el uso del analizador 'XML::Smart::Parser'.
my $XML = XML::Smart->new('archivo.xml' , 'XML::Smart::Parser') ;

## Obtener desde la web:
my $XML = XML::Smart->new('http://www.perlmonks.org/index.pl?node_id=16046') ;
## Cortar la raíz:
$XML = $XML->cut_root ;
## O cambiar la raíz:
$XML = $XML->{hosts} ;
## Obtener la dirección [0] del servidor [0]:
my $srv0_addr0 = $XML->{server}[0]{address}[0] ;
## ...o...
my $srv0_addr0 = $XML->{server}{address} ;

## Obtener el servidor donde el atributo 'type' es 'suse':
my $server = $XML->{server}('type','eq','suse') ;

## Obtener la dirección de nuevo:
my $addr1 = $server->{address}[1] ;
## ...o...
my $addr1 = $XML->{server}('type','eq','suse'){address}[1] ;

## Obtener todas las direcciones de un servidor:
my @addrs = @{$XML->{server}{address}} ;
## ...o...
my @addrs = $XML->{server}{address}('@') ;

## Obtener una lista de tipos de todos los servidores:
my @types = $XML->{server}('[@]','type') ;

## Añadir un nuevo nodo de servidor:
my $newsrv = {
os      => 'Linux' ,
type    => 'Mandrake' ,
version => 8.9 ,
address => [qw(192.168.3.201 192.168.3.202)]
} ;

push(@{$XML->{server}} , $newsrv) ;
## Obtener/reconstruir los datos XML:
my $xmldata = $XML->data ;

## Guardar en algún archivo:
$XML->save('archivo_nuevo.xml') ;

## Enviar a través de un socket:
print $socket $XML->data(length => 1) ; ## muestra la 'longitud' en la cabecera XML para que el
                                        ## socket sepa la cantidad de datos a leer.

__DATA__
<?xml version="1.0" encoding="iso-8859-1"?>
<hosts>
  <server os="linux" type="redhat" version="8.0">
    <address>192.168.0.1</address>
    <address>192.168.0.2</address>
  </server>
  <server os="linux" type="suse" version="7.0">
    <address>192.168.1.10</address>
    <address>192.168.1.20</address>
  </server>
  <server address="192.168.2.100" os="linux" type="conectiva" version="9.0"/>
</hosts>

MÉTODOS

nuevo (ARCHIVO|DATOS|URL , ANALIZADOR , OPCIONES)

Crea un objeto XML.

Argumentos:

ARCHIVO|DATOS|URL
El primer argumento puede ser: 
- Datos XML como cadena.
- Ruta de archivo.
- Manejador de archivo (GLOB).
- URL (Necesita LWP::UserAgent).

Si no se pasa, se inicia un árbol XML nulo, donde deberías crear tus propios datos XML, luego construir/guardar/enviar.

ANALIZADOR (opcional)
Establece el analizador XML a usar. Opciones: 
XML::Parser
XML::Smart::Parser
XML::Smart::HTMLParser

XML::Smart::Parser solo puede manejar datos XML básicos (no soporta PCDATA, ni cabeceras como: ENTITY, NOTATION, etc...), pero es una buena opción cuando no quieres instalar módulos grandes para analizar XML, ya que viene con el módulo principal. Pero aún puede manejar CDATA y datos binarios.

** Ver "ANÁLISIS DE HTML COMO XML" para XML::Smart::HTMLParser.

Alias para las opciones:

SMART|REGEXP   => XML::Smart::Parser
HTML           => XML::Smart::HTMLParser

Por defecto:

Si no se establece, buscará XML::Parser y lo cargará. Si XML::Parser no se puede cargar, usará XML::Smart::Parser, que es en realidad un clon de XML::Parser::Lite con algunas correcciones.

OPCIONES
Puedes forzar mayúsculas y minúsculas para las etiquetas (nodos) y argumentos (atributos), y otras cosas adicionales.
etiqueta_minuscula
Poner las etiquetas en minúsculas.
argumento_minuscula
Poner los argumentos en minúsculas.
etiqueta_mayuscula
Poner las etiquetas en mayúsculas.
argumento_mayuscula
Poner los argumentos en mayúsculas.
argumento_unico
Establece el valor de los argumentos a 1 cuando tienen un valor undef.

** Esta opción solo funcionará cuando los datos XML sean analizados por XML::Smart::HTMLParser, ya que acepta argumentos sin valores:

my $xml = new XML::Smart(
'<root><foo arg1="" flag></root>' ,
'XML::Smart::HTMLParser' ,
argumento_unico => 1 ,
) ;

En este ejemplo se usó la opción "argumento_unico", lo que definirá flag a 1, pero arg1 seguirá teniendo un valor de cadena nulo ("").

Aquí está el árbol del ejemplo anterior:

'root' => {
            'foo' => {
                       'flag' => 1,
                       'arg1' => ''
                     },
          },
usar_espacios
Aceptar contenidos que solo tengan espacios.
al_inicio (CÓDIGO) *opcional
Código/subrutina a llamar al inicio de una etiqueta.

** Se llamará después de que XML::Smart analice la etiqueta, solo debe usarse si quieres cambiar el árbol.

al_caracter (CÓDIGO) *opcional
Código/subrutina a llamar en el contenido.

** Se llamará después de que XML::Smart analice la etiqueta, solo debe usarse si quieres cambiar el árbol.

al_final (CÓDIGO) *opcional
Código/subrutina a llamar al final de una etiqueta.

** Se llamará después de que XML::Smart analice la etiqueta, solo debe usarse si quieres cambiar el árbol.

** Estas opciones se aplican cuando se cargan los datos XML. Para generación de XML ver las OPCIONES de data().

Ejemplos de uso:

my $xml_desde_url = XML::Smart->new("http://www.perlmonks.org/index.pl?node_id=16046") ;

...

my $xml_desde_str = XML::Smart->new(q`<?xml version="1.0" encoding="iso-8859-1"?>
<root>
  <message type="info">Hello World!</message>
</root>`
) ;

## Convertir a mayúsculas las etiquetas y los argumentos:
my $xml = XML::Smart->new($data , 'XML::Parser' , upertag => 1, uperarg => 1) ;
print $xml->data ;
## Imprime: <?xml version="1.0" encoding="iso-8859-1"?>
##         <ROOT>
##           <MESSAGE TYPE="INFO">Hello World!</MESSAGE>
##         </ROOT>

## Acceso dinámico:
my $messg = $xml->{ROOT}{MESSAGE} ; ## Ojo: las etiquetas están en mayúsculas
print $messg->{type} ; ## Imprime: INFO

## Muestra el nodo usando la sintaxis de array:
print $xml->{ROOT}{MESSAGE}[0]->{type} ; ## Imprime: INFO

## Para acceder a la data SIN las etiquetas:
print $xml->{ROOT}{MESSAGE}[0] ; ## Imprime: Hello World!

## Creando XML:
my $xml = XML::Smart->new() ; ## Crea un objeto XML vacio
$xml->{root}{message} = 'A new message' ;
$xml->{root}{message} = ['Msg1', 'Msg2'] ; ## crea múltiples nodos message
$xml->{root}{subnode}{data} = 123 ;
$xml->{root}{node_with_attr}{id} = 500 ;
$xml->{root}{node_with_attr}{type} = 'test' ;

## Obtener la data XML
print $xml->data ;
## Imprime:
## <?xml version="1.0" encoding="UTF-8"?>
## <root>
##   <message>Msg1</message>
##   <message>Msg2</message>
##   <subnode>
##     <data>123</data>
##   </subnode>
##   <node_with_attr id="500" type="test"/>
## </root>

## También se puede usar para generar XML mediante la sintaxis de hash/array estándar
## con los métodos 'data', 'save' y 'send'.

my $xml = XML::Smart->new('file.xml');
$xml->{root}->{element}[0]->{value} = 'one';
$xml->{root}->{element}[1]->{value} = 'two';
$xml->save('new_file.xml');

data(OPTIONS)

Devuelve los datos XML como una cadena.

OPTIONS:

length
Incluye el tamaño de los datos en la cabecera XML (útil para enviar a través de sockets).
encoding
Establece la codificación del XML (por defecto UTF-8).
xml_declaration
Booleano (0 o 1) para incluir o no la declaración XML (por defecto 1).
pretty
Booleano (0 o 1) para formatear el XML con indentación (por defecto 0).
## Pretty print:
print $xml->data(pretty => 1) ;

save(FILE)

Guarda el XML en el archivo especificado.

$xml->save('my_file.xml') ;

## Guardar con indentación:
$xml->save('my_file_pretty.xml', pretty => 1) ;

cut_root()

Quita el nodo raíz del árbol XML y devuelve el objeto con el primer nodo hijo como la nueva raíz.

my $xml = XML::Smart->new('file.xml');
$xml = $xml->cut_root();
## Ahora $xml apunta al primer nodo hijo de la raíz original.

find(PATH)

Busca un nodo usando una ruta de estilo XPath.

## Busca todos los nodos 'address' dentro de 'server'.
my @addresses = $xml->find('//server/address');

## Busca el primer nodo 'server' con el atributo 'type' igual a 'suse'.
my $suse_server = $xml->findone('//server[@type="suse"]');

set(PATH, VALUE)

Establece el valor de un nodo especificado por una ruta.

$xml->set('//server[@type="suse"]/address[1]', '192.168.1.99');

get_attr(NODE_NAME)

Devuelve una lista de atributos del nodo especificado.

my @attrs = $xml->get_attr('server');
## Si el primer nodo server tiene 'os' y 'type' como atributos:
## @attrs contendrá ('os', 'type')

get_values(NODE_NAME)

Devuelve una lista de valores de los nodos hijos del nodo especificado.

my @values = $xml->get_values('server');
## Si el primer nodo server tiene dos nodos 'address':
## @values contendrá las cadenas de los dos nodos address.

get_att_val(NODE_NAME, ATTR_NAME)

Devuelve una lista de valores de un atributo específico para todos los nodos del nombre dado.

my @versions = $xml->get_att_val('server', 'version');

change_node(OLD_NODE_NAME, NEW_NODE_NAME)

Cambia el nombre de un nodo en todo el árbol XML.

$xml->change_node('server', 'host');

merge(XML_OBJECT)

Fusiona dos objetos XML. Los nodos duplicados se añadirán como elementos de un array.

my $xml1 = XML::Smart->new('file1.xml');
my $xml2 = XML::Smart->new('file2.xml');
$xml1->merge($xml2);

ANÁLISIS DE HTML COMO XML

Para analizar datos HTML o XML malformado, usa el analizador XML::Smart::HTMLParser.

my $xml = XML::Smart->new('index.html', 'HTML');

Este analizador es más permisivo y puede manejar etiquetas no cerradas, etc.

Una característica útil de este analizador es la opción arg_single que permite tratar atributos sin valor explícito como si tuvieran el valor 1.

my $xml = XML::Smart->new('<root><element flag /></root>', 'HTML', arg_single => 1);
print $xml->{root}{element}{flag};  ## Imprime: 1

MANEJO DE DATOS BINARIOS

XML::Smart puede manejar datos binarios codificándolos y decodificándolos automáticamente a/desde base64 cuando se guardan o cargan datos XML.

Para habilitar esta característica, debes añadir la opción binary al crear el objeto.

my $xml = XML::Smart->new('data.xml', binary => 1);

Cuando el analizador encuentra datos que parecen ser binarios, los codifica en base64. Cuando se genera el XML, los datos codificados se decodifican automáticamente si se especifica la codificación correcta (por defecto UTF-8).

Alternativamente, puedes codificar/decodificar manualmente usando las subrutinas encode_base64 y decode_base64 proporcionadas por el módulo.

my $encoded = XML::Smart::encode_base64($binary_data);
my $decoded = XML::Smart::decode_base64($encoded_data);

apply_dtd (DTD , OPTIONS)

Aplica el DTD al árbol XML.

DTD puede ser una fuente, archivo, GLOB o URL.

Este método es útil si necesitas que el XML generado por data() esté formateado según un DTD específico, de modo que los elementos se conviertan en nodos automáticamente, los atributos se verifiquen, se creen los elementos y atributos requeridos, se establezca el orden de los elementos, etc...

OPCIONES:

no_delete BOOL
Si es TRUE, indica que los elementos y atributos no definidos en el DTD no se eliminarán del árbol XML.

Ejemplo de uso:

$xml->apply_dtd(q`
<!DOCTYPE cds [
<!ELEMENT cds (album+)>
<!ATTLIST cds
          creator  CDATA
          date     CDATA #REQUIRED
          type     (a|b|c) #REQUIRED "a"
>
<!ELEMENT album (#PCDATA)>
]>
` ,
no_delete => 1 ,
);

args()

Devuelve los nombres de los argumentos (no los nodos).

args_values()

Devuelve los valores de los argumentos (no los nodos).

back()

Retrocede un nivel el puntero en el árbol.

** Ver base().

base()

Vuelve a la base del árbol.

Cada consulta al objeto XML::Smart devuelve un objeto que apunta a un lugar diferente en el árbol (y comparte el mismo árbol HASH). Por lo tanto, puedes obtener el objeto principal nuevamente (un objeto que apunta a la base):

my $srv = $XML->{root}{host}{server} ;
my $addr = $srv->{adress} ;
my $XML2 = $srv->base() ;
$XML2->{root}{hosts}...

content()

Devuelve el contenido de un nodo:

## Datos:
<foo>mi contenido</foo>

## Acceso:

my $content = $XML->{foo}->content ;
print "<<$content>>\n" ; ## Muestra: <<mi contenido>>

## o simplemente:
my $content = $XML->{foo} ;

También se puede usar con múltiples contenidos:

Para estos datos XML:

<root>
contenido0
<tag1 arg="1"/>
contenido1
</root>

Obteniendo todo el contenido:

my $all_content = $XML->{root}->content ;
print "[$all_content]\n" ;

Salida:

[
contenido0

contenido1
]

Obteniendo por partes:

my @contents = $XML->{root}->content ;
print "[@contents[0]]\n" ;
print "[@contents[1]]\n" ;

Salida

[
contenido0
]
[
contenido1
]

Estableciendo múltiples contenidos:

$XML->{root}->content(0,"aaaaa") ;
$XML->{root}->content(1,"bbbbb") ;

La salida ahora será:

[aaaaa]
[bbbbb]

Y ahora los datos XML generados serán:

<root>aaaaa<tag1 arg="1"/>bbbbb</root>

copy()

Devuelve una copia del objeto XML::Smart (apuntando a la base).

** Esto es bueno cuando quieres mantener 2 versiones del mismo árbol XML en memoria, ya que un objeto no puede cambiar el árbol del otro.

ADVERTENCIA: Los cambios de set_node(), set_cdata() y set_binary() no son persistentes después de una copia - Una vez que creas una segunda copia, estos estados se pierden.

b<advertencia:> no copies después de apply_dtd() a menos que hayas verificado errores de DTD.

cut_root()

Corta la clave raíz:

my $srv = $XML->{rootx}{host}{server} ;

## O si no conoces el nombre de la raíz:
$XML = $XML->cut_root() ;
my $srv = $XML->{host}{server} ;

** Nota que esto cortará la raíz del puntero en el árbol. Por lo tanto, si estás en algún lugar que tiene más de una clave (múltiples raíces), se devolverá el mismo objeto sin cortar nada.

data (OPTIONS)

Devuelve los datos del objeto XML (reconstruyéndolo).

Opciones:

nodtd
No añadir en el contenido XML el DTD aplicado por el método apply_dtd().
noident
Si se establece a true, los datos no se identan.
nospace
Si se establece a true, los datos no se identan y no tienen espacio entre las etiquetas (a menos que el CONTENIDO lo tenga).
lowtag
Convierte las etiquetas a minúsculas.
lowarg
Convierte los argumentos a minúsculas.
upertag
Convierte las etiquetas a mayúsculas.
uperarg
Convierte los argumentos a mayúsculas.
length
Si se establece a true, añade el atributo 'length' con el tamaño de los datos a la cabecera xml (<?xml ...?>). Esto es útil cuando se envían los datos a través de un socket, ya que el socket puede conocer la cantidad total de datos a leer.
noheader
No añadir la cabecera <?xml ...?>.
nometagen
No añadir la etiqueta meta generadora: <?meta generator="XML::Smart" ?>
meta
Establece las etiquetas meta del documento XML.
decode
A partir de la VERSIÓN 1.73, existen tres codificaciones base64 diferentes que se utilizan. Se eligen en función de cuál admita los datos proporcionados. Si desea recuperar datos utilizando la función 'data', el xml resultante tendrá dt:dt="binary.based" contenido. Para recuperar los datos decodificados, utilice: $XML->data( decode => 1 )

Ejemplos:

my $meta = {
build_from => "wxWindows 2.4.0" ,
file => "wx26.htm" ,
} ;

print $XML->data( meta => $meta ) ;

__DATA__
<?meta build_from="wxWindows 2.4.0" file="wx283.htm" ?>

Metadatos múltiples:

my $meta = [
{build_from => "wxWindows 2.4.0" , file => "wx26.htm" } ,
{script => "genxml.pl" , ver => "1.0" } ,
] ;

__DATA__
<?meta build_from="wxWindows 2.4.0" file="wx26.htm" ?>
<?meta script="genxml.pl" ver="1.0" ?>

O establezca directamente la etiqueta meta:

my $meta = '<?meta foo="bar" ?>' ;
## Para múltiples:
my $meta = ['<?meta foo="bar" ?>' , '<?meta x="1" ?>'] ;

print $XML->data( meta => $meta ) ;
tree
Establece el árbol HASH para analizar. Si no se establece, utilizará el árbol del objeto XML::Smart (tree()). ;
wild
Acepta etiquetas y argumentos comodín.

** Esto no corregirá claves y etiquetas incorrectas.

sortall
Ordena todas las etiquetas alfabéticamente. Si no se establece, conservará el orden del documento cargado, o el orden de creación de la etiqueta. Por defecto: desactivado

Devuelve la ruta del puntero en formato XPath.

Devuelve el árbol HASH desde el puntero.

save (FILEPATH , OPTIONS)

Guarda los datos XML dentro de un archivo.

Acepta las mismas OPTIONS que el método data().

set_auto

Define la clave que se manejará automáticamente. Así, data() definirá automáticamente si es un nodo, contenido o atributo.

** Este método es útil para eliminar cambios de set_node(), set_cdata() y set_binary().

set_auto_node

Define la clave como un nodo, y data() definirá automáticamente si es CDATA o BINARY.

** Este método es útil para eliminar cambios de set_cdata() y set_binary().

set_binary(BOOL)

Define el nodo como contenido BINARIO cuando es TRUE, o fuerza a no manejarlo como BINARIO cuando es FALSE.

Ejemplo de nodo manejado como BINARY:

<root><foo dt:dt="binary.base64">PGgxPnRlc3QgAzwvaDE+</foo></root>

Contenido original de foo (los datos base64):

<h1>test \x03</h1>

set_cdata(BOOL)

Define el nodo como CDATA cuando es TRUE, o fuerza a no manejarlo como CDATA cuando es FALSE.

Ejemplo de nodo CDATA:

<root><foo><![CDATA[bla bla bla <tag> bla bla]]></foo></root>

set_node(BOOL)

Establece/desestablece la clave actual como un nodo (etiqueta).

** Si BOOL no está definido, usará TRUE.

ADVERTENCIA: No puedes usar set_node, copiar el objeto y luego set_node( 0 ) [ Desestablecer nodo ]

set_order(KEYS)

Establece el orden de las claves (nodos y atributos) en este punto.

set_tag

Igual que set_node.

tree()

Devuelve el árbol HASH de los datos XML.

** Nótese que aquí se devuelve el árbol HASH real. Todas las demás formas devuelven un objeto que funciona como un HASH/ARRAY a través de tie.

tree_pointer()

Igual que pointer().

tree_ok()

Devuelve una copia del árbol del objeto, pero sin las claves internas añadidas por XML::Smart, como /order y /nodes.

tree_pointer_ok()

Devuelve una copia del árbol del objeto, desde el puntero, pero sin las claves internas añadidas por XML::Smart.

xpath() || XPath()

Devuelve un objeto XML::XPath, basado en la raíz XML del árbol.

## buscar desde la raíz:
my $data = $XML->XPath->findnodes_as_string('/') ;

** Necesita XML::XPath instalado, pero solo se carga cuando es necesario.

xpath_pointer() || XPath_pointer()

Devuelve un objeto XML::XPath, basado en el puntero de XML::Smart en el árbol.

## buscar desde este punto, así que XPath '/' en realidad comienza en /server/:

my $srvs = $XML->{server} ;
my $data = $srvs->XPath_pointer->findnodes_as_string('/') ;

** Necesita XML::XPath instalado, pero solo se carga cuando es necesario.

ANNIHILATE

XML::Smart usa XML::XPath que, por razones de rendimiento, tiene fugas de memoria. Para asegurar que esta memoria se libera, puedes llamar explícitamente a ANNIHILATE antes de que el objeto XML::Smart salga del ámbito.

ACCESO

Para acceder a los datos, usas el objeto de una manera similar a HASH y ARRAY:

my $XML = XML::Smart->new('file.xml') ;

my $server = $XML->{server} ;

Pero cuando obtienes una clave {server}, en realidad estás accediendo a los datos a través de tie(), no directamente al árbol HASH dentro del objeto, (esto corregirá accesos incorrectos):

## {server} es una clave normal, no una referencia ARRAY:
my $server = $XML->{server}[0] ; ## devuelve $XML->{server}
my $server = $XML->{server}[1] ; ## devuelve UNDEF

## {server} tiene un ARRAY con 2 elementos:
my $server = $XML->{server} ;    ## devuelve $XML->{server}[0]
my $server = $XML->{server}[0] ; ## devuelve $XML->{server}[0]
my $server = $XML->{server}[1] ; ## devuelve $XML->{server}[1]

Para obtener todos los valores de múltiples elementos/claves:

## Esto funciona teniendo solo una cadena dentro de {address}, o con una referencia ARRAY:
my @addrsses = @{$XML->{server}{address}} ;

Seleccionar búsqueda

Cuando no conoces la posición de los nodos, puedes seleccionarlos por el valor de algún atributo:

my $server = $XML->{server}('type','eq','suse') ; ## devuelve $XML->{server}[1]

Sintaxis para la búsqueda de selección:

(NOMBRE, CONDICION , VALOR)
NOMBRE
El nombre del atributo en el nodo (etiqueta).
CONDICION
Puede ser 
eq  ne  ==  !=  <=  >=  <  >

Para REGEX:

=~  !~

## Insensible a mayúsculas/minúsculas:
=~i !~i
VALOR
El valor.

Para REGEX, úsalo así:

$XML->{server}('type','=~','^s\w+$') ;

Seleccionar atributos en múltiples nodos:

Puedes obtener la lista de valores de un atributo buscando en todos los nodos múltiples:

## Obtener todos los tipos de servidor:
my @types = $XML->{server}('[@]','type') ;

También como:

my @types = $XML->{server}{type}('<@') ;

Sin el recurso:

my @list ;
my @servers = @{$XML->{server}} ;

foreach my $servers_i ( @servers ) {
  push(@list , $servers_i->{type} ) ;
}

Formato de devolución

Puedes cambiar el formato devuelto:

Sintaxis:

(TIPO)

Donde TIPO puede ser:

$  ## el contenido.
@  ## un array (lista de múltiples valores).
%  ## un hash.
.  ## El punto exacto en el árbol, no un objeto.

$@  ## un array, pero con el contenido, no objetos.
$%  ## un hash, pero los valores son el contenido, no un objeto.

## El uso de $@ y $% es bueno si no quieres mantener la referencia del objeto
## (y ahorrar memoria).

@keys  ## Las claves del nodo. Nótese que si tienes una clave con
       ## múltiples nodos, se replicará (esta es la
       ## diferencia de "keys %{$this->{node}}" ).
<@ ## Devuelve el atributo en el nodo anterior, pero buscando
   ## múltiples nodos. Ejemplo:

my @names = $this->{method}{wxFrame}{arg}{name}('<@') ;
#### @names = (parent , id , title) ;

<xml> ## Devuelve datos XML desde este punto.

__DATA__
<method>
  <wxFrame return="wxFrame">
    <arg name="parent" type="wxWindow" />
    <arg name="id" type="wxWindowID" />
    <arg name="title" type="wxString" />
  </wxFrame>
</method>

Ejemplo:

## Contenido de servidores
my $name = $XML->{server}{name}('$') ;
## ... o:
my $name = $XML->{server}{name}->content ;
## ... o:
my $name = $XML->{server}{name} ;
$name = "$name" ;

## Todos los servidores
my @servers = $XML->{server}('@') ;
## ... o:
my @servers = @{$XML->{server}} ;

## Todavía tiene la referencia del objeto:
@servers[0]->{name} ;

## Sin la referencia:
my @servers = $XML->{server}('$@') ;

## Datos XML, igual que data_pointer():
my $xml_data = $XML->{server}('<xml>') ;

CONTENIDO

Si una {clave} tiene un contenido, puedes acceder a él directamente desde la variable o desde el método:

my $server = $XML->{server} ;
print "Contenido: $server\n" ;
## ...o...
print "Contenido: ". $server->content ."\n" ;

Así, si usas el objeto como una cadena funciona como una cadena, si lo usas como un objeto funciona como un objeto! ;-P

** Ver el método content() para más detalles.

CREACIÓN DE DATOS XML

Crear datos XML es fácil, solo tienes que usarlo como un HASH normal, ¡pero no necesitas preocuparte por los múltiples nodos y la creación/conversión de ARRAY!

## Crear un objeto XML nulo:
my $XML = XML::Smart->new() ;

## Añadir un servidor a la lista:
$XML->{server} = {
os => 'Linux' ,
type => 'mandrake' ,
version => 8.9 ,
address => '192.168.3.201' ,
} ;

## Los datos ahora:
<server address="192.168.3.201" os="Linux" type="mandrake" version="8.9"/>

## Añadir una nueva dirección al servidor. Tiene una creación de ARRAY,
## conversión de la clave anterior a ARRAY:
$XML->{server}{address}[1] = '192.168.3.202' ;

## Los datos ahora:
<server os="Linux" type="mandrake" version="8.9">
  <address>192.168.3.201</address>
  <address>192.168.3.202</address>
</server>

Después de crear tu árbol XML, simplemente guárdalo u obtén los datos:

## Obtener los datos:
my $data = $XML->data ;

## O guardarlo directamente:
$XML->save('newfile.xml') ;

## O enviarlo a un socket:
print $socket $XML->data(length => 1) ;

DATOS BINARIOS Y CDATA

CDATA

Desde la versión 1.2, XML::Smart puede manejar datos binarios y bloques CDATA automáticamente.

Al analizar, los datos binarios se detectarán como:

<code dt:dt="binary.base64">f1NPTUUgQklOQVJZIERBVEE=</code>

Dado que este es el formato oficial generado automáticamente para datos binarios en XML.com http://www.xml.com/pub/a/98/07/binary/binary.html. El contenido se decodificará de base64 y se guardará en el árbol de objetos.

CDATA se analizará como cualquier otro contenido, ya que CDATA es solo un bloque que no se analizará.

Al crear datos XML, como en $XML->data(), el formato binario y CDATA se detectan usando estas reglas:

BINARIO:
- Si tus datos tienen caracteres que no pueden estar en XML.
* Caracteres aceptados:

  \s \w \d
  !"#$%&'()*+,-./:;<=>?@[\]^`{|}~
  0x82, 0x83, 0x84, 0x85, 0x86, 0x87, 0x88, 0x89, 0x8a, 0x8b, 0x8c, 0x8e, 0x91, 0x92, 0x93, 0x94, 0x95, 0x96,
  0x97, 0x98, 0x99, 0x9a, 0x9b, 0x9c, 0x9e, 0x9f, 0xa1, 0xa2, 0xa3, 0xa4, 0xa5, 0xa6, 0xa7, 0xa8, 0xa9, 0xaa,
  0xab, 0xac, 0xad, 0xae, 0xaf, 0xb0, 0xb1, 0xb2, 0xb3, 0xb4, 0xb5, 0xb6, 0xb7, 0xb8, 0xb9, 0xba, 0xbb, 0xbc,
  0xbd, 0xbe, 0xbf, 0xc0, 0xc1, 0xc2, 0xc3, 0xc4, 0xc5, 0xc6, 0xc7, 0xc8, 0xc9, 0xca, 0xcb, 0xcc, 0xcd, 0xce,

CDATA:
- Si tiene etiquetas: <...>

CONTENIDO: (<etiqueta>contenido</etiqueta>)
- Si tiene \r\n\t, o ' y " al mismo tiempo.

Así, este sería un contenido CDATA:

<code><![CDATA[
  línea1
  <etiqueta_no_analizada>
  línea2
]]></code>

Si se detecta contenido binario, se convertirá a base64 y se agregará un atributo dt:dt a la etiqueta para indicar el formato.

<code dt:dt="binary.base64">f1NPTUUgQklOQVJZIERBVEE=</code>

NOTA: A partir de la VERSIÓN 1.73, se utilizan tres codificaciones base64 diferentes. Se eligen en función de cuál de ellas admite los datos proporcionados. Si deseas recuperar los datos usando la función 'data', el xml resultante contendrá dt:dt="binary.based". Para recuperar los datos decodificados, usa: $XML->data( decode => 1 )

UNICODE y ASCII-extendido (ISO-8859-1)

XML::Smart solo admite estos 2 tipos de codificación, Unicode (UTF-8) y ASCII-extendido (ISO-8859-1), y debería ser suficiente. (Ten en cuenta que UTF-8 solo se admite en Perl-5.8+).

Al crear datos XML, si se detecta algún carácter UTF-8, el atributo encoding en la cabecera <?xml ...?> se establecerá a UTF-8:

<?xml version="1.0" encoding="utf-8" ?>
<data>0x82, 0x83</data>

Si no, se utiliza iso-8859-1:

<?xml version="1.0" encoding="iso-8859-1" ?>
<data>0x82</data>

Al cargar datos XML con UTF-8, Perl (5.8+) debería hacer todo el trabajo internamente.

ANALIZAR HTML como XML, o formatos XML MALOS

Puedes usar el analizador especial XML::Smart::HTMLParser para "usar" HTML como XML o datos XML no bien formados.

Las diferencias entre un analizador XML normal y XML::Smart::HTMLParser son:

- Acepta valores sin comillas:
  <foo bar=x>

- Acepta cualquier dato en los valores, incluyendo <> y &:
  <root><echo sample="echo \"Hello!\">out.txt"></root>

- Acepta valores URI sin comillas:
  <link url=http://www.foo.com/dir/file?query?q=v&x=y target=#_blank>

- No necesita cerrar las etiquetas añadiendo la '/' antes de '>':
  <root><foo bar="1"></root>

  ** Ten en cuenta que el analizador se esforzará por detectar los nodos y si se cierran automáticamente o no.

- No necesita tener una sola raíz:
  <foo>datos</foo><bar>datos</bar>

Por lo tanto, XML::Smart::HTMLParser es una forma libre de cargar datos con marcas (como HTML), o si no quieres preocuparte por las comillas, las etiquetas de cierre, etc... al escribir tus datos XML a mano. ¡Así, puedes escribir a mano un archivo XML incorrecto, cargarlo con XML::Smart::HTMLParser y **reescribirlo correctamente** guardándolo de nuevo! ;-P

** Ten en cuenta que las etiquetas <SCRIPT> solo se analizarán correctamente si el contenido está dentro de comentarios <!--...-->, ya que pueden contener etiquetas:

<SCRIPT LANGUAGE="JavaScript"><!--
document.writeln("alguna <etiqueta> en la cadena");
--></SCRIPT>

ENTIDADES

Las entidades (ENTITY) son manejadas por el analizador. Por lo tanto, si usas XML::Parser, hará todo el trabajo correctamente. Pero si usas XML::Smart::Parser o XML::Smart::HMLParser, solo se analizarán las entidades básicas (predeterminadas):

&lt;   => El signo menor que (<).
&gt;   => El signo mayor que (>).
&amp;  => El ampersand (&).
&apos; => La comilla simple o apóstrofo (').
&quot; => La comilla doble (").

&#ddd;  => Un carácter ASCII o un carácter Unicode (>255). Donde ddd es un decimal.
&#xHHH; => Un carácter Unicode. Donde HHH está en hexadecimal.

Al crear datos XML, las entidades ya existentes no se modificarán, y los caracteres '<', '&' y '>' se convertirán a la entidad apropiada.

** Ten en cuenta que si un contenido tiene una <etiqueta>, los caracteres '<' y '>' no se convertirán a entidades, y este contenido estará dentro de un bloque CDATA.

PORQUÉ Y CÓMO FUNCIONA

Cualquiera que haya intentado usar HASH y ARRAY de Perl para acceder a datos XML, como en XML::Simple, tiene algunos problemas para agregar nuevos nodos, o para acceder al nodo cuando el usuario no sabe si está dentro de un ARRAY, un HASH o una clave de HASH. XML::Smart crea una forma muy dinámica de acceder a los datos, ya que al mismo tiempo cualquier nodo/punto en el árbol puede ser un HASH y un ARRAY. También tienes otros recursos adicionales, como la búsqueda de nodos por atributo:

my $server = $XML->{server}('type','eq','suse') ; ## ¡Esta sintaxis no es incorrecta! ;-)
## En lugar de:
my $server = $XML->{server}[1] ;

__DATA__
<hosts>
  <server os="linux" type="redhat" version="8.0">
  <server os="linux" type="suse" version="7.0">
</hosts>

La idea de este módulo surgió del problema que existe para acceder a una estructura compleja en XML. Solo necesitas saber cómo es esta estructura, algo que generalmente se hace mirando el archivo XML (lo cual es incorrecto). Pero al mismo tiempo es difícil verificar siempre (por código) la estructura, antes de acceder a ella. XML es un formato bueno y fácil para declarar tus datos, pero extraerlos de forma arbórea, al menos en mi opinión, no es fácil. Para solucionar eso, me vino a la mente una forma de acceder a los datos con un lenguaje de consulta, como SQL. La primera idea fue acceder usando algo como:

XML.foo.bar.baz{arg1}
X = XML.foo.bar*
X.baz{arg1}

XML.hosts.server[0]{argx}

Y vi que esto es muy similar a los Hashes y Arrays en Perl:

$XML->{foo}{bar}{baz}{arg1} ;

$X = $XML->{foo}{bar} ;
$X->{baz}{arg1} ;

$XML->{hosts}{server}[0]{argx} ;

Pero el problema de Hash y Array es no saber cuándo tienes una referencia a Array o no. Por ejemplo, en XML::Simple:

## Esto es muy diferente
$XML->{server}{address} ;
## ... que esto:
$XML->{server}{address}[0] ;

Entonces, ¿por qué no hacer que ambas formas funcionen? ¡Porque necesitas hacer algo loco!

Para crear XML::Smart, primero creé el módulo Object::MultiType. Con él puedes tener un objeto que funcione al mismo tiempo como HASH, ARRAY, SCALAR, CODE y GLOB. Así puedes hacer cosas como estas con el mismo objeto:

$obj = Object::MultiType->new() ;

$obj->{key} ;
$obj->[0] ;
$obj->method ;

@l = @{$obj} ;
%h = %{$obj} ;

&$obj(args) ;

print $obj "enviar datos\n" ;

Parece una locura, y puede ser más si usas tie() dentro de él, y esto es lo que hace XML::Smart.

Para XML::Smart, el acceso de forma Hash y Array pasa a través de tie(). En otras palabras, tienes un HASH enlazado y un ARRAY enlazado dentro de él. Estos Hash y Array enlazados funcionan juntos, así que **puedes acceder a una clave Hash** **como al índice 0 de un Array, o acceder a un índice 0 como a la clave Hash**:

%hash = (
key => ['a','b','c']
) ;

$hash->{key}    ## devuelve $hash{key}[0]
$hash->{key}[0] ## devuelve $hash{key}[0]
$hash->{key}[1] ## devuelve $hash{key}[1]

## Inverso:

%hash = ( key => 'a' ) ;

$hash->{key}    ## devuelve $hash{key}
$hash->{key}[0] ## devuelve $hash{key}
$hash->{key}[1] ## devuelve undef

Lo mejor de este nuevo recurso es evitar accesos incorrectos a los datos y advertencias al intentar acceder a un Hash teniendo un Array (y viceversa). Cosas que generalmente hacen que el script muera().

Una vez que tienes un acceso fácil a los datos, ¡puedes usar el mismo recurso para crear datos! Por ejemplo:

## Datos anteriores:
<hosts>
  <server address="192.168.2.100" os="linux" type="conectiva" version="9.0"/>
</hosts>

## Ahora tienes {address} como una clave normal con una cadena dentro:
$XML->{hosts}{server}{address}

## Y para agregar una nueva dirección, ¡la clave {address} necesita ser una referencia ARRAY!
## Entonces, XML::Smart hace la conversión: ;-P
$XML->{hosts}{server}{address}[1] = '192.168.2.101' ;

## Agregar a una lista cuyo tamaño no conoces:
push(@{$XML->{hosts}{server}{address}} , '192.168.2.102') ;

## Los datos ahora:
<hosts>
  <server os="linux" type="conectiva" version="9.0"/>
    <address>192.168.2.100</address>
    <address>192.168.2.101</address>
    <address>192.168.2.102</address>
  </server>
</hosts>

Luego, después de cambiar tu árbol XML usando los recursos Hash y Array, simplemente obtienes los datos rehechos (a través del árbol Hash dentro del objeto):

my $xmldata = $XML->data ;

Pero ten en cuenta que XML::Smart siempre devuelve un objeto! Incluso cuando obtienes una clave final. Así que esto en realidad devuelve otro objeto, apuntando (dentro de él) a la clave:

$addr = $XML->{hosts}{server}{address}[0] ;

## Como $addr es un objeto puedes intentar acceder a más datos:
$addr->{foo}{bar} ; ## Esto no genera advertencias! Simplemente devuelve UNDEF.
