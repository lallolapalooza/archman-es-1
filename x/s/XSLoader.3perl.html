XSLoader(3perl) Guía del Programador de Perl XSLoader(3perl)

NOMBRE

XSLoader - Carga dinámicamente bibliotecas en código Perl

VERSIÓN

Versión 0.32

SINOPSIS

package TuPaquete;
require XSLoader;
XSLoader::load(__PACKAGE__, $VERSION);

DESCRIPCIÓN

Este módulo define una interfaz estandarizada y *simplificada* a los mecanismos de enlace dinámico disponibles en muchas plataformas. Su propósito principal es implementar la carga dinámica automática y económica de módulos Perl.

Para una interfaz más compleja, consulta DynaLoader. Muchas (la mayoría) de las características de "DynaLoader" no se implementan en "XSLoader", como por ejemplo, "dl_load_flags", que "XSLoader" no respeta.

Migración desde "DynaLoader"

Un módulo típico que usa DynaLoader comienza así:

package TuPaquete;
require DynaLoader;
our @ISA = qw( OtroPaquete DynaLoader );
our $VERSION = '0.01';
__PACKAGE__->bootstrap($VERSION);

Cámbialo a:

package TuPaquete;
use XSLoader;
our @ISA = qw( OtroPaquete );
our $VERSION = '0.01';
XSLoader::load(__PACKAGE__, $VERSION);

En otras palabras: reemplaza "require DynaLoader" por "use XSLoader", elimina "DynaLoader" de @ISA, y cambia "bootstrap" por "XSLoader::load". No olvides entrecomillar el nombre de tu paquete en la línea "XSLoader::load", y añadir una coma (",") antes de los argumentos (como $VERSION arriba).

Por supuesto, si @ISA solo contenía "DynaLoader", no es necesario tener la asignación de @ISA en absoluto; además, si en lugar de "our" usas el más compatible con versiones anteriores

use vars qw($VERSION @ISA);

se puede eliminar esta referencia a @ISA junto con la asignación de @ISA.

Si no se especificó $VERSION en la línea "bootstrap", la última línea se convierte en

XSLoader::load(__PACKAGE__);

en cuyo caso puede simplificarse aún más a

XSLoader::load();

ya que "load" usará "caller" para determinar el paquete.

Plantilla compatible con versiones anteriores

Si quieres tenerlo todo, necesitas una plantilla más complicada.

package TuPaquete;
our @ISA = qw( OtroPaquete );
our $VERSION = '0.01';
eval {
   require XSLoader;
    XSLoader::load(__PACKAGE__, $VERSION);
   1;
} or do {
   require DynaLoader;
   push @ISA, 'DynaLoader';
   __PACKAGE__->bootstrap($VERSION);
};

Los paréntesis en los argumentos de XSLoader::load() son necesarios ya que reemplazamos "use XSLoader" por "require", por lo que el compilador no sabe que una función XSLoader::load() está presente.

Esta plantilla utiliza el "XSLoader" de bajo overhead si está presente; si se usa con una versión antigua de Perl que no tenga "XSLoader", recurre a usar "DynaLoader".

Orden de inicialización: load() temprano

Omite esta sección si las funciones XSUB se van a llamar solo desde otros módulos; léela solo si llamas a tus XSUBs desde el código de tu módulo, o si tienes una sección "BOOT:" en tu archivo XS (ver "The BOOT: Keyword" en perlxs). Lo descrito aquí es igualmente aplicable a la interfaz de DynaLoader.

Un módulo suficientemente complicado que usa XS tendría tanto código Perl (definido en TuPaquete.pm) como código XS (definido en TuPaquete.xs). Si este código Perl hace llamadas a este código XS, y/o este código XS hace llamadas al código Perl, se debe tener cuidado con el orden de inicialización.

La llamada a XSLoader::load() (o bootstrap()) llama al código de arranque del módulo. Para módulos construidos por xsubpp (casi todos los módulos) esto tiene tres efectos secundarios:

  • Se realiza una comprobación de seguridad para asegurar que las versiones de la parte .pm y la parte (compilada) .xs son compatibles. Si se especificó $VERSION, se usa para esta comprobación. Si no se especifica, por defecto es "$XS_VERSION // $VERSION" (en el espacio de nombres del módulo).
  • Las XSUBs se hacen accesibles desde Perl.
  • Si había una sección "BOOT:" en el archivo .xs, se llama al código allí presente.

Consecuentemente, si el código en el archivo .pm hace llamadas a estas XSUBs, es conveniente tener las XSUBs instaladas antes de que se defina el código Perl; por ejemplo, esto hace que los prototipos de las XSUBs sean visibles para este código Perl. Alternativamente, si la sección "BOOT:" hace llamadas a funciones Perl (o usa variables Perl) definidas en el archivo .pm, deben definirse antes de la llamada a XSLoader::load() (o bootstrap()).

La primera situación es mucho más frecuente, por lo que tiene sentido reescribir la plantilla como:

package TuPaquete;
use XSLoader;
our ($VERSION, @ISA);
BEGIN {
   @ISA = qw( OtroPaquete );
   $VERSION = '0.01';
   # Coloca aquí el código Perl usado en la sección BOOT:
   XSLoader::load(__PACKAGE__, $VERSION);
}
# Coloca aquí el código Perl que hace llamadas a XSUBs

El caso más complicado

Si la interdependencia de tu sección "BOOT:" y el código Perl es más complicada que esto (por ejemplo, la sección "BOOT:" hace llamadas a funciones Perl que a su vez hacen llamadas a XSUBs con prototipos), elimina por completo la sección "BOOT:". Reemplázala con una función onBOOT() y llámala así:

package TuPaquete;
use XSLoader;
our ($VERSION, @ISA);
BEGIN {
   @ISA = qw( OtroPaquete );
   $VERSION = '0.01';
   XSLoader::load(__PACKAGE__, $VERSION);
}
# Coloca aquí el código Perl usado en la función onBOOT(); las llamadas a XSUBs
# se comprueban con prototipo.
onBOOT;
# Coloca aquí el código de inicialización Perl asumiendo que XS está inicializado

DIAGNÓSTICOS

"No se puede encontrar el símbolo '%s' en %s"
(F) El símbolo de arranque no se pudo encontrar en el módulo de extensión.
"No se puede cargar '%s' para el módulo %s: %s"
(F) Falló la carga o inicialización del módulo de extensión. El error detallado sigue a continuación.
"Símbolos indefinidos presentes después de cargar %s: %s"
(W) Como dice el mensaje, algunos símbolos permanecen indefinidos aunque el módulo de extensión se cargó e inicializó correctamente. La lista de símbolos indefinidos sigue a continuación.

LIMITACIONES

Para reducir la sobrecarga tanto como sea posible, solo se comprueba una ubicación posible para encontrar la DLL de extensión (esta ubicación es donde "make install" colocaría la DLL). Si no se encuentra, la búsqueda de la DLL se delega transparentemente a "DynaLoader", que busca la DLL a lo largo de la lista @INC.

En particular, esto es aplicable a la estructura de @INC utilizada para probar extensiones aún no instaladas. Esto significa que la ejecución de extensiones no instaladas puede...

mucho más sobrecarga que ejecutar las mismas extensiones después de "make install".

BUGS CONOCIDOS

La nueva y más sencilla forma de llamar a XSLoader::load() sin argumentos no funciona en Perl 5.8.4 y 5.8.5.
