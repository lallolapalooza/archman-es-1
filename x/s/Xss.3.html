XScreenSaver - Biblioteca cliente de extensión de salvapantallas X11

SINOPSIS

#include <X11/extensions/scrnsaver.h>

typedef struct {
    Window window;                /∗ ventana del salvapantallas */

typedef struct {

DESCRIPCIÓN

El Sistema de Ventanas X proporciona soporte para cambiar la imagen en la pantalla de un monitor después de un período de inactividad establecido por el usuario para evitar quemaduras en los fósforos del tubo de rayos catódicos. Sin embargo, no se proporcionan interfaces para que el usuario controle la imagen que se dibuja. Esta extensión permite a un cliente externo de ``salvapantallas'' detectar cuándo se va a mostrar la imagen alternativa y proporcionar los gráficos.

Las implementaciones actuales del servidor X típicamente proporcionan al menos una forma de imagen de ``salvapantallas''. Históricamente, ha sido una copia del logo X dibujada contra el patrón de fondo de la raíz. Sin embargo, muchos usuarios han solicitado un mecanismo que les permita escribir programas salvapantallas que proporcionen capacidades similares a las proporcionadas por otros sistemas de ventanas. En particular, tales usuarios a menudo desean poder mostrar logotipos corporativos, instrucciones sobre cómo reactivar la pantalla y utilidades de bloqueo automático de pantalla. Esta extensión proporciona un medio para escribir tales clientes.

Supuestos

Esta extensión exporta la noción de una ventana de salvapantallas especial que se mapea por encima de todas las demás ventanas en una pantalla. Esta ventana tiene el atributo override-redirect establecido para que no sea manipulada por el gestor de ventanas. Además, el identificador X de la ventana nunca es devuelto por las solicitudes QueryTree en la ventana raíz, por lo que típicamente no es visible para otros clientes.

XScreenSaverQueryExtension devuelve True si la extensión XScreenSaver está disponible en la pantalla dada. Un cliente debe llamar a XScreenSaverQueryExtension antes de llamar a cualquier otra función de XScreenSaver para negociar una versión de protocolo compatible; de lo contrario, el cliente obtendrá un comportamiento indefinido (XScreenSaver puede o no funcionar).

Si la extensión es compatible, el número de evento para los eventos ScreenSaverNotify se devuelve en el valor al que apunta event_base. Dado que esta extensión no define errores adicionales, los resultados de error_base no están definidos.

XScreenSaverQueryVersion devuelve True si la solicitud tuvo éxito; los valores de las versiones de protocolo principal y secundaria compatibles con el servidor se devuelven en major_version_return y minor_version_return.

XScreenSaverAllocInfo asigna y devuelve una estructura XScreenSaverInfo para su uso en llamadas a XScreenSaverQueryInfo. Todos los campos de la estructura se inicializan a cero. Si no hay suficiente memoria disponible, se devuelve NULL. Los resultados de esta rutina se pueden liberar usando XFree.

XScreenSaverQueryInfo devuelve información sobre el estado actual del servidor de pantalla en saver_info y se devuelve un valor distinto de cero. Si la extensión no es compatible, saver_info no cambia y se devuelve 0.

El campo state especifica si el salvapantallas está activo actualmente y cómo se debe interpretar el valor til-or-since:

Off
La pantalla no se está guardando actualmente; til-or-since especifica el número de milisegundos hasta que se espera que se active el salvapantallas.
On
La pantalla se está guardando actualmente; til-or-since especifica el número de milisegundos desde que se activó el salvapantallas.
Disabled
El salvapantallas está actualmente deshabilitado; til-or-since es cero.

El campo kind especifica el mecanismo que se está utilizando actualmente o que se habría utilizado de haberse guardado la pantalla:

Blanked
Se deshabilitó la señal de video al monitor de la pantalla.
Internal
Se mostró una imagen de salvapantallas incorporada, dependiente del servidor; o ningún cliente había establecido los atributos de la ventana del salvapantallas o un cliente diferente tenía el servidor capturado cuando se activó el salvapantallas.
External
La ventana del salvapantallas se mapeó con atributos establecidos por un cliente utilizando la solicitud ScreenSaverSetAttributes.

El campo idle especifica el número de milisegundos desde la última entrada recibida del usuario en cualquiera de los dispositivos de entrada.
El campo event-mask especifica cuáles, si los hay, eventos de salvapantallas ha solicitado este cliente usando ScreenSaverSelectInput.

XScreenSaverSelectInput solicita que se generen eventos relacionados con el salvapantallas para este cliente. Si no se establecen bits en event-mask, no se generarán eventos. De lo contrario, se puede establecer cualquier combinación de los siguientes bits:

ScreenSaverNotify
Si se establece este bit, se generan eventos ScreenSaverNotify cada vez que se activa o desactiva el salvapantallas.
ScreenSaverCycle
Si se establece este bit, se generan eventos ScreenSaverNotify cada vez que pasa el intervalo de ciclo del salvapantallas.

XScreenSaverSetAttributes establece los atributos que se utilizarán la próxima vez que se active el salvapantallas externo. Si otro cliente tiene actualmente los atributos establecidos, se genera un error BadAccess y la solicitud se ignora.
De lo contrario, se comprueban los atributos de ventana especificados como si se hubieran utilizado en una solicitud CreateWindow principal cuyo padre es la raíz. El campo override-redirect se ignora ya que se establece implícitamente en True. Si los atributos de ventana dan como resultado un error de acuerdo con las reglas para CreateWindow, la solicitud se ignora.
De lo contrario, los atributos se almacenan y surtirán efecto en la próxima activación que ocurra cuando el servidor no esté capturado por otro cliente. Cualquier recurso especificado para los atributos background-pixmap o cursor puede liberarse inmediatamente. El servidor es libre de

DESCRIPTION

The X Screen Saver extension provides a mechanism for applications to control the screen saver, blanking, and DPMS (Display Power Management Signaling) features of the X Window System.

XScreenSaverQueryExtension queries the X server to see if the Screen Saver extension is present. If it is, it returns the extension's event and error base codes in event_base_return and error_base_return respectively, and returns True. Otherwise, it returns False.

XScreenSaverAllocInfo allocates and returns a pointer to an XScreenSaverInfo structure. This structure is used by XScreenSaverQueryInfo to return information about the screen saver.

XScreenSaverQueryInfo queries the X server for information about the screen saver on the specified screen d (which can be a window or a pixmap). The information is returned in the XScreenSaverInfo structure pointed to by info_return. This structure contains the following members:

double-width
The width of the screen in pixels.
double-height
The height of the screen in pixels.
min-delay
The minimum time in seconds between screen saver activations.
max-delay
The maximum time in seconds between screen saver activations.
window-id
The XID of the screen saver window, or 0 if no screen saver window is currently active.
til-when
The time in seconds until the next screen saver activation. This value is relative to the time the query was made.
idle-time
The current time in seconds since the last user input event.
prefer-blanking
A boolean indicating whether the server prefers to blank the screen rather than turning off the monitor.
allow-exposures
A boolean indicating whether screen saver exposures are allowed. If this is True, the screen saver will generate Expose events when it is activated.
policy
This specifies the screen saver activation policy. It can be one of ScreenSaverBlanking, ScreenSaverForcing, or ScreenSaverDisabled.

XScreenSaverSelectInput selects the screen saver events to be received by the client on the specified drawable d. The event mask mask can be any combination of ScreenSaverNotify events.

XScreenSaverSetAttributes sets the attributes of the screen saver window. The window w is created implicitly by the server if it doesn't exist. The x, y, width, and height parameters specify the geometry of the screen saver window. The level parameter can be used to control DPMS power saving. A value of 0 or less indicates no DPMS change. A value of 1 requests the screen saver to activate, and a value of 2 requests the screen saver to deactivate. The mask parameter specifies which of the screen saver attributes are being set. The notify_template parameter is a template for ScreenSaverNotify events, which are generated when the screen saver activates or deactivates. If notify_template is NULL, no ScreenSaverNotify events will be generated.

Note that the screen saver window is created with the InputOutput class. The screen saver window is mapped and unmapped automatically by the server. The server may choose to ignore the specified attributes if they are invalid or conflict with server settings. The screen saver window attributes are associated with the client and are lost when the client exits or disconnects from the server. The server cannot directly access resources such as background-pixmap or cursor resources or to use them in place; therefore, the effect of changing the contents of those resources is undefined. If the specified colormap no longer exists when the screen saver activates, the parent's colormap is used instead. If no errors are generated by this request, any previous screen saver window attributes set by this client are released.
When the screen saver next activates and the server is not grabbed by another client, the screen saver window is created, if necessary, and set to the specified attributes and events are generated as usual. The colormap associated with the screen saver window is installed. Finally, the screen saver window is mapped.
The window remains mapped and at the top of the stacking order until the screen saver is deactivated in response to activity on any of the user input devices, a ForceScreenSaver request with a value of Reset, or any request that would cause the window to be unmapped.
If the screen saver activates while the server is grabbed by another client, the internal saver mechanism is used. The ForceScreenSaver request may be used with a value of Active to deactivate the internal saver and activate the external saver.
If the screen saver client's connection to the server is broken while the screen saver is activated and the client's close down mode has not been RetainPermanent or RetainTemporary, the current screen saver is deactivated and the internal screen saver is immediately activated.
When the screen saver deactivates, the screen saver window's colormap is uninstalled and the window is unmapped (except as described below). The screen saver XID is disassociated with the window and the server may, but is not required to, destroy the window along with any children.
When the screen saver is being deactivated and then immediately reactivated (such as when switching screen savers), the server may leave the screen saver window mapped (typically to avoid generating exposures).

XScreenSaverUnsetAttributes instructs the server to discard any previous screen saver window attributes set by this client.

XScreenSaverRegister stores the given XID in the _SCREEN_SAVER_ID property (of the given type) on the root window of the specified screen. It returns zero if an error is encountered and the property is not changed, otherwise it returns non-zero.

XScreenSaverUnregister removes any _SCREEN_SAVER_ID from the root window of the specified screen. It returns zero if an error is encountered and the property is changed, otherwise it returns non-zero.

XScreenSaverGetRegistered returns the XID and type stored in the _SCREEN_SAVER_ID property on the root window of the specified screen. It returns zero if an error is encountered or if the property does not exist or is not of the correct format; otherwise it returns non-zero.

XScreenSaverSuspend temporarily suspends the screensaver and DPMS timer if suspend is 'True', and restarts the timer if suspend is 'False'.
This function should be used by applications that don't want the screensaver or DPMS to become activated while they're for example in the process of playing a media sequence, or are otherwise continuously presenting visual information to the user while in a non-interactive state. This function is not intended to be called by an external screensaver application.
If XScreenSaverSuspend is called multiple times with suspend set to 'True', it must be called an equal number of times with suspend set to 'False' in order for the screensaver timer to be restarted. This request has no affect if a client tries to resume the screensaver without first having suspended it. XScreenSaverSuspend can thus not be used by one client to resume the screensaver if it's been suspended by another client.
If a client that has suspended the screensaver becomes disconnected from the X server, the screensaver timer will automatically be restarted, unless it's still suspended by another client. Suspending the screensaver timer doesn't prevent the screensaver from being forcibly activated with the ForceScreenSaver request, or a DPMS mode from being set with the DPMSForceLevel request.
XScreenSaverSuspend also doesn't deactivate the screensaver or DPMS if either is active at the time the request to suspend them is received by the X server. But once they've been deactivated, they won't automatically be activated again, until the client has canceled the suspension.

ERRORS

XScreenSaverSelectInput, XScreenSaverQueryInfo, XScreenSaverSetAttributes, and XScreenSaverUnsetAttributes will generate a BadDrawable error if drawable is not a valid drawable identifier. If any undefined bits are set in event-mask, a BadValue error is generated by XScreenSaverSelectInput.

AVAILABILITY

XScreenSaverSuspend is available in version 1.1 and later versions of the X Screen Saver Extension. Version 1.1 was first released with X11R7.1.
