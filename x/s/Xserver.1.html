XSERVER(1) Manual de Comandos Generales XSERVER(1)

NOMBRE

Xserver - servidor de pantalla del Sistema de Ventanas X

SINOPSIS

X [opción ...]

DESCRIPCIÓN

X es el nombre genérico del servidor de pantalla del Sistema de Ventanas X. Frecuentemente es un enlace simbólico o una copia del binario del servidor apropiado para controlar el servidor más utilizado en una máquina dada.

INICIANDO EL SERVIDOR

El servidor X normalmente se inicia desde el programa del gestor de pantalla X xdm(1) o un programa similar de gestor de pantalla. Esta utilidad se ejecuta desde los archivos de arranque del sistema y se encarga de mantener el servidor en ejecución, solicitar nombres de usuario y contraseñas, e iniciar las sesiones del usuario.

Las instalaciones que ejecutan más de un sistema de ventanas pueden necesitar usar la utilidad xinit(1) en lugar de un gestor de pantalla. Sin embargo, xinit debe considerarse una herramienta para crear scripts de inicio y no está pensada para ser utilizada por usuarios finales. Se insta **enérgicamente** a los administradores de sistemas a utilizar un gestor de pantalla o a crear otras interfaces para usuarios novatos.

El servidor X también puede ser iniciado directamente por el usuario, aunque este método generalmente se reserva para pruebas y no se recomienda para la operación normal. En algunas plataformas, el usuario debe tener permiso especial para iniciar el servidor X, a menudo porque el acceso a ciertos dispositivos (por ejemplo, /dev/mouse) está restringido. Donde sea aplicable, el servidor X notifica a systemd cuando está listo para procesar solicitudes.

Cuando el servidor X se inicia, típicamente se apodera de la pantalla. Si está ejecutando en una estación de trabajo cuya consola es la pantalla, es posible que no pueda iniciar sesión en la consola mientras el servidor está en ejecución.

OPCIONES

Muchos servidores X tienen opciones de línea de comandos específicas del dispositivo. Consulte las páginas del manual de los servidores individuales para obtener más detalles; a continuación se proporciona una lista de las páginas del manual específicas del servidor en la sección VER TAMBIÉN.

Todos los servidores X aceptan las opciones de línea de comandos descritas a continuación. Algunos servidores X pueden tener formas alternativas de proporcionar los parámetros descritos aquí, pero los valores proporcionados a través de las opciones de línea de comandos deben anular los valores especificados a través de otros mecanismos.

:número-de-pantalla
El servidor X se ejecuta con el número-de-pantalla dado, que por defecto es 0. Si se van a ejecutar varios servidores X simultáneamente en un host, cada uno debe tener un número de pantalla único. Consulte la sección NOMBRES DE PANTALLA de la página del manual de X(7) para aprender cómo especificar qué número de pantalla deben intentar usar los clientes.
-a número
establece la aceleración del puntero (es decir, la relación entre lo que se informa y cuánto se movió realmente el puntero).
-ac
deshabilita los mecanismos de control de acceso basados en host. Permite el acceso de cualquier host y permite que cualquier host modifique la lista de control de acceso. Usar con extrema precaución. Esta opción existe principalmente para ejecutar suites de prueba de forma remota.
-audit nivel
establece el nivel de registro de auditoría. El nivel predeterminado es 1, lo que significa que solo se informan los rechazos de conexión. El nivel 2 además informa todas las conexiones y desconexiones exitosas. El nivel 4 habilita mensajes de la extensión SECURITY, si está presente, incluida la generación y revocación de autorizaciones y violaciones de la política de seguridad. El nivel 0 desactiva el registro de auditoría. Las líneas de auditoría se envían como salida de error estándar.
-auth archivo-autorizaciones
especifica un archivo que contiene una colección de registros de autorización utilizados para autenticar el acceso. Consulte también las páginas del manual de xdm(1) y Xsecurity(7).
-background none
pide al controlador que no limpie el fondo al iniciarse, si el controlador lo soporta. Puede ser útil para una transición suave con, por ejemplo, el controlador fbdev. Por razones de seguridad, este no es el valor predeterminado, ya que el contenido de la pantalla podría mostrar una sesión anterior del usuario.
-br
establece la ventana raíz predeterminada en negro sólido en lugar del patrón de tejido raíz estándar. Este es el valor predeterminado a menos que se especifique -retro o -wr.
-bs
deshabilita el soporte de almacenamiento en caché (backing store) en todas las pantallas.
+byteswappedclients
Permite conexiones de clientes con una distribución de bytes diferente a la del servidor. Este es el valor predeterminado a menos que se especifique -byteswappedclients.
-byteswappedclients
Prohíbe conexiones de clientes con una distribución de bytes diferente a la del servidor.
-c
desactiva el clic de teclas.
c volumen
establece el volumen del clic de teclas (rango permitable: 0-100).
-cc clase
establece la clase visual para la ventana raíz de las pantallas en color. Los números de clase son los especificados en el protocolo X. No todos los servidores lo obedecen.
-core
hace que el servidor genere un volcado de núcleo en errores fatales.
-displayfd fd
especifica un descriptor de archivo en el proceso de lanzamiento. En lugar de especificar un número de pantalla, el servidor X intentará escuchar en números de pantalla sucesivamente más altos, y al encontrar uno libre, escribirá el número de pantalla de vuelta en este descriptor de archivo como una cadena terminada en nueva línea. La opción -pn se ignora al usar -displayfd.
-deferglyphs fuentes
especifica los tipos de fuentes para las cuales el servidor intentará usar la carga diferida de glifos. fuentes puede ser all (todas las fuentes), none (ninguna fuente) o 16 (solo fuentes de 16 bits).
-dpi resolución
establece la resolución para todas las pantallas, en puntos por pulgada. Para ser utilizado cuando el servidor no puede determinar el tamaño de la(s) pantalla(s) a partir del hardware.
dpms
habilita DPMS (servicios de gestión de energía de pantalla), donde sea soportado. El estado predeterminado depende de la plataforma y la configuración.
-dpms
deshabilita DPMS (servicios de gestión de energía de pantalla). El estado predeterminado depende de la plataforma y la configuración.
-extensionnombre-extensión
deshabilita una extensión con nombre. Si se especifica un nombre de extensión desconocido, se imprimirá una lista de nombres de extensiones aceptadas.
+extensionnombre-extensión
habilita una extensión con nombre. Si se especifica un nombre de extensión desconocido, se imprimirá una lista de nombres de extensiones aceptadas.
-f volumen
establece el volumen del pitido (campana) (rango permitable: 0-100).
-fakescreenfps ps
establece los fps predeterminados de la pantalla de presentador falso (rango permitable: 1-600).
-fp ruta-fuentes
establece la ruta de búsqueda de fuentes. Esta ruta es una lista separada por comas de directorios en los que el servidor X busca bases de datos de fuentes. Consulte la sección FUENTES de esta página del manual para obtener más información y la lista predeterminada.
-help
imprime un mensaje de uso.
-I
hace que todos los argumentos restantes de la línea de comandos sean ignorados.
-iglx
Prohíbe la creación de contextos GLX indirectos. GLX indirecto tiene un uso limitado, ya que carece de soporte para muchas características y extensiones modernas de OpenGL; es más lento que los contextos directos; y abre una gran superficie de ataque para errores de análisis del protocolo. Este es el valor predeterminado a menos que se especifique +iglx.
+iglx
Permite la creación de contextos GLX indirectos.
-maxbigreqsize tamaño
establece la solicitud grande máxima en tamaño MB.
-nocur

deshabilita un tipo de transporte. Por ejemplo, las conexiones TCP/IP se pueden deshabilitar con -nolisten tcp. Esta opción se puede invocar varias veces para deshabilitar la escucha en diferentes tipos de transporte. Los tipos de transporte admitidos dependen de la plataforma, pero comúnmente incluyen:

habilita un tipo de transporte. Por ejemplo, las conexiones TCP/IP se pueden habilitar con -listen tcp. Esta opción se puede invocar varias veces para habilitar la escucha en diferentes tipos de transporte.
-noreset
evita un reinicio del servidor cuando se cierra la última conexión de cliente. Esto anula una opción de línea de comandos -terminate anterior.
-p minutos
establece el tiempo del ciclo del patrón del salvapantallas en minutos.
-pn
permite que el servidor continúe ejecutándose si no logra establecer todos sus sockets bien conocidos (puntos de conexión para clientes), pero establece al menos uno. Esta opción está establecida por defecto.
-nopn
hace que el servidor salga si no logra establecer todos sus sockets bien conocidos (puntos de conexión para clientes).
-r
desactiva la repetición automática.
r
activa la repetición automática.
-retro
inicia el servidor con el repujado y el cursor clásicos visibles. El valor predeterminado es iniciar con una ventana raíz negra y suprimir la visualización del cursor hasta la primera vez que una aplicación llama a XDefineCursor(). Para los servidores kdrive, esto implica -zap.
-s minutos
establece el tiempo de espera del salvapantallas en minutos.
-su
deshabilita el soporte de guardado en todas las pantallas.
-seat seat
asiento en el que ejecutar. Toma una cadena que identifica un asiento en una sintaxis específica de la plataforma. En plataformas que admiten esta característica, se puede utilizar para limitar el servidor a exponer solo un subconjunto específico de dispositivos conectados al sistema.
-t número
establece el umbral de aceleración del puntero en píxeles (es decir, después de cuántos píxeles debe tener efecto la aceleración del puntero).
-terminate [retraso]
hace que el servidor termine al reiniciarse el servidor, en lugar de continuar ejecutándose. Esto anula una opción de línea de comandos -noreset anterior. Si se especifica un retraso en segundos, el servidor espera al menos el retraso. Al final de este período de gracia, si no hay ningún cliente conectado, el servidor termina inmediatamente.
-tst
deshabilita todas las extensiones de prueba (por ejemplo, XTEST, XTrap, XTestExtension1, RECORD).
ttyxx
ignorado, para servidores iniciados de la manera antigua (desde init).
v
establece la preferencia de salvapantallas con video apagado.
-v
establece la preferencia de salvapantallas con video encendido.
-wr
establece la ventana raíz predeterminada en blanco sólido en lugar del patrón de tejido raíz estándar.
-x extension
carga la extensión especificada al iniciar. Esto es inoperante para la mayoría de las implementaciones.
[+-]xinerama
habilita(+) o deshabilita(-) la extensión XINERAMA. El estado predeterminado depende de la plataforma y la configuración.

OPCIONES DEPENDIENTES DEL SERVIDOR

Algunos servidores X aceptan las siguientes opciones:

-ld kilobytes
establece el límite del espacio de datos del servidor en el número especificado de kilobytes. Un valor de cero hace que el tamaño de los datos sea lo más grande posible. El valor predeterminado de -1 deja el límite del espacio de datos sin cambios.
-lf archivos
establece el límite de número de archivos abiertos del servidor en el número especificado. Un valor de cero hace que el límite sea lo más grande posible. El valor predeterminado de -1 deja el límite sin cambios.
-ls kilobytes
establece el límite del espacio de pila del servidor en el número especificado de kilobytes. Un valor de cero hace que el tamaño de la pila sea lo más grande posible. El valor predeterminado de -1 deja el límite del espacio de pila sin cambios.
-maxclients
64|128|256|512 Establece el número máximo de clientes permitidos para conectarse al servidor X. Los valores aceptables son 64, 128, 256 o 512.
-render
default|mono|gray|color establece la política de asignación de color que utilizará la extensión de renderizado.
predeterminado
selecciona la política predeterminada definida para la profundidad de pantalla del servidor X.
mono
no usar ninguna celda de color.
gris
utiliza un mapa de grises de 13 celdas de color para la extensión de renderizado X.
color
utiliza un cubo de colores de hasta 4*4*4 colores (es decir, 64 celdas de color).
-dumbSched
deshabilita la programación inteligente en plataformas que admiten el programador inteligente.
-schedInterval intervalo
establece el intervalo de programación del programador inteligente en intervalo milisegundos.

OPCIONES XDMCP

Los servidores X que admiten XDMCP tienen las siguientes opciones. Consulte la especificación del Protocolo de Control del Gestor de Pantallas X para obtener más información.

-query hostname
habilita XDMCP y envía paquetes Query al hostname especificado.
-broadcast
habilita XDMCP y difunde paquetes BroadcastQuery en la red. Se elegirá el primer gestor de pantalla que responda para la sesión.
-multicast [dirección [contador de saltos]]
Habilita XDMCP y difunde paquetes BroadcastQuery en la red. Se elige el primer gestor de pantalla que responde para la sesión. Si se especifica una dirección, la multidifusión se envía a esa dirección. Si no se especifica ninguna dirección, la multidifusión se envía al grupo de multidifusión IPv6 XDMCP predeterminado. Si se especifica un contador de saltos, se utiliza como el contador de saltos máximo para la multidifusión. Si no se especifica ningún contador de saltos, la multidifusión se establece en un máximo de 1 salto, para evitar que la multidifusión se enrute más allá de la red local.
-indirect hostname
habilita XDMCP y envía paquetes IndirectQuery al hostname especificado.
-port número de puerto
utiliza el número de puerto especificado para los paquetes XDMCP, en lugar del predeterminado. Esta opción debe especificarse antes de cualquier opción -query, -broadcast, -multicast o -indirect.
-from dirección local
especifica la dirección local desde la que conectarse (útil si el host de conexión tiene varias interfaces de red). La dirección local se puede expresar en cualquier forma aceptable para la implementación de gethostbyname(3) de la plataforma host.
-once
hace que el servidor termine (en lugar de reiniciarse) cuando finaliza la sesión XDMCP.
-class clase de pantalla
XDMCP tiene un calificador de pantalla adicional utilizado en la búsqueda de recursos para opciones específicas de la pantalla. Esta opción establece ese valor, por defecto es "MIT-unspecified" (un valor no muy útil).
-cookie xdm-auth-bits
Al probar XDM-AUTHENTICATION-1, se comparte una clave privada entre el servidor y el gestor. Esta opción establece el valor de esos datos privados (¡aunque no es muy privado, ya que está en la línea de comandos!).
-displayID display-id
Otro valor específico de XDMCP, este permite al gestor de pantalla identificar cada pantalla para poder localizar la clave compartida.

OPCIONES XKEYBOARD

Los servidores X que admiten la extensión XKEYBOARD (también conocida como "XKB") aceptan las siguientes opciones. Todos los archivos de diseño especificados en la línea de comandos deben ubicarse en el directorio base XKB o en un subdirectorio, y especificarse como la ruta relativa desde el directorio base XKB. El directorio base XKB predeterminado es /usr/lib/X11/xkb.

[+-]accessx [ timeout [ timeout_mask [ feedback [ options_mask ] ] ] ]
habilita(+) o deshabilita(-) las secuencias de teclas AccessX.
-xkbdir directorio
directorio base para los archivos de diseño del teclado. Esta opción no está disponible para servidores X con setuid (es decir, cuando los UID real y efectivo del servidor X son diferentes).
-ardelay milisegundo

OPTIONS

The X server recognizes the following command line options:

-arinterval milliseconds
sets the autorepeat interval (length of time in milliseconds that should elapse between autorepeat-generated keystrokes).
-arwait milliseconds
sets the autorepeat delay (length of time in milliseconds that a key must be depressed before autorepeat starts).
-xkbmap filename
loads keyboard description in filename on server startup.

NETWORK CONNECTIONS

The X server supports client connections via a platform-dependent subset of the following transport types: TCP/IP, Unix Domain sockets, and several varieties of SVR4 local connections. See the DISPLAY NAMES section of the X(7) manual page to learn how to specify which transport type clients should try to use.

GRANTING ACCESS

The X server implements a platform-dependent subset of the following authorization protocols: MIT-MAGIC-COOKIE-1, XDM-AUTHORIZATION-1, SUN-DES-1, Host Access, and Server Interpreted. See the Xsecurity(7) manual page for information on the operation of these protocols.

Authorization data required by the above protocols is passed to the server in a private file named with the -auth command line option. Each time the server is about to accept the first connection after a reset (or when the server is starting), it reads this file. If this file contains any authorization records, the local host is not automatically allowed access to the server, and only clients which send one of the authorization records contained in the file in the connection setup information will be allowed access. See the Xau manual page for a description of the binary format of this file. See xauth(1) for maintenance of this file, and distribution of its contents to remote hosts.

The X server also uses a host-based access control list for deciding whether or not to accept connections from clients on a particular machine. If no other authorization mechanism is being used, this list initially consists of the host on which the server is running as well as any machines listed in the file /etc/Xn.hosts, where n is the display number of the server. Each line of the file should contain either an Internet hostname (e.g. expo.lcs.mit.edu) or a complete name in the format family:name as described in the xhost(1) manual page. There should be no leading or trailing spaces on any lines. For example:


joesworkstation
corporate.company.com
inet:bigcpu
local:

Users can add or remove hosts from this list and enable or disable access control using the xhost command from the same machine as the server.

The X protocol intrinsically does not have any notion of window operation permissions or place any restrictions on what a client can do; if a program can connect to a display, it has full run of the screen. X servers that support the SECURITY extension fare better because clients can be designated untrusted via the authorization they use to connect; see the xauth(1) manual page for details. Restrictions are imposed on untrusted clients that curtail the mischief they can do. See the SECURITY extension specification for a complete list of these restrictions.

Sites that have better authentication and authorization systems might wish to make use of the hooks in the libraries and the server to provide additional security models.

SIGNALS

The X server attaches special meaning to the following signals:

SIGHUP
This signal causes the server to close all existing connections, free all resources, and restore all defaults. It is sent by the display manager whenever the main user's main application (usually an xterm or window manager) exits to force the server to clean up and prepare for the next user.
SIGTERM
This signal causes the server to exit cleanly.
SIGUSR1
This signal is used quite differently from either of the above. When the server starts, it checks to see if it has inherited SIGUSR1 as SIG_IGN instead of the usual SIG_DFL. In this case, the server sends a SIGUSR1 to its parent process after it has set up the various connection schemes. Xdm uses this feature to recognize when connecting to the server is possible.

FONTS

The X server can obtain fonts from directories and/or from font servers. The list of directories and font servers the X server uses when trying to open a font is controlled by the font path.

The default font path is /usr/share/fonts/misc,/usr/share/fonts/TTF,/usr/share/fonts/OTF,/usr/share/fonts/Type1,/usr/share/fonts/100dpi,/usr/share/fonts/75dpi .

A special kind of directory can be specified using the catalogue: prefix. Directories specified this way can contain symlinks pointing to the real font directories. See the FONTPATH.D section for details.

The font path can be set with the -fp option or by xset(1) after the server has started.

FONTPATH.D

You can specify a special kind of font path in the form catalogue:<dir>. The directory specified after the catalogue: prefix will be scanned for symlinks and each symlink destination will be added as a local fontfile FPE.

The symlink can be suffixed by attributes such as 'unscaled', which will be passed through to the underlying fontfile FPE. The only exception is the newly introduced 'pri' attribute, which will be used for ordering the font paths specified by the symlinks.

An example configuration:

    75dpi:unscaled:pri=20 -> /usr/share/X11/fonts/75dpi
    ghostscript:pri=60 -> /usr/share/fonts/default/ghostscript
    misc:unscaled:pri=10 -> /usr/share/X11/fonts/misc
    type1:pri=40 -> /usr/share/X11/fonts/Type1
    type1:pri=50 -> /usr/share/fonts/default/Type1

This will add /usr/share/X11/fonts/misc as the first FPE with the attribute 'unscaled', second FPE will be /usr/share/X11/fonts/75dpi, also with the attribute 'unscaled' etc. This is functionally equivalent to setting the following font path:

    /usr/share/X11/fonts/misc:unscaled,
    /usr/share/X11/fonts/75dpi:unscaled,
    /usr/share/X11/fonts/Type1,
    /usr/share/fonts/default/Type1,
    /usr/share/fonts/default/ghostscript
