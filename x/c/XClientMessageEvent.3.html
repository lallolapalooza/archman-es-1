XClientMessageEvent(3) FUNCIONES DE XLIB XClientMessageEvent(3)

NOMBRE

XClientMessageEvent - estructura del evento ClientMessage

ESTRUCTURAS

La estructura para los eventos de ClientMessage contiene:

typedef struct {
        int type;       /* ClientMessage */
        unsigned long serial;           /* # de la última petición procesada por el servidor */
        Bool send_event;                /* verdadero si esto provino de una petición SendEvent */
        Display *display;               /* Display desde el que se leyó el evento */
        Window window;
        Atom message_type;
        int format;
        union {
                char b[20];
                short s[10];
                long l[5];
                } data;
} XClientMessageEvent;

Cuando recibes este evento, los miembros de la estructura se establecen de la siguiente manera.

El miembro `type` se establece en el nombre de la constante del tipo de evento que lo identifica de forma única. Por ejemplo, cuando el servidor X informa de un evento GraphicsExpose a una aplicación cliente, envía una estructura XGraphicsExposeEvent con el miembro `type` establecido en GraphicsExpose. El miembro `display` se establece en un puntero al display sobre el que se leyó el evento. El miembro `send_event` se establece en True si el evento provino de una petición de protocolo SendEvent. El miembro `serial` se establece a partir del número de serie informado en el protocolo, pero expandido desde los 16 bits menos significativos a un valor completo de 32 bits. El miembro `window` se establece en la ventana que es más útil para los distribuidores de toolkits.

El miembro `message_type` se establece en un átomo que indica cómo deben ser interpretados los datos por el cliente receptor. El miembro `format` se establece en 8, 16 o 32 y especifica si los datos deben verse como una lista de bytes, shorts o longs. El miembro `data` es una unión que contiene los miembros b, s y l. Los miembros b, s y l representan datos de veinte valores de 8 bits, diez valores de 16 bits y cinco valores de 32 bits. Es posible que los tipos de mensaje particulares no utilicen todos estos valores. El servidor X no impone ninguna interpretación sobre los valores en los miembros `window`, `message_type` o `data`.
