XCreateGC(3) XLIB FUNCTIONS XCreateGC(3)

NOMBRE

XCreateGC, XCopyGC, XChangeGC, XGetGCValues, XFreeGC, XGContextFromGC, XGCValues - crear o liberar contextos gráficos y estructura de contexto gráfico

SINTAXIS

GC XCreateGC(Display *display, Drawable d, unsigned long valuemask, XGCValues *values);

int XCopyGC(Display *display, GC src, unsigned long valuemask, GC dest);

int XChangeGC(Display *display, GC gc, unsigned long valuemask, XGCValues *values);

Status XGetGCValues(Display *display, GC gc, unsigned long valuemask, XGCValues *values_return);

int XFreeGC(Display *display, GC gc);

GContext XGContextFromGC(GC gc);

ARGUMENTOS

d
Especifica el drawable.
dest
Especifica el GC de destino.
display
Especifica la conexión con el servidor X.
gc
Especifica el GC.
src
Especifica los componentes del GC de origen.
valuemask
Especifica qué componentes del GC se van a establecer, copiar, cambiar o devolver. Este argumento es el OR inclusivo a nivel de bits de cero o más de los bits de máscara de componentes de GC válidos.
values
Especifica los valores según lo indicado por la máscara de valores.
values_return
Devuelve los valores del GC en la estructura XGCValues especificada.

DESCRIPCIÓN

La función XCreateGC crea un contexto gráfico y devuelve un GC. El GC se puede utilizar con cualquier drawable de destino que tenga la misma raíz y profundidad que el drawable especificado. El uso con otros drawables resulta en un error BadMatch.

XCreateGC puede generar errores BadAlloc, BadDrawable, BadFont, BadMatch, BadPixmap y BadValue.

La función XCopyGC copia los componentes especificados del GC de origen al GC de destino. Los GCs de origen y destino deben tener la misma raíz y profundidad, o se producirá un error BadMatch. La máscara de valores especifica qué componente copiar, como para XCreateGC.

XCopyGC puede generar errores BadAlloc, BadGC y BadMatch.

La función XChangeGC cambia los componentes especificados por la máscara de valores para el GC especificado. El argumento de valores contiene los valores que se van a establecer. Los valores y las restricciones son los mismos que para XCreateGC. Cambiar la máscara de corte anula cualquier solicitud anterior de XSetClipRectangles sobre el contexto. Cambiar el desplazamiento de guiones o la lista de guiones anula cualquier solicitud anterior de XSetDashes sobre el contexto. El orden en que se verifican y alteran los componentes depende del servidor. Si se genera un error, es posible que se hayan alterado un subconjunto de los componentes.

XChangeGC puede generar errores BadAlloc, BadFont, BadGC, BadMatch, BadPixmap y BadValue.

La función XGetGCValues devuelve los componentes especificados por la máscara de valores para el GC especificado. Si la máscara de valores contiene un conjunto válido de bits de máscara de GC (GCFunction, GCPlaneMask, GCForeground, GCBackground, GCLineWidth, GCLineStyle, GCCapStyle, GCJoinStyle, GCFillStyle, GCFillRule, GCTile, GCStipple, GCTileStipXOrigin, GCTileStipYOrigin, GCFont, GCSubwindowMode, GCGraphicsExposures, GCClipXOrigin, GCClipYOrigin, GCDashOffset o GCArcMode) y no se produce ningún error, XGetGCValues establece los componentes solicitados en values_return y devuelve un estado distinto de cero. De lo contrario, devuelve un estado cero. Tenga en cuenta que la máscara de corte y la lista de guiones (representadas por los bits GCClipMask y GCDashList, respectivamente, en la máscara de valores) no se pueden solicitar. Tenga en cuenta también que se devolverá un ID de recurso no válido (con uno o más de los tres bits más significativos establecidos en 1) para GCFont, GCTile y GCStipple si el componente nunca ha sido establecido explícitamente por el cliente.

La función XFreeGC destruye el GC especificado, así como todo el almacenamiento asociado.

XFreeGC puede generar un error BadGC.

Los atributos de función de un GC se utilizan cuando se actualiza una sección de un drawable (el destino) con bits de otro lugar (el origen). La función en un GC define cómo se deben calcular los nuevos bits de destino a partir de los bits de origen y los bits de destino antiguos. GXcopy es típicamente el más útil porque funcionará en una pantalla en color, pero aplicaciones especiales pueden usar otras funciones, particularmente en conjunción con planos particulares de una pantalla en color. Muchas operaciones gráficas dependen de los valores de los píxeles o de los planos en un GC. El atributo de planos es de tipo `long`, y especifica qué planos del destino se van a modificar, un bit por plano. Una pantalla monocromática tiene solo un plano y será el bit menos significativo de la palabra. A medida que se añaden planos al hardware de visualización, ocuparán bits más significativos en la máscara de planos.

En las operaciones gráficas, dado un píxel de origen y otro de destino, el resultado se calcula bit a bit sobre los bits correspondientes de los píxeles. Es decir, se realiza una operación booleana en cada plano de bits. La máscara de planos (`plane_mask`) restringe la operación a un subconjunto de planos. Una constante macro `AllPlanes` se puede usar para referirse a todos los planos de la pantalla simultáneamente. El resultado se calcula de la siguiente manera:

((src FUNC dst) AND plane-mask) OR (dst AND (NOT plane-mask))

No se realiza comprobación de rango en los valores de primer plano (`foreground`), fondo (`background`) o máscara de planos (`plane_mask`). Simplemente se truncan al número apropiado de bits. El ancho de línea se mide en píxeles y puede ser mayor o igual a uno (línea ancha) o puede ser el valor especial cero (línea fina).

Las líneas anchas se dibujan centradas en la trayectoria descrita por la solicitud gráfica. A menos que se especifique lo contrario por el estilo de unión (`join-style`) o el estilo de remate (`cap-style`), el cuadro delimitador de una línea ancha con puntos finales [x1, y1], [x2, y2] y ancho w es un rectángulo con vértices en las siguientes coordenadas reales:

[x1-(w*sn/2), y1+(w*cs/2)], [x1+(w*sn/2), y1-(w*cs/2)],
[x2-(w*sn/2), y2+(w*cs/2)], [x2+(w*sn/2), y2-(w*cs/2)]

Aquí, sn es el seno del ángulo de la línea, y cs es el coseno del ángulo de la línea. Un píxel es parte de la línea y, por lo tanto, se dibuja si el centro del píxel está completamente dentro del cuadro delimitador (que se considera que tiene bordes infinitamente finos). Si el centro del píxel está exactamente en el cuadro delimitador, es parte de la línea si y solo si el interior está inmediatamente a su derecha (dirección de aumento de x). Los píxeles con centros en un borde horizontal son un caso especial y son parte de la línea si y solo si el interior o el borde está inmediatamente debajo (dirección de aumento de y) y el interior o el borde está inmediatamente a la derecha (dirección de aumento de x).

Las líneas finas (ancho de línea cero) son líneas de un píxel de ancho dibujadas utilizando un algoritmo no especificado y dependiente del dispositivo. Solo hay dos restricciones en este algoritmo.

1.
Si se dibuja una línea sin recorte desde [x1,y1] hasta [x2,y2] y si otra línea se dibuja sin recorte desde [x1+dx,y1+dy] hasta [x2+dx,y2+dy], un punto [x,y] es tocado al dibujar la primera línea si y solo si el punto [x+dx,y+dy] es tocado al dibujar la segunda línea.
2.
El conjunto efectivo de puntos que componen una línea no puede verse afectado por el recorte. Es decir, un punto se toca en una línea recortada si y solo si el punto se encuentra dentro de la región de recorte y el punto sería tocado por la línea cuando se dibuja sin recorte.

Una línea ancha dibujada desde [x1,y1] hasta [x2,y2] siempre dibuja los mismos píxeles que una línea ancha dibujada desde [x2,y2] hasta [x1,y1], sin contar el estilo de remate y el estilo de unión. Se recomienda que esta propiedad sea cierta para las líneas finas, pero no es obligatorio. Un ancho de línea de cero puede diferir de un ancho de línea de uno en los píxeles que se dibujan. Esto permite el uso del hardware de dibujo de líneas de muchos fabricantes, que puede funcionar muchas veces más rápido que las líneas anchas especificadas con mayor precisión.

En general, dibujar una línea fina será más rápido que dibujar una línea ancha de ancho uno. Sin embargo, debido a sus diferentes algoritmos de dibujo, las líneas finas pueden no combinarse estéticamente bien con las líneas anchas. Si se desea obtener resultados precisos y uniformes en todas las pantallas, un cliente siempre debe usar un ancho de línea de uno en lugar de un ancho de línea de cero.

El estilo de línea (`line-style`) define qué secciones de una línea se dibujan:

LineSolid Se dibuja toda la trayectoria de la línea.
LineDoubleDash Se dibuja toda la trayectoria de la línea, pero los guiones pares se rellenan de manera diferente a los guiones impares (ver estilo de relleno) con el estilo CapButt utilizado donde se encuentran los guiones pares e impares.
LineOnOffDash Solo se dibujan los guiones pares, y el estilo de remate se aplica a todos los extremos internos de los guiones individuales, excepto que CapNotLast se trata como CapButt.

El estilo de remate (`cap-style`) define cómo se dibujan los puntos finales de una trayectoria:

CapNotLast Esto es equivalente a CapButt, excepto que para un ancho de línea de cero no se dibuja el punto final.
CapButt La línea es cuadrada en el punto final (perpendicular a la pendiente de la línea) sin proyección más allá.
CapRound La línea tiene un arco circular con el diámetro igual al ancho de línea, centrado en el punto final. (Esto es equivalente a CapButt para un ancho de línea de cero).
CapProjecting La línea es cuadrada en el extremo, pero la trayectoria continúa más allá del punto final una distancia igual a la mitad del ancho de línea. (Esto es equivalente a CapButt para un ancho de línea de cero).

El estilo de unión (`join-style`) define cómo se dibujan las esquinas para las líneas anchas:

JoinMiter Los bordes exteriores de dos líneas se extienden para encontrarse en un ángulo. Sin embargo, si el ángulo es menor a 11 grados, entonces se usa un estilo de unión JoinBevel en su lugar.
JoinRound La esquina es un arco circular con el diámetro igual al ancho de línea, centrado en el punto de unión.
JoinBevel La esquina tiene estilos de punto final CapButt con la muesca triangular rellena.

Para una línea con puntos finales coincidentes (x1=x2, y1=y2), cuando se aplica el estilo de remate a ambos puntos finales, la semántica depende del ancho de línea y del estilo de remate:

CapNotLast fina Los resultados dependen del dispositivo, pero el efecto deseado es que no se dibuje nada.
CapButt fina Los resultados dependen del dispositivo, pero el efecto deseado es que se dibuje un solo píxel.
CapRound fina Los resultados son los mismos que para CapButt /fina.
CapProjecting fina Los resultados son los mismos que para CapButt /fina.
CapButt ancha No se dibuja nada.
CapRound ancha La trayectoria cerrada es un círculo, centrado en el punto final, y con el diámetro igual al ancho de línea.
CapProjecting ancha La trayectoria cerrada es un cuadrado, alineado con los ejes de coordenadas, centrado en el punto final y con los lados iguales al ancho de línea.

Para una línea con puntos finales coincidentes (x1=x2, y1=y2), cuando se aplica el estilo de unión en uno o ambos puntos finales, el efecto es como si la línea se hubiera eliminado de la trayectoria general. Sin embargo, si la trayectoria total consiste o se reduce a un solo punto unido consigo mismo, el efecto es el mismo que cuando se aplica el estilo de remate en ambos puntos finales.

La tesela/tramado (`tile/stipple`) representa un plano bidimensional infinito, con la tesela/tramado replicada en todas las dimensiones. Cuando ese plano se superpone al drawable para su uso en una operación gráfica, la esquina superior izquierda de alguna instancia de la tesela/tramado se encuentra en las coordenadas dentro del drawable especificadas por el origen de la tesela/tramado. Los orígenes de la tesela/tramado y del recorte (`tile/stipple` and clip origins) se interpretan en relación con el origen del drawable de destino que se especifica en una solicitud gráfica. El pixmap de tesela debe tener la misma raíz y profundidad que el GC, o se produce un error `BadMatch`. El pixmap de tramado debe tener profundidad uno y debe tener la misma raíz que el GC, o se produce un error `BadMatch`. Para las operaciones de tramado donde el estilo de relleno es `FillStippled` pero no `FillOpaqueStippled`, el patrón de tramado se tesela en un solo plano y actúa como una máscara de recorte adicional que se ANDeará con la máscara de recorte. Aunque algunos tamaños pueden ser más rápidos de usar que otros, se puede utilizar cualquier tamaño de pixmap para teselar o tramar.

El estilo de relleno (`fill-style`) define el contenido del origen para las solicitudes de línea, texto y relleno. Para todas las solicitudes de texto y relleno (por ejemplo, `XDrawText`, `XDrawText16`, `XFillRectangle`, `XFillPolygon` y `XFillArc`); para las solicitudes de línea con estilo de línea `LineSolid` (por ejemplo, `XDrawLine`, `XDrawSegments`, `XDrawRectangle`, `XDrawArc`); y para los guiones pares para las solicitudes de línea con estilo de línea `LineOnOffDash` o `LineDoubleDash`, se aplican lo siguiente:

FillSolid Primer plano (Foreground)
FillTiled Tesela (Tile)
FillOpaqueStippled Una tesela con el mismo ancho y alto que el tramado, pero con fondo en todas partes donde el tramado tiene un cero y con primer plano en todas partes donde el tramado tiene un uno
FillStippled Primer plano enmascarado por el tramado

NAME

XCreateGC - create a graphics context

SYNTAX

GC XCreateGC(Display *display, XIDd, unsigned long valuemask, XGCValues *values);

GC XGCToWindow(Display *display, Window w, unsigned long valuemask, XGCValues *values);

GC XGCToPixmap(Display *display, Pixmap p, unsigned long valuemask, XGCValues *values);

ARGUMENTS

display
Specifies the connection to the X server.
d
Specifies the drawable (a Window or Pixmap).
w
Specifies the window.
p
Specifies the pixmap.
valuemask
Specifies which of the optional values (in the values structure) are to be used.
values
Specifies the structure containing the optional GC attribute values.

DESCRIPTION

A graphics context (GC) is a container for graphics attributes that affect how output is generated. For example, the foreground color, line style, and font are stored in a GC.

When you set GC components, the changes are cached. Some components may be cached in the display hardware for performance reasons. Some components are not cached in hardware.

You can use the same GC for multiple drawables. However, the GC is associated with a particular screen. If you want to use a GC on a different screen, you must explicitly copy it using XCopyGC.

The values in the XGCValues structure are:

foreground
Foreground color.
background
Background color.
line-width
Line width.
line-style
Line style.
cap-style
Line cap style.
join-style
Line join style.
fill-style
Fill style.
fill-rule
Fill rule.
arc-mode
Arc mode.
font
Font.
subwindow-mode
Subwindow mode.
dashes
Dash list for dashed line styles.
clip-x-origin
X-coordinate of clipping origin.
clip-y-origin
Y-coordinate of clipping origin.
clip-mask
Pixmap to use for clipping.
graphics-exposure
Flag to control GraphicsExpose event generation.
tile
Pixmap to use for tiling.
stipple
Pixmap to use for stippling.
tile-stip-x-origin
X-coordinate of tile/stipple origin.
tile-stip-y-origin
Y-coordinate of tile/stipple origin.

The valuemask specifies which attributes are being set.

XCreateGC creates a GC for the specified drawable `d`. The initial values are taken from the GC of the drawable, if any. Any values specified in the values structure override the initial values.

XGCToWindow is equivalent to XCreateGC, but it creates the GC for a window.

XGCToPixmap is equivalent to XCreateGC, but it creates the GC for a pixmap.

If a pixmap is used as a tile or stipple, it must have the same root and depth as the destination drawable, or a BadMatch error results.

If the GC is created for a window, the default clip-mask is a rectangle covering the entire window. If the GC is created for a pixmap, the default clip-mask is undefined.

The default values are: foreground = 1, background = 0, line-width = 0, line-style = LineSolid, cap-style = CapButt, join-style = JoinMiter, fill-style = FillSolid, fill-rule = EvenOddRule, arc-mode = ArcPieSlice, font = default font, subwindow-mode = ClipByChildren, clip-mask = None, graphics-exposure = True, tile = pixmap, stipple = pixmap, and all origins = 0.

Note that the default foreground and background colors depend on the screen.

When drawing lines with line-style LineDoubleDash, the odd dashes are controlled by the fill-style in the following manner:

FillSolid Background
FillTiled Same as for even dashes
FillOpaqueStippled Same as for even dashes
FillStippled Background masked by stipple

Storing a pixmap in a GC might or might not result in a copy being made. If the pixmap is later used as the destination for a graphics request, the change might or might not be reflected in the GC. If the pixmap is used simultaneously in a graphics request both as a destination and as a tile or stipple, the results are undefined.

For optimum performance, you should draw as much as possible with the same GC (without changing its components). The costs of changing GC components relative to using different GCs depend on the display hardware and the server implementation. It is quite likely that some amount of GC information will be cached in display hardware and that such hardware can only cache a small number of GCs.

The dashes value is actually a simplified form of the more general patterns that can be set with XSetDashes. Specifying a value of N is equivalent to specifying the two-element list [N, N] in XSetDashes. The value must be nonzero, or a BadValue error results.

The clip-mask restricts writes to the destination drawable. If the clip-mask is set to a pixmap, it must have depth one and have the same root as the GC, or a BadMatch error results. If clip-mask is set to None, the pixels are always drawn regardless of the clip origin. The clip-mask also can be set by calling the XSetClipRectangles or XSetRegion functions. Only pixels where the clip-mask has a bit set to 1 are drawn. Pixels are not drawn outside the area covered by the clip-mask or where the clip-mask has a bit set to 0. The clip-mask affects all graphics requests. The clip-mask does not clip sources. The clip-mask origin is interpreted relative to the origin of whatever destination drawable is specified in a graphics request.

You can set the subwindow-mode to ClipByChildren or IncludeInferiors. For ClipByChildren, both source and destination windows are additionally clipped by all viewable InputOutput children. For IncludeInferiors, neither source nor destination window is clipped by inferiors. This will result in including subwindow contents in the source and drawing through subwindow boundaries of the destination. The use of IncludeInferiors on a window of one depth with mapped inferiors of differing depth is not illegal, but the semantics are undefined by the core protocol.

The fill-rule defines what pixels are inside (drawn) for paths given in XFillPolygon requests and can be set to EvenOddRule or WindingRule. For EvenOddRule, a point is inside if an infinite ray with the point as origin crosses the path an odd number of times. For WindingRule, a point is inside if an infinite ray with the point as origin crosses an unequal number of clockwise and counterclockwise directed path segments. A clockwise directed path segment is one that crosses the ray from left to right as observed from the point. A counterclockwise segment is one that crosses the ray from right to left as observed from the point. The case where a directed line segment is coincident with the ray is uninteresting because you can simply choose a different ray that is not coincident with a segment.

For both EvenOddRule and WindingRule, a point is infinitely small, and the path is an infinitely thin line. A pixel is inside if the center point of the pixel is inside and the center point is not on the boundary. If the center point is on the boundary, the pixel is inside if and only if the polygon interior is immediately to its right (x increasing direction). Pixels with centers on a horizontal edge are a special case and are inside if and only if the polygon interior is immediately below (y increasing direction).

The arc-mode controls filling in the XFillArcs function and can be set to ArcPieSlice or ArcChord. For ArcPieSlice, the arcs are pie-slice filled. For ArcChord, the arcs are chord filled.

The graphics-exposure flag controls GraphicsExpose event generation for XCopyArea and XCopyPlane requests (and any similar requests defined by extensions).

DIAGNOSTICS

BadAlloc
The server failed to allocate the requested resource or server memory.
BadDrawable
A value for a Drawable argument does not name a defined Window or Pixmap.
BadFont
A value for a Font or GContext argument does not name a defined Font.
BadGC
A value for a GContext argument does not name a defined GContext.
BadMatch
An InputOnly window is used as a Drawable.
BadMatch
Some argument or pair of arguments has the correct type and range but fails to match in some other way required by the request.
BadPixmap
A value for a Pixmap argument does not name a defined Pixmap.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
