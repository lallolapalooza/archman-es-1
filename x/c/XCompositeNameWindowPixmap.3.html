NOMBRE

Xcomposite - biblioteca de la extensión X Composite

SINOPSIS

#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base_return, int *error_base_return);

Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

int XCompositeVersion(void);

void XCompositeRedirectWindow(Display *dpy, Window window, int update);

void XCompositeRedirectSubwindows(Display *dpy, Window window, int update);

void XCompositeUnredirectWindow(Display *dpy, Window window, int update);

void XCompositeUnredirectSubwindows(Display *dpy, Window window, int update);

XserverRegion XCompositeCreateRegionFromBorderClip(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPCIÓN

La extensión composite proporciona varios mecanismos relacionados:

Almacenamiento por jerarquía

La representación de una jerarquía completa de ventanas se redirige a un almacenamiento fuera de pantalla. Los píxeles de esa jerarquía están disponibles siempre que sea visible. El almacenamiento se reasigna automáticamente cuando la ventana de nivel superior cambia de tamaño. El contenido más allá de la geometría de la ventana superior no se conserva.

Actualización automática de sombras

Cuando una jerarquía se representa fuera de pantalla, el servidor X proporciona un mecanismo automático para presentar ese contenido dentro de la ventana padre. La implementación es libre de hacer que esta actualización se retrase una cantidad de tiempo no especificada con respecto a las operaciones de renderizado reales. Este mecanismo de actualización automática puede deshabilitarse para que el contenido de la ventana padre pueda ser determinado completamente por una aplicación externa.

Ventana de superposición de composición (Composite Overlay Window)

La versión 0.3 del protocolo agrega la Ventana de Superposición de Composición, que proporciona a los gestores de composición una superficie sobre la cual dibujar sin interferencias. Esta ventana está siempre por encima de las ventanas normales y siempre por debajo de la ventana del salvapantallas. Es una ventana InputOutput con el ancho y la altura de las dimensiones de la pantalla. Su visual es el visual raíz y su borde tiene cero de ancho. Los intentos de redirigirla usando la extensión composite se ignoran. Esta ventana no aparece en la respuesta de la solicitud QueryTree. También es una ventana de anulación de redirección (override redirect). Estas dos últimas características la hacen invisible para los gestores de ventanas y otros clientes de X11. La única forma de acceder al XID de esta ventana es a través de la solicitud CompositeGetOverlayWindow. Inicialmente, la Ventana de Superposición de Composición está sin mapear.

Recorte de la ventana padre

La versión 0.4 del protocolo modifica la semántica del recorte de la ventana padre en presencia de hijos redirigidos manualmente. Con esta versión, el área en el padre cubierta por hijos redirigidos manualmente se deja en la lista de recorte del padre en lugar de eliminarse como en versiones anteriores.

El almacenamiento fuera de pantalla puede crearse para ventanas individuales o para todos los hijos de una ventana. La actualización manual de sombras puede ser seleccionada por una sola aplicación para cada ventana; la actualización manual también puede seleccionarse por ventana o para cada hijo de una ventana. La detección de cuándo actualizar puede hacerse con la extensión Damage.

El almacenamiento fuera de pantalla incluye el contenido de la ventana, sus bordes y el contenido de todos los descendientes.

ARGUMENTOS

display

Puntero a la estructura Display devuelta por XOpenDisplay para la conexión con el servidor X.

event_base_return

Puntero a un entero donde se almacenará el valor base de los eventos de la Extensión Composite.

error_base_return

Puntero a un entero donde se almacenará el valor base de los errores de la Extensión Composite.

major_version_return

Puntero a un entero donde se almacenará la versión principal de la Extensión Composite soportada por el servidor X.

minor_version_return

Puntero a un entero donde se almacenará la versión menor de la Extensión Composite soportada por el servidor X.

window

Especifica el ID de la ventana sobre la que operar.

update

Especifica el modo de actualización del contenido de la ventana. Debe ser CompositeRedirectAutomatic o CompositeRedirectManual.

FUNCIONES

XCompositeQueryExtension

XCompositeQueryExtension determina si la Extensión Composite está disponible en la pantalla dada. Devuelve True si la extensión es soportada, de lo contrario False. Si la extensión está presente, se devuelven los valores base para eventos y errores, y se pueden usar para decodificar los valores de eventos y errores entrantes.

XCompositeQueryVersion

XCompositeQueryVersion determina si el Servidor X soporta una versión de la Extensión X Composite compatible con la biblioteca cliente. Se devuelve un Status distinto de cero si se soporta una versión compatible de la extensión, de lo contrario se devuelve un Status cero. Si la extensión es soportada, se devuelven los números de versión principal y secundaria para indicar el nivel de soporte de la Extensión Composite. Ninguna otra función de XComposite (excepto XCompositeQueryExtension) puede ser llamada antes de esta función. Si un cliente viola esta regla, los efectos de todas las llamadas posteriores de XComposite que realice no están definidos.

XCompositeVersion

XCompositeVersion devuelve la versión de la biblioteca X Composite. El número de versión se codifica como: (principal * 10000) + (secundaria * 100) + revisión

Por ejemplo, la versión 1.4.6 se codificaría como el entero 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow solicita al servidor X que dirija la jerarquía que comienza en window a un almacenamiento fuera de pantalla. El argumento update especifica si el contenido se refleja automáticamente en la ventana padre o no. Solo un cliente a la vez puede especificar un tipo de actualización de CompositeRedirectManual; otro intento resultará en un error BadAccess. Cuando todos los clientes que habilitan la redirección terminan, la redirección se deshabilitará automáticamente.

La ventana raíz no puede ser redirigida. Hacerlo resulta en un error BadMatch. Especificar un ID de ventana inválido resultará en un error BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows solicita al servidor X que redirija las jerarquías que comienzan en todos los hijos actuales y futuros de window como en XCompositeRedirectWindow. Si update es CompositeRedirectManual, entonces se inhibe la pintura del fondo de la ventana durante la manipulación de la ventana y las solicitudes ClearArea.

XCompositeUnredirectWindow

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de window. Si la ventana especificada no fue seleccionada para redirección por el cliente actual, se produce un error BadValue.

XCompositeUnredirectSubwindows

XCompositeUnredirectSubwindows solicita al servidor X que termine la redirección de todos los hijos de window. Si la ventana especificada no fue seleccionada para sub-redirección por el cliente actual, se produce un error BadValue.

XCompositeCreateRegionFromBorderClip

XCompositeCreateRegionFromBorderClip crea una región que contiene el borde "usual"

XCompositeNameWindowPixmap(3) — libxcomposite — Arch Linux

NAME

XCompositeNameWindowPixmap, XCompositeGetWindowPixmap, XCompositeRegion, XCompositeGetEclipseRegion, XCompositeNameWindow, XCompositeCreateRegion, XCompositeDestroyRegion, XCompositeSetSubwindowMode, XCompositeCompositeWindow, XCompositeRedirectSubwindow, XCompositeUnredirectSubwindow, XCompositeGetOverlayWindow, XCompositeReleaseOverlayWindow, XCompositeGetPixmaps - Composite extension window information and control

SYNOPSIS

#include <X11/extensions/Xcomposite.h>

Pixmap
XCompositeGetWindowPixmap(Display *dpy, Window window);

XRegion
XCompositeGetEclipseRegion(Display *dpy, Window window);

Pixmap
XCompositeNameWindowPixmap(Display *dpy, Window window);

Window
XCompositeGetOverlayWindow(Display *dpy, Window window);

void
XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

The Composite extension provides a mechanism for redirecting graphics operations away from a window to an off-screen pixmap. This allows for applications to implement custom window decorations, effects, or to build compositing window managers.

All functions except XCompositeGetOverlayWindow and XCompositeReleaseOverlayWindow are available in Composite Extension version 0.2.

XCompositeGetWindowPixmap retrieves the pixmap associated with the window. This pixmap is the off-screen storage for the window's contents.

XCompositeGetEclipseRegion returns the region of the window that is actually visible, considering the clipping that occurs due to siblings and the parent window. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.

ARGUMENTS

dpy
Specifies the connection to the X server.
window
Specifies the window or the root window of the screen for which information is requested or actions are to be taken.

FUNCTIONS

The following functions are provided by the X composite extension.

XCompositeGetWindowPixmap

XCompositeGetWindowPixmap returns the pixmap associated with the given window. This pixmap is the off-screen storage used for the window's contents. If the window is not redirected, or if the composite extension is not supported on the screen, a BadMatch error will be raised. The returned Pixmap is valid as long as the window is mapped and has not been reconfigured. Clients should not free this pixmap.

XCompositeRegion

XCompositeRegion returns the clip value; that is the area of the window clipped against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeGetEclipseRegion

XCompositeGetEclipseRegion returns the clip value; that is the area of the window clipped against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
