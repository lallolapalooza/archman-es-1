XCURSOR(3) X Version 11 XCURSOR(3)

NOMBRE

Xcursor - Biblioteca de gestión de cursores

SINOPSIS

#include <X11/Xcursor/Xcursor.h>

DESCRIPCIÓN

Xcursor es una biblioteca simple diseñada para ayudar a localizar y cargar cursores. Los cursores se pueden cargar desde archivos o desde memoria. Existe una biblioteca de cursores comunes que se mapean a los nombres de cursores estándar de X. Los cursores pueden existir en varios tamaños y la biblioteca elige automáticamente el mejor tamaño.

VISIÓN GENERAL FUNCIONAL

Xcursor está construido en un par de capas; en la capa inferior se encuentra el código que puede cargar imágenes de cursores desde archivos. Por encima de eso, hay una capa que localiza archivos de cursores basándose en la ruta de la biblioteca y el tema. En la parte superior, hay una capa que construye cursores ya sea a partir de una imagen cargada de un archivo o de uno de los cursores estándar de X. Al utilizar imágenes cargadas desde archivos, Xcursor prefiere usar la solicitud `CreateCursor` de la extensión Render si es compatible con el servidor X. Cuando no es compatible, Xcursor mapea la imagen del cursor a un cursor estándar de X y utiliza la solicitud `CreateCursor` principal.

ARCHIVOS DE CURSORES

Xcursor define un nuevo formato para cursores en disco. Cada archivo contiene una o más imágenes de cursores. Cada imagen de cursor está etiquetada con un tamaño nominal para que el mejor tamaño pueda seleccionarse automáticamente. Múltiples cursores del mismo tamaño nominal pueden cargarse juntos; se espera que las aplicaciones los utilicen como una secuencia animada.

Los archivos de cursores se almacenan como una cabecera que contiene una tabla de contenido seguida de una secuencia de bloques. La tabla de contenido indica el tipo, subtipo y posición en el archivo de cada bloque. La cabecera del archivo tiene el siguiente aspecto:


mágica:	CARD32 "Xcur" (0x58, 0x63, 0x75, 0x72)
cabecera:	CARD32 bytes en esta cabecera
versión:	CARD32 número de versión del archivo
ntoc:	CARD32 número de entradas de la tabla de contenido
toc:	LISTofTOC tabla de contenido

Cada entrada de la tabla de contenido tiene el siguiente aspecto:


tipo:	CARD32 tipo de entrada
subtipo:	CARD32 etiqueta específica del tipo - tamaño para imágenes
posición:	CARD32 posición absoluta en bytes de la tabla en el archivo

Cada bloque en el archivo tiene un conjunto de campos de cabecera comunes seguidos de campos adicionales específicos del tipo:


cabecera:	CARD32 bytes en la cabecera del bloque (incluyendo campos específicos del tipo)
tipo:	CARD32 debe coincidir con el tipo en la tabla de contenido para este bloque
subtipo:	CARD32 debe coincidir con el subtipo en la tabla de contenido para este bloque
versión:	CARD32 número de versión para este tipo de bloque

Actualmente hay dos tipos de bloques definidos para archivos de cursores; comentarios e imágenes. Los comentarios tienen el siguiente aspecto:


cabecera:	20 Las cabeceras de comentarios tienen 20 bytes
tipo:	0xfffe0001 El tipo de comentario es 0xfffe0001
subtipo:	{ 1 (COPYRIGHT), 2 (LICENSE), 3 (OTHER) }
versión:	1
longitud:	CARD32 longitud en bytes de la cadena UTF-8
cadena:	LISTofCARD8 Cadena UTF-8

Las imágenes tienen el siguiente aspecto:


cabecera:	36 Las cabeceras de imágenes tienen 36 bytes
tipo:	0xfffd0002 El tipo de imagen es 0xfffd0002
subtipo:	CARD32 El subtipo de imagen es el tamaño nominal
versión:	1
ancho:	CARD32 Debe ser menor o igual a 0x7fff
alto:	CARD32 Debe ser menor o igual a 0x7fff
xhot:	CARD32 Debe ser menor o igual al ancho
yhot:	CARD32 Debe ser menor o igual al alto
retraso:	CARD32 Retraso entre fotogramas de animación en milisegundos
píxeles:	LISTofCARD32 Píxeles en formato ARGB empaquetado

TEMAS

Xcursor (en su mayor parte) sigue la especificación de freedesktop.org para temas de iconos. La ruta de búsqueda predeterminada que utiliza es

~/.local/share/icons, ~/.icons, /usr/share/icons, /usr/share/pixmaps

Dentro de cada uno de estos directorios, busca un directorio utilizando el nombre del tema:

•
Dentro del directorio del tema, busca archivos de cursores en el subdirectorio “cursors”.
Xcursor busca un archivo específico, que debe ser uno de los nombres de forma del cursor, por ejemplo, como se usa en `XcursorLibraryLoadImage` o `XcursorLibraryShape`.
•
Si no encuentra un archivo de cursor coincidente en el subdirectorio “cursors”, Xcursor busca a continuación un archivo “index.theme” en cada directorio de tema para buscar temas heredados. Esas son líneas con el siguiente formato:
Hereda = nombre-tema

Xcursor utiliza el primer `nombre-tema` heredado, ignorando otros que puedan existir en un archivo “index.theme” dado. Si encuentra un tema heredado, Xcursor busca en la ruta para usarlo también. Xcursor ignora otras `claves` en el archivo “index.theme”, incluyendo “Nombre” (es decir, el nombre que una aplicación gráfica puede usar como `nombre de presentación`).

Se puede listar más de un `nombre-tema` en la línea Hereda=. La especificación de freedesktop.org establece que los elementos de la lista están separados por comas. Xcursor también acepta punto y coma, pero traduce ambos a dos puntos al buscar en la ruta. Xcursor espera solo una línea `Hereda=`; la especificación de freedesktop.org no es clara sobre si se permiten múltiples claves.

Si no se establece ningún tema, o si no se encuentra ningún cursor para el tema especificado en ningún lugar de la ruta, Xcursor comprueba el tema “predeterminado”.

Cuando Xcursor encuentra un archivo de cursor, deja de buscar. Siempre utiliza el primer archivo de cursor encontrado mientras busca en la ruta.

TIPOS DE DATOS

XcursorImage
contiene una sola imagen de cursor en memoria. Cada píxel del cursor es un valor de 32 bits que contiene ARGB con A en el byte superior. 


typedef struct _XcursorImage {
    XcursorDim 	 size; 	/* tamaño nominal para la coincidencia */
    XcursorDim 	 width; 	/* ancho real */
    XcursorDim 	 height; 	/* alto real */
    XcursorDim 	 xhot; 	/* punto caliente x (debe estar dentro de la imagen) */
    XcursorDim 	 yhot; 	/* punto caliente y (debe estar dentro de la imagen) */
    XcursorPixel 	*pixels; 	/* puntero a píxeles */
} XcursorImage;
XcursorImages
contiene múltiples estructuras `XcursorImage`. Todas se liberan cuando se libera `XcursorImages` en `XcursorImagesDestroy`. 


typedef struct _XcursorImages {
    int 	 nimage; 	/* número de imágenes */
    XcursorImage 	**images; 	/* matriz de punteros XcursorImage */
} XcursorImages;
XcursorCursors
Contiene múltiples objetos `Cursor`. Todos se liberan cuando se libera `XcursorCursors`. Estos tienen un contador de referencias para que múltiples estructuras `XcursorAnimate` puedan usar el mismo `XcursorCursors`. 


typedef struct _XcursorCursors {
    Display 	*dpy; 	/* Pantalla que contiene los cursores */
    int 	 ref; 	/* contador de referencias */
    int 	 ncursor; 	/* número de cursores */
    Cursor 	*cursors; 	/* matriz de cursores */
} XcursorCursors;
XcursorAnimate
Hace referencia a un conjunto de cursores y una secuencia dentro de ese conjunto. Múltiples estructuras `XcursorAnimate` pueden hacer referencia al mismo `XcursorCursors`; cada una mantiene una referencia que se elimina cuando se libera `XcursorAnimate`. 


typedef struct _XcursorAnimate {
    XcursorCursors 	*cursors; 	/* lista de cursores a usar */
    int 	 sequence; 	/* cuál es el siguiente cursor */
} XcursorAnimate;
XcursorFile
Xcursor proporciona una API abstracta para acceder a los datos del archivo. Xcursor proporciona una implementación `stdio` de esta API abstracta; las aplicaciones son libres de crear implementaciones adicionales. Estas funciones son paralelas a las de `fstdio`. 


typedef struct _XcursorFile {
    int 	(*read) (XcursorFile *	file, char *	buf, int 	len);
    int 	(*write) (XcursorFile *	file, const char *	buf, int 	len);
    int 	(*seek) (XcursorFile *	file, long 	offset, int 	whence);
    int 	(*close) (XcursorFile *	file);
    void 	*private; 	/* datos privados para la implementación */
} XcursorFile;

ENVIRONMENT Environment variables can be used to override resource settings, which in turn override compiled-in default values. Some of the environment variables recognized by Xcursor are booleans, specified as follows: true for “t”, “1”, “y” or “on” false for “f”, “0”, “n” or “off” Xcursor ignores other values for these booleans. HOME Xcursor interprets “~” in the search list as the home directory, using this variable rather than the password database. XCURSOR_ANIM If the display supports the Render CreateCursor request, and the Render feature is enabled, disable animated cursors if the environment variable is false. If the environment variable is not given, Xcursor uses the resource Xcursor.anim. XCURSOR_CORE If the display supports the Render CreateCursor request disable the Render feature if the environment variable is false. If the environment variable is not given, Xcursor uses the resource Xcursor.core. XCURSOR_DISCOVER If the variable is set, Xcursor turns on a logging feature. It displays the hash value and the image so that users can see which cursor name is associated with each image. There is no corresponding resource setting. XCURSOR_DITHER This variable sets the desired dither. If the environment variable is not given, Xcursor uses the resource Xcursor.dither. If neither environment variable or resource is found, Xcursor uses “threshold” These are the recognized values: diffuse median ordered threshold XCURSOR_PATH This variable sets the list of paths in which to search for cursors, rather than the compiled-in default list. Directories in this path are separated by colons (:). XCURSOR_RESIZED Enables automatic resizing of cursors to improve their displayed size if the environment variable is true. If the environment variable is not given, Xcursor tries the Xcursor.resized resource. XCURSOR_SIZE This variable sets the desired cursor size, in pixels. If the environment variable is not given, Xcursor tries the Xcursor.size resource. If no size is given, whether by environment variable or resource setting, Xcursor next tries the Xft.dpi resource setting to guess the size of a 16-point cursor. Finally, if Xft.dpi is not set, Xcursor uses the display height, dividing by 48 (assuming that the height is 768). XCURSOR_THEME This variable selects the desired theme. If the environment variable is not given, Xcursor tries the Xcursor.theme resource. If neither environment variable or resource is found, Xcursor uses the default theme. XCURSOR_THEME_CORE If the environment variable is set to false, then cursors are always loaded as ARGB cursors. If the environment variable is not given, Xcursor uses the resource Xcursor.theme_core. NAME

XcursorCommentDestroy

destroy a comment structure

SYNOPSIS

#include <Xcursor/Xcursor.h>
void
XcursorCommentDestroy (
    XcursorComment *comment
);

DESCRIPTION

The XcursorCommentDestroy function frees the memory associated with a given XcursorComment structure. This structure is normally allocated by functions like XcursorFileLoad.

FUNCTIONAL OVERVIEW

This function is part of the Xcursor library, which provides functionality for loading and managing cursors in X Window System environments. Specifically, it handles the destruction and deallocation of comment structures used within cursor files.

DATATYPES

XcursorComment
This structure is used to hold comment information associated with a cursor. It typically includes fields for the comment type and the comment data itself.

FUNCTIONS

XcursorCommentDestroy
Frees the memory occupied by an XcursorComment structure.

ENVIRONMENT

Xcursor.theme_core
Enables themes for core cursors if the environment variable is true.
If the environment variable is not given, Xcursor tries the Xcursor.theme_core resource.
An application can enable or disable themes using XcursorSetThemeCore.
