Paquete: libxcursor

Licencias: HPND-sell-variant

XCURSOR(3) X Version 11 XCURSOR(3)

NOMBRE

Xcursor - Biblioteca de gestión de cursores

SINOPSIS

#include <X11/Xcursor/Xcursor.h>

DESCRIPCIÓN

Xcursor es una biblioteca sencilla diseñada para ayudar a localizar y cargar cursores. Los cursores se pueden cargar desde archivos o desde memoria. Existe una biblioteca de cursores comunes que se corresponden con los nombres de cursores estándar de X. Los cursores pueden existir en varios tamaños y la biblioteca selecciona automáticamente el mejor tamaño.

VISIÓN GENERAL FUNCIONAL

Xcursor está construido en un par de capas; en la capa inferior se encuentra el código que puede cargar imágenes de cursores desde archivos. Por encima hay una capa que localiza los archivos de cursores basándose en la ruta de la biblioteca y el tema. En la capa superior hay una capa que crea cursores ya sea a partir de una imagen cargada desde un archivo o de uno de los cursores estándar de X. Al usar imágenes cargadas desde archivos, Xcursor prefiere utilizar la solicitud `CreateCursor` de la extensión Render si es soportada por el servidor X. Donde no es soportada, Xcursor mapea la imagen del cursor a un cursor estándar de X y utiliza la solicitud `CreateCursor` del núcleo.

ARCHIVOS DE CURSORES

Xcursor define un nuevo formato para los cursores en disco. Cada archivo contiene una o más imágenes de cursor. Cada imagen de cursor está etiquetada con un tamaño nominal para que se pueda seleccionar el mejor tamaño automáticamente. Múltiples cursores del mismo tamaño nominal se pueden cargar juntos; se espera que las aplicaciones los utilicen como una secuencia animada.

Los archivos de cursores se almacenan como una cabecera que contiene una tabla de contenido seguida de una secuencia de bloques. La tabla de contenido indica el tipo, subtipo y posición en el archivo de cada bloque. La cabecera del archivo se ve así:


mágica:	CARD32 "Xcur" (0x58, 0x63, 0x75, 0x72)
cabecera:	CARD32 bytes en esta cabecera
versión:	CARD32 número de versión del archivo
ntoc:	CARD32 número de entradas de la tabla de contenido
toc:	LISTadeTOC tabla de contenido

Cada entrada de la tabla de contenido se ve así:


tipo:	CARD32 tipo de entrada
subtipo:	CARD32 etiqueta específica del tipo - tamaño para imágenes
posición:	CARD32 posición absoluta en bytes de la tabla en el archivo

Cada bloque en el archivo tiene un conjunto de campos de cabecera comunes seguidos de campos adicionales específicos del tipo:


cabecera:	CARD32 bytes en la cabecera del bloque (incluyendo campos específicos del tipo)
tipo:	CARD32 debe coincidir con el tipo en la TOC para este bloque
subtipo:	CARD32 debe coincidir con el subtipo en la TOC para este bloque
versión:	CARD32 número de versión para este tipo de bloque

Actualmente hay dos tipos de bloque definidos para archivos de cursores; comentarios e imágenes. Los comentarios se ven así:


cabecera:	20 Las cabeceras de comentario son de 20 bytes
tipo:	0xfffe0001 El tipo de comentario es 0xfffe0001
subtipo:	{ 1 (COPYRIGHT), 2 (LICENSE), 3 (OTHER) }
versión:	1
longitud:	CARD32 longitud en bytes de la cadena UTF-8
cadena:	LISTaCARD8 cadena UTF-8

Las imágenes se ven así:


cabecera:	36 Las cabeceras de imagen son de 36 bytes
tipo:	0xfffd0002 El tipo de imagen es 0xfffd0002
subtipo:	CARD32 El subtipo de imagen es el tamaño nominal
versión:	1
ancho:	CARD32 Debe ser menor o igual a 0x7fff
alto:	CARD32 Debe ser menor o igual a 0x7fff
xhot:	CARD32 Debe ser menor o igual al ancho
yhot:	CARD32 Debe ser menor o igual al alto
retraso:	CARD32 Retraso entre fotogramas de animación en milisegundos
píxeles:	LISTaCARD32 Píxeles empaquetados en formato ARGB

TEMAS

Xcursor (principalmente) sigue la especificación de freedesktop.org para los iconos de temas. La ruta de búsqueda predeterminada que utiliza es

~/.local/share/icons, ~/.icons, /usr/share/icons, /usr/share/pixmaps

Dentro de cada uno de estos directorios, busca un directorio usando el nombre del tema:

•
Dentro del directorio del tema, busca archivos de cursores en el subdirectorio “cursors”.
Xcursor busca un archivo específico, que debe ser uno de los nombres de forma del cursor, por ejemplo, como se usa en XcursorLibraryLoadImage o XcursorLibraryShape.
•
Si no encuentra un archivo de cursor coincidente en el subdirectorio “cursors”, Xcursor busca a continuación un archivo “index.theme” en cada directorio de tema para buscar temas heredados. Esas son líneas en este formato:
Hereda = nombre-tema

Xcursor utiliza el primer nombre-tema heredado, ignorando otros que puedan existir en un archivo “index.theme” dado. Si encuentra un tema heredado, Xcursor busca a lo largo de la ruta para utilizarlo también. Xcursor ignora otras claves en el archivo “index.theme”, incluido “Name” (es decir, el nombre que una aplicación gráfica puede usar como nombre de presentación).

Puede haber más de un nombre-tema en la línea Hereda=. La especificación de freedesktop.org indica que los elementos de la lista están separados por comas. Xcursor también acepta punto y coma, pero traduce ambos a dos puntos al buscar en la ruta. Xcursor espera solo una línea Hereda=; la especificación de freedesktop.org no es clara sobre si se permiten claves múltiples.

Si no se establece ningún tema, o si no se encuentra ningún cursor para el tema especificado en ningún lugar de la ruta, Xcursor comprueba el tema “predeterminado”.

Cuando Xcursor encuentra un archivo de cursor, deja de buscar. Siempre utiliza el primer archivo de cursor encontrado mientras busca a lo largo de la ruta.

TIPOS DE DATOS

XcursorImage
contiene una única imagen de cursor en memoria. Cada píxel del cursor es un valor de 32 bits que contiene ARGB con A en el byte alto. 


typedef struct _XcursorImage {
    XcursorDim 	 size; 	/* tamaño nominal para coincidencia */
    XcursorDim 	 width; 	/* ancho real */
    XcursorDim 	 height; 	/* alto real */
    XcursorDim 	 xhot; 	/* punto caliente x (debe estar dentro de la imagen) */
    XcursorDim 	 yhot; 	/* punto caliente y (debe estar dentro de la imagen) */
    XcursorPixel 	*pixels; 	/* puntero a los píxeles */
} XcursorImage;
XcursorImages
contiene múltiples estructuras `XcursorImage`. Todas se liberan cuando se libera `XcursorImages` en `XcursorImagesDestroy`. 


typedef struct _XcursorImages {
    int 	 nimage; 	/* número de imágenes */
    XcursorImage 	**images; 	/* matriz de punteros a XcursorImage */
} XcursorImages;
XcursorCursors
Contiene múltiples objetos Cursor. Todos se liberan cuando se libera `XcursorCursors`. Estos tienen un contador de referencias para que múltiples estructuras `XcursorAnimate` puedan usar los mismos `XcursorCursors`. 


typedef struct _XcursorCursors {
    Display 	*dpy; 	/* Pantalla que contiene los cursores */
    int 	 ref; 	/* contador de referencias */
    int 	 ncursor; 	/* número de cursores */
    Cursor 	*cursors; 	/* matriz de cursores */
} XcursorCursors;
XcursorAnimate
Hace referencia a un conjunto de cursores y una secuencia dentro de ese conjunto. Múltiples estructuras `XcursorAnimate` pueden hacer referencia al mismo `XcursorCursors`; cada una mantiene una referencia que se elimina cuando se libera `XcursorAnimate`. 


typedef struct _XcursorAnimate {
    XcursorCursors 	*cursors; 	/* lista de cursores a usar */
    int 	 sequence; 	/* qué cursor es el siguiente */
} XcursorAnimate;
XcursorFile
Xcursor proporciona una API abstracta para acceder a los datos de los archivos. Xcursor proporciona una implementación stdio de esta API abstracta; las aplicaciones son libres de crear implementaciones adicionales. Estas funciones son paralelas a las de stdi

    XcursorComment 	**comments;

typedef struct _XcursorFile {
    void *closure;
    int (*read)  (XcursorFile *file, unsigned char *buf, int len);
    int (*write) (XcursorFile *file, unsigned char *buf, int len);
    int (*seek)  (XcursorFile *file, long offset, int whence);
};

The XcursorFile structure is used internally to abstract the different file I/O methods. The read and write function arguments are swapped compared to standard C library functions, to match the POSIX interface, and to allow for a closure argument.

The read and write functions should return the number of bytes read or written, respectively. If an error occurs, they should return -1. The seek function should behave like fseek.

The closure pointer can be used to pass arbitrary data to the callback functions, e.g. a FILE pointer.

Note: The read and write functions expect the buffer argument first, followed by the file argument, and then the length. This differs from the normal argument order for functions like read and write, but matches the interface used by XcursorFileLoadImage and friends.

The read and write functions flip the arguments around to match the POSIX versions.


typedef struct _XcursorFile {
    void *closure;
    int (*read)  (XcursorFile *file, unsigned char *buf, int len);
    int (*write) (XcursorFile *file, unsigned char *buf, int len);
    int (*seek)  (XcursorFile *file, long offset, int whence);
};

Reading library images

XcursorImage *XcursorLibraryLoadImage (
const char 	*name,
const char 	*theme,
int 	 size)

	const char 	*name,
	const char 	*theme,
	int 	 size)

These search the library path, loading the first file found of the desired size, using a private function (XcursorScanTheme) to find the appropriate theme:

  • If theme is not NULL, use that.
  • If theme is NULL, or if there was no match for the desired theme, use “default” for the theme name.
  • If neither search succeeds, these functions return NULL.
The two functions differ by more than the number of images loaded:
  • XcursorLibraryLoadImage calls XcursorFileLoadImage but
  • XcursorLibraryLoadImages calls XcursorFileLoadImages, and (on success) it calls XcursorImagesSetName to associate name with the result.

      XCURSOR_RESIZED
      Enables automatic resizing of cursors to improve their displayed size if
      the environment variable is true.
      If the environment variable is not given, Xcursor tries the
      Xcursor.resized resource.
      XCURSOR_SIZE
      This variable sets the desired cursor size, in pixels.
      If the environment variable is not given, Xcursor tries the
      Xcursor.size resource.
      If no size is given, whether by environment variable or resource setting,
      Xcursor next tries the Xft.dpi resource setting to guess the size
      of a 16-point cursor.
      Finally, if Xft.dpi is not set, Xcursor uses the display height,
      dividing by 48 (assuming that the height is 768).
      XCURSOR_THEME
      This variable selects the desired theme.
      If the environment variable is not given, Xcursor tries the
      Xcursor.theme resource.
      If neither environment variable or resource is found, Xcursor uses the
      default theme.
      XCURSOR_THEME_CORE



ENVIRONMENT



  
R_THEME_CORE

  
Habilita temas para cursores principales si la variable de entorno es
      true.





  

  
Si no se proporciona la variable de entorno, Xcursor prueba el recurso
      Xcursor.theme_core.

  

  
Una aplicación puede habilitar o deshabilitar temas usando
    XcursorSetThemeCore.
