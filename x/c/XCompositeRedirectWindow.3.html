DESCRIPCIÓN

La extensión composite proporciona varios mecanismos relacionados:

Almacenamiento por jerarquía

La representación de una jerarquía completa de ventanas se redirige a un almacenamiento fuera de pantalla. Los píxeles de esa jerarquía están disponibles siempre que sea visible. El almacenamiento se reasigna automáticamente cuando la ventana de nivel superior cambia de tamaño. El contenido más allá de la geometría de la ventana superior no se conserva.

Actualización automática de sombras

Cuando una jerarquía se representa fuera de pantalla, el servidor X proporciona un mecanismo automático para presentar ese contenido dentro de la ventana padre. La implementación es libre de hacer que esta actualización se retrase respecto a las operaciones de renderizado reales en una cantidad de tiempo no especificada. Este mecanismo de actualización automática puede desactivarse para que el contenido de la ventana padre pueda ser determinado completamente por una aplicación externa.

Ventana de Superposición Composite

La versión 0.3 del protocolo añade la Ventana de Superposición Composite, que proporciona a los gestores de composición una superficie sobre la cual dibujar sin interferencias. Esta ventana siempre está por encima de las ventanas normales y siempre está por debajo de la ventana del salvapantallas. Es una ventana InputOutput cuyas dimensiones de ancho y alto son las dimensiones de la pantalla. Su visual es el visual raíz y su borde es cero. Los intentos de redirigirla usando la extensión composite son ignorados. Esta ventana no aparece en la respuesta de la solicitud QueryTree. También es una ventana de redirección de anulación (override redirect). Estas dos últimas características la hacen invisible para los gestores de ventanas y otros clientes de X11. La única forma de acceder al XID de esta ventana es a través de la solicitud CompositeGetOverlayWindow. Inicialmente, la Ventana de Superposición Composite está desmapeada.

Recorte de la ventana padre

La versión 0.4 del protocolo modifica la semántica del recorte de la ventana padre en presencia de hijos redirigidos manualmente. Con esta versión, el área en el padre cubierta por hijos redirigidos manualmente se deja en la lista de recortes del padre en lugar de eliminarse como en versiones anteriores.

El almacenamiento fuera de pantalla puede crearse para ventanas individuales o para todos los hijos de una ventana. La actualización manual de sombras puede ser seleccionada por una sola aplicación para cada ventana; la actualización manual también puede seleccionarse por ventana o para cada hijo de una ventana. La detección de cuándo actualizar puede hacerse con la extensión Damage.

El almacenamiento fuera de pantalla incluye el contenido de la ventana, sus bordes y el contenido de todos los descendientes.

ARGUMENTOS

display

Puntero a la estructura Display devuelta por XOpenDisplay para la conexión al servidor X.

event_base_return

Puntero a un entero donde se almacenará el valor base para los eventos de la Extensión Composite.

error_base_return

Puntero a un entero donde se almacenará el valor base para los errores de la Extensión Composite.

major_version_return

Puntero a un entero donde se almacenará la versión mayor de la Extensión Composite soportada por el servidor X.

minor_version_return

Puntero a un entero donde se almacenará la versión menor de la Extensión Composite soportada por el servidor X.

window

Especifica el ID de la ventana sobre la que operar.

update

Especifica el modo de actualización del contenido de la ventana. Debe ser CompositeRedirectAutomatic o CompositeRedirectManual.

FUNCIONES

XCompositeQueryExtension

XCompositeQueryExtension determina si la Extensión Composite está disponible en la pantalla dada. Devuelve True si la extensión es soportada, de lo contrario False. Si la extensión está presente, se devuelven los valores base para eventos y errores, y pueden usarse para decodificar valores de eventos y errores entrantes.

XCompositeQueryVersion

XCompositeQueryVersion determina si el Servidor X soporta una versión de la Extensión X Composite que sea compatible con la biblioteca cliente. Se devuelve un Status distinto de cero si se soporta una versión compatible de la extensión, de lo contrario se devuelve un Status cero. Si la extensión es soportada, se devuelven los números de versión mayor y menor para indicar el nivel de soporte de la Extensión Composite. Ninguna otra función XComposite (excepto XCompositeQueryExtension) puede ser llamada antes de esta función. Si un cliente viola esta regla, los efectos de todas las llamadas subsiguientes de XComposite que haga no están definidos.

XCompositeVersion

XCompositeVersion devuelve la versión de la biblioteca X Composite. El número de versión está codificado como: (mayor * 10000) + (menor * 100) + revisión

Por ejemplo, la versión 1.4.6 estaría codificada como el entero 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow solicita al servidor X que redirija la jerarquía que comienza en window a un almacenamiento fuera de pantalla. El argumento update especifica si el contenido se refleja automáticamente en la ventana padre o no. Solo un cliente a la vez puede especificar un tipo de actualización de CompositeRedirectManual; otro intento resultará en un error BadAccess. Cuando todos los clientes que habilitan la redirección terminan, la redirección se deshabilitará automáticamente.

La ventana raíz no puede ser redirigida. Hacerlo resulta en un error BadMatch. Especificar un ID de ventana inválido resultará en un error BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows solicita al servidor X que redirija las jerarquías que comienzan en todos los hijos actuales y futuros de window como en XCompositeRedirectWindow. Si update es CompositeRedirectManual, entonces la pintura del fondo de la ventana durante la manipulación de ventanas y las solicitudes ClearArea se inhiben.

XCompositeUnredirectWindow

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de window. Si la ventana especificada no fue seleccionada para redirección por el cliente actual, resulta un error BadValue.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de todos los hijos de window. Si la ventana especificada no fue seleccionada para sub-redirección por el cliente actual, resulta un error BadValue.

DESCRIPTION

The Composite extension allows clients to redirect the contents of windows to an off-screen pixmap. This allows for effects like transparency, animated windows, and arbitrary transformations. The extension also provides an overlay window facility for applications that need to draw directly onto the screen without being obscured by other windows.

XCompositeQueryExtension determines if the Composite extension is available on the specified display. If it is available, it returns the base event and error numbers for the extension. Otherwise, it returns a non-zero status and sets the event and error base numbers to -1.

XCompositeQueryVersion queries the version of the Composite extension supported by the server. It returns the highest supported version that is less than or equal to the version requested by the client. The client can request any version starting from 0.2.

XCompositeRedirectWindow redirects the contents of the specified window. The redirect_mode argument can be CompositeRedirectManual or CompositeRedirectAutomatic. If CompositeRedirectAutomatic is used, the server automatically redirects all subwindows of the specified window. If CompositeRedirectManual is used, the client is responsible for redirecting subwindows. This function generates a BadMatch error if the window is already redirected or is not redirectable.

XCompositeRedirectSubwindow redirects the contents of the specified subwindow. The redirect_mode argument can be CompositeRedirectManual or CompositeRedirectAutomatic. This function generates a BadMatch error if the window is not a subwindow of a redirected window or is already redirected.

XCompositeUnredirectWindow stops redirecting the contents of the specified window. If CompositeRedirectAutomatic was used to redirect the window, this call also unredirects all of its subwindows. If the window was not redirected, this call has no effect. This function generates a BadMatch error if the window is not redirected.

XCompositeUnredirectSubwindow stops redirecting the contents of the specified subwindow. If the subwindow was not redirected, this call has no effect. This function generates a BadMatch error if the window is not a subwindow of a redirected window.

XCompositeGetWindowAttributes retrieves the Composite extension attributes for the specified window. These attributes include whether the window is redirected, and if so, the redirect mode and the pixmap associated with the window.

The XCompositeWindowAttributes structure is defined as:

        typedef struct {
            Bool        redirect_state;
            Pixmap      pixmap;
            int         width;
            int         height;
            int         depth;
            int         damage_report_level;
        } XCompositeWindowAttributes;

XCompositeGetWindowAttributes generates a BadMatch error if the window is not redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeRedirectWindow, XCompositeRedirectSubwindow, XCompositeUnredirectWindow, XCompositeUnredirectSubwindow, and XCompositeGetWindowAttributes.

FUNCTIONS

XCompositeRedirectWindow, XCompositeRedirectSubwindow, XCompositeUnredirectWindow, XCompositeUnredirectSubwindow, XCompositeGetWindowAttributes

These functions are used to manage the redirection of window contents. When a window is redirected, its contents are drawn to an off-screen pixmap instead of directly to the screen. This allows for effects such as transparency and compositing. The `redirect_mode` argument determines whether the redirection is manual (client must manage subwindows) or automatic (server manages subwindows). The `XCompositeGetWindowAttributes` function retrieves the current redirection state and associated pixmap information for a given window.

A key aspect of redirection is the clipping of the window's content. The server ensures that only the portions of the window that are visible are actually rendered. This is particularly important when a window is partially obscured by other windows or when it is being moved or resized. The clipping region, often referred to as the "clip value," is the area of the window that is clipped against its siblings and parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
