Xcomposite - biblioteca de la extensión X Composite

DESCRIPCIÓN

La extensión composite proporciona varios mecanismos relacionados:

Almacenamiento por jerarquía

El renderizado de una jerarquía completa de ventanas se redirige a almacenamiento fuera de pantalla. Los píxeles de esa jerarquía están disponibles siempre que sea visible. El almacenamiento se reasigna automáticamente cuando la ventana de nivel superior cambia de tamaño. Los contenidos más allá de la geometría de la ventana superior no se conservan.

Actualización automática de sombras

Cuando una jerarquía se renderiza fuera de pantalla, el servidor X proporciona un mecanismo automático para presentar esos contenidos dentro de la ventana padre. La implementación es libre de hacer que esta actualización se retrase una cantidad de tiempo no especificada con respecto a las operaciones de renderizado reales. Este mecanismo de actualización automática puede ser deshabilitado para que los contenidos de la ventana padre puedan ser determinados completamente por una aplicación externa.

Ventana de Superposición Compuesta (Composite Overlay Window)

La versión 0.3 del protocolo agrega la Ventana de Superposición Compuesta, que proporciona a los gestores de composición una superficie sobre la cual dibujar sin interferencias. Esta ventana está siempre por encima de las ventanas normales y siempre por debajo de la ventana del protector de pantalla. Es una ventana de EntradaSalida (InputOutput) cuyas dimensiones son las de la pantalla. Su visual es el visual raíz y su borde es cero. Los intentos de redirigirla usando la extensión composite son ignorados. Esta ventana no aparece en la respuesta de la solicitud QueryTree. También es una ventana de redirección anulada (override redirect). Estas dos últimas características la hacen invisible para los gestores de ventanas y otros clientes X11. La única forma de acceder al XID de esta ventana es a través de la solicitud CompositeGetOverlayWindow. Inicialmente, la Ventana de Superposición Compuesta no está mapeada.

Recorte de ventana padre

La versión 0.4 del protocolo modifica la semántica del recorte de ventana padre en presencia de hijos redirigidos manualmente. Con esta versión, el área en el padre cubierta por hijos redirigidos manualmente se deja en la lista de recorte del padre en lugar de eliminarse como en versiones anteriores.

El almacenamiento por jerarquía puede crearse para ventanas individuales o para todos los hijos de una ventana. La actualización manual de sombras puede ser seleccionada por una sola aplicación para cada ventana; la actualización manual también puede seleccionarse por ventana o para cada hijo de una ventana. La detección de cuándo actualizar puede hacerse con la extensión Damage.

El almacenamiento fuera de pantalla incluye los contenidos de la ventana, sus bordes y los contenidos de todos los descendientes.

ARGUMENTOS

display

Puntero a la estructura Display devuelta por XOpenDisplay para la conexión con el servidor X.

event_base_return

Puntero a un entero donde se almacenará el valor base para los eventos de la Extensión Composite.

error_base_return

Puntero a un entero donde se almacenará el valor base para los errores de la Extensión Composite.

major_version_return

Puntero a un entero donde se almacenará la versión principal de la Extensión Composite soportada por el servidor X.

minor_version_return

Puntero a un entero donde se almacenará la versión secundaria de la Extensión Composite soportada por el servidor X.

window

Especifica el ID de la ventana sobre la que operar.

update

Especifica el modo para actualizar los contenidos de la ventana. Debe ser CompositeRedirectAutomatic o CompositeRedirectManual.

FUNCIONES

XCompositeQueryExtension

XCompositeQueryExtension determina si la Extensión Composite está disponible en la pantalla dada. Devuelve True si la extensión es soportada, de lo contrario False. Si la extensión está presente, se devuelven los valores base para eventos y errores, que pueden usarse para decodificar los valores de eventos y errores entrantes.

XCompositeQueryVersion

XCompositeQueryVersion determina si el Servidor X soporta una versión de la Extensión X Composite que sea compatible con la biblioteca cliente. Se devuelve un Status distinto de cero si se soporta una versión compatible de la extensión, de lo contrario se devuelve un Status cero. Si la extensión es soportada, se devuelven los números de versión principal y secundaria para indicar el nivel de soporte de la Extensión Composite. No se pueden llamar otras funciones XComposite (excepto XCompositeQueryExtension) antes de esta función. Si un cliente viola esta regla, los efectos de todas las llamadas XComposite subsiguientes que realice no están definidos.

XCompositeVersion

XCompositeVersion devuelve la versión de la biblioteca X Composite. El número de versión se codifica como: (principal * 10000) + (secundaria * 100) + revisión

Por ejemplo, la versión 1.4.6 se codificaría como el entero 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow solicita al servidor X que redirija la jerarquía que comienza en window a almacenamiento fuera de pantalla. El argumento update especifica si los contenidos se reflejan automáticamente en la ventana padre o no. Solo un cliente a la vez puede especificar un tipo de actualización de CompositeRedirectManual; otro intento resultará en un error BadAccess. Cuando todos los clientes que habilitan la redirección terminan, la redirección se deshabilitará automáticamente.

La ventana raíz no puede ser redirigida. Hacerlo resulta en un error BadMatch. Especificar un ID de ventana inválido resultará en un error BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows solicita al servidor X que redirija las jerarquías que comienzan en todos los hijos actuales y futuros de window como en XCompositeRedirectWindow. Si update es CompositeRedirectManual, entonces la pintura del fondo de la ventana durante la manipulación de ventanas y las solicitudes ClearArea se inhiben.

XCompositeUnredirectWindow

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de window. Si la ventana especificada no fue seleccionada para redirección por el cliente actual, se produce un error BadValue.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de todos los hijos de window. Si la ventana especificada no fue seleccionada para sub-redirección por el cliente actual, se produce un error BadValue.

NAME

XCompositeNameWindowPixmap, XCompositeGetOverlayWindow, XCompositeReleaseOverlayWindow — create pixmaps and manage overlay windows for the Composite extension

SYNOPSIS

Pixmap XCompositeNameWindowPixmap(Display *display, Window window);

Window XCompositeGetOverlayWindow(Display *display, Window window);

void XCompositeReleaseOverlayWindow(Display *display, Window window);

DESCRIPTION

The Composite extension provides a mechanism for managing the on-screen contents of windows. It allows clients to redirect the contents of a window to an off-screen pixmap, allowing for compositing window managers to apply effects to individual windows, or to combine the contents of multiple windows.

This man page describes the client-side functions for interacting with the Composite extension.

Before using any of the functions described here, a client must first query whether the Composite extension is available and supported by the server using XCompositeQueryExtension(3).

If the Composite extension is available, the client must then request that the window it wishes to manipulate be redirected. This is done using XCompositeRedirectWindow(3) or XCompositeRedirectSubwindow(3).

ARGUMENTS

display
Specifies the connection to the X server.
window
Specifies the window of interest.

FUNCTIONS

XCompositeRedirectWindow

XCompositeRedirectWindow requests that the X server redirect all future contents of window to the off-screen pixmap created using XCompositeNameWindowPixmap(3). The contents of the window will not be changed by this operation; rather, the server will direct drawing operations to the pixmap instead of the window's on-screen contents. If the window is already redirected, this function will generate a BadMatch error.

The update_kind argument specifies how the client wishes to be notified of updates to the window's contents. The following values are valid:

CompositeRedirectManual
The client is responsible for updating the window's contents. The server will not automatically update the contents of the redirected window.
CompositeRedirectAutomatic
The server will automatically update the contents of the redirected window. The client may still draw to the window, but it is not necessary to copy the contents of the window to the pixmap.

The XCompositeRedirectWindow function generates a BadMatch error if the window is not redirectable (e.g., it is a root window or an override-redirect window).

The X server must support at least version 0.2 of the Composite Extension for XCompositeRedirectWindow.

XCompositeRedirectSubwindow

XCompositeRedirectSubwindow is similar to XCompositeRedirectWindow(3), but it redirects only the contents of the subwindow specified by subwindow. The parent window remains unaffected.

The update_kind argument is the same as for XCompositeRedirectWindow(3).

The XCompositeRedirectSubwindow function generates a BadMatch error if the subwindow is not redirectable.

The X server must support at least version 0.3 of the Composite Extension for XCompositeRedirectSubwindow.

XCompositeUnredirectWindow

XCompositeUnredirectWindow tells the X server that the client is no longer interested in redirecting the contents of window. This function should be called when the client is finished manipulating the window's contents.

The update_kind argument must match the value specified in the corresponding XCompositeRedirectWindow(3) or XCompositeRedirectSubwindow(3) call. If the arguments do not match, a BadMatch error is generated.

The X server must support at least version 0.2 of the Composite Extension for XCompositeUnredirectWindow.

XCompositeUnredirectSubwindow

XCompositeUnredirectSubwindow is similar to XCompositeUnredirectWindow(3), but it affects only the subwindow specified by subwindow.

The X server must support at least version 0.3 of the Composite Extension for XCompositeUnredirectSubwindow.

XCompositeQueryExtension

XCompositeQueryExtension queries the X server to determine if the Composite extension is available and supported. It returns the major opcode for the extension if it is available, and -1 otherwise. The major_opcode_ret and event_ret arguments are filled with the major opcode and the first event code for the extension, respectively.

The error_ret argument is filled with the first error code for the extension.

The version_ret argument is filled with the version number of the extension supported by the server. This is a bitmask where the major version is in the upper 16 bits and the minor version is in the lower 16 bits.

XCompositeQueryVersion

XCompositeQueryVersion queries the X server for the maximum version of the Composite extension that it supports. The arguments client_major_version and client_minor_version specify the version of the extension supported by the client. The server will reply with the highest version it supports that is less than or equal to the version specified by the client.

The server_major_version_ret and server_minor_version_ret arguments are filled with the major and minor version numbers of the Composite extension supported by the server.

XCompositeGetClientWindownames

XCompositeGetClientWindownames returns a list of all windows that are currently being redirected by the Composite extension. The count_ret argument is filled with the number of windows in the list. The list of windows should be freed by the client using XFree.

Generates a BadMatch error if the Composite extension is not available.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetClientWindownames.

XCompositeGetWindowPixmap

XCompositeGetWindowPixmap returns the pixmap id that is currently being used as the off-screen storage for window. This function is useful for clients that need to access the contents of a redirected window directly. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeGetWindowPixmap.

XCompositeGetclippedWindow

XCompositeGetclippedWindow returns the region of the specified window that is visible and not obscured by siblings or the parent window. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
