NOMBRE

Xcursor - Librería de gestión de cursores

SINOPSIS

#include <X11/Xcursor/Xcursor.h>

DESCRIPCIÓN

Xcursor es una librería simple diseñada para ayudar a localizar y cargar cursores. Los cursores se pueden cargar desde archivos o memoria. Existe una librería de cursores comunes que se mapean a los nombres de cursor estándar de X. Los cursores pueden existir en varios tamaños y la librería elige automáticamente el mejor tamaño.

VISIÓN GENERAL FUNCIONAL

Xcursor está construido en un par de capas; en la capa inferior se encuentra el código que puede cargar imágenes de cursor desde archivos. Por encima de eso hay una capa que localiza archivos de cursor basándose en la ruta de la librería y el tema. En la parte superior hay una capa que construye cursores a partir de una imagen cargada desde un archivo o de uno de los cursores estándar de X. Al usar imágenes cargadas desde archivos, Xcursor prefiere usar la solicitud CreateCursor de la extensión Render si el servidor X lo soporta. Donde no se soporta, Xcursor mapea la imagen del cursor a un cursor estándar de X y usa la solicitud CreateCursor principal.

ARCHIVOS DE CURSOR

Xcursor define un nuevo formato para cursores en disco. Cada archivo contiene una o más imágenes de cursor. Cada imagen de cursor está etiquetada con un tamaño nominal para que se pueda seleccionar automáticamente el mejor tamaño. Múltiples cursores del mismo tamaño nominal se pueden cargar juntos; se espera que las aplicaciones los utilicen como una secuencia animada.

Los archivos de cursor se almacenan como una cabecera que contiene una tabla de contenidos seguida de una secuencia de bloques. La tabla de contenidos indica el tipo, subtipo y posición en el archivo de cada bloque. La cabecera del archivo se ve así:


mágica:	CARD32 "Xcur" (0x58, 0x63, 0x75, 0x72)
cabecera:	CARD32 bytes en esta cabecera
versión:	CARD32 número de versión del archivo
ntoc:	CARD32 número de entradas en la tabla de contenidos
toc:	LISTofTOC tabla de contenidos

Cada entrada de la tabla de contenidos se ve así:


tipo:	CARD32 tipo de entrada
subtipo:	CARD32 etiqueta específica del tipo - tamaño para imágenes
posición:	CARD32 posición absoluta en bytes de la tabla en el archivo

Cada bloque en el archivo tiene un conjunto de campos de cabecera comunes seguidos de campos adicionales específicos del tipo:


cabecera:	CARD32 bytes en la cabecera del bloque (incluyendo campos específicos del tipo)
tipo:	CARD32 debe coincidir con el tipo en la tabla de contenidos para este bloque
subtipo:	CARD32 debe coincidir con el subtipo en la tabla de contenidos para este bloque
versión:	CARD32 número de versión para este tipo de bloque

Actualmente hay dos tipos de bloques definidos para los archivos de cursor; comentarios e imágenes. Los comentarios se ven así:


cabecera:	Las cabeceras de comentario son de 20 bytes
tipo:	0xfffe0001 el tipo de comentario es 0xfffe0001
subtipo:	{ 1 (COPYRIGHT), 2 (LICENSE), 3 (OTHER) }
versión:	1
longitud:	CARD32 longitud en bytes de la cadena UTF-8
cadena:	LISTofCARD8 cadena UTF-8

Las imágenes se ven así:


cabecera:	Las cabeceras de imagen son de 36 bytes
tipo:	0xfffd0002 el tipo de imagen es 0xfffd0002
subtipo:	CARD32 el subtipo de imagen es el tamaño nominal
versión:	1
ancho:	CARD32 Debe ser menor o igual a 0x7fff
alto:	CARD32 Debe ser menor o igual a 0x7fff
xhot:	CARD32 Debe ser menor o igual al ancho
yhot:	CARD32 Debe ser menor o igual al alto
retraso:	CARD32 Retraso entre fotogramas de animación en milisegundos
píxeles:	LISTofCARD32 Píxeles en formato ARGB empaquetado

TEMAS

Xcursor sigue (en su mayor parte) la especificación de freedesktop.org para tematizar iconos. La ruta de búsqueda predeterminada que utiliza es

~/.local/share/icons, ~/.icons, /usr/share/icons, /usr/share/pixmaps

Dentro de cada uno de estos directorios, busca un directorio usando el nombre del tema:

•
Dentro del directorio del tema, busca archivos de cursor en el subdirectorio “cursors”.
Xcursor busca un archivo específico, que debe ser uno de los nombres de forma de cursor, por ejemplo, como se usa en XcursorLibraryLoadImage o XcursorLibraryShape.
•
Si no encuentra un archivo de cursor coincidente en el subdirectorio “cursors”, Xcursor busca a continuación un archivo “index.theme” en cada directorio de tema para buscar temas heredados. Esas son líneas con este formato:
Hereda = nombre-tema

Xcursor utiliza el primer nombre-tema heredado, ignorando otros que puedan existir en un archivo “index.theme” dado. Si encuentra un tema heredado, Xcursor busca a lo largo de la ruta para usarlo también. Xcursor ignora otras claves en el archivo “index.theme”, incluido “Name” (es decir, el nombre que una aplicación gráfica puede usar como nombre de presentación).

Se puede listar más de un nombre-tema en la línea Hereda=. La especificación de freedesktop.org indica que los elementos de la lista están separados por comas. Xcursor también acepta punto y coma, pero traduce ambos a dos puntos al buscar en la ruta. Xcursor espera solo una línea Hereda=; la especificación de freedesktop.org no aclara si se permiten claves múltiples.

Si no se establece ningún tema, o si no se encuentra ningún cursor para el tema especificado en ninguna parte de la ruta, Xcursor verifica el tema “predeterminado”.

Cuando Xcursor encuentra un archivo de cursor, deja de buscar. Siempre utiliza el primer archivo de cursor encontrado mientras busca a lo largo de la ruta.

TIPOS DE DATOS

XcursorImage
contiene una sola imagen de cursor en memoria. Cada píxel del cursor es un valor de 32 bits que contiene ARGB con A en el byte alto. 


typedef struct _XcursorImage {
    XcursorDim 	 size; 	/* tamaño nominal para la coincidencia */
    XcursorDim 	 width; 	/* ancho real */
    XcursorDim 	 height; 	/* alto real */
    XcursorDim 	 xhot; 	/* punto caliente x (debe estar dentro de la imagen) */
    XcursorDim 	 yhot; 	/* punto caliente y (debe estar dentro de la imagen) */
    XcursorPixel 	*pixels; 	/* puntero a los píxeles */
} XcursorImage;
XcursorImages
contiene múltiples estructuras XcursorImage. Todas se liberan cuando se libera XcursorImages en XcursorImagesDestroy. 


typedef struct _XcursorImages {
    int 	 nimage; 	/* número de imágenes */
    XcursorImage 	**images; 	/* array de punteros XcursorImage */
} XcursorImages;
XcursorCursors
Contiene múltiples objetos Cursor. Todos se liberan cuando se libera XcursorCursors. Estos tienen un recuento de referencias para que múltiples estructuras XcursorAnimate puedan usar el mismo XcursorCursors. 


typedef struct _XcursorCursors {
    Display 	*dpy; 	/* Pantalla que contiene los cursores */
    int 	 ref; 	/* recuento de referencias */
    int 	 ncursor; 	/* número de cursores */
    Cursor 	*cursors; 	/* array de cursores */
} XcursorCursors;
XcursorAnimate
Referencia un conjunto de cursores y una secuencia dentro de ese conjunto. Múltiples estructuras XcursorAnimate pueden referenciar el mismo XcursorCursors; cada una mantiene una referencia que se elimina cuando se libera XcursorAnimate. 


typedef struct _XcursorAnimate {
    XcursorCursors 	*cursors; 	/* lista de cursores a usar */
    int 	 sequence; 	/* cuál es el siguiente cursor */
} XcursorAnimate;
XcursorFile
Xcursor proporciona una API abstracta para acceder a los datos del archivo. Xcursor proporciona una implementación stdio de esta API abstracta; las aplicaciones son libres de crear implementaciones adicionales. Estas funciones son paralelas a las f de stdio

Lectura de imágenes de la biblioteca

XcursorImage *XcursorLibraryLoadImage (
const char 	*name,
const char 	*theme,
int 	 size)
XcursorImages *XcursorLibraryLoadImages (
	const char 	*name,
	const char 	*theme,
	int 	 size)

Estas funciones buscan en la ruta de la biblioteca, cargando el primer archivo encontrado del size deseado, utilizando una función privada (XcursorScanTheme) para encontrar el tema apropiado:

  • Si theme no es NULL, se utiliza ese.
  • Si theme es NULL, o si no hubo coincidencia para el tema deseado, se utiliza "default" como nombre del tema.
  • Si ninguna de las búsquedas tiene éxito, estas funciones devuelven NULL.
Las dos funciones difieren en algo más que el número de imágenes cargadas:
  • XcursorLibraryLoadImage llama a XcursorFileLoadImage pero
  • XcursorLibraryLoadImages llama a XcursorFileLoadImages y (en caso de éxito) llama a XcursorImagesSetName para asociar name con el resultado.

NAME


XcursorCommentsCreate, XcursorCommentsDestroy, XcursorCommentsGet, XcursorCommentsSet, XcursorCommentsSetName, XcursorCommentsSetNameHandle, XcursorCommentsSetParent, XcursorCommentsSetParentHandle — cursor comment handling






SYNOPSIS


#include <Xcursor/Xcursor.h>
XcursorComments *
XcursorCommentsCreate(void);
void
XcursorCommentsDestroy(XcursorComments *comments);
const char *
XcursorCommentsGet(XcursorComments *comments);
void
XcursorCommentsSet(XcursorComments *comments, const char *comment);
void
XcursorCommentsSetName(XcursorComments *comments, const char *name);
void
XcursorCommentsSetNameHandle(XcursorComments *comments, XcursorFile *file, const char *name);
void
XcursorCommentsSetParent(XcursorComments *comments, const char *parent);
void
XcursorCommentsSetParentHandle(XcursorComments *comments, XcursorFile *file, const char *parent);







DESCRIPTION


The Xcursor library provides routines for loading and saving cursors
    in Xcursor file format. This file format is a simple archive format
    containing cursor images and associated metadata. It is used by
    libXcursor to load cursors and is the format
    used by the Xcursor specification.


These functions provide access to the metadata associated with
    cursors, which can include comments and names.






FUNCTIONAL OVERVIEW


When loading a cursor, you can provide a handle to a structure
    to receive comments and names associated with the cursor. These are stored
    in the XcursorComments structure.


XcursorCommentsCreate allocates and
    initializes a new XcursorComments structure.


XcursorCommentsDestroy frees the memory
    associated with a XcursorComments structure.


XcursorCommentsGet returns the comment
    string associated with the cursor.


XcursorCommentsSet sets the comment
    string for the cursor.


XcursorCommentsSetName sets the name
    string for the cursor. This name is used to identify the cursor within the
    theme.


XcursorCommentsSetNameHandle sets the name
    string for the cursor, associating it with a specific XcursorFile
    handle.


XcursorCommentsSetParent sets the parent
    name string for the cursor. This is used to specify a fallback cursor.


XcursorCommentsSetParentHandle sets the
    parent name string for the cursor, associating it with a specific
    XcursorFile handle.






DATATYPES



  
XcursorComments

  
A structure containing metadata for cursors, including comments, names,
      and parent names.

  
XcursorFile

  
A handle representing an opened Xcursor file.








FUNCTIONS


The following functions are provided for managing cursor comments
    and names:



  
XcursorCommentsCreate

  
Allocates and initializes a new XcursorComments
      structure. Returns a pointer to the newly created structure, or
      NULL on failure.

  
XcursorCommentsDestroy

  
Frees all memory associated with the provided
      XcursorComments structure. The pointer itself is
      not freed.

  
XcursorCommentsGet

  
Retrieves the comment string associated with the cursor. Returns a pointer
      to the comment string, or NULL if no comment is
      set.

  
XcursorCommentsSet

  
Sets the comment string for the cursor. The provided string is copied.
      If comment is NULL, any
      existing comment is cleared.

  
XcursorCommentsSetName

  
Sets the name string for the cursor. This name is typically used to
      identify the cursor within a cursor theme. The provided string is copied.
      If name is NULL, any
      existing name is cleared.

  
XcursorCommentsSetNameHandle

  
Sets the name string for the cursor, associating it with a specific
      XcursorFile handle. This is useful when dealing
      with multiple cursors within a single file or archive.

  
XcursorCommentsSetParent

  
Sets the parent name string for the cursor. This is used to specify a
      fallback cursor if the current cursor is not available. The provided
      string is copied. If parent is
      NULL, any existing parent name is cleared.

  
XcursorCommentsSetParentHandle

  
Sets the parent name string for the cursor, associating it with a specific
      XcursorFile handle.








ENVIRONMENT



  
Xcursor.theme_core

  
Enables themes for core cursors if the environment variable is
      true.





  

  
If the environment variable is not given, Xcursor tries the
      Xcursor.theme_core resource.

  

  
An application can enable or disable themes using
    XcursorSetThemeCore.








CAVEATS


Xcursor will probably change radically in the future; weak
    attempts will be made to retain some level of source-file compatibility.
