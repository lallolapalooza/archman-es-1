Paquete: libx11

Licencias: MIT AND X11

XCreateColormap(3) FUNCIONES DE XLIB XCreateColormap(3)

NOMBRE

XCreateColormap, XCopyColormapAndFree, XFreeColormap, XColor - crear, copiar o destruir mapas de color y estructuras de color

SINTAXIS

Colormap XCreateColormap(Display *display, Window w, Visual *visual, int alloc);

Colormap XCopyColormapAndFree(Display *display, Colormap colormap);

int XFreeColormap(Display *display, Colormap colormap);

ARGUMENTOS

alloc
Especifica las entradas del mapa de color a asignar. Puedes pasar AllocNone o AllocAll.
colormap
Especifica el mapa de color que deseas crear, copiar, establecer o destruir.
display
Especifica la conexión con el servidor X.
visual
Especifica un tipo de visual soportado en la pantalla. Si el tipo de visual no es uno soportado por la pantalla, se produce un error BadMatch.
w
Especifica la ventana en cuya pantalla deseas crear un mapa de color.

DESCRIPCIÓN

La función XCreateColormap crea un mapa de color del tipo de visual especificado para la pantalla en la que reside la ventana especificada y devuelve el ID del mapa de color asociado. Ten en cuenta que la ventana especificada solo se utiliza para determinar la pantalla.

Los valores iniciales de las entradas del mapa de color no están definidos para las clases de visual GrayScale, PseudoColor y DirectColor. Para StaticGray, StaticColor y TrueColor, las entradas tienen valores definidos, pero esos valores son específicos del visual y no están definidos por X. Para StaticGray, StaticColor y TrueColor, alloc debe ser AllocNone, o se produce un error BadMatch. Para las otras clases de visual, si alloc es AllocNone, el mapa de color inicialmente no tiene entradas asignadas y los clientes pueden asignarlas. Para obtener información sobre los tipos de visual, consulta la sección 3.1.

Si alloc es AllocAll, todo el mapa de color se asigna como escribible. Los valores iniciales de todas las entradas asignadas no están definidos. Para GrayScale y PseudoColor, el efecto es como si una llamada a XAllocColorCells devolviera todos los valores de píxel de cero a N-1, donde N es el número de entradas de mapa de color en el visual especificado. Para DirectColor, el efecto es como si una llamada a XAllocColorPlanes devolviera un valor de píxel de cero y valores de máscara roja, verde y azul que contuvieran los mismos bits que las máscaras correspondientes en el visual especificado. Sin embargo, en todos los casos, ninguna de estas entradas puede liberarse usando XFreeColors.

XCreateColormap puede generar errores BadAlloc, BadMatch, BadValue y BadWindow.

La función XCopyColormapAndFree crea un mapa de color del mismo tipo de visual y para la misma pantalla que el mapa de color especificado y devuelve el ID del nuevo mapa de color. También mueve todas las asignaciones existentes del cliente del mapa de color especificado al nuevo mapa de color con sus valores de color intactos y sus características de solo lectura o escritura intactas, y libera esas entradas en el mapa de color especificado. Los valores de color en otras entradas del nuevo mapa de color no están definidos. Si el mapa de color especificado fue creado por el cliente con alloc establecido en AllocAll, el nuevo mapa de color también se crea con AllocAll, todos los valores de color para todas las entradas se copian del mapa de color especificado y luego se liberan todas las entradas en el mapa de color especificado. Si el mapa de color especificado no fue creado por el cliente con AllocAll, las asignaciones a mover son todos aquellos píxeles y planos que han sido asignados por el cliente usando XAllocColor, XAllocNamedColor, XAllocColorCells o XAllocColorPlanes y que no han sido liberados desde que fueron asignados.

XCopyColormapAndFree puede generar errores BadAlloc y BadColor.

La función XFreeColormap elimina la asociación entre el ID del recurso del mapa de color y el mapa de color, y libera el almacenamiento del mapa de color. Sin embargo, esta función no tiene ningún efecto sobre el mapa de color predeterminado de una pantalla. Si el mapa de color especificado es un mapa instalado para una pantalla, se desinstala (ver XUninstallColormap). Si el mapa de color especificado se define como el mapa de color para una ventana (mediante XCreateWindow, XSetWindowColormap o XChangeWindowAttributes), XFreeColormap cambia el mapa de color asociado con la ventana a None y genera un evento ColormapNotify. X no define los colores mostrados para una ventana con un mapa de color de None.

XFreeColormap puede generar un error BadColor.

ESTRUCTURAS

La estructura XColor contiene:

typedef struct {
        unsigned long pixel;    /* valor del píxel */
        unsigned short red, green, blue;        /* valores rgb */
        char flags;     /* DoRed, DoGreen, DoBlue */
        char pad;
} XColor;

Los valores rojo, verde y azul están siempre en el rango de 0 a 65535 inclusive, independientemente del número de bits realmente utilizados en el hardware de la pantalla. El servidor escala estos valores hacia abajo al rango utilizado por el hardware. Negro se representa con (0,0,0) y blanco se representa con (65535,65535,65535). En algunas funciones, el miembro flags controla cuáles de los miembros rojo, verde y azul se utilizan y puede ser el OR inclusivo de cero o más de DoRed, DoGreen y DoBlue.

DIAGNÓSTICOS

BadAlloc
El servidor no pudo asignar el recurso solicitado o memoria del servidor.
BadColor
Un valor para un argumento Colormap no nombra un Colormap definido.
BadMatch
Se utiliza una ventana InputOnly como Drawable.
BadMatch
Algún argumento o par de argumentos tiene el tipo y rango correctos pero no coincide de alguna otra manera requerida por la solicitud.
BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
BadWindow
Un valor para un argumento Window no nombra una Window definida.

XCopyColormapAndFree.3 - Manual de Linux

NOMBRE

XCopyColormapAndFree - Copia un mapa de colores y libera el mapa de colores de origen.

SINOPSIS

int XCopyColormapAndFree(Display *display, Colormap cmap, ColormapSegment *segment);

DESCRIPCIÓN

Copia un mapa de colores de origen especificado por cmap en el display dado a un nuevo mapa de colores en el mismo display. El nuevo mapa de colores se pasa de vuelta en segment->new_cmap.

Si cmap es un mapa de colores de solo lectura, entonces XCopyColormapAndFree no hará nada y devolverá un error.

Si cmap es un mapa de colores asignado por el usuario, entonces XCopyColormapAndFree no hará nada y devolverá un error.

Si la copia tiene éxito, XCopyColormapAndFree liberará el mapa de colores de origen y su contenido asociado.

Si la copia falla, XCopyColormapAndFree no hará nada y devolverá un error.

VALOR DE RETORNO

Devuelve Success si la operación se realiza correctamente, de lo contrario, devuelve un código de error.

DIAGNÓSTICOS

BadAlloc: no se pudo asignar memoria suficiente para el nuevo mapa de colores.

BadColor: el mapa de colores especificado no es válido.

BadDrawable: el drawable especificado no es válido.

BadMatch: la pantalla o el profundo no coinciden.

BadPixmap: el pixmap especificado no es válido.

BadWindow: la ventana especificada no es válida.

VER TAMBIÉN

XCreateColormap(3), XFreeColormap(3), XInstallColormap(3), XUninstallColormap(3)
