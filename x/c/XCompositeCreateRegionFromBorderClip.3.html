DESCRIPCIÓN

La extensión composite proporciona varios mecanismos relacionados:

Almacenamiento por jerarquía

La renderización de una jerarquía completa de ventanas se redirige a almacenamiento fuera de pantalla. Los píxeles de esa jerarquía están disponibles siempre que sea visible. El almacenamiento se reasigna automáticamente cuando la ventana de nivel superior cambia de tamaño. No se conservan los contenidos más allá de la geometría de la ventana superior.

Actualización automática de sombra

Cuando una jerarquía se renderiza fuera de pantalla, el servidor X proporciona un mecanismo automático para presentar esos contenidos dentro de la ventana padre. La implementación es libre de hacer que esta actualización se retrase con respecto a las operaciones de renderización reales en una cantidad de tiempo no especificada. Este mecanismo de actualización automática puede deshabilitarse para que el contenido de la ventana padre pueda ser determinado completamente por una aplicación externa.

Ventana de Superposición Composite

La versión 0.3 del protocolo agrega la Ventana de Superposición Composite, que proporciona a los gestores de composición una superficie sobre la cual dibujar sin interferencias. Esta ventana siempre está por encima de las ventanas normales y siempre está por debajo de la ventana del salvapantallas. Es una ventana InputOutput cuyas dimensiones de ancho y alto son las dimensiones de la pantalla. Su visual es el visual raíz y su borde es cero. Los intentos de redirigirla usando la extensión composite se ignoran. Esta ventana no aparece en la respuesta de la solicitud QueryTree. También es una ventana con redirección anulada. Estas dos últimas características la hacen invisible para los gestores de ventanas y otros clientes X11. La única forma de acceder al XID de esta ventana es a través de la solicitud CompositeGetOverlayWindow. Inicialmente, la Ventana de Superposición Composite está desmapeada.

Recorte de ventana padre

La versión 0.4 del protocolo modifica la semántica del recorte de ventana padre en presencia de hijos redirigidos manualmente. Con esta versión, el área en el padre cubierta por hijos redirigidos manualmente se deja en la lista de recorte del padre en lugar de ser eliminada como en versiones anteriores.

El almacenamiento fuera de pantalla puede crearse para ventanas individuales o para todos los hijos de una ventana. La actualización manual de sombra puede ser seleccionada por una sola aplicación por ventana; la actualización manual también puede seleccionarse por ventana o para cada hijo de una ventana. La detección de cuándo actualizar puede hacerse con la extensión Damage.

El almacenamiento fuera de pantalla incluye el contenido de la ventana, sus bordes y el contenido de todos los descendientes.

ARGUMENTOS

display

Puntero a la estructura Display devuelta por XOpenDisplay para la conexión con el servidor X.

event_base_return

Puntero a un entero donde se almacenará el valor base para los eventos de la Extensión Composite.

error_base_return

Puntero a un entero donde se almacenará el valor base para los errores de la Extensión Composite.

major_version_return

Puntero a un entero donde se almacenará la versión mayor de la Extensión Composite soportada por el servidor X.

minor_version_return

Puntero a un entero donde se almacenará la versión menor de la Extensión Composite soportada por el servidor X.

window

Especifica el ID de la ventana sobre la que operar.

update

Especifica el modo de actualización del contenido de la ventana. Debe ser CompositeRedirectAutomatic o CompositeRedirectManual.

FUNCIONES

XCompositeQueryExtension

XCompositeQueryExtension determina si la Extensión Composite está disponible en la pantalla dada. Devuelve True si la extensión es soportada, de lo contrario False. Si la extensión está presente, se devuelven los valores base para eventos y errores, y pueden usarse para decodificar valores de eventos y errores entrantes.

XCompositeQueryVersion

XCompositeQueryVersion determina si el Servidor X soporta una versión de la Extensión X Composite compatible con la biblioteca cliente. Se devuelve un Status distinto de cero si se soporta una versión compatible de la extensión, de lo contrario se devuelve un Status cero. Si la extensión es soportada, se devuelven los números de versión mayor y menor para indicar el nivel de soporte de la Extensión Composite. Ninguna otra función de XComposite (excepto XCompositeQueryExtension) puede ser llamada antes de esta función. Si un cliente viola esta regla, los efectos de todas las llamadas subsiguientes de XComposite que realice son indefinidos.

XCompositeVersion

XCompositeVersion devuelve la versión de la biblioteca X Composite. El número de versión se codifica como: (mayor * 10000) + (menor * 100) + revisión

Por ejemplo, la versión 1.4.6 se codificaría como el entero 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow solicita al servidor X que dirija la jerarquía que comienza en window a almacenamiento fuera de pantalla. El argumento update especifica si el contenido se refleja automáticamente en la ventana padre o no. Solo un cliente a la vez puede especificar un tipo de actualización de CompositeRedirectManual, otro intento resultará en un error BadAccess. Cuando todos los clientes que activan la redirección terminan, la redirección se deshabilitará automáticamente.

La ventana raíz no puede ser redirigida. Hacerlo resulta en un error BadMatch. Especificar un ID de ventana inválido resultará en un error BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows solicita al servidor X que redirija las jerarquías que comienzan en todos los hijos actuales y futuros de window como en XCompositeRedirectWindow. Si update es CompositeRedirectManual, entonces se inhibe la pintura del fondo de la ventana durante la manipulación de la ventana y las solicitudes ClearArea.

XCompositeUnredirectWindow

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de window. Si la ventana especificada no fue seleccionada para redirección por el cliente actual, resulta un error BadValue.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de todos los hijos de window. Si la ventana especificada no fue seleccionada para sub-redirección por el cliente actual, resulta un error BadValue.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap devuelve un Pixmap que contiene el contenido de la ventana especificada y sus descendientes. El Pixmap tendrá el mismo tamaño que la ventana y se creará con el mismo orden de bytes y visual que la ventana. Si la ventana no está redirigida, o si se redirige manualmente, se devuelve un Pixmap nulo. Si la ventana está redirigida y se le asigna una actualización automática, el Pixmap contendrá el contenido actual de la ventana. Este Pixmap debe ser liberado con XFree cuando ya no se necesite.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow devuelve el Window ID de la ventana de superposición del composite. Esta ventana es una ventana InputOutput con el visual raíz y las dimensiones de la pantalla. Es una ventana override-redirect y no aparece en la respuesta de QueryTree. El cliente que llama a esta función asume la propiedad de esta ventana y es responsable de mapearla y desmapearla, así como de liberar su contenido. Llamar a esta función múltiples veces en el mismo Display devolverá el mismo Window ID. La ventana de superposición solo se crea la primera vez que se llama a esta función. Si la extensión Composite no está disponible, se devuelve un valor inválido.

XCompositeReleaseOverlayWindow

XCompositeReleaseOverlayWindow libera la propiedad de la ventana de superposición del composite. Solo el cliente que obtuvo la ventana de superposición puede llamarla. Si se llama por un cliente que no obtuvo la ventana, se produce un error BadAccess. Después de llamar a esta función, el cliente ya no es responsable de la ventana de superposición.

XCompositeCreateRegionFromBorderClip(3)

NAME

XCompositeCreateRegionFromBorderClip - create a region from the clipped window contents

SYNOPSIS

#include <X11/extensions/Xcomposite.h>

/*
 * For XCompositeCreateRegionFromBorderClip
 */
Region
XCompositeCreateRegionFromBorderClip (Display *dpy, Window window);

/*
 * For XCompositeNameWindowPixmap
 */
Pixmap
XCompositeNameWindowPixmap (Display *dpy, Window window);

/*
 * For XCompositeGetOverlayWindow
 */
Window
XCompositeGetOverlayWindow (Display *dpy, Window window);

/*
 * For XCompositeReleaseOverlayWindow
 */
void
XCompositeReleaseOverlayWindow (Display *dpy, Window window);

DESCRIPTION

The Composite Extension provides the ability to redirect arbitrary windows to a pixmap, allowing applications to construct their window contents off-screen and to composite them together, or to composite them with the contents of other windows.

This extension enables efficient screen-shotting and live compositing.

XCompositeCreateRegionFromBorderClip

XCompositeCreateRegionFromBorderClip returns a Region object representing the area of the window that is visible to the X server. This is the same clipping region that is used when the window is to be rendered. This region can be used to restrict rendering to suitable areas while updating only a single window.

The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

The X server must support at least version 0.2 of the Composite Extension for XCompositeCreateRegionFromBorderClip.

ARGUMENTS

dpy
Specifies the connection to the X server.
window
Specifies the window.

FUNCTIONS

XCompositeCreateRegionFromBorderClip

XCompositeCreateRegionFromBorderClip returns a Region object that represents the window's clipped border area. This is the area of the window clipped against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
