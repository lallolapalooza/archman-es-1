XCreateColormap(3)

Paquete: libx11

Licencias: MIT Y X11

XCreateColormap(3) FUNCIONES DE XLIB XCreateColormap(3)

NOMBRE

XCreateColormap, XCopyColormapAndFree, XFreeColormap, XColor - crear, copiar o destruir mapas de color y estructuras de color

SINTAXIS

Colormap XCreateColormap(Display *display, Window w, Visual *visual, int alloc);

Colormap XCopyColormapAndFree(Display *display, Colormap colormap);

int XFreeColormap(Display *display, Colormap colormap);

ARGUMENTOS

alloc
Especifica las entradas del mapa de color a asignar. Puede pasar AllocNone o AllocAll.
colormap
Especifica el mapa de color que desea crear, copiar, establecer o destruir.
display
Especifica la conexión con el servidor X.
visual
Especifica un tipo de visual soportado en la pantalla. Si el tipo de visual no es uno de los soportados por la pantalla, se produce un error BadMatch.
w
Especifica la ventana en cuya pantalla desea crear un mapa de color.

DESCRIPCIÓN

La función XCreateColormap crea un mapa de color del tipo de visual especificado para la pantalla en la que reside la ventana especificada y devuelve el ID del mapa de color asociado.

Los valores iniciales de las entradas del mapa de color no están definidos para las clases de visual GrayScale, PseudoColor y DirectColor. Para StaticGray, StaticColor y TrueColor, las entradas tienen valores definidos, pero esos valores son específicos del visual y no están definidos por X. Para StaticGray, StaticColor y TrueColor, alloc debe ser AllocNone, o se produce un error BadMatch. Para las otras clases de visual, si alloc es AllocNone, el mapa de color inicialmente no tiene entradas asignadas, y los clientes pueden asignarlas. Para información sobre los tipos de visual, consulte la sección 3.1.

Si alloc es AllocAll, todo el mapa de color se asigna como escribible. Los valores iniciales de todas las entradas asignadas no están definidos. Para GrayScale y PseudoColor, el efecto es como si una llamada a XAllocColorCells devolviera todos los valores de píxel desde cero hasta N-1, donde N es el número de entradas del mapa de color en el visual especificado. Para DirectColor, el efecto es como si una llamada a XAllocColorPlanes devolviera un valor de píxel de cero y valores de máscara roja, verde y azul que contengan los mismos bits que las máscaras correspondientes en el visual especificado. Sin embargo, en todos los casos, ninguna de estas entradas puede liberarse utilizando XFreeColors.

XCreateColormap puede generar errores BadAlloc, BadMatch, BadValue y BadWindow.

La función XCopyColormapAndFree crea un mapa de color del mismo tipo de visual y para la misma pantalla que el mapa de color especificado y devuelve el nuevo ID del mapa de color. También mueve todas las asignaciones existentes del cliente del mapa de color especificado al nuevo mapa de color con sus valores de color intactos y sus características de solo lectura o escritura intactas, y libera esas entradas en el mapa de color especificado. Los valores de color en otras entradas del nuevo mapa de color no están definidos. Si el mapa de color especificado fue creado por el cliente con alloc establecido en AllocAll, el nuevo mapa de color también se crea con AllocAll, todos los valores de color para todas las entradas se copian del mapa de color especificado, y luego se liberan todas las entradas en el mapa de color especificado. Si el mapa de color especificado no fue creado por el cliente con AllocAll, las asignaciones a mover son todos los píxeles y planos que han sido asignados por el cliente utilizando XAllocColor, XAllocNamedColor, XAllocColorCells o XAllocColorPlanes y que no han sido liberados desde que fueron asignados.

XCopyColormapAndFree puede generar errores BadAlloc y BadColor.

La función XFreeColormap elimina la asociación entre el ID del recurso del mapa de color y el mapa de color y libera el almacenamiento del mapa de color. Sin embargo, esta función no tiene efecto sobre el mapa de color predeterminado para una pantalla. Si el mapa de color especificado es un mapa instalado para una pantalla, se desinstala (ver XUninstallColormap). Si el mapa de color especificado se define como el mapa de color para una ventana (mediante XCreateWindow, XSetWindowColormap o XChangeWindowAttributes), XFreeColormap cambia el mapa de color asociado con la ventana a None y genera un evento ColormapNotify. X no define los colores mostrados para una ventana con un mapa de color de None.

XFreeColormap puede generar un error BadColor.

ESTRUCTURAS

La estructura XColor contiene:

typedef struct {
        unsigned long pixel;    /* valor del píxel */
        unsigned short red, green, blue;        /* valores rgb */
        char flags;     /* DoRed, DoGreen, DoBlue */
        char pad;
} XColor;

Los valores de rojo, verde y azul siempre están en el rango de 0 a 65535 inclusive, independientemente del número de bits utilizados en el hardware de visualización. El servidor escala estos valores hacia abajo al rango utilizado por el hardware. Negro se representa con (0,0,0) y blanco se representa con (65535,65535,65535). En algunas funciones, el miembro `flags` controla cuáles de los miembros `red`, `green` y `blue` se utilizan y puede ser el OR inclusivo de cero o más de DoRed, DoGreen y DoBlue.

DIAGNÓSTICOS

BadAlloc
El servidor no pudo asignar el recurso solicitado o memoria del servidor.
BadColor
Un valor para un argumento de Colormap no nombra un Colormap definido.
BadMatch
Una ventana InputOnly se utiliza como un Drawable.
BadMatch
Algún argumento o par de argumentos tiene el tipo y rango correctos, pero falla al coincidir de alguna otra manera requerida por la solicitud.
BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
BadWindow
Un valor para un argumento de Window no nombra una Window definida.
