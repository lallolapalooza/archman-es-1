NOMBRE

Xcomposite - biblioteca de la extensión X Composite

SINOPSIS

#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base_return, int *error_base_return);

Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

int XCompositeVersion(void);

void XCompositeRedirectWindow(Display *dpy, Window window, int update);

void XCompositeRedirectSubwindows(Display *dpy, Window window, int update);

void XCompositeUnredirectWindow(Display *dpy, Window window, int update);

void XCompositeUnredirectSubwindows(Display *dpy, Window window, int update);

XserverRegion XCompositeCreateRegionFromBorderClip(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPCIÓN

La extensión composite proporciona varios mecanismos relacionados:

Almacenamiento por jerarquía

La representación de toda una jerarquía de ventanas se redirige a almacenamiento fuera de pantalla. Los píxeles de esa jerarquía están disponibles siempre que sea visible. El almacenamiento se reasigna automáticamente cuando la ventana de nivel superior cambia de tamaño. El contenido más allá de la geometría de la ventana superior no se conserva.

Actualización automática de sombra

Cuando una jerarquía se representa fuera de pantalla, el servidor X proporciona un mecanismo automático para presentar ese contenido dentro de la ventana padre. La implementación es libre de hacer que esta actualización se retrase respecto a las operaciones de renderizado reales en una cantidad de tiempo no especificada. Este mecanismo de actualización automática puede deshabilitarse para que el contenido de la ventana padre pueda ser determinado completamente por una aplicación externa.

Ventana de superposición compuesta (Composite Overlay Window)

La versión 0.3 del protocolo añade la Ventana de Superposición Compuesta, que proporciona a los gestores de composición una superficie sobre la cual dibujar sin interferencias. Esta ventana está siempre por encima de las ventanas normales y siempre por debajo de la ventana del salvapantallas. Es una ventana de EntradaSalida (InputOutput) cuyas anchura y altura son las dimensiones de la pantalla. Su visual es el visual raíz y su ancho de borde es cero. Los intentos de redirigirla usando la extensión composite se ignoran. Esta ventana no aparece en la respuesta de la solicitud QueryTree. También es una ventana de redirección de anulación (override redirect). Estas dos últimas características la hacen invisible para los gestores de ventanas y otros clientes de X11. La única forma de acceder al XID de esta ventana es a través de la solicitud CompositeGetOverlayWindow. Inicialmente, la Ventana de Superposición Compuesta está desmapeada (unmapped).

Recorte de la ventana padre

La versión 0.4 del protocolo modifica la semántica del recorte de la ventana padre en presencia de hijos redirigidos manualmente. Con esta versión, el área en el padre cubierta por hijos redirigidos manualmente se deja en la lista de recortes del padre en lugar de eliminarse como en versiones anteriores.

El almacenamiento fuera de pantalla puede crearse para ventanas individuales o para todos los hijos de una ventana. La actualización manual de sombra puede ser seleccionada por una sola aplicación para cada ventana; la actualización manual también puede ser seleccionada por ventana o para cada hijo de una ventana. La detección de cuándo actualizar puede hacerse con la extensión Damage.

El almacenamiento fuera de pantalla incluye el contenido de la ventana, sus bordes y el contenido de todos los descendientes.

ARGUMENTOS

display

Puntero a la estructura Display devuelta por XOpenDisplay para la conexión con el servidor X.

event_base_return

Puntero a un entero donde se almacenará el valor base para los eventos de la Extensión Composite.

error_base_return

Puntero a un entero donde se almacenará el valor base para los errores de la Extensión Composite.

major_version_return

Puntero a un entero donde se almacenará la versión mayor de la Extensión Composite soportada por el servidor X.

minor_version_return

Puntero a un entero donde se almacenará la versión menor de la Extensión Composite soportada por el servidor X.

window

Especifica el ID de la ventana sobre la que operar.

update

Especifica el modo para actualizar el contenido de la ventana. Debe ser CompositeRedirectAutomatic o CompositeRedirectManual.

FUNCIONES

XCompositeQueryExtension

XCompositeQueryExtension determina si la Extensión Composite está disponible en la pantalla dada. Devuelve True si la extensión es soportada, de lo contrario False. Si la extensión está presente, se devuelven los valores base para los eventos y errores, y pueden usarse para decodificar los valores de eventos y errores entrantes.

XCompositeQueryVersion

XCompositeQueryVersion determina si el Servidor X soporta una versión de la Extensión X Composite compatible con la biblioteca cliente. Se devuelve un Status distinto de cero si se soporta una versión compatible de la extensión, de lo contrario se devuelve un Status cero. Si la extensión es soportada, se devuelven los números de versión mayor y menor para indicar el nivel de soporte de la Extensión Composite. Ninguna otra función XComposite (excepto XCompositeQueryExtension) puede ser llamada antes que esta función. Si un cliente viola esta regla, los efectos de todas las llamadas XComposite subsiguientes que realice son indefinidos.

XCompositeVersion

XCompositeVersion devuelve la versión de la biblioteca X Composite. El número de versión se codifica como: (mayor * 10000) + (menor * 100) + revisión

Por ejemplo, la versión 1.4.6 se codificaría como el entero 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow solicita al servidor X que dirija la jerarquía que comienza en window a almacenamiento fuera de pantalla. El argumento update especifica si los contenidos se reflejan automáticamente en la ventana padre o no. Solo un cliente a la vez puede especificar un tipo de actualización de CompositeRedirectManual, otro intento resultará en un error BadAccess. Cuando todos los clientes que habilitan la redirección terminan, la redirección se deshabilitará automáticamente.

La ventana raíz no puede ser redirigida. Hacerlo resulta en un error BadMatch. Especificar un ID de ventana inválido resultará en un error BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows solicita al servidor X que redirija jerarquías que comienzan en todos los hijos actuales y futuros de window como en XCompositeRedirectWindow. Si update es CompositeRedirectManual, entonces se inhibe la pintura del fondo de la ventana durante la manipulación de la ventana y las solicitudes ClearArea.

XCompositeUnredirectWindow

XCompositeUnredirectWindow solicita al servidor X que termine la redirección de window. Si la ventana especificada no fue seleccionada para redirección por el cliente actual, se produce un error BadValue.

XCompositeUnredirectSubwindows

XCompositeUnredirectSubwindows solicita al servidor X que termine la redirección de todos los hijos de window. Si la ventana especificada no fue seleccionada para sub-redirección por el cliente actual, se produce un error BadValue.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap crea y devuelve un ID de pixmap que sirve como referencia al almacenamiento fuera de pantalla para window. Este pixmap permanecerá asignado hasta que se libere, incluso si la ventana no está mapeada, reconfigurada o destruida. Sin embargo, la ventana obtendrá un nuevo pixmap asignado cada vez que se mapee o redimensione, por lo que esta función deberá ser reinvocada para que el cliente continúe refiriéndose al almacenamiento que contiene el contenido actual de la ventana. Genera un error BadMatch si window no está redirigida o no es visible.

El servidor X debe soportar al menos la versión 0.2 de la Extensión Composite para XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow devuelve el ID de ventana de la Ventana de Superposición Composite para la pantalla especificada por el argumento window. Esta función notifica al servidor X que el cliente desea usar la Ventana de Superposición Composite de esta pantalla. Si esta Ventana de Superposición Composite aún no se ha mapeado, se mapea mediante esta solicitud.

La Ventana de Superposición Composite para una pantalla particular se desmapeará cuando todos los clientes que hayan llamado a esta función hayan llamado a XCompositeReleaseOverlayWindow para esa pantalla, o hayan terminado su conexión con el servidor X.

El servidor X debe soportar al menos la versión 0.3 de la Extensión Composite para XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

Esta solicitud especifica que el cliente ya no está usando la Ventana de Superposición Composite en la pantalla especificada por el argumento window. La Ventana de Superposición Composite de una pantalla se desmapea cuando ya no hay clientes que la estén utilizando.

El servidor X debe soportar al menos la versión 0.3 de la Extensión Composite para XCompositeReleaseOverlayWindow.
