NOMBRE

Xcursor - Biblioteca de gestión de cursores

SINOPSIS

#include <X11/Xcursor/Xcursor.h>

DESCRIPCIÓN

Xcursor es una biblioteca sencilla diseñada para ayudar a localizar y cargar cursores. Los cursores se pueden cargar desde archivos o desde memoria. Existe una biblioteca de cursores comunes que se mapean a los nombres de cursores estándar de X. Los cursores pueden existir en varios tamaños y la biblioteca elige automáticamente el mejor tamaño.

VISIÓN GENERAL FUNCIONAL

Xcursor está construida en un par de capas; en la capa inferior hay código que puede cargar imágenes de cursores desde archivos. Por encima de eso hay una capa que localiza archivos de cursores basándose en la ruta de la biblioteca y el tema. En la capa superior hay una capa que construye cursores ya sea a partir de una imagen cargada desde un archivo o uno de los cursores estándar de X. Al usar imágenes cargadas desde archivos, Xcursor prefiere usar la solicitud `CreateCursor` de la extensión Render si el servidor X la soporta. Donde no se soporta, Xcursor mapea la imagen del cursor a un cursor estándar de X y usa la solicitud `CreateCursor` principal.

ARCHIVOS DE CURSORES

Xcursor define un nuevo formato para los cursores en disco. Cada archivo contiene una o más imágenes de cursores. Cada imagen de cursor está etiquetada con un tamaño nominal para que se pueda seleccionar automáticamente el mejor tamaño. Se pueden cargar juntas múltiples imágenes de cursores del mismo tamaño nominal; se espera que las aplicaciones las usen como una secuencia animada.

Los archivos de cursores se almacenan como una cabecera que contiene una tabla de contenido seguida de una secuencia de fragmentos (chunks). La tabla de contenido indica el tipo, subtipo y posición en el archivo de cada fragmento. La cabecera del archivo se ve así:


mágica:	CARD32 "Xcur" (0x58, 0x63, 0x75, 0x72)
cabecera:	CARD32 bytes en esta cabecera
versión:	CARD32 número de versión del archivo
ntoc:	CARD32 número de entradas de la tabla de contenido
toc:	LISTofTOC tabla de contenido

Cada entrada de la tabla de contenido se ve así:


tipo:	CARD32 tipo de entrada
subtipo:	CARD32 etiqueta específica del tipo - tamaño para imágenes
posición:	CARD32 posición absoluta en bytes de la tabla en el archivo

Cada fragmento en el archivo tiene un conjunto de campos de cabecera comunes seguidos de campos adicionales específicos del tipo:


cabecera:	CARD32 bytes en la cabecera del fragmento (incluyendo campos específicos del tipo)
tipo:	CARD32 debe coincidir con el tipo en la TOC para este fragmento
subtipo:	CARD32 debe coincidir con el subtipo en la TOC para este fragmento
versión:	CARD32 número de versión para este tipo de fragmento

Actualmente hay dos tipos de fragmentos definidos para los archivos de cursores; comentarios e imágenes. Los comentarios se ven así:


cabecera:	20 Las cabeceras de comentarios son de 20 bytes
tipo:	0xfffe0001 El tipo de comentario es 0xfffe0001
subtipo:	{ 1 (COPYRIGHT), 2 (LICENSE), 3 (OTHER) }
versión:	1
longitud:	CARD32 longitud en bytes de la cadena UTF-8
cadena:	LISTofCARD8 cadena UTF-8

Las imágenes se ven así:


cabecera:	36 Las cabeceras de imágenes son de 36 bytes
tipo:	0xfffd0002 El tipo de imagen es 0xfffd0002
subtipo:	CARD32 El subtipo de imagen es el tamaño nominal
versión:	1
ancho:	CARD32 Debe ser menor o igual a 0x7fff
alto:	CARD32 Debe ser menor o igual a 0x7fff
xhot:	CARD32 Debe ser menor o igual al ancho
yhot:	CARD32 Debe ser menor o igual al alto
retraso:	CARD32 Retraso entre fotogramas de animación en milisegundos
píxeles:	LISTofCARD32 Píxeles en formato ARGB empaquetado

TEMAS

Xcursor (en su mayor parte) sigue la especificación de freedesktop.org para los temas de iconos. La ruta de búsqueda predeterminada que utiliza es

~/.local/share/icons, ~/.icons, /usr/share/icons, /usr/share/pixmaps

Dentro de cada uno de estos directorios, busca un directorio con el nombre del tema:

•
Dentro del directorio del tema, busca archivos de cursores en el subdirectorio “cursors”.
Xcursor busca un archivo específico, que debe ser uno de los nombres de forma (shape) del cursor, por ejemplo, como se usa en XcursorLibraryLoadImage o XcursorLibraryShape.
•
Si no encuentra un archivo de cursor coincidente en el subdirectorio “cursors”, Xcursor busca a continuación un archivo “index.theme” en cada directorio de tema para buscar temas heredados. Esas son líneas con este formato:
Hereda = nombre-tema

Xcursor utiliza el primer nombre-tema heredado, ignorando otros que puedan existir en un archivo “index.theme” dado. Si encuentra un tema heredado, Xcursor busca a lo largo de la ruta para usarlo también. Xcursor ignora otras claves en el archivo “index.theme”, incluyendo “Name” (es decir, el nombre que una aplicación gráfica puede usar como nombre de presentación).

Se puede listar más de un nombre-tema en la línea Inherits=. La especificación de freedesktop.org indica que los elementos de la lista están separados por comas. Xcursor también acepta punto y coma, pero traduce ambos a dos puntos al buscar en la ruta. Xcursor espera solo una línea Inherits=; la especificación de freedesktop.org no aclara si se permiten múltiples claves.

Si no se establece ningún tema, o si no se encuentra ningún cursor para el tema especificado en ningún lugar de la ruta, Xcursor verifica el tema “predeterminado”.

Cuando Xcursor encuentra un archivo de cursor, deja de buscar. Siempre utiliza el primer archivo de cursor encontrado mientras busca a lo largo de la ruta.

TIPOS DE DATOS

XcursorImage
contiene una sola imagen de cursor en memoria. Cada píxel del cursor es un valor de 32 bits que contiene ARGB con A en el byte más alto. 


typedef struct _XcursorImage {
    XcursorDim 	 size; 	/* tamaño nominal para coincidencia */
    XcursorDim 	 width; 	/* ancho real */
    XcursorDim 	 height; 	/* alto real */
    XcursorDim 	 xhot; 	/* punto activo x (debe estar dentro de la imagen) */
    XcursorDim 	 yhot; 	/* punto activo y (debe estar dentro de la imagen) */
    XcursorPixel 	*pixels; 	/* puntero a los píxeles */
} XcursorImage;
XcursorImages
contiene múltiples estructuras `XcursorImage`. Todas se liberan cuando se libera `XcursorImages` en `XcursorImagesDestroy`. 


typedef struct _XcursorImages {
    int 	 nimage; 	/* número de imágenes */
    XcursorImage 	**images; 	/* matriz de punteros a XcursorImage */
} XcursorImages;
XcursorCursors
Contiene múltiples objetos `Cursor`. Todos se liberan cuando se libera `XcursorCursors`. Estos tienen un recuento de referencias para que múltiples estructuras `XcursorAnimate` puedan usar los mismos `XcursorCursors`. 


typedef struct _XcursorCursors {
    Display 	*dpy; 	/* Pantalla que contiene los cursores */
    int 	 ref; 	/* recuento de referencias */
    int 	 ncursor; 	/* número de cursores */
    Cursor 	*cursors; 	/* matriz de cursores */
} XcursorCursors;
XcursorAnimate
Hace referencia a un conjunto de cursores y a una secuencia dentro de ese conjunto. Múltiples estructuras `XcursorAnimate` pueden hacer referencia al mismo `XcursorCursors`; cada una mantiene una referencia que se elimina cuando se libera `XcursorAnimate`. 


typedef struct _XcursorAnimate {
    XcursorCursors 	*cursors; 	/* lista de cursores a usar */
    int 	 sequence; 	/* cuál es el siguiente cursor */
} XcursorAnimate;
XcursorFile
Xcursor proporciona una API abstracta para acceder a los datos del archivo. Xcursor proporciona una implementación stdio de esta API abstracta; las aplicaciones son libres de crear implementaciones adicionales. Estas funciones son paralelas a las de stdio
