XCreateGC(3) FUNCIONES XLIB XCreateGC(3)

NOMBRE

XCreateGC, XCopyGC, XChangeGC, XGetGCValues, XFreeGC, XGContextFromGC, XGCValues — crear o liberar contextos gráficos y estructura de contexto gráfico

SINTAXIS

GC XCreateGC(Display *display, Drawable d, unsigned long valuemask, XGCValues *values);

int XCopyGC(Display *display, GC src, unsigned long valuemask, GC dest);

int XChangeGC(Display *display, GC gc, unsigned long valuemask, XGCValues *values);

Status XGetGCValues(Display *display, GC gc, unsigned long valuemask, XGCValues *values_return);

int XFreeGC(Display *display, GC gc);

GContext XGContextFromGC(GC gc);

ARGUMENTOS

d
Especifica el drawable.
dest
Especifica el GC de destino.
display
Especifica la conexión con el servidor X.
gc
Especifica el GC.
src
Especifica los componentes del GC de origen.
valuemask
Especifica qué componentes del GC se van a establecer, copiar, cambiar o devolver. Este argumento es el OR inclusivo a nivel de bits de cero o más de los bits de máscara de componente GC válidos.
values
Especifica cualquier valor según lo especificado por el valuemask.
values_return
Devuelve los valores del GC en la estructura XGCValues especificada.

DESCRIPCIÓN

La función XCreateGC crea un contexto gráfico y devuelve un GC. El GC se puede utilizar con cualquier drawable de destino que tenga la misma raíz y profundidad que el drawable especificado. El uso con otros drawables da como resultado un error BadMatch.

XCreateGC puede generar errores BadAlloc, BadDrawable, BadFont, BadMatch, BadPixmap y BadValue.

La función XCopyGC copia los componentes especificados del GC de origen al GC de destino. Los GC de origen y destino deben tener la misma raíz y profundidad, o se producirá un error BadMatch. El valuemask especifica qué componente copiar, como para XCreateGC.

XCopyGC puede generar errores BadAlloc, BadGC y BadMatch.

La función XChangeGC cambia los componentes especificados por valuemask para el GC especificado. El argumento values contiene los valores a establecer. Los valores y restricciones son los mismos que para XCreateGC. Cambiar la máscara de recorte anula cualquier solicitud anterior de XSetClipRectangles en el contexto. Cambiar el desplazamiento o la lista de guiones anula cualquier solicitud anterior de XSetDashes en el contexto. El orden en que se verifican y modifican los componentes depende del servidor. Si se genera un error, es posible que se hayan modificado un subconjunto de los componentes.

XChangeGC puede generar errores BadAlloc, BadFont, BadGC, BadMatch, BadPixmap y BadValue.

La función XGetGCValues devuelve los componentes especificados por valuemask para el GC especificado. Si el valuemask contiene un conjunto válido de bits de máscara de GC (GCFunction, GCPlaneMask, GCForeground, GCBackground, GCLineWidth, GCLineStyle, GCCapStyle, GCJoinStyle, GCFillStyle, GCFillRule, GCTile, GCStipple, GCTileStipXOrigin, GCTileStipYOrigin, GCFont, GCSubwindowMode, GCGraphicsExposures, GCClipXOrigin, GCClipYOrigin, GCDashOffset o GCArcMode) y no se produce ningún error, XGetGCValues establece los componentes solicitados en values_return y devuelve un estado distinto de cero. De lo contrario, devuelve un estado cero. Tenga en cuenta que la máscara de recorte y la lista de guiones (representadas por los bits GCClipMask y GCDashList, respectivamente, en el valuemask) no se pueden solicitar. Tenga en cuenta también que se devolverá un ID de recurso no válido (con uno o más de los tres bits más significativos establecidos en 1) para GCFont, GCTile y GCStipple si el componente nunca ha sido establecido explícitamente por el cliente.

La función XFreeGC destruye el GC especificado, así como todo el almacenamiento asociado.

XFreeGC puede generar un error BadGC.

Los atributos de función de un GC se utilizan cuando se actualiza una sección de un drawable (el destino) con bits de otro lugar (el origen). La función en un GC define cómo se deben calcular los nuevos bits de destino a partir de los bits de origen y los bits de destino antiguos. GXcopy suele ser el más útil porque funciona en una pantalla en color, pero las aplicaciones especiales pueden utilizar otras funciones, especialmente en conjunción con planos particulares de una pantalla en color. Muchas operaciones gráficas dependen de los valores de los píxeles o de los planos en un GC. El atributo planes es de tipo long, y especifica qué planos del destino se van a modificar, un bit por plano. Una pantalla monocromática tiene solo un plano y será el bit menos significativo de la palabra. A medida que se añaden planos al hardware de pantalla, ocuparán bits más significativos en la máscara de planos.

En las operaciones gráficas, dado un píxel de origen y destino, el resultado se calcula bit a bit en los bits correspondientes de los píxeles. Es decir, se realiza una operación booleana en cada plano de bits. La máscara de planos restringe la operación a un subconjunto de planos. Una constante macro AllPlanes se puede usar para referirse a todos los planos de la pantalla simultáneamente. El resultado se calcula de la siguiente manera:

((src FUNC dst) AND plane-mask) OR (dst AND (NOT plane-mask))

No se realiza ninguna comprobación de rango en los valores de primer plano (foreground), fondo (background) o máscara de planos (plane_mask). Simplemente se truncan al número apropiado de bits. El grosor de línea se mide en píxeles y puede ser mayor o igual que uno (línea gruesa) o puede ser el valor especial cero (línea delgada).

Las líneas gruesas se dibujan centradas en la ruta descrita por la solicitud gráfica. A menos que se especifique lo contrario por el estilo de unión (join-style) o el estilo de extremo (cap-style), el cuadro delimitador de una línea gruesa con puntos finales [x1, y1], [x2, y2] y anchura w es un rectángulo con vértices en las siguientes coordenadas reales:

[x1-(w*sn/2), y1+(w*cs/2)], [x1+(w*sn/2), y1-(w*cs/2)],
[x2-(w*sn/2), y2+(w*cs/2)], [x2+(w*sn/2), y2-(w*cs/2)]

Aquí sn es el seno del ángulo de la línea, y cs es el coseno del ángulo de la línea. Un píxel es parte de la línea y, por lo tanto, se dibuja si el centro del píxel está completamente dentro del cuadro delimitador (que se considera que tiene bordes infinitamente delgados). Si el centro del píxel está exactamente en el cuadro delimitador, es parte de la línea si y solo si el interior está inmediatamente a su derecha (dirección de aumento de x). Los píxeles con centros en un borde horizontal son un caso especial y son parte de la línea si y solo si el interior o el borde está inmediatamente debajo (dirección de aumento de y) y el interior o el borde está inmediatamente a la derecha (dirección de aumento de x).

Las líneas delgadas (anchura de línea cero) son líneas de un píxel de ancho dibujadas usando un algoritmo no especificado y dependiente del dispositivo. Solo hay dos restricciones en este algoritmo.

1.
Si se dibuja una línea sin recortar desde [x1,y1] hasta [x2,y2] y si otra línea se dibuja sin recortar desde [x1+dx,y1+dy] hasta [x2+dx,y2+dy], un punto [x,y] es tocado al dibujar la primera línea si y solo si el punto [x+dx,y+dy] es tocado al dibujar la segunda línea.
2.
El conjunto efectivo de puntos que componen una línea no puede verse afectado por el recorte. Es decir, un punto se toca en una línea recortada si y solo si el punto está dentro de la región de recorte y el punto sería tocado por la línea cuando se dibuja sin recortar.

Una línea gruesa dibujada desde [x1,y1] hasta [x2,y2] siempre dibuja los mismos píxeles que una línea gruesa dibujada desde [x2,y2] hasta [x1,y1], sin contar el estilo de extremo y el estilo de unión. Se recomienda que esta propiedad sea verdadera para las líneas delgadas, pero no es obligatorio. Una anchura de línea de cero puede diferir de una anchura de línea de uno en los píxeles que se dibujan. Esto permite el uso de hardware de dibujo de líneas de muchos fabricantes, que pueden funcionar muchas veces más rápido que las líneas gruesas especificadas con mayor precisión.

En general, dibujar una línea delgada será más rápido que dibujar una línea gruesa de anchura uno. Sin embargo, debido a sus diferentes algoritmos de dibujo, las líneas delgadas pueden no combinarse estéticamente bien con las líneas gruesas. Si se desea obtener resultados precisos y uniformes en todas las pantallas, un cliente siempre debe usar una anchura de línea de uno en lugar de una anchura de línea de cero.

El estilo de línea define qué secciones de una línea se dibujan:

LineSolid Se dibuja la ruta completa de la línea.
LineDoubleDash Se dibuja la ruta completa de la línea, pero los guiones pares se rellenan de manera diferente a los guiones impares (ver estilo de relleno) con el estilo CapButt utilizado donde se unen los guiones pares e impares.
LineOnOffDash Solo se dibujan los guiones pares, y el estilo de extremo se aplica a todos los extremos internos de los guiones individuales, excepto CapNotLast se trata como CapButt.

El estilo de extremo define cómo se dibujan los puntos finales de una ruta:

CapNotLast Esto es equivalente a CapButt, excepto que para una anchura de línea de cero, el punto final no se dibuja.
CapButt La línea es cuadrada en el punto final (perpendicular a la pendiente de la línea) sin proyección más allá.
CapRound La línea tiene un arco circular con el diámetro igual a la anchura de línea, centrado en el punto final. (Esto es equivalente a CapButt para una anchura de línea de cero).
CapProjecting La línea es cuadrada en el extremo, pero la ruta continúa más allá del punto final una distancia igual a la mitad de la anchura de línea. (Esto es equivalente a CapButt para una anchura de línea de cero).

El estilo de unión define cómo se dibujan las esquinas para las líneas gruesas:

JoinMiter Los bordes exteriores de dos líneas se extienden para encontrarse en un ángulo. Sin embargo, si el ángulo es inferior a 11 grados, se utiliza en su lugar un estilo de unión JoinBevel.
JoinRound La esquina es un arco circular con el diámetro igual a la anchura de línea, centrado en el punto de unión.
JoinBevel La esquina tiene estilos de punto final CapButt con la muesca triangular rellena.

Para una línea con puntos finales coincidentes (x1=x2, y1=y2), cuando se aplica el estilo de extremo a ambos puntos finales, la semántica depende de la anchura de línea y del estilo de extremo:

CapNotLast delgada Los resultados dependen del dispositivo, pero el efecto deseado es que no se dibuje nada.
CapButt delgada Los resultados dependen del dispositivo, pero el efecto deseado es que se dibuje un solo píxel.
CapRound delgada Los resultados son los mismos que para CapButt /delgada.
CapProjecting delgada Los resultados son los mismos que para CapButt /delgada.
CapButt gruesa No se dibuja nada.
CapRound gruesa La ruta cerrada es un círculo, centrado en el punto final, y con el diámetro igual a la anchura de línea.
CapProjecting gruesa La ruta cerrada es un cuadrado, alineado con los ejes de coordenadas, centrado en el punto final, y con los lados iguales a la anchura de línea.

Para una línea con puntos finales coincidentes (x1=x2, y1=y2), cuando se aplica el estilo de unión en uno o ambos puntos finales, el efecto es como si la línea se hubiera eliminado de la ruta general. Sin embargo, si la ruta total consiste o se reduce a un solo punto unido consigo mismo, el efecto es el mismo que cuando se aplica el estilo de extremo en ambos puntos finales.

La tesela/relleno representa un plano bidimensional infinito, con la tesela/relleno replicada en todas las dimensiones. Cuando ese plano se superpone al drawable para su uso en una operación gráfica, la esquina superior izquierda de alguna instancia de la tesela/relleno se encuentra en las coordenadas dentro del drawable especificadas por el origen de la tesela/relleno. Los orígenes de la tesela/relleno y del recorte se interpretan en relación con el origen del drawable de destino especificado en una solicitud gráfica. El pixmap de tesela debe tener la misma raíz y profundidad que el GC, o se produce un error BadMatch. El pixmap de relleno debe tener profundidad uno y debe tener la misma raíz que el GC, o se produce un error BadMatch. Para operaciones de relleno donde el estilo de relleno es FillStippled pero no FillOpaqueStippled, el patrón de relleno se tesela en un solo plano y actúa como una máscara de recorte adicional que se aplicará mediante AND con la máscara de recorte. Aunque algunos tamaños pueden ser más rápidos de usar que otros, se puede utilizar cualquier tamaño de pixmap para teselar o rellenar.

El estilo de relleno define el contenido del origen para las solicitudes de línea, texto y relleno. Para todas las solicitudes de texto y relleno (por ejemplo, XDrawText, XDrawText16, XFillRectangle, XFillPolygon y XFillArc); para las solicitudes de línea con estilo de línea LineSolid (por ejemplo, XDrawLine, XDrawSegments, XDrawRectangle, XDrawArc); y para los guiones pares para las solicitudes de línea con estilo de línea LineOnOffDash o LineDoubleDash, se aplican las siguientes reglas:

FillSolid Primer plano
FillTiled Tesela
FillOpaqueStippled Una tesela con el mismo ancho y alto que el relleno, pero con fondo dondequiera que el relleno tenga un cero y con primer plano dondequiera que el relleno tenga un uno
FillStippled Primer plano enmascarado por el relleno

NOMBRE

XCopyGC - copiar un GC

SINTAXIS

 XCopyGC(display, source_gc, destination_gc)
      XImage	*display;
      GC	source_gc;
      GC	destination_gc;

ARGUMENTOS

Especifica el display y la ventana donde se va a realizar la operación.
Especifica el GC fuente.
Especifica el GC destino.

DESCRIPCIÓN

La función XCopyGC copia los componentes de un GC a otro. Esto incluye todos los atributos del GC que no estén especificados por el argumento de máscara de valor. Para obtener los valores de los atributos no copiados, se utiliza el valor por defecto del servidor.

Por ejemplo, si la máscara de valor no especifica la línea-estilo, se utiliza el valor por defecto del servidor en lugar del valor del GC fuente.

La función también se puede utilizar para copiar atributos de un GC a otro, incluso si los GCs pertenecen a diferentes pantallas. Sin embargo, los valores de los atributos que no se copian se establecen en los valores por defecto del servidor.

ESTRUCTURAS

Cuando se dibujan líneas con el estilo de línea LineDoubleDash, los guiones impares se controlan con el estilo de relleno de la siguiente manera:

FillSolid Fondo
FillTiled Igual que para los guiones pares
FillOpaqueStippled Igual que para los guiones pares
FillStippled Fondo enmascarado por el stipple

Almacenar un pixmap en un GC puede o no resultar en una copia. Si el pixmap se usa posteriormente como destino para una solicitud gráfica, el cambio puede o no reflejarse en el GC. Si el pixmap se usa simultáneamente en una solicitud gráfica tanto como destino como para mosaico o stipple, los resultados no están definidos.

Para un rendimiento óptimo, debes dibujar tanto como sea posible con el mismo GC (sin cambiar sus componentes). Los costos de cambiar los componentes del GC en comparación con el uso de diferentes GCs dependen del hardware de visualización y de la implementación del servidor. Es muy probable que parte de la información del GC se almacene en caché en el hardware de visualización y que dicho hardware solo pueda almacenar en caché un pequeño número de GCs.

El valor de los guiones es en realidad una forma simplificada de los patrones más generales que se pueden establecer con XSetDashes. Especificar un valor de N es equivalente a especificar la lista de dos elementos [N, N] en XSetDashes. El valor debe ser distinto de cero, o se producirá un error BadValue.

La máscara de recorte restringe las escrituras al drawable de destino. Si la máscara de recorte se establece en un pixmap, debe tener profundidad uno y la misma raíz que el GC, o se producirá un error BadMatch. Si la máscara de recorte se establece en None, los píxeles siempre se dibujan independientemente del origen del recorte. La máscara de recorte también se puede establecer llamando a las funciones XSetClipRectangles o XSetRegion. Solo se dibujan los píxeles donde la máscara de recorte tiene un bit establecido en 1. Los píxeles no se dibujan fuera del área cubierta por la máscara de recorte o donde la máscara de recorte tiene un bit establecido en 0. La máscara de recorte afecta a todas las solicitudes gráficas. La máscara de recorte no recorta las fuentes. El origen de la máscara de recorte se interpreta en relación con el origen de cualquier drawable de destino que se especifique en una solicitud gráfica.

Puedes establecer el modo de subventana a ClipByChildren o IncludeInferiors. Para ClipByChildren, tanto la ventana de origen como la de destino se recortan adicionalmente por todos los hijos visibles de tipo InputOutput. Para IncludeInferiors, ni la ventana de origen ni la de destino se recortan por los inferiores. Esto dará como resultado la inclusión del contenido de la subventana en el origen y el dibujo a través de los límites de la subventana del destino. El uso de IncludeInferiors en una ventana de una profundidad con inferiores mapeados de diferente profundidad no es ilegal, pero el protocolo central no define las semánticas.

La regla de relleno define qué píxeles están dentro (dibujados) para las rutas dadas en las solicitudes XFillPolygon y se puede establecer en EvenOddRule o WindingRule. Para EvenOddRule, un punto está dentro si un rayo infinito con el punto como origen cruza la ruta un número impar de veces. Para WindingRule, un punto está dentro si un rayo infinito con el punto como origen cruza un número desigual de segmentos de ruta dirigidos en sentido horario y antihorario. Un segmento de ruta dirigido en sentido horario es aquel que cruza el rayo de izquierda a derecha según se observa desde el punto. Un segmento antihorario es aquel que cruza el rayo de derecha a izquierda según se observa desde el punto. El caso en que un segmento de línea dirigido es coincidente con el rayo no es interesante porque simplemente puedes elegir un rayo diferente que no sea coincidente con un segmento.

Tanto para EvenOddRule como para WindingRule, un punto es infinitamente pequeño y la ruta es una línea infinitamente delgada. Un píxel está dentro si el punto central del píxel está dentro y el punto central no está en el límite. Si el punto central está en el límite, el píxel está dentro si y solo si el interior del polígono está inmediatamente a su derecha (dirección de incremento x). Los píxeles con centros en un borde horizontal son un caso especial y están dentro si y solo si el interior del polígono está inmediatamente debajo (dirección de incremento y).

El modo de arco controla el relleno en la función XFillArcs y se puede establecer en ArcPieSlice o ArcChord. Para ArcPieSlice, los arcos se rellenan como porción de tarta. Para ArcChord, los arcos se rellenan como cuerda.

El indicador graphics-exposure controla la generación de eventos GraphicsExpose para las solicitudes XCopyArea y XCopyPlane (y cualquier solicitud similar definida por extensiones).

DIAGNÓSTICOS

BadAlloc
El servidor no pudo asignar el recurso o la memoria del servidor solicitados.
BadDrawable
Un valor para un argumento Drawable no nombra una Ventana o Pixmap definida.
BadFont
Un valor para un argumento Font o GContext no nombra una Fuente definida.
BadGC
Un valor para un argumento GContext no nombra un GContext definido.
BadMatch
Se utiliza una ventana InputOnly como Drawable.
BadMatch
Algún argumento o par de argumentos tiene el tipo y rango correctos pero falla en coincidir de alguna otra manera requerida por la solicitud.
BadPixmap
Un valor para un argumento Pixmap no nombra un Pixmap definido.
BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango específico para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
