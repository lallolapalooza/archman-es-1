XWAYLAND(1) Manual de Comandos Generales XWAYLAND(1)

NOMBRE

Xwayland - un servidor X para ejecutar clientes X bajo Wayland.

SINOPSIS

Xwayland [opción ...]

DESCRIPCIÓN

Xwayland es un servidor X y un cliente Wayland. Juega el papel de proxy entre clientes X heredados que no soportan los protocolos Wayland y el servidor Wayland.

Normalmente, Xwayland es iniciado automáticamente por el servidor Wayland y se ejecuta sin privilegios (rootless) para que los clientes X se integren sin problemas con el resto del escritorio Wayland. Sin embargo, es posible que un usuario lance Xwayland con privilegios (rootful), principalmente con fines de prueba.

Como todos los servidores X, Xwayland acepta las opciones de línea de comandos descritas en la página del manual Xserver(7). Los siguientes argumentos adicionales también son compatibles.

-decorate
Añade decoraciones a la ventana raíz de Xwayland cuando se ejecuta con privilegios (rootful).

Esta opción no tiene efecto cuando Xwayland se compila sin soporte de libdecor (opcional).

Esta opción no es compatible con el modo sin privilegios (-rootless).

-enable-ei-portal
Habilita el soporte para el portal XDG para la emulación de entrada.

Un compositor Wayland ejecutándose anidado no debe usar esta opción de línea de comandos con Xwayland.

Esta opción no tiene efecto si el compositor no soporta el portal XDG relevante o si Xwayland no fue compilado con soporte EI y OEFFIS.

-fullscreen
Establece la ventana de Xwayland a pantalla completa cuando se ejecuta con privilegios (rootful).

Esta opción no es compatible con el modo sin privilegios (-rootless).

-geometry AxA
Establece la geometría de la ventana de Xwayland a AxA cuando se ejecuta con privilegios (rootful).

Esta opción no es compatible con el modo sin privilegios (-rootless).

-glamor [gl|es|off]
Utiliza la API de renderizado dada para la aceleración Glamor. Las opciones posibles son gl y es. Si Xwayland fue compilado con soporte Glamor, esta opción instruirá a Xwayland a usar solo la API solicitada para Glamor. Si se establece en off, el efecto es igual a la opción -shm. Sin esta opción y sin la opción -shm, Xwayland intenta primero la API de renderizado OpenGL y recurre a GL ES si la versión de GL es inferior a 2.1.

Esta opción no es compatible con la opción -shm.

-hidpi
Se ajusta a la escala de las salidas cuando se ejecuta con privilegios (rootful) en modo de ventana.

Esta opción no es compatible con el modo sin privilegios (-rootless).

-host-grab
Deshabilita los atajos de teclado del host y confina el puntero cuando se ejecuta con privilegios (rootful).

Esta función se basa en el protocolo para inhibir los atajos de teclado del compositor y en el protocolo para el bloqueo y confinamiento del puntero, y puede no tener efecto si el compositor Wayland en uso no soporta estos protocolos.

Utilice las teclas [CTRL]+[SHIFT] simultáneamente para liberar los dispositivos de teclado y puntero.

Esta opción no es compatible con el modo sin privilegios (-rootless).

-initfd fd
Añade el fd dado como un socket de escucha para la inicialización de clientes X. Esta opción está dirigida a los servidores Wayland que ejecutan Xwayland bajo demanda, para poder iniciar clientes X específicos que necesitan completarse antes de que otros clientes X regulares puedan conectarse a Xwayland, como xrdb.
-listen fd
obsoleto, usar -listenfd en su lugar.
-listenfd fd
Añade el fd dado como un socket de escucha. Esta opción es utilizada por el servidor Wayland para pasar a Xwayland el socket donde se conectan los clientes X.
-noTouchPointerEmulation
Deshabilita la emulación de puntero táctil. Esto permite que el compositor Wayland implemente su propio mecanismo de emulación de puntero para clientes X11 que no soportan entrada táctil.
-force-xrandr-emulation
Forza a que se expongan modos adicionales no nativos cuando el compositor Wayland no soporta el visor de vistas (viewporter).
-nokeymap
Instruye a Xwayland a ignorar el mapa de teclado establecido por el compositor Wayland.

Por defecto, Xwayland (como cualquier cliente Wayland) utiliza el mapa de teclado establecido por el compositor Wayland usando el protocolo Wayland estándar.

Esta opción está pensada para algunos casos de uso específicos donde podría ser deseable permitir que los clientes X11 controlen el mapa de teclado utilizado en Xwayland, ignorando el mapa de teclado especificado por el compositor Wayland. -output nombre Especifica en qué salida se debe colocar la ventana Xwayland a pantalla completa con privilegios (rootful). El nombre debe coincidir con el nombre de una salida Wayland existente (los nombres de salida se pueden encontrar usando wayland-info).

Si no se encuentra ninguna salida coincidente, el compositor Wayland decidirá en qué salida se colocará la ventana Xwayland a pantalla completa con privilegios (rootful).

Esta opción no tiene efecto si Xwayland no se está ejecutando a pantalla completa con privilegios (rootful).

-rootless
Ejecuta Xwayland sin privilegios (rootless), de modo que los clientes X se integren sin problemas con los clientes Wayland en un escritorio Wayland. Esto requiere que el servidor Wayland sea también un gestor de ventanas X.
-shm
Forza el backend de memoria compartida en lugar de glamor (si está disponible) para pasar búferes al servidor Wayland.

Esta opción no es compatible con la opción -glamor.

-verbose [n]
Establece el nivel de verbosidad para la información impresa en stderr. Si el valor n no se proporciona, cada ocurrencia de esta opción incrementa el nivel de verbosidad. Cuando se proporciona el valor n, el nivel de verbosidad se establece a ese valor. El nivel de verbosidad predeterminado es 0.
-version
Muestra la versión del servidor y sale.
-wm fd
Esta opción es utilizada por el servidor Wayland para pasar a Xwayland el socket donde se conecta el cliente gestor de ventanas X, cuando Xwayland se ejecuta con -rootless.

AMBIENTE

WAYLAND_DISPLAY
el nombre de la pantalla del servidor Wayland.
XWAYLAND_NO_GLAMOR
deshabilita el soporte glamor y DRI3 en Xwayland, con fines de prueba.
