display
       Especifica la conexión con el servidor X.
device
       Especifica el dispositivo que va a ser capturado o liberado
button
       Especifica el botón del dispositivo que va a ser capturado o
       liberado o XIAnyButton.
keycode
       Especifica el keycode que va a ser capturado o liberado
       o XIAnyKeycode.
num_modifiers
       Número de elementos en modifiers o modifiers_inout.
modifiers
       Especifica el conjunto de modificadores fijados y base o
       XIAnyModifier para liberar. El tipo de datos es para
       consistencia con la solicitud de captura respectiva y se ignora
       el código de estado de la estructura XIGrabModifiers.
modifiers_inout
       Especifica el conjunto de modificadores fijados y base o
       XIAnyModifier para capturar. Devuelve los modificadores que no
       pudieron ser capturados y su código de error.
grab_window
       Especifica la ventana de captura.
owner_events
       Especifica un valor booleano que indica si los eventos
       deben ser reportados como de costumbre o reportados con respecto a
       la ventana de captura.
mask
       Especifica la máscara de eventos.
grab_mode
       Especifica un procesamiento adicional de eventos de este dispositivo.
       Puedes pasar XIGrabModeSync o XIGrabModeAsync.
paired_device_mode
       Especifica un procesamiento adicional de eventos del dispositivo maestro emparejado.
       Puedes pasar XIGrabModeSync o
       XIGrabModeAsync. Si deviceid especifica un dispositivo esclavo flotante, este
       parámetro se ignora.

DESCRIPCIÓN

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin,
XIGrabSwipeTouchBegin establecen una captura pasiva.
El dispositivo modificador para una captura de botón es el dispositivo maestro emparejado
si deviceid especifica un puntero maestro. De lo contrario, el dispositivo modificador es el
dispositivo especificado con deviceid. En el futuro,
el dispositivo se captura activamente (como para XIGrabDevice, el
tiempo de última captura se establece en el momento en que se
presionó el botón o keycode y el evento XI_ButtonPress o XI_KeyPress se
reporta si se cumplen todas las siguientes condiciones:
  * El dispositivo no está capturado, y el botón o
    keycode especificado está lógicamente presionado, se produce un evento táctil o un gesto
    cuando las teclas modificadoras especificadas están lógicamente abajo en el dispositivo modificador
    y ningún otro botón o tecla modificadora está lógicamente abajo.
  * Ya sea la ventana de captura es un ancestro de (o es) la ventana de foco,
    O la ventana de captura es un descendiente de la ventana de foco
    y contiene el dispositivo.
  * No existe una captura pasiva en el mismo botón/combinación de modificadores
    en ningún ancestro de grab_window.
La interpretación de los argumentos restantes es como para
XIGrabDevice. La captura activa se termina automáticamente cuando
el estado lógico del dispositivo tiene todos los botones o teclas
liberados (independientemente del estado lógico de las teclas modificadoras).
Si el dispositivo es un dispositivo esclavo adjunto, el dispositivo se
desconecta automáticamente del dispositivo maestro cuando la captura se
activa y se vuelve a conectar al mismo dispositivo maestro cuando la captura se
desactiva. Si el dispositivo maestro se elimina mientras el
dispositivo está flotando como resultado de una captura, el dispositivo permanece
flotando una vez que la captura se desactiva.
Tenga en cuenta que el estado lógico de un dispositivo (como lo ven las aplicaciones cliente) puede ir
detrás del estado físico si el procesamiento de eventos del dispositivo está congelado.
Esta solicitud anula todas las capturas anteriores por el mismo cliente en
las mismas combinaciones de botones/modificadores o keycodes/modificadores en la
misma ventana. Un modificador de XIAnyModifier es equivalente a
emitir la solicitud de captura para todas las combinaciones de modificadores posibles
(incluida la combinación de ningún modificador). No es necesario que todos los modificadores especificados tengan
KeyCodes asignados actualmente.
Un botón de XIAnyButton es equivalente a emitir la solicitud para todos los botones posibles.
De lo contrario, no es necesario que el botón especificado esté actualmente asignado a un
botón físico.
Si algún otro cliente ya ha emitido un XIGrabButton o
XIGrabKeycode con la misma combinación de botón/modificador o keycode/modificador
en la misma ventana, se produce un error BadAccess. Al usar XIAnyModifier o XIAnyButton , la solicitud falla
completamente, y se produce un error XIBadAccess (no se establecen capturas) si existe una captura conflictiva para alguna
combinación. XIGrabButton y XIGrabKeycode no tienen ningún efecto en una
captura activa.
En caso de éxito, XIGrabButton, XIGrabKeycode, XIGrabTouchBegin,
XIGrabPinchGestureBegin y XIGrabSwipeGestureBegin devuelven 0;
Si una o más combinaciones de modificadores no pudieron ser capturadas,
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
y XIGrabSwipeGestureBegin devuelven el número de
combinaciones fallidas y modifiers_inout contiene las combinaciones
fallidas y sus respectivos códigos de error.
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
y XIGrabSwipeGestureBegin pueden generar errores BadClass,
BadDevice, BadMatch, BadValue y BadWindow.
XIUngrabButton, XIUngrabKeycode, XIUngrabTouchBegin, XIUngrabPinchGestureBegin
y XIUngrabSwipeGestureBegin liberan la
captura pasiva para una combinación de botón/modificador, keycode/modificador o táctil/modificador
en la ventana especificada si fue capturada por este cliente. Un
modificador de XIAnyModifier es equivalente a emitir la solicitud de liberación
para todas las combinaciones de modificadores posibles, incluida la
combinación de ningún modificador. Un botón de XIAnyButton es
equivalente a emitir la solicitud para todos los botones posibles.
XIUngrabButton y XIUngrabKeycode no tienen ningún efecto en una captura activa.

NAME

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin, XIGrabSwipeGestureBegin - grab button for XI 2.0

SYNOPSIS

#include <X11/extensions/XInput.h>

XIGrabPinchGestureBegin(

int

    int deviceid,

    int num_modifiers,
    XimodifyGrab* modifiers_inout
);

DESCRIPTION

These functions establish a passive grab on the specified device. A passive grab means that the device is grabbed only when a specific set of buttons, keys or gestures are pressed.

When a passive grab is established, the core X11 grab mode may be used or not. If GrabModeSync is used, the grabbing client will receive events about the grabbed device and the client on which the grab was established. If GrabModeAsync is used, the grabbing client will not receive events about the grabbed device and the client on which the grab was established.

XI 2.0 differs from XI 1.x in that the XIGrabButton, XIGrabKeycode, XIGrabTouchBegin and XIGrabPinchGestureBegin and XIGrabSwipeGestureBegin functions do not grab the pointer or keyboard automatically. Instead, they establish a passive grab on the specified device. The passive grab is only active when the specified button, keycode or gesture is pressed. In addition, the specified grab_mode and event_mode is used for the active grab that is created when the button, keycode or gesture is pressed.

The grab_mode argument specifies whether the grab is synchronous or asynchronous. GrabModeSync means that the grabbing client will receive all events from the grabbed device. GrabModeAsync means that the grabbing client will receive only events that are specified by the event_mode argument.

The event_mode argument specifies which events that are being grabbed. If it is set to GrabModeSync, then all events are grabbed. If it is set to GrabModeAsync, then only the events that are specified by the grab_mode argument are grabbed.

The button, keycode or gesture argument specifies the button, keycode or gesture that will trigger the passive grab. The num_modifiers argument specifies the number of modifiers that will be used in the grab. The modifiers_inout argument is a pointer to an array of XimodifyGrab structures that specify the modifiers that will be used in the grab. The XimodifyGrab structure contains the modifier name and the modifier state. The modifier state can be either XIMODIFIER_ANY or XIMODIFIER_EXACT.

If XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin and XIGrabSwipeGestureBegin succeed, they return zero. If they fail, they return a non-zero value indicating the number of modifier combinations that could not establish a passive grab. The modifiers are returned in modifiers_inout, along with the respective error for this modifier combination.

The following errors can be generated by XIGrabButton, XIGrabKeycode, XIUngrabTouchBegin, XIUngrabPinchGestureBegin and XIUngrabSwipeGestureBegin:

BadDevice, BadMatch, BadValue and BadWindow.

RETURN VALUE

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin and
XIGrabPinchGestureBegin and XIGrabSwipeGestureBegin return the number of
modifier combination that could not establish a passive grab. The
modifiers are returned in modifiers_inout, along with the respective
error for this modifier combination. If XIGrabButton, XIGrabKeycode
or XIGrabTouchBegin return zero, passive grabs with all requested
modifier combinations were established successfully.

DIAGNOSTICS

BadDevice
       An invalid deviceid was specified.
BadMatch
       This error may occur if XIGrabButton specified a device
       that has no buttons, or XIGrabKeycode specified a device
       that has no keys,
       or XIGrabTouchBegin specified a device that is not touch-capable,
       or XIGrabPinchGestureBegin specified a device that is not gesture-capable,
       or XIGrabSwipeGestureBegin specified a device that is not gesture-capable.
BadValue
       Some numeric value falls outside the range of values
       accepted by the request. Unless a specific range is
       specified for an argument, the full range defined by the
       argument's type is accepted. Any argument defined as a
       set of alternatives can generate this error.
BadWindow
       A value for a Window argument does not name a defined
       Window.

BUGS

The protocol headers for XI 2.0 did not provide
XIGrabModeAsync or XIGrabModeSync. Use GrabModeSync and
GrabModeAsync instead, respectively.
