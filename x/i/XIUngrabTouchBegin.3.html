display
       Especifica la conexión con el servidor X.
deviceid
       Especifica el dispositivo que será capturado o liberado
button
       Especifica el botón del dispositivo que será capturado o

keycode
       Especifica la clave que será capturada o liberada
       o XIAnyKeycode.
num_modifiers
       Número de elementos en modifiers o modifiers_inout.
modifiers
       Especifica el conjunto de modificadores latched y base o
       XIAnyModifier para liberar. El tipo de datos es para
       consistencia con la solicitud de captura respectiva y se
       ignora el código de estado de la estructura XIGrabModifiers.
modifiers_inout
       Especifica el conjunto de modificadores latched y base o
       XIAnyModifier para capturar. Devuelve los modificadores que
       no se pudieron capturar y su código de error.
grab_window
       Especifica la ventana de captura.
owner_events
       Especifica un valor booleano que indica si los eventos
       deben ser reportados como de costumbre o reportados con
       respecto a la ventana de captura.
mask
       Especifica la máscara de eventos.
grab_mode
       Especifica el procesamiento adicional de eventos de este
       dispositivo. Se puede pasar XIGrabModeSync o
       XIGrabModeAsync.
paired_device_mode
       Especifica el procesamiento adicional de eventos del
       dispositivo maestro emparejado. Se puede pasar
       XIGrabModeSync o XIGrabModeAsync. Si deviceid especifica un
       dispositivo esclavo flotante, este parámetro se ignora.

DESCRIPCIÓN

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin,
XIGrabSwipeTouchBegin establecen una captura pasiva.
El dispositivo modificador para una captura de botón es el
dispositivo maestro emparejado si deviceid especifica un puntero
maestro. De lo contrario, el dispositivo modificador es el
dispositivo especificado con deviceid. En el futuro,
el dispositivo se captura activamente (como para XIGrabDevice, el
último tiempo de captura se establece en el momento en que se
presionó el botón o la clave y el evento XI_ButtonPress o
XI_KeyPress se reporta si se cumplen todas las siguientes
condiciones:
  * El dispositivo no está capturado, y el botón o clave
    especificado está lógicamente presionado, ocurre un evento táctil o de
    gesto cuando las claves modificadoras especificadas están
    lógicamente presionadas en el dispositivo modificador
    y ningún otro botón o clave modificadora está lógicamente
    presionado.
  * La ventana de captura es un ancestro (o es) la ventana de
    enfoque, O la ventana de captura es un descendiente de la
    ventana de enfoque y contiene el dispositivo.
  * No existe una captura pasiva en el mismo botón/combinación
    modificadora en ningún ancestro de grab_window.
La interpretación de los argumentos restantes es la misma que
para XIGrabDevice. La captura activa se termina
automáticamente cuando el estado lógico del dispositivo tiene
todos los botones o teclas liberados (independientemente del
estado lógico de las teclas modificadoras).
Si el dispositivo es un dispositivo esclavo adjunto, el dispositivo
se desvincula automáticamente del dispositivo maestro cuando la
captura se activa y se vuelve a vincular al mismo dispositivo
maestro cuando la captura se desactiva. Si el dispositivo maestro se
elimina mientras el dispositivo está flotando como resultado de
una captura, el dispositivo permanece flotante una vez que la
captura se desactiva.
Tenga en cuenta que el estado lógico de un dispositivo (visto por
las aplicaciones cliente) puede ir a la zaga del estado físico si el
procesamiento de eventos del dispositivo está congelado.
Esta solicitud anula todas las capturas anteriores por el mismo
cliente en las mismas combinaciones de botones/modificadores o
claves/modificadores en la misma ventana. Un modificador de
XIAnyModifier es equivalente a emitir la solicitud de captura para
todas las combinaciones de modificadores posibles (incluida la
combinación de ningún modificador). No es necesario que todos los
modificadores especificados tengan actualmente códigos de tecla
asignados. Un botón de XIAnyButton es equivalente a emitir la
solicitud para todos los botones posibles. De lo contrario, no es
necesario que el botón especificado esté asignado actualmente a
un botón físico.
Si algún otro cliente ya ha emitido un XIGrabButton o
XIGrabKeycode con la misma combinación de botón/modificador o
clave/modificador en la misma ventana, se produce un error
BadAccess. Al usar XIAnyModifier o XIAnyButton, la solicitud falla
completamente y se produce un error XIBadAccess (no se establecen
capturas) si existe una captura conflictiva para alguna
combinación. XIGrabButton y XIGrabKeycode no tienen efecto sobre una
captura activa.
En caso de éxito, XIGrabButton, XIGrabKeycode, XIGrabTouchBegin,
XIGrabPinchGestureBegin y XIGrabSwipeGestureBegin devuelven 0;
Si una o más combinaciones de modificadores no se pudieron
capturar, XIGrabButton, XIGrabKeycode, XIGrabTouchBegin,
XIGrabPinchGestureBegin y XIGrabSwipeGestureBegin devuelven el
número de combinaciones fallidas y modifiers_inout contiene las
combinaciones fallidas y sus respectivos códigos de error.
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
y XIGrabSwipeGestureBegin pueden generar errores BadClass,
BadDevice, BadMatch, BadValue y BadWindow.
XIUngrabButton, XIUngrabKeycode, XIUngrabTouchBegin, XIUngrabPinchGestureBegin
y XIUngrabSwipeGestureBegin liberan la
captura pasiva para una combinación de botón/modificador,
clave/modificador o táctil/modificador en la ventana especificada si
fue capturada por este cliente. Un modificador de XIAnyModifier
es equivalente a emitir la solicitud de liberación para todas las
combinaciones de modificadores posibles, incluida la
combinación de ningún modificador. Un botón de XIAnyButton es
equivalente a emitir la solicitud para todos los botones
posibles. XIUngrabButton y XIUngrabKeycode no tienen efecto sobre una
captura activa.
XIUngrabButton, XIUngra

DESCRIPTION

The XInput extension allows clients to grab devices. A grab is an operation
where a client gains exclusive access to a device. Only one client can have a
device grabbed at any time.

The functions XIGrabButton, XIGrabKeycode, XIGrabTouchBegin,
XIGrabPinchGestureBegin and XIGrabSwipeGestureBegin establish a passive grab
on the specified device. A passive grab is a grab that is triggered when a
specific button/keycode/gesture combination is pressed/activated. The grab
is active as long as the button/keycode/gesture combination is held down.

The grab_window is the window on which the passive grab is placed. If the
grab_window is None, the grab is placed on the root window of the screen.

The grab_mode parameter determines whether further pointer events
generated by this device are reported to other clients (GrabModeSync) or
all further events are discarded (GrabModeAsync).

The owner_events parameter determines whether events should be reported
to the client that owns thecurrently active grab (if any) or to the client
that established the passive grab.

The event_mask specifies which XI events should be sent to the client that
established the passive grab.

The modifiers_inout parameter is a pointer to an XIGrabModifiers structure
that specifies the modifier combination for the passive grab. If the grab is
established successfully, this structure is updated to reflect the actual
modifiers. If the grab could not be established for any modifier combination,
the function returns the number of failed modifier combinations, and
modifiers_inout is updated to reflect the modifier combination that could
not be grabbed.

The XIUngrabTouchBegin, XIUngrabPinchGestureBegin and XIUngrabSwipeGestureBegin
functions remove a passive grab established by XIGrabTouchBegin,
XIGrabPinchGestureBegin or XIGrabSwipeGestureBegin respectively. The
motion_buffer is an XIEvent structure that contains the event that triggered
the grab. If motion_buffer is NULL, all passive grabs are removed.

Note that XIUngrabTouchBegin, XIUngrabPinchGestureBegin and
XIUngrabSwipeGestureBegin can generate BadDevice, BadMatch, BadValue and
BadWindow errors.

RETURN VALUE

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin and
XIGrabPinchGestureBegin and XIGrabSwipeGestureBegin return the number of
modifier combination that could not establish a passive grab. The
modifiers are returned in modifiers_inout, along with the respective
error for this modifier combination. If XIGrabButton, XIGrabKeycode
or XIGrabTouchBegin return zero, passive grabs with all requested
modifier combinations were established successfully.

DIAGNOSTICS

BadDevice
       An invalid deviceid was specified.
BadMatch
       This error may occur if XIGrabButton specified a device
       that has no buttons, or XIGrabKeycode specified a device
       that has no keys,
       or XIGrabTouchBegin specified a device that is not touch-capable,
       or XIGrabPinchGestureBegin specified a device that is not gesture-capable,
       or XIGrabSwipeGestureBegin specified a device that is not gesture-capable.
BadValue
       Some numeric value falls outside the range of values
       accepted by the request. Unless a specific range is
       specified for an argument, the full range defined by the
       argument's type is accepted. Any argument defined as a
       set of alternatives can generate this error.
BadWindow
       A value for a Window argument does not name a defined
       Window.

BUGS

The protocol headers for XI 2.0 did not provide
XIGrabModeAsync or XIGrabModeSync. Use GrabModeSync and
GrabModeAsync instead, respectively.
