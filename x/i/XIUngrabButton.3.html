display
       Especifica la conexión con el servidor X.
device
       Especifica el dispositivo que se va a capturar o liberar.
button
       Especifica el botón del dispositivo que se va a capturar o
       liberar, o XIAnyButton.
keycode
       Especifica la tecla que se va a capturar o liberar
       o XIAnyKeycode.
num_modifiers
       Número de elementos en modifiers o modifiers_inout.
modifiers
       Especifica el conjunto de modificadores base y activados, o
       XIAnyModifier para liberar. El tipo de datos es para consistencia
       con la solicitud de captura respectiva y se ignora el código de
       estado de la estructura XIGrabModifiers.
modifiers_inout
       Especifica el conjunto de modificadores base y activados, o
       XIAnyModifier para capturar. Devuelve los modificadores que no se
       pudieron capturar y su código de error.
grab_window
       Especifica la ventana de captura.
owner_events
       Especifica un valor booleano que indica si los eventos se
       informarán como de costumbre o se informarán con respecto a la
       ventana de captura.
mask
       Especifica la máscara de eventos.
grab_mode
       Especifica el procesamiento adicional de eventos de este dispositivo.
       Puedes pasar XIGrabModeSync o XIGrabModeAsync.
paired_device_mode
       Especifica el procesamiento adicional de eventos del dispositivo maestro emparejado.
       Puedes pasar XIGrabModeSync o XIGrabModeAsync. Si deviceid especifica
       un dispositivo esclavo flotante, este parámetro se ignora.

DESCRIPCIÓN

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin,
XIGrabSwipeTouchBegin establecen una captura pasiva.
El dispositivo modificador para una captura de botón es el dispositivo maestro
emparejado si deviceid especifica un puntero maestro. De lo contrario, el
dispositivo modificador es el dispositivo especificado con deviceid. En el futuro,
el dispositivo se captura activamente (como para XIGrabDevice, la
hora de la última captura se establece en la hora en que se presionó el
botón o la tecla, y el evento XI_ButtonPress o XI_KeyPress se informa si se cumplen
todas las siguientes condiciones:
  * El dispositivo no está capturado, y el botón o tecla especificado
    está lógicamente presionado, ocurre un evento táctil o de gesto
    cuando las teclas modificadoras especificadas están lógicamente presionadas
    en el dispositivo modificador y ningún otro botón o tecla modificadora
    está lógicamente presionado.
  * Ya sea que la ventana de captura sea un ancestro de (o sea) la ventana de foco,
    O la ventana de captura sea un descendiente de la ventana de foco y contenga
    el dispositivo.
  * No existe una captura pasiva en el mismo botón/combinación de modificadores
    en ningún ancestro de grab_window.
La interpretación de los argumentos restantes es la misma que para
XIGrabDevice. La captura activa se termina automáticamente cuando
el estado lógico del dispositivo tiene todos los botones o teclas
liberados (independientemente del estado lógico de las teclas
modificadoras).
Si el dispositivo es un dispositivo esclavo adjunto, el dispositivo se
desconecta automáticamente del dispositivo maestro cuando la captura
se activa y se vuelve a conectar al mismo dispositivo maestro cuando la
captura se desactiva. Si se elimina el dispositivo maestro mientras el
dispositivo está flotando como resultado de una captura, el dispositivo
permanece flotante una vez que la captura se desactiva.
Tenga en cuenta que el estado lógico de un dispositivo (visto por las
aplicaciones cliente) puede retrasarse respecto al estado físico si el
procesamiento de eventos del dispositivo está congelado.
Esta solicitud anula todas las capturas anteriores del mismo cliente en
las mismas combinaciones de botón/modificador o tecla/modificador en la
misma ventana. Un modificador de XIAnyModifier es equivalente a emitir
la solicitud de captura para todas las combinaciones de modificadores
posibles (incluida la combinación de ningún modificador). No es necesario
que todos los modificadores especificados tengan actualmente códigos de tecla
asignados. Un botón de XIAnyButton es equivalente a emitir la solicitud
para todos los botones posibles. De lo contrario, no es necesario que el
botón especificado esté actualmente asignado a un botón físico.
Si algún otro cliente ya ha emitido un XIGrabButton o
XIGrabKeycode con la misma combinación de botón/modificador o
tecla/modificador en la misma ventana, se produce un error BadAccess.
Al usar XIAnyModifier o XIAnyButton, la solicitud falla
completamente y se produce un error XIBadAccess (no se establecen
capturas) si existe una captura conflictiva para alguna
combinación. XIGrabButton y XIGrabKeycode no tienen efecto sobre una
captura activa.
En caso de éxito, XIGrabButton, XIGrabKeycode, XIGrabTouchBegin,
XIGrabPinchGestureBegin y XIGrabSwipeGestureBegin devuelven 0;
Si una o más combinaciones de modificadores no se pudieron capturar,
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
y XIGrabSwipeGestureBegin devuelven el número de
combinaciones fallidas y modifiers_inout contiene las combinaciones
fallidas y sus respectivos códigos de error.
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
y XIGrabSwipeGestureBegin pueden generar errores BadClass,
BadDevice, BadMatch, BadValue y BadWindow.
XIUngrabButton, XIUngrabKeycode, XIUngrabTouchBegin, XIUngrabPinchGestureBegin
y XIUngrabSwipeGestureBegin liberan la
captura pasiva para una combinación de botón/modificador, tecla/modificador
o toque/modificador en la ventana especificada si fue capturada por este
cliente. Un modificador de XIAnyModifier es equivalente a emitir la
solicitud de liberación para todas las combinaciones de modificadores
posibles, incluida la combinación de ningún modificador. Un botón de XIAnyButton
es equivalente a emitir la solicitud para todos los botones posibles.
XIUngrabButton y XIUngrabKeycode no tienen efecto sobre una captura
activa.
XIUngrabButton, XIUngrabKey

NAME

XIUngrabButton, XIUngrabKeycode, XIUngrabTouchBegin, XIUngrabPinchGestureBegin,
XIUngrabSwipeGestureBegin - ungrab input devices

SYNOPSIS

 Status XIUngrabButton(Display *display,
        int deviceid,
        Windowgrab_window,
        unsigned int modifiers);
 Status XIUngrabKeycode(Display *display,
        int deviceid,
        Windowgrab_window,
        unsigned int modifiers);
 Status XIUngrabTouchBegin(Display *display,
        int deviceid,
        Windowgrab_window);
 Status XIUngrabPinchGestureBegin(Display *display,
        int deviceid,
        Windowgrab_window);
 Status XIUngrabSwipeGestureBegin(Display *display,
        int deviceid,
        Windowgrab_window);

DESCRIPTION

These functions ungrab the specified input device. Only the grab specified by the given window and modifier combination can be removed. If no specific grab is defined for the window and modifiers, this function has no effect.

The grab_window argument specifies the window on which the grab was established. The modifiers argument is a bitmask of the modifiers that were used to establish the grab.

The XIUngrabButton function ungrabs the specified button on the specified device. The XIUngrabKeycode function ungrabs the specified keycode on the specified device.

The XIUngrabTouchBegin, XIUngrabPinchGestureBegin and XIUngrabSwipeGestureBegin functions ungrab the beginning of a touch, pinch gesture, or swipe gesture, respectively.

All of these functions can generate the following errors:

BadDevice
       An invalid deviceid was specified.
BadMatch
       This error may occur if XIUngrabButton specified a device
       that has no buttons, or XIUngrabKeycode specified a device
       that has no keys,
       or XIUngrabTouchBegin specified a device that is not touch-capable,
       or XIUngrabPinchGestureBegin specified a device that is not gesture-capable,
       or XIUngrabSwipeGestureBegin specified a device that is not gesture-capable.
BadValue
       Some numeric value falls outside the range of values
       accepted by the request. Unless a specific range is
       specified for an argument, the full range defined by the
       argument's type is accepted. Any argument defined as a
       set of alternatives can generate this error.
BadWindow
       A value for a Window argument does not name a defined
       Window.
XIUngrabButton, XIUngrabKeycode, XIUngrabTouchBegin and XIUngrabPinchGestureBegin
and XIUngrabSwipeGestureBegin can generate
BadDevice, BadMatch, BadValue and BadWindow errors.

RETURN VALUE

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin and
XIGrabPinchGestureBegin and XIGrabSwipeGestureBegin return the number of
modifier combination that could not establish a passive grab. The
modifiers are returned in modifiers_inout, along with the respective
error for this modifier combination. If XIGrabButton, XIGrabKeycode
or XIGrabTouchBegin return zero, passive grabs with all requested
modifier combinations were established successfully.

DIAGNOSTICS

BadDevice

BadMatch

       that has no keys,
       or XIGrabTouchBegin specified a device that is not touch-capable,
       or XIGrabPinchGestureBegin specified a device that is not gesture-capable,
       or XIGrabSwipeGestureBegin specified a device that is not gesture-capable.
BadValue
       Some numeric value falls outside the range of values
       accepted by the request. Unless a specific range is
       specified for an argument, the full range defined by the
       argument's type is accepted. Any argument defined as a
       set of alternatives can generate this error.
BadWindow

       Window.

BUGS

The protocol headers for XI 2.0 did not provide
XIGrabModeAsync or XIGrabModeSync. Use GrabModeSync and
GrabModeAsync instead, respectively.
