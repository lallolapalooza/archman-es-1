NOMBRE

XIAllowEvents - Liberar eventos en cola

SINOPSIS

#include <X11/extensions/XInput2.h>
Status XIAllowEvents( Display *display,
                      int deviceid,
                      int event_mode,
                      Time time );
Status XIAllowTouchEvents( Display *dpy,
                           int deviceid,
                           unsigned int touchid,
                           Window grab_window,
                           int event_mode );
display
        Especifica la conexión con el servidor X.
device
        Especifica el dispositivo que se va a capturar o liberar
event_mode
        Especifica si un dispositivo va a descongelarse y los eventos se van a
        reproducir, o cómo manejar una secuencia de toque capturada.
time
        Un tiempo de servidor válido o CurrentTime.
touchid
        El ID de la secuencia de toque a aceptar o rechazar. El valor se ignora
        para modos de evento distintos de AcceptTouch y RejectTouch.
grab_window
        La ventana en la que aceptar o rechazar una captura de secuencia de toque. El valor se ignora
        para modos de evento distintos de AcceptTouch y RejectTouch.

DESCRIPCIÓN

La solicitud XIAllowEvents libera algunos eventos en cola si el cliente
ha provocado que un dispositivo se congele. También se utiliza para manejar
el procesamiento de capturas y propiedad de toques.
La función no tiene efecto si el tiempo especificado es anterior a la hora de
la última captura del período de captura activo más reciente para el cliente, o
si el tiempo especificado es posterior a la hora actual del servidor X. El
parámetro time debe ser CurrentTime para solicitudes con modos de evento
XIAcceptTouch y XIRejectTouch.
Lo siguiente describe el procesamiento que ocurre dependiendo de la constante
que pases al argumento event_mode:
XIAsyncDevice:
    Si el dispositivo especificado está congelado por el cliente, el procesamiento
    de eventos para ese dispositivo continúa como de costumbre. Si el dispositivo
    está congelado varias veces por el cliente en nombre de múltiples capturas
    separadas, XIAsyncDevice se descongelará para todas. XIAsyncDevice no tiene
    efecto si el dispositivo especificado no está congelado por el cliente, pero
    el dispositivo no necesita ser capturado por el cliente.
XISyncDevice:
    Si el dispositivo especificado está congelado y capturado activamente por el
    cliente, el procesamiento de eventos para ese dispositivo continúa normalmente
    hasta la próxima pulsación o liberación de botón, o pulsación o liberación de
    tecla, o un evento de inicio o fin de gesto (dependiendo de la captura) se
    reporta al cliente.
    En ese momento, el dispositivo especificado vuelve a parecer congelado.
    Sin embargo, si el evento reportado provoca que se libere la captura, el
    dispositivo especificado no se congela.
    XISyncDevice no tiene efecto si el dispositivo especificado no está congelado por el
    cliente o si no está capturado por el cliente.
XIReplayDevice:
    Si el dispositivo especificado está capturado activamente por el cliente y
    está congelado como resultado de que se envió un evento al cliente (ya sea desde
    la activación de un XIGrabButton o desde un XIAllowEvents anterior con
    modo SyncDevice, pero no desde un Grab), se libera la captura y
    ese evento se reprocesa completamente. Esta vez, sin embargo, la solicitud
    ignora cualquier captura pasiva en o por encima (hacia la raíz) de la
    ventana de captura de la captura recién liberada.
    La solicitud no tiene efecto si el dispositivo especificado no está capturado por el
    cliente o si no está congelado como resultado de un evento.
    En caso de que se reproduzca un evento de inicio de gesto, el cliente que
    capturó originalmente recibirá un evento XI_GesturePinchEnd o XI_GestureSwipeEnd.
XIAsyncPairedDevice:
    Si el dispositivo maestro emparejado está congelado por el cliente, el
    procesamiento de eventos para él continúa como de costumbre. Si el dispositivo
    emparejado está congelado varias veces por el cliente en nombre de múltiples
    capturas separadas, XIAsyncPairedDevice se descongelará para todas.
    XIAsyncPairedDevice no tiene efecto si el dispositivo no está congelado por el
    cliente, pero esos dispositivos no necesitan ser capturados por el cliente.
    XIAsyncPairedDevice no tiene efecto si deviceid especifica un dispositivo esclavo.
XISyncPair:
    Si tanto el dispositivo como el dispositivo maestro emparejado están congelados
    por el cliente, el procesamiento de eventos (para ambos dispositivos) continúa
    normalmente hasta el próximo evento XI_ButtonPress, XI_ButtonRelease, XI_KeyPress,
    o XI_KeyRelease se reporta al cliente para un dispositivo capturado (evento de
    botón para un puntero, evento de tecla para un teclado), momento en el cual los
    dispositivos vuelven a parecer congelados. Sin embargo, si el evento reportado
    provoca que se libere la captura, entonces los dispositivos no se congelan (pero
    si el otro dispositivo todavía está capturado, entonces un evento posterior para
    él todavía hará que ambos dispositivos se congelen).
    XISyncPair no tiene efecto a menos que tanto el dispositivo como el dispositivo maestro
    emparejado estén congelados por el cliente. Si el dispositivo o el dispositivo maestro
    emparejado está congelado dos veces por el cliente en nombre de dos capturas
    separadas, XISyncPair se descongelará para ambos (pero una congelación posterior
    para XISyncPair solo congelará cada dispositivo una vez).
    XISyncPair no tiene efecto si deviceid especifica un dispositivo esclavo.
XIAsyncPair:
    Si el dispositivo y el dispositivo maestro emparejado están congelados por el
    cliente, el procesamiento de eventos para ambos dispositivos continúa
    normalmente. Si un dispositivo está congelado dos veces por el cliente en
    nombre de dos capturas separadas, AsyncBoth se descongelará para ambos.
    XIAsyncPair no tiene efecto a menos que tanto el dispositivo como el dispositivo maestro
    emparejado estén congelados por el cliente.
    XIAsyncPair no tiene efecto si deviceid especifica un dispositivo esclavo.
XIAcceptTouch:
    Se considera que el cliente ha tomado el control de la secuencia de toque una vez que
    posee la secuencia. Los eventos TouchEnd se enviarán a todos los clientes que escuchen
    la secuencia de toque y que hayan capturado la secuencia de toque en una ventana hija
    de grab_window o que hayan recibido eventos para la secuencia de toque a través de
    la selección de eventos. Estos clientes ya no recibirán ningún evento TouchUpdate.
XIRejectTouch:
    El cliente ya no está interesado en la secuencia de toque y recibirá un evento XI_TouchEnd.
    Si el cliente es el propietario actual de la secuencia, la propiedad se transferirá al siguiente oyente.

DIAGNÓSTICOS

BadDevice
        Se especificó un deviceid inválido.
BadAccess
        Este error puede ocurrir si event_mode es XIAcceptTouch y este cliente
        no es el propietario actual o potencial del touch ID especificado.
BadValue
        Este error puede ocurrir si event_mode es XIAcceptTouch y el touch ID es inválido.
BadWindow
        Un valor para un argumento grab_window no nombra una Ventana
        definida.
