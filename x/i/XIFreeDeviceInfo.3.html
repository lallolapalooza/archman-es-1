XIQUERYDEVICE(3)   XIQUERYDEVICE(3)

NOMBRE

XIQueryDevice, XIFreeDeviceInfo - obtener información sobre dispositivos.

SINOPSIS

#include <X11/extensions/XInput2.h>
XIDeviceInfo* XIQueryDevice( Display *display,
                             int deviceid,
                             int *ndevices_return);
XIFreeDeviceInfo( XIDeviceInfo *info);
deviceid
       Especifica el dispositivo a consultar o XIAllDevices o
       XIAllMasterDevices.
display
       Especifica la conexión con el servidor X.
ndevices_return
       Devuelve el número de dispositivos devueltos.
info
       Una lista de estructuras XIDeviceInfo de dispositivos a liberar.

DESCRIPCIÓN

XIQueryDevice devuelve información sobre uno o más dispositivos de entrada.
Si deviceid especifica un dispositivo, ndevices_return es 1 y la información
devuelta describe solo el dispositivo solicitado. Si deviceid es XIAllDevices
o XIAllMasterDevices, ndevices_return es el número de dispositivos o dispositivos
maestros, respectivamente, y la información devuelta representa todos los
dispositivos o todos los dispositivos maestros, respectivamente.
Para liberar la matriz XIDeviceInfo devuelta por XIQueryDevice, use
XIFreeDeviceInfo.
Para cada dispositivo de entrada solicitado, XIQueryDevice devuelve una
estructura XIDeviceInfo. Cada estructura contiene información sobre las
capacidades de un dispositivo de entrada disponible para el servidor.
typedef struct
{
    int                 deviceid;
    char                *name;
    int                 use;
    int                 attachment;
    Bool                enabled;
    int                 num_classes;
    XIAnyClassInfo      **classes;
} XIDeviceInfo;
deviceid es el ID numérico único del dispositivo. Un deviceid es único
durante la vida útil de un dispositivo, pero un servidor puede reutilizar
el ID una vez que un dispositivo ha sido eliminado.
name apunta a una cadena terminada en nulo que especifica el
identificador del dispositivo.
Los campos use y attachment especifican el tipo de dispositivo y la
conexión o emparejamiento actual.
- Si use es XIMasterPointer, el dispositivo es un puntero maestro y
  attachment especifica el deviceid del teclado maestro emparejado.
- Si use es XIMasterKeyboard, el dispositivo es un teclado maestro,
  y el campo attachment especifica el puntero maestro emparejado.
- Si use es XISlavePointer, el dispositivo es un dispositivo esclavo y
  actualmente adjunto al puntero maestro especificado en
  attachment.
- Si use es XISlaveKeyboard, el dispositivo es un dispositivo esclavo y
  actualmente adjunto al teclado maestro especificado en
  attachment.
- Si use es XIFloatingSlave, el dispositivo es un dispositivo esclavo
  actualmente no adjunto a ningún dispositivo maestro. El valor del
  campo attachment para dispositivos esclavos flotantes no está definido.
El campo enabled especifica si el dispositivo está actualmente habilitado
y puede enviar eventos. Los dispositivos deshabilitados no enviarán eventos.
El campo num_classes especifica el número de clases de entrada
apuntadas por classes. Los dos primeros campos de todas las clases de
entrada son idénticos.
typedef struct
{
    int         type;
    int         sourceid;
} XIAnyClassInfo;
El campo type especifica el tipo de clase de entrada.
Actualmente, los siguientes tipos están definidos:
    XIKeyClass, XIButtonClass, XIValuatorClass, XIScrollClass,
    XITouchClass, XIGestureClass.
En el futuro, se pueden agregar tipos adicionales. Se requiere que los
clientes ignoren las clases de entrada desconocidas.
sourceid es el deviceid del que se originó esta clase. Para
dispositivos maestros, el sourceid es típicamente el ID del
dispositivo esclavo que envía eventos actualmente. Para dispositivos
esclavos, el sourceid es típicamente el ID del dispositivo.
Un dispositivo puede tener cero o una XIButtonClass, lo que denota
la capacidad del dispositivo para enviar eventos de botón.
typedef struct {
    int           mask_len;
    unsigned char *mask;
} XIButtonState;
typedef struct
{
    int         type;
    int         sourceid;
    int         num_buttons;
    Atom        *labels;
    XIButtonState state;
} XIButtonClassInfo;
El campo num_buttons especifica el número de botones disponibles
en este dispositivo. Un dispositivo que tiene una XIButtonClass debe tener
al menos un botón.
labels es una lista de átomos num_buttons que especifican las
etiquetas de los botones para este dispositivo. Si la etiqueta no es None,
entonces la etiqueta especifica el tipo de botón en orden físico del
dispositivo (es decir, según los botones están numerados en el dispositivo
de entrada físico).
state es el estado actual del botón visto por los clientes (es decir,
después de aplicar el mapeo de botones). El campo mask_len especifica
la longitud de la máscara en bytes. Para cada botón del dispositivo, el
bit respectivo en mask está establecido si el botón está lógicamente
presionado actualmente.
Un dispositivo puede tener cero o una XIKeyClass, lo que denota la
capacidad del dispositivo para enviar eventos de tecla.
typedef struct
{
    int         type;
    int         sourceid;
    int         num_keycodes;
    int         *keycodes;
} XIKeyClassInfo;
El campo num_keycodes especifica el número de códigos de tecla
disponibles en este dispositivo. Un dispositivo que tiene una XIKeyClass debe
tener al menos un código de tecla.
keycodes es una lista de num_keycodes códigos de tecla que el
dispositivo puede enviar.
Un dispositivo puede tener cero o más XIValuatorClass, lo que denota
la capacidad del dispositivo para enviar coordenadas.
typedef struct
{
    int         type;
    int         sourceid;
    int         number;
    Atom        label;
    double      min;
    double      max;
    double      value;
    int         resolution;
    int         mode;
} XIValuatorClassInfo;
El campo number especifica el número del eje en el dispositivo
físico.
Si el campo label no es None, el valor de label es un Átomo que
describe el eje.
min y max son los valores mínimo y máximo permitidos en este
eje. Si ambos son cero, no hay valores mínimos o máximos establecidos en
este dispositivo. value es el valor actual de este eje.
El campo resolution especifica la resolución del dispositivo en
unidades/m.
El campo mode especifica el modo de este eje. Si el modo es
XIModeAbsolute, este eje envía coordenadas absolutas. Si el
modo es XIModeRelative, este dispositivo envía coordenadas relativas.
typedef struct
{
    int         type;
    int         sourceid;
    int         number;
    int         scroll_type;
    double      increment;
    int         flags;
} XIScrollClassInfo;
Esta clase describe la capacidad de desplazamiento en un
valuator. Para cada XIScrollClassInfo, está presente en el dispositivo
una XIValuatorClassInfo con el mismo número.
El campo number especifica el número del valuator en el dispositivo
físico al que se aplica esta información de desplazamiento. Consulte la
XIValuatorClassInfo correspondiente para obtener información detallada sobre
este valuator.
El campo scroll_type especifica el tipo de desplazamiento, ya sea
XIScrollTypeVertical o XIScrollTypeHorizontal.
increment especifica el cambio de valor considerado como una unidad
de desplazamiento hacia abajo.
El campo flags especifica indicadores que se aplican a esta
información de desplazamiento:
Si XIScrollFlagNoEmulation está establecido, el servidor no
emulará eventos de botón heredados para cambios de valuator en este
valuator.
Si XIScrollFlagPreferred está establecido, este eje es el
eje preferido para este tipo de desplazamiento y se utilizará para la
emulación de eventos XI_Motion cuando el controlador envíe eventos de botón
de desplazamiento heredados.
typedef struct
{
    int         type;
    int         sourceid;
    int         mode;
    int         num_touches;
} XITouchClassInfo;
Un dispositivo puede tener cero o una XITouchClassInfo, lo que
denota capacidad multitáctil en el dispositivo. Un dispositivo con una
XITouchClassInfo puede enviar eventos TouchBegin, TouchUpdate, TouchEnd y
TouchOwnership.
El campo mode es XIDirectTouch para dispositivos táctiles de entrada
directa como pantallas táctiles, o XIDependentTouch para dispositivos de
entrada indirecta como touchpads. Para dispositivos XIDirectTouch, los eventos
táctiles se envían a la ventana en la posición en que ocurrió el toque. Para
dispositivos XIDependentTouch, los eventos táctiles se envían a la ventana
en la posición del sprite del dispositivo.
