display
       Especifica la conexión con el servidor X.
device
       Especifica el dispositivo que va a ser capturado o liberado
button
       Especifica el botón del dispositivo que va a ser capturado o
       liberado o XIAnyButton.
keycode
       Especifica el keycode que va a ser capturado o liberado
       o XIAnyKeycode.
num_modifiers
       Número de elementos en modifiers o modifiers_inout.
modifiers
       Especifica el conjunto de modificadores fijados y base o
       XIAnyModifier para liberar. El tipo de datos es por
       consistencia con la solicitud de captura respectiva y el
       código de estado de la estructura XIGrabModifiers se ignora.
modifiers_inout
       Especifica el conjunto de modificadores fijados y base o
       XIAnyModifier para capturar. Devuelve los modificadores que no se
       pudieron capturar y su código de error.
grab_window
       Especifica la ventana de captura.
owner_events
       Especifica un valor booleano que indica si los eventos
       se van a reportar como de costumbre o se van a reportar con
       respecto a la ventana de captura.
mask
       Especifica la máscara de eventos.
grab_mode
       Especifica el procesamiento adicional de eventos de este
       dispositivo. Puedes pasar XIGrabModeSync o XIGrabModeAsync.
paired_device_mode
       Especifica el procesamiento adicional de eventos del
       dispositivo maestro emparejado. Puedes pasar
       XIGrabModeSync o XIGrabModeAsync. Si deviceid especifica
       un dispositivo esclavo flotante, este parámetro se ignora.

DESCRIPCIÓN

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin,
XIGrabSwipeTouchBegin establecen una captura pasiva.
El dispositivo modificador para una captura de botón es el dispositivo
maestro emparejado si deviceid especifica un puntero maestro. De lo
contrario, el dispositivo modificador es el dispositivo especificado
con deviceid. En el futuro, el dispositivo se captura activamente (como
para XIGrabDevice, la última hora de captura se establece en la hora en
que se presionó el botón o keycode y el evento XI_ButtonPress o
XI_KeyPress se informa si todas las siguientes condiciones son verdaderas:
  * El dispositivo no está capturado, y el botón o keycode especificado
    está lógicamente presionado, se produce un evento táctil o de gesto
    cuando las teclas modificadoras especificadas están lógicamente
    presionadas en el dispositivo modificador y ningún otro botón o
    tecla modificadora está lógicamente presionada.
  * O bien, la ventana de captura es un ancestro de (o es) la ventana de
    enfoque, O bien, la ventana de captura es un descendiente de la
    ventana de enfoque y contiene el dispositivo.
  * No existe una captura pasiva en el mismo botón/modificador
    combinado en ningún ancestro de grab_window.
La interpretación de los argumentos restantes es la misma que para
XIGrabDevice. La captura activa se termina automáticamente cuando el
estado lógico del dispositivo tiene todos los botones o teclas
liberados (independientemente del estado lógico de las teclas
modificadoras).
Si el dispositivo es un dispositivo esclavo adjunto, el dispositivo se
desconecta automáticamente del dispositivo maestro cuando la captura se
activa y se vuelve a conectar al mismo dispositivo maestro cuando la
captura se desactiva. Si se elimina el dispositivo maestro mientras el
dispositivo está flotando como resultado de una captura, el dispositivo
permanece flotando una vez que la captura se desactiva.
Tenga en cuenta que el estado lógico de un dispositivo (tal como lo ven las
aplicaciones cliente) puede ir a la zaga del estado físico si el
procesamiento de eventos del dispositivo está congelado.
Esta solicitud anula todas las capturas anteriores del mismo cliente
en las mismas combinaciones de botones/modificadores o keycode/modificadores
en la misma ventana. Un modificador de XIAnyModifier es equivalente a
emitir la solicitud de captura para todas las combinaciones de
modificadores posibles (incluida la combinación de ningún modificador). No
es necesario que todos los modificadores especificados tengan actualmente
KeyCodes asignados. Un botón de XIAnyButton es equivalente a emitir la
solicitud para todos los botones posibles. De lo contrario, no es
necesario que el botón especificado esté asignado actualmente a un botón
físico.
Si algún otro cliente ya ha emitido un XIGrabButton o XIGrabKeycode
con la misma combinación de botón/modificador o keycode/modificador en la
misma ventana, se produce un error BadAccess. Al usar XIAnyModifier o
XIAnyButton, la solicitud falla por completo y se produce un error
XIBadAccess (no se establecen capturas) si existe una captura
conflictiva para alguna combinación. XIGrabButton y XIGrabKeycode no
tienen ningún efecto sobre una captura activa.
En caso de éxito, XIGrabButton, XIGrabKeycode, XIGrabTouchBegin,
XIGrabPinchGestureBegin y XIGrabSwipeGestureBegin devuelven 0;
Si uno o más combinaciones de modificadores no se pudieron capturar,
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
y XIGrabSwipeGestureBegin devuelven el número de
combinaciones fallidas y modifiers_inout contiene las combinaciones
fallidas y sus respectivos códigos de error.
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
y XIGrabSwipeGestureBegin pueden generar errores BadClass,
BadDevice, BadMatch, BadValue y BadWindow.
XIUngrabButton, XIUngrabKeycode, XIUngrabTouchBegin, XIUngrabPinchGestureBegin
y XIUngrabSwipeGestureBegin liberan la
captura pasiva para una combinación de botón/modificador, keycode/modificador o
táctil/modificador en la ventana especificada si fue capturada por este
cliente. Un modificador de XIAnyModifier es equivalente a emitir la
solicitud de liberación para todas las combinaciones de modificadores
posibles, incluida la combinación de ningún modificador. Un botón de
XIAnyButton es equivalente a emitir la solicitud para todos los
botones posibles. XIUngrabButton y XIUngrabKeycode no tienen
efecto sobre una captura activa.

DESCRIPCIÓN

Las funciones XIGrabKeycode, XIGrabButton, XIGrabTouchBegin,
XIGrabPinchGestureBegin y XIGrabSwipeGestureBegin capturan los dispositivos
especificados y los vinculan a la ventana especificada. El dispositivo y el tipo
de dispositivo se especifican mediante deviceid. La lista de teclas, botones o
gestos a capturar se pasa a través de la cuenta y el puntero a los códigos de
tecla, botones o gestos. Los modificadores son un mapa de bits de los modificadores
de teclado que deben estar activos para que la captura tenga efecto. La lista de
modificadores posibles se encuentra en XKB.

GrabModeSync y GrabModeAsync se utilizan para especificar el modo de captura.
En modo síncrono, el servidor X no devolverá ningún evento hasta que se libere
la captura. En modo asíncrono, el servidor X puede enviar eventos.

OwnerGrabModeSync y OwnerGrabModeAsync se utilizan para especificar el modo de
propiedad de la captura. Si el propietario de la captura está en modo
síncrono, los eventos que no coincidan con la captura se envían al propietario
del siguiente cliente. Si el propietario de la captura está en modo asíncrono,
los eventos se envían al propietario del siguiente cliente.

La ventana especificada es la ventana a la que se vinculará la captura. Si la
ventana es None, la captura se vinculará a la ventana raíz del dispositivo.

El cursor especificado se muestra cuando se captura el dispositivo. Si el cursor
es None, no se muestra ningún cursor.

La marca de tiempo grab_time especifica la marca de tiempo de la captura. Si la
marca de tiempo es `CurrentTime`, se utiliza la marca de tiempo actual del
servidor.

Las funciones XIUngrabKeycode, XIUngrabButton, XIUngrabTouchBegin,
XIUngrabPinchGestureBegin y XIUngrabSwipeGestureBegin liberan las capturas
anteriores en el dispositivo especificado. Los modificadores y las teclas,
botones o gestos especificados deben coincidir con la captura original para que
se libere.

Estas funciones pueden generar los siguientes errores:

BadDevice
       Se especificó un deviceid no válido.

BadMatch
       Este error puede ocurrir si XIGrabKeycode especificó un dispositivo que no
       tiene teclas, o XIGrabButton especificó un dispositivo que no tiene
       botones, o XIGrabTouchBegin especificó un dispositivo que no es táctil,
       o XIGrabPinchGestureBegin especificó un dispositivo que no es capaz de
       gestos, o XIGrabSwipeGestureBegin especificó un dispositivo que no es
       capaz de gestos.

BadValue
       Algún valor numérico cae fuera del rango de valores aceptados por la
       solicitud. A menos que se especifique un rango específico para un argumento,
       se acepta el rango completo definido por el tipo del argumento. Cualquier
       argumento definido como un conjunto de alternativas puede generar este error.

BadWindow
       Un valor para un argumento de Ventana no nombra una Ventana definida.

XIGrabButton, XIGrabKeycode y XIGrabTouchBegin, XIGrabPinchGestureBegin y
XIGrabSwipeGestureBegin pueden generar errores BadDevice, BadMatch, BadValue y
BadWindow.

VALOR DE RETORNO

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin y
XIGrabPinchGestureBegin y XIGrabSwipeGestureBegin devuelven el número de
combinaciones de modificadores que no pudieron establecer una captura pasiva. Los
modificadores se devuelven en modifiers_inout, junto con el error respectivo
para esta combinación de modificadores. Si XIGrabButton, XIGrabKeycode
o XIGrabTouchBegin devuelven cero, las capturas pasivas con todas las
combinaciones de modificadores solicitadas se establecieron con éxito.

       que no tiene teclas,

       aceptados por la solicitud. A menos que se especifique un rango

       tipo del argumento es aceptado. Cualquier argumento definido como un
       conjunto de alternativas puede generar este error.

       Un valor para un argumento de Ventana no nombra una Ventana definida.

ERRORES

Las cabeceras del protocolo para XI 2.0 no proporcionaron
XIGrabModeAsync o XIGrabModeSync. Use GrabModeSync y
GrabModeAsync en su lugar, respectivamente.
