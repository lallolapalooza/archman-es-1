X(7) Manual de Información Miscelánea X(7)

NOMBRE

X - un sistema de ventanas portátil y transparente a la red

VISTA GENERAL

El Sistema de Ventanas X es un sistema transparente a la red que se ejecuta en una amplia gama de máquinas informáticas y gráficas. Debería ser relativamente sencillo compilar la distribución de software de la X.Org Foundation en la mayoría de los sistemas compatibles con ANSI C y POSIX. También están disponibles implementaciones comerciales para una amplia gama de plataformas.

La X.Org Foundation solicita que se utilicen los siguientes nombres al referirse a este software:

X
Sistema de Ventanas X
X Versión 11
Sistema de Ventanas X, Versión 11
X11

Sistema de Ventanas X es una marca registrada de The Open Group.

DESCRIPCIÓN

Los servidores del Sistema de Ventanas X se ejecutan en ordenadores con pantallas de mapa de bits. El servidor distribuye la entrada del usuario y acepta solicitudes de salida de varios programas cliente a través de diversos canales de comunicación entre procesos. Aunque el caso más común es que los programas cliente se ejecuten en la misma máquina que el servidor, los clientes también pueden ejecutarse de forma transparente desde otras máquinas (incluidas máquinas con arquitecturas y sistemas operativos diferentes).

X admite subventanas jerárquicas superpuestas y operaciones de texto y gráficos, tanto en pantallas monocromáticas como en color. Para una explicación completa de las funciones disponibles, consulte el manual de Xlib - Interfaz de C para X, la especificación del Protocolo del Sistema de Ventanas X, el manual de X Toolkit Intrinsics - Interfaz de C y diversos documentos de toolkit. Esos manuales, especificaciones y documentos se pueden encontrar en /usr/share/doc o en el sitio web de la X.Org Foundation en https://www.x.org/releases/current/doc/.

El número de programas que utilizan X es bastante amplio. Los programas de ejemplo proporcionados por la X.Org Foundation incluyen: un emulador de terminal, xterm; un gestor de ventanas, twm; un gestor de composición, xcompmgr; un gestor de pantalla, xdm; un programa de redirección de consola, xconsole; utilidades para gestionar dispositivos de entrada y salida, xinput y xrandr; herramientas de listado/manipulación de recursos, appres, editres; programas de control de acceso, xauth, xhost e iceauth; programas de configuración de preferencias de usuario, transset, xrdb, xcmsdb, xset, xsetroot, xstdcmap y xmodmap; relojes, xclock y oclock; utilidades de visualización de fuentes, xfd y xfontsel; utilidades para listar información sobre pantallas, extensiones y recursos, xdpyinfo, xdriinfo, xvinfo, xwininfo, xlsclients, xprop, xlsatoms, xlsclients y xlsfonts; utilidades de manipulación de imágenes de pantalla, xwd, xwud y xmag; una utilidad de medición de rendimiento, x11perf; un compilador de fuentes, bdftopcf; un servidor de fuentes y utilidades relacionadas, xfs, xfsinfo, fslsfonts, fstobdf; un servidor de pantalla y utilidades relacionadas, Xserver, rgb, mkfontdir; un gestor de portapapeles, xclipboard; un compilador de descripciones de teclado y utilidades relacionadas, xkbcomp, setxkbmap, xkbprint, xkbbell, xkbevd, xkbvleds y xkbwatch; una utilidad para terminar clientes, xkill; y una utilidad para provocar que se redibuje parte o la totalidad de la pantalla, xrefresh.

Muchas otras utilidades, gestores de ventanas, juegos, toolkits, etc., se incluyen como paquetes en muchas distribuciones de sistemas operativos o están disponibles en Internet. Consulte a su administrador del sitio o al gestor de paquetes de su distribución para obtener más detalles.

INICIO

Hay dos formas principales de iniciar el servidor X y un conjunto inicial de aplicaciones cliente. El método particular utilizado depende del sistema operativo que esté ejecutando y de si utiliza otros sistemas de ventanas además de X.

Gestor de Pantalla
Si desea tener siempre X en ejecución en su pantalla, su administrador del sitio puede configurar su máquina para usar un Gestor de Pantalla como xdm, gdm o kdm. Este programa normalmente se inicia con el sistema al arrancar y se encarga de mantener el servidor en ejecución y de que los usuarios inicien sesión. Si está ejecutando uno de estos gestores de pantalla, normalmente verá una ventana en la pantalla dándole la bienvenida al sistema y solicitando su información de inicio de sesión. Simplemente introdúzcala como lo haría en una terminal normal. Si comete un error, el gestor de pantalla mostrará un mensaje de error y le pedirá que lo intente de nuevo. Después de iniciar sesión correctamente, el gestor de pantalla iniciará su entorno X. La documentación del gestor de pantalla que utilice puede proporcionar más detalles.
xinit (ejecutado manualmente desde la shell)
Los sitios que admiten más de un sistema de ventanas pueden optar por usar el programa xinit para iniciar X manualmente. Si este es el caso de su máquina, su administrador del sitio probablemente habrá proporcionado un programa llamado "x11", "startx" o "xstart" que realizará inicializaciones específicas del sitio (como cargar recursos predeterminados convenientes, ejecutar un gestor de ventanas, mostrar un reloj e iniciar varios emuladores de terminal) de manera agradable. Si no es así, puede crear dicho script utilizando el programa xinit. Esta utilidad simplemente ejecuta un programa especificado por el usuario para iniciar el servidor, otro para iniciar los clientes deseados y luego espera a que cualquiera de ellos finalice. Dado que uno o ambos programas especificados por el usuario pueden ser scripts de shell, esto proporciona una flexibilidad considerable a expensas de una interfaz agradable. Por esta razón, xinit no está destinado a usuarios finales.

NOMBRES DE PANTALLA

Desde la perspectiva del usuario, cada servidor X tiene un nombre de pantalla con el formato:

nombrehost:numeropantalla.numeropantalla
o
protocolo/nombrehost:numeropantalla.numeropantalla

Esta información es utilizada por la aplicación para determinar cómo debe conectarse al servidor y qué pantalla debe usar por defecto (en pantallas con múltiples monitores):

protocolo
El protocolo especifica el protocolo a utilizar para la comunicación. Qué protocolos exactos se soportan depende de la plataforma, pero los más comúnmente soportados son:
tcp TCP sobre IPv4 o IPv6
inet TCP solo sobre IPv4
inet6 TCP solo sobre IPv6
unix Sockets de Dominio UNIX (solo mismo host)
local Método de conexión local preferido por la plataforma
Si no se especifica el protocolo, Xlib utiliza el transporte que considera más eficiente.
nombrehost
El nombrehost especifica el nombre de la máquina a la que está conectada físicamente la pantalla. Si no se proporciona el nombre del host, se utilizará una conexión a un servidor en la misma máquina.
numeropantalla
La frase "pantalla" se utiliza normalmente para referirse a una colección de monitores que comparten un conjunto común de dispositivos de entrada (teclado, ratón, tableta, etc.). La mayoría de las estaciones de trabajo tienden a tener solo una pantalla. Los sistemas más grandes y multiusuario, sin embargo, frecuentemente tienen varias pantallas para que más de una persona pueda realizar trabajos gráficos a la vez. Para evitar confusiones, cada pantalla en una máquina recibe un número de pantalla (comenzando en 0) cuando se inicia el servidor X para esa pantalla. El número de pantalla siempre debe proporcionarse en un nombre de pantalla.
numeropantalla
Algunas pantallas comparten sus dispositivos de entrada entre dos o más monitores. Estos pueden configurarse como una única pantalla lógica, lo que permite mover ventanas entre pantallas, o como pantallas individuales, cada una con su propio conjunto de ventanas. Si se configuran de tal manera que cada monitor tenga su propio conjunto de ventanas, a cada pantalla se le asigna un número de pantalla (comenzando en 0) cuando

Un servidor X puede obtener fuentes de archivos individuales almacenados en directorios del sistema de archivos, o de uno o más servidores de fuentes, o de una combinación de directorios y servidores de fuentes. La lista de lugares donde el servidor busca al intentar encontrar una fuente está controlada por su ruta de fuentes (font path). Aunque la mayoría de las instalaciones optarán por que el servidor se inicie con todos los directorios de fuentes de uso común en la ruta de fuentes, la ruta de fuentes se puede cambiar en cualquier momento con el programa xset. Sin embargo, es importante recordar que los nombres de los directorios están en la máquina del **servidor**, no en la de la aplicación.

Los archivos de fuentes de mapa de bits suelen crearse compilando una descripción textual de la fuente en formato binario, utilizando bdftopcf. Las bases de datos de fuentes se crean ejecutando el programa mkfontdir en el directorio que contiene las versiones fuente o compiladas de las fuentes. Cada vez que se añaden fuentes a un directorio, se debe volver a ejecutar mkfontdir para que el servidor pueda encontrar las nuevas fuentes. Para que el servidor relea la base de datos de fuentes, restablezca la ruta de fuentes con el programa xset. Por ejemplo, para añadir una fuente a un directorio privado, se podrían utilizar los siguientes comandos:

    % cp newfont.pcf ~/myfonts
    % mkfontdir ~/myfonts
    % xset fp rehash

Los programas xfontsel y xlsfonts se pueden utilizar para examinar las fuentes disponibles en un servidor. Los nombres de las fuentes tienden a ser bastante largos, ya que contienen toda la información necesaria para identificar de forma única fuentes individuales. Sin embargo, el servidor X admite comodines en los nombres de las fuentes, por lo que la especificación completa

    -adobe-courier-medium-r-normal--10-100-75-75-m-60-iso8859-1

podría abreviarse como:

    -*-courier-medium-r-normal--*-100-*-*-*-*-iso8859-1

Dado que el intérprete de comandos (shell) también tiene significados especiales para * y ?, los nombres de fuentes con comodines deben entrecomillarse:

    % xlsfonts -fn '-*-courier-medium-r-normal--*-100-*-*-*-*-*-*'

El programa xlsfonts se puede utilizar para listar todas las fuentes que coinciden con un patrón dado. Sin argumentos, lista todas las fuentes disponibles. Esto normalmente listará la misma fuente en muchos tamaños diferentes. Para ver solo los nombres base de las fuentes escalables, intente usar uno de los siguientes patrones:

    -*-*-*-*-*-*-0-0-0-0-*-0-*-*
    -*-*-*-*-*-*-0-0-75-75-*-0-*-*
    -*-*-*-*-*-*-0-0-100-100-*-0-*-*

Para convertir uno de los nombres resultantes en una fuente de un tamaño específico, reemplace uno de los dos primeros ceros con un valor distinto de cero. El campo que contiene el primer cero es para el tamaño en píxeles; reemplácelo con una altura específica en píxeles para nombrar una fuente de ese tamaño. Alternativamente, el campo que contiene el segundo cero es para el tamaño en puntos; reemplácelo con un tamaño específico en decipuntos (hay 722,7 decipuntos por pulgada) para nombrar una fuente de ese tamaño. El último cero es un campo de ancho promedio, medido en décimas de píxel; algunos servidores escalarán anamorphicamente si se especifica este valor.

NOMBRES DE SERVIDORES DE FUENTES

Se puede utilizar una de las siguientes formas para nombrar un servidor de fuentes que acepte conexiones TCP:

    tcp/hostname:port
    tcp/hostname:port/cataloguelist

El hostname especifica el nombre (o la dirección numérica decimal) de la máquina en la que se está ejecutando el servidor de fuentes. El port es el puerto TCP decimal en el que el servidor de fuentes está escuchando conexiones. El cataloguelist especifica una lista de nombres de catálogo, con '+' como separador.

Ejemplos: tcp/x.org:7100, tcp/198.112.45.11:7100/all.

NOMBRES DE COLORES

La mayoría de las aplicaciones proporcionan formas de adaptar (generalmente a través de recursos o argumentos de línea de comandos) los colores de varios elementos en el texto y los gráficos que muestran. Un color se puede especificar mediante un nombre de color abstracto o mediante una especificación de color numérica. La especificación numérica puede identificar un color en términos dependientes del dispositivo (RGB) o independientes del dispositivo. Las cadenas de color no distinguen entre mayúsculas y minúsculas.

X admite el uso de nombres de colores abstractos, por ejemplo, "red", "blue". El valor de este nombre abstracto se obtiene buscando una o más bases de datos de nombres de colores. Xlib primero busca cero o más bases de datos del lado del cliente; el número, la ubicación y el contenido de estas bases de datos dependen de la implementación. Si el nombre no se encuentra, el color se busca en la base de datos del servidor X. La forma textual de esta base de datos se almacena comúnmente en el archivo /usr/share/X11/rgb.txt.

Una especificación de color numérica consta de un nombre de espacio de color y un conjunto de valores en la siguiente sintaxis:

    <color_space_name>:<value>/.../<value>

Una especificación de dispositivo RGB se identifica con el prefijo "rgb:" y tiene la siguiente sintaxis:

    rgb:<red>/<green>/<blue>
        <red>, <green>, <blue> := h | hh | hhh | hhhh
        h := dígitos hexadecimales individuales

Tenga en cuenta que h indica el valor escalado en 4 bits, hh el valor escalado en 8 bits, hhh el valor escalado en 12 bits y hhhh el valor escalado en 16 bits, respectivamente. Estos valores se pasan directamente al servidor X y se supone que están corregidos por gamma.

Los ocho colores primarios se pueden representar como:

negro rgb:0/0/0
rojo rgb:ffff/0/0
verde rgb:0/ffff/0
azul rgb:0/0/ffff
amarillo rgb:ffff/ffff/0
magenta rgb:ffff/0/ffff
cian rgb:0/ffff/ffff
blanco rgb:ffff/ffff/ffff

Para compatibilidad con versiones anteriores, se admite una sintaxis antigua para Dispositivo RGB, pero no se recomienda su uso continuado. La sintaxis es un signo de almohadilla inicial seguido de una especificación numérica, en uno de los siguientes formatos:

#RGB (4 bits cada uno)
#RRGGBB (8 bits cada uno)
#RRRGGGBBB (12 bits cada uno)
#RRRRGGGGBBBB (16 bits cada uno)

R, G y B representan dígitos hexadecimales individuales. Cuando se especifican menos de 16 bits cada uno, representan los bits más significativos del valor (a diferencia de la sintaxis "rgb:", en la que los valores se escalan). Por ejemplo, #3a7 es lo mismo que #3000a0007000.

Una especificación de intensidad RGB se identifica con el prefijo "rgbi:" y tiene la siguiente sintaxis:

    rgbi:<red>/<green>/<blue>

Rojo, verde y azul son valores de punto flotante entre 0.0 y 1.0, inclusive. Representan valores de intensidad lineal, donde 1.0 indica intensidad completa, 0.5 media intensidad, y así sucesivamente. Estos valores serán corregidos por gamma por Xlib antes de ser enviados al servidor X. El formato de entrada para estos valores es un signo opcional, una cadena de números que posiblemente contenga un punto decimal y un campo de exponente opcional que contenga una E o e seguida de una cadena de enteros posiblemente con signo.

Las especificaciones de cadena estándar independientes del dispositivo tienen la siguiente sintaxis:

CIEXYZ:<X>/<Y>/<Z> (ninguno, 1, ninguno)
CIEuvY:<u>/<v>/<Y> (~.6, ~.6, 1)
CIExyY:<x>/<y>/<Y> (~.75, ~.85, 1)
CIELab:<L>/<a>/<b> (100, ninguno, ninguno)
CIELuv:<L>/<u>/<v> (100, ninguno, ninguno)
TekHVC:<H>/<V>/<C> (360, 100, 100)

Todos los valores (C, H, V, X, Y, Z, a, b, u, v, y, x) son valores de punto flotante. Algunos de los valores están restringidos a estar entre cero y algún límite superior; los límites superiores se dan entre paréntesis arriba. La sintaxis para estos valores es un signo '+' o '-' opcional, una cadena de dígitos que posiblemente contenga un punto decimal, y un campo de exponente opcional que consiste en una 'E' o 'e' seguida de un '+' o '-' opcional seguido de una cadena de dígitos.

Para más información sobre el color independiente del dispositivo, consulte el manual de referencia de Xlib.

TECLADOS

El modelo de teclado de X se divide en dos capas: códigos específicos del servidor (llamados keycodes) que representan las teclas físicas, y símbolos independientes del servidor (llamados keysyms) que representan las letras o palabras que aparecen en las teclas. Dos tablas se guardan en el servidor para convertir keycodes en keysyms:

lista de modificadores
Algunas teclas (como Shift, Control y Bloq Mayús) se conocen como modificadores y se utilizan para seleccionar diferentes símbolos que están asociados a una única tecla (por ejemplo, Shift-a genera una A mayúscula, y Control-l genera un carácter de control ^L). El servidor mantiene una lista de keycodes correspondientes a las diversas teclas modificadoras. Cada vez que se presiona o suelta una tecla, el servidor genera un evento que contiene el keycode de la tecla indicada, así como una máscara que especifica qué teclas modificadoras están actualmente presionadas. La mayoría de los servidores configuran esta lista para que contenga inicialmente las diversas teclas de mayúsculas, control y bloqueo de mayúsculas del teclado.
tabla de mapa de teclas
Las aplicaciones traducen los keycodes de los eventos y las máscaras de modificadores en keysyms utilizando una tabla de keysyms que contiene una fila por cada keycode y una columna para varios estados de modificador. DIAGNÓSTICOS

Una amplia variedad de mensajes de error se generan desde varios programas. El manejador de errores por defecto en Xlib (también utilizado por muchos toolkits) usa recursos estándar para construir mensajes de diagnóstico cuando ocurren errores. Los valores por defecto para estos mensajes suelen almacenarse en /usr/share/X11/XErrorDB. Si este archivo no está presente, los mensajes de error serán bastante escuetos y crípticos.

Cuando los X Toolkit Intrinsics encuentran errores al convertir cadenas de recursos al formato interno apropiado, normalmente no se imprimen mensajes de error. Esto es conveniente cuando se desea tener un conjunto de recursos para una variedad de pantallas (por ejemplo, color vs. monocromo, muchas fuentes vs. muy pocas, etc.), aunque puede plantear problemas para determinar por qué una aplicación podría estar fallando. Este comportamiento puede ser anulado estableciendo el recurso StringConversionWarnings.

Para forzar a los X Toolkit Intrinsics a imprimir siempre mensajes de error de conversión de cadenas, el siguiente recurso debe colocarse en el archivo que se carga en la propiedad RESOURCE_MANAGER utilizando el programa xrdb (frecuentemente llamado .Xresources o .Xres en el directorio de inicio del usuario):

    *StringConversionWarnings: on

Para que se impriman mensajes de conversión solo para una aplicación en particular, el nombre de instancia apropiado puede colocarse antes del asterisco:

    xterm*StringConversionWarnings: on
