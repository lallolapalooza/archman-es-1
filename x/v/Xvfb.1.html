NOMBRE

Xvfb - servidor X de framebuffer virtual para X Versión 11

SINOPSIS

Xvfb [ opción ] ...

DESCRIPCIÓN

Xvfb es un servidor X que puede ejecutarse en máquinas sin hardware de visualización ni dispositivos de entrada físicos. Emula un framebuffer tonto usando memoria virtual.

El uso principal de este servidor estaba destinado a la prueba de servidores. El código fb de cualquier profundidad puede ser ejercitado con este servidor sin necesidad de hardware real que soporte las profundidades deseadas. La comunidad X ha encontrado muchos otros usos novedosos para Xvfb, incluyendo la prueba de clientes contra profundidades y configuraciones de pantalla inusuales, la realización de procesamiento por lotes con Xvfb como motor de renderizado en segundo plano, pruebas de carga, como ayuda para portar el servidor X a una nueva plataforma, y proporcionando una forma discreta de ejecutar aplicaciones que en realidad no necesitan un servidor X pero insisten en tener uno de todos modos.

OPCIONES

Además de las opciones normales del servidor descritas en la página del manual de Xserver(1), Xvfb acepta las siguientes opciones de línea de comandos:

-screen num_pantalla AnxAlxD
Esta opción crea la pantalla num_pantalla y establece su ancho, alto y profundidad en An, Al y P respectivamente. Por defecto, solo existe la pantalla 0, con dimensiones 1280x1024x24.
-pixdepths lista-de-profundidades
Esta opción especifica una lista de profundidades de pixmap que el servidor debe soportar además de las profundidades implícitas por las pantallas soportadas. lista-de-profundidades es una lista separada por espacios de enteros que pueden tener valores de 1 a 32.
-fbdir directorio-framebuffer
Esta opción especifica el directorio en el que se deben crear los archivos con mapeo de memoria que contienen la memoria del framebuffer. Ver ARCHIVOS. Esta opción solo existe en máquinas que tienen las llamadas del sistema mmap y msync.
-shmem
Esta opción especifica que el framebuffer debe colocarse en memoria compartida. El ID de memoria compartida para cada pantalla será impreso por el servidor. La memoria compartida está en formato xwd. Esta opción solo existe en máquinas que soportan la interfaz de memoria compartida System V.

Si no se especifica ni -shmem ni -fbdir, la memoria del framebuffer se asignará con malloc().

-linebias n
Esta opción especifica cómo ajustar la pixelización de líneas finas. El valor n es una máscara de bits de octantes en la que se prefiere un paso axial cuando el término de error de Bresenham es exactamente cero. Ver el archivo Xserver/mi/miline.h para más información. Esta opción probablemente solo sea útil para los desarrolladores del servidor para experimentar con el rango de pixelización de líneas posible con el código fb.
-blackpixel valor-pixel, -whitepixel valor-pixel
Estas opciones especifican los valores de píxel negro y blanco que el servidor debe usar.

ARCHIVOS

Los siguientes archivos se crean si se proporciona la opción -fbdir.

directorio-framebuffer/Xvfb_screen<n>
Archivo con mapeo de memoria que contiene la memoria del framebuffer de la pantalla n, un archivo por pantalla. El archivo está en formato xwd. Por lo tanto, tomar una instantánea de pantalla completa se puede hacer con un comando de copia de archivos, y la instantánea resultante incluso contendrá la imagen del cursor.

EJEMPLOS

Xvfb :1 -screen 0 1600x1200x24
El servidor escuchará las conexiones como servidor número 1, y la pantalla 0 será de profundidad 24, 1600x1200.
Xvfb :1 -screen 1 1600x1200x16
El servidor escuchará las conexiones como servidor número 1, la pantalla 0 tendrá la configuración de pantalla predeterminada (1280x1024x24), y la pantalla 1 será de profundidad 16, 1600x1200.
Xvfb -pixdepths 3 27 -fbdir /var/tmp
El servidor escuchará las conexiones como servidor número 0, tendrá la configuración de pantalla predeterminada (una pantalla, 1280x1024x24), también soportará profundidades de pixmap de 3 y 27, y usará archivos con mapeo de memoria en /var/tmp para el framebuffer.
xwud -in /var/tmp/Xvfb_screen0
Muestra la pantalla 0 del servidor iniciado por el ejemplo anterior.
