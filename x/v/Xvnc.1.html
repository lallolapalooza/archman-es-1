NOMBRE

Xvnc - el servidor X VNC (Virtual Network Computing)

SINOPSIS

Xvnc [opciones] :pantalla#

DESCRIPCIÓN

Xvnc es el servidor X VNC (Virtual Network Computing). Está basado en un servidor X estándar, pero tiene una pantalla "virtual" en lugar de una física. Las aplicaciones X se muestran en él como si fuera una pantalla X normal, pero solo se puede acceder a ellas a través de un visor VNC; consulta vncviewer(1).

Por lo tanto, Xvnc es en realidad dos servidores en uno. Para las aplicaciones es un servidor X, y para los usuarios remotos de VNC es un servidor VNC. Por convención, hemos organizado las cosas para que el número de pantalla del servidor VNC sea el mismo que el número de pantalla del servidor X, lo que significa que puedes usar, por ejemplo, snoopy:2 para referirte a la pantalla 2 en la máquina "snoopy" tanto en el mundo X como en el mundo VNC.

La mejor manera de iniciar Xvnc es a través de vncsession. Esto configura el entorno adecuadamente e inicia un entorno de escritorio. Consulta la página del manual de vncsession(8) para obtener más información.

OPCIONES

Xvnc toma muchas opciones; ejecutar Xvnc -help proporciona una lista. Muchas de estas son opciones estándar del servidor X, que se describen en la página del manual de Xserver(1). Además de las opciones que solo se pueden configurar a través de la línea de comandos, también hay "parámetros" que se pueden configurar tanto a través de la línea de comandos como a través del programa vncconfig(1).

-depth profundidad
Especifica la profundidad de píxeles en bits del escritorio a crear. El valor predeterminado es 24; otros valores posibles son 16 y 32. Cualquier otra cosa es probable que cause un comportamiento extraño en las aplicaciones y puede impedir que el servidor se inicie.
-geometry anchoxalto
Especifica el tamaño del escritorio a crear. El valor predeterminado es 1024x768.
-help
Lista todas las opciones y parámetros.
-inetd
Esto cambia significativamente el comportamiento de Xvnc para que pueda ser lanzado desde inetd. Consulta la sección a continuación sobre el uso con inetd.
-pixelformat formato
Especifica el formato de píxeles que utilizará el servidor (BGRnnn o RGBnnn). El valor predeterminado para profundidad 16 es RGB565 y para profundidad 24 y 32 es RGB888.
-rendernode ruta
Nodo de renderizado DRM a utilizar para la aceleración de GPU DRI3. Especifica una ruta vacía para deshabilitar DRI3. El valor predeterminado es auto, que hace que Xvnc elija un nodo de renderizado adecuado disponible.

PARÁMETROS

Los parámetros de VNC se pueden configurar tanto a través de la línea de comandos como a través del programa vncconfig(1), y con un servidor Xorg habilitado para VNC a través de entradas Options en el archivo xorg.conf.

Los parámetros se pueden activar con -param o desactivar con -param=0. Los parámetros que toman un valor se pueden especificar como -param valor. Otras formas válidas son param=valor -param=valor --param=valor. Los nombres de los parámetros no distinguen entre mayúsculas y minúsculas.

-AcceptCutText
Acepta actualizaciones del portapapeles desde los clientes. El valor predeterminado está activado.
-AcceptKeyEvents
Acepta eventos de pulsación y liberación de teclas desde los clientes. El valor predeterminado está activado.
-AcceptPointerEvents
Acepta eventos de movimiento del puntero y de botones desde los clientes. El valor predeterminado está activado.
-AcceptSetDesktopSize
Acepta solicitudes para cambiar el tamaño del escritorio. El valor predeterminado está activado.
-AllowOverride
Lista separada por comas de parámetros que se pueden modificar usando la extensión VNC. Los parámetros se pueden modificar, por ejemplo, usando el programa vncconfig(1) desde dentro de una sesión en ejecución.
-AlwaysShared
Siempre trata las conexiones entrantes como compartidas, independientemente de la configuración especificada por el cliente. El valor predeterminado está desactivado.
-AvoidShiftNumLock
Las teclas afectadas por Bloq Num a menudo requieren la inserción de un Shift falso para generar el símbolo correcto. Activar esta opción evita estos eventos Shift falsos adicionales, pero puede resultar en un símbolo ligeramente diferente (por ejemplo, un Retorno en lugar de un Enter del teclado numérico).
-BlacklistThreshold cuenta
El número de intentos de conexión no autenticados permitidos desde cualquier host individual antes de que ese host sea puesto en lista negra. El valor predeterminado es 5.
-BlacklistTimeout segundos
El tiempo de espera inicial aplicado cuando un host se pone por primera vez en lista negra. El host no puede reintentar una conexión hasta que expire el tiempo de espera. El valor predeterminado es 10.
-CompareFB modo
Realiza una comparación de píxeles en el búfer de fotogramas para reducir actualizaciones innecesarias. Puede ser 0 (desactivado), 1 (siempre) o 2 (automático). El valor predeterminado es 2.
-desktop nombre-de-escritorio
Cada escritorio tiene un nombre que puede ser mostrado por el visor. Por defecto es "<usuario>@<nombre-host>".
-DisconnectClients
Desconecta los clientes existentes si una conexión entrante no es compartida. El valor predeterminado está activado. Si DisconnectClients es falso, entonces se rechazará una nueva conexión no compartida mientras haya un cliente activo. Cuando se combina con NeverShared, esto significa que solo se permite un cliente a la vez.
-FrameRate fps
El número máximo de actualizaciones por segundo enviadas a cada cliente. Si la pantalla se actualiza más rápido, esos cambios se agregarán y se enviarán en una única actualización al cliente. Ten en cuenta que esto solo controla la tasa máxima y un cliente puede obtener una tasa menor cuando los recursos son limitados. El valor predeterminado es 60.
-GnuTLSPriority prioridad
Cadena de prioridad GnuTLS que controla los algoritmos de negociación de la sesión TLS. Consulta el manual de GnuTLS para ver los valores posibles. Para GnuTLS < 3.6.3, el valor predeterminado será NORMAL para usar el valor predeterminado de upstream. Para versiones más nuevas de GnuTLS, se utilizará la política criptográfica global del sistema.
-IdleTimeout segundos
El número de segundos después del cual se cerrará una conexión VNC inactiva. El valor predeterminado es 0, lo que significa que las conexiones inactivas nunca se cerrarán.
-ImprovedHextile
Utiliza un algoritmo de compresión mejorado para la codificación Hextile, que logra mejores ratios de compresión a costa de usar un poco más de tiempo de CPU. El valor predeterminado está activado.
-interface dirección IP
Escuchar en la interfaz. Por defecto, Xvnc escucha en todas las interfaces disponibles.
-localhost
Solo permite conexiones desde la misma máquina. Útil si usas SSH y quieres evitar conexiones no-SSH desde otras máquinas.
-Log nombre-log:destino:nivel[, ...]
Configura los ajustes de registro de depuración. destino puede ser actualmente stderr, stdout o syslog, y nivel está entre 0 y 100, siendo 100 la salida más detallada. nombre-log suele ser *, lo que significa todos, pero puedes dirigirte a un archivo fuente específico si conoces el nombre de su "LogWriter". El valor predeterminado es *:stderr:30.
-MaxConnectionTime segundos
El número de segundos después del cual se cerrará una conexión VNC, incluso si está activa. El valor predeterminado es 0, lo que significa que las conexiones nunca se cerrarán por tiempo.

OPTIONS

-MaxConnectionTime seconds
Terminar cuando un cliente ha estado conectado durante N segundos. El valor predeterminado es 0.
-MaxCutText bytes
El tamaño máximo de una actualización del portapapeles que se aceptará de un cliente. El valor predeterminado es 262144.
-MaxDisconnectionTime seconds
Terminar cuando ningún cliente ha estado conectado durante N segundos. El valor predeterminado es 0.
-MaxIdleTime seconds
Terminar después de N segundos de inactividad del usuario. El valor predeterminado es 0.
-NeverShared
Nunca tratar las conexiones entrantes como compartidas, independientemente de la configuración especificada por el cliente. El valor predeterminado es desactivado.
-pam_service name, -PAMService name
Nombre del servicio PAM a utilizar al autenticar usuarios mediante cualquiera de los tipos de seguridad "Plain". El valor predeterminado es vnc.
-Password password
Codificación binaria ofuscada de la contraseña que los clientes deben proporcionar para acceder al servidor. El uso de este parámetro no es seguro, utilice el parámetro PasswordFile en su lugar.
-PasswordFile passwd-file, -rfbauth passwd-file
Archivo de contraseña para la autenticación VNC. No hay un valor predeterminado, debe especificar el archivo de contraseña explícitamente. El archivo de contraseña debe crearse con la utilidad vncpasswd(1). El archivo se accede cada vez que llega una conexión, por lo que se puede cambiar sobre la marcha.
-PlainUsers user-list
Una lista separada por comas de nombres de usuario que tienen permitido autenticarse a través de cualquiera de los tipos de seguridad "Plain" (Plain, TLSPlain, etc.). Especifique * para permitir que cualquier usuario se autentique utilizando este tipo de seguridad. Especifique %u para permitir el usuario del proceso del servidor. El valor predeterminado es denegar a todos los usuarios.
-Protocol3.3
Utilizar siempre la versión del protocolo 3.3 para compatibilidad con versiones anteriores con clientes que se comportan mal. El valor predeterminado es desactivado.
-QueryConnect
Pregunta al usuario del escritorio si acepta o rechaza explícitamente las conexiones entrantes. El valor predeterminado es desactivado.

El programa vncconfig(1) debe estar en ejecución en el escritorio para que se admita QueryConnect.

-QueryConnectTimeout seconds
Número de segundos que se mostrará el diálogo de aceptar conexión antes de rechazar la conexión. El valor predeterminado es 10.
-RawKeyboard
Envía los eventos del teclado directamente y evita mapearlos a la disposición del teclado actual. Esto hace que el teclado se comporte efectivamente de acuerdo con la disposición configurada en el servidor en lugar de la disposición configurada en el cliente. El valor predeterminado es desactivado.
-RemapKeys mapping
Configura un mapeo de teclado. mapping es una cadena separada por comas de mapeos de caracteres, cada uno con el formato char->char, o char<>char, donde char es un keysym hexadecimal. Por ejemplo, para intercambiar los símbolos " y @, especificará lo siguiente:
RemapKeys=0x22<>0x40
-RequireUsername
Requiere nombre de usuario para los tipos de seguridad RSA-AES. El valor predeterminado es desactivado.
-rfbport port
Especifica el puerto TCP en el que Xvnc escucha las conexiones de los visores (el protocolo utilizado en VNC se llama RFB - "remote framebuffer"). El valor predeterminado es 5900 más el número de pantalla. Especifique -1 para deshabilitar la escucha en un puerto TCP.
-rfbunixmode mode
Especifica el modo del socket de dominio Unix. El valor predeterminado es 0600.
-rfbunixpath path
Especifica la ruta de un socket de dominio Unix en el que Xvnc escucha las conexiones de los visores.
-RSAKey path
Ruta de la clave RSA para los tipos de seguridad RSA-AES (RA2, RA2ne, RA2_256 y RA2ne_256) en formato PEM.
-SecurityTypes sec-types
Especifica qué esquema de seguridad utilizar para las conexiones entrantes. Los valores válidos son una lista separada por comas de None, VncAuth, Plain, TLSNone, TLSVnc, TLSPlain, X509None, X509Vnc, X509Plain, RA2, RA2ne, RA2_256 y RA2ne_256. El valor predeterminado es TLSVnc,VncAuth.
-SendCutText
Envía los cambios del portapapeles a los clientes. El valor predeterminado es activado.
-SendPrimary
Envía la selección primaria y el búfer de corte al servidor, además de la selección del portapapeles. El valor predeterminado es activado.
-SetPrimary
Establece la selección primaria además de la selección del portapapeles. El valor predeterminado es activado.
-UseBlacklist
Rechaza temporalmente las conexiones de un host si falla repetidamente la autenticación. El valor predeterminado es activado.
-UseIPv4
Utiliza IPv4 para conexiones entrantes y salientes. El valor predeterminado es activado.
-UseIPv6
Utiliza IPv6 para conexiones entrantes y salientes. El valor predeterminado es activado.
-X509Cert path
Ruta de un certificado X509 en formato PEM que se utilizará para todos los tipos de seguridad basados en X509 (X509None, X509Vnc, etc.).
-X509Key path
La contraparte de la clave privada del certificado proporcionado en X509Cert. Debe estar también en formato PEM.

Permitir la anulación de parámetros como PAMService o PasswordFile puede afectar negativamente la seguridad si Xvnc se ejecuta bajo un usuario diferente al de los programas que tienen permitido anular los parámetros.

Cuando se establece el parámetro NoClipboard, permitir la anulación de SendCutText y AcceptCutText no tiene efecto.

El valor predeterminado es desktop,AcceptPointerEvents,SendCutText,AcceptCutText,SendPrimary,SetPrimary.

USO CON INETD

Configurando adecuadamente el servicio inetd(1), Xvnc puede ser iniciado bajo demanda cuando llega una conexión, en lugar de tener que iniciarse manualmente. Cuando se le da la opción -inetd, en lugar de escuchar conexiones TCP en un puerto determinado, utiliza su entrada y salida estándar. Hay dos modos controlados por la entrada wait/nowait en el archivo inetd.conf.

En el modo nowait, Xvnc utiliza su entrada y salida estándar directamente como la conexión a un visor. Nunca tiene un socket de escucha, por lo que no puede aceptar más conexiones de visores (sin embargo, puede conectarse a visores en escucha mediante el programa vncconfig). Más conexiones de visor al mismo puerto TCP resultan en que inetd inicia un nuevo Xvnc para tratar cada conexión. Cuando la conexión con el visor muere, Xvnc y cualquier cliente X asociado mueren. Este comportamiento es más útil cuando se combina con las opciones XDMCP -query y -once. Una entrada típica en inetd.conf podría ser (todo en una sola línea):

5950 stream tcp nowait nobody /usr/local/bin/Xvnc Xvnc -inetd -query localhost -once securitytypes=none

En este ejemplo, una conexión de visor a :50 resultará en un nuevo Xvnc para esa conexión que debería mostrar la pantalla de inicio de sesión XDM estándar en esa máquina. Generalmente está bien aceptar conexiones sin contraseña VNC, ya que el usuario aún necesita iniciar sesión a través de XDM en este caso.

En el modo wait, cuando llega la primera conexión, inetd le da el socket de escucha a Xvnc. Esto significa que para un puerto TCP dado, solo hay un Xvnc a la vez. Las conexiones de visor posteriores al mismo puerto son aceptadas por el mismo Xvnc de la forma normal. Incluso cuando la conexión original se interrumpe, Xvnc continuará ejecutándose. Si esto se utiliza con las opciones XDMCP -query y -once, Xvnc y los clientes X asociados morirán cuando el usuario cierre la sesión de la forma normal. Es importante usar una contraseña VNC en este caso. Una entrada típica en inetd.conf podría ser:

5951 stream tcp wait james /usr/local/bin/Xvnc Xvnc -inetd -query localhost -once passwordFile=/home/james/.config/tigervnc/passwd

De hecho, típicamente, tendría una entrada para cada usuario que usa VNC regularmente, cada uno de los cuales tiene su propio puerto TCP dedicado que utiliza. En este ejemplo, cuando el usuario "james" se conecta a :51, ingresa su contraseña VNC, y luego obtiene la pantalla de inicio de sesión XDM donde inicia sesión de la forma normal. Sin embargo, a diferencia del ejemplo anterior, si se desconecta, la sesión permanece persistente, y cuando se reconecta obtendrá la misma sesión de nuevo. Cuando cierra la sesión X, Xvnc morirá, pero por supuesto se creará automáticamente uno nuevo la próxima vez que se conecte.

NAME

Xvnc - TigerVNC X server

SYNOPSIS

Xvnc [OPTIONS] [DISPLAY]

DESCRIPTION

Xvnc is a display server for the VNC (Virtual Network Computing) protocol. It implements a TigerVNC server that can be used to run an X11 desktop session on a remote machine.

The Xvnc server listens for incoming TCP connections on a specified port. When a VNC viewer connects, it is presented with a virtual desktop that it can control. The server can be configured to run in different modes, such as sharing an existing desktop or creating a new virtual one.

This manual page provides a brief overview of Xvnc. For more detailed information on configuration, options, and usage, please refer to the TigerVNC documentation.

OPTIONS

Xvnc supports a wide range of options that control its behavior. Some common options include:

  • -display <display>: Specifies the X display name (e.g., :1, :2).
  • -geometry <width>x<height>: Sets the desired screen resolution.
  • -depth <depth>: Sets the color depth of the virtual desktop.
  • -rfbport <port>: Specifies the TCP port for VNC connections.
  • -localhost: Only accept connections from localhost.
  • -fg: Run in the foreground.
  • -help: Display a help message and exit.

Consult the Xvnc documentation for a complete list of options.

PARAMETERS

The DISPLAY parameter specifies the X display to use. If omitted, Xvnc will attempt to start on the next available display number (typically :1).

USAGE WITH INETD

Xvnc can be configured to run under inetd for automatic startup upon connection. This typically involves modifying the /etc/inetd.conf file and ensuring that the VNC port is properly defined.

Example entry in /etc/inetd.conf:

shell stream tcp nowait vnc /usr/bin/Xvnc Xvnc -inetd -query localhost -once -fp /usr/share/X11/fonts/misc -ள -fn -*-misc-fixed-*-*-*-13-*-*-*-*-*-*-*

Note: The exact configuration may vary depending on your system setup.
