Paquete: libx11

Licencias: MIT AND X11

XGrabPointer(3) FUNCIONES DE XLIB XGrabPointer(3)

NOMBRE

XGrabPointer, XUngrabPointer, XChangeActivePointerGrab - capturar el puntero

SINTAXIS

int XGrabPointer(Display *display, Window grab_window, Bool owner_events, unsigned int event_mask, int pointer_mode, int keyboard_mode, Window confine_to, Cursor cursor, Time time);

int XUngrabPointer(Display *display, Time time);

int XChangeActivePointerGrab(Display *display, unsigned int event_mask, Cursor cursor, Time time);

ARGUMENTOS

confine_to
Especifica la ventana en la que confinar el puntero o None.
cursor
Especifica el cursor que se mostrará durante la captura o None.
display
Especifica la conexión con el servidor X.
event_mask
Especifica qué eventos del puntero se reportan al cliente. La máscara es la combinación OR inclusiva a nivel de bits de los bits de máscara de eventos del puntero válidos.
grab_window
Especifica la ventana de captura.
keyboard_mode
Especifica el procesamiento adicional de los eventos del teclado. Puede pasar GrabModeSync o GrabModeAsync.
owner_events
Especifica un valor booleano que indica si los eventos del puntero se reportarán como de costumbre o se reportarán con respecto a la ventana de captura si son seleccionados por la máscara de eventos.
pointer_mode
Especifica el procesamiento adicional de los eventos del puntero. Puede pasar GrabModeSync o GrabModeAsync.
time
Especifica la hora. Puede pasar una marca de tiempo o CurrentTime.

DESCRIPCIÓN

La función XGrabPointer captura activamente el control del puntero y devuelve GrabSuccess si la captura fue exitosa. Los eventos posteriores del puntero solo se reportan al cliente que capturó. XGrabPointer anula cualquier captura activa del puntero por parte de este cliente. Si owner_events es False, todos los eventos del puntero generados se reportarán con respecto a grab_window y solo si son seleccionados por event_mask. Si owner_events es True y si un evento del puntero generado se reportaría normalmente a este cliente, se reportará como de costumbre. De lo contrario, el evento se reportará con respecto a la ventana grab_window y solo si es seleccionado por event_mask. Para cualquier valor de owner_events, los eventos no reportados se descartan.

Si pointer_mode es GrabModeAsync, el procesamiento de los eventos del puntero continúa como de costumbre. Si el puntero está actualmente congelado por este cliente, se reanuda el procesamiento de eventos para el puntero. Si pointer_mode es GrabModeSync, el estado del puntero, según lo ven las aplicaciones cliente, parece congelarse, y el servidor X no genera más eventos del puntero hasta que el cliente que captura llame a XAllowEvents o hasta que se libere la captura del puntero. Los cambios reales del puntero no se pierden mientras el puntero está congelado; simplemente se ponen en cola en el servidor para su procesamiento posterior.

Si keyboard_mode es GrabModeAsync, el procesamiento de los eventos del teclado no se ve afectado por la activación de la captura. Si keyboard_mode es GrabModeSync, el estado del teclado, según lo ven las aplicaciones cliente, parece congelarse, y el servidor X no genera más eventos del teclado hasta que el cliente que captura llame a XAllowEvents o hasta que se libere la captura del puntero. Los cambios reales del teclado no se pierden mientras el puntero está congelado; simplemente se ponen en cola en el servidor para su procesamiento posterior.

Si se especifica un cursor, se muestra independientemente de la ventana en la que se encuentre el puntero. Si se especifica None, se muestra el cursor normal de esa ventana cuando el puntero está en grab_window o en una de sus subventanas; de lo contrario, se muestra el cursor de grab_window.

Si se especifica una ventana de confinamiento (confine_to), el puntero se restringe a permanecer dentro de esa ventana. La ventana de confinamiento no necesita tener relación con la ventana de captura (grab_window). Si el puntero no está inicialmente en la ventana de confinamiento, se mueve automáticamente al borde más cercano justo antes de que se active la captura y se generan eventos de entrada/salida como de costumbre. Si la ventana de confinamiento se reconfigura posteriormente, el puntero se moverá automáticamente, según sea necesario, para mantenerlo dentro de la ventana.

El argumento time permite evitar ciertas circunstancias que surgen si las aplicaciones tardan mucho en responder o si hay largos retrasos de red. Considere una situación en la que tiene dos aplicaciones, ambas de las cuales capturan el puntero al hacer clic en ellas. Si ambas aplicaciones especifican la marca de tiempo del evento, la segunda aplicación puede activarse más rápido y capturar el puntero con éxito antes que la primera aplicación. La primera aplicación entonces recibirá una indicación de que la otra aplicación capturó el puntero antes de que se procesara su solicitud.

XGrabPointer genera eventos EnterNotify y LeaveNotify.

Tanto si la ventana grab_window como la ventana confine_to no son visibles, o si la ventana confine_to se encuentra completamente fuera de los límites de la ventana raíz, XGrabPointer falla y devuelve GrabNotViewable. Si el puntero está capturado activamente por otro cliente, falla y devuelve AlreadyGrabbed. Si el puntero está congelado por una captura activa de otro cliente, falla y devuelve GrabFrozen. Si la hora especificada es anterior a la última hora de captura del puntero o posterior a la hora actual del servidor X, falla y devuelve GrabInvalidTime. De lo contrario, la última hora de captura del puntero se establece en la hora especificada (CurrentTime se reemplaza por la hora actual del servidor X).

XGrabPointer puede generar errores BadCursor, BadValue y BadWindow.

La función XUngrabPointer libera el puntero y cualquier evento en cola si este cliente ha capturado activamente el puntero desde XGrabPointer, XGrabButton o desde una pulsación normal de botón. XUngrabPointer no libera el puntero si la hora especificada es anterior a la última hora de captura del puntero o es posterior a la hora actual del servidor X. También genera eventos EnterNotify y LeaveNotify. El servidor X realiza una solicitud UngrabPointer automáticamente si la ventana de eventos o la ventana de confinamiento para una captura activa del puntero no se vuelven visibles o si la reconfiguración de la ventana provoca que la ventana de confinamiento quede completamente fuera de los límites de la ventana raíz.

La función XChangeActivePointerGrab cambia los parámetros dinámicos especificados si el puntero está capturado activamente por el cliente y si la hora especificada no es anterior a la última hora de captura del puntero y no es posterior a la hora actual del servidor X. Esta función no tiene efecto sobre los parámetros pasivos de XGrabButton. La interpretación de event_mask y cursor es la misma que se describe en XGrabPointer.

XChangeActivePointerGrab puede generar un error BadCursor y BadValue.

DIAGNÓSTICOS

BadCursor
Un valor para un argumento de Cursor no nombra un Cursor definido.
BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango para un argumento, se acepta todo el rango definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
BadWindow
Un valor para un argumento de Window no nombra una Window definida.
