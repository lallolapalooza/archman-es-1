XGrabKeyboard(3) FUNCIONES DE XLIB XGrabKeyboard(3)

NOMBRE

XGrabKeyboard, XUngrabKeyboard - capturar el teclado

SINTAXIS

int XGrabKeyboard(Display *display, Window grab_window, Bool owner_events, int pointer_mode, int keyboard_mode, Time time);

int XUngrabKeyboard(Display *display, Time time);

ARGUMENTOS

display
Especifica la conexión con el servidor X.
grab_window
Especifica la ventana de captura.
keyboard_mode
Especifica el procesamiento adicional de eventos del teclado. Puedes pasar GrabModeSync o GrabModeAsync.
owner_events
Especifica un valor booleano que indica si los eventos del teclado deben ser reportados como de costumbre.
pointer_mode
Especifica el procesamiento adicional de eventos del puntero. Puedes pasar GrabModeSync o GrabModeAsync.
time
Especifica la hora. Puedes pasar una marca de tiempo o CurrentTime.

DESCRIPCION

La función XGrabKeyboard captura activamente el control del teclado y genera eventos FocusIn y FocusOut. Los eventos de teclas posteriores se reportan solo al cliente que captura. XGrabKeyboard anula cualquier captura de teclado activa por parte de este cliente. Si owner_events es False, todos los eventos de teclas generados se reportan con respecto a grab_window. Si owner_events es True y si un evento de tecla generado normalmente se reportaría a este cliente, se reporta normalmente; de lo contrario, el evento se reporta con respecto a grab_window. Los eventos KeyPress y KeyRelease siempre se reportan, independientemente de cualquier selección de eventos realizada por el cliente.

Si el argumento keyboard_mode es GrabModeAsync, el procesamiento de eventos del teclado continúa como de costumbre. Si el teclado está actualmente congelado por este cliente, se reanuda el procesamiento de eventos del teclado. Si el argumento keyboard_mode es GrabModeSync, el estado del teclado (visto por las aplicaciones cliente) parece congelarse, y el servidor X no genera más eventos de teclado hasta que el cliente que captura emita una llamada liberadora de XAllowEvents o hasta que se libere la captura del teclado. Los cambios reales del teclado no se pierden mientras el teclado está congelado; simplemente se ponen en cola en el servidor para su procesamiento posterior.

Si pointer_mode es GrabModeAsync, el procesamiento de eventos del puntero no se ve afectado por la activación de la captura. Si pointer_mode es GrabModeSync, el estado del puntero (visto por las aplicaciones cliente) parece congelarse, y el servidor X no genera más eventos del puntero hasta que el cliente que captura emita una llamada liberadora de XAllowEvents o hasta que se libere la captura del teclado. Los cambios reales del puntero no se pierden mientras el puntero está congelado; simplemente se ponen en cola en el servidor para su procesamiento posterior.

Si el teclado está activamente capturado por algún otro cliente, XGrabKeyboard falla y devuelve AlreadyGrabbed. Si grab_window no es visible, falla y devuelve GrabNotViewable. Si el teclado está congelado por una captura activa de otro cliente, falla y devuelve GrabFrozen. Si la hora especificada es anterior a la hora de la última captura de teclado o posterior a la hora actual del servidor X, falla y devuelve GrabInvalidTime. De lo contrario, la hora de la última captura de teclado se establece en la hora especificada (CurrentTime se reemplaza por la hora actual del servidor X).

XGrabKeyboard puede generar errores BadValue y BadWindow.

La función XUngrabKeyboard libera el teclado y cualquier evento en cola si este cliente lo tiene capturado activamente desde XGrabKeyboard o XGrabKey. XUngrabKeyboard no libera el teclado y cualquier evento en cola si la hora especificada es anterior a la hora de la última captura de teclado o es posterior a la hora actual del servidor X. También genera eventos FocusIn y FocusOut. El servidor X realiza automáticamente una solicitud UngrabKeyboard si la ventana de eventos de una captura de teclado activa deja de ser visible.

DIAGNÓSTICOS

BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango específico para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
BadWindow
Un valor para un argumento de Ventana no nombra una Ventana definida.
