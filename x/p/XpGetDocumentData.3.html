XpGetDocumentData(3)

Paquete: libxp

Licencias: X11, X11-distribute-modifications-variant

XpGetDocumentData(3Xp) FUNCIONES DE XPRINT XpGetDocumentData(3Xp)

NOMBRE

XpGetDocumentData - Crea e inicializa un nuevo contexto de impresión.

SINOPSIS


cc [ opción... ] archivo... -lXp [ biblioteca... ]
#include <X11/extensions/Print.h>

Status XpGetDocumentData ( data_display, context, save_proc, finish_proc, client_data )
Display *data_display;
XPContext context;
XPSaveProc save_proc;
XPFinishProc finish_proc;
XPointer client_data;

ARGUMENTOS

data_display
Especifica un puntero a la estructura Display; devuelto por XOpenDisplay.
context
El contexto de impresión del cual se recuperarán los datos del documento.
save_proc
Un procedimiento que se registrará y se llamará repetidamente para guardar bloques de datos del documento.
finish_proc
Un procedimiento que se registrará y se llamará una vez cuando el trabajo de impresión haya finalizado y todos los datos del documento se hayan enviado a save_proc.
client_data
Especifica datos del cliente que se pasarán a save_proc y finish_proc cuando se llamen.

DESCRIPCIÓN

XpGetDocumentData registra devoluciones de llamada que permiten a un "consumidor" recuperar continuamente los datos del documento generados en el *Servidor de Impresión X* por un "productor" separado, donde ambos hacen referencia al mismo contexto de impresión a través de *conexiones de pantalla* diferentes. Aunque XpGetDocumentData recupera datos del documento, su efecto está limitado por XpStartJob y XpEndJob. XpGetDocumentData siempre devuelve inmediatamente; si ocurre un error y las devoluciones de llamada no se pueden registrar, el estado de retorno es 0, de lo contrario, el estado de retorno es distinto de cero y las devoluciones de llamada se llamarán en algún momento después del retorno de XpGetDocumentData. Este intercambio productor/consumidor se configura cuando XpStartJob es llamado por el productor con output_mode igual a XPGetData, y se inicia posteriormente cuando XpGetDocumentData es llamado por el consumidor. Aunque XpStartJob devolverá inmediatamente, los intentos posteriores de usar la conexión de pantalla del productor pueden ser bloqueados por el *Servidor de Impresión X* hasta que se llame a XpGetDocumentData en la conexión de pantalla del consumidor.

Después de una llamada exitosa a XpGetDocumentData, el consumidor debe entrar en un bucle para procesar eventos del servidor, por ejemplo, llamando a XNextEvent. El código de procesamiento de eventos invocará save_proc y finish_proc según sea necesario para consumir los datos entrantes. Para evitar bloquearse indefinidamente en XNextEvent, el consumidor debe seleccionar los eventos XPPrintNotify y observar XPEndJobNotify. Este evento se enviará después de la llamada a finish_proc y el consumidor podrá salir del bucle de forma segura en este punto. Aparte de este procesamiento de eventos XPrintNotify, data_display no debe usarse para ninguna solicitud X adicional hasta que se llame a finish_proc y devuelva.

ESTRUCTURAS

save_proc se define en <X11/extensions/Print.h> como:

typedef void (*XPSaveProc)( Display *data_display,
                           XPContext context,
                           unsigned char *data,
                           unsigned int data_len,
                           XPointer client_data);

save_proc es llamado repetidamente en cada bloque de datos del documento enviado por el Servidor de Impresión X hasta que se llame a XpEndJob o XpCancelJob. data_len especifica el número de bytes en data. La memoria para data es propiedad de la biblioteca, por lo que save_proc debe copiar data a otra ubicación antes de devolver. Después de que el último bloque de datos se haya entregado a save_proc, se llama a finish_proc con el estado final.

finish_proc se define en <X11/extensions/Print.h> como:

typedef void (*XPFinishProc)( Display *data_display,
                             XPContext context,
                             XPGetDocStatus status,
                             XPointer client_data);

Después de que XpGetDocumentData registre exitosamente las devoluciones de llamada, cualquier error X generado (por ejemplo, BadAlloc) o error Xp (por ejemplo, XPBadContext o XPBadSequence) que sea resultado de XpGetDocumentData invocará el manejador de errores de Xlib y luego llamará a finish_proc con un estado de XPGetDocError. Cualquier otra actividad (por ejemplo, un proceso separado destruyendo el contexto de impresión) que resulte fatal para el progreso de XpGetDocumentData también llamará a finish_proc con un estado de XPGetDocError.

Si se llama a XpGetDocumentData antes de XpStartJob, se genera un error XPBadSequence y se llama a finish_proc con XPGetDocError. Si se llama a XpGetDocumentData después de XpStartJob y se especificó output_mode como XPSpool, se genera un error XPBadSequence y se llama a finish_proc con XPGetDocError. Si el productor comienza a generar datos y el consumidor no puede consumir datos lo suficientemente rápido, el servidor de impresión X bloqueará la conexión de pantalla del productor.

Hasta que se llame a XpEndJob o XpCancelJob, es posible que se generen varios eventos XPPrintNotify (por ejemplo, una página ha sido cancelada). Los datos pasados a save_proc no están necesariamente organizados según las solicitudes del consumidor o cualquier evento generado, y su consistencia solo está garantizada si el trabajo completo finaliza con éxito (es decir, sin ser cancelado o generar un error).

Cuando se llama a finish_proc, en algún momento después de que se llama a XpGetDocumentData y devuelve, status proporciona el estado de finalización del trabajo y se define en <X11/extensions/Print.h> como:

#define XPGetDocFinished        0       /∗ terminación normal */
#define XPGetDocSecondConsumer  1       /∗ error de configuración */
#define XPGetDocError           2       /∗ error de progreso */

XPGetDocFinished indica que todos los datos del documento previstos se han entregado a través de save_proc. Se garantiza que todos los eventos de cancelación han llegado en el momento en que se llama a finished_proc, y deben tenerse en cuenta para evaluar la validez de los datos del documento devueltos.

XPGetDocSecondConsumer indica que ya se había establecido un consumidor para el contexto de impresión. El *Servidor de Impresión X* solo admite un consumidor por contexto de impresión.

XPGetDocError indica que se ha generado un error (por ejemplo, XPBadContext o XPBadSequence) y que el *Servidor de Impresión X* no entregará más datos del documento a save_proc.

Después de que finish_proc devuelve, save_proc y finish_proc se desregistran y ya no se llamarán.

DIAGNÓSTICO

XPBadContext
No se ha establecido un ID de contexto de impresión válido antes de realizar esta llamada.
XPBadSequence
La función no se llamó en el orden correcto con respecto a otras llamadas del Servicio de Extensión de Impresión X (por ejemplo, XpGetDocumentData antes de XpStartJob).
