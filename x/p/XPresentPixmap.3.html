XPresentPixmap(3)

Paquete: libxpresent

Licencias: MIT

XPresentPixmap(3) X Version 11 XPresentPixmap(3)

NOMBRE

XPresentPixmap - proporcionar un pixmap para presentación como contenido de ventana

SINTAXIS

#include <X11/extensions/Xpresent.h>

void XPresentPixmap (Display *display,
	Window window,
	Pixmap pixmap,
	uint32_t serial,
	XserverRegion valid,
	XserverRegion update,
	int x_off,
	int y_off,
	RRCrtc target_crtc,
	XSyncFence wait_fence,
	XSyncFence idle_fence,
	uint32_t options,
	uint64_t target_msc,
	uint64_t divisor,
	uint64_t remainder,
	XPresentNotify *notifies,
	int nnotifies);

DESCRIPCIÓN

XPresentPixmap proporciona nuevo contenido para la ventana especificada, en el servidor X especificado por display, para que sea visible en el momento especificado (definido por target-msc, divisor y remainder). Si las profundidades de pixmap y window no coinciden, se generará un error de Match.

serial es un valor arbitrario especificado por el cliente que se devolverá en el evento asociado PresentCompleteNotify para que el cliente pueda asociar el evento con la solicitud.

valid-area define la porción de pixmap que contiene contenido de ventana válido, o None si el pixmap contiene contenido válido para toda la ventana.

update-area define el subconjunto de la ventana que se actualizará, o None si se actualizará toda la ventana.

XPresentPixmap puede usar cualquier región de pixmap que contenga update-area y que esté contenida en valid-area. En otras palabras, las áreas dentro de update-area se presentarán desde pixmap, las áreas fuera de valid-area no se presentarán desde pixmap, y las áreas dentro de valid-area pero fuera de update-area pueden o no presentarse a discreción del servidor X.

x-off e y-off definen la ubicación en la ventana donde se presentará la ubicación 0,0 del pixmap. valid-area y update-area son relativos al pixmap.

wait-fence e idle-fence son cercas de la extensión XSync, que pueden crearse con XSyncCreateFence().

El servidor X bloqueará la acción de presentación hasta que wait-fence se active, pero la función XPresentPixmap se devolverá inmediatamente.

Cuando el servidor X haya terminado de usar pixmap para esta operación, enviará un evento PresentIdleNotify y organizará que cualquier idle-fence se active. Esto puede ocurrir en cualquier momento después de la solicitud PresentPixmap; el contenido puede copiarse inmediatamente a otro búfer, copiarse justo a tiempo para la interrupción de VBlank, o el pixmap puede usarse directamente para la visualización (en cuyo caso estará ocupado hasta una futura operación de PresentPixmap).

Si idle-fence no es None, el cliente garantiza al servidor X que esperará a que esta cerca se active antes de volver a usar el pixmap. Si idle-fence es None, el servidor X debe organizar que el pixmap sea reutilizable por el cliente tan pronto como se reciba el evento PresentIdleNotify. Tenga en cuenta que si PresentCapabilityFence está configurado para el CRTC asociado, los clientes deben usar cercas para mejorar el rendimiento general del sistema. Si PresentCapabilityFence no está configurado, el uso de cercas no ofrece ningún beneficio, pero tampoco ningún coste.

Si target-msc es mayor que el msc actual para window, la presentación ocurrirá en (o después de) el campo target-msc. De lo contrario, la presentación ocurrirá después del próximo campo donde msc % divisor == remainder.

Si target-crtc es None, el servidor X elegirá un CRTC adecuado para la sincronización.

Si options contiene PresentOptionAsync, y target-msc es menor o igual al contador de flujo multimedia (msc) actual para window, la operación se realizará lo antes posible, sin esperar necesariamente al próximo intervalo de VBlank.

Si options contiene PresentOptionCopy, entonces pixmap estará inactivo y idle-fence se activará tan pronto como ocurra la operación. Si options contiene PresentOptionUST, entonces target-msc, divisor y remainder se interpretarán como valores UST en lugar de MSC y la actualización del fotograma se programará para el tiempo UST especificado. Si el target-crtc admite PresentCapabilityUST, el tiempo de intercambio será lo más cercano posible al tiempo objetivo que el controlador pueda gestionar. De lo contrario, el servidor tomará el tiempo UST objetivo y lo convertirá en un valor MSC objetivo adecuado.

Si options contiene PresentOptionSuboptimal, entonces el evento PresentCompleteNotify puede tener el modo PresentCompleteModeSuboptimalCopy, ya que el cliente lo admite.

Después de que ocurra la presentación, se generará un evento PresentCompleteNotify con el tipo PresentCompleteKindPixmap, tanto para window como para todos los miembros de notifies. notifies se especifica como una matriz de estructuras XPresentNotify con nnotifies miembros en la matriz.

Si window se destruye antes de que ocurra la presentación, la acción de presentación no se completará.

El servidor X mantiene una referencia a pixmap hasta que ocurre la presentación, por lo que pixmap puede liberarse inmediatamente después de que se ejecute la solicitud, incluso si eso es antes de que ocurra la presentación.

Si idle-fence se destruye antes de que ocurra la presentación, entonces idle-fence no se activará, pero la presentación ocurrirá normalmente.

Si wait-fence se destruye antes de que se active, la operación de presentación ya no esperará por él y ocurrirá cuando se satisfagan las otras condiciones.
