Paquete: libxp

Licencias: X11, X11-distribute-modifications-variant

XpPutDocumentData(3Xp) FUNCIONES DE XPRINT XpPutDocumentData(3Xp)

NOMBRE

void XpPutDocumentData - Envía e incorpora datos a la salida.

SINOPSIS


cc [ flag... ] file... -lXp [ library... ]
#include <X11/extensions/Print.h>

XpPutDocumentData ( display, drawable, data, data_len, doc_fmt, options )
Display *display;
Drawable drawable;
unsigned char *data;
int data_len;
char *doc_fmt;
char *options;

ARGUMENTOS

display
Especifica un puntero a la estructura Display; devuelto por XOpenDisplay.
drawable
Especifica el drawable de destino para la representación.
data
Especifica los datos específicos del dispositivo enviados.
data_len
Especifica el número de bytes en data.
doc_fmt
Especifica el tipo de datos enviados. Ver abajo para valores válidos. Cadena limitada a caracteres XPCS.
options
Especifica opciones dependientes del controlador DDX. Cadena limitada a caracteres XPCS.

DESCRIPCIÓN

Dependiendo del tipo para XpStartDoc, XpPutDocumentData tiene dos modos de operación.

En el modo XPDocRaw, XpPutDocumentData envía data directamente a la salida, y drawable debe ser None, de lo contrario se generará un error BadDrawable. El servidor de impresión X no emite códigos de control de documentos o páginas en la salida, y los datos se pasan sin modificar. Esto es útil para enviar documentos previamente construidos y completados usando las capacidades de control y envío de trabajos del servidor de impresión X. El atributo de la impresora xp-raw-formats-supported define los valores válidos para doc_fmt en este modo. Los valores no soportados para doc_fmt generan un error BadMatch.

En el modo XPDocNormal, XpPutDocumentData envía data al servidor de impresión X y, dependiendo de la implementación del controlador DDX, integra data en la salida. Los parámetros doc_fmt y options describen el formato de los datos, lo que guía al controlador DDX en la interpretación de los datos. El atributo de la impresora xp-embedded-formats-supported define los valores válidos para doc_fmt en este modo, y los valores no soportados para doc_fmt generan un error BadMatch.

Si doc_fmt no está ni en xp-raw-formats-supported ni en xp-embedded-formats-supported, se genera un error BadValue.

Dependiendo de la implementación del controlador DDX en uso, XpPutDocumentData podría usarse, por ejemplo, para enviar un archivo de texto simple a un controlador DDX Postscript que sea capaz de envolver las construcciones de control de documentos y páginas apropiadas alrededor del texto para que pueda imprimirse en una impresora Postscript. De manera similar, se podrían manejar Archivos Postscript Encapsulados. Otro uso podría ser enviar un archivo TIFF a un controlador DDX PCL que pueda convertir la imagen de TIFF a PCL e integrarla en la salida PCL actual.

No hay límite para el valor de data_len. XpPutDocumentData descompone automáticamente la llamada en múltiples solicitudes de protocolo para asegurar que no se exceda el tamaño máximo de solicitud del servidor.

DIAGNÓSTICOS

BadDrawable
El valor especificado para drawable no es válido.
BadMatch
El valor especificado para doc_fmt no es válido para el tipo de documento actual o el valor especificado para no es válido para el contexto de impresión y la pantalla de impresión.
BadValue
El valor especificado para doc_fmt no está soportado.
XPBadContext
No se ha establecido un id de contexto de impresión válido antes de realizar esta llamada.
XPBadSequence
La función no se llamó en el orden correcto con respecto a las otras llamadas del Servicio de Impresión X (por ejemplo, XpPutDocumentData antes de XpStartDoc).
