Xaw(3) Manual de Funciones de Biblioteca Xaw(3)

NOMBRE

Xaw - Widgets Athena de X

DESCRIPCIÓN

Xaw es un conjunto de widgets basado en la biblioteca X Toolkit Intrinsics (Xt). Esta versión de la Fundación X.Org incluye adiciones y modificaciones realizadas originalmente para The XFree86 Project, Inc. Esta página del manual describe estos cambios, así como algunas de las interfaces comunes entre su versión y la versión anterior del Consorcio X (Xaw6).

La mayor parte de la documentación de Xaw se encuentra en la especificación de la API, que puede estar instalada en /usr/share/doc/libXaw o encontrarse en el sitio web de X.Org.

ACCIONES

Todos los widgets de Xaw ahora tienen las traducciones adicionales call-proc, declare, get-values y set-values. La sintaxis para estas acciones es:

nombre-acción (expresión-booleana, argumentos)

nombre-acción es uno de call-proc, declare, get-values o set-values.

expresión-booleana se compone con los operadores

| (o),
& (y),
^ (xor), y
~ (no).
Sus operandos pueden ser
  • un nombre de variable, que comienza con un $,
  • un nombre de recurso sin los enlaces . o *, o
  • un nombre constante, incluyendo
  • mine (event->xany.window == XtWindow(widget)),
  • faked (event->xany.send_event != 0),
  • true (1) y
  • false (0).

argumentos son autoexplicativos:

  • cuando comienzan con un $ nombran una variable,
  • de lo contrario, indican un nombre de recurso.
call-proc (expresión-booleana, nombre-procedimiento)
Esta acción permite la evaluación de una expresión booleana en el primer parámetro antes de llamar a un procedimiento de acción. El procedimiento solo se llama si la expresión se evalúa como verdadera. Ejemplo: 
call-proc("$inside & $pressed", notify)
declare (expresión-booleana, variable, valor, ...)
Esta acción se utiliza para crear nuevas variables o cambiar sus valores. Se pueden especificar cualquier número de tuplas variable-valor. Ejemplo: 
declare(1, $pressed, 1)
get-values (expresión-booleana, variable, valor, ...)
Esta acción lee el valor de un recurso de widget en una variable. Se pueden especificar cualquier número de tuplas variable-valor. Ejemplo: 
get-values(1, $fg, foreground, $bg, background)
set-values (expresión-booleana, variable, valor, ...)
Esta acción establece un recurso de widget al valor dado, que puede ser una variable. Se pueden especificar cualquier número de tuplas variable-valor. Ejemplo: 
set-values(1, foreground, $bg, background, $fg)

Aquí hay una traducción de ejemplo para hacer que un widget de etiqueta se comporte como un botón:

<Map>:      get-values(1, $fg, foreground, $bg, background)\n\
<Btn1Down>: set-values(1, foreground, yellow, background, gray30)\n\
<Btn1Up>:   set-values(1, foreground, $fg, background, $bg)

LISTAS DE VISUALIZACIÓN

Todos los widgets de Xaw tienen ahora el recurso adicional displayList. Este recurso permite dibujar las decoraciones del widget utilizando comandos incrustados en una cadena de recursos. El recurso displayList tiene la sintaxis:

[nombre-clase:]nombre-función argumentos[[{;\n}]...]

nombre-clase es cualquier conjunto registrado de funciones para dibujar en el widget. Actualmente, la única clase existente es xlib, que proporciona acceso a los primitivos de dibujo de Xlib.

nombre-función es la función de dibujo o configuración que se llamará, descrita a continuación.

argumentos pueden ser cualquier cosa adecuada a la función displayList que se esté llamando. Cuando la función requiere una coordenada, la sintaxis es

{+-}<entero> o
<entero>/<entero>.
Ejemplos:
+0,+0      arriba, izquierda
-0,-0      abajo, derecha
-+10,-+10  abajo+10, derecha+10
+0,1/2     izquierda, centro-vertical
arc-mode modo
Establece el modo de arco. Los modos aceptados son "pieslice" y "chord", que establecen el arco a ArcPieSlice o ArcChord, respectivamente. Ejemplo: 
arc-mode chord
bg especificación-color
background especificación-color
Establece el color de fondo. especificación-color debe ser una especificación de color válida. Ejemplo: 
background red
cap-style estilo
Establece el estilo de la punta. Los estilos aceptados son "notlast", "butt", "round" y "projecting", que establecen el estilo de la punta a CapNotLast, CapBut, CapRound o CapProjecting, respectivamente. Ejemplo: 
cap-style round
clip-mask especificación-pixmap
Establece el pixmap para la máscara de recorte. Requiere un parámetro de pixmap, como se describe en la sección PIXMAPS más adelante. Ejemplo: 
clip-mask xlogo11
clip-origin x,y
Establece el origen x e y del recorte. Requiere dos argumentos, las coordenadas x e y. Ejemplo: 
clip-origin 10,10
clip-rects x1,y1,x2,y2 [...,xn,yn]
clip-rectangles x1,y1,x2,y2 [...,xn,yn]
Establece una lista de rectángulos en la máscara de recorte. El número de argumentos debe ser un múltiplo de cuatro. Los argumentos son coordenadas. El analizador calcula el ancho y la altura de los rectángulos. Ejemplo: 
clip-rects 0,0,10,20, 20,10,30,30
coord-mode modo
Cambia el modo de coordenadas para fill-polygon, draw-lines y draw-points. Los parámetros aceptados son "modeorigin" y "previous", que establecen el modo de coordenadas a CoordModeOrigin o CoordModePrevious, respectivamente. Ejemplo: 
coord-mode previous
copy-area {especificación-pixmap | .},dstx,dsty[,x2,y2,srcx,srcy]
Llama a XCopyArea. El carácter . significa copiar el contenido de la ventana; especificación-pixmap se define en la sección PIXMAPS más adelante. X2 e y2 son las coordenadas del final de la copia, no el ancho y la altura; si no se definen, el analizador las calcula. src_x y src_y valen por defecto cero. Ejemplo: 
copy-area Term,10,10
copy-plane {especificación-pixmap | .},dstx,dsty[,x2,y2,srcx,srcy,plane]
Llama a XCopyPlane. El carácter . significa copiar el contenido de la ventana; especificación-pixmap se define en la sección PIXMAPS más adelante. X2 e y2 son las coordenadas del final de la copia, no el ancho y la altura; si no se definen, el analizador las calcula. src_x y src_y valen por defecto cero. Plane vale por defecto uno. Ejemplo: 
copy-plane star,10,10
dashes i1[...,in]
Establece los guiones para el dibujo de líneas. Acepta hasta 127 argumentos. Ejemplo: 
dashes 3,7 9,10
draw-arc x1,y1,x2,y2[,ángulo-inicio,ángulo-fin]
Dibuja un arco. Las cuatro fi
arguments son el rectángulo que encierra el arco. Los dos argumentos restantes, si se especifican, son el ángulo de inicio y fin, en grados. Ejemplo: 
draw-arc +0,+0,-1,-1,0,90
draw-rect x1,y1,x2,y2
draw-rectangle x1,y1,x2,y2
Dibuja un rectángulo. Requiere cuatro argumentos, que son los pares de coordenadas de inicio y fin. Ejemplo: 
draw-rect +1,+1,-5,-5
draw-string x,y,"cadena"
Dibuja una cadena de texto. Requiere tres argumentos: una coordenada x, una coordenada y y una cadena. Las cadenas que contienen espacios en blanco pueden ir entre comillas dobles (\"), el carácter de barra invertida (\\), también puede ser utilizado, pero será necesario escaparlo dos veces. Ejemplo: 
draw-string 10,10, "Hola mundo!"
exposures booleano
Establece las exposiciones gráficas en el GC. Los parámetros permitidos son un entero o las cadenas "true", "false", "on" y "off". Ejemplo: 
exposures true
fill-arc x1,y1,x2,y2[,angulo-inicio,angulo-fin]
Similar a draw-arc, pero rellena el contenido del arco con el color de primer plano actualmente seleccionado. Ejemplo: 
fill-arc +0,+0,-1,-1,0,180
fill-poly x1,y1 [...,xn,yn]
fill-polygon x1,y1 [...,xn,yn]
Similar a draw-lines, pero rellena el polígono cerrado y une el primer y último punto, si no están en la misma posición. Ejemplo: 
fill-poly +0,+10, +10,+20, +30,+0
fill-rect x1,y1,x2,y2
fill-rectangle x1,y1,x2,y2
Similar a draw-rect, pero rellena el contenido del rectángulo con el color de primer plano seleccionado. Ejemplo: 
fill-rect +10,+10,-20,-20
fill-rule regla
Establece la regla de relleno. Los parámetros aceptados son "evenodd" y "winding", que establecen la regla de relleno a EvenOddRule o WindingRule, respectivamente. Ejemplo: 
fill-rule winding
fill-style estilo
Establece el estilo de relleno. Los parámetros permitidos son "solid", "tiled", "stippled" y "opaquestippled", que establecen el estilo de relleno a FillSolid, FillTiled, FillStippled o FillOpaqueStippled, respectivamente. Ejemplo: 
fill-style tiled
font espec-fuente
Establece la fuente para las funciones de texto. Ejemplo: 
font -*-*-*-R-*-*-*-120-*-*-*-*-ISO8859-1
fg espec-color
foreground espec-color
Similar a background, pero establece el color de primer plano actual. Ejemplo: 
foreground blue
mask
Este comando es útil cuando se desea dibujar solo en la región que realmente necesita ser repintada. No requiere argumentos.
function espec-funcion
Establece la función específica del GC. Los parámetros permitidos son "set", "clear", "and", "andreverse", "copy", "andinverted", "noop", "xor", "or", "nor", "equiv", "invert", "orreverse", "copyinverted" y "nand", que establecen la función a GXset, GXclear, GXand, GXandReverse, GXcopy, GXandInverted, GXnoop, GXxor, GXor, GXnor, GXequiv, GXinvert, GXorReverse, GXcopyInverted o GXnand, respectivamente. Ejemplo: 
function xor
join-style estilo
Establece el estilo de unión. Los parámetros permitidos son "miter", "round" y "bevel", que establecen el estilo de unión a JoinMiter, JoinRound y JoinBevel, respectivamente. Ejemplo: 
join-style round
image {espec-pixmap},xs,ys,[xe,ye]
Esta función se implementa como una forma de componer rápidamente decoraciones complejas en widgets. Espec-pixmap se define en la sección PIXMAPS más abajo. xs e ys son las coordenadas desde donde se empieza a copiar el pixmap; xe y ye son opcionales (por defecto son xs + ancho_pixmap y ys + alto_pixmap, respectivamente). Si el pixmap tiene una máscara, la copia se enmascara adecuadamente. Ejemplo: 
image pixmap.xpm,0,0,20,20
line x1,y1,x2,y2
draw-line x1,y1,x2,y2
Dibuja una línea con el color de primer plano actual. Requiere cuatro argumentos, los pares de coordenadas de inicio y fin. Ejemplo: 
line +0,+0, -1,-1
line-width entero
Selecciona un grosor de línea para dibujar. Ejemplo: 
line-width 2
line-style estilo
Establece el estilo de línea. Los parámetros aceptados son "solid", "onoffdash" y "doubledash", que establecen el estilo de línea a LineSolid, LineOnOffDash o LineDoubleDash, respectivamente. Ejemplo: 
line-style onoffdash
lines x1,y1,x2,y2 [...,xn,yn]
draw-lines x1,y1,x2,y2 [...,xn,yn]
Dibuja una lista de líneas. Se puede proporcionar cualquier número de pares de argumentos. Ejemplo: 
lines +0,-1, -1,-1, -1,+0
paint-string x,y,"cadena"
Idéntico a draw-string, pero también utiliza el color de fondo. Ejemplo: 
paint-string 10,20, "Texto de ejemplo"
point x,y
draw-point x,y
Dibuja un punto. Requiere dos argumentos, un par de coordenadas. Ejemplo: 
point +10,+10
plane-mask entero
Establece la máscara de planos. Requiere un parámetro entero. Ejemplo: 
plane-mask -1
points x1,y1 [...,xn,yn]
draw-points x1,y1 [...,xn,yn]
Dibuja una lista de puntos en las coordenadas especificadas. Ejemplo: 
points +1,+2, +1,+4, +1,+6
segments x1,y1,x2,y2 [...,xn,yn]
draw-segments x1,y1,x2,y2 [...,xn,yn]
Dibuja una lista de segmentos de línea. El número de parámetros debe ser múltiplo de 4. Ejemplo: 
segments +1,+2,+1,-3, +2,-2,-3,-2
shape-mode modo
Establece el modo de forma utilizado en fill-polygon. Los parámetros aceptados son "complex", "convex" o "nonconvex", que establecen el modo de forma a Complex, Convex o Nonconvex, respectivamente. Ejemplo: 
shape-mode convex
stipple espec-pixmap
Establece el pixmap para un estarcido. Requiere un parámetro de pixmap, como se describe en la sección PIXMAPS más abajo. Ejemplo: 
stipple plaid
subwindow-mode modo
Establece el modo de subventana en el GC. Los parámetros aceptados son "includeinferiors" y "clipbychildren", que establecen el modo de subventana a IncludeInferiors o ClipByChildren, respectivamente. Ejemplo: 
subwindow-mode includeinferiors
tile espec-pixmap
Establece el pixmap para un mosaico. Requiere un parámetro de pixmap, como se describe en la sección PIXMAPS más abajo. Ejemplo: 
tile xlogo11?foreground=red&background=gray80
ts-origin x,y
Establece el origen x e y del mosaico estarcido. Requiere dos argumentos, una coordenada x e y. Ejemplo: 
ts-origin 10,10
umask
Deshabilita la máscara del GC, si se ha establecido con el comando mask. No requiere argumentos.

Ejemplo para dibujar un efecto de sombra en un widget:

foreground gray30;\
draw-lines +1,-1,-1,-1,-1,+1;\
foreground gray85;\
draw-lines -1,+0,+0,+0,+0,-1

PIXMAPS

Se ha añadido un conversor de cadena a Pixmap a Xaw. Este conversor está destinado a ser extendido y tiene suficiente abstracción para permitir la carga de varios formatos de imagen. Utiliza un formato que se parece a una URL, con la sintaxis:

[tipo:]nombre[?arg=val[{&}...]]

tipo
puede ser uno de bitmap, gradient o xpm.
nombre
puede ser un nombre de archivo o, en el caso del tipo gradient, puede ser vertical u horizontal.
arg=val
es una lista de argumentos para el conversor.
Una lista de argumentos va precedida por un signo de interrogación, y los argumentos múltiples están separados

NAME

libXaw - Athena Widget Set

DESCRIPTION

The Athena Widget Set (Xaw) is a collection of widgets that can be used to build X applications. This document describes the additions and modifications made to the Xaw library which were originally made for XFree86.

The primary focus of these changes is the Text widget and its related objects (TextSrcObject and TextSinkObject), although other widgets have also been modified.

ACTIONS

The following is a list of new and modified actions available in the Text widget:

copy-buffer
Copies the current selection to the kill buffer. Bound by default to Meta<Key>6.
cut-buffer
Cuts the current selection and puts it into the kill buffer. Bound by default to Control<Key>U.
delete-buffer
Deletes the current selection. Bound by default to <Key>Delete.
kill-buffer
This action is identical to cut-buffer.
kill-to-end-of-line
Deletes text from the cursor position to the end of the line, placing it in the kill buffer. Bound by default to Control<Key>K.
next-line
Moves the cursor to the next line. Bound by default to <Key>Down.
previous-line
Moves the cursor to the previous line. Bound by default to <Key>Up.
select-to-end-of-line
Selects text from the cursor position to the end of the line. Bound by default to Shift<Key>Right.
select-to-beginning-of-line
Selects text from the beginning of the line to the cursor position. Bound by default to Shift<Key>Left.
select-to-end-of-paragraph
Selects text from the cursor position to the end of the paragraph. Bound by default to Shift<Key>Next.
select-to-beginning-of-paragraph
Selects text from the beginning of the paragraph to the cursor position. Bound by default to Shift<Key>Prior.
select-to-end-of-file
Selects text from the cursor position to the end of the buffer. Bound by default to Shift<Key>End.
select-to-beginning-of-file
Selects text from the beginning of the buffer to the cursor position. Bound by default to Shift<Key>Home.
swap-line-and-next-line
Swaps the current line with the next line. Bound by default to Meta<Key>Down.
swap-line-and-previous-line
Swaps the current line with the previous line. Bound by default to Meta<Key>Up.
transpose-characters
Transposes the character before the cursor with the character at the cursor. Bound by default to Control<Key>T.
transpose-words
Transposes the word before the cursor with the word at the cursor. Bound by default to Meta<Key>T.

CONVERTERS

The following converters have been added:

background-and-foreground
This converter is used to specify colors for the background and foreground of a widget. The arguments are separated by ampersands.
The most common arguments are foreground and background.
Gradients also support the arguments start and end (colors with which to start and end the gradient), the steps argument (to allow using fewer colors), and the dimension argument (to specify the size of the gradient).
The xpm converter understands the closeness argument, which aids in using fewer colors (useful if you have a limited colormap).

TEXT WIDGET

Most of the changes to this version of the Xaw library were done in the TextWidget, TextSrcObject, TextSinkObject and related files.

A couple of highly visible changes in the Text widget are due to many bugs in the Xaw6 implementation involving scrollbars and auto-resizing. Scrollbars being added or removed caused several problems in keeping the text cursor visible, and in Xaw6 it was very easy to have a widget thinking the cursor was visible, when it was not. Also, permitting automatic resizing of the widget to a larger geometry created other problems, making it difficult to have a consistent layout in the application, and, if the window manager did not interfere, windows larger than the screen could result. Therefore, some functionality involving scrollbars and auto-resizing has been disabled; see the section on new and modified Text widget resources below.

The Text widget's default key bindings were originally based on the Emacs text editor. In this release, even more operations familiar to Emacs users have been added. New text actions include:

indent
Indents text blocks. Not bound by default. The Text widget also does not attempt to perform auto-indentation of its source object by default.
keyboard-reset
Resets the keyboard state. Reverts the action multiplier to 1, and if undo is enabled, toggles between undo and redo. Bound by default to Control<Key>G.
kill-ring-yank
In this version of Xaw, text killed in any text field is kept in memory, allowing cut and paste operations internally to the program between text fields. Bound by default to Meta<Key>Y.
numeric
Listed here only for purposes of documentation. Called by default when one of the characters 1, 2, 3, 4, 5, 6, 7, 8, 9, 0, or - is typed, allowing composition of the multiplication number of text actions.
set-keyboard-focus
Sets the input focus of the top level widget to the text field. Not enabled by default, but bound to the <Btn1Down> event.
toggle-overwrite
Toggles overwrite mode. In overwrite mode, any text inserted in a text field will replace existing text. Bound by default to <Key>Insert.
undo
Sets the enableUndo resource of the textSrcObject. Not enabled by default, but bound to Control<Key>_.

New and modified Text widget resources include:

justify (Class Justify)
Sets the text justification. Can be one of left, right, center, or full. Only enabled when the autoFill resource is set, and the resources leftColumn and rightColumn are correctly set.
leftColumn (Class Column)
Specifies the left column at which to break text. Text lines started with an alphanumeric character will automatically start at this column.
positionCallback (Class Callback)
Allows installation of a callback to be called every time the cursor is moved, and/or the file changes its size. The callback is called with a pointer to a structure containing the following data:
typedef struct {
    int line_number;
    int column_number;
    XawTextPosition insert_position;
    XawTextPosition last_position;
    Boolean overwrite_mode;
} XawTextPositionInfo;
This callback is intended to help programmers write text editors based on the Xaw widget set.
resize (Class Resize)
No longer supported, but recognized for backward compatibility with resource specifications written for the Xaw6 Text widget.
rightColumn (Class Column)
Specifies the right column at which to break text. Text lines started with an alphanumeric character will automatically end at this column.
scrollHorizontal (Class Scroll)
scrollVertical (Class Scroll)
These resources control the placement of scrollbars on the left and bottom edges of the Text widget. They accept the values XawtextScrollAlways and XawtextScrollNever. A converter is registered for this resource that will convert the following strings: always and never. The value XawtextScrollWhenNeeded (and whenNeeded, recognized by the converter), is accepted for backwards compatibility with resource specifications written for the Xaw6 Text widget, but ignored (effectively treated as XawtextScrollNever).

TEXT SOURCE OBJECT

The textSrcObject allows display of its contents to more than one window, and also stores undo information. The new resources for the textSrcObject are:

callback (Class Callback)
Previous versions of Xaw had this resource in subclasses of the TextSource object. This was changed to make it possible to tell the callback the state of the text when undo is enabled.
enableUndo (Class Undo)
A boolean resource that enables or disables the undo function. The default value is False.
sourceChanged (Class Changed)
Like the callback resource, this resource was previously in subclasses of the TextSource object. It is now in the textSrcObject to control the changed/unchanged state when undo is enabled.

TEXT SINK OBJECT

The textSinkObject subclasses asciiSinkObject and multiSinkObject have been changed slightly to use a new cursor shape (no longer a caret at the baseline) that indicates the input focus of the text widget, and allow specification of the cursor color. The new resource is:

cursorColor (Class Color)
Sets the cursor color of the text. This color is also used to draw selected text.

SIMPLE MENU WIDGET

The simpleMenuWidget algorithm to lay out menu entries has been changed to enable multiple columns when a single column does not fit on the screen. It was also modified to enable submenus.

SME BSB OBJECT

A new resource has been added to the smeBSBObject to allow binding submenus to it. The new resource is:

menuName (Class MenuName)
Specifies the name of the popup widget to be popped up when the pointer is over the menu entry, or NULL. Note that the named menu must be a child of the popup parent of the smeBSBObject.
