NOMBRE

XAllocColor, XAllocNamedColor, XAllocColorCells, XAllocColorPlanes, XFreeColors - asignar y liberar colores

SINTAXIS

Status XAllocColor(Display *display, Colormap colormap, XColor *screen_in_out);

Status XAllocNamedColor(Display *display, Colormap colormap, _Xconst char *color_name, XColor *screen_def_return, XColor *exact_def_return);

Status XAllocColorCells(Display *display, Colormap colormap, Bool contig, unsigned long plane_masks_return[], unsigned int nplanes, unsigned long pixels_return[], unsigned int npixels);

Status XAllocColorPlanes(Display *display, Colormap colormap, Bool contig, unsigned long pixels_return[], int ncolors, int nreds, int ngreens, int nblues, unsigned long *rmask_return, unsigned long *gmask_return, unsigned long *bmask_return);

int XFreeColors(Display *display, Colormap colormap, unsigned long pixels[], int npixels, unsigned long planes);

DESCRIPCIÓN

La función XAllocColor asigna una entrada de mapa de colores de solo lectura que corresponde al valor RGB más cercano soportado por el hardware. XAllocColor devuelve el valor de píxel del color más cercano a los elementos RGB especificados soportados por el hardware y devuelve el valor RGB realmente utilizado. La celda del mapa de colores correspondiente es de solo lectura. Además, XAllocColor devuelve un valor distinto de cero si tuvo éxito o cero si falló. Múltiples clientes que solicitan el mismo valor RGB efectivo pueden recibir la misma entrada de solo lectura, lo que permite compartir entradas. Cuando el último cliente libera una celda compartida, esta se libera. XAllocColor no utiliza ni afecta a las banderas en la estructura XColor.

XAllocColor puede generar un error BadColor.

La función XAllocNamedColor busca el color nombrado con respecto a la pantalla asociada con el mapa de colores especificado. Devuelve tanto la definición exacta de la base de datos como el color más cercano soportado por la pantalla. La celda de color asignada es de solo lectura. El valor del píxel se devuelve en screen_def_return. Si el nombre del color no está en la codificación de caracteres portable del host, el resultado es dependiente de la implementación. El uso de mayúsculas o minúsculas no importa. Si screen_def_return y exact_def_return apuntan a la misma estructura, el campo de píxel se establecerá correctamente, pero los valores de color no están definidos. XAllocNamedColor devuelve un valor distinto de cero si se asigna una celda; de lo contrario, devuelve cero.

XAllocNamedColor puede generar un error BadColor.

La función XAllocColorCells asigna celdas de color de lectura/escritura. El número de colores debe ser positivo y el número de planos no negativo, o se producirá un error BadValue. Si se solicitan ncolors y nplanes, se devuelven ncolors píxeles y nplanes máscaras de plano. Ninguna máscara tendrá bits establecidos a 1 en común con ninguna otra máscara o con ninguno de los píxeles. Al unir cada píxel con cero o más máscaras, se pueden producir ncolors * 2nplanes píxeles distintos. Todos estos se asignan escribibles mediante la solicitud. Para GrayScale o PseudoColor, cada máscara tiene exactamente un bit establecido a 1. Para DirectColor, cada una tiene exactamente tres bits establecidos a 1. Si contig es True y si todas las máscaras se unen, se formará un único conjunto contiguo de bits establecidos a 1 para GrayScale o PseudoColor y tres conjuntos contiguos de bits establecidos a 1 (uno dentro de cada subcampo de píxel) para DirectColor. Los valores RGB de las entradas asignadas no están definidos. XAllocColorCells devuelve un valor distinto de cero si tuvo éxito o cero si falló.

XAllocColorCells puede generar errores BadColor y BadValue.

Los ncolors especificados deben ser positivos; y nreds, ngreens y nblues deben ser no negativos, o se producirá un error BadValue. Si se solicitan ncolors colores, nreds rojos, ngreens verdes y nblues azules, se devuelven ncolors píxeles; y las máscaras tienen nreds, ngreens y nblues bits establecidos a 1, respectivamente. Si contig es True, cada máscara tendrá un conjunto contiguo de bits establecidos a 1. Ninguna máscara tendrá bits establecidos a 1 en común con ninguna otra máscara o con ninguno de los píxeles. Para DirectColor, cada máscara estará dentro del subcampo de píxel correspondiente. Al unir subconjuntos de máscaras con cada valor de píxel, se pueden producir ncolors * 2(nreds+ngreens+nblues) valores de píxel distintos. Todos estos son asignados por la solicitud. Sin embargo, en el mapa de colores, solo hay ncolors * 2nreds entradas rojas independientes, ncolors * 2ngreens entradas verdes independientes y ncolors * 2nblues entradas azules independientes. Esto es cierto incluso para PseudoColor. Cuando se modifica la entrada del mapa de colores de un valor de píxel (usando XStoreColors, XStoreColor o XStoreNamedColor), el píxel se descompone de acuerdo con las máscaras y se actualizan las entradas independientes correspondientes. XAllocColorPlanes devuelve un valor distinto de cero si tuvo éxito o cero si falló.

XAllocColorPlanes puede generar errores BadColor y BadValue.

La función XFreeColors libera las celdas representadas por los píxeles cuyos valores están en la matriz de píxeles. El argumento planes no debe tener bits establecidos a 1 en común con ninguno de los píxeles. El conjunto de todos los píxeles se produce uniendo subconjuntos del argumento planes wi

XFreeColors(3) — X Version 11

NAME

XFreeColors — free allocated colors

SYNTAX

int XFreeColors (
    Display *display,
    Colormap cmap,
    unsigned long pixels[],
    int ncolors,
    unsigned int planes
);

DESCRIPTION

The XFreeColors function frees the specified pixels in the specified colormap. The planes argument must match the visual.red_mask, visual.green_mask, and visual.blue_mask values for the specified colormap's visual type. Only the bits in planes that are set to 1 are freed. If all bits in planes are set to 1, all pixels are freed. Typically, you would pass the value returned by XAllocColorPlanes for the planes argument.

The request frees all of these pixels that were allocated by the client (using XAllocColor, XAllocNamedColor, XAllocColorCells, and XAllocColorPlanes). Note that freeing an individual pixel obtained from XAllocColorPlanes may not actually allow it to be reused until all of its related pixels are also freed. Similarly, a read-only entry is not actually freed until it has been freed by all clients, and if a client allocates the same read-only entry multiple times, it must free the entry that many times before the entry is actually freed.

All specified pixels that are allocated by the client in the colormap are freed, even if one or more pixels produce an error. If a specified pixel is not a valid index into the colormap, a BadValue error results. If a specified pixel is not allocated by the client (that is, is unallocated or is only allocated by another client) or if the colormap was created with all entries writable (by passing AllocAll to XCreateColormap), a BadAccess error results. If more than one pixel is in error, the one that gets reported is arbitrary.

XFreeColors can generate BadAccess, BadColor, and BadValue errors.

DIAGNOSTICS

BadAccess
A client attempted to free a color map entry that it did not already allocate.
BadAccess
A client attempted to store into a read-only color map entry.
BadColor
A value for a Colormap argument does not name a defined Colormap.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
