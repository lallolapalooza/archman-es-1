XAllocColor(3) FUNCIONES DE XLIB XAllocColor(3)

NOMBRE

XAllocColor, XAllocNamedColor, XAllocColorCells, XAllocColorPlanes, XFreeColors - asignar y liberar colores

SINTAXIS

Status XAllocColor(Display *display, Colormap colormap, XColor *screen_in_out);

Status XAllocNamedColor(Display *display, Colormap colormap, _Xconst char *color_name, XColor *screen_def_return, XColor *exact_def_return);

Status XAllocColorCells(Display *display, Colormap colormap, Bool contig, unsigned long plane_masks_return[], unsigned int nplanes, unsigned long pixels_return[], unsigned int npixels);

Status XAllocColorPlanes(Display *display, Colormap colormap, Bool contig, unsigned long pixels_return[], int ncolors, int nreds, int ngreens, int nblues, unsigned long *rmask_return, unsigned long *gmask_return, unsigned long *bmask_return);

int XFreeColors(Display *display, Colormap colormap, unsigned long pixels[], int npixels, unsigned long planes);

Especifica el número de píxeles.

Especifica el número de máscaras de plano que se devolverán en la matriz de máscaras de plano.
nreds

Devuelve una matriz de máscaras de plano.

Especifica los planos que desea liberar.
rmask_return

gmask_return

Devuelve los valores RGB más cercanos proporcionados por el hardware.

DESCRIPCIÓN

La función XAllocColor asigna una entrada de mapa de colores de solo lectura correspondiente al valor RGB más cercano soportado por el hardware. XAllocColor devuelve el valor del píxel del color más cercano a los elementos RGB especificados soportados por el hardware y devuelve el valor RGB realmente utilizado. La celda de mapa de colores correspondiente es de solo lectura. Además, XAllocColor devuelve un valor distinto de cero si tuvo éxito o cero si falló. Múltiples clientes que solicitan el mismo valor RGB efectivo pueden ser asignados la misma entrada de solo lectura, permitiendo así compartir entradas. Cuando el último cliente desasigna una celda compartida, esta se libera. XAllocColor no usa ni afecta las banderas en la estructura XColor.

XAllocColor puede generar un error BadColor.

La función XAllocNamedColor busca el nombre de color con respecto a la pantalla que está asociada con el mapa de colores especificado. Devuelve tanto la definición exacta de la base de datos como el color más cercano soportado por la pantalla. La celda de color asignada es de solo lectura. El valor del píxel se devuelve en screen_def_return. Si el nombre del color no está en la codificación de caracteres portátil del host, el resultado es dependiente de la implementación. El uso de mayúsculas o minúsculas no importa. Si screen_def_return y exact_def_return apuntan a la misma estructura, el campo de píxel se establecerá correctamente, pero los valores de color no están definidos. XAllocNamedColor devuelve un valor distinto de cero si se asigna una celda; de lo contrario, devuelve cero.

XAllocNamedColor puede generar un error BadColor.

La función XAllocColorCells asigna celdas de color de lectura/escritura. El número de colores debe ser positivo y el número de planos no negativo, o se produce un error BadValue. Si se solicitan ncolors y nplanes, se devuelven ncolors píxeles y nplane máscaras de plano. Ninguna máscara tendrá bits establecidos en 1 en común con ninguna otra máscara o con ninguno de los píxeles. Al unir cada píxel con cero o más máscaras, se pueden producir 2nplanes píxeles distintos, multiplicados por ncolors. Todos estos se asignan como escribibles mediante la solicitud. Para GrayScale o PseudoColor, cada máscara tiene exactamente un bit establecido en 1. Para DirectColor, cada una tiene exactamente tres bits establecidos en 1. Si contig es True y si todas las máscaras se unen, se formará un solo conjunto contiguo de bits establecidos en 1 para GrayScale o PseudoColor y tres conjuntos contiguos de bits establecidos en 1 (uno dentro de cada subcampo de píxel) para DirectColor. Los valores RGB de las entradas asignadas no están definidos. XAllocColorCells devuelve un valor distinto de cero si tuvo éxito o cero si falló.

XAllocColorCells puede generar errores BadColor y BadValue.

El ncolors especificado debe ser positivo; y nreds, ngreens y nblues deben ser no negativos, o se producirá un error BadValue. Si se solicitan ncolors colores, nreds rojos, ngreens verdes y nblues azules, se devuelven ncolors píxeles; y las máscaras tienen nreds, ngreens y nblues bits establecidos en 1, respectivamente. Si contig es True, cada máscara tendrá un conjunto contiguo de bits establecidos en 1. Ninguna máscara tendrá bits establecidos en 1 en común con ninguna otra máscara o con ninguno de los píxeles. Para DirectColor, cada máscara estará dentro del subcampo de píxel correspondiente. Al unir subconjuntos de máscaras con cada valor de píxel, se pueden producir ncolors * 2(nreds+ngreens+nblues) valores de píxeles distintos. Todos estos son asignados por la solicitud. Sin embargo, en el mapa de colores, solo hay ncolors * 2nreds entradas rojas independientes, ncolors * 2ngreens entradas verdes independientes y ncolors * 2nblues entradas azules independientes. Esto es cierto incluso para PseudoColor. Cuando se cambia la entrada del mapa de colores de un valor de píxel (usando XStoreColors, XStoreColor o XStoreNamedColor), el píxel se descompone según las máscaras y se actualizan las entradas independientes correspondientes. XAllocColorPlanes devuelve un valor distinto de cero si tuvo éxito o cero si falló.

XAllocColorPlanes puede generar errores BadColor y BadValue.

La función XFreeColors libera las celdas representadas por los píxeles cuyos valores están en la matriz de píxeles. XFreeColors(3) - ArchWiki

NAME

XFreeColors - libera píxeles de un mapa de colores

SYNTAX

#include <Xlib.h>

int XFreeColors(Display *display, Colormap cmap, unsigned long pixels[],
                int ncolors, int planes);

DESCRIPTION

La función XFreeColors libera las entradas del mapa de colores especificadas por el argumento pixels.

El argumento ncolors especifica el número de píxeles a liberar. El argumento pixels es un puntero a un array de unsigned long, donde cada elemento es un valor de píxel. El argumento planes se utiliza solo para el mapeo de profundidad de bits y no debería ser necesario. Establezca planes en 0. La llamada a esta función libera todos los píxeles que fueron asignados por el cliente (usando XAllocColor, XAllocNamedColor, XAllocColorCells y XAllocColorPlanes). Tenga en cuenta que liberar un píxel individual obtenido de XAllocColorPlanes puede no permitir su reutilización real hasta que todos sus píxeles relacionados también sean liberados. De manera similar, una entrada de solo lectura no se libera realmente hasta que ha sido liberada por todos los clientes, y si un cliente asigna la misma entrada de solo lectura varias veces, debe liberar la entrada tantas veces antes de que la entrada sea realmente liberada.

Todos los píxeles especificados que son asignados por el cliente en el mapa de colores son liberados, incluso si uno o más píxeles producen un error. Si un píxel especificado no es un índice válido en el mapa de colores, se produce un error BadValue. Si un píxel especificado no es asignado por el cliente (es decir, no está asignado o solo está asignado por otro cliente) o si el mapa de colores se creó con todas las entradas grabables (pasando AllocAll a XCreateColormap), se produce un error BadAccess. Si más de un píxel tiene un error, el que se informa es arbitrario.

XFreeColors puede generar errores BadAccess, BadColor y BadValue.

DIAGNOSTICS

BadAccess
Un cliente intentó liberar una entrada de mapa de colores que no había asignado previamente.
BadAccess
Un cliente intentó escribir en una entrada de mapa de colores de solo lectura.
BadColor
Un valor para un argumento de Colormap no nombra un Colormap definido.
BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango específico para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
