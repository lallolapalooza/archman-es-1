XALLOWDEVICEEVENTS(3)   XALLOWDEVICEEVENTS(3)

NOMBRE

XAllowDeviceEvents - liberar eventos en cola

SINOPSIS

#include <X11/extensions/XInput.h>
int XAllowDeviceEvents( Display *display,
                        XDevice *device,
                        int event_mode,
                        Time time);
display
       Especifica la conexión con el servidor X.
device
       Especifica el dispositivo del cual se permitirán los eventos.

event_mode
       Especifica el modo de eventos. Puedes pasar AsyncThisDevice,
       SyncThisDevice, ReplayThisDevice, AsyncOtherDevices,
       SyncAll, o AsyncAll.
time
       Especifica el tiempo. Puedes pasar una marca de tiempo o
       CurrentTime.

DESCRIPCIÓN

La función XAllowDeviceEvents libera algunos eventos en cola si el cliente ha causado que un dispositivo se congele. No tiene ningún efecto si la marca de tiempo especificada es anterior a la hora de última captura del grab más reciente activo para el cliente y el dispositivo, o si la marca de tiempo especificada es posterior a la hora actual del servidor X.

La siguiente tabla describe el procesamiento que ocurre dependiendo de la constante que pases al argumento event_mode.

•AsyncThisDevice - Si el dispositivo especificado está congelado por el cliente, el procesamiento de eventos para ese dispositivo continúa como de costumbre. Si el dispositivo está congelado varias veces por el cliente en nombre de múltiples capturas separadas, AsyncThisDevice se descongela para todas. AsyncThisDevice no tiene ningún efecto si el dispositivo especificado no está congelado por el cliente, pero el dispositivo no necesita estar capturado por el cliente.
•SyncThisDevice - Si el dispositivo especificado está congelado y capturado activamente por el cliente, el procesamiento de eventos para ese dispositivo continúa normalmente hasta que el próximo evento de tecla o botón se reporte al cliente. En ese momento, el dispositivo especificado parece congelarse de nuevo. Sin embargo, si el evento reportado causa que la captura se libere, el dispositivo especificado no se congelará. SyncThisDevice no tiene ningún efecto si el dispositivo especificado no está congelado por el cliente o no está capturado por el cliente.
•ReplayThisDevice - Si el dispositivo especificado está capturado activamente por el cliente y está congelado como resultado de que se envió un evento al cliente (ya sea desde la activación de un GrabDeviceButton o desde un AllowDeviceEvents anterior con el modo SyncThisDevice, pero no desde un GrabDevice), se libera la captura y ese evento se reprocesa por completo. Esta vez, sin embargo, la solicitud ignora cualquier captura pasiva en o por encima (hacia la raíz) de la ventana de captura de la captura recién liberada. La solicitud no tiene ningún efecto si el dispositivo especificado no está capturado por el cliente o si no está congelado como resultado de un evento.
•AsyncOtherDevices - Si los dispositivos restantes están congelados por el cliente, el procesamiento de eventos para ellos continúa como de costumbre. Si los otros dispositivos están congelados varias veces por el cliente en nombre de múltiples capturas, AsyncOtherDevices se "descongela" para todas. AsyncOtherDevices no tiene ningún efecto si los dispositivos no están congelados por el cliente.
•SyncAll - Si todos los dispositivos están congelados por el cliente, el procesamiento de eventos (para todos los dispositivos) continúa normalmente hasta que el próximo evento de botón o tecla se reporte al cliente para un dispositivo capturado, momento en el cual todos los dispositivos vuelven a congelarse. Sin embargo, si el evento reportado causa que la captura se libere, entonces los dispositivos no se congelan. Si algún dispositivo sigue capturado, un evento posterior para él aún causará que todos los dispositivos se congelen. SyncAll no tiene ningún efecto a menos que todos los dispositivos estén congelados por el cliente. Si algún dispositivo está congelado dos veces por el cliente en nombre de dos capturas separadas, SyncAll se descongela para ambas. Una congelación posterior para SyncAll solo congelará cada dispositivo una vez.
•AsyncAll - Si todos los dispositivos están congelados por el cliente, el procesamiento de eventos para todos los dispositivos continúa normalmente. Si algún dispositivo está congelado varias veces por el cliente en nombre de múltiples capturas separadas, AsyncAll se descongela para todas. AsyncAll no tiene ningún efecto a menos que todos los dispositivos estén congelados por el cliente.

AsyncThisDevice, SyncThisDevice y ReplayThisDevice no tienen ningún efecto en el procesamiento de eventos de los dispositivos restantes. AsyncOtherDevices no tiene ningún efecto en el procesamiento de eventos del dispositivo especificado. Cuando event_mode es SyncAll o AsyncAll, el parámetro device se ignora.

Es posible que varias capturas de diferentes dispositivos por el mismo o diferentes clientes estén activas simultáneamente. Si un dispositivo está congelado en nombre de cualquier captura, no se realiza ningún procesamiento de eventos para el dispositivo. Es posible que un solo dispositivo esté congelado debido a varias capturas. En este caso, la congelación debe liberarse en nombre de cada captura antes de que los eventos puedan ser procesados nuevamente.

XAllowDeviceEvents puede generar un error BadDevice o BadValue.

DIAGNÓSTICOS

BadDevice
       Se especificó un dispositivo inválido. El dispositivo
       especificado no existe o no ha sido abierto por este cliente
       a través de XOpenInputDevice. Este error también puede
       ocurrir si el dispositivo especificado es el teclado X o
       el dispositivo puntero X.
BadValue
       Se especificó un modo inválido en la solicitud.
