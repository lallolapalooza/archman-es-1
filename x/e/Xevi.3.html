XEVI(3) FUNCIONES X XEVI(3)

NOMBRE

XeviQueryExtension, XeviQueryVersion, XeviGetVisualInfo - Funciones X de Información Visual Extendida

SINOPSIS

#include <X11/extensions/XEVI.h>

Bool XeviQueryExtension (Display *dpy);

Bool XeviQueryVersion (Display *dpy,
int *major_version_return,
int *minor_version_return);

int XeviGetVisualInfo (Display *dpy, VisualID *visual,
int n_visual, ExtendedVisualInfo ** evi_return,
int * n_info_return);

DESCRIPCIÓN

La extensión de Información Visual Extendida (EVI) de X11 permite a un cliente determinar información sobre visuales principales de X más allá de lo que proporciona el protocolo principal.

La biblioteca de programación de aplicaciones EVI contiene las interfaces descritas a continuación. Con la excepción de XeviQueryExtension, si se llama a alguna de estas rutinas con una pantalla que no soporta la extensión, se llamará al ExtensionErrorHandler (que se puede establecer con XSetExtensionErrorHandler y funciona de la misma manera que XSetErrorHandler) y la función devolverá.

XeviQueryExtension devuelve True si la extensión de Información Visual Extendida está disponible en la pantalla dada. Un cliente debe llamar a XeviQueryExtension antes de llamar a cualquier otra función EVI para negociar una versión de protocolo compatible; de lo contrario, el cliente obtendrá un comportamiento indefinido (EVI puede funcionar o no).

XeviQueryVersion devuelve True si la solicitud tuvo éxito; los valores de la versión principal y secundaria del protocolo soportados por el servidor se devuelven en major_version_return y minor_version_return.

XeviGetVisualInfo devuelve una lista de estructuras ExtendedVisualInfo que describen información visual más allá de lo soportado por el protocolo principal. Esto incluye información de capa relevante para sistemas que soportan planos de superposición y/o subcapa, e información que permite a las aplicaciones determinar mejor el nivel de soporte de hardware para múltiples mapas de color. XeviGetVisualInfo devuelve Success si tiene éxito, o un error X de lo contrario. Si el argumento visual es NULL, entonces se devuelve información para todos los visuales de todas las pantallas. De lo contrario, es un puntero a una lista de visuales para los que se desea información visual extendida. n_visual es el número de elementos en el array visual. evi_return devuelve un puntero a una lista de ExtendedVisualInfo. Cuando termine, el cliente debe liberar la lista usando XFree. n_info_return devuelve el número de elementos en el array evi_return.

La estructura ExtendedVisualInfo tiene los siguientes campos: 

VisualID	core_visual_id
int 	screen
int 	level
unsigned int	transparency_type
unsigned int	transparency_value
unsigned int	min_hw_colormaps
unsigned int	max_hw_colormaps
unsigned int	num_colormap_conflicts
VisualID *  	colormap_conflicts

La combinación de core_visual_id y el número de screen especifican de forma única el visual que se está describiendo.

level devuelve el número de nivel para el visual, 0 para planos normales, > 0 para superposiciones, < 0 para subcapas.

transparency_type devuelve el tipo de transparencia soportado por el visual. XEVI_TRANSPARENCY_NONE si no hay píxeles transparentes, XEVI_TRANSPARENCY_PIXEL si el visual soporta un píxel transparente, XEVI_TRANSPARENCY_MASK si el visual soporta plano(s) transparente(s).

transparency_value devuelve el valor de píxel/plano que se debe establecer para la transparencia si transparency_type no es XEVI_TRANSPARENCY_NONE.

min_hw_colormaps y max_hw_colormaps devuelven el número mínimo y máximo de mapas de color de hardware que respaldan el visual.

num_colormap_conflicts devuelve el número de elementos en colormap_conflicts. Este array devuelve una lista de visuales que pueden causar conflictos en el uso del mapa de color de hardware. Por ejemplo, si un mapa de color de hardware de 12 bits se sobrecarga para soportar mapas de color de 8 bits, los visuales de 8 bits correspondientes entrarían en conflicto con los visuales de 12 bits.

ERRORES

XeviGetVisualInfo devolverá BadValue si se le pasa un ID de visual ilegal, BadAccess si el servidor X no responde, BadAlloc si hay un fallo de asignación de memoria.
