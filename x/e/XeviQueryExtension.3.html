NOMBRE

XeviQueryExtension, XeviQueryVersion, XeviGetVisualInfo - Funciones de información visual extendida de X

SINOPSIS

#include <X11/extensions/XEVI.h>

Bool XeviQueryExtension (Display *dpy);

Bool XeviQueryVersion (Display *dpy,
int *major_version_return,
int *minor_version_return);

int XeviGetVisualInfo (Display *dpy, VisualID *visual,
int n_visual, ExtendedVisualInfo ** evi_return,
int * n_info_return);

DESCRIPCIÓN

La extensión de información visual extendida de X11 (EVI) permite a un cliente determinar información sobre las visualizaciones principales de X más allá de lo que proporciona el protocolo principal.

La biblioteca de aplicaciones EVI contiene las interfaces descritas a continuación. Con la excepción de XeviQueryExtension, si alguna de estas rutinas se llama con una pantalla que no admite la extensión, se llamará al ExtensionErrorHandler (que se puede configurar con XSetExtensionErrorHandler y funciona igual que XSetErrorHandler) y la función devolverá.

XeviQueryExtension devuelve True si la extensión de información visual extendida está disponible en la pantalla dada. Un cliente debe llamar a XeviQueryExtension antes de llamar a cualquier otra función EVI para negociar una versión de protocolo compatible; de lo contrario, el cliente obtendrá un comportamiento indefinido (EVI puede funcionar o no).

XeviQueryVersion devuelve True si la solicitud tuvo éxito; los valores de la versión principal y secundaria del protocolo que soporta el servidor se devuelven en major_version_return y minor_version_return.

XeviGetVisualInfo devuelve una lista de estructuras ExtendedVisualInfo que describen información visual más allá de lo que soporta el protocolo principal. Esto incluye información de nivel relevante para sistemas que admiten planos de superposición y/o subyacentes, e información que permite a las aplicaciones determinar mejor el nivel de soporte de hardware para múltiples mapas de colores. XeviGetVisualInfo devuelve Success si tiene éxito, o un error X en caso contrario. Si el argumento visual es NULL, se devuelve información para todas las visualizaciones de todas las pantallas. De lo contrario, es un puntero a una lista de visualizaciones para las que se desea información visual extendida. n_visual es el número de elementos en el array visual. evi_return devuelve un puntero a una lista de ExtendedVisualInfo. Cuando termine, el cliente debe liberar la lista usando XFree. n_info_return devuelve el número de elementos en el array evi_return.

La estructura ExtendedVisualInfo tiene los siguientes campos: 

VisualID	core_visual_id
int 	screen
int 	level
unsigned int	transparency_type
unsigned int	transparency_value
unsigned int	min_hw_colormaps
unsigned int	max_hw_colormaps
unsigned int	num_colormap_conflicts
VisualID *  	colormap_conflicts

La combinación de core_visual_id y el número de screen especifican de forma única la visualización que se está describiendo.

level devuelve el número de nivel para la visualización, 0 para planos normales, > 0 para superposiciones, < 0 para subyacentes.

transparency_type devuelve el tipo de transparencia soportado por la visualización. XEVI_TRANSPARENCY_NONE si no hay píxeles transparentes, XEVI_TRANSPARENCY_PIXEL si la visualización admite un píxel transparente, XEVI_TRANSPARENCY_MASK si la visualización admite planos transparentes.

transparency_value devuelve el valor de píxel/plano que se debe establecer para la transparencia si transparency_type no es XEVI_TRANSPARENCY_NONE.

min_hw_colormaps y max_hw_colormaps devuelven el mínimo y máximo número de mapas de colores de hardware que respaldan la visualización.

num_colormap_conflicts devuelve el número de elementos en colormap_conflicts. Este array devuelve una lista de visualizaciones que pueden causar conflictos en el uso del mapa de colores de hardware. Por ejemplo, si un mapa de colores de hardware de 12 bits se sobrecarga para admitir mapas de colores de 8 bits, las visualizaciones de 8 bits correspondientes entrarían en conflicto con las visualizaciones de 12 bits.

ERRORES

XeviGetVisualInfo devolverá BadValue si se le pasa un ID de visualización ilegal, BadAccess si el servidor X no responde, BadAlloc si hay un error de asignación de memoria.
