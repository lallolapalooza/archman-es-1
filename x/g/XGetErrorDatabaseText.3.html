NOMBRE

XSetErrorHandler, XGetErrorText, XDisplayName, XSetIOErrorHandler, XSetIOErrorExitHandler, XGetErrorDatabaseText - manejadores de errores por defecto

SINTAXIS

int (*XSetErrorHandler(int (*manejador)(Display *, XErrorEvent *)))();

int XGetErrorText(Display *display, int código, char *buffer_retorno, int longitud);

char *XDisplayName(_Xconst char *cadena);

int (*XSetIOErrorHandler(int (*manejador)(Display *)))();

void (*XSetIOErrorExitHandler(Display *display, void (*manejador)(Display *, void *), void *datos_usuario))();

int XGetErrorDatabaseText(Display *display, _Xconst char *nombre, _Xconst char *mensaje, _Xconst char *cadena_por_defecto, char *buffer_retorno, int longitud);

ARGUMENTOS

buffer_retorno
Devuelve la descripción del error.
código
Especifica el código de error para el cual se desea obtener una descripción.
cadena_por_defecto
Especifica el mensaje de error por defecto si no se encuentra ninguno en la base de datos.
display
Especifica la conexión al servidor X.
manejador
Especifica el manejador de errores proporcionado por el programa.
longitud
Especifica el tamaño del búfer.
mensaje
Especifica el tipo del mensaje de error.
nombre
Especifica el nombre de la aplicación.
cadena
Especifica la cadena de caracteres.

DESCRIPCIÓN

Xlib generalmente llama al manejador de errores proporcionado por el programa cada vez que recibe un error. No se llama en errores BadName de las solicitudes de protocolo OpenFont, LookupColor o AllocNamedColor, ni en errores BadFont de una solicitud de protocolo QueryFont. Estos errores generalmente se reflejan de vuelta al programa a través de la interfaz procedimental. Dado que no se asume que esta condición es fatal, es aceptable que su manejador de errores devuelva; el valor devuelto se ignora. Sin embargo, el manejador de errores no debe llamar a ninguna función (directa o indirectamente) en la pantalla que genere solicitudes de protocolo o que busque eventos de entrada. Se devuelve el manejador de errores anterior.

La función XGetErrorText copia una cadena terminada en nulo que describe el código de error especificado en el búfer especificado. El texto devuelto está en la codificación de la configuración regional actual. Se recomienda que utilice esta función para obtener una descripción de error, ya que las extensiones de Xlib pueden definir sus propios códigos de error y cadenas de error.

La función XDisplayName devuelve el nombre de la pantalla que XOpenDisplay intentaría utilizar. Si se especifica una cadena NULL, XDisplayName busca en el entorno la pantalla y devuelve el nombre de la pantalla que XOpenDisplay intentaría utilizar. Esto facilita informar al usuario de qué pantalla exacta intentó abrir el programa cuando falló el intento de conexión inicial.

La función XSetIOErrorHandler establece el manejador de errores de E/S fatales. Xlib llama al manejador de errores proporcionado por el programa si ocurre algún tipo de error de llamada al sistema (por ejemplo, se perdió la conexión con el servidor). Se asume que esta es una condición fatal y la rutina llamada normalmente no debería devolver. Si el manejador de errores de E/S devuelve, el proceso cliente sale por defecto, este comportamiento puede modificarse con la función XSetIOErrorExitHandler.

Tenga en cuenta que se devuelve el manejador de errores anterior.

La función XGetErrorDatabaseText devuelve un mensaje (o el mensaje por defecto) terminado en nulo de la base de datos de mensajes de error. Xlib utiliza esta función internamente para buscar sus mensajes de error. Se asume que el texto en el argumento cadena_por_defecto está en la codificación de la configuración regional actual, y el texto almacenado en el argumento buffer_retorno está en la codificación de la configuración regional actual.

El argumento nombre generalmente debe ser el nombre de su aplicación. El argumento mensaje debe indicar qué tipo de mensaje de error desea. Si el nombre y el mensaje no están en la codificación de caracteres portátil de host, el resultado es dependiente de la implementación. Xlib utiliza tres "nombres de aplicación" predefinidos para informar de los errores. En estos nombres, las mayúsculas y minúsculas importan.

XProtoError
El número de error de protocolo se utiliza como cadena para el argumento mensaje.
XlibMessage
Estas son las cadenas de mensajes que utiliza internamente la biblioteca.
XRequest
Para una solicitud de protocolo principal, el número de protocolo de solicitud principal se utiliza para el argumento mensaje. Para una solicitud de extensión, el nombre de la extensión (tal como lo proporciona InitExtension) seguido de un punto (.) y el número de protocolo de solicitud menor se utiliza para el argumento mensaje. Si no se encuentra ninguna cadena en la base de datos de errores, se devuelve cadena_por_defecto al argumento buffer_retorno.
