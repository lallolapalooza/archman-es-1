XAllocStandardColormap(3) FUNCIONES DE XLIB XAllocStandardColormap(3)

NOMBRE

XAllocStandardColormap, XSetRGBColormaps, XGetRGBColormaps, XStandardColormap - asignar, establecer o leer una estructura de mapa de colores estándar

SINTAXIS

XStandardColormap *XAllocStandardColormap(void);

void XSetRGBColormaps(Display *display, Window w, XStandardColormap *std_colormap, int count, Atom property);

Status XGetRGBColormaps(Display *display, Window w, XStandardColormap **std_colormap_return, int *count_return, Atom property);

ARGUMENTOS

display
Especifica la conexión con el servidor X.
count
Especifica el número de mapas de colores.
count_return
Devuelve el número de mapas de colores.
property
Especifica el nombre de la propiedad.
std_colormap
Especifica la estructura XStandardColormap que se va a utilizar.
std_colormap_return
Devuelve la estructura XStandardColormap.

DESCRIPCIÓN

La función XAllocStandardColormap asigna y devuelve un puntero a una estructura XStandardColormap. Tenga en cuenta que todos los campos de la estructura XStandardColormap se inicializan a cero. Si no hay suficiente memoria disponible, XAllocStandardColormap devuelve NULL. Para liberar la memoria asignada a esta estructura, use XFree.

La función XSetRGBColormaps reemplaza la definición del mapa de colores RGB en la propiedad especificada en la ventana nombrada. Si la propiedad aún no existe, XSetRGBColormaps establece la definición del mapa de colores RGB en la propiedad especificada en la ventana nombrada. La propiedad se almacena con el tipo RGB_COLOR_MAP y un formato de 32. Tenga en cuenta que es responsabilidad del llamador cumplir la restricción ICCCM de que solo RGB_DEFAULT_MAP contenga más de una definición.

La función XSetRGBColormaps normalmente solo la utilizan los gestores de ventanas o de sesiones. Para crear un mapa de colores estándar, siga este procedimiento:

1.
Abra una nueva conexión al mismo servidor.
2.
Bloquee el servidor.
3.
Compruebe si la propiedad está en la lista de propiedades de la ventana raíz de la pantalla.
4.
Si la propiedad deseada no está presente:
  • Cree un mapa de colores (a menos que esté utilizando el mapa de colores predeterminado de la pantalla).
  • Determine las características de color de la visualización.
  • Asigne celdas en el mapa de colores (o créelo con AllocAll).
  • Llame a XStoreColors para almacenar valores de color apropiados en el mapa de colores.
  • Rellene los miembros descriptivos de la estructura XStandardColormap.
  • Adjunte la propiedad a la ventana raíz.
  • Utilice XSetCloseDownMode para que el recurso sea permanente.
5.
Desbloquee el servidor.

XSetRGBColormaps puede generar errores BadAlloc, BadAtom y BadWindow.

La función XGetRGBColormaps devuelve las definiciones de mapa de colores RGB almacenadas en la propiedad especificada en la ventana nombrada. Si la propiedad existe, es de tipo RGB_COLOR_MAP, es de formato 32 y es lo suficientemente larga como para contener una definición de mapa de colores, XGetRGBColormaps asigna y rellena espacio para los mapas de colores devueltos y devuelve un estado distinto de cero. Si el visualid no está presente, XGetRGBColormaps asume la visualización predeterminada para la pantalla en la que se encuentra la ventana; si el killid no está presente, se asume None, lo que indica que los recursos no se pueden liberar. De lo contrario, ninguno de los campos se establece y XGetRGBColormaps devuelve un estado cero. Tenga en cuenta que es responsabilidad del llamador cumplir la restricción ICCCM de que solo RGB_DEFAULT_MAP contenga más de una definición.

XGetRGBColormaps puede generar errores BadAtom y BadWindow.

ESTRUCTURAS

La estructura XStandardColormap contiene:

/* Pistas */

#define ReleaseByFreeingColormap ( (XID) 1L)
/* Valores */ 
typedef struct {
        Colormap colormap;
        unsigned long red_max;
        unsigned long red_mult;
        unsigned long green_max;
        unsigned long green_mult;
        unsigned long blue_max;
        unsigned long blue_mult;
        unsigned long base_pixel;
        VisualID visualid;
        XID killid;
} XStandardColormap;

El miembro colormap es el mapa de colores creado por la función XCreateColormap. Los miembros red_max, green_max y blue_max indican los valores máximos de rojo, verde y azul, respectivamente. Cada coeficiente de color varía de cero a su máximo, inclusive. Por ejemplo, una asignación de mapa de colores común es 3/3/2 (3 planos para rojo, 3 planos para verde y 2 planos para azul). Este mapa de colores tendría red_max = 7, green_max = 7 y blue_max = 3. Una asignación alternativa que utiliza solo 216 colores es red_max = 5, green_max = 5 y blue_max = 5.

Los miembros red_mult, green_mult y blue_mult indican los factores de escala utilizados para componer un valor de píxel completo. (Consulte la discusión de los miembros base_pixel para obtener más información). Para una asignación de 3/3/2, red_mult podría ser 32, green_mult podría ser 4 y blue_mult podría ser 1. Para una asignación de 6 colores cada una, red_mult podría ser 36, green_mult podría ser 6 y blue_mult podría ser 1.

El miembro base_pixel indica el valor base del píxel utilizado para componer un valor de píxel completo. Normalmente, base_pixel se obtiene de una llamada a la función XAllocColorPlanes. Dados los coeficientes enteros rojo, verde y azul en sus rangos apropiados, se puede calcular un valor de píxel correspondiente utilizando la siguiente expresión:

(r * red_mult + g * green_mult + b * blue_mult + base_pixel) & 0xFFFFFFFF

Para mapas de colores GrayScale, solo se definen los miembros colormap, red_max, red_mult y base_pixel. Los otros miembros se ignoran. Para calcular un valor de píxel GrayScale, utilice la siguiente expresión:

(gray * red_mult + base_pixel) & 0xFFFFFFFF

Los multiplicadores negativos se pueden representar convirtiendo la representación de complemento de dos del multiplicador en un unsigned long y almacenando el resultado en el campo _mult apropiado. El paso de enmascaramiento con 0xFFFFFFFF convierte efectivamente el multiplicador positivo resultante en uno negativo. El paso de enmascaramiento se realizará automáticamente en muchas arquitecturas de máquinas, dependiendo del tamaño del tipo entero utilizado para realizar el cálculo.

El miembro visualid indica el número de ID de la visualización de la que se creó el mapa de colores. El miembro killid indica un ID de recurso que especifica si las celdas mantenidas por este mapa de colores estándar deben liberarse liberando el ID del mapa de colores o llamando a la función XKillClient en el recurso indicado. (Tenga en cuenta que este método es necesario para asignar a partir de un mapa de colores existente).

Las propiedades que contienen la información XStandardColormap tienen el tipo RGB_COLOR_MAP.

DIAGNÓSTICOS

BadAlloc
El servidor no pudo asignar el recurso o la memoria del servidor solicitados.
BadAtom
Un valor para un argumento Atom no nombra un Atom definido.
BadWindow
Un valor para un argumento Window no nombra una Window definida.

XGetRGBColormaps

XGetRGBColormaps(3)             Library Functions Manual             XGetRGBColormaps(3)

NOMBRE

XGetRGBColormaps - obtener las asignaciones de color RGB de un mapa de colores

SINTAXIS 

   #include <X11/Xlib.h>

   Status XGetRGBColormaps(
       Display *display,
       XID       resource_id,
       char     *resource_name,
       Bool      send_event,
       int       max_return
   );

ARGUMENTOS

None.

DESCRIPCIÓN

La función XGetRGBColormaps recupera uno o más mapas de colores RGB asociados con un recurso especificado del servidor X.

  • display: Especifica la conexión con el servidor X.
  • resource_id: El ID del recurso para el que se deben recuperar los mapas de colores. Si es 0, se utiliza resource_name.
  • resource_name: El nombre del recurso para el que se deben recuperar los mapas de colores. Si es NULL y resource_id no es 0, se utiliza resource_id.
  • send_event: Un valor booleano que indica si se debe enviar un evento al cliente cuando se recuperan los mapas de colores.
  • max_return: El número máximo de mapas de colores que se deben devolver.

La función devuelve un estado indicando el éxito o el fracaso de la operación. Los mapas de colores recuperados se almacenan en una estructura proporcionada por el cliente (no especificada en esta descripción básica).

ESTRUCTURAS

Los mapas de colores recuperados se suelen devolver en una estructura XStandardColormap o una estructura similar. Esta estructura generalmente contiene campos para el mapa de colores, la pantalla, el número de bits, etc.

DIAGNÓSTICOS

Esta función puede devolver errores del protocolo X si la conexión con el servidor X falla o si los identificadores de recursos proporcionados no son válidos.

VER TAMBIÉN

XGetStandardColormap, XSetStandardProperties, XFreeColors
