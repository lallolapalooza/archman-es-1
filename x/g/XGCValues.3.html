XCreateGC(3) FUNCIONES DE XLIB XCreateGC(3)

NOMBRE

XCreateGC, XCopyGC, XChangeGC, XGetGCValues, XFreeGC, XGContextFromGC, XGCValues - crear o liberar contextos gráficos y estructura del contexto gráfico

SINTAXIS

GC XCreateGC(Display *display, Drawable d, unsigned long valuemask, XGCValues *values);

int XCopyGC(Display *display, GC src, unsigned long valuemask, GC dest);

int XChangeGC(Display *display, GC gc, unsigned long valuemask, XGCValues *values);

Status XGetGCValues(Display *display, GC gc, unsigned long valuemask, XGCValues *values_return);

int XFreeGC(Display *display, GC gc);

GContext XGContextFromGC(GC gc);

ARGUMENTOS

d
Especifica el drawable.
dest
Especifica el GC de destino.
display
Especifica la conexión con el servidor X.
gc
Especifica el GC.
src
Especifica los componentes del GC de origen.
valuemask
Especifica qué componentes del GC se van a establecer, copiar, cambiar o devolver. Este argumento es el OR inclusivo a nivel de bits de cero o más de los bits de máscara de componente GC válidos.
values
Especifica cualquier valor según lo especificado por el valuemask.
values_return
Devuelve los valores del GC en la estructura XGCValues especificada.

DESCRIPCIÓN

La función XCreateGC crea un contexto gráfico y devuelve un GC. El GC puede usarse con cualquier drawable de destino que tenga la misma raíz y profundidad que el drawable especificado. El uso con otros drawables resulta en un error BadMatch.

XCreateGC puede generar errores BadAlloc, BadDrawable, BadFont, BadMatch, BadPixmap y BadValue.

La función XCopyGC copia los componentes especificados del GC de origen al GC de destino. Los GC de origen y destino deben tener la misma raíz y profundidad, o se producirá un error BadMatch. El valuemask especifica qué componente copiar, como para XCreateGC.

XCopyGC puede generar errores BadAlloc, BadGC y BadMatch.

La función XChangeGC cambia los componentes especificados por valuemask para el GC especificado. El argumento values contiene los valores que se van a establecer. Los valores y restricciones son los mismos que para XCreateGC. Cambiar la máscara de recorte anula cualquier solicitud anterior de XSetClipRectangles en el contexto. Cambiar el offset de guiones o la lista de guiones anula cualquier solicitud anterior de XSetDashes en el contexto. El orden en que se verifican y alteran los componentes depende del servidor. Si se genera un error, es posible que un subconjunto de los componentes se haya alterado.

XChangeGC puede generar errores BadAlloc, BadFont, BadGC, BadMatch, BadPixmap y BadValue.

La función XGetGCValues devuelve los componentes especificados por valuemask para el GC especificado. Si el valuemask contiene un conjunto válido de bits de máscara GC (GCFunction, GCPlaneMask, GCForeground, GCBackground, GCLineWidth, GCLineStyle, GCCapStyle, GCJoinStyle, GCFillStyle, GCFillRule, GCTile, GCStipple, GCTileStipXOrigin, GCTileStipYOrigin, GCFont, GCSubwindowMode, GCGraphicsExposures, GCClipXOrigin, GCClipYOrigin, GCDashOffset o GCArcMode) y no ocurre ningún error, XGetGCValues establece los componentes solicitados en values_return y devuelve un estado distinto de cero. De lo contrario, devuelve un estado cero. Tenga en cuenta que la máscara de recorte y la lista de guiones (representadas por los bits GCClipMask y GCDashList, respectivamente, en el valuemask) no se pueden solicitar. Tenga en cuenta también que se devolverá un ID de recurso no válido (con uno o más de los tres bits más significativos establecidos en 1) para GCFont, GCTile y GCStipple si el componente nunca se ha establecido explícitamente por el cliente.

La función XFreeGC destruye el GC especificado, así como todo el almacenamiento asociado.

XFreeGC puede generar un error BadGC.

La estructura XGCValues contiene:

/* Valores */
typedef struct {
        int function;   /* operación lógica */
        unsigned long plane_mask;       /* máscara de plano */
        unsigned long foreground;       /* píxel de primer plano */
        unsigned long background;       /* píxel de fondo */
        int line_width; /* ancho de línea (en píxeles) */
        int line_style; /* LineSolid, LineOnOffDash, LineDoubleDash */
        int cap_style;  /* CapNotLast, CapButt, CapRound, CapProjecting */
        int join_style; /* JoinMiter, JoinRound, JoinBevel */
        int fill_style; /* FillSolid, FillTiled, FillStippled FillOpaqueStippled*/
        int fill_rule;  /* EvenOddRule, WindingRule */
        int arc_mode;   /* ArcChord, ArcPieSlice */
        Pixmap tile;    /* pixmap de mosaico para operaciones de mosaico */
        Pixmap stipple; /* pixmap de 1 plano de estarcido para operaciones de estarcido */
        int ts_x_origin;        /* offset para operaciones de mosaico o estarcido */
        int ts_y_origin;
        Font font;      /* fuente de texto predeterminada para operaciones de texto */
        int subwindow_mode;     /* ClipByChildren, IncludeInferiors */
        Bool graphics_exposures;        /* booleano, ¿se deben generar exposiciones? */
        int clip_x_origin;      /* origen para el recorte */
        int clip_y_origin;
        Pixmap clip_mask;       /* recorte de mapa de bits; otras llamadas para rectángulos */
        int dash_offset;        /* información de línea con patrones/guiones */
        char dashes;
} XGCValues;

Los atributos de función de un GC se utilizan cuando actualiza una sección de un drawable (el destino) con bits de otro lugar (el origen). La función en un GC define cómo se deben calcular los nuevos bits de destino a partir de los bits de origen y los bits de destino antiguos. GXcopy es típicamente el más útil porque funcionará en una pantalla en color, pero aplicaciones especiales pueden usar otras funciones, particularmente en conjunción con planos particulares de una pantalla en color. Las 16 funciones del GC

, definidos en X11/X.h, son:

Nombre de la Función Valor Operación
GXclear 0x0 0
GXand 0x1 src AND dst
GXandReverse 0x2 src AND NOT dst
GXcopy 0x3 src
GXandInverted 0x4 (NOT src) AND dst
GXnoop 0x5 dst
GXxor 0x6 src XOR dst
GXor 0x7 src OR dst
GXnor 0x8 (NOT src) AND (NOT dst)
GXequiv 0x9 (NOT src) XOR dst
GXinvert 0xa NOT dst
GXorReverse 0xb src OR (NOT dst)
GXcopyInverted 0xc NOT src
GXorInverted 0xd (NOT src) OR dst
GXnand 0xe (NOT src) OR (NOT dst)
GXset 0xf 1

Muchas operaciones gráficas dependen de los valores de los píxeles o de los planos en un GC. El atributo de planos es de tipo `long` y especifica qué planos del destino se modificarán, un bit por plano. Una pantalla monocromática tiene un solo plano y será el bit menos significativo de la palabra. A medida que se añaden planos al hardware de la pantalla, ocuparán bits más significativos en la máscara de planos.

En las operaciones gráficas, dados un píxel de origen y uno de destino, el resultado se calcula bit a bit en los bits correspondientes de los píxeles. Es decir, se realiza una operación booleana en cada plano de bits. La `plane_mask` restringe la operación a un subconjunto de planos. La constante macro `AllPlanes` puede usarse para referirse a todos los planos de la pantalla simultáneamente. El resultado se calcula mediante lo siguiente:

((src FUNC dst) AND plane-mask) OR (dst AND (NOT plane-mask))

No se realiza comprobación de rango en los valores de `foreground`, `background` o `plane_mask`. Simplemente se truncan al número apropiado de bits. El ancho de línea (`line-width`) se mide en píxeles y puede ser mayor o igual que uno (línea ancha) o puede ser el valor especial cero (línea fina).

Las líneas anchas se dibujan centradas en la trayectoria descrita por la solicitud gráfica. A menos que se especifique lo contrario por el `join-style` o `cap-style`, el cuadro delimitador de una línea ancha con puntos finales [x1, y1], [x2, y2] y ancho w es un rectángulo con vértices en las siguientes coordenadas reales:

[x1-(w*sn/2), y1+(w*cs/2)], [x1+(w*sn/2), y1-(w*cs/2)],
[x2-(w*sn/2), y2+(w*cs/2)], [x2+(w*sn/2), y2-(w*cs/2)]

Aquí, sn es el seno del ángulo de la línea, y cs es el coseno del ángulo de la línea. Un píxel forma parte de la línea y se dibuja si el centro del píxel está completamente dentro del cuadro delimitador (que se considera que tiene bordes infinitamente finos). Si el centro del píxel está exactamente en el cuadro delimitador, forma parte de la línea si y solo si el interior está inmediatamente a su derecha (dirección x creciente). Los píxeles con centros en un borde horizontal son un caso especial y forman parte de la línea si y solo si el interior o el borde está inmediatamente debajo (dirección y creciente) y el interior o el borde está inmediatamente a la derecha (dirección x creciente).

Las líneas finas (ancho de línea cero) son líneas de un píxel de ancho dibujadas utilizando un algoritmo no especificado y dependiente del dispositivo. Solo hay dos restricciones en este algoritmo.

1.
Si se dibuja una línea sin recortar desde [x1,y1] hasta [x2,y2] y si se dibuja otra línea sin recortar desde [x1+dx,y1+dy] hasta [x2+dx,y2+dy], un punto [x,y] es tocado al dibujar la primera línea si y solo si el punto [x+dx,y+dy] es tocado al dibujar la segunda línea.
2.
El conjunto efectivo de puntos que componen una línea no puede verse afectado por el recorte. Es decir, un punto se toca en una línea recortada si y solo si el punto está dentro de la región de recorte y el punto sería tocado por la línea al dibujarla sin recortar.

Una línea ancha dibujada desde [x1,y1] hasta [x2,y2] siempre dibuja los mismos píxeles que una línea ancha dibujada desde [x2,y2] hasta [x1,y1], sin contar el `cap-style` y `join-style`. Se recomienda que esta propiedad sea cierta para las líneas finas, pero no es obligatorio. Un ancho de línea de cero puede diferir de un ancho de línea de uno en los píxeles que se dibujan. Esto permite el uso de hardware de dibujo de líneas de muchos fabricantes, que puede funcionar muchas veces más rápido que las líneas anchas especificadas con mayor precisión.

En general, dibujar una línea fina será más rápido que dibujar una línea ancha de ancho uno. Sin embargo, debido a sus diferentes algoritmos de dibujo, las líneas finas pueden no combinarse estéticamente bien con las líneas anchas. Si se desea obtener resultados precisos y uniformes en todas las pantallas, un cliente siempre debe usar un ancho de línea de uno en lugar de un ancho de línea de cero.

El `line-style` define qué secciones de una línea se dibujan:

LineSolid Se dibuja toda la trayectoria de la línea.
LineDoubleDash Se dibuja toda la trayectoria de la línea, pero las rayas pares se rellenan de manera diferente a las rayas impares (ver `fill-style`) con el estilo `CapButt` utilizado donde se unen las rayas pares e impares.
LineOnOffDash Solo se dibujan las rayas pares, y el `cap-style` se aplica a todos los extremos internos de las rayas individuales, excepto que `CapNotLast` se trata como `CapButt`.

El `cap-style` define cómo se dibujan los puntos finales de una trayectoria:

CapNotLast Es equivalente a `CapButt`, excepto que para un ancho de línea de cero, el punto final no se dibuja.
CapButt La línea es cuadrada en el punto final (perpendicular a la pendiente de la línea) sin proyección más allá.
CapRound La línea tiene un arco circular con el diámetro igual al ancho de línea, centrado en el punto final. (Es equivalente a `CapButt` para un ancho de línea de cero).
CapProjecting La línea es cuadrada en el extremo, pero la trayectoria continúa más allá del punto final una distancia igual a la mitad del ancho de línea. (Es equivalente a `CapButt` para un ancho de línea de cero).

El `join-style` define cómo se dibujan las esquinas para líneas anchas:

JoinMiter Los bordes exteriores de dos líneas se extienden para encontrarse en un ángulo. Sin embargo, si el ángulo es inferior a 11 grados, se utiliza en su lugar un estilo de unión `JoinBevel`.
JoinRound La esquina es un arco circular con el diámetro igual al ancho de línea, centrado en el punto de unión.
JoinBevel La esquina tiene estilos de punto final `CapButt` con la muesca triangular rellena.

Para una línea con puntos finales coincidentes (x1=x2, y1=y2), cuando el `cap-style` se aplica a ambos puntos finales, la semántica depende del `line-width` y del `cap-style`:

CapNotLast fina Los resultados dependen del dispositivo, pero el efecto deseado es que no se dibuje nada.
CapButt fina Los resultados dependen del dispositivo, pero el efecto deseado es que se dibuje un solo píxel.
CapRound fina Los resultados son los mismos que para CapButt / fina.
CapProjecting fina Los resultados son los mismos que para CapButt / fina.
CapButt ancha No se dibuja nada.
CapRound ancha La trayectoria cerrada es un círculo, centrado en el punto final, y con el diámetro igual al ancho de línea.
CapProjecting ancha La trayectoria cerrada es un cuadrado, alineado con los ejes de coordenadas, centrado en el punto final, y con los lados iguales al ancho de línea.

Para una línea con puntos finales coincidentes (x1=x2, y1=y2), cuando el `join-style` se aplica en uno o ambos puntos finales, el efecto es como si la línea se hubiera eliminado de la trayectoria general. Sin embargo, si la trayectoria total consiste o se reduce a un solo punto unido consigo mismo, el efecto es el mismo que cuando el `cap-style` se aplica en ambos puntos finales.

El `tile/stipple` representa un plano bidimensional infinito, con el `tile/stipple` replicado en todas las dimensiones. Cuando ese plano se superpone al drawable para su uso en una operación gráfica, la esquina superior izquierda de alguna instancia del `tile/stipple` se encuentra en las coordenadas dentro del drawable especificadas por el origen del `tile/stipple`. Los orígenes del `tile/stipple` y del clip se interpretan en relación con el origen del drawable de destino que se especifica en una solicitud gráfica. El pixmap de `tile` debe tener la misma raíz y profundidad que el GC, o se producirá un error `BadMatch`. El pixmap de `stipple` debe tener profundidad uno y debe tener la misma raíz que el GC, o se producirá un error `BadMatch`. Para operaciones de `stipple` donde el `fill-style` es `FillStippled` pero no `FillOpaqueStippled`, el patrón de `stipple` se mosaica en un solo plano y actúa como una máscara de recorte adicional que se aplicará AND a la máscara de recorte. Aunque algunos tamaños pueden ser más rápidos de usar que otros, cualquier tamaño de pixmap se puede usar para mosaicar o estampar.

El `fill-style` define el contenido del origen para las solicitudes de línea, texto y relleno. Para todas las solicitudes de texto y relleno (por ejemplo, `XDrawText`, `XDrawText16`, `XFillRectangle`, `XFillPolygon` y `XFillArc`); para las solicitudes de línea con `line-style` `LineSolid` (por ejemplo, `XDrawLine`, `XDrawSegments`, `XDrawRectangle`, `XDrawArc`); y para las rayas pares en las solicitudes de línea con `line-style` `LineOnOffDash` o `LineDoubleDash`, se aplican los siguientes:

FillSolid Primer plano (`Foreground`)
FillTiled Mosaico (`Tile`)
FillOpaqueStippled Un mosaico con el mismo ancho y alto que el `stipple`, pero con el fondo en todas partes donde el `stipple` tiene un cero y con el primer plano en todas partes donde el `stipple` tiene un uno
FillStippled Primer plano (`Foreground`) enmascarado por `stipple`

NAME

XGCValues — structure for graphics context component values

SYNTAX

struct XGCValues {
    int function;
    unsigned long foreground;
    unsigned long background;
    int line_width;
    int line_style;
    int cap_style;
    int join_style;
    int fill_style;
    int fill_rule;
    int tile;
    int stipple;
    int tile_stride;
    int font;
    int subwindow_mode;
    int graphics_exposures;
    int clip_x_origin;
    int clip_y_origin;
    int clip_mask;
    int dash_offset;
    int dashes;
};

ARGUMENTS

function
Specifies the logical function to use for combining source and destination (e.g. GXcopy).
foreground
Specifies the foreground color, in pixels.
background
Specifies the background color, in pixels.
line_width
Specifies the width of lines, in pixels.
line_style
Specifies the line style. Possible values are LineSolid, LineOnOffDash, LineDoubleDash.
cap_style
Specifies the line cap style. Possible values are CapNotLast, CapButt, CapRound, CapProjecting.
join_style
Specifies the line join style. Possible values are JoinMiter, JoinRound, JoinBevel.
fill_style
Specifies the fill style. Possible values are FillSolid, FillTiled, FillOpaqueStippled, FillStippled.
fill_rule
Specifies the fill rule. Possible values are EvenOddRule or WindingRule.
tile
Specifies a tiling pixmap for FillTiled.
stipple
Specifies a stipple pixmap for FillStippled and FillOpaqueStippled.
tile_stride
Specifies the number of bytes in a row of the tile or stipple pixmap.
font
Specifies the font for text drawing.
subwindow_mode
Specifies the subwindow mode. Possible values are ClipByChildren or IncludeInferiors.
graphics_exposures
Specifies whether GraphicsExpose and NoExpose events are generated for XCopyArea and XCopyPlane requests. Possible values are True or False.
clip_x_origin
Specifies the x-coordinate of the clipping origin relative to the origin of the destination drawable.
clip_y_origin
Specifies the y-coordinate of the clipping origin relative to the origin of the destination drawable.
clip_mask
Specifies the clip mask. This can be a pixmap or None.
dash_offset
Specifies the offset into the dash list for dashed lines.
dashes
Specifies the dash lengths for dashed lines. A single integer value N is interpreted as the list [N, N].

DESCRIPTION

The XGCValues structure is used to set or retrieve components of a graphics context (GC). A graphics context contains various attributes that control how graphics primitives are drawn.

When drawing lines with line-style LineDoubleDash, the odd dashes are controlled by the fill-style in the following manner:

FillSolid Background
FillTiled Same as for even dashes
FillOpaqueStippled Same as for even dashes
FillStippled Background masked by stipple

Storing a pixmap in a GC might or might not result in a copy being made. If the pixmap is later used as the destination for a graphics request, the change might or might not be reflected in the GC. If the pixmap is used simultaneously in a graphics request both as a destination and as a tile or stipple, the results are undefined.

For optimum performance, you should draw as much as possible with the same GC (without changing its components). The costs of changing GC components relative to using different GCs depend on the display hardware and the server implementation. It is quite likely that some amount of GC information will be cached in display hardware and that such hardware can only cache a small number of GCs.

The dashes value is actually a simplified form of the more general patterns that can be set with XSetDashes. Specifying a value of N is equivalent to specifying the two-element list [N, N] in XSetDashes. The value must be nonzero, or a BadValue error results.

The clip-mask restricts writes to the destination drawable. If the clip-mask is set to a pixmap, it must have depth one and have the same root as the GC, or a BadMatch error results. If clip-mask is set to None, the pixels are always drawn regardless of the clip origin. The clip-mask also can be set by calling the XSetClipRectangles or XSetRegion functions. Only pixels where the clip-mask has a bit set to 1 are drawn. Pixels are not drawn outside the area covered by the clip-mask or where the clip-mask has a bit set to 0. The clip-mask affects all graphics requests. The clip-mask does not clip sources. The clip-mask origin is interpreted relative to the origin of whatever destination drawable is specified in a graphics request.

You can set the subwindow-mode to ClipByChildren or IncludeInferiors. For ClipByChildren, both source and destination windows are additionally clipped by all viewable InputOutput children. For IncludeInferiors, neither source nor destination window is clipped by inferiors. This will result in including subwindow contents in the source and drawing through subwindow boundaries of the destination. The use of IncludeInferiors on a window of one depth with mapped inferiors of differing depth is not illegal, but the semantics are undefined by the core protocol.

The fill-rule defines what pixels are inside (drawn) for paths given in XFillPolygon requests and can be set to EvenOddRule or WindingRule. For EvenOddRule, a point is inside if an infinite ray with the point as origin crosses the path an odd number of times. For WindingRule, a point is inside if an infinite ray with the point as origin crosses an unequal number of clockwise and counterclockwise directed path segments. A clockwise directed path segment is one that crosses the ray from left to right as observed from the point. A counterclockwise segment is one that crosses the ray from right to left as observed from the point. The case where a directed line segment is coincident with the ray is uninteresting because you can simply choose a different ray that is not coincident with a segment.

For both EvenOddRule and WindingRule, a point is infinitely small, and the path is an infinitely thin line. A pixel is inside if the center point of the pixel is inside and the center point is not on the boundary. If the center point is on the boundary, the pixel is inside if and only if the polygon interior is immediately to its right (x increasing direction). Pixels with centers on a horizontal edge are a special case and are inside if and only if the polygon interior is immediately below (y increasing direction).

The arc-mode controls filling in the XFillArcs function and can be set to ArcPieSlice or ArcChord. For ArcPieSlice, the arcs are pie-slice filled. For ArcChord, the arcs are chord filled.

The graphics-exposure flag controls GraphicsExpose event generation for XCopyArea and XCopyPlane requests (and any similar requests defined by extensions).

STRUCTURES

The XGCValues structure contains the following members:

  • function: The logical function (GXcopy, GXxor, etc.).
  • foreground: The foreground pixel value.
  • background: The background pixel value.
  • line_width: The line width in pixels.
  • line_style: The line style (LineSolid, LineOnOffDash, LineDoubleDash).
  • cap_style: The cap style (CapButt, CapRound, CapProjecting).
  • join_style: The join style (JoinMiter, JoinRound, JoinBevel).
  • fill_style: The fill style (FillSolid, FillTiled, FillOpaqueStippled, FillStippled).
  • fill_rule: The fill rule (EvenOddRule, WindingRule).
  • tile: The pixmap for tiling.
  • stipple: The pixmap for stippling.
  • tile_stride: The tile or stipple stride.
  • font: The font ID.
  • subwindow_mode: The subwindow mode (ClipByChildren, IncludeInferiors).
  • graphics_exposures: Boolean indicating whether GraphicsExpose events are generated.
  • clip_x_origin: The x-coordinate of the clipping origin.
  • clip_y_origin: The y-coordinate of the clipping origin.
  • clip_mask: The clip mask pixmap or None.
  • dash_offset: The dash offset.
  • dashes: The dash lengths.

DIAGNOSTICS

BadAlloc
The server failed to allocate the requested resource or server memory.
BadDrawable
A value for a Drawable argument does not name a defined Window or Pixmap.
BadFont
A value for a Font or GContext argument does not name a defined Font.
BadGC
A value for a GContext argument does not name a defined GContext.
BadMatch
An InputOnly window is used as a Drawable.
BadMatch
Some argument or pair of arguments has the correct type and range but fails to match in some other way required by the request.
BadPixmap
A value for a Pixmap argument does not name a defined Pixmap.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
