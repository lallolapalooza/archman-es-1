XGetDeviceFocus(3)

Paquete: libxi

Licencias: MIT-open-group, SMLNJ, MIT

XSETDEVICEFOCUS(3)   XSETDEVICEFOCUS(3)

NOMBRE

XSetDeviceFocus, XGetDeviceFocus - controlar el foco de los dispositivos de entrada de extensión

SINOPSIS

#include <X11/extensions/XInput.h>
XSetDeviceFocus( Display *display,
                 XDevice *device,
                 Window focus,
                 int revert_to,
                 Time time);
XGetDeviceFocus( Display *display,
                 XDevice *device,
                 Window *focus_return,
                 int *revert_to_return,
                 int * time_return);

Argumentos

display
       Especifica la conexión con el servidor X.
device
       Especifica el dispositivo cuyo foco se va a consultar o
       cambiar.
focus
       Especifica la ventana, PointerRoot, FollowKeyboard, o
       None.
focus_return
       Devuelve la ventana de foco, PointerRoot, FollowKeyboard, o
       None.
revert_to
       Especifica a dónde revierte el foco de entrada si la ventana
       deja de ser visible. Puedes pasar RevertToParent,
       RevertToPointerRoot, RevertToFollowKeyboard, o
       RevertToNone.
revert_to_return
       Devuelve el estado actual del foco RevertToParent,
       RevertToPointerRoot, RevertToFollowKeyboard, o
       RevertToNone.
time_return
       Devuelve el last_focus_time del dispositivo.
time
       Especifica el tiempo. Puedes pasar una marca de tiempo o
       CurrentTime.

DESCRIPCIÓN

La solicitud XSetDeviceFocus cambia el foco del dispositivo especificado
y su tiempo de último cambio de foco. No tiene ningún efecto si el
tiempo especificado es anterior al tiempo actual de último cambio de
foco o es posterior al tiempo actual del servidor X. De lo contrario, el
tiempo de último cambio de foco se establece en el tiempo especificado
(CurrentTime se reemplaza por el tiempo actual del servidor X).
XSetDeviceFocus hace que el servidor X genere eventos DeviceFocusIn y
DeviceFocusOut.
Dependiendo del argumento focus, ocurre lo siguiente:
  * Si focus es None , todos los eventos del dispositivo se descartan
    hasta que se establezca una nueva ventana de foco, y el argumento
    revert_to se ignora.
  * Si focus es una ventana, se convierte en la ventana de foco del
    dispositivo. Si un evento de dispositivo generado se informaría
    normalmente a esta ventana o a uno de sus inferiores, el evento se
    informará como de costumbre. De lo contrario, el evento se informará
    en relación con la ventana de foco.
  * Si focus es PointerRoot, la ventana de foco se toma dinámicamente
    como la ventana raíz de la pantalla en la que se encuentra el puntero
    en cada evento del dispositivo especificado. En este caso, el argumento
    revert_to se ignora.
  * Si focus es FollowKeyboard, la ventana de foco se toma dinámicamente
    como la ventana a la que se establece el foco del teclado X en cada
    evento de entrada.
La ventana de foco especificada debe ser visible en el momento en que
se llama a XSetDeviceFocus, o se producirá un error BadMatch. Si la
ventana de foco posteriormente deja de ser visible, el servidor X evalúa
el argumento revert_to para determinar la nueva ventana de foco de la
siguiente manera:
  * Si revert_to es RevertToParent, el foco revierte al padre (o al
    ancestro visible más cercano), y el nuevo valor revert_to se toma
    como RevertToNone.
  * Si revert_to es RevertToPointerRoot,
    RevertToFollowKeyboard, o RevertToNone, el foco revierte a
    PointerRoot, FollowKeyboard, o None, respectivamente.
Cuando el foco revierte, el servidor X genera eventos DeviceFocusIn y
DeviceFocusOut, pero el tiempo del último cambio de foco no se ve
afectado.
Los dispositivos de extensión de entrada no están obligados a admitir
la capacidad de tener foco. Intentar establecer el foco de un dispositivo
que no admite esta solicitud resultará en un error BadMatch. Si un
determinado dispositivo puede admitir esta solicitud se puede determinar
por la información devuelta por XOpenDevice. Para aquellos dispositivos
que admiten el foco, XOpenDevice devolverá una estructura XInputClassInfo
con el campo input_class igual a la constante FocusClass (definida en
el archivo XI.h).
XSetDeviceFocus puede generar errores BadDevice, BadMatch, BadValue y
BadWindow.
La solicitud XGetDeviceFocus devuelve la ventana de foco y el estado
actual del foco.
No todos los dispositivos de extensión de entrada pueden tener foco.
Intentar consultar el estado de foco de un dispositivo que no puede tener
foco da como resultado un error BadMatch. Un dispositivo que puede tener
foco devuelve información para la clase de entrada Focus cuando se realiza
una solicitud XOpenDevice.
XGetDeviceFocus puede generar errores BadDevice y BadMatch.

DIAGNÓSTICOS

BadDevice
       Se especificó un dispositivo inválido. El dispositivo especificado
       no existe o no ha sido abierto por este cliente a través de
       XOpenInputDevice. Este error también puede ocurrir si el
       dispositivo especificado es el teclado X o el dispositivo puntero X.
BadValue
       Algún valor numérico cae fuera del rango de valores aceptados
       por la solicitud. A menos que se especifique un rango específico
       para un argumento, se acepta el rango completo definido por el
       tipo del argumento. Cualquier argumento definido como un conjunto
       de alternativas puede generar este error.
BadWindow
       Un valor para un argumento de Ventana no nombra una Ventana
       definida.
BadMatch
       Este error puede ocurrir si se realizó una solicitud XGetDeviceFocus o
       XSetDeviceFocus especificando un dispositivo que la implementación
       del servidor no permite que tenga foco.
