XSetInputFocus(3) FUNCIONES DE XLIB XSetInputFocus(3)

NOMBRE

XSetInputFocus, XGetInputFocus - controlar el foco de entrada

SINTAXIS

int XSetInputFocus(Display *display, Window focus, int revert_to, Time time);

int XGetInputFocus(Display *display, Window *focus_return, int *revert_to_return);

ARGUMENTOS

display
Especifica la conexión con el servidor X.
focus
Especifica la ventana, PointerRoot o None.
focus_return
Devuelve la ventana de foco, PointerRoot o None.
revert_to
Especifica a dónde se revertirá el foco de entrada si la ventana deja de ser visible. Puede pasar RevertToParent, RevertToPointerRoot o RevertToNone.
revert_to_return
Devuelve el estado actual del foco (RevertToParent, RevertToPointerRoot o RevertToNone).
time
Especifica el tiempo. Puede pasar una marca de tiempo o CurrentTime.

DESCRIPCIÓN

La función XSetInputFocus cambia el foco de entrada y la hora del último cambio de foco. No tiene ningún efecto si la hora especificada es anterior a la hora del último cambio de foco actual o es posterior a la hora actual del servidor X. De lo contrario, la hora del último cambio de foco se establece en la hora especificada (CurrentTime se reemplaza por la hora actual del servidor X). XSetInputFocus provoca que el servidor X genere eventos FocusIn y FocusOut.

Dependiendo del argumento de foco, ocurre lo siguiente:

  • Si focus es None, se descartan todos los eventos de teclado hasta que se establezca una nueva ventana de foco, y el argumento revert_to se ignora.
  • Si focus es una ventana, se convierte en la ventana de foco del teclado. Si un evento de teclado generado se informaría normalmente a esta ventana o a uno de sus inferiores, el evento se informa como de costumbre. De lo contrario, el evento se informa en relación con la ventana de foco.
  • Si focus es PointerRoot, la ventana de foco se considera dinámicamente la ventana raíz de la pantalla en la que se encuentra el puntero en cada evento de teclado. En este caso, el argumento revert_to se ignora.

La ventana de foco especificada debe ser visible en el momento en que se llama a XSetInputFocus, o se produce un error BadMatch. Si la ventana de foco posteriormente deja de ser visible, el servidor X evalúa el argumento revert_to para determinar la nueva ventana de foco de la siguiente manera:

  • Si revert_to es RevertToParent, el foco se revierte al padre (o al ancestro visible más cercano), y el nuevo valor de revert_to se toma como RevertToNone.
  • Si revert_to es RevertToPointerRoot o RevertToNone, el foco se revierte a PointerRoot o None, respectivamente. Cuando el foco se revierte, el servidor X genera eventos FocusIn y FocusOut, pero la hora del último cambio de foco no se ve afectada.

XSetInputFocus puede generar errores BadMatch, BadValue y BadWindow.

La función XGetInputFocus devuelve la ventana de foco y el estado actual del foco.

DIAGNÓSTICOS

BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango específico para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
BadWindow
Un valor para un argumento de Ventana no nombra una Ventana definida.
