XChangeKeyboardMapping(3) XLIB FUNCTIONS XChangeKeyboardMapping(3)

NOMBRE

XChangeKeyboardMapping, XGetKeyboardMapping, XDisplayKeycodes, XSetModifierMapping, XGetModifierMapping, XNewModifiermap, XInsertModifiermapEntry, XDeleteModifiermapEntry, XFreeModifiermap, XModifierKeymap - manipular la codificación del teclado y la estructura de codificación del teclado

SINTAXIS

int XChangeKeyboardMapping(Display *display, int first_keycode, int keysyms_per_keycode, KeySym *keysyms, int num_codes);

KeySym *XGetKeyboardMapping(Display *display, KeyCode first_keycode, int keycode_count, int *keysyms_per_keycode_return);

int XDisplayKeycodes(Display *display, int *min_keycodes_return, int *max_keycodes_return);

int XSetModifierMapping(Display *display, XModifierKeymap *modmap);

XModifierKeymap *XGetModifierMapping(Display *display);

XModifierKeymap *XNewModifiermap(int max_keys_per_mod);

XModifierKeymap *XInsertModifiermapEntry(XModifierKeymap *modmap, KeyCode keycode_entry, int modifier);

XModifierKeymap *XDeleteModifiermapEntry(XModifierKeymap *modmap, KeyCode keycode_entry, int modifier);

int XFreeModifiermap(XModifierKeymap *modmap);

ARGUMENTOS

display
Especifica la conexión con el servidor X.
first_keycode
Especifica el primer KeyCode que se va a cambiar o devolver.
keycode_count
Especifica el número de KeyCodes que se van a devolver.
keycode_entry
Especifica el KeyCode.
keysyms
Especifica una matriz de KeySyms.
keysyms_per_keycode
Especifica el número de KeySyms por KeyCode.
keysyms_per_keycode_return
Devuelve el número de KeySyms por KeyCode.
max_keys_per_mod
Especifica el número de entradas KeyCode preasignadas a los modificadores en el mapa.
max_keycodes_return
Devuelve el número máximo de KeyCodes.
min_keycodes_return
Devuelve el número mínimo de KeyCodes.
modifier
Especifica el modificador.
modmap
Especifica la estructura XModifierKeymap.
num_codes
Especifica el número de KeyCodes que se van a cambiar.

DESCRIPCIÓN

La función XChangeKeyboardMapping define los símbolos para el número especificado de KeyCodes comenzando con first_keycode. Los símbolos para los KeyCodes fuera de este rango permanecen sin cambios. El número de elementos en keysyms debe ser:

num_codes * keysyms_per_keycode

El first_keycode especificado debe ser mayor o igual que min_keycode devuelto por XDisplayKeycodes, o se produce un error BadValue. Además, la siguiente expresión debe ser menor o igual que max_keycode, tal como lo devuelve XDisplayKeycodes, o se produce un error BadValue:

first_keycode + num_codes - 1

El símbolo KeySym número N, contando desde cero, para el KeyCode K tiene el siguiente índice en keysyms, contando desde cero:

(K - first_keycode) * keysyms_per_keycode + N

El keysyms_per_keycode especificado puede ser elegido arbitrariamente por el cliente para que sea lo suficientemente grande como para contener todos los símbolos deseados. Un valor especial de KeySym de NoSymbol debe usarse para rellenar los elementos no utilizados para KeyCodes individuales. Es legal que NoSymbol aparezca en posiciones no finales de la lista efectiva para un KeyCode. XChangeKeyboardMapping genera un evento MappingNotify.

No hay ningún requisito de que el servidor X interprete este mapeo. Simplemente se almacena para que los clientes lo lean y escriban.

XChangeKeyboardMapping puede generar errores BadAlloc y BadValue.

La función XGetKeyboardMapping devuelve los símbolos para el número especificado de KeyCodes comenzando con first_keycode. El valor especificado en first_keycode debe ser mayor o igual que min_keycode, tal como lo devuelve XDisplayKeycodes, o se produce un error BadValue. Además, la siguiente expresión debe ser menor o igual que max_keycode, tal como lo devuelve XDisplayKeycodes:

first_keycode + keycode_count - 1

Si esto no es así, se produce un error BadValue. El número de elementos en la lista KeySyms es:

keycode_count * keysyms_per_keycode_return

El símbolo KeySym número N, contando desde cero, para el KeyCode K tiene el siguiente índice en la lista, contando desde cero:

(K - first_code) * keysyms_per_code_return + N

El servidor X elige arbitrariamente el valor keysyms_per_keycode_return para que sea lo suficientemente grande como para informar todos los símbolos solicitados. Se utiliza un valor especial de KeySym de NoSymbol para rellenar los elementos no utilizados para KeyCodes individuales. Para liberar el almacenamiento devuelto por XGetKeyboardMapping, use XFree.

XGetKeyboardMapping puede generar un error BadValue.

La función XDisplayKeycodes devuelve los min-keycodes y max-keycodes admitidos por la pantalla especificada. El número mínimo de KeyCodes devueltos nunca es inferior a 8, y el número máximo de KeyCodes devueltos nunca es superior a 255. No todos los KeyCodes en este rango tienen necesariamente teclas correspondientes.

La función XSetModifierMapping especifica los KeyCodes de las teclas (si las hay) que se van a utilizar como modificadores. Si tiene éxito, el servidor X genera un evento MappingNotify y XSetModifierMapping devuelve MappingSuccess. X permite como máximo 8 teclas modificadoras. Si se especifican más de 8 en la estructura XModifierKeymap, se produce un error BadLength.

El miembro modifiermap de la estructura XModifierKeymap contiene 8 conjuntos de max_keypermod KeyCodes, uno para cada modificador en el orden Shift, Lock, Control, Mod1, Mod2, Mod3, Mod4 y Mod5. Solo los KeyCodes distintos de cero tienen significado en cada conjunto, y los KeyCodes cero se ignoran. Además, todos los KeyCodes distintos de cero deben estar en el rango especificado por min_keycode y max_keycode en la estructura Display, o se produce un error BadValue.

Un servidor X puede imponer restricciones sobre cómo se pueden cambiar los modificadores, por ejemplo, si ciertas teclas no generan transiciones de subida en hardware, si la repetición automática no se puede deshabilitar en ciertas teclas, o si no se admiten múltiples teclas modificadoras. Si se viola alguna de estas restricciones, la respuesta de estado es MappingFailed y ninguno de los modificadores se cambia. Si los nuevos KeyCodes especificados para un modificador difieren de los definidos actualmente y alguna tecla (actual o nueva) para ese modificador está en el estado lógicamente presionado, XSetModifierMapping devuelve MappingBusy y ninguno de los modificadores se cambia.

XSetModifierMapping puede generar errores BadAlloc y BadValue.

La función XGetModifierMapping devuelve un puntero a una estructura XModifierKeymap recién creada que contiene las teclas que se utilizan como modificadores. La estructura debe liberarse después de su uso llamando a XFreeModifiermap. Si solo aparecen valores cero en el conjunto para cualquier modificador, ese modificador se deshabilita.

La función XNewModifiermap devuelve un puntero a la estructura XModifierKeymap para su uso posterior.

La función XInsertModifiermapEntry agrega el KeyCode especificado al conjunto que controla el modificador especificado y devuelve la estructura XModifierKeymap resultante (expandida según sea necesario).

La función XDeleteModifiermapEntry elimina el KeyCode especificado del conjunto que controla el modificador especificado y devuelve un puntero a la estructura XModifierKeymap resultante.

XDeleteModifiermapEntry(3) - Arch manual pages

NAME

XDeleteModifiermapEntry, XInsertModifiermapEntry, XSetModifierMapping, XGetModifierMapping - delete and insert modifier mapping entries, set and get modifier mappings

SYNTAX

    int XDeleteModifiermapEntry(XModifierKeymap *modmap, KeyCode keycode, int modifier);
    XModifierKeymap *XInsertModifiermapEntry(XModifierKeymap *modmap, KeyCode keycode, int modifier);
    int XSetModifierMapping(Display *display, XModifierKeymap *modmap);
    XModifierKeymap *XGetModifierMapping(Display *display);

ARGUMENTS

display
Specifies the connection to the X server.
keycode
Specifies the keycode to be deleted or inserted.
modifier
Specifies the modifier name. This must be one of ShiftMapIndex, LockMapIndex, ControlMapIndex, ModMapIndex, AltMapIndex, SuperMapIndex, HyperMapIndex, or MetaMapIndex.
modmap
Specifies the modifier keymap structure. If NULL, XInsertModifiermapEntry allocates a new structure. If the structure is not NULL, XInsertModifiermapEntry adds the modifier to the existing structure. You must free the returned structure using XFreeModifiermap(3) when it is no longer needed.

DESCRIPTION

The function XDeleteModifiermapEntry removes the specified keycode from the specified modifier map. It returns zero if the keycode was found and removed, and one if the keycode was not found in the specified map.

The function XInsertModifiermapEntry adds the specified keycode to the specified modifier map. If the specified map is NULL, it allocates and returns a new modifier map. If the specified map is not NULL, it adds the keycode to the existing map and returns the map. It also returns the number of keycodes in the map after the insertion (if the map was not NULL). If the map is NULL, it returns the number of keycodes in the newly allocated map. If the keycode is already present in the map, the map is unchanged and the function returns the current number of keycodes in the map. You are responsible for freeing the returned structure using XFreeModifiermap(3).

The function XSetModifierMapping sets the modifier mappings for the specified display. It returns Success if the modifier mappings were set successfully, or BadRequest if the modifier map is invalid. It returns Busy if the modifier device is grabbed by another client.

The function XGetModifierMapping returns the current modifier mappings for the specified display. If the server cannot allocate the required memory, it returns NULL. You are responsible for freeing the returned structure using XFreeModifiermap(3).

The XModifierKeymap structure returned by XGetModifierMapping and potentially allocated by XInsertModifiermapEntry should be freed by the caller using XFreeModifiermap.

STRUCTURES

The XModifierKeymap structure contains:

typedef struct {
        int max_keypermod;      /* This server's max number of keys per modifier */
        KeyCode *modifiermap;   /* An 8 by max_keypermod array of the modifiers */
} XModifierKeymap;

DIAGNOSTICS

BadAlloc
The server failed to allocate the requested resource or server memory.
BadMatch
A value for an argument is invalid or out of range. This error is generated by the server when a client's request has a value that is not valid for the specified context. For example, a value out of range, or a value that is not compatible with the requested type. This error can also be generated if a client attempts to perform an operation that is not supported by the server or if a client tries to access a resource that it does not own.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
