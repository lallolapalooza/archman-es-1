XSetErrorHandler(3) FUNCIONES DE XLIB XSetErrorHandler(3)

NOMBRE

XSetErrorHandler, XGetErrorText, XDisplayName, XSetIOErrorHandler, XSetIOErrorExitHandler, XGetErrorDatabaseText - manejadores de errores predeterminados

SINTAXIS

int (*XSetErrorHandler(int (*handler)(Display *, XErrorEvent *)))();

int XGetErrorText(Display *display, int code, char *buffer_return, int length);

char *XDisplayName(_Xconst char *string);

int (*XSetIOErrorHandler(int (*handler)(Display *)))();

void (*XSetIOErrorExitHandler(Display *display, void (*handler)(Display *, void *), void *user_data))();

int XGetErrorDatabaseText(Display *display, _Xconst char *name, _Xconst char *message, _Xconst char *default_string, char *buffer_return, int length);

ARGUMENTOS

buffer_return
Devuelve la descripción del error.
code
Especifica el código de error para el cual desea obtener una descripción.
default_string
Especifica el mensaje de error predeterminado si no se encuentra ninguno en la base de datos.
display
Especifica la conexión con el servidor X.
handler
Especifica el manejador de errores proporcionado por el programa.
length
Especifica el tamaño del búfer.
message
Especifica el tipo del mensaje de error.
name
Especifica el nombre de la aplicación.
string
Especifica la cadena de caracteres.

DESCRIPCIÓN

Xlib generalmente llama al manejador de errores proporcionado por el programa siempre que se recibe un error. No se llama en errores BadName de las solicitudes de protocolo OpenFont, LookupColor o AllocNamedColor, ni en errores BadFont de una solicitud de protocolo QueryFont. Estos errores generalmente se reflejan de vuelta al programa a través de la interfaz procedimental. Dado que no se asume que esta condición es fatal, es aceptable que su manejador de errores retorne; el valor retornado se ignora. Sin embargo, el manejador de errores no debe llamar a ninguna función (directa o indirectamente) en la pantalla que genere solicitudes de protocolo o que busque eventos de entrada. Se devuelve el manejador de errores anterior.

La función XGetErrorText copia una cadena terminada en null que describe el código de error especificado en el búfer proporcionado. El texto devuelto está en la codificación de la configuración regional actual. Se recomienda utilizar esta función para obtener una descripción del error, ya que las extensiones de Xlib pueden definir sus propios códigos y cadenas de error.

La función XDisplayName devuelve el nombre de la pantalla que XOpenDisplay intentaría utilizar. Si se especifica una cadena NULL, XDisplayName busca en el entorno el nombre de la pantalla y devuelve el nombre de pantalla que XOpenDisplay intentaría utilizar. Esto facilita informar al usuario qué pantalla exacta intentó abrir el programa cuando falló el intento inicial de conexión.

La función XSetIOErrorHandler establece el manejador de errores fatales de E/S. Xlib llama al manejador de errores proporcionado por el programa si ocurre algún tipo de error de llamada al sistema (por ejemplo, se perdió la conexión con el servidor). Se asume que esta es una condición fatal y la rutina llamada normalmente no debería retornar. Si el manejador de errores de E/S retorna, el proceso cliente sale por defecto; este comportamiento puede ser modificado con la función XSetIOErrorExitHandler.

Tenga en cuenta que se devuelve el manejador de errores anterior.

La función XGetErrorDatabaseText devuelve un mensaje terminado en null (o el mensaje predeterminado) de la base de datos de mensajes de error. Xlib utiliza esta función internamente para buscar sus mensajes de error. Se asume que el texto en el argumento default_string está en la codificación de la configuración regional actual, y el texto almacenado en el argumento buffer_return está en la codificación de la configuración regional actual.

El argumento name generalmente debería ser el nombre de su aplicación. El argumento message debe indicar qué tipo de mensaje de error desea. Si el nombre y el mensaje no están en la codificación de caracteres portátil de host, el resultado depende de la implementación. Xlib utiliza tres "nombres de aplicación" predefinidos para reportar errores. En estos nombres, las mayúsculas y minúsculas importan.

XProtoError
El número de error de protocolo se utiliza como cadena para el argumento message.
XlibMessage
Estas son las cadenas de mensajes que utiliza internamente la biblioteca.
XRequest
Para una solicitud de protocolo principal, el número de protocolo de solicitud principal se utiliza para el argumento message. Para una solicitud de extensión, el nombre de la extensión (como lo proporciona InitExtension) seguido de un punto (.) y el número de protocolo de solicitud menor se utiliza para el argumento message. Si no se encuentra ninguna cadena en la base de datos de errores, se devuelve default_string en el argumento buffer.
