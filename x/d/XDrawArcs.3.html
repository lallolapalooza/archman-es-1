NOMBRE

XDrawArc, XDrawArcs, XArc - dibujar arcos y estructura de arco

SINTAXIS

int XDrawArc(Display *display, Drawable d, GC gc, int x, int y, unsigned int width, unsigned int height, int angle1, int angle2);

int XDrawArcs(Display *display, Drawable d, GC gc, XArc *arcs, int narcs);

ARGUMENTOS

angle1
Especifica el inicio del arco relativo a la posición de las tres en punto desde el centro, en unidades de grados * 64.
angle2
Especifica la trayectoria y la extensión del arco relativas al inicio del arco, en unidades de grados * 64.
arcs
Especifica una matriz de arcos.
d
Especifica el drawable.
display
Especifica la conexión con el servidor X.
gc
Especifica el GC.
narcs
Especifica el número de arcos en la matriz.
width

height
Especifican el ancho y el alto, que son los ejes mayor y menor del arco.
x

y
Especifican las coordenadas x e y, que son relativas al origen del drawable y especifican la esquina superior izquierda del rectángulo delimitador.

DESCRIPCIÓN

XDrawArc dibuja un único arco circular o elíptico, y XDrawArcs dibuja múltiples arcos circulares o elípticos. Cada arco se especifica mediante un rectángulo y dos ángulos. El centro del círculo o la elipse es el centro del rectángulo, y los ejes mayor y menor se especifican por el ancho y el alto. Los ángulos positivos indican movimiento en sentido contrario a las agujas del reloj y los ángulos negativos indican movimiento en sentido de las agujas del reloj. Si la magnitud de angle2 es mayor que 360 grados, XDrawArc o XDrawArcs la truncan a 360 grados.

Para un arco especificado como [x,y,width,height,angle1,angle2] , el origen de los ejes mayor y menor está en [x+width2,y+height2] , y la trayectoria infinitamente delgada que describe el círculo o elipse completo interseca el eje horizontal en [x,y+height2] y [x+width,y+height2] e interseca el eje vertical en [x+width2,y] y [x+width2,y+height] . Estas coordenadas pueden ser fraccionarias y, por lo tanto, no se truncan a coordenadas discretas. La trayectoria debe definirse mediante la trayectoria matemática ideal. Para una línea ancha con un ancho de línea lw, los contornos delimitadores para el relleno se dan por las dos trayectorias infinitamente delgadas que consisten en todos los puntos cuya distancia perpendicular a la trayectoria del círculo/elipse es igual a lw/2 (que puede ser un valor fraccionario). El estilo de borde y el estilo de unión se aplican igual que para una línea correspondiente a la tangente del círculo/elipse en el punto final.

Para un arco especificado como [x,y,width,height,angle1,angle2] , los ángulos deben especificarse en el sistema de coordenadas efectivamente sesgado de la elipse (para un círculo, los ángulos y los sistemas de coordenadas son idénticos). La relación entre estos ángulos y los ángulos expresados en el sistema de coordenadas normal de la pantalla (medidos con un transportador) es la siguiente:


angulo-sesgado=atantan(angulo-normal)*widthheight+ajuste

El ángulo sesgado y el ángulo normal se expresan en radianes (en lugar de grados escalados por 64) en el rango [0,2π] y donde atan devuelve un valor en el rango [−π2,π2] y ajuste es:

%0% para angulo-normal en el rango % [ 0 , ~pi sobre 2 ]%
%pi% para angulo-normal en el rango % [ pi sobre 2 , ~{3 pi} sobre 2 ]%
%2 pi% para angulo-normal en el rango % [ {3 pi} sobre 2 , ~2 pi ]%

Para cualquier arco dado, XDrawArc y XDrawArcs no dibujan un píxel más de una vez. Si dos arcos se unen correctamente y si el ancho de línea es mayor que cero y los arcos se cruzan, XDrawArc y XDrawArcs no dibujan un píxel más de una vez. De lo contrario, los píxeles que se cruzan de los arcos que se cruzan se dibujan varias veces. Especificar un arco con un punto final y una extensión en sentido horario dibuja los mismos píxeles que especificar el otro punto final y una extensión equivalente en sentido antihorario, excepto en la medida en que afecte a las uniones.

Si el último punto de un arco coincide con el primer punto del arco siguiente, los dos arcos se unirán correctamente. Si el primer punto del primer arco coincide con el último punto del último arco, los dos arcos se unirán correctamente. Al especificar un eje como cero, se puede dibujar una línea horizontal o vertical. Los ángulos se calculan basándose únicamente en el sistema de coordenadas e ignoran la relación de aspecto.

Ambas funciones utilizan estos componentes del GC: función, máscara de plano, ancho de línea, estilo de línea, estilo de borde, estilo de unión, estilo de relleno, modo de subventana, origen-x-recorte, origen-y-recorte y máscara de recorte. También utilizan estos componentes dependientes del modo del GC: color de frente, color de fondo, mosaico, patrón, origen-x-mosaico-patrón, origen-y-mosaico-patrón, desplazamiento de guiones y lista de guiones.

XDrawArc y XDrawArcs pueden generar errores BadDrawable, BadGC y BadMatch.

ESTRUCTURAS

La estructura XArc contiene:

typedef struct {
	short x, y;
	unsigned short width, height;
	short angle1, angle2;             /* Grados * 64 */
} XArc;

Todos los miembros x e y son enteros con signo. Los miembros width y height son enteros sin signo de 16 bits. Se debe tener cuidado de no generar coordenadas y tamaños fuera de los rangos de 16 bits, ya que el protocolo solo tiene campos de 16 bits para estos valores.

BadDrawable

BadGC
Un valor para un argumento GContext no nombra un GContext definido.
BadMatch
Se utiliza una ventana de tipo InputOnly como Drawable.

XDrawArcs(3)

NAME

XDrawArcs - draw arcs

SYNTAX

cc [flags] file ... -lX11 [libraries]

#include <X11/Xlib.h> 

int XDrawArcs(Display *display, Drawable d, GC gc, XArc *arcs, int narcs)

ARGUMENTS

display
Specifies the connection to the X server.
d
Specifies the drawable (window or pixmap) of the GC.
gc
Specifies the graphics context.
arcs
Specifies an array of XArc structures, which contain the arcs to be drawn.
narcs
Specifies the number of XArc structures in the array.

DESCRIPTION

The XDrawArcs function draws multiple arcs. The arcs are specified by the arcs argument, which is an array of XArc structures. Each XArc structure contains the bounding box, start angle, and end angle for an arc.

The angles are specified in units of 1/64th of a degree. The angles are measured relative to the positive x-axis. A positive angle means a counter-clockwise rotation. The start angle is the angle where the arc begins, and the end angle is the angle where the arc ends.

The arcs are drawn in the order they appear in the array. If the GC foreground is not None, the arcs are drawn using the GC foreground pixel. If the GC background is not None, the arcs are drawn using the GC background pixel.

The XDrawArcs function returns the number of arcs drawn. This value can be less than the number of arcs requested if the drawing operation is truncated by the drawable boundary.

STRUCTURES

XArc structures are defined as follows:

typedef struct {
    short x;
    short y;
    unsigned short width;
    unsigned short height;
    int start_angle;
    int end_angle;
} XArc;

Where:

x, y
Specify the coordinates of the upper-left corner of the bounding box.
width, height
Specify the width and height of the bounding box.
start_angle
Specifies the starting angle of the arc in 1/64th of a degree.
end_angle
Specifies the ending angle of the arc in 1/64th of a degree.

DIAGNOSTICS

A non-zero status is returned if the arc is successfully drawn. Otherwise, zero is returned.

If any of the arcs are outside the drawable, they are clipped.

If the specified GC is not valid, a BadGC error is generated. If the specified drawable d is not valid, a BadDrawable error is generated. If the specified display is not valid, a BadDisplay error is generated.

The following errors can occur:

BadGC
A value for a graphics context is not a valid graphics context.
BadDrawable
A value is not a valid drawable.
BadValue
A value is out of range.

Any of the following arguments can cause a BadValue error:

display
If the specified display is not valid.
d
If the specified drawable is not valid.
gc
If the specified graphics context is not valid.
narcs
If the specified number of arcs is negative.

The XDrawArcs function can also generate a BadMatch error if the drawable and the GC are not compatible.

If the arguments are of the correct type and range but fail to match in some other way required by the request, a BadMatch error may be generated.
