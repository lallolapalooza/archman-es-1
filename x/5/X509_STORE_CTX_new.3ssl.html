DESCRIPCIÓN

Estas funciones inicializan una estructura X509_STORE_CTX para su uso posterior por X509_verify_cert(3) o X509_STORE_CTX_verify(3).

X509_STORE_CTX_new_ex() devuelve una estructura X509_STORE_CTX recién inicializada asociada con el contexto de librería especificado libctx y la cadena de consulta de propiedades propq. Cualquier algoritmo criptográfico que se obtenga durante el procesamiento con X509_STORE_CTX utilizará ese contexto de librería y cadena de consulta de propiedades.

X509_STORE_CTX_new() es lo mismo que X509_STORE_CTX_new_ex() excepto que se utiliza el contexto de librería predeterminado y una cadena de consulta de propiedades NULL.

X509_STORE_CTX_cleanup() limpia internamente una estructura X509_STORE_CTX. Es utilizada por X509_STORE_CTX_init() y X509_STORE_CTX_free().

X509_STORE_CTX_free() libera completamente ctx. Después de esta llamada ctx ya no es válido. Si ctx es NULL no se hace nada.

X509_STORE_CTX_init() configura ctx para una operación de verificación posterior.

X509_STORE_CTX_init() inicializa el estado interno y los recursos del ctx dado. Entre otras cosas, establece los parámetros de verificación asociados con el nombre del método "default", que incluye el propósito "any", y toma prestados los punteros de las funciones de devolución de llamada de trust_store (a menos que sea NULL). Debe llamarse antes de cada llamada a X509_verify_cert(3) o X509_STORE_CTX_verify(3), es decir, un contexto solo es válido para una verificación. Si desea verificar un certificado o cadena adicional con el mismo ctx, debe llamar de nuevo a X509_STORE_CTX_init(). La tienda de certificados confiables se establece en trust_store de tipo X509_STORE. Esto puede ser NULL porque no hay certificados confiables o porque se proporcionan simplemente como una lista usando X509_STORE_CTX_set0_trusted_stack(). El certificado a verificar se establece en target, y una lista de certificados adicionales puede proporcionarse en untrusted, que no serán confiables pero pueden usarse para construir la cadena. El certificado target no se copia (su contador de referencias no se actualiza), y el llamador no debe liberarlo antes de que la verificación se complete. Cada uno de los parámetros trust_store, target y untrusted puede ser NULL. Sin embargo, tenga en cuenta que X509_verify_cert(3) y X509_STORE_CTX_verify(3) necesitarán un objetivo de verificación. Esto también se puede establecer usando X509_STORE_CTX_set_cert(). Para X509_STORE_CTX_verify(3), que toma por defecto el primer elemento de la lista de certificados no confiables como su objetivo de verificación, esto también se puede establecer indirectamente usando X509_STORE_CTX_set0_untrusted().

X509_STORE_CTX_init_rpk() configura ctx para una operación de verificación posterior de la clave pública sin procesar target. Se comporta de manera similar a X509_STORE_CTX_init(). La clave pública sin procesar target también se puede suministrar por separado, a través de X509_STORE_CTX_set0_rpk(). La clave pública target no se copia (su contador de referencias no se actualiza), y el llamador no debe liberarla antes de que la verificación se complete.

X509_STORE_CTX_set0_trusted_stack() establece el conjunto de certificados confiables de ctx a sk. Esta es una forma alternativa de especificar certificados confiables en lugar de usar un X509_STORE cuando su complejidad no es necesaria o para asegurarse de que solo el conjunto dado sk de certificados es confiable.

X509_STORE_CTX_set_cert() establece el certificado objetivo a verificar en ctx a target. El certificado objetivo no se copia (su contador de referencias no se actualiza), y el llamador no debe liberarlo antes de que la verificación se complete.

X509_STORE_CTX_set0_rpk() establece la clave pública sin procesar objetivo a verificar en ctx a target; una clave pública sin procesar no nula antepone cualquier certificado objetivo, el cual es ignorado. La clave pública target no se copia (su contador de referencias no se actualiza), y el llamador no debe liberarla antes de que la verificación se complete.

X509_STORE_CTX_set0_verified_chain() establece la cadena validada a chain. La propiedad de la cadena se transfiere a ctx, por lo que el llamador no debe liberarla.

X509_STORE_CTX_get0_chain() devuelve el puntero interno utilizado por ctx que contiene la cadena construida (salida).

X509_STORE_CTX_get0_rpk() devuelve el puntero interno utilizado por ctx que contiene la clave pública sin procesar.

X509_STORE_CTX_set0_crls() establece un conjunto de CRLs a usar para ayudar a la verificación del certificado a sk. Estas CRLs solo se usarán si la verificación de CRL está habilitada en la estructura X509_VERIFY_PARAM asociada. Esto podría usarse donde se proporcionan CRLs adicionales "útiles" como parte de un protocolo, por ejemplo en una estructura PKCS#7.

X509_STORE_CTX_get0_param() recupera un puntero interno a los parámetros de verificación asociados con ctx.

X509_STORE_CTX_set0_param() establece el puntero interno de parámetros de verificación a param. Después de esta llamada, param no debe usarse.

X509_STORE_CTX_get0_untrusted() recupera un puntero interno a la pila de certificados no confiables asociados con ctx.

X509_STORE_CTX_set0_untrusted() establece el puntero interno a la pila de certificados no confiables asociados con ctx a sk. X509_STORE_CTX_verify() tomará el primer elemento, si lo hay, como su objetivo predeterminado si el certificado objetivo no está establecido explícitamente.

The structure X509_STORE_CTX is the context structure used during the certificate chain verification process. Functions that manipulate this structure are described below.

FUNCTIONS

X509_STORE_CTX_new(), X509_STORE_CTX_new_ex(), X509_STORE_CTX_init(), X509_STORE_CTX_init_rpk(), X509_STORE_CTX_free(), and X509_STORE_CTX_cleanup() are used to create and destroy context structures.

X509_STORE_CTX_new() allocates and initialises a new context structure.

X509_STORE_CTX_new_ex() allocates and initialises a new context structure and registers a callback cb. This callback is invoked when a client certificate is requested.

X509_STORE_CTX_init() initialises an existing context structure pointed to by ctx. The verification will be performed using the parameters found in the certificate store st. The certificate to be verified is x509 and the chain of intermediate certificates is sk. If sk is NULL, then no intermediate certificates are used.

X509_STORE_CTX_init_rpk() initialises an existing context structure pointed to by ctx for Root Public Key (RPK) based verification. The certificate to be verified is cert, its associated public key is pkey and the chain of intermediate certificates is chain. If chain is NULL, then no intermediate certificates are used.

X509_STORE_CTX_free() and X509_STORE_CTX_cleanup() free up the context structure.

X509_STORE_CTX_verify() performs the certificate chain verification.

X509_STORE_CTX_get_ex_data() and X509_STORE_CTX_set_ex_data() are generic functions to get and set arbitrary data associated with the context. The idx parameter is an index obtained from a previous call to X509_get_ex_new_index(3). See X509_STORE_CTX_get_ex_new_index(3) for details.

X509_STORE_CTX_get_current_cert() returns the certificate currently being processed by the verification process.

X509_STORE_CTX_get0_chain() returns the internal pointer used by the ctx that contains the validated chain. This chain does not count the first element.

X509_STORE_CTX_get0_chain() returns the internal pointer used by the ctx that contains the validated chain.

Details of the chain building and checking process are described in "Certification Path Building" in openssl-verification-options(1) and "Certification Path Validation" in openssl-verification-options(1).

X509_STORE_CTX_set0_verified_chain() sets the validated chain used by ctx to be chain. Ownership of the chain is transferred to ctx, and so it should not be free'd by the caller.

X509_STORE_CTX_set_default() looks up and sets the default verification method. This uses the function X509_VERIFY_PARAM_lookup() to find the set of parameters associated with the given verification method name. Among others, the parameters determine the trust model and verification purpose. More detail, including the list of currently predefined methods, is described for the -verify_name command-line option in "Verification Options" in openssl-verification-options(1).

X509_STORE_CTX_set_verify() provides the capability for overriding the default verify function. This function is responsible for verifying chain signatures and expiration times.

A verify function is defined as an X509_STORE_CTX_verify type which has the following signature:

int (*verify)(X509_STORE_CTX *);

This function should receive the current X509_STORE_CTX as a parameter and return 1 on success or 0 on failure.

X509 certificates may contain information about what purposes keys contained within them can be used for. For example "TLS WWW Server Authentication" or "Email Protection". This "key usage" information is held internally to the certificate itself. In addition the trust store containing trusted certificates can declare what purposes we trust different certificates for. This "trust" information is not held within the certificate itself but is "meta" information held alongside it. This "meta" information is associated with the certificate after it is issued and could be determined by a system administrator. For example a certificate might declare that it is suitable for use for both "TLS WWW Server Authentication" and "TLS Client Authentication", but a system administrator might only trust it for the former. An X.509 certificate extension exists that can record extended key usage information to supplement the purpose information described above. This extended mechanism is arbitrarily extensible and not well suited for a generic library API; applications that need to validate extended key usage information in certificates will need to define a custom "purpose" (see below) or supply a nondefault verification callback (X509_STORE_set_verify_cb_func(3)).

X509_STORE_CTX_set_ocsp_resp() sets the OCSP response(s) for the verification of a certificate chain or for including in the TLS handshake, when the client requests OCSP stapling. The stack of OCSP responses sk is not copied but just stored to the context. ctx holds a pointer to the stack, so the stack must outlive the ctx.

X509_STORE_CTX_set_purpose() sets the purpose for the target certificate being verified in the ctx. Built-in available values for the purpose argument are X509_PURPOSE_SSL_CLIENT, X509_PURPOSE_SSL_SERVER, X509_PURPOSE_NS_SSL_SERVER, X509_PURPOSE_SMIME_SIGN, X509_PURPOSE_SMIME_ENCRYPT, X509_PURPOSE_CRL_SIGN, X509_PURPOSE_ANY, X509_PURPOSE_OCSP_HELPER, X509_PURPOSE_TIMESTAMP_SIGN and X509_PURPOSE_CODE_SIGN. It is also possible to create a custom purpose value. Setting a purpose requests that the key usage and extended key usage (EKU) extensions optionally declared within the certificate and its chain are verified to be consistent with that purpose. For SSL client, SSL server, and S/MIME purposes, the EKU is checked also for the CA certificates along the chain, including any given trust anchor certificate. Potentially also further checks are done (depending on the purpose given). Every purpose also has an associated default trust value, which will also be set at the same time. During verification, this trust setting will be verified to check whether it is consistent with the trust set by the system administrator for certificates in the chain.

X509_STORE_CTX_set_trust() sets the trust value for the target certificate being verified in the ctx. Built-in available values for the trust argument are X509_TRUST_COMPAT, X509_TRUST_SSL_CLIENT, X509_TRUST_SSL_SERVER, X509_TRUST_EMAIL, X509_TRUST_OBJECT_SIGN, X509_TRUST_OCSP_SIGN, X509_TRUST_OCSP_REQUEST and X509_TRUST_TSA. It is also possible to create a custom trust value. Since X509_STORE_CTX_set_purpose() also sets the trust value it is normally sufficient to only call that function. If both are called then X509_STORE_CTX_set_trust() should be called after X509_STORE_CTX_set_purpose() since the trust setting of the last call will be used.

It should not normally be necessary for end user applications to call X509_STORE_CTX_purpose_inherit() directly. Typically applications should call X509_STORE_CTX_set_purpose() or X509_STORE_CTX_set_trust() instead. Using this function it is possible to set the purpose and trust values for the ctx at the same time. Both ctx and its internal verification parameter pointer must not be NULL. The def_purpose and purpose arguments can have the same purpose values as described for X509_STORE_CTX_set_purpose() above. The trust argument can have the same trust values as described in X509_STORE_CTX_set_trust() above. Any of the def_purpose, purpose or trust values may also have the value 0 to indicate that the supplied parameter should be ignored. After calling this function the purpose to be used for verification is set from the purpose argument unless the purpose was already set in ctx before, and the trust is set from the trust argument unless the trust was already set in ctx before. If trust is 0 then the trust value will be set from the default trust value for purpose. If the default trust value for the purpose is X509_TRUST_DEFAULT and trust is 0 then the default trust value associated with the def_purpose value is used for the trust setting instead.

NOTES

The certificates and CRLs in a store are used internally and should not be freed up until after the associated X509_STORE_CTX is freed.

BUGS

The certificates and CRLs in a context are used internally and should not be freed up until after the associated X509_STORE_CTX is freed. Copies should be made or reference counts increased instead.

RETURN VALUES

X509_STORE_CTX_new() returns a newly allocated context or NULL if an error occurred.

X509_STORE_CTX_init() and X509_STORE_CTX_init_rpk() return 1 for success or 0 if an error occurred.

X509_STORE_CTX_get0_param() returns a pointer to an X509_VERIFY_PARAM structure or NULL if an error occurred.

X509_STORE_CTX_get0_rpk() returns a pointer to an EVP_PKEY structure if present, or NULL if absent.

X509_STORE_CTX_cleanup(), X509_STORE_CTX_free(), X509_STORE_CTX_set0_trusted_stack(), X509_STORE_CTX_set_cert(), X509_STORE_CTX_set0_crls() and X509_STORE_CTX_set0_param() do not return values.

X509_STORE_CTX_set_default() returns 1 for success or 0 if an error occurred.

X509_STORE_CTX_get_num_untrusted() returns the number of untrusted certificates used.

HISTORY

The X509_STORE_CTX_set0_crls() function was added in OpenSSL 1.0.0. The X509_STORE_CTX_get_num_untrusted() function was added in OpenSSL 1.1.0. The X509_STORE_CTX_new_ex() function was added in OpenSSL 3.0. The X509_STORE_CTX_init_rpk(), X509_STORE_CTX_get0_rpk(), and X509_STORE_CTX_set0_rpk() functions were added in OpenSSL 3.2. X509_STORE_CTX_set_ocsp_resp() function was added in OpenSSL 3.6.

There is no need to call X509_STORE_CTX_cleanup() explicitly since OpenSSL 3.0.

    void *X509_STORE_CTX_get_ex_data(X509_STORE_CTX *ctx, int index);
    const X509_VERIFY_PARAM *X509_STORE_CTX_get0_param(const X509_STORE_CTX *ctx);
    int X509_STORE_CTX_set0_param(X509_STORE_CTX *ctx, X509_VERIFY_PARAM *param);

DESCRIPCIÓN

Estas funciones gestionan el contexto de verificación de certificados X509. El contexto de verificación contiene toda la información necesaria para realizar una verificación de cadena de certificados.

X509_STORE_CTX_new crea y devuelve un nuevo contexto de verificación de certificados X509 vacío. El contexto debe ser liberado posteriormente por X509_STORE_CTX_free.

X509_STORE_CTX_init inicializa un contexto de verificación existente. El parámetro store es el almacén de certificados a usar, el parámetro x509 es el certificado del sujeto a verificar, y verify_fn es una función de devolución de llamada opcional para la verificación personalizada.

X509_STORE_CTX_set0_trusted_certs establece la lista de certificados de confianza a usar para la verificación. Estos certificados anulan los certificados de confianza encontrados en el store.

X509_STORE_CTX_set0_verify_callback establece una función de devolución de llamada personalizada que se llamará durante el proceso de verificación. Esta función puede usarse para realizar verificaciones personalizadas o para controlar el flujo de verificación.

X509_STORE_CTX_get0_cert devuelve el certificado del sujeto que se está verificando.

X509_STORE_CTX_get0_chain devuelve la cadena de certificados construida por el proceso de verificación.

X509_STORE_CTX_get0_trusted_obj devuelve el objeto de certificado de confianza actual que se está utilizando para la verificación.

X509_STORE_CTX_get0_policy_tree devuelve el árbol de políticas de la cadena de certificados verificada.

X509_STORE_CTX_get_error devuelve el código de error de la última operación de verificación.

X509_STORE_CTX_set_depth establece la profundidad máxima de la cadena de certificados a verificar.

X509_STORE_CTX_get_depth devuelve la profundidad máxima de la cadena de certificados.

X509_STORE_CTX_purpose devuelve el propósito para el cual se está verificando el certificado.

X509_STORE_CTX_set_purpose establece el propósito para el cual se está verificando el certificado.

X509_STORE_CTX_set_ex_data establece datos específicos de la aplicación asociados con el contexto de verificación.

X509_STORE_CTX_get_ex_data recupera datos específicos de la aplicación asociados con el contexto de verificación.

X509_STORE_CTX_get0_param devuelve los parámetros de verificación actuales.

X509_STORE_CTX_set0_param establece los parámetros de verificación para el contexto.

NOTAS

El contexto de verificación de certificados X509 es una estructura importante utilizada por la biblioteca OpenSSL para verificar la autenticidad de los certificados X509. Permite la personalización del proceso de verificación a través de devoluciones de llamada y la configuración de parámetros.

ERRORES

Los errores de verificación se pueden recuperar utilizando X509_STORE_CTX_get_error.

VALORES DE RETORNO

X509_STORE_CTX_new devuelve un puntero a un nuevo X509_STORE_CTX en caso de éxito, o NULL en caso de error.

X509_STORE_CTX_init devuelve 1 en caso de éxito, o 0 en caso de error.

X509_STORE_CTX_set0_trusted_certs y X509_STORE_CTX_set0_verify_callback no devuelven ningún valor.

X509_STORE_CTX_get0_cert, X509_STORE_CTX_get0_chain, X509_STORE_CTX_get0_trusted_obj, X509_STORE_CTX_get0_policy_tree, X509_STORE_CTX_get0_param devuelven punteros a las estructuras correspondientes.

X509_STORE_CTX_get_error devuelve el código de error.

X509_STORE_CTX_set_depth no devuelve ningún valor.

X509_STORE_CTX_get_depth devuelve la profundidad actual.

X509_STORE_CTX_purpose devuelve el propósito actual.

X509_STORE_CTX_set_purpose no devuelve ningún valor.

X509_STORE_CTX_set_ex_data devuelve 1 en caso de éxito, o 0 en caso de error.

X509_STORE_CTX_get_ex_data devuelve un puntero a los datos establecidos, o NULL si no se establecieron datos para el índice dado.

X509_STORE_CTX_set0_param devuelve 1 en caso de éxito, o 0 en caso de error.
