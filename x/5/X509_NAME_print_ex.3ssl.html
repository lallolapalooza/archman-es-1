X509_NAME_print_ex(3ssl)

Paquete: openssl

Licencias: Apache-2.0

X509_NAME_PRINT_EX(3ssl) OpenSSL X509_NAME_PRINT_EX(3ssl)

NOMBRE

X509_NAME_print_ex, X509_NAME_print_ex_fp, X509_NAME_print, X509_NAME_oneline - Rutinas de impresión de X509_NAME

SINOPSIS

#include <openssl/x509.h>
int X509_NAME_print_ex(BIO *out, const X509_NAME *nm,
                       int indent, unsigned long flags);
int X509_NAME_print_ex_fp(FILE *fp, const X509_NAME *nm,
                          int indent, unsigned long flags);
char *X509_NAME_oneline(const X509_NAME *a, char *buf, int size);
int X509_NAME_print(BIO *bp, const X509_NAME *name, int obase);

DESCRIPCIÓN

X509_NAME_print_ex() imprime una versión legible por humanos de nm en el BIO out. Cada línea (para formatos multilínea) se indenta con indent espacios. El formato de salida se puede personalizar ampliamente mediante el parámetro flags.

X509_NAME_print_ex_fp() es idéntica a X509_NAME_print_ex(), excepto que la salida se escribe en el puntero FILE fp.

X509_NAME_oneline() imprime una versión ASCII de a en buf. Admite RDNs multivalor y escapa los caracteres / y + en los valores. Si buf es NULL, se asigna dinámicamente un buffer y se devuelve; size se ignora. De lo contrario, se escribirán como máximo size bytes, incluido el '\0' final, y se devolverá buf.

X509_NAME_print() imprime name en bp, indentando cada línea con obase caracteres. Se utilizan múltiples líneas si la salida (incluida la indentación) supera los 80 caracteres.

NOTAS

Las funciones X509_NAME_oneline() y X509_NAME_print() producen un formato de salida no estándar, no manejan campos de varios caracteres y tienen varias peculiaridades e inconsistencias. Su uso se desaconseja encarecidamente en aplicaciones nuevas y podrían quedar obsoletas en una versión futura.

Aunque hay un gran número de flags posibles, para la mayoría de los propósitos, XN_FLAG_ONELINE, XN_FLAG_MULTILINE o XN_FLAG_RFC2253 serán suficientes. Como se indica en la página del manual de ASN1_STRING_print_ex(3) para terminales UTF8, el flag ASN1_STRFLGS_ESC_MSB debe estar desestablecido: por ejemplo, se usaría XN_FLAG_ONELINE & ~ASN1_STRFLGS_ESC_MSB.

El conjunto completo de flags admitidos por X509_NAME_print_ex() se enumera a continuación.

Varias opciones se pueden combinar mediante OR.

Las opciones XN_FLAG_SEP_COMMA_PLUS, XN_FLAG_SEP_CPLUS_SPC, XN_FLAG_SEP_SPLUS_SPC y XN_FLAG_SEP_MULTILINE determinan los separadores de campo a utilizar. Se utilizan dos separadores distintos entre componentes distintos de RelativeDistinguishedName y para separar valores en el mismo RDN para un RDN multivalor. Los RDNs multivalor son actualmente muy raros, por lo que el segundo separador rara vez se utilizará.

XN_FLAG_SEP_COMMA_PLUS utiliza coma y signo más como separadores. XN_FLAG_SEP_CPLUS_SPC utiliza coma y signo más con espacios: esto es más legible que solo coma y signo más. XN_FLAG_SEP_SPLUS_SPC utiliza punto y coma espaciado y signo más. XN_FLAG_SEP_MULTILINE utiliza nueva línea espaciada y signo más respectivamente.

Si se establece XN_FLAG_DN_REV, el DN completo se imprime en orden inverso.

Los flags XN_FLAG_FN_SN, XN_FLAG_FN_LN, XN_FLAG_FN_OID, XN_FLAG_FN_NONE determinan cómo se muestra un nombre de campo. Utilizará el nombre corto (por ejemplo, CN), el nombre largo (por ejemplo, commonName), siempre usará la forma numérica OID (normalmente los OID solo se usan si el nombre del campo no se reconoce) y ningún nombre de campo, respectivamente.

Si se establece XN_FLAG_SPC_EQ, se colocarán espacios alrededor del carácter '=' que separa los nombres de campo y los valores.

Si se establece XN_FLAG_DUMP_UNKNOWN_FIELDS, se imprimirá la codificación de los campos desconocidos en lugar de los valores.

Si se establece XN_FLAG_FN_ALIGN, los nombres de campo se rellenarán hasta 20 caracteres: esto solo es útil para el formato multilínea.

Además, todas las opciones admitidas por ASN1_STRING_print_ex() se pueden utilizar para controlar cómo se muestra cada valor de campo.

Además, se pueden establecer varias opciones para formatos de uso común.

XN_FLAG_RFC2253 establece opciones que producen una salida compatible con RFC2253. Es equivalente a:
"ASN1_STRFLGS_RFC2253 | XN_FLAG_SEP_COMMA_PLUS | XN_FLAG_DN_REV
| XN_FLAG_FN_SN | XN_FLAG_DUMP_UNKNOWN_FIELDS"

XN_FLAG_ONELINE es un formato de una línea más legible que es lo mismo que:
"ASN1_STRFLGS_RFC2253 | ASN1_STRFLGS_ESC_QUOTE | XN_FLAG_SEP_CPLUS_SPC
| XN_FLAG_SPC_EQ | XN_FLAG_FN_SN"

XN_FLAG_MULTILINE es un formato multilínea que es lo mismo que:
"ASN1_STRFLGS_ESC_CTRL | ASN1_STRFLGS_ESC_MSB | XN_FLAG_SEP_MULTILINE
| XN_FLAG_SPC_EQ | XN_FLAG_FN_LN | XN_FLAG_FN_ALIGN"

XN_FLAG_COMPAT utiliza un formato idéntico a X509_NAME_print(): de hecho, llama internamente a X509_NAME_print().

VALORES DE RETORNO

X509_NAME_oneline() devuelve una cadena válida en caso de éxito o NULL en caso de error.

X509_NAME_print() devuelve 1 en caso de éxito o 0 en caso de error.

X509_NAME_print_ex() y X509_NAME_print_ex_fp() devuelven 1 en caso de éxito o 0 en caso de error si se establece XN_FLAG_COMPAT, que es lo mismo que X509_NAME_print(). De lo contrario, devuelven -1 en caso de error u otros valores en caso de éxito.
