X509_check_host(3ssl)

Paquete: openssl

Licencias: Apache-2.0

X509_CHECK_HOST(3ssl) OpenSSL X509_CHECK_HOST(3ssl)

NOMBRE

X509_check_host, X509_check_email, X509_check_ip, X509_check_ip_asc - Coincidencia de certificados X.509

SINOPSIS

#include <openssl/x509v3.h>
int X509_check_host(X509 *, const char *name, size_t namelen,
                    unsigned int flags, char **peername);
int X509_check_email(X509 *, const char *address, size_t addresslen,
                     unsigned int flags);
int X509_check_ip(X509 *, const unsigned char *address, size_t addresslen,
                  unsigned int flags);
int X509_check_ip_asc(X509 *, const char *address, unsigned int flags);

DESCRIPCIÓN

Las funciones de coincidencia de certificados se utilizan para verificar si un certificado coincide con un nombre de host, una dirección de correo electrónico o una dirección IP dada. La validez del certificado y su nivel de confianza deben verificarse por otros medios.

X509_check_host() verifica si el Nombre Alternativo del Sujeto (SAN) o el Nombre Común del Sujeto (CN) del certificado coincide con el nombre de host especificado, que debe estar codificado en la sintaxis de nombre preferida descrita en la sección 3.5 de RFC 1034. Por defecto, los comodines son compatibles y solo coinciden en la etiqueta más a la izquierda; pero pueden coincidir con parte de esa etiqueta con un prefijo o sufijo explícito. Por ejemplo, por defecto, el host nombre "www.example.com" coincidiría con un certificado con un valor SAN o CN de "*.example.com", "w*.example.com" o "*w.example.com".

Según la sección 6.4.2 de RFC 6125, los valores nombre que representan nombres de dominio internacionales deben proporcionarse en formato A-label. El argumento namelen debe ser el número de caracteres en la cadena de nombre o cero en cuyo caso la longitud se calcula con strlen(name). Cuando name comienza con un punto (por ejemplo, ".example.com"), coincidirá con un certificado válido para cualquier subdominio de name, (ver también X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS abajo).

Cuando el certificado coincide y peername no es NULL, se almacena un puntero a una copia del SAN o CN coincidente del certificado del par en la dirección pasada en peername. La aplicación es responsable de liberar peername mediante OPENSSL_free() cuando ya no sea necesario.

X509_check_email() verifica si el certificado coincide con la dirección de correo electrónico address especificada. Se admite la sintaxis de buzón de RFC 822, no se permiten comentarios y no se intenta normalizar caracteres entrecomillados. La sintaxis de buzón de RFC 6531 se admite para direcciones SmtpUTF8Mailbox en subjectAltName según RFC 8398, con limitaciones similares a las de la sintaxis RFC 822, y no se intenta convertir de A-label a U-label antes de la comparación. El argumento addresslen debe ser el número de caracteres en la cadena de dirección o cero en cuyo caso la longitud se calcula con strlen(address).

X509_check_ip() verifica si el certificado coincide con una dirección IPv4 o IPv6 especificada. La matriz address está en formato binario, en orden de bytes de red. La longitud es 4 (IPv4) o 16 (IPv6). Solo se consideran las direcciones marcadas explícitamente en los certificados; las direcciones IP almacenadas en nombres DNS y Nombres Comunes se ignoran. Actualmente no hay flags que afecten el comportamiento de esta llamada.

X509_check_ip_asc() es similar, excepto que la cadena terminada en NUL address se convierte primero a la representación interna.

El argumento flags suele ser 0. Puede ser el OR a nivel de bits de las flags:

X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT,
X509_CHECK_FLAG_NEVER_CHECK_SUBJECT,
X509_CHECK_FLAG_NO_WILDCARDS,
X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS,
X509_CHECK_FLAG_MULTI_LABEL_WILDCARDS.
X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS.

La flag X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT hace que la función considere el DN del sujeto incluso si el certificado contiene al menos un nombre alternativo del sujeto del tipo correcto (nombre DNS o dirección de correo electrónico según corresponda); el valor por defecto es ignorar el DN del sujeto cuando hay al menos un nombre alternativo del sujeto correspondiente presente.

La flag X509_CHECK_FLAG_NEVER_CHECK_SUBJECT hace que la función nunca considere el DN del sujeto, incluso si el certificado no contiene nombres alternativos del sujeto del tipo correcto (nombre DNS o dirección de correo electrónico según corresponda); el valor por defecto es usar el DN del sujeto cuando no hay nombres alternativos del sujeto correspondientes presentes. Si se especifican tanto X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT como X509_CHECK_FLAG_NEVER_CHECK_SUBJECT, esta última tiene prioridad y el DN del sujeto no se verifica para nombres coincidentes.

Si está configurado, X509_CHECK_FLAG_NO_WILDCARDS deshabilita la expansión de comodines; esto solo se aplica a X509_check_host.

Si está configurado, X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS suprime la compatibilidad con "*" como patrón de comodín en etiquetas que tienen un prefijo o sufijo, como: "www*" o "*www"; esto solo se aplica a X509_check_host.

Si está configurado, X509_CHECK_FLAG_MULTI_LABEL_WILDCARDS permite que un "*" que constituye la etiqueta completa de un nombre DNS (por ejemplo, "*.example.com") coincida con más de una etiqueta en name; esta flag solo se aplica a X509_check_host.

Si está configurado, X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS restringe los valores de name que comienzan con ".", que de otro modo coincidirían con cualquier subdominio en el certificado del par, para que solo coincidan con subdominios hijos directos. Por lo tanto, por ejemplo, con esta flag configurada, un name de ".example.com" coincidirá con un certificado de par con un nombre DNS de "www.example.com", pero no coincidirá con un certificado de par con un nombre DNS de "www.sub.example.com"; esta flag solo se aplica a X509_check_host.

VALORES DE RETORNO

Las funciones devuelven 1 para una coincidencia exitosa, 0 para una coincidencia fallida y -1 para un error interno: típicamente una falla de asignación de memoria o un error de decodificación ASN.1.

Todas las funciones también pueden devolver -2 si la entrada está mal formada. Por ejemplo, X509_check_host() devuelve -2 si el name proporcionado contiene NULs incrustados.

NOTAS

Se anima a las aplicaciones a utilizar X509_VERIFY_PARAM_set1_host() en lugar de llamar explícitamente a X509_check_host(3). Las comprobaciones de nombres de host pueden estar fuera de alcance con el uso del certificado DANE-EE(3), y las comprobaciones internas se suprimirán según corresponda cuando se habilite el soporte de DANE.
