X509_verify_cert(3ssl)

Paquete: openssl

Licencias: Apache-2.0

X509_VERIFY_CERT(3ssl) OpenSSL X509_VERIFY_CERT(3ssl)

NOMBRE

X509_build_chain, X509_verify_cert, X509_STORE_CTX_verify - construir y verificar cadena de certificados X509

SINOPSIS

#include <openssl/x509_vfy.h>
STACK_OF(X509) *X509_build_chain(X509 *target, STACK_OF(X509) *certs,
                                 X509_STORE *store, int with_self_signed,
                                 OSSL_LIB_CTX *libctx, const char *propq);
int X509_verify_cert(X509_STORE_CTX *ctx);
int X509_STORE_CTX_verify(X509_STORE_CTX *ctx);

DESCRIPCIÓN

X509_build_chain() construye una cadena de certificados comenzando desde target usando la lista opcional de certificados CA intermedios certs. Si store es NULL, construye la cadena lo más abajo posible, ignorando errores. De lo contrario, la cadena debe llegar a un ancla de confianza contenida en store. Utiliza internamente una estructura X509_STORE_CTX asociada con el contexto de la biblioteca libctx y la cadena de consulta de propiedades propq, ambos pueden ser NULL. En caso de que haya más de una posibilidad para la cadena, solo se toma una.

En caso de éxito, devuelve un puntero a una nueva pila de certificados (con referencia incrementada) comenzando con target y seguido por todos los certificados intermedios disponibles. Solo se incluye un ancla de confianza autofirmada si target es el ancla de confianza de with_self_signed es 1. Si se devuelve una pila no NULL, el llamador es responsable de liberarla.

La función X509_verify_cert() intenta descubrir y validar una cadena de certificados basándose en los parámetros de ctx. El contexto de verificación, de tipo X509_STORE_CTX, se puede construir usando X509_STORE_CTX_new(3) y X509_STORE_CTX_init(3). Generalmente incluye un certificado objetivo a verificar, un conjunto de certificados que sirven como anclas de confianza, una lista de certificados no confiables que pueden ser útiles para la construcción de la cadena, indicadores como X509_V_FLAG_X509_STRICT, y varios otros componentes opcionales como una función de devolución de llamada que permite personalizar el resultado de la verificación. Una descripción completa del proceso de verificación de certificados se encuentra en la página del manual openssl-verification-options(1).

Las aplicaciones raramente llaman a esta función directamente, pero es utilizada internamente por OpenSSL para la validación de certificados, tanto en el código S/MIME como en el código SSL/TLS.

Un valor de retorno negativo de X509_verify_cert() puede ocurrir si se invoca incorrectamente, como sin ningún certificado establecido en ctx, o cuando se llama dos veces seguidas sin reinicializar ctx para la segunda llamada. Un valor de retorno negativo también puede ocurrir debido a problemas de recursos internos o porque se ha detectado una inconsistencia interna. Las aplicaciones deben interpretar cualquier valor de retorno <= 0 como un error.

X509_STORE_CTX_verify() se comporta de manera similar a X509_verify_cert(), excepto que su certificado objetivo es el primer elemento de la lista de certificados no confiables en ctx, a menos que se establezca explícitamente un certificado objetivo.

Cuando el objetivo de verificación es una clave pública en bruto, en lugar de un certificado, ambas funciones validan la clave pública en bruto objetivo. En ese caso, el número de comprobaciones posibles se reduce significativamente. La clave pública en bruto solo se puede autenticar a través de registros DANE TLSA, ya sean sintetizados localmente u obtenidos por la aplicación de DNS. Los registros DANE TLSA de clave pública en bruto se pueden agregar a través de SSL_add_expected_rpk(3) o SSL_dane_tlsa_add(3).

VALORES DE RETORNO

X509_build_chain() devuelve NULL en caso de error, de lo contrario, una pila de certificados.

Tanto X509_verify_cert() como X509_STORE_CTX_verify() devuelven 1 si se puede construir y validar una cadena completa, de lo contrario, devuelven 0, y en circunstancias excepcionales (como fallo de malloc y errores internos) también pueden devolver un código negativo.

Si se puede construir y validar una cadena completa, ambas funciones devuelven 1. Si el certificado debe ser rechazado basándose en los datos disponibles o si no se pueden obtener los datos de estado del certificado requeridos, devuelven 0. Si no es posible una respuesta definitiva, generalmente devuelven un código negativo.

En caso de error o fallo, se puede obtener información adicional del error examinando ctx utilizando, por ejemplo, X509_STORE_CTX_get_error(3). Incluso si la verificación indicó éxito, el código de error almacenado puede ser diferente de X509_V_OK, probablemente porque una función de devolución de llamada de verificación ha omitido el error.

VER TAMBIÉN

HISTORIA
