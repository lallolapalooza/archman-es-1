X509_LOOKUP_hash_dir(3ssl)

Paquete: openssl

Licencias: Apache-2.0

X509_LOOKUP_HASH_DIR(3ssl) OpenSSL X509_LOOKUP_HASH_DIR(3ssl)

NOMBRE

X509_LOOKUP_hash_dir, X509_LOOKUP_file, X509_LOOKUP_store, X509_load_cert_file_ex, X509_load_cert_file, X509_load_crl_file, X509_load_cert_crl_file_ex, X509_load_cert_crl_file - Métodos predeterminados de búsqueda de certificados de OpenSSL

SINOPSIS

#include <openssl/x509_vfy.h>
X509_LOOKUP_METHOD *X509_LOOKUP_hash_dir(void);
X509_LOOKUP_METHOD *X509_LOOKUP_file(void);
X509_LOOKUP_METHOD *X509_LOOKUP_store(void);
int X509_load_cert_file_ex(X509_LOOKUP *ctx, const char *file, int type,
                           OSSL_LIB_CTX *libctx, const char *propq);
int X509_load_cert_file(X509_LOOKUP *ctx, const char *file, int type);
int X509_load_crl_file(X509_LOOKUP *ctx, const char *file, int type);
int X509_load_cert_crl_file_ex(X509_LOOKUP *ctx, const char *file, int type,
                               OSSL_LIB_CTX *libctx, const char *propq);
int X509_load_cert_crl_file(X509_LOOKUP *ctx, const char *file, int type);

DESCRIPCIÓN

X509_LOOKUP_hash_dir y X509_LOOKUP_file son dos métodos de búsqueda de certificados para usar con X509_STORE, proporcionados por la biblioteca OpenSSL.

Los usuarios de la biblioteca típicamente no necesitan crear instancias de estos métodos manualmente, estos serían creados automáticamente por las funciones X509_STORE_load_locations(3) o SSL_CTX_load_verify_locations(3).

Internamente, la carga de certificados y CRLs se implementa a través de las funciones X509_load_cert_crl_file, X509_load_cert_file y X509_load_crl_file. Estas funciones admiten el parámetro type, que puede ser una de las constantes FILETYPE_PEM, FILETYPE_ASN1 y FILETYPE_DEFAULT. Cargan certificados y/o CRLs desde el archivo especificado a la caché de memoria de los objetos X509_STORE con los que está asociado el parámetro ctx proporcionado.

Las funciones X509_load_cert_file y X509_load_crl_file pueden cargar tanto formatos PEM como DER dependiendo del valor de type. Debido a que el formato DER no puede contener más de un objeto certificado o CRL (mientras que PEM puede contener varios objetos PEM concatenados), X509_load_cert_crl_file con FILETYPE_ASN1 es equivalente a X509_load_cert_file.

La constante FILETYPE_DEFAULT con un nombre de archivo NULL hace que estas funciones carguen el archivo de almacén de certificados predeterminado (ver X509_STORE_set_default_paths(3).

Las funciones devuelven el número de objetos cargados del archivo o 0 en caso de error.

Ambos métodos admiten la adición de varias ubicaciones de certificados a un mismo X509_STORE.

Esta página documenta los formatos de almacén de certificados utilizados por estos métodos y la política de caché.

Método de Archivo

El método X509_LOOKUP_file carga todos los certificados o CRLs presentes en un archivo en memoria en el momento en que el archivo se añade como fuente de búsqueda.

El formato del archivo es texto ASCII que contiene certificados y CRLs PEM concatenados.

Este método debe ser utilizado por aplicaciones que trabajan con un conjunto pequeño de CAs.

Método de Directorio con Hash

X509_LOOKUP_hash_dir es un método más avanzado, que carga certificados y CRLs bajo demanda, y los almacena en caché en memoria una vez que se cargan. A partir de OpenSSL 1.0.0, también verifica CRLs más nuevas en cada búsqueda, de modo que las CRLs más nuevas se actualizan tan pronto como aparecen en el directorio.

El directorio debe contener un certificado o CRL por archivo en formato PEM, con un nombre de archivo de la forma hash.N para un certificado, o hash.rN para un CRL. El hash es el valor devuelto por la función X509_NAME_hash_ex(3) aplicada al nombre del sujeto para certificados o al nombre del emisor para CRLs. El hash también se puede obtener a través de la opción -hash de los comandos openssl-x509(1) o openssl-crl(1).

El sufijo .N o .rN es un número de secuencia que comienza en cero, y se incrementa consecutivamente para cada certificado o CRL con el mismo valor de hash. Los saltos en los números de secuencia no están soportados, se asume que no hay más objetos con el mismo hash más allá del primer número faltante en la secuencia.

Los números de secuencia permiten que el directorio contenga varios certificados con el mismo valor de hash del nombre del sujeto. Por ejemplo, es posible tener en el almacén varios certificados con el mismo sujeto o varios CRLs con el mismo emisor (y, por ejemplo, diferentes períodos de validez).

Al verificar CRLs nuevas una vez cargado un CRL para un valor de hash dado, el método de búsqueda hash_dir solo verifica certificados con un número de secuencia mayor que el del CRL ya en caché.

Tenga en cuenta que el algoritmo de hash utilizado para el hashing del nombre del sujeto cambió en OpenSSL 1.0.0, y todos los almacenes de certificados deben ser hasheados al migrar de OpenSSL 0.9.8 a 1.0.0.

OpenSSL incluye una utilidad openssl-rehash(1) que crea enlaces simbólicos con nombres hasheados para todos los archivos con sufijo .pem en un directorio dado.

Método OSSL_STORE

X509_LOOKUP_store es un método que permite acceder a cualquier almacén de certificados y CRLs a través de cualquier cargador soportado por ossl_store(7). Funciona con la ayuda de URIs, que pueden ser referencias directas a certificados o CRLs, pero también pueden ser referencias a catálogos de dichos objetos (que se comportan como directorios).

Este método se solapa con el "Método de Archivo" y el "Método de Directorio con Hash" debido al cargador con esquema 'file:'. No realiza caché por sí mismo, pero puede utilizar un cargador ossl_store(7) con caché, y por lo tanto depende de la capacidad del cargador.

VALORES DE RETORNO

X509_LOOKUP_hash_dir(), X509_LOOKUP_file() y X509_LOOKUP_store() siempre devuelven una estructura válida X509_LOOKUP_METHOD.

X509_load_cert_file(), X509_load_crl_file() y X509_load_cert_crl_file() devuelven el número de objetos cargados o 0 en caso de error.

VER TAMBIÉN

PEM_read_PrivateKey(3), X509_STORE_load_locations(3), SSL_CTX_load_verify_locations(3), X509_LOOKUP_meth_new(3), ossl_store(7)

HISTORIAL

Las funciones X509_load_cert_file_ex(), X509_load_cert_crl_file_ex() y X509_LOOKUP_store() se añadieron en OpenSSL 3.0.
