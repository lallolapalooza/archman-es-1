DESCRIPCIÓN

Estas funciones manipulan la estructura X509_VERIFY_PARAM asociada a una operación de verificación de certificados.

La función X509_VERIFY_PARAM_set_flags() establece las banderas en param operando con ellas usando OR bit a bit con flags. Ver "FLAGS DE VERIFICACIÓN" para una descripción completa de los valores que el parámetro flags puede tomar.

X509_VERIFY_PARAM_get_flags() devuelve las banderas en param.

X509_VERIFY_PARAM_get_inh_flags() devuelve las banderas de herencia en param que especifican cómo las banderas de verificación se copian de una estructura a otra. X509_VERIFY_PARAM_set_inh_flags() establece las banderas de herencia. Ver la sección FLAGS DE HERENCIA para una descripción de estos bits.

X509_VERIFY_PARAM_clear_flags() borra las banderas flags en param.

X509_VERIFY_PARAM_set_purpose() establece el propósito de verificación en param a purpose. Esto determina el propósito aceptable de la cadena de certificados, por ejemplo X509_PURPOSE_SSL_CLIENT. El requisito de propósito se borra si purpose es X509_PURPOSE_DEFAULT_ANY.

X509_VERIFY_PARAM_get_purpose() devuelve el propósito en param.

X509_VERIFY_PARAM_set_trust() establece la configuración de confianza en param a trust.

X509_VERIFY_PARAM_set_time() establece la hora de verificación en param a t. Normalmente se utiliza la hora actual.

X509_VERIFY_PARAM_add0_policy() añade policy al conjunto de políticas aceptables. Contrariamente a la documentación preexistente de esta función, no habilita la verificación de políticas.

X509_VERIFY_PARAM_set1_policies() habilita la verificación de políticas (está deshabilitada por defecto) y establece el conjunto de políticas aceptables a policies. Cualquier conjunto de políticas existente se borra. El parámetro policies puede ser NULL para borrar un conjunto de políticas existente.

X509_VERIFY_PARAM_set_depth() establece la profundidad máxima de verificación a depth. Este es el número máximo de certificados de CA intermedios que pueden aparecer en una cadena. Una cadena de profundidad máxima contiene 2 certificados más que el límite, ya que ni el certificado de entidad final ni el ancla de confianza cuentan contra este límite. Por lo tanto, un límite de depth de 0 solo permite que el certificado de entidad final sea firmado directamente por el ancla de confianza, mientras que con un límite de depth de 1 puede haber un certificado de CA intermedio entre el ancla de confianza y el certificado de entidad final.

X509_VERIFY_PARAM_set_auth_level() establece el nivel de seguridad de autenticación a auth_level. El nivel de seguridad de autenticación determina la fortaleza aceptable de la firma y la clave pública al verificar cadenas de certificados. Para que una cadena de certificados sea válida, las claves públicas de todos los certificados deben cumplir el nivel de seguridad especificado. El nivel de seguridad del algoritmo de firma no se aplica al certificado de *ancla de confianza* de la cadena, que es directamente confiable o se valida por medios distintos a su firma. Ver SSL_CTX_set_security_level(3) para las definiciones de los niveles disponibles. El nivel de seguridad por defecto es -1, o "no establecido". En el nivel de seguridad 0 o inferior todos los algoritmos son aceptables. El nivel de seguridad 1 requiere al menos una seguridad equivalente a 80 bits y es ampliamente interoperable, aunque rechazará, por ejemplo, firmas MD5 o claves RSA de menos de 1024 bits.

X509_VERIFY_PARAM_get0_host() devuelve el n-ésimo nombre de host DNS esperado que se ha establecido utilizando X509_VERIFY_PARAM_set1_host() o X509_VERIFY_PARAM_add1_host(). Para obtener todos los nombres, comience con n = 0 e incremente n mientras no se devuelva un puntero NULL.

X509_VERIFY_PARAM_set1_host() establece el nombre de host DNS esperado a name, borrando cualquier nombre de host previamente especificado. Si name es NULL o está vacío, la lista de nombres de host se borra y no se realizan verificaciones de nombre en el certificado del peer. Si name termina en NUL, namelen puede ser cero, de lo contrario, namelen debe establecerse a la longitud de name.

Cuando se especifica un nombre de host, la verificación del certificado invoca automáticamente X509_check_host(3) con las banderas iguales al argumento flags dado a X509_VERIFY_PARAM_set_hostflags() (cero por defecto). Se recomienda encarecidamente a las aplicaciones que utilicen esta interfaz en lugar de llamar explícitamente a X509_check_host(3), las verificaciones de nombre de host pueden estar fuera de alcance con el uso de certificado DANE-EE(3), y la verificación interna se suprimirá según corresponda cuando se habilite la verificación DANE.

Cuando el CommonName del sujeto no será ignorado, ya sea como resultado de la bandera de host X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT, o porque no hay nombres de alternativa del sujeto DNS presentes en el certificado, las restricciones de nombre DNS en los certificados emisores se aplicarán al CommonName del sujeto, así como a la extensión de nombre alternativo del sujeto.

Cuando el CommonName del sujeto será ignorado, ya sea como resultado de la bandera de host X509_CHECK_FLAG_NEVER_CHECK_SUBJECT, o porque hay nombres de alternativa del sujeto DNS presentes en el certificado, las restricciones de nombre DNS en los certificados emisores no se aplicarán al DN del sujeto. Como se describe en X509_check_host(3) la bandera X509_CHECK_FLAG_NEVER_CHECK_SUBJECT tiene precedencia sobre la bandera X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT.

VERIFICATION FLAGS

The following flags can be set using X509_VERIFY_PARAM_set_flags():

X509_V_FLAG_CRL_CHECK
This flag causes checking of Certificate Revocation Lists (CRLs) when performing certificate verification during SSL connections associated with an SSL_CTX structure ctx:

X509_VERIFY_PARAM *param;
param = X509_VERIFY_PARAM_new();
X509_VERIFY_PARAM_set_flags(param, X509_V_FLAG_CRL_CHECK);
SSL_CTX_set1_param(ctx, param);
X509_VERIFY_PARAM_free(param);

HISTORIA

La bandera X509_V_FLAG_NO_ALT_CHAINS se añadió en OpenSSL 1.1.0. La bandera X509_V_FLAG_CB_ISSUER_CHECK fue obsoleta en OpenSSL 1.1.0 y no tiene efecto.

La función X509_VERIFY_PARAM_get_hostflags() se añadió en OpenSSL 1.1.0i.

Las funciones X509_VERIFY_PARAM_get0_host(), X509_VERIFY_PARAM_get0_email() y X509_VERIFY_PARAM_get1_ip_asc() se añadieron en OpenSSL 3.0.

La función X509_VERIFY_PARAM_add0_policy() fue históricamente documentada como que habilitaba la verificación de políticas, sin embargo la implementación nunca lo hizo. La documentación se cambió para alinearse con la implementación.

La función X509_VERIFY_PARAM_get_purpose() se añadió en OpenSSL 3.5.
