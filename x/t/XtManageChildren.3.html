XtManageChildren(3) FUNCIONES XT XtManageChildren(3)

NOMBRE

XtManageChildren, XtManageChild, XtUnmanageChildren, XtUnmanageChild, XtChangeManagedSet, XtIsManaged - gestionar y desgestionar hijos

SINTAXIS

#include <X11/Intrinsic.h>

typedef Widget *WidgetList;

void XtManageChildren(WidgetList children, Cardinal num_children);

void XtManageChild(Widget child);

void XtUnmanageChildren(WidgetList children, Cardinal num_children);

void XtUnmanageChild(Widget child);

void XtChangeManagedSet(WidgetList unmanage_children, Cardinal num_unmanage_children, XtDoChangeProc do_change_proc, XtPointer client_data, WidgetList manage_children, Cardinal num_manage_children);

Boolean XtIsManaged(Widget widget);

ARGUMENTOS

child
Especifica el hijo.
children
Especifica una lista de widgets hijos.
num_children
Especifica el número de hijos.
widget
Especifica el widget.
manage_children
Especifica la lista de widgets hijos a añadir al conjunto gestionado.
num_manage_children
Especifica el número de entradas en la lista manage_children.
unmanage_children
Especifica la lista de widgets hijos a eliminar del conjunto gestionado.
num_unmanage_children
Especifica el número de entradas en la lista unmanage_children.
do_change_proc
Especifica el procedimiento de enganche post-desgestión, pre-gestión a invocar.
client_data
Especifica los datos del cliente a pasar al procedimiento de enganche.

DESCRIPCIÓN

La función XtManageChildren realiza lo siguiente:

  • Emite un error si los hijos no tienen todos el mismo padre o si el padre no es una subclase de compositeWidgetClass.
  • Retorna inmediatamente si el padre común está siendo destruido; de lo contrario, para cada hijo único en la lista, XtManageChildren ignora el hijo si ya está gestionado o está siendo destruido y lo marca si no lo está.
  • Si el padre está realizado y después de que todos los hijos han sido marcados, hace visibles a algunos de los hijos recién gestionados:
  • Llama a la rutina de cambio_gestionado del padre de los widgets.
  • Llama a XtRealizeWidget en cada hijo previamente no gestionado que está no realizado.
  • Mapea cada hijo previamente no gestionado que tiene map_when_managed True.

La gestión de hijos es independiente del orden de los hijos y independiente de la creación y eliminación de hijos. La rutina de disposición del padre debe considerar los hijos cuyo campo gestionado es True e ignorar todos los demás hijos. Tenga en cuenta que algunos widgets compuestos, especialmente las cajas fijas, llaman a XtManageChild desde su procedimiento insert_child.

Si el widget padre está realizado, se llama a su procedimiento de cambio_gestionado para notificarle que su conjunto de hijos gestionados ha cambiado. El padre puede reposicionar y redimensionar cualquiera de sus hijos. Mueve cada hijo según sea necesario llamando a XtMoveWidget, que primero actualiza los campos x e y y luego llama a XMoveWindow si el widget está realizado.

La función XtManageChild construye una WidgetList de longitud uno y llama a XtManageChildren.

La función XtUnmanageChildren realiza lo siguiente:

  • Emite un error si los hijos no tienen todos el mismo padre o si el padre no es una subclase de compositeWidgetClass.
  • Retorna inmediatamente si el padre común está siendo destruido; de lo contrario, para cada hijo único en la lista, XtUnmanageChildren realiza lo siguiente:
  • Ignora el hijo si ya está no gestionado o está siendo destruido y lo marca si no lo está.
  • Si el hijo está realizado, se hace no visible desmapeándolo.
•
Llama al procedimiento de cambio_gestionado del padre de los widgets después de que todos los hijos hayan sido marcados si el padre está realizado.

XtUnmanageChildren no destruye los widgets hijos. Eliminar widgets del conjunto gestionado de un padre es a menudo un destierro temporal, y, más tarde, puede gestionar los hijos de nuevo.

La función XtUnmanageChild construye una lista de widgets de longitud uno y llama a XtUnmanageChildren.

La función XtChangeManagedSet realiza lo siguiente:

  • Emite un error si los widgets especificados en las listas manage_children y unmanage_children no tienen todos el mismo padre, o si ese padre no es una subclase de compositeWidgetClass.
  • Retorna inmediatamente si el padre común está siendo destruido.
  • Si no se define una CompositeClassExtension, o si se define una CompositeClassExtension pero con un campo allows_change_managed_set con valor False, y se invocó XtChangeManagedSet con un procedimiento do_change_proc no nulo, entonces XtChangeManagedSet realiza lo siguiente:
  • Llama a XtUnmanageChildren (unmanage_children, num_unmanage_children).
  • Llama al procedimiento do_change_proc especificado.
  • Llama a XtManageChildren (manage_children, num_manage_children) y luego retorna inmediatamente.
•
De lo contrario, si se define una CompositeClassExtension con un campo allows_change_managed_set con valor True, o si no se define ninguna CompositeClassExtension, y se invocó XtChangeManagedSet con un procedimiento do_change_proc nulo, entonces se realiza lo siguiente:
  • Para cada hijo en la lista unmanage_children; si el hijo ya está no gestionado o está siendo destruido se ignora, de lo contrario se marca como no gestionado y si está realizado se hace no visible desmapeándolo.
  • Si el procedimiento do_change_proc no es nulo, entonces se invoca como se especifica.
  • Para cada hijo en la lista manage_children; si el hijo ya está gestionado o está siendo destruido se ignora, de lo contrario se marca como gestionado
•
Si el padre está realizado y después de que todos los hijos han sido marcados, se invoca el método change_managed del padre y posteriormente se hacen visibles algunos de los hijos recién gestionados:
  • Llamando a XtRealizeWidget en cada uno de los hijos previamente no gestionados que está no realizado.
  • Mapeando cada hijo previamente no gestionado que tiene map_when_managed como True.

La función XtIsManaged retorna True si el widget especificado es de la clase RectObj o cualquier subclase de esta y está gestionado, o False en caso contrario.

NAME

XtManageChildren - Manage widgets

SYNTAX

void XtManageChildren(WidgetList children, Cardinal num_children);

ARGUMENTS

children
Specifies a list of the children widgets to manage. This list must not be NULL, and the widgets specified must not be NULL. The widgets must be children of the same parent.
num_children
Specifies the number of children in the children list.

DESCRIPTION

The XtManageChildren function makes the specified widgets children of their parent widget. It also realizes the widgets, makes them visible, and sets up their geometry so that they appear in the parent's window. If the parent is already realized, the children are also realized.

XtManageChildren is called by a parent widget after it has created its children. It is the responsibility of the parent widget to call XtManageChildren for its children.

The children argument is a list of widget pointers. The num_children argument is the number of widgets in the list.

The widgets are managed in the order they appear in the list. If the parent widget has a geometry manager, it is called to determine the final geometry of the children.

If any of the children are already realized, XtManageChildren will realize them if the parent is realized.
