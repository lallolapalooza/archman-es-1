XtCreateWidget(3) FUNCIONES XT XtCreateWidget(3)

NOMBRE

XtCreateWidget, XtVaCreateWidget, XtCreateManagedWidget, XtVaCreateManagedWidget, XtDestroyWidget - crear y destruir widgets

SINTAXIS

#include <X11/Intrinsic.h>

Widget XtCreateWidget(const char *nombre, WidgetClass clase_widget, Widget padre, ArgList args, Cardinal num_args);

Widget XtVaCreateWidget(const char *nombre, WidgetClass clase_widget, Widget padre, ...);

Widget XtCreateManagedWidget(const char *nombre, WidgetClass clase_widget, Widget padre, ArgList args, Cardinal num_args);

Widget XtVaCreateManagedWidget(const char *nombre, WidgetClass clase_widget, Widget padre, ...);

void XtDestroyWidget(Widget w);

ARGUMENTOS

args
Especifica la lista de argumentos para anular los valores predeterminados de los recursos.
nombre
Especifica el nombre de recurso para el widget creado, que se utiliza para recuperar recursos y, por esa razón, no debe ser el mismo que cualquier otro widget que sea hijo del mismo padre.
num_args
Especifica el número de argumentos en la lista de argumentos.
padre
Especifica el widget padre.
w
Especifica el widget.
clase_widget
Especifica el puntero a la clase del widget para el widget creado.
...
Especifica la lista de argumentos variables para anular los valores predeterminados de los recursos.

DESCRIPCIÓN

La función XtCreateWidget realiza muchas de las operaciones repetitivas de la creación de widgets:

  • Comprueba si el procedimiento class_initialize se ha llamado para esta clase y para todas las superclases y, si no es así, llama a las necesarias en orden de superclase a subclase.
  • Asigna memoria para la instancia del widget.
  • Si el padre es una subclase de constraintWidgetClass, asigna memoria para las restricciones del padre y almacena la dirección de esta memoria en el campo de restricciones.
  • Inicializa los campos de datos principales no de recursos (por ejemplo, padre y visible).
  • Inicializa los campos de recursos (por ejemplo, background_pixel) utilizando las listas de recursos especificadas para esta clase y todas las superclases.
  • Si el padre es una subclase de constraintWidgetClass, inicializa los campos de recursos del registro de restricciones utilizando la lista de recursos de restricciones especificada para la clase del padre y todas las superclases hasta constraintWidgetClass.
  • Llama a los procedimientos de inicialización para el widget comenzando desde el procedimiento de inicialización de Core hasta el procedimiento de inicialización del widget.
  • Si el padre es una subclase de compositeWidgetClass, coloca el widget en la lista de hijos de su padre llamando al procedimiento insert_child de su padre. Para más información, véase la Sección 3.5.
  • Si el padre es una subclase de constraintWidgetClass, llama a los procedimientos de inicialización de restricciones, comenzando desde constraintWidgetClass hasta el procedimiento de inicialización de restricciones del padre.

Tenga en cuenta que puede determinar el número de argumentos en una lista de argumentos utilizando la macro XtNumber. Para más información, véase la Sección 11.1.

La función XtCreateManagedWidget es una rutina de conveniencia que llama a XtCreateWidget y XtManageChild.

La función XtDestroyWidget proporciona el único método para destruir un widget, incluidos los widgets que necesitan destruirse a sí mismos. Se puede llamar en cualquier momento, incluso desde una rutina de callback de la aplicación del widget que se está destruyendo. Esto requiere un proceso de destrucción en dos fases para evitar referencias colgantes a widgets destruidos.

En la fase uno, XtDestroyWidget realiza lo siguiente:

  • Si el campo being_destroyed del widget es True, devuelve inmediatamente.
  • Desciende recursivamente el árbol de widgets y establece el campo being_destroyed a True para el widget y todos sus hijos.
  • Añade el widget a una lista de widgets (la lista de destrucción) que deben ser destruidos cuando sea seguro hacerlo.

Las entradas de la lista de destrucción satisfacen el invariante de que si w2 aparece después de w1 en la lista de destrucción, entonces w2 no es un descendiente de w1. (Un descendiente se refiere tanto a hijos normales como a hijos emergentes.)

La fase dos ocurre cuando todos los procedimientos que deben ejecutarse como resultado del evento actual han sido llamados (incluidos todos los procedimientos registrados con los gestores de eventos y traducciones), es decir, cuando la invocación actual de XtDispatchEvent está a punto de devolver o inmediatamente si no está en XtDispatchEvent.

En la fase dos, XtDestroyWidget realiza lo siguiente en cada entrada de la lista de destrucción:

  • Llama a los procedimientos de callback de destrucción registrados en el widget (y en todos sus descendientes) en orden post-fijo (llama a los callbacks de los hijos antes que a los callbacks de los padres).
  • Si el padre del widget es una subclase de compositeWidgetClass y si el padre no está siendo destruido, llama a XtUnmanageChild en el widget y luego llama al procedimiento delete_child del padre del widget (ver Sección 3.4).
  • Si el padre del widget es una subclase de constraintWidgetClass, llama al procedimiento de destrucción de restricciones para el padre, luego al superclase del padre, hasta que finalmente llama al procedimiento de destrucción de restricciones para constraintWidgetClass.
  • Llama a los métodos de destrucción para el widget (y todos sus descendientes) en orden post-fijo. Para cada widget de este tipo, llama al procedimiento de destrucción declarado en la clase del widget, luego al procedimiento de destrucción declarado en su superclase, hasta que finalmente llama al procedimiento de destrucción declarado en el registro de clase Core.
  • Llama a XDestroyWindow si el widget está realizado (es decir, tiene una ventana X). El servidor destruye recursivamente todas las ventanas descendientes.
  • Desciende recursivamente el árbol y desasigna todos los widgets emergentes, registros de restricciones, listas de callbacks y, si el widget es una subclase de compositeWidgetClass, hijos.
