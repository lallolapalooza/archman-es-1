XtAppNextEvent(3) FUNCIONES XT XtAppNextEvent(3)

NOMBRE

XtAppNextEvent, XtAppPending, XtAppPeekEvent, XtAppProcessEvent, XtDispatchEvent, XtAppMainLoop - consultar y procesar eventos y entradas

SINTAXIS

#include <X11/Intrinsic.h>

void XtAppNextEvent(XtAppContext app_context, XEvent *event_return);

Boolean XtAppPeekEvent(XtAppContext app_context, XEvent *event_return);

XtInputMask XtAppPending(XtAppContext app_context);

void XtAppProcessEvent(XtAppContext app_context, XtInputMask mask);

Boolean XtDispatchEvent(XEvent *event);

void XtAppMainLoop(XtAppContext app_context);

ARGUMENTOS

app_context
Especifica el contexto de la aplicación que identifica la aplicación.
event
Especifica un puntero a la estructura de eventos que se va a distribuir al manejador de eventos apropiado.
event_return
Devuelve la información del evento a la estructura de eventos especificada.
mask
Especifica qué tipos de eventos procesar. La máscara es el OR inclusivo a nivel de bits de cualquier combinación de XtIMXEvent, XtIMTimer, XtIMAlternateInput y XtIMSignal. Como conveniencia, el Toolkit X define el nombre simbólico XtIMAll como el OR inclusivo a nivel de bits de todos los tipos de eventos.

DESCRIPCIÓN

Si la cola de eventos X está vacía, XtAppNextEvent vacía los búferes de salida X de cada Display en el contexto de la aplicación y espera un evento mientras examina otras fuentes de entrada, valores de tiempo de espera y manejadores de señales, llamando a los procedimientos de devolución de llamada disparados por ellos. Este tiempo de espera se puede usar para procesamiento en segundo plano (ver Sección 7.8).

Si hay un evento en la cola, XtAppPeekEvent rellena el evento y devuelve un valor distinto de cero. Si no hay entrada X en la cola, XtAppPeekEvent vacía el búfer de salida y se bloquea hasta que haya entrada disponible (posiblemente llamando a algunas devoluciones de llamada de tiempo de espera en el proceso). Si la entrada es un evento, XtAppPeekEvent rellena el evento y devuelve un valor distinto de cero. De lo contrario, la entrada es para una fuente de entrada alternativa y XtAppPeekEvent devuelve cero.

La función XtAppPending devuelve un valor distinto de cero si hay eventos pendientes del servidor X, un temporizador pendiente o otras fuentes de entrada pendientes. El valor devuelto es una máscara de bits que es el OR de XtIMXEvent, XtIMTimer, XtIMAlternateInput y XtIMSignal (ver XtAppProcessEvent). Si no hay eventos pendientes, XtAppPending vacía el búfer de salida y devuelve cero.

La función XtAppProcessEvent procesa un temporizador, una entrada alternativa, una fuente de señal o un evento X. Si no hay nada del tipo apropiado para procesar, XtAppProcessEvent se bloquea hasta que lo haya. Si hay más de un tipo de cosa disponible para procesar, se define que se procesará. Normalmente, este procedimiento no es llamado por aplicaciones cliente (ver XtAppMainLoop). XtAppProcessEvent procesa eventos de temporizador llamando a las devoluciones de llamada de temporizador apropiadas, entradas alternativas llamando a las devoluciones de llamada de entrada alternativa apropiadas, fuentes de señal llamando a las devoluciones de llamada de señal apropiadas y eventos X llamando a XtDispatchEvent.

Cuando se recibe un evento X, se pasa a XtDispatchEvent, que llama a los manejadores de eventos apropiados y les pasa el widget, el evento y los datos específicos del cliente registrados con cada procedimiento. Si no hay manejadores registrados para ese evento, el evento se ignora y el distribuidor simplemente regresa. El orden en que se llaman los manejadores no está definido.

La función XtDispatchEvent envía esos eventos a las funciones manejadoras de eventos que se han registrado previamente con la rutina de distribución. XtDispatchEvent devuelve True si distribuyó el evento a algún manejador y False si no encontró ningún manejador al que distribuir el evento. El uso más común de XtDispatchEvent es distribuir eventos adquiridos con el procedimiento XtAppNextEvent. Sin embargo, también se puede usar para distribuir eventos construidos por el usuario. XtDispatchEvent también es responsable de implementar la semántica de agarre para XtAddGrab.

La función XtAppMainLoop procesa eventos usando XtAppProcessEvent, variando el parámetro mask y usando XtAppPending para asegurar que tenga la oportunidad de manejar eventos de todos los tipos, es decir, eventos X, eventos de temporizador, eventos de entrada y fuentes de señal. Esto constituye el bucle principal de las aplicaciones de X Toolkit y, como tal, no regresa a menos que se llame a XtAppSetExitFlag. Se espera que las aplicaciones salgan en respuesta a alguna acción del usuario. No hay nada especial en XtAppMainLoop; es simplemente un bucle que procesa eventos hasta que XtAppGetExitFlag() devuelve verdadero.

Las aplicaciones pueden proporcionar su propia versión de este bucle, que prueba alguna bandera de terminación global o prueba que el número de widgets de nivel superior sea mayor que cero antes de volver al siguiente evento.
