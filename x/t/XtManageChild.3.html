XtManageChildren(3) FUNCIONES XT XtManageChildren(3)

NOMBRE

XtManageChildren, XtManageChild, XtUnmanageChildren, XtUnmanageChild, XtChangeManagedSet, XtIsManaged - gestionar y desgestionar hijos

SINTAXIS

#include <X11/Intrinsic.h>

typedef Widget *WidgetList;

void XtManageChildren(WidgetList children, Cardinal num_children);

void XtManageChild(Widget child);

void XtUnmanageChildren(WidgetList children, Cardinal num_children);

void XtUnmanageChild(Widget child);

void XtChangeManagedSet(WidgetList unmanage_children, Cardinal num_unmanage_children, XtDoChangeProc do_change_proc, XtPointer client_data, WidgetList manage_children, Cardinal num_manage_children);

Boolean XtIsManaged(Widget widget);

ARGUMENTOS

child
Especifica el hijo.
children
Especifica una lista de widgets hijos.
num_children
Especifica el número de hijos.
widget
Especifica el widget.
manage_children
Especifica la lista de widgets hijos a añadir al conjunto gestionado.
num_manage_children
Especifica el número de entradas en la lista manage_children.
unmanage_children
Especifica la lista de widgets hijos a eliminar del conjunto gestionado.
num_unmanage_children
Especifica el número de entradas en la lista unmanage_children.
do_change_proc
Especifica el procedimiento de hook post-desgestión, pre-gestión a invocar.
client_data
Especifica los datos del cliente a pasar al procedimiento de hook.

DESCRIPCIÓN

La función XtManageChildren realiza lo siguiente:

  • Emite un error si los hijos no tienen todos el mismo padre o si el padre no es una subclase de compositeWidgetClass.
  • Devuelve inmediatamente si el padre común está siendo destruido; de lo contrario, para cada hijo único en la lista, XtManageChildren ignora al hijo si ya está gestionado o está siendo destruido y lo marca si no.
  • Si el padre está realizado y después de que todos los hijos han sido marcados, hace visibles a algunos de los hijos recién gestionados:
  • Llama a la rutina de cambio_gestionado del padre de los widgets.
  • Llama a XtRealizeWidget en cada hijo previamente no gestionado que esté no realizado.
  • Mapea cada hijo previamente no gestionado que tenga map_when_managed en True.

La gestión de hijos es independiente del orden de los hijos y independiente de la creación y eliminación de hijos. La rutina de diseño del padre debe considerar los hijos cuyo campo managed es True e ignorar a todos los demás hijos. Tenga en cuenta que algunos widgets composites, especialmente los de caja fija, llaman a XtManageChild desde su procedimiento insert_child.

Si el widget padre está realizado, se llama a su procedimiento change_managed para notificarle que su conjunto de hijos gestionados ha cambiado. El padre puede reposicionar y redimensionar a cualquiera de sus hijos. Mueve cada hijo según sea necesario llamando a XtMoveWidget, que primero actualiza los campos x e y y luego llama a XMoveWindow si el widget está realizado.

La función XtManageChild construye una WidgetList de longitud uno y llama a XtManageChildren.

La función XtUnmanageChildren realiza lo siguiente:

  • Emite un error si los hijos no tienen todos el mismo padre o si el padre no es una subclase de compositeWidgetClass.
  • Devuelve inmediatamente si el padre común está siendo destruido; de lo contrario, para cada hijo único en la lista, XtUnmanageChildren realiza lo siguiente:
  • Ignora al hijo si ya está no gestionado o está siendo destruido y lo marca si no.
  • Si el hijo está realizado, se hace no visible desmapeándolo.
•
Llama al procedimiento change_managed de los hijos del padre después de que todos los hijos hayan sido marcados si el padre está realizado.

XtUnmanageChildren no destruye los widgets hijos. Quitar widgets del conjunto gestionado de un padre es a menudo un destierro temporal, y, tiempo después, puede que vuelva a gestionar los hijos.

La función XtUnmanageChild construye una lista de widgets de longitud uno y llama a XtUnmanageChildren.

La función XtChangeManagedSet realiza lo siguiente:

  • Emite un error si los widgets especificados en las listas manage_children y unmanage_children no tienen todos el mismo padre, o si ese padre no es una subclase de compositeWidgetClass.
  • Devuelve inmediatamente si el padre común está siendo destruido.
  • Si no se define ninguna CompositeClassExtension, o si se define una CompositeClassExtension pero con un campo allows_change_managed_set con valor False, y se invocó XtChangeManagedSet con un procedimiento do_change_proc no nulo, entonces XtChangeManagedSet realiza lo siguiente:
  • Llama a XtUnmanageChildren (unmanage_children, num_unmanage_children).
  • Llama al procedimiento do_change_proc especificado.
  • Llama a XtManageChildren (manage_children, num_manage_children) y luego devuelve inmediatamente.
•
De lo contrario, si se define una CompositeClassExtension con un campo allows_change_managed_set con valor True, o si no se define ninguna CompositeClassExtension, y se invocó XtChangeManagedSet con un procedimiento do_change_proc nulo, entonces se realiza lo siguiente:
  • Para cada hijo de la lista unmanage_children; si el hijo ya está no gestionado o está siendo destruido, se ignora, de lo contrario se marca como no gestionado y si está realizado se hace no visible desmapeándolo.
  • Si el procedimiento do_change_proc no es nulo, se invoca como se especifica.
  • Para cada hijo de la lista manage_children; si el hijo ya está gestionado o está siendo destruido, se ignora, de lo contrario se marca como gestionado.
•
Si el padre está realizado y después de que todos los hijos han sido marcados, se invoca el método change_managed del padre y posteriormente algunos de los hijos recién gestionados se hacen visibles mediante:
  • Llamando a XtRealizeWidget en cada uno de los hijos previamente no gestionados que no estén realizados.
  • Mapeando cada hijo previamente no gestionado que tenga map_when_managed en True.

La función XtIsManaged devuelve True si el widget especificado es de clase RectObj o cualquier subclase de la misma y está gestionado, o False en caso contrario.

XtManageChild.3

NAME

XtManageChild - manage a child widget

SYNTAX

Widget XtManageChild(Widget widget, Widget parent);

ARGUMENTS

widget
Specifies the widget to be managed.
parent
Specifies the parent widget.

DESCRIPTION

The XtManageChild function manages a child widget. This function is called by a parent widget to inform its child that it is now part of the widget hierarchy. The parent widget then invokes the child's realization procedure, creating the child's window if it does not already exist.

The widget argument is a pointer to the child widget that is to be managed.

The parent argument is a pointer to the parent widget. This argument is typically obtained from the parent field of the child widget's geometry manager structure.

The XtManageChild function returns the managed child widget.
