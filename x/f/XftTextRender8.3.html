NOMBRE

Xft - Librería de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una librería simple que dibuja texto y gráficos:

  • usando información proporcionada por la librería Fontconfig,
  • Xft convierte glifos de fuentes usando el rasterizador FreeType, y
  • muestra los datos de fuentes convertidos usando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta librería.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo podrían usarse las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la librería Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

De Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - C Language Interface.

Xft usa estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa mediante la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

De XRender...

Los tipos de datos de la librería X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft usa estos nombres: Picture, XGlyphInfo, XRenderColor.

De Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc”, que se documentan en Fontconfig Developers Reference.

Xft usa estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

De FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_”, que se documentan en FreeType API Reference.

Xft usa estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 usa FT_UInt (un entero sin signo) para representar *glifos*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que usan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres y patrón de Fontconfig asociados con la fuente.

Los XftFonts se pueblan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se usa para duplicar XftFonts, y XftFontClose() se usa para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar ni liberar espacio para ellos.

XftDrawGlyphs(), la familia de funciones XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() usan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder a un drawable X principal o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia de funciones XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia de funciones XftTextRender*() usan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia de funciones XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar ni liberar espacio para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color del servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado a un XftColor.

Una vez que un XftColor ha sido inicializado, XftDrawSrcPicture(), XftDrawGlyphs(), la familia de funciones XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), y XftDrawRect() pueden usarse para dibujar varios objetos utilizándolo.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar en un drawable X utilizando el protocolo principal o la extensión de Renderizado X.

Los objetos XftDraw se crean con cualquiera de XftDrawCreate() (que asocia un XftDraw con un drawable X existente), XftDrawCreateBitmap() o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable X asociado con un XftDraw se puede cambiar con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar ni liberar almacenamiento para ellos.

Las propiedades de Display, Drawable, Colormap y Visual de X de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode() y la familia XftDrawString*().

La extensión de Renderizado X Picture asociada con un XftDraw se devuelve por XftDrawPicture() y XftDrawSrcPicture(). Es utilizada por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender() y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa la biblioteca explícitamente. Esto suele hacerse como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft encontró que la pantalla soporta la extensión X Render, y si es capaz de encontrar un XRenderPictFormat adecuado (el tipo de datos de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza estas propiedades inicialmente para obtener los siguientes límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft completa las propiedades faltantes en el pattern proporcionado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se estableció en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar antialiasing (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para poner en negrita una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al completar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al completar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión X Render (predeterminado: resultado de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Inicializa la biblioteca Fontconfig (llamando a FcInit()).

El parámetro config no se utiliza.
Xft no desinicializa la biblioteca Fontconfig cuando termina.
FcBool XftInitFtLibrary (void);

    
Inicializa la biblioteca FreeType (llamando a
        FT_Init_FreeType() para crear un objeto de biblioteca) si aún no
        se ha inicializado. Esto es necesario antes de usar la biblioteca
        FreeType para leer datos de fuentes de un archivo.

  





  

  
Xft llama a XftInitFtLibrary() internamente a través de
      XftFontInfoCreate() y XftFontOpenPattern().

  

  
Xft no descarta el objeto de biblioteca (por ejemplo, usando
      FT_Done_FreeType()) cuando termina.

Abrir y Buscar Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de tripletes de elementos de
        patrón del tipo campo, tipo, valor (terminado
        con un NULL), busca ese patrón contra las fuentes disponibles, y abre
        la fuente coincidente, dimensionándola correctamente para la pantalla
        número screen en la pantalla dpy. Devuelve la fuente
        coincidente, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);






  

  
Esto abre la fuente “charter” a 12 puntos. El tamaño de punto
      se convierte automáticamente al tamaño de píxel correcto según la
      resolución del monitor.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName se comporta como
>XftFontOpen, excepto que toma una cadena de patrón de Fontconfig (que se pasa a la
        función FcNameParse() de la biblioteca Fontconfig).

  

  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	int	 screen,

XftFontOpenXlfd se comporta como XftFontOpen,
        excepto que toma una cadena que contiene una X Logical Font Description
        (XLFD) y utiliza la función XftXlfdParse().

FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analiza el parámetro xlfd_orig
        según el documento X Logical Font Description Conventions,
        pero ignora algunos campos: setwidth_name,
        add_style_name, spacing y average_width.

  





  

  
XftXlfdParse crea un patrón de Fontconfig, estableciendo la propiedad
      XFT_XLFD al valor xlfd_orig, y mapea la información recopilada
      a las propiedades de Fontconfig. Los campos vacíos o con “*”
      se ignoran:







  
FC_FOUNDRY

  
de foundry.

  
FC_FAMILY

  
de family.

  
FC_WEIGHT

  
weight_name, con valor predeterminado FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
de slant, con valor predeterminado FC_SLANT_ROMAN.

  
FC_SIZE

  
de point_size.

  
FC_PIXEL_SIZE

  
de pixel_size. Si se estableció point_size, junto con
      resolution_x y resolution_y, entonces el valor se escala
      para convertir la altura de la fuente a puntos.

Determinación   de Extensión de Texto


Xft proporciona varias funciones para determinar la altura
    y el ancho requeridos para mostrar una cadena de texto. Después de tener en
    cuenta el offset, en casos donde la cadena se desplazará hacia arriba,
    abajo, izquierda o derecha, estos números se denominan extensiones de
    texto.



  
void XftTextExtents8 (

  

    
	Display	*dpy,
	XftFont	*font,
	_Xconst FcChar8	*string,
	int	 len,
	XGlyphInfo	*extents);


    
XftTextExtents8 calcula las extensiones de píxeles en la
        pantalla dpy de no más de len glifos de una cadena
        compuesta por caracteres de ocho bits cuando se dibuja con la fuente
        font, almacenándolas en extents.

	Display	*dpy,
	XftFont	*font,
	_Xconst FT_UInt	*glyphs,

	XGlyphInfo	*extents);


    
Utilizado internamente por las funciones
        XftTextExtents*(), XftGlyphExtents calcula las extensiones

        en extents.

  





  

  
Si alguno de los glyphs faltan (determinado por una verificación con
      XftFontCheckGlyph()), la entrada correspondiente en extents
      se rellena con ceros.








Gestión   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utiliza XAllocNamedColor() para buscar el color nombrado
        name para la pantalla asociada con el mapa de color cmap.

  






    
  
  • Si XAllocNamedColor() devuelve un valor distinto de cero,
      XftColorAllocName() rellena el campo de píxel XftColor resultante
      con el color más cercano soportado por la pantalla, así como los campos
      exactos de rojo, verde y azul de la base de datos, y devuelve True.
    • 
  
  • Si XAllocNamedColor() devuelve cero, XftColorAllocName()
      devuelve False y no actualiza el XftColor al que se refiere
      result.
    • 






  

  
El parámetro visual no se utiliza.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Asigna un valor de color:

  






    
  
  • Si la clase visual es TrueColor, XftColorAllocValue() establece
      el campo pixel en el XftColor al que se refiere result
      utilizando los campos rojo, verde y azul del parámetro color.
    • 
  
  • Si la clase visual no es TrueColor, XftColorAllocValue()
      llama a XAllocColor() para asignar una entrada en el mapa de color
      cmap. que devuelve el valor de píxel del color más cercano a los
      elementos RGB especificados soportados por el hardware.
    • 




  

  
Si XAllocColor() tiene éxito, XftColorAllocValue() almacena
      ese valor de píxel en el XRenderColor al que se refiere result
      y devuelve True.

  

  
Si XAllocColor() falla, XftColorAllocValue() devuelve False y
      no modifica el resultado.







  
void XftColorFree (

  

    
	Display	*dpy,

Si la clase visual no es TrueColor, Xft llama a

DESCRIPTION
       The XftDraw object is an abstraction of an X drawable that provides a
       place to draw text and other shapes. It encapsulates the necessary X
       information, such as the display, drawable, visual, and colormap, and
       manages the creation and use of X Render pictures for efficient
       rendering.

Creating an XftDraw Object
       XftDrawCreate() creates an XftDraw object for the specified X
       drawable, visual, and colormap. The drawable can be a window or a pixmap.
       The visual and colormap are used to determine how colors are rendered.

       XftDrawCreateBitmap() behaves like XftDrawCreate(), except that it
       uses an X pixmap of color depth 1 instead of an X drawable.

       XftDrawCreateAlpha() behaves like XftDrawCreate(), except that it
       uses an X pixmap of color depth depth instead of an X drawable.

       Use XftDrawDestroy() to free the memory associated with an XftDraw
       object when it is no longer needed.

Manipulating an XftDraw Object
       XftDrawChange() changes the X drawable associated with an existing
       XftDraw object.

       XftDrawDisplay() returns a pointer to the display associated with the
       XftDraw object.

       XftDrawDrawable() returns the X drawable associated with the XftDraw
       object.

       XftDrawColormap() returns the colormap associated with the XftDraw
       object.

       XftDrawVisual() returns a pointer to the visual associated with the
       XftDraw object.

       XftDrawPicture() returns the X Render picture associated with the
       XftDraw object. If the X server does not support the X Rendering
       Extension, 0 is returned.

       XftDrawSrcPicture() returns an X Render Picture object, which is used
       for rendering glyphs. If the X server does not support the X Render
       extension, those functions use XftGlyphCore(), XftGlyphSpecCore(),
       or XftGlyphFontSpecCore().

       XftLock() and XftUnlock() can be used to lock and unlock the
       internal data structures of an XftDraw object. This is useful in
       multithreaded applications to prevent race conditions.

Clipping
       XftDrawSetClip() sets up clipping for the XftDraw object using a
       Region. If the Region parameter is not null, Xft creates a new
       Region to copy the parameter, destroys any existing clipping region,
       and sets the clip_type for the XftDraw object. It then updates
       clipping for existing objects, the clip_mask for its X Render Picture
       object, and the clipping-mask in the graphics context (GC) associated
       with the XftDraw object. It returns True if no change was necessary
       or if the operation succeeded, and False if it was unable to create
       the new Region.

       XftDrawSetClipRectangles() is similar to XftDrawSetClip(), but it
       uses a set of rectangles to define the clipping region. Xft sets the
       clip_type for the XftDraw object to XftClipTypeRectangles and uses
       XSetClipRectangles() for core (X11) clipping and
       XRenderSetPictureClipRectangles() for X Render clipping.

       XftDrawSetSubwindowMode() sets the subwindow-mode for the XftDraw
       object. The mode can be either ClipByChildren (the default) or
       IncludeInferiors. For ClipByChildren, both source and destination
       windows are additionally clipped by all viewable InputOutput
       children. For IncludeInferiors, neither source nor destination window
       is clipped by inferiors, resulting in including subwindow contents in the
       source and drawing through subwindow boundaries of the destination. In
       addition to the subwindow-mode maintained by Xft, it updates the
       subwindow mode for any associated graphics context GC using
       XSetSubwindowMode() as well as for an X Render Picture using
       XRenderChangePicture().

Drawing Strings
       XftDrawString8() draws a string to the XftDraw object using the
       specified color, font, and position. It draws no more than len glyphs
       of string.

Drawing Other Things
       XftDrawRect() draws a solid rectangle of the specified color, width,
       and height at the specified position to the XftDraw object.

       XftDrawGlyphFontSpec() draws a list of glyphs associated with fonts at
       specified coordinates. All glyphs are drawn using the specified color.
       For each entry in the glyphs array: if the associated font uses the X
       Render extension, Xft uses XftGlyphFontSpecRender() to draw the
       glyph; otherwise, Xft provides an analogous feature using Xlib.

       XftGlyphFontSpecRender() renders glyphs using the X Render extension.
       It first ensures that the glyphs array is complete, loads any missing
       glyphs, examines the glyphs to find the maximum Unicode value, and then
       constructs an equivalent array of glyphs in the format expected by the X
       Render library. Finally, it uses the X Render extension to draw the
       glyphs with the appropriate XRenderCompositeText*() function
       according to the width, and discards temporary data. The op, dst,
       src, srcx, and srcy parameters are used as described in the
       documentation for the X Render library.

       XftDrawGlyphSpec() is similar to XftDrawGlyphFontSpec(), but it
       takes an array of XftGlyphSpec structures instead of
       XftGlyphFontSpec structures.

       XftCharFontSpecRender() converts the chars parameter from
       XftCharFontSpec to XftGlyphFontSpec, passing the converted array
       along with the other parameters unchanged to XftGlyphFontSpecRender()
       to render the data.

Listing Fonts
       XftListFonts() returns a list of FcFontSet matching the specified
       criteria. The caller can dispose of the return value using
       FcPatternDestroy().

       XftNameParse() parses a font name string and returns an FcPattern
       representing the font.

DEBUGGING


The Xft library uses the environment variable
    XFT_DEBUG for debugging output. The value of this
    variable is a bitmask that controls the level of debugging information
    printed to standard output:



  
1

  
Font opening information.

  
2

  
Verbose font matching and opening information.

  
4

  
Details about the XRenderPictFormat used.

  
8

  
The string that will be drawn by XftTextRender8.

  
16

  
The font IDs that are matched.

  
32

  
Details about the glyphs that will be drawn.

  
64

  
ASCII art representation of the glyphs.

  
128

  
Details about memory cache management.

  
256

  
Details about managing cached glyph memory.

  
512

  
Memory usage report.

  
1024

  
Details about extended management of cached glyph memory.
