NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca simple que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte los glifos de fuente utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, anteponiendo a todos los nombres "Xft"

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz de Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa mediante la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, anteponiendo a todos los nombres "Fc", que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, anteponiendo a todos los nombres "FT_", que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFont se rellenan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar ni liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder a un drawable X principal o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar ni liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color al servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado para un XftColor.

Una vez que se ha inicializado un XftColor, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), y XftDrawRect() pueden usarse para dibujar varios objetos utilizando.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable X usando el protocolo principal o la extensión de Renderizado X.

Los objetos XftDraw se crean con cualquiera de XftDrawCreate() (que asocia un XftDraw con un drawable X existente), XftDrawCreateBitmap() o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable X asociado con un XftDraw se puede cambiar con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador no necesita normalmente asignar o liberar almacenamiento para ellos.

Las propiedades Display, Drawable, Colormap y Visual de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode() y la familia XftDrawString*().

El Picture de la Extensión de Renderizado X asociado con un XftDraw se devuelve mediante XftDrawPicture() y XftDrawSrcPicture(). Es utilizado por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender() y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa la biblioteca explícitamente. Eso generalmente se hace como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft hace que parte de esa información esté disponible para la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft determinó que la pantalla soporta la extensión X Render, y si es capaz de encontrar un XRenderPictFormat (tipo de datos de X Render análogo al Visual de Xlib) adecuado en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft completa las propiedades faltantes en el pattern dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones Xft típicas utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar suavizado (antialiasing) (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para poner en negrita una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al completar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al completar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión X Render (predeterminado: resultado de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Inicializa la biblioteca Fontconfig (llamando a FcInit()).

El parámetro config no se utiliza.

Abrir y Comparar Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triples de elementos de
        patrón del tipo campo, tipo, valor (terminado
        con un NULL), compara ese patrón con las fuentes disponibles y abre la
        fuente coincidente, dimensionándola correctamente para la pantalla
        número screen en la pantalla dpy. Devuelve la fuente
        coincidente, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño en puntos se
      convierte automáticamente al tamaño de píxel correcto basándose en la
      resolución del monitor.

Determining Text Extents


Xft provides several functions for determining the required
    height and width for displaying a text-string. After accounting for the
    offset, in cases where the string will be shifted up, down, left or
    right, these numbers are referred to as text extents.

Managing XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Use XAllocNamedColor() to look up the named color
        name for the screen associated with the colormap cmap.

  






    
  
  • If XAllocNamedColor() returns nonzero, XftColorAllocName()
      fills in the resulting XftColor pixel field with the closest color
      supported by the screen, as well as the exact red, green and blue fields
      from the database, and returns True.
    • 
  
  • If XAllocNamedColor() returns zero, XftColorAllocName()
      returns False, and does not update the XftColor referenced by
      result.
    • 






  

  
The visual parameter is unused.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Allocate a color value:

  






    
  
  • If the visual class is TrueColor, XftColorAllocValue() sets
      the pixel field in the XftColor referenced by result
      using the red, green and blue fields from the color parameter.
    • 
  
  • If the visual class is not TrueColor, XftColorAllocValue()
      calls XAllocColor() to allocate an entry in the colormap
      cmap. which returns the pixel value of the color closest to the
      specified RGB elements supported by the hardware.
    • 




  

  
If XAllocColor() succeeds XftColorAllocValue() stores that
      pixel value in the XRenderColor referenced by result and
      returns True.

  

  
If XAllocColor() fails, XftColorAllocValue() returns False
      and does not modify the result.

Dibuja una lista de glifos asociados con fuentes en coordenadas

        XftGlyphFontSpec a través del parámetro glyphs. Todos los
        glifos se dibujan usando el color especificado en el parámetro

Para cada entrada en el array glyphs:






    
  
  • Si la fuente asociada utiliza la extensión X Render, entonces Xft
      utiliza XftGlyphFontSpecRender() para dibujar el glifo, utilizando
      una Picture obtenida al llamar XftDrawSrcPicture () con los
      parámetros draw y color.
    •

    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Esto implica varios pasos:

  






    
  
  • Primero, Xft asegura que el array glyphs esté completo
      utilizando XftFontCheckGlyph() y cargando cualquier glifo faltante
      con XftFontLoadGlyphs().
    • 
  
  • Luego Xft examina los glifos para encontrar el valor Unicode máximo.
      Eso determina el tamaño de codificación, es decir, el width.
    • 
  
  • Luego, para cada glifo, Xft verifica si su valor Unicode es manejado
      por la fuente correspondiente. Si no, el valor se establece en cero (0),
      para ignorarlo. Mientras hace esto, Xft también recuerda cuál fue la
      primera fuente utilizada, y calcula la posición en la que se dibujará cada
      glifo.
    • 
  
  • Xft luego construye un array equivalente de glifos en el formato
      esperado por la biblioteca X Render.
    • 
  
  • Finalmente, XftGlyphFontSpecRender() utiliza la extensión X Render
      para dibujar los glifos, con la función XRenderCompositeText*()
      apropiada de acuerdo con el width, y descarta los datos temporales.
    • 




  

  
Los parámetros op, dst, src, srcx y srcy
      se utilizan como se describe en la documentación de la biblioteca X
      Render.

NAME


Xft - font access library for X rendering extension






SYNOPSIS


#include <X11/Xft/Xft.h>

#include <X11/Xft/XftCompat.h>







DESCRIPTION


The Xft library provides access to the X rendering extension glyphs
    and fonts. It uses FreeType 2 for font rendering and Fontconfig for font
    matching and configuration.


The Xft library is structured into several related components:



  
Fontconfig patterns

  
This library provides functions for parsing and unparsing font names using
      the Fontconfig library conventions.

  
Font data manipulation

  
This library provides functions for loading and unloading font glyphs,
      locking and unlocking font faces, and managing font information.

  
Debugging

  
The library provides debugging options through the XFT_DEBUG environment
      variable.

  
Compatibility

  
This library provides a compatibility interface to older versions of Xft,
      maintaining backward compatibility with previous releases.






Fontconfig Patterns



  
FcPattern *XftNameParse (

  

    
	const char	*name);


    
Parses the font name string name and returns a
        FcPattern structure representing the font. This function uses
        Fontconfig's FcNameParse() to perform the actual parsing.

  

  
FcBool XftNameUnparse (

  

    
	FcPattern	*pat,
	char	*dest,
	int	 len);


    
Converts the FcPattern structure pat back into a
        string representation that can be parsed by XftNameParse() or
        FcNameParse(). The resulting string is stored in the buffer
        pointed to by dest, which has a maximum size of len.
        If the string fits, the function returns FcTrue; otherwise,
        it returns FcFalse.

  








Font data Manipulation



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Loads the glyphs specified by the array glyphs (containing
        nglyph glyph indices) for the font pub. The need_bitmaps
        argument indicates whether bitmaps are required for the glyphs. This
        function uses FreeType 2's FT_Load_Glyph() to load the glyph
        data.

    
Loading glyphs involves more than just reading data. Xft uses
        the Fontconfig pattern associated with the display dpy to
        determine whether to use bounding boxes, clip glyphs, scale them, compute
        font metrics, and add them to the X Render extension using
        XRenderAddGlyphs().

  

  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Unloads the glyphs specified by the array glyphs (containing
        nglyph glyph indices) for the font pub. If the glyphs
        were added to the X Render extension, they are removed using
        XRenderFreeGlyphs(). Xft keeps track of the memory used for
        glyphs and updates the usage statistics for the display dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Increments the reference count for the FreeType 2 face
        associated with the font pub. If no face has been created yet,
        it creates one using FT_New_Face(). This ensures that the face
        remains loaded while it is in use.

    
Face-locking is used by functions such as XftCharIndex()
        and XftFontLoadGlyphs().

    
Face-locking was introduced in Xft version 1 (October 2002).
        It was retained as a public API in version 2.1.9 (June 2006).

  

  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrements the reference count for the FreeType 2 face
        associated with the font pub. When the reference count reaches
        zero, the face is deallocated using FT_Done_Face().

FcBool XftNameUnparse (

Manipulating Font data



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory. Xft uses
      the Fontconfig pattern associated with the display dpy (e.g., via
      XftDefaultSet()) to determine whether to use a bounding box, clip
      the glyphs into those bounds, scale the glyphs, compute font metrics, and
      add it to the X Render extension using XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Discards data for up to nglyph glyphs whose glyph
        indices (Unicode values) are listed in the array glyphs for the
        given font pub. If the glyphs were added to the X Render
        extension, Xft removes those using XRenderFreeGlyphs(). Xft
        keeps track of the amount of memory used for glyphs, and updates the
        usage associated with the display dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory representation of a given
        typeface in a given style) has been created for the pub font,
        create one using FT_New_Face(). Face-locks are a reference count
        used by Xft to ensure that only one face is created, and that it is
        retained until the font is no longer used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few applications,
      such as Gdk/Gimp relied upon these functions. In version 2.1.9 (June
      2006), face-locking was retained as part of the public API when improved
      shared-library configurations provided for hiding private symbols.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrements the reference count for the FreeType 2 “face”
        associated with the font.

  





  

  
FT_Face objects are deallocated using FT_Done_Face(). Xft
      does this in XftFontInfoDestroy() and when cleaning up on failure
      in XftFontInfoCreate() and XftFontOpenPattern().

COMPATIBILITY


As of version 2 (May 2002), Xft became relatively stable. It is
    expected to retain source and binary compatibility in future releases.


Xft provides a compatibility interface to its previous major
    version, Xft 1.x, described below.




Xft 1.x Header File


#include <X11/Xft/XftCompat.h>






Xft 1.x Data Types



  
XftPattern

  
holds a set of names with associated value lists; each name refers to a
      property of a font. XftPatterns are used as inputs to the matching
      code as well as holding information about specific fonts.

  
XftFontSet

  
contains a list of XftPatterns. Internally, Xft uses this data
      structure to hold sets of fonts. Externally, Xft returns the results of
      listing fonts in this format.

  
XftObjectSet

  
holds a set of names and is used to specify which fields from fonts are
      placed in the list of returned patterns when listing fonts.
