NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando la información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuentes convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

De Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - C Language Interface.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

De XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener más detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

De Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc”, que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, y FcResult.

De FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_”, que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library, y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar *glifos*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que usan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFont se rellenan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder a un drawable X básico o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana que ofrezca el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color al servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado para un XftColor.

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa explícitamente la biblioteca. Eso se hace normalmente como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft determinó que la pantalla soporta la extensión X Render, y si es capaz de encontrar un XRenderPictFormat adecuado (el tipo de datos de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza estas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes sin referencia (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft completa las propiedades faltantes en el patrón dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar suavizado (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para engrosar una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor mínimo de espacio utilizado al completar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al completar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión X Render (predeterminado: resultado de XftDefaultHasRender()).

Abrir y emparejar fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triples de elementos de patrón del tipo
        campo, tipo, valor (terminada con un
        NULL), empareja ese patrón con las fuentes disponibles, y abre la
        fuente coincidente, dimensionándola correctamente para el número de pantalla screen en la pantalla dpy. Devuelve la fuente emparejada, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Esto abre la fuente “charter” a 12 puntos. El tamaño en puntos
      se convierte automáticamente al tamaño de píxeles correcto según la
      resolución del monitor.

FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analiza el parámetro xlfd_orig
        de acuerdo con el documento *Convenciones de Descripción Lógica de Fuentes X*
        (X Logical Font Description Conventions), pero ignora algunos de los campos:
        setwidth_name, add_style_name, spacing, y
        average_width.

  





  

  
XftXlfdParse crea un patrón Fontconfig, estableciendo la propiedad
      XFT_XLFD al valor xlfd_orig, y mapea la información recopilada
      a propiedades de Fontconfig. Los campos vacíos o con "*" se ignoran:







  
FC_FOUNDRY

  
desde foundry.

  
FC_FAMILY

  
desde family.

  
FC_WEIGHT

  
weight_name, con un valor predeterminado de FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
desde slant, con un valor predeterminado de FC_SLANT_ROMAN.

  
FC_SIZE

  
desde point_size.

  
FC_PIXEL_SIZE

  
desde pixel_size. Si se estableció point_size, así como
      resolution_x y resolution_y, entonces el valor se escala
      para convertir la altura de la fuente a puntos.

Gestión   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utiliza XAllocNamedColor() para buscar el color nombrado
        name para la pantalla asociada con el mapa de colores
        cmap.

  






    
  
  • Si XAllocNamedColor() devuelve un valor distinto de cero,
      XftColorAllocName() rellena el campo de píxel XftColor resultante
      con el color más cercano soportado por la pantalla, así como los campos exactos
      de rojo, verde y azul de la base de datos, y devuelve True.
    • 
  
  • Si XAllocNamedColor() devuelve cero, XftColorAllocName()
      devuelve False, y no actualiza el XftColor referenciado por
      result.
    • 






  

  
El parámetro visual no se utiliza.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Asigna un valor de color:

  






    
  
  • Si la clase visual es TrueColor, XftColorAllocValue() establece
      el campo pixel en el XftColor referenciado por result
      utilizando los campos rojo, verde y azul del parámetro color.
    • 
  
  • Si la clase visual no es TrueColor, XftColorAllocValue()
      llama a XAllocColor() para asignar una entrada en el mapa de colores
      cmap. que devuelve el valor de píxel del color más cercano a los
      elementos RGB especificados soportados por el hardware.

DESCRIPTION
       The Xft library provides functions for rendering fonts using the Xft
       font rasterizer. The Xft library is an interface to FreeType, and it uses
       the X rendering extension if available.

       This page describes the functions used to create and manage Xft draw
       objects.

   Creating XftDraw Objects
       XftDraw objects are used as targets for drawing operations. They associate
       an X drawable (like a window or a pixmap) with a fontconfig pattern,
       visual, and colormap.

       XftDrawCreate()
               Creates an XftDraw object associated with the X drawable
               drawable, using the specified visual and colormap.
               If visual is NULL, the visual of the drawable is used. If
               colormap is None, the colormap of the drawable is used.

       XftDrawCreatePixmap()
               Behaves like XftDrawCreate(), except that it uses an X pixmap of
               color depth 1 instead of an X drawable. This is useful for
               creating monochrome bitmaps.

       XftDrawCreateAlpha()
               Behaves like XftDrawCreate(), except that it uses an X pixmap of
               color depth depth instead of an X drawable. This is useful
               for creating pixmaps with alpha channel support.

   Managing XftDraw Objects
       XftDrawChange()
               Changes the X drawable associated with an existing XftDraw
               object. This is useful if the drawable associated with the object
               has changed (e.g., due to window resizing).

       XftDrawDisplay()
               Returns a pointer to the X display associated with the XftDraw
               object.

       XftDrawDrawable()
               Returns the X drawable associated with the XftDraw object.

       XftDrawColormap()
               Returns the colormap associated with the XftDraw object.

       XftDrawVisual()
               Returns a pointer to the visual associated with the XftDraw
               object.

       XftDrawPicture()
               Returns the X Render Picture object associated with the XftDraw
               object. If the X server does not support the X Rendering
               Extension, 0 is returned.

       XftDrawSrcPicture()
               Returns an X Render Picture object, which is used for rendering
               glyphs, e.g., with XftGlyphRender(), XftGlyphSpecRender(), or
               XftGlyphFontSpecRender(), by XftDrawGlyphs(),
               XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), respectively. If the
               X server does not support the X Render extension, those functions
               use XftGlyphCore(), XftGlyphSpecCore(), or XftGlyphFontSpecCore().

       XftDrawDestroy()
               Destroys an XftDraw object and frees the memory allocated for
               it. This should be called when the XftDraw object is no longer
               needed.

   Clipping
       XftDrawSetClip()
               Sets the clipping region for the XftDraw object. The r
               parameter is a Region object. If r is not NULL, Xft creates
               a new Region to copy the parameter. Xft destroys any existing
               clipping region. Xft sets the clip_type for the draw parameter to
               XftClipTypeRegion if the r parameter was not null. Otherwise
               it sets the clip_type to XftClipTypeNone. Finally, Xft updates
               clipping for existing objects, updates the clip_mask for its X
               Render Picture object and sets the clipping-mask in the graphic
               context (GC) associated with the XftDraw parameter.
               XftDrawSetClip() returns True if no change was necessary, or if
               the operation succeeded. It returns False if it was unable to
               create the new Region().

       XftDrawSetClipRectangles()
               Like XftDrawSetClip(), this function sets up clipping for the
               given XftDraw object but uses a set of n rectangles (the
               rects parameter) which could be used to construct a Region.
               Xft sets the clip_type for draw to XftClipTypeRectangles
               and uses XSetClipRectangles() for core (X11) clipping and
               XRenderSetPictureClipRectangles() for X Render clipping.

       XftDrawSetSubwindowMode()
               Sets the subwindow-mode for the given XftDraw object. The mode
               can be either ClipByChildren (the default), or IncludeInferiors.
               For ClipByChildren, both source and destination windows are
               additionally clipped by all viewable InputOutput children. For
               IncludeInferiors, neither source nor destination window is clipped
               by inferiors. This will result in including subwindow contents in
               the source and drawing through subwindow boundaries of the
               destination. In addition to the subwindow-mode maintained by Xft,
               it updates the subwindow mode for any associated graphics context
               GC using XSetSubwindowMode() as well as for an X Render Picture
               using XRenderChangePicture().

   Drawing Strings
       XftDrawString8()
               Draws a string of len bytes from string to the Xft
               drawable d using the specified font and color at
               position x, y.

   Drawing Other Things
       XftDrawRect()
               Draws a solid rectangle of the specified color, width, and
               height at position x, y to the Xft drawable d.

       XftCharFontSpecRender()
               Converts the chars parameter from XftCharFontSpec to
               XftGlyphFontSpec, passing the converted array along with the
               other parameters unchanged to XftGlyphFontSpecRender() to render
               the data.

       XftDrawGlyphFontSpec()
               Draws a list of glyphs associated with fonts at specified
               coordinates, passed as an array of len
               XftGlyphFontSpec structures via the parameter glyphs. All
               of the glyphs are drawn using the color specified in the color
               parameter. For each entry in the glyphs array: If the
               associated font uses the X Render extension, then Xft uses
               XftGlyphFontSpecRender() to draw the glyph, using a Picture
               obtained from calling XftDrawSrcPicture() with the draw
               and color parameters. Otherwise, Xft provides an analogous
               feature using Xlib.

       XftGlyphFontSpecRender()
               This involves several steps: First, Xft ensures that the
               glyphs array is complete using XftFontCheckGlyph() and
               loading any missing glyphs with XftFontLoadGlyphs(). Then Xft
               examines the glyphs to find the maximum Unicode value. That
               determines the encoding size, i.e., the width. Then, for
               each glyph, Xft checks if its Unicode value is handled by the
               corresponding font. If not, the value is set to zero (0), to
               ignore it. While doing this, Xft also remembers which was the
               first font used, and computes the position at which each glyph will
               be drawn. Xft then constructs an equivalent array of glyphs in the
               format expected by the X Render library. Finally,
               XftGlyphFontSpecRender() uses the X Render extension to draw the
               glyphs, with the appropriate XRenderCompositeText*() function
               according to the width, and discards temporary data. The
               op, dst, src, srcx, and srcy parameters are
               used as described in the documentation for the X Render library.

   Manipulating patterns
       XftListFonts()
               Xft uses FcPatternVapBuild() and FcObjectSetVapBuild() to process
               the variable-length parameter list, and FcFontList() to obtain a
               list of matching Fontconfig patterns, which it returns to the
               caller. The caller can dispose of the return value using
               FcPatternDestroy().

       FcPattern * XftNameParse (
               _Xconst char *name);

       Parses a font name string and returns a font pattern.

    library. It also provides an interface to the Fontconfig library for font
    matching. This document describes only a few of the functions available from
    Xft.




Parsing and Unparsing font names



  
FcBool XftNameParse (

  

    
	const char	*name,
	FcPattern	**pat);


    
Parses a font name string into a Fontconfig pattern.
        XftNameParse() stores the resulting pattern at the location pointed
        to by pat. If the name is valid, it returns FcTrue,
        otherwise it returns FcFalse.

    
Xft uses Fontconfig to parse the name, passing the
        name to FcNameParse(), returning the result.

  

  
FcBool XftNameUnparse (

  

    
	const XftPattern	*pat,
	char	*dest,
	int	 len);


    
Like XfgNameParse(), Xft uses Fontconfig. In
        this case, it uses FcNameUnparse(), which converts the pattern
        pat back into a string that can be parsed.
        XftNameUnparse() stores the result via the caller's pointer
        dest, but checks first if it will fit, using the len
        parameter. If it fits, Xft copies the string and returns
        FcTrue, otherwise it returns FcFalse.

  








Manipulating   Font data



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	const FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory.
      Xft uses the Fontconfig pattern associated with the display
      dpy (e.g., via XftDefaultSet()) to determine whether to use
      a bounding box, clip the glyphs into those bounds, scale the glyphs,
      compute font metrics, and add it to the X Render extension using
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	const FT_UInt	*glyphs,
	int	 nglyph);


    
Discards data for up to nglyph glyphs whose glyph
        indices (Unicode values) are listed in the array glyphs for the
        given font pub. If the glyphs were added to the X Render
        extension, Xft removes those using XRenderFreeGlyphs().
        Xft keeps track of the amount of memory used for glyphs, and
        updates the usage associated with the display dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory
        representation of a given typeface in a given style) has been created
        for the pub font, create one using FT_New_Face().
        Face-locks are a reference count used by Xft to ensure that only
        one face is created, and that it is retained until the font is no longer
        used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few
      applications, such as Gdk/Gimp relied upon these functions. In version
      2.1.9 (June 2006), face-locking was retained as part of the public API
      when improved shared-library configurations provided for hiding private
      symbols.

    converts that to an integer. Each bit in the resulting value tells
    Xft to print debugging information to the standard output:



  
1

  
font-opening

  
2

  
additional font-matching and opening (verbose)

  
4

  
shows details about the XRenderPictFormat which will be used.

  
8

  
shows the string which XftDrawString8() will draw.

  
16

  
shows which font-ids are matched.

  
32

  
shows useful information about the glyphs which will be drawn

  
64

  
shows an ASCII-art representation of the glyphs.

  
128

  
shows details about the memory-cache management

  
256

  
shows details about managing glyph cached-memory

  
512

  
shows a report on memory-usage

  
1024

COMPATIBILITY


As of version 2 (May 2002), Xft became relatively stable.
    It is expected to retain source and binary compatibility in future
  releases.

    major version, Xft 1.x, described below.

#include <X11/Xft/XftCompat.h>






Xft   1.x Data Types



  
XftPattern

  
holds a set of names with associated value lists; each name refers to a
      property of a font. XftPatterns are used as inputs to the matching
      code as well as holding information about specific fonts.

  
XftFontSet

  
contains a list of XftPatterns. Internally, Xft uses this
      data structure to hold sets of fonts. Externally, Xft returns the
      results of listing fonts in this format.

  
XftObjectSet

  
holds a set of names and is used to specify which fields from fonts are
      placed in the list of returned patterns when listing fonts.
