Xft(3) Versión X11 Xft(3)

NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando la información proporcionada por la biblioteca Fontconfig,
  • Xft convierte los glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la extensión X Rendering Extension.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían utilizar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, anteponiendo a todos los nombres "Xft"

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz del Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, anteponiendo a todos los nombres "Fc", que se documentan en la Referencia para desarrolladores de Fontconfig.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, anteponiendo a todos los nombres "FT_", que se documentan en la Referencia de la API de FreeType.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFonts se rellenan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo() o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador no necesita asignar ni liberar almacenamiento para ellos habitualmente.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder a un drawable de X principal o a un drawable de la extensión X Rendering Extension.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar los límites (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender() y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la extensión X Rendering Extension.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la extensión X Rendering Extension en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy() y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador no necesita asignar ni liberar almacenamiento para ellos habitualmente.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color del servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado a un XftColor.

Una vez que se ha inicializado un XftColor, se pueden usar XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec() y XftDrawRect() para dibujar varios objetos utilizándolo.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable de X utilizando el protocolo principal o la extensión X Rendering.

Los objetos XftDraw se crean con cualquiera de las funciones XftDrawCreate() (que asocia un XftDraw con un drawable de X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable de X asociado con un XftDraw puede cambiarse con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar ni liberar almacenamiento para ellos.

Las propiedades Display, Drawable, Colormap, y Visual de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

La extensión X Rendering Picture asociada con un XftDraw se devuelve mediante XftDrawPicture(), y XftDrawSrcPicture(). Es utilizada por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa explícitamente la biblioteca. Eso generalmente se hace como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón Fontconfig (esencialmente una colección de propiedades con valores tipificados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft determinó que la pantalla soporta la extensión X Render, y si puede encontrar un XRenderPictFormat adecuado (el tipo de datos de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón Fontconfig que contiene las propiedades predeterminadas que Xft usará para esta pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft rellena las propiedades faltantes en el patrón dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se estableció en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar suavizado (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos/pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para embellecer una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al rellenar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al rellenar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al rellenar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al rellenar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión X Render (predeterminado: resultado de XftDefaultHasRender()).

Abrir y Coincidir Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triplete de elementos de patrón de la forma campo, tipo, valor (terminada con un NULL), coincide con ese patrón contra las fuentes disponibles, y abre la fuente coincidente, dimensionándola correctamente para el número de pantalla screen en la pantalla dpy. Devuelve la fuente coincidente, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño del punto se convierte automáticamente al tamaño de píxel correcto según la resolución del monitor.

DESCRIPTION
    The Xft library provides a mechanism for rendering fonts using the FreeType
    library, and drawing them to X drawables and X pictures.

    The Xft draw object is created using one of the XftDrawCreate*() functions.
    It is then used to draw strings, rectangles, and glyphs to the associated X
    drawable or X picture. The Xft draw object should be destroyed using
    XftDrawDestroy() when it is no longer needed.

XftDrawCreate()
    Creates an Xft draw object for the specified X drawable, visual, and
    colormap. The drawable can be a window or a pixmap. The visual and colormap
    specify the visual and colormap to be used for rendering. If the X server
    does not support the X Rendering Extension, then Xft will use the core X
    protocol for rendering.

XftDrawCreatePixmap()
    XftDrawCreatePixmap() behaves as XftDrawCreate(), except that it uses an X
    pixmap of color depth 1 instead of an X drawable.

XftDrawCreateAlpha()
    XftDrawCreateAlpha() behaves as XftDrawCreate(), except that it uses an X
    pixmap of color depth depth instead of an X drawable.

XftDrawChange()
    XftDrawChange() changes the X drawable association of the existing Xft draw
    object draw from its current value to drawable.

XftDrawDisplay()
    XftDrawDisplay() returns a pointer to the display associated with the Xft
    draw object draw.

XftDrawDrawable()
    XftDrawDrawable() returns the X drawable associated with the Xft draw object
    draw.

XftDrawColormap()
    XftDrawColormap() returns the colormap associated with the Xft draw object
    draw.

XftDrawVisual()
    XftDrawVisual() returns a pointer to the visual associated with the Xft draw
    object draw.

XftDrawPicture()
    XftDrawPicture() returns the picture associated with the Xft draw object
    draw.
        If the X server does not support the X Rendering Extension, 0 is
        returned.

XftDrawSrcPicture()
    Return an X Render Picture object, which is used for rendering glyphs, e.g.,
    with XftGlyphRender(), XftGlyphSpecRender(), or XftGlyphFontSpecRender(),
    by XftDrawGlyphs(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(),
    respectively.
        If the X server does not support the X Render extension, those functions
        use XftGlyphCore(), XftGlyphSpecCore(), or XftGlyphFontSpecCore().

XftDrawDestroy()
    XftDrawDestroy() destroys draw (created by one of the XftDrawCreate*()
    functions) and frees the memory that was allocated for it.

XftDrawSetClip()
    Set up clipping for the given XftDraw parameter draw starting with a Region:
        - If the Region parameter r is not null, Xft creates a new Region (to copy the parameter),
        - Xft destroys any existing clipping region.
        - Xft sets the clip_type for the draw parameter to XftClipTypeRegion if the r parameter was not null. Otherwise it sets the clip_type to XftClipTypeNone.
        - Finally, Xft updates clipping for existing objects, updates the clip_mask for its X Render Picture object and sets the clipping-mask in the graphic context (GC) associated with the XftDraw parameter.
    XftDrawSetClip() returns True if no change was necessary, or if the operation succeeded. It returns False if it was unable to create the new Region().

XftDrawSetClipRectangles()
    Like XftDrawSetClip(), XftDrawSetClipRectangles() sets up clipping for the
    given XftDraw parameter draw but uses a set of n rectangles (the rects
    parameter) which could be used to construct a Region .
    Xft sets the clip_type for draw to XftClipTypeRectangles and uses XSetClipRectangles() for core (X11) clipping and XRenderSetPictureClipRectangles() for X Render clipping.

XftDrawSetSubwindowMode()
    Sets the subwindow-mode for the given XftDraw parameter draw. The mode can
    be either ClipByChildren (the default), or IncludeInferiors:
        - For ClipByChildren, both source and destination windows are additionally clipped by all viewable InputOutput children.
        - For IncludeInferiors, neither source nor destination window is clipped by inferiors. This will result in including subwindow contents in the source and drawing through subwindow boundaries of the destination.
    In addition to the subwindow-mode maintained by Xft, it updates the subwindow
    mode for any associated graphics context GC using XSetSubwindowMode() as
    well as for an X Render Picture using XRenderChangePicture().

Drawing Strings
    XftDrawString8()
        XftDrawString8() draws no more than len glyphs of string to Xft
        drawable d using font in color at position x, y.

Drawing Other Things
    XftDrawRect()
    XftDrawRect() draws a solid rectangle of the specified color, width, and
    height at position x, y to Xft drawable d.

    XftCharFontSpecRender()
    XftCharFontSpecRender() converts the chars parameter from XftCharFontSpec
    to XftGlyphFontSpec, passing the converted array along with the other
    parameters unchanged to XftGlyphFontSpecRender() to render the data.

    XftDrawGlyphFontSpec()
    Draw a list of glyphs associated with fonts at specified coordinates,
    passed as an array of len XftGlyphFontSpec structures via the parameter
    glyphs. All of the glyphs are drawn using the color specified in the color
    parameter.
        For each entry in the glyphs array:
            - If the associated font uses the X Render extension, then Xft uses
              XftGlyphFontSpecRender() to draw the glyph, using a Picture
              obtained from calling XftDrawSrcPicture () with the draw and
              color parameters.
            - Otherwise, Xft provides an analogous feature using Xlib.

    XftGlyphFontSpecRender()
        This involves several steps:
            - First, Xft ensures that the glyphs array is complete using
              XftFontCheckGlyph() and loading any missing glyphs with
              XftFontLoadGlyphs().
            - Then Xft examines the glyphs to find the maximum Unicode value.
              That determines the encoding size, i.e., the width.
            - Then, for each glyph, Xft checks if its Unicode value is handled by
              the corresponding font. If not, the value is set to zero (0), to
              ignore it. While doing this, Xft also remembers which was the
              first font used, and computes the position at which each glyph
              will be drawn.
            - Xft then constructs an equivalent array of glyphs in the format
              expected by the X Render library.
            - Finally, XftGlyphFontSpecRender() uses the X Render extension to
              draw the glyphs, with the appropriate XRenderCompositeText*()
              function according to the width, and discards temporary data.
    The op, dst, src, srcx, and srcy parameters are used as described in the
    documentation for the X Render library.

Manipulating patterns

        Display *dpy,

        variable-length parameter list, and FcFontList() to obtain a list of
        matching Fontconfig patterns, which it returns to the caller. The caller
        can dispose of the return value using FcPatternDestroy().

    FcPattern * XftNameParse (
        _Xconst char *name
    );

    from a font list using XftListFonts(). These patterns can then be used in
    calls to FcFontOpen() or FcFontOpenInfo(). The pattern is destroyed using
    FcPatternDestroy().

BUGS
    The Xft library does not support font substitution. If a font is not found,
    an error will be generated.

DESCRIPCIÓN


El sistema de fuentes Xft permite que las aplicaciones X obtengan
    acceso a las fuentes de alta calidad proporcionadas por la biblioteca FreeType
    2. Esto proporciona un renderizado de fuentes antialiased y la capacidad de
    acceder a un conjunto mucho más amplio de fuentes que el proporcionado por
    X Logical Font Description (XLFD).




Abrir fuentes


Las funciones XftFontOpen, XftFontOpenName y XftFontOpenXlfd se utilizan para abrir fuentes. Todas estas funciones devuelven un puntero a una estructura XftFont que contiene información sobre la fuente abierta. Si se produce un error, se devuelve NULL.


XftFontOpen toma un puntero a una pantalla
    X (dpy) y un puntero a datos específicos de la fuente.
    La interpretación de los argumentos data y data2 depende de la naturaleza de los datos pasados en ellos.


XftFontOpenName toma un nombre de fuente
    en el formato de Fontconfig. XftFontOpenXlfd toma un
    nombre de fuente en el formato XLFD. En ambos casos, la biblioteca Fontconfig
    se utiliza para buscar la fuente más cercana que coincida con el nombre
    proporcionado.


Una vez que se ha abierto una fuente, puede cerrarla llamando a
    XftFontClose, pasando el puntero dpy
    y el puntero XftFont devuelto por la llamada a XftFontOpen*.


XftFontMatch es una función para encontrar
    la fuente que mejor coincide con un patrón dado (pat).
    La biblioteca Fontconfig se utiliza para realizar esta coincidencia.
    Se devuelve un puntero a una estructura XftFont que representa
    la fuente coincidente, o NULL si no se encuentra ninguna
    coincidencia. El parámetro result contendrá información
    sobre el resultado de la operación de coincidencia.


XftFontSpecialize toma una fuente existente
    (font) y un patrón de Fontconfig (pat).
    Devuelve una nueva estructura XftFont que es una
    especialización de la fuente original, coincidiendo con las propiedades
    especificadas en pat. Si la fuente original ya cumple
    con el patrón, se puede devolver la fuente original.

FcBool XftNameUnparse (

  

    
	const FcPattern	*pat,
	char	*dest,
	int	 len);


    
Al igual que XfgNameParse(), Xft utiliza Fontconfig.
        En este caso, utiliza FcNameUnparse(), que convierte el patrón
        pat de nuevo a una cadena que se puede analizar.
        XftNameUnparse() almacena el resultado a través del puntero del
        llamante dest, pero comprueba primero si cabrá,
        utilizando el parámetro len. Si cabe, Xft
        copia la cadena y devuelve FcTrue, de lo contrario devuelve
        FcFalse.

void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	const FT_UInt	*glyphs,
	int	 nglyph);


    
Utilizando FT_Load_Glyph(), carga nglyphs
        para los índices de glifos (valores Unicode) listados en el array
        glyphs de la fuente dada pub.

  





  

  
Cargar un glifo implica más que simplemente leer datos en memoria.
      Xft utiliza el patrón Fontconfig asociado con la pantalla
      dpy (por ejemplo, a través de XftDefaultSet())
      para determinar si se utiliza un cuadro delimitador, recortar los glifos
      dentro de esos límites, escalar los glifos, calcular métricas de fuentes y
      añadirlo a la extensión X Render utilizando XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	const FT_UInt	*glyphs,
	int	 nglyph);


    
Descarta datos para hasta nglyph glifos cuyos
        índices de glifos (valores Unicode) están listados en el array
        glyphs para la fuente dada pub. Si los glifos
        se añadieron a la extensión X Render, Xft los elimina usando
        XRenderFreeGlyphs(). Xft lleva la cuenta de la cantidad
        de memoria utilizada para los glifos y actualiza el uso asociado con
        la pantalla dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si no se ha creado ninguna "cara" de FreeType 2 (representación
        en memoria de un tipo de letra dado en un estilo dado) para la fuente
        pub, créela usando FT_New_Face(). Los bloqueos
        de cara son un contador de referencias utilizado por Xft para
        asegurar que solo se crea una cara y que se conserva hasta que la fuente
        ya no se utiliza.

      aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la versión
      2.1.9 (junio de 2006), se mantuvo el bloqueo de cara como parte de la API
      pública cuando las configuraciones mejoradas de bibliotecas compartidas
      proporcionaron la ocultación de símbolos privados.

COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió relativamente
    estable. Se espera que mantenga la compatibilidad de origen y binaria en
    futuras versiones.


Xft proporciona una interfaz de compatibilidad con su
    versión principal anterior, Xft 1.x, descrita a continuación.




Archivo de encabezado de Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de datos de Xft 1.x



  
XftPattern

  
almacena un conjunto de nombres con listas de valores asociadas; cada nombre
      se refiere a una propiedad de una fuente. Los XftPattern se utilizan
      como entradas para el código de coincidencia, así como para almacenar
      información sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPattern. Internamente, Xft utiliza
      esta estructura de datos para almacenar conjuntos de fuentes. Externamente,
      Xft devuelve los resultados de listar fuentes en este formato.

  
XftObjectSet

  
almacena un conjunto de nombres y se utiliza para especificar qué campos de
      las fuentes se colocan en la lista de patrones devueltos al listar
    fuentes.
