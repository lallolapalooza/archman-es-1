Paquete: libx11

XCreateColormap(3) FUNCIONES DE XLIB XCreateColormap(3)

NOMBRE

XCreateColormap, XCopyColormapAndFree, XFreeColormap, XColor - crear, copiar o destruir mapas de colores y estructuras de color

SINTAXIS

Colormap XCreateColormap(Display *display, Window w, Visual *visual, int alloc);

Colormap XCopyColormapAndFree(Display *display, Colormap colormap);

int XFreeColormap(Display *display, Colormap colormap);

ARGUMENTOS

alloc
Especifica las entradas del mapa de colores a asignar. Puedes pasar AllocNone o AllocAll.
colormap
Especifica el mapa de colores que deseas crear, copiar, establecer o destruir.
display
Especifica la conexión con el servidor X.
visual
Especifica un tipo de visualización soportado en la pantalla. Si el tipo de visualización no es uno soportado por la pantalla, se produce un error BadMatch.
w
Especifica la ventana en cuya pantalla deseas crear un mapa de colores.

DESCRIPCIÓN

La función XCreateColormap crea un mapa de colores del tipo de visualización especificado para la pantalla en la que reside la ventana especificada y devuelve el ID del mapa de colores asociado a él. Ten en cuenta que la ventana especificada solo se utiliza para determinar la pantalla.

Los valores iniciales de las entradas del mapa de colores no están definidos para las clases de visualización GrayScale, PseudoColor y DirectColor. Para StaticGray, StaticColor y TrueColor, las entradas tienen valores definidos, pero esos valores son específicos de la visualización y no están definidos por X. Para StaticGray, StaticColor y TrueColor, alloc debe ser AllocNone, o se producirá un error BadMatch. Para las otras clases de visualización, si alloc es AllocNone, el mapa de colores inicialmente no tiene entradas asignadas, y los clientes pueden asignarlas. Para obtener información sobre los tipos de visualización, consulta la sección 3.1.

Si alloc es AllocAll, todo el mapa de colores se asigna como escribible. Los valores iniciales de todas las entradas asignadas no están definidos. Para GrayScale y PseudoColor, el efecto es como si una llamada a XAllocColorCells devolviera todos los valores de píxel de cero a N - 1, donde N es el número de entradas del mapa de colores en la visualización especificada. Para DirectColor, el efecto es como si una llamada a XAllocColorPlanes devolviera un valor de píxel de cero y valores de máscara roja, verde y azul que contengan los mismos bits que las máscaras correspondientes en la visualización especificada. Sin embargo, en todos los casos, ninguna de estas entradas puede liberarse usando XFreeColors.

XCreateColormap puede generar errores BadAlloc, BadMatch, BadValue y BadWindow.

La función XCopyColormapAndFree crea un mapa de colores del mismo tipo de visualización y para la misma pantalla que el mapa de colores especificado y devuelve el nuevo ID del mapa de colores. También mueve toda la asignación existente del cliente del mapa de colores especificado al nuevo mapa de colores con sus valores de color intactos y sus características de solo lectura o escritura intactas, y libera esas entradas en el mapa de colores especificado. Los valores de color en otras entradas del nuevo mapa de colores no están definidos. Si el mapa de colores especificado fue creado por el cliente con alloc establecido en AllocAll, el nuevo mapa de colores también se crea con AllocAll, todos los valores de color para todas las entradas se copian del mapa de colores especificado, y luego se liberan todas las entradas del mapa de colores especificado. Si el mapa de colores especificado no fue creado por el cliente con AllocAll, las asignaciones a mover son todos aquellos píxeles y planos que han sido asignados por el cliente usando XAllocColor, XAllocNamedColor, XAllocColorCells o XAllocColorPlanes y que no han sido liberados desde que fueron asignados.

XCopyColormapAndFree puede generar errores BadAlloc y BadColor.

La función XFreeColormap elimina la asociación entre el ID del recurso del mapa de colores y el mapa de colores, y libera el almacenamiento del mapa de colores. Sin embargo, esta función no tiene efecto en el mapa de colores predeterminado de una pantalla. Si el mapa de colores especificado es un mapa instalado para una pantalla, se desinstala (ver XUninstallColormap). Si el mapa de colores especificado se define como el mapa de colores para una ventana (por XCreateWindow, XSetWindowColormap o XChangeWindowAttributes), XFreeColormap cambia el mapa de colores asociado con la ventana a None y genera un evento ColormapNotify. X no define los colores mostrados para una ventana con un mapa de colores de None.

XFreeColormap puede generar un error BadColor.

ESTRUCTURAS

La estructura XColor contiene:

typedef struct {
        unsigned long pixel;    /* valor del píxel */
        unsigned short red, green, blue;        /* valores rgb */
        char flags;     /* DoRed, DoGreen, DoBlue */
        char pad;
} XColor;

Los valores rojo, verde y azul siempre están en el rango de 0 a 65535 inclusive, independientemente del número de bits realmente utilizados en el hardware de visualización. El servidor escala estos valores al rango utilizado por el hardware. El negro se representa con (0,0,0) y el blanco con (65535,65535,65535). En algunas funciones, el miembro flags controla cuáles de los miembros rojo, verde y azul se utilizan y puede ser el OR inclusivo de cero o más de DoRed, DoGreen y DoBlue.

DIAGNÓSTICOS

BadAlloc
El servidor no pudo asignar el recurso o la memoria del servidor solicitados.
BadColor
Un valor para un argumento de Colormap no nombra un Colormap definido.
BadMatch
Se usa una ventana InputOnly como Drawable.
BadMatch
Algún argumento o par de argumentos tiene el tipo y rango correctos pero no coincide de alguna otra manera requerida por la solicitud.
BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango específico para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
BadWindow
Un valor para un argumento de Ventana no nombra una Ventana definida.

    XFreeColormap(3)

    NAME

    XFreeColormap - liberar un mapa de colores

    SYNOPSIS

    #include <X11/Xlib.h>

    Status XFreeColormap(Display *display, Colormap colormap);

    DESCRIPTION

    La función XFreeColormap libera el mapa de colores especificado. El mapa de colores debe haber sido creado previamente por XCreateColormap o XCopyColormapAndInstalledColormap.

    Si el mapa de colores es el mapa de colores actual para alguna ventana, esta operación no tendrá efecto inmediato en las ventanas. Sin embargo, la aplicación no debe volver a usar el mapa de colores después de liberarlo.

    RETURN VALUES

    XFreeColormap devuelve Success si el mapa de colores se liberó correctamente. De lo contrario, devuelve un código de error.

    DIAGNOSTICS

    Si ocurre un error, XFreeColormap puede devolver uno de los siguientes códigos de error:

    • BadColorMap: El mapa de colores especificado no es válido.
    • BadAlloc: No se pudo asignar memoria para liberar el mapa de colores.

    SEE ALSO

    XCreateColormap(3), XCopyColormapAndInstalledColormap(3)
