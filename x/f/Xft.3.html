NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca simple que dibuja texto y gráficos:

  • utilizando la información proporcionada por la biblioteca Fontconfig,
  • Xft convierte los glifos de las fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de la fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas roza la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("La versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con "Xft"

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Están documentados en Xlib - Interfaz del lenguaje C.

Xft usa estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps se pueden usar como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft usa estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con "Fc", que están documentados en Fontconfig Developers Reference.

Xft usa estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con "FT_", que están documentados en FreeType API Reference.

Xft usa estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 usa FT_UInt (un entero sin signo) para representar *glifos*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFont se rellenan con XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo() o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder a un drawable de X core o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender() y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy() y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color del servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado para un XftColor.

Una vez que un XftColor ha sido inicializado, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec() y XftDrawRect() pueden usarse para dibujar varios objetos utilizando este.

STRUCTURES

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable X utilizando el protocolo principal o la extensión X Rendering.

Los objetos XftDraw se crean con cualquiera de las funciones XftDrawCreate() (que asocia un XftDraw con un drawable X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable X asociado con un XftDraw puede cambiarse con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar espacio para ellos.

Las propiedades X Display, Drawable, Colormap y Visual de un XftDraw pueden consultarse con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

La extensión X Rendering Picture asociada con un XftDraw es devuelta por XftDrawPicture() y XftDrawSrcPicture(). Es utilizada por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa explícitamente la biblioteca. Eso generalmente se hace como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft encontró que la pantalla soporta la extensión X Render, y si es capaz de encontrar un XRenderPictFormat adecuado (el tipo de datos de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esa pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuál descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft rellena las propiedades faltantes en el pattern dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar anti-aliasing (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para embellecer una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al rellenar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al rellenar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al rellenar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al rellenar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión X Render (predeterminado: resultado de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Inicializa la biblioteca Fontconfig (llamando a FcInit()).

El parámetro config no se utiliza.
Xft no desinicializa la biblioteca Fontconfig cuando termina.
FcBool XftInitFtLibrary (void);

    
Inicializa la biblioteca FreeType (llamando a
        FT_Init_FreeType() para crear un objeto de biblioteca) si aún no
        se ha inicializado. Esto es necesario antes de usar la biblioteca FreeType
        para leer datos de fuentes de un archivo.

  





  

  
Xft llama a XftInitFtLibrary() internamente a través de
      XftFontInfoCreate() y XftFontOpenPattern().

  

  
Xft no descarta el objeto de biblioteca (por ejemplo, usando
      FT_Done_FreeType()) cuando termina.

Apertura y Coincidencia de Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triplas de elementos de patrón
        de la forma campo, tipo, valor (terminada con NULL),
        coincide ese patrón con las fuentes disponibles, y abre la fuente coincidente,
        dimensionándola correctamente para el número de pantalla screen en
        la pantalla dpy. Devuelve la fuente coincidente, o NULL si no se encuentra
        ninguna coincidencia.

  




Ejemplo:
    




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);






  

  
Esto abre la fuente “charter” a 12 puntos. El tamaño del punto se
      convierte automáticamente al tamaño de píxel correcto según la resolución
      del monitor.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName se comporta como XftFontOpe





n hace,
        excepto que toma una cadena de patrón Fontconfig (que se pasa a la
        función FcNameParse() de la biblioteca Fontconfig).

  
  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*xlfd)


    
XftFontOpenXlfd se comporta como lo hace XftFontOpen,
        excepto que toma una cadena que contiene una Descripción Lógica de Fuente X
        (XLFD), y utiliza la función XftXlfdParse().

  

  
FcPattern *XftFontMatch (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst FcPattern	*pattern,
	FcResult	*result);


    
También utilizado internamente por las funciones
        XftFontOpen*, XftFontMatch también se puede utilizar
        directamente para determinar el patrón de fuente Fontconfig resultante
        de una solicitud de apertura de fuente Xft.

  

  
FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analiza el parámetro xlfd_orig
        según el documento de X Logical Font Description Conventions,
        pero ignora algunos de los campos: setwidth_name,
        add_style_name, spacing y average_width.

  




  

  
XftXlfdParse crea un patrón Fontconfig, estableciendo la propiedad
      XFT_XLFD con el valor xlfd_orig, y mapea la información
      recopilada a propiedades Fontconfig. Los campos vacíos o con "*” se
      ignoran:







  
FC_FOUNDRY

  
de foundry.

  
FC_FAMILY

  
de family.

  
FC_WEIGHT

  
weight_name, con un valor predeterminado de FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
de slant, con un valor predeterminado de FC_SLANT_ROMAN.

  
FC_SIZE

  
de point_size.

  
FC_PIXEL_SIZE

  
de pixel_size. Si se estableció point_size, así como
      resolution_x y resolution_y, entonces el valor se escala
      para convertir la altura de la fuente a puntos.

Determinación   de Extensiones de Texto


Xft proporciona varias funciones para determinar la altura
    y anchura necesarias para mostrar una cadena de texto. Después de tener en
    cuenta el offset, en casos en que la cadena se desplazará hacia
    arriba, abajo, izquierda o derecha, estos números se denominan
    extensiones de texto.

Gestión   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utiliza XAllocNamedColor() para buscar el color con
        nombre name para la pantalla asociada con el mapa de colores
        cmap.

  






    
  
  • Si XAllocNamedColor() devuelve un valor distinto de cero,
      XftColorAllocName() rellena el campo de píxel XftColor
      resultante con el color más cercano soportado por la pantalla, así como
      los campos exactos de rojo, verde y azul de la base de datos, y devuelve
      True.
    • 
  
  • Si XAllocNamedColor() devuelve cero, XftColorAllocName()
      devuelve False y no actualiza el XftColor al que hace referencia
      result.
    • 






  

  
El parámetro visual no se utiliza.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Asigna un valor de color:

  






    
  
  • Si la clase visual es TrueColor, XftColorAllocValue()
      establece el campo pixel en el XftColor al que hace
      referencia result utilizando los campos de rojo, verde y azul del
      parámetro color.
    • 
  
  • Si la clase visual no es TrueColor, XftColorAllocValue()
      llama a XAllocColor() para asignar una entrada en el mapa de
      colores cmap, que devuelve el valor de píxel del color más
      cercano a los elementos RGB especificados soportados por el hardware.
    • 




  

  
Si XAllocColor() tiene éxito, XftColorAllocValue() almacena
      ese valor de píxel en el XRenderColor al que hace referencia
      result y devuelve True.

  

  
Si XAllocColor() falla, XftColorAllocValue() devuelve False
      y no modifica el resultado.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Configura el recorte para el parámetro XftDraw dado
        draw comenzando con una Region:

  






    
  
  • Si el parámetro Region r no es nulo, Xft crea una nueva
      Region (para copiar el parámetro),
    • 
  
  • Xft destruye cualquier región de recorte existente.
    • 
  
  • Xft establece el tipo de recorte (clip_type) para el parámetro
      draw a XftClipTypeRegion si el parámetro r no era nulo.
      De lo contrario, establece el tipo de recorte a XftClipTypeNone.
    • 
  
  • Finalmente, Xft actualiza el recorte para los objetos existentes,
      actualiza la máscara de recorte (clip_mask) para su objeto Picture
      de X Render y establece la máscara de recorte en el contexto gráfico (GC)
      asociado con el parámetro XftDraw.
    • 






  

  
XftDrawSetClip() devuelve True si no fue necesario ningún cambio,
      o si la operación tuvo éxito. Devuelve False si no pudo crear la
      nueva Region().

      usando XRenderChangePicture().

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Dibuja una lista de glifos asociados con fuentes en coordenadas
        especificadas, pasados como un array de len estructuras
        XftGlyphFontSpec a través del parámetro glyphs. Todos los
        glifos se dibujan usando el color especificado en el parámetro
        color.

  





  

  
Para cada entrada en el array glyphs:






    
  
  • Si la fuente asociada utiliza la extensión X Render, entonces Xft
      utiliza XftGlyphFontSpecRender() para dibujar el glifo, usando una
      Picture obtenida al llamar XftDrawSrcPicture () con los
      parámetros draw y color.
    • 
  
  • De lo contrario, Xft proporciona una característica análoga usando
      Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Esto implica varios pasos:

  






    
  
  • Primero, Xft asegura que el array glyphs esté completo usando
      XftFontCheckGlyph() y cargando cualquier glifo faltante con
      XftFontLoadGlyphs().
    • 
  
  • Luego Xft examina los glifos para encontrar el valor Unicode máximo.
      Eso determina el tamaño de la codificación, es decir, el ancho.
    • 
  
  • Luego, para cada glifo, Xft verifica si su valor Unicode es manejado
      por la fuente correspondiente. Si no, el valor se establece en cero (0),
      para ignorarlo. Mientras hace esto, Xft también recuerda cuál fue la
      primera fuente utilizada y calcula la posición en la que se dibujará cada
      glifo.
    • 
  
  • Xft luego construye un array equivalente de glifos en el formato
      esperado por la biblioteca X Render.
    • 
  
  • Finalmente, XftGlyphFontSpecRender() utiliza la extensión X Render
      para dibujar los glifos, con la función apropiada XRenderCompositeText*()
      según el ancho, y descarta los datos temporales.
    • 




  

  
Los parámetros op, dst, src, srcx y srcy
      se utilizan como se describe en la documentación de la biblioteca X
      Render.

Xft - X FreeType library






NAME


Xft - X FreeType library






SYNOPSIS


#include <X11/Xft/Xft.h>






DESCRIPTION


The Xft library provides a way to use the FreeType 2 library
    to render fonts within an X display. It uses Fontconfig to locate and match
    fonts, and the X Render extension to draw glyphs.

void XftFontLoadGlyphs (

    

        
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


        
Using FT_Load_Glyph(), load nglyphs for the
            glyph indices (Unicode values) listed in the array glyphs from
            the given font pub.

    

    

    
Loading a glyph entails more than just reading data into memory.
        Xft uses the Fontconfig pattern associated with the display
        dpy (e.g., via XftDefaultSet()) to determine whether to use
        a bounding box, clip the glyphs into those bounds, scale the glyphs,
        compute font metrics, and add it to the X Render extension using
        XRenderAddGlyphs().

    
void XftFontUnloadGlyphs (

    

        
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


        
Discards data for up to nglyph glyphs whose glyph
            indices (Unicode values) are listed in the array glyphs for
            the given font pub. If the glyphs were added to the X Render
            extension, Xft removes those using XRenderFreeGlyphs().
            Xft keeps track of the amount of memory used for glyphs, and
            updates the usage associated with the display dpy.

    

    
FT_Face XftLockFace (

    

        
	XftFont	*pub);


        
If no FreeType 2 “face” (in-memory
            representation of a given typeface in a given style) has been created
            for the pub font, create one using FT_New_Face().
            Face-locks are a reference count used by Xft to ensure that
            only one face is created, and that it is retained until the font is
            no longer used.

    

    

    
Face-locking is used directly in XftCharIndex() and
        XftFontLoadGlyphs(), which in turn are used in many functions of
        Xft.

    

    
Face-locking was introduced in version 1 (October 2002). A few
        applications, such as Gdk/Gimp relied upon these functions. In version
        2.1.9 (June 2006), face-locking was retained as part of the public API
        when improved shared-library configurations provided for hiding private
        symbols.

    
void XftUnlockFace (

    

        
	XftFont	*pub);


        
Decrements the reference count for the FreeType 2
            “face” associated with the font.

    

    

    
FT_Face objects are deallocated using FT_Done_Face().
        Xft does this in XftFontInfoDestroy() and when cleaning up
        on failure in XftFontInfoCreate() and
        XftFontOpenPattern().








DEBUGGING


Xft reads the environment variable XFT_DEBUG and
    converts that to an integer. Each bit in the resulting value tells
    Xft to print debugging information to the standard output:



    
1

    
font-opening

    
2

    
additional font-matching and opening (verbose)

    
4

    
shows details about the XRenderPictFormat which will be used.

    
8

    
shows the string which XftDrawString8() will draw.

    
16

    
shows which font-ids are matched.

    
32

    
shows useful information about the glyphs which will be drawn

    
64

    
shows an ASCII-art representation of the glyphs.

    
128

    
shows details about the memory-cache management

    
256

    
shows details about managing glyph cached-memory

    
512

    
shows a report on memory-usage

    
1024

    
shows details on extended management of glyph cached-memory








COMPATIBILITY


As of version 2 (May 2002), Xft became relatively stable.
    It is expected to retain source and binary compatibility in future
    releases.


Xft provides a compatibility interface to its previous
    major version, Xft 1.x, described below.




Xft   1.x Header File


#include <X11/Xft/XftCompat.h>






Xft   1.x Data Types



    
XftPattern

    
holds a set of names with associated value lists; each name refers to a
        property of a font. XftPatterns are used as inputs to the matching
        code as well as holding information about specific fonts.

    
XftFontSet

    
contains a list of XftPatterns. Internally, Xft uses this
        data structure to hold sets of fonts. Externally, Xft returns the
        results of listing fonts in this format.

    
XftObjectSet

    
holds a set of names and is used to specify which fields from fonts are
        placed in the list of returned patterns when listing fonts.
