NOMBRE

Xft - Biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando la información proporcionada por la biblioteca Fontconfig,
  • Xft convierte los glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuentes convertidos utilizando la Extensión de Renderizado de X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo podrían usarse las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, anteponiendo a todos los nombres la cadena "Xft"

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - C Language Interface.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, es un ID de recurso de X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener más detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, anteponiendo a todos los nombres "Fc", que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, anteponiendo a todos los nombres "FT_", que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFont se rellenan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo() o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar memoria para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder a un drawable de X core o a un drawable de la Extensión de Renderizado de X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender() y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado de X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado de X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy() y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar memoria para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual de X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color del servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado para un XftColor.

Una vez que un XftColor ha sido inicializado, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec() y XftDrawRect() pueden ser utilizados para dibujar varios objetos utilizando.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable de X utilizando el protocolo principal o la extensión de renderizado de X.

Los objetos XftDraw se crean con cualquiera de XftDrawCreate() (que asocia un XftDraw con un drawable de X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable de X asociado con un XftDraw puede ser cambiado con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador no necesita asignar ni liberar memoria para ellos de forma ordinaria.

Las propiedades Display, Drawable, Colormap y Visual de un XftDraw pueden ser consultadas con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

El Picture de la Extensión de Renderizado de X asociado con un XftDraw se devuelve por XftDrawPicture(), y XftDrawSrcPicture(). Es utilizado por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que usa Xft no inicializa explícitamente la biblioteca. Eso se hace usualmente como un efecto secundario al abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft encontró que la pantalla soporta la extensión de Renderizado de X, y si es capaz de encontrar un XRenderPictFormat adecuado (el tipo de dato de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft rellena las propiedades faltantes en el pattern dado utilizando propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar antialiasing (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para engrosar una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al rellenar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al rellenar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al rellenar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al rellenar propiedades para abrir una fuente (predeterminado: calculado llamando XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión de Renderizado de X (predeterminado: resultado de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Inicializa la biblioteca Fontconfig (llamando FcInit()).

El parámetro config no se utiliza.
Xft no desinicializa la biblioteca Fontconfig cuando termina.
FcBool XftInitFtLibrary (void);

    
Inicializa la biblioteca FreeType (llamando
        FT_Init_FreeType() para crear un objeto de biblioteca) si aún no se ha inicializado. Esto es necesario antes de usar la biblioteca FreeType para leer datos de fuentes de un archivo.

Abrir y Emparejar Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triplas de elementos de patrón del tipo
        campo, tipo, valor (terminada con NULL), empareja ese patrón con las fuentes disponibles, y abre la fuente emparejada, dimensionándola correctamente para la pantalla número screen en la pantalla dpy. Devuelve la fuente emparejada, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño del punto se convierte automáticamente al tamaño de píxel correcto basándose en la resolución del monitor.

XftFont, XftFontOpen, XftFontOpenName, XftFontOpenXlfd, XftFontMatch, XftXlfdParse, XftDrawString, XftTextExtents, XftColorAllocName, XftColorAllocValue, XftColorFree, XftDrawCreate, XftDrawCreateBitmap - font and drawing library






DESCRIPTION


The Xft library provides functions for font selection and drawing
    text using fonts selected from Fontconfig.




Font Selection


The following functions are used to open fonts:



  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName opens a font corresponding to the
        Fontconfig pattern string name. It uses FcNameParse()
        to parse the string, and FcFontMatch() to find the matching
        font. The returned XftFont structure contains information about
        the matched font, including its metrics and the glyph data.

  

  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);


    
XftFontOpen is similar to XftFontOpenName, except
        that it takes a pre-parsed Fontconfig pattern (created with
        FcPatternCreate() or obtained from other Fontconfig
        functions).

  

  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*xlfd);


    
XftFontOpenXlfd behaves as XftFontOpen does,
        except that it takes a string containing an X Logical Font Description
        (XLFD), and uses the XftXlfdParse() function.

  

  
FcPattern *XftFontMatch (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst FcPattern	*pattern,
	FcResult	*result);


    
Also used internally by the XftFontOpen* functions,
        XftFontMatch can also be used directly to determine the
        Fontconfig font pattern resulting from an Xft font open
        request.

  

  
FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse parses the xlfd_orig parameter
        according to the X Logical Font Description Conventions document,
        but ignores some of the fields: setwidth_name,
        add_style_name, spacing, and average_width.

      XFT_XLFD to the xlfd_orig value, and maps the collected
      information to Fontconfig properties. Empty or “*” fields
      are ignored:

from foundry.

  
FC_FAMILY

  
from family.

  
FC_WEIGHT

  
weight_name, defaulting to FC_WEIGHT_MEDIUM.

from slant, defaulting to FC_SLANT_ROMAN.

from point_size.

  
FC_PIXEL_SIZE

  
from pixel_size. If point_size was set, as well as

Determining   Text Extents


Xft provides several functions for determining the required
    height and width for displaying a text-string. After accounting for the
    offset, in cases where the string will be shifted up, down, left or
    right, these numbers are referred to as text extents.

Managing   XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Use XAllocNamedColor() to look up the named color
        name for the screen associated with the colormap cmap.

  






    
  
  • If XAllocNamedColor() returns nonzero, XftColorAllocName()
      fills in the resulting XftColor pixel field with the closest color
      supported by the screen, as well as the exact red, green and blue fields
      from the database, and returns True.
    • 
  
  • If XAllocNamedColor() returns zero, XftColorAllocName()
      returns False, and does not update the XftColor referenced by
      result.
    • 






  

  
The visual parameter is unused.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Allocate a color value:

  






    
  
  • If the visual class is TrueColor, XftColorAllocValue() sets
      the pixel field in the XftColor referenced by result
      using the red, green and blue fields from the color parameter.
    • 
  
  • If the visual class is not TrueColor, XftColorAllocValue()
      calls XAllocColor() to allocate an entry in the colormap
      cmap. which returns the pixel value of the color closest to the
      specified RGB elements supported by the hardware.
    • 




  

  
If XAllocColor() succeeds XftColorAllocValue() stores that
      pixel value in the XRenderColor referenced by result and
      returns True.

  

  
If XAllocColor() fails, XftColorAllocValue() returns False
      and does not modify the result.







  
void XftColorFree (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	XftColor	*color);


    
If the visual class is not TrueColor, Xft calls
        XFreeColors() to free the entry from the colormap cmap
        whose pixel value in the color parameter was allocated by
        XftColorAllocName().

DESCRIPCIÓN
       Un objeto XftDraw es una estructura opaca que maneja la obtención de
       glifos para un drawable X subyacente. Se puede obtener un objeto XftDraw
       de un drawable X, ya sea un drawable normal o un pixmap. Todas las
       funciones que dibujan texto requieren un objeto XftDraw.

       Los siguientes son los constructores para los objetos XftDraw:

       XftDrawCreate() crea un objeto XftDraw para el drawable X dado. El
       visual y el colormap se toman del vis y cmap dados. Si se pasan
       NULL para alguno de ellos, se utilizará el visual predeterminado y el
       colormap del drawable X.

       XftDrawCreateBitmap() se comporta como XftDrawCreate(), excepto que
       utiliza un pixmap X de profundidad de color 1 en lugar de un drawable X.

       XftDrawCreateAlpha() se comporta como XftDrawCreate(), excepto que
       utiliza un pixmap X de profundidad de color depth en lugar de un
       drawable X.

       Las siguientes funciones devuelven información sobre el objeto XftDraw:

       XftDrawDisplay() devuelve un puntero a la pantalla asociada con el
       objeto de dibujo Xft draw.

       XftDrawDrawable() devuelve el drawable X asociado con el objeto de
       dibujo Xft draw.

       XftDrawColormap() devuelve el colormap asociado con el objeto de
       dibujo Xft draw.

       XftDrawVisual() devuelve un puntero al visual asociado con el objeto de
       dibujo Xft draw.

       XftDrawPicture() devuelve la imagen asociada con el objeto de dibujo
       Xft draw. Si el servidor X no soporta la extensión X Rendering, se
       devuelve 0.

       XftDrawSrcPicture() devuelve un objeto de imagen X Render, que se
       utiliza para renderizar glifos, p. ej., con
       XftGlyphRender(), XftGlyphSpecRender(), o
       XftGlyphFontSpecRender(), por
       XftDrawGlyphs(), XftDrawGlyphSpec(),
       XftDrawGlyphFontSpec(), respectivamente. Si el servidor X no soporta
       la extensión X Render, esas funciones utilizan
       XftGlyphCore(), XftGlyphSpecCore(), o
       XftGlyphFontSpecCore().

       XftDrawChange() cambia la asociación del drawable X del objeto Xft
       existente draw de su valor actual a drawable.

       XftDrawDestroy() destruye draw (creado por una de las funciones
       XftDrawCreate*()) y libera la memoria que fue asignada para él.

       XftDrawSetClip() configura el recorte para el parámetro XftDraw
       dado draw comenzando con una Region:
              - Si el parámetro Region r no es nulo, Xft crea una
              nueva Region (para copiar el parámetro).
              - Xft destruye cualquier región de recorte existente.
              - Xft establece el tipo de recorte (clip_type) para el
              parámetro draw a XftClipTypeRegion si el parámetro r
              no era nulo. De lo contrario, establece el tipo de recorte a
              XftClipTypeNone.
              - Finalmente, Xft actualiza el recorte para los objetos
              existentes, actualiza la máscara de recorte (clip_mask) para su
              objeto Picture de X Render y establece la máscara de recorte
              en el contexto gráfico (GC) asociado con el parámetro
              XftDraw.
       XftDrawSetClip() devuelve True si no fue necesario ningún cambio, o
       si la operación tuvo éxito. Devuelve False si no pudo crear la nueva
       Region().

       XftDrawSetClipRectangles() al igual que XftDrawSetClip(),
       configura el recorte para el parámetro XftDraw dado draw, pero
       utiliza un conjunto de n rectángulos (el parámetro rects) que
       podrían usarse para construir una Region.

       Xft establece el tipo de recorte (clip_type) para draw a
       XftClipTypeRectangles y utiliza XSetClipRectangles() para el recorte
       central (X11) y
       XRenderSetPictureClipRectangles() para el recorte de X Render.

       XftDrawSetSubwindowMode() establece el modo de subventana para el
       parámetro XftDraw dado draw. El modo puede ser
       ClipByChildren (el predeterminado) o
       IncludeInferiors:
              - Para ClipByChildren, tanto la ventana de origen como la de
              destino se recortan además por todos los hijos visibles de
              InputOutput.
              - Para IncludeInferiors, ni la ventana de origen ni la de
              destino se recortan por los inferiores. Esto dará como resultado
              la inclusión de los contenidos de la subventana en el origen y el
              dibujo a través de los límites de la subventana del destino.
       Además del modo de subventana mantenido por Xft, actualiza el modo
       de subventana para cualquier contexto gráfico (GC) asociado usando
       XSetSubwindowMode() así como para un Picture de X Render usando
       XRenderChangePicture().

Dibujo de Cadenas
       XftDrawString8() dibuja no más de len glifos de string en el
       drawable Xft d usando font en color en la posición
       x, y.

Dibujo de Otras Cosas
       XftDrawRect() dibuja un rectángulo sólido del color, width, y
       height especificados en la posición x, y en el drawable
       Xft d.

       XftCharFontSpecRender() convierte el parámetro chars de
       XftCharFontSpec a XftGlyphFontSpec, pasando el array convertido
       junto con los otros parámetros sin cambios a
       XftGlyphFontSpecRender() para renderizar los datos.

       XftDrawGlyphFontSpec() dibuja una lista de glifos asociados con
       fuentes en coordenadas especificadas, pasados como un array de
       estructuras XftGlyphFontSpec de longitud len a través del
       parámetro glyphs. Todos los glifos se dibujan usando el color
       especificado en el parámetro color.
              - Para cada entrada en el array glyphs:
                     - Si la fuente asociada utiliza la extensión X Render,
                     entonces Xft utiliza XftGlyphFontSpecRender() para
                     dibujar el glifo, utilizando una Picture obtenida al
                     llamar a XftDrawSrcPicture() con los parámetros
                     draw y color.
                     - De lo contrario, Xft proporciona una característica
                     análoga utilizando Xlib.

       XftGlyphFontSpecRender() implica varios pasos:
              - Primero, Xft asegura que el array glyphs esté completo
              usando XftFontCheckGlyph() y cargando cualquier glifo faltante
              con XftFontLoadGlyphs().
              - Luego Xft examina los glifos para encontrar el valor Unicode
              máximo. Eso determina el tamaño de la codificación, es decir, el
              width.
              - Luego, para cada glifo, Xft verifica si su valor Unicode es
              manejado por la fuente correspondiente. Si no lo es, el valor se
              establece en cero (0), para ignorarlo. Mientras hace esto,
              Xft también recuerda cuál fue la primera fuente utilizada y
              calcula la posición en la que se dibujará cada glifo.
              - Xft luego construye un array equivalente de glifos en el
              formato esperado por la biblioteca X Render.
              - Finalmente, XftGlyphFontSpecRender() utiliza la extensión
              X Render para dibujar los glifos, con la función apropiada
              XRenderCompositeText*() según el width, y descarta los datos
              temporales.
              Los parámetros op, dst, src, srcx, y srcy se
              utilizan como se describe en la documentación de la biblioteca X
              Render.

Manipulación de patrones
       XftListFonts() utiliza FcPatternVapBuild() y
       FcObjectSetVapBuild() para procesar la lista de parámetros de
       longitud variable, y FcFontList() para obtener una lista de patrones
       de Fontconfig coincidentes, que devuelve al llamador. El llamador puede
       descartar el valor de retorno usando FcPatternDestroy().

       XftNameParse() analiza una cadena de nombre de fuente y devuelve un
       patrón de Fontconfig que representa esa fuente.

void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Usando FT_Load_Glyph(), carga *nglyphs* para los
        índices de glifos (valores Unicode) listados en el array *glyphs* de la
        fuente dada *pub*.

  





  

  
Cargar un glifo implica más que solo leer datos en memoria.
      Xft utiliza el patrón de Fontconfig asociado con la pantalla
      *dpy* (por ejemplo, a través de XftDefaultSet()) para determinar
      si usar un cuadro delimitador, recortar los glifos dentro de esos
      límites, escalar los glifos, calcular métricas de fuente y añadirlo a la
      extensión X Render usando XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Descarta datos para hasta *nglyph* glifos cuyos índices de
        glifos (valores Unicode) están listados en el array *glyphs* para la
        fuente dada *pub*. Si los glifos fueron añadidos a la extensión X
        Render, Xft los elimina usando XRenderFreeGlyphs().
        Xft hace un seguimiento de la cantidad de memoria utilizada para
        glifos y actualiza el uso asociado con la pantalla *dpy*.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si no se ha creado ninguna cara FreeType 2 ("face") (representación
        en memoria de un tipo de letra dado en un estilo dado) para la fuente
        *pub*, créela usando FT_New_Face(). Los bloqueos de cara son un
        contador de referencias utilizado por Xft para asegurar que solo
        se crea una cara y que se retiene hasta que la fuente ya no se use.

  





  

  
El bloqueo de cara se utiliza directamente en XftCharIndex() y
      XftFontLoadGlyphs(), que a su vez se utilizan en muchas funciones
      de Xft.

  

  
El bloqueo de cara se introdujo en la versión 1 (octubre de 2002). Algunas
      aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la versión
      2.1.9 (junio de 2006), se mantuvo el bloqueo de cara como parte de la API
      pública cuando las configuraciones mejoradas de bibliotecas compartidas
      proporcionaron la ocultación de símbolos privados.

DEPURACIÓN


Xft lee la variable de entorno XFT_DEBUG y la
    convierte a un entero. Cada bit en el valor resultante indica a Xft
    que imprima información de depuración en la salida estándar:



  
1

  
apertura de fuente

  
2

  
coincidencia y apertura adicional de fuentes (verboso)

  
4

  
muestra detalles sobre XRenderPictFormat que se utilizará.

  
8

  
muestra la cadena que XftDrawString8() dibujará.

  
16

  
muestra qué ids de fuente coinciden.

  
32

  
muestra información útil sobre los glifos que se dibujarán

  
64

  
muestra una representación en arte ASCII de los glifos.

  
128

  
muestra detalles sobre la gestión de la caché de memoria

  
256

  
muestra detalles sobre la gestión de la memoria caché de glifos

  
512

  
muestra un informe sobre el uso de memoria

  
1024

  
muestra detalles sobre la gestión extendida de la memoria caché de glifos








COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió
    relativamente estable. Se espera que mantenga la compatibilidad de origen y
    binaria en futuras versiones.


Xft proporciona una interfaz de compatibilidad con su
    versión principal anterior, Xft 1.x, descrita a continuación.




Archivo de encabezado Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de datos Xft 1.x



  
XftPattern

  
contiene un conjunto de nombres con listas de valores asociados; cada nombre
      se refiere a una propiedad de una fuente. Los XftPattern se usan
      como entradas para el código de coincidencia, así como para mantener
      información sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPattern. Internamente, Xft utiliza
      esta estructura de datos para mantener conjuntos de fuentes. Externamente,
      Xft devuelve los resultados de listar fuentes en este formato.

  
XftObjectSet

  
contiene un conjunto de nombres y se utiliza para especificar qué campos
      de las fuentes se colocan en la lista de patrones devueltos al listar
      fuentes.
