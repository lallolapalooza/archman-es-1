NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando la información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas roza la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo podrían usarse las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("La versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz del Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada con una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como "drawables". Sin embargo, una ventana InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa mediante la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica el alcance de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc” que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_” que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 usa FT_UInt (un entero sin signo) para representar *glifos*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFonts se poblan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). Se utiliza XftFontCopy() para duplicar XftFonts, y se utiliza XftFontClose() para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto en un objeto XftDraw, que puede corresponder a un drawable X principal o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender() y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() proporcionan un medio de renderizado de fuentes independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy() y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color del servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado para un XftColor.

Una vez que se ha inicializado un XftColor, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec() y XftDrawRect() pueden usarse para dibujar varios objetos utilizándolo.

ESTRUCTURAS

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable de X utilizando el protocolo principal o la extensión de Renderizado de X.

Los objetos XftDraw se crean con cualquiera de las funciones XftDrawCreate() (que asocia un XftDraw con un drawable de X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable de X asociado con un XftDraw se puede cambiar con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Las propiedades Display, Drawable, Colormap, y Visual de X de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

La extensión de Renderizado de X Picture asociada con un XftDraw se devuelve mediante XftDrawPicture(), y XftDrawSrcPicture(). Es utilizada por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa la biblioteca explícitamente. Eso generalmente se hace como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación llamante puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft descubrió que la pantalla soporta la extensión de Renderizado de X, y si puede encontrar un XRenderPictFormat adecuado (el tipo de datos de Renderizado de X que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft rellena las propiedades faltantes en el pattern proporcionado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se estableció en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():

Verdadero si FreeType debe usar antialiasing (predeterminado: Falso). (predeterminado: Verdadero).

Verdadero si FreeType debe usar autohinting (predeterminado: Falso).

Verdadero si se debe usar hinting al rellenar propiedades para abrir una fuente (predeterminado: Verdadero).

XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de tríos de elementos de patrón
        de la forma campo, tipo, valor (terminada con un
        NULL), empareja ese patrón con las fuentes disponibles, y abre la fuente
        emparejada, dimensionándola correctamente para el número de pantalla
        screen en la pantalla dpy. Devuelve la fuente emparejada, o
        NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Esto abre la fuente “charter” a 12 puntos. El tamaño del punto se
      convierte automáticamente al tamaño de píxel correcto según la resolución
      del monitor.

DESCRIPTION


The Xft library is a library for rendering fonts using the
    FreeType library on the X Window System. It provides an interface for
    querying font properties, matching fonts, rendering text, and managing colors
    and drawing surfaces.

Managing   XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Use XAllocNamedColor() to look up the named color
        name for the screen associated with the colormap cmap.

  






    
  
  • If XAllocNamedColor() returns nonzero, XftColorAllocName()
      fills in the resulting XftColor pixel field with the closest color
      supported by the screen, as well as the exact red, green and blue fields
      from the database, and returns True.
    • 
  
  • If XAllocNamedColor() returns zero, XftColorAllocName()
      returns False, and does not update the XftColor referenced by
      result.
    • 






  

  
The visual parameter is unused.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Allocate a color value:

  






    
  
  • If the visual class is TrueColor, XftColorAllocValue() sets
      the pixel field in the XftColor referenced by result
      using the red, green and blue fields from the color parameter.
    • 
  
  • If the visual class is not TrueColor, XftColorAllocValue()
      calls XAllocColor() to allocate an entry in the colormap
      cmap. which returns the pixel value of the color closest to the
      specified RGB elements supported by the hardware.
    • 




  

  
If XAllocColor() succeeds XftColorAllocValue() stores that
      pixel value in the XRenderColor referenced by result and
      returns True.

  

  
If XAllocColor() fails, XftColorAllocValue() returns False
      and does not modify the result.

DESCRIPTION
       The Xft library provides a drawing interface to Xlib. This interface
       supports glyphs and other drawing primitives using the X Rendering
       Extension, as well as core Xlib drawing.

       XftDrawCreate() creates an Xft draw object associated with the specified
       X drawable drawable, colormap and visual.

       XftDrawCreateBitmap() behaves as XftDrawCreate(), except that it uses an
       X pixmap of color depth 1 instead of an X drawable.

       XftDrawCreateAlpha() behaves as XftDrawCreate(), except that it uses an X
       pixmap of color depth depth instead of an X drawable.

       XftDrawChange() changes the X drawable association of the existing Xft
       draw object draw from its current value to drawable.

       XftDrawDisplay() returns a pointer to the display associated with the Xft
       draw object draw.

       XftDrawDrawable() returns the X drawable associated with the Xft draw
       object draw.

       XftDrawColormap() returns the colormap associated with the Xft draw
       object draw.

       XftDrawVisual() returns a pointer to the visual associated with the Xft
       draw object draw.

       XftDrawPicture() returns the picture associated with the Xft draw object
       draw.
           If the X server does not support the X Rendering Extension, 0 is
           returned.

       XftDrawSrcPicture() Return an X Render Picture object, which is used for
       rendering glyphs, e.g., with XftGlyphRender(), XftGlyphSpecRender(), or
       XftGlyphFontSpecRender(), by XftDrawGlyphs(), XftDrawGlyphSpec(),
       XftDrawGlyphFontSpec(), respectively.
           If the X server does not support the X Render extension, those
           functions use XftGlyphCore(), XftGlyphSpecCore(), or
           XftGlyphFontSpecCore().

       XftDrawDestroy() destroys draw (created by one of the
       XftDrawCreate*() functions) and frees the memory that was allocated for
       it.

       XftDrawSetClip() Set up clipping for the given XftDraw parameter
       draw starting with a Region:
           * If the Region parameter r is not null, Xft creates a new
             Region (to copy the parameter),
           * Xft destroys any existing clipping region.
           * Xft sets the clip_type for the draw parameter to
             XftClipTypeRegion if the r parameter was not null. Otherwise
             it sets the clip_type to XftClipTypeNone.
           * Finally, Xft updates clipping for existing objects, updates the
             clip_mask for its X Render Picture object and sets the
             clipping-mask in the graphic context (GC) associated with the
             XftDraw parameter.
           XftDrawSetClip() returns True if no change was necessary, or if the
           operation succeeded. It returns False if it was unable to create the
           new Region().

       XftDrawSetClipRectangles() Like XftDrawSetClip(), XftDrawSetClipRectangles()
       sets up clipping for the given XftDraw parameter draw but uses a
       set of n rectangles (the rects parameter) which could be used to
       construct a Region .
           Xft sets the clip_type for draw to XftClipTypeRectangles and
           uses XSetClipRectangles() for core (X11) clipping and
           XRenderSetPictureClipRectangles() for X Render clipping.

       XftDrawSetSubwindowMode() Sets the subwindow-mode for the given XftDraw
       parameter draw. The mode can be either ClipByChildren (the default),
       or IncludeInferiors:
           * For ClipByChildren, both source and destination windows are
             additionally clipped by all viewable InputOutput children.
           * For IncludeInferiors, neither source nor destination window is
             clipped by inferiors. This will result in including subwindow
             contents in the source and drawing through subwindow boundaries of
             the destination.
           In addition to the subwindow-mode maintained by Xft, it updates the
           subwindow mode for any associated graphics context GC using
           XSetSubwindowMode() as well as for an X Render Picture using
           XRenderChangePicture().

       XftCharFontSpecRender(Display *dpy, int op, Picture src, Picture dst,
            int srcx, int srcy, _Xconst XftCharFontSpec *chars, int len);
       XftCharFontSpecRender() converts the chars parameter from
       XftCharFontSpec to XftGlyphFontSpec, passing the converted array along
       with the other parameters unchanged to XftGlyphFontSpecRender() to render

       void
       XftDrawGlyphFontSpec(XftDraw *draw, _Xconst XftColor *color,
            _Xconst XftGlyphFontSpec *glyphs, int len);
       Draw a list of glyphs associated with fonts at specified coordinates,
       passed as an array of len XftGlyphFontSpec structures via the
       parameter glyphs. All of the glyphs are drawn using the color
       specified in the color parameter.
           For each entry in the glyphs array:
               * If the associated font uses the X Render extension, then Xft
                 uses XftGlyphFontSpecRender() to draw the glyph, using a
                 Picture obtained from calling XftDrawSrcPicture() with the
                 draw and color parameters.
               * Otherwise, Xft provides an analogous feature using Xlib.

       void
       XftGlyphFontSpecRender(Display *dpy, int op, Picture src, Picture dst,
            int srcx, int srcy, _Xconst XftGlyphFontSpec *glyphs, int nglyphs);
       This involves several steps:
           * First, Xft ensures that the glyphs array is complete using
             XftFontCheckGlyph() and loading any missing glyphs with
             XftFontLoadGlyphs().
           * Then Xft examines the glyphs to find the maximum Unicode value.
             That determines the encoding size, i.e., the width.
           * Then, for each glyph, Xft checks if its Unicode value is handled by
             the corresponding font. If not, the value is set to zero (0), to
             ignore it. While doing this, Xft also remembers which was the first
             font used, and computes the position at which each glyph will be
             drawn.
           * Xft then constructs an equivalent array of glyphs in the format
             expected by the X Render library.
           * Finally, XftGlyphFontSpecRender() uses the X Render extension to
             draw the glyphs, with the appropriate XRenderCompositeText*()
             function according to the width, and discards temporary data.
           The op, dst, src, srcx, and srcy parameters are used as
           described in the documentation for the X Render library.
