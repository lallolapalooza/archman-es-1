XFillRectangles(3)

Paquete: libx11

Licencias: MIT AND X11

XFillRectangle(3) FUNCIONES DE XLIB XFillRectangle(3)

NOMBRE

XFillRectangle, XFillRectangles, XFillPolygon, XFillArc, XFillArcs - rellenar rectángulos, polígonos o arcos

SINTAXIS

int XFillRectangle(Display *display, Drawable d, GC gc, int x, int y, unsigned int width, unsigned int height);

int XFillRectangles(Display *display, Drawable d, GC gc, XRectangle *rectangles, int nrectangles);

int XFillPolygon(Display *display, Drawable d, GC gc, XPoint *points, int npoints, int shape, int mode);

int XFillArc(Display *display, Drawable d, GC gc, int x, int y, unsigned int width, unsigned int height, int angle1, int angle2);

int XFillArcs(Display *display, Drawable d, GC gc, XArc *arcs, int narcs);

ARGUMENTOS

angle1
Especifica el inicio del arco relativo a la posición de las tres en punto desde el centro, en unidades de grados * 64.
angle2
Especifica la trayectoria y la extensión del arco relativas al inicio del arco, en unidades de grados * 64.
arcs
Especifica una matriz de arcos.
d
Especifica el drawable.
display
Especifica la conexión con el servidor X.
gc
Especifica el GC.
mode
Especifica el modo de coordenadas. Puedes pasar CoordModeOrigin o CoordModePrevious.
narcs
Especifica el número de arcos en la matriz.
npoints
Especifica el número de puntos en la matriz.
nrectangles
Especifica el número de rectángulos en la matriz.
points
Especifica una matriz de puntos.
rectangles
Especifica una matriz de rectángulos.
shape
Especifica una forma que ayuda al servidor a mejorar el rendimiento. Puedes pasar Complex, Convex o Nonconvex.
width

height
Especifican el ancho y la altura, que son las dimensiones del rectángulo a rellenar o los ejes mayor y menor del arco.
x

y
Especifican las coordenadas x e y, que son relativas al origen del drawable y especifican la esquina superior izquierda del rectángulo.

DESCRIPCIÓN

Las funciones XFillRectangle y XFillRectangles rellenan el rectángulo o los rectángulos especificados como si se hubiera especificado una solicitud de protocolo FillPolygon de cuatro puntos para cada rectángulo:

[x,y] [x+width,y] [x+width,y+height] [x,y+height]

Cada función utiliza las coordenadas x e y, las dimensiones de ancho y alto, y el GC que especifiques.

XFillRectangles rellena los rectángulos en el orden listado en la matriz. Para cualquier rectángulo dado, XFillRectangle y XFillRectangles no dibujan un píxel más de una vez. Si los rectángulos se cruzan, los píxeles que se cruzan se dibujan varias veces.

Ambas funciones utilizan estos componentes del GC: función, máscara de plano, estilo de relleno, modo de subventana, origen x del recorte, origen y del recorte y máscara de recorte. También utilizan estos componentes dependientes del modo del GC: primer plano, fondo, mosaico, punto, origen x del mosaico/punto y origen y del mosaico/punto.

XFillRectangle y XFillRectangles pueden generar errores BadDrawable, BadGC y BadMatch.

XFillPolygon rellena la región cerrada por la trayectoria especificada. La trayectoria se cierra automáticamente si el último punto de la lista no coincide con el primer punto. XFillPolygon no dibuja un píxel de la región más de una vez. CoordModeOrigin trata todas las coordenadas como relativas al origen, y CoordModePrevious trata todas las coordenadas después de la primera como relativas al punto anterior.

Dependiendo de la forma especificada, ocurre lo siguiente:

  • Si la forma es Complex, la trayectoria puede auto-intersecarse. Ten en cuenta que los puntos coincidentes contiguos en la trayectoria no se tratan como auto-intersección.
  • Si la forma es Convex, para cada par de puntos dentro del polígono, el segmento de línea que los une no interseca la trayectoria. Si el cliente lo sabe, especificar Convex puede mejorar el rendimiento. Si especificas Convex para una trayectoria que no es convexa, los resultados gráficos no están definidos.
  • Si la forma es Nonconvex, la trayectoria no se auto-interseca, pero la forma no es totalmente convexa. Si el cliente lo sabe, especificar Nonconvex en lugar de Complex puede mejorar el rendimiento. Si especificas Nonconvex para una trayectoria que se auto-interseca, los resultados gráficos no están definidos.

La regla de relleno del GC controla el comportamiento de relleno de los polígonos que se auto-intersectan.

Esta función utiliza estos componentes del GC: función, máscara de plano, estilo de relleno, regla de relleno, modo de subventana, origen x del recorte, origen y del recorte y máscara de recorte. También utiliza estos componentes dependientes del modo del GC: primer plano, fondo, mosaico, punto, origen x del mosaico/punto y origen y del mosaico/punto.

XFillPolygon puede generar errores BadDrawable, BadGC, BadMatch y BadValue.

Para cada arco, XFillArc o XFillArcs rellena la región cerrada por la trayectoria infinitamente delgada descrita por el arco especificado y, dependiendo del modo de arco especificado en el GC, uno o dos segmentos de línea. Para ArcChord, se utiliza el único segmento de línea que une los extremos del arco. Para ArcPieSlice, se utilizan los dos segmentos de línea que unen los extremos del arco con el punto central. XFillArcs rellena los arcos en el orden listado en la matriz. Para cualquier arco dado, XFillArc y XFillArcs no dibujan un píxel más de una vez. Si las regiones se cruzan, los píxeles que se cruzan se dibujan varias veces.

Ambas funciones utilizan estos componentes del GC: función, máscara de plano, estilo de relleno, modo de arco, modo de subventana, origen x del recorte, origen y del recorte y máscara de recorte. También utilizan estos componentes dependientes del modo del GC: primer plano, fondo, mosaico, punto, origen x del mosaico/punto y origen y del mosaico/punto.

XFillArc y XFillArcs pueden generar errores BadDrawable, BadGC y BadMatch.

DIAGNÓSTICOS

BadDrawable
Un valor para un argumento Drawable no nombra una Ventana o Pixmap definida.
BadGC
Un valor para un argumento GContext no nombra un GContext definido.
BadMatch
Se utiliza una ventana InputOnly como Drawable.
BadMatch
Algún argumento o par de argumentos tiene el tipo y rango correctos pero falla al coincidir de alguna otra manera requerida por la solicitud.
BadValue
Algún valor numérico cae fuera del rango de valores aceptados por la solicitud. A menos que se especifique un rango específico para un argumento, se acepta el rango completo definido por el tipo del argumento. Cualquier argumento definido como un conjunto de alternativas puede generar este error.
