NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca simple que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas araña la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión secundaria de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("La versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

De Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz de Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada con una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

De XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

De Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc” que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

De FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_” que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFont se completan con cualquiera de XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se usa para duplicar XftFonts, y XftFontClose() se usa para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar ni liberar memoria para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto en un objeto XftDraw, que puede corresponder a un drawable X principal o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados internamente y liberados por Xft; el programador normalmente no necesita asignar ni liberar memoria para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {

DESCRIPTION

The Xft library (X FreeType library) is an interface to the FreeType font rasterizer library, which allows applications to use TrueType and OpenType fonts in X Window System applications. Xft provides rendering and font management services.

The primary abstractions are:

XftDraw
An object representing a destination for drawing operations, typically an X drawable (window or pixmap) or an X Render extension picture.
XftFont
An object representing a loaded font, capable of providing font metrics and glyph data.

Xft utilizes the Fontconfig library for font matching and management.

XftDraw

is an opaque object which holds information used to render to an X drawable using either the core protocol or the X Rendering extension.

XftDraw objects are created with any of XftDrawCreate() (which associates an XftDraw with an existing X drawable), XftDrawCreateBitmap(), or XftDrawCreateAlpha(), and destroyed with XftDrawDestroy(). The X drawable associated with an XftDraw can be changed with XftDrawChange(). XftDraw objects are internally allocated and freed by Xft; the programmer does not ordinarily need to allocate or free storage for them.

The X Display, Drawable, Colormap, and Visual properties of an XftDraw can be queried with XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), and XftDrawVisual(), respectively.

Several functions use XftDraw objects: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), and the XftDrawString*() family.

The X Rendering Extension Picture associated with an XftDraw is returned by XftDrawPicture(), and XftDrawSrcPicture(). It is used by XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), and the XftTextRender*() family.

FUNCTIONS

Initialization

A typical application using Xft does not explicitly initialize the library. That is usually done as a side-effect of opening a font.

When Xft initializes, it collects information about the display, and stores some of that information in a Fontconfig pattern (essentially a collection of properties with typed values). The calling application can modify that pattern to change the library's behavior.

Not all of the collected information is stored in a pattern. The remainder is stored in internal data structures. Xft makes some of that available to the application via functions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtain information about the display dpy if not done already, and return true if Xft found that the display supports the X Render extension, and if it is able to find a suitable XRenderPictFormat (X Render's datatype which is analogous to Xlib's Visual) on the display.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtain information about the display dpy if not done already, and set the Fontconfig pattern holding default properties which Xft will use for this display.

Xft uses those properties initially to obtain these limits:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). This is the maximum amount of glyph memory for all fonts used by Xft (default: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). This is the maximum number of unreferenced fonts (default: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). When true, Xft tracks usage of glyph memory to improve performance when deciding which to unload when the maximum amount of glyph memory is reached (default: false).
Xft also uses these default properties in XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft fills in missing properties in the given pattern using default properties for the specified display dpy, e.g., as set in XftDefaultSet().

Typical Xft applications use this function to help Fontconfig choose a suitable font. These properties are substituted before calling FcDefaultSubstitute():
FC_ANTIALIAS
True if FreeType should use antialiasing (default: False). (default: True).
FC_AUTOHINT
True if FreeType should use autohinting (default: False).
FC_DPI
Dots/inch used for resolution (default: computed from the display height).
FC_EMBOLDEN
True if FT_GlyphSlot_Embolden() should be used to embolden a font (default: False).
FC_HINTING
True if hinting should be used when filling in properties to open a font (default: True).
FC_HINT_STYLE
Hinting style used when filling in properties to open a font (default: FC_HINT_FULL).
FC_LCD_FILTER
Parameter passed to FT_Library_SetLcdFilter() when loading glyphs (default: FC_LCD_DEFAULT).
FC_MINSPACE
Minimum space value used when filling in properties to open a font (default: False).
FC_RGBA
RGBA value used when filling in properties to open a font (default: computed by calling XRenderQuerySubpixelOrder()).
FC_SCALE
Scale used in Fontconfig (default: 1.0).
XFT_MAX_GLYPH_MEMORY
Maximum memory for one font (default: 1024*1024).
XFT_RENDER
True if the display supports X Render extension (default: result from XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initializes the Fontconfig library (calling FcInit()).

The config parameter is unused.
Xft does not deinitialize the Fontconfig library when it is done.

Initializes the FreeType library (calling
        FT_Init_FreeType() to create a library object) if it has not

Opening   and Matching Fonts



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen takes a list of pattern element triples of
        the form field, type, value (terminated with a
        NULL), matches that pattern against the available fonts, and opens the
        matching font, sizing it correctly for screen number screen on
        display dpy. Return the matched font, or NULL if no match is
        found.

  




Example:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
This opens the “charter” font at 12 points. The point size
      is automatically converted to the correct pixel size based on the
      resolution of the monitor.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName behaves as






XftFontOpen except that the font name is specified by
    name instead of a pattern.


The string name is parsed into a font pattern and passed
    to XftFontOpenPattern().



  
XftFont *XftFontOpenPattern (

  

    
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);


    
Matches the given pattern against the available fonts,
        and opens the matching font, sizing it correctly for screen number
        screen on display dpy. Return the matched font, or NULL
        if no match is found.

  




This is the primitive function used by both
    XftFontOpen() and XftFontOpenName().



  
void XftFontClose (

  

    
	XftFont	*font);


    
Closes the specified font and frees all associated
        storage.

  




Note that XftFont objects are reference counted. Closing
    a font decrements its reference count. The font is only freed when the
    reference count reaches zero.

Draw a list of glyphs associated with fonts at specified
        coordinates, passed as an array of len XftGlyphFontSpec
        structures via the parameter glyphs. All of the glyphs are drawn
        using the color specified in the color parameter.

  





  

  
For each entry in the glyphs array:






    
  
  • If the associated font uses the X Render extension, then Xft uses
      XftGlyphFontSpecRender() to draw the glyph, using a Picture
      obtained from calling XftDrawSrcPicture () with the draw and
      color parameters.
    •

    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
This involves several steps:

  






    
  
  • First, Xft ensures that the glyphs array is complete using
      XftFontCheckGlyph() and loading any missing glyphs with
      XftFontLoadGlyphs().
    • 
  
  • Then Xft examines the glyphs to find the maximum Unicode value.
      That determines the encoding size, i.e., the width.
    • 
  
  • Then, for each glyph, Xft checks if its Unicode value is handled by
      the corresponding font. If not, the value is set to zero (0), to ignore
      it. While doing this, Xft also remembers which was the first font
      used, and computes the position at which each glyph will be drawn.
    • 
  
  • Xft then constructs an equivalent array of glyphs in the format
      expected by the X Render library.
    • 
  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
      draw the glyphs, with the appropriate XRenderCompositeText*()
      function according to the width, and discards temporary data.
    • 




  

  
The op, dst, src, srcx, and srcy
      parameters are used as described in the documentation for the X Render
      library.

NOMBRE


Xft - fuentes escalables para X






SINOPSIS


#include <X11/Xft/Xft.h>







DESCRIPCIÓN


Xft es una biblioteca que proporciona fuentes escalables para
    X. Utiliza Fontconfig para buscar fuentes y FreeType 2 para renderizar
    las fuentes.




Tipos de datos y constantes



  
XftFont

  
Representa una fuente abierta. Contiene información sobre la fuente,
      incluyendo la familia, el estilo, el tamaño y la métrica de los
      caracteres.

  
XftPattern

  
Representa un patrón de fuente. Se utiliza para especificar las
      propiedades deseadas de una fuente al buscarla. Un patrón contiene una
      colección de pares nombre-valor, donde cada nombre se refiere a una
      propiedad de la fuente (por ejemplo, "family", "style", "size").

  
XftFontSet

  
Contiene un conjunto de patrones de fuente. Se utiliza para devolver listas
      de fuentes que coinciden con un patrón de búsqueda.

  
FcPattern

  
Es el tipo de dato principal de Fontconfig para representar patrones de
      fuente. Xft utiliza internamente los patrones de Fontconfig para
      la búsqueda y el manejo de fuentes.

  
FcCharSet

  
Es el tipo de dato de Fontconfig para representar un conjunto de
      caracteres. Se utiliza para determinar si una fuente puede representar un
      determinado carácter o conjunto de caracteres.

  
FcBool

  
Tipo booleano de Fontconfig, que puede ser FcTrue o FcFalse.

void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Carga los glifos especificados por glyphs (un array de
        índices de glifo) para la fuente pub. Si need_bitmaps
        es FcTrue, también se cargan los mapas de bits de los glifos.
        Esta función utiliza FreeType para cargar los glifos y puede
        realizar operaciones adicionales como el escalado y la adición de
        glifos a la extensión X Render.

  





  

  
La carga de un glifo implica más que solo leer datos en memoria.
      Xft utiliza el patrón de Fontconfig asociado con la pantalla
      dpy (por ejemplo, a través de XftDefaultSet()) para
      determinar si se debe usar un cuadro delimitador, recortar los glifos
      dentro de esos límites, escalar los glifos, calcular métricas de fuente y
      agregarlos a la extensión X Render usando
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Descarga los glifos especificados por glyphs para la
        fuente pub. Si los glifos se agregaron a la extensión X Render,
        Xft los elimina usando XRenderFreeGlyphs(). Xft
        realiza un seguimiento de la cantidad de memoria utilizada para los
        glifos y actualiza el uso asociado con la pantalla dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si aún no se ha creado una "cara" de FreeType 2 (representación
        en memoria de una tipografía determinada en un estilo determinado) para
        la fuente pub, la crea usando FT_New_Face(). Los bloqueos
        de cara son un contador de referencias utilizado por Xft para
        garantizar que solo se cree una cara y que se conserve hasta que la
        fuente ya no se utilice.

  





  

  
El bloqueo de cara se utiliza directamente en XftCharIndex() y
      XftFontLoadGlyphs(), que a su vez se utilizan en muchas funciones de
      Xft.

  

  
El bloqueo de cara se introdujo en la versión 1 (octubre de 2002). Algunas
      aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la versión
      2.1.9 (junio de 2006), se conservó el bloqueo de cara como parte de la API
      pública cuando las configuraciones mejoradas de bibliotecas compartidas
      permitieron ocultar símbolos privados.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrementa el contador de referencias para la "cara" de
        FreeType 2 asociada con la fuente.

  





  

  
Los objetos FT_Face se desasignan usando
      FT_Done_Face(). Xft hace esto en
      XftFontInfoDestroy() y al limpiar en caso de error en
      XftFontInfoCreate() y XftFontOpenPattern().










DEPURACIÓN


Xft lee la variable de entorno XFT_DEBUG y la
    convierte a un entero. Cada bit en el valor resultante indica a Xft que
    imprima información de depuración en la salida estándar:



  
1

  
apertura de fuentes

  
2

  
coincidencia y apertura adicional de fuentes (verboso)

  
4

  
muestra detalles sobre el XRenderPictFormat que se utilizará.

  
8

  
muestra la cadena que XftDrawString8() dibujará.

  
16

  
muestra qué ids de fuente coinciden.

  
32

  
muestra información útil sobre los glifos que se dibujarán

  
64

  
muestra una representación en arte ASCII de los glifos.

  
128

  
muestra detalles sobre la gestión de la caché de memoria

  
256

  
muestra detalles sobre la gestión de la memoria caché de glifos

  
512

  
muestra un informe sobre el uso de memoria

  
1024

  
muestra detalles sobre la gestión extendida de la memoria caché de
      glifos








COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió
    relativamente estable. Se espera que mantenga la compatibilidad de origen y
    binaria en futuras versiones.


Xft proporciona una interfaz de compatibilidad con su
    versión principal anterior, Xft 1.x, descrita a continuación.




Archivo de cabecera Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de datos Xft 1.x



  
XftPattern

  
contiene un conjunto de nombres con listas de valores asociadas; cada nombre
      se refiere a una propiedad de una fuente. Los XftPattern se utilizan
      como entrada para el código de coincidencia, así como para mantener
      información sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPatterns. Internamente, Xft utiliza
      esta estructura de datos para mantener conjuntos de fuentes. Externamente,
      Xft devuelve los resultados de la lista de fuentes en este
      formato.

  
XftObjectSet

  
contiene un conjunto de nombres y se utiliza para especificar qué campos de
      las fuentes se colocan en la lista de patrones devueltos al listar
      fuentes.
