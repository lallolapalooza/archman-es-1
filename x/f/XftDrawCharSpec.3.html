XftDrawCharSpec(3)

Paquete: libxft

Licencias: HPND-sell-variant

XftDrawCharSpec(3) X Version 11 XftDrawCharSpec(3)

NOMBRE

XftDrawCharSpec - dibujar caracteres usando una fuente y una lista de especificaciones de caracteres.

SINOPSIS

#include <X11/Xft/Xft.h>

void XftDrawCharSpec(Display *dpy, Drawable drawable, XftFont *font,
                     int x, int y, XftCharSpec *specs, int nspecs);

DESCRIPCIÓN

La función XftDrawCharSpec dibuja caracteres usando la fuente especificada en el drawable especificado. Los caracteres a dibujar están especificados por la matriz specs, y la cantidad de caracteres a dibujar está especificada por nspecs. La matriz specs contiene el índice del glifo y el desplazamiento del carácter para cada carácter a dibujar.

Los caracteres se dibujan en la posición (x, y) en el drawable. La fuente utilizada para dibujar los caracteres se especifica mediante el puntero font.

El argumento dpy es el puntero a la estructura Display que describe la conexión con el servidor X. El argumento drawable es el identificador del drawable (ventana o pixmap) en el que se dibujarán los caracteres.

El argumento font es un puntero a la estructura XftFont que contiene información sobre la fuente que se utilizará para dibujar los caracteres. La fuente debe haber sido abierta previamente usando una de las funciones XftFontOpen*.

Los argumentos x e y especifican la posición de la línea base del texto a dibujar en coordenadas de píxeles relativas a la esquina superior izquierda del drawable.

El argumento specs es un puntero a una matriz de estructuras XftCharSpec. Cada estructura XftCharSpec contiene información sobre un carácter individual, incluyendo su índice de glifo y su desplazamiento. La matriz specs debe contener al menos nspecs elementos.

El argumento nspecs especifica el número de elementos en la matriz specs.

XftDrawCharSpec utiliza la extensión de renderizado X para dibujar los caracteres. Si la extensión de renderizado X no está disponible, el comportamiento es indefinido.

Esta función es útil para dibujar cadenas de caracteres que contienen caracteres que no se pueden representar directamente mediante un solo punto de código Unicode, como caracteres compuestos o caracteres que requieren un glifo específico.

Para dibujar cadenas de texto más simples, considera usar XftDrawString() o XftDrawStringUtf8().

STRUCTURES

XftDraw

is an opaque object which holds information used to render to an X drawable using either the core protocol or the X Rendering extension.

XftDraw objects are created with any of XftDrawCreate() (which associates an XftDraw with an existing X drawable), XftDrawCreateBitmap(), or XftDrawCreateAlpha(), and destroyed with XftDrawDestroy(). The X drawable associated with an XftDraw can be changed with XftDrawChange(). XftDraw objects are internally allocated and freed by Xft; the programmer does not ordinarily need to allocate or free storage for them.

The X Display, Drawable, Colormap, and Visual properties of an XftDraw can be queried with XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), and XftDrawVisual(), respectively.

Several functions use XftDraw objects: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), and the XftDrawString*() family.

The X Rendering Extension Picture associated with an XftDraw is returned by XftDrawPicture(), and XftDrawSrcPicture(). It is used by XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), and the XftTextRender*() family.

FUNCTIONS

Initialization

A typical application using Xft does not explicitly initialize the library. That is usually done as a side-effect of opening a font.

When Xft initializes, it collects information about the display, and stores some of that information in a Fontconfig pattern (essentially a collection of properties with typed values). The calling application can modify that pattern to change the library's behavior.

Not all of the collected information is stored in a pattern. The remainder is stored in internal data structures. Xft makes some of that available to the application via functions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtain information about the display dpy if not done already, and return true if Xft found that the display supports the X Render extension, and if it is able to find a suitable XRenderPictFormat (X Render's datatype which is analogous to Xlib's Visual) on the display.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtain information about the display dpy if not done already, and set the Fontconfig pattern holding default properties which Xft will use for this display.

Xft uses those properties initially to obtain these limits:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). This is the maximum amount of glyph memory for all fonts used by Xft (default: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). This is the maximum number of unreferenced fonts (default: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). When true, Xft tracks usage of glyph memory to improve performance when deciding which to unload when the maximum amount of glyph memory is reached (default: false).
Xft also uses these default properties in XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft fills in missing properties in the given pattern using default properties for the specified display dpy, e.g., as set in XftDefaultSet().

Typical Xft applications use this function to help Fontconfig choose a suitable font. These properties are substituted before calling FcDefaultSubstitute():
FC_ANTIALIAS
True if FreeType should use antialiasing (default: False). (default: True).
FC_AUTOHINT
True if FreeType should use autohinting (default: False).
FC_DPI
Dots/inch used for resolution (default: computed from the display height).
FC_EMBOLDEN
True if FT_GlyphSlot_Embolden() should be used to embolden a font (default: False).
FC_HINTING
True if hinting should be used when filling in properties to open a font (default: True).
FC_HINT_STYLE
Hinting style used when filling in properties to open a font (default: FC_HINT_FULL).
FC_LCD_FILTER
Parameter passed to FT_Library_SetLcdFilter() when loading glyphs (default: FC_LCD_DEFAULT).
FC_MINSPACE
Minimum space value used when filling in properties to open a font (default: False).
FC_RGBA
RGBA value used when filling in properties to open a font (default: computed by calling XRenderQuerySubpixelOrder()).
FC_SCALE
Scale used in Fontconfig (default: 1.0).
XFT_MAX_GLYPH_MEMORY
Maximum memory for one font (default: 1024*1024).
XFT_RENDER
True if the display supports X Render extension (default: result from XftDefaultHasRender()).

Opening   and Matching Fonts



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen takes a list of pattern element triples of
        the form field, type, value (terminated with a
        NULL), matches that pattern against the available fonts, and opens the
        matching font, sizing it correctly for screen number screen on
        display dpy. Return the matched font, or NULL if no match is
        found.

  




Example:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
This opens the “charter” font at 12 points. The point size
      is automatically converted to the correct pixel size based on the
      resolution of the monitor.

void XftFontClose (

  

    
	Display	*dpy,
	XftFont	*font);


    
XftFontClose destroys the font structure font,
        and decrements the reference count of the underlying font. When the
        reference count reaches zero, the font is unloaded.

	XftFont	*font);


    
XftObjectClose destroys the font structure font
        but does not affect the reference count of the underlying font. This is
        used when the application wants to keep the font loaded, but no longer
        needs the structure.

void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Esto implica varios pasos:

  






    
  
  • Primero, Xft asegura que el array glyphs esté completo
      usando XftFontCheckGlyph() y cargando cualquier glifo faltante con
      XftFontLoadGlyphs().
    • 
  
  • Luego, Xft examina los glifos para encontrar el valor Unicode máximo.
      Eso determina el tamaño de codificación, es decir, el width.
    • 
  
  • Luego, para cada glifo, Xft comprueba si su valor Unicode es manejado
      por la fuente correspondiente. Si no, el valor se establece en cero (0),
      para ignorarlo. Mientras hace esto, Xft también recuerda cuál fue la
      primera fuente utilizada y calcula la posición en la que se dibujará cada
      glifo.
    • 
  
  • Xft luego construye un array equivalente de glifos en el formato
      esperado por la biblioteca de Renderizado X.
    • 
  
  • Finalmente, XftGlyphFontSpecRender() utiliza la extensión de
      Renderizado X para dibujar los glifos, con la función apropiada
      XRenderCompositeText*() según el width, y descarta los datos
      temporales.
    • 




  

  
Los parámetros op, dst, src, srcx y
      srcy se utilizan como se describe en la documentación de la
      biblioteca de Renderizado X.

        de una tipografía dada en un estilo dado) de FreeType 2 para la fuente
        pub, se crea una usando FT_New_Face(). Los bloqueos de
        cara son un contador de referencias utilizado por Xft para
        asegurar que solo se crea una cara y que se conserva hasta que la fuente
        ya no se utiliza.

  





  

  
El bloqueo de cara se utiliza directamente en XftCharIndex() y
      XftFontLoadGlyphs(), que a su vez se utilizan en muchas funciones
      de Xft.

  

  
El bloqueo de cara se introdujo en la versión 1 (octubre de 2002).
      Algunas aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la
      versión 2.1.9 (junio de 2006), se mantuvo el bloqueo de cara como parte
      de la API pública cuando las configuraciones mejoradas de bibliotecas
      compartidas permitieron ocultar símbolos privados.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrementa el contador de referencias para la "cara" de
        FreeType 2 asociada con la fuente.

  





  

  
Los objetos FT_Face se desasignan usando FT_Done_Face().
      Xft lo hace en XftFontInfoDestroy() y al limpiar en caso de
      error en XftFontInfoCreate() y
      XftFontOpenPattern().










DEPURACIÓN


Xft lee la variable de entorno XFT_DEBUG y la
    convierte a un entero. Cada bit en el valor resultante le indica a Xft
    que imprima información de depuración en la salida estándar:



  
1

  
apertura de fuentes

  
2

  
coincidencia y apertura adicional de fuentes (verboso)

  
4

  
muestra detalles sobre el XRenderPictFormat que se utilizará.

  
8

  
muestra la cadena que XftDrawString8() dibujará.

  
16

  
muestra qué ids de fuente coinciden.

  
32

  
muestra información útil sobre los glifos que se dibujarán

  
64

  
muestra una representación de arte ASCII de los glifos.

  
128

  
muestra detalles sobre la gestión de la caché de memoria

  
256

  
muestra detalles sobre la gestión de la memoria caché de glifos

  
512

  
muestra un informe sobre el uso de memoria

  
1024

  
muestra detalles sobre la gestión extendida de la memoria caché de
      glifos








COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió
    relativamente estable. Se espera que mantenga la compatibilidad de origen y
    binaria en futuras versiones.


Xft proporciona una interfaz de compatibilidad con su
    versión principal anterior, Xft 1.x, descrita a continuación.




Archivo de encabezado Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de datos Xft 1.x



  
XftPattern

  
contiene un conjunto de nombres con listas de valores asociados; cada
      nombre se refiere a una propiedad de una fuente. Los XftPattern
      se utilizan como entrada para el código de coincidencia, así como para
      contener información sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPattern. Internamente, Xft utiliza
      esta estructura de datos para mantener conjuntos de fuentes.
      Externamente, Xft devuelve los resultados de la lista de fuentes
      en este formato.

  
XftObjectSet

  
contiene un conjunto de nombres y se utiliza para especificar qué campos
      de las fuentes se colocan en la lista de patrones devueltos al listar
      fuentes.
