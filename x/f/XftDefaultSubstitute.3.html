NOMBRE

Xft - Biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión secundaria de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo podrían usarse las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nombres, prefijando todos los nombres con “Xft”

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nombres. Se documentan en Xlib - C Language Interface.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de encabezado para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nombres, prefijando todos los nombres con “Fc” que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nombres, prefijando todos los nombres con “FT_” que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de fuente y punteros al conjunto de caracteres y patrón de Fontconfig asociados con la fuente.

Los XftFonts se pueblan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo() o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto en un objeto XftDraw, que puede corresponder a un drawable X básico o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont puede determinarse con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender() y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy() y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados internamente y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que puede recuperarse con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

typedef struct _XftColor {

NAME

Xft - X FreeType library

SYNOPSIS

#include <Xft/Xft.h>

DESCRIPTION

The Xft library provides an interface to the FreeType rasterizer for use with the X Window System. It uses Fontconfig for font matching and handling, and the X Rendering Extension for rendering glyphs.

Data Structures

A number of structures are used by the Xft library.

XftDraw

is an opaque object which holds information used to render to an X drawable using either the core protocol or the X Rendering extension.

XftDraw objects are created with any of XftDrawCreate() (which associates an XftDraw with an existing X drawable), XftDrawCreateBitmap(), or XftDrawCreateAlpha(), and destroyed with XftDrawDestroy(). The X drawable associated with an XftDraw can be changed with XftDrawChange(). XftDraw objects are internally allocated and freed by Xft; the programmer does not ordinarily need to allocate or free storage for them.

The X Display, Drawable, Colormap, and Visual properties of an XftDraw can be queried with XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), and XftDrawVisual(), respectively.

Several functions use XftDraw objects: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), and the XftDrawString*() family.

The X Rendering Extension Picture associated with an XftDraw is returned by XftDrawPicture(), and XftDrawSrcPicture(). It is used by XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), and the XftTextRender*() family.

FUNCTIONS

Initialization

A typical application using Xft does not explicitly initialize the library. That is usually done as a side-effect of opening a font.

When Xft initializes, it collects information about the display, and stores some of that information in a Fontconfig pattern (essentially a collection of properties with typed values). The calling application can modify that pattern to change the library's behavior.

Not all of the collected information is stored in a pattern. The remainder is stored in internal data structures. Xft makes some of that available to the application via functions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtain information about the display dpy if not done already, and return true if Xft found that the display supports the X Render extension, and if it is able to find a suitable XRenderPictFormat (X Render's datatype which is analogous to Xlib's Visual) on the display.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtain information about the display dpy if not done already, and set the Fontconfig pattern holding default properties which Xft will use for this display.

Xft uses those properties initially to obtain these limits:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). This is the maximum amount of glyph memory for all fonts used by Xft (default: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). This is the maximum number of unreferenced fonts (default: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). When true, Xft tracks usage of glyph memory to improve performance when deciding which to unload when the maximum amount of glyph memory is reached (default: false).
Xft also uses these default properties in XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft fills in missing properties in the given pattern using default properties for the specified display dpy, e.g., as set in XftDefaultSet().

Typical Xft applications use this function to help Fontconfig choose a suitable font. These properties are substituted before calling FcDefaultSubstitute():
FC_ANTIALIAS
True if FreeType should use antialiasing (default: False). (default: True).
FC_AUTOHINT
True if FreeType should use autohinting (default: False).
FC_DPI
Dots/inch used for resolution (default: computed from the display height).
FC_EMBOLDEN
True if FT_GlyphSlot_Embolden() should be used to embolden a font (default: False).

Opening and Matching Fonts



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen takes a list of pattern element triples of
        the form field, type, value (terminated with a
        NULL), matches that pattern against the available fonts, and opens the
        matching font, sizing it correctly for screen number screen on
        display dpy. Return the matched font, or NULL if no match is
        found.

  




Example:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
This opens the “charter” font at 12 points. The point size
      is automatically converted to the correct pixel size based on the
      resolution of the monitor.

NAME


XftDraw - drawing primitives for Xft






DESCRIPTION


The XftDraw object provides a convenient
    interface to the X Rendering Extension, allowing you to draw text and other
    graphics primitives to an X drawable. It manages the underlying X drawable,
    colormap, visual, and graphics context (GC), and handles the interaction
    with the X Render extension.

Clipping



    
Bool XftDrawSetClip (

    

        
	XftDraw	*draw,
	Region	 r);


        
Set up clipping for the given XftDraw parameter
            draw starting with a Region:

    





    
    
        
  • If the Region parameter r is not null, Xft creates
            a new Region (to copy the parameter),
    • 
        
  • Xft destroys any existing clipping region.
    • 
        
  • Xft sets the clip_type for the draw parameter to
            XftClipTypeRegion if the r parameter was not null.
            Otherwise it sets the clip_type to XftClipTypeNone.
    • 
        
  • Finally, Xft updates clipping for existing objects, updates
            the clip_mask for its X Render Picture object and sets the
            clipping-mask in the graphic context (GC) associated with the
            XftDraw parameter.
    • 
    





    

    
XftDrawSetClip() returns True if no change was necessary, or
        if the operation succeeded. It returns False if it was unable to
        create the new Region().

void XftDrawSetSubwindowMode (

    

        
	XftDraw	*draw,
	int	 mode);


        
Sets the subwindow-mode for the given XftDraw parameter
            draw. The mode can be either ClipByChildren (the
            default), or IncludeInferiors:

    





    
    
        
  • For ClipByChildren, both source and destination windows are
            additionally clipped by all viewable InputOutput children.
    •

        XSetSubwindowMode() as well as for an X Render Picture

void XftDrawGlyphFontSpec (

    

        
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


        
Draw a list of glyphs associated with fonts at specified
            coordinates, passed as an array of len
            XftGlyphFontSpec structures via the parameter glyphs.
            All of the glyphs are drawn using the color specified in the
            color parameter.

    





    

    
For each entry in the glyphs array:





    
    
        
  • If the associated font uses the X Render extension, then Xft
            uses XftGlyphFontSpecRender() to draw the glyph, using a
            Picture obtained from calling XftDrawSrcPicture ()
            with the draw and color parameters.
    • 
        
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 
    





    
void XftGlyphFontSpecRender (

    

        
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


        
This involves several steps:

    





    
    
        
  • First, Xft ensures that the glyphs array is complete
            using XftFontCheckGlyph() and loading any missing glyphs with
            XftFontLoadGlyphs().
    • 
        
  • Then Xft examines the glyphs to find the maximum Unicode
            value. That determines the encoding size, i.e., the width.
    • 
        
  • Then, for each glyph, Xft checks if its Unicode value is
            handled by the corresponding font. If not, the value is set to zero
            (0), to ignore it. While doing this, Xft also remembers which
            was the first font used, and computes the position at which each
            glyph will be drawn.
    • 
        
  • Xft then constructs an equivalent array of glyphs in the
            format expected by the X Render library.
    • 
        
  • Finally, XftGlyphFontSpecRender() uses the X Render
            extension to draw the glyphs, with the appropriate
            XRenderCompositeText*() function according to the width,
            and discards temporary data.
    • 
    

    

        

        
The op, dst, src, srcx, and srcy
            parameters are used as described in the documentation for the X
            Render library.

DESCRIPTION


The Xft library is a library for rendering fonts using the FreeType
    library. It provides functionality for font selection, font loading, glyph
    loading, and drawing text to X displays. It uses the Fontconfig library
    for font matching and configuration.

COMPATIBILITY


Xft version 2, released in May 2002, aimed for stability and is
    expected to maintain source and binary compatibility in future releases. Xft
    provides a compatibility interface to its previous major version, Xft 1.x.




Xft 1.x Header File


To use the Xft 1.x compatibility interface, include the following
    header file:


#include <X11/Xft/XftCompat.h>







Xft 1.x Data Types


The following data types were used in Xft 1.x:



  
XftPattern

  
Represents a set of names (font properties) and their associated value
      lists. Patterns are used both for specifying font search criteria and for
      holding information about specific fonts.

  
XftFontSet

  
Contains a list of XftPatterns. Internally, Xft uses this structure
      to manage sets of fonts, and externally, it is used to return lists of
      available fonts.

  
XftObjectSet

  
Holds a set of names. This structure is used to specify which fields from
      fonts should be included in the list of patterns returned when querying
      available fonts.
