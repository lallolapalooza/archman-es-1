NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca simple que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuentes convertidos utilizando la extensión X Rendering Extension.

Esta página del manual apenas araña la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo podrían usarse las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Están documentados en Xlib - Interfaz del Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada con una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la extensión X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de encabezado para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc”, que están documentados en la Referencia del Desarrollador de Fontconfig.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_”, que están documentados en la Referencia de la API de FreeType.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFonts se rellenan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador no necesita asignar ni liberar espacio para ellos normalmente.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder tanto a un drawable X principal como a un drawable de la extensión X Rendering Extension.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la extensión X Rendering Extension.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la extensión X Rendering Extension en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador no necesita asignar ni liberar espacio para ellos normalmente.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color del servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado para un XftColor.

Una vez que un XftColor ha sido inicializado, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), y XftDrawRect() pueden usarse para dibujar varios objetos utilizando

TYPES

This section describes the data types used by the Xft library.

XftDraw

is an opaque object which holds information used to render to an X drawable using either the core protocol or the X Rendering extension.

XftDraw objects are created with any of XftDrawCreate() (which associates an XftDraw with an existing X drawable), XftDrawCreateBitmap(), or XftDrawCreateAlpha(), and destroyed with XftDrawDestroy(). The X drawable associated with an XftDraw can be changed with XftDrawChange(). XftDraw objects are internally allocated and freed by Xft; the programmer does not ordinarily need to allocate or free storage for them.

The X Display, Drawable, Colormap, and Visual properties of an XftDraw can be queried with XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), and XftDrawVisual(), respectively.

Several functions use XftDraw objects: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), and the XftDrawString*() family.

The X Rendering Extension Picture associated with an XftDraw is returned by XftDrawPicture(), and XftDrawSrcPicture(). It is used by XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), and the XftTextRender*() family.

FUNCTIONS

Initialization

A typical application using Xft does not explicitly initialize the library. That is usually done as a side-effect of opening a font.

When Xft initializes, it collects information about the display, and stores some of that information in a Fontconfig pattern (essentially a collection of properties with typed values). The calling application can modify that pattern to change the library's behavior.

Not all of the collected information is stored in a pattern. The remainder is stored in internal data structures. Xft makes some of that available to the application via functions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtain information about the display dpy if not done already, and return true if Xft found that the display supports the X Render extension, and if it is able to find a suitable XRenderPictFormat (X Render's datatype which is analogous to Xlib's Visual) on the display.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtain information about the display dpy if not done already, and set the Fontconfig pattern holding default properties which Xft will use for this display.

Xft uses those properties initially to obtain these limits:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). This is the maximum amount of glyph memory for all fonts used by Xft (default: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). This is the maximum number of unreferenced fonts (default: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). When true, Xft tracks usage of glyph memory to improve performance when deciding which to unload when the maximum amount of glyph memory is reached (default: false).
Xft also uses these default properties in XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft fills in missing properties in the given pattern using default properties for the specified display dpy, e.g., as set in XftDefaultSet().

Typical Xft applications use this function to help Fontconfig choose a suitable font. These properties are substituted before calling FcDefaultSubstitute():
FC_ANTIALIAS
True if FreeType should use antialiasing (default: False). (default: True).
FC_AUTOHINT
True if FreeType should use autohinting (default: False).
FC_DPI
Dots/inch used for resolution (default: computed from the display height).
FC_EMBOLDEN
True if FT_GlyphSlot_Embolden() should be used to embolden a font (default: False).
FC_HINTING
True if hinting should be used when filling in properties to open a font (default: True).
FC_HINT_STYLE
Hinting style used when filling in properties to open a font (default: FC_HINT_FULL).
FC_LCD_FILTER
Parameter passed to FT_Library_SetLcdFilter() when loading glyphs (default: FC_LCD_DEFAULT).
FC_MINSPACE
Minimum space value used when filling in properties to open a font (default: False).
FC_RGBA
RGBA value used when filling in properties to open a font (default: computed by calling XRenderQuerySubpixelOrder()).
FC_SCALE
Scale used in Fontconfig (default: 1.0).
XFT_MAX_GLYPH_MEMORY
Maximum memory for one font (default: 1024*1024).
XFT_RENDER
True if the display supports X Render extension (default: result from XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initializes the Fontconfig library (calling FcInit()).

The config parameter is unused.
Xft does not deinitialize the Fontconfig library when it is done.
FcBool XftInitFtLibrary (void);

    
Initializes the FreeType library (calling
        FT_Init_FreeType() to create a library object) if it has not
        already been initialized. This is needed before using the FreeType
        library to read font data from a file.

  





  

  
Xft calls XftInitFtLibrary() internally via
      XftFontInfoCreate() and XftFontOpenPattern().

  

  
Xft does not discard the library object (e.g., using
      FT_Done_FreeType()) when it is done.

Opening   and Matching Fonts



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen takes a list of pattern element triples of
        the form field, type, value (terminated with a
        NULL), matches that pattern against the available fonts, and opens the
        matching font, sizing it correctly for screen number screen on
        display dpy. Return the matched font, or NULL if no match is
        found.

  




Example:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);






  

  
This opens the “charter” font at 12 points. The point size
      is automatically converted to the correct pixel size based on the
      resolution of the monitor.

NAME


Xft - X FreeType library






DESCRIPTION


The Xft library provides support for high-quality font
    management and rendering within the X Window System. It leverages the
    FreeType rendering engine to achieve scalable and anti-aliased text
    display.


This library provides functions for creating and managing font
    drawables, drawing strings, shapes, and manipulating font patterns.




Creating   and   Managing   Drawables



  
XftDraw *XftDrawCreate (

  

    
	Display	*dpy,
	Drawable	 drawable,
	Visual	*visual,
	Colormap	 colormap);


    
XftDrawCreate() creates and returns a new XftDraw
        object, which is used for rendering operations. It associates the object
        with the specified X display, drawable, visual, and colormap.

	Display	*dpy,
	Pixmap	 pixmap);


    
XftDrawCreatePixmap behaves as XftDrawCreate(),
        except that it uses an X pixmap of color depth 1 instead of an X
        drawable.

	Pixmap	 pixmap,

XftDrawCreateAlpha behaves as XftDrawCreate(),

        an X drawable.

        existing Xft draw object draw from its current value to

Picture XftDrawSrcPicture (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color);


    
Return an X Render Picture object, which is used for rendering
        glyphs, e.g., with XftGlyphRender(), XftGlyphSpecRender(),
        or XftGlyphFontSpecRender(), by XftDrawGlyphs(),
        XftDrawGlyphSpec(), XftDrawGlyphFontSpec(),
      respectively.

  





  

  
If the X server does not support the X Render extension, those functions
      use XftGlyphCore(), XftGlyphSpecCore(), or
      XftGlyphFontSpecCore().





  
void XftDrawDestroy (

  

    
	XftDraw	*draw);


    
XftDrawDestroy destroys draw (created by one of
        the XftDrawCreate*() functions) and frees the memory that was
        allocated for it.

  

  
Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Set up clipping for the given XftDraw parameter
        draw starting with a Region:

  






    
  
  • If the Region parameter r is not null, Xft creates a
      new Region (to copy the parameter),
    • 
  
  • Xft destroys any existing clipping region.
    • 
  
  • Xft sets the clip_type for the draw parameter to
      XftClipTypeRegion if the r parameter was not null. Otherwise
      it sets the clip_type to XftClipTypeNone.
    • 
  
  • Finally, Xft updates clipping for existing objects, updates the
      clip_mask for its X Render Picture object and sets the
      clipping-mask in the graphic context (GC) associated with the
      XftDraw parameter.
    • 






  

  
XftDrawSetClip() returns True if no change was necessary, or
      if the operation succeeded. It returns False if it was unable to
      create the new Region().





  
Bool XftDrawSetClipRectangles (

  

    
	XftDraw	*draw,
	int	 xOrigin,
	int	 yOrigin,
	_Xconst XRectangle	*rects,
	int	 n);


    
Like XftDrawSetClip(),
        XftDrawSetClipRectangles() sets up clipping for the given
        XftDraw parameter draw but uses a set of n
        rectangles (the rects parameter) which could be used to construct
        a Region .

  





  

  
Xft sets the clip_type for draw to XftClipTypeRectangles and
      uses XSetClipRectangles() for core (X11) clipping and
      XRenderSetPictureClipRectangles() for X Render clipping.





  
void XftDrawSetSubwindowMode (

  

    
	XftDraw	*draw,
	int	 mode);


    
Sets the subwindow-mode for the given XftDraw parameter
        draw. The mode can be either ClipByChildren (the default),
        or IncludeInferiors:

  






    
  
  • For ClipByChildren, both source and destination windows are
      additionally clipped by all viewable InputOutput children.
    • 
  
  • For IncludeInferiors, neither source nor destination window is
      clipped by inferiors. This will result in including subwindow contents in
      the source and drawing through subwindow boundaries of the
    destination.
    • 






  

  
In addition to the subwindow-mode maintained by Xft, it updates the
      subwindow mode for any associated graphics context GC using
      XSetSubwindowMode() as well as for an X Render Picture using
      XRenderChangePicture().

void XftCharFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftCharFontSpec	*chars,
	int	 len);

        parameter from XftCharFontSpec to XftGlyphFontSpec,
        passing the converted array along with the other parameters unchanged to
        XftGlyphFontSpecRender() to render the data.

  

  
void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Draw a list of glyphs associated with fonts at specified
        coordinates, passed as an array of len XftGlyphFontSpec
        structures via the parameter glyphs. All of the glyphs are drawn
        using the color specified in the color parameter.

  





  

  
For each entry in the glyphs array:






    
  
  • If the associated font uses the X Render extension, then Xft uses
      XftGlyphFontSpecRender() to draw the glyph, using a Picture
      obtained from calling XftDrawSrcPicture () with the draw and
      color parameters.
    • 
  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
This involves several steps:

  






    
  
  • First, Xft ensures that the glyphs array is complete using
      XftFontCheckGlyph() and loading any missing glyphs with
      XftFontLoadGlyphs().
    • 
  
  • Then Xft examines the glyphs to find the maximum Unicode value.
      That determines the encoding size, i.e., the width.
    • 
  
  • Then, for each glyph, Xft checks if its Unicode value is handled by
      the corresponding font. If not, the value is set to zero (0), to ignore
      it. While doing this, Xft also remembers which was the first font
      used, and computes the position at which each glyph will be drawn.
    • 
  
  • Xft then constructs an equivalent array of glyphs in the format
      expected by the X Render library.
    • 
  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
      draw the glyphs, with the appropriate XRenderCompositeText*()
      function according to the width, and discards temporary data.
    • 




  

  
The op, dst, src, srcx, and srcy
      parameters are used as described in the documentation for the X Render
      library.

DESCRIPTION


The Xft library provides access to the FreeType library
    for font rendering within the X Window System. It uses Fontconfig for font
    selection and management.




Listing fonts



  
XftFontSet *XftFontList (

  

    
	Display	*dpy,
	FcPattern	*pat,
	...);


    
Returns a list of fonts matching the pattern pat. The
        list is allocated by XftFontList() and must be freed using
        FcFontListDestroy(). The list may be empty, but is never NULL.

  








Opening fonts



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	FcPattern	*pat,
	...);


    
Opens a font matching the pattern pat. This function is
        a variadic function; additional arguments are used to specify the
        desired font size and other properties. If no font can be opened,
        XftFontOpen() returns NULL.

  

  
XftFont *XftFontOpenInfo (

  

    
	Display	*dpy,
	FcPattern	*pat,
	XftFontInfo	**info);


    
Opens a font matching the pattern pat and returns
        additional font information via the info pointer. If info
        is not NULL, it will point to an allocated XftFontInfo structure
        containing details about the opened font. This structure should be freed
        using XftFontInfoDestroy(). Returns NULL if no font can be
        opened.

  

  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	FcPattern	*pat,
	const char	*name,
	...);


    
Opens a font matching the name name. The name
        is parsed using XftNameParse(). Additional arguments are used to
        specify the desired font size and other properties.

  

  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	FcPattern	*pat,
	const char	*xlfd,
	...);


    
Opens a font matching the X Logical Font Description (XLFD)
        string xlfd. Additional arguments are used to specify the desired
        font size and other properties.

  








Name parsing



  
FcPattern *XftNameParse (

  

    
	const char	*name);


    
Parses the font name string name into a Fontconfig
        pattern. This pattern can then be used with functions like
        XftFontOpen() or XftFontOpenName().

  

  
bool XftNameUnparse (

  

    
	const FcPattern	*pat,
	char	*dest,
	int	 len);


    
Converts the Fontconfig pattern pat back into a string
        representation that can be parsed by XftNameParse(). The resulting
        string is stored in the buffer pointed to by dest, with a maximum
        length of len. Returns true if the conversion was successful
        and the string fits within the buffer, false otherwise.

  








Manipulating Font data



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	const FT_UInt	*glyphs,
	int	 nglyph);


    
Loads the specified glyphs for the font pub. The
        glyphs argument is an array of glyph indices (typically Unicode
        values). If need_bitmaps is FcTrue, bitmap versions of the
        glyphs will be loaded if available. This function uses FreeType's glyph
        loading mechanisms and may interact with the X Render extension.

  

  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	const FT_UInt	*glyphs,
	int	 nglyph);


    
Unloads the specified glyphs for the font pub. This
        releases the memory associated with the loaded glyphs. If the glyphs
        were loaded into the X Render extension, they will be freed there as
        well.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Acquires a reference to the FreeType face object associated
        with the font pub. If no face object has been created yet, it will
        be created. This function increments an internal reference count to ensure
        the face object remains valid while in use. It returns the FreeType face
        handle.

  

  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Releases a reference to the FreeType face object associated
        with the font pub. This decrements the internal reference count.
        When the count reaches zero, the FreeType face object is destroyed.

  










DEBUGGING


The XFT_DEBUG environment variable controls the level of
    debugging output. Setting bits in this variable enables different types of
    debugging messages:



  
1

  
Font opening information.

  
2

  
Verbose font matching and opening.

  
4

  
Details about the XRenderPictFormat being used.

  
8

  
Strings being drawn by XftDrawString8(), etc.

  
16

  
Font IDs being matched.

  
32

  
Information about glyphs to be drawn.

  
64

  
ASCII art representation of glyphs.

  
128

  
Glyph cache management details.

  
256

  
Glyph cache memory management details.

  
512

  
Memory usage report.

  
1024

  
Extended glyph cache management details.








COMPATIBILITY


Xft aims to maintain compatibility with previous versions.
    Specifically, the data types and functions described below are part of the
    compatibility interface for Xft 1.x.




Xft 1.x Data Types



  
XftPattern

  
A data structure representing a set of font properties. Used for matching
      fonts and storing font information.

  
XftFontSet

  
A list of XftPattern objects, typically used to return the results
      of font listing operations.

  
XftObjectSet

  
Used to specify which font properties should be included when listing
      fonts.
