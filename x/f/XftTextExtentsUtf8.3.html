NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca simple que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas roza la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo podrían usarse las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con "Xft"

De Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz de Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps se pueden usar como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no se puede usar como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

De XRender...

Los tipos de datos de la biblioteca de Extensión de Renderizado X están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de encabezado para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

De Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con "Fc", que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

De FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con "FT_", que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFont se llenan con XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFont son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto en un objeto XftDraw, que puede corresponder a un drawable X central o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color al servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado para un XftColor.

DESCRIPTION

XftDraw

es un objeto opaco que contiene información utilizada para renderizar en un drawable X utilizando el protocolo principal o la extensión X Rendering.

Los objetos XftDraw se crean con cualquiera de las funciones XftDrawCreate() (que asocia un XftDraw con un drawable X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable X asociado con un XftDraw puede cambiarse con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Las propiedades X Display, Drawable, Colormap, y Visual de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

La extensión X Rendering Picture asociada con un XftDraw se devuelve mediante XftDrawPicture() y XftDrawSrcPicture(). Es utilizada por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa explícitamente la biblioteca. Esto generalmente se hace como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft encontró que la pantalla soporta la extensión X Render, y si es capaz de encontrar un XRenderPictFormat adecuado (el tipo de datos de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza estas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (por defecto: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (por defecto: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir qué descargar cuando se alcanza la cantidad máxima de memoria de glifos (por defecto: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft completa las propiedades que faltan en el pattern dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar antialiasing (por defecto: Falso). (por defecto: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (por defecto: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (por defecto: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para engrosar una fuente (por defecto: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar las propiedades para abrir una fuente (por defecto: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar las propiedades para abrir una fuente (por defecto: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (por defecto: FC_LCD_DEFAULT).
FC_MINSPACE
Espacio mínimo utilizado al completar las propiedades para abrir una fuente (por defecto: Falso).
FC_RGBA
Valor RGBA utilizado al completar las propiedades para abrir una fuente (por defecto: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (por defecto: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (por defecto: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión X Render (por defecto: resultado de XftDefaultHasRender()).

Apertura y Coincidencia de Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triples de elementos de patrón del tipo campo, tipo, valor (terminada con NULL), coincide con ese patrón contra las fuentes disponibles, y abre la fuente coincidente, dimensionándola correctamente para la pantalla número screen en la pantalla dpy. Devuelve la fuente coincidente, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);






  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño del punto se convierte automáticamente al tamaño de píxel correcto según la resolución del monitor.

XftXlfdParse analiza el parámetro xlfd_orig

Determinación de Extensiones de Texto


Xft proporciona varias funciones para determinar la altura y
    anchura necesarias para mostrar una cadena de texto. Después de tener en
    cuenta el offset, en casos en los que la cadena se desplazará hacia
    arriba, abajo, izquierda o derecha, estos números se denominan extensiones
    de texto.



  
void XftTextExtents8 (

  

    
	Display	*dpy,
	XftFont	*font,
	_Xconst FcChar8	*string,
	int	 len,
	XGlyphInfo	*extents);


    
XftTextExtents8 calcula las extensiones de píxeles en la
        pantalla dpy de no más de len glifos de una cadena
        que consta de caracteres de ocho bits al dibujarla con font,
        almacenándolos en extents.

Gestión de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utiliza XAllocNamedColor() para buscar el color con nombre
        name para la pantalla asociada con el mapa de colores
        cmap.

  






    
  
  • Si XAllocNamedColor() devuelve un valor distinto de cero,
      XftColorAllocName() rellena el campo de píxel XftColor
      resultante con el color más cercano admitido por la pantalla, así como los
      campos exactos de rojo, verde y azul de la base de datos, y devuelve True.
    • 
  
  • Si XAllocNamedColor() devuelve cero, XftColorAllocName()
      devuelve False y no actualiza el XftColor referenciado por
      result.
    • 






  

  
El parámetro visual no se utiliza.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Asigna un valor de color:

  






    
  
  • Si la clase visual es TrueColor, XftColorAllocValue() establece
      el campo pixel en el XftColor referenciado por result
      utilizando los campos rojo, verde y azul del parámetro color.
    • 
  
  • Si la clase visual no es TrueColor, XftColorAllocValue()
      llama a XAllocColor() para asignar una entrada en el mapa de colores
      cmap, que devuelve el valor de píxel del color más cercano a los
      elementos RGB especificados admitidos por el hardware.
    • 




  

  
Si XAllocColor() tiene éxito, XftColorAllocValue() almacena ese
      valor de píxel en el XRenderColor referenciado por result y
      devuelve True.

  

  
Si XAllocColor() falla, XftColorAllocValue() devuelve False y
      no modifica el resultado.

void

  

    
XftDrawGlyphFontSpec(
        XftDraw	*draw,
        _Xconst XftColor	*color,
        _Xconst XftGlyphFontSpec	*glyphs,
        int	 len);


    
Draw a list of glyphs associated with fonts at specified
        coordinates, passed as an array of len XftGlyphFontSpec
        structures via the parameter glyphs. All of the glyphs are drawn
        using the color specified in the color parameter.

  






For each entry in the glyphs array:


    
  
  • If the associated font uses the X Render extension, then Xft uses
      XftGlyphFontSpecRender() to draw the glyph, using a Picture
      obtained from calling XftDrawSrcPicture () with the draw and
      color parameters.
    • 
  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 






  
void

  

    
XftGlyphFontSpecRender(
        Display	*dpy,
        int	 op,
        Picture	 src,
        Picture	 dst,
        int	 srcx,
        int	 srcy,
        _Xconst XftGlyphFontSpec	*glyphs,
        int	 nglyphs);


    
This involves several steps:

  






    
  
  • First, Xft ensures that the glyphs array is complete using
      XftFontCheckGlyph() and loading any missing glyphs with
      XftFontLoadGlyphs().
    • 
  
  • Then Xft examines the glyphs to find the maximum Unicode value.
      That determines the encoding size, i.e., the width.
    • 
  
  • Then, for each glyph, Xft checks if its Unicode value is handled by
      the corresponding font. If not, the value is set to zero (0), to ignore
      it. While doing this, Xft also remembers which was the first font
      used, and computes the position at which each glyph will be drawn.
    • 
  
  • Xft then constructs an equivalent array of glyphs in the format
      expected by the X Render library.
    • 
  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
      draw the glyphs, with the appropriate XRenderCompositeText*()
      function according to the width, and discards temporary data.
    • 




  

  
The op, dst, src, srcx, and srcy
      parameters are used as described in the documentation for the X Render
      library.

NOMBRE


XftTextExtentsUtf8, XftTextExtentsWChar, XftTextExtents8 - obtener el ancho y la altura de una cadena de caracteres






SINOPSIS


#include <X11/Xft/Xft.h>

void
XftTextExtentsUtf8(
    Display *dpy,
    XftFont *font,
    const FcChar8 *string,
    int n_chars,
    XftGlyphInfo *info
);

void
XftTextExtentsWChar(
    Display *dpy,
    XftFont *font,
    const FcChar16 *string,
    int n_chars,
    XftGlyphInfo *info
);

void
XftTextExtents8(
    Display *dpy,
    XftFont *font,
    const char *string,
    int n_chars,
    XftGlyphInfo *info
);







DESCRIPCIÓN


Estas funciones calculan la anchura y altura de una cadena de caracteres,
    así como otra información de glifos relacionados, utilizando la fuente
    especificada.


La cadena de caracteres se codifica en UTF-8 para
    XftTextExtentsUtf8, en UTF-16 para
    XftTextExtentsWChar y como una cadena de bytes con codificación
    desconocida para XftTextExtents8. La función
    XftTextExtents8 es una función de conveniencia que
    llama a XftTextExtentsUtf8 después de convertir la
    cadena de bytes de entrada en UTF-8.


La fuente utilizada para calcular las dimensiones se pasa como el
    argumento font. La cadena de caracteres de entrada se
    pasa como string, con la longitud en caracteres (no
    en bytes) especificada por n_chars.


La información calculada sobre los glifos se almacena en la
    estructura XftGlyphInfo, que se pasa a través del
    argumento info. Esta estructura contiene:



  
XftGlyphInfo.width

  
La anchura total de la cadena de caracteres.

  
XftGlyphInfo.height

  
La altura total de la cadena de caracteres.

  
XftGlyphInfo.x

  
El desplazamiento X del primer glifo.

  
XftGlyphInfo.y

  
El desplazamiento Y del primer glifo.

  
XftGlyphInfo.lost

  
Si se han perdido glifos (por ejemplo, si no se encontraron en la
      fuente).




El argumento dpy se utiliza para acceder
    a la información de configuración de la pantalla y para la asignación de
    recursos si es necesario.


Estas funciones son útiles para el diseño de texto, permitiendo
    a las aplicaciones determinar el espacio necesario para dibujar cadenas de
    caracteres antes de dibujarlas realmente.






CONSTANTES


No hay constantes definidas para estas funciones.

FT_Face XftLockFace (

      Algunas aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la
      versión 2.1.9 (junio de 2006), los bloqueos de cara se conservaron como
      parte de la API pública cuando las configuraciones mejoradas de bibliotecas

COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se
    volvió relativamente estable. Se espera que mantenga la compatibilidad de
    código fuente y binaria en futuras versiones.


Xft proporciona una interfaz de compatibilidad
    con su versión principal anterior, Xft 1.x, que se describe a
    continuación.




Archivo de encabezado Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de datos Xft 1.x



  
XftPattern

  
contiene un conjunto de nombres con listas de valores asociadas; cada nombre
      se refiere a una propiedad de una fuente. Los XftPatterns
      se utilizan como entradas para el código de coincidencia, así como para
      almacenar información sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPatterns. Internamente,
      Xft utiliza esta estructura de datos para mantener
      conjuntos de fuentes. Externamente, Xft devuelve los
      resultados de listar fuentes en este formato.

  
XftObjectSet

  
contiene un conjunto de nombres y se utiliza para especificar qué campos de
      las fuentes se colocan en la lista de patrones devueltos al listar
      fuentes.
