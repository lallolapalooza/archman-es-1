NOMBRE

Xft - Librería de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una librería simple que dibuja texto y gráficos:

  • utilizando información proporcionada por la librería Fontconfig,
  • Xft convierte glifos de fuentes usando el rasterizador FreeType, y
  • muestra los datos de fuentes convertidos usando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta librería.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la librería Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz de Lenguaje C.

Xft usa estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa por la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la librería de Extensión de Renderizado X están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft usa estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc”, que se documentan en la Referencia para Desarrolladores de Fontconfig.

Xft usa estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_”, que se documentan en la Referencia de la API de FreeType.

Xft usa estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 usa FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que usan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres de Fontconfig y al patrón asociados con la fuente.

Los XftFont se llenan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo() o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador no necesita normalmente asignar o liberar memoria para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() usan XftFonts para renderizar texto a un objeto XftDraw, que puede corresponder a un drawable X central o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender() y la familia XftTextRender*() usan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec() y XftDrawGlyphSpec() proporcionan un medio de renderizado de fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy() y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador no necesita normalmente asignar o liberar memoria para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color al servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() indica al servidor X que libere el color actualmente asignado para un XftColor.

Una vez que un XftColor ha sido inicializado, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec() y XftDrawRect() pueden usarse para dibujar varios objetos utilizándolo.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar en un drawable de X utilizando el protocolo principal o la extensión de renderización de X.

Los objetos XftDraw se crean con cualquiera de XftDrawCreate() (que asocia un XftDraw con un drawable de X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable de X asociado con un XftDraw se puede cambiar con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Las propiedades Display, Drawable, Colormap y Visual de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

El Picture de la Extensión de Renderización de X asociado con un XftDraw se devuelve mediante XftDrawPicture() y XftDrawSrcPicture(). Es utilizado por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa la biblioteca explícitamente. Eso generalmente se hace como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipificados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft determinó que la pantalla soporta la extensión de Renderización de X, y si es capaz de encontrar un XRenderPictFormat adecuado (el tipo de datos de Renderización de X que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza estas propiedades inicialmente para obtener los siguientes límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft rellena las propiedades faltantes en el pattern dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar suavizado (antialiasing) (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para poner en negrita una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al completar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al completar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión de Renderización de X (predeterminado: resultado de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Inicializa la biblioteca Fontconfig (llamando a FcInit()).

El parámetro config no se utiliza.
Xft no desinicializa la biblioteca Fontconfig cuando termina.
FcBool XftInitFtLibrary (void);

    
Inicializa la biblioteca FreeType (llamando a
        FT_Init_FreeType() para crear un objeto de biblioteca) si aún no se ha inicializado. Esto es necesario antes de utilizar la biblioteca FreeType para leer datos de fuentes de un archivo.

  





  

  
Xft llama a XftInitFtLibrary() internamente a través de
      XftFontInfoCreate() y XftFontOpenPattern().

  

  
Xft no descarta el objeto de biblioteca (por ejemplo, usando
      FT_Done_FreeType()) cuando termina.

Abrir   y Emparejar Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de tripletes de elementos de patrón del tipo campo, tipo, valor (terminada con NULL), empareja ese patrón con las fuentes disponibles, y abre la fuente coincidente, dimensionándola correctamente para la pantalla número screen en la pantalla dpy. Devuelve la fuente coincidente, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño en puntos se convierte automáticamente al tamaño de píxeles correcto basado en la resolución del monitor.

de foundry.

de family.

Determinación de Extremos de Texto


Xft proporciona varias funciones para determinar la altura y
    el ancho requeridos para mostrar una cadena de texto. Después de tener en
    cuenta el offset, en los casos en que la cadena se desplazará hacia
    arriba, hacia abajo, hacia la izquierda o hacia la derecha, estos números se
    denominan extremos de texto.



  
void XftTextExtents8 (

  

    
	Display	*dpy,
	XftFont	*font,
	_Xconst FcChar8	*string,
	int	 len,
	XGlyphInfo	*extents);


    
XftTextExtents8 calcula los extremos de píxeles en la
        pantalla dpy de no más de len glifos de una cadena
        que consta de caracteres de ocho bits cuando se dibuja con font,
        almacenándolos en extents.

Administración de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utiliza XAllocNamedColor() para buscar el color con
        nombre name para la pantalla asociada con el mapa de colores
        cmap.

  






    
  
  • Si XAllocNamedColor() devuelve un valor distinto de cero,
      XftColorAllocName() rellena el campo de píxel XftColor
      resultante con el color más cercano admitido por la pantalla, así como los
      campos exactos de rojo, verde y azul de la base de datos, y devuelve
      True.
    • 
  
  • Si XAllocNamedColor() devuelve cero, XftColorAllocName()
      devuelve False y no actualiza el XftColor al que hace referencia
      result.
    • 






  

  
El parámetro visual no se utiliza.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Asigna un valor de color:

  






    
  
  • Si la clase de visual es TrueColor, XftColorAllocValue()
      establece el campo pixel en el XftColor al que hace
      referencia result utilizando los campos rojo, verde y azul del
      parámetro color.
    • 
  
  • Si la clase de visual no es TrueColor, XftColorAllocValue()
      llama a XAllocColor() para asignar una entrada en el mapa de
      colores cmap. que devuelve el valor de píxel del color más
      cercano a los elementos RGB especificados compatibles con el hardware.
    • 




  

  
Si XAllocColor() tiene éxito, XftColorAllocValue() almacena
      ese valor de píxel en el XRenderColor al que hace referencia
      result y devuelve True.

  

  
Si XAllocColor() falla, XftColorAllocValue() devuelve False
      y no modifica el resultado.

glyphs. All of the glyphs are drawn using the color specified in the
color parameter.
.TP
For each entry in the glyphs array:
.TP
* If the associated font uses the X Render extension, then Xft uses
  XftGlyphFontSpecRender() to draw the glyph, using a Picture
  obtained from calling XftDrawSrcPicture () with the draw and
  color parameters.
* Otherwise, Xft provides an analogous feature using Xlib.
.TP
void
XftGlyphFontSpecRender(
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs
);
This involves several steps:
.TP
* First, Xft ensures that the glyphs array is complete using
  XftFontCheckGlyph() and loading any missing glyphs with
  XftFontLoadGlyphs().
* Then Xft examines the glyphs to find the maximum Unicode value. That
  determines the encoding size, i.e., the width.
* Then, for each glyph, Xft checks if its Unicode value is handled by the
  corresponding font. If not, the value is set to zero (0), to ignore it. While
  doing this, Xft also remembers which was the first font used, and
  computes the position at which each glyph will be drawn.
* Xft then constructs an equivalent array of glyphs in the format expected
  by the X Render library.
* Finally, XftGlyphFontSpecRender() uses the X Render extension to draw
  the glyphs, with the appropriate XRenderCompositeText*() function
  according to the width, and discards temporary data.
.TP
The op, dst, src, srcx, and srcy parameters are used
as described in the documentation for the X Render library.

NAME

        
XftDrawString8, XftDrawString16, XftDrawString32 - draw strings

    

    

        
SYNOPSIS

        
            #include <X11/Xft/Xft.h>

            void
            XftDrawString8(
                XftDraw *draw,
                XftColor *color,
                XftFont *font,
                int x,
                int y,
                const FcChar8 *string,
                int len
            );

            void
            XftDrawString16(
                XftDraw *draw,
                XftColor *color,
                XftFont *font,
                int x,
                int y,
                const FcChar16 *string,
                int len
            );

            void
            XftDrawString32(
                XftDrawDraw *draw,
                XftColor *color,
                XftFont *font,
                int x,
                int y,
                const FcChar32 *string,
                int len
            );
        

    

    

        
DESCRIPTION

        
The function XftDrawString8 draws the string
            of length len at position (x, y) using the
            specified color and font onto the XftDraw
            object draw.

        
XftDrawString16 and XftDrawString32 are
            identical, except that they take FcChar16 and FcChar32 strings,
            respectively.

        
Each function performs the following actions:

        

            
1.

            
Finds the glyph indices corresponding to the characters in the
                string using XftCharIndex().

            
2.

            
Loads these glyphs into the font's glyph cache using
                XftFontLoadGlyphs().

            
3.

            
Adds the glyphs to the XftDraw's
                render picture using XRenderAddGlyphs().

            
4.

            
Draws the string using XftGlyphExtents() to determine
                the bounding box of the string, and then using
                XftDrawGlyphs() to draw the string.

        

    

    

        
CONSTANTS

        
The following constants are defined in
            <X11/Xft/Xft.h>:

        

            
FcChar8

            

            
FcChar16

            

            
FcChar32

            
These are typedefs for unsigned 8-bit, 16-bit, and 32-bit
                integers, respectively. They are used to represent characters in
                different encodings. FcChar8 is typically ISO-8859-1,
                FcChar16 is typically UTF-16, and FcChar32 is
                typically UTF-32.

        

    

    

        
DATA TYPES

        

            
XftDraw

            
An object that represents a drawable surface for rendering glyphs.
                It holds information about the drawable, the screen, the visual,
                and the X Render picture used for drawing.

            
XftFont

            
An opaque structure representing an opened font. It contains
                information about the font's metrics, the FreeType face, and
                the font pattern used to open it.

            
XftColor

            
A structure representing a color, typically in RGBA format. It
                contains fields for the color's red, green, blue, and alpha
                components.

void XftFontLoadGlyphs (

            

                
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


                
Using FT_Load_Glyph(), load nglyphs
                    for the glyph indices (Unicode values) listed in the array
                    glyphs from the given font pub.

            

        

        

            

            
Loading a glyph entails more than just reading data into memory.
                Xft uses the Fontconfig pattern associated with the
                display dpy (e.g., via XftDefaultSet()) to
                determine whether to use a bounding box, clip the glyphs into
                those bounds, scale the glyphs, compute font metrics, and add

	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


                
Discards data for up to nglyph glyphs whose
                    glyph indices (Unicode values) are listed in the array
                    glyphs for the given font pub. If the glyphs
                    were added to the X Render extension, Xft removes
                    those using XRenderFreeGlyphs(). Xft keeps
                    track of the amount of memory used for glyphs, and updates
                    the usage associated with the display dpy.

            

            
FT_Face XftLockFace (

            

                
	XftFont	*pub);


                
If no FreeType 2 “face” (in-memory
                    representation of a given typeface in a given style) has
                    been created for the pub font, create one using
                    FT_New_Face(). Face-locks are a reference count used
                    by Xft to ensure that only one face is created, and
                    that it is retained until the font is no longer used.

            

        

        

            

            
Face-locking is used directly in XftCharIndex() and
                XftFontLoadGlyphs(), which in turn are used in many
                functions of Xft.

            

            
Face-locking was introduced in version 1 (October 2002). A few
                applications, such as Gdk/Gimp relied upon these functions. In
                version 2.1.9 (June 2006), face-locking was retained as part of
                the public API when improved shared-library configurations
                provided for hiding private symbols.

        

        

            
void XftUnlockFace (

            

                
	XftFont	*pub);


                
Decrements the reference count for the FreeType 2
                    “face” associated with the font.

            

        

        

            

            
FT_Face objects are deallocated using
                FT_Done_Face(). Xft does this in
                XftFontInfoDestroy() and when cleaning up on failure in
                XftFontInfoCreate() and XftFontOpenPattern().

32

128

256

            
shows details about managing glyph cached-memory

            
512

1024

COMPATIBILITY

        
As of version 2 (May 2002), Xft became relatively
            stable. It is expected to retain source and binary compatibility in
            future releases.

        
Xft provides a compatibility interface to its previous
            major version, Xft 1.x, described below.

        

            
Xft 1.x Header File

            
#include <X11/Xft/XftCompat.h>

        

        

            
Xft 1.x Data Types

            

                
XftPattern

                
holds a set of names with associated value lists; each name refers to a property of a font. XftPatterns are used as inputs to the matching code as well as holding information about specific fonts.

                
XftFontSet

                
contains a list of XftPatterns. Internally, Xft uses this data structure to hold sets of fonts. Externally, Xft returns the results of listing fonts in this format.

                
XftObjectSet

                
holds a set of names and is used to specify which fields from fonts are placed in the list of returned patterns when listing fonts.
