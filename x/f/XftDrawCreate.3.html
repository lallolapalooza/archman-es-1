NOMBRE

Xft - Biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuentes convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo podrían usarse las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, anteponiendo el prefijo “Xft” a todos los nombres.

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz de Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, anteponiendo el prefijo “Fc” a todos los nombres, que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, anteponiendo el prefijo “FT_” a todos los nombres, que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar glifos.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFonts se pueblan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se usa para duplicar XftFonts, y XftFontClose() se usa para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar ni liberar memoria para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto en un objeto XftDraw, que puede corresponder a un drawable X principal o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados internamente y liberados por Xft; el programador normalmente no necesita asignar ni liberar memoria para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color al servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado a un XftColor.

Una vez que un XftColor ha sido inicializado, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), y XftDrawRect() pueden ser utilizados para dibujar varios objetos utilizando este.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable X utilizando el protocolo principal o la extensión X Rendering.

Los objetos XftDraw se crean con cualquiera de las funciones XftDrawCreate() (que asocia un XftDraw con un drawable X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable X asociado con un XftDraw se puede cambiar con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar memoria para ellos.

Las propiedades de Display, Drawable, Colormap, y Visual de X de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

La extensión X Rendering Picture asociada con un XftDraw se devuelve mediante XftDrawPicture() y XftDrawSrcPicture(). Es utilizada por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa la biblioteca explícitamente. Eso se hace normalmente como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación llamante puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft determinó que la pantalla admite la extensión X Render, y si puede encontrar un XRenderPictFormat adecuado (el tipo de datos de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir qué descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft completa las propiedades faltantes en el pattern dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar antialiasing (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para engrosar una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al completar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al completar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla admite la extensión X Render (predeterminado: resultado de XftDefaultHasRender()).

Abrir y emparejar fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triplas de elementos de
        patrón del tipo campo, tipo, valor (terminada
        con un NULL), empareja ese patrón con las fuentes disponibles, y abre
        la fuente emparejada, dimensionándola correctamente para el número de
        pantalla screen en la pantalla dpy. Devuelve la fuente
        emparejada, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);






  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño del punto se
      convierte automáticamente al tamaño de píxel correcto según la resolución
      del monitor.

Managing   XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Use XAllocNamedColor() to look up the named color
        name for the screen associated with the colormap cmap.

  






    
  
  • If XAllocNamedColor() returns nonzero, XftColorAllocName()
      fills in the resulting XftColor pixel field with the closest color
      supported by the screen, as well as the exact red, green and blue fields
      from the database, and returns True.
    • 
  
  • If XAllocNamedColor() returns zero, XftColorAllocName()
      returns False, and does not update the XftColor referenced by
      result.
    • 






  

  
The visual parameter is unused.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Allocate a color value:

  






    
  
  • If the visual class is TrueColor, XftColorAllocValue() sets
      the pixel field in the XftColor referenced by result
      using the red, green and blue fields from the color parameter.
    • 
  
  • If the visual class is not TrueColor, XftColorAllocValue()
      calls XAllocColor() to allocate an entry in the colormap
      cmap. which returns the pixel value of the color closest to the
      specified RGB elements supported by the hardware.
    • 




  

  
If XAllocColor() succeeds XftColorAllocValue() stores that
      pixel value in the XRenderColor referenced by result and
      returns True.

  

  
If XAllocColor() fails, XftColorAllocValue() returns False
      and does not modify the result.

Bool XftDrawSetClip (

    

        
	XftDraw	*draw,
	Region	 r);


        
Set up clipping for the given XftDraw parameter
            draw starting with a Region:

    






    
    
  • If the Region parameter r is not null, Xft creates a
        new Region (to copy the parameter),
    • 
    
  • Xft destroys any existing clipping region.
    • 
    
  • Xft sets the clip_type for the draw parameter to
        XftClipTypeRegion if the r parameter was not null. Otherwise
        it sets the clip_type to XftClipTypeNone.
    • 
    
  • Finally, Xft updates clipping for existing objects, updates the
        clip_mask for its X Render Picture object and sets the
        clipping-mask in the graphic context (GC) associated with the
        XftDraw parameter.
    • 






    

    
XftDrawSetClip() returns True if no change was necessary, or
        if the operation succeeded. It returns False if it was unable to
        create the new Region().

void XftDrawSetSubwindowMode (

    

        
	XftDraw	*draw,
	int	 mode);


        
Sets the subwindow-mode for the given XftDraw parameter
            draw. The mode can be either ClipByChildren (the default),
            or IncludeInferiors:

    






    
    
  • For ClipByChildren, both source and destination windows are
        additionally clipped by all viewable InputOutput children.
    • 
    
  • For IncludeInferiors, neither source nor destination window is
        clipped by inferiors. This will result in including subwindow contents in
        the source and drawing through subwindow boundaries of the
        destination.
    • 






    

    
In addition to the subwindow-mode maintained by Xft, it updates the
        subwindow mode for any associated graphics context GC using
        XSetSubwindowMode() as well as for an X Render Picture using
        XRenderChangePicture().

void XftDrawGlyphFontSpec (

    

        
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


        
Draw a list of glyphs associated with fonts at specified
            coordinates, passed as an array of len XftGlyphFontSpec
            structures via the parameter glyphs. All of the glyphs are drawn
            using the color specified in the color parameter.

    





    

    
For each entry in the glyphs array:






    
    
  • If the associated font uses the X Render extension, then Xft uses
        XftGlyphFontSpecRender() to draw the glyph, using a Picture
        obtained from calling XftDrawSrcPicture () with the draw and
        color parameters.
    • 
    
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 






    
void XftGlyphFontSpecRender (

    

        
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


        
This involves several steps:

    






    
    
  • First, Xft ensures that the glyphs array is complete using
        XftFontCheckGlyph() and loading any missing glyphs with
        XftFontLoadGlyphs().
    • 
    
  • Then Xft examines the glyphs to find the maximum Unicode value.
        That determines the encoding size, i.e., the width.
    • 
    
  • Then, for each glyph, Xft checks if its Unicode value is handled by
        the corresponding font. If not, the value is set to zero (0), to ignore
        it. While doing this, Xft also remembers which was the first font
        used, and computes the position at which each glyph will be drawn.
    • 
    
  • Xft then constructs an equivalent array of glyphs in the format
        expected by the X Render library.
    • 
    
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
        draw the glyphs, with the appropriate XRenderCompositeText*()
        function according to the width, and discards temporary data.
    • 




    

    
The op, dst, src, srcx, and srcy
        parameters are used as described in the documentation for the X Render
        library.

DESCRIPTION


These functions are used for drawing text and glyphs to an X server.
    They rely on the X Render Extension to do the actual drawing.


XftDrawCreate() creates a drawing context for the specified
    X server display dpy, drawable draw,
    and picture format format. The arguments clip_x
    and clip_y specify the initial clipping offset.


XftDrawDestroy() destroys the drawing context specified by
    draw.


XftDrawSetClip() sets the clipping region for the specified
    draw context to the region r.


XftDrawSetClipRects() sets the clipping region for the
    specified draw context to the list of rectangles
    rects. n_rects is the number of
    rectangles in the list. x_off and y_off
    specify an offset to be applied to the clipping rectangles.


XftDrawSetGlyphFont() sets the default font to be used for
    subsequent calls to XftDrawCharSpec().


XftDrawSetGlyphList() sets the default glyph list to be used
    for subsequent calls to XftDrawCharSpec().


XftDrawCharSpec() draws a list of characters specified by
    spec to the location (x,y).


XftDrawString() draws the specified string
    of length len using the specified font
    and color at the location (x,
    y).


XftDrawString16() is the same as XftDrawString() but
    takes a string of 16-bit characters.


XftDrawGlyphSpec() draws a list of glyphs specified by
    spec to the location (x,
    y).


XftDrawGlyphList() draws a list of glyphs specified by
    gl to the location (x,
    y).


XftDrawCharSpec8() draws a list of 8-bit characters specified
    by spec to the location (x,
    y).


XftDrawGlyphSpec8() draws a list of 8-bit glyphs specified by
    spec to the location (x,
    y).

void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory.
      Xft uses the Fontconfig pattern associated with the display
      dpy (e.g., via XftDefaultSet()) to determine whether to use
      a bounding box, clip the glyphs into those bounds, scale the glyphs,
      compute font metrics, and add it to the X Render extension using
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Discards data for up to nglyph glyphs whose glyph
        indices (Unicode values) are listed in the array glyphs for the
        given font pub. If the glyphs were added to the X Render
        extension, Xft removes those using XRenderFreeGlyphs().
        Xft keeps track of the amount of memory used for glyphs, and
        updates the usage associated with the display dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory
        representation of a given typeface in a given style) has been created
        for the pub font, create one using FT_New_Face().
        Face-locks are a reference count used by Xft to ensure that only
        one face is created, and that it is retained until the font is no longer
        used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few
      applications, such as Gdk/Gimp relied upon these functions. In version
      2.1.9 (June 2006), face-locking was retained as part of the public API
      when improved shared-library configurations provided for hiding private
      symbols.

Decrements the reference count for the FreeType 2
        “face” associated with the font.

COMPATIBILITY


As of version 2 (May 2002), Xft became relatively stable.
    It is expected to retain source and binary compatibility in future
  releases.


Xft provides a compatibility interface to its previous
    major version, Xft 1.x, described below.




Xft   1.x Header File


#include <X11/Xft/XftCompat.h>






Xft   1.x Data Types



  
XftPattern

  
holds a set of names with associated value lists; each name refers to a
      property of a font. XftPatterns are used as inputs to the matching
      code as well as holding information about specific fonts.

  
XftFontSet

  
contains a list of XftPatterns. Internally, Xft uses this
      data structure to hold sets of fonts. Externally, Xft returns the
      results of listing fonts in this format.

  
XftObjectSet

  
holds a set of names and is used to specify which fields from fonts are
      placed in the list of returned patterns when listing fonts.
