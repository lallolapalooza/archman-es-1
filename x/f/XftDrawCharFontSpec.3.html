NOMBRE

XftDrawCharFontSpec - Dibujar texto usando caracteres y una fuente especificada

SINTAXIS

#include <X11/Xft/Xft.h>

void XftDrawCharFontSpec(XftDraw *draw, int x, int y, XftFont *font, const XftCharSpec *specs);

DESCRIPCIÓN

La función XftDrawCharFontSpec dibuja texto en el objeto XftDraw especificado (draw) en las coordenadas (x, y) utilizando la fuente especificada (font) y las especificaciones de caracteres (specs). Cada entrada en specs contiene un punto de código Unicode y una estructura XftGlyphInfo que describe el glifo correspondiente. La longitud de la matriz specs se determina mediante el campo num de la estructura XftFont.

Este método de dibujo es útil cuando se trabaja con conjuntos de caracteres que no se asignan directamente a glifos o cuando se requiere un control explícito sobre qué glifo se utiliza para cada carácter.

Los caracteres se dibujan en el orden en que aparecen en la matriz specs. La posición del siguiente carácter se determina a partir del campo advance.x de la estructura XftGlyphInfo del carácter actual.

ARGUMENTOS

draw
Un puntero al objeto XftDraw en el que se dibujará el texto.
x
La coordenada x de la posición inicial del texto.
y
La coordenada y de la posición inicial del texto.
font
Un puntero a la estructura XftFont que se utilizará para dibujar. Debe ser una fuente válida y abierta.
specs
Un puntero a una matriz de estructuras XftCharSpec. Cada estructura contiene un punto de código Unicode y la información del glifo correspondiente.

MANUAL

This manual page describes the Xft library, which is a FreeType library designed for use with X.

SYNOPSIS

#include <Xft/Xft.h>

DESCRIPTION

The Xft library provides access to the FreeType rendering engine for drawing text using X. It uses the Fontconfig library for font matching and substitution. Xft supports antialiasing, subpixel rendering, and drawing directly to an X drawable using either the core X protocol or the X Rendering Extension.

The library provides functions for opening fonts, creating drawing contexts, rendering text, and querying font information. It also defines several data structures for representing font properties, glyphs, and drawing specifications.

DATA STRUCTURES

XftDraw

is an opaque object which holds information used to render to an X drawable using either the core protocol or the X Rendering extension.

XftDraw objects are created with any of XftDrawCreate() (which associates an XftDraw with an existing X drawable), XftDrawCreateBitmap(), or XftDrawCreateAlpha(), and destroyed with XftDrawDestroy(). The X drawable associated with an XftDraw can be changed with XftDrawChange(). XftDraw objects are internally allocated and freed by Xft; the programmer does not ordinarily need to allocate or free storage for them.

The X Display, Drawable, Colormap, and Visual properties of an XftDraw can be queried with XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), and XftDrawVisual(), respectively.

Several functions use XftDraw objects: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), and the XftDrawString*() family.

The X Rendering Extension Picture associated with an XftDraw is returned by XftDrawPicture(), and XftDrawSrcPicture(). It is used by XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), and the XftTextRender*() family.

FUNCTIONS

Initialization

A typical application using Xft does not explicitly initialize the library. That is usually done as a side-effect of opening a font.

When Xft initializes, it collects information about the display, and stores some of that information in a Fontconfig pattern (essentially a collection of properties with typed values). The calling application can modify that pattern to change the library's behavior.

Not all of the collected information is stored in a pattern. The remainder is stored in internal data structures. Xft makes some of that available to the application via functions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtain information about the display dpy if not done already, and return true if Xft found that the display supports the X Render extension, and if it is able to find a suitable XRenderPictFormat (X Render's datatype which is analogous to Xlib's Visual) on the display.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtain information about the display dpy if not done already, and set the Fontconfig pattern holding default properties which Xft will use for this display.

Xft uses those properties initially to obtain these limits:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). This is the maximum amount of glyph memory for all fonts used by Xft (default: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). This is the maximum number of unreferenced fonts (default: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). When true, Xft tracks usage of glyph memory to improve performance when deciding which to unload when the maximum amount of glyph memory is reached (default: false).
Xft also uses these default properties in XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft fills in missing properties in the given pattern using default properties for the specified display dpy, e.g., as set in XftDefaultSet().

Typical Xft applications use this function to help Fontconfig choose a suitable font. These properties are substituted before calling FcDefaultSubstitute():
FC_ANTIALIAS
True if FreeType should use antialiasing (default: False). (default: True).
FC_AUTOHINT
True if FreeType should use autohinting (default: False).
FC_DPI
Dots/inch used for resolution (default: computed from the display height).
FC_EMBOLDEN
True if FT_GlyphSlot_Embolden() should be used to embolden a font (default: False).
FC_HINTING

Opening   and Matching Fonts



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen takes a list of pattern element triples of
        the form field, type, value (terminated with a
        NULL), matches that pattern against the available fonts, and opens the
        matching font, sizing it correctly for screen number screen on
        display dpy. Return the matched font, or NULL if no match is
        found.

  




Example:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
This opens the “charter” font at 12 points. The point size
      is automatically converted to the correct pixel size based on the
      resolution of the monitor.

Determinación   de Extensión de Texto


Xft proporciona varias funciones para determinar la altura y
    anchura requeridas para mostrar una cadena de texto. Después de tener en
    cuenta el offset, en los casos en que la cadena se desplazará hacia
    arriba, hacia abajo, hacia la izquierda o hacia la derecha, estos números
    se denominan extensiones de texto.

        pantalla dpy de no más de len glifos de una cadena

Administración   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utiliza XAllocNamedColor() para buscar el color con
        nombre name para la pantalla asociada con el mapa de colores
        cmap.

  






    
  
  • Si XAllocNamedColor() devuelve un valor distinto de cero,
      XftColorAllocName() rellena el campo de píxel resultante de
      XftColor con el color más cercano soportado por la pantalla, así
      como los campos exactos de rojo, verde y azul de la base de datos, y
      devuelve True.
    • 
  
  • Si XAllocNamedColor() devuelve cero, XftColorAllocName()
      devuelve False y no actualiza el XftColor al que se hace referencia
      en result.
    • 






  

  
El parámetro visual no se utiliza.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Asigna un valor de color:

  






    
  
  • Si la clase visual es TrueColor, XftColorAllocValue()
      establece el campo pixel en el XftColor al que se hace
      referencia en result utilizando los campos rojo, verde y azul del
      parámetro color.
    • 
  
  • Si la clase visual no es TrueColor, XftColorAllocValue()
      llama a XAllocColor() para asignar una entrada en el mapa de
      colores cmap. que devuelve el valor de píxel del color más
      cercano a los elementos RGB especificados soportados por el hardware.
    • 




  

  
Si XAllocColor() tiene éxito, XftColorAllocValue() almacena
      ese valor de píxel en el XRenderColor al que se hace referencia en
      result y devuelve True.

  

  
Si XAllocColor() falla, XftColorAllocValue() devuelve False y
      no modifica el resultado.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Configura el recorte para el parámetro XftDraw
        proporcionado draw comenzando con una Region:

  






    
  
  • Si el parámetro Region r no es nulo, Xft crea una nueva
      Region (para copiar el parámetro),
    • 
  
  • Xft destruye cualquier región de recorte existente.
    • 
  
  • Xft establece el clip_type para el parámetro draw a
      XftClipTypeRegion si el parámetro r no era nulo. De lo
      contrario, establece el clip_type a XftClipTypeNone.
    • 
  
  • Finalmente, Xft actualiza el recorte para los objetos existentes,
      actualiza la máscara de recorte para su objeto Picture de X Render
      y establece la máscara de recorte en el contexto gráfico (GC) asociado con
      el parámetro XftDraw.
    • 






  

  
XftDrawSetClip() devuelve True si no fue necesario ningún
      cambio, o si la operación tuvo éxito. Devuelve False si no pudo
      crear la nueva Region().

        rectángulos (el parámetro rects) que podrían usarse para
        construir una Region.

void XftDrawSetSubwindowMode (

  

    
	XftDraw	*draw,
	int	 mode);


    
Establece el modo de subventana para el parámetro XftDraw
        proporcionado draw. El modo puede ser ClipByChildren (el
        predeterminado) o IncludeInferiors:

  






    
  
  • Para ClipByChildren, tanto la ventana de origen como la de destino se
      recortan adicionalmente por todos los hijos visibles de tipo
      InputOutput.
    • 
  
  • Para IncludeInferiors, ni la ventana de origen ni la de destino se
      recortan por los inferiores. Esto dará como resultado la inclusión del
      contenido de la subventana en el origen y el dibujo a través de los
      límites de la subventana de destino.
    • 






  

  
Además del modo de subventana mantenido por Xft, actualiza el modo de
      subventana para cualquier contexto gráfico (GC) asociado utilizando
      XSetSubwindowMode(), así como para una Picture de X Render
      usando XRenderChangePicture().

	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftCharFontSpec	*chars,
	int	 len);


    
XftCharFontSpecRender() convierte el parámetro
        chars de XftCharFontSpec a XftGlyphFontSpec,
        pasando el array convertido junto con los otros parámetros sin cambios
        a XftGlyphFontSpecRender() para renderizar los datos.

  

  
void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Dibuja una lista de glifos asociados con fuentes en coordenadas
        especificadas, pasados como un array de len estructuras
        XftGlyphFontSpec a través del parámetro glyphs. Todos los
        glifos se dibujan usando el color especificado en el parámetro
        color.

  





  

  
Para cada entrada en el array glyphs:






    
  
  • Si la fuente asociada usa la extensión X Render, entonces Xft usa
      XftGlyphFontSpecRender() para dibujar el glifo, usando una
      Picture obtenida al llamar a XftDrawSrcPicture() con los
      parámetros draw y color.
    • 
  
  • De lo contrario, Xft proporciona una característica análoga usando
      Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Esto implica varios pasos:

  






    
  
  • Primero, Xft se asegura de que el array glyphs esté completo
      usando XftFontCheckGlyph() y cargando cualquier glifo faltante con
      XftFontLoadGlyphs().
    • 
  
  • Luego Xft examina los glifos para encontrar el valor Unicode máximo.
      Eso determina el tamaño de la codificación, es decir, el width.
    • 
  
  • Luego, para cada glifo, Xft verifica si su valor Unicode es manejado
      por la fuente correspondiente. Si no, el valor se establece en cero (0),
      para ignorarlo. Mientras hace esto, Xft también recuerda cuál fue
      la primera fuente utilizada y calcula la posición en la que se dibujará
      cada glifo.
    • 
  
  • Xft luego construye un array equivalente de glifos en el formato
      esperado por la biblioteca X Render.
    • 
  
  • Finalmente, XftGlyphFontSpecRender() utiliza la extensión X Render
      para dibujar los glifos, con la función apropiada XRenderCompositeText*()
      según el width, y descarta los datos temporales.
    • 




  

  
Los parámetros op, dst, src, srcx y srcy
      se usan como se describe en la documentación de la biblioteca X Render.

Xft usa Fontconfig para analizar el nombre, pasando

FcBool XftNameUnparse (

  

    
	FcPattern	*pat,
	char	*dest,
	int	 len);


    
Al igual que XfgNameParse(), Xft usa Fontconfig.
        En este caso, utiliza FcNameUnparse(), que convierte el patrón
        pat de nuevo en una cadena que se puede analizar.
        XftNameUnparse() almacena el resultado a través del puntero del
        llamador dest, pero comprueba primero si cabe, utilizando el
        parámetro len. Si cabe, Xft copia la cadena y devuelve
        FcTrue, de lo contrario, devuelve FcFalse.

  








Manipulando   datos de fuentes



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Usando FT_Load_Glyph(), carga nglyphs para los
        índices de glifos (valores Unicode) listados en el array glyphs
        de la fuente dada pub.

  





  

  
Cargar un glifo implica más que solo leer datos en memoria.
      Xft utiliza el patrón Fontconfig asociado con la pantalla
      dpy (por ejemplo, a través de XftDefaultSet()) para
      determinar si usar un cuadro delimitador, recortar los glifos dentro de
      esos límites, escalar los glifos, calcular métricas de la fuente y
      añadirla a la extensión X Render usando
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Descarta datos de hasta nglyph glifos cuyos índices
        de glifos (valores Unicode) están listados en el array glyphs
        para la fuente dada pub. Si los glifos se añadieron a la
        extensión X Render, Xft los elimina usando
        XRenderFreeGlyphs(). Xft lleva un registro de la
        cantidad de memoria utilizada para los glifos y actualiza el uso
        asociado con la pantalla dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si no se ha creado ninguna cara de FreeType 2 ("face")
        (representación en memoria de una tipografía dada en un estilo
        dado) para la fuente pub, créela usando
        FT_New_Face(). Los bloqueos de cara ("face-locks") son un
        contador de referencias utilizado por Xft para asegurar que
        solo se cree una cara y que se mantenga hasta que la fuente ya no se
        utilice.

  





  

  
El bloqueo de cara se utiliza directamente en
      XftCharIndex() y XftFontLoadGlyphs(), que a su vez se
      utilizan en muchas funciones de Xft.

  

  
El bloqueo de cara se introdujo en la versión 1 (octubre de 2002).
      Algunas aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la
      versión 2.1.9 (junio de 2006), se conservó el bloqueo de cara como parte
      de la API pública cuando las configuraciones mejoradas de bibliotecas
      compartidas proporcionaron la ocultación de símbolos privados.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrementa el contador de referencias para la "cara" de
        FreeType 2 asociada con la fuente.

  





  

  
Los objetos FT_Face se desasignan usando
      FT_Done_Face(). Xft hace esto en
      XftFontInfoDestroy() y al limpiar en caso de fallo en
      XftFontInfoCreate() y XftFontOpenPattern().









DEPURACIÓN


Xft lee la variable de entorno XFT_DEBUG y la
    convierte a un entero. Cada bit en el valor resultante indica a Xft
    que imprima información de depuración en la salida estándar:



  
1

  
apertura de fuente

  
2

  
coincidencia y apertura adicional de fuentes (verboso)

  
4

  
muestra detalles sobre el XRenderPictFormat que se utilizará.

  
8

  
muestra la cadena que XftDrawString8() dibujará.

  
16

  
muestra qué ids de fuente coinciden.

  
32

  
muestra información útil sobre los glifos que se dibujarán

  
64

  
muestra una representación en arte ASCII de los glifos.

  
128

  
muestra detalles sobre la gestión de la caché de memoria

  
256

  
muestra detalles sobre la gestión de la memoria de glifos en caché

  
512

  
muestra un informe sobre el uso de memoria

  
1024

  
muestra detalles sobre la gestión extendida de la memoria de glifos en
      caché








COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió
    relativamente estable. Se espera que mantenga la compatibilidad de código
    fuente y binaria en futuras versiones.


Xft proporciona una interfaz de compatibilidad con su
    versión principal anterior, Xft 1.x, descrita a continuación.




Archivo   de encabezado de Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos   de datos de Xft 1.x



  
XftPattern

  
almacena un conjunto de nombres con listas de valores asociados; cada nombre
      se refiere a una propiedad de una fuente. Los XftPattern se
      utilizan como entradas para el código de coincidencia, así como para
      almacenar información sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPattern. Internamente, Xft utiliza
      esta estructura de datos para almacenar conjuntos de fuentes.
      Externamente, Xft devuelve los resultados de listar fuentes en
      este formato.

  
XftObjectSet

  
almacena un conjunto de nombres y se utiliza para especificar qué campos
      de las fuentes se colocan en la lista de patrones devueltos al listar
      fuentes.
