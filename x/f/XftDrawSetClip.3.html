NOMBRE

Xft - Biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("La versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - Interfaz de Lenguaje C.

Xft utiliza estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada con una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa mediante la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de cabecera para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft utiliza estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc”, que se documentan en Fontconfig Developers Reference.

Xft utiliza estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_”, que se documentan en FreeType API Reference.

Xft utiliza estos nombres: FT_Face, FT_Library, y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar *glifos*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que utilizan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFonts se popularizan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto en un objeto XftDraw, que puede corresponder tanto a un drawable X principal como a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont que corresponde a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede obtener con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana que ofrezca el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color al servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() instruye al servidor X para que libere el color actualmente asignado a un XftColor.

Una vez que se ha inicializado un XftColor, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), y XftDrawRect() pueden usarse para dibujar varios objetos utilizando este.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar en un drawable de X usando el protocolo central o la extensión de Renderizado de X.

Los objetos XftDraw se crean con XftDrawCreate() (que asocia un XftDraw con un drawable de X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable de X asociado con un XftDraw puede cambiarse con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar memoria para ellos.

Las propiedades de X Display, Drawable, Colormap, y Visual de un XftDraw pueden consultarse con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia de XftDrawString*().

La extensión de Renderizado de X Picture asociada con un XftDraw se devuelve mediante XftDrawPicture(), y XftDrawSrcPicture(). Se utiliza por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia de XftTextRender*().

FUNCIONES

InicializaciÃ³n

Una aplicación típica que utiliza Xft no inicializa explícitamente la biblioteca. Eso generalmente se hace como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón de Fontconfig (esencialmente una colección de propiedades con valores tipificados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft determinó que la pantalla admite la extensión de Renderizado de X, y si puede encontrar un XRenderPictFormat adecuado (el tipo de dato de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón de Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esa pantalla.

Xft utiliza estas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft completa las propiedades faltantes en el pattern dado utilizando propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar antialiasing (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para ennegrecer una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al completar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al completar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla admite la extensión de Renderizado de X (predeterminado: resultado de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Inicializa la biblioteca Fontconfig (llamando a FcInit()).

El parámetro config no se utiliza.

Abrir   y emparejar fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triadas de elementos de patrón
        del formulario campo, tipo, valor (terminado con NULL),
        empareja ese patrón contra las fuentes disponibles, y abre la fuente
        emparejada, dimensionándola correctamente para la pantalla número
        screen en la pantalla dpy. Devuelve la fuente emparejada, o NULL
        si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);






  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño de punto se convierte
      automáticamente al tamaño de píxel correcto en función de la resolución del
      monitor.

XftXlfdParse analiza el parámetro xlfd_orig

de foundry.

Determinación   de Extents de Texto


Xft proporciona varias funciones para determinar la altura y
    anchura necesarias para mostrar una cadena de texto. Después de tener en
    cuenta el offset, en los casos en que la cadena se desplazará hacia
    arriba, hacia abajo, hacia la izquierda o hacia la derecha, estos números
    se denominan extents de texto.

Gestión   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utiliza XAllocNamedColor() para buscar el color con
        nombre name para la pantalla asociada con el mapa de colores
        cmap.

  






    
  
  • Si XAllocNamedColor() devuelve un valor distinto de cero,
      XftColorAllocName() rellena el campo de píxel de XftColor
      resultante con el color más cercano admitido por la pantalla, así como
      los campos exactos de rojo, verde y azul de la base de datos, y devuelve
      True.
    • 
  
  • Si XAllocNamedColor() devuelve cero, XftColorAllocName()
      devuelve False y no actualiza el XftColor referenciado por
      result.
    • 






  

  
El parámetro visual no se utiliza.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Asigna un valor de color:

  






    
  
  • Si la clase visual es TrueColor, XftColorAllocValue()
      establece el campo pixel en el XftColor referenciado por
      result utilizando los campos rojo, verde y azul del parámetro
      color.
    • 
  
  • Si la clase visual no es TrueColor, XftColorAllocValue()
      llama a XAllocColor() para asignar una entrada en el mapa de
      colores cmap. que devuelve el valor de píxel del color más
      cercano a los elementos RGB especificados que admite el hardware.
    • 




  

  
Si XAllocColor() tiene éxito, XftColorAllocValue() almacena
      ese valor de píxel en el XRenderColor referenciado por result
      y devuelve True.

  

  
Si XAllocColor() falla, XftColorAllocValue() devuelve False
      y no modifica el resultado.

DESCRIPTION
       An XftDraw object describes how to render glyphs, such as with
       XftFontGlyph. It holds a reference to an X drawable, a colormap, and a
       visual.

       XftDrawCreate() creates an XftDraw object for the specified X
       drawable, visual and colormap. If the X server does not support the X
       Rendering Extension, then the Picture returned by XftDrawPicture()
       will be zero.

       XftDrawCreateBitmap() behaves like XftDrawCreate(), except that it
       uses an X pixmap of color depth 1 instead of an X drawable.

       XftDrawCreateAlpha() behaves like XftDrawCreate(), except that it
       uses an X pixmap of color depth depth instead of an X drawable.

       XftDrawChange() changes the X drawable association of the existing Xft
       draw object draw from its current value to drawable.

       XftDrawDisplay() returns a pointer to the display associated with the
       Xft draw object draw.

       XftDrawDrawable() returns the X drawable associated with the Xft draw
       object draw.

       XftDrawColormap() returns the colormap associated with the Xft draw
       object draw.

       XftDrawVisual() returns a pointer to the visual associated with the Xft
       draw object draw.

       XftDrawPicture() returns the picture associated with the Xft draw
       object draw. If the X server does not support the X Rendering Extension,
       0 is returned.

       XftDrawSrcPicture() returns an X Render Picture object, which is used
       for rendering glyphs, e.g., with XftGlyphRender(),
       XftGlyphSpecRender(), or XftGlyphFontSpecRender(), by
       XftDrawGlyphs(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(),
       respectively. If the X server does not support the X Render extension,
       those functions use XftGlyphCore(), XftGlyphSpecCore(), or
       XftGlyphFontSpecCore().

       XftDrawDestroy() destroys draw (created by one of the
       XftDrawCreate*() functions) and frees the memory that was allocated
       for it.

       XftDrawSetClip() sets up clipping for the given XftDraw parameter
       draw starting with a Region:
	   * If the Region parameter r is not null, Xft creates a new
	     Region (to copy the parameter),
	   * Xft destroys any existing clipping region.
	   * Xft sets the clip_type for the draw parameter to
	     XftClipTypeRegion if the r parameter was not null. Otherwise
	     it sets the clip_type to XftClipTypeNone.
	   * Finally, Xft updates clipping for existing objects, updates the
	     clip_mask for its X Render Picture object and sets the
	     clipping-mask in the graphic context (GC) associated with the
	     XftDraw parameter.
       XftDrawSetClip() returns True if no change was necessary, or if the
       operation succeeded. It returns False if it was unable to create the
       new Region().

       XftDrawSetClipRectangles() is like XftDrawSetClip(), but uses a set
       of n rectangles (the rects parameter) which could be used to
       construct a Region.
       Xft sets the clip_type for draw to XftClipTypeRectangles and uses
       XSetClipRectangles() for core (X11) clipping and
       XRenderSetPictureClipRectangles() for X Render clipping.

       XftDrawSetSubwindowMode() sets the subwindow-mode for the given XftDraw
       parameter draw. The mode can be either ClipByChildren (the default),
       or IncludeInferiors:
	   * For ClipByChildren, both source and destination windows are
	     additionally clipped by all viewable InputOutput children.
	   * For IncludeInferiors, neither source nor destination window is
	     clipped by inferiors. This will result in including subwindow
	     contents in the source and drawing through subwindow boundaries of
	     the destination.
       In addition to the subwindow-mode maintained by Xft, it updates the
       subwindow mode for any associated graphics context GC using
       XSetSubwindowMode() as well as for an X Render Picture using
       XRenderChangePicture().

Drawing Strings
       XftDrawString8() draws no more than len glyphs of string to
       Xft drawable d using font in color at position x, y.

Drawing Other Things
       XftDrawRect() draws a solid rectangle of the specified color,
       width, and height at position x, y to Xft drawable
       d.

       XftCharFontSpecRender() converts the chars parameter from
       XftCharFontSpec to XftGlyphFontSpec, passing the converted array
       along with the other parameters unchanged to XftGlyphFontSpecRender()
       to render the data.

       XftDrawGlyphFontSpec() draws a list of glyphs associated with fonts at
       specified coordinates, passed as an array of len
       XftGlyphFontSpec structures via the parameter glyphs. All of the
       glyphs are drawn using the color specified in the color parameter.

       For each entry in the glyphs array:
	   * If the associated font uses the X Render extension, then Xft
	     uses XftGlyphFontSpecRender() to draw the glyph, using a
	     Picture obtained from calling XftDrawSrcPicture() with the
	     draw and color parameters.
	   * Otherwise, Xft provides an analogous feature using Xlib.

       XftGlyphFontSpecRender() involves several steps:
	   * First, Xft ensures that the glyphs array is complete using
	     XftFontCheckGlyph() and loading any missing glyphs with
	     XftFontLoadGlyphs().
	   * Then Xft examines the glyphs to find the maximum Unicode value.
	     That determines the encoding size, i.e., the width.
	   * Then, for each glyph, Xft checks if its Unicode value is handled by
	     the corresponding font. If not, the value is set to zero (0), to
	     ignore it. While doing this, Xft also remembers which was the
	     first font used, and computes the position at which each glyph will
	     be drawn.
	   * Xft then constructs an equivalent array of glyphs in the format
	     expected by the X Render library.
	   * Finally, XftGlyphFontSpecRender() uses the X Render extension to
	     draw the glyphs, with the appropriate XRenderCompositeText*()
	     function according to the width, and discards temporary data.
       The op, dst, src, srcx, and srcy parameters are used as
       described in the documentation for the X Render library.

Manipulating patterns
       XftListFonts() uses FcPatternVapBuild() and
       FcObjectSetVapBuild() to process the variable-length parameter list,
       and FcFontList() to obtain a list of matching Fontconfig patterns,
       which it returns to the caller. The caller can dispose of the return
       value using FcPatternDestroy().

       XftNameParse() parses a font name string, returning a FcPattern
       representing the font. This function is a wrapper around
       FcNameParse().

DESCRIPCIÓN


Estas funciones manipulan datos de fuentes y patrones de fuentes. El
    nombre y los patrones se utilizan para encontrar fuentes, y los datos de las
    fuentes se cargan y se descargan según sea necesario.




Manipulación de nombres



  
FcPattern *XftNameParse (

  

    
	_Xconst char	*name);


    
Xft usa Fontconfig para analizar el nombre, pasando el
        name a FcNameParse(), y devuelve el resultado.

  

  
FcBool XftNameUnparse (

  

    
	FcPattern	*pat,
	char	*dest,
	int	 len);


    
Al igual que XfgNameParse(), Xft usa Fontconfig. En
        este caso, utiliza FcNameUnparse(), que convierte el patrón
        pat de nuevo en una cadena que se puede analizar.
        XftNameUnparse() almacena el resultado a través del puntero del
        llamador dest, pero comprueba primero si cabe, utilizando el
        parámetro len. Si cabe, Xft copia la cadena y devuelve
        FcTrue, de lo contrario devuelve FcFalse.

  








Manipulación de datos de fuentes



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Usando FT_Load_Glyph(), carga nglyphs para los
        índices de glifo (valores Unicode) listados en el array glyphs de
        la fuente dada pub.

  





  

  
La carga de un glifo implica más que solo leer datos en la memoria.
      Xft usa el patrón de Fontconfig asociado con la pantalla
      dpy (por ejemplo, a través de XftDefaultSet()) para
      determinar si usar un cuadro delimitador, recortar los glifos a esos
      límites, escalar los glifos, calcular las métricas de la fuente y
      añadirlo a la extensión X Render usando XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Descarta datos para hasta nglyph glifos cuyos índices
        de glifo (valores Unicode) están listados en el array glyphs para
        la fuente dada pub. Si los glifos se agregaron a la extensión X
        Render, Xft los elimina usando XRenderFreeGlyphs().
        Xft rastrea la cantidad de memoria utilizada para los glifos y
        actualiza el uso asociado con la pantalla dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si no se ha creado ninguna "cara" de FreeType 2
        (representación en memoria de un tipo de letra dado en un estilo dado)
        para la fuente pub, créela usando FT_New_Face().
        Los bloqueos de cara son un contador de referencias utilizado por
        Xft para garantizar que solo se cree una cara y que se conserve
        hasta que la fuente ya no se utilice.

  





  

  
El bloqueo de cara se utiliza directamente en XftCharIndex() y
      XftFontLoadGlyphs(), que a su vez se utilizan en muchas funciones de
      Xft.

  

  
El bloqueo de cara se introdujo en la versión 1 (octubre de 2002). Algunas
      aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la versión
      2.1.9 (junio de 2006), se conservó el bloqueo de cara como parte de la API
      pública cuando las configuraciones mejoradas de bibliotecas compartidas
      permitieron ocultar los símbolos privados.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrementa el contador de referencias para la "cara" de
        FreeType 2 asociada con la fuente.

  





  

  
Los objetos FT_Face se desasignan usando FT_Done_Face().
      Xft lo hace en XftFontInfoDestroy() y al limpiar en caso de
      fallo en XftFontInfoCreate() y
      XftFontOpenPattern().










DEPURACIÓN


Xft lee la variable de entorno XFT_DEBUG y la
    convierte en un entero. Cada bit en el valor resultante indica a
    Xft que imprima información de depuración en la salida estándar:



  
1

  
apertura de fuentes

  
2

  
coincidencia y apertura adicional de fuentes (verboso)

  
4

  
muestra detalles sobre XRenderPictFormat que se utilizará.

  
8

  
muestra la cadena que XftDrawString8() dibujará.

  
16

  
muestra qué ids de fuente coinciden.

  
32

  
muestra información útil sobre los glifos que se dibujarán

  
64

  
muestra una representación de arte ASCII de los glifos.

  
128

  
muestra detalles sobre la gestión de la caché de memoria

  
256

  
muestra detalles sobre la gestión de la memoria caché de glifos

  
512

  
muestra un informe sobre el uso de memoria

  
1024

  
muestra detalles sobre la gestión extendida de la memoria caché de
      glifos








COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió
    relativamente estable. Se espera que mantenga la compatibilidad de código
    fuente y binaria en futuras versiones.


Xft proporciona una interfaz de compatibilidad con su
    versión principal anterior, Xft 1.x, descrita a continuación.




Archivo de cabecera Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de datos Xft 1.x



  
XftPattern

  
contiene un conjunto de nombres con listas de valores asociadas; cada nombre
      se refiere a una propiedad de una fuente. Los XftPatterns se usan
      como entradas para el código de coincidencia y también contienen información
      sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPatterns. Internamente, Xft usa esta
      estructura de datos para mantener conjuntos de fuentes. Externamente,
      Xft devuelve los resultados de listar fuentes en este formato.

  
XftObjectSet

  
contiene un conjunto de nombres y se utiliza para especificar qué campos
      de las fuentes se colocan en la lista de patrones devueltos al listar
      fuentes.
