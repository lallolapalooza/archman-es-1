NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca sencilla que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte los glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuente convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("Versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con "Xft"

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Se documentan en Xlib - C Language Interface.

Xft usa estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada a una pantalla. Tanto las ventanas como los pixmaps pueden usarse como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de tipo InputOnly no puede usarse como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una Region es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una Region se representa como la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica la extensión de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre el mapeo de colores posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de encabezado para obtener más detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft usa estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con "Fc", que se documentan en Fontconfig Developers Reference.

Xft usa estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con "FT_", que se documentan en FreeType API Reference.

Xft usa estos nombres: FT_Face, FT_Library, y FT_UInt.

FreeType 2 utiliza FT_UInt (un entero sin signo) para representar *glifos*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont es la estructura de datos principal de interés para los programadores que usan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres y al patrón de Fontconfig asociados con la fuente.

Los XftFonts se pueblan con cualquiera de las funciones XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), o XftFontOpenPattern(). XftFontCopy() se utiliza para duplicar XftFonts, y XftFontClose() se utiliza para marcar un XftFont como no utilizado. Los XftFonts son asignados internamente, contados por referencia y liberados por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() utilizan XftFonts para renderizar texto en un objeto XftDraw, que puede corresponder a un drawable X principal o a un drawable de la Extensión de Renderizado X.

XftGlyphExtents() y la familia XftTextExtents*() se utilizan para determinar las extensiones (dimensiones máximas) de un XftFont.

La cobertura de glifos o caracteres de un XftFont se puede determinar con XftFontCheckGlyph() o XftCharExists(). XftCharIndex() devuelve el índice de carácter específico de XftFont correspondiente a un punto de código Unicode dado.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), y la familia XftTextRender*() utilizan XftFonts para dibujar en estructuras Picture de la Extensión de Renderizado X.

Nota: XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), y XftDrawGlyphSpec() proporcionan un medio para renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras XftFontInfo se crean con XftFontInfoCreate(), se liberan con XftFontInfoDestroy(), y se comparan con XftFontInfoEqual(). Los objetos XftFontInfo son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar almacenamiento para ellos.

Cada estructura XftFontInfo en uso está asociada con un identificador único, que se puede recuperar con XftFontInfoHash(). Se puede abrir un XftFont basándose en los datos de XftFontInfo con XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto XftColor permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

XftColorAllocName() y XftColorAllocValue() solicitan una asignación de color al servidor X (si es necesario) e inicializan los miembros de XftColor. XftColorFree() indica al servidor X que libere el color actualmente asignado para un XftColor.

Una vez que un XftColor ha sido inicializado, XftDrawSrcPicture(), XftDrawGlyphs(), la familia XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), y XftDrawRect() pueden usarse para dibujar varios objetos utilizando dicho color.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable de X utilizando el protocolo principal o la extensión X Rendering.

Los objetos XftDraw se crean con cualquiera de XftDrawCreate() (que asocia un XftDraw con un drawable X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable X asociado con un XftDraw se puede cambiar con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar o liberar memoria para ellos.

Las propiedades Display, Drawable, Colormap, y Visual de X de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

La extensión X Rendering Picture asociada con un XftDraw se devuelve con XftDrawPicture(), y XftDrawSrcPicture(). Se utiliza por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

InicializaciÃ³n

Una aplicación típica que utiliza Xft no inicializa explícitamente la biblioteca. Esto se hace generalmente como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla, y almacena parte de esa información en un patrón Fontconfig (esencialmente una colección de propiedades con valores tipificados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft encontró que la pantalla admite la extensión X Render, y si puede encontrar un XRenderPictFormat adecuado (el tipo de datos de X Render que es análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón Fontconfig que contiene las propiedades predeterminadas que Xft utilizará para esta pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (predeterminado: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (predeterminado: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (predeterminado: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft rellena las propiedades faltantes en el pattern dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar anti-aliasing (predeterminado: Falso). (predeterminado: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (predeterminado: Falso).
FC_DPI
Puntos/pulgada utilizados para la resolución (predeterminado: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para poner en negrita una fuente (predeterminado: Falso).
FC_HINTING
Verdadero si se debe usar hinting al rellenar propiedades para abrir una fuente (predeterminado: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al rellenar propiedades para abrir una fuente (predeterminado: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (predeterminado: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al rellenar propiedades para abrir una fuente (predeterminado: Falso).
FC_RGBA
Valor RGBA utilizado al rellenar propiedades para abrir una fuente (predeterminado: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (predeterminado: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (predeterminado: 1024*1024).
XFT_RENDER
Verdadero si la pantalla admite la extensión X Render (predeterminado: resultado de XftDefaultHasRender()).

Abrir y Emparejar Fuentes



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de triples de elementos de patrón
        del tipo campo, tipo, valor (terminado con un NULL),
        empareja ese patrón con las fuentes disponibles, y abre la fuente
        emparejada, dimensionándola correctamente para el número de pantalla
        screen en la pantalla dpy. Devuelve la fuente emparejada, o
        NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);






  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño en puntos se convierte
      automáticamente al tamaño de píxel correcto basándose en la resolución del
      monitor.

Determining Text Extents


Xft provides several functions for determining the required
    height and width for displaying a text-string. After accounting for the
    offset, in cases where the string will be shifted up, down, left or
    right, these numbers are referred to as text extents.

Managing XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Use XAllocNamedColor() to look up the named color
        name for the screen associated with the colormap cmap.

  






    
  
  • If XAllocNamedColor() returns nonzero, XftColorAllocName()
      fills in the resulting XftColor pixel field with the closest color
      supported by the screen, as well as the exact red, green and blue fields
      from the database, and returns True.
    • 
  
  • If XAllocNamedColor() returns zero, XftColorAllocName()
      returns False, and does not update the XftColor referenced by
      result.
    • 






  

  
The visual parameter is unused.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Allocate a color value:

  






    
  
  • If the visual class is TrueColor, XftColorAllocValue() sets
      the pixel field in the XftColor referenced by result
      using the red, green and blue fields from the color parameter.
    • 
  
  • If the visual class is not TrueColor, XftColorAllocValue()
      calls XAllocColor() to allocate an entry in the colormap
      cmap. which returns the pixel value of the color closest to the
      specified RGB elements supported by the hardware.
    • 




  

  
If XAllocColor() succeeds XftColorAllocValue() stores that
      pixel value in the XRenderColor referenced by result and
      returns True.

  

  
If XAllocColor() fails, XftColorAllocValue() returns False
      and does not modify the result.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    Configura el recorte para el parámetro XftDraw dado draw
        comenzando con una Region:







    
  
  • Si el parámetro Region r no es nulo, Xft crea una
      nueva Region (para copiar el parámetro),
    • 
  
  • Xft destruye cualquier región de recorte existente.
    • 
  
  • Xft establece el tipo de recorte (clip_type) para el parámetro
      draw a XftClipTypeRegion si el parámetro r no era
      nulo. De lo contrario, establece el tipo de recorte a
      XftClipTypeNone.
    • 
  
  • Finalmente, Xft actualiza el recorte para los objetos existentes,
      actualiza la máscara de recorte (clip_mask) para su objeto de imagen de
      Renderizado X y establece la máscara de recorte en el contexto gráfico
      (GC) asociado con el parámetro XftDraw.
    • 






  

  
XftDrawSetClip() devuelve True si no fue necesario ningún
      cambio, o si la operación tuvo éxito. Devuelve False si no pudo
      crear la nueva Region().

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    Dibuja una lista de glifos asociados con fuentes en coordenadas especificadas,
        pasada como un array de len estructuras XftGlyphFontSpec
        a través del parámetro glyphs. Todos los glifos se dibujan usando
        el color especificado en el parámetro color.






  

  
Para cada entrada en el array glyphs:
  






    
  
  • Si la fuente asociada utiliza la extensión de Renderizado X, entonces
      Xft utiliza XftGlyphFontSpecRender() para dibujar el glifo,
      utilizando una Picture obtenida al llamar a XftDrawSrcPicture()
      con los parámetros draw y color.
    • 
  
  • De lo contrario, Xft proporciona una característica análoga usando

    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    Esto implica varios pasos:
  






    
  
  • Primero, Xft asegura que el array glyphs esté completo usando
      XftFontCheckGlyph() y cargando cualquier glifo faltante con
      XftFontLoadGlyphs().
    • 
  
  • Luego Xft examina los glifos para encontrar el valor Unicode
      máximo. Eso determina el tamaño de codificación, es decir, el
      width.
    • 
  
  • Luego, para cada glifo, Xft verifica si su valor Unicode es manejado
      por la fuente correspondiente. Si no, el valor se establece en cero (0),
      para ignorarlo. Mientras hace esto, Xft también recuerda cuál fue
      la primera fuente utilizada, y calcula la posición en la que se dibujará
      cada glifo.
    • 
  
  • Xft luego construye un array equivalente de glifos en el formato
      esperado por la biblioteca de Renderizado X.
    • 
  
  • Finalmente, XftGlyphFontSpecRender() utiliza la extensión de
      Renderizado X para dibujar los glifos, con la función apropiada
      XRenderCompositeText*() de acuerdo con el width, y descarta
      los datos temporales.
    • 




  

  
Los parámetros op, dst, src, srcx, y
      srcy se utilizan como se describe en la documentación de la
      biblioteca de Renderizado X.

DESCRIPCIÓN


La biblioteca Xft proporciona una interfaz a Fontconfig para
    las aplicaciones Xft. La mayoría de las funciones de Xft usan
    Fontconfig para realizar la mayor parte del trabajo de selección, carga y
    renderizado de fuentes.


Las siguientes funciones proporcionan el puente entre el
    código de aplicación y Fontconfig.




Parseando Nombres de Fuentes



  
FcBool XftNameParse (

  

    
	const char	*name,
	FcPattern	**pat);


    
Xft utiliza Fontconfig para analizar el nombre, pasando
        el argumento name a FcNameParse(), devolviendo el
        resultado.

  

  
FcBool XftNameUnparse (

  

    
	FcPattern	*pat,
	char	*dest,
	int	 len);


    
Al igual que XfgNameParse(), Xft utiliza
        Fontconfig. En este caso, utiliza FcNameUnparse(), que convierte
        el patrón pat de nuevo a una cadena que se puede analizar.
        XftNameUnparse() almacena el resultado a través del puntero del
        llamador dest, pero primero comprueba si cabe, utilizando el
        parámetro len. Si cabe, Xft copia la cadena y devuelve
        FcTrue, de lo contrario devuelve FcFalse.

  








Manipulando datos de fuentes



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Utilizando FT_Load_Glyph(), carga nglyphs para
        los índices de glifos (valores Unicode) listados en el array
        glyphs de la fuente dada pub.

  





  

  
La carga de un glifo implica más que simplemente leer datos en memoria.
      Xft utiliza el patrón de Fontconfig asociado a la pantalla
      dpy (por ejemplo, a través de XftDefaultSet()) para
      determinar si se debe utilizar un cuadro delimitador, recortar los glifos
      dentro de esos límites, escalar los glifos, calcular métricas de la fuente
      y añadirlo a la extensión X Render utilizando
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Descarta datos para hasta nglyph glifos cuyos índices
        de glifos (valores Unicode) están listados en el array glyphs
        para la fuente dada pub. Si los glifos se agregaron a la
        extensión X Render, Xft los elimina utilizando
        XRenderFreeGlyphs(). Xft realiza un seguimiento de la
        cantidad de memoria utilizada para los glifos y actualiza el uso
        asociado a la pantalla dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si no se ha creado ninguna "cara" de FreeType 2 (representación
        en memoria de una tipografía dada en un estilo dado) para la fuente
        pub, se crea una utilizando FT_New_Face(). Los bloqueos
        de cara son un contador de referencias utilizado por Xft para
        asegurar que solo se crea una cara y que se conserva hasta que la fuente
        ya no se utiliza.

  





  

  
El bloqueo de cara se utiliza directamente en XftCharIndex() y
      XftFontLoadGlyphs(), que a su vez se utilizan en muchas funciones
      de Xft.

  

  
El bloqueo de cara se introdujo en la versión 1 (octubre de 2002).
      Algunas aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la
      versión 2.1.9 (junio de 2006), el bloqueo de cara se conservó como parte
      de la API pública cuando las configuraciones mejoradas de bibliotecas
      compartidas permitieron ocultar los símbolos privados.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrementa el contador de referencias para la "cara" de
        FreeType 2 asociada con la fuente.

  





  

  
Los objetos FT_Face se desasignan utilizando FT_Done_Face().
      Xft lo hace en XftFontInfoDestroy() y al limpiar en caso de
      fallo en XftFontInfoCreate() y XftFontOpenPattern().

COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió
    relativamente estable. Se espera que mantenga la compatibilidad de origen y
    binaria en futuras versiones.


Xft proporciona una interfaz de compatibilidad con su
    versión principal anterior, Xft 1.x, descrita a continuación.




Archivo de Encabezado Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de Datos Xft 1.x



  
XftPattern

  
contiene un conjunto de nombres con listas de valores asociadas; cada
      nombre se refiere a una propiedad de una fuente. Los XftPattern se
      utilizan como entrada para el código de coincidencia, así como para
      contener información sobre fuentes específicas.

  
XftFontSet

  
contiene una lista de XftPatterns. Internamente, Xft utiliza
      esta estructura de datos para mantener conjuntos de fuentes. Externamente,
      Xft devuelve los resultados de listar fuentes en este formato.

  
XftObjectSet

  
contiene un conjunto de nombres y se utiliza para especificar qué campos
      de las fuentes se incluyen en la lista de patrones devueltos al listar
      fuentes.
