NOMBRE

Xft - biblioteca de interfaz X FreeType

SINOPSIS

#include <X11/Xft/Xft.h>

DESCRIPCIÓN

Xft es una biblioteca simple que dibuja texto y gráficos:

  • utilizando información proporcionada por la biblioteca Fontconfig,
  • Xft convierte glifos de fuentes utilizando el rasterizador FreeType, y
  • muestra los datos de fuentes convertidos utilizando la Extensión de Renderizado X.

Esta página del manual apenas rasca la superficie de esta biblioteca.

CONSTANTES

XFT_MAJOR
es el número de versión principal de Xft.
XFT_MINOR
es el número de versión menor de Xft.
XFT_REVISION
es el número de revisión de Xft.
XFT_VERSION
es XFT_MAJOR multiplicado por 10000 (diez mil), más XFT_MINOR multiplicado por 100, más XFT_REVISION.
XftVersion
es un alias para XFT_VERSION.

El siguiente ejemplo ilustra cómo se podrían usar las constantes de versión de Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("La versión 2.1.7 o posterior de la biblioteca Xft está en"
                " uso.");
    #else
    (void) printf("Versión insuficiente de Xft (%d.%d.%d) instalada;
                  " se necesita al menos la versión 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TIPOS DE DATOS

Los tipos de datos de Xft siguen una convención de nomenclatura, prefijando todos los nombres con “Xft”

Desde Xlib...

Los tipos de datos de Xlib no siguen una convención de nomenclatura. Están documentados en Xlib - C Language Interface.

Xft usa estos nombres: Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, y XRectangle.

Algunos tipos de datos son especialmente relevantes para Xft:

Drawable
Declarado en <X11/X.h>, este es un ID de recurso X, por ejemplo, una ventana asociada con una pantalla. Tanto las ventanas como los pixmaps se pueden usar como fuentes y destinos en operaciones gráficas. Estas ventanas y pixmaps se conocen colectivamente como drawables. Sin embargo, una ventana de **InputOnly** no se puede usar como fuente o destino en una operación gráfica.
Region
Declarado en <X11/Xutil.h> y <X11/Xregion.h>, una **Region** es un conjunto arbitrario de ubicaciones de píxeles que Xlib puede manipular. Internamente, una **Region** se representa por la unión de un número arbitrario de rectángulos. Xlib mantiene un rectángulo que le indica el alcance de esta unión.
Visual
Declarado en <X11/Xutil.h>, esta estructura contiene información sobre la asignación de color posible.

Desde XRender...

Los tipos de datos de la biblioteca X Render Extension están inspirados en Xlib, pero carecen de la documentación correspondiente. Consulte el archivo de encabezado para obtener detalles:

<X11/extensions/Xrender.h>

o lea el código fuente (que proporciona un esquema de libXrender).

Xft usa estos nombres: Picture, XGlyphInfo, XRenderColor.

Desde Fontconfig...

Los tipos de datos de Fontconfig siguen una convención de nomenclatura, prefijando todos los nombres con “Fc” que están documentados en Fontconfig Developers Reference.

Xft usa estos nombres de Fontconfig: FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, y FcResult.

Desde FreeType 2...

Los tipos de datos de FreeType 2 siguen una convención de nomenclatura, prefijando todos los nombres con “FT_” que están documentados en FreeType API Reference.

Xft usa estos nombres: FT_Face, FT_Library, y FT_UInt.

FreeType 2 usa FT_UInt (un entero sin signo) para representar *glifos*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un **XftFont** es la estructura de datos principal de interés para los programadores que usan Xft; contiene métricas generales de la fuente y punteros al conjunto de caracteres de Fontconfig y al patrón asociado con la fuente.

Los **XftFont** se pueblan con cualquiera de **XftFontOpen()**, **XftFontOpenName()**, **XftFontOpenXlfd()**, **XftFontOpenInfo()**, o **XftFontOpenPattern()**. **XftFontCopy()** se usa para duplicar **XftFont**s, y **XftFontClose()** se usa para marcar un **XftFont** como no utilizado. Los **XftFont**s son asignados internamente, contados por referencia y liberados por Xft; el programador no necesita asignar ni liberar almacenamiento para ellos.

XftDrawGlyphs(), la familia **XftDrawString**\*(), **XftDrawCharSpec()**, y **XftDrawGlyphSpec()** usan **XftFont**s para renderizar texto a un objeto **XftDraw**, que puede corresponder a un dibujable X principal o a un dibujable de la Extensión de Renderizado X.

Se usan **XftGlyphExtents()** y la familia **XftTextExtents**\*() para determinar las extents (dimensiones máximas) de un **XftFont**.

La cobertura de glifos o caracteres de un **XftFont** se puede determinar con **XftFontCheckGlyph()** o **XftCharExists()**. **XftCharIndex()** devuelve el índice de carácter específico de **XftFont** correspondiente a un punto de código Unicode dado.

**XftGlyphRender()**, **XftGlyphSpecRender()**, **XftCharSpecRender()**, y la familia **XftTextRender**\*() usan **XftFont**s para dibujar en estructuras de **Picture** de la Extensión de Renderizado X.

Nota: **XftDrawGlyphs()**, la familia **XftDrawString**\*(), **XftDrawCharSpec()**, y **XftDrawGlyphSpec()** proporcionan un medio de renderizar fuentes que es independiente de la disponibilidad de la Extensión de Renderizado X en el servidor X.

XftFontInfo

es un objeto opaco que almacena información sobre una fuente. Las estructuras **XftFontInfo** se crean con **XftFontInfoCreate()**, se liberan con **XftFontInfoDestroy()**, y se comparan con **XftFontInfoEqual()**. Los objetos **XftFontInfo** son asignados y liberados internamente por Xft; el programador no necesita asignar ni liberar almacenamiento para ellos.

Cada estructura **XftFontInfo** en uso está asociada con un identificador único, que se puede obtener con **XftFontInfoHash()**. Se puede abrir un **XftFont** basándose en los datos de **XftFontInfo** con **XftFontOpenInfo()**.

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objeto **XftColor** permite que el texto y otros elementos se rendericen en un color particular (o la aproximación más cercana ofrecida por el visual X en uso).

**XftColorAllocName()** y **XftColorAllocValue()** solicitan una asignación de color del servidor X (si es necesario) e inicializan los miembros de **XftColor**. **XftColorFree()** instruye al servidor X a liberar el color actualmente asignado para un **XftColor**.

Una vez que un **XftColor** ha sido inicializado, **XftDrawSrcPicture()**, **XftDrawGlyphs()**, la familia **XftDrawString**\*(), **XftDrawCharSpec()**, **XftDrawCharFontSpec()**, **XftDrawGlyphSpec()**, **XftDrawGlyphFontSpec()**, y **XftDrawRect()** pueden usarse para dibujar varios objetos usándolo.

XftDraw

es un objeto opaco que contiene información utilizada para renderizar a un drawable de X utilizando el protocolo central o la extensión de renderizado de X.

Los objetos XftDraw se crean con cualquiera de las funciones XftDrawCreate() (que asocia un XftDraw con un drawable de X existente), XftDrawCreateBitmap(), o XftDrawCreateAlpha(), y se destruyen con XftDrawDestroy(). El drawable de X asociado con un XftDraw puede cambiarse con XftDrawChange(). Los objetos XftDraw son asignados y liberados internamente por Xft; el programador normalmente no necesita asignar ni liberar memoria para ellos.

Las propiedades Display, Drawable, Colormap, y Visual de X de un XftDraw se pueden consultar con XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), y XftDrawVisual(), respectivamente.

Varias funciones utilizan objetos XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), y la familia XftDrawString*().

El Picture de la Extensión de Renderizado de X asociado con un XftDraw se devuelve por XftDrawPicture(), y XftDrawSrcPicture(). Es utilizado por XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), y la familia XftTextRender*().

FUNCIONES

Inicialización

Una aplicación típica que utiliza Xft no inicializa explícitamente la biblioteca. Eso se hace generalmente como un efecto secundario de abrir una fuente.

Cuando Xft se inicializa, recopila información sobre la pantalla y almacena parte de esa información en un patrón Fontconfig (esencialmente una colección de propiedades con valores tipados). La aplicación que llama puede modificar ese patrón para cambiar el comportamiento de la biblioteca.

No toda la información recopilada se almacena en un patrón. El resto se almacena en estructuras de datos internas. Xft pone parte de esa información a disposición de la aplicación a través de funciones.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y devuelve verdadero si Xft encontró que la pantalla soporta la extensión X Render, y si puede encontrar un XRenderPictFormat adecuado (el tipo de dato de X Render análogo al Visual de Xlib) en la pantalla.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtiene información sobre la pantalla dpy si aún no se ha hecho, y establece el patrón Fontconfig que contiene las propiedades predeterminadas que Xft usará para esta pantalla.

Xft utiliza esas propiedades inicialmente para obtener estos límites:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Esta es la cantidad máxima de memoria de glifos para todas las fuentes utilizadas por Xft (por defecto: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Este es el número máximo de fuentes no referenciadas (por defecto: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Cuando es verdadero, Xft rastrea el uso de la memoria de glifos para mejorar el rendimiento al decidir cuáles descargar cuando se alcanza la cantidad máxima de memoria de glifos (por defecto: falso).
Xft también utiliza estas propiedades predeterminadas en XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft completa las propiedades faltantes en el pattern dado utilizando las propiedades predeterminadas para la pantalla especificada dpy, por ejemplo, como se establece en XftDefaultSet().

Las aplicaciones típicas de Xft utilizan esta función para ayudar a Fontconfig a elegir una fuente adecuada. Estas propiedades se sustituyen antes de llamar a FcDefaultSubstitute():
FC_ANTIALIAS
Verdadero si FreeType debe usar antialiasing (por defecto: Falso). (por defecto: Verdadero).
FC_AUTOHINT
Verdadero si FreeType debe usar autohinting (por defecto: Falso).
FC_DPI
Puntos por pulgada utilizados para la resolución (por defecto: calculado a partir de la altura de la pantalla).
FC_EMBOLDEN
Verdadero si FT_GlyphSlot_Embolden() debe usarse para emblanquecer una fuente (por defecto: Falso).
FC_HINTING
Verdadero si se debe usar hinting al completar propiedades para abrir una fuente (por defecto: Verdadero).
FC_HINT_STYLE
Estilo de hinting utilizado al completar propiedades para abrir una fuente (por defecto: FC_HINT_FULL).
FC_LCD_FILTER
Parámetro pasado a FT_Library_SetLcdFilter() al cargar glifos (por defecto: FC_LCD_DEFAULT).
FC_MINSPACE
Valor de espacio mínimo utilizado al completar propiedades para abrir una fuente (por defecto: Falso).
FC_RGBA
Valor RGBA utilizado al completar propiedades para abrir una fuente (por defecto: calculado llamando a XRenderQuerySubpixelOrder()).
FC_SCALE
Escala utilizada en Fontconfig (por defecto: 1.0).
XFT_MAX_GLYPH_MEMORY
Memoria máxima para una fuente (por defecto: 1024*1024).
XFT_RENDER
Verdadero si la pantalla soporta la extensión X Render (por defecto: resultado de XftDefaultHasRender()).

XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen toma una lista de trios de elementos de patrón del tipo
        campo, tipo, valor (terminada con NULL), coincide con ese patrón contra las fuentes disponibles, y abre la fuente coincidente, dimensionándola correctamente para la pantalla número screen en la pantalla dpy. Devuelve la fuente coincidente, o NULL si no se encuentra ninguna coincidencia.

  




Ejemplo:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Esto abre la fuente "charter" a 12 puntos. El tamaño en puntos se convierte automáticamente al tamaño de píxel correcto basándose en la resolución del monitor.

.PP
Dibuja una lista de glifos asociados con fuentes en coordenadas especificadas,
pasados como un array de len estructuras XftGlyphFontSpec a través
del parámetro glyphs. Todos los glifos se dibujan usando el color
especificado en el parámetro color.
.TP
Para cada entrada en el array glyphs:
.TP
Si la fuente asociada utiliza la extensión de Renderizado X, entonces
Xft utiliza XftGlyphFontSpecRender() para dibujar el glifo,
utilizando una Picture obtenida al llamar a XftDrawSrcPicture()
con los parámetros draw y color.
.TP
De lo contrario, Xft proporciona una característica análoga utilizando
Xlib.
.TP
void
XftGlyphFontSpecRender(
        Display       *dpy,
        int     op,
        Picture       src,
        Picture       dst,
        int     srcx,
        int     srcy,
        _Xconst XftGlyphFontSpec      *glyphs,
        int     nglyphs);
.PP
Esto implica varios pasos:
.TP
Primero, Xft asegura que el array glyphs esté completo usando
XftFontCheckGlyph() y cargando cualquier glifo faltante con
XftFontLoadGlyphs().
.TP
Luego, Xft examina los glifos para encontrar el valor Unicode máximo.
Eso determina el tamaño de codificación, es decir, el width.
.TP
Luego, para cada glifo, Xft verifica si su valor Unicode es manejado por
la fuente correspondiente. Si no, el valor se establece en cero (0), para
ignorarlo. Mientras hace esto, Xft también recuerda cuál fue la primera
fuente utilizada y calcula la posición en la que se dibujará cada glifo.
.TP
Xft luego construye un array equivalente de glifos en el formato esperado
por la biblioteca de Renderizado X.
.TP
Finalmente, XftGlyphFontSpecRender() utiliza la extensión de
Renderizado X para dibujar los glifos, con la función apropiada
XRenderCompositeText*() según el width, y descarta los datos
temporales.
.TP
Los parámetros op, dst, src, srcx, y srcy
se utilizan como se describe en la documentación de la biblioteca de
Renderizado X.

void XftFontLoadGlyphs (




	Display *dpy,
	XftFont *pub,
	FcBool need_bitmaps,
	_Xconst FT_UInt *glyphs,
	int nglyph);



Usando FT_Load_Glyph(), carga nglyphs para los
índices de glifos (valores Unicode) listados en el array glyphs de la
fuente dada pub.










Cargar un glifo implica más que solo leer datos en la memoria.
    Xft usa el patrón de Fontconfig asociado con la pantalla
    dpy (por ejemplo, a través de XftDefaultSet()) para determinar
    si usar un cuadro delimitador, recortar los glifos dentro de esos
    límites, escalar los glifos, calcular métricas de fuentes y agregarlo a
    la extensión X Render usando XRenderAddGlyphs().






void XftFontUnloadGlyphs (




	Display *dpy,
	XftFont *pub,
	_Xconst FT_UInt *glyphs,
	int nglyph);



Descarta datos para hasta nglyph glifos cuyos índices
de glifo (valores Unicode) están listados en el array glyphs para la
fuente dada pub. Si los glifos se agregaron a la extensión X
Render,
    Xft los elimina usando XRenderFreeGlyphs().
    Xft realiza un seguimiento de la cantidad de memoria utilizada para
    glifos y actualiza el uso asociado con la pantalla

FT_Face XftLockFace (




	XftFont *pub);



Si no se ha creado ninguna "cara" de FreeType 2 (representación
en memoria de una tipografía dada en un estilo dado) para la fuente
pub, créela usando FT_New_Face().
Los bloqueos de cara son un contador de referencias utilizado por
Xft para asegurar que solo se cree una cara y que se conserve hasta
que la fuente ya no se use.










El bloqueo de cara se usa directamente en XftCharIndex() y
    XftFontLoadGlyphs(), que a su vez se utilizan en muchas funciones de
    Xft.




El bloqueo de cara se introdujo en la versión 1 (octubre de 2002).
    Algunas aplicaciones, como Gdk/Gimp, dependían de estas funciones. En la
    versión 2.1.9 (junio de 2006), el bloqueo de cara se conservó como parte
    de la API pública cuando las configuraciones mejoradas de bibliotecas
    compartidas proporcionaron ocultar símbolos privados.






void XftUnlockFace (




	XftFont *pub);



Disminuye el contador de referencias para la "cara" de FreeType
    2 asociada con la fuente.










Los objetos FT_Face se desasignan usando FT_Done_Face().
    Xft hace esto en XftFontInfoDestroy() y al limpiar en caso de
    error en XftFontInfoCreate() y
    XftFontOpenPattern().










DEPURACIÓN


Xft lee la variable de entorno XFT_DEBUG y la
convierte a un entero. Cada bit en el valor resultante indica a
    Xft que imprima información de depuración en la salida estándar:




1


apertura de fuente


2


coincidencia y apertura adicional de fuentes (verboso)


4


muestra detalles sobre el XRenderPictFormat que se utilizará.


8


muestra la cadena que XftDrawString8() dibujará.


16


muestra qué ids de fuente coinciden.


32


muestra información útil sobre los glifos que se dibujarán


64


muestra una representación en arte ASCII de los glifos.


128


muestra detalles sobre la gestión de la caché de memoria


256


muestra detalles sobre la gestión de la memoria caché de glifos


512


muestra un informe sobre el uso de memoria


1024


muestra detalles sobre la gestión extendida de la memoria caché de glifos








COMPATIBILIDAD


A partir de la versión 2 (mayo de 2002), Xft se volvió
relativamente estable. Se espera que mantenga la compatibilidad de
código fuente y binaria en futuras
    versiones.


Xft proporciona una interfaz de compatibilidad con su
versión principal anterior, Xft 1.x, que se describe a
continuación.




Archivo de cabecera de Xft 1.x


#include <X11/Xft/XftCompat.h>






Tipos de datos de Xft 1.x




XftPattern


contiene un conjunto de nombres con listas de valores asociados; cada nombre
se refiere a una propiedad de una fuente. Los XftPattern se utilizan
como entrada para el código de coincidencia, así como para contener
información sobre fuentes específicas.


XftFontSet


contiene una lista de XftPattern. Internamente, Xft utiliza
esta estructura de datos para mantener conjuntos de fuentes.
Externamente,
    Xft devuelve los resultados de la lista de fuentes en este
formato.


XftObjectSet


contiene un conjunto de nombres y se utiliza para especificar qué campos de
las fuentes se colocan en la lista de patrones devueltos al listar las
fuentes.
