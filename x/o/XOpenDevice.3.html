XOPENDEVICE(3)   XOPENDEVICE(3)

NOMBRE

XOpenDevice, XCloseDevice - abrir o cerrar un dispositivo de entrada de extensión

SINOPSIS

#include <X11/extensions/XInput.h>
XDevice *XOpenDevice( Display *display,
                      XID device_id);
XCloseDevice( Display *display,
              XDevice *device);
display
       Especifica la conexión con el servidor X.
device_id
       Especifica el id del dispositivo a abrir
device
       Especifica el dispositivo a cerrar

DESCRIPCIÓN

La solicitud XOpenDevice hace que un dispositivo de entrada sea accesible para un
cliente a través de solicitudes de protocolo de extensión de entrada. Si
tiene éxito, devuelve un puntero a una estructura XDevice.
La solicitud XCloseDevice hace que un dispositivo de entrada sea inaccesible
para un cliente a través de solicitudes de protocolo de extensión de entrada. Antes
de finalizar, cualquier cliente que haya abierto dispositivos de entrada a través
de la extensión de entrada debería cerrarlos mediante CloseDevice.
Cuando un cliente realiza una solicitud XCloseDevice, se liberan cualquier captura activa
que el cliente tenga sobre el dispositivo. Se eliminan todas las selecciones de eventos
que tenga el cliente, así como cualquier captura pasiva. Si el cliente solicitante es el último
cliente que accede al dispositivo, el servidor puede deshabilitar todo acceso por parte de X
al dispositivo.
XOpenDevice y XCloseDevice pueden generar un error BadDevice.

Estructuras

La estructura XDevice devuelta por XOpenDevice contiene:
             typedef struct {
             XID device_id;
             int num_classes;
             XInputClassInfo *classes;
             } XDevice;
El campo classes es un puntero a una matriz de estructuras XInputClassInfo. Cada
elemento de esta matriz contiene una base de tipo de evento para una clase de entrada
soportada por el dispositivo especificado. El campo num_classes indica el número de
elementos en la matriz classes.
La estructura XInputClassInfo contiene:
typedef struct {
    unsigned char input_class;
    unsigned char event_type_base;
} XInputClassInfo;
El campo input_class identifica una clase de entrada soportada
por el dispositivo. Los tipos definidos incluyen KeyClass, ButtonClass,
ValuatorClass, ProximityClass, FeedbackClass, FocusClass y
OtherClass. El event_type_base identifica el tipo de evento
del primer evento de esa clase.
La información contenida en la estructura XInputClassInfo se
utiliza mediante macros para obtener las clases de eventos que los clientes utilizan en
las solicitudes XSelectExtensionEvent. Las macros definidas actualmente incluyen
DeviceKeyPress, DeviceKeyRelease, DeviceButtonPress,
DeviceButtonRelease, DeviceMotionNotify, DeviceFocusIn,
DeviceFocusOut, ProximityIn, ProximityOut, DeviceStateNotify,
DeviceMappingNotify, ChangeDeviceNotify,
DevicePointerMotionHint, DeviceButton1Motion,
DeviceButton2Motion, DeviceButton3Motion, DeviceButton4Motion,
DeviceButton5Motion, DeviceButtonMotion, DeviceOwnerGrabButton,
DeviceButtonPressGrab y NoExtensionEvent.
Para obtener la clase de evento adecuada para un dispositivo en particular, se invoca una de
las macros anteriores utilizando la estructura XDevice para
ese dispositivo. Por ejemplo,
             DeviceKeyPress (*device, type, eventclass);
devuelve el tipo de evento DeviceKeyPress y la eventclass para
los eventos DeviceKeyPress del dispositivo especificado.
Esta eventclass puede usarse luego en una solicitud XSelectExtensionEvent
para solicitar al servidor que envíe eventos DeviceKeyPress desde
este dispositivo. Cuando se recibe un evento seleccionado a través de XNextEvent,
el tipo puede usarse para comparar con el tipo en el evento.

DIAGNÓSTICOS

BadDevice
       Se especificó un dispositivo inválido. El dispositivo
       especificado no existe, o es el teclado X o el puntero X. Este
       error también puede ocurrir si algún otro cliente ha causado que
       el dispositivo especificado se convierta en el teclado X o el puntero X
       mediante las solicitudes XChangeKeyboardDevice o
       XChangePointerDevice.
