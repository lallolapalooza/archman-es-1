Xorg(1) Manual de Comandos Generales Xorg(1)

NOMBRE

Xorg - servidor X X11R7

SINOPSIS

Xorg [:display] [opción ...]

DESCRIPCIÓN

Xorg es un servidor X completo que fue diseñado originalmente para sistemas operativos UNIX y similares a UNIX que se ejecutan en hardware Intel x86. Ahora se ejecuta en una gama más amplia de plataformas de hardware y sistemas operativos.

Este trabajo se derivó de la versión XFree86 4.4rc2 del Proyecto X.Org Foundation. La versión XFree86 se derivó originalmente de X386 1.2 de Thomas Roell, que fue aportada a X11R5 por Snitily Graphics Consulting Service.

PLATAFORMAS

Xorg opera en una amplia gama de sistemas operativos y plataformas de hardware. La arquitectura Intel x86 (IA32) es la plataforma de hardware más compatible. Otras plataformas de hardware incluyen Compaq Alpha, Intel IA64, AMD64, SPARC y PowerPC. Los sistemas operativos más compatibles son los sistemas tipo UNIX libres/de código abierto como Linux, FreeBSD, NetBSD, OpenBSD y Solaris. También se admiten sistemas operativos UNIX comerciales como UnixWare. Otros sistemas operativos compatibles incluyen GNU Hurd. Mac OS X se admite con el servidor X xquartz(1). Win32/Cygwin se admite con el servidor X XWin(1).

CONEXIONES DE RED

Xorg admite conexiones realizadas utilizando los siguientes flujos de bytes fiables:

Local
En la mayoría de las plataformas, el tipo de conexión "Local" es un socket de dominio UNIX. En algunas plataformas System V, los tipos de conexión "local" también incluyen tuberías STREAMS, tuberías con nombre y algunos otros mecanismos. Consulte la sección "CONEXIONES LOCALES" de X(7) para obtener más detalles.
TCP/IP
Xorg escucha en el puerto 6000+n, donde n es el número de pantalla. Este tipo de conexión generalmente está deshabilitado por defecto, pero puede habilitarse con la opción -listen (consulte la página del manual de Xserver(1) para obtener más detalles).

OPCIONES

Xorg admite varios mecanismos para proporcionar/obtener parámetros de configuración y en tiempo de ejecución: opciones de línea de comandos, variables de entorno, archivos de configuración xorg.conf(5), detección automática y valores predeterminados de reserva. Cuando la misma información se proporciona de más de una manera, se utiliza el mecanismo de mayor prioridad. La lista de mecanismos está ordenada de mayor a menor prioridad. Tenga en cuenta que no todos los parámetros se pueden proporcionar a través de todos los métodos. Las opciones de línea de comandos y las variables de entorno disponibles (y algunos valores predeterminados) se describen aquí y en la página del manual de Xserver(1). La mayoría de los parámetros del archivo de configuración, con sus valores predeterminados, se describen en la página del manual de xorg.conf(5). Los parámetros de configuración específicos del controlador y del módulo se describen en la página del manual del controlador o módulo correspondiente.

Además de las opciones normales del servidor descritas en la página del manual de Xserver(1), Xorg acepta los siguientes interruptores de línea de comandos:

vtXX
XX especifica el número del dispositivo de Terminal Virtual que utilizará Xorg. Sin esta opción, Xorg elegirá la primera Terminal Virtual disponible que pueda localizar. Esta opción solo se aplica a plataformas que tienen soporte para terminales virtuales, como Linux, BSD, OpenSolaris, SVR3 y SVR4.
-allowMouseOpenFail
Permite que el servidor se inicie incluso si no se puede abrir o inicializar el dispositivo del ratón. Esto es equivalente a la opción de archivo xorg.conf(5) AllowMouseOpenFail.
-allowNonLocalXvidtune
Hace que la extensión VidMode esté disponible para clientes remotos. Esto permite que el cliente xvidtune se conecte desde otro host. Esto es equivalente a la opción de archivo xorg.conf(5) AllowNonLocalXvidtune. Por defecto, no se permiten las conexiones no locales.
-bgamma valor
Establece la corrección gamma azul. valor debe estar entre 0.1 y 10. El valor predeterminado es 1.0. No todos los controladores admiten esto. Consulte también las opciones -gamma, -rgamma y -ggamma.
-bpp n
Ya no se admite. Utilice -depth para establecer la profundidad de color y utilice -fbbpp si realmente necesita forzar un formato de píxel de fotogramas (hardware) no predeterminado.
-config archivo
Lee la configuración del servidor del archivo. Esta opción funcionará para cualquier archivo cuando el servidor se ejecute como root (es decir, con UID real 0), o para archivos relativos a un directorio en la ruta de búsqueda de configuración para todos los demás usuarios.
-configdir directorio
Lee los archivos de configuración del servidor desde el directorio. Esta opción funcionará para cualquier directorio cuando el servidor se ejecute como root (es decir, con UID real 0), o para directorios relativos a un directorio en la ruta de búsqueda de directorios de configuración para todos los demás usuarios.
-configure
Cuando se especifica esta opción, el servidor Xorg carga todos los módulos del controlador de video, busca el hardware disponible y escribe un archivo xorg.conf(5) inicial basado en lo que se detectó. Esta opción actualmente tiene algunos problemas en algunas plataformas, pero en la mayoría de los casos es una buena manera de iniciar el proceso de configuración. Esta opción solo está disponible cuando el servidor se ejecuta como root (es decir, con UID real 0).
-crt /dev/ttyXX
Solo SCO. Esto es lo mismo que la opción vt, y se proporciona para la compatibilidad con el servidor X nativo de SCO.
-depth n
Establece la profundidad de color predeterminada. Los valores legales son 1, 4, 8, 15, 16 y 24. No todos los controladores admiten todos los valores.
-disableVidMode
Deshabilita las partes de la extensión VidMode (utilizada por el cliente xvidtune) que se pueden usar para cambiar los modos de video. Esto es equivalente a la opción de archivo xorg.conf(5) DisableVidModeExtension.
-fbbpp n
Establece el número de bits por píxel del fotograma. Solo debe establecerlo si está seguro de que es necesario; normalmente el servidor puede deducir el valor correcto de -depth anterior. Útil si desea ejecutar una configuración de profundidad 24 con un fotograma de 24 bpp en lugar del fotograma (posiblemente predeterminado) de 32 bpp (o viceversa). Los valores legales son 1, 8, 16, 24, 32. No todos los controladores admiten todos los valores.
-gamma valor
Establece la corrección gamma. valor debe estar entre 0.1 y 10. El valor predeterminado es 1.0. Este valor se aplica por igual a los valores R, G y B. Estos valores se pueden establecer de forma independiente con las opciones -rgamma, -bgamma y -ggamma. No todos los controladores admiten esto.
-ggamma valor
Establece la corrección gamma verde. valor debe estar entre 0.1 y 10. El valor predeterminado es 1.0. No todos los controladores admiten esto. Consulte también las opciones -gamma, -rgamma y -bgamma.
-ignoreABI
El servidor Xorg comprueba los niveles de revisión ABI de cada módulo que carga. Normalmente se negará a cargar módulos con revisiones ABI más recientes que las del servidor. Esto se debe a que dichos módulos podrían utilizar interfaces que el servidor no tiene. Cuando se especifica esta opción, las discrepancias como esta se degradan de errores fatales a advertencias. Esta opción debe usarse con cuidado.
-isolateDevice bus-id
Restringe los reinicios del dispositivo al dispositivo en bus-id. La cadena bus-id tiene el formato tipobus:bus:dispositivo:función (por ejemplo, "PCI:1:0:0"). Actualmente, solo se admite el aislamiento de dispositivos PCI; es decir, esta opción se ignora si tipobus es algo que no sea
-keeptty
Evita que el servidor se separe de su terminal de control inicial. Si desea utilizar la integración con systemd-logind, debe especificar esta opción. No todas las plataformas soportan (o pueden usar) esta opción.
-keyboard nombre-teclado
Utiliza la sección InputDevice del archivo xorg.conf(5) llamada nombre-teclado como teclado principal. Esta opción se ignora cuando la sección Layout especifica un teclado principal. En ausencia de ambas, una sección de Layout y esta opción, se utiliza la primera sección InputDevice relevante para el teclado principal.
-layout nombre-disposicion
Utiliza la sección Layout del archivo xorg.conf(5) llamada nombre-disposicion. Por defecto, se utiliza la primera sección Layout.
-logfile nombre-archivo
Utiliza el archivo llamado nombre-archivo como archivo de registro del servidor Xorg. El archivo de registro por defecto cuando se ejecuta como root es /var/log/Xorg.n.log y para los no root es $XDG_DATA_HOME/xorg/Xorg.n.log donde n es el número de pantalla del servidor Xorg. El valor por defecto puede estar en un directorio diferente en algunas plataformas. Esta opción solo está disponible cuando el servidor se ejecuta como root (es decir, con uid real 0).
-logverbose [n]
Establece el nivel de verbosidad para la información impresa en el archivo de registro del servidor Xorg. Si no se proporciona el valor n, cada ocurrencia de esta opción incrementa el nivel de verbosidad del archivo de registro. Cuando se proporciona el valor n, el nivel de verbosidad del archivo de registro se establece a ese valor. El nivel de verbosidad del archivo de registro por defecto es 3.
-modulepath rutadebusqueda
Establece la ruta de búsqueda de módulos a rutadebusqueda. rutadebusqueda es una lista de directorios separados por comas donde buscar los módulos del servidor Xorg. Esta opción solo está disponible cuando el servidor se ejecuta como root (es decir, con uid real 0).
-noautoBindGPU
Desactiva la configuración automática de GPUs secundarias como sumideros de salida y fuentes de descarga. Esto es equivalente a establecer la opción de archivo xorg.conf(__filemansuffix__) AutoBindGPU a false.
-nosilk
Desactiva el soporte de ratón sedoso (Silken Mouse).
-novtswitch
Desactiva el cambio automático al reiniciar y apagar el servidor X a la VT que estaba activa cuando el servidor se inició, si es soportado por el sistema operativo.
-pointer nombre-puntero
Utiliza la sección InputDevice del archivo xorg.conf(5) llamada nombre-puntero como puntero principal. Esta opción se ignora cuando la sección Layout especifica un puntero principal. En ausencia de ambas, una sección de Layout y esta opción, se utiliza la primera sección InputDevice relevante para el puntero principal.
-quiet
Suprime la mayoría de los mensajes informativos al inicio. El nivel de verbosidad se establece a cero.
-rgamma valor
Establece la corrección gamma del rojo. El valor debe estar entre 0.1 y 10. El valor por defecto es 1.0. No todos los controladores soportan esto. Ver también las opciones -gamma, -bgamma y -ggamma.
-sharevts
Comparte terminales virtuales con otro servidor X, si es soportado por el sistema operativo.
-screen nombre-pantalla
Utiliza la sección Screen del archivo xorg.conf(5) llamada nombre-pantalla. Por defecto, se utilizan las pantallas referenciadas por la sección Layout por defecto, o la primera sección Screen cuando no hay secciones Layout.
-showconfig
Es lo mismo que la opción -version, y se incluye por razones de compatibilidad. Puede ser eliminada en una futura versión, por lo que se debe usar la opción -version en su lugar.
-showDefaultModulePath
Imprime la ruta de módulos por defecto con la que se compiló el servidor.
-showDefaultLibPath
Imprime la ruta donde se deben instalar las bibliotecas.
-showopts
Para cada módulo de controlador instalado, imprime la lista de opciones y sus tipos de argumento.
-weight nnn
Establece el peso RGB a 16 bpp. El valor por defecto es 565. Esto se aplica solo a aquellos controladores que soportan 16 bpp.
-verbose [n]
Establece el nivel de verbosidad para la información impresa en stderr. Si no se proporciona el valor n, cada ocurrencia de esta opción incrementa el nivel de verbosidad. Cuando se proporciona el valor n, el nivel de verbosidad se establece a ese valor. El nivel de verbosidad por defecto es 0.
-version
Imprime la versión del servidor, nivel de parche, fecha de lanzamiento, el sistema operativo/plataforma en el que fue compilado, y si incluye soporte para el cargador de módulos.

TECLADO

El servidor Xorg normalmente está configurado para reconocer varias combinaciones especiales de pulsaciones de teclas que instruyen al servidor para realizar alguna acción, en lugar de simplemente enviar el evento de pulsación de tecla a una aplicación cliente. Estas acciones dependen del mapa de teclas XKB cargado por un dispositivo de teclado particular y pueden o no estar disponibles en una configuración dada.

Las siguientes combinaciones de teclas son comúnmente parte del mapa de teclas XKEYBOARD por defecto.

Ctrl+Alt+Retroceso
Termina inmediatamente el servidor, sin preguntas. Puede ser desactivado estableciendo la opción de archivo xorg.conf(5) DontZap a un valor TRUE.
Cabe señalar que el "zapping" se activa mediante la acción Terminate_Server en el mapa del teclado. Esta acción no forma parte de los mapas de teclas por defecto, pero puede habilitarse con la opción XKB "terminate:ctrl_alt_bksp".
Ctrl+Alt+BloqueNum-+
Cambia el modo de video al siguiente especificado en el archivo de configuración. Esto puede ser desactivado con la opción de archivo xorg.conf(5) DontZoom.
Ctrl+Alt+BloqueNum--
Cambia el modo de video al anterior especificado en el archivo de configuración. Esto puede ser desactivado con la opción de archivo xorg.conf(5) DontZoom.
Ctrl+Alt+F1...F12
Para sistemas con soporte de terminales virtuales, estas combinaciones de teclas se utilizan para cambiar a las terminales virtuales 1 a 12, respectivamente. Esto puede ser desactivado con la opción de archivo xorg.conf(5) DontVTSwitch.

CONFIGURACIÓN

Xorg utiliza típicamente un archivo de configuración llamado xorg.conf y archivos de configuración con el sufijo .conf en un directorio llamado xorg.conf.d para su configuración inicial. Consulte la página del manual xorg.conf(5) para obtener información sobre el formato de este archivo.

Xorg tiene un mecanismo para generar automáticamente una configuración incorporada en tiempo de ejecución cuando no hay archivos xorg.conf o xorg.conf.d presentes. La versión actual de este mecanismo de configuración automática funciona de dos maneras.

La primera es a través de mejoras que han hecho opcionales muchos componentes del archivo xorg.conf. Esto significa que la información que se puede detectar o deducir razonablemente no necesita especificarse explícitamente, reduciendo en gran medida la cantidad de información de configuración incorporada que necesita generarse en tiempo de ejecución.

La segunda es tener valores de reserva "seguros" para la mayoría de la información de configuración. Esto maximiza la probabilidad de que el servidor Xorg se inicie en alguna configuración utilizable incluso cuando no se dispone de información sobre el hardware específico.

El soporte de configuración automática para Xorg está en progreso. Actualmente está dirigido a las plataformas de hardware y software más populares soportadas por Xorg. Se planean mejoras para futuras versiones.
