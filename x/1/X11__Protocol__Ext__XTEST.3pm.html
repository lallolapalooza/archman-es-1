NOMBRE

X11::Protocol::Ext::XTEST - entrada de usuario sintética y más

SINOPSIS

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('XTEST')
  or print "La extensión XTEST no está disponible";
$X->XTestFakeInput (name   => 'ButtonPress',
                    detail => 3);  # botón físico 3
$X->XTestFakeInput (name   => 'ButtonRelease',
                    detail => 3);

DESCRIPCIÓN

La extensión XTEST proporciona

  • Acciones sintéticas de teclado y puntero del ratón.
  • Comparaciones de cursor mostradas.
  • Programas de prueba que continúan durante "GrabServer" por otros clientes.

Estas cosas ayudan a ejercitar características de bibliotecas o servidores que de otra manera requerirían interacción del usuario.

SOLICITUDES

Las siguientes solicitudes se ponen a disposición con una init_extension(), según "EXTENSIONS" en X11::Protocol.

my $is_available = $X->init_extension('XTEST');
"($server_major, $server_minor) = $X->XTestGetVersion ($client_major, $client_minor)"
Negocia una versión de protocolo con el servidor. $client_major y $client_minor es lo que el cliente desearía. El retornado $server_major y $server_minor es lo que el servidor hará.

El código actual soporta hasta 2.1. La intención sería negociar automáticamente en init_extension() si es necesario.

Comparaciones de Cursor

"$is_same = $X->XTestCompareCursor ($window, $cursor)"
Devuelve verdadero si el atributo del cursor de $window es igual a $cursor. $cursor puede ser
  • XID (un entero) de un cursor.
  • "None" (o 0).
  • "CurrentCursor" (o 1) para el cursor actualmente mostrado.

Esto se puede usar para verificar que el atributo del cursor de alguna $window sea la configuración deseada, por ejemplo

$desired_cursor = $X->new_rsrc;
$X->CreateGlyphCursor ($desired_cursor, ...);
$X->XTestCompareCursor ($window, $desired_cursor)
  or die "¡Ups, $window no tiene el cursor deseado";

O alternativamente, construir una ventana con un cursor particular y usar "CurrentCursor" para verificar que lo que se muestra actualmente es como se desea, por ejemplo, para ver si un GrabPointer() está mostrando lo que se pretende,

my $test_window = $X->new_rsrc;
$X->CreateWindow ($test_window, ...,
                  cursor => $desired_cursor);
$X->XTestCompareCursor ($test_window, "CurrentCursor");
  or die "¡Ups, el cursor mostrado actualmente no es como se desea";

Entrada Simulada

"$X->XTestFakeInput (name=>...)"
"$X->XTestFakeInput ([ name=>... ])"
"$X->XTestFakeInput ([ name=>], [name=>], ...)"
Simula la entrada del usuario para pulsaciones de botones, pulsaciones de teclas y movimiento del puntero.

Una acción de entrada se especifica como un paquete de evento usando campos similares a "$X->pack_event()".

XTestFakeInput() es siempre una acción de usuario única, por lo que, por ejemplo, una pulsación de botón y una liberación de botón son dos solicitudes XTestFakeInput() separadas. Para los eventos principales, un solo paquete de evento es suficiente para describir una entrada, pero algunas extensiones como "XInputExtension" pueden requerir más.

Pulsación y Liberación de Botón
Los campos de argumento son 
name       "ButtonPress" o "ButtonRelease"
detail     número de botón físico (a partir de 1)
time       retraso en milisegundos antes del evento, por defecto 0

Por ejemplo, para simular una pulsación del botón físico 3

$X->XTestFakeInput (name   => 'ButtonPress',
                    detail => 3);

"detail" es el número de botón físico, antes de que se aplique la traducción del protocolo principal SetPointerMapping(). Para simular un botón lógico, es necesario verificar GetPointerMapping() para ver qué botón físico, si lo hay, corresponde.

Tenga cuidado al simular una "ButtonPress", ya que podría ser importante simular también una "ButtonRelease" correspondiente. En el servidor X.org alrededor de la versión 1.9.x, después de una pulsación sintética, el ratón físico no funciona para generar una liberación y el botón queda colgado (presumiblemente en su agarre implícito normal del puntero).

Pulsación y Liberación de Tecla
Los campos de argumento son 
name       "KeyPress" o "KeyRelease"
detail     keycode (entero)
time       retraso en milisegundos antes del evento, por defecto 0
Movimiento del Puntero del Ratón
El movimiento del puntero del ratón se puede inducir con lo siguiente. El efecto es similar a un WarpPointer(). 
name       "MotionNotify"
root       XID de la ventana raíz, por defecto "None" para la actual
root_x     \ posición del puntero a la que moverse
root_y     /
detail     bandera 0=absoluto, 1=relativo, por defecto 0
time       retraso en milisegundos antes del evento, por defecto 0

"root" es la ventana raíz (XID entero) en la que moverse. El valor por defecto "None" (o 0) significa la pantalla en la que se encuentra actualmente el puntero.

$X->XTestFakeInput (name   => 'MotionNotify',
                    root_x => 123,
                    root_y => 456);

"detail" puede ser 1 para moverse relativamente a la posición actual del ratón.

$X->XTestFakeInput (name   => 'MotionNotify',
                    root_x => 10,
                    root_y => -20,
                    detail => 1); # movimiento relativo
Otros Eventos
Los eventos de extensión se pueden simular después de una init_extension() para que sean reconocidos por "$X->pack_event()". Depende del servidor o la extensión qué eventos se pueden simular realmente.

Si una entrada de extensión requiere más de un paquete de evento para describirse, pase múltiples arrayrefs. Por ejemplo, "DeviceMotion" (de "XInputExtension") puede necesitar paquetes adicionales de "DeviceValuator",

$X->XTestFakeInput ([ name => 'DeviceMotion', ... ],
                    [ name => 'DeviceValuator', ... ],
                    [ name => 'DeviceValuator',  ... ]);

Para todos los eventos, "time" es cuánto tiempo en milisegundos debe esperar el servidor antes de reproducir el evento. El valor por defecto es 0 para ningún retraso. No se procesan más solicitudes del cliente actual durante el retraso, por lo que una secuencia de XTestFakeInput() con retrasos se ejecutará secuencialmente, un retraso tras otro.

En general, los campos de evento de una función "$X->{'event_handler'}" no se pueden pasar directamente a XTestFakeInput() para reproducirlos. En particular,

  • "time" de un evento es una marca de tiempo, por lo que tendría que ser puesto a cero o ajustado a un tiempo relativo para un retraso en XTestFakeInput().
  • Para "MotionNotify", "detail" de un evento es el mecanismo de sugerencia, por lo que tendría que ser puesto a cero para la bandera absoluta/relativa en XTestFakeInput().

GrabServer Imperviousness

"$X->XTestGrabControl ($impervious)"
Controla el comportamiento del cliente actual durante una GrabServer() por parte de otro cliente.

Si $impervious es 1, el cliente actual puede continuar haciendo solicitudes, es decir, es invulnerable a los grabs del servidor por parte de otros clientes.

Si $impervious es 0, el cliente actual se comporta de forma normal. Sus solicitudes esperan durante cualquier GrabServer() por parte de otro cliente.
