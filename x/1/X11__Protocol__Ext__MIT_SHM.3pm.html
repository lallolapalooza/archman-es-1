X11::Protocol::Ext::MIT_SHM(3) Documentación Perl contribuida por el usuario X11::Protocol::Ext::MIT_SHM(3)

NOMBRE

X11::Protocol::Ext::MIT_SHM - imágenes en memoria compartida estilo SysV

SINOPSIS

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('MIT-SHM')
  or print "Extensión MIT-SHM no disponible";
use IPC::SysV;
my $shmid = shmget (IPC::SysV::IPC_PRIVATE(),
                    100000,  # bytes
                    IPC::SysV::IPC_CREAT() | 0666);
my $shmseg = $X->new_rsrc;
$X->MitShmAttach ($shmseg, $shmid, 0);
my ($depth, $visual, $size) =  $X->MitShmGetImage
      ($window, 0,0, 16,16, ~0, 'ZPixmap', $shmseg, 0);
my $image_bytes;
shmread ($shmid, $image_bytes, 0, 16*16*$bpp) || die "$!";
# $image_bytes son los 16x16 píxeles superiores izquierdos de la pantalla

DESCRIPCIÓN

La extensión MIT-SHM permite que un cliente y un servidor que se ejecutan en la misma máquina transfieran datos de imagen a través de segmentos de memoria compartida System-V.

El cliente crea un segmento de memoria con shmget() (ver "shmget" en perlfunc y "SysV IPC" en perlipc) y solicita al servidor que se adjunte a él y luego lea o escriba con equivalentes a los GetImage y PutImage centrales.

El objetivo es evitar el envío de imágenes grandes a través de la conexión de E/S cuando se está en la misma máquina. La memoria es más rápida y puede ayudar a evitar límites de tamaño de solicitud para imágenes muy grandes.

El orden de bytes, el relleno, etc., requeridos o generados en las imágenes se especifican por el servidor "$X->{'image_byte_order'}", "$X->{'pixmap_formats'}", etc., lo mismo que para el núcleo GetImage() y PutImage(). Depende del cliente adaptarse al diseño del servidor, lo que puede ser un poco tedioso.

Shm desde Perl

Un segmento de memoria compartida se puede crear desde Perl con shmget(), luego leer o escribir su contenido con shmread() y shmwrite(). Estas funciones adjuntan y desadjuntan cada vez con las llamadas al sistema shmat() y shmdt(), lo cual está bien para capturar todo pero será un poco lento para muchos accesos pequeños.

"IPC::SysV" (versión 2 o superior) ofrece un shmat() para mantener el bloque adjunto y memread() y memwrite() para acceder a él (ver IPC::SysV). Ver IPC::SharedMem para un envoltorio orientado a objetos alrededor de esto también.

Por cierto, si shmget() no está disponible en el sistema, el shmget() de Perl falla. Siempre es posible que devuelva "undef" también por falta de memoria, etc. Con eso, no estar en la misma máquina, no tener permisos identificables, etc., hay varios casos en los que será necesario un recurso a la E/S simple.

Permisos Shm

Un segmento de memoria compartida SysV tiene bits de permiso de propietario/grupo/otros similares a un archivo. El servidor solo se adjuntará a los segmentos a los que el UID/GID del cliente solicitante tenga permiso para leer o escribir.

El servidor generalmente puede determinar el UID/GID de un cliente en una conexión local, como un socket Unix (X11::Protocol::Connection::UNIXSocket, y "SO_PEERCRED" en socket(7)), y quizás en un bucle de retorno localhost TCP. De lo contrario, el servidor trata al cliente como "otro" y solo se adjuntará a segmentos legibles por todos (o legibles/escribibles por todos).

Puede hacer que un segmento shm sea legible por todos para garantizar que el servidor pueda leerlo. Si los datos para un PutImage, etc., provienen ya de un archivo legible por todos o son públicos, no debería importar mucho quién más lea el segmento. Recuerde solicitar solo lectura en MitShmAttach() para que el servidor no necesite también escritura.

Probablemente no sea necesario arriesgarse a relajar los permisos para escribir segmentos. Es probable que si el UID/GID del cliente no se puede identificar, sea porque la conexión no es local y el servidor está en una máquina diferente, por lo que la memoria compartida no se puede usar de todos modos.

Es habitual que el servidor se ejecute como root, de ahí sus propias verificaciones de permisos, pero también es posible que el servidor sea un usuario normal. En ese caso, los segmentos shm a los que puede acceder estarán limitados de la manera habitual para el usuario con el que se esté ejecutando.

SOLICITUDES

Las siguientes solicitudes están disponibles después de una init_extension() por "EXTENSIONS" en X11::Protocol.

my $bool = $X->init_extension('MIT-SHM');

En lo siguiente, $shmid es el ID de memoria compartida (un entero) obtenido del kernel con shmget(). $shmseg es un XID (asignado normalmente por el cliente "$X->new_rsrc()") en el servidor que representa la conexión del servidor al bloque.

"($server_major, $server_minor, $uid, $gid, $shared_pixmaps, $pixmap_format) = $X->MitShmQueryVersion ()"
Devuelve información sobre la extensión MIT-SHM. A diferencia de otras extensiones, no hay negociación de versión cliente/servidor.

$server_major y $server_minor son el número de versión de la extensión implementada por el servidor.

$uid y $gid (enteros) son el ID de usuario y el ID de grupo efectivos del servidor (geteuid() y getegid()). Cero significa root.

$shared_pixmaps es distinto de cero si se admiten mapas de bits en memoria compartida (ver MitShmCreatePixmap() abajo). $pixmap_format (un ImageFormat) es "XYPixmap" o "ZPixmap" para el diseño requerido en dicho mapa de bits.

"$X->MitShmAttach ($shmseg, $shmid, $readonly)"
Adjunta el servidor a un segmento de memoria compartida dado. $shmseg es un nuevo XID para representar la memoria adjunta. 
my $shmseg = $X->new_rsrc;
$X->MitShmAttach ($shmseg, $shmid, 0); # lectura/escritura

$shmid es el ID de memoria compartida a adjuntar, tal como se obtuvo de shmget() (ver "shmget" en perlfunc).

$readonly es 1 para que el servidor se adjunte en modo de solo lectura, o 0 para lectura/escritura. El modo de solo lectura es suficiente para MitShmPutImage(), pero se requiere lectura/escritura para MitShmGetImage() y MitShmCreatePixmap().

"$X->MitShmDetach ($shmseg)"
Desconecta el servidor de la memoria compartida $shmseg (un XID) y libera ese XID. 
$X->MitShmDetach ($shmseg);
"$X->MitShmPutImage ($drawable, $gc, $depth, $total_width, $total_height, $src_x, $src_y, $src_width, $src_height, $dst_x, $dst_y, $format, $send_event, $shmseg, $offset)"
Coloca datos de imagen de $shmseg (un XID) en $drawable. Los parámetros son similares a los del núcleo PutImage().

$depth es la profundidad de la imagen. Para el formato "Bitmap" esto debe ser 1 y entonces se dibujan los colores de primer plano y de fondo de $gc. Para los formatos "XYPixmap" y "ZPixmap", $depth debe ser la profundidad de $drawable.

$total_width, $total_height es el tamaño completo de la imagen en la memoria compartida. $src_x, $src_y y $src_width, $src_height son la porción a dibujar. $dst_x, $dst_y es dónde colocarlo en $drawable.

$format es "Bitmap", "XYPixmap" o "ZPixmap" (un ImageFormat).

X11::Protocol::Ext::MIT_SHM(3pm)

NAME

X11::Protocol::Ext::MIT_SHM - Shared Memory Extension

SYNOPSIS

  use X11::Protocol::Ext::MIT_SHM;
  my $x = X11::Protocol->new;
  # ...
  # Query version
  my ($major, $minor, $pixmap, $image) = $x->MitShmQueryVersion;
  # Check support
  if ($image) {
    # ...
  }
  # Get image
  my ($depth, $visual, $size) = $x->MitShmGetImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset);
  # Create pixmap
  my $pixmap = $x->new_rsrc;
  $x->MitShmCreatePixmap ($pixmap, $drawable, $depth, $width, $height, $shmseg, $offset);
  # Put image
  $x->MitShmPutImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset);
  # Attach to shared memory
  $x->MitShmAttach ($shmseg, $shmid, $offset);
  # Detach from shared memory
  $x->MitShmDetach ($shmseg);
  # Put image and get completion event
  $x->MitShmPutImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset, 1);
  # Get completion event
  my $ev = $x->wait_for_event;
  if ($ev->isa ("X11::Protocol::Event::MitShmCompletion")) {
    # ...
  }

DESCRIPTION

This extension allows X clients to transfer images and pixmaps to and from the X server using shared memory, which is much faster than the normal protocol requests.

The extension must be initialized with MitShmQueryVersion(). This tells you whether the extension is supported, and whether it supports pixmaps and image transfers.

Shared memory segments are created using the standard shmget(2) system call and attached to the client or server process using shmat(2). The client must then attach the segment to the X server using MitShmAttach(). The client can then use the shared memory segment to send images to the server using MitShmPutImage() or receive images using MitShmGetImage(). Shared memory pixmaps can also be created using MitShmCreatePixmap().

When the client or server writes to the shared memory, the contents of the image or pixmap are updated.

REQUESTS

"$major, $minor, $pixmap_support, $image_support = $X->MitShmQueryVersion"
Query the shared memory extension version and capabilities.

$major and $minor are the major and minor version numbers of the extension. $pixmap_support is true if shared memory pixmaps are supported. $image_support is true if shared memory images are supported.

"$X->MitShmAttach ($shmseg, $shmid, $offset)"
Attach a shared memory segment to the X server.

$shmseg is a new XID that will represent the shared memory segment on the server. $shmid is the shared memory identifier obtained from shmget(2). $offset is a byte offset into the shared memory where the image data begins.

The shared memory segment must be created with read-write permissions for the server. If $offset is not zero, the data is assumed to be aligned within the shared memory segment.

"$X->MitShmDetach ($shmseg)"
Detach a shared memory segment from the X server.

$shmseg is the XID of the shared memory segment to detach.

"$X->MitShmPutImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset, $send_event)"
Copy an image from shared memory to a drawable.

$drawable is the drawable to copy the image to. $x, $y, $width, $height define the destination region. $planemask is a bit mask for which bit planes of the pixels are wanted. $format is either "XYPixmap" or "ZPixmap" for the layout of the image data in shared memory. $shmseg is the XID of the shared memory segment. $offset is a byte offset into the shared memory where the image data starts. $send_event is a boolean, true if a MitShmCompletionEvent should be sent to the client when the server has finished copying the image.

"($depth, $visual, $size) = $X->MitShmGetImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset)"
Copy an image from a drawable to shared memory.

The parameters are similar to MitShmPutImage(), except that the image is read from $drawable instead of written to it. The data is written into the shared memory segment $shmseg at the specified $offset.

The returned $depth is the depth of the drawable, $visual is its visual ID (or "None" for a pixmap), and $size is the number of bytes written.

"$X->MitShmCreatePixmap ($pixmap, $drawable, $depth, $width, $height, $shmseg, $offset)"
Create a pixmap with contents in shared memory.

$pixmap is a new XID that will represent the shared memory pixmap. $drawable is used to determine the screen for the new pixmap. $depth, $width, $height define the dimensions of the pixmap. $shmseg is the XID of the shared memory segment. $offset is a byte offset into the shared memory where the pixmap data begins.

The pixmap's contents can be modified by writing directly to the shared memory segment.

EVENTS

"MitShmCompletionEvent" is sent to the client when requested in an MitShmPutImage(). It indicates that the server has finished processing the image data from shared memory.

name             "MitShmCompletionEvent"
synthetic        true if from a SendEvent
code             integer opcode
sequence_number  integer
drawable       XID, target drawable from request
shmseg         XID, shared memory segment from request
offset         integer, byte offset from request
major_opcode   integer, MIT-SHM extension code
minor_opcode   integer, 3 for MitShmPutImage

The major_opcode and minor_opcode fields identify the originating request. This event is analogous to the core protocol's "GraphicsExposure" and "NoExposure" events, but is specific to the MitShmPutImage() request.

ERRORS

The extension defines a "ShmSeg" error type, which is raised if an invalid shared memory segment XID is used in a request.
