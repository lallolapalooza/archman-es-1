X11::Protocol::XSetRoot(3) Documentación de Perl aportada por el usuario X11::Protocol::XSetRoot(3)

NOMBRE

X11::Protocol::XSetRoot -- establece el fondo de la ventana raíz

SINOPSIS

use X11::Protocol::XSetRoot;
X11::Protocol::XSetRoot->set_background (color => 'green');
# o dado $X, pero que entonces no se podrá usar más
X11::Protocol::XSetRoot->set_background
                 (X       => $X,
                  pixmap  => $xid_del_pixmap,
                  pixmap_allocated_colors => 1);

DESCRIPCIÓN

Este módulo establece el fondo de la ventana raíz de X al estilo del programa "xsetroot".

El uso más sencillo es un color con nombre interpretado por AllocNamedColor() del servidor o una cadena hexadecimal de 1 a 4 dígitos como "#RRGGBB" o "#RRRRGGGGBBBB".

X11::Protocol::XSetRoot->set_background
                           (color => 'green');
X11::Protocol::XSetRoot->set_background
                           (color => '#FF0000'); # rojo

Se puede establecer un patrón con un pixmap. Un pixmap del tamaño de la pantalla puede dar una imagen de fondo completa.

# dibuja $pixmap con, digamos, $X->black_pixel y $X->white_pixel,
# luego establécelo con
X11::Protocol::XSetRoot->set_background
                           (X      => $X,
                            pixmap => $pixmap);

set_background() toma posesión del $pixmap proporcionado y lo libera con FreePixmap() una vez que se ha insertado en el fondo de la ventana.

Establecer la raíz a un pixmap dibujado por un programa es el uso principal de este módulo. Si solo deseas un color sólido, eso se puede hacer fácilmente con el programa "xsetroot".

Recursos Retenidos

Los colores de píxeles asignados (en "PseudoColor", etc.) y cualquier "use_esetroot" conservan píxeles y el pixmap con "SetCloseDownMode ('RetainPermanent')" y dejan las propiedades de la ventana raíz "_XSETROOT_ID" o "ESETROOT_PMAP_ID" listas para ser liberadas por un KillClient() en un cambio de fondo posterior.

En estos casos, la conexión $X no se puede volver a utilizar, ya que un cambio de fondo posterior y el consiguiente KillClient() podrían ocurrir en cualquier momento, quizás de inmediato.

Si se proporciona un "pixmap", y este contiene algún píxel asignado (AllocColor(), etc.), entonces esto debe indicarse con la opción "pixmap_allocated_colors". (Los píxeles asignados se notan automáticamente para las opciones "pixel" y "color").

# Colores de AllocColor, dibuja $pixmap con ellos, luego
#
X11::Protocol::XSetRoot->set_background
                           (X      => $X,
                            pixmap => $pixmap,
                            pixmap_allocated_colors => 1);
# no uses más $X

Lo más fácil es cerrar una conexión $X inmediatamente después de un set_background(). Quizás podría haber un valor de retorno para indicar si se retuvo y, por lo tanto, la conexión no se puede volver a usar. O quizás en el futuro si "X11::Protocol" tuviera un explícito "$X->close()", eso podría hacerse aquí, de modo que una conexión cerrada indicaría que no se puede usar más.

Si la visualización raíz es estática ("TrueColor", etc.), entonces no hay asignación de color como tal (AllocColor() es solo una búsqueda). En este caso, set_background() sabe que no es necesario "RetainPermanent" para los colores, solo para los pixmaps.

Si las opciones "color" o "pixel" son el "black_pixel" o "white_pixel" de la pantalla, entonces esos píxeles existen permanentemente en el mapa de colores raíz y set_background() sabe que no es necesario "RetainPermanent" para ellos. Si el servidor tiene la extensión TOG-CUP (ver X11::Protocol::Ext::TOG_CUP), entonces también se reconocen los píxeles permanentes allí.

Raíz Virtual

"XSetRoot" busca "__SWM_VROOT" utilizando X11::Protocol::WM root_to_virtual_root() y actúa sobre él cuando es aplicable. Dicha raíz virtual es utilizada por los gestores de ventanas "amiwm", "swm" y "tvtwm", y por el programa "xscreensaver".

Sin embargo, el gestor de ventanas enlightenment utiliza una ventana de fondo que cubre la ventana raíz. Esto impide que la mayoría de los programas de ventana raíz funcionen, incluido XSetRoot aquí.

Esetroot

El programa "Esetroot" y varios programas compatibles como "fvwm-root" utilizan un conjunto de propiedades separado de lo que utiliza "xsetroot". El método "Esetroot" registra el pixmap raíz listo para ser utilizado por programas como "Eterm", por ejemplo, para implementar pseudo-transparencia (su "Eterm --trans", para el cual se diseñó el método).

La opción "use_esetroot" de set_background() utiliza el estilo "Esetroot" en lugar del estilo "xsetroot" por defecto. Se puede usar también con las opciones "pixel" o "color" y en ese caso set_background() crea un pixmap de 1x1 para dar un color sólido.

set_background() siempre elimina y mata (según corresponda) tanto las propiedades "xsetroot" como "Esetroot", ya que ambas son reemplazadas por un nuevo fondo.

A modo de referencia, para usar "Eterm --trans" (a partir de su versión 0.9.6 de marzo de 2011), debe haber un fondo "Esetroot" presente cuando se inicie "Eterm" y no debe eliminarse más tarde (y no establecerse en "None"). "Eterm" no notará un "Esetroot" inicial mientras se esté ejecutando. Esto significa que se debe realizar un "Esetroot" antes de ejecutar "Eterm" y luego realizar todos los cambios de fondo futuros en estilo "Esetroot".

La ventaja del método "Esetroot" es que el pixmap raíz está disponible para que los programas cliente lo utilicen de formas creativas. Si el cliente dibuja parte del pixmap raíz como su propio fondo, puede parecer semitransparente. Esto no requiere la extensión SHAPE y también permite efectos visuales como sombreado o difuminado.

En comparación, el estilo "xsetroot" significa que el pixmap raíz no está disponible para los programas cliente. En principio, eso permite al servidor aplicarlo al hardware y no volver a referenciarlo. En la práctica, eso podría no ocurrir, por ejemplo, si múltiples "terminales virtuales" de consola significan que el servidor debe ceder el hardware al cambiar de contexto.

NAME

X11::Protocol::XSetRoot - Set the root window background

SYNOPSIS

  use X11::Protocol::XSetRoot;
  my $x = X11::Protocol::Connection->new;
  my $root = $x->choose_screen;
  set_background($x, $root, "blue");
  set_background($x, $root, "#ff0000");
  set_background($x, $root, pixmap_id); # pixmap XID
  set_background($x, $root, "None");
  set_background($x, $root, "None", pixmap_allocated_colors => 1);
  set_background($x, $root, pixmap_id, use_esetroot => 1);
  set_background($x, $root, pixmap_id, use_esetroot => 1, pixmap_allocated_colors => 1);

DESCRIPTION

This module provides a Perl interface to the XSetRoot protocol. It allows you to set the root window background.

The parameters are: "connection", "root", "background", "pixmap_allocated_colors", "use_esetroot".

"connection" is an X11::Protocol::Connection object, or a "display" name to connect to, or the default is the "DISPLAY" environment variable.

The root window is given by "root" or "screen", or the default is the default screen in $X either per "$X->choose_screen()" or the default from the display name.

The background to show is given by a colour name, pixel value, or pixmap. "color" can be anything understood by the server AllocNamedColor(), plus 1 to 4 digit hex

blue              named colours
#RGB              hex digits
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB

"pixel" is an integer pixel value in the root window colormap. It's automatically recognised as allocated or not (the screen pre-defined black or white and TOG-CUP reserved pixels are permanent and so reckoned not allocated).

"pixmap" is an XID integer. set_background() takes ownership of this pixmap and will FreePixmap() once installed. "None" or 0 means no pixmap, which gives the server's default root background (usually a black and white weave pattern).

"pixmap_allocated_colors" should be true if any of the pixels in "pixmap" were allocated with AllocColor() etc, as opposed to just the screen pre-defined black and white pixels (and any TOG-CUP permanent pixels).

"use_esetroot" means use the root window properties in the style of "Esetroot". This allows programs such as "Eterm" to use the root background for "pseudo-transparency" or in other creative ways.

When an allocated pixel or a pixmap with allocated pixels is set as the background the "_XSETROOT_ID" mechanism described above means the $X connection could be killed by another "xsetroot" at any time, perhaps immediately, and for that reason $X should not be used any more. The easiest way is to make set_background() the last thing done on $X.

Setting an allocated "pixel" or any "pixmap" can only be done on a $X connection as such, not with the "display" option. This is because retaining the colours with the "_XSETROOT_ID" mechanism can only be done from the client connection which created the resources, not a new separate client connection.

Virtual Root

A virtual root is a window that is a child of the actual root window. It is used by some window managers to implement virtual desktops. If you are using a virtual root, you should pass the virtual root window ID as the "root" parameter instead of the actual root window ID.

Esetroot

The "use_esetroot" option enables support for "Esetroot" style root window properties. This is used by some programs, like "Eterm", to implement features like pseudo-transparency. When this option is enabled, the module will set the "_XROOTPMAP_ID" and "ESETROOT_PMAP_ID" properties on the root window.

FUNCTIONS

set_background($connection, $root, $background, %options)
Sets the background of the specified root window.

The parameters are:

$connection
An X11::Protocol::Connection object, or a display name string.
$root
The root window ID. Can be obtained using $connection->choose_screen().
$background
The background to set. Can be a color name, a hex color string (e.g., "#RRGGBB"), a pixel value (integer), a pixmap ID (integer), or the string "None".
%options
A hash of options:
pixmap_allocated_colors
Boolean, true if the pixmap contains allocated colors. Defaults to false.
use_esetroot
Boolean, true to use Esetroot style properties. Defaults to false.

ROOT WINDOW PROPERTIES

"_XSETROOT_ID"
For "xsetroot", if colours in the root window background are allocated by AllocColor() etc then "_XSETROOT_ID" is a pixmap XID which can be killed by KillClient() to free those colours when the root background is replaced. "_XSETROOT_ID" is only a 1x1 dummy pixmap, it's not the actual root background pixmap.
"_XROOTPMAP_ID"
For "Esetroot" style, this is the current root window background pixmap. It might be set by an "Esetroot" which has run and exited, or it might be set by a window manager or similar which is still running.

Client programs can use this to combine the root background into their own window in interesting ways. Listen to "PropertyNotify" on the root window for changes to "_XROOTPMAP_ID". Note that this pixmap belongs to another client so it could be freed at any time. Protocol errors when copying or drawing from it should generally be ignored, or cause a fallback to some default.

"ESETROOT_PMAP_ID"
For "Esetroot" style, this is the same as "_XROOTPMAP_ID" if that pixmap was created by "Esetroot" and saved by SetCloseDownMode('RetainPermanent'). This should be freed by KillClient() if the background is replaced.

The specification http://www.eterm.org/docs/view.php?doc=ref#trans advises killing "ESETROOT_PMAP_ID" only when equal to "_XROOTPMAP_ID". Probably it's safer to always kill "ESETROOT_PMAP_ID" if replacing its value, to be sure of not leaking resources. But perhaps if both "ESETROOT_PMAP_ID" and "_XROOTPMAP_ID" exist then they are always equal.

ENVIRONMENT

"DISPLAY"
The default X server.
