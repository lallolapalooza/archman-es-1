X11::Protocol::Ext::DOUBLE_BUFFER(3) Documentación de Perl aportada por el usuario X11::Protocol::Ext::DOUBLE_BUFFER(3)

NOMBRE

X11::Protocol::Ext::DOUBLE_BUFFER - doble buffer fuera de pantalla para ventanas

SINOPSIS

use X11::Protocol;
$X = X11::Protocol->new;
$X->init_extension('DOUBLE-BUFFER')
  or print "La extensión DOUBLE-BUFFER no está disponible";

DESCRIPCIÓN

La extensión DOUBLE-BUFFER permite a un programa dibujar en un "buffer trasero" fuera de pantalla en una ventana y, cuando esté listo, intercambiarlo por el "buffer frontal" visible para el usuario. Un buffer trasero es un objeto dibujable con el mismo tamaño, profundidad, visibilidad, etc., que la ventana propiamente dicha.

Dibujar fuera de pantalla y luego intercambiar para que sea visible es bueno para animaciones fluidas cuadro por cuadro o si algún dibujo es complejo o está mal implementado y tiene efectos de parpadeo si se hiciera directamente en la ventana.

El dibujo fuera de pantalla también puede implementarse con un pixmap y copiarlo en la ventana, pero el servidor podría implementar un buffer trasero de manera más eficiente. En particular, el buffer trasero solo necesita ser las porciones visibles de una ventana, por lo que no se usa memoria para áreas superpuestas.

El servidor podría admitir el doble buffering solo en ciertos visuales. DbeGetVisualInfo() lista los que son soportados, o simplemente intente crear un buffer trasero para una ventana y espere una respuesta de error.

Vea examples/dbe-swap.pl para un programa simple que dibuja con doble buffering.

SOLICITUDES

Las siguientes solicitudes se ponen a disposición con un init_extension() por cada "EXTENSIONS" en X11::Protocol.

my $bool = $X->init_extension('DOUBLE-BUFFER');
"($server_major, $server_minor) = $X->DbeGetVersion ($client_major, $client_minor)"
Negocia una versión de protocolo con el servidor. $client_major y $client_minor son lo que el cliente desearía, $server_major y $server_minor devueltos son lo que el servidor hará, lo cual podría ser menor a lo solicitado (pero no mayor).

El código aquí soporta 1.0 y negocia automáticamente dentro de init_extension(), por lo que el uso directo de DbeGetVersion() no es necesario.

"$X->DbeAllocateBackBufferName ($window, $buffer, $action_hint)"
Crea $buffer (un nuevo XID) como el buffer trasero en $window. $buffer es un objeto dibujable y puede usarse con todas las operaciones de dibujo habituales. 
my $buffer = $X->new_rsrc;
$X->DbeAllocateBackBufferName ($window, $buffer, 'Copied');

$action_hint es la $action más probable en solicitudes posteriores de DbeSwapBuffers() (ver más abajo). Pero esto es solo una pista y no restringe lo que se puede hacer.

Si $window ya tiene doble buffering, entonces $buffer se convierte en otra referencia a ese buffer trasero.

Si $window se destruye (DestroyWindow()), entonces $buffer continúa existiendo y aún debería ser desasignado (abajo), pero intentar dibujar en él genera una respuesta de error de "Resource".

"$X->DbeDellocateBackBufferName ($buffer)"
Desasigna $buffer y libera ese XID.

Si se han realizado múltiples solicitudes de DbeAllocateBackBufferName() en una ventana, entonces todos los otros XIDs continúan refiriéndose al buffer trasero de la ventana. El buffer subyacente permanece hasta que todos los XIDs de buffer para él sean desasignados.

"$X->DbeSwapBuffers ($window1,$action1, $window2,$action2,...)"
Intercambia los buffers frontal y trasero en cada $window (XIDs) dado. El buffer trasero se vuelve visible y lo que era el frontal se convierte en el trasero. 
$X->DbeSwapBuffers ($window1, 'Background',
                    $window2, 'Untouched');

Solo se intercambia el contenido, los XIDs no cambian, por lo que $window sigue siendo el frente visible de la ventana y cualquier XID de $buffer asociado a ella sigue siendo el trasero.

Los contenidos de cada buffer trasero después del intercambio se controlan mediante la $action correspondiente para cada ventana (tipo de cadena "DbeSwapAction"),

 $action        contenido del nuevo buffer trasero
---------       ----------------------------------
"Undefined"     contenido indefinido
"Background"    limpiado al fondo de la ventana
"Untouched"     dejado con el contenido actual (anteriormente visible)
"Copied"        contenido del buffer trasero anterior (sin cambios)

"Untouched" significa que el contenido del buffer frontal se intercambia al buffer trasero sin cambios.

"Copied" es como si el contenido del buffer trasero se copiara al frontal, haciendo que ambos sean iguales.

"$X->DbeBeginIdiom ()"
"$X->DbeEndIdiom ()"
Indica al servidor que una secuencia de operaciones de intercambio y/o dibujo entre Begin y End podría hacerse como una combinación atómica para un mayor rendimiento. Si el servidor no reconoce la secuencia, la ejecuta secuencialmente como de costumbre.

Si hay un DbeSwapBuffers() en el idioma, debe ser la primera solicitud, inmediatamente después de Begin.

# intercambiar y luego limpiar el buffer trasero con un stipple GC
# ¡no hay garantía de que ningún servidor optimice esto!
$X->DbeBeginIdiom;
$X->DbeSwapBuffers ($window, 'Undefined');
$X->PolyFillRectangle ($buffer, $gc, [0,0,$width,$height]);
$X->DbeEndIdiom;

No es necesario que haya un intercambio en un idioma. Por ejemplo, un CopyArea() de algunas partes del buffer trasero a la ventana podría estar en un Begin/End y quizás ser optimizado por el servidor.

$X->DbeBeginIdiom;
$X->CopyArea ($buffer, $window,  # del buffer a la ventana
              $gc, $x,$y,$width,$height, $dstx,$dsty);
# más cosas...
$X->DbeEndIdiom;

La idea de agrupar idiomas es tener una forma flexible de expresar combinaciones de operaciones, incluidas cosas aún no imaginadas, en lugar de añadir solicitudes específicas al protocolo. En principio, el servidor siempre puede optimizar solicitudes consecutivas, pero eso depende de que lleguen al servidor juntas. Un DbeBeginIdiom() es como un permiso para que el servidor posponga la ejecución de las solicitudes y espere, si lo desea, a ver si lo que sigue se puede combinar.

"@infos = $X->DbeGetVisualInfo ($drawable1, $drawable2, ...)"
"@infos = $X->DbeGetVisualInfo ()"
Para cada $drawable, devuelve una lista de los IDs visuales en esa pantalla que admiten doble buffering. 
my ($info_aref_drawable1, $info_aref_drawable2)
  = $X->DbeGetVisualInfo ($drawable1, $drawable2);

Si no se proporcionan drawables, devuelve información sobre cada pantalla del servidor.

my @list_of_info_aref = $X->DbeGetVisualInfo ();

Cada valor devuelto es un arrayref. Cada arrayref contiene una lista de pares de ID visual y datos visuales,

# cada $info_aref es
[ $visual_id1, [ $depth, $perflevel ],
  $visual_id2, [ $depth, $perflevel ],
  ...
]

$depth es la profundidad visual, la misma que en la información del servidor "$X->{'visuals'}->{$visual_id}->{'depth'}".

$perflevel es un entero que indica qué tan bueno es el rendimiento del doble buffering en este visual. Un valor más alto significa un mayor rendimiento, pero el número real no tiene significado y, en particular, no se puede comparar entre diferentes servidores.

Si se consulta sobre la pantalla de un solo drawable, use un contexto de lista como el siguiente. El resultado en contexto escalar aún no está especificado.

my ($info_aref) = $X->DbeGetVisualInfo ($X->root);

El visual + nivel de rendimiento son pares, por lo que se pueden poner en un hash para verificar la compatibilidad con el doble buffering en un visual dado,

my %hash = @$info_aref;   # pares $visualid => [$d,$p]
if ($hash{$my_visual_id}) {
  print "doble buffering está disponible en my_visual_id\n";
}

X11::Protocol::Ext::DOUBLE_BUFFER(3pm)

NAME

X11::Protocol::Ext::DOUBLE_BUFFER - extension for X Double Buffering Extension.

SYNOPSIS

    use X11::Protocol::Ext::DOUBLE_BUFFER;
    my $X = X11::Protocol::Connection->new;
    $X->init_extension('DOUBLE_BUFFER') || die ...;
    my $buffer = $X->DbeAllocateBuffer(...);
    ...
    $X->DbeDeallocateBuffer($buffer);
    ...
    my $info_aref = $X->DbeGetVisualInfo;
    ...
    my $window = $X->DbeGetBackBufferAttributes($buffer);
    ...
    my $num = $X->num("DbeSwapAction", "Background");
    ...
    $X->DbeSwapBuffers($buffer, $action);
    ...
    $X->DbeBeginPicture($drawable, $client_major_version, $client_minor_version);
    ...
    $X->DbeEndPicture($drawable);
    ...
    $X->DbeSetvislosti($buffer, $vislosti_type, $vislosti_value);
    ...
    $X->DbeGetvislosti($buffer);

DESCRIPTION

This module is an X11 protocol extension for the Double Buffering Extension.

The extension is needed by applications needing to draw to off-screen buffers and then swap them into view, to avoid flicker.

This module is usually used indirectly via a higher level module like X11::Protocol::Screen, which knows how to enable the extension.

If you need to use this module directly then you must call $X->init_extension('DOUBLE_BUFFER') to enable the extension.

The module provides the following methods:

$buffer = $X->DbeAllocateBuffer($visual, $width, $height, $depth)
Allocate a double buffer. Return the buffer id (an integer).
$X->DbeDeallocateBuffer($buffer)
Deallocate a double buffer.
$X->DbeSwapBuffers($buffer, $action)
Swap the buffers. $action is one of the DbeSwapAction enum types.
$X->DbeBeginPicture($drawable, $client_major_version, $client_minor_version)
Begin drawing a picture into a drawable. This is needed to get the correct buffer for drawing. $client_major_version and $client_minor_version are the versions of the DBE protocol the client supports.
$X->DbeEndPicture($drawable)
End drawing a picture into a drawable.
$X->DbeSetvislosti($buffer, $vislosti_type, $vislosti_value)
Setvislosti for a buffer. $vislosti_type is an integer identifying the type ofvislosti. $vislosti_value is the value.
$vislosti_aref = $X->DbeGetvislosti($buffer)
Getvislosti for a buffer. Returns a list reference of vislosti_type/vislosti_value pairs.

REQUESTS

$info_aref = $X->DbeGetVisualInfo()
Return a list reference of hash references, each containing information about a visual suitable for double buffering. The keys are:
    'visual' => XID visual id
    'depth' => integer depth
    'perflevel' => integer performance level (higher is better)
    'agemask' => integer agemask

The perflevel can be used to choose a visual with good performance. The extension is intended to be used with visuals that have a performance level > 0.

If the server does not support DBE then it returns an empty list reference.

Use X11::Protocol::List::Pairwise's grep and map functions to filter this list, eg:

    my $best_visual_href = $X->List->grep(sub { $_->{perflevel} > 0 },
                                     $X->DbeGetVisualInfo)->first;

Or just get the info without any filtering, so the application display then the performance level might be compared to choose the best.

"List::Pairwise" has some grep and map functions for pair lists like the $info_aref.

See examples/dbe-info.pl for a simple program printing this info.

$window = $X->DbeGetBackBufferAttributes ($buffer)
Return the window (an integer XID) which $buffer is for. If its target window has been destroyed (DestroyWindow()) then the return is "None".

ENUM TYPES

The following types are available for "$X->interp()" and "$X->num()", after init_extension().

DbeSwapAction
"Undefined"    0
"Background"   1
"Untouched"    2
"Copied"       3

For example,

my $num = $X->num("DbeSwapAction", "Background");
# sets $num to 2

BUGS

In some XFree86 3.x servers there was a bug in DbeGetVisualInfo() where the reply length was miscalculated, being bytes instead of CARD32s, resulting in a length value bigger than the actual data sent. The symptom is the client hangs waiting for data the length says should follow but which never does.

This affects all client code, including the Xlib XdbeGetVisualInfo() as used for instance by the "xdpyinfo" program.

Is there a good way to notice the problem? Probably not beyond looking at the server name and version and either forbidding the request or doing something nasty to the way handle_input() reads as a workaround.
