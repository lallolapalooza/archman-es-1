NOMBRE

X11::Protocol - Módulo Perl para el Protocolo del Sistema de Ventanas X, versión 11

SINOPIS

use X11::Protocol;
$x = X11::Protocol->new();
$win = $x->new_rsrc;
$x->CreateWindow($win, $x->root, 'InputOutput',
                 $x->root_depth, 'CopyFromParent',
                 ($x_coord, $y_coord), $width,
                 $height, $border_w);  
...

DESCRIPCIÓN

X11::Protocol es una interfaz del lado del cliente al Protocolo X11 (ver X(1) para información sobre X11), que permite a los programas de Perl mostrar ventanas y gráficos en servidores X11.

Una descripción completa del protocolo está más allá del alcance de esta documentación; para obtener información completa, consulte el Protocolo del Sistema de Ventanas X, Versión X 11, disponible en formato Postscript o fuente *roff en "ftp://ftp.x.org", o el Volumen 0: Manual de Referencia del Protocolo X de la serie de libros de O'Reilly & Associates sobre X (ISBN 1-56592-083-X, "http://www.oreilly.com"), que contiene la mayor parte de la misma información.

DESCARGO DE RESPONSABILIDAD

``El protocolo contiene muchos mecanismos de gestión que no están destinados a aplicaciones normales. No todos los mecanismos son necesarios para construir una interfaz de usuario particular. Es importante tener en cuenta que el protocolo está destinado a proporcionar mecanismos, no políticas.'' -- Robert W. Scheifler

MÉTODOS BÁSICOS

new

$x = X11::Protocol->new();
$x = X11::Protocol->new($nombre_display);
$x = X11::Protocol->new($conexion);
$x = X11::Protocol->new($nombre_display, [$tipo_auth, $datos_auth]);
$x = X11::Protocol->new($conexion, [$tipo_auth, $datos_auth]);

Abre una conexión a un servidor. $nombre_display debe ser un nombre de pantalla X, con el formato 'host:num_display.num_pantalla'; si no se proporcionan argumentos, se utiliza el contenido de la variable de entorno DISPLAY. Alternativamente, se puede proporcionar una conexión preabierta, de una de las clases de X11::Protocol::Connection (ver X11::Protocol::Connection, X11::Protocol::Connection::FileHandle, X11::Protocol::Connection::Socket, X11::Protocol::Connection::UNIXFH, X11::Protocol::Connection::INETFH, X11::Protocol::Connection::UNIXSocket, X11::Protocol::Connection::INETSocket). Los datos de autorización se obtienen utilizando X11::Auth o el segundo argumento. Si la pantalla se especifica mediante $nombre_display, en lugar de $conexion, también se realiza un choose_screen(), con la pantalla 0 por defecto si el '.num_pantalla' del nombre de la pantalla no está presente. Devuelve el nuevo objeto de protocolo.

new_rsrc

$x->new_rsrc;

Devuelve un identificador de recurso nuevo. Se requiere un ID de recurso único para cada objeto que el servidor crea en nombre del cliente: ventanas, fuentes, cursores, etc. (los ID son elegidos por el cliente en lugar del servidor para mayor eficiencia: el cliente no tiene que esperar a que el servidor confirme la creación antes de empezar a usar el objeto).

Tenga en cuenta que el número total de ID de recursos disponibles, aunque grande, es finito. A partir del establecimiento de una conexión, los ID de recursos se asignan secuencialmente a partir de un rango cuyo tamaño depende del servidor (comúnmente 2**21, unos 2 millones). Si se alcanza este límite y el servidor no admite la extensión XC_MISC, las llamadas posteriores a new_rsrc fallarán. Si el servidor admite esta extensión, el módulo intentará solicitar un nuevo rango de ID libres al servidor. Esto debería permitir que el programa continúe, pero es una solución imperfecta, ya que con el tiempo el conjunto de ID disponibles puede fragmentarse, requiriendo solicitudes de rango de ida y vuelta cada vez más frecuentes al servidor. Para programas de larga duración, el mejor enfoque podría ser hacer un seguimiento de los ID libres a medida que se destruyen los recursos. Sin embargo, en la versión actual no se proporciona soporte especial para esto.

handle_input

$x->handle_input;

Obtiene un bloque de información del servidor y hace algo con él. Si es un error, lo maneja usando el manejador del objeto de protocolo ('error_handler', por defecto es terminar el programa con un mensaje explicativo). Si es un evento, lo pasa al manejador de eventos elegido, o lo pone en una cola si el manejador es 'queue'. Si es una respuesta a una solicitud, la guarda usando el hash 'replies' del objeto para su posterior procesamiento.

atom_name

$nombre = $x->atom_name($atom);

Devuelve la cadena correspondiente al átomo $atom. Esto es similar a la solicitud GetAtomName, pero almacena el resultado en caché para mayor eficiencia.

atom

$atom = $x->atom($nombre);

La operación inversa; devuelve el átomo (numérico) correspondiente a $nombre. Esto es similar a la solicitud InternAtom, pero almacena el resultado en caché.

choose_screen

$x->choose_screen($num_pantalla);

Indica que se prefiere usar una pantalla particular de la pantalla. La información por pantalla, como 'root', 'width_in_pixels' y 'white_pixel' estará disponible como

$x->{'root'}

en lugar de

$x->{'screens'}[$num_pantalla]{'root'}

CONSTANTES SIMBÓLICAS

Generalmente, las constantes simbólicas utilizadas por el protocolo, como 'CopyFromParent' o 'PieSlice', se pasan a los métodos como cadenas de texto, y el módulo las convierte en números. Sus nombres son los mismos que los de la especificación del protocolo, incluida la capitalización, pero con guiones ('-') cambiados por guiones bajos ('_') para que se parezcan más a Perl. Si por alguna razón desea realizar la conversión usted mismo, los siguientes métodos están disponibles:

num

$num = $x->num($tipo, $str)

Dada una cadena que representa una constante y una cadena que especifica qué tipo de constante es, devuelve el número correspondiente. $tipo debe ser un nombre como 'VisualClass' o 'GCLineStyle'. Si el nombre no se reconoce, se devuelve intacto.

interp

$nombre = $x->interp($tipo, $num)

La operación inversa; dado un número y una cadena que especifica su tipo, devuelve una cadena que representa la constante.

Puede deshabilitar interp() y la interpretación interna de números del módulo estableciendo $x->{'do_interp'} a cero. Por supuesto, esto no es muy útil, a menos que tenga sus propias definiciones para todas las constantes.

SOLICITUDES

solicitud

$x->solicitud('CreateWindow', ...);
$x->req('CreateWindow', ...);
$x->CreateWindow(...);

Envía una solicitud de protocolo al servidor y obtiene la respuesta, si la hay. Para los nombres e información de las solicitudes individuales, véase más abajo y/o el manual de referencia del protocolo.

solicitud_robusta

$x->solicitud_robusta('CreateWindow', ...);

Al igual que solicitud(), pero si el servidor devuelve un error, devuelve la información del error en lugar de llamar al manejador de errores (que por defecto simplemente falla). Si la solicitud tiene éxito, devuelve una referencia de array que contiene lo que solicitud() devolvería. De lo contrario, devuelve el tipo de error, los códigos de operación principales y secundarios de la solicitud fallida, y la información adicional del error, si la hay. Tenga en cuenta que incluso si la solicitud normalmente no tendría respuesta, este método aún tiene que esperar un tiempo de ida y vuelta para ver si ocurrió un error. Si le preocupa el rendimiento, debe diseñar su manejo de errores para que sea asíncrono.

agregar_respuesta

$x->agregar_respuesta($numero_secuencia, \$var);

Añade un marcador de posición para una respuesta esperada al hash 'respuestas' del objeto. Cuando llegue una respuesta numerada $numero_secuencia, se almacenará en $var.

eliminar_respuesta

$x->eliminar_respuesta($numero_secuencia);

Elimina la entrada en 'respuestas' para la respuesta especificada. (Esto debe hacerse después de recibir la respuesta).

enviar

$x->enviar('CreateWindow', ...);

Envía una solicitud, pero no espera una respuesta. Debe manejar la respuesta, si la hay, usted mismo, utilizando agregar_respuesta(), manejar_entrada(), eliminar_respuesta(), y desempaquetar_respuesta(), generalmente en ese orden.

desempaquetar_respuesta

$x->desempaquetar_respuesta('GetWindowAttributes', $datos);

Interpreta los datos de respuesta en bruto $datos, según el formato de respuesta para la solicitud con nombre. Devuelve datos en el mismo formato que "solicitud($nombre_solicitud, ...)".

Esta sección solo incluye un resumen de llamada corto para cada solicitud; para descripciones completas, consulte el estándar del protocolo. El orden de los argumentos suele ser el mismo que se enumera en la especificación, pero generalmente no es necesario pasar las longitudes de cadenas o arrays, ya que perl se encarga de ellas. Las constantes simbólicas generalmente se pasan como cadenas. La mayoría de las respuestas se devuelven como listas, pero cuando hay muchos valores, se utiliza un hash. Las listas suelen ir al final; cuando hay más de una, cada una se pasa por referencia. En listas de estructuras de varias partes, cada elemento es una referencia de lista. Se insertan paréntesis en las listas de argumentos para mayor claridad, pero son opcionales. Las solicitudes se enumeran en orden por código de operación principal, por lo que las solicitudes relacionadas suelen estar juntas. Las respuestas siguen el '=>'.

EVENTOS

Para recibir eventos, primero configure el atributo 'event_mask' en una ventana para indicar qué tipos de eventos desea (consulte "pack_event_mask"). Luego, establezca el 'event_handler' del objeto de protocolo a una referencia de subrutina que manejará los eventos. Alternativamente, establezca 'event_handler' en 'queue', y recupere los eventos usando dequeue_event() o next_event(). En ambos casos, los eventos se devuelven como un hash. Por ejemplo, un evento MotionNotify típico podría verse así:

%event = ('name' => 'MotionNotify', 'sequence_number' => 12,
          'state' => 0, 'event' => 58720256, 'root' => 43,
          'child' => None, 'same_screen' => 1, 'time' => 966080746,
          'detail' => 'Normal', 'event_x' => 10, 'event_y' => 3,
          'code' => 6, 'root_x' => 319, 'root_y' => 235)

pack_event_mask

$mask = $x->pack_event_mask('ButtonPress', 'KeyPress', 'Exposure');

Crea una máscara de eventos (adecuada como 'event_mask' de una ventana) a partir de una lista de cadenas que especifican tipos de eventos.

unpack_event_mask

@event_types = $x->unpack_event_mask($mask);

La operación inversa; convierte una máscara de eventos obtenida del servidor en una lista de nombres de categorías de eventos.

dequeue_event

%event = $x->dequeue_event;

Si hay un evento esperando en la cola, devuélvelo.

next_event

%event = $x->next_event;

Al igual que XNextEvent() de Xlib, esta función es equivalente a

$x->handle_input until %event = dequeue_event;

pack_event

$data = $x->pack_event(%event);

Dado un evento en formato hash, empaquételo en una cadena. Esto solo es útil como argumento para SendEvent().

unpack_event

%event = $x->unpack_event($data);

La operación inversa; dada la información bruta de un evento (32 bytes), desempaquétela en formato hash. Normalmente, esto se hace automáticamente.

EXTENSIONES

Las extensiones de protocolo agregan nuevas solicitudes, tipos de eventos y tipos de errores al protocolo. El soporte para ellas está compartimentado en módulos dentro de la jerarquía de X11::Protocol::Ext::. Como ejemplo, consulte X11::Protocol::Ext::SHAPE. Puede saber si el módulo ha cargado una extensión mirando en

$x->{'ext'}{$extension_name}

Si la extensión se ha inicializado, este valor será una referencia a un array, [$request_mayor, $primer_evento, $primer_error, $obj], donde $obj es un objeto que contiene información privada de la extensión.

init_extension

$x->init_extension($name);

Inicializa una extensión: consulta al servidor para encontrar el número de solicitud de la extensión, luego carga el módulo correspondiente. Devuelve 0 si el servidor no admite la extensión nombrada, o si no existe ningún módulo para interactuar con ella.

init_extensions

$x->init_extensions;

Inicializa las extensiones de protocolo. Esto realiza una solicitud ListExtensions, luego llama a init_extension() para cada extensión que el servidor admita.

ESCRIBIR EXTENSIONES

Internamente, el módulo X11::Protocol se basa en tablas. Todo lo que una extensión tiene que hacer es agregar nuevas entradas a las tablas del objeto de protocolo. Un módulo de extensión debe "use X11::Protocol", y debe definir un método new()

X11::Protocol::Ext::NAME
  ->new($x, $request_num, $event_num, $error_num)

donde $x es el objeto de protocolo y $request_num, $event_num y $error_num son los valores devueltos por QueryExtension().

El método new() debe agregar nuevos tipos de constantes como

$x->{'ext_const'}{'ConstantType'} = ['Constant', 'Constant', ...]

y configurar los hashes de traducción correspondientes de nombre a número, como

$x->{'ext_const_num'}{'ConstantType'} =
  {make_num_hash($x->{'ext_const'}{'ConstantType'})}

Los nombres de eventos van en

$x->{'ext_const'}{'Events'}[$event_number]

mientras que las especificaciones para el contenido de los eventos van en

$x->{'ext_event'}[$event_number]

cada elemento del cual es ya sea "[\&unpack_sub, \&pack_sub]" o "[$pack_format, $field, $field, ...]", donde cada $field es 'name', "['name', 'const_type']", o "['name', ['special_name_for_zero', 'special_name_for_one']]", donde 'special_name_for_one' es opcional.

Finalmente,

$x->{'ext_request'}{$major_request_number}

debe ser un array de arrays, con cada array ya sea "[$name, \&packit]" o "[$name, \&packit, \&unpackit]", y

$x->{'ext_request_num'}{$request_name}

debe inicializarse con "[$minor_num, $major_num]" para cada solicitud que la extensión defina.

nes. For examples of code that does all of this, look at X11::Protocol::Ext::SHAPE.

X11::Protocol exports several functions that might be useful in extensions (note that these are not methods).

relleno

$p = relleno $x;

Dado un entero, calcula la cantidad necesaria para redondearlo al múltiplo de 4 más cercano. Por ejemplo, relleno(5) es 3.

rellenar

$p = rellenar $str;

Dada una cadena, devuelve el número de bytes adicionales necesarios para que sea un múltiplo de 4. Equivale a "relleno(longitud($str))".

rellenado

$data = empaquetar(rellenado($str), $str);

Devuelve una cadena de formato, adecuada para empaquetar(), para una cadena rellenada hasta un múltiplo de 4 bytes. Por ejemplo, "empaquetar(rellenado('Hola'), 'Hola')" da "Hola\0\0\0".

hexi

$str = hexi $n;

Formatea un número en hexadecimal y le añade un "0x" al principio.

crear_hash_num

%hash = crear_hash_num(['A', 'B', 'C']);

Dado una referencia a una lista de cadenas, devuelve un hash que mapea las cadenas a números que representan su posición en la lista, como se usa en "$x->{'ext_const_num'}".

ERRORES

Este módulo es demasiado grande (~2500 líneas), demasiado lento (10 segundos para cargarse en una máquina lenta), demasiado ineficiente (los argumentos de las solicitudes se copian varias veces) y ocupa demasiada memoria (3000K para basicwin).

Si tienes más de 65535 respuestas pendientes a la vez, los números de secuencia pueden colisionar.

El protocolo es demasiado complejo.
