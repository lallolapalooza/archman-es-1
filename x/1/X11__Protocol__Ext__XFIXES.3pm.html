NOMBRE

X11::Protocol::Ext::XFIXES - extensión de "arreglos" misceláneos

SINOPSIS

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('XFIXES')
  or print "La extensión XFIXES no está disponible";

DESCRIPCIÓN

La extensión XFIXES agrega algunas características concebidas como "arreglos" a las omisiones en el protocolo X11 principal, incluyendo:

  • Eventos para cambios en la selección (el copiar y pegar entre clientes).
  • Obtención de la imagen del cursor actual, eventos de cambio de cursor, y nomenclatura y ocultación de cursores.
  • Objetos "región" en el lado del servidor que representan un conjunto de rectángulos.

SOLICITUDES

Las siguientes se hacen disponibles con una init_extension() por "EXTENSIONS" en X11::Protocol.

my $bool = $X->init_extension('XFIXES');

XFIXES versión 1.0

"($server_major, $server_minor) = $X->XFixesQueryVersion ($client_major, $client_minor)"
Negocia una versión de protocolo con el servidor. $client_major y $client_minor es lo que el cliente desearía, $server_major y $server_minor es lo que el servidor hará, lo cual podría ser menor a lo solicitado (pero no mayor).

El código actual en este módulo soporta hasta 4.0 y negocia automáticamente dentro de init_extension(), por lo que el uso directo de XFixesQueryVersion() no es necesario. Pedir una versión superior a la que el código soporta podría ser una mala idea.

"($atom, $str) = $X->XFixesChangeSaveSet ($window, $mode, $target, $map)"
Inserta o elimina $window (un XID) del "conjunto de guardado" de recursos a retener en el servidor cuando el cliente se desconecta. Esta es una versión extendida de la solicitud principal ChangeSaveSet().

$mode es "Insert" o "Delete".

$target es cómo se reparentará $window al cerrar el cliente, ya sea "Nearest" o "Root". El ChangeSaveSet() principal es "Nearest" y significa ir al siguiente ancestro de ventana no cliente. "Root" significa ir a la ventana raíz.

$map es "Map" o "Unmap" para aplicar a $window al cerrar. El ChangeSaveSet() principal es "Map".

$X->XFixesSelectSelectionInput ($window, $selection, $event_mask)>
Selecciona eventos "XFixesSelectionNotify" (ver "EVENTOS" abajo) para ser enviados a $window cuando la $selection (un átomo) cambia. 
$X->XFixesSelectSelectionInput ($my_window,
                                $X->atom('PRIMARY'),
                                0x07);

$window se proporciona en el "XFixesSelectionNotify" resultante. Probablemente funciona hacerla una ventana raíz. Las selecciones son globales para todo el servidor, por lo que la ventana no elige implícitamente una pantalla ni nada.

$event_mask tiene tres bits para qué subtipos de evento deben ser reportados.

                        bitpos  bitval
SetSelectionOwner         0      0x01
SelectionWindowDestroy    1      0x02
SelectionClientClose      2      0x04

Todavía no hay una función de empaquetado para estos, así que solo proporcione un entero, por ejemplo, 0x07 para los tres.

Ver examples/xfixes-selection.pl para un programa de ejemplo que escucha los cambios de selección con esta solicitud.

$X->XFixesSelectCursorInput ($window, $event_mask)>
Selecciona eventos "XFixesCursorNotify" (ver "EVENTOS" abajo) para ser enviados al cliente.

$window se proporciona en el "XFixesSelectionNotify" resultante. Probablemente funciona hacerla una ventana raíz. La imagen del cursor es global y los eventos son para cualquier cambio, no meramente dentro de $window.

$event_mask solo tiene un bit, solicitando cambios en el cursor mostrado,

                 bitpos  bitval
DisplayCursor      0      0x01

Todavía no hay una función de empaquetado para esto, solo proporcione el entero 1 o 0.

($root_x,$root_y, $width,$height, $xhot,$yhot, $serial, $pixels) = $X->XFixesGetCursorImage ()>
Devuelve el tamaño y el contenido de píxeles del cursor del puntero del ratón actualmente mostrado.

$root_x,$root_y devueltos son la ubicación del puntero en coordenadas de la ventana raíz (similar a QueryPointer()).

$width,$height es el tamaño de la imagen del cursor. $xhot,$yhot es la posición del "punto de activación" dentro de eso, que es el píxel que sigue a la ubicación del puntero.

$pixels es una cadena de bytes de valores de píxeles "ARGB" empaquetados. Cada uno es de 32 bits en orden de bytes del cliente, con $width en cada fila y $height tales filas y sin relleno entre ellas, por lo que un total de "4*$width*$height" bytes. Esto puede ser desempaquetado con, por ejemplo,

my @argb = unpack 'L*', $pixels; # cada uno 0xAARRGGBB
# el píxel superior izquierdo está en $argb[0]
my $alpha = ($argb[0] >> 24) & 0xFF;  # cada valor
my $red   = ($argb[0] >> 16) & 0xFF;  # 0 a 255
my $green = ($argb[0] >> 8)  & 0xFF;
my $blue  =  $argb[0]        & 0xFF;

La transparencia alfa está pre-multiplicada en los componentes RGB, por lo que si el alfa es cero (transparente), los componentes también son cero.

La máscara de bits principal de CreateCursor() siempre hace que los píxeles alfa=0 sean transparentes o alfa=255 opacos. La extensión RENDER (ver X11::Protocol::Ext::RENDER) puede crear cursores parcialmente transparentes.

No hay una forma directa de obtener la imagen de un cursor por su XID (excepto algo arriesgado como un GrabPointer() para hacerlo el cursor mostrado). Generalmente, los XID de cursor solo son creados por un cliente, así que no hay necesidad de leerlos de vuelta (y el XID del cursor no puede ser leído de una ventana arbitraria — aunque la extensión XTEST puede hacer algunas comparaciones, según X11::Protocol::Ext::XTEST).

Como referencia, en el servidor X.org alrededor de la versión 1.11, el servidor puede iniciarse sin ningún cursor, y cuando eso ocurre, un intento de XFixesGetCursorImage() da un error "Cursor". En la práctica, esto probablemente solo ocurre al usar un Xvfb básico o similar, ya que en el uso normal xdm o el gestor de ventanas casi seguramente habrán configurado un cursor.

Ver examples/xfixes-cursor-image.pl para un programa de ejemplo que obtiene la imagen del cursor con esta solicitud.

XFIXES versión 2.0

Un objeto región en el servidor representa un conjunto de rectángulos, cada uno con x,y,width,height, con x,y positivas o negativas, y el conjunto posiblemente compuesto por secciones desconectadas, etc. (Básicamente una copia en el lado del servidor del código de región de Xlib, ver XCreateRegion(3).)

Cada rectángulo podría ser solo 1x1 para un solo píxel, por lo que una región puede representar cualquier bitmap, pero está orientada a la aritmética de rectángulos que surge de ventanas superpuestas, etc.

"$X->XFixesCreateRegion ($region, $rect...)"
Crea $region (un nuevo XID) como una región y la establece a la unión de los rectángulos dados, o vacía si no hay ninguno. Cada $rect es un arrayref "[$x,$y,$width,$height]". 
my $region = $X->new_rsrc;
$X->XFixesCreateRegion ($region, [0,0,10,5], [100,100,1,1]);

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

"$X->XFixesCreateRegionFromBitmap ($region, $bitmap)"
Crea una región inicializada a partir de los bits 1 de $bitmap (un XID de pixmap). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromBitmap ($region, $bitmap);
"$X->XFixesCreateRegionFromWindow ($region, $window, $kind)"
Crea una región inicializada a partir de la forma de $window (un XID). $kind es ya sea "Bounding" o "Clip" según la extensión SHAPE (ver X11::Protocol::Ext::SHAPE). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromBitmap ($region, $window, 'Clip');

No es necesario "$X->init_extension('SHAPE')" antes de usar esta solicitud. Cualquier forma está solo en el servidor y resulta en una $region de un solo rectángulo o un conjunto de rectángulos para una forma.

"$X->XFixesCreateRegionFromGC ($region, $gc)"
Crea una región inicializada a partir de la máscara de recorte de $gc (un XID). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromGC ($region, $gc);

La región es relativa al "clip_x_origin" y "clip_y_origin" del GC, es decir, esos desplazamientos no se aplican a la X,Y en la región.

"$X->XFixesCreateRegionFromPicture ($region, $picture)"
Crea una región inicializada a partir de una $picture de RENDER (un XID). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromBitmap ($region, $picture);

La región es relativa al "clip_x_origin" y "clip_y_origin" de la imagen, es decir, esos desplazamientos no se aplican a la X,Y en la región.

Los objetos de imagen provienen de la extensión RENDER (ver X11::Protocol::Ext::RENDER). Esta solicitud siempre existe, pero no es útil sin RENDER.

"$X->XFixesDestroyRegion ($region)"
Destruye $region.
"$X->XFixesSetRegion ($region, $rect...)"
Establece $region a la unión de los rectángulos dados, o vacía si no hay ninguno. Cada $rect es un arrayref "[$x,$y,$width,$height]", como en XFixesCreateRegion() arriba. 
$X->XFixesSetRegion ($region, [0,0,20,10], [100,100,5,5])
"$X->XFixesCopyRegion ($dst, $src)"
Copia una región $src a la región $dst.
"$X->XFixesUnionRegion ($src1, $src2, $dst)"
"$X->XFixesIntersectRegion ($src1, $src2, $dst)"
"$X->XFixesSubtractRegion ($src1, $src2, $dst)"
Establece la región $dst a la unión o intersección respectiva de $src1 y $src2, o la resta $src1 - $src2.

$dst puede ser una de las regiones fuente si se desea, para cambiarla en el lugar.

"$X->XFixesInvertRegion ($src, $rect, $dst)"
Establece la región $dst al inverso de $src delimitado por el rectángulo $rect, es decir, $rect menos $src. $rect es un arrayref "[$x,$y,$width,$height]". 
$X-XFixesInvertRegion ($src, [10,10, 200,100], $dst)>

$dst puede ser el mismo que $src para hacer una inversión "en el lugar".

"$X->XFixesTranslateRegion ($region, $dx, $dy)"
Mueve el área cubierta por $region por un desplazamiento de $dx y $dy (enteros).
"$X->XFixesRegionExtents ($dst, $src)"
Establece la región $dst a los límites rectangulares de la región $src. Si $src está vacía, entonces $dst se establece vacía.
"($bounding, @parts) = $X->XFixesFetchRegion ($region)"
Devuelve los rectángulos que cubren $region. Cada elemento devuelto es un arrayref 
[$x,$y,$width,$height]

El primero es un rectángulo delimitador, y después de eso los rectángulos individuales que componen la región, en orden "YX-banded".

my ($bounding, @rects) = $X->XFixesFetchRegion ($region);
print "bounded by ",join(',',@$bounding);
foreach my $rect (@rects) {
  print "  rect part ",join(',',@$rect);
}
"$X->XFixesSetGCClipRegion ($gc, $clip_x_origin, $clip_y_origin, $region)"
Establece la máscara de recorte de $gc (un XID) a $region (un XID), y establece el origen de recorte a $clip_x_origin,$clip_x_origin.

Esto es similar a SetClipRectangles() del núcleo, pero los rectángulos provienen de $region (y sin parámetro de "ordenamiento").

"$X->XFixesSetWindowShapeRegion ($window, $kind, $x_offset, $y_offset, $region)"
Establece la máscara de forma de $window (un XID) a $region, en el desplazamiento $x_offset,$y_offset dentro de la ventana. $kind es un ShapeKind, ya sea "Bounding" o "Clip".

Esto es similar a ShapeMask() (ver X11::Protocol::Ext::SHAPE) con la operación "Set" y una región en lugar de un mapa de bits.

No es necesario "$X->init_extension('SHAPE')" antes de usar esta solicitud. Si SHAPE no está disponible en el servidor, entonces presumiblemente esta solicitud devuelve un error.

"$X->XFixesSetPictureClipRegion ($picture, $clip_x_origin, $clip_y_origin, $region)"
Establece la máscara de recorte de la $picture de RENDER (un XID) a $region, y establece el origen de recorte a $clip_x_origin,$clip_x_origin.

Esto es similar a RenderSetPictureClipRectangles(), pero los rectángulos provienen de $region.

Los objetos de imagen provienen de la extensión RENDER (ver X11::Protocol::Ext::RENDER). La solicitud siempre existe, pero no es útil sin RENDER.

"$X->XFixesSetCursorName ($cursor, $str)"
Establece un nombre para el objeto cursor $cursor (un XID). La cadena de nombre $str se interna como un átomo en el servidor y, por lo tanto, debe ser una cadena de bytes de caracteres latin-1. (Quizás en el futuro eso se imponga aquí, o se conviertan caracteres amplios).
"($atom, $str) = $X->XFixesGetCursorName ($cursor)"
Obtiene el nombre del cursor del puntero del ratón $cursor (un XID), tal como lo establece XFixesSetCursorName().

El $atom devuelto es el átomo de nombre (un entero) y $str es la cadena de nombre (que es el nombre del átomo). Si no hay nombre para $cursor, entonces $atom es la cadena "None" (o 0 si no hay "$X->{'do_interp'}") y $str está vacío "".

"($x,$y, $width,$height, $xhot,$yhot, $serial, $pixels, $atom, $str) = $X->XFixesGetCursorImageAndName ()"
Obtiene la imagen y el nombre del cursor del puntero del ratón actual. La devolución es según XFixesGetCursorImage() más XFixesGetCursorName() descrito anteriormente.
"$X->XFixesChangeCursor ($src, $dst)"
Cambia el contenido del cursor $dst (un XID) al contenido del cursor $src (un XID).
"$X->XFixesChangeCursorByName ($src, $dst_str)"
Cambia el contenido de cualquier cursor con el nombre $dst_str (una cadena) al contenido del cursor $src. Si no hay cursores con el nombre $dst_str, no hace nada.

XFIXES versión 3.0

"$X->XFixesExpandRegion ($src, $dst, $left,$right,$top,$bottom)"
Establece la región $dst (un XID) a los rectángulos de la región $src, con cada rectángulo expandido por $left, $right, $top, $bottom píxeles en esas direcciones respectivas.

Nota que no importa cómo se exprese $src como rectángulos, el efecto es como si cada píxel individual en $src se expandiera y se tomara la unión del resultado.

XFIXES versión 4.0

"$X->XFixesHideCursor ($window)"
"$X->XFixesShowCursor ($window)"
Oculta o muestra el cursor del puntero del ratón mientras está en $window (un XID) o en cualquier subventana de $window.

Este ocultamiento para cada ventana es una configuración por cliente. Si más de un cliente solicita ocultar, el cursor permanece oculto hasta que todos ellos vuelvan a "mostrar". Si un cliente se desconecta o se mata, sus ocultamientos se deshacen automáticamente.

XFIXES versión 5.0

"$X->XFixesCreatePointerBarrier ($barrier, $drawable, $x1,$y1, $x2,$y2, $directions)"
"$X->XFixesCreatePointerBarrier ($barrier, $drawable, $x1,$y1, $x2,$y2, $directions, $deviceid...)"
Crea $barrier (un nuevo XID) como un objeto barrera que previene el movimiento del puntero del ratón del usuario a través de una línea entre los puntos "$x1,$y1" y "$x2,$y2". Por ejemplo 
my $barrier = $X->new_rsrc;
$X->XFixesCreatePointerBarrier ($barrier, $X->root,
                                100,100, 100,500,





NOMBRE


X11::Protocol::Ext::XFIXES - X Fixes extension






SINOPSIS


 use X11::Protocol::Ext::XFixes;
 use X11::Protocol::Ext::XInputExtension; # optionally
 use X11::Protocol::Ext::XINERAMA; # optionally

 my $X = X11::Protocol->new;

 # create some regions
 my $region = $X->XFixesCreateRegion( ... );
 my $region2 = $X->XFixesCreateRegion(...);

 # manipulate regions
 $X->XFixesSetRegion($region, ...);
 $X->XFixesUnionRegion($region, $region, $region2);
 # etc.

 # get region info
 my ($x1, $y1, $x2, $y2) = $X->XFixesFetchRegion($region); # (x2,y2) is exclusive
 my ($width, $height) = $X->XFixesFetchRegion($region); # for width/height
 my ($ext_x1, $ext_y1, $ext_x2, $ext_y2) = $X->XFixesFetchRegion($region); # region bounds
 my ($num_rects, $num_points) = $X->XFixesFetchRegion($region); # for subregions
 # etc.

 # pointer barriers
 $X->XFixesSetPointerBarrier($x1, $y1, $x2, $y2, $directions);
 $X->XFixesSetPointerBarrier($x1, $y1, $x2, $y2, $directions, $deviceid, ...);
 $X->XFixesDestroyPointerBarrier($barrier);

 # selection input
 $X->XFixesSelectSelectionInput($window, $selection, $type);

 # cursor input
 $X->XFixesSelectCursorInput($window, $types);

 # cursor image
 my $cursor_image = $X->XFixesGetCursorImage();

 # name cursors
 $X->XFixesSetCursorName($cursor, $name);

 #...







DESCRIPCIÓN


This module implements the X Fixes extension protocol.


The extension is versioned. Version 1.0 is available from server
    version 1.1.


The extension is versioned. Version 2.0 is available from server
    version 1.6.




REQUESTS



  
"$X->XFixesCreateRegion ($rects)"

  
Create a region. $rects is a list of rectangles,
      where each rectangle is a list [x1, y1, x2, y2].
      x2 and y2 are exclusive.
      An empty list creates an empty region.

  
"$X->XFixesDestroyRegion ($region)"

  
Destroy the given region (an XID).

  
"$X->XFixesSetRegion ($region, $rects)"

  
Set the region to be the list of rectangles. Same format as for
      CreateRegion.

  
"$X->XFixesCopyRegion ($region, $source_region)"

  
Set the region to be a copy of $source_region.

  
"$X->XFixesUnionRegion ($region, $reg1, $reg2)"

  
Set the region to be the union of $reg1 and
      $reg2.

  
"$X->XFixesInverseRegion ($region, $reg, $bounding_box)"

  
Set the region to be the inverse of $reg within
      the specified $bounding_box rectangle.
      $bounding_box is a rectangle [x1, y1, x2, y2].

  
"$X->XFixesDifferenceRegion ($region, $reg1, $reg2)"

  
Set the region to be the difference of $reg1 and
      $reg2 (pixels in $reg1 but
      not in $reg2).

  
"$X->XFixesIntersectionRegion ($region, $reg1, $reg2)"

  
Set the region to be the intersection of $reg1 and
      $reg2.

  
"$X->XFixesSubtractRegion ($region, $reg1, $reg2)"

  
Set the region to be $reg1 minus $reg2.

  
"$X->XFixesTranslateRegion ($region, $dx, $dy)"

  
Translate the region by ($dx, $dy).

  
"$X->XFixesFetchRegion ($region)"

  
Fetch the rectangles comprising the region. Returns a list of rectangles.
      Each rectangle is [x1, y1, x2, y2].
      x2, y2 are exclusive.

  
"$X->XFixesFetchRegion ($region, $bounding_box)"

  
Fetch the rectangles comprising the region that are contained within the
      $bounding_box. This is useful to query only a
      portion of a large region.

  
"$X->XFixesQueryVersion ($major_version, $minor_version)"

  
Query the server's supported version of the XFixes extension.

  
"$X->XFixesSelectSelectionInput ($window, $selection, $type)"

  
Select input events for a selection. $window is
      the window to receive events. $selection is the
      atom for the selection (e.g. primary, secondary). $type
      is an OR of bits:

      
OwnerChanged        1 # selection owner changed
SelectionWindowDestroy 2 # selection window destroyed
SelectionClientClose 4 # selection client closed


  
"$X->XFixesGetSelectionOwner ($selection)"

  
Get the current owner of the selection.

  
"$X->XFixesSelectCursorInput ($window, $types)"

  
Select input events for cursor changes. $window is
      the window to receive events. $types is an OR of
      bits:

      
DisplayCursor    1


  
"$X->XFixesGetCursorImage ()"

  
Get the current cursor image. Returns a hash with the following keys:

      
x, y               pointer position relative to root window
width, height      dimensions of the cursor image
xhot, yhot         hotspot of the cursor
cursor_serial      serial number of the cursor image
pixels             list of pixel values for the cursor image
mask               list of pixel values for the cursor mask


  
"$X->XFixesChangeCursor ($window, $cursor)"

  
Change the cursor for the given window. $cursor
      can be an XID of a cursor created with Xlib's
      XCreateFontCursor or
      XCreatePixmapCursor.

  
"$X->XFixesChangeCursorWithDevice ($deviceid, $window, $cursor)"

  
Like XFixesChangeCursor but for a specific device.

  
"$X->XFixesSetCursorName ($cursor, $name)"

  
Set the name of a cursor. $cursor is a cursor XID.
      $name is a string.

  
"$X->XFixesSetClientName ($client_name)"

  
Set the client name. $client_name is a string.

  
"$X->XFixesSetPointerBarrier ($x1, $y1, $x2, $y2, $directions)"

  
Set a pointer barrier. This is a line segment defined by two points
      ($x1, $y1) and ($x2, $y2).
      These coordinates are relative to the $drawable's
      window.

      
X,Y coordinates are screen coordinates on the screen of
$drawable. The line must be horizontal or
vertical, so either "$x1==$x2" or
"$y1==$y2" (but not both). A
horizontal barrier is across the top edge of the line pixels, a vertical
barrier is along the left edge of the line pixels.

      $directions is an integer OR of the
      follow bits for which directions to allow some movement across the line.
      A value 0 means no movement across is allowed.

          
PositiveX    1
PositiveY    2
NegativeX    4
NegativeY    8


      For example on a horizontal line, value 8 would allow the
      pointer to move through the line in the negative Y direction (up the
      screen), and movement in the positive Y direction (down the screen)
      would still be forbidden.

      $directions can let the user move the
      mouse out of some sort of forbidden region but not go back in.

      Optional $deviceid arguments are X
      Input Extension 2.0 devices the barrier should apply to (see
      X11::Protocol::Ext::XInputExtension). With no arguments the barrier is
      just for the core protocol mouse pointer. Each argument can be

          
device ID                integer
"AllDevices"             enum string, 0
"AllMasterDevices"       enum string, 1


      It's not necessary to
      "$X->init_extension('XInputExtension')"
      before using this barrier request.

      The user can move the mouse pointer to go around a barrier
      line but by putting lines together a region can be constructed keeping
      the pointer inside or outside, or even a maze to trick the user!

      Touchscreen pad input is not affected by barriers, and
      "$X->WarpPointer()" can still move
      the pointer anywhere.

      One intended use is when a Xinerama screen (see
      X11::Protocol::Ext::XINERAMA) is made from monitors of different pixel
      sizes so parts of the logical screen extent are off the edge of one of
      the smaller monitors. Barriers can prevent the user losing the mouse in
      one of those dead regions.

      For reference, some X.org server versions prior to some time
      around version 1.14 did not accept $deviceid
      arguments in the request and gave a
      "Length" error on attempting to pass
      them. Those servers might have given an
      "Implementation" error anyway (for
      barrier feature not yet implemented).

  
"$X->XFixesDestroyPointerBarrier ($barrier)"

  
Destroy the given barrier (an XID).










EVENTOS


The following events have the usual fields


name             "XFixes..."
synthetic        true if from a SendEvent
code             integer opcode
sequence_number  integer



  
"XFixesSelectionNotify"

  
This is sent to the client when selected by
      "XFixesSelectSelectionInput" above. It
      reports changes to the selection. The event-specific fields are
        
subtype         enum string
window          XID
owner           XID of owner window, or "None"
selection       atom integer
time            integer, server timestamp
selection_time  integer, server timestamp


    "subtype" is one of

        
SetSelectionOwner
SelectionWindowDestroy
SelectionClientClose


    "time" is when the event was
      generated, "selection_time" is when
      the selection was owned.

  
"XFixesCursorNotify"

  
This is sent to the client when selected by
      XFixesSelectCursorInput() above. It reports when
      the currently displayed mouse pointer cursor has changed. It has the
      following event-specific fields,
        
subtype         enum string, currently always "DisplayCursor"
window          XID
cursor_serial   integer
time            integer, server timestamp
cursor_name     atom or "None" (XFIXES 2.0 up)


    "subtype" is
      "DisplayCursor" when the displayed cursor has changed. This is
      the only subtype currently.

    "cursor_serial" is a serial
      number as per XFixesGetCursorImage(). A client
      can use this to notice when the displayed cursor is something it has
      already fetched with XFixesGetCursorImage().

    "cursor_name" is the atom of
      the name given to the cursor by
      "XFixesSetCursorName", or string
      "None" if no name. This field is new in XFIXES 2.0 and is
      present in the event unpack only if the server does XFIXES 2.0 or
      higher. For "$X->pack_event()",
      "cursor_name" is optional and the
      field is set if given.
