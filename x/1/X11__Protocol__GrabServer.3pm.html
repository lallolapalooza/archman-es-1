X11::Protocol::GrabServer(3) Documentación de Perl aportada por el usuario X11::Protocol::GrabServer(3)

NOMBRE

X11::Protocol::GrabServer -- Captura del servidor orientada a objetos

SINOPSIS

use X11::Protocol::GrabServer;
{
  my $grab = X11::Protocol::GrabServer->new ($X); 
  do_some_things();
  # UngrabServer cuando $grab sea destruido
}

DESCRIPCIÓN

Este es un enfoque orientado a objetos para GrabServer / UngrabServer en una conexión de "X11::Protocol". Un objeto de captura representa una captura de servidor deseada y su destrucción la libera.

El primer objeto de captura en una conexión realiza un GrabServer() y el último destruido realiza un UngrabServer(). La idea es que es más fácil gestionar la vida útil de un objeto de captura en un bloque, etc., que asegurarse de capturar todas las salidas.

Los objetos de captura múltiples pueden superponerse o anidarse. Se realiza un único GrabServer() y permanece hasta que se destruye el último objeto. Esto es bueno en una biblioteca o subfunción donde un UngrabServer() debería esperar hasta el final de la captura externa deseada.

Una captura de servidor se utiliza normalmente para hacer que algunas operaciones sean atómicas, por ejemplo, algo global como propiedades de la ventana raíz. Un objeto temporal basado en bloques como el de la sinopsis es típico. También es posible mantener un objeto de captura durante un tiempo prolongado, quizás para alguna interacción con el servidor impulsada por el estado.

Se debe tener cuidado de no capturar durante demasiado tiempo, ya que otros programas cliente quedan bloqueados. Además, si un programa de captura se cuelga, el servidor será inutilizable hasta que se elimine el programa o se rompa su conexión de servidor TCP, etc.

Referencia débil $X

Si las referencias débiles de Perl están disponibles (lo que significa Perl 5.6 y superior y "Scalar::Util" con su código XS habitual), entonces un objeto de captura solo mantiene una referencia débil a la conexión $X objetivo. Esto significa que la captura no mantiene viva la conexión una vez que nada más está interesado. Cuando se destruye una conexión, el servidor la libera automáticamente y, por lo tanto, no es necesario un UngrabServer() explícito en ese caso.

El principal efecto del debilitamiento es que $X puede ser recolectado por el recolector de basura en cualquier lugar dentro de un bloque de captura, lo mismo que si no hubiera captura. Sin el debilitamiento, esperaría hasta el final del bloque. En la práctica, esto rara vez marca la diferencia.

En el futuro, si una conexión de "X11::Protocol" tiene la noción de un cierre explícito, la intención sería omitir también cualquier UngrabServer() en ese caso, es decir, tratar una conexión cerrada de la misma manera que una conexión debilitada y eliminada.

Actualmente no se presta atención a si el servidor ha desconectado el enlace. Se realiza un UngrabServer() en la destrucción de la manera habitual. Si el servidor se ha desconectado, se produce una "SIGPIPE" o "EPIPE" igual que para cualquier otra solicitud enviada a $X.

FUNCIONES

"$g = X11::Protocol::GrabServer->new ($X)"
$X es un objeto "X11::Protocol". Crea y devuelve un objeto $g que representa una captura del servidor $X.

Si esta nueva captura $g es la primera nueva captura en $X, entonces se realiza un "$X->GrabServer".

"$g->ungrab ()"
Libera explícitamente el objeto $g. Se realiza una liberación automáticamente cuando se destruye $g, pero "$g->ungrab()" puede hacerlo antes.

Si $g ya está liberado, no hace nada.

"$g->grab ()"
Vuelve a capturar con el objeto $g. Esto se puede usar después de un "$g->ungrab()" para capturar de nuevo con el mismo objeto, lo mismo que si se creara nuevo.

Si $g ya está capturando, no hace nada.

"$bool = $g->is_grabbed ()"
Devuelve verdadero si $g está capturando. Esto es verdadero cuando se crea por primera vez, o falso después de un "$g->ungrab()".

Esta función solo es el estado de $g. Puede haber otros objetos "GrabServer" que estén capturando el servidor.
