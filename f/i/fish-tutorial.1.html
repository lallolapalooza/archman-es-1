¿POR QUÉ

FISH?

Fish es un shell de línea de comandos completamente equipado (como bash o zsh) que es inteligente y fácil de usar. Fish soporta características potentes como resaltado de sintaxis, autocompletado y sugerencias automáticas que simplemente funcionan, sin nada que aprender o

configurar.

Si quieres hacer tu línea de comandos más productiva, más útil y má

s divertida, sin aprender un montón de sintaxis arcanas y opciones d
e configuración, ¡entonces fish podría ser justo lo que estás buscando!

A diferencia de otros shells, fish tiene un comando ordinario para configurar variables: set, que toma un nombre de variable y luego su

valor. 
> set name 'M

> echo $name
Mister Noodle

(Nota las comillas: sin ellas, Mister y Noodle habrían sido argumentos separados, y $name se habría convertido en una lista

VARIABLES

Variables are created when first assigned to. They are expanded with a dollar sign: $variable.

Unlike other shells, variables are not further split after substitution:

> mkdir $name
> ls
Mister Noodle

In bash, this would have created two directories "Mister" and "Noodle". In fish, it created only one: the variable had the value "Mister Noodle", so that is the argument that was passed to mkdir, spaces and all.

You can erase (or "delete") a variable with -e or --erase

> set -e MyVariable
> env | grep MyVariable
(no output)

For more, see Variable expansion <#expand-variable>.

EXPORTACIONES (VARIABLES DEL SHELL)

A veces necesitas que una variable esté disponible para un comando externo, a menudo como una configuración. Por ejemplo, muchos programas como git o man leen la variable $PAGER para determinar tu localizador de texto preferido (el programa que te permite desplazarte por el texto). Otras variables usadas de esta manera incluyen $BROWSER, $LANG (para configurar tu idioma) y $PATH. Notarás que estas están escritas en MAYÚSCULAS, pero eso es solo una convención.

Para pasar una variable a un comando externo, debe ser "exportada". Esto se hace con un indicador para set, ya sea --export o simplemente -x.

> set -x MyVariable SomeValue
> env | grep MyVariable
MyVariable=SomeValue

También se puede des-exportar con --unexport o -u.

¡Esto también funciona a la inversa! Si fish es iniciado por otra cosa, hereda las variables exportadas de su padre. Así que si tu emulador de terminal inicia fish, y este exporta $LANG configurado a en_US.UTF-8, fish recibirá esa configuración. Y lo que sea que haya iniciado tu emulador de terminal también le dio *a este* algunas variables que luego pasará a menos que decida específicamente no hacerlo. Así es como fish generalmente recibe los valores para cosas como $LANG, $PATH y $TERM, sin que tengas que especificarlos de nuevo.

Las variables exportadas pueden ser locales, globales o universales - ¡"exportada" no es un ámbito <#variables-scope>! Normalmente las harías globales mediante set -gx MyVariable SomeValue.

Para más información, ver Exportación de variables <#variables-export>.

LISTAS

El comando set anterior utilizó comillas para asegurar que Mister Noodle fuera un solo argumento. Si hubieran sido dos argumentos, entonces name habría sido una lista de longitud 2. De hecho, todas las variables en fish son realmente listas, que pueden contener cualquier número de valores, o ninguno.

Algunas variables, como $PWD, solo tienen un valor. Por convención, hablamos del valor de esa variable, pero en realidad nos referimos a su primer (y único) valor.

Otras variables, como $PATH, realmente tienen múltiples valores. Durante la expansión de variables, la variable se expande para convertirse en múltiples argumentos:

> echo $PATH
/usr/bin /bin /usr/sbin /sbin /usr/local/bin

Las variables cuyo nombre termina en "PATH" se dividen automáticamente en dos puntos para convertirse en listas. Se unen usando dos puntos cuando se exportan a subcomandos. Esto es para compatibilidad con otras herramientas, que esperan que $PATH use dos puntos. También puedes agregar explícitamente esta peculiaridad a una variable con set --path, o eliminarla con set --unpath.

Las listas no pueden contener otras listas: no hay recursión. Una variable es una lista de cadenas, punto final.

Obtén la longitud de una lista con count:

> count $PATH
5

Puedes añadir (o anteponer) a una lista asignando la lista a sí misma, con algunos argumentos adicionales. Aquí añadimos /usr/local/bin a $PATH:

> set PATH $PATH /usr/local/bin

Puedes acceder a elementos individuales con corchetes. La indexación comienza en 1 desde el principio, y -1 desde el final:

> echo $PATH
/usr/bin /bin /usr/sbin /sbin /usr/local/bin
> echo $PATH[1]
/usr/bin
> echo $PATH[-1]
/usr/local/bin

También puedes acceder a rangos de elementos, conocidos como "rebanadas":

> echo $PATH[1..2]
/usr/bin /bin
> echo $PATH[-1..2]
/usr/local/bin /sbin /usr/sbin /bin

Puedes iterar sobre una lista (o una rebanada) con un bucle for:

for val in $PATH
  echo "entry: $val"
end
# Imprimirá:
# entry: /usr/bin/
# entry: /bin
# entry: /usr/sbin
# entry: /sbin
# entry: /usr/local/bin

Una particularidad es que puedes usar listas como expansión de llaves <#expand-brace>. Si adjuntas otra cadena a una lista, combinará cada elemento de la lista con la cadena:

> set mydirs /usr/bin /bin
> echo $mydirs/fish # esto es como {/usr/bin,/bin}/fish
/usr/bin/fish /bin/fish

Esto también significa que, si la lista está vacía, no habrá ningún argumento:

> set empty # sin argumento
> echo $empty/this_is_gone # imprime una línea vacía

Si antepones comillas a la lista, se usará como una sola cadena y obtendrás un solo argumento incluso si está vacía.

Para más información, ver Listas <#variables-lists>. Para más sobre cómo combinar listas con cadenas (o incluso otras listas), ver productos cartesianos <#cartesian-product> y Expansión de variables <#expand-variable>.

SUSTITUCIONES DE COMANDOS

Las sustituciones de comandos utilizan la salida de un comando como argumento para otro. A diferencia de otros shells, fish no usa comillas invertidas `` para las sustituciones de comandos. En su lugar, utiliza paréntesis con o sin un dólar:

> echo In (pwd), running $(uname)
In /home/tutorial, running FreeBSD

Un modismo común es capturar la salida de un comando en una variable:

> set os (uname)
> echo $os
Linux

Las sustituciones de comandos sin un dólar no se expanden dentro de comillas, por lo que la versión con dólar es más simple:

> touch "testing_$(date +%s).txt"
> ls *.txt
testing_1360099791.txt

A diferencia de otros shells, fish no divide las sustituciones de comandos por ningún espacio en blanco (como espacios o tabulaciones), solo por saltos de línea. Normalmente, esto es una gran ayuda porque los comandos de Unix operan línea por línea. A veces puede ser un problema con comandos como pkg-config que imprimen lo que se supone que son múltiples argumentos en una sola línea. Para dividirlo también por espacios, usa string split.

> printf '%s\n' (pkg-config --libs gio-2.0)
-lgio-2.0 -lgobject-2.0 -lglib-2.0
> printf '%s\n' (pkg-config --libs gio-2.0 | string split -n " ")
-lgio-2.0
-lgobject-2.0
-lglib-2.0

Si necesitas la salida de una sustitución de comandos como un solo argumento, sin divisiones, usa sustitución de comandos entre comillas:

> echo "first line
second line" > myfile
> set myfile "$(cat myfile)"
> printf '|%s|' $myfile
|first line
second line|

Para más información, ver Sustitución de comandos <#expand-command-substitution>.

SEPARAR COMANDOS (PUNTO Y COMA)

Al igual que otros shells, fish permite múltiples comandos ya sea en líneas separadas o en la misma línea.

Para escribirlos en la misma línea, usa el punto y coma (";"). Eso significa que los siguientes dos ejemplos son equivalentes:

echo fish; echo chips
# o
echo fish
echo chips

Esto es útil interactivamente para introducir múltiples comandos. En un script, es más fácil de leer si los comandos están en líneas separadas.

añade el componente si es necesario. O puedes modificar $fish_user_paths tú mismo, pero deberías tener cuidado de no añadirle elementos incondicionalmente en config.fish,

o

crecerá cada vez más.

no

> cat ~/.config/fish/config.fish
set -x PATH $PATH /s

Sin embargo, es más común y eficiente usar funciones de carga automática y variables

universales.

Si desea organizar su configuración, fish también lee comandos en archivos .fish en ~/.config/fish/conf.d/. Consulte Archivos de

FUNCIONES DE CARGA

AUTOMÁTICA

Cuando fish encuentra un comando, intenta cargar automáticamente una función para ese comando, buscando un archivo con el nombre de ese comando en ~/.config/fish/functions/

.

Por ejemplo, si quisiera tener una función ll, añadiría un archivo de texto ll.fish a ~/.config/fish/functions

: 
> cat ~/.config/fi
sh/functions/ll.fi
sh function ll
ls -lh $argv end

Esta es la forma preferida de definir su prompt

también: 
> cat ~/.config/fish/fu
nctions/fish_prompt.fis
h function fish_prompt
echo (pwd) "> " end

Consulte la documentación de funced <> y funcsave <> para for

mas de crear estos archivos automáticamente, y $fish_function_pat
h <#syntax-function-autoloading> para controlar su ubicación.

> set
-U E

vim

Solo necesita establecer variables universales una vez de forma interactiva. N

Para más detalles, consulte Variables Universales <#variables-universal>.
