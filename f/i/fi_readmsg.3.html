NOMBRE

fi_rma - operaciones de acceso a memoria remota

fi_read / fi_readv / fi_readmsg
Inicia una lectura desde memoria remota

fi_write / fi_writev / fi_writemsg fi_inject_write / fi_writedata : Inicia una escritura a memoria remota

SINOPSIS

#include <rdma/fi_rma.h>
ssize_t fi_read(struct fid_ep *ep, void *buf, size_t len, void *desc,
    fi_addr_t src_addr, uint64_t addr, uint64_t key, void *context);
ssize_t fi_readv(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t src_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_readmsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_write(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writev(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writemsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_inject_write(struct fid_ep *ep, const void *buf, size_t len,
    fi_addr_t dest_addr, uint64_t addr, uint64_t key);
ssize_t fi_writedata(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, uint64_t data, fi_addr_t dest_addr, uint64_t addr,
    uint64_t key, void *context);
ssize_t fi_inject_writedata(struct fid_ep *ep, const void *buf, size_t len,
    uint64_t data, fi_addr_t dest_addr, uint64_t addr, uint64_t key);

ARGUMENTOS

ep
Endpoint de fabric sobre el cual iniciar la operación de lectura o escritura.
buf
Búfer de datos local para leer (destino de lectura) o escribir desde (fuente de escritura).
len
Longitud de los datos a leer o escribir, especificada en bytes. Las transferencias válidas van desde 0 bytes hasta el max_msg_size del endpoint.
iov
Búfer de datos vectoriales.
count
Cantidad de entradas de datos vectoriales.
addr
Dirección de la memoria remota a la que acceder. Esta será la dirección virtual de la región remota en el caso de FI_MR_BASIC, o el desplazamiento desde la dirección de inicio en el caso de FI_MR_SCALABLE.
key
Clave de protección asociada con la memoria remota.
desc
Descriptor asociado con el búfer de datos local. Ver fi_mr(3).
data
Datos de CQ remota a transferir con la operación.
dest_addr
Dirección de destino para transferencias de escritura sin conexión. Se ignora para endpoints conectados.
src_addr
Dirección de origen desde la cual leer para transferencias sin conexión. Se ignora para endpoints conectados.
msg
Descriptor de mensaje para operaciones de lectura y escritura.
flags
Banderas adicionales a aplicar para la operación de lectura o escritura.
context
Puntero especificado por el usuario para asociar con la operación. Este parámetro se ignora si la operación no genera una finalización exitosa, a menos que una bandera de operación especifique que el parámetro de contexto se use para entrada requerida.

DESCRIPCIÓN

Las operaciones RMA (acceso a memoria remota) se utilizan para transferir datos directamente entre un búfer de datos local y un búfer de datos remoto. Las transferencias RMA ocurren con granularidad a nivel de byte, y no se mantienen límites de mensaje.

Las funciones de escritura – fi_write, fi_writev, fi_writemsg, fi_inject_write y fi_writedata – se utilizan para transmitir datos a un búfer de memoria remota. La principal diferencia entre las funciones de escritura son el número y tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

Las funciones de lectura – fi_read, fi_readv y fi_readmsg – se utilizan para transferir datos desde una región de memoria remota a uno o varios búferes de datos locales. De manera similar a las operaciones de escritura, las operaciones de lectura son asíncronas. Los usuarios no deben manipular los búferes de datos publicados hasta que la operación de lectura haya finalizado.

Las operaciones RMA completadas se informan al usuario a través de una o más colas de finalización asociadas con el endpoint. Los usuarios proporcionan un contexto que se asocia con cada operación y se devuelve al usuario como parte de la finalización. Ver fi_cq para detalles del evento de finalización.

Por defecto, el endpoint remoto no genera un evento ni notifica al usuario cuando una región de memoria ha sido accedida por una operación RMA de lectura o escritura. Sin embargo, los datos inmediatos pueden asociarse con una operación de escritura RMA. Las escrituras RMA con datos inmediatos generarán una entrada de finalización en el endpoint remoto, para que los datos inmediatos puedan ser entregados.

fi_write

La llamada fi_write transfiere los datos contenidos en el búfer de datos especificado por el usuario a una región de memoria remota.

fi_writev

La llamada fi_writev agrega soporte para una lista de dispersión/recopilación a fi_write. fi_writev transfiere el conjunto de búferes de datos referenciados por el parámetro iov a la región de memoria remota.

fi_writemsg

La llamada fi_writemsg soporta transferencias de datos tanto en endpoints conectados como sin conexión, con la capacidad de controlar la operación de escritura por llamada a través del uso de banderas. La función fi_writemsg toma una estructura fi_msg_rma como entrada.

struct fi_msg_rma {
    const struct iovec *msg_iov;     /* array scatter-gather local */
    void               **desc;       /* descriptor de operación */
    size_t             iov_count;    /* # elementos en msg_iov */
    fi_addr_t          addr;        /* dirección de endpoint opcional */
    const struct fi_rma_iov *rma_iov;/* SGL remoto */
    size_t             rma_iov_count;/* # elementos en rma_iov */
    void               *context;     /* contexto definido por el usuario */
    uint64_t           data;         /* datos inmediatos opcionales */
};
struct fi_rma_iov {
    uint64_t           addr;         /* dirección RMA de destino */
    size_t             len;          /* tamaño del búfer de destino */
    uint64_t           key;          /* clave de acceso */
};

fi_inject_write

La llamada de inyección de escritura es una versión optimizada de fi_write. Proporciona semántica de finalización similar a fi_inject fi_msg(3).

fi_writedata

La llamada de datos de escritura es similar a fi_write, pero permite el envío de datos de CQ remota (ver bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_inject_writedata

La llamada de inyección de datos de escritura es similar a fi_inject_write, pero permite el envío de datos de CQ remota (ver bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_read

La llamada fi_read solicita que el endpoint remoto transfiera datos desde la región de memoria remota al búfer de datos local.

fi_readv

La llamada fi_readv agrega soporte para una lista de dispersión/recopilación a fi_read. fi_readv transfiere datos desde la región de memoria remota al conjunto de búferes de datos referenciados por el parámetro iov.

fi_readmsg

La llamada fi_readmsg soporta transferencias de datos tanto en endpoints conectados como sin conexión, con la capacidad de controlar la operación de lectura por llamada a través del uso de banderas. La función fi_readmsg toma una estructura fi_msg_rma como entrada.

BANDERA

FI_COMMITVERIFY
Para escrituras RMA, esta bandera puede ser utilizada para solicitar que la operación de escritura no se complete hasta que el destino confirme la escritura. Si el destino no confirma la escritura, la operación de escritura se reportará como fallida.
FI_SELECTIVEVERIFY
Similar a FI_COMMITVERIFY, pero puede ser utilizada para escrituras más pequeñas donde el host remoto solo necesita verificar un subconjunto de los datos escritos.
FI_REMOTE_CQ_DATA
Si se especifica, los datos inmediatos proporcionados con la operación de escritura se entregarán en la cola de finalización del endpoint remoto. Esta bandera solo puede ser utilizada con fi_writedata y fi_inject_writedata.
FI_RMA_VERIFY
Esta bandera aplica tanto a operaciones de lectura como de escritura RMA. Si se especifica, el endpoint local esperará una confirmación del endpoint remoto antes de completar la operación local. Si el endpoint remoto no puede confirmar la operación RMA (por ejemplo, debido a acceso denegado o dirección incorrecta), la operación local se reportará como fallida. Esta bandera no puede usarse en conjunto con FI_COMPLETION_ON_ERROR.
FI_COMPLETION_ON_ERROR
Si se especifica, las operaciones RMA que fallan se reportarán en la cola de finalización. Si no se especifica, las operaciones RMA fallidas se pueden perder sin notificación. Esta bandera no puede usarse en conjunto con FI_RMA_VERIFY.

VALORES DE RETORNO

Las funciones RMA devuelven el número de bytes transferidos si la operación se inicia correctamente. En caso de error, devuelven un valor negativo que indica el código de error.

fi_read, fi_readv, fi_write, fi_writev, fi_writedata, fi_inject_write, fi_inject_writedata devuelven el número de bytes transferidos si la operación se inicia correctamente. En caso de error, devuelven un valor negativo que indica el código de error.

fi_readmsg y fi_writemsg devuelven 0 si la operación se inicia correctamente. En caso de error, devuelven un valor negativo que indica el código de error.

Consulte la sección ERRORS de fi_verbs(3) para obtener más detalles.

FLAGS

Las llamadas fi_readmsg y fi_writemsg permiten al usuario especificar banderas que pueden cambiar la operación de transferencia de datos predeterminada. Las banderas especificadas con fi_readmsg / fi_writemsg anulan la mayoría de las banderas configuradas previamente con el punto final, excepto donde se indica (ver fi_endpoint.3). La siguiente lista de banderas son utilizables con fi_readmsg y/o fi_writemsg.

FI_REMOTE_CQ_DATA
Se aplica a fi_writemsg. Indica que los datos de la CQ remota están disponibles y deben enviarse como parte de la solicitud. Ver fi_getinfo para obtener detalles adicionales sobre FI_REMOTE_CQ_DATA. Esta bandera se establece implícitamente para fi_writedata y fi_inject_writedata.
FI_COMPLETION
Indica que se debe generar una entrada de completación para la operación especificada. El punto final debe estar enlazado a una cola de completación con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o esta bandera se ignora.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que se publicarán inmediatamente después de que la llamada actual regrese. El uso de esta bandera puede mejorar el rendimiento al permitir que el proveedor optimice su acceso al hardware de la red.
FI_INJECT
Se aplica a fi_writemsg. Indica que el búfer de datos de salida debe devolverse al usuario inmediatamente después de que la llamada de escritura regrese, incluso si la operación se maneja de forma asíncrona. Esto puede requerir que la implementación del proveedor subyacente copie los datos en un búfer local y transfiera desde ese búfer. Esta bandera solo se puede usar con mensajes más pequeños que inject_size.
FI_INJECT_COMPLETE
Se aplica a fi_writemsg. Indica que se debe generar una completación cuando los búferes de origen puedan reutilizarse.
FI_TRANSMIT_COMPLETE
Se aplica a fi_writemsg. Indica que no se debe generar una completación hasta que la operación se haya transmitido correctamente y ya no esté siendo rastreada por el proveedor.
FI_DELIVERY_COMPLETE
Se aplica a fi_writemsg. Indica que se debe generar una completación cuando la operación haya sido procesada por el destino.
FI_COMMIT_COMPLETE
Se aplica a fi_writemsg cuando se apunta a regiones de memoria persistente. Indica que se debe generar una completación solo después de que el resultado de la operación se haya vuelto duradero.
FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como operación cercada, y cualquier operación publicada después de la operación cercada se aplazarán hasta que todas las operaciones anteriores dirigidas al mismo punto final del par hayan completado. Las operaciones publicadas después del cercado verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación cercada.

El orden de las operaciones que comienzan con la publicación de la operación cercada (inclusive) hasta la publicación de una operación cercada subsiguiente (exclusiva) se controla mediante las semánticas de ordenación del punto final.

VALOR DE RETORNO

Devuelve 0 si tiene éxito. En caso de error, se devuelve un valor negativo que corresponde al errno de fabric. Los valores de errno de fabric se definen en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Ver fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
