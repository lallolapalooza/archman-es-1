SINTAXIS

Los shells como fish se utilizan dándoles comandos. Un comando se ejecuta escribiendo el nombre del comando seguido de cualquier argumento. Por

Cada programa en tu ordenador puede usarse como un comando en fish. Si el archivo del programa está ubicado en uno de los directorios PATH, puedes simplemente escribir el nombre del programa para usarlo. De lo contrario, se requiere el nombre de archivo completo, incluyendo el directorio (como /home/me/code/checkers/checkers o ../checkers)

Un interruptor es un tipo muy común de argumento especial. Los interruptores casi siempre comienzan con uno o más guiones - y alteran la forma en que funciona un comando. Por ejemplo, el comando ls normalmente lista los nombres de todos los archivos y directorios en el directorio de trabajo actual. Fish entiende dos tipos de comillas: simples (') y dobles ("), y ambas funcionan de manera ligeramente

Entre comillas simples, fish no realiza ninguna expansión. Entre comillas dobles, fish solo realiza la expansión de variables y la sustitución de comandos en el formato $(command). No se realiza ningún otro tipo de expansión (incluyendo la expansión de llaves o la expansión de parámetros), y las secuencias de escape (por ejemplo, \n) se ignoran. Dentro de comillas, el espacio en blanco no se usa para separar argumentos, permitiendo que los argumentos entre comillas contengan

espacios.

Las únicas secuencias de escape significativas entre comillas simples son \', que escapa una comilla simple y \\, que escapa el símbolo de barra invertida. Las únicas secuencias de escape significativas entre comillas dobles son \", que escapa una comilla doble, \$, que escapa un carácter de dólar, \ seguido de un salto de línea, que elimina la barra invertida y el salto de línea, y \\, que escapa el símbolo de barra

CONTROL DE

TRABAJOS

Cuando inicia un trabajo en fish, fish mismo se pausará y dará el control de la terminal al programa que acaba de iniciar. A veces, usted quiere seguir usando la línea de comandos y que el trabajo se ejecute en segundo plano. Para crear un trabajo en segundo plano, añada un & (ampersand) a su comando. Esto le dirá a fish que ejecute el trabajo en segundo plano. Los trabajos en segundo plano son muy útiles al ejecutar programas que tienen una interfaz gráfica de

usuario.

Ejemplo

necesario.

La mayoría de los programas le permiten suspender la ejecución del programa y devolver el control a fish presionando ctrl-z (también conocido como ^Z). Una vez de vuelta en la línea de comandos de fish, puede iniciar otros programas y hacer lo que quiera. Si luego lo desea, puede volver al comando suspendido usando el comando fg <> (primer plano)

.

Si en cambio desea poner un trabajo suspendido en segundo plano, use el comando bg <>

.

Para obtener una lista de todos los trabajos iniciados actualmente, use el comando jobs <>. Estos trabajos listados se pueden eliminar con el comando disown <>

.

En este momento, las funciones no se pueden iniciar en segundo plano. Las funciones que se detienen y luego se reinician en segundo plano usando el comando bg <> no se ejecutarán

correctamente.

Si el carácter & está seguido de un carácter no separador, no se interpreta como operador de segundo plano. Los caracteres separadores son el espacio en blanco y los caracteres ;<>

Comillas para variables

La expansión de variables también ocurre en cadenas entrecomilladas dobles. Dentro de comillas dobles ("estas"), las variables siempre se expandirán a exactamente un argumento. Si están vacías o no definidas, resultarán en una cadena vacía. Si tienen un elemento, se expandirán a ese elemento. Si tienen más, los elementos se unirán con espacios, a menos que la variable sea una variable de ruta; en ese caso, utilizará dos puntos (:) en su lugar [3].

Las variables de fish son todas listas y se dividen en elementos cuando se establecen, lo que significa que es importante decidir si usar comillas o no con set <>:

set foo 1 2 3 # una variable con tres elementos
rm $foo # ejecuta el equivalente de `rm 1 2 3` - intentando borrar tres archivos: 1, 2 y 3.
rm "$foo" # ejecuta `rm '1 2 3'` - intentando borrar un archivo llamado '1 2 3'
set foo # una variable vacía
rm $foo # ejecuta `rm` sin argumentos
rm "$foo" # ejecuta el equivalente de `rm ''`
set foo "1 2 3"
rm $foo # ejecuta el equivalente de `rm '1 2 3'` - intentando borrar un archivo
rm "$foo" # lo mismo

Esto es diferente de otros shells, que hacen lo que se conoce como "División de palabras", donde dividen la variable cuando se usa en una expansión. Por ejemplo, en bash:

foo="1 2 3"
rm $foo # ejecuta el equivalente de `rm 1 2 3`
rm "$foo" # ejecuta el equivalente de `rm '1 2 3'`

Esta es la causa de problemas muy comunes con nombres de archivo con espacios en scripts de bash.

En fish, las variables sin comillas se expandirán a tantos argumentos como elementos tengan. Esto significa que una lista vacía se expandirá a nada, una variable con un elemento se expandirá a ese elemento, y una variable con múltiples elementos se expandirá a cada uno de esos elementos por separado.

Si una variable se expande a nada, cancelará cualquier otra cadena adjunta a ella. Consulte la sección Combinación de listas para obtener más información.

La mayoría de las veces, no entrecomillar una variable es lo correcto. La excepción es cuando necesita asegurarse de que la variable se pase como un solo elemento, incluso si podría no estar definida o tener múltiples elementos. Esto ocurre a menudo con test <>:

set -l foo one two three

test -n one two three

test -n "one two three"

Desreferencia de variables

El símbolo $ también se puede usar varias veces, como una especie de operador de "desreferencia" (el * en C o C++), como en el siguiente código:

# 20

$$foo[$i] es "el valor de la variable llamada por $foo[$i]".

    for arg in $argv
        echo Variable $arg es $$arg
    end

Por supuesto, la variable tendrá que ser accesible desde la función, por lo que debe ser global/universal o exportada. Tampoco puede entrar en conflicto con un nombre de variable utilizado dentro de la función. Así que si hubiéramos hecho $foo una variable local allí, o si la hubiéramos llamado "arg" en su lugar, no habría funcionado.

Cuando se utiliza esta característica junto con segmentaciones, las segmentaciones se utilizarán de adentro hacia afuera. $$foo[5] usará el quinto elemento de $foo como nombre de variable, en lugar de dar el quinto elemento de todas las variables a las que $foo se refiere. Eso se expresaría en su lugar como $$foo[1..-1][5] (tomar todos los elementos de $foo, usarlos como nombres de variables, luego dar el quinto elemento de esos).

Algunos ejemplos más:

# $var[2] es listtwo, el tercer elemento de ese es 6, la salida es 6
echo $$var[..][2]
# El segundo elemento de cada variable, así que la salida es 2 5

Sustitución de comandos

Una sustitución de comandos es una expansión que utiliza la salida de un comando como argumentos para otro. Por ejemplo:

echo $(pwd)

Esto ejecuta el comando pwd <>, toma su salida (más específicamente lo que escribió en el flujo de salida estándar "stdout") y lo utiliza como argumentos para echo <>. Por lo tanto, el comando interno (el pwd) se ejecuta primero y debe completarse antes de que el comando externo pueda siquiera iniciarse.

Si el comando interno imprime varias líneas, fish usará cada línea separada como un argumento separado para el comando externo. A diferencia de otros shells, el valor de $IFS no se utiliza [4], fish divide por saltos de línea.

Las sustituciones de comandos también pueden ir entrecomilladas dobles:

echo "$(pwd)"

Cuando se usan comillas dobles, la salida del comando no se divide por líneas, pero las líneas vacías finales aún se eliminan.

Si la salida se canaliza a `string split` o `string split0` <> como último paso, esas divisiones se utilizan tal como aparecen en lugar de dividir por líneas.

Fish también permite escribir sustituciones de comandos sin el signo de dólar, como echo (pwd). Esta variante no se expandirá en comillas dobles (echo "(pwd)" imprimirá (pwd)).

El estado de salida del último comando de sustitución ejecutado está disponible en la variable `status` si la sustitución ocurre en el contexto de un comando `set` <> (así que `if set -l (something)` comprueba si `something` devolvió `true`).

Para usar solo algunas líneas de la salida, consulte las segmentaciones.

Ejemplos:

# Imprime 'image.png'.
echo (basename image.jpg .jpg).png
# Convierte todos los archivos JPEG en el directorio actual al
# formato PNG usando el programa 'convert'.
for i in *.jpg; convert $i (basename $i .jpg).png; end
# Establece la variable ``data`` al contenido de 'data.txt'
# sin dividirlo en una lista.
set data "$(cat data.txt)"
# Establece ``$data`` al contenido de data, dividiendo por bytes NUL.
set data (cat data | string split0)

A veces quieres pasar la salida de un comando a otro comando que solo acepta archivos. Si es solo un archivo, normalmente puedes pasarlo a través de una tubería, como:

grep fish myanimallist1 | wc -l

pero si necesitas múltiples o el comando no lee de la entrada estándar, la "sustitución de procesos" es útil. Otros shells permiten esto a través de foo <(bar) <(baz), y fish usa el comando psub <>:

# Compara solo las líneas que contienen "fish" en dos archivos:
diff -u (grep fish myanimallist1 | psub) (grep fish myanimallist2 | psub)

Esto crea un archivo temporal, almacena la salida del comando en ese archivo e imprime el nombre del archivo, para que se le pase al comando externo.

Fish tiene un límite predeterminado de 1 GiB para los datos que leerá en una sustitución de comandos. Si se alcanza ese límite, el comando (todo él, no solo la sustitución de comandos; el comando externo ni siquiera se ejecutará) falla y $status se establece en 122. Esto es para que las sustituciones de comandos no puedan hacer que el sistema se quede sin memoria, ya que típicamente su sistema operativo tiene un límite mucho menor, por lo que leer más que eso sería inútil y perjudicial. Este límite se puede ajustar con la variable fish_read_limit (0 significa sin límite). Este límite también afecta al comando `read` <>.

Las variables en fish pueden ser exportadas, de modo que serán heredadas por cualquier comando iniciado por fish. En particular, esto es necesario para variables usadas para con

Environment variables

Fish supports environment variables, similar to other shells. These variables are used to configure the environment in which commands run. They can be used to specify external commands like PAGER or GOPATH, as well as general system settings like PATH or LANGUAGE. If an external command requires a variable, it must be exported. Exported variables are also commonly referred to as "environment variables".

Fish, like other shells, inherits environment variables from its parent process (usually the terminal) when it starts up. These typically include system configurations such as PATH and locale-related variables.

Variables can be explicitly set for export using the -x or --export flags, or unset for export using the -u or --unexport flags. The rules for exporting variables when setting them are similar to the scoping rules for variables: if an option is provided, it is respected; otherwise, the variable's existing export state is used. If no option is given and the variable did not exist previously, it is not exported by default.

As a naming convention, exported variables are typically written in uppercase, while unexported variables are in lowercase.

Here are some examples:

set -gx ANDROID_HOME ~/.android # /opt/android-sdk
set -gx CDPATH . ~ (test -e ~/Videos; and echo ~/Videos)
set -gx EDITOR emacs -nw
set -gx GOPATH ~/dev/go
set -gx GTK2_RC_FILES "$XDG_CONFIG_HOME/gtk-2.0/gtkrc"
set -gx LESSHISTFILE "-"

Note: Exporting is an additional state, not a scope. While it often makes sense to make exported variables global as well, local-exported variables can be useful for more specific overrides. They are copied into functions, preventing the function from altering the original variable outside its scope, while still being available to commands. Global variables are accessible to functions regardless of their export status.

    # encontró una opción que no reconoció
    # - imprimirá un error
    or return

    if set -ql _flag_second

    else
        echo $argv[1]
        echo $argv[3]
    end

Variables PATH

Path variables are a specialized type of variable designed to handle colon-delimited path lists, such as PATH, CDPATH, MANPATH, PYTHONPATH, and LANGUAGE (for localization <>), among others. By default, all variables ending in "PATH" (case-sensitive) are treated as PATH variables.

Path variables function like regular lists, with the key difference being their implicit joining and splitting on colons.

set MYPATH 1 2 3
echo "$MYPATH"
# 1:2:3
set MYPATH "$MYPATH:4:5"
echo $MYPATH
# 1 2 3 4 5
echo "$MYPATH"
# 1:2:3:4:5

Path variables are also exported in their colon-delimited form. For example, set -x MYPATH 1 2 3 will be seen by external commands as 1:2:3.

> set -gx MYPATH /bin /usr/bin /sbin
> env | grep MYPATH
MYPATH=/bin:/usr/bin:/sbin

This behavior is implemented for compatibility with other tools. Since Unix traditionally doesn't support variables with multiple elements directly, it relies on colon-delimited lists like PATH. Consequently, no element within a path variable can contain a colon (:).

Variables can be explicitly designated or de-designated as PATH variables using the --path and --unpath options of the set command.

La variable

status

Siempre que un proceso termina, se devuelve un estado de salida al programa que lo inició (generalmente el shell). Este estado de salida es un número entero, que le indica a la aplicación que lo llama cómo fue la ejecución del comando. En general, un estado de salida cero significa que el comando se ejecutó sin problemas, pero un estado de salida distinto de cero significa que hubo algún tipo de

problema.

Fish almacena el estado de salida del último proceso en el último trabajo que terminó en la variable st

atus.

Si fish encuentra un problema mientras ejecuta un comando, la variable status también puede ser establecida a un valor

específico:
  • 0 es generalmente el estado de salida de los comandos si realizaron con éxito la operación
    • solicitada.
  • 1 es generalmente el estado de salida de los comandos si fallaron al realizar la operación
    • solicitada.
  • 121 es generalmente el estado de salida de los comandos si se les proporcionaron argumentos
    • inválidos.
  • 123 significa que el comando no fue ejecutado porque el nombre del comando contenía caracteres
    • inválidos.
  • 124 significa que el comando no fue ejecutado porque ninguno de los comodines (wildcards) en el comando produjo ninguna
    • coincidencia.
  • 125 significa que aunque se localizó un ejecutable con el nombre especificado, el sistema operativo no pudo realmente ejecutar el
    • comando.
  • 126 significa que aunque se localizó un archivo con el nombre especificado, no era
    • ejecutable.
  • 127 significa que no se
    • pudo localizar ninguna
función, builtin o coma
ndo con el nombre dado.

Si un proceso termina a través de una señal, el estado de salida será 128 más el número de la

señal.

El estado puede ser negado con not <> (o !), lo cual es útil en una condición. Esto convierte un estado de 0 en 1 y cualquier estado distinto de cero en

0.

También existe $pipestatus, que es una lista de todos los valores de estado de los procesos en un tubo (pipe). Una diferencia es que not <> se aplica a $status, pero no a $pipestatus, porque pierde

información.

Por

-q fish echo statu

negación.

Así que si tanto cat como grep tuvieron éxito, $status sería 1 debido al not, y $pipestatus sería 0 y

0.

Es posible que el primer comando falle mientras el segundo tiene éxito. Un ejemplo común es cuando el segundo programa termina

temprano.

DEPURACIÓN DE GUIONES DE

FISH

Fish incluye instaladas unas instalaciones básicas de depuración que te permiten detener la ejecución de un guion en un punto arbitrario. Cuando esto ocurre, se te presenta un prompt interactivo donde puedes ejecutar cualquier comando de fish para inspeccionar o cambiar el estado (no hay comandos de depuración como tales). Por ejemplo, puedes comprobar o cambiar el valor de cualquier variable usando printf <> y set <>. Como otro ejemplo, puedes ejecutar status print-stack-trace <> para ver cómo se alcanzó el punto de interrupción actual. Para reanudar la ejecución normal del guion, escribe exit <> o ctrl-d

.

Para iniciar una sesión de depuración, inserta el comando incorporado <> breakpoint en el punto de una función o guion donde desees tomar el control, y luego ejecuta la función o el guion. Además, la acción por defecto de la señal TRAP es llamar a este incorporado, lo que significa que un guion en ejecución puede ser depurado activamente enviándole la señal TRAP (kill -s TRAP <PID>). Hay soporte limitado para establecer o modificar puntos de interrupción interactivamente desde este prompt de depuración: es posible insertar nuevos puntos de interrupción en (o eliminar los antiguos de) otras funciones usando la función funced para editar la definición de una función, pero no es posible añadir o eliminar un punto de interrupción de la función/guion actualmente cargado y en

ejecución.

Otra forma de depurar problemas en los guiones es establecer la variable fish_trace, por ejemplo fish_trace=1 fish_prompt para ver qué comandos ejecuta fish al ejecutar la función fish_prompt <>

.
