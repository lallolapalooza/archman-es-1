NOMBRE

firewalld.richlanguage - Documentación del Lenguaje Rico

DESCRIPCIÓN

Con el lenguaje rico se pueden crear reglas de firewall más complejas de una manera fácil de entender. El lenguaje utiliza palabras clave con valores y es una representación abstracta de las reglas de iptables.

El lenguaje rico extiende los elementos de zona actuales (servicio, puerto, icmp-block, icmp-type, masquerade, forward-port y source-port) con direcciones de origen y destino adicionales, registro, acciones y límites para registros y acciones.

Esta página describe el lenguaje rico utilizado en el cliente de línea de comandos y la interfaz D-Bus. Para obtener información sobre la representación del lenguaje rico utilizada en los archivos de configuración de zona, consulte firewalld.zone(5).

Una regla es parte de una zona. Una zona puede contener varias reglas. Si algunas reglas interactúan/se contradicen, la primera regla que coincide "gana".

Estructura general de la regla

rule
  [source]
  [destination]
  service|port|protocol|icmp-block|icmp-type|masquerade|forward-port|source-port
  [log|nflog]
  [audit]
  [accept|reject|drop|mark]

La regla completa se proporciona como una cadena de una sola línea. Se permite un destino aquí siempre que no entre en conflicto con el destino de un servicio.

Estructura de la regla para listas negras o blancas de origen

rule
  source
  [log|nflog]
  [audit]
  accept|reject|drop|mark

Esto se utiliza para conceder o limitar el acceso desde una fuente a esta máquina o a máquinas a las que esta máquina puede acceder. No se permite un destino aquí.

Información importante sobre las opciones de elementos: Las opciones para los elementos de una regla deben agregarse exactamente después del elemento. Si la opción se coloca en otro lugar, puede ser utilizada para otro elemento siempre que coincida con las opciones del otro elemento o resultará en un error de regla.

Regla

rule [family="ipv4|ipv6"] [priority="priority"]

Si se proporciona la familia de reglas, puede ser "ipv4" o "ipv6", lo que limita la regla a IPv4 o IPv6. Si no se proporciona la familia de reglas, la regla se agregará para IPv4 e IPv6. Si se utilizan direcciones de origen o destino en una regla, entonces se debe proporcionar la familia de reglas. Este también es el caso para el reenvío de puertos/paquetes.

Si se proporciona la prioridad de la regla, puede estar en el rango de -32768 a 32767, donde los valores más bajos tienen mayor precedencia. Las reglas ricas se ordenan por prioridad. El orden de las reglas con el mismo valor de prioridad no está definido. Un valor de prioridad negativo se ejecutará antes que otras primitivas de firewalld. Un valor de prioridad positivo se ejecutará después de otras primitivas de firewalld. Un valor de prioridad de 0 colocará la regla en una cadena basada en la acción según la "Información sobre registro y acciones" a continuación.

Origen

source [not] address="address[/mask]"|mac="mac-address"|ipset="ipset"

Con la dirección de origen, el origen de un intento de conexión puede limitarse a la dirección de origen. Una dirección es una dirección IP única, o una dirección IP de red, una dirección MAC o un IPSet. La dirección debe coincidir con la familia de reglas (IPv4/IPv6). La máscara de subred se expresa en notación decimal punteada (/x.x.x.x) o de prefijo (/x) para IPv4, y en notación de prefijo (/x) para direcciones de red IPv6. Es posible invertir el sentido de una dirección agregando not antes de address. Todas las direcciones excepto la especificada coincidirán entonces.

Destino

destination [not] address="address[/mask]"|ipset="ipset"

Con la dirección de destino, el objetivo puede limitarse a la dirección de destino. La dirección de destino utiliza la misma sintaxis que la dirección de origen.

El uso de direcciones de origen y destino es opcional y el uso de direcciones de destino no es posible con todos los elementos. Esto depende del uso de direcciones de destino, por ejemplo, en las entradas de servicio.

Servicio

service name="nombre del servicio"

El servicio nombre del servicio se agregará a la regla. El nombre del servicio es uno de los servicios proporcionados por firewalld. Para obtener una lista de los servicios compatibles, use firewall-cmd --get-services.

Si un servicio proporciona una dirección de destino, entrará en conflicto con una dirección de destino en la regla y resultará en un error. Los servicios que utilizan direcciones de destino internamente son en su mayoría servicios que utilizan multidifusión.

Puerto

port port="valor del puerto" protocol="tcp|udp|sctp|dccp"

El puerto valor del puerto puede ser un número de puerto único id de puerto o un rango de puertos id de puerto-id de puerto. El protocolo puede ser tcp, udp, sctp o dccp.

Protocolo

protocol value="valor del protocolo"

El valor del protocolo puede ser un número de id de protocolo o un nombre de protocolo. Para ver las entradas de protocolo permitidas, consulte /etc/protocols.

Tcp-Mss-Clamp

tcp-mss-clamp="value=pmtu|value=number >= 536|None"

tcp-mss-clamp establece el tamaño máximo del segmento en la regla.

tcp-mss-clamp tiene un atributo opcional, el valor puede ser "pmtu" o un número mayor o igual a 536. Si no se proporciona el valor del atributo, el tamaño máximo del segmento se establece automáticamente en "pmtu".

ICMP-Block

icmp-block name="nombre del tipo icmp"

El tipo icmp es uno de los tipos icmp que firewalld soporta. Para obtener una lista de los tipos icmp compatibles: firewall-cmd --get-icmptypes

No se permite especificar una acción aquí. icmp-block utiliza la acción reject internamente.

Mascarada

masquerade

Activa la mascarada en la regla. Se puede proporcionar un origen y también un destino para limitar la mascarada a esta área.

No se permite especificar una acción aquí.

Nota: El reenvío de IP se habilitará implícitamente.

ICMP-Type

icmp-type name="nombre del tipo icmp"

El tipo icmp es uno de los tipos icmp que firewalld soporta. Para obtener una lista de los tipos icmp compatibles: firewall-cmd --get-icmptypes

Forward-Port

forward-port port="valor del puerto" protocol="tcp|udp|sctp|dccp" to-port="valor del puerto" to-addr="dirección"

Reenvía el puerto/paquetes desde el valor del puerto local con el protocolo "tcp" o "udp" a otro puerto localmente o a otra máquina o a otro puerto en otra máquina.

El valor del puerto puede ser un número de puerto único o un rango de puertos id de puerto-id de puerto. El to-addr es una dirección IP. El protocolo puede ser tcp, udp, sctp o dccp.

No se permite especificar una acción aquí. forward-port utiliza la acción accept internamente.

Nota: El reenvío de IP se habilitará implícitamente si se especifica to-addr.

Source-Port

source-port port="valor del puerto" protocol="tcp|udp|sctp|dccp"

El source-port valor del puerto puede ser un número de puerto único id de puerto o un rango de puertos id de puerto-id de puerto. El protocolo puede ser tcp, udp, sctp o dccp.

Registro y Acciones

Las acciones específicas de la regla son accept, reject, drop y mark.

reject y drop son acciones destructivas. Si un paquete coincide, se descarta y no se envía ninguna respuesta al remitente.

reject envía un paquete de error ICMP al remitente.

drop descarta el paquete sin enviar ninguna respuesta al remitente.

accept es la acción predeterminada si no se especifica ninguna acción explícita y no se utiliza ninguno de los elementos que tienen una acción interna (forward-port, icmp-block, masquerade).

mark marca los paquetes correspondientes con un valor deshabilitado. Esto se utiliza para el marcado de paquetes de alta prioridad con el objetivo de que un módulo de red de alta prioridad los procese.

Por defecto, las reglas con una acción accept (o sin acción explícita) se colocan en la cadena de aceptación de la zona. Las reglas con una acción reject o drop se colocan en la cadena de rechazo de la zona. Las reglas con una acción mark se colocan en la cadena de marcado de la zona. Las reglas con prioridad 0 se colocan en la cadena correspondiente a su acción.

Las acciones log y nflog se pueden agregar a la regla y registran un mensaje de registro en el registro del sistema o en un registro de auditoría de seguridad. Las acciones log y nflog se pueden utilizar juntas con otras acciones. Si se utilizan juntas con una acción destructiva (reject, drop), el paquete se registra primero y luego se descarta. Si se utilizan con accept, el paquete se acepta y se registra.

Con la acción log, se puede especificar un campo de texto libre con el parámetro prefix. Este texto se antepone a todos los mensajes de registro. El texto no puede contener espacios.

log prefix="string" [level="emerg|alert|crit|err|warning|notice|info|debug"]

El nivel de registro se puede especificar con el parámetro level. El valor predeterminado es notice.

Con la acción nflog, se puede especificar un grupo de registro con el parámetro nflog-group. El grupo de registro debe ser un número entre 0 y 65535. Por defecto, el grupo de registro es 100.

nflog prefix="string" [nflog-group="number"] [nlflag="0|1|2|3"]

El parámetro nlflag se utiliza para activar las banderas de registro de auditoría de seguridad. Si está establecido en 1, se activa el registro de auditoría para los paquetes de entrada. Si está establecido en 2, se activa el registro de auditoría para los paquetes de salida. Si está establecido en 3, se activan ambos. Si no se establece ningún valor, la bandera de registro de auditoría de seguridad se establece en 0.

Es posible agregar una acción audit para una regla. Esto se utiliza para marcar los paquetes correspondientes con una bandera de auditoría de seguridad. Esto se utiliza para el registro de auditoría de seguridad.

Por defecto, la acción log utiliza el nivel de registro notice. Esto se puede cambiar con el parámetro level.

El parámetro limit se puede utilizar con las acciones log y nflog para limitar el registro a un número específico de mensajes por intervalo de tiempo. El valor es un número de mensajes por segundo.

limit value="rate[/second|/minute|/hour|/day]"

El parámetro minute se puede utilizar para establecer un valor de límite por minuto.

limit value="rate" minute="rate"

El parámetro hour se puede utilizar para establecer un valor de límite por hora.

limit value="rate" hour="rate"

El parámetro day se puede utilizar para establecer un valor de límite por día.

limit value="rate" day="rate"

Ejemplo

Permitir el acceso a través del puerto 80 de la red 192.168.0.0/24 a través del protocolo tcp y registrarlo con el prefijo "MiServidorWeb".

firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.168.0.0/24" service name="http" log prefix="MiServidorWeb" accept'

Ejemplo de cómo rechazar un paquete ICMP:

firewall-cmd --zone=home --add-rich-rule='rule family="ipv4" icmp-block name="echo-request" reject'

Ejemplo de cómo reenviar el puerto 8080 al puerto 80 de la máquina local:

firewall-cmd --zone=internal --add-rich-rule='rule family="ipv4" forward-port port="8080" protocol="tcp" to-port="80"'

Ejemplo de cómo activar la mascarada para la red 192.168.1.0/24:

firewall-cmd --zone=external --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" masquerade'

Ejemplo para limitar la velocidad de registro para un servicio:

firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" service name="ssh" log prefix="SSH" limit value="1/minute" accept'
