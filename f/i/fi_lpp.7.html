NOMBRE

fi_lpp - El Proveedor de Fabricación LPP

DESCRIPCIÓN GENERAL

El proveedor LPP se ejecuta en redes FabreX PCIe. FabreX proporciona capacidades RDMA de alto rendimiento que forman la base del proveedor LPP. Las primitivas de nivel superior se implementan en las capas libfabric y del módulo del kernel LPP (KLPP).

CARACTERÍSTICAS SOPORTADAS

El proveedor LPP soporta un subconjunto de la API libfabric. Las características clave incluyen:

Tipos de endpoint
LPP soporta el tipo de endpoint FI_EP_RDM con gestión de recursos.
Capacidades de endpoint
LPP soporta los tipos de mensaje FI_MSG, FI_RMA y FI_TAGGED.
Capacidades adicionales
LPP soporta las características adicionales: FI_DIRECTED_RECV, FI_MULTI_RECV, FI_INJECT, FI_DELIVERY_COMPLETE
Progreso
LPP actualmente solo soporta FI_PROGRESS_MANUAL. Por lo tanto, se requiere que las aplicaciones de usuario consulten para el progreso.

LIMITACIONES

Estas características no están soportadas: gestión de conexiones, cola de eventos, endpoint escalable, endpoint pasivo, contexto de recepción compartido, atómicos.

PARÁMETROS DE EJECUCIÓN

El proveedor LPP verifica las siguientes variables de entorno -

FI_LPP_DISABLE_OSBYPASS
Un booleano que deshabilita escrituras directas en el espacio de usuario cuando se establece. Esto puede usarse como ayuda para depuración, sin embargo, degradará el rendimiento.
FI_LPP_MAX_WR_OSBYPASS_SIZE
Establece el tamaño máximo para PIO al realizar transferencias RDMA de escritura. Las transferencias de este tamaño o menores usarán copia de CPU, mientras que las transferencias mayores usarán un motor DMA.
FI_LPP_MAX_RD_OSBYPASS_SIZE
Establece el tamaño máximo para PIO al realizar transferencias RDMA de lectura. Las transferencias de este tamaño o menores usarán copia de CPU, mientras que las transferencias mayores usarán un motor DMA.
FI_LPP_CQ_OVERCOMMIT
Un booleano que permite iniciar operaciones que podrían sobrecargar la CQ. Normalmente, cuando la gestión de recursos está habilitada, el proveedor LPP intentará limitar las operaciones que podrían sobrecargar la CQ. Este parámetro deshabilita ese comportamiento mientras deja habilitadas el resto de las características de gestión de recursos.
FI_LPP_DOMAIN_CLEANUP
Un booleano que controla si cerrar un dominio con recursos activos causará que esos recursos se cierren automáticamente. Si es verdadero (el valor predeterminado), el proveedor LPP cerrará automáticamente los recursos.
FI_LPP_SYSTEM_MEMCPY
Utiliza la implementación de memcpy en la libc del sistema en lugar de la memcpy específica del proveedor.
