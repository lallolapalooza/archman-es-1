DESCRIPCIÓ

N

El objetivo aquí es simplemente proporcionar versiones recursivas de mkdir() y rmdir() con el menor código y sobrecosto

posible.

Este módulo no pretende en absoluto desacreditar a File::Path y de ninguna manera es un aval para salir y reemplazar todos los usos de File::Path con File::Path::

Tiny.

File::Path es muy bueno en lo que hace pero simplemente hay mucho sucediendo que podemos prescindir la mayor parte del

tiempo.

Aquí hay algunas cosas que File::Path tiene/hace que este módulo intenta

prescindir:
  • múltiples interfaces

    La compatibilidad hacia atrás trae

    mucho código y lógica que
    • no necesitamos de aquí en adelante.
  • chdir()s

    Fuerza un montón de chdir()s que podrían dejarte en algún lugar donde no planeabas estar y requiere mucho más sobrecosto para

    hacerlo.

    Este módulo proporciona una forma de d

    • seguro hacerlo en tu circunstancia.
  • puede morir (croak) sin permitirte detectar y manejar el fallo

mk()

Toma una sola ruta (como mkdir()) para crear recursivamente y, opcionalmente, una máscara (como mkdir()) para todas las llamadas subsiguientes a mkdir()

La máscara por defecto es 0700 (también como mkdir()

)

Devuelve falso si no pudo ser creada, verdadero en caso contrario (devuelve ‘2’ si ya es

-d)

Es recursivo en el sentido de que dada

“foo/bar/baz” como ruta a crear, l
os 3 serán creados si es necesario.

File::Path::Tiny::

rm()

Toma una sola ruta (como rmdir()) para vaciar y eliminar

recursivamente.

Devuelve falso si no pudo ser vaciada o eliminada, verdadero en caso contrario (devuelve ‘2’ si ya es !-d). Ver también

Es recursivo en el sentido de que dada “/foo/bar/baz” como ruta a eliminar, vaciará recursivamente ‘baz’ y luego la eliminará de

¿Cómo puedo crear/eliminar múltiples

rutas?

Por simplicidad && el estado ::Tiny, este módulo debe ser muy muy muy

simple.

Dicho esto, también es muy simple hacer múltiples

rutas: 
for my $path (@paths) {
    File::Path::Tiny::::mk($path) or _my_handle_failed_mk($path, $!);    
}

for my $path (@paths) {
    File::Path::Tiny::::rm($path) or _my_handle_failed_rm($path, $!);
}

Eso también te permite continuar o cortocircuitarlo o manejar errores como

prefieras: 
PATH:
for my $path qw(foo/bar bar/rat) {
    if (!File::Path::Tiny::mk($path)) {
        print "problem unlinking '$path': $!\n";
        last PATH;
    }
    else {
        print "No error encountered with '$path'\n" 
    }
}

¿Cómo me aseguro de que la ruta es segura para crear o

eliminar?

Por supuesto la respuesta depende de lo que quieras decir por

"seguro".

Este módulo no hace ninguna suposición sobre la interpretación de la "seguridad" de una ruta, igual que mkdir() y rmdir()

.

También como mkdir() y rmdir() típicamente encontrarás que los permisos del sistema de archivos son una herramienta bastante confiable (por supuesto si el código se ejecutará como root querrías hacer setuid primero...

)

Podrías usar Cwd::abs_path() para sanitizar una ruta antes de enviarla a ser creada o

eliminada.

Incluso después de eso podría no ser "s

eguro" así que necesitarás discerni
