SINOPSI

S 
use File::Remove 'remove';
# elimina (sin recursión) varios archivos
remove( '*.c', '*.pl' );
# elimina (con recursión) varios directorios
remove( \1, qw{directory1 directory2} );
# elimina (con recursión) varios archivos y directorios
remove( \1, qw{file1 file2 directory1 *~} );
# elimina sin comodines:
remove( \1, {glob => 0}, '*');
# envía a la papelera (con soporte para deshacer más tarde) varios archivos
trash( '*~'
)
;

DESCRIPCIÓ

N

File::Remove::remove elimina archivos y directorios. Actúa como /bin/rm, en su mayor parte. Aunque "unlink" puede recibir una lista de archivos, no eliminará directorios; este módulo lo soluciona. También acepta comodines, * y ?, como argumentos para los nombres de

archivo.

File::Remove::trash acepta los mismos argumentos que remove, con la adición de un hashref opcional

, poco utilizado, d
e "otras plataformas".

SUBRUTINA

S

remov

e

Elimina archivos y directorios. Los directorios se eliminan recursivamente como en rm -rf si el primer argumento es una referencia a un escalar que evalúa a verdadero. Si el primer argumento es una referencia a un escalar, entonces se usa como el valor de la bandera recursiva. Por defecto es falso, así que solo pase

\1.

Si el siguiente argumento es una referencia a un hash, entonces es un conjunto de clave/valor de opciones. Actualmente, hay una opción admitida de "'glob' => 0" que previene la expansión de comodines. Por

ejemplo: 
remove(\1, {glob => 0}, '*')
;

No eliminará los archivos que coincidan con '*' y solo eliminará el archivo llamado asterisco si

existe.

En contexto de lista devuelve una lista de archivos/directorios eliminados, e

n contexto escalar devuelve el número de archivos/directorios eliminados.
La lista/número debería coincidir con lo que se pasó si todo salió bien.
