DESCRIPCIÓ

N

La aplicación findscu implementa un SCU para la Clase de Servicio de Consulta/Recuperación y la Clase de Servicio de Gestión de Listas de Trabajo Básicas. findscu solo admite la funcionalidad de consulta mediante el mensaje C-FIND. Envía claves de consulta a un SCP y espera respuestas. La a

plicación puede usarse para probar SCPs de las Clases de Servicio d
e Consulta/Recuperación y de Gestión de Listas de Trabajo Básicas.

NOTA

S

Cada archivo proporcionado en la línea de comandos será enviado al SCP como parte de una solicitud C-FIND. El archivo de consulta debe ser un conjunto de datos DICOM válido que contenga la parte de datos de un mensaje C-FIND-RQ. El archivo de consulta podría, por ejemplo, crearse con la utilidad dump2dcm a partir de un script como el siguiente

ejemplo: 
# consultar nombres e identificadores de pacientes
(0008,0052) CS [PATIENT]     # QueryRetrieveLevel
(0010,0010) PN []            # PatientName
(0010,0020) LO []            #
PatientID

Los atributos individuales de cada archivo enviado pueden modificarse o complementarse usando la opción -k. Por ejemplo, el

comando: 
findscu -P -k "(0010,0010)=HEWETT*" caesar 5678 patqry.
dcm

cuando se envía al SCP caesar en el puerto TCP/IP 5678, hará que cualquier atributo PatientName en patqry.dcm tenga el valor "HEWETT*". Si está presente un atributo de este tipo, será reemplazado; si no está presente, será insertado. La opción -k puede aparecer más de una vez. La parte del valor (después del '=') puede estar ausente, lo que hace que el atributo se envíe con

longitud

cero. En versiones anteriores de findscu, las claves de etiqueta se especificaban sin llaves alrededor del número de grupo y elemento, p. ej. "0010,0010" en lugar de "(0010,0010)". Se recomienda cambiar a la nueva sintaxis; sin embargo, la sintaxis

antigua

sigue funcionando. Además, -k acepta nombres de diccionario en lugar de etiquetas de elemento para especificar elementos DICOM. Por ejemplo, la llamada a

findscu 
anterior
    se leería así:
findscu -P -k PatientName="HEWETT*
"

caesar 5678 patqry.dcm También es posible especificar secuencias, elementos y atributos anidados usando la opción -k. En estos casos, se debe usar una notación

especial 
de "ruta", p. ej.
findscu -W -k "(0040,0100)[0].
Modality=CT"

caesar 5678 Esta llamada consulta un servidor de lista de trabajo en el host caesar para cualquier procedimiento planificado para modalidades CT especificando la etiqueta (0040,0100) "Secuencia de Pasos de Procedimiento Programado" y un atributo "Modality" en el primer elemento de esta secuencia con el valor "CT". Los detalles sobre esta nota

ción

de ruta se pueden encontrar en la documentación de dcmodify. Si no se especifica ningún archivo en la línea de comandos, la consulta debe especificarse completamente con una o más opciones -k. Si se proporcionan

múltiples

archivos de consulta, findscu enviará múltiples solicitudes C-FIND al SCP. Cada conjunto de identificadores de respuesta recibido se enviará al registrador (logger) a menos que se use la opción --hide-responses, cualquiera de las variantes --extract, --quiet o una configuración apropiada del registr

ador

(logger). En estos casos, la salida al registrador se puede forzar con la opción --show-responses. Además, los conjuntos de datos de respuesta también se pueden extraer como archivos DICOM individuales (usando la opción --extract) o archivos XML (usando la opción --extract-xml). El formato de salida de este último se describe por el archivo dcm2xml.dtd (comenzando con el elemento de nivel superior "data-set"). Para archivos XML, el Juego de Caracteres Específico se mapea automáticamente a una codificación XML apropiada. Si esto no es posible, p. ej. en el caso de conjuntos de caracteres ISO 2022, los caracteres no ASCII y aquellos por debajo de #32 se almacenan como "&" donde "nnn" se refiere al código de carácter numérico. Tenga en cuenta que esto

podría

llevar a referencias de entidad de carácter inválidas (como "&" para ESC) y hará que la mayoría de los analizadores XML rechacen el documento. Alternativamente, todos los conjuntos de datos de respuesta de una asociación se pueden extraer a un solo archivo XML usando la opción --extract-xml-single. El elemento de nivel superior del documento XML es "responses" (con un atributo "type" de "C-FIND"). Los conjuntos de datos individuales se almacenan como se describió arriba. Si el soporte para la conversión de conjuntos de caracteres está habilitado, se usa

la

codificación UTF-8,

es

decir, todos los conjuntos de datos se convierten a la codificación UTF-8

(lo 
cual se recomienda encarecidamente para evitar problemas con
    caracteres no ASCII cuando se usan diferentes conjuntos de caracteres).

REGISTRO (LOGGING) El nivel de salida de registro (logging) de las diversas herramientas de línea de comandos y las bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se reportan mensajes informativos como detalles de procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, p. ej. para propósitos de depuración. Otros niveles de registro se pueden seleccionar usando la opción

--log-level.

En el modo --quiet solo se reportan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, ver la documentación del módulo "oflog". En caso de que la salida de registro se deba escribir en un archivo (opcionalmente con rotación de archivo de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para parámetros: corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores. Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente,

el

orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se conforma a las reglas de evaluación estándar de los shells Unix comunes. Además, se pueden especificar uno o más archivos de comando usando un signo '@' como prefijo del nombre de archivo (p. ej. @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cua

lquie
r otra

evaluación

Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/dumppat.txt). ENTORNO La utilidad findscu

intentará

cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está definida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (por defecto en Windows). Se debe preferir el comportamiento por defecto y la variable de entorno DCMDICTPATH solo se debe usar cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable

PATH

del shell Unix en el que un dos puntos (":") separa las entradas. En sistemas Windows, se usa un punto y coma (";") como separador.
