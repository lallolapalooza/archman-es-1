DESCRIPCIÓ

N

Las transferencias atómicas se utilizan para leer y actualizar datos ubicados en regiones de memoria remotas de manera atómica. Conceptualmente, son similares a las operaciones atómicas locales de naturaleza similar (por ejemplo, incremento atómico, intercambio con comparación, etc.). Las actualizaciones a datos remotos implican una de varias operaciones sobre los datos y actúan sobre tipos específicos de datos, como se lista a continuación. Como tal, las transferencias atómicas tienen conocimiento del formato de los datos que se están accediendo. Una sola función atómica puede operar a través de un array de datos aplicando una operación atómica a cada entrada, pero la atomicidad de una operación está limitada a un solo tipo de dato o

entrada.

Operaciones Atómicas

Se definen las siguientes operaciones atómicas. Una operación atómica a menudo actúa sobre un valor objetivo en el búfer de memoria remota y un valor fuente proporcionado con la función atómica. También puede transportar datos fuente para reemplazar el valor objetivo en operaciones de comparación e intercambio (compare and swap). Se proporciona una descripción conceptual de cada operación.

Funciones Atómicas Base

Las funciones atómicas base – fi_atomic, fi_atomicv, fi_atomicmsg – se utilizan para transmitir datos a un nodo remoto, donde se realiza la operación atómica especificada contra los datos de destino. El resultado de una función atómica base se almacena en la región de memoria remota. La principal diferencia entre las funciones atómicas es el número y el tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

La llamada fi_atomic transfiere los datos contenidos en el búfer de datos especificado por el usuario a un nodo remoto. Para los puntos finales sin conexión, el punto final de destino se especifica a través del parámetro dest_addr. A menos que el punto final se haya configurado de manera diferente, el búfer de datos pasado a fi_atomic no debe ser tocado por la aplicación hasta que la llamada fi_atomic se complete de forma asíncrona. El búfer de destino de una operación atómica base debe permitir el acceso de lectura y/o escritura remota, según corresponda.

La llamada fi_atomicv añade soporte para una lista de dispersión-agrupamiento (scatter-gather) a fi_atomic. El fi_atomicv transfiere el conjunto de búferes de datos referenciados por el parámetro ioc al nodo remoto para su procesamiento.

La llamada fi_inject_atomic es una versión optimizada de fi_atomic. La función fi_inject_atomic se comporta como si la bandera de transferencia FI_INJECT estuviera establecida y FI_COMPLETION no lo estuviera. Es decir, el búfer de datos está disponible para su reutilización inmediatamente al regresar de fi_inject_atomic, y no se generará un evento de finalización para esta operación atómica. El evento de finalización se suprimirá incluso si el punto final no se ha configurado con FI_SELECTIVE_COMPLETION. Consulte la discusión de las banderas más abajo para más detalles. El tamaño de mensaje solicitado que se puede usar con fi_inject_atomic está limitado por inject_size.

La llamada fi_atomicmsg admite funciones atómicas sobre puntos finales conectados y sin conexión, con la capacidad de controlar la operación atómica por llamada mediante el uso de banderas. La función fi_atomicmsg toma un struct fi_msg_atomic como entrada.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* local scatter-gather array */

La siguiente lista de operaciones atómicas se puede utilizar con las operaciones atómicas base: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR y FI_ATOMIC_WRITE.

Funciones de Obtención Atómica (Fetch-Atomic)

Las funciones de obtención atómica – fi_fetch_atomic, fi_fetch_atomicv y fi_fetch atomicmsg – se comportan de manera similar a la función atómica base equivalente. La diferencia entre las llamadas de obtención atómica y las de base es que las rutinas de obtención atómica devuelven al usuario el valor inicial que estaba almacenado en el destino. El valor inicial se lee en el búfer de resultados proporcionado por el usuario. El búfer de destino de las operaciones de obtención atómica debe estar habilitado para acceso de lectura remota.

La siguiente lista de operaciones atómicas se puede utilizar con las operaciones de obtención atómica: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ y FI_ATOMIC_WRITE.

Para las operaciones FI_ATOMIC_READ, el operando del búfer fuente (por ejemplo, el parámetro buf de fi_fetch_atomic) se ignora y puede ser NULL. Los resultados se escriben en el búfer de resultados.

Funciones de validación

atómica

Las funciones de validación atómica – fi_atomicvalid, fi_fetch_atomicvalid y fi_compare_atomicvalid – indican qué operaciones admite el proveedor local. Las operaciones necesarias que no sean compatibles con el proveedor deben ser emuladas por la aplicación. Cada llamada de validación corresponde a un conjunto de funciones atómicas. fi_atomicvalid comprueba si un proveedor admite una operación atómica base específica para un determinado tipo de datos y operación. fi_fetch_atomicvalid indica si un proveedor admite una operación fetch-atomic específica para un determinado tipo de datos y operación. Y fi_compare_atomicvalid comprueba si un proveedor admite una operación compare-atomic especificada para un determinado tipo de datos y

operación.

Completacione

s

Las operaciones atómicas completadas se informan al iniciador de la solicitud a través de una cola de completaciones o contador asociado. Cualquier contexto proporcionado por el usuario especificado con la solicitud se devolverá como parte de cualquier evento de completación escrito a una CQ. Consulte fi_cq para obtener los detalles de los eventos de

completación.

Cualquier resultado devuelto al iniciador como parte de una operación atómica estará disponible antes de que se genere un evento de completación. Esto será cierto incluso si la semántica de completación solicitada proporciona una garantía más débil. Es decir, las operaciones fetch atómicas tienen semántica FI_DELIVERY_COMPLETE. Las completaciones generadas para otros tipos de operaciones atómicas indican que es seguro reutilizar los búferes de datos de

origen.

Cualquier actualización de datos en el destino de una operación atómica será visible para los agentes (procesos CPU, NICs y otros dispositivos) en el nodo de destino antes de que ocurra uno de los siguientes eventos. Si la operación atómica genera un evento de completación o actualiza un contador de completación en el punto de extremo de destino, los resultados estarán disponibles antes de la notificación de completación. Después de procesar una completación para la operación atómica, si el iniciador envía una transferencia entre los mismos puntos de extremo que genera una completación en el destino, los resultados estarán disponibles antes del evento de la transferencia posterior. O, si una transferencia de datos delimitada (fenced) del iniciador sigue a la solicitud atómica, los resultados estarán disponibles antes de una completación en el destino para la transferencia

delimitada.

La corrección de las operaciones atómicas en una región de memoria de destino está garantizada solo cuando las realiza un único actor durante una ventana de tiempo dada. Un actor se define como un único dominio libfabric en el destino (iden

tificado por el nombre del dominio, y no una instancia abierta de ese dominio), un complejo CPU coherente u otro dispositivo (p. ej., GPU) capaz de realizar operaciones atómicas en la memoria de destino. Los resultados de las operacion
es atómicas realizadas por múltiples actores simultáneamente son indefinidos. Por ejemplo, emitir operaciones atómicas basadas en CPU a una región de destino que está siendo actualizada simultáneamente por operaciones atómicas basadas
en NIC puede dejar los datos de la región en un estado desconocido. Los resultados de las operaciones atómicas de un primer actor deben ser visibles para un segundo actor antes de que el segundo actor emita sus propias operaciones atómicas.

NOTA

S

Las operaciones atómicas operan sobre un array de valores de un tipo de datos específico. La atomicidad solo está garantizada para cada operación de tipo de datos, no a través de todo el array. El siguiente pseudocódigo demuestra esta operación para una escritura atómica de 64 bits sin signo. ATOMIC_WRITE_U64 es una macro dependiente de la plataforma que escribe atómicamente 8 bytes en una ubicación de memoria

alineada. 
fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]
);
}

El número de elementos del array sobre los que operar se especifica a través de un parámetro count. Este debe estar entre 1 y el máximo devuelto a través de la operación de validación correspondiente, inclusive. La operación solicitada y el tipo de datos también deben ser válidos para el proveedor

dado.

El orden de las operaciones atómicas transportadas como parte de diferentes mensajes de solicitud está sujeto a las definiciones de orden de mensajes y de datos asignadas a lo

s puntos de extremo de transmisión y recepción. Se requiere tanto el orden de mensajes como el de datos si los resultados de dos operaciones atómicas en los mismos búferes de memor
ia deben reflejar la segunda operación actuando sobre los resultados de la primera. Consulte fi_endpoint(3) para obtener más detalles y las restricciones de tamaño de mensaje.
