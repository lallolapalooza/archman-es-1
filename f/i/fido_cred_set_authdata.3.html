DESCRIPCIÓ

N

El conjunto de funciones fido_cred_set_authdata definen los diversos parámetros de una credencial FIDO2, permitiendo que un tipo fido_cred_t sea preparado para una llamada posterior a fido_dev_make_cred(3) o fido_cred_verify(3). Para la especificación completa de una credencial FIDO2 y el formato de sus partes constituyentes, consulte el estándar Web Authentication (webauthn)

.

Las funciones fido_cred_set_authdata(), fido_cred_set_attstmt(), fido_cred_set_attobj(), fido_cred_set_x509(), fido_cred_set_sig(), fido_cred_set_id(), y fido_cred_set_clientdata_hash() establecen los datos del autenticador, la declaración de atestación, el objeto de atestación, el certificado de atestación, la firma de atestación, el id y el hash de datos del cliente de cred a ptr, donde ptr apunta a len bytes. Se hace una copia de ptr, y no se mantienen referencias al puntero

pasado.

Los datos del autenticador pasados a fido_cred_set_authdata() deben ser una cadena de bytes codificada en CBOR, como se obtiene de fido_cred_authdata_ptr(). Alternativamente, se puede pasar un blob binario sin procesar a ata_raw">fido_cred_set_authdata_raw(). Una aplicación que llame a fido_cred_set_authdata() no necesita llamar a fido_cred_set_id(). Esta última está destinada a usarse en contextos donde los datos de autenticación de la credencial no

están

disponibles. La declaración de atestación pasada a fido_cred_set_attstmt() debe ser un mapa codificado en CBOR, tal como se obtiene de fido_cred_attstmt_ptr(). Una aplicación que llame a fido_cred_set_attstmt() no necesita llamar a fido_cred_set_x509() ni a fido_cred_set_sig(). Estas dos últimas están destinadas a usarse en contextos donde la declaración de atestación completa de la

credencial

no está disponible o no es requerida. El objeto de atestación pasado a fido_cred_set_attobj() debe ser un mapa codificado en CBOR que contenga “authData”, “fmt” y “attStmt”. Una aplicación que llame a fido_cred_set_attobj() no necesita llamar a fido_cred_set_fmt() , fido_cred_set_attstmt(), fido_cred_set_authdata() ni a fido_cred_set_authdata_raw(). fido_cred_set_attobj() puede ser útil en aplicaciones que interactúan con la API de WebAuthn, eliminando la necesidad de analizar primero el

objeto

de atestación para verificar la credencial. La fido_cred_set_clientdata() función permite a una aplicación establecer el hash de los datos del cliente de cred especificando los datos del cliente sin hash de la credencial. Esto es requerido por Windows Hello, que calcula el hash de los datos del cliente internamente. Para la compatibilidad con Windows Hello, las ap

licaciones

deberían usar fido_cred_set_clientdata() en lugar de fido_cred_set_clientdata_hash() . La fido_cred_set_rp() función establece los parámetros de la parte confiante (relying party) id y name de cred, donde id y name son cadenas UTF-8 terminadas en

NUL.

El contenido de id y name se copia, y no se mantienen referencias a los punteros pasados. La fido_cred_set_user() función establece los atributos del usuario de cred, donde user_id apunta a user_id_len bytes y name, display_name, y icon son cadenas UTF-8 terminadas en NUL. El contenido de user_id, name, display_name y icon se copia, y no se mantienen referencias a los punteros pasados. Los atributos de usuario

establecidos

p reviamente se eliminan. Los parámetros user_id, name, display_name y icon pueden ser NULL. La fido_cred_set_entattest() función establece el modo de atestación empresarial de cred a ea. Por el momento, solo se admiten los modos FIDO_ENTATTEST_VENDOR y FIDO_ENTATTEST_PLATFORM

Por el momento, solo se admiten las extensiones FIDO_EXT_CRED_BLOB, FIDO_EXT_CRED_PROTECT, FIDO_EXT_HMAC_SECRET, FIDO_EXT_MINPINLEN y FIDO_EXT_LARGEBLOB_KEY

Si flags es cero, las extensiones de cred se eliminan. La fido_cred_set_blob() función establece el “credBlob” a almacenar con cred a los datos

a

a

Por el momento, solo se admiten las protecciones FIDO_CRED_PROT_UV_OPTIONAL, FIDO_CRED_PROT_UV_OPTIONAL_WITH_ID y FIDO_CRED_PROT_UV_REQUIRED. Si prot es cero,

La fido_cred_set_fmt() función establece el identificador de formato de la declaración de atestación de cred a fmt, donde fmt debe ser packed (el formato usado en FIDO2) , fido-u2f (el formato usado en U2F), tpm (el formato usado por autenticadores basados en TPM), o none. Se hace una copia de fmt, y no se mantienen referencias al puntero pasado. Tenga en cuenta que no todos los autenticadores soportan FIDO2 y por lo

tanto

solo pueden ser capaces de generar declaraciones de atestación fido-u2f. La fido_cred_set_type() cose_alg es función establece el tipo de cred a cose_alg, donde cose_alg es COSE_ES256, COSE_ES384, COSE_RS256, o COSE_EDDSA. El tipo de una credencial solo puede establecerse una vez. Tenga

en

cuenta que no todos los autenticadores soportan COSE_RS256, COSE_ES384 o COSE_EDDSA. El uso del conjunto de funciones fido_cred_set_authdata puede ocurrir en dos situaciones distintas: al generar una nueva credencial en un dispositivo FIDO2, antes de fido_dev_make_cred(3) (es decir, en el contexto de un cliente FIDO2), o al validar
