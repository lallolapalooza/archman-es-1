remotas de manera atómica. Conceptualmente, son similares a las operaciones atómicas locales de naturaleza similar (p. ej., incremento atómico, intercambio comparativo, etc.). Las actualizaciones de datos remotos implican una de varias operaciones sobre los datos, y actúan sobre tipos específicos de datos, como se lista a continuación. Como tal, las transferencias atómicas tienen conocimiento del formato de los datos a los que se accede. Una única función atómica puede operar sobre una matriz de datos aplicando una operación atómica a cada entrada, pero la atomicidad de una operación está limitada a un solo tipo de dato o entrada.

Operaciones Atómicas

Se definen las siguientes operaciones atómicas. Una operación atómica a menudo actúa sobre un valor objetivo en el búfer de memoria remoto y un valor fuente proporcionado con la función atómica. También puede transportar datos fuente para reemplazar el valor objetivo en operaciones de comparación e intercambio (compare and swap). Se proporciona una descripción conceptual de cada operación.

FI_MIN
Mínimo
if (buf[i] < addr[i])
    addr[i] = buf[i]
FI_MAX
Máximo
if (buf[i] > addr[i])
    addr[i] = buf[i]
FI_SUM
Suma
addr[i] = addr[i] + buf[i]
FI_PROD
Producto
addr[i] = addr[i] * buf[i]
FI_LOR
OR lógico
addr[i] = (addr[i] || buf[i])
FI_LAND
AND lógico
addr[i] = (addr[i] && buf[i])
FI_BOR
OR a nivel de bits
addr[i] = addr[i] | buf[i]
FI_BAND
AND a nivel de bits
addr[i] = addr[i] & buf[i]
FI_LXOR
XOR lógico (exclusivo lógico)
addr[i] = ((addr[i] && !buf[i]) || (!addr[i] && buf[i]))
FI_BXOR
XOR a nivel de bits (exclusivo a nivel de bits)
addr[i] = addr[i] ^ buf[i]
FI_ATOMIC_READ
Leer datos de forma atómica
result[i] = addr[i]
FI_ATOMIC_WRITE
Escribir datos de forma atómica
addr[i] = buf[i]
FI_CSWAP
Comparar valores y, si son iguales, intercambiarlos con los datos
if (compare[i] == addr[i])
    addr[i] = buf[i]
FI_CSWAP_NE
Comparar valores y, si no son iguales, intercambiarlos con los datos
if (compare[i] != addr[i])
    addr[i] = buf[i]
FI_CSWAP_LE
Comparar valores y, si son menores o iguales, intercambiarlos con los datos
if (compare[i] <= addr[i])
    addr[i] = buf[i]
FI_CSWAP_LT
Comparar valores y, si son menores, intercambiarlos con los datos
if (compare[i] < addr[i])
    addr[i] = buf[i]
FI_CSWAP_GE
Comparar valores y, si son mayores o iguales, intercambiarlos con los datos
if (compare[i] >= addr[i])
    addr[i] = buf[i]
FI_CSWAP_GT
Comparar valores y, si son mayores, intercambiarlos con los datos
if (compare[i] > addr[i])
    addr[i] = buf[i]
FI_MSWAP
Intercambiar bits enmascarados con los datos
addr[i] = (buf[i] & compare[i]) | (addr[i] & ~compare[i])
FI_DIFF
Calcular la diferencia
addr[i] = addr[i] - buf[i]

Funciones Atómicas Base

Las funciones atómicas base – fi_atomic, fi_atomicv, fi_atomicmsg – se utilizan para transmitir datos a un nodo remoto, donde se realiza la operación atómica especificada sobre los datos de destino. El resultado de una función atómica base se almacena en la región de memoria remota. La principal diferencia entre las funciones atómicas es el número y el tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

La llamada fi_atomic transfiere los datos contenidos en el búfer de datos especificado por el usuario a un nodo remoto. Para los puntos finales sin conexión, el punto final de destino se especifica a través del parámetro dest_addr. A menos que el punto final se haya configurado de otra manera, el búfer de datos pasado a fi_atomic no debe ser tocado por la aplicación hasta que la llamada fi_atomic se complete de forma asíncrona. El búfer de destino de una operación atómica base debe permitir el acceso de lectura y/o escritura remota, según corresponda.

La llamada fi_atomicv añade soporte para una lista de dispersión-agrupación (scatter-gather) a fi_atomic. La fi_atomicv transfiere el conjunto de búferes de datos referenciados por el parámetro ioc al nodo remoto para su procesamiento.

La llamada fi_inject_atomic es una versión optimizada de fi_atomic. La función fi_inject_atomic se comporta como si el indicador de transferencia FI_INJECT estuviera activado y FI_COMPLETION no lo estuviera. Es decir, el búfer de datos está disponible para su reutilización inmediatamente al regresar de fi_inject_atomic, y no se generará un evento de finalización para esta operación atómica. El evento de finalización se suprimirá incluso si el punto final no se ha configurado con FI_SELECTIVE_COMPLETION. Consulte la discusión de indicadores más abajo para más detalles. El tamaño de mensaje solicitado que se puede usar con fi_inject_atomic está limitado por inject_size.

La llamada fi_atomicmsg admite funciones atómicas sobre puntos finales conectados y sin conexión, con la capacidad de controlar la operación atómica en cada llamada mediante el uso de indicadores. La función fi_atomicmsg toma un struct fi_msg_atomic como entrada.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* local scatter-gather array */
    void                **desc;   /* local access descriptors */
    size_t              iov_count;/* # elements in ioc */
    const void          *addr;    /* optional endpoint address */
    const struct fi_rma_ioc *rma_iov; /* remote SGL */
    size_t              rma_iov_count;/* # elements in remote SGL */
    enum fi_datatype    datatype; /* operand datatype */
    enum fi_op          op;       /* atomic operation */
    void                *context; /* user-defined context */
    uint64_t            data;     /* optional data */
};
struct fi_ioc {
    void        *addr;    /* local address */
    size_t      count;    /* # target operands */
};
struct fi_rma_ioc {
    uint64_t    addr;     /* target address */
    size_t      count;    /* # target operands */
    uint64_t    key;      /* access key */
};

La siguiente lista de operaciones atómicas es utilizable con operaciones atómicas base: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR y FI_ATOMIC_WRITE.

Funciones Atómicas con Obtención (Fetch-Atomic)

Las funciones atómicas con obtención – fi_fetch_atomic, fi_fetch_atomicv y fi_fetch_atomicmsg – se comportan de manera similar a la función atómica base equivalente. La diferencia entre las llamadas atómicas con obtención y las base es que las rutinas de obtención atómica devuelven al usuario el valor inicial que estaba almacenado en el destino. El valor inicial se lee en el búfer de resultados proporcionado por el usuario. El búfer de destino de las operaciones de obtención atómica debe estar habilitado para acceso de lectura remota.

La siguiente lista de operaciones atómicas es utilizable con operaciones atómicas con obtención: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ y FI_ATOMIC_WRITE.

Para las operaciones FI_ATOMIC_READ, el operando del búfer fuente (por ejemplo, el parámetro buf de fi_fetch_atomic) se ignora y puede ser NULL. Los resultados se escriben en el búfer de resultados.

ATOMIC OPERATIONS

Atomic operations are operations that perform a read-modify-write operation on remote memory. Atomic operations guarantee that the read, modify, and write phases of the operation are performed atomically and are not interleaved with other operations.

Compare-Atomic Functions

Las funciones atómicas de comparación — fi_compare_atomic, fi_compare_atomicv, y fi_compare atomicmsg — se utilizan para operaciones que requieren comparar los datos de destino con un valor antes de realizar una operación de intercambio. Las funciones atómicas de comparación admiten: FI_CSWAP, FI_CSWAP_NE, FI_CSWAP_LE, FI_CSWAP_LT, FI_CSWAP_GE, FI_CSWAP_GT, y FI_MSWAP.

Funciones Atómicas Válidas

Las funciones atómicas válidas — fi_atomicvalid, fi_fetch_atomicvalid, y fi_compare_atomicvalid — indican qué operaciones admite el proveedor local. Las operaciones necesarias no admitidas por el proveedor deben ser emuladas por la aplicación. Cada llamada válida corresponde a un conjunto de funciones atómicas. fi_atomicvalid comprueba si un proveedor admite una operación atómica base específica para un tipo de dato y operación dados. fi_fetch_atomicvalid indica si un proveedor admite una operación atómica de obtención específica para un tipo de dato y operación dados. Y fi_compare_atomicvalid comprueba si un proveedor admite una operación atómica de comparación especificada para un tipo de dato y operación dados.

Si se admite una operación, una llamada atómica válida devolverá 0, junto con un recuento de unidades de datos atómicas en las que operará una única llamada a función.

Consultar Atributos Atómicos

La llamada fi_query_atomic actúa como una operación atómica válida mejorada (ver las definiciones de funciones atómicas válidas arriba). Se proporciona, en parte, para la extensibilidad futura. La operación de consulta informa qué operaciones atómicas son compatibles con el dominio, para puntos finales configurados adecuadamente.

El comportamiento de fi_query_atomic se ajusta según el parámetro de flags. Si flags es 0, la operación informa los atributos atómicos soportados para operaciones atómicas base, similar a fi_atomicvalid para puntos finales. Si flags tiene el bit FI_FETCH_ATOMIC establecido, la operación se comporta de manera similar a fi_fetch_atomicvalid. De forma similar, el bit de flag FI_COMPARE_ATOMIC da como resultado que la consulta actúe como fi_compare_atomicvalid. Los bits FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC no pueden establecerse ambos.

Si se establece el bit FI_TAGGED, el proveedor indicará si admite operaciones atómicas en búferes de recepción etiquetados. El bit FI_TAGGED puede usarse solo, o en conjunto con los flags FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC.

La salida de fi_query_atomic es struct fi_atomic_attr:

struct fi_atomic_attr {
    size_t count;
    size_t size;
};

El campo de atributo count se define para las llamadas atómicas válidas. El campo size indica el tamaño en bytes del tipo de dato atómico. El campo size es útil para tipos de datos que pueden variar en tamaño según la plataforma o el compilador, como FI_LONG_DOUBLE.

Completados

Las operaciones atómicas completadas se informan al iniciador de la solicitud a través de una cola de completado o un contador asociado. Cualquier contexto proporcionado por el usuario especificado con la solicitud se devolverá como parte de cualquier evento de completado escrito en un CQ. Ver fi_cq para detalles de eventos de completado.

Cualquier resultado devuelto al iniciador como parte de una operación atómica estará disponible antes de que se genere un evento de completado. Esto será cierto incluso si la semántica de completado solicitada proporciona una garantía más débil. Es decir, las operaciones atómicas de obtención tienen la semántica FI_DELIVERY_COMPLETE. Los completados generados para otros tipos de operaciones atómicas indican que es seguro reutilizar los búferes de datos de origen.

Cualquier actualización de datos en el destino de una operación atómica será visible para los agentes (procesos de CPU, NICs y otros dispositivos) en el nodo de destino antes de que ocurra uno de los siguientes eventos. Si la operación atómica genera un evento de completado o actualiza un contador de completado en el punto final de destino, los resultados estarán disponibles antes de la notificación de completado. Después de procesar un completado para lo atómico, si el iniciador envía una transferencia entre los mismos puntos finales que genera un completado en el destino, los resultados estarán disponibles antes del evento de la transferencia subsiguiente. O, si una transferencia de datos cercada del iniciador sigue a la solicitud atómica, los resultados estarán disponibles antes de un completado en el destino para la transferencia cercada.

La corrección de las operaciones atómicas en una región de memoria de destino solo está garantizada cuando es realizada por un único actor para una ventana de tiempo dada. Un actor se define como un único dominio libfabric en el destino (identificado por el nombre del dominio, y no una instancia abierta de ese dominio), un complejo de CPU coherente, u otro dispositivo (por ejemplo, GPU) capaz de realizar operaciones atómicas en la memoria de destino. Los resultados de las operaciones atómicas realizadas por múltiples actores simultáneamente no están definidos. Por ejemplo, emitir operaciones atómicas basadas en CPU a una región de destino que está siendo actualizada concurrentemente por atómicas basadas en NIC puede dejar los datos de la región en un estado desconocido. Los resultados de las operaciones atómicas del primer actor deben ser visibles para el segundo actor antes de que el segundo actor emita sus propias atómicas.

FLAGS

Las llamadas fi_atomicmsg, fi_fetch_atomicmsg, y fi_compare_atomicmsg permiten al usuario especificar flags que pueden cambiar la operación de transferencia de datos predeterminada. Los flags especificados con operaciones de mensajes atómicos anulan la mayoría de los flags configurados previamente con el punto final, excepto donde se indica (ver fi_control). La siguiente lista de flags se puede usar con llamadas de mensajes atómicos.

FI_COMPLETION
Indica que se debe generar una entrada de completado para la operación especificada. El punto final debe estar enlazado a una cola de completado con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o este flag se ignora.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que se publicarán inmediatamente después de que la llamada actual regrese. El uso de este flag puede mejorar el rendimiento al permitir que el proveedor optimice su acceso al hardware de la red.
FI_INJECT
Indica que el control de los búferes de datos constantes debe devolverse al usuario inmediatamente después de que la llamada regrese, incluso si la operación se maneja de forma asíncrona. Esto puede requerir que la implementación del proveedor subyacente copie los datos a un búfer local y transfiera desde ese búfer. Los búferes de datos constantes se refieren a cualquier búfer de datos o iovec utilizado por las APIs atómicas que están marcados como `const'. Los búferes no constantes o de salida no se ven afectados por este flag y pueden ser accedidos por el proveedor en cualquier momento hasta que la operación se haya completado. Este flag solo se puede usar con mensajes más pequeños que inject_size.
FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como operación cercada, y cualquier operación publicada después de la operación cercada se retrasarán hasta que todas las operaciones anteriores dirigidas al mismo punto final par hayan completado. Las operaciones publicadas después del cercado verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación cercada.

El orden de las operaciones que comienzan en la publicación de la operación cercada (inclusive) hasta la publicación de una operación cercada subsiguiente (exclusiva) se controla mediante la semántica de ordenación del punto final. Ambos ordenamientos de mensajes y datos son necesarios si los resultados de dos operaciones atómicas a los mismos búferes de memoria deben reflejar que la segunda operación actúa sobre los resultados de la primera. Ver fi_endpoint(3) para más detalles y restricciones de tamaño de mensaje.

FI_TAGGED
Especifica que el destino de la operación atómica es un búfer de recepción etiquetado en lugar de un búfer RMA. Cuando un búfer etiquetado es la región de memoria de destino, el parámetro addr se utiliza como un offset de byte basado en 0 en el búfer etiquetado, con el parámetro key especificando la etiqueta.

VALOR DE RETORNO

Devuelve 0 en caso de éxito. En caso de error, se devuelve un valor negativo correspondiente al errno de fabric. Los valores de errno de fabric se definen en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Ver fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
-FI_EOPNOTSUPP
La operación atómica solicitada no es compatible con este punto final.
-FI_EMSGSIZE
El número de operaciones atómicas en una sola solicitud excede lo admitido por el proveedor subyacente.

NOTAS

Las operaciones atómicas operan sobre un array de valores de un tipo de dato específico. La atomicidad solo se garantiza para cada operación de tipo de dato, no para todo el array. El siguiente pseudocódigo demuestra esta operación para una escritura atómica unsigned de 64 bits. ATOMIC_WRITE_U64 es una macro dependiente de la plataforma que escribe atómicamente 8 bytes en una ubicación de memoria alineada.

fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]);
}

El número de elementos del array sobre los que operar se especifica mediante un parámetro de recuento. Este debe estar entre 1 y el máximo devuelto a través de la operación válida relevante, inclusive. La operación solicitada y el tipo de dato también deben ser válidos para el proveedor dado.

El ordenamiento de las operaciones atómicas llevadas a cabo como parte de diferentes mensajes de solicitud está sujeto a las definiciones de ordenamiento de mensajes y datos asignadas a los puntos finales de transmisión y recepción. Se requieren tanto el ordenamiento de mensajes como el de datos si los resultados de dos operaciones atómicas a los mismos búferes de memoria deben reflejar que la segunda operación actúa sobre los resultados de la primera. Ver fi_endpoint(3) para más detalles y restricciones de tamaño de mensaje.
