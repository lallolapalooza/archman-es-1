NOMBRE

filter-a - filtrar A en respuestas DNS cuando AAAA está presente

SINOPSIS

plugin query "filter-a.so" [{ parámetros }];

DESCRIPCIÓN

filter-a.so es un módulo de plugin de consulta para named <#std-iscman-named>, que permite a named <#std-iscman-named> omitir algunas direcciones IPv4 al responder a clientes.

Por ejemplo:

plugin query "filter-a.so" {
        filter-a-on-v6 yes;
        filter-a-on-v4 yes;
        filter-a { 192.0.2.1; 2001:db8:2::1; };
};

Este módulo está destinado a ayudar en la transición de IPv4 a IPv6, al retener las direcciones IPv4 de los clientes DNS que no están conectados a Internet IPv4, cuando el nombre que se está consultando tiene una dirección IPv6 disponible. No se recomienda el uso de este módulo a menos que sea absolutamente necesario.

Nota: Este mecanismo puede causar erróneamente que otros servidores no proporcionen registros A a sus clientes. Si un servidor recursivo con conexiones de red IPv6 e IPv4 consulta un servidor autoritativo que utiliza este mecanismo a través de IPv6, se le niegan los registros A incluso si su cliente está utilizando IPv4.

OPCIONES

filter-a
Esta opción especifica una lista de direcciones de cliente a las que se aplicará el filtrado de A. El valor predeterminado es any.
filter-a-on-v6
Si se establece en yes, esta opción indica que el cliente DNS se encuentra en una dirección IPv6, en filter-a. Si la respuesta no incluye firmas DNSSEC, se eliminan todos los registros A de la respuesta. Este filtrado se aplica a todas las respuestas, no solo a las autoritativas.

Si se establece en break-dnssec, los registros A se eliminan incluso cuando DNSSEC está habilitado. Como sugiere el nombre, esto hace que la respuesta falle la verificación, porque el protocolo DNSSEC está diseñado para detectar eliminaciones.

Este mecanismo puede causar erróneamente que otros servidores no proporcionen registros A a sus clientes. Si un servidor recursivo con conexiones de red IPv6 e IPv4 consulta un servidor autoritativo que utiliza este mecanismo a través de IPv6, se le niegan los registros A incluso si su cliente está utilizando IPv4.

filter-a-on-v4
Esta opción es idéntica a filter-a-on-v6, excepto que filtra las respuestas A a las consultas de clientes IPv4 en lugar de clientes IPv6. Para filtrar todas las respuestas, establezca ambas opciones en yes.
