FIDO2-ASSERT(1) Manual de Comandos Generales FIDO2-ASSERT(1)

NOMBRE

fido2-assert — obtener/verificar una aserción FIDO2

SINOPSIS

fido2-assert -G [-bdhpruvw] [-t option] [-i input_file] [-o output_file] device

fido2-assert -V [-dhpv] [-i input_file] key_file [type]

DESCRIPCIÓN

fido2-assert obtiene o verifica una aserción FIDO2.

La entrada de fido2-assert está definida por los parámetros de la aserción a obtener/verificar. Consulte la sección FORMATO DE ENTRADA para más detalles.

La salida de fido2-assert está definida por el resultado de la operación seleccionada. Consulte la sección FORMATO DE SALIDA para más detalles.

Si una aserción se obtiene o verifica correctamente, fido2-assert sale con código 0. De lo contrario, fido2-assert sale con código 1.

Las opciones son las siguientes:

-G
Indica a fido2-assert que obtenga una nueva aserción de device.
-V
Indica a fido2-assert que verifique una aserción usando la clave pública codificada en PEM en key_file de tipo type, donde type puede ser es256 (denotando ECDSA sobre NIST P-256 con SHA-256), es384 (denotando ECDSA sobre NIST P-384 con SHA-384), rs256 (denotando RSA de 2048 bits con relleno PKCS#1.5 y SHA-256), o eddsa (denotando EDDSA sobre Curve25519 con SHA-512). Si type no se especifica, es256 se asume por defecto.
-b
Solicita el «largeBlobKey» de la credencial, una clave simétrica de 32 bytes asociada con la credencial asertada.
-h
Si se obtiene una aserción, habilita la extensión hmac-secret de FIDO2. Si se verifica una aserción, comprueba si el bit de datos de la extensión fue firmado por el autenticador.
-d
Hace que fido2-assert emita salida de depuración en stderr.
-i input_file
Indica a fido2-assert que lea los parámetros de la aserción desde input_file en lugar de stdin.
-o output_file
Indica a fido2-assert que escriba la salida en output_file en lugar de stdout.
-p
Si se obtiene una aserción, solicita la presencia del usuario. Si se verifica una aserción, comprueba si el bit de presencia del usuario fue firmado por el autenticador.
-r
Obtiene una aserción usando una credencial residente. Si -r se especifica, fido2-assert no esperará un id de credencial en su entrada, y puede emitir múltiples aserciones. Las credenciales residentes se denominan «credenciales descubribles» en CTAP 2.1.
-t option
Alterna una opción clave/valor option, donde option es una cadena de la forma «clave=valor». Las opciones soportadas actualmente son:
up=true|false
Pide al autenticador que la presencia del usuario sea habilitada o deshabilitada.
uv=true|false
Pide al autenticador que la verificación del usuario sea habilitada o deshabilitada.
pin=true|false
Indica a fido2-assert si debe solicitar un PIN y pedir la verificación del usuario.

La -t opción puede especificarse múltiples veces.

-u
Obtiene una aserción usando U2F. Por defecto, fido2-assert usará FIDO2 si es soportado por el autenticador, y usará U2F como alternativa en caso contrario.
-v
Si se obtiene una aserción, solicita al usuario un PIN y pide la verificación del usuario al autenticador. Si se verifica una aserción, comprueba si el bit de verificación del usuario fue firmado por el autenticador.
-w
Indica a fido2-assert que la primera línea de entrada al obtener una aserción debe interpretarse como datos del cliente sin hashear. Esto es requerido por Windows Hello, que calcula el hash de los datos del cliente internamente.

Si un tty está disponible, fido2-assert lo usará para obtener el PIN. De lo contrario, stdin se usa.

FORMATO DE ENTRADA

La entrada de fido2-assert consiste en bloques base64 y cadenas UTF-8 separadas por caracteres de salto de línea ('\n').

Al obtener una aserción, fido2-assert espera que su entrada consista de:

  1. hash de datos del cliente (bloque base64);
  2. id de la parte confiable (cadena UTF-8);
  3. id de la credencial, si la credencial no es residente (bloque base64);
  4. sal hmac, si la extensión hmac-secret de FIDO2 está habilitada (bloque base64);

Al verificar una aserción, fido2-assert espera que su entrada consista de:

  1. hash de datos del cliente (bloque base64);
  2. id de la parte confiable (cadena UTF-8);
  3. datos del autenticador codificados en CBOR (bloque base64);
  4. firma de la aserción (bloque base64);

Las cadenas UTF-8 pasadas a fido2-assert no deben contener caracteres de salto de línea o NUL incrustados.

FORMATO DE SALIDA

La salida de fido2-assert consiste en bloques base64 y cadenas UTF-8 separadas por caracteres de salto de línea ('\n').

Para cada aserción generada, fido2-assert emite:

  1. hash de datos del cliente (bloque base64);
  2. id de la parte confiable (cadena UTF-8);
  3. datos del autenticador codificados en CBOR (bloque base64);
  4. firma de la aserción (bloque base64);
  5. id de usuario, si la credencial es residente (bloque base64);
  6. secreto hmac, si la extensión hmac-secret de FIDO2 está habilitada (bloque base64);
  7. la clave simétrica de 32 bytes asociada con la credencial («largeBlobKey»), si se solicitó (bloque base64).

Al verificar una aserción, fido2-assert no produce salida.

EJEMPLOS

Asumiendo que cred contiene una es256 credencial creada según los pasos descritos en fido2-cred(1), obtenga unan una aserción de un autenticador en /dev/hidraw5 y verificarla:

$ echo assertion challenge | openssl sha256 -binary | base64 > assert_param
$ echo relying party >> assert_param
$ head -1 cred >> assert_param
$ tail -n +2 cred > pubkey
$ fido2-assert -G -i assert_param /dev/hidraw5 | fido2-assert -V pubkey es256
