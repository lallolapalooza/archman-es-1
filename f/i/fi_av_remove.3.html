DESCRIPCIÓ

N

Los vectores de dirección se utilizan para mapear direcciones de nivel superior, que pueden ser más naturales para una aplicación, en direcciones específicas del tejido. Por ejemplo, un extremo puede estar asociado con una dirección struct sockaddr_in, indicando que el extremo es accesible mediante un número de puerto TCP sobre una dirección IPv4. Esto puede ser cierto incluso si el extremo comunica datos utilizando un protocolo de red propietario. El propósito del AV es asociar una dirección de nivel superior con un valor más simple y eficiente que pueda ser utilizado por la API de libfabric de una manera agnóstica del tejido. La dirección mapeada es del tipo fi_addr_t y se devuelve a través de una llamada de inserción de

AV.

El proceso de mapeo de una dirección es específico del tejido y del proveedor, pero puede involucrar protocolos largos de resolución de direcciones y gestión de tejido. Las operaciones AV son síncronas por defecto (la opción asíncrona ha sido obsoleta, véase abajo). Consulte la sección NOTAS para las restricciones de AV sobre direcciones

duplicadas.

Obsoleto: Las operaciones AV pueden configurarse para funcionar de manera asíncrona especificando la bandera FI_EVENT para fi_av_open. Cuando se solicita una operación asíncrona, la aplicación debe vincular primero una cola de eventos al AV antes de insertar

direcciones.

Un tipo de AV corresponde a una implementación conceptual de un vector de direcciones. El tipo especifica cómo una aplicación ve los datos almacenados en el AV, incluyendo cómo puede ser accedidos. Los valores válidos
son:
- FI_AV_MAP
(obsoleto)
Las direcciones que se insertan en un AV se mapean a una dirección nativa del tejido para su uso por la aplicación. El uso de FI_AV_MAP requiere que una aplicación almacene el valor fi_addr_t devuelto que está asociado con cada dirección insertada. La ventaja de usar FI_AV_MAP es que el valor fi_addr_t devuelto puede contener datos de dirección codificados, que están inmediatamente disponibles al procesar solicitudes de transferencia de datos. Esto puede eliminar o reducir el número de consultas de memoria necesarias al iniciar una transferencia. La desventaja de FI_AV_MAP es el aumento en el uso de memoria necesario para almacenar las direcciones devueltas. Las direcciones se almacenan en el AV utilizando un mecanismo específico del proveedor, incluyendo, pero no limitado a, un árbol, una tabla hash o mantenido en el montón. Esta opción es obsoleta y se anima a los proveedores para que alineen el comportamiento de FI_AV_MAP con
FI_AV_TABLE.
- FI_AV_TAB
LE
Las direcciones que se insertan en un AV de tipo FI_AV_TABLE son accesibles utilizando un índice simple. Conceptualmente, el AV puede tratarse como un array de direcciones, aunque el proveedor puede implementar el AV utilizando una variedad de mecanismos. Cuando se usa FI_AV_TABLE, el fi_addr_t devuelto es un índice, con el índice para una dirección insertada igual a su orden de inserción en la tabla. El índice de la primera dirección insertada en un FI_AV_TABLE será 0, y las inserciones sucesivas se asignarán índices secuenciales. Los índices secuenciales se asignarán a través de llamadas de inserción en el mismo AV. Debido a que los valores fi_addr_t devueltos por una llamada de inserción son deterministas, las aplicaciones pueden no necesitar proporcionar los parámetros de salida fi_addr_t a las llamadas de inserción. La excepción es cuando los parámetros fi_addr_t también se utilizan como entrada para proporcionar autenticación claves o IDs definidos por el
usuario.

fi_av_inser

t

La llamada fi_av_insert inserta cero o más direcciones en un AV. El número de direcciones se especifica a través del parámetro count. El parámetro addr referencia un array de direcciones a insertar en el AV. Las direcciones insertadas en un vector de direcciones deben estar en el mismo formato que el especificado en el campo addr_format de la estructura fi_info proporcionada al abrir el dominio correspondiente. Al usar el formato FI_ADDR_STR, el parámetro addr debe referenciar un array de cadenas (char **)

.

Obsoleto: Para AVs de tipo FI_AV_MAP, una vez que las direcciones insertadas se han mapeado, los valores mapeados se escriben en el buffer referenciado por fi_addr. El buffer fi_addr debe permanecer válido hasta que la inserción del AV se haya completado y se haya generado un evento a una cola de eventos asociada. El valor del fi_addr devuelto debe considerarse opaco por la aplicación para AVs de tipo FI_AV_MAP. El valor devuelto puede apuntar a una estructura interna o a una codificación específica del proveedor de datos de direccionamiento de bajo nivel, por ejemplo. En este último caso, el uso de FI_AV_MAP puede evitar referencias a memoria durante las operaciones de transferencia de

datos.

Para AVs de tipo FI_AV_TABLE, las direcciones se colocan en la tabla en orden. Una dirección se inserta en el índice más bajo que corresponde a una ubicación de tabla no usada, con los índices comenzando en 0. Es decir, la primera dirección insertada puede referenciarse en el índice 0, la segunda en el índice 1, y así sucesivamente. Cuando se insertan direcciones en una tabla AV, los valores fi_addr asignados serán índices simples correspondientes a la entrada en la tabla donde se insertó la dirección. Los valores de índice se acumulan a lo largo de llamadas de inserción sucesivas en el orden en que se hacen las llamadas, no necesariamente en el orden en que se completan las

inserciones.

Debido a que las inserciones ocurren en un índice predeterminado, el parámetro fi_addr puede ser NULL. Si fi_addr no es NULL, debe referenciar un array de fi_addr_t, y el buffer debe permanecer válido hasta que la operación de inserción se complete. Tenga en cuenta que si fi_addr es NULL y se solicita operación sincrónica sin usar el flag FI_SYNC_ERR, los fallos de inserción individuales no pueden reportarse y la aplicación debe usar otras llamadas, como fi_av_lookup, para averiguar qué direcciones específicas fallaron al

insertarse.

Si el vector de direcciones está configurado con claves de autorización, el parámetro fi_addr puede usarse como entrada para definir las claves de autorización asociadas con las direcciones de endpoint que se están insertando. Esto se hace estableciendo el fi_addr a una clave de autorización fi_addr_t generada a partir de fi_av_insert_auth_key y estableciendo el flag FI_AUTH_KEY. Si el flag FI_AUTH_KEY no está establecido, las direcciones que se insertan no se asociarán con ninguna clave de autorización. Si una dirección puede desasociarse de una clave de autorización o no es específico del proveedor. Si un proveedor no puede soportar esta desasociación, se devolverá un error. Tras una inserción exitosa con el flag FI_AUTH_KEY, los fi_addr_t devueltos se mapearán a la dirección de endpoint contra las claves de autorización especificadas. Estos fi_addr_t pueden usarse como destino para operaciones de transferencia de datos

locales.

Si el endpoint soporta FI_DIRECTED_RECV o FI_TAGGED_DIRECTED_RECV, estos fi_addr_t pueden usarse para restringir los buffers de recepción a una dirección de endpoint y clave de autorización

específicas.

Para vectores de direcciones configurados con FI_AV_USER_ID, todos los eventos de destino posteriores correspondientes a la dirección que se inserta devolverán FI_ADDR_NOTAVAIL hasta que el usuario defina un ID de usuario para este fi_addr_t. Esto se hace usando fi_av_set_user_id

.

fi_av_insertsvc

La llamada fi_av_insertsvc se comporta de manera similar a fi_av_insert, pero permite a la aplicación especificar los nombres de nodo y servicio, similar a las entradas de fi_getinfo, en lugar de una dirección codificada. Los parámetros de nodo y servicio están definidos igual que en fi_getinfo(3). El nodo debe ser una cadena que corresponda a un nombre de host o una dirección de red. La cadena de servicio corresponde a una representación textual de una dirección de transporte. Las aplicaciones también pueden pasar una dirección con formato FI_ADDR_STR como el parámetro de nodo. En tales casos, el parámetro de servicio debe ser NULL. Consulte fi_getinfo.3 para obtener detalles sobre el uso de FI_ADDR_STR. Los indicadores admitidos son los mismos que para fi_av_insert.

fi_av_insertsym

fi_av_insertsym realiza una inserción simétrica que inserta un rango secuencial de direcciones de nodo y/o servicio en un AV. El parámetro svccnt indica el número de direcciones de transporte (punto final) a insertar en el AV para cada dirección de nodo, con el parámetro de servicio especificando la dirección de transporte inicial. Las direcciones de transporte insertadas estarán en el rango {service, service + svccnt - 1}, inclusive. Todas las direcciones de servicio para un nodo se insertarán antes de que se inserte el siguiente nodo.

El parámetro nodecnt indica el número de direcciones de nodo (red) a insertar en el AV, con el parámetro node especificando la dirección de nodo inicial. Las direcciones de nodo insertadas estarán en el rango {node, node + nodecnt - 1}, inclusive. Si node es una cadena no numérica, como un nombre de host, debe contener un sufijo numérico si nodecnt > 1.

Como ejemplo, si node = "10.1.1.1", nodecnt = 2, service = "5000", y svccnt = 2, las siguientes direcciones se insertarán en el AV en el orden mostrado: 10.1.1.1:5000, 10.1.1.1:5001, 10.1.1.2:5000, 10.1.1.2:5001. Si node fuera reemplazado por el nombre de host "host10", las direcciones serían: host10:5000, host10:5001, host11:5000, host11:5001.

El número total de direcciones insertadas será nodecnt x svccnt.

Los indicadores admitidos son los mismos que para fi_av_insert.

fi_av_remove

fi_av_remove elimina un conjunto de direcciones de un vector de direcciones. Los valores fi_addr_t correspondientes quedan invalidados y no pueden usarse en llamadas de transferencia de datos. El comportamiento de las operaciones en curso que referencian las direcciones eliminadas es indefinido.

Tenga en cuenta que eliminar una dirección puede no deshabilitar la recepción de datos desde el punto final del par fi_av_close limpiará automáticamente cualquier recurso asociado.

Si la dirección que se está eliminó provino de fi_av_insert_auth_key, la dirección solo se eliminará si todos los puntos finales, que han sido habilitados contra la clave de autorización correspondiente, han sido cerrados. Si no todos los puntos finales están cerrados, se devolverá -FI_EBUSY. Además, el indicador FI_AUTH_KEY debe establecerse al eliminar una clave de autorización fi_addr_t.

fi_av_lookup

Esta llamada devuelve la dirección almacenada en el vector de direcciones que corresponde al fi_addr dado. La dirección devuelta tiene el mismo formato que las almacenadas por el AV. En la entrada, el parámetro addrlen debe indicar el tamaño del búfer addr. Si la dirección real es más grande de lo que cabe en el búfer, se truncará. En la salida, addrlen se establece en el tamaño del búfer necesario para almacenar la dirección, que puede ser mayor que el valor de entrada.

fi_rx_addr

Esta función se usa para convertir una dirección de punto final, devuelta por fi_av_insert, en una dirección que especifica un contexto de recepción de destino. El valor de rx_ctx_bits debe coincidir con el especificado en los atributos del AV para la dirección dada.

Los puntos finales conectados que admiten múltiples contextos de recepción, pero no están asociados con vectores de direcciones, deben especificar FI_ADDR_NOTAVAIL para el parámetro fi_addr.

fi_av_straddr

La función fi_av_straddr convierte la dirección proporcionada en una cadena imprimible. La dirección especificada debe tener el mismo formato que las almacenadas por el AV, aunque la dirección en sí no necesita haber sido insertada. En la entrada, el parámetro len debe especificar el tamaño del búfer referenciado por buf. En la salida, addrlen se establece en el tamaño del búfer necesario para almacenar la dirección. Este tamaño puede ser mayor que el len de entrada. Si el búfer proporcionado es demasiado pequeño, los resultados se truncarán. fi_av_straddr devuelve un puntero a buf.

fi_av_insert_auth_key

Esta función asocia claves de autorización con un vector de direcciones. Esto requiere que el dominio se abra con FI_AV_AUTH_KEY. FI_AV_AUTH_KEY permite que los puntos finales y las regiones de memoria se asocien con claves de autorización desde el vector de direcciones. Este comportamiento permite que un solo punto final o región de memoria se asocie con múltiples claves de autorización.

Cuando se habilitan puntos finales o regiones de memoria, se configuran con claves de autorización del vector de direcciones en ese momento. Las inserciones posteriores de claves de autorización no se propagarán a los puntos finales y regiones de memoria ya habilitados.

Los parámetros auth_key y auth_key_size se usan para introducir la clave de autorización en el vector de direcciones. La estructura de la clave de autorización es específica del proveedor. Si auth_key_size no se alinea con la estructura específica del proveedor, se devolverá -FI_EINVAL.

La salida de fi_av_insert_auth_key es un identificador fi_addr_t de clave de autorización que representa todas las direcciones de punto final contra esta clave de autorización específica. Para todas las operaciones, incluyendo vector de direcciones, registro de memoria y transferencias de datos, que puedan aceptar un fi_addr_t de clave de autorización como entrada, debe especificarse el indicador FI_AUTH_KEY. De lo contrario, el fi_addr_t se tratará como un fi_addr_t devuelto por fi_av_insert y funciones relacionadas.

Para puntos finales habilitados con FI_DIRECTED_RECV, los fi_addr_t de clave de autorización pueden usarse para restringir los mensajes entrantes solo a direcciones de punto final dentro de la clave de autorización. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_recvmsg y fi_trecvmsg.

Para dominios habilitados con FI_DIRECTED_RECV, los fi_addr_t de clave de autorización pueden usarse para restringir el acceso a la región de memoria solo a direcciones de punto final dentro de la clave de autorización. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_mr_regattr.

Estos fi_addr_t de clave de autorización pueden usarse más adelante como entrada para funciones de inserción de dirección de punto final para generar un fi_addr_t para una dirección de punto final y clave de autorización específicas. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_av_insert y funciones relacionadas.

Para vectores de direcciones configurados con FI_AV_USER_ID y puntos finales con FI_SOURCE_ERR, todos los eventos de error FI_EADDRNOTAVAIL posteriores devolverán FI_ADDR_NOTAVAIL hasta que el usuario defina un ID de usuario para este fi_addr_t de clave de autorización. Esto se hace usando fi_av_set_user_id.

Para vectores de direcciones configurados sin FI_AV_USER_ID y puntos finales con FI_SOURCE_ERR, todos los eventos de error FI_EADDRNOTAVAIL posteriores devolverán el identificador fi_addr_t de clave de autorización.

Los indicadores están reservados para uso futuro y deben ser 0.

NOTA

S

Un AV solo debe almacenar una única instancia de una dirección. Intentar insertar una copia duplicada de la misma dirección en un AV puede resultar en un comportamiento no definido, dependiendo de la implementación del proveedor. No se

exige a los proveedores que comprueben si hay duplicados, ya que hacerlo podría incurrir en una sobrecarga significativa en el proceso de inserción. Para la portabilidad, las aplicaciones pueden necesitar rastrear qué direcciones de
pares se han insertado en un AV determinado para evitar entradas duplicadas. Sin embargo, se exige a los proveedores que admitan la eliminación y la posterior reinserción de una dirección. Solo se restringen las inserciones duplicadas.

IDENTIFICADORES DE USUARIO PARA

DIRECCIONES

Como se describió anteriormente, las direcciones de los puntos finales y las claves de autorización que se insertan en un AV se asignan a un valor fi_addr_t. El fi_addr_t de la dirección del punto final se utiliza en las API de transferencia de datos para especificar el destino de una transferencia saliente, en las API de recepción para indicar el origen de una transferencia entrante, y también en los eventos de finalización para informar de la dirección de origen de las transferencias entrantes. Los fi_addr_t de las claves de autorización se utilizan en las API de recepción y MR para asignar operaciones entrantes a una clave de autorización específica, y también en los eventos de error de finalización si el punto final está configurado con FI_SOURCE_ERR. El bit de capacidad y el indicador FI_AV_USER_ID proporcionan un mecanismo por el cual el valor fi_addr_t informado por un evento de finalización (de éxito o error) se sustituye por un valor especificado por el usuario. Esto es útil para las aplicaciones que necesitan mapear la dirección de origen a su propia estructura de

datos.

El soporte para FI_AV_USER_ID es específico del proveedor, ya que puede que no sea factible para un proveedor implementar este soporte sin una sobrecarga significativa. Por ejemplo, algunos proveedores pueden necesitar añadir un mecanismo de búsqueda inversa. Esta función puede no estar disponible si se solicitan AV compartidos, o puede afectar negativamente a la huella de memoria por proceso si se implementa. Para los proveedores que no admiten FI_AV_USER_ID, los usuarios pueden poder compensar el procesamiento de búsqueda con la sobrecarga del protocolo, incluyendo la identificación del origen en un encabezado del

mensaje.

Para los vectores de direcciones abiertos sin FI_AV_USER_ID, los valores fi_addr_t especificados por el usuario se proporcionan como parte de la inserción de direcciones (p. ej., fi_av_insert) a través del parámetro fi_addr. El parámetro fi_addr actúa como entrada/salida en este caso. Cuando se pasa el indicador FI_AV_USER_ID a cualquiera de las llamadas de inserción, el llamador debe especificar un valor identificador fi_addr_t para asociar con cada dirección. El proveedor registrará ese identificador y lo utilizará donde sea necesario como parte de cualquier evento de finalización. Tenga en cuenta que la salida de la llamada de inserción del AV no cambia. El proveedor devolverá un valor fi_addr_t que asigna a cada dirección, y ese valor debe utilizarse para todas las operaciones de transferencia de

datos.

Para los vectores de direcciones abiertos con FI

_AV_USER_ID, se utiliza fi_av_set_user_id para d
efinir el fi_addr_t especificado por el usuario.

GRUPOS DE

PARES

Los grupos de pares proporcionan una asignación directa a las construcciones de comunicadores de HPC e

IA.

Las direcciones en un AV representan el conjunto completo de pares con los que un proceso local puede comunicarse. Un grupo de pares representa conceptualmente un subconjunto de esos pares. Un grupo de pares puede utilizarse para identificar pares que trabajan en una tarea común, cuya comunicación necesita estar lógicamente separada del resto del tráfico. Los grupos de pares no son un mecanismo de seguridad, sino que ayudan a separar los datos. Un par determinado puede pertenecer a 0 o más grupos de pares, sin límite en el número de pares que pueden pertenecer a un solo grupo de

pares.

Los grupos de pares se identifican mediante un valor entero, conocido como id de grupo. Los id de grupo los selecciona el usuario y se transmiten como parte de un valor fi_addr_t. La gestión de un id de grupo y su relación con las direcciones insertadas en un AV la controla directamente el usuario. Cuando está habilitado, los mensajes enviados se marcan como pertenecientes a un grupo de pares específico, y los búferes de recepción publicados deben tener un id de grupo coincidente para recibir los

datos.

Los usuarios son responsables de seleccionar un id de grupo de pares válido, sujeto a la limitación negociada usando el atributo de dominio max_group_id. El id de grupo de un fi_addr_t puede establecerse usando la función fi_group_addr()

.

VALORES DE

RETORNO

Las llamadas de inserción, excluyendo fi_av_insert_auth_key, para un AV abierto para operación síncrona devolverán el número de direcciones que se insertaron correctamente. En caso de fallo, el valor de retorno será menor que el número de direcciones

especificadas.

Obsoleto: Las llamadas de inserción, excluyendo fi_av_insert_auth_key, para un AV abierto para operación asíncrona (con el indicador FI_EVENT especificado) devolverán FI_SUCCESS si la operación se inició correctamente. En caso de fallo, se devolverá un código de error de fabrica (errno) negativo. Se permite a los proveedores abortar las operaciones de inserción en caso de error. Las direcciones que no se insertan porque fueron abortadas fallarán con un código de error

FI_ECANCELED.

En ambos modos de operación, síncrono y asíncrono, el búfer fi_addr asociado a una inserción fallida o abortada se establecerá en FI_ADDR_NOTAVAIL

.

Todas las demás llamadas devuelven FI_SUCCESS en caso de éxito, o un valo

r negativo correspondiente a un código de error de fabrica (errno) en caso
de error. Los valores de error de fabrica se definen en rdma/fi_errno.h.
