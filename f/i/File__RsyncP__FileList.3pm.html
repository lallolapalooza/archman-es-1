DESCRIPCIÓ

N

El módulo File::RsyncP::FileList se utiliza para codificar y decodificar listas de archivos utilizando el mismo formato que

Rsync.

El lado emisor de Rsync crea una lista de todos los archivos que se van a enviar. Esta lista se envía en un formato compacto al lado receptor. Cada lado ordena la lista y elimina las entradas duplicadas. A partir de este punto, todos los archivos se referencian por su índice entero en la lista de archivos

ordenada.

Se crea un nuevo objeto de lista de archivos llamando a File::RsyncP::FileList->new. Un objeto se puede utilizar para decodificar o codificar una lista de archivos. No hay un mecanismo para restablecer el estado de una lista de archivos: debe crear un nuevo objeto cada vez que necesite realizar una nueva decodificación o

codificación.

La función new() toma una referencia a un hash de opciones, que corresponden a varios interruptores de la línea de comandos de rsync. Estos deben coincidir exactamente con los argumentos del rsync remoto, de lo contrario el formato de la lista de archivos no será compatible y la decodificación

fallará. 
$fileList = File::RsyncP::FileList->new({
    preserve_uid        => 1,       # --owner
    preserve_gid        => 1,       # --group
    preserve_links      => 1,       # --links
    preserve_devices    => 1,       # --devices
    preserve_hard_links => 0,       # --hard-links
    always_checksum     => 0,       # --checksum
    remote_version      => 26,      # remote protocol version
})
;

Decodificaci

ón

Las funciones de decodificación toman un flujo de bytes del rsync remoto y los convierten en una estructura de datos interna. En lugar de almacenar la lista de archivos como una lista nativa de hashes de Perl (lo que ocupa demasiada memoria para listas de archivos grandes), se utiliza la misma estructura de datos interna que rsync. Se pueden devolver entradas individuales de la lista de archivos con la función get()

.

Los datos de la lista de archivos leídos del rsync remoto deben pasarse a la función decode(). Los datos pueden leerse y procesarse en trozos de tamaño arbitrario. La función decode() devuelve cuántos bytes se procesaron realmente. Es responsabilidad del llamador eliminar ese número de bytes del argumento de entrada, conservando los bytes restantes para la siguiente llamada a decode(). La función decodeDone() devuelve verdadero cuando la lista de archivos está completa. La función fatalError() devuelve verdadero si hubo un error no recuperable durante la

decodificación.

La función clean() necesita ser llamada después de que la decodificación de la lista de archivos esté completa. La función clean() ordena la lista de archivos y elimina las entradas repetidas. Omitir este paso producirá resultados inesperados: dado que los archivos se referencian usando enteros, cada lado se referirá a archivos diferentes si las listas de archivos no están ordenadas y depuradas de exactamente la misma

manera.

Un bucle de decodificación típico se ve

así: 
while ( !$fileList->decodeDone && !$fileList->fatalError ) {
    $data .= readMoreDataFromRemoteRsync();
    $bytesDone = $fileList->decode($data);
    $data = substr($data, $bytesDone) if ( $bytesDone > 0 );
}
$fileList->
clean;

Después de que se llame a clean(), el número de archivos en la lista de archivos se puede encontrar llamando a count(). Los archivos se pueden obtener llamando a la función get(), con un índice de 0 a count()

-1: 
$fileInfo = $fileList->get(5)
;

La función get() devuelve una referencia a un hash con varias

entradas: 
name      path name of the file (relative to rsync dir):
          equal to dirname/basename
basename  file name, without directory
dirname   directory where file resides
sum       file MD4 checksum (only present if --checksum specified)
uid       file user id
gid       file group id
mode      file mode
mtime     file modification time
size      file length
dev       device number on which file resides
inode     file inode
link      link contents if the file is a sym link
rdev      major/minor device number if file is char/block
special

Varios campos solo tendrán valores válidos si las opciones correspondientes están establecidas (por ejemplo: uid si preserve_uid está establecido, dev e inode si preserve_hard_links está establecido, etc.)

.

Por ejemplo, para volcar cada hash podría hacer

esto: 
use Data::Dumper;
my $count = $fileList->count;
for ( my $i = 0 ; $i < $count ; $i++ ) {
    print("File $i is:\n");
    print Dumper($fileList->get($i));
}

Codificació

n

La función encode() se utiliza para construir una lista de archivos en preparación para codificar y enviar una lista de archivos a un rsync remoto. La función encode() toma un argumento de referencia a un hash con los parámetros para un archivo. Debe llamarse una vez por cada archivo. Los nombres de los parámetros son los mismos que los devueltos por get(

).

En este ejemplo se muestran los valores de stat() correspondientes

: 
$fileList->encode({
        name  => $filePath,
        dev   => $stat[0],
        inode => $stat[1],
        mode  => $stat[2],
        uid   => $stat[4],
        gid   => $stat[5],
        rdev  => $stat[6],
        size  => $stat[7],
        mtime => $stat[9],
    })
;

No es necesario especificar basename y dirname; estos se extraen de name. Solo necesita especificar los parámetros que coincidan con las opciones dadas a new(). También puede especificar sum y link según sea

necesario.

Para calcular los datos de la lista de archivos codificados, se debe llamar a la función encodeData(). Se puede llamar cada vez que se llama a encode(), o una vez al final de todas las llamadas a encode(). Devuelve los datos codificados que deben enviarse al rsync

remoto: 
$data = $fileList->
encodeData;

Se recomienda que encodeData() se llame con frecuencia para evitar la necesidad de asignar grandes búferes internos para contener la lista de archivos codificada completa. Dado que encodeData() no sabe cuándo se ha codificado el último archivo, es responsabilidad del llamador agregar el byte nulo final (por ejemplo: pack("C", 0)) a los datos para indicar el final de los datos de la lista de

archivos.

Después de procesar todas las entradas de la lista de archivos, debe llamar a clean

(): 
$fileList->
clean;

Esto asegura que cada lado (em

isor/receptor) tenga listas de
archivos ordenadas idénticas.

Funciones de

utilidad

La función count() devuelve el número total de archivos en la lista de archivos interna (ya sea decodificada o codificada)

.

La función fatalError() devuelve verdadero si ha ocurrido un error fatal durante la d

ecodificación de archivos. Debe llamarse e
n el bucle de decodificación para asegura
rse de que no haya ocurrido ningún error.
