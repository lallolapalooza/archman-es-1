Para especificar un completado, use el comando complete . complete recibe como parámetro el nombre del comando para el cual especificar un completado. Por ejemplo, para añadir un completado para el programa myprog, comience el comando de completado con complete -c myprog ...

Para una descripción completa de los distintos interruptores aceptados por el comando complete , consulte la documentación del interno <> complete, o escriba complete --help dentro del shell fish .

Para proporcionar una lista de posibles completados para myprog, use el interruptor -a . Si myprog acepta los argumentos start y stop, esto puede especificarse como complete -c myprog -a 'start stop'. El argumento del interruptor -a es siempre una sola cadena. En el momento del completado, se tokenizará por espacios y tabuladores, y tendrán lugar la expansión de variables, la sustitución de comandos y otras formas de expansión de parámetros:

# Si myprog puede listar las salidas válidas con el subcomando list-outputs:
complete -c myprog -l output -a '(myprog list-outputs)'

fish tiene una sintaxis especial para admitir la especificación de interruptores aceptados por un comando. Los interruptores -s, -l y -o se usan para especificar un interruptor corto (un solo carácter, como -l), un interruptor largo de estilo gnu (como --color) y un interruptor largo de estilo antiguo (con un solo -, como -shuffle), respectivamente. Si el comando 'myprog' tiene una opción que puede escribirse como -o o --output, es decir:

complete -c myprog -s o -l output

Si esta opción toma un argumento opcional, también añadiría --argument o -a, y le daría los posibles argumentos:

complete -c myprog -s o -l output -a "yes no"

Esto ofrece los argumentos "yes" y "no" para:

> myprog -o<TAB>
> myprog --output=<TAB>

Por defecto, los argumentos de las opciones son opcionales, así que los candidatos solo se ofrecen directamente adjuntos como en ese caso, por lo que no se dan en este caso:

> myprog -o <TAB>

Generalmente las opciones requieren un parámetro, así que daría --require-parameter / -r:

complete -c myprog -s o -l output -ra "yes no"

lo que ofrece yes/no en estos casos:

> myprog -o<TAB>
> myprog --output=<TAB>
> myprog -o <TAB>
> myprog --output <TAB>

Fish también ofrecerá archivos por defecto, además de los argumentos que especificó. O bien inhibiría el completado de archivos para una opción individual:

complete -c myprog -s o -l output --no-files -ra "yes no"

o con una condición específica:

complete -c myprog -f --condition '__fish_seen_subcommand_from somesubcommand'

o puede desactivar los completados de archivos globalmente para el comando:

complete -c myprog -f

Si los ha desactivado globalmente, puede habilitarlos solo para una condición u opción específica con la opción --force-files / -F :

# Desactivar archivos por defecto
complete -c myprog -f
# pero reactivarlos para --config-file
complete -c myprog -l config-file --force-files -r

Como un ejemplo más completo, aquí hay un extracto comentado de los completados para el timedatectlde systemd:

# Todos los subcomandos que timedatectl conoce - esto es útil para más tarde.
set -l commands status set-time set-timezone list-timezones set-local-rtc set-ntp
# Desactivar los completados de archivos para todo el comando
# porque no toma archivos en ningún lugar
# Tenga en cuenta que esto se puede deshacer usando "-F".
#
# Los completados de archivos también necesitan desactivarse
# si quiere tener más control sobre qué archivos se ofrecen
# (p. ej., solo directorios, o solo archivos que terminen en ".mp3").
complete -c timedatectl -f
# Esta línea ofrece los subcomandos
# -"status",
# -"set-timezone",
# -"set-time"
# -"list-timezones"
# si no se ha dado ningún subcomando hasta ahora.
#
# La opción `-n`/`--condition` toma un script como cadena, que ejecuta.
# Si devuelve true, se ofrece el completado.
# Aquí la condición es la función auxiliar `__fish_seen_subcommand_from`.
# Devuelve true si alguno de los comandos dados se usa en la línea de comandos,
# según lo determinado por una simple heurística.
# Para usos más complejos, puede escribir su propia función.
# Vea, por ejemplo, los completados de git para un ejemplo.
#
complete -c timedatectl -n "not __fish_seen_subcommand_from $commands" \
    -a "status set-time set-timezone list-timezones"
# Si se usa el subcomando "set-timezone",
# ofrecer la salida de `timedatectl list-timezones` como completados.
# Cada línea de salida se usa como un candidato separado,
# y cualquier cosa después de un tabulador se toma como la descripción.
# A menudo es útil transformar la salida del comando con `string` a esa forma.
complete -c timedatectl -n "__fish_seen_subcommand_from set-timezone" \
    -a "(timedatectl list-timezones)"
# Los candidatos de completado también se pueden describir mediante `-d`,
# lo que es útil si la descripción es constante.
# Intente mantenerlos cortos, porque eso significa que el usuario puede ver más a la vez.
complete -c timedatectl -n "not __fish_seen_subcommand_from $commands" \
    -a "set-local-rtc" -d "Mantener el RTC en hora local"
# También podemos limitar las opciones a ciertos subcomandos usando condiciones.
complete -c timedatectl -n "__fish_seen_subcommand_from set-local-rtc" \
    -l adjust-system-clock -d 'Sincronizar el reloj del sistema desde el RTC'
# Estas son opciones simples que se pueden usar en todas partes.
complete -c timedatectl -s h -l help -d 'Imprimir un texto de ayuda corto y salir'
complete -c timedatectl -l version -d 'Imprimir una cadena de versión corta y salir'
complete -c timedatectl -l no-pager -d 'No canalizar la salida a un paginador'

Para ejemplos de cómo escribir sus propios completados complejos, estudie los completados en /usr/share/fish/completions. (La ruta exacta depende del prefijo de instalación elegido y puede ser ligeramente diferente)

FUNCIONES ÚTILES PARA ESCRIBIR COMPLETADOS

fish incluye varias funciones que pueden ser útiles al escribir completados específicos de un comando. La mayoría de estos nombres de función comienzan con la cadena __fish_. Tales funciones son internas de fish y su nombre e interfaz pueden cambiar en futuras versiones de fish. Algunas de estas funciones se describen aquí.

Las funciones que comienzan con la cadena __fish_print_ imprimen una lista de cadenas separadas por saltos de línea. Por ejemplo, __fish_print_filesystems imprime una lista de todos los sistemas de archivos conocidos. Las funciones que comienzan con __fish_complete_ imprimen una lista separada por saltos de línea de completados con descripciones. La descripción se separa del completado mediante un carácter de tabulador.

  • __fish_complete_directories STRING DESCRIPTION realiza el completado de rutas en STRING, permitiendo solo directorios, y dándoles la descripción DESCRIPTION.
  • __fish_complete_path STRING DESCRIPTION realiza el completado de rutas en STRING, dándoles la descripción DESCRIPTION.
  • __fish_complete_groups imprime una lista de todos los grupos de usuarios con los miembros del grupo como descripción.
  • __fish_complete_pids imprime una lista de todos los IDs de procesos con el nombre del comando como descripción.
  • __fish_complete_suffix SUFFIX realiza el completado de archivos pero ordena los archivos que terminan en SUFFIX primero. Esto es útil en conjunto con complete --keep-order.
  • __fish_complete_users imprime una lista de todos los usuarios con su nombre completo como descripción.
  • __fish_print_filesystems imprime una lista de todos los sistemas de archivos conocidos. Actualmente, esta es una lista estática, y no depende de qué sistemas de archivos el sistema operativo anfitrión realmente entiende.
  • __fish_print_hostnames imprime una lista de todos los nombres de host conocidos. Esta función busca en el fstab servidores nfs, en ssh hosts conocidos y comprueba el archivo /etc/hosts .
  • __fish_print_interfaces imprime una lista de todas las interfaces de red conocidas.

USEFUL FUNCTIONS FOR WRITING COMPLETIONS

Fish proporciona varias funciones útiles que se pueden usar para escribir archivos de completado. Estas funciones se encuentran en los archivos de completado de fish y están disponibles para su uso en sus propios archivos de completado.

complete

La función más importante, utilizada para definir completados para comandos. Permite especificar qué completar (argumentos, opciones, etc.) y cómo completarlos (basado en una lista, un patrón, la salida de un comando, etc.).

string

Una familia de funciones para manipular cadenas. Útil para procesar la salida de comandos y formatearla para su visualización.

__fish_parse_options

Una función auxiliar para analizar las opciones pasadas a un script de completado.

__fish_complete_path

Busca archivos en el directorio especificado.

Consulte la salida de fish --help o la documentación de fish para obtener una lista completa de las funciones disponibles.

WHERE TO PUT COMPLETIONS

Fish busca automáticamente en los directorios de la variable $fish_complete_path cualquier completado definido y estos se cargan automáticamente cuando es necesario. Un archivo de completado debe tener un nombre de archivo que consista en el nombre del comando a completar y el sufijo .fish.

Por defecto, Fish busca lo siguiente para obtener completados, utilizando el primer archivo disponible que encuentra:

  • Un directorio para que los usuarios finales guarden sus propios completados, generalmente ~/.config/fish/completions (controlado por la variable de entorno XDG_CONFIG_HOME);
  • Un directorio para que los administradores del sistema instalen completados para todos los usuarios del sistema, generalmente /etc/fish/completions;
  • Un directorio especificado por el usuario para completados de proveedores externos, generalmente ~/.local/share/fish/vendor_completions.d (controlado por la variable de entorno XDG_DATA_HOME);
  • Un directorio para que los proveedores de software externos envíen sus propios completados para su software, generalmente /usr/share/fish/vendor_completions.d;
  • Los completados distribuidos con fish, generalmente instalados en /usr/share/fish/completions; y
  • Completados generados automáticamente a partir del manual del sistema operativo, generalmente almacenados en ~/.cache/fish/generated_completions (controlado por la variable de entorno XDG_CACHE_HOME).

Estas rutas están controladas por parámetros establecidos en tiempo de compilación, instalación o ejecución, y pueden variar de los valores predeterminados mencionados anteriormente.

Esta amplia búsqueda puede ser confusa. Si no está seguro, sus completados probablemente pertenezcan a ~/.config/fish/completions.

Si ha escrito nuevos completados para un comando Unix común, considere compartir su trabajo enviándolo a través de las instrucciones en Más ayuda y desarrollo <#more-help>.

Si está desarrollando otro programa y desea incluir completados con su programa, instálelos en el directorio de completados de "proveedor". Como esta ruta puede variar de un sistema a otro, se debe usar el framework pkgconfig para descubrir esta ruta con la salida de pkg-config --variable completionsdir fish.
