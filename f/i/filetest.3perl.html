NOMBRE

filetest - pragma de Perl para controlar los operadores de prueba de archivos

SINOPSIS

$puede_quizas_leer = -r "archivo";      # usa los bits de modo
{
    use filetest 'access';          # intuye más
    $puede_realmente_leer = -r "archivo";
}
$puede_quizas_leer = -r "archivo";      # usa los bits de modo de nuevo

DESCRIPCIÓN

Este pragma indica al compilador que cambie el comportamiento de los operadores de prueba de archivos, "-r" "-w" "-x" "-R" "-W" "-X" (ver perlfunc).

El comportamiento predeterminado de los operadores de prueba de archivos es usar los simples bits de modo devueltos por la familia de llamadas al sistema stat(). Sin embargo, muchos sistemas operativos tienen características adicionales para definir derechos de acceso más complejos, por ejemplo, ACLs (Listas de Control de Acceso). Para tales entornos, "use filetest" puede ayudar a los operadores de permiso a devolver resultados más consistentes con otras herramientas.

Las sentencias "use filetest" o "no filetest" afectan a las pruebas de archivo definidas en su bloque, hasta el final del bloque más cercano que las contenga (tienen ámbito léxico de bloque).

Actualmente, solo se implementa el sub-pragma "access". Habilita (o deshabilita) el uso de access() cuando está disponible, es decir, en la mayoría de los sistemas UNIX y otros entornos POSIX. Ver detalles a continuación.

Considerar esto cuidadosamente

Los bits de modo de stat() probablemente sean correctos para la mayoría de los archivos y directorios que se encuentran en su sistema, porque pocas personas querrán usar las características adicionales ofrecidas por access(). Pero puede encontrar sorpresas si su programa se ejecuta en un sistema que utiliza ACLs, ya que la información de stat() no reflejará los permisos reales.

Puede haber una ligera disminución en el rendimiento de las operaciones de prueba de archivos cuando el pragma filetest está en efecto, porque verificar bits es muy barato.

Además, tenga en cuenta que usar las pruebas de archivos con fines de seguridad es una causa perdida desde el principio: hay una ventana abierta a condiciones de carrera (¿quién puede decir que los permisos no cambiarán entre la prueba y la operación real?). Por lo tanto, si se toma en serio la seguridad, simplemente intente la operación real y pruebe su éxito - piense en términos de operaciones atómicas. Las pruebas de archivos son más útiles para tareas administrativas del sistema de archivos, cuando no necesita el contenido de los elementos en disco.

El sub-pragma "access"

Los sistemas UNIX y POSIX proporcionan una llamada al sistema abstracta access(), que debe utilizarse para consultar los derechos de lectura, escritura y ejecución. Esta función oculta varios enfoques distintos en características de seguridad adicionales específicas del sistema operativo, como las Listas de Control de Acceso (ACL).

La funcionalidad extendida de prueba de archivos es utilizada por Perl solo cuando el argumento de los operadores es un nombre de archivo, no cuando es un manejador de archivos.

Limitación con respecto a "_"

Debido a que access() no invoca stat() (al menos no de una manera visible para Perl), la caché de resultados de stat "_" no se establece. Esto significa que el resultado de las dos pruebas siguientes es diferente. La primera tiene los bits de stat de /etc/passwd en "_", y en el segundo caso esto todavía contiene los bits de "/etc".

{ -d '/etc';
  -w '/etc/passwd';
  print -f _ ? 'Sí' : 'No';   # Sí
}
{ use filetest 'access';
  -d '/etc';
  -w '/etc/passwd';
  print -f _ ? 'Sí' : 'No';   # No
}

Por supuesto, a menos que su SO no implemente access(), en cuyo caso el pragma simplemente se ignora. ¡Mejor no usar "_" en absoluto en un archivo donde el pragma filetest esté activo!

Como efecto secundario, dado que "_" no funciona, los operadores de prueba de archivos apilados ("-f -w $archivo") tampoco funcionarán.

Esta limitación podría eliminarse en una versión futura de perl.
