NOMBRE

fi_fabric - Operaciones de red de fabric

fi_fabric / fi_close
Abrir / cerrar una red de fabric
fi_tostr / fi_tostr_r
Convertir atributos, indicadores y capacidades de fabric en una cadena imprimible

SINOPSIS

#include <rdma/fabric.h>
int fi_fabric(struct fi_fabric_attr *attr,
    struct fid_fabric **fabric, void *context);
int fi_close(struct fid *fabric);
char * fi_tostr(const void *data, enum fi_type datatype);
char * fi_tostr_r(char *buf, size_t len, const void *data,
    enum fi_type datatype);

ARGUMENTOS

attr
Atributos del fabric a abrir.
fabric
Red de fabric
context
Contexto especificado por el usuario asociado con el objeto abierto. Este contexto se devuelve como parte de cualquier evento asíncrono asociado.
buf
Búfer de salida donde escribir la cadena.
len
Tamaño en bytes de la memoria referenciada por buf.
data
Datos de entrada a convertir en una cadena. El formato de data lo determina el parámetro datatype.
datatype
Indica los datos a convertir en una cadena imprimible.

DESCRIPCIÓN

Un identificador de fabric se utiliza para referenciar los recursos de fabric abiertos y los objetos relacionados con la biblioteca.

La red de fabric representa un conjunto de recursos de hardware y software que acceden a una única red física o virtual. Todos los puertos de red de un sistema que pueden comunicarse entre sí a través de sus redes conectadas pertenecen al mismo fabric. Una red de fabric comparte direcciones de red y puede abarcar varios proveedores. Una aplicación debe abrir una red de fabric antes de asignar otros recursos de red, como puntos de comunicación.

fi_fabric

Abre un proveedor de red de fabric. Los atributos del proveedor de fabric se especifican a través de la llamada de apertura y pueden obtenerse llamando a fi_getinfo.

fi_close

La llamada fi_close se utiliza para liberar todos los recursos asociados con un objeto fabric. Todos los elementos asociados con el fabric abierto deben liberarse antes de llamar a fi_close.

fi_tostr / fi_tostr_r

Convierte los atributos de la interfaz de fabric, las capacidades, los indicadores y los valores de enumeración en una cadena imprimible. El parámetro data acepta un puntero al atributo o valor(es) a mostrar, con el parámetro datatype indicando el tipo de datos al que hace referencia el parámetro data. Los valores válidos para datatype se enumeran a continuación, junto con el tipo de dato o valor de campo correspondiente.

fi_tostr() devolverá un puntero a un búfer interno de libfabric que no debe modificarse y que se sobrescribirá la próxima vez que se invoque fi_tostr(). fi_tostr() no es seguro para subprocesos.

La función fi_tostr_r() es una versión reentrante y segura para subprocesos de fi_tostr(). Escribe la cadena en un búfer proporcionado por el llamador. fi_tostr_r() devuelve el inicio del búfer del llamador.

NOTAS

Los siguientes recursos están asociados con los dominios de fabric: dominios de acceso, puntos de pasiva y colas de eventos de CM.

ATRIBUTOS DEL FABRIC

La estructura fi_fabric_attr define el conjunto de atributos asociados con un fabric y un proveedor de fabric.

struct fi_fabric_attr {
    struct fid_fabric *fabric;
    char              *name;
    char              *prov_name;
    uint32_t          prov_version;
    uint32_t          api_version;
};

fabric

Como entrada a fi_getinfo, un usuario puede establecer esto en una instancia de fabric abierta para restringir la salida al fabric dado. Como salida de fi_getinfo, si no se especificó ningún fabric, pero el usuario tiene una instancia abierta del fabric nombrado, esto hará referencia a la primera instancia abierta. Si no se ha abierto ninguna instancia, este campo será NULL.

NAME

fi_fabric — fabric information query

SYNOPSIS

#include <rdma/fabric.h>
int fi_fabric(
    const char *name,
    void *context,
    uint64_t flags,
    fi_fabric_t **fabric
);

ARGUMENTS

name

Fabric name specification. If name is NULL, then fi_getinfo() will return information on all available fabric providers.

If name is not NULL, it is a fabric provider name, or a comma separated list of fabric provider names. The specific syntax and semantics of the name string is provider-specific. Some providers may support configuration via environment variables, see fi_getinfo(3) for details.

context

User-specified value to be associated with the fabric. This value is returned to the user in event data. See fi_cq(3) for details.

flags

Flags to control the operation of fi_getinfo. Valid flags include:

FI_WANTON

If specified, fi_getinfo will return information on all available fabric providers that can be used to satisfy the request. If not specified, fi_getinfo will return information on only one fabric provider.

FI_NOFI

If specified, fi_getinfo will not return any information on fabric providers that rely on libfabric to provide fabric functionality. This is primarily used to prevent recursive lookups of utility providers.

FI_ATTACH

If specified, fi_getinfo will return information on fabric providers that can be used to attach to an existing fabric resource. This is primarily used for network interfaces that may not be fully initialized.

FI_LOCAL

If specified, fi_getinfo will only return information on fabric providers that can be used to access local resources. This flag is primarily used for communication between processes on the same node.

FI_ALL

If specified, fi_getinfo will return information on all fabric providers, including those that may not be actively available. This flag is primarily used for discovery and enumeration of fabric providers.

fabric

On return, points to a pointer to a fabric_t structure that describes the fabric. The fabric structure is allocated by fi_getinfo and must be freed by the application using fi_free(3).

DESCRIPTION

The fi_fabric() call is used to query information about the available fabric providers. The information returned can be used to select a fabric provider that meets the application's requirements.

The name parameter can be used to specify a particular fabric provider or a list of fabric providers to query. If name is NULL, then fi_getinfo() will return information on all available fabric providers. If name is not NULL, it is a fabric provider name, or a comma separated list of fabric provider names. The specific syntax and semantics of the name string is provider-specific. Some providers may support configuration via environment variables, see fi_getinfo(3) for details.

The flags parameter can be used to control the operation of fi_getinfo(). Valid flags include FI_WANTON, FI_NOFI, FI_ATTACH, FI_LOCAL, and FI_ALL.

The fabric parameter on return points to a pointer to a fabric_t structure that describes the fabric. The fabric structure is allocated by fi_getinfo() and must be freed by the application using fi_free(3).

NOTES

The returned fabric structure is valid only for the duration of the call to fi_getinfo. The application must copy any information it needs from the fabric structure before returning from fi_getinfo.

The fi_fabric() call is thread-safe. However, the returned fabric structure should only be considered valid if the application does not close any fabric instances from another thread while fi_getinfo() is being processed.

name

A fabric identifier.

prov_name - Provider Name

The name of the underlying fabric provider.

To request an utility provider layered over a specific core provider, both the provider names have to be specified using “;” as delimiter.

e.g. “ofi_rxm;verbs” or “verbs;ofi_rxm”

For debugging and administrative purposes, environment variables can be used to control which fabric providers will be registered with libfabric. Specifying “FI_PROVIDER=foo,bar” will allow any providers with the names “foo” or “bar” to be registered. Similarly, specifying “FI_PROVIDER=^foo,bar” will prevent any providers with the names “foo” or “bar” from being registered. Providers which are not registered will not appear in fi_getinfo results. Applications which need a specific set of providers should implement their own filtering of fi_getinfo’s results rather than relying on these environment variables in a production setting.

prov_version - Provider Version

Version information for the fabric provider, in a major.minor format. The use of the FI_MAJOR() and FI_MINOR() version macros may be used to extract the major and minor version data. See fi_version(3).

In case of an utility provider layered over a core provider, the version would always refer to that of the utility provider.

api_version

The interface version requested by the application. This value corresponds to the version parameter passed into fi_getinfo(3).

RETURN VALUE

Returns FI_SUCCESS on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.
