NOMBRE

fi_cm - Operaciones de gestión de conexiones

fi_connect / fi_listen / fi_accept / fi_reject / fi_shutdown
Gestiona el estado de conexión de un punto final.
fi_setname / fi_getname / fi_getpeer
Establece la dirección local, o devuelve la dirección local o del par del punto final.
fi_join / fi_close / fi_mc_addr
Únete, abandona o recupera una dirección de multidifusión.

SINOPSIS

#include <rdma/fi_cm.h>
int fi_connect(struct fid_ep *ep, const void *addr,
    const void *param, size_t paramlen);
int fi_listen(struct fid_pep *pep);
int fi_accept(struct fid_ep *ep, const void *param, size_t paramlen);
int fi_reject(struct fid_pep *pep, fid_t handle,
    const void *param, size_t paramlen);
int fi_shutdown(struct fid_ep *ep, uint64_t flags);
int fi_setname(fid_t fid, void *addr, size_t addrlen);
int fi_getname(fid_t fid, void *addr, size_t *addrlen);
int fi_getpeer(struct fid_ep *ep, void *addr, size_t *addrlen);
int fi_join(struct fid_ep *ep, const void *addr, uint64_t flags,
    struct fid_mc **mc, void *context);
int fi_close(struct fid *mc);
fi_addr_t fi_mc_addr(struct fid_mc *mc);

ARGUMENTOS

ep / pep
Punto final de la red sobre el cual cambiar el estado de la conexión.

fid Punto final activo o pasivo para obtener/establecer la dirección.

addr
Búfer de dirección. En una llamada de establecimiento, al punto final se le asignará la dirección especificada. En una llamada de obtención, la dirección local se copiará en el búfer, hasta el espacio proporcionado. Para connect, este parámetro indica la dirección del par a la que conectarse. La dirección debe estar en el mismo formato que el especificado mediante fi_info: addr_format cuando se creó el punto final.
addrlen
En la entrada, especifica el tamaño del búfer addr. En la salida, almacena el número de bytes escritos en el búfer addr.
param
Datos especificados por el usuario que se intercambian como parte del intercambio de conexión.
paramlen
Tamaño del búfer param.
info
Información de la red asociada con una solicitud de conexión.
mc
Grupo de multidifusión asociado con un punto final.
flags
Banderas adicionales para controlar la operación de conexión.
context
Contexto de usuario asociado con la solicitud.

DESCRIPCIÓN

Las funciones de gestión de conexiones se utilizan para conectar un punto final orientado a conexiones (FI_EP_MSG) a un par que escucha.

fi_listen

La llamada fi_listen indica que el punto final especificado debe transicionar a un estado de conexión pasiva, permitiéndole aceptar solicitudes de conexión entrantes. Las solicitudes de conexión contra un punto final que escucha se informan de forma asíncrona al usuario a través de una cola de eventos CM vinculada usando el tipo de evento FI_CONNREQ. El número de solicitudes de conexión pendientes que pueden encolarse en un punto final está limitado por el parámetro backlog del punto final que escucha. El backlog se inicializa basándose en valores de configuración administrativa, pero puede ajustarse a través de la llamada fi_control.

fi_connect

La llamada fi_connect inicia una solicitud de conexión en un punto final orientado a conexiones hacia la dirección de destino. fi_connect solo puede ser llamada en un punto final una vez en su vida útil.

fi_accept / fi_reject

Las llamadas fi_accept y fi_reject se usan en el lado pasivo (que escucha) de una conexión para aceptar o rechazar una solicitud de conexión, respectivamente. Para aceptar una conexión, la aplicación que escucha primero espera un evento de solicitud de conexión (FI_CONNREQ). Después de recibir dicho evento, la aplicación asigna un nuevo punto final para aceptar la conexión. Este punto final debe ser asignado usando una estructura fi_info que referencie el manejador de este evento FI_CONNREQ. Luego se invoca fi_accept con el punto final recién asignado. Si la aplicación que escucha desea rechazar una solicitud de conexión, llama a fi_reject con el punto final que escucha y una referencia a la solicitud de conexión.

Una solicitud de conexión aceptada con éxito resultará en que el punto final activo (que conecta) vea un evento FI_CONNECTED en su cola de eventos asociada. Una solicitud de conexión rechazada o fallida generará un evento de error. La entrada de error proporcionará detalles adicionales describiendo la razón del intento fallido.

Un evento FI_CONNECTED también será generado en el lado pasivo para el punto final que acepta una vez que la conexión haya sido establecida correctamente. El fid del evento FI_CONNECTED será el del punto final pasado a fi_accept en oposición al punto final pasivo que escucha. Las transferencias de datos salientes no pueden ser iniciadas en un punto final orientado a conexiones hasta que un evento FI_CONNECTED haya sido generado. Sin embargo, los búferes de recepción pueden ser asociados con un punto final en cualquier momento.

fi_shutdown

La llamada fi_shutdown se usa para desconectar un punto final de su par de manera ordenada. El parámetro flags está reservado y debe ser 0.

Las operaciones pendientes publicadas en el punto final cuando se llama a fi_shutdown serán canceladas o descartadas. La notificación de las operaciones canceladas será reportada por el proveedor a la(s) cola(s) de completado correspondiente(s). Las operaciones descartadas serán eliminadas silenciosamente, sin generar completados. La elección de cancelar, versus descartar operaciones, depende del proveedor. Sin embargo, todos los completados cancelados serán escritos antes de que fi_shutdown retorne.

Cuando se llama, fi_shutdown no afecta los completados ya escritos en una cola de completado. Cualquier completado encolado asociado con operaciones asíncronas publicadas en el punto final aún puede ser recuperado de la(s) cola(s) de completado correspondiente(s) después de que un punto final haya sido apagado.

Un evento FI_SHUTDOWN será generado para un punto final cuando el par remoto emite una desconexión usando fi_shutdown o cierra abruptamente el punto final. Nótese que en el caso de cierre abrupto, un evento FI_SHUTDOWN solo será generado si el sistema del par es accesible y un servicio o agente de kernel en el sistema del par es capaz de notificar al punto final local que la conexión ha sido abortada.

fi_close

Fi_close se usa para desasociar un punto final de un grupo de multidifusión y cerrar todos los recursos asociados con el grupo. Fi_close debe ser llamada en todos los grupos de multidifusión a los que un punto final se une.

fi_setname

La llamada fi_setname puede usarse para modificar o asignar la dirección del punto final local. Es conceptualmente similar a la operación bind de socket. A un punto final puede serle asignada una dirección en su creación, a través de la estructura fi_info. La llamada fi_setname permite que un punto final sea creado sin estar asociado con un servicio específico (por ejemplo, número de puerto) y/o dirección de nodo (por ejemplo, red), con la dirección asignada dinámicamente. El formato de los datos de direccionamiento especificados debe coincidir con el especificado a través de la estructura fi_info cuando se creó el punto final.

Si no se especifica una dirección de servicio y una dirección de servicio aún no ha sido asignada al punto final, entonces el proveedor asignará una dirección de servicio y la asignará al punto final. Si se especifica una dirección de nodo o de servicio, entonces, sobre la finalización exitosa de fi_setname, al punto final se le asignará el direccionamiento dado. Si una dirección no puede ser asignada, o la dirección del punto final no puede ser modificada, se retorna un número de error de red apropiado.

fi_getname / fi_getpeer

Las llamadas fi_getname y fi_getpeer pueden usarse para recuperar la dirección local o del par del punto final, respectivamente. En la entrada, el parámetro addrlen debería indicar el tamaño del búfer addr. Si la dirección actual es más grande de lo que cabe en el búfer, será truncada y se retornará -FI_ETOOSMALL. fi_listen(3) — Libfabric Programmer’s Manual

NAME

fi_listen — enable or disable listening for connection requests

SYNOPSIS

#include <rdma/fabric.h>
int fi_listen(struct fi_info *info, void **context);
int fi_listen(struct fi_info *info, uint32_t flags);

ARGUMENTS

info
An fi_info structure specifying the endpoint to listen on. The addr_count field of the returned fi_info structure should be set to the number of addresses to bind to. If set to zero, the underlying fabric provider will choose the number of addresses. ep_addr is also populated with the addresses to bind to, if the provider chooses addresses. The ep_addr field will be populated with the endpoint address(es) if the provider chooses the addresses. The flags specified in info are also used to control the behavior of the listen call.
context
User specified context for the listen operation. This context is returned in the read_data field of the fi_eq_cm_entry structure for connection events. This field is only used for connection oriented endpoints.
flags
Optional flags to control the behavior of the listen operation. Must be 0 for now.

DESCRIPTION

The fi_listen call enables or disables listening for incoming connection requests on a specified endpoint. The endpoint must be configured to be a server, and must have been successfully bound to an address prior to calling fi_listen.

The fi_listen call is used to enable listening for incoming connection requests. The info parameter is a pointer to a fi_info structure that contains information about the endpoint and the desired listening behavior. The addr_count field of the fi_info structure specifies the number of addresses to bind to. If addr_count is set to zero, the fabric provider will automatically choose the number of addresses to bind to. The ep_addr field of the fi_info structure will be populated with the endpoint address(es) if the provider chooses the addresses.

The fi_listen call is asynchronous. The listen operation is considered complete when an FI_LISTENER_READY event is generated and posted to the associated event queue. The context parameter is a user-defined context that is returned with the FI_LISTENER_READY event.

To disable listening, applications should call fi_close on the endpoint. After a listen operation has completed and the endpoint is ready to accept connections, applications can use fi_accept to accept incoming connection requests.

fi_getname

This function retrieves the address of an endpoint. The addr parameter is a buffer in which the address will be stored. The addrlen parameter is a pointer to a value that, on input, specifies the size of the buffer pointed to by addr, and on output, is set to the size of the buffer needed to store the address, which may be larger than the input value.

fi_getname is not guaranteed to return a valid source address until after the specified endpoint has been enabled or has had an address assigned. An endpoint may be enabled explicitly through fi_enable, or implicitly, such as through fi_connect or fi_listen. An address may be assigned using fi_setname. fi_getpeer is not guaranteed to return a valid peer address until an endpoint has been completely connected – an FI_CONNECTED event has been generated.

fi_join

This call attaches an endpoint to a multicast group. By default, the endpoint will join the group based on the data transfer capabilities of the endpoint. For example, if the endpoint has been configured to both send and receive data, then the endpoint will be able to initiate and receive transfers to and from the multicast group. The fi_join flags may be used to restrict access to the multicast group, subject to endpoint capability limitations.

Multicast join operations complete asynchronously. An endpoint must be bound to an event queue prior to calling fi_join. The result of the join operation will be reported to the EQ as an FI_JOIN_COMPLETE event. Applications cannot issue multicast transfers until receiving notification that the join operation has completed. Note that an endpoint may begin receiving messages from the multicast group as soon as the join completes, which can occur prior to the FI_JOIN_COMPLETE event being generated.

Applications must call fi_close on the multicast group to disconnect the endpoint from the group. After a join operation has completed, the fi_mc_addr call may be used to retrieve the address associated with the multicast group.

fi_mc_addr

Returns the fi_addr_t address associated with a multicast group. This address must be used when transmitting data to a multicast group and paired with the FI_MULTICAST operation flag.

FLAGS

Except in functions noted below, flags are reserved and must be 0.

FI_SEND
Applies to fi_join. This flag indicates that the endpoint should join the multicast group as a send only member. The endpoint must be configured for transmit operations to use this flag, or an error will occur.
FI_RECV
Applies to fi_join. This flag indicates that the endpoint should join the multicast group with receive permissions only. The endpoint must be configured for receive operations to use this flag, or an error will occur.

RETURN VALUE

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.

ERRORS

NOTES

For connection-oriented endpoints, the buffer referenced by param will be sent as part of the connection request or response, subject to the constraints of the underlying connection protocol. Applications may use fi_getopt with the FI_OPT_CM_DATA_SIZE endpoint option to determine the size of application data that may be exchanged as part of a connection request or response. The fi_connect, fi_accept, and fi_reject calls will silently truncate any application data which cannot fit into underlying protocol messages. User data exchanged as part of the connection process is available as part of the fi_eq_cm_entry structure, for FI_CONNREQ and FI_CONNECTED events, or as additional err_data to fi_eq_err_entry, in the case of a rejected connection.
