Filter::Simple(3perl) Guía de referencia del programador de Perl Filter::Simple(3perl)

NOMBRE

Filter::Simple - Filtrado de código fuente simplificado

SINOPSIS

# en MyFilter.pm:
    package MyFilter;
    use Filter::Simple;
    FILTER { ... };
    # o simplemente:
    #
    # use Filter::Simple sub { ... };
# en el código del usuario:
    use MyFilter;
    # este código se filtra
    no MyFilter;
    # este código no

DESCRIPCIÓN

El Problema

El filtrado de código fuente es una característica inmensamente poderosa de las versiones recientes de Perl. Permite extender el propio lenguaje (por ejemplo, el módulo Switch), simplificar el lenguaje (por ejemplo, Language::Pythonesque) o reinterpretar completamente el lenguaje (por ejemplo, Lingua::Romana::Perligata). Efectivamente, permite usar todo el poder de Perl como su propio lenguaje de macros, aplicado recursivamente.

El excelente módulo Filter::Util::Call (de Paul Marquess) proporciona una interfaz utilizable en Perl para el filtrado de código fuente, pero a menudo es demasiado potente y no tan simple como podría ser.

Para usar el módulo es necesario hacer lo siguiente:

1.
Descargar, compilar e instalar el módulo Filter::Util::Call. (Si tienes Perl 5.7.1 o posterior, esto ya está hecho por ti.)
2.
Configurar un módulo que haga un "use Filter::Util::Call".
3.
Dentro de ese módulo, crear una subrutina "import".
4.
Dentro de la subrutina "import" hacer una llamada a "filter_add", pasándole una referencia a subrutina.
5.
Dentro de la referencia a subrutina, llamar "filter_read" o "filter_read_exact" para "iniciar" $_ con datos de código fuente del archivo fuente que "usará" tu módulo. Comprobar el valor de estado devuelto para ver si realmente se leyó algún código fuente.
6.
Procesar el contenido de $_ para cambiar el código fuente de la manera deseada.
7.
Devolver el valor de estado.
8.
Si la desinstalación de tu módulo (a través de un "no") debe hacer que el filtrado de código fuente cese, crear una subrutina "unimport" y hacer que llame a "filter_del". Asegúrate de que la llamada a "filter_read" o "filter_read_exact" en el paso 5 no lea accidentalmente más allá del "no". Efectivamente, esto limita los filtros de código fuente a la operación línea por línea, a menos que la subrutina "import" realice algún pre-análisis avanzado del código fuente que está filtrando.

Por ejemplo, aquí hay un filtro de código fuente mínimo en un módulo llamado BANG.pm. Simplemente convierte cada ocurrencia de la secuencia "BANG\s+BANG" a la secuencia "die 'BANG' if $BANG" en cualquier pieza de código que siga a una declaración "use BANG;" (hasta la siguiente declaración "no BANG;", si la hay):

package BANG;
use Filter::Util::Call ;
sub import {
    filter_add( sub {
    my $caller = caller;
    my ($status, $no_seen, $data);
    while ($status = filter_read()) {
        if (/^\s*no\s+$caller\s*;\s*?$/) {
            $no_seen=1;
            last;
        }
        $data .= $_;
        $_ = "";
    }
    $_ = $data;
    s/BANG\s+BANG/die 'BANG' if \$BANG/g
        unless $status < 0;
    $_ .= "no $class;\n" if $no_seen;
    return 1;
    })
}
sub unimport {
    filter_del();
}
1 ;

Este nivel de sofisticación pone el filtrado fuera del alcance de muchos programadores.

Una Solución

El módulo Filter::Simple proporciona una interfaz simplificada a Filter::Util::Call; una que es suficiente para la mayoría de los casos comunes.

En lugar del proceso anterior, con Filter::Simple la tarea de configurar un filtro de código fuente se reduce a:

1.
Descargar e instalar el módulo Filter::Simple. (Si tienes Perl 5.7.1 o posterior, esto ya está hecho por ti.)
2.
Configurar un módulo que haga un "use Filter::Simple" y luego llame a "FILTER { ... }".
3.
Dentro de la subrutina anónima o bloque que se pasa a "FILTER", procesar el contenido de $_ para cambiar el código fuente de la manera deseada.

En otras palabras, el ejemplo anterior se convertiría en:

package BANG;
use Filter::Simple;
FILTER {
    s/BANG\s+BANG/die 'BANG' if \$BANG/g;
};
1 ;

Ten en cuenta que el código fuente se pasa como una sola cadena, por lo que cualquier regex que use "^" o "$" para detectar límites de línea necesitará el modificador "/m".

Desactivar o cambiar el comportamiento de <no>

Por defecto, el filtro instalado solo filtra hasta una línea que consiste en uno de los tres "terminadores" de código fuente estándar:

no ModuleName;  # comentario opcional

o:

__END__

o:

__DATA__

pero esto puede ser alterado pasando un segundo argumento a "use Filter::Simple" o "FILTER" (solo recuerda: no hay coma después del bloque inicial cuando usas "FILTER").

Ese segundo argumento puede ser una expresión regular "qr"ada (que se usa luego para hacer coincidir la línea terminadora), o un valor falso definido (que indica que no se debe buscar ninguna línea terminadora), o una referencia a un hash (en cuyo caso el terminador es el valor asociado con la clave 'terminator'.

Por ejemplo, para hacer que el filtro anterior filtre solo hasta una línea de la forma:

GNAB esu;

escribirías:

package BANG;
use Filter::Simple;
FILTER {
    s/BANG\s+BANG/die 'BANG' if \$BANG/g;
}
qr/^\s*GNAB\s+esu\s*;\s*?$/;

o:

FILTER {
    s/BANG\s+BANG/die 'BANG' if \$BANG/g;
}
{ terminator => qr/^\s*GNAB\s+esu\s*;\s*?$/ };

y para evitar que el filtro se desactive de ninguna manera:

package BANG;
use Filter::Simple;
FILTER {
    s/BANG\s+BANG/die 'BANG' if \$BANG/g;
}
"";    # o: 0

o:

FILTER {
    s/BANG\s+BANG/die 'BANG' if \$BANG/g;
}
{ terminator => "" };

Nota que, sin importar cuál sea el patrón terminador que establezcas, el terminador en sí mismo debe estar contenido en una única línea de código fuente.

Interfaz todo-en-uno

Separar la carga de Filter::Simple: "use Filter::Simple;" desde la configuración del filtrado: "FILTER { ... };" es útil porque permite que otro código (típicamente código de soporte del analizador o variables de caché) se defina antes de que se invoque el filtro. Sin embargo, a menudo no hay necesidad de tal separación.

En esos casos, es más fácil simplemente añadir la subrutina de filtrado y cualquier especificación de terminador directamente a la declaración "use" que carga Filter::Simple, así:

use Filter::Simple sub {
    s/BANG\s+BANG/die 'BANG' if \$BANG/g;
};

Esto es exactamente lo mismo que:

use Filter::Simple;
BEGIN {
    Filter::Simple::FILTER {
        s/BANG\s+BANG/die 'BANG' if \$BANG/g;
    };
}

excepto que la subrutina "FILTER" no es exportada por Filter::Simple.

Es muy común al filtrar el código fuente querer aplicar el filtro solo a las partes del código que no son cadenas de caracteres, o alternativamente a solo las cadenas de

Filter::Simple soporta este tipo de filtro exportando automáticamente la subrutina "FILT

"FILTER_ONLY" toma una secuencia de especificadores que instalan filtros separados (y posiblemente múltiples) que actúan solo sobre partes del código fuente. Por

ejemplo:

FILTER_ONLY

    quotelike => sub { s/BANG\s+BANG/CHITTY CHITTY/g }
;

    all   => sub { print if $::DEBUG
};

Filtrando solo las partes de código del código

fuente

La mayoría del código fuente deja de ser gramaticalmente correcto cuando se divide en las piezas entre cadenas literales y expresiones regulares. Así que los filtros componentes 'code' y 'code_no_comments' se comportan ligeramente diferente de los otros filtros parciales descritos en la sección

anterior.

En lugar de llamar al procesador especificado en cada pieza individual de código (es decir, en los trozos entre quotelikes), los filtros parciales 'code...' operan sobre el código fuente completo, pero con los trozos de quotelike (y, en el caso de 'code_no_comments', los comentarios) "en

blanco".

Es decir, un filtro 'code...' reemplaza cada cadena entrecomillada, quotelike, expresión regular, POD y sección __DATA__ con un marcador de posición. Los delimitadores de este marcador son el contenido de la variable $; en el momento en que se aplica el filtro (normalmente "\034"). Los cuatro bytes restantes son un identificador único para el componente que se está

reemplazando.

Este enfoque hace que sea comparativamente fácil escribir preprocesadores de código sin preocuparse por la forma o el contenido de cadenas, expresiones regulares,

etc.

Por conveniencia, durante una operación de filtrado 'code...', Filter::Simple proporciona una variable de paquete ($Filter::Simple::placeholder) que contiene una expresión regular precompilada que coincide con cualquier marcador de posición...y captura el identificador dentro del marcador. Los marcadores de posición pueden moverse y reordenarse dentro del código fuente según sea

necesario.

Además, una segunda variable de paquete (@Filter::Simple::components) contiene una lista de los varios trozos de $_, tal como fueron originalmente divididos para permitir la inserción de marcadores de

posición.

Una vez que se ha aplicado el filtrado, las cadenas originales, expresiones regulares, POD, etc., se vuelven a insertar en el código, reemplazando cada marcador de posición con el componente original correspondiente (de @components). Ten en cuenta que esto significa que la variable @components debe tratarse con extrema precaución dentro del filtro. El array @components almacena las "contratraducciones" de cada marcador de posición insertado en $_, así como el código fuente intersticial entre marcadores de posición. Si las contratraducciones de los marcadores se alteran en @components, se cambiarán de manera similar cuando los marcadores se eliminen de $_ después de que el filtro esté

completo.

Por ejemplo, el siguiente filtro detecta pares concatenados de cadenas/quotelikes y invierte el orden en que se

concatenan: 
package DemoRevCat;
use Filter::Simple;
FILTER_ONLY code => sub {
    my $ph = $Filter::Simple::placeholder;
    s{ ($ph) \s* [.] \s* ($ph) }{ $2.$1 }gx
}
;

Así, el siguiente

código: 
use DemoRevCat;
my $str = "abc" . q(def);
print
"$str\n";

se convertiría

en: 
my $str = q(def)."abc";
print
"$str\n";

y por lo tanto

imprimiría: 
defa
b
c

Usando Filter::Simple con una subrutina "import"

explícita

Filter::Simple genera una subrutina "import" especial para tu módulo (ver "Cómo funciona") que normalmente reemplazaría cualquier subrutina "import" que puedas haber declarado

explícitamente.

Sin embargo, Filter::Simple es lo suficientemente inteligente como para notar tu "import" existente y Hacer Lo Correcto con él. Es decir, si defines explícitamente una subrutina "import" en un paquete que está usando Filter::Simple, esa subrutina "import" seguirá siendo invocada inmediatamente después de cualquier filtro que

instales.

Lo único que tienes que recordar es que la subrutina "import" debe ser declarada antes de que se instale el filtro. Si usas "FILTER" para instalar el

filtro: 
package Filter::TurnItUpTo11;
use Filter::Simple;
FILTER { s/(\w+)/\U$1/ }
;

eso casi nunca será un problema, pero si instalas una subrutina de filtrado pasándola directamente a la declaración "use Filter::

Simple": 
package Filter::TurnItUpTo11;
use Filter::Simple sub{ s/(\w+)/\U$1/ }
;

entonces debes asegurarte de que tu subrutina "import" aparezca antes de esa declaraci

ón "u
se".

Usando Filter::Simple y Exporter

juntos

Del mismo modo, Filter::Simple también es lo suficientemente inteligente como para Hacer Lo Correcto si usas

Exporter: 
package Switch;
use base Exporter;
use Filter::Simple;
@EXPORT    = qw(switch case);
@EXPORT_OK = qw(given  when);
FILTER { $_ = magic_Perl_filter($_)
}

Inmediatamente después de que el filtro se haya aplicado al código fuente, Filter::Simple pasará el control a Exporter, para que pueda hacer su magia

también.

Por supuesto, aquí también, Filter::Simple tiene que saber que estás usando Exporter antes de aplicar el filtro. Eso casi nunca es un problema, pero si estás nervioso al respecto, puedes garantizar que las cosas funcionarán correctamente asegurándote de que tu "use base Exporter" siempre preceda a tu "use Filte

r::Si
mple".

Cómo

funciona

El módulo Filter::Simple exporta en el paquete que llama a "FILTER" (o que "use"a directamente) -- como el paquete "BANG" en el ejemplo anterior -- dos subrutinas construidas automáticamente -- "import" y "unimport" -- que se encargan de todos los detalles

desagradables.

Además, la subrutina "import" generada pasa su propia lista de argumentos a la subrutina de filtrado, por lo que el filtro BANG.pm podría fácilmente hacerse

paramétrico: 
package BANG;
use Filter::Simple;
FILTER {
    my ($die_msg, $var_name) = @_;
    s/BANG\s+BANG/die '$die_msg' if \${$var_name}/g;
};
# and in some user code:
use BANG "BOOM", "BAM";  # "BANG BANG" becomes: die 'BOOM' if
$BAM

La subrutina de filtrado especificada se llama cada vez que se encuentra un "use BANG", y se le pasa todo el código fuente que sigue a esa llamada, hasta el siguiente "no BANG;" (o lo que sea el terminador que hayas establecido) o el final del archivo fuente, lo que ocurra primero. Por defecto, cualquier "no BANG;" debe aparecer por sí

solo en una l
ínea separada, o se ignora.
