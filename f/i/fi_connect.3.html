NOMBRE

fi_cm - Operaciones de gestión de conexiones

fi_connect / fi_listen / fi_accept / fi_reject / fi_shutdown
Gestiona el estado de la conexión del endpoint.
fi_setname / fi_getname / fi_getpeer
Establece la dirección local o devuelve la dirección local o del par.
fi_join / fi_close / fi_mc_addr
Únete, abandona o recupera una dirección multicast.

SINOPSIS

#include <rdma/fi_cm.h>
int fi_connect(struct fid_ep *ep, const void *addr,
    const void *param, size_t paramlen);
int fi_listen(struct fid_pep *pep);
int fi_accept(struct fid_ep *ep, const void *param, size_t paramlen);
int fi_reject(struct fid_pep *pep, fid_t handle,
    const void *param, size_t paramlen);
int fi_shutdown(struct fid_ep *ep, uint64_t flags);
int fi_setname(fid_t fid, void *addr, size_t addrlen);
int fi_getname(fid_t fid, void *addr, size_t *addrlen);
int fi_getpeer(struct fid_ep *ep, void *addr, size_t *addrlen);
int fi_join(struct fid_ep *ep, const void *addr, uint64_t flags,
    struct fid_mc **mc, void *context);
int fi_close(struct fid *mc);
fi_addr_t fi_mc_addr(struct fid_mc *mc);

ARGUMENTOS

ep / pep
Endpoint de la red sobre el que cambiar el estado de la conexión.

fid Endpoint activo o pasivo para obtener/establecer la dirección.

addr
Buffer para la dirección. En una llamada de establecimiento, el endpoint se asignará la dirección especificada. En una llamada de obtención, la dirección local se copiará en el buffer, hasta el espacio proporcionado. Para conectar, este parámetro indica la dirección del par al que conectarse. La dirección debe estar en el mismo formato que la especificada usando fi_info: addr_format cuando se creó el endpoint.
addrlen
En la entrada, especifica el tamaño del buffer de addr. En la salida, almacena el número de bytes escritos en el buffer de addr.
param
Datos especificados por el usuario intercambiados como parte del intercambio de conexión.
paramlen
Tamaño del buffer de param.
info
Información de la red asociada con una solicitud de conexión.
mc
Grupo multicast asociado con un endpoint.
flags
Flags adicionales para controlar la operación de conexión.
context
Contexto de usuario asociado con la solicitud.

DESCRIPCIÓN

Las funciones de gestión de conexiones se utilizan para conectar un endpoint orientado a la conexión (FI_EP_MSG) a un par que está escuchando.

fi_listen

La llamada fi_listen indica que el endpoint especificado debe ser transicionado a un estado de conexión pasivo, permitiéndole aceptar solicitudes de conexión entrantes. Las solicitudes de conexión contra un endpoint que escucha se informan asíncronamente al usuario a través de una cola de eventos CM enlazada usando el tipo de evento FI_CONNREQ. El número de solicitudes de conexión pendientes que se pueden poner en cola en un endpoint está limitado por el parámetro de backlog del endpoint que escucha. El backlog se inicializa basándose en valores de configuración administrativa, pero puede ajustarse a través de la llamada fi_control.

fi_connect

La llamada fi_connect inicia una solicitud de conexión en un endpoint orientado a la conexión a la dirección de destino. fi_connect solo puede llamarse en un endpoint una vez en su vida útil.

fi_accept / fi_reject

Las llamadas fi_accept y fi_reject se utilizan en el lado pasivo (escucha) de una conexión para aceptar o rechazar una solicitud de conexión, respectivamente. Para aceptar una conexión, la aplicación que escucha primero espera un evento de solicitud de conexión (FI_CONNREQ). Después de recibir dicho evento, la aplicación asigna un nuevo endpoint para aceptar la conexión. Este endpoint debe asignarse usando una estructura fi_info que haga referencia al handle de este evento FI_CONNREQ. Luego se invoca fi_accept con el endpoint recién asignado. Si la aplicación que escucha desea rechazar una solicitud de conexión, llama a fi_reject con el endpoint que escucha y una referencia a la solicitud de conexión.

Una solicitud de conexión aceptada con éxito resultará en que el endpoint activo (conectándose) vea un evento FI_CONNECTED en su cola de eventos asociada. Una solicitud de conexión rechazada o fallida generará un evento de error. La entrada de error proporcionará detalles adicionales que describen el motivo del intento fallido.

También se generará un evento FI_CONNECTED en el lado pasivo para el endpoint que acepta una vez que la conexión se haya establecido correctamente. El fid del evento FI_CONNECTED será el del endpoint pasado a fi_accept, en contraposición al endpoint pasivo que escucha. Las transferencias de datos salientes no se pueden iniciar en un endpoint orientado a la conexión hasta que se haya generado un evento FI_CONNECTED. Sin embargo, los buffers de recepción pueden asociarse con un endpoint en cualquier momento.

fi_shutdown

La llamada fi_shutdown se utiliza para desconectar de forma segura un endpoint de su par. El parámetro flags está reservado y debe ser 0.

Las operaciones pendientes publicadas en el endpoint cuando se llama a fi_shutdown se cancelarán o descartarán. La notificación de operaciones canceladas será informada por el proveedor a las colas de finalización correspondientes. Las operaciones descartadas se omitirán silenciosamente, sin generar finalizaciones. La elección entre cancelar y descartar operaciones depende del proveedor. Sin embargo, todas las finalizaciones canceladas se escribirán antes de que fi_shutdown devuelva.

Cuando se llama, fi_shutdown no afecta las finalizaciones ya escritas en una cola de finalización. Cualquier finalización en cola asociada con operaciones asíncronas publicadas en el endpoint aún puede recuperarse de las colas de finalización correspondientes después de que un endpoint se haya cerrado.

Se generará un evento FI_SHUTDOWN para un endpoint cuando el par remoto emita una desconexión usando fi_shutdown o cierre abruptamente el endpoint. Tenga en cuenta que en el caso de cierre abrupto, solo se generará un evento FI_SHUTDOWN si el sistema par es accesible y un agente de servicio o kernel en el sistema par puede notificar al endpoint local que la conexión ha sido abortada.

fi_close

Fi_close se utiliza para desasociar un endpoint de un grupo multicast y cerrar todos los recursos asociados con el grupo. Fi_close debe llamarse en todos los grupos multicast a los que se une un endpoint.

fi_setname

La llamada fi_setname puede utilizarse para modificar o asignar la dirección del endpoint local. Es conceptualmente similar a la operación bind de sockets. Un endpoint puede recibir una dirección en su creación, a través de la estructura fi_info. La llamada fi_setname permite crear un endpoint sin asociarlo con una dirección de servicio (por ejemplo, número de puerto) y/o nodo (por ejemplo, red) específica, con la dirección asignada dinámicamente. El formato de los datos de direccionamiento especificados debe coincidir con el especificado a través de la estructura fi_info cuando se creó el endpoint.

Si no se especifica una dirección de servicio y aún no se ha asignado una dirección de servicio al endpoint, el proveedor asignará una dirección de servicio y la asignará al endpoint. Si se especifica una dirección de nodo o servicio, entonces, tras la finalización exitosa de fi_setname, el endpoint se le asignará el direccionamiento dado. Si no se puede asignar una dirección o no se puede modificar la dirección del endpoint, se devuelve un número de error de red apropiado.

fi_getname / fi_getpeer

Las llamadas fi_getname y fi_getpeer pueden utilizarse para recuperar la dirección del endpoint local o del par, respectivamente. En la entrada, el parámetro addrlen debe indicar el tamaño del buffer addr. Si la dirección real es más grande que lo que cabe en el buffer, se truncará y se devolverá -FI_ETOOSMALL

. En la salida, addrlen se establece al tamaño del búfer necesario para almacenar la dirección, que puede ser mayor que el valor de entrada.

No se garantiza que fi_getname devuelva una dirección de origen válida hasta que el punto de conexión especificado haya sido habilitado o se le haya asignado una dirección. Un punto de conexión puede habilitarse explícitamente mediante fi_enable, o implícitamente, como mediante fi_connect o fi_listen. Una dirección puede asignarse usando fi_setname. No se garantiza que fi_getpeer devuelva una dirección de par válida hasta que un punto de conexión haya sido completamente conectado – se haya generado un evento FI_CONNECTED.

fi_join

Esta llamada adjunta un punto de conexión a un grupo de multidifusión. De forma predeterminada, el punto de conexión se unirá al grupo en función de las capacidades de transferencia de datos del punto de conexión. Por ejemplo, si el punto de conexión ha sido configurado tanto para enviar como para recibir datos, entonces el punto de conexión podrá iniciar y recibir transferencias hacia y desde el grupo de multidifusión. Los indicadores de fi_join pueden usarse para restringir el acceso al grupo de multidifusión, sujeto a las limitaciones de las capacidades del punto de conexión.

Las operaciones de unión a multidifusión se completan de forma asíncrona. Un punto de conexión debe estar vinculado a una cola de eventos antes de llamar a fi_join. El resultado de la operación de unión se reportará a la cola de eventos (EQ) como un evento FI_JOIN_COMPLETE. Las aplicaciones no pueden emitir transferencias de multidifusión hasta recibir la notificación de que la operación de unión se ha completado. Tenga en cuenta que un punto de conexión puede comenzar a recibir mensajes del grupo de multidifusión tan pronto como la unión se complete, lo cual puede ocurrir antes de que se genere el evento FI_JOIN_COMPLETE.

Las aplicaciones deben llamar a fi_close en el grupo de multidifusión para desconectar el punto de conexión del grupo. Después de que una operación de unión se haya completado, la llamada fi_mc_addr puede usarse para recuperar la dirección asociada con el grupo de multidifusión.

fi_mc_addr

Devuelve la dirección fi_addr_t asociada con un grupo de multidifusión. Esta dirección debe usarse al transmitir datos a un grupo de multidifusión y debe combinarse con el indicador de operación FI_MULTICAST.

INDICADORES (FLAGS)

Excepto en las funciones señaladas más abajo, los indicadores están reservados y deben ser 0.

FI_SEND
Aplica a fi_join. Este indicador indica que el punto de conexión debe unirse al grupo de multidifusión como un miembro de solo envío. El punto de conexión debe estar configurado para operaciones de transmisión para usar este indicador, o se producirá un error.
FI_RECV
Aplica a fi_join. Este indicador indica que el punto de conexión debe unirse al grupo de multidifusión con permisos de solo recepción. El punto de conexión debe estar configurado para operaciones de recepción para usar este indicador, o se producirá un error.

VALOR DEVUELTO

Devuelve 0 en caso de éxito. En caso de error, se devuelve un valor negativo correspondiente a un código de error de fabric. Los valores de código de error de fabric están definidos en rdma/fi_errno.h.

NOTAS

Para puntos de conexión orientados a conexión, el búfer referenciado por param se enviará como parte de la solicitud o respuesta de conexión, sujeto a las restricciones del protocolo de conexión subyacente. Las aplicaciones pueden usar fi_getopt con la opción de punto de conexión FI_OPT_CM_DATA_SIZE para determinar el tamaño de los datos de aplicación que pueden intercambiarse como parte de una solicitud o respuesta de conexión. Las llamadas fi_connect, fi_accept y fi_reject truncarán silenciosamente cualquier dato de aplicación que no pueda caber en los mensajes del protocolo subyacente. Los datos de usuario intercambiados como parte del proceso de conexión están disponibles como parte de la estructura fi_eq_cm_entry, para los eventos FI_CONNREQ y FI_CONNECTED, o como err_data adicional a fi_eq_err_entry, en el caso de una conexión rechazada.
