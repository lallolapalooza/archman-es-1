File::HomeDir(3) Documentación de Perl aportada por el usuario File::HomeDir(3)

NOMBRE

File::HomeDir - Encuentra tu directorio personal y otros directorios en cualquier plataforma

SINOPSIS

use File::HomeDir;

# Interfaz moderna (Usuario actual)
$home     = File::HomeDir->my_home;
$desktop  = File::HomeDir->my_desktop;
$docs     = File::HomeDir->my_documents;
$music    = File::HomeDir->my_music;
$pics     = File::HomeDir->my_pictures;
$videos   = File::HomeDir->my_videos;
$data     = File::HomeDir->my_data;
$dist     = File::HomeDir->my_dist_data('File-HomeDir');
$dist     = File::HomeDir->my_dist_config('File-HomeDir');

# Interfaz moderna (Otros usuarios)
$home    = File::HomeDir->users_home('foo');
$desktop = File::HomeDir->users_desktop('foo');
$docs    = File::HomeDir->users_documents('foo');
$music   = File::HomeDir->users_music('foo');
$pics    = File::HomeDir->users_pictures('foo');
$video   = File::HomeDir->users_videos('foo');
$data    = File::HomeDir->users_data('foo');

DESCRIPCIÓN

File::HomeDir es un módulo para localizar los directorios que son "propiedad" de un usuario (típicamente el tuyo) y para resolver los diversos problemas que surgen al intentar encontrarlos de manera consistente en una amplia variedad de plataformas.

El resultado final es una única API que puede encontrar tus recursos en cualquier plataforma, haciendo relativamente trivial crear software Perl que funcione de manera elegante y correcta sin importar dónde lo ejecutes.

Neutralidad de plataforma

En el mundo Unix, muchos tipos diferentes de datos pueden mezclarse en tu directorio personal (aunque en algunas plataformas Unix esto ya no es el caso, particularmente en plataformas orientadas al "escritorio").

En algunas plataformas no Unix, se asignan directorios separados para diferentes tipos de datos, y así ha sido durante mucho tiempo.

Al escribir aplicaciones sobre File::HomeDir, siempre deberías intentar usar el método más específico que puedas. Los documentos del usuario deberían guardarse en "my_documents", los datos que soportan una aplicación pero que normalmente no son editados por el usuario deberían ir a "my_data".

En plataformas que no hacen ninguna distinción, todos estos métodos diferentes se degradarán sin problemas al directorio personal principal, pero en plataformas que sí la hacen File::HomeDir siempre intentará Hacer Lo Correcto(tm).

MÉTODOS

Se proporcionan dos tipos de métodos. La serie de métodos "my_method" para encontrar recursos para el usuario actual, y la serie "users_method" (léase "método del usuario") para encontrar recursos para usuarios arbitrarios.

Esta división es necesaria, ya que en la mayoría de las plataformas es mucho más fácil encontrar información sobre el usuario actual en comparación con otros usuarios, y de hecho en algunas plataformas no puedes encontrar información como "users_desktop" en absoluto, debido a restricciones de seguridad.

Todos los métodos verificarán (usando una prueba "-d" ) que un directorio realmente existe antes de devolverlo, por lo que puedes confiar en los valores que se devuelven (sujeto a las advertencias habituales sobre condiciones de carrera donde los directorios pueden ser eliminados en el momento entre que se devuelve un directorio y tú lo usas).

Sin embargo, porque en algunos casos las plataformas pueden no soportar el concepto de directorios personales en absoluto, cualquier método puede devolver "undef" (tanto en contexto escalar como en contexto de lista) para indicar que no hay un directorio coincidente en el sistema.

Por ejemplo, la mayoría de los usuarios no confiables de tipo 'nobody' no tienen un directorio personal. Así que cualquier módulo que se use en una aplicación CGI que en algún nivel de recursión use tu código, resultará en llamadas a File::HomeDir devolviendo undef, incluso para una llamada básica home() .

my_home

El método "my_home" no toma argumentos y devuelve el directorio principal de perfil personal para el usuario actual.

Si la distinción es importante para ti, el término "actual" se refiere al usuario real, y no al usuario efectivo.

Esto también se aplica a todos los demás métodos "my".

Devuelve la ruta del directorio como una cadena, "undef" si el usuario actual no tiene un directorio personal, o muere en caso de error.

my_desktop

El método "my_desktop" no toma argumentos y devuelve el directorio "escritorio" para el usuario actual.

Debido a la diversidad y complejidad de las implementaciones necesarias para manejar la funcionalidad requerida de manera completa y total, el método "my_desktop" puede o no estar implementado en cada plataforma.

Dicho esto, estoy extremadamente interesado en código para implementar "my_desktop" en Unix, siempre que sea capaz de manejar (como lo hace la implementación de Windows) la internacionalización. También debería evitar resultados falsos positivos asegurándose de que solo devuelva los directorios apropiados para las plataformas apropiadas.

Devuelve la ruta del directorio como una cadena, "undef" si el usuario actual no tiene un directorio de escritorio, o muere en caso de error.

my_documents

El método "my_documents" no toma argumentos y devuelve el directorio (para el usuario actual) donde se almacenan los documentos del usuario.

Devuelve la ruta del directorio como una cadena, "undef" si el usuario actual no tiene un directorio de documentos, o muere en caso de error.

my_music

El método "my_music" no toma argumentos y devuelve el directorio donde se almacena la música del usuario actual.

No se hace ninguna preferencia hacia ningún tipo de música o programa musical particular, más bien el concepto de un directorio para contener la música del usuario se hace a nivel del sistema operativo subyacente o (al menos) del entorno de escritorio.

Devuelve la ruta del directorio como una cadena, "undef" si el usuario actual no tiene un directorio adecuado, o muere en caso de error.

my_pictures

El método "my_pictures" no toma argumentos y devuelve el directorio donde se almacenan las imágenes del usuario actual.

No se hace ninguna preferencia hacia ningún tipo de imagen o programa de imágenes particular, más bien el concepto de un directorio para contener las imágenes del usuario se hace a nivel del sistema operativo subyacente o (al menos) del entorno de escritorio.

Devuelve la ruta del directorio como una cadena, "undef" si el usuario actual no tiene un directorio adecuado, o muere en caso de error.

my_videos

El método "my_videos" no toma argumentos y devuelve el directorio donde se almacenan los vídeos del usuario actual.

No se hace ninguna preferencia hacia ningún tipo de vídeo o programa de vídeo particular, más bien el concepto de un directorio para contener los vídeos del usuario se hace a nivel del sistema operativo subyacente o (al menos) del entorno de escritorio.

Devuelve la ruta del directorio como una cadena, "undef" si el usuario actual no tiene un directorio adecuado, o muere en caso de error.

my_data

El método "my_data" no toma argumentos y devuelve el directorio donde las aplicaciones locales deberían almacenar sus datos internos para el usuario actual.

Generalmente una aplicación crearía un subdirectorio como ".foo", debajo de este directorio, y almacenaría sus datos allí. Al crear tu directorio de esta manera, obtienes un resultado preciso en el mayor número de plataformas posible. Pero consulta la documentación sobre my_dist_config() o my_dist_data() below.

Por ejemplo, en Unix obtienes "~/.foo" y en Win32 obtienes "~/Local Settings/Application Data/.foo"

Devuelve la ruta del directorio como una cadena, "undef" si el usuario actual no tiene un directorio de datos, o muere en caso de error.

my_dist_config

File::HomeDir->my_dist_config( $dist [, \%params] );

# Por ejemplo...

File::HomeDir->my_dist_config( 'File-HomeDir' );
File::HomeDir->my_dist_config( 'File-HomeDir', { create => 1 } );

El método "my_dist_config" toma un nombre de distribución como argumento y devuelve un directorio específico de la aplicación donde deberían almacenar su configuración interna.

El directorio base será "my_config" si la plataforma lo soporta, o "my_documents" en caso contrario. El subdirectorio en sí será "BASE/Perl/Dist-Name". Si el directorio base es el directorio de inicio del usuario, "my_dist_config" estará en "~/.perl/Dist-Name" (y por lo tanto oculto en todos los Unixes).

El último argumento opcional es una referencia a hash para ajustar el comportamiento del método. Se reconocen las siguientes claves de hash:

•
create

Pasar un valor verdadero a esta clave forzará la creación del directorio si no existe (recuerda que la política de "File::HomeDir"es devolver "undef" si el directorio no existe).

Por defecto es falso, lo que significa que no se creará el directorio automáticamente.

my_dist_data

File::HomeDir->my_dist_data( $dist [, \%params] );

# Por ejemplo...

File::HomeDir->my_dist_data( 'File-HomeDir' );
File::HomeDir->my_dist_data( 'File-HomeDir', { create => 1 } );

El método "my_dist_data" toma un nombre de distribución como argumento y devuelve un directorio específico de la aplicación donde deberían almacenar sus datos internos.

Este directorio será, por supuesto, un subdirectorio de "my_data". Las plataformas que soportan directorios específicos de datos usarán "DATA_DIR/perl/dist/Dist-Name" siguiendo el patrón común "DATA/vendor/application". Si el directorio "my_data" es el directorio de inicio del usuario, "my_dist_data" estará en "~/.perl/dist/Dist-Name" (y por lo tanto oculto en todos los Unixes).

El último argumento opcional es una referencia a hash para ajustar el comportamiento del método. Se reconocen las siguientes claves de hash:

•
create

Pasar un valor verdadero a esta clave forzará la creación del directorio si no existe (recuerda que la política de "File::HomeDir"es devolver "undef" si el directorio no existe).

Por defecto es falso, lo que significa que no se creará el directorio automáticamente.

users_home

$home = File::HomeDir->users_home('foo');

El método "users_home" toma un único parámetro y se usa para localizar el directorio de inicio/perfil de un usuario identificado en el sistema.

Aunque la mayoría de las veces este identificador sería alguna forma de nombre de usuario, se permite que varíe según la plataforma para soportar ids de usuario o UUIDs según corresponda para esa plataforma.

Devuelve la ruta del directorio como una cadena, "undef" si ese usuario no tiene un directorio de inicio, o muere en caso de error.

Devuelve la ruta del directorio como una cadena, "undef" si ese usuario no tiene un directorio de documentos, o muere en caso de error.

users_desktop

users_music

Devuelve la ruta del directorio como una cadena, "undef" si ese usuario no tiene un directorio de música, o muere en caso de error.

users_pictures

FUNCIONES

home

use File::HomeDir;
$home = home();
$home = home('foo');
$home = File::HomeDir::home();
$home = File::HomeDir::home('foo');

La función "home" se exporta por defecto y se proporciona para compatibilidad con aplicaciones heredadas. En nuevas aplicaciones, deberías usar la interfaz más nueva basada en métodos mencionada arriba.

Devuelve la ruta del directorio al directorio de inicio/perfil de un usuario con nombre.

Si no se proporciona ningún parámetro, devuelve la ruta del directorio al directorio de inicio/perfil del usuario actual.
