NOMBRE

fi_join_collective
Operación donde un subconjunto de pares se une a un nuevo grupo colectivo.
fi_barrier / fi_barrier2
Operación colectiva que no se completa hasta que todos los pares han entrado en la llamada de barrera.
fi_broadcast
Un único remitente transmite datos a todos los pares, incluyéndose a sí mismo.
fi_alltoall
Cada par distribuye una porción de sus datos locales a todos los pares.
fi_allreduce
Operación colectiva donde todos los pares difunden una operación atómica a todos los demás pares.
fi_allgather
Cada par envía una copia completa de sus datos locales a todos los pares.
fi_reduce_scatter
Llamada colectiva donde los datos se recopilan de todos los pares y se fusionan (reducen). Los resultados de la reducción se distribuyen de vuelta a los pares, y cada par recibe una porción de los resultados.
fi_reduce
Llamada colectiva donde los datos se recopilan de todos los pares a un par raíz y se fusionan (reducen).
fi_scatter
Un único remitente distribuye (dispersa) una porción de sus datos locales a todos los pares.
fi_gather
Todos los pares envían sus datos a un par raíz.
fi_query_collective
Devuelve información sobre qué operaciones colectivas son compatibles con un proveedor y las limitaciones de la operación colectiva.

ARGUMENTOS

ep
Punto final de tejido (endpoint) en el que iniciar la operación colectiva.
set
Conjunto de vectores de direcciones (AV set) que define la membresía colectiva.
mc
Grupo de multidifusión (multicast) asociado con la operación colectiva.
buf
Búfer de datos local que especifica el primer operando de la operación colectiva.
count
El número de elementos referenciados, donde cada elemento es del tipo de dato indicado.
datatype
Tipo de dato asociado con los operandos atómicos.
op
Operación atómica a realizar.
result
Búfer de datos local para almacenar el resultado de la operación colectiva.
desc / result_desc
Descriptor de datos asociado con el búfer de datos local y el búfer de resultado local, respectivamente.
coll_addr
Dirección que hace referencia al grupo colectivo de puntos finales.
root_addr
Punto final único que es la fuente o el destino de los datos colectivos.
flags
Marcas adicionales para aplicar a la operación atómica.
context
Puntero especificado por el usuario para asociar con la operación. Este parámetro se ignora si la operación no generará una finalización exitosa, a menos que una marca de operación especifique que el parámetro de contexto se usará para entrada requerida.

DESCRIPCIÓN

En general, las operaciones colectivas se pueden considerar como intercambios atómicos coordinados entre un conjunto de puntos finales pares. Los lectores deben consultar la página del manual de fi_atomic(3) para obtener detalles sobre las operaciones atómicas y los tipos de datos definidos por libfabric.

Una operación colectiva es un intercambio de comunicación grupal. Involucra a múltiples pares intercambiando datos con otros pares que participan en la llamada colectiva. Las operaciones colectivas requieren una estrecha coordinación de todos los miembros participantes. Todos los participantes deben invocar la misma llamada colectiva antes de que cualquier miembro individual pueda completar su operación localmente. Como resultado, las llamadas colectivas pueden sobrecargar el tejido, así como los búferes de datos locales y remotos.

Las interfaces colectivas de Libfabric están dirigidas a tejidos que admiten la descarga de partes de la comunicación colectiva en conmutadores de red, NICs y otros dispositivos. Sin embargo, no se impone ningún requisito de implementación al proveedor.

El primer paso para usar una llamada colectiva es identificar los puntos finales pares que participarán. La membresía colectiva sigue uno de dos modelos, ambos compatibles con libfabric. En el primer modelo, la aplicación gestiona la membresía. Esto generalmente significa que la aplicación está realizando una operación colectiva por sí misma utilizando comunicación punto a punto para identificar a los miembros que participarán. Además, la aplicación puede estar interactuando con un administrador de recursos de tejido para reservar los recursos de red necesarios para ejecutar operaciones colectivas. En este modelo, la aplicación informará a libfabric que la membresía ya se ha establecido.

Un modelo separado traslada la gestión de membresía bajo libfabric y directamente al proveedor. En este modelo, la aplicación debe identificar qué direcciones de pares serán miembros. Esa información se transmite al proveedor de libfabric, que es responsable de coordinar la creación del grupo colectivo. En el modelo gestionado por el proveedor, el proveedor realizará la operación colectiva necesaria para establecer el grupo de comunicación e interactuar con cualquier agente de gestión de tejido.

En ambos modelos, la membresía colectiva se comunica al proveedor creando y configurando un conjunto de vectores de direcciones (AV set). Un AV set representa un subconjunto ordenado de direcciones en un vector de direcciones (AV). Los detalles sobre la creación y configuración de un AV set están disponibles en fi_av_set(3).

Una vez que un AV set ha sido programado con la información de membresía colectiva, un punto final se une al set. Esto utiliza la operación fi_join_collective y opera de forma asíncrona. Esto difiere de cómo se asocia un punto final synchro

Para la comodidad del desarrollador, se define un conjunto de APIs colectivas. Las APIs colectivas difieren de las interfaces de mensajes y RMA en que el formato de los datos es conocido por el proveedor, y la colectiva puede realizar una operación sobre esos datos. Esto alinea las operaciones colectivas estrechamente con las interfaces atómicas.

Únete a la Colectiva (fi_join_collective)

Esta llamada adjunta un punto final a un grupo de membresía colectiva. Libfabric trata a los miembros colectivos como un grupo de multidifusión, y la llamada fi_join_collective adjunta el punto final a ese grupo de multidifusión. Por defecto, el punto final se unirá al grupo basándose en las capacidades de transferencia de datos del punto final. Por ejemplo, si el punto final se ha configurado para enviar y recibir datos, entonces el punto final podrá iniciar y recibir transferencias hacia y desde la colectiva. Las banderas de entrada pueden usarse para restringir el acceso al grupo colectivo, sujeto a las limitaciones de capacidad del punto final.

Las operaciones de unión colectiva se completan de forma asíncrona y pueden implicar transferencias de tejido, dependiendo de la implementación del proveedor. Se debe vincular un punto final a una cola de eventos antes de llamar a fi_join_collective. El resultado de la operación de unión se informará a la EQ como un evento FI_JOIN_COMPLETE. Las aplicaciones no pueden emitir transferencias colectivas hasta recibir notificación de que la operación de unión ha completado. Tenga en cuenta que un punto final puede comenzar a recibir mensajes del grupo colectivo tan pronto como se complete la unión, lo que puede ocurrir antes de que se genere el evento FI_JOIN_COMPLETE.

La operación de unión colectiva es en sí misma una operación colectiva. Todos los pares participantes deben llamar a fi_join_collective antes de que cualquier par individual informe que la unión ha completado. Las membresías colectivas gestionadas por la aplicación son una excepción. Con membresías gestionadas por la aplicación, la llamada fi_join_collective puede completarse localmente sin comunicación de tejido. Para membresías gestionadas por el proveedor, la llamada de unión colectiva requiere como entrada una coll_addr que se refiera a una dirección asociada con un conjunto AV (ver fi_av_set_addr) o un grupo colectivo existente (obtenido a través de una llamada anterior a fi_join_collective). La llamada fi_join_collective creará un nuevo subgrupo colectivo. Si se utilizan membresías gestionadas por la aplicación, coll_addr debe establecerse en FI_ADDR_UNAVAIL.

Las aplicaciones deben llamar a fi_close en el grupo colectivo para desconectar el punto final del grupo. Después de que una operación de unión se haya completado, la llamada fi_mc_addr puede usarse para recuperar la dirección asociada con el grupo de multidifusión. Consulte fi_cm(3) para obtener detalles adicionales sobre fi_mc_addr().

Barrera (fi_barrier)

La operación fi_barrier proporciona un mecanismo para sincronizar pares. La barrera no da como resultado ninguna transferencia de datos a nivel de aplicación. Una barrera no se completa localmente hasta que todos los pares han invocado la llamada de barrera. Esto significa para la aplicación local que el trabajo de los pares que completaron antes de llamar a barrera ha terminado.

Barrera (fi_barrier2)

Las operaciones fi_barrier2 son lo mismo que fi_barrier, pero con un parámetro adicional para pasar indicadores de operación.

Difusión (fi_broadcast)

fi_broadcast transfiere una matriz de datos desde un único remitente a todos los demás miembros del grupo colectivo. El parámetro buf de entrada se trata como el búfer de transmisión si el rango local es la raíz, de lo contrario, es el búfer de recepción. La operación de difusión actúa como una escritura o lectura atómica a una matriz de datos. Como resultado, el formato de los datos en buf se especifica a través del parámetro datatype. Se puede transmitir cualquier tipo de dato no void.

El siguiente diagrama muestra un ejemplo de difusión que se utiliza para transferir una matriz de enteros a un grupo de pares.

[5]  [5]  [5]
[9]  [9]  [9]
 |____^    ^
 |_________|

Todo a Todos (fi_alltoall)

La colectiva fi_alltoall implica la distribución (o dispersión) de diferentes porciones de una matriz de datos a los pares. Se explica mejor utilizando un ejemplo. Aquí tres pares realizan una colectiva todo a todos para intercambiar diferentes entradas en una matriz de enteros.

[1]   [2]   [3]
[5]   [6]   [7]
[9]  [10]  [11]
   \   |   /
   Todo a todos
   /   |   \
[1]   [5]   [9]
[2]   [6]  [10]
[3]   [7]  [11]

Cada par envía una parte de sus datos a los otros pares.

Las operaciones todo a todos pueden realizarse en cualquier tipo de dato no void. Sin embargo, todo a todos no realiza una operación sobre los datos en sí, por lo que no se especifica ninguna operación.

Todo Reducir (fi_allreduce)

fi_allreduce se puede describir como todos los pares que proporcionan entrada a una operación atómica, con el resultado copiado a cada par. Conceptualmente, esto se puede ver como cada par que emite una operación atómica de multidifusión a todos los demás pares, obteniendo los resultados y combinándolos. La combinación de los resultados se denomina reducción. La operación fi_allreduce() toma como entrada una matriz de datos y la operación atómica especificada a realizar. Los resultados de la reducción se escriben en el búfer de resultados.

Se puede especificar cualquier tipo de dato no void. Las operaciones atómicas válidas se enumeran a continuación en la llamada fi_query_collective. El siguiente diagrama muestra un ejemplo de una operación todo reducir que implica sumar una matriz de enteros entre tres pares.

 [1]  [1]  [1]
 [5]  [5]  [5]
 [9]  [9]  [9]
   \   |   /
      suma
   /   |   \
 [3]  [3]  [3]
[15] [15] [15]
[27] [27] [27]
  Todo Reducir

Todo Reunir (fi_allgather)

Conceptualmente, todo reunir se puede ver como lo opuesto al componente scatter de reduce-scatter. Todo reunir recopila datos de todos los pares en una única matriz, y luego copia esa matriz de vuelta a cada par.

[1]  [5]  [9]
  \   |   /
 Todo reunir
  /   |   \
[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]

Todo reunir puede realizarse en cualquier tipo de dato no void. Sin embargo, todo reunir no realiza una operación sobre los datos en sí, por lo que no se especifica ninguna operación.

Reducir-Dispersar (fi_reduce_scatter)

La colectiva fi_reduce_scatter es similar a una operación fi_allreduce, seguida de todo a todos. Con reducir-dispersar, todos los pares proporcionan entrada a una operación atómica, similar a todo reducir. Sin embargo, en lugar de que el resultado completo se copie a cada par, cada participante recibe solo una porción del resultado.

Esto se muestra en el siguiente ejemplo:

[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]
  \   |   /
     suma (reducir)
      |
     [3]
    [15]
    [27]
      |
   dispersar
  /   |   \
[3] [15] [27]

La llamada reducir-dispersar admite el mismo tipo de dato y operación atómica que fi_allreduce.

Reducir (fi_reduce)

La colectiva fi_reduce es la primera mitad de una operación fi_allreduce. Con reducir, todos los pares proporcionan entrada a una operación atómica, con los resultados recopilados por un único punto final 'raíz'.

Esto se muestra en el siguiente ejemplo, con el par más a la izquierda identificado como la raíz:

[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]
  \   |   /
     suma (reducir)
    /
 [3]
[15]
[27]

La llamada reducir admite el mismo tipo de dato y operación atómica que fi_allreduce.

Dispersar (fi_scatter)

La colectiva fi_scatter es la segunda mitad de una operación fi_reduce_scatter. Los datos de un único punto final 'raíz' se dividen y distribuyen a todos los pares.

Esto se muestra en el siguiente ejemplo:

 [3]
[15]
[27]
    \
   dispersar
  /   |   \
[3] [15] [27]

La operación de dispersión se utiliza para distribuir resultados a los pares. No se realiza ninguna operación atómica sobre los datos.

Reunir (fi_gather)

La operación fi_gather se utiliza para recopilar (reunir) los resultados de todos los pares y almacenarlos en un par 'raíz'.

Esto se muestra en el siguiente ejemplo, con el par más a la izquierda identificado como la raíz.

[1]  [5]  [9]
  \   |   /
    reunir
   /
[1]
[5]
[9]

La operación de reunión no realiza ninguna operación sobre los datos en sí.

Consultar Atributos Colectivos (fi_query_collective)

La llamada fi_query_collective informa qué operaciones colectivas son compatibles con el proveedor subyacente, para puntos finales adecuadamente configurados. Las operaciones colectivas necesarias por una aplicación que no son compatibles con el proveedor deben ser implementadas por la aplicación. La llamada de consulta verifica si un proveedor admite una operación colectiva específica para un tipo de dato y operación dados, si corresponde.

El nombre de la colectiva, así como el tipo de dato y la operación asociada, si corresponde, se proporcionan como entrada a fi_query_collective.

El parámetro coll puede hacer referencia a una de estas colectivas: FI_BARRIER, FI_BROADCAST, FI_ALLTOALL, FI_ALLREDUCE, FI_ALLGATHER, FI_REDUCE_SCATTER, FI_REDUCE, FI_SCATTER, o FI_GATHER. Se especifican detalles adicionales sobre la operación colectiva a través del parámetro de estructura fi_collective_attr. Para colectivas que actúan sobre datos, se deben especificar la operación y el tipo de dato relacionado.

a través de los atributos dados.

struct fi_collective_attr {
    enum fi_op op;
    enum fi_datatype datatype;
    struct fi_atomic_attr datatype_attr;
    size_t max_members;
      uint64_t mode;
};

Para una descripción de struct fi_atomic_attr, consulte fi_atomic(3).

op
En la entrada, esto especifica la operación atómica involucrada en la llamada colectiva. Esto debe establecerse en uno de los siguientes valores: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ, FI_ATOMIC_WRITE, o FI_NOOP. Para colectivos que no intercambian datos de la aplicación (fi_barrier), esto debe establecerse en FI_NOOP.
datatype
En la salida, especifica el tipo de dato de los datos que son modificados por el colectivo. Esto debe establecerse en uno de los siguientes valores: FI_INT8, FI_UINT8, FI_INT16, FI_UINT16, FI_INT32, FI_UINT32, FI_INT64, FI_UINT64, FI_FLOAT, FI_DOUBLE, FI_FLOAT_COMPLEX, FI_DOUBLE_COMPLEX, FI_LONG_DOUBLE, FI_LONG_DOUBLE_COMPLEX, o FI_VOID. Para colectivos que no intercambian datos de la aplicación (fi_barrier), esto debe establecerse en FI_VOID.
datatype_attr.count
El número máximo de elementos que pueden usarse con el colectivo.
datatype_attr.size
El tamaño del tipo de dato según lo soportado por el proveedor. Las aplicaciones deben validar el tamaño de los tipos de datos que difieren según la plataforma, como FI_LONG_DOUBLE.
max_members
El número máximo de pares que pueden participar en una operación colectiva.
mode
Este campo está reservado y debe ser 0.

Si una operación colectiva es soportada, la llamada de consulta devolverá FI_SUCCESS, junto con los atributos sobre los límites para usar esa operación colectiva a través del proveedor.

Completados

Las operaciones colectivas se mapean a operaciones fi_atomic subyacentes. Para una discusión de la semántica de completado atómico, consulte fi_atomic(3). El completado, el orden y la atomicidad de las operaciones colectivas coinciden con los definidos para las operaciones atómicas de punto a punto.

BANDERAS

Las siguientes banderas están definidas para las operaciones especificadas.

FI_SCATTER
Aplica a fi_query_collective. Cuando se establece, solicita información de atributos sobre la operación colectiva reduce-scatter.

VALOR DE RETORNO

Devuelve 0 en caso de éxito. En caso de error, se devuelve un valor negativo correspondiente al errno del fabric. Los valores de errno del fabric están definidos en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Consulte fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
-FI_EOPNOTSUPP
La operación atómica solicitada no es soportada en este punto de conexión.
-FI_EMSGSIZE
El número de operaciones colectivas en una sola solicitud excede el soportado por el proveedor subyacente.

NOTAS

Las operaciones colectivas se mapean a operaciones atómicas. Como tal, siguen la mayoría de las convenciones y restricciones que las operaciones atómicas de par a par. Esto incluye la atomicidad de datos, la alineación de datos y la semántica de orden de mensajes. Consulte fi_atomic(3) para información adicional sobre los tipos de datos y operaciones definidos para las operaciones atómicas y colectivas.
