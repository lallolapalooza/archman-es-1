NOMBRE

fi_join_collective
Operación donde un subconjunto de pares se une a un nuevo grupo colectivo.
fi_barrier / fi_barrier2
Operación colectiva que no se completa hasta que todos los pares han entrado en la llamada de barrera.
fi_broadcast
Un único emisor transmite datos a todos los pares, incluido él mismo.
fi_alltoall
Cada par distribuye una porción de sus datos locales a todos los pares.
fi_allreduce
Operación colectiva donde todos los pares difunden una operación atómica a todos los demás pares.
fi_allgather
Cada par envía una copia completa de sus datos locales a todos los pares.
fi_reduce_scatter
Llamada colectiva donde los datos se recopilan de todos los pares y se fusionan (reducen). Los resultados de la reducción se distribuyen de vuelta a los pares, recibiendo cada par una porción de los resultados.
fi_reduce
Llamada colectiva donde los datos se recopilan de todos los pares hacia un par raíz y se fusionan (reducen).
fi_scatter
Un único emisor distribuye (dispersa) una porción de sus datos locales a todos los pares.
fi_gather
Todos los pares envían sus datos a un par raíz.
fi_query_collective
Devuelve información sobre qué operaciones colectivas son soportadas por un proveedor, y las limitaciones del colectivo.

result
Búfer de datos local para almacenar el resultado de la operación colectiva.
desc / result_desc
Descriptor de datos asociado con el búfer de datos local y el búfer de resultados local, respectivamente.

Dirección que se refiere al grupo colectivo de puntos de extremo.

DESCRIPCIÓN

En general, las operaciones colectivas pueden considerarse como operaciones atómicas coordinadas entre un conjunto de puntos de extremo pares. Los lectores deben referirse a la página man fi_atomic(3) para obtener detalles sobre las operaciones atómicas y los tipos de datos definidos por libfabric.

Una operación colectiva es un intercambio de comunicación de grupo. Implica que múltiples pares intercambien datos con otros pares que participan en la llamada colectiva. Las operaciones colectivas requieren una estrecha coordinación por parte de todos los miembros participantes. Todos los participantes deben invocar la misma llamada colectiva antes de que cualquier miembro pueda completar su operación localmente. Como resultado, las llamadas colectivas pueden ejercer presión sobre la fabrica, así como sobre los búferes de datos locales y remotos.

Las interfaces colectivas de Libfabric están dirigidas a fabricas que soportan la descarga de partes de la comunicación colectiva a conmutadores de red, tarjetas de interfaz de red (NIC) y otros dispositivos. Sin embargo, no se impone ningún requisito de implementación al proveedor.

El primer paso para usar una llamada colectiva es identificar los puntos de extremo pares que participarán. La membresía colectiva sigue uno de dos modelos, ambos soportados por libfabric. En el primer modelo, la aplicación gestiona la membresía. Esto generalmente significa que la aplicación está realizando una operación colectiva en sí misma utilizando comunicación de punto a punto para identificar a los miembros que participarán. Además, la aplicación puede interactuar con un gestor de recursos de la fabrica para reservar los recursos de red necesarios para ejecutar operaciones colectivas. En este modelo, la aplicación informará a libfabric que la membresía ya ha sido establecida.

Un modelo separado traslada la gestión de la membresía a libfabric y directamente al proveedor. En este modelo, la aplicación debe identificar qué direcciones de pares serán miembros. Esa información se transmite al proveedor de libfabric, que entonces es responsable de coordinar la creación del grupo colectivo. En el modelo gestionado por el proveedor, el proveedor generalmente realizará la operación colectiva necesaria para establecer el grupo de comunicación e interactuará con cualquier agente de gestión de la fabrica.

En ambos modelos, la membresía colectiva se comunica al proveedor creando y configurando un conjunto de vectores de direcciones (AV set). Un AV set representa un subconjunto ordenado de direcciones en un vector de direcciones (AV). Los detalles sobre cómo crear y configurar un AV set están disponibles en fi_av_set(3).

Una vez que un AV set ha sido programado con la información de membresía colectiva, un punto de extremo se une al conjunto. Esto usa la operación fi_join_collective y opera de forma asíncrona. Esto difiere de cómo un punto de extremo se asocia de forma sincrónica con un AV usando la llamada `fi_ep_bind()`. Una vez completada la operación `fi_join_collective`, se proporciona una `fi_addr` que se utiliza como dirección de destino al invocar una operación colectiva. Para mayor comodidad del desarrollador, se define un conjunto de API colectivas. Las API colectivas difieren de las interfaces de mensajes y RMA en que el formato de los datos es conocido por el proveedor, y la colectiva puede realizar una operación sobre esos datos. Esto alinea las operaciones colectivas estrechamente con las interfaces atómicas.

Unirse Colectivo (fi_join_collective)

Esta llamada adjunta un punto de acceso a un grupo de membresía colectiva. Libfabric trata a los miembros colectivos como un grupo de multidifusión, y la llamada `fi_join_collective` adjunta el punto de acceso a ese grupo de multidifusión. Por defecto, el punto de acceso se unirá al grupo según las capacidades de transferencia de datos del punto de acceso. Por ejemplo, si el punto de acceso se ha configurado para enviar y recibir datos, entonces el punto de acceso podrá iniciar y recibir transferencias hacia y desde la colectiva. Las banderas de entrada pueden usarse para restringir el acceso al grupo colectivo, sujeto a las limitaciones de capacidad del punto de acceso.

Las operaciones de unión colectiva se completan de forma asíncrona y pueden implicar transferencias de tejido, dependiendo de la implementación del proveedor. Un punto de acceso debe estar enlazado a una cola de eventos antes de llamar a `fi_join_collective`. El resultado de la operación de unión se informará a la EQ como un evento FI_JOIN_COMPLETE. Las aplicaciones no pueden emitir transferencias colectivas hasta recibir la notificación de que la operación de unión ha completado. Tenga en cuenta que un punto de acceso puede empezar a recibir mensajes del grupo colectivo tan pronto como la unión se complete, lo que puede ocurrir antes de que se genere el evento FI_JOIN_COMPLETE.

La operación de unión colectiva es en sí misma una operación colectiva. Todos los pares participantes deben llamar a `fi_join_collective` antes de que cualquier par individual informe que la unión se ha completado. La membresía colectiva gestionada por la aplicación es una excepción. Con membresías gestionadas por la aplicación, la llamada `fi_join_collective` puede completarse localmente sin comunicación de tejido. Para membresías gestionadas por el proveedor, la llamada de unión colectiva requiere como entrada una `coll_addr` que se refiera a una dirección asociada con un conjunto AV (ver `fi_av_set_addr`) o un grupo colectivo existente (obtenido a través de una llamada anterior a `fi_join_collective`). La llamada `fi_join_collective` creará un nuevo subgrupo colectivo. Si se utilizan membresías gestionadas por la aplicación, `coll_addr` debe establecerse en FI_ADDR_UNAVAIL.

Las aplicaciones deben llamar a `fi_close` en el grupo colectivo para desconectar el punto de acceso del grupo. Después de que una operación de unión haya completado, la llamada `fi_mc_addr` puede usarse para recuperar la dirección asociada con el grupo de multidifusión. Ver `fi_cm(3)` para detalles adicionales sobre `fi_mc_addr()`.

Barrera (fi_barrier)

La operación `fi_barrier` proporciona un mecanismo para sincronizar pares. La barrera no resulta en ninguna transferencia de datos a nivel de aplicación. Una barrera no se completa localmente hasta que todos los pares han invocado la llamada a barrera. Esto indica a la aplicación local que el trabajo de los pares que se completó antes de que ellos llamaran a la barrera ha terminado.

Barrera (fi_barrier2)

La operación `fi_barrier2` es la misma que `fi_barrier`, pero con un parámetro adicional para pasar banderas de operación.

Difusión (fi_broadcast)

`fi_broadcast` transfiere una matriz de datos desde un único remitente a todos los demás miembros del grupo colectivo. El parámetro de entrada `buf` se trata como el búfer de transmisión si el rango local es la raíz, de lo contrario es el búfer de recepción. La operación de difusión actúa como una escritura o lectura atómica a una matriz de datos. Como resultado, el formato de los datos en `buf` se especifica a través del parámetro `datatype`. Cualquier tipo de datos no nulo puede ser difundido.

El siguiente diagrama muestra un ejemplo de difusión utilizada para transferir una matriz de enteros a un grupo de pares.

[5]  [5]  [5]
[9]  [9]  [9]
 |____^    ^
 |_________|
  difusión

Todo a Todos (fi_alltoall)

La colectiva `fi_alltoall` implica la distribución (o dispersión) de diferentes porciones de una matriz de datos a los pares. Se explica mejor usando un ejemplo. Aquí, tres pares realizan una colectiva de todo a todos para intercambiar diferentes entradas en una matriz de enteros.

[1]   [2]   [3]
[5]   [6]   [7]
[9]  [10]  [11]
   \   |   /
    Todo a todos
   /   |   \
[1]   [5]   [9]
[2]   [6]  [10]
[3]   [7]  [11]

Cada par envía una parte de sus datos a los otros pares.

Las operaciones de todo a todos pueden realizarse en cualquier tipo de datos no nulo. Sin embargo, todo a todos no realiza una operación sobre los datos en sí, por lo que no se especifica ninguna operación.

Todo Reducir (fi_allreduce)

`fi_allreduce` puede describirse como todos los pares que proporcionan entrada a una operación atómica, con el resultado copiado de vuelta a cada par. Conceptualmente, esto puede verse como cada par emitiendo una operación atómica de multidifusión a todos los demás pares, obteniendo los resultados y combinándolos. La combinación de los resultados se denomina reducción. La operación `fi_allreduce()` toma como entrada una matriz de datos y la operación atómica especificada para realizar. Los resultados de la reducción se escriben en el búfer de resultados.

Se puede especificar cualquier tipo de datos no nulo. Las operaciones atómicas válidas se enumeran a continuación en la llamada `fi_query_collective`. El siguiente diagrama muestra un ejemplo de una operación de todo reducir que suma una matriz de enteros entre tres pares.

 [1]  [1]  [1]
 [5]  [5]  [5]
 [9]  [9]  [9]
   \   |   /
      suma
   /   |   \
 [3]  [3]  [3]
[15] [15] [15]
[27] [27] [27]
  Todo Reducir

Todo Agrupar (fi_allgather)

Conceptualmente, todo agrupar puede verse como lo opuesto al componente de dispersión de reduce-scatter. Todo agrupar recopila datos de todos los pares en una única matriz, y luego copia esa matriz de vuelta a cada par.

[1]  [5]  [9]
  \   |   /
 Todo agrupar
  /   |   \
[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]

Todo agrupar puede realizarse en cualquier tipo de datos no nulo. Sin embargo, todo agrupar no realiza una operación sobre los datos en sí, por lo que no se especifica ninguna operación.

Reducir-Dispersar (fi_reduce_scatter)

La colectiva `fi_reduce_scatter` es similar a una operación `fi_allreduce`, seguida de todo a todos. Con reducir dispersar, todos los pares proporcionan entrada a una operación atómica, similar a todo reducir. Sin embargo, en lugar de que el resultado completo se copie a cada par, cada participante recibe solo una porción del resultado.

Esto se muestra en el siguiente ejemplo:

[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]
  \   |   /
     suma (reducir)
      |
     [3]
    [15]
    [27]
      |
    dispersar
  /   |   \
[3] [15] [27]

La llamada reducir dispersar admite el mismo tipo de datos y operación atómica que `fi_allreduce`.

Reducir (fi_reduce)

La colectiva `fi_reduce` es la primera mitad de una operación `fi_allreduce`. Con reducir, todos los pares proporcionan entrada a una operación atómica, con los resultados recopilados por un único punto de acceso 'root'.

Esto se muestra en el siguiente ejemplo, con el par más a la izquierda identificado como la raíz:

[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]
  \   |   /
     suma (reducir)
    /
 [3]
[15]
[27]

La llamada reducir admite el mismo tipo de datos y operación atómica que `fi_allreduce`.

Dispersar (fi_scatter)

La colectiva `fi_scatter` es la segunda mitad de una operación `fi_reduce_scatter`. Los datos de un único punto de acceso 'root' se dividen y distribuyen a todos los pares.

Esto se muestra en el siguiente ejemplo:

 [3]
[15]
[27]
    \
   dispersar
  /   |   \
[3] [15] [27]

La operación de dispersión se utiliza para distribuir resultados a los pares. No se realiza ninguna operación atómica sobre los datos.

Agrupar (fi_gather)

La operación `fi_gather` se utiliza para recopilar (agrupar) los resultados de todos los pares y almacenarlos en un par 'root'.

Esto se muestra en el siguiente ejemplo, con el par más a la izquierda identificado como la raíz.

[1]  [5]  [9]
  \   |   /
    agrupar
   /
[1]
[5]
[9]

La operación de agrupar no realiza ninguna operación sobre los datos en sí.

Consultar Atributos Colectivos (fi_query_collective)

La llamada `fi_query_collective` informa qué operaciones colectivas son compatibles con el proveedor subyacente, para puntos de acceso adecuadamente configurados. Las operaciones colectivas necesarias por una aplicación que no son compatibles con el proveedor deben ser implementadas por la aplicación. La llamada de consulta verifica si un proveedor admite una operación colectiva específica para un tipo de datos y operación dados, si procede.

El nombre de la colectiva, así como el tipo de datos y la operación asociada, si procede, se proporcionan como entrada a `fi_query_collective`.

El parámetro `coll` puede hacer referencia a una de estas colectivas: FI_BARRIER, FI_BROADCAST, FI_ALLTOALL, FI_ALLREDUCE, FI_ALLGATHER, FI_REDUCE_SCATTER, FI_REDUCE, FI_SCATTER o FI_GATHER. Se especifican detalles adicionales sobre la operación colectiva a través del parámetro `struct fi_collective_attr`. NAME

fi_allreduce — perform an allreduce collective operation

SYNOPSIS

#include <libfabric/fabric.h>
int fi_allreduce(fi_addr_t port, void *buf, size_t count,
                 enum fi_datatype datatype, enum fi_op op,
                 uint64_t flags);

DESCRIPTION

The fi_allreduce call performs an allreduce collective operation. An allreduce operation combines data from all participating processes in a group and distributes the result back to all processes.

The fi_allreduce operation is conceptually equivalent to performing a reduce operation and then broadcasting the result to all participating nodes. The fi_allreduce operation is initiated by each process in the communication group. The data from each process is combined using the specified operation (op) and datatype (datatype). The final combined result is then distributed to all processes in the group.

The collective operations are initiated using the endpoint associated with the specified port. The buf and count parameters specify the local buffer and the number of elements to be used in the allreduce operation. The datatype parameter specifies the data type of the elements, and op specifies the reduction operation to be performed.

The flags parameter can be used to control the behavior of the allreduce operation. Currently, the only supported flag is FI_SCATTER, which modifies the operation to perform a reduce-scatter operation. In a reduce-scatter operation, the reduced data is distributed among the participants such that each participant receives a distinct portion of the result.

The number of participants in the collective operation is determined by the communication group associated with the endpoint. The collective operations are executed asynchronously. The completion of the operation can be determined by checking the status of the corresponding completion queue entry.

The fi_allreduce function is part of the libfabric collective communication interface. Collective operations are built upon underlying atomic operations and follow similar semantics regarding data ordering, atomicity, and completion. For detailed information on atomic operations and their semantics, refer to fi_atomic(3).

The fi_allreduce function initiates a collective operation. To query the attributes and capabilities of the collective operation on a specific endpoint, use the fi_query_collective function.

The struct fi_collective_attr is used to specify the attributes of a collective operation when querying its capabilities using fi_query_collective.

struct fi_collective_attr {
    enum fi_op op;
    enum fi_datatype datatype;
    struct fi_atomic_attr datatype_attr;
    size_t max_members;
      uint64_t mode;
};

For a description of struct fi_atomic_attr, see fi_atomic(3).

op
On input, this specifies the atomic operation involved with the collective call. This should be set to one of the following values: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ, FI_ATOMIC_WRITE, of FI_NOOP. For collectives that do not exchange application data (fi_barrier), this should be set to FI_NOOP.
datatype
On onput, specifies the datatype of the data being modified by the collective. This should be set to one of the following values: FI_INT8, FI_UINT8, FI_INT16, FI_UINT16, FI_INT32, FI_UINT32, FI_INT64, FI_UINT64, FI_FLOAT, FI_DOUBLE, FI_FLOAT_COMPLEX, FI_DOUBLE_COMPLEX, FI_LONG_DOUBLE, FI_LONG_DOUBLE_COMPLEX, or FI_VOID. For collectives that do not exchange application data (fi_barrier), this should be set to FI_VOID.
datatype_attr.count
The maximum number of elements that may be used with the collective.
datatype_attr.size
The size of the datatype as supported by the provider. Applications should validate the size of datatypes that differ based on the platform, such as FI_LONG_DOUBLE.
max_members
The maximum number of peers that may participate in a collective operation.
mode
This field is reserved and should be 0.

If a collective operation is supported, the query call will return FI_SUCCESS, along with attributes on the limits for using that collective operation through the provider.

Completions

Collective operations map to underlying fi_atomic operations. For a discussion of atomic completion semantics, see fi_atomic(3). The completion, ordering, and atomicity of collective operations match those defined for point to point atomic operations.

FLAGS

The following flags are defined for the specified operations.

FI_SCATTER
Applies to fi_query_collective. When set, requests attribute information on the reduce-scatter collective operation.

RETURN VALUE

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.

ERRORS

-FI_EAGAIN
See fi_msg(3) for a detailed description of handling FI_EAGAIN.
-FI_EOPNOTSUPP
The requested atomic operation is not supported on this endpoint.
-FI_EMSGSIZE
The number of collective operations in a single request exceeds that supported by the underlying provider.

NOTES

Collective operations map to atomic operations. As such, they follow most of the conventions and restrictions as peer to peer atomic operations. This includes data atomicity, data alignment, and message ordering semantics. See fi_atomic(3) for additional information on the datatypes and operations defined for atomic and collective operations.
