NOMBRE

fi_cm - operaciones de gestión de conexiones

fi_connect / fi_listen / fi_accept / fi_reject / fi_shutdown
Gestiona el estado de conexión del endpoint.
fi_setname / fi_getname / fi_getpeer
Establece la dirección local o devuelve la dirección local o del par.
fi_join / fi_close / fi_mc_addr
Únete, abandona o recupera una dirección multicast.

SINOPSIS

#include <rdma/fi_cm.h>
int fi_connect(struct fid_ep *ep, const void *addr,
    const void *param, size_t paramlen);
int fi_listen(struct fid_pep *pep);
int fi_accept(struct fid_ep *ep, const void *param, size_t paramlen);
int fi_reject(struct fid_pep *pep, fid_t handle,
    const void *param, size_t paramlen);
int fi_shutdown(struct fid_ep *ep, uint64_t flags);
int fi_setname(fid_t fid, void *addr, size_t addrlen);
int fi_getname(fid_t fid, void *addr, size_t *addrlen);
int fi_getpeer(struct fid_ep *ep, void *addr, size_t *addrlen);
int fi_join(struct fid_ep *ep, const void *addr, uint64_t flags,
    struct fid_mc **mc, void *context);
int fi_close(struct fid *mc);
fi_addr_t fi_mc_addr(struct fid_mc *mc);

ARGUMENTOS

ep / pep
Endpoint de fabricación sobre el cual cambiar el estado de la conexión.

fid Endpoint activo o pasivo para obtener/establecer la dirección.

addr
Búfer para la dirección. En una llamada de establecimiento, el endpoint se asociará con la dirección especificada. En una llamada de obtención, la dirección local se copiará en el búfer, hasta el espacio proporcionado. Para conectar, este parámetro indica la dirección del par al que conectarse. La dirección debe estar en el mismo formato que la especificada usando fi_info: addr_format cuando se creó el endpoint.
addrlen
En la entrada, especifica el tamaño del búfer addr. En la salida, almacena el número de bytes escritos en el búfer addr.
param
Datos especificados por el usuario intercambiados como parte del intercambio de conexión.
paramlen
Tamaño del búfer param.
info
Información de fabricación asociada con una solicitud de conexión.
mc
Grupo multicast asociado con un endpoint.
flags
Banderas adicionales para controlar la operación de conexión.
context
Contexto de usuario asociado con la solicitud.

DESCRIPCIÓN

Las funciones de gestión de conexiones se utilizan para conectar un endpoint orientado a la conexión (FI_EP_MSG) a un par que está escuchando.

fi_listen

La llamada a fi_listen indica que el endpoint especificado debe ser transicionado a un estado de conexión pasiva, permitiéndole aceptar solicitudes de conexión entrantes. Las solicitudes de conexión contra un endpoint que está escuchando se reportan de forma asíncrona al usuario a través de una cola de eventos CM enlazada utilizando el tipo de evento FI_CONNREQ. El número de solicitudes de conexión pendientes que pueden ser encoladas en un endpoint está limitado por el parámetro de backlog del endpoint que está escuchando. El backlog se inicializa basándose en los valores de configuración administrativa, pero puede ser ajustado a través de la llamada a fi_control.

fi_connect

La llamada a fi_connect inicia una solicitud de conexión en un endpoint orientado a la conexión a la dirección de destino. fi_connect solo puede ser llamada en un endpoint una vez en su vida útil.

fi_accept / fi_reject

Las llamadas a fi_accept y fi_reject se utilizan en el lado pasivo (escuchando) de una conexión para aceptar o rechazar una solicitud de conexión, respectivamente. Para aceptar una conexión, la aplicación que escucha espera primero un evento de solicitud de conexión (FI_CONNREQ). Después de recibir dicho evento, la aplicación asigna un nuevo endpoint para aceptar la conexión. Este endpoint debe ser asignado usando una estructura fi_info que haga referencia al handle de este evento FI_CONNREQ. Luego se invoca fi_accept con el endpoint recién asignado. Si la aplicación que escucha desea rechazar una solicitud de conexión, llama a fi_reject con el endpoint que está escuchando y una referencia a la solicitud de conexión.

Una solicitud de conexión aceptada con éxito resultará en que el endpoint activo (conectando) reciba un evento FI_CONNECTED en su cola de eventos asociada. Una solicitud de conexión rechazada o fallida generará un evento de error. La entrada de error proporcionará detalles adicionales que describen la razón del intento fallido.

También se generará un evento FI_CONNECTED en el lado pasivo para el endpoint que acepta una vez que la conexión se haya establecido correctamente. El fid del evento FI_CONNECTED será el del endpoint pasado a fi_accept, en contraposición al endpoint pasivo que está escuchando. Las transferencias de datos salientes no se pueden iniciar en un endpoint orientado a la conexión hasta que se haya generado un evento FI_CONNECTED. Sin embargo, los búferes de recepción pueden asociarse con un endpoint en cualquier momento.

fi_shutdown

La llamada a fi_shutdown se utiliza para desconectar elegantemente un endpoint de su par. El parámetro flags está reservado y debe ser 0.

Las operaciones pendientes publicadas en el endpoint cuando se llama a fi_shutdown serán canceladas o descartadas. La notificación de las operaciones canceladas será reportada por el proveedor a las colas de finalización correspondientes. Las operaciones descartadas se eliminarán silenciosamente, sin generar finalizaciones. La elección de cancelar en lugar de descartar operaciones depende del proveedor. Sin embargo, todas las finalizaciones canceladas se escribirán antes de que fi_shutdown devuelva el control.

Cuando se llama, fi_shutdown no afecta a las finalizaciones ya escritas en una cola de finalización. Cualquier finalización en cola asociada con operaciones asíncronas publicadas en el endpoint aún puede ser recuperada de las colas de finalización correspondientes después de que un endpoint haya sido cerrado.

Se generará un evento FI_SHUTDOWN para un endpoint cuando el par remoto emita una desconexión usando fi_shutdown o cierre abruptamente el endpoint. Tenga en cuenta que en el caso de cierre abrupto, solo se generará un evento FI_SHUTDOWN si el sistema par es accesible y un agente de servicio o kernel en el sistema par puede notificar al endpoint local que la conexión ha sido abortada.

fi_close

Fi_close se utiliza para desasociar un endpoint de un grupo multicast y cerrar todos los recursos asociados con el grupo. Fi_close debe ser llamado en todos los grupos multicast a los que se une un endpoint.

fi_setname

La llamada a fi_setname puede ser utilizada para modificar o asignar la dirección del endpoint local. Es conceptualmente similar a la operación de bind de sockets. A un endpoint se le puede asignar una dirección en su creación, a través de la estructura fi_info. La llamada a fi_setname permite crear un endpoint sin asociarlo con un servicio específico (por ejemplo, número de puerto) y/o una dirección de nodo (por ejemplo, red), con la dirección asignada dinámicamente. El formato de los datos de direccionamiento especificados debe coincidir con el especificado a través de la estructura fi_info cuando se creó el endpoint.

Si no se especifica una dirección de servicio y aún no se ha asignado una dirección de servicio al endpoint, entonces el proveedor asignará una dirección de servicio y la asociará al endpoint. Si se especifica una dirección de nodo o de servicio, entonces, tras la finalización exitosa de fi_setname, el endpoint se asociará con la direccionamiento dada. Si no se puede asignar una dirección o no se puede modificar la dirección del endpoint, se devolverá un número de error de fabricación apropiado.

fi_getname / fi_getpeer

Las llamadas a fi_getname y fi_getpeer pueden ser utilizadas para recuperar la dirección del endpoint local o del par, respectivamente. fi_joi

n

Esta llamada adjunta un punto de conexión a un grupo de multidifusión. Por defecto, el punto de conexión se unirá al grupo basándose en las capacidades de transferencia de datos del punto de conexión. Por ejemplo, si el punto de conexión ha sido configurado tanto para enviar como para recibir datos, entonces el punto de conexión podrá iniciar y recibir transferencias hacia y desde el grupo de multidifusión. Los flags de fi_join pueden usarse para restringir el acceso al grupo de multidifusión, sujeto a las limitaciones de las capacidades del punto de

conexión.

Las operaciones de unión a multidifusión se completan de forma asíncrona. Un punto de conexión debe estar vinculado a una cola de eventos antes de llamar a fi_join. El resultado de la operación de unión será reportado a la EQ como un evento FI_JOIN_COMPLETE. Las aplicaciones no pueden emitir transferencias de multidifusión hasta recibir la notificación de que la operación de unión se ha completado. Nótese que un punto de conexión puede comenzar a recibir mensajes del grupo de multidifusión tan pronto como la unión se complete, lo cual puede ocurrir antes de que se genere el evento FI_JOIN_COMPLETE

.

Las aplicaciones deben llamar a fi_close en el grupo de multidifusión para desconectar el pun

to de conexión del grupo. Después de que una operación de unión se haya completado, la llamad
a fi_mc_addr puede usarse para recuperar la dirección asociada con el grupo de multidifusión.

NOTA

S

Para puntos de conexión orientados a conexión, el buffer referenciado por param será enviado como parte de la solicitud o respuesta de conexión, sujeto a las restricciones del protocolo de conexión subyacente. Las aplicaciones pueden usar fi_getopt con la opción de punto de conexión FI

_OPT_CM_DATA_SIZE para determinar el tamaño de los datos de aplicación que pueden intercambiarse como parte de una solicitud o respuesta de conexión. Las llamadas fi_connect, fi_accept y fi_reject truncarán silenciosamente cualquier dato de aplicación que no pueda caber en los mensajes
del protocolo subyacente. Los datos de usuario intercambiados como parte del proceso de conexión están disponibles como parte de la estructura fi_eq_cm_entry, para los eventos FI_CONNREQ y FI_CONNECTED, o como err_data adicional a fi_eq_err_entry, en el caso de una conexión rechazada.
