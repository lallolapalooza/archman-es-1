#include <fido.h>

typedef enum {
	FIDO_OPT_OMIT = 0, /* usar el valor predeterminado del autenticador */
	FIDO_OPT_FALSE,    /* establecer explícitamente la opción en falso */
        FIDO_OPT_TRUE,     /* establecer explícitamente la opción en verdadero */
} fido_opt_t;

DESCRIPCIÓN

Las funciones del conjunto fido_assert_set_authdata definen los diversos parámetros de una aserción FIDO2, permitiendo que un tipo fido_assert_t se prepare para una llamada posterior a fido_dev_get_assert(3) o fido_assert_verify(3). Para la especificación completa de una aserción FIDO2 y el formato de sus partes constituyentes, por favor consulte el estándar de Autenticación Web (webauthn).

La función fido_assert_set_count() establece el número de declaraciones de aserción en assert a n.

Las funciones fido_assert_set_authdata() y fido_assert_set_sig() establecen los datos del autenticador y las partes de la firma de la declaración con índice idx de assert a ptr, donde ptr apunta a len bytes. Se realiza una copia de ptr, y no se conservan referencias al puntero pasado. Tenga en cuenta que la primera declaración de aserción de assert tiene un idx de 0. Los datos del autenticador pasados a fido_assert_set_authdata() deben ser una cadena de bytes codificada en CBOR, tal como se obtiene de fido_assert_authdata_ptr(). Alternativamente, se puede pasar un blob binario crudo a fido_assert_set_authdata_raw().

La función fido_assert_set_clientdata_hash() establece el hash de los datos del cliente de assert a ptr, donde ptr apunta a len bytes. Se realiza una copia de ptr, y no se conservan referencias al puntero pasado.

La función fido_assert_set_clientdata() permite a una aplicación establecer el hash de los datos del cliente de assert especificando los datos del cliente sin hashear de la aserción. Esto es requerido por Windows Hello, que calcula el hash de los datos del cliente internamente. Para compatibilidad con Windows Hello, las aplicaciones deben usar fido_assert_set_clientdata() en lugar de fido_assert_set_clientdata_hash().

La función fido_assert_set_rp() establece el id del région de cuenta (relying party) de assert, donde id es una cadena UTF-8 terminada en NUL. El contenido de id se copia, y no se conservan referencias al puntero pasado.

La función fido_assert_set_extensions() establece las extensiones de assert a la máscara de bits flags. En este momento, solo se admiten las extensiones FIDO_EXT_CRED_BLOB, FIDO_EXT_HMAC_SECRET y FIDO_EXT_LARGEBLOB_KEY. Si flags es cero, las extensiones de assert se borran.

La función fido_assert_set_hmac_salt() establece la sal HMAC de assert a ptr, donde ptr apunta a len bytes. Se realiza una copia de ptr, y no se conservan referencias al puntero pasado. La sal HMAC se utiliza como parte de la generación de claves para la extensión HMAC-Secret.

La función fido_assert_set_hmac_secret() establece el secreto HMAC de la declaración con índice idx de assert a ptr, donde ptr apunta a len bytes. Se realiza una copia de ptr, y no se conservan referencias al puntero pasado. El secreto HMAC se utiliza como parte de la generación de claves para la extensión HMAC-Secret.

La función fido_assert_set_up() indica si el usuario debe ser autenticado. Si se establece en FIDO_OPT_TRUE, la autenticación del usuario será requerida. Si se establece en FIDO_OPT_FALSE, la autenticación del usuario será opcional. Si se establece en FIDO_OPT_OMIT, el autenticador usará su valor predeterminado.

La función fido_assert_set_uv() indica si se requiere verificación de presencia del usuario. Si se establece en FIDO_OPT_TRUE, se requerirá la verificación de presencia del usuario. Si se establece en FIDO_OPT_FALSE, la verificación de presencia del usuario será opcional. Si se establece en FIDO_OPT_OMIT, el autenticador usará su valor predeterminado.

La función fido_assert_set_winhello_appid() establece el ID de aplicación de Windows Hello de assert a id, donde id es una cadena UTF-8 terminada en NUL. El contenido de id se copia, y no se conservan referencias al puntero pasado.

VALORES DE RETORNO

En caso de éxito, estas funciones devuelven 0. En caso de error, devuelven un valor negativo.

VER TAMBIÉN

fido.h(5), fido_assert(3), fido_assert_verify(3), fido_dev_get_assert(3)

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

fido_assert_set_hmac_salt() y fido_assert_set_hmac_secret() establecen las partes hmac-salt y hmac-secret de assert a ptr, donde ptr apunta a len bytes. Se realiza una copia de ptr y no se conservan referencias al puntero pasado. La Extensión HMAC Secret (hmac-secret) es una extensión CTAP 2.0. Tenga en cuenta que el hmac-secret resultante varía según si el autenticador realizó la verificación del usuario. La fido_assert_set_hmac_secret() función es normalmente solo útil al escribir pruebas.

Las fido_assert_set_up() y fido_assert_set_uv() funciones establecen los atributos up (presencia del usuario) y uv (verificación del usuario) de assert. Ambos son FIDO_OPT_OMIT por defecto, permitiendo al autenticador usar sus configuraciones predeterminadas.

La fido_assert_set_winhello_appid() función establece la aplicación U2F id (“U2F AppID”) de assert, donde id es una cadena UTF-8 terminada en NUL. El contenido de id se copia y no se conservan referencias al puntero pasado. La fido_assert_set_winhello_appid() función no tiene efecto a menos que assert se pase a fido_dev_get_assert(3) con un dispositivo dev en el que fido_dev_is_winhello(3) sea verdadero. En este caso, libfido2 instruirá a Windows Hello para intentar la aserción dos veces, primero con el id pasado a fido_assert_set_rp(), y una segunda vez con el id pasado a fido_assert_set_winhello_appid(). Si la segunda aserción tiene éxito, fido_assert_rp_id(3) apuntará al U2F AppID una vez que fido_dev_get_assert(3) se complete. Este mecanismo existe en Windows Hello para garantizar la compatibilidad hacia atrás con U2F sin que la aplicación solicite al usuario dos veces sin querer. Tenga en cuenta que fido_assert_set_winhello_appid() no es necesario en plataformas que ofrecen primitivas CTAP, ya que se puede sondear silenciosamente al autenticador para la existencia de credenciales U2F.

El uso del conjunto de fido_assert_set_authdata funciones puede ocurrir en dos situaciones distintas: al pedir a un dispositivo FIDO2 que produzca una serie de declaraciones de aserción, antes de fido_dev_get_assert(3) (es decir, en el contexto de un cliente FIDO2), o al verificar declaraciones de aserción usando fido_assert_verify(3) (es decir, en el contexto de un servidor FIDO2).

Para una descripción completa de la generación de una aserción FIDO2 y su verificación, consulte la especificación FIDO2. Un ejemplo de cómo usar el conjunto de fido_assert_set_authdata funciones se puede encontrar en el archivo examples/assert.c incluido con libfido2.

VALORES DE RETORNO

Las fido_assert_set_authdata funciones devuelven FIDO_OK en caso de éxito. Los códigos de error devueltos por el conjunto de funciones fido_assert_set_authdata están definidos en <fido/err.h>.
