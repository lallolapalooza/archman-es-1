NOMBRE

firewalld.policies - políticas de firewalld

DESCRIPCIÓN

¿Qué es una política?

Una política aplica un conjunto de reglas al tráfico que fluye entre zonas (ver zonas (ver firewalld.zones(5)). La política afecta al tráfico de manera unidireccional con estado, por ejemplo, de la zonaA a la zonaB. Esto permite políticas de filtrado asimétricas.

La relación de una política con las zonas se define asignando un conjunto de zonas de entrada y un conjunto de zonas de salida. Por ejemplo, si el conjunto de zonas de entrada contiene "internal" y el conjunto de zonas de salida contiene "external", entonces la política afectará a todo el tráfico que fluya desde la zona "internal" hacia la zona "external". Sin embargo, dado que las políticas son unidireccionales, no se aplicarán al tráfico que fluya desde "external" hacia "internal". El conjunto de entrada y el conjunto de salida pueden contener múltiples zonas.

A continuación se muestra una representación visual de la política foobar seguida de los comandos CLI para crearla. Esta política afectaría al tráfico que fluye desde la zona interna hacia la zona externa. Inicialmente, el destino se establece en ACCEPT para permitir todo el tráfico. Esto es común si la red interna es de confianza.

                +----------+           +----------+
                |          |  política |          |
                | internal | --------> | external |
                |   zona   |  foobar   |   zona   |
                |          |           |          |
                +----------+           +----------+

                # firewall-cmd --permanent --new-policy foobar
                # firewall-cmd --permanent --policy foobar --add-ingress-zone internal
                # firewall-cmd --permanent --policy foobar --add-egress-zone external
                # firewall-cmd --permanent --policy foobar --set-target ACCEPT
                # firewall-cmd --reload

Quizás tenga sentido ser más restrictivo. Este ejemplo modifica foobar para que solo permita: dns, http y tráfico https. Todo lo demás está bloqueado. A los clientes solo se les permitiría navegar por la web.

                # firewall-cmd --permanent --policy foobar --set-target REJECT
                # firewall-cmd --permanent --policy foobar --add-service dns
                # firewall-cmd --permanent --policy foobar --add-service http
                # firewall-cmd --permanent --policy foobar --add-service https
                # firewall-cmd --reload

Políticas activas

Las políticas solo se activan si se cumplen todas las siguientes condiciones.

•La política no está deshabilitada.
•La lista de zonas de entrada contiene al menos una zona regular o una única zona simbólica.
•La lista de zonas de salida contiene al menos una zona regular o una única zona simbólica.
•Para las zonas no simbólicas, la zona debe estar activa. Es decir, debe tener interfaces o fuentes asignadas a ella.

Si la política no está activa, entonces la política no tiene ningún efecto.

Zonas simbólicas

Las zonas regulares no son suficientes para expresar todas las formas de filtrado de paquetes. Por ejemplo, no hay ninguna zona que represente el tráfico que fluye hacia o desde el host que ejecuta firewalld. Como tal, existen algunas zonas simbólicas para llenar estos vacíos. Sin embargo, las zonas simbólicas son únicas en que son las únicas zonas permitidas en los conjuntos de zonas de entrada o salida. Por ejemplo, no se puede usar "public" y "HOST" en las zonas de entrada.

Zonas simbólicas:

1.HOST

Esta zona simbólica es para el tráfico que fluye hacia o desde el host que ejecuta firewalld. Esto corresponde a las cadenas de netfilter (iptables/nftables) INPUT y OUTPUT.

•Si se usa en la lista de zonas de salida, se aplicará al tráfico en la cadena INPUT.
•Si se usa en la lista de zonas de entrada, se aplicará al tráfico en la cadena OUTPUT.
2.ANY

Esta zona simbólica se comporta como un comodín para las zonas de entrada y de salida. Con la excepción de que no incluye "HOST". Es útil si se desea que una política se aplique a cada zona.

•Si se usa en la lista de zonas de entrada, se aplicará al tráfico que se origina en cualquier zona.
•Si se usa en la lista de zonas de salida, se aplicará al tráfico destinado a cualquier zona.

Políticas predefinidas

firewalld se envía con algunas políticas predefinidas. Estas pueden o no estar activas de forma predeterminada. Para más detalles, ver la descripción de cada política.

•allow-host-ipv6

Similitud con las zonas

Las políticas son similares a las zonas en que son un punto de anexo para las primitivas de firewalld: servicios, puertos, reenvío de puertos, etc. Esto no es una coincidencia. Las políticas son una generalización de cómo las zonas han logrado tradicionalmente el filtrado. De hecho, en firewalld moderno, las zonas se implementan internamente como un conjunto de políticas.

La principal diferencia entre las políticas y las zonas es que las políticas permiten el filtrado en todas las direcciones: entrada, salida y reenvío. Con algunas excepciones, las zonas solo permiten el filtrado de entrada, lo cual es suficiente para el firewall de una estación final. Sin embargo, para el filtrado a nivel de red o el filtrado en nombre de máquinas virtuales y contenedores, se necesita algo más flexible, es decir, políticas.
