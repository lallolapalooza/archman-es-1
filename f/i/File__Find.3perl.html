File::Find(3perl) Guía de referencia para programadores de Perl File::Find(3perl)

NOMBRE

File::Find - Recorrer un árbol de directorios.

SINOPSIS

use File::Find;
find(\&wanted, @directories_to_search);
sub wanted { ... }
use File::Find;
finddepth(\&wanted, @directories_to_search);
sub wanted { ... }
use File::Find;
find({ wanted => \&process, follow => 1 }, '.');

DESCRIPCIÓN

Estas son funciones para buscar en árboles de directorios realizando trabajo en cada archivo encontrado, similar al comando de Unix find(1) . "File::Find" exporta dos funciones, "find" y "finddepth". Funcionan de manera similar pero tienen diferencias sutiles.

find
find(\&wanted,  @directories);
find(\%options, @directories);

find() realiza una búsqueda en profundidad sobre los siguientes @directories en el orden en que se proporcionan. Para cada archivo o directorio encontrado, llama a la subrutina &wanted . (Vea más abajo para detalles sobre cómo usar la función &wanted ). Adicionalmente, para cada directorio encontrado, hará chdir() a ese directorio y continuará la búsqueda, invocando la función &wanted en cada archivo o subdirectorio del directorio.

finddepth
finddepth(\&wanted,  @directories);
finddepth(\%options, @directories);

finddepth() funciona igual que find() excepto que invoca la función &wanted para un directorio después de haberla invocado para el contenido del directorio. Realiza un recorrido en postorden en lugar de un recorrido en preorden, trabajando desde la parte inferior del árbol de directorios hacia arriba, mientras que find() trabaja desde la parte superior del árbol hacia abajo.

A pesar del nombre de la función finddepth() , tanto find() como finddepth() realizan una búsqueda en profundidad de la jerarquía de directorios.

%options

El primer argumento de find() es una referencia a código de su función &wanted , o una referencia a hash que describe las operaciones a realizar para cada archivo. La referencia a código se describe en "La función wanted" más abajo.

Aquí están las posibles claves para el hash:

"wanted"
El valor debe ser una referencia a código. Esta referencia a código se describe en "La función wanted" más abajo. La subrutina &wanted es obligatoria.
"bydepth"
Informa el nombre de un directorio solo DESPUÉS de que todas sus entradas hayan sido informadas. El punto de entrada finddepth() es un acceso directo para especificar "{ bydepth => 1 }" en el primer argumento de find().
"preprocess"
El valor debe ser una referencia a código. Esta referencia a código se usa para preprocesar el directorio actual. El nombre del directorio actualmente procesado está en $File::Find::dir. Su función de preprocesamiento se llama después de readdir(), pero antes del bucle que llama a la función wanted() . Se llama con una lista de cadenas (en realidad nombres de archivos/directorios) y se espera que devuelva una lista de cadenas. El código se puede usar para ordenar los nombres de archivos/directorios alfabéticamente, numéricamente, o para filtrar entradas de directorio basándose únicamente en su nombre. Cuando "follow" o "follow_fast" están en efecto, "preprocess" no hace nada.
"postprocess"
El valor debe ser una referencia a código. Se invoca justo antes de salir del directorio actualmente procesado. Se llama en contexto vacío sin argumentos. El nombre del directorio actual está en $File::Find::dir. Este gancho es útil para resumir un directorio, como calcular su uso de disco. Cuando "follow" o "follow_fast" están en efecto, "postprocess" no hace nada.
"follow"
Hace que se sigan los enlaces simbólicos. Dado que los árboles de directorios con enlaces simbólicos (seguidos) pueden contener archivos más de una vez e incluso pueden tener ciclos, se debe construir un hash con una entrada para cada archivo. Esto puede ser costoso tanto en espacio como en tiempo para un árbol de directorios grande. Vea "follow_fast" y "follow_skip" más abajo. Si "follow" o "follow_fast" están en efecto:
  • Se garantiza que se ha llamado a "lstat" antes de que se llame a la función wanted() del usuario. Esto permite verificaciones rápidas de archivos que involucran "_". Tenga en cuenta que esta garantía ya no se mantiene si "follow" o "follow_fast" no están establecidos.
  • Existe una variable $File::Find::fullname que contiene la ruta absoluta del archivo con todos los enlaces simbólicos resueltos. Si el enlace es un enlace simbólico colgante, entonces fullname se establecerá en "undef".
"follow_fast"
Esto es similar a "follow" excepto que puede informar algunos archivos más de una vez. Sin embargo, detecta ciclos. Dado que solo se deben hashear los enlaces simbólicos, esto es mucho más barato tanto en espacio como en tiempo. Si procesar un archivo más de una vez (por la función wanted() del usuario) es peor que simplemente tomar tiempo, se debe usar la opción "follow" .
"follow_skip"
"follow_skip==1", que es el valor predeterminado, hace que se ignoren todos los archivos que no son ni directorios ni enlaces simbólicos si están a punto de ser procesados por segunda vez. Si un directorio o un enlace simbólico están a punto de ser procesados por segunda vez, "File::Find" muere.

"follow_skip==0" hace que "File::Find" muera si algún archivo está a punto de ser procesado por segunda vez.

"follow_skip==2" hace que "File::Find" ignore cualquier archivo o directorio duplicado pero continúe normalmente en otros casos.

"dangling_symlinks"
Especifica qué hacer con los enlaces simbólicos cuyo destino no existe. Si es verdadero y una referencia a código, se llamará con el nombre del enlace simbólico y el directorio en el que reside como argumentos. De lo contrario, si es verdadero y las advertencias están activadas, se emitirá una advertencia de la forma "symbolic_link_name es un enlace simbólico colgante\n" . Si es falso, el enlace simbólico colgante será ignorado silenciosamente.
"no_chdir"
No hace chdir() a cada directorio mientras recurre. La función wanted() necesitará ser consciente de esto, por supuesto. En este caso, $_ será lo mismo que $File::Find::name.
"untaint"
Si find se usa en modo de contaminación (taint-mode) ("-T" interruptor de línea de comandos o "if EUID != UID" o "if EGID != GID"), entonces internamente los nombres de directorio deben ser descontaminados antes de poder hacerse "chdir"a ellos. Por lo tanto, se verifican contra una expresión regular "untaint_pattern". Tenga en cuenta que todos los nombres pasados a la función wanted() del usuario siguen estando contaminados. Si se usa esta opción mientras no se está en modo de contaminación, "untaint" no hace nada.
"untaint_pattern"
Vea arriba. Esto debe establecerse usando el operador de cita "qr" . El valor predeterminado está establecido en "qr|^([-+@\w./]+)$|". Tenga en cuenta que los paréntesis son vitales.

NAME

File::Find – traverse a file tree

SYNOPSIS

    use File::Find;
    find(\&wanted, @directories);

DESCRIPTION

The File::Find module simulates the behavior of the find(1) command. It applies a routine of your choice to each file and directory in a specified directory tree.

The main function exported by this module is called find(). It takes two arguments: a subroutine (or coderef) to apply to each file, and a list of directories to search.

The find() function is called like this:

    find(\&wanted, '/usr/local/lib', '/usr/local/bin');

This will call the subroutine wanted() for every file and directory in "/usr/local/lib" and "/usr/local/bin".

There are a number of options that you can pass to find() which will modify its behavior. These options are passed as a single hashref argument in place of the wanted subroutine. For example:

    use File::Find;
    my %options = (
        wanted    => \&process_file,
        follow    => 1,
        debug     => 0,
        maxdepth  => 5,
        mindepth  => 1,
        postorder => 1,
        bydepth   => 1,
        no_chdir  => 1,
        untaint   => 1,
        untaint_pattern => qr!/ \.?!,
        untaint_skip    => 1,
        all                 => 1,
        always_dirs         => 1,
        postvisit           => \&post_dir,
        prune               => 1,
        prune_pattern       => qr!/tmp/!,
    );
    find(\%options, '/tmp');

The options are:

all
If set, File::Find will also call the wanted function on the top-level directories themselves. By default, it only calls wanted on the files and directories within the top-level directories.
always_dirs
If set, the wanted function is called for directories even if they are empty. By default, empty directories are skipped.
bydepth
If set, directories are processed only after all their contents have been processed (like find -depth). This means that $File::Find::prune will not be inherited by the contents of a directory. This option implies postorder.
debug
If set, the function will print out diagnostics about what it's doing. This is mainly useful for debugging File::Find itself.
follow
If set, File::Find will follow symbolic links. This means that if it encounters a symbolic link to a directory, it will descend into that directory. Be careful, as this can lead to infinite loops if the symbolic links are set up incorrectly.
follow_fast
Similar to follow, but doesn't check if it has already visited a directory. Faster, but potentially dangerous.
maxdepth
If set to a non-negative integer N, File::Find will only process files and directories up to N levels deep. maxdepth 0 means only process the starting points themselves. maxdepth implies postorder.
min depth
If set to a non-negative integer N, File::Find will not process files or directories until it has reached a depth of N. mindepth 1 means process all files and directories except for the starting points. min depth implies postorder.
no_chdir
If set, File::Find will not change the current directory as it traverses the file tree. This makes File::Find slower, but it means that the current directory will not be changed. This option is off by default.
postorder
If set, directories will be visited after their contents have been processed. This means that File::Find will call the wanted function on the contents of a directory before calling it on the directory itself.
postvisit
A coderef that will be called on a directory after all of its contents have been visited. This option implies postorder.
prune
If set, and the wanted function returns true, then the current directory will not be recursed into.
prune_pattern
If set, and the current filename matches the given regular expression, then the current directory will not be recursed into. The default is to not prune.
untaint
If set, File::Find will call taint checks on the names of the files and directories it encounters. This is useful if you are running your script with the -T switch and you want to allow File::Find to operate on files that might otherwise be untrusted.
untaint_pattern
If set, File::Find will apply this regular expression to the full path of each file and directory. If the pattern matches, the file is considered "tainted" and cannot be used unless taint checks are disabled or untaint is true. The default is to consider no files as tainted.
untaint_skip
If set, a directory which fails the "untaint_pattern" is skipped, including all its sub-directories. The default is to "die" in such a case.

The wanted function

The wanted() function does whatever verifications you want on each file and directory. Note that despite its name, the wanted() function is a generic callback function, and does not tell "File::Find" if a file is "wanted" or not. In fact, its return value is ignored.

The "wanted" function takes no arguments but rather does its work through a collection of variables.

$File::Find::dir is the current directory name,
$_ is the current filename within that directory
$File::Find::name is the complete pathname to the file.

The above variables have all been localized and may be changed without affecting data outside of the wanted function.

For example, when examining the file /some/path/foo.ext you will have:

$File::Find::dir  = /some/path/
$_                = foo.ext
$File::Find::name = /some/path/foo.ext

You are chdir()'d to $File::Find::dir when the function is called, unless "no_chdir" was specified. Note that when changing to directories is in effect, the root directory (/) is a somewhat special case inasmuch as the concatenation of $File::Find::dir, '/' and $_ is not literally equal to $File::Find::name. The table below summarizes all variants:

             $File::Find::name  $File::Find::dir  $_
default      /                  /                 .
no_chdir=>0  /etc               /                 etc
             /etc/x             /etc              x
no_chdir=>1  /                  /                 /
             /etc               /                 /etc
             /etc/x             /etc              /etc/x

When "follow" or "follow_fast" are in effect, there is also a $File::Find::fullname. The function may set $File::Find::prune to prune the tree unless "bydepth" was specified. Unless "follow" or "follow_fast" is specified, for compatibility reasons ("find.pl", find2perl) there are in addition the following globals available: $File::Find::topdir, $File::Find::topdev, $File::Find::topino, $File::Find::topmode and $File::Find::topnlink.

This library is useful for the "find2perl" tool (distributed with the App::find2perl CPAN module), which when fed:

find2perl / -name .nfs\* -mtime +7 \
  -exec rm -f {} \; -o -fstype nfs -prune

produces something like:

sub wanted {
   /^\.nfs.*\z/s &&
   (($dev, $ino, $mode, $nlink, $uid, $gid) = lstat($_)) &&
   int(-M _) > 7 &&
   unlink($_)
   ||
   ($nlink || (($dev, $ino, $mode, $nlink, $uid, $gid) = lstat($_))) &&
   $dev < 0 &&
   ($File::Find::prune = 1);
}

Notice the "_" in the above "int(-M _)": the "_" is a magical filehandle that caches the information from the preceding stat(), lstat(), or filetest.

Here's another interesting wanted function. It will find all symbolic links that don't resolve:

sub wanted {
     -l && !-e && print "bogus link: $File::Find::name\n";
}

Note that you may mix directories and (non-directory) files in the list of directories to be searched by the wanted() function.

find(\&wanted, "./foo", "./bar", "./baz/epsilon");

In the example above, no file in ./baz/ other than ./baz/epsilon will be evaluated by wanted().

See also the script "pfind" on CPAN for a nice application of this module.

WARNINGS

If you run your program with the "-w" switch, or if you use the "warnings" pragma, File::Find will report warnings for several weird situations. You can disable these warnings by putting the statement

no warnings 'File::Find';

in the appropriate scope. See warnings for more info about lexical warnings.

BUGS AND CAVEATS

$dont_use_nlink
You can set the variable $File::Find::dont_use_nlink to 0 if you are sure the filesystem you are scanning reflects the number of subdirectories in the parent directory's "nlink" count.

If you do set $File::Find::dont_use_nlink to 0, you may notice an improvement in speed at the risk of not recursing into subdirectories if a filesystem doesn't populate "nlink" as expected.

$File::Find::dont_use_nlink now defaults to 1 on all platforms.

Symlinks
Be aware that the option to follow symbolic links can be dangerous. Depending on the structure of the directory tree (including symbolic links to directories) you might traverse a given (physical) directory more than once (only if "follow_fast" is in effect). Furthermore, deleting or changing files in a symbolically linked directory might cause very unpleasant surprises, since you delete or change files in an unknown directory.

HISTORY

"File::Find" used to produce incorrect results if called recursively. During the development of perl 5.8 this bug was fixed. The first fixed version of "File::Find" was 1.01.
