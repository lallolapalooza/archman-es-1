NOMBRE

fi_cntr - Operaciones de contador de finalización y eventos

fi_cntr_open / fi_close
Asignar/liberar un contador
fi_cntr_read
Leer el valor actual de un contador
fi_cntr_readerr
Lee el número de operaciones que han completado con error.
fi_cntr_add
Incrementar un contador en un valor especificado
fi_cntr_set
Establecer un contador a un valor especificado
fi_cntr_wait
Esperar a que un contador sea mayor o igual a un valor umbral

SINOPSIS

#include <rdma/fi_domain.h>
int fi_cntr_open(struct fid_domain *domain, struct fi_cntr_attr *attr,
    struct fid_cntr **cntr, void *context);
int fi_close(struct fid *cntr);
uint64_t fi_cntr_read(struct fid_cntr *cntr);
uint64_t fi_cntr_readerr(struct fid_cntr *cntr);
int fi_cntr_add(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_adderr(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_set(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_seterr(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_wait(struct fid_cntr *cntr, uint64_t threshold,
    int timeout);

ARGUMENTOS

domain
Dominio de tejido (fabric)
cntr
Contador de tejido (fabric)
attr
Atributos del contador
context
Contexto especificado por el usuario asociado al contador
value
Valor para incrementar o establecer el contador
threshold
Valor contra el cual comparar el contador
timeout
Tiempo en milisegundos para esperar. Un valor negativo indica tiempo de espera infinito.

DESCRIPCIÓN

Los contadores registran el número de operaciones solicitadas que se han completado. Los contadores pueden proporcionar un mecanismo de finalización ligero al permitir la supresión de entradas de finalización de CQ. Son útiles para aplicaciones que solo necesitan saber el número de solicitudes completadas, y no los detalles de cada solicitud. Por ejemplo, los contadores pueden ser útiles para implementar control de flujo basado en créditos o para rastrear el número de procesos remotos que han respondido a una solicitud.

Los contadores típicamente solo cuentan las finalizaciones exitosas. Sin embargo, si una operación se completa con error, puede incrementar un valor de error asociado. Es decir, un contador almacena en realidad dos valores distintos, con las finalizaciones de error actualizando un valor específico para errores.

Los contadores se actualizan siguiendo las semánticas de eventos de finalización definidas en fi_cq(3). El momento de la actualización se basa en el tipo de transferencia y las banderas de operación especificadas.

fi_cntr_open

fi_cntr_open asigna un nuevo contador de tejido. Las propiedades y el comportamiento del contador se definen por struct fi_cntr_attr.

struct fi_cntr_attr {
    enum fi_cntr_events  events;    /* tipo de eventos a contar */
    enum fi_wait_obj     wait_obj;  /* objeto de espera solicitado */
    struct fid_wait     *wait_set;  /* conjunto de espera opcional, obsoleto */
    uint64_t             flags;     /* banderas de operación */
};
events
Un contador captura diferentes tipos de eventos. El tipo específico que se va a contar es uno de los siguientes:
- FI_CNTR_EVENTS_COMP
El contador se incrementa por cada finalización exitosa que ocurre en un endpoint enlazado asociado. El tipo de finalizaciones (envíos y/o recepciones) que se cuentan puede restringirse mediante banderas de control al enlazar el contador y el endpoint. Los contadores se incrementan en todas las finalizaciones exitosas, independientemente de si la operación genera una entrada en una cola de eventos.
- FI_CNTR_EVENTS_BYTES
El contador se incrementa por el número de bytes del usuario, excluyendo cualquier dato de CQ, transferido en un mensaje de transporte al alcanzar la semántica de finalización especificada. Para contadores del lado del iniciador, la cuenta refleja el tamaño de la transferencia solicitada y se actualiza después de que el mensaje alcanza el nivel de finalización deseado (FI_INJECT_COMPLETE, FI_TRANSMIT_COMPLETE, etc.). Para operaciones de envío y escritura, la cuenta refleja el número de bytes transferidos al par. Para operaciones de lectura, la cuenta refleja el número de bytes devueltos en una respuesta de lectura. Las operaciones que pueden escribir y leer datos, como las atómicas, se comportan como operaciones de lectura en el iniciador, pero como escrituras en el destino. Para contadores del lado del destino, la cuenta refleja el tamaño de los datos del usuario recibidos y se incrementa sujeto a la semántica de finalización del lado del destino. En la mayoría de los casos, esto indica FI_DELIVERY_COMPLETE, pero puede diferir al acceder a memoria del dispositivo (HMEM). En caso de error, el tamaño de la transferencia no se aplica al campo de error, este campo se incrementa en 1. El tipo de transferencia FI_COLLECTIVE no es compatible.
wait_obj
Los contadores pueden asociarse con un objeto de espera específico. Los objetos de espera permiten a las aplicaciones bloquearse hasta que se señale el objeto de espera, lo que indica que un contador ha alcanzado un umbral específico. Los usuarios pueden usar fi_control para recuperar el objeto de espera subyacente asociado con un contador, para usarlo en otras llamadas del sistema. Los siguientes valores pueden usarse para especificar el tipo de objeto de espera asociado con un contador: FI_WAIT_NONE, FI_WAIT_UNSPEC, FI_WAIT_SET, FI_WAIT_FD, FI_WAIT_MUTEX_COND (obsoleto) y FI_WAIT_YIELD. El valor predeterminado es FI_WAIT_NONE.
- FI_WAIT_NONE
Se utiliza para indicar que el usuario no se bloqueará (esperará) eventos en el contador.
- FI_WAIT_UNSPEC
Especifica que el usuario solo esperará en el contador utilizando llamadas de la interfaz de tejido, como fi_cntr_wait. En este caso, el proveedor subyacente puede seleccionar el objeto de espera más apropiado o de mayor rendimiento disponible, incluidos mecanismos de espera personalizados. Las aplicaciones que seleccionan FI_WAIT_UNSPEC no tienen garantizado que recuperen el objeto de espera subyacente.
- FI_WAIT_SET (obsoleto)
Indica que el contador de eventos debe usar un objeto de conjunto de espera para esperar eventos. Si se especifica, el campo wait_set debe hacer referencia a un objeto de conjunto de espera existente.
- FI_WAIT_FD
Indica que el contador debe usar un descriptor de archivo como mecanismo de espera. Un objeto de espera de descriptor de archivo debe ser utilizable en rutinas select, poll y epoll. Sin embargo, un proveedor puede señalar un objeto de espera FD marcándolo como legible, escribible o con un error.
- FI_WAIT_MUTEX_COND (obsoleto)
Especifica que el contador debe usar un mutex y una variable condicional de pthread como objeto de espera.
- FI_WAIT_YIELD
Indica que el contador esperará sin un objeto de espera, pero en su lugar cederá en cada espera. Permite el uso de fi_cntr_wait a través de un spin.
wait_set (obsoleto)
Si wait_obj es FI_WAIT_SET, este campo hace referencia a un objeto de espera al cual el contador de eventos debe adjuntarse. Cuando se agrega un evento al contador de eventos, el conjunto de espera correspondiente se señalará si se cumplen todas las condiciones necesarias. El uso de un wait_set permite un método optimizado para esperar eventos en múltiples contadores de eventos. Este campo se ignora si wait_obj no es FI_WAIT_SET.
flags
Las banderas están reservadas para uso futuro y deben establecerse en 0.

fi_close

fi_close libera un contador de tejido.

fi_cntr_read

fi_cntr_read lee el valor actual de un contador de finalización exitosas.

fi_cntr_readerr

fi_cntr_readerr lee el valor del contador de errores. El contador de errores se incrementa en 1 por cada operación que se completa con error, independientemente del tamaño de la transferencia.

fi_cntr_add

fi_cntr_add incrementa el contador por el valor especificado. Este método se utiliza normalmente para incrementar un contador de finalización exitosas.

fi_cntr_adderr

fi_cntr_adderr incrementa el contador de errores por el valor especificado. Este método se utiliza normalmente para incrementar el contador de errores.

fi_cntr_set

fi_cntr_set establece el contador a un valor especificado. Esto se utiliza típicamente para restablecer un contador de finalización exitosas.

fi_cntr_seterr

fi_cntr_seterr establece el contador de errores a un valor especificado. Esto se utiliza típicamente para restablecer un contador de errores.

fi_cntr_wait

fi_cntr_wait bloquea hasta que el contador alcance o supere el valor umbral especificado. El parámetro timeout especifica la duración máxima en milisegundos. Si timeout es negativo, la llamada esperará indefinidamente. Si el contador ya es mayor o igual al umbral cuando se llama a fi_cntr_wait, la llamada regresará inmediatamente.

Si el contador está asociado con un objeto de espera (por ejemplo, FI_WAIT_FD), fi_cntr_wait puede utilizar ese objeto de espera para señalizar la finalización. El comportamiento exacto depende de la implementación del proveedor de tejido.

VALORES DE RETORNO

En caso de éxito, las funciones de contador devuelven 0. En caso de error, devuelven un número negativo que identifica el error.

fi_cntr_read y fi_cntr_readerr devuelven el valor del contador.

fi_cntr_wait devuelve 0 si el umbral se alcanza dentro del tiempo especificado, o -FI_ETIMEDOUT si el tiempo de espera expira antes de que se alcance el umbral.

NOTA

S

Para admitir una variedad de implementaciones de contadores, las actualizaciones realizadas en los valores de los contadores (por ejemplo, fi_cntr_set o fi_cntr_add) pueden no ser inmediatamente visibles para las operaciones de lectura del contador (es decir, fi_cntr_read o fi_cntr_readerr). Puede ocurrir un retraso pequeño, pero indefinido, entre el cambio del contador y la actualización del valor informado. Sin embargo, un valor final actualizado eventualmente se reflejará en el valor del contador

leído.

Además, las aplicaciones deben asegurarse de que el valor de un contador sea estable y no esté sujeto a cambios antes de llamar a fi_cntr_set o fi_cntr_seterr. De lo contrario, el val

or resultante del contador después de fi_cntr_set / fi_cntr_seterr es indefinido, ya que las actualizaciones del contador pueden perderse. Un valor de contador se considera estab
le si todas las actualizaciones anteriores realizadas con fi_cntr_set / fi_cntr_seterr y los resultados de las operaciones relacionadas se reflejan en el valor observado del contador.
