NOMBRE

fi_cm - Operaciones de gestión de conexiones

fi_connect / fi_listen / fi_accept / fi_reject / fi_shutdown
Gestiona el estado de conexión del punto de conexión.
fi_setname / fi_getname / fi_getpeer
Establece la dirección local, o devuelve la dirección local o del par del punto de conexión.
fi_join / fi_close / fi_mc_addr
Se une, abandona o recupera una dirección de multidifusión.

SINOPSIS

#include <rdma/fi_cm.h>
int fi_connect(struct fid_ep *ep, const void *addr,
    const void *param, size_t paramlen);
int fi_listen(struct fid_pep *pep);
int fi_accept(struct fid_ep *ep, const void *param, size_t paramlen);
int fi_reject(struct fid_pep *pep, fid_t handle,
    const void *param, size_t paramlen);
int fi_shutdown(struct fid_ep *ep, uint64_t flags);
int fi_setname(fid_t fid, void *addr, size_t addrlen);
int fi_getname(fid_t fid, void *addr, size_t *addrlen);
int fi_getpeer(struct fid_ep *ep, void *addr, size_t *addrlen);
int fi_join(struct fid_ep *ep, const void *addr, uint64_t flags,
    struct fid_mc **mc, void *context);
int fi_close(struct fid *mc);
fi_addr_t fi_mc_addr(struct fid_mc *mc);

ARGUMENTOS

ep / pep
Punto de conexión de la fabrica en el que cambiar el estado de la conexión.

fid Punto de conexión activo o pasivo para obtener/establecer la dirección.

addr
Búfer de dirección. En una llamada de establecimiento, al punto de conexión se le asignará la dirección especificada. En una llamada de obtención, la dirección local se copiará en el búfer, hasta el espacio proporcionado. Para connect, este parámetro indica la dirección del par a la que conectarse. La dirección debe estar en el mismo formato que el especificado mediante fi_info: addr_format cuando se creó el punto de conexión.
addrlen
En la entrada, especifica el tamaño del búfer addr. En la salida, almacena el número de bytes escritos en el búfer addr.
param
Datos especificados por el usuario que se intercambian como parte del intercambio de conexión.
paramlen
Tamaño del búfer param.
info
Información de la fabrica asociada con una solicitud de conexión.
mc
Grupo de multidifusión asociado con un punto de conexión.
flags
Banderas adicionales para controlar la operación de conexión.
context
Contexto de usuario asociado con la solicitud.

DESCRIPCIÓN

Las funciones de gestión de conexiones se utilizan para conectar un punto de conexión orientado a conexiones (FI_EP_MSG) a un par que escucha.

fi_listen

La llamada fi_listen indica que el punto de conexión especificado debe transicionar a un estado de conexión pasiva, permitiéndole aceptar solicitudes de conexión entrantes. Las solicitudes de conexión contra un punto de conexión que escucha se notifican de forma asíncrona al usuario a través de una cola de eventos de gestión de conexiones (CM) vinculada, utilizando el tipo de evento FI_CONNREQ. El número de solicitudes de conexión pendientes que se pueden encolar en un punto de conexión está limitado por el parámetro de backlog del punto de conexión que escucha. El backlog se inicializa en función de valores de configuración administrativa, pero puede ajustarse a través de la llamada fi_control.

fi_connect

La llamada fi_connect inicia una solicitud de conexión en un punto de conexión orientado a conexiones hacia la dirección de destino. fi_connect solo puede llamarse una vez en la vida útil de un punto de conexión.

fi_accept / fi_reject

Las llamadas fi_accept y fi_reject se utilizan en el lado pasivo (que escucha) de una conexión para aceptar o rechazar una solicitud de conexión, respectivamente. Para aceptar una conexión, la aplicación que escucha primero espera un evento de solicitud de conexión (FI_CONNREQ). Tras recibir dicho evento, la aplicación asigna un nuevo punto de conexión para aceptar la conexión. Este punto de conexión debe asignarse utilizando una estructura fi_info que haga referencia al manejador de este evento FI_CONNREQ. Luego se invoca fi_accept con el punto de conexión recién asignado. Si la aplicación que escucha desea rechazar una solicitud de conexión, llama a fi_reject con el punto de conexión que escucha y una referencia a la solicitud de conexión.

Una solicitud de conexión aceptada con éxito resultará en que el punto de conexión activo (que conecta) vea un evento FI_CONNECTED en su cola de eventos asociada. Una solicitud de conexión rechazada o fallida generará un evento de error. La entrada de error proporcionará detalles adicionales describiendo el motivo del intento fallido.

Un evento FI_CONNECTED también se generará en el lado pasivo para el punto de conexión que acepta una vez que la conexión se haya establecido correctamente. El fid del evento FI_CONNECTED será el del punto de conexión pasado a fi_accept, en lugar del punto de conexión pasivo que escucha. No se pueden iniciar transferencias de datos salientes en un punto de conexión orientado a conexiones hasta que se haya generado un evento FI_CONNECTED. Sin embargo, los búferes de recepción pueden asociarse con un punto de conexión en cualquier momento.

fi_shutdown

La llamada fi_shutdown se utiliza para desconectar de forma elegante un punto de conexión de su par. El parámetro flags está reservado y debe ser 0.

Las operaciones pendientes publicadas en el punto de conexión cuando se llama a fi_shutdown serán canceladas o descartadas. La notificación de las operaciones canceladas será reportada por el proveedor a la(s) cola(s) de finalización correspondiente(s). Las operaciones descartadas se eliminarán silenciosamente, sin generar finalizaciones. La elección de cancelar, en lugar de descartar operaciones, depende del proveedor. Sin embargo, todas las finalizaciones canceladas se escribirán antes de que fi_shutdown regrese.

Cuando se llama, fi_shutdown no afecta las finalizaciones ya escritas en una cola de finalización. Cualquier finalización encolada asociada con operaciones asíncronas publicadas en el punto de conexión aún puede recuperarse de la(s) cola(s) de finalización correspondiente(s) después de que un punto de conexión haya sido desconectado.

Se generará un evento FI_SHUTDOWN para un punto de conexión cuando el par remoto emita una desconexión usando fi_shutdown o cierre abruptamente el punto de conexión. Tenga en cuenta que en el caso de un cierre abrupto, un evento FI_SHUTDOWN solo se generará si el sistema del par es accesible y un servicio o agente de kernel en el sistema del par puede notificar al punto de conexión local que la conexión ha sido abortada.

fi_close

Fi_close se utiliza para desasociar un punto de conexión de un grupo de multidifusión y cerrar todos los recursos asociados con el grupo. Fi_close debe llamarse en todos los grupos de multidifusión a los que se une un punto de conexión.

fi_setname

La llamada fi_setname puede usarse para modificar o asignar la dirección del punto de conexión local. Es conceptualmente similar a la operación bind de los sockets. A un punto de conexión puede asignársele una dirección en su creación, a través de la estructura fi_info. La llamada fi_setname permite que un punto de conexión se cree sin estar asociado con un servicio específico (por ejemplo, número de puerto) y/o dirección de nodo (por ejemplo, red), con la dirección asignada dinámicamente. El formato de los datos de direccionamiento especificados debe coincidir con el especificado a través de la estructura fi_info cuando se creó el punto de conexión.

Si no se especifica una dirección de servicio y aún no se ha asignado una dirección de servicio al punto de conexión, entonces el proveedor asignará una dirección de servicio y la asignará al punto de conexión. Si se especifica una dirección de nodo o de servicio, entonces, tras la finalización exitosa de fi_setname, al punto de conexión se le asignará el direccionamiento dado. Si no se puede asignar una dirección, o la dirección del punto de conexión no se puede modificar, se devuelve un número de error de fabrica apropiado.

fi_getname / fi_getpeer

Las llamadas fi_getname y fi_getpeer pueden usarse para recuperar la dirección local o del par del punto de conexión, respectivamente. En la entrada, el parámetro addrlen debe indicar el tamaño del búfer addr. Si la dirección real es más grande de lo que cabe en el búfer, se truncará y se devolverá -FI_ETOOSMALL. En la salida, addrlen se establece al tamaño del búfer necesario para almacenar la dirección, que puede ser mayor que el valor de entrada.

No se garantiza que fi_getname devuelva una dirección de origen válida hasta que el punto de conexión especificado haya sido habilitado o se le haya asignado una dirección. Un punto de conexión puede habilitarse explícitamente mediante fi_enable, o implícitamente, como mediante fi_connect o fi_listen. Una dirección puede asignarse usando fi_setname. No se garantiza que fi_getpeer devuelva una dirección de par válida hasta que un punto de conexión haya sido completamente conectado – se haya generado un evento FI_CONNECTED.

fi_join

Esta llamada adjunta un punto de conexión a un grupo de multidifusión. Por defecto, el punto de conexión se unirá al grupo en función de las capacidades de transferencia de datos del punto de conexión. Por ejemplo, si el punto de conexión ha sido configurado tanto para enviar como para recibir datos, entonces el punto de conexión podrá iniciar y recibir transferencias hacia y desde el grupo de multidifusión. Los flags de fi_join pueden usarse para restringir el acceso al grupo de multidifusión, sujeto a las limitaciones de la capacidad del punto de conexión.

Las operaciones de unión a multidifusión se completan de forma asíncrona. Un punto de conexión debe estar vinculado a una cola de eventos antes de llamar a fi_join. El resultado de la operación de unión se reportará a la EQ como un evento FI_JOIN_COMPLETE. Las aplicaciones no pueden emitir transferencias de multidifusión hasta recibir la notificación de que la operación de unión se ha completado. Tenga en cuenta que un punto de conexión puede comenzar a recibir mensajes del grupo de multidifusión tan pronto como la unión se complete, lo que puede ocurrir antes de que se genere el evento FI_JOIN_COMPLETE.

Las aplicaciones deben llamar a fi_close en el grupo de multidifusión para desconectar el punto de conexión del grupo. Después de que una operación de unión se haya completado, la llamada fi_mc_addr puede usarse para recuperar la dirección asociada con el grupo de multidifusión.

fi_mc_addr

Devuelve la dirección fi_addr_t asociada con un grupo de multidifusión. Esta dirección debe usarse al transmitir datos a un grupo de multidifusión y emparejarse con el flag de operación FI_MULTICAST.

FLAGS

Excepto en las funciones anotadas a continuación, los flags están reservados y deben ser 0.

FI_SEND
Aplica a fi_join. Este flag indica que el punto de conexión debe unirse al grupo de multidifusión como un miembro solo de envío. El punto de conexión debe estar configurado para operaciones de transmisión para usar este flag, o se producirá un error.
FI_RECV
Aplica a fi_join. Este flag indica que el punto de conexión debe unirse al grupo de multidifusión solo con permisos de recepción. El punto de conexión debe estar configurado para operaciones de recepción para usar este flag, o se producirá un error.

VALOR DEVUELTO

Devuelve 0 en caso de éxito. En caso de error, se devuelve un valor negativo correspondiente a un errno de fabric. Los valores de errno de fabric están definidos en rdma/fi_errno.h.

ERRORES

NOTAS

Para puntos de conexión orientados a conexión, el búfer referenciado por param se enviará como parte de la solicitud o respuesta de conexión, sujeto a las restricciones del protocolo de conexión subyacente. Las aplicaciones pueden usar fi_getopt con la opción de punto de conexión FI_OPT_CM_DATA_SIZE para determinar el tamaño de los datos de la aplicación que pueden intercambiarse como parte de una solicitud o respuesta de conexión. Las llamadas fi_connect, fi_accept y fi_reject truncarán silenciosamente cualquier dato de la aplicación que no pueda caber en los mensajes del protocolo subyacente. Los datos de usuario intercambiados como parte del proceso de conexión están disponibles como parte de la estructura fi_eq_cm_entry, para los eventos FI_CONNREQ y FI_CONNECTED, o como err_data adicional a fi_eq_err_entry, en el caso de una conexión rechazada.
