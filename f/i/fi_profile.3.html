NOMBRE

fi_profile - Interfaz de Perfilado de Fabric

fi_profile_open / fi_profile_close
Abrir/cerrar un objeto de perfil en un punto final o un dominio especificado por el fid o asociado con el objeto de perfil.
fi_profile_query_vars / fi_profile_query_events
Consultar variables/eventos de perfilado disponibles asociados con el objeto de perfil.
fi_profile_read_u64
Leer el valor de una variable de tipo FI_UINT64.
fi_profile_reg_callback
Registrar una función de devolución de llamada para un evento de perfilado.
fi_profile_start_reads / fi_profile_end_reads
Controlar el acceso consecutivo a múltiples variables al mismo tiempo.

SINOPSIS

include <rdma/fi_profile.h>
int fi_profile_open(struct fid *fid, uint64_t flags,
    struct fid_profile **prof_fid, void *context);
int fi_profile_close(struct fid_profile *prof_fid);
void fi_profile_reset(struct fid_profile *prof_fid,  uint64_t flags);
ssize_t fi_profile_query_vars(struct fid_profile *prof_fid,
    struct fi_profile_desc *varlist, size_t *count)
ssize_t fi_profile_query_events(struct fid_profile *prof_fid,
    struct fi_profile_desc *eventlist, size_t *count);
int fi_profile_register_callback(struct fid_profile *prof_fid,
    uint32_t event_id,
    int (*callback)(struct fid_profile *prof_fid, 
                    struct fi_profile_desc *event, void *param, 
                    size_t size, void *context),
    void *context);
sszie_t fi_profile_read_u64(struct fid_profile *prof_fid, uint32_t var_id,
    uint64_t *data);
void fi_profile_start_reads(struct fid_profile *prof_fid, uint64_t flags);
void fi_profile_end_reads(struct fid_profile *prof_fid, uint64_t flags);

ARGUMENTOS

fid
Referencia a un punto final o un dominio que es el objetivo del perfilado.
prof_fid
Referencia a un objeto de perfil asociado con el fid objetivo.
flags
Banderas para controlar el perfilado u operación.
context
Contexto asociado con las operaciones de perfilado.
varlist
Un arreglo de variables de perfilado.
eventlist
Un arreglo de eventos de perfilado.
count
Número de variables o eventos disponibles en el proveedor.
var_id
Un ID único para una variable.
event_id
Un ID único para un evento.
callback
Función de devolución de llamada registrada para un evento. Vea la descripción de la devolución de llamada más abajo.
data
El valor actual de una variable.

DESCRIPCIÓN

La interfaz de perfilado de fabric permite a los usuarios obtener propiedades de configuración o de tiempo de ejecución de los proveedores en forma de "variables". Los proveedores definen variables y las hacen legibles para los usuarios a través de la interfaz de perfilado. Los proveedores definen eventos y los usan para reportar cuando una operación ha ocurrido o un estado ha cambiado donde una o más variables pueden cambiar sus valores. Los usuarios pueden registrar funciones de devolución de llamada para uno o más eventos, y recibir notificaciones de los proveedores una vez que un evento ocurre.

Para soportar la interfaz de perfilado, un punto final o un dominio en un proveedor necesita mantener un objeto fid_profile, e implementar las operaciones de perfilado allí. Para iniciar un perfilado, se debe hacer una llamada open en el objeto de punto final o dominio objetivo para obtener el objeto fid_profile. Si el objeto objetivo no soporta perfilado, la llamada open fallará con el código de error -FI_ENOSYS. Una vez que un objeto fid_profile se obtiene exitosamente, puede usarse para consultar variables o eventos disponibles y leer valores de variables.

VARIABLES

Las variables de perfilado son definidas en los proveedores y son accesibles a través de la interfaz de perfilado. Las variables son especificadas usando struct fi_profile_desc descrita más abajo. Una variable puede ser una configuración, un estado de tiempo de ejecución, o un contador asociado con un punto final o un dominio. Algunas variables son comunes y disponibles en la mayoría de los proveedores, mientras que otras son específicas del proveedor y solo están disponibles en un proveedor. Los usuarios pueden consultar variables disponibles y sus valores usando la interfaz de perfilado.

Las variables específicas del proveedor están fuera del alcance de esta página man. Las variables definidas por libfabric y sus tipos de datos se describen más abajo.

FI_VAR_UNEXP_MSG_CNT (tipo de datos: uint64_t)

Esta variable devuelve el número actual de mensajes inesperados que han sido recibidos por el proveedor que están esperando buffers de recepción coincidentes.

FI_VAR_UNEXP_MSG_QUEUE (tipo de datos: struct fi_cq_err_entry)

Esta variable devuelve la información actual de la cola de mensajes inesperados, cada entrada en la cola es para un mensaje inesperado presentado en la estructura fi_cq_err_entry.

EVENTOS

Los eventos de perfilado son definidos para notificar a los usuarios que una operación ha ocurrido o el estado de un objeto ha cambiado, lo que típicamente indica que una o más variables han sido modificadas. Los eventos son especificados usando struct fi_profile_desc descrita más abajo. Similar a las variables, los eventos pueden ser predefinidos por libfabric o ser específicos del proveedor. Los usuarios pueden registrar una devolución de llamada para ser notificados cuando un evento ocurre. Los eventos definidos por libfabric y los datos que corresponden con el evento, si los hay, se describen más abajo.

Las aplicaciones pueden leer valores de variables desde la devolución de llamada del evento cuando se permite, pero no pueden registrar o desregistrar eventos, consultar variables de perfilado o eventos.

Los eventos predefinidos de libfabric incluyen:

FI_EVENT_UNEXP_MSG_RECVD

Este evento indica que un mensaje inesperado fue recibido y ha sido encolado por el proveedor.

FI_EVENT_UNEXP_MSG_MATCHED

Este evento indica que un mensaje inesperado que fue previamente encolado por el proveedor ha sido coincidido.

Estos dos eventos pueden notificar a un usuario sin datos y depender del usuario para leer variables, por ejemplo, FI_VAR_UNEXP_MSG_CNT, para obtener la longitud actual de la cola de mensajes inesperados. También puede notificar a un usuario junto con datos de la variable, por ejemplo, FI_VAR_UNEXP_MSG_QUEUE, para proporcionar la información de los mensajes sobre la cola actual de mensajes inesperados.

PERFIL DESCRIPCIÓN

Las variables y eventos son descritas usando struct fi_profile_desc:

enum fi_profile_type {
    fi_primitive_type,
    fi_defined_type,
};
struct fi_profile_desc {
    uint32_t id;
    enum fi_profile_type datatype_sel;
    union {
        enum fi_datatype primitive;
        enum fi_type defined;
    } datatype;
    uint64_t flags;
    size_t size;
    const char *name;
    const char *desc;
};

id

Cada variable o evento tiene un identificador único (id). Los proveedores proporcionan este id y los usuarios lo usan para obtener el valor de la variable o registrar devoluciones de llamada para el evento.

datatype

El tipo de datos de la variable. Puede ser fi_profile(3) — Libfabric Programmer’s Manual

NAME

fi_profile — fabric profiling interface

SYNOPSIS

#include <libfabric/fi_profile.h>

struct fid_profile *fi_profile_open(struct fid *fid,
    uint32_t flags);

int fi_profile_close(struct fid_profile *prof_fid);

int fi_profile_query_vars(struct fid_profile *prof_fid,
    struct fi_profile_desc *varlist, size_t *count);

int fi_profile_query_events(struct fid_profile *prof_fid,
    struct fi_profile_desc *eventlist, size_t *count);

int fi_profile_reg_callback(struct fid_profile *prof_fid,
    const struct fi_profile_desc *event,
    fi_callback_t callback, void *param,
    void *context);

int fi_profile_read_u64(struct fid_profile *prof_fid,
    const struct fi_profile_desc *var, uint64_t *value);

int fi_profile_start_reads(struct fid_profile *prof_fid);

int fi_profile_end_reads(struct fid_profile *prof_fid);

ARGUMENTS

fid
A reference to an endpoint or domain object. Fabric profiling interface is associated with the fabric endpoint or domain.
flags
User specified flags. Possible flags include:
FI_PROFILE_READ_UNSYNCHRONIZED
Read variables without synchronizing access, which may incur less overhead but may lead to inconsistent data if variables are updated concurrently.
prof_fid
A reference to the profile object returned by fi_profile_open.
varlist
A pointer to an array of struct fi_profile_desc. This structure defines the variable to be queried.
eventlist
A pointer to an array of struct fi_profile_desc. This structure defines the event to be queried.
count
On input, indicates the maximum number of entries allowed in the buffer. On output, indicates the actual number of variables or events available.
event
The event to register a callback function for.
callback
The callback function to register. It is defined by the user and called by a provider.
param
An optional parameter to pass to the callback function.
size
The size of the data pointed to by param.
context
An application context pointer to pass to the callback function.
var
The variable to read.
value
A pointer to a uint64_t where the read value will be stored.

DESCRIPTION

The fabric profiling interface provides a mechanism for monitoring fabric performance counters and events. It allows users to query available profiling information, register callbacks for events, and read variable values.

The interface operates on profile objects, which are created by calling fi_profile_open on an existing endpoint or domain reference.

struct fi_profile_desc

This structure is used to describe profiling variables and events. It has the following fields:

size_t size
The size of the structure, must be initialized to sizeof(struct fi_profile_desc).
type
The type of the variable or event. It can be a primitive type defined in enum fi_datatype, or a libfabric structure type defined in enum fi_type.
datatye_sel
The selector of data type. It is used to indicate the data type is from enum fi_datatype or from enum fi_type.
flags
The features or restrictions of the variable.
size
The size (in bytes) of the data.
name
Reference to the name of a variable or an event. Storage is allocated and managed by the provider. Variables or events with the same name should have an identical id.
desc
Reference to the description of a variable or an event. Storage is allocated and managed by the provider.

fi_profile_open

fi_profile_open is used to initiate a profiling on a target endpoint or domain specified by the fid. Upon retuning successfully, a fid_profile is returned and can be used to perform profiling operations. If the target endpoint or domain does not support fabric profiling interface, the open call will fail with error code -FI_ENOSYS.

fi_profile_close

Close the profiling operations and release related resources.

fi_profile_query_vars / fi_profile_query_events

fi_profile_query_vars and fi_profile_query_events calls can be used to query available variables or events from the target endpoint or domain associated with the profile object. On input, the buffer (“varlist” or “eventlist”) should be allocated, and the “count” indicates the maximum number of entries (variables or events) allowed in the buffer. On output, the “count” indicates the actual number of varibles or events available in the target endpoint or domain. If the buffer is NULL, only the “count” will be set and return. User can use the “count” to allocate space and call the function again. The return value of these calls indicates the number of entries returned the buffer.

fi_profile_reg_callback

fi_profile_reg_callback registers a callback function to the event. The event should be in the event list obtained using the fi_profile_query_events, otherwise, an error code -FI_EINVAL will be returned.

Callback

It is used to receive notifications from a provider when an event occurs. A callback can also take optional parameters that allows a provider to push data to the user when an event occurss.

A callback is defined by the user and called by a provider as an additional operation, normally before or after data transfer operation. This will increase the overhead of the operation. Callback functions must avoid having blocking calls or taking non-trival time. And callback functions should limit interactions with a provider to reading the variables only if allowed.

The signature of the callback function is:

int (*callback)(struct fid_profile *prof_fid, struct fi_profile_desc *event,
                void *param, size_t size, void *context)
prof_fid
Reference to the profile object.
event
The description of event which the callback has been registered.
param
An optional parameter passed to the callback associated with the event. The data type and size of the param are defined in the event description.
size
The amount of the data pointed by param if param is not NULL.
context
The application context passed when the callback is registered.

fi_profile_read_u64

fi_profile_read_u64 is a wrapper function for FI_UINT64-type variables. It returns an uint64_t value of the specified variable. The variable should be in the variable list obtained using fi_profile_query_vars, otherwise, an error code -FI_EINVAL will be returned.

fi_profile_start_reads / fi_profile_end_reads

fi_profile_start_reads and fi_profile_end_reads calls are used when trying to read multiple variables at the same time. Variables read in between these two calls are expected to have values from a single snapshot.

NOTES

Users should call fi_profile_close to release all resources allocated for profiling in the provider.

RETURN VALUES

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. If the provider does not support profiling interface, a -FI_ENOSYS will be returned. For fi_profile_query_vars and fi_profile_query_events, a positive return value indicates the number of variables or events returned in the list.

Fabric errno values are defined in rdma/fi_errno.h.
