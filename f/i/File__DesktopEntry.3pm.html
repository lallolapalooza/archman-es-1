File::DesktopEntry(3) Documentación de Perl aportada por el usuario File::DesktopEntry(3)

NOMBRE

File::DesktopEntry - Objeto para manejar archivos .desktop

SINOPSIS

use File::DesktopEntry;
my $entry = File::DesktopEntry->new('firefox');
print "Usando ".$entry->Name." para abrir http://perl.org\n";
$entry->run('http://perl.org');

DESCRIPCIÓN

Este módulo está diseñado para trabajar con archivos .desktop . El formato de estos archivos está especificado por la especificación "Desktop Entry" de freedesktop. Este módulo puede analizar estos archivos pero también sabe cómo ejecutar las aplicaciones definidas por estos archivos.

Para esta versión del módulo se utilizó la versión 1.0 de la especificación.

Este módulo fue escrito para soportar File::MimeInfo::Applications.

Por favor recuerde: el uso de mayúsculas es significativo para los nombres de las claves de Desktop Entry.

VARIABLES

Puede establecer la variable global $File::DesktopEntry::VERBOSE. Si se establece, el módulo imprime una advertencia cada vez que se ejecuta un comando.

La variable global $File::DesktopEntry::LOCALE le indica cuál es el locale predeterminado que se está utilizando. Sin embargo, cambiarlo no cambiará el locale predeterminado.

AUTOLOAD

Todos los métodos que comienzan con una mayúscula se cargan automáticamente como get(KEY) donde key es el nombre del método cargado automáticamente.

MÉTODOS

new(FILE)
new(\$TEXT)
new(NAME)
Constructor. FILE, NAME o TEXT son argumentos opcionales.

Cuando se da un nombre (una cadena sin '"/"', '"\"' o '"."') se realiza una búsqueda usando File::BaseDir. Si el archivo encontrado en esta búsqueda no es escribible o si no se encontró ningún archivo, se usará la ruta XDG_DATA_HOME al escribir.

lookup(NAME)
Devuelve un nombre de archivo para una entrada de escritorio con el id de archivo de escritorio NAME.
wants_uris( )
Devuelve true si la cadena Exec de esta entrada de escritorio especifica que la aplicación usa URIs en lugar de rutas. Esto se puede usar para determinar si una aplicación usa una biblioteca VFS.
wants_list( )
Devuelve true si la cadena Exec de esta entrada de escritorio especifica que la aplicación puede manejar múltiples argumentos a la vez.
run(@FILES)
Hace un fork y ejecuta la aplicación especificada en esta Desktop Entry con los argumentos FILES como un proceso en segundo plano. Devuelve el pid.

El proceso hijo falla si esto no es una Desktop Entry de tipo Application o si la clave Exec falta o es inválida.

Si la entrada de escritorio especifica que el programa necesita ser ejecutado en una terminal, se usa la variable de entorno $TERMINAL . Si esta variable no está establecida "xterm -e" se usa como predeterminado.

(En Windows este método devuelve un objeto Win32::Process.)

system(@FILES)
Como run() pero usando la llamada al sistema system() . Solo retorna después de que la aplicación ha terminado.
exec(@FILES)
Como run() pero usando la llamada al sistema exec() . Se espera que este método no retorne sino que reemplace el proceso actual con la aplicación que intenta ejecutar.

En Windows este método no siempre funciona como usted quiere debido a la emulación de fork() en esta plataforma. Intente usar run() o system() en su lugar.

parse_Exec(@FILES)
Expande el formato Exec en esta entrada de escritorio. Devuelve una cadena correctamente entrecomillada en contexto escalar o una lista de palabras en contexto lista. Muere si la clave Exec es inválida.

Soporta los siguientes campos:

%f    archivo único
%F    múltiples archivos
%u    url única
%U    múltiples urls
%i    campo Icon prefijado por --icon
%c    campo Name, posiblemente traducido
%k    ubicación de este archivo .desktop
%%    '%' literal

Si es necesario, este método intenta convertir entre rutas y URLs, pero esto no es perfecto.

Campos que están obsoletos, pero (aún) soportados por este módulo:

%d    directorio único
%D    múltiples directorios

Los campos %n, %N, %v y %m están obsoletos y causarán una advertencia si se usa $VERBOSE . Cualquier otro campo desconocido causará un error.

Los campos %F, %U, %D y %i solo pueden ocurrir como palabras separadas porque se expanden a múltiples argumentos.

Vea también "LIMITACIONES".

get(KEY)
"get(GROUP, KEY)"
Obtiene un valor para KEY de GROUP. Si GROUP no se especifica se usa 'Desktop Entry'. Todos los valores se tratan como cadenas, así que por ejemplo los booleanos se devolverán como las cadenas literales "true" y "false".

Cuando KEY no contiene un código de idioma, obtiene la traducción en el locale actual si está disponible o un valor predeterminado razonable. Para solicitar un idioma específico puede añadir la parte del idioma. Por ejemplo "$entry->get('Name[nl_NL]')" puede devolver el valor de 'Name[nl_NL]', 'Name[nl]' o la clave 'Name' en el archivo Desktop Entry. El orden exacto de análisis del idioma se puede encontrar en la especificación. Para forzar que obtenga la clave sin traducir use 'Name[C]' o 'Name[POSIX]'.

"set(KEY => VALUE, ...)"
"set(GROUP, KEY => VALUE, ...)"
Establece valores para una o más claves. Si GROUP no se da se usa "Desktop Entry". Todos los valores se tratan como cadenas, las barras invertidas, saltos de línea y tabulaciones se escapan. Para establecer una clave booleana necesita usar las cadenas literales "true" y "false".

A diferencia de la llamada get() , los idiomas no se manejan automáticamente para set(). KEY debe incluir la parte del idioma si desea establecer una traducción. Por ejemplo "$entry->set("Name[nl_NL]" => "Tekst Verwerker")" establecerá una traducción neerlandesa para la clave Name. Usar "Name[C]" o "Name[POSIX]" será equivalente a no dar un argumento de idioma.

Al establecer la clave Exec sin especificar un grupo, se analizará y entrecomillará correctamente como lo requiere la especificación. Puede usar argumentos entrecomillados para incluir espacios en blanco en un argumento, escapar espacios en blanco no funciona. Para eludir esto, dé explícitamente el nombre del grupo 'Desktop Entry'.

text()
Devuelve el texto (modificado) del archivo.
read(FILE)
read(\$SCALAR)
Lee datos de Desktop Entry de un archivo o búfer de memoria. Sin argumento usa por defecto el archivo dado en el constructor.

Si dio un archivo, búfer de texto o nombre al constructor este método se llamará automáticamente.

read_fh(IO)
Lee datos de Desktop Entry de un filehandle u objeto IO.
write(FILE)
Escribe los datos de Desktop Entry en FILE. Sin argumentos escribe en el nombre de archivo dado al constructor si hay alguno.

Las claves Name y Type son requeridas. Type puede ser &quot;Application", "Link" o "Directory". Para una aplicación, establezca la clave opcional "Exec". Para un enlace, establezca la clave "URL" .

Compatibilidad con versiones anteriores

Métodos compatibles con versiones anteriores con la versión 0.02.

new_from_file(FILE)
Alias para new(FILE).
new_from_data(TEXT)
Alias para new(\$TEXT).
"get_value(NAME, GROUP, LANG)"
Idéntico a "get(GROUP, "NAME[LANG]")". LANG por defecto es 'C', GROUP es opcional.

PLATAFORMAS NO UNIX

Este módulo tiene algunas partes de código para hacerlo funcionar en Windows. Maneja las uri "file://" de forma un poco diferente y usa Win32::Process. En otras plataformas, los resultados pueden variar.

Tenga en cuenta que la especificación está dirigida solo a plataformas Unix y solo tendrá una relevancia limitada en otras plataformas. Cualquier comportamiento dependiente de la plataforma en este módulo debe considerarse una extensión de la especificación.

LIMITACIONES

Si intenta ejecutar un archivo remoto con una aplicación que solo puede manejar archivos en el sistema de archivos local, deberíamos -según la especificación- descargar el archivo a una ubicación temporal. Esto no está soportado. Utilice el wants_uris() método para verificar si una aplicación soporta urls.

Los valores de las diversas claves de Desktop Entry no se analizan (excepto para la clave Exec). Esto significa que los booleanos se devolverán como las cadenas "true" y "false" y las listas seguirán estando separadas por ";".

Si el icono se da como nombre y no como ruta, debería resolverse para el código %i en la clave Exec. Necesitamos un módulo separado para la especificación de iconos para tratar esto.

Según la especificación, los comentarios pueden contener cualquier codificación. Sin embargo, dado que este módulo lee archivos como utf8, los caracteres UTF-8 no válidos en un comentario causarán un error.

No hay soporte para Codificación Mixta Legada. Todo el mundo está usando utf8 ahora ... ¿verdad?
