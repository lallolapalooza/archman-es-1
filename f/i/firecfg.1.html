NOMBRE

Firecfg - Utilidad de integración de escritorio para el software Firejail.

SINOPSIS

firecfg [OPCIONES]

DESCRIPCIÓN

Firecfg es la utilidad de integración de escritorio para el sandbox de Firejail. Permite al usuario aislar aplicaciones automáticamente haciendo clic en los iconos y menús del gestor de escritorio.

La integración abarca:

- programas iniciados en una terminal - escribir "firefox" sería suficiente para iniciar un navegador Firefox aislado

- programas iniciados haciendo clic en los menús del gestor de escritorio - todos los principales gestores de escritorio son compatibles

- programas iniciados haciendo clic en los iconos de archivos en el gestor de archivos - solo los gestores de escritorio Cinnamon, KDE, LXDE/LXQT, MATE y XFCE son compatibles en este momento

Nota: Los ejemplos usan sudo, pero doas también es compatible.

Para configurarlo, ejecute "sudo firecfg" después de instalar el software Firejail. El mismo comando también debe ejecutarse después de instalar nuevos programas. Si el programa es compatible con Firejail, se creará el enlace simbólico en /usr/local/bin.

Para configurar la lista de programas utilizada por firecfg al crear enlaces simbólicos, consulte FICHEROS y SINTAXIS.

Para la integración manual controlada por el usuario, consulte la sección INTEGRACIÓN DE ESCRITORIO en man 1 firejail.

ACCIONES PREDETERMINADAS

Las siguientes acciones se implementan por defecto al ejecutar sudo firecfg:

- establece o actualiza los enlaces simbólicos para la integración de escritorio;

- añade el usuario actual a la base de datos de acceso de usuarios de Firejail (firecfg --add-users);

- corrige los archivos de escritorio en $HOME/.local/share/applications/ (firecfg --fix).
- carga y fuerza automáticamente el perfil AppArmor "firejail-default".

OPCIONES

--add-users usuario [usuario]
Añade la lista de usuarios a la base de datos de acceso de usuarios de Firejail.

Ejemplo:
$ sudo firecfg --add-users dustin lucas mike eleven

--bindir=directorio
Crea y busca enlaces simbólicos en el directorio en lugar de la ubicación predeterminada /usr/local/bin. El directorio debe preceder a /usr/bin y /bin en la variable de entorno PATH.
--clean
Elimina todos los enlaces simbólicos de firejail.
--fix
Corrige los archivos .desktop. Algunos archivos .desktop utilizan la ruta completa del ejecutable. Firecfg comprobará los archivos .desktop en /usr/share/applications/, reemplazará la ruta completa por el nombre si está en PATH, y escribirá el resultado en $HOME/.local/share/applications/. Esta acción se realiza por defecto al ejecutar "sudo firecfg". La tenemos como una opción separada para usuarios regulares.
--fix-sound
Crea un archivo ~/.config/pulse/client.conf adecuado sin soporte shm. En algunas versiones de PulseAudio, el soporte de memoria compartida (shm) rompe el espacio de nombres de ID de proceso. El software PulseAudio fue diseñado hace mucho tiempo, y la introducción del espacio de nombres PID en el kernel de Linux rompe su diseño. Esto se arregló según se informa en la versión 9 de PulseAudio. Si tiene problemas de sonido en su sistema, ejecute el comando "firecfg --fix-sound" en una terminal, seguido de un cierre/inicio de sesión para aplicar los cambios.
--guide
Configuración guiada para nuevos usuarios.

Ejemplo:
$ sudo firecfg --guide

--debug
Muestra mensajes de depuración.
-?, --help
Muestra las opciones y sale.
--list
Lista todos los enlaces simbólicos de firejail
--version
Muestra la versión del programa y sale.

Ejemplo:

$ sudo firecfg
/usr/local/bin/firefox creado
/usr/local/bin/vlc creado
[...]
$ firecfg --list
/usr/local/bin/firefox
/usr/local/bin/vlc
[...]
$ sudo firecfg --clean
/usr/local/bin/firefox eliminado
/usr/local/bin/vlc eliminado
[...]

SINTAXIS

Sintaxis del archivo de configuración:

Una línea que comienza con # se considera un comentario.
Una línea que comienza con !PROGRAMA significa ignorar "PROGRAMA" al crear enlaces simbólicos y al corregir archivos .desktop.
Una línea que comienza con cualquier otra cosa se considera el nombre de un ejecutable y firecfg intentará crear un enlace simbólico para él.

Por ejemplo, para evitar que firecfg cree enlaces simbólicos para "firefox" y "patch" mientras intenta crear un enlace simbólico para "myprog", las siguientes líneas podrían añadirse a /etc/firejail/firecfg.d/10-my.conf:

!firefox
!patch

myprog

Tenga en cuenta que ciertos programas pueden utilizar diferentes esquemas de nomenclatura para su archivo .desktop en comparación con el ejecutable principal. Para garantizar que ambos archivos se manejen de la misma manera, se recomienda listar ambos nombres en la configuración. Por ejemplo, si Spectacle tiene su ejecutable principal en /usr/bin/spectacle y su archivo .desktop en /usr/share/applications/org.kde.spectacle.desktop, entonces las siguientes líneas pueden utilizarse para ignorar ambos:

!org.kde.spectacle
!spectacle

FICHEROS

Los archivos de configuración se buscan y analizan en las siguientes rutas:

1. /etc/firejail/firecfg.d/*.conf (en orden alfabético)
2. /etc/firejail/firecfg.config

Los programas que son compatibles por defecto se listan en /etc/firejail/firecfg.config. Se recomienda dejarlo como está y colocar todas las personalizaciones dentro de /etc/firejail/firecfg.d/.

Los archivos de perfil también se buscan en el directorio de configuración del usuario:

3. ~/.config/firejail/*.profile

Por cada archivo PROGRAMA.profile encontrado, firecfg intenta crear un enlace simbólico para "PROGRAMA", como si "PROGRAMA" estuviera listado en un archivo de configuración.
