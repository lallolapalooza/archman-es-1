File::Which(3) Documentación de Perl contribuida por el usuario File::Which(3)

NOMBRE

File::Which - Implementación en Perl de la utilidad which como una API

VERSIÓN

versión 1.27

SINOPSIS

use File::Which;                  # exporta which()
use File::Which qw(which where);  # exporta which() y where()

my $ruta_ejecutable = which 'perldoc';

my @rutas = where 'perl';
# O
my @rutas = which 'perl'; # un array fuerza la búsqueda de todos

DESCRIPCIÓN

File::Which encuentra las rutas completas o relativas a programas ejecutables en el sistema. Esta es normalmente la función de la utilidad "which". "which" se implementa típicamente como un programa o un comando incorporado de la shell. En algunas plataformas, como Microsoft Windows, no se proporciona como parte del sistema operativo base. Este módulo proporciona una API consistente para esta funcionalidad sin importar la plataforma subyacente.

El enfoque de este módulo es la corrección y la portabilidad. Como consecuencia, las plataformas donde el directorio actual está implícitamente incluido en la ruta de búsqueda, como Microsoft Windows, encontrarán ejecutables en el directorio actual, mientras que en plataformas como UNIX donde no es así, los ejecutables en el directorio actual solo se encontrarán si el directorio actual se añade explícitamente a la ruta.

Si necesita una "which" portable en la línea de comandos en un entorno que no la proporciona, instale App::pwhich, que proporciona una interfaz de línea de comandos para esta API.

Implementaciones

File::Which busca en los directorios de la variable "PATH" del usuario (la implementación actual utiliza File::Spec#path para determinar el "PATH" correcto), buscando archivos ejecutables con el nombre especificado como parámetro para "which". En sistemas Win32, que no tienen una noción de archivos directamente ejecutables, pero utilizan extensiones especiales como ".exe" y ".bat" para identificarlos, "File::Which" toma medidas adicionales para asegurar que encontrará el archivo correcto (así, por ejemplo, si busca "perl", intentará perl.exe, perl.bat, etc.)

Linux, *BSD y otros UNIXes

No debería haber sorpresas aquí. El directorio actual no se buscará a menos que se añada explícitamente a la ruta.

Windows Moderno (incluyendo NT, XP, Vista, 7, 8, 10 etc.)

Windows NT tiene una variable de entorno especial llamada "PATHEXT", que es utilizada por la shell para buscar archivos ejecutables. Usualmente, contendrá una lista en formato ".EXE;.BAT;.COM;.JS;.VBS" etc. Si "File::Which" encuentra tal variable de entorno, analiza la lista y la utiliza como las diferentes extensiones.

Cygwin

Cygwin proporciona un entorno similar a Unix para usuarios de Microsoft Windows. En la mayoría de los aspectos funciona como otros entornos Unix y similares a Unix, pero en algunos aspectos clave funciona como Windows. Al igual que en otros entornos Unix, el directorio actual no se incluye en la búsqueda a menos que se incluya explícitamente en la ruta de búsqueda. Como en Windows, los archivos con extensiones ".EXE" o ".BAT" serán descubiertos incluso si no forman parte de la consulta. Sin embargo, las extensiones ".COM" o las especificadas usando la variable de entorno "PATHEXT" NO serán descubiertas sin el nombre completamente calificado.

Windows ME, 98, 95, MS-DOS, OS/2

Este conjunto de sistemas operativos no tiene la variable "PATHEXT", y usualmente encontrarás archivos ejecutables con las extensiones ".exe", ".bat" y (menos probable) ".com". "File::Which" utiliza esta lista codificada si se ejecuta bajo Win32 pero no encuentra una variable "PATHEXT".

A partir de 2015, ninguna de estas plataformas se prueba con frecuencia (o quizás nunca), pero el mantenedor actual está decidido a no eliminar intencionadamente el soporte para sistemas operativos antiguos.

VMS

Mismo caso que Windows 9x: usa ".exe" y ".com" (en ese orden).

A partir de 2015, el mantenedor actual no prueba en VMS, y de hecho no está seguro de que alguna vez se haya probado en VMS. Si esta plataforma es importante para usted y puede ayudarme a verificar y/o apoyarla en esa plataforma, por favor contácteme.

FUNCIONES

which

my $ruta = which $nombre_ejecutable_corto;
my @rutas = which $nombre_ejecutable_corto;

Exportado por defecto.

$nombre_ejecutable_corto es el nombre utilizado en la shell para llamar al programa (por ejemplo, "perl").

Si encuentra un ejecutable con el nombre que especificó, which() devolverá la ruta absoluta que lleva a ese ejecutable (por ejemplo, /usr/bin/perl o C:\Perl\Bin\perl.exe).

Si *no* encuentra el ejecutable, devuelve "undef".

Si se llama a which() en contexto de lista, devolverá *todas* las coincidencias.

where

my @rutas = where $nombre_ejecutable_corto;

No exportado por defecto.

Igual que "which" en contexto de array. Similar al comando incorporado de csh "where" o al comando "which -a" para plataformas que soportan la opción "-a". Devolverá un array que contiene todos los nombres de ruta que coincidan con $nombre_ejecutable_corto.

VARIABLES GLOBALES

$IMPLICIT_CURRENT_DIR

Verdadero si el directorio actual se incluye implícitamente en la búsqueda en la plataforma que esté utilizando. Normalmente el valor por defecto es razonable, pero en Windows el directorio actual se incluye implícitamente para shells más antiguas como "cmd.exe" y "command.com", pero no para shells más nuevas como PowerShell. Si anula este valor por defecto, SIEMPRE debe localizar la variable al ámbito más pequeño posible, ya que establecer esta variable desde un módulo puede afectar a otros módulos. Por lo tanto, en Windows puede obtener el resultado correcto si el usuario está ejecutando "cmd.exe" o PowerShell; en Windows puede hacer esto:

use File::Which qw( which );
use Shell::Guess;

my $ruta = do {
  my $es_power = Shell::Guess->running_shell->is_power;
  local $File::Which::IMPLICIT_CURRENT_DIR = !$es_power;
  which 'foo';
};

Por una variedad de razones, es difícil calcular con precisión la shell que está utilizando un usuario, pero Shell::Guess hace un esfuerzo razonable.

ADVERTENCIAS

Este módulo no tiene requisitos no esenciales para Perl 5.6.2 y superiores.

Este módulo es totalmente compatible con Perl 5.8.1. Puede que funcione en 5.8.0. Debería funcionar en Perl 5.6.x e incluso puedo probarlo en 5.6.2. Aceptaré parches para mantener la compatibilidad con Perl más antiguo, pero es posible que necesite arreglarlo en 5.6.x / 5.8.0 y enviarme un parche.

No probado en VMS, aunque hay código específico de plataforma para ello. Cualquiera que tenga un momento libre sería muy amable en enviarme un informe de cómo fue.

VÉASE TAMBIÉN
pwhich, App::pwhich
Interfaz de línea de comandos para este módulo.
IPC::Cmd
Requiere Perl 5.8.3. Incluido como parte del núcleo de Perl desde la versión 5.9.5.

Este módulo proporciona (entre otras cosas) una "can_run" función, que es similar a "which". Es un módulo mucho más pesado ya que hace mucho más, y si usas "can_run" carga ExtUtils::MakeMaker. Esta combinación puede ser excesiva para aplicaciones que no necesitan la interfaz complicada de IPC::Cmd para ejecutar programas, o que no necesitan la sobrecarga de memoria requerida para instalar módulos de Perl.

Al menos algunas versiones antiguas encontrarán ejecutables en el directorio actual, incluso si el directorio actual no está en la ruta de búsqueda (que es el valor predeterminado en Unix moderno).

"can_run" convierte el nombre de la ruta del directorio a la versión 8.3 en Windows usando "Win32::GetShortPathName" en algunos casos. Esto es frecuentemente útil para herramientas que solo necesitan ejecutar algo usando "system" en modo escalar, pero puede ser inconveniente para herramientas como App::pwhere donde la legibilidad para el usuario es fundamental. Confiar en "Win32::GetShortPathName" para producir nombres de archivo sin espacios es problemático, ya que los nombres de archivo 8.3 pueden desactivarse con ajustes en el registro (ver https://technet.microsoft.com/en-us/library/cc959352.aspx).

Devel::CheckBin
Requiere Perl 5.8.1.

Este módulo pretende "verificar que un comando está disponible", pero no proporciona ninguna documentación sobre cómo podrías usarlo.

Este módulo también depende de ExtUtils::MakeMaker, por lo que tiene las mismas cargas de sobrecarga que IPC::Cmd.
