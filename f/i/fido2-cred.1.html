NOMBRE

fido2-cred — crear/verificar una credencial FIDO2

SINOPSIS

fido2-cred -M [-bdhqruvw] [-a mode] [-c cred_protect] [-i input_file] [-o output_file] device [type]

fido2-cred -V [-dhv] [-c cred_protect] [-i input_file] [-o output_file] [type]

DESCRIPCIÓN

fido2-cred crea o verifica una credencial FIDO2.

Un tipo de credencial type puede ser es256 (denotando ECDSA sobre NIST P-256 con SHA-256), es384 (denotando ECDSA sobre NIST P-384 con SHA-384), rs256 (denotando RSA de 2048 bits con relleno PKCS#1.5 y SHA-256), o eddsa (denotando EDDSA sobre Curve25519 con SHA-512). Si type no se especifica, es256 se asume.

Al crear una credencial, el autenticador puede requerir que el usuario se autentique con un PIN. Si la opción -q no se especifica, fido2-cred solicitará al usuario el PIN. Si hay un tty disponible, fido2-cred lo usará para obtener el PIN. De lo contrario, stdin se usa.

La entrada de fido2-cred está definida por los parámetros de la credencial a crear/verificar. Consulte la sección FORMATO DE ENTRADA para más detalles.

La salida de fido2-cred está definida por el resultado de la operación seleccionada. Consulte la sección FORMATO DE SALIDA para más detalles.

Si una credencial se crea o verifica con éxito, fido2-cred termina con código 0. De lo contrario, fido2-cred termina con código 1.

Las opciones son las siguientes:

-M
Indica a fido2-cred que cree una nueva credencial en device.
-V
Indica a fido2-cred que verifique una credencial.
-b
Solicita el “largeBlobKey” de la credencial, una clave simétrica de 32 bytes asociada con la credencial generada.
-a mode
Al crear una credencial, solicita la atestación empresarial. Por favor, consulte <fido/param.h> para el conjunto de valores posibles.
-c cred_protect
Si se está creando una credencial, establece el nivel de protección de la credencial en cred_protect, donde cred_protect es el nivel de protección de la credencial en notación decimal. Por favor, consulte <fido/param.h> para el conjunto de valores posibles. Si se está verificando una credencial, comprueba si el nivel de protección de la credencial fue firmado por el autenticador como cred_protect.
-d
Hace que fido2-cred emita salida de depuración en stderr.
-h
Si se está creando una credencial, habilita la extensión hmac-secret de FIDO2. Si se está verificando una credencial, comprueba si el bit de datos de la extensión fue firmado por el autenticador.
-i input_file
Indica a fido2-cred que lea los parámetros de la credencial desde input_file en lugar de stdin.
-o output_file
Indica a fido2-cred que escriba la salida en output_file en lugar de stdout.
-q
Indica a fido2-cred que sea silencioso. Si se requiere un PIN y se especifica -q , fido2-cred fallará.
-r
Crea una credencial residente. Las credenciales residentes se denominan “credenciales descubribles” en CTAP 2.1.
-u
Crea una credencial U2F. Por defecto, fido2-cred usará FIDO2 si es soportado por el autenticador, y recurrirá a U2F de lo contrario.
-v
Si se está creando una credencial, solicita la verificación del usuario. Si se está verificando una credencial, comprueba si el bit de verificación del usuario fue firmado por el autenticador.
-w
Indica a fido2-cred que la primera línea de entrada al crear una credencial debe interpretarse como datos del cliente sin hashear. Esto es requerido por Windows Hello, que calcula el hash de los datos del cliente internamente.

FORMATO DE ENTRADA

La entrada de fido2-cred consiste en bloques base64 y cadenas UTF-8 separadas por caracteres de salto de línea ('\n').

Al crear una credencial, fido2-cred espera que su entrada consista en:

  1. hash de datos del cliente (bloque base64);
  2. id de la parte dependiente (cadena UTF-8);
  3. nombre de usuario (cadena UTF-8);
  4. id de usuario (bloque base64).

Al verificar una credencial, fido2-cred espera que su entrada consista en:

  1. hash de datos del cliente (bloque base64);
  2. id de la parte dependiente (cadena UTF-8);
  3. formato de la credencial (cadena UTF-8);
  4. datos del autenticador codificados en CBOR (bloque base64);
  5. id de la credencial (bloque base64);
  6. firma de atestación (bloque base64);
  7. certificado de atestación (opcional, bloque base64).

Las cadenas UTF-8 pasadas a fido2-cred no deben contener caracteres de salto de línea o NUL incrustados.

FORMATO DE SALIDA

La salida de fido2-cred consiste en bloques base64, cadenas UTF-8 y claves públicas codificadas en PEM separadas por caracteres de salto de línea ('\n').

Tras la generación exitosa de una credencial, fido2-cred produce:

  1. hash de datos del cliente (bloque base64);
  2. id de la parte dependiente (cadena UTF-8);
  3. formato de la credencial (cadena UTF-8);
  4. datos del autenticador codificados en CBOR (bloque base64);
  5. id de la credencial (bloque base64);
  6. firma de atestación (bloque base64);
  7. certificado de atestación, si está presente (bloque base64).
  8. la clave simétrica de 32 bytes asociada con la credencial (“largeBlobKey”), si está presente (bloque base64).

Tras la verificación exitosa de una credencial, fido2-cred produce:

  1. id de la credencial (bloque base64);
  2. clave de la credencial codificada en PEM.

EJEMPLOS

Crear una nueva credencial es256 en /dev/hidraw5, verificarla y guardar el id fido2-cred(1) — Arch Linux Manual Pages

NAME

fido2-cred — Create a FIDO2 credential on an authenticator

SYNOPSIS

fido2-cred [-h] [-v] [-m] [-t] [-i input] [-o output] [device]

DESCRIPTION

This utility is used to create a new FIDO2 credential on an authenticator. It can be used to create a new credential for a specific user, or to create a new credential for a specific relying party. The authenticator will return a public key credential that can be used to assert the user's identity.

OPTIONS

Supported options:

-h
Print a help message and exit.
-v
Print verbose output to stderr.
-m
Use make credential. This is the default behavior.
-t
Use transport (hid, nfc, ble).
-i input
Read input from the specified file. The input file can contain the following fields, separated by newlines:
  • The challenge (a string that should be randomly generated).
  • The relying party ID (a domain name).
  • The user name.
  • An optional user ID (a string that should be randomly generated).
-o output
Write the output to the specified file. The output file will contain the public key credential.

INPUT FORMAT

The input to fido2-cred is a sequence of strings, one per line, representing the challenge, the relying party ID, the user name, and optionally a user ID. The challenge and user ID should be randomly generated strings.

OUTPUT FORMAT

The output of fido2-cred is a JSON object containing the public key credential. The public key credential can be used to assert the user's identity to the relying party.

EXAMPLES

To create a new FIDO2 credential for a user named "user name" on a relying party named "relying party", and save the public key of the credential in cred_param:

$ echo credential challenge | openssl sha256 -binary | base64 > cred_param
$ echo relying party >> cred_param
$ echo user name >> cred_param
$ dd if=/dev/urandom bs=1 count=32 | base64 >> cred_param
$ fido2-cred -M -i cred_param /dev/hidraw5 | fido2-cred -V -o cred

SEE ALSO

fido2-assert(1), fido2-token(1)

CAVEATS

Please note that fido2-cred handles Basic Attestation and Self Attestation transparently. In the case of Basic Attestation, the validity of the authenticator's attestation certificate is not verified.
