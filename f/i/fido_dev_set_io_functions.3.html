fido_dev_set_io_functions(3)

Paquete: libfido2

Licencias: BSD-2-Clause

FIDO_DEV_SET_IO_FUNCTIONS(3) Manual de funciones de biblioteca FIDO_DEV_SET_IO_FUNCTIONS(3)

NAME

fido_dev_set_io_functions, fido_dev_set_sigmask, fido_dev_set_timeout, fido_dev_set_transport_functions, fido_dev_io_handle — Interfaz de entrada/salida (I/O) de dispositivos FIDO2

SYNOPSIS

#include <fido.h>

typedef void *fido_dev_io_open_t(const char *);
typedef void  fido_dev_io_close_t(void *);
typedef int   fido_dev_io_read_t(void *, unsigned char *, size_t, int);
typedef int   fido_dev_io_write_t(void *, const unsigned char *, size_t);

typedef struct fido_dev_io {
	fido_dev_io_open_t  *open;
	fido_dev_io_close_t *close;
	fido_dev_io_read_t  *read;
	fido_dev_io_write_t *write;
} fido_dev_io_t;

#ifdef _WIN32
typedef int fido_sigset_t;
#else
typedef sigset_t fido_sigset_t;
#endif

typedef int   fido_dev_rx_t(struct fido_dev *,
                  uint8_t, unsigned char *, size_t, int);
typedef int   fido_dev_tx_t(struct fido_dev *,
                  uint8_t, const unsigned char *, size_t);

typedef struct fido_dev_transport {
	fido_dev_rx_t *rx;
	fido_dev_tx_t *tx;
} fido_dev_transport_t;


int
fido_dev_set_io_functions(fido_dev_t *dev, const fido_dev_io_t *io);

int
fido_dev_set_sigmask(fido_dev_t *dev, const fido_sigset_t *sigmask);

int
fido_dev_set_timeout(fido_dev_t *dev, int ms);

int
fido_dev_set_transport_functions(fido_dev_t *dev, const fido_dev_transport_t *t);

void *
fido_dev_io_handle(const fido_dev_t *dev);

DESCRIPTION

La fido_dev_set_io_functions() función establece los manejadores de I/O utilizados por libfido2 para comunicarse con dev. Por defecto, estos manejadores se establecen en las interfaces HID o NFC nativas del sistema operativo. Se definen como sigue:

fido_dev_open_t
Recibe un const char * que contiene una ruta y abre el dispositivo correspondiente, devolviendo un puntero opaco no nulo en caso de éxito y NULL en caso de error.
fido_dev_close_t
Recibe el puntero opaco devuelto por fido_dev_open_t y cierra el dispositivo.
fido_dev_read_t
Lee una unidad de transmisión única (informe HID, APDU) desde un dispositivo. El primer parámetro es el puntero opaco devuelto por fido_dev_open_t. El segundo parámetro es el búfer de lectura, y el tercer parámetro es el tamaño del búfer de lectura. El cuarto parámetro es el número de milisegundos en los que el llamador está dispuesto a dormir, si la llamada necesita bloquearse. Si este valor es -1, fido_dev_read_t puede bloquearse indefinidamente. En caso de éxito, se devuelve el número de bytes leídos. En caso de error, se devuelve -1.
fido_dev_write_t
Escribe una unidad de transmisión única (informe HID, APDU) en dev. El primer parámetro es el puntero opaco devuelto por fido_dev_open_t. El segundo parámetro es el búfer de escritura, y el tercer parámetro es el número de bytes a escribir. Un fido_dev_write_t puede bloquearse. En caso de éxito, se devuelve el número de bytes escritos. En caso de error, se devuelve -1.

Al llamar a fido_dev_set_io_functions(), los campos open, close, read y write de io no pueden ser NULL.

No se mantienen referencias a io por parte de fido_dev_set_io_functions().

La fido_dev_set_sigmask() función puede utilizarse para especificar una máscara de señales no nula sigmask a utilizar mientras libfido2's maneja I/O predeterminado espera en dev. En sistemas operativos similares a UNIX, fido_sigset_t se define como sigset_t. En Windows, fido_sigset_t se define como int y fido_dev_set_sigmask() es una operación nula.

No se mantienen referencias a sigmask por parte de fido_dev_set_sigmask().

La fido_dev_set_timeout() función informa a libfido2 de que no debe bloquearse por más de ms milisegundos mientras se comunica con dev. Si se produce un tiempo de espera, la función correspondante fido_dev_* fallará con FIDO_ERR_RX. Si ms es -1, entonces libfido2 puede bloquearse indefinidamente. Este es el comportamiento por defecto. Al utilizar el backend Windows Hello, ms se utiliza como guía y puede ser sobrescrito por la plataforma.

La fido_dev_set_transport_functions() función establece las funciones de transporte utilizadas por libfido2 para comunicarse con dev. Mientras que los manejadores de I/O son responsables de enviar y recibir unidades de transmisión de paquetes de inicialización y continuación ya formateados por libfido2, los manejadores de transporte son responsables de enviar y recibir los comandos y datos CTAPHID directamente, como se define en el estándar FIDO Client to Authenticator Protocol (CTAP). Se definen como sigue:

fido_dev_tx_t
Recibe un dispositivo, un comando CTAPHID a transmitir, un búfer de datos a transmitir y la longitud del búfer de datos. En caso de éxito, se devuelve 0. En caso de error, se devuelve -1.
fido_dev_rx_t
Recibe un dispositivo, un comando CTAPHID cuya respuesta espera el llamador, un búfer de datos para recibir en, el tamaño del búfer de datos que determina la longitud máxima de una respuesta, y el número máximo de milisegundos para esperar una respuesta. En caso de éxito, se devuelve el número de bytes leídos en el búfer de datos. En caso de error, se devuelve -1.

Cuando se especifican funciones de transporte, libfido2 utilizará estas en lugar de las funciones read y write de los manejadores de I/O. Sin embargo, los manejadores de I/O deben especificarse aún para abrir y cerrar el dispositivo.

La fido_dev_io_handle() función devuelve el puntero opaco devuelto por la función open de los manejadores de I/O. Esto es útil principalmente para las funciones de transporte, que, a diferencia de los manejadores de I/O, reciben el puntero fido_dev_t en lugar del puntero opaco de manejo de I/O.

VALORES DE DEVOLUCIÓN

En caso de éxito, fido_dev_set_io_functions(), fido_dev_set_transport_functions(), fido_dev_set_sigmask() y fido_dev_set_timeout() devuelven FIDO_OK. En caso de error, se devuelve un código de error diferente definido en <fido/err.h>.
