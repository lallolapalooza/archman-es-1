int ioctl(int src_fd, FIDEDUPERANGE, struct file_dedupe_range *arg)

DESCRIPCIÓ

N

Si un sistema de archivos admite que los archivos compartan almacenamiento físico entre múltiples archivos, esta operación ioctl(2) puede usarse para hacer que algunos de los datos del archivo src_fd aparezcan en el archivo dest_fd compartiendo el almacenamiento subyacente si los datos del archivo son idénticos ("deduplicación"). Ambos archivos deben residir en el mismo sistema de archivos. Esto reduce el consumo de almacenamiento al permitir que el sistema de archivos almacene una única copia compartida de los datos. Si se produce una escritura en una región compartida, el sistema de archivos debe garantizar que los cambios permanezcan privados para el archivo que se está escribiendo. Este comportamiento se conoce comúnmente como "copia en escritura" (copy on write)

.

Esta ioctl realiza la operación "comparar e compartir si es idéntico" en hasta src_length bytes del descriptor de archivo src_fd en el desplazamiento src_offset. Esta información se transmite en una estructura de la siguiente

forma: 


struct file_dedupe_range {
    __u64 src_offset;
    __u64 src_length;
    __u16 dest_count;
    __u16 reserved1;
    __u32 reserved2;
    struct file_dedupe_range_info info[0];
}
;

La deduplicación es atómica con respecto a las escrituras concurrentes, por lo que no es necesario tomar bloqueos para obtener una copia deduplicada

consistente.

Los campos reserved1 y reserved2 deben ser

cero.

Los destinos de la operación de deduplicación se transmiten en el array al final de la estructura. El número de destinos se indica en dest_count, y la información del destino se transmite en la siguiente

forma: 


struct file_dedupe_range_info {
    __s64 dest_fd;
    __u64 dest_offset;
    __u64 bytes_deduped;
    __s32 status;
    __u32 reserved;
}
;

Cada operación de deduplicación tiene como objetivo src_length bytes en el descriptor de archivo dest_fd en el desplazamiento dest_offset. El campo reserved debe ser cero. Durante la llamada, src_fd debe estar abierto para lectura y dest_fd debe estar abierto para escritura. El tamaño combinado de la struct file_dedupe_range y el array de struct file_dedupe_range_info no debe exceder el tamaño de página del sistema. El tamaño máximo de src_length depende del sistema de archivos y es típicamente 16 MiB. Este límite será aplicado silenciosamente por el sistema de archivos. Por convención, el almacenamiento usado por src_fd se mapea en dest_fd y los contenidos anteriores en dest_fd se

liberan.

Al completarse con éxito esta ioctl, el número de bytes deduplicados con éxito se devuelve en bytes_deduped y un código de estado para la operación de deduplicación se devuelve en status. Si siquiera un solo byte en el rango no coincide, la solicitud de la operación de deduplicación será ignorada y status se establecerá en FILE_DEDUPE_RANGE_DIFFERS. El código de estado se establece en FILE_DEDUPE_RANGE_SAME para éxito, un código de error negativo en caso de error, o FILE_DEDUPE_RANGE_DIFFERS

si los datos n
o coincidieron.

ERRORE

S

Los errores posibles incluyen (pero no se limitan a) los

siguientes:
EBA
DF
src_fd no está abierto para lectura; dest_fd no está abierto para escritura o está abierto solo para escrituras de anexión; o el sistema de archivos en el que reside src_fd no admite
deduplicación.
EINV
AL
El sistema de archivos no admite deduplicar los rangos de los archivos dados. Este error también puede aparecer si cualquiera de los descriptores de archivo representa un dispositivo, FIFO o socket. Los sistemas de archivos de disco generalmente requieren que los argumentos de desplazamiento y longitud estén alineados al tamaño de bloque fundamental. Ni Btrfs ni XFS admiten rangos de deduplicación superpuestos en el mismo
archivo.

IR
Uno de los archivos es un directorio y el sistema de archivos no admite regiones compartidas en
directorios.
ENOM

memoria.
