NOMBRE

File::RsyncP::Digest - Interfaz de Perl para algoritmos de resumen de rsync

SINOPSIS

use File::RsyncP::Digest;

$rsDigest = new File::RsyncP::Digest;
# especificar versión del protocolo rsync (por defecto <= 26 -> resúmenes con errores).
$rsDigest->protocol(version);

# resúmenes MD4 de archivo
$rsDigest->reset();
$rsDigest->add(LISTA);
$rsDigest->addfile(MANEJADOR);
$digest = $rsDigest->digest();
$string = $rsDigest->hexdigest();
# Devuelve un par de resúmenes de 32 bytes (protocolo <= 26 y >= 27).
$digestPair = $rsDigest->digest2();
$digest = File::RsyncP::Digest->hash(ESCALAR);
$string = File::RsyncP::Digest->hexhash(ESCALAR);

# resúmenes de bloque
$digests = $rsDigest->blockDigest($data, $blockSize, $md4DigestLen,
                                  $checksumSeed);
$digests = $rsDigest->blockDigestUpdate($state, $blockSize,
                            $blockLastLen, $md4DigestLen, $checksumSeed);
$digests2 = $rsDigest->blockDigestExtract($digests16, $md4DigestLen);

DESCRIPCIÓN

El módulo File::RsyncP::Digest te permite calcular resúmenes de rsync, incluyendo el algoritmo de Resumen de Mensajes MD4 de RSA Data Security Inc., y sumas de verificación Adler32 desde programas Perl.

Resúmenes de Rsync

Rsync utiliza dos resúmenes principales (o sumas de verificación), para comprobar con muy alta probabilidad que los datos subyacentes son idénticos, sin necesidad de intercambiar los datos subyacentes.

El lado del servidor (remoto) de rsync genera una semilla de suma de verificación (generalmente el time() de Unix) que se intercambia durante el inicio del protocolo. Esta semilla se utiliza tanto en los cálculos de suma de verificación de archivos como de MD4. Esto hace que las sumas de verificación de bloques y archivos cambien cada vez que se ejecuta Rsync.

Resumen de archivo
Este es un resumen MD4 de la semilla de suma de verificación, seguido del contenido completo del archivo. Este resumen tiene una longitud de 128 bits. El resumen del archivo se envía al final de los deltas de un archivo para asegurar que el archivo reconstruido sea correcto. Este resumen también se calcula opcionalmente y se envía como parte de la lista de archivos si se especifica la opción --checksum a rsync.
Resumen de bloque
Cada archivo se divide en bloques de longitud predeterminada de 700 bytes. El resumen de cada bloque se forma calculando la suma de verificación Adler32 del bloque, y también el resumen MD4 del bloque seguido de la semilla de suma de verificación. Durante la fase 1, solo se envían los dos primeros bytes del resumen MD4, lo que significa que el resumen total es de 6 bytes o 48 bits (4 bytes para Adler32 y los primeros 2 bytes del resumen MD4). Durante la fase 2 (que es necesaria para los archivos recibidos que tienen un resumen de archivo incorrecto), se utiliza el resumen MD4 completo (128 bits), lo que significa que el resumen de bloque es de 20 bytes o 160 bits. (Antes del protocolo rsync XXX, se enviaba el resumen completo de 20 bytes cada vez y solo había una fase).

Este módulo contiene rutinas para calcular resúmenes de archivos y bloques de una manera idéntica a rsync.

Por cierto, rsync contiene dos errores en su implementación de MD4 (hasta e incluyendo la versión 26 del protocolo rsync):

  • No se llama a MD4Final() cuando el tamaño de los datos (es decir, el tamaño del archivo o bloque más 4 bytes para la semilla de suma de verificación) es un múltiplo de 64.
  • MD4 no es correcto para tamaños de datos totales superiores a 512 MB (2^32 bits). El MD4 de Rsync solo mantiene el tamaño de los datos utilizando un contador de 32 bits, por lo que se desborda para tamaños de archivo superiores a 512 MB.

Los efectos de estos errores son benignos: el resumen MD4 no debería debilitarse criptográficamente y ambos lados son consistentes.

Este módulo implementa ambas versiones del resumen MD4: la versión con errores para versiones de protocolo <= 26 y la versión correcta para versiones de protocolo >= 27. El modo predeterminado es la versión con errores (versiones de protocolo <= 26).

Puede especificar la versión del protocolo rsync para determinar qué versión de MD4 se utiliza:

# especificar versión del protocolo rsync (por defecto <= 26 -> resúmenes con errores).
$rsDigest->protocol(version);

Además, puede obtener ambos resúmenes en una sola llamada. El resultado se devuelve como un único escalar de 32 bytes: los primeros 16 bytes son el resumen con errores y los segundos 16 bytes son el resumen correcto:

# Devuelve un par de resúmenes de 32 bytes (protocolo <= 26 y >= 27).
$digestPair = $rsDigest->digest2();

Uso

Se crea un nuevo objeto de contexto de resumen rsync con la operación new. Se pueden mantener múltiples contextos de resumen simultáneos, si se desea.

Cálculo de Resúmenes de Bloque

Después de crear un contexto, la función para calcular sumas de verificación de bloques es:

$digests = $rsDigest->blockDigest($data, $blockSize, $md4DigestLen,
                                  $checksumSeed)

El primer argumento son los datos, que pueden contener tantos datos sin procesar como desee (es decir, múltiples bloques). Tanto la suma de verificación Adler32 como el resumen MD4 se calculan para cada bloque en los datos. El bloque final parcial (si está presente) también se procesa. Los 4 bytes de la semilla de suma de verificación entera se agregan al final de cada cálculo de resumen de bloque si no es cero. El blockSize se especifica en el segundo argumento (predeterminado es 700). El tercer argumento, md4DigestLen, especifica cuántos bytes del resumen MD4 se incluyen en los datos devueltos. Rsync utiliza un valor de 2 para el primer paso (lo que significa que se devuelven 6 bytes de resúmenes totales por bloque), y los 16 bytes completos para el segundo paso (lo que significa que se devuelven 20 bytes de resúmenes totales por bloque). El número de bytes devueltos es el número de bytes en cada resumen (Alder32 + MD4 parcial/completo) por el número de bloques:

(4 + md4DigestLen) * ceil(length(data) / blockSize);

Para permitir el almacenamiento en caché de las sumas de verificación de bloques (cuando checksumSeed es desconocido), y luego actualizarlas rápidamente con la checksumSeed conocida, los datos de suma de verificación deben calcularse primero con una longitud de resumen de -1 y una checksumSeed de 0:

$state = $rsDigest->blockDigest($data, $blockSize, -1, 0);

El $state devuelto debe guardarse para su posterior recuperación, junto con la longitud del último bloque parcial (por ejemplo, length($data) % $blockSize). La longitud de $state depende del número de bloques y del tamaño del bloque. Además de los 16 bytes del estado MD4, hasta 63 bytes de datos no procesados por bloque también se guardan en $state. Para cada bloque,

16 + ($blockSize % 64)

se guardan bytes en $state, por lo que $state es más compacto cuando $blockSize es un múltiplo de 64. (El último bloque parcial podría tener un tamaño de bloque menor, requiriendo hasta 63 bytes de estado incluso si $blockSize es un múltiplo de 64).

Una vez que se conoce la checksumSeed, las sumas de verificación actualizadas se pueden calcular usando:

$digests = $rsDigest->blockDigestUpdate($state, $blockSize,
                            $blockLastLen, $md4DigestLen, $checksumSeed);

El primer argumento son las sumas de verificación almacenadas en caché de blockDigest. El tercer argumento es la longitud del último bloque (parcial).

Alternativamente, espero agregar una opción --checksum-seed=n a rsync que permita que la semilla de suma de verificación se establezca en 0. Esto hace que la semilla de suma de verificación se omita del cálculo MD4 y facilita mucho el almacenamiento en caché de las sumas de verificación. Una semilla de suma de verificación cero no debilita el resumen de bloque. No estoy seguro de si debilita o no el resumen de archivo (la semilla de suma de verificación se aplica al principio del resumen de archivo y al final del resumen de bloque). En este caso, los resúmenes completos de 16 bytes se calcularían usando:

$digests16 = $rsDigest->blockDigest($data, $blockSize, 16, 0);

y para la fase 1, las subcadenas MD4 de 2 bytes se pueden extraer con:

$digests2  = $rsDigest->blockDigestExtract($digests16, 2);

El $digests16 original no necesita ningún procesamiento adicional para la fase 2.
