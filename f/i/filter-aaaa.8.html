NOMBRE

filter-aaaa - filtra AAAA en respuestas DNS cuando A está presente

SINOPSIS

plugin query "filter-aaaa.so" [{ parámetros }];

DESCRIPCIÓN

filter-aaaa.so es un módulo de plugin de consulta para named <#std-iscman-named>, que permite a named <#std-iscman-named> omitir algunas direcciones IPv6 al responder a clientes.

Hasta BIND 9.12, esta funcionalidad se implementaba de forma nativa en named <#std-iscman-named> y se habilitaba con la ACL filter-aaaa y las opciones filter-aaaa-on-v4 y filter-aaaa-on-v6. Estas opciones ya no están disponibles en named.conf <#std-iscman-named.conf>, pero se pueden pasar como parámetros al plugin filter-aaaa.so, por ejemplo:

plugin query "filter-aaaa.so" {
        filter-aaaa-on-v4 yes;
        filter-aaaa-on-v6 yes;
        filter-aaaa { 192.0.2.1; 2001:db8:2::1; };
};

Este módulo está diseñado para ayudar en la transición de IPv4 a IPv6 al retener las direcciones IPv6 de los clientes DNS que no están conectados a Internet IPv6, cuando el nombre consultado tiene una dirección IPv4 disponible. No se recomienda el uso de este módulo a menos que sea absolutamente necesario.

Nota: Este mecanismo puede hacer erróneamente que otros servidores no proporcionen registros AAAA a sus clientes. Si un servidor recursivo con conexiones de red IPv6 e IPv4 consulta a un servidor autoritativo que utiliza este mecanismo a través de IPv4, se le niegan los registros AAAA incluso si su cliente está utilizando IPv6.

OPCIONES

filter-aaaa
Esta opción especifica una lista de direcciones de clientes para las que se aplicará el filtrado de AAAA. El valor predeterminado es any.
filter-aaaa-on-v4
Si se establece en yes, esta opción indica que el cliente DNS está en una dirección IPv4, en filter-aaaa. Si la respuesta no incluye firmas DNSSEC, todos los registros AAAA se eliminan de la respuesta. Este filtrado se aplica a todas las respuestas, no solo a las autoritativas.

Si se establece en break-dnssec, los registros AAAA se eliminan incluso cuando DNSSEC está habilitado. Como sugiere el nombre, esto hace que la respuesta falle la verificación, ya que el protocolo DNSSEC está diseñado para detectar eliminaciones.

Este mecanismo puede hacer erróneamente que otros servidores no proporcionen registros AAAA a sus clientes. Si un servidor recursivo con conexiones de red IPv6 e IPv4 consulta a un servidor autoritativo que utiliza este mecanismo a través de IPv4, se le niegan los registros AAAA incluso si su cliente está utilizando IPv6.

filter-aaaa-on-v6
Esta opción es idéntica a filter-aaaa-on-v4, excepto que filtra las respuestas AAAA a consultas de clientes IPv6 en lugar de clientes IPv4. Para filtrar todas las respuestas, establezca ambas opciones en yes.
