DESCRIPCIÓ

N

Las transferencias atómicas se usan para leer y actualizar datos ubicados en regiones de memoria remotas de manera atómica. Conceptualmente, son similares a las operaciones atómicas locales de naturaleza similar (por ejemplo, incremento atómico, intercambio condicional, etc.). Las actualizaciones a datos remotos implican una de varias operaciones sobre los datos, y actúan sobre tipos específicos de datos, como se lista a continuación. Como tal, las transferencias atómicas tienen conocimiento del formato de los datos siendo accedidos. Una sola función atómica puede operar a través de un arreglo de datos aplicando una operación atómica a cada entrada, pero la atomicidad de una operación está limitada a un solo tipo de dato o

entrada.

Operaciones Atómicas

Se definen las siguientes operaciones atómicas. Una operación atómica a menudo actúa contra un valor objetivo en el búfer de memoria remota y un valor fuente proporcionado con la función atómica. También puede transportar datos fuente para reemplazar el valor objetivo en operaciones de intercambio condicional (compare and swap). Se proporciona una descripción conceptual de cada operación.

FI_MIN
Mínimo
if (buf[i] < addr[i])
    addr[i] = buf[i]
FI_MAX
Máximo
if (buf[i] > addr[i])
    addr[i] = buf[i]
FI_SUM
Suma
addr[i] = addr[i] + buf[i]
FI_PROD
Producto
addr[i] = addr[i] * buf[i]
FI_LOR
OR lógico
addr[i] = (addr[i] || buf[i])
FI_LAND
AND lógico
addr[i] = (addr[i] && buf[i])
FI_BOR
OR a nivel de bits
addr[i] = addr[i] | buf[i]
FI_BAND
AND a nivel de bits
addr[i] = addr[i] & buf[i]
FI_LXOR
XOR lógico (exclusivo lógico)
addr[i] = ((addr[i] && !buf[i]) || (!addr[i] && buf[i]))
FI_BXOR
XOR a nivel de bits (exclusivo a nivel de bits)
addr[i] = addr[i] ^ buf[i]
FI_ATOMIC_READ
Leer datos de forma atómica
result[i] = addr[i]
FI_ATOMIC_WRITE
Escribir datos de forma atómica
addr[i] = buf[i]
FI_CSWAP
Comparar valores y, si son iguales, intercambiarlos con los datos
if (compare[i] == addr[i])
    addr[i] = buf[i]
FI_CSWAP_NE
Comparar valores y, si no son iguales, intercambiarlos con los datos
if (compare[i] != addr[i])
    addr[i] = buf[i]
FI_CSWAP_LE
Comparar valores y, si son menores o iguales, intercambiarlos con los datos
if (compare[i] <= addr[i])
    addr[i] = buf[i]
FI_CSWAP_LT
Comparar valores y, si son menores, intercambiarlos con los datos
if (compare[i] < addr[i])
    addr[i] = buf[i]
FI_CSWAP_GE
Comparar valores y, si son mayores o iguales, intercambiarlos con los datos
if (compare[i] >= addr[i])
    addr[i] = buf[i]
FI_CSWAP_GT
Comparar valores y, si son mayores, intercambiarlos con los datos
if (compare[i] > addr[i])
    addr[i] = buf[i]
FI_MSWAP
Intercambiar bits enmascarados con los datos
addr[i] = (buf[i] & compare[i]) | (addr[i] & ~compare[i])
FI_DIFF
Calcular la diferencia
addr[i] = addr[i] - buf[i]

Funciones Atómicas Base

Las funciones atómicas base – fi_atomic, fi_atomicv, fi_atomicmsg – se utilizan para transmitir datos a un nodo remoto, donde se realiza la operación atómica especificada contra los datos de destino. El resultado de una función atómica base se almacena en la región de memoria remota. La principal diferencia entre las funciones atómicas es el número y el tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

La llamada fi_atomic transfiere los datos contenidos en el búfer de datos especificado por el usuario a un nodo remoto. Para los endpoints sin conexión, el endpoint de destino se especifica a través del parámetro dest_addr. A menos que el endpoint se haya configurado de diferente manera, el búfer de datos pasado a fi_atomic no debe ser tocado por la aplicación hasta que la llamada fi_atomic se complete de forma asíncrona. El búfer de destino de una operación atómica base debe permitir acceso de lectura y/o escritura remota, según corresponda.

La llamada fi_atomicv añade soporte para una lista de scatter-gather a fi_atomic. El fi_atomicv transfiere el conjunto de búferes de datos referenciados por el parámetro ioc al nodo remoto para su procesamiento.

La llamada fi_inject_atomic es una versión optimizada de fi_atomic. La función fi_inject_atomic se comporta como si el flag de transferencia FI_INJECT estuviera activado y FI_COMPLETION no. Es decir, el búfer de datos está disponible para su reutilización inmediatamente al regresar de fi_inject_atomic, y no se generará un evento de finalización para esta operación atómica. El evento de finalización se suprimirá incluso si el endpoint no ha sido configurado con FI_SELECTIVE_COMPLETION. Consulte la discusión de flags más abajo para más detalles. El tamaño de mensaje solicitado que puede usarse con fi_inject_atomic está limitado por inject_size.

La llamada fi_atomicmsg soporta funciones atómicas tanto sobre endpoints conectados como sin conexión, con la capacidad de controlar la operación atómica por llamada mediante el uso de flags. La función fi_atomicmsg toma un struct fi_msg_atomic como entrada.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* local scatter-gather array */
    void                **desc;   /* local access descriptors */
    size_t              iov_count;/* # elements in ioc */
    const void          *addr;    /* optional endpoint address */
    const struct fi_rma_ioc *rma_iov; /* remote SGL */
    size_t              rma_iov_count;/* # elements in remote SGL */
    enum fi_datatype    datatype; /* operand datatype */
    enum fi_op          op;       /* atomic operation */
    void                *context; /* user-defined context */
    uint64_t            data;     /* optional data */
};
struct fi_ioc {
    void        *addr;    /* local address */
    size_t      count;    /* # target operands */
};
struct fi_rma_ioc {
    uint64_t    addr;     /* target address */
    size_t      count;    /* # target operands */
    uint64_t    key;      /* access key */
};

La siguiente lista de operaciones atómicas es utilizable con operaciones atómicas base: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR y FI_ATOMIC_WRITE.

Funciones Atómicas Fetch

Las funciones atómicas fetch – fi_fetch_atomic, fi_fetch_atomicv y fi_fetch_atomicmsg – se comportan de manera similar a la función atómica base equivalente. La diferencia entre las llamadas fetch y base es que las rutinas fetch devuelven el valor inicial que estaba almacenado en el destino al usuario. El valor inicial se lee en el búfer de resultados proporcionado por el usuario. El búfer de destino de las operaciones fetch-atomic debe estar habilitado para acceso de lectura remota.

La siguiente lista de operaciones atómicas es utilizable con operaciones atómicas fetch: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ y FI_ATOMIC_WRITE.

Para las operaciones FI_ATOMIC_READ, el operando del búfer fuente (por ejemplo, el parámetro buf de fi_fetch_atomic) se ignora y puede ser NULL. Los resultados se escriben en el búfer de resultados.

Las funciones de intercambio atómico comparativo – fi_compare_atomic, fi_compare_atomicv y fi_compare_atomicmsg – se utilizan para operaciones que requieren comparar los datos de destino contra un valor antes de realizar una operación de intercambio. Las funciones de intercambio atómico comparativo soportan: FI_CSWAP, FI_CSWAP_NE, FI_CSWAP_LE, FI_CSWAP_LT, FI_CSWAP_GE, FI_CSWAP_GT y FI_MSWAP.

Funciones de Validación de Operaciones Atómicas

Las funciones de validación de operaciones atómicas – fi_atomicvalid, fi_fetch_atomicvalid y fi_compare_atomicvalid – indican qué operaciones soporta el proveedor local. Las operaciones necesarias que no son soportadas por el proveedor deben ser emuladas por la aplicación. Cada llamada de validación corresponde a un conjunto de funciones atómicas. fi_atomicvalid comprueba si un proveedor soporta una operación atómica base específica para un dado tipo de datos y operación. fi_fetch_atomicvalid indica si un proveedor soporta una operación de intercambio atómico con obtención (fetch-atomic) específica para un dado tipo de datos y operación. Y fi_compare_atomicvalid comprueba si un proveedor soporta una operación de intercambio atómico comparativo especificada para un dado tipo de datos y operación.

Si una operación es soportada, una llamada de validación de operación atómica devolverá 0, junto con un conteo de unidades de datos atómicos sobre las que operará una sola llamada a la función.

Consulta de Atributos Atómicos

La llamada fi_query_atomic actúa como una operación de validación atómica mejorada (ver las definiciones de las funciones de validación atómica más arriba). Se proporciona, en parte, para una futura extensibilidad. La operación de consulta informa qué operaciones atómicas son soportadas por el dominio, para puntos de conexión debidamente configurados.

El comportamiento de fi_query_atomic se ajusta basándose en el parámetro flags. Si flags es 0, entonces la operación informa los atributos atómicos soportados para operaciones atómicas base, similar a fi_atomicvalid para puntos de conexión. Si flags tiene el bit FI_FETCH_ATOMIC establecido, la operación se comporta similar a fi_fetch_atomicvalid. De manera similar, el bit de flag FI_COMPARE_ATOMIC resulta en que la consulta actúe como fi_compare_atomicvalid. Los bits FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC no pueden estar establecidos a la vez.

Si el bit FI_TAGGED está establecido, el proveedor indicará si soporta operaciones atómicas en búferes de recepción etiquetados (tagged). El bit FI_TAGGED puede usarse por sí solo, o en conjunto con los flags FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC.

La salida de fi_query_atomic es struct fi_atomic_attr:

struct fi_atomic_attr {
    size_t count;
    size_t size;
};

El campo de atributo count está definido como para las llamadas de validación atómica. El campo size indica el tamaño en bytes del tipo de datos atómico. El campo size es útil para tipos de datos que pueden diferir en tamaño basándose en la plataforma o el compilador, como FI_LONG_DOUBLE.

Completados

Las operaciones atómicas completadas son reportadas al iniciador de la solicitud a través de una cola de completados (completion queue) o contador asociado. Cualquier contexto proporcionado por el usuario especificado con la solicitud será devuelto como parte de cualquier evento de completado escrito a una CQ. Ver fi_cq para detalles de los eventos de completado.

Cualquier resultado devuelto al iniciador como parte de una operación atómica estará disponible antes de que se genere un evento de completado. Esto será cierto incluso si la semántica de completado solicitada proporciona una garantía más débil. Es decir, las operaciones atómicas de obtención (fetch) tienen semánticas FI_DELIVERY_COMPLETE. Los completados generados para otros tipos de operaciones atómicas indican que es seguro reutilizar los búferes de datos de origen.

Cualquier actualización a los datos en el destino de una operación atómica será visible a los agentes (procesos CPU, tarjetas de interfaz de red (NICs) y otros dispositivos) en el nodo destino antes de que ocurra uno de los siguientes eventos. Si la operación atómica genera un evento de completado o actualiza un contador de completado en el punto de conexión destino, los resultados estarán disponibles antes de la notificación de completado. Después de procesar un completado para la operación atómica, si el iniciador envía una transferencia entre los mismos puntos de conexión que genera un completado en el destino, los resultados estarán disponibles antes del evento de la transferencia posterior. O, si una transferencia de datos con valla (fenced) del iniciador sigue a la solicitud atómica, los resultados estarán disponibles antes de un completado en el destino para la transferencia con valla.

La corrección de las operaciones atómicas en una región de memoria de destino está garantizada solo cuando son realizadas por un solo actor para una ventana de tiempo dada. Un actor se define como un solo dominio libfabric en el destino (identificado por el nombre del dominio, y no una instancia abierta de ese dominio), un complejo CPU coherente, u otro dispositivo (p. ej. GPU) capaz de realizar operaciones atómicas sobre la memoria de destino. Los resultados de las operaciones atómicas realizadas por múltiples agentes simultáneamente son indefinidos. Por ejemplo, emitir operaciones atómicas basadas en CPU a una región de destino que está siendo actualizada concurrentemente por operaciones atómicas basadas en NIC puede dejar los datos de la región en un estado desconocido. Los resultados de las operaciones atómicas de un primer actor deben ser visibles para un segundo actor antes de que el segundo actor emita sus propias operaciones atómicas.

FLAGS

Las llamadas fi_atomicmsg, fi_fetch_atomicmsg y fi_compare_atomicmsg permiten al usuario especificar flags que pueden cambiar la operación de transferencia de datos predeterminada. Los flags especificados con operaciones de mensaje atómico anulan la mayoría de los flags previamente configurados con el punto de conexión, excepto donde se indique (ver fi_control). La siguiente lista de flags es usable con llamadas de mensaje atómico.

FI_COMPLETION
Indica que una entrada de completado debe ser generada para la operación especificada. El punto de conexión debe estar vinculado a una cola de completados con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o este flag es ignorado.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que serán inmediatamente publicadas después de que la llamada actual retorne. El uso de este flag puede mejorar el rendimiento al permitir al proveedor optimizar su acceso al hardware de la red (fabric).
FI_INJECT
Indica que el control de los búferes de datos constantes debe ser devuelto al usuario inmediatamente después de que la llamada retorne, incluso si la operación es manejada de forma asíncrona. Esto puede requerir que la implementación subyacente del proveedor copie los datos en un búfer local y transfiera desde ese búfer. Búferes de datos constantes se refiere a cualquier búfer de datos o iovec usado por las APIs atómicas que están marcados como `const'. Los búferes no constantes o de salida no se ven afectados por este flag y pueden ser accedidos por el proveedor en cualquier momento hasta que la operación se haya completado. Este flag solo puede usarse con mensajes más pequeños que inject_size.
FI_FENCE
Aplica a transmisiones. Indica que la operación solicitada, también conocida como la operación con valla (fenced), y cualquier operación publicada después de la operación con valla serán diferidas hasta que todas las operaciones previas dirigidas al mismo punto de conexión par hayan completado. Las operaciones publicadas después de la valla verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación con valla.

El orden de las operaciones desde la publicación de la operación con valla (inclusivo) hasta la publicación de una operación con valla posterior (exclusivo) está controlado por la semántica de orden del punto de conexión.

FI_TAGGED
Especifica que el destino de la operación atómica es un búfer de recepción etiquetado (tagged) en lugar de un búfer RMA. Cuando un búfer etiquetado es la región de memoria de destino, el parámetro addr se usa como un desplazamiento de bytes basado en 0 dentro del búfer etiquetado, con el parámetro key especificando la etiqueta (tag).

VALOR DE RETORNO

Devuelve 0 en caso de éxito. En caso de error, se devuelve un valor negativo correspondiente a un errno de red (fabric). Los valores de errno de red están definidos en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Ver fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
-FI_EOPNOTSUPP

-FI_EMSGSIZE

NOTAS

Las operaciones atómicas operan sobre un arreglo de valores de un tipo de datos específico. La atomicidad solo está garantizada para cada operación de tipo de datos, no a través de todo el arreglo. El siguiente pseudocódigo demuestra esta operación para una escritura atómica de 64 bits sin signo. ATOMIC_WRITE_U64 es una macro dependiente de la plataforma que escribe atómicamente 8 bytes en una ubicación de memoria alineada.

fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]);
}

El número de elementos del arreglo sobre los que operar se especifica a través de un parámetro count. Este debe estar entre 1 y el máximo devuelto a través de la operación de validación relevante, inclusive. La operación solicitada y el tipo de datos también deben ser válidos para el proveedor dado.

El orden de las operaciones atómicas transportadas como parte de diferentes mensajes de solicitud está sujeto a las definiciones de orden de mensajes y de datos asignadas a los puntos de conexión de transmisión y recepción. Tanto el orden de mensajes como el de datos son requeridos si los resultados de dos operaciones atómicas a los mismos búferes de memoria deben reflejar la segunda operación actuando sobre los resultados de la primera. Ver fi_endpoint(3) para más detalles y restricciones de tamaño de mensaje.
