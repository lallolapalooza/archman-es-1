Añadir un servicio. Esta opción se puede especificar varias veces. Si se proporciona un tiempo de espera, la regla estará activa durante el tiempo especificado y se eliminará automáticamente después. timeval es un número (de segundos) o un número seguido de uno de los caracteres s (segundos), m (minutos), h (horas), por ejemplo 20m o 1h.

El servicio es uno de los servicios proporcionados por firewalld. Para obtener una lista de los servicios compatibles, use firewall-cmd --get-

services.

La opción --timeout no se puede combinar con la opción --perm

anent.

Nota: Algunos servicios definen auxiliares de seguimiento de conexiones. Los auxiliares que pueden operar en modo cliente (por ejemplo, tftp) deben añadirse a una política de salida en lugar de a una zona para que surtan efecto para los clientes. De lo contrario, el auxiliar no se aplicará al tráfico de salida. El tráfico relacionado, tal como lo define el auxiliar de seguimiento de conexiones, en la ruta de retorno (entrada) será permitido por las reglas de firewall con

estado.

conexiones:

# firewall-cm

firewall-cmd --permanent --policy clientConntrack --add-service tftp

Opciones Directas

OBSOLETO

La interfaz directa ha sido obsoleta. Será eliminada en una futura versión. Ha sido reemplazada por políticas, ver firewalld.policies(5).

Las opciones directas ofrecen un acceso más directo al cortafuegos. Estas opciones requieren que el usuario conozca conceptos básicos de iptables, es decir, tabla (filter/mangle/nat/...), cadena (INPUT/OUTPUT/FORWARD/...), comandos (-A/-D/-I/...), parámetros (-p/-s/-d/-j/...) y objetivos (ACCEPT/DROP/REJECT/...).

Las opciones directas solo deben usarse como último recurso cuando no sea posible usar, por ejemplo, --add-service=service o --add-rich-rule='rule'.

Advertencia: El comportamiento de las reglas directas difiere según el valor de FirewallBackend. Ver CAVEATS en firewalld.direct(5).

El primer argumento de cada opción debe ser ipv4 o ipv6 o eb. Con ipv4 será para IPv4 (iptables(8)), con ipv6 para IPv6 (ip6tables(8)) y con eb para puentes de Ethernet (ebtables(8)).

[--permanent] --direct --get-all-chains

Obtiene todas las cadenas añadidas a todas las tablas. Esta opción solo concierne a las cadenas añadidas previamente con --direct --add-chain.

[--permanent] --direct --get-chains { ipv4 | ipv6 | eb } table

Obtiene todas las cadenas añadidas a la tabla table como una lista separada por espacios. Esta opción solo concierne a las cadenas añadidas previamente con --direct --add-chain.

[--permanent] --direct --add-chain { ipv4 | ipv6 | eb } table chain

Añade una nueva cadena con el nombre chain a la tabla table. Asegúrate de que no exista ya otra cadena con este nombre.

Ya existen cadenas básicas para usar con opciones directas, por ejemplo, la cadena INPUT_direct (ver la salida de iptables-save | grep direct para todas ellas). A estas cadenas se salta antes que a las cadenas de las zonas, es decir, cada regla puesta en INPUT_direct será comprobada antes que las reglas en las zonas.

[--permanent] --direct --remove-chain { ipv4 | ipv6 | eb } table chain

Elimina la cadena con el nombre chain de la tabla table. Solo las cadenas añadidas previamente con --direct --add-chain pueden ser eliminadas de esta manera.

[--permanent] --direct --query-chain { ipv4 | ipv6 | eb } table chain

Devuelve si una cadena con el nombre chain existe en la tabla table. Devuelve 0 si es verdadero, 1 si no. Esta opción solo concierne a las cadenas añadidas previamente con --direct --add-chain.

Obtiene todas las reglas añadidas a todas las cadenas en todas las tablas como una lista separada por saltos de línea de la prioridad y los argumentos. Esta opción solo concierne a las reglas añadidas previamente con --direct --add-rule.

[--permanent] --direct --get-rules { ipv4 | ipv6 | eb } table chain

Obtiene todas las reglas añadidas a la cadena chain en la tabla table como una lista separada por saltos de línea de la prioridad y los argumentos. Esta opción solo concierne a las reglas añadidas previamente con --direct --add-rule.

[--permanent] --direct --add-rule { ipv4 | ipv6 | eb } table chain priority args

Añade una regla con los argumentos args a la cadena chain en la tabla table con prioridad priority.

La priority se utiliza para ordenar las reglas. La prioridad 0 significa añadir la regla al principio de la cadena, con una prioridad mayor la regla se añadirá más abajo. Las reglas con la misma prioridad están en el mismo nivel y el orden de estas reglas no es fijo y puede cambiar. Si quieres asegurarte de que una regla se añadirá después de otra, usa una prioridad baja para la primera y una más alta para la siguiente.

[--permanent] --direct --remove-rule { ipv4 | ipv6 | eb } table chain priority args

Elimina una regla con priority y los argumentos args de la cadena chain en la tabla table. Solo las reglas añadidas previamente con --direct --add-rule pueden ser eliminadas de esta manera.

[--permanent] --direct --remove-rules { ipv4 | ipv6 | eb } table chain

Elimina todas las reglas de la cadena con el nombre chain que exista en la tabla table. Esta opción solo concierne a las reglas añadidas previamente con --direct --add-rule en esta cadena.

[--permanent] --direct --query-rule { ipv4 | ipv6 | eb } table chain priority args

Devuelve si una regla con priority y los argumentos args existe en la cadena chain en la tabla table. Devuelve 0 si es verdadero, 1 si no. Esta opción solo concierne a las reglas añadidas previamente con --direct --add-rule.
