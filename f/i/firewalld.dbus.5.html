org.fedoraproject.FirewallD1.direct

OBSOLETO

La interfaz directa ha sido obsoleta. Será eliminada en una versión futura. Está reemplazada por políticas, ver firewalld.policies(5).

Esta interfaz permite un acceso más directo al firewall. Permite la manipulación en tiempo de ejecución con cadenas y reglas. Para configuración permanente ver la interfaz org.fedoraproject.FirewallD1.config.direct.

Métodos

addChain(s: ipv, s: table, s: chain) → Nothing

Agrega una nueva chain a table para ipv, siendo ipv4 (iptables), ipv6 (ip6tables) o eb (ebtables). Asegúrese de que no exista ya otra cadena con este nombre. Ya existen cadenas básicas para usar con métodos directos, por ejemplo, la cadena INPUT_direct. Estas cadenas se invocan antes que las cadenas de las zonas, es decir, cada regla colocada en INPUT_direct se verificará antes que las reglas en las zonas. Para operación permanente ver org.fedoraproject.FirewallD1.config.direct.Methods.addChain.

Posibles errores: INVALID_IPV, INVALID_TABLE, ALREADY_ENABLED, COMMAND_FAILED

addPassthrough(s: ipv, as: args) → Nothing

Agrega una regla de traspaso rastreada con los argumentos args para ipv, siendo ipv4 (iptables), ipv6 (ip6tables) o eb (ebtables). Los comandos válidos en args son solo -A/--append, -I/--insert y -N/--new-chain. Este método es (a diferencia del método passthrough) rastreado, es decir, firewalld lo recuerda. Es útil con org.fedoraproject.FirewallD1.Methods.runtimeToPermanent. Para operación permanente ver org.fedoraproject.FirewallD1.config.direct.Methods.addPassthrough.

Posibles errores: INVALID_IPV, ALREADY_ENABLED, COMMAND_FAILED

addRule(s: ipv, s: table, s: chain, i: priority, as: args) → Nothing

Agrega una regla con los argumentos args a chain en table con priority para ipv, siendo ipv4 (iptables), ipv6 (ip6tables) o eb (ebtables). La prior La prioridad se utiliza para ordenar las reglas. Una prioridad 0 significa añadir la regla en la parte superior de la cadena, con una prioridad más alta la regla se añadirá más abajo. Las reglas con la misma prioridad están en el mismo nivel y el orden de estas reglas no es fijo y puede cambiar. Si desea asegurarse de que una regla se añadirá después de otra, use una prioridad baja para la primera y una más alta para la siguiente. Para la operación permanente, consulte org.fedoraproject.FirewallD1.config.direct.Methods.addRule.

NOMBRE

firewalld.dbus - Interfaz de D-Bus para firewalld

DESCRIPCIÓN

El demonio firewalld proporciona una interfaz de D-Bus para la gestión de la configuración del firewall. El servicio de D-Bus es org.fedoraproject.FirewallD1. Este servicio expone varias interfaces para la gestión de las zonas, las políticas, los servicios, los tipos ICMP, los ipsets, los helpers y las reglas directas. Además, expone una interfaz para la gestión de las configuraciones de los objetos del firewall y una interfaz para la gestión de la configuración global de firewalld.

Las interfaces se exponen bajo el objeto path /org/fedoraproject/FirewallD1.

Las configuraciones de los objetos del firewall se exponen bajo los siguientes paths:

  • /org/fedoraproject/FirewallD1/zones
  • /org/fedoraproject/FirewallD1/policies
  • /org/fedoraproject/FirewallD1/services
  • /org/fedoraproject/FirewallD1/icmptypes
  • /org/fedoraproject/FirewallD1/ipsets
  • /org/fedoraproject/FirewallD1/helpers
  • /org/fedoraproject/FirewallD1/directrules

Las configuraciones globales de firewalld se exponen bajo:

  • /org/fedoraproject/FirewallD1/config

La interfaz org.fedoraproject.FirewallD1 contiene métodos para la gestión de la configuración global de firewalld.

Las interfaces de los objetos del firewall contienen métodos para la gestión de las configuraciones de los objetos del firewall, como por ejemplo las zonas, los servicios, los tipos ICMP, etc. Cada objeto del firewall se expone bajo el path correspondiente, por ejemplo, la zona 'public' se expone bajo /org/fedoraproject/FirewallD1/zones/public.

Los métodos de las interfaces de los objetos del firewall son descritos a continuación.
