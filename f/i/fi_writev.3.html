DESCRIPCIÓ

N

Las operaciones RMA (acceso a memoria remota) se utilizan para transferir datos directamente entre un búfer de datos local y un búfer de datos remoto. Las transferencias RMA ocurren a nivel de granularidad de byte, y no se mantienen límites de

mensajes.

Las funciones de escritura – fi_write, fi_writev, fi_writemsg, fi_inject_write y fi_writedata – se utilizan para transmitir datos a un búfer de memoria remota. La principal diferencia entre las funciones de escritura es el número y tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función

general.

Las funciones de lectura – fi_read, fi_readv y fi_readmsg – se utilizan para transferir datos desde una región de memoria remota a búfer(es) de datos local(es). Similar a las operaciones de escritura, las operaciones de lectura operan de forma asíncrona. Los usuarios no deben tocar el(los) búfer(es) de datos publicado(s) hasta que la operación de lectura se haya

completado.

Las operaciones RMA completadas se reportan al usuario a través de una o más colas de finalización asociadas con el punto final. Los usuarios proporcionan contextos que se asocian con cada operación, y se devuelven al usuario como parte de la finalización. Véase fi_cq para detalles de eventos de

finalización.

Por defecto, el punto final remoto no genera un evento ni notifica al usuario cuando una región de memoria ha sido accedida por una lectura o escritura RMA. Sin embargo, los datos inmediatos pueden asociarse con una operación de escritura RMA. Las escrituras RMA con datos inmediatos generarán una entrada de finalización en el punto final remoto, de modo que los datos inmediatos puedan ser

entregados.

BANDERA

S

Las llamadas fi_readmsg y fi_writemsg permiten al usuario especificar banderas que pueden cambiar la operación de transferencia de datos predeterminada. Las banderas especificadas con fi_readmsg / fi_writemsg anulan la mayoría de las banderas configuradas previamente con el punto de conexión, excepto donde se indique (véase fi_endpoint.3). La siguiente lista de banderas es utilizable con fi_readmsg y/o

fi_writemsg.
FI_REMOTE_CQ_D
ATA
Aplica a fi_writemsg. Indica que los datos de CQ remoto están disponibles y deben enviarse como parte de la solicitud. Véase fi_getinfo para obtener detalles adicionales sobre FI_REMOTE_CQ_DATA. Esta bandera se establece implícitamente para fi_writedata y fi_inject_writeda
ta.
FI_COMPLETI
ON
Indica que debe generarse una entrada de finalización para la operación especificada. El punto de conexión debe estar vinculado a una cola de finalización con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o esta bandera se
ignora.
FI_MO
RE
Indica que el usuario tiene solicitudes adicionales que se publicarán inmediatamente después de que la llamada actual regrese. El uso de esta bandera puede mejorar el rendimiento al permitir al proveedor optimizar su acceso al hardware de la
red.
FI_INJE
CT
Aplica a fi_writemsg. Indica que el búfer de datos de salida debe devolverse al usuario inmediatamente después de que la llamada de escritura regrese, incluso si la operación se maneja de forma asíncrona. Esto puede requerir que la implementación del proveedor subyacente copie los datos en un búfer local y transfiera desde ese búfer. Esta bandera solo puede usarse con mensajes más pequeños que
inject_size.
FI_INJECT_COMPL
ETE
Aplica a fi_writemsg. Indica que debe generarse una finalización cuando el/los búfer(es) de origen puedan
reutilizarse.
FI_TRANSMIT_COMPL
ETE
Aplica a fi_writemsg. Indica que no debe generarse una finalización hasta que la operación se haya transmitido con éxito y ya no sea rastreada por el
proveedor.
FI_DELIVERY_COMPL
ETE
Aplica a fi_writemsg. Indica que debe generarse una finalización cuando la operación haya sido procesada por el
destino.
FI_COMMIT_COMPL
ETE
Aplica a fi_writemsg al apuntar a regiones de memoria persistente. Indica que una finalización solo debe generarse después de que el resultado de la operación se haya hecho
duradero.
FI_FEN
CE
Aplica a las transmisiones. Indica que la operación solicitada, también conocida como la operación cercada, y cualquier operación publicada después de l
a operación cercada se diferirán hasta que todas las operaciones anteriores dirigidas al mismo punto de conexión de pares se hayan completado. Las
operaciones publicadas después de la cercado verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación cercada.

El orden de las operaciones desde la publicación de la operación cercada

(inclusive) hasta la publicación de una operación cercada posterior (
exclusivo) está controlado por la semántica de orden del punto de conexión.
