DESCRIPCIÓN

GENERAL

El proveedor de enganche es una función utilitaria que puede interceptar llamadas a cualquier proveedor. El

proveedor de enganche siempre está disponible, pero no tiene impacto en las llamadas a menos que se habilit
e. Es útil para proporcionar datos de rendimiento sobre llamadas seleccionadas o información de depuración.

CARACTERÍSTICAS

SOPORTADAS

El soporte de enganche se habilita a través de la variable de entorno FI_HOOK. Para habilitar el enganche, FI_HOOK debe establecerse en el nombre de uno o más de los proveedores de enganche disponibles. Cuando se especifican varios ganchos, los nombres deben separarse por un punto y coma. Para obtener una lista de los proveedores de enganche disponibles en el sistema actual, se puede usar la utilidad fi_info con la opción de línea de comandos `–env'. Los proveedores de enganche suelen identificarse por la aparición de `hook' en el nombre del

proveedor.

Los proveedores de enganche conocidos incluyen los

siguientes:
ofi_hook_pe
rf
Este engancha las llamadas a operaciones de datos de 'ruta rápida'. Se capturan datos de rendimiento en la entrada y salida de la llamada, para proporcionar un promedio de cuánto tiempo tarda cada llamada en completarse. Consulte la sección GANCHOS DE RENDIMIENTO para ver los datos de rendimiento
disponibles.
ofi_hook_tra
ce
Este engancha la mayoría de las llamadas a la API para comunicaciones de fabric. Las APIs y sus parámetros de ejecución se registran para proporcionar información de seguimiento detallada para depuración. Consulte la sección GANCHOS DE TRAZA para ver las APIs habilitadas para la
traza.
ofi_hook_prof
ile
Este engancha las llamadas a operaciones de datos, las llamadas a operaciones de cq y las llamadas de registro de mr. Las llamadas a la API y la cantidad de datos que se están operando se acumulan, para proporcionar una vista del uso de las APIs y un histograma del tamaño de los datos operados en la ejecución de una carga de trabajo. Consulte la sección GANCHOS DE PERFIL para ver el informe en
detalle.
ofi_hook_moni
tor
Similar a ofi_hook_profile, este engancha las llamadas a operaciones de datos, las llamadas a operaciones de cq y las llamadas de registro de mr. Las llamadas a la API y la c
antidad de datos que se están operando se acumulan y se ponen a disposición para
su exportación a través de un muestreador externo mediante un archivo de comun
icación compartido. Consulte la sección GANCHOS DE MONITOREO para más detalles.

GANCHOS DE

RENDIMIENTO

El proveedor de enganche permite capturar datos de rendimiento en línea accediendo a la Unidad de Gestión de Rendimiento de la CPU (PMU). Los datos de la PMU solo están disponibles en sistemas Linux. Además, el acceso a los datos de la PMU puede estar restringido a aplicaciones privilegiadas (superusuario)

.

Se capturan datos de rendimiento para las llamadas críticas de transferencia de datos: fi_msg, fi_rma, fi_tagged, fi_cq y fi_cntr. Los datos capturados se muestran como datos registrados usando el nivel de traza FI_LOG_LEVEL. Los datos de rendimiento se registran cuando se destruye el fabric

asociado.

La variable de entorno FI_PERF_CNTR se utiliza para identificar qué contador de rendimiento se rastrea. Los siguientes contadores están

disponibles:
cpu_cycl
es
Cuenta el número de ciclos de CPU que tarda cada función en
completarse.
cpu_ins
tr
Cuenta el número de instrucciones de CPU
que tarda cada función en completarse.
Este es el contador de rendimiento pr
edeterminado si no se especifica ninguno.

TRAZA

Este proveedor de enganche permite rastrear cada llamada a la API y sus parámetros de ejecución. Se habilita estableciendo FI_HOOK en

"trace".

Los datos de traza incluyen el nombre del proveedor, la función de la API y los valores de los parámetros de entrada/salida. Las APIs habilitadas para el rastreo incluyen las

siguientes:

datos
Esto incluye fi_msg, fi_rma, fi_tagged todas las operaciones de datos. Los datos de traza contienen el búfer de datos, el tamaño de los datos que se están operando, los datos, las etiquetas y los indicadores cuando
corresponda.
llamadas a operaciones
de cq
Esto incluye fi_cq_read, fi_cq_sread, fi_cq_strerror y todas las operaciones de cq. Los datos de traza contienen las entradas de cq basadas en el formato de
cq.
llamadas a operaciones
de cm
Esto incluye fi_getname, fi_setname, fi_getpeer, fi_connect y todas las operaciones de cm. Los datos de traza contienen la dirección de
destino.
llamadas a creación de
recursos
Esto incluye fi_av_open, fi_cq_open, fi_endpoing, fi_cntr_open y las

GANCHOS DE

PERFIL

Este proveedor de enganche permite capturar las llamadas a operaciones de datos y la cantidad de datos que se están operando. Se habilita estableciendo FI_HOOK en

"profile".

El proveedor cuenta las APIs invocadas y acumula el tamaño de los datos que opera cada llamada a la API. Para las operaciones de datos y cq, en lugar de acumular todos los datos juntos, descompone el tamaño de los datos en contenedores de tamaño y acumula la cantidad de datos en el contenedor correspondiente basándose en el tamaño de los datos operados. Para las operaciones de registro de mr, descompone la memoria registrada por interfaz de HMEM. Al final, cuando se destruye el fabric asociado, el proveedor genera un informe de

perfil.

El informe contiene el uso de las APIs de operaciones de datos, la cantidad de datos recibidos en cada formato de CQ y la cantidad de memoria registrada para las operaciones rma, si las hay. Además, las APIs de operaciones de datos se agrupan en 4 grupos basándose en la naturaleza de las operaciones: envío de mensajes (fi_sendXXX, fi_tsendXXX), recepción de mensajes (fi_recvXXX, fi_trecvXXX), lectura rma (fi_readXXX) y escritura rma (fi_writeXXX) para presentar el porcentaje de uso de cada

API.

El informe está en formato de tabla, con las APIs invocadas en las filas, y las columnas contienen los siguientes

campos:

invocan.
Tam

Contenedor de tamaño de datos en el que al menos una llamada a la API opera datos en ese contenedor de tamaño. Los contenedores de tamaño predefinidos (en bytes) son [0-64] [64-512] [512-1K] [1K-4K] [4K-64K] [64K-256K] [256K-1M] [1M-4M] [4M-UP]
.

API.

GANCHOS DE

MONITOREO

Este proveedor de enganche se basa en el proveedor de ganchos "profile" y proporciona capacidades de lectura continua útiles para monitorear aplicaciones libfabric. Se habilita estableciendo FI_HOOK en

"monitor".

Similar al proveedor de ganchos "profile", este proveedor cuenta el número de llamadas a la API invocadas y acumula la cantidad de datos manejados por cada llamada a la API. Consulte la documentación sobre el gancho "profile" para más

información.

La exportación de datos se facilita mediante un archivo de comunicación en el sistema de archivos, que se crea para cada proveedor de libfabric enganchado. El gancho de monitoreo espera ejecutarse en un tmpfs. Si está disponible y a menos que se especifique lo contrario, los archivos se crearán bajo el tmpfs

/dev/shm.

Un muestreador puede leer periódicamente este archivo para extraer los datos recopilados. Cada N llamadas a la API interceptadas o "ticks", el proveedor comprobará si el muestreador ha solicitado la exportación de datos. Si es así, los datos del contador recopilados actualmente se copian al archivo y se informa al muestreador sobre los nuevos datos. Los datos del contador locales del proveedor se borran a continuación. Cada muestra contiene el delta del contador con respecto a la muestra

anterior.

Los archivos de comunicación se crearán en la ruta $FI_OFI_HOOK_MONITOR_BASEPATH/<uid>/<hostname> y tendrá el nombre: <ppid>_<pid>_<id secuencial>_<id de trabajo>_<nombre del proveedor>. ppid y pid se toman desde la perspectiva de la aplicación monitoreada. En un entorno por lotes que ejecuta SLURM, el id de trabajo se establece al ID de trabajo de SLURM, de lo contrario se establece en

0.

Consulte fi_mon_sampler(1) para documentación sobre cómo usar el muestreador del proveedor de

monitoreo.

LIMITACIONE

S

La funcionalidad de gancho no está disponible para los proveedores construidos usando la característica FI_FABRIC_DIRECT. Es decir, vincular directamente con un proveedor impide el uso de

ganchos.

El proveedor de ganchos no funciona con operaciones desenca

denadas. Las aplicaciones que usan operaciones FI_TRIGGE
R e intentan enganchar llamadas probablemente fallarán.
