FICLONE(2const) FICLONE(2const)

NOMBRE

FICLONE, FICLONERANGE - compartir parte de los datos de un archivo con otro archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/fs.h>  /* Definición de constantes FICLONE* */
#include <sys/ioctl.h>
int ioctl(int dest_fd, FICLONERANGE, struct file_clone_range *arg);
int ioctl(int dest_fd, FICLONE, int src_fd);

DESCRIPCIÓN

Si un sistema de archivos admite archivos que comparten almacenamiento físico entre varios archivos ("reflink"), esta operación ioctl(2) puede ser utilizada para hacer que parte de los datos en el archivo src_fd aparezcan en el archivo dest_fd compartiendo el almacenamiento subyacente, lo cual es más rápido que hacer una copia física separada de los datos. Ambos archivos deben residir en el mismo sistema de archivos. Si ocurre una escritura en un archivo dentro de una región compartida, el sistema de archivos debe asegurar que los cambios permanezcan privados al archivo que se está escribiendo. Este comportamiento se conoce comúnmente como "copiar al escribir" (copy on write).

Este ioctl hace reflink de hasta src_length bytes desde el descriptor de archivo src_fd en el desplazamiento src_offset hacia el archivo dest_fd en el desplazamiento dest_offset, siempre que ambos sean archivos. Si src_length es cero, el ioctl hace reflink hasta el final del archivo de origen. Esta información se transmite en una estructura de la siguiente forma:


struct file_clone_range {
    __s64 src_fd;
    __u64 src_offset;
    __u64 src_length;
    __u64 dest_offset;
};

Los clones son atómicos con respecto a escrituras concurrentes, por lo que no es necesario tomar bloqueos para obtener una copia clonada consistente.

El ioctl FICLONE clona archivos enteros.

VALOR DE RETORNO

En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

Los códigos de error pueden ser uno de los siguientes, pero no se limitan a ellos:

EBADF
src_fd no está abierto para lectura; dest_fd no está abierto para escritura o está abierto solo para escritura de anexión; o el sistema de archivos en el que reside src_fd no admite reflink.
EINVAL
El sistema de archivos no admite el reflink de los rangos de los archivos dados. Este error también puede aparecer si alguno de los descriptores de archivo representa un dispositivo, FIFO o socket. Los sistemas de archivos en disco generalmente requieren que los argumentos de desplazamiento y longitud estén alineados al tamaño de bloque fundamental. XFS y Btrfs no admiten rangos de reflink superpuestos en el mismo archivo.
EISDIR
Uno de los archivos es un directorio y el sistema de archivos no admite regiones compartidas en directorios.
EOPNOTSUPP
Esto puede aparecer si el sistema de archivos no admite reflink de ninguno de los descriptores de archivo, o si alguno de los descriptores de archivo se refiere a inodos especiales.
EPERM
dest_fd es inmutable.
ETXTBSY
Uno de los archivos es un archivo de intercambio (swap). Los archivos de intercambio no pueden compartir almacenamiento.
EXDEV
dest_fd y src_fd no están en el mismo sistema de archivos montado.

ESTÁNDARES

Linux.

HISTORIA

Linux 4.5.

Anteriormente se conocían como BTRFS_IOC_CLONE y BTRFS_IOC_CLONE_RANGE, y eran privados de Btrfs.

ADVERTENCIAS

Dado que una operación de copiar al escribir requiere la asignación de nuevo almacenamiento, la operación fallocate(2) puede desunir bloques compartidos para garantizar que las escrituras posteriores no fallen debido a la falta de espacio en disco.
