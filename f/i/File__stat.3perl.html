File::stat(3perl) Guía del programador de Perl File::stat(3perl)

NOMBRE

File::stat - Interfaz por nombre a las funciones stat() integradas de Perl

SINOPSIS

use File::stat;
my $st = stat($file) or die "No $file: $!";
if ( ($st->mode & 0111) && ($st->nlink > 1) ) {
    print "$file es ejecutable con muchos enlaces\n";
} 
if ( -x $st ) {
    print "$file es ejecutable\n";
}
use Fcntl "S_IRUSR";
if ( $st->cando(S_IRUSR, 1) ) {
    print "Mi uid efectivo puede leer $file\n";
}
use File::stat qw(:FIELDS);
stat($file) or die "No $file: $!";
if ( ($st_mode & 0111) && ($st_nlink > 1) ) {
    print "$file es ejecutable con muchos enlaces\n";
}

DESCRIPCIÓN

Las exportaciones por defecto de este módulo anulan las funciones centrales stat() y lstat(), reemplazándolas por versiones que devuelven objetos "File::stat". Este objeto tiene métodos que devuelven el nombre del campo de estructura con el mismo nombre de la función stat(2); a saber, dev, ino, mode, nlink, uid, gid, rdev, size, atime, mtime, ctime, blksize y blocks.

Desde la versión 1.02 (incluida con perl 5.12) el objeto proporciona sobrecarga de "-X", por lo que puede llamar a operadores de prueba de archivos ("-f", "-x", y así sucesivamente) sobre él. También proporciona un método "->cando", que se llama así:

$st->cando( ACCESO, EFECTIVO )

donde ACCESO es uno de "S_IRUSR", "S_IWUSR" o "S_IXUSR" del módulo Fcntl, y EFECTIVO indica si se deben usar los ids efectivos (verdadero) o reales (falso). El método interpreta los campos "mode", "uid" y "gid", y devuelve si el proceso actual tendría permitido el acceso especificado o no.

Si no desea utilizar los objetos, puede importar el método "->cando" a su espacio de nombres como una función normal llamada "stat_cando". Esta toma un arrayref que contiene los valores de retorno de "stat" o "lstat" como su primer argumento, y lo interpreta por usted.

También puede importar todos los campos de estructura directamente a su espacio de nombres como variables normales utilizando la etiqueta de importación :FIELDS. (Tenga en cuenta que esto todavía anula sus funciones stat() y lstat()). Acceda a estos campos como variables llamadas con un "st_" delante de sus nombres de método. Por lo tanto, "$stat_obj->dev()" corresponde a $st_dev si importa los campos.

Para acceder a esta funcionalidad sin las anulaciones centrales, pase a "use" una lista de importación vacía y luego acceda a las funciones con sus nombres completos calificados. Por otro lado, las funciones integradas siguen estando disponibles a través del pseudopaquete "CORE::".

ERRORES GRAVES

A partir de Perl 5.8.0, después de usar este módulo, no puede usar el $_ implícito ni el manejador de archivos especial "_" con stat() o lstat(), intentar hacerlo lleva a errores extraños. La solución es que $_ sea explícito

my $stat_obj = stat $_;

y que "_" popular explícitamente el objeto usando la función populate() no exportada y no documentada con CORE::stat():

my $stat_obj = File::stat::populate(CORE::stat(_));

ERRORES

-%s no está implementado en un objeto File::stat
Los operadores de prueba de archivos "-t", "-T" y "-B" no están implementados, ya que requieren más información que solo un buffer de stat.

ADVERTENCIAS

Todas estas se pueden deshabilitar con

no warnings "File::stat";
File::stat ignora use filetest 'access'
Ha intentado usar uno de los tests de archivo "-rwxRWX" con "use filetest 'access'" en efecto. "File::stat" ignorará el pragma, y solo usará la información del miembro "mode" como de costumbre.
File::stat ignora los ACL de VMS
Los sistemas VMS tienen una estructura de permisos que no puede ser completamente representada en un buffer de stat, y a diferencia de otros sistemas, los operadores de prueba de archivo integrados respetan esto. Las sobrecargas de "File::stat", sin embargo, no lo hacen, ya que la información requerida no está disponible.

NOTA

Aunque esta clase está implementada actualmente utilizando el módulo Class::Struct para construir una clase similar a una estructura, no debe confiar en esto.
