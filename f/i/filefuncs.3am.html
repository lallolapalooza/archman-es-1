FILEFUNCS(3am) Módulos de extensión de GNU Awk FILEFUNCS(3am)

NOMBRE

filefuncs - proporciona algunas funcionalidades relacionadas con archivos a gawk

SINOPSIS

@load "filefuncs"

result = chdir("/some/directory")

result = stat("/some/path", statdata [, follow])

flags = or(FTS_PHYSICAL, ...)
result = fts(pathlist, flags, filedata)

result = statvfs("/some/path", fsdata)

DESCRIPCIÓN

La extensión filefuncs agrega varias funciones que proporcionan acceso a instalaciones relacionadas con archivos.

chdir()

La función chdir() es un enlace directo a la llamada al sistema chdir(2) para cambiar el directorio actual. Devuelve cero en caso de éxito o menos que cero en caso de error. En este último caso, actualiza ERRNO.

stat()

La función stat() proporciona un enlace a la llamada al sistema stat(2) . Devuelve cero en caso de éxito o menos que cero en caso de error. En este último caso, actualiza ERRNO. Por defecto, utiliza lstat(2). Sin embargo, si se le pasa un tercer argumento, utiliza stat(2)en su lugar.

En todos los casos, limpia el arreglo statdata . Cuando la llamada es exitosa, stat() llena el arreglo statdata con información recuperada del sistema de archivos, de la siguiente manera:

statdata["name"]
El nombre del archivo, igual al primer argumento pasado a stat().
statdata["dev"]
Corresponde al campo st_dev en struct stat.
statdata["ino"]
Corresponde al campo st_ino en struct stat.
statdata["mode"]
Corresponde al campo st_mode en struct stat.
statdata["nlink"]
Corresponde al campo st_nlink en struct stat.
statdata["uid"]
Corresponde al campo st_uid en struct stat.
statdata["gid"]
Corresponde al campo st_gid en struct stat.
statdata["size"]
Corresponde al campo st_size en struct stat.
statdata["atime"]
Corresponde al campo st_atime en struct stat.
statdata["mtime"]
Corresponde al campo st_mtime en struct stat.
statdata["ctime"]
Corresponde al campo st_ctime en struct stat.
statdata["rdev"]
Corresponde al campo st_rdev en struct stat. Este elemento solo está presente para archivos de dispositivo.
statdata["major"]
Corresponde al campo st_major en struct stat. Este elemento solo está presente para archivos de dispositivo.
statdata["minor"]
Corresponde al campo st_minor en struct stat. Este elemento solo está presente para archivos de dispositivo.
statdata["blksize"]
Corresponde al campo st_blksize en struct stat, si este campo está presente en su sistema. (Está presente en todos los sistemas modernos que conocemos.)
statdata["pmode"]
Una versión legible para humanos del valor del modo, como la que imprime ls(1). Por ejemplo, "-rwxr-xr-x".
statdata["linkval"]
Si el archivo nombrado es un enlace simbólico, este elemento existirá y su valor es el valor del enlace simbólico (a dónde apunta el enlace simbólico).
statdata["type"]
El tipo del archivo como cadena. Uno de "file", "blockdev", "chardev", "directory", "socket", "fifo", "symlink", "door", o "unknown". No todos los sistemas soportan todos los tipos de archivos.

fts()

La función fts() proporciona un enlace al conjunto de rutinas fts(3) para recorrer jerarquías de archivos. En lugar de devolver datos sobre un archivo a la vez en un flujo, llena un arreglo multidimensional con datos sobre cada archivo y directorio encontrado en las jerarquías solicitadas.

Los argumentos son los siguientes:

pathlist
Un arreglo de nombres de archivo. Se utilizan los valores de los elementos; los valores de los índices se ignoran.
flags
Este debe ser el OR bit a bit de uno o más de los siguientes valores de bandera predefinidos. Al menos uno de FTS_LOGICAL o FTS_PHYSICAL debe ser proporcionado; de lo contrario fts() devuelve un valor de error y establece ERRNO.
FTS_LOGICAL
Realiza un recorrido de archivos "lógico", donde la información devuelta para un enlace simbólico se refiere al archivo enlazado, y no al enlace simbólico mismo. Esta bandera es mutuamente exclusiva con FTS_PHYSICAL.
FTS_PHYSICAL
Realiza un recorrido de archivos "físico", donde la información devuelta para un enlace simbólico se refiere al enlace simbólico mismo. Esta bandera es mutuamente exclusiva con FTS_LOGICAL.
FTS_NOCHDIR
Como una optimización de rendimiento, las rutinas fts(3) cambian de directorio a medida que recorren una jerarquía de archivos. Esta bandera desactiva esa optimización.
FTS_COMFOLLOW
Sigue inmediatamente un enlace simbólico nombrado en pathlist, independientemente de si está establecida FTS_LOGICAL o no.
FTS_SEEDOT
Por defecto, las rutinas fts(3) no devuelven entradas para "." y "..". Esta opción hace que las entradas para ".." también se incluyan. (La extensión de AWK siempre incluye una entrada para ".", ver más abajo.)
FTS_XDEV
Durante un recorrido, no cruza a un sistema de archivos montado diferente.
FTS_SKIP
Cuando se establece, hace que no se descienda a los directorios de nivel superior.
filedata
El arreglo filedata se limpia primero. Luego, fts() crea un elemento en filedata para cada elemento en pathlist. El índice es el nombre del directorio o archivo dado en pathlist. El elemento para este índice es en sí mismo un arreglo. Hay dos casos.
La ruta es un archivo.
En este caso, el arreglo contiene dos o tres elementos:

NAME

filefuncs - functions for manipulating files

SYNOPSIS

    int fts(pathlist, flags)
    int statvfs(fsdata)

DESCRIPTION

The fts() function walks a file tree. The pathlist parameter is an array of strings, each of which is a path to a file or directory. The flags parameter is an integer, whose value is the bitwise OR of zero or more of the following constants:

FTS_COMPOUND
The file hierarchy will be traversed. If the file is a directory, its contents will be returned as an array of entries. If the file is not a directory, the array will contain just the file.
FTS_DIRONLY
Only directories will be returned.
FTS_SEEDOT
If the file is a directory, entries named "." and ".." will be returned.
FTS_SKIP
If a file is a symbolic link that points to a file that does not exist, the link will be skipped.

The return value of fts() is a multi-dimensional array representing the file hierarchy.

The top-level array contains one element for each item in the pathlist array. Each element is itself an array, containing the following information:

"path"
The full path to the file, starting from the directory specified in the pathlist array.
"stat"
This element is itself an array, containing the same information as provided by the stat() function described earlier for its statdata argument. The element may not be present if stat(2) for the file failed.
"error"
If some kind of error was encountered, the array will also contain an element named "error", which is a string describing the error.
The path is a directory.
In this case, the array contains one element for each entry in the directory. If an entry is a file, that element is as for files, just described. If the entry is a directory, that element is (recursively), an array describing the subdirectory. If FTS_SEEDOT was provided in the flags, then there will also be an element named "..". This element will be an array containing the data as provided by stat().

In addition, there will be an element whose index is ".". This element is an array containing the same two or three elements as for a file: "path", "stat", and "error".

statvfs()

The statvfs() function provides a hook into the statvfs(2) system call on systems that supply this system call. It returns zero upon success or less than zero upon error. In the latter case it updates ERRNO.

When the call is successful, statvfs() fills the fsdata array with information retrieved about the filesystem, as follows:

fsdata["bsize"]
Corresponds to the bsize member in the struct statvfs.
fsdata["frsize"]
Corresponds to the f_frsize member in the struct statvfs.
fsdata["blocks"]
Corresponds to the f_blocks member in the struct statvfs.
fsdata["bfree"]
Corresponds to the f_bfree member in the struct statvfs.
fsdata["bavail"]
Corresponds to the f_bavail member in the struct statvfs.
fsdata["files"]
Corresponds to the f_files member in the struct statvfs.
fsdata["ffree"]
Corresponds to the f_ffree member in the struct statvfs.
fsdata["favail"]
Corresponds to the f_favail member in the struct statvfs.
fsdata["fsid"]
Corresponds to the f_fsid member in the struct statvfs. This member is not available on all systems.
fsdata["flag"]
Corresponds to the f_flag member in the struct statvfs.
fsdata["namemax"]
Corresponds to the f_namemax member in the struct statvfs.

NOTES

The AWK fts() extension does not exactly mimic the interface of the fts(3) routines, choosing instead to provide an interface that is based on associative arrays, which should be more comfortable to use from an AWK program. This includes the lack of a comparison function, since gawk already provides powerful array sorting facilities. While an fts_read()-like interface could have been provided, this felt less natural than simply creating a multi-dimensional array to represent the file hierarchy and its information.

Nothing prevents AWK code from changing the predefined FTS_xx values, but doing so may cause strange results when the changed values are passed to fts().

BUGS

There are many more file-related functions for which AWK interfaces would be desirable.

It's not clear why I thought adding FTS_SKIP was a good idea.

EXAMPLE

See test/fts.awk in the gawk distribution for an example.
