NOMBRE

firewalld.service - Archivos de configuración del servicio firewalld

SINOPSIS

/etc/firewalld/services/service.xml
/usr/lib/firewalld/services/service.xml

DESCRIPCIÓN

Un archivo de configuración de servicio de firewalld proporciona la información de una entrada de servicio para firewalld. Las opciones de configuración más importantes son puertos, módulos y direcciones de destino.

Este archivo de configuración de ejemplo muestra la estructura de un archivo de configuración de servicio:

<?xml version="1.0" encoding="utf-8"?>
<service>
  <short>Mi Servicio</short>
  <description>descripción</description>
  <port port="137" protocol="tcp"/>
  <protocol value="igmp"/>
  <module name="nf_conntrack_netbios_ns"/>
  <destination ipv4="224.0.0.251" ipv6="ff02::fb"/>
  <include service="ssdp"/>
  <helper name="ftp"/>
</service>

OPCIONES

La configuración puede contener estas etiquetas y atributos. Algunos de ellos son obligatorios, otros opcionales.

service

La etiqueta de inicio y fin obligatoria service define el servicio. Esta etiqueta solo puede usarse una vez en un archivo de configuración de servicio. Hay atributos opcionales para los servicios:

version="cadena"

Para darle una versión al servicio.

short

Es una etiqueta de inicio y fin opcional y se usa para darle a un servicio un nombre más legible.

description

Es una etiqueta de inicio y fin opcional para tener una descripción de un servicio.

port

Es una etiqueta de elemento vacío opcional y puede usarse varias veces para tener más de una entrada de puerto. Todos los atributos de una entrada de puerto son obligatorios:

port="cadena"

El puerto cadena puede ser un número de puerto único o un rango de puertos portid-portid o también estar vacío para que coincida solo con un protocolo.

protocol="cadena"

El valor del protocolo puede ser tcp, udp, sctp o dccp.

Por compatibilidad con versiones anteriores de firewalld, es posible añadir protocolos con la opción de puerto donde el puerto está vacío. Con la adición del soporte nativo de protocolos en el servicio, esto ya no es necesario. Estas entradas se convertirán automáticamente en protocolos. Con la siguiente modificación del archivo de servicio, las entradas se listarán como protocolos.

protocol

Es una etiqueta de elemento vacío opcional y puede usarse varias veces para tener más de una entrada de protocolo. Una entrada de protocolo tiene exactamente un atributo:

value="cadena"

El protocolo puede ser cualquier protocolo soportado por el sistema. Por favor, consulte /etc/protocols para ver los protocolos soportados.

source-port

Es una etiqueta de elemento vacío opcional y puede usarse varias veces para tener más de una entrada de puerto de origen. Todos los atributos de una entrada de puerto de origen son obligatorios:

port="cadena"

El puerto cadena puede ser un número de puerto único o un rango de puertos portid-portid.

protocol="cadena"

El valor del protocolo puede ser tcp, udp, sctp o dccp.

module

Este elemento está obsoleto. Por favor, use helper descrito más abajo en la sección llamada “helper”.

destination

Es una etiqueta de elemento vacío opcional y solo puede usarse una vez. El destino especifica la red de destino como una dirección IP de red (opcional con /máscara), o una dirección IP simple. El uso de nombres de host no se recomienda, ya que estos solo se resolverán en la activación del servicio y se transmitirán al kernel. Para más información sobre este elemento, por favor, consulte --destination en iptables(8) y ip6tables(8).

ipv4="dirección[/máscara]"

La dirección de destino IPv4 con máscara opcional.

ipv6="dirección[/máscara]"

La dirección de destino IPv6 con máscara opcional.

include

Es una etiqueta de elemento vacío opcional y puede usarse varias veces para tener más de una entrada de inclusión. Una entrada de inclusión tiene exactamente un atributo:

service="cadena"

La inclusión puede ser cualquier servicio soportado por firewalld.

Advertencia:Firewalld solo comprobará que el servicio incluido sea un servicio válido si se aplica a una zona.

helper

Es una etiqueta de elemento vacío opcional y puede usarse varias veces para tener más de una entrada de helper. Una entrada de helper tiene exactamente un atributo:

name="cadena"

El helper puede ser cualquier helper soportado por firewalld.
