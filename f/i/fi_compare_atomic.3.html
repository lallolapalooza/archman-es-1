fi_atomic / fi_atomicv / fi_atomicmsg / fi_inject_atomic

DESCRIPCIÓN

Las transferencias atómicas se utilizan para leer y actualizar datos ubicados en regiones de memoria remota de forma atómica. Conceptualmente, son similares a las operaciones atómicas locales de naturaleza similar (por ejemplo, incremento atómico, comparación y intercambio, etc.). Las actualizaciones a datos remotos implican una de varias operaciones sobre los datos, y actúan sobre tipos específicos de datos, como se enumera a continuación. Como tales, las transferencias atómicas tienen conocimiento del formato de los datos a los que se accede. Una única función atómica puede operar en una matriz de datos aplicando una operación atómica a cada entrada, pero la atomicidad de una operación se limita a un único tipo de dato o entrada.

Tipos de datos atómicos

Las funciones atómicas pueden operar en uno de los siguientes tipos de datos identificados. Una función atómica dada puede admitir cualquier tipo de dato, sujeto a las restricciones de implementación del proveedor.

FI_UINT16

FI_INT32
Entero con signo de 32 bits.
FI_UINT32
Entero sin signo de 32 bits.
FI_INT64
Entero con signo de 64 bits.
FI_UINT64
Entero sin signo de 64 bits.
FI_INT128
Entero con signo de 128 bits.
FI_UINT128
Entero sin signo de 128 bits.
FI_FLOAT
Un valor de punto flotante de precisión simple (IEEE 754).
FI_DOUBLE
Un valor de punto flotante de precisión doble (IEEE 754).
FI_FLOAT_COMPLEX
Un par ordenado de valores de punto flotante de precisión simple (IEEE 754), donde el primer valor representa la parte real de un número complejo y el segundo representa la parte imaginaria.
FI_DOUBLE_COMPLEX
Un par ordenado de valores de punto flotante de precisión doble (IEEE 754), donde el primer valor representa la parte real de un número complejo y el segundo representa la parte imaginaria.

FI_ATOMIC_AND
Realiza una operación AND bit a bit entre el valor de la memoria remota y el valor proporcionado. El valor original no se devuelve.
FI_ATOMIC_FETCH_OR
Realiza una operación OR bit a bit entre el valor de la memoria remota y el valor proporcionado, y devuelve el valor original.
FI_ATOMIC_OR
Realiza una operación OR bit a bit entre el valor de la memoria remota y el valor proporcionado. El valor original no se devuelve.
FI_ATOMIC_FETCH_XOR
Realiza una operación XOR bit a bit entre el valor de la memoria remota y el valor proporcionado, y devuelve el valor original.

FI_ATOMIC_FETCH_MIN
Calcula el mínimo entre el valor de la memoria remota y el valor proporcionado, almacena el resultado en la memoria remota y devuelve el valor original.

Calcula el máximo entre el valor de la memoria remota y el valor proporcionado, y almacena el resultado en la memoria remota. El valor original no se devuelve.

Compara el valor de la memoria remota con un valor de comparación proporcionado. Si son iguales, el valor proporcionado se almacena en la memoria remota. El valor original se devuelve independientemente de si se produjo una escritura.

Los operandos de atomicidad y los valores de operación pueden ser específicos de ciertos tipos de datos. Por ejemplo, las operaciones de punto flotante, complejidad o comparación solo se admiten para tipos de datos de punto flotante. Consulte la documentación específica del proveedor o consulte fi_atomicvalid para obtener información sobre el soporte.

Funciones de interfaz

Las funciones fi_atomic, fi_atomicv y fi_atomicmsg son las interfaces más comunes para realizar operaciones atómicas simples. fi_atomic y fi_atomicv admiten búferes simples y vectorizados, respectivamente, mientras que fi_atomicmsg utiliza un descriptor de mensaje para especificar búferes y otros atributos.

Las funciones fi_fetch_atomic, fi_fetch_atomicv y fi_fetch_atomicmsg son similares a sus contrapartes fi_atomic, pero además recuperan el valor original del operando remoto.

Las funciones fi_compare_atomic, fi_compare_atomicv y fi_compare_atomicmsg son similares a las funciones fetch, pero permiten una operación de comparación y ajuste condicional (CAS o SWAP).

fi_inject_atomic es una variante para operar sin conexión que no admite la recuperación del valor original ni la generación de finalizaciones.

fi_atomicvalid, fi_fetch_atomicvalid y fi_compare_atomicvalid se pueden usar para consultar el soporte de un proveedor para tipos de datos y operaciones atómicas específicas. fi_query_atomic proporciona información más detallada sobre los atributos de las operaciones atómicas admitidas.

Semántica de operación

Las operaciones atómicas garantizan que una operación en un único elemento de memoria remota se complete sin interrupciones. El tamaño de la operación está limitado por el tamaño del tipo de dato especificado. Por ejemplo, una operación FI_ATOMIC_ADD en un tipo de dato FI_UINT32 operará en un elemento de 4 bytes.

Las operaciones vectorizadas (fi_atomicv, fi_fetch_atomicv, fi_compare_atomicv) aplican la operación atómica especificada a cada elemento del vector. Sin embargo, la atomicidad se garantiza solo a nivel de elemento individual, no a nivel de toda la operación vectorizada.

Las operaciones que recuperan el valor original (fetch y compare) almacenan el valor antes de la operación en el búfer de resultado especificado. Las operaciones CAS y SWAP también pueden escribir un valor nuevo en la memoria remota, condicionalmente (CAS) o incondicionalmente (SWAP).

Las operaciones atómicas se pueden iniciar en puntos finales conectados o sin conexión. Para puntos finales sin conexión, la dirección del destino debe especificarse en el parámetro `dest_addr`.

El búfer de contexto (`context`) se puede utilizar para asociar datos definidos por el usuario con la operación atómica. Estos datos se pueden recuperar cuando la operación se completa.

Devolución de errores

En caso de éxito, estas funciones devuelven el número de bytes transferidos o un valor similar (según la función específica). En caso de error, devuelven un código de error negativo.

Operaciones Atómicas

Se definen las siguientes operaciones atómicas. Una operación atómica a menudo actúa sobre un valor objetivo en el búfer de memoria remota y un valor de origen proporcionado con la función atómica. También puede transportar datos de origen para reemplazar el valor objetivo en las operaciones de comparación e intercambio. Se proporciona una descripción conceptual de cada operación.

FI_MIN
Mínimo
if (buf[i] < addr[i])
    addr[i] = buf[i]
FI_MAX
Máximo
if (buf[i] > addr[i])
    addr[i] = buf[i]
FI_SUM
Suma
addr[i] = addr[i] + buf[i]
FI_PROD
Producto
addr[i] = addr[i] * buf[i]
FI_LOR
OR lógico
addr[i] = (addr[i] || buf[i])
FI_LAND
AND lógico
addr[i] = (addr[i] && buf[i])
FI_BOR
OR a nivel de bits
addr[i] = addr[i] | buf[i]
FI_BAND
AND a nivel de bits
addr[i] = addr[i] & buf[i]
FI_LXOR
OR exclusivo lógico (XOR)
addr[i] = ((addr[i] && !buf[i]) || (!addr[i] && buf[i]))
FI_BXOR
OR exclusivo a nivel de bits (XOR)
addr[i] = addr[i] ^ buf[i]
FI_ATOMIC_READ
Lee datos atómicamente
result[i] = addr[i]
FI_ATOMIC_WRITE
Escribe datos atómicamente
addr[i] = buf[i]
FI_CSWAP
Compara valores y si son iguales, los intercambia con los datos
if (compare[i] == addr[i])
    addr[i] = buf[i]
FI_CSWAP_NE
Compara valores y si no son iguales, los intercambia con los datos
if (compare[i] != addr[i])
    addr[i] = buf[i]
FI_CSWAP_LE
Compara valores y si son menores o iguales, los intercambia con los datos
if (compare[i] <= addr[i])
    addr[i] = buf[i]
FI_CSWAP_LT
Compara valores y si son menores, los intercambia con los datos
if (compare[i] < addr[i])
    addr[i] = buf[i]
FI_CSWAP_GE
Compara valores y si son mayores o iguales, los intercambia con los datos
if (compare[i] >= addr[i])
    addr[i] = buf[i]
FI_CSWAP_GT
Compara valores y si son mayores, los intercambia con los datos
if (compare[i] > addr[i])
    addr[i] = buf[i]
FI_MSWAP
Intercambia bits enmascarados con datos
addr[i] = (buf[i] & compare[i]) | (addr[i] & ~compare[i])
FI_DIFF
Calcula la diferencia
addr[i] = addr[i] - buf[i]

Funciones Atómicas Base

Las funciones atómicas base — fi_atomic, fi_atomicv, fi_atomicmsg — se utilizan para transmitir datos a un nodo remoto, donde se realiza la operación atómica especificada contra los datos objetivo. El resultado de una función atómica base se almacena en la región de memoria remota. La principal diferencia entre las funciones atómicas es el número y el tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

La llamada fi_atomic transfiere los datos contenidos en el búfer de datos especificado por el usuario a un nodo remoto. Para puntos finales sin conexión, el punto final de destino se especifica a través del parámetro dest_addr. A menos que el punto final se haya configurado de manera diferente, el búfer de datos pasado a fi_atomic no debe ser modificado por la aplicación hasta que la llamada fi_atomic se complete de forma asíncrona. El búfer objetivo de una operación atómica base debe permitir el acceso de lectura y/o escritura remota, según corresponda.

La llamada fi_atomicv agrega soporte para una lista de dispersión/recopilación a fi_atomic. fi_atomicv transfiere el conjunto de búferes de datos referenciados por el parámetro ioc al nodo remoto para su procesamiento.

La llamada fi_inject_atomic es una versión optimizada de fi_atomic. La función fi_inject_atomic se comporta como si se estableciera la bandera FI_INJECT transfer, y FI_COMPLETION no. Es decir, el búfer de datos está disponible para su reutilización inmediatamente al regresar de fi_inject_atomic, y no se generará ningún evento de finalización para esta operación atómica. El evento de finalización se suprimirá incluso si el punto final no se ha configurado con FI_SELECTIVE_COMPLETION. Consulte la discusión de banderas a continuación para obtener más detalles. El tamaño de mensaje solicitado que se puede utilizar con fi_inject_atomic está limitado por inject_size.

La llamada fi_atomicmsg admite funciones atómicas tanto en puntos finales conectados como sin conexión, con la capacidad de controlar la operación atómica por llamada a través del uso de banderas. La función fi_atomicmsg toma una estructura fi_msg_atomic como entrada.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* lista de dispersión/recopilación local */
    void                **desc;   /* descriptores de acceso local */
    size_t              iov_count;/* # de elementos en ioc */
    const void          *addr;    /* dirección de punto final opcional */
    const struct fi_rma_ioc *rma_iov; /* SGL remota */
    size_t              rma_iov_count;/* # de elementos en SGL remota */
    enum fi_datatype    datatype; /* tipo de dato del operando */
    enum fi_op          op;       /* operación atómica */
    void                *context; /* contexto definido por el usuario */
    uint64_t            data;     /* datos opcionales */
};
struct fi_ioc {
    void        *addr;    /* dirección local */
    size_t      count;    /* # de operandos objetivo */
};
struct fi_rma_ioc {
    uint64_t    addr;     /* dirección objetivo */
    size_t      count;    /* # de operandos objetivo */
    uint64_t    key;      /* clave de acceso */
};

La siguiente lista de operaciones atómicas son utilizables con operaciones atómicas base: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR y FI_ATOMIC_WRITE.

Funciones Fetch-Atomic

Las funciones fetch-atomic — fi_fetch_atomic, fi_fetch_atomicv y fi_fetch atomicmsg — se comportan de manera similar a la función atómica base equivalente. La diferencia entre las llamadas fetch atomic y base es que las rutinas fetch atomic devuelven el valor inicial que estaba almacenado en el objetivo al usuario. El valor inicial se lee en el búfer de resultado proporcionado por el usuario. El búfer objetivo de las operaciones fetch-atomic debe estar habilitado para acceso de lectura remota.

La siguiente lista de operaciones atómicas son utilizables con operaciones fetch-atomic: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ y FI_ATOMIC_WRITE.

Para operaciones FI_ATOMIC_READ, el operando del búfer de origen (por ejemplo, el parámetro buf de fi_fetch_atomic) se ignora y puede ser NULL. Los resultados se escriben en el búfer de resultado.

ATOMIC OPERATIONS

Atomic operations are used to perform read-modify-write operations on remote memory. The atomic operations are designed to be used with a remote memory access (RMA) buffer. However, some atomic operations can also be used with tagged messages.

Compare-Atomic Functions

Las funciones atómicas de comparación – fi_compare_atomic, fi_compare_atomicv, y fi_compare atomicmsg – se usan para operaciones que requieren comparar los datos del destino con un valor antes de realizar una operación de intercambio. Las funciones atómicas de comparación soportan: FI_CSWAP, FI_CSWAP_NE, FI_CSWAP_LE, FI_CSWAP_LT, FI_CSWAP_GE, FI_CSWAP_GT, y FI_MSWAP.

Funciones Atómicas Válidas

Las funciones atómicas válidas – fi_atomicvalid, fi_fetch_atomicvalid, y fi_compare_atomicvalid – indican qué operaciones soporta el proveedor local. Las operaciones necesarias no soportadas por el proveedor deben ser emuladas por la aplicación. Cada llamada válida corresponde a un conjunto de funciones atómicas. fi_atomicvalid verifica si un proveedor soporta una operación atómica base específica para un tipo de dato y operación dados. fi_fetch_atomicvalid indica si un proveedor soporta una operación fetch-atómica específica para un tipo de dato y operación dados. Y fi_compare_atomicvalid verifica si un proveedor soporta una operación compare-atómica especificada para un tipo de dato y operación dados.

Si una operación es soportada, una llamada atómica válida devolverá 0, junto con un recuento de unidades de datos atómicas sobre las que una única llamada a función operará.

Consultar Atributos Atómicos

La llamada fi_query_atomic actúa como una operación atómica válida mejorada (ver las definiciones de funciones atómicas válidas arriba). Se proporciona, en parte, para extensibilidad futura. La operación de consulta informa qué operaciones atómicas son soportadas por el dominio, para endpoints configurados adecuadamente.

El comportamiento de fi_query_atomic se ajusta según el parámetro de flags. Si flags es 0, la operación informa los atributos atómicos soportados para operaciones atómicas base, similar a fi_atomicvalid para endpoints. Si flags tiene el bit FI_FETCH_ATOMIC establecido, la operación se comporta de manera similar a fi_fetch_atomicvalid. De forma similar, el bit de flag FI_COMPARE_ATOMIC resulta en que la consulta actúe como fi_compare_atomicvalid. Los bits FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC no pueden ser establecidos ambos.

Si el bit FI_TAGGED está establecido, el proveedor indicará si soporta operaciones atómicas a buffers de recepción etiquetados. El bit FI_TAGGED puede ser usado por sí solo, o en conjunción con los flags FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC.

La salida de fi_query_atomic es struct fi_atomic_attr:

struct fi_atomic_attr {
    size_t count;
    size_t size;
};

El campo de atributo count es como se define para las llamadas atómicas válidas. El campo size indica el tamaño en bytes del tipo de dato atómico. El campo size es útil para tipos de datos que pueden diferir en tamaños según la plataforma o el compilador, como FI_LONG_DOUBLE.

Completados

Las operaciones atómicas completadas se informan al iniciador de la solicitud a través de una cola de completado o un contador asociado. Cualquier contexto proporcionado por el usuario especificado con la solicitud se devolverá como parte de cualquier evento de completado escrito en un CQ. Ver fi_cq para detalles del evento de completado.

Cualquier resultado devuelto al iniciador como parte de una operación atómica estará disponible antes de que se genere un evento de completado. Esto será cierto incluso si la semántica de completado solicitada proporciona una garantía más débil. Es decir, las operaciones fetch atómicas tienen semánticas FI_DELIVERY_COMPLETE. Los completados generados para otros tipos de operaciones atómicas indican que es seguro reutilizar los buffers de datos de origen.

Cualquier actualización de datos en el destino de una operación atómica será visible para los agentes (procesos de CPU, NICs y otros dispositivos) en el nodo de destino antes de que ocurra una de las siguientes situaciones. Si la operación atómica genera un evento de completado o actualiza un contador de completado en el endpoint de destino, los resultados estarán disponibles antes de la notificación de completado. Después de procesar un completado para la operación atómica, si el iniciador envía una transferencia entre los mismos endpoints que genera un completado en el destino, los resultados estarán disponibles antes del evento de la transferencia posterior. O, si una transferencia de datos con valla (fenced) del iniciador sigue a la solicitud atómica, los resultados estarán disponibles antes de un completado en el destino para la transferencia con valla.

La corrección de las operaciones atómicas en una región de memoria de destino solo está garantizada cuando es realizada por un único actor para una ventana de tiempo dada. Un actor se define como un único dominio libfabric en el destino (identificado por el nombre del dominio, y no por una instancia abierta de ese dominio), un complejo de CPU coherente, u otro dispositivo (por ejemplo, GPU) capaz de realizar operaciones atómicas en la memoria de destino. Los resultados de las operaciones atómicas realizadas por múltiples actores simultáneamente no están definidos. Por ejemplo, emitir operaciones atómicas basadas en CPU a una región de destino que está siendo actualizada concurrentemente por operaciones atómicas basadas en NIC puede dejar los datos de la región en un estado desconocido. Los resultados de las operaciones atómicas del primer actor deben ser visibles para un segundo actor antes de que el segundo actor emita sus propias operaciones atómicas.

FLAGS

Las llamadas fi_atomicmsg, fi_fetch_atomicmsg, y fi_compare_atomicmsg permiten al usuario especificar flags que pueden cambiar la operación de transferencia de datos por defecto. Los flags especificados con operaciones de mensajes atómicos anulan la mayoría de los flags configurados previamente con el endpoint, excepto donde se indica (ver fi_control). La siguiente lista de flags es utilizable con llamadas de mensajes atómicos.

FI_COMPLETION
Indica que se debe generar una entrada de completado para la operación especificada. El endpoint debe estar enlazado a una cola de completado con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o este flag se ignora.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que se publicarán inmediatamente después de que la llamada actual retorne. El uso de este flag puede mejorar el rendimiento al permitir que el proveedor optimice su acceso al hardware de la red.
FI_INJECT
Indica que el control de los buffers de datos constantes debe devolverse al usuario inmediatamente después de que la llamada retorne, incluso si la operación se maneja de forma asíncrona. Esto puede requerir que la implementación del proveedor subyacente copie los datos a un buffer local y transfiera desde ese buffer. Los buffers de datos constantes se refieren a cualquier buffer de datos o iovec utilizado por las APIs atómicas que están marcados como `const'. Los buffers no constantes o de salida no se ven afectados por este flag y pueden ser accedidos por el proveedor en cualquier momento hasta que la operación se haya completado. Este flag solo puede ser utilizado con mensajes más pequeños que inject_size.
FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como operación con valla, y cualquier operación publicada después de la operación con valla se pospondrán hasta que todas las operaciones anteriores dirigidas al mismo endpoint par hayan completado. Las operaciones publicadas después de la valla verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación con valla.

El orden de las operaciones que comienzan con la publicación de la operación con valla (inclusive) hasta la publicación de una operación con valla subsiguiente (exclusiva) está controlado por las semánticas de ordenación del endpoint. Ambas ordenaciones de mensajes y datos son necesarias si los resultados de dos operaciones atómicas a los mismos buffers de memoria deben reflejar la segunda operación actuando sobre los resultados de la primera.

FI_TAGGED
Especifica que el destino de la operación atómica es un buffer de recepción etiquetado en lugar de un buffer RMA. Cuando un buffer etiquetado es la región de memoria de destino, el parámetro addr se utiliza como un offset de byte basado en 0 en el buffer etiquetado, con el parámetro key especificando la etiqueta.

VALOR DE RETORNO

Devuelve 0 si la operación es exitosa. En caso de error, se devuelve un valor negativo correspondiente al errno de fabric. Los valores de errno de fabric se definen en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Ver fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
-FI_EOPNOTSUPP
La operación atómica solicitada no es soportada en este endpoint.
-FI_EMSGSIZE
El número de operaciones atómicas en una única solicitud excede lo soportado por el proveedor subyacente.

NOTAS

Las operaciones atómicas operan sobre un array de valores de un tipo de dato específico. La atomicidad solo está garantizada para cada operación de tipo de dato, no para todo el array. El siguiente pseudocódigo demuestra esta operación para una escritura atómica de entero sin signo de 64 bits. ATOMIC_WRITE_U64 es una macro dependiente de la plataforma que escribe atmicamente 8 bytes en una ubicación de memoria alineada.

fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]);
}

El número de elementos del array sobre los que operar se especifica mediante un parámetro de recuento (count). Este debe estar entre 1 y el máximo devuelto a través de la operación válida relevante, inclusive. La operación y el tipo de dato solicitados también deben ser válidos para el proveedor dado.

El orden de las operaciones atómicas realizadas como parte de diferentes mensajes de solicitud está sujeto a las definiciones de ordenación de mensajes y datos asignadas a los endpoints transmisores y receptores. Se requieren tanto la ordenación de mensajes como la de datos si los resultados de dos operaciones atómicas sobre los mismos buffers de memoria deben reflejar que la segunda operación actúa sobre los resultados de la primera. Ver fi_endpoint(3) para más detalles y restricciones de tamaño de mensaje.
