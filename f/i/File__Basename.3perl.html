File::Basename(3perl) Guía de Referencia para Programadores de Perl File::Basename(3perl)

NOMBRE

File::Basename - Analiza rutas de archivos en directorio, nombre de archivo y sufijo.

SINOPSIS

use File::Basename;
my ($name, $path, $suffix) = fileparse($fullname, @suffixlist);
my $name = fileparse($fullname, @suffixlist);
my $basename = basename($fullname, @suffixlist);
my $dirname  = dirname($fullname);

DESCRIPCIÓN

Estas rutinas le permiten analizar rutas de archivos en su directorio, nombre de archivo y sufijo.

NOTA: dirname() y basename() emulan los comportamientos y peculiaridades de las funciones del shell y de C con el mismo nombre. Consulte la documentación de cada función para obtener detalles. Si su interés es solo analizar rutas, es más seguro usar los métodos splitpath() y splitdir() de File::Spec.

Se garantiza que

# Donde $path_separator es / para Unix, \ para Windows, etc...
dirname($path) . $path_separator . basename($path);

es equivalente a la ruta original en todos los sistemas excepto en VMS.

"fileparse"
my($filename, $dirs, $suffix) = fileparse($path);
my($filename, $dirs, $suffix) = fileparse($path, @suffixes);
my $filename                  = fileparse($path, @suffixes);

La rutina fileparse() divide una ruta de archivo en sus $dirs, $filename y (opcionalmente) el $suffixdel nombre de archivo.

$dirs contiene todo hasta e incluyendo el último separador de directorio en $path incluyendo el volumen (si aplica). El resto de $path es el $filename.

# En Unix devuelve ("baz", "/foo/bar/", "")
fileparse("/foo/bar/baz");
# En Windows devuelve ("baz", 'C:\foo\bar\', "")
fileparse('C:\foo\bar\baz');
# En Unix devuelve ("", "/foo/bar/baz/", "")
fileparse("/foo/bar/baz/");

Si se proporcionan @suffixes , cada elemento es un patrón (ya sea una cadena o un "qr//") que se compara con el final de $filename. La parte que coincide se elimina y se convierte en el $suffix.

# En Unix devuelve ("baz", "/foo/bar/", ".txt")
fileparse("/foo/bar/baz.txt", qr/\.[^.]*/);

Si el tipo no es Unix (ver "fileparse_set_fstype"), la coincidencia de patrones para la eliminación de sufijos se realiza sin distinguir mayúsculas de minúsculas, ya que esos sistemas no distinguen mayúsculas de minúsculas al abrir archivos existentes.

Se garantiza que "$dirs . $filename . $suffix" denotará la misma ubicación que la ruta original $path.

"basename"
my $filename = basename($path);
my $filename = basename($path, @suffixes);

Esta función se proporciona por compatibilidad con el comando de shell de Unix basename(1). No SIEMPRE devuelve la parte del nombre de archivo de una ruta como usted podría esperar. Para estar seguro, si desea la parte del nombre de archivo de una ruta, use fileparse().

basename() devuelve el último nivel de una ruta de archivo incluso si el último nivel es claramente un directorio. En efecto, actúa como pop() para rutas. Esto difiere del comportamiento de fileparse().

# Ambas devuelven "bar"
basename("/foo/bar");
basename("/foo/bar/");

@suffixes funcionan como en fileparse() excepto que todas las metacaracteres de expresiones regulares se citan.

# Estas dos llamadas a función son equivalentes.
my $filename = basename("/foo/bar/baz.txt",  ".txt");
my $filename = fileparse("/foo/bar/baz.txt", qr/\Q.txt\E/);

Tenga en cuenta también que, para ser compatible con el comando de shell, basename() no elimina un sufijo si es idéntico a los caracteres restantes del nombre de archivo.

"dirname"
Esta función se proporciona por compatibilidad con el comando de shell de Unix dirname(1) y ha heredado algunas de sus peculiaridades. A pesar de su nombre, no SIEMPRE devuelve el nombre del directorio como usted podría esperar. Para estar seguro, si desea el nombre del directorio de una ruta, use fileparse().

Solo en VMS (donde no hay ambigüedad entre las partes de archivo y directorio de una ruta) y AmigaOS (posiblemente debido a una peculiaridad de implementación en este módulo), dirname() funciona como fileparse($path), devolviendo solo los $dirs.

# En VMS y AmigaOS
my $dirs = dirname($path);

Cuando se usa sintaxis Unix o MSDOS, esto emula la función de shell dirname(1) que es sutilmente diferente de cómo funciona fileparse() . Devuelve todo excepto el último nivel de una ruta de archivo incluso si el último nivel es claramente un directorio. En efecto, no devuelve la parte del directorio sino simplemente la ruta un nivel arriba, actuando como chop() para rutas de archivo.

Además, a diferencia de fileparse(), dirname() no incluye una barra final en la ruta que devuelve.

# devuelve /foo/bar.  fileparse() devolvería /foo/bar/
dirname("/foo/bar/baz");
# también devuelve /foo/bar a pesar de que baz es claramente un
# directorio.  fileparse() devolvería /foo/bar/baz/
dirname("/foo/bar/baz/");
# devuelve '.'.  fileparse() devolvería 'foo/'
dirname("foo/");

En VMS, si no hay información de directorio en la $path, se utiliza el dispositivo y directorio predeterminados actuales.

"fileparse_set_fstype"
my $type = fileparse_set_fstype();
my $previous_type = fileparse_set_fstype($type);

Normalmente, File::Basename asumirá un tipo de ruta de archivo nativo de su sistema operativo actual (es decir, estilo /foo/bar en Unix, \foo\bar en Windows, etc.). Con esta función puede anular esa suposición.

Los $types válidos son "MacOS", "VMS", "AmigaOS", "OS2", "RISCOS", "MSWin32", "DOS" (también "MSDOS" para compatibilidad con errores anteriores), "Epoc" y "Unix" (todos sin distinguir mayúsculas de minúsculas). Si se proporciona un $type no reconocido, se asumirá "Unix".

Si ha seleccionado la sintaxis VMS y la especificación de archivo que pasa a una de estas rutinas contiene una "/", asumirán que está usando emulación Unix y aplicarán las reglas de sintaxis Unix en su lugar, solo para esa llamada a función.

VER TAMBIÉN

dirname(1), basename(1), File::Spec
