NOMBRE

fi_atomic - Funciones atómicas remotas

fi_atomic / fi_atomicv / fi_atomicmsg / fi_inject_atomic
Inicia una operación atómica en memoria remota
fi_fetch_atomic / fi_fetch_atomicv / fi_fetch_atomicmsg
Inicia una operación atómica en memoria remota, recuperando el valor inicial.
fi_compare_atomic / fi_compare_atomicv / fi_compare_atomicmsg
Inicia una operación atómica de comparación en memoria remota, recuperando el valor inicial.

fi_atomicvalid / fi_fetch_atomicvalid / fi_compare_atomicvalid / fi_query_atomic : Indica si un proveedor soporta una operación atómica específica

DESCRIPCIÓN

Las transferencias atómicas se utilizan para leer y actualizar datos ubicados en regiones de memoria remota de forma atómica. Conceptualmente, son similares a las operaciones atómicas locales de naturaleza similar (por ejemplo, incremento atómico, comparar e intercambiar, etc.). Las actualizaciones a datos remotos implican una de varias operaciones sobre los datos y actúan sobre tipos específicos de datos, como se indica a continuación. Como tales, las transferencias atómicas tienen conocimiento del formato de los datos a los que se accede. Una única función atómica puede operar sobre una matriz de datos aplicando una operación atómica a cada entrada, pero la atomicidad de una operación se limita a un único tipo de dato o entrada.

Tipos de datos atómicos

Las funciones atómicas pueden operar sobre uno de los siguientes tipos de datos identificados. Una función atómica determinada puede soportar cualquier tipo de dato, sujeto a las restricciones de implementación del proveedor.

FI_INT8
Entero con signo de 8 bits.
FI_UINT8
Entero sin signo de 8 bits.
FI_INT16
Entero con signo de 16 bits.
FI_UINT16
Entero sin signo de 16 bits.
FI_INT32
Entero con signo de 32 bits.
FI_UINT32
Entero sin signo de 32 bits.
FI_INT64
Entero con signo de 64 bits.
FI_UINT64
Entero sin signo de 64 bits.
FI_INT128
Entero con signo de 128 bits.
FI_UINT128
Entero sin signo de 128 bits.
FI_FLOAT
Un valor de punto flotante de precisión simple (IEEE 754).
FI_DOUBLE
Un valor de punto flotante de doble precisión (IEEE 754).
FI_FLOAT_COMPLEX
Un par ordenado de valores de punto flotante de precisión simple (IEEE 754), donde el primer valor representa la parte real de un número complejo y el segundo representa la parte imaginaria.
FI_DOUBLE_COMPLEX
Un par ordenado de valores de punto flotante de doble precisión (IEEE 754), donde el primer valor representa la parte real de un número complejo y el segundo representa la parte imaginaria.
FI_LONG_DOUBLE
Un valor de punto flotante de precisión de doble extensión (IEEE 754). Tenga en cuenta que el tamaño de un long double y el número de bits utilizados para la precisión dependen del compilador, la plataforma y/o el proveedor. Los desarrolladores que usen long double deben asegurarse de que libfabric se compile usando un formato de long double que sea compatible con su aplicación y que ese formato sea soportado por el proveedor. El mecanismo utilizado para esta validación está actualmente fuera del alcance de la API de libfabric.
FI_LONG_DOUBLE_COMPLEX
Un par ordenado de valores de punto flotante de precisión de doble extensión (IEEE 754), donde el primer valor representa la parte real de un número complejo y el segundo representa la parte imaginaria.
FI_FLOAT16
Valor de punto flotante de precisión media de 16 bits (IEEE 754-2008).
FI_BFLOAT16
Valor de punto flotante "brain" de 16 bits (IEEE 754-2008).
FI_FLOAT8_E4M3
Valor de punto flotante de 8 bits con exponente de 4 bits y mantisa de 3 bits.
FI_FLOAT8_E5M2
Valor de punto flotante de 8 bits con exponente de 5 bits y mantisa de 2 bits.

Operaciones Atómicas

Se definen las siguientes operaciones atómicas. Una operación atómica a menudo actúa contra un valor objetivo en el búfer de memoria remoto y un valor fuente proporcionado con la función atómica. También puede transportar datos fuente para reemplazar el valor objetivo en operaciones de intercambio condicional (compare and swap). Se proporciona una descripción conceptual de cada operación.

FI_MIN
Mínimo
if (buf[i] < addr[i])
    addr[i] = buf[i]
FI_MAX
Máximo
if (buf[i] > addr[i])
    addr[i] = buf[i]
FI_SUM
Suma
addr[i] = addr[i] + buf[i]
FI_PROD
Producto
addr[i] = addr[i] * buf[i]
FI_LOR
OR lógico
addr[i] = (addr[i] || buf[i])
FI_LAND
AND lógico
addr[i] = (addr[i] && buf[i])
FI_BOR
OR a nivel de bits
addr[i] = addr[i] | buf[i]
FI_BAND
AND a nivel de bits
addr[i] = addr[i] & buf[i]
FI_LXOR
XOR lógico (exclusivo lógico)
addr[i] = ((addr[i] && !buf[i]) || (!addr[i] && buf[i]))
FI_BXOR
XOR a nivel de bits (exclusivo a nivel de bits)
addr[i] = addr[i] ^ buf[i]
FI_ATOMIC_READ
Leer datos de forma atómica
result[i] = addr[i]
FI_ATOMIC_WRITE
Escribir datos de forma atómica
addr[i] = buf[i]
FI_CSWAP
Comparar valores y, si son iguales, intercambiarlos con los datos
if (compare[i] == addr[i])
    addr[i] = buf[i]
FI_CSWAP_NE
Comparar valores y, si no son iguales, intercambiarlos con los datos
if (compare[i] != addr[i])
    addr[i] = buf[i]
FI_CSWAP_LE
Comparar valores y, si son menores o iguales, intercambiarlos con los datos
if (compare[i] <= addr[i])
    addr[i] = buf[i]
FI_CSWAP_LT
Comparar valores y, si son menores, intercambiarlos con los datos
if (compare[i] < addr[i])
    addr[i] = buf[i]
FI_CSWAP_GE
Comparar valores y, si son mayores o iguales, intercambiarlos con los datos
if (compare[i] >= addr[i])
    addr[i] = buf[i]
FI_CSWAP_GT
Comparar valores y, si son mayores, intercambiarlos con los datos
if (compare[i] > addr[i])
    addr[i] = buf[i]
FI_MSWAP
Intercambiar bits enmascarados con los datos
addr[i] = (buf[i] & compare[i]) | (addr[i] & ~compare[i])
FI_DIFF
Calcular la diferencia
addr[i] = addr[i] - buf[i]

Funciones Atómicas Base

Las funciones atómicas base – fi_atomic, fi_atomicv, fi_atomicmsg – se utilizan para transmitir datos a un nodo remoto, donde se realiza la operación atómica especificada contra los datos de destino. El resultado de una función atómica base se almacena en la región de memoria remota. La principal diferencia entre las funciones atómicas es el número y el tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

La llamada fi_atomic transfiere los datos contenidos en el búfer de datos especificado por el usuario a un nodo remoto. Para los puntos finales sin conexión, el punto final de destino se especifica a través del parámetro dest_addr. A menos que el punto final se haya configurado de otra manera, el búfer de datos pasado a fi_atomic no debe ser tocado por la aplicación hasta que la llamada fi_atomic se complete de forma asíncrona. El búfer de destino de una operación atómica base debe permitir el acceso de lectura y/o escritura remota, según corresponda.

La llamada fi_atomicv añade soporte para una lista de dispersión-agrupamiento (scatter-gather) a fi_atomic. La fi_atomicv transfiere el conjunto de búferes de datos referenciados por el parámetro ioc al nodo remoto para su procesamiento.

La llamada fi_inject_atomic es una versión optimizada de fi_atomic. La función fi_inject_atomic se comporta como si la marca de transferencia FI_INJECT estuviera establecida y FI_COMPLETION no lo estuviera. Es decir, el búfer de datos está disponible para su reutilización inmediatamente al regresar de fi_inject_atomic, y no se generará ningún evento de finalización para esta operación atómica. El evento de finalización se suprimirá incluso si el punto final no ha sido configurado con FI_SELECTIVE_COMPLETION. Consulte la discusión de marcas más abajo para más detalles. El tamaño de mensaje solicitado que se puede usar con fi_inject_atomic está limitado por inject_size.

La llamada fi_atomicmsg soporta funciones atómicas sobre puntos finales tanto conectados como sin conexión, con la capacidad de controlar la operación atómica por llamada mediante el uso de marcas (flags). La función fi_atomicmsg toma un struct fi_msg_atomic como entrada.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* arreglo local de dispersión-agrupamiento */
    void                **desc;   /* descriptores de acceso locales */
    size_t              iov_count;/* # de elementos en ioc */
    const void          *addr;    /* dirección del punto final (opcional) */
    const struct fi_rma_ioc *ra_iov; /* SGL remoto */
    size_t              rma_iov_count;/* # de elementos en el SGL remoto */
    enum fi_datatype    datatype; /* tipo de dato del operando */
    enum fi_op          op;       /* operación atómica */
    void                *context; /* contexto definido por el usuario */
    uint64_t            data;     /* datos (opcional) */
};
struct fi_ioc {
    void        *addr;    /* dirección local */
    size_t      count;    /* # de operandos objetivo */
};
struct fi_rma_ioc {
    uint64_t    addr;     /* dirección objetivo */
    size_t      count;    /* # de operandos objetivo */
    uint64_t    key;      /* clave de acceso */
};

La siguiente lista de operaciones atómicas es utilizable con operaciones atómicas base: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR y FI_ATOMIC_WRITE.

Funciones Atómicas con Obtención (Fetch-Atomic)

Las funciones atómicas con obtención – fi_fetch_atomic, fi_fetch_atomicv y fi_fetch atomicmsg – se comportan de manera similar a la función atómica base equivalente. La diferencia entre las llamadas atómicas con obtención y las base es que las rutinas de obtención atómica devuelven al usuario el valor inicial que estaba almacenado en el destino. El valor inicial se lee en el búfer de resultado proporcionado por el usuario. El búfer de destino de las operaciones atómicas con obtención debe tener habilitado el acceso de lectura remota.

La siguiente lista de operaciones atómicas es utilizable con operaciones atómicas con obtención: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ y FI_ATOMIC_WRITE.

Para las operaciones FI_ATOMIC_READ, el operando del búfer fuente (por ejemplo, el parámetro buf de fi_fetch_atomic) se ignora y puede ser NULL. Los resultados se escriben en el búfer de resultado.

FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como la operación con valla, y cualquier operación publicada después de la operación con valla se aplazarán hasta que todas las operaciones anteriores dirigidas al mismo punto de conexión par hayan completado. Las operaciones publicadas después de la valla verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación con valla.

El orden de las operaciones que comienzan con la publicación de la operación con valla (inclusive) hasta la publicación de una operación con valla subsiguiente (exclusiva) está controlado por la semántica de ordenación del punto de conexión.

FI_TAGGED
Especifica que el destino de la operación atómica es un búfer de recepción etiquetado en lugar de un búfer RMA. Cuando un búfer etiquetado es la región de memoria de destino, el parámetro addr se utiliza como un desplazamiento de bytes basado en 0 en el búfer etiquetado, y el parámetro key especifica la etiqueta.

VALOR DE RETORNO

Devuelve 0 si tiene éxito. En caso de error, se devuelve un valor negativo correspondiente al errno de fabric. Los valores de errno de fabric se definen en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Consulte fi_msg(3) para obtener una descripción detallada del manejo de FI_EAGAIN.
-FI_EOPNOTSUPP
La operación atómica solicitada no es compatible con este punto de conexión.
-FI_EMSGSIZE
El número de operaciones atómicas en una sola solicitud excede lo admitido por el proveedor subyacente.

NOTAS

Las operaciones atómicas operan sobre una matriz de valores de un tipo de dato específico. La atomicidad solo está garantizada para cada operación de tipo de dato, no para toda la matriz. El siguiente pseudocódigo demuestra esta operación para una escritura atómica atómica sin signo de 64 bits. ATOMIC_WRITE_U64 es una macro dependiente de la plataforma que escribe atómica mente 8 bytes en una ubicación de memoria alineada.

fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]);
}

El número de elementos de matriz sobre los que operar se especifica a través de un parámetro count. Este debe estar entre 1 y el máximo devuelto a través de la operación válida relevante, inclusive. La operación y el tipo de dato solicitados también deben ser válidos para el proveedor dado.

El orden de las operaciones atómicas realizadas como parte de diferentes mensajes de solicitud está sujeto a las definiciones de ordenación de mensajes y datos asignadas a los puntos de conexión de transmisión y recepción. Se requiere la ordenación de mensajes y datos si los resultados de dos operaciones atómicas en los mismos búferes de memoria deben reflejar la segunda operación actuando sobre los resultados de la primera. Consulte fi_endpoint(3) para obtener más detalles y restricciones de tamaño de mensaje.
