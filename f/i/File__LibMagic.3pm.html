File::LibMagic(3) Documentación de Contribución del Usuario de Perl File::LibMagic(3)

NOMBRE

File::LibMagic - Determina tipos MIME de datos o archivos usando libmagic

VERSIÓN

versión 1.23

SINOPSIS

use File::LibMagic;
my $magic = File::LibMagic->new;
my $info = $magic->info_from_filename('ruta/al/archivo');
# Imprime una descripción como "texto ASCII"
print $info->{description};
# Imprime un tipo MIME como "text/plain"
print $info->{mime_type};
# Imprime una codificación de caracteres como "us-ascii"
print $info->{encoding};
# Imprime un tipo MIME con codificación como "text/plain; charset=us-ascii"
print $info->{mime_with_encoding};
my $contenido_archivo = read_file('ruta/al/archivo');
$info = $magic->info_from_string($contenido_archivo);
open my $fh, '<', 'ruta/al/archivo' or die $!;
$info = $magic->info_from_handle($fh);

DESCRIPCIÓN

El módulo "File::LibMagic" es una interfaz simple de Perl para libmagic del paquete file (versión 4.x o 5.x). Necesitarás tanto la biblioteca (libmagic.so) como el archivo de cabecera (magic.h) para compilar este módulo de Perl.

Instalando libmagic

En Debian/Ubuntu ejecuta:

sudo apt-get install libmagic-dev

en Red Hat ejecuta:

sudo yum install file-devel

En Mac puedes usar homebrew (https://brew.sh/):

brew install libmagic

Especificando lib y/o directorios de inclusión

En algunos sistemas, puede que necesites pasar directorios de biblioteca e inclusión adicionales a Makefile.PL. Puedes hacerlo con los parámetros `--lib` y `--include`:

perl Makefile.PL --lib /usr/local/lib --include /usr/local/include

Puedes pasar estos parámetros varias veces para especificar más de una ubicación.

API

Este módulo proporciona una API orientada a objetos con los siguientes métodos:

File::LibMagic->new

Crea un nuevo objeto File::LibMagic.

El uso de la interfaz orientada a objetos solo abre la base de datos mágica una vez, lo que probablemente sea lo más eficiente para usos repetidos.

Cada objeto "File::LibMagic" carga la base de datos mágica de forma independiente de otros objetos "File::LibMagic", por lo que es posible que desees compartir un único objeto entre muchos módulos.

Este método toma los siguientes parámetros nombrados:

  • "magic_file"

    Debe ser una cadena o una referencia a un array que contenga uno o más archivos mágicos.

    Si un archivo que proporcionas no existe, el constructor lanzará una excepción, pero solo con libmagic 4.17+.

    Si no estableces este parámetro, el constructor lanzará una excepción si no puede encontrar ningún archivo mágico en absoluto.

    Ten en cuenta que incluso si estás utilizando un archivo personalizado, probablemente también quieras usar el archivo estándar (/usr/share/misc/magic en mi sistema, el tuyo puede variar).

  • "follow_symlinks"

    Si esto es verdadero, las llamadas a "$magic->info_from_filename" seguirán los enlaces simbólicos al archivo real.

  • "uncompress"

    Si esto es verdadero, los archivos comprimidos (como los archivos gzip) se descomprimirán, y los diversos métodos "info_from_*" devolverán información sobre el archivo descomprimido.

  • Límites de procesamiento

    Las versiones más nuevas de la biblioteca libmagic tienen una serie de límites para evitar que archivos malformados o maliciosos causen agotamiento de recursos u otros errores.

    Si tu libmagic lo soporta, puedes establecer los siguientes límites a través de parámetros del constructor. Si tu versión no soporta establecer estos límites, pasar estas opciones hará que el constructor falle. Además, los límites específicos se introdujeron a lo largo de varias versiones de libmagic, y tu versión de libmagic puede no soportar cada parámetro. Usar un parámetro no soportado por tu libmagic también hará que el constructor falle.

  • "max_indir"

    Esto limita la recursión para la indirección al procesar entradas en el archivo mágico.

  • "max_name"

    Esto limita el número máximo de niveles de magia de nombre/uso que se procesarán en el archivo mágico.

  • "max_elf_notes"

    Esto limita el número máximo de notas ELF que se procesarán al determinar el tipo MIME de un archivo.

  • "max_elf_phnum"

    Esto limita el número máximo de secciones de programa ELF que se procesarán al determinar el tipo MIME de un archivo.

  • "max_elf_shnum"

    Esto limita el número máximo de secciones ELF que se procesarán al determinar el tipo MIME de un archivo.

  • "max_regex"

    Esto limita el tamaño máximo de las expresiones regulares al procesar entradas en el archivo mágico.

  • "max_bytes"

    Esto limita el número máximo de bytes leídos de un archivo al determinar el tipo MIME de un archivo.

Los valores de estos parámetros deben ser límites enteros.

•
"max_future_compat"

Para compatibilidad con futuras adiciones a los parámetros de límite de procesamiento de libmagic, puedes pasar un parámetro "max_future_compat". Esto es una referencia a un hash donde las claves son valores constantes (enteros definidos por libmagic, no nombres) y los valores son el límite que deseas establecer.

$magic->info_from_filename('ruta/al/archivo')

Este método devuelve información sobre el archivo dado. El valor devuelto es una referencia a un hash con cuatro claves:

  • "description"

    Una descripción textual del contenido del archivo como "texto C ASCII".

  • "mime_type"

    El tipo MIME sin codificación de caracteres, como "text/x-c".

  • "encoding"

    Solo la codificación de caracteres, como "us-ascii".

  • "mime_with_encoding"

    El tipo MIME con codificación de caracteres, como "text/x-c; charset=us-ascii". Ten en cuenta que si no se encontró ninguna codificación, esto será lo mismo que la clave "mime_type".

$magic->info_from_string($string)

Este método devuelve información sobre el contenido de la cadena dada. La cadena se puede pasar como una referencia para ahorrar memoria.

El valor devuelto es el mismo que el de "$mime->info_from_filename".

$magic->info_from_handle($fh)

Este método devuelve información sobre el contenido leído del manejador de archivo dado. Leerá datos comenzando desde la posición actual del manejador, y dejará el manejador en la misma posición después de leer.

RELACIONADOS

Andreas creó File::LibMagic porque quería usar libmagic (de file 4.x). File::MMagic solo funcionaba con file 3.

x.

File::MimeInfo::Magic usa el archivo mágico de freedesktop.org que está codificado en XML, y por lo tanto no es el enfoque más rápido. Consulta https://mail.gnome.org/archives/nautilus-list/2003-December/msg00260.html para una discusión sobre este

problema.

File::Type usa un archivo mágico relativamente pequeño, que está direct

amente hackeado en el código del módulo. Es bastante rápido pero la
base de datos es bastante pequeña en relación con el paquete file.
