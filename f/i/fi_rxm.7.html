DESCRIPCIÓN

GENERAL

El proveedor RxM (ofi_rxm) es un proveedor de utilidad que soporta puntos de extremo del tipo FI_EP_RDM emulados sobre puntos de extremo del tipo FI_EP_MSG de un proveedo

r central subyacente. Los puntos de extremo FI_EP_RDM tienen una interfaz de datagrama fiable y RxM emula esto ocultando la gestión de conexiones de los puntos de extremo
FI_EP_MSG subyacentes al usuario. Además, RxM puede ocultar el requisito de registro de memoria a un proveedor central como verbs si las aplicaciones no lo soportan.

Requisitos para las

Las aplicaciones deben tener esto en cuenta y reintentar hasta que la operación tenga

Limitaciones de

progreso

Al enviar mensajes grandes, una aplicación que realice un sread o espere en el descriptor de archivo de la CQ puede no obtener una finalización al leer la CQ después de ser despertada de la espera. La aplicación tiene qu

e realizar sread o esperar en el descriptor de archivo nuevamente. Esto es necesario porque RxM usa un protocolo de encuentro para envíos de mensajes grandes. Una aplicación sería despertada de la espera en el fd de la
CQ cuando la solicitud del protocolo de encuentro se complete, pero tendría que esperar de nuevo para obtener un ACK del receptor que indique la finalización de la transferencia del mensaje grande por lectura RMA remota.

Limitaciones de

FI_ATOMIC

La capacidad FI_ATOMIC solo se listará en el fi_info si el parámetro de sugerencias de fi_i

nfo especifica FI_ATOMIC. Si se solicita FI_ATOMIC, el orden de mensaje FI_ORDER_RAR, FI_O
RDER_RAW, FI_ORDER_WAR, FI_ORDER_WAW, FI_ORDER_SAR y FI_ORDER_SAW no pueden ser soportados.

PARÁMETROS DE TIEMPO DE

EJECUCIÓN

El proveedor ofi_rxm verifica las siguientes variables de

entorno.
FI_OFI_RXM_BUFFER_S
IZE
Define el tamaño del búfer de transmisión / tamaño de inyección. Los mensajes de un tamaño menor o igual a este serían transmitidos vía un protocolo eager y los mensajes de un tamaño mayor serían transmitidos vía un protocolo de encuentro o SAR (Segmentación Y Reensamblaje). Los datos de transmisión serían copiados hasta este tamaño (por defecto: ~16k)
.
FI_OFI_RXM_COMP_PER_PROGR
ESS
Define el número máximo de entradas de CQ del proveedor MSG (por defecto: 1) que serían leídas por cada progreso (lectura de CQ de
RxM).
FI_OFI_RXM_ENABLE_DYN_R
BUF
Habilita el soporte para búferes de recepción dinámicos, si está disponible por el proveedor de punto de extremo de mensaje. Esta característica permite la colocación directa de los datos del mensaje recibido en los búferes de la aplicación, evitando los búferes de rebote de RxM. Esta característica apunta a proveedores que proveen búferes de red internos, como el proveedor tcp. (por defecto:
false)
FI_OFI_RXM_SAR_LI
MIT
Establezca esta variable de entorno para controlar el protocolo SAR (Segmentación Y Reensamblaje) de RxM. Los mensajes de un tamaño mayor que este (por defecto: 128 Kb) serían transmitidos vía protocolo de
encuentro.
FI_OFI_RXM_USE_
SRX
Establezca esto en 1 para usar el contexto de recepción compartido del proveedor MSG, o en 0 para deshabilitar el uso del contexto de recepción compartido. Los contextos de recepción compartidos reducen el uso general de memoria, pero pueden aumentar la latencia del mensaje. Si no se establece, verbs no usará contextos de recepción compartidos por defecto, pero el proveedor tcp sí lo
hará.
FI_OFI_RXM_TX_S
IZE
Define el tamaño por defecto del contexto TX (por defecto:
1024)
FI_OFI_RXM_RX_S
IZE
Define el tamaño por defecto del contexto RX (por defecto:
1024)
FI_OFI_RXM_MSG_TX_S
IZE
Define el tamaño TX de FI_EP_MSG que sería solicitado (por defecto:
128).
FI_OFI_RXM_MSG_RX_S
IZE
Define el tamaño RX de FI_EP_MSG que sería solicitado (por defecto:
128).
FI_UNIVERSE_S
IZE
Define el número esperado de rangos / pares con los que un punto de extremo se comunicaría (por defecto:
256).
FI_OFI_RXM_CM_PROGRESS_INTER
VAL
Define la duración del tiempo en microsegundos entre llamadas a las funciones de progresión de CM de RxM cuando se usa progreso manual. Valores más altos pueden proporcionar menos ruido para las llamadas a las funciones fi_cq read, pero puede aumentar el tiempo de configuración de la conexión (predeterminado:
10000)
FI_OFI_RXM_CQ_EQ_FAIRN
ESS
Define el número máximo de entradas de CQ del proveedor de mensajes que se pueden leer de forma consecutiva a lo largo de las llamadas de progreso sin comprobar si se ha alcanzado el intervalo de progreso de CM (predeterminado:
128)
FI_OFI_RXM_DETECT_HMEM_IF
ACE
Establezca esto en 1 para permitir la detección automática de la interfaz HMEM de los búferes del
usuario cuando dicha información no se proporciona. Esta característica permite que dichos búfer
es sean copiados o registrados (por ejemplo, en Rendezvous) internamente por RxM. Tenga en cuent
a que con esta opción no se realiza ningún registro de memoria adicional. (predeterminado: false)

Ajust

e

Ancho de

banda

Para optimizar el ancho de banda, asegúrese de usar valores más altos que los predeterminados para FI_OFI_RXM_TX_SIZE, FI_OFI_RXM_RX_SIZE, FI_OFI_RXM_MSG_TX_SIZE, FI_OFI_RXM_MSG_RX_SIZE, sujeto a los límites de memoria del sistema y los tamaños tx y rx soportados por el proveedor

MSG.

FI_OFI_RXM_SAR_LIMIT es otro pará

metro que se puede experimentar
para optimizar el ancho de banda.

Memori

a

Para conservar la memoria, asegúrese de que FI_UNIVERSE_SIZE esté establec

ido en lo que se requiere. De manera similar, verifique que las variables
de entorno FI_OFI_RXM_TX_SIZE, FI_OFI_RXM_RX_SIZE, FI_OFI_RXM_MSG_TX_SIZE y
FI_OFI_RXM_MSG_RX_SIZE estén establecidas solo en los valores requeridos.

NOTA

S

La API de transferencia de datos puede devolver -FI_EAGAIN durante la confi

guración de conexión bajo demanda del proveedor central FI_MSG_EP. Consult
e fi_msg(3) para obtener una descripción detallada del manejo de FI_EAGAIN.

Solución de problemas / Problemas

conocidos

Si se espera que un punto final RxM se comunique con más pares que el valor predeterminado de FI_UNIVERSE_SIZE (256), pueden ocurrir desbordamientos de CQ. Para evitar esto, establezca un valor más alto para FI_UNIVERSE_SIZE. Un desbordamiento de CQ puede hacer que un punto final MSG sea

inutilizable.

Con un número mayor de rangos, puede haber errores de conexión debido a que un nodo se queda sin memoria. La solución es us

ar contextos de recepción compartidos para el proveedor MSG (FI_OFI_RXM_USE_SRX=1) o reducir el tamaño del mensaje eager (FI
_OFI_RXM_BUFFER_SIZE) y los tamaños de las colas TX/RX del proveedor MSG (FI_OFI_RXM_MSG_TX_SIZE / FI_OFI_RXM_MSG_RX_SIZE).
