File::NFSLock(3) Documentación de Perl aportada por el usuario File::NFSLock(3)

NOMBRE

File::NFSLock - módulo de Perl para realizar bloqueos NFS (o no)

SINOPSIS

use File::NFSLock qw(uncache);
use Fcntl qw(LOCK_EX LOCK_NB);
my $file = "algunarchivo";
### configurar un bloqueo - dura hasta que el objeto pierde alcance
if (my $lock = new File::NFSLock {
  file      => $file,
  lock_type => LOCK_EX|LOCK_NB,
  blocking_timeout   => 10,      # 10 seg
  stale_lock_timeout => 30 * 60, # 30 min
}) {
  ### O
  ### my $lock = File::NFSLock->new($file,LOCK_EX|LOCK_NB,10,30*60);
  ### hacer cosas protegidas contra escritura en $file
  ### en este punto $file está sin caché de NFS (el más reciente)
  open(FILE, "+<$file") || die $!;
  ### o abrirlo de cualquier manera que te guste
  ### my $fh = IO::File->open( $file, 'w' ) || die $!
  ### actualizar (sin caché en NFS) otros archivos
  uncache("otroarchivo1");
  uncache("otroarchivo2");
  # open(FILE2,"otroarchivo1");
  ### desbloquearlo
  $lock->unlock();
  ### O
  ### undef $lock;
  ### O dejar que $lock salga del alcance
}else{
  die "No pude bloquear el archivo [$File::NFSLock::errstr]";
}

DESCRIPCIÓN

Programa basado en el concepto de que los enlaces duros de archivos son atómicos en NFS. Este concepto se mencionó en Mail::Box::Locker (que originalmente se presentó en Mail::Folder::Maildir). Algunas rutinas de flujo se toman de allí, en particular la idea de crear un archivo local aleatorio, enlazar un archivo común al archivo local y luego verificar el estado de nlink. Algunas ideologías no estaban completas (mecanismo de caché, bloqueo compartido) y algo de código era incluso incorrecto (índice de stat equivocado). File::NFSLock fue escrito para ser ligero, genérico y rápido.

USO

Los bloqueos ocurren creando un objeto File::NFSLock. Si el objeto se crea con éxito, un bloqueo está actualmente en vigor y permanece hasta que el objeto de bloqueo salga de su alcance (o llame al método unlock).

Se crea un objeto de bloqueo llamando al método new y pasando dos a cuatro parámetros de la siguiente manera:

my $lock = File::NFSLock->new($file,
                              $lock_type,
                              $blocking_timeout,
                              $stale_lock_timeout,
                              );

Adicionalmente, los parámetros pueden pasarse como un hashref:

my $lock = File::NFSLock->new({
  file               => $file,
  lock_type          => $lock_type,
  blocking_timeout   => $blocking_timeout,
  stale_lock_timeout => $stale_lock_timeout,
});

PARÁMETROS

Parámetro 1: file
Nombre del archivo sobre el cual se anticipa que ocurrirá una escritura. El bloqueo proporcionará la versión más reciente (sin caché) de este archivo al obtener un bloqueo de archivo exitoso. No es necesario que este archivo exista.
Parámetro 2: lock_type
El tipo de bloqueo debe ser uno de los siguientes: 
BLOCKING
BL
EXCLUSIVE (BLOCKING)
EX
NONBLOCKING
NB
SHARED
SH

O uno o más de los siguientes unidos con '|':

Fcntl::LOCK_EX() (BLOQUEANTE)
Fcntl::LOCK_NB() (NO BLOQUEANTE)
Fcntl::LOCK_SH() (COMPARTIDO)

El tipo de bloqueo determina si el bloqueo será bloqueante, no bloqueante o compartido. Los bloqueos bloqueantes esperarán hasta que se eliminen otros bloqueos antes de que el proceso continúe. Los bloqueos no bloqueantes devolverán undef si otro proceso tiene actualmente el bloqueo. Compartido permitirá que otros procesos realicen un bloqueo compartido al mismo tiempo, siempre que no haya ya un bloqueo exclusivo obtenido.

Parámetro 3: blocking_timeout (opcional)
El tiempo de espera se utiliza junto con un tiempo de espera de bloqueo. Si se especifica, File::NFSLock bloqueará hasta el número de segundos especificado en el tiempo de espera antes de devolver undef (no se pudo obtener un bloqueo).
Parámetro 4: stale_lock_timeout (opcional)
El tiempo de espera se utiliza para ver si un archivo de bloqueo existente es anterior al tiempo de espera de bloqueo obsoleto. Si do_lock no consigue obtener un bloqueo, se comprueba la hora de modificación y se intenta do_lock de nuevo. Si stale_lock_timeout se establece demasiado bajo, podría existir una carga recursiva, por lo que do_lock solo se recursará 10 veces (esto solo es un problema si stale_lock_timeout se establece demasiado bajo, en el orden de uno o dos segundos).

MÉTODOS

Después de que el objeto $lock se instancia con new, como se describe anteriormente, se pueden usar algunos métodos para funcionalidad adicional.

unlock

$lock->unlock;

Este método puede usarse para liberar explícitamente un bloqueo adquirido. En la mayoría de los casos, no es necesario llamar a unlock directamente, ya que se llamará implícitamente cuando el objeto salga del alcance en el que se encuentre.

uncache

$lock->uncache;
$lock->uncache("otroarchivo1");
uncache("otroarchivo2");

Este método se utiliza para actualizar el contenido de un archivo en NFS, ignorando lo que contiene la caché del cliente NFS. Siempre se llama desde el constructor new en el archivo sobre el que se está intentando el bloqueo. uncache puede usarse como un método de objeto o como una subrutina independiente.

fork

my $pid = $lock->fork;
if (!defined $pid) {
  # Falló el fork
} elsif ($pid) {
  # Padre ...
} else {
  # Hijo ...
}

fork() es un método de conveniencia que actúa igual que el CORE::fork() normal, excepto que asegura de forma segura que el bloqueo se retiene tanto en los procesos padre como en los hijos. SIN ESTO, cuando el proceso padre o hijo libere el bloqueo, todo el bloqueo se perderá, permitiendo que procesos externos adquieran un bloqueo sobre el mismo archivo, incluso si el otro proceso todavía tiene el objeto de bloqueo dentro de su alcance. Esto puede causar corrupción, ya que ambos procesos podrían pensar que tienen acceso exclusivo al archivo.

newpid

my $pid = fork;
if (!defined $pid) {
  # Falló el fork
} elsif ($pid) {
  $lock->newpid;
  # Padre ...
} else {
  $lock->newpid;
  # Hijo ...
}

La sinopsis de newpid() mostrada anteriormente es equivalente a la utilizada para el método fork(), pero no está destinada a ser llamada directamente. Es llamada internamente por el método fork(). Para estar seguro, se recomienda usar $lock->fork() a partir de ahora.

FALLO

En caso de fallo, se debe establecer una variable global, $File::NFSLock::errstr, que contendrá la causa del fallo al obtener un bloqueo. Útil principalmente para depuración.

EXTENSIÓN_DE_BLOQUEO

Por defecto, File::NFSLock utilizará una extensión de archivo de bloqueo de ".NFSLock". Esto está en una variable global $File::NFSLock::LOCK_EXTENSION que puede cambiarse para adaptarse a otros propósitos (como la compatibilidad en sistemas de correo).

FIFO

Los bloqueos no se obtienen necesariamente en base a quién llega primero. Esto no solo parece injusto para los nuevos procesos que intentan obtener un bloqueo, sino que también puede causar una condición de inanición de procesos en archivos fuertemente bloqueados.
