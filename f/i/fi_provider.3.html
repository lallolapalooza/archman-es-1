Registrar y recuperar variables de entorno con el núcleo de libfabric

ARGUMENTOS

provider
Referencia al proveedor.
version
Versión de la API solicitada por la aplicación.
name
Nombre conocido del objeto de biblioteca a abrir.
attr
Atributos opcionales del objeto a abrir.
attr_len
Tamaño de cualquier estructura de atributos pasada a fi_open. Debe ser 0 si no se proporcionan atributos.
fid
Identificador de fabric devuelto para el objeto abierto.

DESCRIPCIÓN

Un proveedor de fabric implementa las interfaces de software orientadas a la aplicación necesarias para acceder a protocolos, controladores y hardware específicos de la red. Las interfaces y estructuras definidas en esta página del manual son exportadas por la biblioteca libfabric, pero están dirigidas a implementaciones de proveedores, más que para el uso directo por la mayoría de las aplicaciones.

Los proveedores integrados son aquellos construidos directamente en la propia biblioteca libfabric. Los proveedores externos son cargados dinámicamente por libfabric en el momento de la inicialización. Los proveedores externos deben estar en una ruta de biblioteca estándar o en la ruta de búsqueda de bibliotecas de libfabric especificada por una variable de entorno. Además, los proveedores externos deben tener el sufijo “-fi.so” al final del nombre.

Los objetos con nombre son recursos de propósito especial que son accesibles directamente por las aplicaciones. Pueden usarse para mejorar o modificar el comportamiento del núcleo de la biblioteca. Para más detalles, consulte la llamada fi_open más abajo.

fi_prov_ini

Este punto de entrada debe ser definido por los proveedores externos. Al cargar, libfabric invocará fi_prov_ini() para recuperar la estructura fi_provider del proveedor. Interacciones adicionales entre el núcleo de libfabric y el proveedor serán a través de las interfaces definidas por esa estructura.

fi_param_define

Define un parámetro de configuración para su uso por un proveedor específico. Los argumentos help_string y param_name no deben ser NULL, y help_string además no debe estar vacío. Se copian internamente y pueden liberarse después de llamar a fi_param_define.

fi_param_get

Obtiene el valor de un parámetro de configuración previamente definido usando fi_param_define(). El valor proviene de la variable de entorno con el nombre de la forma FI__, todo convertido a mayúsculas.

Si el parámetro fue previamente definido y el usuario estableció un valor, se devuelve FI_SUCCESS y (*value) apunta al valor recuperado.

Si el nombre del parámetro fue previamente definido, pero el usuario no estableció un valor, se devuelve -FI_ENODATA y el valor de (*value) no cambia.

Si el nombre del parámetro no fue previamente definido mediante fi_param_define(), se devuelve -FI_ENOENT y el valor de (*value) no cambia.

Si el valor en el entorno no es válido para el tipo de parámetro, se devuelve -FI_EINVAL y el valor de (*value) no cambia.

fi_log_enabled / fi_log_ready / fi_log

Estas funciones controlan la salida de registro de depuración e informativa. Los proveedores típicamente acceden a estas funciones a través de las macros FI_LOG y relacionadas en fi_log.h y no llaman a estas funciones directamente.

fi_open

Abre un recurso de biblioteca usando un nombre conocido. Esta característica permite a las aplicaciones y proveedores un mecanismo que puede usarse para modificar o mejorar los servicios y comportamiento del núcleo de la biblioteca. Los detalles son específicos según el nombre del objeto solicitado. La mayoría de las aplicaciones no necesitarán este nivel de control.

La versión de la API de la biblioteca conocida por la aplicación debe proporcionarse a través del parámetro version. El uso de atributos depende del objeto. Si es necesario, los atributos deben proporcionarse a través del parámetro attr, con attr_len establecido al tamaño de la estructura de atributos referenciada. La siguiente es una lista de nombres publicados, junto con descripciones del servicio o recurso al que corresponden.

mr_cache
El objeto mr_cache referencia la caché interna de registro de memoria usada por los diferentes proveedores. Información adicional sobre la caché está disponible en la página del manual fi_mr(3).
logging
El objeto logging referencia el subsistema interno de registro usado por los diferentes proveedores. Una vez abierto, pueden instalarse callbacks de registro personalizados. Solo puede abrirse una sola vez y solo se usa la última importación si se importa múltiples veces.

fi_import

Esta función auxiliar es una combinación de fi_open y fi_import_fid. Puede usarse para importar un objeto de fabric creado y poseído por el usuario de libfabric. Esto permite a las bibliotecas de nivel superior o a la aplicación anular o definir el comportamiento de libfabric de bajo nivel.

fi_import_log

Función auxiliar para anular el sistema de registro de libfabric de bajo nivel con nuevas funciones de callback.

struct fi_ops_log {
    size_t size;
    int (*enabled)(const struct fi_provider *prov, enum fi_log_level level,
               enum fi_log_subsys subsys, uint64_t flags);
    int (*ready)(const struct fi_provider *prov, enum fi_log_level level,
             enum fi_log_subsys subsys, uint64_t flags, uint64_t *showtime);
    void (*log)(const struct fi_provider *prov, enum fi_log_level level,
            enum fi_log_subsys subsys, const char *func, int line,
            const char *msg);
};
struct fid_logging {
    struct fid          fid;
    struct fi_ops_log   *ops;
};

INTERFAZ DEL PROVEEDOR

La estructura fi_provider define los puntos de entrada que el núcleo de libfabric utiliza para acceder al proveedor. Todas las demás llamadas a un proveedor se realizan a través de punteros a funciones asociados con objetos asignados.

struct fi_provider {
    uint32_t version;
    uint32_t fi_version;
    struct fi_context context;
    const char *name;
    int (*getinfo)(uint32_t version, const char *node, const char *service,
            uint64_t flags, const struct fi_info *hints,
            struct fi_info **info);
    int (*fabric)(struct fi_fabric_attr *attr, struct fid_fabric **fabric,
            void *context);
    void    (*cleanup)(void);
};

version

La versión del proveedor. Para los proveedores integrados con la biblioteca, esta suele ser la misma que la versión de la biblioteca.

fi_version

La versión de la interfaz de la biblioteca contra la que se implementó el proveedor. El fi_version del proveedor debe ser mayor o igual que la versión de la API solicitada por una aplicación para que esta pueda usar el proveedor. Es responsabilidad del proveedor admitir versiones anteriores de la API si desea admitir aplicaciones heredadas. Para los proveedores integrados

VALOR DE RETORNO

Devuelve FI_SUCCESS en caso de éxito. En caso de error, se devuelve un valor negativo correspondiente al errno de fabric. Los valores de errno de fabric se definen en rdma/fi_errno.h.
