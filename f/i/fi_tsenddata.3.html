NAME

fi_tagged - Operaciones de transferencia de datos etiquetados

fi_trecv / fi_trecvv / fi_trecvmsg
Publicar un búfer para recibir un mensaje entrante
fi_tsend / fi_tsendv / fi_tsendmsg / fi_tinject / fi_tsenddata
Iniciar una operación para enviar un mensaje

ssize_t fi_tsend(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, fi_addr_t dest_addr, uint64_t tag, void *context);
ssize_t fi_tsendv(struct fid_ep *ep, const struct iovec *iov,

ARGUMENTOS

fid
Punto final de fabric sobre el cual iniciar la operación de comunicación etiquetada.
buf
Búfer de datos para enviar o recibir.
len
Longitud del búfer de datos a enviar o recibir, especificada en bytes. Las transferencias válidas van desde 0 bytes hasta el max_msg_size del punto final.
iov
Búfer de datos vectorizados.
count
Número de entradas de datos vectorizados.
tag
Etiqueta asociada con el mensaje.
ignore
Máscara de bits a ignorar aplicada a la etiqueta para operaciones de recepción.
desc
Descriptor de memoria asociado con el búfer de datos. Ver fi_mr(3).
data
Datos de CQ remota a transferir con los datos enviados.
dest_addr
Dirección de destino para transferencias sin conexión. Ignorado para puntos finales conectados.
src_addr
Se aplica solo a puntos finales sin conexión configurados con FI_DIRECTED_RECV. Para todas las demás configuraciones de puntos finales, src_addr se ignora. src_addr define la dirección de origen de la que se debe recibir. Por defecto, src_addr se trata como una dirección de punto final de origen (es decir, fi_addr_t devuelto por fi_av_insert / fi_av_insertsvc / fi_av_remove). Si se especifica la bandera FI_AUTH_KEY con fi_trecvmsg, src_addr se trata como una clave de autorización de origen (es decir, fi_addr_t devuelto por fi_av_insert_auth_key). Si se establece en FI_ADDR_UNSPEC, cualquier dirección de origen puede coincidir.
msg
Descriptor de mensaje para operaciones de envío y recepción.
flags
Banderas adicionales a aplicar para la operación de envío o recepción.
context
Puntero especificado por el usuario para asociarlo con la operación. Este parámetro se ignora si la operación no genera una finalización exitosa, a menos que una bandera de operación especifique que el parámetro de contexto se utilizará para entrada requerida.

DESCRIPCION

Los mensajes etiquetados son transferencias de datos que llevan una clave o etiqueta con el búfer del mensaje. La etiqueta se utiliza en el punto final receptor para hacer coincidir el mensaje entrante con un búfer de recepción correspondiente. Las etiquetas de mensaje coinciden cuando la etiqueta del búfer de recepción es la misma que la etiqueta del búfer de envío con los bits ignorados enmascarados. Esto se puede expresar como:

send_tag & ~ignore == recv_tag & ~ignore
o
send_tag | ignore == recv_tag | ignore

En general, las etiquetas de mensaje se comparan con los búferes de recepción en el orden en que se han publicado los mensajes en el punto final. Consulte la discusión sobre el ordenamiento a continuación para obtener más detalles.

Las funciones de envío (fi_tsend, fi_tsendv, fi_tsendmsg, fi_tinject y fi_tsenddata) se utilizan para transmitir un mensaje etiquetado desde un punto final a otro. La principal diferencia entre las funciones de envío son el número y tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

Las funciones de recepción (fi_trecv, fi_trecvv, fi_recvmsg) publican un búfer de datos en un punto final para recibir mensajes etiquetados entrantes. De manera similar a las operaciones de envío, las operaciones de recepción funcionan de forma asíncrona. Los usuarios no deben manipular los búferes de datos publicados hasta que la operación de recepción se haya completado. Los búferes de recepción publicados se emparejan con los mensajes de envío entrantes basándose en las etiquetas asociadas con los búferes de envío y recepción.

Un punto final debe estar habilitado antes de que una aplicación pueda publicar operaciones de envío o recepción en él. Para puntos finales conectados, los búferes de recepción se pueden publicar antes de llamar a connect o accept en el punto final. Esto garantiza que haya búferes disponibles para recibir datos entrantes inmediatamente después de que se haya establecido la conexión.

Las operaciones de mensaje completadas se informan al usuario a través de uno o más colectores de eventos asociados con el punto final. Los usuarios proporcionan contextos que se asocian con cada operación y se devuelven al usuario como parte de la finalización del evento. Consulte fi_cq para obtener detalles sobre los eventos de finalización.

fi_tsend

La llamada fi_tsend transfiere los datos contenidos en el búfer de datos especificado por el usuario a un punto final remoto, manteniendo los límites del mensaje. El punto final local debe estar conectado a un punto final o destino remoto antes de llamar a fi_tsend. A menos que el punto final se haya configurado de manera diferente, el búfer de datos pasado a fi_tsend no debe ser manipulado por la aplicación hasta que la llamada fi_tsend se complete de forma asíncrona.

fi_tsendv

La llamada fi_tsendv agrega soporte para una lista de dispersión-agrupación a fi_tsend. fi_sendv transfiere el conjunto de búferes de datos referenciados por el parámetro iov a un punto final remoto como un solo mensaje.

fi_tsendmsg

La llamada fi_tsendmsg admite transferencias de datos a través de puntos finales conectados y sin conexión, con la capacidad de controlar la operación de envío por llamada mediante el uso de banderas. La función fi_tsendmsg toma una estructura fi_msg_tagged como entrada.

struct fi_msg_tagged {
    const struct iovec *msg_iov; /* array scatter-gather */
    void               *desc;    /* descriptor de datos */
    size_t             iov_count;/* número de elementos en msg_iov */
    fi_addr_t          addr;    /* dirección de punto final opcional */
    uint64_t           tag;      /* etiqueta asociada con el mensaje */
    uint64_t           ignore;   /* máscara aplicada a la etiqueta para recepciones */
    void               *context; /* contexto definido por el usuario */
    uint64_t           data;     /* datos inmediatos opcionales */
};

fi_tinject

La llamada de inyección etiquetada es una versión optimizada de fi_tsend. Proporciona semántica de finalización similar a fi_inject fi_msg(3).

fi_tsenddata

La llamada de envío de datos etiquetados es similar a fi_tsend, pero permite enviar datos de CQ remota (ver bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_tinjectdata

La llamada de inyección de datos etiquetados es similar a fi_tinject, pero permite enviar datos de CQ remota (ver bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_trecv

La llamada fi_trecv publica un búfer de datos a un punto final de fabric para recibir mensajes entrantes. Se espera que los mensajes entrantes coincidan con el búfer de recepción según las etiquetas. Los bits especificados en el parámetro ignore se utilizan para enmascarar bits de las etiquetas de envío y recepción antes de que se realice la comparación.

fi_trecvv

La llamada fi_trecvv agrega soporte para una lista de dispersión-agrupación a fi_trecv. La llamada fi_trecvv publica un conjunto de búferes de datos para recibir un único mensaje entrante.

fi_trecvmsg

La llamada fi_trecvmsg admite operaciones de recepción de mensajes etiquetados en puntos finales conectados y sin conexión. La función fi_trecvmsg toma una estructura fi_msg_tagged como entrada.

MENSAJES ETIQUETADOS Y ORDENAMIENTO

Las operaciones de mensajes etiquetados se pueden clasificar en las siguientes categorías:

1. Orden de publicación de recepción
Los búferes de recepción se publican y se mantienen en una cola de recepción. Los mensajes de envío se emparejan con los búferes de recepción en el orden en que se publicaron los búferes de recepción. Las etiquetas de envío y recepción deben coincidir según lo definido anteriormente.
2. Orden de publicación de envío
Las operaciones de envío se publican y se ejecutan en el orden en que se publicaron. Los mensajes se transmiten en el orden en que se publicaron. Los mensajes enviados a través de un punto final conectado deben llegar al punto final remoto en el orden en que se enviaron.
3. Orden de finalización
Las finalizaciones de operaciones de envío y recepción se informan a través de la cola de finalización. El orden de las finalizaciones no está garantizado y puede diferir del orden de publicación o del orden de recepción.
