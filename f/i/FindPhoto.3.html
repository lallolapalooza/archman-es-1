Tk_FindPhoto(3) Procedimientos de la biblioteca Tk Tk_FindPhoto(3)

NOMBRE

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipular los datos de imagen almacenados en una imagen de tipo foto.

SINOPSIS

#include <tk.h>

Tk_PhotoHandle
Tk_FindPhoto(interp, imageName)

int
Tk_PhotoPutBlock(interp, handle, blockPtr, x, y, width, height,compRule)

int
Tk_PhotoPutZoomedBlock(interp, handle, blockPtr, x, y, width, height,zoomX, zoomY, subsampleX, subsampleY, compRule)

int
Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

void
Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el que se creó la imagen y en el que se debe realizar el informe de errores.
const char *imageName (entrada)
Nombre de la imagen de tipo foto.
Tk_PhotoHandle handle (entrada)
Manipulador opaco que identifica la imagen de tipo foto que se verá afectada.
Tk_PhotoImageBlock *blockPtr (entrada)
Especifica la dirección y la disposición de almacenamiento de los datos de la imagen.
int x (entrada)
Especifica la coordenada X donde se debe colocar la esquina superior izquierda del bloque dentro de la imagen.
int y (entrada)
Especifica la coordenada Y donde se debe colocar la esquina superior izquierda del bloque dentro de la imagen.
int width (entrada)
Especifica el ancho del área de la imagen que se verá afectada (para Tk_PhotoPutBlock) o el ancho deseado de la imagen (para Tk_PhotoExpand y Tk_PhotoSetSize).
int compRule (entrada)
Especifica la regla de composición que se utiliza al combinar píxeles transparentes en un bloque de datos con una imagen de tipo foto. Debe ser uno de TK_PHOTO_COMPOSITE_OVERLAY (que coloca el bloque de datos sobre la imagen de tipo foto existente, con el contenido anterior mostrándose a través de los bits transparentes) o TK_PHOTO_COMPOSITE_SET (que descarta el contenido de la imagen de tipo foto existente en el rectángulo cubierto por el bloque de datos.)
int height (entrada)
Especifica la altura del área de la imagen que se verá afectada (para Tk_PhotoPutBlock) o la altura deseada de la imagen (para Tk_PhotoExpand y Tk_PhotoSetSize).
int *widthPtr (salida)
Puntero a la ubicación donde almacenar el ancho de la imagen.
int *heightPtr (salida)
Puntero a la ubicación donde almacenar la altura de la imagen.
int subsampleX (entrada)
Especifica el factor de submuestreo en la dirección X para los datos de la imagen de entrada.
int subsampleY (entrada)
Especifica el factor de submuestreo en la dirección Y para los datos de la imagen de entrada.
int zoomX (entrada)
Especifica el factor de zoom que se aplicará en la dirección X a los píxeles que se escriben en la imagen de tipo foto.
int zoomY (entrada)
Especifica el factor de zoom que se aplicará en la dirección Y a los píxeles que se escriben en la imagen de tipo foto.

DESCRIPCIÓN

Tk_FindPhoto devuelve un manipulador opaco que se utiliza para identificar una imagen de tipo foto particular para los demás procedimientos. El parámetro es el nombre de la imagen, es decir, el nombre especificado en el image create photo comando, o asignado por ese comando si no se especificó ningún nombre. Si imageName no existe o no es una imagen de tipo foto, Tk_FindPhoto devuelve NULL.

Tk_PhotoPutBlock se utiliza para proporcionar bloques de datos de imagen que se mostrarán. La llamada afecta a un área de la imagen de tamaño width x height píxeles, con su esquina superior izquierda en las coordenadas (x,y). Todos los valores de width, height, xy y deben ser no negativos. Si parte de esta área se encuentra fuera de los límites actuales de la imagen, la imagen se expandirá para incluir el área, a menos que el usuario haya especificado un tamaño de imagen explícito con las -width y/o -height opciones de configuración del widget (ver photo(n)); en ese caso, el área se recorta silenciosamente a los límites de la imagen.

El block parámetro es un puntero a una estructura Tk_PhotoImageBlock , definida de la siguiente manera:

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
El campo pixelPtr apunta al primer píxel, es decir, el píxel de la esquina superior izquierda en el bloque. Los campos width y height especifican las dimensiones del bloque de píxeles. El campo pixelSize especifica la diferencia de dirección entre dos píxeles adyacentes horizontalmente. Debería ser 4 para datos de imagen RGB y 2 para datos de imagen en escala de grises. Otros valores son posibles, si los desplazamientos en el array offset se ajustan en consecuencia (por ejemplo, para datos rojos, verdes y azules almacenados en planos diferentes). Sin embargo, se desaconseja fuertemente el uso de tal disposición. Debido a un error, puede no funcionar correctamente si se proporciona un canal alfa. (ver la sección ERRORES más abajo). El campo pitch especifica la diferencia de dirección entre dos píxeles adyacentes verticalmente. El array offset contiene los desplazamientos desde la dirección de un píxel hasta las direcciones de los bytes que contienen los componentes rojo, verde, azul y alfa (transparencia). Si los desplazamientos para rojo, verde y azul son iguales, la imagen se interpreta como en escala de grises. Si difieren, se asumen datos RGB. Normalmente, los desplazamientos serán 0, 1, 2, 3 para datos RGB y 0, 0, 0, 1 para escala de grises. Es posible proporcionar datos de imagen sin un canal alfa estableciendo el desplazamiento para alfa a un valor negativo y ajustando el campo pixelSize en consecuencia. Sin embargo, se desaconseja este uso (ver la sección ERRORES más abajo).

El parámetro compRule de Tk_PhotoPutBlock especifica una regla de composición que indica qué hacer con los píxeles transparentes. El valor TK_PHOTO_COMPOSITE_OVERLAY indica que el contenido anterior de la imagen de tipo foto debe mostrarse a través, y el valor TK_PHOTO_COMPOSITE_SET indica que el contenido anterior de la imagen de tipo foto debe ignorarse por completo, y los valores del bloque deben copiarse directamente. El comportamiento en Tk8.3 y versiones anteriores era equivalente a tener TK_PHOTO_COMPOSITE_OVERLAY como regla de composición.

El valor dado para los parámetros width y height de Tk_PhotoPutBlock no tienen que corresponder a los valores especificados en block. Si son más pequeños, Tk_PhotoPutBlock extrae un sub-bloque de los datos de la imagen proporcionados. Si son más grandes, los datos dados se replican (de forma mosaico) para llenar el área especificada. Estas reglas operan independientemente en las direcciones horizontal y vertical.

Tk_PhotoPutBlock normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para contener la imagen resultante, se devuelve TCL_ERROR en su lugar y, si el argumento interp no es NULL, se coloca un mensaje de error en el resultado del intérprete.

Tk_PhotoPutZoomedBlock funciona como Tk_PhotoPutBlock excepto que la imagen puede reducirse o ampliarse para su visualización. Los parámetros subsampleX y subsampleY permiten reducir el tamaño de la imagen mediante submuestreo. Tk_PhotoPutZoomedBlock usará solo píxeles de la imagen de entrada cuyas coordenadas X son múltiplos de subsampleX, y cuyas coordenadas Y son múltiplos de subsampleY. Por ejemplo, una imagen de 512x512 píxeles puede reducirse a 256x256 estableciendo subsampleX y subsampleY en 2.

Los parámetros zoomX y zoomY permiten ampliar la imagen mediante replicación de píxeles. Cada píxel de la imagen de entrada (posiblemente submuestreada) se escribirá en un bloque de la imagen mostrada de zoomX píxeles de ancho y zoomY píxeles de alto. El submuestreo y el zoom pueden usarse juntos para efectos especiales.

Tk_PhotoGetImage se puede usar para recuperar datos de imagen de una imagen de tipo foto. Tk_PhotoGetImage rellena la estructura a la que apunta el parámetro blockPtr con valores que describen la dirección y la disposición de los datos de la imagen que la imagen de tipo foto ha almacenado internamente. Los valores son válidos hasta que la imagen se destruya o se cambie su tamaño.

Es posible modificar una imagen escribiendo directamente en los datos a los que apunta el campo pixelPtr . Sin embargo, el tamaño de la imagen no puede cambiarse de esta manera. Además, los cambios realizados escribiendo directamente en pixelPtr no serán visibles inmediatamente, sino solo después de una llamada a Tk_ImageChanged o después de un evento que cause que los widgets interesados se redibujen a sí mismos. Por estas razones, generalmente es preferible realizar los cambios a una copia de los datos de la imagen y escribirlos de nuevo con Tk_PhotoPutBlock o Tk_PhotoPutZoomedBlock.

Tk_PhotoGetImage devuelve 1 por compatibilidad con el procedimiento correspondiente en el widget de foto antiguo.

Tk_PhotoBlank pone en blanco toda el área de la imagen de la foto. Las áreas en blanco de una imagen de foto son transparentes.

Tk_PhotoExpand solicita que la imagen del widget se expanda para tener al menos width x height píxeles de tamaño. El ancho y/o la altura no cambian si el usuario ha especificado un ancho o una altura de imagen explícitos con las -width y/o -height opciones de configuración, respectivamente. Si los datos de la imagen se proporcionan en muchos bloques pequeños, es más eficiente usar Tk_PhotoExpand o Tk_PhotoSetSize al principio en lugar de permitir que la imagen se expanda en muchos pequeños incrementos a medida que se proporcionan los bloques de la imagen.

Tk_PhotoExpand normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para contener la imagen resultante, TCL_ERROR se devuelve en su lugar y, si el interp argumento no es NULL, se coloca un mensaje de error en el resultado del intérprete.

Tk_PhotoSetSize especifica el tamaño de la imagen, como si el usuario hubiera especificado los valores dados de width y height a las -width y -height opciones de configuración. Un valor de cero para width o height no cambia el ancho o la altura de la imagen, pero permite que el ancho o la altura sean cambiados por llamadas subsecuentes a Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock o Tk_PhotoExpand.

Tk_PhotoSetSize normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para contener la imagen resultante, TCL_ERROR se devuelve en su lugar y, si el interp argumento no es NULL, se coloca un mensaje de error en el resultado del intérprete.

Tk_PhotoGetSize devuelve las dimensiones de la imagen en *widthPtr y *heightPtr.

PORTABILIDAD

En Tk 8.3 y versiones anteriores, Tk_PhotoPutBlock y Tk_PhotoPutZoomedBlock tenían firmas diferentes. Si desea compilar código que usa la interfaz antigua contra 8.4 sin actualizar su código, compílelo con el flag -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. El código vinculado usando Stubs contra versiones anteriores de Tk continuará funcionando.

En Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand y Tk_PhotoSetSize no tomaban un interp argumento ni devolvían ningún código de resultado. Si no había suficiente memoria disponible para una imagen, Tk entraba en pánico. Este comportamiento todavía está soportado si compila su extensión con el flag adicional -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. El código vinculado usando Stubs contra versiones anteriores de Tk continuará funcionando.

ERRORES

La estructura Tk_PhotoImageBlock utilizada para proporcionar datos de imagen a Tk_PhotoPutBlock promete una gran flexibilidad en la disposición de los datos (por ejemplo, planos separados para los canales rojo, verde, azul y alfa). Desafortunadamente, la implementación no cumple esta promesa. El problema es que el pixelSize campo se usa (incorrectamente) para determinar si la imagen tiene un canal alfa. Actualmente, si el desplazamiento para el canal alfa es mayor o igual a pixelSize, tk_PhotoPutblock asume que no hay datos alfa presentes y hace que la imagen sea completamente opaca. Esto significa que para disposiciones donde los canales están separados (o cualquier otra disposición exótica donde pixelSize tiene que ser menor que el desplazamiento alfa), el canal alfa no se leerá correctamente. Para estar seguros de que este problema se corregirá en una versión futura, se recomienda encarecidamente que siempre proporcione datos alfa - incluso si la imagen no tiene transparencia - y solo use la disposición "estándar" con un pixelSize de 2 para escala de grises y 4 para datos RGB con offsets de 0, 0, 0, 1 o 0, 1, 2, 3 respectivamente.
