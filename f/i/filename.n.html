INTRODUCCIÓ

N

Todos los comandos de Tcl y los procedimientos en C que toman nombres de archivo como argumentos esperan que los nombres de archivo estén en una de tres formas, dependiendo de la plataforma actual. En cada plataforma, Tcl admite los nombres de archivo en las formas estándar de esa plataforma. Además, en todas las plataformas, Tcl admite una sintaxis tipo Unix destinada a proporcionar una manera conveniente de construir nombres de archivo simples. Sin embargo, los scripts que pretenden ser portables no deben asumir una forma particular para los nombres de archivo. En su lugar, los scripts portables deben usar los comandos file split y file join para manipular nombres de archivo (consulte la entrada del manual de f

ile para má
s detalles).

TIPOS DE

RUTA

Los nombres de archivo se agrupan en tres tipos generales basados en el punto de partida de la ruta utilizada para especificar el archivo: absolutos, relativos y relativos al volumen. Los nombres absolutos están completamente calificados, dando una ruta al archivo relativa a un volumen particular y al directorio raíz en ese volumen. Los nombres relativos no están calificados, dando una ruta al archivo relativa al directorio de trabajo actual. Los nombres relativos al volumen están parcialmente calificados, dando la ruta relativa al directorio raíz en el volumen actual, o relativa al directorio actual del volumen especificado. El comando file pathtype se puede usar para d

eterminar el tipo
de una ruta dada.

En las plataformas Unix y Apple macOS, Tcl usa nombres de ruta donde los componentes están separados por barras diagonales. Los nombres de ruta pueden ser relativos o absolutos, y los nombres de archivo pueden contener cualquier carácter excepto la barra diagonal. Los nombres de archivo . y .. son especiales y se refieren al directorio actual y al padre del directorio actual respectivamente. Múltiples caracteres de barra diagonal adyacentes se interpretan como un solo separador, excepto para la primera doble barra // en rutas absolutas. Cualquier número de caracteres de barra diagonal al final de una ruta simplemente se ignoran, por lo que las rutas foo, foo/ y foo// son todas idénticas, y en particular foo/ no significa necesariamente que

SUSTITUCIÓN DE

TILDE

Además de las reglas de nombres de archivo descritas anteriormente, Tcl también admite la sustitución de tilde al estilo de csh. Si un nombre de archivo comienza con un tilde, entonces el nombre de archivo se interpretará como si el primer elemento se reemplazara con la ubicación del directorio de inicio para el usuario dado. Si el tilde está seguido inmediatamente por un separador, entonces se sustituye la variable de entorno $HOME. De lo contrario, los caracteres entre el tilde y el siguiente separador se toman como un nombre de usuario, que se usa para recuperar el directorio de inicio del usuario para la sustitución. Esto funciona en Unix, macOS y Windows (excepto en versiones muy antiguas)

.

Las plataformas Windows antiguas no admiten la sustitución de tilde cuando un nombre de usuario sigue al tilde. En estas plataformas, los intentos de usar un tilde seguido de un nombre de usuario generarán un error de que el usuario no existe cuando Tcl intente interpretar esa parte de la ruta o acceder al archivo de otra manera. El comportamiento de estas rutas cuando no se intenta interpretarlas es el mismo que en Unix. Los nombres de archivo que tienen un tilde sin nombre de usuario se sustituirán correctamente usando la variable de entorno $HOME, igual

que en
Unix.

PROBLEMAS DE

PORTABILIDAD

No todos los sistemas de archivos distinguen entre mayúsculas y minúsculas, por lo que los scripts deben evitar código que dependa de las mayúsculas y minúsculas de los caracteres en un nombre de archivo. Además, los conjuntos de caracteres permitidos en diferentes dispositivos pueden diferir, por lo que los scripts deben elegir nombres de archivo que no contengan caracteres especiales como: <>:?"/\|. El enfoque más seguro es usar nombres que consistan solo de caracteres alfanuméricos. Debe tenerse cuidado con los nombres de archivo que contienen espacios (comunes en sistemas Windows) y nombres de archivo donde la barra invertida es el separador de directorio (nombres de ruta nativos de Windows)

.

En las plataformas Windows existen restricciones de longitud de archivo y ruta. Las rutas completas o nombres de archivo más largos que unos 260 caracteres conducirán a errores en la mayoría de las operaciones de

archivos.

Otra peculiaridad de Windows es que cualquier número de puntos finales “.” en los nombres de archivo se ignoran totalmente, por lo que, por ejemplo, los intentos de crear un archivo o directorio con el nombre “foo.” resultarán en la creación de un archivo/directorio con el nombre “foo”. Este hecho se refleja en los resultados de file normalize. Además, un nombre de archivo que consiste solo de pun

tos “.........” o puntos con caract
eres finales “.....abc” es ilegal.
