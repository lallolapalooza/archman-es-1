DESCRIPCIÓ

N

Un archivo de configuración de zona de firewalld contiene la información para una zona. Estos son la descripción de la zona, servicios, puertos, protocolos, bloqueos ICMP, enmascaramiento, reenvío de puertos, reenvío intra-zona y reglas de lenguaje enriquecido en un formato de archivo XML. El nombre del archivo debe ser zone_name.xml donde la longitud de zone_name está actualmente limitada a 17

caracteres.

Esta es la estructura de un archivo de configuración de

zona: 
<?xml version="1.0" encoding="utf-8"?>
<zone [version="versionstring"] [target="ACCEPT|%%REJECT%%|DROP"] [ingress-priority="priority"] [egress-priority="priority"]>
    [ <interface name="string"/> ]
    [ <source address="address[/mask]"|mac="MAC"|ipset="ipset"/> ]
    [ <icmp-block-inversion/> ]
    [ <forward/> ]
    [ <short>short description</short> ]
    [ <description>description</description> ]
    [ <service name="string"/> ]
    [ <port port="portid[-portid]" protocol="tcp|udp|sctp|dccp"/> ]
    [ <protocol value="protocol"/> ]
    [ <icmp-block name="string"/> ]
    [ <masquerade/> ]
    [ <forward-port port="portid[-portid]" protocol="tcp|udp|sctp|dccp" [to-port="portid[-portid]"] [to-addr="IP address"]/> ]
    [ <source-port port="portid[-portid]" protocol="tcp|udp|sctp|dccp"/> ]
    [
        <rule [family="ipv4|ipv6"] [priority="priority"]>
            [ <source address="address[/mask]"|mac="MAC"|ipset="ipset" [invert="True"]/> ]
            [ <destination address="address[/mask]"|ipset="ipset" [invert="True"]/> ]
            [
                <service name="string"/> |
                <port port="portid[-portid]" protocol="tcp|udp|sctp|dccp"/> |
                <protocol value="protocol"/> |
                <icmp-block name="icmptype"/> |
                <icmp-type name="icmptype"/> |
                <masquerade/> |
                <forward-port port="portid[-portid]" protocol="tcp|udp|sctp|dccp" [to-port="portid[-portid]"] [to-addr="address"/>>
            ]
            [
                <log [prefix="prefix text"] [level="emerg|alert|crit|err|warn|notice|info|debug"]> [<limit value="rate/duration"/>] </log> |
                <nflog [group="group id"] [prefix="prefix text"] [queue-size="threshold"]> [<limit value="rate/duration"/>] </nflog>
            ]
            [ <audit> [<limit value="rate/duration"/>] </audit> ]
            [
                <accept> [<limit value="rate/duration"/>] </accept> |
                <reject [type="rejecttype"]> [<limit value="rate/duration"/>] </reject> |
                <drop> [<limit value="rate/duration"/>] </drop> |
                <mark set="mark[/mask]"> [<limit value="rate/duration"/>] </mark>
] </rul
e> ] </zone>

La configuración puede contener estas etiquetas y atributos. Algunos son obligatorios, otros

opcionales.

zon

e

La etiqueta de inicio y fin obligatoria zone define la zona. Esta etiqueta solo puede usarse una vez en un archivo de configuración de zona. Hay atributos opcionales para las

zonas:

version="string

"
Para darle a la zona una
versión.

target="ACCEPT|%%REJECT%%|DROP

"
Puede usarse para aceptar, rechazar o descartar cada paquete que no coincida con ninguna regla (puerto, servicio, etc.).

ACCEPT es especial: los paquetes que no están dirigidos al host se reenviarán a su destino independientemente de la configuración de reenvío de la zona, o de cualquier política adjunta a la

zona.

Si no se especifica, se aplica el comp

ortamiento por defecto: se aceptará
ICMP y todo lo demás será rechazado.

ingress-priority="priority

"
Prioridad de entrada para clasificar el tráfico en una zona. Una zona con un valor de prioridad más bajo se considerará antes que una zona con un valor de prioridad más alto. Esto permite un orden personalizado del despacho de
zonas.

egress-priority="priority

"
Igual que ingress-prio
rity, pero para la clas
ificación de salida.

interfac

e

Es una etiqueta de elemento vacío opcional y puede usarse varias veces. Se puede usar para vincular una interfaz a una zona. No necesita esto para interfaces gestionadas por NetworkManager, porque NetworkManager vincula las interfaces a las zonas automáticamente. Véase también 'How to set or change a zone for a connection?' en firewalld.zones(5). Puede usarlo como un mecanismo de respaldo para interfaces que no pueden gestionarse a través de NetworkManager. Una entrada de interfaz tiene exactamente un

atributo:

name="string

"

e

Es una etiqueta de elemento vacío opcional y puede usarse varias veces. Se puede usar para vincular una dirección de origen, un rango de direcciones, una dirección MAC o un ipset a una zona. Una entrada de origen tiene exactamente uno de estos

atributos:

address="address[/mask

]"
El origen es una dirección IP o una dirección IP de red con una máscara para IPv4 o IPv6. La familia de red (IPv4/IPv6) será descubierta automáticamente.
