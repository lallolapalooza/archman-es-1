CONFIGURACIÓN
OPX_
AV
OPX soporta la opción de establecer el modo A
V a usar en una compilación. Se soportan 3
configuraciones: - table - map - runtime

Usar table o map solo permitirá a OPX usar FI_AV_TABLE o FI_AV_MAP. Usar runtime permitirá a OPX usar cualquiera de los modos AV dependiendo de lo que solicite la aplicación. Especificar map o table, sin embargo, puede llevar a una ligera mejora de rendimiento dependiendo de la

aplicación.

Para cambiar OPX_AV, añada OPX_AV=table, OPX_AV=map, o OPX_AV=runtime al comando configure. Por ejemplo, para crear una nueva compilación con

OPX_AV=table:

OPX_AV=table .

/configure

make

install

No hay forma de cambiar OPX_AV después de que se

establezca. Si OPX_AV no está establecido en
el configure, el valor predeterminado es runtime.

FI_OPX_HFI_SEL
ECT
Cadena. Controla cómo OPX elige qué HFI usar al abrir un contexto. Tiene dos forma
s: - <hfi-unit> Fuerza al proveedor OPX a usar hfi-unit. - <selector1>[,<selector2
>[,...,<selectorN>]] Selecciona el HFI basándose en el primer selector coincidente

Donde selector es una de las siguientes formas: - default para usar la lógica predeterminada - fixed:<hfi-unit> para fijar a un hfi-unit - <selector-type>:<hfi-unit>:

<selector-data>

Los campos anteriores tienen el siguiente significado: - selector-type El criterio de selección que el llamador que abre el contexto está evalcontra. - hfi-unit El HFI a usar si el llamante coincide con el selector. - selector-data Datos que el llamante debe coincidir (por ejemplo, ID de nodo NUMA).

Donde selector-type es uno de los siguientes: - numa Verdadero cuando el llamante está local al ID de nodo NUMA dado por selector-data. - core Verdadero cuando el llamante está local al núcleo de CPU dado por selector-data.

Y selector-data es uno de los siguientes: - value El valor específico a coincidir - <range-start>-<range-end> Coincide con cualquier valor en ese rango

En la segunda forma, al abrir un contexto, OPX utiliza la unidad hfi-unit del primer selector coincidente. Los selectores se evalúan de izquierda a derecha. OPX devolverá un error si el llamante no coincide con ningún selector.

En cualquiera de las formas, es un error si el HFI especificado o seleccionado no está en estado Activo. En este caso, OPX devolverá un error y la ejecución no continuará.

Con esta opción, es posible hacer que OPX intente abrir más contextos en un HFI de los que hay contextos libres en ese HFI. En este caso, una o más de las llamadas para abrir contextos fallarán y OPX devolverá un error. Para la segunda forma, dado que el HFI seleccionado depende de las propiedades del llamante, la selección determinista de HFI requiere propiedades de llamante deterministas. Por ejemplo, para el selector numa, si el llamante puede migrar entre dominios NUMA, la selección de HFI no será determinista.

La lógica utilizada siempre será la primera válida en una lista de selectores. Por ejemplo, default y fixed coincidirán con todos los llamantes, por lo que si alguno de ellos está al principio de una lista de selectores, solo se utilizarán las reglas de selección fija o por defecto, independientemente de si hay más selectores.

Ejemplos: - FI_OPX_HFI_SELECT=0 todos los llamantes abrirán contextos en el HFI 0. - FI_OPX_HFI_SELECT=1 todos los llamantes abrirán contextos en el HFI 1. - FI_OPX_HFI_SELECT=numa:0:0,numa:1:1,numa:0:2,numa:1:3 los llamantes locales a los nodos NUMA 0 y 2 usarán el HFI 0, los llamantes locales a los dominios NUMA 1 y 3 usarán el HFI 1. - FI_OPX_HFI_SELECT=numa:0:0-3,default los llamantes locales a los nodos NUMA 0 a 3 (incluidos 0 y 3) usarán el HFI 0, y todos los demás usarán la lógica de selección por defecto. - FI_OPX_HFI_SELECT=core:1:0,fixed:0 los llamantes locales al núcleo de CPU 0 usarán el HFI 1, y todos los demás usarán el HFI 0. - FI_OPX_HFI_SELECT=default,core:1:0 todos los llamantes utilizarán la lógica de selección de HFI por defecto.

FI_OPX_PORT
Entero. Número de puerto del HFI1. Si el puerto especificado no está disponible, se seleccionará un puerto activo por defecto. El valor especial 0 indica cualquier puerto disponible. Por defecto es el puerto 1 en OPA100 y cualquier puerto en CN5000.
FI_OPX_DELIVERY_COMPLETION_THRESHOLD
Entero. Será obsoleto. Por favor, use FI_OPX_SDMA_BOUNCE_BUF_THRESHOLD.
FI_OPX_SDMA_BOUNCE_BUF_THRESHOLD
Entero. La longitud máxima del mensaje en bytes que se copiará al búfer de rebote SDMA. Para mensajes más grandes que este umbral, el envío no se completará hasta que el receptor haya confirmado. El valor debe estar entre 16385 y 2147483646. Por defecto es 16385.
FI_OPX_SDMA_DISABLE
Booleano (1/0, activado/desactivado, verdadero/falso, sí/no). Deshabilita el hardware de descarga SDMA. El valor por defecto es 0.
FI_OPX_MAX_PKT_SIZE
Entero. Establece el tamaño máximo de paquete que debe ser menor o igual al tamaño de MTU (Unidad de Transmisión Máxima) del controlador. Valores válidos: 2048, 4096, 8192, 10240. El valor por defecto es 10240 para bibliotecas compiladas en sistemas CN5000 y 8192 para bibliotecas compiladas en sistemas OPA100.
FI_OPX_SDMA_MIN_PAYLOAD_BYTES
Entero. La longitud mínima en bytes donde se utilizará SDMA. Para mensajes más pequeños que este umbral, el envío se completará utilizando PIO. El valor debe estar entre 64 y 2147483646. Por defecto es 16385.
FI_OPX_SDMA_MAX_WRITEVS_PER_CYCLE
Entero. El número máximo de veces que se llamará a writev durante un ciclo de sondeo. El valor debe estar entre 1 y 1024. Por defecto es 1.
FI_OPX_SDMA_MAX_IOVS_PER_WRITEV
Entero. El número máximo de IOVs pasados a cada llamada a writev. El valor debe estar entre 3 y 128. Por defecto es 64.
FI_OPX_SDMA_MAX_PKTS
Entero. El número máximo de paquetes transmitidos por solicitud SDMA cuando no se utiliza la recepción esperada (TID). El valor debe estar entre 1 y 128. Por defecto es 32.
FI_OPX_SDMA_MAX_PKTS_TID
Entero. El número máximo de paquetes transmitidos por solicitud SDMA cuando se utiliza la recepción esperada (TID). El valor debe estar entre 1 y 512. Por defecto es 64.
FI_OPX_TID_MIN_PAYLOAD_BYTES
Entero. La longitud mínima en bytes donde se utilizará TID (Recepción Esperada). Para mensajes más pequeños que este umbral, el envío se completará utilizando Recepción Eager. El valor debe estar entre 4096 y 2147483646. Por defecto es 4096.
FI_OPX_RZV_MIN_PAYLOAD_BYTES
Entero. La longitud mínima en bytes donde se utilizará Rendezvous. Para mensajes más pequeños que este umbral, el envío intentará completarse primero utilizando Eager o Eager de múltiples paquetes. El valor debe estar entre 64 y 65536. Por defecto es 16385.
FI_OPX_MP_EAGER_DISABLE
Booleano (1/0, activado/desactivado, verdadero/falso, sí/no). Deshabilita el modo Eager de múltiples paquetes. Por defecto es 0.
FI_OPX_TID_DISABLE
Booleano (1/0, activado/desactivado, verdadero/falso, sí/no). Deshabilita el uso de Token ID (TID). Por defecto es 0.
FI_OPX_EXPECTED_RECEIVE_ENABLE
Obsoleto. Use FI_OPX_TID_DISABLE en su lugar.
FI_OPX_PROG_AFFINITY
Cadena. Esto establece la afinidad que se utilizará para los hilos de progreso. Se establece como un triplete separado por dos puntos: inicio:fin:paso, donde el paso controla el intervalo entre los núcleos seleccionados. Por ejemplo, 1:5:2 tendrá los núcleos 1, 3 y 5 como núcleos válidos para los hilos de progreso. Por defecto, no se establece ninguna afinidad.
FI_OPX_AUTO_PROGRESS_INTERVAL_USEC
Obsoleto/ignorado. Los hilos de progreso automático ahora son controlados por interrupciones y solo sondean cuando hay datos disponibles.
FI_OPX_PKEY
Entero. Clave de partición, un entero positivo de 2 bytes. Por defecto es la Pkey en el índice 0 de la tabla Pkey de la unidad y el puerto en los que se crea el contexto.
FI_OPX_SL
Entero. Nivel de Servicio. Esto también determinará la Clase de Servicio y el Carril Virtual. Por defecto es 0.
FI_OPX_GPU_IPC_INTRANODE
Booleano (0/1, activado/desactivado, verdadero/falso, sí/no). Esta configuración controla si se utilizará IPC para facilitar las copias de GPU a GPU dentro del nodo a través de PCIe, NVLINK o xGMI. Cuando esto está desactivado, los datos de la GPU se copiarán al host antes de copiarse a otra GPU, lo que es más lento que usar IPC. Esto solo tiene efecto en las compilaciones de OPX con HMEM habilitado. Por defecto está activado.
FI_OPX_DEV_REG_SEND_THRESHOLD
Entero. El umbral de paquete individual donde las longitudes superiores no utilizan una copia registrada del dispositivo al enviar datos desde la GPU. El umbral por defecto es 4096. Esto no tiene significado si Libfabric no fue configurado con soporte GDRCopy o ROCR.
FI_OPX_DEV_REG_RECV_THRESHOLD
Entero. El umbral de paquete individual donde las longitudes superiores no utilizan una copia registrada del dispositivo al recibir datos en la GPU. El umbral por defecto es 8192. Esto no tiene significado si Libfabric no fue configurado con soporte GDRCopy o ROCR.
FI_OPX_MIXED_NETWORK
Booleano (1/0, activado/desactivado, verdadero/falso, sí/no). Indica que el trabajo requiere soporte OPA100. Establecer en 0 si no se necesita soporte OPA100. Por defecto es 1.
FI_OPX_ROUTE_CONTROL
Entero. Especifica el control de ruta para cada tipo de paquete. El formato es - <valor del tipo de paquete de inyección>:<valor del tipo de paquete eager>:<valor del tipo de paquete multi-packet eager>:<valor del tipo de paquete dput>:<valor del tipo de paquete de control de rendezvous>:<valor del tipo de paquete de datos de rendezvous>.

Cada valor puede variar de 0 a 7. 0-3 se utiliza para en orden y 4-7 se utiliza para fuera de orden. Si Token ID (TID) está habilitado, los controles de ruta fuera de orden se deshabilitan.

Por defecto es 0:0:0:0:0:0 en OPA100 y 4:4:4:4:0:4 en CN5000.

FI_OPX_SHM_ENABLE
Booleano (1/0, activado/desactivado, verdadero/falso, sí/no). Habilita shm en todos los puertos y unidades hfi del nodo. Configurarlo en NO deshabilita shm excepto para pares con el mismo lid y el mismo hfi1 (loopback). Por defecto: "YES".
FI_OPX_LINK_DOWN_WAIT_TIME_MAX_SEC
Entero. El tiempo máximo en segundos para esperar a que un enlace vuelva a estar activo. Por defecto es 70 segundos.
FI_OPX_MMAP_GUARD
Booleano (0/1, activado/desactivado, verdadero/falso, sí/no). Habilita guardias alrededor de los mmap de OPX/HFI. Cuando está habilitado, esto causará un segfault cuando la memoria mapeada se acceda ilegalmente a través de desbordamientos o subdesbordamientos del búfer. Por defecto es falso.
FI_OPX_CONTEXT_SHARING
Booleano (1/0, activado/desactivado, verdadero/falso, sí/no). Habilita el uso compartido de contexto en OPX. Por defecto es FALSE (1 contexto HFI por endpoint).
FI_OPX_ENDPOINTS_PER_HFI_CONTEXT
Entero. Especifica cuántos puntos de extremo deben compartir un único contexto HFI. Los valores válidos van de 2 a 8. El valor predeterminado se determina en función del número de contextos disponibles en el sistema y del número de procesadores en línea. Solo es aplicable si el uso compartido de contextos está habilitado. De lo contrario, este valor se ignora.
