NOMBRE

fi_join_collective
Operación en la que un subconjunto de pares se une a un nuevo grupo colectivo.
fi_barrier / fi_barrier2
Operación colectiva que no se completa hasta que todos los pares han entrado en la llamada de barrera.
fi_broadcast
Un único emisor transmite datos a todos los pares, incluido a sí mismo.
fi_alltoall
Cada par distribuye una porción de sus datos locales a todos los pares.
fi_allreduce
Operación colectiva donde todos los pares transmiten una operación atómica a todos los demás pares.
fi_allgather
Cada par envía una copia completa de sus datos locales a todos los pares.
fi_reduce_scatter
Llamada colectiva donde se recopilan datos de todos los pares y se combinan (reducen). Los resultados de la reducción se distribuyen de vuelta a los pares, recibiendo cada par una porción de los resultados.
fi_reduce
Llamada colectiva donde se recopilan datos de todos los pares hacia un par raíz y se combinan (reducen).
fi_scatter
Un único emisor distribuye (dispersa) una porción de sus datos locales a todos los pares.
fi_gather
Todos los pares envían sus datos a un par raíz.
fi_query_collective
Devuelve información sobre qué operaciones colectivas son soportadas por un proveedor, y las limitaciones del colectivo.

ARGUMENTOS

ep
Punto de extremo de la fabrica en el que iniciar la operación colectiva.
set
Conjunto de vectores de direcciones que define la membresía del colectivo.
mc
Grupo multicast asociado con el colectivo.
buf
Búfer de datos local que especifica el primer operando de la operación colectiva.
count
El número de elementos referenciados, donde cada elemento es el tipo de datos indicado.
datatype
Tipo de datos asociado con los operandos atómicos.
op
Operación atómica a realizar.
result
Búfer de datos local para almacenar el resultado de la operación colectiva.
desc / result_desc
Descriptor de datos asociado con el búfer de datos local y el búfer de resultado local, respectivamente.
coll_addr
Dirección que se refiere al grupo colectivo de puntos de extremo.
root_addr
Punto de extremo único que es el origen o destino de los datos colectivos.
flags
Banderas adicionales a aplicar para la operación atómica.
context
Puntero especificado por el usuario para asociar con la operación. Este parámetro se ignora si la operación no generará una finalización exitosa, a menos que una bandera de operación especifique que el parámetro de contexto debe usarse como entrada requerida.

DESCRIPCIÓN

En general, las operaciones colectivas pueden considerarse como operaciones atómicas coordinadas entre un conjunto de puntos de extremo pares. Los lectores deben referirse a la página de manual fi_atomic(3) para detalles sobre las operaciones atómicas y los tipos de datos definidos por libfabric.

Una operación colectiva es un intercambio de comunicación de grupo. Implica que múltiples pares intercambien datos con otros pares que participan en la llamada colectiva. Las operaciones colectivas requieren una estrecha coordinación por parte de todos los miembros participantes. Todos los participantes deben invocar la misma llamada colectiva antes de que cualquier miembro individual pueda completar su operación localmente. Como resultado, las llamadas colectivas pueden ejercer presión sobre la fabrica, así como sobre los búferes de datos locales y remotos.

Las interfaces colectivas de Libfabric están dirigidas a fabricas que soportan la descarga de partes de la comunicación colectiva en conmutadores de red, tarjetas de interfaz de red (NIC) y otros dispositivos. Sin embargo, no se impone ningún requisito de implementación al proveedor.

El primer paso para usar una llamada colectiva es identificar los puntos de extremo pares que participarán. La membresía colectiva sigue uno de dos modelos, ambos soportados por libfabric. En el primer modelo, la aplicación gestiona la membresía. Esto generalmente significa que la aplicación está realizando una operación colectiva en sí misma utilizando comunicación de punto a punto para identificar a los miembros que participarán. Además, la aplicación puede interactuar con un administrador de recursos de la fabrica para reservar los recursos de red necesarios para ejecutar operaciones colectivas. En este modelo, la aplicación informará a libfabric que la membresía ya ha sido establecida.

Un modelo separado traslada la gestión de la membresía bajo libfabric y directamente al proveedor. En este modelo, la aplicación debe identificar qué direcciones de pares serán miembros. Esa información se transmite al proveedor de libfabric, que entonces es responsable de coordinar la creación del grupo colectivo. En el modelo gestionado por el proveedor, el proveedor generalmente realizará la operación colectiva necesaria para establecer el grupo de comunicación e interactuará con cualquier agente de gestión de la fabrica.

En ambos modelos, la membresía colectiva se comunica al proveedor creando y configurando un conjunto de vectores de direcciones (AV set). Un AV set representa un subconjunto ordenado de direcciones en un vector de direcciones (AV). Los detalles sobre cómo crear y configurar un AV set están disponibles en fi_av_set(3).

Una vez que un AV set ha sido programado con la información de membresía colectiva, un punto de extremo se une al conjunto. Esto utiliza la operación fi_join_collective y opera de forma asíncrona. Esto difiere de cómo un punto de extremo se asocia de forma síncronacon un AV usando la llamada fi_ep_bind(). Al completar la operación fi_join_collective, se proporciona un fi_addr que se utiliza como dirección de destino al invocar una operación colectiva.

Para la comodidad del desarrollador, se define un conjunto de API colectivas. Las API colectivas difieren de las interfaces de mensajes y RMA en que el formato de los datos es conocido por el proveedor, y la operación colectiva puede realizar una operación sobre esos datos. Esto alinea las operaciones colectivas estrechamente con las interfaces atómicas.

Unirse a una operación colectiva (fi_join_collective)

Esta llamada adjunta un punto final a un grupo de membresía colectiva. Libfabric trata a los miembros colectivos como un grupo de multidifusión (multicast), y la llamada fi_join_collective adjunta el punto final a ese grupo de multidifusión. Por defecto, el punto final se unirá al grupo basándose en las capacidades de transferencia de datos del punto final. Por ejemplo, si el punto final ha sido configurado tanto para enviar como para recibir datos, entonces el punto final podrá iniciar y recibir transferencias hacia y desde el colectivo. Los flags de entrada pueden usarse para restringir el acceso al grupo colectivo, sujeto a las limitaciones de las capacidades del punto final.

Las operaciones de unión colectiva se completan de forma asíncrona y pueden involucrar transferencias por el fabric, dependiendo de la implementación del proveedor. Un punto final debe estar vinculado a una cola de eventos antes de llamar a fi_join_collective. El resultado de la operación de unión se reportará a la cola de eventos (EQ) como un evento FI_JOIN_COMPLETE. Las aplicaciones no pueden emitir transferencias colectivas hasta recibir la notificación de que la operación de unión se ha completado. Tenga en cuenta que un punto final puede comenzar a recibir mensajes del grupo colectivo tan pronto como la unión se complete, lo cual puede ocurrir antes de que se genere el evento FI_JOIN_COMPLETE.

La operación de unión colectiva es en sí misma una operación colectiva. Todos los pares participantes deben llamar a fi_join_collective antes de que cualquier par individual reporte que la unión se ha completado. Las membresías colectivas gestionadas por la aplicación son una excepción. Con las membresías gestionadas por la aplicación, la llamada fi_join_collective puede completarse localmente sin comunicación por el fabric. Para las membresías gestionadas por el proveedor, la llamada de unión colectiva requiere como entrada una coll_addr que se refiera a una dirección asociada con un conjunto AV (ver fi_av_set_addr) o a un grupo colectivo existente (obtenido a través de una llamada previa a fi_join_collective). La llamada fi_join_collective creará un nuevo subgrupo colectivo. Si se usan membresías gestionadas por la aplicación, coll_addr debe establecerse en FI_ADDR_UNAVAIL.

Las aplicaciones deben llamar a fi_close en el grupo colectivo para desconectar el punto final del grupo. Después de que una operación de unión se haya completado, la llamada fi_mc_addr puede usarse para recuperar la dirección asociada con el grupo de multidifusión. Ver fi_cm(3) para detalles adicionales sobre fi_mc_addr().

Barrera (fi_barrier)

La operación fi_barrier proporciona un mecanismo para sincronizar pares. La barrera no resulta en que se transfieran datos a nivel de aplicación. Una barrera no se completa localmente hasta que todos los pares hayan invocado la llamada de barrera. Esto le indica a la aplicación local que el trabajo de los pares que se completó antes de que ellos llamaran a la barrera ha terminado.

Barrera (fi_barrier2)

La operación fi_barrier2 es la misma que fi_barrier, pero con un parámetro extra para pasar flags de operación.

Difusión (fi_broadcast)

fi_broadcast transfiere un arreglo de datos de un solo emisor a todos los demás miembros del grupo colectivo. El parámetro de entrada buf se trata como el búfer de transmisión si el rango local es la raíz (root), de lo contrario es el búfer de recepción. La operación de difusión actúa como una escritura o lectura atómica a un arreglo de datos. Como resultado, el formato de los datos en buf se especifica a través del parámetro datatype. Cualquier datatype que no sea void puede ser difundido.

El siguiente diagrama muestra un ejemplo de difusión utilizado para transferir un arreglo de enteros a un grupo de pares.

[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]
 |____^    ^
 |_________|
 broadcast

Todos contra todos (fi_alltoall)

La colectiva fi_alltoall implica distribuir (o dispersar) diferentes porciones de un arreglo de datos a los pares. Se explica mejor usando un ejemplo. Aquí, tres pares realizan una colectiva todos contra todos para intercambiar diferentes entradas en un arreglo de enteros.

[1]   [2]   [3]
[5]   [6]   [7]
[9]  [10]  [11]
   \   |   /
   All to all
   /   |   \
[1]   [5]   [9]
[2]   [6]  [10]
[3]   [7]  [11]

Cada par envía una pieza de sus datos a los otros pares.

Las operaciones todos contra todos pueden realizarse sobre cualquier datatype que no sea void. Sin embargo, todos contra todos no realiza una operación sobre los datos en sí, por lo que no se especifica ninguna operación.

Reducción global (fi_allreduce)

fi_allreduce puede describirse como todos los pares proporcionando entrada a una operación atómica, con el resultado copiado de vuelta a cada par. Conceptualmente, esto puede verse como cada par emitiendo una operación atómica de multidifusión a todos los demás pares, obteniendo los resultados y combinándolos. La combinación de los resultados se conoce como la reducción. La operación fi_allreduce() toma como entrada un arreglo de datos y la operación atómica especificada a realizar. Los resultados de la reducción se escriben en el búfer de resultados.

Se puede especificar cualquier datatype que no sea void. Las operaciones atómicas válidas se enumeran más abajo en la llamada fi_query_collective. El siguiente diagrama muestra un ejemplo de una operación de reducción global que implica sumar un arreglo de enteros entre tres pares.

 [1]  [1]  [1]
 [5]  [5]  [5]
 [9]  [9]  [9]
   \   |   /
      sum
   /   |   \
 [3]  [3]  [3]
[15] [15] [15]
[27] [27] [27]
  All Reduce

Recopilación global (fi_allgather)

Conceptualmente, la recopilación global puede verse como lo opuesto al componente de dispersión de la reducción-dispersión. La recopilación global recopila datos de todos los pares en un solo arreglo, luego copia ese arreglo de vuelta a cada par.

[1]  [5]  [9]
  \   |   /
 All gather
  /   |   \
[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]

La recopilación global puede realizarse sobre cualquier datatype que no sea void. Sin embargo, la recopilación global no realiza una operación sobre los datos en sí, por lo que no se especifica ninguna operación.

Reducción-dispersión (fi_reduce_scatter)

La colectiva fi_reduce_scatter es similar a una operación fi_allreduce, seguida de todos contra todos. Con la reducción-dispersión, todos los pares proporcionan entrada a una operación atómica, similar a la reducción global. Sin embargo, en lugar de que el resultado completo sea copiado a cada par, cada participante recibe solo una porción del resultado.

Esto se muestra en el siguiente ejemplo:

[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]
  \   |   /
     sum (reduce)
      |
     [3]
    [15]
    [27]
      |
   scatter
  /   |   \
[3] [15] [27]

La llamada de reducción-dispersión soporta el mismo datatype y operación atómica que fi_allreduce.

Reducción (fi_reduce)

La colectiva fi_reduce es la primera mitad de una operación fi_allreduce. Con la reducción, todos los pares proporcionan entrada a una operación atómica, con los resultados recopilados por un único punto final `raíz' (root).

Esto se muestra en el siguiente ejemplo, con el par más a la izquierda identificado como la raíz:

[1]  [1]  [1]
[5]  [5]  [5]
[9]  [9]  [9]
  \   |   /
     sum (reduce)
    /
 [3]
[15]
[27]

La llamada de reducción soporta el mismo datatype y operación atómica que fi_allreduce.

Dispersión (fi_scatter)

La colectiva fi_scatter es la segunda mitad de una operación fi_reduce_scatter. Los datos de un único punto final `raíz' (root) se dividen y se distribuyen a todos los pares.

Esto se muestra en el siguiente ejemplo:

 [3]
[15]
[27]
    \
   scatter
  /   |   \
[3] [15] [27]

La operación de dispersión se usa para distribuir resultados a los pares. No se realiza ninguna operación atómica sobre los datos.

Recopilación (fi_gather)

La operación fi_gather se usa para recopilar los resultados de todos los pares y almacenarlos en un par `raíz' (root).

Esto se muestra en el siguiente ejemplo, con el par más a la izquierda identificado como la raíz.

[1]  [5]  [9]
  \   |   /
    gather
   /
[1]
[5]
[9]

La operación de recopilación no realiza ninguna operación sobre los datos en sí.

Consultar atributos colectivos (fi_query_collective)

La llamada fi_query_collective informa qué operaciones colectivas son soportadas por el proveedor subyacente, para puntos finales configurados adecuadamente. Las operaciones colectivas necesarias por una aplicación que no sean soportadas por el proveedor deben ser implementadas por la aplicación. La llamada de consulta verifica si un proveedor soporta una operación colectiva específica para un datatype y operación dados, si es aplicable.

El nombre del colectivo, así como el datatype y la operación asociada, si es aplicable, se proporcionan como entrada en fi_query_collective.

El parámetro coll puede referirse a uno de estos colectivos: FI_BARRIER, FI_BROADCAST, FI_ALLTOALL, FI_ALLREDUCE, FI_ALLGATHER, FI_REDUCE_SCATTER, FI_REDUCE, FI_SCATTER, o FI_GATHER. Detalles adicionales sobre la operación colectiva se especifican a través del parámetro struct fi_collective_attr. Para los colectivos que actúan sobre datos, la operación y el tipo de datos relacionado deben especificarse a través de los atributos dados.

struct fi_collective_attr {
    enum fi_op op;
    enum fi_datatype datatype;
    struct fi_atomic_attr datatype_attr;
    size_t max_members;
      uint64_t mode;
};

Para una descripción de struct fi_atomic_attr, consulte fi_atomic(3).

op
En la entrada, esto especifica la operación atómica involucrada en la llamada colectiva. Esto debe establecerse en uno de los siguientes valores: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ, FI_ATOMIC_WRITE, o FI_NOOP. Para operaciones colectivas que no intercambian datos de la aplicación (fi_barrier), esto debe establecerse en FI_NOOP.
datatype
En la salida, especifica el tipo de dato de los datos que están siendo modificados por la operación colectiva. Esto debe establecerse en uno de los siguientes valores: FI_INT8, FI_UINT8, FI_INT16, FI_UINT16, FI_INT32, FI_UINT32, FI_INT64, FI_UINT64, FI_FLOAT, FI_DOUBLE, FI_FLOAT_COMPLEX, FI_DOUBLE_COMPLEX, FI_LONG_DOUBLE, FI_LONG_DOUBLE_COMPLEX, o FI_VOID. Para operaciones colectivas que no intercambian datos de la aplicación (fi_barrier), esto debe establecerse en FI_VOID.
datatype_attr.count
El número máximo de elementos que pueden usarse con la operación colectiva.
datatype_attr.size
El tamaño del tipo de dato tal como lo soporta el proveedor. Las aplicaciones deben validar el tamaño de los tipos de datos que varían según la plataforma, como FI_LONG_DOUBLE.
max_members
El número máximo de pares que pueden participar en una operación colectiva.
mode
Este campo está reservado y debe ser 0.

Si una operación colectiva es soportada, la llamada de consulta devolverá FI_SUCCESS, junto con los atributos sobre los límites para usar esa operación colectiva a través del proveedor.

Completados

Las operaciones colectivas se mapean a operaciones fi_atomic subyacentes. Para una discusión sobre la semántica de completado atómico, consulte fi_atomic(3). El completado, el ordenamiento y la atomicidad de las operaciones colectivas coinciden con los definidos para operaciones atómicas de punto a punto.

BANDERAS

Las siguientes banderas están definidas para las operaciones especificadas.

FI_SCATTER
Aplica a fi_query_collective. Cuando se establece, solicita información de atributos sobre la operación colectiva reduce-scatter.

VALOR DE RETORNO

Devuelve 0 en caso de éxito. En caso de error, se devuelve un valor negativo correspondiente a el errno del fabric. Los valores de errno del fabric están definidos en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Consulte fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
-FI_EOPNOTSUPP
La operación atómica solicitada no está soportada en este punto de conexión.
-FI_EMSGSIZE
El número de operaciones colectivas en una sola solicitud excede el soportado por el proveedor subyacente.

NOTAS

Las operaciones colectivas se mapean a operaciones atómicas. Como tal, siguen la mayoría de las convenciones y restricciones que las operaciones atómicas de par a par. Esto incluye la atomicidad de los datos, la alineación de los datos y la semántica de ordenamiento de mensajes. Consulte fi_atomic(3) para información adicional sobre los tipos de datos y operaciones definidos para operaciones atómicas y colectivas.
