File::Find::Rule::Extending(3) Documentación de Perl contribuida por el usuario File::Find::Rule::Extending(3)

NOMBRE

File::Find::Rule::Extending - la miniguía para extender File::Find::Rule

SINOPSIS

package File::Find::Rule::Random;
use strict;

# toma cosas útiles de File::Find::Rule
use base 'File::Find::Rule';
# y fuerza nuestra grieta en el espacio de nombres principal
sub File::Find::Rule::random () {
    my $self = shift()->_force_object;
    $self->exec( sub { rand > 0.5 } );
}

1;

DESCRIPCIÓN

File::Find::Rule tuvo tanto éxito con el público comprador que todos quisieron añadir características adicionales. Con la versión 0.07 esto se convirtió en una posibilidad, utilizando las siguientes convenciones.

Declara tu paquete

package File::Find::Rule::Random;
use strict;

Hereda métodos de File::Find::Rule

# toma cosas útiles de File::Find::Rule
use base 'File::Find::Rule';

Fuerza tu locura en el paquete principal

# y fuerza nuestra grieta en el espacio de nombres principal
sub File::Find::Rule::random () {
    my $self = shift()->_force_object;
    $self->exec( sub { rand > 0.5 } );
}

Sí, estamos siendo muy despreocupados aquí y definiendo cosas en el espacio de nombres principal de File::Find::Rule. Esto se debe a la falta de imaginación por mi parte: simplemente no encuentro una manera de que la interfaz funcional y la orientada a objetos funcionen sin hacer esto o algún tipo de herencia, y la herencia te impide usar dos módulos de File::Find::Rule::Foo juntos.

Por esta razón, intenta elegir nombres distintos para tus extensiones. Si esto se convierte en un problema, puede que instituya un registro semi-oficial de nombres ocupados.

Sin argumentos.

Nota el prototipo nulo en random. Este es un truco para que la interfaz procedimental sepa que tu sub no toma argumentos, y así permite que esto suceda:

find( random => in => '.' );

Si no hubieras declarado "random" con un prototipo nulo, habría consumido "in" como parámetro suyo, y luego se habría confundido porque no conoce una regla para '.'.
