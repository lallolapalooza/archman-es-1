NOMBRE

File::RsyncP - Cliente Rsync para Perl

SINOPSIS

use File::RsyncP;
my $rs = File::RsyncP->new({
            logLevel   => 1,
            rsyncCmd   => "/bin/rsync",
            rsyncArgs  => [
                    "--numeric-ids",
                    "--perms",
                    "--owner",
                    "--group",
                    "--devices",
                    "--links",
                    "--ignore-times",
                    "--block-size=700",
                    "--relative",
                    "--recursive",
                    "-v",
                ],
        });
#
# Recibir archivos del directorio remoto srcDirectory al directorio local destDirectory
# ejecutando rsyncCmd con rsyncArgs.
#
$rs->remoteStart(1, srcDirectory);
$rs->go(destDirectory);
$rs->serverClose;
#
# Enviar archivos al directorio remoto destDirectory desde el directorio local srcDirectory
# ejecutando rsyncCmd con rsyncArgs.
#
$rs->remoteStart(0, destDirectory);
$rs->go(srcDirectory);
$rs->serverClose;
#
# Recibir archivos de un módulo remoto al directorio local destDirectory
# conectándose a un servidor rsyncd. ($module es el nombre de
# /etc/rsyncd.conf.)
#
my $port = 873;
$rs->serverConnect($host, $port);
$rs->serverService($module, $authUser, $authPasswd, 0);
$rs->serverStart(1, ".");
$rs->go(destDirectory);
$rs->serverClose;
#
# Obtener estadísticas finales. Esto es un hashref que contiene los elementos
# totalRead, totalWritten, totalSize, más lo que el módulo FileIO
# pueda añadir.
#
my $stats = $rs->statsFinal;

DESCRIPCIÓN

File::RsyncP es una implementación en Perl de un cliente Rsync. Es compatible con Rsync 2.5.5 - 2.6.3 (versiones de protocolo 26-28). Puede enviar o recibir archivos, ya sea ejecutando rsync en la máquina remota, o conectándose a un demonio rsyncd en la máquina remota.

¿Para qué sirve File::RsyncP? El propósito principal es que File::RsyncP separa toda la E/S del sistema de archivos en un módulo independiente, que puede ser reemplazado por cualquier módulo de tu propio diseño. Esto permite que las interfaces de rsync a tipos de datos que no son del sistema de archivos (ej: bases de datos) se desarrollen con relativa facilidad.

File::RsyncP fue escrito inicialmente para proporcionar una interfaz Rsync para BackupPC, http://backuppc.sourceforge.net. Ver BackupPC para ejemplos de programación.

File::RsyncP todavía no proporciona una interfaz de línea de comandos que imite a Rsync nativo. En su lugar proporciona una API que hace posible escribir scripts simples que se comuniquen con rsync o rsyncd.

El módulo File::RsyncP::FileIO contiene las funciones de acceso al sistema de archivos predeterminadas. File::RsyncP::FileIO puede ser subclaseado o reemplazado por un módulo personalizado para proporcionar acceso a tipos de datos que no son del sistema de archivos.

Primeros pasos

Primero, algo de contexto. Cuando ejecutas rsync, analiza sus argumentos de línea de comandos, luego se conecta a un demonio rsyncd remoto, o ejecuta un rsync en la máquina remota a través de ssh o rsh. En este punto hay dos procesos rsync: el que invocaste y el de la máquina remota. El de la máquina local se llama el cliente, y el de la máquina remota es el servidor. Un lado (ya sea el cliente o el servidor) enviará archivos y el otro los recibirá. El rsync que envía genera una lista de archivos y la envía al lado que recibe. El rsync que recibe hará un fork de un proceso hijo.

File::RsyncP no tiene (todavía) un script de línea de comandos que imite el procesamiento de inicio de rsync. Piensa en File::RsyncP como un nivel por debajo del rsync de línea de comandos. File::RsyncP implementa el lado cliente de la conexión, y File::RsyncP sabe cómo ejecutar el lado remoto (ej, a través de rsh o ssh) o conectarse a un demonio rsyncd remoto. File::RsyncP automáticamente añade las opciones internas --server y --sender (si es necesario) a las opciones pasadas al rsync remoto.

Para iniciar cualquier sesión de rsync, se debe llamar a la función File::RsyncP->new. Toma un hashref de parámetros:

logLevel
Un nivel entero de verbosidad. Cero significa silencio, 1 dará algo de información general, 2 dará algo de salida por archivo, valores más altos dan más salida. 10 incluirá volcados de bytes de todos los datos leídos/escritos, lo que hará que la salida del log sea enorme.
rsyncCmd
El comando para ejecutar el par remoto de rsync. Por defecto, los rsyncArgs se añaden al rsyncCmd para crear el comando completo antes de ejecutarlo. Este comportamiento está afectado por rsyncCmdType.

rsyncCmd puede ser una cadena única que da la ruta del comando rsync a ejecutar (ej: /bin/rsync) o una lista que contiene el comando y los argumentos, ej:

rsyncCmd => [qw(
    /bin/ssh -l user host /bin/rsync
)],

o:

rsyncCmd => ["/bin/ssh", "-l", $user, $host, "/bin/rsync"],

Además, rsyncCmd también puede ser establecido a una referencia de código (ej: un sub de perl). En este caso, el código es llamado sin argumentos u otro procesamiento. Depende del código perl que proporciones exec() el rsync remoto.

Esta opción se ignora si te estás conectando a un demonio rsyncd.

rsyncCmdType
Por defecto, el comando rsync remoto completo es creado tomando rsyncCmd y añadiendo rsyncArgs. Este comportamiento puede ser modificado especificando ciertos valores para rsyncCmdType:
'full'
Se considera que rsyncCmd es el comando completo, incluyendo todos los argumentos de rsync. Es responsabilidad del llamador construir el comando rsync remoto correcto, junto con todos los argumentos de rsync. Todavía necesitas especificar rsyncArgs, para que el File::RsyncP local sepa cómo comportarse.
'shell'
Los rsyncArgs son escapados para la shell antes de añadirlos a rsyncCmd.

Esta opción se ignora si te estás conectando a un demonio rsyncd.

rsyncArgs
Una lista de argumentos de rsync. El comando rsync remoto completo que se ejecutará será rsyncCmd añadido con --server (y opcionalmente --sender si el remoto es un emisor) y finalmente todos los rsyncArgs.
protocol_version
Qué versión de protocolo anunciamos que somos. El valor predeterminado es 28.
logHandler
Una referencia a subrutina de una función que maneja todos los mensajes de log. El valor predeterminado es una subrutina que imprime los mensajes a STDERR.
pidHandler
Una referencia a subrutina opcional de una función que espera dos enteros: el pid del proceso rsync (ej: el pid en la máquina local que probablemente es ssh) y el pid del hijo cuando estamos recibiendo archivos. Si está definida, esta función es llamada una vez cuando el proceso rsync es bifurcado, y otra vez cuando el hijo es bifurcado durante la recepción.
fio
El objeto de E/S de archivos que manejará toda la E/S del sistema de archivos. El valor predeterminado es File::RsyncP::FileIO->new.

Esto puede ser reemplazado con un nuevo módulo de tu elección, o puedes subclasear File::RsyncP::FileIO.

timeout
Tiempo de espera en segundos para la E/S. El valor predeterminado es 0, lo que significa sin tiempo de espera. Usa alarm() y es responsabilidad del llamador atrapar la señal de alarma.
doPartial
Si se establece, se hace un rsync parcial. Esto es para soportar la reanudación de copias de seguridad completas en BackupPC. Cuando doPartial está establecido, la opción --ignore-times puede ser establecida a nivel de archivo. En cada archivo de la lista de archivos, File::RsyncP::FileIO->ignoreAttrOnFile() es llamada en cada archivo, y esto devuelve si los atributos deben ser ignorados en ese archivo o no. Si ignoreAttrOnFile() devuelve 1, es como si --ignore-times estuviera establecido para ese archivo.

Un ejemplo de cómo llamar a File::RsyncP->new es:

my $rs = File::RsyncP->new({
            logLevel   => 1,
            rsyncCmd => ["/bin/rsh", $host,  "-l", $user, "/bin/rsync"],
            rsyncArgs  => [
                    "--numeric-ids",
                    "--perms",
                    "--owner",
                    "--group",
                    "--devices",
                    "--links",
                    "--ignore-times&quot;,
                    "--block-size=700",
                    "--relative",
                    "--recursive",
                    "-v",
                ],
        })
;

remoto

funciones:
serverConnect(host,
port)
Se conecta al demonio Rsync en el host de cadena dado y el puerto entero. El argumento port es opcional y por defecto es 873. En caso de error, serverConnect devuelve un mensaje de error en cadena. En caso de éxito, devuelve
undef.
serverService(module, authUser, authPasswd,
authRequired)
Especifica qué módulo usar (un "módulo" es el nombre simbólico que aparece dentro de "[...]" /etc/rsyncd.conf), las credenciales del usuario (authUser y authPasswd) y si la autorización es obligatoria (authRequired). Si se establece en un valor distinto de cero, authRequired asegura que el demonio Rsync remoto requiera autenticación. Si es necesario, esto es para asegurar que no se conecte a un demonio Rsync inseguro. Los argumentos de autenticación son opcionales si el módulo rsyncd seleccionado no requiere autenticación.

LIMITACIONE

S 
La versión inicial
de File::RsyncP (
0.10) tiene varias
limitaciones:

File::RsyncP solo implementa un subconjunto modesto de opciones y características de Rsync. En particular, a partir de la versión 0.10 solo se admiten

estas opciones:

--numeric-ids --perms|-p --owner|-o --group|-g --devices|D --links|-l --ignore-times|I --block-size=i --verbose|-v --recursive|-r

--relative|-R
  • Actualmente no se admiten enlaces duros. Otras opciones que solo afectan al lado remoto funcionarán correctamente ya que se pasan al Rsync remoto sin cambios. 
    Además, la semántica de --relative no está implementada para coincidir con rsync, y el
      comportamiento de la barra diagonal final "/" de rsync (que significa el contenido del directorio, no
      el directorio en sí) no está implementado en File:
    :RsyncP.

    File::RsyncP todavía no proporcion

    a una interfaz de línea de comando
    • s que imite al Rsync nativo.
  • File::RsyncP podría funcionar con versiones ligeramente anteriores de Rsync pero no ha sido probado. Ciertamente no funcionará con versiones anticuadas de
    • Rsync.
  • File::RsyncP no calcula deltas de archivo (es decir: se comporta como si se especificara --whole-file) ni implementa las opciones de exclusión o inclusión al enviar archivos. File::RsyncP sí maneja los deltas de archivo y las opciones de exclusión e inclusión al recibir
    • archivos.
  • File::RsyncP todavía no implementa la funcionalidad de servidor (actuar como el extremo remoto de una conexión o un demonio). Dado que el protocolo es relativamente simétrico, esto no es difícil de añadir, por lo que debería aparecer en una versión
    • futura.
