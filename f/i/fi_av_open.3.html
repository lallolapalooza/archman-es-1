DESCRIPCIÓ

N

Los vectores de direcciones se utilizan para mapear direcciones de nivel superior, que pueden ser más naturales para que una aplicación use, en direcciones específicas del fabric. Por ejemplo, un punto final puede estar asociado con una dirección struct sockaddr_in, indicando que el punto final es alcanzable usando un número de puerto TCP sobre una dirección IPv4. Esto puede ser cierto incluso si el punto final se comunica usando un protocolo de red propietario. El propósito del AV es asociar una dirección de nivel superior con un valor más simple y eficiente que pueda ser usado por la API de libfabric de una manera agnóstica al fabric. La dirección mapeada es de tipo fi_addr_t y se devuelve a través de una llamada de inserción de

AV.

El proceso de mapear una dirección es específico del fabric y del proveedor, pero puede involucrar resoluciones de dirección extensas y protocolos de gestión de fabric. Las operaciones de AV son sincrónicas por defecto (la opción asincrónica ha quedado obsoleta, ver abajo). Ver la sección NOTAS para las restricciones de AV sobre direcciones

duplicadas.

Obsoleto: Las operaciones de AV pueden configurarse para operar asincrónicamente especificando la bandera FI_EVENT a fi_al_open. Al solicitar operación asincrónica, la aplicación debe primero enlazar una cola de eventos al AV antes de insertar

direcciones.

(obsoleto)
Las direcciones que se insertan en un AV se mapean a una dirección nativa de fabric para su uso por la aplicación. El uso de FI_AV_MAP requiere que una aplicación almacene el valor fi_addr_t devuelto que está asociado con cada dirección insertada. La ventaja de usar FI_AV_MAP es que el valor fi_addr_t devuelto puede contener datos de dirección codificados, que están inmediatamente disponibles al procesar solicitudes de transferencia de datos. FI_FIREWALL_ADDR
Este indicador indica que la dirección está detrás de un firewall y que las conexiones salientes no están permitidas. Si no existe una conexión y el proveedor no puede sortear el firewall, se debe esperar un error FI_EFIREWALLADDR. fi_av_insertsvc

La llamada fi_av_insertsvc se comporta de manera similar a fi_av_insert, pero permite a la aplicación especificar los nombres de nodo y servicio, similar a las entradas de fi_getinfo, en lugar de una dirección codificada. Los parámetros de nodo y servicio están definidos igual que en fi_getinfo(3). El nodo debe ser una cadena que corresponda a un nombre de host o una dirección de red. La cadena de servicio corresponde a una representación textual de una dirección de transporte. Las aplicaciones también pueden pasar una dirección con formato FI_ADDR_STR como el parámetro de nodo. En tales casos, el parámetro de servicio debe ser NULL. Vea fi_getinfo.3 para detalles sobre el uso de FI_ADDR_STR. Los indicadores soportados son los mismos que para fi_av_insert.

fi_av_insertsym

fi_av_insertsym realiza una inserción simétrica que inserta un rango secuencial de direcciones de nodo y/o servicio en un AV. El parámetro svccnt indica el número de direcciones de transporte (endpoint) a insertar en el AV para cada dirección de nodo, con el parámetro de servicio especificando la dirección de transporte inicial. Las direcciones de transporte insertadas serán del rango {service, service + svccnt - 1}, inclusive. Todas las direcciones de servicio para un nodo se insertarán antes de que se inserte el siguiente nodo.

El parámetro nodecnt indica el número de direcciones de nodo (red) a insertar en el AV, con el parámetro node especificando la dirección de nodo inicial. Las direcciones de nodo insertadas serán del rango {node, node + nodecnt - 1}, inclusive. Si node es una cadena no numérica, como un nombre de host, debe contener un sufijo numérico si nodecnt > 1.

Como ejemplo, si node = “10.1.1.1”, nodecnt = 2, service = “5000”, y svccnt = 2, las siguientes direcciones serán insertadas en el AV en el orden mostrado: 10.1.1.1:5000, 10.1.1.1:5001, 10.1.1.2:5000, 10.1.1.2:5001. Si node fuera reemplazado por el nombre de host “host10”, las direcciones serían: host10:5000, host10:5001, host11:5000, host11:5001.

El número total de direcciones insertadas será nodecnt x svccnt.

Los indicadores soportados son los mismos que para fi_av_insert.

fi_av_remove

fi_av_remove elimina un conjunto de direcciones de un vector de direcciones. Los valores fi_addr_t correspondientes quedan invalidados y no pueden usarse en llamadas de transferencia de datos. El comportamiento de operaciones en curso que referencian las direcciones eliminadas es indefinido.

Tenga en cuenta que eliminar una dirección puede no deshabilitar la recepción de datos del endpoint del par. fi_av_close limpiará automáticamente cualquier recurso asociado.

Si la dirección que se está eliminó vino de fi_av_insert_auth_key, la dirección solo se eliminará si todos los endpoints, que han sido habilitados contra la clave de autorización correspondiente, han sido cerrados. Si no todos los endpoints están cerrados, se devolverá -FI_EBUSY. Además, el indicador FI_AUTH_KEY debe establecerse al eliminar una clave de autorización fi_addr_t.

fi_av_lookup

En la entrada, el parámetro addrlen debe indicar el tamaño del buffer addr. Si la dirección real es más grande de lo que cabe en el buffer, será truncada. Esta función se usa para convertir una dirección de endpoint, devuelta por fi_av_insert, en una dirección que especifica un contexto de recepción de destino. El valor de rx_ctx_bits debe coincidir con el especificado en los atributos del AV para la dirección dada.

fi_av_straddr

La función fi_av_straddr convierte la dirección proporcionada en una cadena imprimible. La dirección especificada debe tener el mismo formato que las almacenadas por el AV, aunque la dirección en sí no necesita haber sido insertada. En la entrada, el parámetro len debe especificar el tamaño del buffer referenciado por buf. En la salida, addrlen se establece al tamaño del buffer necesario para almacenar la dirección. Este tamaño puede ser mayor que el len de entrada. Si el buffer proporcionado es demasiado pequeño, los resultados serán truncados. fi_av_straddr devuelve un puntero a buf.

fi_av_insert_auth_key

Esta función asocia claves de autorización con un vector de direcciones. Esto requiere que el dominio sea abierto con FI_AV_AUTH_KEY. FI_AV_AUTH_KEY permite que los endpoints y las regiones de memoria sean asociados con claves de autorización desde el vector de direcciones. Este comportamiento permite que un solo endpoint o región de memoria sea asociado con múltiples claves de autorización.

Cuando los endpoints o las regiones de memoria son habilitados, son configurados con claves de autorización del vector de direcciones en ese momento. Las inserciones posteriores de claves de autorización no se propagarán a los endpoints y regiones de memoria ya habilitados.

Los parámetros auth_key y auth_key_size se usan para introducir la clave de autorización en el vector de direcciones. La estructura de la clave de autorización es específica del proveedor. Si el auth_key_size no se alinea con la estructura específica del proveedor, se devolverá -FI_EINVAL.

La salida de fi_av_insert_auth_key es un identificador de clave de autorización fi_addr_t que representa todas las direcciones de endpoint contra esta clave de autorización específica. Para todas las operaciones, incluyendo vector de direcciones, registro de memoria y transferencias de datos, que puedan aceptar una clave de autorización fi_addr_t como entrada, debe especificarse el indicador FI_AUTH_KEY. De lo contrario, el fi_addr_t será tratado como un fi_addr_t devuelto por fi_av_insert y funciones relacionadas.

Para endpoints habilitados con FI_DIRECTED_RECV, las claves de autorización fi_addr_t pueden usarse para restringir los mensajes entrantes solo a direcciones de endpoint dentro de la clave de autorización. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_recvmsg y fi_trecvmsg.

Para dominios habilitados con FI_DIRECTED_RECV, las claves de autorización fi_addr_t pueden usarse para restringir el acceso a la región de memoria solo a direcciones de endpoint dentro de la clave de autorización. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_mr_regattr.

Estas claves de autorización fi_addr_t pueden usarse posteriormente como entrada para funciones de inserción de direcciones de endpoint para generar un fi_addr_t para una dirección de endpoint y clave de autorización específicas. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_av_insert y funciones relacionadas.

Para vectores de direcciones configurados con FI_AV_USER_ID y endpoints con FI_SOURCE_ERR, todos los eventos de error FI_EADDRNOTAVAIL posteriores devolverán FI_ADDR_NOTAVAIL hasta que el usuario defina un ID de usuario para esta clave de autorización fi_addr_t. Esto se hace usando fi_av_set_user_id.

Para vectores de direcciones configurados sin FI_AV_USER_ID y endpoints con FI_SOURCE_ERR, todos los eventos de error FI_EADDRNOTAVAIL posteriores devolverán el identificador de clave de autorización fi_addr_t.

Los indicadores están reservados para uso futuro y deben ser 0.

NOTA

S

Un AV solo debe almacenar una única instancia de una dirección. Intentar insertar una copia duplicada de la misma dirección en un AV puede resultar en un comportamiento indefinido, dependiendo de la implementación del proveedor. No se requiere

que los proveedores comprueben si hay duplicados, ya que hacerlo podría incurrir en una sobrecarga significativa en el proceso de inserción. Para la portabilidad, las aplicaciones pueden necesitar realizar un seguimiento de las direcciones de
los pares que se han insertado en un AV determinado para evitar entradas duplicadas. Sin embargo, se requiere que los proveedores admitan la eliminación y la posterior reinserción de una dirección. Solo se restringen las inserciones duplicadas.

IDENTIFICADORES DE USUARIO PARA

DIRECCIONES

Como se describe arriba, las direcciones de los puntos de conexión y las claves de autorización que se insertan en un AV se asignan a un valor fi_addr_t. El fi_addr_t de la dirección del punto de conexión se utiliza en las API de transferencia de datos para especificar el destino de una transferencia saliente, en las API de recepción para indicar el origen de una transferencia entrante y también en los eventos de finalización para informar de la dirección de origen de las transferencias entrantes. Los fi_addr_t de la clave de autorización se utilizan en las API de recepción y MR para restringir las operaciones entrantes a una clave de autorización específica, y también en los eventos de error de finalización si el punto de conexión está configurado con FI_SOURCE_ERR. El bit de capacidad y el indicador FI_AV_USER_ID proporcionan un mecanismo por el cual el valor fi_addr_t informado por un evento de finalización (de éxito o error) se sustituye por un valor especificado por el usuario. Esto es útil para las aplicaciones que necesitan asignar la dirección de origen a su propia estructura de

datos.

El soporte para FI_AV_USER_ID es específico del proveedor, ya que puede que no sea factible para un proveedor implementar este soporte sin una sobrecarga significativa. Por ejemplo, algunos proveedores pueden necesitar añadir un mecanismo de búsqueda inversa. Esta función puede no estar disponible si se solicitan AV compartidos, o puede afectar negativamente a la huella de memoria por proceso si se implementa. Para los proveedores que no admiten FI_AV_USER_ID, los usuarios pueden compensar el procesamiento de búsqueda con la sobrecarga del protocolo, incluyendo la identificación del origen en un encabezado de

mensaje.

Para los vectores de direcciones abiertos sin FI_AV_USER_ID, los valores fi_addr_t especificados por el usuario se proporcionan como parte de la inserción de direcciones (p. ej., fi_av_insert) a través del parámetro fi_addr. En este caso, el parámetro fi_addr actúa como entrada/salida. Cuando se pasa el indicador FI_AV_USER_ID a cualquiera de las llamadas de inserción, el llamador debe especificar un valor identificador fi_addr_t para asociar con cada dirección. El proveedor registrará ese identificador y lo utilizará donde sea necesario como parte de cualquier evento de finalización. Tenga en cuenta que la salida de la llamada de inserción del AV no cambia. El proveedor devolverá un valor fi_addr_t que se asigna a cada dirección, y ese valor debe utilizarse para todas las operaciones de transferencia de

datos.

GRUPOS DE

PARES

Los grupos de pares proporcionan una asignación directa a las construcciones de comunicadores de HPC e

IA.

Las direcciones en un AV representan el conjunto completo de pares con los que un proceso local puede comunicarse. Un grupo de pares representa conceptualmente un subconjunto de esos pares. Un grupo de pares puede utilizarse para identificar pares que trabajan en una tarea común y cuya comunicación necesita estar lógicamente separada del resto del tráfico. Los grupos de pares no son un mecanismo de seguridad, sino que ayudan a separar los datos. Un par determinado puede pertenecer a 0 o más grupos de pares, sin límite en el número de pares que pueden pertenecer a un solo grupo de

pares.

Los grupos de pares se identifican mediante un valor entero, conocido como id de grupo. Los id de grupo los selecciona el usuario y se transmiten como parte de un valor fi_addr_t. La gestión de un id de grupo y su relación con las direcciones insertadas en un AV la controla directamente el usuario. Cuando está habilitado, los mensajes enviados se marcan como pertenecientes a un grupo de pares específico, y los búferes de recepción publicados deben tener un id de grupo coincidente para recibir los

datos.

Los usuarios son responsables de seleccionar un id de grupo de pares válido, sujeto a la limitación negociada mediante el atributo de dominio max_group_id. El id de grupo de un fi_addr_t se puede establecer usando la función fi_group_addr()

VALORES DE

RETORNO

Las llamadas de inserción, excluyendo fi_av_insert_auth_key, para un AV abierto para operación síncrona devolverán el número de direcciones que se insertaron correctamente. En caso de fallo, el valor de retorno será menor que el número de direcciones

especificado.

Obsoleto: Las llamadas de inserción, excluyendo fi_av_insert_auth_key, para un AV abierto para operación asíncrona (con el indicador FI_EVENT especificado) devolverán FI_SUCCESS si la operación se inició correctamente. En caso de fallo, se devolverá un código de error de fabrica (errno) negativo. Se permite a los proveedores abortar las operaciones de inserción en caso de error. Las direcciones que no se insertan porque fueron abortadas fallarán con un código de error

FI_ECANCELED.

En ambos modos de operación, síncrono y asíncrono, el búfer fi_addr asociado con una inserción fallida o abortada se establecerá en FI_ADDR_NOTAVAIL

.

Todas las demás llamadas devuelven FI_SUCCESS en caso de éxito, o un valo

r negativo correspondiente a un código de error de fabrica (errno) en caso
de error. Los valores de error de fabrica se definen en rdma/fi_errno.h.
