Consulte fi_arch(7) para una descripción breve de cómo los proveedores encajan en la arquitectura de

libfabric.

Conceptualmente, un proveedor de fabric implementa y mapea la API de libfabric sobre software y/o hardware de red de bajo nivel. La mayoría de las llamadas de la aplicación a la API de libfabric van directamente a la implementación de esa API por parte del

proveedor.

Los proveedores de libfabric se agrupan en diferentes tipos: núcleo, utilidad, enganche y descarga. Estos se describen con más detalle a continuación. El siguiente diagrama ilustra la arquitectura entre los tipos de

proveedores. 
---------------------------- API de libfabric ----------------------------
  [núcleo]   proveed
or|<- [proveedor de enganche] [servicios] API | --- API de libfabric ---
|<- [proveedor de utilidad] | ---------------- API de libfabric --------
---------- |<- [proveedor de núcleo] <-API de par-> [proveedor de descarga]

Todos los proveedores se conectan a libfabric utilizando una API de proveedor exportada. libfabric admite tanto proveedores internos, que se incluyen con la biblioteca para la comodidad del usuario, como proveedores externos. Las bibliotecas de proveedores externos deben estar en la ruta de búsqueda de bibliotecas, terminar con el sufijo “-fi” y exportar la función fi_prov_ini()

.

Una vez registrado con el núcleo de libfabric, un proveedor será informado a las aplicaciones como parte del proceso de descubrimiento. Los proveedores de enganche y utilidad interceptarán las llamadas de libfabric de la aplicación para realizar alguna tarea antes de pasar la llamada al siguiente proveedor. Si no es necesario interceptar una llamada API específica, la aplicación llamará directamente al proveedor de núcleo. Siempre que sea posible, la comunicación entre proveedores se realiza utilizando las propias APIs de libfabric, incluido el uso de extensiones específicas del proveedor para reducir la sobrecarga de las

llamadas.

libfabric define un conjunto de APIs que se dirigen específicamente a proveedores que pueden usarse como pares. Estas APIs, por ext

raño que parezca, se llaman APIs de par. Las APIs de par son técnicamente parte de la API externa de libfabric, pero no están di
señadas para el uso directo por parte de las aplicaciones y no se consideran estables para la compatibilidad hacia atrás de la API.

Proveedores de

Núcleo

Los proveedores de núcleo son proveedores independientes que suelen dirigirse a una clase específica de dispositivos de red. Es decir, una NIC específica, una clase de hardware de red o una interfaz de software de bajo nivel. Los proveedores de núcleo son normalmente los que más preocupan a la mayoría de los desarrolladores de aplicaciones. Los proveedores de núcleo pueden solo soportar características e interfaces de libfabric que se mapeen eficientemente al hardware subyacente o a los protocolos de

red.

Los siguientes proveedores de núcleo están integrados en libfabric por defecto, suponiendo que se cumplen todos los prerrequisitos de compilación. Es decir, las bibliotecas necesarias están instaladas, hay soporte del sistema operativo disponible, etc. Esta lista no es

exhaustiva.

Proveedores de

Utilidad

Los proveedores de utilidad se nombran con un prefijo inicial de “ofi_”. Los proveedores de utilidad son distintos de los proveedores de núcleo en que no están asociados con clases específicas de dispositivos. En su lugar, trabajan con los proveedores de núcleo para expandir sus características e interactúan con los proveedores de núcleo a través de interfaces de libfabric internamente. Los proveedores de utilidad se utilizan para soportar un tipo de punto final específico sobre un tipo de punto final más

simple.

Los proveedores de utilidad aparecen como parte del nombre del proveedor devuelto. Consulte fi_fabric(3). Los proveedores de utilidad se habilitan automáticamente para los proveedores de núcleo que no soportan el conjunto de características solicitado por una

aplicación.

Proveedores de

Enganche

Los proveedores de enganche se usan principalmente con fines de depuración. Dado que los proveedores de enganche se construyen e incluyen en las versiones de publicación de libfabric, siempre están disponibles y no tienen impacto en el rendimiento a menos que se habiliten. Los proveedores de enganche pueden superponerse a todos los demás proveedores e interceptar, o enganchar, sus llamadas para realizar alguna tarea dedicada, como recopilar datos de rendimiento sobre rutas de llamada o proporcionar salida de

depuración.

Consulte fi_ho

ok(7) para má
s información.

Proveedores de

Descarga

Los proveedores de descarga comienzan con el prefijo de nombre “off_”. Un proveedor de descarga está destinado a ser emparejado con otros

proveedores de núcleo y/o utilidad. Un proveedor de descarga tiene como objetivo acelerar tipos específicos de comunicación, generalmen
te aprovechando servicios de red que se han descargado en hardware, aunque el soporte real de descarga en hardware no es un requisito.

Proveedor LINKx

(LNX)

El proveedor LNX está diseñado para vincular dos o más proveedores, permitiendo a las aplicaciones usar de forma transparente múltiples proveedores o NICs. Este proveedor utiliza la infraestructura de pares de libfabric para ayudar en el uso de los proveedores subyacentes. Esta versión del proveedor es capaz de vincular cualquier proveedor de libfabric que soporte la capacidad

FI_PEER.

nx(7) para más
información.
