File::Fetch(3perl) Guía del programador de Perl File::Fetch(3perl)

NOMBRE

File::Fetch - Un mecanismo genérico para obtener archivos

SINOPSIS

use File::Fetch;
### construir un objeto File::Fetch ###
my $ff = File::Fetch->new(uri => 'http://algun.lugar.com/directorio/a.txt');
### obtener la uri en cwd() ###
my $donde = $ff->fetch() or die $ff->error;
### obtener la uri en /tmp ###
my $donde = $ff->fetch( to => '/tmp' );
### partes analizadas de la uri ###
$ff->uri;
$ff->scheme;
$ff->host;
$ff->path;
$ff->file;

DESCRIPCIÓN

File::Fetch es un mecanismo genérico para obtener archivos.

Te permite obtener cualquier archivo apuntado por una URI de "ftp", "http", "file", "git" o "rsync" utilizando diversos medios.

Consulta la sección "CÓMO FUNCIONA" más abajo para obtener detalles.

ACCESORES

Un objeto "File::Fetch" tiene los siguientes accesores

$ff->uri
La URI que pasaste al constructor
$ff->scheme
El esquema de la URI (como 'file', 'http', etc.)
$ff->host
El nombre de host en la URI. Estará vacío si el host era originalmente 'localhost' para una URL 'file://'.
$ff->vol
En sistemas operativos con el concepto de volumen, el segundo elemento de un 'file://' se considera la especificación del volumen para el archivo. Por lo tanto, en Win32 esta rutina devuelve el volumen, en otros sistemas operativos no devuelve nada.

En Windows, este valor puede estar vacío si la URI es de un recurso compartido de red, en cuyo caso la propiedad 'share' se definirá. Además, las especificaciones de volumen que usan '|' en lugar de ':' se convertirán al leer para usar ':'.

En VMS, que tiene un concepto de volumen, este campo estará vacío porque las especificaciones de archivos de VMS se convierten al formato UNIX absoluto y la información del volumen se incluye transparente.

$ff->share
En sistemas con el concepto de recurso compartido de red (actualmente solo Windows), devuelve el nombre del recurso compartido de una URL 'file:////'. En otros sistemas operativos, devuelve vacío.
$ff->path
La ruta de la URI, será al menos un solo '/'.
$ff->file
El nombre del archivo remoto. Para el nombre del archivo local, se usará el resultado de $ff->output_file.
$ff->file_default
El nombre del archivo local predeterminado, al que $ff->output_file recurre si de otra manera no devolvería ningún nombre de archivo. Por ejemplo, al obtener una URI como http://www.abc.net.au/, el contenido recuperado puede ser de un archivo remoto llamado 'index.html'. El valor predeterminado de este atributo es literalmente 'file_default'.
$ff->output_file
El nombre del archivo de salida. Es lo mismo que $ff->file, pero se eliminan los parámetros de consulta. Por ejemplo: http://example.com/index.html?x=y

haría que el archivo de salida fuera "index.html" en lugar de "index.html?x=y".

MÉTODOS

(es) $ff = File::Fetch->new( uri => 'http://algun.lugar.com/directorio/archivo.txt' );

Analiza la URI y crea un objeto File::Fetch::Item correspondiente, listo para ser "fetch"ed y lo devuelve.

Devuelve falso en caso de fallo.

(es) $donde = $ff->fetch( [to => /mi/directorio/de/salida/ | \$escalar] )

Obtiene el archivo que solicitaste y devuelve la ruta completa al archivo.

Por defecto, escribe en cwd(), pero puedes anularlo especificando el argumento "to":

### obtener archivo en /tmp, ruta completa al archivo en $donde
$donde = $ff->fetch( to => '/tmp' );
### archivo cargado en $escalar, ruta completa al archivo en $donde
### el archivo se descarga en un directorio temporal y se limpia al salir
$donde = $ff->fetch( to => \$escalar );

Devuelve la ruta completa al archivo descargado en caso de éxito, y falso en caso de fallo.

(es) $ff->error([BOOL])

Devuelve el último error encontrado como una cadena. Pásale un valor verdadero para obtener la salida de Carp::longmess() en su lugar.

CÓMO FUNCIONA

File::Fetch puede obtener una variedad de URIs, utilizando varios programas y módulos externos.

A continuación se muestra una correspondencia de qué utilidades se utilizarán en qué orden y para qué esquemas, si están disponibles:

file    => LWP, lftp, file
http    => LWP, HTTP::Tiny, wget, curl, lftp, fetch, HTTP::Lite, lynx, iosock
ftp     => LWP, Net::FTP, wget, curl, lftp, fetch, ncftp, ftp
rsync   => rsync
git     => git

Si deseas deshabilitar el uso de una o más de estas utilidades y/o módulos, consulta la variable $BLACKLIST más abajo.

Si una utilidad o módulo no está disponible, se marcará en una caché (consulta la variable $METHOD_FAIL más abajo), por lo que no se intentará de nuevo. El método "fetch" solo fallará cuando se agoten todas las opciones y no haya podido recuperar el archivo.

La utilidad "fetch" está disponible en FreeBSD. NetBSD y Dragonfly BSD también pueden tenerla desde "pkgsrc". Solo verificamos "fetch" en esas tres plataformas.

"iosock" es un mecanismo muy limitado basado en IO::Socket::INET para recuperar URL con esquema "http". No sigue redirecciones, por ejemplo.

"git" solo admite URL de estilo "git://".

Una nota especial sobre la obtención de archivos desde una URI ftp:

Por defecto, todas las conexiones ftp se realizan en modo pasivo. Para cambiar eso, consulta la variable $FTP_PASSIVE más abajo.

Además, las URI ftp solo admiten conexiones anónimas, por lo que no se puede pasar un par de nombre de usuario/contraseña.

"/bin/ftp" está en la lista negra por defecto; consulta la variable $BLACKLIST más abajo.

VARIABLES GLOBALES

El comportamiento de File::Fetch se puede alterar cambiando las siguientes variables globales:

$File::Fetch::FROM_EMAIL

Esta es la dirección de correo electrónico que se enviará como tu contraseña de ftp anónimo.

El valor predeterminado es "File-Fetch@example.com".

$File::Fetch::USER_AGENT

Este es el user agent tal como lo informará "LWP".

El valor predeterminado es "File::Fetch/$VERSION".

$File::Fetch::FTP_PASSIVE

Esta variable controla si la variable de entorno "FTP_PASSIVE" y cualquier opción pasiva para herramientas de línea de comandos se establecerán en verdadero.

El valor predeterminado es 1.

Nota: Cuando $FTP_PASSIVE es verdadero, "ncftp" no se usará para obtener archivos, ya que el modo pasivo solo se puede establecer
