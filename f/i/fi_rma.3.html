NOMBRE

fi_rma - Operaciones de acceso a memoria remota

fi_read / fi_readv / fi_readmsg
Inicia una lectura desde la memoria remota

fi_write / fi_writev / fi_writemsg fi_inject_write / fi_writedata : Inicia una escritura hacia la memoria remota

SINOPSIS

#include <rdma/fi_rma.h>
ssize_t fi_read(struct fid_ep *ep, void *buf, size_t len, void *desc,
    fi_addr_t src_addr, uint64_t addr, uint64_t key, void *context);
ssize_t fi_readv(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t src_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_readmsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_write(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writev(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writemsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_inject_write(struct fid_ep *ep, const void *buf, size_t len,
    fi_addr_t dest_addr, uint64_t addr, uint64_t key);
ssize_t fi_writedata(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, uint64_t data, fi_addr_t dest_addr, uint64_t addr,
    uint64_t key, void *context);
ssize_t fi_inject_writedata(struct fid_ep *ep, const void *buf, size_t len,
    uint64_t data, fi_addr_t dest_addr, uint64_t addr, uint64_t key);

ARGUMENTOS

ep
Punto de extremo de la fabrica en el que iniciar la operación de lectura o escritura.
buf
Búfer de datos local en el que leer (destino de lectura) o desde el cual escribir (fuente de escritura)
len
Longitud de datos a leer o escribir, especificada en bytes. Las transferencias válidas son desde 0 bytes hasta el max_msg_size del punto de extremo.
iov
Búfer de datos vectorizado.
count
Recuento de entradas de datos vectorizados.
addr
Dirección de la memoria remota a acceder. Esta será la dirección virtual de la región remota en el caso de FI_MR_BASIC, o el desplazamiento desde la dirección inicial en el caso de FI_MR_SCALABLE.
key
Clave de protección asociada con la memoria remota.
desc
Descriptor asociado con el búfer de datos local. Véase fi_mr(3).
data
Datos de CQ remotos a transferir con la operación.
dest_addr
Dirección de destino para transferencias de escritura sin conexión. Ignorado para puntos de extremo conectados.
src_addr
Dirección de origen desde la que leer para transferencias sin conexión. Ignorado para puntos de extremo conectados.
msg
Descriptor de mensaje para operaciones de lectura y escritura.
flags
Banderas adicionales a aplicar para la operación de lectura o escritura.
context
Puntero especificado por el usuario para asociar con la operación. Este parámetro se ignora si la operación no generará una finalización exitosa, a menos que una bandera de operación especifique que el parámetro context se utilice para la entrada requerida.

DESCRIPCIÓN

Las operaciones RMA (acceso a memoria remota) se utilizan para transferir datos directamente entre un búfer de datos local y un búfer de datos remoto. Las transferencias RMA ocurren a nivel de granularidad de byte, y no se mantienen límites de mensajes.

Las funciones de escritura – fi_write, fi_writev, fi_writemsg, fi_inject_write y fi_writedata – se utilizan para transmitir datos a un búfer de memoria remota. La principal diferencia entre las funciones de escritura son el número y tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

Las funciones de lectura – fi_read, fi_readv y fi_readmsg – se utilizan para transferir datos desde una región de memoria remota hacia búfer(es) de datos local(es). De manera similar a las operaciones de escritura, las operaciones de lectura operan de forma asíncrona. Los usuarios no deben tocar el(los) búfer(es) de datos publicado(s) hasta que la operación de lectura se haya completado.

Las operaciones RMA completadas se reportan al usuario a través de una o más colas de completado asociadas con el punto de extremo. Los usuarios proporcionan contextos que se asocian con cada operación, y se devuelven al usuario como parte de la finalización. Véase fi_cq para detalles de eventos de finalización.

Por defecto, el punto de extremo remoto no genera un evento ni notifica al usuario cuando una región de memoria ha sido accedida por una operación de lectura o escritura RMA. Sin embargo, los datos inmediatos pueden asociarse con una operación de escritura RMA. Las escrituras RMA con datos inmediatos generarán una entrada de finalización en el punto de extremo remoto, de modo que los datos inmediatos puedan ser entregados.

fi_write

La llamada fi_write transfiere los datos contenidos en el búfer de datos especificado por el usuario a una región de memoria remota.

fi_writev

La llamada fi_writev añade soporte para una lista de dispersión-agrupación (scatter-gather) a fi_write. El fi_writev transfiere el conjunto de búferes de datos referenciados por el parámetro iov a la región de memoria remota.

fi_writemsg

La llamada fi_writemsg soporta transferencias de datos sobre puntos de extremo tanto conectados como sin conexión, con la capacidad de controlar la operación de escritura por llamada mediante el uso de banderas. La función fi_writemsg toma un struct fi_msg_rma como entrada.

struct fi_msg_rma {
    const struct iovec *msg_iov;     /* arreglo local de dispersión-agrupación */
    void               **desc;       /* descriptor de operación */
    size_t             iov_count;    /* # elementos en msg_iov */
    fi_addr_t          addr;        /* dirección de extremo opcional */
    const struct fi_rma_iov *rma_iov;/* SGL remoto */
    size_t             rma_iov_count;/* # elementos en rma_iov */
    void               *context;     /* contexto definido por el usuario */
    uint64_t           data;         /* datos inmediatos opcionales */
};
struct fi_rma_iov {
    uint64_t           addr;         /* dirección RMA de destino */
    size_t             len;          /* tamaño del búfer de destino */
    uint64_t           key;          /* clave de acceso */
};

fi_inject_write

La llamada de inyección de escritura es una versión optimizada de fi_write. Proporciona semánticas de finalización similares a fi_inject fi_msg(3).

fi_writedata

La llamada de escritura de datos es similar a fi_write, pero permite el envío de datos de CQ remotos (véase la bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_inject_writedata

La llamada de inyección de escritura de datos es similar a fi_inject_write, pero permite el envío de datos de CQ remotos (véase la bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_read

La llamada fi_read solicita que el punto de extremo remoto transfiera datos desde la región de memoria remota hacia el búfer de datos local.

fi_readv

La llamada fi_readv añade soporte para una lista de dispersión-agrupación (scatter-gather) a fi_read. El fi_readv transfiere datos desde la región de memoria remota hacia el conjunto de búferes de datos referenciados por el parámetro iov.

fi_readmsg

La llamada fi_readmsg soporta transferencias de datos sobre puntos de extremo tanto conectados como sin conexión, con la capacidad de controlar la operación de lectura por llamada mediante el uso de banderas. La función fi_readmsg toma un struct fi_msg_rma como entrada.

FLAGS

Las llamadas `fi_readmsg` y `fi_writemsg` permiten al usuario especificar flags que pueden cambiar la operación de transferencia de datos predeterminada. Los flags especificados con `fi_readmsg` / `fi_writemsg` anulan la mayoría de los flags configurados previamente con el endpoint, excepto donde se indica lo contrario (ver `fi_endpoint.3`). La siguiente lista de flags son utilizables con `fi_readmsg` y/o `fi_writemsg`.

FI_REMOTE_CQ_DATA
Se aplica a `fi_writemsg`. Indica que los datos de CQ remotos están disponibles y deben enviarse como parte de la solicitud. Ver `fi_getinfo` para más detalles sobre `FI_REMOTE_CQ_DATA`. Este flag se establece implícitamente para `fi_writedata` e `fi_inject_writedata`.
FI_COMPLETION
Indica que se debe generar una entrada de finalización para la operación especificada. El endpoint debe estar enlazado a una cola de finalización con `FI_SELECTIVE_COMPLETION` que corresponda a la operación especificada, o este flag se ignorará.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que se publicarán inmediatamente después de que la llamada actual regrese. El uso de este flag puede mejorar el rendimiento al permitir que el proveedor optimice su acceso al hardware de la red.
FI_INJECT
Se aplica a `fi_writemsg`. Indica que el buffer de datos de salida debe devolverse al usuario inmediatamente después de que la llamada de escritura regrese, incluso si la operación se maneja de forma asíncrona. Esto puede requerir que la implementación del proveedor subyacente copie los datos a un buffer local y transfiera desde ese buffer. Este flag solo se puede usar con mensajes más pequeños que `inject_size`.
FI_INJECT_COMPLETE
Se aplica a `fi_writemsg`. Indica que se debe generar una finalización cuando los buffers de origen puedan reutilizarse.
FI_TRANSMIT_COMPLETE
Se aplica a `fi_writemsg`. Indica que no se debe generar una finalización hasta que la operación se haya transmitido con éxito y ya no sea rastreada por el proveedor.
FI_DELIVERY_COMPLETE
Se aplica a `fi_writemsg`. Indica que se debe generar una finalización cuando la operación haya sido procesada por el destino.
FI_COMMIT_COMPLETE
Se aplica a `fi_writemsg` cuando se apunta a regiones de memoria persistente. Indica que una finalización solo se generará después de que el resultado de la operación se haya hecho duradero.
FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como operación cercada, y cualquier operación publicada después de la operación cercada se pospondrán hasta que todas las operaciones anteriores dirigidas al mismo endpoint par hayan completado. Las operaciones publicadas después del cercado verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación cercada.

El orden de las operaciones que comienzan con la publicación de la operación cercada (inclusive) hasta la publicación de una operación cercada subsiguiente (exclusiva) se controla mediante las semánticas de ordenación del endpoint.

VALOR DE RETORNO

Devuelve 0 en caso de éxito. En caso de error, se devuelve un valor negativo que corresponde al errno de la red. Los valores de errno de la red se definen en `rdma/fi_errno.h`.

ERRORES

-FI_EAGAIN
Ver `fi_msg(3)` para una descripción detallada del manejo de `FI_EAGAIN`.

VER TAMBIÉN
