NOMBRE

fi_tcp - Proveedor que se ejecuta sobre TCP/IP

DESCRIPCIÓN

El proveedor tcp es utilizable en todos los sistemas operativos compatibles con libfabric. Se ejecuta sobre sockets TCP (SOCK_STREAM) e incluye la capacidad de aprovechar características específicas de la operación, como el soporte para copia cero y io_uring. El proveedor implementa un protocolo personalizado sobre TCP/IP necesario para admitir las API de comunicación de libfabric.

CARACTERÍSTICAS SOPORTADAS

Las siguientes características son compatibles:

Tipos de punto final
FI_EP_MSG FI_EP_RDM
Capacidades del punto final
FI_MSG, FI_RMA, FI_TAGGED, FI_RMA_PMEM, FI_RMA_EVENT, FI_MULTI_RECV, FI_DIRECTED_RECV
Contexto de recepción compartido
El proveedor tcp soporta el contexto de recepción compartido.

PARÁMETROS DE EJECUCIÓN

El proveedor tcp puede configurarse utilizando varias variables de entorno. Un subconjunto de variables soportadas se define a continuación. Para una lista completa, utilice la utilidad de aplicación fi_info. Por ejemplo, `fi_info -g tcp` mostrará todas las variables de entorno definidas para el proveedor tcp.

FI_TCP_IFACE
Se puede solicitar una interfaz de red específica con esta variable.
FI_TCP_PORT_LOW_RANGE/FI_TCP_PORT_HIGH_RANGE
Estas variables se utilizan para establecer el rango de puertos que utilizará el proveedor tcp para la creación de su punto final pasivo. Esto es útil cuando solo se permite un rango de puertos por el firewall para las conexiones TCP.
FI_TCP_TX_SIZE
Tamaño del contexto de transmisión. Este es el número de solicitudes de transmisión que una aplicación puede publicar al proveedor antes de recibir -FI_EAGAIN. Por defecto: 256 para puntos finales de mensajes, 64k para RDM.
FI_TCP_RX_SIZE
Tamaño del contexto de recepción. Este es el número de búferes de recepción que la aplicación puede publicar al proveedor. Por defecto: 256 para puntos finales de mensajes, 64k para RDM.
FI_TCP_MAX_INJECT
Tamaño máximo de los mensajes de inyección y el tamaño máximo de un mensaje inesperado que puede ser almacenado en búfer en el receptor. Por defecto: 128 bytes.
FI_TCP_STAGING_SBUF_SIZE
Tamaño del búfer utilizado para agrupar iovec o solicitudes de envío antes de publicarlas en el kernel. El búfer de preparación se utiliza cuando el socket está ocupado y no puede aceptar nuevos datos. En ese caso, los datos pueden ser encolados en el búfer de preparación hasta que el socket reanude el envío. Esto optimiza la transferencia de una serie de mensajes pequeños consecutivos al mismo destino. Por defecto: 9000 bytes. Establecer a 0 para deshabilitar.
FI_TCP_PREFETCH_RBUF_SIZE
Tamaño del búfer utilizado para pre-recuperar datos recibidos del kernel. Al comenzar a recibir un nuevo mensaje, el proveedor solicitará al kernel que llene el búfer de pre-recuperación y procese los datos recibidos desde allí. Esto reduce el número de llamadas al kernel necesarias para recibir una serie de mensajes pequeños. Por defecto: 9000 bytes. Establecer a 0 para deshabilitar.
FI_TCP_ZEROCOPY_SIZE
Umbral inferior en el que se utilizarán transferencias de copia cero, si es compatible con la plataforma, establecido a -1 para deshabilitar. Por defecto: deshabilitado.
FI_TCP_TRACE_MSG
Si está habilitado, registrará información de mensajes de transporte en todos los mensajes enviados y recibidos. Debe emparejarse con FI_LOG_LEVEL=trace para imprimir los detalles del mensaje.
FI_TCP_IO_URING
Utiliza io_uring para operaciones de socket si está disponible, en lugar de pasar por las API de socket estándar (es decir, connect, accept, send, recv). Por defecto: deshabilitado.

OPERACIONES DE CONTROL

El proveedor tcp soporta las siguientes operaciones de control (ver fi_control(3)):

FI_GET_FD
Recupera el descriptor de archivo de socket subyacente asociado con un punto final activo. El argumento debe apuntar a un entero donde se almacenará el descriptor. Esto permite a las aplicaciones ajustar opciones de socket no expuestas a través de la API de libfabric (SO_SNDBUF, SO_RCVBUF, SO_BUSY_POLL, etc.).

NOTAS

El proveedor tcp soporta puntos finales de mensajes (msg) y RDM directamente. El soporte para puntos finales RDM está disponible a partir de la versión v1.18.0 de libfabric, y proviene de la fusión del proveedor net que se encuentra en las versiones v1.16 y v1.17 de libfabric. Para compatibilidad con versiones anteriores de libfabric, el proveedor tcp puede combinarse con el proveedor ofi_rxm como una solución alternativa para el soporte de puntos finales RDM. Se recomienda que las aplicaciones que no necesiten compatibilidad de cableado con versiones anteriores de libfabric utilicen el soporte de puntos finales RDM directamente del proveedor tcp. Esto proporcionará el mejor rendimiento.

VER TAMBIÉN
