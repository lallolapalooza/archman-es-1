Paquete: perl-file-finder

File::Finder::Steps(3pm) Documentación de Perl contribuida por el usuario File::Finder::Steps(3pm)

NOMBRE

File::Finder::Steps - pasos para File::Finder

SINOPSIS

## Ver File::Finder para uso normal de los pasos
## ejemplo de subclasificación:
BEGIN {
  package My::File::Finder;
  use base File::Finder;
  sub _steps_class { "My::File::Finder::Steps" }
}
BEGIN {
  package My::File::Finder::Steps;
  use base File::Finder::Steps;
  sub bigger_than { # verdadero si es mayor que N bytes
    my $self = shift;
    my $bytes = shift;
    return sub {
      -s > $bytes;
    }
  }
}
my $over_1k = My::File::Finder->bigger_than(1024);
print "Archivos temporales mayores que 1k:\n";
$over_1k->ls->in("/tmp");

DESCRIPCIÓN

"File::Finder::Steps" proporciona los predicados que se prueban para "File::Finder".

MÉTODOS DE PASOS

Estos métodos se llaman sobre una clase o instancia para añadir un "paso". Cada paso se añade a una lista de pasos, devolviendo el nuevo objeto. Esto le permite encadenar pasos para formar una fórmula.

Al igual que en find, el operador por defecto es "and", y se realiza un cortocircuito.

or
Como el "or" de find.
left
Como un paréntesis izquierdo. Se utiliza anidado en pares con "right".
right
Como un paréntesis derecho. Se utiliza anidado en pares con "left". Por ejemplo: 
my $big_or_old = File::Finder
  ->type('f')
  ->left
    ->size("+100")->or->mtime("+90")
  ->right;
find($big_or_old->ls, "/tmp");

Necesita paréntesis porque el operador "or" tiene menor precedencia que el "and" implícito, por la misma razón que los necesita aquí:

find /tmp -type f '(' -size +100 -o -mtime +90 ')' -print

Sin los paréntesis, -type se vincularía a -size, y no a la elección de -size o -mtime.

Los paréntesis desequilibrados no se encontrarán hasta que se utilice la fórmula, lo que provocará un error fatal.

begin
Alias de "left".
end
Alias de "right".
not
Como el "!" de find. Operador prefijo, puede colocarse delante de términos individuales o paréntesis abiertos. Se puede anidar, pero ¿cuál es el propósito? 
# listar todos los no archivos en /tmp
File::Finder->not->type('f')->ls->in("/tmp");
true
Siempre devuelve verdadero. Útil cuando una subexpresión puede fallar, pero no desea que el código general falle: 
... ->left-> ...[puede devolver falso]... ->or->true->right-> ...

Por supuesto, este es el modismo del comando find de:

find .... '(' .... -o -true ')' ...
false
Siempre devuelve falso.
comma
Como la "," de find de GNU. El resultado de la expresión (o subexpresión si está entre paréntesis) hasta este punto se descarta, y la ejecución continúa de nuevo. Útil cuando una parte de la expresión es necesaria por sus efectos secundarios, pero no debe afectar al resto de la cadena "and"-ed. 
# listar todos los archivos y directorios, pero no descender al contenido del directorio CVS:
File::Finder->type('d')->name('CVS')->prune->comma->ls->in('.');
follow
Habilita el seguimiento de enlaces simbólicos y devuelve verdadero.
name(NOMBRE)
Verdadero si el nombre base coincide con NOMBRE, que puede proporcionarse como un patrón glob o un objeto de expresión regular: 
my $pm_files = File::Finder->name('*.pm')->in('.');
my $pm_files_too = File::Finder->name(qr/pm$/)->in('.');
perm(PERMISO)
Como "-perm" de find. El prefijo "-" significa "todos estos bits". El prefijo "+" significa "cualquiera de estos bits". El valor se de-octaliza si está presente un 0 inicial, lo cual es probable solo si se pasa como una cadena. 
my $files = File::Finder->type('f');
# encontrar archivos con modo exactamente 644
my $files_644 = $files->perm(0644);
# encontrar archivos que sean al menos ejecutables por el mundo:
my $files_world_exec = $files->perm("-1");
# encontrar archivos que tengan algún bit de ejecución establecido:
my $files_exec = $files->perm("+0111");
type(TIPO)
Como "-type" de find. Todos los tipos nativos de Perl son compatibles. Tenga en cuenta que "s" es un socket, que se mapea al "-S" de Perl, para ser consistente con find. Devuelve verdadero o falso, según corresponda.
print
Imprime el nombre completo en "STDOUT", seguido de un salto de línea. Devuelve verdadero.
print0
Imprime el nombre completo en "STDOUT", seguido de un NULO. Devuelve verdadero.
fstype
Aún no implementado.
user(USUARIO|UID)
Verdadero si el propietario es USUARIO o UID.
group(GRUPO|GID)
Verdadero si el grupo es GRUPO o GID.
nouser
Verdadero si la entrada no pertenece a ningún usuario conocido.
nogroup
Verdadero si la entrada no pertenece a ningún grupo conocido.
links( +/- N )
Como "-links N" de find. El prefijo más significa "más de", menos significa "menos de".
inum( +/- N )
Verdadero si el número de inodo cumple la cualificación.
size( +/- N [c/k])
Verdadero si el tamaño del archivo cumple la cualificación. Por defecto, N está en bloques de media K. Añada una "k" al final del número para indicar bloques de 1K, o "c" para indicar caracteres (bytes).
atime( +/- N )
Verdadero si el tiempo de acceso (en días) cumple la cualificación.
exec(@COMANDO)
Crea un proceso hijo mediante system(). Cualquier aparición de "{}" en cualquier argumento se reemplaza por el nombre de archivo actual. Devuelve verdadero si el estado de salida del hijo es 0. La lista se pasa directamente a "system", por lo que si es un solo argumento, puede contener sintaxis de "/bin/sh". De lo contrario, es un comando pre-analizado que debe encontrarse en el PATH.

Tenga en cuenta que no pude averiguar cómo manipular el directorio actual de forma sencilla, así que estoy usando $_ aquí en lugar del más tradicional "File::Find::name". Todavía funciona, porque todavía estamos en el directorio actual, pero se ve raro en un rastreo. Active "no_chdir" en "find" si desea una ruta completa de find tradicional.

my $f = File::Finder->exec('ls', '-ldg', '{}');
find({ no_chdir => 1, wanted => $f }, @starting_dirs);

Sí, sería trivial para mí añadir un método no_chdir. Pronto.

ok(@COMANDO)
Como "exec", pero no pregunta al usuario si la acción debe realizarse. Esto es para scripting. El método ok en find interactúa, pidiendo al usuario confirmación. 
my $f = File::Finder->ok('rm', '{}');
find($f, @dirs);

File::Finder::Steps(3pm) — Arch Linux

NAME

File::Finder::Steps - Steps for File::Finder

SYNOPSIS

    use File::Finder;
    my $finder = File::Finder->new();
    $finder->type('f')
          ->contains(qr/foo/)
          ->exec('rm {}')
          ->in('/tmp');

DESCRIPTION

This documentation is for the steps that may be applied to a File::Finder object. These methods are intended to be chained, and each method is expected to return the invocant object so that further chaining may be performed.

Basic Steps

type(TYPE)
Returns true if the entry is of the specified TYPE. TYPE may be one of "f" for regular files, "d" for directories, "l" for symbolic links, or "b" for block devices, or "p" for named pipes, or "s" for sockets.
readable
Returns true if the file is readable.
writable
Returns true if the file is writable.
executable
Returns true if the file is executable.
size(SIZE)
Returns true if the file is of the specified SIZE. SIZE may be specified in bytes, or with a suffix of "k", "M", or "G". A leading "+" or "-" indicates greater than or less than, respectively. 
    my $big_files = File::Finder->type('f')->size('+100M');
atime(TIME)
Returns true if the file's access time matches TIME. TIME is specified in days. A leading "+" or "-" indicates greater than or less than, respectively.
mtime(TIME)
Returns true if the file's modification time matches TIME. TIME is specified in days. A leading "+" or "-" indicates greater than or less than, respectively.
ctime(TIME)
Returns true if the file's status change time matches TIME. TIME is specified in days. A leading "+" or "-" indicates greater than or less than, respectively.
name(PATTERN)
Returns true if the filename matches PATTERN. PATTERN may be a string or a regex.
iname(PATTERN)
Like name, but case-insensitive.
path(PATTERN)
Like name, but matches against the full path.
ipath(PATTERN)
Like path, but case-insensitive.
exec(CMD)
Runs the specified command CMD. If the command is successful, returns true. Otherwise, returns false. The placeholder "{}" is replaced by the current filename.
exec_prompt(CMD)
Like exec, but prompts the user first. Displays the command line, and waits for a response. If the response begins with "y" or "Y", runs the command. If the command fails, or the response wasn't yes, returns false, otherwise true.
prune
Sets $File::Find::prune, and returns true.
xdev
Not yet implemented.
newer(FILE)
Not yet implemented.
eval(CODEREF)
Ah yes, the master escape, with extra benefits. Give it a coderef, and it evaluates that code at the proper time. The return value is noted for true/false and used accordingly. 
my $blaster = File::Finder->atime("+30")->eval(sub { unlink });

But wait, there's more. If the parameter is an object that responds to "as_wanted", that method is automatically called, hoping for a coderef return. This neat feature allows subroutines to be created and nested:

my $old = File::Finder->atime("+30");
my $big = File::Finder->size("+100");
my $old_or_big = File::Finder->eval($old)->or->eval($big);
my $killer = File::Finder->eval(sub { unlink });
my $kill_old_or_big = File::Finder->eval($old_or_big)->ls->eval($killer);
$kill_old_or_big->in('/tmp');

Almost too cool for words.

depth
Like find's "-depth". Sets a flag for "as_options", and returns true.
ls
Like find's "-ls". Performs a "ls -dils" on the entry to "STDOUT" (without forking), and returns true.
tar
Not yet implemented.
[n]cpio
Not yet implemented.
ffr($ffr_object)
Incorporate a "File::Find::Rule" object as a step. Note that this must be a rule object, and not a result, so don't call or pass "in". For example, using "File::Find::Rule::ImageSize" to define a predicate for image files that are bigger than a megapixel in my friends folder, I get: 
require File::Finder;
require File::Find::Rule;
require File::Find::Rule::ImageSize;
my $ffr = File::Find::Rule->file->image_x('>1000')->image_y('>1000');
my @big_friends = File::Finder->ffr($ffr)
  ->in("/Users/merlyn/Pictures/Sorted/Friends");
contains(pattern)
True if the file contains "pattern" (either a literal string treated as a regex, or a true regex object). 
my $plugh_files = File::Finder->type('f')->contains(qr/plugh/);

Searching is performed on a line-by-line basis, respecting the current value of $/.

EXTENDING

A step consists of a compile-time and a run-time component.

During the creation of a "File::Finder" object, step methods are called as if they were methods against the slowly-growing "File::Finder" instance, including any additional parameters as in a normal method call. The step is expected to return a coderef (possibly a closure) to be executed at run-time.

When a "File::Finder" object is being evaluated as the "File::Find" "wanted" routine, the collected coderefs are evaluated in sequence, again as method calls against the "File::Finder" object. No additional parameters are passed. However, the normal "wanted" values are available, such as $_, $File::Find::name, and so on. The "_" pseudo-handle has been set properly, so you can safely use "-X" filetests and "stat" against the pseudo-handle. The routine is expected to return a true/false value, which becomes the value of the step.

Although a "File::Finder" object is passed both to the compile-time invocation and the resulting run-time invocation, only the "options" self-hash element is properly duplicated through the cloning process. Do not be tempted to add additional self-hash elements without overriding "File::Finder"'s "_clone". Instead, pass values from the compile-time phase to the run-time phase using closure variables, as shown in the synopsis.

For simplicity, you can also just mix-in your methods to the existing "File::Finder::Steps" class, rather than subclassing both classes as shown above. However, this may result in conflicting implementations of a given step name, so beware.
