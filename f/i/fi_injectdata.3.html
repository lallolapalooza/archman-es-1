NOMBRE

fi_msg - Operaciones de transferencia de datos de mensajes

fi_recv / fi_recvv / fi_recvmsg
Publica un búfer para recibir un mensaje entrante

fi_send / fi_sendv / fi_sendmsg fi_inject / fi_senddata : Iniciar una operación para enviar un mensaje

SINOPSIS

#include <rdma/fi_endpoint.h>
ssize_t fi_recv(struct fid_ep *ep, void * buf, size_t len,
    void *desc, fi_addr_t src_addr, void *context);
ssize_t fi_recvv(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t src_addr, void *context);
ssize_t fi_recvmsg(struct fid_ep *ep, const struct fi_msg *msg,
    uint64_t flags);
ssize_t fi_send(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, fi_addr_t dest_addr, void *context);
ssize_t fi_sendv(struct fid_ep *ep, const struct iovec *iov,
    void **desc, size_t count, fi_addr_t dest_addr, void *context);
ssize_t fi_sendmsg(struct fid_ep *ep, const struct fi_msg *msg,
    uint64_t flags);
ssize_t fi_inject(struct fid_ep *ep, const void *buf, size_t len,
    fi_addr_t dest_addr);
ssize_t fi_senddata(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, uint64_t data, fi_addr_t dest_addr, void *context);
ssize_t fi_injectdata(struct fid_ep *ep, const void *buf, size_t len,
    uint64_t data, fi_addr_t dest_addr);

ARGUMENTOS

ep
Punto de conexión de la fabric en el que iniciar el envío o publicar el búfer de recepción.
buf
Búfer de datos a enviar o recibir.
len
Longitud del búfer de datos a enviar o recibir, especificada en bytes. Las transferencias válidas van desde 0 bytes hasta el max_msg_size del punto de conexión.
iov
Búfer de datos vectorial.
count
Número de entradas de datos vectoriales.
desc
Descriptor asociado con el búfer de datos. Consulte fi_mr(3).
data
Datos de CQ remotos a transferir con el mensaje enviado.
dest_addr
Dirección de destino para transferencias sin conexión. Se ignora para los puntos de conexión conectados.
src_addr
Se aplica solo a los puntos de conexión sin conexión configurados con FI_DIRECTED_RECV. Para todas las demás configuraciones de puntos de conexión, src_addr se ignora. src_addr define la dirección de origen desde la que recibir. De forma predeterminada, src_addr se trata como una dirección de punto de conexión de origen (es decir, fi_addr_t devuelto por fi_av_insert / fi_av_insertsvc / fi_av_remove). Si se especifica el indicador FI_AUTH_KEY con fi_recvmsg, src_addr se trata como una clave de autorización de origen (es decir, fi_addr_t devuelto por fi_av_insert_auth_key). Si se establece en FI_ADDR_UNSPEC, cualquier dirección de origen puede coincidir.
msg
Descriptor de mensaje para operaciones de envío y recepción.
flags
Indicadores adicionales a aplicar para la operación de envío o recepción.
context
Puntero especificado por el usuario para asociar con la operación. Este parámetro se ignora si la operación no generará una finalización exitosa, a menos que un indicador de operación especifique que el parámetro de contexto debe usarse como entrada requerida.

DESCRIPCIÓN

Las funciones de envío – fi_send, fi_sendv, fi_sendmsg, fi_inject y fi_senddata – se utilizan para transmitir un mensaje de un punto de conexión a otro. La principal diferencia entre las funciones de envío es el número y tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general. Los mensajes enviados mediante las operaciones de fi_msg son recibidos por un punto de conexión remoto en un búfer publicado para recibir tales mensajes.

Las funciones de recepción – fi_recv, fi_recvv, fi_recvmsg – publican un búfer de datos en un punto de conexión para recibir mensajes entrantes. Al igual que las operaciones de envío, las operaciones de recepción se ejecutan de forma asíncrona. Los usuarios no deben tocar el/los búfer(es) de datos publicados hasta que la operación de recepción se haya completado.

Un punto de conexión debe estar habilitado antes de que una aplicación pueda publicar operaciones de envío o recepción en él. Para los puntos de conexión conectados, los búferes de recepción pueden publicarse antes de que se llame a connect o accept en el punto de conexión. Esto asegura que los búferes estén disponibles para recibir datos entrantes inmediatamente después de que se haya establecido la conexión.

Las operaciones de mensaje completadas se notifican al usuario a través de uno o más colectores de eventos asociados con el punto de conexión. Los usuarios proporcionan el contexto que se asocia con cada operación y se devuelve al usuario como parte del evento de finalización. Consulte fi_cq para los detalles del evento de finalización.

fi_send

La llamada fi_send transfiere los datos contenidos en el búfer de datos especificado por el usuario a un punto de conexión remoto, manteniendo los límites del mensaje.

fi_sendv

La llamada fi_sendv añade soporte para una lista de dispersión-agrupación a fi_send. El fi_sendv transfiere el conjunto de búferes de datos referenciados por el parámetro iov a un punto de conexión remoto como un solo mensaje.

fi_sendmsg

La llamada fi_sendmsg admite transferencias de datos tanto sobre puntos de conexión conectados como sin conexión, con la capacidad de controlar la operación de envío por llamada mediante el uso de indicadores. La función fi_sendmsg toma una struct fi_msg como entrada.

struct fi_msg {
    const struct iovec *msg_iov; /* scatter-gather array */
    void               **desc;   /* local request descriptors */
    size_t             iov_count;/* # elements in iov */
    fi_addr_t          addr;     /* optional endpoint address */
    void               *context; /* user-defined context */
    uint64_t           data;     /* optional message data */
};

fi_inject

La llamada de envío inject es una versión optimizada de fi_send con las siguientes características. El búfer de datos está disponible para su reutilización inmediatamente al regresar de la llamada, y no se escribirá ninguna entrada de CQ si la transferencia se completa con éxito.

Conceptualmente, esto significa que la función fi_inject se comporta como si el indicador de transferencia FI_INJECT estuviera establecido, las finalizaciones selectivas estuvieran habilitadas y el indicador FI_COMPLETION no estuviera especificado. Tenga en cuenta que la entrada de CQ se suprimirá incluso si el comportamiento predeterminado del punto de conexión es escribir entradas de CQ para todas las finalizaciones exitosas. Consulte la discusión de indicadores a continuación para más detalles. El tamaño de mensaje solicitado que se puede usar con fi_inject está limitado por inject_size.

Si FI_HMEM está habilitado, la llamada fi_inject solo puede aceptar un búfer con iface igual a FI_HMEM_SYSTEM si el proveedor requiere el mr_mode FI_MR_HMEM. Esta limitación se aplica a todas las llamadas fi_*inject* y no afecta cómo se informa inject_size.

fi_senddata

La llamada de envío de datos es similar a fi_send, pero permite el envío de datos de CQ remotos (consulte el indicador FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_injectdata

La llamada de inyección de datos es similar a fi_inject, pero permite el envío de datos de CQ remotos (consulte el indicador FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_recv

La llamada fi_recv publica un búfer de datos en la cola de recepción del punto de conexión correspondiente. Las recepciones publicadas se buscan en el orden en que fueron publicadas para intentar hacer coincidir los envíos. Se mantienen los límites del mensaje. El orden en que se completan las recepciones depende del tipo de punto de conexión y del protocolo. Para los puntos de conexión sin conexión, el parámetro src_addr puede usarse para indicar que un búfer debe publicarse para recibir datos entrantes de un punto de conexión remoto específico.

fi_recvv

La llamada fi_recvv añade soporte para una lista de dispersión-agrupación a fi_recv. El fi_recvv publica el conjunto de búfere

Los flags especificados con fi_recvmsg / fi_sendmsg anulan la mayoría de los flags configurados previamente con el punto de conexión, excepto donde se indique (véase fi_endpoint.3). El búfer será liberado por el proveedor cuando el espacio de búfer disponible caiga por debajo del mínimo especificado (véase FI_OPT_MIN_MULTI_RECV). NOTA

S

Si un punto de conexión ha sido configurado con FI_MSG_PREFIX, la aplicación debe incluir espacio de búfer de tamaño msg_prefix_size, como lo especifican los atributos

del punto de conexión. El búfer de prefijo debe ocurrir al inicio de los datos referenciados por el parámetro buf, o ser referenciado por el primer vector de E/S. El esp
acio de prefijo del mensaje no puede dividirse entre múltiples vectores de E/S. El tamaño del búfer de prefijo debe incluirse como parte de la longitud total del búfer.

ERRORE

S
-FI_EAGA
IN
Indica que el proveedor subyacente carece actualmente de los recursos necesarios para iniciar la o
peración solicitada. Los motivos por los que un proveedor devuelve FI_EAGAIN son variados. Sin em
bargo, los motivos comunes incluyen un búfer interno insuficiente o colas de procesamiento llenas.

Un búfer interno insuficiente a menudo se asocia con operaciones que usan FI_INJECT. En tales casos, puede haber búfer adicional disponible a medida que las operaciones publicadas se

completen.

Las colas de procesamiento llenas pueden ser un estado temporal relacionado con el procesamiento local (por ejemplo, se está transfiriendo un mensaje grande), o pueden ser el resultado del control de flujo. En este último caso, las colas pueden permanecer bloqueadas hasta que se hagan disponibles recursos adicionales en el lado remoto de la

transferencia.

En todos los casos, la operación puede reintentarse después de que se hagan disponibles recursos adicionales. Al usar FI_PROGRESS_MANUAL, la aplicación debe verific

ar las finalizaciones de transmisión y recepción después de recibir FI_EAGAIN como valor de retorno, independientemente de la operación que falló. Esto también se re
comienda encarecidamente al usar FI_PROGRESS_AUTO, ya que pueden ser necesarios procesar acuses de recibo o mensajes de control de flujo para reanudar la ejecución.
