File::Spec::Mac(3perl) Guía de referencia para programadores de Perl File::Spec::Mac(3perl)

NOMBRE

File::Spec::Mac - File::Spec para Mac OS (Clásico)

SINOPSIS

require File::Spec::Mac; # Hecho internamente por File::Spec si es necesario

DESCRIPCIÓN

Métodos para manipular especificaciones de archivos.

MÉTODOS

canonpath
En Mac OS, no hay nada que hacer. Devuelve lo que se le da.
catdir()
Concatena dos o más nombres de directorio para formar una ruta separada por dos puntos (":") que termina con un directorio. Las rutas resultantes son relativas por defecto, pero se pueden forzar a ser absolutas (pero evite esto, ver abajo). Pone automáticamente un ":" al final de la ruta completa, porque eso es lo que se hace en el entorno de MacPerl y ayuda a distinguir una ruta de archivo de una ruta de directorio.

NOTA IMPORTANTE: A partir de la versión 1.3 de este módulo, la ruta resultante es relativa por defecto y no absoluta. Esta decisión se tomó por razones de portabilidad. Dado que "File::Spec->catdir()" devuelve rutas relativas en todos los demás sistemas operativos, ahora también seguirá esta convención en Mac OS. Tenga en cuenta que esto podría romper algunos scripts existentes.

El propósito previsto de esta rutina es concatenar nombres de directorio. Pero debido a la naturaleza de las rutas de Macintosh, se permiten algunas posibilidades adicionales para que el uso de esta rutina dé resultados razonables para algunas situaciones comunes. En otras palabras, también se le permite concatenar rutas en lugar de nombres de directorio (hablando estrictamente, una cadena como ":a" es una ruta, pero no un nombre, ya que contiene un carácter de puntuación ":").

Así que, además de llamadas como

catdir("a") = ":a:"
catdir("a","b") = ":a:b:"
catdir() = ""                    (caso especial)

se permiten llamadas como las siguientes

catdir(":a:") = ":a:"
catdir(":a","b") = ":a:b:"
catdir(":a:","b") = ":a:b:"
catdir(":a:",":b:") = ":a:b:"
catdir(":") = ":"

.

Aquí están las reglas que se utilizan en catdir(); tenga en cuenta que intentamos ser lo más compatibles posible con Unix:

1.
La ruta resultante es relativa por defecto, es decir, la ruta resultante tendrá un ":" inicial.
2.
Se añade automáticamente un ":" final a la ruta resultante, para denotar un directorio.
3.
Generalmente, a cada argumento se le quita un ":" inicial y un ":" final (si los hay). Luego se unen con un ":". Se aplica un tratamiento especial a los argumentos que denotan rutas de subida (updir) como "::lib:", ver (4), o argumentos que consisten únicamente de dos puntos ("rutas de dos puntos"), ver (5).
4.
Cuando se pasa como argumento una ruta de subida como ":::lib::", el número de directorios a subir se maneja correctamente, sin quitar los dos puntos iniciales o finales cuando sea necesario. Por ejemplo, 
catdir(":::a","::b","c")    = ":::a::b:c:"
catdir(":::a::","::b","c")  = ":::a:::b:c:"
5.
Añadir un ":" o una cadena vacía "" a una ruta en cualquier posición no altera la ruta, es decir, estos argumentos se ignoran. (Cuando se pasa un "" como primer argumento, tiene un significado especial, ver (6)). De esta manera, un ":" se maneja como un "." (curdir) en Unix, mientras que una cadena vacía "" se ignora generalmente (ver "canonpath()" en File::Spec::Unix ). Del mismo modo, un "::" se maneja como un ".." (updir), y un ":::" se maneja como un "../.." etc. Por ejemplo, 
catdir("a",":",":","b")   = ":a:b:"
catdir("a",":","::",":b") = ":a::b:"
6.
Si el primer argumento es una cadena vacía "" o es un nombre de volumen, es decir, coincide con el patrón /^[^:]+:/, la ruta resultante es absoluta.
7.
Pasar una cadena vacía "" como primer argumento a catdir() es como pasar"File::Spec->rootdir()" como el primer argumento, es decir, 
catdir("","a","b")          es lo mismo que
catdir(rootdir(),"a","b").

Esto es cierto en Unix, donde "catdir("","a","b")" produce "/a/b" y rootdir() es "/". Tenga en cuenta que rootdir() en Mac OS es el volumen de arranque, que es lo más cercano en concepto al "/" de Unix. Esto debería ayudar a ejecutar scripts existentes escritos originalmente para Unix.

8.
Para rutas absolutas, se hace una limpieza, para asegurar que el nombre del volumen no sea seguido inmediatamente por subidas (updirs). Esto es inválido, porque esto iría más allá de la "raíz". Generalmente, estos casos se manejan como sus equivalentes en Unix: 
Unix:
   Unix->catdir("","")                 =  "/"
   Unix->catdir("",".")                =  "/"
   Unix->catdir("","..")               =  "/"        # no se puede ir
                                                     # más allá de la raíz
   Unix->catdir("",".","..","..","a")  =  "/a"
Mac:
   Mac->catdir("","")                  =  rootdir()  # (p. ej. "HD:")
   Mac->catdir("",":")                 =  rootdir()
   Mac->catdir("","::")                =  rootdir()  # no se puede ir
                                                     # más allá de la raíz
   Mac->catdir("",":","::","::","a")   =  rootdir() . "a:"
                                                   # (p. ej. "HD:a:")

Sin embargo, este enfoque se limita a los primeros argumentos que siguen a "raíz" (de nuevo, ver "canonpath()" en File::Spec::Unix. Si hay más argumentos que suben en el árbol de directorios, se puede crear una ruta inválida que vaya más allá de la raíz.

Como ha visto, puede forzar a catdir() a crear una ruta absoluta pasando una cadena vacía o una ruta que comienza con un nombre de volumen como primer argumento. Sin embargo, se le anima firmemente a no hacerlo, ya que esto se hace solo por compatibilidad con versiones anteriores. Las versiones más nuevas de File::Spec vienen con un método llamado catpath() (ver abajo), que está diseñado para ofrecer una solución portátil para la creación de rutas absolutas. Toma las partes de volumen, directorio y archivo y devuelve una ruta completa. Mientras que catdir() sigue siendo adecuado para la concatenación de nombres de directorio, se le anima a usar catpath() para concatenar nombres de volumen y rutas de directorio. Por ejemplo,

$dir      = File::Spec->catdir("tmp","sources");
$abs_path = File::Spec->catpath("MacintoshHD:", $dir,"");

produce

"MacintoshHD:tmp:sources:" .
catfile
Concatena uno o más nombres de directorio y un nombre de archivo para formar una ruta completa que termina con un nombre de archivo. Las rutas resultantes son relativas por defecto, pero se pueden forzar a ser absolutas (pero evite esto).

NOTA IMPORTANTE: A partir de la versión 1.3 de este módulo, la ruta resultante es relativa por defecto y no absoluta. Esta decisión se tomó por razones de portabilidad. Dado que "File::Spec->catfile()" devuelve rutas relativas en todos los demás sistemas operativos, ahora también seguirá esta convención en Mac OS. Tenga en cuenta que esto podría romper algunos scripts existentes.

El último argumento siempre se considera la parte del archivo. Dado que catfile() usa catdir() (ver arriba) para la concatenación de las partes del directorio (si las hay),

NAME

File::Spec::Mac - Mac OS filename conventions

SYNOPSIS

    use File::Spec;
    use File::Spec::Mac;

    # Example: Concatenating path components
    my ($vol, $dir, $file) = ('MyHD:', 'folder:subfolder:', 'file.txt');
    my $path = File::Spec->catpath($vol, $dir, $file); # 'MyHD:folder:subfolder:file.txt'

    # Example: Splitting a path
    my ($vol, $dir, $file) = File::Spec->splitpath('MyHD:folder:subfolder:file.txt');
    # $vol eq 'MyHD:'
    # $dir eq 'folder:subfolder:'
    # $file eq 'file.txt'

    # Example: Getting current directory
    my $curdir = File::Spec->curdir(); # ':'

    # Example: Checking if path is absolute
    my $is_abs = File::Spec->file_name_is_absolute('MyHD:file'); # true
    my $is_rel = File::Spec->file_name_is_absolute(':file');    # false

    # Example: Converting relative to absolute path
    my $abs_path = File::Spec->rel2abs(':file', 'MyHD:folder:'); # 'MyHD:folder:file'

DESCRIPTION

This module implements the conventions for Mac OS filenames and pathnames. It is used by the main File::Spec module. You generally don't need to use this module directly.

The following are the specific Mac OS implementations of the generic File::Spec methods:

catdir
File::Spec->catdir( $dir1, $dir2, ... )

Concatenates the arguments to form a new directory path. The arguments are joined by colons. A leading colon is added to the result if the first argument is empty. Otherwise, the first argument is used as is.

Example:

File::Spec->catdir( 'a', 'b', 'c' )   = 'a:b:c'
File::Spec->catdir( 'a:', 'b', 'c' )  = 'a:b:c'
File::Spec->catdir( '', 'a', 'b' )    = ':a:b'
File::Spec->catdir( 'a', ':b' )       = 'a:b'

This function is called by File::Spec->catpath() when it needs to join the directory components.

Note that catdir is only called when there are two or more arguments.

catfile
$file = File::Spec->catfile( $dir1, $dir2, ..., $file )

Concatenates all arguments, using ':' as the separator. The last argument is the filename, and all preceding arguments are directories.

The following with regard to relative and absolute paths is true:

catfile("")     = ""
catfile("file") = "file"

but

catfile("","")        = rootdir()         # (e.g. "HD:")
catfile("","file")    = rootdir() . file  # (e.g. "HD:file")
catfile("HD:","file") = "HD:file"

This means that catdir() is called only when there are two or more arguments, as one might expect.

Note that the leading ":" is removed from the filename, so that

catfile("a","b","file")  = ":a:b:file"    and
catfile("a","b",":file") = ":a:b:file"

give the same answer.

To concatenate volume names, directory paths and filenames, you are encouraged to use catpath() (see below).

curdir
Returns a string representing the current directory. On Mac OS, this is ":".
devnull
Returns a string representing the null device. On Mac OS, this is "Dev:Null".
rootdir
Returns the empty string. Mac OS has no real root directory.
tmpdir
Returns the contents of $ENV{TMPDIR}, if that directory exits or the current working directory otherwise. Under MacPerl, $ENV{TMPDIR} will contain a path like "MacintoshHD:Temporary Items:", which is a hidden directory on your startup volume.
updir
Returns a string representing the parent directory. On Mac OS, this is "::".
file_name_is_absolute
Takes as argument a path and returns true, if it is an absolute path. If the path has a leading ":", it's a relative path. Otherwise, it's an absolute path, unless the path doesn't contain any colons, i.e. it's a name like "a". In this particular case, the path is considered to be relative (i.e. it is considered to be a filename). Use ":" in the appropriate place in the path if you want to distinguish unambiguously. As a special case, the filename '' is always considered to be absolute. Note that with version 1.2 of File::Spec::Mac, this does no longer consult the local filesystem.

E.g.

File::Spec->file_name_is_absolute("a");         # false (relative)
File::Spec->file_name_is_absolute(":a:b:");     # false (relative)
File::Spec->file_name_is_absolute("MacintoshHD:");
                                                # true (absolute)
File::Spec->file_name_is_absolute("");          # true (absolute)
path
Returns the null list for the MacPerl application, since the concept is usually meaningless under Mac OS. But if you're using the MacPerl tool under MPW, it gives back $ENV{Commands} suitably split, as is done in :lib:ExtUtils:MM_Mac.pm.
splitpath
($volume,$directories,$file) = File::Spec->splitpath( $path );
($volume,$directories,$file) = File::Spec->splitpath( $path,
                                                      $no_file );

Splits a path into volume, directory, and filename portions.

On Mac OS, assumes that the last part of the path is a filename unless $no_file is true or a trailing separator ":" is present.

The volume portion is always returned with a trailing ":". The directory portion is always returned with a leading (to denote a relative path) and a trailing ":" (to denote a directory). The file portion is always returned without a leading ":". Empty portions are returned as empty string ''.

The results can be passed to catpath() to get back a path equivalent to (usually identical to) the original path.

splitdir
The opposite of catdir(). 
@dirs = File::Spec->splitdir( $directories );

$directories should be only the directory portion of the path on systems that have the concept of a volume or that have path syntax that differentiates files from directories. Consider using splitpath() otherwise.

Unlike just splitting the directories on the separator, empty directory names ("") can be returned. Since catdir() on Mac OS always appends a trailing colon to distinguish a directory path from a file path, a single trailing colon will be ignored, i.e. there's no empty directory name after it.

Hence, on Mac OS, both

File::Spec->splitdir( ":a:b::c:" );    and
File::Spec->splitdir( ":a:b::c" );

yield:

( "a", "b", "::", "c" )

while

File::Spec->splitdir( ":a:b::c::" );

yields:

( "a", "b", "::", "c", "::" )
catpath
$path = File::Spec->catpath($volume,$directory,$file);

Takes volume, directory and file portions and returns an entire path. On Mac OS, $volume, $directory and $file are concatenated. A ':' is inserted if need be. You may pass an empty string for each portion. If all portions are empty, the empty string is returned. If $volume is empty, the result will be a relative path, beginning with a ':'. If $volume and $directory are empty, a leading ":" (if any) is removed form $file and the remainder is returned. If $file is empty, the resulting path will have a trailing ':'.

abs2rel
Takes a destination path and an optional base path and returns a relative path from the base path to the destination path: 
$rel_path = File::Spec->abs2rel( $path ) ;
$rel_path = File::Spec->abs2rel( $path, $base ) ;

Note that both paths are assumed to have a notation that distinguishes a directory path (with trailing ':') from a file path (without trailing ':').

If $base is not present or '', then the current working directory is used. If $base is relative, then it is converted to absolute form using rel2abs(). This means that it is taken to be relative to the current working directory.

If $path and $base appear to be on two different volumes, we will not attempt to resolve the two paths, and we will instead simply return $path. Note that previous versions of this module ignored the volume of $base, which resulted in garbage results part of the time.

If $base doesn't have a trailing colon, the last element of $base is assumed to be a filename. This filename is ignored. Otherwise all path components are assumed to be directories.

If $path is relative, it is converted to absolute form using rel2abs(). This means that it is taken to be relative to the current working directory.

Based on code written by Shigio Yamaguchi.

rel2abs
Converts a relative path to an absolute path: 
$abs_path = File::Spec->rel2abs( $path ) ;
$abs_path = File::Spec->rel2abs( $path, $base ) ;

Note that both paths are assumed to have a notation that distinguishes a directory path (with trailing ':') from a file path (without trailing ':').

If $base is not present or '', then $base is set to the current working directory. If $base is relative, then it is converted to absolute form using rel2abs(). This means that it is taken to be relative to the current working directory.

If $base doesn't have a trailing colon, the last element of $base is assumed to be a filename. This filename is ignored. Otherwise all path components are assumed to be directories.

If $path is already absolute, it is returned and $base is ignored.

Based on code written by Shigio Yamaguchi.
