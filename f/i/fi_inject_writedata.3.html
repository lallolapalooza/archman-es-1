DESCRIPCIÓ

N

Las operaciones RMA (acceso a memoria remota) se utilizan para transferir datos directamente entre un búfer de datos local y un búfer de datos remoto. Las transferencias RMA ocurren a nivel de granularidad de byte, y no se mantienen límites de

mensajes.

Las funciones de escritura – fi_write, fi_writev, fi_writemsg, fi_inject_write y fi_writedata – se utilizan para transmitir datos a un búfer de memoria remota. La principal diferencia entre las funciones de escritura es el número y tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función

general.

Las funciones de lectura – fi_read, fi_readv y fi_readmsg – se utilizan para transferir datos desde una región de memoria remota a búfer(es) de datos local(es). De manera similar a las operaciones de escritura, las operaciones de lectura operan de forma asíncrona. Los usuarios no deben tocar el(los) búfer(es) de datos publicado(s) hasta que la operación de lectura se haya

completado.

Las operaciones RMA completadas se notifican al usuario a través de una o más colas de completado (CQ) asociadas con el punto de extremo. Los usuarios proporcionan un contexto que se asocia con cada operación, y se devuelve al usuario como parte de la finalización. Véase fi_cq para detalles de los eventos de

finalización.

Por defecto, el punto de extremo remoto no genera un evento ni notifica al usuario cuando una región de memoria ha sido accedida por una operación de lectura o escritura RMA. Sin embargo, los datos inmediatos pueden asociarse con una operación de escritura RMA. Las escrituras RMA con datos inmediatos generarán una entrada de finalización en el punto de extremo remoto, de modo que los datos inmediatos puedan ser

entregados.

FLAGS

Las llamadas fi_readmsg y fi_writemsg permiten al usuario especificar banderas que pueden cambiar la operación de transferencia de datos predeterminada. Las banderas especificadas con fi_readmsg / fi_writemsg anulan la mayoría de las banderas configuradas previamente con el endpoint, excepto donde se indique (ver fi_endpoint.3). La siguiente lista de banderas son utilizables con fi_readmsg y/o fi_writemsg.

FI_REMOTE_CQ_DATA
Se aplica a fi_writemsg. Indica que los datos de la CQ remota están disponibles y deben enviarse como parte de la solicitud. Ver fi_getinfo para más detalles sobre FI_REMOTE_CQ_DATA. Esta bandera se establece implícitamente para fi_writedata y fi_inject_writedata.
FI_COMPLETION
Indica que se debe generar una entrada de finalización para la operación especificada. El endpoint debe estar enlazado a una cola de finalización con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o esta bandera se ignorará.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que se publicarán inmediatamente después de que la llamada actual regrese. El uso de esta bandera puede mejorar el rendimiento al permitir que el proveedor optimice su acceso al hardware de la red.
FI_INJECT
Se aplica a fi_writemsg. Indica que el búfer de datos de salida debe devolverse al usuario inmediatamente después de que la llamada de escritura regrese, incluso si la operación se maneja de forma asíncrona. Esto puede requerir que la implementación del proveedor subyacente copie los datos en un búfer local y transfiera desde ese búfer. Esta bandera solo se puede usar con mensajes más pequeños que inject_size.
FI_INJECT_COMPLETE
Se aplica a fi_writemsg. Indica que se debe generar una finalización cuando los búferes de origen puedan reutilizarse.
FI_TRANSMIT_COMPLETE
Se aplica a fi_writemsg. Indica que no se debe generar una finalización hasta que la operación se haya transmitido con éxito y ya no esté siendo rastreada por el proveedor.
FI_DELIVERY_COMPLETE
Se aplica a fi_writemsg. Indica que se debe generar una finalización cuando la operación haya sido procesada por el destino.
FI_COMMIT_COMPLETE
Se aplica a fi_writemsg al dirigirse a regiones de memoria persistente. Indica que se debe generar una finalización solo después de que el resultado de la operación se haya hecho duradero.
FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como operación vallada, y cualquier operación publicada después de la operación vallada se pospondrán hasta que todas las operaciones anteriores dirigidas al mismo endpoint par hayan completado. Las operaciones publicadas después del vallado verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación vallada.

El orden de las operaciones que comienzan con la publicación de la operación vallada (inclusive) hasta la publicación de una operación vallada posterior (exclusiva) se controla mediante las semánticas de ordenación del endpoint.

VALOR DE RETORNO

Devuelve 0 si la operación es exitosa. En caso de error, se devuelve un valor negativo correspondiente al errno de la red. Los valores de errno de la red se definen en rdma/fi_errno.h.

ERRORES

Ver fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
