NOMBRE

fi_cntr - Operaciones de contador de eventos y finalización

fi_cntr_open / fi_close
Asignar/liberar un contador
fi_cntr_read
Leer el valor actual de un contador
fi_cntr_readerr
Lee el número de operaciones que han finalizado con error.
fi_cntr_add
Incrementar un contador en un valor especificado
fi_cntr_set
Establecer un contador a un valor especificado
fi_cntr_wait
Esperar a que un contador sea mayor o igual a un valor umbral

SINOPSIS

#include <rdma/fi_domain.h>
int fi_cntr_open(struct fid_domain *domain, struct fi_cntr_attr *attr,
    struct fid_cntr **cntr, void *context);
int fi_close(struct fid *cntr);
uint64_t fi_cntr_read(struct fid_cntr *cntr);
uint64_t fi_cntr_readerr(struct fid_cntr *cntr);
int fi_cntr_add(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_adderr(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_set(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_seterr(struct fid_cntr *cntr, uint64_t value);
int fi_cntr_wait(struct fid_cntr *cntr, uint64_t threshold,
    int timeout);

ARGUMENTOS

Dominio de la red

Atributos del contador

DESCRIPCIÓN

Los contadores registran el número de operaciones solicitadas que se han completado. Los contadores pueden proporcionar un mecanismo de finalización ligero al permitir la supresión de entradas de finalización de CQ. Son útiles para aplicaciones que solo necesitan saber el número de solicitudes que se han completado, y no los detalles de cada solicitud. Por ejemplo, los contadores pueden ser útiles para implementar control de flujo basado en créditos o para rastrear el número de procesos remotos que han respondido a una solicitud.

Los contadores típicamente solo cuentan las finalizaciones exitosas. Sin embargo, si una operación finaliza con error, puede incrementar un valor de error asociado. Es decir, un contador almacena en realidad dos valores distintos, con las finalizaciones de error actualizando un valor específico de error.

Los contadores se actualizan siguiendo las semánticas de eventos de finalización definidas en fi_cq(3). El momento de la actualización se basa en el tipo de transferencia y cualquier bandera de operación especificada.

fi_cntr_open

fi_cntr_open asigna un nuevo contador de red. Las propiedades y el comportamiento del contador se definen por la estructura fi_cntr_attr.

struct fi_cntr_attr {
    enum fi_cntr_events  events;    /* tipo de eventos a contar */
    enum fi_wait_obj     wait_obj;  /* objeto de espera solicitado */
    struct fid_wait     *wait_set;  /* conjunto de espera opcional, obsoleto */
    uint64_t             flags;     /* banderas de operación */
};
events
Un contador captura diferentes tipos de eventos. El tipo específico que se contará es uno de los siguientes:
- FI_CNTR_EVENTS_COMP
El contador se incrementa por cada finalización exitosa que ocurre en un endpoint asociado enlazado. El tipo de finalizaciones (envíos y/o recepciones) que se cuentan puede restringirse mediante banderas de control al enlazar el contador y el endpoint. Los contadores se incrementan en todas las finalizaciones exitosas, independientemente de si la operación genera una entrada en una cola de eventos.
- FI_CNTR_EVENTS_BYTES
El contador se incrementa por el número de bytes del usuario, excluyendo cualquier dato de CQ, transferido en un mensaje de transporte al alcanzar la semántica de finalización especificada. Para contadores del lado del iniciador, la cuenta refleja el tamaño de la transferencia solicitada y se actualiza después de que el mensaje alcanza el nivel de finalización deseado (FI_INJECT_COMPLETE, FI_TRANSMIT_COMPLETE, etc.). Para operaciones de envío y escritura, la cuenta refleja el número de bytes transferidos al par. Para operaciones de lectura, la cuenta refleja el número de bytes devueltos en una respuesta de lectura. Las operaciones que pueden escribir y leer datos, como las atómicas, se comportan como operaciones de lectura en el iniciador, pero como escrituras en el destino. Para contadores del lado del destino, la cuenta refleja el tamaño de los datos del usuario recibidos y se incrementa sujeto a las semánticas de finalización del lado del destino. En la mayoría de los casos, esto indica FI_DELIVERY_COMPLETE, pero puede diferir al acceder a memoria del dispositivo (HMEM). En caso de error, el tamaño de la transferencia no se aplica al campo de error; este campo se incrementa en 1. El tipo de transferencia FI_COLLECTIVE no está soportado.
wait_obj
Los contadores pueden asociarse con un objeto de espera específico. Los objetos de espera permiten a las aplicaciones bloquearse hasta que el objeto de espera se señale, indicando que un contador ha alcanzado un umbral específico. Los usuarios pueden usar fi_control para recuperar el objeto de espera subyacente asociado con un contador, para usarlo en otras llamadas al sistema. Los siguientes valores pueden usarse para especificar el tipo de objeto de espera asociado con un contador: FI_WAIT_NONE, FI_WAIT_UNSPEC, FI_WAIT_SET, FI_WAIT_FD, FI_WAIT_MUTEX_COND (obsoleto) y FI_WAIT_YIELD. El valor predeterminado es FI_WAIT_NONE.
- FI_WAIT_NONE
Se utiliza para indicar que el usuario no se bloqueará (esperará) a eventos en el contador.
- FI_WAIT_UNSPEC
Especifica que el usuario solo esperará en el contador usando llamadas a la interfaz de red, como fi_cntr_wait. En este caso, el proveedor subyacente puede seleccionar el objeto de espera más apropiado o de mayor rendimiento disponible, incluidos mecanismos de espera personalizados. Las aplicaciones que seleccionan FI_WAIT_UNSPEC no tienen garantizado recuperar el objeto de espera subyacente.
- FI_WAIT_SET (obsoleto)
Indica que el contador de eventos debe usar un objeto de conjunto de espera para esperar eventos. Si se especifica, el campo wait_set debe hacer referencia a un objeto de conjunto de espera existente.
- FI_WAIT_FD
Indica que el contador debe usar un descriptor de archivo como mecanismo de espera. Un objeto de espera de descriptor de archivo debe ser utilizable en las rutinas select, poll y epoll. Sin embargo, un proveedor puede señalar un objeto de espera FD marcándolo como legible, escribible o con un error.
- FI_WAIT_MUTEX_COND (obsoleto)
Especifica que el contador debe usar un mutex y una variable de condición pthread como objeto de espera.
- FI_WAIT_YIELD
Indica que el contador esperará sin un objeto de espera, sino que cederá en cada espera. Permite el uso de fi_cntr_wait a través de un spin.
wait_set (obsoleto)
Si wait_obj es FI_WAIT_SET, este campo hace referencia a un objeto de espera al cual el contador de eventos debe adjuntarse. Cuando se agrega un evento al contador de eventos, el conjunto de espera correspondiente se señalará si se cumplen todas las condiciones necesarias. El uso de un wait_set permite un método optimizado para esperar eventos en múltiples contadores de eventos. Este campo se ignora si wait_obj no es FI_WAIT_SET.
flags
Las banderas están reservadas para uso futuro y deben establecerse en 0.

fi_close

La llamada fi_close libera todos los recursos asociados con un contador. Al cerrar el contador, no debe haber puntos

de extremo (endpoints), contextos de transmisión, contextos de recepción ni regiones de memoria abiertos asociados
con el contador. Si aún hay recursos asociados con el contador al intentar cerrarlo, la llamada devolverá -FI_EBUSY.

NOTA

S

Para soportar una variedad de implementaciones de contadores, las actualizaciones realizadas en los valores de los contadores (por ejemplo, fi_cntr_set o fi_cntr_add) pueden no ser inmediatamente visibles para las operaciones de lectura del contador (es decir, fi_cntr_read o fi_cntr_readerr). Puede ocurrir un pequeño retraso, aunque no definido, entre el cambio del contador y la actualización del valor reportado. Sin embargo, un valor final actualizado eventualmente se reflejará en el valor leído del

contador.

Además, las aplicaciones deben asegurarse de que el valor de un contador es estable y no está sujeto a cambios antes de llamar a fi_cntr_set o fi_cntr_seterr. De lo contrario, el

valor resultante del contador después de fi_cntr_set / fi_cntr_seterr es indefinido, ya que las actualizaciones al contador pueden perderse. Un valor de contador se considera est
able si todas las actualizaciones previas usando fi_cntr_set / fi_cntr_seterr y los resultados de las operaciones relacionadas se reflejan en el valor observado del contador.
