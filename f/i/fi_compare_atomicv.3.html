DESCRIPCIÓN Las transferencias atómicas se utilizan para leer
y actualizar datos ubicados en regiones de memoria remotas

de

manera

atómica. Conceptualmente, son similares a las operaciones atómicas locales de naturaleza similar (por ejemplo, incremento atómico, intercambio con comparación, etc.). Las actualizaciones de datos remotos implican una de varias operaciones sobre los datos, y actúan sobre tipos específicos de datos, como se lista a continuación. Como tal, las transferencias atómicas tienen conocimiento del formato de los datos a los que se accede. Una única función atómica puede operar a través de un arreglo de datos aplicando una operación atómica a cada entrada, pero la atomicidad de una operación está limitada a un solo tipo de dato o entrada. Operaciones Atómicas

Se definen las siguientes operaciones atómicas. Una operación atómica a menudo actúa contra un valor objetivo en el búfer de memoria remoto y un valor fuente proporcionado con la función atómica. También puede transportar datos fuente para reemplazar el valor objetivo en operaciones de intercambio condicional (compare and swap). Se proporciona una descripción conceptual de cada operación.

FI_MIN
Mínimo
if (buf[i] < addr[i])
    addr[i] = buf[i]

Suma

FI_PROD
Producto

OR lógico

FI_LAND
AND lógico

FI_BAND
AND a nivel de bits

XOR lógico (exclusivo)
addr[i] = ((addr[i] && !buf[i]) || (!addr[i] && buf[i]))

    addr[i] = buf[i]

    addr[i] = buf[i]

    addr[i] = buf[i]
FI_CSWAP_LT
Comparar valores y, si son menores, intercambiar con los datos

    addr[i] = buf[i]
FI_CSWAP_GE
Comparar valores y, si son mayores o iguales, intercambiar con los datos

    addr[i] = buf[i]

    addr[i] = buf[i]

Funciones Atómicas Base

Las funciones atómicas base – fi_atomic, fi_atomicv, fi_atomicmsg – se utilizan para transmitir datos a un nodo remoto, donde se realiza la operación atómica especificada contra los datos de destino. El resultado de una función atómica base se almacena en la región de memoria remota. La principal diferencia entre las funciones atómicas es el número y el tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

La llamada fi_atomic transfiere los datos contenidos en el búfer de datos especificado por el usuario a un nodo remoto. Para los puntos finales sin conexión, el punto final de destino se especifica a través del parámetro dest_addr. A menos que el punto final se haya configurado de otra manera, el búfer de datos pasado a fi_atomic no debe ser tocado por la aplicación hasta que la llamada fi_atomic se complete de forma asíncrona. El búfer de destino de una operación atómica base debe permitir el acceso de lectura y/o escritura remota, según corresponda.

La llamada fi_atomicv añade soporte para una lista de dispersión-agrupamiento (scatter-gather) a fi_atomic. La fi_atomicv transfiere el conjunto de búferes de datos referenciados por el parámetro ioc al nodo remoto para su procesamiento.

La llamada fi_inject_atomic es una versión optimizada de fi_atomic. La función fi_inject_atomic se comporta como si el indicador de transferencia FI_INJECT estuviera activado y FI_COMPLETION no lo estuviera. Es decir, el búfer de datos está disponible para su reutilización inmediatamente al regresar de fi_inject_atomic, y no se generará un evento de finalización para esta operación atómica. El evento de finalización se suprimirá incluso si el punto final no se ha configurado con FI_SELECTIVE_COMPLETION. Consulte la discusión de indicadores más abajo para más detalles. El tamaño de mensaje solicitado que se puede usar con fi_inject_atomic está limitado por inject_size.

La llamada fi_atomicmsg admite funciones atómicas sobre puntos finales conectados y sin conexión, con la capacidad de controlar la operación atómica en cada llamada mediante el uso de indicadores. La función fi_atomicmsg toma una struct fi_msg_atomic como entrada.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* local scatter-gather array */
    void                **desc;   /* local access descriptors */
    size_t              iov_count;/* # elements in ioc */
    const void          *addr;    /* optional endpoint address */
    const struct fi_rma_ioc *rma_iov; /* remote SGL */
    size_t              rma_iov_count;/* # elements in remote SGL */
    enum fi_datatype    datatype; /* operand datatype */
    enum fi_op          op;       /* atomic operation */
    void                *context; /* user-defined context */
    uint64_t            data;     /* optional data */
};
struct fi_ioc {
    void        *addr;    /* local address */
    size_t      count;    /* # target operands */
};
struct fi_rma_ioc {
    uint64_t    addr;     /* target address */
    size_t      count;    /* # target operands */
    uint64_t    key;      /* access key */
};

La siguiente lista de operaciones atómicas es utilizable con operaciones atómicas base: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR y FI_ATOMIC_WRITE.

Funciones Atómicas de Obtención (Fetch-Atomic)

Las funciones atómicas de obtención – fi_fetch_atomic, fi_fetch_atomicv y fi_fetch atomicmsg – se comportan de manera similar a la función atómica base equivalente. La diferencia entre las llamadas atómicas de obtención y las base es que las rutinas de obtención atómica devuelven al usuario el valor inicial que estaba almacenado en el destino. El valor inicial se lee en el búfer de resultados proporcionado por el usuario. El búfer de destino de las operaciones de obtención atómica debe estar habilitado para acceso de lectura remota.

La siguiente lista de operaciones atómicas es utilizable con operaciones de obtención atómica: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ y FI_ATOMIC_WRITE.

Para las operaciones FI_ATOMIC_READ, el operando del búfer fuente (por ejemplo, el parámetro buf de fi_fetch_atomic) se ignora y puede ser NULL. Los resultados se escriben en el búfer de resultados.

FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como operación con valla, y cualquier operación publicada después de la operación con valla se pospondrán hasta que todas las operaciones anteriores dirigidas al mismo punto de conexión de igual hayan completado. Las operaciones publicadas después de la valla verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación con valla.

El orden de las operaciones que comienzan con la publicación de la operación con valla (inclusive) hasta la publicación de una operación con valla subsiguiente (exclusiva) está controlado por la semántica de ordenación del punto de conexión.

FI_TAGGED
Especifica que el destino de la operación atómica es un búfer de recepción etiquetado en lugar de un búfer RMA. Cuando un búfer etiquetado es la región de memoria de destino, el parámetro addr se usa como un desplazamiento de bytes basado en 0 en el búfer etiquetado, con el parámetro key especificando la etiqueta.

VALOR_DE_RETORNO

Devuelve 0 si la operación es exitosa. En caso de error, devuelve un valor negativo que corresponde al errno de fabric. Los valores de errno de fabric se definen en rdma/fi_errno.h.

NOTAS

Las operaciones atómicas operan sobre un array de valores de un tipo de dato específico. La atomicidad solo está garantizada para cada operación de tipo de dato, no para todo el array. El siguiente pseudocódigo demuestra esta operación para la escritura atómica atómica sin signo de 64 bits. ATOMIC_WRITE_U64 es una macro dependiente de la plataforma que escribe atómicamente 8 bytes en una ubicación de memoria alineada.

fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]);
}

El número de elementos del array sobre los que operar se especifica a través de un parámetro de recuento. Este debe estar entre 1 y el máximo devuelto a través de la operación válida relevante, inclusive. La operación solicitada y el tipo de dato también deben ser válidos para el proveedor dado.

El orden de las operaciones atómicas realizadas como parte de diferentes mensajes de solicitud está sujeto a las definiciones de ordenación de mensajes y datos asignadas a los puntos de conexión de transmisión y recepción. Se requiere tanto la ordenación de mensajes como la de datos si los resultados de dos operaciones atómicas en los mismos búferes de memoria deben reflejar la segunda operación actuando sobre los resultados de la primera. Ver fi_endpoint(3) para más detalles y restricciones de tamaño de mensaje.
