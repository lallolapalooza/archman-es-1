DESCRIPCIÓ

N

Los contadores registran el número de operaciones solicitadas que han finalizado. Los contadores pueden proporcionar un mecanismo de finalización de bajo peso al permitir la supresión de entradas de finalización de CQ. Son útiles para aplicaciones que solo necesitan saber el número de solicitudes que han finalizado, y no los detalles de cada solicitud. Por ejemplo, los contadores pueden ser útiles para implementar control de flujo basado en créditos o para rastrear el número de procesos remotos que han respondido a una

solicitud.

Los contadores típicamente solo cuentan las finalizaciones exitosas. Sin embargo, si una operación finaliza con error, puede incrementar un valor de error asociado. Es decir, un contador en realidad almacena dos valores distintos, con las finalizaciones de error actualizando un valor específico de

error.

Los contadores se actualizan siguiendo la semántica de eventos de finalización definida en fi_cq(3). El momento de la actualización se basa en el tipo de transferencia y en cualquier indicador de operación

especificado.

Un contador captura diferentes tipos de eventos. El tipo específico que se va a contar es uno de los
siguientes:
- FI_CNTR_EVENTS_C
OMP
El contador se incrementa por cada finalización exitosa que ocurre en un punto final vinculado asociado. El tipo de finalizaciones – envíos y/o recepciones – que se cuentan puede restringirse usando indicadores de control al vincular el contador y el punto final. Los contadores se incrementan en todas las finalizaciones exitosas, independientemente de si la operación genera una entrada en una cola de
eventos.
- FI_CNTR_EVENTS_BY
TES
El contador se incrementa en el número de bytes de usuario, excluyendo cualquier dato de CQ, transferidos en un mensaje de transporte al alcanzar la semántica de finalización especificada. Para los contadores del lado iniciador, el recuento refleja el tamaño de la transferencia solicitada y se actualiza después de que el mensaje alcanza el nivel de finalización deseado (FI_INJECT_COMPLETE, FI_TRANSMIT_COMPLETE, etc.). Para las operaciones de envío y escritura, el recuento refleja el número de bytes transferidos al par. Para las operaciones de lectura, el recuento refleja el número de bytes devueltos en una respuesta de lectura. Las operaciones que pueden tanto escribir como leer datos, como las operaciones atómicas, se comportan como operaciones de lectura en el iniciador, pero como escrituras en el destino. Para los contadores del lado destino, el recuento refleja el tamaño de los datos de usuario recibidos y se incrementa sujeto a la semántica de finalización del lado destino. En la mayoría de los casos, esto indica FI_DELIVERY_COMPLETE, pero puede diferir al acceder a memoria de dispositivo (HMEM). En caso de error, el tamaño de la transferencia no se aplica al campo de error, ese campo se incrementa en 1. El tipo de transferencia FI_COLLECTIVE no está
soportado.

ARGUMENTS

counter
Represents the counter object. See fi_domain.3.
buf
The buffer to store the counter value. The size of the buffer must be large enough to hold the counter value. See fi_enum(3) for counter capacity values.
len
The size of the buffer.
value
The value to add or set the counter to.
threshold
The counter threshold value to wait for.
timeout
The timeout value in micro-seconds. If timeout is zero, the call will not block. If timeout is -1, the call will block indefinitely.

DESCRIPTION

Counters are fabric objects used to track the progress of operations. They are associated with a domain and can be controlled and updated by various operations. Counters can be created using fi_domain_control(3) with the FI_DOMAIN_CONTROL_COUNTERS flag.

fi_close

The fi_close call releases all resources associated with a counter. When closing the counter, there must be no opened endpoints, transmit contexts, receive contexts or memory regions associated with the counter. If resources are still associated with the counter when attempting to close, the call will return -FI_EBUSY.

fi_cntr_control

The fi_cntr_control call is used to access provider or implementation specific details of the counter. Access to the counter should be serialized across all calls when fi_cntr_control is invoked, as it may redirect the implementation of counter operations. The following control commands are usable with a counter:

FI_GETOPSFLAG (uint64_t *)
Returns the current default operational flags associated with the counter.
FI_SETOPSFLAG (uint64_t *)
Modifies the current default operational flags associated with the counter.
FI_GETWAIT (void **)
This command allows the user to retrieve the low-level wait object associated with the counter. The format of the wait-object is specified during counter creation, through the counter attributes. See fi_eq.3 for addition details using control with FI_GETWAIT.

fi_cntr_read

The fi_cntr_read call returns the current value of the counter.

fi_cntr_readerr

The read error call returns the number of operations that completed in error and were unable to update the counter.

fi_cntr_add

This adds the user-specified value to the counter.

fi_cntr_adderr

This adds the user-specified value to the error value of the counter.

fi_cntr_set

This sets the counter to the specified value.

fi_cntr_seterr

This sets the error value of the counter to the specified value.

fi_cntr_wait

This call may be used to wait until the counter reaches the specified threshold, or until an error or timeout occurs. Upon successful return from this call, the counter will be greater than or equal to the input threshold value.

If an operation associated with the counter encounters an error, it will increment the error value associated with the counter. Any change in a counter’s error value will unblock any thread inside fi_cntr_wait.

If the call returns due to timeout, -FI_ETIMEDOUT will be returned. The error value associated with the counter remains unchanged.

It is invalid for applications to call this function if the counter has been configured with a wait object of FI_WAIT_NONE or FI_WAIT_SET.

RETURN VALUES

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned.

fi_cntr_read / fi_cntr_readerr
Returns the current value of the counter.

Fabric errno values are defined in rdma/fi_errno.h.

NOTES

In order to support a variety of counter implementations, updates made to counter values (e.g. fi_cntr_set or fi_cntr_add) may not be immediately visible to counter read operations (i.e. fi_cntr_read or fi_cntr_readerr). A small, but undefined, delay may occur between the counter changing and the reported value being updated. However, a final updated value will eventually be reflected in the read counter value.

Additionally, applications should ensure that the value of a counter is stable and not subject to change prior to calling fi_cntr_set or fi_cntr_seterr. Otherwise, the resulting value of the counter after fi_cntr_set / fi_cntr_seterr is undefined, as updates to the counter may be lost. A counter value is considered stable if all previous updates using fi_cntr_set / fi_cntr_seterr and results of related operations are reflected in the observed value of the counter.
