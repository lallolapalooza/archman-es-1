Filter::Util::Call(3perl) Guía de referencia del programador de Perl Filter::Util::Call(3perl)

NOMBRE

Filter::Util::Call - Módulo de utilidad de filtros de origen de Perl

SINOPSIS

use Filter::Util::Call ;

DESCRIPCIÓN

Este módulo le proporciona el marco para escribir filtros de origen en Perl.

Ahora hay disponible una interfaz alternativa a Filter::Util::Call. Consulte Filter::Simple para obtener más detalles.

Un filtro de origen de Perl se implementa como un módulo de Perl. La estructura del módulo puede adoptar uno de dos formatos ampliamente similares. Para distinguirlos, el primero se denominará filtro de método y el segundo filtro de cierre.

Aquí hay un esqueleto para el filtro de método:

package MyFilter ;
use Filter::Util::Call ;
sub import
{
    my($type, @arguments) = @_ ;
    filter_add([]) ;
}
sub filter
{
    my($self) = @_ ;
    my($status) ;
    $status = filter_read() ;
    $status ;
}
1 ;

y este es el esqueleto equivalente para el filtro de cierre:

package MyFilter ;
use Filter::Util::Call ;
sub import
{
    my($type, @arguments) = @_ ;
    filter_add(
        sub 
        {
            my($status) ;
            $status = filter_read() ;
            $status ;
        } )
}
1 ;

Para utilizar cualquiera de los dos módulos de filtro anteriores, coloque la siguiente línea en un archivo fuente de Perl.

use MyFilter;

De hecho, los módulos esqueleto mostrados anteriormente son filtros de origen completamente funcionales, aunque bastante inútiles. Todo lo que hacen es filtrar el flujo de origen sin modificarlo en absoluto.

Como puede ver, ambos módulos tienen una estructura ampliamente similar. Ambos utilizan el módulo "Filter::Util::Call" y ambos tienen un método "import". La diferencia entre ellos es que el filtro de método requiere un método filter, mientras que el filtro de cierre obtiene el equivalente a un método filter con la subrutina anónima pasada a filter_add.

Para hacer un uso adecuado del filtro de cierre que se muestra arriba, necesita tener una buena comprensión del concepto de cierre. Consulte perlref para obtener más detalles sobre la mecánica de los cierres.

use Filter::Util::Call

Las siguientes funciones son exportadas por "Filter::Util::Call":

filter_add()
filter_read()
filter_read_exact()
filter_del()

import()

El método "import" se utiliza para crear una instancia del filtro. Es llamado indirectamente por Perl cuando encuentra la línea "use MyFilter" en un archivo fuente (Consulte "import" en perlfunc para obtener más detalles sobre "import").

Siempre tendrá al menos un parámetro pasado automáticamente por Perl: esto corresponde al nombre del paquete. En el ejemplo anterior será "MyFilter".

Aparte del primer parámetro, import puede aceptar una lista opcional de parámetros. Estos se pueden usar para pasar parámetros al filtro. Por ejemplo:

use MyFilter qw(a b c) ;

resultará en que el array @_ tendrá los siguientes valores:

@_ [0] => "MyFilter"
@_ [1] => "a"
@_ [2] => "b"
@_ [3] => "c"

Antes de finalizar, la función "import" debe instalar explícitamente el filtro llamando a "filter_add".

filter_add()

La función, "filter_add", instala realmente el filtro. Toma un parámetro que debe ser una referencia. El tipo de referencia utilizada dictará cuál de los dos tipos de filtro se utilizará.

Si se utiliza una referencia CODE, se asumirá un filtro de cierre.

Si no se utiliza una referencia CODE, se asumirá un filtro de método. En un filtro de método, la referencia se puede utilizar para almacenar información de contexto. La referencia será bendecida en el paquete por "filter_add", a menos que la referencia ya estuviera bendecida.

Consulte los filtros al final de estos documentos para ver ejemplos de uso de información de contexto utilizando tanto filtros de método como filtros de cierre.

filter() y subrutina anónima

Tanto el método "filter" utilizado con un filtro de método como la subrutina anónima utilizada con un filtro de cierre es donde se realiza el procesamiento principal para el filtro.

La gran diferencia entre los dos tipos de filtro es que el filtro de método utiliza el objeto pasado al método para almacenar los datos de contexto, mientras que el filtro de cierre utiliza las variables léxicas que son mantenidas por el cierre.

Tenga en cuenta que el único parámetro pasado al filtro de método, $self, es la misma referencia que se pasó a "filter_add" bendecida en el paquete del filtro. Consulte los filtros de ejemplo más adelante para ver detalles sobre el uso de $self.

Aquí hay una lista de las características comunes de la subrutina anónima y el método filter().

$_
Aunque $_ no aparece explícitamente en los filtros de ejemplo anteriores, se utiliza implícitamente en varios lugares.

En primer lugar, cuando se llama a "filter" o a la subrutina anónima, se creará automáticamente una copia local de $_. Siempre contendrá la cadena vacía en este punto.

A continuación, tanto "filter_read" como "filter_read_exact" añadirán cualquier dato de origen que se lea al final de $_.

Finalmente, cuando "filter" o la subrutina anónima hayan terminado de procesar, se espera que devuelvan el origen filtrado usando $_.

Este uso implícito de $_ simplifica enormemente el filtro.

$status
El valor de estado que se devuelve desde el método "filter" del usuario o la subrutina anónima y las funciones "filter_read" y "read_exact" toman el mismo conjunto de valores, a saber: 
< 0  Error
= 0  EOF
> 0  OK
filter_read y filter_read_exact
Estas funciones son utilizadas por el filtro para obtener una línea o un bloque del siguiente filtro en la cadena o del archivo de origen real si no hay otros filtros.

La función "filter_read" tiene dos formas:

$status = filter_read() ;
$status = filter_read($size) ;

La primera forma se utiliza para solicitar una línea, la segunda solicita un bloque.

En modo línea, "filter_read" añadirá la siguiente línea de origen al final del escalar $_.

En modo bloque, "filter_read" añadirá un bloque de datos que es <= $size al final del escalar $_. Es importante enfatizar que "filter_read" no necesariamente leerá un bloque que sea exactamente $size bytes.

Si necesita poder leer un bloque que tenga un tamaño exacto, puede usar la función "filter_read_exact". Funciona de manera idéntica a "filter_read" en modo bloque, excepto que intentará leer un bloque que sea exactamente $size bytes de longitud. Las únicas circunstancias en las que no devolverá un bloque de $size bytes es en EOF o error.

Es muy importante verificar el valor de $status después de cada llamada a "filter_read" o "filter_read_exact".

filter_del

"filter_del", se utiliza para desactivar el filtro actual. No afecta la ejecución del filtro. Todo lo que hace es decirle a Perl que no llame al filtro más.

Consulte "Ejemplo 4: Uso de filter_del" para más detalles.

real_import
Función interna que añade el filtro, basándose en el tipo del argumento de filter_add.
unimport()
Puede usarse para desactivar un filtro, pero rara vez es necesario. Consulte filter_del.

LIMITACIONES

Consulte "LIMITACIONES" en perlfilter para un resumen de los problemas generales de filtrar código a nivel de línea de texto únicamente.

__DATA__ es ignorado
El contenido del bloque __DATA__ no se filtra. Esta es una limitación seria, por ejemplo, para el módulo Switch. Consulte http://search.cpan.org/perldoc?Switch#LIMITATIONS para más información.
Tamaño máximo de código limitado a 32 bits
Actualmente, las longitudes de los búferes internos están limitadas a 32 bits únicamente.

EJEMPLOS

Aquí hay algunos ejemplos que ilustran los conceptos clave; como tales, la mayoría de ellos tienen poca utilidad práctica.

El subdirectorio "examples" tiene copias de todos estos filtros implementados tanto como filtros de método como filtros de clausura.

Ejemplo 1: Un filtro simple.

A continuación hay un filtro de método que está cableado para reemplazar todas las apariciones de la cadena "Joe" por "Jim". No es particularmente útil, pero es el primer ejemplo y quería mantenerlo simple.

package Joe2Jim ;
use Filter::Util::Call ;
sub import
{
    my($type) = @_ ;
    filter_add(bless []) ;
}
sub filter
{
    my($self) = @_ ;
    my($status) ;
    s/Joe/Jim/g
        if ($status = filter_read()) > 0 ;
    $status ;
}
1 ;

Aquí hay un ejemplo de uso del filtro:

use Joe2Jim ;
print "Where is Joe?\n" ;

Y esto es lo que el script de arriba imprimirá:

Where is Jim?

Ejemplo 2: Uso del contexto

El ejemplo anterior no fue particularmente útil. Para hacerlo más de propósito general, haremos uso de los datos de contexto y permitiremos que se usen cadenas arbitrarias de origen y de destino . Esta vez usaremos un filtro de clausura. Para reflejar su papel mejorado, el filtro se llama "Subst".

package Subst ;
use Filter::Util::Call ;
use Carp ;
sub import
{
    croak("usage: use Subst qw(from to)")
        unless @_ == 3 ;
    my ($self, $from, $to) = @_ ;
    filter_add(
        sub 
        {
            my ($status) ;
            s/$from/$to/
                if ($status = filter_read()) > 0 ;
            $status ;
        })
}
1 ;

y se usa así:

use Subst qw(Joe Jim) ;
print "Where is Joe?\n" ;

Ejemplo 3: Uso del contexto dentro del filtro

Aquí hay un filtro que es una variación del filtro "Joe2Jim" . Además de sustituir todas las apariciones de "Joe" por "Jim" , mantiene un recuento del número de sustituciones realizadas en el objeto de contexto.

Una vez que se detecta EOF ($status es cero), el filtro insertará una línea extra en el flujo de código fuente. Cuando esta línea extra se ejecute, imprimirá un recuento del número de sustituciones realmente realizadas. Tenga en cuenta que $status se establece en 1 en este caso.

package Count ;
use Filter::Util::Call ;
sub filter
{
    my ($self) = @_ ;
    my ($status) ;
    if (($status = filter_read()) > 0 ) {
        s/Joe/Jim/g ;
        ++ $$self ;
    }
    elsif ($$self >= 0) { # EOF
        $_ = "print q[Made ${$self} substitutions\n]" ;
        $status = 1 ;
        $$self = -1 ;
    }
    $status ;
}
sub import
{
    my ($self) = @_ ;
    my ($count) = 0 ;
    filter_add(\$count) ;
}
1 ;

Aquí hay un script que lo usa:

use Count ;
print "Hello Joe\n" ;
print "Where is Joe\n" ;

Salida:

Hello Jim
Where is Jim
Made 2 substitutions

Ejemplo 4: Uso de filter_del

Otra variación sobre el tema. Esta vez modificaremos el filtro "Subst" para permitir que se especifiquen un patrón de inicio y uno de fin, además de los patrones de origen y de destino . Si conoce el editor vi , es el equivalente de este comando:

:/start/,/stop/s/from/to/

Cuando se usa como un filtro, queremos invocarlo así:

use NewSubst qw(start stop from to) ;

Aquí está el módulo.

package NewSubst ;
use Filter::Util::Call ;
use Carp ;
sub import
{
    my ($self, $start, $stop, $from, $to) = @_ ;
    my ($found) = 0 ;
    croak("usage: use Subst qw(start stop from to)")
        unless @_ == 5 ;
    filter_add( 
        sub 
        {
            my ($status) ;
            if (($status = filter_read()) > 0) {
                $found = 1
                    if $found == 0 and /$start/ ;
                if ($found) {
                    s/$from/$to/ ;
                    filter_del() if /$stop/ ;
                }
            }
            $status ;
        } )
}
1 ;

Filter::Simple

Si pretende usar la funcionalidad de Filter::Call, recomiendo encarecidamente que eche un vistazo al excelente módulo Filter::Simple de Damian Conway. El módulo de Damian proporciona una interfaz mucho más limpia que Filter::Util::Call. Aunque no permite el control fino que Filter::Util::Call, debería ser suficiente para la mayoría de aplicaciones. Está disponible en

http://search.cpan.org/dist/Filter-Simple/
