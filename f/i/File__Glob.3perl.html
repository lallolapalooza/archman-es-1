File::Glob(3perl) Guía del programador de Perl File::Glob(3perl)

NOMBRE

File::Glob - Extensión de Perl para la rutina glob de BSD

SINÓPSIS

use File::Glob ':bsd_glob';
@lista = bsd_glob('*.[ch]');
$directorio_home = bsd_glob('~gnat', GLOB_TILDE | GLOB_ERR);
if (GLOB_ERROR) {
  # ocurrió un error al leer $directorio_home
}
## anular el glob principal (CORE::glob() lo hace automáticamente
## por defecto de todos modos, desde v5.6.0)
use File::Glob ':globally';
my @fuentes = <*.{c,h,y}>;
## anular el glob principal, forzando sensibilidad a mayúsculas
use File::Glob qw(:globally :case);
my @fuentes = <*.{c,h,y}>;
## anular el glob principal forzando insensibilidad a mayúsculas
use File::Glob qw(:globally :nocase);
my @fuentes = <*.{c,h,y}>;
## glob en todos los archivos del directorio home
use File::Glob ':globally';
my @fuentes = <~gnat/*>;

DESCRIPCIÓN

El operador de corchetes angulares de glob "<>" es un generador de nombres de ruta que implementa las reglas para la coincidencia de patrones de nombres de archivos utilizadas por los shells similares a Unix, como el shell Bourne o el shell C.

File::Glob::bsd_glob() implementa la rutina glob(3) de FreeBSD, que es un superconjunto del glob() POSIX (descrito en IEEE Std 1003.2 "POSIX.2"). bsd_glob() toma un argumento obligatorio de "patrón", y un argumento opcional de "flags", y devuelve una lista de nombres de archivos que coinciden con el patrón, con la interpretación del patrón modificada por la variable "flags".

Desde v5.6.0, el CORE::glob() de Perl se implementa en términos de bsd_glob(). Tenga en cuenta que no comparten el mismo prototipo: CORE::glob() solo acepta un argumento. Debido a razones históricas, CORE::glob() también dividirá su argumento en espacios en blanco, tratándolo como múltiples patrones, mientras que bsd_glob() los considera como un solo patrón. Pero vea ":bsd_glob" bajo "EXPORTACIONES", abajo.

CARACTERES META

\       Comillar el siguiente carácter meta
[]      Clase de caracteres
{}      Patrón múltiple
*       Coincide con cualquier cadena de caracteres
?       Coincide con cualquier carácter único
~       Directorio home del nombre de usuario

La metanotación "a{b,c,d}e" es un atajo para "abe ace ade". El orden de izquierda a derecha se conserva, con los resultados de las coincidencias ordenados por separado a bajo nivel para preservar este orden. Como caso especial, "{", "}", y "{}" se pasan sin cambios.

EXPORTACIONES

Vea también los "FLAGS POSIX" a continuación, que se pueden exportar individualmente.

":bsd_glob"

La etiqueta de exportación ":bsd_glob" exporta bsd_glob() y las constantes que se enumeran a continuación. También anula glob() en el paquete que llama con una que se comporta como bsd_glob() con respecto a los espacios (el espacio se trata como parte de un nombre de archivo), pero admite la iteración en contexto escalar; es decir, preserva la característica de la función principal de devolver el siguiente elemento cada vez que se llama.

":glob"

La etiqueta ":glob", ahora desaconsejada, es la versión antigua de ":bsd_glob". Exporta las mismas constantes y funciones, pero su anulación de glob() no admite la iteración; devuelve el último nombre de archivo en contexto escalar. Eso significa que esto será un bucle infinito:

use File::Glob ':glob';
while (my $file = <* copy.txt>) {
    ...
}

"bsd_glob"

Esta función, que está incluida en las dos etiquetas de exportación anteriores, toma uno o dos argumentos. El primero es el patrón glob. El segundo, si se proporciona, es un conjunto de flags ORed juntos. Las flags disponibles y el conjunto de flags por defecto se enumeran a continuación bajo "FLAGS POSIX".

Recuerde que para usar las constantes con nombre para las flags debe importarlas, por ejemplo con ":bsd_glob" descrito anteriormente. Si no se importan y "use strict" no está activo, las constantes se tratarán como cadenas de palabras desnudas, lo que no hará lo que usted quiere.

":nocase" y ":case"

Estas dos etiquetas de exportación modifican globalmente las flags por defecto que usan bsd_glob() y, excepto en VMS, el operador incorporado "glob" de Perl. "GLOB_NOCASE" se activa o desactiva, respectivamente.

"csh_glob"

La función csh_glob() también se puede exportar, pero no debería usarla directamente a menos que realmente sepa lo que está haciendo. Divide el patrón en palabras y alimenta cada una a bsd_glob(). La función glob() propia de Perl utiliza esto internamente.

FLAGS POSIX

Si no se proporciona un argumento de flags, se establece "GLOB_CSH", y en sistemas VMS y Windows, también "GLOB_NOCASE". De lo contrario, las flags a utilizar se determinan únicamente por el argumento de flags. Las flags definidas por POSIX son:

"GLOB_ERR"
Fuerza a bsd_glob() a devolver un error cuando encuentra un directorio que no puede abrir o leer. Ordinariamente bsd_glob() continúa encontrando coincidencias.
"GLOB_LIMIT"
Hace que bsd_glob() devuelva un error (GLOB_NOSPACE) cuando el patrón se expande a un tamaño mayor que la constante del sistema "ARG_MAX" (generalmente encontrada en limits.h). Si su sistema no define esta constante, bsd_glob() usa sysconf(_SC_ARG_MAX) o "_POSIX_ARG_MAX" donde estén disponibles (en ese orden). Puede inspeccionar estos valores usando la extensión estándar "POSIX".
"GLOB_MARK"
A cada nombre de ruta que sea un directorio que coincida con el patrón se le añade una barra.
"GLOB_NOCASE"
Por defecto, se asume que los nombres de archivo son sensibles a mayúsculas y minúsculas; esta flag hace que bsd_glob() trate las diferencias de mayúsculas y minúsculas como no significativas.
"GLOB_NOCHECK"
Si el patrón no coincide con ningún nombre de ruta, entonces bsd_glob() devuelve una lista que consta únicamente del patrón. Si "GLOB_QUOTE" está activada, su efecto está presente en el patrón devuelto.
"GLOB_NOSORT"
Por defecto, los nombres de ruta se ordenan en orden ascendente ASCII; esta flag evita ese ordenamiento (acelerando bsd_glob()).

Las extensiones de FreeBSD al estándar POSIX son las siguientes flags:

"GLOB_BRACE"
Pre-procesa la cadena para expandir cadenas "{pat,pat,...}" como csh(1). El patrón '{}' se deja sin expandir por razones históricas (y csh(1) hace lo mismo para facilitar la escritura de patrones de find(1)).
"GLOB_NOMAGIC"
Igual que "GLOB_NOCHECK", pero solo devuelve el patrón si no contiene ninguno de los caracteres especiales "*", "?" o "[". "NOMAGIC" se proporciona para simplificar la implementación del comportamiento histórico de globbing de csh(1) y probablemente no debería usarse en ningún otro lugar.
"GLOB_QUOTE"
Usa el carácter de barra invertida ('\') para comillar: cada ocurrencia de una barra invertida seguida de un carácter en el patrón se reemplaza por ese carácter, evitando cualquier interpretación especial del carácter. (Pero vea abajo las excepciones en sistemas tipo DOS).
"GLOB_TILDE"
Expande patrones que comienzan con '~' a directorios home de nombres de usuario.
"GLOB_CSH"
Para conveniencia, "GLOB_CSH" es un sinónimo de "GLOB_BRACE | GLOB_NOMAGIC | GLOB_QUOTE | GLOB_TILDE | GLOB_ALPHASORT".

File::Glob(3pm)

NAME

File::Glob - Perl extension for Unix globbing

SYNOPSIS

    use File::Glob qw(:bsd_glob);
    
    @files = bsd_glob($pattern, %options);
    $files_ref = bsd_glob($pattern, %options);
    
    # Example:
    @files = bsd_glob("*.pm", GLOB_TILDE_CHECK);
    @files = bsd_glob("{*.c,*.h}", GLOB_TILDE);
    @files = bsd_glob("foo/bar/*", GLOB_PATHSPEC | GLOB_MARK);

DESCRIPTION

This module provides a Perl interface to the standard C library glob(3) function. The main function exported is bsd_glob().

The bsd_glob() function takes a pattern string and a set of flags, and returns a list of filenames matching the pattern.

The function can also be called in scalar context, in which case it returns a reference to an array of matching filenames. This is more efficient if you intend to use the result in scalar context.

The following flags are supported. They can be imported using "use File::Glob qw(:bsd_glob)" or by explicitly importing them:

"GLOB_APPEND"
The results are appended to the list of results defined by "GLOB_DOOFF". Not applicable in Perl.
"GLOB_DOOFF"
This flag is used to control where results are stored. Not applicable in Perl.
"GLOB_ERR"
If set, bsd_glob() will return immediately upon any error, setting $! and returning &File::Glob::GLOB_ERROR.
"GLOB_MARK"
Each string which matches a directory will have a trailing slash appended. (So that `foo/*` will match `foo/bar/` if `bar` is a directory).
"GLOB_NOCHECK"
If the pattern matches no files, the pattern itself is returned as the only element of the list. This is useful for filenames that contain glob characters, eg. "bsd_glob("*.txt", GLOB_NOCHECK)" should return "*.txt" if no files end in .txt.
"GLOB_NOSORT"
Do not sort the results. The default behaviour is to sort the results.
"GLOB_NOESCAPE"
Do not treat backslashes as escape characters. Note that this is the opposite of the default behaviour for the C shell, but is the same as the default behaviour for the standard C library glob(3).
"GLOB_BRACE"
Expand the following characters: `{a,b,c}` or `{a,b}c` or `a{b,c}`. This is not enabled by default. "GLOB_BRACE" is enabled by default in the standard C library glob(3).
"GLOB_TILDE"
If the first character of the pattern is a tilde ('~'), it is expanded to the current user's home directory. If the tilde is followed by a username, e.g. "~username", it is expanded to that user's home directory. Note that this requires searching the password database. This is not enabled by default.
"GLOB_TILDE_CHECK"
This flag is like "GLOB_TILDE", but requires that the expansion occur. If the tilde cannot be expanded (e.g., if the username does not exist), the pattern is returned unchanged.
"GLOB_ONLYDIR"
If the pattern includes a slash, only return files in that directory. Useful for cases where you want to know if a directory exists, but don't want to match files within it.
"GLOB_PATHSPEC"
If the pattern includes a slash, treat the pattern as a path. Otherwise, treat it as a filename.
"GLOB_QUOTE"
If set, a backslash (backslash) will quote the next character. This behaves like "GLOB_NOESCAPE", but will still allow specific characters to be escaped. This is the default behaviour for the Perl implementation.

The following flags have not been implemented in the Perl version:

"GLOB_ALTDIRFUNC", and "GLOB_MAGCHAR" flags have not been implemented in the Perl version because they involve more complex interaction with the underlying C structures.

The following flag has been added in the Perl implementation for csh compatibility:

"GLOB_ALPHASORT"
If "GLOB_NOSORT" is not in effect, sort filenames is alphabetical order (case does not matter) rather than in ASCII order.

DIAGNOSTICS

bsd_glob() returns a list of matching paths, possibly zero length. If an error occurred, &File::Glob::GLOB_ERROR will be non-zero and $! will be set. &File::Glob::GLOB_ERROR is guaranteed to be zero if no error occurred, or one of the following values otherwise:

"GLOB_NOSPACE"
An attempt to allocate memory failed.
"GLOB_ABEND"
The glob was stopped because an error was encountered.

In the case where bsd_glob() has found some matching paths, but is interrupted by an error, it will return a list of filenames and set &File::Glob::ERROR.

Note that bsd_glob() deviates from POSIX and FreeBSD glob(3) behaviour by not considering "ENOENT" and "ENOTDIR" as errors - bsd_glob() will continue processing despite those errors, unless the "GLOB_ERR" flag is set.

Be aware that all filenames returned from File::Glob are tainted.

NOTES

  • If you want to use multiple patterns, e.g. "bsd_glob("a* b*")", you should probably throw them in a set as in "bsd_glob("{a*,b*}")". This is because the argument to bsd_glob() isn't subjected to parsing by the C shell. Remember that you can use a backslash to escape things.
  • On DOSISH systems, backslash is a valid directory separator character. In this case, use of backslash as a quoting character (via GLOB_QUOTE) interferes with the use of backslash as a directory separator. The best (simplest, most portable) solution is to use forward slashes for directory separators, and backslashes for quoting. However, this does not match "normal practice" on these systems. As a concession to user expectation, therefore, backslashes (under GLOB_QUOTE) only quote the glob metacharacters '[', ']', '{', '}', '-', '~', and backslash itself. All other backslashes are passed through unchanged.
  • Win32 users should use the real slash. If you really want to use backslashes, consider using Sarathy's File::DosGlob, which comes with the standard Perl distribution.
