NOMBRE

firewalld.conf - archivo de configuración de firewalld

SINOPSIS

/etc/firewalld/firewalld.conf

DESCRIPCIÓN

firewalld.conf es cargado por firewalld durante el proceso de inicialización. El archivo contiene las opciones de configuración básicas para firewalld.

OPCIONES

Estas son las opciones que se pueden establecer en el archivo de configuración:

DefaultZone

Establece la zona predeterminada para las conexiones o interfaces si la zona no es seleccionada o especificada por NetworkManager, initscripts o la herramienta de línea de comandos. La zona predeterminada es public.

MinimalMark

Obsoleto. Esta opción se ignora y ya no se utiliza. Las marcas ya no se utilizan internamente.

CleanupModulesOnExit

Establecer esta opción a yes o true descarga todos los módulos del kernel relacionados con el firewall cuando firewalld se detiene. El valor predeterminado es no o false.

CleanupOnExit

Si firewalld se detiene, limpia todas las reglas del firewall. Establecer esta opción a no o false deja las reglas del firewall actuales intactas. El valor predeterminado es yes o true.

IPv6_rpfilter

Realiza filtrado de ruta inversa (RPF) en paquetes IPv6 según RFC 3704. Valores posibles: - strict: Realiza filtrado "estricto" según RFC 3704. Esta verificación verifica que la interfaz de entrada sea la misma interfaz que se usaría para enviar una respuesta de paquete a la fuente. Es decir, entrada == salida. - loose: Realiza filtrado "suelto" según RFC 3704. Esta verificación solo verifica que haya una ruta de regreso a la fuente a través de cualquier interfaz; incluso si no es la misma en la que llegó el paquete. - strict-forward: Esto es casi idéntico a "loose", pero no realiza RPF para paquetes dirigidos al host (INPUT). - loose-forward: Esto es casi idéntico a "loose", pero no realiza RPF para paquetes dirigidos al host (INPUT). - no: RPF se deshabilita por completo. El rp_filter para IPv4 se controla mediante sysctl.

Nota: Esta característica tiene un impacto en el rendimiento. En la mayoría de los casos, el impacto no es suficiente como para causar una diferencia notable. Requiere búsquedas de rutas y su ejecución ocurre antes de la ruta rápida de las conexiones establecidas. Como tal, puede tener un impacto significativo en el rendimiento si hay mucho tráfico. Está habilitado por defecto por seguridad, pero se puede deshabilitar si el rendimiento es una preocupación. Alternativamente, se puede usar una de las variantes que solo realiza RPF en paquetes reenviados.

IndividualCalls

Si esta opción está deshabilitada (lo está por defecto), se utilizan llamadas combinadas de -restore y no llamadas individuales para aplicar cambios al firewall. El uso de llamadas individuales aumenta el tiempo necesario para aplicar cambios y para iniciar el demonio, pero es bueno para la depuración ya que los mensajes de error son más específicos.

LogDenied

Añade reglas de registro justo antes de las reglas de rechazo y caída en las cadenas INPUT, FORWARD y OUTPUT para las reglas por defecto y también para las reglas finales de rechazo y caída en las zonas para el tipo de paquete de capa de enlace configurado. Los valores posibles son: all, unicast, broadcast, multicast y off. La configuración predeterminada es off, que deshabilita el registro.

AutomaticHelpers

Obsoleto. Esta opción se ignora y ya no se utiliza.

FirewallBackend

Selecciona la implementación del backend del firewall. Los valores posibles son: nftables (predeterminado), o iptables. Esto se aplica a todos los primitivos de firewalld. La única excepción son las reglas directas y de traspaso, que siempre utilizan los backends tradicionales iptables, ip6tables y ebtables.

Nota: El backend de iptables está obsoleto. Será eliminado en una futura versión.

FlushAllOnReload

Descarta todas las reglas en tiempo de ejecución al recargar. En versiones anteriores, parte de la configuración en tiempo de ejecución se conservaba durante una recarga, a saber: la asignación de interfaz a zona y las reglas directas. Esto era confuso para los usuarios. Para obtener el comportamiento anterior, establezca esto en "no". El valor por defecto es "yes".

ReloadPolicy

La política durante la recarga. Por defecto, todo el tráfico, excepto las conexiones establecidas, se descarta mientras se recargan las reglas del firewall. Esto se puede anular para INPUT, FORWARD y OUTPUT. Los valores aceptados son "DROP", "REJECT" y "ACCEPT", que luego se aplican a todas las tablas. Alternativamente, la política se puede especificar por tabla, como "INPUT:REJECT,FORWARD:DROP,OUTPUT:ACCEPT". El valor predeterminado es "INPUT:DROP,FORWARD:DROP,OUTPUT:DROP".

RFC3964_IPv4

Según RFC 3964, filtra el tráfico IPv6 con direcciones de destino 6to4 que corresponden a direcciones IPv4 que no deberían ser enrutadas a través de Internet público. El valor predeterminado es "yes".

StrictForwardPorts

Si se establece en yes, las reglas de NAT de destino (DNAT) generadas NO aceptarán tráfico que haya sido DNAT'd por otras entidades, por ejemplo, docker. Firewalld será estricto y no permitirá puertos de contenedor publicados hasta que se permitan explícitamente a través de firewalld. Si se establece en no, entonces docker (y podman) se integra perfectamente con firewalld. Los puertos de contenedor publicados se permiten implícitamente. El valor predeterminado es "no".

AllowZoneDrifting

Obsoleto. Esta opción se ignora y ya no se utiliza.

NftablesFlowtable

Esto puede mejorar el rendimiento del tráfico reenviado al habilitar la tabla de flujo de nftables. Es una ruta rápida de software y evita llamar a la evaluación de reglas de nftables para los paquetes de datos. Su valor es una lista de interfaces separada por espacios. Ejemplo de valor "eth0 eth1". El valor predeterminado es "off".

NftablesCounters

Si se establece en yes, añade un contador a cada regla de nftables. Esto es útil para la depuración y tiene un pequeño costo de rendimiento. El valor predeterminado es "no".

NftablesTableOwner

Si se establece en yes, el conjunto de reglas de nftables generado será propiedad exclusiva de firewalld. Esto evita que otras entidades modifiquen errónea (o maliciosamente) el conjunto de reglas de firewalld. Si modifica intencionalmente las reglas de firewalld, deberá establecer esto en "no". El valor predeterminado es "yes".
