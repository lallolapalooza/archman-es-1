NOMBRE

fi_direct - Acceso directo al proveedor de tejido

SINOPSIS

-DFABRIC_DIRECT
#define FABRIC_DIRECT

El tejido directo proporciona un mecanismo para que las aplicaciones compilen contra proveedores de tejido específicos sin pasar por el framework de libfabric o las tablas de vectores de funciones. Esto permite una optimización extrema a través de la inserción de funciones en línea a costa de admitir múltiples proveedores o diferentes versiones del mismo proveedor.

DESCRIPCIÓN

El uso del tejido directo está destinado únicamente a aplicaciones que requieren la mínima latencia de software posible y están dispuestas a recompilar para hardware de tejido específico. Los proveedores que admiten tejido directo implementan sus propias versiones de las llamadas estáticas en línea que se definen en los archivos de cabecera de libfabric, definen valores de enumeración seleccionados y proporcionan definiciones para optimizaciones en tiempo de compilación. Las aplicaciones pueden entonces programar contra las llamadas estándar de libfabric, pero enlazarse directamente contra las llamadas del proveedor definiendo FABRIC_DIRECT como parte de su compilación.

En general, el uso de tejido directo no requiere cambios en el código fuente de la aplicación y, en cambio, se limita al proceso de compilación.

Los proveedores que admiten tejido directo deben instalar versiones `directas' de todos los archivos de cabecera de libfabric. Para mayor comodidad, las fuentes de libfabric contienen archivos de cabecera de ejemplo que pueden ser modificados por un proveedor. Los nombres de los archivos de cabecera `directos' tienen `fi_direct' como prefijo: fi_direct.h, fi_direct_endpoint.h, etc.

Los proveedores directos tienen prohibido sobrescribir o modificar estructuras de datos existentes. Sin embargo, las extensiones específicas del proveedor siguen estando disponibles. Además de las llamadas a funciones directas del tejido a código del proveedor, un proveedor de tejido directo puede definir cero o más de las siguientes definiciones de capacidad. Las aplicaciones pueden comprobar estas capacidades para optimizar las rutas de código en tiempo de compilación, en lugar de depender de comprobaciones en tiempo de ejecución.

DEFINICIONES DE CAPACIDAD

Para que el código de la aplicación pueda optimizarse en tiempo de compilación, los proveedores directos deben proporcionar definiciones para varias capacidades y modos, si esas capacidades son compatibles. Los siguientes valores de #define pueden ser utilizados por una aplicación para comprobar la compatibilidad del proveedor con las características admitidas.

FI_DIRECT_CONTEXT
El proveedor establece FI_CONTEXT o FI_CONTEXT2 para fi_info:mode. Véase fi_getinfo para más detalles. Cuando se define FI_DIRECT_CONTEXT, las aplicaciones deben usar struct fi_context en sus definiciones, incluso si se establece FI_CONTEXT2.
FI_DIRECT_LOCAL_MR
El proveedor establece FI_LOCAL_MR para fi_info:mode. Véase fi_getinfo para más detalles.

VER TAMBIÉN

fi_getinfo(3), fi_endpoint(3), fi_domain(3)

AUTORES
