NOMBRE

fi_rma - operaciones de acceso a memoria remota

fi_read / fi_readv / fi_readmsg
Inicia una lectura de memoria remota

fi_write / fi_writev / fi_writemsg fi_inject_write / fi_writedata : Inicia una escritura en memoria remota

SINOPSIS

#include <rdma/fi_rma.h>
ssize_t fi_read(struct fid_ep *ep, void *buf, size_t len, void *desc,
    fi_addr_t src_addr, uint64_t addr, uint64_t key, void *context);
ssize_t fi_readv(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t src_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_readmsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_write(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writev(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writemsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_inject_write(struct fid_ep *ep, const void *buf, size_t len,
    fi_addr_t dest_addr, uint64_t addr, uint64_t key);
ssize_t fi_writedata(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, uint64_t data, fi_addr_t dest_addr, uint64_t addr,
    uint64_t key, void *context);
ssize_t fi_inject_writedata(struct fid_ep *ep, const void *buf, size_t len,
    uint64_t data, fi_addr_t dest_addr, uint64_t addr, uint64_t key);

ARGUMENTOS

ep
Punto final de tejido en el que iniciar la operación de lectura o escritura.
buf
Búfer de datos local para leer (destino de lectura) o escribir desde (fuente de escritura)
len
Longitud de los datos a leer o escribir, especificada en bytes. Las transferencias válidas son de 0 bytes hasta el tamaño máximo de mensaje del punto final.
iov
Búfer de datos vectoriales.
count
Número de entradas de datos vectoriales.
addr
Dirección de la memoria remota a la que acceder. Esta será la dirección virtual de la región remota en el caso de FI_MR_BASIC, o el desplazamiento desde la dirección de inicio en el caso de FI_MR_SCALABLE.
key
Clave de protección asociada con la memoria remota.
desc
Descriptor asociado con el búfer de datos local. Ver fi_mr(3).
data
Datos de CQ remotos a transferir con la operación.
dest_addr
Dirección de destino para transferencias de escritura sin conexión. Ignorado para puntos finales conectados.
src_addr
Dirección de origen desde la que leer para transferencias sin conexión. Ignorado para puntos finales conectados.
msg
Descriptor de mensaje para operaciones de lectura y escritura.
flags
Banderas adicionales a aplicar para la operación de lectura o escritura.
context
Puntero especificado por el usuario para asociar con la operación. Este parámetro se ignora si la operación no generará una finalización exitosa, a menos que una bandera de operación especifique que el parámetro de contexto debe usarse para entrada requerida.

DESCRIPCIÓN

Las operaciones de acceso a memoria remota (RMA) se utilizan para transferir datos directamente entre un búfer de datos local y un búfer de datos remoto. Las transferencias RMA ocurren con granularidad a nivel de byte, y no se mantienen límites de mensajes.

Las funciones de escritura – fi_write, fi_writev, fi_writemsg, fi_inject_write y fi_writedata – se utilizan para transmitir datos a un búfer de memoria remota. La principal diferencia entre las funciones de escritura radica en el número y tipo de parámetros que aceptan como entrada. Por lo demás, realizan la misma función general.

Las funciones de lectura – fi_read, fi_readv y fi_readmsg – se utilizan para transferir datos de una región de memoria remota a uno o varios búferes de datos locales. De forma similar a las operaciones de escritura, las operaciones de lectura son asíncronas. Los usuarios no deben manipular los búferes de datos publicados hasta que la operación de lectura haya finalizado.

Las operaciones RMA completadas se informan al usuario a través de una o más colas de finalización asociadas con el punto final. Los usuarios proporcionan un contexto que se asocia con cada operación y se devuelve al usuario como parte de la finalización. Ver fi_cq para detalles del evento de finalización.

Por defecto, el punto final remoto no genera un evento ni notifica al usuario cuando una región de memoria ha sido accedida por una operación de lectura o escritura RMA. Sin embargo, se pueden asociar datos inmediatos con una operación de escritura RMA. Las escrituras RMA con datos inmediatos generarán una entrada de finalización en el punto final remoto, para que los datos inmediatos puedan ser entregados.

fi_write

La llamada fi_write transfiere los datos contenidos en el búfer de datos especificado por el usuario a una región de memoria remota.

fi_writev

La llamada fi_writev añade soporte para una lista de dispersión/recopilación a fi_write. fi_writev transfiere el conjunto de búferes de datos referenciados por el parámetro iov a la región de memoria remota.

fi_writemsg

La llamada fi_writemsg soporta transferencias de datos a través de puntos finales conectados y sin conexión, con la capacidad de controlar la operación de escritura por llamada a través del uso de banderas. La función fi_writemsg toma una estructura fi_msg_rma como entrada.

struct fi_msg_rma {
    const struct iovec *msg_iov;     /* array de dispersión/recopilación local */
    void               **desc;       /* descriptor de operación */
    size_t             iov_count;    /* # elementos en msg_iov */
    fi_addr_t          addr;        /* dirección de punto final opcional */
    const struct fi_rma_iov *rma_iov;/* SGL remota */
    size_t             rma_iov_count;/* # elementos en rma_iov */
    void               *context;     /* contexto definido por el usuario */
    uint64_t           data;         /* datos inmediatos opcionales */
};
struct fi_rma_iov {
    uint64_t           addr;         /* dirección RMA de destino */
    size_t             len;          /* tamaño del búfer de destino */
    uint64_t           key;          /* clave de acceso */
};

fi_inject_write

La llamada de inyección de escritura es una versión optimizada de fi_write. Proporciona semántica de finalización similar a fi_inject fi_msg(3).

fi_writedata

La llamada de escritura de datos es similar a fi_write, pero permite el envío de datos de CQ remotos (ver bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_inject_writedata

La llamada de inyección de escritura de datos es similar a fi_inject_write, pero permite el envío de datos de CQ remotos (ver bandera FI_REMOTE_CQ_DATA) como parte de la transferencia.

fi_read

La llamada fi_read solicita que el punto final remoto transfiera datos de la región de memoria remota al búfer de datos local.

fi_readv

La llamada fi_readv añade soporte para una lista de dispersión/recopilación a fi_read. fi_readv transfiere datos de la región de memoria remota al conjunto de búferes de datos referenciados por el parámetro iov.

fi_readmsg

La llamada fi_readmsg soporta transferencias de datos a través de puntos finales conectados y sin conexión, con la capacidad de controlar la operación de lectura por llamada a través del uso de banderas. La función fi_readmsg toma una estructura fi_msg_rma como entrada.

BANDERA

FLAGS

Las llamadas fi_readmsg y fi_writemsg permiten al usuario especificar indicadores que pueden cambiar la operación de transferencia de datos predeterminada. Los indicadores especificados con fi_readmsg / fi_writemsg anulan la mayoría de los indicadores configurados previamente con el endpoint, excepto donde se indica lo contrario (ver fi_endpoint.3). La siguiente lista de indicadores son utilizables con fi_readmsg y/o fi_writemsg.

FI_REMOTE_CQ_DATA
Se aplica a fi_writemsg. Indica que los datos de CQ remota están disponibles y deben enviarse como parte de la solicitud. Consulte fi_getinfo para obtener detalles adicionales sobre FI_REMOTE_CQ_DATA. Este indicador se establece implícitamente para fi_writedata y fi_inject_writedata.
FI_COMPLETION
Indica que se debe generar una entrada de finalización para la operación especificada. El endpoint debe estar enlazado a una cola de finalización con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o este indicador se ignora.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que se publicarán inmediatamente después de que la llamada actual devuelva. El uso de este indicador puede mejorar el rendimiento al permitir que el proveedor optimice su acceso al hardware de la red.
FI_INJECT
Se aplica a fi_writemsg. Indica que el búfer de datos de salida debe devolverse al usuario inmediatamente después de que la llamada de escritura devuelva, incluso si la operación se maneja de forma asíncrona. Esto puede requerir que la implementación del proveedor subyacente copie los datos en un búfer local y transfiera desde ese búfer. Este indicador solo se puede usar con mensajes más pequeños que inject_size.
FI_INJECT_COMPLETE
Se aplica a fi_writemsg. Indica que se debe generar una finalización cuando los búferes de origen puedan reutilizarse.
FI_TRANSMIT_COMPLETE
Se aplica a fi_writemsg. Indica que no se debe generar una finalización hasta que la operación se haya transmitido correctamente y ya no esté siendo rastreada por el proveedor.
FI_DELIVERY_COMPLETE
Se aplica a fi_writemsg. Indica que se debe generar una finalización cuando la operación haya sido procesada por el destino.
FI_COMMIT_COMPLETE
Se aplica a fi_writemsg cuando se dirige a regiones de memoria persistente. Indica que una finalización solo debe generarse después de que el resultado de la operación se haya hecho duradero.
FI_FENCE
Se aplica a las transmisiones. Indica que la operación solicitada, también conocida como operación cercada, y cualquier operación publicada después de la operación cercada se pospondrán hasta que todas las operaciones anteriores dirigidas al mismo endpoint par hayan finalizado. Las operaciones publicadas después del cercado verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación cercada.

El orden de las operaciones que comienzan con la publicación de la operación cercada (inclusive) hasta la publicación de una operación cercada subsiguiente (exclusiva) se controla mediante la semántica de ordenación del endpoint.

VALOR DE RETORNO

Devuelve 0 si la operación fue exitosa. En caso de error, se devuelve un valor negativo que corresponde al errno de fabric. Los valores de errno de fabric se definen en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Consulte fi_msg(3) para obtener una descripción detallada de cómo manejar FI_EAGAIN.

VER TAMBIÉN

fi_getinfo(3), fi_endpoint(3), fi_domain(3), fi_cq(3)
