DESCRIPCIÓ

N

Los vectores de direcciones se utilizan para mapear direcciones de nivel superior, que pueden ser más naturales para que una aplicación las use, en direcciones específicas del fabric. Por ejemplo, un punto final puede estar asociado con una dirección struct sockaddr_in, indicando que el punto final es alcanzable usando un número de puerto TCP sobre una dirección IPv4. Esto puede ser cierto incluso si el punto final se comunica usando un protocolo de red propietario. El propósito del AV es asociar una dirección de nivel superior con un valor más simple y eficiente que pueda ser usado por la API de libfabric de una manera agnóstica al fabric. La dirección mapeada es de tipo fi_addr_t y se devuelve a través de una llamada de inserción de

AV.

El proceso de mapear una dirección es específico del fabric y del proveedor, pero puede involucrar una resolución de direcciones extensa y protocolos de gestión de fabric. Las operaciones de AV son síncronas por defecto (la opción asincrónica ha quedado obsoleta, ver abajo). Ver la sección NOTAS para las restricciones de AV sobre direcciones

duplicadas.

Obsoleto: Las operaciones de AV pueden configurarse para operar de forma asincrónica especificando la bandera FI_EVENT en fi_av_open. Al solicitar operación asincrónica, la aplicación debe primero vincular una cola de eventos al AV antes de insertar

direcciones.

ty
pe
Un tipo de AV corresponde a una implementación conceptual de un vector de direcciones. El tipo especifica cómo una aplicación ve los datos almacenados en el AV, incluyendo cómo pueden ser accedidos. Los valores válidos
son:
- FI_AV_MAP
(obsoleto)
Las direcciones que se insertan en un AV se mapean a una dirección de fabric nativa para su uso por la aplicación. El uso de FI_AV_MAP requiere que una aplicación almacene el valor fi_addr_t devuelto que está asociado con cada dirección insertada. La ventaja de usar FI_AV_MAP es que el valor fi_addr_t devuelto puede contener datos de dirección codificados, que están inmediatamente disponibles al procesar solicitudes de transferencia de datos. Esto puede eliminar o reducir el número de búsquedas de memoria necesarias al iniciar una transferencia. La desventaja de FI_AV_MAP es el aumento en el uso de memoria necesario para almacenar las direcciones devueltas. Las direcciones se almacenan en el AV usando un mecanismo específico del proveedor, incluyendo, pero no limitado a, un árbol, una tabla hash, o mantenidas en el heap. Esta opción está obsoleta, y se anima a los proveedores a alinear el comportamiento de FI_AV_MAP con
FI_AV_TABLE.
- FI_AV_TAB
LE
Las direcciones que se insertan en un AV de tipo FI_AV_TABLE son accesibles usando un índice simple. Conceptualmente, el AV puede ser tratado como un array de direcciones, aunque el proveedor puede implementar el AV usando una variedad de mecanismos. Cuando se usa FI_AV_TABLE, el fi_addr_t devuelto es un índice, con el índice para una dirección insertada siendo el mismo que su orden de inserción en la tabla. El índice de la primera dirección insertada en un FI_AV_TABLE será 0, y las inserciones sucesivas recibirán índices secuenciales. Los índices secuenciales se asignarán a través de llamadas de inserción en el mismo AV. Debido a que los valores fi_addr_t devueltos de una llamada de inserción son deterministas, las aplicaciones pueden no necesitar proporcionar los parámetros de salida fi_addr_t a las llamadas de inserción. La excepción es cuando los parámetros fi_addr_t también se usan como entrada para proporcionar autenticación claves o IDs definidos por el
usuario.

fi_av_inser

t

La llamada fi_av_insert inserta cero o más direcciones en un AV. El número de direcciones se especifica a través del parámetro count. El parámetro addr referencia un array de direcciones a insertar en el AV. Las direcciones insertadas en un vector de direcciones deben estar en el mismo formato que se especifica en el campo addr_format de la estructura fi_info proporcionada al abrir el dominio correspondiente. Al usar el formato FI_ADDR_STR, el parámetro addr debe referenciar un array de cadenas (char **)

.

Obsoleto: Para AVs de tipo FI_AV_MAP, una vez que las direcciones insertadas se han mapeado, los valores mapeados se escriben en el buffer referenciado por fi_addr. El buffer fi_addr debe permanecer válido hasta que la inserción en el AV se haya completado y se haya generado un evento a una cola de eventos asociada. El valor del fi_addr devuelto debe considerarse opaco por la aplicación para AVs de tipo FI_AV_MAP. El valor devuelto puede apuntar a una estructura interna o a una codificación específica del proveedor de datos de direccionamiento de bajo nivel, por ejemplo. En este último caso, el uso de FI_AV_MAP puede evitar referencias a memoria durante las operaciones de transferencia de

datos.

Para AVs de tipo FI_AV_TABLE, las direcciones se colocan en la tabla en orden. Una dirección se inserta en el índice más bajo que corresponde a una ubicación de tabla no usada, con los índices comenzando en 0. Es decir, la primera dirección insertada puede referenciarse en el índice 0, la segunda en el índice 1, y así sucesivamente. Cuando se insertan direcciones en una tabla AV, los valores de fi_addr asignados serán índices simples correspondientes a la entrada en la tabla donde se insertó la dirección. Los valores de índice se acumulan a lo largo de llamadas de inserción sucesivas en el orden en que se hacen las llamadas, no necesariamente en el orden en que se completan las

inserciones.

Debido a que las inserciones ocurren en un índice predeterminado, el parámetro fi_addr puede ser NULL. Si fi_addr no es NULL, debe referenciar un array de fi_addr_t, y el buffer debe permanecer válido hasta que la operación de inserción se complete. Tenga en cuenta que si fi_addr es NULL y se solicita operación síncrona sin usar el indicador FI_SYNC_ERR, los fallos individuales de inserción no pueden informarse y la aplicación debe usar otras llamadas, como fi_av_lookup, para averiguar qué direcciones específicas fallaron al

insertarse.

Si el vector de direcciones está configurado con claves de autorización, el parámetro fi_addr puede usarse como entrada para definir las claves de autorización asociadas con las direcciones de punto final que se están insertando. Esto se hace estableciendo el fi_addr a una clave de autorización fi_addr_t generada a partir de fi_av_insert_auth_key y estableciendo el indicador FI_AUTH_KEY. Si el indicador FI_AUTH_KEY no está establecido, las direcciones que se insertan no se asociarán con ninguna clave de autorización. Si una dirección puede o no desasociarse de una clave de autorización es específico del proveedor. Si un proveedor no puede soportar esta desasociación, se devolverá un error. Tras una inserción exitosa con el indicador FI_AUTH_KEY, los fi_addr_t devueltos se mapearán a la dirección de punto final contra las claves de autorización especificadas. Estos fi_addr_t pueden usarse como destino para operaciones de transferencia de datos

locales.

Si el punto final soporta FI_DIRECTED_RECV o FI_TAGGED_DIRECTED_RECV, estos fi_addr_t pueden usarse para restringir los buffers de recepción a una dirección de punto final y clave de autorización

específicas.

Para vectores de direcciones configurados con FI_AV_USER_ID, todos los eventos de destino posteriores correspondientes a la dirección que se está insertando devolverán FI_ADDR_NOTAVAIL hasta que el usuario defina un ID de usuario para este fi_addr_t. Esto se hace usando fi_av_set_user_id

fi_av_insertsvc

La llamada fi_av_insertsvc se comporta de manera similar a fi_av_insert, pero permite a la aplicación especificar los nombres de nodo y servicio, similar a las entradas de fi_getinfo, en lugar de una dirección codificada. Los parámetros de nodo y servicio están definidos igual que en fi_getinfo(3). El nodo debe ser una cadena que corresponda a un nombre de host o dirección de red. La cadena de servicio corresponde a una representación textual de una dirección de transporte. Las aplicaciones también pueden pasar una dirección con formato FI_ADDR_STR como el parámetro de nodo. En tales casos, el parámetro de servicio debe ser NULL. Vea fi_getinfo.3 para detalles sobre el uso de FI_ADDR_STR. Los indicadores soportados son los mismos que para fi_av_insert.

fi_av_insertsym

fi_av_insertsym realiza una inserción simétrica que inserta un rango secuencial de direcciones de nodo y/o de servicio en un AV. El parámetro svccnt indica el número de direcciones de transporte (endpoint) a insertar en el AV para cada dirección de nodo, con el parámetro de servicio especificando la dirección de transporte inicial. Las direcciones de transporte insertadas serán del rango {service, service + svccnt - 1}, inclusive. Todas las direcciones de servicio para un nodo se insertarán antes de que se inserte el siguiente nodo.

El parámetro nodecnt indica el número de direcciones de nodo (red) a insertar en el AV, con el parámetro node especificando la dirección de nodo inicial. Las direcciones de nodo insertadas serán del rango {node, node + nodecnt - 1}, inclusive. Si node es una cadena no numérica, como un nombre de host, debe contener un sufijo numérico si nodecnt > 1.

Como ejemplo, si node = “10.1.1.1”, nodecnt = 2, service = “5000”, y svccnt = 2, las siguientes direcciones serán insertadas en el AV en el orden mostrado: 10.1.1.1:5000, 10.1.1.1:5001, 10.1.1.2:5000, 10.1.1.2:5001. Si node fuera reemplazado por el nombre de host “host10”, las direcciones serían: host10:5000, host10:5001, host11:5000, host11:5001.

El número total de direcciones insertadas será nodecnt x svccnt.

Los indicadores soportados son los mismos que para fi_av_insert.

fi_av_remove

fi_av_remove elimina un conjunto de direcciones de un vector de direcciones. Los valores fi_addr_t correspondientes se invalidan y no pueden usarse en llamadas de transferencia de datos. El comportamiento de operaciones en curso que referencian las direcciones eliminadas es indefinido.

Tenga en cuenta que eliminar una dirección puede no deshabilitar la recepción de datos del endpoint par. fi_av_close limpiará automáticamente cualquier recurso asociado.

Si la dirección que se está eliminó provino de fi_av_insert_auth_key, la dirección solo se eliminará si todos los endpoints, que han sido habilitados contra la clave de autorización correspondiente, han sido cerrados. Si no todos los endpoints están cerrados, se devolverá -FI_EBUSY. Además, el indicador FI_AUTH_KEY debe establecerse al eliminar una clave de autorización fi_addr_t.

fi_av_lookup

Esta llamada devuelve la dirección almacenada en el vector de direcciones que corresponde al fi_addr dado. La dirección devuelta tiene el mismo formato que las almacenadas por el AV. En la entrada, el parámetro addrlen debe indicar el tamaño del búfer addr. Si la dirección real es más grande de lo que cabe en el búfer, será truncada. En la salida, addrlen se establece al tamaño del búfer necesario para almacenar la dirección, que puede ser mayor que el valor de entrada.

fi_rx_addr

Esta función se usa para convertir una dirección de endpoint, devuelta por fi_av_insert, en una dirección que especifica un contexto de recepción de destino. El valor de rx_ctx_bits debe coincidir con el especificado en los atributos del AV para la dirección dada.

Los endpoints conectados que soportan múltiples contextos de recepción, pero no están asociados con vectores de direcciones, deben especificar FI_ADDR_NOTAVAIL para el parámetro fi_addr.

fi_av_straddr

La función fi_av_straddr convierte la dirección proporcionada en una cadena imprimible. La dirección especificada debe tener el mismo formato que las almacenadas por el AV, aunque la dirección en sí no necesita haber sido insertada. En la entrada, el parámetro len debe especificar el tamaño del búfer referenciado por buf. En la salida, addrlen se establece al tamaño del búfer necesario para almacenar la dirección. Este tamaño puede ser mayor que el len de entrada. Si el búfer proporcionado es demasiado pequeño, los resultados serán truncados. fi_av_straddr devuelve un puntero a buf.

fi_av_insert_auth_key

Esta función asocia claves de autorización con un vector de direcciones. Esto requiere que el dominio sea abierto con FI_AV_AUTH_KEY. FI_AV_AUTH_KEY permite que endpoints y regiones de memoria se asocien con claves de autorización del vector de direcciones. Este comportamiento permite que un solo endpoint o región de memoria se asocie con múltiples claves de autorización.

Cuando se habilitan endpoints o regiones de memoria, se configuran con claves de autorización del vector de direcciones en ese momento. Las inserciones posteriores de claves de autorización no se propagarán a endpoints y regiones de memoria ya habilitados.

Los parámetros auth_key y auth_key_size se usan para introducir la clave de autorización en el vector de direcciones. La estructura de la clave de autorización es específica del proveedor. Si auth_key_size no se alinea con la estructura específica del proveedor, se devolverá -FI_EINVAL.

La salida de fi_av_insert_auth_key es un manejador fi_addr_t de clave de autorización que representa todas las direcciones de endpoint contra esta clave de autorización específica. Para todas las operaciones, incluyendo vector de direcciones, registro de memoria y transferencias de datos, que puedan aceptar un fi_addr_t de clave de autorización como entrada, se debe especificar el indicador FI_AUTH_KEY. De lo contrario, el fi_addr_t será tratado como un fi_addr_t devuelto por fi_av_insert y funciones relacionadas.

Para endpoints habilitados con FI_DIRECTED_RECV, los fi_addr_t de clave de autorización pueden usarse para restringir los mensajes entrantes a solo direcciones de endpoint dentro de la clave de autorización. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_recvmsg y fi_trecvmsg.

Para dominios habilitados con FI_DIRECTED_RECV, los fi_addr_t de clave de autorización pueden usarse para restringir el acceso a la región de memoria a solo direcciones de endpoint dentro de la clave de autorización. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_mr_regattr.

Estos fi_addr_t de clave de autorización pueden usarse más tarde como entrada para funciones de inserción de dirección de endpoint para generar un fi_addr_t para una dirección de endpoint y clave de autorización específicas. Esto requerirá pasar el indicador FI_AUTH_KEY a fi_av_insert y funciones relacionadas.

Para vectores de direcciones configurados con FI_AV_USER_ID y endpoints con FI_SOURCE_ERR, todos los eventos de error FI_EADDRNOTAVAIL subsecuentes devolverán FI_ADDR_NOTAVAIL hasta que el usuario defina un ID de usuario para este fi_addr_t de clave de autorización. Esto se hace usando fi_av_set_user_id.

Para vectores de direcciones configurados sin FI_AV_USER_ID y endpoints con FI_SOURCE_ERR, todos los eventos de error FI_EADDRNOTAVAIL subsecuentes devolverán el manejador fi_addr_t de clave de autorización.

Los indicadores están reservados para uso futuro y deben ser 0.
