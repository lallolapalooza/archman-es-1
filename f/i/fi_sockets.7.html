NOMBRE

fi_sockets - El Proveedor de Sockets de Fabric

DESCRIPCIÓN GENERAL

El proveedor de sockets está siendo desaprobado en favor de los proveedores tcp, udp y utility. Se realizará un trabajo mínimo adicional en el proveedor de sockets. La mayoría de las aplicaciones deberían usar el proveedor tcp en su lugar.

El proveedor de sockets es un proveedor de propósito general que puede ser utilizado en cualquier sistema que soporte sockets TCP. El proveedor no tiene la intención de proporcionar mejoras de rendimiento sobre sockets TCP regulares, sino permitir a los desarrolladores escribir, probar y depurar código de aplicación incluso en plataformas que no tienen hardware de fabricación de alto rendimiento. El proveedor de sockets soporta todos los requisitos e interfaces del proveedor libfabric.

CARACTERÍSTICAS SOPORTADAS

El proveedor de sockets soporta todas las características definidas para la API de libfabric. Las características clave incluyen:

Tipos de endpoints
El proveedor soporta todos los tipos de endpoints: FI_EP_MSG, FI_EP_RDM y FI_EP_DGRAM.
Capacidades de endpoints
La siguiente interfaz de transferencia de datos es soportada para todos los tipos de endpoints: fi_msg. Adicionalmente, estas interfaces son soportadas para endpoints confiables (FI_EP_MSG y FI_EP_RDM): fi_tagged, fi_atomic y fi_rma.
Modos
El proveedor de sockets soporta todos los modos operacionales, incluyendo FI_CONTEXT y FI_MSG_PREFIX.
Progreso
El proveedor de sockets soporta tanto FI_PROGRESS_AUTO como FI_PROGRESS_MANUAL, con un valor por defecto a auto. Cuando el progreso se establece a auto, un hilo de fondo se ejecuta para asegurar que se progresa en las solicitudes asíncronas.

LIMITACIONES

El proveedor de sockets intenta emular todo el conjunto de API, incluyendo todas las opciones definidas. Para soportar el desarrollo en una amplia gama de sistemas, se implementa sobre sockets TCP. Como resultado, los números de rendimiento son más bajos en comparación con otros proveedores implementados sobre fabric de alta velocidad, y más bajos de lo que una aplicación podría ver al implementarse directamente a sockets.

No soporta el formato de dirección FI_ADDR_STR.

PARÁMETROS DE TIEMPO DE EJECUCIÓN

El proveedor de sockets verifica las siguientes variables de entorno -

FI_SOCKETS_PE_WAITTIME
Un valor entero que especifica cuántos milisegundos girar mientras se espera el progreso en el modo FI_PROGRESS_AUTO.
FI_SOCKETS_CONN_TIMEOUT
Un valor entero que especifica cuántos milisegundos esperar para el establecimiento de una conexión.
FI_SOCKETS_MAX_CONN_RETRY
Un valor entero que especifica el número de reintentos de conexión de socket antes de informar como fallo.
FI_SOCKETS_DEF_CONN_MAP_SZ
Un entero para especificar el tamaño por defecto del mapa de conexión.
FI_SOCKETS_DEF_AV_SZ
Un entero para especificar el tamaño por defecto del vector de direcciones.
FI_SOCKETS_DEF_CQ_SZ
Un entero para especificar el tamaño por defecto de la cola de completado.
FI_SOCKETS_DEF_EQ_SZ
Un entero para especificar el tamaño por defecto de la cola de eventos.
FI_SOCKETS_DGRAM_DROP_RATE
Un valor entero para especificar la tasa de caída de paquetes de datagrama cuando el endpoint es FI_EP_DGRAM. Esto es solo para fines de depuración.
FI_SOCKETS_PE_AFFINITY
Si se especifica, el hilo de progreso se une a los rangos indicados de ID(s) de procesador virtual de Linux. Esta opción actualmente no está soportada en OS X. El uso es: id_inicio[-id_fin[:paso]][,].
FI_SOCKETS_KEEPALIVE_ENABLE
Un booleano para habilitar el soporte de keepalive.
FI_SOCKETS_KEEPALIVE_TIME
Un entero para especificar el tiempo de inactividad en segundos antes de enviar la primera sonda de keepalive. Solo relevante si FI_SOCKETS_KEEPALIVE_ENABLE está habilitado.
FI_SOCKETS_KEEPALIVE_INTVL
Un entero para especificar el tiempo en segundos entre sondas de keepalive individuales. Solo relevante si FI_SOCKETS_KEEPALIVE_ENABLE está habilitado.
FI_SOCKETS_KEEPALIVE_PROBES
Un entero para especificar el número máximo de sondas de keepalive enviadas antes de desconectar. Solo relevante si FI_SOCKETS_KEEPALIVE_ENABLE está habilitado.
FI_SOCKETS_IFACE
El prefijo o el nombre de la interfaz de red (por defecto: cualquiera)

TRABAJOS A GRAN ESCALA

Para ejecuciones a gran escala, se pueden usar estas variables de entorno para establecer los parámetros por defecto, por ejemplo, el tamaño del vector de direcciones (AV), la cola de completado (CQ), el mapa de conexión, etc., que satisfacen los requisitos del benchmark particular. Los parámetros recomendados para ejecuciones a gran escala son FI_SOCKETS_MAX_CONN_RETRY, FI_SOCKETS_DEF_CONN_MAP_SZ, FI_SOCKETS_DEF_AV_SZ, FI_SOCKETS_DEF_CQ_SZ, FI_SOCKETS_DEF_EQ_SZ.
