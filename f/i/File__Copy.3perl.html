N

El módulo File::Copy proporciona dos funciones básicas, "copy" y "move", que son útiles para obtener el contenido de un archivo de un lugar a

otro.

py
La función "copy" toma dos parámetros: un archivo del cual copiar y un archivo al cual copiar. Cualquiera de los argumentos puede ser una cadena, una referencia a FileHandle o un glob de FileHandle. Obviamente, si el primer argumento es algún tipo de manejador de archivo, se leerá de él, y si es un nombre de archivo, se abrirá para lectura. Del mismo modo, el segundo argumento se escribirá. Si el segundo argumento no existe pero el directorio padre sí existe, entonces se creará. Intentar copiar un archivo a un directorio inexistente es un error. Intentar copiar un archivo sobre sí mismo también es un error. "copy" no sobrescribirá archivos de solo lectura.

Si el destino (segundo argumento) ya existe y es un directorio, y el origen (primer argumento) no es un manejador de archivo, entonces el archivo de origen se copiará en el directorio especificado por el destino, usando el mismo nombre base que el archivo de origen. Es un error tener un manejador de archivo como origen cuando el destino es un

directorio.

Tenga en cuenta que pasar archivos como manejadores en lugar de nombres puede llevar a la pérdida de información en algunos sistemas operativos; se recomienda que use nombres de archivo siempre que sea posible. Los archivos se abren en modo binario cuando corresponde. Para obtener un comportamiento consistente al copiar de un manejador de archivo a un archivo, use "binmode" en el manejador de

archivo.

Un tercer parámetro opcional se puede usar para especificar el tamaño del búfer usado para la copia. Este es el número de bytes del primer archivo, que se mantendrán en memoria en cualquier momento dado, antes de ser escritos en el segundo archivo. El tamaño del búfer predeterminado depende del archivo, pero generalmente será todo el archivo (hasta 2MB), o 1k para manejadores de archivo que no referencian archivos (p. ej.,

sockets).

Puede usar la sintaxis "use File::Copy "cp"" para acceder al alias "cp" de esta función. La sintaxis es exactamente la misma. El comportamiento es casi el mismo también: a partir de la versión 2.15, "cp" preservará los bits de permiso del archivo de origen como la utilidad de shell cp(1) haría con las opciones predeterminadas, mientras que "copy" usa los permisos predeterminados para el archivo de destino (lo que puede depender del "umask" del proceso, la propiedad del archivo, los ACL heredados, etc.). Es decir, si el archivo de destino ya existe, "cp" dejará sus permisos sin cambios; de lo contrario, los permisos se toman del archivo de origen y se modifican con el "umask". Si ocurre un error al establecer los permisos, "cp" devolverá 0, independientemente

La función "move" también toma dos parámetros: el nombre actual y el nombre previsto del archivo a mover. Si el destino ya existe y es un directorio, y el origen no es un directorio, entonces el archivo de origen se renombrará en el directorio especificado por el destino.

Si es posible, move() simplemente renombrará el archivo. De lo contrario, copia el archivo a la nueva ubicación y elimina el original. Si ocurre un error durante este proceso de copiar-y-eliminar, es posible que quede con una copia (posiblemente parcial) del archivo con el nombre de

File::Copy también proporciona la rutina "syscopy", que copia el archivo especificado en el primer parámetro al archivo especificado en el segundo parámetro, preservando los atributos específicos del SO y la estructura del archivo. Para sistemas Unix, esto es equivalente a la simple rutina "copy", que no preserva los atributos específicos del SO. Para sistemas VMS, esto llama a la rutina "rmscopy" (ver abajo). Para sistemas OS/2 esto llama directamente al XSUB "syscopy". Para sistemas Win32, esto llama a "Win32::CopyFile".

Comportamiento especial si "syscopy" está definido (OS/2,

VMS y Win32):

Si ambos argumentos de "copy" no son manejadores de archivo, entonces "copy" realizará una "copia de sistema" del archivo de entrada a un nuevo archivo de salida, para preservar los atributos del archivo, la estructura de archivo indexada, etc. El parámetro de tamaño del búfer se ignora. Si cualquiera de los argumentos de "copy" es un manejador de un archivo abierto, entonces los datos se copian usando operadores de Perl, y no se hace ningún esfuerzo para preservar los atributos del archivo o la estructura de

registro.

La rutina de copia de sistema también puede llamarse directamente bajo VMS y OS/2 como "File::Copy::syscopy" (o bajo VMS como "File::Copy::rmscopy", que es la rutina que hace el trabajo real para

syscopy)

El primer y segundo argumentos pueden ser cadenas, typeglobs, referencias a typeglob u objetos que hereden de IO::Handle; se usan en todos los casos para obtener el filespec de los archivos de entrada y salida, respectivamente. El nombre y tipo del archivo de entrada se usan como valores predeterminados para el archivo de salida, si es necesario.

Siempre se crea una nueva versión del archivo de salida, que hereda la estructura y los atributos RMS del archivo de entrada, excepto por el propietario y las protecciones (y posiblemente las marcas de tiempo; ver abajo). Todos los datos del archivo de entrada se copian al archivo de salida; si cualquiera de los dos primeros parámetros de "rmscopy" es un manejador de archivo, su posición no cambia. (Tenga en cuenta que esto significa que un manejador de archivo que apunta al archivo de archivo de salida se asociará con una versión antigua de ese archivo después de que "rmscopy" retorne, no con la versión recién

creada.)

El tercer parámetro es un indicador entero, que le dice a "rmscopy" cómo manejar las marcas de tiempo. Si es < 0, ninguna de las marcas de tiempo del archivo de entrada se propaga al archivo de salida. Si es > 0, entonces se interpreta como una máscara de bits: si el bit 0 (el LSB) está establecido, entonces se propagan las marcas de tiempo distintas de la fecha de revisión; si el bit 1 está establecido, se propaga la fecha de revisión. Si el tercer parámetro de "rmscopy" es 0, entonces se comporta mucho como el comando DCL COPY: si el nombre o tipo de el archivo de salida se especificó explícitamente, entonces no se propagan marcas de tiempo, pero si se tomaron implícitamente del filespec de entrada, entonces se propagan todas las marcas de tiempo distintas de la fecha de revisión. Si este parámetro no se proporciona, su valor predeterminado

es 0.

"rmscopy" es específico de VMS y no se puede exportar; debe referenciarse por su nombre completo,

p. ej.:

$!;
