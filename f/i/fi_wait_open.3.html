NOMBRE

fi_poll - Operaciones de sondeo y conjuntos de espera (obsoleto)

fi_poll_open / fi_close (obsoleto)
Abrir/cerrar un conjunto de sondeo
fi_poll_add / fi_poll_del (obsoleto)
Añadir/eliminar una cola de finalización o un contador a/desde un conjunto de sondeo.
fi_poll (obsoleto)
Sondear el progreso y los eventos en múltiples colas de finalización y contadores.
fi_wait_open / fi_close (obsoleto)
Abrir/cerrar un conjunto de espera
fi_wait (obsoleto)
Espera a que uno o más objetos de espera en un conjunto sean señalizados.
fi_trywait
Indica cuándo es seguro bloquearse en objetos de espera usando llamadas nativas del SO.
fi_control
Controla la operación o los atributos del conjunto de espera.

SINOPSIS

#include <rdma/fi_domain.h>
int fi_poll_open(struct fid_domain *domain, struct fi_poll_attr *attr,
    struct fid_poll **pollset);
int fi_close(struct fid *pollset);
int fi_poll_add(struct fid_poll *pollset, struct fid *event_fid,
    uint64_t flags);
int fi_poll_del(struct fid_poll *pollset, struct fid *event_fid,
    uint64_t flags);
int fi_poll(struct fid_poll *pollset, void **context, int count);
int fi_wait_open(struct fid_fabric *fabric, struct fi_wait_attr *attr,
    struct fid_wait **waitset);
int fi_close(struct fid *waitset);
int fi_wait(struct fid_wait *waitset, int timeout);
int fi_trywait(struct fid_fabric *fabric, struct fid **fids, size_t count);
int fi_control(struct fid *waitset, int command, void *arg);

ARGUMENTOS

fabric
Proveedor de fabric
domain
Dominio de recursos
pollset
Conjunto de sondeo de eventos
waitset
Conjunto de objetos de espera
attr
Atributos del conjunto de sondeo o de espera
context
En caso de éxito, un array de valores de contexto de usuario asociados con las colas de finalización o los contadores.
fids
Un array de descriptores de fabric, cada uno asociado con un objeto de espera nativo.
count
Número de entradas en el array context o fids.
timeout
Tiempo de espera por una señal, en milisegundos.
command
Comando de la operación de control a realizar en el conjunto de espera.
arg
Argumento de control opcional.

DESCRIPCIÓN

fi_poll_open (obsoleto)

fi_poll_open crea un nuevo conjunto de sondeo. Un conjunto de sondeo permite un método optimizado para progresar operaciones asíncronas a través de múltiples colas de finalización y contadores y comprobar sus finalizaciones.

Un conjunto de sondeo se define con los siguientes atributos.

struct fi_poll_attr {
    uint64_t             flags;     /* banderas de operación */
};
flags
Banderas que establecen la operación predeterminada del conjunto de sondeo. El uso de este campo está reservado y debe establecerse a 0 por el llamador.

fi_close (obsoleto)

La llamada fi_close libera todos los recursos asociados con un conjunto de sondeo. El conjunto de sondeo no debe estar asociado con ningún otro recurso antes de ser cerrado, de lo contrario la llamada devolverá -FI_EBUSY.

fi_poll_add (obsoleto)

Asocia una cola de finalización o un contador con un conjunto de sondeo.

fi_poll_del (obsoleto)

Elimina una cola de finalización o un contador de un conjunto de sondeo.

fi_poll (obsoleto)

Progresa todas las colas de finalización y contadores asociados con un conjunto de sondeo y comprueba eventos. Si podrían haber ocurrido eventos, se devuelven los contextos asociados con las colas de finalización y/o los contadores. Las colas de finalización devolverán su contexto si no están vacías. El contexto asociado con un contador se devolverá si el valor de éxito o el valor de error del contador han cambiado desde la última vez que se llamó a fi_poll, fi_cntr_set o fi_cntr_add. El número de contextos está limitado al tamaño del array de contextos, indicado por el parámetro count.

Tenga en cuenta que fi_poll solo indica que podrían estar disponibles eventos. En algunos casos, los proveedores podrían consumir esos eventos internamente, para impulsar el progreso, por ejemplo. Esto puede resultar en que fi_poll devuelva falsos positivos. Las aplicaciones deberían impulsar su progreso basándose en los resultados de leer eventos de una cola de finalización o leer valores de contadores. La función fi_poll devolverá siempre todas las colas de finalización y contadores que tengan nuevos eventos.

fi_wait_open (obsoleto)

fi_wait_open asigna un nuevo conjunto de espera. Un conjunto de espera permite un método optimizado de espera de eventos a través de múltiples colas de finalización y contadores. Donde sea posible, un conjunto de espera usa un único objeto de espera subyacente que se señaliza cuando ocurre una condición especificada en una cola de finalización o un contador asociado.

Las propiedades y el comportamiento de un conjunto de espera se definen por struct fi_wait_attr.

struct fi_wait_attr {
    enum fi_wait_obj     wait_obj;  /* objeto de espera solicitado */
    uint64_t             flags;     /* banderas de operación */
};
wait_obj
Los conjuntos de espera se asocian con objeto(s) de espera específicos. Los objetos de espera permiten a las aplicaciones bloquearse hasta que el objeto de espera sea señalizado, indicando que hay un evento disponible para leer. Los siguientes valores pueden usarse para especificar el tipo de objeto de espera asociado con un conjunto de espera: FI_WAIT_UNSPEC, FI_WAIT_FD, FI_WAIT_MUTEX_COND (obsoleto) y FI_WAIT_YIELD.
- FI_WAIT_UNSPEC
Especifica que el usuario solo esperará en el conjunto de espera usando llamadas de interfaz de fabric, como fi_wait. En este caso, el proveedor subyacente puede seleccionar el objeto de espera más apropiado o de mayor rendimiento disponible, incluyendo mecanismos de espera personalizados. No se garantiza que las aplicaciones que seleccionan FI_WAIT_UNSPEC puedan recuperar el objeto de espera subyacente.
- FI_WAIT_FD
Indica que el conjunto de espera debería usar un único descriptor de archivo como su mecanismo de espera, tal como se expone a la aplicación. Internamente, esto podría requerir el uso de epoll para soportar la espera en un único descriptor de archivo. Los objetos de espera de descriptor de archivo deben ser utilizables en las rutinas POSIX select(2) y poll(2), y Linux epoll(7) (si están disponibles). El proveedor señaliza un objeto de espera FD marcándolo como legible o con un error.
- FI_WAIT_MUTEX_COND (obsoleto)
Especifica que el conjunto de espera debería usar un mutex pthread y una variable de condición como objeto de espera.
- FI_WAIT_POLLFD
Esta opción es similar a FI_WAIT_FD, pero permite que el mecanismo de espera use múltiples descriptores de archivo como su mecanismo de espera, tal como lo ve la aplicación. El uso de FI_WAIT_POLLFD puede eliminar la necesidad de usar epoll para abstraer la necesidad de comprobar múltiples descriptores de archivo al esperar eventos.
