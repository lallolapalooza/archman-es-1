Operaciones Atómicas

Se definen las siguientes operaciones atómicas. Una operación atómica a menudo actúa sobre un valor objetivo en el búfer de memoria remota y un valor fuente proporcionado con la función atómica. También puede transportar datos fuente para reemplazar el valor objetivo en las operaciones de comparación e intercambio. Se proporciona una descripción conceptual de cada operación.

FI_MIN
Mínimo
if (buf[i] < addr[i])
    addr[i] = buf[i]
FI_MAX
Máximo
if (buf[i] > addr[i])
    addr[i] = buf[i]
FI_SUM
Suma
addr[i] = addr[i] + buf[i]
FI_PROD
Producto
addr[i] = addr[i] * buf[i]
FI_LOR
OR lógico
addr[i] = (addr[i] || buf[i])
FI_LAND
AND lógico
addr[i] = (addr[i] && buf[i])
FI_BOR
OR a nivel de bits
addr[i] = addr[i] | buf[i]
FI_BAND
AND a nivel de bits
addr[i] = addr[i] & buf[i]
FI_LXOR
OR exclusivo (XOR) lógico
addr[i] = ((addr[i] && !buf[i]) || (!addr[i] && buf[i]))
FI_BXOR
OR exclusivo (XOR) a nivel de bits
addr[i] = addr[i] ^ buf[i]
FI_ATOMIC_READ
Lee datos de forma atómica
result[i] = addr[i]
FI_ATOMIC_WRITE
Escribe datos de forma atómica
addr[i] = buf[i]
FI_CSWAP
Compara valores y si son iguales, los intercambia con los datos
if (compare[i] == addr[i])
    addr[i] = buf[i]
FI_CSWAP_NE
Compara valores y si son diferentes, los intercambia con los datos
if (compare[i] != addr[i])
    addr[i] = buf[i]
FI_CSWAP_LE
Compara valores y si son menores o iguales, los intercambia con los datos
if (compare[i] <= addr[i])
    addr[i] = buf[i]
FI_CSWAP_LT
Compara valores y si es menor, los intercambia con los datos
if (compare[i] < addr[i])
    addr[i] = buf[i]
FI_CSWAP_GE
Compara valores y si son mayores o iguales, los intercambia con los datos
if (compare[i] >= addr[i])
    addr[i] = buf[i]
FI_CSWAP_GT
Compara valores y si es mayor, los intercambia con los datos
if (compare[i] > addr[i])
    addr[i] = buf[i]
FI_MSWAP
Intercambia bits enmascarados con datos
addr[i] = (buf[i] & compare[i]) | (addr[i] & ~compare[i])
FI_DIFF
Calcula la diferencia
addr[i] = addr[i] - buf[i]

Funciones Atómicas Base

Las funciones atómicas base – fi_atomic, fi_atomicv, fi_atomicmsg – se utilizan para transmitir datos a un nodo remoto, donde la operación atómica especificada se realiza sobre los datos objetivo. El resultado de una función atómica base se almacena en la región de memoria remota. La principal diferencia entre las funciones atómicas es el número y el tipo de parámetros que aceptan como entrada. De lo contrario, realizan la misma función general.

La llamada fi_atomic transfiere los datos contenidos en el búfer de datos especificado por el usuario a un nodo remoto. Para puntos de extremo sin conexión, el punto de extremo de destino se especifica a través del parámetro dest_addr. A menos que el punto de extremo se haya configurado de manera diferente, el búfer de datos pasado a fi_atomic no debe ser manipulado por la aplicación hasta que la llamada fi_atomic se complete de forma asíncrona. El búfer objetivo de una operación atómica base debe permitir el acceso de lectura y/o escritura remota, según corresponda.

La llamada fi_atomicv agrega soporte para una lista de recopilación/dispersión a fi_atomic. fi_atomicv transfiere el conjunto de búferes de datos referenciados por el parámetro ioc al nodo remoto para su procesamiento.

La llamada fi_inject_atomic es una versión optimizada de fi_atomic. La función fi_inject_atomic se comporta como si se hubiera establecido la marca de transferencia FI_INJECT, y no FI_COMPLETION. Es decir, el búfer de datos está disponible para su reutilización inmediatamente al regresar de fi_inject_atomic, y no se generará ningún evento de finalización para esta operación atómica. El evento de finalización se suprimirá incluso si el punto de extremo no se ha configurado con FI_SELECTIVE_COMPLETION. Consulte la discusión sobre las marcas a continuación para obtener más detalles. El tamaño del mensaje solicitado que se puede utilizar con fi_inject_atomic está limitado por inject_size.

La llamada fi_atomicmsg admite operaciones atómicas en puntos de extremo conectados y sin conexión, con la capacidad de controlar la operación atómica por llamada mediante el uso de marcas. La función fi_atomicmsg toma una estructura fi_msg_atomic como entrada.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* lista de recopilación/dispersión local */
    void                **desc;   /* descriptores de acceso local */
    size_t              iov_count;/* # de elementos en ioc */
    const void          *addr;    /* dirección de punto de extremo opcional */
    const struct fi_rma_ioc *rma_iov; /* SGL remota */
    size_t              rma_iov_count;/* # de elementos en SGL remota */
    enum fi_datatype    datatype; /* tipo de dato del operando */
    enum fi_op          op;       /* operación atómica */
    void                *context; /* contexto definido por el usuario */
    uint64_t            data;     /* datos opcionales */
};
struct fi_ioc {
    void        *addr;    /* dirección local */
    size_t      count;    /* # de operandos objetivo */
};
struct fi_rma_ioc {
    uint64_t    addr;     /* dirección objetivo */
    size_t      count;    /* # de operandos objetivo */
    uint64_t    key;      /* clave de acceso */
};

La siguiente lista de operaciones atómicas se pueden utilizar con operaciones atómicas base: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR y FI_ATOMIC_WRITE.

Funciones Fetch-Atómicas

Las funciones fetch-atómicas – fi_fetch_atomic, fi_fetch_atomicv y fi_fetch atomicmsg – se comportan de manera similar a la función atómica base equivalente. La diferencia entre las llamadas fetch atómicas y las atómicas base es que las rutinas fetch atómicas devuelven el valor inicial que se almacenó en el objetivo al usuario. El valor inicial se lee en el búfer de resultados proporcionado por el usuario. El búfer objetivo de las operaciones fetch-atómicas debe estar habilitado para acceso de lectura remota.

La siguiente lista de operaciones atómicas se pueden utilizar con operaciones fetch atómicas: FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ y FI_ATOMIC_WRITE.

Para las operaciones FI_ATOMIC_READ, el operando del búfer fuente (por ejemplo, el parámetro buf de fi_fetch_atomic) se ignora y puede ser NULL. Los resultados se escriben en el búfer de resultados.

Funciones Compare-Atómicas

='permalink' href='#Compare-Atomic_Functions'>Funciones de comparación atómica

Las funciones de comparación atómica – fi_compare_atomic, fi_compare_atomicv, y fi_compare atomicmsg – se utilizan para operaciones que requieren comparar los datos de destino contra un valor antes de realizar una operación de intercambio. Las funciones de comparación atómica soportan: FI_CSWAP, FI_CSWAP_NE, FI_CSWAP_LE, FI_CSWAP_LT, FI_CSWAP_GE, FI_CSWAP_GT, y FI_MSWAP.

Funciones de validación atómica

Las funciones de validación atómica – fi_atomicvalid, fi_fetch_atomicvalid, y fi_compare_atomicvalid – indican qué operaciones soporta el proveedor local. Las operaciones necesarias que no son soportadas por el proveedor deben ser emuladas por la aplicación. Cada llamada de validación corresponde a un conjunto de funciones atómicas. fi_atomicvalid verifica si un proveedor soporta una operación atómica base específica para un dado tipo de datos y operación. fi_fetch_atomicvalid indica si un proveedor soporta una operación fetch-atomic específica para un dado tipo de datos y operación. Y fi_compare_atomicvalid verifica si un proveedor soporta una operación compare-atomic especificada para un dado tipo de datos y operación.

Si una operación es soportada, una llamada de validación atómica retornará 0, junto con un conteo de unidades de datos atómicos con los que una sola llamada de función operará.

Consultar atributos atómicos

La llamada fi_query_atomic actúa como una operación de validación atómica mejorada (ver las definiciones de las funciones de validación atómica arriba). Se provee, en parte, para extensibilidad futura. La operación de consulta reporta qué operaciones atómicas son soportadas por el dominio, para puntos de conexión adecuadamente configurados.

El comportamiento de fi_query_atomic se ajusta basado en el parámetro flags. Si flags es 0, entonces la operación reporta los atributos atómicos soportados para operaciones atómicas base, similar a fi_atomicvalid para puntos de conexión. Si flags tiene el bit FI_FETCH_ATOMIC establecido, la operación se comporta similar a fi_fetch_atomicvalid. De manera similar, el bit de flag FI_COMPARE_ATOMIC resulta en que la consulta actúe como fi_compare_atomicvalid. Los bits FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC no pueden estar ambos establecidos.

Si el bit FI_TAGGED está establecido, el proveedor indicará si soporta operaciones atómicas a búfers de recepción etiquetados. El bit FI_TAGGED puede usarse por sí mismo, o en conjunto con los flags FI_FETCH_ATOMIC y FI_COMPARE_ATOMIC.

La salida de fi_query_atomic es struct fi_atomic_attr:

struct fi_atomic_attr {
    size_t count;
    size_t size;
};

El campo de atributo count está definido como para las llamadas de validación atómica. El campo size indica el tamaño en bytes del tipo de datos atómico. El campo size es útil para tipos de datos que pueden diferir en tamaños basado en la plataforma o compilador, como FI_LONG_DOUBLE.

Completaciones

Las operaciones atómicas completadas son reportadas al iniciador de la solicitud a través de una cola de completaciones o contador asociado. Cualquier contexto proporcionado por el usuario especificado con la solicitud será retornado como parte de cualquier evento de completación escrito a una CQ. Ver fi_cq para detalles de eventos de completación.

Cualquier resultado retornado al iniciador como parte de una operación atómica estará disponible antes de que se genere un evento de completación. Esto será verdadero incluso si la semántica de completación solicitada provee una garantía más débil. Es decir, las operaciones fetch atómicas tienen semánticas FI_DELIVERY_COMPLETE. Las completaciones generadas para otros tipos de operaciones atómicas indican que es seguro reutilizar los búfers de datos de origen.

Cualquier actualización a los datos en el destino de una operación atómica será visible a los agentes (procesos CPU, NICs y otros dispositivos) en el nodo destino antes de que ocurra uno de los siguientes. Si la operación atómica genera un evento de completación o actualiza un contador de completación en el punto de conexión destino, los resultados estarán disponibles antes de la notificación de completación. Después de procesar una completación para la atómica, si el iniciador envía una transferencia entre los mismos puntos de conexión que genera una completación en el destino, los resultados estarán disponibles antes del evento de la transferencia posterior. O, si una transferencia de datos cercada (fenced) del iniciador sigue a la solicitud atómica, los resultados estarán disponibles antes de una completación en el destino para la transferencia cercada.

La corrección de las operaciones atómicas en una región de memoria de destino está garantizada solo cuando son realizadas por un solo actor para una ventana de tiempo dada. Un actor se define como un solo dominio libfabric en el destino (identificado por el nombre del dominio, y no una instancia abierta de ese dominio), un complejo CPU coherente, u otro dispositivo (ej. GPU) capaz de realizar operaciones atómicas en la memoria de destino. Los resultados de operaciones atómicas realizadas por múltiples agentes simultáneamente son indefinidos. Por ejemplo, emitir operaciones atómicas basadas en CPU a una región de destino que está siendo actualizada concurrentemente por atómicas basadas en NIC puede dejar los datos de la región en un estado desconocido. Los resultados de las operaciones atómicas de un primer actor deben ser visibles a un segundo actor antes de que el segundo actor emita sus propias atómicas.

FLAGS

Las llamadas fi_atomicmsg, fi_fetch_atomicmsg, y fi_compare_atomicmsg permiten al usuario especificar flags que pueden cambiar la operación de transferencia de datos predeterminada. Los flags especificados con operaciones de mensaje atómico anulan la mayoría de los flags previamente configurados con el punto de conexión, excepto donde se indique (ver fi_control). La siguiente lista de flags es utilizable con llamadas de mensaje atómico.

FI_COMPLETION
Indica que una entrada de completación debe ser generada para la operación especificada. El punto de conexión debe estar vinculado a una cola de completaciones con FI_SELECTIVE_COMPLETION que corresponda a la operación especificada, o este flag es ignorado.
FI_MORE
Indica que el usuario tiene solicitudes adicionales que serán inmediatamente publicadas después de que la llamada actual retorne. El uso de este flag puede mejorar el rendimiento al permitir al proveedor optimizar su acceso al hardware de la fabric.
FI_INJECT
Indica que el control de los búfers de datos constantes debe ser retornado al usuario inmediatamente después de que la llamada retorne, incluso si la operación es manejada de forma asíncrona. Esto puede requerir que la implementación subyacente del proveedor copie los datos en un búfer local y transfiera desde ese búfer. Los búfers de datos constantes se refiere a cualquier búfer de datos o iovec usado por las APIs atómicas que están marcados como `const'. Los búfers no constantes o de salida no son afectados por este flag y pueden ser accedidos por el proveedor en cualquier momento hasta que la operación haya completado. Este flag solo puede usarse con mensajes más pequeños que inject_size.
FI_FENCE
Aplica a transmisiones. Indica que la operación solicitada, también conocida como la operación cercada (fenced), y cualquier operación publicada después de la operación cercada serán diferidas hasta que todas las operaciones previas dirigidas al mismo punto de conexión par hayan completado. Las operaciones publicadas después del cercado verán y/o reemplazarán los resultados de cualquier operación iniciada antes de la operación cercada.

El ordenamiento de operaciones comenzando en la publicación de la operación cercada (inclusivo) hasta la publicación de una operación cercada posterior (exclusivo) es controlado por la semántica de ordenamiento del punto de conexión.

FI_TAGGED
Especifica que el destino de la operación atómica es un búfer de recepción etiquetado en lugar de un búfer RMA. Cuando un búfer etiquetado es la región de memoria destino, el parámetro addr se usa como un desplazamiento en bytes basado en 0 dentro del búfer etiquetado, con el parámetro key especificando la etiqueta.

VALOR DE RETORNO

Retorna 0 en éxito. En error, se retorna un valor negativo correspondiente a fabric errno. Los valores de fabric errno están definidos en rdma/fi_errno.h.

ERRORES

-FI_EAGAIN
Ver fi_msg(3) para una descripción detallada del manejo de FI_EAGAIN.
-FI_EOPNOTSUPP
La operación atómica solicitada no es soportada en este punto de conexión.
-FI_EMSGSIZE
El número de operaciones atómicas en una sola solicitud excede el soportado por el proveedor subyacente.

NOTAS

Las operaciones atómicas operan sobre un arreglo de valores de un tipo de datos específico. La atomicidad solo está garantizada para cada operación de tipo de datos, no a través de todo el arreglo. El siguiente pseudocódigo demuestra esta operación para una escritura atómica de 64 bits sin signo. ATOMIC_WRITE_U64 es una macro dependiente de la plataforma que escribe atómicamente 8 bytes a una ubicación de memoria alineada.

fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]);
}

El número de elementos del arreglo con los que operar se especifica a través de un parámetro count. Este debe estar entre 1 y el máximo retornado a través de la operación de validación relevante, inclusivo. La operación solicitada y el tipo de datos también deben ser válidos para el proveedor dado.

El ordenamiento de operaciones atómicas llevadas como parte de diferentes mensajes de solicitud está sujeto a las definiciones de ordenamiento de mensajes y datos asignadas a los puntos de conexión de transmisión y recepción. Tanto el ordenamiento de mensajes como el de datos se requieren si los resultados de dos operaciones atómicas a los mismos búfers de memoria deben reflejar la segunda operación actuando sobre los resultados de la primera. Ver fi_endpoint(3) para más detalles y restricciones de tamaño de mensaje.
