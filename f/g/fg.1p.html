FG(1P) Manual del Programador POSIX FG(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux) o la interfaz puede no estar implementada en Linux.

NOMBRE

fg — ejecutar trabajos en primer plano

SINOPSIS

fg [id_trabajo]

DESCRIPCIÓN

Si el control de trabajos está habilitado (ver la descripción de set -m), la utilidad fg moverá un trabajo en segundo plano del entorno actual (ver Sección 2.12, Entorno de Ejecución del Shell) al primer plano.

El uso de fg para colocar un trabajo en primer plano eliminará su ID de proceso de la lista de aquellos ``conocidos en el entorno de ejecución del shell actual''; ver Sección 2.9.3.1, Ejemplos.

OPCIONES

Ninguna.

OPERANDOS

Se soportará el siguiente operando:

id_trabajo
Especifica el trabajo que se ejecutará como trabajo en primer plano. Si no se proporciona un operando id_trabajo, se utilizará el id_trabajo del trabajo que fue suspendido más recientemente, colocado en segundo plano o ejecutado como trabajo en segundo plano. El formato de id_trabajo se describe en el volumen de Definiciones Base de POSIX.1-2017, Sección 3.204, ID de Trabajo de Control de Trabajos.

ENTRADA ESTÁNDAR

No se utiliza.

FICHEROS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de fg:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Ver el volumen de Definiciones Base de POSIX.1-2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en contraposición a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRÓNOS

Predeterminado.

SALIDA ESTÁNDAR

La utilidad fg escribirá la línea de comandos del trabajo en la salida estándar en el siguiente formato:

"%s\n", <comando>

ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

FICHEROS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Si el control de trabajos está deshabilitado, la utilidad fg saldrá con un error y ningún trabajo se colocará en primer plano.

Las siguientes secciones son informativas.

USO DE APLICACIÓN

La utilidad fg no funciona como se espera cuando opera en su propio entorno de ejecución de utilidad porque ese entorno no tiene trabajos aplicables para manipular. Ver la sección USO DE APLICACIÓN para bg. Por esta razón, fg generalmente se implementa como un comando interno del shell.

EJEMPLOS

Ninguno.

RACIOCINIO

Las extensiones al shell especificadas en este volumen de POSIX.1-2017 se han basado en su mayoría en las características proporcionadas por KornShell. Las características de control de trabajos proporcionadas por bg, fg y jobs también se basan en KornShell. Los desarrolladores del estándar examinaron las características de las versiones de C shell de estas utilidades y encontraron que existen diferencias. A pesar del uso generalizado de C shell, las versiones de KornShell fueron seleccionadas para este volumen de POSIX.1-2017 para mantener un grado de uniformidad con el resto de las características de KornShell seleccionadas (como las muy populares características de edición de línea de comandos).
