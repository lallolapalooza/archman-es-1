FGETC(3P) Manual del Programador POSIX FGETC(3P)

PRÓLOGO

Esta página de manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página de manual correspondiente de Linux para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fgetc — obtiene un byte de un flujo

SINOPSIS

#include <stdio.h>
int fgetc(FILE *stream);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C no es intencional. Este volumen de POSIX.1‐2017 se subordina al estándar ISO C.

Si el indicador de fin de archivo para el flujo de entrada apuntado por stream no está establecido y hay un siguiente byte presente, la fgetc() función obtendrá el siguiente byte como un unsigned char convertido a un int, del flujo de entrada apuntado por stream, y avanzará el indicador de posición de archivo asociado para el flujo (si está definido). Dado que fgetc() opera en bytes, leer un carácter que conste de múltiples bytes (o ``un carácter multibyte'') puede requerir múltiples llamadas a fgetc().

La fgetc() función puede marcar la marca de tiempo de acceso a datos del archivo asociado con stream para su actualización. La marca de tiempo de acceso a datos será marcada para su actualización por la primera ejecución exitosa de fgetc(), fgets(), fread(), fscanf(), getc(), getchar(), getdelim(), getline(), gets(), o scanf() usando stream que devuelve datos no proporcionados por una llamada previa a ungetc().

VALOR DE RETORNO

Tras la finalización exitosa, fgetc() devolverá el siguiente byte del flujo de entrada apuntado por stream. Si el indicador de fin de archivo para el flujo está establecido, o si el flujo está en el fin de archivo, el indicador de fin de archivo para el flujo será establecido y fgetc() devolverá EOF. Si ocurre un error de lectura, el indicador de error para el flujo será establecido, fgetc() devolverá EOF, y establecerá errno para indicar el error.

ERRORES

La fgetc() función fallará si se necesitan leer datos y:

EAGAIN
La bandera O_NONBLOCK está establecida para el descriptor de archivo subyacente a stream y el hilo sería retrasado en la fgetc() operación.
EBADF
El descriptor de archivo subyacente a stream no es un descriptor de archivo válido abierto para lectura.
EINTR
La operación de lectura fue terminada debido a la recepción de una señal, y no se transfirieron datos.
EIO
Ha ocurrido un error físico de E/S, o el proceso está en un grupo de procesos en segundo plano intentando leer de su terminal de control, y ya sea que el hilo llamante esté bloqueando SIGTTIN o el proceso esté ignorando SIGTTIN o el grupo de procesos del proceso esté huérfano. Este error también puede ser generado por razones definidas por la implementación.
EOVERFLOW
El archivo es un archivo regular y se intentó leer en o más allá del máximo desplazamiento asociado con el flujo correspondiente.

La fgetc() función puede fallar si:

ENOMEM
No hay suficiente espacio de almacenamiento disponible.
ENXIO
Se hizo una petición a un dispositivo inexistente, o la petición estaba fuera de las capacidades del dispositivo.

USO EN APLICACIONES

Si el valor entero devuelto por fgetc() se almacena en una variable de tipo char y luego se compara contra la constante entera EOF, la comparación puede nunca tener éxito, porque la extensión de signo de una variable de tipo char al ampliarse a entero está definida por la implementación.

Las funciones ferror() o feof() deben usarse para distinguir entre una condición de error y una condición de fin de archivo.
