NOMBRE

chmod, fchmod, fchmodat - cambiar los permisos de un archivo

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/stat.h>
int chmod(const char *path, mode_t mode);
int fchmod(int fd, mode_t mode);
#include <fcntl.h>           /* Definición de las constantes AT_* */
#include <sys/stat.h>
int fchmodat(int dirfd, const char *path, mode_t mode, int flags);

DESCRIPCIÓN

Las llamadas al sistema chmod() y fchmod() cambian los bits de modo de un archivo. (El modo del archivo consiste en los bits de permisos del archivo más los bits set-user-ID, set-group-ID y sticky.) Estas llamadas al sistema difieren únicamente en la forma en que se especifica el archivo:

•
chmod() cambia el modo del archivo especificado cuya ruta de acceso se da en path, la cual se desreferencia si es un enlace simbólico.
•
fchmod() cambia el modo del archivo al que se refiere el descriptor de archivo abierto fd.

El nuevo modo de archivo se especifica en mode, que es una máscara de bits creada mediante la operación OR de cero o más de los siguientes:

S_ISUID (04000)
set-user-ID (establece el ID de usuario efectivo del proceso en execve(2))
S_ISGID (02000)
set-group-ID (establece el ID de grupo efectivo del proceso en execve(2); bloqueo obligatorio, como se describe en fcntl(2); toma el grupo de un archivo nuevo del directorio padre, como se describe en chown(2) y mkdir(2))
S_ISVTX (01000)
bit sticky (bandera de eliminación restringida, como se describe en unlink(2))
S_IRUSR (00400)
lectura por el propietario
S_IWUSR (00200)
escritura por el propietario
S_IXUSR (00100)
ejecución/búsqueda por el propietario ("búsqueda" aplica para directorios, y significa que se pueden acceder las entradas dentro del directorio)
S_IRGRP (00040)
lectura por el grupo
S_IWGRP (00020)
escritura por el grupo
S_IXGRP (00010)
ejecución/búsqueda por el grupo
S_IROTH (00004)
lectura por otros
S_IWOTH (00002)
escritura por otros
S_IXOTH (00001)
ejecución/búsqueda por otros

El UID efectivo del proceso que llama debe coincidir con el propietario del archivo, o el proceso debe ser privilegiado (en Linux: debe tener la capacidad CAP_FOWNER ).

Si el proceso que llama no es privilegiado (en Linux: no tiene la capacidad CAP_FSETID ), y el grupo del archivo no coincide con el ID de grupo efectivo del proceso ni con ninguno de sus IDs de grupo suplementarios, el bit S_ISGID se desactivará, pero esto no hará que se devuelva un error.

Como medida de seguridad, dependiendo del sistema de archivos, los bits de ejecución set-user-ID y set-group-ID pueden desactivarse si se escribe en un archivo. (En Linux, esto ocurre si el proceso que escribe no tiene la capacidad CAP_FSETID .) En algunos sistemas de archivos, solo el superusuario puede establecer el bit sticky, que puede tener un significado especial. Para el bit sticky, y para los bits set-user-ID y set-group-ID en directorios, ver inode(7).

En los sistemas de archivos NFS, restringir los permisos influirá inmediatamente en los archivos ya abiertos, porque el control de acceso se realiza en el servidor, pero los archivos abiertos son mantenidos por el cliente. Ampliar los permisos puede retrasarse para otros clientes si el almacenamiento en caché de atributos está habilitado en ellos.

fchmodat()

La llamada al sistema fchmodat() opera exactamente de la misma manera que chmod(), excepto por las diferencias descritas aquí.

Si path es relativo, entonces se interpreta relativo al directorio al que se refiere el descriptor de archivo dirfd (en lugar de relativo al directorio de trabajo actual del proceso que llama, como lo hace chmod() para una ruta de acceso relativa).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta relativo al directorio de trabajo actual del proceso que llama (como chmod()).

Si path es absoluto, entonces dirfd se ignora.

flags puede ser 0, o incluir las siguientes banderas:

AT_EMPTY_PATH (desde Linux 6.6)
Si path es una cadena vacía, operar sobre el archivo al que se refiere dirfd (que puede haberse obtenido usando la bandera open(2) O_PATH ). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencies: en su lugar, opera sobre el enlace mismo.

Ver openat(2) para una explicación de la necesidad de fchmodat().

VALOR DEVUELTO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1, y errno se establece para indicar el error.

Dependiendo del sistema de archivos, se pueden devolver errores distintos de los enumerados a continuación.

Los errores más generales para chmod() se enumeran a continuación:

EBADF

EBADF
(fchmodat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
path apunta fuera de tu espacio de direcciones accesible.
EINVAL
(fchmodat()) Se especificó una bandera inválida en flags.
EIO
Ocurrió un error de E/S.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
ENAMETOOLONG
path es demasiado largo.
ENOENT
El archivo no existe.
ENOMEM
Memoria de kernel insuficiente

NAME

fchmod, fchmodat - change the mode of a file

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/stat.h>

int
fchmod(int fd, mode_t mode);

#define _ATFILE_SOURCE // For fchmodat
#include <fcntl.h>
#include <sys/stat.h>

int
fchmodat(int dirfd, const char *pathname,
           mode_t mode, int flags);

DESCRIPTION

fchmod() changes the mode (permissions) of the file to which the file descriptor fd refers.

fchmodat() is equivalent to calling fchmod() on the file whose path is specified by the combination of the directory file descriptor dirfd and the buffer pathname. It also allows options and flags to be specified in flags.

The value of mode is a bitmask that should be constructed by OR-ing together bits from sys/stat.h. The relevant bits are:

Permissions bits:
S_IRUSR
Read by owner.
S_IWUSR
Write by owner.
S_IXUSR
Execute by owner.
S_IRGRP
Read by group.
S_IWGRP
Write by group.
S_IXGRP
Execute by group.
S_IROTH
Read by others.
S_IWOTH
Write by others.
S_IXOTH
Execute by others.
Special bits:
S_ISUID
Set-user-ID bit.
S_ISGID
Set-group-ID bit.
S_ISVTX
Sticky bit.

The exact meaning of these bits is described in chmod(1).

The permissions specified in mode replace the existing permissions.

For fchmodat():

If pathname is an absolute path, then dirfd is ignored.

If pathname is a relative path, then it is interpreted relative to the directory referred to by the file descriptor dirfd. If pathname begins with a slash (/), then it is interpreted relative to the root of the filesystem specified by dirfd.

If pathname is NULL, then the function modifies the file referenced by dirfd. In this case, dirfd must refer to a directory.

The flags argument is a bitmask that can contain:

AT_SYMLINK_NOFOLLOW
Do not follow symlinks. If pathname refers to a symbolic link, then affect the symbolic link itself rather than the file that it refers to. This flag is supported since Linux 6.5 and glibc 2.32.

The file descriptor dirfd is specified by one of the constants defined in fcntl.h: AT_FDCWD (representing the current working directory, as is done for fchmod()), or a file descriptor value obtained from a successful open(2) call.

If flags contains AT_SYMLINK_NOFOLLOW and pathname is a symbolic link, then the mode of the symbolic link itself is changed. Otherwise, the mode of the file referenced by the symbolic link is changed.

The S_ISUID, S_ISGID, and S_ISVTX bits may or may not be settable, depending on the filesystem and the process's privileges.

The effective permissions are the result of OR-ing the mode bits with the permissions that are not changed.

The fchmod() and fchmodat() functions are intended to change only the mode bits; they do not affect the file's owner or group.

Changing the mode of a file requires appropriate privileges. Specifically, the process must be the owner of the file, or the process must have the CAP_FOWNER capability (see capabilities(7)). For directories, only the set-group-ID and sticky bits can be changed. For regular files, the set-user-ID and set-group-ID bits can only be set if the calling process has the CAP_SETUID or CAP_SETGID capability respectively, or if the calling process is the owner of the file and the file is not group-writable.

The S_ISUID and S_ISGID bits are cleared on an executable file if the owner ID is changed, or if the group ID is changed and the file is not group-writable. The S_ISUID and S_ISGID bits are cleared on an executable file if the file's owner is changed.

The S_ISUID, S_ISGID, and S_ISVTX bits are cleared on an executable file if the file's group is changed.

RETURN VALUE

On success, fchmod() and fchmodat() return 0. On failure, they return -1, and errno is set to indicate the error.

ERRORS

EBADF
fchmod() sees an invalid file descriptor fd. fchmodat() sees an invalid file descriptor dirfd.
EACCES
Search permission is denied for one of the directories in the path prefix of pathname. Or, pathname refers to a file whose permissions do not allow the requested operation, and the effective UID does not match the owner of the file, and the process is not privileged.
ELOOP
fchmodat() detected a loop while resolving pathname.
ENAMETOOLONG
pathname is too long.
ENOENT
pathname does not exist. Or, dirfd was not valid and pathname is relative, and pathname could not be resolved.
ENOTDIR
A component of the path prefix is not a directory.
ENOTDIR
(fchmodat()) pathname is relative and dirfd is a file descriptor referring to a file other than a directory.
ENOTSUP
(fchmodat()) flags specified AT_SYMLINK_NOFOLLOW, which is not supported.
EPERM
The effective UID does not match the owner of the file, and the process is not privileged (Linux: it does not have the CAP_FOWNER capability).
EPERM
The file is marked immutable or append-only. (See chattr(1).)
EROFS
The named file resides on a read-only filesystem.

VERSIONS

C library/kernel differences

The GNU C library fchmodat() wrapper function implements the POSIX-specified interface described in this page. This interface differs from the underlying Linux system call, which does not have a flags argument.

glibc notes

On older kernels where fchmodat() is unavailable, the glibc wrapper function falls back to the use of fchmod() or chmod(2). When pathname is a relative pathname, glibc constructs a pathname based on the symbolic link in /proc/self/fd that corresponds to the dirfd argument.
