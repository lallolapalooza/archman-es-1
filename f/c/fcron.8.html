NAME

fcron - daemon for scheduling commands

SYNOPSIS

fcron [-n] [-d] [-f]

DESCRIPTION

fcron is a daemon that allows users to specify jobs that are to be run at a particular time or interval. This is the daemon which performs the tasks that you have scheduled with fcrontab(1). It is also able to run jobs that are specified dynamically using fcrondyn(1).

To use fcron, you should create a file called fcrontab(5) in your home directory and then use the fcrontab(1) command to edit it. You may then use the fcrondyn(1) command to add jobs that should only run once.

fcron will automatically check your fcrontab(5) file every 60 seconds. If it detects a change, it will re-read the file. Jobs that are to be run dynamically are submitted using fcrondyn(1) and are kept in memory.

By default, fcron runs in the foreground. To make it run as a daemon, you should call it without any options or use the appropriate init script.

OPTIONS

-n
Don't fork into the background. fcron will stay in the foreground. This is useful for starting fcron from init.
-d
Debug mode. All jobs that are run will be logged in /usr/local/var/log/fcron.log. This option implies -n.
-f
Don't read the system-wide configuration file /usr/local/etc/fcron.conf. Useful if you want to use defaults for everything.

RETURN VALUES

Should never return, unless it is killed or it is started with the -n option.

SIGNALS

SIGHUP
Reload all configuration files and re-read all jobs. This is also the signal sent when the system resumes from suspend, in order to make fcron recalculate jobs.
SIGUSR1
Used internally by fcrondyn to notify fcron that a new job has been added.
SIGCONT
Used internally to resume suspended jobs.

CONFORMING TO

This utility is intended to be compatible with Vixie cron.

FILES

/usr/local/etc/fcron.conf
System-wide configuration file for fcron. See fcron.conf(5).
/usr/local/etc/fcrontab.allow
Users who are allowed to use fcrontab and fcrondyn. If this file exists, only users listed here can use these commands. Users can be specified on a line by themselves, or separated by spaces or tabs. The special name "all" can be used to allow all users. If this file does not exist, then the file in fcron.deny is used.
/usr/local/etc/fcrontab.deny
Users who are NOT allowed to use fcrontab and fcrondyn. If this file exists, users listed here are denied access. The format is the same as for the allow file. If both files exist, the allow file takes precedence. If neither file exists, then all users are allowed.
/usr/local/var/spool/fcron/crondyn
Dynamic jobs are stored here by fcrondyn. This file is managed by fcrondyn. Don't edit it manually!
/usr/local/var/spool/fcron/crondyn.allow
Users who are allowed to use fcrondyn. One name per line. Special name "all" means everyone.
/usr/local/var/spool/fcron/crondyn.deny
Users who are not allowed to use fcrontab and fcrondyn (same format as allow file)
/usr/local/etc/pam.d/fcron (or /usr/local/etc/pam.conf)
PAM configuration file for fcron. Take a look at pam(8) for more details.
/usr/local/var/run/fcron.suspend
Location of fcron suspend file, for non-Linux systems. This should be used to let fcron know how long the system was suspended (to memory or disk), so as task schedules can be updated accordingly. The file must be owned by root:root, and not writable by others. When the system resumes, write the number of seconds (as a string) the system was suspended into this file, and then send a SIGCONT signal to make fcron process (and then delete) that file. This is not needed on Linux as fcron uses Linux-specific APIs to detect the resume and measure the suspend duration.
