FCGI_Accept(3)

Paquete: fcgi

Licencias: custom

() ()
NOMBRE
FCGI_Accept, FCGI_ToFILE, FCGI_ToFcgiStream
- biblioteca de compatibilidad fcgi_stdio

SINOPSIS
#include "fcgi_stdio.h"


int
FCGI_Accept(void);


FILE *
FCGI_ToFILE(FCGI_FILE *);


FCGI_Stream *
FCGI_ToFcgiStream(FCGI_FILE *);

DESCRIPCIÓN
La función FCGI_Accept acepta una nueva solicitud del servidor HTTP
y crea un entorno de ejecución compatible con CGI para la solicitud.


Si la aplicación se invocó como un programa CGI, la primera
llamada a FCGI_Accept es esencialmente una operación nula y la segunda
llamada devuelve -1. Esto hace que una aplicación de Respuesta FastCGI
codificada correctamente ejecute una única solicitud y salga, dando comportamiento
CGI.


Si la aplicación se invocó como un servidor FastCGI, la primera
llamada a FCGI_Accept indica que la aplicación ha completado
su inicialización y está lista para aceptar su primera solicitud.
Llamadas posteriores a FCGI_Accept indican que la aplicación ha
completado el procesamiento de su solicitud actual y está lista para aceptar una
nueva solicitud. Una aplicación puede completar la solicitud actual
sin aceptar una nueva llamando a FCGI_Finish(3); más tarde, cuando
esté lista para aceptar una nueva solicitud, la aplicación llama a FCGI_Accept.


Al completar la solicitud actual, FCGI_Accept puede detectar
errores, por ejemplo, una tubería rota a un cliente que se ha desconectado
temprano. FCGI_Accept ignora dichos errores. Una aplicación
que desee manejar tales errores debería llamar explícitamente
a fclose(stderr), luego a fclose(stdout); un retorno EOF de
cualquiera de ellos indica un error.


Si la variable de entorno FCGI_WEB_SERVER_ADDRS está configurada cuando
se llama a FCGI_Accept, debe contener una lista separada por comas
de direcciones IP. Cada dirección IP se escribe como cuatro números decimales
en el rango [0..255] separados por puntos decimales.
(nslookup(8) traduce el nombre de host IP simbólico más familiar
a esta forma.) Por lo tanto, una vinculación legal para esta variable es


FCGI_WEB_SERVER_ADDRS=199.170.183.28,199.170.183.71


FCGI_Accept comprueba la dirección IP del par de cada nueva conexión para
su pertenencia a la lista. Si la comprobación falla (incluida la
posibilidad de que la conexión no utilizara el transporte TCP/IP),
FCGI_Accept cierra la conexión y acepta otra
(sin devolver entre ellas).


Después de aceptar una nueva solicitud, FCGI_Accept asigna nuevos valores
a las variables globales stdin, stdout, stderr y environ.
Después de que FCGI_Accept devuelva, estas variables tienen la misma
interpretación que en la entrada a un programa CGI.


FCGI_Accept libera cualquier almacenamiento asignado por la llamada anterior
a FCGI_Accept. Esto tiene consecuencias importantes:


NO retenga punteros al array environ ni a ninguna cadena
contenida en él (por ejemplo, al resultado de llamar a getenv(3)),
ya que estos se liberarán en la próxima llamada a FCGI_Finish o
FCGI_Accept.


NO use setenv(3) o putenv(3) para modificar el array environ
creado por FCGI_Accept, ya que esto provocará fugas de almacenamiento
o hará que la próxima llamada a FCGI_Finish o FCGI_Accept libere
almacenamiento que no debería liberarse.


Si su aplicación necesita usar setenv o putenv para modificar
el array environ, debe seguir este patrón de codificación:


char **savedEnviron, **requestEnviron;
int acceptStatus;


savedEnviron = environ;
acceptStatus = FCGI_Accept();
requestEnviron = environ;
environ = savedEnviron;
if(acceptStatus >= 0 && !FCGX_IsCGI()) {
/*
* requestEnviron apunta a pares nombre-valor en
* almacenamiento asignado por FCGI_Accept. OK para leer,
* no OK para retener punteros -- haga copias en su lugar.
*/
}
/*
* OK para hacer setenv o putenv, ¡pero cuidado con las fugas de almacenamiento!
*/


Además de las variables de entorno CGI estándar, la
variable de entorno FCGI_ROLE siempre se establece en el rol
de la solicitud actual. Los roles actualmente definidos son
RESPONDER, AUTHORIZER y FILTER.


En el rol FILTER, las variables adicionales FCGI_DATA_LENGTH
y FCGI_DATA_LAST_MOD también se definen. Consulte la página del manual
FCGI_StartFilterData(3) para obtener información completa.


Las macros FCGI_ToFILE y FCGI_ToFcgiStream se proporcionan
para permitir escapar a funciones nativas que usan los tipos FILE o
FCGI_Stream. En el caso de FILE, las funciones tendrían que
compilarse por separado, ya que fcgi_stdio.h reemplaza el estándar
FILE con FCGI_FILE.

VALORES DE RETORNO
0 para llamada exitosa, -1 para error (la aplicación debe salir).
