DESCRIPCIÓ

N

Estas llamadas al sistema cambian el propietario y el grupo de un archivo. Las chown(), fchown() y lchown() llamadas al sistema difieren solo en cómo se especifica el

archivo:
•
chown() cambia la propiedad del archivo especificado por path, que se desreferencia si es un enlace
simbólico.
•
fchown() cambia la propiedad del archivo referenciado por el descriptor de archivo abierto fd
.
•
lchown() es como chown(), pero no desrefer
encia enlaces
simbólicos.

Solo un proceso privilegiado (Linux: uno con la capacidad CAP_CHOWN ) puede cambiar el propietario de un archivo. El propietario de un archivo puede cambiar el grupo del archivo a cualquier grupo del que ese propietario sea miembro. Un proceso privilegiado (Linux: con CAP_CHOWN) puede cambiar el grupo arbitrariamente

.

Si el propietario o grupo se especifica como -1, entonces ese ID no se

cambia.

Cuando el propietario o grupo de un archivo ejecutable es cambiado por un usuario no privilegiado, los bits de modo S_ISUID y S_ISGID se limpian. POSIX no especifica si esto también debería ocurrir cuando root hace el chown(); el comportamiento de Linux depende de la versión del núcleo, y desde Linux 2.2.13, root es tratado como otros usuarios. En el caso de un archivo no ejecutable por el grupo (es decir, uno para el cual el bit S_IXGRP no está establecido) el bit S_ISGID indica bloqueo obligatorio, y no se limpia por un chown

().

Cuando el propietario o grupo de un archivo ejecutable es cambiado (por cualquier usuario), todos los conjuntos de capacidades para el archivo se

limpian.

fchownat(

)

La llamada al sistema fchownat() opera de exactamente la misma manera que chown(), excepto por las diferencias descritas

aquí.

Si path es relativo, entonces se interpreta relativo al directorio referenciado por el descriptor de archivo dirfd (en lugar de relativo al directorio de trabajo actual del proceso que llama, como lo hace chown() para una ruta relativa)

.

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta relativo al directorio de trabajo actual del proceso que llama (como chown())

.

Si path es absoluto, entonces dirfd se

ignora.

El argumento flags es una máscara de bits creada por la unión (OR) de 0 o más de los siguientes

valores;
AT_EMPTY_PATH (desde Linux 2.6.
39)
Si path es una cadena vacía, operar sobre el archivo referenciado por dirfd (que puede haberse obtenido usando el open(2) flag O_PATH). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Este flag es específico de Linux; define _GNU_SOURCE para obtener su
definición.
AT_SYMLINK_NOFOL
LOW
Si path es un enlace simbólico, no lo desreferencies: en su lugar opera sobre el enlace mismo, como lchown(). (Por defecto, fchownat() desreferencia enlaces simbólicos, como chow
n()
.)

NOTA

S

Propiedad de archivos

nuevos

Cuando se crea un nuevo archivocreado (por ejemplo, con open(2) o mkdir(2)), su propietario se establece igual que el ID de usuario del sistema de archivos del proceso que lo creó. El grupo del archivo depende de una serie de factores, incluyendo el tipo de sistema de archivos, las opciones utilizadas para montar el sistema de archivos y si el bit de modo set-group-ID está habilitado o no en el directorio padre. Si el sistema de archivos admite las opciones de -o grpid (o, sinónimo, -o bsdgroups) y -o nogrpid (o, sinónimo, -o sysvgroups) mount(8), entonces las reglas son las

siguientes:
•
Si el sistema de archivos está montado con -o grpid, entonces el grupo de un nuevo archivo se establece igual que el del directorio
padre.
•
Si el sistema de archivos está montado con -o nogrpid y el bit set-group-ID está deshabilitado en el directorio padre, entonces el grupo de un nuevo archivo se establece igual que el GID del sistema de archivos del
proceso.
•
Si el sistema de archivos está montado con -o nogrpid y el bit set-group-ID está habilitado en el directorio padre, entonc
es el grupo de un nuevo archivo se es
tablece igual que el del directorio padre.

A partir de Linux 4.12, las opciones de montaje -o grpid y -o nogrpid son admitidas por ext2, ext3, ext4, y XFS. Los sistemas de archivos que no admiten estas opciones de montaje siguen las reglas de -o nog

rp
id.

Notas de

glibc

En núcleos antiguos donde fchownat() no está disponible, la función envolvente de glibc recurre al uso de chown() y lchown(). Cuando path es relativo, glibc construye una ruta de acceso basándose en el enlace simbólico en /proc/self/fd que corresponde al argumento dir

f
d.

NF

S

Las semánticas de chown() se violan deliberadamente en los sistemas de archivos NFS que tienen habilitado el mapeo de UID. Además, se violan las semánticas de todas las llamadas al sistema que acceden al contenido del archivo, porque chown() puede causar la revocación inmediata del acceso a archivos ya abiertos. El almacenamiento en caché del lado del cliente puede provocar un retraso entre el momento

en que la propiedad ha sido cambiada para permitir el acceso a un usuario y el mome
nto en que el archivo puede ser realmente accedido por el usuario en otros clientes.

Detalles

históricos

Las llamadas al sistema originales de Linux chown(), fchown(), y lchown() solo admitían IDs de usuario y de grupo de 16 bits. Posteriormente, Linux 2.4 añadió chown32(), fchown32(), y lchown32(), que admitían IDs de 32 bits. Las funciones envolventes de glibc chown(), fchown(), y lchown() manejan de forma transparente las variaciones entre versiones del

núcleo.

Antes de Linux 2.1.81 (excepto 2.1.46), chown() no seguía los enlaces simbólicos. Desde Linux 2.1.81, chown() sí sigue los enlaces simbólicos, y existe una nueva llamada al sistema lchown() que no sigue los enlaces simbólicos. Desde Linux 2.1.86, esta nueva llamada (que tiene las mismas semánticas que la antigua chown()) ha recibido el mismo número de llamada al sistema, y chown() ha recibido

el número
recién in
troducido.

EJEMPLO

S

El siguiente programa cambia la propiedad del archivo nombrado en su segundo argumento de línea de comandos al valor especificado en su primer argumento de línea de comandos. El nuevo propietario se puede especificar ya sea como un ID de usuario numérico, o como un nombre de usuario (que se convierte a un ID de usuario utilizando getpwnam(3) para realizar una búsqueda en el archivo de contraseñas del sistema)

.

Código fuente del

programa 
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char           *endptr;
    uid_t          uid;
    struct passwd  *pwd;
    if (argc != 3 || argv[1][0] == '\0') {
        fprintf(stderr, "%s <owner> <file>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    uid = strtol(argv[1], &endptr, 10);  /* Allow a numeric string */
    if (*endptr != '\0') {         /* Was not pure numeric string */
        pwd = getpwnam(argv[1]);   /* Try getting UID for username */
        if (pwd == NULL) {
            perror("getpwnam");
            exit(EXIT_FAILURE);
        }
        uid = pwd->pw_uid;
    }
    if (chown(argv[2], uid, -1) == -1) {
        perror("chown");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS)
;
}
