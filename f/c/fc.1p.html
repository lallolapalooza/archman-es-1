FC(1P) Manual del Programador POSIX FC(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fc — procesa la lista del historial de comandos

SINOPSIS

fc [-r] [-e editor] [primero [último]]
fc -l [-nr] [primero [último]]
fc -s [viejo=nuevo] [primero]

DESCRIPCIÓN

La utilidad fc listará, o editará y re-ejecutará, comandos introducidos previamente en un sh interactivo.

La lista del historial de comandos hará referencia a los comandos por número. El primer número en la lista se selecciona arbitrariamente. La relación de un número con su comando no cambiará excepto cuando el usuario inicia sesión y ningún otro proceso accede a la lista, momento en el cual el sistema puede restablecer la numeración para que el comando más antiguo conservado comience en otro número (generalmente 1). Cuando el número alcanza un límite superior definido por la implementación, que no será menor que el valor en HISTSIZE o 32767 (el que sea mayor), el shell puede envolver los números, comenzando el siguiente comando con un número menor (generalmente 1). Sin embargo, a pesar de este posible envoltorio de números, fc mantendrá la secuencia de orden temporal de los comandos. Por ejemplo, si se asignan cuatro comandos en secuencia los números 32766, 32767, 1 (envoltorio) y 2 a medida que se ejecutan, el comando 32767 se considera el comando anterior a 1, aunque su número sea mayor.

Cuando se editan comandos (cuando la opción -l no se especifica), las líneas resultantes se introducirán al final de la lista del historial y luego serán re-ejecutadas por sh. El comando fc que causó la edición no se introducirá en la lista del historial. Si el editor devuelve un estado de salida distinto de cero, esto suprimirá la entrada en la lista del historial y la re-ejecución del comando. Cualquier asignación de variables de línea de comandos u operadores de redirección utilizados con fc afectará tanto al propio comando fc como al comando resultante; por ejemplo:

fc -s -- -1 2>/dev/null

reinvoca el comando anterior, suprimiendo el error estándar tanto para fc como para el comando anterior.

OPCIONES

La utilidad fc cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidad.

Se soportarán las siguientes opciones:

-e editor
Utiliza el editor llamado por editor para editar los comandos. La cadena editor es un nombre de utilidad, sujeto a búsqueda a través de la variable PATH (consulte el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 8, Variables de Entorno). El valor de la variable FCEDIT se utilizará como valor predeterminado cuando no se especifique -e. Si FCEDIT está vacío o no está establecido, ed se utilizará como editor.
-l
(La letra ele). Lista los comandos en lugar de invocar un editor sobre ellos. Los comandos se escribirán en la secuencia indicada por los operandos primero y último, según lo afectado por -r, con cada comando precedido por el número de comando.
-n
Suprime los números de comando al listar con -l.
-r
Invierte el orden de los comandos listados (con -l) o editados (sin -l ni -s).
-s
Re-ejecuta el comando sin invocar un editor.

OPERANDOS

Se soportarán los siguientes operandos:

primero, último
Selecciona los comandos a listar o editar. El número de comandos anteriores que se pueden acceder se determinará por el valor de la variable HISTSIZE. El valor de primero o último o ambos será uno de los siguientes:
[+]número
Un número positivo que representa un número de comando; los números de comando se pueden mostrar con la opción -l.
-número
Un número decimal negativo que representa el comando que se ejecutó hace número comandos. Por ejemplo, -1 es el comando inmediatamente anterior.
cadena
Una cadena que indica el comando introducido más recientemente que comienza con esa cadena. Si el operando viejo=nuevo no se especifica también con -s, la forma de cadena del operando primero no puede contener un signo igual (<equals-sign>) incrustado.

Cuando se usa la forma de sinopsis con -s:

*
Si primero se omite, se utilizará el comando anterior.

Para las formas de sinopsis sin -s:

*
Si último se omite, último tendrá como valor predeterminado el comando anterior cuando se especifique -l; de lo contrario, tendrá como valor predeterminado primero.
*
Si primero y último se omiten ambos, se listarán los últimos 16 comandos o se editará el comando único anterior (según la opción -l).
*
Si primero y último están ambos presentes, todos los comandos desde primero hasta último serán editados (sin -l) o listados (con -l). La edición de múltiples comandos se realizará presentando al editor todos los comandos a la vez, cada comando comenzando en una nueva línea. Si primero representa un comando más nuevo que último, los comandos se listarán o editarán en secuencia inversa, equivalente a usar -r. Por ejemplo, los siguientes comandos en la primera línea son equivalentes a los comandos correspondientes en la segunda:
fc -r 10 20    fc    30 40
fc    20 10    fc -r 40 30
*
Cuando se usa un rango de comandos, no será un error especificar valores de primero o último que no estén en la lista del historial; fc sustituirá el valor que representa el comando más antiguo o más reciente en la lista, según corresponda. Por ejemplo, si solo hay diez comandos en la lista del historial, numerados del 1 al 10:
fc -l
fc 1 99

listarará y editará, respectivamente, los diez comandos.

viejo=nuevo
Reemplaza la primera aparición de la cadena viejo en los comandos a re-ejecutar por la cadena nuevo.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de fc:

FCEDIT
Esta variable, cuando sea expandida por el shell, determinará el valor predeterminado para el argumento de opción editor de la opción -e editor. Si FCEDIT está vacío o no está establecido, ed se utilizará como editor.
HISTFILE
Determina una ruta de nombre de archivo de historial de comandos. Si la variable HISTFILE no está establecida, el shell puede intentar acceder o crear un archivo .sh_history en el directorio al que hace referencia la variable de entorno HOME. Si el shell no puede obtener acceso de lectura y escritura, o crear, el archivo de historial, utilizará un mecanismo no especificado que permite que el historial funcione correctamente.
