fcft_rasterize_char_utf32(3)

Paquete: fcft

Licencias: MIT

fcft_rasterize_char_utf32(3) fcft fcft_rasterize_char_utf32(3)

NOMBRE

fcft_rasterize_char_utf32 - rasterizar un glifo para un único punto de código UTF-32

SINOPSIS

#include <fcft/fcft.h>

const struct fcft_glyph *fcft_rasterize_char_utf32(

struct fcft_font *font, uint32_t cp, enum fcft_subpixel subpixel);

DESCRIPCIÓN

fcft_rasterize_char_utf32() rasteriza el punto de código Unicode codificado en UTF-32 cp utilizando la fuente principal, o una de las fuentes de reserva, en font.

Primero se busca cp en la fuente principal. Si no se encuentra, se buscan las fuentes de reserva (en el orden en que se especificaron en fcft_from_name()). Si no se encuentra en ninguna de las fuentes de reserva, se busca en la lista de reserva de FontConfig para la fuente principal.

subpixel le permite especificar qué modo subpíxel usar. Es uno de:

enum fcft_subpixel {
    FCFT_SUBPIXEL_DEFAULT,
    FCFT_SUBPIXEL_NONE,
    FCFT_SUBPIXEL_HORIZONTAL_RGB,
    FCFT_SUBPIXEL_HORIZONTAL_BGR,
    FCFT_SUBPIXEL_VERTICAL_RGB,
    FCFT_SUBPIXEL_VERTICAL_BGR,
};

Si se especifica FCFT_SUBPIXEL_DEFAULT, se utiliza el modo subpíxel configurado en FontConfig. Si se especifica FCFT_SUBPIXEL_NONE, se utilizará anti-aliasing en escala de grises. Para todos los demás valores, se utiliza el modo especificado.

Tenga en cuenta que si el anti-aliasing ha sido deshabilitado (en FontConfig, ya sea globalmente o específicamente para la fuente actual), entonces subpixel se ignora.

La intención es permitir que los programas utilicen modos subpíxel por monitor. Incidentalmente, enum fcft_subpixel coincide con enum wl_output_subpixel, el enum utilizado en Wayland.

Nota: Probablemente no querrá usar nada que no sea FCFT_SUBPIXEL_NONE si se mezcla con un fondo transparente.

VALOR DE RETORNO

En caso de error, se devuelve NULL.

En caso de éxito, se devuelve un puntero a un glifo rasterizado. El glifo se almacena en caché en fcft, lo que hace que las llamadas posteriores con los mismos argumentos sean muy rápidas (es decir, no es necesario que los programas almacenen en caché los glifos por sí mismos).

El objeto glifo es gestionado por font. No es necesario liberarlo explícitamente; se libera cuando font se destruye (con fcft_destroy()).

struct fcft_glyph {
    uint32_t cp;
    int cols;
    const char *font_name;
    pixman_image_t *pix;
    int x;
    int y;
    int width;
    int height;
    struct {
        int x;
        int y;
    } advance;
    bool is_color_glyph;
};

cp es el mismo cp de la llamada a fcft_rasterize_char_utf32().

cols es el número de "columnas" que ocupa el glifo (efectivamente, wcwidth(cp)). Tenga en cuenta que este valor será incorrecto si los caracteres anchos (wchar_t) no están codificados en UTF-32 en la configuración regional actual.

pix es el glifo rasterizado. Su formato depende de varios factores, pero será uno de PIXMAN_a1, PIXMAN_a8, PIXMAN_x8r8g8b8, PIXMAN_a8r8g8b8. Utilice pixman_image_get_format() para averiguar cuál es.

PIXMAN_a1 corresponde a FT_PIXEL_MODE_MONO. Es decir, el glifo es una máscara de bits sin anti-aliasing. Úselo como máscara al mezclar.

PIXMAN_a8 corresponde a FT_PIXEL_MODE_GRAY. Es decir, el glifo es una máscara de bits con anti-aliasing en escala de grises. Úselo como máscara al mezclar.

PIXMAN_x8r8g8b8 corresponde a FT_PIXEL_MODE_LCD o FT_PIXEL_MODE_LCD_V. pixman_image_set_component_alpha() ha sido llamado por fcft para usted. Úselo como máscara al mezclar.

PIXMAN_a8r8g8b8 corresponde a FT_PIXEL_MODE_BGRA. Es decir, el glifo es una imagen RGBA normal. Úselo como fuente al mezclar.

x es el desplazamiento horizontal del glifo, en píxeles. Añada esto a la posición actual del lápiz al mezclar.

y es el desplazamiento vertical del glifo, en píxeles. Añada esto a la posición actual del lápiz al mezclar.

width es el ancho del glifo, en píxeles. Úselo como argumento de 'width' al mezclar.

height es la altura del glifo, en píxeles. Úselo como argumento de 'height' al mezclar.

advance es el "avance" del glifo, en píxeles. Añada esto a la posición del lápiz después de mezclar; x para un diseño horizontal e y para un diseño vertical.

is_color_glyph es verdadero si el glifo es un glifo de color, típicamente un emoji. Cuando es verdadero, el glifo debe ser compuesto SOBRE la superficie de destino, en lugar de usarse como máscara.
