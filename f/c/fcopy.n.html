DESCRIPCIÓ

N

El comando fcopy copia datos de un canal de E/S, inchan a otro canal de E/S, outchan. El comando fcopy aprovecha el almacenamiento en búfer del sistema de E/S de Tcl para evitar copias extra y para no almacenar demasiados datos en la memoria principal al copiar archivos grandes a destinos lentos como sockets de

red.

El comando fcopy transfiere datos desde inchan hasta el fin del archivo o hasta que se hayan transferido size bytes o caracteres; size está en bytes si los dos canales usan la misma codificación, y en caracteres en caso contrario. Si no se proporciona el argumento -size, la copia continúa hasta el fin del archivo. Todos los datos leídos de inchan se copian a outchan. Sin la opción -command, fcopy se bloquea hasta que la copia se completa y devuelve el número de bytes o caracteres (usando las mismas reglas que para la opción -size) escritos en outchan

.

El argumento -command hace que fcopy funcione en segundo plano. En este caso, devuelve inmediatamente y el callback se invoca más tarde cuando la copia se completa. El callback se llama con uno o dos argumentos adicionales que indican cuántos bytes se escribieron en outchan. Si ocurrió un error durante la copia en segundo plano, el segundo argumento es la cadena de error asociada al error. Con una copia en segundo plano, no es necesario poner inchan o outchan en modo no bloqueante; el comando fcopy se encarga de eso automáticamente. Sin embargo, es necesario entrar en el bucle de eventos usando el comando vwait o usando

Tk.

No se permiten realizar otras operaciones de entrada con inchan, u operaciones de salida con outchan, durante una copia en segundo plano con fcopy. Lo contrario es completamente legítimo, como se muestra en el ejemplo de fcopy bidireccional a

continuación.

Si inchan o outchan se cierran mientras la copia está en progreso, la copia actual se detiene y el callback del comando no se realiza. Si inchan se cierra, todos los datos ya encolados para outchan se

escriben.

Tenga en cuenta que inchan puede volverse legible durante una copia en segundo plano. Debe desactivar cualquier manejador de fileevent durante una copia en segundo plano para que esos manejadores no interfieran con la copia. Cualquier intento de E/S incorrecta (realizado por un manejador de fileevent o de otra manera) producirá un error de "canal ocupado" ("channel busy")

.

Fcopy traduce las secuencias de fin de línea en inchan y outchan de acuerdo con la opción -translation de estos canales. Consulte la entrada del manual de fconfigure para obtener detalles sobre la opción -translation. Las traducciones significan que el número de bytes leídos de inchan puede ser diferente del número de bytes escritos en outchan. Solo se informa el número de bytes escritos en outchan, ya sea como valor de retorno de un fcopy síncrono o como argumento del callback para un fcopy asínc

rono.

Fcopy obedece las codificaciones y traducciones de caracteres configuradas para los canales. Esto significa que los caracteres entrantes se convierten internamente primero a UTF-8 y luego a la codificación del canal en el que fcopy escribe. Consulte la entrada del manual de fconfigure para obtener detalles sobre las opciones -encoding y -translation. No se realiza ninguna conversión si ambos canales están configurados con la codificación "binary" y tienen traducciones coincidentes. Si solo el canal de salida está configurado con la codificación "binary", el sistema escribirá la representación UTF-8 interna de los caracteres entrantes. Si

solo el canal de entrada está configurado con la codificación "binary", el sistema asumirá que los bytes entrantes son caracteres UTF-8 válidos y los con
vertirá de acuerdo con la codificación de salida. El comportamiento del sistema para bytes que no son caracteres UTF-8 válidos es indefinido en este caso.

El tercer ejemplo copia en trozos y comprueba el fin del archivo en el callback del

comando. 
proc CopyMore {in out chunk bytes {error {}}} {
    global total done
    incr total $bytes
    if {([string length $error] != 0) || [eof $in]} {
        set done $total
        close $in
        close $out
    } else {
        fcopy $in $out -size $chunk \
                -command [list CopyMore $in $out $chunk]
    }
}
set in [open $file1]
set out [socket $server $port]
set chunk 1024
set total 0
fcopy $in $out -size $chunk \
        -comma
nd [list CopyMore $in $
out $chunk] vwait done
