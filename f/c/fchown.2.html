NOTA

S

Propiedad de archivos

nuevos

Cuando se crea un nuevo archivoed (por ejemplo, open(2) o mkdir(2)), su propietario se establece igual que el ID de usuario del sistema de archivos del proceso creador. El grupo del archivo depende de una serie de factores, incluyendo el tipo de sistema de archivos, las opciones utilizadas para montar el sistema de archivos, y si el bit de modo set-group-ID está habilitado o no en el directorio padre. Si el sistema de archivos admite las -o grpid (o, sinónimamente -o bsdgroups) y -o nogrpid (o, sinónimamente -o sysvgroups) mount(8) opciones, entonces las reglas son las siguientes:

•
Si el sistema de archivos está montado con -o grpid, entonces el grupo de un archivo nuevo se establece igual que el del directorio padre.
•
Si el sistema de archivos está montado con -o nogrpid y el bit set-group-ID está deshabilitado en el directorio padre, entonces el grupo de un archivo nuevo se establece igual que el GID del sistema de archivos del proceso.
•
Si el sistema de archivos está montado con -o nogrpid y el bit set-group-ID está habilitado en el directorio padre, entonces el grupo de un archivo nuevo se establece igual que el del directorio padre.

A partir de Linux 4.12, las -o grpid y -o nogrpid opciones de montaje son soportadas por ext2, ext3, ext4, y XFS. Los sistemas de archivos que no soportan estas opciones de montaje siguen las -o nogrpid reglas.

Notas de glibc

En kernels antiguos donde fchownat() no está disponible, la función envolvente de glibc recurre al uso de chown() y lchown(). Cuando path es relativo, glibc construye un nombre de ruta basado en el enlace simbólico en /proc/self/fd que corresponde al dirfd argumento.

NFS

Las chown() semánticas se violan deliberadamente en sistemas de archivos NFS que tienen habilitado el mapeo de UID. Además, la semántica de todas las llamadas al sistema que acceden al contenido del archivo se viola, porque chown() puede causar la revocación inmediata del acceso en archivos ya abiertos. El almacenamiento en caché del lado del cliente puede llevar a un retraso entre el momento en que la propiedad ha sido cambiada para permitir el acceso a un usuario y el momento en que el archivo puede ser realmente accesible por el usuario en otros clientes.

Detalles históricos

Las llamadas al sistema originales de Linux chown(), fchown(), y lchown() solo soportaban IDs de usuario y de grupo de 16 bits. Posteriormente, Linux 2.4 añadió chown32(), fchown32(), y lchown32(), soportando IDs de 32 bits. Las funciones envolventes de glibc chown(), fchown(), y lchown() manejan de forma transparente las variaciones entre versiones del kernel.

Antes de Linux 2.1.81 (excepto 2.1.46), chown() no seguía enlaces simbólicos. Desde Linux 2.1.81, chown() sí sigue enlaces simbólicos, y hay una nueva llamada al sistema lchown() que no sigue enlaces simbólicos. Desde Linux 2.1.86, esta nueva llamada (que tiene la misma semántica que la antigua chown()) ha obtenido el mismo número de syscall, y chown() obtuvo el número recién introducido.

EJEMPLOS

El siguiente programa cambia la propiedad del archivo nombrado en su segundo argumento de línea de comandos al valor especificado en su primer argumento de línea de comandos. El nuevo propietario puede especificarse ya sea como un ID de usuario numérico, o como un nombre de usuario (que se convierte a un ID de usuario usando getpwnam(3) para realizar una búsqueda en el archivo de contraseñas del sistema).

Código fuente del programa

#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char           *endptr;
    uid_t          uid;
    struct passwd  *pwd;
    if (argc != 3 || argv[1][0] == '\0') {
        fprintf(stderr, "%s <owner> <file>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    uid = strtol(argv[1], &endptr, 10);  /* Allow a numeric string */
    if (*endptr != '\0') {         /* Was not pure numeric string */
        pwd = getpwnam(argv[1]);   /* Try getting UID for username */
        if (pwd == NULL) {
            perror("getpwnam");
            exit(EXIT_FAILURE);
        }
        uid = pwd->pw_uid;
    }
    if (chown(argv[2], uid, -1) == -1) {
        perror("chown");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}
