El <fcntl.h> cabecera debe definir las siguientes constantes simbólicas para el argumento de consejo utilizado por posix_fadvise():

POSIX_FADV_DONTNEED

La aplicación espera que no accederá a los datos especificados en el futuro cercano.
POSIX_FADV_NOREUSE

La aplicación espera acceder a los datos especificados una vez y luego no reutilizarlos posteriormente.
POSIX_FADV_NORMAL

La aplicación no tiene ningún consejo que dar sobre su comportamiento con respecto a los datos especificados. Es la característica por defecto si no se da ningún consejo para un archivo abierto.
POSIX_FADV_RANDOM

La aplicación espera acceder a los datos especificados en un orden aleatorio.
POSIX_FADV_SEQUENTIAL

La aplicación espera acceder a los datos especificados secuencialmente desde desplazamientos más bajos hasta desplazamientos más altos.
POSIX_FADV_WILLNEED

La aplicación espera acceder a los datos especificados en el futuro cercano.

El <fcntl.h> cabecera debe definir la estructura flock que describe un bloqueo de archivo. Debe incluir los siguientes miembros:

short  l_type   Tipo de bloqueo; F_RDLCK, F_WRLCK, F_UNLCK.
short  l_whence Bandera para el desplazamiento inicial.
off_t  l_start  Desplazamiento relativo en bytes.
off_t  l_len    Tamaño; si es 0, entonces hasta EOF.
pid_t  l_pid    ID del proceso que posee el bloqueo; devuelto con F_GETLK.

El <fcntl.h> cabecera debe definir los tipos mode_t, off_ty pid_t como se describe en <sys/types.h>.

Lo siguiente debe declararse como funciones y también puede definirse como macros. Se deben proporcionar los prototipos de función.

int  creat(const char *, mode_t);
int  fcntl(int, int, ...);
int  open(const char *, int, ...);
int  openat(int, const char *, int, ...);
int  posix_fadvise(int, off_t, off_t, int);
int  posix_fallocate(int, off_t, off_t);

La inclusión de la <fcntl.h> cabecera también puede hacer visibles todos los símbolos de <sys/stat.h> y <unistd.h>.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Aunque ninguna implementación existente define AT_SYMLINK_FOLLOW y AT_SYMLINK_NOFOLLOW como el mismo valor numérico, POSIX.1‐2008 no prohíbe eso, ya que las dos constantes no se utilizan con las mismas interfaces.

JUSTIFICACIÓN

Aunque muchas de las constantes simbólicas introducidas en la <fcntl.h> cabecera no necesitan usarse estrictamente en #if directivas del preprocesador, la práctica histórica generalizada las ha definido como macros utilizables en tales construcciones, y el examen de aplicaciones existentes ha mostrado que ocasionalmente se usan de esa manera. Por lo tanto, se decidió mantener este requisito en una implementación en POSIX.1‐2008.
