N

ADVERTENCIA: select() solo puede monitorizar números de descriptores de archivo que sean menores que FD_SETSIZE (1024)—un límite irrazonablemente bajo para muchas aplicaciones modernas—y esta limitación no cambiará. Todas las aplicaciones modernas deberían usar en su lugar poll(2) o epoll(7), que no sufren esta

limitación.

select() permite a un programa monitorizar múltiples descriptores de archivo, esperando hasta que uno o más de los descriptores de archivo se pongan "listos" para alguna clase de operación de E/S (por ejemplo, entrada posible). Un descriptor de archivo se considera listo si es posible realizar una operación de E/S correspondiente (por ejemplo, read(2), o un write(2) suficientemente pequeño) sin

bloquear.

Los argumentos principales de select() son tres "conjuntos" de descriptores de archivo (declarados con el tipo fd_set), que permiten al llamante esperar tres clases de eventos en el conjunto especificado de descriptores de archivo. llamada.

pselect(

)

La llamada al sistema pselect() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo se ponga listo o hasta que se capture una

señal.

El funcionamiento de select() y pselect() es idéntico, excepto por estas tres

diferencias:
•
select() usa un tiempo de espera que es un struct timeval (con segundos y microsegundos), mientras que pselect() usa un struct timespec (con segundos y nanosegundos)
.
•
select() puede actualizar el argumento timeout para indicar cuánto tiempo quedaba. pselect() no cambia este
argumento.
•
select() no tiene argumento sigmask, y se comporta como pselect() llamado con sigmas
k NU
LL.

sigmask es un puntero a una máscara de señales (véase sigprocmask(2)); si no es NULL, entonces pselect() primero reemplaza la máscara de señales actual por la apuntado por sigmask, luego realiza la función "select" y luego restaura la máscara de señales original. (Si sigmask es NULL, la máscara de señales no se modifica durante la llamada a pselect().

)

Aparte de la diferencia en la precisión del argumento timeout, la siguiente llamada a pselect()

: 


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask)
;

es equivalente a ejecutar atómicamente las siguientes

llamadas: 


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL)
;

La razón por la que se necesita pselect() es que si se quiere esperar a una señal o a que un descriptor de archivo esté listo, se necesita una prueba atómica para evitar condiciones de carrera. (Supongamos que el manejador de señales establece una bandera global y retorna. Luego, una prueba de esta bandera global seguida de una llamada a select() podría bloquearse indefinidamente si la señal llega justo después de la prueba pero justo antes de la llamada. Por el contrario, pselect() permite primero bloquear las señales, manejar las señales que han llegado, y luego llamar a pselect() con la sigmask deseada,

evitando la
carrera.)

El

timeout

El argumento timeout para select() es una estructura de el siguiente

tipo:

    time_t      tv_sec;         /* segundos */
    suseconds_t tv_usec;        /* microsegundos */
}

El argumento correspondiente para pselect() es una estructura timespec

(3).

En Linux, select() modifica timeout para reflejar la cantidad de tiempo no dormida; la mayoría de las otras implementaciones no hacen esto. (POSIX.1 permite cualquiera de los dos comportamientos.) Esto causa problemas tanto cuando el código de Linux que lee timeout se porta a otros sistemas operativos, y cuando código se porta a Linux que reutiliza un struct timeval para múltiples select() en un bucle sin reinicializarlo. Aplicaciones

multihilo

Si un descriptor de archivo siendo monitoreado por select() es cerrado en otro hilo, el resultado es indeterminado. En algunos sistemas UNIX, select() desbloquea y retorna, con una indicación de que el descriptor de archivo está listo (una operación de E/S posterior probablemente fallará con un error, a menos que otro proceso reabra el descriptor de archivo entre el tiempo en que select() retornó y la operación de E/S se realiza). En Linux (y algunos otros sistemas), cerrar el descriptor de archivo en otro hilo no tiene efecto en select(). En resumen, cualquier aplicación que dependa de un comp

ortamiento particular en este escen
ario debe considerarse defectuosa.

Diferencias entre la biblioteca C y el

kernel

El kernel de Linux permite conjuntos de descriptores de archivo de tamaño arbitrario, determinando la longitud de los conjuntos a verificar a partir del valor de nfds. Sin embargo, en la implementación de glibc, el tipo fd_set es de tamaño fijo. Consulte también ERRORES

CONOCIDOS.

La interfaz pselect() descrita en esta página es implementada por glibc. La llamada al sistema subyacente de Linux se llama pselect6(). Esta llamada al sistema tiene un comportamiento algo diferente de la función envolvente de

glibc.

La llamada al sistema pselect6() de Linux modifica su argumento timeout. Sin embargo, la función envolvente de glibc oculta este comportamiento usando una variable local para el argumento timeout que se pasa a la llamada al sistema. Así, la función pselect() de glibc no modifica su argumento timeout; este es el comportamiento requerido por POSIX.

1-2001.

El argumento final de la llamada al sistema pselect6() no es un puntero sigset_t *, sino que es en su lugar una estructura de la

forma: 


struct {
    const kernel_sigset_t *ss;   /* Puntero al conjunto de señales */
    size_t ss_len;               /* Tamaño (en bytes) del objeto
                                    apuntado por 'ss' */
}
;

Esto permite a la llamada al sistema obtener tanto un puntero al conjunto de señales como su tamaño, mientras permite el hecho de que la mayoría de las arquitecturas soportan un máximo de 6 argumentos para una llamada al sistema. Consulte sigprocmask(2) para una discusión de la diferencia entre l

a noción del kernel y la de li

ERRORES

CONOCIDOS

POSIX permite que una implementación defina un límite superior, anunciado a través de la constante FD_SETSIZE, en el rango de descriptores de archivo que se pueden especificar en un conjunto de descriptores de archivo. El kernel de Linux no impone un límite fijo, pero la implementación de glibc hace que fd_set sea un tipo de tamaño fijo, con FD_SETSIZE definido como 1024, y las macros FD_*() operan según ese límite. Para monitorear descriptores de archivo mayores que 1023, use poll(2) o epoll(7) en su

lugar.

La implementación de los argumentos fd_set como argumentos de valor-resultado es un error de diseño que se evita en poll(2) y epoll(

7).

Según POSIX, select() debería verificar todos los descriptores de archivo especificados en los tres conjuntos de descriptores de archivo, hasta el límite nfds-1. Sin embargo, la implementación actual ignora cualquier descriptor de archivo en estos conjuntos que sea mayor que el número máximo de descriptor de archivo que el proceso tiene abierto actualmente. Según POSIX, cualquier descriptor de archivo de este tipo que se especifique en uno de los conjuntos debería resultar en el error EBADF

.

A partir de glibc 2.1, glibc proporcionó una emulación de pselect() que se implementó usando sigprocmask(2) y select(). Esta implementación seguía siendo vulnerable a la misma condición de carrera que pselect() fue diseñado para prevenir. Las versiones modernas de glibc usan la llamada al sistema (libre de condiciones de carrera) pselect() en los kernels donde se

proporciona.

En Linux, select() puede reportar un descriptor de archivo de socket como "listo para lectura", aunque una lectura posterior se bloquee. Esto podría ocurrir, por ejemplo, cuando han llegado datos pero al examinarlos tienen una suma de verificación incorrecta y se descartan. Puede haber otras circunstancias en las que un descriptor de archivo se reporta erróneamente como listo. Por lo tanto, puede ser más seguro usar O_NONBLOCK en sockets que no deberían

bloquearse.

En Linux, select() también modifica timeout si la llamada es interrumpida por un manejador de señales (es decir, el retorno de error EINTR). Esto no está permitido por POSIX.1. La llamada al sistema pselect() de Linux tiene el mismo comportamiento, pero el envoltorio de glibc oculta este comportamiento copiando internamente el timeout a una variable local y pasando

esa variable a la
llamada al sistema.

EJEMPLO

S 
#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Vigilar stdin (fd 0) para ver cuándo tiene entrada.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Esperar hasta cinco segundos.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* ¡No confíes en el valor de tv ahora! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Data is available now.\n");
        /* FD_ISSET(0, &rfds) será verdadero.  */
    else
        printf("No data within five seconds.\n");
    exit(EXIT_SUCCESS);
}
