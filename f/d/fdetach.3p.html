FDETACH(3P) Manual del Programador POSIX FDETACH(3P)

PRÓLOGO

Esta página manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fdetach — desvincula un nombre de un descriptor de archivo basado en STREAMS (STREAMS)

SINOPSIS

#include <stropts.h>
int fdetach(const char *path);

DESCRIPCIÓN

La función fdetach() desvinculará un archivo basado en STREAMS del archivo al que fue vinculado por una llamada previa a fattach(). El argumento path apunta al nombre de ruta del archivo STREAMS vinculado. El proceso deberá tener los privilegios apropiados o ser el propietario del archivo. Una llamada exitosa a fdetach() hará que todos los nombres de ruta que nombraban al archivo STREAMS vuelvan a nombrar el archivo al que el archivo STREAMS estaba vinculado. Todas las operaciones subsecuentes en path operarán sobre el archivo subyacente y no sobre el archivo STREAMS.

Todas las descripciones de archivo abiertas establecidas mientras el archivo STREAMS estaba vinculado al archivo referenciado por path seguirán refiriendo al archivo STREAMS después de que fdetach() haya tenido efecto.

Si no hay descriptores de archivo abiertos ni otras referencias al archivo STREAMS, entonces una llamada exitosa a fdetach() será equivalente a realizar el último close() sobre el archivo vinculado.

VALOR DE RETORNO

Al completarse exitosamente, fdetach() devolverá 0; de lo contrario, devolverá -1 y establecerá errno para indicar el error.

ERRORES

La función fdetach() fallará si:

EACCES
Se deniega el permiso de búsqueda en un componente del prefijo de la ruta.
EINVAL
El argumento path nombra un archivo que no está actualmente vinculado.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path .
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <barra invertida> y termina con uno o más caracteres de barra invertida finales, y el último componente del nombre de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EPERM
El ID de usuario efectivo no es el propietario de path y el proceso no tiene los privilegios apropiados.

La función fdetach() puede fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path .
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución del nombre de ruta de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

Las siguientes secciones son informativas.

EJEMPLOS

Desvinculando un archivo

El siguiente ejemplo desvincula el archivo basado en STREAMS /tmp/named-STREAM del archivo al que fue vinculado por una llamada previa y exitosa a fattach(). Las llamadas subsecuentes para abrir este archivo se refieren al archivo subyacente, no al archivo STREAMS.

#include <stropts.h>
...
    char *pathname = "/tmp/named-STREAM";
    int ret;
    ret = fdetach(pathname);

USO EN APLICACIONES

Ninguno.

JUSTIFICATIVA

Ninguna.

DIRECCIONES FUTURAS

La función fdetach() puede ser eliminada en una versión futura.
