select(2) Manual de Llamadas al Sistema select(2)

NOMBRE

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - multiplexación de E/S síncrona

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/select.h>
typedef /* ... */ fd_set;
int select(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
void FD_CLR(int fd, fd_set *set);
int  FD_ISSET(int fd, const fd_set *set);
void FD_SET(int fd, fd_set *set);
void FD_ZERO(fd_set *set);
int pselect(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           const struct timespec *_Nullable restrict timeout,
           const sigset_t *_Nullable restrict sigmask);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

pselect():

    _POSIX_C_SOURCE >= 200112L

DESCRIPCIÓN

ADVERTENCIA: select() solo puede monitorizar números de descriptores de archivo que sean menores que FD_SETSIZE (1024)—un límite irrazonablemente bajo para muchas aplicaciones modernas—y esta limitación no cambiará. Todas las aplicaciones modernas deberían usar en su lugar poll(2) o epoll(7), que no sufren esta limitación.

select() permite a un programa monitorizar múltiples descriptores de archivo, esperando hasta que uno o más de los descriptores de archivo se pongan "listos" para alguna clase de operación de E/S (por ejemplo, posible entrada). Un descriptor de archivo se considera listo si es posible realizar una operación de E/S correspondiente (por ejemplo, read(2), o un write(2)suficientemente pequeño) sin bloquearse.

fd_set

Un tipo de estructura que puede representar un conjunto de descriptores de archivo. Según POSIX, el número máximo de descriptores de archivo en una fd_set estructura es el valor de la macro FD_SETSIZE.

Conjuntos de descriptores de archivo

Los argumentos principales de select() son tres "conjuntos" de descriptores de archivo (declarados con el tipo fd_set), que permiten al llamador esperar tres clases de eventos en el conjunto especificado de descriptores de archivo. Cada uno de los fd_set argumentos puede especificarse como NULL si no se deben observar descriptores de archivo para la clase de eventos correspondiente.

Nótese bien: Al retornar, cada uno de los conjuntos de descriptores de archivo es modificado en el lugar para indicar qué descriptores de archivo están actualmente "listos". Así, si se usa select() dentro de un bucle, los conjuntos deben ser reinicializados antes de cada llamada.

El contenido de un conjunto de descriptores de archivo puede manipularse usando las siguientes macros:

FD_ZERO()
Esta macro limpia (elimina todos los descriptores de archivo de) set. Debería emplearse como el primer paso al inicializar un conjunto de descriptores de archivo.
FD_SET()
Esta macro añade el descriptor de archivo fd a set. Añadir un archivo descriptor que ya está presente en el conjunto es una operación nula, y no produce un error.
FD_CLR()
Esta macro elimina el descriptor de archivo fd de set. Eliminar un descriptor de archivo que no está presente en el conjunto es una operación nula, y no produce un error.
FD_ISSET()
select() modifica el contenido de los conjuntos según las reglas descritas más abajo. Después de llamar a select(), la FD_ISSET() macro puede usarse para probar si un descriptor de archivo sigue presente en un conjunto. FD_ISSET() retorna distinto de cero si el descriptor de archivo fd está presente en set, y cero si no lo está.

Argumentos

Los argumentos de select() son los siguientes:

readfds
Los descriptores de archivo en este conjunto se observan para ver si están listos para la lectura. Un descriptor de archivo está listo para la lectura si una operación de lectura no se bloqueará; en particular, un descriptor de archivo también está listo en fin de archivo.
Después de que select() haya retornado, readfds se limpiará de todos los descriptores de archivo excepto aquellos que estén listos para la lectura.
writefds
Los descriptores de archivo en este conjunto se observan para ver si están listos para la escritura. Un descriptor de archivo está listo para la escritura si una operación de escritura no se bloqueará. Sin embargo, incluso si un descriptor de archivo indica ser escribible, una escritura grande aún puede bloquearse.
Después de que select() haya retornado, writefds se limpiará de todos los descriptores de archivo excepto aquellos que estén listos para la escritura.
exceptfds
Los descriptores de archivo en este conjunto se observan para "condiciones excepcionales". Para ejemplos de algunas condiciones excepcionales, ver la discusión de POLLPRI en poll(2).
Después de que select() haya retornado, exceptfds se limpiará de todos los descriptores de archivo excepto aquellos para los cuales haya ocurrido una condición excepcional.
nfds
Este argumento debería establecerse al número más alto de descriptor de archivo en cualquiera de los tres conjuntos, más 1. Los descriptores de archivo indicados en cada conjunto se comprueban, hasta este límite (pero ver ERRORES).
timeout
El timeout argumento es una timeval estructura (mostrada más abajo) que especifica el intervalo que select() debería bloquear esperando a que un descriptor de archivo se ponga listo. La llamada se bloqueará hasta que:
•
un descriptor de archivo se ponga listo;
•
la llamada sea interrumpida por un manejador de señales; o
•
el tiempo de espera expire.
Nótese que el timeout intervalo se redondeará hacia arriba a la granularidad del reloj del sistema, y los retrasos de planificación del núcleo significan que el intervalo de bloqueo puede excederse en una pequeña cantidad.
Si ambos campos de la timeval estructura son cero, entonces select() retorna inmediatamente. (Esto es útil para sondeo.)
Si timeout se especifica como NULL, select() se bloquea indefinidamente esperando a que un descriptor de archivo se ponga listo.

pselect()

La llamada al sistema pselect() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo se ponga listo o hasta que una señal sea capturada.

El funcionamiento de select() y pselect() es idéntico, excepto por estas tres diferencias:

•
select() usa un tiempo de espera que es un struct timeval (con segundos y microsegundos), mientras que pselect() usa un struct timespec (con segundos y nanosegundos).
•
select() puede actualizar el timeout argumento para indicar cuánto tiempo quedaba. pselect() no cambia este argumento.
•
select() no tiene el argumento sigmask , y se comporta como pselect() llamado con NULL sigmask.

sigmask es un puntero a una máscara de señales (ver sigprocmask(2)); si no es NULL, entonces pselect() primero reemplaza la máscara de señales actual por la queapuntado por sigmask, luego ejecuta la función "select", y luego restaura la máscara de señales original. (Si sigmask es NULL, la máscara de señales no se modifica durante la pselect() llamada.)

Aparte de la diferencia en la precisión del timeout argumento, la siguiente pselect() llamada:


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask);

es equivalente a atómicamente ejecutar las siguientes llamadas:


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

La razón por la que se necesita pselect() es que si uno quiere esperar a que una señal o a que un descriptor de archivo esté listo, entonces se necesita una prueba atómica para evitar condiciones de carrera. (Supongamos que el manejador de señales establece una bandera global y retorna. Luego, una prueba de esta bandera global seguida de una llamada a select() podría bloquearse indefinidamente si la señal llegó justo después de la prueba pero justo antes de la llamada. Por el contrario, pselect() permite primero bloquear las señales, manejar las señales que han llegado, luego llamar a pselect() con el sigmaskdeseado, evitando la carrera.)

El timeout

El timeout argumento para select() es una estructura de el siguiente tipo:


struct timeval {
    time_t      tv_sec;         /* segundos */
    suseconds_t tv_usec;        /* microsegundos */
};

El argumento correspondiente para pselect() es una timespec(3) estructura.

En Linux, select() modifica timeout para reflejar la cantidad de tiempo no dormida; la mayoría de las otras implementaciones no hacen esto. (POSIX.1 permite cualquiera de los comportamientos.) Esto causa problemas tanto cuando el código de Linux que lee timeout se porta a otros sistemas operativos, y cuando el código se porta a Linux que reutiliza un struct timeval para múltiples select()s en un bucle sin reinicializarlo. Considere timeout como indefinido después de que select() retorna.

VALOR RETORNO

En éxito, select() y pselect() retornan el número de descriptores de archivo contenidos en los tres conjuntos de descriptores retornados (es decir, el número total de bits que están establecidos en readfds, writefds, exceptfds). El valor de retorno puede ser cero si el timeout expiró antes de que algún descriptor de archivo estuviera listo.

En error, se retorna -1, y errno se establece para indicar el error; los conjuntos de descriptores de archivo no se modifican, y timeout se vuelve indefinido.

ERRORES

EBADF
Se proporcionó un descriptor de archivo inválido en uno de los conjuntos. (Quizás un descriptor de archivo que ya fue cerrado, o uno en el que ha ocurrido un error.) Sin embargo, vea ERRORES CONOCIDOS.
EINTR
Se capturó una señal; vea signal(7).
EINVAL
nfds es negativo o excede el RLIMIT_NOFILE límite de recursos (vea getrlimit(2)).
EINVAL
El valor contenido en timeout es inválido.
ENOMEM
No se pudo asignar memoria para las tablas internas.

VERSIONES

En algunos otros sistemas UNIX, select() puede fallar con el error EAGAIN si el sistema falla en asignar recursos internos del kernel, en lugar de ENOMEM como lo hace Linux. POSIX especifica este error para poll(2), pero no para select(). Los programas portables pueden desear verificar EAGAIN y hacer un bucle, igual que con EINTR.

ESTÁNDARES

POSIX.1-2024.

NOTAS

El siguiente encabezado también proporciona el fd_set tipo: <sys/time.h>.

Un fd_set es un búfer de tamaño fijo. Ejecutar FD_CLR() o FD_SET() con un valor de fd que es negativo o es igual o mayor que FD_SETSIZE resultará en comportamiento indefinido. Además, POSIX requiere que fd sea un descriptor de archivo válido.

La operación de select() y pselect() no se ve afectada por el O_NONBLOCK indicador.

El truco de la tubería propia

En sistemas que carecen de pselect(), se puede lograr una captura de señales confiable (y más portable) usando el truco de la tubería propia. En esta técnica, un manejador de señales escribe un byte en una tubería cuyo otro extremo es monitoreado por select() en el programa principal. (Para evitar posiblemente bloquearse al escribir en una tubería que puede estar llena o leer de una tubería que puede estar vacía, se usa E/S no bloqueante al leer y escribir en la tubería.)

Emulando usleep(3)

Antes de la llegada de usleep(3), algún código empleaba una llamada a select() con los tres conjuntos vacíos, nfds cero, y un timeout no nulo timeout como una forma bastante portable de dormir con precisión subsegundo.

Correspondencia entre notificaciones de select() y poll()

Dentro del código fuente del kernel de Linux, encontramos las siguientes definiciones que muestran la correspondencia entre las notificaciones de condición legible, escribible y excepcional de select() y las notificaciones de eventos proporcionadas por poll(2) y epoll(7):


#define POLLIN_SET  (EPOLLRDNORM | EPOLLRDBAND | EPOLLIN |
                     EPOLLHUP | EPOLLERR)
                   /* Listo para leer */
#define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT |
                     EPOLLERR)
                   /* Listo para escribir */
#define POLLEX_SET  (EPOLLPRI)
                   /* Condición excepcional */

Aplicaciones multihilo

Si un descriptor de archivo siendo monitoreado por select() es cerrado en otro hilo, el resultado es indeterminado. En algunos sistemas UNIX, select() desbloquea y retorna, con una indicación de que el descriptor de archivo está listo (una operación de E/S posterior probablemente fallará con un error, a menos que otro proceso reabra el descriptor de archivo entre el momento en que select() retornó y en que se realiza la operación de E/S). En Linux (y algunos otros sistemas), cerrar el descriptor de archivo en otro hilo no tiene efecto en select(). En resumen, cualquier aplicación que dependa de un comportamiento particular en este escenario debe considerarse defectuosa.

Diferencias entre la biblioteca C/kernel

El kernel de Linux permite conjuntos de descriptores de archivo de tamaño arbitrario, determinando la longitud de los conjuntos a verificar a partir del valor de nfds. Sin embargo, en la implementación de glibc, el fd_set tipo es de tamaño fijo. Vea también ERRORES CONOCIDOS.

La pselect() interfaz descrita en esta página es implementada por glibc. La llamada al sistema subyacente de Linux se llama pselect6(). Esta llamada al sistema tiene un comportamiento algo diferente del de la función envolvente de glibc.

La llamada al sistema de Linux pselect6() modifica su timeout argumento. Sin embargo, la función envolvente de glibc oculta este comportamiento usando una variable local para el argumento de timeout que se pasa a la llamada al sistema. Así, la función de glibc pselect() no modifica su timeout argumento; este es el comportamiento requerido por POSIX.1-2001.

El argumento final de la pselect6() llamada al sistema no es un sigset_t * puntero, sino que es en su lugar una estructura de la forma:


struct {
    const kernel_sigset_t *ss;   /* Puntero al conjunto de señales */
    size_t ss_len;               /* Tamaño (en bytes) del objeto
                                    apuntado por 'ss' */
};

Esto permite a la llamada al sistema obtener tanto un puntero al conjunto de señales como su tamaño, mientras permite el hecho de que la mayoría de las arquitecturas soportan un máximo de 6 argumentos para una llamada al sistema. Vea sigprocmask(2) para una discusión de la diferencia entre la noción de conjunto de señales del kernel y de libc.

Detalles históricos de glibc

glibc 2.0 proporcionó una versión incorrecta de pselect() que no tomaba un sigmask argumento.

Desde glibc 2.1 hasta glibc 2.2.1, uno debe definir _GNU_SOURCE para obtener la declaración de pselect() desde <sys/select.h>.

ERRORES CONOCIDOS

POSIX permite que una implementación defina un límite superior, anunciado a través de la constante FD_SETSIZE, sobree rango de descriptores de archivo que pueden especificarse en un conjunto de descriptores de archivo. El kernel de Linux no impone un límite fijo, pero la implementación de glibc hace que fd_set sea un tipo de tamaño fijo, con FD_SETSIZE definido como 1024, y las FD_*() macros operando según ese límite. Para monitorizar descriptores de archivo mayores que 1023, use poll(2) o epoll(7) en su lugar.

La implementación de los fd_set argumentos como argumentos de valor-resultante es un error de diseño que se evita en poll(2) y epoll(7).

Según POSIX, select() debería comprobar todos los descriptores de archivo especificados en los tres conjuntos de descriptores de archivo, hasta el límite nfds-1. Sin embargo, la implementación actual ignora cualquier descriptor de archivo en estos conjuntos que sea mayor que el número máximo de descriptor de archivo que el proceso tiene actualmente abierto. Según POSIX, cualquier descriptor de archivo de este tipo especificado en uno de los conjuntos debería resultar en el error EBADF.

A partir de glibc 2.1, glibc proporcionó una emulación de pselect() que se implementó usando sigprocmask(2) y select(). Esta implementación siguió siendo vulnerable a la misma condición de carrera que pselect() fue diseñado para prevenir. Las versiones modernas de glibc usan la llamada al sistema (libre de condiciones de carrera) pselect() en los kernels donde se proporciona.

En Linux, select() puede reportar un descriptor de archivo de socket como "listo para lectura", mientras que sin embargo una lectura posterior se bloquea. Esto podría, por ejemplo, suceder cuando los datos han llegado pero al examinarlos tienen el checksum incorrecto y se descartan. Puede haber otras circunstancias en las que un descriptor de archivo se reporta falsamente como listo. Por lo tanto, puede ser más seguro usar O_NONBLOCK en sockets que no deberían bloquearse.

En Linux, select() también modifica timeout si la llamada es interrumpida por un manejador de señales (es decir, la EINTR devolución de error). Esto no está permitido por POSIX.1. La llamada al sistema pselect() de Linux tiene el mismo comportamiento, pero el envoltorio de glibc oculta este comportamiento copiando internamente el timeout a una variable local y pasando esa variable a la llamada al sistema.

EJEMPLOS

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Observar stdin (fd 0) para ver cuándo tiene entrada.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Esperar hasta cinco segundos.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* ¡No confíes en el valor de tv ahora! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Hay datos disponibles ahora.\n");
        /* FD_ISSET(0, &rfds) será verdadero.  */
    else
        printf("No hay datos dentro de cinco segundos.\n");
    exit(EXIT_SUCCESS);
}
