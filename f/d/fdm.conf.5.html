DESCRIPCIÓ

N

Esta página de manual describe el archivo de configuración de fdm(1). Define cuentas desde las que obtener correo, una serie de posibles acciones a realizar, y reglas que conectan una expresión regular con una acción. El archivo se analiza una vez de arriba hacia abajo, por lo que las definiciones de acciones y cuentas deben aparecer antes de que se referencien en una regla. Las reglas se evalúan de la primera a la última y (a menos que se anule con la palabra clave continue) la evaluación se detiene en la primera

coincidencia.

El archivo tiene el siguiente

formato:

Se ignoran las líneas vacías y las líneas que comienzan con el carácter

‘#’.

Las expresiones regulares y las cadenas deben estar entre comillas dobles. Los caracteres especiales en las expresiones regulares y las cadenas (incluidas las contraseñas) deben escaparse. Tenga en cuenta que esto puede significar doble escape en las expresiones

regulares.

Los comandos posibles

se describen en las
siguientes secciones.

FILE OPTIONS

file-umask user | umask
Esto especifica la umask(2) a usar al crear archivos. user significa usar la umask establecida cuando se inicia fdm(1), o umask puede especificarse como un número octal de tres dígitos. El valor predeterminado es 077.
file-group user | group
Esta opción permite especificar la propiedad de grupo predeterminada de los archivos y directorios creados por fdm(1). group puede ser una cadena de nombre de grupo o un gid numérico. Si se usa user, o si esta opción no aparece en el archivo de configuración, fdm(1) no intenta establecer el grupo de los archivos y directorios nuevos.
timeout time
Esto controla el tiempo máximo de espera para que un servidor envíe datos antes de cerrar una conexión. El valor predeterminado es 900 segundos.
verify-certificates
Instruye a fdm(1) para verificar los certificados SSL para todas las conexiones SSL.

INCLUYENDO ARCHIVOS

Se pueden incluir archivos de configuración adicionales usando el comando include:

include path
 

El archivo a incluir se busca primero como una ruta absoluta y luego en relación con el directorio que contiene el archivo de configuración principal.

MACROS

Los macros se pueden definir usando la siguiente sintaxis:

  • $name = string
  • %name = number

Los macros se prefijan con $ para indicar un valor de cadena y con % para indicar un valor numérico. Una vez definidos, un macro puede usarse en cualquier lugar donde se espere una cadena o un número. Los macros pueden incrustarse en cadenas rodeando su nombre (después del $ o %) con {}s, así:

"abc ${mymacro} %{anothermacro} def"

Las palabras clave ifdef, ifndef y endif pueden usarse para analizar condicionalmente una sección del archivo de configuración dependiendo de si el macro dado existe o no existe. Los bloques ifdef y ifndef pueden anidarse.

COMANDOS DE SHELL

El resultado de un comando de shell puede usarse en cualquier punto donde se espere una cadena o un número encerrándolo en $() o %(). Si se usa el primero, el resultado del comando se usa como una cadena; si se usa el segundo, se convierte a un entero. Los comandos de shell se ejecutan cuando se analiza el archivo de configuración.

CUENTAS

El comando account se usa para instruir a fdm(1) para que obtenga correo de una cuenta. La sintaxis es:

account name [users] [disabled] type [args] [keep]
 

El argumento name es una cadena que especifica un nombre para la cuenta. El argumento opcional users tiene la siguiente forma:

user user | users { user ... }
 

Las dos primeras opciones especifican un usuario o una lista de usuarios como los cuales se entregará el correo cuando se ejecute una acción. Si no se especifican usuarios, se utiliza el usuario predeterminado (establecido con set default-user). Los usuarios especificados como parte de la definición de la cuenta pueden ser anulados por argumentos similares a las definiciones de acción o en reglas de coincidencia. Si fdm(1) se ejecuta como no root, aún ejecutará cualquier acción una vez por cada usuario, pero no podrá cambiar a ese usuario, por lo que la acción se ejecutará varias veces como el usuario actual.

La palabra clave disabled instruye a fdm(1) para que ignore esta cuenta a menos que se habilite explícitamente con la opción -a en la línea de comandos. Si se especifica la palabra clave keep, todo el correo recopilado de esta cuenta se conserva (no se elimina) incluso si coincide con una acción drop.

Los tipos de cuenta y argumentos compatibles son:

stdin
Este tipo de cuenta lee el correo de stdin, si está conectado a una tubería. Esto puede usarse para entregar correo desde sendmail(8), ver fdm(1) para más detalles.

The possible values for action are listed below. If multiple actions are specified they are executed once in the order specified, for each user.

drop
Discard the mail.
keep
Keep the mail, do not remove it from the account.
tag string [value value]
This tags mail with string, and optionally value, which may be matched using the tagged or string conditions.
maildir path
Save the mail to the maildir specified by path. If the maildir or any part of its path does not exist, it is created, unless the no-create option is set.

Mail delivered to a maildir is tagged with a mail_file tag containing the full path of the mail file.

Append the mail to the mbox at path. If compress is specified, fdm(1) will add ‘.gz’ to path and attempt to write mail using gzip(1) compression. If the mbox or any part of its path does not exist, it is created, unless the no-create option is set.

Mail delivered to an mbox is tagged with a mbox_file tag containing the path of the mbox.

Connect to an LMTP server and attempt to store the mail there. If a UNIX socket is to be used, path must be the absolute pathname.

RULES

Rules are specified using the match keyword. It has the following basic form:

match condition [and | or condition ...] [users] actions [continue]
 

The condition argument may be one of:

all
Matches all mail.
matched
Matches only mail that has matched a previous rule and been passed on with continue.
unmatched
The opposite of matched: matches only mails which have matched no previous rules.
account name | accounts { name ... }
Matches only mail fetched from the named account or accounts. The account names may include shell glob wildcards to match multiple accounts, as with the -a and -x command line options.
tagged string
Matches mails tagged with string.
[case] regexp [in headers | in body]
Specifies a regexp against which each mail should be matched. The regexp matches may be restricted to either the headers or body of the message by specifying either in headers or in body. The case keyword forces the regexp to be matched case-sensitively: the default is case-insensitive matching.
exec command [user user] returns (return code, stdout regexp)
 
pipe command [user user] returns (return code, [case] stdout regexp)
These two conditions execute a command and test its return value and output. The return code argument is the numeric return code expected and stdout regexp is a regexp to be tested against the output of the command to stdout. Either of these two arguments may be omitted: if both are specified, both must match for the condition to be true. The pipe version will pipe the mail to the command's stdin when executing it. Coincide como verdadero si alguno de los adjuntos de un correo posee un tipo MIME o nombre de archivo que coincide con cadena. Se pueden usar comodin
es de fnmatch(3).

Múltiples condiciones pueden encadenarse usando las palabras clave and u or. Las condiciones se prueban de izquierda a derecha. Cualquier condición puede prefijarse con la palabra clave not para

invertirla.

El argumento opcional usuarios de la primera forma tiene la misma sintaxis que para una definición de acción. La lista de usuarios de una regla anula cualquier usuario dado como parte de las

acciones.

La lista de acciones especifica las acciones a realizar cuando una regla coincide con un correo. Es de una forma

similar:
acción nombre | acciones { nombre ...
}
 

O puede especificar un número de acciones en línea (acciones lambda)

:
acción acci
ón
 
acción { acción ...
}
 

En el último caso, acción sigue la misma forma descrita en la sección ACCIONES. Las acciones se realizan de la primera a la última en el orden en que se especifican en la definición de la

regla.

Si la palabra clave continue está presente, la evaluación no se detendrá si esta regla coincide. En su lugar, fdm(1) continuará para coincidir con más reglas

después de realizar cualqui
er acción para esta regla.

ANIDADAS

Las reglas pueden anidarse especificando más reglas entre

llaves:
coincidir condición [and | or condición ...]
{
 
coincidir ..
.
 
}
 

Las reglas internas no se evaluarán a menos que la externa coincida. Las reglas pueden anidarse múltiples veces. Ten en cuenta que la regla externa no cuenta como una coincidencia a efectos de las condiciones matched y unmat

che
d.
