fopen(3) Manual de Funciones de Biblioteca fopen(3)

NOMBRE

fopen, fdopen, freopen - funciones de apertura de flujos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
FILE *fopen(const char *restrict path, const char *restrict mode);
FILE *fdopen(int fd, const char *mode);
FILE *freopen(const char *restrict path, const char *restrict mode,
              FILE *restrict stream);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

fdopen():

    _POSIX_C_SOURCE

DESCRIPCIÓN

La función fopen() abre el archivo cuyo nombre es la cadena apuntada por path y asocia un flujo con él.

El argumento mode apunta a una cadena que comienza con una de las siguientes secuencias (posiblemente seguida de caracteres adicionales, como se describe a continuación):

r
Abrir archivo de texto para lectura. El flujo se posiciona al principio del archivo.
r+
Abrir para lectura y escritura. El flujo se posiciona al principio del archivo.
w
Truncar el archivo a longitud cero o crear archivo de texto para escritura. El flujo se posiciona al principio del archivo.
w+
Abrir para lectura y escritura. El archivo se crea si no existe, de lo contrario se trunca. El flujo se posiciona al principio del archivo.
a
Abrir para añadir (escribir al final del archivo). El archivo se crea si no existe. El flujo se posiciona al final del archivo.
a+
Abrir para lectura y añadir (escribir al final del archivo). El archivo se crea si no existe. La salida siempre se añade al final del archivo. POSIX guarda silencio sobre la posición inicial de lectura cuando se usa este modo. Para glibc, la posición inicial del archivo para la lectura está al principio del archivo, pero para Android/BSD/MacOS, la posición inicial del archivo para la lectura está al final del archivo.

La cadena mode también puede incluir la letra 'b' ya sea como último carácter o como un carácter entre los caracteres de cualquiera de las cadenas de dos caracteres descritas anteriormente. Esto es estrictamente para compatibilidad con ISO C y no tiene ningún efecto; la 'b' se ignora en todos los sistemas compatibles con POSIX, incluido Linux. (Otros sistemas pueden tratar los archivos de texto y los archivos binarios de manera diferente, y añadir la 'b' puede ser una buena idea si realiza E/S en un archivo binario y espera que su programa pueda ser portado a entornos no UNIX).

Consulte NOTAS para obtener detalles sobre las extensiones de glibc para mode.

Cualquier archivo creado tendrá el modo S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH (0666), modificado por el valor umask del proceso (ver umask(2)).

Las lecturas y escrituras pueden mezclarse en flujos de lectura/escritura en cualquier orden. Tenga en cuenta que ANSI C requiere que una función de posicionamiento de archivo intervenga entre la salida y la entrada, a menos que una operación de entrada encuentre el fin de archivo. (Si esta condición no se cumple, entonces una lectura puede devolver el resultado de escrituras distintas de la más reciente.) Por lo tanto, es una buena práctica (y de hecho a veces necesario en Linux) colocar una operación fseek(3) o fsetpos(3) entre las operaciones de escritura y lectura en dicho flujo. Esta operación puede ser una aparente no-operación (como en fseek(..., 0L, SEEK_CUR) llamada por su efecto secundario de sincronización).

Abrir un archivo en modo de añadir (a como primer carácter de mode) hace que todas las operaciones de escritura posteriores en este flujo ocurran al final del archivo, como si estuvieran precedidas por la llamada:


fseek(stream, 0, SEEK_END);

El descriptor de archivo asociado con el flujo se abre como si fuera por una llamada a open(2) con las siguientes banderas:

Modo de fopen() Banderas de open()
r O_RDONLY
w O_WRONLY | O_CREAT | O_TRUNC
a O_WRONLY | O_CREAT | O_APPEND
r+ O_RDWR
w+ O_RDWR | O_CREAT | O_TRUNC
a+ O_RDWR | O_CREAT | O_APPEND

fdopen()

La función fdopen() asocia un flujo con el descriptor de archivo existente, fd. El mode del flujo (uno de los valores "r", "r+", "w", "w+", "a", "a+") debe ser compatible con el modo del descriptor de archivo. El indicador de posición del archivo del nuevo flujo se establece en el que pertenece a fd, y los indicadores de error y fin de archivo se limpian. Los modos "w" o "w+" no causan truncamiento del archivo. El descriptor de archivo no se duplica y se cerrará cuando se cierre el flujo creado por fdopen(). El resultado de aplicar fdopen() a un objeto de memoria compartida no está definido.

freopen()

La función freopen() abre el archivo cuyo nombre es la cadena apuntada por path y asocia el flujo apuntado por stream con él. El flujo original (si existe) se cierra. El argumento mode se usa igual que en la función fopen().

Si path es un puntero nulo, freopen() cambia el modo del flujo al especificado en mode; es decir, freopen() vuelve a abrir la ruta de acceso que está asociada con el flujo. La especificación para este comportamiento se añadió en el estándar C99, que dice:

En este caso, el descriptor de archivo asociado con el flujo no necesita cerrarse si la llamada a freopen() tiene éxito. Está definido por la implementación qué cambios de modo son permitidos (si los hay), y bajo qué circunstancias.

El uso principal de la función freopen() es cambiar el archivo asociado con un flujo de texto estándar (stderr, stdin o stdout).

VALOR DE RETORNO

Tras una finalización exitosa, fopen(), fdopen() y freopen() devuelven un puntero FILE. De lo contrario, se devuelve NULL y se establece errno para indicar el error.

ERRORES

EINVAL
El mode proporcionado a fopen(), fdopen() o freopen() era inválido.

Las funciones fopen(), fdopen() y freopen() también pueden fallar y establecer errno para cualquiera de los errores especificados para la rutina malloc(3).

La función fopen() también puede fallar y establecer errno para cualquiera de los errores especificados para la rutina open(2).

La función fdopen() también puede fallar y establecer errno para cualquiera de los errores especificados para la rutina fcntl(2).

La función freopen() también puede fallar y establecer errno para cualquiera de los errores especificados para las rutinas open(2), fclose(3) y fflush(3).

NOTAS

Notas de glibc

La biblioteca C de GNU permite las siguientes extensiones para la cadena especificada en mode:

c (desde glibc 2.3.3)
No hacer que la operación de apertura, o las operaciones de lectura y escritura subsiguientes, sean puntos de cancelación de hilos. Esta bandera se ignora para fdopen().
e (desde glibc 2.7)
Abrir el archivo con la bandera O_CLOEXEC. Ver open(2) para más información. Esta bandera se ignora para fdopen().
m (desde glibc 2.3)
Intentar acceder al archivo usando mmap(2), en lugar de llamadas al sistema de E/S (read(2), write(2)). Actualmente, el uso de mmap(2) solo se intenta para un archivo abierto para lectura.
x
Abrir el archivo exclusivamente (como la bandera O_EXCL de open(2)). Si el archivo ya existe, fopen() falla y establece errno a EEXIST. Esta bandera se ignora para fdopen().

Además de los caracteres anteriores, fopen() y freopen() admiten la siguiente sintaxis en mode:

,ccs=cadena

La cadena dada se toma como el nombre de un conjunto de caracteres codificados y el flujo se marca como orientado a anchos. A partir de entonces, las funciones de conversión internas convierten E/S hacia y desde el conjunto de caracteres cadena. Si no se especifica la sintaxis ,ccs=cadena, la orientación de ancho del flujo se determina por la primera operación de archivo. Si esa operación es una operación de ancho, el flujo se marca como orientado a ancho y se cargan las funciones para convertir al conjunto de caracteres codificados.

ERRORES

Al analizar caracteres de bandera individuales en mode (es decir, los caracteres que preceden a la especificación "ccs"), la implementación de glibc de fopen() y freopen() limita el número de caracteres examinados en mode a 7 (o, antes de glibc 2.14, a 6, lo que no era suficiente para incluir especificaciones posibles como "rb+cmxe"). La implementación actual de fdopen() analiza como máximo 5 caracteres en mode.
