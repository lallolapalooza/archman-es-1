FDOPENDIR(3P) Manual del Programador POSIX FDOPENDIR(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fdopendir, opendir — abrir el directorio asociado con un descriptor de archivo

SINOPSIS

#include <dirent.h>
DIR *fdopendir(int fd);
DIR *opendir(const char *dirname);

DESCRIPCIÓN

La fdopendir() función será equivalente a la opendir() función excepto que el directorio se especifica mediante un archivo descriptor en lugar de mediante un nombre. El desplazamiento de archivo asociado con el archivo descriptor en el momento de la llamada determina qué entradas se devuelven.

Tras el retorno exitoso de fdopendir(), el archivo descriptor está bajo el control del sistema, y si se intenta cerrar el archivo descriptor, o modificar el estado de la descripción asociada, por otros medios que no sean closedir(), readdir(), readdir_r(), rewinddir(), o seekdir(), el comportamiento es indefinido. Tras llamar a closedir() el archivo descriptor será cerrado.

No se especifica si la bandera FD_CLOEXEC será establecida en el archivo descriptor por una llamada exitosa a fdopendir().

La opendir() función abrirá un flujo de directorio correspondiente al directorio nombrado por el dirname argumento. El flujo de directorio se posiciona en la primera entrada. Si el tipo DIR es implementado usando un descriptor de archivo, las aplicaciones solo podrán abrir hasta un total de {OPEN_MAX} archivos y directorios.

Si el tipo DIR es implementado usando un archivo descriptor, el descriptor se obtendrá como si la bandera O_DIRECTORY hubiera sido pasada a open().

VALOR DE RETORNO

Tras la finalización exitosa, estas funciones devolverán un puntero a un objeto de tipo DIR. De lo contrario, estas funciones devolverán un puntero nulo y establecerán errno para indicar el error.

ERRORES

La fdopendir() función fallará si:

EBADF
El fd argumento no es un descriptor de archivo válido abierto para lectura.
ENOTDIR
El descriptor fd no está asociado con un directorio.

La opendir() función fallará si:

EACCES
Se deniega el permiso de búsqueda para el componente del prefijo de ruta de dirname o se deniega el permiso de lectura para dirname.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del dirname argumento.
ENAMETOOLONG

La longitud de un componente de una ruta de acceso es mayor que {NAME_MAX}.
ENOENT
Un componente de dirname no nombra un directorio existente o dirname es una cadena vacía.
ENOTDIR
Un componente de dirname nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.

La opendir() función puede fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del dirname argumento.
EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.
ENAMETOOLONG

La longitud de una ruta de acceso excede {PATH_MAX}, o la resolución de la ruta de acceso de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
ENFILE
Hay demasiados archivos abiertos actualmente en el sistema.

Encontrar y Abrir un Archivo

El siguiente programa busca en un directorio dado buscando archivos cuyo nombre no comienza con un punto y cuyo tamaño es mayor que 1 MiB.

#include <stdio.h>
#include <dirent.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <stdint.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    struct stat statbuf;
    DIR *d;
    struct dirent *dp;
    int dfd, ffd;
    if ((d = fdopendir((dfd = open("./tmp", O_RDONLY)))) == NULL) {
        fprintf(stderr, "Cannot open ./tmp directory\n");
        exit(1);
    }
    while ((dp = readdir(d)) != NULL) {
        if (dp->d_name[0] == '.')
            continue;
        /* there is a possible race condition here as the file
         * could be renamed between the readdir and the open */
        if ((ffd = openat(dfd, dp->d_name, O_RDONLY)) == -1) {
            perror(dp->d_name);
            continue;
        }
        if (fstat(ffd, &statbuf) == 0 && statbuf.st_size > (1024*1024)) {
            /* found it ... */
            printf("%s: %jdK\n", dp->d_name,
                (intmax_t)(statbuf.st_size / 1024));
        }
        close(ffd);
    }
    closedir(d); // note this implicitly closes dfd
    return 0;
}

USO EN APLICACIONES

La opendir() función debe usarse en conjunto con readdir(), closedir(), y rewinddir() para examinar el contenido del directorio (vea la sección EJEMPLOS en readdir()). Este método es recomendado para la portabilidad.

JUSTIFICACIÓN

El propósito de la fdopendir() función es permitir abrir archivos en directorios distintos al directorio de trabajo actual sin exposición a condiciones de carrera. Cualquier parte de la ruta de un archivo podría ser cambiada en paralelo a una llamada a opendir(), resultando en un comportamiento indefinido.

Basado en implementaciones históricas, las reglas sobre archivos descriptores se aplican también a los flujos de directorio. Sin embargo, este volumen de POSIX.1‐2017 no exige que el flujo de directorio sea implementado usando descriptores de archivo. La descripción de closedir() aclara que si se usa un archivo descriptor para el flujo de directorio, es obligatorio que closedir() desasigne el archivo descriptor. Cuando se usa un archivo descriptor para implementar el flujo de directorio, se comporta como si el FD_CLOEXEC hubiera sido establecido para el archivo descriptor.

Las entradas de directorio para dot y dot-dot son opcionales. Este volumen de POSIX.1‐2017 no proporciona una forma de probar a priori su existencia porque una aplicación que sea portable debe ser escrita para buscar (e ignorar normalmente) esas entradas. Escribir código que presuma que son las dos primeras entradas no siempre funciona, ya que muchas implementaciones permiten que no sean las dos primeras entradas, con una entrada "normal" precediéndolas. Hay un valor insignificante en proporcionar una forma de determinar qué hace la implementación porque el código para tratar con dot y dot-dot debe ser escrito de todos modos y porque tal bandera se añadiría a la lista de esas banderas (que ha probado en sí misma ser objetable) y podría serbused.

Dado que la estructura y la asignación de búfer, si las hay, para las operaciones de directorio están definidas por la implementación, este volumen de POSIX.1-2017 no impone requisitos de portabilidad para construcciones erróneas del programa, datos erróneos o el uso de valores no especificados, como el uso o la referencia de un valor de dirp o un valor de estructura dirent después de que un flujo de directorio se haya cerrado o después de que fork() o una de las llamadas de función exec se hayan realizado.
