--changed-within date|duration
Filtrar los resultados basándose en la hora de modificación del archivo. Se devolverán los archivos con marcas de tiempo de modificación mayores que el argumento. El argumento se puede proporcionar como una duración (10h, 1d, 35min) o como un punto específico en tiempo en formato RFC3339 completo con zona horaria, como una fecha o fecha y hora en la zona horaria local (YYYY-MM-DD o YYYY-MM-DD HH:MM:SS), o como el prefijo '@' seguido del número de segundos desde la época Unix (@[0-9]+). --change-newer-than, --newer o --changed-after se pueden usar como alias.

Ejemplos:
--changed-within 2weeks
--change-newer-than "2018-10-27 10:00:00"
--newer 2018-10-27
--changed-after @1704067200

--changed-before date|duration
Filtrar los resultados basándose en la hora de modificación del archivo. Se devolverán los archivos con marcas de tiempo de modificación menores que el argumento. El argumento se puede proporcionar como una duración (10h, 1d, 35min) o como un punto específico en tiempo en formato RFC3339 completo con zona horaria, como una fecha o fecha y hora en la zona horaria local (YYYY-MM-DD o YYYY-MM-DD HH:MM:SS), o como el prefijo '@' seguido del número de segundos desde la época Unix (@[0-9]+). --change-older-than o --older se pueden usar como alias.

Ejemplos:
--changed-before "2018-10-27 10:00:00"
--change-older-than 2weeks
--older @1704067200

-o, --owner [user][:group]
Filtrar archivos por su usuario y/o grupo. Formato: [(user|uid)][:(group|gid)]. Cualquier lado es opcional. Anteponer un '!' a cualquiera de los lados para excluir archivos en su lugar.

Ejemplos:
--owner john
--owner :students
--owner "!john:students"

--base-directory path
Cambiar el directorio de trabajo actual de fd a la ruta proporcionada. Esto significa que los resultados de búsqueda se mostrarán con respecto a la ruta base dada. Ten en cuenta que las rutas relativas que se pasan a fd a través del argumento posicional path o la opción --search-path también se resolverán relativas a este directorio.
--path-separator separator
Establecer el separador de ruta a usar al imprimir las rutas de archivo. El valor por defecto es el separador específico del SO ('/' en Unix, '\' en Windows).
--search-path search-path
Proporcionar rutas para buscar como alternativa al argumento posicional path Cambia el uso a ´fd [FLAGS/OPTIONS] --search-path PATH --search-path PATH2 [PATTERN]´
--format fmt
Especificar una cadena de plantilla que se usa para imprimir una línea para cada archivo encontrado.

Los siguientes marcadores de posición se sustituyen en la cadena para cada archivo antes de imprimir:

{}
ruta (del resultado de búsqueda actual)
{/}
nombre base
{//}
directorio padre
{.}
ruta sin la extensión del archivo
{/.}
nombre base sin la extensión del archivo
{{
'{' literal (una secuencia de escape)
}}
'}' literal (una secuencia de escape)

Ten en cuenta que puedes usar "{{" y "}}" para escapar "{" y "}" respectivamente, lo cual es especialmente útil si necesitas incluir el texto literal de uno de los marcadores de posición anteriores.

-x, --exec command
Ejecutar command para cada resultado de búsqueda en paralelo (usa --threads=1 para la ejecución secuencial de comandos).

Ten en cuenta que todos los argumentos posicionales posteriores se consideran argumentos para el command - no para fd. Por lo tanto, se recomienda colocar la opción -x/--exec al final. Alternativamente, puedes proporcionar un argumento ';' para terminar la lista de argumentos y continuar con más opciones de fd. La mayoría de los shells requieren escapar ';': '\;'. Esta opción se puede especificar múltiples veces, en cuyo caso todos los comandos se ejecutan para cada archivo encontrado, en el orden en que se proporcionan. En ese caso, debes proporcionar un argumento ';' para todos los comandos excepto el último.

Si el paralelismo está habilitado, el orden en que se ejecutarán los comandos es no determinista. E incluso con --threads=1, el orden lo determina el sistema operativo y puede no ser el que esperas. Por lo tanto, se recomienda que no dependas de ningún orden de los resultados.

Antes de ejecutar el comando, cualquier patrón de marcador de posición en el comando se reemplaza con los valores correspondientes para el archivo actual. Se usan los mismos marcadores de posición que en la opción "--format".

Si no hay ningún marcador de posición presente, se asume un "{}" implícito al final.

Ejemplos:


- encontrar todos los archivos *.zip y descomprimirlos:


fd -e zip -x unzip


- encontrar archivos *.h y *.cpp y ejecutar "clang-format -i .." para cada uno de ellos:


fd -e h -e cpp -x clang-format -i


- Convertir todos los archivos *.jpg a archivos *.png:


fd -e jpg -x convert {} {.}.png

-X, --exec-batch command
Ejecutar command una vez, con todos los resultados de búsqueda como argumentos.

El orden de los argumentos no es determinista y no se debe depender de él.

Esto usa los mismos marcadores de posición que "--format" y "--exec", pero en lugar de expandirse una vez por invocación de comando, cada argumento que contiene un marcador de posición se expande para cada archivo en un lote y se pasa como argumentos separados.

Si no hay ningún marcador de posición presente, se asume un "{}" implícito al final.

Al igual que con --exec, se asume que los argumentos posteriores forman parte de command hasta el final de los argumentos del comando o un argumento ';'. Véase arriba.

Al igual que con --exec, esto se puede usar varias veces, en cuyo caso cada comando se ejecutará en el orden dado.

Ejemplos:


- Encontrar todos los archivos test_*.py y abrirlos en tu editor favorito:


fd -g 'test_*.py' -X vim


Tenga en cuenta que esto ejecuta un único proceso "vim" con todos los resultados de búsqueda como argumentos.


- Encontrar todos los archivos *.rs y contar las líneas con "wc -l ...":


fd -e rs -X wc -l

--batch-size size
Número máximo de argumentos a pasar al comando dado con -X. Si el número de resultados es mayor que el tamaño dado, el comando dado con -X se ejecuta de nuevo con los argumentos restantes. Un tamaño de lote de cero significa que no hay límite (por defecto), pero tenga en cuenta que el procesamiento por lotes aún puede ocurrir debido a restricciones del SO sobre la longitud máxima de las líneas de comando.

ENTORNO

LS_COLORS
Determina cómo colorear los resultados de búsqueda, véase dircolors(1).
NO_COLOR
Desactiva la salida coloreada.
XDG_CONFIG_HOME, HOME
Se utiliza para localizar el archivo de ignorados global. Si XDG_CONFIG_HOME está definido, usar $XDG_CONFIG_HOME/fd/ignore. De lo contrario, usar $HOME/.config/fd/ignore.

ARCHIVOS

.fdignore
Este archivo funciona de manera similar a un archivo .gitignore en cualquier lugar del árbel buscado y especifica patrones que deben excluirse de la búsqueda. Sin embargo, este archivo es específico de fd y se usará incluso si se usa la opción --no-ignore-vcs.
$XDG_CONFIG_HOME/fd/ignore
Archivo de ignorados global. A menos que el modo de ignorado esté desactivado (como con --no-ignore), las entradas de ignorado en este archivo serán ignoradas, como si fuera un archivo .fdignore en el directorio actual.

EJEMPLOS

Encontrar archivos y directorios que coincidan con el patrón 'needle':
$ fd needle
Iniciar una búsqueda en un directorio dado (/var/log):
$ fd nginx /var/log
Encontrar todos los archivos de Python (todos los archivos con la extensión .py) en el directorio actual:
$ fd -e py
Abrir todos los resultados de búsqueda con vim:
$ fd pattern -X vim

Consejos y Trucos

•
Si añades ".git/" a tu archivo de ignorados global ($XDG_CONFIG_HOME/fd/ignore), entonces las carpetas ".git" serán ignoradas por defecto, incluso cuando se usa la opción --hidden.
•
Puedes usar un alias de shell o un script envoltorio para pasar los indicadores deseados a fd por defecto. Por ejemplo, si no te gusta el comportamiento por defecto de respetar gitignore, puedes usar `alias fd="/usr/bin/fd --no-ignore-vcs"` en tu .bashrc para crear un alias para fd que no ignore los archivos de git por defecto.
