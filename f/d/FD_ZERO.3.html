Un descriptor de archivo se considera listo si es posible realizar una operación de E/S correspondiente (por ejemplo, read(2), o un write(2) suficientemente pequeño) sin

pselect(

)

La llamada al sistema pselect() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo se convierta en listo o hasta que una señal sea

capturada.

El funcionamiento de select() y pselect() es idéntico, excepto por estas tres

diferencias:
•
select() usa un tiempo de espera que es un struct timeval (con segundos y microsegundos), mientras que pselect() usa un struct timespec (con segundos y nanosegundos)
.
•
select() puede actualizar el argumento timeout para indicar cuánto tiempo quedaba. pselect() no cambia este
argumento.
•
select() no tiene el argumento sigmask, y se comporta como pselect() llamado con NULL sigm
as
k.

sigmask es un puntero a una máscara de señales (véase sigprocmask(2)); si no es NULL, entonces pselect() primero reemplaza la máscara de señales actual por la orientado por sigmask, luego realiza la función "select" y después restaura la máscara de señal original. (Si sigmask es NULL, la máscara de señal no se modifica durante la llamada a pselect()).

Aparte de la diferencia en la precisión del argumento timeout, la siguiente llamada a pselect():


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask);

es equivalente a ejecutar *atmicamente* las siguientes llamadas:


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

La razón por la que se necesita pselect() es que si se desea esperar por una señal o por un descriptor de archivo que esté listo, entonces se necesita una prueba atómica para evitar condiciones de carrera. (Suponga que el manejador de señales establece una bandera global y retorna. Luego, una prueba de esta bandera global seguida de una llamada a select() podría colgarse indefinidamente si la señal llegara justo después de la prueba pero justo antes de la llamada. Por el contrario, pselect() permite bloquear primero las señales, manejar las señales que han llegado, y luego llamar a pselect() con el sigmask deseado, evitando la carrera).

El timeout

El argumento timeout para select() es una estructura del siguiente tipo:


struct timeval {
    time_t      tv_sec;         /* segundos */
    suseconds_t tv_usec;        /* microsegundos */
};

El argumento correspondiente para pselect() es una estructura timespec(3).

En Linux, select() modifica timeout para reflejar la cantidad de tiempo no dormido; la mayoría de las otras implementaciones no hacen esto. (POSIX.1 permite cualquiera de los dos comportamientos). Esto causa problemas tanto cuando el código de Linux que lee timeout se porta a otros sistemas operativos, como cuando el código se porta a Linux que reutiliza una struct timeval para múltiples select()s en un bucle sin reinicializarla. Considere que timeout no está definido después de que select() retorna.

VALOR DE RETORNO

En caso de éxito, select() y pselect() retornan el número de descriptores de archivo contenidos en los tres conjuntos de descriptores retornados (es decir, el número total de bits que están activados en readfds, writefds, exceptfds). El valor de retorno puede ser cero si el tiempo de espera expiró antes de que algún descriptor de archivo estuviera listo.

En caso de error, se retorna -1 y se establece errno para indicar el error; los conjuntos de descriptores de archivo no se modifican y timeout se vuelve indefinido.

ERRORES

EBADF
Se proporcionó un descriptor de archivo inválido en uno de los conjuntos. (Quizás un descriptor de archivo que ya estaba cerrado, o uno en el que ha ocurrido un error). Sin embargo, vea BUGS.
EINTR
Se capturó una señal; vea signal(7).
EINVAL
nfds es negativo o excede el límite de recursos RLIMIT_NOFILE (vea getrlimit(2)).
EINVAL
El valor contenido en timeout es inválido.
ENOMEM
No se pudo asignar memoria para tablas internas.

VERSIONES

En otros sistemas UNIX, select() puede fallar con el error EAGAIN si el sistema no logra asignar recursos internos del kernel, en lugar de ENOMEM como lo hace Linux. POSIX especifica este error para poll(2), pero no para select(). Los programas portables pueden desear verificar EAGAIN y hacer un bucle, al igual que con EINTR.

NOTAS

La siguiente cabecera también proporciona el tipo fd_set: <sys/time.h>.

Una fd_set es un buffer de tamaño fijo. Ejecutar FD_CLR() o FD_SET() con un valor de fd que sea negativo o igual o mayor que FD_SETSIZE resultará en un comportamiento indefinido. Además, POSIX requiere que fd sea un descriptor de archivo válido.

La operación de select() y pselect() no se ve afectada por la bandera O_NONBLOCK.

El truco de la tubería auto

En sistemas que carecen de pselect(), se puede lograr un manejo de señales confiable (y más portable) utilizando el truco de la tubería auto. En esta técnica, un manejador de señales escribe un byte en una tubería cuyo otro extremo es monitoreado por select() en el programa principal. (Para evitar posibles bloqueos al escribir en una tubería que pueda estar llena o leer de una tubería que pueda estar vacía, se utiliza E/S no bloqueante al leer y escribir en la tubería).

Emulando usleep(3)

Antes de la llegada de usleep(3), algunos códigos emplearon una llamada a select() con todos los tres conjuntos vacíos, nfds cero, y un timeout no NULL como una forma bastante portable de dormir con precisión subsegundo.

Correspondencia entre las notificaciones de select() y poll()

Dentro del código fuente del kernel de Linux, encontramos las siguientes definiciones que muestran la correspondencia entre las notificaciones de condición de lectura, escritura y excepcional de select() y las notificaciones de eventos proporcionadas por poll(2) y epoll(7):

                     EPOLLHUP | EPOLLERR)
                   /* Listo para leer */
#define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT |
                     EPOLLERR)

#define POLLEX_SET  (EPOLLPRI)
                   /* Condición excepcional */

Aplicaciones multihilo

Si un descriptor de archivo que está siendo monitoreado por select() se cierra en otro hilo, el resultado no está especificado. En algunos sistemas UNIX, select() se desbloquea y retorna, con una indicación de que el descriptor de archivo está listo (una operación de E/S subsiguiente probablemente fallará con un error, a menos que otro proceso reabra el descriptor de archivo entre el momento en que select() retorna y se realiza la operación de E/S). En Linux (y algunos otros sistemas), cerrar el descriptor de archivo en otro hilo no tiene efecto en select(). En resumen, cualquier aplicación que dependa de un comportamiento particular en este escenario debe considerarse defectuosa.

Diferencias biblioteca C/kernel

El kernel de Linux permite conjuntos de descriptores de archivo de tamaño arbitrario, determinando la longitud de los conjuntos a verificar a partir del valor de nfds. Sin embargo, en la implementación de glibc, el tipo fd_set tiene un tamaño fijo. Vea también BUGS.

La interfaz pselect() descrita en esta página es implementada por glibc. La llamada al sistema subyacente de Linux se llama pselect6(). Esta llamada al sistema tiene un comportamiento ligeramente diferente de la función wrapper de glibc.

La llamada al sistema pselect6() de Linux modifica su argumento timeout. Sin embargo, la función wrapper de glibc oculta este comportamiento utilizando una variable local para el argumento de tiempo de espera que se pasa a la llamada al sistema. Por lo tanto, la función pselect() de glibc no modifica su argumento timeout; este es el comportamiento requerido por POSIX.1-2001.

El último argumento de la llamada al sistema pselect6() no es un puntero sigset_t *, sino una estructura de la forma:


struct {
    const kernel_sigset_t *ss;   /* Puntero al conjunto de señales */
    size_t ss_len;               /* Tamaño (en bytes) del objeto
                                    apuntado por 'ss' */
};

Esto permite a la llamada al sistema obtener tanto un puntero al conjunto de señales como su tamaño, al tiempo que permite el hecho de que la mayoría de las arquitecturas admiten un máximo de 6 argumentos a una llamada al sistema. Vea sigprocmask(2) para una discusión de la diferencia entre la noción de conjunto de señales del kernel y de libc.

DESCRIPTION

The select() system call checks whether one or more file descriptors are ready to perform I/O or have exceptional conditions pending. The file descriptors to be checked are passed in three sets of type fd_set: readfds, writefds, and exceptfds. The first argument, nfds, is the highest-numbered file descriptor in any of the three sets, plus 1. The remaining arguments are pointers to the fd_set structures. The timeout argument specifies the duration the call should block. If timeout is a null pointer, the call blocks indefinitely until at least one file descriptor is ready.

If readfds is not NULL, it points to an fd_set structure that contains the file descriptors that are to be checked for their readiness to be read. If writefds is not NULL, it points to an fd_set structure that contains the file descriptors that are to be checked for their readiness to be written. If exceptfds is not NULL, it points to an fd_set structure that contains the file descriptors that are to be checked for exceptional conditions.

The select() call returns when:

  • At least one file descriptor in the specified sets is ready for I/O.
  • The call is interrupted by a signal.
  • The specified timeout expires.

Upon return, the fd_set structures pointed to by readfds, writefds, and exceptfds are modified to indicate which file descriptors are ready. File descriptors that are not ready are removed from the sets. File descriptors that are ready are left in the sets. If a set is a NULL pointer, then that set is not checked.

The timeout argument points to a struct timeval (defined in <sys/time.h>) which specifies the number of seconds and microseconds to wait for a file descriptor to become ready. If the timeout value is zero, select() returns immediately after checking the file descriptors. If timeout is not NULL, the structure it points to is not changed by the call (unless the call is interrupted by a signal, in which case the value may be updated on Linux). The pselect() system call, on the other hand, has a timeout argument of type const struct timespec and its value is guaranteed to be unchanged on return.

The nfds argument is the number of file descriptors to be checked. It is the highest file descriptor number plus 1. For example, if you want to check file descriptors 0, 1, and 5, then nfds should be 6.

The pselect() system call is similar to select(), but it also takes an additional argument, sigmask, which is a pointer to a signal mask. The pselect() call atomically sets the signal mask for the calling thread to the value specified by sigmask and then waits for I/O readiness. When pselect() returns, it restores the signal mask of the calling thread to its original value. This is useful for preventing signal interruptions during critical sections of code.

RETURN VALUE

On success, select() and pselect() return the total number of file descriptors contained in the selected sets. This count is zero if the timeout expires before any file descriptors are ready. nfds is the highest file descriptor plus 1. If no file descriptor is ready within the specified timeout, zero is returned.

On error, -1 is returned, and errno is set to indicate the error.

ERRORS

EBADF
An invalid file descriptor was given in one of the sets. For example, a file descriptor number was negative or greater than or equal to FD_SETSIZE (see NOTES), or the file descriptor is invalid.
EINTR
A signal was caught before any of the specified file descriptors became ready.
EINVAL
nfds is negative or too large. The timeout argument is invalid.
ENOMEM
Could not allocate memory for internal structures.

VERSIONS

The fd_set type is a fixed-size type, with FD_SETSIZE defined as 1024. This limits the range of file descriptors that can be specified in a file descriptor set. The Linux kernel imposes no fixed limit, but the glibc implementation makes fd_set a fixed-size type, with FD_SETSIZE defined as 1024, and the FD_*() macros operating according to that limit. To monitor file descriptors greater than 1023, use poll(2) or epoll(7) instead.

The implementation of the fd_set arguments as value-result arguments is a design error that is avoided in poll(2) and epoll(7).

According to POSIX, select() should check all specified file descriptors in the three file descriptor sets, up to the limit nfds-1. However, the current implementation ignores any file descriptor in these sets that is greater than the maximum file descriptor number that the process currently has open. According to POSIX, any such file descriptor that is specified in one of the sets should result in the error EBADF.

Starting with glibc 2.1, glibc provided an emulation of pselect() that was implemented using sigprocmask(2) and select(). This implementation remained vulnerable to the very race condition that pselect() was designed to prevent. Modern versions of glibc use the (race-free) pselect() system call on kernels where it is provided.

On Linux, select() may report a socket file descriptor as "ready for reading", while nevertheless a subsequent read blocks. This could for example happen when data has arrived but upon examination has the wrong checksum and is discarded. There may be other circumstances in which a file descriptor is spuriously reported as ready. Thus it may be safer to use O_NONBLOCK on sockets that should not block.

On Linux, select() also modifies timeout if the call is interrupted by a signal handler (i.e., the EINTR error return). This is not permitted by POSIX.1. The Linux pselect() system call has the same behavior, but the glibc wrapper hides this behavior by internally copying the timeout to a local variable and passing that variable to the system call.

The pselect() function is specified by POSIX.1-2008.

EXAMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Watch stdin (fd 0) to see when it has input.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Wait up to five seconds.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Don't rely on the value of tv now! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Data is available now.\n");
        /* FD_ISSET(0, &rfds) will be true.  */
    else
        printf("No data within five seconds.\n");
    exit(EXIT_SUCCESS);
}
