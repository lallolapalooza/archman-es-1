DESCRIPCIÓ

N

Las cadenas se almacenan por número, plataforma, codificación e idioma. Se accede a las cadenas

como: 
$f->{'name'}{'strings'}[$number][$platform_id][$encoding_id]
{$language_id}

Nótese que el idioma se almacena en un array asociativo debido a su naturaleza dispersa en algunas plataformas como Microsoft ($pid = 3). Nótese también que el orden del array es diferente del orden del array almacenado (plataforma, codificación, idioma, número) para permitir una fácil manipulación de cadenas por número (que es lo que supongo que la mayoría de la gente querrá hacer)

.

Por defecto, $Font::TTF::Name::utf8 está establecido a 1, y las cadenas se almacenarán como UTF8 siempre que sea posible. El método "is_utf8" puede usarse para averiguar si una cadena en una plataforma y codificación particulares será devuelta como UTF8. Las cadenas Unicode se convierten siempre si se solicita utf8. De lo contrario, las cadenas se almacenan según la

plataforma:

Ahora tienes que establecer <$Font::TTF::Name::utf8> a 0 para obtener el comportamiento

antiguo.
Apple Unicode (id de plataforma =
0)
Los datos se almacenan como UCS2 en orden de red. No hay un id de codificación para esta plataforma pero sí hay ids de idioma como los ids de idioma de
Mac.
Mac (id de plataforma
= 1)
Los datos se almacenan como datos binarios de 8 bits, dejando la interpretación al usuario según el id de
codificación.
Unicode (id de plataforma =
2)
Actualmente se almacena como UCS2 de 16 bits en orden de red. Con la publicación de Perl 5.005 esto cambiará a utf8 asumiendo la semántica UCS2 actual para todos los ids de
codificación.
Windows (id de plataforma =
3)
Al igual que en Unicode, los datos se almacenan actualment
e como UCS2 de 16 bits en orden de red. Con la public
ación de Perl 5.005 esto cambiará a utf8 asumiendo la semán
tica UCS2 actual para todos los ids de codificación.
