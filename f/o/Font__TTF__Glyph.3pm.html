NOMBRE

Font::TTF::Glyph - Contiene la información de un solo glifo

DESCRIPCIÓN

Esta es la descripción de un solo glifo tal como se almacena en una fuente TT. Al crearlo, solo se lee su cabecera. Así, puedes obtener el cuadro delimitador de cada glifo sin tener que leer toda la demás información.

VARIABLES DE INSTANCIA

Además de las variables con nombre en la cabecera de un glifo ("xMin" etc.), también hay variables de instancia en mayúsculas para almacenar información de trabajo, principalmente de la tabla de ubicaciones.

Variables para todos los glifos:

Los atributos estándar que tiene cada glifo son:

numberOfContours
Para glifos simples, este será el número de contornos. Para glifos compuestos, este será -1.
xMin
yMin
xMax
yMax
Estos identifican el cuadro delimitador del glifo.

También hay otras variables de instancia derivadas para cada glifo que se leen cuando se lee el glifo completo (mediante "read_dat"):

instLen
Número de bytes en las instrucciones de ajuste (advertencia: esta variable está obsoleta, usa "length($g-"{'hints'})> en su lugar).
hints
La cadena que contiene el código de ajuste para el glifo

Variables para glifos simples (numberOfContours >= 0):

endPoints
Un array de puntos finales para cada contorno en el glifo. Hay "numberOfContours" contornos en un glifo. El número de puntos en un glifo es igual al punto final más alto de un contorno.
numPoints
Este es un valor generado que contiene el número total de puntos para este glifo simple.

También hay una serie de arrays indexados por número de punto:

flags
Los indicadores asociados con la lectura de este punto. Los indicadores de un punto se recalculan para un punto cuando se "update"a. Por lo tanto, los indicadores no son muy útiles. El único bit importante es el bit 0, que indica si el punto es un punto 'on' (en la curva) o un punto 'off' (fuera de la curva).
x
La coordenada x absoluta del punto.
y
La coordenada y absoluta del punto

Variables para glifos compuestos (numberOfContours == -1):

metric
Contiene el número de componente (no su número de glifo) del componente del cual deben tomarse las métricas para este glifo.
comps
Este es un array de hashes para cada componente. Cada hash tiene una serie de elementos:
glyph
El número de glifo del glifo que comprende este componente del compuesto. NOTA: En algunas fuentes mal generadas, "glyph" puede contener un valor numérico pero ese glifo podría no existir realmente en el archivo de la fuente. Esto podría ocurrir en cualquier glifo, pero es particularmente probable para glifos que no tienen trazos, como SPACE, U+00A0 NO-BREAK SPACE, o U+200B ZERO WIDTH SPACE.
args
Un array de dos argumentos que pueden ser una coordenada x, y o dos puntos de unión (uno en el glifo base y el otro en el componente). Consulta los indicadores para más detalles.
flag
El indicador para este componente
scale
Un array de 4 números para el escalado del componente. Esto permite estirar, rotar, etc. Ten en cuenta que el escalado se aplica a las coordenadas de colocación (en lugar de los puntos de unión) antes de ubicar en lugar de después.
numPoints
Este es un valor generado que contiene el número de componentes leídos para este glifo compuesto.

Variables de instancia privadas:

INFILE (P)
El archivo de entrada del cual leer cualquier información
LOC (P)
Ubicación relativa al inicio de la tabla glyf en el archivo leído
BASE (P)
La ubicación de la tabla glyf en el archivo leído
LEN (P)
Este es el número de bytes requeridos por el glifo. Debe mantenerse al día llamando al "update" método siempre que cualquiera de los contenidos del glifo cambie.
OUTLOC (P)
Ubicación relativa al inicio de la tabla glyf. Esta variable solo está activa mientras el proceso de salida está en curso. Se usa para informar a la tabla de ubicaciones dónde se encuentra el glifo, ya que la tabla glyf se genera antes que la tabla loca debido al orden alfabético.
OUTLEN (P)
Esto indica la longitud de los datos del glifo cuando se genera. Esto refleja con más precisión la forma de memoria interna que la "LEN" variable que solo refleja la longitud del archivo leído. La "OUTLEN" variable solo se establece después de llamar a "out" o "out_dat".

Edición

Si quieres editar un glifo de alguna manera, entonces debes leer el glifo con read_dat, luego hacer tus cambios y luego actualizar el glifo o establecer la $g->{' isDirty'} variable. La aplicación debe asegurarse de que las siguientes variables de instancia sean correctas, a partir de las cuales update calculará el resto, incluyendo la información del cuadro delimitador.

numPoints
numberOfContours
endPoints
x, y, flags         (solo el bit 0 de flags)
instLen
hints

Para componentes, los numPoints, x, y, endPoints y flags no son requeridos pero la siguiente información es requerida para cada componente.

flag                (bits 2, 10, 11, 12)
glyph
args
scale
metric              (variable de instancia del glifo)

MÉTODOS

Font::TTF::Glyph->new(%parms)

Crea un nuevo glifo estableciendo varias variables de instancia

$g->read

Lee el componente de cabecera del glifo (numberOfContours y cuadro delimitador) y también el contenido del glifo, pero en un campo de datos en lugar de descomponerlo en sus estructuras constituyentes. Usa read_dat para esto.

$g->read_dat

Lee el contenido del glifo (componentes y curvas, etc.) desde el almacén de memoria "DAT" dentro de las estructuras del objeto.

$g->out($fh)

Escribe los datos del glifo a outfile

$g->out_xml($context, $depth)

Genera una descripción XML del glifo

$g->dirty($val)

Esto establece la bandera de suciedad al valor dado o a 1 si no se da ningún valor. Devuelve el valor de la bandera

$g->update

Genera un "$self-"{'DAT'}> a partir de las estructuras internas, si los datos se han leído en las estructuras en primer lugar. Si está construyendo un glifo desde cero, necesitará establecer la variable de instancia ' isDirty'.

$g->update_bbox

Actualiza el cuadro delimitador de este glifo de acuerdo con los puntos en el glifo

$g->maxInfo

Devuelve mucha información sobre un glifo para que la tabla "maxp" "maxp" pueda actualizarse por sí misma. Devuelve una matriz que contiene las contribuciones de este glifo a maxPoints, maxContours, maxCompositePoints, maxCompositeContours, maxSizeOfInstructions, maxComponentElements y maxComponentDepth.

$g->empty

Vacía el glifo de toda la información hasta el nivel de no haber sido leído. Útil para ahorrar memoria en aplicaciones con muchos glifos siendo leídos

$g->get_points

Este método crea información de puntos para un glifo compuesto. La información se almacena en el mismo lugar que si el glifo no fuera un compuesto, pero dado que numberOfContours es negativo, el glifo sigue marcándose como un compuesto

$g->get_refs

Devuelve una matriz de todos los identificadores de glifos que se utilizan para formar este glifo. Es decir, todos los compuestos y sus referencias y así sucesivamente. Si este glifo no es un compuesto, devuelve una matriz vacía.

Tenga en cuenta la advertencia sobre fuentes malas que referencian glifos inexistentes en VARIABLES DE INSTANCIA arriba. Esta función no intentará filtrar números de glifos inexistentes.

ERRORES

  • Las variables de instancia utilizadas aquí son algo torpes e inconsistentes con las otras tablas.
  • "update" no vuelve a calcular el cuadro delimitador ni "numberOfContours".
