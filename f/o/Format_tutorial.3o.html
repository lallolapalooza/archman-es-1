Usando el módulo Format

Principios

El salto de línea se basa en tres conceptos:

-cajas (boxes): una caja es una unidad lógica de impresión formateada, que define un comportamiento del motor de impresión formateada para mostrar el material dentro de la caja.

-indicadores de salto de línea (break hints): un indicador de salto de línea es una directiva para el motor de impresión formateada que propone romper la línea aquí, si es necesario para imprimir correctamente el resto del material. De lo contrario, el motor de impresión formateada nunca rompe las líneas (excepto "en caso de emergencia" para evitar una salida muy mala). En resumen, un indicador de salto de línea le dice al formateador que un salto de línea aquí puede ser apropiado.

-reglas de indentación: Cuando ocurre un salto de línea, el motor de impresión formateada fija la indentación (o cantidad de espacios iniciales) de la nueva línea utilizando reglas de indentación, como sigue:

-Una caja puede indicar la indentación adicional de cada nueva línea abierta en su ámbito. Esta indentación adicional se denomina indentación de salto de caja.

-Un indicador de salto de línea también puede establecer la indentación adicional de la nueva línea que puede disparar. Esta indentación adicional se denomina indentación de salto de indicador.

- Si el indicador de salto de línea bh dispara una nueva línea dentro de la caja b, entonces la indentación de la nueva línea es simplemente la suma de: la indentación actual de la caja b + la indentación adicional de salto de caja, según lo define la caja b + la indentación adicional de salto de indicador, según lo define el indicador de salto de línea bh.

Cajas

Hay 4 tipos de cajas. (La más usada es el tipo de caja "hov", así que salta el resto al principio).

-caja horizontal (caja h, obtenida mediante el procedimiento Format.open_hbox): dentro de esta caja, los indicadores de salto de línea no provocan saltos de línea.

-caja vertical (caja v, obtenida mediante el procedimiento Format.open_vbox): dentro de esta caja, cada indicador de salto de línea provoca una nueva línea.

-caja vertical/horizontal (caja hv, obtenida mediante el procedimiento Format.open_hvbox): si es posible, toda la caja se escribe en una sola línea; de lo contrario, cada indicador de salto de línea dentro de la caja provoca una nueva línea.

-caja vertical u horizontal (caja hov, obtenida mediante los procedimientos Format.open_box o Format.open_hovbox): dentro de esta caja, los indicadores de salto de línea se utilizan para cortar la línea cuando no queda más espacio en la línea. Hay dos tipos de cajas "hov", puedes encontrar los detalles a continuación. En una primera aproximación, consideremos estas dos clases de cajas "hov" como equivalentes y obtenidas llamando al procedimiento Format.open_box.

Permíteme dar un ejemplo. Supongamos que podemos escribir 10 caracteres antes del margen derecho (que indica que no queda más espacio). Representamos cada carácter como un signo -; los caracteres [ y ] indican la apertura y el cierre de una caja y b representa un indicador de salto proporcionado al motor de impresión formateada.

La salida "--b--b--" se muestra de la siguiente manera (el símbolo b representa el valor del salto que se explica a continuación):

Dentro de una caja "h":

--b--b--

Dentro de una caja "v":

--b
--b
--

Dentro de una caja "hv":

Si hay suficiente espacio para imprimir la caja en la línea:

--b--b--

Pero "---b---b---", que no cabe en la línea, se escribe así:

---b
---b
---

Dentro de una caja "hov":

Si hay suficiente espacio para imprimir la caja en la línea:

--b--b--

Pero si "---b---b---" no cabe en la línea, se escribe como:

---b---b
---

El primer indicador de salto no provoca un salto de línea, ya que hay suficiente espacio en la línea. El segundo provoca un salto de línea, ya que no queda espacio para imprimir el material que le sigue. Si el espacio restante en la línea fuera aún menor, el primer indicador de salto podría provocar un salto de línea y "---b---b---" se escribiría como:

---b
---b
---

Imprimiendo espacios

Los indicadores de salto de línea también se utilizan para producir espacios (si la línea no se divide al encontrar el salto, de lo contrario la nueva línea indica adecuadamente la separación entre los elementos de impresión). Se imprime un indicador de salto de línea usando print_break sp indent, y este entero sp se utiliza para imprimir "sp" espacios. Por lo tanto, print_break sp ... puede pensarse como: imprimir sp espacios o sacar una nueva línea.

Por ejemplo, si b es break 1 0 en la salida "--b--b--", obtenemos

dentro de una caja "h":

-- -- --

dentro de una caja "v":

--
--
--

dentro de una caja "hv":

-- -- --

o, según el espacio restante en la línea:

--
--
--

y de forma similar para las cajas "hov".

En general, una rutina de impresión que utiliza "format" no debería imprimir espacios en blanco directamente: la rutina debería usar indicadores de salto de línea en su lugar. (Por ejemplo, print_space () que es una abreviatura conveniente para print_break 1 0 y produce un solo espacio o rompe la línea).

Indentación de nuevas líneas

El usuario tiene 2 formas de fijar la indentación de las nuevas líneas:

Al definir la caja: cuando abres una caja, puedes fijar la indentación que se añade a cada nueva línea abierta dentro de esa caja.

Por ejemplo: open_hovbox 1 abre una caja "hov" con nuevas líneas indentadas 1 más que la indentación inicial de la caja. Con la salida "--[--b--b--b--", obtenemos:

---[--b--b
     --b--

con open_hovbox 2, obtenemos

---[--b--b
      --b--

Nota: el signo [ en la visualización no es visible en la pantalla, está ahí solo para materializar la apertura de la caja de impresión formateada. La última "pantalla" significa:

-----b--b
     --b--

Al definir el salto que provoca la nueva línea. Como se dijo anteriormente, se imprime un indicador de salto usando print_break sp indent. El entero indent se utiliza para fijar la indentación adicional de la nueva línea. Es decir, se suma al desplazamiento de indentación predeterminado de la caja donde ocurre el salto.

Por ejemplo, si [ representa la apertura de una caja "hov" con 1 como indentación adicional (obtenida por open_hovbox 1), y b es print_break 1 2, entonces de la salida "---[--b--b--b--", obtenemos:

   ---[-- --
         --
         --

Refinamiento en cajas hov

El tipo de caja "hov" se refina en dos categorías.

-la caja de empaquetado vertical u horizontal (obtenida mediante el procedimiento Format.open_hovbox): los indicadores de salto de línea se utilizan para cortar la línea cuando no queda más espacio en la línea; no ocurre una nueva línea si hay suficiente espacio en la línea.

-caja estructural vertical u horizontal (obtenida mediante el procedimiento Format.open_box): similar a la caja de empaquetado "hov", los indicadores de salto de línea se utilizan para cortar la línea cuando no queda más espacio en la línea; además, los indicadores de salto de línea que pueden mostrar la estructura de la caja provocan nuevas líneas incluso si hay suficiente espacio en la línea actual.

La diferencia entre una caja "hov" de empaquetado y una estructural se muestra mediante una rutina que cierra cajas y paréntesis al final de la impresión: con cajas de empaquetado, el cierre de cajas y paréntesis no provoca saltos de línea si hay suficiente espacio en la línea, mientras que con cajas estructurales cada indicador de salto de línea provocará un salto de línea. Por ejemplo, al imprimir "[(---[(----[(---b)]b)]b)]", donde "b" es un indicador de corte sin indentación adicional ( print_cut () ). Si "[ " significa apertura de una caja "hov" de empaquetado ( Format.open_hovbox 1), "[(---[(----[(---b)]b)]b)]" se imprime de la siguiente manera:

(---
 (----
  (---)))

NAME

Format - Pretty printing functions.

Module

Format

Documentation

The Format module provides a pretty printing routine. The general idea is that the programmer indicates in the text where the lines can be broken, and the pretty printing routine decides where to break them, in order to obtain a text fitting in a given width.

The pretty printing routine is based on boxes. A box is a rectangular area. The text is laid out within these boxes. Boxes can be nested. Each box has a width, and the pretty printer tries to fit the text within this width. If the text fits on a single line, it is printed that way. Otherwise, the text is broken down into several lines, and indented according to the nesting of boxes.

There are several kinds of boxes:

Vertical boxes
The contents are laid out vertically, one above the other.
Horizontal boxes
The contents are laid out horizontally, side by side.

The layout of the text within a box is determined by break hints. A break hint tells the pretty printer that a line break can occur at that point. Break hints can be tagged with indentation information, to control the indentation of the following text.

Here is a simple example of using boxes and break hints:

Format.open_box 0 opens a vertical box of width 0. Format.print_string prints a string. Format.print_space () prints a breakable space. Format.close_box () closes the current box.

    open Format
    open_box 0;;
    print_string "Hello";
    print_space ();;
    print_string "world";;
    close_box ();;
    print_newline ();;

If the line width is large enough, this produces:

    Hello world

If the line width is too small, this produces:

    Hello
    world

The functions open_box, open_hbox, and open_vbox open a new box. They take an integer argument, specifying the indentation of the box.

The function close_box closes the current box. It must be called exactly as many times as open_box, open_hbox, or open_vbox have been called.

The function print_space () prints a breakable space. If the text fits on one line, it is printed as a space. Otherwise, it is printed as a newline, and the following text is indented according to the current box indentation.

The function print_cut () is similar to print_space (), but it always produces a line break, even if the text fits on one line. This is useful for forcing line breaks at certain points.

The function print_break n m is a more general break hint. It takes two integers, n and m. If the text fits on one line, a space is printed. Otherwise, a newline is printed, and the following text is indented by m spaces. The value n is the number of spaces to print if no line break occurs. This is useful for controlling the spacing around break points.

The function print_flush () flushes the output buffer. It should be called at the end of the printing process.

Boxes and break hints

The layout of text within a box is determined by break hints. A break hint is a potential place where the text can be broken.

For example, consider the following structure:

    open_box 0;;
    print_string "[";
    open_box 1;;
    print_string "---";
    open_box 2;;
    print_string "----";
    open_box 3;;
    print_string "---";
    print_break 0 0;; (* a break hint *)
    print_string "]";
    close_box ();;
    print_string ")";
    close_box ();;
    print_string ")";
    close_box ();;
    print_string ")";
    close_box ();;
    print_newline ();;

If the line width is large enough, this produces:

    [--- ---- ---]

If the line width is smaller, the break hint will be used, and the output will be:

    [
     ---
      ----
       ---
    ]
    )
    )
    )

The `open_box 1`, each break hint that precedes a closing parenthesis can show the boxes structure, if it leads to a new line; hence "[(---[(----[(---b)]b)]b)]" is printed like this:

(---
 (----
  (---
   )
  )
 )

Each break hint increases indentation by one, both for opening and closing parenthesis, because the parenthesis are just characters and don't have special meaning for the formatter. Notice that the closing parenthesis is not vertically aligned with the opening parenthesis.

We can line up the opening and closing parenthesis vertically in two ways:

-by using a break hint "b" with negative indentation that matches the opening indentation of the box @;<0 -1>, canceling it.

-by using an additional box, and making all boxes and break hints use no indentation: "[([---[([----[([---]b)]]b)]]b)]"

In both cases the output would be this:

(---
 (----
  (---
  )
 )
)

Practical advice

When writing a pretty-printing routine, follow these simple rules:

-Boxes must be opened and closed consistently ( open_* and Format.close_box must be nested like parentheses).

-Never hesitate to open a box.

-Output many break hints, otherwise the pretty-printer is in a bad situation where it tries to do its best, which is always "worse than your bad".

-Break hints with negative indentation should only be used when you are sure that you don't exceed the indentation of the opening box (e.g. both part of the same function and an exact match). Exceeding the indentation of the opening box is not compositional.

-Do not try to force spacing using explicit spaces in the character strings. For each space you want in the output emit a break hint ( print_space () ), unless you explicitly don't want the line to be broken here. For instance, imagine you want to pretty print an OCaml definition, more precisely a let rec
ident = expression value definition. You will probably treat the first three spaces as "unbreakable spaces" and write them directly in the string constants for keywords, and print "let rec" before the identifier, and similarly write = to get an unbreakable space after the identifier; in contrast, the space after the = sign is certainly a break hint, since breaking the line after = is a usual (and elegant) way to indent the expression part of a definition. In short, it is often necessary to print unbreakable spaces; however, most of the time a space should be considered a break hint.

-Do not try to force new lines, let the pretty-printer do it for you: that's its only job. In particular, do not use Format.force_newline : this procedure effectively leads to a newline, but it also as the unfortunate side effect to partially reinitialise the pretty-printing engine, so that the rest of the printing material is noticeably messed up.

-Never put newline characters directly in the strings to be printed: pretty printing engine will consider this newline character as any other character written on the current line and this will completely mess up the output. Instead of new line characters use line break hints: if those break hints must always result in new lines, it just means that the surrounding box must be a vertical box!

-End your main program by a print_newline () call, that flushes the pretty-printer tables (hence the output). (Note that the top-level loop of the interactive system does it as well, just before a new input.)

Printing to stdout: using printf

The format module provides a general printing facility "a la" printf. In addition to the usual conversion facility provided by printf, you can write pretty-printing indications directly inside the format string (opening and closing boxes, indicating breaking hints, etc).

Pretty-printing annotations are introduced by the @ symbol, directly into the string format. Almost any function of the Format module can be called from within a printf format string. For instance

-" @[ " open a box (open_box 0). You may precise the type as an extra argument. For instance @[<hov n> is equivalent to open_hovbox n .

-" @] " close a box ( close_box () ).

-" @ " output a breakable space ( print_space () ).

-" @, " output a break hint ( print_cut () ).

-" @;<n m> " emit a "full" break hint ( print_break n m ).

-" @. " end the pretty-printing, closing all the boxes still opened ( print_newline () ).

For instance

printf "@[<1>%s@ =@ %d@ %s@]@." "Prix TTC" 100 "Euros";; Prix TTC = 100 Euros - : unit = ()

A concrete example

Let me give a full example: the shortest non trivial example you could imagine, that is the lambda calculus :)

Thus the problem is to pretty-print the values of a concrete data type that models a language of expressions that defines functions and their applications to arguments.

First, I give the abstract syntax of lambda-terms:

type lambda = | Lambda of string * lambda | Var of string | Apply of lambda * lambda ;;

I use the format library to print the lambda-terms:

open Format;; let ident = print_string;; let kwd = print_string;; val ident : string -> unit = <fun> val kwd : string -> unit = <fun> let rec print_exp0 = function | Var s -> ident s | lam -> open_hovbox 1; kwd "("; print_lambda lam; kwd ")"; close_box () and print_app = function | e -> open_hovbox 2; print_other_applications e; close_box () and print_other_applications f = match f with | Apply (f, arg) -> print_app f; print_space (); print_exp0 arg | f -> print_exp0 f and print_lambda = function | Lambda (s, lam) -> open_hovbox 1; kwd "\\"; ident s; kwd "."; print_space(); print_lambda lam; close_box() | e -> print_app e;; val print_app : lambda -> unit = <fun> val print_other_applications : lambda -> unit = <fun> val print_lambda : lambda -> unit = <fun>

Most general pretty-printing: using fprintf

We use the fprintf function to write the most versatile version of the pretty-printing functions for lambda-terms. Now, the functions get an extra argument, namely a pretty-printing formatter (the ppf argument) where printing will occur. This way the printing routines are more general, since they can print on any formatter defined in the program (either printing to a file, or to stdout , to stderr , or even to a string). Furthermore, the pretty-printing functions are now compositional, since they may be used in conjunction with the special %a conversion, that prints a fprintf argument with a user's supplied function (these user's supplied functions also have a formatter as first argument).

Using fprintf , the lambda-terms printing routines can be written as follows:

open Format;; let ident ppf s = fprintf ppf "%s" s;; let kwd ppf s = fprintf ppf "%s" s;; val ident : Format.formatter -> string -> unit val kwd : Format.formatter -> string -> unit let rec pr_exp0 ppf = function | Var s -> fprintf ppf "%a" ident s | lam -> fprintf ppf "@[<1>(%a)@]" pr_lambda lam and pr_app ppf = function | e -> fprintf ppf "@[<2>%a@]" pr_other_applications e and pr_other_applications ppf f = match f with | Apply (f, arg) -> fprintf ppf "%a@ %a" pr_app f pr_exp0 arg | f -> pr_exp0 ppf f and pr_lambda ppf = function | Lambda (s, lam) -> fprintf ppf "@[<1>%a%a%a@ %a@]" kwd "\\" ident s kwd "." pr_lambda lam | e -> pr_app ppf e ;; val pr_app : Format.formatter -> lambda -> unit val pr_other_applications : Format.formatter -> lambda -> unit val pr_lambda : Format.formatter -> lambda -> unit

Given those general printing routines, procedures to print to stdout or stderr is just a matter of partial application:

let print_lambda = pr_lambda std_formatter;; let eprint_lambda = pr_lambda err_formatter;; val print_lambda : lambda -> unit val eprint_lambda : lambda -> unit
