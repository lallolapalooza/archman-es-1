F_NOTIFY(2const) F_NOTIFY(2const)

NOMBRE

F_NOTIFY - notificación de cambios en archivos y directorios

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE
#include <fcntl.h>
int fcntl(int fd, F_NOTIFY, int arg);

DESCRIPCIÓN

Proporciona notificación cuando el directorio al que se refiere fd o cualquiera de los archivos que contiene es modificado. Los eventos a notificar se especifican en arg, que es una máscara de bits especificada mediante la operación OR bit a bit de cero o más de los siguientes bits:

DN_ACCESS
Se accedió a un archivo (read(2), pread(2), readv(2) y similares)
DN_MODIFY
Se modificó un archivo (write(2), pwrite(2), writev(2), truncate(2), ftruncate(2) y similares).
DN_CREATE
Se creó un archivo (open(2), creat(2), mknod(2), mkdir(2), link(2), symlink(2), rename(2) en este directorio).
DN_DELETE
Se desvinculó un archivo (unlink(2), rename(2) a otro directorio, rmdir(2)).
DN_RENAME
Se renombró un archivo dentro de este directorio (rename(2)).
DN_ATTRIB
Se modificaron los atributos de un archivo (chown(2), chmod(2), utime(2), utimensat(2) y similares).

(Para obtener estas definiciones, la macro de prueba de características _GNU_SOURCE debe definirse antes de incluir cualquier archivo de cabecera.)

Las notificaciones de directorio son normalmente de un solo uso ("one-shot"), y la aplicación debe volver a registrarse para recibir notificaciones futuras. Alternativamente, si se incluye DN_MULTISHOT en arg, la notificación permanecerá en vigor hasta que se elimine explícitamente.

Una serie de llamadas a F_NOTIFY es acumulativa, y los eventos en arg se añaden al conjunto que ya se está monitorizando. Para desactivar la notificación de todos los eventos, realiza una llamada a F_NOTIFY especificando arg como 0.

La notificación se produce mediante la entrega de una señal. La señal predeterminada es SIGIO, pero esto puede cambiarse utilizando la operación F_SETSIG para fcntl(). (Ten en cuenta que SIGIO es una de las señales estándar no encolables; cambiar al uso de una señal en tiempo real significa que se pueden encolar múltiples notificaciones para el proceso). En este último caso, el manejador de señales recibe una estructura siginfo_t como segundo argumento (si el manejador se estableció utilizando SA_SIGINFO) y el campo si_fd de esta estructura contiene el descriptor de archivo que generó la notificación (útil al establecer la notificación en múltiples directorios).

Especialmente cuando se utiliza DN_MULTISHOT, se debe usar una señal en tiempo real para la notificación, de modo que se puedan encolar múltiples notificaciones.

NOTA: Las nuevas aplicaciones deben utilizar la interfaz inotify (disponible desde Linux 2.6.13), que proporciona una interfaz mucho superior para obtener notificaciones de eventos del sistema de archivos. Ver inotify(7).

VALOR DE RETORNO

Cero.

En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

Ver fcntl(2).

ENOTDIR
fd no se refiere a un directorio.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.4.
