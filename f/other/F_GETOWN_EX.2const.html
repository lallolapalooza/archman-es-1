F_GETOWN_EX(2) — Arch manual pages

NAME

F_GETOWN_EX
get and set the owner of a file descriptor for asynchronous I/O events

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <fcntl.h>

/* For F_GETOWN, F_SETOWN, F_GETSIG, F_SETSIG */

long fcntl(int fd, int cmd);
long fcntl(int fd, int cmd, unsigned long arg);

/* For F_GETOWN_EX, F_SETOWN_EX */

struct f_owner_ex {
    int type;
    pid_t pid;
};

long fcntl(int fd, int cmd, struct f_owner_ex *arg);

DESCRIPTION

The fcntl() system call provides a way to control file descriptors and their associated properties. This page describes the use of fcntl() with the commands F_GETOWN, F_SETOWN, F_GETSIG, F_SETSIG, F_GETOWN_EX, and F_SETOWN_EX.

These commands are used to manage asynchronous I/O notification for a file descriptor. When certain I/O events occur on the file descriptor (e.g., data becomes available to read, or the process is ready to write), a signal is sent to a specified process or process group.

F_GETOWN
Return the process ID (PID) or process group ID (PGID) of the current owner of the file descriptor fd. The owner is the entity that receives SIGURG signals by default when out-of-band data is available on a socket. If the returned value is positive, it is a PID. If it is negative, it is a process group ID (PGID), and the value is the absolute value of the PGID.
F_SETOWN
Set the owner of the file descriptor fd to the value given in arg. If arg is positive, it is interpreted as a PID. If arg is negative, it is interpreted as a process group ID (PGID), and the value is the negated value of the PGID.
F_GETSIG
Return the signal number that is sent to the owner of the file descriptor fd when read or write becomes possible. If the return value is 0, then the traditional SIGIO behavior is enabled: a signal is sent to the process group associated with the file descriptor when I/O is possible. Otherwise, the return value is the signal number to be sent.
F_SETSIG
Set the signal number that is sent to the owner of the file descriptor fd when read or write becomes possible to the value in arg. If arg is 0, then the traditional SIGIO behavior is enabled. If arg is a valid signal number (see signal(7)), then that signal will be sent. If SA_SIGINFO is set for the signal handler, then a real-time signal is sent. Otherwise, a standard signal is sent. This command requires that O_ASYNC is enabled for the file descriptor (see the description of O_ASYNC below).
F_GETOWN_EX
Retrieve the owner of the file descriptor fd into the structure pointed to by arg. The structure is of type struct f_owner_ex, which contains a type field and a pid field. The type field can be F_OWNER_TID (owner is a thread ID) or F_OWNER_PID (owner is a process ID). The pid field contains the thread ID or process ID, respectively.
F_SETOWN_EX
Set the owner of the file descriptor fd using the information in the structure pointed to by arg. The structure is of type struct f_owner_ex, which contains a type field and a pid field. The type field can be F_OWNER_TID (owner is a thread ID) or F_OWNER_PID (owner is a process ID). The pid field contains the thread ID or process ID, respectively.

The F_GETOWN_EX and F_SETOWN_EX operations provide a more fine-grained control over the ownership of file descriptors, allowing the owner to be specified as either a process ID or a thread ID.

When using real-time signals (value >= SIGRTMIN), multiple I/O events may be queued using the same signal numbers. (Queuing is dependent on available memory.) Extra information is available if SA_SIGINFO is set for the signal handler, as above.

Note that Linux imposes a limit on the number of real-time signals that may be queued to a process (see getrlimit(2) and signal(7)) and if this limit is reached, then the kernel reverts to delivering SIGIO, and this signal is delivered to the entire process rather than to a specific thread.

Using these mechanisms, a program can implement fully asynchronous I/O without using select(2) or poll(2) most of the time.

The use of O_ASYNC is specific to BSD and Linux. The only use of F_GETOWN and F_SETOWN specified in POSIX.1 is in conjunction with the use of the SIGURG signal on sockets. (POSIX does not specify the SIGIO signal.) F_GETOWN_EX, F_SETOWN_EX, F_GETSIG, and F_SETSIG are Linux-specific. POSIX has asynchronous I/O and the aio_sigevent structure to achieve similar things; these are also available in Linux as part of the GNU C Library (glibc).

BUGS

F_GETOWN

A limitation of the Linux system call conventions on some architectures (notably i386) means that if a (negative) process group ID to be returned by F_GETOWN falls in the range -1 to -4095, then the return value is wrongly interpreted by glibc as an error in the system call; that is, the return value of fcntl() will be -1, and errno will contain the (positive) process group ID. The Linux-specific F_GETOWN_EX operation avoids this problem. Since glibc 2.11, glibc makes the kernel F_GETOWN problem invisible by implementing F_GETOWN using F_GETOWN_EX.

F_SETOWN

In Linux 2.4 and earlier, there is bug that can occur when an unprivileged process uses F_SETOWN to specify the owner of a socket file descriptor as a process (group) other than the caller. In this case, fcntl() can return -1 with errno set to EPERM, even when the owner process (group) is one that the caller has permission to send signals to. Despite this error return, the file descriptor owner is set, and signals will be sent to the owner.
