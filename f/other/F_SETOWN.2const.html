N

F_GETOWN, F_SETOWN, F_GETOWN_EX, F_SETOWN_EX, F_GETSIG y F_SETSIG se utilizan para gestionar las señales de disponibilidad de

E/S:
F_GETO
WN
Devuelve (como resultado de la función) el ID de proceso o el ID de grupo de proceso que está recibiendo actualmente las señales SIGIO y SIGURG por eventos en el descriptor de archivo fd. Los ID de proceso se devuelven como valores positivos; los ID de grupo de proceso se devuelven como valores negativos (pero véase ERRORES más abajo). arg se
ignora.
F_SETO
WN
Establece el ID de proceso o el ID de grupo de proceso que recibirá las señales SIGIO y SIGURG por eventos en el descriptor de archivo fd. El ID del proceso o del grupo de proceso de destino se especifica en arg. Un ID de proceso se especifica como un valor positivo; un ID de grupo de proceso se especifica como un valor negativo. Lo más habitual es que el proceso que llama se especifique a sí mismo como el propietario (es decir, arg se especifica como getpid
(2
)).
Además de establecer el propietario del descriptor de archivo, también se debe habilitar la generación de señales en el descriptor de archivo. Esto se hace utilizando la operación F_SETFL(2const) para establecer el indicador de estado de archivo O_ASYNC en el descriptor de archivo. Posteriormente, se envía una señal SIGIO siempre que sea posible la entrada o la salida en el descriptor de archivo. La operación fcntl() F_SETSIG se puede utilizar para obtener la entrega de una señal distinta de SIGI
O.
El envío de una señal al proceso (grupo) propietario especificado por F_SETOWN está sujeto a las mismas comprobaciones de permisos que se describen para kill(2), donde el proceso que envía es el que emplea F_SETOWN (pero véase ERRORES más abajo). Si esta comprobación de permisos falla, la señal se descarta silenciosamente. Nota: La operación F_SETOWN registra las credenciales del llamante en el momento de la llamada a fcntl(), y son estas credenciales guardadas las que se utilizan para las comprobaciones de
permisos.
Si el descriptor de archivo fd se refiere a un socket, F_SETOWN también selecciona al destinatario de las señales SIGURG que se entregan cuando llegan datos fuera de banda a ese socket. (SIGURG se envía en cualquier situación en la que select(2) informaría de que el socket tiene una "condición excepcional".
)
Lo siguiente era cierto
en Linux 2.6.x hasta Lin

Si se proporciona un valor distinto de cero a F_SETSIG en un proceso multihilo que se ejecuta con una biblioteca de hilos que soporta grupos de hilos (por ejemplo, NPTL), entonces un valor positivo dado a F_SETOWN tiene un significado diferente: en lugar de ser un ID de proceso que identifica a un proceso completo, es un ID de hilo que identifica a un hilo específico dentro de un proceso. Como consecuencia, puede ser necesario pasar a F_SETOWN el resultado de gettid(2) en lugar de getpid(2) para obtener resultados sensatos cuando se utiliza F_SETSIG. (En las implementaciones actuales de hilos de Linux, el ID de hilo de un hilo principal es el mismo que su ID de proceso. Esto significa que un programa de un solo hilo puede usar igualmente gettid(2) o getpid(2) en este escenario.) Nótese, sin embargo, que las afirmaciones de este párrafo no se aplican a la señal SIGURG generada para datos fuera de banda en un socket: esta señal se envía siempre a un proceso o a un grupo de proceso, dependiendo del valor dado a F_SE

IG
Devuelve (como resultado de la función) la señal que se envía cuando es posible la entrada o la salida. Un valor de cero significa que se envía SIGIO. Cualquier otro valor (incluido SIGIO) es la señal que se envía en su lugar, y en este caso hay información adicional disponible para el manejador de señales si se instaló con SA_SIGINFO. arg se

F_SETS
IG
Establece la señal que se envía cuando es posible la entrada o la salida al valor dado en arg. Un valor de cero significa enviar la señal por defecto SIGIO. Cualquier otro valor (incluido SIGIO) es la señal que se envía en su lugar, y en este caso hay información adicional disponible para el manejador de señales si se instaló con SA_SIGINF
O
.
Al utilizar F_SETSIG con un valor distinto de cero, y al establecer SA_SIGINFO para el manejador de señales (véase sigaction(2)), se pasa información adicional sobre los eventos de E/S al manejador en una estructura siginfo_t. Si el campo si_code indica que la fuente es SI_SIGIO, el campo si_fd proporciona el descriptor de archivo asociado al evento. De lo contrario, no hay indicación de qué descriptores de archivo están pendientes, y se deben usar los mecanismos habituales (select(2), poll(2), read(2) con O_NONBLOCK establecido, etc.) para determinar qué descriptores de archivo están disponibles para la
E/S.
Nótese que el descriptor de archivo proporcionado en si_fd es el que se especificó durante la operación F_SETSIG. Esto puede llevar a un caso límite inusual. Si el descriptor de archivo se duplica (dup(2) o similar), y el descriptor de archivo original se cierra, los eventos de E/S seguirán generándose, pero el campo si_fd contendrá el número del descriptor de archivo ahora
cerrado.
Al seleccionar una señal de tiempo real (valor >= SIGRTMIN), múltiples eventos de E/S pueden encolarse usando los mismos números de señal. (El encolado depende de la memoria disponible.) Información adicional está disponible si SA_SIGINFO está establecido para el manejador de la señal, como
arriba.
Tenga en cuenta que Linux impone un límite en el número de señales de tiempo real que pueden encolarse a un proceso (véase getrlimit(2) y signal(7)) y si este límite se alcanza, entonces el kernel revierte a entregar SIGIO, y esta señal se entrega al proceso com
pleto en lugar de
a un hilo específico.

Usando estos mecanismos, un programa puede implementar E/S completamente asíncrona sin usar select(2) o poll(2) la mayor parte del

tiempo.

El uso de O_ASYNC es específico de BSD y Linux. El único uso de F_GETOWN y F_SETOWN especificado en POSIX.1 es en conjunción con el uso de la señal SIGURG en sockets. (POSIX no especifica la señal SIGIO.) F_GETOWN_EX, F_SETOWN_EX, F_GETSIG, y F_SETSIG son específicos de Linux. POSIX tiene E/S asíncrona y la estructura aio_sigevent para lograr cosas similares; estos también est

án disponibles en Linux como parte d
e la Biblioteca C de GNU (glibc).

F_GETOW

N

Una limitación de las convenciones de llamadas al sistema de Linux en algunas arquitecturas (notablemente i386) significa que si un ID de grupo de proceso (negativo) a ser devuelto por F_GETOWN cae en el rango -1 a -4095, entonces el valor de retorno es interpretado erróneamente por glibc como un error en la llamada al sistema; es decir, el valor de retorno de fcntl() será -1, y errno contendrá el ID de grupo de proceso (positivo). La operación específica de Linux F_GETOWN_EX evita este problema. Desde glibc 2.11, glibc hace que el problema de F_GETOWN del kernel sea invisible al implementar F_GETOWN usando F_GETOWN_E

X
.

F_SETOW

N

En Linux 2.4 y anteriores, existe un error que puede ocurrir cuando un proceso sin privilegios usa F_SETOWN para especificar al propietario de un descriptor de archivo de socket como un proceso (grupo) distinto del llamador. En este caso, fcntl() puede devolver -1 con errno establecido a EPERM, incluso cuando el proceso (grupo) propietario es uno al que el llamador tiene permiso para

enviar señales. A pesar de este retorno de er
ror, el propietario del descriptor de archivo se es
tablece, y se enviarán señales al propietario.
