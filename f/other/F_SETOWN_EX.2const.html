NOMBRE

F_GETOWN, F_SETOWN, F_GETOWN_EX, F_SETOWN_EX, F_GETSIG, F_SETSIG - gestión de señales

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <fcntl.h>
int fcntl(int fd, F_GETOWN);
int fcntl(int fd, F_SETOWN, int arg);
#define _GNU_SOURCE
#include <fcntl.h>
int fcntl(int fd, F_GETOWN_EX, struct f_owner_ex *arg);
int fcntl(int fd, F_SETOWN_EX, const struct f_owner_ex *arg);
int fcntl(int fd, F_GETSIG);
int fcntl(int fd, F_SETSIG, int arg);

DESCRIPCIÓN

F_GETOWN, F_SETOWN, F_GETOWN_EX, F_SETOWN_EX, F_GETSIGy F_SETSIG se utilizan para gestionar las señales de disponibilidad de E/S:

F_GETOWN
Devuelve (como resultado de la función) el ID de proceso o el ID de grupo de procesos que está recibiendo actualmente las señales SIGIO y SIGURG para eventos en el descriptor de archivo fd. Los IDs de proceso se devuelven como valores positivos; los IDs de grupo de procesos se devuelven como valores negativos (pero véase ERRORES más abajo). arg se ignora.
F_SETOWN
Establece el ID de proceso o el ID de grupo de procesos que recibirá las señales SIGIO y SIGURG para eventos en el descriptor de archivo fd. El proceso de destino o el ID de grupo de procesos se especifica en arg. Un ID de proceso se especifica como un valor positivo; un ID de grupo de procesos se especifica como un valor negativo. Lo más común es que el proceso que llama se especifique a sí mismo como el propietario (es decir, arg se especifica como getpid(2)).
Además de establecer el propietario del descriptor de archivo, también se debe habilitar la generación de señales en el descriptor de archivo. Esto se hace utilizando la operación F_SETFL(2const) para establecer el indicador de estado de archivo O_ASYNC en el descriptor de archivo. Posteriormente, se envía una señal SIGIO siempre que sea posible la entrada o la salida en el descriptor de archivo. La operación fcntl() F_SETSIG se puede utilizar para obtener la entrega de una señal distinta de SIGIO.
El envío de una señal al proceso (grupo) propietario especificado por F_SETOWN está sujeto a las mismas comprobaciones de permisos que se describen para kill(2), donde el proceso que envía es el que emplea F_SETOWN (pero véase ERRORES más abajo). Si esta comprobación de permisos falla, la señal se descarta silenciosamente. Nota: La operación F_SETOWN registra las credenciales del llamante en el momento de la llamada a fcntl(), y son estas credenciales guardadas las que se utilizan para las comprobaciones de permisos.
Si el descriptor de archivo fd se refiere a un socket, F_SETOWN también selecciona al destinatario de las señales SIGURG que se entregan cuando llegan datos fuera de banda a ese socket. (SIGURG se envía en cualquier situación en la que select(2) informaría que el socket tiene una "condición excepcional".)
Lo siguiente era cierto en Linux 2.6.x hasta y incluyendo Linux 2.6.11:
Si se da un valor distinto de cero a F_SETSIG en un proceso multihilo que se ejecuta con una biblioteca de hilos que soporta grupos de hilos (por ejemplo, NPTL), entonces un valor positivo dado a F_SETOWN tiene un significado diferente: en lugar de ser un ID de proceso que identifica a un proceso completo, es un ID de hilo que identifica a un hilo específico dentro de un proceso. Como consecuencia, puede ser necesario pasar a F_SETOWN el resultado de gettid(2) en lugar de getpid(2) para obtener resultados sensatos cuando se usa F_SETSIG . (En las implementaciones actuales de hilos de Linux, el ID de hilo de un hilo principal es el mismo que su ID de proceso. Esto significa que un programa de un solo hilo puede usar igualmente gettid(2) o getpid(2) en este escenario.) Nótese, sin embargo, que las afirmaciones de este párrafo no se aplican a la señal SIGURG generada para datos fuera de banda en un socket: esta señal se envía siempre a un proceso o a un grupo de procesos, dependiendo del valor dado a F_SETOWN.
El comportamiento anterior se eliminó accidentalmente en Linux 2.6.12 y no se restaurará. A partir de Linux 2.6.32, use F_SETOWN_EX para dirigir las señales SIGIO y SIGURG a un hilo en particular.
F_GETOWN_EX
Devuelve la configuración actual del propietario del descriptor de archivo, tal como fue definida por una operación F_SETOWN_EX anterior. La información se devuelve en la estructura a la que apunta arg, que tiene la siguiente forma:

struct f_owner_ex {
    int   type;
    pid_t pid;
};

El campo type tendrá uno de los valores F_OWNER_TID, F_OWNER_PIDo F_OWNER_PGRP. El campo pid es un entero positivo que representa un ID de hilo, un ID de proceso o un ID de grupo de procesos. Véase F_SETOWN_EX para más detalles.
F_SETOWN_EX
Esta operación realiza una tarea similar a F_SETOWN. Permite al llamante dirigir las señales de disponibilidad de E/S a un hilo, proceso o grupo de procesos específico. El llamante especifica el destino de las señales a través de arg, que es un puntero a una estructura f_owner_ex . El campo type tiene uno de los siguientes valores, que definen cómo pid se interpreta:
F_OWNER_TID
Envía la señal al hilo cuyo ID de hilo (el valor devuelto por una llamada a clone(2) o gettid(2)) está especificado en pid.
F_OWNER_PID
Envía la señal al proceso cuyo ID está especificado en pid.
F_OWNER_PGRP
Envía la señal al grupo de procesos cuyo ID está especificado en pid. (Nótese que, a diferencia de F_SETOWN, un ID de grupo de procesos se especifica aquí como un valor positivo.)
F_GETSIG
Devuelve (como resultado de la función) la señal enviada cuando es posible la entrada o la salida. Un valor de cero significa que se envía SIGIO . Cualquier otro valor (incluyendo SIGIO) es la señal que se envía en su lugar, y en este caso hay información adicional disponible para el manejador de señal si se instaló con SA_SIGINFO. arg se ignora.
F_SETSIG
Establece la señal enviada cuando es posible la entrada o la salida al valor dado en arg. Un valor de cero significa enviar la señal SIGIO por defecto. Cualquier otro valor (incluyendo SIGIO) es la señal a enviar en su lugar, y en este caso hay información adicional disponible para el manejador de señal si se instaló con SA_SIGINFO.
Al usar F_SETSIG con un valor distinto de cero, y establecer SA_SIGINFO para el manejador de señal (véase sigaction(2)), se pasa información adicional sobre los eventos de E/S al manejador en una estructura siginfo_t . Si el campo si_code indica que la fuente es SI_SIGIO, el campo si_fd proporciona el descriptor de archivo asociado con el evento. De lo contrario, no hay indicación de qué descriptores de archivo están pendientes, y se deben usar los mecanismos habituales (select(2), poll(2), read(2) con O_NONBLOCK establecido, etc.) para determinar qué descriptores de archivo están disponibles para E/S.
Nótese que el descriptor de archivo proporcionado en si_fd es el que se especificó durante la operación F_SETSIG . Esto puede llevar a un caso excepcional inusual. Si el descriptor de archivo se duplica (dup(2) o similar), y el descriptor de archivo original se cierra, los eventos de E/S seguirán generándose, pero el campo si_fd contendrá el número del descriptor de archivo ahora cerrado.

DESCRIPCIóN

Al seleccionar una señal en tiempo real (valor >= SIGRTMIN), se pueden encolar múltiples eventos de E/S utilizando los mismos números de señal. (La cola depende de la memoria disponible). Hay información adicional disponible si se establece SA_SIGINFO para el manejador de señales, como se indicó anteriormente.
Tenga en cuenta que Linux impone un límite al número de señales en tiempo real que se pueden poner en cola para un proceso (consulte getrlimit(2) y signal(7)) y si se alcanza este límite, el kernel vuelve a la entrega de SIGIO, y esta señal se entrega a todo el proceso en lugar de a un hilo específico.

Utilizando estos mecanismos, un programa puede implementar E/S completamente asíncrona sin utilizar select(2) o poll(2) la mayor parte del tiempo.

El uso de O_ASYNC es específico de BSD y Linux. El único uso de F_GETOWN y F_SETOWN especificado en POSIX.1 es en conjunción con el uso de la señal SIGURG en sockets. (POSIX no especifica la señal SIGIO). F_GETOWN_EX, F_SETOWN_EX, F_GETSIG y F_SETSIG son específicos de Linux. POSIX tiene E/S asíncrona y la estructura aio_sigevent para lograr cosas similares; estas también están disponibles en Linux como parte de la Biblioteca C de GNU (glibc).

ERRORES CONOCIDOS

F_GETOWN

Una limitación de las convenciones de llamada al sistema de Linux en algunas arquitecturas (notablemente i386) significa que si un ID de grupo de procesos (negativo) que debe ser devuelto por F_GETOWN cae en el rango de -1 a -4095, entonces el valor de retorno es mal interpretado por glibc como un error en la llamada al sistema; es decir, el valor de retorno de fcntl() será -1, y errno contendrá el ID de grupo de procesos (positivo). La operación F_GETOWN_EX, específica de Linux, evita este problema. Desde glibc 2.11, glibc hace que el problema de la llamada al sistema F_GETOWN sea invisible implementando F_GETOWN usando F_GETOWN_EX.

F_SETOWN

En Linux 2.4 y anteriores, existe un error que puede ocurrir cuando un proceso no privilegiado utiliza F_SETOWN para especificar el propietario de un descriptor de archivo de socket como un proceso (grupo) distinto del llamante. En este caso, fcntl() puede devolver -1 con errno establecido en EPERM, incluso cuando el proceso (grupo) propietario es uno al que el llamante tiene permiso para enviar señales. A pesar de esta devolución de error, el propietario del descriptor de archivo se establece y se envían señales al propietario.
