F_GETOW

N

Una limitación de las convenciones de llamadas al sistema de Linux en algunas arquitecturas (notablemente i386) significa que si un ID de grupo de proceso (negativo) que debe ser devuelto por F_GETOWN cae en el rango -1 a -4095, entonces el valor de retorno es interpretado erróneamente por glibc como un error en la llamada al sistema; es decir, el valor de retorno de fcntl() será -1, y errno contendrá el ID de grupo de proceso (positivo). La operación específica de Linux F_GETOWN_EX evita este problema. Desde glibc 2.11, glibc hace que el problema de F_GETOWN en el kernel sea invisible implementando F_GETOWN utilizando F_GETOWN_E

X
.

N

En Linux 2.4 y anteriores, existe un error que puede ocurrir cuando un proceso sin privilegios utiliza F_SETOWN para especificar al propietario de un descriptor de archivo de socket como un proceso (grupo) distinto al del llamador. En este caso, fcntl() puede devolver -1 con errno establecido a EPERM, incluso cuando el proceso (grupo) propietario es uno al que el llamador tiene permiso p

ara enviar señales. A pesar de esta devolución de e

se establece, y se enviarán señales al propietario.
