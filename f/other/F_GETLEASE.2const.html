F_SETLEASE y F_GETLEASE se utilizan para establecer un nuevo arrendamiento, y recuperar el arrendamiento actual, sobre la descripción de archivo abierta a la que hace referencia el descriptor de archivo fd. Un arrendamiento de archivo proporciona un mecanismo mediante el cual el proceso que posee el arrendamiento (el "poseedor del arrendamiento") es notificado (mediante la entrega de una señal) cuando un proceso (el "infractor del arrendamiento") intenta open(2) o truncate(2) el archivo al que hace referencia ese descriptor de

archivo.

SE

g

Adquiere un arrendamiento de lectura. Esto hará que el proceso que llama sea notificado cuando el archivo se abra para escritura o se trunque. Un arrendamiento de lectura solo puede colocarse en un descriptor de archivo que esté abierto en modo solo
lectura.
F_WRL
CK
Adquiere un arrendamiento de escritura. Esto hará que quien llama sea notificado cuando el archivo se abra para lectura o escritura o se trunque. Un arrendamiento de escritura solo puede colocarse en un archivo si no hay otros descriptores de archivo abiertos para el
archivo.

Los arrendamientos se asocian con una descripción de archivo abierta (véase open(2)). Esto significa que los descriptores de archivo duplicados (creados, por ejemplo, por fork(2) o dup(2)) se refieren al mismo arrendamiento, y este arrendamiento puede modificarse o liberarse usando cualquiera de estos descriptores. Además, el arrendamiento se libera mediante una operación explícita de F_UNLCK en cualquiera de estos descriptores de archivo duplicados, o cuando todos esos descriptores de archivo han sido

cerrados.

Los arrendamientos solo pueden adquirirse sobre archivos regulares. Un proceso sin privilegios solo puede adquirir un arrendamiento sobre un archivo cuyo UID (propietario) coincida con el UID del sistema de archivos del proceso. Un proceso con la capacidad CAP_LEASE puede adquirir arrendamientos sobre archivos

arbitrarios.
F_GETLEA
SE
Indica qué tipo de arrendamiento está asociado con el descriptor de archivo fd devolviendo F_RDLCK, F_WRLCK, o F_UNLCK, indicando, respectivamente, un arrendamiento de lectura, un arrendamiento de escritura, o ningún arrendamiento. arg se
ign
ora.

Cuando un proceso (el "infractor del arrendamiento") realiza un open(2) o truncate(2) que entra en conflicto con un arrendamiento establecido mediante F_SETLEASE, la llamada al sistema es bloqueada por el kernel y el kernel notifica al poseedor del arrendamiento enviándole una señal (SIGIO por defecto). El poseedor del arrendamiento debe responder a la recepción de esta señal realizando la limpieza necesaria en preparación para que el archivo sea accedido por otro proceso (por ejemplo, vaciando los búferes en caché) y luego eliminar o rebajar su arrendamiento. Un arrendamiento se elimina realizando una operación F_SETLEASE especificando arg como F_UNLCK. Si el poseedor del arrendamiento actualmente posee un arrendamiento de escritura sobre el archivo, y el infractor del arrendamiento está abriendo el archivo para lectura, entonces es suficiente que el poseedor del arrendamiento rebaje el arrendamiento a uno de lectura. Esto se hace realizando una operación F_SETLEASE especificando arg como F_RDLCK

.

Si el poseedor del arrendamiento no logra rebajar o eliminar el arrendamiento dentro del número de segundos especificado en /proc/sys/fs/lease-break-time, entonces el kernel elimina o rebaja forzosamente el arrendamiento del

poseedor.

Una vez que se ha iniciado una ruptura de arrendamiento, F_GETLEASE devuelve el tipo de arrendamiento objetivo (ya sea F_RDLCK o F_UNLCK, dependiendo de qué sería compatible con el infractor del arrendamiento) hasta que el poseedor del arrendamiento rebaje o elimine voluntariamente el arrendamiento o el kernel lo haga forzosamente después de que el temporizador de ruptura de arrendamiento

expire.

Una vez que el arrendamiento ha sido eliminado o rebajado voluntaria o forzosamente, y asumiendo que el infractor del arrendamiento no ha desbloqueado su llamada al sistema, el kernel permite que la llamada al sistema del infractor del arrendamiento

proceda.

Si el open(2) o truncate(2) bloqueado del infractor del arrendamiento es interrumpido por un manejador de señal, entonces la llamada al sistema falla con el error EINTR, pero los otros pasos aún ocurren como se describe arriba. Si el infractor del arrendamiento es eliminado por una señal mientras está bloqueado en open(2) o truncate(2), entonces los otros pasos aún ocurren como se describe arriba. Si el infractor del arrendamiento especifica el indicador O_NONBLOCK al llamar a open(2), entonces la llamada falla inmediatamente con el error EWOULDBLOCK, pero los otros pasos aún ocurren como se describe

arriba.

La señal predeterminada utilizada para notificar al poseedor del arrendamiento es SIGIO, pero esto puede cambiarse usando la operación F_SETSIG a fcntl(). Si se realiza una operación F_SETSIG (incluso una que especifique SIGIO), y el manejador de señal se establece usando SA_SIGINFO, entonces el manejador recibirá una estructura siginfo_t como su segundo argumento, y el campo si_fd de este argumento contendrá el descriptor de archivo del archivo arren

dado que ha sido accedido por otro proc
eso. (Esto es útil si quien llama posee
arrendamientos contra múltiples archivos.)
