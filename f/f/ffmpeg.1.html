Copia de flujo

La tubería más simple en ffmpeg es la copia de flujo de un solo flujo, es decir, copiar los paquetes de un flujo elemental de entrada sin decodificarlos, filtrarlos ni codificarlos. Como ejemplo, considere un archivo de entrada llamado INPUT.mkv con 3 flujos elementales, de los cuales tomamos el segundo y lo escribimos en el archivo OUTPUT.mp4. Una representación esquemática de dicha tubería se ve así:

┌─────────────────────────┬────────────────────────────────────────┐
│ desmultiplexador        │ flujo elemental 0                    │ flujo no utilizado
➎═════════════════════════╣ flujo elemental 1 ├───────────────────────┤ ┌
│                         │                                        │ │
│INPUT.mkv ├───────────▌ flujo elemental 2 ├───────────────────────┤ │
│                         └────────────────────────────────────────┘ │
└─────────────────────────┘                                        ▼
                                                                OUTPUT.mp4
|--------------------|--------------------|--------------------| | | packets | | muxer | |----------| stream 1 |----------| elementary stream 0 |----------| | | | | OUTPUT.mp4 | |----------|----------|----------|--------------------|----------| | | unused | | stream 2 |----------| | | | |----------|----------|-----------------------------------------| ```

El pipeline anterior se puede construir con la siguiente línea de comandos:

ffmpeg -i INPUT.mkv -map 0:1 -c copy OUTPUT.mp4

En esta línea de comandos

  • hay una única entrada INPUT.mkv;
  • no hay opciones de entrada para esta entrada;
  • hay una única salida OUTPUT.mp4;
  • hay dos opciones de salida para esta salida:
  • "-map 0:1" selecciona el flujo de entrada a ser utilizado - de la entrada con índice 0 (es decir, la primera) el flujo con índice 1 (es decir, el segundo);
  • "-c copy" selecciona el codificador "copy", es decir, copia de flujo sin decodificación ni codificación.

La copia de flujo es útil para cambiar el número de flujos elementales, el formato del contenedor o modificar metadatos a nivel de contenedor. Dado que no hay decodificación ni codificación, es muy rápida y no hay pérdida de calidad. Sin embargo, puede no funcionar en algunos casos debido a una variedad de factores (por ejemplo, cierta información requerida por el contenedor de destino no está disponible en el origen). Aplicar filtros obviamente también es imposible, ya que los filtros operan sobre fotogramas decodificados.

Se pueden construir escenarios de copia de flujo más complejos, por ejemplo, combinando flujos de dos archivos de entrada en una única salida:

----------|----------|----------|----------|----------|----------|
| demuxer 0|          | packets  |          |   muxer   |
|INPUT0.mkv|----------|----------|----------| OUTPUT.mp4 |
|----------|----------|----------|----------|----------|
| demuxer 1|          | packets  | stream 1 |          |
|INPUT1.aac|----------|----------|----------|----------|
|----------|----------|--------------------|----------|

que se puede crear con la línea de comandos

ffmpeg -i INPUT0.mkv -i INPUT1.aac -map 0:0 -map 1:0 -c copy OUTPUT.mp4

La opción de salida -map se usa dos veces aquí, creando dos flujos en el archivo de salida, uno alimentado por la primera entrada y otro por la segunda. La única instancia de la opción -c selecciona la copia de flujo para ambos flujos. También podría usar múltiples instancias de esta opción junto con Especificadores de flujo para aplicar diferentes valores a cada flujo, como se demostrará en las siguientes secciones.

Un escenario inverso es dividir múltiples flujos de una única entrada en múltiples salidas:

----------|----------|----------|----------|----------|----------|
| demuxer  |          | packets  |          | muxer 0   |
|----------| stream 0 |----------| stream 0 |----------|
|          |          |          | OUTPUT0.mp4 |
|INPUT.mkv|----------|----------|----------|----------|
|          |          | packets  |----------|----------|
|          | stream 1 |----------|          | muxer 1   |
|          |          |          | stream 0 |----------|
|----------|----------|----------| OUTPUT1.mp4 |
|----------|----------|--------------------|----------|

creado con

ffmpeg -i INPUT.mkv -map 0:0 -c copy OUTPUT0.mp4 -map 0:1 -c copy OUTPUT1.mp4

Observe cómo se necesita una instancia separada de la opción -c para cada archivo de salida, aunque sus valores sean los mismos. Esto se debe a que las opciones no globales (la mayoría de ellas) solo se aplican en el contexto del archivo antes del cual se colocan.

Estos ejemplos, por supuesto, se pueden generalizar aún más a mapeos arbitrarios de cualquier número de entradas a cualquier número de salidas.

Transcodificación

La transcodificación es el proceso de decodificar un flujo y luego volver a codificarlo. Dado que la codificación tiende a ser costosa en términos computacionales y en la mayoría de los casos degrada la calidad del flujo (es decir, es con pérdida), solo debe transcodificar cuando sea necesario y realizar copia de flujo en caso contrario. Las razones típicas para transcodificar son:

  • aplicar filtros, por ejemplo, cambiar el tamaño, desentrelazar o superponer video; remuestrear o mezclar audio;
  • desea alimentar el flujo a algo que no puede decodificar el códec original.

Tenga en cuenta que ffmpeg transcodificará todos los flujos de audio, video y subtítulos a menos que especifique -c copy para ellos.

Considere un pipeline de ejemplo que lee un archivo de entrada con un flujo de audio y uno de video, transcodifica el video y copia el audio a un único archivo de salida. Esto se puede representar esquemáticamente de la siguiente manera

Gráficos de filtros complejos

Los gráficos de filtros complejos son aquellos que no pueden describirse simplemente como una cadena de procesamiento lineal aplicada a un flujo. Este es el caso, por ejemplo, cuando el gráfico tiene más de una entrada y/o salida, o cuando el tipo de flujo de salida es diferente del de entrada. Los gráficos de filtros complejos se configuran con la opción -filter_complex. Tenga en cuenta que esta opción es global, ya que un gráfico de filtros complejo, por su naturaleza, no puede asociarse de manera inequívoca con un solo flujo o archivo. Cada instancia de -filter_complex crea un nuevo gráfico de filtros complejo, y puede haber cualquier número de ellos.

Un ejemplo trivial de un gráfico de filtros complejo es el filtro "overlay", que tiene dos entradas de video y una salida de video, que contiene un video superpuesto encima del otro. Su contraparte de audio es el filtro "amix".

Esto se hace con la directiva "-dec", que toma como parámetro el índice del flujo de salida que debe decodificarse. Cada una de estas directivas crea un nuevo decodificador de retorno de bucle, indexado con enteros sucesivos a partir de cero. Estos índices deben usarse luego para hacer referencia a los decodificadores de retorno de bucle en las etiquetas de enlace del gráfico de filtros complejo, como se describe en la documentación de -filter_complex.

DEMUXING

When ffmpeg is invoked with one or more input files, it instantiates a demuxer for each input file. The demuxer reads the input file, and supplies packets to the corresponding demuxer stream(s). The stream decoder then decodes the packets and supplies frames to the stream. If a complex filtergraph is used, the frames are passed to the filtergraph. Otherwise, the frames are passed to the corresponding encoder. The encoder then encodes the frames and supplies packets to the demuxer stream.

The demuxer may also read stream information from the input file, such as frame rate, resolution, etc. This information is used for stream selection.

The demuxer stream is responsible for managing the packets belonging to a specific stream. It reads packets from the demuxer and supplies them to the stream decoder. It also reads packets from the encoder and writes them to the output file.

SELECCIÓN DE STREAMS

ffmpeg proporciona la opción "-map" para el control manual de la selección de streams en cada archivo de salida. Los usuarios pueden omitir "-map" y dejar que ffmpeg realice la selección automática de streams como se describe a continuación. Las opciones "-vn / -an / -sn / -dn" se pueden utilizar para omitir la inclusión de streams de video, audio, subtítulos y datos respectivamente, ya sean mapeados manualmente o seleccionados automáticamente, excepto para aquellos streams que son salidas de complex filtergraphs.

Descripción

Las subsecciones siguientes describen las diversas reglas que intervienen en la selección de streams. Los ejemplos que siguen a continuación muestran cómo se aplican estas reglas en la práctica.

Si bien se hace todo lo posible para reflejar con precisión el comportamiento del programa, FFmpeg está en continuo desarrollo y el código puede haber cambiado desde el momento de esta escritura.

Selección automática de streams

En ausencia de cualquier opción de mapeo para un archivo de salida particular, ffmpeg inspecciona el formato de salida para verificar qué tipo de streams se pueden incluir en él, es decir, video, audio y/o subtítulos. Para cada tipo de stream aceptable, ffmpeg seleccionará un stream, cuando esté disponible, entre todas las entradas.

Seleccionará ese stream basándose en los siguientes criterios:

  • para video, es el stream con la mayor resolución,
  • para audio, es el stream con más canales,
  • para subtítulos, es el primer stream de subtítulos encontrado, pero hay una advertencia. El codificador de subtítulos predeterminado del formato de salida puede ser de texto o de imagen, y solo se elegirá un stream de subtítulos del mismo tipo.

En el caso de que varios streams del mismo tipo tengan la misma calificación, se elige el stream con el índice más bajo.

Los streams de datos o adjuntos no se seleccionan automáticamente y solo se pueden incluir mediante "-map".

Selección manual de streams

Cuando se utiliza "-map", solo se incluyen en ese archivo de salida los streams mapeados por el usuario, con una posible excepción para las salidas de filtergraph descritas a continuación.

Complex filtergraphs

Si hay alguna salida de complex filtergraph con pads sin etiqueta, se agregarán al primer archivo de salida. Esto conducirá a un error fatal si el tipo de stream no es compatible con el formato de salida. En ausencia de la opción de mapeo, la inclusión de estos streams hace que se omita la selección automática de streams de sus tipos. Si hay opciones de mapeo presentes, estos streams de filtergraph se incluyen además de los streams mapeados.

Las salidas de complex filtergraph con pads etiquetados deben mapearse una vez y exactamente una vez.

Manejo de streams

El manejo de streams es independiente de la selección de streams, con una excepción para los subtítulos descritos a continuación. El manejo de streams se establece a través de la opción "-codec" dirigida a los streams dentro de un archivo de *salida* específico. En particular, las opciones de códec son aplicadas por ffmpeg después del proceso de selección de streams y, por lo tanto, no influyen en este último. Si no se especifica ninguna opción "-codec" para un tipo de stream, ffmpeg seleccionará el codificador predeterminado registrado por el muxer del archivo de salida.

Existe una excepción para los subtítulos. Si se especifica un codificador de subtítulos para un archivo de salida, se incluirá el primer stream de subtítulos encontrado de cualquier tipo, texto o imagen. ffmpeg no valida si el codificador especificado puede convertir el stream seleccionado o si el stream convertido es aceptable dentro del formato de salida. Esto se aplica en general también: cuando el usuario establece manualmente un codificador, el proceso de selección de streams no puede verificar si el stream codificado se puede multiplexar en el archivo de salida. Si no es posible, ffmpeg abortará y *todos* los archivos de salida no se procesarán.

CODIFICACIÓN

Una vez que se seleccionan o mapean los streams para un archivo de salida, estos se pasan al muxer correspondiente. El muxer es responsable de escribir los paquetes en el archivo de salida. Si los streams de entrada no están en el formato deseado, se pasan a través de un codificador para su conversión. El codificador codifica los frames y los devuelve al muxer en forma de paquetes.

El proceso de codificación puede implicar una o más de las siguientes operaciones:

  • Re-codificación: el stream de entrada se decodifica a sus frames crudos y luego se vuelve a codificar en el formato deseado. Esto generalmente resulta en una pérdida de calidad, pero permite cambiar el códec, el formato o los parámetros del stream.
  • Copia de stream: el stream de entrada se pasa directamente al muxer sin ninguna modificación. Esto es posible si el stream de entrada ya está en un formato compatible con el archivo de salida y no se requieren cambios. La copia de stream es mucho más rápida que la re-codificación y no implica ninguna pérdida de calidad.

AVOptions

Estas opciones son proporcionadas directamente por las bibliotecas libavformat, libavdevice y libavcodec. Para ver la lista de AVOptions disponibles, utilice la opción -help. Se dividen en dos categorías:

genéricas
Estas opciones se pueden establecer para cualquier contenedor, códec o dispositivo. Las opciones genéricas se enumeran en las opciones de AVFormatContext para contenedores/dispositivos y en las opciones de AVCodecContext para códecs.
privadas
Estas opciones son específicas del contenedor, dispositivo o códec dado. Las opciones privadas se enumeran en sus contenedores/dispositivos/códecs correspondientes.

Por ejemplo, para escribir una cabecera ID3v2.3 en lugar de la ID3v2.4 predeterminada en un archivo MP3, utilice la opción privada id3v2_version del multiplexor MP3:

ffmpeg -i input.flac -id3v2_version 3 out.mp3

Todas las AVOptions de códec son por flujo, y por lo tanto, se debe adjuntar un especificador de flujo a ellas:

ffmpeg -i multichannel.mxf -map 0:v:0 -map 0:a:0 -map 0:a:0 -c:a:0 ac3 -b:a:0 640k -ac:a:1 2 -c:a:1 aac -b:2 128k out.mp4

En el ejemplo anterior, un flujo de audio multicanal se mapea dos veces para la salida. La primera instancia se codifica con el códec ac3 y una tasa de bits de 640k. La segunda instancia se reduce a 2 canales y se codifica con el códec aac. Se especifica una tasa de bits de 128k para ella utilizando el índice absoluto del flujo de salida.

Nota: la sintaxis -noopcion no se puede utilizar para AVOptions booleanas, utilice -opcion 0/-opcion 1.

Nota: la antigua forma no documentada de especificar AVOptions por flujo anteponiendo v/a/s al nombre de la opción ha quedado obsoleta y se eliminará pronto.

Crea el grafo de filtros especificado por grafo_de_filtros y lo usa para filtrar el flujo.

grafo_de_filtros es una descripción del grafo de filtros a aplicar al flujo, y debe tener una única entrada y una única salida del mismo tipo que el flujo. En el grafo de filtros, la entrada se asocia a la etiqueta "in", y la salida a la etiqueta "out". Ver el manual de filtros de ffmpeg para más información sobre la sintaxis del grafo de filtros.

-reinit_filter[:especificador_de_flujo] entero (entrada,por-flujo)
Esta opción booleana determina si el(los) grafo(s) de filtros al(los) que se alimenta este flujo se reinicializa(n) cuando los parámetros del fotograma de entrada cambian a mitad del flujo. Esta opción está habilitada por defecto, ya que la mayoría de los filtros de video y todos los filtros de audio no pueden manejar desviaciones en las propiedades del fotograma de entrada. Tras la reinicialización, el estado existente del filtro se pierde, como por ejemplo la referencia al contador de fotogramas "n" disponible en algunos filtros. Se pierden los fotogramas en búfer en el momento de la reinicialización. Las propiedades cuyo cambio desencadena la reinicialización son, para video, la resolución del fotograma o el formato de píxeles; para audio, el formato de muestra, la tasa de muestreo, el número de canales o la disposición de canales.

Esta opción booleana determina si un fotograma con parámetros de fotograma diferentes a mitad del flujo se descarta en lugar de provocar la reinicialización del grafo de filtros, ya que esto provocaría la pérdida del estado del filtro. Generalmente útil para evitar paquetes corruptos pero decodificables en entradas de streaming en vivo. El valor por defecto es falso.

Define el número máximo de fotogramas en búfer permitidos en un grafo de filtros. En circunstancias normales, un grafo de filtros no debería almacenar en búfer más que unos pocos fotogramas, especialmente si los fotogramas se le alimentan y se leen de él de manera equilibrada (que es el comportamiento previsto en ffmpeg). Dicho esto, esta opción le permite limitar el número total de fotogramas almacenados en búfer en todos los enlaces de un grafo de filtros. Si se generan más fotogramas, el filtrado se aborta y se devuelve un error. El valor por defecto es 0, lo que significa que no hay límite.

-progress url (global)
Envía información de progreso amigable para programas a url.

La información de progreso se escribe periódicamente y al final del proceso de codificación. Está compuesta por líneas de "clave=valor". clave consiste solo en caracteres alfanuméricos. La última clave de una secuencia de información de progreso es siempre "progress" con el valor "continue" o "end".

El período de actualización se establece utilizando "-stats_period".

ffmpeg -progress pipe:1 -i in.mkv out.mkv
-stdin
Habilita la interacción en la entrada estándar. Activado por defecto a menos que la entrada estándar se use como una entrada. Para deshabilitar explícitamente la interacción, necesita especificar "-nostdin".

Deshabilitar la interacción en la entrada estándar es útil, por ejemplo, si ffmpeg está en el grupo de procesos en segundo plano. Se puede lograr un resultado aproximadamente similar con "ffmpeg ... < /dev/null" pero requiere una shell.

Imprime información de marca de tiempo/latencia. Está desactivado por defecto. Esta opción es principalmente útil para fines de prueba y depuración, y el formato de salida puede cambiar de una versión a otra, por lo que no debe ser empleada por scripts portátiles.

Ver también la opción "-fdebug ts".

-attach nombre_archivo (salida)
Agrega un archivo adjunto al archivo de salida. Esto es compatible con unos pocos formatos como Matroska, por ejemplo, fuentes utilizadas en la renderización de subtítulos. Los archivos adjuntos se implementan como un tipo específico de flujo, por lo que esta opción agregará un nuevo flujo al archivo. Luego es posible usar opciones por flujo en este flujo de la manera habitual. Los flujos adjuntos creados con esta opción se crearán después de todos los demás flujos (es decir, aquellos creados con "-map" o mapeos automáticos.

Tenga en cuenta que para Matroska también debe establecer la etiqueta de metadatos mimetype:

ffmpeg -i INPUT -attach DejaVuSans.ttf -metadata:s:2 mimetype=application/x-truetype-font out.mkv

(asumiendo que el flujo adjunto será el tercero en el archivo de salida).

-dump_attachment[:especificador_de_flujo] nombre_archivo (entrada,por-flujo)
Extrae el flujo adjunto coincidente en un archivo llamado nombre_archivo. Si nombre_archivo está vacío, entonces se usará el valor de la etiqueta de metadatos "filename".

Por ejemplo, para extraer el primer adjunto a un archivo llamado 'out.ttf':

ffmpeg -dump_attachment:t:0 out.ttf -i INPUT

Para extraer todos los adjuntos a archivos determinados por la etiqueta "filename":

ffmpeg -dump_attachment:t "" -i INPUT

Nota técnica -- los adjuntos se implementan como extradata de códec, por lo que esta opción puede usarse en realidad para extraer extradata de cualquier flujo, no solo de adjuntos.

Selecciona el número de pasada (1 o 2). Se utiliza para realizar codificación de video en dos pasadas. -force_key_frames[:especificador_de_flujo] tiempo[,tiempo...] (salida,por-flujo)
-force_key_frames[:especificador_de_stream] expr:expresión (salida,por-stream)
-force_key_frames[:especificador_de_stream] source (salida,por-stream)
force_key_frames puede aceptar argumentos de las siguientes formas:
tiempo[,tiempo...]
Si el argumento consiste en marcas de tiempo, ffmpeg redondeará las marcas de tiempo especificadas a la marca de tiempo de salida más cercana según la base de tiempo del codificador y forzará un fotograma clave en el primer fotograma que tenga una marca de tiempo igual o mayor que la marca de tiempo calculada. Tenga en cuenta que si la base de tiempo del codificador es demasiado burda, es posible que los fotogramas clave se fuercen en fotogramas con marcas de tiempo inferiores al tiempo especificado. La base de tiempo del codificador predeterminada es la inversa de la velocidad de fotogramas de salida, pero puede establecerse de otra manera mediante "-enc_time_base".

Si una de las marcas de tiempo es ""chapters"[delta]", se expande a la marca de tiempo del inicio de todos los capítulos del archivo, desplazada en delta, expresada como tiempo en segundos. Esta opción puede ser útil para garantizar que un punto de búsqueda esté presente en una marca de capítulo o en cualquier otro lugar designado en el archivo de salida.

Por ejemplo, para insertar un fotograma clave a los 5 minutos, más fotogramas clave 0.1 segundos antes del inicio de cada capítulo:

-force_key_frames 0:05:00,chapters-0.1
expr:expresión
Si el argumento va precedido de "expr:", la cadena expresión se interpreta como una expresión y se evalúa para cada fotograma. Se fuerza un fotograma clave en caso de que la evaluación no sea cero.

La expresión en expresión puede contener las siguientes constantes:

n
el número del fotograma procesado actual, comenzando desde 0
n_forced
el número de fotogramas forzados
prev_forced_n
el número del fotograma forzado anterior, es "NAN" cuando aún no se ha forzado ningún fotograma clave
prev_forced_t
la hora del fotograma forzado anterior, es "NAN" cuando aún no se ha forzado ningún fotograma clave
t
el tiempo del fotograma procesado actual

Por ejemplo, para forzar un fotograma clave cada 5 segundos, puede especificar:

-force_key_frames expr:gte(t,n_forced*5)

Para forzar un fotograma clave 5 segundos después de la hora del último forzado, comenzando desde el segundo 13:

-force_key_frames expr:if(isnan(prev_forced_t),gte(t,13),gte(t,prev_forced_t+5))
source
Si el argumento es "source", ffmpeg forzará un fotograma clave si el fotograma actual que se está codificando está marcado como fotograma clave en su origen. En los casos en que este fotograma de origen en particular tenga que ser descartado, se forzará el siguiente fotograma disponible para que sea un fotograma clave en su lugar.

Tenga en cuenta que forzar demasiados fotogramas clave es muy perjudicial para los algoritmos de lookahead de ciertos codificadores: usar opciones de GOP fijo o similares sería más eficiente.

EJEMPLOS

Captura de video y audio

Si se especifica el formato de entrada y el dispositivo, ffmpeg puede capturar video y audio directamente.

ffmpeg -f oss -i /dev/dsp -f video4linux2 -i /dev/video0 /tmp/out.mpg

O con una fuente de audio ALSA (entrada mono, id de tarjeta 1) en lugar de OSS:

ffmpeg -f alsa -ac 1 -i hw:1 -f video4linux2 -i /dev/video0 /tmp/out.mpg

Tenga en cuenta que debe activar la fuente de video y el canal correctos antes de ejecutar ffmpeg con cualquier visor de TV como http://linux.bytesex.org/xawtv/ de Gerd Knorr. También debe configurar correctamente los niveles de grabación de audio con un mezclador estándar.

Captura X11

Capture la pantalla X11 con ffmpeg a través de

ffmpeg -f x11grab -video_size cif -framerate 25 -i :0.0 /tmp/out.mpg

0.0 es el número de pantalla.display de su servidor X11, igual que la variable de entorno DISPLAY.

ffmpeg -f x11grab -video_size cif -framerate 25 -i :0.0+10,20 /tmp/out.mpg

0.0 es el número de pantalla.display de su servidor X11, igual que la variable de entorno DISPLAY. 10 es el desplazamiento x y 20 el desplazamiento y para la captura.

Conversión de formatos de archivo de video y audio

Cualquier formato de archivo y protocolo compatible puede servir como entrada para ffmpeg:

Ejemplos:

  • Puede usar archivos YUV como entrada: 
    ffmpeg -i /tmp/test%d.Y /tmp/out.mpg

    Usará los archivos:

    /tmp/test0.Y, /tmp/test0.U, /tmp/test0.V,
/tmp/test1.Y, /tmp/test1.U, /tmp/test1.V, etc...

    Los archivos Y usan el doble de resolución que los archivos U y V. Son archivos crudos, sin encabezado. Pueden ser generados por todos los decodificadores de video decentes. Debe especificar el tamaño de la imagen con la opción -s si ffmpeg no puede deducirlo.

  • Puede ingresar desde un archivo YUV420P crudo: 
    ffmpeg -i /tmp/test.yuv /tmp/out.avi

    test.yuv es un archivo que contiene datos planares YUV crudos. Cada fotograma se compone del plano Y seguido de los planos U y V con la mitad de resolución vertical y horizontal.

  • Puede generar un archivo YUV420P crudo: 
    ffmpeg -i mydivx.avi hugefile.yuv
  • Puede configurar varios archivos de entrada y salida: 
    ffmpeg -i /tmp/a.wav -s 640x480 -i /tmp/a.yuv /tmp/a.mpg

    Convierte el archivo de audio a.wav y el archivo de video YUV crudo a.yuv al archivo MPEG a.mpg.

  • También puede hacer conversiones de audio y video al mismo tiempo: 
    ffmpeg -i /tmp/a.wav -ar 22050 /tmp/a.mp2

    Convierte a.wav a audio MPEG a una tasa de muestreo de 22050 Hz.

  • Puede codificar a varios formatos al mismo tiempo y definir un mapeo de flujo de entrada a flujos de salida: 
    ffmpeg -i /tmp/a.wav -map 0:a -b:a 64k /tmp/a.mp2 -map 0:a -b:a 128k /tmp/b.mp2

    Convierte a.wav a a.mp2 a 64 kbits y a b.mp2 a 128 kbits. '-map archivo:índice' especifica qué flujo de entrada se usa para cada flujo de salida, en el orden de definición de los flujos de salida.

  • Puede transcodificar VOBs descifrados: 
    ffmpeg -i snatch_1.vob -f avi -c:v mpeg4 -b:v 800k -g 300 -bf 2 -c:a libmp3lame -b:a 128k snatch.avi

    Este es un ejemplo típico de ripeo de DVD; la entrada es un archivo VOB, la salida un archivo AVI con video MPEG-4 y audio MP3. Tenga en cuenta que en este comando usamos fotogramas B, por lo que el flujo MPEG-4 es compatible con DivX5, y el tamaño del GOP es 300, lo que significa un fotograma intra cada 10 segundos para video de entrada de 29.97 fps. Además, el flujo de audio está codificado en MP3, por lo que necesita habilitar el soporte LAME pasando "--enable-libmp3lame" a configure. El mapeo es particularmente útil para la transcodificación de DVD para obtener el idioma de audio deseado.

    NOTA: Para ver los formatos de entrada compatibles, use "ffmpeg -demuxers".

  • Puede extraer imágenes de un video o crear un video a partir de muchas imágenes:

    Para extraer imágenes de un video:

    ffmpeg -i foo.avi -r 1 -s WxH -f image2 foo-%03d.jpeg

    Esto extraerá un fotograma de video por segundo del video y los generará en archivos llamados foo-001.jpeg, foo-002.jpeg, etc. Las imágenes se redimensionarán para que coincidan con los nuevos valores WxH.

    Si desea extraer solo un número limitado de fotogramas, puede usar el comando anterior en combinación con la opción "-frames:v" o "-t", o en combinación con -ss para comenzar a extraer desde un punto específico en el tiempo.

    Para crear un video a partir de muchas imágenes:

    ffmpeg -f image2 -framerate 12 -i foo-%03d.jpeg -s WxH foo.avi

    La sintaxis "foo-%03d.jpeg" especifica usar un número decimal compuesto por tres dígitos rellenado con ceros para expresar el número de secuencia. Es la misma sintaxis soportada por la función printf de C, pero solo los formatos que aceptan un entero normal son adecuados.

    Al importar una secuencia de imágenes, -i también soporta la expansión de patrones comodín similares a los de shell (globbing) internamente, seleccionando la opción "-pattern_type glob" específica de image2.

    Por ejemplo, para crear un video a partir de nombres de archivo que coincidan con el patrón comodín "foo-*.jpeg":

    ffmpeg -f image2 -pattern_type glob -framerate 12 -i 'foo-*.jpeg' -s WxH foo.avi
  • Puede poner varios flujos del mismo tipo en la salida: 
    ffmpeg -i test1.avi -i test2.avi -map 1:1 -map 1:0 -map 0:1 -map 0:0 -c copy -y test12.nut

    El archivo de salida resultante test12.nut contendrá los primeros cuatro flujos de los archivos de entrada en orden inverso.

  • Para forzar salida de video CBR: 
    ffmpeg -i myfile.avi -b 4000k -minrate 4000k -maxrate 4000k -bufsize 1835k out.m2v
  • Las cuatro opciones lmin, lmax, mblmin y mblmax usan unidades 'lambda', pero puede usar la constante QP2LAMBDA para convertir fácilmente de unidades 'q': 
    ffmpeg -i src.ext -lmax 21*QP2LAMBDA dst.ext
