La biblioteca libavformat proporciona algunas opciones globales genéricas, que pueden establecerse en todos los protocolos. Además, cada protocolo puede admitir las llamadas opciones privadas, que son específicas de ese

PROTOCOLO

S

Los protocolos son elementos configurados en FFmpeg que permiten el acceso a recursos que requieren protocolos

específicos.

Cuando configura su compilación de FFmpeg, todos los protocolos admitidos están habilitados por defecto. Puede listar todos los disponibles usando la opción de configuración "--list-protocols"

Puede deshabilitar todos los protocolos usando la opción de configuración "--disable-protocols", y habilitar selectivamente un protocolo usando la opción "--enable-protocol=PROTOCOLO", o puede deshabilitar un protocolo particular usando la opción "--disable-protocol=PROTOCOLO"

.

La opción "-protocols" de las herramientas ff* mostrará la lista de protocolos

admitidos.

amq

p

Advanced Message Queueing Protocol (AMQP) versión 0-9-1 es un protocolo de comunicación publicar-suscribir basado en un agente (broker)

.

FFmpeg debe compilarse con --enable-librabbitmq para admitir AMQP. También debe ejecutarse un agente AMQP separado. Un ejemplo de agente AMQP de código abierto es

RabbitMQ.

Después de iniciar el agente, un cliente FFmpeg puede transmitir datos al agente usando el

comando: 
ffmpeg -re -i input -f mpegts amqp://[[user]:[password]@]hostname[:port]
[/vhost]

Donde hostname y puerto (el valor por defecto es 5672) es la dirección del agente. El cliente también puede establecer un usuario/contraseña para la autenticación. El valor por defecto para ambos campos es "guest". El nombre del host virtual en el agente puede establecerse con vhost. El valor por defecto es

"/".

Múltiples suscriptores pueden transmitir desde el agente usando el

comando: 
ffplay amqp://[[user]:[password]@]hostname[:port]
[/vhost]

En RabbitMQ, todos los datos publicados en el agente fluyen a través de un intercambio específico, y cada cliente suscriptor tiene una cola/búfer asignada. Cuando un paquete llega a un intercambio, puede copiarse a la cola de un cliente dependiendo de los campos exchange y

routing_key.

Se admiten las siguientes

opciones:
exchan
ge
Establece el intercambio (exchange) a usar en el agente. RabbitMQ tiene varios intercambios predefinidos: "amq.direct" es el intercambio por defecto, donde el publicador y el suscriptor deben tener un routing_key coincidente; "amq.fanout" es lo mismo que una operación de difusión (es decir, los datos se reenvían a todas las colas del intercambio fanout independientemente del routing_key); y "amq.topic" es similar a "amq.direct", pero permite un emparejamiento de patrones más complejo (consulte la documentación de RabbitMQ)
.
routing_k
ey
Establece la clave de enrutamiento (routing key). El valor por defecto es "amqp". La clave de enrutamiento se usa en los intercambios "amq.direct" y "amq.topic" para decidir si los paquetes se escriben en la cola de un
suscriptor.
pkt_si
ze
Tamaño máximo de cada paquete enviado/recibido al agente. El valor por defecto es 131072. El mínimo es 4096 y el máximo es cualquier valor grande (representable por un int). rtsp

Real Time Streaming Protocol (RFC 2326).

The RTSP protocol handler is available in both the "muxer" and "demuxer" modes.

Muxer

The syntax for a RTSP url given to the muxer is:

rtsp://<destination>[:<port>]/<stream_name>[?<options>]

The RTP packets are sent to destination on port port, or to port 554 if no port is specified. options is a "&"-separated list of options that are specific to the RTSP protocol handler.

The following options are supported.

rtsp_flags
Set RTSP flags.

The following values are accepted:

send_rtcp
Send RTCP sender reports.
rfc2190
Use RFC 2190 packetization instead of RFC 4629 for H.263.
skip_rtcp
Don't send RTCP sender reports.
h264_mode0
Use mode 0 for H.264 in RTP.
send_bye
Send RTCP BYE packets when finishing.

Default value is 0.

min_port
Set minimum local UDP port. Default value is 5000.
max_port
Set maximum local UDP port. Default value is 65000.
buffer_size
Set the maximum socket buffer size in bytes.
pkt_size
Set max send packet size (in bytes). Default value is 1472.

Demuxer

The following options are supported.

initial_pause
Do not start playing the stream immediately if set to 1. Default value is 0.
rtsp_transport
Set RTSP transport protocols.

It accepts the following values:

udp
Use UDP as lower transport protocol.
tcp
Use TCP (interleaving within the RTSP control channel) as lower transport protocol.
udp_multicast
Use UDP multicast as lower transport protocol.
http
Use HTTP tunneling as lower transport protocol, which is useful for passing proxies.
https
Use HTTPs tunneling as lower transport protocol, which is useful for passing proxies and widely used for security consideration.

Multiple lower transport protocols may be specified, in that case they are tried one at a time (if the setup of one fails, the next one is tried). For the muxer, only the tcp and udp options are supported.

rtsp_flags
Set RTSP flags.

The following values are accepted:

filter_src
Accept packets only from negotiated peer address and port.
listen
Act as a server, listening for an incoming connection.
prefer_tcp
Try TCP for RTP transport first, if TCP is available as RTSP RTP transport.
satip_raw
Export raw MPEG-TS stream instead of demuxing. The flag will simply write out the raw stream, with the original PAT/PMT/PIDs intact.

Default value is none.

allowed_media_types
Set media types to accept from the server.

The following flags are accepted:

video
audio
data
subtitle

By default it accepts all media types.

min_port
Set minimum local UDP port. Default value is 5000.
max_port
Set maximum local UDP port. Default value is 65000.
listen_timeout
Set maximum timeout (in seconds) to establish an initial connection. Setting listen_timeout > 0 sets rtsp_flags to listen. Default is -1 which means an infinite timeout when listen mode is set.
reorder_queue_size
Set number of packets to buffer for handling of reordered packets.
timeout
Set socket TCP I/O timeout in microseconds.
user_agent
Override User-Agent header. If not specified, it defaults to the libavformat identifier string.
buffer_size
Set the maximum socket buffer size in bytes.

When receiving data over UDP, the demuxer tries to reorder received packets (since they may arrive out of order, or packets may get lost totally). This can be disabled by setting the maximum demuxing delay to zero (via the "max_delay" field of AVFormatContext).

When watching multi-bitrate Real-RTSP streams with ffplay, the streams to display can be chosen with "-vst" n and "-ast" n for video and audio respectively, and can be switched on the fly by pressing "v" and "a".

Examples

The following examples all make use of the ffplay and ffmpeg tools.

  • Watch a stream over UDP, with a max reordering delay of 0.5 seconds: 
    ffplay -max_delay 500000 -rtsp_transport udp rtsp://server/video.mp4
  • Watch a stream tunneled over HTTP: 
    ffplay -rtsp_transport http rtsp://server/video.mp4
  • Send a stream in realtime to a RTSP server, for others to watch: 
    ffmpeg -re -i <input> -f rtsp -muxdelay 0.1 rtsp://server/live.sdp
  • Receive a stream in realtime: 
    ffmpeg -rtsp_flags listen -i rtsp://ownaddress/live.sdp <output>

sap

Session Announcement Protocol (RFC 2974). This is not technically a protocol handler in libavformat, it is a muxer and demuxer. It is used for signalling of RTP streams, by announcing the SDP for the streams regularly on a separate port.

Muxer

The syntax for a SAP url given to the muxer is:

sap://<destination>[:<port>][?<options>]

The RTP packets are sent to destination on port port, or to port 5004 if no port is specified. options is a "&"-separated list. The following options are supported:

announce_addr=address
Specify the destination IP address for sending the announcements to. If omitted, the announcements are sent to the commonly used SAP announcement multicast address 224.2.127.254 (sap.mcast.net), or ff0e::2:7ffe if destination is an IPv6 address.
announce_port=port
Specify the port to send the announcements on, defaults to 9875 if not specified.
ttl=ttl
Specify the time to live value for the announcements and RTP packets, defaults to 255.
same_port=0|1
If set to 1, send all RTP streams on the same port pair. If zero (the default), all streams are sent on unique ports, with each stream on a port 2 numbers higher than the previous. VLC/Live555 requires this to be set to 1, to be able to receive the stream. The RTP stack in libavformat for receiving requires all streams to be sent on unique ports.

Example command lines follow.

To broadcast a stream on the local subnet, for watching in VLC:

ffmpeg -re -i <input> -f sap sap://224.0.0.255?same_port=1

Similarly, for watching in ffplay:

ffmpeg -re -i <input> -f sap sap://224.0.0.255

And for watching in ffplay, over IPv6:

ffmpeg -re -i <input> -f sap sap://[ff0e::1:2:3:4]

Demuxer

The syntax for a SAP url given to the demuxer is:

sap://[<address>][:<port>]

address is the multicast address to listen for announcements on, if omitted, the default 224.2.127.254 (sap.mcast.net) is used. port is the port that is listened on, 9875 if omitted.

The demuxers listens for announcements on the given address and port. Once an announcement is received, it tries to receive that particular stream.

Example command lines follow.

To play back the first stream announced on the normal SAP multicast address:

ffplay sap://

To play back the first stream announced on one the default IPv6 SAP multicast address:

ffplay sap://[ff0e::2:7ffe]

srt

Haivision Secure Reliable Transport Protocol via libsrt.

The supported syntax for a SRT URL is:

srt://<hostname>:<port>[?<options>]

options contains a list of &-separated options of the form key=val.

or

<options> srt:

where options is a list of &-separated options of the form key=val.

For more details on the options, please refer to the libsrt documentation.

Example

To push a stream using SRT:

ffmpeg -re -i input.mp4 -c copy -f mpegts "srt://server.com:1234?mode=caller&pkt_size=1316&latency=100ms"

To pull a stream using SRT:

ffplay "srt://0.0.0.0:1234?mode=listener&latency=100ms"

Note

FFmpeg builds without libsrt support will not be able to use this protocol.

stream_loop

Loop a stream indefinitely.

The supported syntax for a stream_loop url is:

stream_loop://<input_url>

For example:

ffmpeg -i stream_loop://input.ts -c copy output.ts

This will loop the input.ts file indefinitely, writing the looped stream to output.ts.

The following options are supported:

loop
Set the number of times to loop the stream. If not set, the stream is looped indefinitely.
seek_point
Set the seek point for each loop iteration. If not set, it starts from the beginning of the stream.

Example:

ffmpeg -stream_loop 5 -i input.ts -c copy output.ts

This will loop the input.ts file 5 times.

Example:

ffmpeg -seek_point 50.0 -i input.ts -c copy output.ts

This will loop the input.ts file indefinitely, starting from 50% of the stream duration.

Note that the stream_loop protocol handler does not support writing directly to a stream_loop url.

tcp

Transmission Control Protocol.

The supported syntax for a TCP url is:

tcp://<hostname>:<port>[?<options>]

or

tcp://<port>[?<options>]

The protocol accepts the following options:

listen
If set to any value, listen for an incoming connection. Outgoing connection is done by default.
connect_timeout
Set the connection timeout in microseconds. Default value is 10000000.
rw_timeout
Set the read/write timeout in microseconds. Default value is 10000000.
buffer_size
Set the maximum socket buffer size in bytes.

Example command lines follow.

To stream a file over TCP, accepting incoming connections on port 1234:

ffmpeg -re -i input.ts -f format tcp://1234?listen=1

To stream a file over TCP to a remote host:

ffmpeg -re -i input.ts -f format tcp://remote_host:1234

To receive a stream over TCP:

ffmpeg -i tcp://0.0.0.0:1234?listen=1 output.ts

To receive a stream from a remote host over TCP:

ffmpeg -i tcp://remote_host:1234 output.ts

tls

Transport Layer Security.

The supported syntax for a TLS url is:

tls://<hostname>:<port>[?<options>]

The protocol accepts the following options:

listen
If set to any value, listen for an incoming connection. Outgoing connection is done by default.
certfile
Path to the certificate file.
keyfile
Path to the private key file.
cafile
Path to the CA certificate file.
password
Password for decrypting the private key file.
tls_verify
If set to 1, verify the peer's certificate. Default value is 0.
connect_timeout
Set the connection timeout in microseconds. Default value is 10000000.
rw_timeout
Set the read/write timeout in microseconds. Default value is 10000000.

Example command lines follow.

To stream a file over TLS, accepting incoming connections on port 1234:

ffmpeg -re -i input.ts -f format tls://1234?listen=1?certfile=server.crt?keyfile=server.key

To stream a file over TLS to a remote host:

ffmpeg -re -i input.ts -f format tls://remote_host:1234?certfile=client.crt?keyfile=client.key?tls_verify=1?cafile=ca.crt

To receive a stream over TLS:

ffmpeg -i tls://0.0.0.0:1234?listen=1?certfile=server.crt?keyfile=server.key output.ts

To receive a stream from a remote host over TLS:

ffmpeg -i tls://remote_host:1234?certfile=client.crt?keyfile=client.key?tls_verify=1?cafile=ca.crt output.ts

Note

FFmpeg needs to be compiled with OpenSSL support to use TLS.

QSV

Intel Quick Sync Video (QSV) is a hardware video encoding/decoding engine integrated into Intel CPUs. FFmpeg can leverage QSV for video processing via the QSV interfaces.

QSV is supported for encoding, decoding, and some video filtering operations. Note that QSV operations are tied to specific Intel hardware and may require specific drivers and libraries to be installed on your system.

The primary QSV encoders and decoders are:

h264_qsv
QSV H.264 encoder.
hevc_qsv
QSV HEVC (H.265) encoder.
mpeg2_qsv
QSV MPEG-2 encoder.
vp8_qsv
QSV VP8 encoder.
vp9_qsv
QSV VP9 encoder.
h264_qsvdec
QSV H.264 decoder.
hevc_qsvdec
QSV HEVC (H.265) decoder.
mpeg2_qsvdec
QSV MPEG-2 decoder.
vp8_qsvdec
QSV VP8 decoder.
vp9_qsvdec
QSV VP9 decoder.

QSV hardware acceleration can be enabled using the appropriate encoder or decoder. The QSV encoders share a common set of options, which can be found by running ffmpeg -h encoder=h264_qsv.

For example, to encode a video using the QSV H.264 encoder:

ffmpeg -i input.mp4 -c:v h264_qsv -b:v 5M output.mp4

To decode a video using the QSV H.264 decoder:

ffmpeg -c:v h264_qsv -i input.h264 output.mp4

QSV filters like scale_qsv, rotate_qsv, hwupload_qsv, and hwdownload_qsv are also available for performing hardware-accelerated video processing.

You can check if your FFmpeg build supports QSV by running ffmpeg -encoders | grep qsv and ffmpeg -decoders | grep qsv.

Note that using QSV requires the VAAPI (Video Acceleration API) backend on Linux, or the Media SDK on Windows.

QSV encoders generally offer faster encoding speeds compared to software encoders but may have slightly lower compression efficiency or quality at the same bitrate. The specific performance and quality depend on the hardware and the chosen encoder settings.

Some options common to QSV encoders include:

global_quality
Set the quality level for the encoder. Lower values mean higher quality and larger file size. Range is typically 1-51.
rc
Set the rate control mode. Common modes include:
cqp
Constant Quantization Parameter.
cbr
Constant Bitrate.
vbr
Variable Bitrate.
la
Look Ahead Variable Bitrate.
qp
Quantization Parameter value for CQP mode.
la_frames
Number of frames for Look Ahead.
lookahead_depth
Maximum number of frames that can be looked ahead.
preset
Encoder preset for balancing speed and quality. Options like 'veryfast', 'fast', 'medium', 'slow', 'veryslow' might be available.

Refer to the specific encoder documentation (e.g., ffmpeg -h encoder=h264_qsv) for a complete list of available options and their descriptions.

SRTP

Secure Real-time Transport Protocol.

SRTP is used to encrypt and authenticate RTP traffic.

The SRTP protocol handler can be used with RTP-based protocols like RTSP or UDP.

SRTP requires keying material to encrypt/decrypt the media stream. FFmpeg supports several keying methods:

insecure
Use this option if no key is provided. This essentially disables SRTP, but allows negotiation to proceed.
keyfile=filename
Specifies a file containing the SRTP key. The key should be in binary format. The key length depends on the cipher used (e.g., 30 bytes for AES-CM-128-HMAC-SHA1-80).
tx_keyfile=filename
Specifies a file containing the SRTP transmit key.
rx_keyfile=filename
Specifies a file containing the SRTP receive key.
keyformat=format
Specifies the format of the key in the keyfile. Supported formats include binary (default), hex, and base64.
cipher=cipher_name
Specifies the SRTP cipher. Default is aes-cm-128-sha1-80. Other options may include aes-cm-128-sha1-32.

The SRTP options are passed as part of the URL query string.

Example

To play an RTSP stream that uses SRTP with a pre-shared key:

ffplay -rtsp_transport tcp "rtsp://server/stream?srtp_keyfile=key.bin&srtp_keyformat=binary"

To send a stream using RTSP over SRTP:

ffmpeg -re -i input.ts -c copy -f rtsp "rtsp://server/stream?srtp_tx_keyfile=tx_key.bin&srtp_rx_keyfile=rx_key.bin"

Note that FFmpeg needs to be compiled with support for SRTP (typically via libsrtp) to use this protocol.

SSH

Secure Shell.

The SSH protocol handler allows FFmpeg to read from or write to files on remote machines via SSH (using SCP or SFTP).

The supported syntax is:

ssh://[user@]hostname[:port]/path/to/file[?options]

If the user is not specified, it defaults to the current user.

The following options are supported:

transport=scp|sftp
Specify the transport protocol to use. Defaults to sftp.
keyfile=path
Specify an SSH private key file to use for authentication.
password=password
Specify the SSH password for authentication. Note that using passwords directly in the command line can be insecure.
port=number
Specify the SSH port number. Defaults to 22.

Example

To copy a file from a remote server using SFTP:

ffmpeg -i ssh://user@remote.host/path/to/input.mp4 output.mp4

To copy a file from a remote server using SCP with a specific key:

ffmpeg -i ssh://user@remote.host/path/to/input.mp4?transport=scp?keyfile=/path/to/id_rsa output.mp4

To upload a file to a remote server using SFTP:

ffmpeg -i input.mp4 -c copy ssh://user@remote.host/path/to/output.mp4

Note that FFmpeg needs to be compiled with libssh support to use this protocol.

Build Configuration

The build configuration of FFmpeg determines which features, codecs, protocols, and filters are included in the final executable. This is managed primarily through the ./configure script before compilation.

Key aspects of build configuration:

Enabled/Disabled Components
Using --enable-FEATURE and --disable-FEATURE flags, users can control the inclusion of specific codecs (e.g., --enable-libx264), protocols (e.g., --enable-rtsp), filters, and hardware acceleration APIs (e.g., --enable-vaapi).
External Library Linking
FFmpeg relies on many external libraries (e.g., OpenSSL for TLS, libvpx for VP8/VP9, FreeType for text rendering). The configure script detects and links against these libraries if they are found on the system and the corresponding --enable-... flag is used.

FFmpeg can be configured for various platforms and architectures. Options like --enable-cross-compile and specific target architectures allow building FFmpeg for different environments.
Documentation
The configure script also manages the build process for documentation, if enabled.

After running configure, the build process typically involves:

  1. make: Compiles the FFmpeg source code and its dependencies.
  2. make install (optional): Installs the compiled FFmpeg binaries, libraries, and headers to a specified location (or system defaults).

Customizing the build configuration is essential for tailoring FFmpeg to specific use cases, optimizing performance, or enabling support for particular hardware or formats.

Options

FFmpeg uses a wide array of options to control its behavior during encoding, decoding, filtering, and streaming. These options are typically passed on the command line.

Options can be broadly categorized:

Global Options
Apply to the FFmpeg process as a whole, often affecting input/output or general behavior. Examples include:
  • -y: Overwrite output files without asking.
  • -n: Do not overwrite output files, if one already exists.
  • -loglevel level: Set the logging level (e.g., error, warning, info, debug).
  • -hide_banner: Do not show version and configuration information.
Input Options
Apply to specific input files or streams, specified before the input URL. Often prefixed with -i. Examples:
  • -re: Read input at native frame rate (for live streaming).
  • -stream_loop number: Loop the input file a specified number of times.
  • -ss position: Seek to a specific position in the input.
  • -t duration: Limit the duration of input read.
  • -timeout value: Set network timeout.
Output Options
Apply to specific output files or streams, specified before the output URL. Examples:
  • -f format: Force output format.
  • -max_muxing_queue_size size: Set maximum muxing queue size.
  • -map map: Select streams to be mapped to the output.
Codec Options
Control the behavior of encoders and decoders. Prefixed with -c:v (video) or -c:a (audio). Examples:
  • -b:v bitrate: Target video bitrate.
  • -crf value: Constant Rate Factor (quality).
  • -preset speed: Encoding speed preset.
  • -profile:v profile: H.264/HEVC profile.
  • -pix_fmt format: Pixel format.
Filter Options
Used with -vf, -af, or -filter_complex to control filters. Examples:
  • -vf scale=width:height: Resize video.
  • -af aresample=rate: Resample audio.
Protocol Specific Options
Options embedded within URLs to configure protocols like RTSP, HTTP, etc. (e.g., rtsp://server/stream?rtsp_flags=listen).

The full documentation for options related to specific codecs, formats, protocols, and filters can be found by running FFmpeg commands like:

  • ffmpeg -h encoder=libx264
  • ffmpeg -h demuxer=matroska
  • ffmpeg -h protocol=rtsp
  • ffmpeg -h filter=scale

Running ffmpeg -h full provides a comprehensive list of all available options, codecs, filters, etc.
