FFI::CheckLib(3) Documentación de Perl aportada por el usuario FFI::CheckLib(3)

NOMBRE

FFI::CheckLib - Comprobar que una biblioteca está disponible para FFI

VERSIÓN

versión 0.31

SINOPSIS

use FFI::CheckLib;

check_lib_or_exit( lib => 'jpeg', symbol => 'jinit_memory_mgr' );
check_lib_or_exit( lib => [ 'iconv', 'jpeg' ] );

# o preguntar la ruta a la biblioteca y luego:
print "dónde encontrar la biblioteca jpeg: ";
my $path = <STDIN>;
check_lib_or_exit( lib => 'jpeg', libpath => $path );

DESCRIPCIÓN

Este módulo comprueba si una biblioteca dinámica particular está disponible para que FFI la use. Está modelado en gran medida en Devel::CheckLib, pero encontrará bibliotecas dinámicas incluso cuando los paquetes de desarrollo no estén instalados. También proporciona una función find_lib que devolverá la ruta completa a la biblioteca dinámica encontrada, la cual puede ser alimentada directamente a FFI::Platypus u otro sistema FFI.

Aunque está destinado principalmente a módulos FFI a través de FFI::Platypus y similares, este módulo no usa realmente ningún FFI para hacer su detección y sondeo. Este módulo no tiene ninguna dependencia de ejecución que no sea del núcleo. La suite de pruebas sí depende de Test2::Suite.

FUNCIONES

Todas estas toman los mismos parámetros con nombre y se exportan por defecto.

find_lib

my(@libs) = find_lib(%args);

Esto devolverá una lista de bibliotecas dinámicas, o una lista vacía si no se encontraron.

[versión 0.05]

Si se llama en contexto escalar, devolverá la primera biblioteca encontrada.

Los argumentos son pares clave-valor con estas claves:

lib
Debe ser una cadena con el nombre de una sola biblioteca o una referencia a un arreglo de cadenas con nombres de bibliotecas. Dependiendo de su plataforma, "CheckLib" antepondrá "lib" o añadirá ".dll" o ".so" al buscar.

[versión 0.11]

Como caso especial, si se especifica "*" entonces cualquier biblioteca encontrada coincidirá.

libpath
Una cadena o un arreglo de rutas adicionales para buscar bibliotecas.
systempath
[versión 0.11]

Una cadena o un arreglo de rutas del sistema para buscar en lugar de dejar que FFI::CheckLib determine la ruta del sistema. Puede establecer esto a "[]" para no buscar en ninguna ruta del sistema.

symbol
Una cadena o una lista de nombres de símbolos que deben encontrarse.
verify
Una referencia a código utilizada para verificar que una biblioteca es realmente la que usted quiere. Debe tomar dos argumentos, que son el nombre de la biblioteca y la ruta completa al archivo de la biblioteca. Debe devolver verdadero si es aceptable, y falso en caso contrario. Puede usar esto en conjunto con FFI::Platypus para determinar si va a satisfacer sus necesidades. Ejemplo: 
use FFI::CheckLib;
use FFI::Platypus;

my($lib) = find_lib(
  lib => 'foo',
  verify => sub {
    my($name, $libpath) = @_;

    my $ffi = FFI::Platypus->new;
    $ffi->lib($libpath);

    my $f = $ffi->function('foo_version', [] => 'int');

    return $f->call() >= 500; # aceptamos la versión 500 o superior
  },
);
recursive
[versión 0.11]

Buscar recursivamente bibliotecas en cualquier ruta que no sea del sistema (las proporcionadas a través de "libpath" arriba).

try_linker_script
[versión 0.24]

Algunos proveedores proporcionan archivos ".so" que son scripts de enlazado que apuntan a la biblioteca compartida binaria real. Estos scripts de enlazado pueden ser usados por gcc o clang, pero no son directamente utilizables por FFI::Platypus y compañía. En plataformas seleccionadas, esta opción usará el comando de enlazado ("ld") para intentar resolver el ".so" real para archivos que no son binarios. Dado que hay una sobrecarga adicional, esto está desactivado por defecto.

Un ejemplo es libyaml en distribuciones de Linux basadas en Red Hat. En Debian esto se maneja con enlaces simbólicos y no se requiere ninguna truco.

alien
[versión 0.25]

Si no se pueden encontrar bibliotecas, intente con los aliens dados en su lugar. Las clases Alien especificadas deben proporcionar la interfaz Alien::Base para bibliotecas dinámicas, es decir, deben proporcionar un método llamado "dynamic_libs" que devuelva una lista de bibliotecas dinámicas.

[versión 0.28]

En 0.28 y versiones posteriores, si el Alien no está instalado, se ignorará y este módulo buscará solo en los directorios del sistema o los especificados. Este módulo lanzará una excepción si el Alien no parece un nombre de módulo o si no proporciona un método "dynamic_libs" (el cual es implementado por todas las subclases de Alien::Base).

[versión 0.30] [cambio incompatible]

A partir de la versión 0.30, las bibliotecas proporcionadas por los Aliens se prefieren sobre las bibliotecas del sistema. El pensamiento original era que usted quiere preferir las bibliotecas del sistema porque es más probable que sean parcheadas con actualizaciones regulares del sistema. Desafortunadamente, la razón por la que un módulo necesita instalar un Alien es probablemente porque la biblioteca del sistema no es lo suficientemente nueva, así que ahora preferimos los Aliens.

assert_lib

assert_lib(%args);

Se comporta exactamente igual que find_lib, excepto que en lugar de devolver una lista vacía en caso de fallo, lanza una excepción.

check_lib_or_exit

check_lib_or_exit(%args);

Se comporta exactamente igual que assert_lib, excepto que en lugar de morir, emite una advertencia (con exactamente el mismo mensaje de error) y sale. Esto está destinado a ser usado en "Makefile.PL" o "Build.PL"

find_lib_or_exit

[versión 0.05]

my(@libs) = find_lib_or_exit(%args);

Se comporta exactamente igual que find_lib, excepto que si la biblioteca no se encuentra, llamará a exit con un diagnóstico apropiado.

find_lib_or_die

[versión 0.06]

my(@libs) = find_lib_or_die(%args);

Se comporta exactamente igual que find_lib, excepto que si la biblioteca no se encuentra, morirá con un diagnóstico apropiado.

check_lib

my $bool = check_lib(%args);

Se comporta exactamente igual que find_lib, excepto que devuelve verdadero (1) al encontrar las bibliotecas apropiadas o falso (0) en caso contrario.

which

[versión 0.17]

my $path = which($name);

Devuelve la ruta a la primera biblioteca que coincide con el nombre dado.

No se exporta por defecto.

where

[versión 0.17]

my @paths = where($name);

Devuelve las rutas a todas las bibliotecas que coinciden con el nombre dado.

No se exporta por defecto.

has_symbols

[versión 0.17]

my $bool = has_symbols($path, @symbol_names);

Devuelve verdadero si todos los símbolos pueden ser encontrados en la biblioteca dinámica ubicada en la ruta dada. Puede ser útil en conjunto con "verify" con "find_lib&qu FFI::CheckLib(3pm)

NAME

FFI::CheckLib – helper module for checking the availability of dynamic libraries.

VERSION

0.26

SYNOPSIS

    use FFI::CheckLib;

    # Find the library with a given name.
    # The library will be searched in paths defined by libpath(), system_path(),
    # and environment variables.
    my $lib = FFI::CheckLib->find_lib('my_library_name');

    # find_lib can also search for a specific version
    my $lib = FFI::CheckLib->find_lib('my_library_name', '1.2.3');

    # You can provide a list of possible names
    my $lib = FFI::CheckLib->find_lib(
        ['libfoo.so.1', 'libfoo.so', 'foo.dll'],
        '1.2.3',
    );

    # Check if a library exists and is usable.
    # This will call dlopen() or a similar mechanism.
    FFI::CheckLib->check_lib('my_library_name');

    # You can also specify a version or list of names.
    FFI::CheckLib->check_lib(
        ['libfoo.so.1', 'libfoo.so', 'foo.dll'],
        '1.2.3',
    );

    # And you can get the full path to a library.
    my $path = FFI::CheckLib->lib_path('my_library_name');

    # Or check for a specific version.
    my $path = FFI::CheckLib->lib_path('my_library_name', '1.2.3');

    # You can also get the list of system paths that FFI::CheckLib searches.
    my $path_ref = FFI::CheckLib->system_path;
    print "$path_ref\n";

DESCRIPTION

This module is designed to help find dynamic libraries on the system. It provides a simple interface to locate libraries and check their availability.

It is primarily intended for use by other Perl modules that need to link against external dynamic libraries, such as those that use FFI::Platypus.

FFI::CheckLib searches for libraries in several locations:

  • Directories specified by the libpath function.
  • System library paths, as returned by the system_path function.
  • Paths specified by environment variables like LD_LIBRARY_PATH, PATH (on Windows), etc.
  • Platform-specific package manager paths (e.g., Homebrew, MacPorts on macOS).

FUNCTIONS

libpath

my $path = FFI::CheckLib::libpath;
push @$path, '/path/to/my/lib';

Returns a list reference to directories that FFI::CheckLib will search for libraries. By default, this list is empty. You can modify this list to include custom library paths.

This function is not exported by default.

system_path

[version 0.20]

my $path = FFI::CheckLib::system_path;

Returns the system path as a list reference. On some systems, this is "PATH" on others it might be "LD_LIBRARY_PATH" on still others it could be something completely different. So although you may add items to this list, you should probably do some careful consideration before you do so.

This function is not exportable, even on request.

ENVIRONMENT

FFI::CheckLib responds to these environment variables:

FFI_CHECKLIB_PACKAGE
On macOS platforms with Homebrew http://brew.sh and/or MacPorts https://www.macports.org installed, their corresponding lib paths will be automatically appended to $system_path. In case of having both managers installed, Homebrew will appear before.

This behaviour can be overridden using the environment variable "FFI_CHECKLIB_PACKAGE".

Allowed values are:

- "none": Won't use either Homebrew's path nor MacPorts - "homebrew": Will append "$(brew --prefix)/lib" to the system paths - "macports": Will append "port"'s default lib path

A comma separated list is also valid:

export FFI_CHECKLIB_PACKAGE=macports,homebrew

Order matters. So in this example, MacPorts' lib path appears before Homebrew's path.

FFI_CHECKLIB_PATH
List of directories that will be considered by FFI::CheckLib as additional "system directories". They will be searched before other system directories but after "libpath". The variable is colon separated on Unix and semicolon separated on Windows. If you use this variable, "FFI_CHECKLIB_PACKAGE" will be ignored.
PATH
On Windows the "PATH" environment variable will be used as a search path for libraries.

On some operating systems "LD_LIBRARY_PATH", "DYLD_LIBRARY_PATH", "DYLD_FALLBACK_LIBRARY_PATH" or others may be used as part of the search for dynamic libraries and may be used (indirectly) by FFI::CheckLib as well.

FAQ

Why not just use "dlopen"?
Calling "dlopen" on a library name and then "dlclose" immediately can tell you if you have the exact name of a library available on a system. It does have a number of drawbacks as well.
No absolute or relative path
It only tells you that the library is somewhere on the system, not having the absolute or relative path makes it harder to generate useful diagnostics.
POSIX only
This doesn't work on non-POSIX systems like Microsoft Windows. If you are using a POSIX emulation layer on Windows that provides "dlopen", like Cygwin, there are a number of gotchas there as well. Having a layer written in Perl handles this means that developers on Unix can develop FFI that will more likely work on these platforms without special casing them.
inconsistent implementations
Even on POSIX systems you have inconsistent implementations. OpenBSD for example don't usually include symlinks for ".so" files meaning you need to know the exact ".so" version.
non-system directories
By default "dlopen" only works for libraries in the system paths. Most platforms have a way of configuring the search for different non-system paths, but none of them are portable, and are usually discouraged anyway. Alien and friends need to do searches for dynamic libraries in non-system directories for "share" installs.
My 64-bit Perl is misconfigured and has 32-bit libraries in its search path. Is that a bug in FFI::CheckLib?
Nope.
The way FFI::CheckLib is implemented it won't work on AIX, HP-UX, OpenVMS or Plan 9.
I know for a fact that it doesn't work on AIX as currently implemented because I used to develop on AIX in the early 2000s, and I am aware of some of the technical challenges. There are probably other systems that it won't work on. I would love to add support for these platforms. Realistically these platforms have a tiny market share, and absent patches from users or the companies that own these operating systems (patches welcome), or hardware / CPU time donations, these platforms are unsupportable anyway.
