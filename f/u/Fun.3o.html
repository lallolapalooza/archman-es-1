val protect : finally:(unit -> unit) -> (unit -> 'a) ->

'a

protect ~finally work invoca work () y luego finally () antes de que work () retorne con su valor o una excepción. En este último caso, la excepción se relanza después de finally () . Si finally () lanza una excepción, entonces se lanza la excepción Fun.Finally_raised en su

lugar.

protect se puede usar para hacer cumplir invariantes locales ya sea que work () retorne normalmente o lance una excepción. Sin embargo, no protege contra excepciones inesperadas lanzadas dentro de finally () como por ejemplo Out_of_memory , Stack_overflow , o excepciones asíncronas lanzadas por manejadores de señales (por ejemplo, Sys.Break )

.

Nota: Es un error de programación si se lanzan otros tipos de excepciones por parte de finally , ya que cualquier excepción lanzada en work () se perderá en el caso de una excepción Fun.Finally_raised . Por lo tanto, uno debe asegurarse de manejarlas dentro del

finally.

exception Finally_raised of ex

n

Finally_raised exn es lanzada por protect ~finally work cuando finally lanza una excepción exn . Esta excepción denota una excepción inesperada o un error de programación. Como regla general, no se debe capturar una excepción Finally_raised excepto como part

e de un mane
jador catch-all.

s

Los combinadores de Fun proporcionan una forma ligera y a veces más legible de crear funciones anónimas, mejor utilizadas como argumentos de corta duración en lugar de definiciones independientes. Los ejemplos siguientes demostrarán esto principalmente con el módulo

Li
st.

[id

]

List.init con el índice en sí

mismo 
  # List.init 3 Fun.id;;
  - : int list = [0; 1; 2]

Usando List.filter_map en una lista de int option para filtrar los elementos Option.t.

None 
  # List.filter_map Fun.id [None; Some 2; Some 3; None; Some 5];;
  - : int list = [2; 3; 5]

Despachar condicionalmente funciones de tipo foo -> foo o tomarlas como argumentos es otro lugar donde id puede ser útil. Considere una función de registro primitiva que imprime una cadena pero da a su usuario la opción de preformatear la cadena antes de imprimirla, por ejemplo, para insertar una marca de

tiempo 
  let log ?(preformat : string -> string = Fun.id) message =
    print_endline (preformat message)

Siempre que podamos construir closures, id se usa a menudo para el caso base como una operación nula. Considere una función que encadena una lista de funciones

unarias: 
  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> fun x -> f (chain fs x)

[const

]

List.init una lista de

ceros 
  # List.init 3 (Fun.const 0);;
  - : int list = [0; 0; 0]

Un predicado que lo permite todo que podría pasarse a cualquier función de filtrado por ejemplo, List.filter para desactivar el filtrado y obtener todos los

valores 
  # List.filter (Fun.const true) [1; 2; 3];;
  - : int list = [1; 2; 3]

Tenga en cuenta que aplicar const (...) evalúa la expresión (...) una vez, y devuelve una función que solo tiene el resultado de esta evaluación. Para demostrar esto, considere si (...) fuera una llamada a Random.bool ()

:

List.init n (Fun.const (Random.bool())) para cualquier n > 0 tendrá exactamente dos resultados

posibles,

- [true; true; ...;

true]

- [false; false; ...;

false]

mientras que List.init n (fun _ -> Random.bool()) tendrá 2^n resultados posibles, porque el efecto aleatorio se realiza con cada

elemento.

Para usos más del mundo real, considere String.spellcheck con una distancia máxima constante de 2, en lugar de la distancia máxima variable

predeterminada 
  let spellcheck known_words word =
    let dict_iter yield = List.iter yield known_words in
    String.spellcheck ~max_dist:(Fun.const 2) dict_iter word

[flip

]

Usando flip para invertir el comparador pasado a List.sort , que ordena en el orden

opuesto 
  # List.sort (Fun.flip Int.compare) [5; 3; 9; 0; 1; 6; 8];;
  - : int list = [9; 8; 6; 5; 3; 1; 0]

Invirtiendo una lista acumulando una nueva lista usando List.fold_left , que espera que el acumulador sea el primer argumento de la función que se le pasa. Pasamos List.cons que tiene la lista como segundo argumento, así que flip es útil

aquí 
  # List.fold_left (Fun.flip List.cons) [] [1; 2; 3];;
  - : int list = [3; 2; 1]

Curiosamente, flip puede funcionar con funciones que no son binarias, invirtiendo los dos primeros argumentos y dejando el resto en orden. Esto se debe a que una función que toma n+2 argumentos es, conceptualmente, una función binaria que devuelve una función que toma n argumentos. Dada una función f : a -> b -> c -> d

:

- flip f tendrá el tipo b -> a -> c ->

d

- fun x -> flip (f x) tendrá el tipo a -> c -> b ->

d

Usar flip con funciones no binarias como esta es desaconsejado,

por su impacto negativo en la
legibilidad y el razonamiento.

[negate

]

Se usa principalmente para invertir un predicado en una función que espera uno, como List.find_all y funciones

similares

Encontrando todas las listas que no están vacías usando List.

is_empty 
  # List.find_all (Fun.negate List.is_empty) [[0]; [1; 2; 3]; []; [4; 5]];;
  - : int list list = [[0]; [1; 2; 3]; [4; 5]]

De una lista dada de rutas, encontrando todas las rutas que no están ocupadas usando Sys.

file_exists 
  # List.find_all (Fun.negate Sys.file_exists);;
  - : string list -> string list = <fun>

[compose

]

List.map en elementos de par con una función sobre el segundo

elemento 
  # List.map (Fun.compose String.length snd) [1, "one"; 2, "two"; 3, "three"];;
  - : int list = [3; 3; 5]

Una implementación potencial de Fun.

negate 
  let negate f = Fun.compose not f

De Fun.hid , compose podría haberse usado en la rama

recursiva 
  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> Fun.compose f (chain fs)
O incluso más concisamente 
  let chain fs = List.fold_right Fun.compose fs Fun.id

Del Fun.hflip , compose y flip podrían usarse para condensar la definición de la función hasta que se convierta

en 
  # Fun.compose
      (String.spellcheck ~max_dist:(Fun.const 2))
      (Fun.flip List.iter)
    ;;
  - : string list -> string -> string list = <fun>

Como se puede ver aquí, esto impacta fuertemente la legibilidad y la capacidad de razonar sobre la función. Tanto String.spellcheck como Fun.flip no son unarios, por lo que existe una interacción no trivial con la aplicación parcial en esta

definición.

El uso intensivo de estos combinadores en OCaml generalmente se de

saconseja, no solo porque pueden impactar rápidamente la legibi
lidad y el razonamiento, sino también porque las funciones pro
ducidas a menudo están en forma de valor, por lo que están sujetas
a la Restricción de Valor (véase la sección 6.1.2 del manual). -01 Cam
