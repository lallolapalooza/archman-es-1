FUTEX_LOCK_PI(2const) FUTEX_LOCK_PI(2const)

NOMBRE

FUTEX_LOCK_PI - bloquear un futex de herencia de prioridad

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/futex.h>  /* Definición de las constantes FUTEX_* */
#include <sys/syscall.h>  /* Definición de las constantes SYS_* */
#include <unistd.h>
long syscall(SYS_futex, uint32_t *uaddr, FUTEX_LOCK_PI, 0,
             const struct timespec *timeout);

DESCRIPCIÓN

Esta operación se utiliza después de que un intento de adquirir el bloqueo mediante una instrucción atómica en modo usuario falló porque la palabra futex tenía un valor distinto de cero — específicamente, porque contenía el TID (específico del espacio de nombres PID) del propietario del bloqueo.

La operación comprueba el valor de la palabra futex en la dirección uaddr. Si el valor es 0, entonces el kernel intenta establecer atmicamente el valor del futex al TID del llamante. Si el valor de la palabra futex es distinto de cero, el kernel establece atmicamente el bit FUTEX_WAITERS, que indica al propietario del futex que no puede desbloquear el futex en el espacio de usuario de forma atómica estableciendo el valor del futex a 0. Después de eso, el kernel:

(1)
Intenta encontrar el hilo asociado con el TID del propietario.
(2)
Crea o reutiliza el estado del kernel en nombre del propietario. (Si este es el primer esperador, no hay estado del kernel para este futex, por lo que se crea el estado del kernel bloqueando el RT-mutex y el propietario del futex se convierte en el propietario del RT-mutex. Si hay esperadores existentes, se reutiliza el estado existente).
(3)
Adjunta el esperador al futex (es decir, el esperador se encola en la lista de esperadores del RT-mutex).

Si existen varios esperadores, la encolación del esperador se realiza en orden descendente de prioridad. (Para obtener información sobre el orden de prioridad, consulte la discusión de las políticas de planificación SCHED_DEADLINE, SCHED_FIFO y SCHED_RR en sched(7).) El propietario hereda ya sea el ancho de banda de CPU del esperador (si el esperador está planificado bajo la política SCHED_DEADLINE) o la prioridad del esperador (si el esperador está planificado bajo la política SCHED_RR o SCHED_FIFO). Esta herencia sigue la cadena de bloqueo en caso de bloqueos anidados y realiza detección de interbloqueos.

El argumento timeout proporciona un tiempo de espera para el intento de bloqueo. Si timeout no es NULL, la estructura a la que apunta especifica un tiempo de espera absoluto. Si timeout es NULL, la operación se bloqueará indefinidamente.

VALOR DE RETORNO

En caso de error, se devuelve -1 y errno se establece para indicar el error.

En caso de éxito, FUTEX_LOCK_PI devuelve 0 si el futex se bloqueó correctamente.

ERRORES

Ver futex(2).

EAGAIN
El ID del hilo propietario del futex en uaddr está a punto de salir, pero aún no ha manejado la limpieza del estado interno. Inténtelo de nuevo.
EDEADLK
La palabra futex en uaddr ya está bloqueada por el llamante.
EFAULT
timeout no apuntaba a una dirección válida del espacio de usuario.
EINVAL
El argumento timeout proporcionado no era válido (tv_sec era menor que cero, o tv_nsec no era menor que 1.000.000.000).
EINVAL
El kernel detectó una inconsistencia entre el estado del espacio de usuario en uaddr y el estado del kernel. Esto indica corrupción de estado o que el kernel encontró un esperador en uaddr que está esperando a través de FUTEX_WAIT(2const) o FUTEX_WAIT_BITSET(2const).
ENOMEM
El kernel no pudo asignar memoria para mantener la información de estado.
ENOSYS
Una comprobación en tiempo de ejecución determinó que la operación no está disponible. Las operaciones PI-futex no están implementadas en todas las arquitecturas y no son compatibles con algunas variantes de CPU.
EPERM
No se permite al llamante adjuntarse al futex en uaddr. (Esto puede ser causado por corrupción de estado en el espacio de usuario).
ESRCH
El ID de hilo en la palabra futex en uaddr no existe.
ETIMEDOUT
El tiempo de espera expiró antes de que se completara la operación.

ESTANDARES

Linux.

HISTORIA

Linux 2.6.18.

PRECAUCIONES

A diferencia de otras operaciones de futex(2), el tiempo de espera se mide contra el reloj CLOCK_REALTIME.
