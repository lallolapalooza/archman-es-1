FS_IOC_SETFLAGS(2const) FS_IOC_SETFLAGS(2const)

NOMBRE

FS_IOC_GETFLAGS, FS_IOC_SETFLAGS - operaciones ioctl() para flags de inodo

SINOPSIS

#include <linux/fs.h>  /* Definición de constantes FS_* */
#include <sys/ioctl.h>
int ioctl(int fd, FS_IOC_GETFLAGS, int *attr);
int ioctl(int fd, FS_IOC_SETFLAGS, const int *attr);

DESCRIPCIÓN

Varios sistemas de archivos de Linux soportan la noción de flags de inodo — atributos que modifican la semántica de archivos y directorios. Estos flags se pueden recuperar y modificar utilizando dos operaciones de ioctl(2):


int attr;
fd = open("ruta/archivo", ...);
ioctl(fd, FS_IOC_GETFLAGS, &attr);  /* Coloca los flags actuales
                                       en 'attr' */
attr |= FS_NOATIME_FL;              /* Modifica la máscara de bits devuelta */
ioctl(fd, FS_IOC_SETFLAGS, &attr);  /* Actualiza los flags para el inodo
                                       referenciado por 'fd' */

Los comandos de shell lsattr(1) y chattr(1) proporcionan interfaces para estas dos operaciones, permitiendo a un usuario ver y modificar los flags de inodo asociados con un archivo.

Los siguientes flags son soportados (mostrados junto con la letra correspondiente utilizada para indicar el flag por lsattr(1) y chattr(1)):

FS_APPEND_FL 'a'
El archivo solo puede abrirse con el flag O_APPEND. Si se aplica a un directorio, prohíbe la eliminación de archivos del directorio (mediante unlink(), rename(), y similares). (Esta restricción se aplica incluso al superusuario.) Solo un proceso privilegiado (CAP_LINUX_IMMUTABLE) puede establecer o borrar este atributo.
FS_COMPR_FL 'c'
Almacena el archivo en formato comprimido en disco. Este flag no es soportado por la mayoría de las implementaciones de sistemas de archivos principales; una excepción es btrfs(5).
FS_DIRSYNC_FL 'D' (desde Linux 2.6.0)
Escribe los cambios del directorio de forma síncrona en disco. Este flag proporciona una semántica equivalente a la opción MS_DIRSYNC de mount(2), pero a nivel de directorio individual. Este flag solo puede aplicarse a directorios.
FS_IMMUTABLE_FL 'i'
El archivo es inmutable: no se permiten cambios en el contenido o metadatos del archivo (permisos, marcas de tiempo, propiedad, recuento de enlaces, etc.). (Esta restricción se aplica incluso al superusuario.) Solo un proceso privilegiado (CAP_LINUX_IMMUTABLE) puede establecer o borrar este atributo.
FS_JOURNAL_DATA_FL 'j'
Habilita el registro de datos de archivos en sistemas de archivos ext3(5) y ext4(5). En un sistema de archivos que está registrando en modo ordered o writeback, un proceso privilegiado (CAP_SYS_RESOURCE) puede establecer este flag para habilitar el registro de actualizaciones de datos por archivo.
FS_NOATIME_FL 'A'
No actualiza la última marca de tiempo de acceso al archivo cuando se accede a él. Esto puede proporcionar beneficios de rendimiento de I/O para aplicaciones que no se preocupan por la precisión de esta marca de tiempo. Este flag proporciona una funcionalidad similar al flag MS_NOATIME de mount(2), pero a nivel de archivo individual.
FS_NOCOW_FL 'C' (desde Linux 2.6.39)
El archivo no estará sujeto a actualizaciones de copia en escritura. Este flag solo tiene efecto en sistemas de archivos que soportan semántica de copia en escritura, como Btrfs. Ver chattr(1) y btrfs(5).
FS_NODUMP_FL 'd'
No incluir este archivo en las copias de seguridad realizadas con dump(8).
FS_NOTAIL_FL 't'
Este flag solo es soportado en Reiserfs. Deshabilita la característica de empaquetado de colas (tail-packing) de Reiserfs, que intenta empaquetar archivos pequeños (y el fragmento final de archivos más grandes) en el mismo bloque de disco que los metadatos del archivo.
FS_PROJINHERIT_FL 'P' (desde Linux 4.5)
Heredar el ID de proyecto de cuota. Los archivos y subdirectorios heredarán el ID de proyecto del directorio. Este flag solo puede aplicarse a directorios.
FS_SECRM_FL 's'
Marca el archivo para borrado seguro. Esta característica no está implementada por ningún sistema de archivos, ya que la tarea de borrar de forma segura un archivo de un medio de grabación es sorprendentemente difícil.
FS_SYNC_FL 'S'
Hace que las actualizaciones del archivo sean síncronas. Para archivos, esto hace que todas las escrituras sean síncronas (como si todas las aperturas del archivo fueran con el flag O_SYNC). Para directorios, esto tiene el mismo efecto que el flag FS_DIRSYNC_FL.
FS_TOPDIR_FL 'T'
Marca un directorio para un tratamiento especial bajo la estrategia de asignación de bloques de Orlov. Ver chattr(1) para más detalles. Este flag solo puede aplicarse a directorios y solo tiene efecto para ext2, ext3 y ext4.
FS_UNRM_FL 'u'
Permite que el archivo sea recuperado si se borra. Esta característica no está implementada por ningún sistema de archivos, ya que es posible implementar mecanismos de recuperación de archivos fuera del kernel.

En la mayoría de los casos, cuando cualquiera de los flags anteriores se establece en un directorio, el flag se hereda por los archivos y subdirectorios creados dentro de ese directorio. Las excepciones incluyen FS_TOPDIR_FL, que no es heredable, y FS_DIRSYNC_FL, que solo se hereda por los subdirectorios.

ESTÁNDARES

Linux.

NOTAS

Para poder cambiar los flags de inodo de un archivo usando la operación FS_IOC_SETFLAGS, el ID de usuario efectivo del llamante debe coincidir con el propietario del archivo, o el llamante debe tener la capacidad CAP_FOWNER.

VER TAMBIÉN

ioctl(2), chattr(1), lsattr(1), mount(2), btrfs(5), ext4(5), xfs(5), xattr(7), mount(8)
