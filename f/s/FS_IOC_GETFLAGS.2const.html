DESCRIPCIÓ

N

Varios sistemas de archivos de Linux admiten la noción de flags de inodo —atributos que modifican la semántica de archivos y directorios. Estos flags pueden obtenerse y modificarse mediante dos operaciones ioctl(2)

: 


int attr;
fd = open("pathname", ...);
ioctl(fd, FS_IOC_GETFLAGS, &attr);  /* Coloca los flags actuales
                                       en 'attr' */
attr |= FS_NOATIME_FL;              /* Ajusta la máscara de bits devuelta */
ioctl(fd, FS_IOC_SETFLAGS, &attr);  /* Actualiza los flags del inodo
                                       al que se refiere 'fd'
*/

Los comandos de shell lsattr(1) y chattr(1) proporcionan interfaces a estas dos operaciones, permitiendo al usuario ver y modificar los flags de inodo asociados a un

archivo.

Se admiten los siguientes flags (mostrados junto con la letra correspondiente usada para indicar el flag por lsattr(1) y chattr(1))

:
FS_APPEND_FL
'a'
El archivo solo puede abrirse con el flag O_APPEND. Si se aplica a un directorio, prohíbe eliminar archivos del directorio (mediante unlink(), rename(), y similares). (Esta restricción se aplica incluso al superusuario.) Solo un proceso privilegiado (CAP_LINUX_IMMUTABLE) puede establecer o borrar este
atributo.
FS_COMPR_FL
'c'
Almacena el archivo en un formato comprimido en disco. Este flag no es admitido por la mayoría de las implementaciones de sistemas de archivos principales; una excepción es btrfs(
5).
FS_DIRSYNC_FL 'D' (desde Linux 2.
6.0)
Escribe los cambios de directorio de forma síncrona en disco. Este flag proporciona semántica equivalente a la opción mount(2) MS_DIRSYNC, pero a nivel de directorio. Este flag solo puede aplicarse a
directorios.
FS_IMMUTABLE_FL
'i'
El archivo es inmutable: no se permiten cambios en el contenido del archivo ni en sus metadatos (permisos, marcas de tiempo, propiedad, número de enlaces, etc.). (Esta restricción se aplica incluso al superusuario.) Solo un proceso privilegiado (CAP_LINUX_IMMUTABLE) puede establecer o borrar este
atributo.
FS_JOURNAL_DATA_FL
'j'
Activa el registro (journaling) de los datos del archivo en los sistemas de archivos ext3(5) y ext4(5). En un sistema de archivos que usa registro en modo ordenado o writeback, un proceso privilegiado (CAP_SYS_RESOURCE) puede establecer este flag para activar el registro de las actualizaciones de datos a nivel de
archivo.
FS_NOATIME_FL
'A'
No actualiza la hora de último acceso del archivo cuando se accede a él. Esto puede proporcionar beneficios de rendimiento de E/S a las aplicaciones que no les importa la precisión de esta marca de tiempo. Este flag proporciona funcionalidad similar al flag mount(2) MS_NOATIME, pero a nivel de
archivo.
FS_NOCOW_FL 'C' (desde Linux 2.6.
39)
El archivo no estará sujeto a actualizaciones copy-on-write. Este flag tiene efecto solo en sistemas de archivos que admiten la semántica copy-on-write, como Btrfs. Véase chattr(1) y btrfs(
5).
FS_NODUMP_FL
'd'
No incluye este archivo en las copias de seguridad realizadas con dump(
8).
FS_NOTAIL_FL
't'
Este flag solo está admitido en Reiserfs. Desactiva la función de empaquetado de colas (tail-packing) de Reiserfs, que intenta empaquetar archivos pequeños (y el fragmento final de archivos más grandes) en el mismo bloque de disco que los metadatos del
archivo.
FS_PROJINHERIT_FL 'P' (desde Linux
4.5)
Hereda el ID de proyecto de cuota. Los archivos y subdirectorios heredarán el ID de proyecto del directorio. Este flag solo puede aplicarse a
directorios.
FS_SECRM_FL
's'
Marca el archivo para borrado seguro. Esta función no está implementada por ningún sistema de archivos, ya que la tarea de borrar de forma segura un archivo de un medio de grabación es sorprendentemente
difícil.
FS_SYNC_FL
'S'
Hace que las actualizaciones del archivo sean síncronas. Para archivos, esto hace que todas las escrituras sean síncronas (como si todas las aperturas del archivo se hicieran con el flag O_SYNC. Para directorios, tiene el mismo efecto que el flag FS_DIRSYNC_F
L.
FS_TOPDIR_FL
'T'
Marca un directorio para un tratamiento especial bajo la estrategia de asignación de bloques Orlov. Véase chattr(1) para más detalles. Este flag solo puede aplicarse a directorios y tiene efecto solo para ext2, ext3 y
ext4.
FS_UNRM_FL
'u'
Permite que el archivo se pueda deshacer (undelete) si se elimina. Esta funci
ón no está implementada por ningún sistema de archivos, ya que es posib
le implementar mecanismos de recuperación de archivos fuera del núcleo.

En la mayoría de los casos, cuando cualquiera de los flags anteriores se establece en un directorio, el flag es heredado por los archivos y subdirectorios creados dentro de ese directorio. Las excepciones incluyen FS_TOPDIR_FL, que no es heredable, y FS_DIRSYNC_FL, que solo es h

eredado por s
ubdirectorios.
