ioctl_fsmap(2) Manual de Llamadas al Sistema ioctl_fsmap(2)

NOMBRE

ioctl_fsmap, FS_IOC_GETFSMAP - recupera la disposición física del sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <linux/fsmap.h>  /* Definición de FS_IOC_GETFSMAP,
                             FM?_OF_*y *FMR_OWN_* constantes */
#include <sys/ioctl.h>
int ioctl(int fd, FS_IOC_GETFSMAP, struct fsmap_head * arg);

DESCRIPCIÓN

Esta ioctl(2) operación recupera las asignaciones de extensiones físicas de un sistema de archivos. Esta información se puede utilizar para descubrir qué archivos están asignados a un bloque físico, examinar el espacio libre o encontrar bloques defectuosos conocidos, entre otras cosas.

El único argumento de esta operación debe ser un puntero a un único struct fsmap_head:


struct fsmap {
    __u32 fmr_device;      /* ID del dispositivo */
    __u32 fmr_flags;       /* Banderas de asignación */
    __u64 fmr_physical;    /* Desplazamiento del dispositivo del segmento */
    __u64 fmr_owner;       /* ID del propietario */
    __u64 fmr_offset;      /* Desplazamiento del archivo del segmento */
    __u64 fmr_length;      /* Longitud del segmento */
    __u64 fmr_reserved[3]; /* Debe ser cero */
};
struct fsmap_head {
    __u32 fmh_iflags;       /* Banderas de control */
    __u32 fmh_oflags;       /* Banderas de salida */
    __u32 fmh_count;        /* Número de entradas en el array incluyendo la de entrada */
    __u32 fmh_entries;      /* Número de entradas rellenadas (salida) */
    __u64 fmh_reserved[6];  /* Debe ser cero */
    struct fsmap fmh_keys[2];  /* Claves baja y alta para
                                  la búsqueda de asignaciones */
    struct fsmap fmh_recs[];   /* Registros devueltos */
};

Los dos fmh_keys elementos del array especifican la clave de mapeo inverso más baja y más alta para la cual la aplicación desea información de asignación física. Una clave de mapeo inverso consiste en la tupla (dispositivo, bloque, propietario, desplazamiento). Los campos de propietario y desplazamiento forman parte de la clave porque algunos sistemas de archivos admiten el uso compartido de bloques físicos entre múltiples archivos y por lo tanto pueden devolver múltiples asignaciones para un bloque físico dado.

Las asignaciones del sistema de archivos se copian en el fmh_recs array, que sigue inmediatamente a los datos de la cabecera.

Campos de struct fsmap_head

El fmh_iflags campo es una máscara de bits pasada al kernel para alterar la salida. Actualmente no se han definido banderas, por lo que el llamador debe establecer este valor en cero.

El fmh_oflags campo es una máscara de bits de banderas establecidas por el kernel concernientes a las asignaciones devueltas. Si FMH_OF_DEV_T está establecido, entonces el fmr_device campo representa una dev_t estructura que contiene los números mayor y menor del dispositivo de bloque.

El fmh_count campo contiene el número de elementos en el array que se pasa al kernel. Si este valor es 0, fmh_entries se establecerá en el número de registros que se habrían devuelto si el array hubiera sido lo suficientemente grande; no se devolverá información de asignación.

El fmh_entries campo contiene el número de elementos en el fmh_recs array que contienen información útil.

Los fmh_reserved campos deben establecerse en cero.

Claves

Los dos registros de clave en fsmap_head.fmh_keys especifican los registros de extensión más bajos y más altos en el espacio de claves que el llamador quiere que se devuelvan. Un sistema de archivos que pueda compartir bloques entre archivos probablemente requiere la tupla (dispositivo, físico, propietario, desplazamiento, banderas) para indexar de forma única cualquier registro de asignación del sistema de archivos. Los sistemas de archivos clásicos no compartidos podrían identificar cualquier registro con solo (dispositivo, físico, banderas). Por ejemplo, si la clave baja está establecida en (8:0, 36864, 0, 0, 0), el sistema de archivos solo devolverá registros para extensiones que comiencen en o por encima de 36 KiB en disco. Si la clave alta está establecida en (8:0, 1048576, 0, 0, 0), solo se devolverán registros por debajo de 1 MiB. El formato de fmr_device en las claves debe coincidir con el formato del mismo campo en los registros de salida, como se define a continuación. Por convención, el campo fsmap_head.fmh_keys[0] debe contener la clave baja y fsmap_head.fmh_keys[1] debe contener la clave alta para la operación.

Por conveniencia, si fmr_length está establecido en la clave baja, se añadirá a fmr_block o fmr_offset según corresponda. El llamador puede aprovechar esta sutileza para configurar llamadas subsecuentes copiando fsmap_head.fmh_recs[fsmap_head.fmh_entries - 1] en la clave baja. La función fsmap_advance (definida en linux/fsmap.h) proporciona esta funcionalidad.

Campos de struct fsmap

El fmr_device campo identifica de forma única el dispositivo de almacenamiento subyacente. Si la bandera FMH_OF_DEV_T está establecida en el campo fmh_oflags de la cabecera, este campo contiene un dev_t del cual se pueden extraer los números mayor y menor. Si la bandera no está establecida, este campo contiene un valor que debe ser único para cada dispositivo de almacenamiento único.

El fmr_physical campo contiene la dirección en disco de la extensión en bytes.

El fmr_owner campo contiene el propietario de la extensión. Este es un número de inodo a menos que FMR_OF_SPECIAL_OWNER esté establecido en el fmr_flags campo, en cuyo caso el valor lo determina el sistema de archivos. Consulte la sección a continuación sobre valores de propietario para más detalles.

El fmr_offset campo contiene la dirección lógica en el registro de asignación en bytes. Este campo no tiene significado si las banderas FMR_OF_SPECIAL_OWNER o FMR_OF_EXTENT_MAP están establecidas en fmr_flags.

El fmr_length campo contiene la longitud de la extensión en bytes.

El fmr_flags campo es una máscara de bits de banderas de estado de la extensión. Los bits son:

FMR_OF_PREALLOC
La extensión está asignada pero aún no ha sido escrita.
FMR_OF_ATTR_FORK
Esta extensión contiene datos de atributos extendidos.
FMR_OF_EXTENT_MAP
Esta extensión contiene información de mapa de extensiones para el propietario.
FMR_OF_SHARED
Partes de esta extensión pueden ser compartidas.
FMR_OF_SPECIAL_OWNER
El fmr_owner campo contiene un valor especial en lugar de un número de inodo.
FMR_OF_LAST
Este es el último registro en el conjunto de datos.

El fmr_reserved campo se establecerá en cero.

Valores de propietario

Generalmente, el valor del fmr_owner campo para extensiones que no son de metadatos debería ser un número de inodo. Sin embargo, los sistemas de archivos no tienen ninguna obligación de informar números de inodo; pueden informar FMR_OWN_UNKNOWN si el número de inodo no se puede recuperar fácilmente, si el llamador carece de suficientes privilegios, si el sistema de archivos no admite números de inodo estables, o por cualquier otra razón. Si un sistema de archivos desea condicionar la información de números de inodo en función de las capacidades del proceso, se recomienda encarecidamente que se utilice la capacidad CAP_SYS_ADMIN para este propósito.

Los siguientes valores especiales de propietario son genéricos para todos los sistemas de archivos:
FMR_OWN_FREE
Espacio libre.
FMR_OWN_UNKNOWN
Esta extensión está en uso pero su propietario no se conoce o no se puede recuperar fácilmente.
FMR_OWN_METADATA
Esta extensión es metadatos del sistema de archivos.

XFS puede devolver los siguientes valores especiales de propietario:

XFS_FMR_OWN_FREE
Espacio libre.
XFS_FMR_OWN_UNKNOWN
Esta extensión está en uso, pero su propietario no se conoce o no se puede recuperar fácilmente.
XFS_FMR_OWN_FS
Metadatos estáticos del sistema de archivos que existen en una dirección fija. Estos son el superbloque del AG, el AGF, el AGFL y las cabeceras del AGI.
XFS_FMR_OWN_LOG
El diario del sistema de archivos.
XFS_FMR_OWN_AG
Metadatos del grupo de asignación, como los árboles b de espacio libre y los árboles b de mapeo inverso.
XFS_FMR_OWN_INOBT
Los árboles b de inodos y de inodos libres.
XFS_FMR_OWN_INODES
Registros de inodos.
XFS_FMR_OWN_REFC
Información de conteo de referencias.
XFS_FMR_OWN_COW
Esta extensión se está utilizando para preparar una copia en escritura (copy-on-write).
XFS_FMR_OWN_DEFECTIVE:
Esta extensión ha sido marcada como defectuosa ya sea por el sistema de archivos o por el dispositivo subyacente.

ext4 puede devolver los siguientes valores especiales de propietario:

EXT4_FMR_OWN_FREE
Espacio libre.
EXT4_FMR_OWN_UNKNOWN
Esta extensión está en uso, pero su propietario no se conoce o no se puede recuperar fácilmente.
EXT4_FMR_OWN_FS
Metadatos estáticos del sistema de archivos que existen en una dirección fija. Este es el superbloque y los descriptores de grupo.
EXT4_FMR_OWN_LOG
El diario del sistema de archivos.
EXT4_FMR_OWN_INODES
Registros de inodos.
EXT4_FMR_OWN_BLKBM
Mapa de bits de bloques.
EXT4_FMR_OWN_INOBM
Mapa de bits de inodos.

VALOR DEVUELTO

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

El error colocado en errno puede ser uno de los siguientes, aunque no se limita a ellos:

EBADF
fd no está abierto para lectura.
EBADMSG
El sistema de archivos ha detectado un error de suma de comprobación en los metadatos.
EFAULT
El puntero pasado no estaba mapeado a una dirección de memoria válida.
EINVAL
El array no es lo suficientemente largo, las claves no apuntan a una parte válida del sistema de archivos, la clave baja apunta a un punto más alto en el espacio de direcciones de almacenamiento físico del sistema de archivos que la clave alta, o se pasó un valor distinto de cero en uno de los campos que deben ser cero.
ENOMEM
Memoria insuficiente para procesar la operación.
EOPNOTSUPP
El sistema de archivos no admite esta operación.
EUCLEAN
Los metadatos del sistema de archivos están corruptos y necesitan ser reparados.

ESTÁNDARES

Linux.

No todos los sistemas de archivos la admiten.

HISTORIA

Linux 4.12.

EJEMPLOS

Véase io/fsmap.c en la distribución de xfsprogs para un programa de ejemplo.
