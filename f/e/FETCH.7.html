NOMBRE

FETCH - recuperar filas de una consulta usando un cursor

SINOPSIS

FETCH [ dirección ] [ FROM | IN ] nombre_cursor
donde dirección puede ser una de las siguientes:
    NEXT
    PRIOR
    FIRST
    LAST
    ABSOLUTE contador
    RELATIVE contador
    contador
    ALL
    FORWARD
    FORWARD contador
    FORWARD ALL
    BACKWARD
    BACKWARD contador
    BACKWARD ALL

DESCRIPCIÓN

FETCH recupera filas usando un cursor previamente creado.

Un cursor tiene una posición asociada, que es utilizada por FETCH. La posición del cursor puede estar antes de la primera fila del resultado de la consulta, en cualquier fila particular del resultado, o después de la última fila del resultado. Cuando se crea, un cursor se posiciona antes de la primera fila. Después de recuperar algunas filas, el cursor se posiciona en la fila recuperada más recientemente. Si FETCH se queda sin las filas disponibles, el cursor quedará posicionado después de la última fila, o antes de la primera fila si se recupera hacia atrás. FETCH ALL o FETCH BACKWARD ALL siempre dejarán el cursor posicionado después de la última fila o antes de la primera fila.

Las formas NEXT, PRIOR, FIRST, LAST, ABSOLUTE, RELATIVE recuperan una sola fila después de mover el cursor apropiadamente. Si no existe tal fila, se devuelve un resultado vacío y el cursor queda posicionado antes de la primera fila o después de la última fila según corresponda.

Las formas que usan FORWARD y BACKWARD recuperan el número indicado de filas moviéndose en la dirección hacia adelante o hacia atrás, dejando el cursor posicionado en la última fila devuelta (o después/antes de todas las filas, si el contador excede el número de filas disponibles).

RELATIVE 0, FORWARD 0, y BACKWARD 0 solicitan recuperar la fila actual sin mover el cursor, es decir, volver a recuperar la fila recuperada más recientemente. Esto tendrá éxito a menos que el cursor esté posicionado antes de la primera fila o después de la última fila; en cuyo caso, no se devuelve ninguna fila.


Nota

Esta página describe el uso de cursores a nivel de comando SQL. Si está intentando usar cursores dentro de una función PL/pgSQL, las reglas son diferentes — consulte la Sección 41.7.3.

PARÁMETROS

dirección

dirección define la dirección de recuperación y el número de filas a recuperar. Puede ser una de las siguientes:

NEXT

Recupera la siguiente fila. Este es el valor por defecto si se omite dirección.

PRIOR

Recupera la fila anterior.

FIRST

Recupera la primera fila de la consulta (igual que ABSOLUTE 1).

LAST

Recupera la última fila de la consulta (igual que ABSOLUTE -1).

ABSOLUTE contador

Recupera la fila contador de la consulta, o la fila abs(contador) desde el final si contador es negativo. Se posiciona antes de la primera fila o después de la última fila si contador está fuera de rango; en particular, ABSOLUTE 0 se posiciona antes de la primera fila.

RELATIVE contador

Recupera la fila contador siguiente, o la fila abs(contador) anterior si contador es negativo. RELATIVE 0 vuelve a recuperar la fila actual, si la hay.

contador

Recupera las siguientes contador filas (igual que FORWARD contador).

ALL

Recupera todas las filas restantes (igual que FORWARD ALL).

FORWARD

Recupera la siguiente fila (igual que NEXT).

FORWARD contador

Recupera las siguientes contador filas. FORWARD 0 vuelve a recuperar la fila actual.

FORWARD ALL

Recupera todas las filas restantes.

BACKWARD

Recupera la fila anterior (igual que PRIOR).

BACKWARD contador

Recupera las contador filas anteriores (escaneando hacia atrás). BACKWARD 0 vuelve a recuperar la fila actual.

BACKWARD ALL

Recupera todas las filas anteriores (escaneando hacia atrás).

contador

contador es una constante entera, posiblemente con signo, que determina la ubicación o el número de filas a recuperar. Para los casos FORWARD y BACKWARD, especificar un contador negativo equivale a cambiar el sentido de FORWARD y BACKWARD.

nombre_cursor

El nombre de un cursor abierto.

SALIDA

Al completarse con éxito, un comando FETCH devuelve una etiqueta de comando de la forma

FETCH contador

El contador es el número de filas recuperadas (posiblemente cero). Tenga en cuenta que en psql, la etiqueta del comando no se mostrará realmente, ya que psql muestra las filas recuperadas en su lugar.

NOTAS

El cursor debe declararse con la opción SCROLL si se pretende usar alguna variante de FETCH distinta de FETCH NEXT o FETCH FORWARD con un contador positivo. Para consultas simples, PostgreSQL permitirá la recuperación hacia atrás desde cursores no declarados con SCROLL, pero es mejor no depender de este comportamiento. Si el cursor se declara con NO SCROLL, no se permiten recuperaciones hacia atrás.

Las recuperaciones ABSOLUTE no son más rápidas que navegar hasta la fila deseada con un movimiento relativo: la implementación subyacente debe recorrer todas las filas intermedias de todos modos. Las recuperaciones absolutas negativas son aún peores: la consulta debe leerse hasta el final para encontrar la última fila, y luego recorrerla hacia atrás desde allí. Sin embargo, retroceder al inicio de la consulta (como con FETCH ABSOLUTE 0) es rápido.

DECLARE se usa para definir un cursor. Use MOVE para cambiar la posición del cursor sin recuperar datos.

EJEMPLOS

El siguiente ejemplo recorre una tabla usando un cursor:

BEGIN WORK;
-- Configurar un cursor:
DECLARE liahona SCROLL CURSOR FOR SELECT * FROM films;
-- Recuperar las primeras 5 filas del cursor liahona:
FETCH FORWARD 5 FROM liahona;
 code  |          title          | did | date_prod  |   kind   |  len
-------+-------------------------+-----+------------+----------+-------
 BL101 | The Third Man           | 101 | 1949-12-23 | Drama    | 01:44
 BL102 | The African Queen       | 101 | 1951-08-11 | Romantic | 01:43
 JL201 | Une Femme est une Femme | 102 | 1961-03-12 | Romantic | 01:25
 P_301 | Vertigo                 | 103 | 1958-11-14 | Action   | 02:08
 P_302 | Becket                  | 103 | 1964-02-03 | Drama    | 02:28
-- Recuperar la fila anterior:
FETCH PRIOR FROM liahona;
 code  |  title  | did | date_prod  |  kind  |  len
-------+---------+-----+------------+--------+-------
 P_301 | Vertigo | 103 | 1958-11-14 | Action | 02:08
-- Cerrar el cursor y finalizar la transacción:
CLOSE liahona;
COMMIT WORK;

COMPATIBILIDAD

El estándar SQL define FETCH para su uso solo en SQL embebido. La variante de FETCH descrita aquí devuelve los datos como si fueran un resultado de SELECT en lugar de colocarlos en variables del host. Aparte de este punto, FETCH es totalmente compatible con versiones anteriores del estándar SQL.

Las formas de FETCH que involucran FORWARD y BACKWARD, así como las formas FETCH contador y FETCH ALL, en las que FORWARD es implícito, son extensiones de PostgreSQL.

El estándar SQL solo permite FROM precediendo al nombre del cursor; la opción de usar IN, o de omitirlos por completo, es una extensión.
