El modo de presentación de diapositivas es el predeterminado. Abre una ventana y muestra la primera imagen en ella; la posición de la presentación puede avanzarse (o cambiarse de otra manera) usando atajos de teclado y ratón. En el modo de presentación, las imágenes pueden eliminarse tanto de la lista de archivos como del disco, y una lista de archivos modificada también puede guardarse en el disco y reabrirse más tarde. Una imagen también puede leerse desde stdin mediante "feh -". El modo de montaje forma un montaje a partir de la lista de archivos. La imagen resultante puede verse o guardarse, y su tamaño puede limitarse por altura, ancho o ambos. El modo de índice forma una hoja de contactos a partir de la lista de archivos. Se muestran miniaturas de las imágenes junto con el nombre de archivo, el tamaño y las dimensiones, impresas usando una fuente truetype a elección. La imagen resultante puede verse o guardarse, y su tamaño puede limitarse por altura, ancho o ambos. El modo de miniaturas es como el modo de índice, pero las miniaturas son clicables y abren la imagen seleccionada en una nueva

ventana.

El modo de múltiples ventanas muestra imágenes en múltiples ventanas, en lugar de como una presentación en una sola ventana. No lo uses con una lista de archivos grande ;) El modo de lista no muestra imágenes. En su lugar, genera un listado al estilo de ls - de los archivos en la lista de archivos, incluyendo información de la imagen como tamaño, número de píxeles, tipo, etc. También existe un modo Lista personalizada que imprime información de la imagen en un formato personalizado especificado por una cadena de formato similar a printf. feh también puede listar todos los archivos cargables de una lista de archivos

o todos los archivos no cargables. Esto
es útil para limpiar un directorio.

-S, --sort tipo_de_orden
Ordenar la lista de archivos según los parámetros de la imagen. Los tipos de orden permitidos son: name, none, filename, dirname, mtime, width, height, pixels, size, format. Para modos de orden distintos de name, none, filename, dirname, o mtime, es necesaria una ejecución de precarga, causando un retraso proporcional al número de imágenes en la lista.

mtime comienza con la imagen modificada más recientemente. width, height, pixels y size comienzan con la más pequeña. Usa --reverse para ordenar por la más antigua o la más grande primero.

Para name, filenamey dirname puedes usar --version-sort para ordenar números de forma natural, de modo que, por ejemplo, 10.jpg venga después de 2.jpg.

none es el defecto; puedes especificarlo explícitamente para descartar un modo de orden que se haya especificado en un punto anterior de los argumentos de la línea de comandos.

BACKGROUND SETTING

In many desktop environments, feh can also be used as a background setter. Unless you pass the --no-fehbg option, it will write a script to set the current background to ~/.fehbg. So to have your background restored every time you start X, you can add "~/.fehbg &" to your X startup script (such as ~/.xinitrc). Note that the commandline written to ~/.fehbg always includes the --no-fehbg option to ensure that it is not inadvertently changed by differences in X11 screen layout or similar.

Note that feh does not support setting the wallpaper of GNOME shell desktops. In this environment, you can use "gsettings set org.gnome.desktop.background picture-uri file:///path" instead.

For --bg-center, --bg-fill, and --bg-max, you can use --geometry to specify an offset from one side of the monitor instead of centering the image. Positive values will offset from the left/top side, negative values from the bottom/right. +0 and -0 are both valid and distinct values.

Note that all options except --bg-tile support Xinerama. For instance, if you have multiple monitors connected and use e.g. --bg-center, feh will center or appropriately offset the image on each monitor. You may even specify more than one file, in that case, the first file is set on monitor 0, the second on monitor 1, and so on. Use xrandr --listmonitors to determine how Xinerama monitor IDs map to screens / monitors in your setup.

Use --no-xinerama to treat the whole X display as one monitor when setting wallpapers. You may also use --xinerama-index to use feh as a background setter for a specific monitor.

CONFIGURATION

feh has three config files: themes for theme definitions, keys for key bindings and buttons for mouse button bindings. It will try to read them from $XDG_CONFIG_HOME/feh/, which (when XDG_CONFIG_HOME is unset) defaults to ~/.config/feh/. If the files are not found in that directory, it will also try /etc/feh/.

All config files treat lines starting with a "#" character as comments. Comments at the end of a line are not supported.

THEMES CONFIG SYNTAX

.config/feh/themes allows the naming of option groups, called themes.

It takes entries of the form "theme options ...", where theme is the name of the entry and options are the options which will be applied when the theme is used.

Note that the option parser does not behave like a normal shell: filename expansion and backslash escape sequences are not supported and passed to feh's option parser as-is. However, quoting of arguments is respected and can be used for arguments with whitespace. So, the sequence "--info "foo bar"" works as intended (that is, it display the string "foo bar"), whereas the option string "--info foo\ bar" will only display "foo\" and complain about the file bar not existing. Please keep this in mind when writing theme files.

An example entry is "imagemap -rVq --thumb-width 40 --thumb-height 30 --index-info '%n\n%wx%h'".

You can use this theme in two ways. Either call "feh -Timagemap *.jpg", or create a symbolic link to feh with the name of the theme you want it to use. For the example above, this would be "ln -s `which feh ` ~/bin/imagemap". Now just run "imagemap *.jpg" to use these options.

Note that you can split a theme over several lines by placing a backslash at the end of an unfinished line. A single option-argument-pair must not span multiple lines. A single line must not be longer than 1023 characters, but there's no upper limit for the length of a theme.

Command line options always override theme options.

KEYS CONFIG SYNTAX

.config/feh/keys defines key bindings. It has entries of the form "action [key1 [key2 [key3]]]".

Each key is an X11 keysym name as shown by xev(1), like "Delete". It may optionally start with modifiers for things like Control, in which case key looks like mod-keysym (for example "C-Delete" for Ctrl+Delete or "C-1-Delete" for Ctrl+Alt+Delete)

Available modifiers are C for Control, S for Shift and 1, 4 for Mod1 and Mod4. To match an uppercase letter like "S" instead of "s", the Shift modifier is not required.

Specifying an action without any keys unbinds it (i.e. the default bindings are removed).

Note: Do not use the same keybinding for multiple actions. When binding an action to a new key (or mouse button), make sure to unbind it from its previous action, if present. feh does not check for conflicting bindings, so their behaviour is undefined.

For a list of the action names, see KEYS. Note that not all of the key names used there correspond to X11 keysyms. Most notably, page up (Prior / Page_Up), page down (Next / Page_Down) and the keypad keys (KP_*) do not.

Igual que arriba, pero habilitar el almacenamiento en caché de miniaturas y usar una fuente más pequeña.
feh -irFarial/14 -O index.jpg ~/Pictures
Hacer una impresión de índice de ~/Pictures y todos los directorios debajo de él, usando 14 puntos Arial para escribir la información de la imagen debajo de cada miniatura. Guardar la imagen como index.jpg y no mostrarla, solo salir. Tenga en cuenta que esto incluso funciona sin un servidor X en ejecución
feh --unloadable -r ~/Pictures
Imprimir todas las imágenes no cargables en ~/Pictures, recursivamente
feh -f by_width -S width --reverse --list .
Escribir una lista de todas las imágenes en el directorio a by_width, ordenadas por ancho (imágenes más anchas primero)
feh -w ~/Pictures/holidays
Abrir cada imagen en ~/Pictures/holidays en su propia ventana
feh -FD5 -Sname ~/Pictures/presentation
Mostrar las imágenes en .../presentation, ordenadas por nombre, en pantalla completa, cambiar automáticamente a la siguiente imagen después de 5 segundos
feh -rSwidth -A "mv %F ~/images/%N" ~/Pictures
Ver todas las imágenes en ~/Pictures y debajo, ordenadas por ancho, mover una imagen a ~/image/image_name cuando se presiona enter
feh --start-at ~/Pictures/foo.jpg
Ver todas las imágenes en ~/Pictures, empezando por foo.jpg. Todas las demás imágenes están aún en la presentación y pueden verse normalmente
feh --start-at ~/Pictures/foo.jpg ~/Pictures
Igual que arriba.
feh --info "exifgrep '(Model|DateTimeOriginal|FNumber|ISO|Flash)' %F | cut -d . -f 4-" .
Mostrar alguna información EXIF, extraída por exifprobe/exifgrep
feh --action 'rm %F' -rl --max-dimension 1000x800
Eliminar recursivamente todas las imágenes con dimensiones menores o iguales a 1000x800 píxeles del directorio actual.
feh -L '%w %h %f' | awk '{ if ($1 > $2) { print $0 } }' | cut -d ' ' -f 3- | feh -f -
Mostrar imágenes apaisadas (ancho de la imagen mayor que la altura) en el directorio actual.

DEPENDENCIAS

Cuando --edit se usa, feh necesita los jpegtran y jpegexiforient binarios (usualmente distribuidos en "libjpeg-progs" o similar) para la rotación JPEG sin pérdida.

Para ver imágenes de URLs como "http://", feh debe compilarse con soporte libcurl. Está habilitado en esta compilación.

ERRORES CONOCIDOS

Las versiones de Imlib2 anteriores a la 1.7.4 no pueden cargar imágenes gif, tiff y webp si el nombre del archivo no termina con gif, tiff o webp, respectivamente. Notablemente, esto significa que feh no puede mostrar imágenes gif, tiff y webp desde stdin o URLs de red en sistemas que usan una versión de Imlib2 anterior a la 1.7.4.

Las versiones de Imlib2 1.7.5+ rotan automáticamente las imágenes basándose en sus etiquetas EXIF. Cuando se combina con la --auto-rotate opción, esto causa que las imágenes se roten dos veces y terminen en una orientación incorrecta. Como solución, no use --auto-rotate en sistemas con versión de Imlib2 1.7.5 o posterior.

En sistemas con giflib 5.1.2, feh puede ser incapaz de cargar imágenes gif. Para dispositivos afectados mips, mipsel y arm, el soporte de gif está completamente roto, mientras que en x86 / x86_64 los gifs generalmente solo pueden cargarse si son la primera imagen en la lista de archivos. Esto parece ser un error en giflib, véase ⟨https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=813729⟩ para detalles. Solución: Use --conversion-timeout 5 (u algún otro valor positivo) para cargar gifs con imagemagick, o retroceda a giflib 5.1.1, o actualice a giflib 5.1.4.

Mientras carga imágenes usando libcurl, feh no reaccionará a acciones de teclado o ratón.

El modo miniatura es algo ineficiente, y por eso no es casi tan rápido como podría ser.

--scale-down no tiene en cuenta los decorados de la ventana y por lo tanto puede hacer la ventana ligeramente demasiado grande.
