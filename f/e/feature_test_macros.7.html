_XOPEN_SOURCE_EXTENDED
Si esta macro se define, y _XOPEN_SOURCE se define, entonces se exponen definiciones correspondientes a las extensiones UNIX de XPG4v2 (SUSv1) (UNIX 95). Definir _XOPEN_SOURCE con un valor de 500 o más también produce el mismo efecto que definir _XOPEN_SOURCE_EXTENDED. Se debe evitar el uso de _XOPEN_SOURCE_EXTENDED en código fuente nuevo.
Dado que definir _XOPEN_SOURCE con un valor de 500 o más tiene el mismo efecto que definir _XOPEN_SOURCE_EXTENDED, esta última (obsoleta) macro de prueba de características generalmente no se describe en el SYNOPSIS de las páginas man.
_ISOC99_SOURCE (desde glibc 2.1.3)
Expone declaraciones consistentes con el estándar ISO C99.
Versiones anteriores de glibc 2.1.x reconocieron una macro equivalente llamada _ISOC9X_SOURCE (ya que el estándar C99 no se había finalizado todavía). Aunque el uso de esta macro es obsoleto, glibc continúa reconociéndola por compatibilidad con versiones anteriores.
Definir _ISOC99_SOURCE también expone definiciones de la Enmienda 1 de ISO C (1990) ("C95"). (El principal cambio en C95 fue el soporte para conjuntos de caracteres internacionales).
Invocar el compilador C con la opción -std=c99 produce los mismos efectos que definir esta macro.
_ISOC11_SOURCE (desde glibc 2.16)
Expone declaraciones consistentes con el estándar ISO C11. Definir esta macro también habilita características C99 y C95 (como _ISOC99_SOURCE).
Invocar el compilador C con la opción -std=c11 produce los mismos efectos que definir esta macro.
_LARGEFILE64_SOURCE
Expone definiciones para la API alternativa especificada por LFS (Large File Summit) como una "extensión transicional" a la Single UNIX Specification. (Véase http://opengroup.org/platform/lfs.html.) La API alternativa consiste en un conjunto de nuevos objetos (es decir, funciones y tipos) cuyos nombres se sufijan con "64" (por ejemplo, off64_t versus off_t, lseek64() versus lseek(), etc.). Los programas nuevos no deben emplear esta macro; en su lugar se debe emplear _FILE_OFFSET_BITS=64.
_LARGEFILE_SOURCE
Históricamente, esta macro se usaba para exponer ciertas funciones (específicamente fseeko(3) y ftello(3)) que abordan las limitaciones de las APIs anteriores (fseek(3) y ftell(3)) que usan long para los desplazamientos de archivo. Esta macro se define implícitamente si _XOPEN_SOURCE se define con un valor mayor o igual a 500. Los programas nuevos no deben emplear esta macro; definir _XOPEN_SOURCE como se describe justo arriba o definir _FILE_OFFSET_BITS con el valor 64 es el mecanismo preferido para lograr el mismo resultado.
_FILE_OFFSET_BITS
Definir esta macro con el valor 64 convierte automáticamente las referencias a funciones y tipos de datos de 32 bits relacionados con E/S de archivos y operaciones de sistema de archivos en referencias a sus contrapartes de 64 bits. Esto es útil para realizar E/S en archivos grandes (> 2 Gigabytes) en sistemas de 32 bits. También es útil al llamar a funciones como copy_file_range(2) que se añadieron más recientemente y que solo existen en versiones de 64 bits. (Definir esta macro permite que los programas escritos correctamente utilicen archivos grandes con solo una recompilación).
Los sistemas de 64 bits permiten de forma natural tamaños de archivo mayores a 2 Gigabytes, y en esos sistemas esta macro no tiene ningún efecto.
_TIME_BITS
Definir esta macro con el valor 64 cambia el ancho de time_t(3type) a 64 bits, lo que permite manejar marcas de tiempo posteriores a 2038. Está estrechamente relacionada con _FILE_OFFSET_BITS y, dependiendo de la implementación, puede requerir que esta esté establecida. Esta macro está disponible a partir de glibc 2.34.
_BSD_SOURCE (obsoleto desde glibc 2.20)
Definir esta macro con cualquier valor hace que los archivos de cabecera expongan definiciones derivadas de BSD.
En las versiones de glibc hasta la 2.18 inclusive, definir esta macro también hace que las definiciones BSD tengan preferencia en algunas situaciones donde los estándares entran en conflicto, a menos que se defina una o más de las siguientes macros: _SVID_SOURCE, _POSIX_SOURCE, _POSIX_C_SOURCE, _XOPEN_SOURCE, _XOPEN_SOURCE_EXTENDED, o _GNU_SOURCE, en cuyo caso las definiciones BSD se desfavorecen. Desde glibc 2.19, _BSD_SOURCE ya no hace que las definiciones BSD tengan preferencia en caso de conflictos.
Desde glibc 2.20, esta macro está obsoleta. Ahora tiene el mismo efecto que definir _DEFAULT_SOURCE, pero genera una advertencia en tiempo de compilación (a menos que _DEFAULT_SOURCE también se defina). Utilice _DEFAULT_SOURCE en su lugar. Para permitir que el código que requiere _BSD_SOURCE en glibc 2.19 y anteriores y _DEFAULT_SOURCE en glibc 2.20 y posteriores se compile sin advertencias, defina ambas macros: _BSD_SOURCE y _DEFAULT_SOURCE.
_SVID_SOURCE (obsoleto desde glibc 2.20)
Definir esta macro con cualquier valor hace que los archivos de cabecera expongan definiciones derivadas de System V. (SVID == System V Interface Definition; véase standards(7).)
Desde glibc 2.20, esta macro está obsoleta de la misma manera que _BSD_SOURCE.
_DEFAULT_SOURCE (desde glibc 2.19)
Esta macro puede definirse para garantizar que se proporcionen las definiciones "predeterminadas" incluso cuando las predeterminadas se deshabilitarían de otra manera, como ocurre cuando se definen macros individuales explícitamente, o cuando el compilador se invoca en uno de sus modos "estándar" (por ejemplo, cc -std=c99). Definir _DEFAULT_SOURCE sin definir otras macros individuales o invocar el compilador en uno de sus modos "estándar" no tiene ningún efecto.
Las definiciones "predeterminadas" comprenden aquellas requeridas por POSIX.1-2008 e ISO C99, así como varias definiciones originalmente derivadas de BSD y System V. En glibc 2.19 y anteriores, estos valores predeterminados eran aproximadamente equivalentes a definir explícitamente lo siguiente:

cc -D_BSD_SOURCE -D_SVID_SOURCE -D_POSIX_C_SOURCE=200809

_ATFILE_SOURCE (desde glibc 2.4)
Definir esta macro con cualquier valor hace que los archivos de cabecera expongan declaraciones de un rango de funciones con el sufijo "at"; véase openat(2). Desde glibc 2.10, esta macro también se define implícitamente si _POSIX_C_SOURCE se define con un valor mayor o igual a 200809L.
_GNU_SOURCE
Definir esta macro (con cualquier valor) define implícitamente _ATFILE_SOURCE, _LARGEFILE64_SOURCE, _ISOC99_SOURCE, _XOPEN_SOURCE_EXTENDED, _POSIX_SOURCE, _POSIX_C_SOURCE con el valor 200809L (200112L antes de glibc 2.10; 199506L antes de glibc 2.5; 199309L antes de glibc 2.1) y _XOPEN_SOURCE con el valor 700 (600 antes de glibc 2.10; 500 antes de glibc 2.2). Además, también se exponen varias extensiones específicas de GNU.
Desde glibc 2.19, definir _GNU_SOURCE también tiene el efecto de definir implícitamente _DEFAULT_SOURCE. Antes de glibc 2.20, definir _GNU_SOURCE también tenía el efecto de definir implícitamente _BSD_SOURCE y _SVID_SOURCE.
_REENTRANT
Históricamente, en varias bibliotecas C era necesario definir esta macro en todo el código multihilo. (Algunas bibliotecas C pueden seguir necesitándolo). En glibc, esta macro también exponía definiciones de ciertas funciones reentrantes.
Sin embargo, glibc ha sido segura para hilos por defecto durante muchos años; desde glibc 2.3, el único efecto de definir _REENTRANT ha sido habilitar una o dos de las mismas declaraciones que también se habilitan al definir _POSIX_C_SOURCE con un valor de 199606L o superior.
_REENTRANT es ahora obsoleto. En glibc 2.25 y posteriores, definir _REENTRANT es equivalente a definir _POSIX_C_SOURCE con el valor 199606L. Si se selecciona un nivel de conformidad POSIX superior por cualquier otro medio (como _POSIX_C_SOURCE mismo, _XOPEN_SOURCE, _DEFAULT_SOURCE, o _GNU_SOURCE), entonces definir _REENTRANT no tiene ningún efecto.
Esta macro se define automáticamente si se compila con cc -pthread.
_THREAD_SAFE
Sinónimo de _REENTRANT (obsoleto), proporcionado para compatibilidad con algunas otras implementaciones.
_FORTIFY_SOURCE (desde glibc 2.3.4)
Definir esta macro hace que se realicen algunas comprobaciones ligeras para detectar algunos errores de desbordamiento de búfer al utilizar varias funciones de manipulación de cadenas y memoria (por ejemplo, memcpy(3), memset(3), stpcpy(3), strcpy(3), strncpy(3), strcat(3), strncat(3), sprintf(3), snprintf(3), vsprintf(3), vsnprintf(3), gets(3), y sus variantes de caracteres anchos). Para algunas funciones, se comprueba la consistencia de los argumentos; por ejemplo, se comprueba que a open(2) se le haya proporcionado un argumento mode cuando las banderas especificadas incluyen O_CREAT. No todas
l problemas se detectan, solo algunos casos comunes.
Si _FORTIFY_SOURCE está establecido en 1, con nivel de optimización del compilador 1 (gcc -O1) y superiores, se realizan comprobaciones que no deberían cambiar el comportamiento de programas conformes. Con _FORTIFY_SOURCE establecido en 2, se añade alguna comprobación adicional, pero algunos programas conformes podrían fallar.
Algunas de las comprobaciones se pueden realizar en tiempo de compilación (mediante la lógica de macros implementada en archivos de cabecera), y resultan en advertencias del compilador; otras comprobaciones tienen lugar en tiempo de ejecución, y resultan en un error en tiempo de ejecución si la comprobación falla.
Con _FORTIFY_SOURCE establecido en 3, se añade comprobación adicional para interceptar algunas llamadas a funciones utilizadas con un argumento de tamaño variable donde el compilador puede deducir un límite superior para su valor. Por ejemplo, un programa donde el argumento de tamaño de malloc(3)es variable ahora puede ser fortalecido.
El uso de esta macro requiere soporte del compilador, disponible desde gcc 4.0 y clang 2.6. El uso de _FORTIFY_SOURCE establecido en 3 requiere gcc 12.0 o posterior, o clang 9.0 o posterior, en conjunto con glibc 2.33 o posterior.

Definiciones predeterminadas, definiciones implícitas y combinación de definiciones

Si no se definen explícitamente macros de prueba de características, entonces las siguientes macros de prueba de características se definen por defecto: _BSD_SOURCE (en glibc 2.19 y anteriores), _SVID_SOURCE (en glibc 2.19 y anteriores), _DEFAULT_SOURCE (desde glibc 2.19), _POSIX_SOURCE, y _POSIX_C_SOURCE=200809L (200112L antes de glibc 2.10; 199506L antes de glibc 2.4; 199309L antes de glibc 2.1).

Si alguna de __STRICT_ANSI__, _ISOC99_SOURCE, _ISOC11_SOURCE (desde glibc 2.18), _POSIX_SOURCE, _POSIX_C_SOURCE, _XOPEN_SOURCE, _XOPEN_SOURCE_EXTENDED (en glibc 2.11 y anteriores), _BSD_SOURCE (en glibc 2.19 y anteriores), o _SVID_SOURCE (en glibc 2.19 y anteriores) se define explícitamente, entonces _BSD_SOURCE, _SVID_SOURCE, y _DEFAULT_SOURCE no se definen por defecto.

Si _POSIX_SOURCE y _POSIX_C_SOURCE no se definen explícitamente, y ya sea __STRICT_ANSI__ no está definido o _XOPEN_SOURCE está definido con un valor de 500 o más, entonces

•
_POSIX_SOURCE se define con el valor 1; y
•
_POSIX_C_SOURCE se define con uno de los siguientes valores:
•
2, si _XOPEN_SOURCE está definido con un valor menor que 500;
•
199506L, si _XOPEN_SOURCE está definido con un valor mayor o igual a 500 y menor que 600; o
•
(desde glibc 2.4) 200112L, si _XOPEN_SOURCE está definido con un valor mayor o igual a 600 y menor que 700.
•
(Desde glibc 2.10) 200809L, si _XOPEN_SOURCE está definido con un valor mayor o igual a 700.
•
Las versiones anteriores de glibc no conocen los valores 200112L y 200809L para _POSIX_C_SOURCE, y la configuración de esta macro dependerá de la versión de glibc.
•
Si _XOPEN_SOURCE no está definido, entonces la configuración de _POSIX_C_SOURCE depende de la versión de glibc: 199506L, antes de glibc 2.4; 200112L, desde glibc 2.4 hasta glibc 2.9; y 200809L, desde glibc 2.10.

Se pueden definir múltiples macros; los resultados son aditivos.

ESTÁNDARES

POSIX.1 especifica _POSIX_C_SOURCE, _POSIX_SOURCE, y _XOPEN_SOURCE.

_FILE_OFFSET_BITS no está especificado por ningún estándar, pero se emplea en algunas otras implementaciones.

_BSD_SOURCE, _SVID_SOURCE, _DEFAULT_SOURCE, _ATFILE_SOURCE, _GNU_SOURCE, _FORTIFY_SOURCE, _REENTRANT, y _THREAD_SAFE son específicas de glibc.

HISTORIA

_XOPEN_SOURCE_EXTENDED fue especificada por XPG4v2 (también conocido como SUSv1), pero no está presente en SUSv2 y posteriores.

NOTAS

<features.h> es un archivo de cabecera específico de Linux/glibc. Otros sistemas tienen un archivo análogo, pero típicamente con un nombre diferente. Este archivo de cabecera es incluido automáticamente por otros archivos de cabecera según sea necesario: no es necesario incluirlo explícitamente para emplear macros de prueba de características.

Según cuáles de las macros de prueba de características anteriores estén definidas, <features.h> define internamente varias otras macros que son verificadas por otros archivos de cabecera de glibc. Estas macros tienen nombres con el prefijo de dos guiones bajos (por ejemplo, __USE_MISC). Los programas no deben nunca definir estas macros directamente: en su lugar, se deben emplear la(s) macro(s) de prueba de características apropiada(s) de la lista anterior.
