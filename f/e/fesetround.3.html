NOMBRE

feclearexcept, fegetexceptflag, feraiseexcept, fesetexceptflag, fetestexcept, fegetenv, fegetround, feholdexcept, fesetround, fesetenv, feupdateenv, feenableexcept, fedisableexcept, fegetexcept - Redondeo y manejo de excepciones de punto flotante

BIBLIOTECA

Biblioteca matemática (libm,-lm)

SINOPSIS

#include <fenv.h>
int feclearexcept(int excepts);
int fegetexceptflag(fexcept_t *flagp, int excepts);
int feraiseexcept(int excepts);
int fesetexceptflag(const fexcept_t *flagp, int excepts);
int fetestexcept(int excepts);
int fegetround(void);
int fesetround(int rounding_mode);
int fegetenv(fenv_t *envp);
int feholdexcept(fenv_t *envp);
int fesetenv(const fenv_t *envp);
int feupdateenv(const fenv_t *envp);

DESCRIPCIÓN

Estas once funciones se definieron en C99 y describen el manejo del redondeo y las excepciones de punto flotante (desbordamiento, división por cero, etc.).

Excepciones

La división por cero excepción ocurre cuando una operación sobre números finitos produce infinito como respuesta exacta.

La excepción de desbordamiento ocurre cuando un resultado debe representarse como un número de punto flotante, pero tiene un valor absoluto (mucho) mayor que el mayor número de punto flotante (finito) representable.

La excepción de desbordamiento por debajo ocurre cuando un resultado debe representarse como un número de punto flotante, pero tiene un valor absoluto menor que el número de punto flotante normalizado positivo más pequeño (y perdería mucha precisión al representarse como un número desnormalizado).

La excepción de inexactitud ocurre cuando el resultado redondeado de una operación no es igual al resultado de precisión infinita. Puede ocurrir siempre que desbordamiento o desbordamiento por debajo ocurre.

La excepción inválida ocurre cuando no hay un resultado bien definido para una operación, como en 0/0 o infinito - infinito o sqrt(-1).

Manejo de excepciones

Las excepciones se representan de dos maneras: como un solo bit (excepción presente/ausente), y estos bits corresponden de alguna manera definida por la implementación con posiciones de bits en un entero, y también como una estructura opaca que puede contener más información sobre la excepción (quizás la dirección del código donde ocurrió).

Cada una de las macros FE_DIVBYZERO, FE_INEXACT, FE_INVALID, FE_OVERFLOW, FE_UNDERFLOW se define cuando la implementación soporta el manejo de la excepción correspondiente, y si es así, define el bit (o bits) correspondiente, de modo que se puedan llamar funciones de manejo de excepciones, por ejemplo, usando el argumento entero FE_OVERFLOW|FE_UNDERFLOW. Pueden soportarse otras excepciones. La macro FE_ALL_EXCEPT es el OR bit a bit de todos los bits correspondientes a las excepciones soportadas.

La feclearexcept() función limpia las excepciones soportadas representadas por los bits en su argumento.

La fegetexceptflag() función almacena una representación de el estado de los indicadores de excepción representados por el argumento excepts en el objeto opaco *flagp.

La feraiseexcept() función genera las excepciones soportadas representadas por los bits en excepts.

La fesetexceptflag() función establece el estado completo para las excepciones representadas por excepts al valor *flagp. Este valor debe haberse obtenido por una llamada anterior a fegetexceptflag() con un último argumento que contenía todos los bits en excepts.

La fetestexcept() función devuelve una palabra en la que los bits están establecidos que fueron establecidos en el argumento excepts y para los cuales la excepción correspondiente está actualmente activa.

Modo de redondeo

El modo de redondeo determina cómo se trata el resultado de las operaciones de punto flotante cuando el resultado no puede representarse exactamente en el significando. Se pueden proporcionar varios modos de redondeo: redondear al más cercano (el predeterminado), redondear hacia arriba (hacia el infinito positivo), redondear hacia abajo (hacia el infinito negativo), y redondear hacia cero.

Cada una de las macros FE_TONEAREST, FE_UPWARD, FE_DOWNWARD, y FE_TOWARDZERO se define cuando la implementación soporta obtener y establecer la dirección de redondeo correspondiente.

La fegetround() función devuelve la macro correspondiente al modo de redondeo actual.

La fesetround() función establece el modo de redondeo como especificado por su argumento y devuelve cero cuando fue exitosa.

C99 y POSIX.1-2008 especifican un identificador, FLT_ROUNDS, definido en <float.h>, que indica el comportamiento de redondeo definido por la implementación para la suma de punto flotante. Este identificador tiene uno de los siguientes valores:

-1
El modo de redondeo no es determinable.
0
El redondeo es hacia 0.
1
El redondeo es hacia el número más cercano.
2
El redondeo es hacia el infinito positivo.
3
El redondeo es hacia el infinito negativo.

Otros valores representan modos de redondeo no estándar dependientes de la máquina.

El valor de FLT_ROUNDS debería reflejar el modo de redondeo actual establecido por fesetround() (pero ver ERRORES).

Entorno de punto flotante

Todo el entorno de punto flotante, incluyendo modos de control e indicadores de estado, puede manejarse como un solo objeto opaco, de tipo fenv_t. El entorno predeterminado se denota por FE_DFL_ENV (de tipo const fenv_t *). Este es el entorno configurado al inicio del programa y está definido por ISO C para tener redondeo al más cercano, todas las excepciones limpiadas y un modo sin parada (continuar en excepciones).

La fegetenv() función guarda el entorno de punto flotante actual en el objeto *envp.

La feholdexcept() función hace lo mismo, luego limpia todos los indicadores de excepción, y establece un modo sin parada (continuar en excepciones), si está disponible. Devuelve cero cuando es exitosa.

La fesetenv() función restaura el entorno de punto flotante desde el objeto *envp. Este objeto debe ser conocido como válido, por ejemplo, el resultado de una llamada a fegetenv() o feholdexcept() o igual a FE_DFL_ENV. Esta llamada no genera excepciones.

La feupdateenv() función instala el entorno de punto flotante representado por el objeto *envp, excepto que las excepciones actualmente activas no se limpian. Después de llamar a esta función, las excepciones activas serán un OR bit a bit de las previamente establecidas con las en *envp. Como antes, el objeto *envp debe ser conocido como válido.

VALOR DE RETORNO

Estas funciones devuelven cero en éxito y distinto de cero si ocurrió un error.

NOTAS

<a class='permalink' href='#glibc_notes'>notas de glibc

Si es posible, la Biblioteca C de GNU define una macro FE_NOMASK_ENV que representa un entorno en el que cada excepción generada provoca la aparición de una trampa. Puedes comprobar esta macro usando #ifdef. Solo se define si _GNU_SOURCE está definido. El estándar C99 no define una forma de establecer bits individuales en la máscara de coma flotante, por ejemplo, para generar una trampa en indicadores específicos. Desde glibc 2.2, glibc soporta las funciones feenableexcept() y fedisableexcept() para establecer trampas individuales de coma flotante, y fegetexcept() para consultar el estado.

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <fenv.h>
int feenableexcept(int excepts);
int fedisableexcept(int excepts);
int fegetexcept(void);

Las feenableexcept() y fedisableexcept() funciones habilitan (deshabilitan) trampas para cada una de las excepciones representadas por excepts y devuelven el conjunto anterior de excepciones habilitadas cuando se realizan correctamente, y -1 en caso contrario. La fegetexcept() función devuelve el conjunto de todas las excepciones actualmente habilitadas.

ERRORES

C99 especifica que el valor de FLT_ROUNDS debe reflejar cambios en el modo de redondeo actual, tal como lo establece fesetround(). Actualmente, esto no ocurre: FLT_ROUNDS siempre tiene el valor 1.
