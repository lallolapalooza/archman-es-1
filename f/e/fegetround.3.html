fenv(3) Manual de funciones de biblioteca fenv(3)

NOMBRE

feclearexcept, fegetexceptflag, feraiseexcept, fesetexceptflag, fetestexcept, fegetenv, fegetround, feholdexcept, fesetround, fesetenv, feupdateenv, feenableexcept, fedisableexcept, fegetexcept - manejo de redondeo y excepciones de punto flotante

Biblioteca matemática (libm, -lm)

SINOPSIS

#include <fenv.h>

int fegetexceptflag(fexcept_t *flagp, int excepts);
int feraiseexcept(int excepts);
int fesetexceptflag(const fexcept_t *flagp, int excepts);
int fetestexcept(int excepts);
int fegetround(void);
int fesetround(int rounding_mode);
int fegetenv(fenv_t *envp);
int feholdexcept(fenv_t *envp);
int fesetenv(const fenv_t *envp);
int feupdateenv(const fenv_t *envp);

DESCRIPCIÓN

Estas once funciones fueron definidas en C99 y describen el manejo del redondeo y las excepciones de punto flotante (desbordamiento, división por cero, etc.).

Excepciones

La excepción de división por cero ocurre cuando una operación entre números finitos produce infinito como respuesta exacta.

La excepción de desbordamiento ocurre cuando un resultado debe ser representado como un número de punto flotante, pero tiene un valor absoluto (mucho) mayor que el número de punto flotante (finito) más grande que se puede representar.

La excepción de subdesbordamiento ocurre cuando un resultado debe ser representado como un número de punto flotante, pero tiene un valor absoluto menor que el número normalizado positivo más pequeño de punto flotante (y perdería mucha precisión al ser representado como un número denormalizado).

La excepción de inexactitud ocurre cuando el resultado redondeado de una operación no es igual al resultado con precisión infinita. Puede ocurrir siempre que ocurran desbordamiento o subdesbordamiento.

La excepción de inválido ocurre cuando no hay un resultado bien definido para una operación, como en el caso de 0/0 o infinito - infinito o raíz cuadrada de -1.

Manejo de excepciones

Las excepciones se representan de dos maneras: como un solo bit (excepción presente/ausente), y estos bits corresponden de alguna manera definida por la implementación con posiciones de bits en un entero, y también como una estructura opaca que puede contener más información sobre la excepción (quizás la dirección del código donde ocurrió).

Cada una de las macros FE_DIVBYZERO, FE_INEXACT, FE_INVALID, FE_OVERFLOW, FE_UNDERFLOW se define cuando la implementación soporta el manejo de la excepción correspondiente, y si es así, define los bits correspondientes, de modo que se puedan llamar funciones de manejo de excepciones, por ejemplo, usando el argumento entero FE_OVERFLOW|FE_UNDERFLOW. Puede que se soporten otras excepciones. La macro FE_ALL_EXCEPT es el OR bit a bit de todos los bits correspondientes a las excepciones soportadas.

La función feclearexcept() borra las excepciones soportadas representadas por los bits en su argumento.

La función fegetexceptflag() almacena una representación del estado de las banderas de excepción representadas por el argumento excepts en el objeto opaco *flagp.

La función feraiseexcept() eleva las excepciones soportadas representadas por los bits en excepts.

La función fesetexceptflag() establece el estado completo para las excepciones representadas por excepts al valor *flagp. Este valor debe haber sido obtenido por una llamada anterior a fegetexceptflag() con un último argumento que contenía todos los bits en excepts.

La función fetestexcept() devuelve una palabra en la que los bits están establecidos que estaban establecidos en el argumento excepts y para los cuales la excepción correspondiente está actualmente establecida.

Modo de redondeo

El modo de redondeo determina cómo se trata el resultado de las operaciones de punto flotante cuando el resultado no se puede representar exactamente en la mantisa. Se pueden proporcionar varios modos de redondeo: redondear a la más cercana (el predeterminado), redondear hacia arriba (hacia infinito positivo), redondear hacia abajo (hacia infinito negativo) y redondear hacia cero.

Cada una de las macros FE_TONEAREST, FE_UPWARD, FE_DOWNWARD y FE_TOWARDZERO se define cuando la implementación soporta la obtención y el establecimiento de la dirección de redondeo correspondiente.

La función fegetround() devuelve la macro correspondiente al modo de redondeo actual.

La función fesetround() establece el modo de redondeo como se especifica en su argumento y devuelve cero cuando tiene éxito.

C99 y POSIX.1-2008 especifican un identificador, FLT_ROUNDS, definido en <float.h>, que indica el comportamiento de redondeo definido por la implementación para la suma de punto flotante. Este identificador tiene uno de los siguientes valores:

-1
El modo de redondeo no es determinable.
0
El redondeo es hacia 0.
1
El redondeo es hacia el número más cercano.
2
El redondeo es hacia infinito positivo.
3
El redondeo es hacia infinito negativo.

Otros valores representan modos de redondeo dependientes de la máquina, no estándar.

El valor de FLT_ROUNDS debería reflejar el modo de redondeo actual tal como lo establece fesetround() (pero ver BUGS).

Entorno de punto flotante

Todo el entorno de punto flotante, incluidos los modos de control y las banderas de estado, puede manejarse como un solo objeto opaco, de tipo fenv_t. El entorno predeterminado se denota con FE_DFL_ENV (de tipo const fenv_t *). Este es el entorno configurado al inicio del programa y está definido por ISO C para tener redondeo a la más cercana, todas las excepciones borradas y un modo "nonstop" (continuar ante excepciones).

La función fegetenv() guarda el entorno de punto flotante actual en el objeto *envp.

La función feholdexcept() hace lo mismo, luego borra todas las banderas de excepción y establece un modo "nonstop" (continuar ante excepciones), si está disponible. Devuelve cero cuando tiene éxito.

La función fesetenv() restaura el entorno de punto flotante desde el objeto *envp. Este objeto debe ser válido conocido, por ejemplo, el resultado de una llamada a fegetenv() o feholdexcept(), o igual a FE_DFL_ENV. Esta llamada no genera excepciones.

La función feupdateenv() instala el entorno de punto flotante representado por el objeto *envp, excepto que las excepciones actualmente elevadas no se borran. Después de llamar a esta función, las excepciones elevadas serán un OR bit a bit de las previamente establecidas con las de *envp. Como antes, el objeto *envp debe ser válido conocido.

VALOR DE RETORNO

Estas funciones devuelven cero si tienen éxito y un valor distinto de cero si ocurrió un error.

NOTAS

Notas de glibc

Las funciones feenableexcept(), fedisableexcept() y fegetexcept() no forman parte de los estándares C o POSIX. Fueron añadidas en glibc 2.0 y posteriormente eliminadas, pero se han reintroducido en glibc 2.1. Estas funciones proporcionan una interfaz para habilitar/deshabilitar excepciones y para obtener el estado de las excepciones en un nivel más fino que el ofrecido por las funciones estándar. Estas funciones solo son útiles si el hardware subyacente soporta el control de excepciones de punto flotante de esta manera.

Las funciones fegetenv(), feholdexcept(), fesetenv() y feupdateenv() pueden ser ineficientes. El entorno de punto flotante puede ser guardado y restaurado más eficientemente, pero su implementación es específica de la arquitectura.

La norma C y POSIX esperan que FLT_ROUNDS sea un valor constante. Sin embargo, las versiones antiguas de glibc permitían que fesetround() modificara el valor de FLT_ROUNDS. Las versiones más nuevas de glibc no hacen esto y se basan en que el compilador genere el código correcto en función del valor de FLT_ROUNDS para la compilación. Si este valor no es el correcto para el entorno de ejecución, entonces el redondeo puede no comportarse como se espera.

a class='permalink' href='#glibc_notes'>Notas de glibc

Si es posible, la Biblioteca C de GNU define una macro FE_NOMASK_ENV que representa un entorno donde cada excepción generada provoca la aparición de una trampa. Puede comprobar esta macro usando #ifdef. Solo se define si _GNU_SOURCE está definido. El estándar C99 no define una forma de establecer bits individuales en la máscara de punto flotante, por ejemplo, para generar una trampa en indicadores específicos. Desde glibc 2.2, glibc soporta las funciones feenableexcept() y fedisableexcept() para establecer trampas de punto flotante individuales, y fegetexcept() para consultar el estado.

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <fenv.h>
int feenableexcept(int excepts);
int fedisableexcept(int excepts);
int fegetexcept(void);

Las feenableexcept() y fedisableexcept() funciones habilitan (deshabilitan) trampas para cada una de las excepciones representadas por excepts y devuelven el conjunto anterior de excepciones habilitadas cuando se realizan correctamente, y -1 en caso contrario. La fegetexcept() función devuelve el conjunto de todas las excepciones actualmente habilitadas.

ERRORES

C99 especifica que el valor de FLT_ROUNDS debe reflejar cambios en el modo de redondeo actual, tal como lo establece fesetround(). Actualmente, esto no ocurre: FLT_ROUNDS siempre tiene el valor 1.
