DESCRIPCIÓ

N

ferm es una interfaz para iptables. Lee las reglas desde un archivo de configuración estructurado y llama a iptables(8) para insertarlas en el kernel en

ejecución.

El objetivo de ferm es hacer que las reglas de firewall sean fáciles de escribir y fáciles de leer. Intenta reducir la tediosa tarea de escribir reglas, permitiendo así al administrador del firewall dedicar más tiempo a desarrollar buenas reglas que a la implementación correcta de la

regla.

Para lograr esto, ferm utiliza un lenguaje de configuración simple pero potente, que permite variables, funciones, arreglos y bloques. También permite incluir otros archivos, lo que le permite crear bibliotecas de estructuras y funciones comúnmente

utilizadas.

ferm, pronunciado "firm", significa "For Easy

Rule Making" (Para Hac
er Reglas Fácilmente).

PRECAUCIÓ

N

Esta página de manual no pretende enseñarle cómo funciona el firewalling ni cómo escribir buena

s reglas. Ya existe suficiente
documentación sobre este tema.

INTRODUCCIÓ

N

Comencemos con un ejemplo

simple: 
chain INPUT {
    proto tcp ACCEPT;
}

Esto añadirá una regla a la cadena de entrada predefinida, que coincide y acepta todos los paquetes TCP. Bien, hagámoslo más

complicado: 
chain (INPUT OUTPUT) {
    proto (udp tcp) ACCEPT;
}

Esto insertará 4 reglas, a saber, 2 en la cadena input y 2 en la cadena output, que coinciden y aceptan tanto paquetes UDP como TCP. Normalmente escribirías

esto: 
iptables -A INPUT -p tcp -j ACCEPT
iptables -A OUTPUT -p tcp -j ACCEPT
iptables -A INPUT -p udp -j ACCEPT
iptables -A OUTPUT -p udp -j
ACCEPT

Observa cuánto menos tecleo necesitamos hacer? :

-)

Básicamente, esto es todo, aunque puedes hacerlo bastante más complejo. Algo para

ver: 
chain INPUT {
    policy ACCEPT;
    daddr 10.0.0.0/8 proto tcp dport ! ftp jump mychain sport :1023 TOS 4 settos 8 mark 2;
    daddr 10.0.0.0/8 proto tcp dport ftp REJECT;
}

Mi punto aquí es que *tú* necesitas hacer reglas bonitas, mantenerlas legibles para ti y para los demás, y no convertirlas en un

desastre.

Ayudaría al lector si las reglas de firewall resultantes se colocaran aquí para referencia. Además, podrías incluir la versión anidada con mejor

legibilidad.

Intenta usar comentarios para mostrar lo que estás

haciendo: 
# esta línea habilita el proxy http transparente para la red interna:
proto tcp if eth0 daddr ! 192.168.0.0/255.255.255.0
    dport http REDIRECT to-ports
3128;

¡Te lo agradecerás más

tarde! 
chain INPUT {
    policy ACCEPT;
    interface (eth0 ppp0) {
        # denegar el acceso a notorios hackers, volver aquí si no se encontró
        # ninguna coincidencia para reanudar el firewalling normal
        jump badguys;
        protocol tcp jump fw_tcp;
        protocol udp jump fw_udp;
    }
}

Cuanto más anides, mejor se verá. Asegúrate de que el orden que especificas es correcto, no querrías hacer

esto: 
chain FORWARD {
    proto ! udp DROP;
    proto tcp dport ftp ACCEPT;
}

porque la segunda regla nunca coincidirá. La mejor manera es primero especificar todo lo que está permitido, y luego denegar todo lo demás. Mira los ejemplos para ver más buenas instantáneas. La mayoría de la gente hace algo

así: 
proto tcp {
    dport (
        ssh http ftp
    ) ACCEPT;
    dport 1024:65535 ! syn ACCEPT;
    DROP;
}

ESTRUCTURA DE UN ARCHIVO DE

FIREWALL

La estructura de un archivo de firewall adecuado se parece a código C simplificado. Solo se utilizan unos pocos caracteres sintácticos en los archivos de configuración de ferm. Además de estos caracteres especiales, ferm usa 'claves' y 'valores', piensa en ellos como opciones y parámetros, o como variables y valores, lo que

sea.

Con estas palabras, defines las características de tu firewall. Cada firewall consta de dos cosas: primero, ver si el tráfico de red coincide con ciertas condiciones, y segundo, qué hacer con ese

tráfico.

Puedes especificar condiciones que sean válidas para el programa de interfaz del kernel que estás usando, probablemente iptables(8). Por ejemplo, en iptables, cuando intentas coincidir con paquetes TCP,

dirías: 
iptables --protocol
tcp

En ferm, esto se convertirá

en: 
protocol
tcp;

Simplemente escribiendo esto en ferm no hace nada, necesitas decirle a ferm (en realidad, necesitas decirle a iptables(8) y al kernel) qué hacer con cualquier tráfico que coincida con esta

condición: 
iptables --protocol tcp -j
ACCEPT

O, traducido a ferm

: 
protocol tcp
ACCEPT;

El carácter ; está al final de cada regla de ferm. Ferm ignora los saltos de línea, lo que significa que el ejemplo anterior es idéntico al

siguiente: 
protocol tcp
ACCEPT;

especiales:
;

legibilidad:

Las llaves contienen cualquier número de reglas anidadas. Todas las coincidencias antes del bloque se arrastran a

estas.

La llave de cierre finaliza el conjunto de reglas. No deberías escribir un ';' después de eso porque eso sería una regla

vacía.

    icmp-type echo-request ACCEPT;

Variable

s

En archivos de firewall complejos, es útil usar variables, por ejemplo, para dar a una interfaz de red un nombre

significativo.

Para definir variables,

escriba: 
@def $DEV_INTERNET = eth0;
@def $PORTS = (http ftp);
@def $MORE_PORTS = ($PORTS 8080)
;

En el código real de ferm, las variables se usan como cualquier otro parámetro de palabra

clave: 
chain INPUT interface $DEV_INTERNET proto tcp dport $MORE_PORTS
ACCEPT;

Tenga en cuenta que las variables solo pueden usarse en parámetros de palabras clave ("192.168.1.1", "http"); no pueden contener palabras clave de ferm como "proto" o

"interface".

Las variables solo son válidas en el bloque

actual: 
@def $DEV_INTERNET = eth1;
chain INPUT {
    proto tcp {
        @def $DEV_INTERNET = ppp0;
        interface $DEV_INTERNET dport http ACCEPT;
    }
    interface $DEV_INTERNET DROP;
}

se expandirá

a: 
chain INPUT {
    proto tcp {
        interface ppp0 dport http ACCEPT;
    }
    interface eth1 DROP;
}

El "def $DEV_INTERNET = ppp0" solo es válido en el bloque "proto tcp"; el bloque padre todavía conoce "set $DEV_INTERNET =

eth1".

Los archivos incluidos son especiales: las variables declaradas en un ar

chivo incluido siguen estando disponibles en el bloque que lo llama
. Esto es útil cuando incluye un archivo que solo declara variables.

Funcione

s

Las funciones son similares a las variables, excepto que pueden tener parámetros, y proporcionan comandos de ferm, no

@def &FOO() = proto (tcp udp) dport domain;

@def &TCP_TUNNEL($port, $dest) = {
    table filter chain FORWARD interface ppp0 proto tcp dport $port daddr $dest outerface eth0 ACCEPT;
    table nat chain PREROUTING interface ppp0 proto tcp dport $port daddr 1.2.3.4 DNAT to $dest;

&TCP_TUNNEL(ftp, 192.168.1.30);
&TCP_TUNNEL((ssh smtp), 192.168.1.2)
;

Una llamada a función que contiene un bloque (como '{...}') debe ser el último comando en una regla de ferm, es decir, debe ir seguida de ';'. La llamada'&FOO()' no contiene un bloque, por lo que puede escribir 'ACCEPT' después de la llamada. Para evitar esto, puede reordenar las palabras

clave: 
@def &IPSEC() = { proto (esp
ah); proto udp dport 500; }
chain INPUT ACCEPT &IPSEC();

Backtick

s

Con backticks, puede usar la salida de un comando

externo: 
@def $DNSSERVERS = `grep nameserver /etc/resolv.conf | awk '{print $2}'`;
chain INPUT proto tcp saddr $DNSSERVERS
ACCEPT;

El comando se ejecuta con el shell (/bin/sh), igual que los backticks en Perl. ferm no realiza ninguna expansión de variables

aquí.

La salida se tokeniza y se guarda como una lista (array) de ferm. L

as líneas que comienzan con '#' se ignoran; las demás líneas pueden cont
ener cualquier número de valores, separados por espacios en blanco.

    NOMBRE

    ferm - Interfaz de línea de comandos fácil de usar para iptables

    SINOPSIS

    ferm <command> [-v] [-o] [-f <file>] [-c <chain>] [-s <target>] ...

    DESCRIPCIÓN

    ferm es una herramienta de gestión de firewall que simplifica la configuración de iptables. Permite definir reglas de firewall en un archivo de configuración más legible y estructurado, y luego aplicarlas usando el comando ferm.

    COMANDOS

    Los siguientes comandos están disponibles:

    • apply: Aplica las reglas definidas en el archivo de configuración.
    • list: Lista las reglas de firewall actualmente activas.
    • flush: Elimina todas las reglas de firewall.
    • restore: Restaura las reglas de firewall desde un archivo guardado.
    • save: Guarda las reglas de firewall actuales en un archivo.
    • check: Verifica la sintaxis del archivo de configuración sin aplicarlo.

    REGLAS DE FILTRO

    Las reglas de filtro definen cómo se deben tratar los paquetes de red. Se componen de una o más condiciones y una acción.

    Ejemplo: port 22 accept;

    OBJETIVOS

    Los objetivos especifican la acción a realizar con un paquete que coincide con una regla.

    • accept: Permite que el paquete continúe.
    • reject: Rechaza el paquete y envía un mensaje de error ICMP.
    • drop: Descarta silenciosamente el paquete.
    • return: Sale de la cadena actual y vuelve a la cadena que la llamó.
    • jump <chain_name>: Salta a otra cadena de reglas.

    ACCIONES

    Las acciones son las operaciones que se pueden realizar con ferm.

    • port <port_number>: Coincide con un puerto específico.
    • protocol <protocol_name>: Coincide con un protocolo específico (tcp, udp, icmp, etc.).
    • source address <ip_address>: Coincide con una dirección IP de origen.
    • destination address <ip_address>: Coincide con una dirección IP de destino.

    OPCIONES COMUNES

    • -v, --verbose: Muestra información detallada durante la ejecución.
    • -o, --overwrite: Sobrescribe las reglas existentes.
    • -f <file>, --file=<file>: Especifica el archivo de configuración de ferm.
    • -c <chain>, --chain=<chain>: Especifica la cadena de iptables a la que se aplicarán las reglas.
    • -s <target>, --set-target=<target>: Establece el objetivo predeterminado para una cadena.

    OPCIONES EXTENDIDAS

    ferm admite una amplia gama de opciones extendidas para una configuración más detallada, incluyendo el manejo de interfaces de red, estados de conexión, etc.

    CARACTERES ESPECIALES

    Se pueden utilizar caracteres especiales como ! (negación), && (AND lógico), || (OR lógico) para construir condiciones complejas.

    OPCIONES DE PALABRAS CLAVE

    ferm utiliza palabras clave como accept, drop, reject, port, protocol, source, destination para definir reglas.

    OTROS DOMINIOS

    ferm puede gestionar reglas para diferentes dominios o servicios, permitiendo una organización clara de la configuración.

    CARACTERÍSTICAS AVANZADAS

    Incluye soporte para tablas personalizadas, cadenas personalizadas, módulos de iptables (como conntrack, limit, etc.) y políticas de firewall.

    FUNCIONES INCORPORADAS

    ferm proporciona funciones integradas para simplificar tareas comunes, como la definición de rangos de puertos o la importación de direcciones IP desde archivos.

    RECETAS

    La documentación de ferm a menudo incluye "recetas" o ejemplos de configuración para casos de uso comunes, como la configuración de un servidor web o un servidor SSH.

    OPCIONES

    El comando ferm en sí mismo tiene varias opciones que modifican su comportamiento general, como se describe en la sección COMMON_OPTIONS.

    VER TAMBIÉN

    iptables(8)

    REQUISITOS

    ferm requiere iptables instalado en el sistema.

    ERRORES

    Los informes de errores deben enviarse a la lista de correo de ferm o al sistema de seguimiento de errores del proyecto.
