FATTACH(3P) Manual de Programador POSIX FATTACH(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fattach — adjuntar un descriptor de archivo basado en STREAMS a un archivo en el espacio de nombres del sistema de archivos (STREAMS)

SINOPSIS

#include <stropts.h>
int fattach(int fildes, const char *path);

DESCRIPCIÓN

La función fattach() adjunta un descriptor de archivo basado en STREAMS a un archivo, asociando efectivamente un nombre de ruta con fildes. La aplicación debe asegurarse de que el argumento fildes sea un descriptor de archivo abierto válido asociado con un archivo STREAMS. El argumento path apunta a un nombre de ruta de un archivo existente. La aplicación debe tener privilegios apropiados o ser el propietario del archivo nombrado por path y tener permiso de escritura. Una llamada exitosa a fattach() hará que todos los nombres de ruta que nombren el archivo nombrado por path, nombren el archivo STREAMS asociado con fildes, hasta que el archivo STREAMS se desvincule del archivo. Un archivo STREAMS puede adjuntarse a más de un archivo y puede tener varios nombres de ruta asociados.

Los atributos del archivo STREAMS nombrado se inicializarán de la siguiente manera: los permisos, el ID de usuario, el ID de grupo y las horas se establecerán en los del archivo nombrado por path, el número de enlaces se establecerá en 1, y el tamaño y el identificador del dispositivo se establecerán en los del archivo STREAMS asociado con fildes. Si posteriormente se modifican los atributos del archivo STREAMS nombrado (por ejemplo, mediante chmod()), ni los atributos del archivo subyacente ni los atributos del archivo STREAMS al que se refiere fildes se verán afectados.

Los descriptores de archivo que se refieren al archivo subyacente, abiertos antes de una llamada fattach(), continuarán refiriéndose al archivo subyacente.

VALOR DE RETORNO

Al completarse con éxito, fattach() devolverá 0. En caso contrario, se devolverá -1 y se establecerá errno para indicar el error.

ERRORES

La función fattach() fallará si:

EACCES
Se niega el permiso de búsqueda para un componente del prefijo de ruta, o el proceso es el propietario de path pero no tiene permisos de escritura en el archivo nombrado por path.
EBADF
El argumento fildes no es un descriptor de archivo abierto válido.
EBUSY
El archivo nombrado por path es actualmente un punto de montaje o tiene un archivo STREAMS adjunto a él.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> al final.
EPERM
El ID de usuario efectivo del proceso no es el propietario del archivo nombrado por path y el proceso no tiene los privilegios apropiados.

La función fattach() puede fallar si:

EINVAL
El argumento fildes no se refiere a un archivo STREAMS.
ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución del nombre de ruta de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
EXDEV
Se intentó enlazar a un archivo en otro sistema de archivos.

EJEMPLOS

Adjuntar un Descriptor de Archivo a un Archivo

En el siguiente ejemplo, fd se refiere a un archivo STREAMS abierto. La llamada a fattach() asocia este STREAM con el archivo /tmp/named-STREAM, de modo que cualquier llamada futura para abrir /tmp/named-STREAM, antes de romper la asociación mediante una llamada a fdetach(), creará en su lugar un nuevo manejador de archivos que se refiere al archivo STREAMS asociado con fd.

#include <stropts.h>
...
    int fd;
    char *pathname = "/tmp/named-STREAM";
    int ret;
    ret = fattach(fd, pathname);

USO DE APLICACIÓN

La función fattach() se comporta de manera similar a la función tradicional mount() en la forma en que un archivo es reemplazado temporalmente por el directorio raíz del sistema de archivos montado. En el caso de fattach(), el archivo reemplazado no tiene por qué ser un directorio y el archivo que reemplaza es un archivo STREAMS.

RACIOCINIO

Los atributos del archivo de un archivo que ha sido objeto de una llamada fattach() se establecen específicamente debido a un artefacto de la implementación original. El mecanismo interno era el mismo que para la función mount(). Dado que mount() se aplica típicamente solo a directorios, los efectos cuando se aplica a un archivo regular son un poco sorprendentes, especialmente en lo que respecta al recuento de enlaces, que rígidamente permanece en uno, incluso si originalmente había varios enlaces y a pesar del hecho de que todos los enlaces originales se refieren al STREAM siempre que la fattach() permanezca en vigor.

DIRECCIONES FUTURAS

La función fattach() puede ser eliminada en una versión futura.
