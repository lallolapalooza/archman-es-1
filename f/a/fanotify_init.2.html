fanotify_init(2) Manual de Llamadas al Sistema fanotify_init(2)

NOMBRE

fanotify_init - crear e inicializar un grupo fanotify

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <fcntl.h>            /* Definición de las constantes O_* */
#include <sys/fanotify.h>
int fanotify_init(unsigned int flags, unsigned int event_f_flags);

DESCRIPCIÓN

Para una descripción general de la API de fanotify, consulte fanotify(7).

fanotify_init() inicializa un nuevo grupo fanotify y devuelve un descriptor de archivo para la cola de eventos asociada con el grupo.

El descriptor de archivo se utiliza en las llamadas a fanotify_mark(2) para especificar los archivos, directorios, montajes o sistemas de archivos para los cuales se deben crear eventos de fanotify. Estos eventos se reciben leyendo del descriptor de archivo. Algunos eventos son solo informativos, indicando que un archivo ha sido accedido. Otros eventos se pueden utilizar para determinar si otra aplicación tiene permiso para acceder a un archivo o directorio. El permiso para acceder a objetos del sistema de archivos se concede escribiendo en el descriptor de archivo.

Varios programas pueden estar utilizando la interfaz de fanotify al mismo tiempo para monitorear los mismos archivos.

El número de grupos fanotify por usuario está limitado. Consulte fanotify(7) para obtener detalles sobre este límite.

El argumento flags contiene un campo de múltiples bits que define la clase de notificación de la aplicación de escucha y otros campos de un solo bit que especifican el comportamiento del descriptor de archivo.

Si existen múltiples oyentes para eventos de permisos, la clase de notificación se utiliza para establecer el orden en el que los oyentes reciben los eventos.

Solo se puede especificar una de las siguientes clases de notificación en flags:

FAN_CLASS_PRE_CONTENT
Este valor permite la recepción de eventos que notifican que un archivo ha sido accedido y eventos para decisiones de permisos sobre si un archivo puede ser accedido. Está destinado a oyentes de eventos que puedan necesitar escribir datos en los archivos antes de que sus datos finales puedan ser accedidos. Esta clase de notificación podría ser utilizada por, por ejemplo, administradores de almacenamiento jerárquico. El uso de este flag requiere la capacidad CAP_SYS_ADMIN .
FAN_CLASS_CONTENT
Este valor permite la recepción de eventos que notifican que un archivo ha sido accedido y eventos para decisiones de permisos sobre si un archivo puede ser accedido. Está destinado a oyentes de eventos que necesitan acceder a los archivos cuando ya contienen su contenido final. Esta clase de notificación podría ser utilizada por, por ejemplo, programas de detección de malware. El uso de este flag requiere la capacidad CAP_SYS_ADMIN .
FAN_CLASS_NOTIF
Este es el valor predeterminado. No necesita ser especificado. Este valor solo permite la recepción de eventos que notifican que un archivo ha sido accedido. No son posibles decisiones de permisos antes de que el archivo sea accedido.

Los oyentes con diferentes clases de notificación recibirán eventos en el orden FAN_CLASS_PRE_CONTENT, FAN_CLASS_CONTENT, FAN_CLASS_NOTIF. El orden de notificación para los oyentes en la misma clase de no es definido.

Los siguientes bits se pueden establecer adicionalmente en flags:

FAN_CLOEXEC
Establecer el flag close-on-exec (FD_CLOEXEC) en el nuevo descriptor de archivo. Consulte la descripción del flag O_CLOEXEC en open(2).
FAN_NONBLOCK
Habilitar el flag no bloqueante (O_NONBLOCK) para el descriptor de archivo. La lectura del descriptor de archivo no se bloqueará. En su lugar, si no hay datos disponibles, read(2) fallará con el error EAGAIN.
FAN_UNLIMITED_QUEUE
Eliminar el límite en el número de eventos en la cola de eventos. Consulte fanotify(7) para obtener detalles sobre este límite. El uso de este flag requiere la capacidad CAP_SYS_ADMIN .
FAN_UNLIMITED_MARKS
Eliminar el límite en el número de marcas fanotify por usuario. Consulte fanotify(7) para obtener detalles sobre este límite. El uso de este flag requiere la capacidad CAP_SYS_ADMIN .
FAN_REPORT_TID (desde Linux 4.20)
Informar el ID de hilo (TID) en lugar del ID de proceso (PID) en el campo pid de la struct fanotify_event_metadata proporcionada a read(2) (consulte fanotify(7)). El uso de este flag requiere la capacidad CAP_SYS_ADMIN .
FAN_ENABLE_AUDIT (desde Linux 4.15)
Habilitar la generación de registros de auditoría sobre la mediación de acceso realizada por eventos de permisos. La respuesta del evento de permiso debe estar marcada con el flag FAN_AUDIT para que se genere un registro de auditoría. El uso de este flag requiere la capacidad CAP_AUDIT_WRITE .
FAN_REPORT_FID (desde Linux 5.1)
Este valor permite la recepción de eventos que contienen información adicional sobre el objeto del sistema de archivos subyacente correlacionado con un evento. Un registro adicional de tipo FAN_EVENT_INFO_TYPE_FID encapsula la información sobre el objeto y se incluye junto con la estructura genérica de metadatos del evento. El descriptor de archivo que se utiliza para representar el objeto correlacionado con un evento se sustituye en su lugar por un manejador de archivo. Está destinado a aplicaciones que puedan encontrar que el uso de un manejador de archivo para identificar un objeto es más adecuado que un descriptor de archivo. Adicionalmente, puede ser utilizado por aplicaciones que monitorean un directorio o un sistema de archivos y que están interesadas en los eventos de modificación de entradas de directorio FAN_CREATE, FAN_DELETE, FAN_MOVE, y FAN_RENAME, o en eventos como FAN_ATTRIB, FAN_DELETE_SELF, y FAN_MOVE_SELF. Todos los eventos anteriores requieren un grupo fanotify que identifique los objetos del sistema de archivos por manejadores de archivo. Tenga en cuenta que sin el flag FAN_REPORT_TARGET_FID, para los eventos de modificación de entradas de directorio, hay un registro de información que identifica el directorio modificado y no el objeto hijo creado/eliminado/movido. El uso de FAN_CLASS_CONTENT o FAN_CLASS_PRE_CONTENT no está permitido con este flag y resultará en el error EINVAL. Consulte fanotify(7) para detalles adicionales.
FAN_REPORT_DIR_FID (desde Linux 5.9)
Los eventos para grupos fanotify inicializados con este flag contendrán (consulte las excepciones abajo) información adicional sobre un objeto de directorio correlacionado con un evento. Un registro adicional de tipo FAN_EVENT_INFO_TYPE_DFID encapsula la información sobre el objeto de directorio y se incluye junto con la estructura genérica de metadatos del evento. Para eventos que ocurren en un objeto que no es un directorio, la estructura adicional incluye un manejador de archivo que identifica el objeto de directorio padre del sistema de archivos. Tenga en cuenta que no hay garantía de que el objeto de directorio del sistema de archivos se encontrará en la ubicación descrita por la información del manejador de archivo en el momento en que se recibe el evento. Cuando se combina con el flag FAN_REPORT_FID, se pueden informar dos registros con eventos que ocurren en un objeto que no es un directorio, uno para identificar el objeto que no es un directorio en sí mismo y otro para identificar el objeto de directorio padre. Tenga en cuenta que en algunos casos, un objeto del sistema de archivos no tiene un padre, por ejemplo, cuando un evento ocurre en un archivo desvinculado pero abierto. En ese caso, con el flag FAN_REPORT_FID , el evento se informará con solo un registro para identificar el objeto que no es un directorio en sí mismo, porque no hay ningún directorio asociado con el evento. Sin el flag FAN_REPORT_FID , no se informará ningún evento. Consulte fanotify(7) para detalles adicionales.

événements pour les groupes fanotify initialisés avec cet indicateur contiendront des informations supplémentaires sur le nom de l'entrée de répertoire corrélée à un événement. Cet indicateur doit être fourni conjointement avec l'indicateur FAN_REPORT_DIR_FID. Fournir cette valeur d'indicateur sans FAN_REPORT_DIR_FID entraînera l'erreur EINVAL. Cet indicateur peut être combiné avec l'indicateur FAN_REPORT_FID. Un enregistrement supplémentaire de type FAN_EVENT_INFO_TYPE_DFID_NAME, qui encapsule les informations sur l'entrée de répertoire, est inclus à côté de la structure générique de métadonnées d'événement et remplace l'enregistrement d'informations supplémentaires de type FAN_EVENT_INFO_TYPE_DFID. L'enregistrement supplémentaire inclut un descripteur de fichier qui identifie un objet de système de fichiers de répertoire, suivi d'un nom qui identifie une entrée dans ce répertoire. Pour les événements de modification d'entrée de répertoire FAN_CREATE, FAN_DELETE, et FAN_MOVE, le nom rapporté est celui de l'entrée de répertoire créée/supprimée/déplacée. L'événement FAN_RENAME peut contenir deux enregistrements d'informations. L'un de type FAN_EVENT_INFO_T YPE_OLD_DFID_NAME identifiant l'ancienne entrée de répertoire, et un autre de type FAN_EVENT_INFO_TYPE _NEW_DFID_NAME identifiant la nouvelle entrée de répertoire. Pour les autres événements qui se produisent sur un objet répertoire, le descripteur de fichier rapporté est celui de l'objet répertoire lui-même et le nom rapporté est '.'. Pour les autres événements qui se produisent sur un objet non-répertoire, le descripteur de fichier rapporté est celui de l'objet répertoire parent et le nom rapporté est le nom d'une entrée de répertoire où l'objet se trouvait au moment de l'événement. La justification de cette logique est que le descripteur de fichier du répertoire rapporté peut être passé à open_by_handle_at(2) pour obtenir un descripteur de fichier de répertoire ouvert et que ce descripteur de fichier, avec le nom rapporté, peut être utilisé pour appeler fstatat(2). La même règle qui s'applique au type d'enregistrement FAN_EVENT_INFO_TYPE_DFID s'applique aussi au type d'enregistrement FAN_EVENT_INFO_TYPE_DFID_NAME : si un objet non-répertoire n'a pas de parent, soit l'événement ne sera pas rapporté, soit il sera rapporté sans les informations d'entrée de répertoire. Notez qu'il n'y a aucune garantie que l'objet de système de fichiers sera trouvé à l'emplacement décrit par les informations d'entrée de répertoire au moment où l'événement est reçu. El siguiente error estaba presente antes de Linux 3.18:

El O_CLOEXEC se ignora cuando se pasa en event_f_flags.

•
El argumento event_f_flags no se comprueba en busca de flags no válidos. Los flags que están destinados solo para uso interno, como FMODE_EXEC, pueden establecerse y, en consecuencia, se establecerán para los descriptores de archivo devueltos al leer desde el descriptor de archivo de fanotify.
