FAKECHROOT(1) FAKECHROOT(1)

NOMBRE

fakechroot - proporciona un entorno chroot falso

SINOPSIS

fakechroot [-s|--use-system-libs] [-l|--lib biblioteca] [-d|--elfloader ldso] [-e|--environment tipo] [-c|--config-dir directorio] [-b|--bindir directorio] [--] [comando]

fakechroot -h|--help

fakechroot -v|--version

DESCRIPCIÓN

fakechroot ejecuta un comando en un entorno donde existe la posibilidad adicional de usar el comando chroot(8) sin privilegios de root. Esto es útil para permitir a los usuarios crear su propio entorno chrooted con la posibilidad de instalar otros paquetes sin necesidad de privilegios de root.

fakechroot reemplaza algunas funciones de la biblioteca C (chroot(2), open(2), etc.) por otras que simulan el efecto de ser llamadas con privilegios de root.

Estas funciones de envoltorio se proporcionan como una biblioteca compartida libfakechroot.so que se carga a través del mecanismo "LD_PRELOAD" del cargador dinámico. (Ver ld.so(8))

En fake chroot, puedes instalar, por ejemplo, un bootstrap de Debian con el comando debootstrap(8). En dicho entorno, puedes ejecutar, por ejemplo, el comando apt-get(8) para instalar otros paquetes. No necesitas privilegios especiales y puedes ejecutarlo como un usuario común.

OPCIONES

-b|--bindir directorio
Especifica un directorio que contenga los ejecutables de reemplazo distribuidos con fakechroot. Estos son archivos de script con la extensión ".fakechroot". Por defecto, se distribuyen por los directorios "bin" y "sbin" en el prefijo de instalación de fakechroot, pero a veces una ubicación fija en tiempo de compilación no es factible.
-c|--config-dir directorio
Especifica un directorio que contenga configuración adicional para fakechroot. Los directorios por defecto son "$HOME/.fakechroot" y "/etc/fakechroot".
-d ldso|--elfloader ldso
Especifica un enlazador dinámico alternativo. Este enlazador dinámico se invocará directamente.
-e|--environment tipo
Carga configuración adicional con entorno. Este archivo de configuración es un script de shell que se ejecuta antes de llamar a comando. El script puede establecer variables de entorno adicionales, como por ejemplo: "FAKECHROOT_EXCLUDE_PATH", "FAKECHROOT_CMD_SUBST" o "LD_LIBRARY_PATH".

El tipo de entorno se infiere basándose en el nombre del comando sin la extensión opcional (por ejemplo, ejecutar gettext.sh carga el archivo de entorno "gettext"). Si el argumento comando es fakeroot(1), este argumento se omite y el siguiente argumento se toma como el tipo de entorno.

El nombre del archivo de configuración es tipo.env y se busca en los directorios $HOME/.fakechroot y /etc/fakechroot.

El tipo de entorno por defecto es default y su nombre de archivo de configuración es "default.env".

El entorno especial none significa que no se carga ninguna configuración de entorno.

-l biblioteca|--lib biblioteca
Especifica una biblioteca de envoltorio alternativa. La predeterminada es libfakechroot.so
-h|--help
Muestra la ayuda.
-s|--use-system-libs
Usa las bibliotecas del sistema antes que las bibliotecas de chroot. Esto puede ser una solución alternativa si el enlazador dinámico del sistema no puede cargar libc.so desde el fake chroot.

Prueba esta configuración si observas errores como:

$ fakechroot /usr/sbin/chroot /tmp/sarge /bin/true
/bin/true: relocation error: /srv/sarge/lib/tls/libc.so.6: symbol _dl
_starting_up, version GLIBC_PRIVATE not defined in file ld-linux.so.2
 with link time reference
$ fakechroot /usr/sbin/chroot /tmp/centos4 /bin/true
Segmentation fault
-v|--version
Muestra la versión.
[--] comando
Cualquier comando que desees ejecutar como fakechroot. Usa '--' si el comando tiene otras opciones que puedan confundir el análisis de opciones de fakechroot.

FAKEROOT

fakeroot(1) es una herramienta complementaria que emula un entorno root. fakeroot y fakechroot pueden envolver las mismas funciones de biblioteca C, es decir, la función mknod(2). Es importante iniciar el entorno falso en el orden correcto. fakeroot debe iniciarse dentro de fakechroot:

$ fakechroot fakeroot chroot /tmp/sid /bin/mknod /tmp/device c 1 2

ASPECTOS DE SEGURIDAD

fakechroot es un programa regular, no setuid. No aumenta los privilegios de un usuario.

fakechroot no debe usarse como una herramienta para mejorar la seguridad del sistema, es decir, separando (aislando) aplicaciones. Es muy fácil escapar de un entorno fake chroot.

fakechroot no debe ejecutarse con privilegios reales de root. Podría disminuir la seguridad del sistema porque fakechroot proporciona su propia versión de funciones principales con comportamiento dependiente de algunas variables de entorno.

ARCHIVOS

libfakechroot.so
La biblioteca compartida que contiene las funciones de envoltorio.

ENTORNO

FAKECHROOT
El valor es verdadero para el entorno fake chroot.
FAKECHROOT_AF_UNIX_PATH
El directorio raíz para los sockets de unix. El valor por defecto es el mismo que "FAKECHROOT_BASE" y puede establecerse por separado si "FAKECHROOT_BASE" es demasiado largo y la ruta del socket de unix podría exceder el límite de 108 bytes.
FAKECHROOT_BASE
El directorio raíz del entorno fake chroot.
FAKECHROOT_CMD_SUBST
Una lista de sustituciones de comandos. Si un programa intenta ejecutar

uno de los comandos dados (ruta relativa al chroot, el punto final se elimina) entonces el comando sustituto se ejecuta en su lugar (la ruta al comando sustituto no está en chroot).

El comando sustituido hereda "FAKECHROOT_*" variables pero el original "FAKECHROOT_BASE" variable que se guarda como "FAKECHROOT_BASE_ORIG". Esto significa que el comando sustituido se ejecuta fuera del entorno fakechroot. También el nombre original del comando se guarda como "FAKECHROOT_CMD_ORIG".

Por ejemplo:

export FAKECHROOT_CMD_SUBST=/usr/bin/mkfifo=/bin/true

sustituirá "/bin/true" por "/usr/bin/mkfifo" y hará posible instalar el paquete binario de sysvinit.

Proporcione tantos comandos sustitutos como desee, separados por ":" (dos puntos).

Se sugiere sustituir al menos:

  • "/bin/mount=/bin/true"
  • "/sbin/insserv=/bin/true"
  • "/sbin/ldconfig=/bin/true"
  • "/usr/bin/env=/usr/bin/env.fakechroot"
  • "/usr/bin/ischroot=/bin/true"
  • "/usr/bin/ldd=/usr/bin/ldd.fakechroot"
  • "/usr/bin/mkfifo=/bin/true"

para hacer debootstrap(8) funcione correctamente.

Para evitar ciertos bucles, la sustitución del comando solo se realiza si "FAKECHROOT_CMD_ORIG" variable no está establecida actualmente.

FAKECHROOT_DEBUG
La biblioteca fakechroot volcará información de depuración si esta variable está establecida.
FAKECHROOT_DETECT
Si esta variable está establecida, entonces "fakechroot versión" cadena se imprime en la salida estándar y el proceso actual se termina con el estado tomado de esta variable. Puede ser un método para comprobar si fakechroot se ha precargado correctamente. 
$ case "`FAKECHROOT_DETECT=1 /bin/echo`" in fakechroot*) echo LOADED;; esac
FAKECHROOT_ELFLOADER
Una ruta a otro enlazador dinámico (es decir, /lib/ld-linux.so.2 para la arquitectura i386, /lib64/ld-linux-x86-64.so.2 para la arquitectura x86_64).

Este enlazador dinámico se invocará directamente. El enlazador dinámico no permite cambiar "argv[0]" además del nombre de archivo del archivo ejecutable, así que algunas aplicaciones no funcionarán correctamente, es decir, busybox(1).

FAKECHROOT_EXCLUDE_PATH
La lista de directorios que quedan excluidos de ser puestos en chroot. Los elementos de la lista se separan con dos puntos.

Los /dev, /proc y /sys directorios están excluidos por defecto si esta variable de entorno no está establecida.

Esta lista debe contener como máximo 100 elementos.

FAKECHROOT_EXTRA_LIBRARY_PATH
La lista de directorios extra en el entorno de chroot falso que se añaden a "LD_LIBRARY_PATH" variable. Los directorios pueden ser utilizados por algunos comandos importantes que usan bibliotecas colocadas en el runpath. En ese caso, el enlazador dinámico no puede encontrar el directorio correcto en un entorno de chroot falso sin la ruta de biblioteca extra.

El valor por defecto es "/lib/systemd:/usr/lib/man-db" para systemctl(1) y man(1) comandos.

FAKECHROOT_VERSION
El número de versión de la biblioteca fakechroot actual.
LD_LIBRARY_PATH, LD_PRELOAD
Fakechroot se implementa envolviendo las llamadas al sistema. Esto se consigue estableciendo "LD_PRELOAD=libfakechroot.so". Si esta biblioteca no puede ser encontrada por el enlazador dinámico, el /etc/ld.so.conf archivo o "LD_LIBRARY_PATH" variable deben ser modificados.

LIMITACIONES

  • /lib/ld-linux.so.2 y /lib64/ld-linux-x86-64.so.2 son siempre cargados desde el entorno real. Esta ruta está codificada en el enlazador para todos los binarios. Puede establecer la "FAKECHROOT_ELFLOADER" variable de entorno o usar "--elfloader" opción.
  • Cada comando ejecutado dentro de fakechroot necesita estar enlazado a la misma versión del enlazador dinámico del entorno real. Si las bibliotecas en chroot no son compatibles, intente usar "--use-system-libs" opción.
  • Puede proporcionar enlaces simbólicos hacia el exterior. El enlace simbólico debe ser creado antes de que se llame a chroot. Puede ser útil para acceder al /proc y /dev directorios reales. También puede establecer "FAKECHROOT_EXCLUDE_PATH" variable de entorno: 
    $ export FAKECHROOT_EXCLUDE_PATH=/tmp:/proc:/dev:/sys:/var/run:/home
  • Los binarios enlazados estáticamente no funcionan, especialmente ldconfig(8), así que tiene que envolver este comando con una versión ficticia y establecer "FAKECHROOT_CMD_SUBST" variable de entorno.
  • ldd(1) tampoco funciona. Tiene que usar "alias ldd='LD_TRACE_LOADED_OBJECTS=1'" o usar un envoltorio en su lugar. El envoltorio se instala como ldd.fakechroot y puede usarse con "FAKECHROOT_CMD_SUBST" variable de entorno.
  • Las aplicaciones de pantalla completa se bloquean si /dev/tty archivo no es un dispositivo real. Enlace /dev/tty archivo o todo el /dev directorio al real o elimínelo del entorno de chroot falso con "FAKECHROOT_EXCLUDE_PATH" variable.
  • lckpwdf(3) y ulckpwdf(3) se ignoran así que passwd(1) comando debería funcionar
  • Su uid real debe existir en /etc/passwd. Créelo con adduser --uid realuid realuser dentro del entorno de chroot falso.
  • debuild(1) limpia el entorno. Use la opción --preserve-env para evitar este comportamiento.
  • rpmbuild(8) usa su propia glob(3) implementación que rompe fakechroot así que el directorio buildroot debe ser el mismo dentro y fuera de fakechroot.
