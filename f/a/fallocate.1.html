DESCRIPCIÓ

N

fallocate se usa para manipular el espacio en disco asignado para un archivo, ya sea para desasignarlo o preasignarlo. Para los sistemas de archivos que soportan la llamada al sistema fallocate(2), la preasignación se realiza rápidamente al asignar bloques y marcarlos como no inicializados, sin requerir E/S a los bloques de datos. Esto es mucho más rápido que crear un archivo llenándolo de

ceros.

El estado de salida devuelto por fallocate es 0 en caso de éx

ito y 1 en
caso de fallo.

OPCIONE

S

Los argumentos length y offset pueden ir seguidos de los sufijos multiplicativos KiB (=1024), MiB (=1024*1024), y así sucesivamente para GiB, TiB, PiB, EiB, ZiB, y YiB (el "iB" es opcional, por ejemplo, "K" tiene el mismo significado que "KiB") o los sufijos KB (=1000), MB (=1000*1000), y así sucesivamente para GB, TB, PB, EB, ZB, y

YB.

Las opciones --collapse-range, --dig-holes, --punch-hole, --zero-range y --posix son mutuamente

excluyentes.

-c, --collapse-rang

e
Elimina un rango de bytes de un archivo, sin dejar un hueco. El rango de bytes a colapsar comienza en offset y continúa durante length bytes. Al completarse la operación, el contenido del archivo que comienza en la ubicación offset+length se añadirá en la ubicación offset, y el archivo será length bytes más pequeño. La opción --keep-size no puede especificarse para la operación collapse-range.

Disponible desde Linux 3.15 para ext4 (solo para archivos basados en extent) y

XFS.

Un sistema de archivos puede imponer limitaciones en la granularidad de la operación, para asegurar una implementación eficiente. Típicamente, offset y length deben ser múltiplos del tamaño de bloque lógico del sistema de archivos, el cual varía según el tipo y la configuración del sistema de archivos. Si un sistema de archivos tiene tal requisito, la operación fallará con el error EINVAL si este re

quisito s
e viola.

-d, --dig-hole

s
Detecta y excava huecos. Esto hace que el archivo sea disperso en el lugar, sin usar espacio de disco extra. El tamaño mínimo del hueco depende del tamaño de bloque de E/S del sistema de archivos (usualmente 4096 bytes). Además, al usar esta opción, --keep-size está implícito. Si no se especifica un rango con --offset y --length, entonces se analiza el archivo completo en busca de huecos.

Puede pensar en esta opción como hacer un "cp --sparse" y luego renombrar el archivo de destino al original, sin necesidad de espacio de disco

extra.

Vea --punch-hole para una lista de s

istemas de arch
ivos soportados.

existentes.

No modifica la longitud aparente del archivo. Esto puede asignar efectivamente bloques más allá del EOF, los cuales pueden eliminarse con un
truncate.

t

bytes.

-p, --punch-hol

e
Desasigna espacio (es decir, crea un hueco) en el rango de bytes que comienza en offset y continúa durante length bytes. Dentro del rango especificado, los bloques parciales del sistema de archivos se ponen a cero, y los bloques completos del sistema de archivos se eliminan del archivo. Después de una llamada exitosa, las lecturas subsecuentes de este rango devolverán ceros. Esta opción no puede especificarse al mismo tiempo que la opción --zero-range. Además, al usar esta opción, --keep-size está implícito.

Soportado para XFS (desde Linux 2.6.38), ext4 (de

sde Linux 3.0), Btrfs (desde Linux 3.7), tmpfs
(desde Linux 3.5) y gfs2 (desde Linux 4.16).

-v, --verbos

e
Habilita el modo
detallado.

-x, --posi

x
Habilita el modo de operación POSIX. En ese modo la operación de asignación siempre se completa, pero puede tomar más tiempo cuando la asignación rápida no es soportada por el sistema de archivos
subyacente.

-z, --zero-rang

e
Pone a cero el espacio en el rango de bytes que comienza en offset y continúa durante length bytes. Dentro del rango especificado, se preasignan bloques para las regiones que abarcan los huecos en el archivo. Después de una llamada exitosa, las lecturas subsecuentes de este rango devolverán ceros.

El llenado con ceros se realiza dentro del sistema de archivos preferiblemente al convertir el rango en extents no escritos. Este enfoque significa que el rango especificado no será físicamente llenado con ceros en el dispositivo (excepto por bloques parciales en cada extremo del rango), y la E/S es (de otro modo) requerida solo para actualizar

metadatos.

La opción --keep-size puede especificarse para prevenir la modificación de la longitud del

archivo.

Disponible desde Linux 3.14 p

ara ext4 (solo para archivos
basados en extent) y XFS.
