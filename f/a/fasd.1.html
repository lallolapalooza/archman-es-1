NOMBRE

fasd - acceso rápido a archivos y directorios

SINOPSIS

fasd [opciones] [consulta ...]

f|a|s|d|z (#opciones) [consulta ...]

fasd [-A|-D] [rutas ...]

OPCIONES

-s         listar rutas con rangos
-l         listar rutas sin rangos
-i         modo interactivo
-e <cmd>   establecer el comando a ejecutar en el archivo resultado
-b <name>  usar solo el backend <name>
-B <name>  añadir el backend adicional <name>
-a         hacer coincidir archivos y directorios
-d         hacer coincidir solo directorios
-f         hacer coincidir solo archivos
-r         hacer coincidir solo por rango
-t         hacer coincidir solo por acceso reciente
-R         invertir el orden de la lista
-h         mostrar un breve mensaje de ayuda
-[0-9]     seleccionar la n-ésima entrada

DESCRIPCIÓN

Fasd lleva un registro de los archivos y directorios a los que accedes en tu shell y te da acceso rápido a ellos. Puedes usar fasd para referirte a archivos o directorios con solo unos pocos caracteres identificativos. Puedes usar fasd para aumentar tu productividad en la línea de comandos definiendo tus propios alias para lanzar programas sobre archivos o directorios. Fasd, de forma predeterminada, proporciona algunos alias básicos, incluyendo una función de shell "z" que se asemeja a la funcionalidad de "z" y "autojump".

El nombre "fasd" proviene de los alias sugeridos por defecto f(archivos), a(archivos/directorios), s(mostrar/buscar/seleccionar), d(directorios).

Fasd clasifica archivos y directorios por "frecuencia", es decir, tanto por "frecuencia" como por "recencia". El término "frecuencia" fue acuñado por primera vez por Mozilla y utilizado en Firefox.

EJEMPLOS

z bundle
f -e vim nginx conf
f -i rc$
vi `f nginx conf`
cp update.html `d www`
open `sf pdf`

INICIALIZACIÓN DEL SHELL

Para que fasd funcione en un shell, se debe ejecutar algo de código de inicialización. Coloca las líneas siguientes en el archivo rc de tu shell compatible con POSIX.

eval "$(fasd --init auto)"

Esto configurará un gancho de comando que se ejecutará en cada comando y una finalización avanzada por tabulación para zsh y bash.

Si quieres más control sobre lo que se incluye en tu entorno de shell, puedes pasar un conjunto personalizado de argumentos a fasd --init.

zsh-hook             # definir _fasd_preexec y añadirlo al array preexec de zsh
zsh-ccomp            # definiciones de finalización en modo comando para zsh
zsh-ccomp-install    # configurar la finalización en modo comando para zsh
zsh-wcomp            # definiciones de finalización en modo palabra para zsh
zsh-wcomp-install    # configurar la finalización en modo palabra para zsh
bash-hook            # añadir código de gancho a $PROMPT_COMMAND de bash
bash-ccomp           # definiciones de finalización en modo comando para bash
bash-ccomp-install   # configurar la finalización en modo comando para bash
posix-alias          # definir alias que se aplican a todos los shells posix
posix-hook           # configurar el gancho $PS1 para shells compatibles con posix
tcsh-alias           # definir alias para tcsh
tcsh-hook            # configurar el alias precmd de tcsh

Ejemplo para una configuración mínima de zsh (sin finalización por tabulación):

eval "$(fasd --init posix-alias zsh-hook)"

Ten en cuenta que este método aumentará ligeramente el tiempo de inicio de tu shell, ya que llamar a binarios tiene una sobrecarga. Puedes almacenar en caché el código de inicialización de fasd si quieres una sobrecarga mínima. Código de ejemplo para bash (para poner en .bashrc):

fasd_cache="$HOME/.fasd-init-bash"
if [ "$(command -v fasd)" -nt "$fasd_cache" -o ! -s "$fasd_cache" ]; then
  fasd --init posix-alias bash-hook bash-ccomp bash-ccomp-install >| "$fasd_cache"
fi
source "$fasd_cache"
unset fasd_cache

Opcionalmente, también puedes cargar fasd con source si quieres que fasd sea una función de shell en lugar de un ejecutable.

Puedes modificar el código de inicialización. Por ejemplo, si quieres usar "c" en lugar de "z" para saltar de directorio, puedes usar el siguiente alias:

alias c='fasd_cd -d'
# La opción `-d' está presente para la finalización en bash
# La función fasd_cd está definida en posix-alias

COINCIDENCIA

Fasd tiene tres modos de coincidencia: predeterminado, insensible a mayúsculas y difuso.

Para un conjunto determinado de consultas (el conjunto de argumentos de la línea de comandos pasados a fasd), una ruta coincide si y solo si:

1.
Las consultas coinciden con la ruta en orden.
2.
La última consulta coincide con el último segmento de la ruta.

Si no se encuentra ninguna coincidencia, fasd intentará el mismo proceso ignorando las mayúsculas. Si aún no se encuentra ninguna coincidencia, fasd permitirá que se coloquen caracteres extra entre los caracteres de la consulta para una coincidencia difusa.

Consejos:

•
Si quieres que tu última consulta no coincida con el último segmento de la ruta, añade `/' como la última consulta.
•
Si quieres que tu última consulta coincida con el final del nombre de archivo, añade `$' a la última consulta.

COMPATIBILIDAD

Las funcionalidades básicas de fasd son compatibles con POSIX, lo que significa que deberías poder usar fasd en todos los shells compatibles con POSIX. Tu shell necesita soportar sustitución de comandos en $PS1 para que fasd pueda rastrear automáticamente tus comandos y archivos. Esta funcionalidad no está especificada por el estándar POSIX, pero sin embargo está presente en muchos shells compatibles con POSIX. En shells sin comando de prompt o sustitución de comando de prompt (tcsh por ejemplo), puedes añadir entradas manualmente con "fasd -A". Serás muy bienvenido si contribuyes con código de inicialización de shell para shells aún no soportados.

TAB fasd(1) - Arch Linux man pages

NAME

fasd - quickly access files and directories

SYNOPSIS

fasd [OPTIONS]...

OPTIONS

-a
add a file or directory to the database
-A
add multiple files or directories to the database
-d
find a directory that matches the given expression
-f
find a file that matches the given expression
-f
find a file or directory that matches the given expression
-l
list all files and directories in the database
-L
list all files and directories in the database, with scores
-r
remove a file or directory from the database
-R
remove multiple files or directories from the database
-s
find a file or directory that matches the given expression, and print its path
-S
find a file or directory that matches the given expression, and print its path, using a space as separator
-t
show the top 10 most frequently accessed files and directories
-T
show the top 10 most frequently accessed files and directories, with scores
-u
update the database with files and directories that have been accessed
-v
print version information and exit
-h
print help message and exit

DESCRIPTION

Fasd is a command-line tool that allows you to quickly access files and directories. It keeps a database of your accessed files and directories, and provides a fast way to navigate them.

Fasd works by keeping track of the files and directories you access. It assigns a score to each file and directory based on how frequently and recently it has been accessed. The higher the score, the more likely it is that you want to access that file or directory.

Fasd can be used to quickly jump to a file or directory, or to list all files and directories that match a certain pattern.

EXAMPLES

To quickly jump to a file or directory, you can use the -a, -d, -f, or -s options.

$ fasd -a
$ fasd -d www
$ fasd -f index.html
$ fasd -s /etc/rc.local

To list all files and directories in the database, you can use the -l or -L options.

$ fasd -l
$ fasd -L

To remove a file or directory from the database, you can use the -r or -R options.

$ fasd -r index.html
$ fasd -R /var/www/

SHELL INITIALIZATION

To use fasd, you need to initialize it in your shell. Add the following lines to your shell's configuration file (e.g., ~/.bashrc or ~/.zshrc):

eval "$(fasd --init auto)"

This will enable fasd's autocompletion and command-line bindings.

MATCHING

Fasd uses a scoring algorithm to determine the best match for your queries. The scoring algorithm takes into account both the frequency and recency of file access. You can influence the matching behavior with the following options:

-i
Ignore case distinctions in patterns.
-F
Force matching of files, even if they have been deleted.
-D
Force matching of directories, even if they have been deleted.

COMPATIBILITY

Fasd is designed to be compatible with existing command-line tools and workflows. It can be used with bash, zsh, and other shells.

TAB COMPLETION

Fasd offers two completion modes, command mode completion and word mode completion. Command mode completion works in bash and zsh. Word mode completion only works in zsh.

Command mode completion is just like completion for any other commands. It is triggered when you hit tab on a fasd command or its aliases. Under this mode your queries can be separated by a space. Tip: if you find that the completion result overwrites your queries, type an extra space before you hit tab.

Word mode completion can be triggered on any command. Word completion is triggered by any command line argument that starts with "," (all), "f," (files), or "d," (directories), or that ends with ",," (all), ",,f" (files), or ",,d" (directories). Examples:

$ vim ,rc,lo<Tab>
$ vim /etc/rc.local
$ mv index.html d,www<Tab>
$ mv index.html /var/www/

There are also three zle widgets: "fasd-complete", "fasd-complete-f", "fasd-complete-d". You can bind them to keybindings you like:

bindkey '^X^A' fasd-complete     # C-x C-a to do fasd-complete (files and directories)
bindkey '^X^F' fasd-complete-f   # C-x C-f to do fasd-complete-f (only files)
bindkey '^X^D' fasd-complete-d   # C-x C-d to do fasd-complete-d (only directories)

BACKENDS

Fasd can take advantage of different sources of recent / frequent files. Most desktop environments (such as OS X and Gtk) and some editors (such as Vim) keep a list of accessed files. Fasd can use them as additional backends if the data can be converted into fasd's native format. Below is a list of available backends.

•
spotlight: OSX spotlight, provides entries that are changed today or opened within the past month
•
recently-used: GTK's recently-used file (Usually available on Linux)
•
current: Provides everything in $PWD (whereever you are executing fasd)
•
viminfo: Vim's editing history, useful if you want to define an alias just for editing things in vim

You can define your own backend by declaring a function by that name in your configuration file (#CONFIGURATION). You can set default backend with _FASD_BACKENDS variable.

CONFIGURATION

Upon every execution, fasd will look for a configuration file in the following order:

1.
$XDG_CONFIG_HOME/fasd/config
2.
$HOME/.config/fasd/config
3.
$XDG_CONFIG_DIRS/fasd/config
4.
/etc/xdg/fasd/config
5.
/etc/fasdrc and $HOME/.fasdrc (for backward compatibility)

Below are the available variables you can set:

_FASD_DATA
Path to the fasd data file, default ""$XDG_CACHE_HOME/fasd"" or ""$HOME/.cache/fasd"" if $XDG_CACHE_HOME is not set.
_FASD_BLACKLIST
List of blacklisted strings. Commands matching them will not be processed.
Default is ""--help"".
_FASD_SHIFT
List of all commands that needs to be shifted, defaults to ""sudo busybox"".
_FASD_IGNORE
List of all commands that will be ignored, defaults to ""fasd ls echo"".
_FASD_TRACK_PWD
Fasd defaults to track your "$PWD". Set this to 0 to disable this behavior.
_FASD_AWK
Which awk to use. fasd can detect and use a compatible awk.
_FASD_SINK
File to log all STDERR to, defaults to "/dev/null".
_FASD_MAX
Max total score / weight, defaults to 2000.
_FASD_SHELL
Which shell to execute. Some shells will run faster than others. fasd
runs faster with dash and ksh variants.
_FASD_BACKENDS
Default backends.
_FASD_RO
If set to any non-empty string, fasd will not add or delete entries from
database. You can set and export this variable from command line.
_FASD_FUZZY
Level of "fuzziness" when doing fuzzy matching. More precisely, the number of
characters that can be skipped to generate a match. Set to empty or 0 to
disable fuzzy matching. Default value is 2.
_FASD_VIMINFO
Path to .viminfo file for viminfo backend, defaults to "$HOME/.viminfo"
_FASD_RECENTLY_USED_XBEL
Path to XDG recently-used.xbel file for recently-used backend, defaults to
"$HOME/.local/share/recently-used.xbel"
_FASD_NOCASE
Force case insensitivity for default matching with value 1, defaults to .

DEBUGGING

Fasd is hosted on GitHub: https://github.com/clvv/fasd

If fasd does not work as expected, please file a bug report on GitHub describing the unexpected behavior along with your OS version, shell version, awk version, sed version, and a log file.

You can set _FASD_SINK in your configuration file (#configuration) to obtain a log.

_FASD_SINK="$HOME/fasd.log"
