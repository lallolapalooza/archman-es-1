DESCRIPCIÓ

N

Esta es una llamada al sistema específica de Linux y no portable. Para el método portable especificado por POSIX.1 para garantizar que se asigne espacio a un archivo, véase posix_falloca

te(3).

fallocate() permite al llamante manipular directamente el espacio en disco asignado para el archivo referenciado por fd en el rango de bytes que comienza en offset y continúa durante size by

tes.

El argumento mode determina la operación a realizar en el rango dado. Los detalles de las operaciones soportadas se indican en las subsecciones

siguientes.

Asignando espacio en

disco

La operación predeterminada (es decir, mode es cero) de fallocate() asigna el espacio en disco dentro del rango especificado por offset y size. El tamaño del archivo (según lo informado por stat(2)) se cambiará si offset+size es mayor que el tamaño del archivo. Cualquier subregión dentro del rango especificado por offset y size que no contuviera datos antes de la llamada se inicializará a cero. Este comportamiento predeterminado se asemeja mucho al comportamiento de la función de biblioteca posix_fallocate(3), y está destinado a ser un método de implementación óptima de esa

función.

Después de una llamada exitosa, se garantiza que las escrituras posteriores en el rango especificado por offset y size no fallarán por falta de espacio en

disco.

Si se especifica el indicador FALLOC_FL_KEEP_SIZE en mode, el comportamiento de la llamada es similar, pero el tamaño del archivo no se cambiará incluso si offset+size es mayor que el tamaño del archivo. Preasignar bloques con ceros más allá del final del archivo de esta manera es útil para optimizar las cargas de trabajo de

anexado.

Si se especifica el indicador FALLOC_FL_UNSHARE_RANGE en mode, los extentos de datos compartidos del archivo se harán privados para el archivo para garantizar que una escritura posterior no falle por falta de espacio. Normalmente, esto se hará realizando una operación de copia en la escritura (copy-on-write) en todos los datos compartidos en el archivo. Este indicador puede no ser soportado por todos sistemas de

archivos.

Debido a que la asignación se realiza en trozos del tamaño del bloque, fallocate() puede asignar un rango de espa

cio en disco mayor que
el especificado.

Liberando espacio de

archivo

Especificar el indicador FALLOC_FL_PUNCH_HOLE (disponible desde Linux 2.6.38) en mode libera espacio (es decir, crea un hueco) en el rango de bytes que comienza en offset y continúa durante size bytes. Dentro del rango especificado, los bloques parciales del sistema de archivos se ponen a cero, y los bloques completos del sistema de archivos se eliminan del archivo. Después de una llamada exitosa, las lecturas posteriores de este rango devolverán

ceros.

El indicador FALLOC_FL_PUNCH_HOLE debe combinarse con OR con FALLOC_FL_KEEP_SIZE en mode; en otras palabras, incluso cuando se perfora más allá del final del archivo, el tamaño del archivo (según lo informado por stat(2)) no

cambia.

No todos los sistemas de archivos soportan FALLOC_FL_PUNCH_HOLE; si un sistema de archivos no soporta la operación, se devuelve un error. La operación es soportada al menos en los siguientes sistemas de

archivos:
•
XFS (desde Linux 2.6.
38)
•
ext4 (desde Linux
3.0)
•
Btrfs (desde Linux
3.7)
•
tmpfs(5) (desde Linux
3.5)
•
gfs2(5) (d
esde L
inux
4.16)

Colapsando espacio de

archivo

Especificar el indicador FALLOC_FL_COLLAPSE_RANGE (disponible desde Linux 3.15) en mode elimina un rango de bytes de un archivo, sin dejar un hueco. El rango de bytes a colapsar comienza en offset y continúa durante size bytes. Al completarse la operación, los contenidos del archivo que comienzan en la ubicación offset+size se añadirán en la ubicación offset, y el archivo será size bytes más

pequeño.

Un sistema de archivos puede imponer limitaciones en la granularidad de la operación, para asegurar una implementación eficiente. Normalmente, offset y size deben ser múltiplos del tamaño de bloque lógico del sistema de archivos, el cual varía según el tipo y la configuración del sistema de archivos. Si un sistema de archivos tiene tal requisito, fallocate() falla con el error EINVAL si se viola este

requisito.

Si la región especificada por offset más size alcanza o pasa el final del archivo, se devuelve un error; en su lugar, use ftruncate(2) para truncar un

archivo.

No se pueden especificar otros indicadores en mode en conjunto con FALLOC_FL_COLLAPSE_RANGE

.

A partir de Linux 3.15, FALLOC_FL_COLLAPSE_RANGE es soportado por ext

4 (solo para archivos bas
ados en extentos) y XFS.

Poniendo a cero espacio de

archivo

Especificar el indicador FALLOC_FL_ZERO_RANGE (disponible desde Linux 3.15) en mode pone a cero el espacio en el rango de bytes que comienza en offset y continúa durante size bytes. Dentro del rango especificado, se preasignan bloques para las regiones que abarcan los huecos en el archivo. Después de una llamada exitosa, las lecturas posteriores de este rango devolverán

ceros.

El poner a cero se realiza dentro del sistema de archivos preferiblemente convirtiendo el rango en extentos sin escribir. Este enfoque significa que el rango especificado no se pondrá físicamente a cero en el dispositivo (excepto para bloques parciales en cualquiera de los extremos del rango), y la E/S es (de lo contrario) requerida solo para actualizar

metadatos.

Si se especifica adicionalmente el indicador FALLOC_FL_KEEP_SIZE en mode, el comportamiento de la llamada es similar, pero el tamaño del archivo no se cambiará incluso si offset+size es mayor que el tamaño del archivo. Este comportamiento es el mismo que al preasignar espacio con FALLOC_FL_KEEP_SIZE es

pecificado.

No todos los sistemas de archivos soportan FALLOC_FL_ZERO_RANGE; si un sistema de archivos no soporta la operación, se devuelve un error. La operación es soportada al menos en los siguientes sistemas de

archivos:
•
XFS (desde Linux 3.
15)
•
ext4, para archivos basados en extentos (desde Linux 3.
15)
•
SMB3 (desde Linux 3.
17)
•
Btrfs
(desde
Linux
4.16)

Aumentando espacio de

archivo

Especificar el indicador FALLOC_FL_INSERT_RANGE (disponible desde Linux 4.1) en mode aumenta el espacio del archivo insertando un hueco dentro del tamaño del archivo sin sobrescribir ningún dato existente. El hueco comenzará en offset y continuará durante size bytes. Al insertar el hueco dentro del archivo, los contenidos del archivo que comienzan en offset se desplazarán hacia arriba (es decir, a un desplazamiento de archivo mayor) en size bytes. Insertar un hueco dentro de un archivo aumenta el tamaño del archivo en size

bytes.

Este modo tiene las mismas limitaciones que FALLOC_FL_COLLAPSE_RANGE con respecto a la granularidad de la operación. Si no se cumplen los requisitos de granularidad, fallocate() falla con el error EINVAL. Si el offset es igual o mayor que el final del archivo, se devuelve un error. Para tales operaciones (es decir, insertar un hueco al final del archivo), ftruncate(2) debería

usarse.

No se pueden especificar otros indicadores en mode en conjunto con FALLOC_FL_INSERT_RANGE

.

FALLOC_FL_INSERT_RANGE requiere soporte del sistema de archivos. Los

sistemas de archivos que soportan es
ta operación incluyen XFS (desde Linu
x 4.1) y ext4 (desde Linux 4.2).
