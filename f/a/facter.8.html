NOMBRE

facter - Recopilar información del sistema

SINOPSIS

Recopila y muestra información del sistema.

USO

facter [--color] [--config] [--custom-dir DIR] [-d|--debug] [--external-dir DIR] [--help]
  [-j|--json] [--list-block-groups] [--list-cache-groups] [-l|--log-level LEVEL (=warn)]
  [--no-block] [--no-cache] [--no-color] [--no-custom-facts] [--no-external-facts]
  [--trace] [--verbose] [-v|--version] [-y|--yaml] [--strict] [hecho] [hecho] [...]

DESCRIPCIÓN

Recopila y muestra información del sistema actual. La biblioteca subyacente de Facter es fácil de extender, lo que convierte a Facter en una forma sencilla de recopilar información sobre un sistema.

Si no se proporcionan consultas, se devolverán todos los hechos.

Muchas de las opciones de línea de comandos también se pueden configurar a través del archivo de configuración HOCON. Este archivo también se puede usar para bloquear o almacenar en caché ciertos grupos de hechos.

OPCIONES

      --color                      Habilita la salida con color.
      --config                     Una ubicación personalizada para el archivo de configuración.
      --custom-dir arg             Un directorio para usar con hechos personalizados.
-d, [ --debug ]                    Habilita la salida de depuración.
      --external-dir arg           Un directorio para usar con hechos externos.
      --help                       Imprime la ayuda e información de uso.
-j, [ --json ]                     Muestra los hechos en formato JSON.
      --list-block-groups          Lista los nombres de todos los grupos de hechos que se pueden bloquear.
      --list-cache-groups          Lista los nombres de todos los grupos de hechos que se pueden almacenar en caché.
      --show-legacy                Muestra los hechos heredados al consultar todos los hechos.
-l, [ --log-level ] arg (=warn)    Establece el nivel de registro.
                                   Los niveles admitidos son: none, trace, debug,
                                   info, warn, error y fatal.
      --no-block                   Deshabilita el bloqueo de hechos.
      --no-cache                   Deshabilita el almacenamiento en caché de hechos.
      --no-color                   Deshabilita la salida con color.
      --no-custom-fact             Deshabilita los hechos personalizados.
      --no-external-facts          Deshabilita los hechos externos.
      --no-ruby                    Deshabilita la carga de Ruby, los hechos que requieren Ruby y los hechos personalizados.
      --trace                      Habilita las trazas de pila para hechos personalizados.
      --verbose                    Habilita la salida detallada (info).
-v, [ --version ]                  Imprime la versión y sale.
-y, [ --yaml ]                     Muestra los hechos en formato YAML.

ARCHIVOS

/etc/puppetlabs/facter/facter.conf
Un archivo de configuración HOCON que se puede usar para especificar directorios para hechos personalizados y externos, configurar varias opciones de línea de comandos y especificar hechos a bloquear. Consulte el ejemplo a continuación para obtener más detalles, o visite el README de GitHub.

EJEMPLO

Mostrar todos los hechos:

$ facter
disks => {
  sda => {
    model => "Virtual disk",
    size => "8.00 GiB",
    size_bytes => 8589934592,
    vendor => "ExampleVendor"
  }
}
dmi => {
  bios => {
    release_date => "06/23/2013",
    vendor => "Example Vendor",
    version => "6.00"
  }
}
[...]

Mostrar un solo hecho estructurado:

$ facter processors
{
  count => 2,
  isa => "x86_64",
  models => [
    "Intel(R) Xeon(R) CPU E5-2680 v2 @ 2.80GHz",
    "Intel(R) Xeon(R) CPU E5-2680 v2 @ 2.80GHz"
  ],
  physicalcount => 2
}

Mostrar un solo hecho anidado dentro de un hecho estructurado:

$ facter processors.isa
x86_64

Mostrar un solo hecho heredado. Tenga en cuenta que los hechos no estructurados que existían en versiones anteriores de Facter todavía están disponibles, pero no se muestran por defecto debido a la redundancia con hechos estructurados más nuevos:

$ facter processorcount
2

Formatear hechos como JSON:

$ facter --json os.name os.release.major processors.isa
{
  "os.name": "Ubuntu",
  "os.release.major": "14.04",
  "processors.isa": "x86_64"
}

Un ejemplo de archivo de configuración.

# Siempre cargado (CLI y como módulo Ruby)
global : {
    external-dir : "~/external/facts",
    custom-dir   :  [
       "~/custom/facts",
       "~/custom/facts/more-facts"
    ],
    no-external-facts : false,
    no-custom-facts   : false,
    no-ruby           : false
}
# Cargado al ejecutarse desde la línea de comandos
cli : {
    debug     : false,
    trace     : true,
    verbose   : false,
    log-level : "info"
}
# Siempre cargado, configuración específica de hechos
facts : {
    # Para entradas de lista de bloqueo válidas, use --list-block-groups
    blocklist : [ "file system", "EC2" ],
    # Para entradas de tiempo de vida (TTL) válidas, use --list-cache-groups
    ttls : [ { "timezone" : 30 days } ]
}
