NOMBRE

fakeroot - ejecuta un comando en un entorno que simula privilegios de root para la manipulación de archivos

SINOPSIS

fakeroot [-l|--lib biblioteca] [--faked binario-faked] [-i archivo-carga] [-s archivo-guardar] [-u|--unknown-is-real] [-b|--fd-base] [-h|--help] [-v|--version] [--] [comando]

DESCRIPCIÓN

fakeroot ejecuta un comando en un entorno en el que parece tener privilegios de root para la manipulación de archivos. Esto es útil para permitir a los usuarios crear archivos (tar, ar, .deb etc.) con archivos que contengan permisos/propiedad de root. Sin fakeroot, se necesitarían privilegios de root para crear los archivos constituyentes de los archivos con los permisos y propiedad correctos, y luego empaquetarlos, o se tendrían que construir los archivos directamente, sin usar el archivador.

fakeroot funciona reemplazando las funciones de la biblioteca de manipulación de archivos (chmod(2), stat(2) etc.) por otras que simulan el efecto que las funciones reales de la biblioteca habrían tenido, si el usuario hubiera sido realmente root. Estas funciones de envoltorio están en una biblioteca compartida /usr/lib/*/libfakeroot-*.so o una ubicación similar en tu plataforma. El objeto compartido se carga a través del mecanismo LD_PRELOAD del cargador dinámico. (Ver ld.so(8))

Si pretendes construir paquetes con fakeroot, por favor, intenta construir primero el paquete fakeroot: la etapa "debian/rules build" tiene algunas pruebas (probando principalmente errores en versiones antiguas de fakeroot). Si esas pruebas fallan (por ejemplo, porque tienes algunos programas libc5 en tu sistema), otros paquetes que construyas con fakeroot muy probablemente también fallarán, pero posiblemente de formas mucho más sutiles.

Además, ten en cuenta que es mejor no hacer la construcción de los binarios en sí mismos bajo fakeroot. Especialmente configure y sus similares no aprecian que el sistema se comporte de repente de manera diferente a lo que esperan (o, desconfiguran aleatoriamente algunas variables de entorno, algunas de las cuales fakeroot necesita).

OPCIONES

-l biblioteca, --lib biblioteca
Especifica una biblioteca de envoltorio alternativa.
--faked binario
Especifica un binario alternativo para usar como faked.
[--] comando
Cualquier comando que quieras que se ejecute como fakeroot. Usa ‘--’ si en el comando tienes otras opciones que puedan confundir el análisis de opciones de fakeroot.
-s archivo-guardar
Guarda el entorno de fakeroot en archivo-guardar al salir. Este archivo puede usarse para restaurar el entorno más tarde usando -i. Sin embargo, este archivo filtrará y fakeroot se comportará de manera extraña a menos que dejes los archivos tocados dentro de fakeroot en paz cuando estés fuera del entorno. Aun así, esto puede ser útil. Por ejemplo, puede usarse con rsync(1) para hacer copias de seguridad y restaurar árboles de directorios completos con información de usuario, grupo y dispositivo sin necesidad de ser root. Ver /usr/share/doc/fakeroot/README.saving para más detalles.
-i archivo-carga
Carga un entorno de fakeroot previamente guardado usando -s desde archivo-carga. Ten en cuenta que esto no guarda implícitamente el archivo, usa -s también para ese comportamiento. Usar el mismo archivo tanto para -i como para -s en una sola invocación de fakeroot es seguro.
-u, --unknown-is-real
Usa la propiedad real de los archivos previamente desconocidos para fakeroot en lugar de pretender que son propiedad de root:root.
-b fd
Especifica la base de fd (solo modo TCP). fd es el número mínimo de descriptor de archivo a usar para conexiones TCP; esto puede ser importante para evitar conflictos con los descriptores de archivo usados por los programas que se ejecutan bajo fakeroot.
-h
Muestra la ayuda.
-v
Muestra la versión.

EJEMPLOS

Aquí hay un ejemplo de sesión con fakeroot. Nota que dentro del entorno falso de root, la manipulación de archivos que requiere privilegios de root tiene éxito, pero en realidad no está sucediendo.

$  whoami
joost
$ fakeroot /bin/bash
#  whoami
root
# mknod hda3 b 3 1
# ls -ld hda3
brw-r--r--   1 root     root       3,   1 Jul  2 22:58 hda3
# chown joost:root hda3
# ls -ld hda3
brw-r--r--   1 joost    root       3,   1 Jul  2 22:58 hda3
# ls -ld /
drwxr-xr-x  20 root     root         1024 Jun 17 21:50 /
# chown joost:users /
# chmod a+w /
# ls -ld /
drwxrwxrwx  20 joost    users        1024 Jun 17 21:50 /
# exit
$ ls -ld /
drwxr-xr-x  20 root     root         1024 Jun 17 21:50 //
$ ls -ld hda3
-rw-r--r--   1 joost    users           0 Jul  2 22:58 hda3

Solo los efectos que el usuario joost podía hacer de todos modos suceden realmente.

fakeroot fue escrito específicamente para permitir a los usuarios crear paquetes de Debian GNU/Linux (en formato deb(5)) sin darles privilegios de root. Esto se puede hacer con comandos como dpkg-buildpackage -rfakeroot o debuild -rfakeroot (de hecho, -rfakeroot es el predeterminado en debuild hoy en día, por lo que no necesitas ese argumento).

ASPECTOS DE SEGURIDAD

fakeroot es un programa regular, no setuid. No mejora los privilegios de un usuario, ni disminuye la seguridad del sistema.

ARCHIVOS

/usr/lib/*/libfakeroot-*.so La biblioteca compartida que contiene las funciones de envoltorio.

ENTORNO

FAKEROOTKEY
La clave utilizada para comunicarse con el demonio de fakeroot. Cualquier programa iniciado con el LD_PRELOAD correcto y un FAKEROOTKEY de un demonio en ejecución se conectará automáticamente a ese demonio, y tendrá la misma vista "falsa" de los permisos/propiedad del sistema de archivos (asumiendo que el demonio y el programa que se conecta fueron iniciados por el mismo usuario).
LD_LIBRARY_PATH
LD_PRELOAD
fakeroot se implementa envolviendo llamadas al sistema. Esto se logra estableciendo LD_LIBRARY_PATH=/usr/lib/fakeroot y LD_PRELOAD=libfakeroot.so.0. Esa biblioteca se carga antes de la biblioteca C del sistema, y por lo tanto la mayoría de las funciones de la biblioteca son interceptadas por ella. Si necesitas establecer LD_LIBRARY_PATH o LD_PRELOAD desde dentro de un entorno de fakeroot, debe establecerse en relación con las rutas dadas, como en LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/foo/bar/

ya sea 
touch foo
fakeroot
ls -al foo

o de la otra manera,

fakeroot
touch foo
ls -al foo

fakeroot no tiene forma de saber que en el primer caso, el propietario de foo realmente debería ser joost mientras que en el segundo caso debería haber sido root. Para el empaquetado de Debian, dar por defecto a todos los archivos "desconocidos" uid=gid=0, siempre está bien. La forma real de solucionar esto es envolver open() y create(), pero eso crea otros problemas, como demuestra el paquete libtricks. Este paquete envolvía muchas más funciones, e intentaba hacer mucho más que fakeroot . Resultó que una actualización menor de libc (de una en la que la función stat() no usaba open() a una con una función stat() que sí usaba (en algunos casos) open() ), causaría fallos de segmentación inexplicables (es decir, la libc6 stat() llamaba a la open() envuelta, la cual a su vez llamaba a la libc6 stat() , etc). Arreglarlos no fue tan fácil, pero una vez arreglados, solo era cuestión de tiempo antes de que otra función empezara a usar open(), sin mencionar el intento de portarlo a un sistema operativo diferente. Así que decidí mantener el número de funciones envueltas por fakeroot lo más pequeño posible, para limitar la probabilidad de ‘colisiones’.

GNU configure (y otros programas similares)
fakeroot, en efecto, está cambiando la forma en que se comporta el sistema. Los programas que exploran el sistema como GNU configure pueden confundirse por esto (o si no lo hacen, pueden presionar tanto a fakeroot que el propio fakeroot se confunde). Por lo tanto, es aconsejable no ejecutar "configure" desde dentro de fakeroot. Como configure debería ser llamado en el objetivo "debian/rules build", ejecutar "dpkg-buildpackage -rfakeroot" se encarga correctamente de esto.

ERRORES

No envuelve open(). Esto no es malo en sí mismo, pero si un programa hace open("file", O_WRONLY, 000), escribe en el archivo "file", lo cierra, y luego intenta abrir de nuevo para leer el archivo, entonces esa apertura falla, ya que el modo del archivo será 000. El error es que si root hace lo mismo, open() tendrá éxito, ya que los permisos del archivo no se comprueban en absoluto para root. Elegí no envolver open(), ya que open() es usado por muchas otras funciones en libc (también aquellas que ya están envueltas), creando bucles (o posibles bucles futuros, cuando la implementación de varias funciones de libc cambie ligeramente).
