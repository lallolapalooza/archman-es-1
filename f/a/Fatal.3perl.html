Fatal(3perl) Guía de referencia para programadores de Perl Fatal(3perl)

NOMBRE

Fatal - Reemplaza funciones con equivalentes que tengan éxito o mueran

SINOPSIS

use Fatal qw(open close);
open(my $fh, "<", $filename);  # ¡No es necesario comprobar errores!
use File::Copy qw(move);
use Fatal qw(move);
move($file1, $file2); # ¡No es necesario comprobar errores!
sub juggle { . . . }
Fatal->import('juggle');

MEJOR PRÁCTICA

Fatal ha sido obsoleto por el nuevo pragma autodie. Por favor, usa autodie en lugar de "Fatal". autodie soporta ámbito léxico, lanza objetos de excepción reales y proporciona mensajes de error mucho más agradables.

El uso de ":void" con Fatal no es recomendable.

DESCRIPCIÓN

"Fatal" proporciona una forma conveniente de reemplazar funciones que normalmente devuelven un valor falso cuando fallan, con equivalentes que lanzan excepciones si no tienen éxito. Esto te permite usar estas funciones sin tener que comprobar sus valores de retorno explícitamente en cada llamada. Las excepciones se pueden capturar usando "eval{}". Consulta perlfunc y perlvar para obtener detalles.

Los equivalentes de "hazlo o muere" se configuran simplemente llamando a la rutina "import" de Fatal, pasándole los nombres de las funciones a reemplazar. Puedes envolver tanto funciones definidas por el usuario como operadores CORE anulables (excepto "exec", "system", "print", o cualquier otro incorporado que no pueda expresarse mediante prototipos) de esta manera.

Si el símbolo ":void" aparece en la lista de importación, entonces las funciones nombradas más tarde en esa lista de importación lanzarán una excepción solo cuando se llamen en contexto nulo, es decir, cuando se ignoren sus valores de retorno. Por ejemplo:

use Fatal qw/:void open close/;
# Comprobado correctamente, por lo que no se lanza excepción en caso de error
if (not open(my $fh, '<', '/bogotic') {
    warn "No se puede abrir /bogotic: $!";
}
# No comprobado, por lo que el error lanza una excepción
close FH;

El uso de ":void" no es recomendable, ya que puede resultar en que no se lancen excepciones si accidentalmente llamas a un método sin contexto nulo. Usa autodie en su lugar si necesitas poder deshabilitar el comportamiento de autodying/Fatal para un pequeño bloque de código.

DIAGNÓSTICOS

Nombre de subrutina incorrecto para Fatal: %s
Has llamado a "Fatal" con un argumento que no parece un nombre de subrutina, ni un interruptor que esta versión de Fatal entienda.
%s no es una subrutina de Perl
Has pedido a "Fatal" que intente reemplazar una subrutina que no existe, o que aún no se ha definido.
%s no es ni un incorporado, ni una subrutina de Perl
Has pedido a "Fatal" que reemplace una subrutina, pero no es un incorporado de Perl, y "Fatal" no pudo encontrarla como una subrutina regular. O no existe o aún no se ha definido.
No se puede hacer fatal el %s no anulable
Has intentado usar "Fatal" en un incorporado de Perl que no se puede anular, como "print" o "system", lo que significa que "Fatal" no puede ayudarte, aunque otros módulos podrían. Consulta la sección "VER TAMBIÉN" de esta documentación.
Error interno: %s
Has encontrado un error en "Fatal". Por favor, repórtalo usando el comando "perlbug".

ERRORES

"Fatal" estropea el contexto en el que se llama a una función y siempre lo convierte en un contexto escalar, excepto cuando se usa la etiqueta ":void". Este problema no existe en autodie.

Las advertencias de "usado solo una vez" pueden generarse cuando "autodie" o "Fatal" se usan con manejadores de archivo de paquete (por ejemplo, "FILE"). Se recomienda encarecidamente usar manejadores de archivo escalares en su lugar.
