val sub : t -> pos:int -> len:int -> t

sub a ~pos ~len devuelve un floatarray nuevo de longitud len, que contiene los elementos del número pos al pos + len - 1 del floatarray a.

Lanza Invalid_argument si pos y len no designan un subarray válido de a; es decir, si pos < 0, o len < 0, o pos + len > length a.

val copy : t -> t

copy a devuelve una copia de a, es decir, un floatarray nuevo que contiene los mismos elementos que a.

val fill : t -> pos:int -> len:int -> float -> unit

fill a ~pos ~len x modifica el floatarray a en el lugar, almacenando x en los elementos del número pos al pos + len - 1.

Lanza Invalid_argument si pos y len no designan un subarray válido de a.

val blit : src:t -> src_pos:int -> dst:t -> dst_pos:int -> len:int -> unit

blit ~src ~src_pos ~dst ~dst_pos ~len copia len elementos del floatarray src, comenzando en el elemento número src_pos, al floatarray dst, comenzando en el elemento número dst_pos. Funciona correctamente incluso si src y dst son el mismo floatarray, y los fragmentos de origen y destino se solapan.

Lanza Invalid_argument si src_pos y len no designan un subarray válido de src, o si dst_pos y len no designan un subarray válido de dst.

val to_list : t -> float list

to_list a devuelve la lista de todos los elementos de a.

val of_list : float list -> t

of_list l devuelve un floatarray nuevo que contiene los elementos de l.

Lanza Invalid_argument si la longitud de l es mayor que Sys.max_floatarray_length.

val for_all : f:(float -> bool) -> t -> bool

for_all ~f [|a1; ...; an|] comprueba si todos los elementos del array de flotantes satisfacen el predicado f . Es decir, devuelve (f a1) && (f a2) && ... && (f an) .

exists f [|a1; ...; an|] comprueba si al menos un elemento del array de flotantes satisface el predicado f . Es decir, devuelve (f a1) || (f a2) || ... || (f an) .

Ordenación y barajado

val sort : cmp:(float -> float -> int) -> t -> unit

Ordena un array de flotantes en orden ascendente según una función de comparación. La función de comparación debe devolver 0 si sus argumentos se comparan como iguales, un entero positivo si el primero es mayor, y un entero negativo si el primero es menor (ver más abajo para una especificación completa). Por ejemplo, compare es una función de comparación adecuada. Después de llamar a sort , el array se ordena en su lugar en orden ascendente. Se garantiza que sort se ejecuta en espacio de heap constante y (como máximo) espacio de pila logarítmico.

La implementación actual utiliza Heap Sort. Se ejecuta en espacio de pila constante.

Especificación de la función de comparación: Sea a el array de flotantes y cmp la función de comparación. Lo siguiente debe ser cierto para todos los x , y , z en a :

- cmp x y > 0 si y solo si cmp y x < 0

- si cmp x y >= 0 y cmp y z >= 0 entonces cmp x z >= 0

Cuando sort devuelve, a contiene los mismos elementos que antes, reordenados de tal manera que para todos los índices válidos i y j de a :

- cmp a.(i) a.(j) >= 0 si i >= j

val stable_sort : cmp:(float -> float -> int) -> t -> unit

Igual que Float.ArrayLabels.sort , pero el algoritmo de ordenación es estable (es decir, los elementos que se comparan como iguales se mantienen en su orden original) y no se garantiza que se ejecute en espacio de heap constante.

La implementación actual utiliza Merge Sort. Utiliza un array de flotantes temporal de longitud n/2 , donde n es la longitud del array de flotantes. Suele ser más rápido que la implementación actual de Float.ArrayLabels.sort .

val fast_sort : cmp:(float -> float -> int) -> t -> unit

Igual que Float.ArrayLabels.sort o Float.ArrayLabels.stable_sort , el que sea más rápido en entradas típicas.

val shuffle : rand:(int -> int) -> t -> unit

shuffle ~rand a permuta aleatoriamente los elementos de a utilizando rand para la aleatoriedad. La distribución de las permutaciones es uniforme.

rand debe ser tal que una llamada a rand n devuelva un número aleatorio uniformemente distribuido en el rango [ 0 ; n-1 ]. Random.int puede ser utilizado para esto (no olvides hacer Random.self_init al generador).

Arrays y seguridad ante concurrencia

Se debe tener cuidado al acceder a arrays de flotantes concurrentemente desde múltiples dominios: acceder a un array nunca provocará un bloqueo del programa, pero los accesos no sincronizados pueden producir resultados sorprendentes (no consistentes secuencialmente).

Atomicidad

Cualquier operación de array de flotantes que acceda a más de un elemento del array no es atómica. Esto incluye la iteración, el escaneo, la ordenación, la división y la combinación de arrays.

Por ejemplo, considere el siguiente programa:

let size = 100_000_000
  let a = Float.ArrayLabels.make size 1.
  let update a f () =
     Float.ArrayLabels.iteri ~f:(fun i x -> Float.Array.set a i (f x)) a
  let d1 = Domain.spawn (update a (fun x -> x +. 1.))
  let d2 = Domain.spawn (update a (fun x ->  2. *. x +. 1.))
  let () = Domain.join d1; Domain.join d2

Después de ejecutar este código, cada campo del array de flotantes a es 2. , 3. , 4. o 5. . Si se requiere atomicidad, entonces el usuario debe implementar su propia sincronización (por ejemplo, usando Mutex.t ).

Carreras de datos

Si dos dominios solo acceden a partes disjuntas del array, el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de los dos dominios.

Se dice que ocurre una carrera de datos cuando dos dominios acceden al mismo elemento del array sin sincronización y al menos uno de los accesos es una escritura. En ausencia de carreras de datos, el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de diferentes dominios.

Siempre que sea posible, se deben evitar las carreras de datos utilizando la sincronización para mediar los accesos a los elementos del array.

De hecho, en presencia de carreras de datos, los programas no fallarán pero el comportamiento observado puede no ser equivalente a ninguna intercalación secuencial de operaciones de diferentes dominios. Sin embargo, incluso en presencia de carreras de datos, una operación de lectura devolverá el valor de alguna escritura anterior en esa ubicación con algunas excepciones.

Desgarro (Tearing)

Los arrays de flotantes tienen dos advertencias suplementarias en presencia de carreras de datos.

Primero, la operación blit puede copiar un array byte por byte. Las carreras de datos entre una operación blit y otra operación pueden producir valores sorprendentes debido al desgarro: las escrituras parciales intercaladas con otras operaciones pueden crear valores de flotantes que no existirían con una ejecución secuencial.

Por ejemplo, al final de

let zeros = Float.Array.make size 0.
  let max_floats = Float.Array.make size Float.max_float
  let res = Float.Array.copy zeros
  let d1 = Domain.spawn (fun () -> Float.Array.blit zeros 0 res 0 size)
  let d2 = Domain.spawn (fun () -> Float.Array.blit max_floats 0 res 0 size)
  let () = Domain.join d1; Domain.join d2

el array de flotantes res puede contener valores que no son ni 0. ni max_float .

Segundo, en arquitecturas de 32 bits, obtener o establecer un campo implica dos accesos de memoria separados. En presencia de carreras de datos, el usuario puede observar desgarro en cualquier operación.
