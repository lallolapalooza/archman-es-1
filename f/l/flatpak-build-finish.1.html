flatpak-build-finish

- Finaliza un direc
torio de compilación

SINOPSI

S

flatpak build-finish [

OPCIÓN...]
DIRECTORIO

DESCRIPCIÓ

N

Finaliza un directorio de compilación, para prepararlo para su exportación. DIRECTORIO es el nombre del

directorio.

El resultado de este comando es que los archivos .desktop, los iconos, los archivos de servicio D-Bus y los archivos metainfo de AppStream del subdirectorio files son copiados a un nuevo subdirectorio export. En el archivo de metadatos, la clave command se establece en el grupo [Application], y las claves admitidas en el grupo [Environment] se establecen de acuerdo con las

opciones.

Como parte de la finalización, también puede especificar los permisos que la aplicación necesita, usando las diversas opciones especificadas más abajo. Adicionalmente, durante la finalización, los permisos del runtime se heredan en la aplicación a menos que usted especifique --no-inherit-permission

s

Debería revisar los archivos exportados y los metadatos de la aplicación antes de crear y distribuir un paquete de aplicación (bundle)

.

Es un error ejecutar build-finish en un directori

o que no ha sido inicializado como un direct
orio de compilación, o que ya ha sido finalizado.

OPCIONE

S

Se entienden las siguientes

opciones:

-h, --hel

p
Muestra las opciones de ayuda y
sale.

--command=COMAND

O
El comando a usar. Si esta opción no se especifica, se usa el primer ejecutable encontrado en files/bin.

Tenga en cuenta que el comando se usa cuando la aplicación se ejecuta mediante flatpak run, y no afecta a lo que se ejecuta cuando la aplicación se ejecuta de ot

ras maneras, por ejemplo, a través del arc
hivo .desktop o la activación de D-Bus.

--require-version=MAJOR.MINOR.

MICRO
Requiere esta versión o posterior de flatpak para instalar/actualizar a esta
compilación.

--share=SUBSISTEM

A
Comparte un subsistema con la sesión del host. Esto actualiza el grupo [Context] en los metadatos. SUBSISTEMA debe ser uno de: network, ipc. Esta opción se puede usar varias
veces.

--unshare=SUBSISTEM

A
No comparte un subsistema con la sesión del host. Esto actualiza el grupo [Context] en los metadatos. SUBSISTEMA debe ser uno de: network, ipc. Esta opción se puede usar varias
veces.

--socket=SOCKE

T
Expone un socket de nombre bien conocido a la aplicación. Esto actualiza el grupo [Context] en los metadatos. SOCKET debe ser uno de: x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Esta opción se puede usar varias veces.

La opción fallback-x11 hace que el socket X11 esté disponible solo si no hay un socket Wayland. Est

a opción se introdujo en la versión 0.11.3. Para admitir versiones anteriores de Flatpak, especifiqu
e tanto x11 como fallback-x11. La opción fallback-x11 tiene prioridad cuando ambas son compatibles.

--nosocket=SOCKE

T
No expone un socket de nombre bien conocido a la aplicación. Esto actualiza el grupo [Context] en los metadatos. SOCKET debe ser uno de: x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Esta opción se puede usar varias
veces.

--device=DISPOSITIV

O
Expone un dispositivo a la aplicación. Esto actualiza el grupo [Context] en los metadatos. DISPOSITIVO debe ser uno de: dri, input, usb, kvm, shm, all. Esta opción se puede usar varias
veces.

--nodevice=DISPOSITIV

O
No expone un dispositivo a la aplicación. Esto actualiza el grupo [Context] en los metadatos. DISPOSITIVO debe ser uno de: dri, input, usb, kvm, shm, all. Esta opción se puede usar varias
veces.

--allow=CARACTERÍSTIC

A
Permite el acceso a una característica específica. Esto actualiza el grupo [Context] en los metadatos. CARACTERÍSTICA debe ser una de: devel, multiarch, bluetooth, canbus, per-app-dev-shm. Esta opción se puede usar varias veces.

La característica devel permite a la aplicación acceder a ciertas llamadas al sistema como ptrace() y perf_event_open()

.

La característica multiarch permite a la aplicación ejecutar programas compilados para una ABI distinta de la que el sistema admite de forma nativa. Por ejemplo, para la arquitectura x86_64, también se permitirán binarios x86 de 32

bits.

La característica bluetooth permite a la aplicación usar sockets bluetooth (AF_BLUETOOTH). Tenga en cuenta que para que el bluetooth funcione completamente, también debe tener acceso a la

red.

La característica canbus permite a la aplicación usar sockets canbus (AF_CAN). Tenga en cuenta que para que esto funcione, también debe tener acceso a la

red.

La característica per-app-dev-shm comparte una única instancia de /dev/shm entre la a

plicación, cualquier subcaja de sandbox (subsandbox) sin restricciones que cree, y cu
alquier otra instancia de la aplicación que se lance mientras ella está en ejecución.

--disallow=CARACTERÍSTIC

A
No permite el acceso a una característica específica. Esto actualiza el grupo [Context] en los metadatos. CARACTERÍSTICA debe ser una de: devel, multiarch, bluetooth, canbus, per-app-dev-shm. Esta opción se puede usar varias
veces.

--filesystem=F

S
Permite a la aplicación acceder a un subconjunto del sistema de archivos. Esto actualiza el grupo [Context] en los metadatos. FS puede ser uno de: home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, xdg-run, xdg-config, xdg-cache, xdg-data, una ruta absoluta, o una ruta relativa al directorio personal como ~/dir o rutas relativas a los directorios xdg, como xdg-download/subdir. El sufijo opcional :ro indica que la ubicación será de solo lectura. El sufijo opcional :create indica que la ubicación será de lectura y escritura y se creará si no existe. Esta opción se puede usar varias veces. Vea la lista "[Context] filesystems" en flatpak-metadata(5) para detalles sobre el significado de estos sistemas de
archivos.

--nofilesystem=SISTEMA-DE-ARCHIVO

S
Elimina el acceso al subconjunto especificado del sistema de archivos de la aplicación. Esto anula la sección Context de los metadatos de la aplicación. SISTEMA-DE-ARCHIVOS puede ser uno de: home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, una ruta absoluta, o una ruta relativa al directorio personal como ~/dir. Esta opción se puede usar varias
veces.

--add-policy=SUBSISTEMA.

CLAVE=VALOR
Añade una opción de política genérica. Por ejemplo, "--add-policy=subsystem.key=v1 --add-policy=subsystem.key=v2" se mapearía a estos metadatos: 
[Policy su
bsystem]
key=v1;v2;

Esta opción s

e puede usar
varias veces.

--remove-policy=SUBSISTEMA.

CLAVE=VALOR
Elimina una opción de política genérica. Esta opción se puede usar varias
veces.

--usb=TIPO[:

DATOS]
Hace que los dispositivos USB que coincidan con la consulta sean visibles para el portal USB al añadir la consulta a los metadatos de la aplicación. Esto no tiene ningún efecto sobre los dispositivos expuestos en /dev. TIPO debe ser uno de: all, cls, dev, vnd.

al

l
Coincide con todos los
dispositivos.

cl

s
Una consulta de clase y subclase de dispositivo. DATOS debe estar en el formato CLASE:SUBCLASE donde tanto CLASE como SUBCLASE deben ser números de identificación de clase hexadecimales válidos de 2 dígitos. Alternativamente, SUBCLASE puede ser * para coincidir con todas las
subclases.

de

v
Una consulta de id de producto del dispositivo. DATOS debe ser un número de id de producto hexadecimal válido de 4 caracteres, por ejemplo 0a1b. Requiere un filtro vnd en la
consulta.

vn

d
Una consulta de id de vendedor del dispositivo. DATOS debe ser un número de id de vendedor hexadecimal válido de 4 caracteres mayor que cero, por ejemplo 0fab
.

Es posible componer múltiples consultas de dispositivo con el signo +, por ejemplo --usb=vnd:0123+dev:4567. El filtro dev requi

ere un vnd. Disponible d
esde la versión 1.15.11.

--nousb=TIPO[:

DATOS]
Oculta los dispositivos USB que coincidan con la consulta del portal USB al añadir la consulta a los metadatos de la aplicación. Las consultas que ocultan dispositivos tienen prioridad sobre las consultas que hacen visibles los dispositivos (vea --usb). La sintaxis es exactamente igual a la de --usb. Esto no tiene ningún efecto sobre los dispositivos expuestos en /dev. Disponible desde la versión 1.15.
11.

--usb-list-file=NOMBRE-DE-ARCHIV

O
Añade consultas de dispositivos USB a los metadatos de la aplicación desde el archivo NOMBRE-DE-ARCHIVO. La sintaxis de la línea es exactamente igual a la de --usb. Adicionalmente, si comienza con !, entonces la consulta es como para --nousb. Las líneas que comienzan con # se ignoran, como un comentario. Los comentarios no se guardarán. Disponible desde la versión 1.15.11.

--usb-list=LIST

Agrega consultas de dispositivos USB a los metadatos de la aplicación de LIST. La sintaxis es exactamente igual a --usb con consultas separadas por ;. Además, si la consulta comienza con ! entonces la consulta es como para --nousb. Disponible desde la versión 1.15.11.

--env=VAR=VALOR

Establece una variable de entorno en la aplicación. Esto actualiza el grupo [Environment] en los metadatos. Esto anula la sección [Context] de los metadatos de la aplicación. Esta opción se puede usar varias veces.

--unset-env=VAR

Anula una variable de entorno en la aplicación. Esto actualiza la entrada unset-environment en el grupo [Context] de los metadatos. Esta opción se puede usar varias veces.

--env-fd=FD

Lee variables de entorno del descriptor de archivo FD, y las establece como si fuera a través de --env. Esto se puede usar para evitar que las variables de entorno y sus valores sean visibles para otros usuarios.

Cada variable de entorno tiene el formato VAR=VALOR seguido de un byte cero. Este es el mismo formato que usan env -0 y /proc/*/environ.

--own-name=NOMBRE

Permite que la aplicación posea el nombre conocido NAME en el bus de sesión. Si NAME termina con .*, permite que la aplicación posea todos los nombres coincidentes. Esto actualiza el grupo [Session Bus Policy] en los metadatos. Esta opción se puede usar varias veces.

--talk-name=NOMBRE

Permite que la aplicación hable con el nombre conocido NAME en el bus de sesión. Si NAME termina con .*, permite que la aplicación hable con todos los nombres coincidentes. Esto actualiza el grupo [Session Bus Policy] en los metadatos. Esta opción se puede usar varias veces.

--system-own-name= NOMBRE

Permite que la aplicación posea el nombre conocido NAME en el bus del sistema. Si NAME termina con .*, permite que la aplicación posea todos los nombres coincidentes. Esto actualiza el grupo [System Bus Policy] en los metadatos. Esta opción se puede usar varias veces.

--system-talk-name= NOMBRE

Permite que la aplicación hable con el nombre conocido NAME en el bus del sistema. Si NAME termina con .*, permite que la aplicación hable con todos los nombres coincidentes. Esto actualiza el grupo [System Bus Policy] en los metadatos. Esta opción se puede usar varias veces.

--persist=NOMBREARCHIVO

Si la aplicación no tiene acceso al directorio principal real, convierte la ruta (relativa al directorio principal) NOMBREARCHIVO en un montaje bind al camino correspondiente en el directorio por aplicación, lo que permite que esa ubicación se utilice para datos persistentes. Esto actualiza el grupo [Context] en los metadatos. Esta opción se puede usar varias veces.

--runtime=RUNTIME, --sdk=SDK

Cambia el runtime o sdk utilizado por la aplicación a la referencia parcial especificada. Las partes no especificadas de la referencia se toman de los valores antiguos o de los predeterminados.

--metadata=GRUPO=CLAVE[=VALOR]

Establece una clave genérica en el archivo de metadatos. Si se omite el valor, se establecerá como "true".

--extension=NOMBRE=VARIABLE[=VALOR]

Agrega información del punto de extensión. Consulte la documentación de flatpak-metadata(5) para conocer los posibles valores de VARIABLE y VALOR.

--remove-extension=NOMBRE

Elimina información del punto de extensión.

--extension-priority=VALOR

Establece la prioridad (orden de anulación de bibliotecas) del punto de extensión. Solo útil para extensiones. 0 es el valor predeterminado, y un valor más alto significa una prioridad más alta.

--extra-data=NOMBRE:SHA256:TAMANO-DESCARGA:TAMANO-INSTALACION:URL

Agrega información sobre las URIs de datos adicionales a la aplicación. Estos serán descargados y verificados por el cliente cuando se instale la aplicación y se colocarán en el directorio /app/extra. También puedes proporcionar un script /app/bin/apply_extra que se ejecutará después de que los archivos se descarguen.

--no-exports

No busques exportaciones en la compilación.

--no-inherit-permissions

No heredes los permisos de tiempo de ejecución en la aplicación.

-v, --verbose

Imprime información de depuración durante el procesamiento del comando.

--ostree-verbose

Imprime información de depuración de OSTree durante el procesamiento del comando.
