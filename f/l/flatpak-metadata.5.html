DESCRIPCIÓ

N

Flatpak utiliza archivos de metadatos para describir aplicaciones y entornos de ejecución. El archivo de metadatos de una aplicación o un entorno de ejecución desplegado se coloca en el directorio de despliegue de nivel superior. Por ejemplo, los metadatos de la aplicación instalada localmente org.gnome.Calculator se encuentran en ~/.local/share/flatpak/app/org.gnome.Calculator/current/active/metadata

.

La mayoría de los aspectos de la configuración de los metadatos pueden anularse al lanzar aplicaciones, ya sea temporalmente mediante opciones del comando flatpak run o permanentemente con el comando flatpak

override.

Un archivo de metadatos que describe la configuración efectiva está disponible dentro

del sandbox en ejecución en /.flatpak-info. Por compatibilidad con versiones anteri
ores de Flatpak, /run/user/$UID/flatpak-info es un enlace simbólico al mismo archivo.

ARCHIVO

El archivo de metadatos utiliza el mismo formato de archivo .ini que se usa para los archivos de unidad de systemd o los archivos .desktop de las

aplicaciones.

[Session Bus

Policy]

Si la clave sockets no permite acceso completo al bus de sesión D-Bus, entonces flatpak proporciona acceso

filtrado.

La política predeterminada para el bus de sesión solo permite a la aplicación ser propietaria de su propio ID de aplicación, sus subnombres y su propio ID de aplicación como subnombre de org.mpris.MediaPlayer2. Por ejemplo, si la aplicación se llama org.my.App, solo puede ser propietaria de org.my.App, org.my.App.* y org.mpris.MediaPlayer2.org.my.App. Solo se le permite comunicarse con nombres que coincidan con esos patrones, más el propio bus (org.freedesktop.DBus) y las APIs de portal (nombres de bus de la forma org.freedesktop.portal.*)

.

Además, a la aplicación siempre se le permite responder a los mensajes enviados a ella y emitir señales de difusión (pero estas no llegarán a otras aplicaciones en sandbox a menos que se les permita comunicarse con tu

aplicación.

Si el grupo [Session Bus Policy] está presente, proporciona la política para el acceso al bus de

sesión.

Cada clave en este grupo tiene la forma de un nombre de bus D-Bus o un prefijo del mismo, por ejemplo org.gnome.SessionManager o org.freedesktop.p

ortal.*.

Los valores posibles para una entrada son los siguientes, en orden creciente de acceso. Cada valor implica todo el acceso de cualquier valor

inferior:

non

e
El nombre de bus es invisible para la aplicación. Disponible desde 0.
2.

se

e
El nombre de bus puede ser enumerado por la aplicación. Disponible desde 0.
2.

tal

k
La aplicación puede enviar mensajes a, y recibir respuestas y señales de, el nombre de bus. Disponible desde 0.
2.

ow

n
La aplicación puede ser propietaria del nombre de bus. Disponible desde
0.
2.

Policy]

Las entradas en este grupo tienen la misma forma que en el grupo [Session Bus Policy]. Sin embargo,

la aplicación no tiene

[Extension

Los usos típicos de los puntos de extensión incluyen traducciones para aplicaciones, o debuginfo para sdks. El nombre del punto de extensión se especifica como parte del encabezado del grupo. [USB

Devices]

Los dispositivos USB pueden ser enumerables u ocultos por el portal USB según lo especificado por las claves en este grupo. Los IDs de proveedor y producto son validados por Flatpak, pero no se usan ni se analizan de otra manera. Esto simplemente otorga el permiso para enumerar dispositivos USB para su uso por el portal. Esto no da acceso a los dispositivos. Disponible desde 1.15.

11.
