FLUXBOX-APPS(5) Manual de Fluxbox FLUXBOX-APPS(5)

NOMBRE

fluxbox-apps - configuración de atributos por ventana para fluxbox(1)

SINOPSIS

~/.fluxbox/apps

SINTAXIS

Los parámetros variables se muestran en énfasis: argumento

El resto de los caracteres mostrados son requeridos textualmente. El espacio en blanco solo es necesario para delimitar palabras, pero está bien añadir más espacio en blanco.

DESCRIPCIÓN

Es posible forzar que una aplicación tenga siempre las mismas dimensiones, posición y otras configuraciones cuando se inicia por primera vez. Estas configuraciones se guardan en el archivo 'apps'.

La mayoría de las configuraciones sencillas se pueden guardar utilizando el submenú "Recordar..." del menú de ventanas, que generalmente se puede abrir haciendo clic derecho en la barra de título. Las funciones más avanzadas requieren editar manualmente el archivo 'apps'. Esto puede incluir el uso de SECCIONES DE GRUPO para configurar grupos de pestañas de ventanas automáticas.

No es necesario "recargar" fluxbox después de editar el archivo apps, los cambios se volverán a escanear cuando se abra la siguiente ventana.

El archivo está compuesto por dos tipos principales de secciones, aplicaciones y grupos, detallados a continuación.

SECCIONES DE APLICACIONES

Las secciones [app] proporcionan configuraciones para ventanas de aplicaciones individuales.

Estas secciones comienzan con una línea del formato

[app](patrón){conteo}

El patrón puede ser uno o más patrones que coincidan con ventanas. Para más detalles, ver PATRONES DE CLIENTE. Si especifica más de un patrón, TODOS deben coincidir para que se apliquen las configuraciones.

El {conteo} es opcional. Si se especifica, la entrada solo coincidirá como máximo con esa cantidad de ventanas en cualquier momento. Si se omite, el valor predeterminado es aplicar las configuraciones a todas las ventanas coincidentes.

Esta línea de apertura [apps] va seguida de cualquier número de configuraciones para la aplicación. Ver CONFIGURACIONES para más detalles.

Cada una de estas secciones termina con la única línea

[end]

SECCIONES TRANSITORIAS

Las secciones [transient] proporcionan configuraciones para "diálogos".

Esto es lo mismo que la sección [app], pero se aplica a ventanas transitorias. Las ventanas transitorias tienen una propiedad WM_TRANSIENT_FOR. Esto se aplicará a todos los diálogos modales y a varios otros diálogos que tengan un "líder" al que permanecen encima. Notablemente, los diálogos de abrir/guardar entran en esta categoría.

SECCIONES DE GRUPO

El propósito principal de las secciones [group] es agrupar ventanas. Todas las ventanas de un grupo se colocarán automáticamente en pestañas.

Estas secciones comienzan con una línea del formato

[group](patrón)

Donde el elemento patrón es opcional. Si se especifica, este patrón debe coincidir para que el grupo tenga efecto. Es común usar patrones no específicos de ventana como (workspace) aquí. Ver PATRONES DE CLIENTE para más detalles.

Esto va seguido de cualquier número de líneas [app]. Estas tienen un formato similar a la sección [app] detallada arriba en SECCIONES DE APLICACIONES, pero no contienen ninguna configuración y no tienen una línea [end] asociada.

Como esto

[app](patrón)

Esta sección también puede contener configuraciones que se aplican a cada ventana del grupo. Ver la sección CONFIGURACIONES para detalles.

Al igual que con las secciones [app], cada una de estas secciones termina con la única línea

[end]

CONFIGURACIONES

Estas configuraciones pueden guardarse en el archivo 'apps'. Una línea de configuración debe aparecer dentro de una sección [app] o [group].

El formato general es

[configuración]{valor}

Todos los valores permitidos se describen a continuación, excepto bool que simplemente puede tener el valor yes o no, que activa o desactiva la configuración asociada, respectivamente.

[Workspace] {número}

Fuerza que la aplicación se abra en el espacio de trabajo número especificado. Los espacios de trabajo se establecen por número, comenzando desde 0.

[Jump] {bool}

Cambia el espacio de trabajo activo al recordado cuando se abre la aplicación. Esto solo es útil cuando se usa junto con [Workspace]. Ver EJEMPLOS.

[Head] {número}

Fuerza que la aplicación se abra en la pantalla número especificada (solo Xinerama).

[Layer] {número}

Especifica la capa en la que se abrirá la ventana (por número). Cada capa tiene un número. Las nombradas son: 2-AboveDock, 4-Dock, 6-Top, 8-Normal, 10-Bottom, 12-Desktop.

[Dimensions] {ancho[%] alto[%]}

Abre la aplicación con el ancho y alto especificados, en píxeles. Si el valor se da en porcentaje, el tamaño de la ventana se basará en el tamaño de la pantalla actual.

[IgnoreSizeHints] {bool}

Algunas aplicaciones restringen la relación de aspecto, el tamaño mínimo o máximo de las ventanas. Establecer esta clave a "yes" hará que fluxbox ignore esas restricciones. AVISO que las implementaciones de clientes deficientes pueden depender fuertemente de estas restricciones (al usar ciegamente su geometría en cálculos incorrectos, causando divisiones por cero, caídas, etc.)

[Position] (ancla) {X[%] Y[%]}

Posiciona la aplicación en un lugar particular. Por defecto, la esquina superior izquierda se coloca en las coordenadas de pantalla (X, Y). Si especifica un ancla, por ejemplo BottomRight, entonces la esquina inferior derecha de la ventana se posiciona (X, Y) píxeles desde la esquina inferior derecha de la pantalla. Si el valor se da en porcentaje, las coordenadas se basarán en el tamaño de la pantalla actual.

ancla puede configurarse a uno de:

TopLeft Left BottomLeft Top Center Bottom TopRight Right BottomRight

[Deco] {valor}

Especifica el estado de la decoración. Hay varios conjuntos de valor predefinidos:

NORMAL

Decoraciones estándar

NONE

Sin decoraciones

BORDER

Como NONE excepto que se mantiene el borde de la ventana X

TAB

Como BORDER excepto que se mantienen las pestañas externas (si están habilitadas)

TINY

Barra de título con solo un botón de minimizar

TOOL

Solo barra de título

El valor también puede ser una máscara de bits para un control más detallado. Los bits son, de (1<<0) a (1<<10): Barra de título, Mango/Agarres, Borde, Botón de Minimizar, Botón de Maximizar, Botón de Cerrar, Botón de Menú, Botón de Fijar, Botón de Sombrear, Pestañas Externas, Habilitado para Enfoque.

[Shaded] {bool}

Si la ventana está sombreada (plegada) o no.

[Tab] {bool}

Si la ventana tiene pestañas habilitadas.

[FocusNewWindow] {bool}

¡OBSOLETO! Use FocusProtection "Gain" o "Refuse" en su lugar.

Si está habilitado, una nueva ventana obtendrá el foco X tan pronto como se abra. Si está deshabilitado, una nueva ventana no obtendrá el foco X tan pronto como se abra.

CLIENTES

Un patrón se ve

así
([propertyname[!]=]regexp) ..
.

Las definiciones de coincidencia se encierran entre paréntesis (...), y si no se da ningún propertyname, se asume Name. El regexp puede contener cualquier expresión regular, o el valor especial [current], que coincide con el valor correspondiente de la ventana actualmente enfocada. Vea regex(7) para más información sobre las expresiones regulares

aceptables.

propertyname no distingue entre mayúsculas y minúsculas, mientras que regexp

sí.

Si especifica múltiples (patrón) argumentos, esto implica una condión AND - Todos los patrones especificados deben

coincidir.

Puede usar = para probar igualdad o != para probar

desigualdad.
