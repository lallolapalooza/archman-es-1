FLATPAK-BUILDER(1) constructor de flatpak FLATPAK-BUILDER(1)

NOMBRE

flatpak-builder - Ayuda a construir dependencias de aplicaciones

SINOPSIS

flatpak-builder [OPCIÓN...] DIRECTORIO MANIFIESTO

flatpak-builder --run [OPCIÓN...] DIRECTORIO MANIFIESTO COMANDO

flatpak-builder --show-deps [OPCIÓN...] MANIFIESTO

flatpak-builder --show-manifest [OPCIÓN...] MANIFIESTO

DESCRIPCIÓN

flatpak-builder es un envoltorio alrededor del comando build de flatpak que automatiza la construcción de aplicaciones y sus dependencias. Es una opción que puede usar para construir aplicaciones.

El objetivo de flatpak-builder es trasladar tanto conocimiento sobre cómo construir módulos a los proyectos individuales upstream. Lo hace asumiendo que los módulos se adhieren a la API de Construcción especificada en https://github.com/cgwalters/build-api. Esto esencialmente significa que sigue el esquema ./configure && make && make install con un script autogen opcional. Si el upstream no se adhiere a la API, puede hacer que lo haga añadiendo parches y archivos adicionales.

Una invocación de flatpak-builder procede en estas etapas, cada una especificada en detalle en formato json en el MANIFIESTO:

•Descargar todas las fuentes
•Inicializar el directorio de la aplicación con flatpak build-init
•Construir e instalar cada módulo con flatpak build
•Limpiar el árbol de construcción final eliminando archivos no deseados y, por ejemplo, depurando los binarios
•Finalizar el directorio de la aplicación con flatpak build-finish

Después de esto, obtendrá una compilación de la aplicación en el DIRECTORIO, que puede exportar a un repositorio con el comando build-export de flatpak . Si usa la opción --repo , flatpak-builder hará la exportación por usted al final del proceso de construcción. Cuando flatpak-builder hace la exportación, también almacena el manifiesto que se usó para la construcción en /app/manifest.json. El manifiesto está 'resuelto', es decir, los nombres de las ramas git se reemplazan por los IDs de commit reales que se usaron en la construcción.

En cada uno de los pasos anteriores, flatpak almacena en caché el resultado, y si construye el mismo archivo de nuevo, comenzará en el primer paso donde algo cambia. Por ejemplo, la primera fuente controlada por versiones a la que se le añadieron nuevos commits, o el primer módulo donde algunos cambios en el archivo MANIFIESTO hicieron que el entorno de construcción cambiara. Esto hace que flatpak-builder sea muy eficiente para construcciones incrementales.

Al construir un flatpak para publicarlo en Internet, --collection-id=ID-DE-COLECCIÓN debe especificarse como un valor DNS inverso globalmente único para identificar la colección de flatpaks a la que se añadirá. Establecer un ID de colección globalmente único permite que las aplicaciones en el repositorio se compartan a través de sistemas de igual a igual sin necesidad de configuración adicional.

MANIFIESTO

El archivo manifiesto es un archivo json o yaml cuyo formato se describe en detalle en su propia página de manual.

OPCIONES

Se entienden las siguientes opciones:

-h, --help

Muestra las opciones de ayuda y sale.

-v, --verbose

Imprime información de depuración durante el procesamiento del comando.

--version

Imprime información de la versión y sale.

--arch=ARQUITECTURA

Especifica la arquitectura de la máquina para la que construir. Si no se especifica ninguna arquitectura, la arquitectura del host se detectará automáticamente. Solo se pueden especificar arquitecturas compatibles con el host.

--default-branch=RAMA

Establece la rama predeterminada en RAMA. Esto se usa si el manifiesto no especifica una rama. El valor predeterminado es master.

--disable-cache

No buscar en la caché existente una construcción anterior, en su lugar, reconstruir siempre los módulos.

--disable-rofiles-fuse

Desactiva el uso de rofiles-fuse para optimizar el uso de la caché a través de comprobaciones de enlaces duros.

--disable-download

No descargar ninguna fuente. Esto solo funciona si alguna versión de todas las fuentes ya se ha descargado. Esto es útil si quiere garantizar que no se realice ninguna e/s de red. Sin embargo, la construcción fallará si alguna fuente no está disponible localmente.

--disable-updates

Descargar fuentes faltantes, pero no actualizar los espejos locales de los repositorios de control de versiones. Esto es útil para reconstruir cosas pero sin actualizar los repositorios git, bzr o svn desde el repositorio remoto.

--disable-tests

No ejecutar ninguna de las pruebas.

--run

Ejecutar un comando en un entorno aislado basado en el directorio de construcción. Esto inicia flatpak build, con algunos argumentos adicionales para dar el mismo entorno que la construcción, y los mismos permisos que la aplicación final tendrá (excepto los permisos de sistema de archivos). El comando a ejecutar debe ser el último argumento pasado a flatpak-builder, después del directorio y el manifiesto.

Solo las opciones --arch=ARQUITECTURA, --ccache y --verbose pueden combinarse con esta opción.

--build-shell=NOMBREMÓDULO

Extraer y preparar las fuentes para el módulo nombrado, y luego iniciar un shell en un entorno aislado idéntico al que flatpak-builder usaría para construir el módulo. Esto es útil para depurar un módulo.

--show-deps

Listar todos los archivos (locales) de los que depende el manifiesto.

Solo la opción --verbose puede combinarse con esta opción.

--show-manifest

Carga el manifiesto, incluyendo cualquier archivo incluido, y lo imprime en un formato json canónico. Esto es útil para herramientas que quieren manejar archivos manifiesto para evitar tener que soportar tanto yaml como json, así como algo del manejo de json no estándar que se soporta (por ejemplo, comentarios y cadenas multilínea).

Solo la opción --verbose puede combinarse con esta opción.

--download-only

Sale con éxito después de descargar las fuentes requeridas.

--bundle-sources

Crea un runtime adicional con el código fuente para este módulo. Se llamará app-id.Sources, por ejemplo org.gnome.Maps.Sources.

--build-only

No realizar las etapas de limpieza y finalización, lo cual es útil si quiere construir más cosas en la aplicación.

--finish-only

Realizar solo las etapas de limpieza, finalización y exportación, retomando donde lo dejó un comando --build-only.

--export-only

Realizar solo las etapas de exportación, retomando el resultado de la construcción de una construcción anterior. Esto se puede usar para dividir la construcción y la exportación/firma en dos llamadas omitiendo --repo en la primera llamada.

--require-changes

No hacer nada, dejando un DIRECTORIO inexistente si nada cambia desde la última construcción en caché. Si esto no se especifica, la última versión de la caché se pondrá en el DIRECTORIO.

--state-dir=RUTA

Usar este directorio para almacenar el estado (descargas, directorios de construcción, caché de construcción, etc) en lugar de .flatpak-builder. Esta puede ser una ruta absoluta o relativa, pero debe estar en el mismo sistema de archivos que el DIRECTORIO de destino especificado.

--keep-build-dirs

No eliminar las fuentes y la construcción después de haber construido e instalado cada módulo. Esto también crea un enlace simbólico al directorio de construcción con un nombre estable ("build-nomdeldemódulo").

--delete-build-dirs

Eliminar siempre las fuentes y la construcción después de haber construido cada módulo, incluso si la construcción falló. El valor predeterminado es mantener los directorios de construcción fallidos pero eliminar los exitosos. Esto es útil en, por ejemplo, sistemas de construcción automáticos.

--ccache

Habilitar el uso de ccache en la construcción (necesita ccache en el sdk). La carpeta predeterminada de ccache se puede sobreescribir estableciendo la variable de entorno CCACHE_DIR.

--stop-at=NOMBREMÓDULO

Detenerse en el módulo especificado, ignorándolo y todos los siguientes en las fases de "descarga" y "construcción". Esto es útil para depuración y desarrollo. Por ejemplo, puede construir todas las dependencias, pero detenerse en la aplicación principalion para que luego puedas realizar una compilación desde una copia de trabajo preexistente. Implica --build-only.

--repo=DIR

Cuando la compilación finalice, ejecuta flatpak build-export para exportar el resultado al repositorio DIR. Si DIR existe, debe ser un repositorio OSTree; de lo contrario, se creará uno nuevo.

-s, --subject=SUBJECT

Asunto de una línea para el mensaje de confirmación. Se usa al exportar los resultados de la compilación.

-b, --body=BODY

Descripción completa para el mensaje de confirmación. Se usa al exportar los resultados de la compilación.

--collection-id=COLLECTION-ID

Establece el ID de colección del repositorio. Establecer un ID de colección globalmente único permite que las aplicaciones del repositorio se compartan a través de sistemas de igual a igual sin necesidad de configuración adicional. Si se compila en un repositorio existente, el ID de colección debe coincidir con el ID de colección configurado existente para ese repositorio.

--token-type=VAL

Establece el tipo de token necesario para instalar esta confirmación. Establecer esto en un valor mayor que 0 implica que se necesitará autenticación para instalar el flatpak. Una token-type propiedad establecida en el manifiesto tiene prioridad sobre esta opción. Se usa al exportar los resultados de la compilación.

--gpg-sign=KEYID

Firma la confirmación con esta clave GPG. Se usa al exportar los resultados de la compilación. Esta opción se puede usar varias veces.

--gpg-homedir=PATH

Directorio personal de GPG a usar al buscar anillos de claves. Se usa al exportar los resultados de la compilación.

--jobs=JOBS

Limita el número de trabajos paralelos durante la compilación. El valor predeterminado es el número de CPU en la máquina.

--force-clean

Borra el contenido anterior de DIRECTORY si no está vacío. Desde la versión 1.4.6, se rechazará el borrado si DIRECTORY es el directorio de trabajo actual, el directorio de estado o cualquiera de sus directorios superiores.

--sandbox

Desactiva la posibilidad de especificar build-args que se pasan a flatpak build. Esto significa que el proceso de compilación no puede salir de su entorno aislado, y es útil al compilar software de menor confianza.

--allow-missing-runtimes

No falla inmediatamente si los entornos de ejecución sdk o platform no están instalados en este sistema. Intentar compilar cualquier módulo del manifiesto seguirá fallando si falta el sdk, pero puede ser útil para aplicaciones que instalan archivos sin una compilación en entorno aislado.

--rebuild-on-sdk-change

Registra la versión exacta del sdk en la caché y recompila todo si cambia. Esto es útil si estás compilando contra un entorno de ejecución con API inestable, como una compilación nocturna.

--skip-if-unchanged

Si el json no ha cambiado desde la última compilación de este nombre de archivo, no hace nada y devuelve el código de salida 42.

--mirror-screenshots-url=URL

Refleja cualquier medio en appstream y reescribe las URL de los medios en el xml de appstream a la URL especificada. Los archivos resultantes se almacenarán en el subdirectorio "screenshots" del directorio de la aplicación para versiones anteriores a la 1.3.4 y en el subdirectorio "files/share/app-info/media" para versiones más recientes. Desde la versión 1.4.5, esto también creará una referencia de captura de pantalla en el repositorio OSTree exportado para cada arquitectura que contenga los medios reflejados.

--extra-sources=SOURCE-DIR

Al descargar fuentes (archivos, archivos, git, bzr, svn), busca en este directorio copias preexistentes y úsalas en lugar de descargarlas. El directorio debe coincidir con la estructura del directorio de estado:
•Los archivos y los archivos comprimidos deben estar dentro de la carpeta: downloads/<sha256>/
•Las fuentes de tipo git, bzr y svn deben estar dentro de la carpeta: <type>/<converted-uri>/

El converted-uri se construye a partir de la ruta o url (en el caso de git) y de la url (en el caso de bzr y svn). :// se convierte en un solo guion bajo y cada otra / se reemplaza por un guion bajo. Por ejemplo, https://github.com/user/repo.git se convierte en https_github.com_user_repo.git. En el caso de las fuentes de svn, si la revisión está presente, el nombre de la carpeta es svn/<converted-uri>__r<revision>/. En el caso de las fuentes de git, debe ser un clon reflejado.

--extra-sources-url=URL

Al descargar fuentes (archivos, archivos, git, bzr, svn), mira esta url para descargas reflejadas antes de descargar desde la url original.

--from-git=GIT

Busca el manifiesto en el repositorio git indicado. Si se proporciona esta opción, MANIFEST se interpreta como una ruta relativa dentro del repositorio.

--from-git-branch=BRANCH

La rama a usar con --from-git.

--no-shallow-clone

No uses clonaciones superficiales al reflejar repositorios git.

--override-source-date-epoch

Establece esta marca de tiempo como SOURCE_DATE_EPOCH para realizar la compilación, en lugar de la hora de la última modificación del manifiesto. Esto está disponible desde la versión 1.3.1.

--compose-url-policy=POLICY

Establece la política de URL de composición de AppStream. Los valores aceptados son partial y full. full requiere AppStream versión >= 0.16.3. El valor predeterminado es partial si no se especifica. Esta política solo tiene efecto cuando se usa en conjunto con --mirror-screenshots-url=URL; de lo contrario, el catálogo de Appstream conservará las URL de los medios de origen.

--add-tag=TAG

Añade esta etiqueta a la lista de etiquetas del manifiesto antes de compilar.

--remove-tag=TAG

Elimina esta etiqueta de la lista de etiquetas del manifiesto antes de compilar. La eliminación ocurre antes de procesar la opción --add-tag, así que si se especifican ambas, --app-tag tiene prioridad.

--install-deps-from=REMOTE

Instala/actualiza las dependencias requeridas para la compilación desde el remoto especificado.

--install-deps-only

Se detiene después de descargar las dependencias.

--install

Cuando la compilación finalice, instala el resultado localmente.

--user

Instala las dependencias en una instalación por usuario.

--system

Instala las dependencias en la instalación predeterminada del sistema.

--installation=NAME

Instala las dependencias en una instalación a nivel de sistema especificada por NAME entre las definidas en /etc/flatpak/installations.d/. Usar --installation=default es equivalente a usar --system.

CACHING

flatpak-builder guarda en caché las fuentes y los resultados parciales de la compilación en el directorio de estado (que por defecto es el subdirectorio .flatpak-builder del directorio actual). Si usas --keep-build-dirs, los directorios de compilación de cada módulo también se almacenan aquí.

Es seguro eliminar el directorio de estado. Esto forzará una compilación completa la próxima vez que compiles.
