flock

flock - manejo de bloqueos de archivos

SINOPSIS

flock [options] file command [args]
flock [options] file -c command
flock [options] fd

DESCRIPCIÓN

flock gestiona un bloqueo en un archivo especificado. Un bloqueo de archivo es un mecanismo que permite a un proceso indicar que está accediendo a un recurso (generalmente un archivo) y que otros procesos deben esperar. Esto es útil para prevenir condiciones de carrera y garantizar la integridad de los datos.

El programa flock puede usarse de dos maneras principales:

  1. Para ejecutar un comando y asegurarse de que solo un proceso a la vez pueda acceder a un archivo de bloqueo.
  2. Para adquirir un bloqueo en un archivo y mantenerlo abierto, permitiendo que el script que llama a flock controle la duración del bloqueo.

El archivo especificado no necesita existir. Si no existe, flock lo creará (con permisos 0666, modificados por umask) si se le solicita un bloqueo de escritura o de lectura/escritura.

Los bloqueos son gestionados por el kernel y se liberan automáticamente cuando todos los descriptores de archivo que contienen el bloqueo se cierran, o cuando un proceso termina.

flock admite bloqueos exclusivos (escritura) y compartidos (lectura). Por defecto, se solicita un bloqueo exclusivo.

OPCIONES

-n, --nonblock

Falla inmediatamente si el bloqueo no se puede adquirir. De lo contrario, flock esperará indefinidamente hasta que el bloqueo esté disponible.

-w, --timeout seconds

Espera hasta seconds para adquirir el bloqueo. flock fallará si el bloqueo no se puede adquirir dentro de ese tiempo. Si seconds es 0, es equivalente a -n. Se pueden especificar segundos fraccionarios.

-x

Requiere un bloqueo exclusivo (escritura). Este es el comportamiento predeterminado.

-s

Requiere un bloqueo compartido (lectura).

-u

Libera un bloqueo existente. Esta opción generalmente no se necesita, ya que los bloqueos se liberan automáticamente cuando el proceso termina o el descriptor de archivo se cierra.

-c command

Ejecuta el comando especificado. Esto es un atajo para ejecutar flock, adquirir el bloqueo, ejecutar el comando y luego liberar el bloqueo.

ESTADO DE SALIDA

El código de salida de flock es el código de salida del comando que se ejecutó, si se proporcionó uno. Si no se proporcionó ningún comando, flock devuelve 0 si adquirió el bloqueo y 1 si falló (por ejemplo, debido a un tiempo de espera agotado o a la opción -n).

NOTAS

Los bloqueos de archivos gestionados por flock son bloqueos de estilo BSD y no son compatibles con los bloqueos de estilo POSIX gestionados por fcntl. Los bloqueos de estilo BSD se aplican a todo el archivo, mientras que los bloqueos de estilo POSIX pueden aplicarse a regiones específicas del archivo.

Es importante utilizar el mismo archivo de bloqueo para todos los procesos que necesitan coordinar el acceso. El contenido del archivo de bloqueo no importa; solo la existencia del bloqueo en el archivo es relevante.

EJEMPLOS

Ejecutar un script de copia de seguridad de forma segura:

$ flock -n /var/lock/mybackup.lock -c '/usr/local/bin/mybackup.sh'

Este comando intentará adquirir un bloqueo exclusivo en el archivo /var/lock/mybackup.lock. Si el bloqueo se adquiere, se ejecutará el script /usr/local/bin/mybackup.sh. Si el bloqueo no se puede adquirir inmediatamente (porque otro proceso ya lo tiene), el comando flock fallará y saldrá con un código de error.

Esperar a que se libere un bloqueo:

$ flock /var/lock/another_process.lock -c 'echo "Procesando datos..."; sleep 60; echo "Procesamiento completado."'

Este comando esperará indefinidamente hasta que se pueda adquirir un bloqueo exclusivo en /var/lock/another_process.lock. Una vez adquirido, ejecutará el comando interno, que imprime un mensaje, duerme durante 60 segundos y luego imprime otro mensaje.

Adquirir un bloqueo compartido:

$ flock -s /var/lock/shared_resource.lock -c 'echo "Accediendo al recurso compartido..."; sleep 10;'

Esto adquiere un bloqueo compartido (de lectura) en el archivo. Múltiples procesos pueden tener bloqueos compartidos simultáneamente, pero ningún proceso puede adquirir un bloqueo exclusivo mientras existan bloqueos compartidos.
