flatpak-install(1)

Paquete: flatpak

Licencias: LGPL-2.1-or-later

REF...
install UBICACIÓN CRIPC
flatpak [OPCIÓN...] [--from|--bundle] DES
IÓN

Instala una aplicación o un runtime. La forma principal de instalar es especificar un nombre de REMOTO como origen y una o más REF para indicar la aplicación o el runtime a instalar. Si se omite el REMOTO, se buscan los remotos configurados para la primera

REF y se le pide al usuario que confirme la elección resultante.

Cada argumento REF es un identificador completo o parcial en el formato de referencia de flatpak, que tiene la forma "(app|runtime)/ID/ARCH/BRANCH". Todos los elementos excepto ID son opcionales y pueden omitirse, incluidas las barras, por lo que la mayoría de las veces solo es necesario especificar ID. Cualquier parte omitida se comparará con lo que hay en el remoto, y si hay múltiples coincidencias se le pedirá que elija una de ellas. También se le presentarán opciones si REF no coincide exactamente con nada en el remoto pero es similar a una o más referencias en el remoto (por ejemplo, "devhelp" es similar a "org.gnome.Devhelp"), pero este comportamiento de coincidencia difusa se desactiva si

REF contiene
barras o puntos.

Por defecto, esto busca tanto aplicaciones como runtimes con la REF dada en el REMOTO especificado, pero puede limitar esto

usando la opción

--ap

p

o

--runtime [[27]], o proporcionando el elemento inicial en

la REF.

Si el REMOTO especificado es una URI o una ruta (absoluta o relativa que comienza con ./) a un repositorio local, entonces ese repositorio se usará como origen, y se creará un remoto temporal durante la vigencia de la

REF.

Si el REMOTO especificado tiene un ID de colección configurado, Flatpak buscará en los directorios de repositorios de carga lateral (sideload-repos) configurados ya sea con la

opción

--sideload-repo [[31]], o de forma individual por instalación o a nivel de sistema (véase flatpak(1) [[33]]). La forma alternativa del comando

(con

--fro

m

o --bundle [[38]]) permite instalar directamente desde una fuente como un paquete de archivo único .flatpak o un archivo de descripción de aplicación .flatpakref. Las opciones son opcionales si el primer argumento tiene la extensión de nombre de archivo esperada. Tenga en cuenta que flatpak permite tener múltiples ramas de una aplicación y runtimes instalados y usados al mismo tiempo. Sin embargo, solo una versión de una aplicación puede ser la actual, lo que significa que sus archivos exportados (por ejemplo, archivos de escritorio e iconos) son visibles para el host. La última versión instalada se convierte en la actual por defecto, pero esto puede cambiarse

manualmente con flatpak make-current.

A menos que se anule con la opción --user o la --installation [[44]], este comando instala la aplicación o el runtime en la instalación predeterminada a nivel de sistema. OPCIONE
