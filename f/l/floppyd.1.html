Autenticación

floppyd

autentica a los clientes remotos utilizando el protocolo Xauthority. La autenticación Xhost no está soportada. Cada floppyd está asociado a un servidor X. Cuando un cliente remoto intenta conectarse a floppyd, envía a floppyd el registro de autoridad X correspondiente al servidor X de floppyd. Floppyd a su vez intenta abrir una conexión con el servidor X para verificar la autenticidad del registro xauth. Si la conexión con el servidor X tiene éxito, se concede acceso al cliente. DISPLAY. Precaución: Para que la autenticació

n

funcione correctamente, el host local no debe estar listado en la lista xhost de hosts permitidos. De hecho, los hosts listados en xhost no
necesitan una cookie Xauthority correcta para conectarse al servidor X. Como floppyd se ejecuta en el mismo host que el servidor X, todas sus conexiones de sondeo tendrían éxito incluso para clientes que proporcionaron una cookie incorrecta. Esto significa que tu unidad de disquete estaría abierta al mundo, es decir, un agujero de seguridad enorme. Si tu
servidor X no te permite eliminar localhost:0 y :0 de la lista xhost, puedes evitar que floppyd sondee esos nombres de pantalla con la opción -l. Opciones de línea de comandos d Modo se
