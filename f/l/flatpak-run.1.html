FLATPAK RUN(1) flatpak run FLATPAK RUN(1)

NOMBRE

flatpak-run - Ejecuta una aplicación o abre una shell en un entorno de ejecución

SINOPSIS

flatpak run [OPCIÓN...] REF [ARG...]

DESCRIPCIÓN

Si REF nombra una aplicación instalada, Flatpak ejecuta la aplicación en un entorno aislado (sandbox). Los argumentos adicionales se pasan a la aplicación. Se utiliza la rama y arquitectura actuales de la aplicación a menos que se especifique lo contrario con --branch o --arch. Ver flatpak-make-current(1).

Si REF nombra un entorno de ejecución (runtime), se abre una shell en el entorno de ejecución. Esto es útil para desarrollo y pruebas. Si hay ambigüedad sobre qué rama usar, se le pedirá que elija. Utilice --branch para evitar esto. Se utiliza la arquitectura principal a menos que se especifique lo contrario con --arch.

Por defecto, Flatpak buscará la aplicación o el entorno de ejecución primero en la instalación por usuario y luego en todas las instalaciones del sistema. Esto se puede anular con las opciones --user, --system y --installation.

Flatpak crea un entorno aislado para que la aplicación se ejecute montando el entorno de ejecución correcto en /usr y un directorio escribible en /var, cuyo contenido se conserva entre ejecuciones de la aplicación. La aplicación en sí se monta en /app.

Los detalles del entorno aislado se controlan por los metadatos de la aplicación y varias opciones como --share y --socket que se pasan al comando run: El acceso está permitido si se solicitó en el archivo de metadatos de la aplicación o con una opción y el usuario no lo ha anulado.

Los argumentos restantes se pasan al comando que se ejecuta en el entorno aislado. Ver la opción --file-forwarding para el manejo de argumentos de archivo.

Las variables de entorno generalmente se pasan a la aplicación aislada, con ciertas excepciones. Los metadatos de la aplicación pueden anular las variables de entorno, al igual que la opción --env. Flatpak también anula las variables de entorno XDG para apuntar a las aplicaciones aisladas a sus ubicaciones de sistema de archivos escribibles debajo de ~/.var/app/$APPID/:

XDG_DATA_HOME

Las aplicaciones pueden usar las opciones --persist=.local/state y --unset-env=XDG_STATE_HOME para obtener un ~/.local/state compatible con Flatpak 1.13 en versiones anteriores de Flatpak.

Los valores del host de estas variables están disponibles dentro del sandbox a través de estas variables con prefijo HOST_:

HOST_XDG_DATA_HOME
HOST_XDG_CONFIG_HOME
HOST_XDG_CACHE_HOME
HOST_XDG_STATE_HOME (desde Flatpak 1.13)

Flatpak establece la variable de entorno FLATPAK_ID al ID de la aplicación de la app en ejecución.

Flatpak también monta como solo lectura el /etc/os-release del host (si está disponible, o /usr/lib/os-release como respaldo) en /run/host/os-release, de acuerdo con la especificación de os-release[1].

Si el soporte de control parental está habilitado, flatpak verificará la configuración de control parental del usuario actual y se negará a ejecutar una aplicación si está bloqueada para el usuario actual.

OPCIONES

Se entienden las siguientes opciones:

-h, --help

Muestra las opciones de ayuda y sale.

-u, --user

Busca la aplicación y el entorno de ejecución en las instalaciones por usuario.

--system

Busca la aplicación y el entorno de ejecución en las instalaciones predeterminadas a nivel de sistema.

--installation=NAME

Busca la aplicación y el entorno de ejecución en la instalación a nivel de sistema especificada por NAME entre las definidas en /etc/flatpak/installations.d/. Usar --installation=default es equivalente a usar --system.

-v, --verbose

Imprime información de depuración durante el procesamiento del comando.

--ostree-verbose

Imprime información de depuración de OSTree durante el procesamiento del comando.

--arch=ARCH

La arquitectura a ejecutar. Ver flatpak --supported-arches para las arquitecturas compatibles con el host.

--command=COMMAND

El comando a ejecutar en lugar del listado en los metadatos de la aplicación.

--cwd=DIR

El directorio en el que ejecutar el comando. Ten en cuenta que debe ser un directorio dentro del sandbox.

--branch=BRANCH

La rama a usar.

-d, --devel

Utiliza el entorno de ejecución devel especificado en los metadatos de la aplicación en lugar del entorno de ejecución regular, y usa un perfil seccomp que sea menos probable que cause problemas con las herramientas de desarrollo.

--runtime=RUNTIME

Usa este entorno de ejecución en lugar del especificado en los metadatos de la aplicación. Esta es una tupla completa, como por ejemplo org.freedesktop.Sdk/x86_64/1.2, pero se permiten tuplas parciales. Cualquier parte vacía o faltante se rellena con los valores correspondientes especificados por la app.

--runtime-version=VERSION

Usa esta versión del entorno de ejecución en lugar de la especificada en los metadatos de la aplicación. Esto anula cualquier versión especificada con la opción --runtime.

--share=SUBSYSTEM

Comparte un subsistema con la sesión del host. Esto anula la sección Context de los metadatos de la aplicación. SUBSYSTEM debe ser uno de: network, ipc. Esta opción se puede usar varias veces.

--unshare=SUBSYSTEM

No comparte un subsistema con la sesión del host. Esto anula la sección Context de los metadatos de la aplicación. SUBSYSTEM debe ser uno de: network, ipc. Esta opción se puede usar varias veces.

--socket=SOCKET

Expone un socket conocido a la aplicación. Esto anula la sección Context de los metadatos de la aplicación. SOCKET debe ser uno de: x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Esta opción se puede usar varias veces.
