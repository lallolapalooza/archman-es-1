Paquete: flatpak

FLATPAK BUILD-EXPORT(1) flatpak build-export FLATPAK BUILD-EXPORT(1)

NOMBRE

flatpak build-export - Crear un repositorio a partir de un directorio de compilación

SINOPSIS

flatpak build-export [OPCIÓN...] UBICACIÓN DIRECTORIO [RAMA]

DESCRIPCIÓN

Crea o actualiza un repositorio con una compilación de aplicación. UBICACIÓN es la ubicación del repositorio. DIRECTORIO debe ser un directorio de compilación finalizado. Si no se especifica RAMA, se asume que es "master".

Si UBICACIÓN existe, se asume que es un repositorio OSTree; de lo contrario, se crea un nuevo repositorio OSTree en esta ubicación. El repositorio se puede inspeccionar con la herramienta ostree.

El contenido de DIRECTORIO se confirma en la rama con el nombre app/NOMBREAPP/ARQUITECTURA/RAMA, donde ARQUITECTURA es la arquitectura del entorno de ejecución que utiliza la aplicación. Se utiliza un filtro de confirmación para garantizar que solo se incluyan en la confirmación los contenidos de los subdirectorios files/ y export/ y el archivo de metadatos; todo lo demás se ignora.

Al exportar un flatpak para publicarlo en Internet, se debe especificar --collection-id=ID-COLECCIÓN como un valor DNS inverso globalmente único para identificar la colección de flatpaks que se añadirán. Establecer un ID de colección globalmente único permite que las aplicaciones del repositorio se compartan a través de sistemas punto a punto sin necesidad de configuración adicional.

El comando build-update-repo debe usarse para actualizar los metadatos del repositorio cada vez que se añaden compilaciones de aplicaciones a un repositorio.

OPCIONES

Se entienden las siguientes opciones:

-h, --help

Muestra las opciones de ayuda y sale.

-s, --subject=ASUNTO

Asunto de una línea para el mensaje de confirmación.

-b, --body=CUERPO

Descripción completa para el mensaje de confirmación.

--collection-id=ID-COLECCIÓN

Se establece como el ID de colección del repositorio. Establecer un ID de colección globalmente único permite que las aplicaciones del repositorio se compartan a través de sistemas punto a punto sin necesidad de configuración adicional. Si se exporta a un repositorio existente, el ID de colección debe coincidir con el ID de colección configurado existente para ese repositorio.

--subset=SUBJUEGO

Marca la confirmación para que se incluya en el subconjunto con nombre. Esto hará que la confirmación se incluya en el resumen del subconjunto con nombre (además del principal), permitiendo a los usuarios ver solo este subconjunto en lugar de todo el repositorio.

--arch=ARQUITECTURA

Especifica el componente de arquitectura de la rama a exportar. Solo se pueden especificar arquitecturas compatibles con el host; consulta flatpak --supported-arches para ver los valores válidos.

--exclude=PATRÓN

Excluye los archivos que coincidan con PATRÓN de la confirmación. Esta opción se puede usar varias veces.

--include=PATRÓN

No excluye los archivos que coincidan con PATRÓN de la confirmación, incluso si coinciden con los patrones de --exclude. Esta opción se puede usar varias veces.

--metadata=NOMBRE-ARCHIVO

Utiliza el nombre de archivo especificado como metadatos en la aplicación exportada en lugar del archivo predeterminado (llamado metadata). Esto es útil si deseas confirmar varias cosas de un único árbol de compilación, generalmente se usa en combinación con --files y --exclude.

--files=SUBDIR

Utiliza los archivos del subdirectorio especificado como contenido de archivos, en lugar del directorio de archivos regular.

--timestamp=FECHA

Utiliza la fecha en formato ISO 8601 especificada o NOW, para la hora actual, en los metadatos de confirmación y, si se usa --update-appstream, en los datos de appstream.

--end-of-life=RAZÓN

Marca la compilación como fin de vida útil. RAZÓN es un mensaje que puede mostrarse a los usuarios que instalen esta compilación.

--end-of-life-rebase=ID

Marca la compilación como fin de vida útil. A diferencia de --end-of-life, este toma un ID que reemplaza al actual. Por solicitud del usuario, los datos de la aplicación pueden conservarse para la nueva aplicación.

--disable-fsync

No usa fsync al escribir en el repositorio. Esto puede resultar en pérdida de datos en situaciones excepcionales, pero puede mejorar el rendimiento al trabajar con repositorios temporales o de prueba.

--update-appstream

Actualiza la rama appstream después de la compilación.

--no-update-summary

No actualiza el archivo summary después de agregar la nueva confirmación. Esto significa que el repositorio no será útil para servir a través de http hasta que se ejecute build-update-repo. Esto es útil si deseas realizar varias operaciones de repositorio antes de actualizar finalmente el summary.

--gpg-sign=KEYID

Firma la confirmación con esta clave GPG. Esta opción se puede usar varias veces.

--gpg-homedir=RUTA

Directorio de inicio GPG a usar al buscar keyring.

-r, --runtime

Exporta un entorno de ejecución en lugar de una aplicación (esto usa el subdirectorio usr como archivos).

-v, --verbose

Imprime información de depuración durante el procesamiento del comando.

--ostree-verbose

Imprime información de depuración de OSTree durante el procesamiento del comando.
