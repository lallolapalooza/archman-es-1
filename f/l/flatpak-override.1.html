FLATPAK OVERRIDE(1) flatpak override FLATPAK OVERRIDE(1)

NOMBRE

flatpak-override - Anular los requisitos de una aplicación

SINOPSIS

flatpak override [OPCIÓN...] [APP]

DESCRIPCIÓN

Anula los requisitos del entorno de ejecución de la aplicación especificada. Esto se puede usar para otorgar a una aplicación aislada más o menos recursos de los que solicitó.

Por defecto, la aplicación obtiene acceso a los recursos que solicitó cuando se inicia. Pero el usuario puede anularlo en una instancia particular especificando argumentos adicionales a flatpak run, o cada vez usando flatpak override.

Las anulaciones de aplicaciones se guardan en archivos de texto que residen en $XDG_DATA_HOME/flatpak/overrides en modo de usuario.

Si no se especifica el ID de aplicación APP, las anulaciones afectan a todas las aplicaciones, pero las anulaciones por aplicación pueden anular las anulaciones globales.

A menos que se anule con las opciones --user o --installation, este comando cambia la instalación predeterminada a nivel de sistema.

OPCIONES

Se entienden las siguientes opciones:

-h, --help

Muestra las opciones de ayuda y sale.

-u, --user

Actualiza una instalación por usuario.

--system

Actualiza la instalación predeterminada a nivel de sistema.

--installation=NOMBRE

Actualiza una instalación a nivel de sistema especificada por NOMBRE entre las definidas en /etc/flatpak/installations.d/. Usar --installation=default es equivalente a usar --system.

--share=SUBSISTEMA

Comparte un subsistema con la sesión del host. Esto anula la sección Context del metadato de la aplicación. SUBSISTEMA debe ser uno de: network, ipc. Esta opción se puede usar varias veces.

--unshare=SUBSISTEMA

No comparte un subsistema con la sesión del host. Esto anula la sección Context del metadato de la aplicación. SUBSISTEMA debe ser uno de: network, ipc. Esta opción se puede usar varias veces.

--socket=SOCKET

Expone un socket conocido a la aplicación. Esto anula la sección Context del metadato de la aplicación. SOCKET debe ser uno de: x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Esta opción se puede usar varias veces.

--nosocket=SOCKET

No expone un socket conocido a la aplicación. Esto anula la sección Context del metadato de la aplicación. SOCKET debe ser uno de: x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Esta opción se puede usar varias veces.

--device=DISPOSITIVO

Expone un dispositivo a la aplicación. Esto anula la sección Context del metadato de la aplicación. DISPOSITIVO debe ser uno de: dri, input, usb, kvm, shm, all. Esta opción se puede usar varias veces.

--nodevice=DISPOSITIVO

No expone un dispositivo a la aplicación. Esto anula la sección Context del metadato de la aplicación. DISPOSITIVO debe ser uno de: dri, input, usb, kvm, shm, all. Esta opción se puede usar varias veces.

--allow=CARACTERÍSTICA

Permite el acceso a una característica específica. Esto actualiza el grupo [Context] en los metadatos. CARACTERÍSTICA debe ser uno de: devel, multiarch, bluetooth, canbus, per-app-dev-shm. Esta opción se puede usar varias veces.

Consulte flatpak-build-finish(1) para conocer el significado de las diversas características.

--disallow=CARACTERÍSTICA

Deniega el acceso a una característica específica. Esto actualiza el grupo [Context] en los metadatos. CARACTERÍSTICA debe ser uno de: devel, multiarch, bluetooth, canbus, per-app-dev-shm. Esta opción se puede usar varias veces.

--filesystem=SISTEMA_ARCHIVOS

Permite a la aplicación acceder a un subconjunto del sistema de archivos. Esto anula la sección Context del metadato de la aplicación. SISTEMA_ARCHIVOS puede ser uno de: home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, xdg-run, xdg-config, xdg-cache, xdg-data, una ruta absoluta, o una ruta relativa al directorio principal como ~/dir o rutas relativas a los directorios xdg, como xdg-download/subdir. El sufijo opcional :ro indica que la ubicación será de solo lectura. El sufijo opcional :create indica que la ubicación será de lectura/escritura y se creará si no existe. Esta opción se puede usar varias veces. Consulte la lista "[Context] filesystems" en flatpak-metadata(5) para obtener detalles sobre los significados de estos sistemas de archivos.

--nofilesystem=SISTEMA_ARCHIVOS

Anula el efecto de un --filesystem=SISTEMA_ARCHIVOS anterior en el manifiesto de la aplicación o en una capa de anulaciones de menor precedencia, y/o elimina un --filesystem=SISTEMA_ARCHIVOS anterior de esta capa de anulaciones. Esto anula la sección Context del metadato de la aplicación. SISTEMA_ARCHIVOS puede tomar los mismos valores que para --filesystem, pero los sufijos :ro y :create no se usan aquí. Esta opción se puede usar varias veces.

Esta opción no impide el acceso a un --filesystem más específico. Por ejemplo, si una aplicación tiene el equivalente a --filesystem=xdg-config/MyApp en su manifiesto o como anulación a nivel de sistema, y flatpak override --user --nofilesystem=home como anulación por usuario, entonces se le impedirá acceder a la mayor parte del directorio principal, pero todavía se le permitirá acceder a $XDG_CONFIG_HOME/MyApp.

Como caso especial, --nofilesystem=host:reset ignorará todos los permisos --filesystem heredados del manifiesto de la aplicación o de una capa de anulaciones de menor precedencia, además de tener el comportamiento de --nofilesystem=host.

--add-policy=SUBSISTEMA.CLAVE=VALOR

Agrega una opción de política genérica. Por ejemplo, "--add-policy=subsystem.key=v1 --add-policy=subsystem.key=v2" se mapearía a estos metadatos: 
[Policy subsystem]
key=v1;v2;

Esta opción se puede usar varias veces.

--remove-policy=SUBSISTEMA.CLAVE=VALOR

Elimina una opción de política genérica. Esta opción se puede usar varias veces.

--env=VAR=VALOR

Establece una variable de entorno en la aplicación. Esto anula la sección Context del metadato de la aplicación. Esta opción se puede usar varias veces.

--unset-env=VAR

Anula una variable de entorno en la aplicación. Esto anula la entrada unset-environment en el grupo [Context] de los metadatos, y el grupo [Environment]. Esta opción se puede usar varias veces.

--env-fd=FD

Lee variables de entorno desde el descriptor de archivo FD y las establece como si fuera a través de --env. Esto puede usarse para evitar que las variables de entorno y sus valores sean visibles para otros usuarios.

Cada variable de entorno tiene el formato VAR=VALOR seguido de un byte nulo. Este es el mismo formato que usan env -0 y /proc/*/environ.

--own-name=NOMBRE

Permite que la aplicación posea el nombre conocido NOMBRE en el bus de sesión. Esto anula la sección Context del metadato de la aplicación. Esta opción se puede usar varias veces.

--talk-name=NOMBRE

Permite que la aplicación hable con el nombre conocido NOMBRE en el bus de sesión. Esto anula la sección Context del metadato de la aplicación. Esta opción se puede usar varias veces.

--no-talk-name=NOMBRE

No permite que la aplicación hable con el nombre conocido NOMBRE en el bus de sesión. Esto anula la sección Context del metadato de la aplicación. Esta opción se puede usar varias veces.

--system-own-name=NOMBRE

Permite que la aplicación posea el nombre conocido del sistema NOMBRE en el bus del sistema. Si NOMBRE termina con .*, permite que la aplicación posea todos los nombres coincidentes. Esto anula la sección Context del metadato de la aplicación. Esta opción se puede usar varias veces.

--system-talk-name=NOMBRE

Permite que la aplicación hable con el nombre conocido del sistema NOMBRE en el bus del sistema. Si NOMBRE termina con .*, permite que la aplicación hable con todos los nombres coincidentes. Esto anula la sección Context del metadato de la aplicación. Esta opción se puede usar varias veces.

--system-no-talk -name=NOMBR

E
No permitir que la aplicación se comunique con el nombre bien conocido NOMBRE en el bus del sistema. Si NOMBRE termina con .*, permite que la aplicación se comunique con todos los nombres coincidentes. Esto anula la sección Context de los metadatos de la aplicación. Esta opción se puede usar varias
veces.

--persist=ARCHIV

O
Si la aplicación no tiene acceso al directorio de inicio real, hace que la ruta ARCHIVO (relativa al directorio de inicio) sea un montaje de enlace a la ruta correspondiente en el directorio de la aplicación, permitiendo que esa ubicación se use para datos persistentes. Esto anula la sección Context de los metadatos de la aplicación. Esta opción se puede usar varias
veces.

--rese

t
Eliminar las anulaciones. Si se proporciona una APLICACIÓN, se eliminan las anulaciones para esa aplicación; de lo contrario, se eliminan las anulaciones
globales.

--sho

w
Muestra las anulaciones. Si se proporciona una APLICACIÓN, muestra las anulaciones para esa aplicación; de lo contrario, muestra las anulaciones
globales.

-v, --verbos

e
Imprimir información de depuración durante el procesamiento del
comando.

--ostree-verbos

e
Imprimir información de depu
ración de OSTree durante el
procesamiento del comando.
