Descripción

Detallada

Una interfaz abstracta de

entrada/salida.

Advertenci

a
Esto es material avanzado y complejo. No lo necesita a menos que sepa realmente lo que está haciendo. La mayoría de las aplicaciones no necesitarán
esto.

Históricamente, PhysicsFS proporcionaba acceso al sistema de archivos físico y a archivos comprimidos dentro de ese sistema de archivos. Sin embargo, a veces necesita más potencia que esto. Quizás necesita proporcionar un archivo comprimido que esté completamente contenido en RAM, o necesita conectar alguna otra API de entrada/salida de archivos a PhysicsFS, o necesita traducir los bits (quizás tiene un archivo .zip estándar que está encriptado y necesita desencriptarlo al vuelo para el desapercibido archivador zip)

.

Un PHYSFS_Io es la interfaz que los Archivadores usan para obtener datos de archivos comprimidos. Históricamente, esto se ha mapeado a la entrada/salida de archivos al sistema de archivos físico, pero a partir de PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de entrada/salida en tiempo de

ejecución.

Esta interfaz no es necesariamente una buena adaptación universal para la entrada/salida. Hay algunos requisitos a tener en

cuenta:
  • Solo realizan entrada/salida bloqueante (al menos, por
    • ahora).
  • Necesitan poder duplicarse. Si tiene un identificador de archivo de fopen(), necesita poder crear un clon único de él (para que tengamos dos identificadores al mismo archivo que puedan ambos buscar/leer/etc sin pisarse entre
    • sí).
  • Necesitan saber el tamaño de su conjunto de datos
    • completo.
  • Necesitan poder
    • buscar y rebobin
ar bajo demanda.

...en resumen, probablemente no va a escribir una implementación de

HTTP.

Seguridad de hilos: Las implementaciones de PHYSFS_Io no están garantizadas para ser seguras en hilos en sí mismas. Internamente, donde PhysicsFS las usa, la biblioteca proporciona sus propios bloqueos. Si planea usarlas directamente desde hilos separados, debería usar mutexes para protegerlas, o no usar el mismo PHYSFS_Io desde dos hilos al mismo

tiempo.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io

*io)

Limpiar y desasignar la instancia de entrada/salida. Liberar recursos asociados, incluyendo (opaque) si es

aplicable.

Esta función siempre debe tener éxito: como tal, devuelve void. El sistema puede llamar a su método flush() antes que este. Puede informar de un fallo allí si es necesario. Este método aún puede ser llamado si flush() falla, en cuyo caso tendrá que abandonar los datos no volcados y otras condiciones fallidas y

limpiar.

Una vez que este método es llamado para una instancia dada, el sistema asumirá que no es seguro tocar esa instancia de nuevo y descartará cualquier referencia a

ella.

Duplicar esta instancia de entrada/salida. Esto necesita resultar en una copia completa de este PHYSFS_Io, que pueda vivir completamente independientemente.
