FLOCKFILE(3P) Manual del Programador POSIX FLOCKFILE(3P)

PRÓLOGO

Esta página de manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página de manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

flockfile, ftrylockfile, funlockfile — funciones de bloqueo de stdio

SINOPSIS

#include <stdio.h>
void flockfile(FILE *file);
int ftrylockfile(FILE *file);
void funlockfile(FILE *file);

DESCRIPCIÓN

Estas funciones deben proporcionar bloqueo explícito a nivel de aplicación de objetos stdio (FILE *). Estas funciones pueden ser usadas por un hilo para delimitar una secuencia de sentencias de E/S que se ejecutan como una unidad.

La flockfile() función debe adquirir para un hilo la propiedad de un objeto (FILE *).

La ftrylockfile() función debe adquirir para un hilo la propiedad de un objeto (FILE *) si el objeto está disponible; ftrylockfile() es una versión no bloqueante de flockfile().

La funlockfile() función debe renunciar a la propiedad otorgada al hilo. El comportamiento es indefinido si un hilo distinto del propietario actual llama a la funlockfile() función.

Las funciones deben comportarse como si hubiera un contador de bloqueo asociado con cada objeto (FILE *). Este contador se inicializa implícitamente a cero cuando el objeto (FILE *) se crea. El objeto (FILE *) está desbloqueado cuando el contador es cero. Cuando el contador es positivo, un solo hilo es propietario del objeto (FILE *). Cuando la flockfile() función es llamada, si el contador es cero o si el contador es positivo y el llamador es propietario del objeto (FILE *), el contador debe incrementarse. De lo contrario, el hilo llamante debe ser suspendido, esperando a que el contador vuelva a cero. Cada llamada a funlockfile() debe decrementar el contador. Esto permite que las llamadas coincidentes a flockfile() (o llamadas exitosas a ftrylockfile()) y funlockfile() sean anidadas.

Todas las funciones que referencian objetos (FILE *), excepto aquellas con nombres que terminan en _unlocked, deben comportarse como si usaran flockfile() y funlockfile() internamente para obtener la propiedad de estos objetos (FILE *).

VALOR DE RETORNO

Ninguno para flockfile() y funlockfile().

La ftrylockfile() función debe devolver cero para éxito y distinto de cero para indicar que el bloqueo no puede ser adquirido.

ERRORES

No se definen errores.

USO EN APLICACIONES

Las aplicaciones que usan estas funciones pueden estar sujetas a inversión de prioridad, como se discute en el volumen de Definiciones Básicas de POSIX.1‐2017, Sección 3.291, Inversión de Prioridad.

Una llamada a exit() puede bloquearse hasta que los flujos bloqueados sean desbloqueados porque un hilo que tiene la propiedad de un objeto (FILE*) bloquea todas las llamadas a funciones que referencian ese objeto (FILE*) (excepto aquellas con nombres que terminan en _unlocked) de otros hilos, incluyendo llamadas a exit().

JUSTIFICACIÓN

Las flockfile() y funlockfile() funciones proporcionan un bloqueo mutuo ortogonal para cada FILE. La ftrylockfile() función proporciona un intento no bloqueante de adquirir un bloqueo de archivo, análogo a pthread_mutex_trylock().

Estos bloqueos se comportan como si fueran los mismos que los usados internamente por stdio para la seguridad de hilos. Esto tanto proporciona seguridad de hilos de estas funciones sin requerir un segundo nivel de bloqueo interno como permite que las funciones en stdio sean implementadas en términos de otras stdio funciones.

Los desarrolladores e implementadores de aplicaciones deben ser conscientes de que hay problemas potenciales de interbloqueo en los objetos FILE . Por ejemplo, la semántica de vaciado de buffers con líneas de stdio (solicitada mediante {_IOLBF}) requiere que ciertas operaciones de entrada a veces causen que el contenido en buffers de flujos de salida con buffers de líneas definidos por la implementación sea vaciado. Si dos hilos cada uno retienen el bloqueo en el FILEdel otro, se produce un interbloqueo. Este tipo de interbloqueo puede evitarse adquiriendo los bloqueos de FILE en un orden consistente. En particular, el interbloqueo de flujos de salida con buffers de líneas puede típicamente evitarse adquiriendo bloqueos en flujos de entrada antes que bloqueos en flujos de salida si un hilo estaría adquiriendo ambos.

En resumen, los hilos que comparten flujos stdio con otros hilos pueden usar flockfile() y funlockfile() para causar que las secuencias de E/S realizadas por un solo hilo sean mantenidas juntas. El único caso donde el uso de flockfile() y funlockfile() es requerido es para proporcionar un ámbito que proteja los usos de las funciones/macros *_unlocked . Esto mueve el compromiso costo/rendimiento al punto óptimo.
