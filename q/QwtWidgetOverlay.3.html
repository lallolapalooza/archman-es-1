Descripción Detallada

Una superposición para un widget.

El principal caso de uso de una superposición de widget es evitar operaciones de repintado intensivas del widget inferior.

Por ejemplo, en combinación con el lienzo del gráfico, una superposición evita volver a dibujar, ya que el contenido del lienzo se puede restaurar desde su almacenamiento en búfer.

QwtWidgetOverlay es una clase base abstracta. Las clases derivadas deben reimplementar los siguientes métodos:

  • drawOverlay()
  • maskHint()

Internamente, QwtPlotPicker utiliza superposiciones para mostrar la banda de selección y el texto del rastreador.

Documentación de Enumeraciones de Miembros

enum QwtWidgetOverlay::MaskMode

Modo de máscara. Al usar máscaras, al widget inferior se le envían eventos de pintado solo para las regiones enmascaradas de la superposición. De lo contrario, Qt activa repintados completos. En hardware menos potente (por ejemplo, sistemas integrados) - o al usar el motor de pintado rasterizado en una conexión de escritorio remoto - la transferencia de bits es una operación notable que debe evitarse.

Si y cómo enmascarar depende de cuán costosa sea la cálculo de la máscara y cuántos píxeles se puedan excluir con la máscara.

La configuración predeterminada es MaskHint.

Ver también

setMaskMode(), maskMode()

Enumerator

NoMask
No usar máscara.
MaskHint
Usar maskHint() como máscara. Para muchas situaciones, una aproximación rápida es suficiente y no es necesario construir una máscara más detallada (por ejemplo, el rectángulo delimitador de un texto).
AlphaMask
Calcular una máscara comprobando los valores alfa. A veces no es posible dar una aproximación rápida y la máscara necesita ser calculada pintando la superposición y probando el resultado.

Cuando hay un maskHint() válido disponible, solo se comprueban los píxeles dentro de esta aproximación.

enum QwtWidgetOverlay::RenderMode

Modo de renderizado. Para calcular la máscara alfa, la superposición ya se ha pintado en una QImage temporal. En lugar de renderizar la superposición dos veces, este búfer se puede copiar para pintar la superposición.

En sistemas gráficos que usan el motor de pintado rasterizado (QWS, Windows) generalmente significa solo copiar algo de memoria. En X11, resulta en una operación costosa de construir un pixmap y para superposiciones simples podría no ser recomendable.

Nota

El modo de renderizado no tiene efecto cuando maskMode() != AlphaMask.

Enumerator

AutoRenderMode
Copiar el búfer, al usar el motor de pintado rasterizado.
CopyAlphaMask
Copiar siempre el búfer.
DrawOverlay
Nunca copiar el búfer.

Detailed Description

Overlay for widgets that want to draw themselves on top of the widget's canvas.

The simplest usage is to set the update mode to ImmediateUpdate and override drawOverlay().

class MyWidget: public QWidget, public QwtWidgetOverlay
{
public:
    MyWidget( QWidget *parent = NULL ):
        QwtWidgetOverlay( parent )
    {
        setUpdateMode( ImmediateUpdate );
    }

protected:
    virtual void drawOverlay( QPainter *painter )
    {
        // draw something on top of the widget
        painter->setPen( Qt::red );
        painter->drawRect( rect().adjusted( 0, 0, -1, -1 ) );
    }
};

If the overlay needs to be updated only on demand, the update mode can be set to LateUpdate. In this case the user has to call updateOverlay() manually when the overlay needs to be redrawn.

The render mode determines how the overlay is painted:

ImageMode The widget content is first rendered into an off-screen image. This image is then copied to the overlay, and the actual overlay is painted on top of this image. This mode might be slower, but guarantees that the overlay is painted correctly, even if the widget is partially transparent or has complex painting rules.

PainterMode The overlay is painted directly onto the widget's painter. This mode is faster, but might lead to visual artifacts if the widget's painting behavior is complex (e.g. when using alpha blending).

The mask mode determines how the mask for the overlay is calculated:

MaskHint The mask is calculated using the widget's mask(). If the widget doesn't have a mask, the whole widget area is used.

CheckablePolygon The mask is calculated using the polygon defined by the widget's shape().
