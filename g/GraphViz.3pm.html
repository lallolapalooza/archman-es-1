NOMBRE

GraphViz - Interfaz para GraphViz de AT&T. Obsoleto. Ver GraphViz2

SINOPSIS

use GraphViz;
my $g = GraphViz->new();
$g->add_node('London');
$g->add_node('Paris', label => 'City of\nlurve');
$g->add_node('New York');
$g->add_edge('London' => 'Paris');
$g->add_edge('London' => 'New York', label => 'Far');
$g->add_edge('Paris' => 'London');
print $g->as_png;

DESCRIPCIÓN

Este módulo proporciona una interfaz para la disposición y generación de imágenes de grafos dirigidos y no dirigidos en una variedad de formatos (PostScript, PNG, etc.) utilizando los programas "dot", "neato", "twopi", "circo" y "fdp" del proyecto Graphviz (http://www.graphviz.org/ o http://www.research.att.com/sw/tools/graphviz/).

GraphViz está obsoleto en favor de GraphViz2.

Instalación

Por supuesto, necesita instalar Graphviz de AT&T antes de usar este módulo. Vea http://www.graphviz.org/Download.php.

Se recomienda encarecidamente que descargue la versión estable de Graphviz, porque las instantáneas de desarrollo (haga clic en 'Source code') a veces no funcionan.

Instale GraphViz como lo haría con cualquier módulo de "Perl":

Ejecute:

cpanm GraphViz
Nota: cpanm se distribuye en App::cpanminus. Vea también App::perlbrew.

o ejecute:

sudo cpan GraphViz

o descomprima la distribución, y luego ya sea:

perl Build.PL
./Build
./Build test
sudo ./Build install

o:

perl Makefile.PL
make (o dmake o nmake)
make test
make install

¿Qué es un grafo?

Un grafo (no dirigido) es una colección de nodos enlazados entre sí con aristas.

Un grafo dirigido es igual que un grafo, pero las aristas tienen una dirección.

¿Qué es GraphViz?

Este módulo es una interfaz para el conjunto de herramientas GraphViz (http://www.graphviz.org/). Las herramientas GraphViz proporcionan el dibujo y la disposición automática de grafos. Este módulo simplifica la creación de grafos y oculta parte de la complejidad del módulo GraphViz.

Disponer los grafos de una manera estéticamente agradable es un problema difícil: puede haber múltiples formas de disponer el mismo grafo, cada una con sus propias peculiaridades. Afortunadamente, GraphViz se encarga de parte de este difícil problema y hace un bastante buen trabajo en un par de segundos para la mayoría de los grafos.

¿Por qué debería usar este módulo?

La observación ayuda a la comprensión. Esa es una manera elegante de expresar el popular proverbio pseudo-chino: "una imagen vale más que mil palabras".

El texto no siempre es la mejor manera de representar cualquier cosa y todo lo relacionado con los programas de computadora. Las imágenes son más fáciles de asimilar que el texto. La capacidad de mostrar algo gráficamente puede ayudar mucho a comprender lo que esa cosa realmente representa.

Los diagramas son computacionalmente eficientes, porque la información puede indexarse por ubicación; agrupan información relacionada en la misma área. También permiten expresar relaciones entre elementos sin etiquetar los elementos.

Un amigo mío usó esto a su favor cuando intentaba recordar fechas importantes en la historia de la computadora. En lugar de sentarse e intentar recordar todo, imprimió más de un cartel (cada uno con una fecha y un evento) y los pegó por toda su casa. Su memoria espacial es todavía tan buena que cuando se le preguntó la semana pasada (más de un año desde el experimento) cuándo se inventó Lisp, respondió que estaba en el piso de arriba, alrededor de la esquina del baño, así que debió ser alrededor de 1958.

Las hojas de cálculo también son una representación gráfica maravillosamente simple de modelos computacionales.

Aplicaciones

Incluidos con este módulo hay varios módulos para ayudar a graficar estructuras de datos (GraphViz::Data::Dumper), XML (GraphViz::XML), y Parse::RecDescent, Parse::Yapp, y gramáticas yacc (GraphViz::Parse::RecDescent, GraphViz::Parse::Yapp, y GraphViz::Parse::Yacc).

MÉTODOS

new

Este es el constructor. Acepta varios atributos.

my $g = GraphViz->new();
my $g = GraphViz->new(directed => 0);
my $g = GraphViz->new(layout => 'neato', ratio => 'compress');
my $g = GraphViz->new(rankdir  => 'BT');
my $g = GraphViz->new(width => 8.5, height => 11);
my $g = GraphViz->new(width => 30, height => 20,
                      pagewidth => 8.5, pageheight => 11);

Los dos atributos más importantes son 'layout' y 'directed'.

layout
El atributo 'layout' determina qué algoritmo de disposición usará GraphViz.pm. Los valores posibles son:
dot
La disposición por defecto de GraphViz para grafos dirigidos
neato
Para grafos no dirigidos - modelo de resorte
twopi
Para grafos no dirigidos - radial
circo
Para grafos no dirigidos - circular
fdp
Para grafos no dirigidos - modelo de resorte dirigido por fuerza
directed
El atributo 'directed', que por defecto es 1 (verdadero), especifica grafos dirigidos (las aristas tienen flechas). Establecer esto en cero produce grafos no dirigidos (las aristas no tienen flechas).
rankdir
Otro atributo, 'rankdir', controla la dirección en la que los nodos están enlazados entre sí. El valor por defecto es 'TB' (flechas de arriba hacia abajo). Otros valores legales son 'BT' (abajo->arriba), 'LR' (izquierda->derecha) y 'RL' (derecha->izquierda).
width, height
Los atributos 'width' y 'height' controlan el tamaño del cuadro delimitador del dibujo en pulgadas. Esto es más útil para la salida PostScript, al igual que para gráficos ráster (como PNG), las dimensiones de píxeles no se pueden establecer, aunque generalmente hay 96 píxeles por pulgada.
pagewidth, pageheight
Los atributos 'pagewidth' y 'pageheight' establecen el tamaño de paginación PostScript en pulgadas. Es decir, si la imagen es más grande que la página, entonces la imagen PostScript resultante es una secuencia de páginas que se pueden dividir o ensamblar en un mosaico de la imagen completa. (Esto solo funciona para la salida PostScript).
concentrate
El atributo 'concentrate' controla y habilita una técnica de fusión de aristas para reducir el desorden en diseños densos de grafos dirigidos. El valor predeterminado es no fusionar aristas.
orientation
Esta opción controla el ángulo, en grados, utilizado para rotar las formas de los nodos poligonales.
random_start
Para grafos no dirigidos, el atributo 'random_start' solicita una colocación inicial aleatoria para el grafo, lo que puede dar un mejor resultado. El valor predeterminado no es aleatorio.
epsilon
Para grafos no dirigidos, el atributo 'epsilon' decide cuánto tiempo intenta el solucionador de grafos antes de encontrar un diseño de grafo. Los números más bajos permiten que el solucionador se ejecute durante más tiempo y potencialmente dé un mejor diseño. Los valores más altos pueden reducir el tiempo de ejecución pero con una reducción en la calidad del diseño. El valor predeterminado es 0.1.
overlap
La opción 'overlap' te permite establecer el comportamiento del diseño para los nodos del grafo que se superponen. (De la documentación de GraphViz:)

Determina si y cómo se deben eliminar las superposiciones de nodos.

true
(el valor predeterminado) se conservan las superposiciones.
scale
las superposiciones se eliminan escalando uniformemente en x e y.
false
Si el valor se convierte en "false", las superposiciones de nodos se eliminan mediante una técnica basada en Voronoi.
scalexy
x e y se escalan por separado para eliminar superposiciones.
orthoxy, orthxy
Si el valor es "orthoxy" u "orthoyx", las superposiciones se mueven optimizando dos problemas de restricciones, uno para el eje x y otro para el eje y. El sufijo indica qué eje se procesa primero.

NOTA: Los métodos relacionados con "orthoxy" y "orthoyx" aún están en evolución. La semántica de estos puede cambiar, o estos métodos pueden desaparecer por completo.

compress
Si el valor es "compress", el diseño se escalará hacia abajo tanto como sea posible sin introducir superposiciones.

Excepto por el método Voronoi, todas estas transformaciones conservan el orden ortogonal del diseño original. Es decir, si las coordenadas x de dos nodos son originalmente las mismas, seguirán siendo las mismas, y si la coordenada x de un nodo es originalmente menor que la coordenada x de otro, esta relación aún se mantendrá en el diseño transformado. Las propiedades similares se aplican a las coordenadas y.

no_overlap
La opción 'no_overlap', si está establecida, indica al solucionador del grafo que no superponga los nodos. Obsoleto, use 'overlap' => 'false'.
ratio
La opción 'ratio' establece la relación de aspecto (altura del dibujo/anchura del dibujo) para el dibujo. Tenga en cuenta que esto se ajusta antes de que se apliquen las restricciones del atributo de tamaño. El valor predeterminado es "fill".
numeric
Si la relación es numérica, se toma como la relación de aspecto deseada. Luego, si la relación de aspecto real es menor que la relación deseada, la altura del dibujo se escala hacia arriba para lograr la relación deseada; si la relación real es mayor que la relación deseada, la anchura del dibujo se escala hacia arriba.
fill
Si ratio = "fill" y el atributo size está establecido, las posiciones de los nodos se escalan, por separado en x e y, de modo que el dibujo final llene exactamente el tamaño especificado.
compress
Si ratio = "compress" y el atributo size está establecido, dot intenta comprimir el diseño inicial para que quepa en el tamaño dado. Esto logra un empaquetamiento más denso de nodos pero reduce el equilibrio y la simetría. Esta función solo funciona en dot.
expand
Si ratio = "expand" el atributo size está establecido, y tanto la anchura como la altura del grafo son menores que el valor en size, las posiciones de los nodos se escalan uniformemente hasta que al menos una dimensión se ajusta exactamente a size. Tenga en cuenta que esto es distinto de usar size como el tamaño deseado, ya que aquí el dibujo se expande antes de que se generen las aristas y todos los tamaños de nodos y texto permanecen sin cambios.
auto
Si ratio = "auto" el atributo page está establecido y el grafo no se puede dibujar en una sola página, entonces size se establece en un valor "ideal". En particular, el tamaño en una dimensión dada será el múltiplo entero más pequeño del tamaño de página en esa dimensión que sea al menos la mitad del tamaño actual. Las dos dimensiones se escalan independientemente al nuevo tamaño. Esta función solo funciona en dot.
bgcolor
La opción 'bgcolor' establece el color de fondo. Un valor de color puede ser "h,s,v" (tono, saturación, brillo) números de punto flotante entre 0 y 1, o un nombre de color X11 como 'white', 'black', 'red', 'green', 'blue', 'yellow', 'magenta', 'cyan', o 'burlywood'.
name
La opción 'name' establece el nombre del grafo. Esta opción es útil en algunas situaciones, como la generación de mapas de imágenes del lado del cliente, ver cmapx. Por defecto se utiliza 'test'.
node,edge,graph
Los atributos 'node', 'edge' y 'graph' le permiten especificar atributos globales de nodo, arista y grafo (además de los controlados por los atributos especiales descritos anteriormente). El valor debe ser una referencia hash que contenga los pares clave-valor correspondientes. Por ejemplo, para hacer que todos los nodos tengan forma de caja (a menos que se les dé explícitamente otra forma): 
my $g = GraphViz->new(node => {shape => 'box'});

add_node

Un grafo consta de al menos un nodo. Todos los nodos tienen un nombre adjunto que representa de forma única a ese nodo.

El método add_node crea un nuevo nodo y opcionalmente le asigna atributos.

La forma más simple se usa cuando no se requieren atributos, en la que la cadena representa el nombre del nodo:

$g->add_node('Paris');

Varios atributos son posibles: "label" proporciona una etiqueta para el nodo (la etiqueta se basa en el nombre si no se especifica ninguna). La etiqueta puede contener saltos de línea incrustados con '\n', así como '\c', '\l', '\r' para líneas centradas, alineadas a la izquierda y a la derecha:

$g->add_node('Paris', label => 'Ciudad del\namor');

Los atributos no necesitan ser especificados todos en la misma línea: las declaraciones sucesivas del mismo nodo tienen un efecto acumulativo, en el sentido de que cualquier atributo posterior simplemente se agrega a los existentes. Por ejemplo, las dos líneas siguientes son equivalentes a la anterior:

$g->add_node('Paris');
$g->add_node('Paris', label => 'Ciudad del\namor');

Tenga en cuenta que se pueden especificar varios atributos. Otros atributos incluyen:

height, width
establece la altura o anchura mínima
shape
establece la forma del nodo. Puede ser uno de: 'record', 'plaintext', 'ellipse', 'circle', 'egg', 'triangle', 'box', 'diamond', 'trapezium', 'parallelogram', 'house', 'hexagon', 'octagon'
fontsize
establece el tamaño de la etiqueta en puntos
fontname
establece el nombre de la familia de fuentes de la etiqueta
color
establece el color del contorno y el color de relleno predeterminado si el 'style' es 'filled' y 'fillcolor' no se especifica.

Un valor de color puede ser "h,s,v" (tono, saturación, brillo) números de punto flotante entre 0 y 1, o un nombre de color X11 como 'white', 'black', 'red', 'green', 'blue', 'yellow', 'magenta', 'cyan', o 'burlywood'

fillcolor
establece el color de relleno cuando el estilo es 'filled'. Si no se especifica, el 'fillcolor' cuando el 'style' es 'filled' será el mismo que el color del contorno.
style
establece el estilo del nodo. Puede ser uno de: 'filled', 'solid', 'dashed', 'dotted', 'bold', 'invis'
URL
establece la URL para el nodo en mapas de imagen y archivos PostScript. El valor de la cadena '\N' se reemplazará por el nombre del nodo. En los archivos PostScript, la información de URL está incrustada de tal manera que Acrobat Distiller crea archivos PDF con hipervínculos activos.

Si desea agregar un nodo anónimo, es decir, un nodo para el cual no desea generar un nombre, puede usar la siguiente forma, donde el módulo GraphViz genera un nombre y se lo devuelve. Luego puede usar este nombre más adelante para referirse a este nodo:

my $nodename = $g->add_node('label' => 'Ciudad romana');

Los nodos se pueden agrupar con el atributo "cluster", que se dibuja teniendo un rectángulo etiquetado alrededor de todos los nodos de un clúster. Una cadena vacía significa que no está agrupado.

$g->add_node('Londres', cluster => 'Europa');
$g->add_node('Ámsterdam', cluster => 'Europa');

Los clústeres también pueden tomar un hashref para que pueda establecer atributos:

my $eurocluster = {
  name      =>'Europa',
  style     =>'filled',
  fillcolor =>'lightgray',
  fontname  =>'arial',
  fontsize  =>'12',
};
$g->add_node('Londres', cluster => $eurocluster, @default_attrs);

Preguntas frecuentes

¿Por qué recibo mensajes de error como el siguiente?

Error: <stdin>:1: error de sintaxis cerca de la línea 1
contexto: digraph >>>  Graph <<<  {

Graphviz reserva algunas palabras como palabras clave, lo que significa que no pueden usarse como un ID, por ejemplo, para el nombre del grafo. Así que, no haga esto:

strict graph graph{...}
strict graph Graph{...}
strict graph strict{...}
etc...

Lo mismo para grafos no estrictos y digraphs. Sin embargo, puede añadir comillas dobles alrededor de tales palabras reservadas:

strict graph "graph"{...}

Aún mejor, use un nombre más significativo para su grafo...

Las palabras clave son: node, edge, graph, digraph, subgraph y strict. Los puntos cardinales no son palabras clave.

Vea palabras clave http://www.graphviz.org/content/dot-language en la discusión de la sintaxis de DOT para más detalles.

¿Cómo se maneja XXE dentro de XML?

Debido a los riesgos de seguridad con XXE en XML, Graphviz no soporta XML que contiene XXE. Por lo tanto, automáticamente evita que las entidades externas sean analizadas usando la opción no_xxe en XML::Twig al llamar a XML::Twig -> new(). Y por esta razón también los prerrequisitos en Makefile.PL especifican XML::Twig V 3.52.

Vea https://metacpan.org/pod/release/MIROD/XML-Twig-3.52/Twig.pm#no_xxe

NOTAS

Las versiones anteriores de GraphViz usaban una sintaxis ligeramente diferente para añadir nodos y aristas (con referencias a hashes). El nuevo formato es ligeramente más claro, aunque por el momento soportamos ambos. Use la nueva sintaxis clara, por favor.
