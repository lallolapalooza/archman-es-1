Graphics::ColorNames(3) Documentación de Perl aportada por el usuario Graphics::ColorNames(3)

NOMBRE

Graphics::ColorNames - define valores RGB para nombres de colores comunes

VERSIÓN

versión v3.5.0

SINOPSIS

use Graphics::ColorNames;
use Graphics::ColorNames::WWW;
$pal = Graphics::ColorNames->new( qw[ X WWW ] );
$rgb = $pal->hex('green');          # devuelve '00ff00'
$rgb = $pal->hex('green', '0x');    # devuelve '0x00ff00'
$rgb = $pal->hex('green', '#');     # devuelve '#00ff00'
$rgb = $pal->rgb('green');          # devuelve '0,255,0'
@rgb = $pal->rgb('green');          # devuelve (0, 255, 0)

DESCRIPCIÓN

Este módulo proporciona una interfaz común para obtener los valores RGB de los colores mediante nombres estándar. La intención es (1) proporcionar un módulo común que los autores puedan usar con otros módulos para especificar colores por nombre; y (2) liberar a los autores de módulos de tener que "reinventar la rueda" cada vez que decidan dar a los usuarios la opción de especificar un color por nombre en lugar de un valor RGB.

MÉTODOS

"new"

El constructor es el siguiente:

my $pal = Graphics::ColorNames->new( @schemes );

donde @schemes es un array de esquemas de color (paletas, diccionarios).

Un esquema de color válido puede ser el nombre de un esquema de color (como "X" o un nombre completo de módulo como "Graphics::ColorNames::X"), una referencia a un hash o subrutina de esquema de color, o la ruta o el manejador de archivo abierto para un rgb.txt archivo.

Si no se especifica ninguno, utiliza el esquema de color predeterminado "X" , que corresponde a los colores de X-Windows rgb.txt . Para la mayoría de los propósitos, esto es suficiente. Desde la versión v3.2.0, se actualizó para usar los colores del 2014-07-06, por lo que incluye los colores CSS estándar también.

Otros esquemas de color están disponibles en CPAN, por ejemplo Graphics::ColorNames::WWW.

Desde la versión 2.1002, los diccionarios de Color::Library también se pueden usar:

my $pal = Graphics::ColorNames->new( 'Color::Library::Dictionary::HTML' );

"rgb"

@rgb = $pal->rgb($name);
$rgb = $pal->rgb($name, $separator);

Si se llama en un contexto de lista, devuelve una terna.

Si se llama en un contexto escalar, devuelve una cadena separada por un separador opcional (cuyo valor predeterminado es una coma). Por ejemplo,

@rgb = $pal->rgb('blue');      # devuelve (0, 0, 255)
$rgb = $pal->rgb('blue', ','); # devuelve "0,0,255"

Los nombres de colores desconocidos devuelven listas o cadenas vacías, dependiendo del contexto.

Los nombres de colores no distinguen mayúsculas de minúsculas, y se ignoran los espacios o la puntuación. Por lo tanto, "Alice Blue" devuelve el mismo valor que "aliceblue", "ALICE-BLUE" y "a*lICEbl-ue". (Si está utilizando nombres de colores basados en la entrada del usuario, debe agregar una validación adicional de los nombres de colores.)

El valor devuelto está en el formato hexadecimal de seis dígitos utilizado en HTML y CSS (sin el '#' inicial). Para convertirlo en valores separados de rojo, verde y azul (entre 0 y 255), utilice la función "hex2tuple".

También puede especificar un nombre de archivo absoluto como esquema de color, si el archivo está en el mismo formato que el estándar rgb.txt archivo.

"hex"

$hex = $pal->hex($name, $prefix);

Devuelve un código RGB hexadecimal de 6 dígitos para el color. Si se especifica un prefijo opcional, se antepondrá esa cadena al código. Por ejemplo,

$hex = $pal->hex('blue', '#'); # devuelve "#0000ff"

Si el color no existe, devolverá una cadena vacía.

Un valor RGB hexadecimal en la forma de "#RRGGBB", "0xRRGGBB" o "RRGGBB" se devolverá a sí mismo:

$color = $pal->hex('#123abc');         # devuelve '123abc'

métodos de nombre de color cargados automáticamente

Los métodos de nombre de color cargados automáticamente se eliminaron en la versión v3.4.0.

"load_scheme"

$pal->load_scheme( $scheme );

Esto carga dinámicamente un esquema de color, que puede ser una referencia a un hash o una referencia a código.

EXPORTACIONES

"all_schemes"

my @schemes = all_schemes();

Devuelve una lista de todos los esquemas de color disponibles instalados en la máquina en el espacio de nombres Graphics::ColorNames .

El orden no tiene significado.

"hex2tuple"

Convierte una cadena hexadecimal en una terna.

"tuple2hex"

Convierte una terna en una cadena hexadecimal.

INTERFAZ VINCULADA

La interfaz estándar (antes de la versión 0.40) era a través de un hash vinculado:

tie %pal, 'Graphics::ColorNames', qw[ X WWW ];

Esta interfaz está obsoleta y se moverá a un módulo separado en el futuro.

ESQUEMAS DE COLOR PERSONALIZADOS

Puede agregar archivos de esquemas de nombres creando un módulo de Perl con el nombre "Graphics::ColorNames::SCHEMENAME" que tiene una subrutina llamada "NamesRgbTable" que devuelve un hash de nombres de colores y valores RGB. (Los esquemas con un espacio de nombres base diferente requerirán que se proporcione el espacio de nombres completo.)

Los nombres de colores deben estar en minúsculas, y los valores RGB deben ser números de 24 bits que contengan los valores rojo, verde y azul en orden de byte más significativo a menos significativo.

A continuación se muestra un ejemplo de esquema de nombres:

package Graphics::ColorNames::Metallic;
sub NamesRgbTable() {
  use integer;
  return {
    copper => 0xb87333,
    gold   => 0xcd7f32,
    silver => 0xe6e8fa,
  };
}

Utilizaría el esquema anterior de la siguiente manera:

tie %colors, 'Graphics::ColorNames', 'Metallic';

El comportamiento de especificar múltiples claves con el mismo nombre es indefinido en cuanto a cuál tiene prioridad.

A partir de la versión 2.10, se ignoran las mayúsculas/minúsculas, los espacios y la puntuación en los nombres de colores. Por lo tanto, un nombre como "Willy's Favorite Shade-of-Blue" se trata igual que "willysfavoroteshadeofblue". (Si su esquema no incluye entradas duplicadas con espacios y puntuación, entonces la versión mínima de Graphics::ColorNames debe ser 2.10 en sus requisitos.)

Un ejemplo de un módulo adicional es el módulo Graphics::ColorNames::Mozilla.

Desde la versión 1.03, "NamesRgbTable" también puede devolver una referencia a código:

package Graphics::ColorNames::Orange;
sub NamesRgbTable() {
  return sub {
    my $name = shift;
    return 0xffa500;
  };
}

Consulte Graphics::ColorNames::GrayScale para ver un ejemplo.

HOJA DE RUTA

Se planean los siguientes cambios en el futuro:

  • La interfaz vinculada se eliminará, pero se implementará en un módulo separado para los usuarios que deseen utilizarla.
  • El espacio de nombres para los esquemas de color se moverá a "Graphics::ColorNames::Schemes" pero se agregarán opciones para usar el esquema existente.

    Esto permitirá que los módulos se llamen como "Graphics::ColorNames::Tied" sin confundidos con esquemas de color.

  • Este módulo será reescrito para ser una clase basada en Moo.

VÉASE TAMBIÉN

Color::Library proporciona una extensa biblioteca de esquemas de color. Una diferencia notable es que soporta esquemas más complejos que contienen información adicional sobre colores individuales y mapean múltiples colores a un solo nombre.

Color::Rgb tiene una función similar a la de este módulo, pero analiza un rgb.txt archivo.

Graphics::ColorObject puede convertir entre RGB y otros tipos de espacio de color.

Graphics::ColorUtils también puede convertir entre RGB y otros tipos de espacio de color, y soporta RGB a partir de nombres en varios esquemas de color.

Acme::AutoColor proporciona subrutinas correspondientes a nombres de colores.
