Gc.Memprof - Memprof es un motor de perfilado que muestrea aleatoriamente las palabras de memoria asignadas.

MÓDULO

Módulo Gc.Memprof

DOCUMENTACIÓN

Módulo Memprof
: sig end

Memprof es un motor de perfilado que muestrea aleatoriamente las palabras de memoria asignadas. Cada palabra asignada tiene una probabilidad de ser muestreada igual a una tasa de muestreo configurable. Una vez que un bloque se muestrea, se rastrea. Un bloque rastreado activa una devolución de llamada definida por el usuario tan pronto como se asigna, se promueve o se libera.

Dado que los bloques se componen de varias palabras, un bloque puede potencialmente muestrearse varias veces. Si un bloque se muestrea varias veces, entonces cada una de las devoluciones de llamada se llama una vez por cada evento de este bloque: la multiplicidad se da en el campo n_samples de la estructura allocation.

Este motor hace posible implementar un perfilador de memoria de bajo overhead como una biblioteca OCaml.

Nota: esta API es EXPERIMENTAL. Puede cambiar sin previo aviso.

*)

El tipo de metadatos asociados con las asignaciones. Este es el tipo de registros pasados a la devolución de llamada activada por el muestreo de una asignación.

type ('minor, 'major) tracker = {
alloc_minor : allocation -> 'minor option ;
alloc_major : allocation -> 'major option ;
promote : 'minor -> 'major option ;
dealloc_minor : 'minor -> unit ;
dealloc_major : 'major -> unit ;
}

Un tracker ('minor, 'major) describe cómo memprof debe rastrear los bloques muestreados a lo largo de su vida útil, manteniendo una pieza de metadatos definida por el usuario para cada uno de ellos: 'minor es el tipo de metadatos a mantener para bloques menores, y 'major el tipo de metadatos para bloques mayores.

Las funciones miembro de un tracker se llaman devoluciones de llamada.

Si una devolución de llamada de asignación o promoción genera una excepción o devuelve None , memprof deja de rastrear el bloque correspondiente.

val null_tracker : ('minor, 'major) tracker

Las devoluciones de llamada predeterminadas simplemente devuelven None o ()

val start : sampling_rate:float -> ?callstack_size:int -> ('minor, 'major) tracker -> t

Inicia un perfil con los parámetros dados. Genera una excepción si un perfil ya está muestreando en el dominio actual.

El muestreo comienza inmediatamente. El parámetro sampling_rate es la tasa de muestreo en muestras por palabra (incluyendo cabeceras). Generalmente, con devoluciones de llamada baratas, una tasa de 1e-4 no tiene un efecto visible en el rendimiento, y 1e-3 causa que el programa sea un poco más lento. 0.0 <= sampling_rate <= 1.0.

El parámetro callstack_size es la longitud de la pila de llamadas registrada en cada muestra. Su valor predeterminado es max_int.

El parámetro tracker determina cómo rastrear los bloques muestreados a lo largo de su vida útil en el heap menor y mayor.

El muestreo y la ejecución de las devoluciones de llamada se deshabilitan temporalmente en el hilo actual al llamar a una devolución de llamada, por lo que las devoluciones de llamada no necesitan ser reentrantes si el programa es monohilo y monodominio. Sin embargo, si se utilizan hilos o múltiples dominios, es posible que varias devoluciones de llamada se ejecuten en paralelo. En este caso, las funciones de devolución de llamada deben ser reentrantes.

Tenga en cuenta que una devolución de llamada puede posponerse ligeramente después del evento real. La pila de llamadas pasada a una devolución de llamada de asignación siempre refleja con precisión la asignación, pero el estado del programa puede haber evolucionado entre la asignación y la llamada a la devolución de llamada.

Si se crea un nuevo hilo o dominio cuando el dominio actual está muestreado para un perfil, el hilo o dominio hijo se une a ese perfil (utilizando la misma sampling_rate , callstack_size y devoluciones de llamada tracker).

Una devolución de llamada de asignación siempre es ejecutada por el hilo que asignó el bloque. Si el hilo finaliza o el perfil se detiene antes de que se llame a la devolución de llamada, esta no se llama y el bloque no se rastrea.

Cada devolución de llamada posterior generalmente es ejecutada por el dominio que asignó el bloque. Si el dominio termina o el perfil se detiene antes de que se llame a la devolución de llamada, esta puede ser ejecutada por un dominio diferente.

Diferentes dominios pueden muestrear perfiles diferentes simultáneamente.

val stop : unit -> unit

Detiene el muestreo para el perfil actual. Falla si ningún perfil está muestreado en el dominio actual. Detiene el muestreo en todos los hilos y dominios que comparten el perfil.

Las devoluciones de llamada de promoción y desasignación de un perfil pueden ejecutarse después de que se llame a stop , hasta que se aplique discard al perfil.

Un perfil se detiene implícitamente (pero no se descarta) si todos los dominios e hilos que lo muestrean terminan.

val discard : t -> unit

Descarta todo el estado de perfilado para un perfil detenido, lo que impide futuras devoluciones de llamada para él. Genera una excepción si se llama en un perfil que no ha sido detenido.
