NOMBRE

GD::Graph - Módulo de trazado de gráficos para Perl 5

SINOPSIS

use GD::Graph::moduleName;

DESCRIPCIÓN

GD::Graph es un módulo de perl5 para crear gráficos usando el módulo GD. Se definen las siguientes clases para gráficos con ejes:

"GD::Graph::lines"
Crea un gráfico de líneas.
"GD::Graph::bars" y "GD::Graph::hbars"
Crea un gráfico de barras con barras verticales u horizontales.
"GD::Graph::points"
Crea un gráfico, mostrando los datos como puntos.
"GD::Graph::linespoints"
Combinación de líneas y puntos.
"GD::Graph::area"
Crea un gráfico, representando los datos como áreas bajo una línea.
"GD::Graph::mixed"
Crea un gráfico de tipo mixto, cualquier combinación de los anteriores. Por el momento esto es bastante limitado. Algunas de las opciones que se pueden usar con algunos de los tipos de gráfico individuales no funcionarán muy bien. Los gráficos de barras dibujados después de los gráficos de líneas o de puntos pueden ocultar los datos anteriores, y especificar bar_width no producirá los resultados que probablemente esperabas.

Tipos adicionales:

"GD::Graph::pie"
Crea un gráfico circular.

EJEMPLOS

Consulte el directorio de ejemplos en la distribución y lea el Makefile que se encuentra allí.

USO

Rellene un array de arrays con los valores x y los valores de los conjuntos de datos. Asegúrese de que cada array tenga el mismo tamaño, de lo contrario GD::Graph se quejará y se negará a compilar el gráfico.

@data = ( 
  ["1st","2nd","3rd","4th","5th","6th","7th", "8th", "9th"],
  [    1,    2,    5,    6,    3,  1.5,    1,     3,     4],
  [ sort { $a <=> $b } (1, 2, 5, 6, 3, 1.5, 1, 3, 4) ]
);

Si no tiene un valor para un punto en un determinado conjunto de datos, puede usar undef, y el punto se omitirá.

Cree un nuevo objeto GD::Graph llamando al método new en el tipo de gráfico que desea crear (chart es bars, hbars, lines, points, linespoints, mixed o pie).

my $graph = GD::Graph::chart->new(400, 300);

Establezca las opciones del gráfico.

$graph->set( 
    x_label           => 'X Label',
    y_label           => 'Y label',
    title             => 'Some simple graph',
    y_max_value       => 8,
    y_tick_number     => 8,
    y_label_skip      => 2 
) or die $graph->error;

y trace el gráfico.

my $gd = $graph->plot(\@data) or die $graph->error;

Luego haga lo que su versión actual de GD le permita hacer para guardar el archivo. Para versiones de GD anteriores a la 1.19 (o más recientes que la 2.15), haría algo como:

open(IMG, '>file.gif') or die $!;
binmode IMG;
print IMG $gd->gif;
close IMG;

y para versiones más nuevas (1.20 en adelante) escribiría

open(IMG, '>file.png') or die $!;
binmode IMG;
print IMG $gd->png;

o

open(IMG, '>file.gd2') or die $!;
binmode IMG;
print IMG $gd->gd2;

Luego también existe, por supuesto, la posibilidad de usar una versión más corta (para cada una de las funciones de exportación que GD admite):

print IMG $graph->plot(\@data)->gif;
print IMG $graph->plot(\@data)->png;
print IMG $graph->plot(\@data)->gd;
print IMG $graph->plot(\@data)->gd2;

Si desea escribir algo que no requiera que su código 'sepa' si usar gif o png, podría hacer algo como:

if ($gd->can('png')) { # blabla }

o puede usar el método de conveniencia "export_format":

my $format = $graph->export_format;
open(IMG, ">file.$format") or die $!;
binmode IMG;
print IMG $graph->plot(\@data)->$format();
close IMG;

o para programas CGI:

use CGI qw(:standard);
#...
my $format = $graph->export_format;
print header("image/$format");
binmode STDOUT;
print $graph->plot(\@data)->$format();

(los paréntesis después de $format son necesarios, para ayudar al compilador a decidir que se refiere a un nombre de método allí)

Vea en "SEE ALSO" las referencias a otra documentación, especialmente las FAQ.

MÉTODOS

Métodos para todos los gráficos

GD::Graph::chart->new([ancho,alto])
Crea un nuevo objeto $graph con ancho y alto opcionales. Ancho predeterminado = 400, alto predeterminado = 300. chart es bars, lines, points, linespoints, area, mixed o pie.
$graph->set_text_clr(nombre del color)
Establece el color del texto. Esto establecerá el color de los títulos, las etiquetas y las etiquetas de los ejes a nombre del color. Consulte también las opciones textclr, labelclr y axislabelclr.
$graph->set_title_font(especificación de fuente)
Establece la fuente que se utilizará para el título del gráfico. Consulte "FUENTES".
$graph->plot(\@datos)
Dibuja el gráfico y devuelve el objeto GD::Image.
$graph->set(atrib1 => valor1, atrib2 => valor2 ...)
Establece las opciones del gráfico. Consulte la sección OPCIONES.
$graph->get(atrib1, atrib2)
Devuelve una lista con los valores de los atributos. En contexto escalar devuelve solo el valor del primer atributo.
$graph->gd()
Obtiene el objeto GD::Image que se va a utilizar para dibujar. Puede hacer esto antes o después de llamar al método plot, para realizar su propio dibujo.

Nota: a partir de la versión actual, este objeto GD::Image siempre será basado en paleta, incluso si la versión instalada de GD admite imágenes en color verdadero.

Tenga en cuenta también que si dibuja sobre el objeto GD::Image antes de llamar al método plot, usted es responsable de asegurarse de que el color de fondo sea correcto y de establecer la transparencia.

$graph->export_format()
Consulta el formato de exportación de la biblioteca GD en uso. En contexto escalar, devuelve 'gif', 'png' o undef, lo cual es suficiente para la mayoría de los usuarios. En contexto de lista, devuelve una lista de todos los formatos que admite la versión actual de GD. Se puede llamar como método de clase u objeto.
$graph->can_do_ttf()
Devuelve verdadero si la biblioteca GD actual admite fuentes TrueType, falso en caso contrario. También se puede llamar como método de clase o método estático.

Métodos para gráficos circulares

$graph->set_label_font(especificación de fuente)
$graph->set_value_font(especificación de fuente)
Establece la fuente que se utilizará para la etiqueta del gráfico circular o los valores del gráfico circular. Consulte "FUENTES".

Métodos para gráficos con ejes.

$graph->set_x_label_font(especificación de fuente)
$graph->set_y_label_font(especificación de fuente)
$graph->set_x_axis_font(especificación de fuente)
$graph->set_y_axis_font(especificación de fuente)
$graph->set_values_font(especificación de fuente)
Establece la fuente para la etiqueta del eje x e y, las etiquetas de valores de los ejes x e y, y para los valores impresos sobre los puntos de datos. Consulte "FUENTES".
$graph->get_hotspot($conjunto_de_datos, $punto)
Experimental: Devuelve una especificación de coordenadas para un punto de un conjunto de datos. Devuelve una lista. Si no se especifica el punto, devuelve una lista de referencias a arrays para todos los puntos del conjunto de datos. Si tampoco se especifica el conjunto de datos, devuelve una lista de referencias a arrays para cada conjunto de datos. Consulte "PUNTOS ACTIVOS".
$graph->get_feature_coordinates($nombre_de_la_característica)
Experimental: Devuelve una especificación de coordenadas para una determinada característica del gráfico. Actualmente, las características definidas son axes, las coordenadas del rectángulo dentro de los ejes; x_label, y1_label e y2_label, las etiquetas impresas a lo largo de los ejes, con y_label proporcionado como alias de y1_label; y title, que es el cuadro de texto del título. Consulte "PUNTOS ACTIVOS".

OPCIONES

Opciones para todos los gráficos

width, height
El ancho y alto del lienzo en píxeles. Predeterminado: 400 x 300. NB Por el momento, estas son opciones de solo lectura. Si quieres establecer el tamaño de un gráfico, tendrás que hacerlo con el método new.
t_margin, b_margin, l_margin, r_margin
Margen superior, inferior, izquierdo y derecho del lienzo. Estos márgenes se dejarán en blanco. Predeterminado: 0 para todos.
logo
Nombre de un archivo de logotipo. Generalmente, este debería ser el mismo formato en el que tu versión de GD exporta imágenes. Actualmente, este archivo puede estar en cualquier formato que GD pueda importar, pero consulta GD si usas un archivo XPM y obtienes resultados inesperados.

Predeterminado: sin logotipo.

logo_resize, logo_position
Factor por el que redimensionar el logotipo, y la posición en el lienzo del logotipo. Los valores posibles para logo_position son 'LL', 'LR', 'UL' y 'UR'. (inferior e izquierda y derecha superior). Predeterminado: 'LR'.
transparent
Si se establece en un valor verdadero, la imagen producida tendrá el color de fondo marcado como transparente (ver también la opción bgclr). Predeterminado: 1.
interlaced
Si se establece en un valor verdadero, la imagen producida será entrelazada. Predeterminado: 1.

Nota: las versiones de GD superiores a 2.0 (es decir, desde que se restauró el soporte de GIF después de haber sido eliminado debido a problemas de patentes) no admiten el entrelazado de imágenes GIF. El soporte para PNG entrelazado y JPEG progresivo sigue disponible usando esta opción.

Colores

bgclr, fgclr, boxclr, accentclr, shadowclr
Colores de dibujo usados para el gráfico: fondo, primer plano (ejes y cuadrícula), color de relleno de la caja de ejes, acentos (contornos de barras, áreas y sectores) y sombra (actualmente solo para barras).

Todos los colores deben tener un valor válido como se describe en "COLOURS", excepto boxclr, que puede no estar definido, en cuyo caso la caja no se rellenará.

shadow_depth
Profundidad de una sombra, positiva para sombra a la derecha/abajo, negativa para sombra a la izquierda/arriba, 0 para sin sombra (predeterminado). Ver también las opciones "shadowclr" y "bar_spacing".
labelclr, axislabelclr, legendclr, valuesclr, textclr
Colores de texto usados para el gráfico: etiqueta (etiquetas para los ejes o el sector), etiqueta de eje (nombre inapropiado: valores impresos a lo largo de los ejes, o en un sector del gráfico circular), texto de leyenda, texto de valores mostrados y todo el demás texto.

Todos los colores deben tener un valor válido como se describe en "COLOURS".

dclrs (abreviatura de datacolours)
Esto controla los colores de las barras, líneas, marcadores o sectores del gráfico circular. Esto debería ser una referencia a un array de nombres de colores como se define en GD::Graph::colour ("perldoc GD::Graph::colour" para los nombres disponibles). 
$graph->set( dclrs => [ qw(green pink blue cyan) ] );

El primer (quinto, noveno) conjunto de datos será verde, el siguiente rosa, etc.

Un color puede ser "undef", en cuyo caso el conjunto de datos no se dibujará. Esto puede ser útil para conjuntos de barras acumuladas donde quieres que ciertas series de datos (a menudo la primera) no aparezcan, lo que puede usarse para emular barras de error (ver ejemplos 1-7 y 6-3 en la distribución).

Predeterminado: [ qw(lred lgreen lblue lyellow lpurple cyan lorange) ]

borderclrs
Esto controla los colores de los bordes de los conjuntos de datos de barras. Como dclrs, es una referencia a un array de nombres de colores como se define en GD::Graph::colour. Establecer un color de borde en "undef" significa que el borde no se dibujará.
cycle_clrs
Si se establece en un valor verdadero, las barras no tendrán un color de "dclrs" por conjunto de datos, sino por punto. La secuencia de colores será idéntica para cada conjunto de datos. Ten en cuenta que esto puede tener un efecto extraño si estás dibujando más de un conjunto de datos. Si esto se establece en un valor mayor que 1, el color del borde de las barras recorrerá cíclicamente los colores en "borderclrs".
accent_treshold
No es realmente un color, pero controla un aspecto visual: los acentos en las barras solo se dibujan cuando el ancho de una barra es mayor que este número de píxeles. Los acentos dentro de las áreas solo se dibujan cuando la distancia horizontal entre puntos es mayor que este número. Predeterminado 4

Opciones para gráficos con ejes.

opciones para gráficos de barras, líneas, puntos, líneas y puntos, mixtos y área.

x_label, y_label
Las etiquetas que se imprimirán junto a, o justo debajo de, los ejes. Ten en cuenta que si usas la opción two_axes necesitas usar y1_label y y2_label.
long_ticks, tick_length
Si long_ticks es un valor verdadero, las marcas se dibujarán con la misma longitud que los ejes. De lo contrario, las marcas se dibujarán con longitud tick_length. si tick_length es negativo, las marcas se dibujarán fuera de los ejes. Predeterminado: long_ticks = 0, tick_length = 4.

Estos atributos también se pueden establecer para los ejes x e y por separado con x_long_ticks, y_long_ticks, x_tick_length y y_tick_length.

x_ticks
Si x_ticks es un valor verdadero, se dibujarán marcas para el eje x. Estas marcas están sujetas a los valores de long_ticks y tick_length. Predeterminado: 1.
y_tick_number
Número de marcas a imprimir para el eje Y. Usa esto, junto con y_label_skip para controlar la apariencia de las marcas en el eje y. Predeterminado: 5.
y_number_format
Esto puede ser una cadena, o una referencia a una subrutina. Si es una cadena, se tomará como el primer argumento de un sprintf, con el valor como segundo argumento: 
$label = sprintf( $s->{y_number_format}, $value );

Si es una referencia de código, se ejecutará con el valor como argumento:

$label = &{$s->{y_number_format}}($value);

Esto puede ser útil, por ejemplo, si quieres reformatear tus valores en moneda, con el signo - en el lugar correcto. Algo como:

sub y_format
{
    my $value = shift;
    my $ret;
    if ($value >= 0)
    {
        $ret = sprintf("\$%d", $value * $refit);
    }
    else
    {
        $ret = sprintf("-\$%d", abs($value) * $refit);
    }
    return $ret;
}
$graph->set( 'y_number_format' => \&y_format );

(Sí, sé que esto puede ser mucho más corto y conciso)

Predeterminado: undef.

y1_number_format, y2_number_format
Al igual que con y_number_format, estos pueden ser una cadena o una referencia a una subrutina. Se utilizan como formatos para gráficos con dos escalas de eje y, de modo que se puedan usar formatos independientes.

Por motivos de compatibilidad, cada uno de estos recurrirá a y_number_format si no se especifica.

Predeterminado: undef para ambos.

x_label_skip, y_label_skip
Imprime cada x_label_skip-ésimo número bajo la marca en el eje x, y cada y_label_skip-ésimo número junto a la marca en el eje y. Predeterminado: 1 para ambos.
x_last_label_skip
De forma predeterminada, cuando x_label_skip se establece en algo mayor que 1, se imprimirá la última etiqueta del eje, incluso cuando no pertenezca a la serie normal que debería imprimirse. Establecer esto en un valor verdadero lo impide.

Por ejemplo, cuando tus valores X son los meses del año (es decir, Ene - Dic), y estableces x_label_skip en 3, los meses impresos en el eje serán Ene, Abr, Jul, Oct y Dic; aunque Dic no pertenece realmente a esa secuencia. Si no te gusta que se imprima el último mes, establece x_last_label_skip en un valor verdadero.

Esta opción no tiene efecto en otras circunstancias. Véase también x_tick_offset para otro método que hace que esto se vea mejor. Predeterminado: 0 para ambos

x_tick_offset
Cuando se usa x_label_skip, esto omitirá los primeros x_tick_offset valores en las etiquetas antes de comenzar a imprimir. Déjame dar un ejemplo. Si tienes una serie de etiquetas X como 
qw(Jan Feb Mar Apr May Jun Jul Aug Sep Oct Nov Dec)

y estableces x_label_skip en 3, verás marcas en el eje X para Ene, Abr, Jul, Oct y Dic. Esto no siempre es lo que se quiere. Si estableces x_tick_offset en 1, obtienes Feb, May, Ago, Nov y Dic, y si lo estableces en 2, obtienes Mar, Jun Sep y Dic, y esta última definitivamente se ve mejor. Una combinación de 6 y 5 también funciona bien para los meses.

Ten en cuenta que el valor de x_tick_offset es periódico. Esto significa que tendrá el mismo efecto para cada entero n en x_tick_offset + n * x_label_skip.

Véase también x_last_label_skip para otro método para influir en esto.

x_all_ticks
Fuerza la impresión de todas las marcas x, incluso si x_label_skip está establecido en un valor Predeterminado: 0.
x_label_position
Controla la posición de la etiqueta (título) del eje X. El valor de esto debe estar entre 0 y 1, donde 0 significa alineado a la izquierda, 1 significa alineado a la derecha, y 1/2 significa centrado. Predeterminado: 3/4
y_label_position
Controla la posición de ambas etiquetas (títulos) del eje Y. El valor de esto debe estar entre 0 y 1, donde 0 significa alineado abajo, 1 significa alineado arriba, y 1/2 significa centrado. Predeterminado: 1/2
x_labels_vertical
Si se establece en un valor verdadero, las etiquetas del eje X se imprimirán verticalmente. Esto puede ser útil en caso de que estas etiquetas se vuelvan muy largas. Predeterminado: 0.
x_plot_values, y_plot_values
Si se establece en un valor verdadero, los valores de las marcas en los ejes x o y se trazarán junto a la marca. Véase también x_label_skip, y_label_skip. Predeterminado: 1 para ambos.
box_axis
Dibuja los ejes como una caja, si es verdadero. Predeterminado: 1.
no_axes
No dibuja ningún eje. Si se establece en undef, se dibujan todos los ejes. Si se establece en 0, se dibujará el eje cero, solo para gráficos de barras. Si esto se establece en un valor verdadero, no se dibujará ningún eje. Las etiquetas de valores en los ejes y las marcas tampoco se dibujarán, pero las etiquetas de los ejes sí se dibujan. Predeterminado: undef.
two_axes
Usa dos ejes separados para el primer y segundo conjunto de datos. El primer conjunto de datos se establecerá contra el eje izquierdo, el segundo contra el eje derecho. Si se están trazando más de dos conjuntos de datos, se debe usar la opción use_axis para especificar qué conjuntos de datos usan qué eje.

Ten en cuenta que si usas esta opción, necesitas usar y1_label e y2_label, en lugar de solo y_label, si quieres que los dos ejes tengan etiquetas diferentes. Lo mismo ocurre con algunas otras opciones que comienzan con la letra 'y' y un guion bajo.

Predeterminado: 0.

use_axis
Si se están usando dos ejes y y se especifican más de dos conjuntos de datos, establece esta opción en una referencia a un array que contenga un valor de 1 o 2 (para las escalas izquierda y derecha respectivamente) para cada conjunto de datos que se esté trazando. Es decir, para trazar tres conjuntos de datos con el segundo en una escala diferente a la del primero y el tercero, establece esto en "[1,2,1]".

Predeterminado: [1,2].

zero_axis
Si se establece en un valor verdadero, siempre se dibujará el eje para los valores y de 0. Esto puede ser útil en caso de que tu gráfico contenga valores negativos, pero quieras que quede claro dónde está el valor cero. (véase también zero_axis_only y box_axes). Predeterminado: 0.
zero_axis_only
Si se establece en un valor verdadero, se dibujará el eje cero (véase zero_axis), y no se dibujará ningún eje en la parte inferior del gráfico. Las etiquetas para los valores X se colocarán en el eje cero. Predeterminado: 0.
y_max_value, y_min_value
Valor máximo y mínimo mostrado en el eje y.

El rango (y_min_value..y_max_value) tiene que incluir todos los valores de los puntos de datos, o GD::Graph morirá con un mensaje.

Para gráficos de barras y de área, el rango (y_min_value..y_max_value) tiene que incluir 0. Si no lo hace, los valores se adaptarán antes de intentar dibujar el gráfico.

Predeterminado: Calculado a partir de los conjuntos de datos.

y1_max_value, y1_min_value, y2_max_value, y2_min_value
Valores máximo y mínimo para los ejes izquierdo (y1) y derecho (y2) cuando two_axes es un valor verdadero. Tienen precedencia sobre y_min_value e y_max_value.

De forma predeterminada, el 0 del eje izquierdo está alineado con el 0 del eje derecho; esto no es cierto si se define cualquiera de estas opciones.

En caso contrario, el comportamiento y los valores predeterminados son como con y_max_value e y_min_value.

y_min_range, y1_min_range, y2_min_range
Rango mínimo entre los valores mínimo y máximo en el eje y que se usa para ajustar los valores calculados y_min_value e y_max_value.

NOTA que el autor de la característica la implementó solo para el caso de two_axes; los parches son bienvenidos para ampliarla a un solo eje y.

Si two_axes es un valor verdadero, entonces y1_min_range e y2_min_range tienen precedencia sobre el valor de y_min_range.

Predeterminado: undef

axis_space
Este espacio se dejará en blanco entre los ejes y el texto del valor de la marca. Predeterminado: 4.
text_space
Este espacio se dejará abierto entre los elementos de texto y el gráfico (los elementos de texto son el título y las etiquetas de los ejes.

Predeterminado: 8.

cumulate
Si este atributo se establece en un valor verdadero, los conjuntos de datos se acumularán. Esto significa que se apilarán uno encima del otro. Un efecto secundario de esto es que "overwrite" se establecerá en un valor verdadero.

Notas: Por el momento, esto solo funciona para gráficos de barras y de áreas.

Si tiene valores negativos en sus conjuntos de datos, establecer esta opción podría producir resultados extraños. Por supuesto, el gráfico en sí mismo sería bastante carente de sentido.

overwrite
Si se establece en 0, las barras de diferentes conjuntos de datos se dibujarán una al lado de la otra. Si se establece en 1, se dibujarán una delante de la otra. Predeterminado: 0.

Nota: Establecer overwrite en 2 para producir conjuntos acumulativos está obsoleto y puede desaparecer en futuras versiones de GD::Graph. En su lugar, consulte el atributo "cumulate".

correct_width
Si esto se establece en un valor verdadero y "x_tick_number" es falso, entonces el ancho del gráfico (o la altura para gráficos rotados como "GD::Graph::hbar") se recalculará para asegurarse de que cada punto de datos tenga exactamente un número entero de píxeles de ancho. Probablemente nunca quiera modificar esto.

Cuando este valor es verdadero, deberá asegurarse de que el número de puntos de datos sea menor que el número de píxeles en el área de trazado del gráfico. Si obtiene errores que indican que su tamaño horizontal es demasiado pequeño, es posible que deba desactivar esto manualmente, o considerar usar algo distinto a un tipo de barra para su gráfico.

Predeterminado: 1 para barras, calculado en tiempo de ejecución para gráficos mixtos, 0 para los demás.

Trazar los valores de los puntos de datos con el punto de datos

A veces querrá trazar el valor de un punto de datos o de una barra por encima del punto de datos para mayor claridad. GD::Graph le permite controlar esto de forma genérica, o incluso punto por punto.

show_values
Establezca esto en 1 para mostrar el valor de cada punto de datos por encima del punto o de la barra misma. No se hace ningún esfuerzo para asegurar que haya suficiente espacio para el texto.

Establezca esto en un objeto GD::Graph::Data, o en una referencia a un array de la misma forma, con las mismas dimensiones que su objeto de datos que pasa al método plot. La razón de esta opción es que le permite hacer una copia de su conjunto de datos y establecer selectivamente puntos en "undef" para deshabilitar su trazado.

my $data = GD::Graph::Data->new( 
  [ [ 'A', 'B', 'C' ], [ 1, 2, 3 ], [ 11, 12, 13 ] ]);
my $values = $data->copy;
$values->set_y(1, 1, undef);
$values->set_y(2, 0, undef);
$graph->set(show_values => $values);
$graph->plot($data);

Predeterminado: 0.

values_vertical
Si se establece en un valor verdadero, los valores se imprimirán verticalmente, en lugar de horizontalmente. Esto puede ser útil si los valores son números largos. Predeterminado: 0.
values_space
Espacio a insertar entre el punto de datos y el valor a imprimir. Predeterminado: 4.
values_format
Cómo formatear los valores para su visualización. Consulte y_number_format para obtener más información. Predeterminado: undef.
hide_overlapping_values
Si se establece en un valor verdadero, los valores que se salen del espacio del gráfico se ocultan. La opción es EXPERIMENTAL, solo funciona para barras, el texto aún puede superponerse con otras barras y etiquetas, más útil solo con texto en la misma dirección que las barras. Predeterminado: undef

Opciones para gráficos con un eje X numérico

Antes que nada: GD::Graph no admite un eje x numérico de la manera en que debería. Los datos para los ejes X deben estar igualmente espaciados. Entendido esto: Hay cierto soporte para hacer que la impresión de gráficos con valores numéricos en el eje X sea un poco mejor, gracias a Scott Prahl. Si la opción "x_tick_number" se establece en un valor definido, GD::Graph intentará tratar los datos X como numéricos.

Las opciones adicionales son:

x_tick_number
Si se establece en 'auto', GD::Graph intentará formatear el eje X de una manera agradable, basándose en los valores X reales. Si se establece en un número, ese es el número de marcas que obtendrá. Si se establece en undef, GD::Graph tratará los datos X como etiquetas. Predeterminado: undef.
x_min_value, x_max_value
El valor mínimo y máximo a usar para el eje X. Predeterminado: calculado.
x_min_range
Rango mínimo del eje x.

Predeterminado: undef

x_number_format
Consulte y_number_format
x_label_skip
Consulte y_label_skip

Opciones para gráficos con barras

bar_width
El ancho de una barra en píxeles. Consulte también "bar_spacing". Use "bar_width" si desea tener barras de ancho fijo, sin importar cuán ancho se vuelva el gráfico. Predeterminado: lo más ancho posible, dentro de las restricciones del tamaño del gráfico y la configuración de "bar_spacing".
bar_spacing
Número de píxeles a dejar libres entre barras. Esto funciona bien en la mayoría de los casos, pero en algunas plataformas, un valor de 1 se redondeará a 0. Use "bar_spacing" para obtener una cantidad fija de espacio entre barras, con anchos de barra variables, dependiendo del ancho del gráfico. Tenga en cuenta que si "bar_width" también está establecido, esta configuración se ignorará y se calculará automáticamente. Predeterminado: 0
bargroup_spacing
Número de píxeles (además de lo que se especifique en "bar_spacing") a dejar entre grupos de barras cuando se muestran múltiples conjuntos de datos. A diferencia de "bar_spacing", sin embargo, este parámetro mantendrá su valor si "bar_width" está establecido.

Opciones para gráficos con líneas

line_types
Qué tipos de línea usar para gráficos de lines y linespoints. Esto debería ser una referencia a un array de números: 
$graph->set( line_types => [3, 2, 4] );

Los tipos de línea disponibles son 1: sólida, 2: discontinua, 3: punteada, 4: punto-raya.

Predeterminado: [1] (usar siempre sólido)

line_type_scale
Controla la longitud de los guiones en los tipos de línea. predeterminado: 6.
line_width
El ancho de la línea utilizada en los gráficos lines y linespoints, en píxeles. Predeterminado: 1.
skip_undef
Para todos los demás tipos de gráficos de ejes, el comportamiento predeterminado es (por su naturaleza) no dibujar un punto cuando el valor Y es "undef". Para los gráficos de líneas el punto también se omite, pero la línea se dibuja entre los puntos n-1 a n+1 directamente. Si "skip_undef" tiene un valor verdadero, habrá un hueco en el gráfico donde un valor Y no está definido.

Tenga en cuenta que no se dibujará una línea a menos que existan al menos dos puntos de datos consecutivos que tengan un valor definido. El siguiente conjunto de datos solo trazará una línea muy corta hacia el final si "skip_undef" está establecido:

@data = (
  [ qw( Jan Feb Mar Apr May Jun Jul Aug Sep Oct ) ],
  [ 1, undef, 2, undef, 3, undef, 4, undef, 5, 6 ]
);

Esta opción es útil cuando tiene un hueco consecutivo en sus datos, o con gráficos linespoints. Si tiene datos donde hay huecos intermitentes, tenga cuidado cuando use esto. Valor predeterminado: 0

Opciones para gráficos con puntos

markers
Esto controla el orden de los marcadores en los gráficos points y linespoints. Esto debería ser una referencia a un array de números: 
$graph->set( markers => [3, 5, 6] );

Los marcadores disponibles son: 1: cuadrado relleno, 2: cuadrado vacío, 3: cruz horizontal, 4: cruz diagonal, 5: rombo relleno, 6: rombo vacío, 7: círculo relleno, 8: círculo vacío, 9: línea horizontal, 10: línea vertical. Tenga en cuenta que los dos últimos no forman parte de la lista predeterminada.

Predeterminado: [1,2,3,4,5,6,7,8]

marker_size
El tamaño de los marcadores utilizados en los gráficos points y linespoints, en píxeles. Predeterminado: 4.

Opciones para gráficos mixtos

types
Una referencia a un array con tipos de gráfico, en el mismo orden que los conjuntos de datos. Los valores posibles son: 
$graph->set( types => [qw(lines bars points area linespoints)] );
$graph->set( types => ['lines', undef, undef, 'bars'] );

los valores que no estén definidos o sean desconocidos se establecerán en "default_type".

Predeterminado: todos establecidos en "default_type"

default_type
El tipo de gráfico a dibujar para los conjuntos de datos que no tienen ningún tipo establecido, o que tienen un tipo desconocido establecido.

Predeterminado: lines

Leyendas de gráficos (solo gráficos de tipo ejes)

Por el momento el soporte de leyendas es mínimo.

Métodos

$graph->set_legend(@legend_keys);
Establece las claves para la leyenda. Los elementos de @legend_keys corresponden a los conjuntos de datos tal como se proporcionan a plot().

Si una clave es undef o una cadena vacía, la entrada de la leyenda se omitirá.

$graph->set_legend_font(nombre de fuente);
Establece la fuente para el texto de la leyenda (consulte "FONTS"). Predeterminado: GD::gdTinyFont.

Opciones

legend_placement
Dónde colocar la leyenda. Esto debería ser una clave de dos letras de la forma: 'B[LCR]|R[TCB]'. La primera letra indica la ubicación (Bottom o Right), y la segunda letra la alineación (Left, Right, Center, Top, o Bottom). Predeterminado: 'BC'

Si la leyenda se coloca en la parte inferior, se harán algunos cálculos para asegurar que haya un ajuste de línea 'inteligente'. Si la leyenda se coloca a la derecha, todas las entradas se colocarán una debajo de otra.

legend_spacing
El número de píxeles a colocar alrededor de un elemento de la leyenda, y entre un 'marcador' de la leyenda y el texto. Predeterminado: 4
legend_marker_width, legend_marker_height
El ancho y alto de un 'marcador' de la leyenda en píxeles. Predeterminados: 12, 8
lg_cols
Si, por alguna razón, necesita forzar que la leyenda en la parte inferior tenga un número específico de columnas, puede usar esto. Predeterminado: calculado

Opciones para gráficos circulares

3d
Si se establece en un valor verdadero, el gráfico circular se dibujará con un aspecto 3d. Predeterminado: 1.
pie_height
El grosor del gráfico circular cuando 3d es verdadero. Predeterminado: 0.1 x altura.
start_angle
El ángulo en el que se mostrará la primera porción de datos, siendo 0 grados las "6 en punto". Predeterminado: 0.
suppress_angle
Si una porción del gráfico circular es menor que este ángulo (en grados), no se dibujará una etiqueta sobre ella. Predeterminado: 0.
label
Imprime esta etiqueta debajo del gráfico circular. Predeterminado: undef.

COLORES

Todas las referencias a colores en las opciones de este módulo se han abreviado como clr. La razón principal de esto fue que no quería admitir dos grafías para la misma palabra ('colour' y 'color')

Siempre que se requiera un color, se debe usar un nombre de color del paquete GD::Graph::colour. "perldoc GD::Graph::colour" debería proporcionarte la documentación de ese módulo, que contiene todos los nombres de colores válidos. Probablemente cambiaré esto para leer el archivo rgb.txt del sistema si está disponible.

FUENTES

Dependiendo de su versión de GD, esto acepta tanto las fuentes integradas de GD como el nombre de un archivo de fuente TrueType. En el caso de una fuente TrueType, debe especificar el tamaño de la fuente. Consulte GD::Text para obtener más detalles y otras cosas, ya que todo el manejo de fuentes en GD::Graph se delega allí.

Ejemplos:

$graph->set_title_font('/fonts/arial.ttf', 18);
$graph->set_legend_font(gdTinyFont);
$graph->set_legend_font(
    ['verdana', 'arial', gdMediumBoldFont], 12)

(La discusión anterior se basa en GD::Text 0.65. Las versiones anteriores tienen un comportamiento más restrictivo).

PUNTOS ACTIVOS

Tenga en cuenta que esta es una característica experimental, y su interfaz puede, y probablemente lo hará, cambiar en el futuro. Actualmente no funciona para gráficos de área o gráficos circulares.

Un problema conocido con los puntos activos para GD::Graph::hbars es que las coordenadas x e y salen transpuestas. Esto probablemente no se corregirá hasta el rediseño de esta sección

GD::Graph mantiene un conjunto interno de coordenadas para cada punto de datos y para ciertas características de un gráfico, como el título y las etiquetas de los ejes. Esta especificación es muy similar a la especificación de mapas de imágenes HTML, y de hecho existe principalmente para ese propósito. Puede acceder a estos puntos activos con el método "get_hotspot" para un punto de datos, y "get_feature_coordinates" para las características del gráfico.

El método <get_hotspot> acepta dos argumentos opcionales, el número del conjunto de datos que le interesa, y el número del punto en ese conjunto de datos que le interesa. Cuando se llama con dos argumentos, el método devuelve una lista de una de las siguientes formas:

'rect', x1, y1, x2, y2
'poly', x1, y1, x2, y2, x3, y3, ....
'line', xs, ys, xe, ye, width

Los parámetros para "rect" son las coordenadas de las esquinas del rectángulo, los parámetros para "poly" son las coordenadas de los vértices del polígono, y los parámetros para la "line" son las coordenadas para el punto de inicio y fin, y el ancho de la línea. Debería ser posible traducir casi directamente estas listas a especificaciones de mapas de imágenes HTML.

Si se omite el segundo argumento de "get_hotspot", se devolverá una lista de referencias a arrays. Esta lista representa todos los puntos en el conjunto de datos especificado, y cada array referenciado es de la forma descrita anteriormente.

['rect', x1, y1, x2, y2 ], ['rect', x1, y1, x2, y2], ...

si se omiten ambos argumentos de "get_hotspot", la lista que se devuelve contendrá referencias a arrays para cada conjunto de datos, que a su vez contienen referencias a arrays para cada punto.

[
  ['rect', x1, y1, x2, y2 ], ['rect', x1, y1, x2, y2], ...
],
[
  ['line', xs, ys, xe, ye, w], ['line', xs, ys, xe, ye, w], ...
],...

El método "get_feature", cuando se llama con el nombre de una característica, devuelve una única referencia a array con un tipo y coordenadas como se describe anteriormente. Cuando se llama sin argumentos, se devuelve una referencia a hash con las claves siendo todas las características actualmente definidas y establecidas, y los valores referencias a arrays con el tipo y las coordenadas para cada una de esas características.

MANEJO DE ERRORES

Los objetos GD::Graph heredan de la clase GD::Graph::Error (no al revés), por lo que se comportan de la misma manera. La característica principal de ese comportamiento es que tienes el método error() disponible para obtener algo de información sobre qué salió mal. Todos los métodos de GD::Graph devuelven undef si algo salió mal, por lo que deberías poder escribir programas seguros como este:

my $graph = GD::Graph->new()    or die GD::Graph->error;
$graph->set( %attributes )      or die $graph->error;
$graph->plot($gdg_data)         or die $graph->error;

Es posible un uso más avanzado, y hay algunas advertencias con este manejo de errores, que se explican todas en GD::Graph::Error.

Desafortunadamente, es casi imposible recuperarse de forma controlada de un error en GD::Graph, por lo que realmente deberías deshacerte del objeto y recrearlo desde cero si quieres recuperarte. Por ejemplo, para ajustar el atributo correct_width si obtienes el error "Horizontal size too small" o "Vertical size too small" (en el caso de hbar), podrías hacer algo como:

sub plot_graph
{
    my $data    = shift;
    my %attribs = @_;
    my $graph   = GD::Graph::bars->new()
       or die GD::Graph->error;
    $graph->set(%attribs)     or die $graph->error;
    $graph->plot($data)       or die $graph->error;
}

my $gd;
eval { $gd = plot_graph(\@data, %attribs) };
if ($@)
{
    die $@ unless $@ =~ /size too small/;
    $gd = plot_graph(\@data, %attribs, correct_width => 0);
}

Por supuesto, también podrías ajustar el ancho de esta manera, y puedes comprobar otros errores.

NOTAS

Como con todos los Módulos para Perl: Por favor, cíñete al uso de la interfaz. Si intentas trastear demasiado con el conocimiento de los aspectos internos de este módulo, podrías quemarte. Puedo cambiarlos en cualquier momento.

ERRORES

Los objetos GD::Graph no se pueden reutilizar. Para crear un nuevo gráfico, debe crear un nuevo objeto GD::Graph.

Los gráficos rotados (aquellos con el eje X a la izquierda) actualmente solo se pueden crear para barras. Con un poco de trabajo, esto funcionará también para todos los demás. Por favor, tenga paciencia :)

Otros errores pendientes probablemente se puedan encontrar (por desgracia) en la cola de RT para esta distribución, en http://rt.cpan.org/Public/Dist/Display.html?Name=GDGraph

Si cree que ha encontrado un error, compruebe primero si ya se ha informado. Si no es así, hágalo (puede usar la interfaz web anterior o enviar un correo electrónico a <bug-GDGraph@rt.cpan.org>). Los informes de errores deben contener tantos de los siguientes elementos como sea posible:

  • una descripción concisa del comportamiento defectuoso y en qué difiere de lo que esperaba,
  • las versiones de Perl, GD::Graph y GD que está usando,
  • un breve script de demostración que muestre el error en acción,
  • un parche que lo corrija. :-)

De todos estos, el tercero es probablemente el más importante, ya que producir un caso de prueba generalmente hace que la explicación sea mucho más concisa y comprensible, además de hacer mucho más sencillo demostrar que el error ha sido corregido. Como beneficio incidental, si el error es de hecho causado por algún código fuera de GD::Graph, se hará evidente mientras escribe el caso de prueba, ahorrando así tiempo y confusión a todos los implicados.
