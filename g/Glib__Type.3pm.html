Glib::Type - Utilidades

para trabajar con el s
istema de tipos de GLib

DESCRIPCIÓ

N

Este paquete define varias utilidades para trabajar con el sistema de tipos de GLib desde Perl. Debido a algunas diferencias fundamentales en cómo funcionan los sistemas de tipos de GLib y Perl, una cantidad considerable de la magia del enlace se filtra, y puedes encontrar la mayoría de eso en las funciones "Glib::Type::register*", que registran nuevos tipos con el sistema de tipos de

GLib.

La mayoría del resto de las funciones proporcionan funcionalidad de introspecció

n, como listar propiedades y valores y otras cosas geniales que se usan principal
mente en el generador de documentación de referencia de Glib (ver Glib::GenPod).

Registra e inicializa un nuevo tipo Glib::Enum con los "values" proporcionados. Esto crea un tipo correctamente registrado en GLib para que pueda usarse como tipo de parámetro o de retorno de propiedades y señales creadas con "Glib::Type->register" o "Glib::Object::Su

La lista de valores se usa para crear los "nicknames" (apodos) que se usan en el código Perl general; los valores numéricos reales usados a nivel C se asignan automáticamente, empezando con 1. Si necesitas especificar un valor numérico particular para un apodo, usa en su lugar una referencia a un arreglo que contenga el apodo y el valor numérico. Puedes mezclar y combinar los dos

estilos. 
Glib::Type->register_enum ('MyFoo::Bar',
        'value-one',            # asignado 1
        'value-two',            # asignado 2
        ['value-three' => 15 ], # explícito 15
        ['value-four' => 35 ],  # explícito 35
        'value-five',           # asignado 5
)
;

Glib::Type->register_object ($paquete_padre, $paquete_nuevo, ...

)
  • $paquete_padre (cadena) nombre del paquete padre, que debe ser un derivado de Glib::
    • Object.
  • $paquete_nuevo (cadena) normalmente
    • __PACKAGE__.
  • ... (lista) pares clav
    • e/valor que controlan
cómo se crea la clase.

Registra paquete_nuevo como un derivado oficialmente sancionado por GLib del (derivado de GObject) paquete_padre. Esto configura automáticamente una entrada @ISA para ti, y crea un nuevo GObjectClass

internamente.

Los parámetros ... son pares clave/valor, que actualmente

admiten:
signals =>
HASHREF
La clave "signals" contiene un hash, indexado por nombres de señales, que describe cómo configurar las señales para paquete_nuevo.

Si el valor es una referencia a código, la señal nombrada debe existir en algún lugar de paquete_padre o en su linaje; la referencia a código se usará para anular el cierre de clase de esa señal. Esta es la forma oficialmente sancionada de anular métodos virtuales en Glib::Objects. El valor puede ser una cadena en lugar de una referencia a código, en cuyo caso se usará el sub con ese nombre en paquete_nuevo. (La función no debería ser heredada.

)

Si el valor es una referencia a hash, la clave será el no

mbre de una nueva señal creada con las propiedade
s definidas en el hash. Todas las propiedades so
n opcionales, con valores predeterminados proporcionados:
class_closure => subrutina o
undef
Usa esta referencia a código (o nombre de sub) como cierre de clase (es decir, el manejador predeterminado de la señal). Si no se especifica, se usa "do_signal_name", en el paquete
actual.
return_type => nombre de paquete o
undef
Tipo de retorno de la señal. Si no se especifica, la señal tiene retorno
void.
param_types =>
ARRAYREF
Referencia a una lista de tipos de parámetros (nombres de paquete), omitiendo la instancia y los datos de usuario. Las devoluciones de llamada conectadas a esta señal recibirán el objeto de instancia como primer argumento, seguido de los argumentos con los tipos listados aquí, y finalmente por cualquier dato de usuario que se haya proporcionado cuando se conectó la devolución de llamada. No especificar esta clave es equivalente a proporcionar una lista vacía, lo que en realidad significa instancia y posiblemente
datos.
flags => Glib::
SignalFlags
Banderas que describen las propiedades de esta señal. Consulta la descripción de GSignalFlags en la referencia de la API C de GObject para una descripción
completa.
accumulator => subrutina o
undef
El acumulador de señales es una devolución de llamada especial que se puede usar para recopilar los valores de retorno
de las diversas devoluciones de llamada que se invocan durante una emisión de señal. Generalmente, puedes omitir este
parámetro; los acumuladores personalizados se usan para hacer cosas como detener la propagación de la señal por valo
r de retorno o crear una lista de retornos, etc. Consulta "SIGNALS" en Glib::Object::Subclass para más detalles.
properties =>
ARRAYREF
Matriz de objetos Glib::ParamSpec, cada uno describiendo una propiedad de objeto a añadir al nuevo tipo. Estas propiedades están disponibles para su uso por todo el código que pueda acceder al objeto, independientemente del lenguaje de implementación. Consulta Glib::ParamSpec. Esta lista puede estar vacía; si no lo está, se llamarán a las funciones "GET_PROPERTY" y "SET_PROPERTY" en $paquete_nuevo para obtener y establecer los valores. Ten en cuenta que una propiedad de objeto es solo un mecanismo para obtener y establecer un valor -- no implica almacenamiento. Sin embargo, como conveniencia, Glib::Object proporciona implementaciones predeterminadas para GET_PROPERTY y SET_PROPERTY que usan los apodos de las propiedades como claves de hash en la variable del objeto para el almacenamiento.

Además, puedes especificar ParamSpecs como un hash descriptivo en lugar de como un objeto; esta forma te permite proporcionar métodos de obtención y establecimiento explícitos que anulan GET_PROPERY y SET_PROPERTY. El getter y el setter son opcionales en la forma de hash. Por

ejemplo: 
Glib::Type->register_object ('Glib::Object', 'Foo',
   properties => [
      # especificado normalmente
      Glib::ParamSpec->string (...),
      # especificado explícitamente
      {
         pspec => Glib::ParamSpec->int (...),
         set => sub {
            my ($object, $newval) = @_;
            ...
         },
         get => sub {
            my ($object) = @_;
            ...
            return $val;
         },
      },
] );

Puedes mezclar los dos estilos de declaración como desees. Si tienes métodos individuales "get_foo" / "set_foo" con el código operativo para una propiedad, entonces la forma "get"/"set" es una manera práctica de ir directamente

a
eso.
interfaces =>
ARRAYREF
Matriz de nombres de paquetes de interfaz que el nuevo objeto implementa. Las interfaces son la forma de GObject de hacer herencia múltiple, así que, en Perl, los nombres de paquetes se antepondrán a @ISA y ciertos métodos ALLCAPS heredables y anulables se llamarán automáti
camente cuando sea necesario. Qué métodos e
xactamente depende de la interfaz --
Gtk2::CellEditable por ejemplo usa START_ED
ITING, EDITING_DONE, y REMOVE_WIDGET.
