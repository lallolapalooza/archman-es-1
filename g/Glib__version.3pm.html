DESCRIPCIÓ

N

Tanto el módulo Glib como la biblioteca C GLib son trabajos en progreso, y sus interfaces crecen con el tiempo. A medida que se añaden más funciones a cada uno, y tu código usa esas nuevas funciones, introducirás dependencias específicas de la versión, y naturalmente, querrás poder programar alrededor de ellas. Aquí entra la API de

versionado.

Para módulos Perl simples, un único número de versión es suficiente; sin embargo, Glib es un enlace a otra biblioteca de software, y esto introduce cierta complejidad. Tenemos tres versiones que especifican completamente la API disponible para

ti.
Versión de los enlaces
Perl
Los módulos Perl usan un número de versión, y Glib no es una excepción. $Glib::VERSION es la versión del módulo Glib actual. Por convención ad hoc, los módulos gtk2-perl generalmente usan números de versión en la forma x.yyz, donde los valores pares de yy denotan versiones estables y z es un nivel de parche.

¿Cuál uso y

¿Dónde usas cada versión? Depende completamente de lo que estés haciendo. Lo explicaremos con un

ejemplo:
o Usa la versión del módulo Perl para problemas de soporte de
enlaces
Necesitas registrar un nuevo enum para usar como tipo de una propiedad de objeto. Esto es algo que puedes hacer con todas las versiones de la biblioteca C subyacente, pero que no fue soportado en el módulo Perl Glib hasta $Glib::VERSION >= 1.
040.
o Usa la versión enlazada para funciones de la
biblioteca
Quieres llamar a Glib::set_application_name para establecer un nombre legible para tu aplicación (que es usado por varias partes de Gtk2 y Gnome2). g_set_application_name() (la función C subyacente) fue añadida en la versión 2.2.0 de glib, y el soporte para ella fue introducido en el módulo Perl Glib en la versión 1.040. Sin embargo, puedes compilar el módulo Perl contra cualquier versión estable 2.x.x de glib, ¡así que podrías no tener esa función disponible aunque tu módulo Glib sea suficientemente nuevo!
Por lo tanto, necesitas verificar dos cosas para ver si esta función está disponible: 
if ($Glib::VERSION >= 1.040 && Glib->CHECK_VERSION (2,2,0)) {
    # está disponible, ¡y podemos llamarla!
    Glib::set_application_name ('Mi Aplicación Genial')
; }

Ahora, ¿qué pasa si instalaste el módulo Perl cuando tu sistema tenía glib 2.0.6, y actualizaste glib a 2.4.1? ¿No estaría g_set_application_name() disponible? Bueno, está ahí, bajo el capó, pero los enlaces fueron compilados cuando no estaba ahí, ¡así que no podrás llamarla! Es por eso que verificamos la versión "enlazada" o en tiempo de compilación. Por cierto, para habilitar el soporte para la nueva función, necesitarías reinstalar (o actualizar) el módulo

Perl.
o Usa la versión enlazada para soluciones alternativas en tiempo de
ejecución
Supongamos que hay una función cuya API no cambió, pero cuya implementación tenía un error en una versión que fue corregido en otra versión. Para determinar si necesitas aplicar una solución alternativa, verificarías la versión que está siendo usada realmente en tiempo de ejecución. 
if (Glib::major_version == 2 &&
    Glib::minor_version == 2 &&
    Glib::micro_version == 1) {
   # solución alternativa para el error que existe solo en glib 2.
2.1. }
