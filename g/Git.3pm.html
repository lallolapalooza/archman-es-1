DESCRIPCIÓ

N

Este módulo proporciona a los scripts de Perl una manera fácil de interactuar con el sistema de control de versiones Git. Los módulos tienen una manera fácil y bien probada de llamar a comandos arbitrarios de Git; en el futuro, la interfaz también proporcionará métodos especializados para realizar fácilmente operaciones que no son totalmente triviales de hacer a través de la interfaz de comandos

genérica.

Aunque algunos comandos pueden ejecutarse fuera de cualquier contexto (por ejemplo, 'version' o 'init'), la mayoría de las operaciones requieren un contexto de repositorio, lo que en la práctica significa obtener una instancia del objeto Git utilizando el constructor repository(). (En el futuro, también tendremos un constructor new_repository().) Todos los comandos llamados como métodos del objeto se ejecutan entonces en el contexto del

repositorio.

Parte del "estado del repositorio" es también información sobre la ruta a la copia de trabajo adjunta (a menos que trabajes con un repositorio desnudo). También puedes navegar dentro de la copia de trabajo utilizando el método wc_chdir(). (Ten en cuenta que el objeto repositorio es autónomo y no cambiará el directorio de trabajo de tu proceso.

)

POR HACER: En el futuro, también podríamos

hacer 
my $remoterepo = $repo->remote_repository (Name => 'cogito', Branch => 'master');
$remoterepo ||= Git->remote_repository ('http://git.or.cz/cogito.git/');
my @refs = $remoterepo->refs()

Actualmente, el módulo simplemente envuelve llamadas a herramientas externas de Git. En el futuro, prop

orcionará una manera mucho más rápida de interactuar con Git enlazando directamente con libgit. Esto d
ebería ser completamente opaco para el usuario, aunque (sin tener en cuenta el aumento de rendimiento).

Construye un nuevo objeto repositorio. Las "OPCIONES" se pasan de manera similar a un hash, usando pares de clave y valor. Las opciones posibles son:

Repository - Ruta al repositorio de

Git.

WorkingCopy - Ruta a la copia de trabajo asociada; no es estrictamente necesaria ya que muchos comandos funcionarán felizmente con un repositorio

desnudo.

WorkingSubdir - Subdirectorio en la copia de trabajo dentro del cual trabajar. Simplemente déjalo sin definir si no quieres limitar el alcance de las

operaciones.

Directory - Ruta al directorio de trabajo de Git en su configuración habitual. El directorio ".git" se busca en el directorio y en todos los directorios padres; si se encuentra, "WorkingCopy" se establece en el directorio que lo contiene y "Repository" en el directorio ".git" en sí mismo. Si no se encontró ningún directorio ".git", se asume que "Directory" es un repositorio desnudo, "Repository" se establece para apuntar a él y "WorkingCopy" se deja sin definir. Si la variable de entorno $GIT_DIR está establecida, las cosas se comportan como se espera

también.

No deberías usar tanto "Directory" como "Repository" o "WorkingCopy" - los resultados de eso son

indefinidos.

Alternativamente, una ruta de directorio puede pasarse como un único argumento escalar al constructor; es equivalente a establecer solo el campo de opción

"Directory".

Llamar al constructor sin ninguna opción en absoluto es equivalente a llamarlo con "Directory => '.'". En general, si estás construyendo un comando estándar de porcelana, simplemente hacer "Git->repository()" debería hacer lo correct

Tenga en cuenta que las funciones "command_*_pipe()" no pueden lanzar esta excepción ya que no tienen forma de saber si el comando ha fallado o no. Solo lo sabrá en el momento en que "cierre" la tubería; si desea que esto se haga automáticamente, utilice command_close_pipe(), que puede lanzar la
