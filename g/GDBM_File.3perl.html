TOLERANCIA A

FALLOS

La tolerancia a fallos (crash tolerance) es una nueva característica que, dada la apoyatura apropiada del SO y del sistema de archivos, garantiza que se pueda recuperar un estado reciente y lógicamente consistente de la base de datos tras un fallo, como un corte de energía, un pánico del núcleo del SO o algo

similar.

El soporte para tolerancia a fallos apareció en la versión 1.21 de gdbm. La teoría detrás de esto se explica en "Crashproofing the Original NoSQL Key-Value Store", de Terence Kelly (https://queue.acm.org/detail.cfm?id=3487353). Una discusión detallada de la implementación en gdbm está disponible en el Manual de GDBM (https://www.gnu.org.ua/software/gdbm/manual/Crash-Tolerance.html). La información a continuación describe la interfaz de

Perl.

Para una robustez máxima, recomendamos usar el formato de base de datos extendido para bases de datos tolerantes a fallos. Para crear una base de datos en formato extendido, use GDBM_NEWDB|GDBM_NUMSYNC al abrir la base de datos, p. ej.

: 
$db = tie %hash, 'GDBM_File', $filename,
          GDBM_NEWDB|GDBM_NUMSYNC,
0640;

Para convertir una base de datos existente al formato extendido, use el método convert, descrito arriba, p. ej.

: 
$db->convert(GDBM_NUMSYNC)
;

SEGURIDAD Y

PORTABILIDAD

Los archivos GDBM no son portables entre plataformas. Si desea transferir un archivo GDBM por la red, vuelque primero a un formato

portable.

No acepte archivos GDBM de fuentes no

confiables.

La robustez de GDBM contra bases de datos corruptas depende en gran medida de su versión. Las versiones anteriores a la 1.15 no implementaban ninguna comprobación de validez, de modo que un archivo

de base de datos corrupto o maliciosamente manipulado podía hacer que perl se bloqueara o incluso exponer una vulnerabilidad de seguridad. Las versiones entre la 1.15 y la 1.20 se fortalecieron p
rogresivamente contra entradas inválidas. Finalmente, la versión 1.21 se sometió a una extensa comprobación difusa que demostró su capacidad para soportar cualquier tipo de entradas sin bloquearse.
