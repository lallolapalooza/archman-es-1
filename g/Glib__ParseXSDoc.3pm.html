Glib::ParseXSDoc(3) Documentación de Perl aportada por el usuario Glib::ParseXSDoc(3)

NOMBRE

Glib::ParseXSDoc - Analiza POD y declaraciones XSub a partir de archivos XS.

DESCRIPCIÓN

Este es el núcleo de un sistema de documentación de referencia de API automática para módulos Perl basados en XS. ARREGLAR: más información aquí!!

ARREGLAR: documentar las directivas POD reconocidas y las estructuras de datos de salida

FUNCIONES

xsdocparse (@filenames)
Analiza archivos xs en busca de firmas de xsub y pod. Escribe en la salida estándar una estructura de datos adecuada para ser evaluada (eval) en otro script Perl, describiendo todo lo encontrado. La salida contiene tres variables:
$xspods = ARRAYREF
matriz de pods encontrados en la porción verbatim C del archivo XS, listados en el orden en que se encontraron. Se supone que pertenecen a la api XS/C, no a la api de Perl. Cualquier "=for apidoc" párrafos que sigan a "=object" párrafos en las secciones verbatim son eliminados (al igual que los "=object" párrafos), y aparecerán en su lugar en "$data->{$package}{pods}".
$data = HASHREF
gran hash indexado por nombre de paquete (tal como se encuentra en la línea MODULE), que contiene bajo cada clave un hash con todos los xsubs y pods de ese paquete, en el orden en que se encontraron. Los paquetes se consolidan a través de múltiples archivos.

Para su información, esto crea un nuevo analizador y llama a "parse_file" en él para cada nombre de archivo de entrada; luego llama a "swizzle_pods" para asegurarse de que cualquier "=for apidoc name" pods estén emparejados con sus xsubs de destino; y finalmente llama a Data::Dumper para escribir los datos en stdout. Así que, si quieres obtener un control más fino sobre cómo se crea la salida, o mantener todos los datos en el proceso, ahora sabes cómo. :-)

MÉTODOS

$Glib::ParseXSDoc::verbose
Si es verdadero, hace que el analizador sea detallado.
$parser = Glib::ParseXSDoc->new
Crea un nuevo analizador de xsub.
string = $parser->package
Obtiene el nombre del paquete actual. Vuelve al nombre del módulo como alternativa. Será undef si el analizador no ha alcanzado la primera línea MODULE.
HASHREF = $parser->pkgdata
El hash de datos correspondiente al paquete actual, respetando la directiva "=for object" encontrada más recientemente. Se asegura de que exista. Devuelve una referencia al miembro de la estructura de datos principal, por lo que las modificaciones son permanentes y útiles.
$parser->parse_file (filename)
Analiza un archivo xs. Almacena todos los datos recopilados en las estructuras de datos internas de $parser".
$parser->swizzle_pods
Empareja "=for apidoc" pods con xsubs.
$parser->preprocess_pods
Respeta las directivas "__hide__" y "__function__" en las líneas "=for apidoc" .

Buscamos las cadenas en cualquier lugar, pero normalmente las tendrás al final de la línea, por ejemplo:

=for apidoc symname __hide__        para bloques desprendidos
=for apidoc __hide__                para bloques adjuntos
=for apidoc symname __function__    para funciones en lugar de métodos
=for apidoc __function__            para funciones en lugar de métodos
bool = $parser->is_module_line ($line)
Analiza $line" para ver si contiene una directiva XS MODULE. Si es así, devuelve verdadero después de establecer $parser"'s module", package", y prefix" en consecuencia.
$pod = $parser->slurp_pod_paragraph ($firstline, $term_regex=/^=cut\s*/)
Lee líneas POD desde $filehandle" desde aquí hasta el siguiente $term_regex" o EOF. Dado que probablemente ya leíste una línea para determinar que necesitábamos empezar un pod, puedes pasar esa primera línea para que sea incluida.
$xsub = $parser->parse_xsub (\@lines)
$xsub = $parser->parse_xsub (@lines)
Analiza un encabezado xsub, en forma de lista de líneas, en una estructura de datos que describe el xsub. Eso incluye extraer los tipos de argumentos, alias y tipo de código.

Sin inteligencia artificial, no podemos determinar de manera confiable nada sobre los tipos o el número de parámetros devueltos por xsubs con cuerpos PPCODE.

Los parámetros OUTLIST se extraen de la lista de argumentos y se colocan en una clave "outlist". Los parámetros IN_OUTLIST se colocan en ambas.

Los nombres de tipos de datos no se alteran en absoluto.

Ten en cuenta que el método puede tomar tanto una lista de líneas como una referencia a una lista de líneas. La forma de lista plana se proporciona por compatibilidad; se prefiere la forma de referencia, para evitar duplicar una lista potencialmente grande de cadenas.

$parser->clean_out_empty_pods
Busca en el miembro de datos del analizador y elimina cualquier clave (y valores asociados) cuando no exista pod, enums y xsubs para el paquete.
