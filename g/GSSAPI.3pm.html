DESCRIPCIÓN

Este módulo da acceso a las rutinas de la biblioteca GSSAPI, tal como se describe en rfc2743 y rfc2744 e implementado por la distribución Kerberos-1.2 de MIT.

Desde la versión 0.14 también compila y funciona con Heimdal. Las carencias de soporte para Heimdal son gss_release_oid(), gss_str_to_oid() y fallan algunas pruebas. Echa un vistazo a las pruebas en el directorio t/ para ver qué pruebas fallan en Heimdal (las pruebas *.t solo las están omitiendo por el momento)

La API presentada por este módulo es una reinterpretación ligeramente orientada a objetos de la API C, donde las estructuras C opacas son objetos Perl, pero el estilo de llamada a función se ha dejado mayormente intacto. Como resultado, la mayoría de las rutinas modifican uno o más de los parámetros que se les pasan, reflejando la semántica C de paso por referencia (o paso por valor-retorno).

Por lo tanto, se aconseja encarecidamente a todos los usuarios de este módulo que localicen todo el uso de estas rutinas para minimizar problemas si la API cambia en el futuro.

USO

Este módulo envuelve las vinculaciones C de GSSAPI. Si eres nuevo en GSSAPI, es una buena idea leer RFC2743 y RFC2744, la documentación requiere que estés familiarizado con el concepto y la terminología de la programación GSSAPI.

El directorio de ejemplos contiene algunos ejemplos de uso funcionales:

getcred_hostbased.pl
obtiene un Token GSSAPI para un servicio especificado en la línea de comandos. (como kgetcred en Heimdal o kvno en MIT)
gss-client.pl
un cliente TCP GSSAPI simple.
gss-server.pl
un servidor TCP GSSAPI simple. Utiliza ambos como plantillas si necesitas desarrollar rápidamente servicios TCP habilitados para GSSAPI.

GSSAPI::Name

Representación interna de GSSAPI de un nombre de principal.

Métodos

import( $gssapinameobj, $servicename, $mechnism_oid );
convierte la representación en cadena $servicename del servicio a un formato interno GSSAPI y lo almacena en $gssapiservicename.
entrada
servicename
Valor escalar, como 'HTTP@moerbsen.grolmsnet.lan'.
mechnism_oid
Elige uno de los OIDs de mecanismo predefinidos de GSSAPI::OID
salida
$gssapinameobj
Representación interna de GSSAPI del nombre del servicio
valor de retorno
devuelve un objeto GSSAPI::Status
Ejemplo:
$status = GSSAPI::Name->import( $gssapinameobj,
                                'HTTP@moerbsen.grolmsnet.lan',
                                GSSAPI::OID::gss_nt_hostbased_service);
display($tname);
convierte el formato interno GSSAPI a una cadena legible por humanos y la almacena en $tname.
salida
La cadena legible por humanos se almacenará en $tname.
valor de retorno
devuelve un objeto GSSAPI::Status
Ejemplo:
my $tname;
$status = $gssapinameobj->display($tname);
die 'hmm, error...' if($status->major != GSS_S_COMPLETE );
print "\n  El nombre es $tname";
compare( nameobj, ret)
Envuelve gss_compare_name().
Entrada
nameobj
el segundo GSSAPI::Name a comparar
salida
ret
el valor es distinto de cero
los nombres se refieren a la misma entidad
el valor es cero
los nombres se refieren a entidades diferentes.
valor de retorno
devuelve un objeto GSSAPI::Status

Funciones exportables

$status = indicate_mechs($oidset)

Ejemplo

use GSSAPI qw(:all);
my $oidset;
my $isin = 0;
my $status = indicate_mechs( $oidset );
$status->major == GSS_S_COMPLETE || die 'error';
$status = $oidset->contains( gss_mech_krb5_old, $isin );
$status->major == GSS_S_COMPLETE || die 'error';
if ( $isin ) {
  print 'Soporte del tipo de mecanismo antiguo Kerberos 5';
} else {
  print 'Sin soporte del tipo de mecanismo antiguo Kerberos 5';
}
