Los archivos de opciones pueden simplif

de un script. Imagine lo siguiente:

Rompiendo los límites de la línea de

comandos

Un script puede ofrecer muchas opciones, con posiblemente algunas de ellas incluso tomando parámetros. Si estas opciones y sus parámetros se pasan directamente a la invocación del programa, podría excederse el número de caracteres aceptados por la línea de comandos de su shell. Perl en sí mismo n

o

limita el número de caracteres pasados a un script por parámetros, pero el shell o el intérprete de comandos a menudo establec

e

un límite aquí. El mismo problema puede ocurrir si desea almacenar una invocación larga en un archivo de sistema como crontab. Si tal límite le restringe, las opciones y parámetros pueden moverse a archivos de opciones, lo que resultará en una invocación de línea de comandos más corta. Invocaciones de scripts preparadas por scripts A veces un script invoca a otro script. Las opciones pasadas al script anidado podrían depender de situaciones variables, como la entrada de un usuario o el

entorno detectado. En tal caso,

pued

e
ser más fácil generar un archivo de opciones intermedio que luego se pasa al script
anidado.
O imagine dos trabajos de cron uno preparando al otro: el primero puede generar un archivo de opciones que luego es usado por el segundo.

Acceso simple a escenarios de invocación típicos Si se necesitan establecer varias opciones, pero en ciertas circunstancias son siempre las mismas, podría volverse ligeramente agotador escribirlas una y otra vez. Con un archivo de opciones, pueden almacenarse una vez y recuperarse fácilmente tantas veces como sea

necesario.

Además, los archivos de opciones pueden usarse para agrupar opciones. Varias configuraciones pueden establecer un cierto comportamiento del programa, mientras que otras influyen en otro. O un cierto conjunto de opciones puede ser útil en una situación típica, mientras que otro debería usarse en otro lugar. O hay un conjunto común de opciones que debe usarse en cada invocación, mientras que otras opciones se añaden dependiendo de las necesidades actuales. O hay algunos grupos de usuarios con formas diferentes pero típicas de invocar su script. En todos estos casos, los archivos de opciones pueden recopilar opciones que pertenecen juntas, y pueden combinarse por los usuarios del script para establecer una cierta invocación. En

conjunción con
la posibilidad de
anida
r

todo
s

Todos los usuarios del script son libres entonces de olvidar completamente cada opción de configuración ya establecida. Y si uno de ellos añade regularmente ciertas opciones a cada invocación, podría almacenarlas en su archivo de opc

iones de
inicio
individual

Por ejemplo, uso esta característica para hacer que mis scripts sean tanto flexibles como utilizables. Tengo varios scripts que acceden a una base de datos a través de DBI. Los parámetros de la cuenta de la base de datos, así como las configuraciones de inicio de DBI, no deberían codificarse dentro de los scripts porque esto no es muy flexible, así que los implementé mediante opciones. Pero por otro lado, no debería haber necesidad para un usuario normal de pasar todas estas configuraciones a cada invocación del script. Mi solución para esto es usar archivos de opciones predeterminados [[83]] establecidos y mantenidos por un administrador. Esto es muy transparente, la mayoría de los usuarios no saben nada de estas (documentadas ;-) configuraciones ... y si algo cambia, solo los archivos de opciones tienen que adaptarse.

INVOCACIÓN EN UNA LÍNEA para más detalles. argvFile() Escanea los parámetros de la línea de comandos (almacenados en @ARG

V

o en un array pasado alternativamente) en busca de pistas de archivos de opciones

(ver

Conceptos básicos más abajo), lee los archivos señalados y hace que su contenido forme parte del array fuente (@ARGV por defecto) reemplazando las pistas. Debido a que la función fue diseñada intencionadamente para trabajar

sobre

@ARGV y este sigue siendo el comportamiento por defecto, este manual habla principalmente sobre @ARGV . Por favor, tenga en cuenta que es posible procesar cualquier otro array también. Conceptos b

ásicos

Una pista de archivo de opciones es simplemente el nombre del archivo precedido por (al menos)

un carácter "@":

> script -optA argA -optB @optionFile -optC

argC 
Esto hará
que

argvFile() escanee "optionFile" en busca de opciones. El elemento "@optionFile" será eliminado del @ARG

V

array y será reemplazado por las opciones

encontradas.

Nota: puede elegir otro prefijo usando el parámetro "prefix", ver más

abajo.

Un archivo de opciones que no se pueda encontrar será ignorado silenciosamente. Bueno, ¿qué hay dentro de un archivo de opciones? Está destinado a

almacenar 
argumentos de la línea de
comandos

que deberían ser pasados al script llamado. Pueden almacenarse exactamente como se escribirían en la línea de comandos, pero pueden distribuirse en múltiples líneas. Para hacer el archivo más legible, se permiten además líneas en blanco y líneas de comentario (que comienzan con un "#"). Los comentarios POD también son soportados. Por ejemplo,

la llamada 
> script -optA argA -optB -optC cArg par1
par2

podría transformarse

en 
> script @scriptOptions par1
par2

donde el archivo "scriptOptions"

podría verse así: 
# opción a
-optA
argA

"" =pod opción b =cut -optB "" #

opción c -optC cArg 
Archivos de opciones
anidados

Los archivos de opciones pueden anidarse. La recursión se evita globalmente, lo que significa que cada archivo será abierto

solo

una vez (la primera vez que argvFile() encuentra una pista que apunta a él). Esta es la implementación más simple, ciertamente, pero debería ser adecuada. (Desafortunadamente, hay LÍMITES .) Usando esta característica, puede combinar grupos de opciones típicas en un archivo de opciones de nivel superior,

por ejemplo:

Archivo ab:

"" 
# opción a
-optA argA
# opción b
-optB

"" Archivo

c: 
"" # opción c
-optC
cArg

"" Archivo

abc: 
"" # combinar ab y c
@ab
@c

Si alguien proporciona estos archivos, un usuario puede usar una llamada muy corta: > script @abc y argvFile() moverá

recursivamente todos los parámetros del archivo al array @ARGV 
.

Rutas 
relativas

Las rutas en los archivos de opciones pueden ser relativas, 
como en

-file ../file @../..
/configs/nested

Si se escriben teniendo en mente el directorio de inicio (preparado), funcionará, pero puede fallar si se escribió de forma relativa a la ubicación del archivo de opciones, porque por defecto esas rutas no se resolverán cuando se escriban desde un archivo de 
opciones.

Use el parámetro "resolveRelativePathes
"

para cambiar a la resolución de rutas: argvFile(resolveRelativePathes=>
1);

hará que argvFile() expanda esas
    rutas, tanto en cadenas estándar como en archivos de opciones anidados. Con resolveRelativePathes, ambas rutas

-file ../file @../../configs/nested Una ruta se r

Variables de entorno De manera similar a las rutas relativas, las variables de entorno se manejan
    de forma diferente dependiendo de si la opción se especifica en la línea de comandos o desde un
    archivo de opciones, debido al procesamiento del shell omitido. Por 
defecto,

argvFile(

    Pero si se requiere, se le puede ordenar hacerlo mediante el parámetro "resolveEnvVars"

inicio

Estableciendo varios parámetros con nombre, puede habilitar el procesamiento automático 
de

archivos de opciones de inicio . Hay tres de ellos: El archivo de opciones por defecto se busca en la ruta de
    instalación del script que lo llama, 
el

archivo de opciones de inicio de 
usuario

se busca en el
    directorio de inicio del usuario (evaluado a través de la variable de entorno "HOME"), y el archivo de opciones de script 
actual

se busca en el directorio 
actual.

Por defecto, se espera que todos los archivos de opciones de inicio se llamen como
    el script, precedidos por un punto, pero esto se puede adaptar a necesidades individuales
    si se prefiere, ver más abajo. Ejemplos:
 Si un script ubicado en "/path/script" es invocado en el directorio
 /the/current/dir por un usuario "user" cuya variable "HOME" apunta
 a "/homes/user", sucede lo siguiente: ""
    argvFile()                    # ignora todos los archivos de opciones de inicio;
argvFile(default=>1)          # busca y expande "/path/.script",
                              # si está disponible (la configuración "default");
argvFile(home=>1)             # busca y expande "/homes/user/.script",
                              # si está disponible (la configuración "home");
argvFile(current=>1)          # busca y expande "/the/current/dir/.script",
                              # si está disponible (la configuración "current");
argvFile(
         default => 1,
         home    => 1,
         current => 1
        )                     # intenta manejar todos los inicios.
    Cualquier valor verdadero activará la configuraci
ón a la que se le asigna.

En caso de que la regla de nombre ".script" no se ajuste a sus necesidades
    o no encaje en una política determinada, los nombres de archivo de inicio esperados pueden
    configurarse mediante una 
opción

"startupFilename
"

. El
    valor de la opción puede ser un escalar usado como el nombre de archivo esperado, o una referencia
    a un array de opciones aceptadas, o una referencia a código que devuelva el nombre - ya sea
    directamente o como una referencia a un array de nombres. Tal código de devolución de llamada será llamado una v
ez

y recibirá el nombre del script. # usar ".config"
argvFile(startupFilename => '.config');
# usar ".config" o "config"
argvFile(startupFilename => [qw(.config config)]);
# emular el comportamiento por defecto,
# pero usar un sufijo de punto extra
my $nameBuilder=sub {join('', '.', basename($_[0]), '.');};
argvFile(startupFilename => $nameBuilder);
# usar .(script)rc o .(script)/config
my $nameBuilder=sub
                 {
                  my $sname=basename($_[0]);
                  [".${sname}rc", ".${sname}/config"];
                 };
argvFile(startupFilename => $nameBuilder); Tenga en cuenta que las variantes de lista usarán el primer nombre de archivo coincidente
    en cada posible ruta de archivo de inicio. Por ejemplo, si su array es
    "['.scrip
trc',

'.script.config']" y tiene tanto un archivo ".
scriptrc"

como un archivo ".script.
config"

en (digamos) su
    directorio actual, solo 
se usará el archivo

".
scriptrc"

, ya que es el primero 
encontrado.

El contenido encontrado en un archivo de inicio se coloca antes de todos
    los argumentos de la línea de comandos establecidos explícitamente. Esto permite sobrescribir una configuración
    por defecto mediante una opción explícita. Si se leen todos los archivos de inicio, los archivos de 
inicio

current pueden sobrescribir los archivos home que tienen precedencia sobre los default , de modo que los 
inicios

default
    son los más comunes. En
    otras palabras, si el módulo no soportara archivos de inicio, podría obtener el mismo resultado con "script @/path/.script @/homes/user/.script
    @/the/current/dir/.script".
    Nota: Hay un caso cierto en el que la sobrescritura
    no
    funcionará completamente porque se eliminan duplicados: si se usan los tres tipos de
    archivos de inicio y el script se inicia en el directorio de instalación, el archivo por defecto será idéntico al archivo actual. El archivo por defecto se procesa, pero el archivo actual se omite como duplicado más adelante y n
o

sobrescribirá las configuraciones hechas causadas por el archivo home procesado intermedio. Si se inicia en otro directorio, sí sobrescribirá las configuraciones home. Pero la alternativa parece ser aún más confusa: el script se comportaría de manera diferente si se inicia solo en su ruta de instalación. Dado que un usuario podría estar más al tanto de la edición de la configuración que de la ruta actual, elegí la implementación actual, pero esta precedencia podría volverse configurable en una versión futura. Si no existe la variable de entorno
    HOME , la configuración 
home

no tiene efecto para evitar problemas al acceder al directorio raíz. Cascadas La función soporta archivos de opciones de múltiples niveles (o llamados
    en casc
ada

). Si un nombre de archivo en una pista de archivo de opciones comienza de nuevo con un "@", este nombre completo es la resolución que se escribe de vuelta en @ARGV - asumiendo que habrá otra utilidad
    leyendo archivos de 
opciones.

Ejemplos:
 @rfile          rfile será abierto, su contenido se
                 hace parte de @ARGV.
 @@rfile         cascada: "@rfile" se escribe de vuelta en
                 @ARGV asumiendo que hay una herramienta posterior
                 llamada por el script a la que se le pasará esta
                 pista para resolverla mediante una 
propia
                 llamada de argvFile().

El número de pistas en cascada es ilimitado. Procesamiento de un array alternativo
    Aunque la función fue diseñada para 
procesar

@ARG
V

, es posible procesar otro array también si lo prefiere. Para hacer esto, simplemente pase 
una

referenci
a

a este array
    mediante el parámetro array . Ejemplos:
 argvFile()                    # procesa @ARGV;

Elección de un prefijo de pista 
alternativo

Por defecto, "@" es el prefijo usado para marcar un archivo de opciones. Esto se puede cambiar usando el parámetro 
opcional

prefix : Ejemplos:
 argvFile();                   # usa "@";
 argvFile(prefix=>'~');      
  # usa "~";

Tenga en cuenta que las cadenas "#", "=", "-"
    y "+" están reservadas 
y

no pueden elegirse aquí porque se
    usan para iniciar comentarios simples o POD o son típicamente prefijos de 
opciones.

Uso de una opción en lugar de un prefijo de 
pista

Las personas no familiarizadas con los archivos de opciones podrían confundirseeditado por archivo
    prefijos. Esto se puede evitar ofreciendo una opción que se puede usar
    en lugar de un prefijo, usando el parámetro opcional fileOption:


# instale una opción de archivo
# (todas las líneas son equivalentes)
argvFile(fileOption=>'options');
argvFile(fileOption=>'-options');
argvFile(fileOption=>'+options');
argvFile(fileOption=>'--options');


El nombre de la opción se puede especificar con o sin los prefijos
    de opción habituales "-",
    "--" y
    "+".


Una vez que una opción está declarada, puede reemplazar un prefijo.
    (Los prefijos también permanecen activos).


# con -options declarado como una opción de archivo,
# estas secuencias son equivalentes
@file
-options file
# cinco cascadas equivalentes
@@@@file
-options @@@file
-options -options @@file
-options -options -options @file
-options -options -options -options file


Tenga en cuenta que los prefijos se adjuntan al nombre del archivo sin
    espacios entre ellos, mientras que la opción declarada a través de -fileOption
    está separada del nombre del archivo por espacios en blanco, como para las
    opciones normales.








INVOCACIÓN EN UNA LÍNEA


La secuencia tradicional de dos líneas


# carga el módulo
use Getopt::ArgvFile qw(argvFile);
...
# resuelve los archivos de opciones
argvFile(default=>1);


se puede reducir a una línea: simplemente pase los parámetros de
    argvFile() a
    use():


# carga el módulo y procesa las sugerencias de archivos de opciones en @ARGV
use Getopt::ArgvFile default=>1;


Tenga en cuenta que en este caso las sugerencias de archivos de
    opciones se procesan en tiempo de compilación. Esto significa que si desea
    procesar arreglos alternativos, estos arreglos deben prepararse antes,
    generalmente en un bloque
    "BEGIN".


En las versiones 1.07 y posteriores, el manejo implícito de archivos
    de opciones es el predeterminado y solo se suprime para la carga
    tradicional


use Getopt::ArgvFile qw(argvFile);


por razones de compatibilidad con versiones anteriores. Una carga
    simple como


use Getopt::ArgvFile;


procesará las sugerencias de opciones. Si desea suprimir esto,
    use el modificador
    "justload":


use Getopt::ArgvFile justload=>1;


Consulte FUNCIONES para obtener información adicional.






NOTAS


Si un script que llama a argvFile() con el
    modificador
    "default" se invoca usando una ruta relativa, se
    recomienda encarecidamente realizar la llamada a
    argvFile() en el directorio de inicio porque
    argvFile() utiliza la ruta relativa del script
    también.






LÍMITES


Si un archivo de opciones no existe, argvFile() simplemente
    lo ignora. No se mostrará ningún mensaje, no se establecerá ningún código de
    retorno especial.
