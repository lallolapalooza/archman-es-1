Glib::Object::Introspection(3) Documentación de Perl aportada por el usuario Glib::Object::Introspection(3)

NOMBRE

Glib::Object::Introspection - Creación dinámica de enlaces de Perl

SINOPSIS

use Glib::Object::Introspection;
Glib::Object::Introspection->setup(
  basename => 'Gtk',
  version => '3.0',
  package => 'Gtk3');
# ahora GtkWindow, por mencionar un ejemplo, está disponible como
# Gtk3::Window, y puedes llamar a gtk_window_new como Gtk3::Window->new

RESUMEN

Glib::Object::Introspection utiliza los proyectos gobject-introspection y libffi para crear dinámicamente enlaces de Perl para una amplia variedad de bibliotecas. Los ejemplos incluyen Gtk, webkit, libsoup y muchos más.

DESCRIPCIÓN PARA USUARIOS DE BIBLIOTECAS

Para permitir que Glib::Object::Introspection cree enlaces para una biblioteca, esta debe tener un archivo typelib instalado, por ejemplo "$prefix/lib/girepository-1.0/Gtk-3.0.typelib". En tu código, simplemente llamas a "Glib::Object::Introspection->setup" con los siguientes pares clave-valor para configurar todo:

basename => $basename
El nombre base de la biblioteca que debe ser envuelta. Si tu typelib se llama "Gtk-3.0.typelib", entonces el nombre base es 'Gtk'.
version => $version
La versión particular de la biblioteca que debe ser envuelta, en formato de cadena. Para "Gtk-3.0.typelib", es '3.0'.
package => $package
El nombre del paquete Perl donde todas las clases y métodos de la biblioteca deben estar anclados. Si una biblioteca con nombre base 'Gtk' contiene una clase 'GtkWindow', y eliges como paquete 'Gtk3', entonces esa clase estará disponible como 'Gtk3::Window'.

Los envoltorios de Perl creados por "Glib::Object::Introspection" siguen las convenciones del módulo Glib y los enlaces antiguos escritos a mano como Gtk2. Puedes usar la herramienta incluida "perli11ndoc" para ver la documentación de todas las bibliotecas instaladas organizadas y mostradas de acuerdo con estas convenciones. Los principios rectores que subyacen a las convenciones se describen a continuación.

Espacios de nombres y Objetos

Los espacios de nombres de las bibliotecas C se mapean a paquetes Perl según la opción "package" especificada, por ejemplo:

gtk_ => Gtk3
gdk_ => Gtk3::Gdk
gdk_pixbuf_ => Gtk3::Gdk::Pixbuf
pango_ => Pango

Las clases, interfaces y tipos empaquetados y fundamentales obtienen sus propios espacios de nombres, en cierto modo, ya que el concepto de GType es completamente reemplazado en los enlaces de Perl por el nombre del paquete Perl.

GtkButton => Gtk3::Button
GdkPixbuf => Gtk3::Gdk::Pixbuf
GtkScrolledWindow => Gtk3::ScrolledWindow
PangoFontDescription => Pango::FontDescription

Con este mapeo de paquetes y la búsqueda de métodos incorporada de Perl, los enlaces pueden realizar la conversión de objetos por ti. Esto nos da una sintaxis bastante cómoda y orientada a objetos, utilizando semántica normal de objetos Perl:

en C:
  GtkWidget * b;
  b = gtk_check_button_new_with_mnemonic ("_Something");
  gtk_toggle_button_set_active (GTK_TOGGLE_BUTTON (b), TRUE);
  gtk_widget_show (b);
en Perl:
  my $b = Gtk3::CheckButton->new_with_mnemonic ('_Something');
  $b->set_active (1);
  $b->show;

Ves de esto que las macros de conversión no son necesarias y que no necesitas escribir prefijos de espacio de nombres tan a menudo, por lo que tu código es mucho más corto.

Banderas y Enumeraciones

Las banderas y los valores de enumeración se manejan como cadenas, porque es mucho más legible que los números, y porque es automático gracias al sistema GType. Los valores se hacen referencia por sus apodos; básicamente, quita el prefijo común, ponlo en minúsculas y opcionalmente convierte '_' a '-':

GTK_WINDOW_TOPLEVEL => 'toplevel'
GTK_BUTTONS_OK_CANCEL => 'ok-cancel' (o 'ok_cancel')

Las banderas son un caso especial. No puedes (sensiblemente) hacer un OR a nivel de bits de estas constantes de cadena, así que proporcionas una referencia a un array de ellas en su lugar. Los arrays anónimos son útiles aquí, y un array anónimo vacío es una forma sencilla de decir 'sin banderas'.

FOO_BAR_BAZ | FOO_BAR_QUU | FOO_BAR_QUUX => [qw/baz quu qux/]
0 => []

En algunos casos necesitas ver si un bit está activado en un campo de bits; los métodos que devuelven banderas, por lo tanto, devuelven un objeto sobrecargado. Consulta Glib para obtener más detalles sobre qué operaciones están permitidas en estos objetos de bandera, pero aquí tienes un ejemplo rápido:

en C:
  /* event->state es un campo de bits */
  if (event->state & GDK_CONTROL_MASK) g_printerr ("control was down\n");
en Perl:
  # $event->state es un objeto especial
  warn "control was down\n" if $event->state & "control-mask";

Pero esto también funciona:

warn "control was down\n" if $event->state * "control-mask";
warn "control was down\n" if $event->state >= "control-mask";
warn "control and shift were down\n"
                          if $event->state >= ["control-mask", "shift-mask"];

Gestión de memoria

Las funciones para referenciar y desreferenciar objetos y liberar estructuras empaquetadas ni siquiera se mapean a Perl, porque todo se maneja automáticamente por los enlaces. Los objetos se mantendrán vivos mientras tengas un escalar Perl apuntando a él o el objeto esté referenciado de otra manera, por ejemplo, desde un contenedor.

Lo único de lo que debes tener cuidado es de la vida útil de las estructuras no contadas por referencia, lo que significa la mayoría de las cosas derivadas de "Glib::Boxed". Si proviene de una devolución de llamada de señal, puede ser válido solo hasta que regreses, o si es el interior de otro objeto, entonces puede ser válido solo mientras ese objeto viva. En caso de duda, puedes usar "copy". Las estructuras de "copy" o "new" son tuyas y viven mientras estén referenciadas desde Perl.

Devoluciones de llamada

Utiliza trucos normales de devolución de llamada/cierre de Perl con las devoluciones de llamada. El uso más común que tendrás para las devoluciones de llamada es con el método Glib "signal_connect":

$widget->signal_connect (event => \&event_handler, $user_data);
$button->signal_connect (clicked => sub { warn "hi!\n" });

$user_data es opcional, y con los cierres de Perl no lo necesitas a menudo (ver "Variables persistentes con cierres" en perlsub).

Los datos del usuario se mantienen en un escalar, inicializado desde lo que proporcionas en "signal_connect", etc. Se pasa a la devolución de llamada en el estilo habitual de Perl de "llamada por referencia", lo que significa que la devolución de llamada puede modificar su último argumento, es decir, $_[-1], para modificar los datos del usuario mantenidos. Esto es un poco sutil, pero puedes usarlo para algún "estado" asociado con la conexión.

$widget->signal_connect (activate => \&my_func, 1);
sub my_func {
  print "activation count: $_[-1]\n";
  $_[-1] ++;
}

Debido a que los datos del usuario mantenidos son un nuevo escalar, no hay cambios en la variable (etc.) que pasaste originalmente a "signal_connect".

Si tienes un objeto padre en los datos del usuario (o cierre) tienes que tener cuidado con las referencias circulares que impiden que el padre y el hijo sean destruidos. Consulta "Recolección de basura en dos fases" en perlobj sobre esto en general. Los widgets de nivel superior como "Gtk3::Window" siempre necesitan una "$widget->destroy" explícita, por lo que su señal de "destroy" es un buen lugar para romper las referencias circulares. Pero para otros widgets, generalmente es más amigable evitar las circularidades en primer lugar, ya sea usando referencias débiles en los datos del usuario, o posiblemente localizando un padre dinámicamente con "$widget->get_ancestor".

Manejo de excepciones

Cualquier cosa que utilice GError en C hará un "croak" en caso de fallo, estableciendo $@ como un objeto de excepción mágico, el cual está sobrecargado para imprimirse como el mensaje de error devuelto. La ideología aquí es que GError debe usarse para excepciones en tiempo de ejecución, y "croak" es la forma de hacerlo en Perl. Puedes capturar un croak muy fácilmente envolviendo la función en un

eval: 
eval {
  my $pixbuf = Gtk3::Gdk::Pixbuf->new_from_file ($filename);
  $image->set_from_pixbuf ($pixbuf);
};
if ($@) {
  print "$@\n"; # imprime el mensaje de error posiblemente localizado
  if (Glib::Error::matches ($@, 'Gtk3::Gdk::Pixbuf::Error',
                                'unknown-format')) {
    change_format_and_try_again ();
  } elsif (Glib::Error::matches ($@, 'Glib::File::Error', 'noent')) {
    change_source_dir_and_try_again ();
  } else {
    # no sé cómo manejar esto
    die $@;
  }
}

Esto tiene la ventaja añadida de permitirte agrupar cosas juntas como lo harías con un bloque try/throw/catch en C++ -- obtienes códi

go más limpio. Al usar objetos de excepción Glib::Error, no tienes que depender de la coincidencia de cadenas en un mensaje de error posiblemente localizado; puedes hacer coincidir errores por condiciones explícitas y predecibles. Consulta Glib::Error para más información.

Argumentos de salida, listas,

hashes

En C solo puedes devolver un valor de una función, y es una práctica común modificar los punteros pasados para simular la devolución de múltiples valores. En Perl, puedes devolver listas; cualquier función que modifique argumentos se cambia para devolverlos en su

lugar.

Los argumentos y valores de retorno que tienen los tipos GList o GSList o que

son arrays C de valores se convertirán a y desde referencias a arrays Perl no
rmales. Lo mismo se aplica a GHashTable y referencias a hashes Perl normales.

objeto

Sobrescritura

s

Para sobrescribir el comportamiento de una función o método específico, crea un sub con el nombre apropiado en el paquete correcto y haz que llame a "Glib::Object::Introspection->invoke". Supón que quieres sobrescribir "Gtk3::Window::list_toplevels", entonces haz

esto: 
sub Gtk3::Window::list_toplevels {
  # ...hacer algo...
  my $ref = Glib::Object::Introspection->invoke (
              'Gtk', 'Window', 'list_toplevels',
              @_);
  # ...hacer algo...
  return wantarray ? @$ref : $ref->[$#$ref];
}

El nombre y el paquete del sub

deben ser aquellos después de
las correcciones de nombres.

Convertir una variable Perl a un

GValue

Si necesitas convertir a un GValue, entonces Glib::Object::Introspection no puede hacerlo automáticamente porque falta la información de tipo. Sin embargo, si tienes esta información en tu módulo, puedes usar Glib::Object::Introspection::GValueWrapper para hacer la conversión. En el wrapper para una función que espera un GValue, haz

esto:

  Glib::Object::Introspection::GValueWrapper->new ($type, $value);
# ahora usa Glib::Object::Introspection->invoke y
