NOMBRE

GnuPG::Interface - Interfaz de Perl para GnuPG

SINOPSIS

# Un ejemplo simple
use IO::Handle;
use GnuPG::Interface;
# configurando la situación
my $gnupg = GnuPG::Interface->new();
$gnupg->options->hash_init( armor   => 1,
                            homedir => '/home/foobar' );
# Nota, puedes establecer los destinatarios incluso si no estás cifrando!
$gnupg->options->push_recipients( 'ftobin@cpan.org' );
$gnupg->options->meta_interactive( 0 );
# cómo creamos algunos manejadores para interactuar con GnuPG
my $input   = IO::Handle->new();
my $output  = IO::Handle->new();
my $handles = GnuPG::Handles->new( stdin  => $input,
                                   stdout => $output );
# Ahora vamos a cifrar con las opciones ya establecidas
my @plaintext = ( 'foobar' );
my $pid = $gnupg->encrypt( handles => $handles );
# Ahora escribimos en la entrada de GnuPG
print $input @plaintext;
close $input;
# ahora leemos la salida
my @ciphertext = <$output>;
close $output;
waitpid $pid, 0;

DESCRIPCIÓN

GnuPG::Interface y sus módulos asociados están diseñados para proporcionar un método orientado a objetos para interactuar con GnuPG, siendo capaz de realizar funciones como, pero no limitadas a, cifrado, firmado, descifrado, verificación y análisis de listados de claves.

Cómo se crean los métodos accesores de miembros de datos

Cada módulo del paquete GnuPG::Interface se basa en Moo para generar los métodos de obtención/establecimiento utilizados para configurar los miembros de datos del objeto. ¡Es muy importante tener esto en cuenta! Esto significa que cualquier miembro de datos que sea una lista tiene métodos especiales asignados para añadir, quitar y vaciar la lista.

Comprendiendo la comunicación bidireccional

También es imperativo darse cuenta de que este paquete utiliza métodos de comunicación entre procesos similares a los utilizados en IPC::Open3 y en "Bidirectional Communication with Another Process" en perlipc, y que los usuarios de este paquete deben comprender cómo utilizar este método porque este paquete no abstrae estos métodos para el usuario en gran medida. Este paquete no está diseñado para abstraer esto por completo (en parte por razones de seguridad), sino más bien para ayudar a crear llamadas 'correctas' y limpias a GnuPG, y para implementar el análisis de listados de claves. Consulte "Bidirectional Communication with Another Process" en perlipc para aprender a tratar estos métodos.

Utilizar este paquete para procesar mensajes generalmente implica crear un objeto GnuPG::Interface, crear un objeto GnuPG::Handles, establecer algunas opciones en su miembro de datos options, y luego llamar a un método que invoca GnuPG, como clearsign. A continuación, se interactúa con los manejadores apropiadamente, como se describe en "Bidirectional Communication with Another Process" en perlipc.

Versiones de GnuPG

A partir de esta versión de GnuPG::Interface, hay tres versiones soportadas de GnuPG: 1.4.x, 2.2.x y 2.4.x. La página de descargas de GnuPG https://gnupg.org/download/index.html tiene información actualizada sobre las versiones actualmente soportadas.

GnuPG lanzó las versiones 2.0 y 2.1 en el pasado y algunos sistemas de empaquetado todavía pueden proporcionar estas si instala los paquetes predeterminados "gpg", "gnupg", "gnupg2", etc. Las versiones 2.0 y 2.1 no están soportadas, por lo que es posible que necesite encontrar repositorios de paquetes adicionales o compilar desde el código fuente para obtener la versión actualizada.

Estos métodos corresponden directamente o son muy similares a un comando GnuPG descrito en gpg. Cada uno de estos métodos toma un hash, que actualmente debe contener una clave de handles con el valor de un objeto GnuPG::Handles. Otra clave opcional es command_args que debe tener el valor de una referencia de array; estos argumentos se pasarán a GnuPG como argumentos de línea de comandos. Estos argumentos de línea de comandos se utilizan para determinar, por ejemplo, las claves a listar en el método export_keys. Tenga en cuenta que los argumentos de línea de comandos de GnuPG no son lo mismo que las opciones de GnuPG. Para entender qué son opciones y qué son argumentos de línea de comandos, lea "COMMANDS" en gpg y "OPTIONS" en gpg.

Cada una de estas llamadas devuelve el PID del proceso GnuPG resultante. Se puede utilizar este PID en una llamada "waitpid" en lugar de una llamada "wait" si se necesita una recolección de procesos más precisa.

Estos métodos adjuntarán los manejadores especificados en el objeto handles al objeto GnuPG en ejecución, para que se pueda establecer una comunicación bidireccional. Es decir, los manejadores opcionalmente definidos stdin, stdout, stderr, status, logger y passphrase se adjuntarán a la entrada, salida, error estándar de GnuPG, al manejador creado al establecer status-fd, al manejador creado al establecer logger-fd y al manejador creado al establecer passphrase-fd respectivamente. Esta vinculación de manejadores es similar al proceso realizado en IPC::Open3.

Si desea que el proceso GnuPG lea o escriba directamente en un manejador de archivos ya abierto, no puede hacerlo a través de los mecanismos normales de IPC::Open3. Para lograr esto, establezca el miembro de datos handles apropiado al manejador de archivos ya abierto, y luego establezca la opción direct en verdadero para ese manejador, como se describe en "options" en GnuPG::Handles. Por ejemplo, para que GnuPG lea del archivo input.txt y escriba en output.txt, el siguiente fragmento puede funcionar:

my $infile  = IO::File->new( 'input.txt' );
my $outfile = IO::File->new( '>output.txt' );
my $handles = GnuPG::Handles->new( stdin  => $infile,
                                   stdout => $outfile,
                                 );
$handles->options( 'stdin'  )->{direct} = 1;
