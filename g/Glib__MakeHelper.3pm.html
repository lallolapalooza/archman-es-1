des de Makefile.PL para e

SINOPSI

S 
eval "use Glib::MakeHelper; 1"
    or complain_that_glib_is_too_old_and_die();

%xspod_files = Glib::MakeHelper->do_pod_files (@xs_files);
package MY;
sub postamble {
    return Glib::MakeHelper->postamble_clean ()
         . Glib::MakeHelper->postamble_docs (@main::xs_files)
         . Glib::MakeHelper->postamble_rpms (
                MYLIB     => $build_reqs{MyLib},
           );
}

DESCRIPCIÓ

N

El Makefile.PL de tu módulo típico basado en Glib es enorme y complicado, gracias a todos los locos obstácul

os que tienes que superar para que todo funcione correctamente. Este módulo envuelve algunos de los fragmen
tos más intensos y propensos a errores para reducir la cantidad de código copiado y el potencial de errores.

MÉTODO

S
HASH = Glib::MakeHelper->do_pod_files
(@xs_files)
Escanea @xs_files y devuelve un hash que describe los archivos pod que se crearán. Este está en el formato deseado por WriteMakefile(). Si @ARGV contiene la cadena "disable-apidoc" se devolverá una lista vacía y por lo tanto no se generará ningún pod de apidoc, acelerando el proceso de
compilación.
LIST = Glib::MakeHelper->select_files_by_version ($stem, $major,
$minor)
Devuelve una lista de todos los archivos que coinciden con "$stem-\d+\.\d+" y para los cuales el primer número es mayor que $major y el segundo número es mayor que $minor. Si $minor es impar, se incrementará en uno para que el número de versión de una próxima versión estable pueda usarse también durante el
desarrollo.
LIST = Glib::MakeHelper->read_source_list_file
($filename)
Lee $filename, elimina todos los comentarios (que comienzan con "#") y el espacio en blanco inicial y final, y devuelve una lista de todas las líneas que sobrevivieron al
tratamiento.
string = Glib::MakeHelper->get_configure_requires_yaml (%module_to_versi
on)
Genera código YAML que lista cada módulo encontrado en %module_to_version bajo la clave "configure_requires". Esto puede usarse con el parámetro "EXTRA_META" de ExtUtils::MakeMaker para especificar qué módulos se necesitan a la hora de Makefile.PL.

Esta función está obsoleta desde que ExtUtils::MakeMaker 6.46 eliminó el soporte para "EXTRA_META" en favor de las nuevas claves "META_MERGE" y "META_A

DD
".
string = Glib::MakeHelper->postamble_clean
(@files)
Crea y devuelve el texto de una regla realclean que limpia después de gran parte de la autogeneración realizada por los módulos basados en Glib. Todo lo que hay en @files también se eliminará (puede estar vacío).

El razonamiento detrás de usar esto en lugar de simplemente hacerte usar la

s claves 'clean' o 'realclean' es que esto evita que tengas que recordar po
ner las cosas de Glib en los argumentos de WriteMakefile de tu Makefile.PL.
string = Glib::MakeHelper->postamble_docs
(@xs_files)
NOTA: esta es La Forma Antigua. Consulta postamble_docs_full para La Forma Nueva.

Crea y devuelve el texto de reglas de Makefile para construir documentación a partir de los archivos XS con Glib::ParseXSDoc y Glib::

GenPod.

Usa esto en tu MY::postamble para habilitar la autogeneración de

POD.

Esto actualiza las dependencias con la lista de nombres de pod generados por una ejecución anterior de "do_pod_fil

es".

Hay una variable especial de Makefile POD_DEPENDS que debe establecerse a la lista de archivos que necesitan ser creados antes de que se ejecute el paso doc.pl, incluyendo archivos de

inclusión.

También hay una variable BLIB_DONE que debe usarse como una dependenc

ia en cualquier lugar donde una regla necesite asegurarse de que un módulo c
argable y funcional reside en el directorio blib antes de ejecutarse.
string = Glib::MakeHelper->postamble_docs_full (.
..)
Crea y devuelve el texto de reglas de Makefile para construir documentación a partir de los archivos XS con Glib::ParseXSDoc y Glib::GenPod.

Usa esto en tu MY::postamble para habilitar la autogeneración de

POD.

Esto actualiza las dependencias con la lista de nombres de pod generados por una ejecución anterior de "do_pod_fil

es".

Hay una variable especial de Makefile POD_DEPENDS que debe establecerse a la lista de archivos que necesitan ser creados antes de que se ejecute el paso doc.pl, incluyendo archivos de

inclusión.

También hay una variable BLIB_DONE que debe usarse como una dependencia en cualquier lugar donde una regla necesite asegurarse de que un módulo cargable y funcional reside en el directorio blib antes de

ejecutarse.

Los parámetros son una list

a de pares clave=>valor. De
bes especificar como
mínimo DEPENDS o XS_FILES.
DEPENDS => objeto ExtUtils::
Depends
La mayoría de los módulos gtk2-perl usan ExtUtils::Depends para encontrar encabezados, mapas de tipos, y otros datos de los módulos padres y para instalar estos datos para los módulos hijos. Podemos encontrar a partir de este objeto la lista de archivos XS para escanear en busca de documentación, mapeos de doctype para los módulos padres, y otras
utilidades.
XS_FILES =>
\@xs_file_names
Una lista de archivos xs para escanear en busca de documentación. Se ignora si se usa
DEPENDS.
DOCTYPES => \@doctypes_file_na
mes
Lista de nombres de archivo para pasar a "Glib::GenPod::add_types". Puede
omitirse.
COPYRIGHT =>
string
Texto POD para insertar en la sección 'COPYRIGHT' de cada página generada. Puede
omitirse.
COPYRIGHT_FROM => nombre de
archivo
El nombre de un archivo que contiene el POD a insertar en la sección 'COPYRIGHT' de cada página generada. Puede
omitirse.
NAME => nombre de la
extensión
El nombre de la extensión, usado para establecer el módulo principal para
Glib::GenPod (usado en los listados de ver también generados). Pue
de omitirse en favor del nombre contenido dentro del objeto ExtUtil
s::Depends. Si también se especifica DEPENDS, NAME tiene prioridad.
string = Glib::MakeHelper->postamble_rpms
(HASH)
Crea y devuelve el texto de reglas de Makefile para gestionar la construcción de RPMs. Lo pondrías en el MY::postamble de tu Makefile.PL.

HASH es un conjunto de claves de búsqueda y reemplazo para el archivo spec. Todas las ocurrencias de @clave@ en la plantilla del archivo spec perl-$(DISTNAME).spec.in serán reemplazadas con valor. 'VERSION' y 'SOURCE' se proporcionan por ti. Por

ejemplo: 
Glib::MakeHelper->postamble_rpms (
       MYLIB     => 2.0.0, # podemos trabajar con cualquier cosa desde esto en adelante
       MYLIB_RUN => 2.3.1, # en realidad estamos compilados contra este
       PERL_GLIB => 1.01,  # debes tener esta versión de
Glib );

reemplazará @MYLIB@, @MYLIB_RUN@, y @PERL_GLIB@ en el archivo spec. Consulta las configuraciones de compilación de Glib y Gtk2 para ver

ejemplos.

Nota: Esta función sim

plemente devuelve una
cadena vacía en Win32.
string = Glib::MakeHelper->postamble_precompiled_headers
(@headers)
Crea y devuelve el texto de reglas de Makefile para un objetivo 'precompiled-headers' que precompila @headers. Si llamas a esto antes de llamar a "postamble_clean", todos los archivos te
mporales serán
eliminados por el o
bjetivo 'realclean'.

AVISO>

El MakeMaker distribuido con perl 5.8.x genera archivos make con un error que causa

que los archivos objeto se creen en el directorio incorrecto. Hay una anulación in

sertada por este módulo bajo el nombre MY::const_cccmd para corregir este problema.
