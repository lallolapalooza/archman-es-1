GSSAPI::Status(3) Documentación de Perl contribuida por el usuario GSSAPI::Status(3)

NOMBRE

GSSAPI::Status - métodos para manejar estados GSSAPI

SINOPSIS

use GSSAPI;

$status = GSSAPI::Status->new(GSS_S_COMPLETE, 0);
if (GSS_ERROR($status->major)) {
  die "una muerte horrible";
}
if (! $status) {                      # otra forma de escribir lo anterior
  die "una muerte horrible";
}
$status = $some_GSSAPI->someop($args1, etc);
if ($status) {
  foreach ($status->generic_message, $status->specific_message) {
    print "error GSSAPI: $_\n";
  }
  die "ayúdame";
}

DESCRIPCIÓN

"GSSAPI::Status" los objetos son devueltos por la mayoría de las otras operaciones GSSAPI. Dichos estados consisten en un código genérico GSSAPI y, para la mayoría de las operaciones, un código específico del mecanismo. Estos códigos numéricos se pueden acceder a través de los métodos "major" y "minor". Los mensajes de texto estándar que acompañan al estado actual se pueden obtener a través de los métodos "generic_message" y "specific_message". Cada uno de estos devuelve una lista de textos que presumiblemente deberían mostrarse en orden.

La parte del código genérico de un GSSAPI::Status se compone de tres subcampos a los que se puede acceder con las funciones "GSS_CALLING_ERROR", "GSS_ROUTINE_ERROR" y "GSS_SUPPLEMENTARY_INFO". Los valores devueltos se pueden comparar con las constantes cuyos nombres comienzan con "GSS_S_" si su código desea manejar errores particulares por sí mismo. La función "GSS_ERROR" devuelve verdadero si y solo si el código genérico dado no contiene un error de llamada ni un error de rutina.

Cuando se evalúa en un contexto booleano, un objeto "GSSAPI::Status" será verdadero si y solo si el código de estado principal es "GSS_S_COMPLETE".

Cuando se evalúa en un contexto de cadena, un objeto "GSSAPI::Status" devolverá los mensajes genérico y específico unidos con saltos de línea. Esto puede o no hacer que "die $status" funcione útilmente.

ERRORES

Los objetos base se implementan actualmente como una estructura C bendecida que contiene los códigos de estado principal y secundario. Probablemente debería ser un array o hash bendecido en su lugar, lo que reduciría la cantidad de código C involucrado y lo haría más flexible.
