KERNEL_PMDAS(1) Manual de comandos generales KERNEL_PMDAS(1)

NOMBRE

pmdaaix, pmdadarwin, pmdafreebsd, pmdalinux, pmdanetbsd, pmdaopenbsd, pmdasolaris, pmdawindows - agentes de dominio de métricas de rendimiento del kernel del sistema operativo

SINOPSIS

$PCP_PMDAS_DIR/aix/pmdaaix [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]
$PCP_PMDAS_DIR/darwin/pmdadarwin [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]
$PCP_PMDAS_DIR/freebsd/pmdafreebsd [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]
$PCP_PMDAS_DIR/linux/pmdalinux [-A] [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]
$PCP_PMDAS_DIR/netbsd/pmdanetbsd [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]
$PCP_PMDAS_DIR/netbsd/pmdaopenbsd [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]
$PCP_PMDAS_DIR/solaris/pmdasolaris [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]
$PCP_PMDAS_DIR/windows/pmdawindows [-D depuración] [-d dominio] [-l archivo_registro] [-U nombre_usuario]

DESCRIPCIÓN

Cada plataforma compatible tiene un Agente de Dominio de Métricas de Rendimiento (PMDA) del kernel que extrae métricas de rendimiento del kernel de esa plataforma. Hay una variedad de métricas específicas de la plataforma, con un conjunto igualmente variado de mecanismos de acceso; típicamente esto implica llamadas al sistema especiales, o la lectura de archivos en sistemas de archivos virtuales del kernel, como los sistemas de archivos sysfs y procfs de Linux.

El PMDA del kernel de la plataforma es uno de los componentes más críticos de la instalación de PCP y debe ser lo más eficiente y confiable posible. En todas las instalaciones, el PMDA del kernel predeterminado se instalará como una biblioteca compartida y, por lo tanto, se ejecutará directamente dentro del proceso pmcd(1). Esto reduce ligeramente las sobrecargas asociadas con la consulta de metadatos y valores relacionados con estas métricas (no se requiere paso de mensajes).

A diferencia de muchos otros PMDA, el PMDA del kernel exporta una serie de subárboles de espacio de nombres de métricas, como kernel, network, swap, mem, ipc, filesys, nfs, disk y hinv (inventario de hardware).

A pesar de ejecutarse generalmente como bibliotecas compartidas, la mayoría de las instalaciones también incluyen un ejecutable independiente para el PMDA del kernel. Esto es para ayudar en las actividades de seguimiento y depuración, con dbpmda(1), por ejemplo. En este caso (pero no para bibliotecas compartidas), las siguientes opciones de línea de comandos están disponibles:

-A
Deshabilita el uso de las credenciales proporcionadas por las herramientas cliente de PMAPI y ejecuta todo bajo la cuenta de "root". Habilite esta opción solo si comprende los riesgos y está seguro de que todos los accesos remotos provendrán de usuarios benévolos. Si está habilitado, los clientes PMAPI remotos no autenticados podrán acceder a valores potencialmente sensibles de métricas de rendimiento que un cliente PMAPI no autenticado normalmente no podría. Consulte CVE-2012-3419 para obtener detalles adicionales.
-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y se debe usar el mismo número de dominio para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, un archivo de registro llamado [plataforma].log se escribe en el directorio actual de pmcd(1) cuando se inicia pmda[plataforma], es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no es escribible, la salida se escribe en el error estándar en su lugar.
-U
Cuenta de usuario bajo la cual ejecutar el agente. El valor predeterminado es la cuenta privilegiada "root" en algunas plataformas (Linux, por ejemplo) o la cuenta no privilegiada "pcp" (siempre que sea posible).

INSTALACIÓN

El acceso a los nombres, texto de ayuda y valores de las métricas de rendimiento del kernel está disponible por defecto; a diferencia de la mayoría de los otros agentes, no se requiere ninguna acción para habilitarlos y no deben eliminarse.

ARCHIVOS

$PCP_PMDAS_DIR/[plataforma]/help
archivo de texto de ayuda predeterminado para las métricas del kernel
$PCP_LOG_DIR/pmcd/[plataforma].log
archivo de registro predeterminado para mensajes de error y otra información del PMDA del kernel.

AMBIENTE PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a orientar a los desarrolladores en lugar de a los usuarios finales. depuración es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdaaix, pmdafreebsd, pmdanetbsd, pmdaopenbsd y pmdasolaris son las siguientes:

Opción Descripción
appl0 diagnósticos detallados

Las opciones de depuración específicas para pmdalinux son las siguientes:

Opción Descripción
appl1 métricas relacionadas con disco
appl8 métricas de sistema de archivos
