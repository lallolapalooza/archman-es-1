KEYCTL_ASSUME_AUTHORITY(2const) KEYCTL_ASSUME_AUTHORITY(2const)

NOMBRE

KEYCTL_ASSUME_AUTHORITY - asumir la autoridad para instanciar una clave

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/keyctl.h>  /* Definición de constantes KEY* */
#include <sys/syscall.h>   /* Definición de constantes SYS_* */
#include <unistd.h>
long syscall(SYS_keyctl, KEYCTL_ASSUME_AUTHORITY, key_serial_t key);

DESCRIPCIÓN

Asumir (o despojarse) de la autoridad para que el hilo llamante instancie una clave.

El argumento key especifica una clave ID no nula para asumir la autoridad, o el valor 0 para despojarse de la autoridad.

Si key no es nulo, entonces especifica el ID de una clave no instanciada para la cual se debe asumir autoridad. Esa clave puede entonces ser instanciada usando una de las opciones KEYCTL_INSTANTIATE(2const), KEYCTL_INSTANTIATE_IOV(2const), KEYCTL_REJECT(2const), o KEYCTL_NEGATE(2const). Una vez que la clave ha sido instanciada, el hilo es automáticamente despojado de la autoridad para instanciar la clave.

La autoridad sobre una clave solo se puede asumir si el hilo llamante tiene presente en sus keyrings la clave de autorización que está asociada con la clave especificada. (En otras palabras, la operación KEYCTL_ASSUME_AUTHORITY solo está disponible desde un programa tipo request-key(8); consulte request_key(2) para una explicación de cómo se usa esta operación.) El llamante debe tener permiso de búsqueda sobre la clave de autorización.

Si la clave especificada tiene una clave de autorización coincidente, entonces se devuelve el ID de esa clave. La clave de autorización se puede leer (KEYCTL_READ(2const)) para obtener la información de llamada pasada a request_key(2).

Si el ID dado en key es 0, entonces se borra la autoridad actualmente asumida (se despoja), y se devuelve el valor 0.

El mecanismo KEYCTL_ASSUME_AUTHORITY permite que un programa como request-key(8) asuma la autoridad necesaria para instanciar una nueva clave no instanciada que fue creada como consecuencia de una llamada a request_key(2). Para más información, consulte request_key(2) y el archivo fuente del kernel Documentation/security/keys-request-key.txt.

VALOR DE RETORNO

En caso de éxito, devuelve 0, si el ID proporcionado era 0, o el ID de la clave de autorización coincidente con la clave especificada, si se proporcionó un ID de clave no nulo.

En caso de error, se devuelve -1 y errno se establece para indicar el error.

VERSIONES

Se proporciona una envoltura en la biblioteca libkeyutils: keyctl_assume_authority(3).

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.16.

VER TAMBIÉN

keyctl(2), keyctl_assume_authority(3)
