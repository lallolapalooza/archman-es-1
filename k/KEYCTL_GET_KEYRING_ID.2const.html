KEYCTL_GET_KEYRING_ID(2const) KEYCTL_GET_KEYRING_ID(2const)

NOMBRE

KEYCTL_GET_KEYRING_ID - mapear un ID de clave especial a un ID de clave real para este proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/keyctl.h>  /* Definición de constantes KEY* */
#include <sys/syscall.h>   /* Definición de constantes SYS_* */
#include <unistd.h>
long syscall(SYS_keyctl, KEYCTL_GET_KEYRING_ID, key_serial_t key,
             int arg3);

DESCRIPCIÓN

Mapea un ID de clave especial a un ID de clave real para este proceso.

Esta operación busca la clave especial cuyo ID se proporciona en key. Si se encuentra la clave especial, el ID de la clave real correspondiente se devuelve como resultado de la función. Los siguientes valores pueden especificarse en key:

KEY_SPEC_THREAD_KEYRING
Esto especifica el keyring específico del hilo del llamador. Ver thread-keyring(7).
KEY_SPEC_PROCESS_KEYRING
Esto especifica el keyring específico del proceso del llamador. Ver process-keyring(7).
KEY_SPEC_SESSION_KEYRING
Esto especifica el keyring específico de la sesión del llamador. Ver session-keyring(7).
KEY_SPEC_USER_KEYRING
Esto especifica el keyring específico del UID del llamador. Ver user-keyring(7).
KEY_SPEC_USER_SESSION_KEYRING
Esto especifica el keyring de sesión del UID del llamador. Ver user-session-keyring(7).
KEY_SPEC_REQKEY_AUTH_KEY (desde Linux 2.6.16)
Esto especifica la clave de autorización creada por request_key(2) y pasada al proceso que genera una clave. Esta clave solo está disponible en un programa estilo request-key(8) al que el kernel le pasó una clave de autorización y deja de estar disponible una vez que la clave solicitada ha sido instanciada; ver request_key(2).
KEY_SPEC_REQUESTOR_KEYRING (desde Linux 2.6.29)
Esto especifica el ID de clave para el keyring de destino de request_key(2). Este keyring solo está disponible en un programa estilo request-key(8) al que el kernel le pasó una clave de autorización y deja de estar disponible una vez que la clave solicitada ha sido instanciada; ver request_key(2).

El comportamiento si la clave especificada en key no existe depende del valor de arg3. Si arg3 contiene un valor distinto de cero, entonces —si es apropiado hacerlo (por ejemplo, al buscar la clave del usuario, de sesión de usuario o de sesión)— se crea una nueva clave y su ID real se devuelve como resultado de la función. De lo contrario, la operación falla con el error ENOKEY.

Si se especifica un ID de clave válido en key, y la clave existe, entonces esta operación simplemente devuelve el ID de clave. Si la clave no existe, la llamada falla con el error ENOKEY.

El llamador debe tener permiso de *búsqueda* en un keyring para que este sea encontrado.

VALOR DE RETORNO

En caso de éxito, el ID del keyring solicitado.

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

ENOKEY
La clave especificada en key no existía, y arg3 era cero (lo que significa no crear la clave si no existía).

VERSIÓNES

Se proporciona un envoltorio en la biblioteca libkeyutils: keyctl_get_keyring_ID(3).

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.10.

VER TAMBIÉN

keyctl(2), keyctl_get_keyring_ID(3)
