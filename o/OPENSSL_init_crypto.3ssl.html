DESCRIPCIÓN

Durante el funcionamiento normal, OpenSSL (libcrypto) asignará varios recursos al inicio que, posteriormente, deberán liberarse al cerrar la biblioteca. Además, algunos recursos se asignan por hilo (si la aplicación es multihilo) y estos recursos deben liberarse antes de que el hilo finalice.

A partir de la versión 1.1.0, OpenSSL asignará automáticamente todos los recursos que necesita, por lo que no se requiere inicialización explícita. Del mismo modo, también se desinicializará automáticamente según sea necesario.

Sin embargo, puede haber situaciones en las que la inicialización explícita sea deseable o necesaria, por ejemplo, cuando se requiere alguna inicialización no predeterminada. La función OPENSSL_init_crypto() puede utilizarse para este propósito para libcrypto (consulte también OPENSSL_init_ssl(3) para el equivalente de libssl).

Numerosas funciones internas de OpenSSL llaman a OPENSSL_init_crypto(). Por lo tanto, para realizar una inicialización no predeterminada, el código de la aplicación DEBE llamar a OPENSSL_init_crypto() antes de cualquier otra llamada a funciones de OpenSSL.

El parámetro opts especifica qué aspectos de libcrypto deben inicializarse. Las opciones válidas son:

OPENSSL_INIT_NO_LOAD_CRYPTO_STRINGS
Suprimir la carga automática de las cadenas de error de libcrypto. Esta opción no es una opción predeterminada. Una vez seleccionada, se ignorarán las llamadas posteriores a OPENSSL_init_crypto() con la opción OPENSSL_INIT_LOAD_CRYPTO_STRINGS.
OPENSSL_INIT_LOAD_CRYPTO_STRINGS
Carga automática de las cadenas de error de libcrypto. Con esta opción, la biblioteca cargará automáticamente las cadenas de error de libcrypto. Esta opción es una opción predeterminada. Una vez seleccionada, se ignorarán las llamadas posteriores a OPENSSL_init_crypto() con la opción OPENSSL_INIT_NO_LOAD_CRYPTO_STRINGS.
OPENSSL_INIT_ADD_ALL_CIPHERS
Con esta opción, la biblioteca cargará y pondrá a disposición automáticamente todos los cifrados de libcrypto. Esta opción es una opción predeterminada. Una vez seleccionada, se ignorarán las llamadas posteriores a OPENSSL_init_crypto() con la opción OPENSSL_INIT_NO_ADD_ALL_CIPHERS.
OPENSSL_INIT_ADD_ALL_DIGESTS
Con esta opción, la biblioteca cargará y pondrá a disposición automáticamente todos los resúmenes (digests) de libcrypto. Esta opción es una opción predeterminada. Una vez seleccionada, se ignorarán las llamadas posteriores a OPENSSL_init_crypto() con la opción OPENSSL_INIT_NO_ADD_ALL_DIGESTS.
OPENSSL_INIT_NO_ADD_ALL_CIPHERS
Con esta opción, la biblioteca suprimirá la carga automática de cifrados de libcrypto. Esta opción no es una opción predeterminada. Una vez seleccionada, se ignorarán las llamadas posteriores a OPENSSL_init_crypto() con la opción OPENSSL_INIT_ADD_ALL_CIPHERS.
OPENSSL_INIT_NO_ADD_ALL_DIGESTS
Con esta opción, la biblioteca suprimirá la carga automática de resúmenes de libcrypto. Esta opción no es una opción predeterminada. Una vez seleccionada, se ignorarán las llamadas posteriores a OPENSSL_init_crypto() con la opción OPENSSL_INIT_ADD_ALL_DIGESTS.
OPENSSL_INIT_LOAD_CONFIG
Con esta opción, se cargará automáticamente un archivo de configuración de OpenSSL y será utilizado por la llamada a OPENSSL_config(). Esta es una opción predeterminada. Tenga en cuenta que en OpenSSL 1.1.1 esta era la opción predeterminada para libssl, pero no para libcrypto (consulte OPENSSL_init_ssl(3) para más detalles sobre la inicialización de libssl). En OpenSSL 1.1.0, esta era una opción no predeterminada tanto para libssl como para libcrypto. Consulte la descripción de OPENSSL_INIT_new(), a continuación.
OPENSSL_INIT_NO_LOAD_CONFIG
Con esta opción, se suprimirá la carga de archivos de configuración de OpenSSL. Es el equivalente a llamar a OPENSSL_no_config(). Esta no es una opción predeterminada.
OPENSSL_INIT_ASYNC
Con esta opción, la biblioteca inicializará automáticamente la sub-biblioteca asíncrona de libcrypto (consulte ASYNC_start_job(3)). Esta es una opción predeterminada.
OPENSSL_INIT_ENGINE_RDRAND
Con esta opción, la biblioteca cargará e inicializará automáticamente el motor RDRAND (si está disponible). Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ENGINE_DYNAMIC
Con esta opción, la biblioteca cargará e inicializará automáticamente el motor dinámico. Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ENGINE_OPENSSL
Con esta opción, la biblioteca cargará e inicializará automáticamente el motor openssl. Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ENGINE_CRYPTODEV
Con esta opción, la biblioteca cargará e inicializará automáticamente el motor cryptodev (si está disponible). Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ENGINE_CAPI
Con esta opción, la biblioteca cargará e inicializará automáticamente el motor CAPI (si está disponible). Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ENGINE_PADLOCK
Con esta opción, la biblioteca cargará e inicializará automáticamente el motor padlock (si está disponible). Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ENGINE_AFALG
Con esta opción, la biblioteca cargará e inicializará automáticamente el motor AFALG. Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ENGINE_ALL_BUILTIN
Con esta opción, la biblioteca cargará e inicializará automáticamente todos los motores integrados mencionados anteriormente, con la excepción de los motores openssl y afalg. Esta no es una opción predeterminada y está obsoleta en OpenSSL 3.0.
OPENSSL_INIT_ATFORK
Con esta opción, la biblioteca registrará sus manejadores de bifurcación (fork). Consulte OPENSSL_fork_prepare(3) para más detalles.
OPENSSL_INIT_NO_ATEXIT
Por defecto, OpenSSL intentará limpiarse cuando el proceso finalice a través de un manejador "atexit". El uso de esta opción suprime ese comportamiento. Esto significa que la aplicación tendrá que limpiar OpenSSL explícitamente usando OPENSSL_cleanup().

DESCRIPTION

The OpenSSL library is initialised using OPENSSL_init_crypto(). This function should be called before any other OpenSSL functions are used, except for a few exceptions that are listed under OPENSSL_init_ssl(3). The function must be called exactly once per application. Subsequent calls to OPENSSL_init_crypto() will fail with an error.

The opts parameter is a bitmask of options. The available options are:

  • OPENSSL_INIT_LOAD_CONFIG: Load the OpenSSL configuration file. This is equivalent to calling CONF_modules_load_file(3) with NULL filename and application name, and the CONF_MFLAGS_IGNORE_MISSING_FILE, CONF_MFLAGS_IGNORE_RETURN_CODES and CONF_MFLAGS_DEFAULT_SECTION flags.
  • OPENSSL_INIT_NO_LOAD_CONFIG: Do not load the OpenSSL configuration file. This is the default behaviour if the OPENSSL_INIT_LOAD_CONFIG flag is not specified.
  • OPENSSL_INIT_LOAD_CRYPTO_STRINGS: Load the OpenSSL error strings for libcrypto. This is the default behaviour.
  • OPENSSL_INIT_NO_LOAD_CRYPTO_STRINGS: Do not load the OpenSSL error strings for libcrypto.
  • OPENSSL_INIT_LOAD_SSL_STRINGS: Load the OpenSSL error strings for libssl. This is the default behaviour.
  • OPENSSL_INIT_NO_LOAD_SSL_STRINGS: Do not load the OpenSSL error strings for libssl.
  • OPENSSL_INIT_ADD_ALL_CIPHERS: Add all available ciphers to the internal cipher list. This is the default behaviour.
  • OPENSSL_INIT_NO_ADD_ALL_CIPHERS: Do not add any ciphers to the internal cipher list.
  • OPENSSL_INIT_ADD_ALL_DIGESTS: Add all available digests to the internal digest list. This is the default behaviour.
  • OPENSSL_INIT_NO_ADD_ALL_DIGESTS: Do not add any digests to the internal digest list.
  • OPENSSL_INIT_ASYNC: Initialise the async engine.
  • OPENSSL_INIT_NO_ASYNC: Do not initialise the async engine.
  • OPENSSL_INIT_ENGINE: Load crypto engines.
  • OPENSSL_INIT_NO_ENGINE: Do not load crypto engines.

The OPENSSL_INIT_SETTINGS structure pointed to by settings can be used to customize configuration loading. It can be allocated using OPENSSL_INIT_new() and released using OPENSSL_INIT_free(). The filename, application name and flags can be customized using OPENSSL_INIT_set_config_filename(), OPENSSL_INIT_set_config_appname() and OPENSSL_INIT_set_file_flags() respectively. If the CONF_MFLAGS_IGNORE_RETURN_CODES flag is not included in the flags set via OPENSSL_INIT_set_file_flags(), then any errors during config file loading will cause OPENSSL_init_crypto() to fail.

Multiple options may be combined together in a single call to OPENSSL_init_crypto(). For example:

OPENSSL_init_crypto(OPENSSL_INIT_NO_ADD_ALL_CIPHERS
                    | OPENSSL_INIT_NO_ADD_ALL_DIGESTS, NULL);

The OPENSSL_cleanup() function deinitialises OpenSSL (both libcrypto and libssl). All resources allocated by OpenSSL are freed. Typically there should be no need to call this function directly as it is initiated automatically on application exit. This is done via the standard C library atexit() function. In the event that the application will close in a manner that will not call the registered atexit() handlers then the application should call OPENSSL_cleanup() directly. Developers of libraries using OpenSSL are discouraged from calling this function and should instead, typically, rely on auto-deinitialisation. This is to avoid error conditions where both an application and a library it depends on both use OpenSSL, and the library deinitialises it before the application has finished using it.

Once OPENSSL_cleanup() has been called the library cannot be reinitialised. Attempts to call OPENSSL_init_crypto() will fail and an ERR_R_INIT_FAIL error will be added to the error stack. Note that because initialisation has failed OpenSSL error strings will not be available, only an error code. This code can be put through the openssl errstr command line application to produce a human readable error (see openssl-errstr(1)).

The OPENSSL_atexit() function enables the registration of a function to be called during OPENSSL_cleanup(). Stop handlers are called after deinitialisation of resources local to a thread, but before other process wide resources are freed. In the event that multiple stop handlers are registered, no guarantees are made about the order of execution.

The OPENSSL_thread_stop_ex() function deallocates resources associated with the current thread for the given OSSL_LIB_CTX ctx. The ctx parameter can be NULL in which case the default OSSL_LIB_CTX is used.

Typically, this function will be called automatically by the library when the thread exits as long as the OSSL_LIB_CTX has not been freed before the thread exits. If OSSL_LIB_CTX_free() is called OPENSSL_thread_stop_ex will be called automatically for the current thread (but not any other threads that may have used this OSSL_LIB_CTX).

OPENSSL_thread_stop_ex should be called on all threads that will exit after the OSSL_LIB_CTX is freed. Typically this is not necessary for the default OSSL_LIB_CTX (because all resources are cleaned up on library exit) except if thread local resources should be freed before library exit, or under the circumstances described in the NOTES section below.

OPENSSL_thread_stop() is the same as OPENSSL_thread_stop_ex() except that the default OSSL_LIB_CTX is always used.

The OPENSSL_INIT_LOAD_CONFIG flag will load a configuration file, as with CONF_modules_load_file(3) with NULL filename and application name and the CONF_MFLAGS_IGNORE_MISSING_FILE, CONF_MFLAGS_IGNORE_RETURN_CODES and CONF_MFLAGS_DEFAULT_SECTION flags. The filename, application name, and flags can be customized by providing a non-null OPENSSL_INIT_SETTINGS object. The object can be allocated via OPENSSL_INIT_new(). The OPENSSL_INIT_set_config_filename() function can be used to specify a nondefault filename, which is copied and need not refer to persistent storage. Similarly, OPENSSL_INIT_set_config_appname() can be used to specify a nondefault application name. Finally, OPENSSL_INIT_set_file_flags can be used to specify nondefault flags. If the CONF_MFLAGS_IGNORE_RETURN_CODES flag is not included, any errors in the configuration file will cause an error return from OPENSSL_init_crypto or indirectly OPENSSL_init_ssl(3). The object can be released with OPENSSL_INIT_free() when done. If the argument to OPENSSL_INIT_free() is NULL, nothing is done.

NOTES

Resources local to a thread are deallocated automatically when the thread exits (e.g. in a pthreads environment, when pthread_exit() is called). On Windows platforms this is done in response to a DLL_THREAD_DETACH message being sent to the libcrypto32.dll entry point. Some windows functions may cause threads to exit without sending this message (for example ExitProcess()). If the application uses such functions, then the application must free up OpenSSL resources directly via a call to OPENSSL_thread_stop() on each thread. Similarly this message will also not be sent if OpenSSL is linked statically, and therefore applications using static linking should also call OPENSSL_thread_stop() on each thread. Additionally if OpenSSL is loaded dynamically via LoadLibrary() and the threads are not destroyed until after FreeLibrary() is called then each thread should call OPENSSL_thread_stop() prior to the FreeLibrary() call.

On Linux/Unix where OpenSSL has been loaded via dlopen() and the application is multi-threaded and if dlclose() is subsequently called prior to the threads being destroyed then OpenSSL will not be able to deallocate resources associated with those threads. The application should either call OPENSSL_thread_stop() on each thread prior to the dlclose() call, or alternatively the original dlopen() call should use the RTLD_NODELETE flag (where available on the platform).

RETURN VALUES

The functions OPENSSL_init_crypto, OPENSSL_atexit() and OPENSSL_INIT_set_config_appname() return 1 on success or 0 on error.
