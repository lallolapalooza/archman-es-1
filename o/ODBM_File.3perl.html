ODBM_File(3perl) Guía de referencia para programadores de Perl ODBM_File(3perl)

NOMBRE

ODBM_File - Acceso enlazado a archivos odbm

SINOPSIS

use Fcntl;   # Para O_RDWR, O_CREAT, etc.
use ODBM_File;
tie(%h, 'ODBM_File', 'nombre_archivo.dbmx', O_RDWR|O_CREAT, 0640)
  or die "No se pudo enlazar el archivo ODBM 'nombre_archivo.dbmx': $!; abortando";
# Ahora lee y modifica el hash
$h{nueva_clave} = nuevo_valor;
print $h{clave_antigua};
...
untie %h;

DESCRIPCIÓN

"ODBM_File" establece una conexión entre una variable hash de Perl y un archivo en formato ODBM_File. Puedes manipular los datos del archivo como si estuvieran en un hash de Perl, pero cuando tu programa finalice, los datos permanecerán en el archivo, para ser utilizados la próxima vez que tu programa se ejecute.

Utiliza "ODBM_File" con la función incorporada de Perl "tie" para establecer la conexión entre la variable y el archivo. Los argumentos para "tie" deben ser:

1.
La variable hash que deseas enlazar.
2.
La cadena "ODBM_File". (Esto le dice a Perl que use el paquete "ODBM_File" para realizar las funciones del hash.)
3.
El nombre del archivo al que deseas enlazar el hash.
4.
Indicadores. Utiliza uno de:
"O_RDONLY"
Acceso de solo lectura a los datos del archivo.
"O_WRONLY"
Acceso de solo escritura a los datos del archivo.
"O_RDWR"
Acceso de lectura y escritura.

Si deseas crear el archivo si no existe, añade "O_CREAT" a cualquiera de estos, como en el ejemplo. Si omites "O_CREAT" y el archivo no existe, la llamada "tie" fallará.

5.
Los permisos predeterminados a utilizar si se crea un nuevo archivo. Los permisos reales serán modificados por la umask del usuario, por lo que probablemente deberías usar 0666 aquí. (Ver "umask" en perlfunc.)

DIAGNÓSTICOS

En caso de fallo, la llamada "tie" devuelve un valor indefinido y probablemente establece $! para contener la razón por la cual el archivo no pudo ser enlazado.

"odbm store devolvió -1, errno 22, clave "..." en ..."

Esta advertencia se emite cuando intentas almacenar una clave o un valor demasiado largos. Significa que el cambio no se registró en la base de datos. Ver ERRORES Y ADVERTENCIAS abajo.

SEGURIDAD Y PORTABILIDAD

No aceptes archivos ODBM de fuentes no confiables.

En los sistemas Linux modernos, estos suelen ser archivos GDBM, que no son portátiles entre plataformas.

La documentación de GDBM no implica que los archivos de fuentes no confiables puedan usarse de forma segura con "libgdbm".

Los sistemas que no utilizan compatibilidad GDBM para el soporte antiguo de dbm usarán una biblioteca específica de la plataforma, posiblemente heredada de los sistemas BSD, donde puede ser seguro o no usar un archivo no confiable.

Un archivo maliciosamente diseñado podría hacer que perl se cuelgue o incluso exponer una vulnerabilidad de seguridad.

ERRORES Y ADVERTENCIAS

Existen varios límites en el tamaño de los datos que puedes almacenar en el archivo ODBM. El más importante es que la longitud de una clave, más la longitud de su valor asociado, no puede exceder los 1008 bytes.

Ver "tie" en perlfunc, perldbmfilter, Fcntl
