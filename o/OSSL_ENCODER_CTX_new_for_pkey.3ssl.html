OSSL_ENCODER_CTX_new_for_pkey(3ssl)

Licencias: Apache-2.0

Nombre

OSSL_ENCODER_CTX_new_for_pkey, OSSL_ENCODER_CTX_set_cipher, OSSL_ENCODER_CTX_set_passphrase, OSSL_ENCODER_CTX_set_pem_password_cb, OSSL_ENCODER_CTX_set_passphrase_cb, OSSL_ENCODER_CTX_set_passphrase_ui - Rutinas de codificación para codificar EVP_PKEYs

Sintaxis

#include <openssl/encoder.h>
OSSL_ENCODER_CTX *
OSSL_ENCODER_CTX_new_for_pkey(const EVP_PKEY *pkey, int selection,
                              const char *output_type,
                              const char *output_structure,
                              const char *propquery);
int OSSL_ENCODER_CTX_set_cipher(OSSL_ENCODER_CTX *ctx,
                                const char *cipher_name,
                                const char *propquery);
int OSSL_ENCODER_CTX_set_passphrase(OSSL_ENCODER_CTX *ctx,
                                    const unsigned char *kstr,
                                    size_t klen);
int OSSL_ENCODER_CTX_set_pem_password_cb(OSSL_ENCODER_CTX *ctx,
                                         pem_password_cb *cb, void *cbarg);
int OSSL_ENCODER_CTX_set_passphrase_ui(OSSL_ENCODER_CTX *ctx,
                                       const UI_METHOD *ui_method,
                                       void *ui_data);
int OSSL_ENCODER_CTX_set_passphrase_cb(OSSL_ENCODER_CTX *ctx,
                                       OSSL_PASSPHRASE_CALLBACK *cb,
                                       void *cbarg);

Descripción

OSSL_ENCODER_CTX_new_for_pkey() es una función utilitaria que crea un OSSL_ENCODER_CTX, encuentra todas las implementaciones de codificadoras aplicables y las configura, así que casi todo lo que el llamador tiene que hacer después es llamar a funciones como OSSL_ENCODER_to_bio(3). output_type determina el tipo de codificación final, y selection puede usarse para seleccionar qué partes de pkey deben estar incluidas en la salida. output_type se discute más en "Tipos de salida" a continuación, y selection se describe más en "Selección".

Internamente, OSSL_ENCODER_CTX_new_for_pkey() usa los nombres de las implementaciones de EVP_KEYMGMT(3) asociadas con pkey para construir una lista de implementaciones de codificadoras aplicables que se usan para procesar el pkey en la codificación especificada por output_type, con la estructura externa llamada por output_structure si es relevante. Todas estas implementaciones se implícitamente recuperan, con propquery para selección más fina.

Si no hay ninguna implementación de codificador adecuada, OSSL_ENCODER_CTX_new_for_pkey() aún crea un OSSL_ENCODER_CTX, pero sin asociado codificador (OSSL_ENCODER_CTX_get_num_encoders(3) devuelve cero). Esto ayuda al llamador a distinguir entre un error al crear el OSSL_ENCODER_CTX y la falta de implementación de codificador, y permite que actúe según corresponda.

OSSL_ENCODER_CTX_set_cipher() dice a la implementación qué cifra debería usarse para cifrar las claves codificadas. El cifra se da por el nombre cipher_name. La interpretación de ese cipher_name es dependiente de la implementación. La implementación puede implementar directamente el cifra, o mediante otras implementaciones, o puede elegir recuperarlo. Si la implementación soporta la recuperación del cifra, puede usar propquery como propiedades para recuperar cuando se recupera. cipher_name también puede ser NULL, lo que resulta en codificación sin cifrado.

OSSL_ENCODER_CTX_set_passphrase() da a la implementación un pasapalabra para usar cuando se cifra la clave privada codificada. Alternativamente, puede especificar un pasapalabra de la siguiente manera.

OSSL_ENCODER_CTX_set_pem_password_cb(), OSSL_ENCODER_CTX_set_passphrase_ui() y OSSL_ENCODER_CTX_set_passphrase_cb() configuran un método de callback que la implementación puede usar para solicitar un pasapalabra, dando al llamador la opción de elegir la forma preferida de pasapalabra de callback. Estas se llaman indirectamente, a través de una función interna OSSL_PASSPHRASE_CALLBACK(3).

Tipos de salida

Los tipos de EVP_PKEY de salida dependen de las implementaciones disponibles.

OpenSSL tiene implementaciones predefinidas para los siguientes tipos de salida:

"TEXT"
La salida es una descripción humana de la clave. EVP_PKEY_print_private(3), EVP_PKEY_print_public(3) y EVP_PKEY_print_params(3) usan este tipo de salida para sus resultados.
"DER"
La salida es la codificación DER de la selección de pkey.
"PEM"
La salida es la selección de pkey en formato PEM.

Selección

selection puede ser cualquier valor de los descritos en "Selección" en EVP_PKEY_fromdata(3).

Estos son solo 'indicadores' ya que las implementaciones de codificadoras son libres de decidir qué parte de la salida se incluye y esto puede depender del tipo deseado. Por ejemplo, una clave EC en un estructura de PKCS#8 no suele incluir la clave pública.

Valores de retorno

OSSL_ENCODER_CTX_new_for_pkey() devuelve un puntero a un OSSL_ENCODER_CTX, o NULL si no se pudo crear.

OSSL_ENCODER_CTX_set_cipher(), OSSL_ENCODER_CTX_set_passphrase(), OSSL_ENCODER_CTX_set_pem_password_cb(), OSSL_ENCODER_CTX_set_passphrase_ui() y OSSL_ENCODER_CTX_set_passphrase_cb() devuelven 1 en caso de éxito, o 0 en caso de error.
