NOMBRE

OSSL_PROVIDER-FIPS - Proveedor FIPS de OpenSSL

DESCRIPCIÓN

El proveedor FIPS de OpenSSL es un proveedor especial que cumple con los Estándares Federales de Procesamiento de Información (FIPS) especificados en FIPS 140-3. Este 'módulo' contiene un conjunto aprobado de algoritmos criptográficos que ha sido validado por un laboratorio de pruebas acreditado.

Propiedades

Las implementaciones en este proveedor tienen específicamente estas propiedades definidas para algoritmos aprobados:

"provider=fips"
"fips=yes"

Puede ser utilizado en una cadena de consulta de propiedades con funciones de obtención como EVP_MD_fetch(3) o EVP_CIPHER_fetch(3), así como con otras funciones que toman una cadena de consulta de propiedades, como EVP_PKEY_CTX_new_from_name(3).

Para cumplir con FIPS, es obligatorio incluir "fips=yes" como parte de todas las consultas de propiedades. Esto asegura que solo se utilicen implementaciones aprobadas por FIPS para las operaciones criptográficas. La consulta "fips=yes" también puede incluir otras operaciones de soporte no criptográficas que no están en el proveedor FIPS, como codificadores de claves asimétricas, vea "Gestión de claves asimétricas" en OSSL_PROVIDER-default(7).

No es obligatorio incluir "provider=fips" como parte de su consulta de propiedades. Incluir "provider=fips" en su consulta de propiedades garantiza que se utilice el proveedor FIPS de OpenSSL para las operaciones criptográficas en lugar de otros proveedores capaces de FIPS.

Algoritmos aprobados

Los algoritmos que se obtienen usando "fips=yes" aún pueden no estar aprobados si no se cumplen ciertas condiciones. Vea "Indicadores FIPS" en fips_module(7) para información adicional.

Parámetros del proveedor

Vea "Parámetros del proveedor" en provider-base(7) para una lista de parámetros base. El proveedor FIPS de OpenSSL también maneja los parámetros relacionados con los indicadores FIPS según lo especificado por "Opciones de indicadores FIPS" en fips_config(5).

AUTOCOMPROBACIÓN

Un requisito de los módulos FIPS es ejecutar pruebas de autocomprobación de algoritmos criptográficos. FIPS 140-3 requiere que se ejecuten pruebas de respuesta conocida al inicio, así como pruebas condicionales que se ejecutan durante las operaciones criptográficas.

Un mecanismo de devolución de llamada opcional está disponible para devolver información al usuario utilizando OSSL_SELF_TEST_set_callback(3).

Los parámetros pasados a la devolución de llamada se describen en OSSL_SELF_TEST_new(3)

El módulo FIPS de OpenSSL utiliza el siguiente mecanismo para proporcionar información sobre las autocomprobaciones a medida que se ejecutan. Esto es útil para la depuración si una autocomprobación falla. La devolución de llamada también permite forzar que cualquier autocomprobación falle, para comprobar que funciona correctamente en caso de fallo. Tenga en cuenta que todas las autocomprobaciones se ejecutan incluso si ocurre un fallo en la autocomprobación.

El módulo FIPS pasa el(los) siguiente(s) tipo(s) a OSSL_SELF_TEST_onbegin().

"Module_Integrity" (OSSL_SELF_TEST_TYPE_MODULE_INTEGRITY)
Utiliza HMAC SHA256 sobre el archivo del módulo para validar que el módulo no ha sido modificado. El valor de integridad se compara con un valor escrito en un archivo de configuración durante la instalación.
"KAT_Integrity" (OSSL_SELF_TEST_TYPE_KAT_INTEGRITY)
Se utiliza durante la prueba de integridad del módulo para realizar una prueba de respuesta conocida en HMAC SHA256 antes de usarlo.
"KAT_Cipher" (OSSL_SELF_TEST_TYPE_KAT_CIPHER)
Prueba de respuesta conocida para un cifrado simétrico.
"KAT_AsymmetricCipher" (OSSL_SELF_TEST_TYPE_KAT_ASYM_CIPHER)
Prueba de respuesta conocida para un cifrado asimétrico.
"KAT_Digest" (OSSL_SELF_TEST_TYPE_KAT_DIGEST)
Prueba de respuesta conocida para un digestor.
"KAT_AsymmetricKeyGeneration" (OSSL_SELF_TEST_TYPE_KAT_ASYM_KEYGEN)
Prueba de respuesta conocida para la generación de claves asimétricas.
"KAT_Signature" (OSSL_SELF_TEST_TYPE_KAT_SIGNATURE)
Prueba de respuesta conocida para una firma.
"PCT_Signature" (OSSL_SELF_TEST_TYPE_PCT_SIGNATURE)
Comprobación de consistencia por pares para una firma.
"KAT_KDF" (OSSL_SELF_TEST_TYPE_KAT_KDF)
Prueba de respuesta conocida para una función de derivación de claves.
"KAT_KA" (OSSL_SELF_TEST_TYPE_KAT_KA)
Prueba de respuesta conocida para el acuerdo de claves.
"KAT_KEM" (OSSL_SELF_TEST_TYPE_KAT_KEM)
Prueba de respuesta conocida para la encapsulación de claves.
"DRBG" (OSSL_SELF_TEST_TYPE_DRBG)
Prueba de respuesta conocida para un generador de bits aleatorios determinista.
"Conditional_PCT" (OSSL_SELF_TEST_TYPE_PCT)
Prueba condicional que se ejecuta durante la generación de pares de claves.
"Import_PCT" (OSSL_SELF_TEST_TYPE_PCT_IMPORT)
Prueba condicional que se ejecuta durante la importación de pares de claves.
"Conditional_KAT" (OSSL_SELF_TEST_TYPE_PCT_KAT)
Prueba condicional ejecutada durante la generación que deriva la clave pública de la clave privada y verifica que la clave pública coincide. Este es un requisito de SP 800-56A.

Prueba continua del generador de números aleatorios.

EJEMPLOS

A continuación se muestra una sencilla rutina de devolución de llamada de autocomprobación a modo de ilustración.

#include <openssl/self_test.h>
static OSSL_CALLBACK self_test_cb;
static int self_test_cb(const OSSL_PARAM params[], void *arg)
{
  int ret = 0;
  const OSSL_PARAM *p = NULL;
  const char *phase = NULL, *type = NULL, *desc = NULL;
  p = OSSL_PARAM_locate_const(params, OSSL_PROV_PARAM_SELF_TEST_PHASE);
  if (p == NULL || p->data_type != OSSL_PARAM_UTF8_STRING)
      goto err;
  phase = (const char *)p->data;
  p = OSSL_PARAM_locate_const(params, OSSL_PROV_PARAM_SELF_TEST_DESC);
  if (p == NULL || p->data_type != OSSL_PARAM_UTF8_STRING)
      goto err;
  desc = (const char *)p->data;
  p = OSSL_PARAM_locate_const(params, OSSL_PROV_PARAM_SELF_TEST_TYPE);
  if (p == NULL || p->data_type != OSSL_PARAM_UTF8_STRING)
      goto err;
  type = (const char *)p->data;
  /* Realizar algún registro */
  if (strcmp(phase, OSSL_SELF_TEST_PHASE_START) == 0)
      BIO_printf(bio_out, "%s : (%s) : ", desc, type);
  if (strcmp(phase, OSSL_SELF_TEST_PHASE_PASS) == 0
          || strcmp(phase, OSSL_SELF_TEST_PHASE_FAIL) == 0)
      BIO_printf(bio_out, "%s\n", phase);
  /* Corromper la autocomprobación SHA1 durante la fase 'corrupt' devolviendo 0 */
  if (strcmp(phase, OSSL_SELF_TEST_PHASE_CORRUPT) == 0
          && strcmp(desc, OSSL_SELF_TEST_DESC_MD_SHA1) == 0) {
      BIO_printf(bio_out, "%s %s", phase, desc);
      return 0;
  }
  ret = 1;
err:
  return ret;
}

NOTAS

Algunas versiones publicadas de OpenSSL no incluyen un proveedor FIPS validado. Para determinar qué versiones se han sometido al proceso de validación, consulte la página de descargas de OpenSSL https://www.openssl.org/source/. Si necesita funcionalidad aprobada por FIPS, es esencial compilar su proveedor FIPS utilizando una de las versiones validadas que figuran allí. Normalmente, es posible utilizar un proveedor FIPS construido a partir de una de las versiones validadas junto con libcrypto y libssl compilados desde cualquier versión de la misma serie de versiones principales. Esta flexibilidad le permite abordar correcciones de errores y CVE que quedan fuera del límite FIPS.

Puede cargar el proveedor FIPS en múltiples contextos de biblioteca como cualquier otro proveedor. Sin embargo, se aplica la siguiente restricción. El proveedor FIPS no puede ser utilizado por múltiples copias de OpenSSL libcrypto en un solo proceso.

Dado que el proveedor guarda las devoluciones de llamada principales de la biblioteca libcrypto obtenida en la llamada a OSSL_provider_init() en datos globales, fallará si las invocaciones subsiguientes de su función OSSL_provider_init() devuelven direcciones diferentes de estas devoluciones de llamada que en la llamada inicial. Esto ocurre cuando diferentes copias de libcrypto están presentes en la memoria del proceso y ambas intentan cargar el mismo proveedor FIPS. Una solución es tener una copia diferente del proveedor FIPS cargada para cada una de las instancias de libcrypto en el proceso.
