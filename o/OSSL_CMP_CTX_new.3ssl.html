DESCRIPCION

Esta es la API de contexto para usar CMP (Certificate Management Protocol) con OpenSSL.

OSSL_CMP_CTX_new() asigna una estructura OSSL_CMP_CTX asociada al contexto de la biblioteca libctx y a la cadena de consulta de propiedades propq, ambas pueden ser NULL para seleccionar los valores predeterminados. Inicializa los campos restantes con sus valores por defecto; por ejemplo, la verbosidad del registro se establece en OSSL_CMP_LOG_INFO, el tiempo de espera del mensaje se establece en 120 segundos y el método de prueba de posesión se establece en OSSL_CRMF_POPO_SIGNATURE.

OSSL_CMP_CTX_free() desasigna una estructura OSSL_CMP_CTX. Si el argumento es NULL, no se hace nada.

OSSL_CMP_CTX_reinit() prepara el ctx dado para una transacción adicional borrando el estado de transacción (también conocido como sesión) interna de CMP, PKIStatusInfo, y cualquier resultado previo (newCert, newChain, caPubs y extraCertsIn) de la última transacción ejecutada. También borra cualquier ITAV que haya sido añadido por OSSL_CMP_CTX_push0_genm_ITAV(). Todos los demás valores de campo (es decir, opciones de CMP) se conservan para posible reutilización.

OSSL_CMP_CTX_get0_libctx() devuelve el argumento libctx que se utilizó al construir ctx con OSSL_CMP_CTX_new(), que puede ser NULL.

OSSL_CMP_CTX_get0_propq() devuelve el argumento propq que se utilizó al construir ctx con OSSL_CMP_CTX_new(), que puede ser NULL.

OSSL_CMP_CTX_set_option() establece el valor dado para la opción dada (por ejemplo, OSSL_CMP_OPT_IMPLICIT_CONFIRM) en la estructura OSSL_CMP_CTX dada.

Las siguientes opciones se pueden establecer:

OSSL_CMP_OPT_LOG_LEVEL
Establece el nivel de registro.
OSSL_CMP_OPT_IMPLICIT_CONFIRM
Si se establece, la confirmación implícita se utiliza cuando sea posible, en lugar de esperar explícitamente una confirmación de certificado.
OSSL_CMP_OPT_UNPROTECTED_Basic_Challenge
Permitir solicitudes Basic Challenge no protegidas.
OSSL_CMP_OPT_UNPROTECTED_POP
Permitir solicitudes de Prueba de Posesión (POP) no protegidas.
OSSL_CMP_OPT_SEND_UNPROTECTED_EVERYWHERE
Permitir el envío de mensajes no protegidos en cualquier lugar.
OSSL_CMP_OPT_ALLOW_UNPROTECTED_GETPOPO
Permitir solicitudes GETPOPO no protegidas.
OSSL_CMP_OPT_DISABLE_CONFIRM
Deshabilitar la confirmación de certificado.
OSSL_CMP_OPT_SEND_BACKDATED_CERT
Permitir el envío de certificados con fecha anterior.
OSSL_CMP_OPT_TRANS_ID_LEN
Establece la longitud del ID de transacción.
OSSL_CMP_OPT_VALIDITY_LEN
Establece la longitud de la validez del certificado.
OSSL_CMP_OPT_MAX_TOTAL_LEN
Establece la longitud máxima total de los datos de mensajes.
OSSL_CMP_OPT_POPO_CORRELATION
Establecer el método de correlación de POP.

OSSL_CMP_CTX_get_option() recupera el valor de la opción dada.

OSSL_CMP_CTX_set_log_cb() establece la función de devolución de llamada de registro para ctx. Si cb es NULL, se deshabilita el registro.

OSSL_CMP_CTX_set_log_verbosity() establece el nivel de verbosidad del registro para ctx. Los niveles de registro válidos son:

OSSL_CMP_LOG_NONE
OSSL_CMP_LOG_ERR
OSSL_CMP_LOG_WARN
OSSL_CMP_LOG_INFO
OSSL_CMP_LOG_DEBUG
OSSL_CMP_LOG_TRACE

OSSL_CMP_CTX_print_errors() imprime los errores registrados en el contexto ctx en la salida de error estándar.

OSSL_CMP_CTX_set1_serverPath() establece la ruta del servidor CMP. La cadena se copia.

OSSL_CMP_CTX_set1_server() establece la dirección del servidor CMP. La cadena se copia.

OSSL_CMP_CTX_set_serverPort() establece el puerto del servidor CMP.

OSSL_CMP_CTX_set1_proxy() establece el nombre del servidor proxy HTTP. La cadena se copia.

OSSL_CMP_CTX_set1_no_proxy() establece una lista de nombres de host para los cuales no se debe usar el proxy. La cadena se copia.

OSSL_CMP_CTX_set_http_cb() establece la función de devolución de llamada para la transferencia HTTP. Esta función se llama para realizar la transferencia HTTP real.

OSSL_CMP_CTX_set_http_cb_arg() establece el argumento para la función de devolución de llamada HTTP.

OSSL_CMP_CTX_get_http_cb_arg() recupera el argumento de la función de devolución de llamada HTTP.

OSSL_CMP_transfer_cb_t es un tipo de puntero a función que define la interfaz para la transferencia de mensajes CMP. La función debe tomar el contexto CMP y el mensaje de solicitud, y devolver el mensaje de respuesta.

OSSL_CMP_CTX_set_transfer_cb() establece la función de devolución de llamada para la transferencia de mensajes CMP.

OSSL_CMP_CTX_set_transfer_cb_arg() establece el argumento para la función de devolución de llamada de transferencia.

OSSL_CMP_CTX_get_transfer_cb_arg() recupera el argumento de la función de devolución de llamada de transferencia.

OSSL_CMP_CTX_set1_srvCert() establece el certificado del servidor CMP. El certificado se copia.

OSSL_CMP_CTX_set1_expected_sender() establece el nombre del remitente esperado del certificado del servidor. El nombre se copia.

OSSL_CMP_CTX_set0_trusted() es un alias de OSSL_CMP_CTX_set0_trustedStore().

OSSL_CMP_CTX_set0_trustedStore() establece el almacén de certificados de confianza para la validación del certificado del servidor. El almacén no se copia.

OSSL_CMP_OPT_LOG_VERBOSITY
El nivel de severidad necesario para emitir realmente mensajes de registro debido a errores, advertencias, información general, depuración, etc. El valor predeterminado es OSSL_CMP_LOG_INFO. Ver también OSSL_CMP_log_open(3).
OSSL_CMP_OPT_KEEP_ALIVE
Si el valor dado es 0, las conexiones HTTP no se mantienen abiertas después de recibir una respuesta, lo cual es el comportamiento predeterminado para HTTP 1.0. Si el valor es 1 o 2, se solicitan conexiones persistentes. Si el valor es 2, las conexiones persistentes son obligatorias, es decir, en caso de que el servidor no las conceda, se produce un error. El valor predeterminado es 1: preferir mantener la conexión abierta.
OSSL_CMP_OPT_MSG_TIMEOUT
Número de segundos que se permite que un viaje de ida y vuelta de mensajes de solicitud-respuesta CMP tome antes de que se devuelva un error de tiempo de espera. Un valor <= 0 significa que no hay limitación (espera indefinida). El valor predeterminado es utilizar la configuración OSSL_CMP_OPT_TOTAL_TIMEOUT.
OSSL_CMP_OPT_TOTAL_TIMEOUT
Número máximo total de segundos que puede durar una transacción, incluida la sondeo etc. Un valor <= 0 significa que no hay limitación (espera indefinida). El valor predeterminado es 0.
OSSL_CMP_OPT_USE_TLS
Utilice esta opción para indicar a la implementación HTTP si TLS se va a utilizar para la conexión (resultando en HTTPS). El valor 1 indica que TLS se utiliza para conexiones HTTP del lado del cliente, lo que requiere implementarse a través de una función de devolución de llamada establecida por OSSL_CMP_CTX_set_http_cb(). El valor 0 indica que TLS no se utiliza. El valor predeterminado es -1 por compatibilidad con versiones anteriores: TLS es utilizado por el cliente lado si y solo si OSSL_CMP_CTX_set_http_cb_arg() establece un argumento no NULL arg.
OSSL_CMP_OPT_VALIDITY_DAYS
Número de días para los que se solicitan nuevos certificados.
OSSL_CMP_OPT_SUBJECTALTNAME_NODEFAULT
No tomar Nombres Alternativos del Sujeto predeterminados del certificado de referencia.
OSSL_CMP_OPT_SUBJECTALTNAME_CRITICAL
Exigir que los Nombres Alternativos del Sujeto proporcionados se marquen como críticos.
OSSL_CMP_OPT_POLICIES_CRITICAL
Exigir que las políticas proporcionadas se marquen como críticas.
OSSL_CMP_OPT_POPO_METHOD
Selecciona el método de prueba de posesión a utilizar. Los valores posibles son: 
OSSL_CRMF_POPO_NONE       - Campo ProofOfPossession omitido,
                            lo que implica generación central de claves
OSSL_CRMF_POPO_RAVERIFIED - afirmar que la RA ya ha
                            verificado el PoPo
OSSL_CRMF_POPO_SIGNATURE  - firmar un valor con la clave privada,
                            que es el valor predeterminado.
OSSL_CRMF_POPO_KEYENC     - descifrar el certificado cifrado
                            ("método indirecto")

Tenga en cuenta que solo se puede producir un POPO basado en firma si se proporciona una clave privada como componente newPkey o pkey del cliente del contexto CMP.

OSSL_CMP_OPT_DIGEST_ALGNID
El NID del algoritmo de resumen a utilizar en MSG_SIG_ALG de RFC 4210 para protección de mensajes basada en firma y Prueba de Posesión (POPO). El valor predeterminado es SHA256.
OSSL_CMP_OPT_OWF_ALGNID El NID del algoritmo de resumen a utilizar como función unidireccional (OWF) para protección de mensajes basada en MAC con MAC basada en contraseña (PBM). Ver RFC 4210 sección 5.1.3.1 para detalles. El valor predeterminado es SHA256.
OSSL_CMP_OPT_MAC_ALGNID El NID del algoritmo MAC a utilizar para la protección de mensajes con PBM. El valor predeterminado es HMAC-SHA1 según RFC 4210.
OSSL_CMP_OPT_REVOCATION_REASON
El código de razón a incluir en una Solicitud de Revocación (RR); valores: 0..10 (RFC 5210, 5.3.1) o -1 para ninguno, que es el valor predeterminado.
OSSL_CMP_OPT_IMPLICIT_CONFIRM
Solicitar al servidor que habilite el modo de confirmación implícita, donde el cliente no necesita enviar confirmación al recibir el certificado. Si el servidor no habilita la confirmación implícita en el mensaje de respuesta, entonces la confirmación se envía de todos modos.
OSSL_CMP_OPT_DISABLE_CONFIRM
No confirmar los certificados inscritos, para hacer frente a servidores defectuosos que no admiten la confirmación implícita correctamente. ADVERTENCIA: esta configuración conduce a un comportamiento no especificado y está destinada exclusivamente a permitir la interoperabilidad con implementaciones de servidor que violan RFC 4210.
OSSL_CMP_OPT_UNPROTECTED_SEND
Enviar mensajes de solicitud o respuesta sin protección a nivel CMP.
OSSL_CMP_OPT_UNPROTECTED_ERRORS
Aceptar respuestas de error no protegidas que están explícitamente sin protección o donde la verificación de protección falló. Se aplica tanto a mensajes de error regulares como a respuestas de certificado (IP/CP/KUP) y respuestas de revocación (RP) con rechazo. ADVERTENCIA: esta configuración conduce a un comportamiento no especificado y está destinada exclusivamente a permitir la interoperabilidad con implementaciones de servidor que violan RFC 4210.
OSSL_CMP_OPT_IGNORE_KEYUSAGE
Ignorar las restricciones de uso de claves en el certificado del firmante al validar la protección basada en firma en mensajes CMP recibidos. De lo contrario, 'digitalSignature' debe estar permitido por los certificados del firmante CMP.
OSSL_CMP_OPT_PERMIT_TA_IN_EXTRACERTS_FOR_IR
Permitir recuperar un ancla de confianza de extraCerts y usarla para validar la cadena de certificados de un mensaje IP. Esta es una opción peculiar añadida para soportar 3GPP TS 33.310.

Tenga en cuenta que el uso de esta opción es peligroso, ya que el certificado obtenido de esta manera no ha sido autenticado (al menos no a nivel CMP). Tomarlo como ancla de confianza implementa confianza en el primer uso (TOFU).

OSSL_CMP_OPT_NO_CACHE_EXTRACERTS
No almacenar en caché los certificados recibidos en el campo de mensaje CMP extraCerts. De lo contrario, se almacenan para ayudar potencialmente a validar mensajes posteriores.

DESCRIPCIÓN

Estas funciones son utilidades para configurar un contexto CMP (ver OSSL_CMP_CTX_new(3)) y para obtener información de él.

OSSL_CMP_CTX_set1_oldCert() establece la certificación antigua en el contexto. Este valor por defecto se utiliza solo para solicitudes de inicialización (IR) y solicitudes de solicitud de certificación (CR), a menos que se hayan especificado algunos SANs. El subjectName también se utiliza como fallback para el campo de destinatario en los mensajes de CMP salientes si no se tiene una referencia de certificación disponible.

OSSL_CMP_CTX_push1_subjectAltName() agrega el nombre X509 dado a la lista de nombres alternos en la plantilla de solicitud de certificación. Esto no se puede usar si se ha especificado cualquier extensión de nombre alternos mediante OSSL_CMP_CTX_set0_reqExtensions(). Por defecto, si no se ha establecido OSSL_CMP_OPT_SUBJECTALTNAME_NODEFAULT, los nombres alternos se copian de la certificación de referencia, ver OSSL_CMP_CTX_set1_oldCert(). Si se ha especificado y el DN del sujeto no está establecido mediante OSSL_CMP_CTX_set1_subjectName(), la plantilla de un IR o CR no tendrá el DN del sujeto por defecto de la certificación de referencia. Si se desea un DN del sujeto, debe establecerlo explícitamente mediante OSSL_CMP_CTX_set1_subjectName().

OSSL_CMP_CTX_set0_reqExtensions() establece las extensiones X.509v3 a utilizar en IR/CR/KUR.

OSSL_CMP_CTX_reqExtensions_have_SAN() devuelve 1 si el contexto contiene una extensión de nombre alternos, de lo contrario 0 o -1 en error.

OSSL_CMP_CTX_push0_policy() agrega la información de objeto de política a X509_EXTENSIONS de la plantilla de solicitud de certificación.

OSSL_CMP_CTX_set1_oldCert() establece la certificación antigua para actualizar en solicitudes de cambio de clave (KUR) o revocar en solicitudes de revocación (RR). Para RR, este valor se ignora si se proporcionan el nombre del emisor y el número de serie mediante OSSL_CMP_CTX_set1_issuer() y OSSL_CMP_CTX_set1_serialNumber(). Para IR/CR/KUR, este establece la referencia de certificación, que de otro modo se usa como la certificación del CMP. La referencia de certificación determinada de esta manera, si existen, se utiliza para proporcionar valores por defecto de la clave pública, DN del sujeto, nombres alternos y DN del emisor en la plantilla de certificación de los mensajes de IR/CR/KUR.

El sujeto de la certificación de referencia se utiliza como valor del campo destinatario en las cabeceras de mensajes de CMP. Su emisor se utiliza como destinatario por defecto en las cabeceras de mensajes de CMP.

OSSL_CMP_CTX_set1_p10CSR() establece el PKCS#10 CSR a utilizar en los mensajes P10CR. Si se proporciona un CSR, sus campos de sujeto y clave pública también se utilizan como valores de reemplazo para la plantilla de IR/CR/KUR/RR, y las extensiones incluidas se agregan a la plantilla de IR/CR/KUR.

OSSL_CMP_CTX_push0_genm_ITAV() agrega el itav a la pila en el ctx que será el cuerpo de un mensaje general enviado con este contexto.

OSSL_CMP_certConf_cb() es la función de callback por defecto para la confirmación de certificados. Si el argumento del callback no es NULL, debe apuntar a un conjunto de certificados de confianza. En este caso, la función verifica que la certificación recién inscrita pueda ser verificada utilizando este conjunto de certificados de confianza y certificados no confiables de la ctx, que han sido ampliados por la lista de extraCerts. Durante esta verificación, se desactiva cualquier verificación de estado. Si el argumento del callback es NULL, la función intenta construir una cadena aproximada tan lejos como sea posible utilizando los mismos certificados no confiables de la ctx, y si esto falla, utiliza los extraCerts recibidos como fallback. La cadena de certificados resultante puede recuperarse mediante OSSL_CMP_CTX_get1_newChain(). Esta cadena excluye el certificado de hoja, es decir, el certificado recién inscrito. También se excluye el ancla de confianza (el certificado raíz).

OSSL_CMP_CTX_set_certConf_cb() establece el callback utilizado para evaluar la certificación recién inscrita antes de que la biblioteca envíe, según el resultado, un mensaje de tipo certConf positivo o negativo al servidor. El callback tiene el tipo:

typedef int (*OSSL_CMP_certConf_cb_t)(OSSL_CMP_CTX *ctx, X509 *cert, int fail_info, const char **txt);

y debe inspeccionar el certificado que se obtiene a través del parámetro cert y puede sobreescribir la predicción dada en los parámetros fail_info y *txt. Si acepta la certificación, debe devolver 0, indicando éxito. De lo contrario, debe devolver un bitfield reflejando OSSL_CMP_PKIFailureInfo con al menos un bit de fallo y puede establecer el parámetro *txt para apuntar a una constante de cadena con más detalles. El callback de transferencia puede usar un argumento definido personalmente almacenado en el ctx mediante OSSL_CMP_CTX_set_certConf_cb_arg(), que puede recuperarse mediante OSSL_CMP_CTX_get_certConf_cb_arg(). En general, el callback verificará al menos que el certificado pueda ser verificado usando un conjunto de certificados confiables. También podría comparar el DN del sujeto y otros campos del certificado recién inscrito con la plantilla de certificación del solicitante.

OSSL_CMP_CTX_set_certConf_cb_arg() establece un argumento, respectivamente un puntero a una estructura que contiene los argumentos, opcionalmente utilizado por el callback de confirmación de certificados. arg no se consume y debe así ser explícitamente liberado cuando no lo necesita más. arg puede ser NULL para limpiar el registro.

OSSL_CMP_CTX_get_certConf_cb_arg() obtiene el argumento, respectivamente el puntero a una estructura que contiene los argumentos, previamente establecido mediante OSSL_CMP_CTX_set_certConf_cb_arg(), o NULL si no ha sido establecido.

OSSL_CMP_CTX_get_status() devuelve para contextos de cliente el OSSL_CMP_PKISTATUS del estado PKI desde el último mensaje de CertRepMessage o Respuesta de Revocación o mensaje de error recibido:

OSSL_CMP_PKISTATUS_request
si no se pudo producir una solicitud IR/CR/KUR/RR/GENM,
OSSL_CMP_PKISTATUS_trans
en caso de error de transmisión o error de transacción para este tipo de solicitud, y
OSSL_CMP_PKISTATUS_unspecified
si no se intentó ninguna solicitud así o OSSL_CMP_CTX_reinit() ha sido llamado.

Para contextos de servidor, devuelve OSSL_CMP_PKISTATUS_trans si una transacción está abierta, de lo contrario OSSL_CMP_PKISTATUS_unspecified.

OSSL_CMP_CTX_get0_statusString() devuelve el statusString de la última recepción de mensaje de CertRepMessage o Respuesta de Revocación o mensaje de error, o NULL si no ha sido establecido.

OSSL_CMP_CTX_get_failInfoCode() devuelve el código de error del campo failInfo de la última recepción de mensaje de CertRepMessage o Respuesta de Revocación o mensaje de error, o -1 si no se ha recibido ninguna respuesta así o OSSL_CMP_CTX_reinit() ha sido llamado. Este es un bitfield y los flags se especifican en el archivo de encabezado <openssl/cmp.h>. Los flags comienzan con OSSL_CMP_CTX_FAILINFO, por ejemplo: OSSL_CMP_CTX_FAILINFO_badAlg. Devuelve -1 si el campo failInfoCode no está establecido.

OSSL_CMP_CTX_get0_validatedSrvCert() devuelve el certificado validado correctamente que el servidor utilizó en la transacción actual para la protección de mensajes de respuesta basada en la firma, o NULL si el servidor utilizó protección basada en MAC. El valor es relevante solo al final de una transacción exitosa. Puede usarse para verificar la autorización del servidor según su certificación.

OSSL_CMP_CTX_get0_newCert() devuelve el puntero al certificado nuevo obtenido si está disponible, de lo contrario NULL.

OSSL_CMP_CTX_get1_newChain() devuelve un puntero a una copia de la pila de certificados X.509 calculada mediante OSSL_CMP_certConf_cb() (si esta función ha sido llamada) en el mensaje de respuesta de la última transacción IP/CP/KUP.

OSSL_CMP_CTX_get1_caPubs() devuelve un puntero a una copia de la lista de certificados X.509 en el campo caPubs de la última respuesta de mensaje de certificación (de tipo IP, CP, o KUP), o una pila vacía si no se ha recibido ningún caPubs en la transacción actual.

OSSL_CMP_CTX_get1_extraCertsIn() devuelve un puntero a una copia de la lista de certificados X.509 contenidos en el campo extraCerts de la última respuesta de mensaje de certificación (excepto para pollRep y OSSL_CMP_PKIConf), o una pila vacía si no se ha recibido ningún extraCerts en la transacción actual.

OSSL_CMP_CTX_set1_transactionID() establece el ID de transacción dado en la estructura OSSL_CMP_CTX dada.

OSSL_CMP_CTX_set1_senderNonce() almacena el nonce del destinatario más reciente en ctx. Este se usará para validar el reciprocanteNonce en los mensajes entrantes.

NOTAS

CMP está definido en RFC 4210 (y CRMF en RFC 4211).

VALORES DE RETORNO

OSSL_CMP_CTX_free() y OSSL_CMP_CTX_print_errors() no devuelven nada.

OSSL_CMP_CTX_new(), OSSL_CMP_CTX_get0_libctx(), OSSL_CMP_CTX_get0_propq(), OSSL_CMP_CTX_get_http_cb_arg(), OSSL_CMP_CTX_get_transfer_cb_arg(), OSSL_CMP_CTX_get0_trusted(), OSSL_CMP_CTX_get0_untrusted(), OSSL_CMP_CTX_get0_geninfo_ITAVs(), OSSL_CMP_CTX_get0_newPkey(), OSSL_CMP_CTX_get_certConf_cb_arg(), OSSL_CMP_CTX_get0_statusString(), OSSL_CMP_CTX_get0_validatedSrvCert(), OSSL_CMP_CTX_get0_newCert(), OSSL_CMP_CTX_get1_caPubs(), y OSSL_CMP_CTX_get1_extraCertsIn() devuelven el valor de puntero intencionado como se describe o NULL en caso de error.

OSSL_CMP_CTX_get_option(), OSSL_CMP_CTX_reqExtensions_have_SAN(), OSSL_CMP_CTX_get_status(), y OSSL_CMP_CTX_get_failInfoCode() devuelven el valor intencionado como se describe o -1 en caso de error.

OSSL_CMP_certConf_cb() devuelve fail_info si no es igual a 0, de lo contrario 0 en caso de validación exitosa, o un bitfield con el bit OSSL_CMP_PKIFAILUREINFO_incorrectData establecido.

Todas las otras funciones, incluidas OSSL_CMP_CTX_reinit() y OSSL_CMP_CTX_reset_geninfo_ITAVs(), devuelven 1 en caso de éxito, 0 en caso de error.

EJEMPLOS

El siguiente código omite la gestión de errores.

Configura un contexto de cliente CMP para enviar solicitudes y verificar respuestas:

cmp_ctx = OSSL_CMP_CTX_new();
OSSL_CMP_CTX_set1_server(cmp_ctx, name_or_address);
OSSL_CMP_CTX_set1_serverPort(cmp_ctx, port_string);
OSSL_CMP_CTX_set1_serverPath(cmp_ctx, path_or_alias);
OSSL_CMP_CTX_set0_trusted(cmp_ctx, ts);

Configura credenciales simétricas para protección basada en MAC como PBM:

OSSL_CMP_CTX_set1_referenceValue(cmp_ctx, ref, ref_len);
OSSL_CMP_CTX_set1_secretValue(cmp_ctx, sec, sec_len);

EJEMPLOS

Establecer los detalles para las solicitudes de certificado:

OSSL_CMP_CTX_set1_subjectName(cmp_ctx, name);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, initialKey);

Realizar una transacción de Solicitud de Inicialización:

initialCert = OSSL_CMP_exec_IR_ses(cmp_ctx);

Restablecer el estado de la transacción del contexto CMP y las credenciales:

OSSL_CMP_CTX_reinit(cmp_ctx);
OSSL_CMP_CTX_set1_referenceValue(cmp_ctx, NULL, 0);
OSSL_CMP_CTX_set1_secretValue(cmp_ctx, NULL, 0);

Realizar una transacción de Solicitud de Certificación, haciendo uso de las nuevas credenciales:

OSSL_CMP_CTX_set1_cert(cmp_ctx, initialCert);
OSSL_CMP_CTX_set1_pkey(cmp_ctx, initialKey);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, curentKey);
currentCert = OSSL_CMP_exec_CR_ses(cmp_ctx);

Realizar una Solicitud de Actualización de Clave, firmada utilizando el certificado (y la clave) a actualizar:

OSSL_CMP_CTX_reinit(cmp_ctx);
OSSL_CMP_CTX_set1_cert(cmp_ctx, currentCert);
OSSL_CMP_CTX_set1_pkey(cmp_ctx, currentKey);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, updatedKey);
currentCert = OSSL_CMP_exec_KUR_ses(cmp_ctx);
currentKey = updatedKey;

Realizar una transacción de Mensaje General incluyendo, como ejemplo, el OID id-it-signKeyPairTypes e imprimiendo información sobre el contenido de la Respuesta General:

OSSL_CMP_CTX_reinit(cmp_ctx);
ASN1_OBJECT *type = OBJ_txt2obj("1.3.6.1.5.5.7.4.2", 1);
OSSL_CMP_ITAV *itav = OSSL_CMP_ITAV_create(type, NULL);
OSSL_CMP_CTX_push0_genm_ITAV(cmp_ctx, itav);
STACK_OF(OSSL_CMP_ITAV) *itavs;
itavs = OSSL_CMP_exec_GENM_ses(cmp_ctx);
print_itavs(itavs);
sk_OSSL_CMP_ITAV_pop_free(itavs, OSSL_CMP_ITAV_free);

HISTORIA

Las funciones CMP de OpenSSL se añadieron en OpenSSL 3.0.

OSSL_CMP_CTX_get0_trustedStore() se renombró a OSSL_CMP_CTX_get0_trusted() y OSSL_CMP_CTX_set0_trustedStore() se renombró a OSSL_CMP_CTX_set0_trusted(), utilizando macros, mientras se mantenían los nombres antiguos por compatibilidad con versiones anteriores, en OpenSSL 3.2.

OSSL_CMP_CTX_reset_geninfo_ITAVs() se añadió en OpenSSL 3.0.8.

OSSL_CMP_CTX_set1_serialNumber(), OSSL_CMP_CTX_get0_libctx(), OSSL_CMP_CTX_get0_propq(), y OSSL_CMP_CTX_get0_validatedSrvCert() se añadieron en OpenSSL 3.2.

OSSL_CMP_CTX_get0_geninfo_ITAVs() se añadió en OpenSSL 3.3.

El soporte para la generación central de claves, solicitado a través de OSSL_CRMF_POPO_NONE, se añadió en OpenSSL 3.5.
