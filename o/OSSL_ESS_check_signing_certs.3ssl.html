OSSL_ESS_check_signing_certs(3ssl)

Paquete: openssl

Licencias: Apache-2.0

OSSL_ESS_CHECK_SIGNING_CERTS(3ssl) OpenSSL OSSL_ESS_CHECK_SIGNING_CERTS(3ssl)

NOMBRE

OSSL_ESS_signing_cert_new_init, OSSL_ESS_signing_cert_v2_new_init, OSSL_ESS_check_signing_certs - Funciones de Enhanced Security Services (ESS)

SINOPSIS

#include <openssl/ess.h>
ESS_SIGNING_CERT *OSSL_ESS_signing_cert_new_init(const X509 *signcert,
                                                 const STACK_OF(X509) *certs,
                                                 int set_issuer_serial);
ESS_SIGNING_CERT_V2 *OSSL_ESS_signing_cert_v2_new_init(const EVP_MD *hash_alg,
                                                       const X509 *signcert,
                                                       const
                                                       STACK_OF(X509) *certs,
                                                       int set_issuer_serial);
int OSSL_ESS_check_signing_certs(const ESS_SIGNING_CERT *ss,
                                 const ESS_SIGNING_CERT_V2 *ssv2,
                                 const STACK_OF(X509) *chain,
                                 int require_signing_cert);

DESCRIPCIÓN

OSSL_ESS_signing_cert_new_init() genera una nueva estructura ESS_SIGNING_CERT que hace referencia al signcert dado y a cualquier certs adicional usando sus huellas digitales SHA-1. Si set_issuer_serial es distinto de cero, entonces también se incluyen el emisor y el número de serie de signcert en el campo ESS_CERT_ID como campo issuerSerial. Para todos los miembros de certs, el campo issuerSerial siempre se incluye.

OSSL_ESS_signing_cert_v2_new_init() es lo mismo que OSSL_ESS_signing_cert_new_init() excepto que utiliza el hash_alg dado y genera una estructura ESS_SIGNING_CERT_V2 con elementos ESS_CERT_ID_V2.

OSSL_ESS_check_signing_certs() comprueba si la cadena de validación chain contiene los certificados requeridos por los identificadores dados en ss y/o ssv2. Si require_signing_cert es distinto de cero, ss o ssv2 no deben ser NULL. Si tanto ss como ssv2 no son NULL, se evalúan de forma independiente. La lista de identificadores de certificados en ss es de tipo ESS_CERT_ID, mientras que la lista contenida en ssv2 es de tipo ESS_CERT_ID_V2. En la medida en que estas listas estén presentes, deben ser no vacías. El certificado identificado por su primera entrada debe ser el primer elemento de chain, es decir, el certificado firmante. Cualquier certificado adicional referenciado en la lista también debe encontrarse en chain. La coincidencia se realiza utilizando el algoritmo de hash y el valor del certificado dados. Además de las comprobaciones requeridas por las RFC 2624 y 5035, si el campo issuerSerial se incluye en un ESSCertID o ESSCertIDv2, debe coincidir con los atributos del emisor y número de serie del certificado.

NOTAS

ESS se definió en la RFC 2634, que ha sido actualizada en la RFC 5035 (ESS versión 2) para soportar algoritmos de hash distintos de SHA-1. Esto se utiliza para TSP (RFC 3161) y CAdES-BES (RFC 5126 informativa).

VALORES DE RETORNO

OSSL_ESS_signing_cert_new_init() y OSSL_ESS_signing_cert_v2_new_init() devuelven un puntero a la nueva estructura o NULL en caso de fallo de asignación de memoria.

OSSL_ESS_check_signing_certs() devuelve 1 en caso de éxito, 0 si no se puede encontrar un certificado requerido, -1 en caso de otro error.

VER TAMBIÉN

TS_VERIFY_CTX_set_certs(3), CMS_verify(3)

HISTORIA

OSSL_ESS_signing_cert_new_init(), OSSL_ESS_signing_cert_v2_new_init() y OSSL_ESS_check_signing_certs() se añadieron en OpenSSL 3.0.
