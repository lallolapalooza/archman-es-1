OSSL_STORE_open(3ssl)

Paquete: openssl

Licencias: Apache-2.0

OSSL_STORE_OPEN(3ssl) OpenSSL OSSL_STORE_OPEN(3ssl)

NOMBRE

OSSL_STORE_CTX, OSSL_STORE_post_process_info_fn, OSSL_STORE_OPEN, OSSL_STORE_OPEN_ex, OSSL_STORE_ctrl, OSSL_STORE_load, OSSL_STORE_eof, OSSL_STORE_delete, OSSL_STORE_error, OSSL_STORE_close - Tipos y funciones para leer objetos de una URI

SINOPSIS

#include <openssl/store.h>
typedef struct ossl_store_ctx_st OSSL_STORE_CTX;
typedef OSSL_STORE_INFO *(*OSSL_STORE_post_process_info_fn)(OSSL_STORE_INFO *,
                                                            void *);
OSSL_STORE_CTX *OSSL_STORE_OPEN(const char *uri, const UI_METHOD *ui_method,
                                void *ui_data,
                                OSSL_STORE_post_process_info_fn post_process,
                                void *post_process_data);
OSSL_STORE_CTX *
OSSL_STORE_OPEN_ex(const char *uri, OSSL_LIB_CTX *libctx, const char *propq,
                   const UI_METHOD *ui_method, void *ui_data,
                   const OSSL_PARAM params[],
                   OSSL_STORE_post_process_info_fn post_process,
                   void *post_process_data);
OSSL_STORE_INFO *OSSL_STORE_LOAD(OSSL_STORE_CTX *ctx);
int OSSL_STORE_EOF(OSSL_STORE_CTX *ctx);
int OSSL_STORE_DELETE(const char *uri, OSSL_LIB_CTX *libctx, const char *propq,
                      const UI_METHOD *ui_method, void *ui_data,
                      const OSSL_PARAM params[]);
int OSSL_STORE_ERROR(OSSL_STORE_CTX *ctx);
int OSSL_STORE_CLOSE(OSSL_STORE_CTX *ctx);

Las siguientes funciones han sido obsoletas desde OpenSSL 3.0 y pueden ser ocultadas completamente definiendo OPENSSL_API_COMPAT con un valor adecuado, véase openssl_user_macros(7):

int OSSL_STORE_CTRL(OSSL_STORE_CTX *ctx, int cmd, ... /* args */);

DESCRIPCIÓN

Estas funciones ayudan al programa a obtener objetos soportados (ver "OBJETOS SOPORTADOS" en OSSL_STORE_INFO(3) para información sobre cuáles son estos) desde una URI dada. El método general para hacerlo es abrir la URI usando OSSL_STORE_OPEN(), leer cada objeto disponible y soportado usando OSSL_STORE_LOAD() hasta que OSSL_STORE_EOF() no haya sido alcanzado, y finalizarlo con OSSL_STORE_CLOSE().

La información recuperada está almacenada en un OSSL_STORE_INFO, que se describe en OSSL_STORE_INFO(3).

Tipos

OSSL_STORE_CTX es un contexto que contiene toda la información interna para OSSL_STORE_OPEN(), OSSL_STORE_OPEN_ex(), OSSL_STORE_LOAD(), OSSL_STORE_EOF() y OSSL_STORE_CLOSE() para trabajar juntos.

Funciones

OSSL_STORE_OPEN_ex() toma una URI o ruta uri, un método de entrada de contraseña ui_method con datos asociados ui_data, y un callback de post-procesamiento post_process con datos asociados post_process_data, un contexto de librería libctx con una consulta de propiedad propq, y abre un canal para los datos ubicados en la URI, devolviendo un OSSL_STORE_CTX con toda la información interna necesaria. Los datos asociados ui_method y ui_data se usarán por todas las funciones que usen OSSL_STORE_CTX cuando se requiera interacción, por ejemplo para proporcionar una contraseña. Los parámetros auxiliares OSSL_PARAM(3) en params pueden ser establecidos para modificar aún más la operación del store. Los datos asociados post_process y post_process_data se usarán por OSSL_STORE_LOAD() para modificar o eliminar el valor a devolver. El callback post_process elimina valores devolviendo NULL, lo que causará que OSSL_STORE_LOAD() comience su proceso de carga del siguiente objeto, hasta que post_process devuelva algo diferente de NULL, o hasta que se alcance el final de datos indicado por OSSL_STORE_EOF().

OSSL_STORE_OPEN() es similar a OSSL_STORE_OPEN_ex() pero usa NULL para params, el contexto de librería libctx y la consulta de propiedad propq.

OSSL_STORE_CTRL() toma un OSSL_STORE_CTX y un número de comando cmd y más argumentos no especificados aquí. Los números de comando específicos del cargador y los argumentos que cada uno toma dependen del cargador utilizado y se documentan junto con ese cargador.

También hay controles globales disponibles:

OSSL_STORE_C_USE_SECMEM
Controla si el cargador debe intentar usar memoria segura para cualquier OSSL_STORE_INFO y sus contenidos. Este control espera un argumento, un puntero a un *int* que se espera tenga el valor 1 (sí) o 0 (no). Cualquier otro valor es un error.

OSSL_STORE_LOAD() toma un OSSL_STORE_CTX e intenta cargar el siguiente objeto y lo devuelve envuelto en OSSL_STORE_INFO.

OSSL_STORE_DELETE() elimina el objeto identificado por uri.

OSSL_STORE_EOF() toma un OSSL_STORE_CTX y comprueba si se ha alcanzado el final de los datos.

OSSL_STORE_ERROR() toma un OSSL_STORE_CTX y comprueba si se produjo un error en la última llamada a OSSL_STORE_LOAD(). Nota: puede ser útil intentar cargar más objetos, a menos que OSSL_STORE_EOF() indique que el final de los datos ha sido alcanzado.

OSSL_STORE_CLOSE() toma un OSSL_STORE_CTX, cierra el canal que fue abierto por OSSL_STORE_OPEN() y libera toda la información que fue almacenada en el OSSL_STORE_CTX, así como el propio OSSL_STORE_CTX. Si ctx es NULL, no hace nada.

NOTAS

Una cadena sin prefijo de esquema (es decir, una cadena que no es URI) se interpreta implícitamente como usando el esquema file:.

Hay algunas herramientas que pueden usarse junto con OSSL_STORE_OPEN() para determinar si algún error se produce debido a una URI no analizable o si es un error diferente (como fallos de memoria de asignación); si la URI era analizable pero el esquema no está registrado, el error más alto tendrá el motivo "OSSL_STORE_R_UNREGISTERED_SCHEME".

Estas funciones no hacen ninguna suposición directa sobre la frase de contraseña recibida del callback de contraseña. Los cargadores pueden hacer suposiciones, sin embargo. Por ejemplo, el cargador file: hereda las suposiciones hechas por la funcionalidad de OpenSSL que maneja diferentes tipos de archivos; esto es principalmente relevante para los objetos PKCS#12. Véase passphrase-encoding(7) para más información.

VALORES DE RETORNO

OSSL_STORE_OPEN() devuelve un puntero a OSSL_STORE_CTX en caso de éxito, o NULL en caso de fallo.

OSSL_STORE_LOAD() devuelve un puntero a OSSL_STORE_INFO en caso de éxito, o NULL en caso de error o al alcanzar el final de los datos. Use OSSL_STORE_ERROR() y OSSL_STORE_EOF() para determinar el significado de un retorno NULL.

OSSL_STORE_EOF() devuelve 1 si se ha alcanzado el final de los datos o se ha producido un error, 0 en caso contrario.

OSSL_STORE_ERROR() devuelve 1 si se produjo un error en una llamada a OSSL_STORE_LOAD(), de lo contrario 0.

OSSL_STORE_DELETE(), OSSL_STORE_CTRL() y OSSL_STORE_CLOSE() devuelven 1 en caso de éxito, o 0 en caso de fallo.

VER TAMBIÉN

ossl_store(7), OSSL_STORE_INFO(3), OSSL_STORE_register_loader(3), passphrase-encoding(7)

HISTORIA

OSSL_STORE_DELETE() fue agregado en OpenSSL 3.2.

OSSL_STORE_OPEN_ex() fue agregado en OpenSSL 3.0.

OSSL_STORE_CTX, OSSL_STORE_post_process_info_fn(), OSSL_STORE_OPEN(), OSSL_STORE_CTRL(), OSSL_STORE_LOAD(), OSSL_STORE_EOF() y OSSL_STORE_CLOSE() fueron agregados en OpenSSL 1.1.1.

El manejo de un argumento ctx nulo para OSSL_STORE_CLOSE() fue introducido en OpenSSL 1.1.1h.

OSSL_STORE_CTRL() y OSSL_STORE_vctrl() fueron obsoletos en OpenSSL 3.0.
