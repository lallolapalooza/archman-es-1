Documentación de constructor y destructor

OpenDBX::Conn::Conn ()

El constructor por defecto para objetos de conexión recién creados sin parámetros. Este método se proporciona para permitir a los programadores utilizar objetos de conexión como variables miembro de otras clases. Se inicializan en el momento de la construcción del objeto que encapsula cuando aún no se dispone de valores para el backend, host y puerto.

Es necesario reemplazar el objeto creado posteriormente por una instancia de conexión en la que se hayan proporcionado los parámetros necesarios a través de uno de los otros constructores. No es posible llamar a ninguna de las funciones miembro de una instancia creada por el constructor por defecto y se lanzará una excepción.

Devuelve

Instancia de conexión vacía

OpenDBX::Conn::Conn (const char * backend, const char * host = '', const char * port = '')

Crea un objeto de conexión usando parámetros de cadena de estilo C. Inicializa una nueva conexión utilizando los parámetros backend, host y port, pero aún no abre la conexión a la base de datos. Este método permite cadenas de estilo C como valores para todos los parámetros. También está disponible otro constructor para cadenas de estilo C++. Devuelve una nueva instancia de conexión, que puede usarse para consultar opciones implementadas por el controlador o para crear una sentencia. En caso de error, lanza una excepción OpenDBX con el mensaje de error, código y severidad.

El parámetro backend es el nombre del controlador que la biblioteca OpenDBX debe usar para conectarse a una base de datos. El nombre debe ser uno de los controladores implementados y disponibles en el sistema y distingue entre mayúsculas y minúsculas. Todos los nombres de controlador están en minúsculas, por ejemplo, 'mysql'.

Dependiendo del controlador de la base de datos, host puede tener diferentes significados. Normalmente, es el nombre o la dirección IP del servidor que aloja la aplicación del servidor de base de datos. En el caso de implementaciones de bases de datos sin servidor como SQLite, es la ruta del directorio donde se encuentra el archivo de la base de datos. La ruta debe contener los separadores de ruta específicos de la plataforma, como la barra ('/') en sistemas tipo Unix y la barra invertida ('\') en sistemas Windows. La ruta también debe terminar con el separador de ruta, como '/ruta/al/archivo/'.

Además, port puede ser el número o el nombre al que la aplicación del servidor de base de datos está escuchando. Si se permite un nombre en lugar del número depende de la biblioteca cliente de la base de datos, pero el número como cadena siempre funciona. Si se proporciona una cadena vacía, la biblioteca cliente de la base de datos utilizará el puerto predeterminado de la aplicación del servidor de base de datos.

Parámetros

backend Nombre del módulo backend a utilizar
host Nombre o dirección IP del servidor de base de datos
port Nombre o número del puerto utilizado por el servidor de base de datos

Devuelve

Instancia de conexión

Excepciones

std::invalid_argument Si el objeto solo se inicializó con el constructor por defecto
OpenDBX::Exception Si la biblioteca de base de datos subyacente devuelve un error

OpenDBX::Conn::~Conn ()

Destruye la instancia de conexión si no hay otras referencias. Cada objeto de conexión usa un contador de referencias para recordar si la conexión es compartida con otros objetos. Si esto no es el caso o si este objeto es el último que refiere a la conexión, la conexión se cierra y el espacio de memoria asignado se libera.

void OpenDBX::Conn::bind (const char * database, const char * who = '', const char * cred = '', odbxbind method = ODBX_BIND_SIMPLE)

Autentica al usuario y selecciona la base de datos utilizando parámetros estilo C. Después de inicializar la instancia del objeto con uno de los constructores que aceptan un módulo de backend, host y puerto como parámetro, es necesario autenticar al usuario y seleccionar una base de datos. Dependiendo de la librería cliente de la base de datos, también se establece la conexión con el servidor de base de datos. Este método acepta cadenas estilo C para el nombre de la base de datos, el nombre de usuario y la contraseña.

El primer parámetro, el nombre de la base de datos, se utilizará para seleccionar la base de datos en todos los comandos siguientes. La base de datos es el contenedor de las tablas, vistas, etc., que almacenan los registros y proporcionan acceso a ellos.

La autenticación se realiza en la mayoría de los casos mediante una combinación de nombre de usuario y contraseña. Si el nombre de usuario es conocido por el servidor de base de datos y la contraseña proporcionada coincide con la almacenada, el servidor de base de datos permitirá al usuario operar en la base de datos seleccionada y sus tablas, siempre que el usuario tenga permisos para leer y/o modificar el contenido.

El parámetro method puede utilizarse para seleccionar diferentes métodos de autenticación. Actualmente, solo se ofrece autenticación simple (ODBX_BIND_SIMPLE) con nombre de usuario y contraseña.

Parámetros

database Nombre de la base de datos gestionada por el servidor de base de datos
who Nombre de la cuenta de usuario conocida por el servidor de base de datos
cred Credencial necesaria perteneciente a la cuenta de usuario
method Método utilizado para la autenticación

Excepciones

std::invalid_argument Si el objeto fue solo inicializado mediante el constructor por defecto
OpenDBX::Exception Si la librería de base de datos devuelve un error

Stmt OpenDBX::Conn::create (const char * sql, unsigned long size = 0, Stmt::Type type = Stmt::Simple)

Crea una instancia de objeto de sentencia a partir de una cadena SQL utilizando un buffer estilo C. Este método devuelve una instancia de la clase Stmt que contiene la sentencia enviada al servidor de base de datos posteriormente. Actualmente, solo se soportan consultas simples, que se envían al servidor de base de datos para ser parseadas y devolver resultados después de invocar Stmt::execute(). Posteriormente, también se podrán manejar consultas preparadas, que se parsean por el servidor de base de datos cuando se crea el objeto y solo se envían los parámetros al servidor de base de datos durante la ejecución. Esto puede acelerar el proceso, especialmente si la consulta se ejecuta múltiples veces con contenido diferente para los parámetros.

El parámetro sql debe contener la cadena SQL que se debe enviar al servidor de base de datos para su ejecución. Debe ser un buffer estilo C en este caso. Para una referencia de consultas SQL válidas, por favor consulte la documentación del servidor de base de datos.

La longitud de la sentencia, excluyendo el carácter nulo de terminación '0', debe indicarse mediante el parámetro size. Si la longitud de la sentencia es desconocida, también se puede proporcionar un valor de tamaño 0, que es el valor predeterminado si se pasa solo un parámetro. En este caso, la longitud de la cadena se calcula internamente antes de que la sentencia sea enviada a la librería de base de datos nativa.

A través del último parámetro, se puede seleccionar cómo la sentencia debe tratarse internamente por OpenDBX y la librería de base de datos nativa. Actualmente, solo se ofrece procesamiento simple, que envía completamente las sentencias SQL incluyendo sus parámetros como cadena al servidor de base de datos para parsear y ejecutar. Posteriormente, también se podrá manejar consultas preparadas, que se parsean primero y solo se envían los parámetros al servidor antes de la ejecución. Este parámetro es opcional.

El objeto devuelto representa la sentencia dada, que puede ser ejecutada posteriormente. La sentencia es válida solo para la conexión actual y, una vez que la conexión se invalide o se cierre, el uso de este objeto lanzará un error.

Parámetros

sql Cadena SQL que contiene una sentencia válida comprensible por el servidor de base de datos
size Tamaño de la cadena SQL en bytes
type Tipo de objeto de sentencia que se crea

Devuelve

Instancia de sentencia vinculada a esta conexión

Excepciones

std::invalid_argument Si el objeto fue solo inicializado mediante el constructor por defecto
OpenDBX::Exception Si la librería de base de datos devuelve un error

void OpenDBX::Conn::prepare (const string & sql, odbxtype type)

Prepare an SQL statement for later execution. The statement is internally processed by OpenDBX and the native database library. Currently, only simple processing is available which sends complete SQL statements including its parameters as string to the database server for parsing and execution. Later on, also prepared statement handling will be available which parses the statements first and sends only the parameters to the server before execution. This parameter is also optional.

The returned object is representing the given statement, which can be executed later on. The statement is only valid for the current connection and as soon as the connection gets invalid or is closed, working with this object will throw an error.

Parameters

sql SQL text string containing a valid statement understood by the database server
type Type of statement object that should be created

Returns

Statement instance bound to this connection

Exceptions

std::invalid_argument If the object was only initialized by the default constructor
OpenDBX::Exception If the underlying database library returns an error

string & OpenDBX::Conn::escape (const char * from, unsigned long fromlen, string & to)

Escapes potentially dangerous characters in user input using a C style buffer. For preventing SQL injection attacks which can have desasterous effects, all text input that will be part of an SQL statement must be escaped. This does also apply to user content that is already stored in the database and should be copied to another record or stored again as the escaping is removed before the database server writes the content to disk.

The first parameter must contain the character sequence that should be escaped as C style string. This string itself won't be modified by this method.

The escaped string will be written to the third parameter named to, which have to be also an C++ style string. After transforming the input to an escaped string, the result may be more then twice the size of the original input. The additional escape sequences aren't stored in the database column so only the original string will be written to the disk.

A C++ reference of the third parameter containing the escaped string afterwards is also returned by this method to providing the possibility to write more elegant code.

Parameters

from Input string with which may contain dangerous characters
fromlen Size of the input string to escape in bytes
to String instance where the escaped characters should be written to

Returns

Reference to the second parameter containing the escaped characters

Exceptions

std::invalid_argument If the object was only initialized by the default constructor
OpenDBX::Exception If the underlying database library returns an error

bool OpenDBX::Conn::getCapability (odbxcap cap)

Tests if the database driver module does understand certain extensions. The OpenDBX library consists of a basic set of functions that must be implemented by all drivers and optional sets for additional functionality. This method allows an application to ask the driver selected by the first parameter of the constructor of this object if it supports one or more optional sets. The available sets and its constants are:

  • ODBX_CAP_BASIC
    The core function set which have to be implemented by all backends. It consists of all functions necessary to connect to, send textual queries to and process simple results returned from the database server as well as error handling functions.
  • ODBX_CAP_LO
    The function set for handling large objects whose content isn't accessible by the basic function. Currently, Firebird/Interbase and Oracle requires using the LOB functions.

The basic set makes sure that all drivers can handle connections to the databases, send statements and retrieve results. It's supported by all drivers and usually don't have to be checked.

Some databases client libraries provide the content of large objects not via the basic functions. Instead, the Result::fieldValue() method returns only a handle to the large object and reading or modifying the content of this data object requires calling additional methods.

Parameters

cap Constant of the capability

Returns

True if supported, false if not

Exceptions

std::invalid_argument If the object was only initialized by the default constructor
OpenDBX::Exception If the underlying database library returns an error

void OpenDBX::Conn::getOption (odbxopt option, void * value)

Gets the value of a certain option provided by the database driver module. It asks the backend module for implemented options and their current values. This function can be used at every stage and its primary use is to find out supported features of the backend module. This features can be enable with setOption() before the connection to the database server is established by calling bind().

There are several option values defined as named constants in the opendbx/api.h header file. A few of them are for informational purpose only while most of the options can also be set to different values by setOption() to change the behavior of the backend module. These options are:

  • ODBX_OPT_API_VERSION
    The API version implemented by the backend. It returns a five digit number representing the API version of the backend module in the form XYYZZ where X is the major number, YY the revision and ZZ the minor number of the API.
  • ODBX_OPT_THREAD_SAFE
    If it is safe to use this backend and especially the native database client library in an application which uses threads where more than one thread opens database connections via the OpenDBX library.
  • ODBX_OPT_TLS
    The database client library may support transmitting all data securely by encrypting the network traffic via SSL or TLS.
  • ODBX_OPT_MULTI_STATEMENTS
    The database server may be able to support multiple SQL statements in one string sent to the database.
  • ODBX_OPT_PAGED_RESULTS
    All database servers and client libraries are able to transfer the records row by row. Some of them can also transfer multiple rows or even all at once to minimize server load, network traffic and latency. The downside of this is an increased memory consumption.
  • ODBX_OPT_COMPRESS
    Support of compressed network traffic between database client and server. This can lead to higher throughput if the network is the bottleneck.
  • ODBX_OPT_MODE
    Some database servers support different modes of operation, e.g. modes for compliance to other SQL implementations or completely different query languages.

The parameter value must be a pointer to an integer variable where the backend module will store the result for the supplied option. If it's not stated otherwise, the value assigned to the this parameter will be of boolean nature and therefore is ODBX_ENABLE for a supported option or ODBX_DISABLE for an option which isn't supported.

Parameters

option Constant of the option
value Pointer to memory where the result is stored

Exceptions

void OpenDBX::Conn::setOption (odbxopt opción, void * valor)

Establece una opción específica proporcionada por el módulo del controlador de base de datos. Cambia el valor de la opción especificada en el módulo backend o en la biblioteca de base de datos nativa. Antes de intentar establecer una opción, debe probarla con getOption() para asegurarse de que sea compatible con el backend. Casi todas las opciones deben establecerse antes de conectarse al servidor de base de datos usando bind() para que surtan efecto.

Hay varios valores de opción definidos como constantes con nombre en el archivo opendbx/api.h. Las opciones posibles son:

  • ODBX_OPT_TLS
    Usa cifrado para transmitir todos los datos de forma segura a través de la red mediante SSL o TLS. Esta opción se puede establecer en ODBX_TLS_NEVER (el valor predeterminado) para evitar el cifrado, ODBX_TLS_ALWAYS para exigir el cifrado y fallar si no se puede usar entre la biblioteca del cliente y el servidor, o ODBX_TLS_TRY para usar el cifrado si es posible con la opción de recurrir a una conexión no cifrada.
  • ODBX_OPT_MULTI_STATEMENTS
    Habilita el servidor de base de datos para aceptar múltiples sentencias en una cadena a la base de datos si el valor se establece en ODBX_ENABLE. Sin embargo, podría ser posible deshabilitarlo estableciéndolo en ODBX_DISABLE.
  • ODBX_OPT_PAGED_RESULTS
    Todos los servidores de bases de datos y bibliotecas de clientes pueden transferir los registros fila por fila. Algunos de ellos también pueden transferir múltiples filas o incluso todas a la vez para minimizar la carga del servidor, el tráfico de red y la latencia. La desventaja de esto es un mayor consumo de memoria. Si los resultados paginados son compatibles con el backend, pasar valores positivos obtendrá el número especificado de registros a la vez del servidor de base de datos. El valor cero ('0') es especial en este caso porque le pide al módulo backend que recupere todos los registros a la vez.
  • ODBX_OPT_COMPRESS
    Habilita el tráfico de red comprimido entre el cliente y el servidor de la base de datos. Esto puede maximizar el rendimiento si la red es el cuello de botella. Pase una variable entera con ODBX_ENABLE para habilitar la compresión o con ODBX_DISABLE para deshabilitarla para esta conexión.
  • ODBX_OPT_MODE
    Algunos servidores de bases de datos admiten diferentes modos de operación, por ejemplo, modos de cumplimiento con otras implementaciones de SQL o lenguajes de consulta completamente diferentes. El valor de esta opción debe apuntar a una cadena terminada en cero.

Si no se indica lo contrario, el tipo del valor pasado al segundo parámetro, denominado valor, debe ser un puntero a un entero. Sus valores deben estar en el rango especificado por la opción que se está modificando.
