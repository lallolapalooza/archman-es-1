DESCRIPTION

OSSL_HTTP_REQ_CTX is a context structure for an HTTP request and response, used to collect all necessary data for performing such a request.

This man page documents low level HTTP functions rarely used directly. Higher level functions like OSSL_HTTP_get(3) and OSSL_HTTP_transfer(3) should be preferred.

OSSL_HTTP_REQ_CTX_new() allocates a new HTTP request context structure, which is filled with the BIO to write/send the request to (wbio), the BIO to read/receive the response from (rbio, which may be the same as wbio), and the maximum header line length expected buf_size. A value <= 0 indicates that the default OSSL_HTTP_DEFAULT_MAX_LINE_LEN of 4 KiB should be used. buf_size is also used as the number of bytes to read at a time. The context structure includes an internal memory BIO that collects the HTTP request header lines.

OSSL_HTTP_REQ_CTX_free() frees the HTTP request context rctx. The rbio is not freed, wbio is freed if free_wbio is specified. If the argument is NULL, nothing is done.

OSSL_HTTP_REQ_CTX_set_request_line() adds the first HTTP request line to rctx. The HTTP method is determined by method_POST, which must be 1 to indicate "POST" or 0 to indicate "GET". server and port can be set to indicate the server and optional port that an HTTP proxy should pass the request to, otherwise they must be NULL. path provides the HTTP request path; if it is NULL, "/" is used. For backward compatibility, path may start with "http://" and thus an absolute URI can be indicated. In this case, it indicates that an HTTP proxy is being used and also provides the server (and optionally port) that the proxy should pass the request to. In this case server and port must be NULL.

OSSL_HTTP_REQ_CTX_add1_header() adds the header name with value value to rctx. It can be called more than once to add multiple header lines. For example, to add the "Host" header for "example.com", one would call:

OSSL_HTTP_REQ_CTX_add1_header(ctx, "Host", "example.com");

OSSL_HTTP_REQ_CTX_set_expected() optionally sets HTTP client expectations on the response. Due to the structure of an HTTP request, if the argument keep_alive is non-zero, it must be called before using OSSL_HTTP_REQ_CTX_set1_req().

If the argument expected_content_type is not NULL, the client will check that the value specified in the "Content-Type" header line is included in the response header and return an error if it is not. In the "Content-Type" header line, the specified value must be present as such, or in case the specified value does not contain a ";" character, it is sufficient that it appears as a prefix in the header line, followed by a ";" and any further text. For example, if the argument expected_content_type specifies "text/html", "Text/HTML", "text/html; charset=UTF-8", etc., will match.

If the parameter expect_asn1 is non-zero, an ASN.1 structure is expected as the response body and data input is disabled. This means that an ASN.1 sequence must be required in the header, its length field is checked and OSSL_HTTP_REQ_CTX_get0_mem_bio() must be used to get the response body previously bufferized. Otherwise (default), any input format is allowed, with response body length checks only on error messages. In this case the BIO given as rbio in OSSL_HTTP_REQ_CTX_new() must be used directly to read the response contents, which may support streaming.

If the parameter timeout is greater than 0, it indicates the maximum number of seconds that the HTTP transfer (sending the request and receiving a response) is allowed to complete. timeout == 0 enables waiting indefinitely, i.e. no timeout. This is the default. timeout < 0 takes the value set by the overall_timeout argument of OSSL_HTTP_open(3) with the default value of 0, meaning no timeout.

If the parameter keep_alive is 0, which is the default, the connection is not kept alive after receiving a response. This is the default behavior for HTTP 1.0. If the value is 1 or 2, a persistent connection is requested. If the value is 2, a persistent connection is required, i.e. an error occurs if the server does not grant it.

OSSL_HTTP_REQ_CTX_set1_req() finalizes the HTTP request context. It must be used if the parameter method_POST in OSSL_HTTP_REQ_CTX_set_request_line() was 1 and an ASN.1 request is to be sent. It must also be used when requesting "keep-alive" even if a GET request is to be sent, in which case req must be NULL. Unless req is NULL, the function adds the DER encoding of req using the ASN.1 model it for encoding (which does not support streaming). The HTTP header "Content-Length" is filled with the length of the request. content_type must be NULL if req is NULL. If content_type is not NULL, the "Content-Type" header is also added with the specified value. Header lines are added to the internal memory BIO of the request context.

OSSL_HTTP_REQ_CTX_nbio() attempts to send the prepared request in rctx and collect the HTTP response, using the wbio and rbio that were used when calling OSSL_HTTP_REQ_CTX_new(). The function may need to be called again if its result is -1, which indicates BIO_should_retry(3). In that case, it is recommended to wait a bit between calls, using BIO_wait(3) on the read BIO to avoid a busy-wait loop. See OSSL_HTTP_REQ_CTX_set_expected() on how the response content type, response body, HTTP transfer timeout and keep-alive are handled. Any error message body is consumed.

OSSL_HTTP_REQ_CTX_nbio_d2i() attempts to read and decode an ASN.1 structure from the response, using the ASN.1 model it. The decoded value is stored in **pval. See OSSL_HTTP_REQ_CTX_nbio() on how the response is consumed.

OSSL_HTTP_REQ_CTX_exchange() sends the prepared request and receives the response. It is a convenience function that is equivalent to calling OSSL_HTTP_REQ_CTX_nbio() until it returns a value other than -1, and then returning the result.

OSSL_HTTP_REQ_CTX_get0_mem_bio() returns the memory BIO containing the response body, if it is available. This is usually the case when expect_asn1 is non-zero in OSSL_HTTP_REQ_CTX_set_expected(). Otherwise, the response body is streamed directly to the rbio specified in OSSL_HTTP_REQ_CTX_new(), and this function returns NULL.

OSSL_HTTP_REQ_CTX_get_resp_len() returns the length of the response body that has been received so far. This is useful when OSSL_HTTP_REQ_CTX_get0_mem_bio() returns a non-NULL value.

OSSL_HTTP_REQ_CTX_set_max_response_length() sets the maximum response length to len bytes. If the response exceeds this length, it is truncated and an error is returned. A value of 0 means no limit.

OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines() sets the maximum number of response header lines to count. If the response exceeds this number, it is truncated and an error is returned. A value of 0 means no limit.

OSSL_HTTP_is_alive() returns 1 if the connection is expected to be kept alive, 0 otherwise.

Returns 0 on success, -1 on error.

DESCRIPTION

These functions manage an HTTP request context and perform HTTP requests.

OSSL_HTTP_REQ_CTX_new() allocates and initializes a new HTTP request context. The caller must provide the read BIO (rbio) and write BIO (wbio) to use for the HTTP communication. These BIOs are owned by the context and will be freed when the context is freed. host and path are optional and used for generating a default request line and Host header if not otherwise specified. info_cb and info_cbarg are a callback function and its argument that will be called when certain events occur during the HTTP transaction, for example, when HTTP headers are received.

OSSL_HTTP_REQ_CTX_free() frees the HTTP request context rctx and any associated resources. The BIOs passed to OSSL_HTTP_REQ_CTX_new() are also freed.

OSSL_HTTP_REQ_CTX_set_request_line() sets the HTTP method (e.g. "GET") and the path for the request.

OSSL_HTTP_REQ_CTX_add1_header() adds an HTTP header line with the specified name and value to the request. This function can be called multiple times to add multiple headers. Note that certain headers like "Host" and "Content-Length" are handled specially.

OSSL_HTTP_REQ_CTX_set1_req() is used to set the client certificate and key for the request. cert_provider is the name of the provider for the certificate and key. cb is an async callback function for operations that may block.

OSSL_HTTP_REQ_CTX_set_expected() specifies the expected type of the response. Currently supported types are "OSSL_HTTP_EXPECT_ sesuatu" for ASN.1 encoded data or "OSSL_HTTP_EXPECT_nothing" for no response body expected. Default is "OSSL_HTTP_EXPECT_nothing".

OSSL_HTTP_REQ_CTX_nbio() performs a non-blocking HTTP request. It should be called repeatedly until it returns 1 (success), 0 (error or redirection), or -1 (retry). The BIOs rbio and wbio passed to OSSL_HTTP_REQ_CTX_new() are used for the exchange. It handles chunked transfer encoding, redirects, and content tracing if enabled. An error occurs if the "Content-Type" header is not included or its value starts with "text/". This is used for tracing the body contents if HTTP tracing is enabled. If the "Content-Length" header is present in the response and its value exceeds the maximum allowed response content length or the response is an error message with its body length exceeding this value or the content is an ASN.1-encoded structure with a length exceeding this value or both length indications are present but disagree then an error occurs.

OSSL_HTTP_REQ_CTX_nbio_d2i() is like OSSL_HTTP_REQ_CTX_nbio() but on success in addition parses the response, which must be a DER-encoded ASN.1 structure, using the ASN.1 template it and places the result in *pval.

OSSL_HTTP_REQ_CTX_exchange() calls OSSL_HTTP_REQ_CTX_nbio() as often as needed in order to exchange a request and response or until a timeout is reached. On success it returns a pointer to the BIO that can be used to read the result. If an ASN.1-encoded response was expected, this is the BIO returned by OSSL_HTTP_REQ_CTX_get0_mem_bio() when called after the exchange. This memory BIO does not support streaming. Otherwise the returned BIO is the rbio given to OSSL_HTTP_REQ_CTX_new(), which may support streaming. When this BIO is returned, it has been read past the end of the response header, such that the actual response body can be read from it. The returned BIO pointer MUST NOT be freed by the caller.

OSSL_HTTP_REQ_CTX_get0_mem_bio() returns the internal memory BIO. Before the HTTP request is sent, this could be used to adapt its header lines. Use with caution! After receiving a response via HTTP, the BIO represents the current state of reading the response header. If the response was expected to be ASN.1 encoded, its contents can be read via this BIO, which does not support streaming. The returned BIO pointer must not be freed by the caller.

OSSL_HTTP_REQ_CTX_get_resp_len() returns the size of the response contents in rctx if provided by the server as "Content-Length" header field, else 0.

OSSL_HTTP_REQ_CTX_set_max_response_length() sets the maximum allowed response content length for rctx to len. If not set or len is 0 then the OSSL_HTTP_DEFAULT_MAX_RESP_LEN is used, which currently is 100 KiB.

OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines() changes the limit for the number of HTTP header lines allowed to be received in a response. The default limit is OSSL_HTTP_DEFAULT_MAX_RESP_HDR_LINES, currently 256. If the limit is not 0 and the number of lines exceeds the limit, then the HTTP_R_RESPONSE_TOO_MANY_HDRLINES error is indicated. Setting the limit to 0 disables the check.

OSSL_HTTP_is_alive() can be used to query if the HTTP connection given by rctx is still alive, i.e., has not been closed. It returns 0 if rctx is NULL.

If the client application requested or required a persistent connection and this was granted by the server, it can keep rctx as long as it wants to send further requests and OSSL_HTTP_is_alive() returns nonzero, else it should call OSSL_HTTP_REQ_CTX_free(rctx) or OSSL_HTTP_close(3). In case the client application keeps rctx but the connection then dies for any reason at the server side, it will notice this obtaining an I/O error when trying to send the next request via rctx.

WARNINGS

The server's response may be unexpected if the hostname that was used to create the wbio, any "Host" header, and the host specified in the request URL do not match.

Many of these functions must be called in a certain order.

First, the HTTP request context must be allocated: OSSL_HTTP_REQ_CTX_new().

Then, the HTTP request must be prepared with request data:

1.
Calling OSSL_HTTP_REQ_CTX_set_request_line().
2.
Adding extra header lines with OSSL_HTTP_REQ_CTX_add1_header(). This is optional and may be done multiple times with different names.
3.
Finalize the request using OSSL_HTTP_REQ_CTX_set1_req(). This may be omitted if the GET method is used and "keep-alive" is not requested.

When the request context is fully prepared, the HTTP exchange may be performed with OSSL_HTTP_REQ_CTX_nbio() or OSSL_HTTP_REQ_CTX_exchange().

NOTES

When built with tracing enabled, OSSL_HTTP_REQ_CTX_nbio() and all functions using it, such as OSSL_HTTP_REQ_CTX_exchange() and OSSL_HTTP_transfer(3), may be traced using OSSL_TRACE_CATEGORY_HTTP. See also OSSL_trace_enabled(3) and openssl-env(7).

RETURN VALUES

OSSL_HTTP_REQ_CTX_new() returns a pointer to a OSSL_HTTP_REQ_CTX, or NULL on error.

OSSL_HTTP_REQ_CTX_free(), OSSL_HTTP_REQ_CTX_set_max_response_length(), and OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines() do not return values.

OSSL_HTTP_REQ_CTX_set_request_line(), OSSL_HTTP_REQ_CTX_add1_header(), OSSL_HTTP_REQ_CTX_set1_req(), and OSSL_HTTP_REQ_CTX_set_expected() return 1 for success and 0 for failure.

OSSL_HTTP_REQ_CTX_nbio() and OSSL_HTTP_REQ_CTX_nbio_d2i() return 1 for success, 0 on error or redirection, -1 if retry is needed.

OSSL_HTTP_REQ_CTX_exchange() and OSSL_HTTP_REQ_CTX_get0_mem_bio() return a pointer to a BIO on success as described above or NULL on failure. The returned BIO must not be freed by the caller.

OSSL_HTTP_REQ_CTX_get_resp_len() returns the size of the response contents or 0 if not available or an error occurred.

OSSL_HTTP_is_alive() returns 1 if its argument is non-NULL and the client requested a persistent connection and the server did not disagree on keeping the connection open, else 0.
