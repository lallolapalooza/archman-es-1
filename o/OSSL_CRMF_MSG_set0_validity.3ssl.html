OSSL_CRMF_MSG_set0_validity(3ssl)

Paquete: openssl

Licencias: Apache-2.0

OSSL_CRMF_MSG_SET0_VALIDITY(3ssl) OpenSSL OSSL_CRMF_MSG_SET0_VALIDITY(3ssl)

NOMBRE

OSSL_CRMF_MSG_set0_validity, OSSL_CRMF_MSG_set_certReqId, OSSL_CRMF_CERTTEMPLATE_fill, OSSL_CRMF_MSG_set0_extensions, OSSL_CRMF_MSG_push0_extension, OSSL_CRMF_MSG_create_popo, OSSL_CRMF_MSGS_verify_popo - funciones para poblar y verificar estructuras CRMF CertReqMsg

SINOPSIS

#include <openssl/crmf.h>
int OSSL_CRMF_MSG_set0_validity(OSSL_CRMF_MSG *crm,
                                ASN1_TIME *notBefore, ASN1_TIME *notAfter);
int OSSL_CRMF_MSG_set_certReqId(OSSL_CRMF_MSG *crm, int rid);
int OSSL_CRMF_CERTTEMPLATE_fill(OSSL_CRMF_CERTTEMPLATE *tmpl,
                                EVP_PKEY *pubkey,
                                const X509_NAME *subject,
                                const X509_NAME *issuer,
                                const ASN1_INTEGER *serial);
int OSSL_CRMF_MSG_set0_extensions(OSSL_CRMF_MSG *crm, X509_EXTENSIONS *exts);
int OSSL_CRMF_MSG_push0_extension(OSSL_CRMF_MSG *crm, X509_EXTENSION *ext);
int OSSL_CRMF_MSG_create_popo(int meth, OSSL_CRMF_MSG *crm,
                              EVP_PKEY *pkey, const EVP_MD *digest,
                              OSSL_LIB_CTX *libctx, const char *propq);
int OSSL_CRMF_MSGS_verify_popo(const OSSL_CRMF_MSGS *reqs,
                               int rid, int acceptRAVerified,
                               OSSL_LIB_CTX *libctx, const char *propq);

DESCRIPCIÓN

OSSL_CRMF_MSG_set0_validity() establece los campos notBefore y notAfter como restricciones de validez en el certTemplate de crm. Cualquiera de los parámetros notBefore y notAfter puede ser NULL, lo que significa que no hay restricción para el campo respectivo. En caso de éxito, la propiedad de notBefore y notAfter se transfiere a crm.

OSSL_CRMF_MSG_set_certReqId() establece rid como el certReqId de crm.

OSSL_CRMF_CERTTEMPLATE_fill() establece aquellos campos del certTemplate tmpl para los que se proporcionan valores no NULL: pubkey, subject, issuer y/o serial. Las extensiones X.509 pueden establecerse usando OSSL_CRMF_MSG_set0_extensions(). En caso de éxito, el contador de referencias de pubkey (si se proporciona) se incrementa, mientras que las estructuras subject, issuer y serial (si se proporcionan) se copian.

OSSL_CRMF_MSG_set0_extensions() establece exts como las extensiones en el certTemplate de crm. Libera cualquier extensión preexistente y consume exts.

OSSL_CRMF_MSG_push0_extension() agrega la extensión X509 ext a las extensiones en el certTemplate de crm. Consume ext.

OSSL_CRMF_MSG_create_popo() crea y establece la Prueba de Posesión (POPO) de acuerdo con el método meth en crm. El contexto de la biblioteca libctx y la cadena de consulta de propiedad propq, pueden ser NULL para seleccionar los valores predeterminados. En caso de que el método sea OSSL_CRMF_POPO_SIGNATURE, el POPO se calcula usando la clave privada pkey y el método digest digest, donde el argumento digest se ignora si pkey es de un tipo (como Ed25519 y Ed448) que está implícitamente asociado con un algoritmo digest.

meth puede ser uno de los siguientes:

  • OSSL_CRMF_POPO_NONE - RFC 4211, sección 4, campo POP omitido. CA/RA utiliza un método fuera de banda para verificar el POP. Tenga en cuenta que los servidores pueden fallar en este caso, resultando por ejemplo en el código de error HTTP 500 (Error interno).
  • OSSL_CRMF_POPO_RAVERIFIED - RFC 4211, sección 4, indicación explícita de que el RA ya ha verificado el POP.
  • OSSL_CRMF_POPO_SIGNATURE - RFC 4211, sección 4.1, solo se soporta el caso 3 hasta ahora.
  • OSSL_CRMF_POPO_KEYENC - RFC 4211, sección 4.2, solo se soporta el método indirecto (subsequentMessage/enccert), el intercambio de desafío-respuesta (challengeResp) aún no se soporta.
  • OSSL_CRMF_POPO_KEYAGREE - RFC 4211, sección 4.3, aún no se soporta.

OSSL_CRMF_MSGS_verify_popo verifica la Prueba de Posesión de la solicitud con el rid dado en la lista de reqs. Acepta opcionalmente RAVerified. Puede utilizar el contexto de la biblioteca libctx y la cadena de consulta de propiedad propq.

VALORES DE RETORNO

Todas las funciones devuelven 1 en caso de éxito, 0 en caso de error.

VER TAMBIÉN

RFC 4211

HISTORIA
