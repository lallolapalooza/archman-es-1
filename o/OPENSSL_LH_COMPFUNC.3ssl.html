El siguiente macro está obsoleto:

DEFINE_LHASH_OF(TYPE);

DESCRIPCIÓN

Esta librería implementa tablas hash dinámicas tipadas. Las entradas de la tabla hash pueden ser estructuras arbitrarias. Usualmente consisten en campos de clave y valor. En la descripción aquí, TYPE se usa como marcador de posición para cualquiera de los tipos de datos de OpenSSL, como SSL_SESSION.

Para definir una nueva tabla hash dinámica tipada, usa DEFINE_LHASH_OF_EX(). Anteriormente se usaba DEFINE_LHASH_OF() para este propósito, pero ahora está obsoleto. El macro DEFINE_LHASH_OF_EX() proporciona toda la funcionalidad de DEFINE_LHASH_OF() excepto por ciertas funciones de estadísticas obsoletas (ver OPENSSL_LH_stats(3)).

lh_TYPE_new() crea una nueva estructura LHASH_OF(TYPE) para almacenar entradas de datos arbitrarias, y especifica las funciones de callback 'hash' y 'compare' que se usarán en la organización de las entradas de la tabla. La función de callback hash toma un puntero a una entrada de tabla como su argumento y devuelve un valor hash de unsigned long para su campo de clave. El valor hash normalmente se trunca a una potencia de 2, así que asegúrate de que tu función hash devuelva bits de orden bajo bien mezclados. La función de callback compare toma dos argumentos (punteros a dos entradas de tabla hash) y devuelve 0 si sus claves son iguales, de lo contrario devuelve un valor distinto de cero.

Si tu tabla hash contendrá elementos de algún tipo particular y las funciones de callback hash y compare calculan el hash/comparan estos tipos, entonces los macros IMPLEMENT_LHASH_HASH_FN y IMPLEMENT_LHASH_COMP_FN se pueden usar para crear envoltorios de funciones con los prototipos requeridos por lh_TYPE_new() como se muestra en este ejemplo:

/*
 * Implementa las funciones hash y compare; "stuff" puede ser cualquier palabra.
 */
static unsigned long stuff_hash(const TYPE *a)
{
    ...
}
static int stuff_cmp(const TYPE *a, const TYPE *b)
{
    ...
}
/*
 * Implementa las funciones envoltorio.
 */
static IMPLEMENT_LHASH_HASH_FN(stuff, TYPE)
static IMPLEMENT_LHASH_COMP_FN(stuff, TYPE)

Si el tipo se va a usar en varios lugares, los siguientes macros se pueden usar en un archivo de cabecera común para declarar los envoltorios de funciones:

DECLARE_LHASH_HASH_FN(stuff, TYPE)
DECLARE_LHASH_COMP_FN(stuff, TYPE)

Luego, una tabla hash de objetos TYPE se puede crear usando esto:

LHASH_OF(TYPE) *htable;
htable = B<lh_I<TYPE>_new>(LHASH_HASH_FN(stuff), LHASH_COMP_FN(stuff));

lh_TYPE_free() libera la estructura LHASH_OF(TYPE) table. Las entradas de tabla hash asignadas no se liberarán; considera usar lh_TYPE_doall() para desasignar cualquier entrada restante en la tabla hash (ver abajo). Si el argumento es NULL, no se hace nada.

lh_TYPE_flush() vacía la estructura LHASH_OF(TYPE) table. Se pueden agregar nuevas entradas a la tabla vaciada. Las entradas de tabla hash asignadas no se liberarán; considera usar lh_TYPE_doall() para desasignar cualquier entrada restante en la tabla hash (ver abajo).

lh_TYPE_insert() inserta la estructura apuntada por data en table. Si ya existe una entrada con la misma clave, el valor antiguo se reemplaza. Ten en cuenta que lh_TYPE_insert() almacena punteros, los datos no se copian.

lh_TYPE_delete() elimina una entrada de table.

lh_TYPE_retrieve() busca una entrada en table. Normalmente, data es una estructura con los campos de clave establecidos; la función devolverá un puntero a una estructura completamente poblada.

lh_TYPE_doall() llamará, por cada entrada en la tabla hash, a func con el elemento de datos como su parámetro. Por ejemplo:

/* Limpia los recursos pertenecientes a 'a' (esto se implementa en otro lugar) */
void TYPE_cleanup_doall(TYPE *a);
/* Implementa un envoltorio compatible con el prototipo para "TYPE_cleanup" */
IMPLEMENT_LHASH_DOALL_FN(TYPE_cleanup, TYPE)
/* Llama a "TYPE_cleanup" contra todos los elementos en una tabla hash. */
lh_TYPE_doall(hashtable, LHASH_DOALL_FN(TYPE_cleanup));
/* Luego, la tabla hash en sí puede ser desasignada */
lh_TYPE_free(hashtable);

lh_TYPE_doall_arg() es lo mismo que lh_TYPE_doall() excepto que func será llamada con arg como segundo argumento y func debería ser de tipo LHASH_DOALL_ARG_FN(TYPE) (un prototipo de callback que recibe tanto la entrada de la tabla como un argumento adicional). Al igual que con lh_doall(), puedes elegir declarar tu callback con un prototipo que coincida con los tipos con los que estás trabajando y usar los macros declare/implement para crear envoltorios compatibles que conviertan variables antes de llamar a tus callbacks específicos del tipo. Un ejemplo de esto se demuestra aquí (imprimiendo todas las entradas de la tabla hash a un BIO que es proporcionado por el llamador):

/* Imprime el elemento 'a' a 'output_bio' (esto se implementa en otro lugar) */
void TYPE_print_doall_arg(const TYPE *a, BIO *output_bio);
/* Implementa un envoltorio compatible con el prototipo para "TYPE_print" */
static IMPLEMENT_LHASH_DOALL_ARG_FN(TYPE, const TYPE, BIO)
/* Imprime toda la tabla hash a un BIO particular */
lh_TYPE_doall_arg(hashtable, LHASH_DOALL_ARG_FN(TYPE_print), BIO,
                  logging_bio);

Ten en cuenta que por defecto **no** es seguro usar lh_TYPE_delete() dentro de un callback pasado a lh_TYPE_doall() o lh_TYPE_doall_arg(). La razón es que eliminar un elemento de la tabla hash puede resultar en que la tabla hash se contraiga a un tamaño más pequeño y se vuelva a calcular el hash. lh_

NOMBRE

OPENSSL_LH_doall, OPENSSL_LH_doall_arg, lh_TYPE_doall, lh_TYPE_doall_arg - recorrido de todos los elementos de una tabla hash.

SINOPSIS

#include <openssl/lhash.h>

void lh_TYPE_doall(LHASH_OF(TYPE) *lh,
                   void (*func)(TYPE *, char));
void lh_TYPE_doall_arg(LHASH_OF(TYPE) *lh,
                       void (*func)(TYPE *, char), void *arg);
void OPENSSL_LH_doall(LHASH *lh, void (*func)(void *, void *));
void OPENSSL_LH_doall_arg(LHASH *lh, void (*func)(void *, void *),
                          void *arg);

DESCRIPCIÓN

Estas funciones recorren todos los elementos de la tabla hash especificada por lh y llaman a la función de retorno de llamada func para cada elemento. Los elementos se pasan a func como punteros. Cuando se usan las versiones específicas de tipo, los elementos se pasan como punteros a TYPE. Cuando se usan las versiones genéricas OPENSSL_LH_*, los elementos se pasan como punteros a void.

La función lh_TYPE_doall_arg() y OPENSSL_LH_doall_arg() también pasan un argumento adicional arg a la función de retorno de llamada func.

lh_TYPE_doall() y lh_TYPE_doall_arg() no son seguras y exhibirán comportamiento indefinido bajo estas condiciones, ya que estas funciones asumen que el tamaño de la tabla hash y los punteros de los cubos no cambian durante la llamada.

Si se desea utilizar lh_TYPE_doall() o lh_TYPE_doall_arg() con lh_TYPE_delete(), es esencial que llame a lh_TYPE_set_down_load() con un argumento down_load de 0 primero. Esto deshabilita la contracción de la tabla hash y garantiza que será seguro eliminar elementos de una tabla hash durante una llamada a lh_TYPE_doall() o lh_TYPE_doall_arg().

Nunca es seguro llamar a lh_TYPE_insert() durante una llamada a lh_TYPE_doall() o lh_TYPE_doall_arg().

lh_TYPE_error() se puede usar para determinar si ocurrió un error en la última operación.

lh_TYPE_num_items() devuelve el número de elementos en la tabla hash.

lh_TYPE_get_down_load() y lh_TYPE_set_down_load() obtienen y establecen el factor utilizado para determinar cuándo se contrae la tabla hash. El factor es el factor de carga en o por debajo del cual ocurrirá la contracción de la tabla hash, multiplicado por LH_LOAD_MULT, donde el factor de carga es el número de elementos dividido por el número de nodos. Establecer este valor a 0 deshabilita la contracción de la tabla hash.

OPENSSL_LH_new() es lo mismo que lh_TYPE_new(), excepto que no es específico de tipo. Por lo tanto, en lugar de devolver un valor LHASH_OF(TYPE), devuelve un void *. De la misma manera, las funciones OPENSSL_LH_free(), OPENSSL_LH_flush(), OPENSSL_LH_insert(), OPENSSL_LH_delete(), OPENSSL_LH_retrieve(), OPENSSL_LH_doall(), OPENSSL_LH_doall_arg(), OPENSSL_LH_num_items(), OPENSSL_LH_get_down_load(), OPENSSL_LH_set_down_load() y OPENSSL_LH_error() son equivalentes a las funciones lh_TYPE de nombre similar, excepto que devuelven o usan un void * donde la función equivalente lh_TYPE devuelve o usa un TYPE * o LHASH_OF(TYPE) *. Las funciones lh_TYPE se implementan como envolturas verificadas por tipo alrededor de las funciones OPENSSL_LH. La mayoría de las aplicaciones no deben llamar a las funciones OPENSSL_LH directamente.

OPENSSL_LH_set_thunks() y OPENSSL_LH_doall_arg_thunk(), aunque públicas por necesidad, son en realidad funciones internas y no deben usarse.

VALORES DE RETORNO

lh_TYPE_new() y OPENSSL_LH_new() devuelven NULL en caso de error, de lo contrario, un puntero a la nueva estructura LHASH.

Cuando se reemplaza una entrada de tabla hash, lh_TYPE_insert() o OPENSSL_LH_insert() devuelven el valor que se está reemplazando. Se devuelve NULL en operación normal y en caso de error.

lh_TYPE_delete() y OPENSSL_LH_delete() devuelven la entrada que se está eliminando. Se devuelve NULL si no existe tal valor en la tabla hash.

lh_TYPE_retrieve() y OPENSSL_LH_retrieve() devuelven la entrada de la tabla hash si se ha encontrado, de lo contrario NULL.

lh_TYPE_error() y OPENSSL_LH_error() devuelven 1 si ocurrió un error en la última operación, 0 en caso contrario. Solo tiene sentido después de operaciones que no sean de recuperación.

lh_TYPE_free(), OPENSSL_LH_free(), lh_TYPE_flush(), OPENSSL_LH_flush(), lh_TYPE_doall() OPENSSL_LH_doall(), lh_TYPE_doall_arg() y OPENSSL_LH_doall_arg() no devuelven valores.

NOTA

El código LHASH no es seguro para hilos. Todas las operaciones de actualización, así como las llamadas a lh_TYPE_error() o OPENSSL_LH_error() deben realizarse bajo un bloqueo de escritura. Todas las operaciones de recuperación deben realizarse bajo un bloqueo de lectura, _a menos_ que se deseen estadísticas de uso precisas. En ese caso, se debe usar un bloqueo de escritura también para las operaciones de recuperación. Para la salida de las estadísticas de uso, utilizando las funciones de OPENSSL_LH_stats(3), basta con un bloqueo de lectura.

El código LHASH considera las entradas de la tabla como datos constantes. Como tal, internamente representa los elementos insertados con lh_insert() con un tipo de puntero "const void *". Es por esto que las funciones de retorno de llamada, como las utilizadas por lh_doall() y lh_doall_arg(), declaran sus prototipos con "const", incluso para los parámetros que devuelven los punteros de datos de los elementos de la tabla; para mantener la coherencia, los datos proporcionados por el usuario son "const" en todo momento en lo que respecta al código LHASH. Sin embargo, dado que los llamadores proporcionan estos punteros, pueden optar por tratar todos esos parámetros como constantes.

Como ejemplo, una tabla hash puede ser mantenida por código que, por razones de encapsulación, solo tiene acceso "const" a los datos que se indexan en la tabla hash (es decir, se devuelve como "const" desde otras partes de su código); en este caso, los prototipos LHASH son apropiados tal como están. Por el contrario, si el llamador es responsable del ciclo de vida de los datos en cuestión, entonces pueden desear realizar modificaciones en los elementos de la tabla que se devuelven en las funciones de retorno de llamada lh_doall() o lh_doall_arg() (ver el ejemplo de "TYPE_cleanup" anterior). Si es así, el llamador puede eliminar la calificación "const" (si proporcionan las funciones de retorno de llamada brutas ellos mismos) o usar las macros para declarar/implementar las funciones envolventes sin tipos "const".

Los llamadores que solo tienen acceso "const" a los datos que indexan en una tabla, pero declaran funciones de retorno de llamada sin tipos constantes (o eliminan la calificación "const" ellos mismos), están creando sus propios riesgos/errores sin ser alentados a hacerlo por la API. En una nota relacionada, aquellos que auditan código deben prestar especial atención a cualquier instancia de las macros DECLARE/IMPLEMENT_LHASH_DOALL_[ARG_]_FN que proporcionen tipos sin ningún calificador "const".

ERRORES

lh_TYPE_insert() y OPENSSL_LH_insert() devuelven NULL tanto para el éxito como para el error.

VER TAMBIÉN

HISTORIA

En OpenSSL 1.0.0, la interfaz lhash fue renovada para una mejor verificación de tipos.

En OpenSSL 3.1, se introdujo DEFINE_LHASH_OF_EX() y se _obsoleto_ DEFINE_LHASH_OF().

OPENSSL_LH_doall_arg_thunk(), OPENSSL_LH_set_thunks() se agregaron en OpenSSL 3.3.
