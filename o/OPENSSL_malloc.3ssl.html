DESCRIPCIÓN

La asignación de memoria de OpenSSL se maneja mediante la API OPENSSL_xxx. Estas son generalmente macros que añaden los parámetros estándar de C __FILE__ y __LINE__ y llaman a una API de nivel inferior CRYPTO_xxx. Algunas funciones no añaden esos parámetros, pero existen por coherencia.

OPENSSL_malloc_init() no hace nada y no necesita ser llamada. Se incluye por compatibilidad con versiones anteriores de OpenSSL.

OPENSSL_malloc(), OPENSSL_realloc() y OPENSSL_free() son como las funciones C malloc(), realloc() y free(). OPENSSL_zalloc() llama a memset() para poner a cero la memoria antes de devolverla.

OPENSSL_aligned_alloc() funciona igual que OPENSSL_malloc(), pero permite al llamador especificar un valor de alineación, para instancias en las que la alineación predeterminada de malloc es insuficiente para las necesidades del llamador. Nota, el valor de alineación debe ser una potencia de 2, y el tamaño especificado debe ser un múltiplo de la alineación. NOTAS:

  • La llamada a OPENSSL_aligned_alloc() acepta un tercer argumento, freeptr, que debe apuntar a un puntero void. En algunas plataformas, no hay ninguna llamada a biblioteca disponible para obtener asignaciones de memoria con una alineación mayor que la que proporciona malloc. En este caso, OPENSSL_aligned_alloc() implementa su propia rutina de alineación, asignando memoria adicional y desplazando el puntero devuelto para que esté en el límite de alineación solicitado. Para liberar de forma segura las asignaciones realizadas por este método, el llamador debe devolver el valor en la variable freeptr, en lugar del puntero devuelto.
  • La llamada a OPENSSL_aligned_alloc() puede fallar por razones distintas al agotamiento de memoria, dependiendo de la implementación subyacente y, sobre todo, de la configuración de compilación de la biblioteca OpenSSL: por ejemplo, siempre devuelve "NULL" sin establecer ningún error si OpenSSL se compila con la macro "OPENSSL_SMALL_FOOTPRINT" definida. En consecuencia, el llamador puede necesitar recurrir a una asignación de memoria no alineada (y codificar la rutina de alineación si la alineación es un requisito).

OPENSSL_clear_realloc() y OPENSSL_clear_free() deben usarse cuando el búfer en addr contiene información sensible. El búfer antiguo se rellena con ceros llamando a OPENSSL_cleanse() antes de llamar finalmente a OPENSSL_free(). Si el argumento a OPENSSL_free() es NULL, no se hace nada.

OPENSSL_malloc_array(), OPENSSL_calloc(), OPENSSL_aligned_alloc_array(), OPENSSL_realloc_array() y OPENSSL_clear_realloc_array() son variantes de OPENSSL_malloc(), OPENSSL_zalloc(), OPENSSL_aligned_alloc(), OPENSSL_realloc() y OPENSSL_clear_realloc(), respectivamente, que aceptan un parámetro adicional, size, que permite operaciones de asignación de memoria para un array de num miembros de size bytes cada uno; estas funciones devuelven un error si la multiplicación de num y size provoca un desbordamiento de enteros, evitando así asignaciones de tamaño incorrecto.

OPENSSL_cleanse() rellena ptr de tamaño len con una cadena de ceros. Use OPENSSL_cleanse() con cuidado si la memoria es un mapeo de un archivo. Si el controlador de almacenamiento utiliza compresión de escritura, es posible que los bytes finales sensibles sobrevivan a la puesta a cero porque el bloque de ceros se comprimirá. Si el controlador de almacenamiento utiliza nivelación de desgaste, los datos sensibles antiguos no se sobrescribirán; en su lugar, se escribirá un bloque de ceros en una nueva ubicación física.

OPENSSL_strdup(), OPENSSL_strndup() y OPENSSL_memdup() son como las funciones C equivalentes, excepto que la memoria se asigna llamando a OPENSSL_malloc() y debe liberarse llamando a OPENSSL_free().

SINOPSIS

OPENSSL_malloc(), OPENSSL_free(), OPENSSL_clear_free() CRYPTO_free(), CRYPTO_clear_free() CRYPTO_get_mem_functions() no devuelven valor.

OPENSSL_malloc(), OPENSSL_aligned_alloc(), OPENSSL_zalloc(), OPENSSL_realloc(), OPENSSL_malloc_array(), OPENSSL_aligned_alloc_array(), OPENSSL_calloc(), OPENSSL_realloc_array(), OPENSSL_clear_realloc(), OPENSSL_clear_realloc_array(), CRYPTO_malloc(), CRYPTO_zalloc(), CRYPTO_realloc(), CRYPTO_malloc_array(), CRYPTO_calloc(), CRYPTO_realloc_array(), CRYPTO_clear_realloc(), CRYPTO_clear_realloc_array(), OPENSSL_strdup() y OPENSSL_strndup() devuelven un puntero a la memoria asignada o NULL en caso de error.

OPENSSL_aligned_alloc() y OPENSSL_aligned_alloc_array() establecen freeptr a NULL en caso de error.

CRYPTO_set_mem_functions() devuelve 1 en caso de éxito o 0 en caso de fallo (casi siempre porque las asignaciones ya han ocurrido).

CRYPTO_mem_leaks(), CRYPTO_mem_leaks_fp(), CRYPTO_mem_leaks_cb(), CRYPTO_set_mem_debug() y CRYPTO_mem_ctrl() están obsoletos y son funciones nulas que siempre devuelven -1. OPENSSL_mem_debug_push(), OPENSSL_mem_debug_pop(), CRYPTO_mem_debug_push() y CRYPTO_mem_debug_pop() están obsoletos y son funciones nulas que siempre devuelven 0.

OPENSSL_strtoul() devuelve 1 en caso de éxito y 0 en caso de que haya ocurrido un error. Específicamente, se devuelve 0 en los siguientes eventos:

  • Si la llamada subyacente a strtol devolvió un valor errno distinto de cero
  • Si la traducción no consumió toda la cadena de entrada y el valor endptr pasado fue NULL
  • Si no se consumieron caracteres en la traducción

Tenga en cuenta que una condición de éxito no implica que se haya realizado la traducción esperada. Por ejemplo, llamar a

OPENSSL_strtoul("0x12345", &endptr, 10, &num);

resultará en una traducción exitosa con num teniendo el valor 0 y endptr = 'x'. Asegúrese de validar cuántos datos se consumieron al llamar a esta función.
