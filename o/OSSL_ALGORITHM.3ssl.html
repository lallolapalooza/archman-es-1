OSSL_ALGORITHM(3ssl)

Paquete: openssl

Licencias: Apache-2.0

OSSL_ALGORITHM(3ssl) OpenSSL OSSL_ALGORITHM(3ssl)

NOMBRE

OSSL_ALGORITHM - Tipo central de OpenSSL para definir un algoritmo recuperable

SINOPSIS

#include <openssl/core.h>
typedef struct ossl_algorithm_st OSSL_ALGORITHM;
struct ossl_algorithm_st {
    const char *algorithm_names;     /* clave */
    const char *property_definition; /* clave */
    const OSSL_DISPATCH *implementation;
    const char *algorithm_description;
};

DESCRIPCIÓN

El tipo OSSL_ALGORITHM es una estructura pública que describe un algoritmo proporcionado por un proveedor(7). Los arrays de este tipo son devueltos por los proveedores a petición de las bibliotecas OpenSSL para describir qué algoritmos proporcionan implementaciones y con qué propiedades.

Los arrays de este tipo deben terminar con una tupla donde algorithm_names sea NULL.

Este tipo de array normalmente es devuelto por la función de consulta de operaciones del proveedor, descrita además en "Funciones del Proveedor" en provider-base(7).

Campos OSSL_ALGORITHM

algorithm_names
Esta cadena es un conjunto de nombres/identidades separados por dos puntos, y es utilizada por la funcionalidad de recuperación adecuada (como EVP_CIPHER_fetch(3), EVP_MD_fetch(3), etc.) para encontrar el algoritmo deseado.

Múltiples nombres/identidades permiten que una implementación de algoritmo específica se recupere de múltiples maneras. Por ejemplo, el algoritmo RSA tiene las siguientes identidades conocidas:

  • "RSA"
  • "rsaEncryption"

    Este es el nombre del OBJECT IDENTIFIER (OID) del algoritmo, tal como se da en el módulo ASN.1 de las RFC de PKCS#1 https://www.rfc-editor.org/rfc/rfc8017#appendix-C

  • 1.2.840.113549.1.1.1

    Este es el propio OID para "rsaEncryption", en forma de texto decimal canónico.

La cadena resultante de algorithm_names se vería así:

"RSA:rsaEncryption:1.2.840.113549.1.1.1"

Las bibliotecas OpenSSL usan el primero de los nombres de algoritmo como el nombre principal o canónico, en base a cada implementación de algoritmo.

Ver las notas "Sobre el tema de los nombres de algoritmos" a continuación para una discusión más profunda sobre algorithm_names y cómo puede interactuar con aplicaciones y bibliotecas, incluidas las de OpenSSL.

property_definition
Esta cadena define un conjunto de propiedades asociadas con una implementación de algoritmo particular, y es utilizada por la funcionalidad de recuperación adecuada (como EVP_CIPHER_fetch(3), EVP_MD_fetch(3), etc.) para una búsqueda más detallada de una implementación de algoritmo, lo cual es útil en caso de que haya múltiples implementaciones del mismo algoritmo disponibles.

Ver property(7) para una descripción adicional del contenido de esta cadena.

implementation
Puntero a un array de OSSL_DISPATCH(3), que contiene punteros a las funciones de una implementación de algoritmo particular.
algorithm_description
Una cadena con una breve descripción legible del algoritmo.

NOTAS

Sobre el tema de los nombres de algoritmos

Los proveedores pueden necesitar registrar OIDs ASN.1 para algoritmos utilizando OBJ_create(3) (a través de la llamada ascendente core_obj_create descrita en provider-base(7), porque alguna aplicación o biblioteca -- posiblemente aún las bibliotecas OpenSSL -- usa NIDs para buscar algoritmos.

En ese escenario, debe asegurarse de que los algorithm_names correspondientes de OSSL_ALGORITHM incluyan tanto el nombre corto como el largo.

La mayoría de las veces, registrar OIDs ASN.1 de esta manera no debería ser necesario, y se anima a las aplicaciones y bibliotecas a usar OBJ_obj2txt(3) para obtener una representación textual del OID, que puede ser un nombre largo o corto para OIDs registrados, o el propio OID en forma de texto decimal canónico si no lo es (o si se llama a OBJ_obj2txt(3) con no_name = 1).

Se recomienda asegurarse de que los algorithm_names correspondientes de OSSL_ALGORITHM incluyan los nombres conocidos, así como el propio OID en forma de texto decimal canónico. Eso debería cubrir todos los escenarios.
