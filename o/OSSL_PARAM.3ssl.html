Paquete: openssl

OSSL_PARAM(3ssl) OpenSSL OSSL_PARAM(3ssl)

NOMBRE

OSSL_PARAM - una estructura para pasar o solicitar parámetros de objeto

SINOPSIS

#include <openssl/core.h>
typedef struct ossl_param_st OSSL_PARAM;
struct ossl_param_st {
    const char *key;             /* el nombre del parámetro */
    unsigned int data_type;      /* declara qué tipo de contenido hay en data */
    void *data;                  /* valor que se pasa o se recibe */
    size_t data_size;            /* tamaño de los datos */
    size_t return_size;          /* tamaño devuelto */
};

DESCRIPCIÓN

OSSL_PARAM es un tipo que permite pasar datos arbitrarios para algún objeto entre dos partes que tienen poco o ningún conocimiento compartido sobre sus respectivas estructuras internas para ese objeto.

Un ejemplo de uso típico podría ser una aplicación que quiere establecer algunos parámetros para un objeto, o quiere averiguar algunos parámetros de un objeto.

Se pueden utilizar arrays de este tipo para los siguientes propósitos:

  • Establecer parámetros para algún objeto

    El llamador configura el array OSSL_PARAM y llama a alguna función (el establecedor) que tiene conocimiento íntimo sobre el objeto y puede tomar los datos del array OSSL_PARAM y asignarlos de una forma adecuada para la estructura interna del objeto.

  • Solicitar parámetros de algún objeto

    El llamador (el solicitante) configura el array OSSL_PARAM y llama a alguna función (el respondedor) que tiene conocimiento íntimo sobre el objeto, la cual puede tomar los datos internos del objeto y copiarlos (posiblemente convertirlos) a la memoria preparada por el solicitante y apuntada con el data de OSSL_PARAM.

  • Solicitar descriptores de parámetros

    El llamador obtiene un array de OSSL_PARAM constantes, que describen los parámetros disponibles y algunas de sus propiedades; nombre, tipo de datos y tamaño esperado de los datos. Para una descripción detallada de cada campo para este uso, ver las descripciones de los campos a continuación.

    El llamador puede entonces usar la información de este array descriptor para construir su propio array OSSL_PARAM para pasarlo a un establecedor o respondedor.

Normalmente, el orden de un array de OSSL_PARAM no es relevante. Sin embargo, si el respondedor puede manejar múltiples elementos con la misma clave, esos elementos deben manejarse en el orden en que están.

Un array de OSSL_PARAM debe tener un elemento terminador, donde key es NULL. La plantilla terminadora completa usual es:

{ NULL, 0, NULL, 0, 0 }

Esto también se puede especificar usando OSSL_PARAM_END(3).

Soporte funcional

Libcrypto ofrece un conjunto limitado de funciones de ayuda para manejar elementos y arrays de OSSL_PARAM, por favor ver OSSL_PARAM_get_int(3). Los desarrolladores son libres de extenderlos o reemplazarlos como consideren oportuno.

Campos de OSSL_PARAM

key
La identidad del parámetro en forma de cadena.

En un array de OSSL_PARAM, un elemento con este campo establecido a NULL se considera un elemento terminador.

data_type
El data_type es un valor que describe el tipo y la organización de los datos. Ver "Tipos soportados" a continuación para una descripción de los tipos.
data
data_size
data es un puntero a la memoria donde los datos del parámetro están (al establecer parámetros) o deben estar (al solicitar parámetros) almacenados, y data_size es su tamaño en bytes. La organización de los datos depende del tipo de parámetro y la bandera.

El data_size necesita atención especial con el tipo de parámetro OSSL_PARAM_UTF8_STRING en relación con las cadenas C. Al establecer parámetros, el tamaño debe establecerse a la longitud de la cadena, sin contar el byte NUL terminador. Al solicitar parámetros, el tamaño debe establecerse al tamaño del buffer a poblar, el cual debe permitir suficiente espacio para un byte NUL terminador.

Cuando se solicitan parámetros, es aceptable que data sea NULL. Esto puede ser utilizado por el solicitante para averiguar dinámicamente exactamente cuánto espacio de buffer se necesita para almacenar los datos del parámetro. En este caso, se ignora data_size.

Cuando se utiliza OSSL_PARAM como descriptor de parámetro, se debe ignorar data. Si data_size es cero, significa que se acepta un tamaño de datos arbitrario, de lo contrario especifica el tamaño máximo permitido.

return_size
Cuando un array de OSSL_PARAM se utiliza para solicitar datos, el respondedor debe establecer este campo para indicar el tamaño de los datos del parámetro, incluyendo el relleno si fuera el caso. En caso de que data_size sea un tamaño inadecuado para los datos, el respondedor debe aún así establecer este campo para indicar el tamaño mínimo de datos requerido. (más notas sobre esto en "NOTAS" a continuación).

Cuando se utiliza OSSL_PARAM como descriptor de parámetro, se debe ignorar return_size.

NOTA:

Los nombres de clave y los tipos asociados son definidos por la entidad que ofrece estos parámetros, es decir, los nombres de los parámetros proporcionados por las bibliotecas OpenSSL son definidos por las bibliotecas, y los nombres de los parámetros proporcionados por los proveedores son definidos por esos proveedores, excepto por la forma puntero de las cadenas (ver descripciones de tipos de datos a continuación). Las entidades que desean establecer o solicitar parámetros necesitan saber cuáles son esas claves y de qué tipo, cualquier funcionalidad entre esas dos entidades debe permanecer ajena y simplemente pasar el array OSSL_PARAM.

Tipos soportados

El campo data_type puede ser uno de los siguientes tipos:

OSSL_PARAM_INTEGER
OSSL_PARAM_UNSIGNED_INTEGER
Los datos del parámetro son un entero (con signo o sin signo) de longitud arbitraria, organizado en forma nativa, es decir, byte más significativo primero en sistemas Big-Endian, y byte menos significativo primero en sistemas Little-Endian.
OSSL_PARAM_REAL
Los datos del parámetro son un valor de punto flotante en forma nativa.
OSSL_PARAM_UTF8_STRING
Los datos del parámetro son una cadena imprimible.
OSSL_PARAM_OCTET_STRING
Los datos del parámetro son una cadena de bytes arbitraria.
OSSL_PARAM_UTF8_PTR
Los datos del parámetro son un puntero a una cadena imprimible.

La diferencia entre este y OSSL_PARAM_UTF8_STRING es que data no apunta directamente a los datos, sino a un puntero que apunta a los datos.

Si hay alguna incertidumbre sobre cuál usar, OSSL_PARAM_UTF8_STRING es casi con seguridad la opción correcta.

Esto se utiliza para indicar que se están pasando datos constantes o se pasarán, y por lo tanto no es necesario copiar los datos que se pasan, solo el puntero a ellos.

data_size debe establecerse al tamaño de los datos, no al tamaño del puntero a los datos. Si se utiliza en una solicitud de parámetro, data_size no es relevante. Sin embargo, el respondedor establecerá return_size al tamaño de los datos.

Tenga en cuenta que el uso de este tipo es **frágil** y solo se puede utilizar de forma segura para datos que permanecen constantes y en una ubicación constante durante un tiempo suficiente (como la vida útil de la entidad que ofrece estos parámetros).

OSSL_PARAM_OCTET_PTR
Los datos del parámetro son un puntero a una cadena de bytes arbitraria.

L_PARAM_OCTET_STRING

es que data no se refiere directamente al dato, sino a un puntero que apunta al dato.

Si hay alguna incertidumbre sobre qué usar, OSSL_PARAM_OCTET_STRING es casi siempre la elección correcta.

Nota: El uso de este tipo es frágil y solo puede usarse de forma segura para datos que permanezcan constantes y en una ubicación constante durante un período suficiente (como la vida útil de la entidad que ofrece estos parámetros).

NOTAS

Cuando se establecen y se solicitan parámetros, las funciones llamadas deberán decidir qué es y qué no es un error. El comportamiento recomendado es:

  • Los claves que un setter o responder no reconoce deben simplemente ser ignorados. Esto en sí no es un error.
  • Si las claves que un setter reconoce forman un conjunto de datos consistente, esa llamada debería exitar.
  • Aparte de return_size, un responder nunca debe cambiar los campos de un OSSL_PARAM. Para devolver un valor, debe cambiar el contenido de la memoria que data apunta.
  • Si el tipo de dato asociado a una clave es incorrecto, la función llamada puede devolver un error.

    La función llamada puede también intentar convertir el dato a un formato adecuado (por ejemplo, es plausible pasar un número grande como un OSSL_PARAM_OCTET_STRING, así que aunque un clave esté definida como un OSSL_PARAM_UNSIGNED_INTEGER, se puede pasar el valor como un OSSL_PARAM_OCTET_STRING

  • Si el data de un OSSL_PARAM_OCTET_STRING o un OSSL_PARAM_UTF8_STRING es NULL, el responder debe establecer return_size a la longitud del elemento a devolver y devolver éxito. Luego el responder será llamado de nuevo con data apuntando a la ubicación para el valor a colocar.
  • Si un responder encuentra que algunas dimensiones de datos son demasiado pequeñas para el dato solicitado, debe establecer return_size para cada tal OSSL_PARAM a la longitud mínima requerida y eventualmente devolver un error.
  • Para los parámetros de tipo entero (OSSL_PARAM_UNSIGNED_INTEGER y OSSL_PARAM_INTEGER), un responder puede elegir devolver un error si data_size no es un tamaño adecuado ( incluso si data_size es mayor que el necesario). Si el responder encuentra el tamaño adecuado, debe llenar todos los data_size bytes y asegurarse de la correcta padding para el endianness nativo, y establecer return_size a la misma valor que data_size.

EJEMPLOS

Un par de ejemplos para mostrar cómo podrían configurarse los arrays de OSSL_PARAM.

Ejemplo 1

Este ejemplo es para establecer parámetros en algún objeto:

#include <openssl/core.h>
const char *foo = "some string";
size_t foo_l = strlen(foo);
const char bar[] = "some other string";
OSSL_PARAM set[] = {
    { "foo", OSSL_PARAM_UTF8_PTR, &foo, foo_l, 0 },
    { "bar", OSSL_PARAM_UTF8_STRING, (void *)&bar, sizeof(bar) - 1, 0 },
    { NULL, 0, NULL, 0, 0 }
};

Ejemplo 2

Este ejemplo es para solicitar parámetros en algún objeto:

const char *foo = NULL;
size_t foo_l;
char bar[1024];
size_t bar_l;
OSSL_PARAM request[] = {
    { "foo", OSSL_PARAM_UTF8_PTR, &foo, 0 /*irrelevant*/, 0 },
    { "bar", OSSL_PARAM_UTF8_STRING, &bar, sizeof(bar), 0 },
    { NULL, 0, NULL, 0, 0 }
};

Un responder que recibe este array (como params en este ejemplo) podría llenar los parámetros así:

/* OSSL_PARAM *params */
int i;
for (i = 0; params[i].key != NULL; i++) {
    if (strcmp(params[i].key, "foo") == 0) {
        *(char **)params[i].data = "foo value";
        params[i].return_size = 9; /* longitud de "foo value" */
    } else if (strcmp(params[i].key, "bar") == 0) {
        memcpy(params[i].data, "bar value", 10);
        params[i].return_size = 9; /* longitud de "bar value" */
    }
    /* Ignorar lo que no se conoce */
}
