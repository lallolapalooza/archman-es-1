NOMBRE

OPENSSL_ia32cap - el vector de capacidades del procesador x86[_64]

SINOPSIS

env OPENSSL_ia32cap=... <aplicación>

DESCRIPCIÓN

OpenSSL soporta una gama de extensiones y características de conjuntos de instrucciones x86[_64]. Estas extensiones se denotan por bits individuales o grupos de bits almacenados internamente como diez vectores de capacidades de 32 bits y, para simplificar, representados lógicamente a continuación como cinco vectores de 64 bits. Esta representación de vector lógico (LV) se utiliza para simplificar la definición de la variable de entorno OPENSSL_ia32cap.

Tras la inicialización del toolkit, los vectores de capacidades se rellenan mediante ejecuciones sucesivas de la instrucción CPUID, después de lo cual se aplican las modificaciones de bits de capacidad de la variable de entorno OPENSSL_ia32cap. Una vez completada la inicialización del toolkit, los vectores rellenados se utilizan para elegir entre diferentes rutas de código para proporcionar un rendimiento óptimo en una amplia gama de procesadores basados en x86[_64].

Se puede encontrar más información sobre CPUID en el Manual de Programación de Extensiones de Conjuntos de Instrucciones de la Arquitectura Intel(R) y en el Manual del Programador de la Arquitectura AMD64 (Volumen 3).

Bits de capacidad notables para LV0

Los siguientes son bits de capacidad notables del vector lógico 0 (LV0) resultantes de la siguiente ejecución de CPUID.(EAX=01H).EDX y CPUID.(EAX=01H).ECX:

bit #0+4 que indica la presencia del contador de marcas de tiempo (Time-Stamp Counter);
bit #0+19 que indica la disponibilidad de la instrucción CLFLUSH;
bit #0+20, reservado por Intel, se utiliza para elegir entre las rutas de código RC4;
bit #0+23 que indica soporte MMX;
bit #0+24, bit FXSR, que indica la disponibilidad de registros XMM;
bit #0+25 que indica soporte SSE;
bit #0+26 que indica soporte SSE2;
bit #0+28, Hyperthreading, que se utiliza para distinguir núcleos con caché compartida;
bit #0+30, reservado por Intel, indica específicamente CPUs Intel;
bit #0+33 que indica la disponibilidad de la instrucción PCLMULQDQ;
bit #0+41 que indica soporte SSSE3, Supplemental SSE3;
bit #0+43 que indica soporte AMD XOP (forzado a cero en CPUs no AMD);
bit #0+54 que indica la disponibilidad de la instrucción MOVBE;
bit #0+57, extensión del conjunto de instrucciones AES-NI;
bit #0+58, bit XSAVE, cuya ausencia en combinación con MOVBE se utiliza para identificar el núcleo Atom Silvermont;
bit #0+59, bit OSXSAVE, que indica la disponibilidad de registros YMM;
bit #0+60, extensión AVX;
bit #0+62 que indica la disponibilidad de la instrucción RDRAND;

bit #64+18 que indica la disponibilidad de la instrucción RDSEED;
bit #64+19 que indica la disponibilidad de las instrucciones ADCX y ADOX;
bit #64+21 que indica la disponibilidad de la extensión AVX512IFMA;
bit #64+29 que indica la disponibilidad de la extensión SHA;
bit #64+30 que indica la disponibilidad de la extensión AVX512BW;
bit #64+31 que indica la disponibilidad de la extensión AVX512VL;
bit #64+41 que indica la disponibilidad de la extensión VAES;
bit #64+42 que indica la disponibilidad de la extensión VPCLMULQDQ;

Los siguientes son bits de capacidad notables del vector lógico 2 (LV2) resultantes de la siguiente ejecución de CPUID.(EAX=07H,ECX=0H).EDX y CPUID.(EAX=07H,ECX=1H).EAX:

Bits de capacidad notables para LV3

Los siguientes son bits de capacidad notables del vector lógico 3 (LV3) resultantes de la siguiente ejecución de CPUID.(EAX=07H,ECX=1H).EDX y CPUID.(EAX=07H,ECX=1H).EBX:

bit #192+19 que indica la disponibilidad de la extensión AVX10 Converged Vector ISA;

bit #256+48 que indica soporte AVX10 XMM;
bit #256+49 que indica soporte AVX10 YMM;
bit #256+50 que indica soporte AVX10 ZMM;

OPENSSL_ia32cap(3ssl)

NAME

OPENSSL_ia32cap - OPENSSL_ia32cap environment variable

SYNOPSIS

OPENSSL_ia32cap

DESCRIPTION

This environment variable allows run-time modification of the processor capabilities. It is intended for use with openssl(1) built with the default configuration for specific architectures, e.g. x86_64. The variable expects a colon-separated list of logical vector values, where each value is a string representation of a logical vector (LV).

A logical vector is a bit mask of processor capabilities. The OpenSSL build checks and utilizes a selection of these. The standard set of logical vectors currently consists of five values, typically referred to as LV0 through LV4.

Each logical vector is represented by a sequence of decimal, octal, or hexadecimal digits. The bits within the logical vector are ordered from least significant to most significant.

The environment variable syntax is as follows:

"env OPENSSL_ia32cap=LV0:LV1:LV2:LV3:LV4"

Where each LVn is a string representing the value of logical vector n. If a logical vector value is omitted or empty, the corresponding capability bits will not be modified. A colon followed by another colon, like "::", means the corresponding logical vector is not set. A single colon, like ":", signifies the end of the provided values, and any remaining logical vectors not explicitly mentioned will be left unchanged.

Example usage:

To set logical vectors 0 and 1 to specific values, leaving others unchanged:

"env OPENSSL_ia32cap=0x1:0x2"

To set logical vector 2 to a specific value and zero out all subsequent logical vectors:

"env OPENSSL_ia32cap=::0x4:::"

The following command zeros out all capability bits in logical vectors 0 through 4:

"env OPENSSL_ia32cap=0:0:0:0:0"

To clear specific bits within a logical vector, the '~' prefix is used, followed by the value. This acts as a bit mask to clear bits.

For example, to disable specific instruction set extensions, you might use:

"env OPENSSL_ia32cap=:~0x20000000000"

This example zeros out the AVX2 capability bit (bit 57 in LV0) and all subsequent extension bits. Note that the specific bit assignments might vary depending on the CPU architecture and OpenSSL version.

To disable AESNI (LV0 bit 57) and VAES (LV1 bit 41) extensions, leaving other logical vectors unchanged:

"env OPENSSL_ia32cap=~0x200000000000000:~0x20000000000:~0x0:~0x0:~0x0"

The logical vectors (LV) described above. Each value is delimited by a ':'. Decimal/Octal/Hexadecimal values representations are supported.

"env OPENSSL_ia32cap=LV0:LV1:LV2:LV3:LV4"

Used in this form, each non-null logical vector will *overwrite* the entire corresponding capability vector pair with the provided value. To keep compatibility with the behaviour of the original OPENSSL_ia32cap environment variable <env OPENSSL_ia32cap=LV0:LV1>, the next capability vector pairs will be set to zero.

To illustrate, the following will zero all capability bits in logical vectors 1 and further (disable all post-AVX extensions):

"env OPENSSL_ia32cap=:0"

The following will zero all capability bits in logical vectors 2 and further:

"env OPENSSL_ia32cap=::0"

The following will zero all capability bits only in logical vector 1: "env OPENSSL_ia32cap=:0::::"

A more likely usage scenario would be to disable specific instruction set extensions. The '~' character is used to specify a bit mask of the extensions to be disabled for a particular logical vector.

To illustrate, the following will disable AVX2 code paths and further extensions:

"env OPENSSL_ia32cap=:~0x20000000000"

The following will disable AESNI (LV0 bit 57) and VAES (LV1 bit 41) extensions and therefore any code paths using those extensions but leave the rest of the logical vectors unchanged:

"env OPENSSL_ia32cap=~0x200000000000000:~0x20000000000:~0x0:~0x0:~0x0"

NOTES

Not all capability bits are copied from CPUID output verbatim. An example of this is the somewhat less intuitive clearing of LV0 bit #28, or ~0x10000000 in the "environment variable" terms. It has been adjusted to reflect whether or not the data cache is actually shared between logical cores. This in turn affects the decision on whether or not expensive countermeasures against cache-timing attacks are applied, most notably in AES assembler module.

RETURN VALUES

Not available.
