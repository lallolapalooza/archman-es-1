DESCRIPCIÓN

Las funciones descritas aquí son principalmente de interés para aquellos que proporcionan funcionalidad de OpenSSL, ya sea en OpenSSL mismo o en módulos de motor o similares.

Si la instalación de rastreo está habilitada (ver "Configurar Rastreo" a continuación), estas funciones se utilizan para generar salida de rastreo en texto libre.

La salida de rastreo se divide en tipos que se habilitan individualmente por la aplicación. Los tipos de rastreo se describen en detalle en "Tipos de rastreo" en OSSL_trace_set_callback(3). El tipo de respaldo OSSL_TRACE_CATEGORY_ALL no debe usarse con las funciones descritas aquí.

El rastreo para una categoría específica se habilita en tiempo de ejecución si se adjunta un llamado canal de rastreo a ella. Un canal de rastreo es simplemente un objeto BIO al cual la aplicación puede escribir su salida de rastreo.

La aplicación tiene dos formas diferentes de registrar un canal de rastreo, ya sea proporcionando directamente un objeto BIO usando OSSL_trace_set_channel(3), o proporcionando una rutina de callback usando OSSL_trace_set_callback(3). Este último está envuelto internamente por un objeto BIO dedicado, por lo que para el código de rastreo, ambos tipos de canal son efectivamente indistinguibles. Los llamamos un canal de rastreo simple y un canal de rastreo de callback, respectivamente.

Para producir salida de rastreo, es necesario obtener un puntero al canal de rastreo (es decir, el objeto BIO) usando OSSL_trace_begin(), escribir en él usando rutinas de salida BIO arbitrarias y, finalmente, liberar el canal usando OSSL_trace_end(). Las llamadas OSSL_trace_begin()/OSSL_trace_end() que rodean la salida de rastreo crean un grupo, que actúa como una sección crítica (protegida por un mutex) para garantizar que la salida de rastreo de diferentes hilos no se mezcle.

El código de rastreo normalmente no llama a OSSL_trace_{begin,end}() directamente, sino que utiliza un conjunto de macros de conveniencia, consulte la sección "Macros" a continuación.

Funciones

OSSL_trace_enabled() se puede usar para verificar si el rastreo para la categoría dada está habilitado, es decir, si la instalación de rastreo se ha habilitado estáticamente (ver "Configurar Rastreo" a continuación) y se ha registrado un canal de rastreo usando OSSL_trace_set_channel(3) o OSSL_trace_set_callback(3).

OSSL_trace_begin() se utiliza para iniciar una sección de rastreo y obtener el canal para la categoría dada en forma de un BIO. Este BIO solo se puede usar para salida. El puntero devuelto es NULL si la categoría es inválida o no está habilitada.

OSSL_trace_end() se utiliza para finalizar una sección de rastreo.

Usar OSSL_trace_begin() y OSSL_trace_end() para envolver secciones de rastreo es obligatorio. El resultado de intentar producir salida de rastreo fuera de tales secciones no está definido.

OSSL_trace_string() produce la salida de datos de longitud tamaño como una cadena en el BIO out. Si texto es 0, la función enmascara cualquier carácter de control incluido, aparte de los saltos de línea, y se asegura de que para una entrada no vacía, la salida termine con un salto de línea. A menos que completo no sea cero, la longitud se limita (con una advertencia adecuada) a OSSL_TRACE_STRING_MAX caracteres, que actualmente es 80.

Macros

Hay una serie de macros de conveniencia definidas para hacer el rastreo fácil y consistente.

OSSL_TRACE_BEGIN() y OSSL_TRACE_END() reservan el BIO "trc_out" y se utilizan de la siguiente manera para envolver una sección de rastreo:

OSSL_TRACE_BEGIN(TLS) {
    BIO_printf(trc_out, ... );
} OSSL_TRACE_END(TLS);

Esto normalmente se expandirá a:

do {
    BIO *trc_out = OSSL_trace_begin(OSSL_TRACE_CATEGORY_TLS);
    if (trc_out != NULL) {
        ...
        BIO_printf(trc_out, ...);
    }
    OSSL_trace_end(OSSL_TRACE_CATEGORY_TLS, trc_out);
} while (0);

OSSL_TRACE_CANCEL() debe usarse antes de regresar o saltar fuera de una sección de rastreo:

OSSL_TRACE_BEGIN(TLS) {
    if (algún_error) {
        OSSL_TRACE_CANCEL(TLS);
        goto err;
    }
    BIO_printf(trc_out, ... );
} OSSL_TRACE_END(TLS);

Esto normalmente se expandirá a:

do {
    BIO *trc_out = OSSL_trace_begin(OSSL_TRACE_CATEGORY_TLS);
    if (trc_out != NULL) {
        if (algún_error) {
            OSSL_trace_end(OSSL_TRACE_CATEGORY_TLS, trc_out);
            goto err;
        }
        BIO_printf(trc_out, ... );
    }
    OSSL_trace_end(OSSL_TRACE_CATEGORY_TLS, trc_out);
} while (0);

OSSL_TRACE() y OSSL_TRACE1(), OSSL_TRACE2(), ... OSSL_TRACE9() son los llamados macros de un solo disparo:

La llamada al macro "OSSL_TRACE(categoría, texto)" produce una salida de rastreo de texto literal.

La llamada al macro "OSSL_TRACEn(categoría, formato, arg1, ..., argn)" produce una salida de rastreo estilo printf con n argumentos de campo de formato (n=1,...,9). Se expande a:

OSSL_TRACE_BEGIN(category) {
    BIO_printf(trc_out, formato, arg1, ..., argN);
} OSSL_TRACE_END(category)

Internamente, todos los macros de un solo disparo se implementan utilizando un macro genérico OSSL_TRACEV(), ya que C90 no admite macros variádicos. Este macro auxiliar tiene una sinopsis bastante extraña y no debe usarse directamente.

La llamada al macro "OSSL_TRACE_STRING(categoría, texto, completo, datos, longitud)" produce la salida de datos de longitud tamaño como una cadena si el rastreo para la categoría dada está habilitado. Se expande a:

OSSL_TRACE_BEGIN(category) {
    OSSL_trace_string(trc_out, text, full, data, len);
} OSSL_TRACE_END(category)

El macro OSSL_TRACE_ENABLED() se puede usar para ejecutar condicionalmente algún código solo si una categoría de rastreo específica está habilitada. En algunas situaciones, esto es más simple que iniciar una sección de rastreo usando OSSL_TRACE_BEGIN() y OSSL_TRACE_END(). Por ejemplo, el código

if (OSSL_TRACE_ENABLED(TLS)) {
    ...
}

se expande a

if (OSSL_trace_enabled(OSSL_TRACE_CATEGORY_TLS) {
    ...
}

NOTAS

No es necesario proteger las llamadas a funciones de salida de rastreo como OSSL_TRACE(categoría, ...) con OSSL_TRACE_ENABLED(categoría).

Si la producción de la salida de rastreo requiere la realización de cálculos auxiliares, este código auxiliar debe colocarse dentro de un bloque condicional que se ejecute solo si la categoría de rastreo está habilitada.

La forma más natural de hacerlo es colocar el código dentro de la propia sección de rastreo, ya que ya introduce dicho bloque condicional.

OSSL_TRACE_BEGIN(TLS) {
    int var = do_some_auxiliary_calculation();
    BIO_printf(trc_out, "var = %d\n", var);
} OSSL_TRACE_END(TLS);

En algunos casos, es más ventajoso usar un grupo condicional simple en lugar de una sección de rastreo. Este es el caso si los cálculos y el rastreo ocurren en diferentes ubicaciones del código, o si los cálculos son tan lentos que colocarlos dentro de una sección de rastreo (crítica) crearía demasiada contención.

DESCRIPTION

The OpenSSL library includes a tracing facility that can be used for debugging and diagnostic purposes. This facility allows developers to insert trace points into the code that will only be active when tracing is explicitly enabled. When tracing is enabled, trace messages are directed to a channel, which can be configured to be a file, standard error, or other output streams.

The tracing facility is organized around types of tracing events. These types are defined in the include file <openssl/trace.h> and typically correspond to specific areas of the library's functionality, such as TLS, crypto algorithms, or other subsystems. The specific types available depend on how OpenSSL was configured and built.

The core functions are:

OSSL_trace_enabled(3)
Checks if tracing is currently enabled for the given trace type.
OSSL_trace_begin(3)
Starts a trace block for the given type. If tracing is enabled for this type, it returns an initialized BIO object that can be used for writing trace information. Otherwise, it returns NULL.
OSSL_trace_end(3)
Ends a trace block started by OSSL_trace_begin(3). It takes the type and the BIO pointer returned by OSSL_trace_begin(3). If the type is enabled, it writes any buffered trace data and releases the BIO object. If the type is not enabled, it simply releases the BIO object without writing anything.
OSSL_trace_cancel(3)
Cancels a trace block without writing any output. This is useful for handling error conditions within a trace block.
OSSL_trace_printf(3), OSSL_trace_vprintf(3), OSSL_trace_puts(3)
These functions provide direct ways to write trace messages for a given type without explicitly using OSSL_trace_begin(3) and OSSL_trace_end(3). They automatically check if tracing is enabled for the given type and handle the output accordingly. OSSL_trace_puts(3) is a convenience function for writing a simple string.
OSSL_trace_end_string(3)
This function is similar to OSSL_trace_puts(3) but is intended to be used for writing the final part of a trace message, potentially followed by a newline character.
OSSL_trace_string(3)
This function writes a string to the trace output for the specified type. It is intended for writing complete trace messages that do not require formatting.

In addition to the core functions, there are convenience macros that simplify the use of the tracing facility. These macros often wrap the core functions to provide a more concise syntax:

OSSL_TRACE_BEGIN(type)
Expands to a call to OSSL_trace_begin(type) and sets up the necessary context for subsequent trace output within the block.
OSSL_TRACE_END(type)
Expands to a call to OSSL_trace_end(type) to close the trace block.
OSSL_TRACE_CANCEL(type)
Expands to a call to OSSL_trace_cancel(type) to discard any buffered trace output for the current block.
OSSL_TRACE_PRINTF(type, ...)
Expands to a call to OSSL_trace_printf(type, ...).
OSSL_TRACE_VPRINTF(type, ...)
Expands to a call to OSSL_trace_vprintf(type, ...).
OSSL_TRACE_PUTS(type, ...)
Expands to a call to OSSL_trace_puts(type, ...).
OSSL_TRACE_STRING_MAX(type, str)
This macro is intended for tracing strings up to a maximum length. It handles potential buffer overflows.
SL_TRACE1(type, ...), SL_TRACE2(type, ...), ..., SL_TRACE6(type, ...)
These are specialized convenience macros for outputting trace messages with varying numbers of arguments. For example, SL_TRACE1 is for messages with one argument, SL_TRACE2 for two, and so on, up to SL_TRACE6. They are typically used for formatted string output similar to printf.

Example usage:

    #include <openssl/trace.h>

    void process_data(int var)
    {
        OSSL_TRACE_BEGIN(TLS_CLIENT);
        if (condition_for_error) {
            OSSL_TRACE_CANCEL(TLS_CLIENT);
            goto err;
        }
        OSSL_TRACE_PRINTF(TLS_CLIENT, "Processing data with var = %d\n", var);
        // ... other operations ...
        OSSL_TRACE_END(TLS_CLIENT);
        return;

    err:
        // Error handling
        OSSL_TRACE_END(TLS_CLIENT); // Ensure trace is ended even on error
        return;
    }

Note however that premature optimization of tracing code is in general futile and it's better to keep the tracing code as simple as possible. Because most often the limiting factor for the application's speed is the time it takes to print the trace output, not to calculate it.

Configure Tracing

By default, the OpenSSL library is built with tracing disabled. To use the tracing functionality documented here, it is therefore necessary to configure and build OpenSSL with the 'enable-trace' option.

When the library is built with tracing disabled:

  • The macro OPENSSL_NO_TRACE is defined in <openssl/opensslconf.h>.
  • all functions are still present, but OSSL_trace_enabled() will always report the categories as disabled, and all other functions will do nothing.
  • the convenience macros are defined to produce dead code. For example, take this example from "Macros" section above: 
    OSSL_TRACE_BEGIN(TLS) {
    if (condition) {
        OSSL_TRACE_CANCEL(TLS);
        goto err;
    }
    BIO_printf(trc_out, ... );
} OSSL_TRACE_END(TLS);

    When the tracing API isn't operational, that will expand to:

    do {
    BIO *trc_out = NULL;
    if (0) {
        if (condition) {
            ((void)0);
            goto err;
        }
        BIO_printf(trc_out, ... );
    }
} while (0);

RETURN VALUES

OSSL_trace_enabled() returns 1 if tracing for the given type is operational and enabled, otherwise 0.

OSSL_trace_begin() returns a BIO pointer if the given type is enabled, otherwise NULL.

OSSL_trace_string() returns the number of characters emitted, or -1 on error.
