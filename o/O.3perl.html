O(3perl) Guía de referencia para programadores de Perl O(3perl)

NOMBRE

O - Interfaz genérica para backends de compilador de Perl

SINOPSIS

perl -MO=[-q,]Backend[,OPCIONES] foo.pl

DESCRIPCIÓN

Este es el módulo que se utiliza como front-end para el Compilador de Perl.

Si pasas la opción "-q" al módulo, el manejador de archivo STDOUT se redirigirá a la variable $O::BEGIN_output durante la compilación. Esto tiene el efecto de que cualquier salida impresa en STDOUT por bloques BEGIN o módulos usados se almacenará en esta variable en lugar de imprimirse. Es útil con aquellos backends que producen su propia salida ("Deparse", "Concise", etc.), para que su salida no se confunda con la generada por el código que se está compilando.

La opción "-qq" se comporta como "-q", excepto que también cierra STDERR después de que ha terminado la decompilación. Esto suprime el mensaje "Syntax OK" normalmente producido por perl.

CONVENCIONES

La mayoría de los backends de compilador usan las siguientes convenciones: OPCIONES consiste en una lista separada por comas de palabras (sin espacios en blanco). La opción "-v" normalmente pone el backend en modo verboso. La opción "-ofile" genera salida al archivo file en lugar de stdout. La opción "-D" seguida de varias letras activa varias banderas de depuración internas. Ver la documentación del backend deseado (llamado "B::Backend" para el ejemplo anterior) para saber más sobre ese backend.

IMPLEMENTACIÓN

Esta sección es necesaria solo para aquellos que quieren escribir un módulo backend de compilador que pueda ser usado a través de este módulo.

El comando de línea mencionado en la sección SINOPSIS corresponde al código de Perl

use O ("Backend", OPCIONES);

La función "O::import" carga el módulo apropiado "B::Backend" y llama a su función "compile", pasándole OPCIONES. Se espera que esa función devuelva una referencia a subrutina que llamaremos CALLBACK. A continuación, se activa la bandera "compile-only" (equivalente a la opción de línea de comandos "-c") y se registra un bloque CHECK que llama a CALLBACK. Por lo tanto, el programa principal de Perl mencionado en la línea de comandos se lee, se analiza y se compila en forma de árbol de sintaxis interno. Dado que la bandera "-c" está activada, el programa no se ejecuta (excepto los bloques BEGIN, por supuesto), sino que se invoca la función CALLBACK registrada por el backend del compilador.

En resumen, un módulo backend de compilador debería llamarse "B::Foo" para algún foo y vivir en el directorio apropiado para ese nombre. Debería definir una función llamada "compile". Cuando el usuario escribe

perl -MO=Foo,OPCIONES foo.pl

se llama a esa función y se le pasan esas OPCIONES (divididas por comas). Debería devolver una ref de subrutina a la función de compilación principal. Después de que el programa del usuario se carga y se analiza, se invoca la ref de subrutina devuelta, que puede proceder a realizar la compilación, generalmente haciendo uso de la funcionalidad del módulo "B".

ERRORES

Las opciones "-q" y "-qq" no funcionan correctamente si perl no se compila con soporte PerlIO: STDOUT se cerrará en lugar de ser redirigido a $O::BEGIN_output.
