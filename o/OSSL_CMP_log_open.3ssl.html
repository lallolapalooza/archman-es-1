OSSL_CMP_log_open(3ssl)

Paquete: openssl

Licencias: Apache-2.0

OSSL_CMP_LOG_OPEN(3ssl) OpenSSL OSSL_CMP_LOG_OPEN(3ssl)

NOMBRE

OSSL_CMP_log_open, OSSL_CMP_log_close, OSSL_CMP_severity, OSSL_CMP_LOG_EMERG, OSSL_CMP_LOG_ALERT, OSSL_CMP_LOG_CRIT, OSSL_CMP_LOG_ERR, OSSL_CMP_LOG_WARNING, OSSL_CMP_LOG_NOTICE, OSSL_CMP_LOG_INFO, OSSL_CMP_LOG_DEBUG, OSSL_CMP_LOG_TRACE,

OSSL_CMP_log_cb_t, OSSL_CMP_print_to_bio, OSSL_CMP_print_errors_cb - funciones para registrar y reportar errores

SINOPSIS

#include <openssl/cmp_util.h>
int  OSSL_CMP_log_open(void);
void OSSL_CMP_log_close(void);
/* las declaraciones de nivel de severidad se parecen a las de syslog.h */
typedef int OSSL_CMP_severity;
#define OSSL_CMP_LOG_EMERG   0
#define OSSL_CMP_LOG_ALERT   1
#define OSSL_CMP_LOG_CRIT    2
#define OSSL_CMP_LOG_ERR     3
#define OSSL_CMP_LOG_WARNING 4
#define OSSL_CMP_LOG_NOTICE  5
#define OSSL_CMP_LOG_INFO    6
#define OSSL_CMP_LOG_DEBUG   7
#define OSSL_CMP_LOG_TRACE   8
typedef int (*OSSL_CMP_log_cb_t)(const char *component,
                                 const char *file, int line,
                                 OSSL_CMP_severity level, const char *msg);
int OSSL_CMP_print_to_bio(BIO *bio, const char *component, const char *file,
                          int line, OSSL_CMP_severity level, const char *msg);
void OSSL_CMP_print_errors_cb(OSSL_CMP_log_cb_t log_fn);

DESCRIPCIÓN

El sistema de registro y reporte de errores descrito aquí contiene funciones de conveniencia para el registro específico de CMP, incluyendo un prefijo de cadena que refleja los niveles de severidad de syslog.h, y mejoras al mecanismo de cola de errores necesarias para mensajes de diagnóstico grandes producidos por la biblioteca CMP en caso de fallos de validación de certificados.

Cuando se realiza una actividad interesante o ocurre un error, se debe proporcionar algún detalle para información del usuario, depuración y propósitos de auditoría. Una aplicación CMP puede obtener esta información proporcionando una función de callback con el siguiente tipo:

typedef int (*OSSL_CMP_log_cb_t)(const char *component,
                                 const char *file, int line,
                                 OSSL_CMP_severity level, const char *msg);

Los parámetros pueden proporcionar información de algún componente (que puede ser un nombre de módulo y/o nombre de función) o NULL, una ruta de archivo o NULL, un número de línea o 0 indicando la ubicación del código fuente, un nivel de severidad y una cadena de mensaje que describe la naturaleza del evento, terminada por '\n'.

Incluso cuando una actividad es exitosa, algunas advertencias pueden ser útiles y puede requerirse cierto grado de auditoría. Por lo tanto, el sistema de registro soporta un nivel de severidad y la función de callback tiene un parámetro level que indica dicho nivel, de modo que los errores, advertencias, información, depuración, etc. puedan tratarse de manera diferente. El callback se activa solo cuando el nivel de severidad es suficiente según el nivel actual de verbosidad, que por defecto es OSSL_CMP_LOG_INFO.

La función de callback puede realizar tareas no triviales como escribir en un archivo de registro o un stream remoto, lo que a su vez puede fallar. Por lo tanto, la función debe devolver 1 en caso de éxito y 0 en caso de error.

OSSL_CMP_log_open() inicializa el sistema de registro específico de CMP para que emita todo a STDOUT. Falla si el rastreo integrado está deshabilitado o STDIO no está disponible. Puede llamarse durante el inicio de la aplicación. Alternativamente, OSSL_CMP_CTX_set_log_cb(3) puede usarse para mayor flexibilidad. Mientras ninguna de las dos se use, cualquier salida de registro se ignora.

OSSL_CMP_log_close() puede llamarse cuando todas las actividades hayan finalizado para vaciar cualquier salida de registro pendiente específica de CMP y desasignar recursos relacionados. Puede llamarse varias veces. Se llama al apagar OpenSSL.

OSSL_CMP_print_to_bio() imprime la información del componente, nombre de archivo, número de línea, nivel de severidad y mensaje de registro o mensaje de la cola de errores dados al bio especificado. component suele ser el nombre de una función o módulo. Si es NULL, está vacío, o es "(unknown function)" entonces se usa "CMP" como alternativa.

OSSL_CMP_print_errors_cb() emite cualquier entrada en la cola de errores de OpenSSL. Es similar a ERR_print_errors_cb(3) pero usa la función de callback de registro de CMP log_fn para uniformidad con el registro de CMP si no es NULL. De lo contrario, imprime a STDERR usando OSSL_CMP_print_to_bio(3) (a menos que esté definido OPENSSL_NO_STDIO).

VALORES DE RETORNO

OSSL_CMP_log_close() y OSSL_CMP_print_errors_cb() no devuelven nada.

Todas las demás funciones devuelven 1 en caso de éxito, 0 en caso de error.

HISTORIA

El soporte CMP de OpenSSL se añadió en OpenSSL 3.0.
