DESCRIPCIÓN

OSSL_CMP_SRV_process_request() implementa los aspectos generales de un servidor CMP. Sus argumentos son el OSSL_CMP_SRV_CTX srv_ctx y el mensaje de solicitud CMP req. Realiza los comprobamientos generales en req, llama a la función de callback correspondiente (si está presente) para procesar más específicamente, y luego junta el resultado, que puede ser un mensaje CMP de error. Si después de devolver la función la expresión OSSL_CMP_CTX_get_status(OSSL_CMP_SRV_CTX_get0_cmp_ctx(srv_ctx)) devuelve -1, entonces la función ha cerrado la transacción actual, que podría ser debido a un final normal de la transacción o a un error.

OSSL_CMP_CTX_server_perform() es una interfaz para OSSL_CMP_SRV_process_request() que puede usarse por parte de un cliente CMP de manera similar a OSSL_CMP_MSG_http_perform(3). El OSSL_CMP_SRV_CTX debe ser establecido como transfer_cb_arg del client_ctx.

OSSL_CMP_SRV_CTX_new() crea y inicializa un OSSL_CMP_SRV_CTX estructura asociada al contexto de la librería libctx y la cadena de propiedades propq, ambos de los cuales pueden ser NULL para seleccionar los valores por defecto.

OSSL_CMP_SRV_CTX_free() elimina el srv_ctx dado. Si el argumento es NULL, nada se hace.

OSSL_CMP_SRV_CTX_init() establece en el srv_ctx un contexto personalizado del servidor CMP y las funciones de callback que realizan el procesamiento específico de solicitudes de certificados, solicitudes de revocación, solicitudes de confirmación de certificados, mensajes generales, mensajes de error y solicitudes de poll. Todos los argumentos excepto srv_ctx pueden ser NULL. Si no se proporciona una función de callback para algún tipo de mensaje, esto significa que ese tipo de mensaje no está soportado por el servidor.

OSSL_CMP_SRV_CTX_init_trans() establece en srv_ctx las funciones de callback opcionales para iniciar el envío de respuestas retrasadas y limpiar una transacción. Si la función delay> es NULL, el envío de respuestas nunca se retrasa. De lo contrario, delay toma un contexto personalizado del servidor y un mensaje de solicitud como entrada. Debe retornar 1 si el envío de la respuesta correspondiente se debe retrasar, 0 si no, y -1 en caso de error. Si la función clean> es NULL, no se realiza ningún limpieza específica. De lo contrario, clean toma un contexto personalizado del servidor y un puntero a la identificación de la transacción como entrada, donde el puntero es NULL si se está iniciando una nueva transacción, y proporciona la identificación de la transacción que se está terminando. La función clean> debe resetear las partes correspondientes del estado y liberar la memoria relacionada. Debe retornar 1 en caso de éxito y 0 en caso de error.

OSSL_CMP_SRV_CTX_get0_cmp_ctx() devuelve el OSSL_CMP_CTX del srv_ctx.

OSSL_CMP_SRV_CTX_get0_custom_ctx() devuelve el contexto personalizado del servidor del srv_ctx que ha sido establecido usando OSSL_CMP_SRV_CTX_init().

OSSL_CMP_SRV_CTX_set_send_unprotected_errors() activa el envío de mensajes de error y respuestas negativas sin protección.

OSSL_CMP_SRV_CTX_set_accept_unprotected() activa la aceptación de solicitudes sin protección de con validación de protección.

OSSL_CMP_SRV_CTX_set_accept_raverified() activa la aceptación de mensajes de ir/cr/kur con POPO 'RAVerified'.

OSSL_CMP_SRV_CTX_set_grant_implicit_confirm() activa la confirme implícita de certificados nuevos si se lo solicita.

NOTAS

CMP está definido en RFC 4210 (y CRMF en RFC 4211).

Hasta ahora, la implementación del servidor CMP está limitada a una solicitud por mensaje CMP (y por lo tanto a un componente de respuesta por mensaje CMP máximo).

VALORES DE RETORNO

OSSL_CMP_SRV_CTX_new() devuelve un OSSL_CMP_SRV_CTX estructura en caso de éxito, NULL en error.

OSSL_CMP_SRV_CTX_free() no devuelve un valor.

OSSL_CMP_SRV_CTX_get0_cmp_ctx() devuelve un OSSL_CMP_CTX.

OSSL_CMP_SRV_CTX_get0_custom_ctx() devuelve el contexto personalizado del servidor del srv_ctx que ha sido establecido usando OSSL_CMP_SRV_CTX_init().

OSSL_CMP_SRV_CTX_set_send_unprotected_errors() habilita el envío de mensajes de error y respuestas negativas sin protección.

OSSL_CMP_SRV_CTX_set_accept_unprotected() habilita la aceptación de solicitudes sin protección de con validación de protección.

OSSL_CMP_SRV_CTX_set_accept_raverified() habilita la aceptación de mensajes de ir/cr/kur con POPO 'RAVerified'.

OSSL_CMP_SRV_CTX_set_grant_implicit_confirm() habilita la confirme implícita de certificados nuevos si se lo solicita.

DESCRIPTION

The OSSL_CMP library provides server side support for the CMP protocol. This man page describes the functions for setting up and configuring an OSSL_CMP_SRV_CTX server context.

OSSL_CMP_SRV_CTX is a structure that holds all the server side configuration, and is used by the CMP server implementation to process incoming requests.

OSSL_CMP_SRV_CTX_new() creates and initialises a new server context.

OSSL_CMP_SRV_CTX_init() performs initialisation of the server context, potentially loading configurations from a file. This is a shortcut for loading a configuration file and initialising the context.

OSSL_CMP_SRV_CTX_init_trans() performs initialisation of the server context, supporting delayed delivery of all types of response messages. This function allows a CMP server to be implemented that can hold pending responses and deliver them later when a transport becomes available.

OSSL_CMP_SRV_CTX_free() frees the provided server context and all allocated resources.

OSSL_CMP_SRV_CTX_set0_pass_cb() and OSSL_CMP_SRV_CTX_set1_pass_cb() set a callback function for password handling during protection of CMP messages. The callback function is invoked when a password is required for PBM (Password Based Message Authentication). The callback function should return the password string. For OSSL_CMP_SRV_CTX_set0_pass_cb() the passed password callback data is not duplicated, while for OSSL_CMP_SRV_CTX_set1_pass_cb() it is duplicated. The callback function signature is:

typedef int OSSL_CMP_PBM_PASS_CB(char *buf, int size, int rwflag, void *userdata);

OSSL_CMP_SRV_CTX_set_fail_cb() sets a callback function to be called when the CMP server encounters a failure. The callback function can be used for logging or other error handling purposes. The callback function signature is:

typedef void OSSL_CMP_FAIL_CB(int error, void *userdata);

OSSL_CMP_SRV_CTX_set_log_cb() sets a callback function to be called for logging messages from the CMP server. The callback function can be used to direct logs to different destinations. The callback function signature is:

typedef void OSSL_CMP_LOG_CB(int level, const char *msg, void *userdata);

OSSL_CMP_SRV_CTX_set_expected_content_type() sets the expected content type for incoming messages. This can be used to validate that the received message conforms to the expected type, e.g. OSSL_CMP_MSGTYPE_IR.

OSSL_CMP_SRV_CTX_set_expected_operation() sets the expected operation for incoming messages. This can be used to validate that the received message conforms to the expected operation, e.g. OSSL_CMP_OP_IR.

OSSL_CMP_SRV_CTX_set_expected_sender() sets the expected sender name for incoming messages. This can be used to validate that the received message originates from an expected entity.

OSSL_CMP_SRV_CTX_set_transport_failure_info_expected() configures whether transport failure information is expected in the response. If expected is non-zero, transport failure information will be included.

OSSL_CMP_SRV_CTX_set_proxy_cert_auth() sets the authentication key and certificate for proxy authentication. This is used when the CMP server acts as a proxy for another CMP entity.

OSSL_CMP_SRV_CTX_set0_custom_ctx() sets a pointer to a custom context that can be used by the CMP server implementation to store application-specific data.

OSSL_CMP_SRV_CTX_get0_custom_ctx() returns the custom server context that has been set using OSSL_CMP_SRV_CTX_set0_custom_ctx().

NOTES

The OSSL_CMP_SRV_CTX_init() and OSSL_CMP_SRV_CTX_init_trans() functions allow loading server context information from a configuration file. The format of the configuration file is described in the OSSL_CMP_CONFIG(5) manual page.

The callback functions passed to OSSL_CMP_SRV_CTX_set0_pass_cb(), OSSL_CMP_SRV_CTX_set1_pass_cb(), OSSL_CMP_SRV_CTX_set_fail_cb(), and OSSL_CMP_SRV_CTX_set_log_cb() are owned by the caller. The caller is responsible for managing their lifetime.

RETURN VALUES

OSSL_CMP_SRV_CTX_new(), OSSL_CMP_SRV_CTX_init(), and OSSL_CMP_SRV_CTX_init_trans() return a pointer to a newly created OSSL_CMP_SRV_CTX structure on success, and NULL on error.

OSSL_CMP_SRV_CTX_free() returns nothing.

All other functions return 1 on success, 0 on error.

HISTORY

The OpenSSL CMP support was added in OpenSSL 3.0.

OSSL_CMP_SRV_CTX_init_trans() supporting delayed delivery of all types of response messages was added in OpenSSL 3.3.
