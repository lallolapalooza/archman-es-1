OPENSSL_secure_malloc(3ssl)

Paquete: openssl

Licencias: Apache-2.0

OPENSSL_SECURE_MALLOC(3ssl) OpenSSL OPENSSL_SECURE_MALLOC(3ssl)

NOMBRE

CRYPTO_secure_malloc_init, CRYPTO_secure_malloc_initialized, CRYPTO_secure_malloc_done, OPENSSL_secure_malloc, CRYPTO_secure_malloc, OPENSSL_secure_zalloc, CRYPTO_secure_zalloc, OPENSSL_secure_malloc_array, CRYPTO_secure_malloc_array, OPENSSL_secure_calloc, CRYPTO_secure_calloc, OPENSSL_secure_free, CRYPTO_secure_free, OPENSSL_secure_clear_free, CRYPTO_secure_clear_free, OPENSSL_secure_actual_size, CRYPTO_secure_allocated, CRYPTO_secure_used - almacenamiento seguro en el heap

SINOPSIS

#include <openssl/crypto.h>
int CRYPTO_secure_malloc_init(size_t size, size_t minsize);
int CRYPTO_secure_malloc_initialized();
int CRYPTO_secure_malloc_done();
void *OPENSSL_secure_malloc(size_t num);
void *CRYPTO_secure_malloc(size_t num, const char *file, int line);
void *OPENSSL_secure_zalloc(size_t num);
void *CRYPTO_secure_zalloc(size_t num, const char *file, int line);
void *OPENSSL_secure_malloc_array(size_t num, size_t size);
void *CRYPTO_secure_malloc_array(size_t num, size_t size,
                                 const char *file, int line);
void *OPENSSL_secure_calloc(size_t num, size_t size);
void *CRYPTO_secure_calloc(size_t num, size_t size,
                           const char *file, int line);
void OPENSSL_secure_free(void* ptr);
void CRYPTO_secure_free(void *ptr, const char *, int);
void OPENSSL_secure_clear_free(void* ptr, size_t num);
void CRYPTO_secure_clear_free(void *ptr, size_t num, const char *, int);
size_t OPENSSL_secure_actual_size(const void *ptr);
int CRYPTO_secure_allocated(const void *ptr);
size_t CRYPTO_secure_used();

DESCRIPCIÓN

Para ayudar a proteger las aplicaciones (particularmente servidores de larga ejecución) de desbordamientos o subdesbordamientos de punteros que podrían devolver datos arbitrarios del área de memoria dinámica del programa, donde podrían almacenarse claves y otra información sensible, OpenSSL soporta el concepto de un "heap seguro". El nivel y el tipo de garantías de seguridad dependen del sistema operativo. Es una buena idea revisar el código y ver si aborda su modelo de amenaza y sus preocupaciones. Cabe señalar que el heap seguro utiliza un único bloqueo de lectura/escritura, y por lo tanto, cualquier operación que involucre la asignación o liberación de memoria del heap seguro se serializa, bloqueando otros hilos. Con esto en mente, las aplicaciones altamente concurrentes deberían habilitar el heap seguro con precaución y ser conscientes de las implicaciones de rendimiento para el código multihilo.

Si se utiliza un heap seguro, entonces los valores de clave privada BIGNUM se almacenan allí. Esto protege el almacenamiento a largo plazo de claves privadas, pero no necesariamente pondrá todos los valores intermedios y cálculos allí.

CRYPTO_secure_malloc_init() crea el heap seguro, con el "size" especificado en bytes. El parámetro "minsize" es el tamaño mínimo a asignar desde el heap o cero para usar un valor predeterminado razonable. Tanto "size" como, si se especifica, "minsize" deben ser potencias de dos y "minsize" generalmente debe ser pequeño, por ejemplo, 16 o 32. "minsize" debe ser menor que una cuarta parte de "size" en cualquier caso.

CRYPTO_secure_malloc_initialized() indica si el heap seguro ha sido inicializado y está disponible.

CRYPTO_secure_malloc_done() libera el heap y hace que la memoria no esté disponible para el proceso si se ha liberado toda la memoria segura. Puede tardar notablemente en completarse.

OPENSSL_secure_malloc() asigna "num" bytes del heap. Si no se llama a CRYPTO_secure_malloc_init(), esto es equivalente a llamar a OPENSSL_malloc(). Es una macro que se expande a CRYPTO_secure_malloc() y agrega los parámetros "__FILE__" y "__LINE__".

OPENSSL_secure_zalloc() y CRYPTO_secure_zalloc() son como OPENSSL_secure_malloc() y CRYPTO_secure_malloc(), respectivamente, excepto que llaman a memset() para poner a cero la memoria antes de devolverla.

OPENSSL_secure_malloc_array(), CRYPTO_secure_malloc_array(), OPENSSL_secure_calloc() y CRYPTO_secure_calloc() son variantes de OPENSSL_secure_malloc(), CRYPTO_secure_malloc(), OPENSSL_secure_zalloc() y CRYPTO_secure_zalloc(), respectivamente, que aceptan un parámetro adicional, size, que permite operaciones de asignación de memoria para una matriz de num elementos de size bytes cada uno; estas funciones devuelven un error si la multiplicación de num y size produce un desbordamiento de entero, previniendo así la asignación de un tamaño incorrecto.

OPENSSL_secure_free() libera la memoria en "ptr" de vuelta al heap. Debe llamarse con un valor previamente obtenido de OPENSSL_secure_malloc(). Si no se llama a CRYPTO_secure_malloc_init(), esto es equivalente a llamar a OPENSSL_free(). Existe para la consistencia con OPENSSL_secure_malloc(), y es una macro que se expande a CRYPTO_secure_free() y agrega los parámetros "__FILE__" y "__LINE__". Si el argumento para OPENSSL_secure_free() es NULL, no se hace nada.

OPENSSL_secure_clear_free() es similar a OPENSSL_secure_free() excepto que tiene un parámetro adicional "num" que se utiliza para limpiar la memoria si no fue asignada desde el heap seguro. Si no se llama a CRYPTO_secure_malloc_init(), esto es equivalente a llamar a OPENSSL_clear_free(). Si el argumento para OPENSSL_secure_clear_free() es NULL, no se hace nada.

OPENSSL_secure_actual_size() indica el tamaño real asignado al puntero; las implementaciones pueden asignar más espacio del solicitado inicialmente, para "redondear" y reducir la fragmentación del heap seguro.

OPENSSL_secure_allocated() indica si un puntero está asignado en el heap seguro.

CRYPTO_secure_used() devuelve el número de bytes asignados en el heap seguro.

VALORES DE RETORNO

CRYPTO_secure_malloc_init() devuelve 0 en caso de fallo, 1 si tiene éxito, y 2 si tiene éxito pero el heap no pudo ser protegido por mapeo de memoria.

CRYPTO_secure_malloc_initialized() devuelve 1 si el heap seguro está disponible (es decir, si se ha llamado a CRYPTO_secure_malloc_init(), pero no se ha llamado a CRYPTO_secure_malloc_done() o ha fallado) o 0 si no.

OPENSSL_secure_malloc(), CRYPTO_secure_malloc(), OPENSSL_secure_zalloc(), CRYPTO_secure_zalloc(), OPENSSL_secure_malloc_array(), CRYPTO_secure_malloc_array(), OPENSSL_secure_calloc() y CRYPTO_secure_calloc() devuelven un puntero al heap seguro del tamaño solicitado, si está inicializado, un puntero devuelto por la llamada subyacente a OPENSSL_malloc(), si no lo está, o "NULL" en caso de error.

CRYPTO_secure_allocated() devuelve 1 si el puntero está en el heap seguro, o 0 si no.

CRYPTO_secure_malloc_done() devuelve 1 si el área de memoria segura se libera, o 0 si no.

OPENSSL_secure_free() y OPENSSL_secure_clear_free() no devuelven valores.

VER TAMBIÉN

OPENSSL_malloc(3), BN_new(3)

HISTORIA

La función OPENSSL_secure_clear_free() se añadió en OpenSSL 1.1.0g.

El segundo argumento para CRYPTO_secure_malloc_init() se cambió de un int a un size_t en OpenSSL 3.0.

Las funciones OPENSSL_secure_malloc_array(), CRYPTO_secure_malloc_array(), OPENSSL_secure_calloc() y CRYPTO_secure_calloc() se añadieron en OpenSSL 3.6.
