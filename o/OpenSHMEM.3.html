intro_shmem - Introducción al modelo de programación OpenSHMEM

DESCRIPCIÓN

El modelo de programación SHMEM consta de rutinas de biblioteca que proporcionan comunicación de baja latencia y alto ancho de banda para su uso en programas escalables altamente paralelizados. Las rutinas de la interfaz de programación de aplicaciones (API) de OpenSHMEM proporcionan un modelo de programación para intercambiar datos entre procesos paralelos cooperativos. Los programas resultantes son de estilo similar a los programas Message Passing Interface (MPI). La API de SHMEM puede usarse sola o en combinación con rutinas MPI en el mismo programa paralelo.

Un programa OpenSHMEM es de estilo SPMD (programa único, datos múltiples). Los procesos SHMEM, llamados elementos de procesamiento o PE (del inglés *processing elements*), se inician todos al mismo tiempo y todos ejecutan el mismo programa. Normalmente, los PE realizan cálculos en sus subdominios propios del problema más grande y se comunican periódicamente con otros PE para intercambiar información de la que depende la siguiente fase de cálculo.

Las rutinas de OpenSHMEM minimizan la sobrecarga asociada con las solicitudes de transferencia de datos, maximizan el ancho de banda y minimizan la latencia de los datos. La latencia de los datos es el período de tiempo que comienza cuando un PE inicia una transferencia de datos y termina cuando un PE puede utilizar los datos. Las rutinas de OpenSHMEM admiten la transferencia de datos remota a través de operaciones *put* (poner), que transfieren datos a un PE diferente, operaciones *get* (obtener), que transfieren datos desde un PE diferente, y punteros remotos, que permiten referencias directas a objetos de datos propiedad de otro PE. Otras operaciones admitidas son difusión colectiva y reducción, sincronización de barrera y operaciones atómicas de memoria. Una operación atómica de memoria es una operación atómica de lectura y actualización, como un *fetch-and-increment* (obtener e incrementar), sobre un objeto de datos remoto o local.
