OSSL_LIB_CTX(3ssl)

OSSL_LIB_CTX(3ssl) OpenSSL OSSL_LIB_CTX(3ssl)

NOMBRE

OSSL_LIB_CTX, OSSL_LIB_CTX_get_data, OSSL_LIB_CTX_new, OSSL_LIB_CTX_new_from_dispatch, OSSL_LIB_CTX_new_child, OSSL_LIB_CTX_free, OSSL_LIB_CTX_load_config, OSSL_LIB_CTX_get0_global_default, OSSL_LIB_CTX_set0_default - contexto de la biblioteca OpenSSL

SINOPSIS

#include <openssl/crypto.h>
typedef struct ossl_lib_ctx_st OSSL_LIB_CTX;
OSSL_LIB_CTX *OSSL_LIB_CTX_new(void);
OSSL_LIB_CTX *OSSL_LIB_CTX_new_from_dispatch(const OSSL_CORE_HANDLE *handle,
                                             const OSSL_DISPATCH *in);
OSSL_LIB_CTX *OSSL_LIB_CTX_new_child(const OSSL_CORE_HANDLE *handle,
                                     const OSSL_DISPATCH *in);
int OSSL_LIB_CTX_load_config(OSSL_LIB_CTX *ctx, const char *config_file);
void OSSL_LIB_CTX_free(OSSL_LIB_CTX *ctx);
OSSL_LIB_CTX *OSSL_LIB_CTX_get0_global_default(void);
OSSL_LIB_CTX *OSSL_LIB_CTX_set0_default(OSSL_LIB_CTX *ctx);
void *OSSL_LIB_CTX_get_data(OSSL_LIB_CTX *ctx, int index);

DESCRIPCIÓN

OSSL_LIB_CTX es un tipo de contexto de biblioteca interna de OpenSSL. Las aplicaciones pueden asignar las suyas propias, pero también pueden usar NULL para usar un contexto predeterminado con funciones que toman un argumento OSSL_LIB_CTX.

Cuando se utiliza un contexto de biblioteca no predeterminado, se debe tener cuidado con las aplicaciones multihilo para limpiar adecuadamente los recursos locales de hilo antes de liberar el OSSL_LIB_CTX. Consulte OPENSSL_thread_stop_ex(3) para obtener más información.

OSSL_LIB_CTX_new() crea un nuevo contexto de biblioteca OpenSSL.

OSSL_LIB_CTX_new_from_dispatch() crea un nuevo contexto de biblioteca OpenSSL inicializado para usar devoluciones de llamada de la estructura OSSL_DISPATCH. Esto es principalmente útil para los autores de proveedores. Los argumentos handle y estructura de despacho pasados deben ser los mismos que los pasados a la función OSSL_provider_init de un proveedor. Algunas funciones de OpenSSL, como BIO_new_from_core_bio(3), requieren que el contexto de la biblioteca se cree de esta manera para funcionar.

OSSL_LIB_CTX_new_child() solo es útil para los autores de proveedores y hace lo mismo que OSSL_LIB_CTX_new_from_dispatch() excepto que además vincula el nuevo contexto de biblioteca al contexto de biblioteca de la aplicación. El nuevo contexto de biblioteca es un contexto de biblioteca completo por derecho propio, pero tendrá todos los mismos proveedores disponibles que están disponibles en el contexto de biblioteca de la aplicación (sin tener que volver a cargarlos). Si la aplicación carga o descarga proveedores del contexto de biblioteca de la aplicación, esto se reflejará automáticamente en el contexto de biblioteca hijo.

Además, los proveedores que no están cargados en el contexto de biblioteca padre se pueden cargar explícitamente en el contexto de biblioteca hijo independientemente del contexto de biblioteca padre. Los proveedores cargados de forma independiente de esta manera no se reflejarán en el contexto de biblioteca padre y no se verán afectados si el contexto de biblioteca padre carga posteriormente el mismo proveedor.

Un proveedor puede llamar a la función OSSL_PROVIDER_load(3) con el contexto de biblioteca hijo según sea necesario. Si el proveedor ya existe debido a que se refleja desde el contexto de biblioteca padre, seguirá estando disponible y su recuento de referencias aumentará. Si se llama a OSSL_PROVIDER_load(3) de esta manera, posteriormente se debe llamar a OSSL_PROVIDER_unload(3) para decrementar el recuento de referencias. No se debe llamar a OSSL_PROVIDER_unload(3) para un proveedor en el contexto de biblioteca hijo que no tuvo una llamada anterior a OSSL_PROVIDER_load(3) para ese proveedor en ese contexto de biblioteca hijo.

Además de los proveedores, un contexto de biblioteca hijo también reflejará las propiedades predeterminadas (establecidas a través de EVP_set_default_properties(3)) del contexto de biblioteca padre. Si se llama directamente a EVP_set_default_properties(3) en un contexto de biblioteca hijo, las nuevas propiedades anularán cualquier cosa del contexto de biblioteca padre y se detendrá el reflejo de las propiedades.

Cuando se llama a OSSL_LIB_CTX_new_child() desde el ámbito de la función OSSL_provider_init de un proveedor, el proveedor que se está inicializando actualmente no está disponible en el contexto de biblioteca de la aplicación y, por lo tanto, tampoco estará disponible en el contexto de biblioteca hijo recién construido. Tan pronto como la función OSSL_provider_init devuelva, el nuevo proveedor estará disponible en el contexto de biblioteca de la aplicación y se reflejará de manera similar en el contexto de biblioteca hijo.

OSSL_LIB_CTX_load_config() carga un archivo de configuración utilizando el ctx dado. Esto se puede utilizar para asociar un contexto de biblioteca con los proveedores que se cargan desde una configuración. Esta función no debe llamarse simultáneamente desde múltiples hilos en un solo ctx.

OSSL_LIB_CTX_free() libera el ctx dado, a menos que resulte ser el contexto de biblioteca predeterminado de OpenSSL. Si el argumento es NULL, no se hace nada.

OSSL_LIB_CTX_get0_global_default() devuelve una referencia concreta (no NULL) al contexto de biblioteca predeterminado global.

OSSL_LIB_CTX_set0_default() establece el contexto de biblioteca predeterminado de OpenSSL como ctx en el hilo actual. Se devuelve el contexto de biblioteca predeterminado anterior. El llamador debe tener cuidado de restaurar el contexto de biblioteca predeterminado anterior con una llamada posterior a esta función. Si ctx es NULL, no se realiza ningún cambio en el contexto de biblioteca predeterminado, pero aún se devuelve un puntero al contexto de biblioteca actual. En una llamada exitosa de esta función, el valor devuelto siempre será un contexto de biblioteca concreto (no NULL).

Se debe tener cuidado al cambiar el contexto de biblioteca predeterminado e iniciar trabajos asíncronos (ver ASYNC_start_job(3)), ya que el contexto de biblioteca predeterminado cuando se inicia el trabajo se utilizará durante toda la vida útil de un trabajo asíncrono, sin importar cómo el hilo llamador realice más cambios en el contexto de biblioteca predeterminado mientras tanto. Esto significa que el hilo llamador no debe liberar el contexto de biblioteca que era el predeterminado al inicio del trabajo asíncrono antes de que ese trabajo haya terminado.

OSSL_LIB_CTX_get_data() devuelve una dirección de memoria cuya interpretación depende del índice. El argumento del índice se refiere a un miembro del contexto que se va a recuperar. Los valores del índice son todos privados para OpenSSL actualmente y, por lo tanto, las aplicaciones normalmente no deberían llamar a esta función. Si ctx es NULL, la función opera en el contexto de biblioteca predeterminado. OSSL_LIB_CTX_get_data() devuelve una dirección de memoria cuya interpretación depende del índice.

VALORES DE RETORNO

OSSL_LIB_CTX_new(), OSSL_LIB_CTX_get0_global_default() y OSSL_LIB_CTX_set0_default() devuelven un puntero al contexto de biblioteca en caso de éxito, o NULL en caso de error.

OSSL_LIB_CTX_free() no devuelve ningún valor.

OSSL_LIB_CTX_load_config() devuelve 1 en caso de éxito, 0 en caso de error.

OSSL_LIB_CTX_get_data() devuelve una dirección de memoria cuya interpretación depende del índice.

HISTORIAL

Todas las funciones descritas en esta página se agregaron en OpenSSL 3.0.

OSSL_LIB_CTX_get_data() se introdujo en OpenSSL 3.4.
