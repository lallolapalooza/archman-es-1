NAME

Locale::Po4a::Man - convert man pages from text to PO

DESCRIPTION

The po4a project aims at making translations (and more interestingly, the maintenance of these translations) easier, using the gettext tools in areas where they were not expected to be.

Locale::Po4a::Man is a module to help with the translation of documents in nroff format (man page language) to other human languages.

TRANSLATING WITH PO4A::MAN

This module tries to make the translator's life easier. To achieve this, the text shown to the translator is not a literal copy of the text found in the man page. In fact, the crudest parts of the nroff formatting are hidden, so that the translator cannot possibly break them.

Text justification

Unindented paragraphs are automatically re-justified for the translator. This may lead to small differences in the final output, as the justification rules used by groff are not very clear. For example, two spaces after a parenthesis may be kept.

However, the difference will only be about the position of extra spaces in a justified paragraph, and I think it is worth it.

Font specifications

The first modification is about font specifications. In nroff, there are several ways to specify if a given term should be written in small, bold, or italic. In the text to be translated, there is only one way, borrowed from the POD (Plain Old Documentation) format:

I<text> -- italic text
equivalent to \fItext\fP or ".I text"
B<text> -- bold text
equivalent to \fBtext\fP or ".B text"
R<text> -- Roman text
equivalent to \fRtext\fP
CW<text> -- constant width text
equivalent to \f(CWtext\fP or ".CW text"

Note: the CW style is not available on some groff devices. Its use is not recommended. It is available for your convenience.

Automatic character translations

Po4a automatically translates some characters to ease translation or translation review. Here is the list of translations:

hyphens
Hyphens (-) and minus signs (\-) in man pages are translated as simple hyphens (-) in the PO file. Then, when the translation is inserted into the output document, all hyphens are translated into roff minus signs (\-).
non-breaking spaces
Translators may use non-breaking spaces in their translations. These non-breaking spaces (0xA0 in latin1) are translated into roff non-breaking spaces ('\ ').
quotes transliterations
The "" and '' characters are translated as \*(lq and \*(rq.
To prevent these translations, translators may insert a roff zero-width character (i.e. using `\&` or `\&` respectively).

Inserting '<' and '>' in translations

Since these characters are used to delimit parts under font modification, you cannot use them literally. Use E<lt> and E<gt> instead (as in POD, by the way).

OPTIONS ACCEPTED BY THIS MODULE

These are the options specific to this module:

debug
Turns on debugging of some internal mechanisms of the module. Use the source code to see which parts can be debugged.
verbose
Increases verbosity.
groff_code
This option controls the behaviour of the module when it detects a .de, .ie, or .if section. It may take the following values:
fail
This is the default value. The module will fail when a .de, .ie, or .if section is detected.
verbatim
Tells that .de, .ie, or .if sections must be copied as-is from the original to the translated document.
translate
Tells that .de, .ie, or .if sections will be proposed for translation. You should use this option only if there is a translatable string in one of these sections. Otherwise, the verbatim mode is recommended.
generated
This option indicates that the file was generated, and that po4a will not try to detect whether the man pages were generated from another format. This option is mandatory for using po4a on generated man pages. Note: translating generated man pages instead of the sources is often more fragile, and therefore not a good idea.
mdoc
This option is useful only for mdoc pages.
This option selects a stricter support of the mdoc format, telling po4a not to translate the NAME section. Mdoc pages whose NAME is translated will not produce any header or footer.
According to the groff_mdoc page, the NAME, SYNOPSIS, and DESCRIPTION sections are mandatory. There are no known issues with translated SYNOPSIS or DESCRIPTION sections, but you may also specify these sections like this:
-o mdoc=NAME,SYNOPSIS,DESCRIPTION
This mdoc issue might also be solved with an addendum like:
PO4A-HEADER:mode=before;position=^.Dd
.TH DOCUMENT_TITLE 1 "Month day, year" OS "Section Name"

The following options specify the behavior of a user-defined macro (with a .de request) or a classic macro not supported by po4a. They take a comma-separated list of macros as argument. For example:

-o noarg=FO,OB,AR -o translate_joined=BA,ZQ,UX

Note: if a macro is not supported by po4a and you consider it is a standard roff macro, you should use & instead.

Locale::Po4a::Man - Po4a manual pages

NAME

Locale::Po4a::Man - Po4a manual pages

DESCRIPTION

The po4a (po for anything) project goal is to help translating documentation from any format into any other format. To do so, it uses the PO file format, that is widely used in software translation.

This module handles the man pages. The most common format is the nroff/troff format used in Unix systems. We parse these files and extract the strings that have to be translated.

The main idea is that authors of man pages often use macro definitions that are not necessarily a part of the text and should not be translated.

For example, in ls man page, the command name ls is written using macro Nm like this: Nm ls. We don't want translators to translate ls. It's the name of the command. That's why we have a list of macros that won't be translated, or that will be translated differently.

If you are a translator, po4a will give you a PO file which contains the strings to be translated. You'll be able to use your favorite PO file editor, like gtranslator, ktranslator, or even vim with the appropriate plugin.

If you are an author of man pages, you might want to ensure that your man page can be translated by po4a. This implies that you should avoid some specific nroff macros or programming constructs.

See the AUTHORING MAN PAGES COMPLIANT WITH PO4A::MAN section for more details.

If you are the person in charge of the translation workflow, po4a provides scripts that will help you manage the translation process. You'll have to call po4a-translate.

This module should be called by the po4a-translate script. You should not call it directly. For example, to translate a man page named my_man_page.1, you would run: po4a-translate -m my_man_page.1 -l fr

This module is a plugin for po4a-translate. It's not a standalone script. If you want to add new features to this module, you should submit it to the po4a development team.

untranslated
untranslated indica que esta macro (en sus argumentos) no tiene que ser traducida.
noarg
noarg es como untranslated, excepto que po4a verificará que no se añadan argumentos a esta macro.
translate_joined
translate_joined indica que po4a debe proponer traducir los argumentos de la macro.
translate_each
Con translate_each, los argumentos también se propondrán para la traducción, excepto que cada uno se traducirá por separado.
no_wrap
Esta opción toma como argumento una lista de parejas separadas por comas begin:end, donde begin y end son comandos que delimitan el inicio y el fin de una sección que no debe ser reajustada.

Nota: no se realiza ninguna prueba para asegurar que un comando end coincida con su comando begin; cualquier comando de finalización detiene el modo no_wrap. Si tiene una macro begin (respectivamente end) que no tiene end (respectivamente begin), puede especificar un end (como fi) o begin (como nf) existente como contraparte. Estas macros (y sus argumentos) no serán traducidas.

inline
Esta opción especifica una lista de macros separadas por comas que no deben dividir el párrafo actual. La cadena a traducir contendrá entonces foo <.bar baz qux> quux, donde bar es el comando que debería ser incrustado, y baz qux sus argumentos.
unknown_macros
Esta opción indica cómo debe comportarse po4a cuando se encuentra una macro desconocida. Por defecto, po4a falla con una advertencia. Puede tomar los siguientes valores: failed (el valor por defecto), untranslated, noarg, translate_joined, o translate_each (ver arriba para una explicación de estos valores).

AUTHORING MAN PAGES COMPLIANT WITH PO4A::MAN

Este módulo todavía es muy limitado, y siempre lo será, porque no es un intérprete nroff real. Sería posible hacer un intérprete nroff real, para permitir a los autores usar todas las macros existentes, o incluso definir nuevas en sus páginas, pero no queríamos hacerlo. Sería demasiado difícil, y pensamos que no era necesario. Creemos que si los autores de páginas man quieren ver sus producciones traducidas, puede que tengan que adaptarse para facilitar el trabajo de los traductores.

Por lo tanto, el analizador de man implementado en po4a tiene algunas limitaciones conocidas que no estamos realmente inclinados a corregir, y que constituirán algunas trampas que tendrá que evitar si quiere que los traductores se encarguen de su documentación.

Don't program in nroff

nroff es un lenguaje de programación completo, con definición de macros, condicionales y demás. Dado que este analizador no es un intérprete nroff con todas las funciones, fallará en páginas que utilicen estas funcionalidades (Hay unas 200 páginas de este tipo en mi equipo).

Use the plain macro set

Todavía hay algunas macros que no son compatibles con po4a::man. Esto se debe únicamente a que no he podido encontrar ninguna documentación sobre ellas. Aquí está la lista de macros no compatibles utilizadas en mi equipo. Tenga en cuenta que esta lista no es exhaustiva, ya que el programa falla ante la primera macro no compatible encontrada. Si tiene alguna información sobre alguna de estas macros, con gusto añadiré soporte para ellas. Debido a estas macros, unas 250 páginas en mi equipo son inaccesibles para po4a::man.

..               ."              .AT             .b              .bank
.BE              ..br            .Bu             .BUGS           .BY
.ce              .dbmmanage      .do                             .En
.EP              .EX             .Fi             .hw             .i
.Id              .l              .LO             .mf
.N               .na             .NF             .nh             .nl
.Nm              .ns             .NXR            .OPTIONS        .PB
.pp              .PR             .PRE            .PU             .REq
.RH              .rn             .S<             .sh             .SI
.splitfont       .Sx             .T              .TF             .The
.TT              .UC             .ul             .Vb             .zZ

Hiding text from po4a

A veces, el autor sabe que algunas partes no son traducibles y no deberían ser extraídas por po4a. Por ejemplo, una opción puede aceptar un argumento other, y other también puede aparecer como el último elemento de una lista. En el primer caso, other no debería ser traducible. Y en el segundo caso, other debería ser traducido.

En tal caso, el autor puede evitar que po4a extraiga algunas cadenas, utilizando algunas construcciones especiales de groff:

.if !'po4a'hide' .B other

(esto requerirá la opción -o groff_code=verbatim)

También se puede definir una nueva macro para automatizar esto:
.de IR_untranslated
. IR \\$@
..

.IR_untranslated \-q ", " \-\-quiet

(esto requerirá las opciones -o groff_code=verbatim y -o untranslated=IR_untranslated; con esta construcción, la condición .if !'po4a'hide' no es estrictamente necesaria ya que po4a no analizará el interior de la definición de la macro)

o usando un alias:
.als IR_untranslated IR

.IR_untranslated \-q ", " \-\-quiet

Esto requerirá la opción -o untranslated=als,IR_untranslated.

Conclusion

Para resumir esta sección, sea simple y no intente ser ingenioso al escribir sus páginas man. Muchas cosas son posibles en nroff y no son soportadas por este analizador. Por ejemplo, no intente jugar con \c para interrumpir el procesamiento de texto (como lo hacen 40 páginas en mi equipo). O, asegúrese de poner los argumentos de la macro en la misma línea que la macro misma. Sé que es válido en nroff, pero complicaría demasiado el analizador para poder manejarlo.

Por supuesto, otra posibilidad es usar otro formato, más amigable para el traductor (como POD usando po4a::pod, o una de la familia XML como SGML), pero gracias a po4a::man ya no es necesario. Dicho esto, si el formato fuente de su documentación es POD o XML, puede ser inteligente traducir el formato fuente y no este generado. En la mayoría de los casos, po4a::man detectará las páginas generadas y emitirá una advertencia. Incluso se negará a procesar páginas generadas desde POD, porque esas páginas son perfectamente manejadas por po4a::pod, y porque su contraparte nroff define muchas macros nuevas para las que no quería escribir soporte. En mi equipo, 1432 de las 4323 páginas están generadas desde POD y serán ignoradas por po4a::man.

En la mayoría de los casos, po4a::man detectará el problema y se negará a procesar la página, emitiendo un mensaje adaptado. En algunos casos raros, el programa se completará sin advertencia, pero la salida será incorrecta. Tales casos se llaman "bugs" ;) Si se encuentra con tal caso, asegúrese de informarlo, junto con una corrección cuando sea posible...

STATUS OF THIS MODULE

Este módulo se puede utilizar para la mayoría de las páginas man existentes.

Se ejecutan pruebas regularmente en equipos Linux:

  • un tercio de las páginas son rechazadas porque fueron generadas a partir de otro formato compatible con po4a (por ejemplo, POD o SGML).
  • el 10% de las páginas restantes son rechazadas con un error (por ejemplo, una macro groff no es compatible).
  • Luego, menos del 1% de las páginas son aceptadas silenciosamente por po4a, pero con problemas significativos (es decir, palabras faltantes o inserción de nuevas palabras).
  • Las otras páginas generalmente se manejan sin diferencias más importantes que diferencias de espaciado o reajuste de líneas (problemas de fuente en menos del 10% de las páginas procesadas).
