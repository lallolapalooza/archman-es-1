NOMBRE

Locale::Po4a::TeX — convertir documentos de TeX y derivados de PO files

DESCRIPCIÓN

El proyecto po4a (PO para cualquier cosa) tiene como objetivo facilitar las traducciones (y más interesante, la mantención de las traducciones) usando herramientas de gettext en áreas donde no se esperaban como la documentación.

Locale::Po4a::TeX es un módulo para ayudar a la traducción de documentos de TeX a otros [idiomas humanos]. También puede usarse como base para construir módulos para documentos de TeX.

Los usuarios probablemente deberían usar el módulo LaTeX, que hereda de este módulo y contiene las definiciones de comandos comunes de LaTeX.

TRADUCIR CON PO4A::TEX

Este módulo puede usarse directamente para manejar documentos genéricos de TeX. Esto dividirá tu documento en bloques más pequeños (párrafos, bloques verbatim, o incluso más pequeños como títulos o índices).

Hay algunas opciones (descritas en la siguiente sección) que pueden personalizar este comportamiento. Si esto no se ajusta a tu formato de documento, te animamos a escribir tu propio módulo derivado de este, para describir los detalles de tu formato. Véase la sección ESCRIBIR MÓDULOS DERIVADOS a continuación, para una descripción del proceso.

Este módulo también puede personalizarse mediante líneas que empiecen con "% po4a:" en el archivo TeX. Este proceso se describe en la sección PERSONALIZACIÓN DE INLINED.

OPCIONES ACEPTRADAS POR ESTE MÓDULO

Estas son las opciones particulares de este módulo:

debug
Activa el depurado de algunos mecanismos internos de este módulo. Usa el código fuente para ver qué partes pueden ser depuradas.
no_wrap
Lista separada por comas de entornos que no deben ser re-embutidos.

Nota que existe una diferencia entre verbatim y no_wrap. No hay análisis de comandos y comentarios en bloques verbatim.

Si este entorno no estaba ya registrado, po4a considerará que este entorno no toma parámetros.

exclude_include
Lista separada por colones de archivos que no deben ser incluidos por \input y \include.
definitions
Nombre de un archivo que contiene definiciones para po4a, como se describe en la sección PERSONALIZACIÓN DE INLINED. Puedes usar esta opción si no es posible poner las definiciones en el documento que se está traduciendo.
verbatim
Lista separada por comas de entornos que deben ser tomados como verbatim.

Si este entorno no estaba ya registrado, po4a considerará que este entorno no toma parámetros.

Usa estas opciones para sobrescribir el comportamiento por defecto de los comandos definidos.

PERSONALIZACIÓN DE INLINED

El módulo TeX puede personalizarse con líneas que empiecen con % po4a: . Estas líneas se interpretan como comandos para el analizador. Los siguientes comandos se reconocen:

% po4a: command command1 alias command2
Indica que los argumentos de command1 deben tratarse como los argumentos de command2.
% po4a: command command1 parameters
Describe en detalle los parámetros de command1. Esta información se usará para verificar el número de argumentos y su tipo.

Puedes preceder a command1 con

un asterisco (*)
po4a extraerá este comando de párrafos (si está en el comienzo o el final de un párrafo). Los traductores tendrán que traducir los parámetros que se marcan como translatable.
un más (+)
Como en el caso de un asterisco, el comando será extraído si aparezca en un extremo de un bloque, pero los parámetros no se traducirán por separado. El traductor tendrá que traducir el comando concatenado a todos sus parámetros. Esto mantiene más contexto y es útil para comandos con palabras en parámetro pequeñas, que pueden tener múltiples significados (y traducciones).

Nota: En este caso no tienes que especificar cuáles parámetros son translatable, pero po4a debe saber el tipo y número de parámetros.

un menos (-)
En este caso, el comando no será extraído de ningún bloque. Pero si aparece solo en un bloque, solo los parámetros marcados como translatable se presentarán al traductor. Esto es útil para comandos de fuente. Estos comandos generalmente no deben estar separados de su párrafo (para mantener el contexto), pero no hay razón para molestar al traductor con ellos si una cadena completa está encerrada en tal comando.

Los parámetros parameters es una lista de [] (para un argumento opcional) o {} (para un argumento obligatorio). Puedes colocar un _ (underscore) entre estos paréntesis para indicar que el parámetro debe traducarse. Por ejemplo:
% po4a: command *chapter [_]{_}

Esto indica que el comando chapter tiene dos parámetros: un opcional (título corto) y obligatorio, ambos deben traducirse. Si quieres indicar que el comando href tiene dos parámetros obligatorios, que no quieres traducir el URL (primero parámetro) y que no quieres que este comando sea separado de su párrafo (lo que permite al traductor mover el enlace en la oración), puedes usar:
% po4a: command -href {}{_}

En este caso, la información indicando qué parámetros deben traducirse solo se usará si el párrafo está compuesto solo de este comando href.

% po4a: environment env parameters
Define los parámetros aceptados por el entorno env y especifica los que deben traducirse. Esta información se usará más tarde para verificar el número de argumentos de la comanda \begin. El formato de los parámetros parameters es el mismo que se describe para otros comandos. El primer argumento de la comanda \begin es el nombre del entorno. Este parámetro no debe especificarse en la lista de parámetros. Aquí hay algunos ejemplos:
% po4a: environment multicols {}
% po4a: environment equation

Como para los comandos, env puede precederse por un + (+) para indicar que la comanda \begin debe traducirse con todos sus argumentos.

% po4a: separator env "regex"
Indica que un entorno debe ser dividido según el patrón regular especificado.

El patrón regular está delimitado por comillas. Debe tener en cuenta que el patrón se usa para separar los entornos.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

no pude crear ninguna referencia posterior. Debería usar (?:) si necesita un grupo. También puede necesitar algunos escapes.

Por ejemplo, el módulo LaTeX usa la expresión regular "(?:&|\\\\)" para traducir por separado cada celda de una tabla (las líneas se separan por '\\' y las celdas por '&').

La noción de entorno se amplía al tipo que se muestra en el archivo PO. Esto se puede utilizar para dividir por "\\\\" en el primer argumento obligatorio del comando de título. En este caso, el entorno es title{#1}.

% po4a: entorno verbatim env
Indicar que env es un entorno verbatim. Los comentarios y comandos serán ignorados en este entorno.

Si este entorno no estaba registrado previamente, po4a considerará que este entorno no toma ningún parámetro.

ESCRITURA DE MÓDULOS DERIVADOS

pre_trans
post_trans
add_comment
Añadir una cadena como comentario que se añadirá alrededor del siguiente elemento traducido. Esto es útil principalmente para el módulo texinfo, ya que los comentarios se manejan automáticamente en TeX.
translate
Envoltorio alrededor del translate de Transtractor, con filtros de pre- y post-procesamiento.

Los comentarios de un párrafo se insertan como comentario PO para la primera cadena traducida de este párrafo.

get_leading_command($buffer)
Esta función devuelve:
Un nombre de comando
Si no se encuentra ningún comando al principio del búfer dado, esta cadena estará vacía. Solo se consideran los comandos que se pueden separar. El hash %separated_command contiene la lista de estos comandos.
Una variante
Esto indica si se utiliza una variante. Por ejemplo, un asterisco (*) puede añadirse al final de los comandos de sección para especificar que no deben numerarse. En este caso, este campo contendrá "*". Si no hay variante, el campo es una cadena vacía.
Un array de tuplas (tipo de argumento, argumento)
El tipo de argumento puede ser '{' (para argumentos obligatorios) o '[' (para argumentos opcionales).
El búfer restante
El resto del búfer después de la eliminación de este comando inicial y sus argumentos. Si no se encuentra ningún comando, el búfer original no se modifica y se devuelve en este campo.
get_trailing_command($buffer)
Lo mismo que get_leading_command, pero para comandos al final de un búfer.
translate_buffer
Traduce recursivamente un búfer separando los comandos iniciales y finales (aquellos que deben traducirse por separado) del búfer.

Si hay definida una función en %translate_buffer_env para el entorno actual, se utilizará esta función para traducir el búfer en lugar de translate_buffer().

read
Sobrescribe el read() de Transtractor.
read_file
Lee recursivamente un archivo, añadiendo los archivos incluidos que no están listados en el array @exclude_include. Los archivos incluidos se buscan utilizando el comando kpsewhich de la biblioteca Kpathsea.

Excepto por la parte de inclusión de archivos, es un cortar y pegar de la lectura de Transtractor.

parse_definition_file
Subrutina para analizar un archivo con directivas po4a (definiciones para nuevos comandos).
parse_definition_line
Analiza una línea de definición del tipo "% po4a: ".

Ver la sección PERSONALIZACIÓN EN LÍNEA para más detalles.

FUNCIONES INTERNAS utilizadas para escribir analizadores derivados

Las funciones de comando y entorno toman los siguientes argumentos (además del objeto $self):

Un nombre de comando
Una variante
Un array de tuplas (tipo, argumento)
El entorno actual

Los 3 primeros argumentos son extraídos por get_leading_command o get_trailing_command.

Las funciones de comando y entorno devuelven la traducción del comando con sus argumentos y un nuevo entorno.

Las funciones de entorno se llaman cuando se encuentra un comando \begin. Se llaman con el comando \begin y sus argumentos.

El módulo TeX solo propone una función de comando y una función de entorno: generic_command y generic_environment.

generic_command utiliza la información especificada por register_generic_command o añadiendo definiciones al archivo TeX:
% po4a: command command1 parameters

generic_environment utiliza la información especificada por register_generic_environment o añadiendo definiciones al archivo TeX:
% po4a: environment env parameters

Ambas funciones solo traducirán los parámetros que se especificaron como traducibles (con un '_'). generic_environment añadirá el nombre del entorno a la pila de entornos y generic_command añadirá el nombre del comando seguido de un identificador del parámetro (como {#7} o [#2]).

Locale::Po4a::TeX

NAME

Locale::Po4a::TeX - Maneja la traducción de archivos TeX

SYNOPSIS

use Locale::Po4a::TeX;

DESCRIPTION

Locale::Po4a::TeX es una clase que hereda de Locale::Po4a::Common para manejar la traducción de archivos TeX.

Esta clase se encarga de extraer las cadenas traducibles de un archivo TeX y de reinsertar las traducciones en el archivo original.

Se utiliza principalmente a través de la herramienta po4a.

EXAMPLE

Para traducir un archivo TeX llamado document.tex a español, se usaría el siguiente comando:

po4a --format tex --lang es document.tex

Esto generará un archivo document.po que contiene las cadenas traducibles. Una vez traducidas las cadenas en el archivo .po, se puede regenerar el archivo traducido con:

po4a --format tex --lang es document.tex --update-po
