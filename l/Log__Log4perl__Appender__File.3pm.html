Nombre

Log::Log4perl::Appender::File - Escribe en un archivo

SINTAXIS

use Log::Log4perl::Appender::File;
my $app = Log::Log4perl::Appender::File->new(
  filename  => 'file.log',
  mode      => 'append',
  autoflush => 1,
  umask     => 0222,
);
$file->log(message => "Log me\n");

DESCRIPCIÓN

Este es un apuntador simple para escribir en un archivo.

El método log() toma un único escalar. Si se requiere un carácter de nueva línea al final del mensaje, debe ser añadido explícitamente.

Al destruir el objeto, el manejador de archivo para acceder al archivo se vacía y se cierra.

Si deseas cambiar a un nuevo archivo de registro, usa el método file_switch($newfile) que primero cierra el manejador de archivo del archivo antiguo y luego abre uno nuevo para el archivo especificado.

OPCIONES

nombre del archivo
Nombre del archivo de registro.
modo
Los mensajes se añaden al archivo si $mode está configurado como "append". Si está configurado como "clobber", el archivo se sobrescribirá. Si es "pipe", el archivo se interpretará como ejecutable para pasar la salida a una tubería. El modo predeterminado es "append".
autoflush
"autoflush", si se establece a un valor verdadero, activa el vaciado de los datos al archivo cada vez que se llama al método log(). "autoflush" está activo por defecto.
syswrite
"syswrite", si se establece a un valor verdadero, asegura que el apuntador use syswrite() en lugar de print() para registrar el mensaje. syswrite() generalmente se mapea a la función write() del sistema operativo y asegura que ningún otro proceso escriba en el mismo archivo mientras write() está ocupado. Puede ser más seguro que no tengas que usar medidas de sincronización como semáforos (ver: Appender sincronizado).
umask
Establece el "umask" a usar cuando se cree el archivo, determinando los permisos del archivo. Si se establece a 0022 (por defecto), los archivos nuevos tendrán permisos "rw-r--r--". Si se establece a 0000, los archivos nuevos tendrán permisos "rw-rw-rw-".
propietario
Si se establece, indica que el propietario del nuevo archivo de registro debe ser diferente del usuario actual del proceso que ejecuta el programa. Esto solo tiene sentido si el proceso se está ejecutando como root. Tanto los valores numéricos como los nombres de usuario son aceptables. Log4perl no intenta cambiar el propietario de archivos existentes.
grupo
Si se establece, indica que el grupo del nuevo archivo de registro debe ser diferente del grupo actual del proceso que ejecuta el programa. Esto solo tiene sentido si el proceso se está ejecutando como root. Tanto los valores numéricos como los nombres de grupo son aceptables. Log4perl no intenta cambiar la membresía del grupo de archivos existentes.
utf8
Si estás imprimiendo cadenas Unicode, el archivo de salida debe estar configurado en modo ":utf8": 
my $app = Log::Log4perl::Appender::File->new(
  filename  => 'file.log',
  mode      => 'append',
  utf8      => 1,
);
binmode
Para manipular el manejador de salida usando binmode(), usa el parámetro binmode: 
my $app = Log::Log4perl::Appender::File->new(
  filename  => 'file.log',
  mode      => 'append',
  binmode   => ":utf8",
);

Un valor de ":utf8" para "binmode" es equivalente a especificar el parámetro "utf8" (ver arriba).

recreate
Normalmente, si un apuntador de archivo escribe en un archivo y este archivo se mueve a una ubicación diferente (por ejemplo, mediante "mv"), el manejador de archivo del apuntador seguirá automáticamente la nueva ubicación.

Esto puede ser indeseable. Cuando se usa un rotador de archivos externo, el apuntador debería crear un nuevo archivo con el nombre antiguo y comenzar a escribir en él. Si el valor de "recreate" está establecido a un valor verdadero, "Log::Log4perl::Appender::File" hará exactamente eso. Por defecto, es falso. Verifica la opción "recreate_check_interval" para optimizar el rendimiento con esta característica.

recreate_check_interval
En modo "recreate", el apuntador debe verificar continuamente si el archivo en el que está escribiendo sigue en la misma ubicación. Esta verificación es relativamente costosa, ya que requiere llamar a "stat" en el nombre del archivo y determinar si su inodo ha cambiado. Hacer esto en cada llamada a "log() puede ser prohibitivamente costoso. Establecerlo a un valor entero positivo N verificará el archivo solo cada N segundos. Por defecto, es 30.

Evidentemente, el apuntador seguirá escribiendo en un archivo movido hasta que ocurra la próxima verificación; en el peor de los casos, esto puede suceder "recreate_check_interval" segundos después de que el archivo haya sido movido o eliminado. Si esto es indeseable, establecer "recreate_check_interval" a 0 hará que el apuntador verifique el archivo en cada llamada a "log().

recreate_check_signal
En modo "recreate", si esta opción se establece a un nombre de señal (por ejemplo, "USR1"), el apuntador recreará un archivo de registro faltante cuando reciba la señal. Consume menos recursos que el sondeo constante. Se aplican las limitaciones comunes con el manejo de señales en Perl. Ver la FAQ para usar esta opción con la utilidad de rotación de logs "newsyslog".
recreate_pid_write
La popular utilidad de rotación de logs "newsyslog" espera un archivo PID para enviar una señal al programa cuando sus logs hayan sido rotados. Esta opción espera una ruta a un archivo donde se escribirá el PID del programa actual. Ver la FAQ para usar esta opción con la utilidad de rotación de logs "newsyslog".
create_at_logtime
El apuntador de archivo típicamente crea su archivo de registro en su constructor, es decir, al tiempo de inicialización de Log4perl init(). Esto es deseable para casi todos los casos, ya que asegura que los problemas de permisos se detecten inmediatamente, y no después de días/semanas/meses de operación, cuando el apuntador de archivo necesita registrar algo y falla debido a un problema evidente al inicio.

Sin embargo, hay casos raros en los que el archivo no debe crearse al tiempo de inicialización de Log4perl init(), por ejemplo, si el apuntador no puede ser usado por el usuario actual aunque esté definido en el archivo de configuración. Si se establece "create_at_logtime" a un valor verdadero, el apuntador de archivo intentará crear el archivo en el momento del log. A tener en cuenta que este ajuste permite que los problemas de permisos se ignoren hasta el momento del log, lo cual puede ser indeseable.

NOMBRE

Log::Log4perl::Appender::File - Un appender que escribe en un archivo.

SINOPSIS

  use Log::Log4perl qw(:easyout);

  # Escribe en /var/log/myapp.log
  my $logger = get_logger();
  ERROR $logger, "This is an error message";

  use Log::Log4perl qw(init_with_config);

  my $conf = q(
    log4perl.rootLogger=DEBUG, File

    log4perl.appender.File=Log::Log4perl::Appender::File
    log4perl.appender.File.filename=/var/log/myapp.log
    log4perl.appender.File.layout=Pattern
    log4perl.appender.File.layout.pattern=%d{yyyy-MM-dd HH:mm:ss} %p %m %n
  );
  init_with_config($conf);

  my $logger = get_logger();
  INFO $logger, "Starting application...";

DESCRIPCIÓN

Este appender escribe los mensajes de log en un archivo especificado. Puede crear el archivo si no existe. Los permisos del archivo se pueden controlar con el parámetro mkpath_umask.

path
El nombre del archivo de log. Si se especifica una ruta, se usará esa ruta para crear el archivo de log.
create_parent_dirs
Si se establece en verdadero, el directorio padre será creado si no existe ya.
mkpath
Si esta opción se establece en verdadero, la ruta del directorio se creará si aún no existe.
mkpath_umask
Especifica el "umask" a usar al crear el directorio, determinando la configuración de permisos del directorio. Si se establece en 0022 (predeterminado), el nuevo directorio se creará con permisos "rwxr-xr-x". Si se establece en 0000, el nuevo directorio se creará con permisos "rwxrwxrwx".

El diseño e implementación de este módulo se ha inspirado en gran medida en el framework de appender "Log::Dispatch" de Dave Rolsky.
