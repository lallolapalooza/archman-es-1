NOMBRE

Log::Log4perl::Appender::Synchronized - Sincronización de otros appenders

SINOPSIS

    use Log::Log4perl qw(:easy);
    my $conf = qq(
    log4perl.category                   = WARN, Syncer

        # Appender de archivo (no sincronizado)
    log4perl.appender.Logfile           = Log::Log4perl::Appender::File
    log4perl.appender.Logfile.autoflush = 1
    log4perl.appender.Logfile.filename  = test.log
    log4perl.appender.Logfile.mode      = truncate
    log4perl.appender.Logfile.layout    = SimpleLayout

        # Appender de sincronización, usando el appender de archivo anterior
    log4perl.appender.Syncer            = Log::Log4perl::Appender::Synchronized
    log4perl.appender.Syncer.appender   = Logfile
);
    Log::Log4perl->init(\$conf);
    WARN("Este mensaje está garantizado que esté completo.");

DESCRIPCIÓN

Si varios procesos utilizan el mismo appender de "Log::Log4perl" sin sincronización, pueden ocurrir sobrescrituras. Un escenario típico para esto sería un proceso que genera hijos, cada uno de los cuales hereda la configuración Log::Log4perl del padre.

En la mayoría de los casos, no necesitará una herramienta de sincronización externa como Log::Log4perl::Appender::Synchronized en absoluto. El appender de archivo de Log4perl, Log::Log4perl::Appender::File, por ejemplo, proporciona el mecanismo "syswrite" para asegurar que incluso las líneas de registro largas no se intercalen. Las líneas de registro cortas no se intercalarán de todos modos, ya que el sistema operativo se asegura de que la línea se escriba antes de que ocurra un cambio de tarea.

Sin embargo, en los casos en que necesite sincronización adicional, puede usar "Log::Log4perl::Appender::Synchronized" como una puerta de enlace entre sus loggers y sus appenders. Un appender en sí, "Log::Log4perl::Appender::Synchronized" simplemente toma dos argumentos adicionales:

"appender"
Especifica el nombre del appender que sincroniza el acceso a él. El appender especificado debe definirse en algún lugar del archivo de configuración, no necesariamente antes de la definición de "Log::Log4perl::Appender::Synchronized".
"key"
Este argumento opcional especifica la clave para el semáforo que "Log::Log4perl::Appender::Synchronized" utiliza internamente para garantizar operaciones atómicas. Por defecto es "_l4p". Si define más de un appender "Log::Log4perl::Appender::Synchronized", es importante especificar claves diferentes para ellos, ya que de lo contrario cada nuevo appender "Log::Log4perl::Appender::Synchronized" eliminará semáforos definidos previamente. La longitud máxima de la clave es de cuatro caracteres, las claves más largas se truncarán a 4 caracteres: "mylongkey1" y "mylongkey2" se interpretan como lo mismo: "mylo" (gracias a David Viner <dviner@yahoo-inc.com> por señalar esto).

"Log::Log4perl::Appender::Synchronized" utiliza Log::Log4perl::Util::Semaphore internamente para realizar bloqueos con semáforos proporcionados por el sistema operativo utilizado.

Consejos de rendimiento

La "Log::Log4perl::Appender::Synchronized" serializa el acceso a un recurso protegido globalmente, ralentizando las acciones que de otro modo se realizarían en paralelo.

A menos que se especifique lo contrario, todas las instancias de objetos "Log::Log4perl::Appender::Synchronized" en el sistema utilizarán la misma clave IPC global "_l4p".

Para controlar el acceso a diferentes instancias de appender, a menudo tiene sentido definir claves diferentes para diferentes appenders sincronizados. De esta manera, Log::Log4perl serializa el acceso a cada instancia de appender por separado:

log4perl.category                   = WARN, Syncer1, Syncer2

    # Appender de archivo 1 (no sincronizado)
log4perl.appender.Logfile1           = Log::Log4perl::Appender::File
log4perl.appender.Logfile1.filename  = test1.log
log4perl.appender.Logfile1.layout    = SimpleLayout

    # Appender de archivo 2 (no sincronizado)
log4perl.appender.Logfile2           = Log::Log4perl::Appender::File
log4perl.appender.Logfile2.filename  = test2.log
log4perl.appender.Logfile2.layout    = SimpleLayout

    # Appender de sincronización, usando el appender de archivo anterior
log4perl.appender.Syncer1            = Log::Log4perl::Appender::Synchronized
log4perl.appender.Syncer1.appender   = Logfile1
log4perl.appender.Syncer1.key        = l4p1
    # Appender de sincronización, usando el appender de archivo anterior
log4perl.appender.Syncer2            = Log::Log4perl::Appender::Synchronized
log4perl.appender.Syncer2.appender   = Logfile2
log4perl.appender.Syncer2.key        = l4p2

Sin las líneas ".key = l4p1" y ".key = l4p2", ambos appenders Sincronizados utilizarían la clave predeterminada "_l4p", lo que provocaría una serialización innecesaria de la salida escrita en archivos diferentes.

Configuración avanzada

Para configurar el módulo subyacente Log::Log4perl::Util::Semaphore de una manera diferente a la configuración predeterminada proporcionada por Log::Log4perl::Appender::Synchronized, utilice los siguientes parámetros:

log4perl.appender.Syncer1.destroy  = 1
log4perl.appender.Syncer1.mode     = sub { 0775 }
log4perl.appender.Syncer1.uid      = hugo
log4perl.appender.Syncer1.gid      = 100

Las opciones válidas son "destroy" (Eliminar el semáforo al salir), "mode" (permisos en el semáforo), "uid" (uid o nombre de usuario al que pertenece el semáforo) y "gid" (id de grupo al que pertenece el semáforo).

Tenga en cuenta que "mode" se proporciona normalmente en octal y, por lo tanto, debe especificarse como una subrutina de Perl {}, a menos que desee calcular lo que 0755 significa en decimal.

Cambiar la configuración de propiedad o grupo de un semáforo obviamente solo funcionará si el usuario actual es propietario del semáforo ya o si el usuario actual es "root". La opción "destroy" hace que el proceso actual destruya el semáforo al salir. Los hijos generados del proceso no heredarán este comportamiento.

IDs de usuario y grupo de semáforo con mod_perl

Establecer IDs de usuario y grupo es especialmente importante cuando el appender Sincronizado se utiliza con mod_perl. Si Log4perl se inicializa mediante un manejador de inicio, que se ejecuta como root, y no como el usuario que utilizará el semáforo posteriormente, la configuración de uid, gid y mode puede ayudar a establecer una propiedad y derechos de acceso de semáforo coincidentes.

NOTAS DE DESARROLLO

"Log::Log4perl::Appender::Synchronized" es un appender *compuesto*. A diferencia de otros appenders, no registra ningún mensaje, solo los pasa a su sub-appenders adjunto. Por esta razón, no necesita un layout (a diferencia de los appenders normales). Si no define ninguno, los mensajes se pasan sin alterar.

Los filtros personalizados también se aplican solo al appender compuesto. *No* se aplican al sub-appenders. Lo mismo se aplica a los umbrales del appender. Este comportamiento puede cambiar en el futuro.
