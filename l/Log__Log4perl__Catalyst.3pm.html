NAME

Log::Log4perl::Catalyst - Módulo Catalyst de Log::Log4perl

SYNOPSIS

En tu módulo principal de aplicación Catalyst:

use Log::Log4perl::Catalyst;
  # O bien, hacer que Log4perl actúe como el logger por defecto de Catalyst:
__PACKAGE__->log(Log::Log4perl::Catalyst->new());
  # o usar un archivo de configuración de Log4perl, aprovechando la funcionalidad completa 
  # de Log4perl
__PACKAGE__->log(Log::Log4perl::Catalyst->new('l4p.conf'));

... y luego esparcir sentencias de logging por todo el código ejecutado por Catalyst:

$c->log->debug("¡Esto usa log4perl!");

DESCRIPTION

Este módulo proporciona funciones de Log4perl para aplicaciones Catalyst. Se inspiró en Catalyst::Log::Log4perl en CPAN, pero ha sido reescrito completamente y utiliza un enfoque diferente para unir Catalyst y Log4perl.

Log4perl proporciona loggers, usualmente asociados con el paquete actual, que pueden ser controlados remotamente por una configuración central. Esto significa que si tienes una función controladora como

package MyApp::Controller::User;
sub add : Chained('base'): PathPart('add'): Args(0) {
    my ( $self, $c ) = @_;
    $c->log->info("Añadiendo un usuario");
    # ...
}

El control basado en niveles está disponible a través de los siguientes métodos:

$c->log->debug("Leyendo configuración");
$c->log->info("Añadiendo un usuario");
$c->log->warn("No se puede leer la configuración ($!)");
$c->log->error("No se puede añadir el usuario ", $user);
$c->log->fatal("Base de datos caída, abortando la petición");

Pero eso no es todo, Log4perl es mucho más potente.

La sentencia de logging puede ser suprimida o activada basándose en un archivo de Log4perl que se ve así:

  # Todos los loggers de MyApp abiertos a DEBUG y superior
log4perl.logger.MyApp = DEBUG, Screen
# ...

o

  # Todos los loggers bloquean mensajes por debajo de INFO
log4perl.logger=INFO, Screen
# ...

respectivamente. Consulta la página man de Log4perl sobre cómo realizar un filtrado detallado de niveles y ubicaciones de log, y cómo reenviar mensajes no solo a la pantalla o a archivos de log, sino también a bases de datos, appenders de correo electrónico y mucho más.

Además, puedes cambiar el diseño del mensaje. Por ejemplo, si quieres saber dónde se registró una sentencia particular, activa los nombres de archivo y los números de línea:

# Archivo de configuración de Log4perl
# ...
log4perl.appender.Screen.layout.ConversionPattern = \
      %F{1}-%L: %p %m%n

Los mensajes se verán así:

MyApp.pm-1869: INFO Guardando perfil de usuario para el usuario "wonko"

¿O quieres registrar la dirección IP de una petición con cada sentencia de log? No hay problema con Log4perl, solo llama a

Log::Log4perl::MDC->put( "ip", $c->req->address() );

al principio del ciclo de petición y usa

# Archivo de configuración de Log4perl
# ...
log4perl.appender.Screen.layout.ConversionPattern = \
      [%d]-%X{ip} %F{1}-%L: %p %m%n

como un diseño de Log4perl. Los mensajes se verán así:

[2010/02/22 23:25:55]-123.122.108.10 MyApp.pm-1953: INFO Leyendo perfil para el usuario "wonko"

De nuevo, consulta la página man de Log4perl, hay una plétora de opciones de configuración.

METHODS

new($config, [%options])
Si se llama sin parámetros, new() inicializa Log4perl de tal manera que los mensajes se registran de forma similar al mecanismo de logging por defecto de Catalyst. Si proporcionas una configuración, ya sea el nombre de un archivo de configuración o una referencia a una cadena escalar que contenga la configuración, llamará a Log4perl con esos parámetros.

El segundo parámetro (opcional) es una lista de pares clave/valor:

'autoflush'   =>  1   # Registrar sin búfer ('abort' no soportado)
'watch_delay' => 30   # Si se establece, usa L<Log::Log4perl>'s init_and_watch
_flush()
Vacía la caché.
abort($abort)
Borra los búferes internos del sistema de logging sin registrar nada.

Usando Macros :easy con Catalyst

Si estás cansado de escribir

$c->log->debug("...");

y preferirías usar las convenientes macros del modo :easy de Log4perl como

DEBUG "...";

entonces simplemente importa esas macros a través del modo :easy de Log::Log4perl y empieza a usarlas:

use Log::Log4perl qw(:easy);
  # ... usa macros más tarde
sub base :Chained('/') :PathPart('apples') :CaptureArgs(0) {
    my ( $self, $c ) = @_;
    DEBUG "Manejando manzanas";
}

Nota la diferencia entre la inicialización de Log4perl en Catalyst, que usa el módulo específico de Catalyst Log::Log4perl::Catalyst (al principio de esta página), y el uso de los loggers de Log4perl con los loggers y macros estándar de Log::Log4perl. Mientras que la inicialización requiere que Log4perl realice magia oscura para adaptarse a la estrategia de logging diferente de Catalyst, la obtención de los objetos logger de Log4perl o la llamada a sus macros no cambian.

En lugar de usar la forma de Catalyst de referenciar el objeto de "contexto" $c para obtener referencias de logger a través de su método log(), puedes usar igualmente get_logger() de Log4perl o las macros para acceder a los singletons de logger de Log4perl. El resultado es el mismo.
