List::SomeUtils(3) Documentación de Perl aportada por el usuario List::SomeUtils(3)

NOMBRE

List::SomeUtils - Proporciona lo que falta en List::Util

VERSIÓN

versión 0.59

SINOPSIS

# importar funciones específicas
use List::SomeUtils qw( any uniq );
if ( any {/foo/} uniq @has_duplicates ) {
    # hacer cosas
}
# importar todo
use List::SomeUtils ':all';

DESCRIPCIÓN

List::SomeUtils proporciona una funcionalidad trivial pero comúnmente necesaria en listas que no va a incluirse en List::Util.

Todas las funciones a continuación son implementables en solo un par de líneas de código Perl. Sin embargo, usar las funciones de este módulo debería ofrecer un rendimiento ligeramente mejor ya que todo está implementado en C. La implementación puramente en Perl de estas funciones solo sirve como reserva en caso de que las partes en C de este módulo no pudieran compilarse en esta máquina.

¿POR QUÉ EXISTE ESTE MÓDULO?

Puede que te preguntes por qué existe este módulo cuando ya tenemos List::MoreUtils. De hecho, este módulo es (casi) el mismo código que se encuentra en LMU sin cambios significativos. Sin embargo, la distribución de LMU depende de varios módulos para la configuración (para ejecutar Makefile.PL) que algunas personas en la comunidad Perl no consideran apropiados para un módulo en la parte superior del río CPAN.

Yo (Dave Rolsky) no tengo una opinión firme sobre esto, pero sí me gustan las funciones proporcionadas por LMU, y estoy cansado de recibir parches y PR para eliminar LMU de mi código.

Esta distribución existe para permitirme usar la funcionalidad que me gusta sin tener que entrar en discusiones agotadoras sobre temas que en realidad no me importan.

EXPORTACIONES

Comportamiento por defecto

Nada por defecto. Para importar todos los símbolos de este módulo, usa la etiqueta ":all". De lo contrario, las funciones se pueden importar por nombre como de costumbre:

use List::SomeUtils ':all';
use List::SomeUtils qw{ any firstidx };

Debido a que los cambios históricos en la API podrían dificultar la actualización de List::SomeUtils para algunos proyectos, la API heredada está disponible a través de etiquetas de importación especiales.

FUNCIONES

Uniones (Junctions)

Tratamiento de una lista vacía

Hay dos corrientes de pensamiento sobre cómo evaluar una unión en una lista vacía:

  • Reducción a una identidad (booleana)
  • El resultado no está definido (ternario)

En el primer caso, el resultado de la unión aplicada a la lista vacía se determina por una reducción matemática a una identidad dependiendo de si la comparación subyacente es "or" o "and". Conceptualmente:

                "cualquiera es verdadero"      "todos son verdaderos"
                --------------      --------------
2 elementos:     A || B || 0         A && B && 1
1 elemento:      A || 0              A && 1
0 elementos:     0                   1

En el segundo caso, se desea una lógica ternaria, en la cual una unión aplicada a una lista vacía devuelve "undef" en lugar de verdadero o falso.

Las uniones con un sufijo "_u" implementan lógica ternaria. Las que no lo tienen son booleanas.

all BLOCK LIST

all_u BLOCK LIST

Devuelve un valor verdadero si todos los elementos de LIST cumplen el criterio dado a través de BLOCK. Establece $_ para cada elemento en LIST por turno:

print "Todos los valores son no negativos"
  if all { $_ >= 0 } ($x, $y, $z);

Para una LISTA vacía, "all" devuelve verdadero (es decir, ningún valor falló la condición) y "all_u" devuelve "undef".

Por lo tanto, all_u(@list) es equivalente a "@list ? all(@list) : undef".

Nota: debido a que Perl trata "undef" como falso, debes verificar el valor de retorno de "all_u" con "defined" o obtendrás el resultado opuesto al que esperas.

any BLOCK LIST

any_u BLOCK LIST

Devuelve un valor verdadero si algún elemento de LIST cumple el criterio dado a través de BLOCK. Establece $_ para cada elemento en LIST por turno:

print "Al menos un valor no negativo"
  if any { $_ >= 0 } ($x, $y, $z);

Para una LISTA vacía, "any" devuelve falso y "any_u" devuelve "undef".

Por lo tanto, any_u(@list) es equivalente a "@list ? any(@list) : undef".

none BLOCK LIST

none_u BLOCK LIST

Lógicamente, la negación de "any". Devuelve un valor verdadero si ningún elemento de LIST cumple el criterio dado a través de BLOCK. Establece $_ para cada elemento en LIST por turno:

print "Ningún valor no negativo"
  if none { $_ >= 0 } ($x, $y, $z);

Para una LISTA vacía, "none" devuelve verdadero (es decir, ningún valor falló la condición) y "none_u" devuelve "undef".

Por lo tanto, none_u(@list) es equivalente a "@list ? none(@list) : undef".

Nota: debido a que Perl trata "undef" como falso, debes verificar el valor de retorno de "none_u" con "defined" o obtendrás el resultado opuesto al que esperas.

notall BLOCK LIST

notall_u BLOCK LIST

Lógicamente, la negación de "all". Devuelve un valor verdadero si no todos los elementos de LIST cumplen el criterio dado a través de BLOCK. Establece $_ para cada elemento en LIST por turno:

print "No todos los valores son no negativos"
  if notall { $_ >= 0 } ($x, $y, $z);

Para una LISTA vacía, "notall" devuelve falso y "notall_u" devuelve "undef".

Por lo tanto, notall_u(@list) es equivalente a "@list ? notall(@list) : undef".

one BLOCK LIST

one_u BLOCK LIST

Devuelve un valor verdadero si exactamente un elemento de LIST cumple el criterio dado a través de BLOCK. Establece $_ para cada elemento en LIST por turno:

print "Precisamente un valor definido"
    if one { defined($_) } @list;

Devuelve falso en caso contrario.

Para una LISTA vacía, "one" devuelve falso y "one_u" devuelve "undef".

La expresión "one BLOCK LIST" es casi equivalente a "1 == true BLOCK LIST", excepto por el acortamiento. La evaluación de BLOCK se detendrá inmediatamente en el segundo valor verdadero.

Transformación

apply BLOCK LIST

Crea una copia de la lista y luego pasa cada elemento *de la copia* al BLOCK. Cualquier cambio o asignación a $_ en el BLOCK solo afectará a los elementos de la nueva lista. Sin embargo, si $_ es una referencia, los cambios en el valor referenciado se verán tanto en la lista original como en la nueva.

Esta función es similar a "map" pero no modificará los elementos de la lista de entrada:

my @list = (1 .. 4);
my @mult = apply { $_ *= 2 } @list;
print "\@list = @list\n";
print "\@mult = @mult\n";
__END__
@list = 1 2 3 4
@mult = 2 4 6 8

Piensa en ello como azúcar sintáctico para

for (my @mult = @list) { $_ *= 2 }

Modifying lists

Note that you must alter $_ directly inside BLOCK in order for changes to make effect. New value returned from the BLOCK are ignored:

# @new is identical to @list.
my @new = apply { $_ * 2 } @list;
# @new is different from @list
my @new = apply { $_ =* 2 } @list;

insert_after BLOCK VALUE LIST

Inserts VALUE after the first item in LIST for which the criterion in BLOCK is true. Sets $_ for each item in LIST in turn.

my @list = qw/This is a list/;
insert_after { $_ eq "a" } "longer" => @list;
print "@list";
__END__
This is a longer list

insert_after_string STRING VALUE LIST

Inserts VALUE after the first item in LIST which is equal to STRING.

my @list = qw/This is a list/;
insert_after_string "a", "longer" => @list;
print "@list";
__END__
This is a longer list

pairwise BLOCK ARRAY1 ARRAY2

Evaluates BLOCK for each pair of elements in ARRAY1 and ARRAY2 and returns a new list consisting of BLOCK's return values. The two elements are set to $a and $b. Note that those two are aliases to the original value so changing them will modify the input arrays.

@a = (1 .. 5);
@b = (11 .. 15);
@x = pairwise { $a + $b } @a, @b;     # returns 12, 14, 16, 18, 20
# mesh with pairwise
@a = qw/a b c/;
@b = qw/1 2 3/;
@x = pairwise { ($a, $b) } @a, @b;    # returns a, 1, b, 2, c, 3

mesh ARRAY1 ARRAY2 [ ARRAY3 ... ]

zip ARRAY1 ARRAY2 [ ARRAY3 ... ]

Returns a list consisting of the first elements of each array, then the second, then the third, etc, until all arrays are exhausted.

Examples:

@x = qw/a b c d/;
@y = qw/1 2 3 4/;
@z = mesh @x, @y;         # returns a, 1, b, 2, c, 3, d, 4
@a = ('x');
@b = ('1', '2');
@c = qw/zip zap zot/;
@d = mesh @a, @b, @c;   # x, 1, zip, undef, 2, zap, undef, undef, zot

"zip" is an alias for "mesh".

uniq LIST

distinct LIST

Returns a new list by stripping duplicate values in LIST by comparing the values as hash keys, except that undef is considered separate from ''. The order of elements in the returned list is the same as in LIST. In scalar context, returns the number of unique elements in LIST.

my @x = uniq 1, 1, 2, 2, 3, 5, 3, 4; # returns 1 2 3 5 4
my $x = uniq 1, 1, 2, 2, 3, 5, 3, 4; # returns 5
# returns "Mike", "Michael", "Richard", "Rick"
my @n = distinct "Mike", "Michael", "Richard", "Rick", "Michael", "Rick"
# returns '', undef, 'S1', A5'
my @s = distinct '', undef, 'S1', 'A5'
# returns '', undef, 'S1', A5'
my @w = uniq undef, '', 'S1', 'A5'

"distinct" is an alias for "uniq".

RT#49800 can be used to give feedback about this behavior.

singleton

Returns a new list by stripping values in LIST occurring more than once by comparing the values as hash keys, except that undef is considered separate from ''. The order of elements in the returned list is the same as in LIST. In scalar context, returns the number of elements occurring only once in LIST.

my @x = singleton 1,1,2,2,3,4,5 # returns 3 4 5

Partitioning

after BLOCK LIST

Returns a list of the values of LIST after (and not including) the point where BLOCK returns a true value. Sets $_ for each element in LIST in turn.

@x = after { $_ % 5 == 0 } (1..9);    # returns 6, 7, 8, 9

after_incl BLOCK LIST

Same as "after" but also includes the element for which BLOCK is true.

before BLOCK LIST

Returns a list of values of LIST up to (and not including) the point where BLOCK returns a true value. Sets $_ for each element in LIST in turn.

before_incl BLOCK LIST

Same as "before" but also includes the element for which BLOCK is true.

part BLOCK LIST

Partitions LIST based on the return value of BLOCK which denotes into which partition the current value is put.

Returns a list of the partitions thusly created. Each partition created is a reference to an array.

my $i = 0;
my @part = part { $i++ % 2 } 1 .. 8;   # returns [1, 3, 5, 7], [2, 4, 6, 8]

You can have a sparse list of partitions as well where non-set partitions will be undef:

my @part = part { 2 } 1 .. 10;            # returns undef, undef, [ 1 .. 10 ]

Be careful with negative values, though:

my @part = part { -1 } 1 .. 10;
__END__
Modification of non-creatable array value attempted, subscript -1 ...

Negative values are only ok when they refer to a partition previously created:

my @idx  = ( 0, 1, -1 );
my $i    = 0;
my @part = part { $idx[$i++ % 3] } 1 .. 8; # [1, 4, 7], [2, 3, 5, 6, 8]

Iteration

each_array ARRAY1 ARRAY2 ...

Creates an array iterator to return the elements of the list of arrays ARRAY1, ARRAY2 throughout ARRAYn in turn. That is, the first time it is called, it returns the first element of each array. The next time, it returns the second elements. And so on, until all elements are exhausted.

This is useful for looping over more than one array at once:

my $ea = each_array(@a, @b, @c);
while ( my ($a, $b, $c) = $ea->() )   { .... }

The iterator returns the empty list when it reached the end of all arrays.

If the iterator is passed an argument of '"index"', then it returns the index of the last fetched set of values, as a scalar.

each_arrayref LIST

Like each_array, but the arguments are references to arrays, not the plain arrays.

natatime EXPR, LIST

Creates an array iterator, for looping over an array in chunks of $n items at a time. (n at a time, get it?). An example is probably a better explanation than I could give in words.

Example:

my @x = ('a' .. 'g');
my $it = natatime 3, @x;
while (my @vals = $it->())
{
  print "@vals\n";
}

This prints

a b c
d e f
g

Searching

bsearch BLOCK LIST

Performs a binary search on LIST which must be a sorted list of values. BLOCK must return a negative value if the current element (stored in $_) is smaller, a positive value if it is bigger and zero if it matches.

Returns a boolean value in scalar context. In list context, it returns the element if it was found, otherwise the empty list.

bsearchidx BLOCK LIST

bsearch_index BLOCK LIST

Performs a binary search on LIST which must be a sorted list of values. BLOCK must return a negative value if the current element (stored in $_) is smaller, a positive value if it is bigger and zero if it matches.

Returns the index of found element, otherwise -1.

"bsearch_index" is an alias for "bsearchidx".

firstval BLOCK LIST

first_value BLOCK LIST

Returns the first element in LIST for which BLOCK evaluates to true. Each element of LIST is set to $_ in turn. Returns "undef" if no such element has been found.

"first_value" is an alias for "firstval".

onlyval BLOCK LIST

only_value BLOCK LIST

Returns the only element in LIST for which BLOCK evaluates to true. Sets $_ for each item in LIST in turn. Returns "undef" if no such element has been found.

"only_value" is an alias for "onlyval".

lastval BLOCK LIST

Ordenar

sort_by BLOCK LIST

Devuelve la lista de valores ordenada según los valores de cadena devueltos por el bloque de FUNCIÓN clave o función. Una utilización típica de este puede ser ordenar objetos según el valor de cadena de algún accesorio, como

sort_by { $_->name } @people

El función clave se llama en contexto escalare, siendo pasada cada valor por turnos como $_ y el único argumento en los parámetros, @_. Los valores son luego ordenados según comparaciones de cadena en los valores devueltos. Esto es equivalente a

sort { $a->name cmp $b->name } @people

aunque garantiza que el accesorio nombre será ejecutado solo una vez por cada valor. Una utilización interesante es ordenar cadenas que pueden tener números incorporados en ellas "naturalmente", en lugar de de manera lógica.

sort_by { s/(\d+)/sprintf "%09d", $1/eg; $_ } @strings

Esta ordena cadenas generando claves de ordenamiento que cuelgan con ceros a la izquierda para algunos niveles (9 dígitos en este caso), ayudando a asegurar que el ordenamiento lógico los coloque en el orden correcto.

nsort_by BLOCK LIST

Similar a sort_by, pero compara sus valores numéricamente.

Contando y calculando

true BLOCK LIST

Cuenta el número de elementos en LIST para los cuales el criterio en BLOCK es verdadero. 设定 $_ para cada elemento en LIST en orden:

printf "%i item(s) are defined", true { defined($_) } @list;

false BLOCK LIST

Cuenta el número de elementos en LIST para los cuales el criterio en BLOCK es falso. 设定 $_ para cada elemento en LIST en orden:

printf "%i item(s) are not defined", false { defined($_) } @list;

minmax LIST

Calcula el mínimo y el máximo de LIST y devuelve una lista de dos elementos con el primer elemento siendo el mínimo y el segundo el máximo. Devuelve una lista vacía si LIST era vacío.

El algoritmo "minmax" difiere de una iteración naive sobre la lista donde cada elemento se compara con dos valores siendo el valor actual mínimo y máximo calculado hasta ahora. Solo requiere 3n/2 - 2 comparaciones. Por lo tanto, es el algoritmo más eficiente posible.

Sin embargo, el implementación Perl del algoritmo tiene algunos sobrecostes simplemente debido a que hay más líneas de código Perl involucradas. Por lo tanto, LIST necesita ser bastante grande para que "minmax" gane sobre una implementación no naive. Esta limitación no aplica al versión XS.

mode LIST

Calcula los elementos más comunes en la lista y devuelve los mismos como una lista. Esto se hace efectivamente mediante comparaciones de cadena, por lo que los referencias serán serializadas. Si ellos implementan sobrecarga de cadena, este se utilizará.

Si más de un elemento aparece la misma cantidad de veces en la lista, todos estos elementos se devolverán. Por ejemplo, el modo de una lista única es la lista misma.

Esta función devuelve una lista en contexto de lista. En contexto escalare devuelve un conteo indicando el número de modas en la lista.

MANTENIMIENTO

El objetivo de mantenimiento es preservar el semántico documentado de la API; los correcciones de errores que lleven a un comportamiento que se alinee con la semántica son permitidas. Se pueden agregar nuevas funciones de API a lo largo del tiempo. Si una modificación incompatible es ineludible, intentaremos proporcionar soporte para la API antigua usando el mismo mecanismo de exportación.

Este módulo intenta utilizar pocas dependencias no core. Las dependencias de configuración y testing no core se incluirán solo cuando sea razonable; las dependencias de runtime se añadirán solamente si brinden un beneficio sustancial.

PROBLEMAS CONOCIDOS

Existe un problema con un bug en 5.6.x de Perl. Es un error de sintaxis escribir cosas como:

my @x = apply { s/foo/bar/ } qw{ foo bar baz };

Debe escribirse como:

my @x = apply { s/foo/bar/ } 'foo', 'bar', 'baz';

o

my @x = apply { s/foo/bar/ } my @dummy = qw/foo bar baz/;

Perl 5.5.x y Perl 5.8.x no sufren de esta limitación.

Si tienes una funcionalidad que puedas imaginar estar en este módulo, por favor escríbeme un mensaje. La política de este módulo será más laxa que la de List::Util cuando se añadan funciones, ya que no es un módulo core.

Cuando reportes errores, sería genial si también me pudieras dar el output de tu programa con la variable de entorno "LIST_MOREUTILS_PP" establecida a un valor verdadero. Así sabré dónde buscar el problema (en XS, en código Perl o tal vez ambos).
