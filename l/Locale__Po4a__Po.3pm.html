NOMBRE

Locale::Po4a::Po - Módulo para la manipulación de catálogos de mensajes

SINTAXIS

use Locale::Po4a::Po;
my $pofile=Locale::Po4a::Po->new();
# Leer un catálogo de mensajes
$pofile->read('file.po');
# Añadir un registro
$pofile->push('msgid' => 'Hello', 'msgstr' => 'bonjour',
              'flags' => "wrap", 'reference'=>'file.c:46');
# Extraer una traducción
$pofile->gettext("Hello"); # devuelve 'bonjour'
# Escribir de nuevo en un archivo
$pofile->write('otherfile.po');

DESCRIPCIÓN

Locale::Po4a::Po es un módulo que permite manipular catálogos de mensajes. Puedes cargar y escribir en un archivo (cuyo nombre suele ser po), puedes construir nuevos registros en el momento o solicitar una traducción de una cadena.

Para una descripción más completa de los catálogos de mensajes en el formato PO y su uso, por favor consulta la documentación de información del programa gettext (nodo "`PO Archivos`").

Este módulo forma parte del proyecto po4a, el cual tiene como objetivo utilizar archivos de tipo PO (desarrollados originalmente para facilitar la traducción de mensajes de programas) para traducir todo, incluyendo la documentación (man pages, info manuals), el descripción de paquetes, los templates de debconf y todo lo que pueda beneficiarse de esto.

OPCIONES ACEPTADAS POR ESTE MÓDULO

--porefs tipo
Indica el formato de referencia. El argumento tipo puede ser uno de never para no producir ninguna referencia, file para indicar el archivo sin número de línea, counter para reemplazar el número de línea por un contador incrementando, y full para incluir referencias completas (valor predeterminado: full).
--wrap-po no|newlines|numero (valor predeterminado: 76)
Indica cómo debe estar empaquetado el archivo po. Esta ofrece el elegibilidad entre archivos que estén bien empaquetados pero que puedan provocar conflictos en git, o archivos que sean más fáciles de manejar automáticamente pero más difíciles de leer para los humanos.

Históricamente, el conjunto gettext ha reformatado los archivos po en la columna 77 para mejorar el aspecto visual. Esta opción indica el comportamiento de po4a. Si se establece en un valor numérico, po4a se empaquetará el archivo po después de esta columna y después de nuevas líneas en el contenido. Si se establece en newlines, po4a se dividirá el msgid y msgstr después de nuevas líneas en el contenido. Si se establece en no, po4a no empaquetará el archivo. Las comentarios de referencia son siempre empaquetados por los herramientas de texto internos.

Nota: Esta opción no tiene impacto en cómo se empaquetan los msgid y msgstr, es decir, en cómo se añaden nuevas líneas a los contenidos de estos strings.

--msgid-bugs-address correo@dirección
Establece el correo de reporte para los errores en msgid. Por defecto, los archivos POT creados no tienen campo Report-Msgid-Bugs-To.
--copyright-holder cadena
Establece el dueño de la licencia en el encabezado de POT. El valor por defecto es "Free Software Foundation, Inc."
--package-name cadena
Establece el nombre del paquete para el encabezado de POT. El valor por defecto es "PACKAGE".
--package-version cadena
Establece la versión del paquete para el encabezado de POT. El valor por defecto es "VERSION".

Funciones relacionadas con catálogos de mensajes completos

new()
Crea un nuevo catálogo de mensajes. Si se proporciona un argumento, este es el nombre de un archivo po que debemos cargar.
read($)
Lee un catálogo de mensajes (cuyo nombre se proporciona como argumento). Las entradas previamente existentes en self no se eliminan, sino que se añaden al final del catálogo.
write($)
Escribe el catálogo actual en el archivo dado.
write_if_needed($$)
Como write, pero si el archivo po o POT ya existe, el objeto se escribirá en un archivo temporal que se comparará con el archivo existente para verificar si la actualización es necesaria (evita cambiar un POT solo para actualizar una referencia de línea o el campo POT-Creation-Date).
filter($)
Esta función extrae un catálogo de uno existente. Solo las entradas con una referencia en el archivo dado se colocarán en el catálogo resultado.

Esta función analiza su argumento, lo convierte en una definición de función Perl, evalúa esta definición y filtra las entradas cuyo campo devuelve true.

Funciones para usar un catálogo de mensajes para traducciones

gettext($%)
Requiere la traducción de la cadena dada como argumento en el catálogo actual. Si la cadena no se encuentra, devuelve la cadena original (no traducida).

Después de la cadena a traducar, puedes pasar un hash de argumentos adicionales. Aquí están los entradas válidas:

wrap
un booleano que indica si podemos considerar que los espacios en blanco en la cadena son importantes. Si es sí, la función canoniza la cadena antes de buscar una traducción, y redondea el resultado.
wrapcol
la columna en la que debemos redondear (valor predeterminado: 76).
stats_get()
Devuelve estadísticas sobre el porcentaje de hitos de gettext desde el último tiempo que stats_clear() fue llamado. Por favor note que no son las mismas estadísticas que las impresionadas por msgfmt --statistic. Aquí, son estadísticas sobre el uso reciente del archivo PO, mientras que msgfmt reporta el estado del archivo. Ejemplo de uso: 
[uso de un archivo PO para traducir algo]
($percent,$hit,$queries) = $pofile->stats_get();
print "Hasta ahora, hemos encontrado traducciones para $percent\%  ($hit de $queries) de strings.\n";
stats_clear()
Limita las estadísticas sobre los hitos de gettext.

Funciones para construir un catálogo de mensajes

push(%)
Añade un nuevo registro a un catálogo de mensajes existente. Las claves válidas para el hash son msgid, msgstr, flags, reference, previous, fuzzy, msgctxt.

msgid es la cadena original. msgstr es su traducción. flags es una cadena que contiene coma separada de las banderas (ej. "fuzzy,wrap"). reference es la información de ubicación, tal como es generada por la mayoría de los utilitarios de extracción de cadenas (ej. "file.c:42,56"). previous es la cadena original del registro anterior (solo se usa para cadenas plurales). fuzzy es un booleano indicando si la entrada está marcada como fuzzy. msgctxt es el contexto del mensaje.

Si el registro existe, su contenido se actualizará.

add_header(%)
Añade o actualiza una línea de encabezado en el catálogo. Las claves válidas son las mismas que las de git, como Project-Id-Version, POT-Creation-Date, PO-Revision-Date, Last-Translator, Language-Team, MIME-Version, Content-Type, Content-Transfer-Encoding.

ush una nueva entrada al final del catálogo actual. Los argumentos deben formar una tabla hash. Las claves válidas son:
msgid
la cadena en el idioma original.
msgstr
la traducción.
reference
una indicación de dónde se encontró esta cadena. Ejemplo: file.c:46 (que significa en 'file.c' en la línea 46). Puede ser una lista separada por espacios en caso de múltiples ocurrencias.
comment
un comentario añadido aquí manualmente (por los traductores). El formato aquí es libre.
automatic
un comentario que fue añadido automáticamente por el programa de extracción de cadenas. Ver la opción --add-comments del programa xgettext para más información.
flags
lista separada por espacios de todas las banderas definidas para esta entrada.

Las banderas válidas son: c-text, python-text, lisp-text, elisp-text, librep-text, smalltalk-text, java-text, awk-text, object-pascal-text, ycp-text, tcl-text, wrap, no-wrap y fuzzy.

Ver la documentación de gettext para su significado.

type
este es principalmente un argumento interno: se utiliza mientras se realiza la "gettextización" de documentos. La idea aquí es analizar tanto el original como la traducción en un objeto PO, y fusionarlos, usando el msgid de uno como msgid y el msgid del otro como msgstr. Para asegurarse de que las cosas salgan bien, a cada msgid en los objetos PO se le da un tipo, basado en su estructura (como "chapt", "sect1", "p" y así sucesivamente en DocBook). Si los tipos de las cadenas no son los mismos, significa que ambos archivos no comparten la misma estructura, y el proceso informa de un error.

Esta información se escribe como un comentario automático en el archivo PO, ya que esto da a los traductores algo de contexto sobre las cadenas a traducir.

wrap
booleano que indica si los espacios en blanco pueden ser modificados en re-formateos cosméticos. Si es verdadero, la cadena se canoniza antes de su uso.

Esta información se escribe en el archivo PO utilizando la bandera wrap o no-wrap.

wrapcol
ignorado; la clave se mantiene por compatibilidad hacia atrás.

Funciones varias

count_entries()
Devuelve el número de entradas en el catálogo (sin la cabecera).
count_entries_doc()
Devuelve el número de entradas en el documento. Si una cadena aparece múltiples veces en el documento, se contará múltiples veces.
msgid($)
Devuelve el msgid del número dado.
msgid_doc($)
Devuelve el msgid con la posición dada en el documento.
type_doc($)
Devuelve el tipo del msgid con la posición dada en el documento. Esto es probablemente útil solo para la "gettextización", y se almacena por separado de {$msgid}{'type'} porque esta última ubicación puede ser sobrescrita por otro tipo cuando el $msgid se duplica en el documento maestro.
get_charset()
Devuelve el conjunto de caracteres especificado en la cabecera del PO. Si no se ha establecido, devolverá "UTF-8".
