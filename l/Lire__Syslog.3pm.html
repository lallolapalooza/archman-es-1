Syslog(3pm) Documentación de Lire de LogReport Syslog(3pm)

NOMBRE

Lire::Syslog - analizador de líneas estilo syslog

SINOPSIS

use Lire::Syslog;

my $parser = new Lire::Syslog;

my $rec = $parser->parse( $line );

DESCRIPCIÓN

Este módulo define objetos capaces de analizar registros que provienen de varios tipos de demonios de registro.

Actualmente soporta los siguientes formatos de archivo syslog:

Demonio syslog BSD Clásico
El formato syslog BSD "clásico": 
MMM DD HH:MM:SS NombreHost Mensaje
Demonio syslog Solaris 8
El demonio syslog de Solaris 8 también incluye la facilidad y el nivel: 
MMM DD HH:MM:SS NombreHost Proceso[Pid]: [ID DDDDDD Facilidad.Nivel] Mensaje
Demonio de registro Netscape Messaging Server
El demonio syslog que viene con Netscape Messaging Server utiliza una fecha en formato de registro común: 
[DD/MMM/YYYY:HH:MM:SS +ZZZZ] NombreHost Proceso[Pid]: Facilidad Nivel: Mensaje
Demonio syslog WebTrends
El formato utilizado por el demonio syslog que viene con WebTrends: 
WTsyslog[YYYY-MM-DD HH:MM:SS ip=NOMBREHOST pri=PRIORIDAD_WT] <XX>Mensaje
Syslog Kiwi (formato de fecha ISO)
Los formatos de registro ISO utilizados por el demonio Kiwi Syslog (http://www.kiwisyslog.com/info_sysd.htm), un demonio de registro encontrado frecuentemente en plataformas Win32: 
YYYY-MM-DD HH:MM:SS [TAB] Facilidad.Nivel [TAB] NombreHost [TAB] Mensaje
Syslog Kiwi (formato de fecha US)
El formato de fecha US utilizado por el demonio Kiwi Syslog: 
MM-DD-YYYY HH:MM:SS [TAB] Facilidad.Nivel [TAB] NombreHost [TAB] Mensaje
Syslog Kiwi (formato de fecha DD-MM-YYYY)
El formato de fecha DD-MM-YYYY utilizado por el demonio Kiwi Syslog: 
DD-MM-YYYY HH:MM:SS [TAB] Facilidad.Nivel [TAB] NombreHost [TAB] Mensaje
Demonio de registro Sendmail Switch
El formato utilizado por el demonio de registro que viene con Sendmail Switch en plataformas Win32: 
MM/DD/YY HH:MM:SS Proceso(Pid): Nivel: Mensaje
Demonio Syslog compatible con RFC 3164
Un formato de los demonios Syslog compatibles con RFC 3164 que incluye la prioridad codificada y el año en la fecha. RFC 3164 define el "Protocolo Syslog BSD". 
<Prioridad>MMM DD AAAA HH:MM:SS: Proceso[Pid]: Mensaje

La primera vez que se utiliza el método parse(), el analizador intentará cada uno de los formatos soportados para detectar el formato syslog. Si ningún formato coincide, el módulo llamará a lr_err() y abortará el programa. Cada otra invocación de parse() usará el mismo formato.

El método parse() devolverá una referencia a un hash que contiene las siguientes claves:

timestamp
La marca de tiempo del evento.
hostname
El nombre o la dirección IP del host que envió el mensaje.
process
El "proceso" que registró el evento. Formalmente, el mensaje syslog no contiene un campo de proceso, pero suele ser la primera palabra que aparece antes de dos puntos en el contenido del mensaje.
pid
El PID del proceso que registró el evento. Esto es generalmente lo que está entre corchetes en la parte del proceso del mensaje.
identifier
Esta clave solo está presente cuando el registro proviene de un demonio syslog de Solaris 8. Contiene el identificador que sigue a ID en el mensaje.
facility
La facilidad (kern, mail, local0, etc.) del mensaje syslog. Esto no es soportado en todos los formatos de archivo, por lo que esta clave podría no estar disponible.
level
El nivel (emerg, info, notice, etc.) del mensaje syslog. Esto no es soportado en todos los formatos de archivo, por lo que esta clave podría no estar disponible.
content
El mensaje syslog real (con el proceso y el PID eliminados). Muchos dispositivos de red también tendrán otra marca de tiempo estilo BSD al principio del mensaje. Si está presente, también será eliminada.

USO

package Lire::Foo;
use base qw/ Lire::Syslog /;
sub parse {
   my $self = shift;
   my $line = shift;
   # esto ejecuta parse de Lire::Syslog, estableciendo claves como 'day', 'process'
   # y 'hostname'
   my $rec = $self->SUPER::parse($line);
   $rec->{'foo'} = dosomethingwith( $rec->{'content'} );
   return $rec
}

Ahora, uno puede ejecutar en un script

my $parser = new Lire::Foo();
while ( <> ) {
   chomp;
   my $log = $parser->parse( $line );
}

lo que establece $log->{'day'}, ... $log->{'process'} y $log->{'foo'}.

RMATS(1)

rmats - A tool for managing files with arbitrary metadata.

SYNOPSIS

rmats [OPTIONS] [FILE]...

DESCRIPTION

The rmats command allows users to associate arbitrary metadata with files. This metadata can be used to categorize, search, and manage files more effectively.

OPTIONS

-a, --add KEY=VALUE
Adds or updates a metadata key-value pair for the specified file(s).
-r, --remove KEY
Removes a metadata key and its associated value from the specified file(s).
-g, --get KEY
Retrieves the value of a specific metadata key for the specified file(s).
-l, --list
Lists all metadata associated with the specified file(s).
-s, --search KEY=VALUE
Searches for files that have a specific metadata key-value pair.
-h, --help
Displays a help message and exits.

EXAMPLES

Add metadata to a file: 

                    rmats -a project=alpha report.docx

Remove metadata from a file: 

                    rmats -r project report.docx

Get metadata value: 

                    rmats -g project report.docx

List all metadata for a file: 

                    rmats -l report.docx

Search for files with specific metadata: 

                    rmats -s project=alpha *.docx
