W3CExtendedLog(3pm) Documentación de Lire W3CExtendedLog(3pm)

NOMBRE

Lire::W3CExtendedLog - Implementación base de un parser de log de W3C Extended Log

SINTAXIS

use Lire::W3CExtendedLog;

my $parser = new Lire::W3CExtendedLog;

my $w3c_rec = $parser->parse( $line );

DESCRIPCIÓN

Este módulo define objetos que pueden parsear el formato de log de W3C Extended Log. Este formato de log está definido en http://www.w3.org/TR/WD-logfile.html

Todos los atributos de los objetos creados pueden ser sobrescritos por módulos que extienden los objetos. Los atributos son:

type2regex

type2regex es una tabla asociativa con pares clave-valor como

'name' => '([-_.0-9a-zA-Z]+)'

Las claves son todos los formatos de campo para entradas de log como definidos en la especificación W3C: 'integer', 'fixed', 'uri', 'date', 'time' y 'string', junto con 'name' y 'address'.

identifier2type

identifier2type es una tabla asociativa con pares clave-valor como

'dns'        => 'name',
'uri-query'  => 'uri',
'ip'         =>

Las claves son los identificadores de campo definidos en la especificación W3C, con sus prefijos eliminados.

field2re

field2re es una subrutina; cuando se llama como

$self->{field2re('c-ip')}

devuelve por ejemplo

'(\d+\.\d+\.\d+\.\d+|-)'

Los argumentos son como encontrados en el Directiva Fields, así que, en el mundo ideal, deberían ser identificadores. Usa type2regex.

field2decoder

field2decoder es una subrutina; devuelve uno de \&uri_decode, \&string_decode o undef, según, entre otros, el valor de is_iis. Se utiliza por build_parser.

parse

parse es la interfaz preferida de este módulo. Espera una línea como argumento y devuelve un referencia a un hash (como &w3c_parser), o ejecuta &parse_directive.

parse_directive

parse_directive espera un directivo como argumento y llena el objeto.

w3c_parser

w3c_parser es una subrutina; espera un línea de log como argumento y devuelve una referencia a un hash, que mapea entradas de $self->{'fields'} a sus valores deseados. Usa &field2re y &field2decoder. Se genera mediante build_parser.

build_parser

build_parser es una subrutina, genera y devuelve &w3c_parser. Se llama en &parse_directive.

log_date y log_time

log_date y log_time contienen las cadenas construidas a partir de la Directiva Date.

version y sofware

version y sofware contienen las cadenas construidas a partir de las Directivas Version y Software, respectivamente.

fields

fields contiene toda la cadena de la Directiva Fields.

is_iis

is_iis está definido si la Directiva Software contiene 'Microsoft Internet' como substring. Se usa para activar soporte específico de IIS.

tab_sep

tab_sep está definido si hay tabulaciones en la Directiva Fields. Asumimos que se usarán en el propio log y permitimos espacios no escapados en el log.

Resumiendo:

&parse --llama-- &parse_directive
       `--llama-- &w3c_parser
&parse_directive --llama-- &build_parser
&build_parser --llama-- &field2decoder
             `--llama-- &field2re
             `--devuelve-- &w3c_parser
&field2decoder --devuelve-- &uri_decode, &string_decode
&field2re --usa-- %type2regex
          `--usa-- %identifier2type
