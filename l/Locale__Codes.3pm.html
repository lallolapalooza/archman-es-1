NOMBRE

Locale::Codes - una distribución de módulos para manejar códigos de localización

DESCRIPCIÓN

Locale-Codes es una distribución que contiene un conjunto de módulos diseñados para trabajar con conjuntos de códigos que identifican algo de forma única. Por ejemplo, existen códigos asociados con diferentes países, diferentes divisas, diferentes idiomas, etc. Estos conjuntos de códigos se mantienen típicamente en algún estándar.

Esta distribución proporciona una forma de trabajar con estas listas de códigos. Dado que los datos de los diversos estándares no están disponibles en ninguna API consistente, el acceso a las listas no está disponible de forma directa. Para compensar esto, la lista de códigos se almacena internamente dentro de esta distribución, y la distribución se actualiza regularmente para incluir todos los códigos conocidos en ese momento. Esto significa que es necesario mantener esta distribución actualizada para estar al día con los diversos cambios que se realizan en los diversos estándares.

Tradicionalmente, se ha creado un módulo para trabajar con cada tipo de conjunto de códigos. Así, hay un módulo para trabajar con listas de países, otro para listas de divisas, etc. Desde la versión 3.00, todos estos módulos individuales se escribieron como envoltorios (wrappers) alrededor de un módulo central (que no estaba destinado a ser utilizado directamente) que realizaba todo el trabajo real.

A partir de la versión 3.50, el módulo central se rediseñó ligeramente para proporcionar una interfaz orientada a objetos. Todos los módulos para trabajar con tipos individuales de conjuntos de códigos se rediseñaron para utilizar el módulo OO mejorado, por lo que las interfaces tradicionales siguen funcionando como siempre. Como resultado, puede usar las interfaces funcionales (no OO) tradicionales, o usar la interfaz OO y omitir los módulos envoltorio por completo.

Ambos métodos se admitirán en el futuro, así que utilice el que mejor se adapte a sus necesidades.

Dentro de cada tipo, se permiten varios conjuntos de códigos. Por ejemplo, los conjuntos de códigos de países se mantienen en varios lugares diferentes, incluyendo el estándar ISO-3166, la IANA y las Naciones Unidas. Las listas de países son similares, pero no idénticas. Se admiten múltiples conjuntos de códigos, aunque intentar convertir de un conjunto de códigos a otro no siempre funcionará, ya que la lista de países no es uno a uno.

Todos los datos de todos estos módulos provienen directamente de los estándares originales (o lo más cercano posible a lo directo), por lo que deberían estar actualizados en el momento de su publicación.

Planeo lanzar una nueva versión varias veces al año para incorporar cualquier cambio realizado en los estándares. Sin embargo, no siempre conozco los cambios que ocurren, por lo que si alguno de los estándares cambia y usted quiere una nueva versión antes, solo envíeme un correo electrónico y la publicaré.

SINOPSIS (INTERFAZ ORIENTADA A OBJETOS)

use Locale::Codes;
o
use Locale::Codes ':constants';
$obj = new Locale::Codes 'country';

MÉTODOS ORIENTADOS A OBJETOS

Los siguientes métodos están disponibles.

En todos los métodos, al especificar un conjunto de códigos, el nombre (como cadena) siempre está disponible.

Tradicionalmente, también podía usar una constante de perl para especificar el conjunto de códigos. Para hacerlo con la interfaz OO, tiene que importar las constantes. Para hacerlo, cargue el módulo con:

use Locale::Codes ':constants';
new ( [TIPO [,CONJUNTO_DE_CODIGOS]] )
$obj = new Locale::Codes;
$obj = new Locale::Codes 'country';
$obj = new Locale::Codes 'country','alpha-3';
$obj = new Locale::Codes 'country',LOCALE_COUNTRY_ALPHA_3;

Esto crea un nuevo objeto que puede acceder a los datos. Si no se especifica ningún tipo (en el primer argumento), debe usar el método type descrito a continuación. Ninguna operación funcionará a menos que se especifique el tipo.

El segundo argumento es el conjunto de códigos predeterminado a utilizar. Es opcional, ya que cada tipo tiene un conjunto de códigos predeterminado. El conjunto de códigos predeterminado se puede establecer usando el método codeset a continuación.

El último ejemplo solo está disponible si las constantes se importaron al cargar el módulo.

show_errors ( BANDERA )
$obj->show_errors(1);
$obj->show_errors(0);

Por defecto, se generarán mensajes de error cuando se pasen datos incorrectos a cualquier método. Al pasar '0', estos se desactivarán para que todos los fallos sean silenciosos.

type ( TIPO )
$obj->type($tipo)

Esto establecerá el tipo de códigos con los que se trabajará. $tipo puede ser cualquiera de los tipos de conjuntos de códigos reconocidos, incluyendo:

country
language
currency
script
etc.

La lista de tipos válidos y los conjuntos de códigos admitidos en cada uno se describen en el documento Locale::Codes::Types.

Este método se puede llamar cualquier número de veces para alternar entre diferentes tipos de conjuntos de códigos.

codeset ( CONJUNTO_DE_CODIGOS )
$obj->codeset($conjunto_de_codigos);

Esto establece el conjunto de códigos predeterminado a usar. La lista de conjuntos de códigos disponibles para cada tipo se describe en el documento Locale::Codes::Types.

En todos los demás métodos a continuación, cuando se omite un argumento opcional CONJUNTO_DE_CODIGOS, se usará este valor por defecto.

code2name ( CODIGO [,CONJUNTO_DE_CODIGOS] [,'retired'] )
$nombre = $obj->code2name($codigo [,$conjunto_de_codigos] [,'retired']);

Esta función toma un código y devuelve una cadena que contiene el nombre del elemento identificado. Si el código no es un código válido en el CONJUNTO_DE_CODIGOS especificado, se devolverá "undef".

El nombre del elemento es el nombre especificado en el estándar y, como resultado, pueden devolverse diferentes variaciones del nombre de un elemento para diferentes valores de CONJUNTO_DE_CODIGOS.

Por ejemplo, el conjunto de códigos de país alpha-2 define el código de dos letras "bo" como "Bolivia, Plurinational State of", mientras que el conjunto de códigos alpha-3 define el código 'bol' como el país "Bolivia (Plurinational State of)". Así:

$obj->code2name('bo','alpha-2');
   => 'Bolivia, Plurinational State of'
$obj->code2name('bol','alpha-3');
   => 'Bolivia (Plurinational State of)'

Por defecto, solo se utilizarán códigos activos, pero si se pasa la cadena 'retired' como argumento, se examinarán tanto los códigos activos como los retirados.

code2names ( CODIGO [,CONJUNTO_DE_CODIGOS] )
@nombre = $obj->code2names($codigo [,$conjunto_de_codigos]);

Esta función toma un código y devuelve una lista de todos los nombres y alias asociados con ese código.

Solo se pueden usar códigos activos y solo se devolverán nombres y alias activos.

name2code ( NOMBRE [,CONJUNTO_DE_CODIGOS] [,'retired'] )
$codigo = $obj->name2code($nombre [,$conjunto_de_codigos] [,'retired']);

Esta función toma el nombre de un elemento (o cualquiera de sus alias) y devuelve el código que le corresponde, si existe. Si NOMBRE no pudo ser identificado como el nombre de uno de los elementos, se devolverá "undef".

El nombre no distingue entre mayúsculas y minúsculas. Además, se puede pasar cualquier variación conocida de un nombre.

Por ejemplo, aunque los nombres de país devueltos usando los códigos de país 'alpha-2' y 'alpha-3' para Bolivia son diferentes, se puede pasar cualquiera de los nombres de país, ya que para cada conjunto de códigos (además del alias más común 'Bolivia'). Así:

$obj->name2code('Bolivia, Plurinational State of','alpha-2');
   => bo
$obj->name2code('Bolivia (Plurinational State of)','alpha-2');
   => bo
$obj->name2code('Bolivia','alpha-2');
   => bo

Por defecto, solo se usarán nombres activos, pero si se pasa la cadena 'retired' como argumento, se examinarán tanto los nombres activos como los retirados.

code2code ( CODIGO [,CONJUNTO_DE_CODIGOS] ,CONJUNTO_DE_CODIGOS2 )
$codigo = $obj->code2code($codigo [,$conjunto_de_codigos] ,$conjunto_de_codigos2);

METHODS

code2name ( CODE [,CODESET] )
$name = $obj->code2name($code [,$codeset]);

This method returns the official name for the specified CODE in the given CODESET. If CODESET is not specified, the default code set is used.

If the code is not found, or if it is a retired code, then "undef" is returned.

For example:

$obj->code2name('us');
   => 'United States'
$obj->code2name('usa', 'alpha-3');
   => 'United States'
name2code ( NAME [,CODESET] )
$code = $obj->name2code($name [,$codeset]);

This method returns the official code for the specified NAME in the given CODESET. If CODESET is not specified, the default code set is used.

If the name is not found, or if it is a retired name, then "undef" is returned.

Note that this function does NOT support retired codes.

For example:

$obj->name2code('United States');
   => 'us'
$obj->name2code('United States', 'alpha-3');
   => 'usa'

You may also specify an alias name. For example, if you have added an alias for 'United States' called 'USA':

$obj->add_alias('United States', 'USA');
$obj->name2code('USA');
   => 'us'
code2code ( CODE ,CODESET ,CODESET2 )
$code = $obj->code2code($code, $codeset, $codeset2);

This method takes a code from one code set (CODESET or the default code set), and returns the corresponding code from another code set (CODESET2). CODE must exists in the code set specified by CODESET and must have a corresponding code in the code set specified by CODESET2 or "undef" will be returned.

$obj->code2code('fin','alpha-3','alpha-2');
   => 'fi'

Note that this function does NOT support retired codes.

all_codes ( [CODESET] [,'retired'] )
@code = $obj->all_codes([$codeset] [,'retired']);

This returns a list of all code in the code set. The codes will be sorted.

By default, only active codes will be returned, but if the string 'retired' is passed in as an argument, both active and retired codes will be returned.

all_names ( [CODESET] [,'retired'] )
@name = $obj->all_names([$codeset] [,'retired']);

This method returns a list of all elements names for which there is a corresponding code in the specified code set.

The names returned are exactly as they are specified in the standard, and are sorted.

Since not all elements are listed in all code sets, the list of elements may differ depending on the code set specified.

By default, only active names will be returned, but if the string 'retired' is passed in as an argument, both active and retired names will be returned.

The following additional methods are available and can be used to modify the code list data (and are therefore not generally useful).

rename_code ( CODE ,NEW_NAME [,CODESET] )
$flag = $obj->rename_code($code,$new_name [,$codeset]);

This method can be used to change the official name of an element. At that point, the name returned by the "code2name" method would be NEW_NAME instead of the name specified in the standard.

The original name will remain as an alias.

For example, the official country name for code 'gb' is 'United Kingdom'. If you want to change that, you might call:

$obj->rename_code('gb', 'Great Britain');

This means that calling code2name('gb') will now return 'Great Britain' instead of 'United Kingdom'.

If any error occurs, a warning is issued and 0 is returned. An error occurs if CODE doesn't exist in the specified code set, or if NEW_NAME is already in use but for a different element.

If the method succeeds, 1 is returned.

add_code ( CODE ,NAME [,CODESET] )
$flag = $obj->add_code($code,$name [,$codeset]);

This method is used to add a new code and name to the data.

Both CODE and NAME must be unused in the data set or an error occurs (though NAME may be used in a different data set).

For example, to create the fictitious country named "Duchy of Grand Fenwick" with codes "gf" and "fen", use the following:

$obj->add_code("fe","Duchy of Grand Fenwick",'alpha-2');
$obj->add_code("fen","Duchy of Grand Fenwick",'alpha-3');

The return value is 1 on success, 0 on an error.

delete_code ( CODE [,CODESET] )
$flag = $obj->delete_code($code [,$codeset]);

This method is used to delete a code from the data.

CODE must refer to an existing code in the code set.

The return value is 1 on success, 0 on an error.

add_alias ( NAME ,NEW_NAME )
$flag = $obj->add_alias($name,$new_name);

This method is used to add a new alias to the data. They do not alter the return value of the "code2name" function.

NAME must be an existing element name, and NEW_NAME must be unused or an error occurs.

The return value is 1 on success, 0 on an error.

delete_alias ( NAME )
$flag = $obj->delete_alias($name);

This method is used to delete an alias from the data. Once removed, the element may not be referred to by NAME.

NAME must be one of a list of at least two names that may be used to specify an element. If the element may only be referred to by a single name, you'll need to use the "add_alias" method to add a new alias first, or the "remove_code" method to remove the element entirely.

If the alias is used as the name in any code set, one of the other names will be used instead. Predicting exactly which one will be used requires you to know the order in which the standards were read, which is not reliable, so you may want to use the "rename_code" method to force one of the alternate names to be used.

The return value is 1 on success, 0 on an error.

replace_code ( CODE ,NEW_CODE [,CODESET] )
$flag = $obj->replace_code($code,$new_code [,$codeset]);

This method is used to change the official code for an element. At that point, the code returned by the "name2code" method would be NEW_CODE instead of the code specified in the standard.

NEW_CODE may either be a code that is not in use, or it may be an alias for CODE (in which case, CODE becomes and alias and NEW_CODE becomes the "real" code).

The original code is kept as an alias, so that the "code2name" routines will work with either the code from the standard or the new code.

However, the "all_codes" method will only return the codes which are considered "real" (which means that the list of codes will now contain NEW_CODE, but will not contain CODE).

add_code_alias ( CODE ,NEW_CODE [,CODESET] )
$flag = $obj->add_code_alias($code,$new_code [,$codeset]);

This method adds an alias for the code. At that point, NEW_CODE and CODE will both work in the "code2name" method. However, the "name2code" method will still return the original code.

delete_code_alias ( CODE [,CODESET] )
These routines delete an alias for the code.

These will only work if CODE is actually an alias. If it is the "real" code, it will not be deleted. You will need to use the "rename_code" method to switch the real code with one of the aliases, and then delete the alias.

TRADITIONAL INTERFACES

In addition the the primary OO module, the following modules are included in the distribution for the traditional way of working with code sets.

Each module will work with one specific type of code sets.

Locale::Codes::Country, Locale::Country
This includes support for country codes (such as those listed in ISO-3166) to specify the country.

Because this module was originally distributed as Locale::Country, it is also available under that name.

Locale::Codes::Language, Locale::Language
This includes support for language codes (such as those listed in ISO-639) to specify the language.

Because this module was originally distributed as Locale::Language, it is also available under that name.

Locale::Codes::Currency, Locale::Currency
This includes support for currency codes (such as those listed in ISO-4217) to specify the currency.

Because this module was originally distributed as Locale::Currency, it is also available under that name.

Locale::Codes::Script, Locale::Script
This includes support for script codes (such as those listed in ISO-15924) to specify the script.

Because this module was originally distributed as Locale::Script, it is also available under that name.

Locale::Codes::LangExt
This includes support for language extension codes (such as those listed in the IANA language registry) to specify the language extension.
Locale::Codes::LangVar
This includes support for language variation codes (such as those listed in the IANA language registry) to specify the language variation.
Locale::Codes::LangFam
This includes support for language family codes (such as those listed in ISO 639-5) to specify families of languages.

In addition to the modules above, there are a number of support modules included in the distribution. Any module not listed above falls into that category.

These modules are not intended to be used by programmers. They contain functions or data that are used by the modules listed above. No support of any kind is offered for using these modules directly. They may be modified at any time.

NAME

Locale::Codes - codes for various locale entities

DESCRIPTION

Locale::Codes is a module that provides codes for various locale entities such as countries, languages, currencies, scripts, timezones, etc.

The codes are generally taken from the relevant ISO standards, but may include other codes as well.

The module provides both an object-oriented interface and a set of traditional procedural interfaces.

SYNOPSIS (OBJECT-ORIENTED INTERFACE)

use Locale::Codes;

my $codes = Locale::Codes->new(
     codeset => 'ISO 3166-1', # or 'IANA', 'CLDR', 'UN', etc.
     type    => 'country',    # or 'language', 'currency', etc.
);

print $codes->codeset();     # 'ISO 3166-1'
print $codes->type();      # 'country'

print $codes->code2name('us');       # 'United States'
print $codes->name2code('United States'); # 'us'

print $codes->all_codes();   # array ref of all country codes
print $codes->all_names();   # array ref of all country names

print $codes->code2name('gb');       # 'United Kingdom'
print $codes->code2name('gb', 'zh'); # '英國' (if language data available)

print $codes->name2code('United Kingdom'); # 'gb'
print $codes->name2code('United Kingdom', 'zh'); # 'gb' (no change)

# The object can also be used to look up other types of codes:
my $lang_codes = Locale::Codes->new(type => 'language');
print $lang_codes->code2name('en'); # 'English'

my $tz_codes = Locale::Codes->new(type => 'timezone');
print $tz_codes->code2name('America/Los_Angeles'); # 'Pacific Time Zone'

my $currency_codes = Locale::Codes->new(type => 'currency');
print $currency_codes->code2name('usd'); # 'US Dollar'

OBJECT-ORIENTED METHODS

new ( %args )
Creates a new Locale::Codes object. The following arguments are supported:
codeset
The name of the codeset to use. Defaults to the most appropriate codeset for the given type.
type
The type of codes to use. Must be one of the types supported by the module (e.g., 'country', 'language', 'currency', 'timezone', etc.). Defaults to 'country'.
code2name( $code [, $locale ] )
Given a code, returns the corresponding name. If the optional locale argument is given, it attempts to return the name in that locale.
name2code( $name [, $locale ] )
Given a name, returns the corresponding code. If the optional locale argument is given, it attempts to return the code that corresponds to the name in that locale.
all_codes()
Returns a reference to an array of all codes in the codeset.
all_names()
Returns a reference to an array of all names in the codeset.
codeset()
Returns the name of the codeset used by this object.
type()
Returns the type of codes used by this object.

TRADITIONAL INTERFACES

In addition to the object-oriented interface, the module also provides a set of traditional procedural interfaces. These interfaces are simpler to use but offer less flexibility.

use Locale::Codes qw(:all);

print country2code('United States'); # 'us'
print code2country('us');      # 'United States'

print language2code('English');      # 'en'
print code2language('en');      # 'English'

# etc. for currency, timezone, script, etc.

The following functions are available:

country2code( $name )
Returns the country code for the given country name.

Returns the country name for the given country code.
language2code( $name )
Returns the language code for the given language name.
code2language( $code )
Returns the language name for the given language code.
currency2code( $name )
Returns the currency code for the given currency name.

Returns the currency name for the given currency code.

Returns the timezone code for the given timezone name.
code2timezone( $code )
Returns the timezone name for the given timezone code.

Returns the script code for the given script name.

Returns the script name for the given script code.

Returns a reference to an array of all country names.

COMMON ALIASES

As of version 2.00, the modules supported common variants of names.

For example, Locale::Country supports variant names for countries, and a few of the most common ones are included in the data. The country code for "United States" is "us", so:

country2code('United States');
  => "us"

Now the following will also return 'us':

country2code('United States of America');
country2code('USA');

Any number of common aliases may be included in the data, in addition to the names that come directly from the standards. If you have a common alias for a country, language, or any other of the types of codes, let me know and I'll add it, with some restrictions.

For example, the country name "North Korea" never appeared in any of the official sources (instead, it was "Korea, North" or "Korea, Democratic People's Republic of". I would honor a request to add an alias "North Korea" since that's a very common way to specify the country (please don't request this... I've already added it).

On the other hand, a request to add Zaire as an alias for "Congo, The Democratic Republic of" will not be honored. The country's official name is no longer Zaire, so adding it as an alias violates the standard. Zaire was kept as an alias in versions of this module prior to 3.00, but it has been removed. Other aliases (if any) which no longer appear in any standard (and which are not common variations of the name in the standards) have also been removed.

RETIRED CODES

Occasionally, a code is deprecated, but it may still be desirable to have access to it.

Although there is no way to see every code that has ever existed and been deprecated (since most codesets do not have that information available), as of version 3.20, every code which has ever been included in these modules can be referenced.

For more information, refer to the documentation on the code2name, name2code, all_codes, and all_names methods above.

KNOWN BUGS AND LIMITATIONS

Relationship between code sets
Because each code set uses a slightly different list of elements, and they are not necessarily one-to-one, there may be some confusion about the relationship between codes from different code sets.

For example, ISO 3166 assigns one code to the country "United States Minor Outlying Islands", but the IANA codes give different codes to different islands (Baker Island, Howland Island, etc.).

This may cause some confusion... I've done the best that I could do to minimize it.

Non-ASCII characters not supported
Currently all names must be all ASCII. I plan on relaxing that limitation in the future.
