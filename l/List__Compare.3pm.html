Paquete: perl-list-compare

Licencias: GPL, PerlArtistic

List::Compare(3) Documentación de Perl aportada por el usuario List::Compare(3)

NOMBRE

List::Compare - Compara elementos de dos o más listas

VERSIÓN

Este documento se refiere a la versión 0.55 de List::Compare. Esta versión fue lanzada el 16 de agosto de 2020.

SINOPSIS

Lo más esencial:

@Llist = qw(abel abel baker camera delta edward fargo golfer);
@Rlist = qw(baker camera delta delta edward fargo golfer hilton);
$lc = List::Compare->new(\@Llist, \@Rlist);
@intersection = $lc->get_intersection;
@union = $lc->get_union;

... y así sucesivamente.

DISCUSIÓN: MODOS Y MÉTODOS

CASO REGULAR: COMPARAR DOS LISTAS

  • Constructor: new()

    Crea un objeto List::Compare. Coloca las dos listas en arreglos (nombrados o anónimos) y pasa referencias a los arreglos al constructor.

    @Llist = qw(abel abel baker camera delta edward fargo golfer);
@Rlist = qw(baker camera delta delta edward fargo golfer hilton);
$lc = List::Compare->new(\@Llist, \@Rlist);

    Por defecto, los métodos de List::Compare devuelven listas que están ordenadas usando el modo de ordenación por defecto de Perl "sort": ordenación alfabética ASCII. Si no necesitas que estas listas estén ordenadas, puedes lograr un impulso de velocidad construyendo el objeto List::Compare con la opción `unsorted`:

    $lc = List::Compare->new('-u', \@Llist, \@Rlist);

    o

    $lc = List::Compare->new('--unsorted', \@Llist, \@Rlist);
  • Constructor Alternativo

    Si prefieres una delimitación más explícita de los tipos de argumentos pasados a una función, puedes usar este constructor tipo 'hashref único' para construir un objeto List::Compare:

    $lc = List::Compare->new( { lists => [\@Llist, \@Rlist] } );

    o

    $lc = List::Compare->new( {
    lists    => [\@Llist, \@Rlist],
    unsorted => 1,
} );
  • get_intersection()

    Obtiene los elementos que aparecen al menos una vez en ambas listas (su intersección).

    @intersection = $lc->get_intersection;
  • get_union()

    Obtiene los elementos que aparecen al menos una vez en alguna de las listas (su unión).

    @union = $lc->get_union;
  • get_unique()

    Obtiene los elementos que aparecen (al menos una vez) solo en la primera lista.

    @Lonly = $lc->get_unique;
@Lonly = $lc->get_Lonly;    # alias
  • get_complement()

    Obtiene los elementos que aparecen (al menos una vez) solo en la segunda lista.

    @Ronly = $lc->get_complement;
@Ronly = $lc->get_Ronly;            # alias
  • get_symmetric_difference()

    Obtiene los elementos que aparecen al menos una vez en la primera o en la segunda lista, pero no en ambas.

    @LorRonly = $lc->get_symmetric_difference;
@LorRonly = $lc->get_symdiff;       # alias
@LorRonly = $lc->get_LorRonly;      # alias
  • get_bag()

    Crea una bolsa (bag) con todos los elementos de ambas listas. La bolsa difiere de la unión de las dos listas en que contiene tantas copias de elementos individuales como aparecen en las listas originales.

    @bag = $lc->get_bag;
  • Devolver referencias en lugar de listas

    Un enfoque alternativo a los métodos anteriores: Si no necesitas inmediatamente un arreglo como valor de retorno de la llamada al método, sino que simplemente necesitas una referencia a un arreglo (anónimo), usa uno de los siguientes métodos paralelos:

    $intersection_ref = $lc->get_intersection_ref;
$union_ref        = $lc->get_union_ref;
$Lonly_ref        = $lc->get_unique_ref;
$Lonly_ref        = $lc->get_Lonly_ref;                 # alias
$Ronly_ref        = $lc->get_complement_ref;
$Ronly_ref        = $lc->get_Ronly_ref;                 # alias
$LorRonly_ref     = $lc->get_symmetric_difference_ref;
$LorRonly_ref     = $lc->get_symdiff_ref;               # alias
$LorRonly_ref     = $lc->get_LorRonly_ref;              # alias
$bag_ref          = $lc->get_bag_ref;
  • is_LsubsetR()

    Devuelve un valor verdadero si el primer argumento pasado al constructor ('L' para 'izquierda') es un subconjunto del segundo argumento pasado al constructor ('R' para 'derecha').

    $LR = $lc->is_LsubsetR;

    Devuelve un valor verdadero si R es un subconjunto de L.

    $RL = $lc->is_RsubsetL;
  • is_LequivalentR()

    Devuelve un valor verdadero si las dos listas pasadas al constructor son equivalentes, es decir, si cada elemento de la lista izquierda ('L') aparece al menos una vez en la lista derecha ('R') y viceversa.

    $eqv = $lc->is_LequivalentR;
$eqv = $lc->is_LeqvlntR;            # alias
  • is_LdisjointR()

    Devuelve un valor verdadero si las dos listas pasadas al constructor son disjuntas, es decir, si las dos listas tienen cero elementos en común (o, lo que es lo mismo, si su intersección es un conjunto vacío).

    $disj = $lc->is_LdisjointR;
  • print_subset_chart()

    Imprime una tabla formateada mostrando si una lista es un subconjunto de la otra.

    $lc->print_subset_chart;
  • print_equivalence_chart()

    Imprime una tabla formateada mostrando si las dos listas son equivalentes (mismos elementos presentes al menos una vez en ambas).

    $lc->print_equivalence_chart;
  • is_member_which()

    Determina en cuál (si alguna) de las listas pasadas al constructor se puede encontrar una cadena dada. En contexto de lista, devuelve una lista de los índices en la lista de argumentos del constructor que corresponden a las listas que contienen la cadena que se está probando.

    @memb_arr = $lc->is_member_which('abel');

    En el ejemplo anterior, @memb_arr será:

    ( 0 )

    porque 'abel' se encuentra solo en @Al, que tiene la posición 0 en la lista de argumentos pasados a new().

    En contexto escalar, el valor devuelto es el número de listas pasadas al constructor en las que se encuentra una cadena dada.

    Al igual que con otros métodos de List::Compare que devuelven una lista, es posible que desees que el método anterior devuelva una referencia (escalar) a un arreglo que contenga la lista:

    $memb_arr_ref = $lc->is_member_which_ref('baker');

    En el ejemplo anterior, $memb_arr_ref será:

    [ 0, 1 ]

    porque 'baker' se encuentra en @Llist y @Rlist, que tienen las posiciones 0 y 1, respectivamente, en la lista de argumentos pasados a new().

    Nota: Los métodos is_member_which() y "is_member_which_ref" prueban solo una cadena a la vez y, por lo tanto, solo toman un argumento. Para probar más de una cadena a la vez, consulta el siguiente método, are_members_which().

  • are_members_which()

    Determina en cuál (si alguna) de las listas pasadas al constructor se pueden encontrar una o más cadenas dadas. Las cadenas a probar se colocan en un arreglo (nombrado o anónimo); se pasa una referencia a ese arreglo al método.

    $memb_hash_ref =
    $lc->are_members_which([ qw| abel baker fargo hilton zebra | ]);

    Nota: En versiones de List::Compare anteriores a la 0.25 (abril de 2004), las cadenas a probar podían pasarse como una lista plana. Esto ya no es posible; el argumento ahora debe ser una referencia a un arreglo.

    El valor devuelto es una referencia a un hash de arreglos. La clave de cada elemento en este hash es la cadena que se está probando. El valor de cada elemento es una referencia a un arreglo anónimo cuyos elementos son los índices en la lista de argumentos del constructor que corresponden a las listas que contienen las cadenas que se están probando.

Ejemplos

  • are_members_which()

    Determinar a qué listas pasadas como argumentos al constructor pertenece un elemento dado. El primer argumento es el elemento a buscar. El segundo argumento es una referencia a un hash donde las claves son los nombres (o índices) de las listas que se van a devolver. El valor asociado con cada clave es una matriz que contiene los índices de las listas en las que se encuentra el elemento. El valor devuelto es una referencia a un hash, que es una copia del hash de entrada. Si se omite un nombre de lista, el valor devuelto asociado con esa clave será una matriz vacía. Si no se pasa un segundo argumento, se asume que el usuario desea un hash de listas donde el nombre de la clave sea la lista que contiene el elemento y el valor sea una matriz de índices de esas listas.

    $memb_hash_ref = $lc->are_members_which('abel');

    En los ejemplos anteriores, $memb_hash_ref será:

    {
     abel     => [ 0    ],
     baker    => [ 0, 1 ],
     fargo    => [ 0, 1 ],
     hilton   => [    1 ],
     zebra    => [      ],
};

    Nota: are_members_which() puede aceptar más de un argumento; is_member_which() y is_member_which_ref() cada uno acepta solo un argumento. A diferencia de esos dos métodos, are_members_which() devuelve una referencia a un hash.

  • is_member_any()

    Determinar si una cadena dada se puede encontrar en *alguna* de las listas pasadas como argumentos al constructor. Devolver 1 si una cadena especificada se puede encontrar en alguna de las listas y 0 si no.

    $found = $lc->is_member_any('abel');

    En el ejemplo anterior, $found será 1 porque 'abel' se encuentra en una o más de las listas pasadas como argumentos a new().

  • are_members_any()

    Determinar si una o más cadenas especificadas se pueden encontrar en *alguna* de las listas pasadas como argumentos al constructor. Las cadenas a probar se colocan en una matriz (nombrada o anónima); se pasa una referencia a esa matriz a "are_members_any".

    $memb_hash_ref = $lc->are_members_any([ qw| abel baker fargo hilton zebra | ]);

    Nota: En versiones de List::Compare anteriores a la 0.25 (abril de 2004), las cadenas a probar se podían pasar como una lista plana. Esto ya no es posible; el argumento ahora debe ser una referencia a una matriz.

    El valor de retorno es una referencia a un hash donde la clave de un elemento es la cadena que se está probando y el valor del elemento es 1 si la cadena se puede encontrar en *alguna* de las listas y 0 si no. En los ejemplos anteriores, $memb_hash_ref será:

    {
     abel     => 1,
     baker    => 1,
     fargo    => 1,
     hilton   => 1,
     zebra    => 0,
};

    El valor de "zebra" es 0 porque "zebra" no se encuentra en ninguna de las listas pasadas como argumentos a new().

  • get_version()

    Devolver el número de versión actual de List::Compare.

    $vers = $lc->get_version;

Caso Acelerado: Cuando el Usuario Solo Quiere una Comparación Única

  • Constructor new()

    Si está seguro de que solo querrá los resultados de una *única* comparación, el cálculo puede acelerarse pasando '-a' o "'--accelerated" como primer argumento al constructor.

    @Llist = qw(abel abel baker camera delta edward fargo golfer);
@Rlist = qw(baker camera delta delta edward fargo golfer hilton);
$lca = List::Compare->new('-a', \@Llist, \@Rlist);

    o

    $lca = List::Compare->new('--accelerated', \@Llist, \@Rlist);

    Al igual que con el caso Regular de List::Compare, si no necesita que un método acelerado de List::Compare devuelva una lista ordenada, puede lograr un aumento de velocidad construyendo el objeto acelerado de List::Compare con la opción no ordenada:

    $lca = List::Compare->new('-u', '-a', \@Llist, \@Rlist);

    o

    $lca = List::Compare->new('--unsorted', '--accelerated', \@Llist, \@Rlist);
  • Constructor Alternativo

    Puede utilizar el formato de constructor de 'hashref único' para construir un objeto List::Compare que solicite el modo Acelerado:

    $lca = List::Compare->new( {
    lists    => [\@Llist, \@Rlist],
    accelerated => 1,
} );

    o

    $lca = List::Compare->new( {
    lists    => [\@Llist, \@Rlist],
    accelerated => 1,
    unsorted => 1,
} );
  • Métodos

    Todos los métodos de comparación disponibles en el caso Regular están disponibles para usted en el caso Acelerado también.

    @intersection     = $lca->get_intersection;
@union            = $lca->get_union;
@Lonly            = $lca->get_unique;
@Ronly            = $lca->get_complement;
@LorRonly         = $lca->get_symmetric_difference;
@bag              = $lca->get_bag;
$intersection_ref = $lca->get_intersection_ref;
$union_ref        = $lca->get_union_ref;
$Lonly_ref        = $lca->get_unique_ref;
$Ronly_ref        = $lca->get_complement_ref;
$LorRonly_ref     = $lca->get_symmetric_difference_ref;
$bag_ref          = $lca->get_bag_ref;
$LR               = $lca->is_LsubsetR;
$RL               = $lca->is_RsubsetL;
$eqv              = $lca->is_LequivalentR;
$disj             = $lca->is_LdisjointR;
                    $lca->print_subset_chart;
                    $lca->print_equivalence_chart;
@memb_arr         = $lca->is_member_which('abel');
$memb_arr_ref     = $lca->is_member_which_ref('baker');
$memb_hash_ref    = $lca->are_members_which(
                        [ qw| abel baker fargo hilton zebra | ]);
$found            = $lca->is_member_any('abel');
$memb_hash_ref    = $lca->are_members_any(
                        [ qw| abel baker fargo hilton zebra | ]);
$vers             = $lca->get_version;

    Todas las alias para métodos disponibles en el caso Regular están disponibles para usted en el caso Acelerado también.

Caso Múltiple: Comparar Tres o Más Listas

  • Constructor new()

    Crea un objeto List::Compare. Coloque cada lista en una matriz y pase referencias a las matrices al constructor.

    @Al     = qw(abel abel baker camera delta edward fargo golfer);
@Bob    = qw(baker camera delta delta edward fargo golfer hilton);
@Carmen = qw(fargo golfer hilton icon icon jerky kappa);
@Don    = qw(fargo icon jerky);
@Ed     = qw(fargo icon icon jerky);
$lcm = List::Compare->new(\@Al, \@Bob, \@Carmen, \@Don, \@Ed);

    Al igual que con el caso Regular de List::Compare, si no necesita que un método de List::Compare devuelva una lista ordenada, puede lograr un aumento de velocidad construyendo el objeto con la opción no ordenada:

    $lcm = List::Compare->new('-u', \@Al, \@Bob, \@Carmen, \@Don, \@Ed);

    o

    $lcm = List::Compare->new('--unsorted', \@Al, \@Bob, \@Carmen, \@Don, \@Ed);
  • Constructor Alternativo

    Puede utilizar el formato de constructor de 'hashref único' para construir un objeto List::Compare que procese tres o más listas a la vez:

    $lcm = List::Compare->new( {
    lists    => [\@Al, \@Bob, \@Carmen, \@Don, \@Ed],
} );

    o

    $lcm = List::Compare->new( {
    lists    => [\@Al, \@Bob, \@Carmen, \@Don, \@Ed],
    unsorted => 1,
} );
  • Métodos Análogos a los Métodos del Caso Regular y Acelerado en Modo Múltiple

    Cada método de List::Compare disponible en los casos Regular y Acelerado tiene un análogo en el caso Múltiple. Sin embargo, los resultados producidos generalmente requieren una especificación más cuidadosa.

    Nota: Ciertos de los siguientes métodos disponibles en el modo Múltiple de List::Compare toman argumentos numéricos opcionales donde esos números representan la posición del índice de una lista particular en la lista de argumentos pasados al constructor. Para especificar esta posición de índice correctamente,

  • comience la cuenta en 0 (como es habitual con los índices de matrices de Perl); y
  • *no* cuente ninguna opción no ordenada ('-u' o '--unsorted') que preceda a las referencias de matriz en la propia lista de argumentos del constructor.

Ejemplo:

$lcmex = List::Compare->new('--unsorted', \@alpha, \@beta, \@gamma);

Para el propósito de proporcionar un argumento numérico a un método que opcionalmente toma tal argumento, se omite '--unsorted', @alpha es 0, @beta es 1, y así sucesivamente.

  • get_intersection()

    Obtener los elementos que se encuentran en *cada una* de las listas pasadas al constructor (su intersección):

    @intersection = $lcm->get_intersection;
  • get_union()

    Obtener los elementos que se encuentran en *alguna* de las listas pasadas al constructor (su unión):

    @union = $lcm->get_union;
  • get_unique()

    Para obtener aquellos elementos que aparecen solo en *una lista particular*, proporcione a get_unique() la posición del índice de esa lista en la lista de argumentos pasados al constructor (sin contar ninguna opción '-u' o '--unsorted').

    Ejemplo: @Carmen tiene la posición del índice 2 en @_ del constructor. Para obtener elementos únicos de @Carmen:

    @Lonly = $lcm->get_unique(2);

    Si no se pasa ninguna posición de índice a get_unique(), se usará 0 por defecto e informará los elementos únicos de la primera lista pasada al constructor.

  • get_complement()

    Para obtener aquellos elementos que se encuentran en cualquier lista *que no sea una lista particular*, proporcione a get_complement() la posición del índice de esa lista en la lista de argumentos pasados al constructor (sin contar ninguna opción '-u' o '--unsorted').

    Ejemplo: @Don tiene la posición del índice 3 en @_ del constructor. Para obtener elementos no encontrados en @Don:

    @Ronly = $lcm->get_complement(3);

    Si no se pasa ninguna posición de índice a get_complement(), se usará 0 por defecto e informará los elementos encontrados en cualquier lista que no sea la primera lista pasada al constructor.

  • get_symmetric_difference()

    Obtener aquellos elementos que cada uno

    f que aparece en una sola de las listas pasadas al constructor (su diferencia simétrica);

    @LorRonly = $lcm->get_symmetric_difference;
  • get_bag()

    Crea un "bag" (bolsa) con todos los elementos encontrados en cualquier lista. El "bag" difiere de la unión de las listas en que contiene tantas copias de elementos individuales como aparecen en las listas originales.

    @bag = $lcm->get_bag;
  • Devolver referencia en lugar de lista

    Un enfoque alternativo a los métodos anteriores: Si no requiere inmediatamente un array como valor de retorno de la llamada al método, sino que simplemente necesita una referencia a un array, use uno de los siguientes métodos paralelos:

    $intersection_ref = $lcm->get_intersection_ref;
$union_ref        = $lcm->get_union_ref;
$Lonly_ref        = $lcm->get_unique_ref(2);
$Ronly_ref        = $lcm->get_complement_ref(3);
$LorRonly_ref     = $lcm->get_symmetric_difference_ref;
$bag_ref          = $lcm->get_bag_ref;
  • is_LsubsetR()

    Para determinar si una lista particular es un subconjunto de otra lista pasada al constructor, proporcione a is_LsubsetR() la posición del índice del presunto subconjunto (ignorando cualquier opción no ordenada), seguida de la posición del índice del presunto superconjunto.

    Ejemplo: Para determinar si @Ed es un subconjunto de @Carmen, llame a:

    $LR = $lcm->is_LsubsetR(4,2);

    Se devuelve un valor verdadero (1) si la lista del lado izquierdo es un subconjunto de la lista del lado derecho; de lo contrario, se devuelve un valor falso (0).

    Si no se pasan argumentos, is_LsubsetR() usa por defecto "(0,1)" y compara las dos primeras listas pasadas al constructor.

  • is_LequivalentR()

    Para determinar si dos listas particulares son equivalentes entre sí, proporcione a "is_LequivalentR" sus posiciones de índice en la lista de argumentos pasados al constructor (ignorando cualquier opción no ordenada).

    Ejemplo: Para determinar si @Don y @Ed son equivalentes, llame a:

    $eqv = $lcm->is_LequivalentR(3,4);

    Se devuelve un valor verdadero (1) si las listas son equivalentes; de lo contrario, un valor falso (0).

    Si no se pasan argumentos, "is_LequivalentR" usa por defecto "(0,1)" y compara las dos primeras listas pasadas al constructor.

  • is_LdisjointR()

    Para determinar si dos listas particulares son disjuntas entre sí (es decir, no tienen miembros en común), proporcione a "is_LdisjointR" sus posiciones de índice en la lista de argumentos pasados al constructor (ignorando cualquier opción no ordenada).

    Ejemplo: Para determinar si @Don y @Ed son disjuntas, llame a:

    $disj = $lcm->is_LdisjointR(3,4);

    Se devuelve un valor verdadero (1) si las listas son equivalentes; de lo contrario, un valor falso (0).

    Si no se pasan argumentos, "is_LdisjointR" usa por defecto "(0,1)" y compara las dos primeras listas pasadas al constructor.

  • print_subset_chart()

    Imprime de forma bonita un gráfico que muestra las relaciones de subconjuntos entre las diversas listas de origen:

    $lcm->print_subset_chart;
  • print_equivalence_chart()

    Imprime de forma bonita un gráfico que muestra las relaciones de equivalencia entre las diversas listas de origen:

    $lcm->print_equivalence_chart;
  • is_member_which()

    Determine en cuál (si es que en alguna) de las listas pasadas al constructor se puede encontrar una cadena dada. En contexto de lista, devuelva una lista de los índices en la lista de argumentos del constructor (ignorando cualquier opción no ordenada) que corresponden a las listas que contienen la cadena que se está probando.

    @memb_arr = $lcm->is_member_which('abel');

    En el ejemplo anterior, @memb_arr será:

    ( 0 )

    porque 'abel' se encuentra solo en @Al, que ocupa la posición 0 en la lista de argumentos pasados a new().

  • is_member_which_ref()

    Al igual que con otros métodos de List::Compare que devuelven una lista, es posible que desee que el método anterior devuelva una referencia (escalar) a un array que contenga la lista:

    $memb_arr_ref = $lcm->is_member_which_ref('jerky');

    En el ejemplo anterior, $memb_arr_ref será:

    [ 3, 4 ]

    porque 'jerky' se encuentra en @Don y @Ed, que ocupan las posiciones 3 y 4, respectivamente, en la lista de argumentos pasados a new().

    Nota: los métodos is_member_which() y "is_member_which_ref" prueban solo una cadena a la vez y, por lo tanto, toman solo un argumento. Para probar más de una cadena a la vez, consulte el siguiente método, are_members_which().

  • are_members_which()

    Determine en "cuál" (si es que en alguna) de las listas pasadas al constructor se pueden encontrar una o más cadenas dadas. Las cadenas a probar se colocan en un array anónimo, una referencia al cual se pasa al método.

    $memb_hash_ref =
    $lcm->are_members_which([ qw| abel baker fargo hilton zebra | ]);

    Nota: En versiones de List::Compare anteriores a la 0.25 (abril de 2004), las cadenas a probar podían pasarse como una lista plana. Esto ya no es posible; el argumento ahora debe ser una referencia a un array anónimo.

    El valor de retorno es una referencia a un hash de arrays. La clave de cada elemento en este hash es la cadena que se está probando. El valor de cada elemento es una referencia a un array anónimo cuyos elementos son los índices en la lista de argumentos del constructor que corresponden a las listas que contienen las cadenas que se están probando.

    En los dos ejemplos anteriores, $memb_hash_ref será:

    {
     abel     => [ 0             ],
     baker    => [ 0, 1          ],
     fargo    => [ 0, 1, 2, 3, 4 ],
     hilton   => [    1, 2       ],
     zebra    => [               ],
};

    Nota: are_members_which() puede tomar más de un argumento; is_member_which() y is_member_which_ref() toman solo un argumento cada uno. are_members_which() devuelve una referencia a un hash; los otros métodos devuelven una lista o una referencia a un array que contiene esa lista, dependiendo del contexto.

  • is_member_any()

    Determine si una cadena dada se puede encontrar en alguna de las listas pasadas como argumentos al constructor.

    $found = $lcm->is_member_any('abel');

    Devuelve 1 si una cadena especificada se puede encontrar en alguna de las listas y 0 si no.

    En el ejemplo anterior, $found será 1 porque 'abel' se encuentra en una o más de las listas pasadas como argumentos a new().

  • are_members_any()

    Determine si una o más cadenas especificadas se pueden encontrar en alguna de las listas pasadas como argumentos al constructor. Las cadenas a probar se colocan en un array (anónimo o con nombre), una referencia al cual se pasa al método.

    $memb_hash_ref = $lcm->are_members_any([ qw| abel baker fargo hilton zebra | ]);

    Nota: En versiones de List::Compare anteriores a la 0.25 (abril de 2004), las cadenas a probar podían pasarse como una lista plana. Esto ya no es posible; el argumento ahora debe ser una referencia a un array anónimo.

    DISCUSIÓN: Principios

    Comentarios Generales

    List::Compare es una implementación orientada a objetos de código común en Perl (ver "Historia, Referencias y Desarrollo" a continuación) utilizado para determinar relaciones interesantes entre dos o más listas a la vez. Un objeto List::Compare se crea y automáticamente calcula los valores necesarios para proporcionar los resultados adecuados a los métodos de List::Compare. En la implementación actual, los métodos de List::Compare devuelven nuevas listas que contienen los elementos encontrados en cualquier lista designada (único), cualquier lista diferente de una lista designada (complemento), la intersección y la unión de todas las listas, y así sucesivamente. List::Compare también tiene (a) métodos para devolver valores booleanos que indican si una lista es un subconjunto de otra y si dos listas son equivalentes entre sí y (b) métodos para imprimir gráficos simples que muestran las relaciones de subconjunto y equivalencia entre listas en forma de tablas.

    Excepto por el método get_bag() de List::Compare, instancias múltiples de un elemento en una lista se cuentan solo una vez con respecto a la intersección, unión, etc. de las dos listas. En particular, List::Compare considera dos listas equivalentes si cada elemento de la primera lista se puede encontrar en la segunda lista y *viceversa*. 'Equivalencia' en este uso no tiene en cuenta la frecuencia con que los elementos aparecen en una lista o su orden dentro de la otra.

    Modos de List::Compare

    En su implementación actual, List::Compare tiene cuatro modos de operación.

    • Modo Regular

      El modo Regular de List::Compare se basa en List::Compare v0.11 – la primera versión de List::Compare publicada en CPAN (junio 2002). Compara solo dos listas a la vez. Internamente, su inicializador realiza todos los cálculos necesarios para reportar cualquier comparación deseada y su constructor almacena los resultados de estos cálculos. Sus métodos públicos solo reportan estos resultados.

      Esta aproximación tiene la ventaja de que si necesitas examinar más de una forma de comparación entre dos listas (p. ej., la unión, la intersección y la diferencia simétrica de dos listas), las comparaciones se calculan previamente. Esta aproximación es eficiente porque ciertos tipos de comparación suponen que otros tipos ya hayan sido calculados. Por ejemplo, para calcular la diferencia simétrica de dos listas, primero debe determinarse los elementos únicos de cada una de las dos listas.

    • Modo Acelerado

      La implementación actual de List::Compare ofrece la opción de obtener resultados aún más rápidos siempre que solo necesites el resultado de una única forma de comparación entre dos listas. (p. ej., solo la unión – nada más). En el modo Acelerado, el inicializador de List::Compare no realiza ningún cálculo y su constructor almacena solo referencias a las dos listas de origen. Todos los cálculos necesarios para reportar resultados se difieren a las llamadas a los métodos.

      El usuario selecciona esta aproximación pasando el parámetro de opción '-a' al constructor antes de pasar las referencias a las dos listas de origen. List::Compare nota el parámetro de opción y se cambia silenciosamente a modo Acelerado. Desde el punto de vista del usuario, no hay diferencia en el código o en los resultados.

      El benchmarking sugiere que el modo Acelerado de List::Compare (a) es más rápido que su modo Regular cuando solo se solicita una comparación; (b) es aproximadamente tan rápido como el modo Regular cuando se solicitan dos comparaciones; y (c) se vuelve considerablemente más lento que el modo Regular cuando se solicitan cada vez más comparaciones que superan dos.

    • Modo Múltiple

      List::Compare ahora ofrece la posibilidad de comparar tres o más listas a la vez. Simplemente almacena las listas adicionales en arrays y pasa referencias a esos arrays al constructor. List::Compare detecta que más de dos listas han sido pasadas al constructor y se cambia silenciosamente a modo Múltiple.

      Como se describe en el resumen anterior, comparar más de dos listas a la vez ofrece un amplio y complejo conjunto de métodos de comparación. Un elemento puede aparecer solo en una lista de origen, en todas las listas de origen o en un número de listas entre una y todas. El significado de "unión", "intersección" y "diferencia simétrica" no cambia conceptualmente cuando se pasan a múltiples listas, ya que son propiedades de todas las listas consideradas. En contraste, el significado de "único", "complemento", "subconjunto" y "equivalente" cambia porque son propiedades de una lista comparada con otra o con todas las otras listas combinadas.

      List::Compare considera esta complejidad al permitir que le pases argumentos a los métodos públicos para solicitar resultados con respecto a una lista específica (para get_unique() y get_complement()) o a una pareja específica de listas (para is_LsubsetR() y is_LequivalentR()).

      List::Compare también considera esta complejidad al ofrecer los nuevos métodos get_shared() y get_nonintersection() descritos en el resumen anterior.

    • Modo Múltiple Acelerado

      Desde la versión 0.25 introducida en abril de 2004, List::Compare ofrece la posibilidad de realizar cálculos acelerados de una comparación entre tres o más listas a la vez. Simplemente almacena las listas adicionales en arrays y pasa referencias a esos arrays al constructor, precedidas por el parámetro de opción '-a' como se hizo con el modo acelerado del simple (dos listas solo). List::Compare detecta que más de dos listas han sido pasadas al constructor y se cambia silenciosamente a modo Múltiple Acelerado.

    • Opción No Ordenada

      Cuando List::Compare se utiliza para devolver listas que representan comparaciones de varias listas (p. ej., la unión o la intersección de varias listas), las listas devueltas son, por defecto, ordenadas usando el modo "sort" de Perl: ordenación ascendente. El ordenamiento produce resultados más fácilmente legibles por el usuario pero puede implicar un costo de rendimiento.

      Si no necesitas resultados ordenados, puedes evitar el costo de rendimiento al evitar la llamada al constructor de List::Compare con la opción no ordenada. Esto se hace llamando '-u' o '--unsorted' como el primer argumento pasado al constructor, es decir, como un argumento llamado antes de pasar cualquier referencia a listas al constructor.

      Nota: Si estás llamando a List::Compare en el modo Acelerado o en el modo Múltiple Acelerado y deseas tener las listas devueltas en orden no ordenado, primero pasa el argumento para la opción no ordenada ('-u' o '--unsorted') y luego pasa el argumento para el modo Acelerado ('-a' o '--accelerated').

    Métodos Misceláneos

    No sería apropiado llamar a get_shared() y get_nonintersection() en el modo Regular o en el modo Acelerado, ya que son conceptualmente basados en comparar más de dos listas. Sin embargo, siempre existe la posibilidad de que un usuario esté comparando solo dos listas (acelerado o no) y por error llame a uno de esos dos métodos. Para evitar errores de ejecución fatales y advertirte de usar un método más apropiado, estos dos métodos están definidos para los modos Regular y Acelerado para devolver resultados adecuados pero también generar un mensaje de advertencia (carp) que te indica que reescribas el código.

    Análogamente, el método is_RsubsetL() es apropiado para los modos Regular y Acelerado pero no es adecuado para el modo Múltiple. Como medida defensiva, se ha definido para el modo Múltiple para devolver resultados adecuados pero también generar un mensaje de advertencia (carp) que te indica que reescribas el código.

    En List::Compare v0.11 y versiones anteriores, el autor proporcionó alias para varios métodos basados en la suposición de que las listas de origen se referirían a 'A' y 'B'. Ahora que puedes comparar más de dos listas, el autor siente que sería más adecuado referirte a los elementos de listas de dos argumentos como los elementos de la izquierda y de la derecha. Por eso, estamos desaconsejando el uso de métodos como get_Aonly(), get_Bonly() y get_AorBonly() como alias de get_unique(), get_complement() y get_symmetric_difference(). Sin embargo, para garantizar la compatibilidad inversa con el vasto público de programadores Perl que usan versiones anteriores de List::Compare (todos 10e1 de ustedes), estos y otros métodos relacionados con relaciones de subconjunto todavía están definidos.

    List::Compare::SeenHash Descontinuado a Partir de la Versión 0.26

    Antes de la v0.26, introducida el 11 de abril de 2004, si deseabas pasar referencias a listas de 'seen-hash' al constructor de List::Compare en lugar de referencias a arrays, tendrías que llamar a un módulo diferente: List::Compare::SeenHash. El código para eso era así:

    use List::Compare::SeenHash;
my %Llist = (
   abel     => 2,
   baker    => 1,
   camera   => 1,
   delta    => 1,
   edward   => 1,
   fargo    => 1,
   golfer   => 1,
);
my %Rlist = (
   baker    => 1,
   camera   => 1,
   delta    => 2,
   edward   => 1,
   fargo    => 1,
   golfer   => 1,
   hilton   => 1,
);
my $lcsh = List::Compare::SeenHash->new(\%Llist, \%Rlist);

    List::Compare::SeenHash se descontinuó a partir de la versión 0.26. Toda su funcionalidad (y más) ha sido implementada en List::Compare mismo, ya que un usuario ahora puede pasar, o un conjunto de referencias a arrays o un conjunto de referencias a 'seen-hash' al constructor de List::Compare.

    Para simplificar el mantenimiento futuro de List::Compare, List::Compare::SeenHash.pm ya no se distribuirá con List::Compare, ni los archivos en la suite de pruebas que probaron List::Compare::SeenHash durante la instalación se distribuirán.

    Si aún necesitas List::Compare::SeenHash, usa la versión 0.25 de CPAN, o simplemente edita tus programas Perl que usaban List::Compare::SeenHash. Estos scripts pueden ser editados rápidamente con, por ejemplo, este comando de edición en un editor de texto Unix vi:

    :1,$s/List::Compare::SeenHash/List::Compare/gc

    Una Interfaz No Orientada a Objetos: List::Compare::Functional

    La versión 0.21 de List::Compare introdujo List::Compare::Functional, una interfaz funcional (es decir,, no orientada a objetos) para funciones de comparación de listas. List::Compare::Functional soporta las mismas funciones que List::Compare. Funciona de manera similar a los modos Acelerado y Múltiple Acelerado de List::Compare (descritos anteriormente), pero no requiere el uso del parámetro de opción '-a' en la llamada a la función. List::Compare::Functional devolverá comparaciones no ordenadas de dos listas pasando '-u' o '--unsorted' como el primer argumento a la función. Consulta la documentación de List::Compare::Functional para aprender cómo importar sus funciones en tu paquete principal.

    HISTORIAL, REFERENCIAS Y DESARROLLO

    El Código en Sí

    List::Compare se basa en código presentado por Tom Christiansen y Nathan Torkington en Perl Cookbook http://www.oreilly.com/catalog/cookbook/ (también conocido como el libro 'Ram'), O'Reilly & Associates, 1998, recetas 4.7 y 4.8. Código similar se presenta en el libro Camel: Programming Perl, por Larry Wall, Tom Christiansen, Jon Orwant. http://www.oreilly.com/catalog/pperl3/, 3ª ed., O'Reilly & Associates, 2000. El código de comparación de listas es tan básico y "perlish" que sospecho que pudo haber sido escrito por el propio Larry en los albores de Perl. El método get_bag() se inspiró en el módulo Set::Bag de Jarkko Hietaniemi y el módulo Set::Array de Daniel Berger, ambos disponibles en CPAN.

    El objetivo original de List::Compare fue simplemente poner este código en un marco modular y orientado a objetos. Ese marco, como era de esperar, se toma en su mayor parte del libro de Damian Conway, Object Oriented Perl http://www.manning.com/Conway/index.html, Manning Publications, 2000.

    Con la adición de los modos Acelerado, Múltiple y Múltiple Acelerado, List::Compare se expande considerablemente tanto en tamaño como en capacidades. Sin embargo, el código de Cookbook de Tom y Nat todavía yace en su núcleo: el uso de hashes como tablas de consulta para registrar elementos vistos en las listas. Tenga en cuenta: List::Compare no se preocupa por ningún concepto de 'igualdad' entre listas que dependa de la frecuencia con la que, o el orden en el que, aparecen los elementos en las listas a comparar. Si esto no satisface sus necesidades, debería buscar en otro lugar o escribir su propio módulo.

La versión 0.31 debe su inspiración a una charla en la YAPC de Buffalo y a una charla anterior en YAPC::EU::2003 en París. En París escuché a Paul Johnson hablar sobre su módulo CPAN Devel::Cover y sobre el análisis de cobertura en general. Ese material estaba por encima de mi cabeza en ese momento, pero en Buffalo escuché a Andy Lester discutir Devel::Cover como parte de su discusión sobre pruebas y del proyecto Phalanx (http://qa.perl.org/phalanx). Esta vez lo entendí, y al regresar de Buffalo apliqué Devel::Cover a List::Compare y escribí pruebas adicionales para mejorar su cobertura de subrutinas y sentencias. Además, añadí dos nuevos métodos, "get_unique_all" y "get_complement_all". Al escribir estos dos métodos, seguí un modelo de desarrollo guiado por pruebas mucho más que en versiones anteriores de List::Compare y mis otros módulos CPAN. ¿El resultado? El conjunto de pruebas de List::Compare creció en más de 3300 pruebas hasta casi 23.000 pruebas.

    En el Segundo New York Perl Hackathon (2 de mayo de 2015), se creó un proyecto para solicitar mejoras de rendimiento en ciertas funciones de List::Compare (https://github.com/nyperlmongers/nyperlhackathon2015/wiki/List-Compare-Performance-Improvements). El participante del Hackathon Michael Rawson envió una solicitud de extracción con cambios en List::Compare::Base::_Auxiliary. Después de evaluar el rendimiento de estas revisiones, se aceptó un parche que incorporaba la solicitud de extracción, lo que llevó a la versión 0.53 de CPAN.

    Si te gusta List::Compare, te encantará...

    Mientras preparaba este módulo para su distribución a través de CPAN, tuve la oportunidad de estudiar varios otros módulos ya disponibles en CPAN. Cada uno de estos módulos es más sofisticado que List::Compare, lo cual no es sorprendente ya que todo lo que List::Compare originalmente aspiraba a hacer era evitar escribir código de Cookbook repetidamente. Aquí hay una breve descripción de las características de estos módulos. (Advertencia: la siguiente discusión solo es válida a partir de junio de 2002. Algunos de estos módulos pueden haber cambiado desde entonces).

    • Algorithm::Diff - Calcula diferencias 'inteligentes' entre dos archivos/listas (http://search.cpan.org/dist/Algorithm-Diff/)

      Algorithm::Diff es un módulo sofisticado escrito originalmente por Mark-Jason Dominus, mantenido posteriormente por Ned Konz, y ahora por Tye McQueen. Piensa en la utilidad Unix "diff" y estarás en el camino correcto. Algorithm::Diff exporta métodos como "diff", que "calcula el conjunto más pequeño de adiciones y eliminaciones necesarias para convertir la primera secuencia en la segunda, y devuelve una descripción de estos cambios". Algorithm::Diff se ocupa principalmente de la secuencia de elementos dentro de dos listas. No exporta funciones para intersección, unión, estado de subconjunto, etc.

    • Array::Compare - Extensión de Perl para comparar arrays (http://search.cpan.org/dist/Array-Compare/)

      Array::Compare, de Dave Cross, pregunta si dos arrays son iguales o diferentes haciendo un "join" en cada cadena con un carácter separador y comparando las cadenas resultantes. Al igual que List::Compare, es un módulo orientado a objetos. Una característica sofisticada de Array::Compare es que te permite especificar cómo se debe evaluar el 'espacio en blanco' en un array (un elemento que no está definido, la cadena vacía o el espacio en blanco dentro de un elemento) a efectos de determinar la igualdad o la diferencia. No proporciona directamente métodos para intersección y unión.

    • Data::Compare - compara estructuras de datos de Perl (http://search.cpan.org/dist/Data-Compare/)

      Esta biblioteca compara estructuras de datos de Perl recursivamente. ¡Recomendado por Slaven Rezić!

    • List::Util - Una selección de subrutinas de utilidad general para listas (http://search.cpan.org/dist/Scalar-List-Utils/)

      List::Util, de Graham Barr, exporta una variedad de funciones simples y útiles para operar en una lista a la vez. La función "min" devuelve el valor numérico más bajo en una lista; la función "max" devuelve el valor más alto; y así sucesivamente. List::Compare difiere de List::Util en que está orientado a objetos y que funciona en dos cadenas a la vez en lugar de solo una, pero tiene como objetivo ser tan simple y útil como List::Util. List::Util se incluirá en la distribución estándar de Perl a partir de Perl 5.8.0.

    HISTORY, REFERENCES AND DEVELOPMENT

    See the List::Compare Perl module for a list of alternate implementations and related modules. Those modules are:

    • List::Compare (http://search.cpan.org/dist/List-Compare/) by James E. Keenan. Provides a very fast and simple way to compare lists of strings, numbers, or both.

    • List::MoreUtils (http://search.cpan.org/dist/List-MoreUtils/), by Tassilo von Parseval, building on code by Terrence Brannon, provides methods which extend List::Util's functionality.
    • Quantum::Superpositions (http://search.cpan.org/dist/Quantum-Superpositions/), originally by Damian Conway, now maintained by Steven Lembark is useful if, in addition to comparing lists, you need to emulate quantum supercomputing as well. Not for the eigen-challenged.
    • Set::Scalar - basic set operations (http://search.cpan.org/dist/Set-Scalar/)

      Set::Bag - bag (multiset) class (http://search.cpan.org/dist/Set-Bag/)

      Both of these modules are by Jarkko Hietaniemi. Set::Scalar has methods to return the intersection, union, difference and symmetric difference of two sets, as well as methods to return items unique to a first set and complementary to it in a second set. It has methods for reporting considerably more variants on subset status than does List::Compare. However, benchmarking suggests that List::Compare, at least in Regular mode, is considerably faster than Set::Scalar for those comparison methods which List::Compare makes available.

      Set::Bag enables one to deal more flexibly with the situation in which one has more than one instance of an element in a list.

    • Set::Array - Arrays as objects with lots of handy methods (including set comparisons) and support for method chaining. (http://search.cpan.org/dist/Set-Array/)

      Set::Array, by Daniel Berger, now maintained by Ron Savage, ''aims to provide built-in methods for operations that people are always asking how to do,and which already exist in languages like Ruby.'' Among the many methods in this module are some for intersection, union, etc. To install Set::Array, you must first install the Want module, also available on CPAN.
