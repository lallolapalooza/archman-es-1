Layout::PatternLayout(3) Documentación de Contribución de Usuarios de Perl Layout::PatternLayout(3)

NOMBRE

Log::Log4perl::Layout::PatternLayout - Layout de Patrón

SINOPSIS

use Log::Log4perl::Layout::PatternLayout;
my $layout = Log::Log4perl::Layout::PatternLayout->new(
                                                 "%d (%F:%L)> %m");

DESCRIPCIÓN

Crea un layout de patrón según http://jakarta.apache.org/log4j/docs/api/org/apache/log4j/PatternLayout.html y un par de extensiones específicas de Log::Log4perl.

El método new() crea un nuevo PatternLayout, especificando su formato de registro. El string de formato puede contener un número de marcadores de posición que serán reemplazados por el motor de registro cuando sea el momento de registrar el mensaje:

%c Categoría del evento de registro.
%C Nombre completo del paquete (o clase) del llamador
%d Fecha actual en formato yyyy/MM/dd hh:mm:ss
%d{...} Fecha actual en formato personalizado (ver abajo)
%F Archivo donde ocurrió el evento de registro
%H Nombre del host (si Sys::Hostname está disponible)
%l Nombre completo del método llamador seguido por el
   nombre del archivo fuente del llamador y el número de línea entre 
   paréntesis.
%L Número de línea dentro del archivo donde se emitió la instrucción de registro
%m El mensaje a registrar
%m{chomp} Mensaje de registro, eliminado el salto de línea final
%m{indent} Mensaje de registro, multilíneas indentadas para que se alineen con la primera
%m{indent=n} Mensaje de registro, multilíneas indentadas por n espacios
%M Método o función donde se emitió la solicitud de registro
%n Salto de línea (independiente del SO)
%p Prioridad/nivel del evento de registro (%p{1} muestra la primera letra)
%P pid del proceso actual
%r Número de milisegundos transcurridos desde el inicio del programa hasta el evento de registro
%R Número de milisegundos transcurridos desde el último evento de registro hasta el evento de registro actual
%T Una traza de pila de las funciones llamadas
%x El NDC (ver abajo) más superior
%X{key} La entrada 'key' del MDC (ver abajo)
%% Un signo de porcentaje literal (%)

NDC y MDC se explican en "Contexto de Diagnóstico Anidado (NDC)" en Log::Log4perl y "Contexto de Diagnóstico Mapeado (MDC)" en Log::Log4perl.

La granularidad de los valores de tiempo es milisegundos si Time::HiRes está disponible. Si no, solo se utilizan segundos completos.

De vez en cuando, alguien usa el patrón "%m%n" y además proporciona un salto de línea adicional en el mensaje de registro (por ejemplo, "->log("mensaje\n")". Para evitar imprimir un salto de línea adicional en este caso, PatternLayout eliminará el salto de línea del mensaje, imprimiendo solo un salto de línea. Esta opción puede ser controlada por la opción "message_chomp_before_newline" de PatternLayout. Consulte "Opciones avanzadas" para más detalles.

Cuantificar marcadores de posición

Todos los marcadores de posición pueden ser extendidos con instrucciones de formato, al igual que en printf:

%20c   Reserva 20 caracteres para la categoría, justificación a la derecha y relleno
       con espacios si es más corto
%-20c  Lo mismo que %20c, pero justificación a la izquierda y relleno del lado derecho 
       con espacios
%09r   Relleno con ceros del número de milisegundos a 9 dígitos
%.8c   Especifica el ancho máximo del campo y hace que el formateador
       corte el resto del valor

Ajuste fino con llaves

Algunos marcadores de posición tienen funciones especiales definidas si agregas llaves con contenido después de ellos:

%c{1}  Muestra solo el componente de categoría más a la derecha, útil en jerarquías
       de clases grandes (Foo::Baz::Bar -> Bar)
%c{2}  Muestra solo los dos componentes de categoría más a la derecha
       (Foo::Baz::Bar -> Baz::Bar)
%F     Muestra el archivo fuente incluyendo la ruta completa
%F{1}  Solo muestra el nombre del archivo
%F{2}  Muestra el nombre del archivo y el último componente de la ruta (dir/test.log)
%F{3}  Muestra el nombre del archivo y los dos últimos componentes de la ruta (d1/d2/test.log)
%M     Muestra el nombre completo del método/función
%M{1}  Solo muestra el nombre del método (foo)
%M{2}  Muestra el nombre del método y el último componente de la ruta (main::foo)

De esta manera, puedes reducir la categoría mostrada o limitar los componentes de archivo/ruta para ahorrar espacio en tus registros.

Ajuste fino de la fecha

Si no estás satisfecho con el formato predeterminado de %d para la fecha, que se ve así:

yyyy/MM/DD HH:mm:ss

(que es ligeramente diferente de Log4j, que usa "yyyy-MM-dd HH:mm:ss,SSS") eres libre de ajustarlo para mostrar solo ciertas características de una fecha, de acuerdo con SimpleDateFormat en el Mundo Java (http://docs.oracle.com/javase/8/docs/api/java/text/SimpleDateFormat.html):

%d{HH:mm}     "23:45" -- Solo muestra horas y minutos
%d{yy, EEEE}  "02, Lunes" -- Solo muestra el año de dos dígitos 
                              y el día de la semana escrito
%d{e}         "1473741760" -- Segundos de época
%d{h a}       "12 PM"      -- Hora y marcador am/pm
... y muchos más

Para una lista exhaustiva de todas las características de fecha admitidas, consulta Log::Log4perl::DateFormat.

cspecs personalizados

En primer lugar, "cspecs" es la abreviatura de "especificadores de conversión", que es el término de log4j y de printf(3) para lo que Mike llama "marcadores de posición". Sugerí "cspecs" para esta parte de la API antes de ver que Mike usaba "marcadores de posición" consistentemente en la documentación de log4perl. Ah, las alegrías de la colaboración ;=) --kg

Si el corpus existente de marcadores de posición/cspecs no es suficiente para ti, puedes crear los tuyos fácilmente:

#'U' un cspec definido por el usuario global     
log4j.PatternLayout.cspec.U = sub { return "UID: $< "}

#'K' cspec local al appndr1                 (pid en hexadecimal)
log4j.appender.appndr1.layout.cspec.K = sub { return sprintf "%1x", $$}

#y ahora puedes usarlos
log4j.appender.appndr1.layout.ConversionPattern = %K %U %m%n

El beneficio de este enfoque es que puedes definir y usar los cspecs justo uno al lado del otro en el archivo de configuración.

Si eres de los que prefieren la API, también existe esta llamada:

Log::Log4perl::Layout::PatternLayout::
                add_global_cspec('Z', sub {'zzzzzzzz'}); #¿dormir?

Cuando se está ensamblando el mensaje de registro, tu subrutina anónima será llamada con estos argumentos:

($layout, $message, $category, $priority, $caller_level);

layout: la referencia al objeto PatternLayout que la llamó
message: el mensaje de registro (%m)
category: por ejemplo, groceries.beverages.adult.beer.schlitz
priority: por ejemplo, DEBUG|WARN|INFO|ERROR|FATAL
caller_level: cuántos niveles hacia atrás en la pila de llamadas tienes 
    que ir para encontrar al llamador

Ten en cuenta que las subrutinas que estás definiendo de esta manera se ejecutarán en el espacio de nombres "main", así que asegúrate de calificar completamente las funciones y variables si están ubicadas en paquetes diferentes. *Además, asegúrate* *de que estas subrutinas no estén usando Log4perl, de lo contrario Log4perl entrará* *en una recursión infinita.*

Con Log4perl 1.20 y versiones posteriores, los cspecs se pueden escribir con parámetros entre llaves. Escribir algo como

log4perl.appender.Screen.layout.ConversionPattern = %U{user} %U{id} %m%n

hará que la función cspec definida para %U sea llamada dos veces, una vez con el parámetro 'user' y luego otra vez con el parámetro 'id', y los marcadores de posición en el string del cspec serán reemplazados con los valores de retorno respectivos.

El valor del parámetro está disponible en la entrada 'curlies' del primer parámetro pasado a la subrutina (la referencia al objeto layout). Así, si quisieras mapear %U{xxx} a entradas en el hash de sesión de POE, escribirías algo como:

log4perl.PatternLayout.cspec.U = sub { \
  POE::Kernel->get_active_session->get_heap()->{ $_[0]->{curlies} } }

NOTA DE SEGURIDAD

Esta característica significa que se puede incrustar código perl arbitrario en el archivo de configuración. En el caso raro en que las personas que tienen acceso a tu archivo de configuración sean diferentes de las personas que escriben tu código y no deberían tener derechos de ejecución, podrías querer establecer

$Log::Log4perl::Config->allow_code(0);

antes de llamar a init(). Alternativamente, puedes proporcionar un conjunto restringido de opcodes de Perl que pueden ser incrustados en el archivo de configuración, como se describe en "Restringir qué opcodes pueden estar en un Hook de Perl" en Log::Log4perl.

El constructor del Log::Log4perl::Layout::PatternLayout(3pm)

NAME

Log::Log4perl::Layout::PatternLayout - A layout that formats log messages based on a given pattern.

SYNOPSIS

    use Log::Log4perl::Layout::PatternLayout;

    # Basic usage:
    my $layout = Log::Log4perl::Layout::PatternLayout->new("%d %m%n");

    # With options:
    my $layout = Log::Log4perl::Layout::PatternLayout->new(
        { time_function => \&my_time_func, },
        "%d (%F:%L)> %m%n"
    );

    # In a Log4perl configuration file:
    # log4perl.appender.App.layout   = PatternLayout
    # log4perl.appender.App.layout.ConversionPattern = %d %m%n

DESCRIPTION

This is the most common layout. It allows you to specify the format of your log messages using a conversion pattern string. The pattern string can contain literal characters and special conversion specifiers that start with a percent sign (%).

The following conversion specifiers are recognized:

%d
The date and time the log event was created. If the time function returns a scalar (e.g. seconds since the epoch), the date is formatted as yyyy-MM-dd HH:mm:ss. If the time function returns an array (seconds, microseconds), the date is formatted as yyyy-MM-dd HH:mm:ss.uuuuuu.
%m
The log message itself.
%n
A newline character. This is platform-independent.
%p
The level of the log event (e.g. DEBUG, INFO, WARN, ERROR, FATAL).
%r
The number of milliseconds elapsed since the layout was created.
%c
The name of the logger (logger hierarchy).
%C
The name of the caller class (usually requires debugging symbols).
%F
The name of the source file from which the logging request was made (requires debugging symbols).
%L
The line number from which the logging request was made (requires debugging symbols).
%M
The name of the method from which the logging request was made (requires debugging symbols).
%h
The name of the calling host.
%u
The user name of the calling user.
%t
The name of the thread in which the event was logged.
%x
The context of the logging event.
%X{key}
The value associated with key in the logging event's context map. If key is omitted, all key-value pairs from the context map are printed.
%xEx
The exception information associated with the logging event. This will print the stack trace of the exception. Note that this conversion specifier is only relevant if you are logging exceptions.

Conversion specifiers can be modified by preceding them with a decimal number, which specifies the minimum width to which the output should be padded. If the output is shorter than the specified width, it will be padded with spaces (on the left by default). If the width is preceded by a minus sign, the padding will be on the right (left-alignment).

    %8c     : Right-justified logger name, minimum 8 characters wide.
    %-8c    : Left-justified logger name, minimum 8 characters wide.

The Log::Log4perl::Layout::PatternLayout class takes an optional hash reference as a first argument to specify additional options in order to (ab)use it in creative ways:

my $layout = Log::Log4perl::Layout::PatternLayout->new(
  { time_function       => \&my_time_func,
  },
  "%d (%F:%L)> %m");

Here's a list of parameters:

time_function
Takes a reference to a function returning the time for the time/date fields, either in seconds since the epoch or as an array, carrying seconds and microseconds, just like "Time::HiRes::gettimeofday" does.
message_chomp_before_newline
If a layout contains the pattern "%m%n" and the message ends with a newline, PatternLayout will chomp the message, to prevent printing two newlines. If this is not desired, and you want two newlines in this case, the feature can be turned off by setting the "message_chomp_before_newline" option to a false value: 
my $layout = Log::Log4perl::Layout::PatternLayout->new(
    { message_chomp_before_newline => 0
    },
    "%d (%F:%L)> %m%n");

In a Log4perl configuration file, the feature can be turned off like this:

log4perl.appender.App.layout   = PatternLayout
log4perl.appender.App.layout.ConversionPattern = %d %m%n
  # Yes, I want two newlines
log4perl.appender.App.layout.message_chomp_before_newline = 0

Getting rid of newlines

If your code contains logging statements like

  # WRONG, don't do that!
$logger->debug("Some message\n");

then it's usually best to strip the newlines from these calls. As explained in "Logging newlines" in Log::Log4perl, logging statements should never contain newlines, but rely on appender layouts to add necessary newlines instead.

If changing the code is not an option, use the special PatternLayout placeholder %m{chomp} to refer to the message excluding a trailing newline:

log4perl.appender.App.layout.ConversionPattern = %d %m{chomp}%n

This will add a single newline to every message, regardless if it complies with the Log4perl newline guidelines or not (thanks to Tim Bunce for this idea).

Multi Lines

If a log message consists of several lines, like

$logger->debug("line1\nline2\nline3");

then by default, they get logged like this (assuming the the layout is set to "%d>%m%n"):

  # layout %d>%m%n
2014/07/27 12:46:16>line1
line2
line3

If you'd rather have the messages aligned like

  # layout %d>%m{indent}%n
2014/07/27 12:46:16>line1
                    line2
                    line3

then use the %m{indent} option for the %m specifier. This option can also take a fixed value, as in %m{indent=2}, which indents subsequent lines by two spaces:

  # layout %d>%m{indent=2}%n
2014/07/27 12:46:16>line1
  line2
  line3

Note that you can still add the "chomp" option for the %m specifier in this case (see above what it does), simply add it after a separating comma, like in %m{indent=2,chomp}.
