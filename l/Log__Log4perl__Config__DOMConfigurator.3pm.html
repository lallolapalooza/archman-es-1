NOMBRE

Log::Log4perl::Config::DOMConfigurator - lee archivos de configuración XML

SINOPSIS

 --------------------------
 --usando el DTD log4j --
 --------------------------
 <?xml version="1.0" encoding="UTF-8"?>
 <!DOCTYPE log4j:configuration SYSTEM "log4j.dtd">
 <log4j:configuration xmlns:log4j="http://jakarta.apache.org/log4j/">
 <appender name="FileAppndr1" class="org.apache.log4j.FileAppender">
     <layout class="Log::Log4perl::Layout::PatternLayout">
             <param name="ConversionPattern"
                    value="%d %4r [%t] %-5p %c %t - %m%n"/>
     </layout>
     <param name="File" value="t/tmp/DOMtest"/>
     <param name="Append" value="false"/>
 </appender>
 <category name="a.b.c.d" additivity="false">
     <level value="warn"/>  <!-- ¡no en minúsculas! -->
     <appender-ref ref="FileAppndr1"/>
 </category>
<root>
     <priority value="warn"/>
     <appender-ref ref="FileAppndr1"/>
</root>
</log4j:configuration>

DESCRIPCIÓN

Este módulo implementa la configuración XML, complementando la configuración de propiedades descrita en otro lugar.

¿POR QUÉ?

¿Por qué quiero mi configuración en XML? Te preguntarás. Basta con que tengas una preferencia personal por los archivos XML. Tal vez gestiones tu configuración con herramientas que tienen afinidad con XML, como editores XML-aware o generadores de configuración automáticos. O tal vez (y este es el gran punto) no quieras tener que ejecutar tu aplicación solo para verificar la sintaxis de tu archivo de configuración.

Usando una configuración XML y referenciando un DTD, puedes usar un analizador de DTD sensible a espacios de nombres para ver si tu configuración XML al menos sigue las reglas establecidas en el DTD.

CÓMO

Para referenciar un DTD, colócalo después de la declaración de XML en tu archivo de configuración:

<!DOCTYPE log4perl:configuration SYSTEM "log4perl.dtd">

Eso le dice al analizador que validará tu configuración contra el DTD en "log4perl.dtd", que está disponible en la carpeta xml/ de la distribución log4perl. Nota que también necesitarás conseguir el log4j-1.2.dtd desde allí, ya que se incluye por defecto en el DTD log4perl.

Los analizadores de DTD sensibles a espacios de nombres no son lo estándar en Perl. Pero el proyecto Xerces (http://xml.apache.org/xerces-c/index.html -- hay muchos binarios disponibles, incluso rpm's) sí proporciona un analizador que puedes usar de esta manera:

StdInParse -ns -v < my-log4perl-config.xml

Este módulo en sí no usa un analizador de DTD, XML::DOM::ValParser parece no manejar espacios de nombres.

¿POR QUÉ DOS DTDs?

El DTD log4j proviene del proyecto log4j, diseñado para manejar sus necesidades. log4perl ha añadido algunas extensiones a la funcionalidad original de log4j que necesitaban extensiones en el DTD log4j. Si no estás usando estas características, puedes validar tu configuración contra el DTD log4j y estar seguro de que estás usando configuración de log4j sin adulterar.

Las características añadidas por el DTD log4perl son:

1) Configuración global oneMessagePerAppender
log4perl.oneMessagePerAppender=1
2) Especificadores de conversión de usuario globales
log4perl.PatternLayout.cspec.G=sub { return "UID $< GID $("; }
3) Especificadores de conversión personalizados por appender
log4j.appender.appndr1.layout.cspec.K = sub {return sprintf "%1x", $$ }
4) Opciones anidadas
log4j.appender.jabbender          = Log::Dispatch::Jabber
#(nota cómo estas están anidadas bajo 'login')
log4j.appender.jabbender.login.hostname = a.jabber.server
log4j.appender.jabbender.login.port     = 5222
log4j.appender.jabbender.login.username = bobjones
5) Filtros específicos de log4perl, ver Log::Log4perl::Filter, muchos ejemplos en t/044XML-Filter.t, aquí tienes uno corto:
<?xml version="1.0" encoding="UTF-8"?> 
<!DOCTYPE log4perl:configuration SYSTEM "log4perl.dtd">
<log4perl:configuration xmlns:log4perl="http://log4perl.sourceforge.net/">

<appender name="A1" class="Log::Log4perl::Appender::TestBuffer">
      <layout class="Log::Log4perl::Layout::SimpleLayout"/>
      <filter class="Log::Log4perl::Filter::Boolean">
          <param name="logic" value="!Match3 &amp;&amp; (Match1 || Match2)"/> 
      </filter>
</appender>   

<appender name="A2" class="Log::Log4perl::Appender::TestBuffer">
      <layout class="Log::Log4perl::Layout::SimpleLayout"/>
      <filter-ref id="Match1"/>
</appender>   

<log4perl:filter name="Match1" value="sub { /let this through/ }"/>

<log4perl:filter name="Match2">
      sub { 
          /and that, too/ 
      }
 </log4perl:filter>

</log4perl:configuration>

Así que necesitábamos extender el DTD de log4j para cubrir estas adiciones. Ahora podría haber adoptado un enfoque de "robar este código" y mezclado partes del DTD de log4j en un DTD de log4perl, pero eso sería programación de copiar y pegar. Así que he usado namespaces y

•
reemplazado tres elementos:
<log4perl:configuration>
maneja el punto 1) y acepta <PatternLayout>
<log4perl:appender>
acepta <param-nested> y <param-text>
<log4perl:layout>
acepta cspecs personalizados para el punto 3)
  • añadido un elemento <param-nested> (complementando al elemento <param>)
    para manejar el punto 4)
  • añadido un elemento raíz <PatternLayout> para manejar el punto 2)
  • añadido <param-text> que te permite poner cosas como código perl
    entre CDATA escapado entre las etiquetas, para que no tengas que preocuparte
    por escapar caracteres y comillas
  • añadido <cspec>

Ver los ejemplos en el apartado "SYNOPSIS" para ver cómo se usa todo eso.

¿POR QUÉ NAMESPACES?

Me gustó la idea de usar el DTD de log4j *in situ*, así que usé namespaces para extenderlo. Si realmente no te gusta tener que escribir <log4perl:appender> en lugar de simplemente <appender>, puedes crear tu propio DTD combinando los dos DTDs y eliminando los prefijos de namespace. Luego puedes validar contra él, y log4perl debería aceptarlo sin problemas.

SUSTITUCIÓN DE VARIABLES

Esto soporta la sustitución de variables como "${foobar}" en texto y en valores de atributos, excepto en appender-ref. Si existe una variable de entorno definida para ese nombre, se sustituye su valor. Así puedes hacer cosas como

<param name="${hostname}" value="${hostnameval}.foo.com"/>
<param-text name="to">${currentsysadmin}@foo.com</param-text>

REQUIERE

Para usar este módulo, necesitas tener instalado XML::DOM.

Para usar log4perl.dtd, tendrás que referenciarlo en tu config XML, y también debes tener en cuenta que log4perl.dtd referencia al DTD de log4j como "log4j-1.2.dtd", por lo que tu validador debe poder encontrar ese archivo también. Si no te gusta tener que arrastrar dos archivos, siéntete libre de volcar el contenido de "log4j-1.2.dtd" en tu archivo "log4perl.dtd".

ADVERTENCIAS

No puedes mezclar múltiples param-nesteds con el mismo nombre, voy a dejar eso por ahora, actualmente no hay necesidad de una lista de structs en la configuración.
