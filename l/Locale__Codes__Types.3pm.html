NOMBRE

Locale::Codes::Types - tipos de conjuntos de datos compatibles

DESCRIPCIÓN

Este documento contiene una descripción de los diferentes tipos de conjuntos de códigos compatibles con la distribución Locale-Codes.

Los siguientes tipos son compatibles:

"country"
"language"
"currency"
"script"
"langfam"
"langvar"
"langext"

Cada vez que tenga que especificar el tipo de datos, utilice uno de los valores de esta lista. Al utilizar la interfaz OO, tiene que especificar el tipo de datos con el que está trabajando. Por ejemplo:

use Locale::Codes;
...
$obj->type('country');
$obj->type('langext');

Al utilizar las interfaces tradicionales, todas las funciones tienen el tipo de datos incluido en el nombre de la función. Por ejemplo:

use Locale::Codes::Country;
code2country(...);
use Locale::Codes::LangExt;
code2langext(...);

Cada tipo de datos puede tener cualquier número de conjuntos de códigos. Los conjuntos de códigos pueden especificarse por nombre. Tradicionalmente, se exportaba una constante de perl que también podía usarse para especificar el conjunto de códigos.

Ambos métodos están disponibles tanto para la interfaz OO como para las interfaces tradicionales, por lo que cada vez que una función o método acepta un argumento que especifica un conjunto de códigos, se puede utilizar el nombre o una constante.

En las listas siguientes, un conjunto de códigos se especifica en la lista incluyendo el nombre y la constante. Así, por ejemplo, el primer conjunto de códigos de país se llama 'alpha-2' y tiene una constante de perl "LOCALE_COUNTRY_ALPHA_2" asociada a él. Al utilizar la interfaz OO, las constantes solo están disponibles si las importa cargando el módulo con:

use Locale::Codes ':constants';

Las constantes siempre están disponibles al utilizar las interfaces tradicionales.

Algunos de los nombres de constantes de perl más antiguos no eran consistentes, y en esos casos, hay dos constantes disponibles (un nombre más nuevo y consistente y el antiguo inconsistente). Cualquiera de ellas puede ser utilizada.

El conjunto de códigos predeterminado para cada tipo se marca con un asterisco (*).

country

Los conjuntos de códigos para identificar países son mantenidos por varias agencias y estándares diferentes.

Los siguientes conjuntos de códigos se mantienen en el estándar ISO 3166. La página principal oficial de la agencia de mantenimiento ISO 3166 es: http://www.iso.org/iso/home/standards/country_codes.htm .

Solo se incluyen los códigos asignados oficialmente.

* alpha-2, LOCALE_COUNTRY_ALPHA_2, LOCALE_CODE_ALPHA_2
Este es el conjunto de códigos de dos letras (en minúsculas) de ISO 3166-1, como 'tv' para Tuvalu.
alpha-3, LOCALE_COUNTRY_ALPHA_3, LOCALE_CODE_ALPHA_3
Este es el conjunto de códigos de tres letras (en minúsculas) de ISO 3166-1, como 'brb' para Barbados. Estos códigos son definidos y mantenidos por la división de estadísticas de la ONU.
numeric, LOCALE_COUNTRY_NUMERIC, LOCALE_CODE_NUMERIC
Este es el conjunto de códigos numéricos de tres dígitos de ISO 3166-1, como 064 para Bután.

Si se introduce un código de 2 dígitos, se convierte a 3 dígitos anteponiendo un 0.

Un conjunto de nombres de dominio es mantenido por la IANA (Internet Assigned Numbers Authority). Estos están disponibles en: http://www.iana.org/domains/root/db/ . Solo se utilizan los códigos de país reales, y los nombres de los países provienen de ISO 3166.

dom, LOCALE_COUNTRY_DOM, LOCALE_CODE_DOM
Los dominios de país asignados por la IANA suelen ser los códigos de dos letras (en minúsculas) de ISO 3166, pero hay algunas adiciones.

Las Naciones Unidas también mantienen listas de países. Su lista también es similar, pero no idéntica, a la lista ISO 3166.

Los datos están disponibles aquí: https://unstats.un.org/unsd/methodology/m49/

Anteriormente, esta tabla se trataba como una fuente de datos ISO 3166, pero descubrí que la tabla estaba incompleta, por lo que dejé de utilizarla. Más tarde, se añadió de nuevo como su propia lista de códigos.

un-alpha-3, LOCALE_COUNTRY_UN_ALPHA_3, LOCALE_CODE_UN_ALPHA_3
Esto es similar al conjunto 'alpha-3' de ISO 3166, excepto que los códigos están en mayúsculas.
un-numeric, LOCALE_COUNTRY_UN_NUMERIC, LOCALE_CODE_UN_NUMERIC
Esto es similar al conjunto 'numeric' de ISO 3166.

El gobierno de EE. UU. también mantiene una lista de códigos. Originalmente, mantenía el conjunto de códigos FIPS-11, pero este fue descatalogado y reemplazado por el conjunto de códigos GENC. Los conjuntos de códigos FIPS-11 ya no son compatibles con Locale-Codes.

Los conjuntos de códigos GENC están disponibles aquí: https://nsgreg.nga.mil/genc/discovery . También son similares, pero no idénticos, a los conjuntos de códigos ISO 3166.

genc-alpha-2, LOCALE_COUNTRY_GENC_ALPHA_2, LOCALE_CODE_GENC_ALPHA_2
Similar al conjunto 'alpha-2', pero en mayúsculas.
genc-alpha-3, LOCALE_COUNTRY_GENC_ALPHA_3, LOCALE_CODE_GENC_ALPHA_3
Similar al conjunto 'alpha-3', pero en mayúsculas.
genc-numeric, LOCALE_COUNTRY_GENC_NUMERIC, LOCALE_CODE_GENC_NUMERIC
Similar al conjunto 'numeric'.

Existen otras fuentes de códigos que actualmente no se utilizan en esta distribución.

Códigos ISO para subdivisiones de países (estados, condados, provincias, etc.), tal como se definen en ISO 3166-2. Este módulo no forma parte de la distribución Locale-Codes, pero está disponible en CPAN en CPAN/modules/by-module/Locale/

El World Factbook mantenido por la CIA es una fuente potencial de datos. Desafortunadamente, añade/conserva códigos no estándar, por lo que no se utiliza como fuente de datos. https://www.cia.gov/library/publications/the-world-factbook/appendix/appendix-d.html

Otra fuente de datos no oficial es el sitio web de Statoids: http://www.statoids.com/wab.html . Actualmente, no se utiliza para obtener datos, pero las notas y el material explicativo fueron muy útiles para comprender las discrepancias entre las fuentes.

language

Los conjuntos de códigos para identificar idiomas provienen de un par de ubicaciones diferentes.

La fuente principal es ISO 639 . Los códigos ISO 639-2 están disponibles aquí: http://www.loc.gov/standards/iso639-2/ y los códigos ISO 639-5 están disponibles aquí: http://www.loc.gov/standards/iso639-5/ .

Además, la IANA mantiene un registro de idiomas que se añaden a las listas ISO. Dado que está destinado a complementar el estándar ISO, la lista de la IANA no está separada.

Los datos de la IANA están disponibles aquí: http://www.iana.org/assignments/language-subtag-registry

Los conjuntos de códigos son:

* alpha-2, LOCALE_LANGUAGE_ALPHA_2, LOCALE_LANG_ALPHA_2
Este es el conjunto de códigos de dos letras (en minúsculas) de ISO 639-1, como 'he' para hebreo. También incluye adiciones a este conjunto incluidas en el registro de idiomas de la IANA.
alpha-3, LOCALE_LANGUAGE_ALPHA_3, LOCALE_LANG_ALPHA_3
Este es el conjunto de códigos bibliográficos de tres letras (en minúsculas) de ISO 639-2 y 639-5, como 'heb' para hebreo. También incluye adiciones a este conjunto incluidas en el registro de idiomas de la IANA.
term, LOCALE_LANGUAGE_TERM, LOCALE_LANG_TERM
Este es el conjunto de códigos terminológicos de tres letras (en minúsculas) de ISO 639.

Locale::Codes::Types - Code Set Type Definitions

DESCRIPTION

This file contains definitions of the code sets used by the Locale::Codes module.

country

Country codes are specified using codes from ISO 3166-1 available here: http://www.iso.org/iso/en/prods-services/iso3166/endshorten.html

Code sets are:

* alpha, LOCALE_COUNTRY_ALPHA, LOCALE_CCODE_ALPHA
This is the set of two-letter (uppercase) codes from ISO 3166-1 alpha-2. such as US for United States.

It also includes the three-letter (uppercase) codes from ISO 3166-1 alpha-3 such as USA for United States.

It also includes the three-digit numeric codes from ISO 3166-1 numeric such as 840 for United States.

The 'ZZ' code is not used.

language

Language codes are specified using codes from ISO 639-2 available here: http://www.loc.gov/standards/iso639/

Code sets are:

* alpha, LOCALE_LANGUAGE_ALPHA, LOCALE_LANG_ALPHA
This is a set of three-letter (lowercase) codes from ISO 639-2 such as 'eng' for English.

It also includes the two-letter (lowercase) codes from ISO 639-1 such as 'en' for English.

It also includes the three-digit numeric codes from ISO 639-2 such as 396 for English.

The 'und' code is not used.

currency

Currency codes are specified using codes from ISO 4217 available here: https://www.six-group.com/en/products-services/financial-information/data-standards.html

The code sets are:

* alpha, LOCALE_CURRENCY_ALPHA, LOCALE_CURR_ALPHA
This is a set of three-letter (uppercase) codes from ISO 4217 such as EUR for Euro.

Two of the codes specified by the standard (XTS which is reserved for testing purposes and XXX which is for transactions where no currency is involved) are omitted.

num, LOCALE_CURRENCY_NUMERIC, LOCALE_CURR_NUMERIC
This is the set of three-digit numeric codes from ISO 4217.

script

The source of script code sets is ISO 15924 available here: http://www.unicode.org/iso15924/

Additional data comes from the IANA language subtag registry: http://www.iana.org/assignments/language-subtag-registry .

Code sets are:

* alpha, LOCALE_SCRIPT_ALPHA
This is a set of four-letter (capitalized) codes from ISO 15924 such as 'Phnx' for Phoenician. It also includes additions to this set included in the IANA language registry.

The Zxxx, Zyyy, and Zzzz codes are not used.

num, LOCALE_SCRIPT_NUMERIC
This is a set of three-digit numeric codes from ISO 15924 such as 115 for Phoenician.

langfam

Language families are specified using codes from ISO 639-5 available here: http://www.loc.gov/standards/iso639-5/id.php

Code sets are:

* alpha, LOCALE_LANGFAM_ALPHA
This is the set of three-letter (lowercase) codes from ISO 639-5 such as 'apa' for Apache languages.

langvar

Language variations are specified using codes from he IANA language subtag registry available here: http://www.iana.org/assignments/language-subtag-registry

Code sets are:

* alpha, LOCALE_LANGVAR_ALPHA
This is the set of alphanumeric codes from the IANA language registry, such as 'arevela' for Eastern Armenian.

langext

Language extensions are specified using codes from he IANA language subtag registry available here: http://www.iana.org/assignments/language-subtag-registry

Code sets are:

* alpha, LOCALE_LANGEXT_ALPHA
This is the set of three-letter (lowercase) codes from the IANA language registry, such as 'acm' for Mesopotamian Arabic.

NEW CODE SETS

I'm always open to suggestions for new code sets.

In order for me to add a code set, I want the following criteria to be met:

General-use code set
If a code set is not general use, I'm not likely to spend the time to add and support it.
An official source of data
I require an official (or at least, a NEARLY official) source where I can get the data on a regular basis.

Ideally, I'd only get data from an official source, but sometimes that is not possible. For example the ISO standards are not typically available for free, so I may have to get some of that data from alternate sources that I'm confident are getting their data from the official source. However, I will always be hesitant to accept a non-official source.

As an example, I used to get some country data from the CIA World Factbook. Given the nature of the source, I'm sure they're updating data from the official sources and I consider it "nearly" official. However, even in this case, I found that they were adding codes that were not part of the standard, so I have stopped using them as a source.

There are many 3rd party sites which maintain lists (many of which are actually in a more convenient form than the official sites). Unfortunately, I will reject most of them since I have no feel for how "official" they are.

A free source of the data
Obviously, the data must be free-of-charge. I'm not interested in paying for the data (and I'm not interested in the overhead of having someone else pay for the data for me).
A reliable source of data
The source of data must come from a source that I can reasonably expect to exist for the foreseeable future since I will be extremely reluctant to drop support for a data set once it's included.

I am also reluctant to accept data sent to me by an individual. Although I appreciate the offer, it is simply not practical to consider an individual contribution as a reliable source of data. The source should be an official agency of some sort.

These requirements are open to discussion. If you have a code set you'd like to see added, but which may not meet all of the above requirements, feel free to email me and we'll discuss it. Depending on circumstances, I may be willing to waive some of these criteria.
