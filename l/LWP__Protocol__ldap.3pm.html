NOMBRE

LWP::Protocol::ldap - Proporciona soporte LDAP para LWP::UserAgent

SINOPSIS

use LWP::UserAgent;
$ua = LWP::UserAgent->new();
$res = $ua->get('ldap://ldap.example.com/' .
                'o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)',
                 Accept => 'text/json'):

DESCRIPCIÓN

El módulo LWP::Protocol::ldap proporciona soporte para usar URLs con esquema ldap siguiendo RFC 4516 con LWP. Este módulo es un complemento para el manejo de protocolos de LWP, por lo que no se usa directamente.

Además de usarse con URIs LDAP, LWP::Protocol::ldap también actúa como clase base para sus módulos hermanos LWP::Protocol::ldaps y LWP::Protocol::ldapi.

Características

Métodos HTTP compatibles

LWP::Protocol::ldap implementa los métodos HTTP GET y HEAD. Se mapean a la operación de búsqueda LDAP,

Formato de respuesta

Dependiendo de la cabecera HTTP Accept proporcionada por el agente de usuario, LWP::Protocol::ldap puede responder a las solicitudes en uno de los siguientes formatos:

DSML
Cuando la cabecera HTTP Accept contiene el tipo MIME "text/dsml", la respuesta se envía como DSMLv1.
JSON
Cuando la cabecera HTTP Accept contiene el tipo MIME "text/json", la respuesta se envía como JSON. Para que esto funcione, el módulo Perl JSON debe estar instalado.
LDIF
Cuando la cabecera HTTP Accept contiene el tipo MIME "text/ldif", la respuesta se envía en formato LDIFv1.
HTML
En caso de que no se haya enviado ninguna cabecera HTTP Accept o no se hayan podido detectar los tipos MIME anteriores, y la extensión x-format tampoco se haya proporcionado, la respuesta se envía utilizando marcado HTML en un formato de tabla de 2 columnas (aproximadamente basado en LDIF).

Como alternativa a enviar una cabecera HTTP Accept, LWP::Protocol::ldap también acepta la extensión "x-format"

Ejemplo:

ldap://ldap.example.com/o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)?x-format=dsml

Soporte TLS

Para URIs ldap y ldapi, el módulo implementa la extensión "x-tls" que cambia la conexión LDAP a TLS utilizando una llamada al método start_tls.

Ejemplo:

ldap://ldap.example.com/o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)?x-tls=1

Nota: En el ejemplo anterior, idealmente dar "x-tls" debería ser suficiente, pero desafortunadamente el analizador en URI::ldap tiene un pequeño defecto.

Autorización

Normalmente la conexión se realiza anónimamente, pero si se proporciona la cabecera HTTP Authorization con credenciales para autorización HTTP básica, las credenciales dadas en esa cabecera se utilizarán para realizar un enlace simple al servidor LDAP.

VER TAMBIÉN

LWP::Protocol::ldaps, LWP::Protocol::ldapi
