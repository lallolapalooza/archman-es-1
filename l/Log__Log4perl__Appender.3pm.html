NOMBRE

Log::Log4perl::Apendedor - Clase de apendedor de log

SINTAXIS

use Log::Log4perl;
    # Definir un logger
my $logger = Log::Log4perl->get_logger("abc.def.ghi");
    # Definir un layout
my $layout = Log::Log4perl::Layout::PatternLayout->new(
                 "%d (%F:%L)> %m");
    # Definir un apendedor
my $apendedor = Log::Log4perl::Apendedor->new(
                 "Log::Log4perl::Apendedor::Screen",
                 name => 'dumpy');
    # Configurar el layout del apendedor
$apendedor->layout($layout);
$logger->add_apendedor($apendedor);

DESCRIPCIÓN

Esta clase es una capa que rodea la clase de apendedor "Log::Log4perl::Apendedor" de la colección.

También soporta las colecciones de apendedores de "Log::Dispatch::*". La librería oculta los aspectos extraños de "Log::Dispatch" (por ejemplo, cada dispatcher debe tener un nombre, pero no hay acceso para obtenerlo) de "Log::Log4perl" y recicla los tipos de apendedores ya creados y probados en "Log::Dispatch".

FUNCIONES

Log::Log4perl::Apendedor->new($dispatcher_class_name, ...);

La función new() toma el nombre de la clase de apendedor a crear como un argumento cadena (!) y opcionalmente seguido de parámetros específicos al apendedor, por ejemplo:

    # Definir un apendedor
my $apendedor = Log::Log4perl::Apendedor->new(
    "Log::Log4perl::Apendedor::File"
    filename => 'out.log');

En caso de apendedores de "Log::Dispatch", si no se especifica el parámetro "name", el objeto de apendedor creará un nombre único (formato "appNNN"), que se puede recuperar posteriormente mediante el método name():

print "El nombre del apendedor es ", $apendedor->name(), "\n";

Otros parámetros son específicos de la clase de apendedor utilizada. En el ejemplo anterior, el parámetro "filename" especifica el nombre del apendedor "Log::Log4perl::Apendedor::File" utilizado.

Sin embargo, si estás usando un apendedor de "Log::Dispatch::Email" para enviar correos, tendrás que especificar "from" y "to" direcciones de correo. Cada apendedor es diferente. Por favor consulta la documentación de "Log::Dispatch::*" para detalles sobre los requisitos específicos del apendedor utilizado.

La función new() pasará simplemente estos parámetros a un objeto de apendedor "Log::Dispatch::*" de la clase especificada.

Cuando se trata de registros, el apendedor "Log::Log4perl::Apendedor" relayerá transparentemente todos los mensajes a través del objeto de apendedor "Log::Dispatch::*" que lleva en su interior.

$apendedor->layout($layout);

El método layout() establece el formato de registro utilizado por el apendedor, que se pasa como un objeto de la clase "Log::Log4perl::Layout::*". Actualmente hay dos layouts disponibles:

Log::Log4perl::Layout::SimpleLayout
Log::Log4perl::Layout::PatternLayout

Por favor consulta las páginas de documentación de "Log::Log4perl::Layout::SimpleLayout" y "Log::Log4perl::Layout::PatternLayout" para detalles.

Parámetros pasados a método log() del apendedor

Cuando se llama al método log() del apendedor, Log::Log4perl enviará una lista de pares clave/valor. Las entradas siguientes a los siguientes pares son garantizadas para estar presentes:

message
Texto del mensaje renderizado
log4p_category
Nombre de la categoría del logger que provocó el evento.
log4p_level
Nivel de log de Log::Log4perl del evento.

Avisos de Pitfall

Dado que el apendedor "Log::Dispatch::File" trunca los archivos de log por defecto y la mayoría de las veces esto no es lo que deseas, hemos indicado a "Log::Log4perl" que cambie este comportamiento, pasando el parámetro "mode => append" por debajo del capitel. Así, con "Log::Log4perl" 0.23, una configuración como:

log4perl.category = INFO, FileAppndr
log4perl.appender.FileAppndr          = Log::Dispatch::File
log4perl.appender.FileAppndr.filename = test.log
log4perl.appender.FileAppndr.layout   = Log::Log4perl::Layout::SimpleLayout

siempre appendirá a un archivo de log existente "test.log" mientras que si especificas como en:

log4perl.category = INFO, FileAppndr
log4perl.appender.FileAppndr          = Log::Dispatch::File
log4perl.appender.FileAppndr.filename = test.log
log4perl.appender.FileAppndr.mode     = write
log4perl.appender.FileAppndr.layout   = Log::Log4perl::Layout::SimpleLayout

va a reescribir un archivo de log existente "test.log" y empezará desde cero.

Apendedores Esperando Cuerpos de Mensaje

En lugar de strings simples, certaines apendedores esperan múltiples campos como cuerpos de mensajes de log. Si una declaración como

$logger->debug($ip, $user, "signed in");

causa que un apendedor como "Log::Log4perl::Apendedor::Screen" se active, el apendedor usará simplemente la concatenación de los tres cuerpos de mensaje pasados a él para formar una cadena única. Los cuerpos estarán separados por una cadena definida en

$Log::Log4perl::JOIN_MSG_ARRAY_CHAR
(por defecto es la cadena vacía "").

Sin embargo, diferentes apendedores pueden interpretar el mensaje de arriba de manera diferente: un apendedor como "Log::Log4perl::Apendedor::DBI" podría colocar los tres argumentos pasados al logger en tres filas separadas en la base de datos.

La opción "warp_message" del apendedor se usa para especificar el comportamiento deseado. Si no se define ningún valor para la propiedad del apendedor

# *** No definido ***
# log4perl.appender.SomeApp.warp_message

en el archivo de configuración de Log4perl, el apendedor referenciado por "SomeApp" se retraerá a comportamiento estándar y concatenará todos los cuerpos de mensaje, separándolos mediante

$Log::Log4perl::JOIN_MSG_ARRAY_CHAR
.

NAME

Log::Log4perl::Appender - Base class for Log4perl appenders

SYNOPSIS

use Log::Log4perl::Appender;

# See Log::Log4perl::Appender::Screen
# See Log::Log4perl::Appender::File
# See Log::Log4perl::Appender::Handle
# See Log::Log4perl::Appender::Callback
# See Log::Log4perl::Appender::Email
# See Log::Log4perl::Appender::Socket
# See Log::Log4perl::Appender::DBI
# See Log::Log4perl::Appender::Mmap
# See Log::Log4perl::Appender::Buffer
# See Log::Log4perl::Appender::Sync
# See Log::Log4perl::Appender::Virtual

DESCRIPTION

This module implements the base class for all Log4perl appenders. Appenders are responsible for sending log messages to their destination. Log4perl comes with a lot of appenders, and you can easily write your own by inheriting from this module.

Each appender must implement a log() method. This method is called by the Logger object and is passed a Log4perl LogEvent object.

The LogEvent object contains all information about the event being logged:

  • The log level (e.g. DEBUG, INFO, WARN, ERROR, FATAL).
  • The message itself.
  • The timestamp when the event occurred.
  • The name of the logger that created the event.
  • The source file and line number where the logging call was made.
  • The thread name (if threading is enabled).
  • The throwable object (if an exception was logged).

The LogEvent object is a subclass of Log::Log4perl::LogEvent.

An appender can be configured using parameters passed in a hash reference when it is created.

my $appender = Log::Log4perl::Appender::File->new(
    -file   => '/tmp/log.txt',
    -mode   => 'append',
    -layout => $layout,
);

The base class provides:

  • A default log() method that calls the appender's write() method.
  • Methods for setting and getting the appender's layout.
  • Methods for setting and getting the appender's threshold.
  • Methods for handling calls to log() from threads.

METHODS

new( %params )

Constructor for the appender. It accepts a hash of parameters. The available parameters depend on the specific appender, but most appenders accept:

  • -layout: A Log4perl layout object. If not provided, a default layout (Log::Log4perl::Layout::Pattern with pattern %m%n) is used.
  • -level: The minimum level for messages to be processed by this appender. Messages with a level lower than this will be ignored.

Subclasses should override this method to parse their own parameters and call the parent constructor.

layout( [ $layout ] )

Get or set the appender's layout object. The layout is used to format the log messages before they are sent to the appender's destination.

level( [ $level ] )

Get or set the appender's threshold level. Messages with a level lower than this will be ignored.

threshold( [ $level ] )

An alias for level().

is_enabled_for( $level )

Returns true if the appender is enabled for the given log level. This method checks if the given level is greater than or equal to the appender's threshold level.

log( $log_event )

This method is called by the logger to log a message. It checks if the appender is enabled for the message's level and then calls the write() method with the formatted message.

write( $message )

This method must be implemented by subclasses. It receives the formatted log message as a string and is responsible for sending it to the appender's destination.

requires_layout()

Returns true if the appender requires a layout. Most appenders do require a layout, but some (like Log::Log4perl::Appender::Handle) don't.

The default implementation returns true.

init( %params )

This method is called after the appender has been created and its parameters have been parsed. It can be used for any initialization that requires the parameters to be set.

The default implementation does nothing.

close()

This method is called when the appender is being closed. It can be used to release any resources held by the appender (e.g., close files, network connections, etc.).

The default implementation does nothing.

Parameters passed on to the appender's log() method

The log() method of the appender receives a Log::Log4perl::LogEvent object. This object is a subclass of Log::Log4perl::LogEvent and contains the following attributes:

  • level: The log level (e.g., $event->level() returns 'INFO').
  • message: The log message string (e.g., $event->message()).
  • timestamp: The time the event occurred (a Time::HiRes timestamp).
  • logger: The logger object that created the event.
  • logger_name: The name of the logger.
  • file: The source file name where the logging call was made.
  • line: The line number in the source file.
  • thread: The name of the thread (if threading is enabled).
  • throwable: The exception object, if an exception was logged.
  • location_info: A hash reference containing file, line, and possibly function information. This is primarily used by appenders that need precise location data.

Appenders Expecting Message Chunks

Some appenders might receive log messages in chunks if the layout generates multi-line output. For example, a layout that formats stack traces might output several lines for a single log event. If you are writing a custom appender that needs to handle such cases, you might need to implement logic to buffer and reassemble these chunks before writing them to the destination.

However, most standard appenders (like File, Screen) and layouts handle this correctly by default. The LogEvent object passed to the appender's log() method contains the fully formatted message, so explicit chunk handling is usually not required unless you are dealing with very specific output scenarios.
