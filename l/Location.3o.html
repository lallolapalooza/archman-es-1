Códigos de ubicación (rango de posiciones), utilizados en parsetree.

Advertencia: este módulo es inestable y parte de Compiler_libs .

tipo t = Warnings.loc = {
loc_start : Lexing.position ;
loc_end : Lexing.position ;
loc_ghost : bool ;
}

t representa un rango de caracteres en el código fuente.

loc_ghost=false cuando el árbol de sintaxis descrito por la ubicación puede ser parseado desde la ubicación. En todos los otros casos, loc_ghost debe ser true. La mayoría de las ubicaciones producidas por el analizador tienen loc_ghost=false. Cuando loc_ghost=true, la ubicación es una aproximación de mejor intento.

Esta información se usa por herramientas como merlin que quieren relacionar el código fuente con los arboles de parseo o arboles más tarde. ocamlprof ignora la instrumentación de nodos de ghost.

Ejemplo: en `let f x = x`, tenemos:

- un elemento de estructura en la ubicación "let f x = x"

- un patrón "f" en la ubicación "f"

- un expresión "fun x -> x" en la ubicación "x = x" con loc_ghost=true

- un patrón "x" en la ubicación "x"

- una expresión "x" en la ubicación "x" En este caso, cada nodo tiene loc_ghost=false, excepto el nodo "fun x -> x", ya que Parser.expression (Lexing.from_string "x = x") fallaría para parsear. En cambio, en `let f = fun x -> x`, cada nodo tiene loc_ghost=false.

Las directivas de línea pueden modificar arbitrariamente los nombres de archivos y números de líneas, lo cual es ortogonal a loc_ghost, que describe el rango de caracteres desde loc_start.pos_cnum hasta loc_end.pos_cnum en el string parseado.

Nota sobre el uso de Lexing.position en este módulo. Si pos_fname = "", entonces usa !input_name. Si pos_lnum = -1, entonces pos_bol = 0. Usa pos_cnum y re-parsea el archivo para obtener el número de línea y carácter. De lo contrario, todos los campos son correctos.

Ruta de reescripción

val rewrite_absolute_path : string -> string

rewrite_absolute_path path reescribe path para honrar el variable BUILD_PATH_PREFIX_MAP si está definida. No verifica si path es absoluto o no. El resultado es el siguiente:

- Si BUILD_PATH_PREFIX_MAP no está definido, devuelve simplemente path.

- De lo contrario, reescribe usando la mapeo (y si no hay mapeos coincidentes, devuelve path).

Ver la especificación de BUILD_PATH_PREFIX_MAP.

val rewrite_find_first_existing : string -> string option

rewrite_find_first_existing path usa una mapeo de BUILD_PATH_PREFIX_MAP y intenta encontrar un archivo en el que se mapea a un resultado que exista en el sistema de archivos. Los valores posibles son:

- None , significa que:

- BUILD_PATH_PREFIX_MAP no está definido y path no existe, o

- no hay prefijos de fuentes para path en el mapeo, o

- Some target , significa que target existe y:

- BUILD_PATH_PREFIX_MAP no está definido y target = path , o

- target es el primer archivo (en orden de prioridad) que path mapea a un resultado que exista en el sistema de archivos.

- Not_found arrojado, significa que algunos prefijos de fuentes en el mapeo coinciden con path pero ninguno de ellos existe en el sistema de archivos. El llamador debe capturar este error y emitir un mensaje adecuado.

Ver la especificación de BUILD_PATH_PREFIX_MAP.

val rewrite_find_all_existing_dirs : string -> string list

rewrite_find_all_existing_dirs dir acumula una lista de directorios existentes, dirs , que son los resultados de mapear un directorio abstracto, dir , a través de todos los pares de mapeo en el entorno BUILD_PATH_PREFIX_MAP, si hay algún. La lista dirs está ordenada por prioridad (head como mayor prioridad).

Los posibles resultados son:

- [] , significa que:

- BUILD_PATH_PREFIX_MAP no está definido y dir no es un directorio existente, o

- si está definido, no hay prefijos que coincidan con dir .

- Some dirs , significa que dirs son los directorios encontrados. O bien:

- BUILD_PATH_PREFIX_MAP no está definido y dirs = [dir] , o

- fue establecido y dirs son los directorios existentes que fueron mapeados.

- Not_found arrojado, significa que algunos prefijos de fuentes en el mapeo coinciden con dir , pero ninguno de los resultados de mapeo era un directorio existente (posiblemente debido a una configuración incorrecta). El llamador debe capturar este error y emitir un mensaje adecuado.

Ver la especificación de BUILD_PATH_PREFIX_MAP.

val absolute_path : string -> string

absolute_path path primero hace una ruta absoluta, s , a partir de path , prepending el directorio actual si path era relativo. Luego s se reescribe con rewrite_absolute_path . Finalmente, el resultado se normaliza eliminando instancias de '.' o '..' .

Notificación automática de errores para excepciones lanzadas

val register_error_of_exn : (exn -> error option) -> unit

Cada módulo del compilador que define un tipo de excepción personalizado que puede ser visible para el usuario debe registrar un "impresor" para esta excepción usando register_error_of_exn. El resultado del impresor es un valor error que contiene una ubicación, un mensaje y, opcionalmente, submensajes (cada uno de ellos también ubicado).

val error_of_exn : exn -> [ `Already_displayed | `Ok of error ] option

exception Error of error

Lanzar Error e señala un error e; la excepción será capturada y el error se imprimirá.

exception Already_displayed_error

Lanzar Already_displayed_error señala un error que ya ha sido impreso. La excepción será capturada, pero no se imprimirá nada.
