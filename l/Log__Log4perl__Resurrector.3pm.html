Log__Log4perl__Resurrector(3pm)

Paquete: perl-log-log4perl

Licencias: PerlArtistic, GPL

Resurrector(3) Documentación de Perl contribuida por el usuario Resurrector(3)

NOMBRE

Log::Log4perl::Resurrector - Magia oscura para resucitar sentencias l4p ocultas

DESCRIPCIÓN

Cargar "use Log::Log4perl::Resurrector" hace que los módulos cargados posteriormente tengan sus sentencias

###l4p use Log::Log4perl qw(:easy);
###l4p DEBUG(...)
###l4p INFO(...)
...

ocultas, descomentadas y, por lo tanto, 'resucitadas', es decir, activadas.

Esto permite que un módulo "Foobar.pm" sea escrito con sentencias Log4perl comentadas y se ejecute a toda velocidad en modo normal. Cuando se carga a través de

use Foobar;

todas las sentencias ocultas de Log4perl serán ignoradas.

Sin embargo, si un script carga el módulo "Foobar" después de cargar "Log::Log4perl::Resurrector", como en

use Log::Log4perl::Resurrector;
use Foobar;

entonces "Log::Log4perl::Resurrector" habrá colocado un filtro de origen que extraerá todas las sentencias ocultas de Log4perl en "Foobar" antes de que "Foobar" sea realmente cargado.

Por lo tanto, "Foobar" se comportará como si las sentencias

###l4p use Log::Log4perl qw(:easy);
###l4p DEBUG(...)
###l4p INFO(...)
...

fueran realmente escritas como

use Log::Log4perl qw(:easy);
DEBUG(...)
INFO(...)
...

y el módulo "Foobar" sí estará habilitado para Log4perl. Si alguna sentencia Log4perl activada realmente desencadenará mensajes de registro, dependerá de la configuración de Log4perl, por supuesto.

Hay un costo inicial al usar "Log::Log4perl::Resurrector" (todos los módulos cargados posteriormente se examinan), pero una vez que la fase de compilación ha finalizado, el programa perl se ejecutará a toda velocidad.

Algunas de las técnicas utilizadas en este módulo han sido robadas del módulo CPAN "Acme::Incorporated", escrito por chromatic. ¡Larga vida a CPAN!
