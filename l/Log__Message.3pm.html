Log::Message(3) Documentación de Perl aportada por el usuario Log::Message(3)

NOMBRE

Log::Message - Un mecanismo genérico de almacenamiento de mensajes;

SINOPSIS

use Log::Message private => 0, config => '/nuestro/archivo_cf';
my $log = Log::Message->new(    private => 1,
                                level   => 'log',
                                config  => '/mi/archivo_cf',
                           );
$log->store('este es mi primer mensaje');
$log->store(    message => 'mensaje #2',
                tag     => 'MI_TAG',
                level   => 'carp',
                extra   => ['este es un argumento para el manejador'],
           );
my @ultimos_cinco_elementos = $log->retrieve(5);
my @elementos = $log->retrieve( tag     => qr/mi_tag/i,
                            message => qr/\d/,
                            remove  => 1,
                          );
my @elementos = $log->final( level => qr/carp/, amount => 2 );
my $primer_error = $log->first()
# fallar con el último error en la pila
$log->final->croak;
# vaciar la pila
$log->flush();

DESCRIPCIÓN

Log::Message es un mecanismo genérico de almacenamiento de mensajes. Te permite almacenar mensajes en una pila, ya sea compartida o privada, y asignarles metadatos. Algunos metadatos se agregarán automáticamente por ti, como una marca de tiempo y un rastro de la pila, pero otros pueden ser completados por el usuario, como una etiqueta para identificarlo o agruparlo, y un nivel al que manejar el mensaje (por ejemplo, registrarlo o morir con él).

Log::Message también proporciona una forma potente de buscar en los elementos mediante expresiones regulares en mensajes, etiquetas y niveles.

Jerarquía

Hay 4 módulos de interés al tratar con los módulos de Log::Message::*:

Log::Message
Log::Message proporciona algunos métodos para manipular la pila que mantiene. Tiene la opción de mantener una pila privada o pública. Más sobre esto a continuación.
Log::Message::Item
Estos son elementos de mensaje individuales, que son objetos que contienen el mensaje del usuario junto con los metadatos descritos anteriormente. Consulta la página del manual de Log::Message::Item para ver cómo extraer estos metadatos y cómo trabajar con los objetos Item. Nunca deberías necesitar crear tus propios objetos Item, pero conocer sus métodos y accedentes es importante si quieres escribir tus propios manejadores (ver más abajo).
Log::Message::Handlers
Esta es una colección de manejadores que se llamarán para un nivel que se utiliza en un objeto Log::Message::Item. Por ejemplo, si se registra un mensaje con el nivel 'carp', se llamará al manejador 'carp' de Log::Message::Handlers. Consulta la página del manual de Log::Message::Handlers para obtener más explicaciones sobre cómo funcionan los manejadores, cuáles están disponibles y cómo crear los tuyos propios.
Log::Message::Config
Por objeto Log::Message, se requiere una configuración que rellenará los valores predeterminados si el usuario no especificó argumentos para anularlos (como por ejemplo, qué etiqueta se establecerá si no se proporcionó ninguna). Log::Message::Config se encarga de la creación de estas configuraciones.

La configuración se puede especificar de 4 maneras:

  • Como archivo de configuración cuando usas "use Log::Message"
  • Como argumentos cuando usas "use Log::Message"
  • Como archivo de configuración cuando creas un nuevo objeto Log::Message. (La configuración solo se aplicará a ese objeto si lo marcaste como privado)
  • Como argumentos cuando creas un nuevo objeto Log::Message.

    Nunca deberías necesitar usar el módulo Log::Message::Config tú mismo, ya que esto lo hace Log::Message de forma transparente, pero su página del manual sí proporciona una explicación de cómo puedes crear un archivo de configuración.

Opciones

Al usar Log::Message o crear un nuevo objeto Log::Message, puedes proporcionar varias opciones para alterar su comportamiento. Por supuesto, hay valores predeterminados razonables en caso de que elijas omitir estas opciones.

A continuación, se explica cada una de las opciones y cómo funcionan.

config
La ruta a un archivo de configuración para ser leído. Consulta la página del manual de Log::Message::Config para ver el formato requerido.

Estas opciones serán anuladas por cualquier argumento explícito pasado.

private
Si se crearán, por defecto, objetos privados o compartidos. Si eliges crear objetos compartidos, todos los objetos Log::Message utilizarán la misma pila.

Esto significa que aunque cada módulo pueda crear su propio objeto $log, seguirán compartiendo la misma pila de errores en la que ponen los errores y de la que los recuperan.

Esto puede ser útil en proyectos grandes.

Si eliges crear un objeto privado, la pila estará por supuesto privada a este objeto, pero aún así recurrirá a la configuración compartida si no se proporciona ninguna configuración privada o argumentos de anulación.

verbose
Log::Message utiliza otro módulo para validar sus argumentos, llamado Params::Check, que es un verificador y analizador de entrada ligero pero potente (consulta la página del manual de Params::Check para obtener detalles).

La configuración verbose controlará si este módulo genera advertencias si se pasa algo inadecuado como entrada, o simplemente devuelve undef silenciosamente, momento en el cual Log::Message generará una advertencia.

Es mejor dejar esto en su valor predeterminado, que es '1'.

tag
La etiqueta que se añadirá a los mensajes si no se proporcionó ninguna. Si ni tu configuración ni ningún argumento específico proporcionan una etiqueta, Log::Message la establecerá en 'NONE'.

Las etiquetas son útiles para buscar o agrupar. Por ejemplo, podrías etiquetar todos los mensajes que quieres que vayan al usuario como 'ERROR DE USUARIO' y todos los que son solo información de depuración como 'DEBUG'.

Al final de tu programa, podrías imprimir todos los etiquetados como 'ERROR DE USUARIO' en STDOUT, y los marcados como 'DEBUG' en un archivo de registro.

level
"level" describe qué acción tomar cuando se registra un mensaje. Al igual que "tag", Log::Message proporcionará un valor predeterminado (que es 'log') si ni tu archivo de configuración ni ningún argumento explícito se dan para anularlo.

Consulta la página del manual de Log::Message::Handlers para ver qué manejadores están disponibles por defecto y qué hacen, así como para saber cómo añadir tus propios manejadores.

remove
Esto indica si se deben eliminar automáticamente los mensajes de la pila cuando los has recuperado o no. El ajuste predeterminado proporcionado por Log::Message es '0': no eliminar.
chrono
Esto indica si los mensajes siempre deben recuperarse en orden cronológico o no. Esto simplemente significa que puedes elegir si, al recuperar los elementos, se debe devolver primero el elemento agregado más recientemente o el que se agregó hace más tiempo.

El valor predeterminado es devolver primero los más nuevos.

Métodos

new

Esto crea un nuevo objeto Log::Message; Los parámetros que toma se describen en la sección "Opciones" a continuación y basta con repetirlo que puedes usar estas opciones así:

my $log = Log::Message->new( %options );

así como en el momento de "use", así:

use Log::Message option1 => value, option2 => value

Solo hay 3 reglas a tener en cuenta:

  • Los argumentos proporcionados tienen prioridad sobre un archivo de configuración.
  • Los argumentos para new tienen prioridad sobre las opciones proporcionadas en el momento de "use".
  • Un objeto marcado como privado siempre tendrá una pila vacía

NAME

Log::Message - A simple logging mechanism

SYNOPSIS

    use Log::Message;

    # Store a message
    Log::Message->store( message => "This is a test message." );
    Log::Message->store( "Another test message." ); # shortcut

    # Store a message with tag and level
    Log::Message->store(
        message => "Something went wrong",
        tag     => "Error",
        level   => "critical"
    );

    # Retrieve messages
    my @errors = Log::Message->retrieve( tag => qr/Error/ );
    my @all    = Log::Message->retrieve();

    # Retrieve and remove
    my $msg    = Log::Message->retrieve( remove => 1 );
    my @old    = Log::Message->retrieve( tag => qr/old/, remove => 1 );

    # Flush all messages from the stack
    my @flushed = Log::Message->flush();

DESCRIPTION

This module provides a very simple mechanism for logging messages. It is designed to be lightweight and easy to use. It uses a stack to store message objects, which can then be retrieved based on various criteria. Handlers can be configured to process these messages.

Hierarchy

This module is a subclass of Log::Message::Item.

Options

The following options can be set via the configuration:

Log::Message::Config->level
Sets the default level for messages. Default is 'info'.
Log::Message::Config->tag
Sets the default tag for messages. Default is 'default'.
Log::Message::Config->handler
Sets the default handler for messages. This can be a coderef or a string name of a handler. Default is a handler that simply prints to STDERR.
Log::Message::Config->stack_size
Sets the maximum size of the message stack. If the stack exceeds this size, the oldest message will be removed. Default is undef (no limit).

store

This will create a new Item object and store it on the stack.

Possible arguments you can give to it are:

message
This is the only argument that is required. If no other arguments are given, you may even leave off the "message" key. The argument will then automatically be assumed to be the message.
tag
The tag to add to this message. If not provided, Log::Message will look in your configuration for one.
level
The level at which this message should be handled. If not provided, Log::Message will look in your configuration for one.
extra
This is an array ref with arguments passed to the handler for this message, when it is called from store();

The handler will receive them as a normal list

store() will return true upon success and undef upon failure, as well as issue a warning as to why it failed.

retrieve

This will retrieve all message items matching the criteria specified from the stack.

Here are the criteria you can discriminate on:

tag
A regex to which the tag must adhere. For example "qr/\w/".
level
A regex to which the level must adhere.
message
A regex to which the message must adhere.
amount
Maximum amount of errors to return
chrono
Return in chronological order, or not?
remove
Remove items from the stack upon retrieval?

In scalar context it will return the first item matching your criteria and in list context, it will return all of them.

If an error occurs while retrieving, a warning will be issued and undef will be returned.

first

This is a shortcut for retrieving the first item(s) stored on the stack. It will default to only retrieving one if called with no arguments, and will always return results in chronological order.

If you only supply one argument, it is assumed to be the amount you wish returned.

Furthermore, it can take the same arguments as "retrieve" can.

last

This is a shortcut for retrieving the last item(s) stored on the stack. It will default to only retrieving one if called with no arguments, and will always return results in reverse chronological order.

If you only supply one argument, it is assumed to be the amount you wish returned.

Furthermore, it can take the same arguments as "retrieve" can.

flush

This removes all items from the stack and returns them to the caller
