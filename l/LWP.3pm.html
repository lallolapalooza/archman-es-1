NOMBRE

LWP - La librería del mundo web para Perl

SINTAXIS

use LWP;
print "This is libwww-perl-$LWP::VERSION\n";

DESCRIPCIÓN

La colección libwww-perl es un conjunto de módulos Perl que ofrece una interfaz de programación de aplicación simple y consistente para el mundo web. El foco principal de la librería es proporcionar clases y funciones que permitan escribir clientes WWW. La librería también contiene módulos que son de más amplio uso y incluso clases que ayudan a implementar servidores HTTP simples.

La mayoría de los módulos en esta librería ofrecen una interfaz orientada a objetos. Los objetos usuarios, los pedidos enviados y los respuestas recibidas desde el servidor WWW son representados por objetos. Esto hace una interfaz sencilla y poderosa para estos servicios. La interfaz es fácil de extender y personalizar según las necesidades del usuario.

Las principales características de la librería son:

  • Incluye diversos componentes reutilizables (módulos) que pueden usarse por separado o juntos.
  • Proporciona un modelo orientado a objetos para comunicaciones HTTP estilo. Dentro de este marco, actualmente soportamos acceso a

COMUNICACIÓN DE TIPO HTTP

La librería libwww-perl se basa en una comunicación de tipo HTTP. Esta sección intenta describir lo que significa eso.

Vamos a comenzar con esta cita de un documento de especificación de HTTP:

•
El protocolo HTTP se basa en un paradigma de solicitud/responsuesta. Un cliente establece una conexión con un servidor y envía una solicitud al servidor en forma de método de solicitud, URI, y versión del protocolo, seguido de un mensaje MIME que contiene modificaciones de solicitud, información del cliente y contenido posible. El servidor responde con una línea de estado, incluyendo la versión del mensaje de protocolo y un código de éxito o error, seguido de un mensaje MIME que contiene información del servidor, información de entidad, y contenido posible.

Lo que significa para libwww-perl es que la comunicación siempre ocurre mediante estos pasos: Primero se crea y configura un objeto request. Este objeto se pasa a un servidor y se obtiene un objeto response que podemos examinar. Un request siempre es independiente de cualquier solicitud previa, es decir, el servicio es estadoless. El mismo modelo simple se usa para cualquier servicio que queramos acceder.

Por ejemplo, si queremos obtener un documento de un servidor remoto, enviamos un request que contiene el nombre del documento y el response contendrá el documento mismo. Si accedemos a un motor de búsqueda, el contenido de la solicitud contendrá los parámetros de búsqueda y el response contendrá el resultado de la búsqueda. Si queremos enviar un mensaje de correo a alguien, enviamos un objeto request que contiene nuestro mensaje al servidor de correo y el response contendrá un reconocimiento que indique que el mensaje ha sido aceptado y se enviará al destinatario(s).

Es tan simple como eso!

El Objeto de Solicitud

El objeto de solicitud de libwww-perl tiene el nombre de clase HTTP::Request. El hecho de que el nombre de la clase use "HTTP::" como prefijo solo implica que usamos el modelo de comunicación HTTP. No limita el tipo de servicios que podemos intentar pasar este request a. Por ejemplo, enviaríamos HTTP::Requests tanto a servidores FTP y gopher, así como a el sistema local.

Los atributos principales de los objetos de solicitud son:

  • method es una cadena corta que indica qué tipo de solicitud es. Los métodos más comunes son GET, PUT, POST y HEAD.
  • uri es una cadena que denota el protocolo, el servidor y el nombre del "documento" que queremos acceder. El uri puede también codificar otros parámetros.
  • headers contiene información adicional sobre la solicitud y puede usarse para describir el contenido. Las cabeceras son un conjunto de pares de palabra clave/valor.
  • content es cualquier cantidad de datos.

El Objeto de Respuesta

El objeto de respuesta de libwww-perl tiene el nombre de clase HTTP::Response. Los atributos principales de los objetos de esta clase son:

  • code es un valor numérico que indica el resultado general de la solicitud.
  • message es una cadena corta y fácil de leer que corresponde al code.
  • headers contiene información adicional sobre la respuesta y describe el contenido.
  • content es cualquier cantidad de datos.

Como no queremos manejar todos los valores de code directamente en nuestros programas, un objeto de respuesta de libwww-perl tiene métodos que podemos usar para consultar qué tipo de respuesta es este. Los métodos más comunes de clasificación de respuestas son:

is_success()
La solicitud fue correctamente recibida, comprendida o aceptada.
is_error()
La solicitud falló. El servidor o el recurso no está disponible, el acceso al recurso puede estar denegado o hay otros errores por qué.

El Agente de Usuario

Asumamos que hemos creado un objeto request. ¿Qué realmente hacemos con él para recibir un response?

La respuesta es que lo pasamos a un objeto user agent y este se encarga de todo lo que necesita hacer (como comunicación baja nivel y manejo de errores) y devuelve un objeto response. El agente de usuario representa tu aplicación en la red y proporciona una interfaz que puede aceptar requests y devolver responses.

El agente de usuario es una capa de interfaz entre tu código de aplicación y la red. A través de esta capa puedes acceder a diversos servidores en la red.

El nombre de clase del agente de usuario es LWP::UserAgent. Cada aplicación de libwww-perl que quiere comunicarse debe crear al menos un objeto de esta clase. La principal método proporcionado por este objeto es request(). Este método toma un objeto HTTP::Request como argumento y (eventualmente) devuelve un objeto HTTP::Response.

El agente de usuario tiene muchos otros atributos que te permiten configurar cómo se comunicará con la red y con tu aplicación.

  • timeout especifica cuánto tiempo damos a los servidores remotos para responder antes de que la librería se desconecte y cree una respuesta de tiempo limite interna.
  • agent especifica el nombre que usa tu aplicación cuando presenta su identidad en la red.
  • from puede ser configurado como el correo electrónico del responsable de ejecutar la aplicación. Si este es configurado, entonces el correo será enviado a los servidores con cada solicitud.
  • parse_head especifica si debemos inicializar las cabeceras de respuesta desde la sección <head> de documentos HTML.
  • proxy y no_proxy especifican si y cuándo debe pasar por un servidor proxy. http://www.w3.org/History/1994/WWW/Proxies/

DESCRIPCIÓN

LWP (libwww-perl) is a library for writing World-Wide Web clients. It supports protocols like HTTP, HTTPS, FTP, and more. The library is designed to be easy to use for common tasks, while also providing low-level access to HTTP requests and responses. It includes features for handling different content types, authentication, proxies, and more.

ESTILO DE COMUNICACIÓN HTTP

The following modules provide the basic HTTP client functionality.

HTTP::UserAgent     -- The main class for making requests
HTTP::Request       -- Represents an HTTP request
HTTP::Response      -- Represents an HTTP response
HTTP::Headers       -- Handles HTTP header manipulation
HTTP::Cookies       -- Cookie jar object
HTTP::Request::Common -- Helper functions for creating common requests
HTTP::Detector      -- Try to guess the content type of a resource

SOPORTE DE RED

The following modules provide support for various network protocols and related functionality.

Net::FTP            -- FTP client class

URI::URL            -- Perl module for parsing and manipulating URLs
URI::WWW::Foundation -- Base classes for WWW related URIs
LWP::Protocol::http -- HTTP protocol handler
LWP::Protocol::https -- HTTPS protocol handler

LWP::Protocol::mailto -- Mailto protocol handler

MÁS DOCUMENTACIÓN

All modules contain detailed information on the interfaces they provide. The lwpcook manpage is the libwww-perl cookbook that contain examples of typical usage of the library. You might want to take a look at how the scripts lwp-request, lwp-download, lwp-dump and lwp-mirror are implemented.

AMBIENTE

The following environment variables are used by LWP:

HOME
The LWP::MediaTypes functions will look for the .media.types and .mime.types files relative to you home directory.
http_proxy
ftp_proxy
xxx_proxy
no_proxy
These environment variables can be set to enable communication through a proxy server. See the description of the "env_proxy" method in LWP::UserAgent.
PERL_LWP_ENV_PROXY
If set to a TRUE value, then the LWP::UserAgent will by default call "env_proxy" during initialization. This makes LWP honor the proxy variables described above.
PERL_LWP_SSL_VERIFY_HOSTNAME
The default "verify_hostname" setting for LWP::UserAgent. If not set the default will be 1. Set it as 0 to disable hostname verification (the default prior to libwww-perl 5.840.
PERL_LWP_SSL_CA_FILE
PERL_LWP_SSL_CA_PATH
The file and/or directory where the trusted Certificate Authority certificates is located. See LWP::UserAgent for details.
PERL_HTTP_URI_CLASS
Used to decide what URI objects to instantiate. The default is URI. You might want to set it to URI::URL for compatibility with old times.
