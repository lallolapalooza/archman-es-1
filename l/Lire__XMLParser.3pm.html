XMLParser(3pm) Documentación de Lire de LogReport XMLParser(3pm)

NOMBRE

Lire::XMLParser - Analizador XML orientado a objetos base.

SINOPSIS

package MyParser;
use base qw/ Lire::XMLParser /;

DESCRIPCIÓN

Este módulo permite escribir analizadores orientados a objetos utilizando el módulo no-oo XML::Parser.

MÉTODOS CLIENTE

parse( $xml )

Analiza el XML y devuelve el resultado. $xml puede ser una cadena o una referencia a un manejador de archivos abierto o un objeto IO::Handle.

parsefile( $archivo )

Analiza el XML contenido en $archivo y devuelve el resultado.

MÉTODOS PLANTILLA DE METADATOS

Dos métodos plantilla deben ser implementados por las subclases. Estos métodos proporcionan información sobre el modelo de contenido del XML esperado por el analizador.

namespaces()

Este método debe devolver una referencia a un hash. Las claves son los namespaces XML entendidos por el analizador. El valor es el prefijo que se utiliza para ese namespace en el método elements_spec().

elements_spec()

Este método debe devolver una referencia a un hash. Las claves son los elementos XML conocidos. Se generará un error por parte del analizador cuando se encuentre un elemento no definido en este hash.

La clave debe tener el formato [ prefijo : ] nombre_elemento. Si se utiliza prefijo, debe estar definido en el método namespaces().

El valor del hash son especificaciones de elementos. Esta especificación se puede utilizar para configurar los manejadores de eventos que se llamarán, así como para especificar el modelo de contenido de los elementos. Esta especificación es una referencia a un hash con las siguientes claves:

contenido
Esta es una referencia a un array que debe contener el nombre de los elementos permitidos dentro de ese elemento. Estos nombres están en el mismo formato que las claves de elements_spec(). Si este elemento se omite, se considera que el elemento está vacío y, por lo tanto, no puede contener ningún otro elemento. Si el elemento puede contener PCDATA, la cadena 'PCDATA' debe figurar en el array.
inicio
Esto especifica el manejador que se llama cuando se encuentra la etiqueta de apertura de este elemento. Puede ser una referencia a una función o un nombre de método. Si este elemento se omite, el manejador será el método llamado elemento_fin si existe, o ningún manejador en caso contrario. Se sustituye '_' por caracteres inválidos para nombres de método, es decir, report-spec se convierte en report_spec_inicio.
fin
Esto especifica el manejador que se llama cuando se encuentra la etiqueta de cierre de este elemento. Puede ser una referencia a una función o un nombre de método. Si este elemento se omite, el manejador será el método llamado elemento_fin si existe, o ningún manejador en caso contrario. Se sustituye '_' por caracteres inválidos para nombres de método, es decir, report-spec se convierte en report_spec_fin.
caracter
Esto especifica el manejador que se llama cuando se encuentra PCDATA dentro del elemento. Esto solo puede ocurrir si 'PCDATA' apareció en el atributo 'contenido'. Puede ser una referencia a una función o un nombre de método. Si este elemento se omite, el manejador será el método llamado elemento_caracter si existe, o ningún manejador en caso contrario. Se sustituye '_' por caracteres inválidos para nombres de método, es decir, list-item se convierte en list_item_caracter.

La especificación también puede ser una referencia a un array, en cuyo caso se interpretará como el contenido del atributo hash 'contenido'.

Se informarán errores por especificaciones inválidas.

MÉTODOS UTILIDAD

expat()

Durante el análisis, esto devuelve el objeto analizador subyacente Lire::XMLParser::Expat.

error( $msg )

Terminará el análisis con el mensaje de error $msg. El contexto de análisis actual se añadirá al mensaje.

warning( $msg )

Imprimirá un mensaje de advertencia $msg. El contexto de análisis actual se añadirá al mensaje.

context()

Devuelve como una referencia a un array los nombres de los elementos actualmente abiertos. En la etiqueta de inicio y fin, el último elemento será la etiqueta del elemento padre. El nombre de los elementos estará en el mismo formato que el utilizado por elements_spec().

current_element()

Devuelve el nombre del elemento abierto actualmente más interno. En la etiqueta de inicio y fin, el último elemento será la etiqueta del elemento padre. El nombre de los elementos estará en el mismo formato que el utilizado por elements_spec().

in_element( $nombre_elemento )

Esto devuelve verdadero si el elemento abierto actualmente más interno tiene el mismo nombre que $nombre_elemento. $nombre_elemento debe ser uno de los elementos definidos por elements_spec(), de lo contrario el método fallará.

Ejemplo:

if ( $self->in_element( "lire:report") ) {
    # El elemento padre es un elemento de informe de Lire.
} elsif ( $self->in_element( "listitem" ) ) {
    # Estamos en un elemento listitem de DocBook
}

within_element( $nombre_elemento )

Esto devuelve el número de veces que un elemento está abierto en el ancestro del elemento actual. Al igual que con in_element(), el nombre del elemento debería haber sido definido por elements_spec(), de lo contrario el método fallará.

recognized_string()

Devuelve la cadena que activa el evento actual.

depth()

Devuelve el número de elementos abiertos y aún no cerrados. En los manejadores de inicio y fin, el elemento actual forma parte de esa lista.

MÉTODOS MANEJADORES DE EVENTOS

Estos son métodos que se llaman durante el análisis XML.

parse_start()

Este método se invoca una vez antes de que se analice el documento. Se puede utilizar para cualquier inicialización que el procesador deba realizar. La implementación predeterminada no hace nada.

parse_end( )

Este método se invoca una vez después de que se haya procesado todo el archivo XML. El valor que devuelva este método será devuelto por el método parse() o parsefile() (el que se haya utilizado para iniciar el análisis). La implementación predeterminada no hace nada.

element_start( $nombre, $atributos )

Se llama cuando se abre un elemento válido. $nombre contiene el nombre del elemento. Este nombre es la forma canónica, es decir, si el elemento está dentro de un namespace, se prefijará con el prefijo declarado por el método namespaces(). $atributos contiene los atributos definidos en una referencia a un hash.

El método predeterminado distribuirá a los manejadores definidos por elements_spec().

element_end( $nombre )

Se llama cuando se cierra un elemento válido. $nombre contiene el nombre del elemen

Lire::XMLParser(3pm)

NAME

Lire::XMLParser - Event-based XML parser.

SYNOPSIS

    use Lire::XMLParser;

    my $parser = Lire::XMLParser->new( spec_file => "my_spec.xml" );
    $parser->parse( file => "my_data.xml" );

DESCRIPTION

This module implements an event-based XML parser. It parses an XML file based on a DTD file and dispatches events to methods defined in the handler object. The handler object can be either the parser object itself, or another object passed to the parser.

The parser behaviour is defined by a specification file. This file describe the expected XML structure, and the action to take when an event occurs.

The parser is instantiated with a specification file defining the expected structure of the XML document.

The behaviour of the parser is defined by a spec file. This file describes the expected structure of the XML document, and the actions to take when an event occurs. The specification file is an XML document itself.

The specification file contains definitions of elements, their attributes and their children. It also defines the handler methods to be called when an event occurs.

The parser dispatches events to the handler object. The handler object is responsible for reacting to these events. The handler object can be the parser object itself, or another object passed to the parser.

CLIENT METHODS

new( %args )

Creates a new XMLParser object.

The following arguments are recognized:

spec_file
The path to the XML specification file.
handler
The object that will handle the events. If not provided, the parser object itself will handle the events.

parse( %args )

Parses the given XML file or string.

The following arguments are recognized:

file
The path to the XML file to parse.
string
The XML string to parse.

Either file or string must be provided.

META-INFORMATION TEMPLATE METHODS

These methods are called by the parser to retrieve meta-information about the document being parsed. They are typically implemented in the handler object.

start_document()

Called at the beginning of the XML document.

end_document()

Called at the end of the XML document.

start_element( $element, $attributes )

Called when an element is encountered. $element is the name of the element, and $attributes is a hash reference containing the element's attributes.

end_element( $element )

Called when the end of an element is encountered. $element is the name of the element.

UTILITY METHODS

get_spec()

Returns the specification object used by the parser.

get_handler()

Returns the handler object used by the parser.

get_current_element()

Returns the name of the current element.

get_current_attributes()

Returns a hash reference of the current element's attributes.

EVENT HANDLERS METHODS

These methods are called by the parser when specific events occur. They are defined in the specification file.

pcdata( $text )

Called when parsed character data are encountered in an element which is allowed to contain PCDATA. Default implementation dispatch to the handler defined by elements_spec().

ignorable_ws( $ws )

Called when whitespace is encountered while processing an element which cannot contain PCDATA. Default implementation does nothing. This is mainly used by parser which want to keep the user's format.

HELPERS METHODS

Two common tasks when writing event-based parsers is to use "stacks" and "collectors". The XMLParser object offers some method to manage these common objects.

init_collector( $name )

This initialize a collector with the name $name. If there was already a collector defined under this name, its content will be reset to the empty string ''.

collect( $name, $text )

Appends $text to the collector $name. An exception will be thrown if no collector $name was previously defined.

get_collector( $name )

Returns the content accumulated in the collector $name. An exception will be thrown if no collector $name was previously defined.

collector_start( $element, $attributes )

This is a method which can be used as a start event handler. It will define a collector with the same name than the element which is started.

collector_char( $text )

This is a method which can be used as a char event handler. It will append $text to the collector named under the element in which this text occurs.

init_stack( $name )

Initialize a stack object named $name.

stack_push( $name, $value )

Returns true if the stack $name is empty. An exception will be raise if no stack $name was defined.

stack_depth( $name )

Returns the number of element on the stack $name. An exception will be raise if no stack $name was defined.

stack_push( $name, $value )

Pushes $value onto the stack $name. An exception will be raise if no stack $name was defined.

stack_pop( $name )

Removes and returns the top value on the stack $name. An exception will be raised if no stack $name was defined or if the stack is empty.

stack_peek( $name )

Returns the top value of the stack $name. An exception will be raised if no stack $name was defined or if the stack is empty.
