NAME

Locale::Po4a::Xml — convertir documentos XML y derivados en/de archivos PO

DESCRIPCIÓN

El proyecto po4a (PO para cualquier cosa) tiene como objetivo facilitar las traducciones (y más interesante, la mantenimiento de las traducciones) usando los herramientas gettext en áreas donde no eran esperadas, como la documentación.

Locale::Po4a::Xml es un módulo para ayudar en la traducción de documentos XML a otros idiomas. También puede usarse como base para construir módulos para documentos basados en XML.

TRANSLAR CON PO4A::XML

Este módulo puede usarse directamente para manejar documentos generales XML. Esto extraerá el contenido de todas las etiquetas, y no los atributos, ya que es donde se escribe el texto en los documentos XML basados en la mayoría de los casos.

Hay algunas opciones (descripciones en la siguiente sección) que pueden personalizar este comportamiento. Si esto no se ajusta a tu formato de documento, se recomienda escribir tu propio módulo derivado de este, para describir los detalles de tu formato. Ve la sección WRITING DERIVATE MODULES a continuación, para obtener la descripción del proceso.

OPCIONES ACEPTADAS POR ESTE MODULO

La opción global de depuración hace que este módulo muestre las palabras excluidas, para ver si pasa algo importante.

Estas son las opciones particulares de este módulo:

nostrip
Previene que se quiten los espacios alrededor de las palabras extraídas.
wrap
Establece el texto a traducir en un esquema canónico, considerando que los espacios no son importantes, y agrupa el documento traducido. Esta opción puede ser superada por las opciones de etiqueta personalizadas. Ve la opción translated más abajo.
unwrap_attributes
Los atributos se agrupan por defecto. Esta opción desactiva el agrupamiento.
caseinsensitive
Permite que el busco de etiquetas y atributos sea insensible a mayúsculas y minúsculas. Si está definido, se tratará <BooK>laNG y <BOOK>Lang como <book>lang.
escapequotes
Escapa las comillas en los strings de salida. Es necesario, por ejemplo, para crear recursos de strings para usar por los build tools de Android.

Ver también: https://developer.android.com/guide/topics/resources/string-resource.html

includeexternal
Si se define, se incluyen en el documento traducido (documentado) las entidades externas, y para la extracción de strings. Si no se define, deberás traducir las entidades externas como documentos independientes.
ontagerror
Esta opción define el comportamiento del módulo cuando encuentra sintaxis XML inválida (una etiqueta de cierre que no coincide con la etiqueta de apertura final). Puede tomar los siguientes valores:
fail
Este es el valor predeterminado. El módulo se detendrá con un error.
warn
El módulo continuará, y emitirá un aviso.
silent
El módulo continuará sin emitir avisos.

Debes tener cuidado al usar esta opción. Es generalmente recomendable corregir el archivo de entrada.

tagsonly
Nota: Esta opción es obsoleta.

Solo extrae las etiquetas especificadas en la opción tags. De lo contrario, extraerá todos los tags excepto los especificados.

doctype
La cadena que intentará coincidir con la primera línea del tipo de documento del archivo (si está definida). Si no está, se emitirá un aviso indicando que el documento podría ser de un tipo malo.
addlang
La cadena que indica la ruta (por ejemplo, <bbb><aaa>) de una etiqueta donde se deberá añadir un atributo lang con valor "...". El idioma se definirá como el nombre de la PO archivo sin extensión .po.
optionalclosingtag
Booleano que indica si las etiquetas de cierre son opcionales (como en HTML). Por defecto, las etiquetas de cierre que faltan generan un error, según el valor ontagerror.
tags
Nota: Esta opción es obsoleta. Debes usar las opciones translated y untranslated en su lugar.

Una lista separada por espacios de etiquetas que quieres traducir o omitir. Por defecto, las etiquetas especificadas se excluirán, pero si usas la opción tagsonly, las etiquetas especificadas serán las únicas incluidas. Las etiquetas deben estar en el formato <aaa>, pero puedes unir algunas (<bbb><aaa>) para indicar que el contenido de la etiqueta <aaa> se traducirá solo cuando esté dentro de una etiqueta <bbb>.

También puedes especificar algunas opciones de etiqueta por poner algunos caracteres delante de la jerarquía de etiquetas. Por ejemplo, puedes poner w (wrap) o W (no wrap) para sobreescalar el comportamiento por defecto especificado en la opción global wrap.

Ejemplo: W<chapter><title>

attributes
Una lista separada por espacios de atributos de etiquetas que quieres traducir. Puedes especificar los atributos por su nombre (por ejemplo, "lang"), pero también puedes prefiñarlo con una jerarquía de etiqueta para indicar que este atributo solo será traducido si está en la etiqueta especificada. Por ejemplo, <bbb><aaa>lang especifica que el atributo lang se traducirá solo si está en una etiqueta <aaa> y está dentro de una etiqueta <bbb>.
foldattributes
No traduce atributos en etiquetas inline. En lugar de reemplazar todos los atributos de una etiqueta con po4a-id=<id>.

Este es útil cuando los atributos no deben ser traducados, ya que simplifica las cadenas para los traductores y evita errores de tipo.

customtag
Una lista separada por espacios de etiquetas que no se tratan como etiquetas. Estas etiquetas se tratan como inline y no necesitan ser cerradas.
break
Una lista separada por espacios de etiquetas que deben romper la secuencia. Por defecto, todas las etiquetas rompen la secuencia.

Las etiquetas deben estar en el formato <aaa>, pero puedes unir algunas (<bbb><aaa>), si una etiqueta (<aaa>) debe ser considerada solo cuando está dentro de otra etiqueta (<bbb>).

Nota: Una etiqueta debe estar lista en solo una de las listas break,

TRABAJANDO CON ETIQUETAS

get_path()
Esta función devuelve la ruta a la etiqueta actual desde la raíz del documento, en el formato <html><body><p>.

Se puede pasar un array adicional de etiquetas (sin corchetes) como argumento. Estos elementos de ruta se añadirán al final de la ruta actual.

tag_type()
Esta función devuelve el índice de la lista `tag_types` que se ajusta a la siguiente etiqueta en el flujo de entrada, o -1 si se encuentra al final del archivo de entrada.

Aquí, la etiqueta tiene una estructura iniciada por < y terminada por >, y puede contener múltiples líneas.

Esto funciona sobre el array "@{$self->{TT}{doc_in}}" que contiene los datos del documento de entrada y la referencia indirectamente a través de "$self->shiftline()" y "$self->unshiftline($$)".

extract_tag($$)
Esta función devuelve la siguiente etiqueta del flujo de entrada sin el principio y el final, en formato de array, para mantener las referencias del archivo de entrada. Tiene dos parámetros: el tipo de etiqueta (tal como lo devuelve `tag_type`) y un booleano que indica si debe ser eliminada del flujo de entrada.

Esto funciona sobre el array "@{$self->{TT}{doc_in}}" que contiene los datos del documento de entrada y la referencia indirectamente a través de "$self->shiftline()" y "$self->unshiftline($$)".

get_tag_name(@)
Esta función devuelve el nombre de la etiqueta pasada como argumento, en el formato de array devuelto por `extract_tag`.
breaking_tag()
Esta función devuelve un booleano que indica si la siguiente etiqueta en el flujo de entrada es una etiqueta de interrupción (tag de interrupción) o no (etiqueta en línea). Deja el flujo de entrada intacto.
treat_tag()
Esta función traduce la siguiente etiqueta del flujo de entrada. Utiliza las funciones de traducción personalizadas de cada tipo de etiqueta.

Esto funciona sobre el array "@{$self->{TT}{doc_in}}" que contiene los datos del documento de entrada y la referencia indirectamente a través de "$self->shiftline()" y "$self->unshiftline($$)".

tag_in_list($@)
Esta función devuelve un valor de cadena que indica si el primer argumento (una jerarquía de etiquetas) coincide con alguna de las etiquetas del segundo argumento (una lista de etiquetas o jerarquías de etiquetas). Si no coincide, devuelve 0. De lo contrario, devuelve las opciones de la etiqueta coincidente (los caracteres delante de la etiqueta) o 1 (si esa etiqueta no tiene opciones).

TRABAJANDO CON ATRIBUTOS

treat_attributes(@)
Esta función maneja la traducción de los atributos de las etiquetas. Recibe la etiqueta sin las marcas de inicio/fin, y luego encuentra los atributos, y traduce los que son traducibles (especificados por la opción del módulo attributes). Esto devuelve una cadena plana con la etiqueta traducida.

TRABAJANDO CON CONTENIDOS ETIQUETADOS

treat_content()
Esta función obtiene el texto hasta la siguiente etiqueta de interrupción (no en línea) del flujo de entrada. La traduce utilizando las funciones de traducción personalizadas de cada tipo de etiqueta.

Esto funciona sobre el array "@{$self->{TT}{doc_in}}" que contiene los datos del documento de entrada y la referencia indirectamente a través de "$self->shiftline()" y "$self->unshiftline($$)".

TRABAJANDO CON LAS OPCIONES DEL MÓDULO

treat_options()
Esta función rellena las estructuras internas que contienen las etiquetas, atributos y datos en línea con las opciones del módulo (especificadas en la línea de comandos o en la función de inicialización).

OBTENIENDO TEXTO DEL DOCUMENTO DE ENTRADA

get_string_until($%)
Esta función devuelve un array con las líneas (y referencias) del documento de entrada hasta que encuentra el primer argumento. El segundo argumento es un hash de opciones. El valor 0 significa deshabilitado (por defecto) y 1, habilitado.

Las opciones válidas son:

include
Esto hace que el array devuelto contenga el texto buscado
remove
Esto elimina el flujo devuelto de la entrada
unquoted
Esto asegura que el texto buscado esté fuera de cualquier comilla
regex
Esto indica que el primer argumento es una expresión regular en lugar de una cadena normal
skip_spaces(\@)
Esta función recibe como argumento la referencia a un párrafo (en el formato devuelto por `get_string_until`), omite sus espacios iniciales y los devuelve como una cadena simple.
join_lines(@)
Esta función devuelve una cadena simple con el texto del array de argumentos (descartando las referencias).

ESTADO DE ESTE MÓDULO

Este módulo puede traducir etiquetas y atributos.

LISTA DE TAREAS PENDIENTES

DOCTYPE (ENTIDADES)

Existe un soporte mínimo para la traducción de entidades. Se traducen en su totalidad, y no se tienen en cuenta las etiquetas. Las entidades multilínea no son compatibles y las entidades siempre se reenvuelven durante la traducción.

MODIFICAR TIPOS DE ETIQUETAS DE MÓDULOS HEREDADOS (¿mover la estructura `tag_types` dentro del hash $self?)
