NOMBRE

Log::Log4perl::Filter - Clase base de filtro personalizado de Log4perl

SINOPSIS

use Log::Log4perl;
Log::Log4perl->init(\ <<'EOT');
  log4perl.logger = INFO, Screen
  log4perl.filter.MiFiltro        = sub { /dejar pasar esto/ }
  log4perl.appender.Screen        = Log::Log4perl::Appender::Screen
  log4perl.appender.Screen.Filter = MiFiltro
  log4perl.appender.Screen.layout = Log::Log4perl::Layout::SimpleLayout
EOT
    # Definir un logger
my $logger = Log::Log4perl->get_logger("Algo");
    # Dejar pasar esto
$logger->info("¡Aquí está la información, dejar pasar esto!");
    # Suprimir esto
$logger->info("¡Aquí está la información, suprimir esto!");
#################################################################
# Filtro StringMatch:
#################################################################
log4perl.filter.M1               = Log::Log4perl::Filter::StringMatch
log4perl.filter.M1.StringToMatch = dejar pasar esto
log4perl.filter.M1.AcceptOnMatch = true
#################################################################
# Filtro LevelMatch:
#################################################################
log4perl.filter.M1               = Log::Log4perl::Filter::LevelMatch
log4perl.filter.M1.LevelToMatch  = INFO
log4perl.filter.M1.AcceptOnMatch = true

DESCRIPCIÓN

Log4perl permite el uso de filtros personalizados en sus appenders para controlar la salida de los mensajes. Estos filtros pueden buscar ciertos fragmentos de texto en un mensaje, verificar que su prioridad coincida o supere un cierto nivel, o que sea la décima vez que se envía el mismo mensaje, y tomar una decisión de registrar/no registrar basándose en estos hechos circunstanciales.

Los filtros tienen nombres y se pueden especificar de dos maneras en el archivo de configuración de Log4perl: como subrutinas o como clases de filtro. Aquí hay un filtro simple llamado "MiFiltro" que simplemente verifica que el mensaje entrante coincida con la expresión regular "/dejar pasar esto/i":

log4perl.filter.MiFiltro        = sub { /dejar pasar esto/i }

Explota el hecho de que cuando la subrutina definida arriba se llama con un mensaje, la variable especial $_ de Perl se establecerá al texto del mensaje (pre-renderizado, es decir, concatenado pero no maquetado) que se va a registrar. Se espera que la subrutina devuelva un valor verdadero si desea que se registre el mensaje o un valor falso si no lo desea.

Además, Log::Log4perl pasará un hash a la subrutina, que contendrá todos los pares clave/valor que pasaría al appender correspondiente, como se especifica en Log::Log4perl::Appender. Aquí hay un ejemplo de un filtro que comprueba la prioridad del mensaje entrante:

log4perl.filter.MiFiltro        = sub {    \
     my %p = @_;                           \
     if($p{log4p_level} eq "WARN" or       \
        $p{log4p_level} eq "INFO") {       \
         return 1;                         \
     }                                     \
     return 0;                             \
}

Si la prioridad del mensaje es igual a "WARN" o "INFO", devuelve un valor verdadero, haciendo que el mensaje se registre.

Filtros predefinidos

Para tareas comunes como verificar que la prioridad del mensaje coincida con una prioridad específica, ya existe un conjunto de filtros predefinidos disponibles. Para realizar una coincidencia exacta de nivel, es mucho más limpio usar el filtro "LevelMatch" de Log4perl en su lugar:

log4perl.filter.M1               = Log::Log4perl::Filter::LevelMatch
log4perl.filter.M1.LevelToMatch  = INFO
log4perl.filter.M1.AcceptOnMatch = true

Esto dejará pasar el mensaje si su prioridad es INFO y lo suprimirá de lo contrario. La declaración se puede negar diciendo

log4perl.filter.M1.AcceptOnMatch = false

en su lugar. De esta manera, el mensaje se registrará si su prioridad es cualquier cosa excepto INFO.

En una nota similar, el filtro "StringMatch" de Log4perl verificará el mensaje entrante en busca de cadenas o expresiones regulares:

log4perl.filter.M1               = Log::Log4perl::Filter::StringMatch
log4perl.filter.M1.StringToMatch = bl.. bl..
log4perl.filter.M1.AcceptOnMatch = true

Esto abrirá la puerta a mensajes como "blah blah" porque la expresión regular en "StringToMatch" coincide con ellos. De nuevo, la configuración de "AcceptOnMatch" determina si el filtro se define de forma positiva o negativa.

Todas las entradas de filtro de clase en el archivo de configuración deben adherirse a la siguiente regla: Solo después de que un filtro haya sido definido por nombre y clase/subrutina, se pueden asignar sus valores de atributo, al igual que el valor "true" arriba se asigna al atributo "AcceptOnMatch" después de que se haya definido el filtro "M1".

Adjuntar un filtro a un appender

Adjuntar un filtro a un appender es tan fácil como asignar su nombre al atributo "Filter" del appender:

log4perl.appender.MyAppender.Filter = MiFiltro

Esto hará que "Log::Log4perl" llame a la subrutina/método del filtro cada vez que se suponga que un mensaje debe pasarse al appender. Dependiendo del valor de retorno del filtro, "Log::Log4perl" continuará según lo planeado o se retirará inmediatamente.

Combinar filtros con Log::Log4perl::Filter::Boolean

A veces, es útil combinar la salida de varios filtros para llegar a una decisión de registrar/no registrar. Mientras que Log4j, la nave nodriza de Log4perl, ha optado por implementar esta característica como una cadena de filtros, similar a las cadenas IP de Linux, Log4perl intenta un enfoque diferente.

Típicamente, los resultados de los filtros no necesitarán ser transmitidos a través de cadenas, sino combinados de manera programática usando lógica booleana. "Registrar si este filtro dice 'sí' y ese filtro dice 'no'" es un requisito bastante común, pero difícil de implementar como una cadena.

"Log::Log4perl::Filter::Boolean" es un filtro personalizado especialmente predefinido para Log4perl. Combina los resultados de otros filtros personalizados de maneras arbitrarias, utilizando expresiones booleanas:

log4perl.logger = WARN, AppWarn, AppError
log4perl.filter.Match1       = sub { /dejar pasar esto/ }
log4perl.filter.Match2       = sub { /y eso también/ }
log4perl.filter.MiBooleano      = Log::Log4perl::Filter::Boolean
log4perl.filter.MiBooleano.logic = Match1 || Match2
log4perl.appender.Screen        = Log::Log4perl::Appender::Screen
log4perl.appender.Screen.Filter = MiBooleano
log4perl.appender.Screen.layout = Log::Log4perl::Layout::SimpleLayout

"Log::Log4perl::Filter::Boolean"'s las expresiones booleanas permiten combinar diferentes appenders por nombre usando AND (&& o &), OR (|| o |) y NOT (!) como expresiones lógicas. Además, se pueden usar paréntesis para definir precedencias. La precedencia de operadores sigue las convenciones estándar de Perl. Aquí hay un montón de ejemplos:

Match1 && !Match2            # Match1 y no Match2
!(Match1 || Match2)          # Ni Match1 ni Match2
(Match1 && Match2) || Match3 # Ambos Match1 y Match2 o Match3

Escribir tus propias clases de filtro

Si ninguna de las clases de filtro predefinidas de Log::Log4perl se ajusta a tus necesidades, puedes crear la tuya fácilmente: solo define una nueva clase, derívala de la clase base "Log::Log4perl::Filter" y define sus métodos "new" y "ok" de esta manera:

package Log::Log4perl::Filter::MiFiltro;
use base Log::Log4perl::Filter;
sub new {
    my ($class, %options) = @_;
    my $self = { %options,
               };

    bless $self, $class;
    return $self;
}
sub ok {
     my ($self, %p) = @_;
     # ... decidir y devolver 1 o 0
}
1;

Log4perl llamará al método ok() para determinar si el filtro debe dejar pasar el mensaje o no. Un valor de retorno verdadero indica que el mensaje será registrado por el appender, un valor falso lo bloquea.

Los valores que has definido para sus atributos en el archivo de configuración de Log4perl, se recibirán a través de i

NAME

Log::Log4perl::Filter - Base class for Log4perl Filters

SYNOPSIS

  package Log::Log4perl::Filter::MyFilter;

  use strict;
  use warnings;
  use base 'Log::Log4perl::Filter';

  sub new {
      my ($class, %params) = @_;
      my $self = $class->SUPER::new(%params);
      $self->{color} = delete $params{color}; # Store params
      $self
  }

  sub decide {
      my ($self, $event) = @_;
      return $self->{color} eq 'red' ? $self->DENY : $self->ACCEPT;
  }

DESCRIPTION

This is the base class for all Log4perl filters. Filters allow you to decide whether a logging event should be processed further or not. Filters can be stacked, combined with boolean operators and be applied to specific appenders.

When Log4perl encounters a filter in the configuration, it will try to instantiate it, calling its "new" method:

log4perl.filter.MyFilter       = Log::Log4perl::Filter::MyFilter
log4perl.filter.MyFilter.color = red

will cause "Log::Log4perl::Filter::MyFilter"'s constructor to be called like this:

Log::Log4perl::Filter::MyFilter->new( name  => "MyFilter",
                                      color => "red" );

The custom filter class should use this to set the object's attributes, to have them available later to base log/nolog decisions on it.

ok() is the filter's method to tell if it agrees or disagrees with logging the message. It will be called by Log::Log4perl whenever it needs the filter to decide. A false value returned by ok() will block messages, a true value will let them through.
