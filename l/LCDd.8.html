NOMBRE

LCDd - demonio del servidor LCDproc

SINOPSIS

LCDd [-hf] [-c config] [-d driver] [-i bool] [-a addr] [-p puerto] [-u usuario] [-w tiempo] [-r nivel] [-s bool]

DESCRIPCIÓN

LCDd es la parte del servidor de LCDproc, un demonio que escucha en un puerto determinado (normalmente 13666) y muestra información en una pantalla LCD. Funciona con varios tipos y tamaños de pantallas.

La mayoría de las configuraciones de LCDd se configuran a través de su archivo de configuración /etc/LCDd.conf, algunas de ellas se pueden anular usando opciones de línea de comandos. Antes de ejecutar LCDd, deberías leer detenidamente ese archivo y modificar todo lo necesario según tus necesidades. De lo contrario, podrías encontrar que LCDd no funciona correctamente en tu sistema.

Para aprovechar al máximo LCDd, se requiere un cliente como lcdproc(1), lcdexec(1) o lcdvc.

OPCIONES

Las opciones disponibles son:

-h
Mostrar pantalla de ayuda
-c config
Usar un archivo de configuración distinto de /etc/LCDd.conf
-d driver
Especificar un controlador a usar (solo salida al primero), anulando el parámetro Driver en la sección [Server] del archivo de configuración.
-f
Ejecutar en primer plano, anulando el parámetro Foreground en la sección [Server] del archivo de configuración. El valor predeterminado, si no se especifica en el archivo de configuración, es demonizar LCDd ya que está destinado a operar en segundo plano.
-i bool
Indicar si habilitar (1) o deshabilitar (0) la visualización de la pantalla del servidor LCDproc en la rotación de pantallas, anulando ServerScreen en la sección [Server] del archivo de configuración.
-w tiempodepausa
Tiempo de pausa en cada pantalla (en segundos), anulando el parámetro WaitTime en la sección [Server] del archivo de configuración.
-a dirección
Vincular a la dirección de red dirección, anulando el parámetro Bind en la sección [Server] del archivo de configuración.
-p puerto
Escuchar en el puerto puerto las conexiones entrantes, anulando el parámetro Port en la sección [Server] del archivo de configuración.
-u usuario
Ejecutar como el usuario usuario, anulando el parámetro User en la sección [Server] del archivo de configuración.
-s bool
Enviar mensajes a syslog (1) o a stdout (0), anulando el parámetro ReportToSyslog en la sección [Server] del archivo de configuración.
-r nivel
Establecer el nivel de reporte a nivel, anulando el parámetro ReportLevel en la sección [Server] del archivo de configuración.

The LCDd daemon provides a consistent interface to various LCD displays and input devices. It handles the communication between the application and the hardware, allowing applications to display information on the LCD and receive input from the connected devices without needing to know the specifics of each hardware type.

Multiple drivers can be used simultaneously; thus, for example, a Matrix Orbital display (MtxOrb driver) can be combined with an infrared driver (irman driver).

INVOCATION

LCDd -d MtxOrb -d joy

The invocation example above will start LCDd reading its configuration from the default configuration file /etc/LCDd.conf but overriding the drivers specified therein with the Matrix Orbital driver and the Joystick input driver.

LCDPROC CLIENT-SERVER PROTOCOL

There is a basic sequence:

1. Open a TCP connection to the LCDd server port (usually 13666).
2. Say "hello"
3. The server will return some information on the type
of display available.
4. Define (and use) a new screen and its widgets.
5. Close the socket when done displaying data.

CLIENT COMMANDS

There are many commands for the client to send to the LCDd server:

hello
This starts a client-server session with the LCDd server; the server will return a data string detailing the type of display and its size.
client_set -name name
Set the client's name.
screen_add #id
Add a new screen to the display.
screen_del #id
Remove a screen from the display.
screen_set #id [-name name] [-wid width] [-hgt height] [-priority prio] [-duration int] [-timeout int] [-heartbeat mode] [-backlight mode] [-cursor mode] [-cursor_x xpos] [-cursor_y ypos]
Initialize a screen, or reset its data.
widget_add #screen #id type [-in #frame]
Add a widget of type type to screen #screen.
widget_del #screen #id
Delete widget #id from screen #screen.
widget_set #screen #id data
Set the data used to define a particular widget #id on screen #screen.

HEARTBEAT MODES

Valid heartbeat mode values (for the screen_set command) are:

on
Display pulsing heart symbol.
off
No heartbeat display.
open
Usa la configuración de latido del cliente. Este es el valor predeterminado.

MODOS_DE_RETROILUMINACIÓN

Los valores válidos del modo de retroiluminación (para el comando screen_set) son:

on
Enciende la retroiluminación.
off
Apaga la retroiluminación.
toggle
Apaga la retroiluminación cuando está encendida y viceversa.
open
Usa la configuración de retroiluminación del cliente. Este es el valor predeterminado.
blink
Retroiluminación parpadeante.
flash
Retroiluminación intermitente.

Prioridades

Los ajustes de prioridad válidos (utilizados en el comando screen_set) son los siguientes:

input
El cliente está realizando entrada interactiva.
alert
La pantalla tiene un mensaje importante para el usuario.
foreground
Un cliente activo.
info
Pantalla de información normal, prioridad predeterminada.
background
La pantalla solo es visible cuando no existen pantallas de información normales.
hidden
La pantalla nunca será visible.

Para compatibilidad con versiones anteriores de clientes, también se admite un mapeo de valores numéricos de prioridad:

1 - 64
foreground (primer plano)
65 - 192
normal
193 - (infinito)
background (fondo)

Un ejemplo de cómo usar correctamente las prioridades es el siguiente:

Imagina que estás creando un reproductor de mp3 para lcdproc. Cuando la canción cambia, es agradable mostrar el nuevo nombre inmediatamente. Entonces, podrías establecer la prioridad de tu pantalla en foreground, esperar a que el servidor muestre (o ignore) tu pantalla y luego volver a establecer la pantalla en normal. Esto haría que la pantalla de mp3 apareciera tan pronto como terminara la anterior, y luego volviera a la prioridad normal.

O, digamos que tu cliente monitorea la salud de pacientes de un hospital. Si uno de los pacientes tiene un ataque cardíaco, podrías establecer la prioridad de la pantalla en alert, y se mostraría de inmediato. Ni siquiera esperaría a que terminara la pantalla anterior. Además, la pantalla permanecería encendida la mayor parte del tiempo hasta que el usuario hiciera algo al respecto.

TIPOS_DE_WIDGETS

Los widgets pueden ser cualquiera de los siguientes:

string
Una cadena de texto para mostrar (tal cual).
hbar
Un gráfico de barras horizontal.
vbar
Un gráfico de barras vertical.
title
Un título que se muestra en la parte superior de la pantalla, dentro de una barra de título.
icon
Un icono gráfico.
scroller
Una pantalla de texto desplazable, que se desplaza horizontal o verticalmente.
frame
Un contenedor para albergar otros widgets, lo que permite referirse a ellos como una sola unidad. Un widget se coloca dentro de un frame usando el parámetro -in #id, donde #id se refiere al id del frame.
num
Muestra un dígito decimal grande.

Los widgets se dibujan en la pantalla en el orden en que se crean.

CONFIGURACIÓN_DE_DATOS_DE_WIDGETS

En el comando widget_set, el argumento data depende del widget que se esté configurando. Cada widget toma un conjunto particular de argumentos que define su forma y comportamiento:

string x y texto
Muestra texto en la posición (x,y).
title texto
Usa texto como título para mostrar.
hbar x y longitud
Muestra una barra horizontal comenzando en la posición (x,y) que tiene una longitud de píxeles de ancho.
vbar x y longitud
Muestra una barra vertical comenzando en la posición (x,y) que tiene una longitud de píxeles de alto.
icon x y nombre
Muestra el icono nombre en la posición (x,y).
scroller izquierda arriba derecha abajo dirección velocidad texto
El texto definido se desplazará en la dirección definida. Las direcciones válidas son h (horizontal), m (marquee) y v (vertical). La velocidad define cuántos "movimientos" (o cambios) ocurrirán por fotograma. Un número positivo indica fotogramas por movimiento; un número negativo indica movimientos por fotograma.
frame izquierda arriba derecha abajo ancho alto dir velocidad
Los frames definen un "recuadro" visible en la pantalla, desde la esquina (izquierda, arriba) hasta la esquina (derecha, abajo). Los datos reales pueden ser más grandes y se definen como ancho (width) por alto (height); si es más grande, el frame se desplazará en la dirección (dir) y la velocidad definidas.
num x int
Muestra el dígito decimal grande int en la posición horizontal x, que es una coordenada x de carácter normal en la pantalla. El valor especial 10 para int muestra un dos puntos.

ERRORES

Si LCDd no parece funcionar como se esperaba, intente ejecutarlo en primer plano con el nivel de reporte al máximo y la salida a stderr. Esto se puede lograr sin cambios en el archivo de configuración utilizando la línea de comandos:

LCDd -f -r 5 -s 0
