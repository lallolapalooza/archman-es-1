NOMBRE

Locale::Po4a::VimHelp - convierte archivos de ayuda de Vim desde/hacia archivos PO.

DESCRIPCIÓN

El objetivo del proyecto po4a (PO para cualquier cosa) es facilitar las traducciones (y, lo que es más interesante, el mantenimiento de las traducciones) utilizando herramientas gettext en áreas donde no se esperaban, como la documentación.

"Locale::Po4a::VimHelp" es un módulo para ayudar a la traducción de archivos de ayuda de Vim. Vea también Escribir archivos de ayuda https://vimhelp.org/helphelp.txt.html#help-writing para su sintaxis.

ESTADO DE ESTE MÓDULO

Este módulo se encuentra en una etapa temprana de desarrollo. Se ha probado con éxito en archivos simples como "helphelp.txt". Sin embargo, aún no se ha probado en archivos de ayuda completos, y la forma en que los analiza puede cambiar para correcciones y mejoras, especialmente el ajuste de párrafos.

DESARROLLO

Analizar archivos de ayuda de Vim para po4a es difícil. Aquí hay algunos obstáculos durante el desarrollo de este módulo. Si tiene una idea mejor, no dude en sugerir un parche (con casos de prueba adicionales).

"1. foo" suena como una lista ordenada
No necesariamente. Considere el siguiente párrafo. 
Hay 2 tanukis errantes, no
1. Él está usando su técnica de clonación.

Por la misma razón, lo que parece ser un encabezado (por ejemplo, "1.1 bar") o una lista no ordenada (por ejemplo, "o baz") no se puede detectar.

Las etiquetas alineadas a la derecha deben excluirse del objetivo de traducción
Este tema también es difícil ya que se relaciona con las diferencias lingüísticas en la localización.

Considere el siguiente ejemplo.

Un concepto tan común y corto en algunos idiomas *etiquetas*

que podría traducirse a

Son desconocidos, no hay conceptos correspondientes y *etiquetas*
lleva una oración más larga expresarlos en este idioma

Cuando esto sucede, tienes que decidir en qué punto quieres agregar una etiqueta *elegantemente*. Esto no debería ser fácil. El archivo de ayuda de Vim tiene un formato de ajuste forzado, incluso para partes que no son bloques de código.

Lo mismo se aplica a las referencias de etiquetas como "|ref|".

Aprovechar "--wrapcol" para monitorizar anchos de texto
Usar la opción "--wrapcol" para emitir advertencias cuando el ancho del texto excede los límites especificados parece un enfoque razonable. Los archivos de ayuda oficiales de Vim cuentan con una línea de modo, como "vim:tw=78:ts=8:noet:ft=help:norl:", como se ve en "runtime/doc/if_perl.txt" https://github.com/vim/vim/blob/04cc8975930b7b2c5d6753d3eddf57dab2816518/runtime/doc/if_perl.txt#L307. Sin embargo, hay algunos desafíos a considerar:
Comportamiento del análisis de archivos
Si esta opción se implementa, sería ideal leer el archivo completo primero, detectar si existe la línea de modo y determinar qué secciones están afectadas. Desafortunadamente, el mecanismo de análisis progresivo no se emplea en este caso.
Valor predeterminado frente a valores personalizados
El valor predeterminado genérico de "--wrapcol" es 76, mientras que los archivos de ayuda de Vim comúnmente usan 78. En la mayoría de los casos, el valor en las opciones pasadas a este módulo predetermina a 76, pero no está claro si este valor se estableció explícitamente o se aplicó implícitamente.
