NOMBRE

Lire::Test::FunctionalTestCase - Clase base para escribir pruebas funcionales unitarias

SINOPSIS

use base qw/ Lire::Test::FunctionalTestCase/

DESCRIPCIÓN

Esta es una subclase de Test::Unit::TestCase que puede usarse para facilitar la escritura de pruebas funcionales.

¿QUÉ SON LAS PRUEBAS FUNCIONALES?

A diferencia de las pruebas unitarias que prueban la semántica de la API y documentan las suposiciones internas, las pruebas funcionales son pruebas que verifican la 'funcionalidad' del software en general. Son una especie de documentación de la funcionalidad esperada del software.

Lire::Test::FunctionalTestCase

En Lire, la "funcionalidad esperada" se ejerce ejecutando comandos, por lo que este módulo proporciona métodos convenientes para ejecutar comandos de Lire y probar su salida esperada.

También configura un sendmail simulado que puede usarse para analizar el correo electrónico que el sistema Lire debería enviar.

Algunas funcionalidades de Lire ya no se pueden probar simplemente ejecutando comandos (por ejemplo, la interfaz de usuario basada en Curses::UI no se puede probar de esa manera, sino a través del uso de Lire::Test::CursesUIDriver). Para este tipo de pruebas, esta clase base configurará una nueva instancia de Lire::Config y Lire::PluginManager en el método set_up. Las pruebas que requieren estas funcionalidades pueden simplemente llamar a Lire::Config->init() y Lire::PluginManager->instance()->register_default_converters() sin temor a dañar el entorno de prueba.

homedir()

Devuelve el directorio que se asignará a ENV{'HOME'} cuando se ejecuten los comandos. Este directorio se limpia después de cada prueba.

rundir()

Devuelve el directorio que será el directorio de trabajo cuando se ejecuten los comandos. Este directorio se limpia después de cada prueba.

config_spec()

Devuelve el objeto Lire::Config::TypeSpec que se utilizará en tiempo de ejecución por las pruebas funcionales. Puede usarse para configurar archivos de configuración para la prueba.

locale( [nuevo_locale] )

Cambia la configuración regional bajo la cual se ejecutará la prueba funcional. Por defecto, todas las pruebas se ejecutan en la configuración regional 'C', ignorando todas las variables de entorno del usuario.

Devuelve la configuración regional anterior establecida.

lire_run( $comando_shell )

Este método ejecuta el comando $comando_shell a través del shell y devuelve un objeto Lire::Test::CommandResult que puede usarse para ejecutar pruebas en este comando. El entorno de Lire se configurará antes de invocar el shell.

sent_mail()

Devuelve en una referencia de matriz los mensajes que se enviaron durante la prueba. Los elementos de esta matriz son referencias de hash que contienen dos claves:

recipients
Una referencia de matriz que contiene los destinatarios tal como se pasaron en la línea de comandos a sendmail.
message
El correo electrónico que se envió. Este es el texto completo del correo electrónico. Esto es lo que se pasó a sendmail a través de STDIN.

create_test_file( $nombre_archivo, [$contenido] )

Crea un archivo $nombre_archivo con el contenido $contenido. Este archivo se eliminará después de que se ejecute la prueba en el método tear_down(). Se creará un archivo vacío si se omite el parámetro $contenido.

install_xml_spec( $tipo_especial, $super_servicio, $archivo )

Instala la especificación XML en $archivo del esquema base $super_servicio. El parámetro $tipo_especial especifica dónde se instalará el archivo:

site_filter
El archivo se instalará como una especificación de filtro en el directorio del sistema.
site_report
El archivo se instalará como una especificación de informe en el directorio del sistema.
site_schema
El archivo se instalará como una especificación de esquema en el directorio del sistema.
filter
El archivo se instalará como una especificación de filtro en el directorio HOME.
report
El archivo se instalará como una especificación de informe en el directorio HOME.
schema
El archivo se instalará como una especificación de esquema en el directorio HOME.

Estos archivos se eliminarán después de la prueba.

create_test_cfg_file( $nombre )

Devuelve un objeto Lire::Config::ConfigFile inicializado con la especificación de configuración apropiada. Este archivo de configuración se creará en $HOME/.lire/config/$nombre.xml cuando se utilice lire_run(). Puede usarse para establecer opciones de configuración que se utilizarán cuando se ejecute el comando:

my $cfg = $self->create_test_cfg_file( "test" );
$cfg->global->get( "lr_from" )->set( "flacoste\@logreport.org" );

Si ya se creó un archivo de configuración $nombre, devuelve el objeto ConfigFile asociado.

Tenga en cuenta que si desea que estas variables de configuración tengan efecto al ejecutar pruebas en proceso (no a través de lire_run()), debe llamar a save() en el objeto antes de llamar a Lire::Config->init(). De lo contrario, es mejor establecer la opción de configuración directamente utilizando la API de Lire::Config.
