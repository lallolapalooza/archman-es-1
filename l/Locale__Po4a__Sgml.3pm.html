NOMBRE

Locale::Po4a::Sgml - convierte documentos SGML de/a archivos PO

DESCRIPCIÓN

El objetivo del proyecto po4a (PO para cualquier cosa) es facilitar las traducciones (y, lo que es más interesante, el mantenimiento de las traducciones) utilizando herramientas gettext en áreas donde no se esperaban, como la documentación.

Locale::Po4a::Sgml es un módulo para ayudar a la traducción de documentación en formato SGML a otros idiomas [humanos].

Este módulo utiliza onsgmls(1) para analizar los archivos SGML. Asegúrate de que esté instalado. Asegúrate también de que las DTD de los archivos SGML estén instaladas en el sistema.

OPCIONES ACEPTADAS POR ESTE MÓDULO

debug
Lista separada por espacios de palabras clave que indican qué categoría de mensajes de depuración adicionales deben mostrarse. Los valores posibles son: "entities", "generic", "onsgml", "refs" y "tag".
verbose
Proporciona más información sobre lo que está sucediendo.
translate
Lista separada por espacios de etiquetas adicionales (además de las proporcionadas por la DTD) cuyo contenido debe formar un msgid adicional, es decir, que debe ser traducido.
section
Lista separada por espacios de etiquetas adicionales (además de las proporcionadas por la DTD) que contienen otras etiquetas, algunas de las cuales son de la categoría translate.
indent
Lista separada por espacios de etiquetas que aumentan el nivel de sangría. Esto afectará la sangría en el documento resultante.
verbatim
La disposición dentro de estas etiquetas no debe cambiarse. El párrafo no se ajustará, y no se agregará sangría adicional ni nueva línea con fines cosméticos.
empty
Etiquetas que no necesitan ser cerradas.
ignore
Etiquetas ignoradas y consideradas como datos de caracteres planos por po4a. Es decir, pueden formar parte de un msgid. Por ejemplo, <b> es un buen candidato para esta categoría, ya que incluirlo en la sección translate crearía msgids con solo su contenido (y generalmente no es una oración completa), lo cual es malo.
attributes
Una lista separada por espacios de atributos que necesitan ser traducidos. Puedes especificar los atributos por su nombre (por ejemplo, "lang"), pero también puedes prefijarlo con una jerarquía de etiquetas para especificar que este atributo solo se traducirá cuando esté dentro de la etiqueta especificada. Por ejemplo: "<bbb><aaa>lang" especifica que el atributo lang solo se traducirá si está en una etiqueta "<aaa>", que está dentro de una etiqueta "<bbb>". Los nombres de las etiquetas son en realidad expresiones regulares, por lo que también puedes escribir cosas como "<aaa|bbb>lang" para traducir solo los atributos "lang" que se encuentran en una etiqueta "<aaa>" o una "<bbb>".
qualify
Una lista separada por espacios de atributos para los cuales la traducción debe ser calificada por el nombre del atributo, es decir, el texto extraído para la traducción incluirá tanto el nombre del atributo como su valor. Por ejemplo, para una etiqueta como "<aaa lang_en="foo">", a los traductores se les presentará la cadena "lang_en="foo"". Ten en cuenta que esto también añade automáticamente el atributo dado a la lista de attributes.
force
Continuar incluso si la DTD es desconocida o si onsgmls encuentra errores en el archivo de entrada.
include-all
Por defecto, los msgids que contienen solo una entidad (como "&version;") se omiten para la comodidad de los traductores. La activación de esta opción evita esta optimización. Puede ser útil si el documento contiene una construcción como "<title>&Aacute;</title>", aunque dudo que tales cosas sucedan...
ignore-inclusion
Lista separada por espacios de entidades que no se incluirán. Usa esta opción con precaución: puede hacer que onsgmls (utilizado internamente) agregue etiquetas y haga que el documento de salida no sea válido.

ESTADO DE ESTE MÓDULO

El resultado es perfecto. Es decir, los documentos generados son exactamente iguales a los originales. Pero todavía hay algunos problemas:

  • La salida de errores de onsgmls se redirige a /dev/null por defecto, lo cual es claramente malo. No sé cómo evitarlo.

    El problema es que tengo que "proteger" las inclusiones condicionales (es decir, el " y el "]]>") de onsgmls. De lo contrario, onsgmls se los come, y no sé cómo restaurarlos en el documento final. Para evitarlo, los reescribo como "{PO4A-beg-foo}" y "{PO4A-end}".

    El problema con esto es que "{PO4A-end}" y similares que agrego son inválidos en el documento (no están dentro de una etiqueta <p> o similar).

    Si deseas ver la salida de onsgmls, simplemente agrega lo siguiente a tu línea de comandos (o línea de configuración de po4a):

    -o debug=onsgmls
  • Solo funciona con las DTD DebianDoc y DocBook. Agregar soporte para una nueva DTD debería ser muy fácil. El mecanismo es el mismo para cada DTD, solo tienes que proporcionar una lista de las etiquetas existentes y algunas de sus características.

    De acuerdo, esto necesita más documentación, pero todavía se considera beta, y odio documentar cosas que pueden/cambiarán.

  • Advertencia, el soporte para DTD es bastante experimental. No he leído ningún manual de referencia para encontrar la definición de cada etiqueta. He agregado definiciones de etiquetas al módulo hasta que funcione para algunos documentos que encontré en la red. Si tu documento usa más etiquetas que las mías, no funcionará. Pero como dije anteriormente, solucionarlo debería ser bastante fácil.

    He probado DocBook solo contra la SAG (System Administrator Guide), pero este documento es bastante grande y debería usar la mayoría de las especificidades de DocBook.

    Para DebianDoc, he probado algunos de los manuales del DDP, pero aún no todos.

NAME

Locale::Po4a::Sgml - A PO4A module to handle SGML

DESCRIPTION

This module is a PO4A filter to handle SGML. It can be used to translate SGML files using the standard gettext tools. It can also be used to translate various SGML DTDs, such as DocBook.

The main goal of this module is to extract translatable strings from SGML documents, convert them to PO format, allow translators to translate them, and then convert the translated PO files back into SGML documents.

The module supports the following features:

  • Extraction of translatable strings from SGML elements and attributes.
  • Preservation of SGML markup and structure.
  • Support for various SGML DTDs.
  • Integration with gettext tools for translation.
  • Generation of translated SGML documents.

OPTIONS ACCEPTED BY THIS MODULE

This module accepts the following options:

--sgml-input-file file
Specifies the input SGML file.
--sgml-output-file file
Specifies the output SGML file.
--sgml-po-file file
Specifies the PO file for translation.
--sgml-dtd-file file
Specifies the SGML DTD file.
--sgml-encoding encoding
Specifies the encoding of the SGML file.
--sgml-element element
Specifies an SGML element to be treated as translatable.
--sgml-attribute attribute
Specifies an SGML attribute to be treated as translatable.

STATUS OF THIS MODULE

This module is still under development and may not be fully functional.

Here is a description of the current status of the module:

  • The module can parse SGML files and extract translatable strings.
  • The module can generate PO files from the extracted strings.
  • The module can generate translated SGML files from PO files.
  • However, there are still some issues that need to be addressed:
  • The module does not handle conditional inclusion directives (i.e., the <! [%foo ... ]> and ... ]]> stuff) and some entities (like &version;) correctly. These need to be protected from onsgmls so that they are passed verbatim to the generated document. To work around this, a temporary copy of the input file is made and modified before being passed to onsgmls for parsing.
  • Entities that request file inclusion are replaced by the content of the given file. This allows for the protection of subfiles as well. However, references (filename and line number) are not corrected afterward, and the best approach for this is still uncertain.
