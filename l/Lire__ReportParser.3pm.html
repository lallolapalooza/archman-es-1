NOMBRE

Lire::ReportParser - Lire::XMLParser que parsea reportes XML

SINTAXIS

package MyParser;
use base qw/ Lire::ReportParser /;
sub parse_end {
    return "Finalizado";
}
package main::
my $parser = new MyParser;
my $result = eval { $parser->parsefile( "report.xml" ) };
croak "Error al parsear report.xml: $@" if $@
print $result, "\n";

DESCRIPCIÓN

Este es un Lire::XMLParser(3pm) que maneja documentos XML que siguen el formato de Lire Report Markup Language. Su propósito principal es escribir manejadores personalizados para reportes XML de Lire.

USO

Crea una instancia de una subclase de Lire::ReportParser y usa una de las metodologías parse() o parsefile() para procesar reportes XML. Probablemente nunca usarás directamente el módulo Lire::ReportParser; probablemente usarás una subclase que realmente hace algo al procesar el documento.

new( %args )

my $parser = new Lire::ReportParser::ReportBuilder();

La metodología new() toma parámetros en forma de pares clave-valor. Los parámetros disponibles son específicos a cada procesador. No hay parámetros generales.

ESCRIBIR UN MANEJADOR DE REPORTES XML

Usando Lire::ReportParser, se puede escribir un manejador de reportes XML.

El modelo de programación es similar al interfaz basada en eventos de expat o al modelo conocido como SAX. La principal diferencia con esos modelos es que este módulo ofrece puentes específicos para los reportes de Lire. Por ejemplo, en lugar de tener un evento genérico de inicio de elemento, tienes métodos específicos para cada tipo de elemento, lo que hace fácil atar solo los elementos que estés interesados en. También ofrece funciones que hacen más fácil determinar el contexto (un problema constante en programación basada en eventos).

Si no estás acostumbrado a ese tipo de programación, también está disponible una API orientada a objetos para los reportes XML. Esta API es más similar a un modelo de DOM. Su principal desventaja es que es más lento por tener que parsear toda la documentación XML en memoria para construir una representación del objeto. Pero si necesitas navegar la documentación, es mucho mejor que la API basada en eventos.

La manera principal de usar esta API para escribir un manejador personalizado de reportes XML es mediante la subclase de Lire::ReportParser y sobrescribir las funciones relacionadas con los elementos que estés interesados en.

Hay tres categorías de métodos que puedes sobrescribir.

Métodos de personalización
Estos son métodos que personalizan cómo Lire::ReportParser operará. La más importante es el new() “constructor”.
Métodos genéricos de elemento
Estos son métodos que se invocan antes de los más específicos o de mayor nivel y pueden usarse para atar antes de que los otros eventos se sinteticen.

MÉTODOS DE EVENTO DE NIVEL ALTO

Para cada elemento definido, se invoca un método element_name_start() y un método element_name_end(). Para elementos que contienen texto, se invoca un método element_name_char(), aunque probablemente quieras atar los métodos más fáciles handle_element_name() en estos casos.

Cuando sobrescribes cualquiera de estos métodos (excepto el método handle_element_name()), debes invocar también al método padre:

sub subreport_start {
    my ( $self, $name, $attr ) = @_;
    $self->SUPER::subreport_start( $name, $attr );
    # Manejo específico del procesador.
}

report_start( $name, $attr )

Se llama cuando se detecta la etiqueta de inicio del elemento "report".

El único atributo definido es "version". La versión actual es 2.0, pero se pueden parsear también reportes de versión 1.0.

report_end( $name )

Se llama cuando se detecta la etiqueta de cierre del elemento "report".

handle_title( $title )

Se invoca después de procesar el elemento "title". El parámetro $title contiene el contenido del elemento. Esto puede ser el título de un reporte, subreporte o sección. Se necesita usar el método in_element() para determinar el contexto.

handle_description( $docbook_desc )

Si no sobrescribes los eventos description_start y description_end, el contenido de la descripción se colectará y estará disponible en el método handle_description().

handle_date( $date, $date_epoch )

Se llama después de parsear el elemento "date". La fecha formateada está disponible en el parámetro $date, y el número de segundos desde la época está disponible en el parámetro $date_epoch).

Esta puede ser la fecha de un reporte o de un subreporte; se necesita usar el método in_element() para determinar el contexto adecuado.

handle_timespan( $timespan, $epoch_start, $epoch_end, $period )

Se llama después de parsear el elemento "timespan". La forma de tiempo formateada está disponible en el parámetro $timespan, y las fechas de inicio y fin del tiempo están disponibles como número de segundos desde la época en los parámetros $epoch_start y $epoch_end. El parámetro $period contiene el atributo periodo del tiempo.

Este puede ser el tiempo de un reporte o de un subreporte; se necesita usar el método in_element() para determinar el contexto adecuado.

section_start( $name, $attr )

Se llama cuando se detecta la etiqueta de apertura de un elemento "section".

section_end( $name )

Se llama cuando se detecta la etiqueta de cierre de un elemento "section".

missing_subreport_start( $name, $attr )

Se llama cuando se detecta la etiqueta de apertura de un elemento "missing-subreport". El atributo "superservice" contiene el superservice del subreporte, el atributo "type" contiene el ID de especificación del reporte y el atributo "reason" contendrá la razón por la que falta el subreporte.

missing_subreport_end( $name )

Se llama cuando se detecta la etiqueta de cierre de un elemento "missing-subreport".

subreport_start( $name, $attr )

Se llama cuando se detecta la etiqueta de apertura de un elemento "subreport".

subreport_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "subreport".

table_start( $name, $attr )

Se llama cuando se encuentra la etiqueta de inicio del elemento "table". La propiedad "show" contiene el número máximo de entradas que deben mostrarse (puede haber más entradas que este número).

table_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "table".

table_info_start( $name, $attr )

Se llama cuando se encuentra la etiqueta de cierre del elemento "table-info".

No hay razón para sobrescribir este método en las subclases. El Lire::ReportParser se encarga de parsear el contenido de "table-info" y ofrece esa información a través de un objeto Lire::Report::TableInfo que se accede mediante el método current_table_info().

table_info_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "table-info". Consulte la documentación del método table_info_start() para comentarios importantes.

group_info_start( $name, $attr )

Se llama cuando se encuentra la etiqueta de inicio del elemento "group-info". Consulte la documentación del método table_info_start() para comentarios importantes.

group_info_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "group-info". Consulte la documentación del método table_info_start() para comentarios importantes.

column_info_start( $name, $attr )

Se llama cuando se encuentra la etiqueta de inicio del elemento "column-info". Consulte la documentación del método table_info_start() para comentarios importantes.

column_info_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "column-info". Consulte la documentación del método table_info_start() para comentarios importantes.

group_summary_start( $name, $attr )

Se llama cuando se encuentra la etiqueta de inicio del elemento "group-summary".

group_summary_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "group-summary".

group_start( $name, $attr )

Se llama cuando se encuentra la etiqueta de inicio del elemento "group". Los elementos "group" introducen un tipo de tabla anidada. La propiedad "show" contiene el número máximo de entradas que deben mostrarse, aunque pueden existir más entradas en el informe.

group_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "group".

entry_start( $name, $attr )

Se llama cuando se encuentra la etiqueta de inicio del elemento "entry".

entry_end( $name )

Se llama cuando se encuentra la etiqueta de cierre del elemento "entry".

handle_name( $name_rec )

Se llama después de parsear el elemento "name". El parámetro $name_rec es un referencia a un hash que contiene diferentes valores del dato de nombre. Las claves definidas en este hash:

content
Es el contenido real del elemento "name". Este contiene el nombre en un formato adecuado para la visualización.
value
Contiene el valor no formato del elemento "name". Por ejemplo, cuando el nombre es una cadena de tiempo, esta propiedad contendrá el tiempo en segundos desde el epoch.
range
Para algunos nombres, el contenido real expresa un rango (tiempo, tamaño, etc.). Esta propiedad contiene la longitud del rango.
col_info
El objeto Lire::ColumnInfo que describe la columna en la cual se encuentra este nombre.

handle_value( $value_rec )

Se llama después de parsear el elemento "value". El parámetro $value_rec es una referencia a un hash que contiene diferentes valores del dato de valor. Las claves definidas en este hash:

content
Es el contenido real del elemento "value". Este contiene el valor en un formato adecuado para la visualización.
value
Contiene el valor no formateado. Por ejemplo, cuando se muestren los bytes usando "1M" o "1.1G", esta propiedad contendrá el valor en bytes.
total
Se utiliza por los valores que representan un promedio. Contiene el total que forma el promedio.
n
Se utiliza por los valores que representan un promedio. Contiene el total que se utilizó en la división para calcular el promedio.
col_info
El objeto Lire::ColumnInfo que describe la columna en la cual se encuentra este nombre.

handle_summary_value( $value_rec )

Se llama después de parsear el elemento "value" ubicado dentro del elemento "group-summary". El parámetro $value_rec es idéntico al del método handle_value().

handle_chart_configs( $configs )

Si el Subreport contiene configuraciones de gráfico, se pasarán a este evento un array de objetos Lire::Report::ChartConfig.

MÉTODOS DE CONTEXTO

Finalmente, aquí una lista de métodos adicionales que pueden usarse para consultar información contextual durante el procesamiento de elementos.

current_subreport_count( )

Devuelve el número de subinformes presentes hasta ahora en el informe. Este número es igual al número de elementos "subreport" procesados, es decir, el subinforme actual no se cuenta hasta que se procese la etiqueta de cierre.

current_section_subreport_count( )

Devuelve el número de subinformes presentes hasta ahora en la sección. Este número es igual al número de elementos "subreport" procesados, es decir, el subinforme actual no se cuenta hasta que se procese la etiqueta de cierre.

current_date( )

Devuelve el contenido del elemento "date" que se aplica al elemento actual. Este contendrá la fecha del subinforme actual o la fecha por defecto tomada del elemento "report".

La fecha se devuelve como una referencia a un hash que contendrá la fecha formateada en la clave "date" y la fecha en segundos desde el epoch en la clave "time".

current_timespan( )

Devuelve el contenido del elemento "timespan" que se aplica al elemento actual. Este contendrá la fecha del subinforme actual o la fecha por defecto tomada del elemento "report".

El intervalo de tiempo se devuelve como una referencia a un hash que contendrá el intervalo formateado en la clave "timespan". Las fechas de inicio y fin del intervalo están disponibles en segundos desde el epoch en las claves "start" y "end". La clave "period" contiene el tiempo.

CONTEXT METHODS

These methods are used to get information about the current report element being processed. They are useful in specific contexts such as "entry", "group", "table", or "subreport".

current_report( )

Returns the current report object.

current_timespan( )

Returns the current time span for the report.

current_superservice( )

Useful in "subreport" context, it returns the superservice's of the current subreport.

current_type( )

Useful in "subreport" context, it returns the ID of the report specification that was used to generate the current subreport.

current_table_info()

Useful when processing "group" and "entry", this returns a Lire::Report;:TableInfo object which describes the layout of the current table.

current_group_entry_show( )

Useful in "table" and "group" context, it returns the maximum number of entries that should be displayed.

show_current_entry( )

Useful in "entry" context , this can be used to test whether or not the current "entry" should be displayed based on the current entry index and the parent's "show" attribute.

current_table_entry_count( )

Useful in "table" context, it returns the number of entries that were processed so far. This only reports the entries in the "table" element, not counting the one in the nested "group".
