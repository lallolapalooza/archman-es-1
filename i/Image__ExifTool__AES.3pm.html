NOMBRE

Image::ExifTool::AES - Cifrado AES con encadenamiento de bloques de cifra

SINOPSIS

use Image::ExifTool::AES qw(Crypt);
$err = Crypt(\$plaintext, $key, 1);   # cifrado
$err = Crypt(\$ciphertext, $key);     # descifrado

DESCRIPCIÓN

Este módulo contiene una implementación de los algoritmos de cifrado/descifrado AES con encadenamiento de bloques de cifra (CBC) y relleno PKCS #5 RFC 2898. Este es el modo de cifrado AESV2 y AESV3 utilizado en los documentos PDF.

EXPORTACIONES

No exporta nada por defecto, pero se puede exportar "Crypt".

MÉTODOS

Crypt

Implementa el cifrado/descifrado AES con encadenamiento de bloques de cifra.

Entradas:
0) Referencia escalar para los datos a cifrar/descifrar.

1) Cadena de clave de cifrado (debe tener una longitud de 16, 24 o 32).

2) [opcional] Indicador de cifrado (falso para descifrar).

3) [opcional] Indicador para evitar eliminar el relleno después de descifrar, o para evitar añadir 16 bytes de relleno antes de cifrar cuando la longitud de los datos ya es múltiplo de 16 bytes.

Devuelve:
En caso de éxito, el valor de retorno no está definido y los datos se cifran o descifran según lo especificado. De lo contrario, devuelve una cadena de error y los datos quedan en un estado indeterminado.
Notas:
La longitud de la clave de cifrado determina el modo AES, con longitudes de 16, 24 y 32 bytes que dan como resultado AES-128, AES-192 y AES-256.

Al cifrar, los datos de entrada pueden tener cualquier longitud y se rellenarán hasta un tamaño de bloque par de 16 bytes utilizando la técnica de relleno especificada. Si el indicador de cifrado tiene una longitud de 16, se utiliza como vector de inicialización para el encadenamiento de bloques de cifra; de lo contrario, se genera un IV aleatorio. Tras la devolución exitosa, los datos estarán cifrados, con los primeros 16 bytes de los datos siendo el IV de CBC.

Al descifrar, los datos de entrada comienzan con el vector de inicialización de CBC de 16 bytes.

ERRORES

Este código es deslumbrantemente lento. Pero, en verdad, ralentizar el procesamiento es el propósito principal del cifrado, por lo que esto no realmente se puede considerar un error.
