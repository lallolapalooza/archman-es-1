Inline::C(3) Documentación de Perl aportada por el usuario Inline::C(3)

NOMBRE

Inline::C - Soporte del lenguaje C para Inline

VERSIÓN

Este documento describe Inline::C versión 0.82.

DESCRIPCIÓN

"Inline::C" es un módulo que permite escribir subrutinas de Perl en C. Desde la versión 0.30, el módulo Inline admite varios lenguajes de programación y cada lenguaje tiene su propio módulo de soporte. Este documento describe cómo usar Inline con el lenguaje de programación C. También profundiza un poco en los internos de Perl C.

Si quieres empezar a trabajar con ejemplos de programación de inmediato, consulta Inline::C::Cookbook. Para más información sobre Inline en general, consulta Inline.

USO

Nunca usas realmente "Inline::C" directamente. Es solo un módulo de soporte para usar "Inline.pm" con C. Así que el uso siempre es:

use Inline C => ...;

o

bind Inline C => ...;

DEFINICIONES DE FUNCIONES

La gramática de Inline para C reconoce ciertas definiciones de funciones (o firmas) en tu código C. Si una firma es reconocida por Inline, estará disponible en el espacio de Perl. Es decir, Inline generará el "pegamento" necesario para llamar a esa función como si fuera una subrutina de Perl. Si la firma no es reconocida, Inline simplemente la ignorará, sin quejas. No estará disponible desde el espacio de Perl, aunque sí lo estará desde el espacio de C.

Inline busca definiciones de funciones estilo ANSI/prototipo. Deben tener la forma:

tipo-de-retorno nombre-de-función ( pares-tipo-nombre ) { ... }

Los tipos más comunes son: "int", "long", "double", "char*"y "SV*". Pero puedes usar cualquier tipo para el que Inline pueda encontrar un typemap. Inline usa el archivo "typemap" distribuido con Perl como predeterminado. Puedes especificar más typemaps con la opción de configuración "typemaps" .

También se puede usar un tipo de retorno "void" . Los siguientes son ejemplos de definiciones de funciones válidas.

int Foo(double num, char* str) {
void Foo(double num, char* str) {
void Foo(SV*, ...) {
long Foo(int i, int j, ...) {
SV* Foo(void) { # El argumento 'void' no es válido con el analizador ParseRecDescent.
                # Solo funciona con el analizador ParseRegExp.
                # Ver la sección sobre `using` (más abajo).
SV* Foo() {  # Alternativa a especificar el argumento 'void'. Es válida con
             # ambos analizadores, ParseRecDescent y ParseRegExp.

Las siguientes definiciones no serían reconocidas:

Foo(int i) {               # sin tipo de retorno
int Foo(float f) {         # sin typemap (predeterminado) para float
int Foo(num, str) double num; char* str; {

Observa que Inline solo busca definicionesde funciones, no los prototiposde las funciones. Las definiciones son la sintaxis que precede directamente a un cuerpo de función. Además, Inline no escanea archivos externos, como cabeceras. Solo el código pasado a Inline se usa para crear enlaces; aunque otras bibliotecas pueden enlazarse y llamarse desde el espacio de C.

OPCIONES DE CONFIGURACIÓN DE C

Para información sobre cómo especificar opciones de configuración de Inline, consulta Inline. Esta sección describe cada una de las opciones de configuración disponibles para C. La mayoría de las opciones corresponden a opciones de MakeMaker o XS con el mismo nombre. Consulta ExtUtils::MakeMaker y perlxs.

"auto_include"
Especifica sentencias extra a incluir automáticamente. Se añadirán a las predeterminadas. Se añadirá automáticamente un carácter de nueva línea. 
use Inline C => config => auto_include => '#include "yourheader.h"';
"autowrap"
Si "enable => autowrap", Inline::C analizará las declaraciones de funciones (sentencias de prototipo) en tu código C. Para cada declaración a la que pueda enlazará, creará un envoltorio ficticio que llamará a la función real, la cual puede estar en una biblioteca externa. Esto es una comodidad conveniente para funciones que de otro modo solo requerirían una función envoltorio vacía.

Esto es similar a la funcionalidad base que obtienes de "h2xs". Puede ser muy útil para enlazar bibliotecas externas.

"boot"
Especifica el código C a ejecutar en la sección "BOOT" de XS. Corresponde al parámetro de XS.
"cc"
Especifica qué compilador usar.
"ccflags"
Especifica los indicadores del compilador; igual que la opción "CCFLAGS" de ExtUtils::MakeMaker. Lo que se especifique aquí reemplaza al $Config{ccflags}predeterminado. A menudo, querrás añadir un indicador extra o dos sin pisar los indicadores predeterminados, en cuyo caso podrías usar "ccflagsex" (ver más abajo) o, si Config.pm ya ha sido cargado: 
use Inline C => Config => ccflags => $Config{ccflags} . " -DXTRA -DTOO";
"ccflagsex"
Extiende los indicadores del compilador. Establece "CCFLAGS" como $Config{ccflags} seguido de un espacio, seguido del valor especificado: 
use Inline C => config => ccflagsex => "-DXTRA -DTOO";
"cppflags"

Especifica los indicadores del preprocesador. Se pasan al "cpp" preprocesador de C por Preprocess() en Inline::Filters.

use Inline C => <<'END',
    CPPFLAGS => ' -DPREPROCESSOR_DEFINE',
    FILTERS => 'Preprocess';
use Inline C => <<'END',
    CPPFLAGS => ' -DPREPROCESSOR_DEFINE=4321',
    FILTERS => 'Preprocess';
"filters"
Permite especificar una lista de filtros de código fuente. Si se solicita más de uno, asegúrate de agruparlos con una referencia a array. Los filtros pueden ser referencias a subrutinas o nombres de filtros proporcionados por el módulo suplementario Inline::Filters.

Tu código fuente será filtrado justo antes de ser analizado por Inline. La huella digital MD5 se genera antes del filtrado. Los filtros de código fuente pueden usarse para hacer cosas como eliminar la documentación POD, pre-expandir las sentencias "#include" o cualquier otra cosa que desees. Por ejemplo:

use Inline C => DATA =>
           filters => [Strip_POD => \&MyFilter => Preprocess ];

Los filtros se invocan en el orden especificado. Consulta Inline::Filters para más información.

Si un filtro es una referencia a array, se asume que es el uso de un complemento de filtro nombrado por el primer elemento de esa referencia a array. El resto de los elementos de la referencia a array se usan como argumentos al filtro. Por ejemplo, considera un parámetro "filters" como este:

use Inline C => DATA => filters => [ [ Ragel => '-G2' ] ];

Para que Inline::C procese este filtro, intentará requerir el módulo Inline::Filters::Ragel y luego llamará a la función "filter" en ese paquete con el argumento '-G2'. Esta función devolverá la función de filtrado real.

"inc"
Especifica una ruta de inclusión a usar. Corresponde al parámetro de MakeMaker. Espera una ruta completamente calificada. 
use Inline C => config => inc => '-I/inc/path';
"ld"
Especifica qué enlazador usar.
"lddlflags"
Especifica qué indicadores del enlazador usar.

ESCRIBIENDO SUBRUTINAS

DEFINICIONES DE FUNCIONES

Las definiciones de tus funciones C caerán en una de las siguientes cuatro categorías. Para cada categoría hay consideraciones especiales.

"int Foo(int arg1, char* arg2, SV* arg3) {"
Este es el caso más simple. Tienes un tipo de retorno que no es "void" y una lista de argumentos de longitud fija. No necesitas preocuparte mucho. Todas las conversiones ocurrirán automáticamente.
"void Foo(int arg1, char* arg2, SV* arg3) {"
En esta categoría tienes un tipo de retorno "void". Esto significa que o bien quieres retornar nada, o quieres retornar una lista. En este último caso, necesitarás hacer push de los valores en la Pila tú mismo. Hay algunas macros de Inline que facilitan esto. Código como esto: 
int i, max; SV* my_sv[10];
Inline_Stack_Vars;
Inline_Stack_Reset;
for (i = 0; i < max; i++)
  Inline_Stack_Push(my_sv[i]);
Inline_Stack_Done;

Después de resetear el puntero de la Pila, este código hace push de una serie de valores de retorno. Al final utiliza "Inline_Stack_Done" para marcar el fin de la pila de retorno.

Si realmente quieres retornar nada, entonces no uses las macros "Inline_Stack_". Si debes usarlas, entonces establece usa "Inline_Stack_Void" al final de tu función.

"char* Foo(SV* arg1, ...) {"
En esta categoría tienes un número no fijo de argumentos. Esto significa que tendrás que hacer pop de los valores de la Pila tú mismo. Hazlo así: 
int i;
Inline_Stack_Vars;
for (i = 0; i < Inline_Stack_Items; i++)
  handle_sv(Inline_Stack_Item(i));

El tipo de retorno de Inline_Stack_Item(i) es "SV*".

"void* Foo(SV* arg1, ...) {"
En esta categoría tienes tanto un tipo de retorno "void" como un número no fijo de argumentos. Simplemente combina las técnicas de las Categorías 3 y 4.

EJEMPLOS

Aquí hay algunos ejemplos. Cada uno es un programa completo que puedes intentar ejecutar tú mismo. Para muchos más ejemplos, consulta Inline::C::Cookbook.

Ejemplo #1 - Saludos

Este ejemplo tomará un argumento de cadena (un nombre) e imprimirá un saludo. La función se llama con una cadena y con un número. En el segundo caso, el número se fuerza a una cadena.

Observa que no necesitas "#include <stdio.h">. El archivo de cabecera "perl.h" que se incluye por defecto, carga automáticamente los archivos de cabecera C estándar por ti.

use Inline 'C';
greet('Ingy');
greet(42);
__END__
__C__
void greet(char* name) {
  printf("Hello %s!\n", name);
}

Ejemplo #2 - y Saludos

Esto es similar al último ejemplo, excepto que el nombre se pasa como un "SV*" (puntero a Valor Escalar) en lugar de una cadena ("char*"). Eso significa que necesitamos convertir el "SV" a una cadena nosotros mismos. Esto se logra usando la función "SvPVX" que es parte de la API interna de "Perl". Consulta "perldocperlapi" para más información.

Un problema es que "SvPVX" no convierte automáticamente las cadenas a números, por lo que obtenemos una pequeña sorpresa cuando intentamos saludar a 42. El programa se segfaultea, una ocurrencia común al adentrarse en las entrañas de Perl.

use Inline 'C';
greet('Ingy');
greet(42);
__END__
__C__
void greet(SV* sv_name) {
  printf("Hello %s!\n", SvPVX(sv_name));
}

Ejemplo #3 - Arreglando el problema

Podemos arreglar el problema del Ejemplo #2 usando la función "SvPV" en su lugar. Esta función convertirá el "SV" a cadena si no contiene una cadena. "SvPV" devuelve la longitud de la cadena como segundo parámetro. Como no nos importa la longitud, podemos simplemente poner "PL_na" ahí, que es una variable especial diseñada para ese propósito.

use Inline 'C';
greet('Ingy');
greet(42);
__END__
__C__
void greet(SV* sv_name) {
  printf("Hello %s!\n", SvPV(sv_name, PL_na));
}

ERRORES Y DEFICIENCIAS

Si usas nombres de funciones C que también son usados internamente por Perl, obtendrás un error de carga en tiempo de ejecución. Actualmente no hay funcionalidad para prevenir esto o para advertirte. Por ahora, una lista de los símbolos internos de Perl está empaquetada en la distribución del módulo Inline bajo el nombre de archivo 'symbols.perl'. Evita usar estos en tu código.
