DESCRIPCIÓ

N

La función langinfo() consulta diversa información de configuración regional que puede usarse para localizar la salida y las interfaces de usuario. Utiliza la configuración regional subyacente actual, independientemente de si se llamó dentro del ámbito de "use locale". La función langinfo() requiere un argumento numérico que identifica la constante de configuración regional a consultar: si no se proporciona ningún argumento, se usa $_. Las constantes numéricas adecuadas para usarse como argumentos son exportables desde I18N::

Langinfo.

El siguiente ejemplo importará la función langinfo() en sí misma y tres constantes para usar como argumentos de langinfo(): una constante para el día abreviado de la semana (la numeración comienza desde domingo = 1) y dos constantes más para las respuestas afirmativa y negativa a una pregunta de sí/no en la configuración regional

actual. 
use I18N::Langinfo qw(langinfo ABDAY_1 YESSTR NOSTR);
my ($abday_1, $yesstr, $nostr) =
    map { langinfo($_) } (ABDAY_1, YESSTR, NOSTR);
print "$abday_1? [$yesstr/$nostr]
";

Para sistemas sin

"nl_langinfo"

Este módulo originalmente era solo una envoltura para la función de libc "nl_langinfo", y no funcionaba en sistemas que carecían de ella, como

Windows.

A partir de Perl 5.28, este módulo funciona en todas las plataformas. Cuando "nl_langinfo" no está disponible, utiliza varios métodos para construir lo que esa función, si estuviera presente, devolvería. Pero puede haber fallos potenciales. Estos son los elementos que podrían ser

De lo contrario, depende del nombre de la configuración regional. Si es de la forma "foo.bar", asumirá que "bar" es el juego de caracteres; y también conoce las dos configuraciones regionales "C" y "POSIX". Si ninguna de ellas aplica, devuelve ""

Antes de Perl 5.28, los valores devueltos no son

fiables para las

constantes de configuración regional "RADIXCHAR" y "THOUSEP". A partir de 5.28, cambiar configuraciones regionales en compilaciones con hilos está soportado en sistemas que ofrecen funciones de configuración regional seguras para hilos. Estos incluyen sistemas POSIX 2008 y Windows a partir de Visual Studio 2005, y este módulo funcionará correctamente en tales situaciones. Sin embargo, en compilaciones con hilos en Windows anteriores a Visual Studio 2015, recuperar

los elementos

"CRNCYSTR" y "THOUSEP" puede resultar en una condición de carrera con un hilo que se ha convertido para usar la configuración regional global. Es bastante poco común que un hilo haya hecho esto.
