NOMBRE

Inline-FAQ - El FAQ de Inline

DESCRIPCIÓN

Bienvenido al FAQ oficial de Inline. En este caso, FAQ significa: Preguntas Antiguamente Respondidas

Esta es una colección de correos electrónicos antiguos y extensos que yo y otros hemos enviado a la lista de correo de Inline. (inline@perl.org). Han sido revisados y editados para la edificación general de Inline. Algunos de ellos pueden estar relacionados con un lenguaje específico. Se presentan aquí en un formato tradicional de FAQ.

GENERAL INLINE

Dado que hasta ahora solo hay un puñado de contenido, todas las preguntas frecuentes están actualmente bajo este encabezado.

¿Qué tan desechable es un ".Inline" o "_Inline" directorio?

Probablemente necesite ser más enfático sobre el papel de los directorios de caché "_Inline/". Dado que se crean automáticamente, son completamente desechables. Los elimino todo el tiempo. Y está bien tener uno diferente para cada proyecto. De hecho, siempre que no tenga "~/.Inline/" definido, Inline creará un nuevo directorio "./_Inline" (a menos que haya hecho algo para anular este proceso automático, como usar la opción de configuración DIRECTORY o la variable de entorno "PERL_INLINE_DIRECTORY"). Puede moverlo a "./.Inline" y seguirá funcionando si desea darle más longevidad y ocultarlo de la vista. Hay una larga y complicada lista de reglas sobre cómo se utilizan/crean los directorios "[_.]Inline/". Pero fue diseñado para brindarle la mayor flexibilidad/facilidad de uso. Nunca tenga miedo de eliminarlos. Simplemente volverán a aparecer la próxima vez que se necesiten. :)

¿Cuál es la mejor manera de empaquetar código Inline para CPAN?

Esta distribución incluye Inline::MakeMaker, descrito a continuación, que toma medidas especiales durante la instalación de su módulo para asegurarse de que el código se compile e instale, en lugar de que los usuarios lo compilen en tiempo de ejecución. Pero los usuarios de su módulo deben instalar Inline y el módulo de soporte de lenguaje como Inline::CPP como requisitos previos para su módulo.

Una mejor manera de distribuir su módulo es con Inline::Module, que toma medidas especiales para eliminar las dependencias de Inline::* y convertirlo en un módulo XS simple durante la construcción de su distribución antes de subirlo a CPAN. También se integra fácilmente con Dist::Zilla y otras herramientas de autoría modernas para una experiencia de autoría más optimizada.

¿Qué pasó con la opción "SITE_INSTALL"?

"SITE_INSTALL" ya no existe. Iba a dejarlo y cambiar la semántica, pero pensé que sería mejor eliminarlo, para que la gente no intentara usarlo de la manera antigua. Ahora existe "_INSTALL_" (pero se supone que no lo sabes :). Funciona mágicamente a través del uso de Inline::MakeMaker. Lo expliqué antes, pero vale la pena repasarlo porque es el mayor cambio para la versión 0.40. Aquí se explica cómo instalar 'permanentemente' una extensión de Inline (módulo basado en Inline) con la versión 0.40:

1.
Crea un módulo con Inline.
2.
Pruébalo usando la caché local normal "_Inline/".
3.
Crea un Makefile.PL (como el producido por h2xs)
4.
Cambia 'use ExtUtils::MakeMaker' a 'use Inline::MakeMaker'
5.
En WriteMakefile() de Makefile.PL inserta: 
CONFIGURE_REQUIRES  =>  {
    'Inline::MakeMaker'     => 0.45,
    'ExtUtils::MakeMaker'   => 6.52,
},

(Consulta la sección "Escribir módulos con Inline" de Inline.pod para obtener una explicación/elaboración.)

6.
Cambia tu 'use Inline C => DATA' a 'use Inline C => DATA => NAME => Foo

=> VERSION => 1.23' + Asegúrate de que NAME coincida con el nombre de tu paquete ('Foo'), o => comience con 'Foo::'. + Si quieres silenciar una advertencia inofensiva que aparecerá cuando el módulo se cargue mediante "require", haz "Inline->init();". Ve a "Escribir módulos con Inline" en el pod de Inline para obtener detalles. + Asegúrate de que => VERSION coincida con $Foo::VERSION. Debe ser una cadena (no un número) => que coincida con "/^\d\.\d\d$/" + Realiza la danza de perl / make / test / install => (gracias binkley :)

Con Inline 0.41 (o alrededor) puedes omitir los pasos 3 y 4, y simplemente decir "perl -MInline=INSTALL ./Foo.pm". Esto funcionará también para módulos que no son de Inline. Se convertirá en el estándar de facto (ya que no hay un estándar fácil) para instalar un módulo Perl. Permitirá parámetros de Makefile.PL "perl -MInline=INSTALL ./Foo.pm - PREFIX=/home/ingy/perl" y cosas así. También utilizará un MANIFEST si proporcionas uno.

¿Cómo creo una distribución binaria usando Inline?

He descubierto cómo crear e instalar una distribución binaria PPM; ¡con o sin la distribución del código C! Y he decidido compartirlo con todos ustedes :)

NOTA: Las versiones futuras de Inline harán que este proceso sea un comando de una sola línea. Pero
por ahora, solo use esta simple receta.

La distribución Inline 0.40 viene con un módulo de extensión de ejemplo llamado Math::Simple. Teóricamente, podrías distribuir este módulo en CPAN. Tiene todo el soporte necesario para la instalación. Puedes encontrarlo en "Inline-0.40/modules/Math/Simple/". Aquí están los pasos para convertirlo en una distribución binaria sin código fuente C.

NOTA: El destinatario de esta distribución binaria necesitará tener instalado el módulo
PPM.pm. Este módulo requiere muchos otros módulos de CPAN.
ActivePerl (disponible para Win32, Linux y Solaris) tiene todos
estos incluidos. Si bien ActivePerl no es obligatorio, hace las cosas (mucho)
más fáciles.
