DESCRIPCIÓ

N

IO::All combina todos los mejores módulos de IO de Perl en una sola interfaz orientada a objetos elegante para simplificar enormemente tus modismos de IO de Perl diarios. Exporta una única función llamada "io", que devuelve un nuevo objeto IO::All. ¡Y ese objeto puede hacerlo

todo!

El objeto IO::All es un proxy para IO::File, IO::Dir, IO::Socket, Tie::File, File::Spec, File::Path, File::MimeInfo y File::ReadBackwards; así como todos los módulos DBM y MLDBM. Puedes usar la mayoría de los métodos encontrados en estas clases y en IO::Handle (del cual heredan). IO::All añade docenas de otros métodos idiomáticos útiles incluyendo funciones de estado y manipulación de

archivos.

IO::All es enchufable, y módulos como IO::All::LWP y IO::All::Mailto añaden aún más funcionalidad. Opcionalmente, cada objeto IO::All puede vincularse a sí mismo. Esto significa que puedes usar la mayoría de las funciones incorporadas de IO de perl en él: readline, "<>", getc, print, printf, syswrite, sysread,

close.

La magia distintiva de IO::All es que abrirá automáticamente (y cerrará) archivos, directorios, sockets y otras cosas de IO por ti. Nunca necesitas especificar el modo ("<", ">>", etc), ya que está determinado por el contexto de uso. Eso significa que puedes reemplazar

esto: 
open STUFF, '<', './mystuff'
  or die "No se puede abrir './mystuff' para entrada:\n$!";
local $/;
my $stuff = <STUFF>;
close
STUFF;

con

esto: 
my $stuff < io '.
/mystuff';

¡Y eso es una cosa buena!

Nota sobre

La función "io" es un constructor mágico. Es fácil de usar y normalmente hará lo correcto, pero también puede fallar

fácilmente.

Toma un único argumento opcional y determina qué tipo de objeto subclase de IO::All devolver. Sin argumentos, devuelve un objeto "IO::All", que no tiene métodos de E/S, pero tiene métodos para construir objetos de subclase como "IO::All::F

ile".

En otras palabras, estas 2 sentencias suelen ser

iguales:

all;

Use la primera forma cuando esté demos

trando sus virtudes de Perl de pere
za e impaciencia, y use la segunda form
a cuando su trabajo esté en juego.

SOBRECARGA DE

OPERADORES

Los objetos IO::All sobrecargan un pequeño conjunto de operadores de Perl con gran efecto. Las sobrecargas se limitan a "<", "<<", ">", ">>", operaciones de desreferenciación y conversión a

cadena.

Aunque se sobrecargan relativamente pocas operaciones, en realidad existe una enorme matriz de posibilidades para la magia. Esto se debe a que la sobrecarga es sensible a los tipos, la posición y el contexto de los argumentos, y un objeto IO::All puede ser de uno de muchos

tipos.

La sobrecarga más importante con la que familiarizarse es la conversión a cadena. Los objetos IO::All se convierten a cadena en su nombre de archivo o directorio. Aquí imprimimos el contenido del directorio

actual: 
perl -MIO::All -le 'print for io(".")->
all'

es lo mismo

que: 
perl -MIO::All -le 'print $_->name for io(".")->
all'

La conversión a cadena es importante porque permite que las operaciones de IO::All devuelvan objetos cuando de otro modo podrían devolver nombres de archivo. Así, el destinatario puede usar el resultado ya sea como objeto o como

cadena.

">" y "<" mueven datos entre objetos en la dirección apuntada por el

operador. 
$content1 < io('file1');
$content1 > io('file2');
io('file2') > $content3;
io('file3') < $content3;
io('file3') > io('file4');
io('file5') < io('file4')
;

">>" y "<<" hacen lo mismo, excepto que la cadena o archivo de destino se añade al

final.

Un archivo IO::All usado como referencia de matriz se asocia usando Tie::

File: 
$file = io "file";
# Imprimir la última línea del archivo
print $file->[-1];
# Insertar una nueva línea en el medio del archivo
$file->[$#$file / 2] = 'New
line';

Un archivo IO::All usado como referencia de hash se asocia a una clase

DBM: 
io('mydbm')->{ingy} =
'YAML';

Un directorio IO::All usado como referencia de matriz expondrá cada archivo o subdirectorio como un elemento de la

matriz. 
print "$_\n" for @{io 'dir'}
;

Los directorios IO::All usados como referencias de hash tienen nombres de archivo como claves y objetos IO::All como

valores: 
print io('dir')->{'foo.txt'}->
slurp;

Los archivos usados como referencias escalares se leen

completos: 
print ${io('dir')->{'foo.txt'}}
;

No todas las combinaciones de operaciones y tipos de objeto están soporta

das. Algunas simplemente no se han añadido todavía, y algunas simplemente
no tienen sentido. Si usa una combinación no válida, se lanzará un error.

Bloqueo de

Archivos

IO::All hace que sea muy fácil bloquear archivos. Simplemente use el método "lock". Aquí hay un programa independiente que demuestra el bloqueo tanto para escritura como para

lectura: 
use IO::All;
my $io1 = io('myfile')->lock;
$io1->println('line 1');
fork or do {
  my $io2 = io('myfile')->lock;
  print $io2->slurp;
  exit;
};
sleep 1;
$io1->println('line 2');
$io1->println('line 3');
$io1->
unlock;

Hay muchas cosas sutiles ocurriendo aquí. Se emite un bloqueo exclusivo para $io1 en el primer "println". Esto se debe a que el archivo no se abre realmente hasta la primera operación de

E/S.

Cuando el proceso hijo intenta leer el archivo usando $io2, se coloca un bloqueo compartido en él. Dado que $io1 tiene el bloqueo exclusivo, la lectura completa se

bloquea.

El proceso padre duerme solo para asegurarse de que el proceso hijo tenga la oportunidad. El padre necesita llamar a "unlock" o "close" para liberar el bloqueo. Si todo

va bien, el hijo
imprimirá 3 líneas.

NAME

IO::All — A OO interface to all things IO

VERSION

0.87

SYNOPSIS

  use IO::All;
  my $io = io('filename');
  my $file = $io->file;
  my $dir  = $io->dir;
  my $size = $io->size;
  my $mode = $io->mode;
  my $content = $io->slurp;
  my $lines = $io->lines;
  my $parent = $io->parent;
  print $io << "EOF";
  Some text
  EOF
  $io->print("More text\n");
  $io->slurp( "more text\n" );

DESCRIPTION

IO::All is a framework for interacting with various IO resources. It provides a common interface to files, directories, sockets, etc. It also allows for easy manipulation of file content, such as reading entire files into memory, or iterating over lines.

IO::All uses a system of role delegation. When you create an IO::All object, it will try to determine the type of IO resource and delegate the appropriate methods to a specialized object. For example, if you provide a filename, it will delegate file-related methods to an IO::All::File object.

The primary goal of IO::All is to simplify common IO tasks and provide a consistent interface across different IO types.

USAGE

The main entry point for IO::All is the io() function. It takes a string representing the IO resource (e.g., a filename) and returns an IO::All object.

You can then call various methods on this object to interact with the resource.

METHOD ROLE CALL

You can call methods that correspond to the roles that the object might have. For example, if you have an IO::All object that might be a directory, you can call $io->dir to get an IO::All::Dir object.

  my $io = io('some_directory');
  my $dir = $io->dir; # Returns an IO::All::Dir object

If the object does not support that role, it will return undef.

  my $io = io('some_file.txt');
  my $dir = $io->dir; # Returns undef

OPERATOR OVERLOADING

IO::All overloads operators for convenient reading and writing.

[ > ]
Write to the IO object.
[ < ]
Read from the IO object.
  my $io = io('file.txt');
  $io << 'Some text'; # Write 'Some text' to file.txt
  my $content = $io << ''; # Read all content from file.txt

COOKBOOK

Reading whole file
      my $content = io('file.txt')->slurp;
      # or
      my $content = io('file.txt') << '';
Reading file into lines
      my @lines = io('file.txt')->lines;
Writing to a file
      io('output.txt')->print("Hello world\n");
      # or
      io('output.txt') << 'Hello world\n';
      # or
      io('output.txt') << "Hello\n" << "world\n";
Appending to a file
      io('log.txt')->append->print("New log entry\n");
      # or
      io('log.txt')->autoclose(0)->append->print("Keep me open\n");
Getting file size
      my $size = io('file.txt')->size;
Getting parent directory
      my $parent_dir = io('path/to/file.txt')->parent;
      # $parent_dir is an IO::All object representing 'path/to'

THE IO::ALL METHODS

parent
Returns an IO::All object representing the current parent directory.

OPERATIONAL NOTES

Reblessing
Each IO::All object gets reblessed into an IO::All::* object as soon as IO::All can determine what type of object it should be. Sometimes it gets reblessed more than once: 
my $io = io('mydbm.db');
$io->dbm('DB_File');
$io->{foo} = 'bar';

In the first statement, $io has a reference value of 'IO::All::File', if "mydbm.db" exists. In the second statement, the object is reblessed into class 'IO::All::DBM'.

Auto-Open
An IO::All object will automatically be opened as soon as there is enough contextual information to know what type of object it is, and what mode it should be opened for. This is usually when the first read or write operation is invoked but might be sooner.
Auto-Mode
The mode for an object to be opened with is determined heuristically unless specified explicitly.
Auto-Close
For input, IO::All objects will automatically be closed after EOF (or EOD). For output, the object closes when it goes out of scope.

To keep input objects from closing at EOF, do this:

$io->autoclose(0);
Explicit open and close
You can always call "open" and "close" explicitly, if you need that level of control. To test if an object is currently open, use the "is_open" method.
Overload
Overloaded operations return the target object, if one exists.

This would set $xxx to the IO::All object:

my $xxx = $contents > io('file.txt');

While this would set $xxx to the content string:

my $xxx = $contents < io('file.txt');

STABILITY

The goal of the IO::All project is to continually refine the module to be as simple and consistent to use as possible. Therefore, in the early stages of the project, I will not hesitate to break backwards compatibility with other versions of IO::All if I can find an easier and clearer way to do a particular thing.

IO is tricky stuff. There is definitely more work to be done. On the other hand, this module relies heavily on very stable existing IO modules; so it may work fairly well.

I am sure you will find many unexpected "features". Please send all problems, ideas and suggestions to ingy@cpan.org.

Known Bugs and Deficiencies

Not all possible combinations of objects and methods have been tested. There are many many combinations. All of the examples have been tested. If you find a bug with a particular combination of calls, let me know.

If you call a method that does not make sense for a particular object, the result probably won't make sense. Little attempt is made to check for improper usage.
