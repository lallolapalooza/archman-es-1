DESCRIPCIÓ

N 
IPC::Shareable permite vincular una variable a la
memoria compartida, facilitando el contenido de e
sa variable con otros procesos y scripts de Perl.

Se pueden vincular escalares, arreglos, hashes e incluso objetos. La variable que se vincula puede contener estructuras de datos arbitrariamente complejas, incluyendo referencias a arreglos, hashes

de hashes, etc.

La asociación entre variables en procesos distintos es proporcionada por GLUE (también conocido como "clave"). Esta es cualquier cadena o entero arbitrario que sirve como identificador común para los datos a través del espacio de procesos. Por lo tanto, la

declaración:

tie my $scalar, 'IPC::Shareable', { key => 'CADENA GLUE', create => 1 }

;

...en el programa uno y la

declaración 
tie my $variable, 'IPC::Shareable', { key => 'CADENA GLUE' }
;

...en el programa dos crearán y

vincularán 
$scalar a la memoria compartida en el programa uno y la vincularán
a

$variable en el programa dos. No hay un límite preestablecido al número de procesos que pueden vincularse a los datos; ni hay un límite preestablecido a la complejidad de los datos subyacentes de las variables vinculadas. La cantidad de datos que se pueden compartir dentro de una sola variable vinculada está limitada por el tamaño máximo del sistema para un segmento de memoria compartida (el valor exacto depende del sistema). Las estructuras de datos vinculadas se serializan (usando el módulo Storable de Raphael Manfredi o, opcionalmente, JSON) antes de ser cargadas en la memoria compartida. Al recuperarlas, se restaura el formato original de la estructura de datos. Se pueden usar indicadores de semáforo para bloquear datos entre procesos en

competencia.

BLOQUE

O

IPC::Shareable proporciona métodos para implementar bloqueo consultivo a nivel de aplicación de las estructuras de datos compartidas. Estos métodos se llaman lock() y unlock(). Para usarlos primero debes obtener el objeto subyacente a la variable atada, ya sea guardando el valor de retorno de la llamada original a tie() o usando la función incorporada tied(

).

Para bloquear y posteriormente desbloquear una variable, haz

esto: 
my $knot = tie my %hash, 'IPC::Shareable', { %options };
$knot->lock;
$hash{a} = 'foo';
$knot->
unlock;

o equivalentemente, si has decidido descartar el retorno de tie(

): 
tie my %hash, 'IPC::Shareable', { %options };
tied(%hash)->lock;
$hash{a} = 'foo';
tied(%hash)->
unlock;

Esto colocará un bloqueo exclusivo sobre los datos de $scalar. También puedes obtener bloqueos compartidos o intentar obtener un bloqueo sin

bloquear.

IPC::Shareable hace que las constantes "LOCK_EX", "LOCK_SH", "LOCK_UN", y "LOCK_NB" sean exportables a tu espacio de direcciones con las etiquetas de exportación ":lock", ":flock", o ":all". Los valores deberían ser los mismos que los argumentos de opción estándar de "flock"

. 
if (tied(%hash)->lock(LOCK_SH|LOCK_NB)){
    print "The value is $hash{a}\n";
    tied(%hash)->unlock;
} else {
    print "Another process has an exclusive lock.\n";
}

Si no se proporciona ningún argumento a "lock", por defecto es "LOCK_EX"

.

Hay algunas trampas con respecto al bloqueo y las señales de las que deberías ser consciente; estas se discuten en

"NOTES".

Ten en cuenta que en segundo plano, realizamos optimización de bloqueo al leer y escribir en el almacenamiento compartido incluso si los bloqueos consultivos no se están

usando.

Usar los bloqueos consultivos puede acel

erar procesos que están haciendo var

DESTRUCCIÓ

N

perl(1) destruirá el objeto subyacente a una variable atada cuando la variable atada salga del ámbito. Desafortunadamente para IPC::Shareable, esto puede no ser deseable: otros procesos pueden aún necesitar un manejo del segmento de memoria compartida

relevante.

IPC::Shareable por lo tanto proporciona varias opciones para controlar el momento de la eliminación de los segmentos de memoria

compartida.

Opción

destroy

Como se describe en "OPTIONS", especificar la opción destroy al hacer tie() a una variable obliga a IPC::Shareable a eliminar el segmento de memoria compartida subyacente cuando el proceso que llama a tie() salga del programa de forma

ordenada.

NOTA: La destrucción se maneja en un bloque "END". Solo aquellos segmentos de memoria que estén atados al proceso actual serán

eliminados.

NOTA: Si el segmento fue creado con su atributo "protected" establecido, no será eliminado en el bloque "END", incluso si pan class="Li">"destr

Notas

Generales
o
Al usar lock() para bloquear una variable, ten cuidado de protegerte contra las señales. Bajo circunstancias normales, el método "END" de "IPC::Shareable" desbloquea cualquier variable bloqueada cuando el proceso sale. Sin embargo, si se recibe una señal no atrapada mientras un proceso mantiene un bloqueo exclusivo, "END" no se llamará y el bloqueo puede mantenerse aunque el proceso haya salido. Si esto te asusta, podría ser mejor que implementes tus propios métodos de bloqueo.

Una ventaja de usar "flock" en algún archivo conocido en lugar del bloqueo implementado con semáforos en "IPC::Shareable" es que cuando un proceso muere, libera automáticamente cualquier bloqueo. Esto solo sucede con "IPC::Shareable" si el proceso muere de forma

elegante.

La alternativa es intentar dar cuenta de cada posible final catastrófico para tu proceso (el manejo robusto de señales en Perl es una fuente de mucho debate, aunque g

eneralmente funciona bien) o familiarizarse con las herramientas de tu sistema para eliminar memoria compartida y semáforos. Esta preocupación debería equilibrarse co
ntra las mejoras significativas de rendimiento que puedes obtener para estructuras de datos más grandes usando el mecanismo de bloqueo implementado en IPC::Shareable.
