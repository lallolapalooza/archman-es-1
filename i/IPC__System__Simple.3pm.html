NOMBRE

IPC::System::Simple - Ejecuta comandos de forma sencilla, con diagnósticos detallados

SINOPSIS

use IPC::System::Simple qw(system systemx capture capturex);
system("some_command");        # ¡El comando tiene éxito o muere!
system("some_command",@args);  # Tiene éxito o muere, evita el shell si @args
systemx("some_command",@args); # Tiene éxito o muere, NUNCA usa el shell
# Captura la salida de un comando (igual que comillas invertidas). Muere en caso de error.
my $output = capture("some_command");
# Igual que comillas invertidas en contexto de lista.  Muere en caso de error.
my @output = capture("some_command");
# Como arriba, pero evita el shell si @args no está vacío
my $output = capture("some_command", @args);
# Como arriba, pero NUNCA invoca el shell.
my $output = capturex("some_command", @args);
my @output = capturex("some_command", @args);

DESCRIPCIÓN

Llamar a la función incorporada de Perl system() es fácil, determinar si tuvo éxito es difícil. Seamos sinceros, $? no es la variable más agradable del mundo con la que jugar, e incluso si lo compruebas, producir una cadena de error bien formateada requiere mucho trabajo.

"IPC::System::Simple" elimina el trabajo difícil de llamar a comandos externos. De hecho, si quieres ser realmente perezoso, puedes simplemente escribir:

use IPC::System::Simple qw(system);

y todos tus comandos "system" tendrán éxito (se ejecutarán hasta completarse y devolverán un valor de salida cero) o morirán con mensajes de diagnóstico detallados.

El módulo "IPC::System::Simple" también proporciona un reemplazo sencillo para el operador de comillas invertidas de Perl. Simplemente escribe:

use IPC::System::Simple qw(capture);

y luego usa el comando "capture()" tal como usarías las comillas invertidas. Si hay un error, morirá con una descripción detallada de lo que salió mal. Mejor aún, puedes incluso usar capturex() para ejecutar el equivalente a las comillas invertidas, pero sin el shell:

use IPC::System::Simple qw(capturex);
my $result = capturex($command, @args);

Si quieres más potencia que la interfaz básica, incluyendo la capacidad de especificar qué valores de salida son aceptables, atrapar errores o procesar diagnósticos, ¡entonces sigue leyendo!

SINOPSIS AVANZADA

use IPC::System::Simple qw(
  capture capturex system systemx run runx $EXITVAL EXIT_ANY
);
# Ejecuta un comando, lanzando una excepción en caso de fallo
run("some_command");
runx("some_command",@args);  # Ejecuta un comando, evitando el shell
# Hace lo mismo, pero con el reemplazo drop-in de system.
system("some_command");
systemx("some_command", @args);
# Ejecuta un comando que debe devolver 0..5, evita el shell y obtiene el
# valor de salida (también podríamos mirar $EXITVAL)
my $exit_value = runx([0..5], "some_command", @args);
# Lo mismo, pero cualquier valor de salida sirve.
my $exit_value = runx(EXIT_ANY, "some_command", @args);
# Captura la salida en $result y lanza una excepción en caso de fallo
my $result = capture("some_command"); 
# Comprueba el valor de salida del comando capturado
print "some_command exited with status $EXITVAL\n";
# Captura en @lines, dividiendo en $/
my @lines = capture("some_command"); 
# Ejecuta un comando que debe devolver 0..5, captura la salida en
# @lines y evita el shell.
my @lines  = capturex([0..5], "some_command", @args);

USO AVANZADO

run() y system()

"IPC::System::Simple" proporciona una subrutina llamada "run", que ejecuta un comando usando la misma semántica que el incorporado "system"de Perl:

use IPC::System::Simple qw(run);
run("cat *.txt");           # Ejecuta el comando a través del shell
run("cat","/etc/motd");     # Ejecuta el comando sin shell

La diferencia principal entre el system incorporado de Perl y el comando "run" es que "run" lanzará una excepción en caso de fallo y permite establecer una lista de valores de salida aceptables. Consulta "Valores de salida" para más información.

De hecho, puedes incluso hacer que "IPC::System::Simple" reemplace la función "system" por defecto de tu paquete para que tenga el mismo comportamiento:

use IPC::System::Simple qw(system);
system("cat *.txt");  # ¡system ahora tiene éxito o muere!

"system" y "run" son alias el uno del otro.

Consulta también "runx(), systemx() y capturex()" para las variantes de system() y run() que nunca invocan el shell, incluso con un solo argumento.

capture()

Una segunda subrutina, llamada "capture" ejecuta un comando con la misma semántica que las comillas invertidas incorporadas de Perl (y qx()):

use IPC::System::Simple qw(capture);
# Captura texto invocando el shell.
my $file  = capture("cat /etc/motd");
my @lines = capture("cat /etc/passwd");

Sin embargo, a diferencia de las comillas invertidas regulares, que siempre usan el shell, "capture" evitará el shell cuando se llame con múltiples argumentos:

# Captura texto evitando el shell.
my $file  = capture("cat", "/etc/motd");
my @lines = capture("cat", "/etc/passwd");

Consulta también "runx(), systemx() y capturex()" para una variante de capture() que nunca invoca el shell, incluso con un solo argumento.

runx(), systemx() y capturex()

Los comandos runx(), systemx() y capturex() son idénticos a las formas de múltiples argumentos de run(), system() y capture() respectivamente, pero nunca invocan el shell, incluso cuando se llaman con un solo argumento. Estas formas son particularmente útiles cuando la lista de argumentos de un comando podría estar vacía, por ejemplo:

systemx($cmd, @args);

El uso de systemx() aquí garantiza que el shell nunca será invocado, incluso si @args está vacío.

Manejo de excepciones

En el caso de que el comando devuelva un estado inesperado, tanto "run" como "capture" lanzarán una excepción, que si no se captura terminará tu programa con un error.

Capturar la excepción es fácil:

eval {
    run("cat *.txt");
};
if ($@) {
    print "Something went wrong - $@\n";
}

Consulta la sección de diagnósticos más abajo para más detalles.

Casos de excepción

"IPC::System::Simple" considera lo siguiente como inesperado y digno de excepción:

  • No iniciar completamente (por ejemplo, comando no encontrado, permiso denegado).
  • Devolver un valor de salida distinto de cero (pero consulta más abajo).
  • Ser terminado por una señal.
  • Recibir datos contaminados (en modo taint).

Valores de salida

Tradicionalmente, los comandos del sistema devuelven un estado cero para éxito y un estado distinto de cero para fallo. "IPC::System::Simple" lanzará por defecto una excepción si se devuelve un valor de salida distinto de cero.

Puedes especificar un rango de valores considerados como valores de salida aceptables pasando una referencia a array como primer argumento. La constante especial "EXIT_ANY" puede usarse para permitir cualquier valor de salida.

use IPC::System::Simple qw(run system capture EXIT_ANY);
run( [0..5], "cat *.txt");             # Los valores de salida 0-5 están bien
system( [0..5], "cat *.txt");          # Esto funciona de la misma manera
my @lines = capture( EXIT_ANY, "cat *.txt"); # Cualquier salida está bien.

BUGS

The exotic form "system { $cmd } @args" is not supported if "system" is exported, the exotic form "system { $cmd } @args" is not supported. Attemping to use the exotic form is a syntax error. This affects the calling package only. Use "CORE::system" if you need it, or consider using the autodie module to replace "system" with lexical scope.

Core dumps are only checked for when a process dies due to a signal. It is not believed there are any systems where processes can dump core without dying to a signal.

"WIFSTOPPED" status is not checked, as perl never spawns processes with the "WUNTRACED" option.

Signals are not supported under Win32 systems, since they don't work at all like Unix signals. Win32 signals cause commands to exit with a given exit value, which this modules does capture.

Puedes encontrar el rastreador de errores de "IPC::System::Simple" en http://rt.cpan.org/Public/Dist/Display.html?Name=IPC-System-Simple . Por favor, comprueba si tu error ya ha sido reportado; si tienes dudas, repórtalo de todas formas.
