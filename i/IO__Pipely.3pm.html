DESCRIPCIÓ

N

Las tuberías (pipes) son criaturas problemáticas porque hay algunas formas diferentes e incompatibles de crearlas. No todas las plataformas soportan todas las formas, y algunas plataformas pueden tener dificultades ocultas como soporte incompleto o con

errores.

IO::Pipely proporciona un par de funciones para crear de forma portable tuberías de una y dos vías y pares de sockets tipo tubería. Reconoce y soluciona los problemas de plataforma conocidos para que usted no tenga que

hacerlo.

Por otro lado, no soluciona problemas desconocidos, así que por favor informe de cualquier problema pronto y con

frecuencia.

IO::Pipely actualmente entiende pipe(), sockets de dominio UNIX socketpair() y sockets regulares de IPv4 en localhost. Esto cubre todas las plataformas probadas hasta ahora, pero está lejos de ser completo. Por favor, ayude a soportar otros mecanismos, como socketpair() de dominio INET y sockets de IPv6 en

localhost.

IO::Pipely usará diferentes tipos de tuberías o sockets dependiendo de las capacidades del sistema operativo y el número de direcciones solicitadas. La autodetección puede ser anulada especificando un tipo de tubería

particular.

pipel

y

pipely() crea un socket o tubería pipe() unidireccional. Está modelada después de la función incorporada de Perl pipe(), pero crea y devuelve manejadores en lugar de abrir los que se le

dan.

En caso de éxito, pipely() devuelve dos manejadores de archivo, el primero para leer de la tubería, y el segundo escribe en la tubería. Devuelve nada en caso de

fallo. 
use IO::Pipely qw(pipely);
my ($a_read, $b_write) = pipely();
die "pipely() falló: $!" unless
$a_read;

Cuando tiene la opción, preferirá usar llamadas pipe() más ligeras en lugar de socketpair() y socket

().

La elección de pipely() puede ser forzada usando un parámetro con nombre opcional "type". Vea "TIPOS DE TUBERÍA" para los tipos que se pueden

usar. 
my ($a_read, $b_write) = pipely(
  type => 'pipe',
)
;

En la mayoría de los sistemas, pipely() preferirá abrir un pipe() primero. Recurrirá a un socketpair() UNIX o dos sockets de Internet en localhost, en ese

orden.

En Windows (ActiveState y Strawberry Perl), pipely() prefiere dos sockets de Internet en localhost. Recurrirá a socketpair() y pipe(), ambos de los cuales probablemente

fallarán.

Perl en Cygwin prefiere pipe() primero, sockets de Internet en localhost, y luego socketpair(). Se sabe que socketpair() tiene problemas en

Cygwin.

MacPerl (MacOS 9 y anterior

es) tiene capacidades simi
lares a las de Windows.

socketpairl

y

socketpairly() crea un par de sockets bidireccional. Está modelada después de la función incorporada de Perl socketpair(), pero crea y devuelve manejadores en lugar de abrir los que se le

dan.

En caso de éxito, socketpairly() devuelve cuatro manejadores de archivo, lectura y escritura para un extremo, y lectura y escritura para el otro. En caso de fallo, devuelve

nada. 
use IO::Pipely qw(socketpairly);
my ($a_read, $a_write, $b_read, $b_write) = socketpairly();
die "socketpairly() falló: $!" unless
$a_read;

socketpairly() devuelve dos manejadores extra de "escritor". Existen para el caso de recurso donde se necesitan dos llamadas a pipe() en lugar de un par de sockets. Los manejadores extra pueden ser ignorados siempre que pipe() nunca se use. Por

ejemplo: 
use IO::Pipely qw(socketpairly);
my ($side_a, undef, $side_b, undef) = socketpairly( type => 'socketpair' );
die "socketpairly() falló: $!" unless
$side_a;

Cuando tiene la opción, preferirá sockets bidireccionales en lugar de llamadas a pipe()

.

La elección de socketpairly() puede ser forzada usando un parámetro con nombre opcional "type". Vea "TIPOS DE TUBERÍA" para los tipos que se pueden usar. En este ejemplo, se usarán dos tuberías unidireccionales en lugar de un par de sockets más

eficiente: 
my ($a_read, $a_write, $b_read, $b_write) = socketpairly(
  type => 'pipe',
)
;

En la mayoría de los sistemas, socketpairly() intentará abrir un socketpair() UNIX primero. Luego recurrirá a un par de sockets de Internet en localhost, y finalmente intentará un par de llamadas a pipe()

.

En Windows (ActiveState y Strawberry Perl), socketpairly() prefiere un par de sockets de Internet en localhost primero. Luego recurrirá a un socketpair() UNIX, y finalmente un par de llamadas a pipe(). Las opciones de recurso probablemente fallarán, pero el código permanece

esperanzado.

Perl en Cygwin prefiere los sockets de Internet en localhost primero, seguidos de un par de llamadas a pipe(), y finalmente un socketpair() UNIX. Quienes sepan pueden encontrar esto contraintuitivo, pero soluciona problemas conocidos en algunas versiones de socketpair() de

Cygwin.

MacPerl (MacOS 9 y anterior

es) tiene capacidades simi
lares a las de Windows.

TIPOS DE

TUBERÍA

IO::Pipely actualmente soporta tres tipos de tubería y socket. Otros tipos son posibles, pero estos tres cubren todos los usos conocidos hasta ahora. Por favor, pregunte (o env parches) si se necesitan tipos

adicionales.

pip

e

Intenta establecer una tubería unidireccional usando un par de manejadores de archivo pipe() (2 descriptores de archivo), o una conexión tipo tubería bidireccional usando dos pares de pipe() (4 descriptores de archivo)

.

IO::Pipely prefiere usar pipe() para tuberías unidireccionales y alguna forma de par de sockets para cosas tipo tubería bidireccionales

.

socketpai

r

Intenta establecer una conexión tipo tubería unidireccional o bidireccional usando una sola llamada a socketpair(). Esto usa dos descriptores de archivo independientemente de si la conexión es unidireccional o

bidireccional.

IO::Pipely prefiere socketpair() para conexiones bidireccionales, a menos que la plataforma actual tenga problemas conocidos con la llamada a socketpair()

.

Los pares de sockets son solo de dominio UNIX por ahora. El dominio INET puede ser añadido si mejora la compatibilidad en alguna plataforma, o si alguien contribuye el

código.

ine

t

Intenta establecer una conexión tipo tubería unidireccional o bidireccional usando llamadas a socket() en localhost. Esto usa dos descriptores de archivo independientemente de si la conexión es unidireccional o

bidireccional.

Los sockets de dominio INET en localhost son un último recurso para plat

aformas que no soportan algo mejor. Son el método de comunicación me
nos seguro ya que herramientas como tcpdump y Wireshark pueden inte
rceptarlos. Por otro lado, esto los hace los más fáciles de depurar.

NAME


IO::Pipely - Perl's version of Perl's pipes and sockets.






VERSION


0.006






SYNOPSIS


    use IO::Pipely qw(pipe socketpairly);
    
    my ($read, $write) = pipe()
        or die "pipe() failed: $!";
    
    my ($read_sock, $write_sock) = socketpairly()
        or die "socketpairly() failed: $!";
    
    # ... use $read, $write, $read_sock, $write_sock ...
    
    close $read;
    close $write;
    close $read_sock;
    close $write_sock;






DESCRIPTION


IO::Pipely implements Perl's pipe() and socketpair()
    functions in a way that is intended to be portable across Perl platforms.


When pipe() is called, it returns a pair of connected file
    handles. Data written to the first handle can be read from the second handle,
    and vice-versa. This is typically used to implement one-way communication
    between a parent process and a child process.


When socketpairly() is called, it returns a pair of connected
    sockets. Data written to one socket can be read from the other, and vice-versa.
    This is generally used for bidirectional communication between two processes
    that are not necessarily parent and child.


IO::Pipely is a drop-in replacement for Perl's built-in pipe()
    and socketpair() functions. Simply include it in your code with
    use IO::Pipely; and it will override the built-ins.






KNOWN ISSUES




MacOS 9


IO::Pipely supports MacOS 9 for historical reasons. It's unclear
    whether anyone still uses MacPerl, but the support is cheap since pipes and
    sockets there have many of the same caveats as they do on Windows.






Symbol::gensym


IO::Pipely uses Symbol::gensym() instead of autovivifying
    file handles. The main reasons against gensym() have been stylistic
    ones so far. Meanwhile, gensym() is compatible farther back than
    handle autovivification.






Windows


ActiveState and Strawberry Perl don't support pipe() or
    UNIX socketpair(). Localhost Internet sockets are used for everything
    there, including one-way pipes.


For one-way pipes, the unused socket directions are shut down to
    avoid sending data the wrong way through them. Use socketpairly()
    instead.








BUGS


The functions implemented here die outright upon failure,
    requiring eval{} around their calls.


The following conduit types are currently unsupported because
    nobody has needed them so far. Please submit a request (and/or a patch) if
    any of these is needed:


UNIX socket()
INET-domain socketpair()
IPv4-specific localhost sockets
IPv6-specific localhost sockets
