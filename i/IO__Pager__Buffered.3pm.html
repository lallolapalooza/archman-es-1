IO::Pager::Buffered(3) Documentación de Perl contribuida por el usuario IO::Pager::Buffered(3)

NOMBRE

IO::Pager::Buffered - Canaliza la salida diferida a PAGER si el destino es una TTY

SINOPSIS

use IO::Pager::Buffered;
{
  local $token = IO::Pager::Buffered::open local *STDOUT;
  print <<"  HEREDOC" ;
  ...
  Una gran cantidad de texto después
  HEREDOC
}
{
  # También puedes usar manejadores de archivos escalares...
  my $token = IO::Pager::Buffered::open($FH) or warn($!);
  print $FH "¡Nada de globs ni barewords para nosotros, gracias!\n" while 1;
}
{
  # ... o una interfaz de objeto
  my $token = new IO::Pager::Buffered;
  $token->print("OO brillante...\n") while 1;
}

DESCRIPCIÓN

Las subclases de IO::Pager están diseñadas para decidir programáticamente si canalizar o no la salida de un manejador de archivos a un programa especificado en PAGER; determinado y establecido por IO::Pager en tiempo de ejecución si aún no está definido.

Esta subclase almacena en búfer toda la salida para su visualización hasta que la ejecución regresa al ámbito padre o se produce una limpieza manual. Si esto no es lo que desea, mire otra subclase como IO::Pager::Unbuffered. Aunque probablemente no sea común, esto puede ser útil en algunos casos, como almacenar en búfer toda la salida a STDOUT mientras ocurre el proceso para que las advertencias en STDERR sean más visibles, y luego mostrar la salida menos urgente de STDOUT después. O, alternativamente, dejar pasar la salida a STDOUT y diferir las advertencias para una revisión posterior.

MÉTODOS

Detalles específicos de los métodos de esta clase a continuación, otros se heredan de IO::Pager.

open( [MANEJADOR DE ARCHIVOS] )

Instancia un nuevo IO::Pager para paginar el MANEJADOR DE ARCHIVOS si es necesario. Asigna el valor de retorno a una variable de ámbito. La salida no se produce hasta que el manejador de archivos se limpie o se cierre.

new( [MANEJADOR DE ARCHIVOS] )

Casi idéntico a open, excepto que obtendrá un IO::Handle si no hay una TTY para permitir la programación agnóstica de IO::Pager.

close( MANEJADOR DE ARCHIVOS )

Limpia el búfer al paginador y cierra el manejador de archivos para escritura. Normalmente, cuando se utiliza una variable léxica o localmente con ámbito para mantener el token proporcionado por open, las llamadas explícitas a close no son necesarias. Sin embargo, si está utilizando IO::Pager::Buffered con un STDOUT o STDERR no localizado, cierre el manejador de archivos para mostrar el contenido almacenado en búfer o espere a la limpieza global de la basura al finalizar el programa.

Alternativamente, puede preferir usar un manejador de archivos no principal con IO::Pager y llamar a "select" en perlfunc para que sea el predeterminado para la salida.

tell( MANEJADOR DE ARCHIVOS )

Devuelve el tamaño del búfer en bytes.

flush( MANEJADOR DE ARCHIVOS )

Limpia inmediatamente el contenido del búfer.

Si la última impresión no terminó con una nueva línea, el texto desde la nueva línea anterior hasta el final del búfer se limpiará, pero es poco probable que se muestre hasta que se imprima una nueva línea y se limpie.

SALVEDADES

Si mezcla operaciones con búfer y sin búfer, el orden de la salida no está especificado y probablemente diferirá para una TTY frente a un archivo. Ver perlfunc.

Se utiliza $, ver perlvar.

Probablemente querrá hacer algo con SIGPIPE, por ejemplo:

eval {
  local $SIG{PIPE} = sub { die };
  local $STDOUT = IO::Pager::open(*STDOUT);
  while (1) {
    # Hacer algo
  }
}
# Hacer otra cosa
