Este módulo proporciona una interfaz de Perl que permite la lectura de archivos/búferes

zlib.

Para escribir archivos/búferes zip, consulte el módulo complementario IO::Compress::

DESCRIPTION

This module provides an interface to uncompress zip files. It supports zipped files that contain multiple members, and can also handle zip files that have the uncompressed data appended immediately after the compressed data stream.

Functional Interface

The "unzip" function provides a convenient way to uncompress data.

use IO::Uncompress::Unzip qw(unzip $UnzipError) ;
my $data = unzip $file_or_buffer
    or die "Unzip failed: $UnzipError\n";

The "unzip" function will:

  • Read the contents of the file specified by $file_or_buffer.
  • If $file_or_buffer is a scalar reference or a buffer, it assumes that the buffer contains the compressed data.
  • If $file_or_buffer is a filehandle, it reads compressed data from the filehandle until the end-of-file is reached.
  • It uncompresses the data.
  • It returns the uncompressed data as a scalar.
  • If an error occurs, it returns an undefined value and sets the $UnzipError variable to a string describing the error.

The "unzip" function can also take an optional hash reference of options. These options are:

"Name"
The name of the member to uncompress from the zip archive. If not specified, the first member is uncompressed.
"Seek"
If set to 1, the zip archive is scanned for the central directory. This is needed if the archive is not seekable, or if the central directory is at the end of the archive.
"TrailingData"
If set to 1, any data that immediately follows the compressed data stream will be returned. This is useful for zip files that have the uncompressed data appended after the compressed data.

OO Interface

The OO interface provides more control over the uncompression process.

use IO::Uncompress::Unzip ;
my $zip = IO::Uncompress::Unzip->new($file_or_buffer, %options)
    or die "Failed to create IO::Uncompress::Unzip object: $UnzipError\n";
my $status ;
while ( ($status = $zip->read($buffer)) > 0 ) {
    # Process $buffer
}
die "Error reading zip file: $UnzipError\n" if $status < 0;

Methods

new
Creates a new IO::Uncompress::Unzip object. $file_or_buffer can be a filename, a scalar reference to a buffer containing the zip data, or a filehandle. %options is a hash of options that can be passed to the constructor. These options are the same as those for the "unzip" function, with the addition of "InputLength".
InputLength
If you know the length of the compressed data stream before you start uncompressing, you can set the "InputLength" option in the constructor. This avoids the need to scan the zip file for the central directory. This option is only valid when the input is a buffer or a filehandle.
read
Reads up to UNCOMPRESSED_BUFFER_SIZE bytes of uncompressed data from the zip stream. Returns the number of bytes read, or 0 if the end of the stream has been reached, or -1 if an error occurred.
getHeaderInfo
Returns a hash reference containing information about the current member being processed. The hash contains the following keys:
Name
The name of the member.
Type
The type of the member (e.g., 'file', 'directory').
Size
The uncompressed size of the member.
CRC
The CRC32 checksum of the uncompressed data.
ModTime
The modification time of the member.
nextStream
Skips to the next compressed data stream in the zip file. This is useful for processing zip archives that contain multiple compressed members. It returns 1 if successful, 0 if there are no more streams, and -1 if an error occurred.
close
Closes the zip file and cleans up resources.
trailingData
Returns any data that immediately follows the compressed data stream. This is useful for zip files that have the uncompressed data appended directly after the compressed data stream, and you do not know the length of the compressed data stream.

If the input is a buffer, "trailingData" will return everything from the end of the compressed data stream to the end of the buffer.

If the input is a filehandle, "trailingData" will return the data that is left in the filehandle input buffer once the end of the compressed data stream has been reached. You can then use the filehandle to read the rest of the input file.

Don't bother using "trailingData" if the input is a filename.

If you know the length of the compressed data stream before you start uncompressing, you can avoid having to use "trailingData" by setting the "InputLength" option in the constructor.

No symbolic constants are required by IO::Uncompress::Unzip at present.

use IO::Uncompress::Unzip qw(unzip $UnzipError) ;

EXAMPLES

Simple Read

Say you have a zip file, "file1.zip", that only contains a single member, you can read it and write the uncompressed data to the file "file1.txt" like this.

use strict ;
use warnings ;
use IO::Uncompress::Unzip qw(unzip $UnzipError) ;
my $filename = "file1.zip";
my $z = IO::Uncompress::Unzip->new($filename)
    or die "IO::Uncompress::Unzip failed: $UnzipError\n";
open my $out, ">", "file1.txt";
while (<$z>) {
    print $out $_;
}
$z->close();

If you have a zip file that contains multiple members and want to read a specific member from the file, say "data1", use the "Name" option when constructing the

use strict ;
use warnings ;
use IO::Uncompress::Unzip qw(unzip $UnzipError) ;
my $filename = "file1.zip";
my $z = IO::Uncompress::Unzip->new($filename, Name => "data1")
    or die "IO::Uncompress::Unzip failed: $UnzipError\n";

Walking through a zip file

The code below can be used to traverse a zip file, one compressed data stream at a time.

use IO::Uncompress::Unzip qw($UnzipError);
my $zipfile = "somefile.zip";
my $u = IO::Uncompress::Unzip->new( $zipfile )
    or die "Cannot open $zipfile: $UnzipError";
my $status;
for ($status = 1; $status > 0; $status = $u->nextStream())
{
    my $name = $u->getHeaderInfo()->{Name};
    warn "Processing member $name\n" ;
    my $buff;
    while (($status = $u->read($buff)) > 0) {
        # Do something here
    }
    last if $status < 0;
}
die "Error processing $zipfile: $!\n"
    if $status < 0 ;

Each individual compressed data stream is read until the logical end-of-file is reached. Then "nextStream" is called. This will skip to the start of the next compressed data stream and clear the end-of-file flag.

It is also worth noting that "nextStream" can be called at any time -- you don't have to wait until you have exhausted a compressed data stream before skipping to the next one.
