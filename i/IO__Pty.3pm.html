NOMBRE

IO::Pty - Clase de objetos Pseudo TTY

VERSIÓN

1.20

SINOPSIS

use IO::Pty;
$pty = new IO::Pty;
$slave  = $pty->slave;
foreach $val (1..10) {
    print $pty "$val\n";
    $_ = <$slave>;
    print "$_";
}
close($slave);

DESCRIPCIÓN

"IO::Pty" proporciona una interfaz para permitir la creación de un tty pseudo.

"IO::Pty" hereda de "IO::Handle" y por lo tanto proporciona todos los métodos definidos por el paquete "IO::Handle" .

Tenga en cuenta que la creación de pty depende mucho del sistema. Si tiene problemas, consulte IO::Tty para obtener ayuda.

CONSTRUCTOR

new
El "new" constructor no toma argumentos y devuelve un nuevo objeto de archivo que es el lado maestro del pseudo tty.

MÉTODOS

ttyname()
Devuelve el nombre del pseudo tty esclavo. En máquinas UNIX este será la ruta del nombre del dispositivo. Utilice este nombre solo con fines informativos, para obtener un manejador de archivo esclavo, use slave().
slave()
El "slave" método devolverá el manejador de archivo esclavo del pty maestro dado, abriéndolo de nuevo si es necesario. Si IO::Stty está instalado, entonces puede llamar a "$slave->stty()" para modificar la configuración del terminal.
close_slave()
El manejador de archivo esclavo será cerrado y destruido. Esto es necesario en el padre después de hacer fork para deshacerse del manejador de archivo abierto, de lo contrario el padre no notará si el hijo sale. Las llamadas posteriores a slave() devolverán un manejador de archivo esclavo recién abierto.
make_slave_controlling_terminal()
Esto establecerá el manejador de archivo esclavo como la terminal de control del proceso actual, que se convertirá en líder de sesión, por lo que esto solo debe ser llamado por un proceso hijo después de un fork(), por ejemplo, en la función de retorno a sync_exec() (ver Proc::SyncExec). Vea el "try" script (también "test.pl") para un ejemplo de cómo generar correctamente un subproceso.
set_raw()
Establecerá el pty en modo crudo. Tenga en cuenta que esta es una operación de un solo sentido, necesita IO::Stty para establecer la configuración del terminal en cualquier otra cosa.

En algunos sistemas, el pty maestro no es un tty. Este método verifica eso y devuelve éxito de todos modos en tales sistemas. Tenga en cuenta que este método debe ser llamado en el esclavo, y probablemente debería ser llamado en el maestro, solo para estar seguro, es decir,

$pty->slave->set_raw();
$pty->set_raw();
clone_winsize_from(\*FH)
Obtiene el tamaño del terminal del manejador de archivo FH (que debe ser un terminal) y lo transfiere al pty. Devuelve true en caso de éxito y undef en caso de fallo. Tenga en cuenta que esto debe ser llamado sobre el slave, es decir, 
$pty->slave->clone_winsize_from(\*STDIN);

En algunos sistemas, el pty maestro también es isatty. Realmente no tengo idea de si la configuración de los tamaños de terminal allí se transmite al esclavo, por lo que si este método es llamado para un maestro que no es un tty, devuelve OK silenciosamente.

Vea el "try" script para código de ejemplo de cómo propagar SIGWINCH.

get_winsize()
Devuelve el tamaño del terminal, en una lista de 4 elementos. 
($row, $col, $xpixel, $ypixel) = $tty->get_winsize()
set_winsize($row, $col, $xpixel, $ypixel)
Establece el tamaño del terminal. Si no se especifica, $xpixel y $ypixel se establecen en 0. Como con "clone_winsize_from", esto debe ser llamado sobre el slave.
