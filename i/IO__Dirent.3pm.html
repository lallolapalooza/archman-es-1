NOMBRE

IO::Dirent - Acceso a estructuras dirent devueltas por readdir

SINOPSIS

use IO::Dirent;
## estilo de lectura completa
opendir DIR, "/usr/local/foo";
my @entries = readdirent(DIR);
closedir DIR;
print $entries[0]->{name}, "\n";
print $entries[0]->{type}, "\n";
print $entries[0]->{inode}, "\n";
## usando el enumerador
opendir DIR, "/etc";
while( my $entry = nextdirent(DIR) ) {
  print $entry->{name} . "\n";
}
closedir DIR;

DESCRIPCIÓN

readdirent devuelve una lista de hashrefs. Cada hashref contiene el nombre de la entrada del directorio, su inodo para el sistema de archivos en el que reside y su tipo (si está disponible). Si el tipo de archivo o el inodo no están disponibles, ¡no estarán allí!

nextdirent devuelve el siguiente dirent como un hashref, permitiéndote iterar sobre las entradas del directorio una por una. Esto puede ser útil en situaciones de baja memoria o cuando tienes directorios enormes.

IO::Dirent exporta los siguientes símbolos por defecto:

readdirent
nextdirent

Las siguientes etiquetas pueden ser exportadas a tu espacio de nombres:

ALL

que incluye readdirent, nextdirent y los siguientes símbolos:

DT_UNKNOWN
DT_FIFO
DT_CHR
DT_DIR
DT_BLK
DT_REG
DT_LNK
DT_SOCK
DT_WHT

Estos símbolos pueden usarse para probar el tipo de archivo devuelto por readdirent de la siguiente manera:

for my $entry ( readdirent(DIR) ) {
    next unless $entry->{'type'} == DT_LNK;
    print $entry->{'name'} . " es un enlace simbólico.\n";
}

Para plataformas que no implementan el tipo de archivo en su estructura dirent, readdirent devolverá un hashref con una única clave/valor de 'name' y el nombre del archivo (efectivamente lo mismo que readdir). Esto está sujeto a cambios, si puedo implementar algunos de los elementos de la lista de tareas pendientes a continuación.

ADVERTENCIAS

Esto se escribió en FreeBSD y OS X, que implementan una estructura dirent robusta (pero algo no estándar) y que incluye una entrada de tipo de archivo. Tengo planes para hacer que este módulo sea más portable y útil realizando una `stat` en cada entrada del directorio para encontrar el tipo de archivo y el número de inodo cuando `dirent.h` no lo implemente de otra manera.

Se aceptan mejoras y puertos adicionales.

TAREAS PENDIENTES

  • Para plataformas que no implementan una estructura dirent con tipo de archivo, realiza una `stat` en la entrada y popula la estructura de todos modos.
  • Realizar alguna profilación de memoria (no estoy seguro de si tengo alguna fuga o no).
