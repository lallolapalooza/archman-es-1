NOMBRE

Image::ExifTool - Leer y escribir información meta

SINOPSIS

use Image::ExifTool qw(:Public);
# ---- Uso procedimental simple ----
# Obtener un hash de nombres/valores de etiquetas de información meta de una imagen
$info = ImageInfo('a.jpg');
# ---- Uso orientado a objetos ----
# Crear un nuevo objeto Image::ExifTool
$exifTool = Image::ExifTool->new;
# Extraer información meta de una imagen
$exifTool->ExtractInfo($archivo, \%opciones);
# Obtener la lista de etiquetas en el orden en que fueron encontradas en el archivo
@listaEtiquetas = $exifTool->GetFoundTags('Archivo');
# Obtener el valor de una etiqueta especificada
$valor = $exifTool->GetValue($etiqueta, $tipo);
# Obtener una descripción de la etiqueta
$descripcion = $exifTool->GetDescription($etiqueta);
# Obtener el nombre del grupo asociado con esta etiqueta
$grupo = $exifTool->GetGroup($etiqueta, $familia);
# Establecer un nuevo valor para una etiqueta
$exifTool->SetNewValue($etiqueta, $nuevoValor);
# Escribir nueva información meta en un archivo
$exito = $exifTool->WriteInfo($archivoFuente, $archivoDestino);
# ...además de una gran cantidad de otros métodos útiles...

CONFIGURACIÓN

Se pueden añadir etiquetas definidas por el usuario a través del archivo de configuración de ExifTool, o definiendo el hash %Image::ExifTool::UserDefined antes de llamar a cualquier método de ExifTool. Consulte "ExifTool_config" en la distribución de ExifTool para obtener más detalles.

Por defecto, ExifTool busca un archivo de configuración llamado ".ExifTool_config" primero en su directorio personal, luego en el directorio del script de la aplicación, pero se puede especificar un directorio diferente estableciendo la variable de entorno EXIFTOOL_HOME, o se puede especificar un archivo diferente estableciendo la variable "configFile" de ExifTool antes de usar Image::ExifTool. Por ejemplo:

BEGIN { $Image::ExifTool::configFile = '/Users/phil/myconfig.cfg' }
use Image::ExifTool;

La característica de configuración también se puede deshabilitar estableciendo "configFile" a una cadena vacía:

BEGIN { $Image::ExifTool::configFile = '' }
use Image::ExifTool;

EXPORTACIONES

No exporta nada por defecto, pero "ImageInfo" y todos los métodos estáticos pueden ser exportados con la lista de exportación ":Public".

MÉTODOS

Se accede a todas las funciones de ExifTool a través de los métodos de la interfaz pública que se enumera a continuación. Otros métodos y módulos de Image::ExifTool no deben ser accedidos directamente ya que su interfaz puede cambiar en versiones futuras.

Ninguno de estos métodos debería fallar o emitir advertencias a STDERR si se llama con los argumentos correctos (con la excepción de "SetNewValue" que puede enviar un mensaje de error a STDERR, pero solo cuando se llama en contexto escalar). Los mensajes de error y advertencia que ocurren durante el procesamiento se almacenan en los valores de las etiquetas Error y Warning, y son accesibles a través del método "GetValue" para recuperar un único mensaje de Error o Warning, o "GetInfo" para recuperar cualquiera de ellos.

Los métodos de ExifTool no son seguros para hilos (thread-safe).

ImageInfo

Lee el archivo de imagen y devuelve la información meta. Esta es la función de un solo paso para recuperar información meta de una imagen. $info = $exifTool->ImageInfo(\*ARCHIVO);
# devuelve información de datos de imagen en memoria para etiquetas especificadas

El primer argumento escalar se toma como el nombre del archivo a menos que un argumento anterior haya especificado los datos de la imagen mediante una referencia de archivo (file ref) o una referencia de datos (SCALAR ref). Los demás argumentos escalares son nombres de etiquetas para la información solicitada. Se devuelven todas las etiquetas si no se especifican etiquetas.

Los nombres de las etiquetas no distinguen entre mayúsculas y minúsculas y pueden tener un prefijo de nombres de grupo opcionales separados por dos puntos. Un nombre de grupo puede comenzar con un número de familia (p. ej. '1IPTC:Keywords'), para restringir las coincidencias a una familia específica. En el nombre de la etiqueta, un '?' coincide con cualquier carácter único y un '*' coincide con cero o más caracteres. Así, 'GROUP:*' representa todas las etiquetas de un grupo específico. Los comodines no pueden usarse en los nombres de grupo, con la excepción de que un nombre de grupo de '*' puede usarse para extraer todas las instancias disponibles de una etiqueta independientemente de la configuración "Duplicates" (p. ej. '*:WhiteBalance'). Se pueden especificar múltiples grupos (p. ej. 'EXIF:Time:*' extrae todas las etiquetas de tiempo EXIF). Y finalmente, un guion inicial '-' indica una etiqueta a excluir (p. ej. '-IFD1:*'), o un '#' final hace que se devuelva el valor ValueConv para esta

WriteInfo

Escribe meta información en un archivo. El archivo de origen especificado se reescribe en un archivo de destino del mismo tipo con la nueva información especificada por llamadas anteriores a "SetNewValue". Los segmentos y/o directorios necesarios se crean en el archivo de destino según sea necesario para almacenar la información especificada. Puede llamarse repetidamente para escribir la misma información en archivos adicionales sin necesidad de llamar a "SetNewValue" de nuevo.

ExifTool encola todos los nuevos valores que se asignan a través de llamadas a "SetNewValue", luego los aplica a cualquier número de archivos a través de una o más llamadas a "WriteInfo". Estos valores encolados pueden accederse a través de "GetNewValue", y son completamente separados de los metadatos extraídos de los archivos a través de "ExtractInfo" o "ImageInfo" y accedidos a través de "GetInfo" o "GetValue".

Para ser claro, NO es necesario llamar a "ExtractInfo" o "ImageInfo" antes de "WriteInfo". "WriteInfo" cambia solo los metadatos especificados por llamadas anteriores a "SetNewValue".

# añadir información a un archivo de origen, escribiendo la salida en un archivo nuevo
$exifTool->WriteInfo($srcfile, $dstfile);
# crear un archivo de datos XMP desde cero
$exifTool->WriteInfo(undef, $dstfile, 'XMP');
# sobrescribir archivo (tienes copias de seguridad, ¿verdad?)
$exifTool->WriteInfo($srcfile);
Entradas:
0) Referencia al objeto ExifTool

1) Nombre del archivo de origen, referencia de archivo, referencia de escalar, o undef para crear un archivo desde cero. También se permite una referencia a un objeto File::RandomAccess como origen, pero en este caso el destino no es opcional.

2) [opcional] Nombre del archivo de destino, referencia de archivo, referencia de escalar para escribir en memoria, o undef para sobrescribir el archivo original. Puede ser '-' para escribir en stdout.

3) [opcional] Tipo del archivo de destino. Se ignora si se define un origen.

Valor de retorno:
1 si el archivo se escribió correctamente, 2 si el archivo se escribió pero no se hicieron cambios, 0 en caso de error de escritura de archivo.

Si se devuelve un código de error, se establece una etiqueta Error y se puede llamar a GetValue('Error') para obtener la descripción del error. Una etiqueta Warning puede establecerse incluso si esta rutina es exitosa. Llamar a WriteInfo borra cualquier etiqueta Error y Warning preexistente.

$errorMessage = $exifTool->GetValue('Error');
$warningMessage = $exifTool->GetValue('Warning');
Notas:
El nombre del archivo de origen puede ser indefinido para crear un archivo desde cero (actualmente solo se pueden crear archivos XMP, MIE, ICC, VRD, DR4, EXV y EXIF de esta manera -- ver "CanCreate" para detalles). Si es indefinido, el tipo del archivo de destino es requerido a menos que el tipo pueda determinarse a partir de la extensión del nombre del archivo de destino.

Si se proporciona un nombre de archivo de destino, el archivo especificado no debe existir porque un archivo de destino existente no será sobrescrito. Cualquier valor nuevo para FileName, Directory o HardLink se ignora cuando se especifica un nombre de archivo de destino.

El nombre del archivo de destino puede ser indefinido para sobrescribir el archivo original (¡asegúrate de tener copias de seguridad!). En este caso, si se proporciona un nombre de archivo de origen, se crea un archivo temporal y se renombra para reemplazar el archivo de origen si no ocurrieron errores al escribir. De lo contrario, si se usa una referencia de archivo de origen o una referencia de escalar, la imagen se escribe primero en memoria y luego se copia de vuelta para reemplazar el original si no hubo errores.

En sistemas Mac OS, la fork de recursos del archivo se conserva si esta rutina se llama con un nombre de archivo de origen.

GetValue

Obtener el valor de una etiqueta especificada. El valor devuelto es o el valor legible por humanos (PrintConv), el valor convertido legible por máquina (ValueConv), el valor original sin procesar (Raw), o el valor original racional (Rational) para formatos racionales. Si no se especifica el tipo de valor, se devuelve el valor PrintConv si la opción PrintConv está activada, de lo contrario se devuelve el valor ValueConv. Los valores PrintConv son los mismos que los valores devueltos por "ImageInfo" y "GetInfo" en el hash etiqueta/valor a menos que la opción PrintConv esté deshabilitada.

Las etiquetas que representan listas de múltiples valores (como puede ocurrir con 'Keywords' por ejemplo) se manejan de manera especial. En contexto escalar, el valor PrintConv devuelto para estas etiquetas es o una cadena de valores o una referencia a lista (dependiendo de la configuración de la opción ListJoin), y el valor ValueConv es siempre una referencia a lista. Pero en contexto de lista, "GetValue" siempre devuelve la lista en sí.

Ten en cuenta que "GetValue" requiere una clave de etiqueta sensible a mayúsculas como argumento. Para recuperar información de etiquetas basándose en un nombre de etiqueta insensible a mayúsculas (con un especificador de grupo opcional), usa "GetInfo" en su lugar.

# Ejemplo PrintConv
my $val = $exifTool->GetValue($tag);
if (ref $val eq 'SCALAR') {
    print "$tag = (valor imprimible)\n";
} else {
    print "$tag = $val\n";
}
# Ejemplos ValueConv
my $val = $exifTool->GetValue($tag, 'ValueConv');
if (ref $val eq 'ARRAY') {
    print "$tag es una lista de valores\n";
} elsif (ref $val eq 'SCALAR') {
    print "$tag representa datos binarios\n";
} else {
    print "$tag es un escalar simple\n";
}
my @keywords = $exifTool->GetValue('Keywords', 'ValueConv');
Entradas:
0) Referencia al objeto ExifTool

1) Clave de etiqueta, o nombre de etiqueta sensible a mayúsculas con prefijo(s) de grupo opcional(es)

2) [opcional] Tipo de valor: 'PrintConv', 'ValueConv', 'Both', 'Raw', 'Bin' o 'Rational'

El tipo de valor predeterminado es 'PrintConv' si la opción PrintConv está activada, de lo contrario el valor predeterminado es 'ValueConv'. Un tipo de valor 'Both' devuelve tanto los valores ValueConv como PrintConv como una lista. 'Raw' devuelve el valor de etiqueta sin procesar decodificado. 'Bin' devuelve los datos binarios originales para las etiquetas EXIF si la opción "SaveBin" estaba activada. 'Rational' devuelve el valor racional sin procesar como una fracción de cadena para tipos racionales, o undef para otros tipos.

Valores de retorno:
El valor de la etiqueta especificada. Si la etiqueta representa una lista de múltiples valores y la opción ListJoin está habilitada, entonces PrintConv devuelve una cadena de valores, de lo contrario se devuelve una referencia a la lista en contexto escalar. La lista en sí se devuelve en contexto de lista. (A menos que se soliciten valores 'Both', en cuyo caso se devuelven dos referencias a lista, independientemente del contexto.) Los valores también pueden ser referencias escalar a datos binarios, o referencias a hash si la opción "Struct" está activada.

Nota: Es posible que "GetValue" devuelva un valor ValueConv o PrintConv indefinido (o una lista vacía en contexto de lista) incluso si la etiqueta existe, ya que es posible que estas conversiones produzcan valores indefinidos. Y el valor Rational será indefinido para cualquier etiqueta no racional. El valor Raw siempre debería existir si la etiqueta existe.

CODIFICACIONES DE

CARACTERES

Ciertos formatos de metainformación permiten conjuntos de caracteres codificados distintos del ASCII simple. Al leer, la mayoría de las codificaciones conocidas se convierten al conjunto de caracteres externo según la opción "Charset", o a UTF-8 por defecto. Al escribir, se realizan las conversiones inversas. Alternativamente, los caracteres especiales pueden convertirse a/desde entidades de caracteres HTML con la opción "Escape"

HTML.

Se hace una distinción entre el conjunto de caracteres externo visible a través de la API de ExifTool y el carácter interno utilizado para almacenar texto en los metadatos de un archivo. Estos conjuntos de caracteres pueden especificarse por separado de la siguiente

manera:
Conjuntos de caracteres
externos:
La codificación para los valores de etiqueta pasados a/desde las funciones de la API de ExifTool se establece a través de la opción "Charset", que es 'UTF8' por defecto.

La codificación de los nombres de archivo se especifica a través de la opción "CharsetFileName". Por defecto, "CharsetFileName" no está definida, y los nombres de archivo pasados a ExifTool se utilizan directamente en las llamadas a las rutinas de e/s del sistema (que esperan cadenas UTF-8 en Mac/Linux, pero usan la página de códigos del sistema por defecto en Windows). En este modo en Windows se emite una advertencia si un nombre de archivo contiene caracteres especiales, pero esta advertencia puede evitarse estableciendo "CharsetFileName" en una cadena vacía. Establecer "CharsetFileName" en cualquier otro valor hace que los nombres de archivo se conviertan desde la codificación especificada a una apropiada para el sistema. En Windows esto también tiene el efecto de activar el soporte de nombres de archivo Unicode a través de las rutinas de e/s de caracteres anchos especiales de Windows si Win32API::File está

disponible.

Tenga en cuenta que establecer la opción "WindowsWideFile" o "WindowsLongPath" hace que "

CharsetFileName" tenga como valor predeterminado 'UTF8' en Windows si no está definida, y
"WindowsLongPath" está establecida por defecto en ExifTool 13.07 y versiones posteriores.
Conjuntos de caracteres
internos:
Las codificaciones utilizadas para almacenar cadenas en los diversos formatos de metadatos. Est
as codificaciones pueden cambiarse para ciertos tipos de metadatos a través de las opciones "Cha
rsetEXIF", "CharsetID3", "CharsetIPTC", "CharsetPhotoshop", "CharsetQuickTime" y "CharsetRIFF".

Los valores se devuelven como cadenas de bytes de caracteres codificados. No se utilizan caracteres anchos de Perl. Por defecto, la mayoría de las cadenas devueltas están codificadas en UTF-8. Para estas, Encode::decode_utf8() puede usarse para convertir a una secuencia de caracteres lógicos de Perl. Tenga en cuenta que algunas configuraciones de la variable de entorno PERL_UNICODE pueden ser incompatibles con el manejo de caracteres de

ExifTool.

Se proporcionan detalles más específicos a continuación sobre cómo se maneja la codificación de caracteres para la información EXIF, IPTC, XMP, PNG, ID3, PDF, Photoshop, QuickTime, AIFF, MIE y

Vorbis:

EXI

F

La mayor parte de la información textual en EXIF se almacena en formato ASCII (llamado "string" en la documentación de nombres de etiquetas de ExifTool). Por defecto ExifTool no convierte estas cadenas. Sin embargo, no es infrecuente que las aplicaciones escriban UTF-8 u otras codificaciones donde se espera ASCII. Para tratar con estas, ExifTool permite especificar la codificación interna de la cadena EXIF con "CharsetEXIF", lo que hace que los valores de cadena EXIF se conviertan desde el conjunto de caracteres especificado al leer, y se almacenen con este conjunto de caracteres al escribir. (El MWG recomienda usar la codificación UTF-8 para las cadenas EXIF, y en consonancia con esto, el módulo MWG establece la codificación interna predeterminada de la cadena EXIF en UTF-8, pero tenga en cuenta que esto no tendrá ningún efecto a menos que la codificación externa también se establezca en algo distinto del valor predeterminado de UTF-8.

)

Algunas etiquetas EXIF (UserComment, GPSProcessingMethod y GPSAreaInformation) admiten una codificación de texto interna designada, con valores almacenados como ASCII, Unicode (UCS-2) o JIS. Al leer estas etiquetas, ExifTool convierte Unicode y JIS al juego de caracteres externo especificado por la opción "Charset", o a UTF-8 por defecto. El texto ASCII no se convierte. Al escribir, el texto se almacena como ASCII a menos que la cadena contenga caracteres especiales, en cuyo caso se convierte desde el juego de caracteres externo (UTF-8 por defecto) y se almacena como Unicode. ExifTool escribe Unicode en el orden de bytes nativo de EXIF por defecto, pero el orden de los bytes puede especificarse estableciendo la etiqueta ExifUnicodeByteOrder (véase la documentación de Etiquetas Adicionales)

.

Las etiquetas "XP" de EXIF (XPTitle, XPComment, etc.) siempre

se almacenan como Unicode little-endian (UCS-2), y se le
en y escriben usando el juego de caracteres especificado.

IPT

C

El valor de la etiqueta IPTC:CodedCharacterSet determina cómo se interpretan los valores de cadenas IPTC internas. Si CodedCharacterSet existe y tiene un valor de 'UTF8' (o 'ESC % G'), se asume que las cadenas están almacenadas como UTF-8; de lo contrario, se asume por defecto la codificación Windows Latin1 (cp1252, 'Latin'), pero esto puede cambiarse con la opción "CharsetIPTC". Al leer, estas cadenas se convierten al juego de caracteres especificado por la opción "Charset". Al escribir, se realizan las conversiones inversas. No se realiza ninguna conversión si los juegos de caracteres internos (IPTC) y externos (ExifTool) son los mismos. Nótese que no se admite el cambio de juego de caracteres ISO 2022. En su lugar, se emite una advertencia y la cadena no se convierte si se encuentra un código de cambio ISO 2022. Véase http://www.iptc.org/IIM/ para la especificación oficial de

IPTC.

ExifTool puede usarse para convertir valores IPTC a una codificación interna diferente. Para hacer esto, todas las etiquetas IPTC deben reescribirse junto con el valor deseado de CodedCharacterSet. Por ejemplo, el siguiente comando cambia la codificación IPTC interna a UTF-8 (desde Windows Latin1 a menos que CodedCharacterSet ya fuera 'UTF8')

: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset=utf8 a.
jpg

o desde Windows Latin2 (cp1250) a

UTF-8: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset=utf8 \
-charset iptc=latin2 a.
jpg

y este comando lo cambia de vuelta de UTF-8 a Windows Latin1 (cp1252)

: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset= a.
jpg

o a Windows

Latin2: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset= \
-charset iptc=latin2 a.
jpg

A menos que CodedCharacterSet sea 'UTF8', las aplicaciones no tienen una forma fiable de determinar la codificación de caracteres IPTC. Por esta razón, se recomienda que CodedCharacterSet se establezca en 'UTF8' al crear nuevo

IPTC.

(Nota: Aquí, "IPTC" se refiere al formato IPTC IIM más

antiguo. Las especificaciones IPTC Core y Extensi
on más recientes usan en realidad el formato XMP.)

XM

P

ExifTool lee XMP codificado como UTF-8, UTF-16 o UTF-32, y los convierte todos a UTF-8 internamente. Además, se convierten todas las referencias de entidades de caracteres XML y las refer

encias numéricas de caracteres. Al escribir, ExifTool siempre codifica XMP como UTF-8, convirtiendo los siguientes 5 caracteres a referencias de caracteres XML: & < > ' ". Por defecto no s
e realiza ninguna conversión adicional, sin embargo, si la opción "Charset" es otra que 'UTF8', el texto se convierte desde/hacia el juego de caracteres especificado al leer/escribir.

PN

G

Las etiquetas TextualData de PNG se almacenan como trozos tEXt, zTXt e iTXt en imágenes PNG. Los trozos tEXt y zTXt usan la codificación ISO 8859-1, mientras que iTXt usa UTF-8. Al leer, ExifTool con

vierte todos los datos textuales de PNG al juego de caracteres especificado por la opción "Charset". Al escribir, ExifTool genera un trozo tEXt (o zTXt con la opción "Compress") si el texto no co
ntiene caracteres especiales o si se especifica la codificación Latin; de lo contrario se usa un trozo iTXt y el texto se convierte desde el juego de caracteres especificado y se almacena como UTF-8.

Comentario

JPEG

La codificación para el Comentario JPEG (segme

nto COM) no está especificada, por lo que E
xifTool lee/escribe este texto sin conversión.

ID

3

La especificación ID3v1 admite oficialmente solo la codificación ISO 8859-1 (un subconjunto de Windows Latin1), aunque algunas aplicaciones pueden usar incorrectamente otros juegos de caracteres. Por defecto, ExifTool convi

erte el texto ID3v1 de Latin al juego de caracteres especificado por la opción "Charset". Sin embargo, el juego de caracteres interno ID3v1 puede especificarse con la opción "CharsetID3". La codificación para la informac
ión ID3v2 está almacenada en el archivo, por lo que ExifTool convierte el texto ID3v2 desde esta codificación al juego de caracteres especificado por la opción "Charset". ExifTool no escribe actualmente información ID3.

PD

F

Las cadenas de texto PDF se almacenan en PDFDocEncoding (similar a Windows Latin1) o Unicode (UCS-2). Al leer, ExifTool convierte

al juego de caracteres especificado por la opción "Charset". Al escribir, ExifTool codifica el texto de entrada desde el juego
de caracteres especificado como Unicode solo si la cadena contiene caracteres especiales; de lo contrario, se usa PDFDocEncoding.

Photosho

p

Algunos nombres de recursos de Photoshop se almacenan como cadenas Pascal con codificación desconocida. Por defecto, ExifTool asume la codificación MacRoman y la convierte a UTF-8, pero los juegos de caracteres interno y externo pueden especificarse con las opciones "CharsetPhotoshop" y "Charset"

respectivamente
.

QuickTim

e

Las cadenas de texto de QuickTime pueden almacenarse en una variedad de formatos mal documentados. ExifTool hace lo mejor posible para decodificarlas de acuerdo con la configuración de la opción "Charset". Para algunas cadenas de QuickTime, ExifTool asume una codificación por defecto de MacRoman, pero esto puede cambiarse con la opción "CharsetQuickTime

"
.

F

enadas en MacRoman, y se convierten de
acuerdo con la opción "Charset" al leer.

RIF

F

Se asume que la codificación interna de las cadenas RIFF (p. ej.,

en archivos AVI y WAV) es Latin a menos que se especifique l

MI

E

Las cadenas MIE se almacenan como UTF-8 o ISO 8859-1. Al leer, las cadenas UTF-8 se convierten de acuerdo con la opción "Charset", y las cade

nas ISO 8859-1 nunca se convierten. Al escribir, las cadenas de entrada se convierten desde el juego de caracteres especificado a UTF-8. Las
cadenas resultantes se almacenan como UTF-8 si contienen secuencias de caracteres UTF-8 multibyte; de lo contrario, se almacenan como ISO 8859-1.
