VARIABLES SOPORTADAS

@EXPORT

Se usa exactamente de la misma manera que Exporter lo usa.

Lista de símbolos a exportar. El sigilo es opcional para los subs. Los símbolos listados aquí se exportan por defecto. Si es posible, deberías poner los símbolos en @EXPORT_OK en su lugar.

our @EXPORT = qw/foo bar &baz $BAT/;

@EXPORT_OK

Se usa exactamente de la misma manera que Exporter lo usa.

Lista de símbolos que se pueden importar. El sigilo es opcional para los subs. Los símbolos listados aquí no se exportan por defecto. Esto es preferible a @EXPORT.

our @EXPORT_OK = qw/foo bar &baz $BAT/;

%EXPORT_TAGS

Este módulo soporta etiquetas exactamente de la misma manera que Exporter lo hace.

use Importer 'Some::Thing'  => ':DEFAULT';
use Importer 'Other::Thing' => ':some_tag';

Las etiquetas se pueden especificar de esta manera:

our %EXPORT_TAGS = (
    oos => [qw/foo boo zoo/],
    ees => [qw/fee bee zee/],
);

@EXPORT_FAIL

Se usa exactamente de la misma manera que Exporter lo usa.

Usa esto para listar subs que no están disponibles en todas las plataformas. Si alguien intenta importar uno de estos, Importer llamará a tu "$from->export_fail(@items)" callback para intentar resolver el problema. Ver Exporter para la documentación de esta característica.

our @EXPORT_FAIL = qw/maybe_bad/;

%EXPORT_ANON

Esto es nuevo en este módulo, Exporter no lo soporta.

Esto te permite exportar símbolos que no están realmente en la tabla de símbolos de tu paquete. Las claves deben ser los nombres de los símbolos, los valores son las referencias para los símbolos.

our %EXPORT_ANON = (
    '&foo' => sub { 'foo' }
    '$foo' => \$foo,
    ...
);

%EXPORT_GEN

Esto es nuevo en este módulo, Exporter no lo soporta.

Esto te permite exportar símbolos que se generan durante la exportación. La clave debe ser el nombre de un símbolo. El valor debe ser un coderef que produce una referencia que será exportada.

Cuando se llaman a los generadores, recibirán 2 argumentos, el paquete al que se está exportando el símbolo, y el símbolo que se está importando (el nombre puede o no incluir el sigilo para los subs).

our %EXPORT_GEN = (
    '&foo' => sub {
        my $from_package = shift;
        my ($into_package, $symbol_name) = @_;
        ...
        return sub { ... };
    },
    ...
);

%EXPORT_MAGIC

Esto es nuevo en este módulo. Exporter no lo soporta.

Esto te permite definir acciones personalizadas para ejecutar DESPUÉS de que una exportación ha sido inyectada en el espacio de nombres del consumidor. Este es un buen lugar para habilitar hooks del analizador como con Devel::Declare. Estos NO se ejecutarán si un consumidor usa un callback de asignación personalizado.

our %EXPORT_MAGIC = (
    foo => sub {
        my $from = shift;    # Debería ser el paquete que hace la exportación
        my %args = @_;
        my $into      = $args{into};         # Paquete al que se exportó el símbolo
        my $orig_name = $args{orig_name};    # Nombre original de la exportación (en el exportador)
        my $new_name  = $args{new_name};     # Nombre con el que se importó el símbolo
        my $ref       = $args{ref};          # La referencia al símbolo
        ...; # lo que quieras, el valor de retorno se ignora.
    },
);

USO CON OTRAS IMPLEMENTACIONES DE EXPORTER

Si quieres que tu módulo funcione con Importer, pero usas algo diferente a Exporter para definir tus exportaciones, puedes hacer que funcione definiendo el "IMPORTER_MENU" método en tu paquete. Asimismo, otros exportadores pueden ser actualizados para soportar Importer al poner este sub en tu paquete. IMPORTER_MENU() debe estar definido en tu paquete, ¡no en una clase base!

sub IMPORTER_MENU {
    my $class = shift;
    my ($into, $caller) = @_;
    return (
        export       => \@EXPORT,          # Exportaciones por defecto
        export_ok    => \@EXPORT_OK,       # Otras exportaciones permitidas
        export_tags  => \%EXPORT_TAGS,     # Definir etiquetas
        export_fail  => \@EXPORT_FAIL,     # Para subs que pueden no estar siempre disponibles
        export_anon  => \%EXPORT_ANON,     # Símbolos anónimos para exportar
        export_magic => \%EXPORT_MAGIC,    # Magia a aplicar después de que un símbolo sea exportado
        generate   => \&GENERATE,          # Sub para generar exportaciones dinámicas
                                           # O
        export_gen => \%EXPORT_GEN,        # Hash de constructores, la clave es el nombre
                                           # del símbolo, el valor es un sub que genera
                                           # la referencia del símbolo.
    );
}
sub GENERATE {
    my ($symbol) = @_;
    ...
    return $ref;
}

Todas las exportaciones deben estar listadas en @EXPORT o @EXPORT_OK, o ser claves en %EXPORT_GEN o %EXPORT_ANON para ser permitidas. 'export_tags', 'export_fail', 'export_anon', 'export_gen' y 'generate' son opcionales. No puedes combinar 'generate' y 'export_gen'.

Nota: Si tu sub GENERATE necesita el $class, $into, o $caller entonces tu IMPORTER_MENU() método necesitará construir un sub anónimo que capture estas variables:

sub IMPORTER_MENU {
    my $class = shift;
    my ($into, $caller) = @_;
    return (
        ...
        generate => sub { $class->GENERATE($into, $caller, @_) },
    );
}

NOMBRE

Importer - Un framework de exportación de Perl más amigable

DESCRIPCIÓN

Si alguna vez has querido escribir tu propio módulo de exportación de Perl, pero has descubierto que la API de Exporter es un poco arcaica, entonces ¡Importer es para ti!

Importer está diseñado para ser un framework más moderno y amigable para la escritura de módulos de exportación, y al mismo tiempo, ser completamente compatible con los módulos de exportación existentes.

El objetivo es permitirle concentrarse en las exportaciones que quiere admitir, y no en la forma de hacerlo. Se pueden admitir todas las exportaciones de Exporter, incluyendo:

  • Exportaciones simples de subrutinas, escalares y arrays.
  • Etiquetas de exportación para agrupar exportaciones.
  • Exportaciones condicionales (versión, sistema operativo, etc.).
  • Soporte para generar exportaciones sobre la marcha.
  • Un uso más sencillo de import y export.

SINOPSIS

  package My::Exporter;
  use Importer;

  our @EXPORT_OK = qw( foo bar );
  our %EXPORT_TAGS = (
      'utils' => [qw( foo )],
      'all'   => [ @EXPORT_OK ],
  );

  sub foo { print "foo\n" }
  sub bar { print "bar\n" }

  package My::User;
  use My::Exporter qw( foo ); # Lo mismo que Exporter
  use My::Exporter qw( :utils ); # Lo mismo que Exporter
  use My::Exporter qw( :all ); # Lo mismo que Exporter

O para uso OO:

  package My::Exporter;
  use Importer;

  sub import {
      my $class = shift;
      my $caller = caller;
      my $imp = Importer->new($caller); # O puede usar 'new($class)' si lo necesita
      $imp->import($caller, @_); # ¡Eso es todo!
  }

¿POR QUÉ?

El módulo Exporter ha sido la columna vertebral de las exportaciones de Perl durante mucho tiempo, pero su API puede ser un poco difícil de entender, especialmente para los principiantes. Importer tiene como objetivo simplificar el proceso de creación de módulos de exportación.

Además, Importer proporciona una interfaz orientada a objetos que puede ser más intuitiva para algunos usuarios, y permite una mayor flexibilidad en la forma en que se manejan las exportaciones.

COMPATIBILIDAD

Un objetivo principal de Importer es ser completamente compatible con el módulo Exporter. Esto significa que puedes usar Importer en tu módulo y tus usuarios no verán ninguna diferencia. Pueden seguir usando las directivas use Module qw( ... ) como siempre.

Si tu módulo ya utiliza Exporter, puedes cambiar fácilmente a Importer simplemente reemplazando use Exporter; con use Importer; y asegurándote de que tu antigua @EXPORT_OK y %EXPORT_TAGS sigan siendo exportados por tu módulo (por ejemplo, usando use Importer qw(Exporter::Export::*); o exportando manualmente las variables de la manera antigua).

Por defecto, Importer exportará @EXPORT, @EXPORT_OK y %EXPORT_TAGS del módulo que lo usa, al igual que Exporter.

PARÁMETROS DE IMPORTACIÓN

Cuando un usuario escribe use My::Module qw( ... ), los argumentos en la lista qw( ... ) son pasados al método import del módulo. Si usas Importer, estos argumentos se pasan a Importer->new->parse_args(), el cual devuelve una lista de valores que luego se pasan a Importer->import(). Los argumentos admitidos son:

Paquete de destino
El primer argumento siempre debe ser el nombre del paquete al que se importarán los símbolos (por ejemplo, el paquete que contiene el use).
Nombres de símbolos
Los nombres de las subrutinas, escalares o arrays que se importarán. Estos pueden incluir o no el sigilo (por ejemplo, "foo" o "$foo").
Etiquetas
Prefijadas con ":" (por ejemplo, ":utils"). Estas se expanden a la lista de símbolos definidos en la etiqueta correspondiente en %EXPORT_TAGS.
Patrones
Cadenas que contienen comodines "*" y "?". Estos se expanden para que coincidan con los símbolos disponibles que coinciden con el patrón.
Versiones
Se pueden especificar números de versión como cadenas (por ejemplo, "v1.2", "v1.2.3"). Si un símbolo importado tiene una versión asociada (a través de %EXPORT_VERSION), esta se utilizará para verificar la compatibilidad. Si no se especifica, se importará el símbolo.
Exclusiones
Prefijadas con "^" (por ejemplo, "^foo"). Estos símbolos se excluyen de la importación, incluso si coinciden con otros criterios.

CARACTERÍSTICAS SOPORTADAS

my $imp = Importer->new($caller)
Crea una nueva instancia de Importer. $caller es el paquete que está realizando la importación. Si se omite, Importer intentará detectarlo automáticamente (lo que puede ser lento).
$imp->import($into, @args)
Realiza la importación real. $into es el paquete de destino. @args son los argumentos analizados de la directiva use.
$imp->parse_args($default_caller, @args)
Analiza los argumentos proporcionados por el usuario. $default_caller es el paquete que se presupone si no se proporciona explícitamente.
$imp->export_list(@args)
Devuelve una lista de símbolos que se exportarán según los argumentos proporcionados.
$imp->filter_args(@args)
Filtra los argumentos proporcionados, resolviendo etiquetas, patrones y exclusiones.
$imp->resolve_tag($tag_name)
Resuelve un nombre de etiqueta a una lista de símbolos.
$imp->resolve_pattern($pattern)
Resuelve un patrón a una lista de símbolos disponibles.
$imp->check_version($symbol, $version)
Verifica si la versión especificada del símbolo es compatible con la versión requerida.
$imp->get_caller()
Obtiene el paquete llamador. Útil para informes de error.
$imp->load_module($module_name)
Carga un módulo si aún no está cargado.

PARÁMETROS DE DESIMPORTACIÓN

También puedes desimportar símbolos usando el método unimport de Importer, que funciona de manera similar a Exporter::unimport.

$imp->unimport($package, @symbols)
Elimina los símbolos especificados del paquete dado. Si no se proporcionan símbolos, se eliminarán todos los símbolos importados por Importer.

VARIABLES SOPORTADAS

Al igual que Exporter, Importer reconocerá y utilizará las siguientes variables si están definidas en el módulo que lo utiliza:

@EXPORT
Lista de símbolos que se exportan por defecto.
@EXPORT_OK
Lista de símbolos que se pueden exportar explícitamente bajo demanda.
%EXPORT_TAGS
Un hash que mapea nombres de etiquetas a listas de símbolos.
%EXPORT_VERSION
Un hash que mapea nombres de símbolos a números de versión.

MÉTODOS DE CLASE

my $imp = Importer->new($caller)
Crea una nueva instancia de Importer. El argumento $caller es el nombre del paquete que está realizando la importación. Si se omite, Importer intentará determinarlo dinámicamente cada vez que lo necesite (esto es lento y costoso, pero necesario si tienes la intención de reutilizar el objeto).

USO CON OTRAS IMPLEMENTACIONES DE EXPORTADOR

Si deseas usar Importer junto con una implementación de exportador existente (como Exporter), puedes hacerlo sin problemas. Simplemente incluye ambos módulos y asegúrate de que sus exportaciones no entren en conflicto.

Por ejemplo:

  package My::Module;
  use Importer;
  use Exporter qw(); # Necesario si quieres usarlo directamente

  our @EXPORT_OK = qw( foo );
  our %EXPORT_TAGS = (utils => [qw( foo )]);

  # Puedes delegar algunas exportaciones a Exporter si lo deseas
  sub export {
      my $self = shift;
      my $call = caller;
      # Pasar los argumentos a Importer para el manejo estándar
      return Importer->new($call)->export($call, @_);
  }

  sub foo { ... }

Interfaz OO

Importer proporciona una interfaz orientada a objetos completa para gestionar las importaciones y exportaciones.

my $imp = Importer->new($caller)
Crea un nuevo objeto Importer. El argumento $caller es opcional pero recomendado. Si no se proporciona, Importer intentará descubrirlo dinámicamente, lo que puede ser menos eficiente si se reutiliza el objeto.
$imp->do_import($into)
$imp->do_import($into, @symbols)
Importa símbolos desde el paquete "from" del objeto al paquete $into. Puedes proporcionar una lista de @symbols o dejarla vacía para usar los valores predeterminados.
$imp->do_unimport()
$imp->do_unimport(@symbols)
Elimina los símbolos importados del paquete "from" del objeto. Si se proporciona una lista de @symbols, solo se eliminarán los símbolos especificados; de lo contrario, se eliminarán todos los símbolos importados usando Importer.

Nota: Ten en cuenta la diferencia entre do_import() y do_unimport(). Para la importación, 'from' se usa como origen; en la desimportación, se usa como destino. Esto significa que no puedes reutilizar una instancia para importar y luego desimportar.

($into, $versions, $exclude, $symbols, $set) = $imp->parse_args('Dest::Package')
($into, $versions, $exclude, $symbols, $set) = $imp->parse_args('Dest::Package', @symbols)
Analiza los argumentos. El primer argumento debe ser el paquete de destino. Otros argumentos pueden ser una mezcla de nombres de símbolos, etiquetas, patrones, números de versión y exclusiones.
$caller_ref = $imp->get_caller()
Encuentra el llamador. Esto se usa principalmente para informes de errores. Si el objeto se construyó con un llamador, eso es lo que se devuelve; de lo contrario, se buscará en la pila la primera llamada que no se origine en un paquete que sea Importer.
$imp->carp($warning)
Emite una advertencia en el nivel del llamador.
$imp->croak($exception)
Termina la ejecución con un error en el nivel del llamador.
$from_package = $imp->from()
Obtiene el paquete "from" que se especificó en la construcción.
$file = $imp->from_file()
Obtiene el nombre de archivo para el paquete "from".
$imp->load_from()
Carga el paquete "from" si aún no se ha cargado. Utiliza cierta magia para garantizar que los errores en el proceso de carga se informen al "caller".
$menu_hr = $imp->menu($into)
Obtiene el menú de exportación construido desde, o proporcionado por, el paquete "from". Esto se almacena en caché después de la primera vez que se llama. Usa "$imp->reload_menu()" para actualizarlo.

La estructura del menú se ve así:

$menu = {
    # cada exportación válida tiene una clave en el hashref de búsqueda, el valor es siempre
    # 1, la clave siempre incluye el sigilo
    lookup => {'&symbol_a' => 1, '$symbol_b' => 1, ...},
    # la mayoría de las exportaciones se enumeran aquí, el nombre del símbolo con sigilo es la clave, el valor es
    # una referencia al símbolo. Si falta un símbolo, puede generarse.
    exports => {'&symbol_a' => \&symbol_a, '$symbol_b' => \$symbol_b, ...},
    # Hashref de etiquetas, el nombre de la etiqueta (sin el prefijo ':') es la clave, el valor es un
    # arrayref de nombres de símbolos, las subs pueden tener un sigilo, pero no es obligatorio
    # hacerlo.
    tags => { DEFAULT => [...], foo => [...], ... },
    # Magia para aplicar
    magic => { foo => sub { ... }, ... },
    # Este es un hashref igual que 'lookup'. Las claves son símbolos que pueden no
    # estar siempre disponibles. Si no hay símbolos en esta categoría,
    # el valor de la clave 'fail' será undef en lugar de un hashref.
    fail => { '&iffy_symbol' => 1, '\&only_on_linux' => 1 },
    # O fail => undef,
    # Si está presente, esta subrutina sabe cómo generar referencias para los
    # símbolos enumerados en 'lookup', pero que faltan en 'exports'. Las referencias
    # que devuelve NUNCA se almacenan en caché.
    generate => sub { my $sym_name = shift; ...; return $symbol_ref },
};
$imp->reload_menu($into)
Recarga el menú de exportación desde el paquete "from".
my $exports = $imp->get(@imports)
Devuelve un hashref de "{ $name => $ref }" para todas las importaciones especificadas.
my @export_refs = $imp->get_list(@imports)
Devuelve una lista de referencias para cada importación especificada. Solo se devuelven las referencias de exportación, no los nombres.
$export_ref = $imp->get_one($import)
Devuelve una única referencia a una única exportación. Si se proporcionan múltiples importaciones, solo se utilizará la ÚLTIMA.

FUNCIONES

Estas pueden ser importadas:

use Importer 'Importer' => qw/import optimal_import/;
$bool = optimal_import($from, $into, \@caller, @imports)
Esta función intentará importar @imports desde el paquete $from al paquete $into. @caller necesita tener un nombre de paquete, nombre de archivo y número de línea. Si esta función falla, no se realizará ninguna exportación.

Si la importación es exitosa, devolverá verdadero.

Si la importación no es exitosa, devolverá falso y no se producirán modificaciones en la tabla de símbolos.

$class->import(@imports)
Si escribes una clase destinada a ser utilizada con Importer, pero también necesitas proporcionar un método import() heredado para consumidores directos de tu clase, puedes importar este método import(). 
package My::Exporter;
# Esto te dará 'import()' muy parecido a 'use base "Exporter";'
use Importer 'Importer' => qw/import/;
...
