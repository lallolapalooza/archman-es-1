SINOPSI

S 
use IO::Multiplex;
my $mux = new IO::Multiplex;
$mux->add($fh1);
$mux->add(\*FH2);
$mux->set_callback_object(...);
$mux->listen($server_socket);
$mux->loop;
sub mux_input { ...
}

"IO::Multiplex" está diseñado para facilitar la gestión de múltiples manejadores de archivos. Es esencialmente una interfaz de usuario muy sofisticada para la "select" llamada al sistema. Además de mantener el bucle "select", almacena en búfer toda la entrada y salida de/para los manejadores de ar

chivos. También puede aceptar conexiones ent
rantes en uno o más sockets de escucha.

DESCRIPCIÓ

N

Está diseñado de forma orientada a objetos y le notificará de eventos significativos llamando a métodos en un objeto que usted proporcione. Si no está utilizando objetos, simplemente puede proporcionar "__PACKAGE__" en lugar de una referencia a un

objeto.

Puede tener un objeto de callback registrado para cada manejador de archivos, o uno global. Posiblemente ambos -- el objeto de callback por manejador de archivos será utilizado en lugar del

global.

Cada manejador de archivos también puede tener un temporizador asociado con él. Una función de callback se llama cuando el temporizador

expira.

Manejo de entrada en

descriptores

Cuando la entrada llega a un manejador de archivos, el método "mux_input" es llamado en el objeto de callback apropiado. A este método se le pasan tres argumentos (en adición a la referencia al objeto, por supuesto)

:
1
.
una referencia al
multiplexor,
2
.
una referencia al manejador de archivos,
y
3
.
una referencia al búfe
r de entrada para el
manejador de archivos.

El método debe eliminar los datos que ha consum

ido de la referencia proporcionada. Puede de
jar datos no consumidos en el búfer de entrada.

Manejo de salida a

descriptores

Si "IO::Multiplex" no manejara la salida a los manejadores de archivos así como la entrada de ellos, entonces existe la posibilidad de que el programa se bloquee mientras intenta escribir. Si deja que el multiplexor almacene la salida en búfer, escribirá los datos solo cuando el manejador de archivos sea capaz de

recibirlos.

El método básico para entregar la salida al multiplexor es el método "write", que simplemente toma un descriptor de archivo y los datos a escribir,

así: 
$mux->write($fh, "Some data")
;

Por conveniencia, cuando el manejador de archivos es "add"ido al multiplexor, está vinculado a una clase especial que intercepta todos los intentos de escribir en el manejador de archivos. Así, puede usar print y printf para enviar salida al manejador de una manera

normal: 
printf $fh "%s%d%X", $foo, $bar,
$baz

Desafortunadamente, el soporte de Perl para manejadores de archivos vinculados es incompleto, y funciones como "send" no pueden ser

soportadas.

Además, los métodos de objetos de manejadores de archivos como el método "send" de "IO::Socket" no

pueden se
r interc
eptados.

EJEMPLO

S

Ejemplo

simple

Este es un programa simple tipo telnet, que demuestra los conceptos cubiertos hasta ahora. No funciona realmente muy bien contra un servidor telnet, pero funciona bien contra el servidor de ejemplo presentado más

abajo. 
use IO::Socket;
use IO::Multiplex;
# Create a multiplex object
my $mux  = new IO::Multiplex;
# Connect to the host/port specified on the command line,
# or localhost:23
my $sock = new IO::Socket::INET(Proto    => 'tcp',
                                PeerAddr => shift || 'localhost',
                                PeerPort => shift || 23)
    or die "socket: $@";
# add the relevant file handles to the mux
$mux->add($sock);
$mux->add(\*STDIN);
# We want to buffer output to the terminal.  This prevents the program
# from blocking if the user hits CTRL-S for example.
$mux->add(\*STDOUT);
# We're not object oriented, so just request callbacks to the
# current package
$mux->set_callback_object(__PACKAGE__);
# Enter the main mux loop.
$mux->loop;
# mux_input is called when input is available on one of
# the descriptors.
sub mux_input {
    my $package = shift;
    my $mux     = shift;
    my $fh      = shift;
    my $input   = shift;
    # Figure out whence the input came, and send it on to the
    # other place.
    if ($fh == $sock) {
        print STDOUT $$input;
    } else {
        print $sock $$input;
    }
    # Remove the input from the input buffer.
    $$input = '';
}
# This gets called if the other end closes the connection.
sub mux_close {
    print STDERR "Connection Closed\n";
    exit;
}

Un ejemplo de

servidor

Los servidores son igual de simples de escribir. Solo registramos un socket de escucha con el método "listen" del objeto multiplexor. Aceptará automáticamente conexiones en él y las añadirá a su lista de manejadores de archivos

activos.

Este ejemplo es un servidor de chat

simple. 
use IO::Socket;
use IO::Multiplex;
my $mux  = new IO::Multiplex;
# Create a listening socket
my $sock = new IO::Socket::INET(Proto     => 'tcp',
                                LocalPort => shift || 2300,
                                Listen    => 4)
    or die "socket: $@";
# We use the listen method instead of the add method.
$mux->listen($sock);
$mux->set_callback_object(__PACKAGE__);
$mux->loop;
sub mux_input {
    my $package = shift;
    my $mux     = shift;
    my $fh      = shift;
    my $input   = shift;
    # The handles method returns a list of references to handles which
    # we have registered, except for listen sockets.
    foreach $c ($mux->handles) {
        print $c $$input;
    }
    $$input = '';
}

Un ejemplo de servidor más

complejo

Echemos un vistazo a los comienzos de un servidor de juego multijugador. Tendremos un objeto Player para cada

jugador. 
# Paste the above example in here, up to but not including the
# mux_input subroutine.
# mux_connection is called when a new connection is accepted.
sub mux_connection {
    my $package = shift;
    my $mux     = shift;
    my $fh      = shift;
    # Construct a new player object
    Player->new($mux, $fh);
}
package Player;
my %players = ();
sub new {
    my $package = shift;
    my $self    = bless { mux  => shift,
                          fh   => shift } => $package;
    # Register the new player object as the callback specifically for
    # this file handle.
    $self->{mux}->set_callback_object($self, $self->{fh});
    print $self->{fh}
        "Greetings, Professor.  Would you like to play a game?\n";
    # Register this player object in the main list of players
    $players{$self} = $self;
    $mux->set_timeout($self->{fh}, 1);
}
sub players { return values %players; }
sub mux_input {
    my $self = shift;
    shift; shift;         # These two args are boring
    my $input = shift;    # Scalar reference to the input
    # Process each line in the input, leaving partial lines
    # in the input buffer
    while ($$input =~ s/^(.*?)\n//) {
        $self->process_command($1);
    }
}
sub mux_close {
   my $self = shift;
   # Player disconnected;
   # [Notify other players or something...]
   delete $players{$self};
}
# This gets called every second to update player info, etc...
sub mux_timeout {
    my $self = shift;
    my $mux  = shift;
    $self->heartbeat;
    $mux->set_timeout($self->{fh}, 1)
;
}

CALLBACK

INTERFACE

Les objets de rappel doivent prendre en charge l'interface suivante. Vous n'avez pas à fournir toutes ces méthodes, fournissez seulement celles qui vous

intéressent.

Toutes les méthodes reçoivent une référence à l'objet de rappel (ou paquet) comme premier argument, de la manière orientée objet traditionnelle. Des références à l'objet "IO::Multiplex" et au descripteur de fichier pertinent sont également fournies. Cela sera supposé dans les descriptions des

méthodes.

mux_inpu

t

Appelé lorsque l'entrée est prête sur un descripteur. Une référence au tampon d'entrée lui est passée. Il doit supprimer toute entrée qu'il a consommée et laisser toute donnée partiellement reçue dans le

tampon. 
sub mux_input {
    my $self = shift;
    my $mux  = shift;
    my $fh   = shift;
    my $data = shift;
    # Process each line in the input, leaving partial lines
    # in the input buffer
    while ($$data =~ s/^(.*?\n)//) {
        $self->process_command($1);
    }
}

mux_eo

f

C'est appelé lorsqu'une condition de fin de fichier est présente sur le descripteur. Cela ne signifie pas nécessairement que le descripteur a été fermé, car l'autre extrémité d'un socket pourrait avoir utilisé "shutdown" pour fermer seulement la moitié du socket, nous laissant libre d'écrire des données vers la moitié encore ouverte. Comme mux_input, une référence au tampon d'entrée lui est également passée. Il doit consommer tout le tampon, sinon il sera simplement

perdu.

Dans cet exemple, nous envoyons une réponse finale à l'autre extrémité du socket, puis nous l'arrêtons pour l'écriture. Comme il est également arrêté pour la lecture (implicitement par la condition de fin de fichier), il sera fermé une fois la sortie envoyée, après quoi le rappel mux_close sera

appelé. 
sub mux_eof {
    my $self = shift;
    my $mux  = shift;
    my $fh   = shift;
    print $fh "Well, goodbye then!\n";
    $mux->shutdown($fh, 1);
}
