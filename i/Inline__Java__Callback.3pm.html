"Inline::Java::Callback" le permite llamar a funciones de Perl desde Java. Para hacer esto, necesita

crear un

objeto "org.perl.inline.java.InlinePerlCaller". CONTEXTO DE LLAMADA DE

RETORNO

Por defecto, las llamadas de retorno se ejecutan en contexto escalar. Sin embargo, si desea llamar a ciertas funciones en contexto de lista, debe insertar "@" delante del nombre de la función. El resultado se pasará entonces a Java como un

Array: 
use Inline Java => <<'END' ;
   import org.perl.inline.java.* ;
   class Pod_Context {
      static private String dummy[] = {} ;
      static public String [] get_list()
         throws InlineJavaException, InlineJavaPerlException {
         InlineJavaPerlCaller pc = new InlineJavaPerlCaller() ;
         return (String [])pc.CallPerlSub("@main::list",
             null, dummy.getClass()) ;
      }
   }
END
sub list {
   return ('a', 'b', 'c') ;
}
print(Pod_Context->get_list()->[1] . "\n") ; # imprime
b

Nota: Al llamar a una función de Perl que devuelve una lista o un array, necesitará pasar el objeto Class para el tipo de array esperado (en este caso String []). Dado que estos objetos Class son difíciles de acceder para los tipos de array, la forma más fácil de hacerlo es crear un array ficticio del tipo deseado y llamar al método getClass() en ese ob

jeto (como se
ve arriba).

BUCLES DE LLAMADA DE

RETORNO

Ahora es posible usar llamadas de retorno desde diferentes hilos de Java. Una de las grandes ventajas de esto es que ahora puede manejar, por ejemplo, eventos SWING en Perl. Aquí hay un

ejemplo: 
use Inline Java => <<'END' ;
   import java.util.* ;
   import org.perl.inline.java.* ;
   import javax.swing.* ;
   import java.awt.event.* ;
   class Pod_Button extends InlineJavaPerlCaller
                    implements ActionListener {
      JFrame frame = null ;
      public Pod_Button() throws InlineJavaException {
         frame = new JFrame("Pod_Button") ;
         frame.setSize(100,100) ;
         JButton button = new JButton("Click Me!") ;
         frame.getContentPane().add(button) ;
         button.addActionListener(this) ;
         frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE) ; 
         frame.show() ;
      }
      public void actionPerformed(ActionEvent e){
         try {
            CallPerlSub("main::button_pressed", new Object [] {}) ;
         }
         catch (InlineJavaPerlException pe){
            // $@ está en pe.GetObject()
         }
         catch (InlineJavaException pe) {
            pe.printStackTrace() ;
         }
      }
      public void close(){
         frame.dispose() ;
         frame.hide() ;
         frame = null ;
      }
      public void quit(){
         System.exit(0) ;
      }
   }
END
my $b = new Pod_Button() ;
$b->StartCallbackLoop() ;
$b->close() ;
# Quizás hacer otras cosas
exit() ;      # en modo cliente-servidor, opcional
$b->quit() ;  # en modo JNI
sub button_pressed {
   print("click!\n") ; # imprime click!
   $b->StopCallbackLoop() ;
}

El método StartCallbackLoop se puede llamar en cualquier objeto "org.perl.inline.java.InlineJavaPerlCaller" y bloqueará el hilo actual y permitirá la recepción de llamadas de retorno a través de cualquier InlineJavaPerlCaller que haya sido creado por el mismo (actual) hilo. La única forma de interrumpir un método StartCallbackLoop como ese es llamar al método StopCallbackLoop en cualquier objeto "org.perl.inline.java.InlineJavaPerlCaller" que haya sido creado por ese mismo

hilo.

Además, solo los hilos que se comuniquen con Perl a través de &quot;Inline::Java" están permitidos para crear "org.perl.inline.java.InlineJavaPerlCaller" objetos e invocar sus métodos StartCallbackLoop / StopCallbackLoo

p
.

BUCLES DE CALLBACK DE ESTILO

SELECT

La desventaja del tipo de bucle de callback presentado en la sección anterior es que la parte principal del programa Perl queda completamente bloqueada mientras espera callbacks. En la versión 0.51 se introdujo una nueva API para bucles de callback, lo que permite que los callbacks se procesen de una manera muy similar a la que se usa select(2) para leer datos de un filehandle. Aquí hay un

ejemplo: 
use Inline Java => <<'END' ;
   import java.util.* ;
   import org.perl.inline.java.* ;
   import javax.swing.* ;
   import java.awt.event.* ;
   class Pod_Button extends InlineJavaPerlCaller
                    implements ActionListener {
      JFrame frame = null ;
      public Pod_Button() throws InlineJavaException {
         frame = new JFrame("Pod_Button") ;
         frame.setSize(100,100) ;
         JButton button = new JButton("Click Me!") ;
         frame.getContentPane().add(button) ;
         button.addActionListener(this) ;
         frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE) ; 
         frame.show() ;
      }
      public void actionPerformed(ActionEvent e){
         try {
            CallPerlSub("main::button_pressed", new Object [] {}) ;
         }
         catch (InlineJavaPerlException pe){
            // $@ is in pe.GetObject()
         }
         catch (InlineJavaException pe) {
            pe.printStackTrace() ;
         }
      }
      public void close(){
         frame.dispose() ;
         frame.hide() ;
         frame = null ;
      }
      public void quit(){
         System.exit(0) ;
      }
   }
END
my $b = new Pod_Button() ;  
$b->OpenCallbackStream() ;
while ((my $rc = $b->WaitForCallback(5)) > -1){
   if ($rc > 0){
      # A callback is pending, we must process it.
      $b->ProcessNextCallback() ;
   }
   else {
      # A timeout has occurred after, in this case, 5 secs.
      print "5 seconds have passed, still waiting for callback...\n" ;
      # Maybe do some other stuff
   }
}
$b->close() ;
# Maybe do some other stuff
exit() ;      # in client-server mode, optional
$b->quit() ;  # in JNI mode
sub button_pressed {
   print('click!' . "\n") ; # prints click!
   $b->CloseCallbackStream() ;
}

El método StartCallbackStream se puede llamar en cualquier objeto InlineJavaPerlCaller para inicializar un canal para recibir callbacks. Luego se puede llamar al método WaitForCallback con un valor de tiempo de espera flotante (-1 significa esperar para siempre, 0 significa devolver inmediatamente). El método WaitForCallback puede

devolver: 
rc  >  0, indicando que rc callbacks están esperando ser procesados
rc ==  0, indicando que ha ocurrido un tiempo de espera y no hay callbacks esperando
rc == -1, indicando que el stream de callbacks ha sido
cerrado

El stream de callbacks se puede cerrar llamando a CloseCallbackStream, que funciona de manera similar al método StopCallbackLoop usado en la sección

anterior.

Además, las restricciones sobre la comunicac

ión entre hilos establecidas en la secció
n anterior también son válidas en este caso.
