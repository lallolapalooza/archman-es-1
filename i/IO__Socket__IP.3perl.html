BLOQUEANTE

Si al constructor se le pasa un valor definido pero falso para el argumento "Blocking", entonces el socket se pone en modo no bloqueante. Cuando está en modo no bloqueante, el socket no estará configurado para cuando el constructor retorne, porque la llamada al sistema connect(2) de lo contrario tendría que

bloquear.

El comportamiento no bloqueante es una extensión de la API de "IO::Socket::INET", única de "IO::Socket::IP", porque la primera no admite conexiones no bloqueantes en hosts

múltiples.

Al usar el modo no bloqueante, el llamador debe comprobar repetidamente si el manejador de archivo es escribible (por ejemplo, usando "select" o "IO::Poll"). Cada vez que el manejador de archivo esté listo para escribir, se debe llamar al método "connect", sans arguments. Notez que certains systèmes d'exploitation, notamment "MSWin32", ne signalent pas un échec de connect() via la sélection en écriture ; vous devez donc aussi sélectionner

pour

un statut exceptionnel. Tant que "connect" renvoie false, la valeur de $! indique s'il faut réessayer (en étant défini à la valeur "EINPROGRESS", ou "EWOULDBLOCK" sur MSWin32), ou si une erreur permanente s'est produite (par ex. "ECONNREFUS

ED").

Une fois que le socket est connecté au pair, "connect" renverra true et le socket sera maintenant prêt à être utilisé.
