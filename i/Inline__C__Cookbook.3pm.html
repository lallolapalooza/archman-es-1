NOMBRE

Inline::C::Cookbook - Una cornucopia de recetas de Inline C

DESCRIPCIÓN

Es mucho más fácil para la mayoría de nosotros cocinar una comida siguiendo una receta, que simplemente tirar cosas en una olla hasta que algo comestible se forme. Así también ocurre con la programación. "Inline.pm" hace que la programación en C para Perl sea lo más fácil posible. Tener un conjunto de ejemplos fáciles de entender, lo hace aún más simple.

Este Cookbook está destinado a ser un repositorio en constante crecimiento de ejemplos de código pequeños pero completos; cada uno mostrando cómo lograr una tarea particular con Inline. Cada ejemplo va seguido de una breve discusión, explicando en detalle las características particulares que se están demostrando.

Muchas de estas recetas se adaptan de discusiones por correo electrónico que he tenido con usuarios de Inline en todo el mundo. Hasta ahora, mi experiencia ha sido que Inline proporciona una solución elegante a casi todos los problemas que involucran Perl y C.

¡Buen provecho!

Hola, mundo

Problema

Parece que lo primero que cualquier programador quiere hacer cuando aprende una nueva técnica de programación es usarla para saludar a la Tierra. ¿Cómo puedo hacer esto usando Inline?

Solución
use Inline C => <<'...';
void greet() {
  printf("Hello, world\n");
}
...
greet;
Discusión
Nada demasiado sofisticado aquí. Definimos una única función C greet() que imprime un mensaje en STDOUT. Una cosa a tener en cuenta es que como el código Inline aparece antes de la llamada a la función "greet", podemos llamarla como una palabra desnuda (sin paréntesis).

Tipos de datos

Problema
¿Cómo paso diferentes tipos de datos desde y hacia las funciones C de Inline; como cadenas, números y enteros?
Solución
# vowels.pl
use Inline 'C';
$filename = $ARGV[0];
die "Usage: perl vowels.pl filename\n" unless -f $filename;
$text = join '', <>;           # lee el archivo completo
$vp = vowel_scan($text);       # llama a nuestra función
$vp = sprintf("%03.1f", $vp * 100);  # formatea para imprimir
print "The letters in $filename are $vp% vowels.\n";
__END__
__C__
/* Encuentra el porcentaje de vocales sobre letras */
double vowel_scan(char* str) {
  int letters = 0;
  int vowels = 0;
  int i = 0;
  char c;
  char normalize = 'a' ^ 'A';
  /* normalize fuerza a minúsculas en ASCII; mayúsculas en EBCDIC */
  char A = normalize | 'a';
  char E = normalize | 'e';
  char I = normalize | 'i';
  char O = normalize | 'o';
  char U = normalize | 'u';
  char Z = normalize | 'z';
  while(c = str[i++]) {
    c |= normalize;
    if (c >= A && c <= Z) {
       letters++;
       if (c == A || c == E || c == I || c == O || c == U)
         vowels++;
    }
  }
  return letters ? ((double) vowels / letters) : 0.0;
}
Discusión
Este script toma un nombre de archivo de la línea de comandos e imprime la relación de vocales a letras en ese archivo. "vowels.pl" usa una función Inline C llamada "vowel_scan", que toma un argumento de cadena y devuelve el porcentaje de vocales como un número de punto flotante entre 0 y 1. Maneja letras mayúsculas y minúsculas, y funciona con ASCII y EBCDIC. También es bastante rápido.

Ejecutar este script produce:

> perl vowels.pl /usr/dict/words
The letters in /usr/dict/words are 37.5% vowels.

Es muy importante notar que los ejemplos en este Cookbook usan "char *" para referirse a una cadena. Internamente Perl tiene varios mecanismos para tratar con cadenas que contienen caracteres con puntos de código mayores a 255, usando Unicode. Esto significa que tratar las cadenas de forma ingenua como "char *", un array de caracteres de 8 bits, puede llevar a problemas. Necesitas ser consciente de esto y considerar usar una biblioteca UTF-8 para tratar con cadenas.

Listas de argumentos variables

Problema

¿Cómo paso una lista de argumentos de tamaño variable a una función C de Inline?

Solución
greet(qw(Sarathy Jan Sparky Murray Mike));
use Inline C => <<'END_OF_C_CODE';
void greet(SV* name1, ...) {
  Inline_Stack_Vars;
  int i;
  for (i = 0; i < Inline_Stack_Items; i++)
    printf("Hello %s!\n", SvPV(Inline_Stack_Item(i), PL_na));
  Inline_Stack_Void;
}
END_OF_C_CODE
Discusión
Este pequeño programa saluda a un grupo de personas, como a mis compañeros de trabajo. Usamos la sintaxis de elipsis "C": ""..."", ya que la lista puede ser de cualquier tamaño.

Como no hay tipos ni nombres asociados con cada argumento, no podemos esperar que XS maneje las conversiones por nosotros. Tendremos que sacarlos de la Stack nosotros mismos. Afortunadamente, hay dos funciones (macros) que hacen de esta una tarea muy fácil.

Primero, necesitamos comenzar nuestra función con una declaración ""Inline_Stack_Vars"". Esto define algunas variables internas que necesitamos para acceder a la Stack. Ahora podemos usar ""Inline_Stack_Items"", que devuelve un entero que contiene el número de argumentos que se nos pasaron desde Perl.

NOTA: Es importante usar solo los macros ""Inline_Stack_"" cuando hay una elipsis ("...") en la lista de argumentos, o la función tiene un tipo de retorno void.

Segundo, usamos la función Inline_Stack_Item(x) para acceder a cada argumento donde "0 <= x < items".

NOTA: Cuando u

de una lista de argumentos de longitud variable, debe especificar al menos un argumento antes de las elipsis. (En mi compilador, de todos modos.) Cuando XS realiza la verificación de argumentos, se quejará si se pasan menos argumentos que el número de argumentos *definidos*. Por lo tanto, actualmente no hay forma de pasar una lista vacía cuando se espera una lista de longitud variable.

Múltiples valores de retorno

Problema
¿Cómo devuelvo una lista de valores de una función C?
Solución
print map {"$_\n"} get_localtime(time);
use Inline C => <<'END_OF_C_CODE';
#include <time.h>
void get_localtime(SV * utc) {
  const time_t utc_ = (time_t)SvIV(utc);
  struct tm *ltime = localtime(&utc_);
  Inline_Stack_Vars;
  Inline_Stack_Reset;
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_year)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_mon)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_mday)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_hour)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_min)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_sec)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_isdst)));
  Inline_Stack_Done;
}
END_OF_C_CODE
Discusión
Perl es un lenguaje donde es común devolver una lista de valores de una llamada a subrutina en lugar de un solo valor. C no es un lenguaje así. Para lograr esto en C, necesitamos manipular la pila de llamadas de Perl manualmente. Afortunadamente, Inline proporciona macros para facilitar esto.

Este ejemplo llama a la función del sistema "localtime" y devuelve cada una de las partes de la estructura de tiempo; muy similar a la función incorporada de Perl localtime(). En cada inserción en la pila, creamos un nuevo entero de Perl (SVIV) y lo hacemos mortal. La llamada sv_2mortal() se asegura de que el recuento de referencias se establezca correctamente. Sin ella, el programa tendría fugas de memoria.

NOTA: La instrucción "#include" no es realmente necesaria, porque Inline
incluye automáticamente las cabeceras de Perl que incluyen casi todas
las llamadas estándar del sistema.

Múltiples valores de retorno (Otra forma)

Problema
¿Cómo puedo devolver más de un valor sin usar la pila de Perl?
Solución
use Inline::Files;
use Inline 'C';
my ($foo, $bar);
change($foo, $bar);
print "\$foo = $foo\n";
print "\$bar = $bar\n";
__C__
int change(SV* var1, SV* var2) {
  sv_setpvn(var1, "Perl Rocks!", 11);
  sv_setpvn(var2, "Inline Rules!", 13);
  return 1;
}
Discusión
La mayoría de las interfaces de funciones de Perl devuelven valores como una lista de uno o más escalares. Muy pocas, como "chomp", modifican un escalar de entrada en el lugar. Por otro lado, en C esto se hace con bastante frecuencia. Los valores se pasan por referencia y son modificados en el lugar por la función llamada.

Resulta que también podemos hacer eso con Inline. El secreto es usar un tipo de '"SV*"' para cada argumento que se va a modificar. Esto asegura el paso por referencia, porque no se necesita mapeo de tipos.

La función puede entonces usar la API de Perl5 para operar sobre ese argumento. Cuando el control regresa a Perl, el argumento conservará el valor establecido por la función C. En este ejemplo, pasamos 2 escalares vacíos y les asignamos valores directamente.

Tomar una referencia a un array como argumento

Problema
¿Cómo puedo tomar una referencia a un array de Perl como argumento en mi función C?
Solución
SV *sum(SV *array) {
    int total = 0;
    int numelts, i;
    if ((!SvROK(array))
        || (SvTYPE(SvRV(array)) != SVt_PVAV)
        || ((numelts = av_len((AV *)SvRV(array))) < 0)
    ) {
        return &PL_sv_undef;
    }
    for (i = 0; i <= numelts; i++) {
        total += SvIV(*av_fetch((AV *)SvRV(array), i, 0));
    }
    return newSViv(total);
}
Discusión
Este ejemplo devuelve "undef" si se le da una referencia no válida, o una referencia no a un array, o una referencia a un array vacío. Puedes ver cómo podrías expandirlo para tomar más de una referencia a array.

Usando memoria

Problema
¿Cómo debo asignar buffers en mi código de Inline C?
Solución
print greeting('Ingy');
use Inline C => <<'END_OF_C_CODE';
SV* greeting(SV* sv_name) {
  return (newSVpvf("Hello %s!\n", SvPV(sv_name, PL_na)));
}
END_OF_C_CODE
Discusión
En este ejemplo, devolveremos el saludo al llamador, en lugar de imprimirlo. Esto parecería muy fácil, excepto por el hecho de que necesitamos asignar un pequeño buffer para crear el saludo.

Te insto a que te mantengas alejado de "malloc" tu propio buffer. Simplemente usa la gestión de memoria incorporada de Perl. En otras palabras, simplemente crea un nuevo escalar de cadena de Perl. La función "newSVpv" hace precisamente eso. Y "newSVpvf" incluye funcionalidad de "sprintf".

El otro problema es deshacerse de este nuevo escalar. ¿Cómo se reducirá el recuento de referencias después de que pasemos el escalar de vuelta? Perl también proporciona una función llamada "sv_2mortal". Las variables mortales mueren cuando el contexto sale del alcance. En otras palabras, Perl esperará hasta que el nuevo escalar se pase de vuelta y luego reducirá el recuento de referencias por ti, haciéndolo elegible para la recolección de basura. Ver "perldoc perlguts".

En este ejemplo, la llamada a "sv_2mortal" se realiza internamente por XS, porque declaramos el tipo de retorno como "SV*".

Para ver el código XS generado, ejecuta el comando ""perl -MInline=INFO,FORCE,NOCLEAN example004.pl"". Esto dejará intacto el directorio de compilación y te dirá dónde encontrarlo.

Acceso directo a variables de Perl

Problema
¿Puedo escribir una función de Inline C que pueda acceder a una variable de Perl directamente sin tener que pasarla como argumento?
Solución
use strict;
use warnings;
use Inline C => "DATA";
our $mesh_data = "MESH-POINTS 0.0 0.0 0.5 0.25 1.0 0.5 1.5 0.75";
CalcSurfaceHeights();
__DATA__
__C__
#define N_MP 4
void CalcSurfaceHeights() {
   double x[N_MP], y[N_MP], z;
   int    ix;
   char   *mesh_data = SvPV_nolen(get_sv("main::mesh_data", 0));
   sscanf(mesh_data, "MESH-POINTS %lf%lf%lf%lf%lf%lf%lf%lf",
                     x, y, x+1, y+1, x+2, y+2, x+3, y+3);
   for (ix=0; ix < N_MP; ix++) {
      z = 0.5*( sin(x[ix]) + sin(y[ix]) );
      printf("Surface-Height: %6.3f Mesh-Point: %6.2f, %6.2f\n",
             z, x[ix], y[ix]);
   }
}
Discusión
Solo hay dos puntos que necesitan una explicación para entender por qué el código anterior funciona. En la sección de Perl, notarás la declaración 
our $mesh_data = "...";

Para que las variables de Perl sean accesibles directamente desde las funciones de Inline::C , deben declararse como variables de paquete. Las variables léxicas, aquellas declaradas con my, no se pueden acceder de esta manera.

En la sección de código C del ejemplo, la siguiente línea es lo que hace que el acceso directo a la variable de Perl funcione;

char *mesh_data = SvPV_nolen(get_sv("main::mesh_data", 0))

Aquí SvPV_nolen() devuelve un puntero a la cadena C contenida en la variable escalar. La variación "_nolen" ignora la longitud de la cadena C. Por lo tanto, la función toma solo un único argumento, que es el SV* de la variable escalar.

Podríamos haber usado la forma habitual de dos argumentos de SvPV() y, dado que no nos importa la longitud de la cadena, especificar PL_na para el segundo argumento. La llamada a la función entonces cambiaría a,

SvPV(get_sv("main::mesh_data", 0), PL_na)

La función get_sv() devuelve el SV* de una variable de paquete escalar con nombre. Toma una cadena C, que contiene el nombre completamente calificado de la variable, como primer argumento.

. El segundo argumento contiene valores de bandera relacionados con el tipo de datos. Dado que solo estamos leyendo la variable escalar, en nuestro ejemplo, se puede usar un valor

de 0.

El problema con la ejecución de código Inline desde un script CGI es que Inline escribe en un área de compilación en su disco cada vez que compila código. La mayoría de los scripts CGI no pueden (y no deberían) crear un directorio y escribir en él.

De esa manera, el CGI solo necesitará acceso de lectura al directorio de compilación (para cargar la biblioteca compartida desde

allí).

package Soldier;
use Inline C => <<'END';
/*
Allocate memory with Newx if it's
available - if it's an older perl
that doesn't have Newx then we
resort to using New.
*/
#ifndef Newx
#  define Newx(v,n,t) New(0,v,n,t)
#endif
typedef struct {
  char* name;
  char* rank;
  long  serial;
} Soldier;
SV* new(const char * classname, const char * name,
        const char * rank, long serial) {
  Soldier * soldier;
  SV      * obj;
  SV      * obj_ref;
  Newx(soldier, 1, Soldier);
  soldier->name = savepv(name);
  soldier->rank = savepv(rank);
  soldier->serial = serial;
  obj = newSViv((IV)soldier);
  obj_ref = newRV_noinc(obj);
  sv_bless(obj_ref, gv_stashpv(classname, GV_ADD));
  SvREADONLY_on(obj);
  return obj_ref;
}
char* get_name(SV* obj) {
  return ((Soldier*)SvIV(SvRV(obj)))->name;
}
char* get_rank(SV* obj) {
  return ((Soldier*)SvIV(SvRV(obj)))->rank;
}
long get_serial(SV* obj) {
  return ((Soldier*)SvIV(SvRV(obj)))->serial;
}
void DESTROY(SV* obj) {
  Soldier* soldier = (Soldier*)SvIV(SvRV(obj));
  Safefree(soldier->name);
  Safefree(soldier->rank);
  Safefree(soldier);
}
END
Discusi
ón

Damian Conway nos ha dado innumerables formas de implementar OOP en Perl. Esta es una que él podría no haber

pensado.

Lo interesante de este ejemplo es que usa Perl para todos los enlaces OO mientras usa C para los atributos y

métodos.

Si examina el código de Perl, todo se ve exactamente como un ejemplo OO regular. Hay un método "new" y varios métodos de acceso. Se usa la familiar 'sintaxis de flecha' para

invocarlos.

En la definición de la clase (segunda parte), se usa la declaración de Perl "package" para nombrar la clase de objeto o espacio de nombres. Pero ahí es donde terminan las similitudes, Inline toma el

control.

La idea es que llamamos a una subrutina en C llamada new() que devuelve un escalar bendito. El escalar contiene un entero de solo lectura que es un puntero en C a una estructura Soldier. Este es nuestro

objeto.

La función new() necesita asignar la memoria con malloc para la estructura y luego copiar los valores iniciales en ella usando savepv(). Esto también asigna más memoria (de la que tenemos que hacer un seguimiento)

.

Los métodos de acceso son bastante sencillos. Devuelven el valor actual de su

atributo.

El último método DESTROY() es llamado automáticamente por Perl cada vez que un objeto sale del ámbito. Aquí es donde podemos liberar toda la memoria usada por el

objeto.

Eso es todo. Es un ejemplo muy simplista. No muestra ninguna característica OO avanzada, pero es bastante genial ver cuán fácil puede ser la implementación. La llamada importante en Perl es newSVrv() que crea un escalar

bendito.

Una de las preguntas más comunes que recibo es "¿Cómo puedo usar Inline para hacer uso de alguna biblioteca compartida?". Aunque siempre ha sido posible hacerlo, la configuración era fea, y no había ejemplos
