DESCRIPCIÓ

N

El módulo "Inline::Java" te permite poner código fuente de Java directamente "inline" en un script o módulo Perl. Se lanza un compilador de Java y el código Java se compila. Luego, Perl le pregunta a las clases Java qué métodos públicos han sido definidos. Estas clases y métodos están disponibles para el programa Perl como si hubieran sido escritos en

Perl.

El proceso de interrogar a las clases Java por sus métodos públicos ocur

re la primera vez que ejecutas tu código Java. El espacio de nombres se
almacena en caché, y las llamadas posteriores usan la versión en caché.

JDK

entre

USO DEL MÓDULO Inline::

Java

"Inline::Java" está impulsado por fundamentalmente la misma idea que otros módulos de lenguaje "Inline", como "Inline::C" o "Inline::CPP". Dado que Java es tanto compilado como interpretado, el método para obtener tu código es diferente, pero en general, usar "Inline::Java" es muy similar a cualquier otro módulo de lenguaje

"Inline".

Esta sección explicará las diferentes formas de "usar" Inline::Java. Para más detalles sobre "Inline", consulta 'perldoc

Inline'.

CLASES Y

OBJETOS

Debido a que Java es orientado a objetos, cualquier interfaz entre Perl y Java necesita soportar adecuadamente las clases de

Java.

Ejemplo

: 
use Inline Java => <<'END' ;
   class Pod_1 {
      String data = "data" ;
      static String sdata = "static data" ;
      public Pod_1(){
      }
      public String get_data(){
         return data ;
      }
      public static String get_static_data(){
         return sdata ;
      }
      public void set_data(String d){
         data = d ;
      }
      private void priv(){
      }
   }
END
my $obj = new Pod_1 ;
print($obj->get_data() . "\n") ; # imprime data
$obj->set_data("new data") ;
print($obj->get_data() . "\n") ; # imprime new
data

"Inline::Java" creó un nuevo espacio de nombres llamado "main::Pod_1" y creó las siguientes

funciones: 
sub main::Pod_::new { ... }
sub main::Pod_::Pod_1 { ... }
sub main::Pod_::get_data { ... }
sub main::Pod_::get_sdata { ... }
sub main::Pod_::set_data { ... }
sub main::Pod_::DESTROY { ...
}

Tenga en cuenta que solo los métodos públicos se exportan a

Perl.

Las clases internas también son soportadas, simplemente necesita proporcionar una referencia a un objeto de la clase externa como el primer parámetro del

constructor: 
use Inline Java => <<'END' ;
   class Pod_2 {
      public Pod_2(){
      }
      public class Pod_2_Inner {
public String name = "Pod_2_Inner" ; public Pod_2_Inner(){ } } } END my $obj
= new Pod_2() ; my $obj2 = new Pod_2::Pod_2_Inner($obj) ; print($obj2->{name} . "\n") ; # imprime Pod_2_Inner

EXCEPTIONS


Si Java lanza una excepción, la detectará Perl.


use Inline Java => <<'END' ;
   class Pod_9 {
      public Pod_9(){
         throw new Exception("An example exception") ;
      }
   }
END
eval {
   my $obj = new Pod_9() ;
};
if ($@) {
   print $@->getMessage() . "\n" ; # prints An example exception
   die $@ ;
}


Lo importante de entender es que $@ realmente contiene una
    referencia al objeto Throwable que fue lanzado por Java. La
    función getMessage() es en realidad un método de la clase java.lang.Exception.
    Así que si Java está lanzando una excepción personalizada que tienes en tu
    código, tendrás acceso a los métodos públicos de ese objeto de excepción como
    cualquier otro objeto Java en "Inline::Java".
    Nota: "Inline::Java" usa eval internamente,
    por lo que se recomienda almacenar cualquier excepción en una variable temporal
    antes de procesarla, especialmente si vas a llamar a otras funciones de
    "Inline::Java". También es probablemente una
    buena idea hacer undef $@ una vez que hayas tratado una excepción Java, o
    de lo contrario, el objeto todavía tendrá una referencia hasta que $@ sea
    restablecido por el próximo eval.






FILEHANDLES


Los filehandles de Java (objetos java.io.Reader, java.io.Writer,
    java.io.InputStream o java.io.OutputStream) pueden ser envueltos por la
    clase "Inline::Java::Handle" para permitir
    la lectura o escritura desde Perl. Aquí tienes un ejemplo:


use Inline Java => <<'END' ;
   import java.io.* ;
   class Pod_91 {
      public static Reader getReader(String file) throws FileNotFoundException {
        return new FileReader(file) ;
      }
   }
END
 my $o = Pod_91->getReader('t/t13.txt') ;
 my $h = Inline::Java::Handle->new($o) ;
 # lee una línea
 my $text = <$h>;
 chomp $text;
 print($text . "\n") ; # imprime 1


Lo importante de entender es que el objeto
    "Inline::Java::Handle" devuelto contiene
    realmente una referencia al lector o escritor de Java. Probablemente sea una
    buena idea hacer undef esto una vez que hayas completado las operaciones de
    I/O para que el objeto subyacente de Java pueda ser liberado.

ESTUDIANDO


A partir de la versión 0.21, "Inline::Java"
    puede aprender sobre otras clases de Java y usarlas como el código Java que
    escribes dentro de tu script de Perl. De hecho, ya ni siquiera es necesario
    escribir código Java dentro de tu script de Perl. Así es como se usa la
    función 'study':


use Inline (
   Java => 'study',
   study => ['java.util.HashMap'],
   autostudy => 1,
) ;
my $hm = new java::util::HashMap() ;
$hm->put("key", "value") ;
my $val = $hm->get("key") ;
print($val . "\n") ; # imprime value


Si no deseas incluir ningún código Java dentro de tu script de
    Perl, debes usar la cadena 'study' como tu código. Esto omitirá la sección
    de compilación.


También puedes usar la opción autostudy para indicarle a
    "Inline::Java" que deseas estudiar todas
    las clases que encuentre:


use Inline Java => <<'END', autostudy => 1 ;
   import java.util.* ;
   class Pod_10 {
      public Pod_10(){
      }
      public HashMap get_hm(){
         HashMap hm = new HashMap() ;
         return hm ;
      }
   }
END
my $obj = new Pod_10() ;
my $hm = $obj->get_hm() ;
$hm->put("key", "value") ;
my $val = $hm->get("key") ;
print($val . "\n") ; # imprime value


En este caso, "Inline::Java"
    intercepta el valor de retorno del método get_hm(), ve que es de un
    tipo que no conoce (java.lang.HashMap), y estudia inmediatamente la clase.
    Después de esa llamada, la clase java.lang.HashMap está disponible para ser
    usada a través de Perl.


En algunos casos, puede que no sepas qué clases estudiar hasta el
    tiempo de ejecución. En estos casos, puedes usar la función
    study_classes():


use Inline (
   Java => 'study',
   study => [],
) ;
use Inline::Java qw(study_classes) ;
study_classes(['java.util.HashMap'], undef) ;
my $hm = new java::util::HashMap() ;
$hm->put("key", "value") ;
my $val = $hm->get("key") ;
print($val . "\n") ; # imprime value


La función study_classes() toma 2 argumentos, una referencia
    a un array de nombres de clase (como la opción de configuración STUDY) y el
    nombre del paquete en el que vincular esas clases. Si el nombre del paquete
    es indefinido, las clases se vincularán al paquete actual (llamador).


Nota: Solo puedes especificar los nombres de los paquetes en los
    que previamente has "usado"
    "Inline::Java".






TYPE   CASTING


A veces necesitas manipular un objeto Java usando un subtipo
    específico. Ahí es cuando el type casting es necesario. Aquí tienes un ejemplo
    de esto:


use Inline (
   Java => 'study',
   study => ['java.util.HashMap'],
   autostudy => 1,
) ;
use Inline::Java qw(cast) ;
my $hm = new java::util::HashMap() ;
$hm->put('key', 'value') ;
my $entries = $hm->entrySet()->toArray() ;
foreach my $e (@{$entries}){
  # print($e->getKey() . "\n") ; # No!
  print(cast('java.util.Map$Entry', $e)->getKey() . "\n") ; # imprime key
}


En este caso, "Inline::Java"
    sabe que $e es de tipo java.util.HashMap$Entry. El
    problema es que este tipo no es público, y por lo tanto no podemos acceder
    al objeto a través de ese tipo. Debemos hacerle un cast a java.util.Map$Entry,
    que es una interfaz pública y nos permitirá acceder al método
    getKey().


También puedes usar type casting para forzar la selección de una
    firma de método específica para métodos que tienen múltiples firmas. Vea
    ejemplos similares a este en la sección "TYPE COERCING" a
    continuación.






TYPE   COERCING


Type coercing es el equivalente de casting para tipos primitivos y
    arrays. Se utiliza para forzar la selección de una firma de método específica
    cuando "Inline::Java" tiene múltiples
    opciones. La función coerce devuelve un objeto especial que solo puede ser
    utilizado al llamar a métodos de Java o al asignar miembros de Java. Aquí hay
    un ejemplo:


use Inline Java => <<'END' ;
   class Pod_101 {
      public Pod_101(){
      }
      public String f(int i){
         return "int" ;
      }
      public String f(char c){
         return "char" ;
      }
   }
END
my $obj = new Pod_101() ;
print($obj->f('5') . "\n") ; # imprime int


En este caso, "Inline::Java"
    llamará a f(int i), porque '5' es un entero. Pero '5' también es un char
    válido. Así que para forzar la llamada a f(char c), haz lo siguiente:


use Inline::Java qw(coerce) ;
$obj->f(coerce('char', '5')) ;
# o
$obj->f(Inline::Java::coerce('char', '5')) ;


La función coerce fuerza la selección de la firma coincidente.
    Ten en cuenta que la coerción debe coincidir exactamente con el tipo del
    argumento. Coercionar a una clase que extiende el tipo del argumento no
    funcionará.


Otro caso en el que se necesita type coercing es cuando se desea
    pasar un array como un java.lang.Object:


use Inline Java => <<'END';
   class Pod_8 {
      public Object o ;
      int a[] = {1, 2, 3} ;
      public Pod_8() {
      }
   }
END
my $obj = new Pod_8() ;
$obj->{o} = [1, 2, 3] ;      # ¡No!


La razón por la que esto no funcionará es simple. Cuando
    "Inline::Java" ve un array, verifica el
    tipo de Java al que intentas igualarlo para validar la construcción de tu
    lista de Perl. Pero en este caso, no puede validar el array porque lo estás
    asignando a un Object. Debes usar la versión de tres parámetros de la función
    coerce para hacer esto:


$obj->{o} = Inline::Java::coerce(
  "java.lang.Object",
  [1, 2, 3],
  "[Ljava.lang.String;") ;


Esto le dice a "Inline::Java"
    que valide tu lista de Perl como un String [], y luego lo coercione como un
    Object.


Así es como se construyen las representaciones de tipos de array:


[<tipo>  -> array de 1 dimensión de <tipo>
[[<tipo> -> array de 2 dimensiones de <tipo>
...
donde <tipo> es uno de:
  B byte     S short     I int     J long
  F float    D double    C char    Z boolean
  L<clase>; array de objetos de <clase>


Esto se describe con más detalle en la mayoría de los libros de Java
    que hablan sobre reflexión.


Pero solo necesitas hacer esto si tienes una lista de Perl. Si ya
    tienes una referencia a un array de Java obtenida de otro lugar, ni siquiera
    necesitas hacer coerce:


$obj->{o} = $obj->{a} ;






MODOS JNI vs CLIENTE/SERVIDOR


A partir de la versión 0.20, es posible usar la extensión JNI (Java
    Native Interface). Esto permite a "Inline::Java"
    cargar la máquina virtual de Java como un objeto compartido en lugar de
    ejecutarla como un servidor independiente. Esto aporta una mejora en el
    rendimiento.


Si has compilado la extensión JNI, debes habilitarla explícitamente
    haciendo una de las siguientes cosas:



  
1.

  
Establecer la opción de configuración JNI a 1

  
2.

  
Establecer la variable de entorno PERL_INLINE_JAVA_JNI a 1




Nota: "Inline::Java" solo crea
    una instancia de máquina virtual. Por lo tanto, no puedes usar JNI para
    algunas secciones y cliente/servidor para otras. La primera sección determina
    el modo de ejecución.


Consulta README.JNI para más información sobre la extensión JNI.






JVM COMPARTIDA


A partir de la versión 0.30, la JVM de
    "Inline::Java" ahora puede ser compartida
    entre múltiples procesos. El primer proceso que inicia crea la JVM pero no
    la cierra al salir. Todos los demás procesos pueden conectarse según sea
    necesario a la JVM. Si alguno de estos otros procesos fue creado por fork del
    proceso padre, la función Inline::Java->reconnect_JVM() debe ser
    llamada en el hijo para obtener una conexión nueva a la JVM. Ej:


use Inline (
   Java => <<'END',
      class Pod_11 {
         public static int i = 0 ;
         public Pod_11(){
            i++ ;
         }
      }
END
   shared_jvm => 1,
) ;
my $nb = 5 ;
for (my $i = 0 ; $i < $nb ; $i++){
   if (! fork()){
      Inline::Java::reconnect_JVM() ;
      my $f = new Pod_11() ;
      exit ;
   }
}
sleep(5) ;
my $f = new Pod_11() ;
print($f->{i} . "\n") ; # imprime 6


Una vez ejecutado este código, cada uno de los 6 procesos habrá
    creado una instancia diferente de la clase 't'. Los datos se pueden



compartido entre los procesos utilizando miembros estáticos en el código 
Java.

Nota: El flujo System.
out de Java se cierra
en el modo SHARED_JVM.

USANDO Inline::Java EN UN

CGI

Si desea usar "Inline::Java" en un script CGI, haga lo

siguiente: 
use CGI ;
use Inline (
   Java => <<'END',
      class Pod_counter {
         public static int cnt = 0 ;
         public Pod_counter(){
            cnt++ ;
         }
      }
END
   shared_jvm => 1,
   directory => '/somewhere/your/web/server/can/write',
) ;
my $c = new Pod_counter() ;
my $q = new CGI() ;
print
   $q->start_html() .
   "This page has been accessed " . $c->{cnt} . " times." .
   $q->end_html()
;

En este escenario, el primer CGI en ejecutarse iniciará la JVM, pero no la apagará al salir. Los CGI posteriores, dado que tienen la opción shared_jvm habilitada, intentarán conectarse a la JVM ya existente antes de intentar iniciar una nueva. Por lo tanto, si la JVM se bloquea o es terminada, el siguiente CGI que se ejecute iniciará una nueva. La JVM será terminada cuando Apache se

apague.

Consulte la sección DE ERRORES Y DEFIC

IENCIAS si tiene problemas al ini
ciar el servidor shared_jvm en un CGI.

Precarga y PerlChildInitHandle

r

Si está cargando "Inline::Java" durante el inicio de su servidor (una práctica común para aumentar la memoria compartida y reducir el tiempo de ejecución) y está usando "shared_jvm", entonces sus procesos de Apache compartirán todos la misma conexión de socket con esa JVM. Esto resultará en una comunicación distorsionada y errores extraños (como "Can't receive packet from JVM", "Broken pipe", etc)

.

Para solucionar esto, necesita decirle a Apache que después de que cada proceso hijo haya hecho fork, cada uno necesita crear sus propias conexiones a la JVM. Esto se hace durante la etapa "Child

Init".

Para Apache 1.3.x esto podría verse

así: 
# en httpd.conf
PerlChildInitHandler MyProject::
JavaReconnect

Y "MyProject::JavaReconnect" podría ser tan simple como

esto: 
package MyProject::Jav
aReconnect; sub handl
er($$) { Inline::Java
::reconnect_JVM() } 1;

ERRORES Y

DEFICIENCIAS

Al informar un error, por favor haga lo

siguiente: 
- Ponga "use Inline REPORTBUG;" en la parte superior de su código, o
  use la opción de línea de comando "perl -MInline=REPORTBUG ...".
- Ejecute su código.
- Siga las instrucciones
impresas.

Aquí hay algunas cosas a tener en

cuenta:
1
.
No debería nombrar ninguna de sus clases 'B', 'S', 'I', 'J', 'F', 'D', 'C', 'Z' o 'L'. Estas clases parecen ser usadas internamente por Java para representar los tipos
primitivos.
2
.
Si actualiza "Inline::Java" desde una versión anterior, asegúrese de borrar su directorio _Inline para que las clases Java propias de "Inline::Java" sean reconstruidas para coincidir con el código
Perl.
3
.
Bajo ciertos entornos, es decir, CGI o mod_perl, la JVM no puede iniciar correctamente debido a la forma en que estos entornos configuran STDIN y STDOUT. En estos casos, es posible que desee controlar la JVM (en modo compartido) manualmente usando los siguientes comandos: 
% perl -MInline::Java::Server=status
% perl -MInline::Java::Server=start
% perl -MInline::Java::Server=stop
% perl -MInline::Java::
Server=restart

Puede especificar opciones de "Inline::Java" configurando las variables de entorno adecuadas, y también puede configurar el directorio _Inline usando la variable de entorno PERL_INLINE_JAVA_DIREC

TORY.

Además, es posible que también desee configurar la opción start_j

vm a 0 en sus scripts para evitar que intenten iniciar su
propia JVM si no encuentran una, causando así problemas.
4
.
Debido a problemas con los módulos de los que "Inline::Java" depende, el uso de rutas que contienen espacios no está completamente soportado en todas las plataformas. Esto aplica al directorio de instalación así como a la ruta para J2SDK y los elementos de
CLASSPATH.
5
.
Aunque se ejecuta regularmente a través de un perfilador, "Inline::Java" es relativamente l
ento en com
paración con Per
l o Java nativos.
