NOMBRE

IO::WrapTie - envolver objetos encadenables en la interfaz IO::Handle

Este es actualmente código Alpha, liberado para comentarios.
¡Por favor, dadme vuestra opinión!

SINOPSIS

Primero de todo, necesitaréis tie(), así que:

require 5.004;

Interfaz de función (experimental). Usad esto con cualquier clase existente...

use IO::WrapTie;
use FooHandle;                  ### implementa la interfaz TIEHANDLE
### Supongamos que queremos un "FooHandle->new(&FOO_RDWR, 2)".
### Podemos decir en su lugar...
$FH = wraptie('FooHandle', &FOO_RDWR, 2);
### Ahora podemos usar...
print $FH "Hola, ";            ### sintaxis de operador tradicional...
$FH->print("mundo!\n");         ### ...¡y también sintaxis OO!

Interfaz OO (preferida). Podéis heredar del "Slave" en el mixin de IO::WrapTie para obtener un constructor new_tie() ingenioso...

#------------------------------
package FooHandle;                        ### una clase que puede TIEHANDLE
use IO::WrapTie;
@ISA = qw(IO::WrapTie::Slave);            ### hereda new_tie()
...
#------------------------------
package main;
$FH = FooHandle->new_tie(&FOO_RDWR, 2);   ### $FH es un IO::WrapTie::Master
print $FH "Hola, ";                      ### sintaxis de operador tradicional
$FH->print("mundo!\n");                   ### sintaxis OO

Ver IO::Scalar como ejemplo. También os muestra cómo crear clases que funcionan tanto con como sin 5.004.

DESCRIPCIÓN

Supongamos que tenéis una clase "FooHandle", donde...

  • "FooHandle" no hereda de IO::Handle. Es decir, realiza E/S similar a la de un manejador de archivo, pero a algo que no es un descriptor de archivo subyacente. Buenos ejemplos son IO::Scalar (para imprimir a una cadena) e IO::Lines (para imprimir a un array de líneas).
  • "FooHandle" implementa la interfaz "TIEHANDLE" (ver perltie). Es decir, proporciona métodos "TIEHANDLE", "GETC", "PRINT", "PRINTF", "READ" y "READLINE".
  • "FooHandle" implementa la interfaz OO tradicional de FileHandle e IO::Handle. Es decir, contiene métodos como "getline", "read", "print", "seek", "tell", "eof", etc.

Normalmente, los usuarios de vuestra clase tendrían dos opciones:

  • Usar solo sintaxis OO, y renunciar a operadores de E/S con nombre como "print".
  • Usar con tie, y renunciar a tratarla como un objeto de primera clase (es decir, los métodos específicos de la clase solo se pueden invocar a través del objeto subyacente mediante "tied"... dando al objeto una "personalidad dividida").

Pero ahora con IO::WrapTie, podéis decir:

$WT = wraptie('FooHandle', &FOO_RDWR, 2);
$WT->print("Hola, mundo\n");   ### Sintaxis OO
print $WT "¡Sí!\n";             ### ¡También sintaxis de operador con nombre!
$WT->weird_stuff;               ### ¡Otros métodos!

Y si estáis creando una clase como "FooHandle", simplemente haced que herede de "IO::WrapTie::Slave" y esa primera línea será aún más bonita:

$WT = FooHandle->new_tie(&FOO_RDWR, 2);

En resumen: ahora, casi cualquier clase puede parecer y funcionar exactamente como un IO::Handle y usarse tanto con sintaxis de manejador de archivo OO como no OO.

Las estructuras de datos

Considerad este código de ejemplo, usando clases de esta distribución:

use IO::Scalar;
use IO::WrapTie;
$WT = wraptie('IO::Scalar',\$s);
print $WT "Hola, ";
$WT->print("mundo!\n");

En él, la función "wraptie" crea una estructura de datos como sigue:

                      * $WT es una referencia bendecida a un manejador de archivo encadenado
          $WT           glob; ese glob está encadenado al objeto "Slave".
           |          * Deberíais hacer toda vuestra E/S con $WT directamente.
           |
           |
           |     ,---isa--> IO::WrapTie::Master >--isa--> IO::Handle
           V    /
    .-------------.
    |             |
    |             |   * Los operadores de E/S de Perl funcionan en el objeto encadenado,
    |  "Master"   |     invocando los métodos TIEHANDLE.
    |             |   * Las invocaciones de métodos se delegan al slave encadenado.
    `-------------'
           |
tied(*$WT) |     .---isa--> IO::WrapTie::Slave
           V    /
    .-------------.
    |             |
    |   "Slave"   |   * Instancia de una clase similar a FileHandle que en realidad no
    |             |     usa descriptores de archivo, como IO::Scalar.
    |  IO::Scalar |   * El slave puede ser cualquier tipo de objeto.
    |             |   * Debe implementar la interfaz TIEHANDLE.
    `-------------'

NOTA: así como un IO::Handle es realmente solo una referencia tradicional de manejador de archivo glob bendecida. También, un "IO::WrapTie::Master" es realmente solo una referencia bendecida a un manejador de archivo glob que ha sido encadenado a alguna clase "esclava".

Cómo funciona "wraptie"

1.
La llamada a la función "wraptie(CLASE_ESCLAVA, ARG_TIE...)" se pasa a IO::WrapTie::Master::new(). Tened en cuenta que la clase "IO::WrapTie::Master" es una subclase de IO::Handle.
2.
El método "IO::WrapTie::Master->new" crea un nuevo objeto IO::Handle, rebautizado a la clase "IO::WrapTie::Master". Este objeto es el maestro, que será devuelto desde el constructor. Al mismo tiempo...
3.
El método "new" también crea el esclavo: esta es una instancia de "CLASE_ESCLAVA" que se crea encadenando el IO::Handle del maestro a "CLASE_ESCLAVA" mediante "tie". Esta llamada a "tie" crea el esclavo de la siguiente manera:
4.
La clase "CLASE_ESCLAVA" recibe el mensaje "TIEHANDLE"; normalmente delegará esto a "CLASE_ESCLAVA->new(ARG_TIE)", resultando en una nueva instancia de "CLASE_ESCLAVA" creada y devuelta.
5.
Una vez creados tanto el maestro como el esclavo, el maestro se devuelve al llamador.

Cómo funcionan los operadores de E/S (en el maestro)

Considerad el uso de un operador de E/S en el maestro:

print $WT "Hola, mundo!\n";

Dado que el maestro $WT es realmente una referencia "bendecida" a un glob de manejador de archivo, los operadores de E/S normales de Perl como "print" pueden ser usados en él. Simplemente operarán en la parte del símbolo del glob.

Dado que el glob está encadenado al esclavo, el método "PRINT" del esclavo (parte de la interfaz "TIEHANDLE") será invocado automáticamente.

Si el esclavo es un IO::Scalar, eso significa que se invocará el "PRINT" en IO::Scalar, y ese método casualmente delega al método "print" de la misma clase. Así que el verdadero trabajo lo hace en última instancia el "print" en IO::Scalar.

Porque (1) tienes que usar "tied" para invocar métodos en la interfaz pública del objeto (puaj), y (2) es posible que necesites pasar el símbolo atado a otra subrutina que intente tratarlo de manera OO... ¡y eso lo

romperá!
