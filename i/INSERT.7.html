NOMBRE

INSERT - crear nuevas filas en una tabla

SINOPSIS

[ WITH [ RECURSIVE ] consulta_with [, ...] ]
INSERT INTO nombre_tabla [ AS alias ] [ ( nombre_columna [, ...] ) ]
    [ OVERRIDING { SYSTEM | USER } VALUE ]
    { DEFAULT VALUES | VALUES ( { expresión | DEFAULT } [, ...] ) [, ...] | consulta }
    [ ON CONFLICT [ objetivo_conflicto ] accion_conflicto ]
    [ RETURNING [ WITH ( { OLD | NEW } AS alias_salida [, ...] ) ]
                { * | expresión_salida [ [ AS ] nombre_salida ] } [, ...] ]
donde objetivo_conflicto puede ser uno de:
    ( { nombre_columna_indice | ( expresión_indice ) } [ COLLATE collation ] [ opclass ] [, ...] ) [ WHERE predicado_indice ]
    ON CONSTRAINT nombre_restricción
y accion_conflicto es uno de:
    DO NOTHING
    DO UPDATE SET { nombre_columna = { expresión | DEFAULT } |
                    ( nombre_columna [, ...] ) = [ ROW ] ( { expresión | DEFAULT } [, ...] ) |
                    ( nombre_columna [, ...] ) = ( subconsulta )
                  } [, ...]
              [ WHERE condición ]

DESCRIPCIÓN

INSERT inserta nuevas filas en una tabla. Se pueden insertar una o más filas especificadas por expresiones de valor, o cero o más filas resultantes de una consulta.

Los nombres de las columnas de destino se pueden enumerar en cualquier orden. Si no se proporciona ninguna lista de nombres de columna, el valor por defecto son todas las columnas de la tabla en su orden declarado; o los primeros N nombres de columna, si solo hay N columnas suministradas por la cláusula VALUES o por la consulta. Los valores suministrados por la cláusula VALUES o por la consulta se asocian con la lista de columnas explícita o implícita de izquierda a derecha.

Cada columna no presente en la lista de columnas explícita o implícita se rellenará con un valor predeterminado, ya sea su valor predeterminado declarado o NULL si no hay ninguno.

Si la expresión para cualquier columna no es del tipo de dato correcto, se intentará una conversión automática de tipo.

La inserción en tablas que carecen de índices únicos no se bloqueará por actividad concurrente. Las tablas con índices únicos podrían bloquearse si sesiones concurrentes realizan acciones que bloquean o modifican filas que coinciden con los valores del índice único que se están insertando; los detalles se cubren en la Sección 63.5. ON CONFLICT se puede usar para especificar una acción alternativa a la de generar un error de violación de restricción única o de exclusión. (Ver la Cláusula ON CONFLICT a continuación.)

La cláusula RETURNING opcional hace que INSERT calcule y devuelva valor(es) basados en cada fila realmente insertada (o actualizada, si se usó una cláusula ON CONFLICT DO UPDATE). Esto es principalmente útil para obtener valores que fueron suministrados por defecto, como un número de serie secuencial. Sin embargo, cualquier expresión que use las columnas de la tabla está permitida. La sintaxis de la lista RETURNING es idéntica a la de la lista de salida de SELECT. Solo se devolverán las filas que se insertaron o actualizaron correctamente. Por ejemplo, si una fila se bloqueó pero no se actualizó porque una cláusula condición de ON CONFLICT DO UPDATE ... WHERE no se cumplió, la fila no se devolverá.

Debes tener el privilegio INSERT en una tabla para poder insertar en ella. Si está presente ON CONFLICT DO UPDATE, también se requiere el privilegio UPDATE en la tabla.

Si se especifica una lista de columnas, solo necesitas el privilegio INSERT en las columnas listadas. De manera similar, cuando se especifica ON CONFLICT DO UPDATE, solo necesitas el privilegio UPDATE en las columnas listadas para ser actualizadas. Sin embargo, ON CONFLICT DO UPDATE también requiere el privilegio SELECT en cualquier columna cuyos valores se lean en las expresiones ON CONFLICT DO UPDATE o en la condición.

El uso de la cláusula RETURNING requiere el privilegio SELECT en todas las columnas mencionadas en RETURNING. Si usas la cláusula consulta para insertar filas desde una consulta, por supuesto, debes tener el privilegio SELECT en cualquier tabla o columna utilizada en la consulta.

PARÁMETROS

Insertar

Esta sección cubre los parámetros que se pueden usar cuando solo se insertan nuevas filas. Los parámetros utilizados exclusivamente con la cláusula ON CONFLICT se describen por separado.

consulta_with

La cláusula WITH permite especificar una o más subconsultas que pueden ser referenciadas por nombre en la consulta INSERT. Consulte la Sección 7.8 y SELECT(7) para más detalles.

Es posible que la consulta (declaración SELECT) también contenga una cláusula WITH. En tal caso, ambos conjuntos de consulta_with pueden ser referenciados dentro de la consulta, pero el segundo tiene precedencia ya que está anidado más cercanamente.

nombre_tabla

El nombre (opcionalmente calificado con esquema) de una tabla existente.

alias

Un nombre sustituto para nombre_tabla. Cuando se proporciona un alias, oculta completamente el nombre real de la tabla. Esto es particularmente útil cuando ON CONFLICT DO UPDATE apunta a una tabla llamada excluded, ya que de lo contrario se tomaría como el nombre de la tabla especial que representa la fila propuesta para la inserción.

nombre_columna

El nombre de una columna en la tabla denominada por nombre_tabla. El nombre de la columna puede calificarse con un nombre de subcampo o un subíndice de arreglo, si es necesario. (Insertar solo en algunos campos de una columna compuesta deja los otros campos como NULL). Al hacer referencia a una columna con ON CONFLICT DO UPDATE, no incluyas el nombre de la tabla en la especificación de una columna de destino. Por ejemplo, INSERT INTO nombre_tabla ... ON CONFLICT DO UPDATE SET nombre_tabla.col = 1 es inválido (esto sigue el comportamiento general de UPDATE).

OVERRIDING SYSTEM VALUE

Si se especifica esta cláusula, cualquier valor suministrado para las columnas de identidad anulará los valores generados por secuencia por defecto.

Para una columna de identidad definida como GENERATED ALWAYS, es un error insertar un valor explícito (que no sea DEFAULT) sin especificar OVERRIDING SYSTEM VALUE u OVERRIDING USER VALUE. (Para una columna de identidad definida como GENERATED BY DEFAULT, OVERRIDING SYSTEM VALUE es el comportamiento normal y especificarlo no hace nada, pero PostgreSQL lo permite como una extensión).

OVERRIDING USER VALUE

Si se especifica esta cláusula, cualquier valor suministrado para las columnas de identidad se ignora y se aplican los valores generados por secuencia por defecto.

Esta cláusula es útil, por ejemplo, al copiar valores entre tablas. Escribir INSERT INTO tbl2 OVERRIDING USER VALUE SELECT * FROM tbl1 copiará de tbl1 todas las columnas que no sean columnas de identidad en tbl2, mientras que los valores para las columnas de identidad en tbl2 serán generados por las secuencias asociadas a tbl2.

DEFAULT VALUES

Todas las columnas se rellenarán con sus valores predeterminados, como si DEFAULT se hubiera especificado explícitamente para cada columna. (No se permite una cláusula OVERRIDING en esta forma).

expresión

Una expresión o valor a asignar a la columna correspondiente.

DEFAULT

La columna correspondiente se rellenará con su valor predeterminado. Una columna de identidad se rellenará con un nuevo valor generado por la secuencia asociada. Para una columna generada, especificar esto está permitido pero simplemente especifica el comportamiento normal de calcular la columna a partir de su expresión de generación.

consulta

Una consulta (declaración SELECT) que suministra las filas a insertar. Consulte la declaración SELECT(7) para una descripción de la sintaxis.

alias_salida

Un nombre sustituto opcional para las filas OLD o NEW en la lista RETURNING.

Por defecto, los valores antiguos de la tabla de destino se pueden devolver escribiendo OLD.nombre_columna o OLD.*, y los valores nuevos se pueden devolver escribiendo NEW.nombre_columna o NEW.*. Cuando se proporciona un alias, estos nombres se ocultan y las filas antiguas o nuevas deben referenciarse usando el alias. Por ejemplo, RETURNING WITH (OLD AS o, NEW AS n) o.*, n.*.

expresión_salida

Una expresión que se calculará y devolverá por el comando INSERT después de que cada fila sea insertada o actualizada. La expresión puede usar cualquier nombre de columna de la tabla denominada por nombre_tabla. Escriba * para devolver todas las columnas de las filas insertadas o actualizadas.

COMPATIBILIDAD

INSERT cumple con el estándar SQL, excepto que la cláusula RETURNING es una extensión de PostgreSQL, al igual que la capacidad de usar WITH con INSERT, y la capacidad de especificar una acción alternativa con ON CONFLICT. Además, el estándar prohíbe el caso en el que se omite una lista de nombres de columna, pero no todas las columnas se rellenan desde la cláusula VALUES o la consulta. Si prefiere una sentencia más conforme al estándar SQL que ON CONFLICT, consulte MERGE(7).

El estándar SQL especifica que OVERRIDING SYSTEM VALUE solo puede especificarse si existe una columna de identidad que se genera siempre. PostgreSQL permite la cláusula en cualquier caso y la ignora si no es aplicable.

Las posibles limitaciones de la cláusula query se documentan en SELECT(7).
