IPC::Open2(3perl) Guía de referencia para programadores de Perl IPC::Open2(3perl)

NOMBRE

IPC::Open2 - abre un proceso para lectura y escritura usando open2()

SINOPSIS

use IPC::Open2;
my $pid = open2(my $chld_out, my $chld_in,
  'some', 'cmd', 'and', 'args');
# o pasando el comando a través del shell
my $pid = open2(my $chld_out, my $chld_in, 'some cmd and args');
# leer de la entrada estándar del padre y escribir a un manejador ya abierto
open my $outfile, '>', 'outfile.txt' or die "open failed: $!";
my $pid = open2(['&', $outfile], ['&', *STDIN],
  'some', 'cmd', 'and', 'args');
# leer de un manejador ya abierto y escribir a la salida estándar del padre
open my $infile, '<', 'infile.txt' or die "open failed: $!";
my $pid = open2(['&', *STDOUT], ['&', $infile],
  'some', 'cmd', 'and', 'args');
# recolectar zombie y obtener el estado de salida
waitpid( $pid, 0 );
my $child_exit_status = $? >> 8;

DESCRIPCIÓN

La función open2() ejecuta el comando dado y conecta $chld_out para leer y $chld_in para escribir. Es lo que crees que debería funcionar cuando intentas

my $pid = open(my $fh, "|cmd args|");  # ERROR

pero tienes que escribirlo así:

my $pid = open2($chld_out, $chld_in, @command_and_args);

El manejador de archivo $chld_in tendrá autoflush activado.

Por defecto, los manejadores de archivo que pasas se usan como parámetros de salida. "open2" crea internamente dos tuberías. El extremo de escritura de la primera tubería y el extremo de lectura de la segunda tubería se conectan a la salida estándar y entrada estándar del comando, respectivamente. Los extremos correspondientes de lectura y escritura se colocan en el primer y segundo argumento de "open2".

Los argumentos del manejador de archivo pueden tomar las siguientes formas:

  • Una variable no inicializada (técnicamente, "undef" o la cadena vacía funcionarán): "open2" genera un nuevo manejador de archivo y lo asigna al argumento, que debe ser una variable modificable para que esto funcione (de lo contrario, se generará una excepción).
  • Un manejador existente en forma de typeglob como *STDIN o *FOO o una referencia a uno: "open2" coloca el manejador de archivo en la ranura "IO" del typeglob, lo que significa que el manejador de archivo bareword correspondiente (como "STDIN" o "FOO") se puede usar para E/S desde/hacia el proceso hijo. (Si el manejador ya está abierto, se cierra automáticamente primero).
  • Una cadena que contiene el nombre de un manejador bareword (como 'STDIN' o 'FOO'): Dichas cadenas se resuelven a typeglobs en tiempo de ejecución y luego actúan como en el caso descrito anteriormente.

Sin embargo, es posible hacer que "open2" use un manejador existente directamente (como argumento de entrada) y omitir la creación de una tubería. Para hacer esto, el argumento del manejador de archivo debe tener una de las siguientes dos formas:

  • Una referencia a un array como "['&', $fh]", es decir, el primer elemento es la cadena '&' y el segundo elemento es el manejador existente a usar en el proceso hijo.
  • Una cadena de la forma '<&FOO' o '>&FOO', es decir, una cadena que comienza con los dos caracteres "<&" (para entrada) o ">&" (para salida), seguido por el nombre de un manejador de archivo bareword. (La forma de cadena no se puede usar con manejadores almacenados en variables).

Si utiliza esta forma para $chld_in, el manejador de archivo se cerrará en el proceso padre.

"open2" devuelve el ID de proceso del proceso hijo. No devuelve nada en caso de fallo: simplemente genera una excepción que coincide con "/^open2:/". Sin embargo, los fallos de "exec" en el hijo no se detectan. Tendrás que atrapar SIGPIPE tú mismo.

"open2" no espera ni recolecta el proceso hijo después de que sale. Excepto en programas cortos donde es aceptable dejar que el sistema operativo se encargue de esto, necesitas hacerlo tú mismo. Normalmente, esto es tan simple como llamar a "waitpid $pid, 0" cuando hayas terminado con el proceso. No hacer esto puede resultar en una acumulación de procesos difuntos o "zombies". Consulta "waitpid" en perlfunc para obtener más información.

Todo este asunto es bastante peligroso, ya que puedes bloquearte para siempre. Asume que va a hablar con algo como bc(1), tanto escribiendo en él como leyendo de él. Esto es presumiblemente seguro porque "sabes" que comandos como bc(1) leerán línea por línea y producirán salida línea por línea. Sin embargo, programas como sort(1) que leen todo su flujo de entrada primero, son bastante propensos a causar interbloqueo.

El gran problema con este enfoque es que si no tienes control sobre el código fuente que se ejecuta en el proceso hijo, no puedes controlar qué hace con el almacenamiento en búfer de la tubería. Por lo tanto, no puedes simplemente abrir una tubería a "cat -v" y leer y escribir continuamente una línea de ella.

Los módulos IO::Pty y Expect de CPAN pueden ayudar con esto, ya que proporcionan una tty real (bueno, una pseudo-tty, en realidad), lo que vuelve a colocar el almacenamiento en búfer de línea en el comando invocado.

ADVERTENCIA

El orden de los argumentos difiere del de "open3" de IPC::Open3.

VER TAMBIÉN

Ver IPC::Open3 para una alternativa que también maneja "STDERR". Esta función es realmente solo un envoltorio alrededor de "open3".
