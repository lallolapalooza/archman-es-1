UFFDIO_ZEROPAGE(2const) UFFDIO_ZEROPAGE(2const)

NOMBRE

UFFDIO_ZEROPAGE - poner a cero un rango de memoria registrado con userfaultfd

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/userfaultfd.h>  /* Definición de constantes UFFD* */
#include <sys/ioctl.h>
int ioctl(int fd, UFFDIO_ZEROPAGE, struct uffdio_zeropage *argp);
#include <linux/userfaultfd.h>
struct uffdio_zeropage {
    struct uffdio_range  range;
    __u64                mode;      /* Banderas que controlan el comportamiento */
    __s64                zeropage;  /* Número de bytes puestos a cero */
};

DESCRIPCIÓN

Poner a cero un rango de memoria registrado con userfaultfd.

El siguiente valor puede ser OR-ed a nivel de bits en mode para cambiar el comportamiento de la operación UFFDIO_ZEROPAGE:

UFFDIO_ZEROPAGE_MODE_DONTWAKE
No despertar al hilo que espera la resolución de fallos de página.

El campo zeropage es utilizado por el kernel para devolver el número de bytes que realmente se pusieron a cero, o un error de la misma manera que UFFDIO_COPY. Si el valor devuelto en el campo zeropage no coincide con el valor especificado en range.len, la operación falla con el error EAGAIN. El campo zeropage es solo de salida; no es leído por la operación UFFDIO_ZEROPAGE.

VALOR DE RETORNO

Esta operación ioctl(2) devuelve 0 en caso de éxito. En este caso, toda el área fue puesta a cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EAGAIN
El número de bytes puestos a cero (es decir, el valor devuelto en el campo zeropage) no es igual al valor especificado en el campo range.len.
EINVAL
Ya sea range.start o range.len no eran múltiplos del tamaño de página del sistema; o range.len era cero; o el rango especificado era inválido.
EINVAL
Se especificó un bit inválido en el campo mode.
ESRCH (desde Linux 4.13)
El proceso que provoca el fallo ha salido en el momento de una operación UFFDIO_ZEROPAGE.

ESTÁNDARES

Linux.

HISTORIA

Linux 4.3.
