UFFDIO_MOVE(2const) UFFDIO_MOVE(2const)

NOMBRE

UFFDIO_MOVE - mover atómicamente un fragmento de memoria continuo al rango registrado de userfault

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/userfaultfd.h>  /* Definición de constantes UFFD* */
#include <sys/ioctl.h>
int ioctl(int fd, UFFDIO_MOVE, struct uffdio_move *argp);
#include <linux/userfaultfd.h>
struct uffdio_move {
    __u64  dst;   /* Destino del movimiento */
    __u64  src;   /* Origen del movimiento */
    __u64  len;   /* Número de bytes a mover */
    __u64  mode;  /* Banderas que controlan el comportamiento del movimiento */
    __s64  move;  /* Número de bytes movidos, o error negado */
};

DESCRIPCIÓN

Mover atómicamente un fragmento de memoria continuo al rango registrado de userfault y, opcionalmente, despertar al hilo bloqueado.

El siguiente valor puede ser OR-bitwise en .mode para cambiar el comportamiento de la operación UFFDIO_MOVE:

UFFDIO_MOVE_MODE_DONTWAKE
No despertar al hilo que espera la resolución de fallos de página
UFFDIO_MOVE_MODE_ALLOW_SRC_HOLES
Permitir huecos en el rango virtual de origen que se está moviendo. Cuando no se especifica, los huecos resultarán en un error ENOENT. Cuando se especifica, los huecos se contarán como memoria movida con éxito. Esto es útil principalmente para mover regiones virtuales alineadas con páginas grandes sin saber si hay páginas grandes transparentes en las regiones o no, pero evitando el riesgo de tener que dividir la página grande durante la operación.

El campo .move es utilizado por el kernel para devolver el número de bytes que realmente se movió, o un error (un valor negado de estilo errno). El campo .move es de solo salida; no es leído por la operación UFFDIO_MOVE.

VALOR DE RETORNO

En caso de éxito, se devuelve 0. En este caso, toda el área fue movida.

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EAGAIN
El número de bytes movidos (es decir, el valor devuelto en el campo .move) no coincide con el valor especificado en el campo .len.
EINVAL
Ya sea .dst o .len no eran múltiplos del tamaño de página del sistema, o el rango especificado por .src y .len o .dst y .len era inválido.
EINVAL
Se especificó un bit inválido en el campo .mode.
ENOENT
El rango de memoria virtual de origen tiene huecos sin mapear y no se establece UFFDIO_MOVE_MODE_ALLOW_SRC_HOLES.
EEXIST
El rango de memoria virtual de destino está total o parcialmente mapeado.
EBUSY
Las páginas en el rango de memoria virtual de origen están ancladas o no son exclusivas del proceso. Una vez que KSM desduplica páginas o fork(2) comparte páginas COW durante fork(2) con procesos hijos, ya no son exclusivas. El kernel solo puede realizar comprobaciones ligeras para detectar si las páginas son exclusivas. Para que la operación tenga más probabilidades de éxito, KSM debe estar deshabilitado, se debe evitar fork(2) o se debe configurar MADV_DONTFORK para el área de memoria virtual de origen antes de fork(2).
ENOMEM
Falló la asignación de memoria necesaria para la operación.
ESRCH
El proceso objetivo ha salido en el momento de una operación UFFDIO_MOVE.
