Unicode::Collate::Locale(3perl) Guía de referencia para programadores de Perl Unicode::Collate::Locale(3perl)

NOMBRE

Unicode::Collate::Locale - Adaptación lingüística para DUCET vía Unicode::Collate

SINOPSIS

use Unicode::Collate::Locale;
# Construir
$Collator = Unicode::Collate::Locale->
    new(locale => $nombre_local, %adaptaciones);
# Ordenar
@ordenadas = $Collator->sort(@no_ordenadas);
# Comparar
$resultado = $Collator->cmp($a, $b); # Devuelve 1, 0 o -1.

Nota: Las cadenas en @no_ordenadas, $a y $b se interpretan de acuerdo con el soporte de Unicode de Perl. Ver perlunicode, perluniintro, perlunifaq, utf8. De lo contrario, puedes usar "preprocess" (ver "Unicode::Collate") o deberías decodificarlas antes.

DESCRIPCIÓN

Este módulo proporciona adaptación lingüística para aprovechar "Unicode::Collate".

Constructor

El método "new" devuelve un objeto de ordenación.

Una lista de parámetros para el constructor es un hash, que puede incluir una clave especial "locale" y su valor (sin distinción de mayúsculas y minúsculas) que representa un código base de idioma Unicode (de dos o tres letras). Por ejemplo, "Unicode::Collate::Locale->new(locale => 'ES')" devuelve un ordenador adaptado para el español.

$nombre_local puede ir seguido de un código de script Unicode (cuatro letras), un código de región (territorio) Unicode, un código de variante de idioma Unicode. Estos códigos no distinguen entre mayúsculas y minúsculas, y se separan con '_' o '-'. Por ejemplo, "en_US" para inglés en EE. UU., "az_Cyrl" para azerbaiyano en escritura cirílica, "es_ES_traditional" para español en España (Tradicional).

Si $nombre_local no está disponible, se selecciona una opción de reserva en el siguiente orden:

1. idioma con código de variante
2. idioma con código de script
3. idioma con código de región
4. idioma
5. predeterminado

Las etiquetas de adaptación proporcionadas por "Unicode::Collate" están permitidas siempre que no se utilicen para soporte de "locale". Especialmente la etiqueta "table" nunca se puede adaptar, ya que está reservada para DUCET.

Sin embargo, "entry" está permitido, incluso si se utiliza para soporte de "locale", para añadir o sobrescribir mapeos.

Por ejemplo, un ordenamiento para español, que ignora los diacríticos y la diferencia de mayúsculas/minúsculas (es decir, nivel 1), con orden de mayúsculas/minúsculas invertido y sin normalización.

Unicode::Collate::Locale->new(
    level => 1,
    locale => 'es',
    upper_before_lower => 1,
    normalization => undef
)

Sobrescribir un comportamiento ya adaptado por "locale" no está permitido si dicha adaptación se pasa a new().

Unicode::Collate::Locale->new(
    locale => 'da',
    upper_before_lower => 0, # causa error ya que está reservado por 'da'
)

Sin embargo, change() heredado de "Unicode::Collate" permite dicha adaptación que está reservada por "locale". Ejemplos:

new(locale => 'fr_ca')->change(backwards => undef)
new(locale => 'da')->change(upper_before_lower => 0)
new(locale => 'ja')->change(overrideCJK => undef)

Métodos

"Unicode::Collate::Locale" es una subclase de "Unicode::Collate" y los métodos distintos de "new" se heredan de "Unicode::Collate".

Aquí hay una lista de métodos adicionales:

"$Collator->getlocale"
Devuelve un código de idioma aceptado y utilizado realmente en la ordenación. Si no se proporciona adaptación lingüística para un código de idioma que pasaste (intencionalmente para algunos idiomas, o debido a la implementación incompleta), este método devuelve la cadena 'default', lo que significa que no hay adaptación especial.
"$Collator->locale_version"
(Desde Unicode::Collate::Locale 0.87) Devuelve el número de versión (quizás "/\d\.\d\d/") de la configuración regional, como la de Locale/*.pl.

Nota: Locale/*.pl que utiliza un ordenamiento debe identificarse mediante una combinación de los valores de retorno de "getlocale" y "locale_version".

Nota

[1] ja: Los ideogramas se ordenan según el orden JIS X 0208. Las formas de ancho completo y medio ancho son idénticas a su forma regular. La diferencia entre hiragana y katakana está en el 4º nivel, la comparación también requiere "(variable => 'No ignorable')", y entonces "katakana_before_hiragana" no tiene efecto.

[2] ko: Muchos ideogramas se ordenan por su lectura. Dicho ideograma es primario (nivel 1) igual, y secundario (nivel 2) mayor que la sílaba hangul correspondiente.

[3] zh__pinyin, zh__stroke y zh__zhuyin: implementado alt='short', donde se adapta un menor número de ideogramas.

INSTALACIÓN

La instalación de "Unicode::Collate::Locale" requiere Collate/Locale.pm, Collate/Locale/*.pm, Collate/CJK/*.pm y Collate/allkeys.txt. Al compilar, "Unicode::Collate::Locale" no requiere ninguno de los archivos data/*.txt, gendata/*, y mklocale. Las pruebas para "Unicode::Collate::Locale" se nombran t/loc_*.t.

ADVERTENCIA

La adaptación no es máxima
Incluso si una letra determinada está adaptada, su equivalente no siempre estará tan bien adaptado como esta. Por ejemplo, aunque la W está adaptada, la W de ancho completo ("U+FF37"), la W con acento agudo ("U+1E82"), etc. no están adaptadas. El resultado puede depender de si las cadenas de origen están normalizadas o no, y de si están descompuestas o compuestas. Por lo tanto, "(normalization => undef)" es menos preferible.
No se admite la reordenación de la ordenación
El orden de ningún grupo, incluidos los scripts, se modifica.
