UNIVERSAL(3perl) Perl Programadores Reference Guide UNIVERSAL(3perl)

NOMBRE

UNIVERSAL - clase base para TODAS las clases (referencias bendecidas)

SINOPSIS

my $obj_is_io    = $fd->isa("IO::Handle");
my $cls_is_io    = Class->isa("IO::Handle");
my $obj_does_log = $obj->DOES("Logger");
my $cls_does_log = Class->DOES("Logger");
my $obj_sub      = $obj->can("print");
my $cls_sub      = Class->can("print");
my $eval_sub     = eval { $ref->can("fandango") };
my $ver          = $obj->VERSION;
# pero nunca hagas esto!
my $is_io        = UNIVERSAL::isa($fd, "IO::Handle");
my $sub          = UNIVERSAL::can($obj, "print");

DESCRIPCIÓN

"UNIVERSAL" es la clase base de la cual heredan todas las referencias bendecidas. Ver perlobj.

"UNIVERSAL" proporciona los siguientes métodos:

"$obj->isa( TIPO )"
"CLASE->isa( TIPO )"
"eval { VAL->isa( TIPO ) }"
Donde
"TIPO"
es un nombre de paquete
$obj
es una referencia bendecida o un nombre de paquete
"CLASE"
es un nombre de paquete
"VAL"
es cualquiera de los anteriores o una referencia no bendecida

Cuando se usa como método de instancia o de clase ("$obj->isa( TIPO )"), "isa" devuelve *verdadero* si $obj está bendecido en el paquete "TIPO" o hereda del paquete "TIPO".

Cuando se usa como método de clase ("CLASE->isa( TIPO )", a veces referido como método estático), "isa" devuelve *verdadero* si "CLASE" hereda de (o es en sí misma) el nombre del paquete "TIPO" o hereda del paquete "TIPO".

Si no estás seguro de lo que tienes (el caso "VAL"), envuelve la llamada al método en un bloque "eval" para capturar la excepción si "VAL" es indefinido o una referencia no bendecida. El operador "isa" es una alternativa que simplemente devuelve falso en este caso, por lo que "eval" no es necesario.

Si quieres asegurarte de que estás llamando a "isa" en una instancia, no en una clase, verifica el invocante con "blessed" de Scalar::Util primero:

use Scalar::Util 'blessed';
if ( blessed( $obj ) && $obj->isa("Some::Class") ) {
    ...
}
"$obj->DOES( ROL )"
"CLASE->DOES( ROL )"
"DOES" comprueba si el objeto o la clase realiza el rol "ROL". Un rol es un grupo con nombre de comportamiento específico (a menudo métodos con nombres y firmas particulares), similar a una clase, pero no necesariamente una clase completa por sí misma. Por ejemplo, el registro o la serialización pueden ser roles.

"DOES" e "isa" son similares, en que si alguno es verdadero, sabes que el objeto o clase en el que llamas al método puede realizar un comportamiento específico. Sin embargo, "DOES" es diferente de "isa" en que no le importa *cómo* el invocante realiza las operaciones, sino solo que las realiza. ("isa" por supuesto exige una relación de herencia. Otras relaciones incluyen agregación, delegación y mocking.)

Por defecto, las clases en Perl solo realizan el rol "UNIVERSAL", así como el rol de todas las clases en su herencia. En otras palabras, por defecto "DOES" responde de manera idéntica a "isa".

Existe una relación entre roles y clases, ya que cada clase implica la existencia de un rol del mismo nombre. También existe una relación entre herencia y roles, en el sentido de que una subclase que hereda de una clase ancestral realiza implícitamente cualquier rol que su padre realice. Por lo tanto, puedes usar "DOES" en lugar de "isa" de forma segura, ya que devolverá verdadero en todos los lugares donde "isa" devuelva verdadero (siempre que los métodos "DOES" y "isa" sobrescritos se comporten adecuadamente).

"$obj->can( MÉTODO )"
"CLASE->can( MÉTODO )"
"eval { VAL->can( MÉTODO ) }"
"can" comprueba si el objeto o la clase tiene un método llamado "MÉTODO". Si lo tiene, devuelve una referencia a la subrutina. Si no lo tiene, devuelve *undef*. Esto incluye métodos heredados o importados por $obj, "CLASE", o "VAL".

"can" no puede saber si un objeto podrá proporcionar un método a través de AUTOLOAD (a menos que la clase del objeto haya sobrescrito "can" adecuadamente), por lo que un valor de retorno de *undef* no significa necesariamente que el objeto no podrá manejar la llamada al método. Para evitar esto, algunos autores de módulos usan una declaración forward (ver perlsub) para los métodos que manejarán a través de AUTOLOAD. Para dichas subrutinas 'dummy', "can" aún devolverá una referencia de código que, al ser llamada, se dirigirá a AUTOLOAD. Si no se proporciona un AUTOLOAD adecuado, llamar a la referencia de código causará un error.

Puedes llamar a "can" como método de clase (estático) o como método de objeto.

De nuevo, la misma regla sobre tener un invocante válido se aplica: usa un bloque "eval" o "blessed" si necesitas estar extra paranoico.

"VERSION ( [ REQUIERE ] )"
"VERSION" devolverá el valor de la variable $VERSION en el paquete en el que está bendecida el objeto. Si se proporciona "REQUIERE", entonces hará una comparación y morirá si la versión del paquete no es mayor o igual a "REQUIERE", o si tanto $VERSION como "REQUIERE" no son números de versión "lax" (según se define en el módulo version).

El retorno de "VERSION" será en realidad el objeto de versión serializado usando el escalar $VERSION del paquete, que está garantizado que es equivalente pero puede que no sea precisamente el contenido del escalar $VERSION. Si quieres el contenido real de $VERSION, usa $CLASS::VERSION en su lugar.

"VERSION" puede ser llamado tanto como método de clase (estático) como método de objeto.

ADVERTENCIAS

NOTA: "can" utiliza directamente el código interno de Perl para la búsqueda de métodos, y "isa" utiliza un método muy similar y una estrategia de caché. Esto puede causar efectos extraños si el código Perl cambia dinámicamente @ISA en cualquier paquete.

Puedes añadir otros métodos a la clase UNIVERSAL a través de código Perl o XS. No necesitas "use UNIVERSAL" para hacer estos métodos disponibles para tu programa (y no deberías hacerlo).

Ninguna.

UNIVERSAL(3pm)

NAME

UNIVERSAL - isa() and can() methods for all objects

SYNOPSIS

    package Foo;
    use base 'UNIVERSAL';

    sub bar { ... }

    package main;
    my $foo = Foo->new;

    # isa()
    if ($foo->isa('Foo')) {
        print "It's a Foo!\n";
    }
    if ($foo->isa('Bar')) {
        print "It's a Bar!\n";
    }

    # can()
    if ($foo->can('bar')) {
        print "It can do bar!\n";
    }
    if ($foo->can('baz')) {
        print "It can do baz!\n";
    } else {
        print "It can't do baz!\n";
    }

    # Note that these methods are inherited by all classes.
    # You do NOT need to explicitly inherit from UNIVERSAL.
    # This is only done in the example for clarity.

DESCRIPTION

The UNIVERSAL package provides two methods, isa and can, that are automatically available to all classes and objects in Perl. You do not need to explicitly inherit from UNIVERSAL; it's done for you automatically.

isa( CLASSNAME ): Returns true if the object (or class) is an instance of the specified CLASSNAME, or inherits from it.

can( METHODNAME ): Returns true if the object (or class) has a method by the name of METHODNAME, or inherits one. Otherwise, returns false.

These methods are part of the object system and are fundamental to Perl's object-oriented capabilities. They work with both blessed references and class names.

WARNINGS

In older versions of Perl, it was sometimes suggested to check if a reference was a hash or an array using methods like:

    # BAD CODE - DO NOT USE
    my $h = { a => 1 };
    my $yes = tied( $h ) ? tied( $h )->isa("HASH") : $h->isa("HASH");
    my $a = [1, 2];
    my $yes = tied( $a ) ? tied( $a )->isa("ARRAY") : $a->isa("ARRAY");

    # Also BAD CODE - DO NOT USE
    my $yes = Foo->isa("Bar");

The problem is that this code would never call an overridden "isa" method in any class. Instead, use "reftype" from Scalar::Util for the first case:

    use Scalar::Util 'reftype';
    $yes = reftype( $h ) eq "HASH";

and the method form of "isa" for the second:

$yes = Foo->isa("Bar");
