Unicode::Stringprep(3pm) Documentación de Perl aportada por el usuario Unicode::Stringprep(3pm)

NOMBRE

Unicode::Stringprep - Preparación de Cadenas Internacionalizadas (RFC 3454)

SINOPSIS

use Unicode::Stringprep;
use Unicode::Stringprep::Mapping;
use Unicode::Stringprep::Prohibited;
my $prepper = Unicode::Stringprep->new(
  3.2,
  [ { 32 => '<SPACE>'},  ],
  'KC',
  [ @Unicode::Stringprep::Prohibited::C12, @Unicode::Stringprep::Prohibited::C22,
    @Unicode::Stringprep::Prohibited::C3, @Unicode::Stringprep::Prohibited::C4,
    @Unicode::Stringprep::Prohibited::C5, @Unicode::Stringprep::Prohibited::C6,
    @Unicode::Stringprep::Prohibited::C7, @Unicode::Stringprep::Prohibited::C8,
    @Unicode::Stringprep::Prohibited::C9 ],
  1, 0 );
$output = $prepper->($input)

DESCRIPCIÓN

Este módulo implementa el marco de trabajo de stringprep para preparar cadenas de texto Unicode con el fin de aumentar la probabilidad de que la entrada de cadenas y la comparación de cadenas funcionen de maneras que tengan sentido para los usuarios típicos de todo el mundo. El protocolo de stringprep es útil para valores de identificadores de protocolo, nombres de empresas y personales, nombres de dominio internacionalizados y otras cadenas de texto.

El marco de trabajo de stringprep no especifica cómo los protocolos deben preparar las cadenas de texto. Los protocolos deben crear perfiles de stringprep para especificar completamente las opciones de procesamiento.

FUNCIONES

Este módulo proporciona una única función, "new", que crea una función perl que implementa un perfil de stringprep.

Este módulo no exporta nada.

new($unicode_version, $mapping_tables, $unicode_normalization, $prohibited_tables, $bidi_check, $unassigned_check)
Crea una referencia de función "bless"ed que implementa un perfil de stringprep.

Esta función toma los siguientes parámetros:

$unicode_version
La versión de Unicode especificada por el perfil de stringprep.

Actualmente, este parámetro debe ser 3.2 (numérico).

$mapping_tables
Las tablas de mapeo utilizadas para stringprep.

El parámetro puede ser una referencia a un hash o a un array, o "undef". Un hash debe mapear puntos de código Unicode (como enteros, p. ej. 0x0020 para U+0020) a cadenas de reemplazo (como cadenas perl). Un array puede contener pares de puntos de código Unicode y cadenas de reemplazo, así como referencias a hashes y arrays anidados.

Unicode::Stringprep::Mapping proporciona las tablas del Apéndice B de RFC 3454.

Para más información sobre el paso de mapeo, ver la sección 3 de RFC 3454.

$unicode_normalization
La normalización Unicode que se utilizará.

Actualmente, se especifican "undef"/'' (sin normalización) y 'KC' (composición de compatibilidad) para stringprep.

Para más información sobre el paso de normalización, ver la sección 4 de RFC 3454.

La forma de normalización KC también habilitará comprobaciones para algunas secuencias problemáticas para las que la normalización no se puede implementar de forma interoperable.

Para más información, ver "CAVEATS" (Advertencias) abajo.

$prohibited_tables
La lista de caracteres de salida prohibidos para stringprep.

El parámetro puede ser una referencia a un array, o "undef". El array contiene **pares** de puntos de código, que definen el **inicio** y el **fin** de un rango de caracteres Unicode (como enteros). El carácter final puede ser "undef", especificando un rango de un solo carácter. El array también puede contener referencias a arrays anidados.

Unicode::Stringprep::Prohibited proporciona las tablas del Apéndice C de RFC 3454.

Para más información sobre el paso de verificación de prohibición, ver la sección 5 de RFC 3454.

$bidi_check
Si se deben emplear comprobaciones para texto bidireccional confuso. Un valor booleano.

Para más información sobre el paso de verificación de bidi, ver la sección 6 de RFC 3454.

$unassigned_check
Si se deben comprobar y prohibir los caracteres no asignados. Un valor booleano.

La comprobación debe usarse al crear cadenas **almacenadas**. No debe usarse para cadenas de **consulta**, aumentando la probabilidad de que los caracteres recién asignados funcionen como se espera.

Para más información sobre cadenas **almacenadas** y de **consulta**, ver la sección 7 de RFC 3454.

La función devuelta se puede llamar con un único parámetro, la cadena a preparar, y devuelve la cadena preparada. Fallará si la cadena de entrada no se puede preparar con éxito porque contendría una salida inválida (así que use "eval" si es necesario).

Por razones de rendimiento, se recomienda encarecidamente llamar a la función "new" tan pocas veces como sea posible, es decir, exactamente una vez por perfil de stringprep. También podría ser mejor no usar este módulo directamente, sino usar (o escribir) un módulo que implemente un perfil, como Authen::SASL::SASLprep.

IMPLEMENTACIÓN DE PERFILES

Puedes implementar fácilmente un perfil de stringprep sin subclasear:

package ACME::ExamplePrep;
use Unicode::Stringprep;
use Unicode::Stringprep::Mapping;
use Unicode::Stringprep::Prohibited;
*exampleprep = Unicode::Stringprep->new(
  3.2,
  [ \@Unicode::Stringprep::Mapping::B1, ],
  '',
  [ \@Unicode::Stringprep::Prohibited::C12,
    \@Unicode::Stringprep::Prohibited::C22, ],
  1,
);

Esto enlaza "ACME::ExamplePrep::exampleprep" a la función creada por "Unicode::Stringprep->new".

Normalmente, no es necesario subclasear este módulo. No se recomienda subclasear este módulo.

ADVERTENCIAS

En Unicode 3.2 a 4.0.1, la especificación de UAX #15: Formularios de Normalización Unicode para las formas NFC y NFKC no es lógicamente autoconsistente. Esto se ha corregido en la Corrigendum #5 (http://unicode.org/versions/corrigendum5.html).

Desafortunadamente, esto da como resultado dos formas de implementar NFC y NFKC en Unicode 3.2, en el que se basa el estándar Stringprep: una basada en una interpretación literal de la especificación original y otra basada en la especificación corregida. La salida de estas implementaciones difiere para una pequeña clase de cadenas, ninguna de las cuales puede aparecer en texto significativo. Ver UAX #15, sección 19 NAME

Unicode::Stringprep - Perl module for String preparation

SYNOPSIS

use Unicode::Stringprep;

my $string = "étude";
my $prepared_string = prepare($string);
print $prepared_string;
# Output: etude

my $string = " ​string ​with ​ZWSP";
my $prepared_string = prepare(string => $string, profile => 'RFC3491');
print $prepared_string;
# Output: stringwithZWSP

my $string = "Äa"; # A umlaut + a
my $prepared_string = prepare(string => $string, profile => 'RFC3491', normalization => 'NFC');
print $prepared_string;
# Output: äa

DESCRIPTION

This module implements the String preparation Algorithm as specified by the Internet Engineering Task Force (IETF) in RFC 3454.

String preparation is a process that transforms a string into a form suitable for comparison. This includes mapping characters to a common representation, normalizing them, and removing disallowed characters.

RFC 3454 specifies two primary profiles for string preparation:

RFC3491
The general purpose string preparation profile.
RFC4253
A specific profile used for preparing strings for comparison in SSH.

The module also allows for optional Unicode normalization (NFC, NFD, NFKC, NFKD) before or after the string preparation steps.

FUNCTIONS

prepare( string => $input_string [, profile => $profile_name ] [, normalization => $normalization_form ] )
Prepares the given input_string according to the specified profile_name. If no profile is specified, it defaults to 'RFC3491'.
prepare( string => $input_string [, profile => $profile_name ] [, normalization => $normalization_form ] )
Performs Unicode normalization on the input_string before applying the string preparation steps. The normalization_form can be 'NFC', 'NFD', 'NFKC', or 'NFKD'.
prepare( string => $input_string [, profile => $profile_name ] [, normalization => $normalization_form ] )
Performs Unicode normalization on the prepared string after applying the string preparation steps. The normalization_form can be 'NFC', 'NFD', 'NFKC', or 'NFKD'.
prepare( string => $input_string [, profile => $profile_name ] [, normalization => $normalization_form ] )
Performs Unicode normalization on the input string before and after applying the string preparation steps.

IMPLEMENTING PROFILES

This module currently implements the following profiles:

RFC3491
The general string preparation profile as defined in RFC 3454, Section 6.
RFC4253
The string preparation profile for SSH as defined in RFC 4253, Section 6.

DATA TABLES

This module uses data tables generated from the Unicode Character Database (UCD). These tables define character properties, mappings, and normalization forms used in the string preparation process.

CAVEATS

RFC 3454 specifies certain character sequences that are not allowed in prepared strings. These include:

  • Bidirectionality (Bidi) control characters.
  • Non-characters (e.g., U+FFFE, U+FFFF).
  • Characters with the Unicode property 'unassigned'.
  • Sequences that violate canonical equivalence (e.g., combining characters that should be mapped to precomposed characters).

    This module checks for these disallowed sequences. If any are found during the preparation process, the preparation will fail, and an error will be raised.

    For more details on these restrictions and the string preparation algorithm, please refer to the following document:

    The Unicode Standard, Version 3.0, Chapter 5.32: String Preparation http://unicode.org/reports/tr15/

    This module will check for these strings and, if normalization is done, prohibit them in output as it is not possible to interoperate under these circumstandes.

    Please note that due to this, the normalization step may cause the preparation to fail. That is, the preparation function may die even if there are no prohibited characters and no checks for bidi sequences and unassigned characters, which may be surprising.
