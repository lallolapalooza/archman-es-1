NOMBRE

URI - Identificadores Uniformes de Recursos (absolutos y relativos)

SINOPSIS

use URI ();
$u1 = URI->new("http://www.example.com");
$u2 = URI->new("foo", "http");
$u3 = $u2->abs($u1);
$u4 = $u3->clone;
$u5 = URI->new("HTTP://WWW.example.com:80")->canonical;
$str = $u->as_string;
$str = "$u";
$scheme = $u->scheme;
$opaque = $u->opaque;
$path   = $u->path;
$frag   = $u->fragment;
$u->scheme("ftp");
$u->host("ftp.example.com");
$u->path("cpan/");

DESCRIPCIÓN

Este módulo implementa la clase "URI". Los objetos de esta clase representan "referencias de Identificador Uniforme de Recurso" tal como se especifica en RFC 2396 (y actualizado por RFC 2732).

Un Identificador Uniforme de Recurso es una cadena compacta de caracteres que identifica un recurso abstracto o físico. Un Identificador Uniforme de Recurso se puede clasificar además como un Localizador Uniforme de Recurso (URL) o un Nombre Uniforme de Recurso (URN). La distinción entre URL y URN no importa para la interfaz de la clase "URI". Una "referencia URI" es una URI que puede tener información adicional adjunta en forma de un identificador de fragmento.

Una referencia URI absoluta consta de tres partes: un esquema, una parte específica del esquema y un identificador de fragmento. Un subconjunto de referencias URI comparte una sintaxis común para espacios de nombres jerárquicos. Para estos, la parte específica del esquema se divide además en componentes de autoridad, ruta y consulta. Estas URI también pueden tener la forma de referencias URI relativas, donde falta el componente de esquema (y generalmente también la autoridad), pero se infiere por el contexto de la referencia URI. Las tres formas de sintaxis de referencia URI se resumen de la siguiente manera:

<esquema>:<parte-especifica-del-esquema>#<fragmento>
<esquema>://<autoridad><ruta>?<consulta>#<fragmento>
<ruta>?<consulta>#<fragmento>

Los componentes en los que se puede dividir una referencia URI dependen del esquema. La clase "URI" proporciona métodos para obtener y establecer los componentes individuales. Los métodos disponibles para un objeto "URI" específico dependen del esquema.

CONSTRUCTORES

Los siguientes métodos construyen nuevos objetos "URI":

$uri = URI->new( $str )
$uri = URI->new( $str, $scheme )
Construye un nuevo objeto URI. La representación de cadena de una URI se proporciona como argumento, junto con una especificación de esquema opcional. Los envoltorios de URI comunes como "" y <>, así como los espacios en blanco iniciales y finales, se eliminan automáticamente del argumento $str antes de ser procesado.

El constructor determina el esquema, lo mapea a una subclase URI apropiada, construye un nuevo objeto de esa clase y lo devuelve.

Si el esquema no es uno de los que URI reconoce, aún obtendrá un objeto URI que podrá acceder a los métodos genéricos. El método "$uri->has_recognized_scheme" se puede usar para probar esto.

El argumento $scheme solo se usa cuando $str es una URI relativa. Puede ser una cadena simple que denota el esquema, una cadena que contiene una referencia URI absoluta o un objeto "URI" absoluto. Si no se especifica $scheme para una URI relativa $str, entonces $str simplemente se trata como una URI genérica (sin métodos específicos del esquema disponibles).

El conjunto de caracteres disponibles para construir referencias URI está restringido (ver URI::Escape). Los caracteres fuera de este conjunto se escapan automáticamente por el constructor URI.

$uri = URI->new_abs( $str, $base_uri )
Construye un nuevo objeto URI absoluto. El argumento $str puede denotar una URI relativa o absoluta. Si es relativa, se absolutiza usando $base_uri como base. $base_uri debe ser una URI absoluta.
$uri = URI::file->new( $filename )
$uri = URI::file->new( $filename, $os )
Construye una nueva URI de archivo a partir de un nombre de archivo. Ver URI::file.
$uri = URI::file->new_abs( $filename )
$uri = URI::file->new_abs( $filename, $os )
Construye una nueva URI de archivo absoluta a partir de un nombre de archivo. Ver URI::file.
$uri = URI::file->cwd
Devuelve el directorio de trabajo actual como una URI de archivo. Ver URI::file.
$uri->clone
Devuelve una copia de $uri.

MÉTODOS COMUNES

Los métodos descritos en esta sección están disponibles para todos los objetos "URI".

Los métodos que proporcionan acceso a los componentes de una URI siempre devuelven el valor antiguo del componente. El valor devuelto es "undef" si el componente no estaba presente. Generalmente hay una diferencia entre un componente que está vacío (representado como "") y un componente que falta (representado como "undef"). Si un método accessor recibe un argumento, actualiza el componente correspondiente además de devolver el valor antiguo del componente. Pasar un argumento indefinido elimina el componente (si es posible). La descripción de cada método accessor indica si el componente se pasa como una cadena escapada (percent-encoded) o sin escapar. Un componente que se puede dividir aún más en sub-partes generalmente se pasa escapado, ya que la eliminación de escape podría cambiar su semántica.

Los métodos comunes disponibles para todas las URI son:

$uri->scheme
$uri->scheme( $nuevo_esquema )
Establece y devuelve la parte del esquema de la $uri. Si la $uri es relativa, entonces $uri->scheme devuelve "undef". Si se llama con un argumento, actualiza el esquema de $uri, posiblemente cambiando la clase de $uri, y devuelve el esquema antiguo. El método revienta si el nuevo nombre de esquema es ilegal; un nombre de esquema debe comenzar con una letra y debe consistir solo en letras US-ASCII, números y algunas marcas especiales: ".", "+", "-". Esta restricción significa efectivamente que el esquema debe pasarse sin escapar. Pasar un argumento indefinido al método de esquema hace que la URI sea relativa (si es posible).

La capitalización no importa para los nombres de esquema. La cadena devuelta por $uri->scheme siempre está en minúsculas. Si desea el esquema tal como estaba escrito en la URI en su capitalización original, puede usar el método $uri->_scheme en su lugar.

$uri->has_recognized_scheme
Devuelve VERDADERO si el esquema URI es uno que URI reconoce.

También será VERDADERO para URLs relativas donde se proporcionó un esquema reconocido al constructor, incluso si "$uri->scheme" devuelve "undef" para estos.

$uri->opaque
$uri->opaque( $nuevo_opaque )
Establece y devuelve la parte específica del esquema de la $uri (todo entre el esquema y el fragmento) como una cadena escapada.
$uri->path
$uri->path( $nueva_ruta )
Establece y devuelve el mismo valor que $uri->opaque a menos que la URI admita la sintaxis genérica para espacios de nombres jerárquicos. En ese caso, el método genérico se anula para establecer y devolver la parte de la URI entre el nombre de host y el fragmento.
$uri->fragment
$uri->fragment( $nuevo_frag )
Devuelve el identificador de fragmento de una referencia URI como una cadena escapada.
$uri->as_string
Devuelve un objeto URI a una cadena ASCII simple. Los objetos URI también se convierten en cadenas simples automáticamente por sobrecarga. Esto significa que los objetos $uri se pueden usar como cadenas simples en la mayoría de las construcciones de Perl.
$uri->as_iri

$uri->canonical
Devuelve una versión normalizada de la URI. Las reglas de normalización dependen del esquema. Normalmente implican convertir a minúsculas los componentes del esquema y el nombre de host de Internet, eliminar la especificación explícita del puerto si coincide con el puerto por defecto, convertir todas las secuencias de escape a mayúsculas y decodificar los octetos que se pueden representar mejor como caracteres normales.

Por razones de eficiencia, si la $uri ya está en forma normalizada, se devuelve una referencia a ella en lugar de una copia.

$uri->eq( $other_uri )
URI::eq( $first_uri, $other_uri )
Comprueba si dos referencias de URI son iguales. Dos referencias de URI que se normalizan a la misma cadena se consideran iguales. El método también se puede utilizar como una función normal que también puede comparar dos argumentos de cadena.

Si necesita comprobar si dos referencias de objeto "URI" denotan el mismo objeto, utilice el operador '=='.

$uri->abs( $base_uri )
Devuelve una referencia de URI absoluta. Si $uri ya es absoluta, simplemente se devuelve una referencia a ella. Si la $uri es relativa, se construye una nueva URI absoluta combinando la $uri y la $base_uri, y se devuelve.
$uri->rel( $base_uri )
Devuelve una referencia de URI relativa si es posible crear una que denote el mismo recurso relativo a $base_uri. Si no es así, simplemente se devuelve $uri.
$uri->secure
Devuelve un valor VERDADERO si se considera que la URI apunta a un recurso en un canal seguro, como uno cifrado con SSL o TLS.

MÉTODOS GENÉRICOS

Los siguientes métodos están disponibles para esquemas que utilizan la sintaxis común/genérica para espacios de nombres jerárquicos. Las descripciones de esquemas a continuación indican cuáles son. Se asume que los esquemas no reconocidos admiten la sintaxis genérica y, por lo tanto, los siguientes métodos:

$uri->authority
$uri->authority( $new_authority )
Establece y devuelve el componente de autoridad escapado de la $uri.
$uri->path
$uri->path( $new_path )
Establece y devuelve el componente de ruta escapado de la $uri (la parte entre el nombre de host y la consulta o fragmento). La ruta nunca puede ser indefinida, pero puede ser la cadena vacía.
$uri->path_query
$uri->path_query( $new_path_query )
Establece y devuelve los componentes de ruta y consulta como una sola entidad. La ruta y la consulta están separadas por un carácter "?", pero la consulta puede contener "?" en sí misma.
$uri->path_segments
$uri->path_segments( $segment, ... )
Establece y devuelve la ruta. En un contexto escalar, devuelve el mismo valor que $uri->path. En un contexto de lista, devuelve los segmentos de ruta decodificados que componen la ruta. Los segmentos de ruta que tienen parámetros se devuelven como un array anónimo. El primer elemento es el segmento de ruta propiamente dicho decodificado; los elementos subsiguientes son cadenas de parámetros escapadas. Dicho array anónimo utiliza sobrecarga para que también pueda tratarse como una cadena, pero esta cadena no incluye los parámetros.

Tenga en cuenta que las rutas absolutas tienen la cadena vacía como su primer *path_segment*, es decir, la *ruta* "/foo/bar" tiene 3 *path_segments*: "", "foo" y "bar".

$uri->query
$uri->query( $new_query )
Establece y devuelve el componente de consulta escapado de la $uri.
$uri->query_form
$uri->query_form( $key1 => $val1, $key2 => $val2, ... )
$uri->query_form( $key1 => $val1, $key2 => $val2, ..., $delim )
$uri->query_form( \@key_value_pairs )
$uri->query_form( \@key_value_pairs, $delim )
$uri->query_form( \%hash )
$uri->query_form( \%hash, $delim )
Establece y devuelve componentes de consulta que utilizan el formato *application/x-www-form-urlencoded*. Los pares clave/valor están separados por "&", y la clave está separada del valor por un carácter "=".

El formulario se puede establecer pasando pares clave/valor separados, o a través de una referencia a un array o hash. Pasar un array o hash vacío elimina el componente de consulta, mientras que no pasar ningún argumento deja el componente sin cambios. El orden de las claves no está definido si se pasa una referencia a un hash. El valor antiguo siempre se devuelve como una lista de pares clave/valor separados. Asignar esta lista a un hash es poco aconsejable, ya que las claves devueltas podrían repetirse.

Los valores pasados al establecer el formulario pueden ser cadenas normales o referencias a arrays de cadenas. Pasar un array de valores tiene el mismo efecto que pasar la clave repetidamente con un valor a la vez. Todas las siguientes sentencias tienen el mismo efecto:

$uri->query_form(foo => 1, foo => 2);
$uri->query_form(foo => [1, 2]);
$uri->query_form([ foo => 1, foo => 2 ]);
$uri->query_form([ foo => [1, 2] ]);
$uri->query_form({ foo => [1, 2] });

El parámetro $delim se puede pasar como ";" para forzar que los pares clave/valor se delimiten con ";" en lugar de "&" en la cadena de consulta. Esta práctica a menudo se recomienda para URLs incrustadas en documentos HTML o XML, ya que evita la molestia de escapar el carácter "&". También puede establecer la variable $URI::DEFAULT_QUERY_FORM_DELIMITER a ";" para el mismo efecto global.

@keys = $u->query_param
@values = $u->query_param( $key )
$first_value = $u->query_param( $key )
$u->query_param( $key, $value,... )
Si se llama a $u->query_param sin argumentos, devuelve todas las claves de parámetro distintas de la URI. En un contexto escalar, devuelve el número de claves distintas.

Cuando se proporciona un argumento $key, el método devuelve los valores del parámetro con la clave dada. En un contexto escalar, solo se devuelve el primer valor del parámetro.

Si se proporcionan argumentos adicionales, se utilizan para actualizar parámetros sucesivos con la clave dada. Si alguno de los valores proporcionados son referencias a arrays, el array se dereferencia para obtener los valores reales.

Tenga en cuenta que puede proporcionar varios valores a este método, pero no puede proporcionar varias claves.

Haga esto:

$uri->query_param( widget_id => 1, 5, 9 );

NO haga esto:

$uri->query_param( widget_id => 1, frobnicator_id => 99 );
$u->query_param_append($key, $value,...)
Añade nuevos parámetros con la clave dada sin tocar ningún parámetro antiguo con la misma clave. Se puede explicar como una versión más eficiente de: 
$u->query_param($key,
                $u->query_param($key),
                $value,...);

Una diferencia es que esta expresión devolvería los valores antiguos de $key, mientras que el método query_param_append() no lo hace.

@values = $u->query_param_delete($key)
$first_value = $u->query_param_delete($key)
Elimina todos los pares clave/valor con la clave dada. Se devuelven los valores antiguos. En un contexto escalar, solo se devuelve el primer valor.

Usar el método query_param_delete() es ligeramente más eficiente que el equivalente:

$u->query_param($key, []);
$hashref = $u->query_form_hash
$u->query_form_hash( \%new_form )
Devuelve una referencia a un hash que representa los pares clave/valor del formulario de consulta. Si una clave aparece varias veces, el valor del hash se convierte en una referencia a un array.

Tenga en cuenta que la información de secuencia se pierde. Esto significa que:

$u->query_form_hash($u->query_form_hash);

no es necesariamente una operación nula, ya que puede reordenar los pares clave/valor. Sin embargo, los valores devueltos por el método query_param() deberían permanecer iguales.

$uri->query_keywords
$uri->query_keywords( $keywords, ... )
$uri->query_keywords( \@keywords )
Establece y devuelve componentes de consulta que utilizan el formato de palabras clave separadas por "+".

Las palabras clave se pueden establecer pasando palabras clave separadas directamente o pasando una referencia a un array de palabras clave. Pasar un array vacío elimina el componente de consulta, mientras que no pasar ningún argumento deja el componente sin cambios. El valor antiguo siempre se devuelve como una lista de palabras separadas.

MÉTODOS DE SERVIDOR

Para esquemas donde el componente *authority* denota un host de Internet, los siguientes métodos están disponibles además de los métodos genéricos.

$uri->userinfo
$uri->userinfo( $new_userinfo )
Establece y devuelve la parte de información de usuario escapada del componente de autoridad.

Para algunos esquemas, este es un nombre de usuario y una contraseña separados por dos puntos. Esta práctica no se recomienda. Incrustar contraseñas en texto plano (como en una URI) ha demostrado ser un riesgo de seguridad en casi todos los casos en que se ha utilizado.

$uri->host
$uri->host( $new_host )
Establece y devuelve el nombre de host decodificado.

Si la cadena $new_host termina con dos puntos y un número, este número también establece el puerto.

Para direcciones IPv6, se eliminan los corchetes alrededor de la dirección bruta en el valor devuelto por $uri->host. Al establecer el atributo host a una dirección IPv6, puede usar una dirección bruta o una entre corchetes. La dirección debe encerrarse entre corchetes si también desea pasar un nuevo valor de puerto.

my $uri = URI->new("http://www.\xC3\xBCri-sample/foo/bar.html");
print $u->host; # www.xn--ri-sample-fra0f
$uri->ihost
Devuelve el host en formato Unicode. Cualquier etiqueta A de IDNA (caracteres unicode codificados
con prefijo xn--) se convierten en etiquetas U (caracteres unicode). 
my $uri = URI->new("http://www.\xC3\xBCri-sample/foo/bar.html");
print $u->ihost; # www.\xC3\xBCri-sample
$uri->port
$uri->port( $new_port )
Establece y devuelve el puerto. El puerto es un entero simple que debe ser mayor que 0.

Si no se especifica un puerto explícitamente en la URI, se devuelve el puerto predeterminado del esquema de la URI. Si no desea que se sustituya el puerto predeterminado, puede usar el método $uri->_port en su lugar.

$uri->host_port
$uri->host_port( $new_host_port )
Establece y devuelve el host y el puerto como una sola unidad. El valor devuelto incluye un puerto, incluso si coincide con el puerto predeterminado. La parte del host y la parte del puerto están separadas por dos puntos: «:».

Para las direcciones IPv6, se conservan los corchetes; por lo tanto, URI->new("http://[::1]/")->host_port devuelve «[::1]:80». Contrasta esto con $uri->host, que eliminará los corchetes.

$uri->default_port
Devuelve el puerto predeterminado del esquema de la URI al que pertenece $uri. Para http es el número 80, para ftp es el número 21, etc. El puerto predeterminado de un esquema no se puede cambiar.

SOPORTE ESPECIFICO DEL ESQUEMA

Se proporciona soporte específico del esquema para los siguientes esquemas de URI. Para los objetos "URI" que no pertenecen a uno de estos, solo puede usar los métodos comunes y genéricos.

data:
El esquema de URI data se especifica en RFC 2397. Permite la inclusión de pequeños elementos de datos como datos «inmediatos», como si hubieran sido incluidos externamente.

Los objetos "URI" que pertenecen al esquema de datos admiten los métodos comunes y dos métodos nuevos para acceder a sus componentes específicos del esquema: $uri->media_type y $uri->data. Consulte URI::data para obtener más detalles.

file:
Una especificación antigua del esquema de URI file se encuentra en RFC 1738. Aún no hay una nueva especificación basada en RFC 2396, pero las referencias de URI de archivo están en uso común.

Los objetos "URI" que pertenecen al esquema de archivo admiten los métodos comunes y genéricos. Además, proporcionan dos métodos para mapear las URI de archivo a nombres de archivo locales; $uri->file y $uri->dir. Consulte URI::file para obtener más detalles.

ftp:
Una especificación antigua del esquema de URI ftp se encuentra en RFC 1738. Aún no hay una nueva especificación basada en RFC 2396, pero las referencias de URI ftp están en uso común.

Los objetos "URI" que pertenecen al esquema ftp admiten los métodos comunes, genéricos y de servidor. Además, proporcionan dos métodos para acceder a los subcomponentes de userinfo: $uri->user y $uri->password.

También admite el acceso al modo de cifrado ($uri->encrypt_mode), que tiene sus propios valores predeterminados para los esquemas de URI ftps y ftpes.

gopher:
El esquema de URI gopher se especifica en "draft-murali-url-gopher-1996-12-04" y esperemos que esté disponible como una especificación basada en RFC 2396.

Los objetos "URI" que pertenecen al esquema gopher admiten los métodos comunes, genéricos y de servidor. Además, admiten algunos métodos para acceder a los componentes de ruta específicos de gopher: $uri->gopher_type, $uri->selector, $uri->search, $uri->string.

http:
El esquema de URI http se especifica en RFC 2616. El esquema se usa para hacer referencia a recursos alojados por servidores HTTP.

Los objetos "URI" que pertenecen al esquema http admiten los métodos comunes, genéricos y de servidor.

https:
El esquema de URI https es una invención de Netscape que se implementa comúnmente. El esquema se usa para hacer referencia a servidores HTTP a través de conexiones SSL. Su sintaxis es la misma que http, pero el puerto predeterminado es diferente.
geo:
El esquema de URI geo se especifica en RFC 5870 http://tools.ietf.org/html/rfc5870. El esquema se utiliza para referenciar la ubicación física en un sistema de referencia de coordenadas bidimensional o tridimensional de forma compacta, simple, legible por humanos e independiente del protocolo.

Los objetos "URI" que pertenecen al esquema geo admiten los métodos comunes.

icap:
El esquema de URI icap se especifica en RFC 3507 http://tools.ietf.org/html/rfc3507. El esquema se usa para referenciar recursos alojados por servidores ICAP.

Los objetos "URI" que pertenecen al esquema icap admiten los métodos comunes, genéricos y de servidor.

icaps:
El esquema de URI icaps se especifica también en RFC 3507 http://tools.ietf.org/html/rfc3507. El esquema se usa para referenciar servidores ICAP a través de conexiones SSL. Su sintaxis es la misma que icap, incluido el mismo puerto predeterminado.
irc:
El esquema de URI irc se especifica en draft-butcher-irc-url-04 https://datatracker.ietf.org/doc/html/draft-butcher-irc-url-04. El esquema se usa para referenciar servidores IRC y sus recursos.

Los objetos "URI" que pertenecen a los esquemas irc o ircs admiten métodos de inicio de sesión y los siguientes métodos específicos de IRC: $uri->entity, $uri->flags, $uri->options.

ldap:
El esquema de URI ldap se especifica en RFC 2255. LDAP es el Protocolo Ligero de Acceso a Directorios. Una URI ldap describe una operación de búsqueda LDAP a realizar para recuperar información de un directorio LDAP.

Los objetos "URI" que pertenecen al esquema ldap admiten los métodos comunes, genéricos y de servidor, así como métodos específicos de ldap: $uri->dn, $uri->attributes, $uri->scope, $uri->filter, $uri->extensions. Consulte URI::ldap para obtener más detalles.

ldapi:
Similar al esquema de URI ldap, pero utiliza un socket de dominio UNIX. Los métodos de servidor no son compatibles, y la ruta del socket local está disponible como $uri->un_path. El esquema ldapi es utilizado por el paquete OpenLDAP. No hay una especificación real para él, pero se menciona en varias páginas del manual de OpenLDAP.
ldaps:
Similar al esquema de URI ldap, pero utiliza una conexión SSL. Este esquema está obsoleto, ya que la forma preferida es usar el mecanismo start_tls.
mailto:
El esquema de URI mailto se especifica en RFC 2368. El esquema se utilizaba originalmente para designar la dirección de correo electrónico de Internet de un individuo o servicio. Se ha ampliado (en RFC 2368) para permitir la configuración de otros campos de encabezado de correo y el cuerpo del mensaje.

Los objetos "URI" que pertenecen al esquema mailto admiten los métodos comunes y los métodos genéricos de consulta. Además, admiten los siguientes métodos específicos de mailto: $uri->to, $uri->headers.

Tenga en cuenta que la parte «foo@example.com» de un mailto *no* es el "userinfo" y el "host", sino el "path". Esto permite que una URI mailto contenga varias direcciones de correo electrónico separadas por comas.

mms:
La especificación de URL mms se puede encontrar en http://sdp.ppona.com/. Los objetos "URI" que pertenecen al esquema mms admiten los métodos comunes, genéricos y de servidor, con la excepción de los subcomponentes relacionados con userinfo y consulta.
news:
Los esquemas de URI news, nntp y snews se especifican en <draft-gilman-news-url-01> y esperemos que estén disponibles como una especificación basada en RFC 2396 pronto. (Actualización: a partir de abril de 2010, están en RFC 5538 https://tools.ietf.org/html/rfc5538.

Los objetos "URI" que pertenecen al esquema news admiten los métodos comunes, genéricos y de servidor. Además, proporcionan algunos métodos para acceder a la ruta: $uri->group y $uri->message.

nntp:
Consulte el esquema news.
nntps:
Consulte el esquema news y RFC 5538 https://tools.ietf.org/html/rfc5538.
otpauth:
El esquema de URI otpauth se especifica en https://github.com/google/google-authenticator/wiki/Key-Uri-Format. El esquema se utiliza para codificar claves secretas para su uso en esquemas TOTP o HOTP.

Los objetos "URI" que pertenecen al esquema otpauth admiten los métodos comunes.

BUGS

  • El uso de variables de expresiones regulares como $1 directamente como argumentos a los métodos de acceso URI no funciona muy bien con las implementaciones actuales de Perl. Argumentaría que esto es realmente un error en Perl. La solución es citarlas. Ejemplo: 
    /(...)/ || die;
$u->query("$1");
  • El escape (codificación por porcentaje) de caracteres en el rango 128 .. 255 pasados al constructor URI o al establecer partes de URI utilizando los métodos de acceso dependen del estado de la bandera interna UTF8 (ver utf8::is_utf8) de la cadena pasada. Si la bandera UTF8 está establecida, la versión codificada en UTF-8 del carácter se codifica por porcentaje. Si la bandera UTF8 no está establecida, la versión Latin-1 (byte) del carácter se codifica por porcentaje. Esto expone básicamente la codificación interna de las cadenas de Perl.

ANÁLISIS DE URIS CON EXPRESIONES REGULARES

Como alternativa a este módulo, la siguiente expresión regular (oficial) se puede utilizar para decodificar una URI:

my($scheme, $authority, $path, $query, $fragment) =
$uri =~ m|(?:([^:/?#]+):)?(?://([^/?#]*))?([^?#]*)(?:\?([^#]*))?(?:#(.*))?|;

El módulo "URI::Split" proporciona la función uri_split() como una alternativa legible.
