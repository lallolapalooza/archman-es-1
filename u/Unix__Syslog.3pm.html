NOMBRE

Unix::Syslog - Interfaz de Perl para las llamadas syslog(3) de UNIX

SINOPSIS

use Unix::Syslog qw(:macros);  # Macros de Syslog
use Unix::Syslog qw(:subs);    # Funciones de Syslog
openlog $ident, $option, $facility;
syslog $priority, $format, @formatargs;
closelog;
$oldmask = setlogmask $mask_priority;

DESCRIPCIÓN

Este módulo proporciona una interfaz al registrador del sistema syslogd(8) a través de las XSUBs de Perl. La implementación intenta parecerse a las funciones nativas de la biblioteca C de su sistema, de modo que cualquiera que esté familiarizado con syslog.h pueda utilizar este módulo de inmediato.

A diferencia de Sys::Syslog(3), este módulo no abre una conexión de red para enviar los mensajes. Esto puede ayudarle a evitar abrir agujeros de seguridad en su ordenador (ver "PREGUNTAS FRECUENTES").

Las subrutinas importadas por la etiqueta "macros" son simplemente envoltorios alrededor de las "#define" más importantes del archivo de cabecera syslog.h de su sistema. Las macros devuelven valores enteros que se utilizan para especificar opciones, instalaciones y prioridades de una manera más o menos portable. También proporcionan información general sobre su mecanismo local de syslog. Consulte syslog(3) y su syslog.h local para obtener información sobre las macros, opciones e instalaciones disponibles en su sistema.

Las siguientes funciones se proporcionan:

openlog $ident, $option, $facility
abre una conexión con el registrador del sistema. $ident es una cadena identificadora que syslogd(8) imprime en cada mensaje. Normalmente equivale al nombre del proceso. $option es un valor entero que es el resultado de opciones ORed. $facility es un valor entero que especifica la parte del sistema con la que se debe asociar el mensaje (por ejemplo, mensaje del kernel, subsistema de correo).
syslog $priority, $format, @formatargs
genera un mensaje de registro y lo pasa al registrador del sistema. Si syslog() se llama sin llamar primero a openlog(), probablemente se utilizarán valores predeterminados dependientes del sistema como argumentos para una llamada implícita a openlog().

$priority es un valor entero que especifica la prioridad del mensaje. Alternativamente, $priority puede ser el valor ORed de una prioridad y una instalación. En ese caso, se anulará una instalación seleccionada previamente.

En caso de que syslog() se llame sin llamar primero a openlog() y priority no especifique tanto una prioridad como una instalación, se utilizará una instalación predeterminada. Este comportamiento es muy probablemente dependiente del sistema y el usuario no debería confiar en ningún valor particular en ese caso.

$format es una cadena de formato al estilo de printf(3). Además de las directivas printf habituales, se puede especificar %m en la cadena. Se reemplazará implícitamente por el contenido de la variable Perl $! ($ERRNO). @formatargs es una lista de valores con los que se reemplazarán posteriormente las directivas de formato.

closelog
cierra la conexión con el registrador del sistema.
setlogmask $mask_priority
establece la máscara de prioridad y devuelve la máscara antigua. El registro se habilita para las prioridades indicadas por los bits en la máscara que están establecidos y se deshabilita donde los bits no están establecidos. Se proporcionan macros para especificar argumentos válidos y portátiles para setlogmask(). Normalmente, la máscara de registro predeterminada permite que se registren todos los mensajes.
priorityname $priority
devuelve una cadena que contiene el nombre de $priority como cadena. Si esta funcionalidad no se habilitó en la instalación, la función devuelve undef.
facilityname $facility
devuelve una cadena que contiene el nombre de $facility como cadena. Si esta funcionalidad no se habilitó en la instalación, la función devuelve undef.

NOTA: El comportamiento de este módulo depende del sistema. Se recomienda encarecidamente consultar el manual de su sistema para ver las macros disponibles y el comportamiento de las funciones proporcionadas.

VALORES DE RETORNO

Las funciones openlog(), syslog() y closelog() devuelven el valor indefinido. La función setlogmask devuelve el valor de la máscara anterior.

EJEMPLOS

Abre un canal a syslogd especificando un identificador (normalmente el nombre del proceso), algunas opciones y la instalación:
"openlog "test.pl", LOG_PID | LOG_PERROR, LOG_LOCAL7;"

Genera un mensaje de registro de la prioridad especificada utilizando una cadena formateada tipo printf:
"syslog LOG_INFO, "Este es el mensaje número %d", 42;"

Establece la máscara de prioridad de registro para bloquear todos los mensajes excepto los de prioridad "LOG_DEBUG":
"$oldmask = setlogmask(LOG_MASK(LOG_DEBUG))"

Establece la máscara de prioridad de registro para bloquear todos los mensajes con una prioridad superior a "LOG_ERR":
"$oldmask = setlogmask(LOG_UPTO(LOG_ERR))"

Cierra el canal a syslogd:
"closelog;"

PREGUNTAS FRECUENTES

1.
¿Cuál es el beneficio de usar este módulo en lugar de Sys::Syslog?

Sys::Syslog siempre abre una conexión de red al servicio syslog. Al menos en sistemas Linux, esto puede causar algunos problemas, porque

  • El syslogd de Linux (del paquete sysklogd) no escucha en la red por defecto. La mayoría de las personas que trabajan en máquinas independientes (incluyéndome a mí) no vieron ninguna razón para habilitar esta opción. Otros no la habilitaron por razones de seguridad.

    Independientemente del sistema operativo, algunos administradores de sistemas pueden ejecutar un firewall en su red que bloquee las conexiones al puerto 514/udp.

  • Por defecto, el syslogd de Linux no reenvía mensajes que ya ha recibido de la red a otros hosts de registro. Hay razones para no habilitar esta opción a menos que sea realmente necesario. Los bucles de mensajes resultantes de una mala configuración pueden colapsar su sistema (de registro).

Peter Stamfest <peter.stamfest@eunet.at> señaló algunas otras ventajas de Unix::Syslog que no se me ocurrieron.

  • LOG_PERROR funciona.
  • funciona con perl -Tw sin advertencias ni problemas debido a datos contaminados como ocurre con Sys::Syslog en algunas aplicaciones especiales. [Especialmente al ejecutar un script como root]
2.
Entonces, ¿hay alguna razón para seguir usando Sys::Syslog?

¡Sí! A diferencia de Unix::Syslog, Sys::Syslog funciona incluso si no tienes un demonio syslog ejecutándose en tu sistema, siempre que estés conectado a un host de registro a través de una red y tengas acceso al archivo de cabecera syslog.h de tu host de registro para generar los archivos iniciales para Sys::Syslog (ver Sys::Syslog(3) para más detalles). Unix::Syslog solo registra en su demonio syslog local, que a su vez puede estar configurado para distribuir el mensaje a través de la red.

3.
¿Son las llamadas a las funciones proporcionadas por Unix::Syslog compatibles con las de Sys::Syslog?

Actualmente no. Sys::Syslog requiere cadenas para especificar muchos de los argumentos de las funciones, mientras que Unix::Syslog utiliza constantes numéricas accedidas a través de macros definidas en s

Unix::Syslog(3pm) - Perl manual page

NAME

Unix::Syslog - Perl interface to the Unix syslog(3) system log

SYNOPSIS

use Unix::Syslog qw(:DEFAULT setlogsock openlog syslogcloselog);
openlog('myprog', 'pid|cons', 'user');
syslog('info', 'this is an informational message');
syslog('warning', 'this is a warning message');
syslog('err', 'this is an error message');
syslogcloselog();

Or using the default constants:

use Unix::Syslog qw(:DEFAULT);
openlog('myprog', LOG_PID | LOG_CONS, LOG_USER);
syslog(LOG_INFO, 'this is an informational message');
syslog(LOG_WARNING, 'this is a warning message');
syslog(LOG_ERR, 'this is an error message');
syslogcloselog();

DESCRIPTION

This module provides a Perl interface to the standard Unix syslog facility.

It exports the following functions and constants:

  • openlog(ident, logopt, facility): Initializes the connection to the syslog daemon. ident is the string that will be prepended to every message. logopt is a bitmask of options (see below). facility is the default facility code for messages.
  • syslog(priority, message): Sends a message to the syslog daemon. priority is the message priority (see below). message is the string to log.
  • syslogcloselog(): Closes the connection to the syslog daemon.
  • setlogsock(socktype): Sets the type of socket used to connect to the syslog daemon. socktype can be undef (use default, usually unix_stream), unix_stream, or udp.

The following constants are exported if :DEFAULT is used:

LOG_KERN, LOG_USER, LOG_MAIL, LOG_DAEMON, LOG_AUTH, LOG_SYSLOG, LOG_LPR, LOG_NEWS, LOG_UUCP, LOG_CRON, LOG_AUTHPRIV, LOG_FTP, LOG_LOCAL0 through LOG_LOCAL7
Facility codes.
LOG_EMERG (or LOG_ALERT), LOG_ALERT (or LOG_CRIT), LOG_CRIT (or LOG_ERR), LOG_ERR (or LOG_WARNING), LOG_WARNING (or LOG_NOTICE), LOG_NOTICE (or LOG_INFO), LOG_INFO (or LOG_DEBUG), LOG_DEBUG
Priority codes. These can be combined with facility codes using the bitwise OR operator (|).
LOG_PRIMASK
Mask to extract priority.
LOG_FACMASK
Mask to extract facility.
LOG_PID
Log option: include PID with each message.
LOG_CONS
Log option: put message on console if there is an error in sending to the logger.
LOG_NDELAY
Log option: open the connection to the logger immediately.
LOG_PERROR
Log option: print message to stderr if it is sent to the system logger.

The syslog function can also accept string equivalents for priorities like 'emerg', 'alert', 'crit', 'err', 'warning', 'notice', 'info', and 'debug'. However, these strings are not exported by default. You would have to explicitly get them from the syslog.h header file.

The openlog function can also accept string equivalents for options like 'pid', 'cons', 'ndelay', and 'perror'. Similarly, it can accept string equivalents for facilities.

If you want to use the string representations, you can import them like this:

use Unix::Syslog qw(openlog syslog syslogcloselog setlogsock
    'info', 'warning', 'err', 'pid', 'cons', 'user');

RETURN VALUES

openlog and syslogcloselog return true on success and false on failure.

syslog returns true on success and false on failure.

setlogsock returns true on success and false on failure.

FAQ

Why do I get a warning 'syslog facility XXX not defined' when I use a string facility name?
This module uses the numeric constants defined in C<syslog.h> under the hood. It does not automatically know the string equivalents. If you want to use string names, you have to explicitly import them as shown in the SYNOPSIS. The module does try to define some common ones.
What about the string based calls in Sys::Syslog?
The strings used by Sys::Syslog are also defined in syslog.h, it seems that most people got used to the numeric arguments. I will implement the string based calls if there are enough people ($min_people > 10**40) complaining about the lack of compatibility.
