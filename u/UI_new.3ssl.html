DESCRIPCIÓN

UI significa User Interface (Interfaz de Usuario), y es un conjunto de rutinas de propósito general para solicitar información al usuario basada en texto. A través de métodos escritos por el usuario (ver UI_create_method(3)), la solicitud puede realizarse de cualquier manera imaginable, ya sea solicitando texto plano, a través de cuadros de diálogo o desde un teléfono móvil.

Todas las funciones operan a través de un contexto de tipo UI. Este contexto contiene toda la información necesaria para solicitar información correctamente, así como una referencia a un UI_METHOD, que es un vector ordenado de funciones que llevan a cabo la solicitud real.

Lo primero que hay que hacer es crear una UI con UI_new() o UI_new_method(), luego añadirle información con las funciones UI_add o UI_dup. Además, se pueden pasar datos aleatorios definidos por el usuario al método subyacente mediante llamadas a UI_add_user_data() o UI_dup_user_data(). El método de UI predeterminado no se preocupa por estos datos, pero otros métodos sí podrían. Finalmente, se utiliza UI_process() para realizar la solicitud y UI_get0_result() y UI_get_result_length() para obtener el resultado de la solicitud y su longitud.

Una UI puede contener más de una solicitud, que se realizan en la secuencia dada. Cada solicitud recibe un número de índice que es devuelto por las funciones UI_add y UI_dup, y debe utilizarse para obtener el resultado correspondiente con UI_get0_result() y UI_get_result_length().

Se puede llamar a UI_process() más de una vez en la misma UI, permitiendo así que una UI tenga una vida útil larga, pero también puede tener una vida útil corta.

Las funciones son las siguientes:

UI_new() crea una nueva UI utilizando el método de UI predeterminado. Cuando se haya terminado con esta UI, se debe liberar con UI_free().

UI_new_method() crea una nueva UI utilizando el método de UI dado. Cuando se haya terminado con esta UI, se debe liberar con UI_free().

UI_OpenSSL() devuelve el método de UI incorporado (nota: no necesariamente el predeterminado, ya que el predeterminado puede cambiarse. Ver más adelante). Este método es la parte más dependiente de la máquina/SO de OpenSSL y normalmente genera la mayoría de los problemas al portar.

UI_null() devuelve un método de UI que no hace nada. Su uso es para evitar obtener valores predeterminados internos para los punteros UI_METHOD pasados.

UI_free() elimina una UI de la memoria, junto con todas las demás piezas de memoria que están conectadas a ella, como cadenas de entrada duplicadas, resultados y otros. Si ui es NULL, no se hace nada.

UI_add_input_string() y UI_add_verify_string() añaden una solicitud a la UI, así como flags y un buffer de resultados, y los tamaños mínimo y máximo deseados del resultado, sin contar el carácter NUL final. La información proporcionada se utiliza para solicitar información, por ejemplo, una contraseña, y para verificar una contraseña (es decir, solicitar al usuario que la introduzca dos veces y comprobar que se introdujo la misma cadena dos veces). UI_add_verify_string() toma un argumento extra que debe ser un puntero al buffer de resultados de la cadena de entrada que se supone que debe verificar, o la verificación fallará.

UI_add_input_boolean() añade una solicitud a la UI que se supone que debe responder de forma booleana, con un solo carácter para sí y otro carácter diferente para no. También se proporciona un conjunto de caracteres que se pueden utilizar para cancelar la solicitud. La solicitud en sí está dividida en dos partes: una es el texto descriptivo (proporcionado a través del argumento prompt) y otra describe las respuestas posibles (proporcionado a través del argumento action_desc).

UI_add_info_string() y UI_add_error_string() añaden cadenas que se muestran al mismo tiempo que la solicitud para obtener información adicional o para mostrar una cadena de error. La diferencia entre ambas es solo conceptual. Con el método incorporado, no hay diferencia técnica entre ellas. Otros métodos pueden hacer una diferencia entre ellas, sin embargo.

Los flags actualmente soportados son UI_INPUT_FLAG_ECHO, que es relevante para UI_add_input_string() y hará que la respuesta del usuario sea mostrada (cuando se solicite una contraseña, este flag obviamente no debe usarse, y UI_INPUT_FLAG_DEFAULT_PWD, que significa que se utilizará una contraseña predeterminada de algún tipo (dependiendo completamente de la aplicación y del método de UI)).

UI_dup_input_string(), UI_dup_verify_string(), UI_dup_input_boolean(), UI_dup_info_string() y UI_dup_error_string() son básicamente lo mismo que sus homólogos UI_add, excepto que crean sus propias copias de todas las cadenas.

UI_construct_prompt() es una función auxiliar que puede ser utilizada para crear una solicitud a partir de dos piezas de información: una descripción de frase phrase_desc y un nombre de objeto object_name, donde este último puede ser NULL. El constructor predeterminado (si no hay ninguno proporcionado por el método utilizado) crea una cadena "Enter phrase_desc for object_name:" donde la parte " for object_name" se omite si object_name es NULL. Con la descripción "pass phrase" y el nombre de archivo "foo.key", eso se convierte en "Enter pass phrase for foo.key:". Otros métodos pueden crear cualquier cadena y pueden incluir codificaciones que serán procesadas por las otras funciones del método.

UI_add_user_data() añade un puntero de datos de usuario para que el método lo utilice en cualquier momento. El método de UI incorporado no se preocupa por esta información. Tenga en cuenta que varias llamadas a esta función no añaden datos, sino que reemplazan el bloque anterior con el dado como argumento.

UI_dup_user_data() duplica los datos del usuario y funciona como una alternativa a UI_add_user_data() cuando los datos del usuario necesitan ser preservados durante un período de tiempo más largo, quizás incluso la vida útil de la aplicación. El objeto UI toma posesión de este duplicado y lo liberará siempre que sea reemplazado o que la UI sea destruida. UI_dup_user_data() devuelve 0 en caso de éxito, o -1 en caso de fallo de asignación de memoria o si el método no tiene una función duplicadora.

UI_get0_user_data() recupera los datos que han sido dados por última vez a la UI con UI_add_user_data() o UI_dup_user_data.

UI_get0_result() devuelve un puntero al buffer de resultados asociado con la información indexada por i.

UI_process() recorre la información proporcionada hasta el momento, realiza todas las impresiones y solicitudes, y devuelve el estado final, que es -2 para eventos fuera de banda (Interrupción, Cancelar, ...), -1 en caso de error y 0 si tiene éxito.

UI_ctrl() añade control adicional para el autor de la aplicación. Por ahora, entiende dos comandos: UI_CTRL_PRINT_ERRORS, que hace que UI_process() imprima la pila de errores de OpenSSL como parte del procesamiento de la interfaz de usuario, y UI_CTRL_IS_REDOABLE, que devuelve una bandera indicando si la interfaz de usuario utilizada puede ser utilizada de nuevo o no.

UI_set_default_method() cambia el método de interfaz de usuario predeterminado al proporcionado. Esta función no es segura para hilos y no debe ser llamada al mismo tiempo que otras funciones de OpenSSL.

UI_get_default_method() devuelve un puntero al método de interfaz de usuario predeterminado actual.

UI_get_method() devuelve el método de interfaz de usuario asociado con una interfaz de usuario dada.

UI_set_method() cambia el método de interfaz de usuario asociado con una interfaz de usuario dada.

NOTAS

Se asume que las cadenas resultantes que genera el método incorporado UI_OpenSSL() están codificadas según la configuración regional actual o (para Windows) la página de códigos. Para aplicaciones con demandas diferentes, estas cadenas deben ser convertidas apropiadamente por el llamante. Para Windows, si la variable de entorno OPENSSL_WIN32_UTF8 está configurada, el método incorporado UI_OpenSSL() producirá cadenas codificadas en UTF-8 en su lugar.

VALORES DE RETORNO

UI_new() y UI_new_method() devuelven una estructura UI válida o NULL si ocurrió un error.

UI_add_input_string(), UI_dup_input_string(), UI_add_verify_string(), UI_dup_verify_string(), UI_add_input_boolean(), UI_dup_input_boolean(), UI_add_info_string(), UI_dup_info_string(), UI_add_error_string() y UI_dup_error_string() devuelven un número positivo en caso de éxito o un valor menor o igual a 0 en caso contrario.

UI_construct_prompt() devuelve una cadena o NULL si ocurrió un error.

UI_dup_user_data() devuelve 0 en caso de éxito o -1 en caso de error.

UI_get0_result() devuelve una cadena o NULL en caso de error.

UI_get_result_length() devuelve un entero positivo o 0 en caso de éxito; de lo contrario, devuelve -1 en caso de error.

UI_process() devuelve 0 en caso de éxito o un valor negativo en caso de error.

UI_ctrl() devuelve una máscara en caso de éxito o -1 en caso de error.

UI_get_default_method(), UI_get_method(), UI_OpenSSL(), UI_null() y UI_set_method() devuelven respectivamente una estructura UI_METHOD válida o NULL.
