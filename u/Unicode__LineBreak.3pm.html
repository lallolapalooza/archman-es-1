Unicode::LineBreak(3) Documentación de Perl contribuida por el usuario Unicode::LineBreak(3)

NOMBRE

Unicode::LineBreak - Algoritmo de saltos de línea de Unicode UAX #14

SINOPSIS

use Unicode::LineBreak;
$lb = Unicode::LineBreak->new();
$broken = $lb->break($string);

DESCRIPCIÓN

Unicode::LineBreak realiza el Algoritmo de Saltos de Línea descrito en el Anexo #14 del Estándar Unicode [UAX #14]. La propiedad informativa East_Asian_Width definida por el Anexo #11 [UAX #11] será considerada para determinar las posiciones de salto.

Terminología

Los siguientes términos se utilizan para conveniencia.

Salto obligatorio es un comportamiento de salto de línea obligatorio definido por reglas centrales y realizado independientemente de los caracteres circundantes. Salto arbitrario es un comportamiento de salto de línea permitido por reglas centrales y elegido por el usuario para realizarlo. El salto arbitrario incluye salto directo y salto indirecto definidos por [UAX #14].

Caracteres alfabéticos son caracteres entre los cuales generalmente no se permiten saltos de línea, excepto que otros caracteres proporcionen oportunidades de salto. Caracteres ideográficos son caracteres que generalmente permiten saltos de línea antes y después de ellos. [UAX #14] clasifica la mayoría de los caracteres alfabéticos como AL y la mayoría de los ideográficos como ID (estos términos son inexactos desde el punto de vista de la gramatología). En varios guiones, las posiciones de salto no son obvias para cada carácter, por lo que se utiliza heurística basada en diccionarios.

El número de columnas de una cadena no es siempre igual al número de caracteres que contiene: cada uno de los caracteres es ancho, estrecho o no espaciador; ocupan 2, 1 o 0 columnas, respectivamente. Varios caracteres pueden ser tanto anchos como estrechos según los contextos en los que se utilicen. Los caracteres pueden tener anchos más variados mediante personalización.

Obtener información

breakingRule (ANTESDE, DESPUESDE)
Método de instancia. Obtiene el comportamiento de salto de línea posible entre las cadenas ANTESDE y DESPUESDE. Consulte "Constantes" para el valor devuelto.

Nota: Este método solo proporciona una descripción aproximada del comportamiento de salto de línea. Utilice break() y otros para ajustar textos reales.

Opciones

Los métodos "new" y "config" aceptan los siguientes pares. Algunos de ellos afectan el número de columnas ([E]), la segmentación de clústeres de grafemas ([G]) (ver también Unicode::GCString) o el comportamiento de salto de línea ([L]).

BreakIndent => "SÍ" | "NO"
[L] Siempre permite saltar después de los ESPACIOS al principio de la línea, también conocido como sangría. [UAX #14] no tiene en cuenta dicho uso de ESPACIO. El valor predeterminado es "SÍ".

Nota: Esta opción se introdujo en la versión 1.011.

CharMax => NÚMERO
[L] Número máximo posible de caracteres en una línea, sin contar los ESPACIOS finales y la secuencia de nueva línea. Tenga en cuenta que el número de caracteres generalmente no representa la longitud de la línea. El valor predeterminado es 998. 0 significa ilimitado (a partir de la versión 2012.01).
ColMin => NÚMERO
[L] Número mínimo de columnas que una línea rota arbitrariamente puede incluir, sin contar los espacios finales y las secuencias de nueva línea. El valor predeterminado es 0.
ColMax => NÚMERO
[L] Número máximo de columnas que una línea puede incluir sin contar los espacios finales y la secuencia de nueva línea. En otras palabras, la longitud máxima de la línea. El valor predeterminado es 76.

Ver también la opción "Urgent" y "Comportamientos de Salto de Línea Definidos por el Usuario".

ComplexBreaking => "SÍ" | "NO"
[L] Realiza saltos heurísticos en contextos complejos del sudeste asiático. El valor predeterminado es, si la segmentación de palabras para sistemas de escritura del sudeste asiático está habilitada, "SÍ".
Context => CONTEXTO
[E][L] Especifica el contexto de idioma/región. Actualmente, los contextos disponibles son "EASTASIAN" y "NONEASTASIAN". El contexto predeterminado es "NONEASTASIAN".

En el contexto "EASTASIAN", los caracteres con la propiedad East_Asian_Width ambigua (A) se tratan como "anchos" y con la clase de salto de línea AI como ideográficos (ID).

En el contexto "NONEASTASIAN", los caracteres con la propiedad East_Asian_Width ambigua (A) se tratan como "estrechos" y con la clase de salto de línea AI como alfabéticos (AL).

EAWidth => "[" ORD "=>" PROPERTY "]"
EAWidth => "undef"
[E] Adapta la clasificación de la propiedad East_Asian_Width. ORD es el valor escalar UCS del carácter o una referencia de array de ellos. PROPERTY es uno de los valores de propiedad East_Asian_Width y valores extendidos (ver "Constantes"). Esta opción se puede especificar varias veces. Si se especifica "undef", todas las adaptaciones asignadas anteriormente se cancelarán.

Por defecto, no hay adaptaciones disponibles. Ver también "Adaptación de Propiedades de Caracteres".

Format => METODO
[L] Especifica el método para formatear las líneas rotas.
"SIMPLE"
Método predeterminado. Simplemente inserta saltos de línea en posiciones de salto arbitrarias.
"NEWLINE"
Inserta o reemplaza secuencias de nueva línea con la especificada por la opción "Newline", elimina los ESPACIOS que preceden a las secuencias de nueva línea o al final del texto. Luego, añade una nueva línea al final del texto si no existe.
"TRIM"
Inserta saltos de línea en posiciones de salto arbitrarias. Elimina los ESPACIOS que preceden a las secuencias de nueva línea.
"undef"
No hace nada, ni siquiera inserta saltos de línea.

Calcular Tamaño de Cadena

Si especifica una referencia a subrutina como valor de la opción "Sizing", se llamará con cinco argumentos:

$COLS = \&subroutine(SELF, LEN, PRE, SPC, STR);

SELF es un objeto Unicode::LineBreak, LEN es el tamaño de la cadena precedente, PRE es la cadena Unicode precedente, SPC son ESPACIOS adicionales y STR es una cadena Unicode a procesar.

La subrutina debe devolver el número calculado de columnas de "PRE.SPC.STR". El número de columnas puede no ser un entero: la unidad del número puede elegirse libremente, sin embargo, debe ser la misma que la de las opciones "ColMin" y "ColMax".

Nota: Los argumentos de cadena son en realidad secuencias de clústeres de grafemas. Ver Unicode::GCString.

Por ejemplo, el siguiente código procesa líneas con tabulaciones cada ocho columnas.

sub tabbedsizing {
    my ($self, $cols, $pre, $spc, $str) = @_;

    my $spcstr = $spc.$str;
    while ($spcstr->lbc == LB_SP) {
        my $c = $spcstr->item(0);
        if ($c eq "\t") {
            $cols += 8 - $cols % 8;
        } else {
            $cols += $c->columns;
        }
        $spcstr = $spcstr->substr(1);
    }
    $cols += $spcstr->columns;
    return $cols;
};
my $lb = Unicode::LineBreak->new(LBClass => [ord("\t") => LB_SP],
                                 Sizing => \&tabbedsizing);
$output = $lb->break($string);

Personalización de Propiedades de Carácter

Las propiedades de los caracteres se pueden personalizar mediante las opciones "LBClass" y "EAWidth". Se definen algunas constantes para facilitar la personalización.

Propiedades de Salto de Línea

No iniciadores de Caracteres tipo Kana

Por defecto, varios hiragana, katakana y caracteres correspondientes a kana se tratan como no iniciadores (NS o CJ). Cuando se especifican los siguientes pares para el valor de la opción "LBClass", estos caracteres se tratan como caracteres ideográficos normales (ID).

"KANA_NONSTARTERS() => LB_ID"
Todos los caracteres a continuación.
"IDEOGRAPHIC_ITERATION_MARKS() => LB_ID"
Marcas de iteración ideográficas. U+3005 MARCA DE ITERACIÓN IDEOGRÁFICA, U+303B MARCA DE ITERACIÓN IDEOGRÁFICA VERTICAL, U+309D MARCA DE ITERACIÓN HIRAGANA, U+309E MARCA DE ITERACIÓN HIRAGANA CON SONIDO, U+30FD MARCA DE ITERACIÓN KATAKANA y U+30FE MARCA DE ITERACIÓN KATAKANA CON SONIDO.

N.B. Algunos de ellos no son ni hiragana ni katakana.

"KANA_SMALL_LETTERS() => LB_ID"
"KANA_PROLONGED_SOUND_MARKS() => LB_ID"
Letras pequeñas hiragana o katakana: letras pequeñas hiragana U+3041 A, U+3043 I, U+3045 U, U+3047 E, U+3049 O, U+3063 TU, U+3083 YA, U+3085 YU, U+3087 YO, U+308E WA, U+3095 KA, U+3096 KE. Letras pequeñas katakana U+30A1 A, U+30A3 I, U+30A5 U, U+30A7 E, U+30A9 O, U+30C3 TU, U+30E3 YA, U+30E5 YU, U+30E7 YO, U+30EE WA, U+30F5 KA, U+30F6 KE. Extensiones fonéticas katakana U+31F0 KU - U+31FF RO. Letras pequeñas katakana de ancho reducido U+FF67 A - U+FF6F TU.

Marcas de sonido prolongado hiragana o katakana: U+30FC MARCA DE SONIDO PROLONGADO KATAKANA-HIRAGANA y U+FF70 MARCA DE SONIDO PROLONGADO KATAKANA-HIRAGANA DE ANCHO REDUCIDO.

N.B. Estas letras se tratan opcionalmente como no iniciadores o como ideográficas normales. Ver [JIS X 4051] 6.1.1, [JLREQ] 3.1.7 o [UAX14].

N.B. U+3095, U+3096, U+30F5, U+30F6 no se consideran ni hiragana ni katakana.

"MASU_MARK() => LB_ID"
U+303C MARCA MASU.

N.B. Aunque este carácter no es kana, se considera generalmente como una abreviatura de la secuencia de hiragana ま す o katakana マ ス, MA y SU.

N.B. Este carácter está clasificado como no iniciador (NS) por [UAX #14] y como la clase correspondiente a ID por [JIS X 4051] y [JLREQ].

Comillas Ambiguas

Por defecto, algunos signos de puntuación son comillas ambiguas (QU).

"BACKWARD_QUOTES() => LB_OP, FORWARD_QUOTES() => LB_CL"
Algunos idiomas (neerlandés, inglés, italiano, portugués, español, turco y la mayoría de Asia Oriental) usan signos de puntuación al estilo "9 girado" (‘ “) como comillas de apertura y signos de puntuación al estilo "9" (“ ”) como comillas de cierre.
"FORWARD_QUOTES() => LB_OP, BACKWARD_QUOTES() => LB_CL"
Otros (checo, alemán y eslovaco) usan signos de puntuación al estilo "9" (’ ”) como de apertura y signos de puntuación al estilo "9 girado" (‘ “) como de cierre.
"BACKWARD_GUILLEMETS() => LB_OP, FORWARD_GUILLEMETS() => LB_CL"
Francés, griego, ruso, etc., usan guillemets de apertura (guiones angulares) hacia la izquierda (« ‹) como apertura y guillemets hacia la derecha (» ›) como cierre.
"FORWARD_GUILLEMETS() => LB_OP, BACKWARD_GUILLEMETS() => LB_CL"
Alemán y eslovaco usan guillemets hacia la derecha (» ›) como apertura y guillemets hacia la izquierda (« ‹) como cierre.

Danés, finlandés, noruego y sueco usan signos de puntuación al estilo "9" o hacia la derecha (’ ” » ›) tanto como apertura como cierre.

ESPACIO IDEOGRÁFICO

"IDEOGRAPHIC_SPACE() => LB_BA"
U+3000 ESPACIO IDEOGRÁFICO no se colocará al principio de la línea. Este es el comportamiento por defecto.
"IDEOGRAPHIC_SPACE() => LB_ID"
El ESPACIO IDEOGRÁFICO puede colocarse al principio de la línea. Este era el comportamiento por defecto según Unicode 6.2 y anteriores.
"IDEOGRAPHIC_SPACE() => LB_SP"
El ESPACIO IDEOGRÁFICO no se colocará al principio de la línea y sobresaldrá del final de la línea.

Propiedades East_Asian_Width

Algunos caracteres particulares de los scripts latino, griego y cirílico tienen una propiedad East_Asian_Width ambigua (A). Por lo tanto, estos caracteres se tratan como anchos en el contexto de "EASTASIAN". Al especificar "EAWidth => [ AMBIGUOUS_"*"() => EA_N ]", estos caracteres se tratan siempre como estrechos.

"AMBIGUOUS_ALPHABETICS() => EA_N"
Trata todos los caracteres a continuación como neutros de East_Asian_Width (N).
"AMBIGUOUS_CYRILLIC() => EA_N"
"AMBIGUOUS_GREEK() => EA_N"
"AMBIGUOUS_LATIN() => EA_N"
Trata las letras que tienen ancho ambiguo (A) de los scripts cirílico, griego y latino como neutros (N).

Por otro lado, a pesar de que varios caracteres fueron renderizados ocasionalmente como caracteres anchos por varias implementaciones para conjuntos de caracteres de Asia Oriental, se les da la propiedad East_Asian_Width estrecha (Na) solo porque tienen caracteres de compatibilidad de ancho completo (F). Al especificar "EAWidth" como se indica a continuación, estos caracteres se tratan como ambiguos: anchos en el contexto de "EASTASIAN".

"QUESTIONABLE_NARROW_SIGNS() => EA_A"
U+00A2 SIGNO DE CENT, U+00A3 SIGNO DE LIBRAS, U+00A5 SIGNO DE YEN (o signo de yuan), U+00A6 BARRA ROTA, U+00AC SIGNO DE NEGACIÓN, U+00AF MACRÓN.

    NAME
    

    Unicode::LineBreak — Unicode Line Breaking Algorithm
    

    

    

    SYNOPSIS
    

     use Unicode::LineBreak qw( :all );

 my $string = "This is a test string.";
 my @breaks = line_break_points($string);
 print $string, "\n";
 my $pos = 0;
 for my $break (@breaks) {
   print substr($string, $pos, $break - $pos), "\n";
   $pos = $break;
 }

    

    

    

    DESCRIPTION
    

    This module implements the Unicode Line Breaking Algorithm (UAX #14).
    

    It identifies potential line break opportunities within a given
    Unicode string. The algorithm is based on assigning properties to characters
    and defining rules for breaking based on these properties.
    

    

    

    PUBLIC INTERFACE
    

    
  
    line_break_points
    
  
    Takes a string as input and returns an array of indices where line breaks
      are permitted. These indices are character offsets, not byte offsets.
    
  
    line_break_classes
    
  
    Takes a string as input and returns a hash where keys are character indices
      and values are the corresponding line break classes for the character at
      that index.
    
  
    is_line_break
    
  
    Takes two character indices, prev and curr,
      representing the previous and current character positions. It returns true
      if a line break is allowed between these two positions according to the
      Unicode Line Breaking Algorithm, and false otherwise.
    

    

    The following constants can be exported by tagging:
    

    
  
    :all
    
  
    Exports all public symbols.
    

    

    

    

    CUSTOMIZATION
    

    This module adheres strictly to the Unicode Line Breaking Algorithm
    specification. Customization of line breaking rules is not supported.
    

    

    

    BUGS
    

    Please report bugs to the CPAN bug tracker for this module.

    Unicode::LineBreak.
    

    

    

    IMPLEMENTATION NOTES
    

    The line breaking properties are derived from the Unicode Character
    Database (UCD) file LineBreak.txt.
    

    The algorithm classifies characters into different line breaking
    classes. Some classes are specific to certain languages or scripts. The
    algorithm defines rules based on the combination of classes of adjacent
    characters.
    

    Special handling is applied to certain characters, including:
    

      
  
    • Combining marks (General Category Mn, Me) are generally treated as non-breaking
      when following their base character.
      • 
  
    • Format characters (General Category Cf) are ignored for line breaking purposes.
      • 
  
    • Surrogate code points are handled according to Unicode standards.
      •
