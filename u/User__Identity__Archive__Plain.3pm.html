NOMBRE

User::Identity::Archive::Plain - archivador simple de texto plano

HERENCIA

User::Identity::Archive::Plain
  es un User::Identity::Archive
  es un User::Identity::Item

SINOPSIS

use User::Identity::Archive::Plain;
my $amigos = User::Identity::Archive::Plain->new('amigos');
$amigos->from(\*FH);
$amigos->from('.amigos');

DESCRIPCIÓN

Este archivador, que extiende User::Identity::Archive, utiliza un archivo de texto plano muy simple para almacenar la información de los usuarios. La sintaxis se describe en la sección DETALLES, más abajo.

DETALLES

El formato del archivador de texto plano

Nombres de clase simplificados

Es demasiado trabajo especificar nombres de clase completos en cada lugar donde quieras crear un nuevo objeto con datos. Por lo tanto, se introducen abreviaturas. Usa new(abreviaturas) o abreviaturas() para añadir abreviaturas adicionales o para anular algunas predefinidas.

Nombres predefinidos:
user User::Identity
email Mail::Identity
location User::Identity::Location
system User::Identity::System
list User::Identity::Collection::Emails

Habría sido más agradable referirse a una persona en lugar de a un usuario, sin embargo, eso aumentaría la confusión con el espacio de nombres.

La indentación lo dice todo

La sintaxis es lo más simple posible. Una indentación adicional en una línea significa que la variable o clase es una colección dentro de la clase de la línea anterior.

user markov
  location home
     country NL
  email home
     address  mark@overmeer.net
     location home
  email work
     address  solutions@overmeer.bet
email tux
   address tux@fish.net

Lo anterior define dos elementos: un User::Identity llamado "markov" y una dirección de correo electrónico "tux". El usuario tiene dos colecciones: una contiene una única ubicación y otra almacena dos direcciones de correo electrónico.

Para añadir confusión: la "location" se define como campo en "email" y como colección. La diferencia se detecta fácilmente: si hay campos indentados después de la línea, es una colección. Los errores, en la mayoría de los casos, resultarán en un mensaje de error.

Líneas largas

Si deseas continuar en la siguiente línea, porque tu contenido es demasiado grande, añade una barra invertida al final, así:

email home
   description Esta es mi dirección de casa,     \
               Pero a veces uso esta para \
               el trabajo también
   address tux@fish.aq

Las continuaciones no siguen las reglas de indentación, así que lo que también puedes hacer es:

email home
   description               \
Esta es mi dirección de casa,     \
Pero a veces uso esta para

User::Identity::Archive::Plain(3pm)

NAME

User::Identity::Archive::Plain — write and read plain text user identity files.

INHERITANCE

This module is part of the User::Identity distribution.

SYNOPSIS

  use User::Identity::Archive::Plain;

  # create a new archive
  my $archive = User::Identity::Archive::Plain->new(
      file => '/path/to/my/users.txt',
  );

  # add some users
  $archive->add( User::Identity->new( name => 'markov' ) );

  # get a user
  my $user = $archive->get('markov');

  # store the archive
  $archive->store;

  # load an existing archive
  my $archive2 = User::Identity::Archive::Plain->load(
      file => '/path/to/my/users.txt',
  );

DESCRIPTION

This archive module implements the storage of user identity information in plain text files. The format is simple and very readable.

The identity information is structured into records. Each record describes one person or organization. A record starts with the keyword user, person or organization, followed by the name of the record. All following lines until the next record starts or the file ends are part of the record. Fields are identified by a keyword, followed by the value.

Example of a file:

  user markov
     name       Mark Overmeer
     email      markov@overmeer.net
     email      markov@cpan.org
     location   Amsterdam
     active     yes

  person Cleo
     name       Cleo
     location   Zutphen
     email      cleo@example.org

  organization MARKOV Solutions
     address    Grotegracht 72
     address    6211 GW Maastricht
     zip        6211 GW Maastricht
     city       Maastricht
     country    NL
     phone      +31 43 3260075
     email      info@markov.nl

The lines are parsed with Text::ParseWords with the option '’' set. This means that single quotes are ignored, and spaces within quotes are preserved.

user "some user"
   email home='my home email'
   address      \" Amsterdam \"

will be parsed as:

user some user
   email home my home email
   address      " Amsterdam "

The first line of a record must start with user, person or organization. The name follows immediately. If the name contains spaces, it must be quoted. The name of the record is used as the unique identifier for the record within the archive.

All other lines in a record are fields. Fields are specified as keyword = value. The keyword is a simple string, the value is the rest of the line. If the value contains spaces, it will be split into words, unless the value is quoted. The parsing is done on a line-by-line basis.

There are some special fields:

description
A textual description of the person or organization. This field can be used multiple times, in which case the values are concatenated. The parser recognizes quoted strings as single values.
email
The email address of the person or organization. This field can be used multiple times. The values are returned as a list.
location
The location of the person or organization. This field can be used multiple times. The values are returned as a list.
address
The street address. This field can be used multiple times. The values are returned as a list.

The User::Identity::Archive::Plain module tries to be tolerant about the format. It will ignore empty lines and lines starting with a hash (#) character, which are treated as comments.

OVERLOADED

None.

METHODS

The following methods are available:

new( \%args )
Creates a new, empty archive. The following arguments are recognized:
file
The name of the file to be used for storing the archive.
directory
The directory where the archive file should be created.
permissions
The file permissions to use for the created file (e.g. 0644).
load( \%args )
Loads an archive from the specified file. The following arguments are recognized:
file (required)
The name of the file to load.
store()
Stores the current archive content to the file specified in the constructor. This method will overwrite the existing file.
add( $user )
Adds a User::Identity object to the archive.
get( $name )
Retrieves a User::Identity object by its name.
remove( $name )
Removes a user from the archive by its name.
users()
Returns a list of all user names in the archive.
export()
Exports the archive content as a data structure.

DETAILS

The parsing of the file is done line by line. Empty lines and lines starting with a '#' are ignored.

Lines starting with 'user', 'person' or 'organization' indicate the start of a new record. The name follows immediately. If the name contains spaces, it must be quoted.

All other lines are considered fields. A field consists of a key and a value, separated by whitespace. The key is the first word on the line. The value is the rest of the line.

If the value contains spaces, it will be split into words, unless the entire value is enclosed in quotes. For example:

user test
   address 123 Main Street Anytown
   address "456 Oak Avenue, Sometown"

will be parsed as:

user test
   address 123 Main Street Anytown
   address 456 Oak Avenue, Sometown

Special fields:

email
Multiple email addresses are allowed. They are stored as a list.
location
Multiple locations are allowed. They are stored as a list.
address
Multiple address lines are allowed. They are stored as a list.

The module uses File::Slurp for reading and writing files.

When writing the file, the module uses the specified permissions. If no permissions are specified, the default is 0644. The directory permissions are not explicitly set.

When storing the archive, the module will format the output nicely. Fields will be indented, and comments will be added where appropriate. Lines that are part of a multi-line value (e.g., address) will be indented to align with the first line of the value.

user test
   name       Test User
   email      test@example.com
   address    123 Main Street
              Anytown
              CA 12345
   address    work
      organization   Test Corp
      street         456 Second Avenue
      city           Metropolis
      zip            67890
      country        US
   work well
   address tux@fish.aq

The fields "comment" and "address" must be correctly indented. The line terminations are lost, which is useful for most fields. However, if you need them, you have to check the description of the applicable field.

Comments

You may add comments and white spaces. Comments start with a '#' as first non-blank character on the line. Comments are not allowed on the same line as real data, as some languages (like Perl) permit.

You can insert comments and blank lines on all places where you need them:

user markov
   # my home address
   email home
      # useless comment statement
      address tux@fish.aq
      location #mind_the_hash

is equivalent to:

user markov
   email home
      address tux@fish.aq
      location #mind_the_hash

References

Often you will have the need to add the same information to two items, for instance, multiple people share the same address. In this case, you can create a reference. However, this is only permitted for whole items: you can refer to someone's location, but not to the person's street.

To create a reference to an item of someone else, use

user markov
   location home = user(cleo).location(home)
   location work
      organization   MARKOV Solutions

Configuration parameters

You can add some configuration lines as well. On the moment, the only one defined is

tabstop = 4

which can be used to change the meaning of tabs in the file. The default setting is 8, but some people prefer 4 (or other values).

DIAGNOSTICS

Error: $object is not a collection.
The first argument is an object, but not of a class which extends User::Identity::Collection. Cast by addCollection()
Error: Cannot load collection module for $type ($class).
Either the specified $type does not exist, or that module named $class returns compilation errors. If the type as specified in the warning is not the name of a package, you specified a nickname which was not defined. Maybe you forgot the 'require' the package which defines the nickname. Cast by addCollection()
Warning: Cannot read archive from $source
Cast by from()
Error: Creation of a collection via $class failed.
The $class did compile, but it was not possible to create an object of that class using the options you specified. Cast by addCollection()
Error: Don't know what type of collection you want to add.
If you add a collection, it must either by a collection object or a list of options which can be used to create a collection object. In the latter case, the type of collection must be specified. Cast by addCollection()
Warning: No collection $name
The collection with $name does not exist and can not be created. Cast by add()
