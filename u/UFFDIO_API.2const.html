UFFDIO_API(2const) UFFDIO_API(2const)

NOMBRE

UFFDIO_API - habilitar la operación del userfaultfd y realizar el apretón de manos de la API

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/userfaultfd.h>  /* Definición de constantes UFFD* */
#include <sys/ioctl.h>
int ioctl(int fd, UFFDIO_API, struct uffdio_api *argp);
#include <linux/userfaultfd.h>
struct uffdio_api {
    __u64 api;       /* Versión de la API solicitada (entrada) */
    __u64 features;  /* Características solicitadas (entrada/salida) */
    __u64 ioctls;    /* Operaciones ioctl() disponibles (salida) */
};

DESCRIPCIÓN

Habilita la operación del userfaultfd y realiza el apretón de manos de la API.

El campo api indica la versión de la API solicitada por la aplicación. El kernel verifica que pueda admitir la versión de la API solicitada y establece los campos features e ioctls a máscaras de bits que representan todas las características disponibles y las operaciones ioctl(2) genéricas disponibles.

Antes de Linux 4.11, el campo features debe inicializarse a cero antes de la llamada a UFFDIO_API, y se coloca cero (es decir, sin bits de características) en el campo features por el kernel al regresar de ioctl(2).

Desde Linux 4.11, userfaultfd admite características que deben habilitarse explícitamente. Para habilitar cualquiera de las características, es necesario establecer los bits de características correspondientes en features al emitir el ioctl UFFDIO_API.

Por razones históricas, se necesita un userfaultfd temporal para sondear qué características de userfaultfd admite el kernel. La aplicación necesita crear un userfaultfd temporal, emitir un ioctl UFFDIO_API con features establecido a cero. Después de que el ioctl UFFDIO_API regrese con éxito, features contendrá todas las características de userfaultfd que el kernel admite. El userfaultfd temporal puede cerrarse de forma segura después de la sondeo.

Si la aplicación establece bits de características no admitidos, el kernel pondrá a cero la estructura uffdio_api devuelta y devolverá EINVAL.

Los siguientes bits de características pueden establecerse:

UFFD_FEATURE_EVENT_FORK (desde Linux 4.11)
Cuando esta característica está habilitada, los objetos userfaultfd asociados con un proceso padre se duplican en el proceso hijo durante fork(2) y se entrega un evento UFFD_EVENT_FORK al monitor de userfaultfd.
UFFD_FEATURE_EVENT_REMAP (desde Linux 4.11)
Si esta característica está habilitada, cuando el proceso que causa la excepción invoca mremap(2), el monitor de userfaultfd recibirá un evento de tipo UFFD_EVENT_REMAP.
UFFD_FEATURE_EVENT_REMOVE (desde Linux 4.11)
Si esta característica está habilitada, cuando el proceso que causa la excepción llama a madvise(2) con el valor de consejo MADV_DONTNEED o MADV_REMOVE para liberar un área de memoria virtual, el monitor de userfaultfd recibirá un evento de tipo UFFD_EVENT_REMOVE.
UFFD_FEATURE_EVENT_UNMAP (desde Linux 4.11)
Si esta característica está habilitada, cuando el proceso que causa la excepción anula el mapeo de memoria virtual ya sea explícitamente con munmap(2), o implícitamente durante mmap(2) o mremap(2), el monitor de userfaultfd recibirá un evento de tipo UFFD_EVENT_UNMAP.
UFFD_FEATURE_MISSING_HUGETLBFS (desde Linux 4.11)
Si este bit de característica está establecido, el kernel admite el registro de rangos de userfaultfd en áreas de memoria virtual hugetlbfs.
UFFD_FEATURE_MISSING_SHMEM (desde Linux 4.11)
Si este bit de característica está establecido, el kernel admite el registro de rangos de userfaultfd en áreas de memoria compartida. Esto incluye todas las API de memoria compartida del kernel: memoria compartida de System V, tmpfs(5), mapeos compartidos de /dev/zero, mmap(2) con el flag MAP_SHARED establecido, memfd_create(2), y así sucesivamente.
UFFD_FEATURE_SIGBUS (desde Linux 4.14)
Si este bit de característica está establecido, no se entregarán eventos de excepción de página (UFFD_EVENT_PAGEFAULT). En cambio, se enviará una señal SIGBUS al proceso que causa la excepción. Las aplicaciones que utilizan esta característica no requerirán el uso de un monitor de userfaultfd para procesar accesos a memoria a las regiones registradas con userfaultfd.
UFFD_FEATURE_THREAD_ID (desde Linux 4.14)
Si este bit de característica está establecido, uffd_msg.pagefault.feat.ptid se establecerá en el ID del hilo que causó la excepción para cada mensaje de excepción de página.
UFFD_FEATURE_PAGEFAULT_FLAG_WP (desde Linux 5.10)
Si este bit de característica está establecido, userfaultfd admite excepciones de protección de escritura para memoria anónima. (Tenga en cuenta que el soporte para shmem / hugetlbfs se indica mediante una característica separada).
UFFD_FEATURE_MINOR_HUGETLBFS (desde Linux 5.13)
Si este bit de característica está establecido, el kernel admite el registro de rangos de userfaultfd en modo menor en áreas de memoria respaldadas por hugetlbfs.
UFFD_FEATURE_MINOR_SHMEM (desde Linux 5.14)
Si este bit de característica está establecido, el kernel admite el registro de rangos de userfaultfd en modo menor en áreas de memoria respaldadas por shmem.
UFFD_FEATURE_EXACT_ADDRESS (desde Linux 5.18)
Si este bit de característica está establecido, uffd_msg.pagefault.address se establecerá en la dirección exacta de la excepción de página informada por el hardware, y no enmascarará el desplazamiento dentro de la página. Tenga en cuenta que las versiones antiguas de Linux también pueden indicar la dirección exacta, aunque el bit de característica no esté establecido.
UFFD_FEATURE_WP_HUGETLBFS_SHMEM (desde Linux 5.19)
Si este bit de característica está establecido, userfaultfd admite excepciones de protección de escritura para memoria hugetlbfs y shmem / tmpfs.
UFFD_FEATURE_WP_UNPOPULATED (desde Linux 6.4)
Si este bit de característica está establecido, el kernel manejará la memoria anónima de la misma manera que la memoria de archivo, permitiendo al usuario proteger contra escritura las entradas de tabla de páginas no pobladas.
UFFD_FEATURE_POISON (desde Linux 6.6)
Si este bit de característica está establecido, el kernel admite la resolución de excepciones con el ioctl UFFDIO_POISON.
UFFD_FEATURE_WP_ASYNC (desde Linux 6.7)
Si este bit de característica está establecido, las excepciones de protección de escritura se resolverían de forma asíncrona por el kernel.
UFFD_FEATURE_MOVE (desde Linux 6.8)
Si este bit de característica está establecido, el kernel admite la resolución de excepciones con el ioctl UFFDIO_MOVE.

El campo devuelto argp->ioctls puede contener los siguientes bits:

1 << _UFFDIO_API
La operación UFFDIO_API es compatible.
1 << _UFFDIO_REGISTER
La operación UFFDIO_REGISTER es compatible.
1 << _UFFDIO_UNREGISTER
La operación UFFDIO_UNREGISTER es compatible.

VALOR DE RETORNO

En caso de éxito, se devuelve 0.

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
argp se refiere a una dirección que está fuera del espacio de direcciones accesible del proceso que llama.
EINVAL
La versión de la API solicitada en el campo api no es compatible con este kernel, o el campo features pasado al kernel incluye bits de características que no son compatibles con la versión actual del kernel.
EINVAL
Una llamada anterior a UFFDIO_API ya habilitó una o más características para este userfaultfd. Llamar a UFFDIO_API dos veces, la primera sin características establecidas, está explícitamente permitido según el apretón de manos de detección de características de dos pasos.
EPERM
La característica UFFD_FEATURE_EVENT_FORK estaba habilitada, pero el proceso que llama no tiene la capacidad CAP_SYS_PTRACE.

ESTÁNDARES

Linux.

HISTORIA

Linux 4.3.

ADVERTENCIAS

Si ocurre un error, el kernel puede poner a cero la estructura uffdio_api proporcionada. El llamante debe tratar su contenido como no especificado y reinicializarlo antes de reintentar otra llamada a UFFDIO_API.

ERRORES

Para detectar las características de userfault disponibles y habilitar un subconjunto de esas características, el descriptor de archivo userfaultfd debe cerrarse después de la primera operación UFFDIO_API que consulta la disponibilidad de características y reabrirse antes de la segunda operación UFFDIO_API que realmente habilita las características deseadas.
