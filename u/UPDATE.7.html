NOMBRE

UPDATE - actualizar filas de una tabla

SINOPSIS

[ WITH [ RECURSIVE ] consulta_with [, ...] ]
UPDATE [ ONLY ] nombre_tabla [ * ] [ [ AS ] alias ]
    SET { nombre_columna = { expresión | DEFAULT } |
          ( nombre_columna [, ...] ) = [ ROW ] ( { expresión | DEFAULT } [, ...] ) |
          ( nombre_columna [, ...] ) = ( subconsulta )
        } [, ...]
    [ FROM elemento_from [, ...] ]
    [ WHERE condición | WHERE CURRENT OF nombre_cursor ]
    [ RETURNING [ WITH ( { OLD | NEW } AS alias_salida [, ...] ) ]
                { * | expresión_salida [ [ AS ] nombre_salida ] } [, ...] ]

DESCRIPCIÓN

UPDATE cambia los valores de las columnas especificadas en todas las filas que satisfacen la condición. Solo las columnas a modificar deben ser mencionadas en la cláusula SET; las columnas no modificadas explícitamente conservan sus valores anteriores.

Hay dos formas de modificar una tabla utilizando información contenida en otras tablas de la base de datos: utilizando subconsultas o especificando tablas adicionales en la cláusula FROM. Qué técnica es más apropiada depende de las circunstancias específicas.

La cláusula opcional RETURNING hace que UPDATE calcule y devuelva uno o más valores basados en cada fila realmente actualizada. Se puede calcular cualquier expresión que utilice las columnas de la tabla y/o columnas de otras tablas mencionadas en FROM. Por defecto, se utilizan los valores nuevos (posteriores a la actualización) de las columnas de la tabla, pero también es posible solicitar los valores antiguos (anteriores a la actualización). La sintaxis de la lista RETURNING es idéntica a la de la lista de salida de SELECT.

Debes tener el privilegio UPDATE sobre la tabla, o al menos sobre la(s) columna(s) que se listan para actualizar. También debes tener el privilegio SELECT sobre cualquier columna cuyos valores se lean en las expresiones o la condición.

PARÁMETROS

consulta_with

La cláusula WITH te permite especificar una o más subconsultas que pueden ser referenciadas por nombre en la consulta UPDATE. Consulta la Sección 7.8 y SELECT(7) para más detalles.

nombre_tabla

El nombre (opcionalmente calificado por esquema) de la tabla a actualizar. Si se especifica ONLY antes del nombre de la tabla, se actualizan las filas coincidentes solo en la tabla nombrada. Si ONLY no se especifica, las filas coincidentes también se actualizan en cualquier tabla que herede de la tabla nombrada. Opcionalmente, se puede especificar * después del nombre de la tabla para indicar explícitamente que se incluyen las tablas descendientes.

alias

Un nombre sustituto para la tabla de destino. Cuando se proporciona un alias, oculta completamente el nombre real de la tabla. Por ejemplo, dada la sentencia UPDATE foo AS f, el resto de la sentencia UPDATE debe referirse a esta tabla como f y no como foo.

nombre_columna

El nombre de una columna en la tabla nombrada por nombre_tabla. El nombre de la columna puede ser calificado con un nombre de subcampo o un índice de matriz, si es necesario. No incluyas el nombre de la tabla en la especificación de una columna de destino; por ejemplo, UPDATE table_name SET table_name.col = 1 es inválido.

expresión

Una expresión para asignar a la columna. La expresión puede usar los valores antiguos de esta y otras columnas de la tabla.

DEFAULT

Establece la columna a su valor predeterminado (que será NULL si no se ha asignado una expresión predeterminada específica a ella). Una columna de identidad se establecerá a un nuevo valor generado por la secuencia asociada. Para una columna generada, especificar esto está permitido pero simplemente especifica el comportamiento normal de calcular la columna a partir de su expresión de generación.

subconsulta

Una subconsulta SELECT que produce tantas columnas de salida como las listadas en la lista de columnas entre paréntesis que la preceden. La subconsulta no debe producir más de una fila cuando se ejecuta. Si produce una fila, sus valores de columna se asignan a las columnas de destino; si no produce ninguna fila, se asignan valores NULL a las columnas de destino. La subconsulta puede referirse a valores antiguos de la fila actual de la tabla que se está actualizando.

elemento_from

Una expresión de tabla que permite que las columnas de otras tablas aparezcan en la condición WHERE y en las expresiones de actualización. Esto utiliza la misma sintaxis que la cláusula FROM de una declaración SELECT; por ejemplo, se puede especificar un alias para el nombre de la tabla. No repitas la tabla de destino como un elemento_from a menos que intentes una auto-unión (en cuyo caso debe aparecer con un alias en el elemento_from).

condición

Una expresión que devuelve un valor de tipo booleano. Solo se actualizarán las filas para las que esta expresión devuelva verdadero.

nombre_cursor

El nombre del cursor a utilizar en una condición WHERE CURRENT OF. La fila a actualizar es la que se ha obtenido más recientemente de este cursor. El cursor debe ser una consulta no agrupada sobre la tabla de destino de la UPDATE. Ten en cuenta que WHERE CURRENT OF no se puede especificar junto con una condición booleana. Consulta DECLARE(7) para más información sobre el uso de cursores con WHERE CURRENT OF.

alias_salida

Un nombre sustituto opcional para las filas OLD o NEW en la lista RETURNING.

Por defecto, los valores antiguos de la tabla de destino se pueden devolver escribiendo OLD.nombre_columna o OLD.*, y los valores nuevos se pueden devolver escribiendo NEW.nombre_columna o NEW.*. Cuando se proporciona un alias, estos nombres se ocultan y las filas antiguas o nuevas deben referenciarse usando el alias. Por ejemplo, RETURNING WITH (OLD AS o, NEW AS n) o.*, n.*.

expresión_salida

Una expresión que será calculada y devuelta por el comando UPDATE después de actualizar cada fila. La expresión puede usar cualquier nombre de columna de la tabla nombrada por nombre_tabla o las tablas listadas en FROM. Escribe * para devolver todas las columnas.

Un nombre de columna o * puede ser calificado usando OLD o NEW, o el alias_salida correspondiente para OLD o NEW, para que se devuelvan valores antiguos o nuevos. Un nombre de columna no calificado, o *, o un nombre de columna o * calificado usando el nombre de la tabla de destino o alias devolverá valores nuevos.

nombre_salida

Un nombre a usar para una columna devuelta.

SALIDAS

Al completarse con éxito, un comando UPDATE devuelve una etiqueta de comando del formato

UPDATE cuenta

Cuenta es el número de filas actualizadas, incluidas las filas coincidentes cuyos valores no cambiaron. Ten en cuenta que el número puede ser menor que el número de filas que coincidieron con la condición cuando las actualizaciones fueron suprimidas por un disparador BEFORE UPDATE. Si cuenta es 0, ninguna fila fue actualizada por la consulta (esto no se considera un error).

Si el comando UPDATE contiene una cláusula RETURNING, el resultado será similar al de una declaración SELECT que contenga las columnas y valores definidos en la lista RETURNING, calculados sobre la(s) fila(s) actualizadas por el comando.

NOTAS

Cuando está presente una cláusula FROM, lo que esencialmente sucede es que la tabla de destino se une a las tablas mencionadas en la lista elemento_from, y cada fila de salida de la unión representa una operación de actualización para la tabla de destino. Al usar FROM, debes asegurarte de que la unión produzca como máximo una fila de salida por cada fila a modificar. En otras palabras, una fila de destino no debería unirse a más de una fila de las otras tablas. Si lo hace, solo una de las filas de unión se utilizará para actualizar la fila de destino, pero cuál se usará no es fácil de predecir.

Debido a esta indeterminación, referenciar otras tablas solo dentro de subconsultas es más seguro, aunque a menudo más difícil de leer y más lento que usar una unión.

En el caso de una tabla particionada, actualizar una fila podría hacer que ya no satisfaga la restricción de partición de la partición contenedora. En ese caso, si hay alguna otra partición en el árbol de particiones para la cual esta fila satisface su restricción de partición, entonces la fila se moverá a esa partición. Si no existe tal partición, ocurrirá un error. Detrás de escena, el movimiento de la fila es en realidad una operación de DELETE e INSERT.

UPDATE PostgreSQL - Manual Page

NAME

UPDATE

modificar filas de una tabla

SYNOPSIS

UPDATE tabla
SET columna = expresión [ , columna = expresión ... ]
[ FROM fuentes ... ]
[ WHERE condición ]
[ RETURNING expresión [ , expresión ... ] ]

DESCRIPTION

UPDATE es el comando SQL estándar para modificar los valores de las columnas existentes en una fila o conjunto de filas de una tabla.

UPDATE tiene dos formas básicas. La primera especifica la tabla a modificar directamente. La segunda especifica la tabla a modificar usando la cláusula FROM . Estas dos formas se pueden usar para actualizar una tabla basándose en valores de otras tablas.

Si la cláusula WHERE se omite, todas las filas de la tabla serán actualizadas. Tenga cuidado cuando actualice sin una cláusula WHERE , ya que se modificarán todas las filas de la tabla.

Si una tabla tiene claves foráneas referenciando a sí misma, o si múltiples actualizaciones en la misma fila son posibles dentro de una sola sentencia de comando, UPDATE aumentará los contadores de actualizaciones de filas de la tabla y de las tablas de clave foránea, y potencialmente los de las tablas de índice.

El valor de una columna puede ser establecido a cualquier expresión, incluyendo el uso de otras columnas de la misma tabla, u otras tablas. El valor DEFAULT puede ser usado para establecer el valor de la columna a su valor por defecto.

La cláusula RETURNING permite especificar las filas que son modificadas por este comando. Cualquier expresión que pueda ser usada en una cláusula SELECT puede ser especificada en la cláusula RETURNING . La sentencia UPDATE retornará el conjunto de resultados de esta cláusula RETURNING . Si la cláusula RETURNING se omite, el comando es un proceso de solo escritura, que no retorna datos ni filas. Si se especifica RETURNING sin ninguna expresión, el comando devolverá el conjunto de filas modificadas por la sentencia UPDATE .

Si una tabla está particionada, una operación UPDATE puede causar que una fila se mueva de una partición a otra. Esto sucede si la actualización cambia una clave de partición. Por ejemplo, si una tabla está particionada por hash en una columna, y el valor de esa columna se actualiza, la fila puede ser reubicada a otra partición. Si la fila es reubicada, esta puede ser eliminada de la partición original y insertada en la nueva partición. En este caso, la sentencia UPDATE será internamente reescrita como un DELETE de la fila original, seguido por un INSERT de la nueva fila. Esto puede tener implicaciones para otras sesiones concurrentes.

Por ejemplo, si la sesión 1 actualiza una fila que provoca su movimiento entre particiones, y la sesión 2 intenta realizar una operación de UPDATE o DELETE sobre esta fila en su ubicación original. En tal caso, la operación de la sesión 2 detectará el movimiento de la fila y lanzará un error de falla de serialización (que siempre se devuelve con un código SQLSTATE '40001'). Las aplicaciones pueden desear reintentar la transacción si esto ocurre. En el caso usual donde la tabla no está particionada, o donde no hay movimiento de filas, la sesión 2 habría identificado la fila recién actualizada y llevado a cabo la actualización/eliminación sobre esta nueva versión de la fila.

Note que si bien las filas pueden moverse de particiones locales a una partición de tabla externa (siempre que el manejador de datos externos soporte enrutamiento de tuplas), no pueden moverse de una partición de tabla externa a otra partición.

Un intento de mover una fila de una partición a otra fallará si una clave foránea referencia directamente a un ancestro de la partición de origen que no sea el mismo que el ancestro mencionado en la consulta UPDATE .

EJEMPLOS

Cambiar la palabra Drama por Dramatic en la columna kind de la tabla films:

UPDATE films SET kind = 'Dramatic' WHERE kind = 'Drama';

Ajustar las entradas de temperatura y restablecer la precipitación a su valor predeterminado en una fila de la tabla weather:

UPDATE weather SET temp_lo = temp_lo+1, temp_hi = temp_lo+15, prcp = DEFAULT
  WHERE city = 'San Francisco' AND date = '2003-07-03';

Realizar la misma operación y devolver las entradas actualizadas, y el valor de precipitación anterior:

UPDATE weather SET temp_lo = temp_lo+1, temp_hi = temp_lo+15, prcp = DEFAULT
  WHERE city = 'San Francisco' AND date = '2003-07-03'
  RETURNING temp_lo, temp_hi, prcp, old.prcp AS old_prcp;

Usar la sintaxis alternativa de lista de columnas para realizar la misma actualización:

UPDATE weather SET (temp_lo, temp_hi, prcp) = (temp_lo+1, temp_lo+15, DEFAULT)
  WHERE city = 'San Francisco' AND date = '2003-07-03';

Incrementar el contador de ventas del vendedor que gestiona la cuenta de Acme Corporation, usando la sintaxis de cláusula FROM:

UPDATE employees SET sales_count = sales_count + 1 FROM accounts
  WHERE accounts.name = 'Acme Corporation'
  AND employees.id = accounts.sales_person;

Realizar la misma operación, usando una subconsulta en la cláusula WHERE:

UPDATE employees SET sales_count = sales_count + 1 WHERE id =
  (SELECT sales_person FROM accounts WHERE name = 'Acme Corporation');

Actualizar los nombres de contacto en una tabla de cuentas para que coincidan con los vendedores asignados actualmente:

UPDATE accounts SET (contact_first_name, contact_last_name) =
    (SELECT first_name, last_name FROM employees
     WHERE employees.id = accounts.sales_person);

Un resultado similar podría lograrse con un JOIN:

UPDATE accounts SET contact_first_name = first_name,
                    contact_last_name = last_name
  FROM employees WHERE employees.id = accounts.sales_person;

Sin embargo, la segunda consulta puede dar resultados inesperados si employees.id no es una clave única, mientras que la primera consulta garantiza que se producirá un error si hay múltiples coincidencias de id. Además, si no hay coincidencia para una entrada particular de accounts.sales_person, la primera consulta establecerá los campos de nombre correspondientes a NULL, mientras que la segunda consulta no actualizará esa fila en absoluto.

Actualizar estadísticas en una tabla de resumen para que coincidan con los datos actuales:

UPDATE summary s SET (sum_x, sum_y, avg_x, avg_y) =
    (SELECT sum(x), sum(y), avg(x), avg(y) FROM data d
     WHERE d.group_id = s.group_id);

Intentar insertar un nuevo artículo en stock junto con la cantidad de stock. Si el artículo ya existe, en su lugar actualizar la cantidad de stock del artículo existente. Para hacer esto sin fallar la transacción completa, use puntos de salvaguarda:

BEGIN;
-- otras operaciones
SAVEPOINT sp1;
INSERT INTO wines VALUES('Chateau Lafite 2003', '24');
-- Suponiendo que lo anterior falla debido a una violación de clave única,
-- entonces emitimos estos comandos:
ROLLBACK TO sp1;
UPDATE wines SET stock = stock + 24 WHERE winename = 'Chateau Lafite 2003';
-- continuar con otras operaciones, y eventualmente
COMMIT;

Cambiar la columna kind de la tabla films en la fila en la que está posicionada actualmente el cursor c_films:

UPDATE films SET kind = 'Dramatic' WHERE CURRENT OF c_films;

Las actualizaciones que afectan a muchas filas pueden tener efectos negativos en el rendimiento del sistema, como hinchazón de tablas, aumento del retraso de réplicas y aumento de la contención de bloqueos. En tales situaciones, puede tener sentido realizar la operación en lotes más pequeños, posiblemente con una operación VACUUM en la tabla entre lotes. Si bien no hay una cláusula LIMIT para UPDATE , es posible obtener un efecto similar a través del uso de una Expresión Común de Tabla (CTE) y un auto-join. Con el método de acceso a tablas estándar de PostgreSQL, un auto-join en la columna del sistema ctid es muy eficiente:

WITH exceeded_max_retries AS (
  SELECT w.ctid FROM work_item AS w
    WHERE w.status = 'active' AND w.num_retries > 10
    ORDER BY w.retry_timestamp
    FOR UPDATE
    LIMIT 5000
)
UPDATE work_item SET status = 'failed'
  FROM exceeded_max_retries AS emr
  WHERE work_item.ctid = emr.ctid;

Este comando deberá repetirse hasta que no queden filas por actualizar. El uso de una cláusula ORDER BY permite que el comando priorice qué filas se actualizarán; también puede evitar el interbloqueo con otras operaciones de actualización si utilizan el mismo orden. Si la contención de bloqueos es una preocupación, entonces SKIP LOCKED puede agregarse a la CTE para evitar que múltiples comandos actualicen la misma fila. Sin embargo, entonces se necesitará una actualización final sin SKIP LOCKED o LIMIT para asegurar que ninguna fila coincidente haya sido pasada por alto.

COMPATIBILIDAD

Este comando se ajusta al estándar SQL, excepto que las cláusulas FROM y RETURNING son extensiones de PostgreSQL, al igual que la capacidad de usar WITH con UPDATE .

Algunos otros sistemas de bases de datos ofrecen una opción FROM en la que la tabla de destino debe aparecer nuevamente dentro de FROM. Así no es como PostgreSQL interpreta FROM. Tenga cuidado al portar aplicaciones que utilizan esta extensión.

De acuerdo con el estándar, el valor de origen para una sublista entre paréntesis de nombres de columnas de destino puede ser cualquier expresión de valor de fila que produzca el número correcto de columnas. PostgreSQL solo permite que el valor de origen sea un constructor de fila o una sub-SELECT. El valor actualizado de una columna individual se puede especificar como DEFAULT en el caso del constructor de fila, pero no dentro de una sub-SELECT.
