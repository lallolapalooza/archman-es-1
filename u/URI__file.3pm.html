URI::file(3) Documentación de Perl contribuida por el usuario URI::file(3)

NOMBRE

URI::file - URI que se mapea a nombres de archivo locales

SINOPSIS

use URI::file;
$u1 = URI->new("file:/foo/bar");
$u2 = URI->new("foo/bar", "file");
$u3 = URI::file->new($path);
$u4 = URI::file->new("c:\\windows\\", "win32");
$u1->file;
$u1->file("mac");

DESCRIPCIÓN

La clase "URI::file" soporta objetos "URI" pertenecientes al esquema URI file. Este esquema nos permite mapear los nombres de archivo convencionales encontrados en varios sistemas informáticos al espacio de nombres URI, véase RFC 8089 https://www.rfc-editor.org/rfc/rfc8089.html.

Si simplemente desea construir objetos URI de tipo file a partir de cadenas URI, utilice el constructor normal "URI". Si desea construir objetos URI de tipo file a partir de los nombres de archivo reales utilizados por varios sistemas, entonces utilice uno de los siguientes constructores "URI::file":

$u = URI::file->new( $filename, [$os] )
Mapea un nombre de archivo al espacio de nombres URI file:, crea un objeto URI y lo devuelve. El $filename se interpreta como perteneciente al sistema operativo indicado ($os), que por defecto es el valor de la variable $^O. El $filename puede ser absoluto o relativo, y se devuelve el tipo de objeto URI correspondiente para $os.
$u = URI::file->new_abs( $filename, [$os] )
Igual que URI::file->new, pero se asegura de que el URI devuelto represente un nombre de archivo absoluto. Si el argumento $filename es relativo, el nombre se resuelve en relación con el directorio actual, es decir, este constructor es realmente lo mismo que: 
URI::file->new($filename)->abs(URI::file->cwd);
$u = URI::file->cwd
Devuelve un URI de tipo file que representa el directorio de trabajo actual. Véase Cwd.

Los siguientes métodos son compatibles con los URI de tipo file (además de los métodos comunes y genéricos descritos en URI):

$u->file( [$os] )
Devuelve un nombre de archivo. Mapea desde el espacio de nombres URI al espacio de nombres de archivos del sistema operativo indicado.

Puede devolver "undef" si el nombre no se puede representar en el sistema de archivos indicado.

$u->dir( [$os] )
Algunos sistemas utilizan una forma diferente para los nombres de directorios que para los archivos normales. Utilice este método si sabe que desea usar el nombre para un directorio.

El módulo "URI::file" se puede usar para mapear nombres de archivo genéricos a nombres adecuados para el sistema local. Como tal, puede servir como un buen reemplazo para el módulo "File::Spec". Por ejemplo, el siguiente código traduce el nombre de archivo estilo UNIX Foo/Bar.pm a un nombre adecuado para el sistema local:

$file = URI::file->new("Foo/Bar.pm", "unix")->file;
die "No se puede mapear el nombre de archivo Foo/Bar.pm para $^O" unless defined $file;
open(FILE, $file) || die "No se puede abrir '$file': $!";
# hacer algo con FILE

NOTAS DE MAPEO

La mayoría de los sistemas informáticos actuales tienen sistemas de archivos organizados jerárquicamente. Mapear los nombres utilizados en estos sistemas a la sintaxis genérica de URI nos permite trabajar con URIs de archivos relativos que se comportan como deberían al resolverse utilizando el algoritmo genérico para URIs (especificado en RFC 3986 https://www.rfc-editor.org/rfc/rfc3986.html). Mapear un nombre de archivo a la sintaxis genérica de URI implica mapear el carácter separador de ruta a "/" y codificar cualquier carácter reservado que aparezca en los segmentos de ruta del nombre de archivo. Si los segmentos de ruta que consisten en las cadenas "." o ".." tienen un significado diferente al especificado para los URIs genéricos, entonces estos también deben codificarse.

Si el sistema de archivos tiene especificaciones de dispositivo, volumen o unidad como raíz del espacio de nombres, entonces tiene sentido mapearlas al campo de autoridad de la sintaxis genérica de URI. Esto asegura que los URIs relativos no puedan resolverse "por encima" de ellos, es decir, generalmente cómo funcionan los nombres de archivos relativos en esos sistemas.

Otro uso común del campo de autoridad es codificar el host en el que este nombre de archivo es válido. El nombre de host "localhost" es especial y generalmente tiene el mismo significado que un campo de autoridad faltante o vacío. Este uso entra en conflicto con el uso como especificación de dispositivo, pero a menudo se puede resolver para especificaciones de dispositivo que tienen caracteres no válidos en nombres de host simples.

El mapeo de nombres de archivo a URI normalmente no es uno a uno. Generalmente hay muchos URIs que se mapean a cualquier nombre de archivo dado. Por ejemplo, una autoridad de "localhost" se mapea igual que un URI con una autoridad faltante o vacía.

Ejemplo 1: El Mac clásico (Mac OS 9 y anteriores) usaba ":" como separador de ruta, pero no de la misma manera que un URI genérico. ":foo" era un nombre relativo. "foo:bar" era un nombre absoluto. Además, los segmentos de ruta podían contener el carácter "/" así como los literales "." o "..". Por lo tanto, el mapeo se ve así:

Mac clásico           URI
----------            -------------------
:foo:bar     <==>     foo/bar
:            <==>     ./
::foo:bar    <==>     ../foo/bar
:::          <==>     ../../
foo:bar      <==>     file:/foo/bar
foo:bar:     <==>     file:/foo/bar/
..           <==>     %2E%2E
<undef>      <==      /
foo/         <==      file:/foo%2F
./foo.txt    <==      file:/.%2Ffoo.txt

Tenga en cuenta que si desea una URL relativa, *debe* comenzar la ruta con un :. Cualquier ruta que comience con [^:] se trata como absoluta.

Ejemplo 2: El sistema de archivos UNIX es fácil de mapear, ya que utiliza el mismo separador de ruta que los URIs, tiene una única raíz y los segmentos de "." y ".." tienen el mismo significado. Los URIs que tienen el carácter "\0" o "/" como parte de cualquier segmento de ruta no se pueden convertir en nombres de archivo UNIX válidos.

UNIX                  URI
----------            ------------------
foo/bar      <==>     foo/bar
/foo/bar     <==>     file:/foo/bar
/foo/bar     <==      file://localhost/foo/bar
file:         ==>     ./file:
<undef>      <==      file:/fo%00/bar
/            <==>     file:/

VARIABLES DE CONFIGURACIÓN

Las siguientes variables de configuración influyen en cómo se comportan la clase y sus métodos:

%URI::file::OS_CLASS
Este hash mapea identificadores de SO a clases de implementación. Es posible que desee añadir o modificar esto si desea conectar su propia clase de manejador de archivos. Normalmente, las claves deben coincidir con los valores de $^O en uso.

Si no hay correspondencia, se utiliza la implementación "Unix".

$URI::file::DEFAULT_AUTHORITY
Esto determina qué cadena de "autoridad" incluir en los URIs de archivos absolutos. Por defecto es "". Si prefiere URIs verborreicos, puede configurarlo como "localhost".

Establecer este valor en "undef" fuerza un comportamiento compatible con URI v1.31 y anteriores. En este modo, los nombres de host en rutas UNC y las letras de unidad se mapean al componente de autoridad en Windows, mientras que producimos URIs sin autoridad en Unix.

URI::file(3pm)

NAME

URI::file - file URI constructor and accessors

SYNOPSIS

use URI::file;

# Create a file URI
$uri = URI::file->new("file:///path/to/some/file.txt");
$uri = URI::file->new("/path/to/some/file.txt");
$uri = URI::file->new_abs("file.txt");

# Access components
print $uri->path; # /path/to/some/file.txt

# Create a relative URI
$rel_uri = URI::file->new_abs("another.txt")->abs_to_rel("file.txt");
print $rel_uri; # ../path/to/some/another.txt

DESCRIPTION

This module provides a concrete implementation of the URI base class for file URIs. It supports the parsing, construction and manipulation of file URIs.

A file URI is a URI that specifies a location on the local filesystem. They typically start with "file://" followed by the path to the file.

The URI module is used as the base class, and URI::file inherits all of its methods.

MAPPING NOTES

When constructing a URI from a path, the path is canonicalized to remove redundant separators and resolve '..'.

When creating a relative URI using abs_to_rel, the current directory is determined using the current working directory of the Perl process.

CONFIGURATION VARIABLES

None.
