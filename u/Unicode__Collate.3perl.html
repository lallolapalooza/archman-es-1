Unicode::Collate(3perl) Guía de Referencia del Programador Perl Unicode::Collate(3perl)

NOMBRE

Unicode::Collate - Algoritmo de Colación Unicode

SINOPSIS

use Unicode::Collate;
# Construir
$Collator = Unicode::Collate->new(%tailoring);
# Ordenar
@sorted = $Collator->sort(@not_sorted);
# Comparar
$result = $Collator->cmp($a, $b); # devuelve 1, 0, o -1.

Nota: Las cadenas en @not_sorted, $a y $b se interpretan según el soporte Unicode de Perl. Ver perlunicode, perluniintro, perlunitut, perlunifaq, utf8. De lo contrario, puedes usar "preprocess" o deberías decodificarlas antes.

DESCRIPCIÓN

Este módulo es una implementación del Estándar Técnico de Unicode #10 (también conocido como UTS #10) - Algoritmo de Colación Unicode (también conocido como UCA).

Constructor y Ajuste

El método "new" devuelve un objeto collator. Si se llama a new() sin parámetros, el collator debería hacer la colación por defecto.

$Collator = Unicode::Collate->new(
   UCA_Version => $UCA_Version,
   alternate => $alternate, # alias para 'variable'
   backwards => $levelNumber, # o \@levelNumbers
   entry => $element,
   hangul_terminator => $term_primary_weight,
   highestFFFF => $bool,
   identical => $bool,
   ignoreName => qr/$ignoreName/,
   ignoreChar => qr/$ignoreChar/,
   ignore_level2 => $bool,
   katakana_before_hiragana => $bool,
   level => $collationLevel,
   long_contraction => $bool,
   minimalFFFE => $bool,
   normalization  => $normalization_form,
   overrideCJK => \&overrideCJK,
   overrideHangul => \&overrideHangul,
   preprocess => \&preprocess,
   rearrange => \@charList,
   rewrite => \&rewrite,
   suppress => \@charList,
   table => $filename,
   undefName => qr/$undefName/,
   undefChar => qr/$undefChar/,
   upper_before_lower => $bool,
   variable => $variable,
);
UCA_Version
Si se proporciona el número de revisión (anteriormente "versión de seguimiento") de UCA, se emula el comportamiento de esa revisión al colacionar. Si se omite, se utiliza el valor de retorno de UCA_Version().

Se admiten las siguientes revisiones. La predeterminada es 43.

  UCA       Estándar Unicode         DUCET (@version)
-------------------------------------------------------
   8              3.1                3.0.1 (3.0.1d9)
   9     3.1 con Corrigendum 3      3.1.1
  11             4.0.0
  14             4.1.0
  16             5.0.0
  18             5.1.0
  20             5.2.0
  22             6.0.0
  24             6.1.0
  26             6.2.0
  28             6.3.0
  30             7.0.0
  32             8.0.0
  34             9.0.0
  36            10.0.0
  38            11.0.0
  40            12.0.0
  41            12.1.0
  43            13.0.0

* Ver más abajo para "long_contraction" con "UCA_Version" 22 y 24.

* Los no caracteres (por ejemplo, U+FFFF) no se ignoran y pueden ser anulados desde "UCA_Version" 22.

* Los puntos de código fuera de rango (mayores que U+10FFFF) no se ignoran y pueden ser anulados desde "UCA_Version" 22.

* Los caracteres completamente ignorables se ignoraban y no interrumpían las contracciones con "UCA_Version" 9 y 11.

* El tratamiento de los ignorables después de las variables y algunos comportamientos se modificaron en "UCA_Version" 9.

* Los caracteres considerados ideogramas unificados CJK (ver "overrideCJK") dependen de "UCA_Version".

* Muchos jamos Hangul se asignan en "UCA_Version" 20, lo que afectará a "hangul_terminator".

alternate
-- ver 3.2.2 Pesos Alternativos, versión 8 de UTS #10

Para compatibilidad hacia atrás, "alternate" (nombre antiguo) puede ser utilizado como alias de "variable".

backwards
-- ver 3.4 Acentos hacia atrás, UTS #10. 
backwards => $levelNumber o \@levelNumbers

Pesos en orden inverso; ej. nivel 2 (ordenación de diacríticos) en francés. Si se omite (o $levelNumber es "undef" o "\@levelNumbers" es "[]"), hacia adelante en todos los niveles.

entry
-- ver 5 Tailoring; 9.1 Formato de Archivo Allkeys, UTS #10.

Si el mismo carácter (o una secuencia de caracteres) existe en la tabla de elementos de colación a través de "table", se anula el mapeo a elementos de colación. Si no existe, se define el mapeo adicionalmente.

    entry => <<'ENTRY', # para DUCET v4.0.0 (allkeys-4.0.0.txt)
0063 0068 ; [.0E6A.0020.0002.0063] # ch
0043 0068 ; [.0E6A.0020.0007.0043] # Ch
0043 0048 ; [.0E6A.0020.0008.0043] # CH
006C 006C ; [.0F4C.0020.0002.006C] # ll
004C 006C ; [.0F4C.0020.0007.004C] # Ll
004C 004C ; [.0F4C.0020.0008.004C] # LL
00F1      ; [.0F7B.0020.0002.00F1] # ñ
006E 0303 ; [.0F7B.0020.0002.00F1] # ñ
00D1      ; [.0F7B.0020.0008.00D1] # Ñ
004E 0303 ; [.0F7B.0020.0008.00D1] # Ñ
ENTRY
    entry => <<'ENTRY', # para DUCET v4.0.0 (allkeys-4.0.0.txt)
00E6 ; [.0E33.0020.0002.00E6][.0E8B.0020.0002.00E6] # ligadura ae como <a><e>
00C6 ; [.0E33.0020.0008.00C6][.0E8B.0020.0008.00C6] # ligadura AE como <A><E>
ENTRY

NOTA: El punto de código en el formato de archivo UCA (antes de ';') debe ser un punto de código Unicode (definido como hexadecimal), no un punto de código nativo. Por lo tanto 0063 siempre debe denotar "U+0063", no un carácter de "\x63".

La ponderación puede variar dependiendo de la tabla de elementos de colación. Por lo tanto, asegúrate de que las ponderaciones definidas en "entry" sean consistentes con las de la tabla de elementos de colación cargada a través de "table".

En DUCET v4.0.0, el peso primario de "C" es 0E6A y el de "D" es "0E6D". Por lo tanto, al establecer el peso primario de "CH" a "0E6A" (como un valor entre 0E60 y "0E6D") hace que la ordenación sea como "C < CH < D". Hablando estrictamente, DUCET ya tiene algunos caracteres entre "C" y "D": "c minúscula cursiva" ("U+1D04") con peso primario 0E64, "c-gancho/C-gancho" ("U+0188/U+0187") con 0E65, y "c-rizada" ("U+0255") con 0E69. Entonces el peso primario "0E6A" para "CH" hace que "CH" se ordene entre "c-rizada" y "D".

hangul_terminator
-- ver 7.1.4 Pesos finales, UTS #10.

Si se proporciona un valor verdadero (no cero pero debe ser positivo), se añadirá como un peso primario terminador al final de cada sílaba Hangul estándar. Los pesos secundarios y de orden superior para el terminador se establecen a cero. Si el valor es falso o la clave "hangul_terminator" no existe, no se realizará la inserción de pesos terminadores.

Los límites de las sílabas Hangul se determinan de acuerdo con el comportamiento de los jamos conjugados en el Estándar Unicode y HangulSyllableType.txt.

Cuando el valor es 0x0002, se utilizan los pesos de terminador de la DUCET (los que figuran en el archivo allkeys) y se suprime su peso primario 0x0002 para jamos compuestos.

highestFFFF
-- ver 6.2 Special Characters, UTS #10.

Si se establece en verdadero, los caracteres con puntos de código 0xFFFF se ordenarán como si fueran el peso primario más alto (0xFFFF). Si se establece en falso, se aplicarán los pesos correspondientes de la tabla de colación. Si se omite, su comportamiento es idéntico a false.

identical
-- ver 3.11 Identical Level, UTS #10.

Si se establece en verdadero, se añadirá un cuarto nivel (nivel idéntico) a la comparación. Solo se utilizará cuando los tres primeros niveles sean idénticos. El peso de este nivel se establece en cero. Si se omite, solo se utilizarán los tres primeros niveles.

Nota: El cuarto nivel se utiliza actualmente en el algoritmo de colación UCA solo para definir el orden de los caracteres que son idénticos en los tres primeros niveles, pero que no son realmente idénticos (por ejemplo, versiones diferentes del mismo carácter, o caracteres que no se pueden distinguir en los tres primeros niveles). El cuarto nivel se utiliza principalmente en implementaciones de UCA para representar la diferencia entre variantes de caracteres que son idénticas en los tres primeros niveles. El cuarto nivel es un peso de comparación adicional que se añade al final de la cadena de pesos UCA, solo para diferenciar estos casos.

ignoreChar
-- ver 4 Ignorables, UTS #10.

Se ignoran los caracteres que coincidan con la expresión regular dada. Por ejemplo, si ignoreChar se establece en qr/^$/, se ignoran las cadenas vacías. Si se omite, no se ignoran caracteres.

ignoreName
-- ver 4 Ignorables, UTS #10.

Se ignoran los caracteres cuyos nombres Unicode coincidan con la expresión regular dada. Por ejemplo, si ignoreName se establece en qr/^LATIN SMALL LETTER/, se ignoran todas las letras minúsculas latinas. Si se omite, no se ignoran caracteres.

ignore_level2
-- ver 3.2.2 Alternate Weighting, version 8 of UTS #10.

Si se establece en verdadero, se ignorarán los pesos del segundo nivel (que corresponden a las diferencias entre mayúsculas y minúsculas, acentos, etc.). Si se omite, se aplicarán los pesos del segundo nivel.

katakana_before_hiragana
-- ver 7.3.3 Kana Ordering, UTS #10.

Si se establece en verdadero, el katakana se ordenará antes que el hiragana. Si se establece en falso, el hiragana se ordenará antes que el katakana. Si se omite, se aplicará el orden del DUCET.

level
-- ver 3 Niveles de Comparación, UTS #10.

Establece el número de niveles de comparación. Los valores válidos son 1, 2, 3 o 4 (si "identical" se establece en verdadero). Si se omite, se utilizará 3.

long_contraction
-- ver 7.2.2 Contracción de Cadenas, UTS #10.

Si se establece en verdadero, se permite la contracción de cadenas largas, como se especifica en la versión 3.0 de UTS #10. Si se establece en falso, no se permite la contracción de cadenas largas. Si se omite, su comportamiento es idéntico a false.

Nota: La contracción de cadenas largas no se admite para "UCA_Version" 22 y 24.

minimalFFFE
-- ver 6.3 Special Characters, UTS #10.

Si se establece en verdadero, el carácter U+FFFE (no carácter) se tratará como un carácter completamente ignorable. Si se establece en falso, se aplicarán los pesos correspondientes de la tabla de colación. Si se omite, su comportamiento es idéntico a false.

normalization
-- ver 5.34 Normalization, UTS #10.

Si se especifica un formulario de normalización (por ejemplo, "NFC", "NFD", "NFKC", "NFKD"), la cadena de entrada se normalizará a ese formulario antes de la colación. Si se omite, no se realizará ninguna normalización.

overrideCJK
-- ver 7.2.1 CJK Unified Ideographs, UTS #10.

Define una subrutina para anular la ponderación de los caracteres unificados CJK. La subrutina debe aceptar un punto de código Unicode como argumento y devolver una cadena de pesos (por ejemplo, "[.1234.5678.9ABC]") o una cadena vacía si no se aplica ninguna anulación. Si se omite, no se aplicarán anulaciones CJK.

overrideHangul
-- ver 7.1 Hangul Syllables, UTS #10.

Define una subrutina para anular la ponderación de las sílabas Hangul. La subrutina debe aceptar un punto de código Unicode como argumento y devolver una cadena de pesos o una cadena vacía si no se aplica ninguna anulación. Si se omite, no se aplicarán anulaciones Hangul.

preprocess
-- ver 5 Tailoring, UTS #10.

Define una subrutina para preprocesar la cadena de entrada antes de la colación. La subrutina debe aceptar una cadena como argumento y devolver una cadena preprocesada. Si se omite, no se aplicará ningún preprocesamiento.

rearrange
-- ver 5 Tailoring, UTS #10.

Reordena los elementos de colación según la lista dada. Por ejemplo, rearrange => [\"[\x{1100}-\x{11FF}]"] reordenará los bloques Jamo Hangul al principio de la tabla de colación. Si se omite, no se aplicará ninguna reorganización.

rewrite
-- ver 5 Tailoring, UTS #10.

Define una subrutina para reescribir cadenas antes de la colación. La subrutina debe aceptar una cadena como argumento y devolver una cadena reescrita. Si se omite, no se aplicará ninguna reescritura.

suppress
-- ver 4 Ignorables, UTS #10.

Suprime los caracteres que coincidan con la lista dada. Por ejemplo, suppress => [\"\x{00AD}"] suprimirá el guion suave. Si se omite, no se suprimirá ningún carácter.

table
-- ver 7 Collation Element Table, UTS #10.

Especifica el nombre del archivo de tabla de elementos de colación a utilizar. Si se omite, se utilizará el archivo de tabla de elementos de colación por defecto (DUCET).

Se puede proporcionar una lista de nombres de archivo para construir la tabla de colación a partir de varios archivos.

undefChar
-- ver 4 Ignorables, UTS #10.

Se ignoran los caracteres que coincidan con la expresión regular dada. Por ejemplo, si undefChar se establece en qr/^$/, se ignoran las cadenas vacías. Si se omite, no se ignoran caracteres.

undefName
-- ver 4 Ignorables, UTS #10.

Se ignoran los caracteres cuyos nombres Unicode coincidan con la expresión regular dada. Por ejemplo, si undefName se establece en qr/^LATIN SMALL LETTER/, se ignoran todas las letras minúsculas latinas. Si se omite, no se ignoran caracteres.

upper_before_lower
-- ver 3.10 Case Ordering, UTS #10.

Si se establece en verdadero, las letras mayúsculas se ordenarán antes que las minúsculas. Si se establece en falso, las letras minúsculas se ordenarán antes que las mayúsculas. Si se omite, se aplicará el orden del DUCET.

variable
-- ver 3.2 Variable Weighting, UTS #10.

Si se establece en verdadero, los caracteres variables (como acentos y otros signos diacríticos) se tratarán como si fueran completamente ignorables en el primer nivel de comparación, pero se tendrán en cuenta en los niveles superiores. Si se establece en falso, los caracteres variables se tratarán como cualquier otro carácter. Si se omite, se aplicará el comportamiento del DUCET.

Ordenación

El método "sort" toma una lista de cadenas y las devuelve ordenadas según las reglas de colación del objeto collator.

$Collator = Unicode::Collate->new();
@sorted = $Collator->sort(@not_sorted);

Se puede especificar el número de niveles de comparación utilizando el parámetro "level" en el constructor.

Comparación

El método "cmp" toma dos cadenas y devuelve un valor numérico que indica su relación de ordenación:

  • -1 si $a es menor que $b.
  • 0 si $a es igual a $b.
  • 1 si $a es mayor que $b.

$Collator = Unicode::Collate->new();
$result = $Collator->cmp($a, $b);

Soporte de Componentes Internacionales para Unicode (ICU)

Si el módulo Unicode::Collate::ICU está disponible, se utilizará automáticamente para proporcionar una implementación más completa y precisa del UCA, incluyendo soporte para más de 100 idiomas.

Implementation Note

Nota de implementación: (1) Para el mapeo de expansión (caracteres Unicode mapeados a una secuencia de elementos de ordenación), no se agregará un terminador entre elementos de ordenación, incluso si existe un límite de sílabas Hangul allí. La adición de un terminador se restringe a la posición siguiente al último elemento de ordenación.

(2) Las letras Hangul no conjugadas (Jamo de compatibilidad, Jamo de ancho medio y letras encerradas) no se terminan automáticamente con un peso primario terminador. Es posible que estos caracteres necesiten que el terminador se incluya de antemano en una tabla de elementos de ordenación.

highestFFFF
-- véase 2.4 Pesos no caracteriales adaptados, UTS #35 (LDML) Parte 5: Ordenación.

Si el parámetro se establece en verdadero, "U+FFFF" tiene un peso primario más alto. Cuando un booleano de "$coll->ge($str, "abc")" y "$coll->le($str, "abc\x{FFFF}")" es verdadero, se espera que $str comience con "abc", o con un equivalente primario. $str puede ser "abcd", "abc012", pero no debe incluir "U+FFFF" como "abc\x{FFFF}xyz".

"$coll->le($str, "abc\x{FFFF}")" funciona casi como "$coll->lt($str, "abd")", pero este último tiene un problema que debes saber qué letra está junto a "c". Para cierto idioma donde "ch" es la siguiente letra, "abch" es mayor que "abc\x{FFFF}", pero menor que "abd".

Nota: Esto es equivalente a "(entry => 'FFFF ; [.FFFE.0020.0005.FFFF]')". Cualquier carácter que no sea "U+FFFF" puede ser adaptado con "entry".

identical
-- véase A.3 Comparación Determinista, UTS #10.

Por defecto, las cadenas cuyas ponderaciones son iguales deben ser iguales, aunque sus puntos de código no lo sean. Los caracteres completamente ignorables se ignoran.

Si el parámetro se establece en verdadero, se utiliza un nivel final de desempate. Si no se encuentra ninguna diferencia de ponderaciones después de la comparación a través de todos los niveles especificados por "level", se realizará la comparación con los puntos de código. Para la comparación de desempate, la clave de ordenación tiene adjuntos los puntos de código de la cadena original. Los caracteres completamente ignorables no se ignoran.

Si se aplica "preprocess" y/o "normalization", se utilizan los puntos de código de la cadena después de ellos (en NFD por defecto).

ignoreChar
ignoreName
-- véase 3.6 Ponderación Variable, UTS #10.

Hace que la entrada en la tabla sea completamente ignorable; es decir, como si las ponderaciones fueran cero en todos los niveles.

A través de "ignoreChar", cualquier carácter que coincida con "qr/$ignoreChar/" será ignorado. A través de "ignoreName", cualquier carácter cuyo nombre (dado en el archivo "table" como comentario) coincida con "qr/$ignoreName/" será ignorado.

Por ejemplo, cuando 'a' y 'e' son ignorables, 'element' es igual a 'lament' (o 'lmnt').

ignore_level2
-- véase 5.1 Adaptación Paramétrica, UTS #10.

Por defecto, la comparación sensible a mayúsculas y minúsculas (es decir, diferencia de nivel 3) no ignorará los acentos (es decir, diferencia de nivel 2).

Si el parámetro se establece en verdadero, los acentos (y otros caracteres primariamente ignorables) se ignoran, a pesar de que las mayúsculas y minúsculas se tengan en cuenta.

NOTA: "level" debe ser 3 o mayor.

katakana_before_hiragana
-- véase 7.2 Tabla de Ponderación Terciaria, UTS #10.

Por defecto, hiragana está antes que katakana. Si el parámetro se establece en verdadero, esto se invierte.

NOTA: Este parámetro asume ingenuamente que todas las distinciones entre hiragana y katakana deben ocurrir en el nivel 3, y sus ponderaciones en el nivel 3 deben ser las mismas que las mencionadas en 7.3.1, UTS #10. Si defines tus elementos de ordenación que violan este requisito, este parámetro no funcionará válidamente.

level
-- véase 4.3 Formar Clave de Ordenación, UTS #10.

Establece el nivel máximo. Se ignorarán todos los niveles superiores al especificado.

Nivel 1: ordenación alfabética
Nivel 2: ordenación de diacríticos
Nivel 3: ordenación de mayúsculas/minúsculas
Nivel 4: desempate (por ejemplo, en el caso en que la variable sea 'shift')
ej.level => 2,

Si se omite, el máximo es 4.

NOTA: El DUCET incluye ponderaciones superiores a 0xFFFF en el nivel 4. Pero este módulo solo utiliza ponderaciones dentro de 0xFFFF. Cuando la variable está 'en blanco' o 'no ignorable' (aparte de 'shift' y 'shift-trimmed'), el nivel 4 puede no ser fiable.

Véase también "identical".

long_contraction
-- véase 3.8.2 Bien formulado del DUCET, 4.2 Producir Array, UTS #10.

Si el parámetro se establece en verdadero, para una contracción con tres o más caracteres (aquí apodada "contracción larga"), se manejarán las subcadenas iniciales. Por ejemplo, una contracción ABC, donde A es un iniciador y B y C son no iniciadores (carácter con clase de carácter combinatorio no cero), se detectará incluso si no hay AB como contracción.

Por defecto: Generalmente falso. Si "UCA_Version" es 22 o 24, y el valor de "long_contraction" no se especifica en new(), se establece un valor verdadero implícitamente. Esto es una solución provisional para pasar las Pruebas de Conformidad para Unicode 6.0.0 y 6.1.0.

change() maneja "long_contraction" explícitamente solo. Si "long_contraction" no se especifica en change(), aunque "UCA_Version" se cambie, "long_contraction" no se cambiará.

Limitación: El escaneo de no iniciadores es unidireccional (sin retroceso). Si se encuentra AB pero no ABC, es posible que no se encuentre otra contracción larga donde el primer carácter sea A y el segundo no sea B.

Bajo "(normalization => undef)", se omitirá el paso de detección de contracciones discontinuas.

Nota: Las siguientes contracciones en el DUCET no se consideran en los pasos S2.1.1 a S2.1.3, donde son discontinuas.

0FB2 0F71 0F80 (VOCALIC RR TIBETAN VOWEL SIGN)
0FB3 0F71 0F80 (VOCALIC LL TIBETAN VOWEL SIGN)

Por ejemplo, "VOCALIC RR TIBETAN VOWEL SIGN" con "COMBINING TILDE OVERLAY" ("U+0344") es "0FB2 0344 0F71 0F80" en NFD. En este caso, se detecta "0FB2 0F80" ("VOCALIC R TIBETAN VOWEL SIGN"), en lugar de "0FB2 0F71 0F80". El 0344 insertado hace que "0FB2 0F71 0F80" sea discontinuo y la falta de contracción "0FB2 0F71" prohíbe que "0FB2 0F71 0F80" sea detectado.

minimalFFFE
-- véase 1.1.1 U+FFFE, UTS #35 (LDML) Parte 5: Ordenación.

Si el parámetro se establece en verdadero, "U+FFFE" tiene un peso primario mínimo. La comparación entre "$a1\x{FFFE}$a2" y "$b1\x{FFFE}$b2" primero compara $a1 y $b1 en el nivel 1, y luego $a2 y $b2 en el nivel 1, como sigue.

"ab\x{FFFE}a"
"Ab\x{FFFE}a"
"ab\x{FFFE}c"
"Ab\x{FFFE}c"
"ab\x{FFFE}xyz"
"abc\x{FFFE}def"
"abc\x{FFFE}xYz"
"aBc\x{FFFE}xyz"
"abcX\x{FFFE}def"
"abcx\x{FFFE}xyz"
"b\x{FFFE}aaa"
"bbb\x{FFFE}a"

Nota: Esto es equivalente a "(entry => 'FFFE ; [.0001.0020.0005.FFFE]')". Cualquier carácter que no sea "U+FFFE" puede ser adaptado con "entry".

normalization
-- véase 4.1 Normalizar, UTS #10.

Si se especifica, las cadenas se normalizan antes de la preparación de las claves de ordenación (la normalización se ejecuta después del preprocesamiento).

Se aplicará un nombre de forma que Unicode::Normalize::normalize() acepte como $normalization_form. Los nombres aceptables incluyen 'NFD', 'NFC', 'NFKD' y 'NFKC'. Véase Unicode::Normalize::normalize() para más detalles. Si se omite, se utiliza 'NFD'.

"normalization" se realiza después de "preprocess" (si está definido).

Además, se pueden utilizar valores especiales, "undef" y "prenormalized", aunque no están relacionados con Unicode::Normalize::normalize().

Si "undef" (no una cadena

s="Li">"undef") se pasa explícitamente como el valor para esta clave, no se realiza ninguna normalización (esto puede facilitar la adaptación si no se desea ninguna normalización). Bajo "(normalization => undef)", solo se resuelven las contracciones contiguas; por ejemplo, incluso si "A-ring" (y "A-ring-cedilla") se ordena después de "Z", "A-cedilla-ring" sería primariamente igual a "A". En este punto, "(normalization => undef, preprocess => sub { NFD(shift) })" no es equivalente a "(normalization => 'NFD')".

En el caso de "(normalization => "prenormalized")", no se realiza ninguna normalización, pero se realizan contracciones no contiguas con caracteres de combinación. Por lo tanto, "(normalization => 'prenormalized', preprocess => sub { NFD(shift) })" es equivalente a "(normalization => 'NFD')". Si las cadenas de origen están finamente prenormalizadas, "(normalization => 'prenormalized')" puede ahorrar tiempo en la normalización.

Excepto "(normalization => undef)", se requiere Unicode::Normalize (ver también CAVEAT).

overrideCJK
-- ver 7.1 Elementos de Colación Derivados, UTS #10.

Por defecto, los ideogramas unificados CJK se ordenan en orden de punto de código Unicode, pero aquellos en el bloque CJK Unified Ideographs son menores que aquellos en CJK Unified Ideographs Extension A, etc.

En el bloque CJK Unified Ideographs:
U+4E00..U+9FA5 si UCA_Version es 8, 9 o 11.
U+4E00..U+9FBB si UCA_Version es 14 o 16.
U+4E00..U+9FC3 si UCA_Version es 18.
U+4E00..U+9FCB si UCA_Version es 20 o 22.
U+4E00..U+9FCC si UCA_Version es 24 a 30.
U+4E00..U+9FD5 si UCA_Version es 32 o 34.
U+4E00..U+9FEA si UCA_Version es 36.
U+4E00..U+9FEF si UCA_Version es 38, 40 o 41.
U+4E00..U+9FFC si UCA_Version es 43.
En los bloques CJK Unified Ideographs Extension:
Ext.A (U+3400..U+4DB5)   si UCA_Version es  8 a 41.
Ext.A (U+3400..U+4DBF)   si UCA_Version es 43.
Ext.B (U+20000..U+2A6D6) si UCA_Version es  8 a 41.
Ext.B (U+20000..U+2A6DD) si UCA_Version es 43.
Ext.C (U+2A700..U+2B734) si UCA_Version es 20 o posterior.
Ext.D (U+2B740..U+2B81D) si UCA_Version es 22 o posterior.
Ext.E (U+2B820..U+2CEA1) si UCA_Version es 32 o posterior.
Ext.F (U+2CEB0..U+2EBE0) si UCA_Version es 36 o posterior.
Ext.G (U+30000..U+3134A) si UCA_Version es 43.

A través de "overrideCJK", se puede anular el orden de los ideogramas unificados CJK (incluidas las extensiones).

ej. orden de puntos de código JIS de los ideogramas unificados CJK.

overrideCJK => sub {
    my $u = shift;             # obtener un punto de código Unicode
    my $b = pack('n', $u);     # a UTF-16BE
    my $s = your_unicode_to_sjis_converter($b); # convertir
    my $n = unpack('n', $s);   # convertir sjis a corto
    [ $n, 0x20, 0x2, $u ];     # devolver el elemento de colación
},

El valor de retorno puede ser un arrayref de pesos del 1.º al 4.º como se muestra arriba. El valor de retorno puede ser un entero como peso primario como se muestra a continuación. Si se devuelve "undef", se utilizará el elemento de colación derivado por defecto.

overrideCJK => sub {
    my $u = shift;             # obtener un punto de código Unicode
    my $b = pack('n', $u);     # a UTF-16BE
    my $s = your_unicode_to_sjis_converter($b); # convertir
    my $n = unpack('n', $s);   # convertir sjis a corto
    return $n;                 # devolver el peso primario
},

El valor de retorno puede ser una lista que contenga cero o más de un arrayref, un entero o "undef".

ej. ignora todos los ideogramas unificados CJK.

overrideCJK => sub {()}, # CODEREF que devuelve una lista vacía
 # donde ->eq("Pe\x{4E00}rl", "Perl") es verdadero
 # ya que U+4E00 es un ideograma unificado CJK y debe ser ignorado.

Si se pasa un valor falso (incluido "undef"), "overrideCJK" no tiene efecto. "$Collator->change(overrideCJK => 0)" restablece el anterior.

Pero la asignación de peso para los ideogramas unificados CJK en "table" o "entry" sigue siendo válida. Si se pasa "undef" explícitamente como el valor para esta clave, los pesos para los ideogramas unificados CJK se tratan como indefinidos. Sin embargo, cuando "UCA_Version" > 8, "(overrideCJK => undef)" no tiene significado especial.

Nota: Además de estos, 12 ideogramas de compatibilidad CJK ("U+FA0E", "U+FA0F", "U+FA11", "U+FA13", "U+FA14", "U+FA1F", "U+FA21", "U+FA23", "U+FA24", "U+FA27", "U+FA28", "U+FA29") también se tratan como ideogramas unificados CJK. Pero no pueden anularse a través de "overrideCJK" cuando se utiliza DUCET, ya que la tabla incluye pesos para ellos. "table" o "entry" tiene prioridad sobre "overrideCJK".

overrideHangul
-- ver 7.1 Elementos de Colación Derivados, UTS #10.

Por defecto, las sílabas Hangul se descomponen en Jamos Hangul, incluso si "(normalization => undef)". Pero la correspondencia de las sílabas Hangul puede ser anulada.

Este parámetro funciona como "overrideCJK", así que véalo allí para ejemplos.

Si desea anular la correspondencia de las sílabas Hangul, NFD y NFKD no son apropiados, ya que NFD y NFKD descompondrán las sílabas Hangul antes de la anulación. FCD puede descomponer sílabas Hangul según el caso.

Si se pasa un valor falso (pero no "undef"), "overrideHangul" no tiene efecto. "$Collator->change(overrideHangul => 0)" restablece el anterior.

Si se pasa "undef" explícitamente como el valor para esta clave, el peso de las sílabas Hangul se trata como indefinido sin descomposición en Jamos Hangul. Pero la definición de peso para sílabas Hangul en "table" o "entry" sigue siendo válida.

overrideOut
-- ver 7.1.1 Manejo de Secuencias de Unidades de Código Mal Formadas, UTS #10.

Perl parece permitir valores fuera de rango (mayores que 0x10FFFF). Por defecto, los valores fuera de rango se reemplazan con "U+FFFD" (CARÁCTER DE REEMPLAZO) cuando "UCA_Version" >= 22, o se ignoran cuando "UCA_Version" <= 20.

Cuando "UCA_Version" >= 22, los pesos de los valores fuera de rango se pueden anular. Aunque "table" o "entry" están disponibles para ellos, los valores fuera de rango son demasiados.

"overrideOut" puede realizarlo algorítmicamente. Este parámetro funciona como "overrideCJK", así que véalo allí para ejemplos.

ej. ignora todos los valores fuera de rango.

overrideOut => sub {()}, # CODEREF que devuelve una lista vacía

Si se pasa un valor falso (incluido "undef"), "overrideOut" no tiene efecto. "$Collator->change(overrideOut => 0)" restablece el anterior.

NOTA SOBRE U+FFFD:

UCA recomienda que los valores fuera de rango no se ignoren por razones de seguridad. Por ejemplo, "pe\x{110000}rl" no debería ser igual a "perl". Sin embargo, "U+FFFD" se mapea incorrectamente a un elemento de colación variable en DUCET para Unicode 6.0.0 a 6.2.0, lo que significa que los valores fuera de rango se ignorarán cuando "variable" no sea "Non-ignorable".

El mapeo de "U+FFFD" se corrige en Unicode 6.3.0. Ver http://www.unicode.org/reports/tr10/tr10-28.html#Trailing_Weights (7.1.4 Pesos de Cola). Dicha corrección se reproduce con esto.

overrideOut => sub { 0xFFFD }, # CODEREF que devuelve un entero muy grande

Esta solución no es necesaria desde Unicode 6.3.0.

preprocess
-- ver 5.4 Preprocesamiento, UTS #10.

Si se especifica, el coderef se utiliza para preprocesar cada cadena antes de la formación de claves de ordenación.

ej. eliminando artículos en inglés, como "a" o "the". Entonces, "the pen" va antes de "a pencil".

preprocess => sub {
      my $str = shift;
      $str =~ s/\b(?:an?|the)\s+//gi;
      return $str;
   },

"preprocess" se realiza antes de "normalization" (si está definido).

ej. decodificando cadenas en una codificación heredada como shift-jis:

$sjis_collator = Unicode::Collate->new(
    preprocess => \&your_shiftjis_to_unicode_decoder,
);
@result = $sjis_collator->sort(@shiftjis_strings);

Nota: Las cadenas devueltas por el coderef se interpretarán según el soporte Unicode de Perl. Ver perlunicode, perluniintro, perlunitut, perlunifaq, utf8.

Characters that are not coded in logical order and to be rearranged. If "UCA_Version" is equal to or less than 11, default is:

If specified, the coderef is used to rewrite lines in "table" or "entry". The coderef will get each line, and then should return a rewritten line according to the UCA file format. If the coderef returns an empty line, the line will be skipped.

-- see 3.12 Special-Purpose Commands, UTS #35 (LDML) Part 5: Collation.

Contractions beginning with the specified characters are suppressed, even if those contractions are defined in "table".

suppress => [0x0400..0x0417, 0x041A..0x0437, 0x043A..0x045F],

table
-- see 3.8 Default Unicode Collation Element Table, UTS #10.

You can use another collation element table if desired.

The table file should locate in the Unicode/Collate directory on @INC. Say, if the filename is Foo.txt, the table file is searched as Unicode/Collate/Foo.txt in @INC.

By default, allkeys.txt (as the filename of DUCET) is used. If you will prepare your own table file, any name other than allkeys.txt may be better to avoid namespace conflict.

NOTE: When XSUB is used, the DUCET is compiled on building this module, and it may save time at the run time. Explicit saying "(table => 'allkeys.txt')", or using another table, or using "ignoreChar", "ignoreName", "undefChar", "undefName" or "rewrite" will prevent this module from using the compiled DUCET.

If "undef" is passed explicitly as the value for this key, no file is read (but you can define collation elements via "entry").

A typical way to define a collation element table without any file of table:

   $onlyABC = Unicode::Collate->new(
       table => undef,
       entry => << 'ENTRIES',
0061 ; [.0101.0020.0002.0061] # LATIN SMALL LETTER A
0041 ; [.0101.0020.0008.0041] # LATIN CAPITAL LETTER A
0062 ; [.0102.0020.0002.0062] # LATIN SMALL LETTER B
0042 ; [.0102.0020.0008.0042] # LATIN CAPITAL LETTER B
0063 ; [.0103.0020.0002.0063] # LATIN SMALL LETTER C
0043 ; [.0103.0020.0008.0043] # LATIN CAPITAL LETTER C
ENTRIES
    );

If "ignoreName" or "undefName" is used, character names should be specified as a comment (following "#") on each line.

undefChar
undefName
-- see 6.3.3 Reducing the Repertoire, UTS #10.

Undefines the collation element as if it were unassigned in the "table". This reduces the size of the table. If an unassigned character appears in the string to be collated, the sort key is made from its codepoint as a single-character collation element, as it is greater than any other assigned collation elements (in the codepoint order among the unassigned characters). But, it'd be better to ignore characters unfamiliar to you and maybe never used.

Through "undefChar", any character matching "qr/$undefChar/" will be undefined. Through "undefName", any character whose name (given in the "table" file as a comment) matches "qr/$undefName/" will be undefined.

ex. Collation weights for beyond-BMP characters are not stored in object:

undefChar => qr/[^\0-\x{fffd}]/,
upper_before_lower
-- see 6.6 Case Comparisons, UTS #10.

By default, lowercase is before uppercase. If the parameter is made true, this is reversed.

NOTE: This parameter simplemindedly assumes that any lowercase/uppercase distinctions must occur in level 3, and their weights at level 3 must be same as those mentioned in 7.3.1, UTS #10. If you define your collation elements which differs from this requirement, this parameter doesn't work validly.

variable
-- see 3.6 Variable Weighting, UTS #10.

This key allows for variable weighting of variable collation elements, which are marked with an ASTERISK in the table (NOTE: Many punctuation marks and symbols are variable in allkeys.txt).

variable => 'blanked', 'non-ignorable', 'shifted', or 'shift-trimmed'.

These names are case-insensitive. By default (if specification is omitted), 'shifted' is adopted.

'Blanked'        Variable elements are made ignorable at levels 1 through 3;
                 considered at the 4th level.
'Non-Ignorable'  Variable elements are not reset to ignorable.
'Shifted'        Variable elements are made ignorable at levels 1 through 3
                 their level 4 weight is replaced by the old level 1 weight.
                 Level 4 weight for Non-Variable elements is 0xFFFF.
'Shift-Trimmed'  Same as 'shifted', but all FFFF's at the 4th level
                 are trimmed.

The "match", "gmatch", "subst", "gsubst" methods work like "m//", "m//g", "s///", "s///g", respectively, but they are not aware of any pattern, but only a literal substring.

METHODS

"$collator->eq($string1, $string2)"
"$collator->neq($string1, $string2)"
"$collator->cmp($string1, $string2)"
"$collator->lt($string1, $string2)"
"$collator->le($string1, $string2)"

These methods perform string comparison.

cmp returns -1, 0, or 1, exactly like the built-in cmp operator. eq, neq, lt, le, gt, ge return true or false, exactly like the built-in operators.

When comparing strings, the comparison is based on the collation strength specified by the level parameter, or by the comparison level specified by the variable parameter. The behavior of levels and variables are ignored for the comparison.

e.g.

    my $Collator = Unicode::Collate->new( level => 2 );
    $Collator->eq( "a\xcc\x80", "a" ); # true, if level is 1 or 2
    $Collator->eq( "a\xcc\x80", "a" ); # false, if level is 3 or 4

The following options are not used during comparison:

normalization
Normalization is done before comparison if it is specified.
case
Ignored.
lang
Ignored.
variable
Ignored (unless it is set to non-ignorable). In that case, the collation level is effectively set to 4.
ignore_level2
Ignored.
"$position = $Collator->index($string, $substring[, $position])"
"($position, $length) = $Collator->index($string, $substring[, $position])"
If $substring matches a part of $string, returns the position of the first occurrence of the matching part in scalar context; in list context, returns a two-element list of the position and the length of the matching part.

If $substring does not match any part of $string, returns -1 in scalar context and an empty list in list context.

e.g. when the content of $str is "Ich muß studieren Perl.", you say the following where $sub is "MüSS",

    my $Collator = Unicode::Collate->new( normalization => undef, level => 1 );
                                   # (normalization => undef) is REQUIRED.
    my $match;
    if (my($pos,$len) = $Collator->index($str, $sub)) {
        $match = substr($str, $pos, $len);
    }

and get "muß" in $match, since "muß" is primary equal to "MüSS".

"$match_ref = $Collator->match($string, $substring)"
"($match) = $Collator->match($string, $substring)"
If $substring matches a part of $string, in scalar context, returns a reference to the first occurrence of the matching part ($match_ref is always true if matches, since every reference is true); in list context, returns the first occurrence of the matching part.

If $substring does not match any part of $string, returns "undef" in scalar context and an empty list in list context.

e.g.

    if ($match_ref = $Collator->match($str, $sub)) { # scalar context
        print "matches [$$match_ref].\n";
    } else {
        print "doesn't match.\n";
    }
     or
    if (($match) = $Collator->match($str, $sub)) { # list context
        print "matches [$match].\n";
    } else {
        print "doesn't match.\n";
    }
"@match = $Collator->gmatch($string, $substring)"
If $substring matches a part of $string, returns all the matching parts (or matching count in scalar context).

If $substring does not match any part of $string, returns an empty list.

"$count = $Collator->subst($string, $substring, $replacement)"
If $substring matches a part of $string, the first occurrence of the matching part is replaced by $replacement ($string is modified) and $count (always equals to 1) is returned.

$replacement can be a "CODEREF", taking the matching part as an argument, and returning a string to replace the matching part (a bit similar to "s/(..)/$coderef->($1)/e").

"$count = $Collator->gsubst($string, $substring, $replacement)"
If $substring matches a part of $string, all the occurrences of the matching part are replaced by $replacement ($string is modified) and $count is returned.

$replacement can be a "CODEREF", taking the matching part as an argument, and returning a string to replace the matching part (a bit similar to "s/(..)/$coderef->($1)/eg").

e.g.

    my $Collator = Unicode::Collate->new( normalization => undef, level => 1 );
                                   # (normalization => undef) is REQUIRED.
    my $str = "Camel donkey zebra came\x{301}l CAMEL horse cam\0e\0l...";
    $Collator->gsubst($str, "camel", sub { "$_[0]" });
    # now $str is "Camel donkey zebra came\x{301}l CAMEL horse cam\0e\0l...";
    # i.e., all the camels are made bold-faced.

-----------------------|---------------------------------------------------
   1        false      |   yes    yes      yes          yes        yes
   2        false      |   yes    yes      no           yes        yes
   3        false      |   yes    no       no           yes        yes
   4        false      |   yes    no       no           no         yes
-----------------------|---------------------------------------------------

   2        true       |   yes    yes      yes          yes        yes
   3        true       |   yes    no       yes          yes        yes

 note: if variable => non-ignorable, camel doesn't match c-a-m-e-l
       at any level.

In the scalar context, returns the modified collator (but it is not a clone from the original). 

    $Collator->change(level => 2)->eq("perl", "PERL"); # true
    $Collator->eq("perl", "PERL"); # true; now max level is 2nd.
    $Collator->change(level => 4)->eq("perl", "PERL"); # false
"$version = $Collator->version()"
Returns the version number (a string) of the Unicode Standard which the "table" file used by the collator object is based on. If the table does not include a version line (starting with @version), returns "unknown".

Returns the revision number of UTS #10 this module consults, that should correspond with the DUCET incorporated.

Returns the version number of UTS #10 this module consults, that should correspond with the DUCET incorporated.

INSTALL

Though this module can be used without any "table" file, to use this module easily, it is recommended to install a table file in the UCA format, by copying it under the directory <a place in @INC>/Unicode/Collate.

The most preferable one is "The Default Unicode Collation Element Table" (aka DUCET), available from the Unicode Consortium's website:

    http://www.unicode.org/Public/UCA/
    http://www.unicode.org/Public/UCA/latest/allkeys.txt
    (latest version)

If DUCET is not installed, it is recommended to copy the file from http://www.unicode.org/Public/UCA/latest/allkeys.txt to <a place in @INC>/Unicode/Collate/allkeys.txt manually.

Normalization
Use of the "normalization" parameter requires the Unicode::Normalize module (see Unicode::Normalize).

If you need not it (say, in the case when you need not handle any combining characters), assign "(normalization => undef)" explicitly.

Conformance Test
The Conformance Test for the UCA is available under http://www.unicode.org/Public/UCA/.

For CollationTest_SHIFTED.txt, a collator via "Unicode::Collate->new( )" should be used; for CollationTest_NON_IGNORABLE.txt, a collator via "Unicode::Collate->new(variable => "non-ignorable", level => 3)".

If "UCA_Version" is 26 or later, the "identical" level is preferred; "Unicode::Collate->new(identical => 1)" and "Unicode::Collate->new(identical => 1, variable => " ".

NAME

Unicode::Collate ‐ Unicode Collation Algorithm

SYNOPSIS

 use Unicode::Collate;
 my $collator = Unicode::Collate->new(locale => 'en');
 my $comparison_result = $collator->cmp($string1, $string2);
 my $sorted_arrayref = $collator->sort($arrayref);
 my $collator_ja = Unicode::Collate->new(locale => 'ja');
 my $collator_nodefault = Unicode::Collate->new(locale => undef);

DESCRIPTION

This module implements the Unicode Collation Algorithm (UCA) specified by UTS #10. It provides a way to compare strings according to the rules of different locales.

The module supports the following features:

  • Support for locale-specific collation rules based on the locale name. The module uses the default locale of the system if no locale is specified. See the new() method for details.
  • Support for the UCA version 13.0.0.
  • Support for the Default Unicode Collation Element Table (DUCET).
  • Customizable collation rules through the use of tailoring files.
  • Support for Hangul syllable decomposition.
  • Support for EBCDIC character sets (experimental).

The primary methods are:

new(...)
Creates a new Unicode::Collate object. It takes optional parameters, such as:
  • locale: A string specifying the locale for collation. If not provided or set to undef, the module attempts to determine the system's default locale. If that fails, it falls back to the UCA default rules. Common locale names include 'en' (English), 'de' (German), 'fr' (French), 'ja' (Japanese), etc. The module supports locale names in the format defined by UTS #35, such as "en_US" or "zh_Hant_TW".
  • rules: A string containing custom collation rules, or a path to a tailoring file. This allows for fine-tuning the collation behavior for specific needs.
  • numeric: A boolean value. If true, numbers within strings are compared numerically (e.g., "file10.txt" comes after "file2.txt"). Default is false.
  • case: Specifies how case differences are handled. Possible values are 'upper', 'lower', 'off'. 'upper' means uppercase letters are sorted before lowercase letters. 'lower' means lowercase letters are sorted before uppercase letters. 'off' means case is ignored. Default is 'off'.
  • backwards: A boolean value. If true, the collation order is reversed. Default is false.
  • alternate: Controls how ignorable characters (like punctuation) are handled. Possible values are 'nonignorable' and 'shifted'. 'nonignorable' means ignorable characters are treated as any other character. 'shifted' means they are sorted after all non-ignorable characters. Default is 'nonignorable'.
  • normalization: Specifies the normalization form to use for comparison. Possible values are 'none', 'NFC', 'NFD', 'NFKC', 'NFKD'. Default is 'none'.
  • HiraganaQuotenon-ignorable': A boolean value. If true, the distinction between Hiragana and Katakana characters is taken into account during sorting. Default is false.
cmp($string1, $string2)
Compares two strings based on the collator's rules. Returns:
  • -1 if $string1 comes before $string2.
  • 0 if $string1 is equal to $string2.
  • 1 if $string1 comes after $string2.
sort(@array)
Sorts an array of strings according to the collator's rules. Returns a new array reference with the sorted strings.
lcmp($string1, $string2)
Compares two strings based on the collator's rules, but returns locale-aware comparison results. This is equivalent to calling cmp and then applying the locale-specific tertiary weighting. This method is useful for implementing language-aware sorting order beyond simple lexicographical comparison.
collate($string)
Returns the collation key for a given string. The collation key is a byte string that can be used for comparison. Two strings are equal if their collation keys are equal.
levels($string)
Returns the different levels of collation weights for a given string as a list of strings. The levels represent primary, secondary, and tertiary differences.

EXPORT

Nothing is exported by default.

INSTALL

To install this module, run the following commands:

 perl Makefile.PL
 make
 make test
 make install

CAVEATS

Note on the 'alternate' parameter
The behavior of the 'alternate' parameter when set to 'shifted' might not be fully compliant with all locale specifications. The default value is 'nonignorable'.
The 'HiraganaQuote' parameter
The 'HiraganaQuote' parameter (which should have been named 'hiragana_quote' or similar and is deprecated) is a boolean value. If true, the distinction between Hiragana and Katakana characters is taken into account during sorting. This is equivalent to setting the tertiary level weight for these characters. The correct way to achieve this is by using locale tailoring files. For example, in Japanese collation, Hiragana characters are typically sorted before Katakana characters. If this parameter is set to true, and level parameter is not explicitly set to 3, the default value of level for Japanese locale will be effectively set to 3, so that cmp() method will take into account the third level of sorting: Unicode::Collate->new(locale => 'ja', HiraganaQuote => 1, level => 3) is equivalent to Unicode::Collate->new(locale => 'ja', level => 3) (because Japanese locale already takes Hiragana/Katakana difference into account at level 3).

However, if you want to disable the Hiragana/Katakana distinction, you should explicitly set the level parameter to 2 or less:

Unicode::Collate->new(locale => 'ja', HiraganaQuote => 0, level => 2)

Or simply rely on the default level for the locale. If the level parameter is explicitly set to 3, the HiraganaQuote parameter will be ignored, as the level 3 comparison implies taking the Hiragana/Katakana difference into account.

Unicode::Normalize is required to try The Conformance Test.
