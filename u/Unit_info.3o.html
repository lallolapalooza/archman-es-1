Módulo Unit_info
: sig end

Este módulo centraliza el manejo de archivos de compilación y sus metadatos.

Quizás más importante, este módulo proporciona funciones para derivar nombres de módulos a partir de cadenas o nombres de archivo.

Convención y cálculo del nombre del módulo

type intf_or_impl =
| Intf
| Impl

type modname = string

type filename = string

type file_prefix = string

type error =
| Invalid_encoding de filename

exception Error de error

val modulize : string -> modname

modulize s pone en mayúscula la primera letra de s.

val normalize : string -> string

normalize s pone en minúscula la primera letra de s.

val lax_modname_from_source : filename -> modname

lax_modname_from_source filename es modulize stem donde stem es el nombre base del nombre de archivo filename sin sus extensiones. Por ejemplo, lax_modname_from_source "/pa.th/x.ml.pp" es "X".

val strict_modname_from_source : filename -> modname

Igual que Unit_info.lax_modname_from_source pero lanza un error Unit_info.error.Invalid_encoding en nombres de archivo con codificación utf8 inválida.

Función de validación del nombre del módulo

val is_unit_name : modname -> bool

is_unit_name name es verdadero solo si name puede usarse como un nombre de módulo válido.

Metadatos para la unidad de compilación

type t

Metadatos para una unidad de compilación:

-el nombre del módulo asociado a la unidad

-el prefijo del nombre de archivo (directorio + nombre base sin extensiones) para los artefactos de compilación

-el archivo fuente de entrada. Por ejemplo, al llamar ocamlopt dir/x.mli -o target/y.cmi,

-el archivo fuente de entrada es dir/x.mli

-el nombre del módulo es Y

-el prefijo es target/y

val source_file : t -> filename

source_file u es el archivo fuente de u.

val prefix : t -> file_prefix

prefix u es el prefijo del nombre de archivo de la unidad.

val modname : t -> modname

modname u o artifact_modname a es el nombre del módulo de la unidad o del artefacto de compilación.

val kind : t -> intf_or_impl

kind u es el tipo (interfaz o implementación) de la unidad.

val check_unit_name : t -> unit

check_unit_name u imprime una advertencia si el nombre de módulo derivado modname u no debe usarse como nombre de módulo según Unit_info.is_unit_name ~strict:true.

val make : ?check_modname:bool -> source_file:filename -> intf_or_impl -> file_prefix -> t

make ~check ~source_file kind prefix asocia tanto el source_file como el nombre del módulo Unit_info.lax_modname_from_source target_prefix a la ruta del sistema de archivos prefix.

Si check_modname=true, esta función emite una advertencia si el nombre del módulo derivado no es válido según Unit_info.check_unit_name.

module Artifact : sig end

Artefactos de compilación

Metadatos de artefactos de compilación derivados

val cmi : t -> Artifact.t

Estas funciones derivan metadatos de un artefacto específico a partir de los metadatos de una unidad.

val cmo : t -> Artifact.t

val cmx : t -> Artifact.t

val obj : t -> Artifact.t

val cmt : t -> Artifact.t

val cmti : t -> Artifact.t

val annot : t -> Artifact.t

val companion_obj : Artifact.t -> Artifact.t

Las siguientes funciones cambian el tipo de un artefacto actualizando la extensión de su nombre de archivo. Estas funciones intencionalmente no cubren todos los tipos de artefactos porque queremos rastrear qué artefactos se asume que están agrupados.

val companion_cmt : Artifact.t -> Artifact.t

val companion_cmi : Artifact.t -> Artifact.t

Ten en cuenta que companion_cmi a elimina todas las extensiones del nombre de archivo de a antes de agregar el sufijo ".cmi", a diferencia de las otras funciones que solo eliminan la extensión más a la derecha. En otras palabras, el cmi compañero de un archivo something.d.cmo es something.cmi y no something.d.cmi.

Mli y cmi derivados de archivos de implementación

La compilación de la implementación de módulos cambia en presencia de archivos mli y cmi, las siguientes funciones ayudan a manejar esto.

val mli_from_source : t -> filename

mli_from_source u es el nombre del archivo fuente de la interfaz asociado a la unidad u. El sufijo real depende de Config.interface_suffix.

val mli_from_artifact : Artifact.t -> filename

mli_from_artifact t es el nombre del archivo fuente de la interfaz derivado del artefacto t. Esta variante es necesaria cuando se manejan artefactos derivados de archivos fuente desconocidos (por ejemplo, módulos empaquetados).

val is_cmi : Artifact.t -> bool

Verifica si el artefacto es un cmi.

val find_normalized_cmi : t -> Artifact.t

find_normalized_cmi u encuentra en el load_path un archivo que coincide con el nombre del módulo modname u.

Lanza Not_found si no existe tal cmi.
