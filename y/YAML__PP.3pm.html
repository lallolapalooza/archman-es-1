YAML::PP(3) Documentación de Perl contribuida por el usuario YAML::PP(3)

NOMBRE

YAML::PP - procesador YAML 1.2

SINOPSIS

ADVERTENCIA: La mayor parte de la API interna aún no es estable.

Aquí hay algunos ejemplos de los métodos básicos de carga y volcado:

use YAML::PP;
my $ypp = YAML::PP->new;
my $yaml = <<'EOM';
--- # Documento uno es un mapeo
nombre: Tina
edad: 29
lenguaje favorito: Perl
--- # Documento dos es una secuencia
- cadena simple
- 'entre comillas simples'
- "entre comillas dobles tenemos escapes! como \t y \n"
- | # un escalar de bloque literal
  linea1
  linea2
- > # un escalar de bloque plegado
  esto es todo una
  sola línea porque los
  saltos de línea se plegarán
EOM
my @documentos = $ypp->load_string($yaml);
my @documentos = $ypp->load_file($nombre_archivo);
my $yaml = $ypp->dump_string($datos1, $datos2);
$ypp->dump_file($nombre_archivo, $datos1, $datos2);
# Habilitar tipos de datos y objetos Perl
my $ypp = YAML::PP->new(schema => [qw/ + Perl /]);
my $yaml = $yp->dump_string($datos_con_objetos_perl);
# Interfaz heredada
use YAML::PP qw/ Load Dump LoadFile DumpFile /;
my @documentos = Load($yaml);
my @documentos = LoadFile($nombre_archivo);
my @documentos = LoadFile($descriptor_archivo);
my $yaml = Dump(@documentos);
DumpFile($nombre_archivo, @documentos);
DumpFile($descriptor_archivo @documentos);

Algunos scripts de utilidad, mayormente útiles para depuración:

# Cargar YAML en una estructura de datos y volcar con Data::Dumper
yamlpp-load < archivo.yaml
# Cargar y Volcar
yamlpp-load-dump < archivo.yaml
# Imprimir los eventos del analizador en formato yaml-test-suite
yamlpp-events < archivo.yaml
# Analizar y emitir eventos directamente sin cargar
yamlpp-parse-emit < archivo.yaml
# Crear YAML con color ANSI. También puede ser útil para YAML inválido,
# mostrándole la ubicación exacta del error.
yamlpp-highlight < archivo.yaml

DESCRIPCIÓN

YAML::PP es un procesador YAML modular.

Su objetivo es soportar "YAML 1.2" y "YAML 1.1". Ver https://yaml.org/. Algunos elementos de sintaxis (raros) aún no son compatibles y se documentan a continuación.

YAML es un lenguaje de serialización. La entrada YAML se llama "Stream YAML". Un stream consiste en uno o más "Documentos", separados por una línea con un marcador de inicio de documento "---". Un documento termina opcionalmente con el marcador de fin de documento "...".

Esto permite procesar streams continuos además de un archivo o cadena de entrada fija.

La interfaz de YAML::PP actualmente cargará todos los documentos y devolverá solo el primero si se llama en contexto escalar.

El backend YAML está implementado de manera modular que permite añadir manejo personalizado de etiquetas YAML, objetos y tipos de datos Perl. La API interna aún no es estable. ¡Sugerencias bienvenidas!

Puede consultar todos los resultados actuales de análisis y carga del yaml-test-suite aquí: https://perlpunk.github.io/YAML-PP-p5/test-suite.html

MÉTODOS

new

my $ypp = YAML::PP->new;

# Usar el Esquema Failsafe de YAML 1.2
my $ypp = YAML::PP->new( schema => ['Failsafe'] );
# Usar el Esquema JSON de YAML 1.2
my $ypp = YAML::PP->new( schema => ['JSON'] );
# Usar el Esquema Core de YAML 1.2
my $ypp = YAML::PP->new( schema => ['Core'] );

# Morir al detectar referencias cíclicas
my $ypp = YAML::PP->new( cyclic_refs => 'fatal' );

my $ypp = YAML::PP->new(
    boolean => 'perl',
    schema => ['Core'],
    cyclic_refs => 'fatal',
    indent => 4,
    header => 1,
    footer => 0,
    version_directive => 0,
);

Opciones:

boolean
Valores: "perl" (actualmente por defecto), "JSON::PP", "boolean", "perl_experimental"

Esta opción es para cargar y volcar.

En el caso de perl 5.36 y posteriores, los booleanos nativos deberían funcionar directamente (desde YAML::PP >= 0.38.0).

print YAML::PP->new->dump_string([ builtin::true, !1 ]);
# ---
# - true
# - false

Para versiones anteriores de perl, puede usar booleanos "pseudo" como se documenta en los siguientes ejemplos.

# cargar/volcar booleanos vía boolean.pm
my $ypp = YAML::PP->new( boolean => 'boolean' );
# cargar/volcar booleanos vía JSON::PP::true/false
my $ypp = YAML::PP->new( boolean => 'JSON::PP' );

También puede especificar más de una clase, separada por comas. Esto es importante para volcar.

boolean => 'JSON::PP,boolean'
Los booleanos se cargarán como JSON::PP::Booleans, pero al volcar,
también se reconocerán los objetos 'boolean'.
boolean => 'JSON::PP,*'
Los booleanos se cargarán como JSON::PP::Booleans, pero al volcar,
todas las clases booleanas soportadas actualmente serán reconocidas.
boolean => '*'
Los booleanos se cargarán como booleanos de perl, pero al volcar,
todas las clases booleanas soportadas actualmente serán reconocidas.
boolean => ''
Los booleanos se cargarán como booleanos de perl, pero al volcar,
nada será reconocido como booleano.
Esta opción es para compatibilidad hacia atrás para versiones de perl < 5.36,
si confía en que [!!1, !1] se vuelque como [1, ''].

La opción "perl_experimental" fue introducida cuando se agregó soporte booleano experimental a perl 5.36. Dado que ya no será experimental en perl 5.40 \o/ la opción está obsoleta y es la misma que "perl".

schema
Por defecto: "['Core']"

Esta opción es para cargar y volcar.

Referencia a un array. Aquí puede definir qué esquema usar. Los Esquemas estándar soportados son: "Failsafe", "JSON", "Core", "YAML1_1".

Para obtener una visión general de cómo se comportan los diferentes esquemas, vea https://perlpunk.github.io/YAML-PP-p5/schemas.html

Adicionalmente puede añadir más esquemas, por ejemplo "Merge".

cyclic_refs
Por defecto: "fatal" (desde 0.037)

Antes, el valor por defecto era "allow", pero esto puede causar fugas de memoria al cargar datos no confiables, por lo que se cambió a "fatal" por defecto.

Esta opción es solo para cargar.

Define qué hacer cuando se detecta una referencia cíclica al cargar.

# fatal  - morir
# warn   - Solo advertir sobre ellas y reemplazar con undef
# ignore - reemplazar con undef
# allow  - Por defecto
duplicate_keys
Por defecto: 0

Desde la versión 0.027

Esta opción es para cargar.

La especificación YAML dice que las claves duplicadas en los mapeos deben ser prohibidas.

Cuando se establece en verdadero, se permiten claves duplicadas en los mapeos (y sobrescribirán la clave anterior).

Cuando se establece en falso, las claves duplicadas resultarán en un error al cargar.

Esto es especialmente útil cuando tienes un mapeo largo y no ves la clave duplicada en tu editor:

---
a: 1
b: 2
# .............
a: 23 # error
indent
Por defecto: 2

Esta opción es para volcar.

Usar esa cantidad de espacios para la indentación

width
Desde la versión 0.025

Por defecto: 80

Esta opción es para volcar.

Columnas máximas al volcar.

Actualmente solo se respeta al volcar colecciones de flujo.

En el futuro también se usará para envolver cadenas largas.

header
Por defecto: 1

Esta opción es para volcar.

Imprimir cabecera de documento "---"

footer
Por defecto: 0

Esta opción es para volcar.

Imprimir pie de documento "..."

load_string

my $data = $ypp->load_string($yaml_string);
my @docs = $ypp->load_string($yaml_string);

Carga el YAML desde una cadena. Devuelve un solo elemento si se llama en contexto escalar, o una lista de todos los documentos si se llama en contexto de lista.

load_file

my $data = $ypp->load_file($filename);
my @docs = $ypp->load_file($filename);

Carga el YAML desde un archivo. Devuelve un solo elemento si se llama en contexto escalar, o una lista de todos los documentos si se llama en contexto de lista.

load_handle

my $data = $ypp->load_handle(\*FH);
my @docs = $ypp->load_handle(\*FH);

Carga el YAML desde un descriptor de archivo abierto. Devuelve un solo elemento si se llama en contexto escalar, o una lista de todos los documentos si se llama en contexto de lista.

dump_string

my $yaml_string = $ypp->dump_string($data);
my $yaml_string = $ypp->dump_string($data1, $data2, ...);

Vuelca datos Perl a una cadena YAML. Se pueden pasar varios argumentos para volcar múltiples documentos.

dump_file

$ypp->dump_file($filename, $data);
$ypp->dump_file($filename, $data1, $data2, ...);

Vuelca datos Perl a un archivo YAML. Se pueden pasar varios argumentos para volcar múltiples documentos.

dump_handle

$ypp->dump_handle(\*FH, $data);
$ypp->dump_handle(\*FH, $data1, $data2, ...);

Vuelca datos Perl a un descriptor de archivo YAML abierto. Se pueden pasar varios argumentos para volcar múltiples documentos.

add_event_handler

$ypp->add_event_handler( $event_name, $callback );

Se puede registrar un callback para cada evento generado por el analizador YAML. Útil para inspeccionar o modificar el proceso de análisis.

Ver YAML::PP::Event::* para nombres de eventos.

add_emitter_handler

$ypp->add_emitter_handler( $event_name, $callback );

Se puede registrar un callback para cada evento que el emisor genera. Útil para inspeccionar o modificar el proceso de emisión.

Ver YAML::PP::Event::* para nombres de eventos.

add_solver

$ypp->add_solver( $solver_module );

Añade un módulo solver personalizado. Por ejemplo:

  $ypp->add_solver('YAML::PP::Solver::AAM');
  $ypp->add_solver('YAML::PP::Solver::Timestamp');

Los solvers se prueban en orden. El primero que reconoce una etiqueta se encargará de ella.

add_representer

$ypp->add_representer( $perl_class, $callback );

Registra una función de devolución de llamada para representar una clase Perl dada al volcar.

  $ypp->add_representer( DateTime => sub { shift->ymd } );

add_node_maker

$ypp->add_node_maker( $yaml_tag, $callback );

Registra una función de devolución de llamada para crear un nodo YAML para una etiqueta YAML dada al cargar.

  $ypp->add_node_maker('!my_tag' => sub { +{ _my_tag => shift } });

add_type

$ypp->add_type( $perl_class, $yaml_tag );

Registra un mapeo entre una clase Perl y una etiqueta YAML. Esto es un atajo para add_solver y add_representer.

  # Soporte para DateTime::Tiny
  $ypp->add_type('DateTime::Tiny', '!timestamp');

ESQUEMAS

YAML::PP viene con algunos esquemas predefinidos para mapear tipos YAML a tipos Perl y viceversa.

Failsafe

El esquema más restringido. Solo permite los tipos de datos básicos de YAML: Secuencias, Mapeos, Cadenas, Números, Booleanos y Nulos. No se permiten etiquetas personalizadas.

JSON

El esquema JSON es un subconjunto de YAML 1.2. Permite los mismos tipos que el esquema Failsafe, además de fechas y binarios.

Core

El esquema Core incluye todos los tipos del esquema JSON, además de un número mayor de tipos de datos estándar como !!str, !!int, !!float, !!bool, !!null, !!binary, !!timestamp, !!omap, !!pairs, !!set y !!str.

YAML1_1

Proporciona soporte para las etiquetas específicas de YAML 1.1, como !!perl/object, que permiten la serialización de objetos Perl. Esto puede ser peligroso si se carga YAML de fuentes no confiables.

Perl

Este esquema se enfoca en la serialización de tipos y objetos Perl. Incluye soporte para referencias anidadas, paquetes, objetos, etc.

¡Advertencia! Cargar YAML con el esquema Perl de fuentes no confiables puede ser peligroso, ya que puede permitir la ejecución de código arbitrario.

UTILIDADES DE LÍNEA DE COMANDOS

YAML::PP proporciona varios scripts de línea de comandos para ayudar con el procesamiento y la depuración de YAML.

yamlpp-load
Lee un archivo YAML, lo carga en una estructura de datos Perl y lo imprime usando Data::Dumper. Útil para inspeccionar el contenido de un archivo YAML.
yamlpp-load-dump
Lee un archivo YAML, lo carga y luego lo vuelve a volcar a formato YAML. Útil para verificar la fidelidad de la serialización.
yamlpp-events
Lee un archivo YAML y emite una lista de eventos generados por el analizador en el formato estándar de la suite de pruebas YAML. Útil para depurar el proceso de análisis.
yamlpp-parse-emit
Analiza un archivo YAML y emite eventos sin construir completamente la estructura de datos Perl. Eficiente para streams grandes.
yamlpp-highlight
Colorea la salida YAML usando códigos de color ANSI. También resalta los errores de sintaxis en el YAML de entrada, indicando la ubicación exacta del problema.

LIMITACIONES Y COSAS NO SOPORTADAS

La siguiente sintaxis YAML no es compatible actualmente:

  • Marcadores de flujo de ancho variable para secuencias y mapeos.
  • Secuencias y mapeos encadenados.
  • Entrada/salida de anotaciones.
  • Etiquetas dentro de marcadores de flujo.
  • Anclas y alias dentro de marcadores de flujo.
  • Especificaciones de anclaje y alias más complejas.

Se recomienda encarecidamente no depender de la sintaxis no estándar o menos común, ya que puede que no se implemente en el futuro.

# Correcto

yaml_version
Desde la versión 0.020

Esta opción es para cargar y volcar.

Por defecto: 1.2

Tenga en cuenta que en este caso, una directiva "%YAML 1.1" básicamente será ignorada y todo se cargará con el Esquema "1.2 Core".

Si desea admitir tanto YAML 1.1 como 1.2, debe especificarlo, y el esquema ("Core" o "YAML1_1") se elegirá automáticamente.

my $yp = YAML::PP->new(
    yaml_version => ['1.2', '1.1'],
);

Esto es lo mismo que

my $yp = YAML::PP->new(
    schema => ['+'],
    yaml_version => ['1.2', '1.1'],
);

porque el "+" representa el esquema predeterminado por versión.

Al cargar, y no hay una directiva %YAML, se considerará 1.2 como predeterminado, y se usará el esquema "Core".

Si hay una directiva "%YAML 1.1", se utilizará el esquema "YAML1_1".

Por supuesto, también puede hacer de 1.1 el predeterminado:

my $yp = YAML::PP->new(
    yaml_version => ['1.1', '1.2'],
);

También puede especificar solo 1.1:

my $yp = YAML::PP->new(
    yaml_version => ['1.1'],
);

En este caso, incluso los documentos con "%YAML 1.2" se cargarán con el esquema "YAML1_1".

version_directive
Desde la versión 0.020

Esta opción es para volcar.

Por defecto: 0

Imprime la Directiva de Versión "%YAML 1.2" (o "%YAML 1.1") en la parte superior de cada documento YAML. Usará la primera versión especificada en la opción "yaml_version".

preserve
Desde la versión 0.021

Por defecto: false

Esta opción es para cargar y volcar.

Preservar los estilos de escalares sigue siendo experimental.

use YAML::PP::Common qw/ :PRESERVE /;
# Preservar el orden de las claves del hash
my $yp = YAML::PP->new( preserve => PRESERVE_ORDER );
# Preservar el estilo de comillas de los escalares
my $yp = YAML::PP->new( preserve => PRESERVE_SCALAR_STYLE );
# Preservar el estilo de bloque/flujo (desde 0.024)
my $yp = YAML::PP->new( preserve => PRESERVE_FLOW_STYLE );
# Preservar nombres de alias (desde 0.027)
my $yp = YAML::PP->new( preserve => PRESERVE_ALIAS );
# Combinar, por ejemplo, preservar el orden y el estilo escalar
my $yp = YAML::PP->new( preserve => PRESERVE_ORDER | PRESERVE_SCALAR_STYLE );

NO confíe en la implementación interna.

Si carga la siguiente entrada:

---
z: 1
a: 2
---
- plain
- 'single'
- "double"
- |
  literal
- >
  folded
---
block mapping: &alias
  flow sequence: [a, b]
same mapping: *alias
flow mapping: {a: b}

con este código:

my $yp = YAML::PP->new(
    preserve => PRESERVE_ORDER | PRESERVE_SCALAR_STYLE
                | PRESERVE_FLOW_STYLE | PRESERVE_ALIAS
);
my ($hash, $styles, $flow) = $yp->load_file($file);
$yp->dump_file($hash, $styles, $flow);

Entonces volcarlo devolverá la misma salida.

Tenga en cuenta que YAML permite la definición repetida de anclas. Actualmente no se pueden preservar con YAML::PP. Ejemplo:

---
- &seq [a]
- *seq
- &seq [b]
- *seq

Debido a que los datos podrían barajarse antes de volver a volcarlos, la definición del ancla podría romperse. En este caso, los nombres de anclas repetidos se descartarán al cargar y se volcarán con anclas numéricas como de costumbre.

Implementación:

Al cargar, los hashes se vincularán a una clase interna ("YAML::PP::Preserve::Hash") que mantiene el orden de las claves.

Los escalares se devolverán como objetos de una clase interna ("YAML::PP::Preserve::Scalar") con sobrecarga. Si asigna a dicho escalar, el objeto será reemplazado por un escalar simple.

# asignación, el estilo se pierde
$styles->[1] .= ' append';

También puede pasar 1 como valor. En este caso, se habilitarán todas las opciones de preservación, incluso si hay nuevas opciones agregadas en el futuro.

También hay métodos para crear nodos preservados desde cero. Consulte los métodos preserved_(scalar|mapping|sequence) más abajo.

load_string

my $doc = $ypp->load_string("foo: bar");
my @docs = $ypp->load_string("foo: bar\n---\n- a");

La entrada deben ser caracteres Unicode.

Por lo tanto, si lee de un archivo, debe decodificarlo, por ejemplo con Encode::decode().

Tenga en cuenta que en contexto escalar, "load_string" y "load_file" devuelven el primer documento (como YAML::Syck), mientras que YAML y YAML::XS devuelven el último.

load_file

my $doc = $ypp->load_file("file.yaml");
my @docs = $ypp->load_file("file.yaml");

Las cadenas se cargarán como caracteres Unicode.

dump_string

my $yaml = $ypp->dump_string($doc);
my $yaml = $ypp->dump_string($doc1, $doc2);
my $yaml = $ypp->dump_string(@docs);

Las cadenas de entrada deben ser caracteres Unicode.

La salida devolverá caracteres Unicode.

Por lo tanto, si desea escribir eso en un archivo (o pasarlo a YAML::XS, por ejemplo), normalmente lo codificará a través de Encode::encode().

dump_file

$ypp->dump_file("file.yaml", $doc);
$ypp->dump_file("file.yaml", $doc1, $doc2);
$ypp->dump_file("file.yaml", @docs);

Los datos de entrada deben ser caracteres Unicode.

dump

Esto volcará a un escritor predefinido. Por defecto, simplemente usará YAML::PP::Writer y generará una cadena.

my $writer = MyWriter->new(\my $output);
my $yp = YAML::PP->new(
    writer => $writer,
);
$yp->dump($data);

preserved_scalar

Desde la versión 0.024

Experimental. Por favor, informe de errores o hágame saber que esto es útil y funciona.

Puede definir un estilo escalar específico al volcar datos. Averiguar el mejor estilo es una tarea difícil y prácticamente imposible de hacer bien en todos los casos. También es una cuestión de gusto.

use YAML::PP::Common qw/ PRESERVE_SCALAR_STYLE YAML_LITERAL_SCALAR_STYLE /;
my $yp = YAML::PP->new(
    preserve => PRESERVE_SCALAR_STYLE,
);
# una sola nueva línea normalmente se volcaría con comillas dobles: "\n"
my $scalar = $yp->preserved_scalar("\n", style => YAML_LITERAL_SCALAR_STYLE );
my $data = { literal => $scalar };
my $dump = $yp->dump_string($data);
# salida
---
literal: |+
...

preserved_mapping, preserved_sequence

Desde la versión 0.024

Experimental. Por favor, informe de errores o hágame saber que esto es útil y funciona.

Con esto puede definir qué nodos se vuelcan con el estilo de flujo más compacto en lugar del estilo de bloque.

Si agrega "PRESERVE_ORDER" a la opción "preserve", también mantendrá el orden de las claves en un hash.

use YAML::PP::Common qw/
    PRESERVE_ORDER PRESERVE_FLOW_STYLE
    YAML_FLOW_MAPPING_STYLE YAML_FLOW_SEQUENCE_STYLE
/;
my $yp = YAML::PP->new(
    preserve => PRESERVE_FLOW_STYLE | PRESERVE_ORDER
);
my $hash = $yp->preserved_mapping({}, style => YAML_FLOW_MAPPING_STYLE);
# Agregar valores después de la inicialización para preservar el orden
%$hash = (z => 1, a => 2, y => 3, b => 4);
my $array = $yp->preserved_sequence([23, 24], style => YAML_FLOW_SEQUENCE_STYLE);
my $data = $yp->preserved_mapping({});
%$data = ( map => $hash, seq => $array );
my $dump = $yp->dump_string($data);
# salida
---
map: {z: 1, a: 2, y: 3, b: 4}
seq: [23, 24]

FUNCIONES

Las funciones "Load", "LoadFile", "Dump" y "DumpFile" se proporcionan como un reemplazo directo para otros procesadores YAML existentes. Ninguna función se exporta por defecto.

Tenga en cuenta que en contexto escalar, "Load" y "LoadFile" devuelven el primer documento (como YAML::Syck), mientras que YAML y YAML::XS devuelven el

último.

Load
use YAML::PP qw/ Load /;
my $doc = Load($yaml);
my @docs = Load($yaml);

Funciona como "load_string".

LoadFile
use YAML::PP qw/ LoadFile /;
my $doc = LoadFile($file);
my @docs = LoadFile($file);
my @docs = LoadFile($filehandle);

Funciona como "load_file".

Dump
use YAML::PP qw/ Dump /;
my $yaml = Dump($doc);
my $yaml = Dump(@docs);

Funciona como "dump_string".

DumpFile
use YAML::PP qw/ DumpFile /;
DumpFile($file, $doc);
DumpFile($file, @docs);
DumpFile($filehandle, @docs);

Funciona como "dump_file".

IMPLEMENTACIÓN

El proceso de carga y volcado se divide en los siguientes pasos:

Carga:
Flujo YAML        Lista de Tokens        Lista de Eventos        Estructura de Datos
          --------->    --------->        --------->
            lex           parse           construct
Vuelto:
Estructura de Datos       Lista de Eventos        Flujo YAML
            --------->        --------->
            represent           emit

Puedes volcar tipos básicos de perl como hashes, arrays, escalares (cadenas, números). Para volcar objetos bendecidos y cosas como coderefs, mira YAML::PP::Perl/YAML::PP::Schema::Perl.

YAML::PP::Lexer
El Lexer lee el flujo YAML en tokens. Esto hace posible generar salida YAML con resaltado de sintaxis.

Ten en cuenta que la API para recuperar los tokens cambiará.

YAML::PP::Parser
El Parser recupera los tokens del Lexer. El contenido principal de YAML se analiza con la Gramática.
YAML::PP::Grammar
YAML::PP::Constructor
El Constructor crea una estructura de datos a partir de los eventos del Parser.
YAML::PP::Loader
El Loader combina el constructor y el parser.
YAML::PP::Dumper
El Dumper delegará al Representer
YAML::PP::Representer
El Representer creará eventos Emitter a partir de la estructura de datos dada.
YAML::PP::Emitter
El Emitter crea un flujo YAML.

YAML::PP::Constructor

El Constructor ahora soporta los tres Esquemas de YAML 1.2, Failsafe, JSON y Core. Adicionalmente puedes elegir el esquema para YAML 1.1 como "YAML1_1".

Para ver qué cadenas se resuelven como booleanos, números, nulo, etc., mira https://perlpunk.github.io/YAML-PP-p5/schema-examples.html.

Puedes elegir el Esquema así:

my $ypp = YAML::PP->new(schema => ['JSON']); # por defecto es 'Core'

Las etiquetas "!!seq" y "!!map" todavía se ignoran por ahora.

Soporta:

Manejo de Anclas/Alias
Al igual que en módulos como YAML, el Constructor usará referencias para mapeos y secuencias, pero obviamente no para escalares.

YAML::XS usa alias reales, lo que también permite alias de escalares. Podría añadir una opción para eso ya que el aliasing está disponible en perl puro.

Manejo de Booleanos
Puedes elegir entre 'perl' (1/'', actualmente por defecto), 'JSON::PP' y 'boolean'.pm para manejar tipos booleanos. Eso te permite volcar la estructura de datos con uno de los módulos JSON sin perder información sobre booleanos.
Números
Los números se crean como números reales en lugar de cadenas, para que sean volcados correctamente por módulos como JSON::PP o JSON::XS, por ejemplo.
Claves Complejas
Las Claves de Mapeo en YAML pueden ser más que solo escalares. Por supuesto, no puedes cargar eso en una estructura nativa de perl. El Constructor convertirá en cadena estas claves con Data::Dumper en lugar de simplemente devolver algo como HASH(0x55dc1b5d0178).

Ejemplo:

use YAML::PP;
use JSON::PP;
my $ypp = YAML::PP->new;
my $coder = JSON::PP->new->ascii->pretty->allow_nonref->canonical;
my $yaml = <<'EOM';
complex:
    ?
        ?
            a: 1
            c: 2
        : 23
    : 42
EOM
my $data = $yppl->load_string($yaml);
say $coder->encode($data);
__END__
{
   "complex" : {
      "{'{a => 1,c => 2}' => 23}" : 42
   }
}

La especificación dice que este es contenido desechable, pero he leído que mucha gente desea poder conservar los comentarios.

YAML::PP::Dumper, YAML::PP::Emitter

El Dumper debería ser capaz de volcar cadenas correctamente, añadiendo comillas siempre que un escalar simple parezca una cadena especial, como "true", o cuando contenga o empiece con caracteres que no están permitidos.

La mayoría de las cadenas se volcarán como escalares simples sin comillas. Si contienen caracteres especiales o tienen un significado especial, se volcarán con comillas simples. Si contienen caracteres de control, incluyendo <"\n">, se volcarán con comillas dobles.

Reconocerá objetos JSON::PP::Boolean y boolean.pm y los volcará correctamente.

Los números que también tienen un indicador "PV" serán reconocidos como números y no como cadenas:

my $int = 23;
say "int: $int"; # $int ahora también tendrá un indicador PV

Eso significa que si accidentalmente usas una cadena en contexto numérico, también será reconocida como un número:

my $string = "23";
my $something = $string + 0;
print $yp->dump_string($string);

DESCRIPTION

This module is intended to be a YAML 1.2 parser and emitter. It is pure perl and thus should be portable. It supports all YAML 1.2 types from the Core schema, and also includes support for binary data and multi-line strings.

By default it handles the following datatypes:

String
Strings are represented as perl strings.
Integer
Integers are represented as perl integers. Integers outside the range of a perl integer will be represented as big integers. In this case, it is emitted as an integer without quotes!
Float
Floats are represented as perl floats.
Boolean
Booleans are represented as perl constants true and false.
Null
Null values are represented as perl constants undef.
Array
Arrays are represented as perl arrays.
Map
Maps are represented as perl hashes.
Binary
Binary data is represented as perl strings.

The layout is like libyaml output:

key:
- a
- b
- c
---
- key1: 1
  key2: 2
  key3: 3
---
- - a1
  - a2
- - b1
  - b2

FAQ - Frequently Asked Questions

Are "<<" merge keys supported?
Yes, this can be enabled optionally, see YAML::PP::Schema::Merge
Is there a linter / formatter for YAML
There is the widely used "yamllint" https://yamllint.readthedocs.io/, based on python's PyYAML. It is very configurable and will report errors or warnings. It cannot format.

Now there is also YAML::Tidy, which will format the given file according to your configuration. So far only a few configuration options exist, but they can already be quite helpful.

Which YAML module should I use?

There are many YAML modules on CPAN. For historical reasons some of them aren't handling YAML correctly.

Most of them are not compatible with the YAML spec and with each other, meaning they can interpret the same YAML differently.

The behaviours we are discussing here can be divided into parsing issues (syntax) and loading/constructing issues (for example type resolving which decides what is a number, boolean or null).

See also https://matrix.yaml.info/ (parsing) and https://perlpunk.github.io/YAML-PP-p5/schema-examples.html (loading).

"YAML.pm"
It was written even before the YAML 1.0 spec was finished and by that enabled perl users to process YAML very early. It might work for you if you have simple data, but it's missing quite some features and can also produce YAML that doesn't roundtrip. Nowadays it might be a good idea to switch.
YAML::XS
A libyaml binding that is robust and widely used. However, there are two things to consider.

1. (syntax) libyaml diverged from the spec in several aspects. They are rare though. 2. The type resolving does not adhere to YAML 1.1 or YAML 1.2, meaning it is
incompatible with other YAML libraries in perl or other languages.

YAML::Tiny
It implements both a tiny subset of YAML, but also a superset. Meaning it will happily accept some YAML documents that are not officially valid. Type resolving is also not implemented according to the spec.
YAML::Syck
A binding to libsyck. It is even less compatible to YAML than libyaml. Also type resolving is not implemented according to the spec.
YAML::PP
Regarding YAML syntax, it is the second most YAML 1.2 compatible perl module. The cases it cannot (yet) parse are not relevant in perl programming, e.g. hash keys that are not strings. Regarding type resolving, it is compatible with the YAML 1.2 Core schema, so it should be possible to exchange data as YAML with other libraries in other languages. One downside is that it is the slowest perl YAML module.
YAML::Parser
This is a parser generated by the YAML grammar, and it's passing all official tests. A YAML::PP::Ref frontend exists that you can use just like YAML::PP. It is quite slow (although it might be ok for small files depending on the use case). The error messages it creates on invalid YAML are not helpful currently.
YAML::PP::LibYAML
This combines the YAML::LibYAML::API binding for parsing with the YAML::PP frontend for loading and type resolving. It is faster than YAML::PP but slower than YAML::XS. The divergence from the YAML spec regarding syntax is usually not a problem, and at the same time you have the advantage of being compatible to the YAML 1.2 Core Schema.

WHY

Why did I start to write a new YAML module?

All the available parsers and loaders for Perl are behaving differently, and more important, aren't conforming to the spec. YAML::XS is doing pretty well, but "libyaml" only handles YAML 1.1 and diverges a bit from the spec. The pure perl loaders lack support for a number of features.

I was going over YAML.pm issues end of 2016, integrating old patches from rt.cpan.org and creating some pull requests myself. I realized that it would be difficult to patch YAML.pm to parse YAML 1.1 or even 1.2, and it would also break existing usages relying on the current behaviour.

In 2016 Ingy döt Net initiated two really cool projects:

"YAML TEST SUITE"
"YAML EDITOR"

These projects are a big help for any developer. So I got the idea to write my own parser and started on New Year's Day 2017. Without the test suite and the editor I would have never started this.

I also started another YAML Test project which allows one to get a quick overview of which frameworks support which YAML features:

"YAML TEST MATRIX"

YAML TEST SUITE

https://github.com/yaml/yaml-test-suite

It contains almost 400 test cases and expected parsing events and more. There will be more tests coming. This test suite allows you to write parsers without turning the examples from the Specification into tests yourself. Also the examples aren't completely covering all cases - the test suite aims to do that.

Thanks also to Felix Krause, who is writing a YAML parser in Nim. He turned all the spec examples into test cases.

YAML EDITOR

This is a tool to play around with several YAML parsers and loaders in vim.

https://github.com/yaml/yaml-editor

The project contains the code to build the frameworks (16 as of this writing) and put it into one big Docker image.

It also contains the yaml-editor itself, which will start a vim in the docker container. It uses a lot of funky vimscript that makes playing with it easy and useful. You can choose which frameworks you want to test and see the output in a grid of vim windows.

Especially when writing a parser it is extremely helpful to have all the test cases and be able to play around with your own examples to see how they are handled.

YAML TEST MATRIX

I was curious to see how the different frameworks handle the test cases, so, using the test suite and the docker image, I wrote some code that runs the tests, manipulates the output to compare it with the expected output, and created a matrix view.

https://github.com/perlpunk/yaml-test-matrix

You can find the latest build at https://matrix.yaml.info
