YAML::XS(3) Documentación de Perl contribuida por el usuario YAML::XS(3)

NOMBRE

YAML::XS - Serialización YAML de Perl usando XS y libyaml

SINOPSIS

use YAML::XS;
# Interfaz funcional clásica
my $yaml = Dump [ 1..4 ];
my $array = Load $yaml;
# EXPERIMENTAL: Interfaz orientada a objetos para YAML 1.2
# Incompatible con la interfaz funcional!
my $xs = YAML::XS->new;
my $yaml = $xs->dump([ 1..4 ]);
my $array = $xs->load($yaml);

DESCRIPCIÓN

La "libyaml" de Kirill Simonov es posiblemente la mejor implementación de YAML. La biblioteca C está escrita precisamente según la especificación YAML 1.1. Originalmente se enlazó a Python y más tarde se enlazó a Ruby.

Este módulo es un enlace XS de Perl a libyaml que ofrece a Perl el mejor soporte de YAML hasta la fecha.

Este módulo exporta las funciones "Dump", "Load", "DumpFile" y "LoadFile". Estas funciones están destinadas a funcionar exactamente como las funciones correspondientes de "YAML.pm". Solo "Load" y "Dump" se exportan por defecto.

CONFIGURACIÓN

La interfaz orientada a objetos se describe a continuación: "INTERFAZ ORIENTADA A OBJETOS"

  • $YAML::XS::LoadBlessed (desde v0.69)

    Por defecto: false.

    El valor por defecto se cambió en la versión 0.81.

    Cuando se establece en false, no "bendecirá" (bless) los datos en objetos, lo que puede ser un problema de seguridad al cargar YAML de una fuente no confiable. Ignorará silenciosamente la etiqueta y solo cargarçá los datos sin bendecir.

    En PyYAML, esto se llama SafeLoad.

    Si se establece en true, cargará lo siguiente de YAML como objetos:

    ---
local: !Foo::Bar [a]
perl: !!perl/hash:Foo::Bar { a: 1 }
regex: !!perl/regexp:Foo::Bar pattern

    Puedes crear cualquier tipo de objeto con YAML. La creación en sí no es la parte crítica. Si la clase tiene un método "DESTROY", se llamará una vez que el objeto sea eliminado. Un ejemplo con File::Temp eliminando archivos se puede encontrar en https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=862373.

  • $YAML::XS::ForbidDuplicateKeys (desde 0.84)

    Por defecto: false

    Cuando se establece en true, "Load" morirá al encontrar una clave duplicada en un hash, por ejemplo:

    key: value
key: another value

    Esto puede ser útil para documentos YAML más grandes donde no es tan obvio, y se recomienda establecerlo en true. Eso es también lo que un cargador YAML debería hacer por defecto según la especificación YAML.

  • $YAML::XS::UseCode
  • $YAML::XS::DumpCode
  • $YAML::XS::LoadCode

    Si está habilitado, admite la depuración y evaluación de bloques de código.

    Tenga en cuenta que el soporte para cargar código se agregó en la versión 0.75, aunque $LoadCode ya estaba documentado en versiones anteriores.

  • $YAML::XS::QuoteNumericStrings

    Cuando es true (el valor por defecto), las cadenas que parecen números pero que no han sido numificadas se citarán al volcar.

    Esto asegura que se conserven los formatos como ceros iniciales y otros.

  • $YAML::XS::Boolean (desde v0.67)

    Por defecto: undef

    Desde YAML::XS 0.89: Cuando se usa con perl 5.36 o posterior, los booleanos incorporados funcionarán directamente. Serán creados por "Load" y reconocidos por "Dump" automáticamente (desde YAML::XS 0.89).

    say Dump({ truth => builtin::true });
# truth: true

    Desde YAML::XS v0.902: los booleanos cargados ya no se establecen como de solo lectura.

    Para versiones de perl anteriores, puede usar la siguiente configuración para serializar datos como booleanos de YAML:

    Cuando se establece en "JSON::PP" o "boolean", las cadenas simples (sin comillas) "true" y "false" se cargarán como objetos "JSON::PP::Boolean" o "boolean.pm". Esos objetos se volcarán nuevamente como "true" o "false" simples.

    Intentará cargar [JSON::PP] o [boolean] y morirá si no se puede cargar.

    Con eso es posible agregar nuevos booleanos "reales" a una estructura de datos:

    local $YAML::XS::Boolean = "JSON::PP"; # o "boolean"
my $data = Load("booltrue: true");
$data->{boolfalse} = JSON::PP::false;
my $yaml = Dump($data);
# boolfalse: false
# booltrue: true

    También permite que los booleanos sobrevivan al cargar YAML a través de YAML::XS y codificarlos en JSON a través de uno de los varios codificadores JSON, que en su mayoría admiten booleanos de JSON::PP.

    Tenga en cuenta que JSON::PP::Boolean y boolean.pm se comportan un poco diferente. Idealmente, solo debería usarlos en contexto booleano.

    Si no se establece, los booleanos se cargan como variables especiales de perl "PL_sv_yes" y "PL_sv_no", que tienen la desventaja de ser de solo lectura, y no puede agregarlas a una estructura de datos existente con perl puro.

    Si simplemente necesita cargar "booleanos de perl" que sean true o false en contexto booleano, estará bien con la configuración predeterminada.

  • $YAML::XS::Indent (desde v0.76)

    El valor por defecto es 2.

    Establece el número de espacios para la indentación de "Dump".

USANDO YAML::XS CON UNICODE

Manejar unicode correctamente en Perl puede ser un dolor. YAML::XS solo trabaja con flujos de octetos utf8. Solo recuerde esto:

$perl = Load($utf8_octets);
$utf8_octets = Dump($perl);

Hay muchos, muchos lugares donde las cosas pueden salir mal con unicode. Si tiene problemas, use Devel::Peek en todos los puntos de datos posibles.

INTERFAZ ORIENTADA A OBJETOS

Desde la versión v0.904.0, EXPERIMENTAL

+++NOTA: ¡Esto es incompatible con la interfaz funcional y tratará los valores YAML de manera diferente.+++

Esto tiene dos diferencias PRINCIPALES con la antigua interfaz funcional:

Objeto con opciones
Esto proporciona una interfaz donde crea un objeto YAML::XS con opciones (en lugar de la antigua interfaz con variables globales).
Esquema Principal YAML 1.2
Implementa el Esquema Principal YAML 1.2.

(Tenga en cuenta que la interfaz funcional no implementa YAML 1.1, cuando se trata de cargar números, booleanos, nulos, etc. Implementa su propio conjunto de reglas).

Aquí hay un ejemplo (incompleto) de valores que se tratan de manera diferente que con la interfaz funcional. Los valores YAML que coinciden con un cierto patrón no se cargan como cadenas, sino como otros tipos:

# Interfaz funcional: valores especiales (no compatibles con otros módulos YAML)
- [true, false]                             # booleanos
- [null, ~]                                 # undef
- [inf, INF, iNf, iNF, InF, INf, -inf, ...] # Inf
- [100_000]                                 # 100000
- # anything that looks_like_number()       # número
# Valores especiales OOP YAML 1.2
- [true, True, TRUE, false, False, FALSE]   # booleanos
- [null, Null, NULL, ~]                     # undef
- [.inf, .Inf, .INF, -.inf, -.Inf, -.INF]   # Inf
- [.nan, .NAN, .NaN]                        # nan
- [42, 0x10, 0o10]                          # dec 42, hex 16, oct 8

Para diferencias más sutiles con respecto a los números, consulte los datos completos aquí:

YAML::XS(3pm) - Arch manual pages

NAME

YAML::XS - A YAML 1.2 processor, implemented in C.

SYNOPSIS

use YAML::XS ();
my $xs = YAML::XS->new;
my $yaml = $xs->load($yaml);
my $yaml = $xs->dump($data);

DESCRIPTION

YAML::XS is a parser and emitter for the YAML 1.2 data serialization language. It uses the libyaml C library.

It is written in C and therefore faster than pure-Perl modules like YAML::Tiny or YAML::PP.

For a full spec please see http://www.yaml.org/spec/1.2/spec.html

The test suite is based on the YAML Test Suite and can be found at https://github.com/yaml/yaml-test-suite

YAML Test Schema: <https://perlpunk.github.io/yaml-test-schema/schemas.html>
Test data: <https://perlpunk.github.io/yaml-test-schema/data.html>

This way the OOP interface is compatible to YAML::PP and YAML processors in other languages supporting YAML 1.2.

"load" will return the first document in scalar context
The functional interface returns the last.
Numbers don't have string flags
Booleans currently are only preserved for the new builtin booleans
Adding a JSON::PP boolean option for older perls is planned
References, objects, globs, regexes and coderefs cannot be loaded or dumped
This is planned.

Usage

use YAML::XS ();
my $xs = YAML::XS->new;
my $yaml = "foo: bar";
# Load single (first) document:
my $data = $xs->load($yaml);
$yaml = $xs->dump($data);
# Or to load all documents:
my @data = $xs->load($yaml);
$yaml = $xs->dump(@data);

METHODS

new

use YAML::XS;
my $xs = YAML::XS->new(
    # load options
    # require_footer => 0,
    # dump options
    # indent => 2,
    # header => 1,
    # footer => 0,
    # width => 80,
    # anchor_prefix => '',
    # load and dump options
    # utf8 => 0,
);

Options:

indent
Default: 2

Sets the number of spaces for indentation for dumping.

utf8
Default: false

When false, the loader will accept unencoded character strings, and the dumper returns unencoded character strings.

When true, the loader accepts a UTF-8 encoded string of bytes, and the dumper returns a UTF-8 encoded string of bytes. This typically makes sense when you read from / write to a file directly.

header
Default: 1

Writes a "---" before every document

footer
Default: 0

Writes a "..." at the end of every document.

width
Set the maximum number of colums for dumping. If a value has too many characters, it will be split into multiple lines.
require_footer
Default: 0

Can be useful in a use case where you want to make sure you received the complete document from the sender.

anchor_prefix
Default: ''

If set to a string like "ANCHOR", anchors and aliases will be prefixed with this instead of just being numbers:

# my $xs = YAML::XS->new( anchor_prefix => 'ANCHOR' );
# my $hash = { some => "mapping" };
# say $xs->dump([$hash, $hash]);
- &ANCHOR1
  some: mapping
- *ANCHOR1

load

my $yaml = <<'EOM';
---
- 23
---
some: mapping
EOM
my $array = $xs->load($yaml);
# [23]
my @documents = $xs->load($yaml);
# (
#   [23],
#   { some => "mapping" }
# )

In scalar context, if the YAML string contains more than one document, it will return the first document.

dump

$yaml = $xs->dump($data);
$yaml = $xs->dump($data1, $data2, $data3);
$yaml = $xs->dump(@data);

CONFIGURATION

YAML::XS loads the options passed to its constructor. The same options can be passed to the load and dump methods.

USING YAML::XS WITH UNICODE

By default, YAML::XS operates in binary mode. This means that non-ASCII characters will be encoded using UTF-8 when dumping, and will be decoded from UTF-8 when loading.

If you want to use UTF-8 explicitly, you can pass the utf8 option to the constructor:

my $xs = YAML::XS->new( utf8 => 1 );

When utf8 is true, YAML::XS will always use UTF-8 encoding for input and output. This is usually the desired behavior when working with text files.

When utf8 is false (the default), YAML::XS will perform auto-detection of character encoding. This can be useful when dealing with input that may not be UTF-8 encoded.

OBJECT ORIENTED INTERFACE

YAML::XS provides an object-oriented interface for loading and dumping YAML data. You can create a YAML::XS object and then use its load and dump methods.

my $xs = YAML::XS->new;
my $data = $xs->load($yaml_string);
my $yaml_string = $xs->dump($perl_data);

The object-oriented interface is generally preferred, as it allows you to configure options like indentation and header/footer printing.

LIBYAML

You can find out (since v.079) which libyaml version this module was built with:

my $libyaml_version = YAML::XS::LibYAML::libyaml_version();
