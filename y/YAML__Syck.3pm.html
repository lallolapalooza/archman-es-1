YAML::Syck(3) Documentación de Perl aportada por el usuario YAML::Syck(3)

NOMBRE

YAML::Syck - Cargador y volcador YAML rápido y ligero

SINOPSIS

use YAML::Syck;
# Establecer esto para interoperabilidad con otros enlaces YAML/Syck:
# p. ej., Load('Yes') se convierte en 1 y Load('No') se convierte en ''.
$YAML::Syck::ImplicitTyping = 1;
$data = Load($yaml);
$yaml = Dump($data);
# $file puede ser un objeto IO o un nombre de archivo
$data = LoadFile($file);
DumpFile($file, $data);
# Una cadena con múltiples flujos YAML en ella
$yaml = Dump(@data);
@data = Load($yaml);
# Volcado en un búfer de salida preexistente
my $yaml;
DumpInto(\$yaml, @data);

DESCRIPCIÓN

Este módulo proporciona una interfaz de Perl a la biblioteca de serialización de datos libsyck. Exporta las funciones "Dump" y "Load" para convertir estructuras de datos de Perl a cadenas YAML y viceversa.

NOTA: Si está trabajando con enlaces YAML/Syck de otros lenguajes (como Ruby), establezca $YAML::Syck::ImplicitTyping a 1 antes de llamar a las funciones "Load"/"Dump". La configuración predeterminada es para preservar la compatibilidad con versiones anteriores con "YAML.pm".

Diferencias entre YAML::Syck y YAML

Manejo de errores

Algunas llamadas están diseñadas para fallar en lugar de devolver YAML. Debería envolver sus llamadas en eval para asegurarse de no obtener resultados inesperados.

FLAGS

$YAML::Syck::Headless

Por defecto es falso. Establecer esto a un valor verdadero hará que "Dump" omita el marcador inicial "---\n".

$YAML::Syck::SortKeys

Por defecto es falso. Establecer esto a un valor verdadero hará que "Dump" ordene las claves hash.

$YAML::Syck::SingleQuote

Por defecto es falso. Establecer esto a un valor verdadero hará que "Dump" emita siempre comillas simples en lugar de cadenas sin comillas.

$YAML::Syck::ImplicitTyping

Por defecto es falso. Establecer esto a un valor verdadero hará que "Load" reconozca varios tipos implícitos en YAML, como "true", "false" sin comillas, así como enteros y números de punto flotante. De lo contrario, solo "~" se reconoce como "undef".

$YAML::Syck::ImplicitUnicode

Por defecto es falso. Para Perl 5.8.0 o posterior, establecer esto a un valor verdadero hará que "Load" establezca el indicador Unicode para cada cadena que contenga secuencias UTF8 válidas, y hará que "Dump" devuelva una cadena Unicode.

Independientemente de esta bandera, las cadenas Unicode se vuelcan tal cual sin escapar; las cadenas de bytes con el bit alto establecido se volcarán con escape de barra invertida.

Sin embargo, dado que YAML no distingue entre estos dos tipos de cadenas, esta bandera afectará la carga de ambas variantes de cadenas.

Si desea utilizar LoadFile o DumpFile con Unicode, debe abrir su propio archivo para asegurarse de que esté codificado en UTF8:

open(my $fh, ">:encoding(UTF-8)", "out.yml");
DumpFile($fh, $hashref);

$YAML::Syck::ImplicitBinary

Por defecto es falso. Para Perl 5.8.0 o posterior, establecer esto a un valor verdadero hará que "Dump" genere datos "!!binary" codificados en Base64 para todos los escalares no Unicode que contengan bytes de bit alto.

$YAML::Syck::UseCode / $YAML::Syck::LoadCode / $YAML::Syck::DumpCode

Estos flags controlan si se intenta evaluar/descompilar código fuente de perl; cada uno de ellos tiene un valor predeterminado de falso.

Establecer $YAML::Syck::UseCode a un valor verdadero es equivalente a establecer tanto $YAML::Syck::LoadCode como $YAML::Syck::DumpCode a verdadero.

$YAML::Syck::LoadBlessed

Por defecto es falso. Establecerlo a verdadero permitirá que YAML::Syck bendiga objetos al importar objetos. Este valor predeterminado cambió en 1.32.

Puede crear cualquier tipo de objeto con YAML. La creación en sí no es la parte crítica. Si la clase tiene un método DESTROY, se llamará una vez que el objeto sea eliminado. Un ejemplo con File::Temp eliminando archivos se puede encontrar en https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=862373

ERRORES

El volcado de valores Glob/IO aún no funciona.

El volcado de variables ligadas (Tied) no está soportado.

El volcado en variables ligadas (o otras variables mágicas) con "DumpInto" podría no funcionar correctamente en todos los casos.

ADVERTENCIAS

Este módulo implementa la especificación YAML 1.0. Para tratar con datos en YAML 1.1, utilice el módulo "YAML::XS" en su lugar.

La implementación actual agrupa el código fuente de libsyck; si su sistema tiene una libsyck compartida a nivel de sitio, no se utilizará.

Los nombres de etiquetas como "!!perl/hash:Foo" se bendicen en el paquete "Foo", pero las etiquetas "!hs/foo" y "!!hs/Foo" se bendicen en "hs::Foo". Tenga en cuenta que esto es cierto incluso si la etiqueta contiene caracteres no alfanuméricos; por ejemplo, "!haskell.org/Foo" se bendice en "haskell.org::Foo". Por favor, utilice Class::Rebless para convertirlo a otros paquetes definidos por el usuario. También puede establecer la bandera LoadBlessed a falso para deshabilitar toda la bendición.

Este módulo tiene muchos errores conocidos https://rt.cpan.org/Public/Dist/Display.html?Name=YAML-Syck y solo ha sido mantenido semi-activamente desde 2007. Si encuentra un problema con él, probablemente no se solucionará a menos que ofrezca un parche http://github.com/toddr/YAML-Syck en Git que esté listo para ser lanzado.

Todavía hay buenas razones para usar este módulo, como una mejor interoperabilidad con otros envoltorios de syck (como el de Ruby), o algún caso límite de la sintaxis de YAML que maneja mejor. Probablemente funcionará perfectamente para usted, pero si no lo hace, puede que quiera considerar YAML::XS, o quizás buscar otro formato de serialización como JSON.
