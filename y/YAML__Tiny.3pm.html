YAML::Tiny(3) Documentación de Perl contribuida por el usuario YAML::Tiny(3)

NOMBRE

YAML::Tiny - Leer/Escribir archivos YAML con la menor cantidad de código posible

VERSIÓN

versión 1.76

PREÁMBULO

La especificación YAML es enorme. Realmente, muy enorme. Contiene toda la funcionalidad de XML, pero con flexibilidad y elección, lo que la hace más fácil de leer, pero con una especificación formal más compleja que XML.

La implementación original puramente en Perl de YAML cuesta poco más de 4 megabytes de memoria para cargar. Al igual que con los archivos .ini de Windows (3 megas para cargar) y CSS (3.5 megas para cargar), la situación solo pide un módulo YAML::Tiny, un subconjunto incompleto pero correcto y utilizable de la funcionalidad, con la menor cantidad de código posible.

Al igual que otros módulos "::Tiny", YAML::Tiny no tiene dependencias externas al núcleo, no requiere un compilador para instalarse, es compatible hacia atrás hasta Perl v5.8.1 y puede ser incrustado en otros módulos si es necesario.

A cambio de añadir esta extrema flexibilidad, proporciona soporte para solo un subconjunto limitado de YAML. Pero el subconjunto soportado contiene la mayoría de las características para los usos más comunes de YAML.

SINOPSIS

Asumiendo un archivo file.yml como este:

---
rootproperty: blah
section:
  one: two
  three: four
  Foo: Bar
  empty: ~

Leer y escribir el archivo file.yml así:

use YAML::Tiny;
# Abrir la configuración
my $yaml = YAML::Tiny->read( 'file.yml' );
# Obtener una referencia al primer documento
my $config = $yaml->[0];
# O leer propiedades directamente
my $root = $yaml->[0]->{rootproperty};
my $one  = $yaml->[0]->{section}->{one};
my $Foo  = $yaml->[0]->{section}->{Foo};
# Cambiar datos directamente
$yaml->[0]->{newsection} = { this => 'that' }; # Añadir una sección
$yaml->[0]->{section}->{Foo} = 'Not Bar!';     # Cambiar un valor
delete $yaml->[0]->{section};                  # Eliminar un valor
# Guardar el documento de vuelta al archivo
$yaml->write( 'file.yml' );

Para crear un nuevo archivo YAML desde cero:

# Crear un nuevo objeto con un solo documento hashref
my $yaml = YAML::Tiny->new( { wibble => "wobble" } );
# Añadir un documento arrayref
push @$yaml, [ 'foo', 'bar', 'baz' ];
# Guardar ambos documentos en un archivo
$yaml->write( 'data.yml' );

Entonces data.yml contendrá:

---
wibble: wobble
---
- foo
- bar
- baz

DESCRIPCIÓN

YAML::Tiny es una clase de Perl para leer y escribir archivos estilo YAML, escrita con la menor cantidad de código posible, reduciendo el tiempo de carga y la sobrecarga de memoria.

La mayoría de las veces se acepta que las aplicaciones de Perl utilizan mucha memoria y módulos. La familia de módulos ::Tiny está específicamente destinada a proporcionar una alternativa ultraligera y sin dependencias a muchos módulos estándar más completos.

Este módulo es principalmente para leer archivos escritos por humanos (como archivos de configuración sencillos) y generar archivos muy simples y legibles por humanos. Tenga en cuenta que dije legibles por humanos y no legibles por geeks. El tipo de archivos que su gerente o secretario promedio debería poder mirar y entender.

YAML::Tiny no genera comentarios, no conservará necesariamente el orden de sus hashes y normalizará si lee y escribe de nuevo.

Solo soporta un subconjunto muy básico de la especificación completa de YAML.

El uso está dirigido a archivos como el META.yml de Perl, para el cual un módulo pequeño y fácilmente incrustable es extremadamente atractivo.

Las características solo se añadirán si son legibles por humanos y pueden ser escritas en unas pocas líneas de código. Por favor, no se ofenda si su solicitud es rechazada. Alguien tiene que trazar la línea, y para YAML::Tiny ese alguien soy yo.

Si necesita algo con más potencia, pase a YAML (7 megabytes de sobrecarga de memoria) o YAML::XS (6 megabytes de sobrecarga de memoria y requiere un compilador C).

Para reiterar, YAML::Tiny no conserva sus comentarios, espacios en blanco ni el orden de sus datos YAML. Pero debería funcionar sin problemas de la estructura de Perl al archivo y viceversa.

MÉTODOS

new

El constructor "new" crea un objeto "YAML::Tiny" como una referencia a un array bendecido. Cualquier argumento proporcionado se toma como documentos separados para ser serializados.

read $nombre_archivo

El constructor "read" lee un archivo YAML de un nombre de archivo y devuelve un nuevo objeto "YAML::Tiny" que contiene el contenido analizado.

Devuelve el objeto en caso de éxito o lanza un error en caso de fallo.

read_string $cadena;

El constructor "read_string" lee datos YAML de una cadena de caracteres y devuelve un nuevo objeto "YAML::Tiny" que contiene el contenido analizado. Si ha leído la cadena de un archivo usted mismo, asegúrese de haberla decodificado correctamente en caracteres primero.

Devuelve el objeto en caso de éxito o lanza un error en caso de fallo.

write $nombre_archivo

El método "write" genera el contenido del archivo para las propiedades y lo escribe en disco usando codificación UTF-8 al nombre de archivo especificado.

Devuelve verdadero en caso de éxito o lanza un error en caso de fallo.

write_string

Genera el contenido del archivo para el objeto y lo devuelve como una cadena de caracteres. Esto puede contener caracteres no ASCII y debe ser codificado antes de escribirlo en un archivo.

Devuelve verdadero en caso de éxito o lanza un error en caso de fallo.

errstr (DEPRECADO)

Antes de la versión 1.57, algunos errores eran fatales y otros solo estaban disponibles a través de la variable $YAML::Tiny::errstr, a la que se podía acceder a través del método errstr().

A partir de la versión 1.57, todos los errores son fatales y lanzan excepciones.

La variable $errstr todavía se establece cuando se lanzan excepciones, pero $errstr y el método errstr() están deprecados y pueden ser eliminados en una futura versión. El primer uso de errstr() emitirá una advertencia de deprecación.

FUNCIONES

YAML::Tiny implementa una serie de funciones para añadir compatibilidad con la API de YAML. Estas deberían ser un reemplazo directo.

Dump

my $cadena = Dump(lista-de-estructuras-de-datos-de-Perl);

Convertir datos de Perl a YAML. Esta función funciona de manera muy similar a Data::Dumper::Dumper().

Toma una lista de estructuras de datos de Perl y las vuelca en un formato serializado.

Devuelve una cadena de caracteres que contiene el flujo YAML. Asegúrese de codificarlo como UTF-8 antes de serializarlo a un archivo o socket.

Las estructuras pueden ser referencias o escalares simples.

Muere ante cualquier error.

Load

my @estructuras_de_datos = Load(cadena-que-contiene-un-flujo-YAML);

Convertir YAML a datos de Perl. Este es el opuesto de Dump.

Al igual que la función thaw() de Storable o la función eval() en relación con Data::Dumper.

Analiza una cadena de caracteres que contiene un flujo YAML válido en una lista de estructuras de datos de Perl que representan los documentos YAML individuales. Asegúrese de decodificar correctamente la cadena de caracteres si la cadena provino de un archivo o socket.

my $ultima_estructura_de_datos = Load(cadena-que-contiene-un-flujo-YAML);

Para consistencia con YAML.pm, cuando Load se llama en contexto de escalar, devuelve la estructura de datos correspondiente al último de los documentos YAML encontrados en el flujo de entrada.

>

Muere en cualquier error.

freeze() y thaw()

Alias de Dump() y Load() para fans de Storable. Esto también permitirá que YAML::Tiny se conecte directamente a módulos como POE.pm, que utilizan la API freeze/thaw para la serialización interna.

DumpFile(filepath, lista)

Escribe el flujo YAML en un archivo con codificación UTF-8 en lugar de simplemente devolver una cadena.

Muere en cualquier error.

LoadFile(filepath)

Lee el flujo YAML de un archivo codificado en UTF-8 en lugar de una cadena.

Muere en cualquier error.

ESPECIFICACIÓN DE YAML TINY

Esta sección de la documentación proporciona una especificación para "YAML Tiny", un subconjunto de la especificación YAML.

Se basa y se describe comparativamente con la especificación del Borrador de Trabajo 2004-12-28 de YAML 1.1, ubicada en http://yaml.org/spec/current.html.

La terminología y los números de capítulo se basan en esa especificación.

1. Introducción y Objetivos

El propósito de la especificación YAML Tiny es describir un subconjunto útil de la especificación YAML que puede usarse para casos de uso típicos orientados a documentos, como archivos de configuración y volcados de estructuras de datos simples.

Muchos elementos de especificación que agregan flexibilidad o extensibilidad se eliminan intencionalmente, al igual que el soporte para estructuras de datos complejas, orientación a clases y objetos.

En general, el lenguaje YAML Tiny apunta solo a aquellas estructuras de datos disponibles en JSON, con la limitación adicional de que solo se admiten claves simples.

Como resultado, todos los documentos YAML Tiny posibles deberían poder transformarse en un documento JSON equivalente, aunque lo inverso no es necesariamente cierto (pero será cierto en casos simples).

Como resultado de estas simplificaciones, la especificación YAML Tiny debería ser implementable en una cantidad (relativamente) pequeña de código en cualquier idioma que admita expresiones regulares compatibles con Perl (PCRE).

2. Introducción

YAML Tiny admite tres estructuras de datos. Estas son escalares (en una variedad de formas), secuencias de forma de bloque y mapeos de forma de bloque. No se admiten secuencias y mapeos de estilo de flujo, con algunas excepciones menores detalladas más adelante.

Se admite el uso de tres guiones "---" para indicar el inicio de un nuevo documento, y se permiten múltiples documentos por archivo/flujo.

Se admiten tanto los comentarios de línea como los en línea.

Los escalares se admiten a través del estilo plano, comillas simples y comillas dobles, así como escalares multilínea de estilo literal y plegado.

No se admite el uso de etiquetas explícitas.

Se admite el uso de escalares de tipo "null" a través del carácter ~.

No se admite el uso de escalares de tipo "bool".

Sin embargo, las implementaciones del serializador deben tener cuidado de escapar explícitamente las cadenas que coincidan con una palabra clave "bool" en el siguiente conjunto para evitar que otras implementaciones que admiten "bool" lean accidentalmente una cadena como booleana

y|Y|yes|Yes|YES|n|N|no|No|NO
|true|True|TRUE|false|False|FALSE
|on|On|ON|off|Off|OFF

No se admite el uso de anclajes y alias.

Se admite el uso de directivas solo para la directiva %YAML.

3. Procesamiento de Información de YAML Tiny

Procesos

La especificación YAML dicta serialización en tres fases y deserialización en tres fases.

La especificación YAML Tiny no exige ninguna metodología o mecanismo de análisis particular.

Cualquier analizador compatible solo debe analizar un documento a la vez. La capacidad de admitir flujos de documentos es opcional y muy probablemente no típica.

Dado que no se admiten anclajes ni alias, el gráfico de representación resultante es, por lo tanto, dirigido pero (a diferencia de la especificación YAML principal) acíclico.

No son posibles referencias/punteros circulares, y cualquier serializador YAML Tiny que detecte una referencia circular debería generar un error con un mensaje apropiado.

Flujo de Presentación

YAML Tiny lee y escribe archivos codificados en UTF-8. Las operaciones sobre cadenas esperan o producen caracteres Unicode, no bytes codificados en UTF-8.

Puntos de Fallo de Carga

No se espera que los analizadores y emisores de YAML Tiny se recuperen o adapten a los errores. La modalidad de error específica de cualquier implementación no está dictada (códigos de retorno, excepciones, etc.), pero se espera que sea consistente.

4. Sintaxis

Conjunto de Caracteres

Los flujos de YAML Tiny se procesan en memoria como caracteres Unicode y se leen/escriben con codificación UTF-8.

Se requiere el escape y desescape de los escapes YAML de 8 bits.

No se requiere el escape y desescape de los escapes YAML de 16 y 32 bits.

Caracteres Indicadores

Se requiere soporte para el indicador nulo/indefinido "~".

Las implementaciones pueden representarlo como sea apropiado para el idioma subyacente.

Se requiere soporte para el indicador de secuencia de bloque "-".

No se requiere soporte para el indicador de clave de mapeo "?".

Se requiere soporte para el indicador de valor de mapeo ":".

No se requiere soporte para el indicador de colección de flujo ",".

No se requiere soporte para el indicador de secuencia de flujo "[" , con una excepción (detallada más adelante).

No se requiere soporte para el indicador de secuencia de flujo "]", con una excepción (detallada más adelante).

No se requiere soporte para el indicador de mapeo de flujo "{", con una excepción (detallada más adelante).

No se requiere soporte para el indicador de mapeo de flujo "}", con una excepción (detallada más adelante).

Se requiere soporte para el indicador de comentario "#".

No se requiere soporte para el indicador de anclaje "&".

No se requiere soporte para el indicador de alias "*".

No se requiere soporte para el indicador de etiqueta "!".

Se requiere soporte para el indicador de bloque literal "|".

Se requiere soporte para el indicador de bloque plegado ">".

Se requiere soporte para el indicador de comillas simples "'".

Se requiere soporte para el indicador de comillas dobles "\"".

Se requiere soporte para el indicador de directiva "%", pero solo para el caso especial de una directiva de versión %YAML antes del encabezado del documento "---", o en la misma línea que el encabezado del documento.

Por ejemplo:

%YAML 1.1
---
- Una secuencia con un solo elemento

Excepción Especial:

Para proporcionar la capacidad de admitir secuencias y mapeos vacíos, se requiere soporte para las construcciones [] (secuencia vacía) y {} (mapeo vacío).

Por ejemplo,

%YAML 1.1
# Un documento que consiste solo en un mapeo vacío
--- {}
# Un documento que consiste solo en una secuencia vacía
--- []
# Un documento que consiste en un mapeo vacío dentro de una secuencia
- foo
- {}
- bar

Primitivas de Sintaxis

Aparte de los casos de secuencia y mapeo vacíos descritos anteriormente, YAML Tiny solo admite el grupo de contextos de estilo de bloque basado en la indentación.

Los cinco contextos escalares son compatibles.

Los espacios de indentación funcionan según la especificación YAML en todos los casos.

Los comentarios funcionan según la especificación YAML en todos los casos simples. No se requiere soporte para comentarios multilínea indentados.

Los espacios de separación funcionan según la especificación YAML en todos los casos.

Flujo de Caracteres de YAML Tiny

La única directiva admitida por la especificación YAML Tiny es el identificador de idioma/versión %YAML. Aunque detectada, esta directiva no tendrá control sobre el análisis en sí.

El analizador debe reconocer tanto el formato YAML 1.0 como el YAML 1.1+ de esta directiva (así como la forma comentada, aunque no se debe necesitar código explícito para tratar este caso, al ser un comentario de todos modos)

Es decir, se deben admitir todas las siguientes opciones.

--- #YAML:1.0
- foo
%YAML:1.0
---
- foo
% YAML 1.1
---
- foo

No se requiere soporte para la directiva %TAG.

No se requiere soporte para directivas adicionales.

Se requiere soporte para el marcador de límite de documento "---".

No se requiere soporte para el marcador de límite de documento "...".

Si es necesario, un límite de documento simplemente debe indicarse con un marcador "---", sin un marcador "..." precedente.

Se requiere soporte para flujos vacíos (que no contienen documentos).

Se requiere soporte para inicios de documentos implícitos.

Es decir, lo siguiente debe ser equivalente.

# Forma completa
%YAML 1.1
---
foo: bar
# Forma implícita
foo: bar

Nodos

No se requiere soporte para las propiedades opcionales de anclaje y etiqueta de los nodos.

No se requiere soporte para anclajes de nodos.

No se requiere soporte para etiquetas de nodos.

No se requiere soporte para nodos alias.

No se requiere soporte para nodos de flujo.

Se requiere soporte para nodos de bloque.

Estilos Escalares

Se requiere soporte para los cinco estilos escalares según la especificación YAML, aunque no se requiere soporte para escalares entre comillas que abarquen más de una línea.

No se requiere soporte para documentos escalares multilínea que comiencen en el encabezado.

Se requiere soporte para los indicadores de "chopped" en estilos escalares multilínea.

NAME

YAML::Tiny - A minimal subset of the YAML specification.

VERSION

1.76

PREAMBLE

This document describes the YAML Tiny specification.

SYNOPSIS

    use YAML::Tiny;

    my $yaml = YAML::Tiny->new({
        'a' => [ 1, 2, 3 ],
        'b' => {
            'c' => 'hello',
            'd' => 'world',
        },
    });

    my $string = $yaml->write('file.yaml');
    my $data = YAML::Tiny->read('file.yaml');

DESCRIPTION

YAML Tiny is a subset of the YAML specification that is intended to be very simple to implement and to use. It can be used to represent simple data structures such as hashes and arrays.

METHODS

new
Creates a new YAML::Tiny object. The object can be initialized with a Perl data structure. If no data structure is provided, an empty object is created.
read
Reads a YAML document from a file. Takes a file name as an argument and returns a YAML::Tiny object representing the data in the file.
parse
Parses a YAML string. Takes a string as an argument and returns a YAML::Tiny object representing the data in the string.
write
Writes a YAML document to a file. Takes a file name as an argument. If the file exists, it will be overwritten. Returns the YAML string that was written.
dump
Dumps a YAML::Tiny object to a string. Returns the YAML string representation of the object.

FUNCTIONS

The following functions are also exported by YAML::Tiny:

load
An alias for read.
dump
An alias for dump.
load_file
An alias for read.
parse_string
An alias for parse.

YAML TINY SPECIFICATION

YAML Tiny is a very small subset of the YAML specification. It is intended to be sufficient for common configuration file needs.

The following features are supported:

  • Indentation-based block structures.
  • Plain-style scalars.
  • Numeric, boolean and null scalars.
  • Key-value pairs in mappings.
  • Elements in sequences.

The following features are not supported:

  • Flow-style sequences (e.g., [a, b, c]).
  • Flow-style mappings (e.g., {a: 1, b: 2}).
  • Quoted keys in mappings.
  • Explicit keys (e.g., ? key).
  • Tags and anchors.
  • Comments.
  • Multi-document YAML files.
  • Pipes and greater-than indicators for block literals.
  • Explicit document start/end markers (--- and ...).

Specific requirements:

Support for block-style sequences is required.

Support for flow-style sequences is not required.

Support for block-style mappings is required.

Support for flow-style mappings is not required.

Both sequences and mappings should be able to be arbitrarily nested.

Support for plain-style mapping keys is required.

Support for quoted keys in mappings is not required.

Support for "?"-indicated explicit keys is not required.

Here endeth the specification.

Additional Perl-Specific Notes

For some Perl applications, it's important to know if you really have a number and not a string.

That is, in some contexts is important that 3 the number is distinctive from "3" the string.

Because even Perl itself is not trivially able to understand the difference (certainly without XS-based modules) Perl implementations of the YAML Tiny specification are not required to retain the distinctiveness of 3 vs "3".
