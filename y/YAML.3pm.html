YAML(3pm) Documentación de Contribución de Usuarios de Perl YAML(3pm)

NOMBRE

YAML - YAML Ain't Markup Language™

VERSIÓN

Este documento describe la versión de YAML 1.31.

IMPORTANTE - POR FAVOR LEER ESTO PRIMERO

Si necesita usar YAML con Perl, es probable que mire este módulo ("YAML.pm") primero. Hay varios módulos de YAML https://metacpan.org/search?q=yaml en Perl y todos ellos soportan la API simple Load() y Dump(). Dado que este tiene el nombre obvio "YAML", puede parecer obvio elegir este.

Como autor de este módulo, humildemente le pido que elija otro. YAML.pm fue la primera implementación de YAML del mundo, lanzada en 2001. Originalmente se hizo como un prototipo, más de 2 años antes de que se publicara la especificación YAML 1.0. Aunque puede funcionar para sus necesidades, tiene numerosos errores y apenas se mantiene.

Por favor, considere usar estos primero:

  • YAML::PP - Puro Perl, Completo, Bien Mantenido
  • YAML::PP::LibYAML - Un enlace de Perl a "libyaml" similar a YAML::XS pero con la API de YAML::PP.

El resto de esta documentación se deja sin cambios...

use YAML;
# Carga un flujo YAML de 3 documentos YAML en estructuras de datos Perl.
my ($hashref, $arrayref, $string) = Load(<<'...');

age: old
weight: heavy
# Debería comentar que también me gusta el rosa, pero no se lo digas a nadie.
favorite colors:
  - red
  - green
  - blue
---
- Clark Evans    # Una Secuencia
- Oren Ben-Kiki
- Ingy döt Net
--- >            # Un Escalar de Bloque

DESCRIPCIÓN

El módulo YAML.pm implementa un Cargador y un Volcador YAML basado en la especificación YAML 1.0. http://www.yaml.org/spec/

YAML es un lenguaje de serialización de datos genérico optimizado para la legibilidad humana. Se puede usar para expresar las estructuras de datos de la mayoría de los lenguajes de programación modernos. (¡¡¡Incluido Perl!!!)

Para obtener información sobre la sintaxis YAML, consulte la especificación YAML.

POR QUÉ YAML ES GENIAL

YAML es legible para personas.
Da sentido claro a estructuras de datos complejas. Debería encontrar que YAML es una herramienta excepcional para volcar datos. La estructura se muestra a través de la indentación, YAML soporta datos recursivos y las claves de hash se ordenan por defecto. Además, YAML soporta varios estilos de formato de escalar para diferentes tipos de datos.
YAML es editable.
YAML fue diseñado desde cero para ser una sintaxis excelente para archivos de configuración. Casi todos los programas necesitan archivos de configuración, ¿por qué inventar una nueva sintaxis para cada uno? ¿Y por qué someter a los usuarios a las complejidades de XML o código Perl nativo?
YAML es multilingüe.
Sí, YAML soporta Unicode. Pero en realidad me refiero a lenguajes de programación. YAML fue diseñado para satisfacer las necesidades de serialización de Perl, Python, Ruby, Tcl, PHP, Javascript y Java. También fue diseñado para ser interoperable entre esos lenguajes. Eso significa que las serializaciones YAML producidas por Perl pueden ser procesadas por Python.
YAML es seguro contra contaminación (taint safe).
Usar módulos como Data::Dumper para la serialización está bien siempre que pueda estar seguro de que nadie puede manipular sus archivos o transmisiones de datos. Eso es porque necesita usar el comando incorporado de Perl eval() para deserializar los datos. Alguien podría agregar un fragmento de Perl para borrar sus archivos.

El analizador de YAML no necesita evaluar nada.

YAML es completo.
YAML puede serializar con precisión todas las estructuras de datos Perl comunes y deserializarlas de nuevo sin perder las relaciones de datos. Aunque no es 100% perfecto (ningún serializador lo es o puede serlo), funciona tan bien como los módulos populares actuales: Data::Dumper, Storable, XML::Dumper y Data::Denter.

YAML.pm también tiene la capacidad de manejar referencias de código (subrutinas) y typeglobs. (Aún experimental) Estas características no se encuentran en otros módulos de serialización de Perl.

YAML es extensible.
El lenguaje YAML ha sido diseñado para ser lo suficientemente flexible como para resolver sus propios problemas. El marcado en sí tiene 3 constructos básicos que se asemejan al hash, array y escalar de Perl. Por defecto, estos se mapean a sus equivalentes en Perl. Pero cada nodo YAML también soporta un mecanismo de etiquetado (sistema de tipos) que puede hacer que ese nodo se interprete de manera completamente diferente. Así es como YAML puede soportar la serialización de objetos y estructuras peculiares como el typeglob de Perl.

IMPLEMENTACIONES DE YAML EN PERL

Este módulo, YAML.pm, es realmente solo el módulo de interfaz para módulos YAML escritos en Perl. La interfaz básica para YAML consta de dos funciones: "Dump" y "Load". El trabajo real lo realizan los módulos YAML::Dumper y YAML::Loader.

Se pueden crear diferentes distribuciones de módulos YAML subclasificando YAML.pm y YAML::Loader y YAML::Dumper. Por ejemplo, YAML-Simple consta de YAML::Simple YAML::Dumper::Simple y YAML::Loader::Simple.

¿Por qué habría más de una implementación de YAML? Bueno, a pesar de que YAML ofrece ser un formato de datos simple, en realidad es muy profundo y complejo. Implementar la totalidad de la especificación YAML es una tarea abrumadora.

Por esta razón, actualmente estoy trabajando en 3 implementaciones diferentes de YAML.

YAML
La distribución principal de YAML seguirá evolucionando para soportar la especificación YAML completa en Perl puro. Sin embargo, puede que no sea el módulo más rápido o más estable. Actualmente, YAML.pm tiene muchos errores conocidos. Es principalmente una gran herramienta para volcar estructuras de datos Perl a un formato legible.
YAML::Tiny
El propósito de YAML::Tiny es reducir YAML al 90% que la gente usa más y ofrecerlo en un formato pequeño, rápido, estable y puro Perl. YAML::Tiny simplemente fallará cuando se le pida hacer algo que no puede.
YAML::Syck
"libsyck" es la biblioteca de procesamiento YAML basada en C utilizada por el lenguaje de programación Ruby (y también Python, PHP y Pugs). YAML::Syck es el enlace de Perl a "libsyck". Debería ser muy rápido, pero puede tener sus propios problemas. También requerirá compilación en C.

NOTA: Audrey Tang ha completado este módulo y funciona muy bien y es
10 veces más rápido que YAML.pm.

En el futuro, probablemente habrá aún más módulos YAML. ¡Recuerde, otras personas además de Ingy tienen permitido escribir módulos YAML!

USO FUNCIONAL

YAML es completamente OO bajo el capó. Aún así, exporta algunas funciones útiles de nivel superior para que sea muy simple de usar. Estas funciones simplemente hacen el trabajo OO por usted. Si desea acceso directo a la API OO, consulte la documentación de YAML::Dumper y YAML::Loader.

Funciones Exportadas

Las siguientes funciones son exportadas por YAML.pm por defecto. La razón por la que se exportan es para que YAML funcione de manera muy similar a Data::Dumper. Si no desea que se importen funciones, simplemente use YAML con una lista de importación vacía:

use YAML ();
Dump(lista-de-estructuras-de-datos-Perl)<

NAME

YAML - A Perl module to serialize and deserialize Perl data structures to/from the YAML format.

SYNOPSIS

    use YAML;
    my $perl_data = {
        foo => 1,
        bar => [ 'a', 'b', 'c' ],
        baz => {
            qux => 'hello',
            quux => 'world',
        },
    };
    my $yaml_string = Dump($perl_data);
    print $yaml_string;
    my @loaded_data = Load($yaml_string);

DESCRIPTION

This module provides functions to convert Perl data structures into YAML streams, and vice versa.

Core Functions

Dump(list)
Turn Perl data into YAML. This function works very much like Data::Dumper::Dumper(). It takes a list of Perl data structures and dumps them into a serialized form. It returns a string containing the YAML stream. The structures can be references or plain scalars.
Load(string-containing-a-YAML-stream)
Turn YAML into Perl data. This is the opposite of Dump. Just like Storable's thaw() function or the eval() function in relation to Data::Dumper. It parses a string containing a valid YAML stream into a list of Perl data structures.

Exportable Functions

These functions are not exported by default but you can request them in an import list like this:

use YAML qw'freeze thaw Bless';
freeze() and thaw()
Aliases to Dump() and Load() for Storable fans. This will also allow YAML.pm to be plugged directly into modules like POE.pm, that use the freeze/thaw API for internal serialization.
DumpFile(filepath, list)
Writes the YAML stream to a file instead of just returning a string.
LoadFile(filepath)
Reads the YAML stream from a file instead of a string.
Bless(perl-node, [yaml-node | class-name])
Associate a normal Perl node, with a yaml node. A yaml node is an object tied to the YAML::Node class. The second argument is either a yaml node that you've already created or a class (package) name that supports a yaml_dump() function. A yaml_dump() function should take a perl node and return a yaml node. If no second argument is provided, Bless will create a yaml node. This node is not returned, but can be retrieved with the Blessed() function.

Here's an example of how to use Bless. Say you have a hash containing three keys, but you only want to dump two of them. Furthermore the keys must be dumped in a certain order. Here's how you do that:

use YAML qw(Dump Bless);
$hash = {apple => 'good', banana => 'bad', cauliflower => 'ugly'};
print Dump $hash;
Bless($hash)->keys(['banana', 'apple']);
print Dump $hash;

produces:

---
apple: good
banana: bad
cauliflower: ugly
---
banana: bad
apple: good

Bless returns the tied part of a yaml-node, so that you can call the YAML::Node methods. This is the same thing that YAML::Node::ynode() returns. So another way to do the above example is:

use YAML qw(Dump Bless);
use YAML::Node;
$hash = {apple => 'good', banana => 'bad', cauliflower => 'ugly'};
print Dump $hash;
Bless($hash);
$ynode = ynode(Blessed($hash));
$ynode->keys(['banana', 'apple']);
print Dump $hash;

Note that Blessing a Perl data structure does not change it anyway. The extra information is stored separately and looked up by the Blessed node's memory address.

Blessed(perl-node)
Returns the yaml node that a particular perl node is associated with (see above). Returns undef if the node is not (YAML) Blessed.

GLOBAL OPTIONS

YAML options are set using a group of global variables in the YAML namespace. This is similar to how Data::Dumper works.

For example, to change the indentation width, do something like:

local $YAML::Indent = 3;

The current options are:

DumperClass
You can override which module/class YAML uses for Dumping data.
LoadBlessed (since 1.25)
Default is undef (false)

The default was changed in version 1.30.

When set to true, YAML nodes with special tags will be automatocally blessed into objects:

- !perl/hash:Foo::Bar
    foo: 42

When loading untrusted YAML, you should disable this option by setting it to 0. This will also disable setting typeglobs when loading them.

You can create any kind of object with YAML. The creation itself is not the critical part. If the class has a "DESTROY" method, it will be called once the object is deleted. An example with File::Temp removing files can be found at https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=862373

LoaderClass
You can override which module/class YAML uses for Loading data.
Indent
This is the number of space characters to use for each indentation level when doing a Dump(). The default is 2.

By the way, YAML can use any number of characters for indentation at any level. So if you are editing YAML by hand feel free to do it anyway that looks pleasing to you; just be consistent for a given level.

SortKeys
Default is 1. (true)

Tells YAML.pm whether or not to sort hash keys when storing a document.

YAML::Node objects can have their own sort order, which is usually what you want. To override the YAML::Node order and sort the keys anyway, set SortKeys to 2.

Stringify
Default is 0. (false)

Objects with string overloading should honor the overloading and dump the stringification of themselves, rather than the actual object's guts.

Numify
Default is 0. (false)

Values that look like numbers (integers, floats) will be numified when loaded.

UseHeader
Default is 1. (true)

This tells YAML.pm whether to use a separator string for a Dump operation. This only applies to the first document in a stream. Subsequent documents must have a YAML header by definition.

UseVersion
Default is 0. (false)

Tells YAML.pm whether to include the YAML version on the separator/header.

--- %YAML:1.0
AnchorPrefix
Default is ''.

Anchor names are normally numeric. YAML.pm simply starts with '1' and increases by one for each new anchor. This option allows you to specify a string to be prepended to each anchor number.

UseCode
Setting the UseCode option is a shortcut to set both the DumpCode and LoadCode options at once. Setting UseCode to '1' tells YAML.pm to dump Perl code references as Perl (using B::Deparse) and to load them back into memory using eval(). The reason this has to be an option is that using eval() to parse untrusted code is, well, untrustworthy.
DumpCode
Determines if and how YAML.pm should serialize Perl code references. By default YAML.pm will dump code references as dummy placeholders (much like Data::Dumper). If DumpCode is set to '1' or 'deparse', code references will be dumped as actual Perl code.
LoadCode
LoadCode is the opposite of DumpCode. It tells YAML if and how to deserialize code references. When set to '1' or 'deparse' it will use eval(). Since this is potentially risky, only use this option if you know where your YAML has been.

LoadCode must be enabled also to use the feature of evaluating typeglobs (because with the typeglob feature you would be able to set the variable $YAML::LoadCode from a YAML file).

Preserve
When set to true, this option tells the Loader to load hashes into YAML::Node objects. These are tied hashes. This has the effect of remembering the key order, thus it will be preserved when the hash is dumped again. See YAML::Node for more information.
UseBlock
YAML.pm uses heuristics to guess which scalar style is best for a given node. Sometimes you'll want all multiline scalars to use the 'block' style. If so, set this option to 1.

NOTE: YAML's block style is akin to Perl's here-document.

UseFold (Not supported anymore since v0.60)
If you want to force YAML to use the 'folded' style for all multiline scalars, then set $UseFold to 1.

NOTE: YAML's folded style is akin to the way HTML folds text, except smarter.

UseAliases
YAML has an alias mechanism such that any given structure in memory gets serialized once. Any other references to that structure are serialized only as alias markers. This is how YAML can serialize duplicate and recursive structures.

Sometimes, when you KNOW that your data is nonrecursive in nature, you may want to serialize such that every node is expressed in full. (ie as a copy of the original). Setting $YAML::UseAliases to 0 will allow you to do this. This also may result in faster processing because the lookup overhead is by bypassed.

THIS OPTION CAN BE DANGEROUS. If your data is recursive, this option will cause Dump() to run in an endless loop, chewing up your computers memory. You have been warned.

CompressSeries
Default is 1.

Compresses the formatting of arrays of hashes:

-
  foo: bar
-
  bar: foo

becomes:

- foo: bar
- bar: foo

Since this output is usually more desirable, this option is turned on by default.

QuoteNumericStrings
Default is 0. (false)

Quote strings that look like numbers. Eg, '042', '0xff', '6.02e23'.
