NOMBRE

VALUES - calcular un conjunto de filas

SINOPSIS

VALUES ( expresión [, ...] ) [, ...]
    [ ORDER BY expresión_de_ordenación [ ASC | DESC | USING operador ] [, ...] ]
    [ LIMIT { contador | ALL } ]
    [ OFFSET inicio [ ROW | ROWS ] ]
    [ FETCH { FIRST | NEXT } [ contador ] { ROW | ROWS } ONLY ]

DESCRIPCIÓN

VALUES calcula uno o varios valores de fila especificados por expresiones de valor. Se utiliza comúnmente para generar una "tabla constante" dentro de un comando más grande, pero se puede usar por sí sola.

Cuando se especifican varias filas, todas las filas deben tener el mismo número de elementos. Los tipos de datos de las columnas de la tabla resultante se determinan combinando los tipos explícitos o inferidos de las expresiones que aparecen en esa columna, utilizando las mismas reglas que para UNION (ver Sección 10.5).

Dentro de comandos más grandes, VALUES está sintácticamente permitido donde SELECT está permitido. Debido a que la gramática lo trata como un SELECT, es posible usar las cláusulas ORDER BY, LIMIT (o equivalente FETCH FIRST) y OFFSET con un comando VALUES.

PARÁMETROS

expresión

Una constante o expresión para calcular e insertar en el lugar indicado en la tabla resultante (conjunto de filas). En una lista VALUES que aparece en el nivel superior de un INSERT, una expresión puede ser reemplazada por DEFAULT para indicar que se debe insertar el valor predeterminado de la columna de destino. DEFAULT no se puede usar cuando VALUES aparece en otros contextos.

expresión_de_ordenación

Una expresión o constante entera que indica cómo ordenar las filas resultantes. Esta expresión puede referirse a las columnas del resultado de VALUES como column1, column2, etc. Para más detalles, ver Cláusula ORDER BY en la documentación de SELECT(7).

operador

Un operador de ordenación. Para más detalles, ver Cláusula ORDER BY en la documentación de SELECT(7).

contador

El número máximo de filas a devolver. Para más detalles, ver Cláusula LIMIT en la documentación de SELECT(7).

inicio

El número de filas a omitir antes de empezar a devolver filas. Para más detalles, ver Cláusula LIMIT en la documentación de SELECT(7).

NOTAS

Se deben evitar las listas VALUES con un número muy grande de filas, ya que podría experimentar errores de falta de memoria o un rendimiento deficiente. VALUES que aparece dentro de INSERT es un caso especial (ya que los tipos de datos deseados de las columnas se conocen de la tabla de destino de INSERT y no necesitan ser inferidos escaneando la lista VALUES), por lo que puede manejar listas más grandes de lo que es práctico en otros contextos.

EJEMPLOS

Un comando VALUES simple:

VALUES (1, 'one'), (2, 'two'), (3, 'three');

Esto devolverá una tabla de dos columnas y tres filas. Es efectivamente equivalente a:

SELECT 1 AS column1, 'one' AS column2
UNION ALL
SELECT 2, 'two'
UNION ALL
SELECT 3, 'three';

Más comúnmente, VALUES se utiliza dentro de un comando SQL más grande. El uso más común es en INSERT:

INSERT INTO films (code, title, did, date_prod, kind)
    VALUES ('T_601', 'Yojimbo', 106, '1961-06-16', 'Drama');

En el contexto de INSERT, las entradas de una lista VALUES pueden ser DEFAULT para indicar que se debe usar el valor predeterminado de la columna aquí en lugar de especificar un valor:

INSERT INTO films VALUES
    ('UA502', 'Bananas', 105, DEFAULT, 'Comedy', '82 minutes'),
    ('T_601', 'Yojimbo', 106, DEFAULT, 'Drama', DEFAULT);

VALUES también se puede usar donde se podría escribir una sub-SELECT, por ejemplo en una cláusula FROM:

SELECT f.*
  FROM films f, (VALUES('MGM', 'Horror'), ('UA', 'Sci-Fi')) AS t (studio, kind)
  WHERE f.studio = t.studio AND f.kind = t.kind;
UPDATE employees SET salary = salary * v.increase
  FROM (VALUES(1, 200000, 1.2), (2, 400000, 1.4)) AS v (depno, target, increase)
  WHERE employees.depno = v.depno AND employees.sales >= v.target;

Tenga en cuenta que se requiere una cláusula AS cuando se utiliza VALUES en una cláusula FROM, al igual que ocurre con SELECT. No es necesario que la cláusula AS especifique nombres para todas las columnas, pero es una buena práctica hacerlo. (Los nombres de columna predeterminados para VALUES son column1, column2, etc. en PostgreSQL, pero estos nombres pueden ser diferentes en otros sistemas de bases de datos).

Cuando se utiliza VALUES en INSERT, todos los valores se convierten automáticamente al tipo de datos de la columna de destino correspondiente. Cuando se utiliza en otros contextos, puede ser necesario especificar el tipo de datos correcto. Si todas las entradas son literales entre comillas, la conversión del primero es suficiente para determinar el tipo asumido para todos:

SELECT * FROM machines
WHERE ip_address IN (VALUES('192.168.0.1'::inet), ('192.168.0.10'), ('192.168.1.43'));

Consejo

Para pruebas IN simples, es mejor confiar en la forma de lista de escalares de IN que escribir una consulta VALUES como se muestra arriba. El método de lista de escalares requiere menos escritura y a menudo es más eficiente.

COMPATIBILIDAD

VALUES cumple con el estándar SQL. LIMIT y OFFSET son extensiones de PostgreSQL; ver también bajo SELECT(7).
