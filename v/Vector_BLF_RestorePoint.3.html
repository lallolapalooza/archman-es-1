Descripción Detallada

Punto de Restauración

Los Puntos de Restauración se mantienen en una lista que es básicamente un índice que hace referencia a cada objeto 1001. Así que omitiendo el objeto 0, cuenta 1000, 2001, 3002, ...

Nota

Esta clase se basa en observaciones, ya que no hay documentación pública disponible. Hay funciones de API no documentadas para el manejo de RestorePoint. Y esto parece ser una de ellas.

uint64_t Vector::BLF::RestorePoint::compressedFilePosition {}

posición del archivo comprimido

Esto designa la posición de un LogContainer en el archivo comprimido.

uint64_t Vector::BLF::RestorePoint::timeStamp {}

marca de tiempo (en ns)

Las siguientes posiciones y desplazamientos del archivo se refieren a un Objeto. La marca de tiempo pertenece a este objeto.

uint32_t Vector::BLF::RestorePoint::uncompressedFileOffset {}

desplazamiento del archivo sin comprimir

Esto designa el desplazamiento dentro del contenido sin comprimir del LogContainer, donde comienza un Objeto. Este Objeto no es necesariamente el primer o último Objeto, sino uno arbitrario.

uint32_t Vector::BLF::RestorePoint::unknownRestorePoint {}

Pendiente

No está claro qué es esta variable.

Quizás solo un campo reservado para futuras extensiones.

Los ejemplos muestran:

  • Archivo1: 0, 0x9a
  • Archivo2: 0, 1, 2, 3, 4, 5, 6
  • Archivo3: 0, 0xffffffff, 0x10020
  • Archivo4: 0xb9
  • Archivo5: 0, 0x2c9a8a00

Estos son datos similares a los de LogContainer.unknownLogContainer.
