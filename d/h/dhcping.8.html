Licencias: BSD

dhcping(8) Manual de Comandos Generales dhcping(8)

NOMBRE

dhcping - envía una solicitud DHCP al servidor DHCP para ver si está en funcionamiento

SINOPSIS

dhcping [-v] [-q] [-i] [-r] -t tiempo-máximo-espera -c dirección-IP-cliente -s dirección-IP-servidor -h dirección-hardware-cliente [-g dirección-IP-puerta-de-enlace]

DESCRIPCIÓN

Este comando permite al administrador del sistema comprobar si un servidor DHCP remoto sigue funcionando.

Las opciones son:

-v
Detallado, imprime algo de información.
-i
Utiliza paquetes DHCPINFORM.
-r
Utiliza paquetes DHCPREQUEST (comportamiento predeterminado).
-q
Silencioso, no imprime nada en la pantalla.
-t tiempo-máximo-espera
Tiempo máximo de espera por una respuesta del servidor en segundos. El valor predeterminado es 3 segundos.
-c dirección-IP-cliente
Solicita esta dirección IP. Ten en cuenta que esta es también la dirección IP a la que se enviará la respuesta.
-s dirección-IP-servidor
Envía el paquete DHCP a esta dirección IP.
-h dirección-hardware-cliente
Utiliza esta dirección de hardware en la solicitud DHCP. Puede tener hasta dieciséis octetos separados por dos puntos (es decir, 01:02:03:04)
-g dirección-IP-puerta-de-enlace
Utiliza esta dirección IP para la dirección IP de la puerta de enlace en el paquete DHCP. Esta opción está rota actualmente.

VALORES DE RETORNO

Si todo va bien, devuelve 0. Si algo salió mal, devuelve 1.

CONFIGURACIÓN

Este programa debe instalarse con permisos setuid root o ejecutarse solo por root. Consulta SEGURIDAD para obtener más información.

En tu servidor DHCP, añade estas líneas a dhcpd.conf:

host <nombre-dominio-completo-de-tu-host-de-monitorización> {
   hardware ethernet <dirección-mac-de-tu-host-de-monitorización>;
   fixed-address     <dirección-IP-de-tu-host-de-monitorización>;
}
Luego, inténtalo:

$ dhcping -c dirección-IP-de-tu-host-de-monitorización \
-s dirección-IP-de-tu-servidor-DHCP \
-h dirección-mac-de-tu-host-de-monitorización

Responderá con "no answer" o "Got answer from: dirección-IP-de-tu-servidor-DHCP"

El archivo de registro del servidor DHCP mostrará:
DHCPREQUEST for 192.168.1.1 from 00:20:18:56:29:8f via ed0
DHCPACK on 192.168.1.1 to 00:20:18:56:29:8f via ed0
DHCPRELEASE of 192.168.1.1 from 00:20:18:56:29:8f via ed0 (found)

Ejecutando en modo DHCPINFORM con -i:

Si ves "DHCPINFORM from 192.168.1.1 via xl0: not authoritative for subnet 192.168.1.0", deberías añadir la declaración authoritative a la subred. Consulta dhcpd.conf(5) para más detalles.

Al ejecutarse en modo muy detallado, dhcping intenta volcar todos los datos de los paquetes DHCP enviados y recibidos. Primero volcará el paquete en formato hexadecimal, luego decodificará la cabecera y finalmente las opciones.

CÓMO FUNCIONA

El cliente envía un paquete DHCPREQUEST o DHCPINFORM al servidor y espera una respuesta. Luego, si se envió un DHCPREQUEST, enviará un DHCPRELEASE de vuelta al servidor.

SEGURIDAD

Este programa se instala con permisos setuid root ya que requiere los privilegios para vincularse al puerto 68 (bootpc). Los privilegios de root se descartan tan pronto como el programa se haya vinculado a ese puerto.

ERRORES

Actualmente (esto puede, o no, cambiar en el futuro) el demonio DHCP de ISC no escribe concesiones con una IP fija en el archivo dhcpd.leases.

Los paquetes DHCPINFORM solo se pueden usar en subredes para las que el servidor es autoritativo. Si el script de monitorización se ejecuta en una subred para la que el servidor no es autoritativo, debería utilizar los paquetes DHCPREQUEST. También he experimentado algunos problemas con los servidores ISC DHCPD v2, pero eso también está en el README.

La opción -V sigue funcionando, pero no debería usarse para depurar los paquetes. Es mejor usar dhcpdump(8) para eso, que está disponible en mi sitio web. Quería eliminarla, pero decidí hacerlo solo en la documentación, no en el código. Quizás la necesite algún día para depuración.
