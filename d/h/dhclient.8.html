Lorsqu'un nouveau bail est acquis, il est ajouté à la fin du fichier dhclient.leases. Afin d'empêcher le fichier de

Lorsque toutes les tentatives de contacter un serveur DHCP ont échoué, dhclient essaiera de valider le bail statique, et s'il réussit, utilisera ce bail jusqu'à ce qu'il soit redémarré. OPCIONES

-r
Detiene el cliente DHCP en ejecución sin liberar la concesión actual. Elimina el proceso dhclient existente según lo registrado previamente en el archivo PID. Cuando se apaga mediante este método, se ejecutará dhclient-script con el motivo específico para la llamada al script establecido.
-p número-de-puerto
El número de puerto UDP en el que el cliente DHCP debe escuchar y transmitir. Si no se especifica, dhclient utiliza el puerto predeterminado 68. Esto es principalmente útil para fines de depuración. Si se especifica un puerto diferente en el que el cliente debe escuchar y transmitir, el cliente también utilizará un puerto de destino diferente, uno menos que el puerto especificado.
-s dirección-del-servidor
Especifica la dirección IP del servidor o el nombre de dominio completo que se utilizará como destino para los mensajes del protocolo DHCP antes de que dhclient haya adquirido una dirección IP. Normalmente, dhclient transmite estos mensajes a 255.255.255.255 (la dirección IP de difusión limitada). Anular esto es principalmente útil para fines de depuración. Esta función no se admite en el modo DHCPv6 (-6).
-g relevo
Establece el campo giaddr de todos los paquetes a la dirección IP del relevo, simulando un agente de relevo. Esto es solo para fines de prueba y no se debe esperar que funcione de manera consistente o útil.
-i
Utiliza un DUID con clientes DHCPv4. Si no hay un DUID disponible en el archivo de concesión, se construirá y guardará uno. El DUID se utilizará para construir un ID de cliente estilo RFC4361 que se incluirá en los mensajes del cliente. Este ID de cliente puede ser anulado estableciendo un ID de cliente en el archivo de configuración. Se desaconseja anular el ID de cliente de esta manera.
-I
Utiliza el esquema DDNS estándar de las RFC 4701 y 4702.
--decline-wait-time segundos
Especifica el tiempo (en segundos) que un cliente IPv4 debe esperar después de rechazar una dirección antes de emitir una solicitud de descubrimiento. El valor predeterminado es 10 segundos, como lo recomienda la RFC 2131, Sección 3.1.5. Un valor de cero equivale a ninguna espera.

--version Imprime el número de versión y sale.

Opciones disponibles para el modo DHCPv6:

-S
Utiliza una solicitud de información para obtener solo parámetros de configuración sin estado (es decir, sin dirección). Esto implica -6. Tampoco reescribe la base de datos de concesiones.
-T
Solicita direcciones temporales IPv6, un conjunto por cada indicador -T. Esto implica -6 y también deshabilita la consulta de direcciones normal. Consulte -N para restaurarla.
-P
Habilita la delegación de prefijos IPv6. Esto implica -6 y también deshabilita la consulta de direcciones normal. Consulte -N para restaurarla. Se pueden solicitar varios prefijos con varios indicadores -P. Tenga en cuenta que solo se permite una interfaz solicitada.
-R
Requiere que las respuestas incluyan todos los elementos solicitados por cualquiera de las opciones -N, -T o -P. Normalmente, incluso si la línea de comandos incluye varios de estos, el cliente estará dispuesto a aceptar la mejor concesión que pueda recibir, incluso si la concesión no incluye todos los elementos solicitados. Esta opción hace que el cliente solo acepte concesiones que incluyan todos los elementos solicitados.

¡Atención! habilitar esto puede impedir que el cliente utilice cualquier concesión que reciba si los servidores no están configurados para suministrar todos los elementos.

-D LL o LLT
Anula el valor predeterminado al seleccionar el tipo de DUID a utilizar. Por predeterminado, el cliente DHCPv6 dhclient crea un identificador basado en la dirección de capa de enlace (DUID-LL) si se está ejecutando en modo sin estado (con -S, sin solicitar una dirección), o crea un identificador basado en la dirección de capa de enlace más una marca de tiempo (DUID-LLT) si se está ejecutando en modo con estado (sin -S, solicitando una dirección). Cuando DHCPv4 está configurado para usar un DUID mediante la opción -i, el valor predeterminado es usar un DUID-LLT. -D anula estos valores predeterminados, con un valor de LL o LLT.
-N
Restaura la consulta de direcciones normal para IPv6. Esto implica -6. Se utiliza para restaurar el funcionamiento normal después de usar -T o -P. Se pueden solicitar varias direcciones con varios indicadores -N.
--address-prefix-len longitud
Especifica la longitud del prefijo para las direcciones IPv6. Este valor es pasado por dhclient al script del cliente a través de la variable de entorno, ip6_prefixlen, al enlazar direcciones IPv6. El valor predeterminado es 128. Alternativamente, puede cambiar el valor predeterminado en el momento de la compilación estableciendo DHCLIENT_DEFAULT_PREFIX_LEN en includes/site.h.
--dad-wait-time segundos
Especifica el tiempo máximo (en segundos) que el cliente debe esperar a que se complete la detección de direcciones duplicadas (DAD) en una interfaz. Este valor se propaga al script de dhclient en una variable de entorno dad_wait_time. Si alguna de las direcciones IPv6 de la interfaz está tentativa (DAD en curso), el script esperará el número especificado de segundos a que se complete DAD. Si el script ignora esta variable, el parámetro no tendrá ningún efecto.
--prefix-len-hint longitud
Cuando se utiliza junto con -P, indica al cliente que utilice la longitud dada para una pista de prefijo de "::/longitud", al solicitar nuevos prefijos.

Modificación de ubicaciones de archivos predeterminados: Las siguientes opciones se pueden usar para modificar las ubicaciones que el cliente utiliza para sus archivos. Pueden ser particularmente útiles si, por ejemplo, DBDIR o RUNDIR no se han montado cuando se inicia el cliente DHCP.

-cf archivo-de-configuración
Ruta al archivo de configuración del cliente. Si no se especifica, se usa el valor predeterminado ETCDIR/dhclient.conf. Consulte dhclient.conf(5) para una descripción de este archivo.
-df archivo-de-concesión-duid
Ruta a un archivo de concesión secundario. Si el archivo de concesión principal no contiene un DUID, se buscará en este archivo. El DUID leído del secundario se escribirá en el principal. Esta opción se puede usar para permitir que una instancia IPv4 del cliente comparta un DUID con una instancia IPv6. Después de iniciar una de las instancias, la segunda se puede iniciar con esta opción apuntando al archivo de concesión de la primera instancia. No hay un valor predeterminado. Si no se especifica ningún archivo, no se buscará un DUID en caso de que no se encuentre en el archivo de concesión principal.
-lf archivo-de-concesión
Ruta al archivo de base de datos de concesiones. Si no se especifica, se usa el valor predeterminado DBDIR/dhclient.leases. Consulte dhclient.leases(5) para una descripción de este archivo.
-pf archivo-pid
Ruta al archivo del ID del proceso. Si no se especifica, se usa el valor predeterminado RUNDIR/dhclient.pid.
--no-pid
Opción para deshabilitar la escritura de archivos PID. Por defecto, el programa escribirá un archivo PID. Si el programa se invoca con esta opción, no intentará eliminar ningún proceso cliente existente, incluso si se invoca con -r o -x.
-sf archivo-de-script
Ruta al script de configuración de red invocado por dhclient cuando obtiene una concesión. Si no se especifica, se usa el valor predeterminado CLIENTBINDIR/dhclient-script. Consulte dhclient-script(8) para una descripción de este archivo.

PUERTOS

Durante las operaciones, el cliente puede utilizar varios puertos UDP para proporcionar diferentes funciones. Qué puertos se abren depende tanto de la forma en que se compiló su código como de la configuración que usted suministra. Lo siguiente debería darle una idea de qué puertos pueden estar en uso.

Normalmente, un cliente DHCPv4 abrirá un socket UDP crudo para recibir y enviar la mayoría de los paquetes DHCPv4. También abre un socket UDP de respaldo para enviar paquetes unicast. Normalmente, ambos utilizarán el número de puerto conocido para BOOTPC.

Para DHCPv6, el cliente abre un socket UDP en el puerto de cliente conocido y un socket UDP de respaldo en un puerto aleatorio para enviar mensajes unicast. A diferencia de DHCPv4, el socket conocido no necesita ser abierto en modo crudo.

Si ha incluido una declaración de puerto omapi en su archivo de configuración, el cliente abrirá un socket TCP en ese puerto para escuchar conexiones OMAPI. Cuando algo se conecte, se utilizará otro puerto para la conexión establecida.

Cuando DDNS está habilitado en tiempo de compilación (ver includes/site.h), el cliente abrirá un socket UDP v4 y uno v6 en puertos aleatorios. Estos puertos no se abrirán a menos que o hasta que el cliente intente realizar una actualización por primera vez. Si el cliente no está configurado para realizar actualizaciones, los puertos nunca se abrirán.

CONFIGURACIÓN

La sintaxis del archivo dhclient.conf(5) se discute por separado.

OMAPI

El cliente DHCP proporciona cierta capacidad para controlarlo mientras se ejecuta, sin detenerlo. Esta capacidad se proporciona utilizando OMAPI, una API para manipular objetos remotos. Los clientes OMAPI se conectan al cliente usando TCP/IP, se autentican y luego pueden examinar el estado actual del cliente y hacerle cambios.

En lugar de implementar el protocolo OMAPI subyacente directamente, los programas de usuario deben usar la API dhcpctl o OMAPI en sí. Dhcpctl es un envoltorio que maneja algunas de las tareas de mantenimiento que OMAPI no hace automáticamente. Dhcpctl y OMAPI se documentan en dhcpctl(3) y omapi(3). La mayoría de las cosas que querría hacer con el cliente se pueden hacer directamente usando el comando omshell(1), en lugar de tener que escribir un programa especial.

EL OBJETO DE CONTROL

CONTROL_OBJECT'>EL OBJETO DE CONTROL

El objeto de control le permite apagar el cliente, liberando todos los arrendamientos que posee y eliminando cualquier registro DNS que pueda haber añadido. También le permite pausar el cliente: esto desconfigura todas las interfaces que el cliente está utilizando. Luego puede reiniciarlo, lo que hace que vuelva a configurar esas interfaces. Normalmente, pausaría el cliente antes de entrar en hibernación o en modo de suspensión en un ordenador portátil. Luego lo reanudaría después de que se restablezca la alimentación. Esto permite que las tarjetas PC se apaguen mientras el ordenador está en hibernación o en suspensión, y luego se reinicialicen a su estado anterior una vez que el ordenador sale de la hibernación o de la

suspensión.

El objeto de control tiene un atributo: el atributo state. Para apagar el cliente, esta

blezca su atributo state en 2. Realizará automáticamente un DHCPRELEASE. Para pausarlo,
establezca su atributo state en 3. Para reanudarlo, establezca su atributo state en 4.
