NOMBRE

dhclient-script - script de configuración de red del cliente DHCP

DESCRIPCIÓN

El script de configuración de red del cliente DHCP es invocado de vez en cuando por dhclient(8). Este script es utilizado por el cliente dhcp para establecer la configuración inicial de cada interfaz antes de solicitar una dirección, para probar la dirección una vez que ha sido ofrecida, y para establecer la configuración final de la interfaz una vez que se ha adquirido una concesión. Si no se adquiere ninguna concesión, el script se utiliza para probar las concesiones predefinidas, si las hay, y también se llama una vez si no se puede identificar ninguna concesión válida.

Este script no está destinado a ser personalizado por el usuario final. Si se necesitan personalizaciones locales, deberían ser posibles utilizando los ganchos (hooks) de entrada y salida proporcionados (consulte GANCHOS para más detalles). Estos ganchos permitirán al usuario anular el comportamiento predeterminado del cliente al crear un /etc/resolv.conf archivo.

No existe un script de cliente estándar para algunos sistemas operativos, aunque el cliente real pueda funcionar, por lo que un usuario pionero podría necesitar crear un nuevo script o modificar uno existente. En general, las personalizaciones específicas para un ordenador particular deben realizarse en el archivo ETCDIR/dhclient.conf . Si encuentra que no puede hacer una personalización sin personalizar ETCDIR/dhclient.conf o utilizando los ganchos de entrada y salida, por favor envíe un informe de error.

GANCHOS

Cuando se inicia, el script del cliente define primero una función de shell, make_resolv_conf , que se utiliza más adelante para crear el archivo /etc/resolv.conf . Para anular el comportamiento predeterminado, redefina esta función en el script gancho de entrada (enter hook).

Después de definir la función make_resolv_conf, el script del cliente comprueba la presencia de un script ejecutable ETCDIR/dhclient-enter-hooks y, si está presente, invoca el script en línea, utilizando el comando ´.´ de Bourne shell. Todo el entorno documentado bajo OPERACIÓN está disponible para este script, que puede modificar el entorno si es necesario para cambiar el comportamiento del script. Si ocurre un error durante la ejecución del script, puede establecer la variable exit_status a un valor distinto de cero, y CLIENTBINDIR/dhclient-script saldrá con ese código de error inmediatamente después de que el script del cliente salga.

Después de que todo el procesamiento se haya completado, CLIENTBINDIR/dhclient-script comprueba la presencia de un script ejecutable ETCDIR/dhclient-exit-hooks que, si está presente, se invoca utilizando el comando ´.´. El estado de salida de dhclient-script se pasará a dhclient-exit-hooks en la variable de shell exit_status, y siempre será cero si el script tuvo éxito en la tarea para la que fue invocado. El resto del entorno, como se describió anteriormente para dhclient-enter-hooks, también está presente. El script ETCDIR/dhclient-exit-hooks puede modificar el valor de exit_status para cambiar el estado de salida de dhclient-script.

OPERACIÓN

Cuando dhclient necesita invocar el script de configuración del cliente, define un conjunto de variables en el entorno y luego invoca CLIENTBINDIR/dhclient-script. En todos los casos, $reason se establece al nombre de la razón por la que se ha invocado el script. Las siguientes razones están actualmente definidas: MEDIUM, PREINIT, BOUND, RENEW, REBIND, REBOOT, EXPIRE, FAIL, STOP, RELEASE, NBI y TIMEOUT.

MEDIUM

El cliente DHCP está solicitando que se establezca el tipo de medio de una interfaz. El nombre de la interfaz se pasa en $interface, y el tipo de medio se pasa en $medium.

PREINIT

El cliente DHCP está solicitando que una interfaz se configure como sea necesario para enviar paquetes antes de recibir una dirección real. Para los clientes que utilizan la biblioteca de sockets BSD, esto significa configurar la interfaz con una dirección IP de 0.0.0.0 y una dirección de difusión de 255.255.255.255. Para otros clientes, podría ser posible simplemente configurar la interfaz sin darle realmente ninguna dirección IP. El nombre de la interfaz se pasa en $interface, y el tipo de medio en $medium.

Si se ha declarado un alias IP en dhclient.conf, su dirección se pasará en $alias_ip_address, y ese alias IP debe ser eliminado de la interfaz, junto con cualquier ruta hacia él.

BOUND

El cliente DHCP ha realizado un enlace inicial a una nueva dirección. La nueva dirección IP se pasa en $new_ip_address, y el nombre de la interfaz se pasa en $interface. El tipo de medio se pasa en $medium. Cualquier opción adquirida del servidor se pasa utilizando el nombre de opción descrito en dhcp-options, excepto que los guiones (´-´) se reemplazan por guiones bajos (´_´) para hacer variables de shell válidas, y los nombres de las variables comienzan con new_. Así, por ejemplo, la nueva máscara de subred se pasaría en $new_subnet_mask. Las opciones de un universo no predeterminado tendrán el nombre del universo antepuesto al nombre de la opción, por ejemplo $new_dhcp6_server_id. Las opciones que el cliente solicitó explícitamente a través de una opción PRL u ORO se pasan con el mismo nombre de opción que arriba pero antepuesto con requested_ y con un valor de 1, por ejemplo requested_subnet_mask=1. No se define ninguna variable de este tipo para las opciones no solicitadas por el cliente u opciones que no requieren una opción de solicitud, como la dirección IP (*_ip_address) o el tiempo de expiración (*_expiry).

Antes de configurar realmente la dirección, dhclient-script debería hacer ARP de alguna manera por ella y salir con un estado distinto de cero si recibe una respuesta. En este caso, el cliente enviará un mensaje DHCPDECLINE al servidor y adquirirá una dirección diferente. Esto también puede hacerse en los estados RENEW, REBIND o REBOOT, pero no es requerido, y de hecho puede no ser deseable.

Cuando se ha completado un enlace, es probable que se necesiten configurar muchos parámetros de red. Se necesita crear un nuevo /etc/resolv.conf, utilizando los valores de $new_domain_name y $new_domain_name_servers (que pueden listar más de un servidor, separados por espacios). Se debería establecer una ruta por defecto utilizando $new_routers, y pueden necesitar establecerse rutas estáticas utilizando $new_static_routes.

Si se ha declarado un alias IP, debe establecerse aquí. La dirección IP del alias se escribirá como $alias_ip_address, y otras opciones DHCP que se establezcan para el alias (por ejemplo, máscara de subred) se pasarán en variables nombradas como se describió anteriormente pero comenzando con $alias_ en lugar de $new_. Se debe tener cuidado de no usar la dirección IP del alias si es idéntica a la dirección IP enlazada ($new_ip_address), ya que los otros parámetros del alias pueden ser incorrectos en este caso.

RENEW

Cuando se ha renovado un enlace, el script se llama como en BOUND, excepto que además de todas las variables que comienzan con $new_ y $requested_ hay otro conjunto de variables que comienzan con $old_. Los ajustes persistentes que puedan haber cambiado deben eliminarse - por ejemplo, si se está configurando una ruta local hacia la dirección enlazada, la ruta local antigua debe eliminarse. Si la ruta por defecto ha cambiado, la ruta por defecto antigua debe eliminarse. Si las rutas estáticas han cambiado, las antiguas deben eliminarse. De lo contrario, el procesamiento puede hacerse como con BOUND.

REBIND

El cliente DHCP se ha vuelto a enlazar a un nuevo servidor DHCP. Esto puede manejarse como con RENEW, excepto que si la dirección IP ha cambiado, la tabla ARP debe ser limpiada.

REBOOT

El cliente DHCP ha vuelto a adquirir con éxito su dirección antigua después de un reinicio. Esto puede procesarse como con BOUND.

EXPIRE

El cliente DHCP ha fallado al renovar su concesión o adquirir una nueva, y la concesión ha expirado. La dirección IP debe ser relinquida, y todos los parámetros relacionados deben ser eliminados, como en RENEW y REBIND.

FAIL

El cliente DHCP no ha podido contactar con ningún servidor DHCP, y cualquier concesión que haya sido probada no ha resultado ser válida. Los parámetros de la última concesión probada deben ser desconfigurados. Esto puede manejarse de la misma manera que EXPIRE.

STOP

Se ha informado a dhclient que se apague de forma ordenada, el dhclient-script debería desconfigurar o apagar la interfaz según corresponda.

RELEASE

El dhclient se ha ejecutado con la bandera -r, indicando que el administrador desea que libere su(s) concesión(es). dhclient-script debería desconfigurar o apagar la interfaz.

NBI

No-Broadcast-Interfaces...dhclient no pudo encontrar ninguna interfaz sobre la que creyera que debía iniciar DHCP. Lo que dhclient-script debería hacer en esta situación depende completamente del implementador.

TIMEOUT

El cliente DHCP no ha podido contactar con ningún servidor DHCP. Sin embargo, se ha identificado una concesión antigua y sus parámetros se han pasado como con BOUND. El script de configuración del cliente debería probar estos parámetros y, si tiene motivos para creer que son válidos, debería salir con un valor de cero. Si no, debería salir con un valor distinto de cero.

V6ONLY

El cliente DHCPv4 ha recibido una opción solicitada v6-only-preferred válida. El sistema debería deshabilitar IPv4 en la interfaz. Por su parte, dhclient espera V6ONLY_WAIT segundos (el temporizador es transportado por la opción con un mínimo de MIN_V6ONLY_WAIT) antes de regresar al estado INIT.

La forma habitual de probar una concesión es configurar la red como con REBIND (ya que esto puede ser llamado para probar más de una concesión) y luego hacer ping al primer router definido en $routers. Si se recibe una respuesta, la concesión debe ser válida para la red a la que la interfaz está actualmente conectada. Sería más completo intentar hacer ping a todos los routers listados en $new_routers, así como a los listados en $new_static_routes, pero los scripts actuales no lo hacen.

FILES

Cada sistema operativo debería tener generalmente su propio archivo de script, aunque los archivos de script para sistemas operativos similares pueden ser similares o incluso idénticos. Los archivos de script incluidos en la distribución DHCP de Internet Systems Consortium aparecen en el árbol de distribución bajo client/scripts y llevan los nombres de los sistemas operativos en los que se pretende que funcionen.

BUGS

Si se está utilizando más de una interfaz, no hay forma obvia de evitar conflictos entre los parámetros de configuración suministrados por el servidor; por ejemplo, el script estándar de dhclient reescribe /etc/resolv.conf. Si se está configurando más de una interfaz, /etc/resolv.conf se inicializará repetidamente con los valores proporcionados por un servidor y luego por el otro. Suponiendo que la información proporcionada por ambos servidores sea válida, esto no debería causar problemas reales, pero podría ser confuso.
