Aunque dhcpcd puede hacer todo desde la línea de comandos, hay casos en los que es más fácil hacerlo una vez en un archivo de configuración. La mayoría de las opciones que se encuentran en dhcpcd(8) pueden usarse aquí. La primera palabra de la línea es la opción y el resto de la línea es el valor. Los espacios en blanco al principio y al final de la opción y el valor se eliminan. Puede escapar caracteres en el valor usando el carácter \. Los comentarios pueden ir precedidos por el carácter #. Los valores de cadena deben ir entrecomillados con el carácter

".

Solicita la opción del servidor. Puede ser una variable para ser utilizada en dhcpcd-run-hooks(8) o el valor numérico. Puede especificar más opcións separadas por comas, espacios o más líneas de option. Anteponer dhcp6_ a opción para solicitar una opción DHCPv6. Si no hay opciones DHCPv6 configuradas, las opciones DHCPv4 se mapean a opciones DHCPv6 equivalentes.

Anteponer nd_ a opción para manejar opciones ND, pero esto solo funciona para las opciones nooption, reject y require.

Para ver una lista de opciones que puede usar, llame a dhcpcd con el argumento -V, --variables.

nooption opción
Elimina la opción del mensaje antes de que sea procesada.
require opción
Requiere que la opción esté presente en todos los mensajes, de lo contrario el mensaje se ignora. Para forzar que dhcpcd solo responda a servidores DHCP y no a servidores BOOTP, puede require dhcp_message_type. Sin embargo, esto no es una ciencia exacta, ya que un servidor BOOTP puede enviar opciones similares a DHCP.
reject opción
Rechaza un mensaje que contenga la opción. Esto es útil cuando no puede usar require para seleccionar / deseleccionar mensajes BOOTP.
destination opción
Si dhcpcd.conf detecta una dirección agregada a una interfaz punto a punto (PPP, TUN, etc.), entonces establecerá las opciones DHCP especificadas a la dirección de destino de la interfaz.
profile nombre
Las opciones subsiguientes solo se analizan para este perfil nombre.
quiet
Suprime cualquier salida de dhcpcd en la consola, excepto los errores.
reboot segundos
Permite reboot segundos antes de pasar a la fase DISCOVER si tenemos un arrendamiento antiguo para usar. Permite reboot segundos antes de iniciar estados de respaldo desde la fase DISCOVER. IPv4LL se inicia cuando se alcanza el primer tiempo de espera de reboot. El valor predeterminado es 5 segundos. Un ajuste de 0 segundos hace que dhcpcd.conf omita la fase de reinicio y vaya directamente a DISCOVER. Esto es deseable para usuarios móviles porque si cambia de la red A a la red B y utilizan la misma subred y la dirección de la red A no está en uso en la red B, entonces el servidor DHCP permanecerá en silencio incluso si es autoritativo, lo que significa que dhcpcd se agotará antes de volver a la fase DISCOVER. Esto no tiene efecto en DHCPv6, aparte de omitir la fase de reinicio.
release
dhcpcd liberará el arrendamiento antes de detener la interfaz.
script script
Utiliza script en lugar del valor predeterminado /usr/lib/dhcpcd/dhcpcd-run-hooks.
request_time segundos
Solicita el arrendamiento durante segundos antes de volver a DISCOVER. El valor predeterminado es 180 segundos.

DEFINITION SYNTAX

DHCP options are defined using the define keyword followed by the option number and optionally a keyword representing the option name.

define number [name]

The option definition itself is then made of a series of statements, one per line, in the following order:

request variable
Requests the option by default without having to be specified in user configuration.
norequest variable
This option cannot be requested, regardless of user configuration.
optional variable
This option is optional. Only makes sense for embedded options like the client FQDN option, where the FQDN string itself is optional.
index variable
The option can appear more than once and will be indexed.
array variable
The option data is split into a space separated array, each element being the same type.
truncated variable
The option might truncated from its normal length. The end of the normal size is zero padded on expansion. Currently this is only supported for ip6address where it's a prefix.
embed type variable
Defines an embedded variable within the defined option. The length is determined by the type. If the variable is not the same as defined in the parent option, it is prefixed with the parent variable first with an underscore. If the variable has the name of reserved then it is not processed.
encap code type variable
Defines an encapsulated variable within the defined option. The length is determined by the type. If the variable is not the same as defined in the parent option, it is prefixed with the parent variable first with an underscore.

Type prefix

These keywords come before the type itself, to describe it more fully. You can use more than one, but they must appear in the order listed below.

request
Requests the option by default without having to be specified in user configuration.
norequest
This option cannot be requested, regardless of user configuration.
optional
This option is optional. Only makes sense for embedded options like the client FQDN option, where the FQDN string itself is optional.
index
The option can appear more than once and will be indexed.
array
The option data is split into a space separated array, each element being the same type.
truncated
The option might truncated from its normal length. The end of the normal size is zero padded on expansion. Currently this is only supported for ip6address where it's a prefix.

Types to define

The type directly affects the length of data consumed inside the option. Any remaining data is normally discarded. Lengths can be specified for string and binhex types, but this is generally with other data embedded afterwards in the same option.

ipaddress
An IPv4 address, 4 bytes.
ip6address
An IPv6 address, 16 bytes.
string [: length]
A NVT ASCII string of printable characters.
byte
A byte.
bitflags: flags
A byte represented as a string of flags, most significant bit first. For example, using ABCDEFGH then A would equal 10000000, B 01000000, C 00100000, etc. If the bit is not set, the flag is not printed. A flag of 0 is not printed even if the bit position is set. This is to allow reservation of the first bits while assigning the last bits. A flag of 1 prints the bit set or unset.
int16
A signed 16bit integer, 2 bytes.
uint16
An unsigned 16bit integer, 2 bytes.
int32
A signed 32bit integer, 4 bytes.
uint32
An unsigned 32bit integer, 4 bytes.
flag
A fixed value (1) to indicate that the option is present, 0 bytes.
domain
An RFC 3397 encoded string.
dname
An RFC 1035 validated string.
uri
If an array then the first two bytes are the URI length inside the option data. Otherwise, the whole option data is the URI. As a space is not allowed in the URI encoding, the URIs are space separated.
binhex [: length]
Binary data expressed as hexadecimal.
embed
Contains embedded options (implies encap as well).
encap
Contains encapsulated options (implies embed as well).
option
References an option from the global definition.

Example definition

# DHCP option 81, Fully Qualified Domain Name, RFC 4702
define 81 embed fqdn
embed byte flags
embed byte rcode1
embed byte rcode2
embed domain fqdn
# DHCP option 125, Vendor Specific Information Option, RFC 3925
define 125 encap vsio
embed uint32 enterprise_number
# Options defined for the enterprise number
encap 1 ipaddress ipaddress

Supported Authentication Protocols

token
Sends a plain text token the server expects and matches a token sent by the server. The tokens do not have to be the same. If unspecified, the token with a secretid of 0 will be used in sending messages and validating received messages.
delayedrealm
Delayed Authentication. dhcpcd will send an authentication option with no key or MAC. The server will see this option, and select a key for dhcpcd.conf, writing the realm and secretid in it. dhcpcd will then look for an unexpired token with a matching realm and secretid. This token is used to authenticate all other messages.
delayed
Same as above, but without a realm.

Supported Authentication Algorithms

If none specified, hmac-md5 is the default.

hmac-md5
 

Supported Replay Detection Mechanisms

If none specified, monotonic is the default. If this is changed from what was previously used, or the means of calculating or storing it is broken, then the DHCP server will probably have to have its notion of the client's Replay Detection Value reset.

monocounter
Read the number in the file /var/lib/dhcpcd/dhcpcd-rdm.monotonic and add one to it.
monotime
Create an NTP timestamp from the system time.
monotonic
Same as monotime.
