DH_set_method(3ssl)

Paquete: openssl

Licencias: Apache-2.0

DH_SET_METHOD(3ssl) OpenSSL DH_SET_METHOD(3ssl)

NOMBRE

DH_set_default_method, DH_get_default_method, DH_set_method, DH_new_method, DH_OpenSSL - seleccionar método DH

SINOPSIS

#include <openssl/dh.h>

Las siguientes funciones han sido marcadas como obsoletas desde OpenSSL 3.0, y pueden ser ocultadas completamente definiendo OPENSSL_API_COMPAT con un valor de versión adecuado, ver openssl_user_macros(7):

void DH_set_default_method(const DH_METHOD *meth);
const DH_METHOD *DH_get_default_method(void);
int DH_set_method(DH *dh, const DH_METHOD *meth);
DH *DH_new_method(ENGINE *engine);
const DH_METHOD *DH_OpenSSL(void);

DESCRIPCIÓN

Todas las funciones descritas en esta página están obsoletas. Las aplicaciones deberían usar las APIs de proveedores en su lugar.

Un DH_METHOD especifica las funciones que OpenSSL usa para operaciones Diffie-Hellman. Modificando el método, se pueden usar implementaciones alternativas, como aceleradores de hardware. IMPORTANTE: Ver la sección NOTAS para información importante sobre cómo estas funciones de la API DH se ven afectadas por el uso de llamadas a la API de ENGINE.

Inicialmente, el DH_METHOD por defecto es la implementación interna de OpenSSL, tal como se devuelve con DH_OpenSSL().

DH_set_default_method() hace que meth sea el método por defecto para todas las estructuras DH creadas posteriormente. NB: Esto es cierto solo mientras no se haya establecido un ENGINE como predeterminado para DH, por lo que esta función ya no se recomienda. Esta función no es segura para hilos y no debe llamarse al mismo tiempo que otras funciones de OpenSSL.

DH_get_default_method() devuelve un puntero al DH_METHOD predeterminado actual. Sin embargo, la significancia de este resultado depende de si se está utilizando la API de ENGINE, por lo que esta función ya no se recomienda.

DH_set_method() selecciona meth para realizar todas las operaciones utilizando la clave dh. Esto reemplazará el DH_METHOD utilizado por la clave DH y si el método anterior fue proporcionado por un ENGINE, el manejador de ese ENGINE se liberará durante el cambio. Es posible tener claves DH que solo funcionen con ciertas implementaciones de DH_METHOD (por ejemplo, de un módulo ENGINE que soporte claves protegidas por hardware incrustado), y en tales casos, intentar cambiar el DH_METHOD para la clave puede tener resultados inesperados.

DH_new_method() asigna e inicializa una estructura DH para que engine se utilice para las operaciones DH. Si engine es NULL, se utiliza el ENGINE predeterminado para las operaciones DH y, si no se establece ningún ENGINE predeterminado, se utiliza el DH_METHOD controlado por DH_set_default_method().

Un nuevo objeto DH_METHOD puede construirse usando DH_meth_new() (ver DH_meth_new(3)).

VALORES DE RETORNO

DH_OpenSSL() y DH_get_default_method() devuelven punteros a los respectivos DH_METHODs.

DH_set_default_method() no devuelve ningún valor.

DH_set_method() devuelve un valor distinto de cero si el meth proporcionado se estableció correctamente como el método para dh (incluyendo la descarga del manejador de ENGINE si el método anterior fue proporcionado por un ENGINE).

DH_new_method() devuelve NULL y establece un código de error que puede obtenerse con ERR_get_error(3) si falla la asignación. De lo contrario, devuelve un puntero a la estructura recién asignada.

VER TAMBIÉN

DH_new(3), DH_new(3), DH_meth_new(3)

HISTORIA

Todas estas funciones fueron marcadas como obsoletas en OpenSSL 3.0.
