Les combinaisons clé/valeur suivantes sont valides

:
hpfile=archivo
Inserta archivo en la posición actual. archivo se busca con kpathsea(3), ver más abajo.

El contenido del archivo debe ser válido para esta impresora, es decir, debe contener secuencias de escape PCL o comandos HP-GL/2. Si el archivo es un archivo gráfico, esto generalmente significa que la esquina superior izquierda del gráfico se coloca en la posición actual.

Las secuencias de escape de posicionamiento absoluto PCL en archivo se reescriben para que sean comandos de posicionamiento relativo; la coordenada más baja que aparece se utiliza como referencia.

hpfile_verbatim=archivo
Inserta archivo verbatim en la posición actual, sin ningún cambio en el contenido del archivo. archivo se busca con kpathsea(3), ver más abajo.

Esto se utiliza principalmente para mantener posiciones absolutas en archivos PCL.

psfile=archivo llx=x0 lly=y0 urx=x1 ury=y1 rwi=s
Convierte el archivo PostScript archivo a HP PCL, mediante Ghostscript con el dispositivo "ljetplus", e inserta el archivo gráfico resultante en la posición actual, reescribiendo las secuencias de escape de posición absoluta. archivo se busca con kpathsea(3), ver más abajo.

Los pares clave/valor adjuntos son obligatorios, pueden especificarse en cualquier orden. Los valores x0, x1, y0, y1 y s son enteros. (x0,y0) es la esquina inferior izquierda, (x1,y1) la esquina superior derecha de la imagen.

Tenga en cuenta: La semántica específica de esta especialidad no se conoce. En particular, el parámetro rwi es algún factor de escala; pero incluso mirando el código fuente no está del todo claro qué pretendía implementar el autor de la especialidad aquí. Además, no está claro qué dimensiones se utilizan para especificar las esquinas, puntos PostScript o puntos PCL.

Si conoce la semántica de psfile, o si se ha tomado el trabajo de analizarla, por favor infórmenos en tex-k@tug.org, para que podamos actualizar esta página de manual con la información relevante.

dvilj-psfile-syntax=sintaxis
donde sintaxis es "dvilj" o "ignore". Esta es una forma muy rudimentaria de indicar al controlador qué hacer con las especialidades psfile.

Si el valor es "ignore", todas las especialidades psfile que se procesen después se ignorarán, hasta que se procese la siguiente especialidad dvilj-psfile-syntax.

Si el valor es "dvilj", las especialidades psfiles se procesan como se explicó anteriormente, hasta que se procese la siguiente especialidad dvilj-psfile-syntax.

Una extensión obvia y planificada es el valor "dvips", pero esto aún no se ha implementado.

Esa especialidad no es tan simple como parece a primera vista. Dado que su semántica se define por el orden de procesamiento, solo es útil si se coloca en la misma página que la especialidad psfile. Tenerla una vez en un archivo (por ejemplo, en la primera página) no ayuda si se imprime solo una página del documento; dvilj no realiza un preescaneo de las especialidades de la primera página como hacen otros controladores. (Los parches serían bienvenidos, por supuesto).

comment=texto arbitrario
comment texto arbitrario
Esto hace que el resto de la especialidad se ignore; se puede utilizar para agregar metainformación a un archivo DVI.

Con la primera forma, el comentario puede aparecer en cualquier lugar de la especialidad. Cuando aparece primero, el procesamiento de esta especialidad se termina y todo el texto posterior se ignora.

La segunda forma es una especialidad que se introdujo por compatibilidad con otros controladores. Si la primera palabra clave de la especialidad es comment y no tiene valor, también se considera una sintaxis de comentario válida; el resto de la especialidad se ignora.

0  para retrato
1  para paisaje

defpoint=n(x,y)
Define el punto número n. Este punto puede ser referenciado más tarde en otros comandos especiales para especificar áreas que se rellenarán con algún patrón. n debe estar entre 0 y 79.

x e y son la posición de ese punto y tienen el formato "?pt" donde "?" es un número de punto flotante. Las posiciones son relativas al origen de la página DVI; es decir, las coordenadas aumentan moviéndose hacia la derecha y hacia abajo, el punto de origen es (1 pulg, 1 pulg) en la esquina superior izquierda, alterado por las opciones -x, -y, -X y -Y, pero no por \hoffset y \voffset.

x e y pueden omitirse, es decir, los valores 3 o "4(,)" son válidos. Entonces, la posición actual de la página se utiliza como posición para el punto n.

resetpoints="all"
Esto anula la definición de todos los puntos nuevamente.
gray=escala_gris
grey=escala_gris
Esto establece el modo de relleno para la siguiente especialidad fill, el área se rellenará con color gris. (grey es un alias para gray.) Cualquier especificación de patrón se restablece.

escala_gris es el porcentaje de gris que se debe usar aquí; con 0 significando blanco y 100 significando negro.

Advertencia: Esta especialidad es en realidad un nombre equivocado. PCL llama a estas escalas de grises patrones de sombreado y se crean colocando puntos en el área. La escala de grises selecciona cuán separados están los puntos. En los rangos más bajos, esto no se ve muy gris de cerca, sino más como un fondo punteado. Además, las escalas de grises no son tan finas como el rango de valores 0..100 podría hacerte creer. En realidad, solo hay 8 patrones de gris diferentes disponibles:

 1 -  2%
 3 - 10%
11 - 20%
21 - 35%
36 - 55%
56 - 80%
81 - 99%
100%

Uno de estos patrones se selecciona según el valor de escala_gris.

pattern=pat
Esto establece el modo de relleno para la siguiente especialidad fill, el área se rellenará con un patrón. Cualquier especificación de color gris se restablece.

pat es uno de los siguientes valores:

1  líneas horizontales
2  líneas verticales
3  líneas diagonales, desde la esquina inferior izquierda a la superior derecha
4  líneas diagonales, desde la esquina superior derecha a la inferior izquierda
5  líneas cruzadas, verticales
6  líneas cruzadas, diagonales
fill=a/b
Rellena el área entre los puntos a y b, de acuerdo con el modo de relleno actual.

El punto a debe ser la esquina superior izquierda y el punto b debe ser la esquina inferior izquierda del rectángulo. De lo contrario, el resultado será basura.

El modo de relleno predeterminado es relleno de color gris al 10%.

nombre_archivo
Esta es una especialidad heredada, su uso está obsoleto. Si la especialidad es solo una palabra que nombra un archivo existente, ese archivo se incluye verbatim. A diferencia de otros medios de inclusión de archivos, el archivo no se busca con kpathsea(3). No se supone que use esta especialidad y no solucionaremos ningún problema con ella.

Cabe señalar que el analizador de especialidades a veces acepta construcciones que no son válidas según la documentación anterior. Entonces, la salida a menudo se daña de alguna manera.

Búsqueda de Archivos Incluidos

Las especialidades de inclusión de archivos adecuadas buscan el archivo con kpathsea(3). La ruta de búsqueda está configurada por la variable "DVILJINPUTS" y, si el archivo no se encuentra en esa ruta de búsqueda, por la variable "TEXINPUTS".

La búsqueda a través de "DVILJINPUTS" cubre el caso de uso de tener gráficos comunes en todo el sitio que se incluirán en documentos, por ejemplo, firmas escaneadas. La búsqueda a través de "TEXINPUTS" cubre el caso de uso de tener gráficos como parte del documento actual.

"dvilj" se utiliza como nombre de ".PROGRAM" en texmf.cnf, para todas las variantes del controlador, independientemente del nombre real del programa.

Especialidades Desconocidas y configuración de "TEX_HUSH"

Kpathsea(3) tiene el concepto de supresión de advertencias con la variable de configuración "TEX_HUSH", consulte su nodo de información TeX support / Suppressing warnings. Esa variable contiene identificadores separados por dos puntos que especifican las advertencias a suprimir.

Si "special" está entre los valores listados, dvilj ya no emite advertencias sobre especialidades que no conoce. Pero si hay una especialidad reconocida y si esa especialidad tiene un parámetro inválido, de todos modos se emite una advertencia, independientemente del contenido de "TEX_HUSH".

NAME

dvilj

print a DVI file on an HP LaserJet printer

SYNOPSIS

dvilj [-a] [-b] [-c] [-D[1|2|-]] [-F] [-f] [-h] [-i] [-l] [-m] [-n] [-pX] [-q] [-r] [-s] [-t] [-w] [-W] [-xN] [-z] [--] [dvi-file]

DESCRIPTION

dvilj

is a driver for HP LaserJet printers. It processes a TeX Device Independent file (DVI) and outputs it as a PCL stream suitable for an HP LaserJet printer. It can handle most printers available from HP, and also printers from other manufacturers that use HP PCL 4 or PCL 5 command sets.

The driver uses Ghostscript to render PostScript specials in the DVI file. If Ghostscript is not available, PostScript specials are ignored.

The driver has been developed and tested on Linux. It should also run on other Unix-like systems, and on Windows if Ghostscript is installed and found.

OPTIONS

The command line options are:

-a
Print pages in ascending order (from 1 to N).
-b
Print pages in descending order (from N to 1). This is the default.
-c
Use compressed PCL-commands. This reduces the size of the output file, but some older printers might not support it.
-D[1|2|-]
Enable double-side printing. When this option is used, the driver prints the even pages of a document on one side of the paper and the odd pages on the other. The default behavior is to print odd pages first, then even pages.

If -D is used without an argument, or with -D, then the driver will print the odd pages first and then the even pages. The printer will stop after printing half of the pages, and will show a message "FEED" and switch on the manual feed led. The printer continues when the operator feeds the printed pages into the manual page feeder, or pushes the continue button (after placing the printed pages into the paper tray).

If -D1 was specified, only odd pages will be printed. -D2 can be used for even pages. A trailing "-" (as in -D-, -D1- or -D2-) suppresses printing of empty pages which are generated for padding otherwise.

-F
Force font re-creation. When a font is not found, or not found in the correct size, a PK font file is generated. This option forces the driver to re-create PK font files even if they already exist.
-f
Print front-to-back. Default is back-to-front.
-h
Output HP-GL/2 plots for HP-GL specials.
-i
Use emulation of the LaserJet 4. This means 600 dpi instead of 300 dpi.
-l
Use landscape mode.
-m
Generate monochrome output only. If the printer does not support color, this option is recommended.
-n
Generate output for the printer model specified by the environment variable DVILJMODEL. This is an alternative to specifying the printer type with the -i option.
-pX
Print only the first X pages. This option can lead to strange results when used together with the -D option.
-q
Quiet mode. Suppress warnings about unknown specials.
-r
Reverse the order of pages. This is the default.
-s
Force use of PostScript specials. This is the default.
-t
Print on plain paper. Default is to use special paper.
-w
Warnings. Warn about unknown specials.
-W
Warn about checksum mismatches.
-xN
Set the resolution to N dots per inch. Default is 300 dpi. This option can be used to set the resolution for printers that support higher resolutions, like the LaserJet 4 (600 dpi).
-z
Do not use Ghostscript for PostScript specials. PostScript specials will be ignored.
--
End of options. All subsequent arguments are treated as filenames.

OPERANDS

dvi-file :: Input DVI file.

SUPPORTED TeX \special COMMANDS

The driver supports the following TeX \special commands:

eps
Include Encapsulated PostScript file.
pdf
Include PDF file.
color, fill, stroke, draw, clip, shades, rule, putpic
Color specials for colored output.
hplaser
Print the following text verbatim on the printer.
dvicopy
Special commands for dvicopy(1).
font, setfont
Set font parameters.
pjl
PJL commands.

A full description of supported specials can be found in the documentation provided with the driver.

DOUBLE PAGE PRINTING

The -D option enables double-side printing. This option can be used to print the even pages of a document on one side of the paper and the odd pages on the other. The default behavior is to print odd pages first, then even pages.

If -D is used without an argument (or with -D), the driver will print the odd pages first and then the even pages. The printer will stop after half of the pages have been printed, showing a message "FEED" and switching on the manual feed LED. The printer will continue when the operator feeds the printed pages into the manual page feeder, or pushes the continue button (after placing the printed pages into the paper tray).

If -D1 was specified, only odd pages will be printed. -D2 can be used for even pages. A trailing "-" (as in -D-, -D1- or -D2-) suppresses printing of empty pages which are generated for padding otherwise.

The driver allows the -D option for both print directions (front-to-back or back-to-front printing). It tries to be clever in certain cases: when a document has an odd number of pages, it inserts an empty page in the right place. When a document starts with page 0, the driver inserts an empty page after the 0-page. When a piece of a document is printed that starts with an even page number, the driver prints this page on the back of the first page to ensure that the odd sides are always on the frontside. The 0-page is treated like an odd page.

The doubleside option works for all LJs, not only for the new D model which does doubleside-printing (actually, I don't know whether it makes much sense on the new LJ II D at all).

Caveat on the doubleside-option: When it is used frequently or on very large files, it might become necessary to clean the printer much more frequently.

The command line option -pX can be used to abort printing after the output of X pages (can lead to strange results together with -D). I personally dislike this option. The secure way of printing a part of a document is using -f (from) and -t (to).

ENVIRONMENT

dvilj uses the same environment variables and algorithms for finding font files as TeX and its friends do. See the documentation for the kpathsea(3) library for details. (Repeating it here is too cumbersome.)

"DVILJFONTS"
If set, overrides all other font paths.
"DVILJMAKEPK"
If set, overrides mktexpk(1) as the name of the command to execute to create a PK file if one isn't found.
"DVILJSIZES"
May be set to indicate which sizes of fonts are available. It should consist of a list of numbers separated by colons. If the list begins with a colon, the system default sizes are used, as well. Sizes are expressed in dots per inch; decimals may be used for "pxl" files: for example, a 300 dots per inch file magnified by half a step comes out to 1643 dots per five inches, which should be encoded as 328.6. dvilj tries the actual size of the font before trying any of the given sizes.
"DVILJINPUTS"
Primary search path for include files.
"TEXINPUTS"
Secondary search path for include files.
"TEX_HUSH"
Colon separated list of identifiers that name situations where no warning shall be output. The following identifiers are used: 
checksum  suppress mismatched font checksum warnings
readable  suppress warnings about unreadable files
special   suppress warnings about unknown specials
all       suppress all warning classes above
none      suppress no warnings
"KPATHSEA_DEBUG"
Trace kpathsea(3) lookups; set to -1 for complete tracing.
"GS_PATH"
On Windows, this may be the path to Ghostscript; there the default is gswin32c.exe.

On Unix, this environment variable is not used. Ghostscript is called as gs(1) and must be found over $PATH.
