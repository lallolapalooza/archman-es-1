NOMBRE

dsr2html - Renderiza un archivo DICOM SR y un conjunto de datos a HTML/XHTML

SINOPSIS

dsr2html [opciones] dsrfile-in [htmlfile-out]

DESCRIPCIÓN

La utilidad dsr2html renderiza el contenido de un documento DICOM Structured Reporting (SR) (formato de archivo o conjunto de datos sin procesar) a HTML (Hyper Text Markup Language) versión 3.2 o 4.01, así como a XHTML (Extensible Hyper Text Markup Language) versión 1.1.

Si dsr2html lee un conjunto de datos sin procesar (datos DICOM sin un metadato de formato de archivo), intentará adivinar la sintaxis de transferencia examinando los primeros bytes del archivo. No siempre es posible adivinar correctamente la sintaxis de transferencia y es mejor convertir un conjunto de datos a formato de archivo siempre que sea posible (utilizando la utilidad dcmconv). También es posible utilizar las opciones -f y -t[ieb] para forzar a dsr2html a leer un conjunto de datos con una sintaxis de transferencia particular.

PARÁMETROS

dsrfile-in    Nombre del archivo de entrada DICOM SR a renderizar ("-" para stdin)
htmlfile-out  Nombre del archivo de salida HTML/XHTML (por defecto: stdout)

OPCIONES

Opciones generales

  -h   --help
         imprimir este texto de ayuda y salir
       --version
         imprimir información de la versión y salir
       --arguments
         imprimir argumentos expandidos de la línea de comandos
  -q   --quiet
         modo silencioso, no imprimir advertencias ni errores
  -v   --verbose
         modo detallado, imprimir detalles del procesamiento
  -d   --debug
         modo de depuración, imprimir información de depuración
  -ll  --log-level  [n]ivel: cadena constante
         (fatal, error, warn, info, debug, trace)
         usar el nivel l para el registrador
  -lc  --log-config  [a]rchivo: cadena
         usar el archivo de configuración f para el registrador

Opciones de entrada

formato del archivo de entrada:
  +f   --read-file
         leer formato de archivo o conjunto de datos (por defecto)
  +fo  --read-file-only
         leer solo el formato del archivo
  -f   --read-dataset
         leer conjunto de datos sin información meta del archivo
sintaxis de transferencia de entrada:
  -t=  --read-xfer-auto
         usar reconocimiento de TS (por defecto)
  -td  --read-xfer-detect
         ignorar TS especificada en el metadato del archivo
  -te  --read-xfer-little
         leer con sintaxis de transferencia explícita VR little endian
  -tb  --read-xfer-big
         leer con sintaxis de transferencia explícita VR big endian
  -ti  --read-xfer-implicit
         leer con sintaxis de transferencia VR implícita little endian

Opciones de procesamiento

información adicional:
  -Ip  --processing-details
         mostrar el elemento de contenido que se está procesando actualmente
manejo de errores:
  -Er  --unknown-relationship
         aceptar tipo de relación desconocido/faltante
  -Ev  --invalid-item-value
         aceptar valor de elemento de contenido inválido
         (p. ej., violación de la definición VR o VM)
  -Ec  --ignore-constraints
         ignorar restricciones de contenido de relación
  -Ee  --ignore-item-errors
         no abortar en errores de elementos de contenido, solo advertir
         (p. ej., atributos faltantes específicos del tipo de valor)
  -Ei  --skip-invalid-items
         omitir elementos de contenido inválidos (incluido el subárbol)
  -Dv  --disable-vr-checker
         deshabilitar la verificación de valores de cadena conformes a VR
juego de caracteres específico:
  +Cr  --charset-require
         requerir la declaración de juego de caracteres extendido (por defecto)
  +Ca  --charset-assume  [j]uego de caracteres: cadena
         asumir el juego de caracteres c si no se declara un juego de caracteres extendido
       --charset-check-all
         verificar todos los elementos de datos con valores de cadena
         (por defecto: solo PN, LO, LT, SH, ST, UC y UT)
         # esta opción solo se usa para la verificación extendida si
         # el atributo Specific Character Set (0008,0005) debe
         # estar presente, pero no para la conversión de valores de elemento
         # no afectados a UTF-8 (p. ej., valores de elemento con un VR de CS)
  +U8  --convert-to-utf8
         convertir todos los valores de elemento que están afectados
         por Specific Character Set (0008,0005) a UTF-8
         # requiere soporte de una biblioteca de codificación de caracteres
         # subyacente (ver la salida de --version sobre cuál está disponible)

Opciones de salida

compatibilidad HTML/XHTML:
  +H3  --html-3.2
         usar solo características compatibles con HTML versión 3.2
  +H4  --html-4.0
         permitir todas las características de HTML versión 4.01 (por defecto)
  +X1  --xhtml-1.1
         cumplir con la especificación XHTML versión 1.1
  +Hd  --add-document-type
         agregar referencia a la definición del tipo de documento SGML
hoja de estilos en cascada (CSS), no con HTML 3.2:
  +Sr  --css-reference  URL: cadena
         agregar referencia a CSS especificado al documento
  +Sf  --css-file  [a]rchivo: cadena
         incrustar contenido del CSS especificado en el documento
renderización general:
  +Ri  --expand-inline
         expandir elementos de contenido cortos en línea (por defecto)
  -Ri  --never-expand-inline
         nunca expandir elementos de contenido en línea
  +Ra  --always-expand-inline
         siempre expandir elementos de contenido en línea
  +Rd  --render-full-data
         renderizar datos completos de elementos de contenido
  +Rt  --section-title-inline
         renderizar títulos de sección en línea, no por separado
  +Rh  --hyperlink-url-prefix  [p]refijo: cadena
         usar prefijo de URL p para hipervínculos a objetos compuestos
         (por defecto: http://localhost/dicom.cgi)
renderización de documentos:
  +Dt  --document-type-title
         usar el tipo de documento como título del documento (por defecto)
  +Dp  --patient-info-title
         usar información del paciente como título del documento
  -Dh  --no-document-header
         no renderizar información general del documento
renderización de códigos:
  +Ci  --render-inline-codes
         renderizar códigos en bloques de texto continuos
  +Cn  --concept-name-codes
         renderizar código de nombres de conceptos
  +Cu  --numeric-unit-codes
         renderizar código de unidades de medida numéricas
  +Cv  --code-value-unit
         usar valor de código como unidad de medida (por defecto)
  +Cm  --code-meaning-unit
         usar significado de código como unidad de medida
  +Cc  --render-all-codes
         renderizar todos los códigos (implica +Ci, +Cn y +Cu)
  +Ct  --code-details-tooltip
         renderizar detalles del código como una tooltip (implica +Cc)

Codificación de caracteres

La codificación HTML/XHTML se determina automáticamente a partir del atributo DICOM (0008,0005) "Specific Character Set" utilizando la siguiente correspondencia:

ASCII         (ISO_IR 6)                       =>  (ninguno)
UTF-8         "ISO_IR 192"                     =>  "UTF-8"
ISO Latin 1   "ISO_IR 100"                     =>  "ISO-8859-1"
ISO Latin 2   "ISO_IR 101"                     =>  "ISO-8859-2"
ISO Latin 3   "ISO_IR 109"                     =>  "ISO-8859-3"
ISO Latin 4   "ISO_IR 110"                     =>  "ISO-8859-4"
ISO Latin 5   "ISO_IR 148"                     =>  "ISO-8859-9"
ISO Latin 9   "ISO_IR 203"                     =>  "ISO-8859-15"
Cyrillic      "ISO_IR 144"                     =>  "

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

;ISO-8859-5" Árabe "ISO_IR 127" => "ISO-8859-6" Griego "ISO_IR 126" => "ISO-8859-7" Hebreo "ISO_IR 138" => "ISO-8859-8" Tailandés "ISO_IR 166" => "TIS-620" Japonés "ISO 2022 IR 13\ISO 2022 IR 87" => "ISO-2022-JP" Coreano "ISO 2022 IR 6\ISO 2022 IR 149" => "ISO-2022-KR" Chino "ISO 2022 IR 6\ISO 2022 IR 58" => "ISO-2022-CN" Chino "GB18030" => "GB18030" Chino "GBK" => "GBK"

Si este atributo DICOM falta en el archivo de entrada, aunque sea necesario, se puede usar la opción --charset-assume para especificar manualmente un juego de caracteres apropiado (usando uno de los términos definidos en DICOM). Por razones de compatibilidad con versiones anteriores de esta herramienta, también se admiten los siguientes términos y se asignan automáticamente a los términos DICOM asociados: latin-1, latin-2, latin-3, latin-4, latin-5, latin-9, cyrillic, arabic, greek, hebrew.

La opción --convert-to-utf8 se puede usar para convertir el archivo o conjunto de datos DICOM a la codificación UTF-8 antes de la representación en formato HTML/XHTML.

REGISTRO (LOGGING)

El usuario puede especificar el nivel de salida de registro de las diversas herramientas de línea de línea de comandos y bibliotecas subyacentes. De forma predeterminada, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como los detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config . Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basados en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Normalmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comando usando el signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comando largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dsr2html intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . De forma predeterminada, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en la que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.

Dependiendo de las opciones de la línea de comandos especificadas, la utilidad dsr2html intentará cargar tablas de asignación de juegos de caracteres. Esto ocurre cuando DCMTK se compiló con la biblioteca oficonv (que es lo predeterminado) y las tablas de asignación no están compiladas en la biblioteca (predeterminado cuando DCMTK usa bibliotecas compartidas).

Se espera que los archivos de la tabla de asignación estén en <datadir>de DCMTK. La variable de entorno DCMICONVPATH se puede usar para especificar una ubicación diferente. Si se especifica una ubicación diferente, esas tablas de asignación también reemplazan cualquier tabla integrada.
