DS-LOGPIPE.PY(1) Manual de comandos generales DS-LOGPIPE.PY(1)

NOMBRE

ds-logpipe.py - Crea y lee de una tubería con nombre en lugar de un archivo de registro

SINOPSIS

ds-logpipe.py /ruta/completa/a/tubería-con-nombre
[-m max_líneas_a_almacenar] [-u id_usuario] [-s archivo_pid_servidor] [-t tiempo_espera_servidor] [--plugin=/ruta/a/archivo_plugin.py] [argumento_archivo_plugin=valor]

DESCRIPCIÓN

El script de tubería de registro con nombre permite reemplazar un archivo de registro con una tubería con nombre conectada a un script. El servidor puede entonces enviar la salida del registro a un script en lugar de a un archivo de registro. Esto permite hacer muchas cosas diferentes, tales como:


* registrar solo ciertos eventos, por ejemplo, fallos de enlace, conexiones de ciertas direcciones IP, etc.
* registrar solo líneas que coincidan con un patrón determinado
* registrar solo las últimas N líneas: útil para habilitar niveles de depuración completos de registro de errores en entornos de producción
* enviar un correo electrónico u otra notificación cuando se detecta un evento determinado

El script está escrito en Python y permite el uso de plugins. Por defecto, el script registrará las últimas N líneas (por defecto 1000). Se proporcionan dos plugins: uno para registrar solo los intentos de enlace fallidos y otro que registrará solo las líneas que coincidan con las expresiones regulares dadas.

OPCIONES

A continuación se incluye un resumen de las opciones.

/ruta/completa/a/tubería-con-nombre
Requerido: ruta completa y nombre de archivo de la tubería con nombre. Si no existe, se creará. Si existe y es una tubería con nombre, el script la utilizará. Si existe y no es una tubería, el script abortará. La propiedad será la misma que la del usuario que ejecuta el script (o vea la opción -u a continuación).
-m|--maxlíneas=N
Número de líneas a almacenar en búfer. El valor predeterminado es 1000.
-u|--id_usuario=usuario
La tubería y cualquier otro archivo creado por el script se asignarán a este id_usuario. Puede ser un nombre de id_usuario de cadena o un valor numérico de id_usuario.
-s|--archivo_pid_servidor=/ruta/a/nombre_servidor.pid
Si desea que el script salga cuando exista un servidor de directorio particular, especifique la ruta completa al archivo que contiene el pid del servidor. El valor predeterminado suele ser algo como /var/run/dirsrv/slapd-<nombre_instancia>.pid, donde <nombre_instancia> suele ser el nombre de host.
-t|--tiempo_espera_servidor=N
Dado que el archivo_pid_servidor puede no existir aún cuando se ejecuta el script, el script esperará por defecto 60 segundos a que el archivo pid exista y el servidor se inicie. Use esta opción para especificar un tiempo de espera diferente. La opción -t solo se aplica cuando se usa -s o --archivo_pid_servidor; de lo contrario, no hace nada.
--archivo_pid_servidor=P
SI el servidor que desea rastrear ya está en ejecución, puede especificarlo usando este argumento. Si el pid especificado no es válido, el script abortará.
-p|--plugin=/ruta/completa/a/nombre_plugin.py
Especifique un plugin a utilizar. El plugin debe ser un archivo Python y debe terminar en .py. Debe especificar una función llamada plugin y puede especificar funciones llamadas pre y post.
nombre_plugin.arg1=valor ... nombre_plugin.argN=valor
Puede especificar argumentos para los plugins en la línea de comandos. Si hay un plugin especificado como --plugin=/ruta/completa/a/nombre_plugin.py, los argumentos para ese plugin se especifican como nombre_plugin.nombre_arg=valor. El script analiza estos argumentos y los pasa a la función pre del plugin como un diccionario Python. SI hay más de un argumento llamado nombre_plugin.nombre_arg, los valores se pasan como una lista Python.

NOTAS DEL SERVIDOR DE DIRECTORIO

El servidor de directorio generalmente necesitará ser configurado para registrar en la tubería con nombre en lugar del archivo de registro habitual. Por ejemplo, use el siguiente LDIF para indicarle al servidor que use el archivo access.pipe para el registro de acceso:
dn: cn=config
changetype: modify
replace: nsslapd-accesslog-maxlogsperdir
nsslapd-accesslog-maxlogsperdir: 1
-
replace: nsslapd-accesslog-logexpirationtime
nsslapd-accesslog-logexpirationtime: -1
-
replace: nsslapd-accesslog-logrotationtime
nsslapd-accesslog-logrotationtime: -1
-
replace: nsslapd-accesslog
nsslapd-accesslog: /var/log/dirsrv/slapd-localhost/access.pipe
-
replace: nsslapd-accesslog-logbuffering
nsslapd-accesslog-logbuffering: off

NOTA: Antes de hacer esto, debe guardar su configuración actual para poder restaurarla más tarde.
ldapsearch ... -s base -b "cn=config" nsslapd-accesslog-maxlogsperdir nsslapd-accesslog-logexpirationtime nsslapd-accesslog-logrotationtime nsslapd-accesslog > savedaccesslog.ldif

El registro de errores y el registro de auditoría tienen atributos de configuración con nombres similares, por ejemplo, nsslapd-errorlog, nsslapd-auditlog. Tenga en cuenta que el registro de auditoría está deshabilitado por defecto; use nsslapd-auditlog-logging-enabled: on para habilitarlo.
