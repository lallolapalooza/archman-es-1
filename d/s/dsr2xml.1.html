Codificación de

caracteres

La codificación XML se determina automáticamente a partir del atributo DICOM (0008,0005) "Juego de Caracteres Específico" utilizando la siguiente correspondencia

: 
ASCII         (ISO_IR 6)                       =>  "UTF-8"
UTF-8         "ISO_IR 192"                     =>  "UTF-8"
ISO Latin 1   "ISO_IR 100"                     =>  "ISO-8859-1"
ISO Latin 2   "ISO_IR 101"                     =>  "ISO-8859-2"
ISO Latin 3   "ISO_IR 109"                     =>  "ISO-8859-3"
ISO Latin 4   "ISO_IR 110"                     =>  "ISO-8859-4"
ISO Latin 5   "ISO_IR 148"                     =>  "ISO-8859-9"
ISO Latin 9   "ISO_IR 203"                     =>  "ISO-8859-15"
Cyrillic      "ISO_IR 144"                     =>  "ISO-8859-5"
Arabic        "ISO_IR 127"                     =>  "ISO-8859-6"
Greek         "ISO_IR 126"                     =>  "ISO-8859-7"
Hebrew        "ISO_IR 138"                     =>  "ISO-8859-8"
Thai          "ISO_IR 166"                     =>  "TIS-620"
Japanese      "ISO 2022 IR 13\ISO 2022 IR 87"  =>  "ISO-2022-JP"
Korean        "ISO 2022 IR 6\ISO 2022 IR 149"  =>  "ISO-2022-KR"
Chinese       "ISO 2022 IR 6\ISO 2022 IR 58"   =>  "ISO-2022-CN"
Chinese       "GB18030"                        =>  "GB18030"
Chinese       "GBK"                            =>  "GBK"

Si este atributo DICOM falta en el archivo de entrada, aunque sea necesario, se puede usar la opción --charset-assume para especificar manualmente un juego de caracteres apropiado (usando uno de los términos definidos por DICOM). Por razones de compatibilidad con versiones anteriores de esta herramienta, también se admiten y se asignan automáticamente a los términos DICOM asociados los siguientes términos: latin-1, latin-2, latin-3, latin-4, latin-5, latin-9, cyrillic, arabic, greek, hebrew.

La opción --convert-to-utf8 se puede usar para convertir el archivo o conjunto de datos DICOM a la codificación UTF-8 antes de la conversión al formato XML.

Si no se define ninguna asignación y no se usa la opción --convert-to-utf8 , los caracteres no ASCII y aquellos por debajo de #32 se almacenan como "&" donde "nnn" se refiere al código numérico del carácter. Esto puede dar lugar a referencias de entidades de caracteres no válidas (como "&" para ESC) y hará que la mayoría de los analizadores XML rechacen el documento.

Manejo de errores

Tenga cuidado con las opciones de procesamiento --unknown-relationship, --invalid-item-value, --ignore-constraints, --ignore-item-errors y --skip-invalid-items ya que desactivan ciertas comprobaciones de validación en el archivo de entrada DICOM SR y, por lo tanto, podrían resultar en una salida no conforme a los estándares. Sin embargo, puede haber razones para usar una o más de estas opciones, por ejemplo, para leer y procesar un documento SR codificado incorrectamente.

Limitaciones

El esquema XML dsr2xml.xsd no admite todas las variaciones del formato de salida de dsr2xml . Sin embargo, el formato de salida predeterminado (más la opción --use-xml-namespace) debería funcionar.

REGISTRO

El nivel de salida de registro de los distintos programas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informa de mensajes informativos como detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, para fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet solo se informa de errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de registros), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config . Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comando largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

El utilidad dsr2xml intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento por defecto y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en la que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.

Dependiendo de las opciones de la línea de comandos especificadas, la utilidad dsr2xml intentará cargar tablas de asignación de juegos de caracteres. Esto ocurre cuando DCMTK se compiló con la biblioteca oficonv (que es el predeterminado) y las tablas de asignación no están integradas en la biblioteca (predeterminado cuando DCMTK usa bibliotecas compartidas).

Se espera que los archivos de la tabla de asignación estén en el <datadir>de DCMTK. La variable de entorno DCMICONVPATH se puede usar para especificar una ubicación diferente. Si se especifica una ubicación diferente, esas tablas de asignación también reemplazan cualquier tabla integrada.
