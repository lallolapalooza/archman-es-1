DESCRIPCIÓ

N

La utilidad dsrdump vuelca el contenido de un documento DICOM de Informes Estructurados (SR) (formato de archivo o conjunto de datos sin procesar) a stdout en forma de texto. El contenido del documento se muestra siguiendo el formato propuesto en el libro de David Clunie "DICOM Structured Reporting" (PixelMed Publishing, 2000)

.

Si dsrdump lee un conjunto de datos sin procesar (datos DICOM sin un encabezado meta de formato de archivo) intentará adivinar la sintaxis de transferencia examinando los primeros bytes del archivo. No siempre es posible adivinar correctamente la sintaxis de transferencia y es mejor convertir un conjunto de datos a un formato de archivo siempre que sea posible (utilizando la utilidad dcmconv). También es posible usar las opciones -f y -t[ieb] para forzar a dsrdump a leer un conjunto de datos con

una sintaxis de trans
ferencia particular.

REGISTR

O

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias al flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, p. ej. para propósitos de depuración. Otros niveles de registro pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, ver la documentación del módulo

"oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de registro), a syslog (Unix) o al registro de eventos (Windows), puede usarse la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier parte). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix

comunes.

Además, se pueden especificar uno o más archivos de comando usando el signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Un argumento de comando de este tipo se sustituye por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un único separador, a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque sencillo pero eficaz permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comando largas y confusas (se proporciona un ejemplo en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dsrdump intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. De forma predeterminada, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows)

.

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en la que dos puntos (":") separan las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de

entorno

DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos. Dependiendo de las opciones de la línea de comando especificadas, la

utilidad

dsrdump intentará cargar tablas de asignación de conjuntos de caracteres. Esto ocurre cuando DCMTK se compiló con la biblioteca oficonv (que es lo predeterminado) y las tablas de asignación no están compiladas en la biblioteca (predeterminado cuando DCMTK usa bibliotecas compartidas). Se espera que los archivos de la tabla de asignación estén en el <datadir> de DCMTK. L

a variable
de entorno

DCMICONVPATH puede usarse para especificar una ubicación diferente. Si se especifica una ubicación diferente, esas tablas de asignación también reemplazan cualquier

tabla integrada.
