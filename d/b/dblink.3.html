NOMBRE

dblink — ejecuta una consulta en una base de datos remota

SINOPSIS

dblink(text connname, text sql [, bool fail_on_error]) retorna setof record
dblink(text connstr, text sql [, bool fail_on_error]) retorna setof record
dblink(text sql [, bool fail_on_error]) retorna setof record

DESCRIPCIÓN

dblink ejecuta una consulta (normalmente un SELECT, pero puede ser cualquier sentencia SQL que devuelva filas) en una base de datos remota.

Cuando se proporcionan dos argumentos de texto, primero se busca el nombre de una conexión persistente; si se encuentra, el comando se ejecuta en esa conexión. Si no se encuentra, el primer argumento se trata como una cadena de información de conexión, como para dblink_connect, y la conexión indicada se establece solo durante la duración de este comando.

ARGUMENTOS

connname

Nombre de la conexión a usar; omite este parámetro para usar la conexión sin nombre.

connstr

Una cadena de información de conexión, como se describió previamente para dblink_connect.

sql

La consulta SQL que deseas ejecutar en la base de datos remota, por ejemplo select * from foo.

fail_on_error

Si es verdadero (el valor predeterminado cuando se omite) entonces un error lanzado en el lado remoto de la conexión provoca que también se lance un error localmente. Si es falso, el error remoto se informa localmente como un NOTICE, y la función no devuelve ninguna fila.

VALOR DE RETORNO

La función devuelve la(s) fila(s) producida(s) por la consulta. Dado que dblink puede usarse con cualquier consulta, se declara para devolver `record`, en lugar de especificar cualquier conjunto particular de columnas. Esto significa que debes especificar el conjunto esperado de columnas en la consulta que llama; de lo contrario, PostgreSQL no sabría qué esperar. Aquí tienes un ejemplo:

SELECT *
    FROM dblink('dbname=mydb options=-csearch_path=',
                'select proname, prosrc from pg_proc')
      AS t1(proname name, prosrc text)
    WHERE proname LIKE 'bytea%';

La parte de "alias" de la cláusula FROM debe especificar los nombres y tipos de columna que la función devolverá. (Especificar nombres de columna en un alias es en realidad sintaxis SQL estándar, pero especificar tipos de columna es una extensión de PostgreSQL). Esto permite que el sistema comprenda a qué se expande “*”, y a qué se refiere `proname` en la cláusula WHERE, antes de intentar ejecutar la función. En tiempo de ejecución, se lanzará un error si la consulta resultante de la base de datos remota no tiene el mismo número de columnas que se muestra en la cláusula FROM. Sin embargo, los nombres de columna no necesitan coincidir, y dblink tampoco insiste en coincidencias exactas de tipo. Tendrá éxito siempre que las cadenas de datos devueltas sean una entrada válida para el tipo de columna declarado en la cláusula FROM.

NOTAS

Una forma conveniente de usar dblink con consultas predeterminadas es crear una vista. Esto permite que la información del tipo de columna esté oculta en la vista, en lugar de tener que especificarla en cada consulta. Por ejemplo,

CREATE VIEW myremote_pg_proc AS
  SELECT *
    FROM dblink('dbname=postgres options=-csearch_path=',
                'select proname, prosrc from pg_proc')
    AS t1(proname name, prosrc text);
SELECT * FROM myremote_pg_proc WHERE proname LIKE 'bytea%';
