Las transacciones de DBI/DBD::SQLite pueden ser un poco confusas. Se comportan de manera diferente según el estado de la bandera "AutoC

Se supone que siempre debe usar el modo de autoconfirmación, a menos que comience explícitamente una transacción, y cuando la transacción termine, debe volver al modo de autoconfirmación. Para comenzar una transacción, llame al método "begin_work", o emita una sentencia "BEGIN". Para terminarla, llame a los métodos "commit/rollback", o emita las sentencias correspondientes.

Transacciones y bloqueo de la base de

datos

El comportamiento transaccional por defecto de SQLite es "deferred" (diferido), lo que significa que los bloqueos no se adquieren hasta la primera operación de lectura o escritura, y por lo tanto es posible que otro hilo o proceso cree una transacción separada y escriba en la base de datos después de que el "BEGIN" en el hilo actual se haya ejecutado, y eventualmente cause un "deadlock" (interbloqueo). Para evitar esto, DBD::SQLite emite internamente un "BEGIN IMMEDIATE" si comienzas una transacción llamando a "begin_work" o desactivando "AutoCommit" (desde 1.38_01)

.

Si realmente necesitas desactivar esta característica por alguna razón, establece el atributo de manejador de base de datos "sqlite_use_immediate_transaction" a falso, y se usará la transacción "deferred" por

defecto.

})

O, emite una sentencia "BEGIN" explícitamente cada vez que comiences una

transacción.

Ver http://sqlite.org/lockingv3.html

"$sth->finish" y reversión de

transacciones

Como dice la documentación de DBI, casi con toda seguridad no necesitas llamar a "finish" en un método de DBI si obtienes todas las filas (probablemente en un bucle). Sin embargo, hay varias excepciones a esta regla, y la reversión de una sentencia "SELECT" sin finalizar es uno de esos casos

excepcionales.

SQLite prohíbe el "ROLLBACK" de sentencias "SELECT" sin finalizar en una transacción (ver http://sqlite.org/lang_transaction.html para detalles). Por lo tanto, necesitas llamar a "finish" antes de emitir un

rollback.

    $sth->execute;
    $row = $sth->fetch;
    ...
    die "Por alguna razón";
    ...
};
if($@) {
   $sth->finish;  # Necesitas esto para SQLite
   $dbh->rollback;
} else {
   $dbh->commit;
}

Añadiendo colaciones definidas por el

La API nativa de SQLite para añadir colaciones definidas por el usuario se expone a través de los métodos "sqlite_create_collation" y "sqlite_collation_needed"

    [aaaaaacdeeeeiiiinoooooouuuuy] for $a, $b;
