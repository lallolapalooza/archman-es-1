dbopen(3) Manual de funciones de biblioteca dbopen(3)

NOMBRE

dbopen - métodos de acceso a bases de datos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/types.h>
#include <limits.h>
#include <db.h>
#include <fcntl.h>
DB *dbopen(const char *path, int flags, int mode, DBTYPE type,
           const void *openinfo);

DESCRIPCIÓN

Nota importante: Esta página documenta las interfaces proporcionadas hasta glibc 2.1. Desde glibc 2.2, glibc ya no proporciona estas interfaces. Probablemente, esté buscando las API proporcionadas por la biblioteca libdb en su lugar.

dbopen() es la interfaz de biblioteca para archivos de base de datos. Los formatos de archivo admitidos son btree, hashed y orientados a archivos UNIX. El formato btree es una representación de una estructura de árbol ordenada y equilibrada. El formato hashed es un esquema de hash extensible y dinámico. El formato de archivo plano es un archivo de flujo de bytes con registros de longitud fija o variable. Los formatos y la información específica del formato de archivo se describen en detalle en sus respectivas páginas de manual btree(3), hash(3) y recno(3).

dbopen() abre path para lectura y/o escritura. Los archivos que nunca se pretenden conservar en disco se pueden crear estableciendo el argumento path en NULL.

Los argumentos flags y mode son como se especifican para la rutina open(2), sin embargo, solo los indicadores O_CREAT, O_EXCL, O_EXLOCK, O_NONBLOCK, O_RDONLY, O_RDWR, O_SHLOCK y O_TRUNC son significativos. (Nota, no es posible abrir un archivo de base de datos O_WRONLY).

El argumento type es de tipo DBTYPE (como se define en el archivo de inclusión <db.h>) y puede establecerse en DB_BTREE, DB_HASH o DB_RECNO.

El argumento openinfo es un puntero a una estructura específica del método de acceso descrita en la página de manual del método de acceso. Si openinfo es NULL, cada método de acceso utilizará los valores predeterminados apropiados para el sistema y el método de acceso.

dbopen() devuelve un puntero a una estructura DB en caso de éxito y NULL en caso de error. La estructura DB se define en el archivo de inclusión <db.h>, y contiene al menos los siguientes campos:


typedef struct {
    DBTYPE type;
    int (*close)(const DB *db);
    int (*del)(const DB *db, const DBT *key, unsigned int flags);
    int (*fd)(const DB *db);
    int (*get)(const DB *db, DBT *key, DBT *data,
               unsigned int flags);
    int (*put)(const DB *db, DBT *key, const DBT *data,
               unsigned int flags);
    int (*sync)(const DB *db, unsigned int flags);
    int (*seq)(const DB *db, DBT *key, DBT *data,
               unsigned int flags);
} DB;

Estos elementos describen un tipo de base de datos y un conjunto de funciones que realizan diversas acciones. Estas funciones toman un puntero a una estructura devuelta por dbopen(), y a veces uno o más punteros a estructuras de clave/datos y un valor de indicador. Estos elementos describen un tipo de base de datos y un conjunto de funciones que realizan diversas acciones. Estas funciones toman un puntero a una estructura devuelta por dbopen(), y a veces uno o más punteros a estructuras de clave/datos y un valor de indicador.

type
El tipo del método de acceso subyacente (y formato de archivo).
close
Un puntero a una rutina para vaciar cualquier información en caché en el disco, liberar cualquier recurso asignado y cerrar los archivos subyacentes. Dado que los pares clave/datos pueden almacenarse en caché en memoria, no vaciar el archivo con una función close o sync puede resultar en información inconsistente o perdida. Las rutinas close devuelven -1 en caso de error (estableciendo errno) y 0 en caso de éxito.
del
Un puntero a una rutina para eliminar pares clave/datos de la base de datos.
El argumento flag puede establecerse en el siguiente valor:
R_CURSOR
Eliminar el registro al que hace referencia el cursor. El cursor debe haber sido inicializado previamente.
Las rutinas delete devuelven -1 en caso de error (estableciendo errno), 0 en caso de éxito, y 1 si la key especificada no estaba en el archivo.
fd
Un puntero a una rutina que devuelve un descriptor de archivo representativo de la base de datos subyacente. Se devolverá un descriptor de archivo que hace referencia al mismo archivo a todos los procesos que llamen a dbopen() con el mismo nombre path. Este descriptor de archivo se puede utilizar de forma segura como argumento para las funciones de bloqueo fcntl(2) y flock(2). El descriptor de archivo no está necesariamente asociado con ninguno de los archivos subyacentes utilizados por el método de acceso. No hay descriptor de archivo disponible para bases de datos en memoria. Las rutinas fd devuelven -1 en caso de error (estableciendo errno) y el descriptor de archivo en caso de éxito.
get
Un puntero a una rutina que es la interfaz para la recuperación por clave de la base de datos. La dirección y la longitud de los datos asociados con la key especificada se devuelven en la estructura a la que apunta data. Las rutinas get devuelven -1 en caso de error (estableciendo errno), 0 en caso de éxito, y 1 si la key no estaba en el archivo.
put
Un puntero a una rutina para almacenar pares clave/datos en la base de datos.
El argumento flag puede establecerse en uno de los siguientes valores:
R_CURSOR
Reemplazar el par clave/datos al que hace referencia el cursor. El cursor debe haber sido inicializado previamente.
R_IAFTER
Añadir los datos inmediatamente después de los datos a los que hace referencia key, creando un nuevo par clave/datos. El número de registro del par clave/datos añadido se devuelve en la estructura key. (Solo aplicable al método de acceso DB_RECNO).
R_IBEFORE
Insertar los datos inmediatamente antes de los datos a los que hace referencia key, creando un nuevo par clave/datos. El número de registro del par clave/datos insertado se devuelve en la estructura key. (Solo aplicable al método de acceso DB_RECNO).
R_NOOVERWRITE
Introducir el nuevo par clave/datos solo si la clave no existe previamente.
R_SETCURSOR
Almacenar el par clave/datos, estableciendo o inicializando la posición del cursor para que haga referencia a él. (Solo aplicable a los métodos de acceso DB_BTREE y DB_RECNO).
R_SETCURSOR solo está disponible para los métodos de acceso DB_BTREE y DB_RECNO porque implica que las claves tienen un orden inherente que no cambia.
R_IAFTER y R_IBEFORE solo están disponibles para el método de acceso DB_RECNO porque cada uno implica que el método de acceso puede crear nuevas claves. Esto solo es cierto si las claves están ordenadas e independientes, como los números de registro.
El comportamiento predeterminado de las rutinas put es introducir el nuevo par clave/datos, reemplazando cualquier clave existente previamente.
Las rutinas put devuelven -1 en caso de error (estableciendo errno), 0 en caso de éxito, y 1 si el flag R_NOOVERWRITE se estableció y la clave ya existe en el archivo.
seq
Un puntero a una rutina que es la interfaz para la recuperación secuencial de la base de datos. La dirección y la longitud de la clave se devuelven en la estructura a la que apunta key, y la dirección y la longitud de los datos se devuelven en la estructura a la que apunta data.

Pares
clave/datos
El acceso a todos los tipos de archivos se basa en pares clave/datos. Tanto las claves como los datos están representados por la siguiente estructura
de
datos:

typedef struct

Los elementos de la estructura DBT se definen como sigue: data Un puntero a una cadena

de bytes. size

La longitud de la cadena de bytes. Las cadenas de bytes de clave y datos pueden referenciar cadenas de longitud esencialmente ilimitada, aunque cualquiera de dos de ellas debe caber en la memoria disponible al mismo tiempo. Debe tenerse en cuenta que los métodos de acceso no proporcionan garantías sobre la alineación de las cadenas de bytes.
