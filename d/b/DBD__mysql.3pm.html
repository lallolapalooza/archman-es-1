DESCRIPCIÓ

N

DBD::mysql es el controlador de la Interfaz de Base de Datos de Perl5 para la base de datos MySQL. En otras palabras: DBD::mysql es una interfaz entre el lenguaje de programación Perl y la API de programación de MySQL que viene con el sistema de gestión de bases de datos relacional MySQL. La mayoría de las funciones proporcionadas por esta API de programación son compatibles. Faltan algunas funciones raramente utilizadas, principalmente porque nadie las ha solicitado nunca. :

-)

A continuación, discutimos primero el uso de DBD::mysql, porque es lo que más necesitará. Para la instalación, consulte el documento separado DBD::mysql::INSTALL. Vea "EJEMPLO" para un ejemplo simple

arriba.

Desde perl, activa la interfaz con la

declaración 
use
DBI;

Después de eso, puede conectarse a múltiples servidores de bases de datos MySQL y enviar múltiples consultas a cualquiera de ellos a través de una simple interfaz orientada a objetos. Hay disponibles dos tipos de objetos: manejadores de base de datos y manejadores de sentencias. Perl devuelve un manejador de base de datos al método connect

así: 
$dbh = DBI->connect("DBI:mysql:database=$db;host=$host",
  $user, $password, {RaiseError => 1})
;

Una vez que se haya conectado a una base de datos, puede ejecutar sentencias SQL

con: 
my $query = sprintf("INSERT INTO foo VALUES (%d, %s)",
                    $number, $dbh->quote("name"));
$dbh->do($query)
;

Vea DBI para detalles sobre los métodos quote y do. Un enfoque alternativo

es 
$dbh->do("INSERT INTO foo VALUES (?, ?)", undef,
         $number, $name)
;

en cuyo caso el método quote se ejecuta automáticamente. Vea también el método bind_param en DBI. Vea "MANEJADORES DE BASE DE DATOS" más abajo para más detalles sobre los manejadores de base de

datos.

Si desea recuperar resultados, necesita crear un llamado manejador de sentencia

con: 
$sth = $dbh->prepare("SELECT * FROM $table");
$sth->execute()
;

Este manejador de sentencia puede usarse para múltiples cosas. Primero, puede recuperar una fila de

datos: 
my $row = $sth->fetchrow_hashref()
;

Si su tabla tiene las columnas ID y NAME, entonces $row será una referencia a un hash con las claves ID y NAME. Vea "MANEJADORES DE SENTENCIAS" más abajo para más detalles sobre los manejadores de

sentencias.

formal:

Este atributo determina si DBD::mysql se reconectará automáticamente a mysql si se pierde la conexión. Esta función está desactivada de forma predeterminada; sin embargo, si la variable de entorno GATEWAY_INTERFACE o MOD_PERL está establecida, DBD::mysql activará mysql_auto_reconnect. Este atributo determina si DBD::mysql debe asumir que las cadenas almacenadas en la base de datos son utf8. Esta función está desactivada de forma predeterminada.

SENTENCIAS

Los manejores de sentencias de DBD::mysql admiten una serie de atributos. Se acceden a ellos utilizando, por

ejemplo, 
my $numFields = $sth->{NUM_OF_FIELDS}
;

Tenga en cuenta que la mayoría de los atributos solo son válidos después de un execute exitoso. De lo contrario se devolverá un valor "undef". La excepción más importante es el atributo "mysql_use_result", que fuerza al controlador a usar mysql_use_result en lugar de mysql_store_result. El primero es más rápido y consume menos memoria, pero tiende a bloquear otros procesos. (Por eso mysql_store_result es el valor predeterminado.

)

Para establecer el atributo "mysql_use_result", use cualquiera de los

siguientes: 
my $sth = $dbh->prepare("QUERY", { mysql_use_result => 1})
;

o 
my $sth = $dbh->prepare($sql);
$sth->{mysql_use_result} =
1;

Los atributos dependientes de la columna, por ejemplo NAME (los nombres de las columnas), se devuelven como una referencia a un array. Los índices del array corresponden a los índices de los arrays devueltos por fetchrow y métodos similares. Por ejemplo, el siguiente código imprimirá una cabecera con los nombres de las tablas junto con todas las

filas: 
my $sth = $dbh->prepare("SELECT * FROM $table") ||
  die "Error:" . $dbh->errstr . "\n";
$sth->execute ||  die "Error:" . $sth->errstr . "\n";
my $names = $sth->{NAME};
my $numFields = $sth->{'NUM_OF_FIELDS'} - 1;
for my $i ( 0..$numFields ) {
    printf("%s%s", $i ? "," : "", $$names[$i]);
}
print "\n";
while (my $ref = $sth->fetchrow_arrayref) {
    for my $i ( 0..$numFields ) {
    printf("%s%s", $i ? "," : "", $$ref[$i]);
    }
    print "\n";
}

SOPORTE DE

TRANSACCIONES

El soporte de transacciones funciona de la siguiente

manera:
  • Por defecto, el modo AutoCommit está activado, siguiendo las especificaciones de
    • DBI.
  • Si ejecuta 
    $dbh->{AutoCommit}
    = 0;

    o 
    $dbh->{AutoCommit}
    = 1;

    entonces el controlador establecerá la variable del servidor de MySQL autocommit a 0 o 1, respectivamente. Cambiar de 0 a 1 también emitirá un COMMIT, siguiendo las especificaciones

    de
    • DBI.
  • Los métodos 
    $dbh->rollback();
$dbh->commit()
    ;

    emitirán los comandos ROLLBACK y COMMIT, respectivamente. También

    se emitirá un ROLLBACK si el modo AutoCommit está desactiv
    • ado y se llama al método DESTROY del controlador de base d
e datos. De nuevo, esto sigue las especificaciones de DBI.

Dado lo anterior, debe tener en cuenta lo

siguiente:
  • Nunca debe cambiar manualmente la variable del servidor autocommit, a menos que esté ignorando el soporte de transacciones de
    • DBI.
  • Cambiar el modo AutoCommit de activado a desactivado o viceversa puede fallar. Debe comprobar siempre si hay errores al cambiar el modo AutoCommit. La forma recomendada de hacerlo es usando el indicador RaiseError de DBI. Si no le gusta RaiseError, tiene que usar código como el siguiente: 
    $dbh->{AutoCommit} = 0;
if ($dbh->{AutoCommit}) {
  # ¡Ocurrió un
    error!
    • }
  • Si detecta un error al cambiar el modo AutoCommit, ya no debe usar el controlador de base de datos. En otras palabras, debe desconectarse y conectarse de nuevo, porque el modo de transacción es impredecible. Alternativamente, puede verificar el modo de transacción comprobando el valor de la variable del servidor autocommit. Sin embargo, ese comportamiento no es
    • portable.
  • DBD::mysql tiene una función de "reconexión" que maneja el llamado "error de la mañana" de MySQL: Si el servidor se ha desconectado, muy probablemente debido a un tiempo de espera, entonces por defecto el controlador se reconectará y intentará ejecutar la misma sentencia SQL de nuevo. Sin embargo, este comportamiento está desactivado cuando AutoCommit está desactivado: De lo contrario, el estado de la transacción sería completamente impredecible después de una
    • reconexión.
  • La función de "reconexión" de DBD::mysql se puede activar o desactivar usando el atributo
    • mysql_auto_reconnect. Este comportamiento debería estar desactivado en código que usa LO
CK TABLE, porque si el servidor de base de datos expira el tiempo de espera y DBD::mysql
se reconecta, los bloqueos de tablas se perderán sin ninguna indicación de dicha pérdida.

MULTIHILO

S

Las capacidades multihilo de DBD::mysql dependen completamente de las bibliotecas C subyacentes. Los módulos trabajan solo con datos de manejadores, no se accede a variables globales ni (hasta donde yo sé) se llaman funciones no seguras para hilos. Por lo tanto, se cree que DBD::mysql es completamente seguro para hilos, si las bibliotecas C son seguras para hilos y usted no comparte manejadores entre

hilos.

La pregunta obvia es: ¿Son las bibliotecas C

seguras para hilos? En el caso de MySQ
L la respuesta es sí, desde MySQL 5.5 lo es.

CONSULTAS

ASÍNCRONAS

Puede hacer una única consulta asíncrona por conexión de MySQL; esto le permite enviar una consulta de larga ejecución al servidor y tener un bucle de eventos que le informe cuando esté lista. Una consulta asíncrona se inicia estableciendo el atributo 'async' a un valor verdadero en el método "do" de DBI, o en el método "prepare" de DBI. Las sentencias creadas con 'async' establecido a verdadero en prepare siempre ejecutan sus consultas de forma asíncrona cuando se llama a "execute" de DBI. El controlador también ofrece tres métodos adicionales: "mysql_async_result", "mysql_async_ready", y "mysql_fd". "mysql_async_result" devuelve lo que do o execute habrían devuelto; es decir, el número de filas afectadas. "mysql_async_ready" devuelve verdadero si "mysql_async_result" no se bloqueará, y cero en caso contrario. Ambos devuelven "undef" si ese manejador no se creó con 'async' establecido a verdadero o si una consulta asíncrona no se ha iniciado todavía. "mysql_fd" devuelve el número de descriptor de archivo para la conexión de MySQL; puede usar esto en un bucle de

eventos.

Aquí hay un ejemplo de cómo usar la interfaz de consulta

asíncrona: 
use feature 'say';
$dbh->do('SELECT SLEEP(10)', { async => 1 });
until($dbh->mysql_async_ready) {
  say 'not ready yet!';
  sleep 1;
}
