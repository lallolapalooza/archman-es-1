MULTI-HOP

Dropbear también permite especificar múltiples "saltos", separados por comas. En este caso, se establecerá una conexión con el primer host, luego se hará una conexión TCP reenviada a través de él al segundo host, y así sucesivamente. Los hosts que no sean el destino final no verán nada más que el flujo SSH cifrado. El puerto de un host puede especificarse con un acento circunflejo (por ejemplo matt@martello^44). Esta sintaxis también puede usarse con scp o rsync (especificando dbclient como el comando ssh/rsh). Un archivo puede ser "rebotado" a través de múltiples saltos SSH, por ejemplo

scp -S dbclient matt@martello,root@wrt,canyons:/tmp/dump .

Tenga en cuenta que los nombres de host son resueltos por el salto anterior (así "canyons" sería resuelto por el host "wrt") en el ejemplo anterior, de la misma manera que otros hosts con TCP reenviado con -L. Las claves de host se comprueban localmente basándose en el nombre de host dado.

CARACTERES DE FUGA

Escribir un salto de línea seguido de la secuencia de teclas ~. (tilde, punto) terminará una conexión. La secuencia ~^Z (tilde, ctrl-z) pondrá la conexión en segundo plano. Este comportamiento solo se aplica cuando se usa un PTY.

~R realizará un reintercambio de claves de sesión efímeras.

ENTORNO

DROPBEAR_PASSWORD
Se puede especificar una contraseña para usar en la autenticación remota en la variable de entorno DROPBEAR_PASSWORD. Se debe tener cuidado de que la contraseña no se exponga a otros usuarios en un sistema multiusuario, ni se almacene en archivos accesibles.
SSH_ASKPASS
dbclient puede usar un programa externo para solicitar una contraseña a un usuario. SSH_ASKPASS debe establecerse en la ruta de un programa que devuelva una contraseña en la salida estándar. Este programa solo se usará si DISPLAY está configurado y la entrada estándar no es un TTY, o si la variable de entorno SSH_ASKPASS_ALWAYS está configurada.

ARCHIVOS

~/.ssh/dropbear_config

Este es el archivo de configuración por usuario. Se admite un subconjunto muy limitado de las palabras clave de ssh_config(5), y ninguna de las funciones avanzadas. El archivo contiene pares clave-valor en una sola línea separados por espacio o '='. Las líneas vacías se ignoran. El texto que comienza con '#' es un comentario, y también se ignora.

El archivo no se tiene en cuenta si se usa una conexión multi-hop. Los valores de la línea de comandos anulan los valores respectivos del archivo.

Las palabras clave reconocidas son las siguientes. Las palabras clave no distinguen mayúsculas de minúsculas y los valores tampoco.

Host
Define las opciones que se aplicarían si este valor coincide con el host especificado en la línea de comandos. La siguiente entrada Host o EOF determina la lista de opciones aplicables.
HostName
Especifica el nombre de host real al que conectarse. Puede ser un nombre DNS o una dirección IP.
Port
Especifica el número de puerto a usar para conectarse al host remoto.
User
Especifica el nombre de usuario con el que iniciar sesión.
IdentityFile
Especifica el archivo con la clave privada usada para la autenticación por clave pública con el host remoto. El archivo debe estar en el formato Dropbear. Consulte dropbearkey(1) para generar uno. Un '~/' al inicio de la ruta se expandirá al directorio de inicio del usuario que ejecuta el comando. Una ruta que no comience con '/' se tratará como relativa al directorio de este archivo de configuración. De lo contrario, la ruta se usará tal cual.

Dado que este archivo contiene un secreto, debe tener permisos estrictos para prevenir intentos de abuso: lectura/escritura para el usuario que ejecuta el comando, y sin acceso para nadie más.

NOTAS

Si se compila con soporte zlib y si el servidor lo soporta, dbclient siempre usará compresión.
