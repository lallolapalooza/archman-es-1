DBI::Gofer::Execute(3) Documentación de Perl aportada por el usuario DBI::Gofer::Execute(3)

NOMBRE

DBI::Gofer::Execute - Ejuta peticiones Gofer y devuelve respuestas Gofer

SINOPSIS

$executor = DBI::Gofer::Execute->new( { ...config... });
$response = $executor->execute_request( $request );

DESCRIPCIÓN

Acepta un objeto DBI::Gofer::Request, ejecuta las llamadas a métodos DBI solicitadas y devuelve un objeto DBI::Gofer::Response.

Cualquier error, incluidos los errores internos 'fatales', se capturan y se convierten en un objeto DBI::Gofer::Response.

Este módulo es invocado normalmente por un módulo de transporte Gofer 'del lado del servidor'. Suelen tener nombres en el espacio de nombres ""DBI::Gofer::Transport::*"" . Ejemplos: DBI::Gofer::Transport::stream y DBI::Gofer::Transport::mod_perl.

CONFIGURACIÓN

check_request_sub

Si está definido, debe ser una referencia a una subrutina que 'verificará' la petición. Se le pasan el objeto de la petición y el ejecutor como sus únicos argumentos.

La subrutina puede devolver el objeto de petición original o morir con un mensaje de error adecuado (que se convertirá en una respuesta Gofer).

También puede construir y devolver una nueva petición que debería ejecutarse en lugar de la petición original.

check_response_sub

Si está definido, debe ser una referencia a una subrutina que 'verificará' la respuesta. Se le pasan el objeto de respuesta, el ejecutor y el objeto de petición. La subrutina puede modificar el objeto de respuesta y devolver undef, o devolver un nuevo objeto de respuesta.

Este mecanismo puede usarse, por ejemplo, para terminar el servicio si se ven errores específicos de la base de datos.

forced_connect_dsn

Si está establecido, este DSN se usa siempre en lugar del de la petición.

default_connect_dsn

Si está establecido, este DSN se usa si "forced_connect_dsn" no está establecido y la petición no contiene un DSN en sí misma.

forced_connect_attributes

Una referencia a un hash de atributos de connect() . Atributos individuales en "forced_connect_attributes" tendrán prioridad sobre los atributos correspondientes en la petición.

default_connect_attributes

Una referencia a un hash de atributos de connect() . Atributos individuales en la petición tienen prioridad sobre los atributos correspondientes en "default_connect_attributes".

max_cached_dbh_per_drh

Si está establecido, se verificarán los controladores cargados para asegurarse de que no tengan más de este número de conexiones en caché. No hay un valor por defecto. Este límite no se aplica en cada petición.

max_cached_sth_per_dbh

Si está establecido, todos los manejadores de sentencia en caché se borrarán una vez que el número de manejadores de sentencia en caché supere este límite. El valor por defecto es 1000.

forced_single_resultset

Si es verdadero, solo se obtendrá y devolverá en la respuesta el primer conjunto de resultados.

forced_response_attributes

Una referencia a una estructura de datos que puede especificar atributos extra a devolver en las respuestas.

forced_response_attributes => {
    DriverName => {
        dbh => [ qw(dbh_attrib_name) ],
        sth => [ qw(sth_attrib_name) ],
    },
},

Esto puede ser útil en casos donde el controlador no ha implementado el método private_attribute_info() y la lista de respaldo de atributos privados de DBI::Gofer::Execute no incluye el controlador o los atributos que necesita.

track_recent

Si está establecido, especifica el número de peticiones y respuestas recientes que deberían ser mantenidas por el método update_stats() para diagnóstico. Ver DBI::Gofer::Transport::mod_perl.

Ten en cuenta que este ajuste puede aumentar significativamente el uso de memoria. Úsalo con precaución.

forced_gofer_random

Habilita fallos aleatorios y/o retrasos forzados para pruebas. Ver "DBI_GOFER_RANDOM" más abajo.

PROBLEMAS ESPECÍFICOS DEL CONTROLADOR

Gofer necesita conocer cualquier atributo privado del controlador cuyos valores deberían enviarse de vuelta al cliente.

Si el controlador no soporta el método private_attribute_info() (y muy pocos lo hacen), el módulo recurre a usar algunos detalles codificados, si están disponibles, para el controlador en uso. Actualmente hay detalles codificados para los controladores mysql, Pg, Sybase y SQLite.

PRUEBAS

DBD::Gofer, DBD::Execute y los paquetes relacionados están bien probados ejecutando la suite de pruebas de DBI con DBI_AUTOPROXY configurado para enrutar todas las llamadas a DBI a través de DBD::Gofer.

Debido a que Gofer incluye mecanismos de tiempo de espera y 'reintentar en caso de error', es necesario tener alguna forma de provocar retrasos y/o errores. Esto puede hacerse a través del elemento de configuración "forced_gofer_random" o de la variable de entorno DBI_GOFER_RANDOM.

DBI_GOFER_RANDOM

El valor del elemento de configuración "forced_gofer_random" (o de la variable de entorno DBI_GOFER_RANDOM) se trata como una serie de tokens separados por comas.

Los tokens pueden ser de uno de tres tipos:

fail=R%
Establece la tasa de fallos actual a R, donde R es un porcentaje. El valor R puede ser de punto flotante, por ejemplo, "fail=0.05%". Los valores negativos para R tienen un significado especial, ver más abajo.
err=N
Establece el valor de error actual a N (en lugar del 'valor de error estándar' por defecto de DBI de 2000000000). Esto es útil cuando quieres simular un error específico.
delayN=R%
Establece la tasa de retraso aleatorio actual a R, donde R es un porcentaje, y establece la duración del retraso actual a N segundos. Los valores de R y N pueden ser de punto flotante, por ejemplo, "delay0.5=0.2%". Los valores negativos para R tienen un significado especial, ver más abajo.

Si R es un número impar (R % 2 == 1), entonces se registra un mensaje a través de warn() que será devuelto al cliente y mostrado en él.

nombremétodo
Aplica los valores actuales de fallo, error y retraso al método nombrado. Si ni el fallo ni el retraso se han establecido todavía, se genera una advertencia.

Por ejemplo:

$executor = DBI::Gofer::Execute->new( {
  forced_gofer_random => "fail=0.01%,do,delay60=1%,execute",
});

hará que el método do() falle en el 0.01% de las llamadas, y que el método execute() falle en el 0.01% de las llamadas y se retrase 60 segundos en el 1% de las llamadas.

Si el valor del porcentaje ("R") es negativo, en lugar de que los fallos se activen aleatoriamente (a través de la función rand() ), se activan a través de un número de secuencia. En otras palabras, ""fail=-20%"" significaráan cada quinta llamada fallará. Cada método tiene un número de secuencia distinto.
