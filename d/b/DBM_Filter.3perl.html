DESCRIPCIÓ

N

Este módulo proporciona una interfaz que permite aplicar filtros a los hashes vinculados asociados con archivos DBM. Se basa en los ganchos de filtro DBM que están pres

entes en todos los módulos *DB*_File incluidos con la distribución estándar de fuentes de Perl a partir de la versión 5.6.1. Además de los módulos *DB*_File distribuidos
con Perl, el módulo BerkeleyDB, disponible en CPAN, admite los ganchos de filtro DBM. Consulte perldbmfilter para obtener más detalles sobre los ganchos de filtro DBM.

¿Qué es un filtro

DBM?

Un filtro DBM permite que las claves y/o valores en un hash vinculado sean modificados por algún código definido por el usuario justo antes de que se escriban en el archivo DBM y justo después de que se lean de vuelta del archivo DBM. Por ejemplo, este fragmento de

código 
$some_hash{"abc"} =
42;

podría potencialmente activar dos filtros, uno para la escritura de la clave "abc" y otro para escribir el valor 42. De manera similar, este

fragmento 
my ($key, $value) = each
%some_hash

activará dos filtros, uno para la lectura de la clave y otro para la lectura del

valor.

Al igual que la funcionalidad existente de filtro DBM, este módulo se encarga de que la variable $_ se rellene con la clave o el valor que un filtro comprobará. Esto generalmente significa que la mayoría de los filtros DBM tienden a ser muy

cortos.

Escribir un

filtro

Los filtros pueden crearse de dos maneras

principales

Filtros

inmediatos

Un filtro inmediato le permite especificar el código del filtro a usar en el punto donde se aplica el filtro a un dbm. En este modo, los métodos Filter_*_Push esperan recibir exactamente dos

parámetros. 
my $db = tie %hash, 'SDBM_File', ...
$db->Filter_Push( Store => sub { },
                  Fetch => sub { })
;

La referencia de código asociada con "Store" se llamará antes de que cualquier clave/valor se escriba en la base de datos, y la referencia de código asociada con "Fetch" se llamará después de que cualquier clave/valor se lea de la base de

datos.

Por ejemplo, aquí hay un filtro de muestra que añade un carácter NULL final a todas las cadenas antes de que se escriban en el archivo DBM, y elimina el NULL final cuando se leen del archivo

DBM. 
my $db = tie %hash, 'SDBM_File', ...
$db->Filter_Push( Store => sub { $_ .= "\x00" ; },
                  Fetch => sub { s/\x00$// ;    })
;

NOTA

S

Mantener la integridad de ida y

vuelta

Al escribir un filtro DBM es muy importante garantizar que sea posible recuperar todos los datos que ha escrito cuando el filtro DBM está activo. En la práctica, esto significa que, sin importar qué transformación se aplique a los datos en el método Store, la operación inversa exacta debería aplicarse en el método

Fetch.

Si no proporciona una transformación inversa exacta, encontrará que código como este no se comportará como

espera. 
while (my ($k, $v) = each %hash)
{
    ...
}

Dependiendo de la transformación, encontrará que sucederá una o más de las siguientes

cosas
1
.
El bucle nunca
terminará.
2
.
Se recuperarán muy pocos
registros.
3
.
Se recuperarán
demasiados.
4
.
El bucle hará lo c
orrecto durante un
tiempo, pero fallar

No mezcle datos filtrados y no filtrados en el mismo archivo de base de

datos.

Esto es solo una reafirmación de la secció

seguro de saber lo que está haciendo, evi
