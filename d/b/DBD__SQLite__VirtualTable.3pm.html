BEST_INDE

X 
my $index_info = $vtab->BEST_INDEX($constraints, $order_by)

Este es el método más complejo de redefinir en las subclases. Este método será llamado al comienzo de una nueva consulta sobre la tabla virtual; el trabajo del método es ensamblar alguna información que será usada

a)
por el núcleo de sqlite para decidir sobre la mejor estrategia de búsqueda
b)
por el método "FILTER" del cursor para producir el subconjunto deseado de filas de la tabla virtual.

Al llamar a este método, el núcleo de SQLite le está diciendo a la tabla virtual que necesita acceder a algún subconjunto de las filas en la tabla virtual y quiere saber la forma más eficiente de hacer ese acceso. El "BEST_INDEX" método responde con información que el núcleo de SQLite puede entonces usar para conducir una búsqueda eficiente de la tabla virtual.

El método toma como entrada una lista de $constraints y una lista de $order_by instrucciones. Devuelve un hashref de propiedades de indexación, descritas más abajo; además, el método también agrega información suplementaria dentro de la entrada $constraints. Se dan explicaciones detalladas en http://sqlite.org/vtab.html#xbestindex.

Restricciones de entrada

Los elementos del $constraints arrayref corresponden a cláusulas específicas de la "WHERE ..." parte de la consulta SQL. Cada restricción es un hashref con las claves :

"col"
el índice entero de la columna en el lado izquierdo de la restricción
"op"
el operador de comparación, expresado como una cadena que contiene '=', '>', '>=', '<', '<=' o 'MATCH'.
"usable"
un booleano que indica si esa restricción es utilizable; algunas restricciones podrían no ser utilizables debido a la forma en que las tablas están ordenadas en un join.

El $constraints arrayref se usa tanto para entrada como para salida. Mientras se itera sobre el array, el método debería agregar las siguientes claves a las restricciones utilizables :

"argvIndex"
Un índice en el array @values que será pasado al método "FILTER" del cursor. En otras palabras, si la restricción actual corresponde al fragmento SQL "WHERE ... AND foo < 123 ...", y el "argvIndex" correspondiente toma el valor 5, esto significa que el "FILTER" método recibirá 123 en $values[5].
"omit"
Un booleano que le dice al núcleo de sqlite que puede omitir con seguridad verificar esa restricción antes de devolver el conjunto de resultados al programa que llama; esto significa que el método FILTER ha cumplido el trabajo de filtrado en esa restricción y no hay necesidad de hacer ninguna verificación adicional.

El "BEST_INDEX" método no recibirá necesariamente todas las restricciones de la cláusula SQL "WHERE" : por ejemplo, una restricción como "col1 < col2 + col3" no puede ser manejada en este nivel. Además, el "BEST_INDEX" podría decidir ignorar algunas de las restricciones recibidas. Es por esto que una segunda pasada sobre los resultados será realizada por el núcleo de sqlite.

Información de entrada "order_by"

El $order_by arrayref corresponde a las cláusulas "ORDER BY" en la consulta SQL. Cada entrada es un hashref con las claves :

"col"
el índice entero de la columna que está siendo ordenada
"desc"
un booleano que indica si el ordenamiento es DESCendente o ascendente

Esta información podría ser usada por algunas subclases para optimizar la estrategia de consulta; pero usualmente el núcleo de sqlite realizará otra pasada de ordenamiento una vez que todos los resultados sean recopilados.

Información Hashref devuelta por BEST_INDEX

El método debería devolver un hashref con las siguientes claves :

"idxNum"
Un entero arbitrario asociado con ese índice; esta información será devuelta a "FILTER".
"idxStr"
Una cadena arbitraria asociada con ese índice; esta información será devuelta a "FILTER".
"orderByConsumed"
Un booleano que le dice al núcleo de sqlite si la información de $order_by ha sido tomada en cuenta o no.
"estimatedCost"
Un flotante que debería ser establecido al número estimado de operaciones de acceso a disco requeridas para ejecutar esta consulta contra la tabla virtual. El núcleo de SQLite a menudo llamará a BEST_INDEX múltiples veces con diferentes restricciones, obtendrá múltiples estimaciones de costo, y luego elegirá el plan de consulta que dé la estimación más baja.
"estimatedRows"
Un entero que da el número estimado de filas devueltas por esa consulta.

OPEN

Llamado para instanciar un nuevo cursor. La implementación por defecto agrega "::Cursor" al nombre de clase actual y llama a NEW() dentro de esa clase de cursor.

_SQLITE_UPDATE

Este es el método de despacho que implementa el xUpdate() callback para tablas virtuales. La implementación por defecto aplica el algoritmo descrito en http://sqlite.org/vtab.html#xupdate para decidir llamar a "INSERT", "DELETE" o "UPDATE"; así que no hay razón para sobreescribir este método en las subclases.

INSERT

my $rowid = $vtab->INSERT($new_rowid, @values);

Este método debería ser sobrescrito en las subclases para implementar la inserción de una nueva fila en la tabla virtual. El tamaño del @values array corresponde al número de columnas declaradas a través de "VTAB_TO_DECLARE". El $new_rowid puede ser dado explícitamente, o puede ser "undef", en cuyo caso el método debe calcular un nuevo id y devolverlo como el resultado de la llamada al método.

DELETE

$vtab->INSERT($old_rowid);

Este método debería ser sobrescrito en las subclases para implementar el borrado de una fila de la tabla virtual.

UPDATE

$vtab->UPDATE($old_rowid, $new_rowid, @values);

Este método debería ser sobrescrito en las subclases para implementar una actualización de fila dentro de la tabla virtual. Usualmente $old_rowid es igual a $new_rowid, lo cual es una actualización regular; sin embargo, el rowid podría ser cambiado desde una sentencia SQL como

UPDATE table SET rowid=rowid+1 WHERE ...;

FIND_FUNCTION

$vtab->FIND_FUNCTION($num_args, $func_name);

Cuando una función usa una columna de una tabla virtual como su primer argumento, este método es llamado para ver si la tabla virtual quisiera sobrecargar la función. Los parámetros son el número de argumentos de la función, y el nombre de la función. Si no se desea sobrecarga, este método debería devolver falso. Para sobrecargar la función, este método debería devolver un coderef a la implementación de la función.

Cada tabla virtual mantiene un caché de resultados de las llamadas a FIND_FUNCTION, así que el método será llamado solo una vez para cada par "($num_args, $func_name)".

Llamado para renombrar una tabla virtual.

SAVEPOINT

$vtab->SAVEPOINT($savepoint)

Llamado para señalar a la tabla virtual que guarde su estado actual en el savepoint $savepoint (un entero).

ROLLBACK_TO

$vtab->ROLLBACK_TO($savepoint)

Llamado para señalar a la tabla virtual que regrese al estado $savepoint. Esto invalidará todos los savepoints con valores mayores que $savepoint.

Llamado para invalidar todos los savepoints con valores mayores o iguales a $savepoint.

Métodos de clase

NEW

my $cursor = $cursor_class->NEW($vtable, @args)

Instancia un nuevo cursor. La implementación por defecto simplemente devuelve un hashref bendito con las claves "vtable" y "args".

Métodos de instancia

FILTER

$cursor->FILTER($idxNum, $idxStr, @values);

Este método comienza una búsqueda de una tabla virtual.

Los argumentos $idxNum y $idxStr corresponden a valores devueltos por "BEST_INDEX" para el índice elegido. Los significados específicos de esos valores no son importantes para SQLite, siempre que "BEST_INDEX" y "FILTER" estén de acuerdo sobre cuál es ese significado.

El "BEST_INDEX" método pudo haber solicitado los valores de ciertas expresiones usando los valores de "argvIndex" de la lista $constraints . Esos Los valores se pasan a "FILTER" a través del @values array.

Si la tabla virtual contiene una o más filas que coinciden con los criterios de búsqueda, entonces el cursor debe quedar apuntando a la primera fila. Las llamadas posteriores a "EOF" deben devolver false. Si no hay filas que coincidan, entonces el cursor debe quedar en un estado que haga que "EOF" devuelva true. El motor SQLite usará los métodos "COLUMN" y "ROWID" para acceder al contenido de esa fila. El método "NEXT" se usará para avanzar a la siguiente fila.

EOF

Este método debe devolver false si el cursor apunta actualmente a una fila válida de datos, o true en caso contrario. Este método es llamado por el motor SQL inmediatamente después de cada invocación de "FILTER" y "NEXT".

NEXT

Este método avanza el cursor a la siguiente fila de un conjunto de resultados iniciado por "FILTER". Si el cursor ya está apuntando a la última fila cuando se llama a este método, entonces el cursor ya no apunta a datos válidos y una llamada posterior al método "EOF" debe devolver true. Si el cursor se avanza con éxito a otra fila de contenido, entonces las llamadas posteriores a "EOF" deben devolver false.

COLUMN

my $value = $cursor->COLUMN($idxCol);

El núcleo de SQLite invoca este método para encontrar el valor de la columna N de la fila actual. N es base cero, por lo que la primera columna es numerada 0.

ROWID

my $value = $cursor->ROWID;

Devuelve el rowid de la fila a la que el cursor está actualmente apuntando.

VÉASE TAMBIÉN

SQLite::VirtualTable es otro módulo para tablas virtuales escrito en Perl, pero diseñado para el caso de uso inverso: en lugar de iniciar un programa Perl e incrustar la biblioteca SQLite en él, el uso previsto es iniciar un programa sqlite e incrustar el intérprete de Perl en él.
