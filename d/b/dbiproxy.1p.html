DBIPROXY(1) Documentación de Perl contribuida por el usuario DBIPROXY(1)

NOMBRE

dbiproxy - Un servidor proxy para el driver DBD::Proxy

SINOPSIS

dbiproxy <opciones> --localport=<puerto>

DESCRIPCIÓN

Esta herramienta es solo una interfaz para el paquete DBI::ProxyServer. Todo lo que hace es elegir opciones de la línea de comandos y llamar a DBI::ProxyServer::main(). Ver DBI::ProxyServer para más detalles.

Las opciones disponibles incluyen:

--chroot=dir
(Solo UNIX) Después de hacer un bind(), cambia el directorio raíz al directorio dado haciendo un chroot(). Esto es útil para la seguridad, pero restringe mucho el entorno. Por ejemplo, necesitas cargar drivers de DBI en el archivo de configuración o tienes que crear enlaces duros a sockets Unix, si tus drivers los utilizan. Por ejemplo, con MySQL, un archivo de configuración podría contener las siguientes líneas: 
my $rootdir = '/var/dbiproxy';
my $unixsockdir = '/tmp';
my $unixsockfile = 'mysql.sock';
foreach $dir ($rootdir, "$rootdir$unixsockdir") {
    mkdir 0755, $dir;
}
link("$unixsockdir/$unixsockfile",
     "$rootdir$unixsockdir/$unixsockfile");
require DBD::mysql;
{
    'chroot' => $rootdir,
    ...
}

Si no sabes qué es chroot(), piensa en un servidor FTP donde solo puedes ver un árbol de directorios determinado después de iniciar sesión. Ver también las opciones --group y --user.

--configfile=file
Se asume que los archivos de configuración devuelven un único hash ref que anula los argumentos del nuevo método. Sin embargo, los argumentos de la línea de comandos, a su vez, tienen prioridad sobre el archivo de configuración. Ver la sección "ARCHIVO DE CONFIGURACIÓN" en la documentación de DBI::ProxyServer para detalles sobre el archivo de configuración.
--debug
Activa el modo de depuración. Principalmente, esto asegura que se generen mensajes de registro de nivel "debug".
--facility=mode
(Solo UNIX) Instalación a utilizar para Sys::Syslog. El valor predeterminado es daemon.
--group=gid
Después de hacer un bind(), cambia el GID real y efectivo al dado. Esto es útil si quieres que tu servidor se conecte a un puerto privilegiado (<1024), pero no quieres que el servidor se ejecute como root. Ver también la opción --user.

Los GID se pueden pasar como nombres de grupo o valores numéricos.

--localaddr=ip
Por defecto, un demonio escucha en cualquier número IP que tenga una máquina. Este atributo permite restringir el servidor al número IP dado.
--localport=port
Este atributo establece el puerto en el que escucha el demonio. Debe ser proporcionado de alguna manera, ya que no hay valor predeterminado.
--logfile=file
Por defecto, los mensajes de registro se escribirán en syslog (Unix) o en el registro de eventos (Windows NT). En otros sistemas operativos, necesitarás especificar un archivo de registro. El valor especial "STDERR" fuerza el registro a stderr. Ver Net::Daemon::Log para detalles.
--mode=modename
El servidor puede ejecutarse en tres modos diferentes, dependiendo del entorno.

Si estás ejecutando Perl 5.005 y lo compilaste para hilos, entonces el servidor creará un nuevo hilo para cada conexión. El hilo ejecutará el método Run() del servidor y luego terminará. Este modo es el predeterminado, puedes forzarlo con "--mode=threads".

Si los hilos no están disponibles, pero tienes un fork() funcional, entonces el servidor se comportará de manera similar creando un nuevo proceso para cada conexión. Este modo se usará automáticamente en ausencia de hilos o si usas la opción "--mode=fork".

Finalmente, existe un modo de conexión única: Si el servidor ha aceptado una conexión, entrará en el método Run(). No se aceptarán otras conexiones hasta que el método Run() devuelva (si el cliente se desconecta). Este modo de operación es útil si no tienes hilos ni fork(), por ejemplo en Macintosh. Para fines de depuración, puedes forzar este modo con "--mode=single".

--pidfile=file
(Solo UNIX) Si esta opción está presente, se creará un archivo PID en la ubicación dada. El valor predeterminado es no crear un archivo PID.
--user=uid
Después de hacer un bind(), cambia el UID real y efectivo al dado. Esto es útil si quieres que tu servidor se conecte a un puerto privilegiado (<1024), pero no quieres que el servidor se ejecute como root. Ver también las opciones --group y --chroot.

Los UID se pueden pasar como nombres de grupo o valores numéricos.

--version
Suprime el inicio del servidor; en su lugar, se imprimirá la cadena de versión y el programa saldrá inmediatamente.
