DESCRIPCIÓ

N

Una tabla virtual "PerlData" es una vista de base de datos sobre alguna estructura de datos dentro de un programa Perl. Los datos pueden ser leídos o modificados tanto desd

e SQL como desde Perl. Esto es útil para operaciones simples de importación/exp
ortación, para propósitos de depuración, para unir datos de diferentes fuentes, etc.

PARÁMETRO

S

Los parámetros para crear una tabla virtual "PerlData" se especifican dentro de la declaración "CREATE VIRTUAL TABLE", mezclados con declaraciones de columnas regulares, pero con un signo

'='.

El único parámetro autorizado (y obligatorio) es el que especifica la estructura de datos de Perl a la que está vinculada la tabla virtual. Debe darse como el nombre completamente calificado de una variable global; el parámetro puede ser de uno de tres tipos diferentes

:
"arrayref
s"
arrayref que contiene un arrayref para cada fila. Cada una de estas filas tendrá un tamaño equivalente al número de columnas declaradas para la tabla
virtual.
"hashref
s"
arrayref que contiene un hashref para cada fila. Las claves en cada hashref deben corresponder a las columnas declaradas para la tabla
virtual.
"colre
f"
arrayref que contiene un solo
escalar para cada fila; obvia
mente, esta es una tabl
a virtual de una sola columna.

US

O

Parte común de todos los ejemplos : declarar el

módulo

En todos los ejemplos siguientes, la parte común es que el programa Perl debe conectarse a la base de datos y luego declarar el módulo de tabla virtual "PerlData", así

: 
# connect to the database
my $dbh = DBI->connect("dbi:SQLite:dbname=$dbfile", '', '',
                        {RaiseError => 1, AutoCommit => 1});
                        # or any other options suitable to your needs

# register the module
$dbh->sqlite_create_module(perl => "DBD::SQLite::VirtualTable::PerlData")
;

Luego cree una variable global arrayref, usando "our" en lugar de "my", de modo que la variable se almacene en la tabla de símbolos del módulo

contenedor. 
package Foo::Bar; # could as well be just "main"
our $rows = [ ... ]
;

Finalmente, cree la tabla virtual y vincúlela a la variable global (aquí asumimos que @$rows contiene arrayrefs)

: 
$dbh->do('CREATE VIRTUAL TABLE temp.vtab'
        .'  USING perl(col1 INT, col2 TEXT, etc,
                       arrayrefs="Foo::Bar::rows')
;

En la mayoría de los casos, la tabla virtual será para uso temporal, que es la razón por la que este ejemplo antepone "temp." delante del nombre de la tabla : esto le indica a SQLite que limpie esa tabla cuando el manejador de base de datos sea desconectado, sin necesidad de emitir una declaración DROP

explícita.

Los nombres de las columnas (y opcionalmente sus ti

pos) se especifican en la declaración de la tab
la virtual, igual que para cualquier tabla regular.

archivos

Supongamos que queremos realizar algunas búsquedas sobre una colección de archivos, donde las restricciones de búsqueda pueden basarse en algunos de los campos devueltos por stat, como el tamaño del archivo o su última hora de modificación. Aquí hay una forma de hacerlo con una tabla virtual

: 
my @files = ... ; # list of files to inspect
# apply the L<stat> function to each file
our $file_stats = [ map { [ $_, stat $_ ] } @files];

$dbh->do(<<"");
   CREATE VIRTUAL TABLE temp.file_stats'
      USING perl(path, dev, ino, mode, nlink, uid, gid, rdev, size,
                       atime, mtime, ctime, blksize, blocks,
                 arrayrefs="main::file_stats");
# search files

Ejemplo con hashref : caracteres

unicode

Dado cualquier carácter unicode, la función "charinfo" en Unicode::UCD devuelve un hashref con varios bits de información sobre ese carácter. Así que esto puede ser explotado en una tabla virtual

: 
use Unicode::UCD 'charinfo';
our $chars = [map {charinfo($_)} 0x300..0x400]; # arbitrary subrange
# create a temporary virtual table
$dbh->do(<<""); CREATE VIRTUAL TABLE charinfo USING perl( code, name, block, script, category, hashrefs="main::chars"
) # search characters my $sth = $dbh->prepare(<<""); SELECT * FROM charinfo WHERE script='Greek' AND name LIKE '%SIGMA%'

Ejemplo con colref: SELECT WHERE ... IN ..

.

Nota: La idea para el siguiente ejemplo es tomada del archivo "test_intarray.h" en el código fuente de SQLite (http://www.sqlite.

org/src).

Una tabla virtual "colref" está diseñada para facilitar el uso de un array de valores como el lado derecho de un operador IN. La sintaxis habitual para IN es preparar una declaración como

esta: 
SELECT * FROM table WHERE x IN (?,?,?,...,?)
;

y luego vincular valores individuales a cada uno de los espacios ?; pero esto tiene la desventaja de que el número de valores debe conocerse de antemano. En su lugar, podemos almacenar valores en un array de Perl, vincular ese array a una tabla virtual, y luego escribir una declaración como

esta 
SELECT * FROM table WHERE x IN
perl_array;

Aquí es como se vería tal programa

: 
# connect to the database
my $dbh = DBI->connect("dbi:SQLite:dbname=$dbfile", '', '',
                        {RaiseError => 1, AutoCommit => 1});

# Declare a global arrayref containing the values. Here we assume
# they are taken from @ARGV, but any other datasource would do.
# Note the use of "our" instead of "my".
our $values = \@ARGV; 

# register the module and declare the virtual table
$dbh->sqlite_create_module(perl => "DBD::SQLite::VirtualTable::PerlData");
$dbh->do('CREATE VIRTUAL TABLE temp.intarray'
        .'  USING perl(i INT, colref="main::values');

# now we can SELECT from another table, using the intarray as a constraint
my $sql    = "SELECT * FROM some_table WHERE some_col IN intarray";
my $result = $dbh->selectall_arrayref($sql)
;
