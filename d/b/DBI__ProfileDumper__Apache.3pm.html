DESCRIPCIÓ

N

Este módulo conecta DBI::ProfileDumper con Apache/mod_perl. Usando este módulo puede recopilar datos de perfilado de aplica

ciones mod_perl. Funciona creando un archivo de datos DBI::ProfileDumper para cada proceso de Apache. Estos archivos s
e crean en su directorio de registros de Apache. Luego puede usar la utilidad dbiprof para analizar los archivos de perfil.

US

O

CARGANDO EL

MÓDULO

La forma más fácil de usar este módulo es simplemente establecer la variable de entorno DBI_PROFILE en su httpd.c

onf: 
PerlSetEnv DBI_PROFILE 2/DBI::ProfileDumper::
Apache

DBI se encargará de cargar y usar el módulo cuando se cree el primer identificador (handle) de

DBI.

También es posible usar este módulo estableciendo el atributo Profile de cualquier identificador de

DBI: 
$dbh->{Profile} = "2/DBI::ProfileDumper::
Apache";

Consulte DBI::ProfileDumper para más posibili

dades, y DBI::Profile para detalles comp
letos sobre el mecanismo de perfilado de DBI.

ESCRIBIENDO DATOS DE

PERFIL

Los archivos de datos de perfil se escribirán en su directorio de registros de Apache por

defecto.

El usuario bajo el que se ejecutan los procesos httpd necesitará acceso de escritura al directorio. Así que, por ejemplo, si está ejecutando los httpd secundarios como el usuario 'nobody' y usando chronolog para escribir en el directorio de registros, entonces necesitará cambiar el valor por

defecto.

Puede cambiar el directorio de destino ya sea especificando un valor "Dir" al crear el perfil (como "File" en la documentación de DBI::ProfileDumper), o puede usar la variable de entorno "DBI_PROFILE_APACHE_LOG_DIR" para cambiar eso. Por

ejemplo: 
PerlSetEnv DBI_PROFILE_APACHE_LOG_DIR /raiz_del_servidor/registro
s

Al usar

mod_perl2

Bajo mod_perl2 necesitará establecer la variable de entorno "DBI_PROFILE_APACHE_LOG_DIR", o habilitar la opción "GlobalRequest" de mod_perl2,

así: 
PerlOptions
+GlobalRequest

en la sección de configuración global que va a probar con DBI::ProfileDumper::Apache. Si no hace una de esas cosas, verá mensajes en su error_log similares

a: 
DBI::ProfileDumper::Apache on_destroy failed: Global $r object is not available. Set:
  PerlOptions +GlobalRequest in httpd.conf at ..../DBI/ProfileDumper/Apache.pm line
144

Nombrando los

archivos

El nombre de archivo por defecto se hereda de DBI::ProfileDumper a través del método filename(), pero DBI::ProfileDumper::Apache añade el pid del padre y el pid actual, separados por puntos, a ese

nombre.

Silenciando el

registro

Por defecto, se escribe un mensaje en STDERR (es decir, el archivo error_log de apache) cuando se llama a flush_to_disk() (ya sea explícitamente, o implícitamente a través de DESTROY)

.

Eso es generalmente muy útil. Si no desea el mensaje de registro puede silenciarlo estableciendo el atributo "Quiet" a

verdadero. 
PerlSetEnv DBI_PROFILE 2/DBI::ProfileDumper::Apache/Quiet:1
$dbh->{Profile} = "!Statement/DBI::ProfileDumper/Quiet:1";
$dbh->{Profile} = DBI::ProfileDumper->new(
    Path => [ '!Statement' ]
    Quiet => 1
)
;

RECOPILANDO DATOS DE

PERFIL

Una vez que tenga el módulo cargado, use su aplicación como lo haría normalmente. Detenga el servidor web cuando sus pruebas estén completas. Los archivos de datos de perfil se producirán cuando Apache salga y verá algo como esto en su

error_log: 
DBI::ProfileDumper::Apache writing to /usr/local/apache/logs/dbi.prof.2604.
2619

Ahora puede usar dbiprof para examinar los

datos: 
dbiprof /usr/local/apache/logs/dbi.prof.2604.
*

Al pasar a dbiprof una lista de todos los archivos generados, dbiprof los fus

ionará automáticamente en un solo conjunto de resultados. También puede pasar a d
biprof opciones de ordenación y consulta, consulte dbiprof para más detalles.

O

antiguos: 
rm /usr/local/apache/logs/dbi.prof.
*

ie su servid

OTROS

PROBLEMAS

Uso de

memoria

DBI::Profile puede usar mucha memoria para aplicaciones muy activas porque recopila datos de perfilado en memoria para cada consulta distinta ejecutada. Llamar a flush_to_disk() escribirá los datos actuales en disco y liberará la memoria que está usando. Por

ejemplo: 
$dbh->{Profile}->flush_to_disk() if $dbh->{Profile}
;

o, en lugar de vaciar cada vez, podría vaciar con menos

frecuencia: 
$dbh->{Profile}->
flush_to_disk()
if $dbh->{Profile
} and ++$i % 100;
