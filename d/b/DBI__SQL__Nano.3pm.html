DBI::SQL::Nano::Statement opera exactamente con una tabla. Esta tabla será abierta por herencia desde DBI::SQL::Nano::Statement y

implementará el método

"open_table" .

sub open_table ($$$$$)
{
    ...
    return Your::Table->new( \%attributes );
}

DBI::SQL::Nano::Statement_ espera que el objeto de tabla implemente una interfaz rudimentaria, al igual que espera SQL::

Statement. 
package Your::Table;
our @ISA = qw(DBI::SQL::Nano::Table);
sub drop ($$)        { ... }
sub fetch_row ($$$)  { ... }
sub push_row ($$$)   { ... }
sub push_names ($$$) { ... }
sub truncate ($$)    { ... }
sub seek ($$$$)      { ...
}

Las interfaces de la clase base son proporcionadas por DBI::SQL:

:Nano::Table_ en caso de depender de DBI::SQL::Nano o SQL::

ERRORES Y

LIMITACIONES

No hay errores conocidos en DBI::SQL::Nano::Statement. Si encuentras uno y quieres reportarlo, consulta DBI para saber cómo reportar

errores.

DBI::SQL::Nano::Statement está diseñado para proporcionar un subconjunto mínimo para ejecutar sentencias

SQL.

La limitación más importante puede ser la restricción de una tabla por sentencia. Esto implica que no se admiten JOINs y no puede haber ninguna relación de clave externa entre

tablas.

La evaluación de la cláusula where de DBI::SQL::Nano::Statement es muy lenta (SQL::Statement usa una evaluación precompilada)

.

INSERT solo puede manejar una fila por sentencia. Para insertar múltiples filas, usa marcadores de posición como se explica en

DBI.

El analizador de DBI::SQL::Nano es muy limitado y no admite ninguna sintaxis adicional como corchetes, comentarios, funciones, agregaciones

etc.

A diferencia de SQL::S

tatement, no se admite
n tablas temporales.
