NAME

dbmmanage - Gestionar archivos de autenticación de usuario en formato DBM

SYNOPSIS

dbmmanage [ encoding ] filename add|adduser|check|delete|update username [ encpasswd [ group[,group...] [ comment ] ] ]

dbmmanage filename view [ username ]

dbmmanage filename import

SUMMARY

dbmmanage se utiliza para crear y actualizar los archivos en formato DBM utilizados para almacenar nombres de usuario y contraseñas para la autenticación básica de usuarios HTTP a través de mod_authn_dbm. Los recursos disponibles desde el servidor Apache HTTP pueden restringirse únicamente a los usuarios listados en los archivos creados por dbmmanage. Este programa solo puede utilizarse cuando los nombres de usuario se almacenan en un archivo DBM. Para utilizar una base de datos de archivo plano, consulte htpasswd.

Otra herramienta para mantener una base de datos de contraseñas DBM es htdbm.

Esta página de manual solo lista los argumentos de línea de comando. Para detalles de las directivas necesarias para configurar la autenticación de usuario en httpd, consulte el manual de httpd, que forma parte de la distribución Apache o puede encontrarse en http://httpd.apache.org/.

OPTIONS

filename
El nombre del archivo en formato DBM. Normalmente sin la extensión .db, .pag o .dir.
username
El usuario para el cual se realizan las operaciones. El username no puede contener un punto y coma (:).
encpasswd
Esta es la contraseña ya hash para utilizar en los comandos update y add. Puede utilizar un guion (-) si desea que se le solicite la contraseña, pero rellenar los campos después. Además, cuando se utiliza el comando update, un punto (.) mantiene la contraseña original intacta.
group
Un grupo al cual pertenece el usuario. El nombre de grupo no puede contener un punto y coma (:). Puede utilizar un guion (-) si no desea asignar el usuario a un grupo, pero rellenar el campo de comentario. Además, cuando se utiliza el comando update, un punto (.) mantiene los grupos originales intactos.
comment
Este es el lugar para sus comentarios opacos sobre el usuario, como nombre real, dirección de correo electrónico o cosas similares. El servidor ignorará este campo.

Encodings

-d
hashing de criptografía (por defecto, excepto en Win32, Netware)
-m
hashing MD5 (por defecto en Win32, Netware)
-s
hashing SHA1
-p
texto plano (no recomendado)

Commands

add
Añade una entrada para username en filename utilizando la contraseña hash encpasswd. dbmmanage passwords.dat add rbowen foKntnEF3KSXA
adduser
Pide una contraseña y luego añade una entrada para username en filename. dbmmanage passwords.dat adduser krietz
check
Pide una contraseña y luego comprueba si username está en filename y si su contraseña coincide con la especificada. dbmmanage passwords.dat check rbowen
delete
Borra la entrada username de filename. dbmmanage passwords.dat delete rbowen
import
Lee entradas username:password (una por línea) desde STDIN y las añade a filename. Las contraseñas ya deben estar cifradas.
update
Lo mismo que el comando adduser, excepto que se asegura de que username ya existe en filename. dbmmanage passwords.dat update rbowen
view
Simplemente muestra el contenido del archivo DBM. Si especifica un username, muestra solo el registro particular. dbmmanage passwords.dat view

BUGS

Debe tener en cuenta que existen varios formatos de archivo DBM diferentes en existencia, y con toda probabilidad, existen bibliotecas para más de un formato en su sistema. Los tres ejemplos principales son SDBM, NDBM, el proyecto GNU GDBM y Berkeley DB 2. Desafortunadamente, todas estas bibliotecas utilizan diferentes formatos de archivo, y debe asegurarse de que el formato de archivo utilizado por filename es el mismo formato que dbmmanage espera ver. dbmmanage actualmente no tiene forma de determinar qué tipo de archivo DBM está mirando. Si se utiliza contra el formato incorrecto, simplemente devolverá nada, o puede crear un archivo DBM diferente con un nombre diferente, o en el peor de los casos, puede corromper el archivo DBM si estaba intentando escribir en él.

dbmmanage tiene una lista de preferencias de formato DBM, definidas por el array @AnyDBM::ISA cerca del principio del programa. Dado que prefiere el formato de archivo Berkeley DB 2, el orden en el que dbmmanage buscará las bibliotecas del sistema es Berkeley DB 2, luego NDBM, luego GDBM y luego SDBM. La primera biblioteca encontrada será la biblioteca que dbmmanage intentará utilizar para todas las transacciones de archivo DBM. Este orden es ligeramente diferente al orden estándar @AnyDBM::ISA en Perl, así como al orden utilizado por la llamada simple dbmopen() en Perl, por lo que si utiliza cualquier otra utilidad para gestionar sus archivos DBM, también debe seguir este orden de preferencia. Se debe tener cuidado similar si se utilizan programas en otros idiomas, como C, para acceder a estos archivos.

Normalmente se puede utilizar el programa file suministrado con la mayoría de sistemas Unix para ver en qué formato está un archivo DBM.
