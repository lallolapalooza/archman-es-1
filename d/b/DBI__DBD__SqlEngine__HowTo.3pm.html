        foo_bar             => 1,   # contient l'attribut bar

        foo_valid_attrs     => 1,   # ne pas permettre d'ajouter d'autres attributs valides ...

Jusqu'ici,

nous pouvons empêcher les utilisateurs d'utiliser notre pilote de base de données comme stockage de données pour n'impo

Principalement, DBI::DBD:: SqlEngine fournit l'accès via les accesseurs « new_sql_engine_meta », « get_sql_engine_meta », « get_single_table_meta », « set_single_table_meta », « set_sql_engine_meta » et « clear_sql_engine_meta ». Ces méthodes sont facilement accessibles par les utilisateurs via l'interface « $dbh->func () » fournie par DBI. Eh

    « Gestion de vos propres attributs ») :
sub init_valid_attributes
{
    my $dbh = $_[0];
    $dbh->SUPER::init_valid_attributes ();
    $dbh->{foo_valid_attrs} = {
        foo_version         => 1,   # contient la version de ce pilote
        foo_valid_attrs     => 1,   # contient les attributs valides des pilotes foo
        foo_readonly_attrs  => 1,   # contient les attributs immuables des pilotes foo
        foo_bar             => 1,   # contient l'attribut bar
        foo_baz             => 1,   # contient l'attribut baz
        foo_manager         => 1,   # contient le gestionnaire de l'instance de pilote
        foo_manager_type    => 1,   # contient la classe de gestionnaire de l'instance de pilote
        foo_meta            => 1,   # contient l'interface publique pour modifier les attributs méta de table
    };
    $dbh->{foo_readonly_attrs} = {
        foo_version         => 1,   # asegurar que nadie modifique la versión del controlador
        foo_valid_attrs     => 1,   # no permitir que se añadan más atributos válidos ...
        foo_readonly_attrs  => 1,   # ... ni que se haga mutable lo inmutable
        foo_manager         => 1,   # el gestor se establece solo internamente
        foo_meta            => 1,   # asegurar que la interfaz pública para modificar los atributos meta de la tabla sea inmutable
    };
    $dbh->{foo_meta} = "foo_tables";
    return $dbh;
}

Esto proporciona un hash vinculado en "$dbh->{foo_tables}" y un hash vinculado para los metadatos de cada tabla en "$dbh->{foo_tables}->{$table_name}". Las modificaciones de los atributos meta de la tabla se realizan usando los métodos de la

tabla: 
sub get_table_meta_attr { ... }
sub set_table_meta_attr { ...
}

Ambos métodos pueden ajustar el nombre del atributo por razones de compatibilidad, p. ej. cuando versiones anteriores del DBD permitían usar nombres diferentes para el mismo

indicador: 
my %compat_map = (
                   abc => 'foo_abc',
                   xyz => 'foo_xyz',
                 );
__PACKAGE__->register_compat_map( \%compat_map )
;

Si cualquier modificación del usuario en un atributo meta necesita la reinicialización de la estructura meta (en el caso de "DBI::DBD::SqlEngine" estos son los atributos "f_file", "f_dir", "f_ext" y "f_lockfile"), informe a DBI::DBD::SqlEngine

haciendo 
my %reset_on_modify = (
                        foo_xyz => "foo_bar",
                        foo_abc => "foo_bar",
                      );
__PACKAGE__->register_reset_on_modify( \%reset_on_modify )
;

El siguiente acceso a los metadatos de la tabla forzará a DBI::DBD::SqlEngine a rehacer todo el proceso de inicialización de

metadatos.

Cualquier acción adicional que deba realizarse puede manejarse en "table_meta_attr_changed"

: 
sub table_meta_attr_changed
{
    my ($class, $meta, $attrib, $value) = @_;
    ...
    $class->SUPER::table_meta_attr_changed ($meta, $attrib, $value);
}

Esto se hace antes de que se establezca el nuevo valor en $meta, de modo que el manejador de cambio de atrib

uto puede actuar depen
diendo del valor antiguo.
