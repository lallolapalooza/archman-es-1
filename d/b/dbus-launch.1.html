DESCRIPCIÓ

N

El comando dbus-launch se utiliza para iniciar una instancia de sesión de dbus-daemon desde un script de shell. Normalmente se llamaría desde los scripts de inicio de sesión de un usuario. A diferencia del propio demonio, dbus-launch termina, por lo que se pueden usar comillas invertidas o la construcción $() para leer información de dbus-launch

.

Sin argumentos, dbus-launch iniciará una instancia de sesión de bus e imprimirá la dirección y el PID de esa instancia en la salida

estándar.

Puede especificar un programa para ejecutar; en este caso, dbus-launch iniciará una instancia de sesión de bus, establecerá las variables de entorno apropiadas para que el programa especificado pueda encontrar el bus y luego ejecutará el programa especificado con los argumentos especificados. Vea los ejemplos a

continuación.

Si inicia un programa, dbus-launch no imprimirá la información sobre el nuevo bus en la salida

estándar.

Cuando dbus-launch imprime información del bus en la salida estándar, por defecto está en un formato simple de pares clave-valor. Sin embargo, puede solicitar varias sintaxis alternativas usando las opciones --sh-syntax, --csh-syntax, --binary-syntax o --auto-syntax. Varias de estas hacen que dbus-launch emita código shell para configurar el

entorno.

Con la opción --auto-syntax, dbus-launch examina el valor de la variable de entorno SHELL para determinar qué sintaxis de shell debe usarse. Si SHELL termina en "csh", se emitirá código compatible con csh; de lo contrario, se emitirá código de shell Bourne. En lugar de pasar --auto-syntax, puede especificar explícitamente una en particular usando --sh-syntax para la sintaxis Bourne o --csh-syntax para la sintaxis csh. En scripts, es más robusto evitar --auto-syntax y con suerte sabe en qué shell está escrito su

script.

Vea https://www.freedesktop.org/wiki/Software/dbus/ para más información sobre D-Bus. Vea también la página man de dbus-daemo

n
.

LANZAMIENTO

AUTOMÁTICO

Si DBUS_SESSION_BUS_ADDRESS no está configurado para un proceso que intente usar D-Bus, por defecto el proceso intentará invocar dbus-launch con la opción --autolaunch para iniciar un nuevo bus de sesión o encontrar la dirección del bus existente en la pantalla X o en un archivo en ~/.dbus/session-bus

/

Siempre que ocurra un lanzamiento automático, la aplicación que tuvo que iniciar un nuevo bus estará en su propio pequeño mundo; puede terminar iniciando efectivamente una sesión completamente nueva si intenta usar muchos servicios de bus. Esto puede ser subóptimo o incluso totalmente roto, dependiendo de la aplicación y de lo que intente

hacer.

Hay dos razones comunes para el lanzamiento automático. Una es ssh a una máquina remota. La solución ideal para eso sería el reenvío de DBUS_SESSION_BUS_ADDRESS de la misma manera que se reenvía DISPLAY. Mientras tanto, puede editar el archivo de configuración session.conf para que su bus de sesión escuche en TCP y configurar manualmente DBUS_SESSION_BUS_ADDRESS, si lo

desea.

La segunda razón común para el lanzamiento automático es un su a otro usuario, y la visualización de aplicaciones X que se ejecutan como el segundo usuario en la pantalla que pertenece al primer usuario. Quizás la solución ideal en este caso sería permitir que el segundo usuario se conecte al bus de sesión del primer usuario, tal como pueden conectarse a la pantalla del primer usuario. Sin embargo, no se ha codificado un mecanismo para

eso.

Siempre puede evitar el lanzamiento automático configurando manualmente DBUS_SESSION_BUS_ADDRESS. El lanzamiento automático ocurre porque la dirección predeterminada si no se establece ninguna es "autolaunch:", así que si se establece cualquier otra dirección no habrá lanzamiento automático. Sin embargo, puede incluir autolaunch en una dirección de bus de sesión explícita como respaldo, por ejemplo DBUS_SESSION_BUS_ADDRESS="something:,autolaunch:" - en ese caso, si la primera dirección no funciona, los procesos se lanzarán automáticamente. (La variable de dirección del bus contiene una lista de direcciones separadas por comas para intentar.

)

La opción --autolaunch se considera un detalle de implementación inter

no de libdbus, y de hecho hay planes para cambiarla. De todos modos, no
hay una razón real para usarla fuera de la implementación de libdbus.

OPCIONE

S

Se admiten las siguientes

opciones:

--auto-synta

x
Elige --csh-syntax o --sh-syntax basándose en la variable de entorno
SHELL.

--binary-synta

x
Escribe en stdout una dirección de bus terminada en nul, luego el PID del bus como un entero binario de tamaño sizeof(pid_t), luego el ID de ventana X del bus como un entero binario de tamaño sizeof(long). Los enteros están en el orden de bytes de la máquina, no en el orden de bytes de la red ni en ningún otro orden de bytes
canónico.

--close-stder

r
Cierra el flujo de salida de error estándar antes de iniciar el demonio D-Bus. Esto es útil si desea capturar los mensajes de error de dbus-launch pero no quiere que dbus-daemon mantenga el flujo abierto para su
aplicación.

--config-file=FILENAM

E
Pasa --config-file=FILENAME al demonio del bus, en lugar de pasarle el argumento --session. Vea la página man de
dbus-daemon

--csh-synta

x
Emite código compatible con csh para configurar variables de
entorno.

--exit-with-x1

1
Si se proporciona esta opción, se creará un proceso persistente de "niñera", y se conectará al servidor X. Si no puede hacerlo, el lanzamiento falla. Si el proceso de "niñera" pierde su conexión X, mata al demonio del bus de mensajes, desconectando a todos sus clientes (que deberían terminar en respuesta). Esto evita tener procesos de demonio residuales de una sesión X de usuario después de que la sesión X haya
terminado.

--exit-with-sessio

n
Si se proporciona esta opción, se creará un proceso persistente de "niñera", como si fuera para --exit-with-x11. Si no puede conectarse al servidor X, en su lugar monitoreará la terminal desde la que se inició dbus-launch, y si recibe un HUP en stdin, se matará al demonio del bus de mensajes. Esta opción no se recomienda, ya que consumirá la entrada de la terminal donde se inició; se proporciona principalmente para compatibilidad con versiones
anteriores.

--autolaunch=MACHINEI

D
Esta opción implica que dbus-launch debe buscar una sesión iniciada previamente y reutilizar los valores encontrados allí. Si no se encuentra ninguna sesión, iniciará una nueva sesión. Se implica la opción --exit-with-session si se da --autolaunch. Esta opción es para el uso exclusivo de libdbus, no desea usarla manualmente. Puede cambiar en el
futuro.

--sh-synta

x
Emite código compatible con shell Bourne para configurar variables de
entorno.

--versio

n
Imprime la versión de
dbus-launch

--hel

p
Imprime la info
rmación de ayuda
de dbus-launch on class="Sh">

NOTA

S

Si ejecutas dbus-launch myapp (con cualquier otra opción), dbus-daemon no saldrá cuando myapp termine: esto es porque myapp se asume que es parte de una sesión más

grande, en lugar de
una sesión en sí misma.
