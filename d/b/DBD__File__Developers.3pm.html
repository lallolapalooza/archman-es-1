DESCRIPCIÓN

Este documento describe cómo los desarrolladores de DBD pueden escribir controladores DBI basados en DBD::File. Complementa a DBI::DBD y DBI::DBD::SqlEngine::Developers, que deberías leer primero.

CLASES

Cada controlador DBI debe proporcionar un método global de paquete "driver" y tres clases relacionadas con DBI:

DBD::File::dr
Paquete del controlador, contiene los métodos que DBI invoca indirectamente a través de la interfaz DBI: 
DBI->connect ('DBI:DBM:', undef, undef, {})
# invoca
package DBD::DBM::dr;
@DBD::DBM::dr::ISA = qw( DBD::File::dr );
sub connect ($$;$$$)
{
    ...
    }

Similar para "data_sources" y "disconnect_all".

Los controladores DBI puros en Perl derivados de DBD::File normalmente no necesitan sobreescribir ninguno de los métodos proporcionados a través del paquete DBD::XXX::dr, sin embargo, si necesitas inicialización adicional en el método connect podrías necesitarlo.

DBD::File::db
Contiene los métodos que se llaman a través de los manejadores de base de datos DBI ($dbh). p. ej., 
$sth = $dbh->prepare ("select * from foo");
# devuelve la configuración f_encoding para la tabla foo
$dbh->csv_get_meta ("foo", "f_encoding");

DBD::File proporciona los métodos típicos requeridos aquí. Los desarrolladores que escriben controladores DBI basados en DBD::File necesitan sobreescribir los métodos "set_versions" y "init_valid_attributes".

DBD::File::st
Contiene los métodos para tratar con manejadores de sentencias preparadas. p. ej., 
$sth->execute () or die $sth->errstr;

DBD::File

Este es el paquete principal que contiene las rutinas para inicializar controladores DBI basados en DBD::File. Principalmente se invoca el método "DBD::File::driver" , ya sea directamente desde DBI cuando el controlador es inicializado o desde la clase derivada.

package DBD::DBM;
use base qw( DBD::File );
sub driver
{
    my ($class, $attr) = @_;
    ...
    my $drh = $class->SUPER::driver ($attr);
    ...
    return $drh;
    }

No es necesario implementar tu propio método driver siempre que no se requiera inicialización adicional (p. ej. instalar más métodos privados del controlador). No necesitas llamar a "setup_driver" ya que DBD::File se encarga de ello.

DBD::File::dr

El paquete del controlador contiene los métodos que DBI invoca indirectamente a través de la interfaz DBI (ver "DBI Class Methods" en DBI).

Los controladores DBI basados en DBD::File usualmente no necesitan implementar nada aquí, es suficiente hacer la inicialización básica:

package DBD:XXX::dr;
@DBD::XXX::dr::ISA = qw (DBD::File::dr);
$DBD::XXX::dr::imp_data_size     = 0;
$DBD::XXX::dr::data_sources_attr = undef;
$DBD::XXX::ATTRIBUTION = "DBD::XXX $DBD::XXX::VERSION by Hans Mustermann";

DBD::File::db

Este paquete define los métodos de la base de datos, que son llamados a través del manejador de base de datos DBI $dbh.

Métodos proporcionados por DBD::File:

ping
Simplemente devuelve el contenido del atributo "Active" . Sobreescribe cuando tu controlador necesita acciones más complicadas aquí.
prepare
Prepara una nueva sentencia SQL para ejecutar. Devuelve un manejador de sentencia, $sth - instancia de DBD:XXX::st. No es necesario ni recomendado sobreescribir este método.
FETCH
Obtiene un atributo de un objeto de base de datos DBI. Los atributos privados del manejador deben tener un prefijo (esto es obligatorio). Si un atributo solicitado es detectado como un atributo privado sin un prefijo válido, se añade el prefijo del controlador (escrito como $drv_prefix).

El prefijo del controlador es extraído del nombre del atributo y verificado contra "$dbh->{$drv_prefix . "valid_attrs"}" (cuando existe). Si el valor del atributo solicitado no está listado como un atributo válido, este método emite un error fatal (croak). Si el atributo es válido y de solo lectura (listado en "$dbh->{ $drv_prefix . "readonly_attrs" }" cuando existe), se devuelve una copia real del valor del atributo. Así que no es posible modificar "f_valid_attrs" desde fuera de DBD::File::db o una clase derivada.

STORE
Almacena un atributo privado de la base de datos. Los atributos privados del manejador deben tener un prefijo (esto es obligatorio). Si un atributo solicitado es detectado como un atributo privado sin un prefijo válido, se añade el prefijo del controlador (escrito como $drv_prefix). Si el manejador de base de datos tiene un atributo "${drv_prefix}_valid_attrs" - para nombres de atributos que no están listados en ese hash, este método emite un error fatal (croak). Si el manejador de base de datos tiene un atributo "${drv_prefix}_readonly_attrs", solo atributos que no están listados allí pueden ser almacenados (una vez que están inicializados). Intentar sobreescribir un atributo inmutable tal fuerza a este método a emitir un error fatal (croak).

Un ejemplo de una lista de atributos válidos puede encontrarse en "DBD::File::db::init_valid_attributes".

set_versions
Este método establece el atributo "f_version" con la versión de DBD::File.

Este método es llamado al comienzo de la fase "connect ()" .

Al sobreescribir este método, no olvides invocar al superior.

init_valid_attributes
Este método es llamado después de que el manejador de base de datos es instanciado como la primera inicialización de atributos.

"DBD::File::db::init_valid_attributes" inicializa los atributos "f_valid_attrs" y "f_readonly_attrs".

Al sobreescribir este método, no olvides invocar al superior, preferiblemente antes de hacer cualquier otra cosa. El acceso al atributo de tabla de compatibilidad debe sere inicializado aquí para permitir que DBD::File instancie el tie del mapa:

# para DBD::CSV
$dbh->{csv_meta} = "csv_tables";
# para DBD::DBM
$dbh->{dbm_meta} = "dbm_tables";
# para DBD::AnyData
$dbh->{ad_meta}  = "ad_tables";
init_default_attributes
Este método se llama después de que el gestor de base de datos sea instanciado para inicializar los atributos predeterminados.

"DBD::File::db::init_default_attributes" inicializa los atributos "f_dir", "f_meta", "f_meta_map", "f_version".

Cuando la clase de implementación derivada proporciona el atributo para validar atributos (por ejemplo, "$dbh->{dbm_valid_attrs} = {...};") o el atributo que contiene los atributos inmutables (por ejemplo, "$dbh->{dbm_readonly_attrs} = {...};"), los atributos "drv_valid_attrs", "drv_readonly_attrs", "drv_version" y "drv_meta" se añaden (cuando están disponibles) a la lista de atributos válidos e inmutables (donde "drv_" se interpreta como el prefijo del controlador).

Si "drv_meta" está establecido, un atributo con el nombre en "drv_meta" se inicializa proporcionando acceso de lectura/escritura restringido a los metadatos de las tablas usando "DBD::File::TieTables" en el primer nivel (tabla) y "DBD::File::TieMeta" para el nivel del atributo meta. "DBD::File::TieTables" usa "DBD::DRV::Table::get_table_meta" para inicializar el hash vinculado de segundo nivel en FETCH/STORE. La clase "DBD::File::TieMeta" usa "DBD::DRV::Table::get_table_meta_attr" para obtener valores de atributos (FETCH) y "DBD::DRV::Table::set_table_meta_attr" para almacenar valores de atributos (STORE). Esto le permite mapear atributos meta por razones de compatibilidad.

get_single_table_meta
get_file_meta
Recupera un atributo de la información meta de una tabla. La firma del método es "get_file_meta ($dbh, $table, $attr)". Este método es llamado por el método del gestor de base de datos inyectado "${drv_prefix}get_meta".

Mientras que get_file_meta permite que $table o $attr sea una lista de tablas o atributos a recuperar, get_single_table_meta permite solo un nombre de tabla y solo un nombre de atributo. Un nombre de tabla de '.' (punto simple) se interpreta como la tabla predeterminada y esto recuperará el atributo apropiado globalmente desde el dbh. Esto tiene las mismas restricciones que "$dbh->{$attrib}".

get_file_meta permite '+' y '*' como comodines para nombres de tabla y $table siendo una expresión regular que coincide con los nombres de tabla (evaluada sin la tabla predeterminada). El nombre de tabla '*' es todas las tablas actualmente conocidas, incluyendo la predeterminada. El nombre de tabla '+' es todos los nombres de tabla que cumplen con las restricciones de nombre de archivo ANSI (/^[_A-Za-z0-9]+$/).

La información meta de la tabla se recupera usando los métodos get_table_meta y get_table_meta_attr de la clase de tabla de la implementación.

set_single_table_meta
set_file_meta
Establece un atributo en la información meta de una tabla. La firma del método es "set_file_meta ($dbh, $table, $attr, $value)". Este método es llamado por el método del gestor de base de datos inyectado "${drv_prefix}set_meta".

Mientras que set_file_meta permite que $table sea una lista de tablas y $attr sea un hash de varios atributos a establecer, set_single_table_meta permite solo un nombre de tabla y solo un par nombre de atributo/valor.

Los caracteres comodín para el nombre de tabla son los mismos que para get_file_meta.

La información meta de la tabla se actualiza usando los métodos get_table_meta y set_table_meta_attr de la clase de tabla de la implementación.

clear_file_meta
Borra toda la información meta almacenada en caché sobre una tabla. La firma del método es "clear_file_meta ($dbh, $table)". Este método es llamado por el método del gestor de base de datos inyectado "${drv_prefix}clear_meta".

DBD::File::st

Contiene los métodos para manejar gestores de sentencias preparadas:

FETCH
Obtiene atributos del gestor de sentencias. Los atributos soportados (para una visión completa ver "Statement Handle Attributes" en DBI) son "NAME", "TYPE", "PRECISION" y "NULLABLE" en caso de que SQL::Statement se use como motor de ejecución SQL y una sentencia se prepare exitosamente. Cuando SQL::Statement tiene información adicional sobre una tabla, esa información es devuelta. De lo contrario, se usan los mismos valores predeterminados que en DBI::DBD::SqlEngine.

Este método usualmente requiere ser extendido en una implementación derivada. Ver DBD::CSV o DBD::DBM para algunos ejemplos.

DBD::File::TableSource::FileSystem

Proporciona fuentes de datos e información de tablas a nivel de controlador de base de datos y gestor de base de datos.

package DBD::File::TableSource::FileSystem;
sub data_sources ($;$)
{
    my ($class, $drh, $attrs) = @_;
    ...
    }
sub avail_tables
{
    my ($class, $drh) = @_;
    ...
    }

El método "data_sources" se llama cuando el usuario invoca cualquiera de los siguientes:

@ary = DBI->data_sources ($driver);
@ary = DBI->data_sources ($driver, \%attr);

@ary = $dbh->data_sources ();
@ary = $dbh->data_sources (\%attr);

El método "avail_tables" se llama cuando el usuario invoca cualquiera de los siguientes:

@names = $dbh->tables ($catalog, $schema, $table, $type);

$sth   = $dbh->table_info ($catalog, $schema, $table, $type);
$sth   = $dbh->table_info ($catalog, $schema, $table, $type, \%attr);
$dbh->func ("list_tables");

Cada vez que se pueda especificar un argumento "\%attr" , el atributo "sql_table_source" de este objeto "\%attr" tiene prioridad sobre el atributo $dbh o el valor predeterminado del controlador.

DBD::File::DataSource::File

package DBD::File::DataSource::File;
sub complete_table_name ($$;$)
{
    my ($self, $meta, $table, $respect_case) = @_;
    ...
    }

El método "complete_table_name" intenta mapear un nombre de archivo al nombre de tabla asociado. Es llamado con una estructura meta parcialmente llena para la tabla resultante que contiene al menos los siguientes atributos: "f_ext", "f_dir", "f_lockfile" y "sql_identifier_case".

Si se puede encontrar un mapa archivo/tabla, entonces este método establece los atributos "f_fqfn", "f_fqbn", "f_fqln" y "table_name" en la estructura meta. Si no se puede encontrar un mapa, el nombre de la tabla será undef.

package DBD::File::DataSource::File;
sub open_data ($)
{
    my ($self, $meta, $attrs, $flags) = @_;
    ...
    }

Dependiendo de los atributos establecidos en los metadatos de la tabla, se realizan los siguientes pasos. A menos que "f_dontopen" se establezca en un valor verdadero, "f_fqfn" debe contener el nombre de archivo completamente calificado para la tabla con la que trabajar (file2table asegura esto). La codificación en "f_encoding" se aplica si está establecida y el archivo se abre. Si "<f_fqln "> (completamente se establece (nombre de bloqueo completamente calificado), este archivo también se abre. Dependiendo del valor en "f_lock", se establece el bloqueo apropiado en el archivo de datos o en el archivo de bloqueo abierto.

DBD::File::Statement

Se deriva de DBI::SQL::Nano::Statement para proporcionar el siguiente método:

open_table
Implementa el método open_table requerido por SQL::Statement y DBI::SQL::Nano. Todo el trabajo para abrir los archivos pertenecientes a la tabla se maneja y parametriza en DBD::File::Table. A menos que pretenda añadir algo a la siguiente implementación, un paquete DBD::XXX::Statement vacío satisface a DBD::File. 
sub open_table ($$$$$)
{
    my ($self, $data, $table, $createMode, $lockMode) = @_;
    my $class = ref $self;
    $class =~ s/::Statement/::Table/;
    my $flags = {
        createMode => $createMode,
        lockMode   => $lockMode,
        };
    $self->{command} eq "DROP" and $flags->{dropMode} = 1;
    return $class->new ($data, { table => $table }, $flags);
    } # open_table

DBD::File::Table

Se deriva de DBI::SQL::Nano::Table y proporciona acceso físico a los datos de la tabla que están almacenados en los archivos.

bootstrap_table_meta
Inicializa una estructura de metadatos de tabla. Puede ser sobrescrito de forma segura en una clase derivada, siempre que el método "SUPER" se llame al final del método sobrescrito.

Copia los siguientes atributos de la base de datos a los metadatos de la tabla: "f_dir", "f_ext", "f_encoding", "f_lock", "f_schema" y "f_lockfile" y los hace permanentes en la tabla.

Este método debe llamarse antes de intentar mapear entre el nombre del archivo y el nombre de la tabla para asegurarse de que se utilicen el directorio, la extensión, etc., correctos.

init_table_meta
Inicializa más atributos de los metadatos de la tabla - generalmente los más costosos (p. ej., aquellos que requieren la instanciación de clases) - cuando se ha podido mapear el nombre del archivo y el nombre de la tabla.
get_table_meta
Devuelve los metadatos de la tabla. Si no existen para la tabla requerida, se inicializa uno nuevo. Cuando falla, no se devuelve nada. En caso de éxito, se devuelve el nombre de la tabla y la estructura de metadatos.
get_table_meta_attr
Devuelve un único atributo de los metadatos de la tabla. Si el nombre del atributo aparece en %compat_map, el nombre del atributo se actualiza desde allí.
set_table_meta_attr
Establece un único atributo en los metadatos de la tabla. Si el nombre del atributo aparece en %compat_map, el nombre del atributo se actualiza desde allí.
table_meta_attr_changed
Se llama cuando se modifica un atributo de los metadatos.

Si el atributo modificado requiere restablecer un atributo calculado, el atributo calculado se restablece (se elimina de la estructura de metadatos) y el indicador initialized también se elimina. La decisión se toma basándose en %register_reset_on_modify.

register_reset_on_modify
Permite que "set_table_meta_attr" restablezca metaatributos cuando se modifican atributos especiales. Para DBD::File, modificar uno de "f_file", "f_dir", "f_ext" o "f_lockfile" restablecerá "f_fqfn". DBD::DBM amplía la lista para "dbm_type" y "dbm_mldbm" para restablecer el valor de "dbm_tietype".

Si su DBD tiene valores calculados en el área de metadatos, entonces llame a "register_reset_on_modify":

my %reset_on_modify = (xxx_foo => "xxx_bar");
__PACKAGE__->register_reset_on_modify (\%reset_on_modify);
register_compat_map
Permite que "get_table_meta_attr" y "set_table_meta_attr" actualicen el nombre del atributo al actualmente preferido: 
# from DBD::DBM
my %compat_map = (dbm_ext => "f_ext");
__PACKAGE__->register_compat_map (\%compat_map);
open_file
Se llama para abrir el archivo de datos de la tabla.

Dependiendo de los atributos establecidos en los metadatos de la tabla, se realizan los siguientes pasos. A menos que "f_dontopen" esté establecido a un valor verdadero, "f_fqfn" debe contener el nombre de archivo completamente calificado para que la tabla funcione (file2table se asegura de esto). La codificación en "f_encoding" se aplica si está establecida y el archivo se abre. Si "<f_fqln "> (nombre de bloqueo completamente calificado) está establecido, este archivo también se abre. Dependiendo del valor en "f_lock", se establece el bloqueo apropiado en el archivo de datos o en el archivo de bloqueo abierto.

Después de que esto se haya hecho, una clase derivada podría añadir más pasos en un método "open_file" sobrescrito.

new
Instancia la tabla. Esto se hace en 3 pasos: 
1. obtener los metadatos de la tabla
2. abrir el archivo de datos
3. hacer bless a la estructura de datos de la tabla usando el constructor heredado new

No se recomienda sobrescribir el constructor de la clase de tabla. Encuentre un lugar razonable para añadir sus extensiones en uno de los cuatro métodos anteriores.

drop
Implementa el método abstracto de tabla para el comando "DROP" . Descarta los metadatos de la tabla después de que todos los archivos pertenecientes a la tabla se hayan cerrado y desvinculado.

Sobrescribir este método podría ser razonable en casos muy raros.

seek
Implementa el método abstracto de tabla utilizado al acceder a la tabla desde el motor. "seek" se llama cada vez que el motor usa algoritmos tontos para iterar sobre el contenido de la tabla.
truncate
Implementa el método abstracto de tabla utilizado cuando los algoritmos tontos de tabla para "UPDATE" o "DELETE" necesitan truncar el almacenamiento de la tabla después de la última fila escrita.

Debería consultar la documentación de "SQL::Eval::Table" (ver SQL::Eval) para obtener más información sobre los métodos abstractos de la clase base de la tabla que tiene que sobrescribir y una descripción de la información meta de la tabla esperada por los motores SQL.
