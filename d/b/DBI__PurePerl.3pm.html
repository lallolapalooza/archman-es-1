DBI::PurePerl(3) Documentación de Perl aportada por el usuario DBI::PurePerl(3)

NOMBRE

DBI::PurePerl -- una emulación de DBI usando perl puro (no se requiere compilación C/XS)

SINOPSIS

BEGIN { $ENV{DBI_PUREPERL} = 2 }
use DBI;

DESCRIPCIÓN

Esta es una emulación en perl puro de los internos de DBI. En casi todos los casos será mejor que utilice el DBI estándar, ya que las partes de la versión estándar escritas en C lo hacen *mucho* más rápido.

Sin embargo, si se encuentra en una situación donde no es posible instalar una versión compilada del DBI estándar, y está utilizando controladores DBD en perl puro, entonces este módulo le permite utilizar las características más comunes de DBI sin necesidad de realizar cambios en sus scripts.

ESTADO EXPERIMENTAL

DBI::PurePerl es nuevo, así que por favor trátelo como experimental pendiente de pruebas más extensas. Hasta ahora ha pasado todas las pruebas con DBD::CSV, DBD::AnyData, DBD::XBase, DBD::Sprite, DBD::mysqlPP. Por favor envíe informes de errores a Jeff Zucker en <jeff@vpservices.com> con una copia a <dbi-dev@perl.org>.

USO

El uso es el mismo que para el DBI estándar, con la excepción de que necesita establecer la variable de entorno DBI_PUREPERL si desea usar la versión PurePerl.

DBI_PUREPERL == 0 (el valor por defecto) Usar siempre DBI compilado, morir
                  si no está correctamente compilado e instalado
DBI_PUREPERL == 1 Usar DBI compilado si está correctamente compilado
                  e instalado, de lo contrario usar PurePerl
DBI_PUREPERL == 2 Usar siempre PurePerl

Puede establecer la variable de entorno en su shell (por ejemplo, con set o setenv o export, etc.) o establecerla en su script de esta manera:

BEGIN { $ENV{DBI_PUREPERL}=2 }

antes de "use DBI;".

INSTALACIÓN

En la mayoría de las situaciones, simplemente instale DBI (consulte el pod de DBI para obtener detalles).

En la situación en la que no puede instalar el propio DBI, puede copiar manualmente DBI.pm y PurePerl.pm a los directorios apropiados.

Por ejemplo:

cp DBI.pm      /usr/jdoe/mylibs/.
cp PurePerl.pm /usr/jdoe/mylibs/DBI/.

Luego agregue esto al principio de los scripts:

BEGIN {
  $ENV{DBI_PUREPERL} = 1;      # o =2
  unshift @INC, '/usr/jdoe/mylibs';
}

(¿O deberíamos quizás parchear Makefile.PL para que, si DBI_PUREPERL está establecido en 2 antes de make, el proceso de compilación normal se omita y los archivos se instalen automáticamente?)

DIFERENCIAS ENTRE DBI Y DBI::PurePerl

Atributos

Los atributos booleanos aún devuelven valores booleanos, pero los valores reales utilizados pueden ser diferentes, es decir, 0 o undef en lugar de una cadena vacía.

Algunos atributos del manejador no están soportados o tienen una funcionalidad muy limitada:

ActiveKids
InactiveDestroy
AutoInactiveDestroy
Kids
Taint
TaintIn
TaintOut

(y probablemente otros)

Traza

La funcionalidad de traza es más limitada y el código para manejar la traza solo se incrusta en DBI:PurePerl si la variable de entorno DBI_TRACE está definida. Para habilitar la traza total, puede establecer la variable de entorno DBI_TRACE como de costumbre. Pero para habilitar la traza individual del manejador usando el trace() método, también necesita establecer la variable de entorno DBI_TRACE, pero estableciéndola en 0.

Verificación de Uso de Parámetros

El DBI realiza una verificación básica del número de parámetros en las llamadas a métodos. DBI::PurePerl no lo hace.

Velocidad

DBI::PurePerl es más lento. Aunque, con algunos controladores en algunos contextos esto puede no ser muy significativo para usted.

A modo de ejemplo... el script test.pl en la distribución de fuentes de DBI tiene un simple benchmark que simplemente hace:

my $null_dbh = DBI->connect('dbi:NullP:','','');
my $i = 10_000;
$null_dbh->prepare('') while $i--;

En otras palabras, simplemente prepara una declaración, creando y destruyendo un manejador de declaración, una y otra vez. Usando el DBI real, esto se ejecuta a ~4550 manejadores por segundo, mientras que DBI::PurePerl logra ~2800 por segundo en la misma máquina (no está tan mal realmente).

Puede no soportar completamente hash()

Si desea usar el hash de tipo 1, es decir, "hash($string,1)" con DBI::PurePerl, necesitará la versión 1.56 o superior de Math::BigInt (disponible en CPAN).

No soporta preparse()

El método DBI->preparse() no está soportado en DBI::PurePerl.

No soporta DBD::Proxy

Hay un problema sutil en algún lugar que no he podido identificar. DBI::ProxyServer parece funcionar bien con DBI::PurePerl, pero DBD::Proxy no funciona al 100% (lo cual es una lástima porque eso sería mucho más útil :). Intente volver a habilitar t/80proxy.t para DBI::PurePerl para ver si el problema que queda afectará su uso.

Otros

can() - no tiene ningún comportamiento especial

Por favor, háganos saber si encuentra alguna otra diferencia entre DBI y DBI::PurePerl.
