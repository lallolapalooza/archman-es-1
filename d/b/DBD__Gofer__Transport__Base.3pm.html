NOMBRE

DBD::Gofer::Transport::Base - clase base para transportes cliente de DBD::Gofer

SINOPSIS

my $remote_dsn = "..."
DBI->connect("dbi:Gofer:transport=...;url=...;timeout=...;retry_limit=...;dsn=$remote_dsn",...)

o, habilítelo configurando la variable de entorno DBI_AUTOPROXY:

export DBI_AUTOPROXY='dbi:Gofer:transport=...;url=...'

lo que forzará que *todas* las conexiones DBI se realicen a través de ese servidor Gofer.

DESCRIPCIÓN

Esta es la clase base para todos los transportes cliente de DBD::Gofer.

ATRIBUTOS

Los atributos de transporte de Gofer se pueden especificar bien en el parámetro de atributos de la llamada al método connect(), o en la cadena DSN. Cuando se usan en la cadena DSN, los nombres de los atributos no tienen el prefijo "go_".

go_dsn

El DSN de DBI completo al que el servidor Gofer debe conectarse en su nombre.

Cuando se usa en el DSN, debe ser el último elemento en la cadena DSN.

go_timeout

Un límite de tiempo para enviar una solicitud y recibir una respuesta. Algunos controladores pueden implementar el envío y la recepción como pasos separados, en cuyo caso (actualmente) el tiempo de espera se aplica a cada uno por separado.

Si se necesita reenviar una solicitud, el tiempo de espera se reinicia para cada envío de una solicitud y recepción de una respuesta.

go_retry_limit

El número máximo de veces que se puede reintentar una solicitud. El valor predeterminado es 2.

go_retry_hook

Esta referencia de subrutina se llama, si está definida, para cada respuesta recibida donde $response->err es verdadero.

La subrutina recibe tres parámetros: el objeto de solicitud, el objeto de respuesta y el objeto de transporte.

Si devuelve un valor indefinido, se utiliza el comportamiento de reintento predeterminado. Ver "REINTENTO EN CASO DE ERROR" a continuación.

Si devuelve un valor definido pero falso, la solicitud no se reenvía.

Si devuelve un valor verdadero, la solicitud se reenvía, siempre que el número de reintentos no supere "go_retry_limit".

REINTENTO EN CASO DE ERROR

El comportamiento predeterminado de reintento en caso de error es:

- Reintentar si el error se debió a DBI_GOFER_RANDOM. Ver L<DBI::Gofer::Execute>.
- Reintentar si $request->is_idempotent devuelve verdadero. Ver L<DBI::Gofer::Request>.

No se permitirá un reintento si el número de reintentos anteriores ha alcanzado "go_retry_limit".

TRAZADO

El trazado de solicitudes y respuestas de gofer se puede habilitar configurando la variable de entorno "DBD_GOFER_TRACE". Un valor de 1 proporciona un resumen razonablemente conciso de cada solicitud y respuesta. Un valor de 2 o más proporciona un volcado detallado y voluminoso.

El rastro se escribe utilizando DBI->trace_msg() y, por lo tanto, se escribe en la salida de rastro predeterminada de DBI, que suele ser STDERR.

MÉTODOS

Esta sección está actualmente lejos de estar completa.

preferencia_reintento_respuesta

$retry = $transport->preferencia_reintento_respuesta($request, $response);

DBD::Gofer llama a la preferencia_reintento_respuesta al considerar si una solicitud debe ser reintentada después de un error.

Devuelve verdadero (desea reintentar), falso (no se debe reintentar), indefinido (sin preferencia).

Si se devuelve un valor verdadero en forma de una referencia CODE, entonces, si DBD::Gofer decide reintentar la solicitud, llama a la referencia CODE pasándole $retry_count, $retry_limit. Puede usarse para el registro y/o para implementar un comportamiento de retroceso exponencial. Actualmente, el código llamado debe salir usando "return;" para permitir extensiones futuras.
