DBI::DBD::Metadata(3) Documentación de Perl contribuida por el usuario DBI::DBD::Metadata(3)

NOMBRE

DBI::DBD::Metadata - Genera el código y los datos para algunos métodos de metadatos de DBI

SINOPSIS

La idea es extraer información de metadatos de un controlador ODBC de buena calidad y usarla para generar código y datos para usar en tu propio controlador DBI para la misma base de datos.

Para generar código para soportar el método get_info:

perl -MDBI::DBD::Metadata -e "write_getinfo_pm('dbi:ODBC:dsn-name','user','pass','Driver')"
perl -MDBI::DBD::Metadata -e write_getinfo_pm dbi:ODBC:foo_db username password Driver

Para generar código para soportar el método type_info:

perl -MDBI::DBD::Metadata -e "write_typeinfo_pm('dbi:ODBC:dsn-name','user','pass','Driver')"
perl -MDBI::DBD::Metadata -e write_typeinfo_pm dbi:ODBC:dsn-name user pass Driver

Donde "dbi:ODBC:dsn-name" es la conexión a usar para extraer los datos, y "Driver" es el nombre del controlador para el que se generará el código (el nombre del controlador se incrusta en la salida en numerosos lugares).

Generando un paquete GetInfo para un controlador

El "write_getinfo_pm" en el módulo DBI::DBD::Metadata genera un paquete DBD::Driver::GetInfo en la salida estándar.

Este método genera un paquete DBD::Driver::GetInfo a partir de la fuente de datos que especificaste en la lista de parámetros o en la variable de entorno DBI_DSN. DBD::Driver::GetInfo debería ayudar a un autor de DBD a implementar el método get_info() de DBI. Debido a que solo estás creando este paquete, es muy poco probable que DBD::Driver ya proporcione una buena implementación para get_info(). Por lo tanto, probablemente te conectarás a través de DBD::ODBC.

Una vez que estés seguro de que está produciendo datos razonablemente sensatos, normalmente deberías redirigir la salida estándar a lib/DBD/Driver/GetInfo.pm, y luego editar manualmente el resultado. No olvides actualizar tu Makefile.PL y MANIFEST para incluir esto como un archivo PM adicional que deba ser instalado.

Si te conectas a través de DBD::ODBC, deberías usar la versión 0.38 o superior;

¡Por favor, echa un vistazo crítico a los datos devueltos! Los controladores ODBC varían drásticamente en su calidad.

El generador asume que la mayoría de los valores son estáticos y coloca estos valores directamente en el hash %info. Algunos ejemplos muestran el uso de referencias a CÓDIGO y la implementación a través de subrutinas. Es muy probable que tengas que escribir subrutinas adicionales para valores que dependen del estado de la sesión o de la versión del servidor, por ejemplo, SQL_DBMS_VER.

Una posible implementación de DBD::Driver::db::get_info() podría ser:

sub get_info {
  my($dbh, $info_type) = @_;
  require DBD::Driver::GetInfo;
  my $v = $DBD::Driver::GetInfo::info{int($info_type)};
  $v = $v->($dbh) if ref $v eq 'CODE';
  return $v;
}

Por favor, reemplaza Driver (o "<foo>") con el nombre de tu controlador. Ten en cuenta que esta función stub es generada para ti por la función write_getinfo_pm, pero debes transferir manualmente el código a Driver.pm.

Generando un paquete TypeInfo para un controlador

La función "write_typeinfo_pm" en el módulo DBI::DBD::Metadata genera en la salida estándar los datos necesarios para el método type_info_all de un controlador. También proporciona implementaciones predeterminadas del método type_info_all para su inclusión en el archivo principal de implementación del controlador.

El parámetro del controlador es el nombre del controlador para el que se generarán los métodos; a efectos de los ejemplos, este será "Driver". Típicamente, el parámetro dsn tendrá el formato "dbi:ODBC:odbc_dsn", donde odbc_dsn es un DSN para una de las bases de datos del controlador. Los parámetros user y pass son los otros parámetros de conexión opcionales que se proporcionarán al método connect de DBI.

Una vez que estés seguro de que está produciendo datos razonablemente sensatos, normalmente deberías redirigir la salida estándar a lib/DBD/Driver/TypeInfo.pm, y luego editar manualmente el resultado si es necesario. No olvides actualizar tu Makefile.PL y MANIFEST para incluir esto como un archivo PM adicional que deba ser instalado.

¡Por favor, echa un vistazo crítico a los datos devueltos! Los controladores ODBC varían drásticamente en su calidad.

El generador asume que todos los valores son estáticos y coloca estos valores directamente en el hash %info.

Una posible implementación de DBD::Driver::type_info_all() podría ser:

sub type_info_all {
  my ($dbh) = @_;
  require DBD::Driver::TypeInfo;
  return [ @$DBD::Driver::TypeInfo::type_info_all ];
}

Por favor, reemplaza Driver (o "<foo>") con el nombre de tu controlador. Ten en cuenta que esta función stub es generada para ti por la función write_typeinfo_pm, pero debes transferir manualmente el código a Driver.pm.
