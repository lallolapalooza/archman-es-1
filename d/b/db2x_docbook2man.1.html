NOMBRE

docbook2man - Convierte DocBook a páginas de manual

SINOPSIS


docbook2man
[opciones] documento-xml

DESCRIPCIÓN

docbook2man convierte el documento DocBook XML proporcionado en páginas de manual. De forma predeterminada, las páginas de manual se generarán en el directorio actual.

Solo se convierte el contenido de refentry en el documento DocBook. (Para convertir contenido fuera de un refentry, se requiere la personalización de la hoja de estilo. Consulte el paquete docbook2X para obtener más detalles.)

El comando docbook2man es un script envoltorio para un proceso de conversión en dos pasos. Consulte la sección «PROCESO DE CONVERSIÓN» más abajo para obtener más detalles.

OPCIONES

Las opciones disponibles son esencialmente la unión de las opciones de db2x_xsltproc(1) y db2x_manxml(1).

A continuación se enumeran algunas opciones de uso común:

--encoding=codificación
Establece la codificación de caracteres de la salida.
--string-param parámetro=valor
Establece un parámetro de la hoja de estilo (opciones que afectan a la apariencia de la salida). Consulte «Parámetros de la hoja de estilo» más abajo para ver los parámetros que se pueden establecer.
--sgml
Acepta un documento fuente SGML como entrada en lugar de XML.
--solinks
Crea páginas de marcador para los nombres alternativos de una página de manual de salida.

PARÁMETROS DE LA HOJA DE ESTILO

uppercase-headings
Resumen. ¿Convertir los encabezados a mayúsculas?

Configuración predeterminada. 1 (booleano verdadero)

Los encabezados en el contenido de la página de manual deben o no deben convertirse a mayúsculas.

manvolnum-cite-numeral-only
Resumen. La cita de la sección de la página de manual debe usar solo el número

Configuración predeterminada. 1 (booleano verdadero)

Al citar otras páginas de manual, la sección de la página de manual se da tal cual, o se le eliminan las letras, citando solo el número de la sección (por ejemplo, la sección 3x se convierte en 3). Esta opción especifica qué estilo se utiliza.

quotes-on-literals
Resumen. ¿Mostrar comillas en los elementos literales?

Configuración predeterminada. 0 (booleano falso)

Si es verdadero, los elementos literales se muestran con comillas.

show-comments
Resumen. ¿Mostrar los elementos de comentario?

Configuración predeterminada. 1 (booleano verdadero)

Si es verdadero, los comentarios se mostrarán; de lo contrario, se suprimirán. Los comentarios aquí se refieren al elemento comment, que se renombrará remark en DocBook V4.0, y no a los comentarios XML (<-- como este -->), que no están disponibles.

function-parens
Resumen. ¿Generar paréntesis después de una función?

Configuración predeterminada. 0 (booleano falso)

Si es verdadero, el formato de un elemento <function> incluirá paréntesis generados.

xref-on-link
Resumen. ¿Debe link generar una referencia cruzada?

Configuración predeterminada. 1 (booleano verdadero)

Las páginas de manual no pueden mostrar los enlaces de hipertexto creados por link. Si se establece esta opción, la hoja de estilo generará una referencia cruzada al destino del enlace. (Esto puede reducir el desorden). De lo contrario, solo se muestra el contenido del enlace y el enlace real se ignora.

header-3
Resumen. Texto del tercer encabezado

Configuración predeterminada. (vacío)

Especifica el texto del tercer encabezado de una página de manual, normalmente la fecha de la página de manual. Si está vacío, se utiliza el contenido de la fecha del refentry.

header-4
Resumen. Texto del cuarto encabezado

Configuración predeterminada. (vacío)

Especifica el texto del cuarto encabezado de una página de manual. Si está vacío, se utiliza el contenido de refmiscinfo del refentry.

header-5
Resumen. Texto del quinto encabezado

Configuración predeterminada. (vacío)

Especifica el texto del quinto encabezado de una página de manual. Si está vacío, se utiliza el «nombre del manual», es decir, el título del libro o del contenedor de referencia.

default-manpage-section
Resumen. Sección de la página de manual predeterminada

Configuración predeterminada. 1

El documento fuente normalmente indica las secciones a las que debe pertenecer cada página de manual (con manvolnum en refmeta). En caso de que el documento fuente no indique las secciones de las páginas de manual, esta opción especifica la predeterminada.

custom-localization-file
Resumen. URI del documento XML que contiene datos de localización personalizados

Configuración predeterminada. (vacío)

Este parámetro especifica el URI de un documento XML que describe las traducciones de texto (y otra información específica de la configuración regional) que la hoja de estilo necesita para procesar el documento DocBook.

Las traducciones de texto a las que apunta este parámetro siempre anulan las traducciones de texto predeterminadas (del parámetro interno localization-file). Si una traducción en particular no está presente aquí, se utiliza la traducción predeterminada correspondiente como alternativa.

Este parámetro se utiliza principalmente para cambiar ciertos caracteres de puntuación utilizados en el formato del documento fuente. La configuración de los caracteres de puntuación a menudo es específica del documento fuente, pero también puede depender de la configuración regional.

Para no usar traducciones de texto personalizadas, deje este parámetro como una cadena vacía.

custom-l10n-data
Resumen. Documento XML que contiene datos de localización personalizados

Configuración predeterminada. document($custom-localization-file)

Este parámetro especifica el documento XML que describe las traducciones de texto (y otra información específica de la configuración regional) que la hoja de estilo necesita para procesar el documento DocBook.

Este parámetro es interno de la hoja de estilo. Para apuntar a un documento XML externo con un URI o un nombre de archivo, debe usar el parámetro custom-localization-file en su lugar.

Sin embargo, dentro de una hoja de estilo personalizada (no en la línea de comandos), este parámetro se puede establecer en la expresión XPath document(''), lo que hará que se lean las traducciones personalizadas incrustadas directamente dentro de la hoja de estilo personalizada.

author-othername-in-middle
Resumen. ¿Es othername en author un segundo nombre?

Configuración predeterminada. 1

Si es verdadero, el othername de un autor aparece entre el firstname y el surname. De lo contrario, othername se suprime.

EJEMPLOS

$ docbook2man --solinks manpages.xml
$ docbook2man --solinks --encoding=utf-8//TRANSLIT manpages.xml
$ docbook2man --string-param header-4="Free Recode 3.6" document.xml
.fi

PROCESO DE CONVERSIÓN

Conversión a páginas de manual

Los documentos DocBook se convierten en páginas de manual en dos pasos:

1.
La fuente DocBook se convierte mediante una hoja de estilo XSLT en un formato XML intermedio, Man-XML.

Man-XML es más simple que DocBook y más cercano al formato de la página de manual; está diseñado para facilitar el trabajo de las hojas de estilo.

La hoja de estilo para este propósito está en xslt/man/docbook.xsl. Para la portabilidad, siempre debe referenciarse mediante la siguiente URI:

http://docbook2x.sourceforge.net/latest/xslt/man/docbook.xsl

Ejecute esta hoja de estilo con db2x_xsltproc(1).

Personalización. También puede personalizar la salida creando su propia hoja de estilo XSLT — cambiando parámetros o añadiendo nuevas plantillas — e importando xslt/man/docbook.xsl.

2.
Man-XML se convierte a las páginas de manual reales mediante db2x_manxml(1).

El docbook2man comando realiza automáticamente ambos pasos, pero si ocurre algún problema, puede ver los errores con más claridad si realiza cada paso por separado:

$ db2x_xsltproc -s man mydoc.xml -o mydoc.mxml
$ db2x_manxml mydoc.mxml
.fi
Las opciones para la hoja de estilo de conversión se describen en la referencia de hojas de estilo de páginas de manual.
Conversión pura con XSLT. 
Una alternativa al db2x_manxml script de Perl es la hoja de estilo XSLT en 
xslt/backend/db2x_manxml.xsl.
Esta hoja de estilo realiza una función similar de convertir Man-XML a páginas de manual reales.
Es útil si desea una solución pura de XSLT para la conversión de páginas de manual.
Por supuesto, la calidad de la conversión usando esta hoja de estilo nunca será tan buena como la del db2x_manxmlde Perl, y se ejecuta más lento. 
En particular, la versión pura de XSLT actualmente no soporta tablas en las páginas de manual, pero su contraparte en Perl sí lo hace.

Conversión de conjunto de caracteres

Al traducir XML a formatos heredados basados en ASCII con un soporte pobre para Unicode, como páginas de manual y Texinfo, siempre existe el problema de que los caracteres Unicode en el documento de origen también deben traducirse de alguna manera.

Una conversión de conjunto de caracteres directa desde Unicode no es suficiente, porque el conjunto de caracteres de destino, usualmente US-ASCII o ISO Latin-1, no contiene caracteres comunes como guiones y comillas direccionales que se usan ampliamente en documentos XML. Pero los formateadores de documentos (man y Texinfo) permiten la entrada de tales caracteres mediante una escape de marcado: por ejemplo, \(lq para la comilla direccional izquierda “. Y si no hay disponible un escape a nivel de marcado, podría usarse una transliteración ASCII: por ejemplo, usando el signo menor que ASCII < para el signo de comilla angular ⟨.

Así, el problema del carácter Unicode puede resolverse en dos pasos:

1.
utf8trans(1), un programa incluido en docbook2X, mapea caracteres Unicode a escapes a nivel de marcado o transliteraciones.

Dado que no existe necesariamente un mapeo fijo y oficial de caracteres Unicode, utf8trans puede leer mapeos de caracteres modificables por el usuario expresados en archivos de texto y aplicarlos. (A diferencia de la mayoría de los convertidores de conjuntos de caracteres.)

En charmaps/man/roff.charmap y charmaps/man/texi.charmap hay mapas de caracteres que pueden usarse para la conversión a páginas de manual y Texinfo. Los programas db2x_manxml(1) y db2x_texixml(1) aplicarán estos mapas de caracteres, u otro mapa de caracteres especificado por el usuario, automáticamente.

2.
El resto del texto Unicode se convierte a algún otro conjunto de caracteres (codificación). Por ejemplo, un documento en francés con caracteres acentuados (como é) podría convertirse a ISO Latin 1.

Este paso se aplica después del utf8trans mapeo de caracteres, usando la iconv(1) herramienta de conversión de codificación. Tanto db2x_manxml(1) como db2x_texixml(1) pueden llamar a iconv(1) automáticamente al producir su salida.

NOTAS

El docbook2man o el docbook2texi comando descrito en esta página de manual proviene del paquete docbook2X. No debe confundirse con el comando del mismo nombre del paquete obsoleto docbook-utils.

LIMITACIONES

•
Internamente hay un largo pipeline de programas por el que pasa su documento. Si cualquier segmento del pipeline falla (aunque sea trivialmente, como por opciones de programa mal escritas), los errores resultantes pueden ser difíciles de descifrar — en ese caso, intente ejecutar los componentes de docbook2X por separado.
