Se añadió la macro DBIh_CLEAR_ERROR(imp_xxh).
El DBI ahora hace EXPORT_OK de algunas funciones de utilidad: neat($value),
neat_list(@values) y dump_results($sth).
Se mejoró ligeramente el script de prueba mínimo t/min.t en un esfuerzo por ayudar a
acotar los pocos volcados de memoria (core dumps) que algunos portadores aún reportan.
Se renombró readblob a blob_read (el nombre antiguo sigue funcionando pero emite una advertencia).
Se añadió el método blob_copy_to_file por defecto.
Se añadió el método $sth = $dbh->tables. Este devuelve un $sth para una consulta
que tiene estas columnas: TABLE_CATALOGUE, TABLE_OWNER, TABLE_NAME,
TABLE_TYPE, REMARKS en ese orden. La columna TABLE_CATALOGUE
debe ignorarse por ahora.

Cambios en DBI 0.64 - 23 oct 1995

Se corrigió el problema de 'disconnect invalidates 1 associated cursor(s)' (la desconexión invalida 1 cursor(es) asociado(s)).
Los controladores que usan las macros DBIc_ACTIVE_on/off() no deberían necesitar cambios
además de comprobar DBIc_ACTIVE_KIDS() en lugar de DBIc_KIDS().
Se corrigió un posible volcado de memoria (core dump) en dbih_clearcom durante la destrucción global.

Cambios en DBI 0.63 - 01 sep 1995

Actualización menor. Se corrigió un error de memoria no inicializada en el manejo de

Cambios en DBI 0.62 - 26 ago 1995

Se añadió el método de redirección de métodos $h->func(..., $method_name).
Esta es ahora la forma oficial de llamar a métodos privados del controlador
que no forman parte del estándar del DBI. Por ejemplo:
    @ary = $sth->func('ora_types');
También se puede usar para llamar a métodos existentes. Tiene un costo muy bajo.
Las columnas de $sth->bind_col ahora comienzan desde 1 (no 0) para coincidir con SQL.
$sth->bind_columns ahora toma un parámetro de atributo inicial (o undef),
por ejemplo, $sth->bind_columns($attribs, \$col1 [, \$col2 , ...]);
Se añadió la útil macro DBD_ATTRIBS_CHECK para verificar atributos en XS.
Se añadieron las útiles macros DBD_ATTRIB_GET_SVP, DBD_ATTRIB_GET_BOOL y
DBD_ATTRIB_GET_IV para manejar atributos.
Se corrigió STORE para NUM_OF_FIELDS y NUM_OF_PARAMS.
Se añadió FETCH para NUM_OF_FIELDS y NUM_OF_PARAMS.
El despachado ya no se molesta en llamar a _untie().
Arranque más rápido mediante cambios en install_method/_add_dispatch.

Cambios en DBI 0.61 - 22 ago 1995

Se añadió $sth->bind_col($column, \$var [, \%attribs ]);
Este método permite que una variable perl se actualice directa y automáticamente
cuando se obtiene una fila. No requiere soporte del controlador
(si el controlador ha sido escrito para usar DBIS->get_fbav).
Actualmente \%attribs no se usa.
Se añadió $sth->bind_columns(\$var [, \$var , ...]);
Este método es un atajo para bind_col que vincula todas las
columnas de una consulta de una sola vez (sin atributos). También
no requiere soporte del controlador.
Se añadió $sth->bind_param($parameter, $var [, \%attribs ]);
Este método permite especificar atributos cuando se vinculan valores
a marcadores de posición (placeholders). También permite que la vinculación
ocurra lejos del método execute para mejorar la eficiencia de execute.
El DBI no proporciona una implementación predeterminada de esto.
Consulta el módulo DBD::Oracle para un ejemplo detallado.
El DBI ahora proporciona implementaciones predeterminadas tanto de fetch como
de fetchrow. Cada una está escrita en términos de la otra. Se espera que un controlador
implemente al menos una de ellas.
Más cambios de macros y estructuras varias en DBDXS.h. ¡Lo siento!
Las definiciones antiguas de dbihcom han desaparecido. Todos los campos tienen macros.
El tipo imp_xxh_t se usa ahora dentro del DBI así como en los controladores.
Los controladores deben establecer DBIc_NUM_FIELDS(imp_sth) y DBIc_NUM_PARAMS(imp_sth).
test.pl incluye una prueba trivial de bind_param y bind_columns.

Cambios en DBI 0.60 - 17 ago 1995

Esta versión tiene cambios de código significativos pero mucho menos
drásticos que la versión anterior. El nuevo mecanismo de manejo de datos de implementadores
ha madurado significativamente (no te desanimes
por todos los typedefs de estructuras en DBIXS.h, están ahí solo para
facilitar las cosas a los controladores manteniendo la seguridad de tipos).
El DBI ahora incluye dos nuevos métodos:
do            $dbh->do($statement)
Este método prepara, ejecuta y finaliza una declaración. Está
diseñado para usarse en la ejecución de declaraciones no-select de una sola vez
donde no hay beneficio en reutilizar un manejador de declaración preparada.
fetch         $array_ref = $sth->fetch;
Este método es el nuevo método de obtención de filas de 'nivel más bajo'.
El método anterior @row = $sth->fetchrow ahora llama por defecto al método
fetch y expande la referencia de array devuelta.
El DBI ahora proporciona funciones de FETCH y STORE de atributos de respaldo
que los controladores deben llamar si no reconocen un atributo.

Estudia DBIXS.h del DBI y Oracle.xs etc de DBD::Oracle.
¡Habrá más cambios en la interfaz pero nada
tan drástico como en estas dos últimas versiones! (Espero :-)
