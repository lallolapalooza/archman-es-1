DESCRIPCIÓN

Este documento proporciona una guía paso a paso sobre cómo crear un nuevo driver basado en "DBD::File". Se espera que haya leído cuidadosamente la documentación de DBI y que esté familiarizado con DBI::DBD y haya leído y comprendido DBD::ExampleP.

Este documento se dirige a desarrolladores experimentados que estén realmente seguros de que necesitan invertir tiempo al escribir un nuevo Driver de DBI. Escribir un Driver de DBI no es un proyecto de fin de semana ni una tarea fácil para programadores aficionados después del trabajo. Espere uno o dos meses-hombre de tiempo para empezar.

Aquellos que todavía están leyendo, deberían poder recitar las reglas de "CREACIÓN DE UN NUEVO DRIVER" en DBI::DBD.

Por supuesto, DBD::File es un DBI::DBD::SqlEngine y seguramente ha leído DBI::DBD::SqlEngine::HowTo antes de continuar aquí.

CREACIÓN DE CLASES DE DRIVER

¿Tiene una entrada en el registro de DBD de DBI? Para esta guía, se asume un prefijo de "foo_".

Esqueleto de ejemplo

package DBD::Foo;
use strict;
use warnings;
use base qw(DBD::File);
use DBI ();
our $VERSION = "0.001";
package DBD::Foo::dr;
our @ISA = qw(DBD::File::dr);
our $imp_data_size = 0;
package DBD::Foo::db;
our @ISA = qw(DBD::File::db);
our $imp_data_size = 0;
package DBD::Foo::st;
our @ISA = qw(DBD::File::st);
our $imp_data_size = 0;
package DBD::Foo::Statement;
our @ISA = qw(DBD::File::Statement);
package DBD::Foo::Table;
our @ISA = qw(DBD::File::Table);
1;

Pequeño, ¿eh? Y todo lo que tiene ahora es un DBD llamado foo que será capaz de manejar tablas temporales, siempre que utilice SQL::Statement. En entornos de DBI::SQL::Nano, este DBD no puede hacer nada.

Empezar de nuevo

Basado en DBI::DBD::SqlEngine::HowTo, ahora tenemos un driver que podría hacer cosas básicas. Por supuesto, debería derivar de DBD::File en lugar de DBI::DBD::SqlEngine, ¿no?

DBD::File extiende DBI::DBD::SqlEngine para manejar cualquier tipo de archivo. En principio, las únicas extensiones requeridas son para la clase de tabla:

package DBD::Foo::Table;
sub bootstrap_table_meta
{
    my ( $self, $dbh, $meta, $table ) = @_;
    # inicializar todos los atributos $meta que puedan ser relevantes para
    # file2table
    return $self->SUPER::bootstrap_table_meta($dbh, $meta, $table);
}
sub init_table_meta
{
    my ( $self, $dbh, $meta, $table ) = @_;
    # llamado después de que $meta contenga los resultados de file2table
    # inicializar todos los atributos $meta faltantes
    $self->SUPER::init_table_meta( $dbh, $meta, $table );
}

En caso de que "DBD::File::Table::open_file" no abra los archivos como el driver lo necesita, ¡anúlalo!

sub open_file
{
    my ( $self, $meta, $attrs, $flags ) = @_;
    # asegurarse de que $meta->{f_dontopen} esté establecido
    $self->SUPER::open_file( $meta, $attrs, $flags );
    # ahora haga lo que sea necesario
}

Combinado con los métodos implementados utilizando la guía de SQL::Statement::Embed, la tabla está completamente funcional y se podría intentar empezar de nuevo.

Comodidad del usuario

"DBD::File" desde 0.39 consolida todos los metadatos persistentes de una tabla en una única estructura almacenada en "$dbh->{f_meta}". Con la versión "DBD::File" 0.41 y la versión de "DBI::DBD::SqlEngine" 0.05, esta consolidación se traslada a DBI::DBD::SqlEngine. Sigue siendo el atributo "$dbh->{$drv_prefix . "_meta"}" el que se encarga, así que lo que aprendió aquí antes, sigue siendo válido.

sub init_valid_attributes
{
    my $dbh = $_[0];
    $dbh->SUPER::init_valid_attributes ();
    $dbh->{foo_valid_attrs} = { ... };
    $dbh->{foo_readonly_attrs} = { ...  };
    $dbh->{foo_meta} = "foo_tables";
    return $dbh;
}

Vea las actualizaciones en "Comodidad del usuario" en DBI::DBD::SqlEngine::HowTo.

Pruebas

Ahora debería tener su propio driver basado en DBD::File. Fácil, ¿no? ¿Pero funciona bien? Pruébelo escribiendo pruebas y recuerde usar dbd_edit_mm_attribs de DBI::DBD para asegurar la prueba incluso de los casos raros.
