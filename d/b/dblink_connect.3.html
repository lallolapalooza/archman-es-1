DBLINK_CONNECT(3) Documentación de PostgreSQL 18.1 DBLINK_CONNECT(3)

NOMBRE

dblink_connect - abre una conexión persistente a una base de datos remota

SINOPSIS

dblink_connect(text connstr) returns text
dblink_connect(text connname, text connstr) returns text

DESCRIPCIÓN

dblink_connect() establece una conexión a una base de datos PostgreSQL remota. El servidor y la base de datos a contactar se identifican a través de una cadena de conexión libpq estándar. Opcionalmente, se puede asignar un nombre a la conexión. Se pueden mantener abiertas múltiples conexiones con nombre a la vez, pero solo se permite una conexión sin nombre a la vez. La conexión persistirá hasta que se cierre o hasta que termine la sesión de la base de datos.

La cadena de conexión también puede ser el nombre de un servidor externo existente. Se recomienda usar el wrapper de datos externos dblink_fdw al definir el servidor externo. Consulte el siguiente ejemplo, así como CREATE SERVER ( CREATE_SERVER(7) ) y CREATE USER MAPPING ( CREATE_USER_MAPPING(7) ).

ARGUMENTOS

connname

El nombre a usar para esta conexión; si se omite, se abrirá una conexión sin nombre, reemplazando cualquier conexión sin nombre existente.

connstr

Cadena de información de conexión estilo libpq, por ejemplo hostaddr=127.0.0.1 port=5432 dbname=mydb user=postgres password=mypasswd options=-csearch_path=. Para más detalles consulte la Sección 32.1.1. Alternativamente, el nombre de un servidor externo.

VALOR DE RETORNO

Devuelve el estado, que siempre es OK (ya que cualquier error hace que la función lance un error en lugar de devolver).

NOTAS

Si usuarios no confiables tienen acceso a una base de datos que no ha adoptado un patrón seguro de uso de esquemas, comience cada sesión eliminando los esquemas escribibles públicamente de search_path. Uno podría, por ejemplo, añadir options=-csearch_path= a connstr. Esta consideración no es específica de dblink; se aplica a todas las interfaces para ejecutar comandos SQL arbitrarios.

El wrapper de datos externos dblink_fdw tiene una opción booleana adicional use_scram_passthrough que controla si dblink usará la autenticación SCRAM de paso para conectarse a la base de datos remota. Con la autenticación SCRAM de paso, dblink usa secretos cifrados con SCRAM en lugar de contraseñas de usuario en texto plano para conectarse al servidor remoto. Esto evita almacenar contraseñas de usuario en texto plano en los catálogos del sistema de PostgreSQL. Consulte la documentación de la opción equivalente use_scram_passthrough de postgres_fdw para más detalles y restricciones.

Solo los superusuarios pueden usar dblink_connect para crear conexiones que no utilicen autenticación por contraseña, SCRAM de paso ni autenticación GSSAPI. Si los no superusuarios necesitan esta capacidad, usen dblink_connect_u en su lugar.

No es aconsejable elegir nombres de conexión que contengan signos de igual, ya que esto abre un riesgo de confusión con las cadenas de información de conexión en otras funciones de dblink.

EJEMPLOS

SELECT dblink_connect('dbname=postgres options=-csearch_path=');
 dblink_connect
----------------
 OK
(1 row)
SELECT dblink_connect('myconn', 'dbname=postgres options=-csearch_path=');
 dblink_connect
----------------
 OK
(1 row)
-- Funcionalidad del WRAPPER DE DATOS EXTERNOS
-- Nota: las conexiones locales que no usan SCRAM de paso requieren autenticación
--       por contraseña para que esto funcione correctamente. De lo contrario, recibirá
--       el siguiente error de dblink_connect():
--       ERROR:  password is required
--       DETAIL:  Non-superuser cannot connect if the server does not request a password.
--       HINT:  Target server's authentication method must be changed.
CREATE SERVER fdtest FOREIGN DATA WRAPPER dblink_fdw OPTIONS (hostaddr '127.0.0.1', dbname 'contrib_regression');
CREATE USER regress_dblink_user WITH PASSWORD 'secret';
CREATE USER MAPPING FOR regress_dblink_user SERVER fdtest OPTIONS (user 'regress_dblink_user', password 'secret');
GRANT USAGE ON FOREIGN SERVER fdtest TO regress_dblink_user;
GRANT SELECT ON TABLE foo TO regress_dblink_user;
\set ORIGINAL_USER :USER
\c - regress_dblink_user
SELECT dblink_connect('myconn', 'fdtest');
 dblink_connect
----------------
 OK
(1 row)
