NOMBRE

db2x_xsltproc - Envoltorio de invocación del procesador XSLT

SINOPSIS


db2x_xsltproc
[opciones] documento-xml

DESCRIPCIÓN

db2x_xsltproc invoca el procesador XSLT 1.0 para docbook2X.

Este comando aplica la hoja de estilos XSLT (normalmente dada por la opción --stylesheet) al documento XML en el archivo documento-xml. El resultado se escribe en la salida estándar (a menos que se cambie con --output).

Para leer el documento XML de origen desde la entrada estándar, especifique - como documento de entrada.

OPCIONES

--version
Muestra la versión de docbook2X.

OPCIONES DE SALIDA DE TRANSFORMACIÓN

--output archivo, -o archivo
Escribe la salida en el archivo (o URI) dado, en lugar de la salida estándar.

OPCIONES DE DOCUMENTO DE ORIGEN

--xinclude, -I
Procesa directivas XInclude en el documento de origen.
--sgml, -S
Indica que el documento de entrada es SGML en lugar de XML. Necesitas establecer esta opción si documento-xml es en realidad un archivo SGML.

El análisis SGML se implementa mediante la conversión a XML a través de sgml2xml(1) del paquete SP (o osx(1) del paquete OpenSP). Todos los nombres de etiquetas en el archivo SGML se normalizarán a minúsculas (es decir, se usa la opción -xlower de sgml2xml(1)). Los atributos ID están disponibles para la hoja de estilos (es decir, la opción -xid). Además, cualquier entidad SDATA ISO utilizada en el documento SGML se convierte automáticamente a sus equivalentes Unicode XML. (Esto se hace mediante un filtro sed).

La codificación del documento SGML, si no es us-ascii, debe especificarse con las variables de entorno estándar de SP: SP_CHARSET_FIXED=1 SP_ENCODING=codificación. (Tenga en cuenta que los archivos XML especifican su codificación con la declaración XML <?xml version="1.0" encoding="codificación" ?> en la parte superior del archivo).

Las opciones de conversión anteriores no se pueden cambiar. Si desea opciones de conversión diferentes, debe invocar sgml2xml(1) manualmente y luego pasar los resultados de esa conversión a este programa.

OPCIONES DE RECUPERACIÓN

--catalogs archivos-de-catálogo, -C archivos-de-catálogo
Especifica catálogos XML adicionales para resolver Identificadores Públicos Formales o URIs. No se admiten catálogos SGML.

Estos catálogos *no* se utilizan para analizar un documento SGML bajo la opción --sgml. Utilice la variable de entorno SGML_CATALOG_FILES en su lugar para especificar los catálogos para analizar el documento SGML.

--network, -N
db2x_xsltproc normalmente se negará a cargar recursos externos de la red, por razones de seguridad. Si desea cargar desde la red, establezca esta opción.

Normalmente querrá haber instalado localmente los DTDs y otros archivos relevantes, y haber configurado catálogos para ellos, en lugar de cargarlos automáticamente desde la red.

OPCIONES DE HOJA DE ESTILOS

--stylesheet archivo, -s archivo
Especifica el nombre del archivo (o URI) de la hoja de estilos a utilizar. Los valores especiales man y texi se aceptan como abreviaturas, para especificar que documento-xml está en DocBook y debe convertirse a páginas de manual (man pages) o Texinfo (respectivamente).
--param nombre=expresión, -p nombre=expresión
Añade o modifica un parámetro en la hoja de estilos. nombre es un nombre de parámetro XSLT y expresión es una expresión XPath que evalúa al valor deseado para el parámetro. (Esto significa que las cadenas deben entrecomillarse, *además* de entrecomillar los argumentos del shell; use --string-param para evitar esto).
--string-param nombre=cadena, -g nombre=cadena
Añade o modifica un parámetro con valor de cadena en la hoja de estilos.

La cadena debe estar codificada en UTF-8 (independientemente de la codificación de caracteres de la configuración regional).

DEPURACIÓN Y PERFILADO

--debug, -d
Muestra, en la salida de error estándar, registros de lo que está sucediendo durante la transformación XSL.
--nesting-limit n, -D n
Cambia el número máximo de llamadas anidadas a plantillas XSL, utilizado para detectar posibles bucles infinitos. Si no se especifica, el límite es 500 (valor predeterminado de libxslt).
--profile, -P
Muestra información de perfilado: el número total de llamadas a cada plantilla en la hoja de estilos y el tiempo empleado para cada una. Esta información se envía a la salida de error estándar.
--xslt-processor procesador, -X procesador
Selecciona el procesador XSLT subyacente utilizado. Las opciones posibles para procesador son: libxslt, saxon, xalan-j.

El procesador predeterminado es el que se configuró cuando se compiló docbook2X. Se recomienda libxslt (porque es ligero y rápido), pero SAXON es mucho más robusto y sería más útil al depurar hojas de estilos.

Todos los procesadores tienen el soporte de catálogos XML habilitado. (docbook2X lo requiere). Pero tenga en cuenta que no todas las opciones anteriores funcionan con procesadores distintos del de libxslt.

AMBIENTE

XML_CATALOG_FILES
Especifica catálogos XML. Si no se especifica, se carga el catálogo estándar (/etc/xml/catalog), si está disponible.
DB2X_XSLT_PROCESSOR
Especifica el procesador XSLT a utilizar. El efecto es el mismo que la opción --xslt-processor. El uso principal de esta variable es permitirle probar rápidamente diferentes procesadores XSLT sin tener que añadir --xslt-processor a cada script o archivo make en su sistema de compilación de documentación.

CONFORME A

Lenguaje de Hojas de Estilo XML – Transformaciones (XSLT), versión 1.0 ⟨http://www.w3.org/TR/xslt⟩ , una Recomendación del W3C.

NOTAS

En sus versiones anteriores (< 0.8.4), docbook2X requería extensiones XSLT para ejecutarse, y db2x_xsltproc era un procesador especial basado en libxslt que tenía estas extensiones compiladas. Cuando se eliminó el requisito de extensiones XSLT, db2x_xsltproc se convirtió en un script de Perl que traduce las opciones de db2x_xsltproc para que se ajusten al formato aceptado por el xsltproc(1) estándar que viene con libxslt.
