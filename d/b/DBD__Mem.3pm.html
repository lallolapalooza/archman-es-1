DBD::Mem(3) Documentación de Perl contribuida por el usuario DBD::Mem(3)

NOMBRE

DBD::Mem - un controlador DBI para archivos Mem & MLMem

SINOPSIS

use DBI;
$dbh = DBI->connect('dbi:Mem:', undef, undef, {});
$dbh = DBI->connect('dbi:Mem:', undef, undef, {RaiseError => 1});
# o
$dbh = DBI->connect('dbi:Mem:');
$dbh = DBI->connect('DBI:Mem(RaiseError=1):');

y otras variaciones de connect() como se muestra en la documentación de DBI y <metadatos de DBI::DBD::SqlEngine|DBI::DBD::SqlEngine/Metadata>.

Utiliza prepare, execute, fetch, placeholders, etc. estándar de DBI.

DESCRIPCIÓN

DBD::Mem es un sistema de gestión de bases de datos que funciona directamente al sacarlo de la caja. Si tienes una instalación estándar de Perl y DBI, puedes empezar a crear, acceder y modificar tablas de bases de datos sencillas sin módulos adicionales. Puedes añadir otros módulos (por ejemplo, SQL::Statement) para mejorar la funcionalidad.

DBD::Mem no almacena ningún dato de forma persistente; todos los datos tienen la vida útil del $dbh instanciado. La razón principal para usar DBD::Mem es utilizar las características extendidas de SQL::Statement donde se requieren tablas temporales. Se puede usar DBD::Mem para simular "VISTAS" o subconsultas.

Incluir "DBD::Mem" con DBI nos permitirá realizar más comprobaciones de compatibilidad de DBI::DBD::SqlEngine más allá de las capacidades de DBD::File y DBD::DBM. Esto asegurará que la base proporcionada por DBI para controladores como DBD::AnyData2 o DBD::Amazon estén mejor preparados y probados para backends que no sean de archivos.

Metadatos

No hay nuevos metadatos introducidos por "DBD::Mem". Consulta "Metadata" en DBI::DBD::SqlEngine para una descripción completa.

OBTENER AYUDA, HACER SUGERENCIAS Y REPORTAR ERRORES

Si necesitas ayuda para instalar o usar DBD::Mem, por favor escribe a la lista de correo de usuarios de DBI en <mailto:dbi-users@perl.org> o al grupo de noticias comp.lang.perl.modules en usenet. No siempre puedo responder a todas las preguntas rápidamente, pero hay muchas personas en la lista de correo o en el grupo de noticias que sí pueden hacerlo.

Se sugiere a los desarrolladores de DBD para los controladores que dependen de DBI::DBD::SqlEngine o DBD::Mem, o que utilizan uno de ellos como ejemplo, que se unan a la lista de correo de desarrolladores de DBI en <mailto:dbi-dev@perl.org> y se les anima encarecidamente a unirse a nuestro canal IRC en <irc://irc.perl.org/dbi>.

Si tienes sugerencias, ideas de mejora o errores que reportar, por favor reporta un error como se describe en DBI. No envíes correos a ninguno de los autores directamente, podrías no recibir una respuesta.

Al reportar errores, por favor envía la salida de "$dbh->mem_versions($table)" para una tabla que muestre el error y la muestra más pequeña posible del código que produce el error. Y, por supuesto, los parches también son bienvenidos :-).

Si necesitas mejoras rápidamente, puedes obtener soporte comercial como se describe en http://dbi.perl.org/support/ o puedes contactar a Jens Rehsack en rehsack@cpan.org para soporte comercial.

VER TAMBIÉN

DBI para la interfaz de base de datos del Lenguaje de Programación Perl.

SQL::Statement y DBI::SQL::Nano para los motores SQL disponibles.

SQL::Statement::RAM de donde se roba descaradamente la implementación para permitir que los controladores Pure-Perl incluidos en DBI aumenten la cobertura de pruebas.

DBD::SQLite usando "dbname=:memory:" para un motor de base de datos en memoria increíblemente rápido.
