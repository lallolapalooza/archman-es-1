DBM_CLEARERR(3P) Manual del programador POSIX DBM_CLEARERR(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

dbm_clearerr, dbm_close, dbm_delete, dbm_error, dbm_fetch, dbm_firstkey, dbm_nextkey, dbm_open, dbm_store — funciones de base de datos

SINOPSIS

#include <ndbm.h>
int dbm_clearerr(DBM *db);
void dbm_close(DBM *db);
int dbm_delete(DBM *db, datum key);
int dbm_error(DBM *db);
datum dbm_fetch(DBM *db, datum key);
datum dbm_firstkey(DBM *db);
datum dbm_nextkey(DBM *db);
DBM *dbm_open(const char *file, int open_flags, mode_t file_mode);
int dbm_store(DBM *db, datum key, datum content, int store_mode);

DESCRIPCIÓN

Estas funciones crean, acceden y modifican una base de datos.

Un datum consiste en al menos dos miembros, dptr y dsize. El miembro dptr apunta a un objeto que tiene una longitud de dsize bytes. Se pueden almacenar datos binarios arbitrarios, así como cadenas de caracteres, en el objeto al que apunta dptr.

Una base de datos se almacenará en uno o dos archivos. Cuando se utiliza un archivo, el nombre del archivo de la base de datos se formará añadiendo el sufijo .db al argumento file proporcionado a dbm_open(). Cuando se utilizan dos archivos, los nombres de los archivos de la base de datos se formarán añadiendo los sufijos .dir y .pag respectivamente al argumento file.

La función dbm_open() abrirá una base de datos. El argumento file de la función es la ruta del archivo de la base de datos. El argumento open_flags tiene el mismo significado que el argumento flags de open(), excepto que una base de datos abierta en modo solo escritura abre los archivos para acceso de lectura y escritura, y el comportamiento de la bandera O_APPEND no está especificado. El argumento file_mode tiene el mismo significado que el tercer argumento de open().

La función dbm_open() no tiene por qué aceptar rutas de archivo más largas que {PATH_MAX}-4 bytes (incluyendo el terminador nulo), o rutas con un último componente más largo que {NAME_MAX}-4 bytes (excluyendo el terminador nulo).

La función dbm_close() cerrará una base de datos. La aplicación deberá asegurarse de que el argumento db es un puntero a una estructura dbm que ha sido devuelta por una llamada a dbm_open().

Estas funciones de base de datos admitirán un tamaño de bloque interno lo suficientemente grande como para soportar pares clave/contenido de al menos 1023 bytes.

La función dbm_fetch() leerá un registro de una base de datos. El argumento db es un puntero a una estructura de base de datos que ha sido devuelta por una llamada a dbm_open(). El argumento key es un datum que ha sido inicializado por la aplicación con el valor de la clave que coincide con la clave del registro que el programa está obteniendo.

La función dbm_store() escribirá un registro en una base de datos. El argumento db es un puntero a una estructura de base de datos que ha sido devuelta por una llamada a dbm_open(). El argumento key es un datum que ha sido inicializado por la aplicación con el valor de la clave que identifica (para lectura, escritura o eliminación posteriores) el registro que la aplicación está escribiendo. El argumento content es un datum que ha sido inicializado por la aplicación con el valor del registro que el programa está escribiendo. El argumento store_mode controla si dbm_store() reemplaza cualquier registro preexistente que tenga la misma clave que se especifica por el argumento key. La aplicación deberá establecer store_mode en DBM_INSERT o DBM_REPLACE. Si la base de datos contiene un registro que coincide con el argumento key y store_mode es DBM_REPLACE, el registro existente será reemplazado por el nuevo registro. Si la base de datos contiene un registro que coincide con el argumento key y store_mode es DBM_INSERT, el registro existente se dejará sin cambios y el nuevo registro se ignorará. Si la base de datos no contiene un registro que coincida con el argumento key y store_mode es DBM_INSERT o DBM_REPLACE, el nuevo registro se insertará en la base de datos.

Si la suma de un par clave/contenido excede el tamaño de bloque interno, el resultado no está especificado. Además, la aplicación deberá asegurarse de que todos los pares clave/contenido que se mezclan quepan en un solo bloque. La función dbm_store() devolverá un error en caso de que un bloque de disco se llene con datos inseparables.

La función dbm_delete() eliminará un registro y su clave de la base de datos. El argumento db es un puntero a una estructura de base de datos que ha sido devuelta por una llamada a dbm_open(). El argumento key es un datum que ha sido inicializado por la aplicación con el valor de la clave que identifica el registro que el programa está eliminando.

La función dbm_firstkey() devolverá la primera clave de la base de datos. El argumento db es un puntero a una estructura de base de datos que ha sido devuelta por una llamada a dbm_open().

La función dbm_nextkey() devolverá la siguiente clave de la base de datos. El argumento db es un puntero a una estructura de base de datos que ha sido devuelta por una llamada a dbm_open(). La aplicación deberá asegurarse de que se llama a la función dbm_firstkey() antes de llamar a dbm_nextkey(). Las llamadas subsiguientes a dbm_nextkey() devuelven la siguiente clave hasta que se hayan devuelto todas las claves de la base de datos.

La función dbm_error() devolverá la condición de error de la base de datos. El argumento db es un puntero a una estructura de base de datos que ha sido devuelta por una llamada a dbm_open().

La función dbm_clearerr() borrará la condición de error de la base de datos. El argumento db es un puntero a una estructura de base de datos que ha sido devuelta por una llamada a dbm_open().

Los punteros dptr devueltos por estas funciones pueden apuntar a almacenamiento estático que puede ser modificado por llamadas posteriores.

Estas funciones no tienen por qué ser seguras para hilos.

VALOR DE RETORNO

Las funciones dbm_store() y dbm_delete() devolverán 0 cuando tengan éxito y un valor negativo cuando fallen.

La función dbm_store() devolverá 1 si se llama con un valor de flags de DBM_INSERT y la función encuentra un registro existente con la misma clave.

La función dbm_error() devolverá 0 si la condición de error no está establecida y devolverá un valor distinto de cero si la condición de error está establecida.

El valor de retorno de dbm_clearerr() no está especificado.

Las funciones dbm_firstkey() y dbm_nextkey() devolverán un datum de clave. Cuando se llega al final de la base de datos, el miembro dptr de la clave es un puntero nulo. Si se detecta un error, el miembro dptr de la clave será un puntero nulo y se establecerá la condición de error de la base de datos.

La función dbm_fetch() devolverá un datum de contenido. Si ningún registro en la base de datos coincide con la clave o si se ha detectado una condición de error en la base de datos, el miembro dptr del contenido será un puntero nulo.

La función dbm_open() devolverá un puntero a una estructura de base de datos. Si se detecta un error durante la operación, dbm_open() devolverá un (DBM *)0.

ERRORES

No se definen errores.

Las siguientes secciones son informativas.

EJEMPLOS

Ninguno.

USO DE APLICACIÓN

El siguiente código se puede utilizar para recorrer la base de datos:

for(key = dbm_firstkey(db); key.dptr != NULL; key = dbm_nextkey(db))

Las funciones dbm_* proporcionadas en esta biblioteca no deben confundirse de ninguna manera con las de un sistema de gestión de bases de datos de propósito general. Estas funciones no proporcionan claves de búsqueda múltiples por entrada, no protegen contra el acceso multiusuario (es decir, no bloquean registros ni archivos) y no proporcionan muchas otras funciones útiles de bases de datos que se encuentran en sistemas de gestión de bases de datos más robustos.

PROLOG

This page is part of the POSIX Programmer's Manual. The man page POSIX.1-2017 is available on the POSIX.1-2008 system.

NAME

dbm_clearerr, dbm_error, dbm_close, dbm_delete, dbm_fetch, dbm_firstkey, dbm_nextkey, dbm_open, dbm_store, dbm_set_record_max - database subroutines

SYNOPSIS

#include <ndbm.h>

void
dbm_clearerr(DBM *db);

int
dbm_error(DBM *db);

void
dbm_close(DBM *db);

int
dbm_delete(DBM *db, datum key);

datum
dbm_fetch(DBM *db, datum key);

datum
dbm_firstkey(DBM *db);

datum
dbm_nextkey(DBM *db);

DBM *
dbm_open(const char *name, int oflag, mode_t mode);

int
dbm_store(DBM *db, datum key, datum content, int replace);

int
dbm_set_record_max(DBM *db, size_t record_max);

DESCRIPTION

The dbm_open() function shall establish a connection to a database described by the file name name. The database files are created with the specified mode and oflag arguments, which are the same as for open(). The oflag argument can be O_RDONLY, O_RDWR, or O_WRONLY.

The dbm_close() function shall close the database.

The dbm_delete() function shall delete the item specified by key from the database.

The dbm_fetch() function shall return the item associated with key.

The dbm_firstkey() function shall return the first key in the database.

The dbm_nextkey() function shall return the next key in the database.

The dbm_store() function shall store the pair key, content in the database. If replace is zero, and the key already exists, the data will not be stored. If replace is non-zero, and the key already exists, the data will be stored and the old data overwritten.

The dbm_clearerr() function shall clear the error and end-of-file indicators for the database stream associated with db.

The dbm_error() function shall return non-zero if and only if the error indicator is set for the database stream associated with db.

The dbm_set_record_max() function shall set the maximum size, in bytes, for a record to record_max. If record_max is 0, the size is unlimited. This function should be called before any data is stored in the database.

A datum is a structure that holds a character array and its length:

typedef struct {
    char *dptr;
    int  dsize;
} datum;

RETURN VALUE

Upon successful completion, dbm_firstkey() and dbm_nextkey() shall return a datum structure representing a key. If there is no next key, or if an error occurs, they shall return a datum structure with a dptr value of NULL.

The dbm_fetch() function shall return a datum structure representing the data associated with the key. If the key is not found, or if an error occurs, it shall return a datum structure with a dptr value of NULL.

The dbm_store() and dbm_delete() functions shall return zero upon success, and non-zero upon failure.

The dbm_open() function shall return a pointer to a DBM structure upon success, or NULL upon failure.

The dbm_error() function returns non-zero if an error occurred, zero otherwise.

The dbm_set_record_max() function shall return 0 upon success, or a non-zero value if an error occurred.

ERRORS

The behavior is undefined if db is not a pointer to a DBM structure returned by a prior call to dbm_open().

The dbm_open() function may fail if:

[EACCES]
Search permission is denied for a component of the path prefix of name.
[EEXIST]
The database specified by name exists, but it is not a database file. O_CREAT and O_EXCL were specified.
[EINTR]
A signal was caught during the execution of this function.
[EINVAL]
The specified oflag value is invalid.
[EISDIR]
The name string specifies a directory.
[EMFILE]
Too many file descriptors are open by the process.
[ENFILE]
Too many files are open in the system.
[ENOENT]
The database does not exist and O_CREAT was not specified.
[ENOSPC]
The database cannot be created because the directory in which it is to be placed lacks the necessary space.
[ENOTDIR]
A component of the name string is not a directory, and more of the string exists.
[ENXIO]
A block device required for name does not exist or is unavailable.
[EOVERFLOW]
The database file cannot be created because of a too-large file ）（
[EROFS]
The database is to be created on a read-only file system.
[ETXTBSY]
The database file is being executed.

The dbm_store() and dbm_delete() functions may fail if:

[EACCES]
Permission to access the database file is denied.
[EINTR]
A signal was caught during the execution of this function.
[EINVAL]
The key structure is invalid.
[ENOSPC]
There is not enough space in the database.

EXAMPLES

To store a key-value pair:

datum key, content, retrieved_content;
DBM	*db;

db = dbm_open("my_database", O_RDWR | O_CREAT, 0600);
if (db == NULL) {
    // handle error
}

key.dptr = "my_key";
key.dsize = strlen(key.dptr);
content.dptr = "my_value";
content.dsize = strlen(content.dptr);

if (dbm_store(db, key, content, 1) < 0) {
    // handle error
}

retrieved_content = dbm_fetch(db, key);
if (retrieved_content.dptr != NULL) {
    // process retrieved_content.dptr and retrieved_content.dsize
}

dbm_close(db);

APPLICATION USAGE

The dbm family of functions provides a simple, flat-file database interface. They are intended for applications that require fast lookup of relatively static information that is to be indexed by a single key. The size of keys and data are limited only by available memory. The interface is not intended for applications that require frequent updates, concurrent access, or complex data structures.

The dbm functions use a hashing algorithm to store and retrieve data. This means that data is not stored in any particular order, and there is no guarantee that keys will be stored or retrieved in the same order that they were inserted. The hashing algorithm can lead to collisions, where two different keys hash to the same value. In such cases, the dbm implementation must handle the collision, which can slow down database operations.

The dbm functions are not thread-safe. Applications that use these functions from multiple threads must provide their own synchronization mechanisms.

The dbm functions are not designed for handling large databases. As the database grows, performance may degrade due to increased hash collisions and file I/O. For larger or more demanding applications, consider using more robust database systems like SQLite or Berkeley DB.

The dbm_set_record_max function can be used to limit the size of individual records. This can be useful for preventing excessively large records from consuming too much memory or disk space. If set to 0, there is no limit on record size.

Creating and updating databases using these functions can be relatively slow due to data copies that occur upon hash collisions. These functions are useful for applications requiring fast lookup of relatively static information that is to be indexed by a single key.

Note that a strictly conforming application is extremely limited by these functions: since there is no way to determine that the keys in use do not all hash to the same value (although that would be rare), a strictly conforming application cannot be guaranteed that it can store more than one block's worth of data in the database. As long as a key collision does not occur, additional data may be stored, but because there is no way to determine whether an error is due to a key collision or some other error condition (dbm_error() being effectively a Boolean), once an error is detected, the application is effectively limited to guessing what the error might be if it wishes to continue using these functions.

The dbm_delete() function need not physically reclaim file space, although it does make it available for reuse by the database.

After calling dbm_store() or dbm_delete() during a pass through the keys by dbm_firstkey() and dbm_nextkey(), the application should reset the database by calling dbm_firstkey() before again calling dbm_nextkey(). The contents of these files are unspecified and may not be portable.

Applications should take care that database pathname arguments specified to dbm_open() are not prefixes of unrelated files. This might be done, for example, by placing databases in a separate directory.

Since some implementations use three characters for a suffix and others use four characters for a suffix, applications should ensure that the maximum portable pathname length passed to dbm_open() is no greater than {PATH_MAX}-4 bytes, with the last component of the pathname no greater than {NAME_MAX}-4 bytes.

RATIONALE

Previously the standard required the database to be stored in two files, one file being a directory containing a bitmap of keys and having .dir as its suffix. The second file containing all data and having .pag as its suffix. This has been changed not to specify the use of the files and to allow newer implementations of the Berkeley DB interface using a single file that have evolved while remaining compatible with the application programming interface. The standard developers considered removing the specific suffixes altogether but decided to retain them so as not to pollute the application file name space more than necessary and to allow for portable backups of the database.
