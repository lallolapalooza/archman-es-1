DBD::SQLite2(3) Documentación de Perl aportada por el usuario DBD::SQLite2(3)

NOMBRE

DBD::SQLite2 - RDBMS autocontenido en un controlador DBI (sqlite 2.x)

SINOPSIS

use DBI;
my $dbh = DBI->connect("dbi:SQLite2:dbname=dbfile","","");

DESCRIPCIÓN

SQLite es un motor de base de datos RDBMS de dominio público que puedes encontrar en http://www.sqlite.org/.

En lugar de pedirte que instales SQLite primero, dado que SQLite es de dominio público, DBD::SQLite2 incluye todo el paquete en la distribución. Así que para obtener un RDBMS rápido con capacidad de transacciones para tu proyecto perl simplemente tienes que instalar este módulo, y nada más.

Para trabajo real, por favor usa el controlador actualizado DBD::SQLite con el backend sqlite3 actualizado. SQLite2 soporta las siguientes características:

Implementa un gran subconjunto de SQL92
Ver http://www.sqlite.org/lang.html para detalles.
Una base de datos completa en un solo archivo de disco
Todo para tu base de datos se almacena en un solo archivo de disco, haciéndolo más fácil de mover que con DBD::CSV.
Confirmación y reversión atómicas
Sí, DBD::SQLite2 es pequeño y ligero, pero soporta transacciones completas
Extensible
Se pueden registrar funciones agregadas o regulares definidas por el usuario con el analizador SQL.

Hay mucho más, así que por favor consulta la documentación en la página web de SQLite, listada arriba, para detalles de SQL. También consulta DBI para detalles sobre cómo usar DBI en sí mismo.

CONFORMIDAD CON LA ESPECIFICACIÓN DBI

La API funciona como todo módulo DBI. Por favor consulta DBI para más detalles sobre características principales.

Actualmente muchos atributos de sentencia no están implementados o están limitados por la naturaleza sin tipos de la base de datos SQLite2.

ATRIBUTOS PRIVADOS DEL CONTROLADOR

Atributos del Manejador de Base de Datos

sqlite_version
Devuelve la versión de la biblioteca SQLite que DBD::SQLite2 está usando, es decir, "2.8.15".
sqlite_encoding
Devuelve "UTF-8" o "iso8859" para indicar cómo se compiló la biblioteca SQLite.
sqlite_handle_binary_nulls
Establece este atributo a 1 para manejar de forma transparente nulos binarios en datos entrecomillados y devueltos.

NOTA: Esto causará que todos los caracteres de barra invertida ("\") se dupliquen en todas las columnas independientemente de si contienen datos binarios o no. Esto puede romper tu base de datos si la usas desde otra aplicación. Esto no usa las funciones incorporadas "sqlite_encode_binary" y "sqlite_decode_binary" , lo cual puede considerarse un error.

MÉTODOS PRIVADOS DEL CONTROLADOR

$dbh->func('last_insert_rowid')

Este método devuelve el último rowid insertado. Si especificas un INTEGER PRIMARY KEY como la primera columna en tu tabla, esa es la columna que se devuelve. De lo contrario, es la columna oculta ROWID. Ver la documentación de sqlite para detalles.

$dbh->func( $name, $argc, $func_ref, "create_function" )

Este método registrará una nueva función que será utilizable en consultas SQL. Los parámetros del método son:

$name
El nombre de la función. Este es el nombre de la función tal como será usada desde SQL.
$argc
El número de argumentos que toma la función. Si este número es -1, la función puede tomar cualquier número de argumentos.
$func_ref
Esto debería ser una referencia a la implementación de la función.

Por ejemplo, aquí está cómo definir una now() función que devuelve el número actual de segundos desde la época:

$dbh->func( 'now', 0, sub { return time }, 'create_function' );

Después de esto, podría usarse desde SQL como:

INSERT INTO mytable ( now() );

$dbh->func( $name, $argc, $pkg, 'create_aggregate' )

Este método registrará una nueva función agregada que puede ser usada desde SQL. Los parámetros del método son:

$name
El nombre de la función agregada, este es el nombre bajo el cual la función estará disponible desde SQL.
$argc
Este es un entero que le dice al analizador SQL cuántos argumentos toma la función. Si ese número es -1, la función puede tomar cualquier número de argumentos.
$pkg
Este es el paquete que implementa la interfaz de agregación.

La interfaz de agregación consiste en definir tres métodos:

new()
Este método será llamado una vez para crear un objeto que debería ser usado para agregar las filas de un grupo particular. Los métodos step() y finalize() serán llamados sobre la referencia devuelta por el método.
step(@_)
Este método será llamado una vez por cada fila en el agregado.
finalize()
Este método será llamado una vez que todas las filas en el agregado hayan sido procesadas y debería devolver el resultado de la función agregada. Cuando no hay filas en el agregado, finalize() será llamado justo después de new().

Aquí está una función agregada simple que devuelve la varianza (ejemplo adaptado de pysqlite):

package variance;
sub new { bless [], shift; }
sub step {
    my ( $self, $value ) = @_;
    push @$self, $value;
}
sub finalize {
    my $self = $_[0];
    my $n = @$self;
    # Variance is NULL unless there is more than one row
    return undef unless $n || $n == 1;
    my $mu = 0;
    foreach my $v ( @$self ) {
        $mu += $v;
    }
    $mu /= $n;
    my $sigma = 0;
    foreach my $v ( @$self ) {
        $sigma += ($x - $mu)**2;
    }
    $sigma = $sigma / ($n - 1);
    return $sigma;
}
$dbh->func( "variance", 1, 'variance', "create_aggregate" );

La función agregada puede entonces usarse como:

SELECT group_name, variance(score) FROM results
GROUP BY group_name;

NOTAS

Para acceder a la base de datos desde la línea de comandos, intenta usar dbish que viene con el módulo DBI. Simplemente escribe:

dbish dbi:SQLite:foo.db

En la línea de comandos para acceder al archivo foo.db.

Alternativamente puedes instalar SQLite desde el enlace de arriba sin conflicto con DBD::SQLite2 y usar la herramienta de línea de comandos "sqlite" proporcionada.

RENDIMIENTO

SQLite es rápido, muy rápido. Recientemente procesé mi archivo de registro de 72MB con él, insertando los datos (400,000+ filas) usando transacciones y solo confirmando cada 1000 filas (de lo contrario la inserción es bastante lenta), y luego realizando consultas sobre los datos.

Consultas como count(*) y avg(bytes) tomaron fracciones de segundo para devolver, pero lo que más me sorprendió fue:

SELECT url, count(*) as count FROM access_log
  GROUP BY url
  ORDER BY count desc
  LIMIT 20

Para descubrir las 20 URLs más visitadas en el sitio (http://axkit.org), y devolvió en 2 segundos. Estoy seriamente considerando cambiar mi código de análisis de registros para usar este pequeño demonio de velocidad!

Oh sí, y eso fue sin índices en la tabla, en un PIII de 400MHz.

Para el mejor rendimiento asegúrese de ajustar sus configuraciones de hdparm si está utilizando Linux. También podría querer establecer:

PRAGMA default_synchronous = OFF

Esto evitará que sqlite realice fsync's al escribir (lo cual ralentiza significativamente las escrituras no transaccionales) a cambio de algo de tranquilidad. También intente jugar con la directiva cache_size.
