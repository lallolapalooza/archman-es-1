dbus-binding-tool(1) Comandos de usuario dbus-binding-tool(1)

NOMBRE

dbus-binding-tool - Utilidad de generación de enlaces dbus-glib para lenguaje C.

SINOPSIS

dbus-binding-tool [--force] [--help] [--ignore-unsupported] [--mode=pretty|glib-client|glib-server] [--output=archivo] [--prefix=prefijo-símbolo] [--version] [archivo...]

DESCRIPCIÓN

dbus-binding-tool se utiliza para exponer un GObject a través de D-Bus, utilizando el enlace obsoleto dbus-glib para GLib. Como entrada, dbus-binding-tool utiliza un archivo XML de introspección de D-Bus. Como salida, se generan los enlaces del lado del cliente o del lado del servidor. Esta salida es un archivo de cabecera que facilita el uso de un objeto D-Bus remoto. La salida se envía a la salida estándar o al nombre de archivo especificado con el argumento --output.

DESCRIPCIÓN EXTENDIDA

El siguiente es un archivo XML de ejemplo de introspección de D-Bus que describe un objeto que expone un método, llamado ManyArgs:

<?xml version="1.0" encoding="UTF-8" ?>
<node name="/com/example/MyObject">
  <interface name="com.example.MyObject">
    <method name="ManyArgs">
      <arg type="u" name="x" direction="in" />
      <arg type="s" name="str" direction="in" />
      <arg type="d" name="trouble" direction="in" />
      <arg type="d" name="d_ret" direction="out" />
      <arg type="s" name="str_ret" direction="out" />
    </method>
  </interface>
</node>

dbus-binding-tool admite anotaciones en formato XML para controlar aún más cómo se generan los enlaces.

enlaces del lado del cliente

Al crear enlaces del lado del cliente, se utiliza el argumento --mode=glib-client. Los enlaces del lado del cliente admiten la anotación "org.freedesktop.DBus.Glib.NoReply". Esto se especifica dentro de la etiqueta <method> para indicar que el cliente no espera una respuesta a la llamada al método, por lo que no se debe enviar una respuesta. Esto se utiliza a menudo para acelerar llamadas de métodos rápidas donde no hay argumentos "out", y no saber si el método tuvo éxito es un compromiso aceptable para reducir a la mitad el tráfico en el bus. Por ejemplo:

<method name "FooMethod">
  [...]
  <annotation name="org.freedesktop.DBus.GLib.NoReply" value="yes"/>
  [...]
</method>

enlaces del lado del servidor

Al crear enlaces del lado del servidor, se utiliza el argumento --mode=glib-server. También se debe usar el argumento --prefix al crear enlaces del lado del servidor para que las funciones en la salida generada tengan el prefijo del valor especificado. Los enlaces del lado del servidor admiten las siguientes anotaciones:

"org.freedesktop.DBus.GLib.CSymbol"

Esta anotación se utiliza para especificar los nombres de símbolos C para los diversos tipos (interfaz, método, etc.), si difiere del nombre que D-Bus genera.

<interface name="com.example.MyObject">
  <annotation name="org.freedesktop.DBus.GLib.CSymbol" value="my_object"/>
  [...]
  <method name "ManyArgs">
    <annotation name="org.freedesktop.DBus.GLib.CSymbol" value="my_object_many_args"/>
    [...]
  </method>
</interface>

"org.freedesktop.DBus.GLib.Async"

Esta anotación marca la implementación del método como una función asíncrona, que no devuelve una respuesta de inmediato sino que enviará la respuesta en un momento posterior para completar la llamada. Esto se utiliza para implementar servicios no bloqueantes donde las llamadas a métodos pueden llevar tiempo.

Cuando un método es asíncrono, el prototipo de la función es diferente. Es obligatorio que la función cumpla las siguientes reglas:


•
La función debe devolver un valor de tipo gboolean; TRUE en caso de éxito y FALSE en caso contrario.
•
El primer parámetro es un puntero a una instancia del objeto.
•
Siguiendo el puntero a la instancia del objeto están los valores de entrada del método.
•
El último parámetro debe ser un (DBusGMethodInvocation *). Esto se utiliza al enviar el mensaje de respuesta de vuelta al cliente, llamando a dbus_g_method_return o dbus_g_method_return_error.

Por ejemplo:

<method name "FooMethod">
  [...]
  <annotation name="org.freedesktop.DBus.GLib.Async" value="yes"/>
  [...]
</method>

"org.freedesktop.DBus.GLib.Const"

Este atributo solo se puede aplicar a nodos <arg> "out", y especifica que el parámetro no se está copiando al devolverlo. Por ejemplo, esto convierte un argumento 's' de (char **) a (const char **), y da como resultado que D-Bus no libere el argumento después de enviar el mensaje. Por ejemplo:

  <arg type="u" name="x" direction="out">
    <annotation name="org.freedesktop.DBus.GLib.Const" value=""/>
  </arg>

"org.freedesktop.DBus.GLib.ReturnVal"

Este atributo solo se puede aplicar a nodos <arg> "out", y altera la firma de la función esperada. Actualmente puede establecerse en dos valores: "" o "error". El argumento marcado con este atributo no se devuelve a través de un argumento de puntero, sino mediante el valor de retorno de la función. Si el valor del atributo es la cadena vacía, el argumento (GError *) también se omite, por lo que no hay una forma estándar de devolver un valor de error. Esto es muy útil para interactuar con código existente, ya que es posible coincidir con API existentes. Si el valor del atributo es "error", entonces el último argumento es un (GError *) como de costumbre. Por ejemplo:

  <arg type="u" name="x" direction="out">
    <annotation name="org.freedesktop.DBus.GLib.ReturnVal" value=""/>
  </arg>

OPCIONES

Se soportan las siguientes opciones:

--force


Sobrescribir el archivo de salida si ya existe con una marca de tiempo más reciente que los archivos fuente.


--help


Mostrar información de uso.


--ignore-unsupported


Si se establece, se ignoran las firmas no soportadas para los parámetros de <method>.


--mode=pretty|glib-client|glib-server


Si el valor es "glib-client", se generan los enlaces del cliente. Si el valor es "glib-server", se generan los enlaces del servidor. Si el valor es "pretty", la salida está en un formato más legible para el humano.


--output=archivo


Especificar el archivo de salida.


--prefix=prefijo-símbolo


Las funciones en la salida generada tienen el prefijo del valor prefijo-símbolo.


--version


Mostrar el número de versión del comando dbus-binding-tool.


OPERANDOS

Se soportan los siguientes operandos:

archivo
Una lista de uno o más archivos XML de introspección de D-Bus de entrada a incluir en la salida generada.


ARCHIVOS

Los siguientes archivos son utilizados por esta aplicación:

${exec_prefix}/bin/dbus-binding-tool
Ejecutable para la aplicación D-Bus Binding Tool.

NOTAS

dbus-binding-tool es parte de dbus-glib, que es un enlace deprecado de D-Bus para GLib.

dbus-glib recibe mantenimiento y correcciones de seguridad mínimas en beneficio de proyectos como Telepathy y NetworkManager que aún dependen de él, pero no debería usarse en proyectos nuevos (y los proyectos existentes también deberían intentar abandonarlo). Por favor, use GDBus, parte de GLib desde la versión 2.26.

gdbus-codegen(1) es el reemplazo de GDBus para dbus-binding-tool.
