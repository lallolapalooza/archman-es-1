Para perfilar un programa existente que utilice DBI::ProfileDumper, establezca la variable de entorno DBI_PROFILE y ejecute su programa como de costumbre. Por ejemplo, usando

bash: 
DBI_PROFILE=2/DBI::ProfileDumper program.

También puede activar DBI::ProfileDumper desde dentro de su

código: 
use DBI;
# perfil con la ruta por defecto (2) y el archivo de salida (dbi.prof)
$dbh->{Profile} = "!Statement/DBI::ProfileDumper";
# lo mismo, escrito explícitamente
$dbh->{Profile} = "!Statement/DBI::ProfileDumper/File:dbi.prof";
# otra forma de decirlo
use DBI::ProfileDumper;
$dbh->{Profile} = DBI::ProfileDumper->new(
                      Path => [ '!Statement' ],
                      File => 'dbi.prof' );
# usando una ruta personalizada
$dbh->{Profile} = DBI::ProfileDumper->new(
    Path => [ "foo", "bar" ],
    File => 'dbi.prof',
)
;

DESCRIPCIÓ

N

DBI::ProfileDumper es una subclase de DBI::Profile que vuelca los datos de perfil al disco en lugar de imprimir un resumen en su pantalla. Puede luego usar dbiprof para analizar los datos de varias maneras interesantes, o puede crear su propio análisis usando DBI::

ProfileData.

NOTA: Para aplicaciones Apache/mod_per

fileDumper::Apache.

US

O

Una forma de usar este módulo es simplemente habilitarlo en su $dbh

$dbh->{Profile} = "1/DBI::
ProfileDumper";

Esto escribirá los datos de perfil por sentencia en un archivo llamado dbi.prof. Si desea modificar cualquiera de estas propiedades, puede construir el objeto DBI::ProfileDumper usted

mismo: 
use DBI::ProfileDumper;
$dbh->{Profile} = DBI::ProfileDumper->new(
    Path => [ '!Statement' ],
    File => 'dbi.prof'
)
;

La opción "Path" toma los mismos valores que en DBI::Profile. La opción "File" da el nombre del archivo donde se recopilarán los resultados. Si ya existía, será

sobrescrito.

También puede activar este módulo estableciendo la variable de entorno DBI_PROFILE

$ENV{DBI_PROFILE} = "!Statement/DBI::
ProfileDumper";

FORMATO DE

DATOS

El formato de datos escrito por DBI::ProfileDumper comienza con un encabezado que contiene el número de versión del módulo utilizado para generarlo. Luego un bloque de declaraciones de variables describe el perfil. Después de dos saltos de línea, los datos de perfil forman el cuerpo del archivo. Por

ejemplo: 
DBI::ProfileDumper 2.003762
Path = [ '!Statement', '!MethodName' ]
Program = t/42profile_data.t
+ 1 SELECT name FROM users WHERE id = ?
+ 2 prepare
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 2 execute
1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 2 fetchrow_hashref
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 1 UPDATE users SET name = ? WHERE id = ?
+ 2 prepare
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 2 execute
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.
86576

Las líneas que comienzan con signos "+" significan claves. El número después del signo "+" muestra el nivel de anidamiento de la clave. Las líneas que comienzan con "=" son los datos de perfil reales, en el mismo orden que en DBI::

Profile.

Tenga en cuenta que la misma ruta puede estar presente varias veces en el archivo de datos ya que format() puede ser llamado más de una vez. Cuando sea leído por DBI::ProfileData, los puntos de datos serán fusionados para producir un único conjunto de datos para cada ruta

distinta.

Las cadenas de clave se transforman de tres maneras. Primero, todas las barras invertidas se duplican. Luego, todos los saltos de línea y retornos de carro se transforman en "\n" y "\r" respectivamente. Finalmente, cualquier byte NULL ("\0") es eliminado por completo. Cuando DBI::ProfileData lee el archivo, las dos pr

imeras transformaciones serán revertida
s, pero los bytes NULL no serán restaurados.
