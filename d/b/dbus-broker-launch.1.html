NOMBRE

dbus-broker-launch - Lanzador para D-Bus Message Brokers

SINOPSIS

dbus-broker-launch [ OPCIONES ]
dbus-broker-launch --version
dbus-broker-launch --help

DESCRIPCIÓN

dbus-broker-launch es un lanzador para dbus-broker, que inicia y gestiona un D-Bus Message Bus. El lanzador pretende ser totalmente compatible con la implementación de referencia de D-Bus dbus-daemon(1), soportando la misma sintaxis de configuración y entorno de ejecución.

Cada instancia de dbus-broker-launch gestiona exactamente un bus de mensajes. Cada bus de mensajes es independiente. El archivo de configuración puede especificarse a través de la línea de comandos, o se selecciona el predeterminado de /usr/share/dbus-1/. Casi todos los atributos de configuración son soportados. Ver dbus-daemon(1) para detalles sobre la sintaxis de configuración.

OPCIONES

Se soportan las siguientes opciones de línea de comandos. Si se pasa una opción que no está listada aquí, el lanzador denegará el inicio y saldrá con un error.

-h, --help
imprime información de uso y sale inmediatamente
--version
imprime la versión de compilación y sale inmediatamente
--audit
habilita el registro en el subsistema de auditoría de Linux (no hace nada si el soporte de auditoría no fue compilado; Predeterminado: desactivado)
--config-file=RUTA
archivo de configuración a usar (Predeterminado: /usr/share/dbus-1/{system,session}.conf)
--scope=ÁMBITO
selecciona el ámbito en el que ejecutarse (uno de: system, user; Predeterminado: system)

REGISTRO

Por defecto, dbus-broker-launch registra mensajes en el diario del sistema (system journal). Los mensajes se aumentan con muchos metadatos, así que asegúrate de comprobar los campos adicionales del diario. El mensaje de registro legible está intencionadamente corto.

Al inicio y al apagado, el lanzador registra mensajes iniciales que contienen información sobre los archivos de configuración analizados y las definiciones de servicio. No se generan otros mensajes de registro, excepto los que se originan en dbus-broker(1).

ÁMBITO

A diferencia de dbus-daemon(1), dbus-broker-launch activa todos los servicios como unidades de systemd. Los servicios que ya vienen con una unidad de systemd se activan como de costumbre, pero los servicios que carecen de una unidad de systemd se activan como unidades transitorias, con un archivo de unidad ad-hoc generado en tiempo de ejecución. Esto garantiza que todos los servicios se ejecuten en un entorno bien definido.

El parámetro --scope define qué instancia de systemd usará el lanzador para activar servicios. En caso de system, el lanzador usará la instancia del sistema de systemd. En caso de user, se usará en su lugar la instancia de usuario.

Además, el ámbito seleccionado también define qué archivo de configuración se utiliza si no se especifica ninguno en la línea de comandos.

El ámbito seleccionado no tiene ningún efecto adicional. Solo es necesario para definir el entorno de activación de las definiciones de servicio cargadas. Si no se declaran servicios activables, el ámbito no tendrá ningún efecto.

SOCKETS

El socket para escuchar las conexiones de clientes debe ser creado y pasado a dbus-broker-launch por su proceso padre. El protocolo debe seguir la activación por socket tal como se define en systemd.socket(1). Actualmente solo se soporta un único socket.

Los atributos adicionales <listen>%path%</listen> en la configuración son ignorados.

PRIVILEGIOS

El lanzador necesita acceso de lectura a su archivo de configuración. Aparte de eso, no se necesitan privilegios. Si se utiliza el atributo de configuración <user>%user%</user>, el lanzador reducirá privilegios al ejecutar dbus-broker.

Si se declaran servicios activables, el lanzador necesitará acceso a la instancia de systemd correspondiente. El lanzador debe tener permiso para iniciar unidades transitorias, así como para gestionar las unidades declaradas en las definiciones de servicio.
