DBI::Shell(3) Documentación de Perl aportada por el usuario DBI::Shell(3)

NOMBRE

DBI::Shell - Shell de comandos interactivo para el DBI

SINOPSIS

perl -MDBI::Shell -e shell [<fuente de datos DBI> [<usuario> [<contraseña>]]]

o

dbish [<fuente de datos DBI> [<usuario> [<contraseña>]]]
dbish --debug [<fuente de datos DBI> [<usuario> [<contraseña>]]]
dbish --batch [<fuente de datos DBI> [<usuario> [<contraseña>]]] < archivo de lote

DESCRIPCIÓN

El módulo DBI::Shell (y el comando dbish, si está instalado) proporciona una interfaz de línea de comandos simple pero efectiva para el módulo Perl DBI.

POR HACER

Documentación adecuada - pero no todavía, demasiadas cosas están cambiando.

Comando "source file" para leer un archivo de comandos. Permitir anidar mediante una pila de manejadores de archivo de comandos. Añadir una utilidad de registro de comandos para crear archivos de lote.

Comandos:

Usar Data::ShowTable si está disponible.

Definir la semántica de los plug-ins de DBI::Shell. Implementar importar/exportar como módulo plug-in

Aclarar el significado del modo de lote

Ganchos de autocompletado

Establecer/Obtener atributos del manejador DBI

Portabilidad

¿Emular modos populares de shells de comandos (Oracle, Ingres, etc.)?

CONFIGURACIÓN

El archivo de configuración (~/.dbish_config por defecto, anulado por $DBISH_CONFIG) se evalúa como código perl y debe devolver una referencia a un hash que contenga los elementos de configuración. Las claves notables incluyen

options
El valor es otra referencia a hash que contiene las opciones y sus valores. Escribe "/option" en la línea de comandos para obtener una lista de opciones aceptables.
plug-ins
Plugins a cargar. Esto es bastante estructura de datos compleja que se recorre recursivamente para determinar qué complementos deben cargarse. En el nivel superior, están las fases "pre-init", "post-init", "pre-connect", y "post-connect". En niveles inferiores, los complementos pueden seleccionarse por el nombre del controlador de la base de datos, y se pueden establecer opciones individuales. Finalmente, en algún punto debe encontrarse un arrayref que contenga los nombres de los paquetes de los complementos a cargar.

Dado que el archivo de configuración puede contener código perl arbitrario, puede hacer cualquier cosa que se pueda hacer en perl. Un truco bastante útil es llamar a binmode para establecer la codificación para la entrada y salida estándar.

Ejemplo

binmode STDIN,  ":utf8";
binmode STDOUT, ":utf8";
{
    options => {
        format => 'partbox',
    },
    'plug-ins' => {
        'pre-init' => [
            'DBI::Shell::Timing',
            'DBI::Shell::Spool',
        ],
    },
};

Este archivo de configuración primero establece la capa :utf8 para la entrada y salida para que coincida con la terminal (si no usa UTF-8, podría usar :encoding() aquí), y luego devuelve el hashref con los elementos de configuración: El formato se establece en 'partbox', y los dos complementos 'DBI::Shell::Timing' y 'DBI::Shell::Spool' se cargan.

ENTORNO

DBISH_TMP
Dónde escribir archivos temporales.
DBISH_CONFIG
Qué archivo de configuración se usa. Sin definir para no leer ninguna configuración adicional.

AUTORES y AGRADECIMIENTOS

DBI::Shell tiene una larga linaje.

Comenzó su vida alrededor de 1994-1997 como el script pmsql escrito por Andreas König. Jochen Wiedmann lo tomó y lo hizo suyo (añadiendo mucho por el camino) como dbimon, incluido con sus módulos de controladores DBD::mSQL. En 1998, alrededor de la época en que quería incluir un shell con el DBI, Adam Marks estaba trabajando en un dbish modelado después de la utilidad sqsh de Sybase.

Al querer empezar desde una base más limpia que el dbimon lleno de características pero complejo, trabajé con Adam para crear un módulo DBI::Shell bastante abierto, modular y muy configurable. Por el camino, Tom Lowery aportó ideas y parches. A medida que avancemos, es probable que más código útil y conceptos del dbimon de Jochen vuelvan a encontrar su lugar.
