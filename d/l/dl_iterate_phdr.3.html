dl_iterate_phdr(3) Manual de Funciones de la Biblioteca dl_iterate_phdr(3)

NOMBRE

dl_iterate_phdr - recorrer la lista de objetos compartidos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <link.h>
int dl_iterate_phdr(
         typeof(int (struct dl_phdr_info *info, size_t size, void *data))
             *callback,
         void *data);

DESCRIPCIÓN

La función dl_iterate_phdr() permite a una aplicación consultar en tiempo de ejecución para averiguar qué objetos compartidos ha cargado, y el orden en el que fueron cargados.

La función dl_iterate_phdr() recorre la lista de objetos compartidos de una aplicación y llama a la función callback una vez por cada objeto, hasta que se hayan procesado todos los objetos compartidos o callback devuelva un valor distinto de cero.

Cada llamada a callback recibe tres argumentos: info, que es un puntero a una estructura que contiene información sobre el objeto compartido; size, que es el tamaño de la estructura a la que apunta info; y data, que es una copia de cualquier valor que el programa que llama haya pasado como segundo argumento (también llamado data) en la llamada a dl_iterate_phdr().

El argumento info es una estructura del siguiente tipo:


struct dl_phdr_info {
    ElfW(Addr)        dlpi_addr;  /* Dirección base del objeto */
    const char       *dlpi_name;  /* Nombre del objeto
                                     (terminado en nulo) */
    const ElfW(Phdr) *dlpi_phdr;  /* Puntero al array de
                                     cabeceras de programa ELF
                                     de este objeto */
    ElfW(Half)        dlpi_phnum; /* Número de elementos en dlpi_phdr */
    /* Los siguientes campos se añadieron en glibc 2.4, después de que
       estuviera disponible la primera versión de esta estructura. Compruebe el size
       argumento pasado al callback de dl_iterate_phdr para determinar
       si cada miembro posterior está disponible o no.  */
    unsigned long long dlpi_adds;
                    /* Incrementado cuando un nuevo objeto
                       puede haberse añadido */
    unsigned long long dlpi_subs;
                    /* Incrementado cuando un objeto
                       puede haberse eliminado */
    size_t dlpi_tls_modid;
                    /* Si hay un segmento PT_TLS, su ID de
                       módulo como se usa en las reubicaciones TLS, si no, cero */
    void  *dlpi_tls_data;
                    /* La dirección de la instancia del segmento
                       PT_TLS de este módulo del hilo que llama, si tiene
                       uno y ha sido asignado en el hilo que llama,
                       si no, un puntero nulo */
};

(La definición de la macro ElfW() convierte su argumento en el nombre de un tipo de datos ELF adecuado para la arquitectura del hardware. Por ejemplo, en una plataforma de 32 bits, ElfW(Addr) produce el nombre del tipo de datos Elf32_Addr. Se puede encontrar más información sobre estos tipos en los archivos de cabecera <elf.h> y <link.h> .)

El campo dlpi_addr indica la dirección base del objeto compartido (es decir, la diferencia entre la dirección de memoria virtual del objeto compartido y el desplazamiento de ese objeto en el archivo desde el que fue cargado). El campo dlpi_name es una cadena terminada en nulo que da la ruta de acceso desde la que se cargó el objeto compartido.

Para entender el significado de los campos dlpi_phdr y dlpi_phnum , debemos tener en cuenta que un objeto compartido ELF consta de varios segmentos, cada uno de los cuales tiene una cabecera de programa correspondiente que describe el segmento. El campo dlpi_phdr es un puntero a un array de las cabeceras de programa de este objeto compartido. El campo dlpi_phnum indica el tamaño de este array.

Estas cabeceras de programa son estructuras de la siguiente forma:


typedef struct {
    Elf32_Word  p_type;    /* Tipo de segmento */
    Elf32_Off   p_offset;  /* Desplazamiento del segmento en el archivo */
    Elf32_Addr  p_vaddr;   /* Dirección virtual del segmento */
    Elf32_Addr  p_paddr;   /* Dirección física del segmento */
    Elf32_Word  p_filesz;  /* Tamaño del segmento en el archivo */
    Elf32_Word  p_memsz;   /* Tamaño del segmento en memoria */
    Elf32_Word  p_flags;   /* Banderas del segmento */
    Elf32_Word  p_align;   /* Alineación del segmento */
} Elf32_Phdr;

Tenga en cuenta que podemos calcular la ubicación de una cabecera de programa particular, x, en la memoria virtual usando la fórmula:


addr == info->dlpi_addr + info->dlpi_phdr[x].p_vaddr;

Los valores posibles para p_type incluyen los siguientes (ver <elf.h> para más detalles):


#define PT_LOAD         1    /* Segmento de programa cargable */
#define PT_DYNAMIC      2    /* Información de enlace dinámico */
#define PT_INTERP       3    /* Intérprete de programa */
#define PT_NOTE         4    /* Información auxiliar */
#define PT_SHLIB        5    /* Reservado */
#define PT_PHDR         6    /* Entrada para la propia tabla de cabeceras */
#define PT_TLS          7    /* Segmento de almacenamiento local de hilo */
#define PT_GNU_EH_FRAME 0x6474e550 /* Segmento .eh_frame_hdr de GCC */
#define PT_GNU_STACK  0x6474e551 /* Indica la ejecutabilidad de la pila */
#define PT_GNU_RELRO  0x6474e552 /* Solo lectura después de la reubicación */

VALOR DE RETORNO

La función dl_iterate_phdr() devuelve cualquier valor que haya sido devuelto por la última llamada a callback.

ATRIBUTOS

Para una explicación de los términos usados en esta sección, ver attributes(7).

Interfaz Atributo Valor
dl_iterate_phdr () Seguridad de hilos MT-Safe

VERSIONES

Varios otros sistemas proporcionan una versión de esta función, aunque los detalles de la estructura dl_phdr_info devuelta difieren. En los sistemas BSD y Solaris, la estructura incluye los campos dlpi_addr, dlpi_name, dlpi_phdry dlpi_phnum además de otros campos específicos de la implementación.

Las versiones futuras de la biblioteca C pueden añadir más campos a la estructura dl_phdr_info ; en ese caso, el argumento size proporciona un mecanismo para que la función de callback descubra si se está ejecutando en un sistema con campos añadidos.

ESTÁNDARES

Ninguno.

HISTORIA

glibc 2.2.4.

NOTAS

El primer objeto visitado por callback es el programa principal. Para el programa principal, el campo dlpi_name será una cadena vacía.
