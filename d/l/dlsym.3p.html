DESCRIPCIÓ

N

La función dlsym() obtiene la dirección de un símbolo (un identificador de función o un identificador de objeto de datos) definido en la tabla de símbolos identificada por el argumento handle. El argumento handle es un identificador de tabla de símbolos devuelto por una llamada a dlopen() (y que no ha sido liberado desde entonces por una llamada a dlclose()), y name es el nombre del símbolo como cadena de caracteres. El valor devuelto por dlsym(), convertido a un puntero al tipo del símbolo nombrado, puede usarse para llamar (en el caso de una función) o acceder al contenido de (en el caso de un objeto de datos) el símbolo

nombrado.

La función dlsym() busca el símbolo nombrado en la tabla de símbolos referenciada por handle. Si la tabla de símbolos fue creada con carga diferida (vea RTLD_LAZY en dlopen()), se usará el orden de carga en las operaciones de dlsym() para reubicar los archivos de objeto ejecutables necesarios para resolver el símbolo. El algoritmo de resolución de símbolos utilizado será el orden de dependencia descrito en dlopen

().

Las constantes simbólicas RTLD_DEFAULT y RTLD_NEXT (que pueden estar definidas en <dlfcn.h>) están reservadas para uso futuro como valores especiales que a las aplicaciones se les puede permitir usar para hand

l
e.

VALOR

DEVUELTO

Tras la finalización exitosa, si name nombra un identificador de función, dlsym() devuelve la dirección de la función convertida del tipo puntero a función al tipo puntero a void; de lo contrario, dlsym() devuelve la dirección del objeto de datos asociado con el identificador de objeto de datos nombrado por name convertido de un puntero al tipo del objeto de datos a un puntero a void. Si handle no se refiere a un identificador de tabla de símbolos válido o si el símbolo nombrado por name no se puede encontrar en la tabla de símbolos asociada con handle, dlsym() devuelve un puntero

nulo.

Información de diagnóstico más detallada estará disponible a través de dlerr

or(
).

(int))dlsym(handle, "my_function"); /* encontrar la dirección del objeto de datos my_object */ iptr = (int *)dlsy

USO EN

APLICACIONES

Los siguientes valores especiales para handle están reservados para uso futuro y tienen los significados

indicados:
RTLD_DEFAU
LT
La búsqueda del identificador ocurre en el ámbito global normal; es decir, una búsqueda de un identificador usando handle encontraría la misma definición que el uso directo de este identificador en el código del
programa.
RTLD_NE
XT
Especifica el siguiente archivo de objeto ejecutable después de este que define name. Este se refiere al archivo de objeto ejecutable que contiene la invocación de dlsym(). El siguiente archivo de objeto ejecutable es el que se encuentra al aplicar un algoritmo de resolución de símbolos por orden de carga (vea dlopen()). El siguiente símbolo es o bien uno de ámbito global (porque fue introducido como parte de la imagen de proceso original o porque fue añadido con una operación de dlopen() que incluye el indicador RTLD_GLOBAL), o está en un archivo de objeto ejecutable que fue incluido en la misma operación de dlopen() que
cargó
este.

El indicador RTLD_NEXT es útil para navegar una jerarquía intencionalmente creada de símbolos definidos múltiples veces creados a través de interposición. Por ejemplo, si un programa quisiera crear una implementación de malloc() que incorporara algunas estadísticas sobre asignaciones de memoria, tal implementación podría usar la definición real de malloc() para realizar la asignación de memoria — y ella misma solo incorporar la lógica necesaria para implementar la función de recopilación de

estadísticas.

Nótese que la conversión de un puntero void * a un puntero a función como

en: 
fptr = (int (*)(i
nt))dlsym(handle
, "my_function");

no está definida por el estándar ISO C. Este es

tándar requiere que esta conversión funcione
correctamente en implementaciones conformes.
