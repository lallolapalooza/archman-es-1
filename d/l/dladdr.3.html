dladdr(3) Manual de Funciones de Biblioteca dladdr(3)

NOMBRE

dladdr, dladdr1 - traduce una dirección a información simbólica

BIBLIOTECA

Biblioteca de enlace dinámico (libdl,-ldl)

SINOPSIS

#define _GNU_SOURCE
#include <dlfcn.h>
int dladdr(const void *addr, Dl_info *info);
int dladdr1(const void *addr, Dl_info *info, void **extra_info,
            int flags);

DESCRIPCIÓN

La función dladdr() determina si la dirección especificada en addr se encuentra en uno de los objetos compartidos cargados por la aplicación que llama. Si es así, entonces dladdr() devuelve información sobre el objeto compartido y el símbolo que se superpone a addr. Esta información se devuelve en una estructura Dl_info :


typedef struct {
    const char *dli_fname;  /* Ruta del objeto compartido que
                               contiene la dirección */
    void       *dli_fbase;  /* Dirección base en la que se carga
                               el objeto compartido */
    const char *dli_sname;  /* Nombre del símbolo cuya definición
                               se superpone a addr */
    void       *dli_saddr;  /* Dirección exacta del símbolo nombrado en
                               dli_sname */ } Dl_info;

Si no se pudo encontrar ningún símbolo que coincida con addr , entonces dli_sname y dli_saddr se establecen en NULL.

La función dladdr1() es como dladdr(), pero devuelve información adicional a través del argumento extra_info. La información devuelta depende del valor especificado en flags, que puede tener uno de los siguientes valores:

RTLD_DL_LINKMAP
Obtiene un puntero al mapa de enlace (link map) del archivo coincidente. El extra_info argumento apunta a un puntero a una link_map estructura (es decir, struct link_map **), definida en <link.h> como:

struct link_map {
    ElfW(Addr) l_addr;  /* Diferencia entre la
                           dirección en el archivo ELF y
                           la dirección en memoria */
    char      *l_name;  /* Ruta absoluta donde se encontró
                           el objeto */
    ElfW(Dyn) *l_ld;    /* Sección dinámica del
                           objeto compartido */
    struct link_map *l_next, *l_prev;
                        /* Cadena de objetos cargados */
    /* Más campos adicionales privados de la
       implementación */
};

RTLD_DL_SYMENT
Obtiene un puntero a la entrada de la tabla de símbolos ELF del símbolo coincidente. El extra_info argumento es un puntero a un puntero a símbolo: const ElfW(Sym) **. La ElfW() definición de macro convierte su argumento en el nombre de un tipo de datos ELF adecuado para la arquitectura del hardware. Por ejemplo, en una plataforma de 64 bits, ElfW(Sym) produce el nombre del tipo de datos Elf64_Sym, que está definido en <elf.h> como:

typedef struct  {
    Elf64_Word    st_name;     /* Nombre del símbolo */
    unsigned char st_info;     /* Tipo y enlace del símbolo */
    unsigned char st_other;    /* Visibilidad del símbolo */
    Elf64_Section st_shndx;    /* Índice de la sección */
    Elf64_Addr    st_value;    /* Valor del símbolo */
    Elf64_Xword   st_size;     /* Tamaño del símbolo */
} Elf64_Sym;

El campo st_name es un índice en la tabla de cadenas.
El campo st_info codifica el tipo y el enlace del símbolo. El tipo se puede extraer usando la macro ELF64_ST_TYPE(st_info) (o ELF32_ST_TYPE() en plataformas de 32 bits), que produce uno de los siguientes valores:
Valor Descripción
STT_NOTYPE El tipo de símbolo no está especificado
STT_OBJECT El símbolo es un objeto de datos
STT_FUNC El símbolo es un objeto de código
STT_SECTION Símbolo asociado con una sección
STT_FILE El nombre del símbolo es un nombre de archivo
STT_COMMON El símbolo es un objeto de datos común
STT_TLS El símbolo es un objeto de datos local a hilo
STT_GNU_IFUNC El símbolo es un objeto de código indirecto

El enlace del símbolo se puede extraer del campo st_info usando la macro ELF64_ST_BIND(st_info) (o ELF32_ST_BIND() en plataformas de 32 bits), que produce uno de los siguientes valores:
Valor Descripción
STB_LOCAL Símbolo local
STB_GLOBAL Símbolo global
STB_WEAK Símbolo débil
STB_GNU_UNIQUE Símbolo único

El campo st_other contiene la visibilidad del símbolo, que se puede extraer usando la macro ELF64_ST_VISIBILITY(st_info) (o ELF32_ST_VISIBILITY() en plataformas de 32 bits), que produce uno de los siguientes valores:
Valor Descripción
STV_DEFAULT Reglas de visibilidad de símbolo por defecto
STV_INTERNAL Clase oculta específica del procesador
STV_HIDDEN Símbolo no disponible en otros módulos
STV_PROTECTED No preempible, no exportado

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un valor distinto de cero. Si la dirección especificada en addr pudo ser asociada a un objeto compartido, pero no a un símbolo en el objeto compartido, entonces los campos info->dli_sname y info->dli_saddr se establecen en NULL.

Si la dirección especificada en addr no pudo ser asociada a un objeto compartido, entonces estas funciones devuelven 0. En este caso, un mensaje de error no está disponible a través de dlerror(3).

ERRORES

A veces, los punteros a funciones que pasas a dladdr() pueden sorprenderte. En algunas arquitecturas (notablemente i386 y x86-64), dli_fname y dli_fbase pueden terminar apuntando de vuelta al objeto desde el que llamaste a dladdr(), incluso si la función usada como argumento debería provenir de una biblioteca enlazada dinámicamente.

El problema es que el puntero a la función seguirá resolviéndose en tiempo de compilación, pero simplemente apuntará a la sección plt (Tabla de Enlace de Procedimientos) del objeto original (que despacha la llamada después de pedirle al enlazador dinámico que resuelva el símbolo). Para solucionar esto, puedes intentar para compilar el código de forma independiente de la posición: entonces, el compilador ya no puede preparar el puntero en tiempo de compilación y gcc(1) generará código que simplemente carga la dirección final del símbolo desde la got (Global Offset Table) en tiempo de ejecución antes de pasarla a dladdr().
