Documentación de la función/subrutina

subrutina dlarrd (character range, character order, integer n, double precision vl, double precision vu, integer il, integer iu, double precision, dimension( * ) gers, double precision reltol, double precision, dimension( * ) d, double precision, dimension( * ) e, double precision, dimension( * ) e2, double precision pivmin, integer nsplit, integer, dimension( * ) isplit, integer m, double precision, dimension( * ) w, double precision, dimension( * ) werr, double precision wl, double precision wu, integer, dimension( * ) iblock, integer, dimension( * ) indexw, double precision, dimension( * ) work, integer, dimension( * ) iwork, integer info)

DLARRD calcula los valores propios de una matriz simétrica tridiagonal con la precisión adecuada.

Propósito:

!>
!> DLARRD calcula los valores propios de una matriz simétrica
!> tridiagonal T con la precisión adecuada. Este es un código auxiliar
!> para ser llamado desde DSTEMR.
!> El usuario puede solicitar todos los valores propios, todos los valores propios
!> en el intervalo semiabierto (VL, VU], o los valores propios del IL-ésimo
!> al IU-ésimo.
!>
!> Para evitar desbordamiento, la matriz debe escalarse para que su
!> elemento más grande no exceda overflow**(1/2) * underflow**(1/4) en valor absoluto,
!> y para mayor precisión, no debe ser mucho menor que eso.
!>
!> Véase W. Kahan, Report CS41, Computer Science Dept., Stanford
!> University, 21 de julio de 1966.
!>

Parámetros

RANGE 
!>          RANGE es CHARACTER*1
!>          = 'A': ()   se encontrarán todos los valores propios.
!>          = 'V': () se encontrarán todos los valores propios en el intervalo
!>                           semiabierto (VL, VU].
!>          = 'I': () se encontrarán los valores propios del IL-ésimo al IU-ésimo
!>                           (de la matriz completa).
!>

ORDER

!>          ORDER es CHARACTER*1
!>          = 'B': () los valores propios se agruparán por
!>                              bloque de separación (ver IBLOCK, ISPLIT) y
!>                              se ordenarán de menor a mayor dentro del
!>                              bloque.
!>          = 'E': ()
!>                              los valores propios de la matriz completa
!>                              se ordenarán de menor a
!>                              mayor.
!>

N

!>          N es INTEGER
!>          El orden de la matriz tridiagonal T. N >= 0.
!>

VL

!>          VL es DOUBLE PRECISION
!>          Si RANGE='V', el límite inferior del intervalo a
!>          buscar para los valores propios. Los valores propios menores o iguales
!>          que VL, o mayores que VU, no se devolverán. VL < VU.
!>          No se referencia si RANGE = 'A' o 'I'.
!>

VU

!>          VU es DOUBLE PRECISION
!>          Si RANGE='V', el límite superior del intervalo a
!>          buscar para los valores propios. Los valores propios menores o iguales
!>          que VL, o mayores que VU, no se devolverán. VL < VU.
!>          No se referencia si RANGE = 'A' o 'I'.
!>

IL

!>          IL es INTEGER
!>          Si RANGE='I', el índice del
!>          valor propio más pequeño a devolver.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 e IU = 0 si N = 0.
!>          No se referencia si RANGE = 'A' o 'V'.
!>

IU

!>          IU es INTEGER
!>          Si RANGE='I', el índice del
!>          valor propio más grande a devolver.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 e IU = 0 si N = 0.
!>          No se referencia si RANGE = 'A' o 'V'.
!>

GERS

!>          GERS es array DOUBLE PRECISION, dimension (2*N)
!>          Los N intervalos de Gerschgorin (el i-ésimo intervalo
!>          de Gerschgorin es (GERS(2*i-1), GERS(2*i)).
!>

RELTOL

!>          RELTOL es DOUBLE PRECISION
!>          El ancho relativo mínimo de un intervalo. Cuando un intervalo
!>          es más estrecho que RELTOL multiplicado por el mayor (en
!>          magnitud) extremo, se considera
!>          suficientemente pequeño, es decir, convergido. Nota: esto debería
!>          ser siempre al menos radix*epsilon de máquina.
!>

D

!>          D es array DOUBLE PRECISION, dimension (N)
!>          Los N elementos diagonales de la matriz tridiagonal T.
!>

E

!>          E es array DOUBLE PRECISION, dimension (N-1)
!>          Los N-1 elementos fuera de la diagonal de la matriz tridiagonal T.
!>

E2

!>          E2 es array DOUBLE PRECISION, dimension (N-1)
!>          Los N-1 elementos fuera de la diagonal al cuadrado de la matriz
!>          tridiagonal T.
!>

PIVMIN

!>          PIVMIN es DOUBLE PRECISION
!>          El pivote mínimo permitido en la secuencia de Sturm para T.
!>

NSPLIT

!>          NSPLIT es INTEGER
!>          El número de bloques diagonales en la matriz T.
!>          1 <= NSPLIT <= N.
!>

ISPLIT

!>          ISPLIT es array INTEGER, dimension (N)
!>          Los puntos de división, en los que T se divide en submatrices.
!>          La primera submatriz consta de las filas/columnas 1 a ISPLIT(1),
!>          la segunda de las filas/columnas ISPLIT(1)+1 a ISPLIT(2),
!>          etc., y la NSPLIT-ésima consta de las filas/columnas
!>          ISPLIT(NSPLIT-1)+1 a ISPLIT(NSPLIT)=N.
!>          (Solo se utilizarán los primeros NSPLIT elementos, pero
!>          como el usuario no puede saber de antemano qué valor tendrá NSPLIT,
!>          se deben reservar N palabras para ISPLIT).
!>

M

!>          M es INTEGER
!>          El número real de valores propios encontrados. 0 <= M <= N.
!>          (Ver también la descripción de INFO=2,3.)
!>

W

!>          W es array DOUBLE PRECISION, dimension (N)
!>          A la salida, los primeros M elementos de W contendrán las
!>          aproximaciones de los valores propios. DLARRD calcula un intervalo
!>          I_j = (a_j, b_j] que incluye el valor propio j. La aproximación del
!>          valor propio se da como el punto medio del intervalo
!>          W(j)= ( a_j + b_j)/2. El error correspondiente está acotado por
!>          WERR(j) = abs( a_j - b_j)/2
!>

WERR

!>          WERR es array DOUBLE PRECISION, dimension (N)
!>          El límite de error en la aproximación del valor propio
!>          correspondiente en W.
!>

WL

!>          WL es DOUBLE PRECISION
!>

WU

!>          WU es DOUBLE PRECISION
!>          El intervalo (WL, WU] contiene todos los valores propios deseados.
!>          Si RANGE='V', entonces WL=VL y WU=VU.
!>          Si RANGE='A', entonces WL y WU son los límites de Gerschgorin globales
!>                        del espectro.
!>          Si RANGE='I', entonces WL y WU son calculados por DLAEBZ a partir del
!>                        índice

NAME

DLARRD - This routine is obsolete and has been replaced by DLAED1

SYNOPSIS

 SUBROUTINE DLARRD(N, VL, VU, IL, IU, ABSTOL, M, NZ, WORK,
                 IWORK, INFO)
 INTEGER N, IL, IU, M, NZ, INFO
 DOUBLE PRECISION VL, VU, ABSTOL
 DOUBLE PRECISION WORK(N), IWORK(N)

Description:

 DLARRD is obsolete. Use DLAED1 instead.
 DLARRD uses the inverse iteration to find a few eigenvalues and
 eigenvectors of a symmetric tridiagonal matrix T.
 The subroutine uses the notation of the "LAPACK Working Note TN.10"
 by Wu and Simon.

Function/Subroutine Documentation

N

 N is INTEGER
     The order of the matrix T. N >= 0.

VL

 VL is DOUBLE PRECISION
     The lower bound of the interval for the desired eigenvalues.

VU

 VU is DOUBLE PRECISION
     The upper bound of the interval for the desired eigenvalues.

IL

 IL is INTEGER
     The starting index for the desired eigenvalues.

IU

 IU is INTEGER
     The ending index for the desired eigenvalues.

ABSTOL

 ABSTOL is DOUBLE PRECISION
     The absolute tolerance to which the desired eigenvalues are computed.

M

 M is INTEGER
     On exit, the number of eigenvalues found in the interval (VL, VU).

NZ

 NZ is INTEGER
     On exit, the number of non-zero elements in the eigenvectors
     corresponding to the found eigenvalues.

WORK

 WORK is DOUBLE PRECISION array, dimension (N)
     Workspace.

IWORK

 IWORK is INTEGER array, dimension (N)
     Workspace.

INFO

 INFO is INTEGER
     = 0:  successful exit
     < 0:  if INFO = -i, the i-th argument had an illegal value
     > 0:  The algorithm failed to converge for some eigenvalues.
           The diagonal elements of the matrix E are modified by DLARRD.
           The effect is that the eigenvalues may not be as accurate as
           the requested tolerance ABSTOL.
           The output values of M and NZ should not be trusted.

IBLOCK

 IBLOCK is INTEGER array, dimension (N)
 On exit, if INFO = 0, IBLOCK(i) specifies to which
 block (from 1 to the number of blocks) the eigenvalue W(i)
 belongs.  (DLARRD may use the remaining N-M elements as
 workspace.)

INDEXW

 INDEXW is INTEGER array, dimension (N)
 The indices of the eigenvalues within each block (submatrix);
 for example, INDEXW(i)= j and IBLOCK(i)=k imply that the
 i-th eigenvalue W(i) is the j-th eigenvalue in block k.

WORK

 WORK is DOUBLE PRECISION array, dimension (4*N)

IWORK

 IWORK is INTEGER array, dimension (3*N)

INFO

 INFO is INTEGER
 = 0:  successful exit
 < 0:  if INFO = -i, the i-th argument had an illegal value
 > 0:  some or all of the eigenvalues failed to converge or
       were not computed:
       =1 or 3: Bisection failed to converge for some
               eigenvalues; these eigenvalues are flagged by a
               negative block number.  The effect is that the
               eigenvalues may not be as accurate as the
               absolute and relative tolerances.  This is
               generally caused by unexpectedly inaccurate
               arithmetic.
       =2 or 3: RANGE='I' only: Not all of the eigenvalues
               IL:IU were found.
               Effect: M < IU+1-IL
               Cause:  non-monotonic arithmetic, causing the
                       Sturm sequence to be non-monotonic.
               Cure:   recalculate, using RANGE='A', and pick
                       out eigenvalues IL:IU.  In some cases,
                       increasing the PARAMETER  may
                       make things work.
       = 4:    RANGE='I', and the Gershgorin interval
               initially used was too small.  No eigenvalues
               were computed.
               Probable cause: your machine has sloppy
                               floating-point arithmetic.
               Cure: Increase the PARAMETER ,
                     recompile, and try again.

Internal Parameters:

  FUDGE   DOUBLE PRECISION, default = 2
          A  to widen the Gershgorin intervals.  Ideally,
          a value of 1 should work, but on machines with sloppy
          arithmetic, this needs to be larger.  The default for
          publicly released versions should be large enough to handle
          the worst machine around.  Note that this has no effect
          on accuracy of the solution.
