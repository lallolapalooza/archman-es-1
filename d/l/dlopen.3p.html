DESCRIPCIÓ

N

La función dlopen() hará que los símbolos (identificadores de funciones e identificadores de objetos de datos) en el archivo de objeto ejecutable especificado por file estén disponibles para el programa que

llama.

La clase de archivos de objeto ejecutables elegibles para esta operación y la manera de su construcción están definidas por la implementación, aunque típicamente tales archivos son bibliotecas compartidas o

programas.

Las implementaciones pueden permitir la construcción de dependencias incrustadas en archivos de objeto ejecutables. En tales casos, una operación dlopen() cargará esas dependencias además del archivo de objeto ejecutable especificado por file. Las implementaciones también pueden imponer restricciones específicas sobre la construcción de programas que pueden emplear dlopen() y sus servicios

relacionados.

Un dlopen() exitoso devolverá un manejador de tabla de símbolos que el llamador puede usar en llamadas subsecuentes a dlsym() y dlclose

().

El valor de este manejador de tabla de símbolos no debe ser interpretado de ninguna manera por el

llamador.

El argumento file se usa para construir una ruta de acceso al archivo de objeto ejecutable. Si file contiene un carácter <slash>, el argumento file se usa como la ruta de acceso para el archivo. De lo contrario, file se usa de una manera definida por la implementación para producir una ruta de

acceso.

Si file es un puntero nulo, dlopen() devolverá un manejador de tabla de símbolos global para la imagen del proceso en ejecución actualmente. Este manejador de tabla de símbolos proporcionará acceso a los símbolos de un conjunto ordenado de archivos de objeto ejecutables que consiste en el archivo de imagen del programa original, cualquier archivo de objeto ejecutable cargado al inicio del programa como lo especifique ese archivo de proceso (por ejemplo, bibliotecas compartidas), y el conjunto de archivos de objeto ejecutables cargados usando operaciones dlopen() con el indicador RTLD_GLOBAL. Dado que el conjunto posterior de archivos de objeto ejecutables puede cambiar durante la ejecución, el conjunto de símbolos disponibles por este manejador de tabla de símbolos también puede cambiar

dinámicamente.

Solo se traerá una única copia de un archivo de objeto ejecutable al espacio de direcciones, incluso si dlopen() se invoca múltiples veces en referencia al archivo de objeto ejecutable, e incluso si se usan diferentes rutas de acceso para referenciar el archivo de objeto

ejecutable.

El parámetro mode describe cómo dlopen() debe operar sobre file con respecto al procesamiento de reubicaciones y el alcance de visibilidad de los símbolos proporcionados dentro de file. Cuando un archivo de objeto ejecutable se trae al espacio de direcciones de un proceso, puede contener referencias a símbolos cuyas direcciones no se conocen hasta que el archivo de objeto ejecutable se

carga.

Estas referencias deben ser reubicadas antes de que los símbolos puedan ser accedidos. El parámetro mode gobierna cuándo tienen lugar estas reubicaciones y puede tener los siguientes

valores:
RTLD_LA
ZY
Las reubicaciones se realizarán en un tiempo definido por la implementación, que va desde el momento de la llamada a dlopen() hasta que ocurra la primera referencia a un símbolo dado. Especificar RTLD_LAZY debería mejorar el rendimiento en implementaciones que soporten enlace dinámico de símbolos, ya que un proceso podría no referenciar todos los símbolos en un archivo de objeto ejecutable. Y, para sistemas que soporten resolución dinámica de símbolos para la ejecución normal de procesos, este comportamiento imita el manejo normal de la ejecución de
procesos.
RTLD_N
OW
Todas las reubicaciones necesarias se realizarán cuando el archivo de objeto ejecutable se cargue por primera vez. Esto puede desperdiciar algo de procesamiento si se realizan reubicaciones para símbolos que nunca se referencian. Este comportamiento puede ser útil para aplicaciones que necesitan saber que todos los símbolos referenciados durante la ejecución estarán disponibles antes de que dlopen()
reto
rne.

Cualquier archivo de objeto ejecutable cargado por dlopen() que requiera reubicaciones contra símbolos globales puede referenciar los símbolos en el archivo de imagen del proceso original, cualquier archivo de objeto ejecutable cargado al inicio del programa, desde la imagen del proceso inicial misma, desde cualquier otro archivo de objeto ejecutable incluido en la misma invocación de dlopen(), y cualquier archivo de objeto ejecutable que haya sido cargado en cualquier invocación de dlopen() y que haya especificado el indicador RTLD_GLOBAL. Para determinar el alcance de visibilidad para los símbolos cargados con una invocación de dlopen(), el parámetro mode debe ser un OR inclusivo a nivel de bits con uno de los siguientes

valores:
RTLD_GLOB
AL
Los símbolos del archivo de objeto ejecutable se harán disponibles para el procesamiento de reubicaciones de cualquier otro archivo de objeto ejecutable. Además, la búsqueda de símbolos usando dlopen(NULL,mode) y un dlsym() asociado permite que los archivos de objeto ejecutables cargados con este modo sean
buscados.
RTLD_LOC
AL
Los símbolos del archivo de objeto ejecutable no se hará
n disponibles para el procesamiento de reubicacion
es de cualquier otro archivo de objeto ejecutable.

Si no se especifica ni RTLD_GLOBAL ni RTLD_LOCAL, el comportamiento por defecto no está

especificado.

Si un archivo de objeto ejecutable se especifica en múltiples invocaciones de dlopen(), mode se interpreta en cada

invocación.

Si se ha especificado RTLD_NOW, todas las reubicaciones deberán haber sido completadas, haciendo que operaciones RTLD_NOW posteriores sean redundantes y que cualquier operación RTLD_LAZY posterior sea

irrelevante.

Si se ha especificado RTLD_GLOBAL, el archivo de objeto ejecutable mantendrá el estado RTLD_GLOBAL independientemente de cualquier especificación previa o futura de RTLD_LOCAL, siempre que el archivo de objeto ejecutable permanezca en el espacio de direcciones (vea dlclose(

)).

Los símbolos introducidos en la imagen del proceso a través de llamadas a dlopen() pueden ser usados en actividades de reubicación. Los símbolos así introducidos pueden duplicar símbolos ya definidos por el programa o por operaciones dlopen() previas. Para resolver las ambigüedades que tal situación podría presentar, la resolución de una referencia de símbolo a una definición de símbolo se basa en un orden de resolución de símbolos. Se definen dos tales órdenes de resolución: orden de carga y orden de dependencia. El orden de carga establece un ordenamiento entre las definiciones de símbolos, de modo que la primera definición cargada (incluyendo definiciones del archivo de imagen del proceso y cualquier archivo de objeto ejecutable dependiente cargado con él) tiene prioridad sobre los archivos de objeto ejecutables añadidos posteriormente (por dlopen()). El ordenamiento de carga se usa en el procesamiento de reubicaciones. El orden de dependencia usa un orden de amplitud (BFS) comenzando con un archivo de objeto ejecutable dado, luego todas sus dependencias, luego cualquier dependiente de esas, iterando hasta que todas las dependencias sean satisfechas. Con la excepción del manejador de tabla de símbolos global obtenido a través de una operación dlopen() con un puntero nulo como el argumento file, el orden de dependencia es usado por la función dlsym(). El orden de carga es usado en operaciones dlsym() sobre el manejador de tabla de símbolos

global.

Cuando un archivo de objeto ejecutable se hace accesible por primera vez a través de dlopen(), él y sus archivos de objeto ejecutables dependientes se añaden en orden de dependencia. Una vez que todos los archivos de objeto ejecutables son añadidos, se realizan reubicaciones usando el orden de carga. Nótese que si un archivo de objeto ejecutable o sus dependencias habían sido cargados previamente, los órdenes de carga y de dependencia pueden producir resoluciones

diferentes.

Los símbolos introducidos por operaciones dlopen() y disponibles a través de dlsym() son como mínimo aquellos que son exportados como identificadores de alcance global por el archivo de objeto ejecutable. Típicamente, tales identificadores serán aquellos que fueron especificados en (por ejemplo) código fuente C como teniendo enlace externo. La manera precisa en que una implementación construye el conjunto de símb

olos exportados para un archivo de objeto ejecu
table está definida por la implementación.

RETORNO

Tras la finalización exitosa, dlopen() devolverá un manejador de tabla de símbolos. Si file no puede ser encontrado, no puede ser abierto para lectura, no es de un formato de archivo de objeto ejecutable apropiado para elsing por dlopen(), o si se produce un error durante el proceso de carga archivo o al reubicar sus referencias simbólicas, dlopen() devolverá un puntero nulo. Se dispondrá de información de diagnóstico más detallada a través de dlerr
