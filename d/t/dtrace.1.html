NOMBRE

dtrace - Herramienta de generación estática de sondas de aplicación de usuario compatible con Dtrace.

SINOPSIS

dtrace -s archivo [OPCIONES]

DESCRIPCIÓN

El comando dtrace convierte las descripciones de sondas definidas en archivo.d en un archivo de cabecera de sondas a través de la opción -h o en un archivo de descripción de sondas a través de la opción -G.

OPCIONES

-h
generar un archivo de cabecera de systemtap.
-G
generar un archivo de objeto de definición de sondas de systemtap. Esto invoca al compilador C con un conjunto sensato de flags de compilación. Si necesita añadir más, los flags encontrados en la variable de entorno CFLAGS se transcribirán al compilador. Si esto no es suficiente control, use la opción -k para capturar el archivo C generado y compilar según sea necesario.
-o archivo
es el nombre del archivo de salida. Si se proporciona la opción -G, el archivo de salida se llamará archivo.o; si se proporciona la opción -h, el archivo de salida se llamará archivo.h.
-C
ejecutar el preprocesador cpp en el archivo de entrada cuando se proporcione la opción -h.
-I archivo
dar esta ruta de inclusión a cpp cuando se proporcione la opción -C.
-k
mantener archivos temporales, por ejemplo, el código fuente en lenguaje C para la opción -G.

EJEMPLOS

Systemtap es compatible a nivel de fuente con el soporte de sondas estáticas de aplicaciones de usuario de dtrace. Dado un archivo test.d que contiene:

provider sdt_probes 
{
  probe test_0 (int type);
  probe test_1 (struct astruct node);
};
struct astruct {int a; int b;};

Entonces el comando "dtrace -s test.d -G" creará el archivo de definición de sondas test.o y el comando "dtrace -stest.d -h" creará el archivo de cabecera de sondas test.h Posteriormente, la aplicación puede usar las macros generadas de esta manera:

#include "test.h"
 ...
struct astruct s;
 ...
SDT_PROBES_TEST_0(value);
 ...
if (SDT_PROBES_TEST_1_ENABLED())
    SDT_PROBES_TEST_1(expensive_function(s));

SEMÁFOROS

Los semáforos son variables de bandera utilizadas por las sondas como una forma de omitir el procesamiento potencialmente costoso para preparar argumentos para sondas que quizás ni siquiera estén activas. Systemtap los establece/borra automáticamente cuando se está ejecutando un script relevante, por lo que el costo de preparación de argumentos solo se paga cuando es necesario. Estas variables semáforo se definen dentro del archivo objeto "test.o", que por lo tanto debe enlazarse a una aplicación.

A veces, las variables semáforo no son necesarias ni útiles. Omitirlas puede simplificar el proceso de compilación, al omitir el archivo "test.o" adicional. Para omitir la dependencia de las variables semáforo, incluya "<sys/sdt.h>" dentro de la aplicación antes de "test.h":

#include <sys/sdt.h>
#include "test.h"
 ...
struct astruct s;
 ...
SDT_PROBES_TEST_0(value);
 ...
if (SDT_PROBES_TEST_1_ENABLED())
   SDT_PROBES_TEST_1(cheap_function(s));

En este modo, la prueba ENABLED() está fijada en 1.
