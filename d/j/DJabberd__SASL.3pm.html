NOMBRE

DJabberd::SASL - Plugin base para la negociación SASL

DESCRIPCIÓN

Este plugin base solo proporciona el esqueleto necesario para construir capas SASL dentro de DJabberd. Proporciona un hook (GetSASLManager) para iniciar la negociación SASL y devolver un objeto SASL Manager; y enlaza los stanzas SASL a la clase DJabberd::Stanza::SASL por defecto.

Consulta DJabberd::SASL::AuthenSASL para un plugin concreto basado en DJabberd::SASL.

¿CÓMO FUNCIONA LA INFRAESTRUCTURA SASL POR DEFECTO?

Cuando una subclase de DJabberd::SASL se declara dentro de un VHost, habilita la negociación SASL para la conexión.

Eso significa que SASL se anunciará en las características del stream. Luego, cuando el cliente envía un stanza SASL (ver RFC 3920), se manejan utilizando la clase DJabberd::Stanza::SASL, que hace algunas suposiciones:

  • El plugin soporta el hook GetSASLManager que devuelve una subclase de DJabberd::SASL::ManagerBase.
  • La interfaz a este gestor y al objeto de conexión sasl (ver más adelante) es un superconjunto de la interfaz de Authen::SASL.

A partir de ahí, la negociación SASL está en manos del Gestor SASL configurado.

Una opción de configuración es común a todos los plugins: Es "Opcional", que anuncia al cliente si SASL es opcional o no. Por defecto, SASL es (y debe ser) requerido.

SINOPSIS

<VHost yann.cyberion.net>
    <Plugin DJabberd::SASL::%Subclass%>
        Optional   yes
        %Config%
    </Plugin>
</VHost>

EXTENSIÓN DE SASL EN DJABBERD

Ver ejemplos.

Es bastante fácil extender la fase SASL con lo que quieras, siempre que se respeten los simples DJabberd::SASL::ManagerBase y DJabberd::SASL::Connection, que se basan en Authen::SASL.

Alternativamente, dado que esto es solo un plugin, también puedes descartarlo por completo y escribir algo desde cero. Tendrás que proporcionar un nuevo conjunto de manejadores para los stanzas SASL (en reemplazo de DJabberd::Stanzas::SASL).
