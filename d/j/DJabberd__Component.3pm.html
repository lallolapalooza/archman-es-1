NOMBRE

DJabberd::Component - Clase abstracta que representa un componente en DJabberd

SINOPSIS

paquete MiPaquete::DJabberd::MiComponente;
use base DJabberd::Componente;

# Ejemplo de un componente que acepta Comandos Ad-Hoc XEP-0050

sub finalizar {
    mi ($self, $opts) = @_;

    # Deja que la clase padre finalice
    $self->SUPER::finalizar;

    $self->registrar_manejador_iq(
        "set-{http://jabber.org/protocol/commands}command",
        sub { $self->manejar_comando_ad_hoc(@_) },
    );
}

sub manejar_comando_ad_hoc {
    mi ($self, $vhost, $stanza) = @_;

    # maneja el stanza DJabberd::IQ en $stanza,
    # o envía algún tipo de respuesta de error.
}

Esta clase proporciona una clase padre para todos los componentes de DJabberd. Los componentes que heredan de esta clase pueden ser utilizados directamente por el servidor como plugins de entrega, o ser utilizados directamente por otras clases.

Ver DJabberd::Component::Example para un ejemplo de implementación de componente.

USO

Esta clase es una especialización de DJabberd::Agent, orientada a aquellos que desean crear "componentes", que son agentes de software que manejan un dominio XMPP completo, incluyendo todos los nodos dentro de ese dominio.

En la mayoría de los casos, los usuarios de esta clase utilizarán la API expuesta por DJabberd::Agent. Sin embargo, hay algunos comportamientos especiales a tener en cuenta y algunos métodos adicionales que no forman parte de la clase base del agente.

maneja_destino($self, $jid_destino, $vhost)

Esta clase proporciona una versión anulada de este método que responde con un valor verdadero si y solo si el dominio del JID proporcionado coincide con el dominio del componente en sí. Es poco probable que necesites anular esto.

manejar_stanza($self, $vhost, $stanza)

La versión anulada de este método tiene un comportamiento especial al tratar stanzas dirigidas a nodos dentro del dominio manejado por tu componente. (Es decir, JIDs de la forma "usuario@ejemplo.com", en lugar de solo "ejemplo.com".)

Cuando se recibe un stanza de este tipo, se llamará al método "obtener_nodo" para recuperar un objeto que represente ese nodo.

Si deseas un manejo de bajo nivel de todos los stanzas entrantes, puedes anular este método. Al igual que con DJabberd::Agent, anular este método deshabilitará todos los métodos de manejo de nivel superior a menos que delegues al método anulado.

Si deseas conservar los métodos de manejo de nivel superior pero no manejar los nodos como objetos separados, podrías anular este método para llamar a la versión original de DJabberd::Agent de la siguiente manera:

sub manejar_stanza {
    $self->DJabberd::Agent::manejar_stanza(@_);
}

Con este método implementado, el método "obtener_nodo" ya no se utilizará y todos los stanzas adecuados se pasarán a los propios métodos de manejo de esta instancia, independientemente del nombre del nodo del JID de destino.

obtener_nodo($self, $nombre_nodo)

Se llama cuando esta clase desea encontrar un agente para manejar un nodo dado dentro del dominio de este componente.

La mayoría de las implementaciones normales de este método devolverán una instancia de una subclase de DJabberd::Agent::Node, pero en realidad, cualquier subclase de DJabberd::Agent servirá siempre que acepte stanzas dirigidos al nombre_nodo proporcionado.

vcard($self)

La versión anulada de este método devolverá una vCard donde el nombre completo se establece en el nombre de dominio del componente. Las subclases pueden anular esto para hacer algo más sofisticado.

identidades($self)

La versión anulada de este método devuelve una única identidad genérica que indica que el componente es una "rama" en el árbol de Descubrimiento de Servicios. Esto se incluye porque algunos clientes parecen enfadarse un poco si un JID soporta disco pero no tiene identidades.

VER TAMBIÉN
