DESCRIPCIÓ
N

Este módulo es la base para varias otras clases de DJabberd de nivel superior que proporcionan una API para crear agentes de software que se comunican sobre XMPP. Esto incluye componentes que sirven un dominio completo (ver DJabberd::Component) y nodos tipo bot que responden solo a un nombre de nodo específico en un dominio (ver DJabberd::Agent::

Node). 
Es poco probable que otras clases hereden de esta clase
    directamente. La mayoría de los usuarios deberían heredar de una de las subclases de nivel superior
    dependiendo de qué tipo de agente deseen crear. Esta clase proporciona la
    maquinaria básica para manejar stanzas que todos los agentes pueden
usar.

vcard($self, $requester_jid)

Llamado por la implementación integrada de vCard de esta clase para obtener el contenido de la vCard de este agente. Las subclases deben sobrescribir esto y devolver una cadena que contenga el XML que representa el cuerpo de la vcard a devolver, sin el "vCard" elemento contenedor.

La implementación predeterminada simplemente devuelve una vCard vacía. Esto es preferible a no devolver ninguna respuesta en absoluto, porque algunos clientes realizan acciones subóptimas cuando una solicitud de vCard falla.

features($self, $requester_jid)

Llamado por la implementación integrada de Service Discovery (Descubrimiento de Servicios) de esta clase para obtener una lista de "características" soportadas por este agente. Las subclases deben sobrescribir esto y devolver una referencia a un ARRAY que contenga una lista de cadenas con los URI de las características.

La implementación predeterminada devuelve los URI de características correctos para indicar soporte para vCards y Service Discovery. Se sugiere que los métodos que sobrescriben inicialmente llamen a la clase padre para obtener la lista predeterminada y luego añadan sus propias características a la lista según corresponda.

identities($self, $requester_jid)

Llamado por la implementación integrada de Service Discovery de esta clase para obtener una lista de "identidades" expuestas por este agente. Las subclases deben sobrescribir esto y devolver una referencia a un ARRAY que contenga una lista de referencias a ARRAYs de la forma "[$category,$type,$name]", donde estos valores corresponden a los atributos del mismo nombre en la especificación de Service Discovery (XEP-0030).

Por ejemplo, puede ser apropiado que un agente que proporciona una sala de conferencia multiusuario devuelva la identidad "["conference","text","General Discussion"]".

La implementación predeterminada actualmente devuelve una lista vacía. Se sugiere que los métodos que sobrescriben inicialmente llamen a la clase padre para obtener la lista predeterminada y luego añadan sus propias características a la lista según corresponda. Aunque la lista devuelta por esta clase está actualmente vacía, las subclases abstractas de nivel superior pueden añadir sus propias identidades a esta lista.

child_services($self, $requester_jid)

Llamado por la implementación integrada de Service Discovery de esta clase para obtener una lista de servicios secundarios referenciados por este agente. Las subclases deben sobrescribir esto y devolver una referencia a un ARRAY que contenga una lista de referencias a ARRAYs de la forma "[$jid,$name]", donde estos valores corresponden a los atributos del mismo nombre en la especificación de Service Discovery (XEP-0030).

La implementación predeterminada actualmente devuelve una lista vacía. Se sugiere que los métodos que sobrescriben inicialmente llamen a la clase padre para obtener la lista predeterminada y luego añadan sus propias características a la lista según corresponda. Aunque la lista devuelta por esta clase está actualmente vacía, las subclases abstractas de nivel superior pueden añadir sus propios servicios secundarios a esta lista.
