Advertencia Esto es avanzado, cosas de nivel hardcore. No necesita esto a menos que realmente sepa lo que está haciendo. La mayoría de las aplicaciones no necesitarán esto. Históricamente, PhysicsFS proporcionaba acceso al sistema de archivos físico y a los archivos comprimidos dentro de ese sistema de archivos. Sin embargo, a veces necesita más potencia que esto. Quizás necesita proporcionar un archivo comprimido que esté completamente contenido en RAM, o necesita conectar alguna otra API de entrada/salida de archivos a PhysicsFS, o necesita traducir los bits (quizás tiene un archivo .zip estándar que está encriptado, y necesita desencriptarlo al vuelo para el desconocido archivador zip). Un PHYSFS_Io es la interfaz que usan los Archivers para obtener datos del archivo comprimido. Históricamente, esto se ha mapeado a la entrada/salida de archivos al sistema de archivos físico, pero a partir de PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de entrada/salida en tiempo de ejecución.
Esta interfaz no es necesariamente un buen ajuste universal para la entrada/salida. Hay algunos requisitos a tener en cuenta: Solo hacen entrada/salida bloqueante (al menos, por ahora). Necesitan poder duplicarse. Si tiene un identificador de archivo de fopen(), necesita poder crear un clon único de él (para que tengamos dos identificadores al mismo archivo que puedan ambos buscar/leer/etc sin pisarse el uno al otro). Necesitan saber el tamaño de su conjunto de datos completo.
Necesitan poder buscar y rebobinar a demanda. ...en resumen, probablemente no va a escribir una implementación de HTTP. Seguridad de hilos:

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Escribe más datos. Escribe (len) bytes desde (buffer) a la interfaz en la posición de e/s actual. La posición de e/s actual debería avanzar por el número de bytes escritos con éxito.

No tiene que implementar esto; establezca a NULL si no está implementado. Esto solo se usará si el archivo se abre para escritura. Si se establece a NULL, se usará una implementación predeterminada que informa un fallo inmediatamente.

Está permitido almacenar en búfer; una escritura puede tener éxito aquí y luego fallar más tarde al vaciar el búfer. Tenga en cuenta que PHYSFS_setBuffer() puede estar operando a un nivel superior a su e/s, por lo que normalmente no debería implementar sus propias rutinas de búfer.

buffer El búfer desde el que leer los datos. Debe tener al menos (len) bytes de longitud y no puede ser NULL.
len El número de bytes a leer desde (buffer).

Devuelve

número de bytes escritos en el archivo, -1 si hay un fallo completo.
