-d

<
Dump the code generated for the capture filter in a human-readable form, and exit.

-D|--list-interfaces

Print a list of the interfaces on which Dumpcap can capture, and exit. For each network interface, a number and an interface name, possibly followed by a text description of the interface, is printed. The interface name or the number can be supplied to the -i flag to specify an interface on which to capture. The number can be useful on Windows systems, where the interfaces have long names that usually contain a GUID.

-f <filtro de captura>

Establece la expresión del filtro de captura.

Toda la expresión del filtro debe especificarse como un único argumento (lo que significa que si contiene espacios, debe ir entre comillas).

Esta opción puede aparecer varias veces. Si se usa antes de la primera aparición de la opción -i, establece la expresión del filtro de captura por defecto. Si se usa después de una opción -i, establece la expresión del filtro de captura para la interfaz especificada por la última opción -i que aparezca antes de esta opción. Si la expresión del filtro de captura no se establece específicamente, se utiliza la expresión del filtro de captura por defecto si se proporciona.

-F <formato de archivo>

Establece el formato de archivo del archivo de captura de salida escrito utilizando la opción -w. En situaciones que requieran el formato pcapng, como la captura desde múltiples interfaces, esta opción se anulará. La opción -F sin valor mostrará los formatos disponibles. El valor por defecto es el formato pcapng.

Se admiten menos formatos que en tshark(1); esto es intencional por motivos de seguridad. Utilice tshark o capture y luego convierta el archivo con editcap(1) si necesita otro formato.

-g

Esta opción hace que el archivo o archivos de salida se creen con permisos de lectura grupal (lo que significa que el archivo o archivos de salida pueden ser leídos por otros miembros del grupo del usuario que llama).

-h|--help

Imprime la versión y las opciones y sale.

-i|--interface <interfaz de captura>|rpcap://<host>:<puerto>/<interfaz de captura>|TCP@<host>:<puerto>|-

Establece el nombre de la interfaz de red o del pipe a utilizar para la captura de paquetes en vivo.

Los nombres de las interfaces de red deben coincidir con uno de los nombres listados en "tshark -D" (descrito anteriormente); también se puede utilizar un número, tal como lo informa "dumpcap -D".

Si no se especifica ninguna interfaz, Dumpcap busca en la lista de interfaces, eligiendo la primera interfaz no loopback si existen interfaces no loopback, y eligiendo la primera interfaz loopback si no existen interfaces no loopback. Si no hay ninguna interfaz, Dumpcap informa un error y no inicia la captura.

Los nombres de los pipes deben ser el nombre de una FIFO (pipe con nombre) o "-" para leer datos de la entrada estándar. En los sistemas Windows, los nombres de los pipes deben tener el formato "\\.\pipe\nombre_del_pipe". Los datos leídos de los pipes deben estar en formato pcapng o pcap estándar. Los datos Pcapng deben tener la misma endianidad que el host que captura.

"TCP@<host>:<puerto>" hace que Dumpcap intente conectarse al puerto especificado en el host especificado y leer datos pcapng o pcap.

Esta opción puede aparecer varias veces. Al capturar desde múltiples interfaces, el archivo de captura se guardará en formato pcapng, incluso si se especifica -P.

--ifdescr> <descripción>

Utiliza descripción como la descripción en el archivo de captura para la interfaz o pipe especificado anteriormente con -i.

--ifname> <nombre>

Utiliza nombre como el nombre en el archivo de captura para la interfaz o pipe especificado anteriormente con -i.

-I|--monitor-mode

Pone la interfaz en "modo monitor"; esto solo se admite en interfaces Wi-Fi IEEE 802.11 y solo en algunos sistemas operativos.

Tenga en cuenta que en modo monitor, el adaptador podría desvincularse de la red con la que está asociado, por lo que no podrá usar redes inalámbricas con ese adaptador. Esto podría impedir el acceso a archivos en un servidor de red, o la resolución de nombres de host o direcciones de red, si está capturando en modo monitor y no está conectado a otra red con otro adaptador.

Esta opción puede aparecer varias veces. Si se usa antes de la primera aparición de la opción -i, habilita el modo monitor para todas las interfaces. Si se usa después de una opción -i, habilita el modo monitor para la interfaz especificada por la última opción -i que ocurra antes de esta opción.

-k <frecuencia>,[<tipo>],[<frecuencia_central1>],[<frecuencia_central2>>

Establece el canal en la interfaz; esto solo se admite en interfaces Wi-Fi IEEE 802.11 y solo en algunos sistemas operativos.

frecuencia es la frecuencia del canal. tipo es el tipo de canal para 802.11n y posteriores. Los valores para tipo son

NOHT

Utilizado para canales 802.11b/g

HT20

Canal de 20 MHz

HT40-

Canal principal de 40 MHz y un canal secundario inferior

HT40+

Canal principal de 40 MHz y un canal secundario superior

HE40

Canal de 40 MHz, con centerfreq1 como su frecuencia central

HT80

Canal de 80 MHz, con centerfreq1 como su frecuencia central

VHT80+80

Dos canales de 80 MHz combinados, con centerfreq1 y centerfreq2 como las frecuencias centrales de los dos canales

VHT160

Canal de 160 MHz, con centerfreq1 como su frecuencia central

EHT320

Canal de 320 MHz, con centerfreq1 como su frecuencia central

-L|--list-data-link-types

Enumera los tipos de enlace de datos admitidos por la interfaz y sale. Los tipos de enlace informados se pueden usar para la opción -y.

-M

Cuando se usa con -D, -L, -S o --list-time-stamp-types imprime la salida legible por máquina. La salida legible por máquina está destinada a ser leída por Wireshark y TShark; su formato está sujeto a cambios de una versión a otra.

-n

Guarda los archivos como pcapng. Este es el valor por defecto. Esta opción está obsoleta y puede eliminarse.

-N <límite de paquetes>

Limita el número de paquetes utilizados para almacenar los paquetes capturados en memoria mientras se procesa. Si se usa en combinación con la opción -C, ambos límites se aplicarán. Establecer este límite permitirá el uso de un hilo separado por interfaz.

-p|--no-promiscuous-mode

No pongas la interfaz en modo promiscuo. Ten en cuenta que la interfaz podría estar en modo promiscuo por alguna otra razón; por lo tanto, -p no se puede usar para garantizar que el único tráfico que se captura sea el tráfico enviado desde o hacia la máquina en la que se está ejecutando Dumpcap, el tráfico de broadcast y el tráfico multicast a direcciones recibidas por esa máquina.

Esta opción puede aparecer varias veces. Si se usa antes de la primera aparición de la opción -i, ninguna interfaz se pondrá en modo promiscuo. Si se usa después de una opción -i, la interfaz especificada por la última opción -i que ocurra antes de esta opción no se pondrá en modo promiscuo.

-P

Guarda los archivos como pcap en lugar del pcapng predeterminado. En situaciones que requieran pcapng, como la captura desde múltiples interfaces, esta opción se anulará. Esta opción está obsoleta en favor de la opción -F y puede eliminarse.

-q

Al capturar paquetes, no muestres el recuento continuo de paquetes capturados que normalmente se muestra al guardar una captura en un archivo; en su lugar, solo muestra, al final de la captura, un recuento de los paquetes capturados. En los sistemas que admiten la señal SIGINFO, como varios BSD, puede hacer que se muestre el recuento actual escribiendo su carácter de "estado" (normalmente Control-T, aunque podría estar configurado como "deshabilitado" por defecto en al menos algunos BSD, por lo que tendría que establecerlo explícitamente para usarlo).

-Q

Al capturar paquetes, no muestres, en el error estándar, el mensaje inicial indicando en qué interfaces se está realizando la captura, los mensajes que indican a qué archivo se está escribiendo una captura, el recuento continuo de paquetes capturados que normalmente se muestra al guardar una captura en un archivo, y el mensaje al final de la captura que da un recuento de los paquetes capturados. Esto produce menos salida que la opción -q; solo se muestran errores reales en el error estándar.

En los sistemas que admiten la señal SIGINFO, como varios BSD, puede hacer que se muestre el recuento actual escribiendo su carácter de "estado" (normalmente Control-T, aunque podría estar configurado como "deshabilitado" por defecto en al menos algunos BSD, por lo que tendría que establecerlo explícitamente para usarlo).

-s|--snapshot-length <longitud de captura>

Establece la longitud de instantánea predeterminada a utilizar al capturar datos en vivo. No se leerán ni se guardarán en el disco más de snaplen bytes de cada paquete de red en la memoria. Un valor de 0 especifica una longitud de instantánea de 262144, de modo que se capture el paquete completo; este es el valor por defecto.

Esta opción puede aparecer varias veces. Si se usa antes de la primera aparición de la opción -i, establece la longitud de instantánea predeterminada. Si se usa después de una opción -i, establece la longitud de instantánea para la interfaz especificada por la última opción -i que ocurra antes de esta opción. Si la longitud de instantánea no se establece específicamente, se utiliza la longitud de instantánea predeterminada si se proporciona.

-S

Imprime estadísticas para cada interfaz una vez cada segundo.

-t

Utiliza un hilo separado por interfaz.

--temp-dir <directorio>

Especifica el directorio en el que se escribirán los archivos temporales (incluidos los archivos de captura). El comportamiento predeterminado en sistemas compatibles con UNIX, como Linux, macOS, \*BSD, Solaris y AIX, es utilizar la variable de entorno $TMPDIR si está configurada, y el valor predeterminado del sistema, normalmente /tmp, si no lo está. En Windows, se utiliza la variable de entorno %TEMP%, que normalmente se predetermina a %USERPROFI

LE%\AppData\Local\Temp.

-v|--version

Imprime la información completa de la versión y sale.

-w <outfile>

Escribe los datos de los paquetes sin procesar en outfile. Usa "-" para stdout.

-y|--linktype <tipo de enlace de captura>

Establece el tipo de enlace de datos a usar mientras se capturan paquetes. Los valores reportados por -L son los valores que se pueden usar.

Esta opción puede aparecer varias veces. Si se usa antes de la primera aparición de la -i opción, establece el tipo de enlace de captura predeterminado. Si se usa después de una -i opción, establece el tipo de enlace de captura para la interfaz especificada por la última -i opción que aparece antes de esta opción. Si el tipo de enlace de captura no se establece específicamente, se usa el tipo de enlace de captura predeterminado si se proporciona.

--application-flavor [wireshark|stratoshark]

Establece la variante de la aplicación. Hace que la salida de la opción -D y otro comportamiento sean adecuados para la captura de paquetes o la captura de llamadas al sistema y registros. La variante predeterminada es "wireshark".

--capture-comment <comentario>

Agrega un comentario de captura al archivo de salida, si el formato del archivo de salida lo admite.

Esta opción solo está disponible si se envían los paquetes capturados a un solo archivo.

Esta opción puede especificarse varias veces. Ten en cuenta que Wireshark actualmente solo muestra el primer comentario de un archivo de captura.

--list-time-stamp-types

Lista los tipos de marca de tiempo admitidos para la interfaz. Si no se puede establecer ningún tipo de marca de tiempo, no se lista ningún tipo de marca de tiempo.

--time-stamp-type <tipo>

Cambia el método de marca de tiempo de la interfaz.

--update-interval <intervalo>

Establece la longitud de tiempo en milisegundos entre los informes de nuevos paquetes durante una captura. También establece la granularidad de las condiciones de duración del archivo. El valor predeterminado es 100 ms.

OPCIONES DE DIAGNÓSTICO

--log-level <nivel>

Establece el nivel de registro activo. Los niveles admitidos, del más bajo al más alto, son "noisy", "debug", "info", "message", "warning", "critical" y "error". Se imprimirán los mensajes de cada nivel y superiores, por ejemplo, "warning" imprime los mensajes "warning", "critical" y "error", y "noisy" imprime todos los mensajes. Los niveles no distinguen mayúsculas de minúsculas.

--log-fatal <nivel>

Aborta el programa si se registran mensajes en el nivel especificado o superior. Por ejemplo, "warning" aborta ante cualquier mensaje "warning", "critical" o "error".

--log-domains <lista>

Solo imprime los mensajes de los dominios de registro especificados, por ejemplo "GUI,Epan,sshdump". La lista de dominios debe estar separada por comas. Se puede negar con "!" como primer carácter (invierte la coincidencia).

--log-debug <lista>

Fuerza a los dominios especificados a registrar en el nivel "debug". La lista de dominios debe estar separada por comas. Se puede negar con "!" como primer carácter (invierte la coincidencia).

--log-noisy <lista>

Fuerza a los dominios especificados a registrar en el nivel "noisy". La lista de dominios debe estar separada por comas. Se puede negar con "!" como primer carácter (invierte la coincidencia).

--log-fatal-domains <lista>

Aborta el programa si se registran mensajes para los dominios de registro especificados. La lista de dominios debe estar separada por comas.

--log-file <ruta>

Escribe los mensajes de registro y la salida de stderr en el archivo especificado.
