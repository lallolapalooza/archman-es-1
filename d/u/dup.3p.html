dup(3p)

Paquete: man-pages

DUP(3P) Manual del Programador POSIX DUP(3P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

dup, dup2 — duplicar un descriptor de archivo abierto

SINOPSIS

#include <unistd.h>
int dup(int fildes);
int dup2(int fildes, int fildes2);

DESCRIPCION

La función dup() proporciona una interfaz alternativa al servicio proporcionado por fcntl() usando el comando F_DUPFD. La llamada dup(fildes) será equivalente a:

fcntl(fildes, F_DUPFD, 0);

La función dup2() hará que el descriptor de archivo fildes2 se refiera a la misma descripción de archivo abierta que el descriptor de archivo fildes y que comparta cualquier bloqueo, y devolverá fildes2. Si fildes2 ya es un descriptor de archivo válido y abierto, se cerrará primero, a menos que fildes sea igual a fildes2, en cuyo caso dup2() devolverá fildes2 sin cerrarlo. Si la operación de cierre falla al cerrar fildes2, dup2() devolverá -1 sin cambiar la descripción de archivo abierta a la que se refiere fildes2. Si fildes no es un descriptor de archivo válido, dup2() devolverá -1 y no cerrará fildes2. Si fildes2 es menor que 0 o mayor o igual que {OPEN_MAX}, dup2() devolverá -1 con errno establecido a [EBADF].

Tras la finalización exitosa, si fildes no es igual a fildes2, se borrará el flag FD_CLOEXEC asociado con fildes2. Si fildes es igual a fildes2, el flag FD_CLOEXEC asociado con fildes2 no se cambiará.

Si fildes se refiere a un objeto de memoria tipado, el resultado de la función dup2() no está especificado.

VALOR DE RETORNO

Tras la finalización exitosa, se devolverá un entero no negativo, es decir, el descriptor de archivo; de lo contrario, se devolverá -1 y errno se establecerá para indicar el error.

ERRORES

La función dup() fallará si:

EBADF
El argumento fildes no es un descriptor de archivo válido y abierto.
EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.

La función dup2() fallará si:

EBADF
El argumento fildes no es un descriptor de archivo válido y abierto o el argumento fildes2 es negativo o mayor o igual que {OPEN_MAX}.
EINTR
La función dup2() fue interrumpida por una señal.

La función dup2() puede fallar si:

EIO
Ocurrió un error de E/S al intentar cerrar fildes2.

Las siguientes secciones son informativas.

EJEMPLOS

Redirección de la Salida Estándar a un Archivo S

El siguiente ejemplo cierra la salida estándar para el proceso actual, reasigna la salida estándar para que vaya al archivo referenciado por pfd, y cierra el descriptor de archivo original para limpieza.

#include <unistd.h>
...
int pfd;
...
close(1);
dup(pfd);
close(pfd);
...

Redirección de Mensajes de Error

El siguiente ejemplo redirige los mensajes de stderr a stdout.

#include <unistd.h>
...
dup2(1, 2);
...

USO DE APLICACIÓN

Las implementaciones pueden usar descriptores de archivo que deben ser heredados por los procesos hijos para que el proceso hijo siga siendo conforme, por ejemplo, para fines de catálogo de mensajes o rastreo. Por lo tanto, una aplicación que llama a dup2() con un entero arbitrario para fildes2 corre el riesgo de un comportamiento no conforme, y dup2() solo puede usarse de forma portable para sobrescribir valores de descriptores de archivo que la aplicación ha obtenido a través de acciones explícitas, o para los tres descriptores de archivo correspondientes a los flujos de archivo estándar. Para evitar una condición de carrera de filtrar un descriptor de archivo no deseado en un proceso hijo, una aplicación debería considerar abrir todos los descriptores de archivo con el bit FD_CLOEXEC establecido a menos que el descriptor de archivo esté destinado a ser heredado a través de exec.

RACIONALE

La función dup() es redundante. Sus servicios también son proporcionados por la función fcntl(). Se ha incluido en este volumen de POSIX.1‐2017 principalmente por razones históricas, ya que muchas aplicaciones existentes la utilizan. Por otro lado, la función dup2() proporciona servicios únicos, ya que ninguna otra interfaz puede reemplazar de forma atómica un descriptor de archivo existente.

La función dup2() no está marcada como obsoleta porque presenta una versión segura en cuanto a tipos de la funcionalidad proporcionada en una versión insegura en cuanto a tipos por fcntl(). Se utiliza en la vinculación Ada de POSIX.

La función dup2() no está pensada para su uso en regiones críticas como mecanismo de sincronización.

En la descripción de [EBADF], el caso de fildes fuera de rango está cubierto por el caso dado de fildes no siendo válido. Las descripciones para fildes y fildes2 son diferentes porque el único tipo de invalidez relevante para fildes2 es si está fuera de rango; es decir, no importa si fildes2 se refiere a un archivo abierto cuando se realiza la llamada dup2().
