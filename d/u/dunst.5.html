NOMBRE

dunstrc - archivo de configuración de dunst

DESCRIPCIÓN

La configuración se divide en secciones con un formato similar a ini. Cada sección comienza con el nombre de la sección entre corchetes. A continuación, hay una lista de pares clave-valor que especifican la configuración. Los espacios en blanco son puramente cosméticos y no cambian el resultado.

La sección "global" contiene la configuración general que se aplica a todo dunst. El resto de la configuración se puede especificar mediante reglas y se puede ubicar en cualquier sección. Estas reglas pueden cambiar una notificación en función de sus propiedades. Hay reglas de filtrado y reglas de modificación. Las reglas de filtrado especifican a qué notificaciones se aplica la regla. Las reglas de modificación especifican cambios en las notificaciones que coinciden. Algunas secciones especiales tienen filtros implícitos que no se pueden cambiar. Por ejemplo, la sección "global" no tiene filtros: se aplica a todas las notificaciones.

Consulte REGLAS para obtener más detalles.

La sección "experimental" contiene configuraciones experimentales e inestables. Estas opciones pueden cambiar de forma que rompan la compatibilidad entre versiones. Si encuentra un problema con estas nuevas funciones, asegúrese de informarlo.

Sección global

default_pause_level (valores: [0-100], por defecto: 0)
Especifica un nivel de pausa que se establecerá al inicio de dunst. Las notificaciones solo se muestran si su nivel de urgencia es superior al nivel de pausa. Consulte override_pause_level para obtener más información.
monitor (por defecto: 0)
Especifica en qué monitor se mostrarán las notificaciones, ya sea por nombre o por número, comenzando desde 0. Consulte la configuración follow.
follow (valores: [none/mouse/keyboard], por defecto: none)
Define dónde se colocarán las notificaciones en una configuración de múltiples monitores. Todos los valores excepto none anulan la configuración monitor.

En Wayland no hay diferencia entre el foco del ratón y el del teclado. Cuando se usa uno de ellos, el compositor elegirá una salida. Generalmente, será la salida con la que se interactuó por última vez.

none
Las notificaciones se colocarán en el monitor especificado por la configuración monitor.
mouse
Las notificaciones se colocarán en el monitor en el que se encuentre el ratón actualmente.
keyboard
Las notificaciones se colocarán en el monitor que contenga la ventana con foco del teclado.
enable_posix_regex (por defecto: false)
Cuando se establece en true (recomendado), puede usar expresiones regulares POSIX para las reglas de filtrado. Utiliza la sintaxis de expresiones regulares extendidas POSIX: https://en.m.wikibooks.org/wiki/Regular_Expressions/POSIX-Extended_Regular_Expressions.

Si esto se establece en false (no recomendado), dunst usará fnmatch(3) para comparar cadenas. Dunst no pasa ninguna bandera a fnmatch, por lo que no puede aprovechar los patrones extendidos.

La sintaxis POSIX es más potente y eventualmente se convertirá en el valor predeterminado. Las principales diferencias entre POSIX y fnmatch(3) son que POSIX usa ".*" para comodines en lugar de "*" y POSIX permite coincidencias parciales sin necesidad de comodines. Esto significa que el patrón "abc" coincidirá con todas las cadenas que contengan "abc", como "abcdef".

width
El ancho de la ventana de notificación en píxeles. Puede ser un solo número para especificar un ancho constante o dos números para el ancho mínimo y máximo. La notificación se expandirá desde el ancho mínimo según sea necesario.

Ejemplos:

width = 300      # ancho constante de 300
width = (0, 300) # ancho entre 0 y 300

Al establecer un ancho mayor que la pantalla, dunst limitará el ancho al ancho de la pantalla. Por lo tanto, si desea que la notificación se extienda dinámicamente por toda la pantalla, puede establecer un número suficientemente alto que ninguna de sus pantallas exceda (por ejemplo, 10000).

height
La altura de cada notificación en píxeles. Puede ser un solo número para especificar una altura constante o dos números para el ancho mínimo y máximo. La notificación se expandirá desde la altura mínima según sea necesario.

Ejemplos:

height = 300      # altura constante de 300
height = (0, 300) # altura entre 0 y 300

Tenga en cuenta que, a diferencia del ancho, las diferentes notificaciones pueden tener valores de altura diferentes.

Dunst v1.11 y anteriores no admiten una altura dinámica y height acepta un solo valor cuyo comportamiento es equivalente a (0, valor).

notification_limit (por defecto: 20)
El número de notificaciones que pueden aparecer a la vez. Cuando se alcanza este límite, las notificaciones adicionales se pondrán en cola y se mostrarán cuando las que se muestran actualmente expiren o se descarten manualmente. El valor 0 significa sin límite. Si indicate_hidden es true, el límite especificado se reduce en 1 y la última notificación es un mensaje que informa cuántas notificaciones ocultas están esperando para ser mostradas. Consulte la entrada indicate_hidden para obtener más información.

override_pause_level (valores: [0-100], por defecto: 0)
Una notificación aparecerá siempre que el override_pause_level de la notificación sea mayor que el nivel de pausa. Establecer esto a valores distintos de 0 le permite crear modos de pausa parciales, donde las notificaciones más urgentes pasan, pero las menos urgentes permanecen en pausa.

Por ejemplo, puede establecer el override_pause_level de una notificación de batería baja en 60 y luego establecer el nivel de pausa de dunst en 60. Esto hará que dunst solo muestre la notificación del nivel de batería (y otras notificaciones con override_pause_level >= 60), mientras suspende otras.

Atajos de teclado (solo X11)

Los atajos de teclado se definen con el siguiente formato: "Modificador+tecla", donde el modificador es uno de ctrl,mod1,mod2,mod3,mod4 y la tecla es cualquier tecla del teclado.

Tenga en cuenta que los atajos de teclado se han trasladado a la sección global de la configuración por coherencia con otras opciones.

Alternativamente, también puede definir atajos dentro de su gestor de ventanas y enlazarlos a comandos de dunstctl(1).

Wayland no permite que las aplicaciones escuchen eventos globales del teclado, por lo que esta función solo se puede implementar para X.

DUNSTCT

L

Dunst ahora contiene un comando de control de línea de comandos que se puede usar para interactuar con él. Soporta todas las funciones que anteriormente se hacían solo a través de atajos de teclado, pero también tiene muchas funcionalidades adicionales. Para más información, consulte dunstc

HISTORIA

L

Dunst guarda un número de notificaciones (especificado por history_length) en memoria. Estas notificaciones pueden ser recuperadas (es decir, mostradas de nuevo) llamando a dunstctl history (consulte dunstctl(1)). Si estas notificaciones expirarán como si se hubieran enviado recientemente depende del valor de la configuración sticky_history. Las acciones se invalidan una vez que la notificación se cierra, por lo que no puede ejecutar esa acción cuando recupera una notificación del

historial.

Las notificaciones pasadas se muestran de nuevo en orden de último en entrar, primero en salir, lo que significa que presionar la tecla de historial una vez mostrará la notificación más reciente que fue cerrada/expirad

a
.

WAYLAN

D

Dunst tiene soporte de Wayland desde la versión 1.6.0. Debido a que el protocolo Wayland está más enfocado en la seguridad, algunas cosas que son posibles en X11 no son posibles en Wayland. Esas diferencias se reflejan en la configuración. Las principales cosas que cambian son que dunst en Wayland no puede usar atajos globales, use dunstctl en su

lugar.

Algunas características de dunst en Wayland podrían necesitar que su compositor soporte cierto protocolo. Dunst le advertirá si una función opcional no es soportada y deshabilitará la funcionalidad correspondiente

.

La detección de pantalla completa funciona en wayland con algunas limitaciones (consulte fullscreen). Si quiere que las notificaciones aparezcan sobre ventanas de pantalla completa, establezca layer = overlay en las opciones

globales.

Tenga en cuenta que las mismas limitaciones existen al usar

XWayland.

Si algo no funciona correctamente en Wayland, por favor presente un reporte de error. Mientras tanto, puede intentar si la salida X11 funciona en wayland. Use force_xwayland = true para

eso.

Si tiene sus notificaciones de dunst en el mismo lado de su pantalla que su barra de estado, podría notar que sus notificaciones aparecen un poco más arriba o más abajo que en X11. Esto se debe a que la notificación no puede colocarse encima de su barra de estado. Las notificaciones se colocan de forma relativa a su barra de estado, haciendo que aparezcan más arriba o más abajo por la altura de su barra de estado. No podemos hacer nada sobre ese

comportamiento.

Tenga en cuenta que dunst crea una "capa de escritorio" usando el protocolo lay

er shell y no una ventana Wayland regular. Esto tiene algunas limitaciones como
se indicó arriba. Por ejemplo, no puede establecer un título/clase de ventana.

SCRIPTIN

G

Dentro de las reglas puede especificar un script a ejecutar cada vez que la regla coincida asignando la opción 'script' al nombre del script a

ejecutar.

Cuando se llama al script, los detalles de la notificación que lo activó se pasarán a través de variables de entorno. Las siguientes variables están disponibles: DUNST_APP_NAME, DUNST_SUMMARY, DUNST_BODY, DUNST_ICON_PATH, DUNST_URGENCY, DUNST_ID, DUNST_PROGRESS, DUNST_CATEGORY, DUNST_STACK_TAG, DUNST_URLS, DUNST_TIMEOUT, DUNST_TIMESTAMP, DUNST_DESKTOP_ENTRY, y DUNST_STACK_TAG

.

Otra forma, menos recomendada, de obtener los detalles de las notificaciones desde un script es a través de parámetros de línea de comandos. Estos se pasan al script en el siguiente orden: appname, summary, body, icon_path, urgency

.

Donde DUNST_ICON_PATH o icon_path es la ruta absoluta al archivo de icono si existe uno. DUNST_URGENCY o urgency es uno de "LOW", "NORMAL" o "CRITICAL". DUNST_URLS es una lista de urls separadas por saltos de línea asociadas con la

notificación.

Tenga en cuenta que algunas variables pueden estar

vacías.

Si la notificación es suprimida, el script no se ejecutará a menos que always_run_script esté establecido en

El parámetro script se expande de acuerdo con wordexp(3) con la sustitución de comandos deshabilitada. Si el valor expandi

ACCIONE

S

Dunst permite a los notificadores (es decir, los programas que envían las notificaciones) especificar acciones. Dunst tiene soporte tanto para mostrar indicadores de estas, como para interactuar con estas

acciones.

Si "show_indicators" es verdadero y una notificación tiene una acción, se antepondrá un "(A)" al formato de la notificación. Del mismo modo, se anteponen "(U)" a las notificaciones con URLs. Es posible interactuar con las notificaciones que tienen acciones independientemente de este ajuste, aunque puede no ser obvio qué notificaciones TIENEN

acciones.

La tecla de atajo "context" se utiliza para interactuar con estas acciones, mostrando un menú de las acciones posibles. Esta característica requiere la presencia de "dmenu" o un reemplazo compatible con

dmenu.

Alternativamente, puedes invocar una acción con un clic central en la notificación. Si hay exa

ctamente una acción asociada, o una está marcada como predeterminada, se invoca esa. Si hay mú
ltiples, se muestra el menú de contexto. Lo mismo se aplica a las URLs cuando no hay acciones.
