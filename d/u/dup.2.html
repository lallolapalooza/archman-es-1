DESCRIPCIÓ

N

La llamada al sistema dup() asigna un nuevo descriptor de archivo que se refiere a la misma descripción de archivo abierto que el descriptor oldfd. (Para una explicación de las descripciones de archivo abierto, ver open(2).) Se garantiza que el número del nuevo descriptor de archivo sea el número de descriptor de archivo más bajo que no estuviera en uso en el proceso que realiza la

llamada.

Después de una devolución exitosa, los descriptores de archivo antiguos y nuevos pueden usarse indistintamente. Dado que los dos descriptores de archivo se refieren a la misma descripción de archivo abierto, comparten el desplazamiento del archivo y los indicadores de estado del archivo; por ejemplo, si el desplazamiento del archivo se modifica mediante el uso de lseek(2) en uno de los descriptores de archivo, el desplazamiento también cambia para el otro descriptor de

archivo.

Los dos descriptores de archivo no comparten los indicadores de descriptor de archivo (el indicador close-on-exec). El indicador close-on-exec (FD_CLOEXEC; ver fcntl(2)) para el descriptor duplicado está

desactivado.

dup2(

)

La llamada al sistema dup2() realiza la misma tarea que dup(), pero en lugar de usar el descriptor de archivo no utilizado con el número más bajo, usa el número de descriptor de archivo especificado en newfd. En otras palabras, el descriptor de archivo newfd se ajusta para que ahora se refiera a la misma descripción de archivo abierto que oldfd

.

Si el descriptor de archivo newfd estaba previamente abierto, se cierra antes de ser reutilizado; el cierre se realiza silenciosamente (es decir, cualquier error durante el cierre no es reportado por dup2())

.

Los pasos de cierre y reutilización del descriptor de archivo newfd se realizan de forma atómica. Esto es importante, porque intentar implementar funcionalidad equivalente usando close(2) y dup() estaría sujeto a condiciones de carrera, por las cuales newfd podría ser reutilizado entre los dos pasos. Tal reutilización podría ocurrir porque el programa principal es interrumpido por un manejador de señales que asigna un descriptor de archivo, o porque un hilo paralelo asigna un descriptor de

archivo.

Tenga en cuenta los siguientes

puntos:
•
Si oldfd no es un descriptor de archivo válido, entonces la llamada falla, y newfd no se
cierra.
•
Si oldfd es un descriptor de archivo válido, y newfd tiene el mismo valor que oldfd, entonces dup2() no hace nada, y devuelve ne
wf
d
.

NOTA

S

El error devuelto por dup2() es diferente de aquel devuelto por fcntl(..., F_DUPFD, ...) cuando newfd está fuera de rango. En algunos sistemas, dup2() también a veces devuelve EINVAL como F_DUPFD

.

Si newfd estaba abierto, cualquier error que hubiera sido reportado en el momento de close(2) se pierde. Si esto es una preocupación, entonces—a menos que el programa sea de un solo hilo y no asigne descriptores de archivo en manejadores de señales—el enfoque correcto es no cerrar newfd antes de llamar a dup2(), debido a la condición de carrera descrita anteriormente. En su lugar, se podría usar código como el

siguiente: 


/* Obtener un duplicado de 'newfd' que pueda ser usado
   posteriormente para verificar errores de close(); un error EBADF
   significa que 'newfd' no estaba abierto.  */
tmpfd = dup(newfd);
if (tmpfd == -1 && errno != EBADF) {
    /* Manejar error inesperado de dup().  */
}
/* Duplicar atómicamente 'oldfd' en 'newfd'.  */
if (dup2(oldfd, newfd) == -1) {
    /* Manejar error de dup2().  */
}
/* Ahora verificar errores de close() en el archivo originalmente
   referenciado por 'newfd'.  */
if (tmpfd != -1) {
    if (close(tmpfd) == -1) {
        /* Manejar errores de close.  */
    }
}
