DUNE-INIT(1) Manual de Dune DUNE-INIT(1)

NOMBRE

dune-init - Grupo de comandos para inicializar componentes de Dune.

SINOPSIS

dune init project NOMBRE [RUTA] [OPCIÓN]...

dune init executable NOMBRE [RUTA] [OPCIÓN]...

dune init library NOMBRE [RUTA] [OPCIÓN]...

dune init test NOMBRE [RUTA] [OPCIÓN]...

DESCRIPCIÓN

dune init COMPONENTE NOMBRE [RUTA] [OPCIÓN]... inicializa una nueva configuración de dune para un componente del tipo especificado por el subcomando COMPONENTE, llamado NOMBRE, con campos determinados por las OPCIÓNes proporcionadas.

Ejecuta un subcomando con --help para obtener detalles sobre sus argumentos admitidos.

Si se proporciona la RUTA opcional, debe ser la ruta a un directorio, y el componente se creará allí. De lo contrario, se crea en un hijo del directorio de trabajo actual, llamado NOMBRE. Para inicializar un componente en el directorio de trabajo actual, utiliza `.` como RUTA.

Se puede suministrar cualquier prefijo del nombre de un COMANDO en lugar del nombre completo (como se ilustra en la sinopsis).

Para más detalles, consulta https://dune.readthedocs.io/en/stable/usage.html#initializing-components

COMANDOS

executable [OPCIÓN]… NOMBRE [RUTA]
Un ejecutable binario.
library [OPCIÓN]… NOMBRE [RUTA]
Una librería OCaml.
project [OPCIÓN]… NOMBRE [RUTA]
Un proyecto es una composición predefinida de componentes organizados en una estructura de directorios estándar. El tipo de proyecto inicializado se determina por el valor de la bandera --kind y, por defecto, es un proyecto ejecutable, compuesto por una librería, un ejecutable y un componente de prueba.
test [OPCIÓN]… NOMBRE [RUTA]
Un entorno de pruebas. (Para pruebas en línea, utiliza la bandera --inline-tests junto con los otros tipos de componentes.)

OPCIONES COMUNES

--help[=FMT] (predeterminado:auto)
Muestra esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable de entorno TERM sea dumb o indefinida.
--version
Muestra la información de la versión.

ESTADO DE SALIDA

dune init sale con:

0
en caso de éxito.
1
si ocurrió un error.
130
si fue interrumpido por una señal.

EJEMPLOS

1.
Generar un esqueleto de proyecto para un ejecutable llamado `myproj' en un nuevo directorio llamado `myproj', dependiendo de la librería bos y usando pruebas en línea junto con ppx_inline_test:
      dune init project myproj --libs bos --ppx ppx_inline_test --inline-tests
2.
Configurar un componente ejecutable llamado `myexe' en un archivo dune en el directorio actual:
      dune init executable myexe
3.
Configurar un componente de librería llamado `mylib' en un archivo dune en el directorio ./src dependiendo de las librerías core y cmdliner, los preprocesadores ppx_let y ppx_inline_test, y declarado como que usa pruebas en línea:
      dune init library mylib src --libs core,cmdliner --ppx ppx_let,ppx_inline_test --inline-tests
4.
Configurar un componente de prueba llamado `mytest' en un archivo dune en el directorio ./test que dependa de `mylib':
      dune init test mytest test --libs mylib
