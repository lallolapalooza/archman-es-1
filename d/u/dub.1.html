DESCRIPCIÓ

N

Gestiona el proyecto DUB en el directorio actual. DUB puede servir como sistema de

compilación y gestor de paquetes, manteniendo automáticamente un seguimiento de las
dependencias del proyecto, tanto descargándolas como enlazándolas en la aplicación.

Compila el paquete y ejecuta todas las pruebas unitarias contenidas.

Si no se proporciona una configuración explícita, se preferirá una configuración "unittest" existente para las pruebas. Si no existe ninguna, se utilizará la primera configuración de tipo biblioteca, y si tampoco existe, se elige la primera configuración

ejecutable.

Cuando se especifica un archivo principal personalizado (--main-file), solo se pueden usar configuraciones de biblioteca. De lo contrario, dependiendo del tipo de la configuración seleccionada, se usará un archivo principal existente (y debe ajustarse adecuadamente para ejecutar solo las pruebas unitarias para 'version(unittest)'), o DUB generará uno para las configuraciones de tipo

biblioteca.

Finalmente, si el paquete contiene una dependencia al

Imprime una descripción de compilación JSON para el paquete raíz y todas sus dependencias en un formato similar al de un archivo de descripción de paquete JSON. Esto es útil principalmente para los IDE.

Se aplican todas las opciones habituales que también se utilizan para

build/run/generate.

Cuando se proporciona --data=VALUE, se imprimirán en su lugar configuraciones de compilación específicas de un proyecto (por defecto, formateadas para el compilador

actual).

La opción --data=VALUE se puede especificar varias veces para obtener varias piezas de información a la vez. También se acepta una lista separada por comas (ej: --data=dflags,libs). Los datos se emitirán en el mismo orden solicitado en la línea de

comandos.

Este comando utiliza la utilidad Dustmite para aislar la causa de los errores de compilación en un proyecto DUB.

Creará una copia de todos los paquetes involucrados y ejecutará dustmite en esta copia, dejando un caso de prueba

reducido.

La determinación de la condición de error deseada se realiza verificando el código de estado del compilador/enla

zador, así como su salida (stdout y stderr combinados). Si se proporciona --program-status o --program-re
gex y el binario generado es un ejecutable, se ejecutará y su salida también se incorporará a la decisión final.

Cuando se ejecuta con uno o más argumentos, independientemente de la ubicación en la que se ejecute, obtendrá los paquetes que coincidan con el/los argumento(s). Ejemplos: $ dub fetch vibe-d $ dub fetch vibe-d@v0.9.0 --cache=local --recursive

Cuando se ejecuta en un proyecto sin argumentos, obtendrá todas las dependencias de ese proyecto. Si el proyecto no tiene dependencias establecidas (no hay 'dub.selections.json'), también realizará la resolución de dependencias. Ejemplo: $ cd myProject && dub

fetch

Tenga en cuenta que 'build', 'run' y cualquier otro comando que necesite paquetes realizarán automáticamente el fetch, por lo que generalmente no es necesario ejecutar este comando antes que ningún

otro.

th
Añade una ruta de búsqueda de paquetes predeterminada. Se buscarán todas las subcarpetas directas de esta ruta en busca de descripciones de paquetes y estarán disponibles como paquetes. Usar este comando tiene el mismo efecto que llamar a 'dub add-local' manualmente en cada una de las subcarpetas.

Cualquier paquete registrado usando add-path tendrá preferencia sobre los paquetes descargados del registro de paquetes al buscar dependencias durante una operación de

compilación.

La versión de los paquetes se determinará por uno de los siguientes métodos:
- Para copias de trabajo de GIT, se utiliza la última etiqueta (git describe) para determinar la versión
- Si el paquete contiene un campo "version" en la descripción del paquete, se utiliza este
- Si ninguno de los

anteriores aplica,
se asume "~master"
