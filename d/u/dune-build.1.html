NAME

dune-build - build system

SYNOPSIS

dune build [OPTIONS] [TARGETS...]

DESCRIPTION

Builds the project. When no targets are given, it builds the default target, which is usually the minimal set of targets required for tooling such as Merlin (useful for quickly detecting errors).

When no targets are specified, dune builds the target @install if the --release option is passed, and @all otherwise.

Targets are usually directories and are interpreted relative to the workspace root. When a target is a directory, dune builds all the libraries and executables located in that directory and all its subdirectories.

Targets can also be specific files (e.g. dune build src/main.exe), which will be built. This is mostly useful for executables.

It is also possible to specify targets starting with '@'. These are called Aliases. They are defined in the corresponding dune files.

For instance, @all is an alias for all the targets of the project. @install is an alias for the targets that need to be built to install the project.

By default, dune selects a build directory named `_build' in the current directory. This can be changed using the DUNE_BUILD_DIR environment variable.

The build is reproducible, meaning that given the same inputs, dune will always produce the same outputs. This is achieved by default by disabling the use of the cache and by selecting a specific profile. This behaviour can be changed by passing --release.

When this option is given, dune installs the specified targets in the current environment. The targets are specified using the same syntax as for dune-build(1).

It's possible to specify targets that are not built by default using the --target option. This option takes a comma-separated list of targets.

For instance, to build only the executables in the current directory, you would use:

dune build @exe

To build everything that is not an executable, you would use:

dune build @all --without-targets @exe

OPTIONS

--build-dir=DIR
Use directory DIR as the build directory.
--bump-requires
Bump the specified requirements to the given version.
--color=MODE
MODE must be one of: never, always, auto. Control whether to use ANSI color codes. The default is auto.
-j N
Use N parallel jobs. The default is to use the number of CPUs available.
--display=MODE
Change the way build results are displayed. Supported modes: quiet, progress, verbose, short, list, no-print-directory.
--dry-run
Do not run any build actions, just print them.
--file-edit=SH_EXPR
Run SH_EXPR on generated files to edit them. Note that this is a temporary measure and may be removed in the future.
--fix
Fix the specified files. This is a temporary measure and may be removed in the future.
--ignore-promoted-rules
Do not promote any rules to the source tree. This is mostly for releases.
--keep-build-stderr
Keep standard error output from build actions when they fail.
--no-print-directory
Do not print the directory name when entering it.
--no-config
Do not load the user's configuration file.
--no-parallel
Do not run parallel jobs.
--pass-destination=DIR
Use this directory as the destination for the installed files. This option is intended for scripts.
--promote=MODE
Set promotion mode. MODE must be one of: auto, always, never. The default is auto.
--only-packages=PACKAGES
Build only the specified packages. This is a comma-separated list of package names. Note that this has the same effect as deleting the relevant stanzas from dune files. It is mostly meant for releases. During development, it is likely that what you want instead is to build a particular <package>.install target.
-p PACKAGES, --for-release-of-packages=PACKAGES (required)
Shorthand for --release --only-packages PACKAGE. You must use this option in your <package>.opam files, in order to build only what's necessary when your project contains multiple packages as well as getting reproducible builds.
--print-metrics
Print out various performance metrics after every build.
--profile=VAL (absent DUNE_PROFILE env)
Select the build profile, for instance dev or release. The default is dev.
--promote-install-files[=VAL] (default=true)
Promote any generated <package>.install files to the source tree.
--release
Put dune into a reproducible release mode. Shorthand for --root . --ignore-promoted-rules --no-config --profile release --always-show-command-line --promote-install-files --require-dune-project-file --default-target @install. You should use this option for release builds. For instance, you must use this option in your <package>.opam files. Except if you already use -p, as -p implies this option.
--require-dune-project-file[=VAL] (default=true)
Fail if a dune-project file is missing.
--root=DIR
Use this directory as workspace root instead of guessing it. Note that this option doesn't change the interpretation of targets given on the command line. It is only intended for scripts.
--store-orig-source-dir (absent DUNE_STORE_ORIG_SOURCE_DIR env)
Store original source location in dune-package metadata.
--terminal-persistence=MODE
Change how the log of build results are displayed to the console between rebuilds while in --watch mode. Supported modes: preserve, clear-on-rebuild, clear-on-rebuild-and-flush-history.
--trace-extended
Output extended trace data (requires trace-file).
--trace-file=FILE
Output trace data in catapult format (compatible with chrome://tracing).
--verbose
Same as --display verbose
--version
Show version information.
--watch-exclusions=REGEX
Adds a POSIX regular expression that will exclude matching directories from `dune build --watch`. The option --watch-exclusions can be repeated to add multiple exclusions. Semicolons can be also used as a separator. If no exclusions are provided, then a standard set of exclusions is used; however, if one or more --watch-exclusions are used, none of the standard exclusions are used. The standard exclusions are: ^_opam /_opam ^_esy /_esy ^\.#.* /\.#.* ~$ ^#[^#]*#$ /#[^#]*#$ ^4913$ /4913$ /.git /.hg :/windows
--workspace=FILE (absent DUNE_WORKSPACE env)
Use this specific workspace file instead of looking it up.
-x VAL
Cross-compile using this toolchain.

MORE HELP

Use `dune COMMAND --help' for help on a single command.

EXIT STATUS

dune build exits with:

0
on success.
1
if an error happened.
130
if it was interrupted by a signal.

ENVIRONMENT

These environment variables affect the execution of build:

CLICOLOR
If different than 0, ANSI colors are supported and should be used when the program isn't piped. If equal to 0, don't output ANSI color escape codes
CLICOLOR_FORCE
If different than 0, ANSI colors should be enabled no matter what.
DUNE_BUILD_DIR
Specified build directory. _build if unspecified
DUNE_CACHE
Enable or disable Dune cache (one of disabled, enabled-except-user-rules or enabled). Default is `enabled-except-user-rules'.
DUNE_CACHE_CHECK_PROBABILITY
Check build reproducibility by re-executing randomly chosen rules and comparing their results with those stored in Dune cache. Note: by increasing the probability of such checks you slow down the build. The default probability is zero, i.e. no rules are checked.
DUNE_CACHE_ROOT
If set, determines the location of the machine-global shared cache.
DUNE_CACHE_STORAGE_MODE
Dune cache storage mode (one of auto, hardlink or copy). Default is `hardlink'.
DUNE_DEBUG_PACKAGE_LOGS
Always print the standard logs when building packages
DUNE_DIFF_COMMAND
Shell command to use to diff files. Use - to disable printing the diff.
DUNE_DISABLE_PROMOTION
Disable all promotion rules
DUNE_INSTRUMENT_WITH
Enable instrumentation by BACKENDS. BACKENDS is a comma-separated list of library names, each one of which must declare an instrumentation backend.
DUNE_PROFILE
Build profile. dev if unspecified or release if -p is set.
DUNE_SANDBOX
Sandboxing mode to use by default. (see --sandbox)
DUNE_STORE_ORIG_SOURCE_DIR
Store original source location in dune-package metadata.
DUNE_WORKSPACE
Use this specific workspace file instead of looking it up.

EXAMPLES

1.
Build all targets in the current source tree:
      dune build
2.
Build targets in the `./foo/bar' directory:
      dune build ./foo/bar
3.
Build the minimal set of targets required for tooling such as Merlin (useful for quickly detecting errors):
      dune build @check
4.
Run all code formatting tools in-place:
      dune build --auto-promote @fmt
