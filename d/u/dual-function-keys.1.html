Tocar para una tecla, mantener para

Ideal para teclas modificadoras como: mantener para ctrl, tocar para

Un salvador de manos para aquellos con movilidad de dedos

a

No asignes el mismo modificador a dos teclas que pretendas pulsar al mismo tiempo, ya que interferirán entre sí. Usa las versiones izquierda y derecha de los modificadores, p. ej. alt-tab con

espacio-caps:

  - KEY: KEY_CAPSLOCK

- JOB: "intercept -g $DEVNODE | dual-f

n-keys.yaml> | uinput -d $DEVNODE"
DEVICE: NAME: <nombre del teclado>

El nombre puede determinarse

ejecutando: 
sudo uinput -p -d
/dev/input/by-id
/

donde X es el dispositivo con el nombre que parece el de tu teclado. Asegúrate de que todos los EV_KEY estén presentes bajo EVENTS. Si no puedes encontrar tu teclado bajo /dev/input/by-id, mira los dispositivos directamente bajo

/dev/input.

Consulta Herramientas de Intercepción: Cómo Funciona (https://gitlab.com/interception/linux/tools#how-it-works) para más información sobre uinput

-p.

Normalmente el nombre es suficiente para identificar únicamente el teclado, sin embargo algunos teclados registran muchos dispositivos como un ratón virtual. Puedes ejecutar dual-function-keys para todos los dispositivos, sin embargo prefiero ejecutarlo solo para el teclado

real.

Múltiples

Dispositivos

Al usar entradas de múltiples dispositivos, p. ej. ctrl-scroll, puede ser necesario multiplexar (https://gitlab.com/interception/linux/tools#mux) esos dispositivos para que dual-function-keys funcione a través de estos dispositivos, p. ej. scroll consumiendo

ctrl.

Ejemplo de configuración de udevmon para un ratón y un

teclado: 
- CMD: mux -c dfk -c my-keyboard -c my-mouse
- JOB:
  - mux -i dfk | dual-function-keys -c /etc/interception/dual-function-keys/my-cfg.yaml | mux -o my-
keyboard -o my-mouse - mux -i my-keyboard | uinput -c /etc/interception/udevmon.d/my-keyboard.yaml - mux -i my-mouse | uinput -c /etc/interception/ud
evmon.d/my-mouse.yaml - JOB: intercept -g $DEVNODE | mux -o dfk DEVICE: NAME: AT Translated Set 2 keyboard EVENTS: EV_KEY: [ KEY_LEFTCTRL
] - JOB: intercept -g $DEVNODE | mux -o dfk DEVICE: NAME: Razer Razer Naga Trinity EVENTS: EV_REL: [REL_WHEEL] EV_KEY: [BTN_LEFT]

En el ejemplo anterior, my-keyboard.yaml y my-mouse.yaml representan los dispositivos virtuales que udevmon creará para emitir eventos. Son generados una vez desde el propio dispositivo, p.

ej. 
sudo uinput -p -d
/dev/input/by-id/u
sb-my-keyboard-kbd
> my-keyboard.yaml

Una alternativa, si quieres vivir peligrosamente (https://gitlab.com/interception/linux/plugins/dual-function-keys/-/issues/31#note_725722450), es generar la configuración del dispositivo virtual sobre la marcha, p. ej.

- CMD: mux -c dfk -c my-keyboard -c my-mouse
- JOB:
  - mux -i dfk | dual-function-keys -c /etc/interception/dual-function-keys/my-cfg.yaml | mux -o my-keyboard -o my-mouse
  - mux -i my-keyboard | uinput -d /dev/input/by-path/my-keyboard-event-kbd
  - mux -i my-mouse | uinput -d /dev/input/by-id/usb-my-mouse-event-mouse
- JOB: intercept -g $DEVNODE | mux -o dfk
  DEVICE:

ADVERTENCI

AS

Como siempre, hay una advertencia: dual-function-keys opera con códigos de tecla crudos, no con símbolos de tecla, como los ve X11 o

Wayland.

Si tienes algo que modifique el mapeo código de tecla->símbolo de tecla, como XKB (https://www.x.org/wiki/XKB/) o xmodmap (https://wiki.archlinux.org/index.php/Xmodmap), ten en cuenta que dual-function-keys opera antes que

ellos.

Algunos usos comunes de XKB que podrían encontrarse en tu configuración de

X11: 
    Option "XkbModel" "pc105
" Option "XKbLayout"
"us" Option "XkbVari
ant" "dvp" Option "X
kbOptions" "caps:escape"
