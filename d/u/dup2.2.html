dup(2) Manual de llamadas al sistema dup(2)

NOMBRE

dup, dup2, dup3 - duplicar un descriptor de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int dup(int oldfd);
int dup2(int oldfd, int newfd);
#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#include <fcntl.h>              /* Definición de constantes O_* */
#include <unistd.h>
int dup3(int oldfd, int newfd, int flags);

DESCRIPCIÓN

La llamada al sistema dup() asigna un nuevo descriptor de archivo que se refiere a la misma descripción de archivo abierto que el descriptor oldfd. (Para una explicación de las descripciones de archivo abiertas, ver open(2)). El nuevo número de descriptor de archivo garantizado es el descriptor de archivo no utilizado de menor número en el proceso llamante.

Después de un retorno exitoso, los descriptores de archivo viejos y nuevos pueden ser usados indistintamente. Dado que los dos descriptores de archivo se refieren a la misma descripción de archivo abierta, comparten el desplazamiento del archivo y los indicadores de estado del archivo; por ejemplo, si el desplazamiento del archivo se modifica usando lseek(2) en uno de los descriptores de archivo, el desplazamiento también cambia para el otro descriptor de archivo.

Los dos descriptores de archivo no comparten los indicadores de descriptor de archivo (el indicador close-on-exec). El indicador close-on-exec (FD_CLOEXEC; ver fcntl(2)) para el descriptor duplicado está desactivado.

dup2()

La llamada al sistema dup2() realiza la misma tarea que dup(), pero en lugar de usar el descriptor de archivo no utilizado de menor número, usa el número de descriptor de archivo especificado en newfd. En otras palabras, el descriptor de archivo newfd se ajusta para que ahora se refiera a la misma descripción de archivo abierta que oldfd.

Si el descriptor de archivo newfd estaba previamente abierto, se cierra antes de ser reutilizado; el cierre se realiza silenciosamente (es decir, cualquier error durante el cierre no es reportado por dup2()).

Los pasos de cierre y reutilización del descriptor de archivo newfd se realizan de forma atómica. Esto es importante, ya que intentar implementar una funcionalidad equivalente usando close(2) y dup() estaría sujeto a condiciones de carrera, donde newfd podría ser reutilizado entre los dos pasos. Dicha reutilización podría ocurrir porque el programa principal es interrumpido por un manejador de señales que asigna un descriptor de archivo, o porque un hilo paralelo asigna un descriptor de archivo.

Tenga en cuenta los siguientes puntos:

•
Si oldfd no es un descriptor de archivo válido, la llamada falla y newfd no se cierra.
•
Si oldfd es un descriptor de archivo válido y newfd tiene el mismo valor que oldfd, entonces dup2() no hace nada y devuelve newfd.

dup3()

dup3() es lo mismo que dup2(), excepto que:

•
El llamante puede forzar que se establezca el indicador close-on-exec para el nuevo descriptor de archivo especificando O_CLOEXEC en flags. Ver la descripción del mismo indicador en open(2) para conocer las razones por las que esto puede ser útil.
•
Si oldfd es igual a newfd, entonces dup3() falla con el error EINVAL.

VALOR DE RETORNO

En caso de éxito, estas llamadas al sistema devuelven el nuevo descriptor de archivo. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EBADF
oldfd no es un descriptor de archivo abierto.
EBADF
newfd está fuera del rango permitido para descriptores de archivo (ver la discusión de RLIMIT_NOFILE en getrlimit(2)).
EBUSY
(Solo Linux) Puede ser devuelto por dup2() o dup3() durante una condición de carrera con open(2) y dup().
EINTR
La llamada dup2() o dup3() fue interrumpida por una señal; ver signal(7).
EINVAL
(dup3()) flags contiene un valor inválido.
EINVAL
(dup3()) oldfd era igual a newfd.
EMFILE
Se ha alcanzado el límite por proceso del número de descriptores de archivo abiertos (ver la discusión de RLIMIT_NOFILE en getrlimit(2)).
ENOMEM
No había suficiente memoria del kernel disponible.

NOTAS

El error devuelto por dup2() es diferente del devuelto por fcntl(..., F_DUPFD, ...) cuando newfd está fuera de rango. En algunos sistemas, dup2() también devuelve a veces EINVAL como F_DUPFD.

Si newfd estaba abierto, cualquier error que pudiera haberse reportado en el momento de close(2) se pierde. Si esto es una preocupación, entonces —a menos que el programa sea monohilo y no asigne descriptores de archivo en manejadores de señales— el enfoque correcto es no cerrar newfd antes de llamar a dup2(), debido a la condición de carrera descrita anteriormente. En su lugar, se podría usar un código como el siguiente:


/* Obtener un duplicado de 'newfd' que posteriormente
   pueda ser usado para verificar errores de close(); un error EBADF
   significa que 'newfd' no estaba abierto.  */
tmpfd = dup(newfd);
if (tmpfd == -1 && errno != EBADF) {
    /* Manejar error inesperado de dup().  */
}
/* Duplicar atómicamente 'oldfd' en 'newfd'.  */
if (dup2(oldfd, newfd) == -1) {
    /* Manejar error de dup2().  */
}
/* Ahora verificar errores de close() en el archivo
   referenciado originalmente por 'newfd'.  */
if (tmpfd != -1) {
    if (close(tmpfd) == -1) {
        /* Manejar errores de close.  */
    }
}
