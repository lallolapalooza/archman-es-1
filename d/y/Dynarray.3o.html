Arreglos

dinámicos.

El módulo Array proporciona arreglos de longitud fija. Dynarray proporciona arreglos cuya longitud puede cambiar con el tiempo, añadiendo o eliminando elementos al final del

arreglo.

Esto se usa típicamente para acumular elementos cuyo número no se conoce de antemano o cambia durante el cálculo, proporcionando también un acceso rápido a elementos en índices

arbitrarios. 
    let dynarray_of_list li =
      let arr = Dynarray.create () in
      List.iter (fun v -> Dynarray.add_last arr v) li;
      arr

El módulo Buffer proporciona características similares, pero está especializado en acumular caracteres en una cadena de tamaño

dinámico.

El módulo Stack proporciona una estructura de datos de tipo pila (último en entrar, primero en salir) que puede implementarse fácilmente sobre arreglos

dinámicos.

Accesos no

sincronizados

Los accesos concurrentes a arreglos dinámicos deben ser sincronizados (por ejemplo con un Mutex.t ). Los accesos no sincronizados a un arreglo dinámico son un error de programación que puede llevar a un estado inválido del arreglo dinámico, sobre el cual algunas operaciones fallarían con una excepción Invalid_argument

.

Las funciones de iteración recorren los elementos de un array dinámico. Los recorridos de a se calculan en orden de índice creciente: desde el elemento de índice 0 hasta el elemento de índice length a - 1

longitud.

Matriz de respaldo,

capacidad

Internamente, una matriz dinámica utiliza una matriz de respaldo (una matriz de tamaño fijo proporcionada por el módulo Array) cuya longitud es mayor o igual a la longitud de la matriz dinámica. Definimos la capacidad de una matriz dinámica como la longitud de su matriz de

respaldo.

La capacidad de una matriz dinámica es relevante en escenarios avanzados, al razonar sobre el rendimiento de los programas con matrices

dinámicas:

-El uso de memoria de una matriz dinámica es proporcional a su capacidad, más bien que a su

longitud.

-Cuando no queda espacio vacío al final de la matriz de respaldo, añadir elementos requiere asignar una nueva matriz de respaldo más

grande.

La implementación utiliza una estrategia estándar de realocación exponencial que garantiza una operación de tiempo constante amortizado; en particular, la capacidad total de todas las matrices de respaldo asignadas durante la vida útil de una matriz dinámica es, en el peor de los casos, proporcional al número total de elementos

añadidos.

En otras palabras, los usuarios no necesitan preocuparse por la capacidad y las realocaciones, y obtendrán un comportamiento razonable de forma predeterminada. Sin embargo, en algunos escenarios sensibles al rendimiento, las funciones siguientes pueden ayudar a controlar el uso de memoria o a garantizar un número óptimo de

realocaciones.

val capacity : 'a t ->

int

capacity a es la longitud de la matriz de respaldo de

a.

val ensure_capacity : 'a t -> int ->

unit

ensure_capacity a n se asegura de que la capacidad de a sea al menos n

.

Lanza Invalid_argument si la capacidad solicitada está fuera del rango 0 .. Sys.max_array_length

.

Un ejemplo sería reimplementar Dynarray.of_array sin usar Dynarray.

init: 
    let of_array arr =
      let a = Dynarray.create () in
      Dynarray.ensure_capacity a (Array.length arr);
      Array.iter (fun v -> add_last a v)
arr

Usar ensure_capacity garantiza que como máximo tendrá lugar una realocación, en lugar de posiblemente

varias.

Sin esta pista de ensure_capacity, el número de redimensionamientos sería logarítmico en la longitud de arr, creando una ralentización de factor constante perceptible cuando arr es

grande.

val ensure_extra_capacity : 'a t -> int ->

unit

ensure_extra_capacity a n es ensure_capacity a (length a + n), se asegura de que a tenga espacio para n elementos

extra.

Lanza Invalid_argument si la capacidad total solicitada está fuera del rango 0 .. Sys.max_array_length

.

Un caso de uso sería implementar Dynarray.append

arr

val fit_capacity : 'a t ->

unit

fit_capacity a realoca una matriz de respaldo si es necesario, de modo que la capacidad resultante sea exactamente length a, sin espacio vacío adicional al final. Esto puede ser útil para asegurarse de que no se desperdicie memoria en una matriz de vida

larga.

Ten en cuenta que llamar a fit_capacity rompe las garantías de complejidad amortizada proporcionadas por la estrategia de realocación predeterminada. Llamarlo repetidamente en una matriz puede tener complejidad cuadrática, tanto en tiempo como en el número total de palabras

asignadas.

Si sabes que una matriz dinámica ha alcanzado su longitud final, que permanecerá fija en el futuro, es suficiente llamar a to_array y conservar solo la matriz de tamaño fijo resultante. fit_capacity es útil cuando necesitas conservar una matriz dinámica para posibles redimensionamientos

futuros.

val set_capacity : 'a t -> int ->

unit

set_capacity a n realoca una matriz de respaldo si es necesario, de modo que la capacidad resultante sea exactamente n. En particular, todos los elementos de índice n o superior son

eliminados.

Al igual que Dynarray.fit_capacity, esta función rompe las garantías de complejidad amortizada proporcionadas por la estrategia de realocación. Llamarla repetidamente en una matriz puede tener complejidad cuadrática, tanto en tiempo como en el número total de palabras

asignadas.

Esta es una función avanzada; en particular, se debe preferir Dynarray.ensure_capacity para aumentar la capacidad, ya que preserva esas garantías

amortizadas.

Lanza Invalid_argument si n <

0.

Sin fugas: preservación de la vida de la

memoria

Los valores proporcionados por el usuario alcanzables desde una matriz dinámica a son exactamente los elementos en los índices 0 a length a - 1. En particular, no se "fuga" ningún valor proporcionado por el usuario al estar presente en la matriz de respaldo en el índice length a o

posterior.

val unsafe_to_iarray : capacity:int -> ('a t -> unit) -> 'a

iarray

condiciones:

-los elementos de la matriz no son flotantes,

y

-después de que f haya devuelto, la capacidad de la matriz es igual a su

Ten en cuenta que el argumento capacity es solo una pista. Por ejemplo, nada impide llamar a Dynarray.fit_capacity al final de f

Esta función es insegura porque la seguridad de tipos puede verse comprometida por escrituras concurrentes en la dynarray desde otros dominios, sin la sincronización adecuada, antes de que f devu

Heaps mínimos para colas de prioridad

mutables

Podemos usar matrices dinámicas para implementar una cola de prioridad mutable. Una cola de prioridad proporciona una función para añadir elementos y una función para extraer el elemento mínimo -- según alguna función de

comparación. 
(* Presentamos nuestras colas de prioridad como un functor
   parametrizado sobre la función de comparación. *)
module Heap (Elem : Map.OrderedType) : sig
  type t
  val create : unit -> t
  val add : t -> Elem.t -> unit
  val pop_min : t -> Elem.t option
end = struct
  (* Nuestras colas de prioridad se implementan usando la estructura de datos
     estándar de "min heap", una matriz dinámica que representa un árbol binario. *)
  type t = Elem.t Dynarray.t
  let create = Dynarray.create
 (* El nodo de índice [i] tiene como hijos los nodos de índice [2 * i + 1]
    y [2 * i + 2] -- si son índices válidos en la dynarray. *)
  let left_child i = 2 * i + 1
  let right_child i = 2 * i + 2
  let parent_node i = (i - 1) / 2
  (* Usamos operadores de indexación para notaciones convenientes. *)
  let ( .!() ) = Dynarray.get
  let ( .!()<- ) = Dynarray.set
  (* Funciones auxiliares para comparar e intercambiar dos elementos
     en la matriz dinámica. *)
  let order h i j =
    Elem.compare h.!(i) h.!(j)
  let swap h i j =
    let v = h.!(i) in
    h.!(i) <- h.!(j);
    h.!(j) <- v
  (* Decimos que un heap respeta el "ordenamiento de heap" si el valor de
     cada nodo es menor que el valor de sus hijos. El
     algoritmo manipula arrays que respetan el algoritmo de heap,
     excepto un nodo cuyo valor puede ser demasiado pequeño o demasiado grande.
     Las funciones auxiliares [heap_up] y [heap_down] toman
     un valor desplazado así, y lo mueven "hacia arriba" (respectivamente: "hacia abajo")
     el árbol permutándolo con el valor de su padre (respectivamente:
     un valor hijo) hasta que se restaura el ordenamiento del heap. *)
  let rec heap_up h i =
    if i = 0 then () else
    let parent = parent_node i in
    if order h i parent < 0 then
      (swap h i parent; heap_up h parent)
  and heap_down h ~len i =
    let left, right = left_child i, right_child i in
    if left >= len then () (* sin hijo, parar *) else
    let smallest =
      if right >= len then left (* sin hijo derecho *) else
      if order h left right < 0 then left else right
    in
    if order h i smallest > 0 then
      (swap h i smallest; heap_down h ~len smallest)
  let add h s =
    let i = Dynarray.length h in
    Dynarray.add_last h s;
    heap_up h i
  let pop_min h =
    if Dynarray.is_empty h then None
    else begin
      (* Truco estándar: intercambiar el valor 'mejor' en el índice 0
         con el último valor del array. *)
      let last = Dynarray.length h - 1 in
      swap h 0 last;
      (* En este punto [pop_last] devuelve el valor 'mejor',
         y deja un heap con un elemento desplazado en el índice [0]. *)
      let best = Dynarray.pop_last h in
      (* Restaurar el ordenamiento del heap -- no hace nada si el heap está vacío. *)
      heap_down h ~len:last 0;
      Some best
    end
end

El código de producción del cual se inspiró este ejemplo incluye lógica para liberar la matriz de respaldo cuando el heap se vuelve vacío, solo en el caso donde la capacidad está por encima de cierto umbral. Esto se puede hacer llamando a la siguiente función desde pop

: 
let shrink h =
  if Dynarray.length h = 0 && Dynarray.capacity h > 1 lsl 18 then
    Dynarray.reset h

El functor Heap se puede usar para implementar una función de ordenamiento, añadiendo todos los elementos a una cola de prioridad y luego extrayéndolos en

orden. 
let heap_sort (type a) cmp li =
  let module Heap = Heap(struct type t = a let compare = cmp end) in
  let heap = Heap.create () in
  List.iter (Heap.add heap) li;
  List.map (fun _ -> Heap.pop_min heap |> Option.get) li
