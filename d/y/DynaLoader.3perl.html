NOMBRE

DynaLoader - Carga dinámicamente bibliotecas C en código Perl

SINOPSIS

package YourPackage;
require DynaLoader;
@ISA = qw(... DynaLoader ...);
__PACKAGE__->bootstrap;
# método opcional para la carga 'global'
sub dl_load_flags { 0x01 }

DESCRIPCIÓN

Este documento define una interfaz genérica estándar para los mecanismos de enlace dinámico disponibles en muchas plataformas. Su propósito principal es implementar la carga dinámica automática de módulos Perl.

Este documento sirve tanto como especificación para quien desee implementar el DynaLoader para una nueva plataforma como como guía para quien desee usar el DynaLoader directamente en una aplicación.

El DynaLoader está diseñado para ser una interfaz genérica de alto nivel muy simple, suficientemente general para cubrir los requisitos de SunOS, HP-UX, Linux, VMS y otras plataformas.

También se espera que la interfaz cubra las necesidades de OS/2, NT, etc., y que también permita el enlace dinámico pseudo (usando "ld -A" en tiempo de ejecución).

Debe enfatizarse que el DynaLoader, por sí solo, es prácticamente inútil para acceder a bibliotecas no Perl porque no proporciona casi ningún 'pegamento' de Perl a C. Por ejemplo, no hay ningún mecanismo para llamar a una función de biblioteca C o proporcionar argumentos. Un módulo C::DynaLib está disponible desde los sitios de CPAN que realiza esa función para algunos tipos de sistemas comunes. Y desde el año 2000, también existe Inline::C, un módulo que le permite escribir subrutinas Perl en C. También disponible desde su sitio local de CPAN.

@dl_library_path
La lista estándar/por defecto de directorios en los que dl_findfile() buscará bibliotecas, etc. Los directorios se buscan en orden: $dl_library_path[0], [1], ... etc

@dl_library_path se inicializa para contener la lista de directorios 'normales' (/usr/lib, etc) determinados por Configure ($Config{'libpth'}). Esto debería asegurar la portabilidad en una amplia gama de plataformas.

@dl_library_path también debería inicializarse con cualquier otro directorio que pueda determinarse del entorno en tiempo de ejecución (como LD_LIBRARY_PATH para SunOS).

Después de la inicialización @dl_library_path puede ser manipulado por una aplicación usando push y unshift antes de llamar a dl_findfile(). Unshift puede usarse para añadir directorios al principio del orden de búsqueda, ya sea para ahorrar tiempo de búsqueda o para sobreescribir bibliotecas con el mismo nombre en los directorios 'normales'.

La función de carga que dl_load_file() llama puede requerir una ruta de archivo absoluta. La función dl_findfile() y @dl_library_path pueden usarse para buscar y devolver la ruta de archivo absoluta para la biblioteca/objeto que desee cargar.

@dl_resolve_using
Una lista de bibliotecas adicionales u otros objetos compartidos que pueden usarse para resolver cualquier símbolo indefinido que pueda generarse por una llamada posterior a load_file().

Esto solo se requiere en algunas plataformas que no manejan las bibliotecas dependientes automáticamente. Por ejemplo, la biblioteca de extensión Perl Socket (auto/Socket/Socket.so) contiene referencias a muchas funciones de socket que necesitan resolverse cuando se carga. La mayoría de las plataformas sabrán automáticamente dónde encontrar la biblioteca 'dependiente' (por ejemplo, /usr/lib/libsocket.so). Algunas pocas plataformas necesitan que se les indique explícitamente la ubicación de la biblioteca dependiente. Use @dl_resolve_using para esto.

Ejemplo de uso:

@dl_resolve_using = dl_findfile('-lsocket');
@dl_require_symbols
Una lista de uno o más nombres de símbolo que están en el archivo de biblioteca/objeto a ser cargado dinámicamente. Esto solo se requiere en algunas plataformas.
@dl_librefs
Un array de los manejadores devueltos por llamadas exitosas a dl_load_file(), hechas por bootstrap, en el orden en el que fueron cargados. Puede usarse con dl_find_symbol() para buscar un símbolo en cualquiera de los archivos cargados.
@dl_modules
Un array de nombres de módulos (paquetes) que han sido bootstrap'eados.
@dl_shared_objects
Un array de nombres de archivo para los objetos compartidos que fueron cargados.
dl_error()
Sintaxis: 
$message = dl_error();

Texto del mensaje de error de la última función DynaLoader fallida. Nótese que, similar a errno en unix, una llamada exitosa a una función no restablece este mensaje.

Las implementaciones deberían detectar el error tan pronto como ocurra en cualquiera de las otras funciones y guardar el mensaje correspondiente para su posterior recuperación. Esto evitará problemas en algunas plataformas (como SunOS) donde el mensaje de error es muy temporal (por ejemplo, dlerror()).

$dl_debug
Los mensajes de depuración internos se habilitan cuando $dl_debug se establece en verdadero. Actualmente, establecer $dl_debug solo afecta al lado Perl del DynaLoader. Estos mensajes deberían ayudar a un desarrollador de aplicaciones a resolver cualquier problema de uso de DynaLoader.

$dl_debug se establece en $ENV{'PERL_DL_DEBUG'} si está definido.

Para el desarrollador/porteador de DynaLoader hay una variable de depuración similar añadida al código C (ver dlutils.c) y habilitada si Perl fue compilado con el -DDEBUGGING flag. Esto también puede establecerse a través de la variable de entorno PERL_DL_DEBUG. Establezca a 1 para información mínima o a un valor mayor para más.

$dl_dlext
Cuando se especifica (localizado) en el archivo .pm de un módulo, indica la extensión que tendrá el objeto cargable del módulo. Por ejemplo: 
local $DynaLoader::dl_dlext = 'unusual_ext';

indicaría que el objeto cargable del módulo tiene una extensión de "unusual_ext" en lugar de la más usual $Config{dlext}. NOTA: Esto también requiere que el Makefile.PL del módulo especifique (en WriteMakefile()):

DLEXT => 'unusual_ext',
dl_findfile()
Sintaxis: 
@filepaths = dl_findfile(@names)

Determina las rutas completas (incluyendo el sufijo de archivo) de uno o más archivos cargables dados sus nombres genéricos y opcionalmente uno o más directorios. Busca en los directorios de @dl_library_path por defecto y devuelve una lista vacía si no se encontraron archivos.

Los nombres pueden especificarse en una variedad de formas independientes de la plataforma. Cualquier nombre en la forma -lname se convierte en libname.*, donde .* es un sufijo apropiado para la plataforma.

Si un nombre no tiene ya un prefijo y/o sufijo adecuado, entonces el archivo correspondiente se buscará probando combinaciones de prefijo y sufijo apropiadas para la plataforma: "$name.o", "lib$name.*" y "$name".

Si se incluyen directorios en @names se buscan antes que @dl_library_path. Los directorios pueden especificarse como -Ldir. Cualquier otro nombre se trata como nombres de archivo a ser buscados.

Se recomienda usar argumentos de la forma "-Ldir" y "-lname" .

Ejemplo:

@dl_resolve_using = dl_findfile(qw(-L/usr/5lib -lposix));
