sk_sk_TYPE _find() recherche sk pour l'élément <i>ptr. En el caso en que no se haya especificado una función de comparación, la función realiza una búsqueda lineal de un puntero igual a ptr. En el caso en que se haya especificado una función de comparación, la función realiza una búsqueda de un elemento que la función de comparación indica que coincide. Si la pila está ordenada, se utiliza una búsqueda binaria; de lo contrario, se utiliza una búsqueda lineal. sk_TYPE_find() devuelve el índice de un elemento coincidente o -1 si no hay coincidencia.

sk_TYPE_find_ex() funciona como sk_TYPE_find() excepto cuando se ha especificado una función de comparación y no se encuentra ningún elemento coincidente. En lugar de devolver -1, sk_TYPE_find_ex() devuelve el índice del elemento anterior o posterior a la ubicación donde ptr estaría si estuviera presente en sk. La función tampoco garantiza que se devuelva el primer elemento coincidente en la pila ordenada.

sk_TYPE_find_all() funciona como sk_TYPE_find() pero también establece *pnum al número de elementos coincidentes en la pila. En caso de que no se haya especificado una función de comparación, *pnum se establecerá siempre en 1 si se encontró un elemento coincidente, y en 0 en caso contrario.

sk_TYPE_sort() ordena sk usando la función de comparación proporcionada.

sk_TYPE_is_sorted() devuelve 1 si sk está ordenada y 0 en caso contrario.

sk_TYPE_dup() devuelve una copia superficial de sk o una pila vacía si la pila pasada es NULL. Tenga en cuenta que los punteros en la copia son idénticos a los del original.

sk_TYPE_deep_copy() devuelve una nueva pila donde cada elemento ha sido copiado, o una pila vacía si la pila pasada es NULL. La copia se realiza mediante la copyfunc() proporcionada y la liberación mediante freefunc(). La función freefunc() solo se llama si ocurre un error.

NOTAS

Se debe tener cuidado al acceder a las pilas en entornos multihilo. Cualquier operación que aumente el tamaño de una pila, como sk_TYPE_insert() o sk_TYPE_push(), puede "ampliar" el tamaño de un array interno y causar condiciones de carrera si se accede a la misma pila en un hilo diferente. Operaciones como sk_TYPE_find() y sk_TYPE_sort() también pueden reordenar la pila.

Cualquier función de comparación proporcionada debe usar una métrica adecuada para su uso en una operación de búsqueda binaria. Es decir, debe devolver cero, un valor positivo o negativo si a es igual a, mayor que o menor que b respectivamente.

Se debe tener cuidado al comprobar los valores de retorno de las funciones sk_TYPE_find() y sk_TYPE_find_ex(). Devuelven un índice al elemento coincidente. En particular, 0 indica un primer elemento coincidente. Una búsqueda fallida se indica con un valor de retorno -1 .

STACK_OF(), DEFINE_STACK_OF(), DEFINE_STACK_OF_CONST()y DEFINE_SPECIAL_STACK_OF() están implementados como macros.

No es un error llamar a sk_TYPE_num(), sk_TYPE_value(), sk_TYPE_free(), sk_TYPE_zero(), sk_TYPE_pop_free(), sk_TYPE_delete(), sk_TYPE_delete_ptr(), sk_TYPE_pop(), sk_TYPE_shift(), sk_TYPE_find(), sk_TYPE_find_ex() y sk_TYPE_find_all() en una pila NULL, una pila vacía o con un índice no válido. No se genera un error en estas condiciones.

La API de utilidad subyacente OPENSSL_sk_ no debe usarse directamente. Define estas funciones: OPENSSL_sk_deep_copy(), OPENSSL_sk_delete(), OPENSSL_sk_delete_ptr(), OPENSSL_sk_dup(), OPENSSL_sk_find(), OPENSSL_sk_find_ex(), OPENSSL_sk_find_all(), OPENSSL_sk_free(), OPENSSL_sk_insert(), OPENSSL_sk_is_sorted(), OPENSSL_sk_new(), OPENSSL_sk_new_null(), OPENSSL_sk_new_reserve(), OPENSSL_sk_num(), OPENSSL_sk_pop(), OPENSSL_sk_pop_free(), OPENSSL_sk_push(), OPENSSL_sk_reserve(), OPENSSL_sk_set(), OPENSSL_sk_set_cmp_func(), OPENSSL_sk_set_thunks(), OPENSSL_sk_shift(), OPENSSL_sk_sort(), OPENSSL_sk_unshift(), OPENSSL_sk_value(), OPENSSL_sk_zero().

OPENSSL_sk_set_thunks(), aunque es pública por necesidad, es en realidad una función interna y no debe usarse.

VALORES DE RETORNO

sk_TYPE_num() devuelve el número de elementos en la pila o -1 si la pila pasada es NULL.

sk_TYPE_value() devuelve un puntero a un elemento de la pila o NULL si el índice está fuera de rango.

sk_TYPE_new(), sk_TYPE_new_null() y sk_TYPE_new_reserve() devuelven una pila vacía o NULL si ocurre un error.

sk_TYPE_reserve() devuelve 1 en la asignación exitosa de la memoria requerida o 0 en caso de error.

sk_TYPE_set_cmp_func() devuelve la función de comparación antigua o NULL si no había una función de comparación antigua.

sk_TYPE_free(), sk_TYPE_zero(), sk_TYPE_pop_free() y sk_TYPE_sort() no devuelven valores.

sk_TYPE_pop(), sk_TYPE_shift(), sk_TYPE_delete() y sk_TYPE_delete_ptr() devuelven un puntero al elemento eliminado o NULL en caso de error.

sk_TYPE_insert(), sk_TYPE_push() y sk_TYPE_unshift() devuelven el número total de elementos en la pila y 0 si ocurrió un error.

sk_TYPE_set() devuelve un puntero al elemento de reemplazo o NULL en caso de error.

sk_TYPE_find() y sk_TYPE_find_ex() devuelven un índice al elemento encontrado o -1 en caso de error.

sk_TYPE_is_sorted() devuelve 1 si la pila está ordenada y 0 si no lo está.

sk_TYPE_dup() y sk_TYPE_deep_copy() devuelven un puntero a la copia de la pila o NULL en caso de error.

HISTORIAL

Antes de OpenSSL 1.1.0, esto se implementaba mediante macros y no mediante funciones inline, y no era una API pública.

sk_TYPE_reserve() y sk_TYPE_new_reserve() se añadieron en OpenSSL 1.1.1.

A partir de OpenSSL 3.2.0, las llamadas sk_TYPE_find(), sk_TYPE_find_ex() y sk_TYPE_find_all() son de solo lectura y no ordenan la pila. Para evitar cualquier implicación de rendimiento que introduzca este cambio, sk_TYPE_sort() debe llamarse antes de estas operaciones de búsqueda.

Antes de OpenSSL 3.3.0, sk_TYPE_push() devolvía -1 si sk era NULL. Se cambió para devolver 0 en esta condición, igual que para otros errores.

OPENSSL_sk_set_thunks() se añadió en OpenSSL 3.6.0.
