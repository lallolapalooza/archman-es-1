Descripción Detallada

Una interfaz abstracta de E/S.

Advertencia

Esto es para usuarios avanzados y experimentados. No lo necesitas a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba acceso al sistema de archivos físico y a los archivos dentro de ese sistema de archivos. Sin embargo, a veces se necesita más potencia que esto. Quizás necesites proporcionar un archivo que esté completamente contenido en RAM, o necesites conectar alguna otra API de E/S de archivos a PhysicsFS, o necesites traducir bits (quizás tengas un archivo .zip estándar cifrado y necesites descifrarlo sobre la marcha para el descompresor zip desprevenido).

Un PHYSFS_Io es la interfaz que utilizan los Archivos para obtener datos de archivo. Históricamente, esto se mapeaba a E/S de archivos al sistema de archivos físico, pero a partir de PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de E/S en tiempo de ejecución.

Esta interfaz no es necesariamente un buen ajuste universal para E/S. Hay algunos requisitos notables:

  • Solo realizan E/S bloqueante (al menos, por ahora).
  • Necesitan poder duplicarse. Si tienes un manejador de archivos de fopen(), necesitas poder crear un clon único de él (para que tengamos dos manejadores del mismo archivo que puedan buscar/leer/etc. sin interferir entre sí).
  • Necesitan conocer el tamaño de todo su conjunto de datos.
  • Necesitan poder buscar y rebobinar bajo demanda.

... en resumen, probablemente no vas a escribir una implementación HTTP.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Io sean seguras para hilos por sí mismas. Internamente, donde PhysicsFS las utiliza, la biblioteca proporciona sus propios bloqueos. Si planeas usarlas directamente desde hilos separados, debes usar mutexes para protegerlas, o no usar el mismo PHYSFS_Io desde dos hilos al mismo tiempo.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Limpiar y desasignar la instancia de E/S. Liberar recursos asociados, incluido (opaque) si corresponde.

Esta función siempre debe tener éxito: como tal, devuelve void. El sistema puede llamar a tu método flush() antes que a este. Puedes informar un error allí si es necesario. Este método aún puede ser llamado si flush() falla, en cuyo caso tendrás que abandonar los datos no vaciados y otras condiciones de fallo, y limpiar.

Una vez que se llama a este método para una instancia dada, el sistema asumirá que no es seguro volver a tocar esa instancia y descartará cualquier referencia a ella.

Parámetros

io La instancia de E/S a destruir.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Duplicar esta instancia de E/S. Esto necesita resultar en una copia completa de este PHYSFS_Io, que pueda vivir de forma completamente independiente. La copia debe ser capaz de realizar todas sus operaciones sin alterar el original, incluido que cualquiera de los dos objetos pueda ser destruido por separado (por lo tanto, por ejemplo: no pueden compartir un manejador de archivo; cada uno necesita el suyo).

Si no puedes duplicar un manejador, es legal devolver NULL, pero casi con seguridad necesitarás esta funcionalidad si quieres usar este PHYSFS_Io para respaldar un archivo.

Parámetros

io La instancia de E/S a duplicar.

Devuelve

Un nuevo valor para el campo (opaque) de un flujo, o NULL en caso de error.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vaciar recursos a los medios, o donde sea. Esta es la oportunidad de informar fallos en escrituras que antes se habían declarado exitosas, pero que aún tenían la posibilidad de fallar. Este método puede ser NULL si no es necesario vaciar.

Esta función puede ser llamada antes de destroy(), ya que puede informar fallos y destroy() no puede. Puede ser llamada en otros momentos también.

Parámetros

io La instancia de E/S a vaciar.

Devuelve

Cero en caso de error, distinto de cero en caso de éxito.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Determinar el tamaño del conjunto de datos de la instancia de E/S. Devuelve el número de bytes disponibles en el archivo, o -1 si no se puede determinar. Un fallo casi seguramente será fatal para el uso posterior de este flujo, por lo que no puedes dejar esto sin implementar.

Parámetros

io La instancia de E/S a consultar.

Devuelve

Tamaño total, en bytes, del conjunto de datos.

void* PHYSFS_Io::opaque

Datos de instancia para esta estructura. Cada instancia tiene un puntero asociado que se puede utilizar para almacenar lo que desee. Este puntero es por instancia del flujo, por lo que presumiblemente cambiará al llamar a duplicate(). Esto se puede desasignar durante el método destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Leer más datos. Lee (len) bytes de la interfaz, en la posición actual de E/S, y almacénalos en (buffer). La posición actual de E/S debe avanzar por el número de bytes leídos con éxito.

No tienes que implementar esto; establécelo a NULL si no está implementado. Esto solo se usará si el archivo se abre para lectura. Si se establece a NULL, se utilizará una implementación predeterminada que informa inmediatamente un fallo.

Parámetros

io La instancia de E/S de la que leer.
buf El búfer donde almacenar los datos. Debe tener al menos (len) bytes de longitud y no puede ser NULL.
len El número de bytes a leer de la interfaz.

Devuelve

número de bytes leídos del archivo, 0 en EOF, -1 en caso de fallo completo.

NAME

PHYSFS_Io — Abstract I/O interface

SYNOPSIS

#include <physfs.h>

typedef struct PHYSFS_Io PHYSFS_Io;

/* Fields */

  PHYSFS_sint64 (*write)(struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len);
  PHYSFS_sint64 (*read)(struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len);
  int (*seek)(struct PHYSFS_Io *io, PHYSFS_uint64 offset);
  PHYSFS_sint64 (*tell)(struct PHYSFS_Io *io);
  int (*close)(struct PHYSFS_Io *io);
  PHYSFS_uint32 version;

Detailed Description

This is the abstract I/O interface. You'll use this in the PHYSFS_mountIo() function to mount a new file archive.

The fields are: write, read, seek, tell, close, and version.

All functions are expected to return meaningful values (or -1/NULL on error). If a function is not implemented, it should be set to NULL. A NULL function will be treated as an error condition.

Field Documentation

int(* PHYSFS_Io::close) (struct PHYSFS_Io *io)

Close the i/o stream and free all associated resources. This must be implemented.

Parameters

io The i/o instance to close.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read more data. Read (len) bytes from the interface into (buffer) at the current i/o position. The current i/o position should move ahead by the number of bytes successfully read.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a read can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The maximum number of bytes to read into (buffer).

Returns

number of bytes read from file, zero if eof, or -1 if complete failure.

int(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Set the current i/o position. Set the new byte offset for the i/o position. If the underlying system doesn't support seeking, this function should return zero (fail) to make sure it is treated as an error condition.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
