DELTA(1P) Manual del Programador POSIX DELTA(1P)

PRÓLOGO

Esta página de manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página de manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

delta — hacer un delta (cambio) en un archivo SCCS (DESARROLLO)

SINOPSIS

delta [-nps] [-g lista] [-m listamr] [-r SID] [-y[comentario]] archivo...

DESCRIPCIÓN

La utilidad delta se utilizará para introducir permanentemente en los archivos SCCS nombrados los cambios que se realizaron en los archivos recuperados por get (llamados los g-files, o archivos generados).

OPCIONES

La utilidad delta deberá cumplir con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades, excepto que la opción -y tiene un argumento de opción opcional. Este argumento de opción opcional no debe presentarse como un argumento separado.

Se deberán soportar las siguientes opciones:

-rSID
Identificar de manera única qué delta se va a hacer en el archivo SCCS. El uso de esta opción solo será necesario si dos o más comandos get pendientes para edición (get -e) en el mismo archivo SCCS fueron realizados por la misma persona (nombre de inicio de sesión). El valor SID especificado con la opción -r puede ser el SID especificado en la línea de comandos get o el SID a ser creado como lo informa la utilidad get ; véase get.
-s
Suprimir el informe a la salida estándar de la actividad asociada con cada archivo. Véase la sección SALIDA ESTÁNDAR.
-n
Especificar la retención del g-file editado (normalmente eliminado al completar el procesamiento de delta).
-glista
Especificar una lista (véase get para la definición de lista) de deltas que se ignorarán cuando se acceda al archivo en el nivel de cambio (SID) creado por esta delta.
-mlistamr
Especificar un número de solicitud de modificación (MR) que la aplicación deberá proporcionar como la razón para crear la nueva delta. Esto se usará si el archivo SCCS tiene la v bandera establecida; véase admin.

Si -m no se usa y '-' no se especifica como un argumento de archivo, y la entrada estándar es una terminal, el mensaje descrito en la sección SALIDA ESTÁNDAR se escribirá en la salida estándar antes de leer la entrada estándar; si la entrada estándar no es una terminal, no se emitirá ningún mensaje.

Los MR en una lista deberán estar separados por caracteres <blanco> o caracteres <nueva línea> escapados. Una <nueva línea> no escapada terminará la lista de MR. El carácter de escape es <barra invertida>.

Si la v bandera tiene un valor, se tomará como el nombre de un programa que valida la corrección de los números MR. Si el programa de validación de números MR devuelve un estado de salida distinto de cero, la utilidad delta terminará. (Se asume que los números MR no fueron todos válidos.)

-y[comentario]
Describir la razón para hacer la delta. El comentario deberá ser un grupo arbitrario de líneas que cumpla con la definición de un archivo de texto. Las implementaciones deberán soportar comentariosde cero a 512 bytes y pueden soportar valores más largos. Una cadena nula (especificada como -y, -y"", o en respuesta a un mensaje para un comentario) se considerará un comentarioválido.

Si -y no se especifica y '-' no se especifica como un argumento de archivo, y la entrada estándar es una terminal, el mensaje descrito en la sección SALIDA ESTÁNDAR se escribirá en la salida estándar antes de leer la entrada estándar; si la entrada estándar no es una terminal, no se emitirá ningún mensaje. Una <nueva línea> no escapada terminará el texto del comentario. El carácter de escape es <barra invertida>.

La -y opción será requerida si el archivo operando se especifica como '-'.

-p
Escribir (a la salida estándar) las diferencias del archivo SCCS antes y después de aplicar la delta en formato diff ; véase diff.

OPERANDOS

Se soportará el siguiente operando:

archivo
Una ruta de acceso de un archivo SCCS existente o un directorio. Si archivo es un directorio, la utilidad delta se comportará como si cada archivo en el directorio fuera especificado como un archivo nombrado, excepto que los archivos no-SCCS (el último componente de la ruta de acceso no comienza con s.) y los archivos no legibles serán ignorados silenciosamente.

Si exactamente un operando archivo aparece, y es '-', la entrada estándar será leída; cada línea de la entrada estándar será tomada como el nombre de un archivo SCCS a ser procesado. Los archivos no-SCCS y los archivos no legibles serán ignorados silenciosamente.

ENTRADA ESTÁNDAR

La entrada estándar será un archivo de texto usado solo en los siguientes casos:

*
Para leer una listamr o un comentario (véanse las opciones -m y -y ).
*
Un operando archivo deberá ser especificado como '-'. En este caso, la opción -y debe usarse para especificar el comentario, y si el archivo SCCS tiene la v bandera establecida, la opción -m también debe usarse para especificar la lista de MR.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos de texto cuyos datos deben incluirse en los archivos SCCS. Si el primer carácter de cualquier línea de un archivo de entrada es <SOH> en la configuración regional POSIX, los resultados no están especificados. Si este archivo contiene más de 99999 líneas, el número de líneas registrado en el encabezado para este archivo será 99999 para esta delta.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de delta:

LANG
Proporcionar un valor por defecto para las variables de internacionalización que no están establecidas o son nulas. (Véase el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización usadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las otras variables de internacionalización.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en oposición a múltiples bytes en argumentos y archivos de entrada).
LC_MESSAGES

Determinar la configuración regional que debe usarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar, y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
TZ
Determinar la zona horaria en la que se escriben la hora y la fecha en el archivo SCCS. Si la variable TZ no está establecida o es NULA, se usa una zona horaria predeterminada del sistema no especificada.

EVENTOS ASÍNCRONOS

Si se captura SIGINT, los archivos temporales serán limpiados y delta saldrá con un estado de salida distinto de cero.código de salida distinto de cero. Se tomará la acción estándar para todas las demás señales; véase Sección 1.4, Descripción de la utilidad Valores por defecto.

SALIDA ESTÁNDAR

La salida estándar se utilizará únicamente para los siguientes mensajes en la configuración regional POSIX:

*
Indicaciones (véanse las -m y -y opciones) en los siguientes formatos:
"MRs? "
"comments? "

La indicación de MR, si se escribe, siempre debe preceder a la indicación de comentarios.

*
Un informe de las actividades de cada archivo (a menos que se especifique la opción -s ) en el siguiente formato:
"%s\n%d inserted\n%d deleted\n%d unchanged\n", <Nuevo SID>,
    <número de líneas insertadas>, <número de líneas eliminadas>,
    <número de líneas sin cambios>

ERROR ESTÁNDAR

El error estándar se utilizará únicamente para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Cualquier archivo SCCS actualizado será un archivo de un formato no especificado.

DESCRIPCIÓN AMPLIADA

Sistema Fecha y hora

Cuando se añade una delta a un archivo SCCS, se registrarán la fecha y hora del sistema para la nueva delta. Si se realiza un get utilizando un archivo SCCS con una fecha registrada aparentemente en el futuro, el comportamiento no está especificado.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

0
Finalización correcta.
>0
Se produjo un error.

CONSECUENCIAS DE LOS ERRORES

Por defecto.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Pueden surgir problemas si la fecha y hora del sistema han sido modificadas (por ejemplo, adelantadas y luego retrasadas, o relojes desincronizados en una red) y también pueden surgir cuando se utilizan valores diferentes de la TZ variable de entorno.

Problemas de naturaleza similar también pueden surgir para la operación de la utilidad get , que registra la fecha y hora en el cuerpo del archivo.
