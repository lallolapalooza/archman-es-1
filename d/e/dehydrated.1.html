certificats,

Dehydrated doit obtenir un compte auprès des autorités de certification. Une adresse courriel peut être fournie de manière facultative. Elle sera utilisée pour, par exemple, notifier de l'expiration des certificats. Vous devrez généralement accepter les conditions d'utilisation de l'AC. Dehydrated vous préviendra si aucun compte n'est configuré. Exécutez avec --register --accept-terms pour créer un nouveau compte.

Ensuite,

tous les noms de domaine doivent être fournis dans domains.txt. Le format est basé sur les lignes : si le fichier contient deux lignes "example.com" et "example.net", dehydrated demandera deux certificats, un pour "example.com" et l'autre pour "example.net". Une seule ligne contenant "example.com example.net" demandera un seul certificat valide pour "example.net" et "example.com" via le champ Subject Alternative Name (SAN) . Pour l'étape suivante, une

méthode

de vérification de la propriété du nom de domaine doit être configurée. Dehydrated implémente la vérification http-01 et dns-01. La vérification

http-01

fournit une preuve de propriété en fournissant un jeton de défi. Pour ce faire, le répertoire référencé dans la variable de configuration WELLKNOWN doit être exposé à http://{domain}/.well-known/acme-challenge/, où {domain} est chaque nom de domaine spécifié dans domains.txt. Dehydrated ne fournit pas son propre répondant de défi, mais s'appuie sur un serveur web existant pour fournir la réponse au défi. Voir wellknown.md pour des exemples de configuration de serveurs web populaires. La vérification dns-01 fonctionne en

fournissant

un jeton de défi via DNS. C'est particulièrement intéressant pour les hôtes qui ne peuvent pas être exposés à Internet public. Comme l'ajout d'enregistrements aux zones DNS est souvent très spécifique au logiciel ou au fournisseur DNS en question, il existe de nombreux crochets (hooks) tiers disponibles pour dehydrated. Voir dns-verification.md pour les crochets pour les serveurs DNS et les hébergeurs DNS populaires. Enfin, les

certificats

doivent être demandés et mis à jour sur une base régulière. Cela peut se faire via une tâche cron ou un minuteur. Au début, vous pouvez forcer cela en invoquant dehydrated -c manuellement. Après une exé

cution

réussie, les certificats sont stockés dans /etc/dehydrated/certs/{domain} , où {domain} est le nom de domaine dans la première colonne de domains.txt. OPTIONS Commandes
