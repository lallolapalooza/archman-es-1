DESCRIPCIÓ

N

Un cliente para Autoridades de Certificados basadas en ACME, como LetsEncrypt. Puede usarse para solicitar y obtener certificados TLS de una autoridad de certificados basada en

ACME.

Antes de poder solicitar cualquier certificado, Dehydrated necesita adquirir una cuenta con las Autoridades de Certificados. Opcionalmente, se puede proporcionar una dirección de correo electrónico. Se usará, por ejemplo, para notificar sobre certificados que estén por expirar. Por lo general, será necesario aceptar los Términos de Servicio de la AC. Dehydrated notificará si no hay ninguna cuenta configurada. Ejecute con --register --accept-terms para crear una nueva

cuenta.

A continuación, todos los nombres de dominio deben proporcionarse en domains.txt. El formato es basado en líneas: Si el archivo contiene dos líneas "example.com" y "example.net", dehydrated solicitará dos certificados, uno para "example.com" y el otro para "example.net". Una sola línea que contenga "example.com example.net" solicitará un único certificado válido tanto para "example.net" como para "example.com" a través del campo Subject Alternative Name (SAN)

.

Para el siguiente paso, se debe configurar una forma de verificar la propiedad del nombre de dominio. Dehydrated implementa la verificación http-01 y dns-01

.

La verificación http-01 proporciona una prueba de propiedad al proporcionar un token de desafío. Para ello, el directorio referenciado en la variable de configuración WELLKNOWN debe estar expuesto en http://{dominio}/.well-known/acme-challenge/, donde {dominio} es cada nombre de dominio especificado en domains.txt. Dehydrated no proporciona su propio respondedor de desafíos, sino que se apoya en un servidor web existente para proporcionar la respuesta al desafío. Vea wellknown.md para ejemplos de configuración de servidores web

populares.

La verificación dns-01 funciona proporcionando un token de desafío a través de DNS. Esto es especialmente interesante para hosts que no pueden ser expuestos a Internet público. Dado que añadir registros a zonas DNS es a menudo muy específico del software o del proveedor de DNS en cuestión, existen muchos hooks de terceros disponibles para dehydrated. Vea dns-verification.md para hooks para servidores DNS y proveedores de alojamiento DNS

populares.

Finalmente, los certificados deben solicitarse y actualizarse de forma regular. Esto puede ocurrir a través de un trabajo de cron o un temporizador. Inicialmente, puede forzar esto invocando dehydrated -c man

ualmente.

Después de una ejecución exitosa, los certificados se almacenan en /etc/dehydrated/certs/{dominio}, donde {dominio} es el nombre de dominio en la primera columna de domain

s.t
xt.
