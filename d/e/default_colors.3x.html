NOMBRE

use_default_colors, assume_default_colors - usar los colores predeterminados del terminal en curses

SINOPSIS

#include <curses.h>
int use_default_colors(void);
int assume_default_colors(int fg, int bg);

DESCRIPCIÓN

Las funciones use_default_colors y assume_default_colors son extensiones de la biblioteca curses. Se utilizan con terminales que soportan color ISO 6429, o equivalente. Estos terminales permiten a la aplicación restablecer el color a un valor predeterminado no especificado (por ejemplo, con SGR 39 o SGR 49).

Las aplicaciones que pintan un fondo de color sobre toda la pantalla no aprovechan SGR 39 y SGR 49. Algunas aplicaciones están diseñadas para funcionar con el fondo predeterminado, utilizando colores solo para el texto. Por ejemplo, existen varias implementaciones del programa ls que utilizan colores para denotar diferentes tipos de archivo o permisos. Estos programas de “color ls” no modifican necesariamente el color de fondo, utilizando típicamente solo la capacidad setaf de terminfo para establecer el color del primer plano. Las aplicaciones de pantalla completa que utilizan colores predeterminados pueden lograr efectos visuales similares.

La primera función, use_default_colors, indica a la biblioteca curses que asigne los colores predeterminados del primer plano/fondo del terminal al número de color -1. Por lo tanto, init_pair(x,COLOR_RED,-1) inicializará el par x como rojo sobre fondo predeterminado y init_pair(x,-1,COLOR_BLUE) inicializará el par x como primer plano predeterminado sobre azul.

La otra, assume_default_colors, es un refinamiento que indica qué colores pintar para el par de colores 0. Esta función reconoce un número de color especial -1, que denota el color predeterminado del terminal.

Los siguientes son equivalentes:


use_default_colors();
assume_default_colors(-1,-1);

Estas son extensiones de ncurses. Para otras implementaciones de curses, el número de color -1 no significa nada, al igual que para ncurses antes de una llamada exitosa a use_default_colors o assume_default_colors.

Otras implementaciones de curses no permiten que una aplicación modifique el par de colores 0. Asumen que el fondo es COLOR_BLACK, pero no aseguran que el par de colores 0 se pinte para que coincida con la suposición. Si su aplicación no utiliza ni use_default_colors ni assume_default_colors, ncurses pintará un primer plano blanco (texto) con fondo negro para el par de colores 0.

VALOR DE RETORNO

Estas funciones devuelven el entero ERR en caso de fallo y OK en caso de éxito. Fallarán si el terminal no soporta la capacidad orig_pair u orig_colors. Si la capacidad initialize_pair no se encuentra, esto también causa un error.

NOTAS

Asociada a esta extensión, la función init_pair acepta argumentos negativos para especificar los colores predeterminados del primer plano o del fondo.

La función use_default_colors se añadió para soportar ded. Esta es una aplicación de pantalla completa que utiliza curses para gestionar solo una parte de la pantalla. La parte inferior de la pantalla, que es de tamaño ajustable, se deja sin colorear para mostrar los resultados de los comandos de shell. La parte superior de la pantalla colorea los nombres de archivo utilizando un esquema similar a los programas “color ls”. Intentar gestionar el color de fondo de la pantalla para esta aplicación daría resultados insatisfactorios por diversas razones. Esta extensión se ideó después de observar que el xterm en color (y programas similares) proporciona un color de fondo que no corresponde necesariamente a ninguno de los colores ANSI. Si bien se podría construir una entrada terminfo especial utilizando nueve colores, no se proporcionó ningún mecanismo dentro de curses para tener en cuenta las capacidades relacionadas orig_pair y back_color_erase.

La función assume_default_colors se añadió para resolver un problema diferente: el soporte para aplicaciones que utilizarían variables de entorno y otras configuraciones para eludir la noción de curses de los colores predeterminados del terminal, estableciendo valores específicos.

PORTABILIDAD

Estas rutinas son específicas de ncurses. No eran compatibles con las implementaciones de la Versión 7, BSD o System V. Se recomienda que cualquier código que dependa de ellas esté condicionado usando NCURSES_VERSION.

AUTORES

Thomas Dickey (de un análisis de los requisitos para el xterm en color para XFree86 3.1.2C, febrero de 1996).
