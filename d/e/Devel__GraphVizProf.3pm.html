DESCRIPCIÓ

N

NOTA: Este módulo es una adaptación de Devel::SmallProf de Ted Ashton. Ha sido modificado por Leon Brocard para producir salida para GraphViz, pero de lo único que me he ocupado es de cambiar el nombre. Espero conseguir que mis parches se incorporen al código principal de Devel::SmallProf eventualmente, o alternativamente leer la salida de Devel::SmallProf. De todos modos, la documentación normal, que probablemente puedes ignorar, sigue a

continuación.

El perfilador Devel::GraphVizProf se centra en el tiempo que tarda un programa en ejecutarse línea por línea. Está diseñado para ser lo más "ligero" posible en términos de impacto en la velocidad y el uso de memoria del programa perfilado, y también en términos de sencillez de uso. Esas estadísticas se colocan en el archivo smallprof.out con el siguiente

formato: 
<num> <time> <ctime> <line>:
<text>

donde <num> es el número de veces que la línea fue ejecutada, <time> es la cantidad de "tiempo real" (tiempo según el reloj de la pared frente al tiempo de CPU) dedicado a ejecutarla, <ctime> es la cantidad de tiempo de CPU empleado en ella y <line> y <text> son el número de línea y el texto real de la línea ejecutada (leído del archivo)

.

El paquete utiliza los ganchos de depuración en Perl y por lo tanto necesita el interruptor -d, así que para perfilar test.pl, usa el

comando: 
perl5 -d:GraphVizProf test.
pl

Una vez que el script ha terminado, las estadísticas en smallprof.out pueden ordenarse para mostrar qué líneas tomaron más tiempo. La salida puede ordenarse para encontrar qué líneas toman más tiempo, ya sea con el comando

sort: 
sort -k 2nr,2 smallprof.out |
less

o con un script en

perl: 
open(PROF,"smallprof.out");
@sorted = sort {(split
(/\s+/,$b))[2] <=> (split(/\s+/,$a
))[2]} <PROF>; close PROF; print join('',@sorted);

NOTA

S
  • Las lecturas de "tiempo real" provienen de Time::HiRes y son razonablemente útiles, al menos en mi sistema. Los tiempos de CPU provienen de la función incorporada 'times' y la granularidad no es necesariamente tan pequeña como con el tiempo real. En algunos sistemas esta columna puede ser útil. En otros puede no
    • serlo.
  • GraphVizProf intenta compensar sus deficiencias restando una pequeña cantidad de cada medición de tiempo (compensación de tiempo nulo). Esto debería ayudar en cierta medida con la
    • precisión.
  • GraphVizProf depende del paquete Time::HiRes para h
    • acer sus mediciones de tiempo. Reclama requer
ir la versión 1.20, pero puede funcionar con versio
nes anteriores, dependiendo de tu plataforma.

OPCIONE

S

GraphVizProf tiene 3 variables que pueden usarse durante tu script para afectar a lo que se

perfila.
  • Si no deseas ver líneas que nunca fueron llamadas, establece la variable "$DB::drop_zeros = 1". Con "drop_zeros" establecido, GraphVizProf puede usarse para análisis de cobertura
    • básica.
  • Para desactivar el perfilado por un tiempo, inserta un "$DB::profile = 0" en tu código (el perfilado puede activarse de nuevo con "$DB::profile = 1"). Todo el tiempo entre que el perfilado se desactiva y se reactiva se agrupará y se informará en la línea "$DB::profile = 0". Esto puede usarse para resumir una llamada a subrutina o un trozo de
    • código.
  • Para perfilar solo el código en un paquete determinado, establece el arreglo %DB::packages. Por ejemplo, para ver solo el código en los paquetes "main" y "Test1", haz esto: 
    %DB::packages = ( 'main' => 1, 'Test1' =>
    • 1 );
  • Estas variables pueden ponerse en un archivo llamado .smallprof en el directorio actual. Por ejemplo, un .smallprof que contenga 
    $DB::drop_zeros = 1;
$DB::profile
    = 0;

desactivado inicialmente (presumiblemente para activ
arlo solo para una pequeña porción de código).

ERRORE

S

Las llamadas a subrutinas actualmente no están bajo el control de %DB::packages. Esto no debería ser una gran molestia en

general.

El manejo de los evals es un desastre. Esto se debe al manejo que hace Perl de los evals bajo el indicador -d. Para ciertos evals, caller() devuelve '(eval n)' como nombre de archivo y para otros no. Para algunos de los que sí lo hace, el arreglo "@{'_<filename'}" contiene el código del eval. Para otros no. Algún día, cuando tenga un tuit o dos de sobra, averiguaré por qué y cómo puedo compensar

esto.
