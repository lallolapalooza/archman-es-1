Los siguientes ejemplos no intentan mostrar todo, ya que eso sería una tarea monumental y, francamente, no queremos que esta página man sea un documento de internos de Perl. No hay guías ni redes de seguridad, ni senderos trazados, así que prepárese para viajar solo a partir de este punto y, si es posible, no caiga en la arena movediza (es malo para el negocio)

.

Oh, un último consejo: llévese perlguts. Cuando regrese esperamos verlo bien

consultado.

Un escalar de cadena

simple

Comencemos mirando un escalar simple que contiene una

cadena. 
use Devel::Peek;
$a = 42; $a = "hello";
Dump
$a;

La

salida: 
SV = PVIV(0xbc288) at 0xbe9a8
  REFCNT = 1
  FLAGS = (POK,pPOK)
  IV = 42
  PV = 0xb2048 "hello"\0
  CUR = 5
  LEN =
8

Esto dice que $a es un SV, un escalar. El tipo de escalar es un PVIV, que es capaz de contenter un valor entero (IV) y/o una cadena (PV). La cabecera del escalar está asignada en la dirección 0xbe9a8, mientras que el cuerpo está en 0xbc288. Su conteo de referencia es 1. Tiene el "POK"> se activa el indicador, lo que significa que su campo PV actual es válido. Dado que POK está activado, examinamos el elemento PV para ver qué contiene el escalar. El \0 al final indica que este PV está correctamente terminado en NUL. Nótese que el campo IV aún contiene su valor numérico antiguo, pero como FLAGS no tiene IOK activado, debemos ignorar el elemento IV. CUR indica el número de caracteres en el PV. LEN indica el número de bytes asignados para el PV (al menos uno más que CUR, porque LEN incluye un byte extra para el marcador de fin de cadena, y luego generalmente se redondea a alguna unidad de asignación eficiente).

Un escalar numérico simple

Si el escalar contiene un número, el SV crudo será más ligero.

use Devel::Peek;
$a = 42;
Dump $a;

La salida:

SV = IV(0xbc818) at 0xbe9a8
  REFCNT = 1
  FLAGS = (IOK,pIOK)
  IV = 42

Esto dice $a es un SV, un escalar. El escalar es un IV, un número. Su conteo de referencias es 1. Tiene el "IOK" indicador activado, lo que significa que actualmente se está evaluando como un número. Dado que IOK está activado, examinamos el elemento IV para ver qué contiene el escalar.

Un escalar simple con una referencia extra

Si el escalar del ejemplo anterior tuviera una referencia extra:

use Devel::Peek;
$a = 42;
$b = \$a;
Dump $a;

La salida:

SV = IV(0xbe860) at 0xbe9a8
  REFCNT = 2
  FLAGS = (IOK,pIOK)
  IV = 42

Nótese que este ejemplo difiere del ejemplo anterior solo en su conteo de referencias. Compare esto con el siguiente ejemplo, donde volcamos $b en lugar de $a.

Una referencia a un escalar simple

Esto muestra cómo es una referencia cuando referencia un escalar simple.

use Devel::Peek;
$a = 42;
$b = \$a;
Dump $b;

La salida:

SV = IV(0xf041c) at 0xbe9a0
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xbab08
  SV = IV(0xbe860) at 0xbe9a8
    REFCNT = 2
    FLAGS = (IOK,pIOK)
    IV = 42

Empezando desde arriba, esto dice $b es un SV. El escalar es un IV, que es capaz de contener un valor entero o de referencia. Tiene el "ROK" indicador activado, lo que significa que es una referencia (en lugar de un entero o una cadena). Nótese que Dump sigue la referencia y nos muestra qué $b estaba referenciando. Vemos el mismo $a que encontramos en el ejemplo anterior.

Nótese que el valor de "RV" coincide con los números que vemos cuando convertimos a cadena $b. Las direcciones dentro de IV() son direcciones de "X***" estructuras que contienen el estado actual de un "SV". Esta dirección puede cambiar durante la vida útil de un SV.

Una referencia a un array

Esto muestra cómo es una referencia a un array.

use Devel::Peek;
$a = [42];
Dump $a;

La salida:

SV = IV(0xc85998) at 0xc859a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xc70de8
  SV = PVAV(0xc71e10) at 0xc70de8
    REFCNT = 1
    FLAGS = ()
    ARRAY = 0xc7e820
    FILL = 0
    MAX = 0
    FLAGS = (REAL)
    Elt No. 0
    SV = IV(0xc70f88) at 0xc70f98
      REFCNT = 1
      FLAGS = (IOK,pIOK)
      IV = 42

Esto dice $a es una referencia (ROK), que apunta a otro SV que es un PVAV, un array. El array tiene un elemento, el elemento cero, que es otro SV. El campo "FILL" de arriba indica el último elemento en el array, similar a "$#$a".

Si $a apuntara a un array de dos elementos entonces veríamos lo siguiente.

use Devel::Peek 'Dump';
$a = [42,24];
Dump $a;

La salida:

SV = IV(0x158c998) at 0x158c9a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0x1577de8
  SV = PVAV(0x1578e10) at 0x1577de8
    REFCNT = 1
    FLAGS = ()
    ARRAY = 0x1585820
    FILL = 1
    MAX = 1
    FLAGS = (REAL)
    Elt No. 0
    SV = IV(0x1577f88) at 0x1577f98
      REFCNT = 1
      FLAGS = (IOK,pIOK)
      IV = 42
    Elt No. 1
    SV = IV(0x158be88) at 0x158be98
      REFCNT = 1
      FLAGS = (IOK,pIOK)

Nótese que "Dump" no reportará todos los elementos en el array, solo los primeros varios (dependiendo de qué tan profundo ya haya entrado en el árbol del informe).

Una referencia a un hash

Lo siguiente muestra la forma cruda de una referencia a un hash.

use Devel::Peek;
$a = {hello=>42};
Dump $a;

La salida:

SV = IV(0x55cb50b50fb0) at 0x55cb50b50fc0
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0x55cb50b2b758
  SV = PVHV(0x55cb50b319c0) at 0x55cb50b2b758
    REFCNT = 1
    FLAGS = (SHAREKEYS)
    ARRAY = 0x55cb50b941a0  (0:7, 1:1)
    hash quality = 100.0%
    KEYS = 1
    FILL = 1
    MAX = 7
    Elt "hello" HASH = 0x3128ece4
    SV = IV(0x55cb50b464f8) at 0x55cb50b46508
      REFCNT = 1
      FLAGS = (IOK,pIOK)
      IV = 42

Esto muestra $a es una referencia que apunta a un SV. Ese SV es un PVHV, un hash.

La "calidad" de un hash se define como el número total de comparaciones necesarias para acceder a cada elemento una vez, en relación con el número esperado para un hash aleatorio. El valor puede superar el 100%.

El número total de comparaciones es igual a la suma de los cuadrados del número de entradas en cada cubeta. Para un hash aleatorio de "<n"> claves en "<k"> cubetas, el valor esperado es:

n + n(n-1)/2k

Volcando un array o hash grande

La Dump() función, por defecto, vuelca hasta 4 elementos de un array o hash de nivel superior. Este número puede aumentarse proporcionando un segundo argumento a la función.

use Devel::Peek;
$a = [10,11,12,13,14];
Dump $a;

Nótese que Dump() imprime solo los elementos 10 a 13 en el código anterior. El siguiente código imprimirá todos los elementos.

use Devel::Peek 'Dump';
$a = [10,11,12,13,14];
Dump $a, 5;

Una referencia a un SV que contiene un puntero C

Esto es lo que realmente necesita saber como programador XS, por supuesto. Cuando un XSUB devuelve un puntero a una estructura C, ese puntero se almacena en un SV y una referencia a ese SV se coloca en la pila del XSUB. Así que la salida de un XSUB que usa algo como el mapa T_PTROBJ podría verse algo así:

SV = IV(0xf381c) at 0xc859a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xb8ad8
  SV = PVMG(0xbb3c8) at 0xc859a0
    REFCNT = 1
    FLAGS = (OBJECT,IOK,pIOK)
    IV = 729160
    NV = 0
    PV = 0
    STASH = 0xc1d10       "CookBookB::Opaque"

Esto muestra que tenemos un SV que es una referencia, que apunta a otro SV. En este caso ese segundo SV es un PVMG, un escalar bendito. Dado que está bendito tiene el "OBJECT" indicador activado. Nótese que un SV que contiene un puntero C también tiene el "IOK" indicador activado. El "STASH" está establecido al nombre del paquete en el que este SV fue bendecido.

La salida de un XSUB que usa algo como el mapa T_PTRREF, que no bendice el objeto, podría verse algo así:

SV = IV(0xf381c) at 0xc859a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xb8ad8
  SV = PVMG(0xbb3c8) at 0xc859a0
    REFCNT = 1
    FLAGS = (IOK,pIOK)
    IV = 729160
    NV = 0
    PV = 0

Una referencia a una subrutina

Se ve así:

SV = IV(0x24d2dd8) at 0x24d2de8
  REFCNT = 1
  FLAGS = (TEMP,ROK)
  RV = 0x24e79d8
  SV = PVCV(0x24e5798) at 0x24e79d8
    REFCNT = 2
    FLAGS = ()
    COMP_STASH = 0x22c9c50      "main"
    START = 0x22eed60 ===> 0
    ROOT = 0x22ee490
    GVGV::GV = 0x22de9d8        "MY" :: "top_targets"
    FILE = "(eval 5)"
    DEPTH = 0
    FLAGS = 0x0
    OUTSIDE_SEQ = 93
    PADLIST = 0x22e9ed8
    PADNAME = 0x22e9ec0(0x22eed00) PAD = 0x22e9ea8(0x22eecd0)
    OUTSIDE = 0x22c9fb0 (MAIN)

Esto muestra que

  • la subrutina no es un XSUB (ya que "START" y "ROOT" son distintos de cero, y "XSUB" no está listado, y por lo tanto es nulo);
  • que fue compilada en el paquete "main";
  • bajo el nombre "MY::top_targets";
  • dentro de un 5º eval en el programa;
  • no se está ejecutando actualmente (porque "DEPTH" es 0);
  • no tiene prototipo ("PROTOTYPE" campo falta).
