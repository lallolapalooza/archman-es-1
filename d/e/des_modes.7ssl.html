NOMBRE

des_modes - las variantes de DES y otros algoritmos criptográficos de OpenSSL

DESCRIPCIÓN

Varios algoritmos criptográficos para OpenSSL se pueden usar en varios modos. Estos se utilizan para usar cifradores de bloque de una manera similar a los cifradores de flujo, entre otras cosas.

VISIÓN GENERAL

Modo de Libro de Códigos Electrónicos (ECB)

Normalmente, esto se encuentra como la función algoritmo_ecb_encrypt().

  • Se cifran 64 bits a la vez.
  • El orden de los bloques puede reorganizarse sin ser detectado.
  • El mismo bloque de texto plano siempre produce el mismo bloque de texto cifrado (para la misma clave) lo que lo hace vulnerable a un 'ataque de diccionario'.
  • Un error solo afectará a un bloque de texto cifrado.

Modo de Encadenamiento de Bloques de Cifrado (CBC)

Normalmente, esto se encuentra como la función algoritmo_cbc_encrypt(). Tenga en cuenta que des_cbc_encrypt() no es realmente DES CBC (no actualiza el IV); use des_ncbc_encrypt() en su lugar.

  • Se cifra un múltiplo de 64 bits a la vez.
  • El modo CBC produce el mismo texto cifrado siempre que el mismo texto plano se cifra utilizando la misma clave y variable de inicio.
  • La operación de encadenamiento hace que los bloques de texto cifrado dependan de los bloques de texto plano actuales y de todos los anteriores, por lo que los bloques no se pueden reorganizar.
  • El uso de diferentes variables de inicio evita que el mismo texto plano se cifre en el mismo texto cifrado.
  • Un error afectará a los bloques de texto cifrado actuales y siguientes.

Modo de Retroalimentación de Cifrado (CFB)

Normalmente, esto se encuentra como la función algoritmo_cfb_encrypt().

  • Se cifra un número de bits (j) <= 64 a la vez.
  • El modo CFB produce el mismo texto cifrado siempre que el mismo texto plano se cifra utilizando la misma clave y variable de inicio.
  • La operación de encadenamiento hace que las variables de texto cifrado dependan de las variables actuales y todas las anteriores, por lo que las variables de j bits se encadenan juntas y no se pueden reorganizar.
  • El uso de diferentes variables de inicio evita que el mismo texto plano se cifre en el mismo texto cifrado.
  • La fortaleza del modo CFB depende del tamaño de k (máxima si j == k). En mi implementación, este es siempre el caso.
  • La selección de un valor pequeño para j requerirá más ciclos a través del algoritmo de cifrado por unidad de texto plano y, por lo tanto, causará mayores sobrecargas de procesamiento.
  • Solo se pueden cifrar múltiplos de j bits.
  • Un error afectará a las variables de texto cifrado actuales y siguientes.

Modo de Retroalimentación de Salida (OFB)

Normalmente, esto se encuentra como la función algoritmo_ofb_encrypt().

  • Se cifra un número de bits (j) <= 64 a la vez.
  • El modo OFB produce el mismo texto cifrado siempre que el mismo texto plano se cifre utilizando la misma clave y variable de inicio. Además, en el modo OFB se produce el mismo flujo de claves cuando se utilizan la misma clave y variable de inicio. En consecuencia, por razones de seguridad, una variable de inicio específica solo debe usarse una vez para una clave dada.
  • La ausencia de encadenamiento hace que el OFB sea más vulnerable a ataques específicos.
  • El uso de diferentes valores de variables de inicio evita que el mismo texto plano se cifre en el mismo texto cifrado, produciendo diferentes flujos de claves.
  • La selección de un valor pequeño para j requerirá más ciclos a través del algoritmo de cifrado por unidad de texto plano y, por lo tanto, causará mayores sobrecargas de procesamiento.
  • Solo se pueden cifrar múltiplos de j bits.
  • El modo de operación OFB no extiende los errores de texto cifrado en la salida de texto plano resultante. Cada error de bit en el texto cifrado causa solo un bit de error en el texto plano descifrado.
  • El modo OFB no se auto-sincroniza. Si las dos operaciones de cifrado y descifrado pierden la sincronización, el sistema debe reinicializarse.
  • Cada reinicialización debe usar un valor de la variable de inicio diferente de los valores de la variable de inicio utilizados anteriormente con la misma clave. La razón de esto es que se produciría un flujo de bits idéntico cada vez a partir de los mismos parámetros. Esto sería susceptible a un ataque de 'texto plano conocido'.

Modo Triple ECB

Normalmente, esto se encuentra como la función algoritmo_ecb3_encrypt().

  • Cifrar con clave1, descifrar con clave2 y volver a cifrar con clave3.
  • Al igual que con el cifrado ECB, pero aumenta la longitud de la clave a 168 bits. Existen ataques teóricos que pueden utilizarse para que la longitud efectiva de la clave sea de 112 bits, pero este ataque también requiere 2^56 bloques de memoria, lo cual no es muy probable, ni siquiera para la NSA.
  • Si ambas claves son iguales, es equivalente a cifrar una vez con una sola clave.
  • Si la primera y la última clave son iguales, la longitud de la clave es de 112 bits. Existen ataques que podrían reducir la fortaleza efectiva de la clave a solo un poco más de 56 bits, pero estos requieren mucha memoria.
  • Si las 3 claves son iguales, esto es efectivamente lo mismo que el modo ecb normal.

Modo Triple CBC

Normalmente, esto se encuentra como la función algoritmo_ede3_cbc_encrypt().

  • Cifrar con clave1, descifrar con clave2 y luego cifrar con clave3.
  • Al igual que con el cifrado CBC, pero aumenta la longitud de la clave a 168 bits con las mismas restricciones que para el modo triple ecb.
