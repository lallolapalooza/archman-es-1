Device::Modem(3) Documentación de Perl aportada por el usuario Device::Modem(3)

NOMBRE

Device::Modem - Extensión de Perl para comunicarse con dispositivos de módem conectados a través de puerto serie

ADVERTENCIA

Este es software BETA , así que úselo bajo su propio riesgo y sin NINGUNA garantía. Diviértase.

SINOPSIS

use Device::Modem;
my $modem = Device::Modem->new( port => '/dev/ttyS1' );
if( $modem->connect( baudrate => 9600 ) ) {
    print "connected!\n";
} else {
    print "sorry, no connection with serial port!\n";
}
$modem->attention();          # send `attention' sequence (+++)
($ok, $answer) = $modem->dial('02270469012');  # dial phone number
$ok = $modem->dial(3);        # 1-digit parameter = dial number stored in memory 3
$modem->echo(1);              # enable local echo (0 to disable)
$modem->offhook();            # Take off hook (ready to dial)
$modem->hangup();             # returns modem answer
$modem->is_active();          # Tests whether modem device is active or not
                              # So far it works for modem OFF/ modem ON condition
$modem->reset();              # hangup + attention + restore setting 0 (Z0)
$modem->restore_factory_settings();  # Handle with care!
$modem->restore_factory_settings(1); # Same with preset profile 1 (can be 0 or 1)
$modem->send_init_string();   # Send initialization string
                              # Now this is fixed to 'AT H0 Z S7=45 S0=0 Q0 V1 E0 &C0 X4'
# Get/Set value of S1 register
my $S1 = $modem->S_register(1);
my $S1 = $modem->S_register(1, 55); # Don't do that if you definitely don't know!
# Get status of managed signals (CTS, DSR, RLSD, RING)
my %signal = $modem->status();
if( $signal{DSR} ) { print "Data Set Ready signal active!\n"; }
# Stores this number in modem memory number 3
$modem->store_number(3, '01005552817');
$modem->repeat();             # Repeat last command
$modem->verbose(1);           # Normal text responses (0=numeric codes)
# Some raw AT commands
$modem->atsend( 'ATH0' );
print $modem->answer();
$modem->atsend( 'ATDT01234567' . Device::Modem::CR );
print $modem->answer();

DESCRIPCIÓN

La clase "Device::Modem" implementa una abstracción de dispositivo básica compatible con AT (Hayes) . Puede ser heredada por subclases (como "Device::Gsm"), que están basadas en conexiones seriales.

Cosas que "Device::Modem" puede hacer

  • conectarse a un módem en su puerto serie
  • probar si el módem está vivo y funcionando
  • marcar un número y conectarse a un módem remoto
  • trabajar con registros y ajustes del módem
  • emitir comandos AT estándar o arbitrarios "AT" , obteniendo resultados del módem

Cosas que "Device::Modem" aún no puede hacer

  • Transferir un archivo a un módem remoto
  • Controlar una conexión tipo terminal (o PPP). Esto realmente no debería ser muy difícil de hacer.
  • Muchas otras...

Cosas que nunca podrá hacer

•
Café :-)

Ejemplos

En el directorio 'examples', hay algunos scripts que deberían funcionar sin grandes problemas, que puede tomar como (sí) ejemplos:

`examples/active.pl'
Prueba si el módem está vivo
`examples/caller-id.pl'
Espera una llamada entrante y muestra la fecha, hora y número de teléfono del llamante. Normalmente esto está disponible en todas partes, pero debería verificar su línea telefónica local y la configuración.
`examples/dial.pl'
Marca un número de teléfono y muestra el resultado de la llamada
`examples/shell.pl'
Utilidad minicom/hyperterminal para el pobre (muy) pobre
`examples/xmodem.pl'
Primer intento de un script de prueba para recibir un archivo mediante el protocolo xmodem. Tenga en cuenta que esto no tiene ninguna posibilidad de funcionar. Es solo un trabajo en progreso (de muy baja prioridad)...

Si desea ayudar, ¡sea bienvenido!

MÉTODOS

answer()

Uno de los métodos más utilizados, espera una respuesta del dispositivo. Espera hasta que se alcance $timeout (segundos) (pero no confíe en que este tiempo sea muy preciso) o hasta que se encuentre una cadena esperada. Ejemplo:

$answer = $modem->answer( [$expect [, $timeout]] )

Devuelve $answer que es la cadena recibida del módem, eliminando todos los Retornos de carro y Saltos de línea caracteres solo al principio y al final de la cadena. No se eliminan los CR+LF intermedios.

Tenga en cuenta que si necesita la respuesta cruda del módem, puede usar el método _answer() (note el carácter guion bajo antes de answer), que no elimina nada de la respuesta, por lo que obtiene la cadena de respuesta real del módem.

Parámetros:

  • $expect - Puede ser una expresión regular compilada con "qr" o una subcadena simple. La entrada que viene del módem se compara con este parámetro. Si la entrada coincide, se devuelve el resultado.
  • $timeout - Expresado en milisegundos. Después de ese tiempo, answer devuelve el resultado incluso si no se ha recibido nada. Ejemplo: 10000. Por defecto: $Device::Modem::TIMEOUT, actualmente 500 ms.

atsend()

Envía un comando AT crudo "AT" al dispositivo conectado. Tenga en cuenta que este método se usa principalmente internamente, pero también puede usarse para enviar sus propios comandos personalizados. Ejemplo:

$ok = $modem->atsend( $msg )

El único parámetro es $msg, que es el comando AT crudo a enviar al módem expresado como cadena. Debe incluir el prefijo "AT" y el Retorno de carro final y/o Salto de línea manualmente. Existe la constante especial "CR" que puede usarse para incluir tal secuencia de caracteres en el comando at.

Devuelve $ok que es verdadero si todos los caracteres se envían correctamente, falso en caso contrario.

Ejemplo:

# Enable verbose messages
$modem->atsend( 'AT V1' . Device::Modem::CR );
# The same as:
$modem->verbose(1);

attention()

Este comando envía una secuencia de atención al módem. Esto permite al módem pasar al estado de comando y aceptar comandos AT . Ejemplo:

$ok = $modem->attention()

connect()

Conecta el objeto "Device::Modem" al puerto serie especificado. Hay opciones (las mismas opciones que "Device::SerialPort" tiene) para controlar los parámetros asociados al enlace serie. Ejemplo:

$ok = $modem->connect( [%options] )

La lista de opciones permitidas sigue:

"baudrate"
Controla la velocidad de las comunicaciones seriales. El valor por defecto es 19200 baudios, que debería ser soportado por todos los módems modernos. Sin embargo, aquí puede proporcionar un valor personalizado. Valores de velocidad comunes: 300, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200. Este parámetro es manejado directamente por el objeto "Device::SerialPort" .
"databits"
Indica de cuántos bits se compone su palabra de datos. El valor por defecto (y la configuración más común) es 8. Este parámetro es manejado directamente por el objeto "Device::SerialPort" .
"handshake"
Establece el método de handshake (o control de flujo) para el puerto serie. Por defecto es "none", pero puede ser "rts" (control de flujo por hardware) o "xoff" (control de flujo por software). Estos modos de control de flujo pueden o no funcionar dependiendo de su dispositivo de módem o software.
"init_string"
Puede proporcionarse una cadena de inicialización personalizada en lugar de la incorporada, que es la siguiente: "H0 Z S7=45 S0=0 Q0 V1 E0 &C0 X4", que parece haberse tomado descaradamente de la utilidad "minicom", creo yo.
"parity"
Controla cómo se genera y verifica el bit de paridad. Puede ser even (par), odd (impar) o none (ninguno). El valor predeterminado es none. Este parámetro se maneja directamente por el objeto "Device::SerialPort".
"stopbits"
Indica cuántos bits se utilizan para identificar el final de una palabra de datos. El valor predeterminado (y el uso más común) es 1. Este parámetro se maneja directamente por el objeto "Device::SerialPort".

dial()

Establece una conexión telefónica. Puede realizar llamadas tanto de voz como de datos.

Uso:

    $ok = $modem->dial($number);
$ok = $modem->dial($number, $timeout);
$ok = $modem->dial($number, $timeout, $mode);

Coloca el módem en estado "off hook" (descolgado), establece la conexión con el número especificado y devuelve la respuesta del módem.

En cuanto a las llamadas de voz, no podrá enviar su voz a través de la conexión. Es probable que tenga que conectar un micrófono analógico y simplemente hablar. O utilizar un teléfono GSM. Para las llamadas de voz, se añade un simple ";" al final del número a marcar.

Si el número a marcar tiene solo un dígito, extrae el número del directorio de contactos, siempre que su dispositivo lo tenga. Vea store_number().

Ejemplos:

    # Uso simple. Timeout y mode son opcionales.
$ok = $mode->dial('123456789');
    # Contexto de lista: permite obtener la respuesta exacta del módem
    # como `CONNECT 19200/...', `BUSY', `NO CARRIER', ...
# Además, un timeout de 30 segundos
    ($ok, $answer) = $modem->dial('123456789', 30);

Si se llama en contexto escalar, devuelve solo el éxito o fracaso de la conexión. Si la respuesta del módem contiene la cadena "CONNECT", dial() devuelve un estado de éxito; de lo contrario, se devuelve un valor falso.

Si se llama en contexto de lista, devuelve el mismo $ok flag, pero también la respuesta exacta del módem a la operación de marcado en el escalar $answer. $answer típicamente puede contener cadenas como:

"CONNECT 19200"
"NO CARRIER"
"BUSY"

y así sucesivamente... todas las respuestas estándar del módem a un comando de marcado.

Los parámetros son:

$number
obligatorio, este es el número de teléfono a marcar. Si $number tiene solo un dígito, se interpreta como: marcar el número en la posición de mi directorio de contactos $number.

Así que si su código es:

$modem->dial( 2, 10 );

Esto significa: marcar el número en el directorio interno del módem (vea "store_number" para saber cómo leer/escribir el directorio de contactos) en la posición número 2 y esperar un timeout de 10 segundos.

$timeout
opcional, el predeterminado es 30 segundos.

Tiempo de espera en segundos para que el dispositivo remoto responda. Por favor, no espere un tiempo exacto al número de segundos que haya especificado.

$mode
opcional, el predeterminado es "DATA", como cadena. Permite especificar el tipo de llamada. Puede ser cualquiera de:
"DATA" (predeterminado)
Para realizar una llamada de datos.
"VOICE"
Para realizar una llamada de voz, si su dispositivo lo soporta. No se intentará verificar si su dispositivo puede hacerlo.

disconnect()

Desconecta el objeto "Device::Modem" de la porta serial. Este método llama al método subyacente disconnect() de "Device::SerialPort". Ejemplo:

$modem->disconnect();

echo()

Habilita o deshabilita el eco local de comandos. Esto se gestiona automáticamente por el objeto "Device::Modem". Normalmente no debería preocuparse por esto. Uso:

$ok = $modem->echo( $enable )

hangup()

Hace lo que se supone que debe hacer. Colgar el teléfono, terminando así cualquier llamada activa. Uso:

$ok = $modem->hangup();

is_active()

Puede utilizarse para comprobar si hay un módem conectado a su ordenador. Si el módem está activo y responde (en el enlace serial, no a una llamada remota), is_active() devuelve true (1), de lo contrario devuelve false (0).

La prueba de actividad del módem se realiza a través de la señal DSR (Data Set Ready). Si esta señal está en estado apagado, el módem probablemente está apagado o no funciona. Según mis pruebas, he encontrado que la DSR permanece en estado "encendido" durante más o menos un segundo después de apagar mi módem, así que ahora lo sabes.

Ejemplo:

if( $modem->is_active() ) {
        # Ok!
} else {
        # ¿Módem apagado?
}

log()

Accesor simple para el objeto de registro instanciado en el momento de la creación del objeto. Se utiliza internamente. Si desea conocer los detalles, vea "Device::Modem::Log::*" objetos. Puede también ver los ejemplos para saber cómo registrar algo sin conocer todos los detalles.

Pista: $modem->log->write('warning', 'ok, my log message here');

new()

Constructor de "Device::Modem". Esto acepta varias opciones. Un ejemplo básico:

my $modem = Device::Modem->new( port => '/dev/ttyS0' );

si está bajo Linux o algún tipo de máquina unix, o

my $modem = Device::Modem->new( port => 'COM1' );

si está utilizando una máquina Win32.

Esto crea el objeto "Device::Modem" con todos los parámetros predeterminados. Esto debería ser bastante útil si desea conectarse a un módem real. Nota que lo estoy probando con un módem 3Com US Robotics 56K Message a 19200 baudios y funciona bien.

Lista de opciones permitidas:

  • "port" - porta serial a la que conectarse. En Unix, también puede ser un enlace conveniente como /dev/modem (el valor predeterminado). Para Win32, se pueden usar "COM1,2,3,4".
  • "log" - esto especifica el método y eventualmente el nombre del archivo para el registro. El proceso de registro con "Device::Modem" está controlado por plugins de registro, almacenados en la carpeta Device/Modem/Log/. Por ahora, hay dos plugins principales: "Syslog" y "File". "Syslog" no funciona con máquinas Win32. Cuando se utiliza el plugin "File", toda la información de registro se escribirá en un nombre de archivo predeterminado si no especifica uno usted mismo. El predeterminado es %WINBOOTDIR%\temp\modem.log en Win32 y /var/log/modem.log en Unix.

    Además, existe la posibilidad de pasar un objeto de registro personalizado, si este objeto proporciona la siguiente llamada write():

    $log_object->write( $loglevel, $logmessage )

    Puede simplemente pasar este objeto (ya instanciado) como la propiedad "log".

    Ejemplos:

    # Para Win32, el predeterminado es registrar en el archivo "%WINBOOTDIR%/temp/modem.log"
my $modem = Device::Modem->new( port => 'COM1' );
# Unix, archivo de registro personalizado
my $modem = Device::Modem->new( port => '/dev/ttyS0', log => 'file,/home/neo/matrix.log' )
# Con objeto de registro personalizado
my $modem = Device::Modem->new( port => '/dev/ttyS0', log => My::LogObj->new() );
  • "loglevel" - nivel de registro predeterminado. Uno de (orden de decreciente de verbosidad): "debug", "verbose", "notice", "info", "warning", "err", "crit", "alert", "emerg".

offhook()

Pone el módem en estado "off hook" (descolgado), listo para marcar. Normalmente no necesita utilizar esto. Además, dial() pasa automáticamente a estado off hook antes de marcar.

parse_answer()

Este método funciona como answer(), acepta los mismos parámetros, pero no devuelve la respuesta cruda del módem. En su lugar, devuelve la cadena de respuesta eliminando todos los caracteres CR/LF al principio y al final.

parse_answer() está diseñado como una forma fácil de extraer el código de resultado ("OK", "ERROR", ...) y las cadenas de información que pueden enviarse por el módem en respuesta a comandos específicos. Ejemplo:

> AT xSHOW_MODELx<CR>
US Robotics 56K Message
OK
>

En este ejemplo, "OK" es el resultado y "US Robotics 56K Message" es el mensaje de información.

De hecho, otra diferencia con answer() es en el valor de retorno(s). Aquí hay algunos ejemplos:

$modem->atsend( '?my_at_command?' );
$answer = $modem->parse_answer();

donde $answer es la cadena de respuesta completa, o:

($result, @lines) = $modem->parse_answer();

donde $result es el mensaje final "OK" o "ERROR" y @lines es el array de mensajes de información (una o más líneas). Para el ejemplo de modelo, $result contendría ""OK"" y @lines consistiría en solo una línea con la cadena ""US Robotics 56K Message"".

port()>

Usado internamente. Accede al "Device::SerialPort" objeto subyacente. Si necesitas experimentar o realizar llamadas seriales de bajo nivel, es posible que quieras acceder a esto. Por favor, informa de cualquier uso de este tipo, porque probablemente (?) es posible incluirlo en un método de nivel superior.

A partir de la versión 1.52, port() intentará automáticamente reconectar si detecta un objeto de puerto subyacente inválido. Se reconectará con las mismas opciones utilizadas cuando se connect()ó por primera vez.

Si aún no se ha producido ninguna conexión, entonces no se intentará la reconexión automática .

repeat()

Repite el último "AT" comando emitido. Uso:

$ok = $modem->repeat()

reset()

Intenta de cualquier manera posible restablecer el módem al estado inicial, colgando todas las llamadas activas, reenviando la cadena de inicialización y preparándose para recibir "AT" comandos.

restore_factory_settings()

Restaura la configuración de fábrica predeterminada del módem. Normalmente hay dos "perfiles" principales, dos memorias diferentes para toda la configuración del módem, de modo que puedes cargar el perfil 0 y el perfil 1, que pueden ser diferentes dependiendo del fabricante de tu módem.

Uso:

$ok = $modem->restore_factory_settings( [$profile] )

Si no se proporciona $profile , 0 se asume como valor predeterminado.

Consulta el manual de hardware de tu módem para el significado de estos perfiles.

S_register()

Obtiene o establece un registro S valor. Estos son algunos registros internos del módem que contienen información importante que controla todo el comportamiento del módem. Si no sabes lo que estás haciendo, no uses este método. Uso:

$value = $modem->S_register( $reg_number [, $new_value] );

$reg_number varía de 0 a 99 (¿seguro?). Si no se proporciona $new_value , el valor de retorno es el valor actual del registro. Si se proporciona un $new_value (quieres establecer el valor del registro), el valor de retorno es el nuevo valor o "undef" si hubo un error al establecer el nuevo valor.

<!-- Aquí se explica de todo -->

Ejemplos:

# Obtener el valor del registro S7
$modem->S_register(7);
# Establecer el valor del registro S0 a 0
$modem->S_register(0, 0);

send_init_string()

Envía la cadena de inicialización al módem conectado. Uso:

$ok = $modem->send_init_string( [$init_string] );

Si especificaste un "init_string" como opción al new() constructor de objetos, se toma por defecto para inicializar el módem. De lo contrario, puedes especificar el parámetro $init_string para usar tu propia cadena de inicialización personalizada. ¡Ten cuidado!

status()

Devuelve el estado de las señales principales del módem según lo gestionado por "Device::SerialPort" (o "Win32::SerialPort") objetos. Las señales reportadas son:

CTS
Listo para enviar
DSR
Conjunto de datos listo
RING
Activo si el módem está sonando
RLSD
??? Línea liberada ???

El valor de retorno de la llamada status() es un hash, donde cada clave es un nombre de señal y cada valor es > 0 si la señal está activa, 0 en caso contrario. Uso:

...
my %sig = $modem->status();
for ('CTS','DSR','RING','RLSD') {
        print "Signal $_ is ", ($sig{$_} > 0 ? 'on' : 'off'), "\n";
}

store_number()

Almacena un número de teléfono en la libreta de direcciones interna del módem, para ser marcado más tarde (ver dial() método). Uso:

$ok = $modem->store_number( $position, $number )

donde $position es la ranura de memoria de la libreta de direcciones donde almacenar el número de teléfono (generalmente de 0 a 9), y $number es el número a almacenar en la ranura. El valor de retorno es verdadero si la operación fue exitosa, falso en caso contrario.

verbose()

Habilita o deshabilita los mensajes detallados. Esto es gestionado automáticamente por el objeto "Device::Modem" . Normalmente no deberías preocuparte por esto. Uso:

$ok = $modem->verbose( $enable )

wait()

Espera (sí) una cantidad de tiempo dada (en milisegundos). Uso:

$modem->wait( [$msecs] )

La espera está implementada a través de la llamada al sistema "select" . No sé si esto es realmente un problema en algunas plataformas.

write_drain()

Solo un simple envoltorio alrededor del método "Device::SerialPort::write_drain" . Deshabilitado para la plataforma Win32, que no lo tiene.

REQUIERE

Device::SerialPort (Win32::SerialPort para máquinas Win32)

EXPORTA

Nada

POR HACER

AutoScan
Se ejecuta un script de comandos AT con todos los comandos interesantes cuando se invoca `autoscan', creando un `perfil' del dispositivo actual, con la lista de comandos soportados, y una base de datos de comandos específicos de marca/modelo
Autodetección de velocidad serial
Ahora, si te conectas a una velocidad de baudios diferente a la de tu módem, probablemente no obtendrás ninguna respuesta. Sería bueno si "Device::Modem" pudiera autodetectar la velocidad para conectarse correctamente a tu módem.
Transferencias de archivos
Sería bueno implementar transferencias como "[xyz]modem" entre dos "Device::Modem" objetos conectados con dos módems.
