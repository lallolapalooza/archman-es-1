CABECERA HTTP

Antes de que se inicie cada función de búsqueda, una aplicación cliente puede añadir cabeceras de solicitud HTTP. Estas se restablecen después de cada función de búsqueda. debuginfod_add_http_header() puede llamarse con cadenas de la forma "Header: value". Estas cadenas son copiadas por la biblioteca. Un valor de retorno cero indica éxito, pero las condiciones de falta de memoria pueden resultar en un -ENOMEMdistinto de cero. Si la cadena tiene el formato incorrecto, se devolverá -EINVAL .

$DEBUGINFOD_HEADERS_FILE especifica un archivo para proporcionar cabeceras a las solicitudes salientes. Cada línea que no esté en blanco de este archivo se maneja como si se hubiera llamado a debuginfod_add_http_header() con su contenido.

Tenga en cuenta que la implementación actual de la biblioteca debuginfod-client usa libcurl, pero no debe depender de ese hecho. No use esta función para reemplazar ninguna cabecera estándar, excepto para la User-Agent mencionada a continuación. Puede usar esta función para añadir información de autorización para el control de acceso, o para proporcionar cabeceras opcionales al servidor con fines de registro.

De forma predeterminada, la biblioteca añade una cabecera User-Agent: descriptiva a las solicitudes salientes. Si la aplicación cliente añade una cabecera con el mismo nombre, esta configuración predeterminada se suprime.

Durante o después de una búsqueda, una aplicación cliente puede llamar a debuginfod_get_headers() para recopilar el subconjunto de cabeceras de respuesta HTTP recibidas del servidor debuginfod actual o más reciente. Solo se conservan aquellas cabeceras con el prefijo X-DEBUGINFOD (sin distinguir mayúsculas de minúsculas). Se devuelven como una sola cadena, con cada "cabecera: valor" terminada con un \n (no \r\n como en HTTP). Puede ser NULL. La cadena resultante es propiedad de la biblioteca y no debe ser modificada ni liberada. El llamante debe copiar la cadena devuelta si necesita usarla más allá de la liberación del objeto cliente.

MACROS

DEBUGINFOD_SONAME

Definido como la cadena que podría pasarse a dlopen(3) si la biblioteca se carga en tiempo de ejecución, por ejemplo


void *debuginfod_so = dlopen(DEBUGINFOD_SONAME, RTLD_LAZY);

SEGURIDAD

Si hay firmas IMA disponibles de los RPM que contienen los archivos solicitados, entonces debuginfod extraerá esas firmas en cabeceras de respuesta, y debuginfod_find_*() realizará la verificación de los archivos. La política de validación se controla mediante etiquetas insertadas en $DEBUGINFOD_URLS. De forma predeterminada, debuginfod_find_*() actúa en modo de ignorar.

Si se accede a través de HTTP en lugar de HTTPS, la red debe ser de confianza. La información de autenticación a través de la biblioteca interna libcurl no está habilitada actualmente, excepto para el estilo de texto plano básico http[s]://userid:password@hostname/ . (El servidor debuginfod no realiza autenticación, pero un servidor proxy de front-end podría hacerlo.)

ERRORES

La siguiente lista no es exhaustiva. Los códigos de error también pueden originarse en llamadas a varias funciones de la Biblioteca C.

EACCESS
Acceso denegado al recurso ubicado en la URL.
ECONNREFUSED
No se pudo conectar con el host remoto. También se devuelve cuando una conexión HTTPS no pudo ser verificada (certificado incorrecto).
ECONNRESET
No se pudieron enviar ni recibir datos de red.
EHOSTUNREACH
No se pudo resolver el host remoto.
EINVAL
Uno o más argumentos tienen un formato incorrecto. build_id puede ser demasiado largo (más de 256 caracteres), filename puede no ser una ruta absoluta o una URL de debuginfod está mal formada.
EIO
No se pudieron escribir los datos recibidos del servidor en el archivo local.
EMLINK
Demasiadas redirecciones HTTP.
ENETUNREACH
No se pudo inicializar la conexión de red.
ENOENT
No se pudo encontrar el recurso ubicado en la URL. A menudo este código de error indica que un servidor debuginfod fue contactado con éxito pero el servidor no pudo encontrar el archivo de destino.
ENOMEM
El sistema no puede asignar recursos.
ENOSYS
$DEBUGINFOD_URLS no está definido.
ETIME
La consulta falló debido a un tiempo de espera agotado. $DEBUGINFOD_TIMEOUT y $DEBUGINFOD_MAXTIME controlan esto.
EF2BIG
La consulta fue abortada debido a que el archivo solicitado es demasiado grande. El $DEBUGINFOD_MAXSIZE controla esto.
EBADMSG
El contenido del archivo falló la verificación IMA contra un certificado de firmante conocido.
ENOKEY
El contenido del archivo falló la verificación IMA debido a la falta de un certificado de firmante.
ENODATA
El contenido del archivo falló la verificación IMA debido a una firma faltante.

VARIABLES DE ENTORNO

$TMPDIR
Esta variable de entorno apunta a un sistema de archivos para usar con archivos temporales. El valor predeterminado es /tmp.
$DEBUGINFOD_URLS
Esta variable de entorno contiene una lista de prefijos de URL para instancias debuginfod de confianza. Los prefijos de URL alternativos se separan por espacios. Esta variable de entorno puede ser establecida por scripts /etc/profile.d que leen archivos /etc/debuginfod/*.urls.

Esta variable de entorno también puede contener etiquetas que definen la política y dictan la política de respuesta para verificar firmas IMA por archivo en RPM. Dado que la lista separada por espacios se lee de izquierda a derecha, al encontrar una etiqueta, las URL subsiguientes hasta la siguiente etiqueta se manejarán usando esa política especificada. Todas las URL antes de la primera etiqueta usarán la política predeterminada, ima:ignore. Por ejemplo:


DEBUGINFOD_URLS="https://foo.com ima:enforcing https://bar.ca http://localhost:8002/ ima:ignore https://baz.org"

Donde foo.com y baz.org usan la política predeterminada ignore y bar.ca y localhost usan una política enforcing . La etiqueta de política puede ser una de las siguientes:

ima:enforcing Cada archivo descargado requiere una firma válida, protegiendo completamente la integridad.
ima:ignore Omite la verificación por completo, sin proporcionar ninguna protección.

Las alertas de fallo de validación se dirigirán como se especifica en $DEBUGINFOD_VERBOSE.

$DEBUGINFOD_CACHE_PATH
Esta variable de entorno gobierna la ubicación de la caché donde se guardan los archivos descargados y los archivos de control de caché. El directorio predeterminado se elige basándose en otras variables de entorno, ver más abajo.
$DEBUGINFOD_PROGRESS
Esta variable de entorno gobierna la función de progreso predeterminada. Si está definida, y si no se establece explícitamente una progressfn, entonces la biblioteca configurará una progressfn predeterminada. Esta función añadirá un mensaje de progreso simple periódicamente a stderr. El valor predeterminado es sin salida de función de progreso.
$DEBUGINFOD_VERBOSE
Esta variable de entorno gobierna el descriptor de archivo predeterminado para la salida detallada. Si está definida, y si no se establece explícitamente un fd detallado, entonces la salida detallada se producirá en STDERR_FILENO.
$DEBUGINFOD_RETRY_LIMIT
Esta variable de entorno gobierna el límite predeterminado de intentos de reintento. Si una consulta falló con un errno distinto de ENOENT, se iniciarán varios intentos dentro del límite.
$DEBUGINFOD_TIMEOUT
Esta variable de entorno gobierna el tiempo de espera de inicio de descarga para cada conexión HTTP de debuginfod. Un servidor que no proporcione al menos 100K de datos dentro de este número de segundos es omitido. El valor predeterminado es 90 segundos. (Cero o negativo significa "sin tiempo de espera".)
$DEBUGINFOD_MAXTIME
Esta variable de entorno dicta cuánto tiempo esperará el cliente para completar la descarga de un archivo encontrado en un servidor, en segundos. Es mejor usarla para asegurar que un archivo se descargue rápidamente o sea rechazado. El valor predeterminado es 0 (tiempo infinito).
$DEBUGINFOD_MAXSIZE
Esta variable de entorno dicta el tamaño máximo de un archivo a descargar en bytes. Es mejor usarla si el usuario desea asegurar que solo se descarguen archivos pequeños. Un valor de 0 causa que no se considere el tamaño, y el cliente puede intentar descargar un archivo de cualquier tamaño. El valor predeterminado es 0 (tamaño infinito).
$DEBUGINFOD_HEADERS_FILE
Esta variable de entorno apunta a un archivo que proporciona cabeceras a las solicitudes HTTP salientes, una por línea. Las líneas de cabecera no deberían terminar con CRLF, a menos que esa sea la convención de salto de línea del sistema. Las líneas que solo contienen espacios en blanco se omiten.
$DEBUGINFOD_IMA_CERT_PATH
Esta variable de entorno contiene una lista de rutas de directorio absolutas que contienen certificados X.509 para la verificación IMA por archivo de RPM. Las rutas alternativas se separan por dos puntos.

CACHÉ

Antes de cada consulta, la biblioteca cliente debuginfod comprueba si es necesario limpiar la caché. Si es momento de limpiar, la biblioteca recorre el directorio de caché y elimina las descargasartefactos relacionados con debuginfo y directorios recién vaciados, si no se han accedido recientemente.

Los archivos de control se encuentran directamente bajo el directorio de caché. Contienen números decimales simples para establecer parámetros de configuración relacionados con la caché. Si los archivos no existen, la biblioteca de cliente crea los archivos con los valores de parámetros predeterminados como contenido.

Después de cada consulta, la biblioteca de cliente de debuginfod deposita los archivos recién recibidos en un directorio y archivo cuyo nombre se basa en el build-id. Una consulta fallida también se almacena en caché mediante un archivo especial. La convención de nomenclatura utilizada para estos artefactos es deliberadamente no documentada.

$XDG_CACHE_HOME/debuginfod_client/
Directorio de caché predeterminado, si $XDG_CACHE_HOME está establecido.
$HOME/.cache/debuginfod_client/
Directorio de caché predeterminado, si $XDG_CACHE_HOME no está establecido.
$HOME/.debuginfod_client_cache/
Directorio de caché obsoleto, utilizado solo si ya existe.
cache_clean_interval_s
Este archivo de control indica el intervalo entre rondas de limpieza de la caché, en segundos. El valor predeterminado es 86400, un día. 0 significa "inmediatamente".
max_unused_age_s
Este archivo de control establece cuánto tiempo se conservan los archivos relacionados con debuginfo no accedidos, en segundos. El valor predeterminado es 604800, una semana. 0 significa "inmediatamente".
cache_miss_s
Este archivo de control establece cuánto tiempo recordar un fallo de consulta, en segundos. Las nuevas consultas para los mismos artefactos dentro de esta ventana de tiempo se cortocircuitan (devolviendo un fallo inmediato en lugar de enviar una nueva consulta a los servidores). Esto acelera las consultas que probablemente seguirían fallando. El valor predeterminado es 600, 10 minutos. 0 significa "olvidar inmediatamente".
metadata_retention_s
Este archivo de control establece cuánto tiempo recordar los resultados de una consulta de metadatos. Las nuevas consultas para los mismos artefactos dentro de esta ventana de tiempo se cortocircuitan (repitiendo los mismos resultados). Esto acelera las consultas que probablemente tendrían los mismos resultados. El valor predeterminado es 3600, 1 hora. 0 significa "no conservar".
