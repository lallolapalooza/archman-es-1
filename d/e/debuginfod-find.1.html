debuginfoden busca de datos relacionados con debuginfo. En caso de coincidencia, guarda el archivo solicitado en una caché local, imprime el nombre del archivo en la salida estándar y termina con un estado de éxito de 0. En caso de cualquier error, termina con un estado de fallo y un mensaje de error en la salida de error estándar. El sistema debuginfod utiliza buildids para identificar datos relacionados con debuginfo. Estos se almacenan como notas binarias en archivos ELF/DWARF y se representan en hexadecimal en minúsculas. Los nombres de ruta relativos aparecen comúnmente en el directorio de fuentes del archivo DWARF, pero estas rutas son relativas a las rutas AT_comp_dir de cada unidad de compilación, y sin embargo un ejecutable está compuesto por múltiples UCs. Por lo tanto, para desambiguar, debuginfod espera que las consultas de fuente prefijen los nombres de ruta relativos con el directorio de compilación de la UC, seguido de un "/" obligatorio. VARIABLES DE ENTORNO



  
$TMPDIR

  
Esta variable de entorno apunta a un sistema de archivos que se utilizará para archivos
      temporales. El valor predeterminado es /tmp.
      

  
$DEBUGINFOD_URLS

  
Esta variable de entorno contiene una lista de prefijos de URL para instancias
      debuginfod de confianza. Los prefijos de URL alternativos están separados por espacios. Esta
      variable de entorno puede ser establecida por scripts de /etc/profile.d que leen
      archivos /etc/debuginfod/*.urls.
    
Esta variable de entorno también puede contener etiquetas que definen
        políticas, las cuales dictan la política de respuesta para verificar firmas IMA
        por archivo en RPMs. Dado que la lista separada por espacios se lee de izquierda a derecha,
        al encontrar una etiqueta, las URL subsiguientes hasta la siguiente etiqueta serán
        manejadas usando esa política especificada. Todas las URL antes de la primera etiqueta usarán
        la política predeterminada, ima:ignore. Por ejemplo:

    

      

    

    
DEBUGINFOD_URLS="https://foo.com ima:enforcing https://bar.ca http://localhost:8002/ ima:ignore https://baz.org"


    

    
Donde foo.com y baz.org usan la política ignore predeterminada
        y bar.ca y localhost usan una política enforcing . La etiqueta de política
        puede ser una de las siguientes:

  





  

  
ima:enforcing Cada archivo descargado requiere una firma válida,
      protegiendo completamente la integridad.

  

  
ima:ignore Omite la verificación por completo, sin proporcionar
    ninguna protección.

  

  

    
Las alertas de fallo de validación serán dirigidas como se especifica en
        $DEBUGINFOD_VERBOSE.

      





  
$DEBUGINFOD_CACHE_PATH

  
Esta variable de entorno gobierna la ubicación de la caché donde
      se guardan los archivos descargados y los archivos de control de caché. El directorio
      predeterminado se elige basándose en otras variables de entorno, ver abajo.
      

  
$DEBUGINFOD_PROGRESS

  
Esta variable de entorno gobierna la función de progreso predeterminada. Si está establecida,
      y si no se establece explícitamente una progressfn, la biblioteca configurará
      una progressfn predeterminada. Esta función añadirá un mensaje de progreso simple
      periódicamente a stderr. El valor predeterminado es sin salida de la función de progreso.
      

  
$DEBUGINFOD_VERBOSE

  
Esta variable de entorno gobierna el descriptor de archivo predeterminado para la salida
      detallada. Si está establecida, y si no se establece explícitamente un fd detallado, la
      salida detallada se producirá en STDERR_FILENO.
      

  
$DEBUGINFOD_RETRY_LIMIT

  
Esta variable de entorno gobierna el límite predeterminado de intentos de reintento. Si
      una consulta falla con un errno distinto de ENOENT, se iniciarán varios
      intentos dentro del límite.
      

  
$DEBUGINFOD_TIMEOUT

  
Esta variable de entorno gobierna el tiempo de espera de inicio de descarga
      para cada conexión HTTP de debuginfod. Un servidor que no proporcione al menos
      100K de datos dentro de este número de segundos será omitido. El valor predeterminado es 90
      segundos. (Cero o negativo significa "sin tiempo de espera".)
      

  
$DEBUGINFOD_MAXTIME

  
Esta variable de entorno dicta cuánto tiempo esperará el cliente para
      completar la descarga de un archivo encontrado en un servidor, en segundos. Es
      mejor usarla para asegurar que un archivo se descargue rápidamente o sea rechazado. El
      valor predeterminado es 0 (tiempo infinito).
      

  
$DEBUGINFOD_MAXSIZE

  
Esta variable de entorno dicta el tamaño máximo de un archivo a descargar
      en bytes. Es mejor usarla si el usuario desea asegurar que solo se descarguen archivos
      pequeños. Un valor de 0 causa que no se considere el tamaño, y el
      cliente puede intentar descargar un archivo de cualquier tamaño. El valor predeterminado es 0
      (tamaño infinito).
      

  
$DEBUGINFOD_HEADERS_FILE

  
Esta variable de entorno apunta a un archivo que proporciona cabeceras a
      solicitudes HTTP salientes, una por línea. Las líneas de cabecera no deberían terminar con
      CRLF, a menos que esa sea la convención de salto de línea del sistema. Las líneas
      que solo contienen espacios en blanco se omiten.
      

  
$DEBUGINFOD_IMA_CERT_PATH

  
Esta variable de entorno contiene una lista de rutas de directorio absolutas
      que contienen certificados X.509 para la verificación IMA por archivo de RPM. Las rutas
      alternativas están separadas por dos puntos.
      








CACHÉ


Antes de cada consulta, la biblioteca cliente debuginfod comprueba si es necesario
    limpiar la caché. Si es momento de limpiar, la biblioteca recorre el directorio de
    caché y elimina artefactos relacionados con debuginfo descargados y directorios que se hayan
    quedado vacíos, si no han sido accedidos recientemente.


Los archivos de control se encuentran directamente bajo el directorio de caché. Contienen
    números decimales simples para establecer parámetros de configuración relacionados con la
    caché. Si los archivos no existen, la biblioteca cliente crea los archivos
    con los valores de parámetros predeterminados como contenido.


Después de cada consulta, la biblioteca cliente debuginfod deposita los archivos
    recién recibidos en un directorio y archivo cuyo nombre se basa en el
    build-id. Una consulta fallida también se almacena en caché mediante un archivo especial. La
    convención de nombrado utilizada para estos artefactos es deliberadamente no documentada.



  
$XDG_CACHE_HOME/debuginfod_client/

  
Directorio de caché predeterminado, si $XDG_CACHE_HOME está establecida.
      

  
$HOME/.cache/debuginfod_client/

  
Directorio de caché predeterminado, si $XDG_CACHE_HOME no está establecida.
      

  
$HOME/.debuginfod_client_cache/

  
Directorio de caché obsoleto, utilizado solo si ya existe.
      

  
cache_clean_interval_s

  
Este archivo de control indica el intervalo entre rondas de limpieza de la caché, en
      segundos. El valor predeterminado es 86400, un día. 0 significa "inmediatamente".
      

  
max_unused_age_s

  
Este archivo de control establece cuánto tiempo se retienen los archivos relacionados con
      debuginfo que no han sido accedidos, en segundos. El valor predeterminado es 604800, una
      semana. 0 significa "inmediatamente".
      

  
cache_miss_s

  
Este archivo de control establece cuánto tiempo recordar un fallo de consulta, en
      segundos. Nuevas consultas para los mismos artefactos dentro de esta ventana de tiempo se
      acortan (devolviendo un fallo inmediato en lugar de enviar una nueva
      consulta a los servidores). Esto acelera las consultas que probablemente seguirían
      fallando. El valor predeterminado es 600, 10 minutos. 0 significa "olvidar
      inmediatamente".
      

  
metadata_retention_s

  
Este archivo de control establece cuánto tiempo recordar los resultados de una consulta de
      metadatos. Nuevas consultas para los mismos artefactos dentro de esta ventana de tiempo se
      acortan (repitiendo los mismos resultados). Esto acelera las consultas
      que probablemente tendrían los mismos resultados. El valor predeterminado es 3600, 1
      hora. 0 significa "no retener".
