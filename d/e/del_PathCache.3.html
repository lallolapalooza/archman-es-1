DESCRIPCIÓN

El objeto PathCache forma parte de la biblioteca tecla (ver la página del manual libtecla(3)).

Los objetos PathCache permiten a una aplicación buscar archivos en cualquier lista de directorios separada por dos puntos, como la variable de entorno de ejecución PATH de Unix. Los archivos en directorios absolutos se almacenan en caché en un objeto PathCache, mientras que los directorios relativos se escanean según sea necesario. Usando un objeto PathCache, puede buscar la ruta completa de un nombre de archivo simple, o puede obtener una lista de las posibles completaciones de un prefijo de nombre de archivo dado. Por defecto, todos los archivos en la lista de directorios son objetivos de búsqueda y completación, pero se proporciona un mecanismo versátil para seleccionar solo tipos específicos de archivos. La aplicación obvia de esta facilidad es proporcionar completación con Tab y búsqueda de comandos ejecutables en el PATH de Unix, por lo que se proporciona una opción de devolución de llamada que rechaza todo excepto los archivos ejecutables.

UN EJEMPLO

En UNIX, el siguiente programa de ejemplo busca y muestra las rutas completas de cada uno de los nombres de comando en la línea de comandos.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Crea una caché para archivos ejecutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Escanea el PATH del usuario en busca de ejecutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * Organiza para reportar solo archivos ejecutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Busca y muestra la ruta completa de cada uno de los
   * comandos listados en la línea de comandos.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("La ruta completa de '%s' es %s\n", argv[i],
             cmd ? cmd : "desconocido");
    }
    pc = del_PathCache(pc);  /* Limpiar */
    return 0;
  }

El siguiente es un ejemplo de lo que hace esto en mi portátil bajo Linux:

  $ ./example less more blob
  La ruta completa de 'less' es /usr/bin/less
  La ruta completa de 'more' es /bin/more
  La ruta completa de 'blob' es desconocido
  $

DESCRIPCIONES DE FUNCIONES

Para usar las facilidades de este módulo, primero debe asignar un objeto PathCache llamando a la función constructora new_PathCache().

  PathCache *new_PathCache(void)

Esta función crea los recursos necesarios para almacenar en caché y buscar archivos en una lista de directorios. Devuelve NULL en caso de error.

POBLANDO LA CACHÉ

Una vez que haya creado una caché, debe poblarla con archivos. Para hacer esto, llame a la función pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Cada vez que se llama a esta función, descarta el contenido actual de la caché y luego escanea la lista de directorios especificados en su argumento path en busca de archivos. El argumento path debe ser una cadena que contenga una lista de directorios separados por dos puntos, como "/usr/bin:/home/mcs/bin:.". Esto puede incluir directorios especificados por rutas absolutas como "/usr/bin", así como subdirectorios especificados por rutas relativas como "." o "bin". Los archivos en los directorios absolutos se almacenan en caché inmediatamente en el objeto PathCache especificado, mientras que los subdirectorios, cuyas identidades obviamente cambian cada vez que cambia el directorio de trabajo actual, se marcan para ser escaneados sobre la marcha cada vez que se busca un archivo.

En caso de éxito, esta función devuelve 0. En caso de error, devuelve 1, y se puede obtener una descripción del error llamando a pca_last_error(pc).

BUSCANDO ARCHIVOS

Una vez que la caché se ha poblado con archivos, puede buscar la ruta completa de un archivo, simplemente especificando su nombre de archivo a pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Para hacer posible pasarle a esta función un nombre de archivo que en realidad es parte de una cadena más larga, el argumento name_len puede usarse para especificar la longitud del nombre de archivo al inicio del argumento name[]. Si pasa -1 para esta longitud, la longitud de la cadena se determinará con strlen(). Si la cadena name[] puede contener barras invertidas que escapan los significados especiales de espacios y tabulaciones dentro del nombre del archivo, dé al argumento literal el valor 0. De lo contrario, si las barras invertidas deben tratarse como caracteres normales, pase 1 como valor del argumento literal.

COMPLETADO DE NOMBRES DE ARCHIVO

La búsqueda de las posibles completaciones de un prefijo de nombre de archivo en la caché de nombres de archivo se logra pasando la función de devolución de llamada proporcionada pca_path_completions() a la función cpl_complete_word() (ver la página del manual cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Esta devolución de llamada requiere que su argumento data sea un puntero a un objeto PcaPathConf. Los objetos de configuración de este tipo se asignan llamando a new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Esta función devuelve un objeto inicializado con parámetros de configuración predeterminados, que determinan cómo se comporta la función de devolución de llamada cpl_path_completions(). Las funciones que permiten cambiar individualmente estos parámetros se discuten a continuación.

Por defecto, la función de devolución de llamada pca_path_completions() busca hacia atrás el inicio del nombre de archivo que se está completando, buscando el primer espacio no escapado o el inicio de la línea de entrada. Si desea especificar una ubicación diferente, llame a ppc_file_start() con el índice en el que comienza el nombre del archivo en la línea de entrada. Pasar start_index=-1 vuelve a habilitar el comportamiento predeterminado.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Por defecto, cuando pca_path_completions() examina un nombre de archivo en la línea de entrada, cada barra invertida solitaria en la línea de entrada se interpreta como un carácter especial que elimina cualquier significado especial del carácter que le sigue, como un espacio que debe ser tomado como parte del nombre del archivo en lugar de delimitar el inicio del nombre del archivo. Estas barras invertidas se ignoran al buscar completaciones y, posteriormente, se agregan antes de los espacios, las tabulaciones y las barras invertidas literales en la lista de completaciones. Para que las barras invertidas no escapadas se traten como caracteres normales, llame a ppc_literal_escapes() con un valor distinto de cero en su argumento literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Cuando haya terminado con una variable PcaPathConf, puede pasarla a la función destructora del_PcaPathConf() para recuperar su memoria.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

SIENDO SELECTIVO

Si solo está interesado en ciertos tipos o archivos, como, por ejemplo, archivos ejecutables, o archivos cuyos nombres terminan en un sufijo particular, puede organizar las funciones de completado y búsqueda de archivos para que sean selectivas en los nombres de archivo que devuelven. Esto se hace registrando una función de devolución de llamada con su objeto PathCache.
