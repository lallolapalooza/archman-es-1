debuginfod-client-config - variables

de entorno del cliente debuginfod,
archivos de control de caché, etc.

SINOPSI

S

Varias variables de entorno y archivos de

control determinan el comportamiento
de las aplicaciones cliente de debuginfod.

VARIABLES DE

ENTORNO
$TMPD
IR
Esta variable de entorno apunta a un sistema de archivos para usar con archivos temporales. El valor predeterminado es
/tmp.
$DEBUGINFOD_U
RLS
Esta variable de entorno contiene una lista de prefijos URL para instancias de debuginfod de confianza. Los prefijos URL alternativos se separan por espacios. Esta variable de entorno puede ser establecida por scripts de /etc/profile.d que leen los archivos /etc/debuginfod/*.urls.

Esta variable de entorno también puede contener etiquetas que definen la política que dictan la política de respuesta para verificar firmas IMA por archivo en RPM. Dado que la lista separada por espacios se lee de izquierda a derecha, al encontrar una etiqueta, las URL siguientes hasta la siguiente etiqueta se manejarán utilizando esa política especificada. Todas las URL antes de la primera etiqueta usarán la política predeterminada, ima:ignore. Por

ejemplo: 


DEBUGINFOD_URLS="https://foo.com ima:enforcing https://bar.ca http://localhost:8002/ ima:ignore https://baz.
org"

Donde foo.com y baz.org usan la política predeterminada de ignorar y bar.ca y localhost usan una política de hacer cumplir. La etique

ta de política
puede ser una
de las siguientes:
ima:enforcing Cada archivo descargado requiere una firma válida, protegiendo completamente la
integridad.
ima:ignore Omite la verificación por completo, sin proporcionar
protección.

Las alertas de fallo de validación se dirigirán como se especifica en

$DEBUGINFOD_VERBOS
E

ATH
Esta variable de entorno gobierna la ubicación de la caché donde se guardan los archivos descargados y los archivos de control de caché. El directorio predeterminado se elige en función de otras variables de entorno, ver más
abajo.
$DEBUGINFOD_PROGR
ESS
Esta variable de entorno gobierna la función de progreso predeterminada. Si se establece, y si no se establece explícitamente un progressfn, la biblioteca configurará un progressfn predeterminado. Esta función añadirá periódicamente un mensaje de progreso simple a stderr. El valor predeterminado es sin salida de función de
progreso.
$DEBUGINFOD_VERB
OSE
Esta variable de entorno gobierna el descriptor de archivo predeterminado para la salida detallada. Si se establece, y si no se establece explícitamente un fd detallado, la salida detallada se producirá en
STDERR_FILENO.
$DEBUGINFOD_RETRY_LI
MIT
Esta variable de entorno gobierna el límite predeterminado de intentos de reintento. Si una consulta falló con un errno distinto de ENOENT, se iniciarán varios intentos dentro del
límite.
$DEBUGINFOD_TIME
OUT
Esta variable de entorno gobierna el tiempo de espera de inicio de descarga predeterminado para cada conexión HTTP de debuginfod. Un servidor que no proporcione al menos 100K de datos dentro de este número de segundos se omite. El valor predeterminado es 90 segundos. (Cero o negativo significa "sin tiempo de espera".
)
$DEBUGINFOD_MAXT
IME
Esta variable de entorno dicta cuánto tiempo esperará el cliente para completar la descarga de un archivo encontrado en un servidor, en segundos. Es mejor usarla para asegurar que un archivo se descargue rápidamente o sea rechazado. El valor predeterminado es 0 (tiempo infinito)
.
$DEBUGINFOD_MAXS
IZE
Esta variable de entorno dicta el tamaño máximo de un archivo a descargar en bytes. Es mejor usarla si el usuario desea asegurar que solo se descarguen archivos pequeños. Un valor de 0 hace que no se considere el tamaño, y el cliente puede intentar descargar un archivo de cualquier tamaño. El valor predeterminado es 0 (tamaño infinito)
.
$DEBUGINFOD_HEADERS_F
ILE
Esta variable de entorno apunta a un archivo que proporciona encabezados a solicitudes HTTP salientes, uno por línea. Las líneas de encabezado no deberían terminar con CRLF, a menos que esa sea la convención de salto de línea del sistema. Las líneas que solo contienen espacios en blanco se
omiten.

CACH

É

Antes de cada consulta, la biblioteca cliente de debuginfod comprueba la necesidad de limpiar la caché. Si es momento de limpiar, la biblioteca recorre el directorio de caché y elimina artefactos relacionados con debuginfo descargados y directorios recién vacíos, si no se han accedido

recientemente.

Los archivos de control se encuentran directamente bajo el directorio de caché. Contienen números decimales simples para establecer parámetros de configuración relacionados con la caché. Si los archivos no existen, la biblioteca cliente crea los archivos con los valores de parámetros predeterminados como

contenido.

Después de cada consulta, la biblioteca cliente de debuginfod deposita los archivos recién recibidos en un directorio y archivo que se nombran en función del build-id. Una consulta fallida también se almacena en caché mediante un archivo especial. La convención de nomenclatura utilizada para estos artefactos es deliberadamente indocumentada

.
$XDG_CACHE_HOME/debuginfod_clie
nt/
Directorio de caché predeterminado, si $XDG_CACHE_HOME está
establecido.
$HOME/.cache/debuginfod_clie
nt/
Directorio de caché predeterminado, si $XDG_CACHE_HOME no está
establecido.
$HOME/.debuginfod_client_cac
he/
Directorio de caché obsoleto, usado solo si ya
existe.
cache_clean_interva
l_s
Este archivo de control da el intervalo entre rondas de limpieza de caché, en segundos. El valor predeterminado es 86400, un día. 0 significa
"inmediatamente".
max_unused_ag
e_s
Este archivo de control establece cuánto tiempo se retienen los archivos relacionados con debuginfo no accedidos, en segundos. El valor predeterminado es 604800, una semana. 0 significa
"inmediatamente".
cache_miss
_s
Este archivo de control establece cuánto tiempo recordar un fallo de consulta, en segundos. Las nuevas consultas para los mismos artefactos dentro de esta ventana de tiempo se evitan (devolviendo un fallo inmediato en lugar de enviar una nueva consulta a los servidores). Esto acelera las consultas que probablemente seguirían fallando. El valor predeterminado es 600, 10 minutos. 0 significa "olvidar
inmediatamente".
metadata_retentio
n_s
Este archivo de control establece cuánto tiempo recordar los resultados de una
consulta de metadatos. Las nuevas consultas para los mismos artefactos de
ntro de esta ventana de tiempo se evitan (repitiendo los mismos resultados
). Esto acelera las consultas que probablemente tendrían los mismos resul
tados. El valor predeterminado es 3600, 1 hora. 0 significa "no retener".
