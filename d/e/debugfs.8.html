DESCRIPCIÓ

N

El programa debugfs es un depurador interactivo de sistemas de archivos. Se puede utilizar para examinar y cambiar el estado de un sistema de archivos ext2, ext3 o

ext4.

device es un dispositivo de bloque (p. ej., /dev/sdXX)

o un archivo que conti
ene el sistema de archivos.

OPCIONE

S
-
w
Especifica que el sistema de archivos debe abrirse en modo de lectura y escritura. Sin esta opción, el sistema de archivos se abre en modo de solo
lectura.
-
n
Desactiva la verificación de sumas de comprobación de metadatos. Esto solo debe usarse si cree que los metadatos son correctos a pesar de las quejas de
e2fsprogs.
-
c
Especifica que el sistema de archivos debe abrirse en modo catastrófico, en el que los mapas de bits de inodos y de grupos no se leen inicialmente. Esto puede ser útil para sistemas de archivos con una corrupción significativa, pero debido a esto, el modo catastrófico fuerza la apertura del sistema de archivos en solo
lectura.
-
i
Especifica que device representa un archivo de imagen ext2 creado por el programa e2image. Dado que el archivo de imagen ext2 solo contiene el superbloque, el descriptor de grupo de bloques, los mapas de bits de asignación de bloques y de inodos, y la tabla de inodos, muchas comandos de debugfs no funcionarán correctamente. Advertencia: no hay comprobaciones de seguridad, y debugfs puede fallar de maneras interesantes si se intentan comandos como ls, dump, etc., sin especificar el data_source_device usando la opción -d. debugfs es una herramienta de depuración. ¡Tiene bordes
ásperos!
-d data_source_dev
ice
Se usa con la opción -i, especifica que data_source_device debe usarse al leer bloques que no se encuentran en el archivo de imagen ext2. Esto incluye bloques de datos, de directorio e
indirectos.
-b
blocksize
Fuerza el uso del tamaño de bloque dado (en bytes) para el sistema de archivos, en lugar de detectar el tamaño de bloque correcto automáticamente. (Esta opción rara vez es necesaria; se usa principalmente cuando el sistema de archivos está extremadamente dañado/corrupto.
)
-s
superblock
Hace que el superbloque del sistema de archivos se lea del número de bloque dado, en lugar de usar el superbloque primario (ubicado en un desplazamiento de 1024 bytes desde el comienzo del sistema de archivos). Si especifica la opción -s, también debe proporcionar el blocksize del sistema de archivos a través de la opción -b. (Esta opción rara vez es necesaria; se usa principalmente cuando el sistema de archivos está extremadamente dañado/corrupto.
)
-f
cmd_file
Hace que debugfs lea comandos de cmd_file y los ejecute. Cuando debugfs termine de ejecutar esos comandos,
saldrá.
-
D
Hace que debugfs abra el dispositivo usando E/S Directa (Direct I/O), evitando la caché de búfer. Tenga en cuenta que algunos dispositivos Linux, notablemente el mapeador de dispositivos (device mapper) en el momento de escribir esto, no admiten E/S
Directa.
-R
request
Hace que debugfs ejecute el único comando request y luego
salga.
-
V
imprime el número de versión de debugfs y
sale.
-z undo_fi
le
Antes de sobrescribir un bloque del sistema de archivos, escribe los contenidos antiguos del bloque en un archivo de deshacer (undo file). Este archivo de deshacer se puede usar con e2undo(8) para restaurar los contenidos antiguos del sistema de archivos si algo sale mal. Si se pasa la cadena vacía como argumento undo_file, el archivo de deshacer se escribirá en un archivo llamado debugfs-device.e2undo en el directorio especificado a través de la variable de entorno E2FSPROGS_UNDO_DIR.

ESPECIFICANDO

ARCHIVOS

Muchos comandos de debugfs toman un filespec como argumento para especificar un inodo (a diferencia de una ruta de acceso) en el sistema de archivos que está actualmente abierto por debugfs. El argumento filespec puede especificarse en dos formas. La primera forma es un número de inodo rodeado por corchetes angulares, p. ej., <2>. La segunda forma es una ruta de acceso; si la ruta de acceso tiene un prefijo de barra diagonal ('/'), se interpreta relativa a la raíz del sistema de archivos que está actualmente abierto por debugfs. Si no, la ruta de acceso se interpreta relativa al directorio de trabajo actual mantenido por debugfs. Esto puede modificarse usando el comando de debugfs cd

.

VARIABLES DE

ENTORNO
DEBUGFS_PAGER,
PAGER
El programa debugfs siempre canaliza la salida de algunos comandos a través de un programa paginador. Estos comandos incluyen: show_super_stats (stats), list_directory (ls), show_inode_info (stat), list_deleted_inodes (lsdel), y htree_dump. El paginador específico puede ser especificado explícitamente por la variable de entorno DEBUGFS_PAGER, y si no está definida, por la variable de entorno PAGER
Tenga en cuenta que como siempre se utiliza un paginador, el paginador less(1) no es particularmente apropiado, ya que borra la pantalla antes de mostrar la salida del comando y borra la pantalla al salir del paginador. Muchos usuarios prefieren usar el paginador less(1) para la mayoría de los propósitos, razón por la cual la variable de entorno DEBUGFS_PAGER está disponible para anular la variable de entorno más general PAGER.
