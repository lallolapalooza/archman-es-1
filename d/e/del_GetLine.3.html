DESCRIPCIÓN

La función gl_get_line() es parte de la biblioteca tecla (ver la página del manual libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de línea de comandos, admite la recuperación de líneas de comandos ingresadas previamente, la compleción TAB de nombres de archivos y la expansión de comodines en línea de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página del manual tecla(7). Esta página del manual se centra en la documentación para programadores interesados en utilizar esta biblioteca en sus aplicaciones.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para registrar líneas ingresadas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Luego, finalmente los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esto es una medida de seguridad. Si el programa posteriormente intenta pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar usar el objeto de recurso eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita a continuación. Si no desea historial, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() se puede llamar cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifique el prompt que se presentará al usuario. Por defecto, los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los prompts pueden contener directivas para subrayar, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea se posiciona inicialmente el cursor.

EL ARGUMENTO START_POS

Si desea que el cursor siga al último carácter de la línea de inicio, establezca este valor en -1. Si no desea precargar la línea de esta manera, envíe start_line como NULL y establezca start_pos en -1. Tenga en cuenta que el puntero de línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente de nuevo al usuario para su reedición, con el cursor posicionado inicialmente donde se encontró el error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto forma parte del objeto de recurso gl especificado y, por lo tanto, el llamador no debe liberarlo ni asumir que es inmutable entre llamadas. Al leer de un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o un archivo, de manera similar habrá una nueva línea, a menos que la línea de entrada sea demasiado larga para almacenarla en el búfer interno. En este último caso, debería llamar a gl_get_line() nuevamente para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal, gl_get_line() simplemente llama a fgets().

  const char *gl_error_message(GetLine *gl, char *buff,
                               size_t n);

El valor de retorno es un puntero al mensaje que ocurrió. Si el argumento buff es NULL, será un puntero a un búfer dentro de gl, cuyo valor probablemente cambiará en la próxima llamada a cualquier función asociada con gl_get_line(). Si el mensaje no cabe en el búfer proporcionado, se truncará para que quepa.

FUENTES DE CONFIGURACION ALTERNATIVAS

Como se mencionó anteriormente, por defecto los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios personales. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. Sin embargo, en algunas aplicaciones, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos para leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para cubrir tales casos, la siguiente función permite a la aplicación controlar dónde se leen las informaciones de configuración.

  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file);

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de cualquiera o ninguna de estas fuentes: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL, entonces se interpreta como la ruta completa de un archivo de configuración específico de la aplicación. Si user_file != NULL, entonces se interpreta como la ruta completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente llamada:

  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc");

el argumento app_string hace que la aplicación que llama comience en modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración del sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo opcional .teclarc en el directorio personal del usuario. Tenga en cuenta que los argumentos se enumeran en orden ascendente de prioridad, y el contenido de app_string puede ser anulado por comandos en app_file, y los comandos en app_file pueden ser anulados por comandos en user_file.

Puede llamar a esta función tantas veces como sea necesario, y los resultados serán acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través del argumento app_fil

e y los argumentos user_file se registran internamente para su uso posterior por la función read-init-files de enlace de teclas, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea releer cuando el usuario solicite que se relean los archivos de

configuración.

PERSONALIZADO

Si en su aplicación desea que la finalización con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizarlo registrando una función de devolución de llamada de finalización alternativa, a través de una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de devolución de llamada. Esto se pasa a la devolución de llamada cada vez que se invoca. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles finalizaciones. El argumento match_fn especifica la función de devolución de llamada a invocar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de devolución de llamada. La declaración y las responsabilidades de las funciones de devolución de llamada se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de devolución de llamada es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar las posibles finalizaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de devolución de llamada desea proporcionar la finalización de nombres de archivo además de sus propias finalizaciones específicas, tiene la opción de llamar por sí misma a la función de devolución de llamada de finalización de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una finalización exitosa, puede organizarlo cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la finalización, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de devolución de llamada necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará ser

redibujada cuando la devo
lución de llamada regrese.

FINALIZACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de finalización predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que se puedan vincular diferentes tipos de finalización de palabras a diferentes secuencias de teclas. Esto se logra utilizando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen como en la página del manual de cpl_complete_word, y especifican la función de devolución de llamada que debe invocarse para identificar las posibles finalizaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier finalización ambigua posible, o si simplemente debe mostrar la lista de posibles finalizaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de finalización existente que se va a cambiar, o un nombre nuevo no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que vincular la acción. Si esto es NULL, no se vinculará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas vinculada a las acciones instaladas de esta manera, cuando llame a gl_completion_action() para instalar una acción determinada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un

error.

Como se discutió para gl_customize_completion(), si su función de devolución de llamada, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() a

DEFINIENDO ACCIONES

PERSONALIZADAS

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, vinculadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondía a un número de pieza precedente al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada siempre que se introduzca la secuencia de teclas especificada, keyseq, por el usuario, o que el usuario introduzca cualquier otra secuencia de teclas que el usuario vincule posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea

invocada.

La función de acción, fn, debe declararse utilizando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de introducir utilizando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. En la práctica, sin embargo, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count o usar su valor para un propósito

diferente.

Se pasa una copia de la línea de entrada actual en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena está dada por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi versus el modo emacs, el modo sin eco, y el modo de inserción versus el modo de sobrescritura, etc., lo hacen demasiado complejo para que un desarrollador de aplicaciones escriba una acción de edición conforme, así como restringen cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea utilizando las acciones de edición existentes. Esto está actualmente bajo

consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de líneas llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado adecuado para su uso con las instalaciones stdio de C. Lo último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la función de acción puede leer de y escribir en la terminal sin temor a crear un desorden. No es necesario que la función de acción restaure el entorno de edición original antes de regresar. Esto se hace automáticamente por gl_get_line() después de que la función de acción regrese. El siguiente es un ejemplo sencillo de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de líneas se

reanuda. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspender temporalmente la edición */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

Las funciones de acción deben devolver uno de los siguientes valores, para informar a gl_get_line() cómo

proceder. 
  GLA_ABORT     -   Provoca que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Provoca que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanudar la edición de la línea de
comandos.

Nótese que el argumento name de gl_register_action() especifica el nombre con el que un usuario puede referirse a la acción en su archivo de configuración. Esto les permite reasociar la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_

lin
e().

Por defecto, siempre que el usuario introduce una línea, esta se añade automáticamente a la lista de historial, justo antes de gl_get_line() devuelve la línea al llamante. ;

Si esta función se llama con su argumento enable establecido en 0, gl_get_line() no archivará automáticamente las líneas introducidas posteriormente. El archivado automático puede reactivarse más tarde, llamando a esta función de nuevo, con su argumento enable establecido en 1. necesario. 
  int gl_append_history(GetLine *gl, const char *line)
;

El argumento line especifica la línea que se añadirá a la lista de historial. Esta debe ser una cadena normal terminada en '\0'. Si esta cadena contiene algún carácter de salto de línea, la línea que se archiva en la lista de historial terminará en el primero de ellos. De lo contrario, terminará en el terminador '\0'. Si la línea es más larga que la longitud máxima de línea de entrada, que fue especificada cuando se llamó a new_GetLine(), cuando se recuerde la línea, será truncada a la longitud real de la línea de gl_get_li

ne().

valores. 
   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el tamaño
              asignado del búfer de historial (como se especificó cuando se
              llamó a new_GetLine()), por lo que no pudo ser
archivada.

Se puede obtener opcionalmente una descripción textual del error llamando a gl_error_message(). Nótese que después de tal error, la lista de historial permanece en un estado válido para recibir nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el estado de retorno de gl_append_

El uso de la función de historial, es decir, la capacidad de almacenar y recuperar líneas previamente escritas, se controla mediante las siguientes funciones.

La función gl_limit_history() establece un límite superior en el número de líneas que se pueden almacenar en el búfer de historial.

El argumento all_groups indica a la función si debe eliminar solo las líneas asociadas con el grupo de historial actual (ver gl_group_history()) o todas las líneas históricas del búfer.

CAMBIO DE TERMINALES

La función constructora new_GetLine() asume que la entrada se leerá de stdin y la salida se escribirá en stdout. La siguiente función permite cambiar a diferentes flujos de entrada y salida.

  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);

El argumento gl es el objeto devuelto por new_GetLine(). El argumento input_fp especifica el flujo del que se leerá, y output_fp especifica el flujo que se escribirá. Solo si ambos se refieren a una terminal, se habilitará la entrada interactiva de terminal. De lo contrario, gl_get_line() simplemente llamará a fgets() para leer la entrada de comandos. Si ambos flujos se refieren a una terminal, deben referirse a la misma terminal, y el tipo de esta terminal debe especificarse a través del argumento term. El valor del argumento term se busca en la base de datos de información de terminales (terminfo o termcap), para determinar qué secuencias de control especiales se necesitan para controlar varios aspectos de la terminal. Por ejemplo, new_GetLine() pasa el valor de retorno de getenv("TERM") en este argumento. Tenga en cuenta que si uno o ambos de input_fp y output_fp no se refieren a una terminal, entonces es legal pasar NULL en lugar de un tipo de terminal.

Tenga en cuenta que si desea pasar descriptores de archivo a gl_change_terminal(), puede hacerlo creando envoltorios de flujos stdio utilizando la función POSIX fdopen().

GESTIÓN DE EVENTOS EXTERNOS

Por defecto, gl_get_line() no regresa hasta que el usuario haya ingresado una línea de entrada completa o ocurra un error. En programas que necesitan monitorear E/S de otras fuentes que no sean la terminal, existen dos opciones.

  1. Utilice las funciones descritas en la página del manual
     gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este
     modo, gl_get_line() se convierte en una función de edición
     de línea incremental y no bloqueante que se puede llamar de
     forma segura desde un bucle de eventos externo. Aunque este es
     un método muy versátil, implica asumir algunas
     responsabilidades que normalmente realiza
     gl_get_line() tras bambalinas.
  2. Mientras gl_get_line() está esperando entrada del teclado
     del usuario, puede pedirle que también vigile la actividad en
     descriptores de archivo arbitrarios, como sockets de red, tuberías,
     etc., y hacer que llame a funciones de su elección cuando se detecte
     actividad. Esto funciona en cualquier sistema que tenga la llamada
     al sistema select(), que es la mayoría, si no todos, los
     sabores de Unix.

Registrar un descriptor de archivo para ser monitoreado por gl_get_line() implica llamar a la función gl_watch_fd().

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);

Si esto devuelve un valor distinto de cero, significa que sus argumentos no son válidos o que esta funcionalidad no es compatible en el sistema anfitrión.

El argumento fd es el descriptor de archivo a monitorear. El argumento event especifica qué tipo de actividad interesa, elegido de los siguientes valores enumerados:

  GLFD_READ   -  Vigilar la llegada de datos para ser leídos.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de archivo.

El argumento callback es la función a llamar cuando se ve la actividad seleccionada. Debe definirse con la siguiente macro, que se define en libtecla.h.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)

El argumento data de la función gl_watch_fd() se pasa a la función de devolución de llamada para su propio uso, y puede apuntar a lo que desee, incluido NULL. El descriptor de archivo y el argumento de evento también se pasan a la función de devolución de llamada, y esto permite potencialmente que la misma función de devolución de llamada se registre para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de devolución de llamada debe ser uno de los siguientes valores.

  GLFD_ABORT    -  Indicar a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() devuelve
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_FDABORT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre
                   tenga un valor significativo cuando
                   gl_get_line() devuelve NULL,
                   la función de devolución de llamada debe
                   establecer errno apropiadamente.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando entrada. Devuelva esto si su
                   devolución de llamada escribió en la
                   terminal.
  GLFD_CONTINUE -  Continuar esperando entrada, sin redibujar
                   la línea.

Tenga en cuenta que antes de llamar a la devolución de llamada, gl_get_line() bloquea la mayoría de las señales y deja sus propios manejadores de señales instalados, por lo que si necesita capturar una señal particular, deberá instalar temporalmente su propio manejador de señales y desbloquear la señal. MANEJO DE SEÑALES FIABLE

El manejo de señales es sorprendentemente difícil de hacer de manera confiable sin condiciones de carrera. En gl_get_line() se ha puesto mucho cuidado para permitir que las aplicaciones realicen un manejo de señales confiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que una aplicación tiene un controlador de señales SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la declaración que prueba el valor de esta bandera y la declaración que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no será interrumpida. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto puede ser o no un desastre, pero como mínimo confundirá al usuario.

La forma de evitar tales problemas es hacer lo siguiente.

1. Si es necesario, use la función gl_trap_signal() para configurar gl_get_line() para que aborte cuando se capturen señales importantes.

2. Configure gl_get_line() de tal manera que si alguna de las señales que captura está bloqueada cuando se llama a gl_get_line(), se desbloquearán automáticamente durante los momentos en que gl_get_line() está esperando E/S. Esto se puede hacer por señal, llamando a la función gl_trap_signal() y especificando el atributo GLS_UNBLOCK de la señal, o globalmente llamando a la función gl_catch_blocked().

     void gl_catch_blocked(GetLine *gl);

Esta función simplemente agrega el atributo GLS_UNBLOCK a todas las señales que actualmente está configurada para capturar.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega de todas las señales que gl_get_line() está configurada para capturar. Esto se puede hacer usando la función POSIX sigprocmask() en conjunción con la función gl_list_signals().

      int gl_list_signals(GetLine *gl, sigset_t *set);

Esta función devuelve el conjunto de señales que actualmente está configurada para capturar en el argumento set, que está en el formato requerido por sigprocmask().

4. En el ejemplo, ahora probaría la bandera global que establece el controlador de señales, sabiendo que ahora no hay peligro de que esta bandera se establezca nuevamente hasta que gl_get_line() desbloquee sus señales al realizar E/S.

5. Finalmente, gl_get_line() regresa, ya sea porque se capturó una señal, ocurrió un error o el usuario terminó de ingresar su línea de entrada.

6. Ahora probaría la bandera global de señales nuevamente, y si está establecida, respondería a ella y pondría la bandera a cero.

7. Use sigprocmask() para desbloquear las señales que se bloquearon en el paso 3.

La misma técnica se puede utilizar alrededor de ciertas funciones conscientes de señales POSIX, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunción con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas del sistema de largo plazo. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de manera confiable alrededor de llamadas a funciones como read() y select() sin condiciones de carrera.

Lo primero que hace gl_get_line(), cada vez que se llama, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que actualmente está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no hace daño. Deshace este paso justo antes de regresar.

Siempre que gl_get_line() necesite llamar a read() o select() para esperar la entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón del último argumento será clara en breve.

Si sigsetjmp() devuelve cero, gl_get_line() hace lo siguiente.

   controlador de señales temporal para todas las señales que
   está configurada para capturar. Este controlador de señales
   hace dos cosas.
   1. Registra el número de la señal que se recibió en una
      variable a nivel de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a sigsetjmp() como

   gl_get_line() desbloquea todas las señales que está

EL TAMAÑO DEL

TERMINAL

En la mayoría de los sistemas, la combinación de el ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta nuevamente cada vez que gl_get_line() es llamada y siempre que se recibe una señal

SIGWINCH.

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() primero busca las variables de entorno LINES y COLUMNS. Si estas no se encuentran, o contienen valores inutilizables, entonces si una base de datos de información del terminal como terminfo o termcap está disponible, el tamaño por defecto del terminal se busca en esta base de datos. Si esto también falla en proporcionar el tamaño del terminal, se usa un tamaño por defecto de 80 columnas por 24

líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales instancias es proporcionar una manera para que el usuario ingrese un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de

tamaño. 
  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio de tamaño. En el modo de E/S de servidor no bloqueante, si una línea se está ingresando actualmente, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por gl_get_li

ne().

Tenga en cuenta que el tamaño del terminal no estará disponible si se lee de una tubería o un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del

OCULTANDO LO QUE

ESCRIBES

Al ingresar información sensible, como contraseñas, es mejor no tener el texto que está ingresando reflejado en el terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre su terminal desatendida podría entonces recuperarlo, o alguien husmeando en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() le permite alternar la visualización y el archivo de cualquier texto que se ingrese posteriormente en llamadas a gl_get_li

ne(). 
  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto ingresado debe ser visible o no. Si es 0, entonces las líneas ingresadas posteriormente no serán visibles en el terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores serán mostradas a medida que se ingresan, y siempre que el historial no haya sido desactivado mediante una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba desactivado antes de que la función fuera llamada, y 1 si estaba

activado.

Cuando el eco está desactivado, tenga en cuenta que aunque la finali

zación con tabulador completará invisiblemente su prefijo lo má
s lejos posible, las finalizaciones ambiguas no serán mostradas.

CONSULTAS DE UN SOLO

CARÁCTER

Usar gl_get_line() para consultar al usuario para una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla enter o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como

esta. 
  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el prompt especificado al inicio de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa llamador. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el último caso, la aplicación puede llamar a la previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría, por ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad

activándose.

Si el usuario simplemente presiona enter, el valor del argumento defchar se sustituye. Esto significa que cuando el usuario presiona ya sea newline o retorno, el carácter especificado en defchar, se muestra después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación llamadora. Si tal reemplazo no es importante, simplemente pase '0 como el valor de defchar

.

Si el carácter ingresado es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra

invertida.

Al igual que con gl_get_line(), el eco del carácter ingresado puede ser desactivado usando la función gl_echo_mode()

.

Si el proceso llamador es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del prompt, luego, cuando el proceso se reanuda, el prompt se vuelve a mostrar, y gl_query_char() reanuda la espera a que el usuario escriba un

carácter.

Tenga en cuenta que en el modo de servidor no bloqueante, (vea gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando gl_query_char() es llamada, la línea de entrada parcial es descartada, y borrada del terminal, antes de que el nuevo prompt sea mostrado. La siguiente llamada a gl_get_line() por lo tanto come

nzará a editar
una nueva línea.

LEYENDO CARACTERES

CRUDOS

Mientras que la función gl_query_char() pide visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter del usuario, sin escribir nada en el terminal, o perturbar cualquier línea de entrada incompleta. Esto significa que puede ser llamada no solo entre llamadas a gl_get_line(), sino también desde funciones de retorno de llamada que la aplicación ha registrado para ser llamadas por gl_get_li

ne(). 
  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, se devuelve EOF, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de la E/S del terminal, cuando se está en el modo de E/S de servidor no

bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() no será suficiente
