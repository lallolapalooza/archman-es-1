DESCRIPCIÓ

N 
El
obj

PathCach

e

forma parte de la biblioteca tecla (véase la página man libtecla(3)). Los obj

etos

PathCache permiten a una aplicación buscar archivos en cualquier lista de directorios separada por dos puntos, como la variable de entorno de ejecución PATH de unix. Los archivos en directorios absolutos se almacenan en caché en un objeto [[24]] PathCache , mientras que los directorios relativos se escanean según

sea necesario. Usando u
n objeto [[26]] PathCache

, puede buscar el nombre de ruta completo de un nombre de archivo simple, u obtener una lista de las posibles completaciones de un prefijo de nombre de archivo dado. Por defecto, todos los archivos en la lista de directorios son objetivos de búsqueda y completación, pero se proporciona un mecanismo versátil para seleccionar solo tipos específicos de archivos. La aplicación obvia de esta funcionalidad es proporcionar la completación con Tabulador y la búsqueda de comandos ejecutables en el PATH de unix, por lo que se proporciona una función de retorno opcional que rechaza

todos los archivos excepto los ejecutables.

EJEMPLO 
  Bajo UNIX, el siguiente programa de ejemplo busca y muestra
    los nombres de ruta completos de cada uno de los nombres de comandos en la línea de
comandos.

#include <stdio.h> #include <stdlib.h> #include <libtecla.h> int main(int argc, char *argv[]) { int i; /* * Crear una caché para archivos ejecutables. */ PathCache *pc = new_PathCache(); if(!pc) exit(1); /* * Escanear el PATH del usuario en busca de ejecutables. */ if(pca_scan_path(pc, getenv("PATH"))) { fprintf(stderr, "%s\n", pca_last_error(pc)); exit(1); } /* * Configurar para informar solo de archivos ejecutables. */ pca_set_check_fn(pc, cpl_check_exe, NULL); /* * Buscar y mostrar el nombre de ruta completo de cada uno de los * comandos listados en la línea de comandos. */ for(i=1; i<argc; i++) { char *cmd = pca_lookup_file(pc, argv[i], -1, 0); printf("El nombre de ruta completo de '%s' es %s\n", argv[i], cmd ? cmd : "desconocido"); } pc = del_PathCache(pc); /* Limpieza */

return 0; }

POBLANDO LA CACHÉ Una vez que haya creado una caché, necesita ser poblada con archivos. Para hacer esto, llame a la función [[45]]

pca_scan_path()

int pca_scan_path(PathCache *pc, const char *path); Cada vez que se llama a esta función, descarta el contenido actual de la caché, y luego escanea la lista de directorios especificada en su argumento [[49]] path en busca de archivos. El argumento [[51]] path debe ser una cadena que contenga una lista de directorios separada por dos puntos, como [[53]] "/usr/bin:/home/mcs/bin:." . Esto puede incluir directorios especificados por nombres de ruta absolutos como [[55]] "/usr/bin" , así como subdirectorios especificados por nombres de ruta relativos como [[57]] "." o [[59]] "bin" . Los archivos en los directorios absolutos se almacenan inmediatamente en caché en el objeto [[61]]

PathCache

especificado, mientras que los subdirectorios, cuyas identidades obviamente cambian cada vez que se cambia el directorio de trabajo actual, se marcan para ser escaneados al vuelo cada vez que se busca un archivo. En caso de éxito, esta función devuelve [[64]] 0 . En caso de error, devuelve [[66]] 1 , y se puede obtener una descripción del err

or llamando a [[6

Una vez que la caché ha sido poblada con archivos, puede buscar el nombre de ruta completo de un archivo, simplemente especificando su nombre de archivo a [[72]] pca_lookup_file() .

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal)
;

Para hacer posible pasar a esta función un nombre de archivo que es en realidad parte de una cadena más larga, el argumento [[76]] name_len puede usarse para especificar la longitud del nombre de archivo al inicio del argumento [[78]] name[] . Si pasa [[80]] -1 para esta longitud, la longitud de la cadena se determinará con [[82]] strlen() . Si la cadena [[84]] name[] podría contener barras invertidas que escapan los significados especiales de espacios y tabulaciones dentro del nombre de archivo, dé al argumento [[86]] literal el valor [[88]] 0 . De lo contrario, si las barras invertidas deben tratarse como caracteres normales, pase [[90]] 1 como valor del argumento [[92]] literal

ARCHIVO

Buscar las posibles completaciones de un prefijo de nombre de archivo en la caché de nombres de archivo se logra pasando la función de retorno proporcionada [[96]] pca_path_completions() a la función [[98]] cpl_complete_word() (véase la página man [[100]] cpl_complete_word(3) )

  CPL_MATCH_FN(pca_path_completions)

Esta función de retorno requiere que su argumento [[104]] data sea un puntero a un objeto [[106]] PcaPathConf . Los objetos de configuración de este tipo se asignan llamando a [[108]] new_PcaPathConf() .

  PcaPathConf *new_PcaPathConf(PathCache *pc)
;

Esta función devuelve un objeto inicializado con parámetros de configuración predeterminados, que determinan cómo se comporta la función de retorno [[112]] cpl_path_completions() . Las funciones que le permiten cambiar individualmente estos parámetros se discuten a

continuación.

Por defecto, la función de retorno [[115]] pca_path_completions() busca hacia atrás el inicio del nombre de archivo que se está completando, buscando el primer espacio sin escapar o el inicio de la línea de entrada. Si desea especificar una ubicación diferente, llame a [[117]] ppc_file_start() con el índice en el que comienza el nombre de archivo en la línea de entrada. Pasar [[119]] start_index=-1 vuelve a habilitar el comportamiento

predeterminado. 
  void ppc_file_start(PcaPathConf *ppc, int start_index)
;

Por defecto, cuando [[123]] pca_path_completions() examina un nombre de archivo en la línea de entrada, cada barra invertida aislada en la línea de entrada se interpreta como un carácter especial que elimina cualquier significado especial del carácter que le sigue, como un espacio que debe tomarse como parte del nombre de archivo en lugar de delimitar el inicio del nombre de archivo. Estas barras invertidas se ignoran por lo tanto al buscar completaciones, y posteriormente se añaden antes de espacios, tabulaciones y barras invertidas literales en la lista de completaciones. Para que las barras invertidas sin escapar se traten como caracteres normales, llame a [[125]] ppc_literal_escapes() con un valor distinto de cero en su argumento [[127]] literal .

  void ppc_literal_escapes(PcaPathConf *ppc, int literal)
;

SIENDO

SELECTIVO

Si solo le interesan ciertos tipos de archivos, como, por ejemplo, archivos ejecutables, o archivos cuyos nombres terminen en un sufijo particular, puede hacer que las funciones de completación y búsqueda de archivos sean selectivas en los nombres de archivo que devuelven. Esto se hace registrando una función de retorno con su objeto [[138]] PathCache . A partir de ahí, cada vez que se encuentra un nombre de archivo que coincide con un nombre de archivo que se está buscando, o que coincide con un prefijo que se está completando, su función de retornofunción será llamada con la ruta completa del archivo, más cualquier dato específico de la aplicación que usted proporcione, y si la función de retorno devuelve 1 el nombre de archivo será reportado como una coincidencia, y si devuelve 0 , será ignorado. Funciones de retorno adecuadas y sus prototipos deben ser declarados con el siguiente macro.

Tenga en cuenta que estas funciones de retorno reciben la ruta completa de cada archivo que coincide, por lo que la decisión sobre si un archivo es de interés puede basarse en cualquier propiedad del archivo, no solo en su nombre de archivo. Como ejemplo, la función de retorno

proporcionada

cpl_check_exe() mira los permisos de ejecución del archivo y los permisos de sus directorios padre, y solo devuelve

1

si el usuario tiene permiso de ejecución sobre el archivo. Esta función de retorno puede usarse para buscar o completar nombres de comandos encontrados en los directorios listados en la variable

de entorno

PATH del usuario. El programa de ejemplo dado anteriormente en esta página del manual proporciona una demostración de esto. Tenga cuidado de que si alguien intenta completar una cadena vacía, su función de retorno será llamada una vez por cada archivo en la caché, lo que podría numerar en los miles. Si su función de retorno hace algo que consume tiempo, esto podría resultar en un retraso inaceptable para el usuario, por lo que las funciones de retorno deben mantenerse cortas. Para mejorar el rendimiento, siempre que una de estas funciones de retorno es llamada, la elección que hace se almacena en caché, y la próxima vez que el archivo correspondiente se busca, en lugar de llamar a la función de retorno de nuevo, se usa el registro en caché de si fue aceptado o rechazado. Por lo tanto, si alguien intenta completar una cadena vacía, y presiona tabulador una segunda vez cuando no parece que nada suceda, solo habrá un largo retraso, ya que la segunda pasada operará completamente a partir de las disposiciones en caché de los archivos.
