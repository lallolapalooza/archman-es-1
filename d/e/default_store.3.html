DESCRIPCIÓ

N

El propósito del almacenamiento por defecto es

triple:
1
)
Crear un espacio de almacenamiento global sin crear un montón de variables globalmente accesibles o un montón de funciones de acceso para trabajar con variables de acceso más
restringido.
2
)
Proporcionar una única ubicación donde se necesita implementar el bloqueo de hilos. Sin embargo, en el momento de escribir esto, el bloqueo de hilos aún no está
implementado.
3
)
Reducir el número de dependencias cruzadas entre piezas de código que pueden o no estar vinculadas juntas
a largo plazo. Esto proporciona una única ubicación en la que se pueden almacenar datos de configuración,
por ejemplo, para una sección separada de código que puede no estar vinculada a la aplicación en cuestión.

Las funciones definidas aquí implementan estos

objetivos.

Actualmente, se admiten tres tipos de datos: booleanos, enteros y cadenas. Cada uno de estos tipos de datos tiene espacios de almacenamiento separados. Además, el espacio de almacenamiento para cada tipo de datos se divide aún más por el nivel de la aplicación. Actualmente, hay dos espacios de almacenamiento. El primero está reservado para la propia biblioteca SNMP. El segundo está destinado a su uso en aplicaciones y no es modificado ni verificado por la biblioteca y, por lo tanto, este es el espacio que usted puede

usar.

Puede pensar en estos espacios de almacenamiento como 3 matrices, algo como bool_storage[storeid][which], int_storage[storeid][which] y string_storage[storeid][which]. Los datos se acceden a través de las funciones definidas a continuación. Para los datos que desee almacenar, debe usar un parámetro store de NETSNMP_DS_APPLICATION_ID

.

El espacio de almacenamiento utilizado por la biblioteca (para el cual el parámetro store es NETSNMP_DS_LIBRARY_ID) está definido en el archivo default_store.h, que actualmente contiene las siguientes

FUNCIONE

S
int netsnmp_ds_set_boolean(int store, int which, int val)
;
Almacena TRUE si val != 0 o FALSE en caso contrario en el slot bool_storage[store][which]. Devuelve SNMPERR_GENERR si los parámetros store y which no corresponden a un slot válido, o SNMPERR_SUCCESS en caso
contrario.
int netsnmp_ds_get_boolean(int store, int which)
;
Devuelve 1 si bool_storage[store][which] es TRUE o 0 si no lo es. También puede devolver SNMPERR_GENERR si los parámetros store y which no corresponden a un slot
válido.
int netsnmp_ds_set_string(int store, int which, const char *val)
;
Almacena val en el slot string_storage[store][which]. Devuelve SNMPERR_SUCCESS normalmente, o SNMPERR_GENERR si los parámetros store y which no corresponden a un slot
válido.
char *netsnmp_ds_get_string(int store, int which)
;
Devuelve la cadena que ha sido almacenada en el slot string_storage[store][which], o NULL si los parámetros store y which no corresponden a un slot
válido.
netsnmp_ds_set_int(int store, int which, int val)
;
Almacena val en el slot int_storage[store][which]. Devuelve SNMPERR_GENERR si los parámetros store y which no corresponden a un slot válido, o SNMPERR_SUCCESS en caso
contrario.
int netsnmp_ds_get_int(int store, int which)
;
Devuelve el entero que ha sido almacenado en el slot int_storage[store][which] , o SNMPERR_GENERR si los parámetros store y which no corresponden a un slot
válido.
void netsnmp_ds_shutdown(void)
;
Reclama la memoria utilizada para mantener la información recopilada por netsnmp_ds_register_config y netsnmp_ds_register_prem
ib.
int netsnmp_ds_register_config(u_char type, const char *ftype, const char *token, int store, int which)
;
Registra una directiva de archivo de configuración token y la asocia a un tipo de almacenamiento y slot predeterminados. Específicamente, store y which indican el slot de almacenamiento en el tipo de datos indicado por type, donde type es una de las siguientes constantes: ASN_BOOLEAN, ASN_INTEGER, o ASN_OCTET_STR. La variable ftype indica la cadena base del nombre de archivo que se busca para la palabra clave token. Por ejemplo
, la siguie
nte llamada:

la palabra "testtoken" debería ser leída y el valor después de "testtoken" debería ser almacenado en el
slot int_storage[DS_APPLICATION_ID][5]. Por ejemplo, la siguiente línea en el archivo de configuración:
