cmode

runtime | driverinit | permanent } Modo de configuración en el que se establece el

runtime - Establece el nuevo valor mientras el controlador está en ejecución. Este modo de configuración no requiere ningún reinicio para aplicar el nuevo valor.

driverinit - Establece un nuevo valor que se aplicará durante la inicialización del controlador. Este modo de configuración requiere reiniciar el controlador con el comando devlink reload para aplicar el

nuevo valor.

permanent - El nuevo valor se escribe en la memoria no volátil del dispositivo. Este modo de configuración requiere un reinicio duro para aplicar el nuevo

valor.

PID | NAME | ID } - Especifica el espacio de nombres de red en el que recargar, ya sea por pid, nombre o id. actio

n {

driver_reinit | fw_activate } - Especifica la acción de recarga requerida. Si este argumento se omite se usará la acción driver_reinit. Tenga en cuenta que aunque el usuario pida una acción específica, la implementación del controlador podría requerir realizar otra acción junto con ella. Por ejemplo, algunos controladores no soportan la reinicialización del controlador sin la activación del firmware. Por lo tanto, el comando devlink reload devuelve la lista de acciones que fueron realmente realizadas. driver_reinit - Reinicialización de las entidades del controlador, aplicando los valores de devlink-param y devlink-resource

.

fw_activate - Activa el nuevo firmware si tal imagen está almacenada y pendiente de activación. Si no se especifica ninguna limitación, esta acción puede implicar un reinicio del firmware. Si no hay ninguna imagen nueva pendiente, esta acción recargará la imagen de firmware

actual.

limit no_reset - Especifica una limitación en la acción de recarga. Si este argumento se omite, el límite no está especificado y la acción de recarga no está limitada. En tal caso, la implementación del controlador puede incluir un reinicio o tiempo de inactividad según sea necesario para realizar las

acciones.

no_reset - No se permite ningún reinicio, no se permite tiempo de inactividad, no se permite la caída del enlace y no se pierde ninguna

configuración.

devlink dev info - muestra l

a información d
el dispositivo.

Muestra la información del dispositivo proporcionada por el controlador. Este comando se puede usar para consultar las versiones de los componentes de hardware o los componentes del dispositivo que no pueden actualizarse

(

fixed ) así como el firmware del dispositivo que sí puede actualizarse. Para los componentes de firmware running muestra las versiones del firmware actualmente cargadas en el dispositivo, mientras que stored informa de las versiones en la flash del dispositivo. Las versiones running y stored pueden diferir después de que la flash haya sido actualizada, pero antes del

reinicio.

DEV - especifica el dispositivo devlink a mostrar. Si este

argumento se omite, se l
istan todos los dispositivos.
