CABECERA HTTP

Antes de que se inicie cada función de búsqueda, una aplicación cliente puede añadir cabeceras de solicitud HTTP. Estas se restablecen después de cada función de búsqueda. debuginfod_add_http_header() puede llamarse con cadenas de la forma "Header: value". Estas cadenas son copiadas por la biblioteca. Un valor de retorno cero indica éxito, pero las condiciones de falta de memoria pueden resultar en un -ENOMEMdistinto de cero. Si la cadena tiene el formato incorrecto, se devolverá -EINVAL .

$DEBUGINFOD_HEADERS_FILE especifica un archivo para proporcionar cabeceras a las solicitudes salientes. Cada línea no vacía de este archivo se maneja como si se hubiera llamado a debuginfod_add_http_header() con su contenido.

Tenga en cuenta que la implementación actual de la biblioteca debuginfod-client usa libcurl, pero no debe depender de ese hecho. No use esta función para reemplazar ninguna cabecera estándar, excepto para el User-Agent mencionado a continuación. Puede usar esta función para añadir información de autorización para el control de acceso, o para proporcionar cabeceras opcionales al servidor con fines de registro.

De forma predeterminada, la biblioteca añade un User-Agent: descriptivo a las solicitudes salientes. Si la aplicación cliente añade una cabecera con el mismo nombre, esta configuración predeterminada se suprime.

Durante o después de una búsqueda, una aplicación cliente puede llamar a debuginfod_get_headers() para recopilar el subconjunto de cabeceras de respuesta HTTP recibidas del servidor debuginfod actual o más reciente. Solo se conservan aquellas cabeceras con el prefijo X-DEBUGINFOD (sin distinguir mayúsculas de minúsculas). Se devuelven como una sola cadena, con cada "cabecera: valor" terminada con un \n (no \r\n como en HTTP). Puede ser NULL. La cadena resultante es propiedad de la biblioteca y no debe ser modificada ni liberada. El llamante debe copiar la cadena devuelta si necesita usarla más allá de la liberación del objeto cliente.

SEGURIDAD

Si hay firmas IMA disponibles de los RPM que contienen los archivos solicitados, entonces debuginfod extraerá esas firmas en cabeceras de respuesta, y debuginfod_find_*() realizará la verificación sobre los archivos. La política de validación se controla mediante etiquetas insertadas en $DEBUGINFOD_URLS. De forma predeterminada, debuginfod_find_*() actúa en modo de ignorar.

Si se accede a través de HTTP en lugar de HTTPS, la red debe ser de confianza. La información de autenticación a través de la biblioteca interna libcurl no está habilitada actualmente, excepto para el estilo de texto plano básico http[s]://userid:password@hostname/ . (El servidor debuginfod no realiza autenticación, pero un servidor proxy frontal podría hacerlo.)

VARIABLES DE ENTORNO

$TMPDIR
Esta variable de entorno apunta a un sistema de archivos para usar con archivos temporales. El valor predeterminado es /tmp.
$DEBUGINFOD_URLS
Esta variable de entorno contiene una lista de prefijos de URL para instancias debuginfod de confianza. Los prefijos de URL alternativos se separan por espacios. Esta variable de entorno puede ser establecida por scripts de /etc/profile.d que leen archivos /etc/debuginfod/*.urls.

Esta variable de entorno también puede contener etiquetas que definen la política, las cuales dictan la política de respuesta para verificar las firmas IMA por archivo en los RPM. Como la lista separada por espacios se lee de izquierda a derecha, al encontrar una etiqueta, las URLs subsiguientes hasta la siguiente etiqueta se manejarán usando esa política especificada. Todas las URLs antes de la primera etiqueta usarán la política predeterminada, ima:ignore. Por ejemplo:


DEBUGINFOD_URLS="https://foo.com ima:enforcing https://bar.ca http://localhost:8002/ ima:ignore https://baz.org"

Donde foo.com y baz.org usan la política predeterminada ignore y bar.ca y localhost usan una política enforcing . La etiqueta de política puede ser una de las siguientes:

ima:enforcing Cada archivo descargado requiere una firma válida, protegiendo completamente la integridad.
ima:ignore Omite la verificación por completo, sin proporcionar protección.

Las alertas de fallo de validación se dirigirán como se especifica en $DEBUGINFOD_VERBOSE.

$DEBUGINFOD_CACHE_PATH
Esta variable de entorno gobierna la ubicación de la caché donde se guardan los archivos descargados y los archivos de control de caché. El directorio predeterminado se elige basándose en otras variables de entorno, vea más abajo.
$DEBUGINFOD_PROGRESS
Esta variable de entorno gobierna la función de progreso predeterminada. Si está definida, y si no se establece explícitamente una progressfn, entonces la biblioteca configurará una progressfn predeterminada. Esta función añadirá periódicamente un mensaje de progreso simple a stderr. El valor predeterminado es sin salida de la función de progreso.
$DEBUGINFOD_VERBOSE
Esta variable de entorno gobierna el descriptor de archivo predeterminado para la salida detallada. Si está definida, y si no se establece explícitamente un fd detallado, entonces la salida detallada se producirá en STDERR_FILENO.
$DEBUGINFOD_RETRY_LIMIT
Esta variable de entorno gobierna el límite predeterminado de intentos de reintento. Si una consulta falló con un errno distinto de ENOENT, se iniciarán varios intentos dentro del límite.
$DEBUGINFOD_TIMEOUT
Esta variable de entorno gobierna el tiempo de espera de comienzo de descarga para cada conexión HTTP de debuginfod. Un servidor que no proporcione al menos 100K de datos dentro de este número de segundos se omite. El valor predeterminado es 90 segundos. (Cero o negativo significa "sin tiempo de espera".)
$DEBUGINFOD_MAXTIME
Esta variable de entorno dicta cuánto tiempo esperará el cliente para completar la descarga de un archivo encontrado en un servidor, en segundos. Es mejor usarla para asegurar que un archivo se descargue rápidamente o sea rechazado. El valor predeterminado es 0 (tiempo infinito).
$DEBUGINFOD_MAXSIZE
Esta variable de entorno dicta el tamaño máximo de un archivo a descargar en bytes. Es mejor usarla si el usuario desea asegurar que solo se descarguen archivos pequeños. Un valor de 0 causa que no se considere el tamaño, y el cliente puede intentar descargar un archivo de cualquier tamaño. El valor predeterminado es 0 (tamaño infinito).
$DEBUGINFOD_HEADERS_FILE
Esta variable de entorno apunta a un archivo que proporciona cabeceras a las solicitudes HTTP salientes, una por línea. Las líneas de cabecera no deberían terminar con CRLF, a menos que esa sea la convención de salto de línea del sistema. Las líneas que solo contienen espacios en blanco se omiten.
$DEBUGINFOD_IMA_CERT_PATH
Esta variable de entorno contiene una lista de rutas de directorio absolutas que contienen certificados X.509 para la verificación IMA por archivo de los RPM. Las rutas alternativas se separan con dos puntos.

CACHÉ

Antes de cada consulta, la biblioteca cliente debuginfod comprueba si es necesario limpiar la caché. Si es momento de limpiar, la biblioteca recorre el directorio de caché y elimina debuginfod_client(3) — debuginfod manual

NAME

debuginfod_client — libdebuginfod client cache

DESCRIPTION

The debuginfod client library uses a cache to store downloaded debuginfo-related artifacts and newly empty directories, if they have not been accessed recently.

Control files are located directly under the cache directory. They contain simple decimal numbers to set cache-related configuration parameters. If the files do not exist, the client library creates the files with the default parameter values as content.

After each query, the debuginfod client library deposits newly received files into a directory & file that is named based on the build-id. A failed query is also cached by a special file. The naming convention used for these artifacts is deliberately undocumented.

$XDG_CACHE_HOME/debuginfod_client/
Default cache directory, if $XDG_CACHE_HOME is set.
$HOME/.cache/debuginfod_client/
Default cache directory, if $XDG_CACHE_HOME is not set.
$HOME/.debuginfod_client_cache/
Deprecated cache directory, used only if preexisting.
cache_clean_interval_s
This control file gives the interval between cache cleaning rounds, in seconds. The default is 86400, one day. 0 means "immediately".
max_unused_age_s
This control file sets how long unaccessed debuginfo-related files are retained, in seconds. The default is 604800, one week. 0 means "immediately".
cache_miss_s
This control file sets how long to remember a query failure, in seconds. New queries for the same artifacts within this time window are short-circuited (returning an immediate failure instead of sending a new query to servers). This accelerates queries that probably would still fail. The default is 600, 10 minutes. 0 means "forget immediately".
metadata_retention_s
This control file sets how long to remember the results of a metadata query. New queries for the same artifacts within this time window are short-circuited (repeating the same results). This accelerates queries that probably would probably have the same results. The default is 3600, 1 hour. 0 means "do not retain".
