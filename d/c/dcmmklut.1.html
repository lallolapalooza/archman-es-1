DESCRIPCIÓ

N

La utilidad dcmmklut permite crear una variedad de tablas de consulta (LUT) de Modalidad, Presentación y VOI DICOM y está destinada a la creación de imágenes de prueba. La utilidad es capaz de leer un archivo de imagen DICOM existente, crear una tabla de consulta según las opciones de la línea de comandos y escribir el nuevo objeto de vuelta al archivo. También es posible crear un nuevo objeto que contenga la LUT especificada sin leer un archivo de imagen DICOM existente. Esto es, por ejemplo, útil para almacenar simplemente diferentes tablas de consulta en una estructura tipo DICOM. De forma predeterminada, el archivo de salida se codifica con la misma sintaxis de transferencia utilizada para el archivo de entrada, pero la sintaxis de transferencia también se puede especificar como una opción de la línea de

comandos.

Los datos de la LUT se pueden derivar de la forma de una curva gamma (el valor predeterminado para el factor gamma es 1) o importarse de un archivo (actualmente se admiten el formato MAP de PhotoImpact de Ulead y un formato de texto simple). La entrada y la salida de la LUT también se pueden especificar en el rango permitido por el estándar DICOM. La interpolación del rango de entrada se realiza mediante un algoritmo de ajuste de curva

polinómica.

Además del archivo de salida DICOM, los datos de la LUT también se pueden exporta

r a un archivo de texto con pestañas, lo que permite la fácil visualización de las
curvas con una aplicación de hoja de cálculo común (por ejemplo, Microsoft Excel).

REGISTR

O

El nivel de salida de registro de las diversas herramientas de línea de comandos y las bibliotecas subyacentes puede ser especificado por el usuario. De forma predeterminada, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como los detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo

"oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Normalmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix

comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dcmmklut intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. De forma predeterminada, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows)

.

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es ies un error si no se

puede cargar ningún
diccionario de datos.
