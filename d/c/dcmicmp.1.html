DESCRIPCIÓ

N

La utilidad dcmicmp lee dos imágenes DICOM, una imagen "imagen de referencia" original y una "imagen de prueba" postprocesada, a la cual se le ha aplicado algún tipo de procesamiento como una compresión de imagen con pérdida, seguida de la descompresión. Esta herramienta requiere que ambas imágenes tengan la misma resolución, el mismo número de fotogramas y que sean ambas a color o monocromas. No se admiten imágenes

comprimidas.

La utilidad dcmicmp luego compara ambas imágenes y calcula e imprime métricas que describen cuán similares o diferentes son ambas

imágenes:
  • el error absoluto máximo es la diferencia más grande entre un valor de píxel en la imagen de referencia y el valor de píxel correspondiente en la imagen de
    • prueba.
  • el error absoluto medio (MAE) es la diferencia promedio entre el valor de píxel original y el valor de píxel de la imagen de
    • prueba
  • el error cuadrático medio (RMSE) se calcula sumando los cuadrados de todos los valores de diferencia, luego dividiendo por el número de valores sumados, y luego tomando la raíz
    • cuadrada.
  • La relación pico señal a ruido (PSNR) considera la imagen de referencia como una señal y las diferencias entre la imagen de referencia y la de prueba como ruido. La PSNR es la fuerza de señal máxima (es decir, el valor de píxel máximo en la imagen de referencia) dividida por el RMSE, expresada en una escala logarítmica en
    • dB.
  • La relación señal a ruido (SNR) también considera la imagen de referencia como una señal
    • y las diferencias entre la imagen de referencia y la de prueba como ruido. La SNR es la
fuerza de señal promedio dividida por el RMSE, expresada en una escala logarítmica en dB.

Todas las métricas se calculan según lo de

finido en R.C. Gonzalez y R.E. Woods, "Digi
tal Image Processing," Prentice Hall 2008.

NOTA

S

canalización de visualización de escala de

grises

Las imágenes DICOM monocromas requieren que se ejecute una canalización de visualización de múltiples etapas para convertir los valores de píxel crudos en los llamados valores de presentación (p-valores) que se envían al monitor (posiblemente calibrado). Al comparar la similitud de imágenes antes y después del postprocesamiento, puede ser relevante activar algunas etapas de esta canalización de visualización antes de calcular la imagen de diferencia y las métricas. Las opciones de procesamiento de imagen permiten al llamador activar o desactivar las transformaciones de LUT de Modalidad, LUT de VOI y LUT de Presentación. En cualquier caso, se aplica la misma transformación a ambas imágenes, aunque posiblemente con diferentes parámetros si, por ejemplo, se aplica la "primera ventana de LUT de VOI" almacenada en cada imagen. Esto asume que el algoritmo de postprocesamiento (por ejemplo, el algoritmo de compresión) ha adaptado los valores de tales ventanas durante la compresión de modo que la visualización de la imagen después de aplicar la ventana sea lo más cercana posible a la referencia. Para imágenes con más de 8 bits por muestra, puede ser importante saber qué transformación de LUT de VOI aplicará el usuario al ver la imagen, porque esto puede afectar la calidad de imagen percibida. Por lo tanto, los parámetros absolutos de ventana también pueden sere dado con la opción --

set-window, que luego se apl
icará a ambas imágenes.

idoneidad de las imágenes para fines

diagnósticos

El usuario también debe tener en cuenta que las métricas calculadas por esta herramienta no pueden predecir ni estimar la

idoneidad de una imagen comprimida con pérdida para fines diagnósticos. Para este propósito se necesitaría un procesamie
nto de imágenes mucho más complejo y una comprensión del contenido de la imagen (p. ej., la parte del cuerpo). Las mé
tricas calculadas proporcionan una estimación del nivel de distorsión causado por el postprocesamiento - ni más ni menos.

El usuario puede especificar el nivel de registro de salida de las diversas herramientas de línea de comandos y las bibliotecas subyacentes. De forma predeterminada, solo se escriben errores y advertencias en el flujo de error estándar. La opción --debug se puede utilizar para obtener más detalles sobre la actividad interna, p. ej., con fines de depuración. "oflog".

Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/l

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten valores múltiples (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Normalmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones se excluyen mutuamente, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix

comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (p. ej. @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separa

dor a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. T
enga en cuenta que un archivo de comando no puede contener otro archivo de comando.

ENTORN

O

La utilidad dcmicmp intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. De forma predeterminada, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows)

.

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo se debe usar cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En los sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se pu

ede cargar ningún d
iccionario de datos.
