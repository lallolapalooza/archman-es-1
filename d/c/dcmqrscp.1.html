NOMBRE

dcmqrscp - Archivo de imágenes DICOM (nodo de prueba central)

SINOPSIS

dcmqrscp [opciones] [puerto]

DESCRIPCIÓN

La aplicación Nodo de Prueba Central de Imágenes (dcmqrscp) implementa un archivo de imágenes simple. Gestiona un número de áreas de almacenamiento y permite que las imágenes se almacenen en estas áreas de almacenamiento utilizando la Clase de Servicio de Almacenamiento DICOM. También permite consultar atributos de imágenes y recuperar imágenes utilizando la Clase de Servicio de Consulta/Recuperación DICOM. La dcmqrscp aplicación también implementa reglas de restricción de acceso para limitar las operaciones a entidades de aplicación pares específicas.

La dcmqrscp aplicación está destinada a ser utilizada en demostraciones DICOM y como herramienta de prueba de compatibilidad. En particular, dcmqrscp eliminará imágenes si se han excedido sus restricciones de cuota.

Precaución: Tenga en cuenta que el formato del archivo binario index.dat de dcmqrdb cambió el 20130705 debido a una corrección de errores en el código correspondiente. Un archivo index.dat creado antes de esa fecha no funcionará con el código de dcmqrdb compilado después de esa fecha, sino que debe ser recreado. Utilice dcmqridx para esa tarea o vuelva a enviar todas las imágenes al servidor después de eliminar todos los archivos antiguos (y crear un nuevo archivo index.dat vacío).

NOTAS

Operación

dcmqrscp espera a que otra aplicación se conecte en la dirección de presentación (número de puerto) especificada en su archivo de configuración (o anulado por una opción de línea de comando). Cuando otra aplicación se conecta, dcmqrscp espera que sea una aplicación DICOM y que use los Títulos de AE de llamada y de llamado especificados en el archivo de configuración de dcmqrscp. dcmqrscp aceptará asociaciones con Contextos de Presentación para Clases SOP de la Clase de Servicio de Verificación, la Clase de Servicio de Almacenamiento y la Clase de Servicio de Consulta/Recuperación. Las asociaciones serán rechazadas o los Contextos de Presentación serán rechazados si la aplicación par no tiene los derechos de acceso apropiados como lo especifica el archivo de configuración de dcmqrscp.

dcmqrscp recibirá imágenes en Contextos de Presentación de la Clase de Servicio de Almacenamiento, las escribirá en un área de almacenamiento configurable asociada con el título de AE de la clase, extraerá atributos de estas imágenes y los almacenará en una base de datos. dcmqrscp recibirá solicitudes de consulta y generará respuestas de consulta en Contextos de Presentación de la Clase de Servicio de Consulta/Recuperación. dcmqrscp recibirá solicitudes de recuperación y generará respuestas de recuperación en Contextos de Presentación de la Clase de Servicio de Consulta/Recuperación. dcmqrscp también procesará mensajes C-CANCEL para interrumpir operaciones de consulta/recuperación.

En operaciones normales dcmqrscp nunca saldrá, seguirá esperando nuevas asociaciones hasta que sea terminado.

Configuración

El programa dcmqrscp utiliza el mismo archivo de configuración que el programa dcmqrti . Consulte la documentación sobre la configuración para más información.

Control de Acceso

Cuando se compila en plataformas Unix con soporte de TCP wrapper, el control de acceso basado en host se puede habilitar con la opción de línea de comandos --access-control . En este caso, se aplican las reglas de control de acceso definidas en las tablas de control de acceso de host del sistema para dcmqrscp . Las ubicaciones predeterminadas de las tablas de control de acceso de host son /etc/hosts.allow y /etc/hosts.deny. Más detalles se describen en hosts_access(5).

REGISTRO

El nivel de salida de registro de las diversas herramientas de línea de comandos y las bibliotecas subyacentes lo puede especificar el usuario. De forma predeterminada, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como los detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows) opción --log-config se puede utilizar. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos utilizando el signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando es reemplazado por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

El dcmqrscp utilidad intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado en Windows).

Se debe preferir el comportamiento por defecto y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.

Dependiendo de las opciones de la línea de comandos especificadas, la utilidad dcmqrscp intentará cargar tablas de asignación de conjuntos de caracteres. Esto ocurre cuando DCMTK se compiló con la biblioteca oficonv (que es el predeterminado) y las tablas de asignación no están integradas en la biblioteca (predeterminado cuando DCMTK usa bibliotecas compartidas).

Se espera que los archivos de tablas de asignación estén en <datadir>de DCMTK. La variable de entorno DCMICONVPATH se puede usar para especificar una ubicación diferente. Si se especifica una ubicación diferente, esas tablas de asignación también reemplazan cualquier tabla integrada.
