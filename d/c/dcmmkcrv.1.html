NOMBRE

dcmmkcrv - Añadir datos de curva 2D a imagen

SINOPSIS

dcmmkcrv [opciones] dcmfile-in curvedata-in dcmfile-out

DESCRIPCIÓN

La utilidad dcmmkcrv permite crear imágenes DICOM que contienen datos de curva. Dado que los datos de curva apenas son utilizados por los proveedores hoy en día, esto está destinado a ser un medio para probar implementaciones que puedan leer datos de curva. La utilidad lee una imagen DICOM existente y un archivo de texto que contiene los datos de la curva en forma textual. Se crea un grupo de repetición de datos de curva DICOM según las opciones especificadas en la línea de comandos, se añade a la imagen existente y se vuelve a escribir en un archivo. El archivo de salida se codifica con la misma sintaxis de transferencia utilizada para el archivo de entrada. Esta utilidad solo admite la creación de curvas bidimensionales.

PARÁMETROS

dcmfile-in    Archivo DICOM de entrada ("-" para stdin)
curvedata-in  Archivo de entrada de datos de curva (texto)
dcmfile-out   Nombre del archivo de salida DICOM ("-" para stdout)

OPCIONES

opciones generales

  -h   --help
         imprimir este texto de ayuda y salir
       --version
         imprimir información de versión y salir
       --arguments
         imprimir argumentos de línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprimir advertencias ni errores
  -v   --verbose
         modo verboso, imprimir detalles del procesamiento
  -d   --debug
         modo de depuración, imprimir información de depuración
  -ll  --log-level  [l]evel: cadena
         (fatal, error, warn, info, debug, trace)
         usar nivel l para el registrador
  -lc  --log-config  [f]ilename: cadena
         usar archivo de configuración f para el registrador

opciones de creación de curvas

tipo de curva:
  -r  --poly
        crear como curva POLY (predeterminado)
  +r  --roi
        crear como curva ROI
representación de valor de curva:
  +v  --data-vr  [n]úmero: entero 0..4 (predeterminado: 4)
        seleccionar VR de datos de curva: 0=US, 1=SS, 2=FL, 3=FD, 4=SL
  -c  --curve-vr  [n]úmero: entero 0..2 (predeterminado: 0)
        seleccionar VR con la que se escribe el elemento Curve Data
        0=VR según --data-vr, 1=OB, 2=OW
grupo de repetición:
  -g  --group  [n]úmero: entero 0..15 (predeterminado: 0)
        seleccionar grupo de repetición: 0=0x5000, 1=0x5002 etc.
descripción de la curva:
  -l  --label  s: cadena
        establecer la Etiqueta de Curva a s (predeterminado: ausente)
  +d  --description  s: cadena
        establecer la Descripción de Curva a s (predeterminado: ausente)
  -a  --axis  x: cadena, y: cadena
        establecer Unidades de Eje a x\y (predeterminado: ausente)

NOTAS

Sintaxis del Archivo de Datos de Curva

Se espera que el archivo de datos de curva sea un archivo de texto plano ASCII que contenga números (enteros o de punto flotante) que comprendan los valores de las coordenadas de los puntos. Los números deben estar separados por espacios en blanco. No se realiza ninguna verificación del rango de valores ni conversión del rango de valores. Ejemplo:

 256.451947    1.000000
 477.689863  128.822080
 128.822080  477.689863
  35.310137  128.822080
 256.451947    1.000000

REGISTRO

El nivel de salida del registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. El uso de la opción --verbose también informa mensajes informativos como detalles del procesamiento. La opción --debug se puede utilizar para obtener más detalles sobre la actividad interna, por ejemplo, para fines de depuración. Se pueden seleccionar otros niveles de registro utilizando la opción --log-level. En el modo --quiet, solo se informan los errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida del registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos al final indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' al principio, respectivamente. Por lo general, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comando usando un signo '@' como prefijo del nombre del archivo (por ejemplo, @command.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmmkcrv intentará cargar diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está configurada, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en el sentido de que dos puntos (":") separan las entradas. En sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
