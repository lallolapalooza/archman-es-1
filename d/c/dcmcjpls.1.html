DESCRIPCIÓ

N

La utilidad dcmcjpls lee una imagen DICOM sin comprimir (dcmfile-in), realiza una compresión JPEG-LS (es decir, una conversión a una sintaxis de transferencia DICOM encapsulada) y escribe la imagen convertida en un archivo de salida (dcmfil

e-ou
t).

a convertir ("-" para stdin) dcmfile-out Nomb
re de archivo DICOM de salida ("-" para stdout)

NOTA

S

La utilidad dcmcjpls comprime imágenes DICOM de todas las clases SOP. Procesa todos los elementos de datos de píxel (7fe0,0010) en el conjunto de datos, es decir, también se realiza la compresión en una imagen de icono. Sin embargo, dcmcjpls no intenta asegurar que la imagen comprimida todavía cumpla con todas las restricciones del IOD del

objeto.

El usuario es responsable de asegurarse de que las imágenes comprimidas que crea sean conformes con el estándar DICOM. En caso de duda, la utilidad dcmcjpls permite convertir una imagen a captura secundaria -

esta clase SOP no plantea restriccione
s como las mencionadas anteriormente.

REGISTRO DE

EVENTOS

El nivel de registro de eventos de las diversas herramientas de línea de comandos y las bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro de eventos pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro de eventos, vea la documentación del módulo

"oflog".

En caso de que el registro de eventos deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basados en el módulo o la aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix

comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando es reemplazado por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dcmcjpls intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está definida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows)

.

Se debe preferir el comportamiento por defecto y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se pued

e cargar ningún di
ccionario de datos.
