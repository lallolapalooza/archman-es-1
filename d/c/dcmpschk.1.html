NOMBRE

dcmpschk - Herramienta de comprobación de estados de presentación

SINOPSIS

dcmpschk [opciones] [fichero_estado_presentacion...]

DESCRIPCIÓN

La utilidad dcmpschk comprueba los objetos DICOM Grayscale Softcopy Presentation State para verificar su conformidad con el estándar. La prueba se realiza en tres fases:

  • La fase 1 comprueba la metahcabecera del archivo DICOM. Se prueba si todos los atributos requeridos están presentes, si la clase SOP y las UIDs de instancia coinciden con las UIDs del objeto principal y si el atributo de longitud de grupo contiene un valor correcto. La sintaxis de transferencia de la metahcabecera también se comprueba.
  • La fase 2 realiza una comprobación sintáctica de los valores, representaciones de valor y multiplicidades de valor para cada atributo del objeto. Los valores presentes en el objeto bajo prueba se comparan con las definiciones del diccionario de datos DICOM.
  • La fase 3 realiza una comprobación semántica de la integridad del Estado de Presentación. Esta fase se omite cuando se encuentran objetos de otras Clases SOP. Las fases 1 y 2 también se pueden aplicar a otros objetos DICOM de clases SOP arbitrarias. Cabe señalar que dcmpschk no soporta Estados de Presentación que contengan el Módulo Máscara. Estos serán rechazados con un mensaje indicando que el Módulo Máscara no está soportado.

PARÁMETROS

fichero_estado_presentacion  uno o más archivos de estado de presentación a comprobar

OPCIONES

opciones generales

REGISTRO

El nivel de salida del registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles de procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, p. ej., para fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida del registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos al final indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Normalmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre del archivo (p. ej., @comando.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios se tratan como un solo separador a menos que aparezcan entre comillas dobles) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmpschk intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (por defecto para Windows).

Se debe preferir el comportamiento por defecto y utilizar la variable de entorno DCMDICTPATH solo cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, de modo que un dos puntos (":") separa las entradas. En sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
