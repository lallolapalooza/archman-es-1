NOMBRE

dcmdjpeg - Decodificar un archivo DICOM comprimido con JPEG

SINOPSIS

dcmdjpeg [opciones] dcmfile-in dcmfile-out

DESCRIPCIÓN

La utilidad dcmdjpeg lee una imagen DICOM comprimida con JPEG (dcmfile-in), descomprime los datos JPEG (es decir, la convierte a una sintaxis de transferencia DICOM nativa) y escribe la imagen convertida en un archivo de salida (dcmfile-out).

PARÁMETROS

dcmfile-in   Nombre de archivo DICOM de entrada a convertir ("-" para stdin)
dcmfile-out  Nombre de archivo DICOM de salida ("-" para stdout)

OPCIONES

opciones generales

  -h    --help
          imprime este texto de ayuda y sale
        --version
          imprime la información de la versión y sale
        --arguments
          imprime los argumentos de la línea de comandos expandidos
  -q    --quiet
          modo silencioso, no imprime advertencias ni errores
  -v    --verbose
          modo detallado, imprime los detalles del procesamiento
  -d    --debug
          modo de depuración, imprime la información de depuración
  -ll   --log-level  [l]evel: constante de cadena
          (fatal, error, warn, info, debug, trace)
          usa el nivel l para el registrador
  -lc   --log-config  [f]ilename: cadena
          usa el archivo de configuración f para el registrador

opciones de entrada

formato del archivo de entrada:
  +f    --read-file
          lee el formato del archivo o el conjunto de datos (por defecto)
  +fo   --read-file-only
          lee solo el formato del archivo
  -f    --read-dataset
          lee el conjunto de datos sin la meta-información del archivo
  # Esta opción permite descomprimir objetos DICOM comprimidos con JPEG que
  # se han almacenado como conjunto de datos sin meta-cabecera. Tal cosa no
  # debería existir ya que la sintaxis de transferencia no se puede determinar
  # de forma fiable sin meta-cabecera, pero desafortunadamente existe.

opciones de procesamiento

conversión de espacio de color:
  +cp   --conv-photometric
          convierte si la interpretación fotométrica es YCbCr (por defecto)
  # Si la imagen comprimida usa la interpretación fotométrica YBR_FULL o YBR_FULL_422,
  # convierte a RGB durante la descompresión.
  +cl   --conv-lossy
          convierte YCbCr a RGB si es JPEG con pérdida
  # Si la imagen comprimida está codificada en JPEG con pérdida, asume el modelo
  # de color YCbCr y convierte a RGB.
  +cg   --conv-guess
          convierte a RGB si la biblioteca asume que es YCbCr
  # Si la biblioteca JPEG subyacente "supone" que el espacio de color de la
  # imagen comprimida es YCbCr, convierte a RGB.
  +cgl  --conv-guess-lossy
          convierte a RGB si es JPEG con pérdida y se asume que es YCbCr
          por la biblioteca JPEG subyacente
  # Si la imagen comprimida está codificada en JPEG con pérdida y la biblioteca
  # JPEG subyacente "supone" que el espacio de color es YCbCr, convierte a RGB.
  +ca   --conv-always
          convierte siempre YCbCr a RGB
  # Si la imagen comprimida es una imagen a color, asume el modelo de color
  # YCbCr y convierte a RGB. Advertencia: Esto llevará a una imagen decodificada
  # incorrectamente si el espacio de color es en realidad RGB. Las imágenes
  # comprimidas con JPEG sin pérdida casi nunca se codifican en YCbCr, por lo
  # que esta opción debe usarse con cuidado en tales imágenes.
  +cn   --conv-never
          nunca convierte YCbCr a RGB
  # Nunca convierte el espacio de color de YCbCr a RGB durante la descompresión.
  # Tenga en cuenta que una conversión de YBR_FULL_422 a YBR_FULL aún tendrá lugar
  # si la imagen de origen se ha comprimido con submuestreo.
configuración de planos:
  +pa   --planar-auto
          determina automáticamente la configuración de planos
          a partir de la clase SOP y el espacio de color (por defecto)
  # Si la imagen comprimida es una imagen a color, la almacena en configuración
  # de planos color-por-plano si lo requiere la clase SOP y la interpretación
  # fotométrica. Las imágenes de color de copia dura siempre se almacenan
  # color-por-plano, y los objetos de imagen de ultrasonido revisados se
  # almacenan color-por-plano si el modelo de color es YBR_FULL. Todo lo demás
  # se almacena color-por-píxel.
  +px   --color-by-pixel
          almacena siempre color-por-píxel
  # Si la imagen comprimida es una imagen a color, la almacena en configuración
  # de planos color-por-píxel.
  +pl   --color-by-plane
          almacena siempre color-por-plano
  # Si la imagen comprimida es una imagen a color, la almacena en configuración
  # de planos color-por-plano.
UID de instancia SOP:
  +ud   --uid-default
          mantiene el mismo UID de instancia SOP (por defecto)
  #  Nunca asigna un nuevo UID de instancia SOP.
  +ua   --uid-always
          asigna siempre un nuevo UID
  # Asigna siempre un nuevo UID de instancia SOP.
opciones de solución de problemas para codificaciones JPEG incorrectas:
  +w6   --workaround-pred6
          habilita la solución de problemas para imágenes JPEG sin pérdida
          con desbordamiento en el predictor 6
  # Se han observado imágenes DICOM de 16 bits/píxel "en la naturaleza"
  # que están comprimidas con JPEG sin pérdida y necesitan un manejo especial
  # porque el codificador produjo un desbordamiento de entero de 16 bits en el
  # predictor 6, que necesita ser compensado (reproducido) durante la
  # descompresión. Esta opción permite una descompresión correcta de tales
  # imágenes defectuosas, pero al mismo tiempo causará una descompresión
  # incorrecta de imágenes comprimidas correctamente. Úsela con cuidado.
  +wi   --workaround-incpl
          habilita la solución de problemas para datos JPEG incompletos
  # Esta opción hace que dcmjpeg ignore los datos JPEG incompletos
  # al final de un fragmento comprimido y comience a descomprimir
  # el siguiente fotograma desde el siguiente fragmento (si lo hay). Esto permite
  # decodificar imágenes con datos JPEG incompletos.
  +wc   --workaround-cornell
          habilita la solución de problemas para imágenes JPEG sin pérdida de 16 bits
          de Cornell con desbordamiento de la tabla de Huffman
  # Una de las primeras implementaciones de código abierto de la compresión
  # JPEG sin pérdida, la biblioteca "Cornell", tiene un error bien conocido que
  # conduce a valores inválidos en la tabla de Huffman cuando se comprimen
  # imágenes de 16 bits/muestra. Esta opción habilita una solución de problemas
  # que permite decodificar tales imágenes correctamente.

opciones de salida

formato del archivo de salida:
  +F    --write-file
          escribe el formato del archivo (por defecto)
  -F    --write-dataset
          escribe el conjunto de datos sin la meta-información del archivo
sintaxis de transferencia de salida:
  +te   --write-xfer-little
          escribe con VR explícito little endian (por defecto)
  +tb   --write-xfer-big
          escribe con sintaxis de transferencia VR explícito big endian
  +ti   --write-xfer-implicit
          escribe con sintaxis de transferencia VR implícito little endian
representaciones de valor posteriores a 1993:
  +u    --enable-new-vr
          habilita el soporte para nuevos VR (UN/UT) (por defecto)
  -u    --disable-new-vr
          deshabilita el soporte para nuevos VR, convierte a OB
codificación de longitud de grupo:
  +g=   --group-length-recalc
          recalcula las longitudes de grupo si están presentes (por defecto)
  +g    --group-length-create
          escribe siempre con elementos de longitud de grupo
  -g    --group-length-remove
          escribe siempre sin elementos de longitud de grupo
codificación de longitud en secuencias e ítems:
  +e    --length-explicit
          escribe con longitudes explícitas (por defecto)
  -e    --length-undefined
          escribe con longitudes indefinidas
relleno al final del conjunto de datos (no con --write-dataset):
  -p=   --padding-retain
          no cambia el relleno (por defecto si no --write-dataset)
  -p    --padding-off
          sin relleno (implícito si --write-dataset)
  +p    --padding-create  [f]ile-pad [i]tem-pad: entero
          alinea el archivo en un múltiplo de f bytes
          y los ítems en un múltiplo de i bytes

SINTAXIS DE TRANSFERENCIA

dcmdjpeg soporta las siguientes sintaxis de transferencia para la entrada (dcmfile-in):

LittleEndianImplicitTransferSyntax             1.2.840.10008.1.2
LittleEndianExplicitTransferSyntax             1.2.840.10008.1.2.1
DeflatedExplicitVRLittleEndianTransferSyntax   1.2.840.10008.1.2.1.99 (*)
BigEndianExplicitTransferSyntax                1.2.840.10008.1.2.2
JPEGProcess1TransferSyntax                     1.2.840.10008.1.2.4.50
JPEGProcess2_4TransferSyntax                   1.2.840.10008.1.2.4.51
JPEGProcess6_8TransferSyntax                   1.2.840.10008.1.2.4.53
JPEGProcess10_12TransferSyntax                 1.2.840.10008.1.2.4.55
JPEGProcess14TransferSyntax                    1.2.840.10008.1.2.4.57
JPEGProcess14SV1TransferSyntax                 1.2.840.10008.1.2.4.70

(*) si se compiló con soporte para zlib habilitado

dcmdjpeg soporta las siguientes sintaxis de transferencia para la salida (dcmfile-out):

LittleEndianImplicitTransferSyntax             1.2.840.10008.1.2
LittleEndianExplicitTransferSyntax             1.2.840.10008.1.2.1
BigEndianExplicitTransferSyntax                1.2.840.10008.1.2.2

REGISTRO

El nivel de registro de salida de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por predeterminado, solo se escriben en el flujo de error estándar los errores y las advertencias. Usando la opción --verbose también se informan mensajes informativos como los detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, para propósitos de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet solo se informan los errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config . Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos suspensivos indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comando usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un único separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comando largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmdjpeg intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.
