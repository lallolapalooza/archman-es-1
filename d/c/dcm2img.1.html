imagen DICOM a un for
mato de imagen estándar

SINOPSI

S 
dcm2img [opcio
nes] dcmfile-i
n [bitmap-out]

DESCRIPCIÓ

N

La utilidad dcm2img lee una imagen DICOM, convierte los datos de píxeles de acuerdo con las opciones de procesamiento de imagen seleccionadas y escribe una imagen en uno de los siguientes formatos

de imagen de propósito general: BMP, PGM/PPM, PNG, TIFF, JPEG o JPEG-LS. Esta utilidad admit
e imágenes DICOM sin comprimir, así como imágenes DICOM comprimidas con JPEG, JPEG-LS y RLE.

PARÁMETRO

S 
dcmfile-in  nombre del archivo DICOM de entrada a c
onvertir ("-" para stdin) bitmap-out nombre del ar
chivo de salida a escribir (predeterminado: stdout)

opciones de solución de problemas para codificaciones incorrectas (solo imágenes comprimidas con JPEG):
  +w6   --workaround-pred6
          habilita la solución de problemas para imágenes JPEG sin pérdida
          con desbordamiento en el predictor 6
  # Se han observado imágenes DICOM de 16 bits/píxel "en la naturaleza"
  # que están comprimidas con JPEG sin pérdida y necesitan un manejo especial
  # porque el codificador produjo un desbordamiento de entero de 16 bits en el predictor
  # 6, que necesita ser compensado (reproducido) durante la descompresión.
  # Esta opción habilita una descompresión correcta de tales imágenes defectuosas, pero
  # al mismo tiempo causará una descompresión incorrecta de imágenes correctamente
  # comprimidas. Úsese con cuidado.
  +wi   --workaround-incpl
          habilita la solución de problemas para datos JPEG incompletos
  # Esta opción hace que dcm2img ignore los datos JPEG incompletos
  # al final de un fragmento comprimido y comience a descomprimir
  # el siguiente fotograma desde el siguiente fragmento (si lo hay). Esto permite
  # decodificar imágenes con datos JPEG incompletos.
  +wc   --workaround-cornell
          habilita la solución de problemas para imágenes JPEG sin pérdida de 16 bits
          de Cornell con desbordamiento en la tabla de Huffman
  # Una de las primeras implementaciones de código abierto de la compresión JPEG
  # sin pérdida, la biblioteca "Cornell", tiene un error conocido que conduce
  # a valores no válidos en la tabla de Huffman cuando se comprimen imágenes con 16 bits por muestra.
  # Esta opción habilita una solución de problemas que permite decodificar
  # correctamente tales imágenes.

REGISTR

O

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose también se reportan mensajes informativos como detalles de procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, p. ej. con fines de depuración. Otros niveles de registro pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se reportan errores fatales. En eventos de error tan graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, ver la documentación del módulo

"oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para parámetros: corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n

valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes se usa la aparición más a la derecha. Este comportamiento se conforma a las reglas de evaluación estándar de los shells Unix

comunes.

Además, uno o más archivos de comandos pueden especificarse usando un signo '@' como prefijo del nombre de archivo (p. ej. @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier evaluación posterior. Tener en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dcm2img intentará cargar diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows)

.

El comportamiento predeterminado debería preferirse y la variable de entorno DCMDICTPATH solo usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en la que dos puntos (":") separan entradas. En sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error s

i no se puede cargar nin
gún diccionario de datos.
