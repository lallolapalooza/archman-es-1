NOMBRE

dcmpssnd - Envío de red para el visor de estado de presentación

SINOPSIS

dcmpssnd [opciones] archivo-configuración objetivo estudio [serie] [instancia]

DESCRIPCIÓN

La aplicación dcmpssnd es invocada por el Visor de Estado de Presentación en Escala de Grises y no está destinada a ser invocada manualmente. La aplicación lee el archivo de configuración común que se comparte entre los diferentes componentes del visor, intenta establecer una asociación DICOM con el objetivo seleccionado y, si tiene éxito, selecciona las instancias DICOM requeridas de la base de datos del visor y las transmite utilizando el servicio de clase de almacenamiento DICOM, que es compatible como SCU. Cuando la transmisión finaliza (con éxito o sin él), la aplicación termina. Esta aplicación es compatible con las mismas clases SOP de almacenamiento que la utilidad storescu, pero no es compatible con sintaxis de transferencia encapsuladas. Consulte la declaración de conformidad completa para obtener más detalles.

PARÁMETROS

archivo-configuración  archivo de configuración a leer
objetivo               identificador simbólico del objetivo de envío en el archivo de configuración
estudio                UID de la instancia del estudio en la base de datos a enviar
serie                  UID de la instancia de la serie (por defecto: enviar estudio completo)
instancia              UID de la instancia SOP (por defecto: enviar serie completa)

REGISTRO

El nivel de salida de registro de las diversas herramientas de línea de comandos y las bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose, también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede ser utilizada para obtener más detalles sobre la actividad interna, por ejemplo, para fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet, solo se informan los errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos seguidos indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' al principio, respectivamente. Por lo general, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se puede especificar uno o más archivos de comando usando un signo '@' como prefijo del nombre del archivo (por ejemplo, @comando.txt). Dicho argumento de comando es reemplazado por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un único separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmpssnd intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (por defecto para Windows).

Se debe preferir el comportamiento por defecto y utilizar la variable de entorno DCMDICTPATH solo cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, de modo que dos puntos (":") separan las entradas. En sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
