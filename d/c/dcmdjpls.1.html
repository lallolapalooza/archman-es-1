REGISTR

O

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, p. ej. con fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, véase la documentación del módulo

"oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo inicial '+' o '-' respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los comunes shells

Unix.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (p. ej. @command.txt). Tal argumento de comando es reemplazado por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Téngase en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dcmdjpls intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si DCMDICTPATH

ENVIRONMENT

If the DCMDICTPATH environment variable is not set, the file <datadir>/dicom.dic will be loaded unless the dictionary is built into the application (default for Windows).

The default behavior should be preferred and the DCMDICTPATH environment variable only used when alternative data dictionaries are required. The DCMDICTPATH environment variable has the same format as the Unix shell PATH variable in that a colon (":") separates entries. On Windows systems, a semicolon (";") is used as a separator. The data dictionary code will attempt to load each file specified in the DCMDICTPATH environment variable. It is an error if no data dictionary can be loaded.
