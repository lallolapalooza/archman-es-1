NOMBRE

dcmdump - Volcar archivo y conjunto de datos DICOM

SINOPSIS

dcmdump [opciones] dcmfile-in...

DESCRIPCIÓN

La utilidad dcmdump vuelca el contenido de un archivo DICOM (formato de archivo o conjunto de datos sin procesar) a stdout en forma textual. Los atributos con campos de valor muy grandes (por ejemplo, datos de píxeles) pueden describirse como "(not loaded)". Los campos de valor de cadena se delimitarán con corchetes ([]). Los UID conocidos se mostrarán por sus nombres precedidos por un signo de igualdad (por ejemplo, "=MRImageStorage") a menos que este mapeo se desactive explícitamente. Los campos de valor vacíos se describen como "(no value available)".

Si dcmdump lee un conjunto de datos sin procesar (datos DICOM sin un metaencabezado de formato de archivo) intentará adivinar la sintaxis de transferencia examinando los primeros bytes del archivo. No siempre es posible adivinar correctamente la sintaxis de transferencia y es mejor convertir un conjunto de datos a un formato de archivo siempre que sea posible (utilizando la dcmconv utilidad). También es posible usar las opciones -f y -t[ieb] para forzar a dcmdump a leer un conjunto de datos con una sintaxis de transferencia en particular.

PARÁMETROS

dcmfile-in  Archivo de entrada DICOM o directorio a volcar ("-" para stdin)

OPCIONES

opciones generales

  -h   --help
         imprime este texto de ayuda y sale
       --version
         imprime información de versión y sale
       --arguments
         imprime los argumentos de la línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprime advertencias ni errores
  -v   --verbose
         modo detallado, imprime detalles del procesamiento
  -d   --debug
         modo depuración, imprime información de depuración
  -ll  --log-level  [l]evel: constante de cadena
         (fatal, error, warn, info, debug, trace)
         usa el nivel l para el registrador
  -lc  --log-config  [f]ilename: cadena
         usa el archivo de configuración f para el registrador

opciones de entrada

formato de archivo de entrada:
  +f   --read-file
         lee formato de archivo o conjunto de datos (predeterminado)
  +fo  --read-file-only
         lee solo formato de archivo
  -f   --read-dataset
         lee conjunto de datos sin meta-información de archivo
sintaxis de transferencia de entrada:
  -t=  --read-xfer-auto
         usa reconocimiento de sintaxis de transferencia (predeterminado)
  -td  --read-xfer-detect
         ignora la sintaxis de transferencia especificada en el metaencabezado del archivo
  -te  --read-xfer-little
         lee con sintaxis de transferencia de VR explícito little endian
  -tb  --read-xfer-big
         lee con sintaxis de transferencia de VR explícito big endian
  -ti  --read-xfer-implicit
         lee con sintaxis de transferencia de VR implícito little endian
archivos de entrada:
  +sd  --scan-directories
         escanea directorios en busca de archivos de entrada (dcmfile-in)
  +sp  --scan-pattern  [p]attern: cadena (solo con --scan-directories)
         patrón para coincidencia de nombres de archivo (comodines)
         # posiblemente no disponible en todos los sistemas
  -r   --no-recurse
         no recursa dentro de los directorios (predeterminado)
  +r   --recurse
         recursa dentro de los directorios especificados
valores de etiqueta largos:
  +M   --load-all
         carga valores de etiqueta muy largos (predeterminado)
  -M   --load-short
         no carga valores muy largos (por ejemplo, datos de píxeles)
  +R   --max-read-length  [k]bytes: entero (4..4194302, predeterminado: 4)
         establece el umbral para valores largos en k kbytes
análisis de meta-información de archivo:
  +ml  --use-meta-length
         usa la longitud del grupo de meta-información de archivo (predeterminado)
  -ml  --ignore-meta-length
         ignora la longitud del grupo de meta-información de archivo
análisis de atributos de longitud impar:
  +ao  --accept-odd-length
         acepta atributos de longitud impar (predeterminado)
  +ae  --assume-even-length
         asume que la longitud real es un byte mayor
manejo de VR explícito:
  +ev  --use-explicit-vr
         usa el VR explícito del conjunto de datos (predeterminado)
  -ev  --ignore-explicit-vr
         ignora el VR explícito (prefiere el diccionario de datos)
manejo de VR no estándar:
  +vr  --treat-as-unknown
         trata el VR no estándar como desconocido (predeterminado)
  -vr  --assume-implicit
         intenta leer con sintaxis de transferencia de VR implícito little endian
manejo de elementos UN de longitud indefinida:
  +ui  --enable-cp246
         lee UN de longitud indefinida como VR implícito (predeterminado)
  -ui  --disable-cp246
         lee UN de longitud indefinida como VR explícito
manejo de elementos UN de longitud definida:
  -uc  --retain-un
         retiene los elementos como UN (predeterminado)
  +uc  --convert-un
         convierte al VR real si se conoce
manejo de elementos privados de longitud máxima (VR implícito):
  -sq  --maxlength-dict
         lee como está definido en el diccionario (predeterminado)
  +sq  --maxlength-seq
         lee como secuencia con longitud indefinida
manejo de elementos de delimitación incorrectos:
  -rd  --use-delim-items
         usa los elementos de delimitación del conjunto de datos (predeterminado)
  +rd  --replace-wrong-delim
         reemplaza los elementos de delimitación de secuencia/elemento incorrectos
manejo de elementos OB/OW ilegales de longitud indefinida:
  -oi  --illegal-obow-rej
         rechaza el conjunto de datos con elemento ilegal (predeterminado)
  +oi  --illegal-obow-conv
         convierte el elemento OB/OW de longitud indefinida a SQ
manejo de la secuencia VOI LUT con VR OW y longitud explícita:
  -vi  --illegal-voi-rej
         rechaza el conjunto de datos con VOI LUT ilegal (predeterminado)
  +vi  --illegal-voi-conv
         convierte el VOI LUT ilegal a SQ
manejo de datos de píxeles de longitud explícita para sintaxis de transferencia encapsuladas:
  -pe  --abort-expl-pixdata
         aborta en datos de píxeles de longitud explícita (predeterminado)
  +pe  --use-expl-pixdata
         usa datos de píxeles de longitud explícita
manejo general de errores del analizador:
  +Ep  --ignore-parse-errors
         intenta recuperarse de errores de análisis
  -Ep  --handle-parse-errors
         maneja los errores de análisis y detiene el análisis (predeterminado)
otras opciones de análisis:
  +st  --stop-after-elem  [t]ag: "gggg,eeee" o nombre del diccionario
         detiene el análisis después del elemento especificado por t
  +sb  --stop-before-elem [t]ag: "gggg,eeee" o nombre del diccionario
         detiene el análisis antes del elemento especificado por t
         # solo considera elementos en el nivel del conjunto de datos principal y también
         # funciona si la etiqueta dada no está presente en el archivo
corrección automática de datos:
  +dc  --enable-correction
         habilita la corrección automática de datos (predeterminado)
  -dc  --disable-correction
         deshabilita la corrección automática de datos
formato de flujo de bits de entrada descomprimida:
  +bd  --bitstream-deflated
         espera flujo de bits descomprimido (predeterminado)
  +bz  --bitstream-zlib
         espera flujo de bits zlib descomprimido

opciones de procesamiento

juego de caracteres específico:
  +U8  --convert-to-utf8
         convierte todos los valores de elemento afectados
         por el Juego de Caracteres Específico (0008,0005) a UTF-8
         # requiere soporte de una biblioteca de codificación de caracteres subyacente
         # (ver la salida de --version para saber cuál está disponible)

opciones de salida

impresión:
  +L   --print-all
         imprime los valores de etiqueta largos completamente
  -L   --print-short
         imprime los valores de etiqueta largos acortados (predeterminado)
  +T   --print-tree
         imprime la estructura jerárquica como un árbol simple
  -T   --print-indented
         imprime la estructura jerárquica con sangría (predeterminado)
  +F   --print-filename
         imprime una cabecera con el nombre de archivo para cada archivo de entrada
  +Fs  --print-file-search
         imprime una cabecera con el nombre de archivo solo para aquellos archivos de entrada
         que contienen una de las etiquetas buscadas
mapeo:
  +Un  --map-uid-names
         mapea números de UID bien conocidos a nombres (predeterminado)
  -Un  --no-uid-names
         no mapea números de UID bien conocidos a nombres
entrecomillado:
  +Qn  --quote-nonascii
         entrecomilla caracteres no ASCII y de control como marcado XML
  +Qo  --quote-as-octal
         entrecomilla caracteres no ASCII y de control como números octales
  -Qn  --print-nonascii
         imprime caracteres no ASCII y de control (predeterminado)
color:
  +C   --print-color
         usa códigos de escape ANSI para salida con color
  -C   --no-color
         no usa ningún código de escape ANSI (predeterminado)
manejo de errores:
  -E   --stop-on-error
         no imprime si el archivo está dañado (predeterminado)
  +E   --ignore-errors
         intenta imprimir incluso si el archivo está dañado
búsqueda:
  +P   --search  [t]ag: "gggg,eeee" o nombre del diccionario
         imprime el volcado textual de la etiqueta t
         esta opción se puede especificar varias veces
         (predeterminado: se imprime el archivo completo)
  +s   --search-all
         imprime todas las instancias de las etiquetas buscadas (predeterminado)
  -s   --search-first
         solo imprime la primera instancia de las etiquetas buscadas
  +p   --prepend
         antepone la jerarquía de secuencia a la etiqueta impresa,
         denotada por: (gggg,eeee).(gggg,eeee).*
         (solo cuando se usa con --search)
  -p   --no-prepend
         no antepone la jerarquía a la etiqueta (predeterminado)
escritura:
  +W   --write-pixel  [d]irectory: cadena
         escribe los datos de píxeles en un archivo .raw almacenado en d
         (little endian, nombre de archivo creado automáticamente)

NOTAS

Agregar directorios como un parámetro para la línea de comandos solo tiene sentido si la opción --scan-directories también se proporciona. Si los archivos en los directorios proporcionados deben seleccionarse según un patrón de nombre específico (por ejemplo, usando coincidencia de comodines), se debe usar la opción --scan-pattern . Tenga en cuenta que este patrón de archivos solo se aplica a los archivos dentro de los directorios escaneados y, si se especifican otros patrones en la línea de comandos fuera de la opción --scan-pattern (por ejemplo, para seleccionar archivos adicionales), estos no se aplican a los directorios especificados.

REGISTRO (LOGGING)

El nivel de salida de registro de las diversas herramientas de línea de comandos y las bibliotecas subyacentes puede ser especificado por el usuario. De forma predeterminada, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config . Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos suspensivos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Por lo general, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmdump intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . De forma predeterminada, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.

Dependiendo de las opciones de línea de comandos especificadas, la utilidad dcmdump intentará cargar tablas de asignación de conjuntos de caracteres. Esto ocurre cuando DCMTK se compiló con la biblioteca oficonv (que es la predeterminada) y las tablas de asignación no están compiladas en la biblioteca (predeterminado cuando DCMTK usa bibliotecas compartidas).

Se espera que los archivos de tablas de asignación estén en el <datadir>de DCMTK. La variable de entorno DCMICONVPATH se puede usar para especificar una ubicación diferente. Si se especifica una ubicación diferente, esas tablas de asignación también reemplazan cualquier tabla integrada.
