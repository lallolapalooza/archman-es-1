NOMBRE

dcmpsrcv - Recepción de red para el visor de estado de presentación

SINOPSIS

dcmpsrcv [opciones] archivo-config

DESCRIPCIÓN

La aplicación dcmpsrcv es invocada por el Visor de Estado de Presentación de Escala de Grises y no está destinada a ser invocada manualmente. La aplicación lee el archivo de configuración común que se comparte entre los diferentes componentes del visor y abre un socket TCP/IP en el que se aceptan las solicitudes de asociación entrantes. La aplicación inicia un proceso separado para cada conexión DICOM. Admite las mismas clases SOP de almacenamiento que la utilidad storescp como SCP, pero no admite sintaxis de transferencia encapsuladas. Las imágenes entrantes se almacenan en la base de datos común del visor. Consulte la declaración de conformidad completa para obtener más detalles.

PARÁMETROS

archivo-config  archivo de configuración a leer

OPCIONES

Opciones generales

  -h   --help
         imprime este texto de ayuda y sale
       --version
         imprime información de la versión y sale
       --arguments
         imprime los argumentos de la línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprime advertencias ni errores
  -v   --verbose
         modo detallado, imprime detalles del procesamiento
  -d   --debug
         modo de depuración, imprime información de depuración
  -ll  --log-level  [n]ivel: cadena de caracteres
         (fatal, error, warn, info, debug, trace)
         usa el nivel n para el registrador
  -lc  --log-config  [a]rchivo: cadena de caracteres
         usa el archivo de configuración a para el registrador
  -t   --terminate
         termina todos los receptores en ejecución

REGISTRO

El nivel de salida del registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En modo --quiet solo se informan los errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida del registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos suspensivos al final indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Por lo general, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se puede especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre del archivo (por ejemplo, @comando.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador, a menos que aparezcan entre comillas dobles) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmpsrcv intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté incorporado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo se debe usar cuando se requieren diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, de modo que los dos puntos (":") separan las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
