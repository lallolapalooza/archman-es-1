NOMBRE

dcmconv - Convertir la codificación de un archivo DICOM

SINOPSIS

dcmconv [opciones] dcmfile-in dcmfile-out

DESCRIPCIÓN

La utilidad dcmconv lee un archivo DICOM (dcmfile-in), realiza una conversión de codificación y escribe los datos convertidos en un archivo de salida (dcmfile-out).

PARÁMETROS

dcmfile-in   Nombre del archivo DICOM de entrada a convertir ("-" para stdin)
dcmfile-out  Nombre del archivo DICOM de salida donde escribir ("-" para stdout)

OPCIONES

opciones generales

  -h   --help
         imprimir este texto de ayuda y salir
       --version
         imprimir información de la versión y salir
       --arguments
         imprimir los argumentos de la línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprimir advertencias ni errores
  -v   --verbose
         modo detallado, imprimir detalles del procesamiento
  -d   --debug
         modo de depuración, imprimir información de depuración
  -l   --log-level  [l]evel: constante de cadena
         (fatal, error, warn, info, debug, trace)
         usar el nivel l para el registrador
  -l   --log-config  [f]ilename: cadena
         usar el archivo de configuración f para el registrador

opciones de entrada

formato del archivo de entrada:
  +f   --read-file
         leer el formato del archivo o el conjunto de datos (predeterminado)
  +fo  --read-file-only
         leer solo el formato del archivo
  -f   --read-dataset
         leer el conjunto de datos sin la meta-información del archivo
sintaxis de transferencia de entrada:
  -t=  --read-xfer-auto
         usar el reconocimiento de ST (predeterminado)
  -td  --read-xfer-detect
         ignorar la ST especificada en la cabecera de meta-información del archivo
  -te  --read-xfer-little
         leer con la sintaxis de transferencia de VR explícito little endian
  -tb  --read-xfer-big
         leer con la sintaxis de transferencia de VR explícito big endian
  -ti  --read-xfer-implicit
         leer con la sintaxis de transferencia de VR implícito little endian
análisis de la meta-información del archivo:
  +ml  --use-meta-length
         usar la longitud del grupo de meta-información del archivo (predeterminado)
  -ml  --ignore-meta-length
         ignorar la longitud del grupo de meta-información del archivo
análisis de atributos de longitud impar:
  +ao  --accept-odd-length
         aceptar atributos de longitud impar (predeterminado)
  +ae  --assume-even-length
         asumir que la longitud real es un byte mayor
manejo de VR explícito:
  +ev  --use-explicit-vr
         usar el VR explícito del conjunto de datos (predeterminado)
  -ev  --ignore-explicit-vr
         ignorar el VR explícito (preferir el diccionario de datos)
manejo de VR no estándar:
  +vr  --treat-as-unknown
         tratar el VR no estándar como desconocido (predeterminado)
  -vr  --assume-implicit
         intentar leer con la sintaxis de transferencia de VR implícito little endian
manejo de elementos UN de longitud indefinida:
  +ui  --enable-cp246
         leer UN de longitud indefinida como VR implícito (predeterminado)
  -ui  --disable-cp246
         leer UN de longitud indefinida como VR explícito
manejo de elementos UN de longitud definida:
  -uc  --retain-un
         retener los elementos como UN (predeterminado)
  +uc  --convert-un
         convertir al VR real si se conoce
manejo de elementos privados de longitud máxima (VR implícito):
  -sq  --maxlength-dict
         leer como está definido en el diccionario (predeterminado)
  +sq  --maxlength-seq
         leer como secuencia con longitud indefinida
manejo de elementos delimitadores incorrectos:
  -rd  --use-delim-items
         usar los elementos delimitadores del conjunto de datos (predeterminado)
  +rd  --replace-wrong-delim
         reemplazar los elementos delimitadores de secuencia/elemento incorrectos
manejo de elementos OB/OW ilegales de longitud indefinida:
  -oi  --illegal-obow-rej
         rechazar el conjunto de datos con un elemento ilegal (predeterminado)
  +oi  --illegal-obow-conv
         convertir el elemento OB/OW de longitud indefinida a SQ
manejo de la secuencia VOI LUT con VR OW y longitud explícita:
  -vi  --illegal-voi-rej
         rechazar el conjunto de datos con un VOI LUT ilegal (predeterminado)
  +vi  --illegal-voi-conv
         convertir el VOI LUT ilegal a SQ
manejo de datos de píxeles de longitud explícita para sintaxis de transferencia encapsuladas:
  -pe  --abort-expl-pixdata
         abortar en datos de píxeles de longitud explícita (predeterminado)
  +pe  --use-expl-pixdata
         usar datos de píxeles de longitud explícita
manejo general de errores de análisis:
  +Ep  --ignore-parse-errors
         intentar recuperarse de los errores de análisis
  -Ep  --handle-parse-errors
         manejar los errores de análisis y detener el análisis (predeterminado)
otras opciones de análisis:
  +st  --stop-after-elem  [t]ag: "gggg,eeee" o nombre del diccionario
         detener el análisis después del elemento especificado por t
corrección automática de datos:
  +dc  --enable-correction
         habilitar la corrección automática de datos (predeterminado)
  -dc  --disable-correction
         deshabilitar la corrección automática de datos
formato de flujo de bits de entrada comprimida:
  +bd  --bitstream-deflated
         esperar un flujo de bits comprimido (predeterminado)
  +bz  --bitstream-zlib
         esperar un flujo de bits zlib comprimido

opciones de procesamiento

juego de caracteres específico:
  # las siguientes opciones requieren soporte de una biblioteca de codificación
  # de caracteres subyacente (ver la salida de --version para saber cuál está disponible)
  +U8  --convert-to-utf8
         convertir todos los valores de elementos afectados por
         Juego de Caracteres Específico (0008,0005) a UTF-8
  +L1  --convert-to-latin1
         convertir los valores de elementos afectados a ISO 8859-1
  +A7  --convert-to-ascii
         convertir los valores de elementos afectados a ASCII de 7 bits
  +C   --convert-to-charset  [c]harset: cadena
         convertir los valores de elementos afectados al juego de caracteres
         especificado por el término definido por DICOM c
  -Ct  --transliterate
         intentar aproximar los caracteres que no pueden ser representados
         mediante caracteres de apariencia similar
  -Cd  --discard-illegal
         descartar los caracteres que no pueden ser representados
         en el juego de caracteres de destino
otras opciones de procesamiento:
  -ig  --no-invalid-groups
         eliminar los elementos con un número de grupo no válido

opciones de salida

formato del archivo de salida:
  +Fm  --write-new-meta-info
         escribir el formato de archivo con nueva meta-información (predeterminado)
  +F   --write-file
         escribir el formato de archivo
  -F   --write-dataset
         escribir el conjunto de datos sin la meta-información del archivo
sintaxis de transferencia de salida:
  +t=  --write-xfer-same
         escribir con la misma ST que la entrada (predeterminado)
  +te  --write-xfer-little
         escribir con la sintaxis de transferencia de VR explícito little endian
  +tb  --write-xfer-big
         escribir con la sintaxis de transferencia de VR explícito big endian
  +ti  --write-xfer-implicit
         escribir con la sintaxis de transferencia de VR implícito little endian
  +td  --write-xfer-deflated
         escribir con la sintaxis de transferencia de VR explícito little endian comprimida
  +tg  --write-xfer-ge
         escribir la sintaxis de transferencia privada de GE VR implícito little endian
         con datos de píxeles big endian (no estándar)
representaciones de valor posteriores a 1993:
  +u   --enable-new-vr
         habilitar el soporte para nuevos VR (UN/UT) (predeterminado)
  -u   --disable-new-vr
         deshabilitar el soporte para nuevos VR, convertir a OB
codificación de longitud de grupo:
  +g=  --group-length-recalc
         recalcular las longitudes de grupo si están presentes (predeterminado)
  +g   --group-length-create
         escribir siempre con elementos de longitud de grupo
  -g   --group-length-remove
         escribir siempre sin elementos de longitud de grupo
codificación de longitud en secuencias y elementos:
  +e   --length-explicit
         escribir con longitudes explícitas (predeterminado)
  -e   --length-undefined
         escribir con longitudes indefinidas
  +eo  --write-oversized
         escribir secuencias y elementos de longitud explícita sobredimensionados
         con longitud indefinida (predeterminado)
  -eo  --abort-oversized
         abortar en secuencias/elementos explícitos sobredimensionados
relleno al final del conjunto de datos (no con --write-dataset):
  -p=  --padding-retain
         no cambiar el relleno (predeterminado si no se usa --write-dataset)
  -p   --padding-off
         sin relleno (implícito si se usa --write-dataset)
  +p   --padding-create  [f]ile-pad [i]tem-pad: entero
         alinear el archivo a un múltiplo de f bytes
         y los elementos a un múltiplo de i bytes
nivel de compresión deflate (solo con --write-xfer-deflated):
  +cl  --compression-level  [l]evel: entero (predeterminado: 6)
         0=sin comprimir, 1=lo más rápido, 9=la mejor compresión

REGISTRO

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como los detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config . Este archivo de configuración tambiénpermite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Generalmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos utilizando un signo '@' como prefijo del nombre del archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

El dcmconv utilidad intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado en Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo se debe usar cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en la que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.

Dependiendo de las opciones de la línea de comandos especificadas, el dcmconv utilidad intentará cargar tablas de asignación de conjuntos de caracteres. Esto ocurre cuando DCMTK se compiló con la biblioteca oficonv (que es la predeterminada) y las tablas de asignación no están integradas en la biblioteca (predeterminado cuando DCMTK usa bibliotecas compartidas).

Se espera que los archivos de tablas de asignación estén en <datadir>de DCMTK. La variable de entorno DCMICONVPATH se puede usar para especificar una ubicación diferente. Si se especifica una ubicación diferente, esas tablas de asignación también reemplazan cualquier tabla integrada.
