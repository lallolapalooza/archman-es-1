NOMBRE

dcmp2pgm - Lee una imagen DICOM y un estado de presentación y renderiza un mapa de bits

SINOPSIS

dcmp2pgm [opciones] dcmimage-in [bitmap-out]

DESCRIPCIÓN

La utilidad dcmp2pgm renderiza una imagen DICOM monocroma bajo el control de un objeto de estado de presentación de copia suave en escala de grises en un mapa de bits monocromo con 8 bits/píxel. El mapa de bits se almacena ya sea como "Portable Gray Map" (PGM) o como un objeto de imagen de captura secundaria DICOM. Si no se lee ningún estado de presentación desde un archivo, se crea un estado de presentación predeterminado. La utilidad permite leer un archivo de configuración del Visor de Estados de Presentación de Copia Suave durante el inicio. En este caso, se utilizan las configuraciones del archivo de configuración que afectan la representación del estado de presentación, por ejemplo, se puede realizar una corrección del rango de escala de grises de acuerdo con el modelo de Barten (DICOM parte 14) si la curva característica del sistema de visualización está disponible y definida en el archivo de configuración.

PARÁMETROS

dcmimage-in  imagen DICOM de entrada ("-" para stdin)
bitmap-out   imagen DICOM de salida o mapa de bits PGM

OPCIONES

opciones generales

  -h   --help
         imprime este texto de ayuda y sale
       --version
         imprime información de la versión y sale
       --arguments
         imprime los argumentos de la línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprime advertencias ni errores
  -v   --verbose
         modo detallado, imprime detalles del procesamiento
  -d   --debug
         modo de depuración, imprime información de depuración
  -ll  --log-level  [l]evel: constante de cadena
         (fatal, error, warn, info, debug, trace)
         usa el nivel l para el registrador
  -lc  --log-config  [f]ilename: cadena
         usa el archivo de configuración f para el registrador

opciones de procesamiento

  -p   --pstate  [f]ilename: cadena
         procesa usando el archivo de estado de presentación
  -c   --config  [f]ilename: cadena
         procesa usando la configuración del archivo de configuración
  -f   --frame  [f]rame: entero
         procesa usando el fotograma f de la imagen (predeterminado: 1)

formato de salida

  -D   --pgm
         guarda la imagen como PGM (predeterminado)
  +D   --dicom
         guarda la imagen como captura secundaria DICOM

opciones de salida

  +S   --save-pstate  [f]ilename: cadena
         guarda el estado de presentación en un archivo

NOTAS

Limitaciones

Tenga en cuenta que la herramienta dcmp2pgm no renderiza todos los aspectos definidos por el objeto de Estado de Presentación de Copia Suave en Escala de Grises (GSPS), sino solo aquellos que son soportados por las clases DCMTK subyacentes. En particular, las anotaciones textuales y gráficas no serán visibles en la imagen de salida. La razón es que estos aspectos de un objeto GSPS son típicamente renderizados por DICOMscope, la interfaz gráfica de usuario que se coloca sobre las clases DCMTK relacionadas y está escrita en Java.

También se ignoran los conceptos que se introdujeron después de la definición inicial del IOD de GSPS (ver Suplemento 33). Esto incluye el Suplemento 120 con sus características extendidas como, por ejemplo, Gráficos Compuestos.

REGISTRO

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config . Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basados en el módulo o la aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comando usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando es reemplazado por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmp2pgm intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH . Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En los sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH . Es un error si no se puede cargar ningún diccionario de datos.
