NOTAS

La utilidad dcmcjpeg comprime imágenes DICOM de todas las clases SOP. Procesa todos los elementos de Datos de Píxeles (7fe0,0010) en el conjunto de datos, es decir, la compresión también se realiza en una imagen de icono. Se ha implementado un manejo especial para imágenes CT (donde la transformación de modalidad es requerida para crear unidades Hounsfield) y las clases SOP XA/RF/Biplano (donde la transformación de modalidad tiene semántica "invertida"). Sin embargo, dcmcjpeg no intenta asegurar que la imagen comprimida aún cumpla con todas las restricciones del IOD del objeto.

Algunos ejemplos:

  • Las imágenes MR requieren BitsAllocated=16.
  • Las imágenes NM solo pueden codificarse con interpretación fotométrica MONOCHROME2 o PALETTE COLOR pero no con RGB o YBR_FULL (lo que efectivamente impide la compresión).
  • Las imágenes Hardcopy Color deben tener un modelo de color RGB, lo que es un problema si se va a realizar compresión con pérdida.

El usuario es responsable de asegurarse de que las imágenes comprimidas que crea cumplen con el estándar DICOM. En caso de duda, la utilidad dcmcjpeg permite convertir una imagen a captura secundaria - esta clase SOP no presenta restricciones como las mencionadas anteriormente.

Con la versión DCMTK 3.5.4 se agregó un nuevo codificador para compresión JPEG verdaderamente sin pérdida (--true-lossless). Comparado con el codificador antiguo (--pseudo-lossless), que crea imágenes ligeramente con pérdida causadas por conversiones internas de espacio de color, ventanas, etc., hay algunos puntos a considerar:

  • Solo se admiten imágenes de origen con Bits Allocados 8 o 16.
  • Las opciones para conversiones de espacio de color, ventanas o escalado de píxeles se ignoran o anulan.
  • Las Interpretaciones Fotométricas YBR_FULL_422, YBR_PARTIAL_422, YBR_PARTIAL_420, YBR_ICT, YBR_RCT no son compatibles.
  • El codificador cambia automáticamente la Configuración del Plan de 1 a 0 si es necesario.
  • La relación de compresión puede ser menor que en el modo --pseudo-lossless.

Sin embargo, al usar el nuevo codificador (predeterminado), puede estar seguro de que la compresión no afecta la calidad de la imagen.

Para estar seguro, el Indicador de Compresión con Pérdida siempre se establece en "01" y se asigna un nuevo UID de instancia SOP (por defecto) para el antiguo codificador pseudo-sin pérdida. La salida del codificador sin pérdida antiguo y nuevo también se puede distinguir por la Descripción de Derivación en la imagen DICOM resultante, que contiene el término "Compresión JPEG sin pérdida" para el nuevo y "Compresión JPEG Pseudo-Sin Pérdida" para el codificador antiguo.

REGISTRO DE

EVENTOS

El nivel de registro de eventos de las diversas herramientas de línea de comandos y las bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como los detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo

"oflog".

En caso de que la salida del registro de eventos deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), puede usarse la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix

comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dcmcjpeg intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está definida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows)

.

Se debe preferir el comportamiento por defecto y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en la que un dos puntos (":") separa las entradas. En sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede

cargar ningún dicci
onario de datos.
