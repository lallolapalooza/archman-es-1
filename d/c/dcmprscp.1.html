DESCRIPCIÓ

N

La utilidad dcmprscp implementa la Clase de Servicio de Gestión de Impresión en Escala de Grises Básica DICOM como SCP. También admite la Clase SOP de LUT de Presentación opcional. La utilidad está destinada a su uso dentro del visor

DICOMscope.

La utilidad dcmprscp acepta trabajos de impresión de un Print SCU remoto. No crea copias físicas reales, sino que almacena los trabajos de impresión en la base de datos local de DICOMscope como un conjunto de objetos Stored Print (uno por página) e imágenes Hardcopy Grayscale (uno por N-SET de film box). La aplicación DICOMscope permite cargar un objeto Stored Print creado por dcmprscp y renderizar una vista previa en pantalla de la copia física. La utilidad dcmprscp lee las características de la impreso

ra a emular desde el ar
chivo de configuración.

REGISTR

O

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro pueden seleccionarse usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo

"oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), puede usarse la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se conforma a las reglas de evaluación estándar de los shells Unix

comunes.

Además, uno o más archivos de comandos pueden especificarse usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando es reemplazado por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier evaluación posterior. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dcmprscp intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está definida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows)

.

Se debe preferir el comportamiento predeterminado y usar la variable de entorno DCMDICTPATH solo cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un signo de dos puntos (":") separa las entradas. En sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se pued

e cargar ningún di
ccionario de datos.
