DESCRIPCIÓ

N

dcmodify es una herramienta que permite modificar, insertar y eliminar etiquetas y elementos en archivos DICOM. También se admiten secuencias y etiquetas con multiplicidad de valor > 1. La información del metaencabezado y la VR de la etiqueta no pueden modificarse directamente con dcmodify en este momento. Además de las modificaciones de etiquetas, dcmodify pone a disposición algunas opciones de entrada - forzando a dcmodify a manejar sus archivos de entrada como el usuario especifica - y opciones de salida para controlar el formato de salida de los archivos

resultantes.

En caso de que deban realizarse múltiples modificaciones, dcmodify realiza las modificaciones en el mismo orden en que aparecen en la línea de comandos. Tenga en cuenta que dcmodify no comprueba si un valor dado coincide con su representación de valor (VR). Generalmente se imprime un mensaje de error, pero en general el usuario debe cuidar el uso correcto de la

VR.

Si dcmodify no conoce la etiqueta que debe insertar, entonces la VR de la etiqueta se establece en UN y el valor proporcionado en la línea de comandos se interpreta como una serie de números hexadecimales (como se proporcionan para VR=OB). Por favor, inserte estas etiquetas en el diccionario para evitar este comportamiento. También, especificando la opción -iun, es posible forzar a dcmodify a dejar los valores UN intactos. Usando la opción -u hace que dcmodify guarde todos los atributos VR=UN como

OB.

dcmodify es capaz de trabajar con los llamados rutas de etiquetas para acceder a etiquetas en secuencias. La sintaxis (pseudo-formalizada)

es 
{sequence[item-no].}
*element

donde 'sequence' es una etiqueta de secuencia como (0008,1111) o un nombre de diccionario para una etiqueta. 'item-no' describe el número de elemento a acceder (contando desde cero). 'element' define la etiqueta objetivo con la que trabajar. Una etiqueta puede especificarse directamente como (0010,0010) o a través del nombre de diccionario correspondiente "PatientName". El '' denota que puede repetir las declaraciones de secuencia para acceder a niveles más profundos en archivos DICOM (vea la sección EJEMPLOS). Para 'item-no', también se puede usar un carácter comodín '' que selecciona todos los elementos en la secuencia circundante (vea la sección COMODINES más abajo)

.

Al insertar rutas de etiquetas que consisten en múltiples nodos (es decir, no un solo elemento) usando la opción -i, cualquier elemento de ruta faltante (elementos, secuencias, elementos hoja) se inserta automáticamente cuando falta. Eso no funciona con comodines de elementos: cuando no existe un solo elemento en la secuencia circundante dcmodify por supuesto no puede decidir cuántos elementos deben generarse. Sin embargo, si se especifica un número de elemento como '5', los 6 elementos (contados desde cero) pueden (y son) generados automáticamente en modo inserción. Si ya existieran 2 elementos, el resto (4) se

insertaría.

dcmodify no trabaja en directorios, es decir, el parámetro dcmfile-in... no debe incluir nombres de

directorios.

Tenga en cuenta que existen algunos problemas relacionados con

la modificación de etiquetas privadas (vea la sección ETIQ
UETAS PRIVADAS) y para cambiar UIDs (sección CAMBIAR UIDs).

ETIQUETAS

PRIVADAS

Hay algunos problemas que debe considerar al trabajar con etiquetas privadas. Sin embargo, la inserción oLa modificación de una etiqueta de reserva (gggg,00xx) siempre debe

funcionar.

Insercione

s

Si desea insertar una etiqueta privada (no una reserva con gggg,00xx), asegúrese de haberla listado en su diccionario (véase <docdir>/datadict.txt para más detalles). Si no está listada, dcmodify la insertará con VR=UN. Además, en algunos casos la inserción puede fallar para ciertos

valores.

Si tiene su etiqueta privada en el diccionario, dcmodify actúa de la siguiente manera: cuando encuentra una reserva en el conjunto de datos que contiene la etiqueta, cuyo creador privado coincide, la inserción se realiza con el VR encontrado en el diccionario y el valor dado en la línea de comandos. Pero si el creador privado no coincide o no está establecido, dcmodify devolverá un error. Si una etiqueta privada debe insertarse independientemente de que no exista una reserva, se puede usar la opción -nrc, forzando una inserción. Sin embargo, el VR se establece entonces en UN, porque la etiqueta no se puede encontrar en el

diccionario.

Véase la descripción anterior sobre có

mo se manejan las inserciones de valore
s en elementos con VR desconocido.

Modificacione

s

Si modifica el valor de una etiqueta privada, dcmodify no comprobará su VR contra el diccionario. Por lo tanto, tenga cuidado de introducir solo valores que coincidan con el VR de la

etiqueta.

Si desea cambiar el valor de una etiqueta privada y su VR, porque acaba de añadir esta etiqueta a su diccionario, puede eliminarla con dcmodify y volver a insertarla. Entonces dcmodify usará su entrada del diccionario para determinar el VR correcto (véase también la subsección inserciones)

.

También, véase la descripción anterior so

bre cómo se manejan las inserciones de val
ores en elementos con VR desconocido.

Eliminacione

s

Cuando use dcmodify para eliminar una etiqueta de reserva privada, tenga en cuenta que dcmodify no tocará las etiquetas privadas que están bajo esta reserva. El usuario debe garantizar la coherencia entre las reservas y sus etiquetas privadas

asociadas.

Para la eliminación de e

tiquetas privadas que no
son de reserva no hay
problemas especiales.

CAMBIANDO

UIDS

dcmodify corregirá automáticamente 'Media Storage SOP Class UID' y 'Media Storage SOP Instance UID' en el metaencabezado, si usted realiza cambios en las etiquetas relacionadas en el conjunto de datos ('SOP Class UID' y 'SOP Instance UID') mediante las opciones de modo de inserción o modificación. Puede desactivar este comportamiento usando la opción -nmu

.

Si genera nuevos UID con -gst, -gse o -gin, esto solo afectará al UID que eligió generar. Así que si usa -gst para generar un nuevo 'Study Instance UID', ¡entonces 'Series Instance UID' y 'SOP Instance UID' no se verán afectados! Esto le da la posibilidad de generar cada valor por separado. Normalmente, también modificaría los UID 'subyacentes'. Como desventaja de esta flexibilidad, el usuario debe asegurarse de que, al crear archivos DICOM 'nuevos' con nuevos UID con dcmodify, otros UID deben ser actualizados por el usuario según sea

necesario.

Al elegir la opción -gin, la etiqueta de metaencabezado relacionada ('Media Storage SOP Instance UID') se actualiza automáticamente. Este comportamiento no se puede

desactivar.

Al trabajar con múltiples archivos de entrada, dcmodify procesa cada archivo de forma aislada, es decir, generará UID para cada archivo individual. Por ejemplo, al usar la opción -gst, dcmodify insertará un Study Instance UID diferente en cada archivo en luga

r de generar uno solo y escribirlo
en cada archivo que se está procesando.

CREANDO ARCHIVOS

NUEVOS

La opción --create-file permite que dcmodify cree un archivo si aún no existe en el disco. Esto se puede usar para crear archivos desde cero realizando inserciones consecutivas con opciones como --insert. Esto puede ser especialmente útil al crear archivos de consulta para herramientas como findscu o movescu. En caso de que no se defina una sintaxis de transferencia de salida específica, dcmodify elige Little Endian Explicit Uncompressed para la salida. Los archivos que se crean nuevos siempre se escriben en formato de archivo DICOM, es decir, la opción --write-dataset no está permitida junto con --create. De esta manera, al menos el metaencabezado se escribe y no se crea un archivo con longitud de cero bytes en el caso de que no se realicen inserciones en la llamada a dcmo

dif
y.

VALORES DE ELEMENTOS DESDE UN

ARCHIVO

Para leer el valor de un elemento desde un archivo en lugar de especificarlo en la línea de comandos, se puede usar la opción -mf y -if. Tenga en cuenta que para los elementos OW, se espera que los datos estén en orden little endian y se intercambiarán si

es necesario. El tamaño del archivo siempre debe ser un númer
o par de bytes, es decir, no se realiza un relleno automático.

COMODINE

S

dcmodify también permite el uso del carácter comodín "*" para números de ítem en expresiones de ruta, por ejemplo "ContentSequence[*].CodeValue" selecciona todos los atributos "Code Value" en todos los ítems de la ContentSequence. El uso de un comodín es posible para todas las operaciones básicas, es decir, modificando -m, insertando -i y -e, lo que la convierte, junto con la creación automática de nodos de ruta intermedios, en una herramienta poderosa para la construcción y el procesamiento de conjuntos de datos

complejos.

Las opciones -ma y -ea para modificar o eliminar todas las ocurrencias de un elemento DICOM basándose en su etiqueta no aceptan comod

ines, sino que solo funcionan en elementos individuales (es de
cir, un nombre de diccionario único o clave de etiqueta).

-i   --insert:
       dcmodify -i "(0010,0010)=A Name" file.dcm
       Inserta la etiqueta PatientName en 'file.dcm' en el primer nivel.
       ¡Si la etiqueta ya existe, -i la sobrescribirá! Si desea
       insertar un elemento con multiplicidad de valor > 1 (por ejemplo, 4), puede
       hacerlo con: dcmodify -i "(0018,1310)=1\\2\\3\\4"
       dcmodify -i "(0008,1111)[0].PatientName=Another Name" *.dcm
       Inserta la etiqueta PatientName en el primer ítem de la secuencia
       (0008,1111). Tenga en cuenta que el uso de comodines para archivos es
       posible. También puede especificar rutas de etiquetas más largas (por ejemplo,
       "(0008,1111)[0].(0008,1111)[1].(0010,0010)=A Third One").
       Si alguna parte de la ruta, por ejemplo, la secuencia o el ítem "0"
       no existe, dcmodify la insertará automáticamente.
       dcmodify -i "(0008,1111)[*].PatientName=Another Name" *.dcm
       Inserta la etiqueta PatientName en _cada_ ítem de la secuencia
       (0008,1111). Tenga en cuenta que el uso de comodines para archivos es
       posible. También puede especificar rutas de etiquetas más largas (por ejemplo,
       "(0008,1111)[*].(0008,1111)[*].(0010,0010)=A Third One").

       Se espera que los datos OW estén en orden little endian y se intercambiarán
       si es necesario. No se realizarán comprobaciones para asegurar que la
       cantidad de datos sea raz

Esta opción también permite rutas de etiquetas más largas como se demostró arriba para -i. Si el elemento hoja o cualquier parte intermedia de la ruta no existe, no se inserta como lo haría si se usara la opción '-i'. dcmodify -m "(0010,0010)=A Name" -imt file.dcm Cambia la etiqueta (0010,0010) en el primer nivel a "A Name". Debido a la opción '-imt' dada, se devuelve éxito en lugar de "tag not found", si el elemento/ítem (o cualquier nodo intermedio en una ruta más larga) no existe. Tenga en cuenta que para la opción '-m' el último nodo en la ruta debe ser un elemento hoja, es decir, no una secuencia ni un ítem. -mf --modify-from-file: dcmodify -mf "PixelData=pixel.raw" file.dcm Hace lo mismo que -if en caso de que ya hubiera un elemento PixelData en 'file.dcm'. De lo contrario, no se cambia nada. -ma --modify-all: dcmodify -ma "(0010,0010)=New Name" file.dcm Hace lo mismo que -m pero trabaja en todas las etiquetas coincidentes encontradas en 'file.dcm'. Por lo tanto, busca en todo el conjunto de datos, incluyendo secuencias, la etiqueta (0010,0010) y las cambia a "New Name" -e --erase: dcmodify -e "(0010,0010)" *.dcm Borra la etiqueta (0010,0010) en todos los archivos *.dcm en el primer nivel. Esta opción también permite rutas de etiquetas más l
argas como se demostró arriba para -i. dcmodify -e "(0010,0010)" -imt *.dcm Borra la etiqueta (0010,0010) en todos los archivos *.dcm en el primer nivel. Debido a la opción '-imt' dada, se devuelve éxito en lugar de "tag not found", si el elemento/ítem (o cualquier nodo intermedio en una ruta más larga) no existe. -ea --erase-all: dcmodify -ea "(0010,0010)" *.dcm Igual que -e, pero también busca en secuencias e ítems. -ep --erase-private: dcmodify -ep *.dcm Elimina todas las etiquetas privadas (es decir, etiquetas que tienen un número de grupo impar) de todos los archivos que coinciden con *.dcm en el directorio actual. -gst --gen-stud-uid: dcmodify -gst file.dcm Esto genera un nuevo valor para el StudyInstanceUID (0020,000d). ¡Otros UID no se modifican! -gse --gen-ser-uid: dcmodify -gse file.dcm Esto genera un nuevo valor para el SeriesInstanceUID (0020,000e). ¡Otros UID no se modifican! -gin --gen-inst-uid: dcmodify -gin file.dcm Este comando genera un nuevo valor para el SOPInstanceUID (0008,0018). MANEJO DE

ERRORES

dcmodify intenta ejecutar cada operación de modificación dada en la línea de comandos: si una devuelve un error, las demás se realizan de todos modos. Sin embargo, en caso de cualquier error, el archivo modificado no se guarda, a menos que se especifique la opción --ignore-errors. Si se selecciona esa opción, dcmodify también continúa modificando los archivos adicionales especificados en la línea de comandos; otros dcmodify(1) — Arch Linux manual pages

ERROR HANDLING

El programa dcmodify sale después del primer archivo que tuvo errores de modificación.

Si la opción --ignore-missing-tags está habilitada, cualquier operación de modificación o borrado (es decir, no --insert) que falle debido a una etiqueta inexistente se trata como exitosa. Esto tiene sentido si alguien quiere asegurarse de que etiquetas específicas no estén presentes en el archivo o que, si existen, se les asigne un valor específico.

REGISTRO

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose, también se informan mensajes informativos como detalles del procesamiento. La opción --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, para fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En modo --quiet, solo se informan los errores fatales. En eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos seguidos indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' respectivamente. Por lo general, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells comunes de Unix.

Además, se pueden especificar uno o más archivos de comandos utilizando un signo '@' como prefijo del nombre del archivo (por ejemplo, @command.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (los espacios en blanco múltiples se tratan como un solo separador a menos que aparezcan entre comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad dcmodify intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está configurada, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (por defecto para Windows).

Se debe preferir el comportamiento por defecto y usar la variable de entorno DCMDICTPATH solo cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell de Unix, en que dos puntos (":") separan las entradas. En sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
