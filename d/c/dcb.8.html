NOMBRE

dcb - mostrar / manipular configuraciones DCB (Data Center Bridging)

SINOPSIS


dcb [ OPCIONES ] { app | buffer | ets | maxrate | pfc } { COMANDO | help }

dcb [ -force ] -batch archivo

dcb [ OPCIONES ] help

OPCIONES

-n, --netns <ESPACIO_RED>
cambia dcb al espacio de nombres de red especificado ESPACIO_RED.
-V, --Version
Imprime la versión de la utilidad dcb y sale.
-b, --batch <ARCHIVO>
Lee comandos del archivo proporcionado o de la entrada estándar y los invoca. El primer error provocará la terminación de dcb.
-f, --force
No terminar dcb en caso de errores en modo batch. Si hubo algún error durante la ejecución de los comandos, el código de retorno de la aplicación será distinto de cero.
-i, --iec
Al mostrar tasas, usa prefijos basados en ISO/IEC 1024 (Ki, Mi, Bi) en lugar de los basados en 1000 (K, M, B).
-j, --json
Genera salida JSON.
-N, --Numeric
Si la subherramienta en cuestión traduce números a nombres simbólicos de alguna manera, suprime esta traducción.
-p, --pretty
Cuando se combina con -j, genera una salida JSON formateada.
-s, --statistics
Si el objeto en cuestión contiene contadores estadísticos, muéstralos como parte de la salida "show".

OBJETOS

app
- Configuración de la tabla de prioridades de aplicaciones
buffer
- Configuración de los búferes de puerto
ets
- Configuración de ETS (Enhanced Transmission Selection)
maxrate
- Configuración de la tasa máxima de transmisión por TC
pfc
- Configuración de PFC (Priority-based Flow Control)

COMANDOS

Un COMANDO especifica la acción a realizar sobre el objeto. El conjunto de acciones posibles depende del tipo de objeto. Como regla general, es posible mostrar objetos e invocar help, que imprime una lista de comandos disponibles y convenciones de sintaxis de argumentos.

PARÁMETROS ARRAY

Al igual que los comandos, la especificación de parámetros está en el dominio de los objetos individuales (y sus comandos) también. Sin embargo, gran parte de la interfaz DCB gira en torno a arrays de tamaño fijo que especifican un valor por alguna clave, como por clase de tráfico o por prioridad. Por lo tanto, existe una única sintaxis para ajustar elementos de estos arrays. Consiste en una serie de pares CLAVE:VALOR, donde el significado de las claves y valores individuales depende del parámetro.

Los elementos se evalúan en orden de izquierda a derecha, y los posteriores anulan a los anteriores. Los elementos que no se especifican en la línea de comandos se consultan del kernel y su valor actual se conserva.

Como ejemplo, tomemos un parámetro inventado tc-juju, que puede configurarse para dar "encanto" al tráfico en una TC dada con buena o mala suerte. La CLAVE puede ser 0..7 (como es habitual para los números de TC en DCB), y el VALOR uno de none, good, y bad. Un ejemplo de cambio de un valor de "juju" de las TC 0 y 7, dejando todas las demás intactas, sería entonces:

# dcb foo set dev eth0 tc-juju 0:good 7:bad

Se reconoce una clave especial, all, que establece el mismo valor para todos los elementos del array. Esto se puede combinar con la sintaxis habitual de un solo elemento. Por ejemplo, en el siguiente comando, el "juju" de todas las claves se establece en none, excepto 0 y 7, que tienen otros valores:

# dcb foo set dev eth0 tc-juju all:none 0:good 7:bad

ESTADO DE SALIDA

El estado de salida es 0 si el comando se ejecutó correctamente o un entero positivo en caso de fallo.
