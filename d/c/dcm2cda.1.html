REGISTR

El nivel de salida de registro de las diversas herramientas de
línea de comandos y bibliotecas subyacentes puede ser especi
ficado por el usuario. Por defecto, solo se escriben errores
y advertencias en el flujo de error estándar. Usando la opción

--verbose también se informan mensajes informativos como detalles del procesamiento.

La opción

--debug se puede usar para obtener más detalles sobre la actividad interna, p. ej. con fines de depuración. Otros niveles de registro se pueden seleccionar usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog". En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo

COMANDOS 
Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa
de 0
a n
valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Usualmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se conforma a las reglas de evaluación estándar

de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (p.

ej.

@command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el

archivo

<datadir>/dumppat.txt). ENTORNO La uti

dad

dcm2cda intentará cargar los diccionarios de datos DICOM especificados en la variable de

entorno

DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está definida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows). Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo se debe usar cuando se requieran diccionarios de datos alternativos. La variable de

entorno

DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se pued

e cargar ningún di
ccionario de datos.
