DESCRIPCIÓ

N

La utilidad dcm2json convierte el contenido de un archivo DICOM (formato de archivo o conjunto de datos sin procesar) a JSON (JavaScript Object Notation). La salida se refiere al "Modelo JSON de DICOM", que se encuentra en DICOM Parte 18 Sección

F.

Si dcm2json lee un conjunto de datos sin procesar (datos DICOM sin un metaencabezado de formato de archivo), intentará adivinar la sintaxis de transferencia examinando los primeros bytes del archivo. No siempre es posible adivinar correctamente la sintaxis de transferencia y es mejor convertir un conjunto de datos a un formato de archivo siempre que sea posible (utilizando la utilidad dcmconv). También es posible utilizar las opciones -f y -t[ieb] para forzar a dcm2json a leer un conjunto de datos con u

na sintaxis de transfe
rencia en particular.

Datos

masivos

Los datos binarios, es decir, los valores de elementos DICOM con Representaciones de Valor (VR) de OB u OW, así como los valores

OD, OF, OL, OV y UN, siempre se escriben como "InlineBinary" (codificación base64) en la salida JSON. Una versión futura de
esta herramienta podría usar opcionalmente un "BulkDataURI" en su lugar, es decir, la URL WADO-RS de un elemento de datos masivo
que contiene el valor del elemento. Esto sería particularmente útil para grandes cantidades de datos, como los datos de píxeles.

NOTA

S

Números como

cadenas

El estándar DICOM permite que ciertas representaciones de valor numéricas DICOM, DS, IS, SV y UV, se conviertan ya sea a un número JSON o a una cadena JSON. dcm2json convierte los valores DS e IS a números JSON si son cadenas decimales o enteras válidas, y a cadenas si contienen algún carácter ilegal. dcm2json convierte valores SV y UV a números si no son mayores que 9007199254740991ll ni menores que -9007199254740991ll, y a caden

as de texto en caso contrario. Aunque la especificación JSON permite números más grandes, estos son los enteros más
grandes que JavaScript puede manejar. Por lo tanto, muchos analizadores JSON no pueden procesar números más grandes.

Codificación de

caracteres

Según lo requiere la codificación JSON de DICOM, dcm2json siempre crea la salida en codificación Unicode UTF-8 y convierte los conjuntos de datos DICOM

en consecuencia. Si esto no es posible, por ejemplo p
orque DCMTK ha sido compilado sin soporte de conve
rsión de conjuntos de caracteres, se devuelve un error.

REGISTRO DE

EVENTOS

El nivel de registro de eventos de las diversas herramientas de línea de comandos y las bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo se escriben errores y advertencias en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Se pueden seleccionar otros niveles de registro usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, véase la documentación del módulo

"oflog".

En caso de que la salida del registro de eventos deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos usan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos suspensivos indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de la línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Normalmente, el orden y la posición de las opciones de la línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier parte). Sin embargo, si las opciones son mutuamente excluyentes, se usa la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix

comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Téngase en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad dcm2json intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está definida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté compilado en la aplicación (predeterminado para Windows)

.

Se debe preferir el comportamiento por defecto y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable de shell Unix PATH, en la que un dos puntos (":") separa las entradas. En sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de

datos.

La utilidad dcm2json intentará cargar las tablas de mapeo de caracteres. Esto ocurre cuando DCMTK fue compilado con la biblioteca oficonv (que es el predeterminado) y las tablas de mapeo no están compiladas en la biblioteca (predeterminado cuando DCMTK usa bibliotecas compartidas)

.

Se espera que los archivos de tablas de mapeo estén en el <datadir> de DCMTK. La variable de entorno DCMICONVPATH puede usarse para especificar una ubicación diferente. Si se espe

cifica una ubicación diferente, esas tablas de
mapeo también reemplazan cualquier tabla integrada.
