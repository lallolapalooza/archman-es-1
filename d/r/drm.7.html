drm(7) Direct Rendering Manager drm(7)

Nombre

drm - Direct Rendering Manager

Sinopsis

#include <xf86drm.h>

Descripción

El Direct Rendering Manager (DRM) es un framework para gestionar las Graphics Processing Units (GPUs). Está diseñado para soportar las necesidades de dispositivos gráficos complejos, que suelen contener pipelines programables bien adaptados para la aceleración de gráficos 3D. Además, es responsable de la gestión de memoria, el manejo de interrupciones y DMA para proporcionar una interfaz uniforme a las aplicaciones.

En los primeros tiempos, el framework del kernel se usaba exclusivamente para proporcionar acceso de hardware crudo a procesos privilegiados del espacio de usuario que implementaban todas las capas de abstracción del hardware. Pero cada vez más tareas se trasladaron al kernel. Todas estas interfaces se basan en comandos ioctl(2) en el dispositivo de caracteres DRM. La biblioteca libdrm proporciona envoltorios para estas llamadas al sistema y muchos ayudantes para simplificar la API.

Cuando se detecta una GPU, el sistema DRM carga un controlador para el tipo de hardware detectado. Cada GPU conectada se presenta al espacio de usuario a través de un dispositivo de caracteres que normalmente está disponible como /dev/dri/card0 y al que se puede acceder con open(2) y close(2). Sin embargo, todavía depende del controlador gráfico qué interfaces están disponibles en estos dispositivos. Si una interfaz no está disponible, las llamadas al sistema fallarán con EINVAL.

Autenticación

Todos los dispositivos DRM proporcionan mecanismos de autenticación. Solo un DRM master puede realizar la configuración de modo o modificar el estado central y solo un usuario puede ser DRM master a la vez. Consulte drmSetMaster(3) para obtener información sobre cómo convertirse en DRM master y cuáles son las limitaciones. Otros usuarios de DRM pueden autenticarse ante el DRM Master a través de drmAuthMagic(3) para que puedan realizar asignaciones de búfer y renderizado.

Configuración de modo

La gestión de monitores y pantallas conectados y el cambio de los modos actuales se denomina Configuración de modo. Esto está restringido al DRM master actual. Históricamente, esto se implementaba en el espacio de usuario, pero los nuevos controladores DRM implementan una interfaz del kernel para realizar la configuración de modo llamada Kernel Mode Setting (KMS). Si su controlador de hardware lo soporta, puede utilizar la API KMS proporcionada por DRM. Esto incluye la asignación de framebuffers, la selección de modos y la gestión de CRTCs y codificadores. Consulte drm-kms(7) para más detalles.

Gestión de memoria

Las tareas más sofisticadas para las GPUs hoy en día es la gestión de objetos de memoria. Texturas, framebuffers, búferes de comandos y todos los demás tipos de comandos para la GPU deben almacenarse en memoria. El controlador DRM se encarga de gestionar todos los objetos de memoria, vaciar cachés, sincronizar el acceso y proporcionar acceso de CPU a la memoria de la GPU. Toda la gestión de memoria depende del controlador de hardware. Sin embargo, hay dos frameworks genéricos disponibles que son utilizados por la mayoría de los controladores DRM. Estos son el Translation Table Manager (TTM) y el Graphics Execution Manager (GEM). Proporcionan APIs genéricas para crear, destruir y acceder a búferes desde el espacio de usuario. Sin embargo, todavía hay muchas diferencias entre los controladores, por lo que todavía se necesita código específico del controlador. libgbm (Graphics Buffer Manager) del proyecto Mesa proporciona muchos ayudantes. Para más información sobre la gestión de memoria de DRM, consulte drm-memory(7).

Reportar errores

Los errores en este manual deben reportarse a https://gitlab.freedesktop.org/mesa/libdrm/-/issues.
