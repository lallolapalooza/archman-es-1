NOMBRE

dropuser - elimina una cuenta de usuario de PostgreSQL

SINOPSIS

dropuser [opción-conexión...] [opción...] [nombre_usuario]

DESCRIPCIÓN

dropuser elimina un rol (usuario) existente de PostgreSQL. Los superusuarios pueden usar este comando para eliminar cualquier rol; de lo contrario, solo se pueden eliminar roles que no son de superusuario, y solo por un usuario que posea el privilegio CREATEROLE y se le haya concedido la ADMIN OPTION sobre el rol de destino.

dropuser es un envoltorio alrededor del comando SQL DROP ROLE. No hay una diferencia efectiva entre eliminar usuarios a través de esta utilidad y a través de otros métodos de acceso al servidor.

OPCIONES

dropuser acepta los siguientes argumentos de línea de comandos:

nombre_usuario

Especifica el nombre del usuario de PostgreSQL a eliminar. Se le pedirá un nombre si no se especifica en la línea de comandos y se utiliza la opción -i/--interactive.

-e
--echo

Muestra los comandos que dropuser genera y envía al servidor.

-i
--interactive

Pide confirmación antes de eliminar realmente al usuario, y pide el nombre de usuario si no se especifica en la línea de comandos.

-V
--version

Imprime la versión de dropuser y sale.

--if-exists

No lanza un error si el usuario no existe. En este caso, se emite una notificación.

-?
--help

Muestra ayuda sobre los argumentos de la línea de comandos de dropuser y sale.

dropuser también acepta los siguientes argumentos de línea de comandos para parámetros de conexión:

-h host
--host=host

Especifica el nombre del host de la máquina en la que se está ejecutando el servidor. Si el valor comienza con una barra, se utiliza como directorio para el socket de dominio Unix.

-p puerto
--port=puerto

Especifica el puerto TCP o la extensión del archivo de socket de dominio Unix local en el que el servidor está escuchando las conexiones.

-U nombre_usuario
--username=nombre_usuario

Nombre de usuario para conectarse como (no el nombre de usuario a eliminar).

-w
--no-password

Nunca solicita una contraseña. Si el servidor requiere autenticación por contraseña y no hay una contraseña disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.

-W
--password

Fuerza a dropuser a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que dropuser solicitará automáticamente una contraseña si el servidor la exige. Sin embargo, dropuser desperdiciará un intento de conexión al averiguar que el servidor quiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

ENTORNO

PGHOST
PGPORT
PGUSER

Parámetros de conexión por defecto

PG_COLOR

Especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son always, auto y never.

Esta utilidad, como la mayoría de las otras utilidades de PostgreSQL, también utiliza las variables de entorno admitidas por libpq (ver Sección 32.15).

DIAGNÓSTICOS

En caso de dificultad, consulte DROP ROLE (DROP_ROLE(7)) y psql(1) para discusiones sobre posibles problemas y mensajes de error. El servidor de base de datos debe estar en ejecución en el host de destino. Además, se aplicarán todos los ajustes de conexión por defecto y las variables de entorno utilizadas por la biblioteca front-end libpq.

EJEMPLOS

Para eliminar al usuario joe del servidor de base de datos por defecto:

$ dropuser joe

Para eliminar al usuario joe utilizando el servidor en el host eden, puerto 5000, con verificación y una vista previa del comando subyacente:

$ dropuser -p 5000 -h eden -i -e joe
Role "joe" will be permanently removed.
Are you sure? (y/n) y
DROP ROLE joe;

VER TAMBIÉN

createuser(1), DROP ROLE (DROP_ROLE(7))
