DROP OWNED(7) Documentación de PostgreSQL 18.1 DROP OWNED(7)

NOMBRE

DROP_OWNED - elimina objetos de base de datos propiedad de un rol de base de datos

SINOPSIS

DROP OWNED BY { nombre | CURRENT_ROLE | CURRENT_USER | SESSION_USER } [, ...] [ CASCADE | RESTRICT ]

DESCRIPCIÓN

DROP OWNED elimina todos los objetos dentro de la base de datos actual que son propiedad de uno de los roles especificados. También se revocarán todos los privilegios otorgados a los roles dados sobre objetos en la base de datos actual o sobre objetos compartidos (bases de datos, tablespaces, parámetros de configuración).

PARÁMETROS

nombre

El nombre de un rol cuyos objetos serán eliminados, y cuyos privilegios serán revocados.

CASCADE

Elimina automáticamente los objetos que dependen de los objetos afectados, y a su vez todos los objetos que dependen de esos objetos (ver Sección 5.15).

RESTRICT

Rechaza eliminar los objetos propiedad de un rol si cualquier otro objeto de base de datos depende de uno de los objetos afectados. Esta es la opción predeterminada.

NOTAS

DROP OWNED se usa a menudo para preparar la eliminación de uno o más roles. Debido a que DROP OWNED solo afecta a los objetos en la base de datos actual, generalmente es necesario ejecutar este comando en cada base de datos que contenga objetos propiedad de un rol que se va a eliminar.

El uso de la opción CASCADE podría hacer que el comando se recorra hasta objetos propiedad de otros usuarios.

El comando REASSIGN OWNED es una alternativa que reasigna la propiedad de todos los objetos de base de datos propiedad de uno o más roles. Sin embargo, REASSIGN OWNED no se ocupa de los privilegios para otros objetos.

Las bases de datos y tablespaces propiedad del rol o roles no serán eliminados.

Ver Sección 21.4 para más discusión.

COMPATIBILIDAD

El comando DROP OWNED es una extensión de PostgreSQL.

VER TAMBIÉN

REASSIGN OWNED (REASSIGN_OWNED(7)), DROP ROLE (DROP_ROLE(7))
