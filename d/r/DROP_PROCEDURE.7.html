Paquete: postgresql

Licencias: PostgreSQL

DROP PROCEDURE(7) Documentación de PostgreSQL 18.1 DROP PROCEDURE(7)

NOMBRE

DROP_PROCEDURE - eliminar un procedimiento

SINOPSIS

DROP PROCEDURE [ IF EXISTS ] nombre [ ( [ [ argmode ] [ argname ] argtype [, ...] ] ) ] [, ...]
    [ CASCADE | RESTRICT ]

DESCRIPCIÓN

DROP PROCEDURE elimina la definición de uno o más procedimientos existentes. Para ejecutar este comando, el usuario debe ser el propietario del(los) procedimiento(s). Los tipos de argumento del(los) procedimiento(s) generalmente deben especificarse, ya que varios procedimientos diferentes pueden existir con el mismo nombre y diferentes listas de argumentos.

PARÁMETROS

IF EXISTS

No genere un error si el procedimiento no existe. Se emitirá un aviso en este caso.

nombre

El nombre (opcionalmente calificado por esquema) de un procedimiento existente.

argmode

El modo de un argumento: IN, OUT, INOUT o VARIADIC. Si se omite, el valor predeterminado es IN (pero vea abajo).

argname

El nombre de un argumento. Tenga en cuenta que DROP PROCEDURE en realidad no presta atención a los nombres de los argumentos, ya que solo los tipos de datos de los argumentos se utilizan para determinar la identidad del procedimiento.

argtype

El(los) tipo(s) de datos de los argumentos del procedimiento (opcionalmente calificado por esquema), si los hay. Vea abajo para más detalles.

CASCADE

Eliminar automáticamente los objetos que dependen del procedimiento, y a su vez todos los objetos que dependen de esos objetos (ver Sección 5.15).

RESTRICT

Rechazar la eliminación del procedimiento si algún objeto depende de él. Este es el valor predeterminado.

NOTAS

Si solo hay un procedimiento con el nombre dado, la lista de argumentos puede omitirse. Omita también los paréntesis en este caso.

En PostgreSQL, es suficiente enumerar los argumentos de entrada (incluidos los INOUT), ya que no se permite que dos rutinas del mismo nombre compartan la misma lista de argumentos de entrada. Además, el comando DROP no verificará realmente que haya escrito correctamente los tipos de los argumentos OUT; por lo tanto, cualquier argumento marcado explícitamente como OUT es solo ruido. Pero escribirlo es recomendable para la coherencia con el comando CREATE correspondiente.

Para compatibilidad con el estándar SQL, también se permite escribir todos los tipos de datos de los argumentos (incluidos los de los argumentos OUT) sin ningún marcador argmode. Cuando esto se hace, se verificarán los tipos de los argumentos OUT del procedimiento contra el comando. Esta disposición crea una ambigüedad, ya que cuando la lista de argumentos no contiene marcadores argmode, no está claro qué regla se pretende. El comando DROP intentará la búsqueda de ambas maneras, y generará un error si se encuentran dos procedimientos diferentes. Para evitar el riesgo de tal ambigüedad, es recomendable escribir marcadores IN explícitamente en lugar de dejar que se usen por defecto, forzando así el uso de la interpretación tradicional de PostgreSQL.

Las reglas de búsqueda explicadas anteriormente también son utilizadas por otros comandos que actúan sobre procedimientos existentes, como ALTER PROCEDURE y COMMENT ON PROCEDURE.

EJEMPLOS

Si solo hay un procedimiento do_db_maintenance, este comando es suficiente para eliminarlo:

DROP PROCEDURE do_db_maintenance;

Dada la siguiente definición de procedimiento:

CREATE PROCEDURE do_db_maintenance(IN target_schema text, OUT results text) ...

cualquiera de estos comandos serviría para eliminarlo:

DROP PROCEDURE do_db_maintenance(IN target_schema text, OUT results text);
DROP PROCEDURE do_db_maintenance(IN text, OUT text);
DROP PROCEDURE do_db_maintenance(IN text);
DROP PROCEDURE do_db_maintenance(text);
DROP PROCEDURE do_db_maintenance(text, text);  -- potencialmente ambiguo

Sin embargo, el último ejemplo sería ambiguo si también hubiera, por ejemplo,

CREATE PROCEDURE do_db_maintenance(IN target_schema text, IN options text) ...

COMPATIBILIDAD

Este comando se ajusta al estándar SQL, con estas extensiones de PostgreSQL:

•El estándar solo permite eliminar un procedimiento por comando.
•La opción IF EXISTS es una extensión.
•La capacidad de especificar modos y nombres de argumentos es una extensión, y las reglas de búsqueda difieren cuando se proporcionan modos.
