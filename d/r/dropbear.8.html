dropbear(8) Manual de Administrador del Sistema dropbear(8)

NOMBRE

dropbear - servidor SSH ligero

SINOPSIS

dropbear [argumentos de bandera] [-b banner] [-r archivo_de_clave_host] [-p [direccion:]puerto]

DESCRIPCIÓN

dropbear es un servidor SSH pequeño

OPCIONES

-b banner
archivo_banner. Muestra el contenido del archivo banner antes del inicio de sesión del usuario (por defecto: ninguno).
-r clave_host
Usa el contenido del archivo clave_host para la clave del host SSH. Este archivo se genera con dropbearkey(1) o automáticamente con la opción '-R'. Ver "Archivos de Clave de Host" abajo.
-R
Genera claves de host automáticamente. Ver "Archivos de Clave de Host" abajo.
-F
No se bifurca en segundo plano.
-E
Registra en la salida de error estándar en lugar de syslog.
-e
Pasa el entorno del servidor a todos los procesos hijos. Esto es necesario, por ejemplo, si Dropbear se lanza sobre la marcha desde un gestor de trabajos SLURM. El entorno no se pasa por defecto. Tenga en cuenta que esto podría exponer secretos en variables de entorno del proceso que llama; úsese con precaución.
-m
No muestra el mensaje del día al iniciar sesión.
-w
Inhabilita los inicios de sesión como root.
-s
Inhabilita los inicios de sesión con contraseña.
-g
Inhabilita los inicios de sesión con contraseña para root.
-t
Habilita la autenticación de dos factores. Se requieren tanto el inicio de sesión con contraseña como la autenticación de clave pública. No debe usarse con la opción '-s'.
-j
Inhabilita el reenvío de puertos local. Esto incluye los reenvíos de streams de Unix.
-k
Inhabilita el reenvío de puertos remoto.
-p [direccion:]puerto
Escucha en la direccion y el puerto TCP especificados. Si solo se da un puerto, escucha en todas las direcciones. Se pueden especificar hasta 10 (por defecto 22 si no se especifica ninguno).
-l interfaz
Escucha en la interfaz especificada
-i
Modo de programa de servicio. Usa esta opción para ejecutar dropbear bajo servidores TCP/IP como inetd, tcpsvd, o tcpserver. En modo programa, la opción -F se implica y las opciones -p se ignoran.
-P archivo_pid
Especifica un archivo PID a crear al ejecutarse como demonio. Si no se especifica, el valor por defecto es /var/run/dropbear.pid
-a
Permite que los hosts remotos se conecten a los puertos reenviados.
-W tamaño_ventana
Especifica el buffer de ventana de recepción por canal. Aumentar esto puede mejorar el rendimiento de la red a expensas del uso de memoria. Usa -h para ver el tamaño de buffer por defecto.
-K segundos_timeout
Asegura que el tráfico se transmita a un intervalo determinado en segundos. Esto es útil para solucionar problemas de firewalls o routers que cierran conexiones después de un cierto período de inactividad. La contrapartida es que una sesión puede cerrarse si hay una interrupción temporal de la conectividad de red. Una configuración de 0 deshabilita los keepalives. Si no se recibe respuesta para 3 keepalives consecutivos, la conexión se cerrará.
-I timeout_inactividad
Desconecta la sesión si no se transmite ni se recibe tráfico durante timeout_inactividad segundos.
-z
Por defecto Dropbear enviará tráfico de red con la configuración AF21 para QoS, permitiendo que los dispositivos de red le den mayor prioridad. Algunos dispositivos pueden tener problemas con eso; -z puede usarse para deshabilitarlo.
-T intentos_max_autenticacion
Establece el número de intentos de autenticación permitidos por conexión. Si no se especifica, el valor por defecto es 10 (MAX_AUTH_TRIES)
-c comando_forzado
Ignora el comando proporcionado por el usuario y ejecuta siempre comando_forzado. Esto también anula cualquier opción command= en authorized_keys. El comando original se guarda en la variable de entorno SSH_ORIGINAL_COMMAND (ver abajo).
-D directorio_claves_autorizadas
Especifica el directorio a usar para los archivos authorized_keys. El valor por defecto es ~/.ssh, las rutas con un prefijo ~/ se expandirán con el directorio home.
-V
Imprime la versión

ARCHIVOS

Claves autorizadas

~/.ssh/authorized_keys puede configurarse para permitir el inicio de sesión remoto con una clave RSA, ECDSA, Ed25519 o DSS. Cada línea tiene el formato

[restricciones] ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAIgAsp... [comentario]

y puede extraerse de una clave de host privada de Dropbear con "dropbearkey -y". Este es el mismo formato que utiliza OpenSSH, aunque las restricciones son un subconjunto (las claves con restricciones desconocidas se ignoran). Las restricciones se separan por comas, con comillas dobles alrededor de los espacios en los argumentos. Las restricciones disponibles son:

sin-reenvio-puertos
No permitir el reenvío de puertos para esta conexión, incluidos los streams de Unix.
sin-reenvio-agente
No permitir el reenvío de agente para esta conexión
sin-reenvio-x11
No permitir el reenvío X11 para esta conexión
sin-pty
Inhabilitar la asignación de PTY. Tenga en cuenta que un usuario aún puede obtener la mayor parte de la misma funcionalidad por otros medios, incluso si se establece sin-pty.
restringir
Aplica todas las restricciones sin- listadas anteriormente.
permitir-abrir="host:puerto"
Restringe el reenvío de puertos local para que la conexión solo se permita al host y puerto especificados. Se pueden establecer múltiples opciones permitir-abrir separadas por comas en authorized_keys. El carácter comodín ('*') puede usarse en la especificación del puerto para que coincida con cualquier puerto. Los hosts deben ser nombres de dominio literales o direcciones IP.
comando="comando_forzado"
Ignora el comando proporcionado por el usuario y ejecuta siempre comando_forzado. La opción de línea de comandos -c anula esto.

El archivo authorized_keys y su directorio ~/.ssh que lo contiene deben ser escribibles solo por el usuario, de lo contrario Dropbear no permitirá un inicio de sesión utilizando autenticación de clave pública.

Archivos de Clave de Host

Los archivos de clave de host se leen al inicio desde una ubicación estándar, por defecto /etc/dropbear/dropbear_dss_host_key, /etc/dropbear/dropbear_rsa_host_key, /etc/dropbear/dropbear_ecdsa_host_key y /etc/dropbear/dropbear_ed25519_host_key

Si se especifica la opción de línea de comandos -r, los archivos por defecto no se cargan. Los archivos de clave de host son del formato generado por dropbearkey. La opción -R se puede usar para generar automáticamente claves en la ubicación por defecto; las claves se generarán después del inicio, cuando se establezca la primera conexión. Esto tiene el beneficio de que la fuente de números aleatorios del sistema /dev/urandom tiene una mayor probabilidad de estar bien inicializada.
