SINOPSI

S

Este documento describe la información de configuración que se almacena

en cada objeto Date::Manip::Base, cómo modificar esta información y
cómo se utiliza la información en los demás módulos de Date::Manip.

DESCRIPCIÓ

N

Date::Manip es un paquete de módulos muy configurable. Muchos de sus comportamientos pueden modificarse para cambiar la forma en que se realizan las operaciones de fechas. Para ello, se puede establecer una lista de variables de configuración que definen muchos comportamientos de Date::

Manip.

Hay tres formas de establecer variables de configuración. Las dos primeras son pasarlas al crear un objeto o pasarlas al método config después de que el objeto haya sido creado. Todos los módulos principales de Date::Manip (Date::Manip::Base, Date::Manip::TZ, Date::Manip::Date, Date::Manip::Delta, y Date::Manip::Recur) tienen el método

config.

Como ejemplo, puede crear y configurar un objeto Date::Manip::Date utilizando los

comandos: 
$date = new Date::Manip::Date;
$date->config($var1,$val1,$var2,$val2,...)
;

Esto puede acortarse

a: 
$date = new Date::Manip::Date [$var1,$val1,...]
;

Los valores de las variables de configuración se almacenan en el objeto Date::Manip::Base. Así, si tiene un objeto Date::Manip::Date, este tiene un objeto Date::Manip::Base asociado a él, y la información de configuración se almacena allí. El mismo objeto Date::Manip::Base puede ser utilizado por cualquier número de objetos de nivel superior, y todos compartirán la misma configuración. Si varios objetos Date::Manip::Date comparten el mismo objeto Date::Manip::Base , establecer una variable de configuración en cualquiera de ellos afecta a todos los objetos Date::Manip::Date. Si necesita trabajar con configuraciones diferentes simultáneamente, es necesario trabajar con múltiples objetos Date::Manip::Base . Esto se describe en el documento Date::Manip::

Objects.

Existe un método alternativo si está utilizando una de las interfaces funcionales. Para establecer una variable utilizando la interfaz funcional, use la

llamada: 
Date_Init("$var1=$val1")
;

La tercera forma de establecer variables de configuración es almacenarlas en un archivo de configuración. El archivo de configuración se lee pasando los

valores apropiados al método config como se describe a continuación. Un archivo de configuración es una buena manera de cambiar fácilmente una gran
cantidad de ajustes. También son necesarios para otros propósitos (como eventos y festivos que se describen en el documento Date::Manip::Holidays).

La sección inicial de un archivo de configuración contiene variables de configuración generales. A continuación se muestra una lista de todas las variables de

documentación.

Date::Manip se puede utilizar para analizar fechas en muchos idiomas diferentes. Una lista de los idiomas se encuentra en el documento Date::Manip::Lang.

Para analizar fechas en un idioma diferente, simplemente use la variable de configuración Language con el nombre del idioma como valor. Los nombres de idiomas no distinguen entre mayúsculas y

Encodi
ng
Date::Manip tiene cierto soporte para manejar cadenas de fechas codificadas en codificaciones de caracteres alternativas.

De forma predeterminada, las cadenas de entrada pueden probarse utilizando múltiples codificaciones que se usan comúnmente para los idiomas específicos, así como utilizando secuencias de escape estándar de perl, y la salida se realiza en

UTF-8.

La entrada, la salida o ambas se pueden anular utilizando la variable

Encoding.

Establecer Encoding en el nombre de una sola codificación (un nombre admitido por el módulo perl Encoding), forzará que toda la entrada y salida se realicen en esa

codificación. p">Así, configurar:

Encoding = iso-8859-1

significa que toda la entrada y salida estará en esa codificación. La codificación 'perl' tiene el significado especial de almacenar la cadena en secuencias de escape de perl.

Encoding también se puede establecer al nombre de dos codificaciones (separadas por una coma).

Encoding = iso-8859-1,utf-16

lo que significa que toda la entrada está en la codificación iso-8859-1, pero toda la salida será utf-16.

Encoding también se puede establecer de la siguiente manera:

Encoding = iso-8859-1,

lo que significa que la entrada está en iso-8859-1 y la salida está en la codificación predeterminada (es decir, UTF-8).

Encoding = ,utf-16

significa verificar la entrada en todas las codificaciones, pero toda la salida estará en la codificación utf-16.

Tenga en cuenta que cada vez que cambie de idioma, se restablecerán las codificaciones, por lo que debe establecer esta variable de configuración DESPUÉS de establecer el idioma.

FirstDay
A veces es necesario saber qué día de la semana se considera el primero. De forma predeterminada, esto se establece en lunes, ya que se ajusta a ISO 8601, pero muchos países y personas preferirán el domingo (y en unos pocos casos, se puede desear un día diferente). Establezca la variable FirstDay en un dígito 1-7 correspondiente al día de la semana (1=Lunes a 7=Domingo).
Week1ofYear
Esta variable (junto con la variable FirstDay) se utiliza para definir exactamente cuándo comienza la primera semana del año.

Si el valor es 'janX' (donde X es un dígito 1-7), entonces significa que la primera semana del año contiene esa fecha. La definición ISO 8601 predeterminada de una semana es que es la primera semana que contiene el 4 de enero, por lo que el valor predeterminado de esta variable es 'jan4'.

Si el valor es 'dowX' (donde X es un dígito 1-7), entonces la primera semana del año es la que contiene la primera aparición de el día de la semana dado (X=1 es Lunes, X=7 es Domingo). Así que, si desea que la primera semana sea la que contiene el primer lunes del año, use 'dow1'.

Si el valor es 'firstday', entonces la primera semana del año es la que contiene la primera aparición del día de la semana dado en la variable de configuración FirstDay.

Printable
Algunos comandos pueden producir una versión imprimible de una fecha. De forma predeterminada, la versión imprimible de la fecha tiene el formato: 
YYYYMMDDHH:MN:SS

Se han creado otras dos versiones simples. Si la variable Printable se establece en 1, el formato es:

YYYYMMDDHHMNSS

Si Printable se establece en 2, el formato es:

YYYY-MM-DD-HH:MN:SS

Esta variable de configuración está presente para mantener la compatibilidad hacia atrás, y en realidad puede quedar obsoleta en algún momento. Como tal, no se agregarán formatos adicionales. En su lugar, use el método printf en el módulo Date::Manip::Date para extraer información con total flexibilidad.

VARIABLES DE CONFIGURACIÓN DE ANÁLISIS DE FECHAS

DateFormat
Diferentes países ven la fecha 12/10 como 10 de diciembre o 12 de octubre. En Estados Unidos, lo primero es más común, pero esto ciertamente no se cumple para otros países. Establecer DateFormat en "US" (sin distinción de mayúsculas y minúsculas) fuerza el primer comportamiento (10 de diciembre). Establecer DateFormat en cualquier otra cosa fuerza el segundo comportamiento (12 de octubre). La configuración "US" es la predeterminada (perdón por eso... vivo en EE. UU.).
YYtoYYYY
Al analizar una fecha que contiene un año de 2 dígitos, el año debe convertirse a 4 dígitos. Esta variable de configuración determina cómo se hace esto.

De forma predeterminada, un año de 2 dígitos se trata como si cayera en el período de 100 años de CURR-89 a CURR+10. Así que en el año 2005, un año de dos dígitos estará en algún lugar del rango 1916 a 2015.

YYtoYYYY se puede establecer en cualquier entero N para forzar un año de 2 dígitos en el período CURR-N a CURR+(99-N). Un valor de 0 fuerza el año a ser el año actual o posterior. Un valor de 99 fuerza el año a ser el año actual o anterior. Aunque la elección más común de valores estará en algún lugar entre 0 y 99, no hay restricción en N que fuerce a que sea así. En realidad, puede ser cualquier número positivo o negativo que desee para forzarlo en cualquier período de 100 años deseado.

YYtoYYYY también se puede establecer en "C" para forzarlo al siglo actual, o en "C##" para forzarlo a un siglo específico. Así, en 1998, "C" fuerza a los años de 2 dígitos a ser 1900-1999. "C18" siempre forzaría un año de 2 dígitos a estar en el rango 1800-1899. Nota: soy consciente de que las definiciones reales de siglo son 1901-2000, NO 1900-1999, así que para los puristas, trate esto como la forma de proporcionar los dos primeros dígitos en lugar de proporcionar un siglo.

También se puede establecer en la forma "C####" para forzarlo a un período específico de 100 años. C1950 se refiere a 1950-2049.

DefaultTime
Cuando se analiza una fecha desde uno de los formatos enumerados en las secciones "Formatos de fecha comunes" o "Formatos menos comunes" del documento Date::Manip::Date, y no se incluye explícitamente ninguna hora, la hora predeterminada puede determinarse por el valor de esta variable. Los dos valores posibles son: 
midnight   la hora predeterminada es 00:00:00
curr       la hora predeterminada es la hora actual

"midnight" es el valor predeterminado.

NOTA: esto solo se aplica a las fechas analizadas con el método parse. Las fechas analizadas usando el método parse_date siempre usan 00:00:00 por defecto.

PeriodTimeSep
De forma predeterminada, el separador de hora (es decir, el carácter que separa las horas de los minutos y los minutos de los segundos) se especifica en las traducciones de idioma y en la mayoría de los casos no incluye un punto. En inglés, el único separador de hora definido es los dos puntos (:), por lo que la hora se puede escribir como 12:15:30 .

Si desea usar un punto (.) como separador de hora también, establezca esto en 1. Luego puede escribir la hora como 12.15.30 .

De forma predeterminada, un punto se usa como separador de fecha, así que 12.15.30 se interpretaría como 15 de diciembre de 1930 (o 2030), así que si usa el punto como separador de fecha, no debe usarse también como separador de hora.

Format_MMMYYYY
De forma predeterminada, al analizar una cadena como 'Jun 1925', se interpretará como 'Jun 19, 2025' (es decir, MMM DDYY). Además, la cadena '1925 Jun' no está permitida.

Esta variable se puede establecer en 'first' o 'last', y en ese caso, tanto 'Jun 1925' como '1925 Jun' estarán permitidos, y se referirán al primer o último día de junio de 1925.

VARIABLES DE CONFIGURACIÓN DE NEGOCIOS

Estas son variables de configuración utilizadas para definir días laborables y festivos utilizados en cálculos en modo negocio. Consulte la documentación de Date::Manip::Calc para obtener detalles sobre estos cálculos.

WorkWeekBeg
WorkWeekEnd
El primer y último día de la semana laboral. Estos están predeterminados en lunes y viernes. Los días están numerados desde 1 (Lunes) hasta 7 (Domingo). WorkWeekBeg debe ser numéricamente anterior a WorkWeekEnd, por lo que no hay forma de manejar una semana laboral de domingo a jueves usando estas variables.

Tampoco hay forma de manejar un horario laboral extraño como 10 días trabajando, 4 días libres.

Sin embargo, ambas situaciones se pueden manejar usando una solución alternativa bastante simple.

Para manejar una semana laboral de domingo a jueves, simplemente establezca WorkWeekBeg=1 y WorkWeekEnd=7 y defina un festivo que ocurra todos los viernes y sábados.

Para manejar un horario de 10 días trabajando, 4 días libres, haga algo similar pero defina un festivo que ocurra en los 4 días libres.

Ambas cosas se pueden hacer usando recurrencias. Consulte la documentación de Date::Manip::Recur para obtener detalles.

WorkDay24Hr
WorkDayBeg
WorkDayEnd
Si WorkDay24Hr es distinto de cero, un día laboral se trata como si tuviera normalmente 24 horas de duración (los cambios de horario de verano SÍ se tienen en cuenta). Las variables WorkDayBeg y WorkDayEnd se ignoran en este caso.

De forma predeterminada, WorkDay24Hr es cero, y el día laboral está definido por las variables WorkDayBeg y WorkDayEnd. Estas son las horas en las que el día laboral comienza y termina respectivamente. WorkDayBeg debe ser anterior a WorkDayEnd (es decir, no hay forma de manejar el turno de noche donde el día laboral comienza un día y termina otro).

La hora en ambas debe ser un formato de hora válido (H, H:M, o H:M:S).

Tenga en cuenta que establecer WorkDay24Hr en un valor distinto de cero establece automáticamente WorkDayBeg y WorkDayEnd en "00:00:00" y "24:00:00" respectivamente, así que para volver a un día que no sea de 24 horas, necesitará restablecer ambas variables de configuración.

De manera similar, establecer cualquiera de las variables WorkDayBeg o WorkDayEnd desactiva automáticamente WorkDay24Hr.

TomorrowFirst
Periódicamente, si un día no es un día laborable, necesitamos encontrar el día laborable más cercano. De forma predeterminada, buscaremos "mañana" primero, pero si esta variable se establece en 0, buscaremos "ayer" primero. Esto solo se usa en el "Date::Manip::Date::nearest_business_day" método (y la función "Date_NearestWorkDay" ) y se puede anular fácilmente (consulte la documentación del método nearest_business_day).
EraseHolidays
EraseEvents
Si se usan estas variables (se debe pasar un valor, pero se ignora), se borra la lista actual de festivos o eventos definidos. Se establecerá un nuevo conjuntot la próxima vez que se lea un archivo de configuración.

VARIABLES DE CONFIGURACIÓN RELACIONADAS CON ZONA

HORARIA

Las siguientes variables de configuración pueden alterar la zona horaria actual. Como tal, solo están disponibles una vez que el módulo Date::Manip::TZ está disponible. Una manera fácil de manejar esto es pasarlas solo al método config de un objeto Date::Manip::TZ o uno de los objetos de alto nivel (Date::Manip::Date, Date::Manip::Delta o Date::Manip::Recur)

.

Muchas de las operaciones de Date::Manip dependen de saber qué hora es ahora. Esto consiste en tres cosas: saber qué fecha y hora es, saber en qué zona horaria está, y saber si es horario de verano o no. Todo esto es necesario para manejar correctamente cada posible

fecha.

La información del horario de verano solo se usa durante un par de horas cada año durante los cambios de horario de verano (en todos los demás momentos, la fecha, hora y zona horaria son información suficiente), por lo que es opcional, y por defecto se usa la hora estándar si se

omite.

El comportamiento predeterminado de Date::Manip es usar la función localtime del sistema para determinar la fecha, hora e información de horario de verano, y usar varios métodos (ver "DETERMINING THE SYSTEM TIME ZONE" en Date::Manip::TZ) para determinar en qué zona horaria se encuentra la

computadora.
SetDa
te
La variable de configuración SetDate se usa para establecer la fecha, hora o zona horaria actual, pero luego permitir que cambie con el tiempo usando las reglas de esa zona horaria.

Hay varios casos en los que esto puede ser

útil.

A menudo, puede querer usar la hora del sistema para obtener la fecha y hora, pero quiere trabajar en otra zona horaria. Para esto, use la siguiente

ZONE");

La hora continuará avanzando, pero usará las reglas de cambio de hora de la zona horaria Europe/Rome. Lo que eso significa es que si ocurre un horario de verano en la computadora, pero NO en la zona horaria Europe/Rome (o viceversa), la fecha y hora del sistema ya no coincidirán con los resultados de analizar la fecha "now" en Date::

Si se usa "stdonly" o "dstonly", la fecha será forzada a ser estándar o de verano respectivamente (se producirá un error si no hay una fecha válida en ese

horario).

Si la fecha/hora actual no existe en la zona alternativa, ocurrirá un

error.

ZONE");

America/New_York

ZONE puede ser cualquier nombre de zona horaria, alias, abreviatura o desfase, y se determinará la mejor zona horaria a partir de toda la información

dada.

Debe tenerse en cuenta que establecer la variable SetDate o ForceDate dos veces siempre se referirá a la fecha/hora del sistema como punto de partida. Por ejemplo, si un programa se está ejecutando y llama al

método: 
$date->config("forcedate","now")
;

en Jun 6, 2009 a las 12:00, esa hora será tratada como "now" desde ese punto en adelante. Si se hace la misma llamada una hora después, "now" será entonces Jun 6, 2009 a las 13:00 desde ese momento en

adelante.

Dado que se usa la fecha actual en las rutinas de análisis de fechas, no se puede hacer ningún análisis sobre el valor DATE en ninguna de las llamadas. En su lugar, DATE debe ser una fecha en uno de los dos

formatos: 
YYYY-MM-DD-H
H:MN:SS YYYY
MMDDHH:MN:SS
