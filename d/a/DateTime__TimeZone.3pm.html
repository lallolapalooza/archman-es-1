DateTime::TimeZone(3) Documentación de Perl aportada por el usuario DateTime::TimeZone(3)

NOMBRE

DateTime::TimeZone - Clase base de objetos de zona horaria y fábrica

VERSIÓN

versión 2.65

SINOPSIS

use DateTime;
use DateTime::TimeZone;
my $tz = DateTime::TimeZone->new( name => 'America/Chicago' );
my $dt = DateTime->now();
my $offset = $tz->offset_for_datetime($dt);

DESCRIPCIÓN

Esta clase es la clase base para todos los objetos de zona horaria. Una zona horaria se representa internamente como un conjunto de observancias, cada una de las cuales describe el desplazamiento desde GMT para un período de tiempo dado.

Tenga en cuenta que sin el módulo DateTime, este módulo no hace mucho. Su interfaz principal es a través de un objeto DateTime, y la mayoría de los usuarios no necesitarán usar directamente "DateTime::TimeZone" métodos.

Plataformas de Caso Especial

Si está en la plataforma Win32, querrá instalar también DateTime::TimeZone::Local::Win32. Esto le permitirá especificar una zona horaria de 'local' al crear un objeto DateTime.

Si está en HPUX, instale DateTime::TimeZone::HPUX. Esto proporciona soporte para zonas horarias estilo HPUX como 'MET-1METDST'.

USO

Esta clase tiene los siguientes métodos:

DateTime::TimeZone->new( name => $tz_name )

Dado un nombre de zona horaria válido, este método devuelve una nueva zona horaria bendecida (blessed) en la subclase apropiada. Las subclases se nombran para la zona horaria dada, de modo que la zona horaria "America/Chicago" es la clase DateTime::TimeZone::America::Chicago.

Si el nombre dado es un nombre de "enlace" (link) en la base de datos Olson, el objeto creado puede tener un nombre diferente. Por ejemplo, existe un enlace del antiguo nombre "EST5EDT" a "America/New_York".

Al cargar una zona horaria desde la base de datos Olson, el constructor verifica la versión de la clase cargada para asegurarse de que coincida con la versión de la instalación actual de DateTime::TimeZone. Si no coinciden, emitirá una advertencia. Esto es útil porque los nombres de zona horaria pueden dejar de usarse, pero puede tener un archivo de módulo antiguo instalado para esa zona horaria.

También hay varios valores especiales que se pueden dar como nombres.

Si el parámetro "name" es "floating", entonces un "DateTime::TimeZone::Floating" objeto es devuelto. Una zona horaria flotante no tiene ningún desplazamiento, y es siempre la misma hora. Esto es útil para aplicaciones de calendario, que pueden necesitar especificar que un evento dado ocurre a la misma hora local , independientemente de dónde ocurra. Vea RFC 2445 https://www.ietf.org/rfc/rfc2445.txt para más detalles.

Si el parámetro "name" es "UTC", entonces un "DateTime::TimeZone::UTC" objeto es devuelto.

Si el "name" es una cadena de desplazamiento (offset), se convierte a un número, y un "DateTime::TimeZone::OffsetOnly" objeto es devuelto.

La zona horaria "local"

Si el parámetro "name" es "local", entonces el módulo intenta determinar la zona horaria local para el sistema.

El método para encontrar la zona local varía según el sistema operativo. Vea el módulo apropiado para los detalles de cómo verificamos la zona horaria local.

  • DateTime::TimeZone::Local::Unix
  • DateTime::TimeZone::Local::Android
  • DateTime::TimeZone::Local::hpux
  • DateTime::TimeZone::Local::Win32
  • DateTime::TimeZone::Local::VMS

Si no se encuentra una zona horaria local, se lanzará una excepción. Esta excepción siempre se convertirá a cadena (stringify) en algo que contiene el texto "Cannot determine local time zone".

Si está escribiendo código para que los usuarios lo ejecuten en sistemas que no controla, debería intentar tener en cuenta la posibilidad de que se lance esta excepción. Volver a UTC podría ser una alternativa razonable.

Al escribir pruebas para sus módulos que podrían ejecutarse en los sistemas de otros, se le recomienda encarecidamente no usar "local" al crear objetos DateTime o establecer $ENV{TZ} a un valor conocido en su código de prueba. Todas las clases por SO verifican esta variable de entorno.

$tz->offset_for_datetime( $dt )

Dado un "DateTime" objeto, este método devuelve el desplazamiento en segundos para la fecha y hora dadas. Esto tiene en cuenta la información histórica de la zona horaria, así como el Horario de Verano. El desplazamiento se determina mirando los días y segundos Rata Die UTC del objeto.

$tz->offset_for_local_datetime( $dt )

Dado un "DateTime" objeto, este método devuelve el desplazamiento en segundos para la fecha y hora dadas. A diferencia del método anterior, este método usa los días y segundos Rata Die de la hora local. Esto solo debe hacerse cuando la hora UTC correspondiente aún no se conoce, porque las horas locales pueden ser ambiguas debido a las reglas del Horario de Verano.

$tz->is_dst_for_datetime( $dt )

Dado un "DateTime" objeto, este método devuelve verdadero si el DateTime está actualmente en Horario de Verano.

$tz->name

Devuelve el nombre de la zona horaria.

$tz->short_name_for_datetime( $dt )

Dado un "DateTime" objeto, este método devuelve el "nombre corto" para la observancia y regla actuales en las que se encuentra esta fecha y hora. Estos son nombres como "EST", "GMT", etc.

Se recomienda encarecidamente que no confíe en estos nombres para nada más que para la visualización. Estos nombres no son oficiales, y muchos de ellos son simplemente la invención de los mantenedores de la base de datos Olson. Además, estos nombres no son únicos. Por ejemplo, hay un "EST" tanto en -0500 como en +1000/+1100.

$tz->is_floating

Devuelve un booleano que indica si este objeto representa una zona horaria flotante, tal como la define RFC 2445 https://www.ietf.org/rfc/rfc2445.txt.

$tz->is_utc

Indica si este objeto representa la zona horaria UTC (GMT).

$tz->has_dst_changes

Indica si esta zona ha tenido alguna vez un cambio hacia y desde el Horario de Verano, ya sea en el pasado o en el futuro.

$tz->is_olson

Devuelve verdadero si la zona horaria es una zona horaria con nombre de la base de datos Olson.

$tz->category

Devuelve la parte del nombre de la zona horaria antes de la primera barra. Por ejemplo, la zona horaria "America/Chicago" devolvería "America".

DateTime::TimeZone->is_valid_name($name)

Dado una cadena, este método devuelve un valor booleano que indica si la cadena es un nombre de zona horaria válido o no. Si está usando "DateTime::TimeZone::Alias", cualquier alias que haya creado será válido.

DateTime::TimeZone->all_names

Esto devuelve una lista pre-ordenada de todos los nombres de zona horaria. Esta lista no incluye los nombres de enlace. En scalar contexto, devuelve una referencia a array mientras que en contexto de lista devuelve un array.

DateTime::TimeZone->categories

Esto devuelve una lista de todas las categorías de zonas horarias. En contexto escalar, devuelve una referencia a array, mientras que en contexto de lista devuelve un array.

DateTime::TimeZone->links

Esto devuelve un hash de todos los enlaces de zonas horarias, donde las claves son los nombres antiguos, obsoletos, y los valores son los nuevos nombres. En contexto escalar, devuelve una referencia a hash, mientras que en contexto de lista devuelve un hash.

DateTime::TimeZone->names_in_category( $category )

Dada una categoría válida, este método devuelve una lista de los nombres en esa categoría, sin la parte de la categoría. Así que la lista para la categoría "America" incluiría las cadenas "Chicago", "Kentucky/Monticello" y "New_York". En contexto escalar, devuelve una referencia a array, mientras que en contexto de lista devuelve un array.

DateTime::TimeZone->countries()

Devuelve una lista ordenada de todos los códigos de país válidos (en minúsculas) que se pueden pasar a names_in_country(). En contexto escalar, devuelve una referencia a array, mientras que en contexto de lista devuelve un array.

Si necesita convertir códigos de país a nombres o viceversa, puede usar "Locale::Country" para hacerlo. Tenga en cuenta que uno de los códigos devueltos es "uk", que es un alias para el código de país "gb", y no es un código de país ISO válido.

DateTime::TimeZone->names_in_country( $country_code )

Dado un código de país ISO3166 de dos letras, este método devuelve una lista de zonas horarias usadas en ese país. El código de país puede tener cualquier formato de mayúsculas/minúsculas. En contexto escalar, devuelve una referencia a array, mientras que en contexto de lista devuelve un array.

Esta lista se devuelve en un orden vagamente basado en la geografía y la población. En general, las zonas menos usadas vienen al final, pero no hay garantías de un orden específico de una versión a la siguiente. Este orden es probablemente la mejor opción para presentar los nombres de las zonas a los usuarios finales.

DateTime::TimeZone->offset_as_seconds( $offset )

Dado un desfase como cadena, esto devuelve el número de segundos representados por el desfase como un número positivo o negativo. Devuelve "undef" si $offset no está en el rango "-99:59:59" a "+99:59:59".

Se espera que el desfase coincida con "/^([\+\-])?(\d\d?):(\d\d)(?::(\d\d))?$/" o "/^([\+\-])?(\d\d)(\d\d)(\d\d)?$/". Si no coincide con ninguno de estos, "undef" será devuelto.

Esto significa que si desea especificar las horas con un solo dígito, entonces cada elemento del desfase debe estar separado por dos puntos (:).

DateTime::TimeZone->offset_as_string( $offset, $sep )

Dado un desfase como número, esto devuelve el desfase como cadena. Devuelve "undef" si $offset no está en el rango -359999 a 359999.

También puede proporcionar un separador opcional que irá entre las partes de horas, minutos y segundos (si aplica) del desfase.

Hooks de Storable

Este módulo proporciona hooks de congelación y descongelación para "Storable" de modo que las enormes estructuras de datos de las zonas horarias de Olson no se almacenen realmente en la estructura serializada.

Si crea una subclase de "DateTime::TimeZone", heredará sus hooks, que pueden no funcionar para su módulo, así que por favor pruebe la interacción de su módulo con Storable.

CARGANDO ZONAS HORARIAS EN UN SISTEMA CON PRE-FORK

Si está ejecutando una aplicación que realiza pre-fork (por ejemplo con Starman), entonces debería intentar cargar todas las zonas horarias que necesitará en el proceso padre. Las zonas horarias se cargan bajo demanda, así que cargarlas una vez en cada hijo desperdiciará memoria que de otro modo podría ser compartida.
