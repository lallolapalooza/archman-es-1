DateTime::Format::Builder::Tutorial - Clase rápida sobre el uso de Builder

VERSIÓN

versión 0.83

CREAR UNA CLASE

Como saben la mayoría de las personas que escriben módulos, se comienza un paquete con una declaración de paquete y alguna indicación de la versión del módulo:

package DateTime::Format::ICal; our $VERSION = '0.04';

Después de eso, se llama a Builder con algunas opciones. Solo hay unas pocas (detalladas más adelante). Por ahora, solo estamos interesados en parsers.

use DateTime::Format::Builder ( parsers => {...} );

La parsers opción toma una referencia a un hash de nombres de métodos y especificaciones:

parsers => {
        parse_datetime => ... ,
        parse_datetime_with_timezone => ... ,
        ...
    }

Builder creará métodos en tu clase, cada método siendo un analizador (parser) que sigue las especificaciones dadas. Es fuertemente recomendado que un método sea llamado parse_datetime, ya sea un método creado por Builder o uno de los tuyos propios.

Además de crear cualquiera de los métodos analizadores, también crea un método "new" que puede instanciar (o clonar) objetos de esta clase. Este comportamiento puede modificarse con la constructor opción, pero no necesitamos saber eso todavía.

Cada valor correspondiente a un nombre de método en la lista de analizadores es o bien una especificación única, o una lista de especificaciones. Comenzaremos con el caso simple.

parse_briefdate => { params => [qw( year month day )], regex =>
    qr/^(\d\d\d\d)(\d\d)(\d\d)$/, },

Esto resultará en un método llamado parse_briefdate que tomará cadenas en la forma 20040716 y devolverá objetos DateTime que representan esa fecha. Un usuario de la clase podría escribir:

use DateTime::Format::ICal;
my $date = '19790716';
my $dt   = DateTime::Format::ICal->parse_briefdate($date);
print "My birth month is ", $dt->month_name, "\n";

El "regex" se aplica a la cadena de entrada, y si coincide, entonces $1, $2, ... se mapean a los params dados y se pasan a "DateTime->new". Esencialmente:

my $rv = DateTime->new( year => $1, month => $2, day => $3 );

Hay cosas más complicadas que se pueden hacer dentro de una sola especificación, pero las cubriremos más adelante.

A menudo, querrás que un método pueda tomar una cadena y ejecutarla contra múltiples especificaciones de analizador. Sería muy molesto si el usuario tuviera que averiguar en qué formato estaba la cadena datetime y luego cuál era el método más apropiado.

Así que, Builder te permite especificar múltiples especificaciones:

parse_datetime => [
    {
        params => [qw( year month day hour minute second )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour minute )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
    },
    {
        params => [qw( year month day )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
    },
],

Es una referencia a un array de especificaciones. Se creará un analizador que intentará cada una de estas especificaciones secuencialmente, en el orden que especificaste.

Hay un defecto con esto, sin embargo. En este ejemplo, estamos construyendo un analizador para datetimes de ICal. Se puede colocar un id de zona horaria al inicio de un datetime de ICal. Podrías extraer un id así con el siguiente código:

if ( $date =~ s/^TZID=([^:]+):// ) {
    $time_zone = $1;
}
# Z at end means UTC
elsif ( $date =~ s/Z$// ) {
    $time_zone = 'UTC';
}
else {
    $time_zone = 'floating';
}

$date terminaría sin el id, y $time_zone contendría algo apropiado para dar al método set_time_zone de DateTime, o al argumento time_zone .

Pero cómo meter este fragmento de código en tu analizador. Podrías verse tentado a llamar al analizador de otra manera y construir un pequeño envoltorio. No hay necesidad, sin embargo, porque se proporciona una opción para preprocesar fechas:

parse_datetime => [
    [ preprocess => \&_parse_tz ],    # Only changed line!
    {
        params => [qw( year month day hour minute second )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour minute )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
    },
    {
        params => [qw( year month day )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
    },
],

Esto hará necesario que _parse_tz sea escrito, y esa rutina se ve así:

sub _parse_tz {
    my %args = @_;
    my ( $date, $p ) = @args{qw( input parsed )};
    if ( $date =~ s/^TZID=([^:]+):// ) {
        $p->{time_zone} = $1;
    }
    # Z at end means UTC
    elsif ( $date =~ s/Z$// ) {
        $p->{time_zone} = 'UTC';
    }
    else {
        $p->{time_zone} = 'floating';
    }
    return $date;
}

En la entrada se le da un hash que contiene dos elementos: la fecha de entrada y una referencia a un hash que se usará en el análisis. El valor de retorno de la rutina es contra lo que se ejecutarán las especificaciones del analizador, y cualquier cosa en el parsed hash ($p en el ejemplo) será puesta en la llamada a "DateTime->new(...)".

Así que, ahora tenemos un analizador de ICal que funciona felizmente. Analiza los formatos variados y también puede manejar zonas horarias. ¿Hay algo más que necesite hacer? No. Pero podemos hacerlo funcionar más eficientemente.

Actualmente, las especificaciones se prueban secuencialmente. Sin embargo, cada una aplica a cadenas de longitudes particulares. Así que podríamos ser eficientes y hacer que el analizador solo pruebe las cadenas dadas contra un analizador que maneje esa longitud de cadena. Nuevamente, Builder lo hace fácil:

parse_datetime => [
    [ preprocess => \&_parse_tz ],
    {
        length => 15,    # We handle strings of exactly 15 chars
        params => [qw( year month day hour minute second )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
    },
    {
        length => 13,                                # exactly 13 chars...
        params => [qw( year month day hour minute )],
        regex => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
    },
    {
        length => 11,                                    # 11..
        params => [qw( year month day hour )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
    },
    {
        length => 8,                                     # yes.
        params => [qw( year month day )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
    },
],

Ahora el analizador creado creará un analizador que solo ejecuta especificaciones contra cadenas apropiadas.

Así que nuestro código completo se ve así:

package DateTime::Format::ICal;
use strict;
our $VERSION = '0.04';
use DateTime::Format::Builder (
    parsers => {
        parse_datetime => [
            [ preprocess => \&_parse_tz ],
            {
                length => 15,
                params => [qw( year month day hour minute second )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
            },
            {
                length => 13,
                params => [qw( year month day hour minute )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
            },
            {
                length => 11,
                params => [qw( year month day hour )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
            },
            {
                length => 8,
                params => [qw( year month day )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
            },
        ],
    },
);
sub _parse_tz {
    my %args = @_;
    my ( $date, $p ) = @args{qw( input parsed )};
    if ( $date =~ s/^TZID=([^:]+):// ) {
        $p->{time_zone} = $1;
    }
    # Z at end means UTC
    elsif ( $date =~ s/Z$// ) {
        $p->{time_zone} = 'UTC';
    }
    else {
        $p->{time_zone} = 'floating';
    }
    return $date;
}
1;

Y ese es un analizador de ICal. El módulo DateTime::Format::ICal real también incluye métodos de formateo y análisis para duraciones, pero Builder no soporta esos todavía. Un reemplazo directo (al momento de escribir el reemplazo) se puede encontrar en el directorio examples de la distribución de Builder, junto con variantes similares de otrosotros módulos comunes.
