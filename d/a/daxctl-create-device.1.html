NOMBRE

daxctl-create-device - Crear un dispositivo devdax

SINOPSIS

daxctl create-device [<opciones>]

EJEMPLOS

•Crea dax0.1 con un tamaño de 4G
# daxctl create-device -s 4G
[
  {
    "chardev":"dax0.1",
    "size":4294967296,
    "target_node":0,
    "mode":"devdax"
  }
]
•Crea dispositivos con tamaño totalmente disponible en todas las regiones
# daxctl create-device -u
[
  {
    "chardev":"dax0.1",
    "size":"15.63 GiB (16.78 GB)",
    "target_node":0,
    "mode":"devdax"
  },
  {
    "chardev":"dax1.1",
    "size":"15.63 GiB (16.78 GB)",
    "target_node":1,
    "mode":"devdax"
  }
]
•Crea dax0.1 con tamaño totalmente disponible en la región id 0
# daxctl create-device -r 0 -u
{
  "chardev":"dax0.1",
  "size":"15.63 GiB (16.78 GB)",
  "target_node":0,
  "mode":"devdax"
}

DESCRIPCIÓN

Crea un dispositivo dax en modo devdax en regiones dinámicas. El resultado también puede ser convertido al modo system-ram, que dispone que el rango dax sea insertado en caliente en el sistema como memoria regular.

daxctl create-device espera que la BIOS o el kernel definan un rango en el mapa de memoria EFI con EFI_MEMORY_SP. Los rangos resultantes significan que el 100% de su capacidad está reservada para aplicaciones.

OPCIONES

-r, --region=

Restringe la operación a los dispositivos que pertenecen a la(s) región(es) especificada(s). Una región dax de dispositivo es un rango contiguo de memoria que aloja uno o más dispositivos /dev/daxX.Y, donde X es el id de la región y Y es el id de la instancia del dispositivo.

-s, --size=

Para regiones que soportan la creación de dispositivos dax, establece el tamaño del dispositivo en bytes. De lo contrario, por defecto será el tamaño máximo especificado por la región. Esta opción soporta los sufijos "k" o "K" para KiB, "m" o "M" para MiB, "g" o "G" para GiB y "t" o "T" para TiB. 
El tamaño debe ser un múltiplo de la alineación de la región.

-a, --align

Las aplicaciones que desean establecer mapeos de memoria dax con entradas de tabla de páginas mayores que el tamaño de página base del sistema (4K en x86) necesitan un dispositivo suficientemente alineado. Por defecto es 2M. Tenga en cuenta que el modo "devdax" impone que todos los mapeos estén alineados a este valor, es decir, falla los intentos de mapeo no alineados.

--input

Las aplicaciones que desean seleccionar rangos asignados a una instancia de dax de dispositivo, o que desean establecer dispositivos creados previamente, pueden pasar un archivo JSON de entrada. La opción de archivo permite al usuario pasar un objeto JSON similar al que se enumera con "daxctl list". 
El nombre del dispositivo no se recrea, pero si se pasa un "chardev"
en el archivo JSON, se usará para obtener el id de la región.
Tenga en cuenta que el contenido JSON del archivo no puede ser un
array de objetos JSON, sino un único objeto JSON, es decir, sin
los corchetes del array envolvente.

-u, --human

Por defecto, el comando emitirá datos de enteros crudos, amigables para máquinas. En cambio, con esta bandera, los números que representan el tamaño del almacenamiento se formatearán como cadenas legibles por humanos con unidades, otros campos se convertirán a cadenas hexadecimales.

-v, --verbose

Emitir más mensajes de depuración
