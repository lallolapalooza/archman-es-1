DAXCTL-MIGRATE-DEVICE-MODEL(1) Manual de daxctl DAXCTL-MIGRATE-DEVICE-MODEL(1)

NOMBRE

daxctl-migrate-device-model - Optar por el modelo de dispositivo /sys/bus/dax, permitiendo controladores alternativos de instancias de Device-DAX.

SINOPSIS

daxctl migrate-device-model

Organizar modprobe para deshabilitar dax_pmem_compat, si está presente, y en su lugar implementar el módulo dax_pmem para convertir al modelo /sys/bus/dax. Las versiones del kernel anteriores a la v5.1 pueden no ser compatibles con /sys/bus/dax, en cuyo caso el resultado de este comando es una operación nula hasta que el kernel sea actualizado. La motivación para cambiar de /sys/class/dax a /sys/bus/dax es permitir controladores alternativos para instancias de Device-DAX, en particular el controlador dax_kmem.

Por defecto, device-dax publica un dispositivo de carácter /dev/daxX.Y para que el espacio de usuario pueda mapear directamente la memoria diferenciada por rendimiento. Esto está bien si la memoria va a ser consumida / gestionada exclusivamente por el espacio de usuario. Alternativamente, un administrador puede querer que el kernel gestione la memoria, hacerla disponible a través de malloc(), permitir el aprovisionamiento excesivo y/o aplicar esquemas de control de recursos basados en el kernel a la memoria. En ese caso, la memoria respaldada por una instancia dada de Device-DAX puede ser asignada al controlador dax_kmem, que organiza el subsistema principal de gestión de memoria del kernel para asumir la gestión del rango de memoria.

Este comportamiento es opcional (opt-in) para tener en cuenta aplicaciones / scripts existentes que puedan estar codificados para usar /sys/class/dax. Se han enviado correcciones a aplicaciones conocidas por tener estas dependencias directas *FIO* http://git.kernel.dk/cgit/fio/commit/?id=b08e7d6b18b4 *PMDK* https://github.com/pmem/pmdk/commit/91bc8620884e, sin embargo, puede haber otras y un propietario del sistema debe ser consciente del potencial de regresión de scripts, aplicaciones que consumen Device-DAX, o binarios daxctl más antiguos.

La política de modprobe establecida por esta utilidad se vuelve efectiva después del próximo reinicio, o después de que todos los módulos relacionados con DAX hayan sido eliminados y recargados con "udevadm trigger"
