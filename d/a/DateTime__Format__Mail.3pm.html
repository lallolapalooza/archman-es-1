DateTime::Format::Mail(3) Documentación de Perl aportada por el usuario DateTime::Format::Mail(3)

NOMBRE

DateTime::Format::Mail - Convierte entre DateTime y los formatos RFC2822/822

SINOPSIS

use DateTime::Format::Mail;
# Desde RFC2822 mediante un método de clase:
my $datetime = DateTime::Format::Mail->parse_datetime(
    "Sat, 29 Mar 2003 22:11:18 -0800"
);
print $datetime->ymd('.'); # "2003.03.29"
#  o mediante un objeto

my $pf = DateTime::Format::Mail->new();
print $pf->parse_datetime(
    "Fri, 23 Nov 2001 21:57:24 -0600"
)->ymd; # "2001-11-23"
# De vuelta a la fecha RFC2822

use DateTime;
my $dt = DateTime->new(
    year => 1979, month => 7, day => 16,
    hour => 16, minute => 45, second => 20,
    time_zone => "Australia/Sydney"
);
my $str = DateTime::Format::Mail->format_datetime( $dt );
print $str; # "Mon, 16 Jul 1979 16:45:20 +1000"
# o mediante un objeto
$str = $pf->format_datetime( $dt );
print $str; # "Mon, 16 Jul 1979 16:45:20 +1000"

DESCRIPCIÓN

Las RFC 2822 y 822 especifican los formatos de fecha que deben usarse para el correo electrónico. Este módulo analiza y genera tales fechas.

La RFC2822 (abril de 2001) introduce un formato de fecha ligeramente diferente al utilizado por la RFC822 (agosto de 1982). La corrección principal es que el formato preferido es más limitado y, por lo tanto, más fácil de analizar programáticamente.

A pesar de la facilidad para generar y analizar fechas RFC822 y RFC2822 perfectamente válidas, la gente sigue cometiendo errores. Por lo tanto, este módulo proporciona cuatro cosas para quienes manejan fechas de correo:

1.
Un analizador estricto que solo aceptará fechas RFC2822, para que puedas ver dónde estás en lo correcto.
2.
Un formateador estricto, para que puedas generar lo correcto desde el principio.
3.
Un analizador laxo, para que puedas tomar la salida defectuosa de otros programas y convertirla en algo útil. Esto incluye varios errores menores, así como algunos errores algo más extraños. El archivo t/sample_dates en la distribución de este módulo debería darte una idea de lo que es válido, mientras que t/invalid.t debería hacer lo mismo con lo que no lo es. Aquellos considerados como inválidos son simplemente un poco demasiado extraños para
ser permitidos.
4.

Interoperabilidad con el resto de la suite de DateTime. Estos son un conjunto de módulos para manejar fechas de una manera moderna y precisa. En particular, hacen que sea trivial analizar, manipular y luego formatear fechas. Cambiar de zona horaria es muy fácil, y convertir entre formatos es sencillo.

Como dirección futura, estoy contemplando un analizador aún más estricto que solo acepte fechas sin elementos obsoletos.

CONSTRUCTORES

new Crea una nueva instancia de "DateTime::Format::Mail"

. Esto generalmente no es necesario para operaciones simples. Si deseas usar un estilo de análisis diferente al del analizador predeterminado, estricto, necesitarás crear un objeto.

my $parser = DateTime::Format::Mail->new() my $copy = $parser->new();

Si se llama en un objeto existente, entonces clona el objeto.

  • Tiene dos parámetros con nombre opcionales. "loose"
  • debe ser un valor verdadero si quieres un analizador laxo; de lo contrario, no lo especifíques o dale un valor falso. "year_cutoff"
debe ser un entero mayor o igual a cero que especifique el año de corte. Consulta "set_year_cutoff" para más detalles.

my $loose = DateTime::Format::Mail->new( loose => 1 ); my $post_2049 = DateTime::Format::Mail->new( year_cutoff => 60 );

clone Para aquellos que prefieren clonar explícitamente mediante un método llamadoclone()

. Si se llama como método de clase, morirá.

my $clone = $original->clone();

MÉTODOS DE ANÁLISIS

Estos métodos funcionan tanto en nuestros objetos como en métodos de clase.

loose, strict

Estos métodos establecen la rigurosidad del análisis.

my $parser = DateTime::Format::Mail->new; $parser->loose; $parser->strict; # (el predeterminado) my $p = DateTime::Format::Mail->new->loose;

parse_datetime Dada una cadena de fecha y hora RFC2822 o 822, devuelve un objeto "DateTime"

que representa esa fecha y hora. Las cadenas que no se puedan analizar harán que el método muera.

Consulta la sinopsis para ver ejemplos.

set_year_cutoff

Los años de dos dígitos se tratan como válidos en la traducción laxa y se traducen a una cifra 19xx o 20xx. Por defecto, siguiendo la especificación de la RFC2822, si el año es mayor que '49', se trata como si estuviera en el siglo XX (19xx). Si es menor o igual, entonces en el siglo XXI (20xx). Es decir, 50 se convierte en 1950 mientras que 49 es 2049. set_year_cutoff()

te permite modificar este comportamiento especificando un corte diferente.

El valor de retorno es el propio objeto.

$parser->set_year_cutoff( 60 );

year_cutoff

Devuelve el corte actual. Puede usarse como método de clase u objeto.

my $cutoff = $parser->set_year_cutoff;

default_cutoff

Devuelve el corte predeterminado. Un método útil para sobreescribir en subclases.

my $default = $parser->default_cutoff;

fix_year

Toma un año y lo devuelve normalizado.

my $fixed = $parser->fix_year( 3 );

MÉTODOS DE FORMATEO

format_datetime Dado un objeto "DateTime"

, devuélvelo como una cadena compatible con RFC2822.

use DateTime; use DateTime::Format::Mail; my $dt = DateTime->new( year => 1979, month => 7, day => 16, time_zone => 'UTC' ); my $mail = DateTime::Format::Mail->format_datetime( $dt ); print $mail, "\n"; # o mediante un objeto my $formatter = DateTime::Format::Mail->new(); my $rfcdate = $formatter->format_datetime( $dt ); print $rfcdate, "\n";
