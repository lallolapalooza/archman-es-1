daemon(3) Manual de funciones de biblioteca daemon(3)

NOMBRE

daemon - ejecutarse en segundo plano

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int daemon(int nochdir, int noclose);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

daemon():

    Desde glibc 2.21:
        _DEFAULT_SOURCE
    En glibc 2.19 y 2.20:
        _DEFAULT_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)
    Hasta glibc 2.19 inclusive:
        _BSD_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)

DESCRIPCIÓN

La función daemon() es para programas que desean desvincularse de la terminal de control y ejecutarse en segundo plano como demonios del sistema.

Si nochdir es cero, daemon() cambia el directorio de trabajo actual del proceso al directorio raíz ("/"); de lo contrario, el directorio de trabajo actual permanece sin cambios.

Si noclose es cero, daemon() redirige la entrada estándar, la salida estándar y el error estándar a /dev/null; de lo contrario, no se realizan cambios en estos descriptores de archivo.

VALOR DE RETORNO

(Esta función bifurca y, si fork(2) tiene éxito, el proceso padre llama a _exit(2), de modo que los errores posteriores solo los ve el hijo). En caso de éxito, daemon() devuelve cero. Si ocurre un error, daemon() devuelve -1 y establece errno a cualquiera de los errores especificados para fork(2) y setsid(2).

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, ver attributes(7).

Interfaz Atributo Valor
daemon () Seguridad de hilos MT-Safe

VERSIONES

Una función similar aparece en los BSD.

La implementación de glibc también puede devolver -1 cuando /dev/null existe pero no es un dispositivo de caracteres con los números mayor y menor esperados. En este caso, errno no necesita estar establecido.

ESTANDARES

Ninguno.

HISTORIA

4.4BSD.

ERRORES CONOCIDOS

La implementación de esta función en la biblioteca GNU C se tomó de BSD y no emplea la técnica de doble bifurcación (es decir, fork(2), setsid(2), fork(2)) que es necesaria para garantizar que el proceso demonio resultante no sea un líder de sesión. En su lugar, el demonio resultante es un líder de sesión. En sistemas que siguen la semántica de System V (por ejemplo, Linux), esto significa que si el demonio abre una terminal que no es ya una terminal de control para otra sesión, entonces esa terminal se convertirá inadvertidamente en la terminal de control para el demonio.

VER TAMBIÉN

fork(2), setsid(2), daemon(7), logrotate(8)
