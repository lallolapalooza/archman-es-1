darkman(1) Manual de comandos generales darkman(1)

NOMBRE

darkman - controlar las transiciones de modo oscuro y claro

SINOPSIS

darkman [OPCIONES] COMANDO

DESCRIPCIÓN

darkman se ejecuta en segundo plano y activa el modo oscuro al atardecer, y lo desactiva nuevamente al amanecer. darkman no está diseñado para ser utilizado interactivamente: está diseñado para configurarse una vez y ejecutarse en segundo plano.

También es posible activar transiciones manuales y también es posible deshabilitar las transiciones automáticas por completo.

COMANDOS

run [--ready-fd FD]

Ejecuta el servicio darkman. Este comando está destinado a ser ejecutado por un gestor de servicios, script de inicio o similar.

El FD opcional es un descriptor de archivo donde darkman notificará cuando esté listo para recibir conexiones de clientes. El protocolo utilizado es compatible con las notificaciones de preparación para s6, dinit y systemd.

set <claro|oscuro>

Establece el modo actual.

get

Imprime el modo actual.

toggle

Cambia el modo actual.

OPCIONES

--verbose

Imprime registros detallados. Predeterminado a *verdadero* para el comando run y a *falso* para todos los demás comandos.

INTEGRACIONES

El ecosistema de escritorio de código abierto es bastante heterogéneo y hacer que diferentes aplicaciones cambien entre oscuro/claro requiere diferentes mecanismos.

Darkman busca implementar los estándares más adoptados, dejando espacio para que los usuarios conecten scripts personalizados para otras aplicaciones.

Ejecutables personalizados

Darkman puede ejecutar ejecutables personalizados (que pueden ser simples scripts de shell).

Los scripts se buscan en un directorio llamado darkman dentro de las rutas definidas en XDG_DATA_DIRS, así como en XDG_DATA_HOME. Cada script recibe el modo actual ("oscuro" o "claro") como su primer argumento ($1). Esto permite que un solo script maneje ambos modos:

#!/bin/sh
case "$1" in
oscuro) TEMA=tema-oscuro ;;
claro) TEMA=tema-claro ;;
esac
gsettings set org.ejemplo.app tema "$TEMA"

Para compatibilidad con versiones anteriores, darkman también busca los directorios dark-mode.d y light-mode.d (formato heredado). Los scripts en estos directorios se ejecutan sin argumentos. Los scripts en el directorio darkman con el mismo nombre anularán los scripts heredados.

Tanto estas variables como sus alternativas se definen en la Especificación de Directorios Base de XDG:

https://specifications.freedesktop.org/basedir-spec/latest/

Estos scripts o ejecutables pueden realizar cualquier acción requerida, como reescribir archivos de configuración para un lector de PDF, controlar un demonio de notificaciones para cambiar a un tema diferente o alternar una configuración específica del DE.

Los archivos deben tener el bit de ejecución establecido para ser considerados ejecutables. Los scripts deben tener el shebang adecuado para que el sistema operativo los ejecute correctamente.

Típicamente, las variables XDG_DATA_* mencionadas anteriormente se resolverán en el siguiente conjunto de directorios:

  • ~/.local/share/
  • /usr/local/share/
  • /usr/share/

Ejemplos de scripts (y discusión sobre cómo integrar diferentes aplicaciones) están disponibles en el repositorio del proyecto:

https://gitlab.com/WhyNotHugo/darkman

Los paquetes también pueden insertar sus propios scripts en cualquiera de estas ubicaciones, aunque se anima a los desarrolladores de aplicaciones a utilizar la API de D-Bus para determinar el modo actual y escuchar los cambios (ver más abajo para más detalles).

Portal de configuración XDG

Darkman implementa el estándar del portal de modo oscuro de XDG desktop portal. Las aplicaciones que utilizan esta API deben cambiar al modo oscuro/claro en función de la preferencia actual de darkman. Este estándar fue impulsado originalmente por los equipos de GNOME y Elementary, y actualmente es compatible con KDE, Firefox y muchos otros proyectos. Debería esperar que las aplicaciones de esos entornos lo soporten, entre otros.

Para más detalles sobre este protocolo, ver:

https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Settings.html

A partir de xdg-desktop-portal versión 1.17.0, los portales DEBEN configurarse con configuración por usuario portals.conf(5). Para forzar el uso de darkman para la configuración del modo oscuro/claro, use algo como lo siguiente:

[preferido]
org.freedesktop.impl.portal.Settings=darkman

Al usar una configuración específica del escritorio (por ejemplo: swaywm-portals.conf), tenga en cuenta que la variable de entorno XDG_CURRENT_DESKTOP debe establecerse para el xdg-desktop-portal.

El xdg-desktop-portal debería iniciarse después de que darkman se haya iniciado y esté listo. Use --ready-fd para la notificación de preparación. Esto probablemente no sea relevante en configuraciones basadas en systemd, donde el gestor de servicios interviene en la toma del bus con nombre.

Para una explicación más detallada, vea este artículo:

https://whynothugo.nl/journal/2024/04/09/darkman-portal-configuration/

API D-Bus

Para integraciones personalizadas, darkman expone una API de D-Bus que permite consultar y controlar el modo actual. Los comandos get, set y toggle utilizan esta API. El uso de esta API es también el enfoque recomendado al escribir herramientas personalizadas (por ejemplo: cambiar el modo actual basándose en la entrada de un sensor de luz).

Integraciones de terceros

Para usuarios de Emacs, existe un paquete de terceros para integrar darkman con Emacs:

https://github.com/grtcdr/darkman.el

También existe un plugin para usuarios de neovim:

https://github.com/4e554c4c/darkman.nvim

UBICACIÓN

La ubicación actual puede especificarse en el archivo de configuración. La ubicación se utiliza para calcular a qué hora ocurren el atardecer y el amanecer.

También es posible que darkman determine automáticamente la ubicación del sistema utilizando geoclue. La fiabilidad de Geoclue varía según la distribución y el entorno de escritorio, ya que a menudo es necesario configurar un agente para que funcione correctamente.

Si no se conoce la ubicación, las transiciones automáticas se deshabilitan.

CONFIGURACIÓN

Un archivo de configuración y todas las configuraciones son opcionales. La configuración se lee de ~/.config/darkman/config.yaml (o de otras rutas definidas en la especificación de bases de datos XDG), y tiene el siguiente formato:

lat: 52.3
lng: 4.8
dbusserver: true

Las siguientes configuraciones están disponibles:

•
lat, lng: Latitud y longitud respectivamente. Este valor se utilizará al iniciar, pero más tarde será reemplazado por lo que geoclue resuelva (si está habilitado). Generalmente no se necesita más de un punto decimal, como se describe en https://xkcd.com/2170/.
•
usegeoclue (true/false): Si se debe utilizar una instancia local de geoclue para determinar la ubicación actual. En algunas distribuciones/configuraciones, esto puede requerir la configuración de un agente geoclue para que funcione correctamente. PRIVACIDA

D

Darkman activará una transición de modo oscuro/claro al atardecer en la ubicación actual. Cualquier aplicación que se esté ejecutando localmente puede registrar o transmitir la hora de estas transiciones e intentar extrapolar información relacionada con la ubicación

actual.

Cuando un navegador web aplica esta transición al mismo tiempo, los sitios web abiertos también pueden registrar esta

información.

Un posible acosador o rastreador puede usar la información anterior para inferir que probablemente te encuentras en una región del mundo donde el atardecer ocurrió a una hora específica. Esta región suele ser un área amplia que abarca decenas de miles de kilómetros, pero puede ser más pequeña para ciertas ubicaciones

geográficas.

El autor de esta herramienta utiliza una ubicación configu

rada manualmente con una latitud y longitud enteras para lo
grar un equilibrio razonable entre privacidad y comodidad.
