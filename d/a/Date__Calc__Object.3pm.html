  • Modo Preciso y Modo Normalizado

    El método "accurate_mode()" controla el indicador interno que determina cuál de los dos modos fundamentales de operación se

    utiliza.

    Cuando se establece en verdadero (el valor predeterminado al inicio), los vectores delta se calculan para dar la diferencia exacta en días entre dos fechas. Las entradas "year" y "month" en el vector delta resultante son siempre cero en ese

    caso.

    Si el "modo preciso" se desactiva (cuando el indicador correspondiente se establece en falso), los vectores delta se calculan con diferencias de año

    y mes.

    Por ejemplo, la diferencia entre "[1999,12,6]" y "[2000,6,24]" es "[+0 +0 +201]" (más 201 días) en modo preciso y "[+1 -6 +18]" (más un año, menos 6 meses, más 18 días) cuando el modo preciso está desactivado, y es "[+0 +6 +18]" (más 6 meses, más 18 días) si además, el "modo normalizado" está

    activado.

    El vector delta se calcula simplemente tomando la diferencia en años, la diferencia en meses y la diferencia en días (si el "modo preciso" está desactivado y si el "modo normalizado" no se ha activado). Esto se llama semántica "uno por uno" o "modo año-mes-día"; "modo YMD" para

    abreviar.

    Cuando el "modo normalizado" se activa (mientras el "modo preciso" está desactivado), el vector delta se calcula de una manera más compleja que involucra las funciones "Add_Delta_YM()" (para "truncamiento") y "Delta_Day

    s()".

    Además, el resultado se normaliza, es decir, los valores de retorno están garantizados para tener todos el mismo signo (o para ser cero), y para todos ser "mínimos", es decir, para no exceder los rangos "[-11..+11]" para meses, "[-30..+30]" para días, "[-23..+23]" para horas y "[-59..+59]" para minutos y

    segundos.

    La regla es agregar estos valores de resultado a una fecha en orden de izquierda a derecha, y truncar fechas intermedias inválidas, como por ejemplo "[2009,2,29]", al último día válido de ese mismo mes, por ejemplo "[2009,2,28]". Esto se llama semántica "de izquierda a derecha con truncamiento" o "modo normalizado"; "modo N_YMD" para

    abreviar.

    El método "normalized_mode()" controla el indicador interno que determina si se usa el "modo YMD" (el predeterminado al inicio, por razones de compatibilidad con versiones anteriores) o el "modo

    N_YMD".

    Tenga en cuenta que también por razones de compatibilidad con versiones anteriores, este indicador solo tiene efecto cuando el "modo preciso" está

    desactivado.

    Sin embargo, ambos indicadores se pueden establecer y restablecer independientemente el uno del

    otro.

    Por lo tanto, al inicio, puede, por ejemplo, activar el "modo normalizado", sin tener ningún efecto inmediato, y desactivar el "modo preciso" más tarde, lo que instantáneamente también hace que el "modo normalizado" entre en

    vigor.

    Debido a que los años y meses tienen longitudes variables en términos de días, los modos "YMD" y "N_YMD" son menos precisos que el "modo preciso", porque estos modos dependen del contexto de las dos fechas de las que el vector delta es la diferencia. Al agregarlo a una fecha diferente, un vector delta calculado en "modo YMD" o "modo N_YMD" puede producir un desplazamiento diferente en términos de días, es decir, el resultado final a veces puede variar de manera aparentemente impredecible (o en otras situaciones puede darle el resultado esperado, a costa de representar realmente una diferencia variable en días, determinada exclusivamente por el contexto)

    .

    Tenga también cuidado de que - por la misma razón - el valor absoluto ("abs()") de un vector delta devuelve un número ficticio de días si el vector delta contiene valores distintos de cero para "year" y/o "month" (véase también la siguiente sección "Valor Absoluto" a continuación para más detalles)

    .

    Ejemp

    lo:

    La diferencia entre "[2000,1,1]" y "[2000,3,1]" es "[+0 +0 +60]" en "modo preciso" y "[+0 +2 +0]" en "modo YMD" (en este ejemplo "benigno", el resultado es el mismo en "modo YMD" y en "modo

    N_YMD").

    Cuando se agrega a la fecha "[2000,4,1]", el delta preciso produce la fecha "[2000,5,31]", mientras que el delta en "modo YMD" produce la fecha "[2000,6,1]" (que es en realidad una diferencia de 61

    días).

    Además, cuando se agrega a la fecha "[1999,1,1]", el delta preciso produce la fecha "[1999,3,2]", mientras que el delta "impreciso" en "modo YMD" produce la fecha "[1999,3,1]" (que es en realidad una diferencia de 59

    días).

    Dependiendo de lo que desee, cualquiera de los modos puede servirle

    • mejor.
  • Valor Absoluto

    Tenga en cuenta que "abs($date)" y "abs($delta)" son solo abreviaturas de ""$date->number()"" y ""$delta->numb

    er()"".

    El operador "abs()", cuando se aplica a una fecha o vector delta, devuelve el número correspondiente de días (véase más abajo para una excepción a esto), con la parte de tiempo (si está disponible) representada por una fracción después del punto

    decimal.

    En el caso de las fechas, el valor absoluto (a la izquierda del punto decimal) es el número de días desde el 1 de enero del año 1 d.C. (extrapolando el calendario gregoriano más allá de su límite "natural" de 1582 d.C.) MÁS U

    NO.

    (Es decir, el valor absoluto del 1 de enero del año 1 d.C. es

    1.)

    Excepci

    ón:

    Si "NUMBER" o "number_format()" está establecido en 0 (la configuración predeterminada), el valor absoluto de una fecha a la izquierda del punto decimal es "yyyymmdd", es decir, el número en el que los cuatro dígitos superiores corresponden al año, los dos dígitos inferiores siguientes al mes y los dos dígitos inferiores al

    día.

    En el caso de los vectores delta, el valor absoluto (a la izquierda del punto decimal) es simplemente la diferencia en días (pero véase también más

    abajo).

    Tenga en cuenta que el valor absoluto de un vector delta puede ser

    negativo.

    Si desea un valor positivo en todos los casos, aplique el operador "abs()" de nuevo, es decir, ""$posdiff = abs(abs($delta))

    ;"".

    Si el vector delta contiene valores distintos de cero para "year" y/o "month" (véase también la discusión del "Modo Preciso" en la sección anterior), una representación exacta en días no se puede calcular, porque los años y meses no tienen equivalentes fijos en

    días.

    Si a pesar de esto intenta calcular el valor absoluto de tal vector delta, se devuelve un valor ficticio, que se calcula simplemente multiplicando la diferencia de años por 12, agregando la diferencia de meses, multiplicando esta suma por 31 y finalmente agregando la diferencia de

    días.

    Tenga cuidado de que debido a esto, los valores absolutos de los vectores delta no son necesariamente

    contiguos.

    Además, dado que hay más de una manera de expresar la diferencia entre dos fechas, las comparaciones de vectores delta pueden no siempre producir el resultado

    esperado.

    Ejemp

    lo:

    La diferencia entre las dos fechas "[2000,4,30]" y "[2001,5,1]" se puede expresar como "[+1 +1 -29]", o como "[+1 +0 +

    1]".

    El primer vector delta tiene un valor absoluto de 374, mientras que el último vector delta tiene un valor absoluto de solo 373 (mientras que la verdadera diferencia en días entre las dos fechas es

    366).

    Si la fecha o el vector delta tiene una parte de tiempo, el tiempo se devuelve como una fracción de un día completo después del punto decimal como sigu

    e:

    Si "NUMBER" o "number_format()" está establecido en 0 (la configuración predeterminada) o 1, esta fracción es simplemente ".hhmmss", es decir, los dos dígitos después del punto decimal representan las horas, los dos dígitos siguientes los minutos y los últimos dos dígitos los

    segundos.

    Ten en cuenta que no puedes simplemente sumar y restar estos valores para obtener fechas o deltas significativas nuevamente, solo puedes usarlos para comparaciones (igual, no igual, menor que, mayor que, etc.). Si quieres sumar/restar, sigue

    leyendo:

    Solo cuando "NUMBER" o "number_format()" está establecido en 2, esta fracción será el número equivalente de segundos (es decir, "(((hours * 60) + minutes) * 60) + seconds") dividido por el número de segundos en un día completo (es decir, "24*60*60 = 86400"), o "0/86400", "1/86400", ... , "86399/86

    400".

    En otras palabras, la fracción (matemáticamente correcta) de un

    día.

    Puedes realizar operaciones aritméticas con estos valores de forma segura

    hasta donde la precisión interna de la implementación de tu proveedor de la bib
    • lioteca de tiempo de ejecución de C (de la que depende Perl) lo permita.
  • Renormalizando Vectores Delta

    Al sumar o restar vectores delta entre sí, la suma o resta se realiza componente por

    componente.

    Ejem

    plo: 
    [+0 +0 +0 +3 +29 +50] + [+0 +0 +0 +0 +55 +5] = [+0 +0 +0 +3 +84 +55]
[+0 +0 +0 +3 +29 +50] - [+0 +0 +0 +0 +55 +5] = [+0 +0 +0 +3 -26
    +45]

    Esto puede resultar en valores de tiempo fuera de los rangos habituales ("[-23..+23]" para horas y "[-59..+59]" para minutos y segundos)

    .

    Ten en cuenta que aunque el valor delta para los días a menudo se volverá bastante grande, es imposible renormalizar este valor porque no hay un factor de conversión constante de días a meses (¿debería ser 28, 29, 30 o

    31?).

    Si el modo preciso (consulta más arriba para saber qué es eso) está desactivado, los vectores delta también pueden contener valores distintos de cero para años y meses. Si los sumas o restas, el valor para meses puede estar fuera del rango "[-11..11]", que no está mal, pero puede parecer

    extraño.

    Por lo tanto, el método "normalize()" también renormalizará el valor "months", si y solo si el modo preciso ha sido desactivado.

    (!)

    (Por lo tanto, activa el modo preciso TEMPORALMENTE si NO quieres que ocurra la renormalización del valor "months".

    )

    Si quieres forzar que los valores de tiempo del ejemplo anterior vuelvan a sus rangos adecuados, usa el método "normalize()" de la siguiente

    manera: 
    print "[$delta]\n";
$delta->normalize();
print "[$delta]
    \n";

    Esto

    imprimirá 
    [+0 +0 +0 +3 +84 +55]
[+0 +0 +0 +4 +24
    +55]

    para el

    primero y 
    [+0 +0 +0 +3 -26 +45]
[+0 +0 +0 +2 +34
    +45]

    para el segundo vector delta del ejemplo más

    arriba.

    Ten en cuenta que los valores para días, horas, minutos y segundos garantizan tener el mismo signo después de la

    renormalización.

    En "circunstancias normales", es decir, cuando el modo preciso está activado (el predeterminado), este método solo tiene un efecto en la parte de tiempo del vector

    delta.

    Si el vector delta en cuestión no tiene una parte de tiempo, no ocurre

    nada.

    Si el modo preciso está desactivado, el valor "months" también se normaliza, es decir, si está fuera del rango "[-11..11]", múltiplos enteros de 12 se añaden al valor "years" y se restan del valor "months". Además, el valor "months" garantiza tener el mismo signo que los valores de días, horas, minutos y segundos, a menos que el valor "months" sea cero o los valores de días, horas, minutos y segundos sean todos

    cero.

    Si el objeto en cuestión es una fecha y si las advertencias están habilitadas, el mensaje "normalizing a date is a no-op" será impreso en

    STDERR.

    Si el objeto en cuestión no es un objeto "Date::Calc" válido, no ocurre

    nada.

    El método devuelve la referencia de su objeto, lo que permite encadenar llamadas a métodos, como en el siguiente

    ejemplo: 
    @time = $delta->normalize()->

  • Funciones de Callback

    Ten en cuenta que no estás restringido a los formatos integrados (numerados del 0 al 2 para "number_format()" y "number()" y del 0 al 4 para "delta_format()", "date_format()" y "string()") para convertir un objeto fecha o delta en un número o una

    cadena.

    También puedes proporcionar tu(s) propia(s) función(es) para hacerlo, para adaptarte a tu propio gusto o necesidades, pasando una referencia de subrutina al método correspondiente, es decir, "number_format()", "number()", "delta_format()", "date_format()" y "string(

    )".

    Puedes pasar un manejador a solo uno o más de estos métodos, o a todos ellos, como prefieras. Puedes usar funciones de callback diferentes, o la misma para

    todos.

    Para facilitar lo último, y para hacer que la decodificación de los varios casos sea más fácil para ti, la función de callback recibe un código de función de identificación única como su segundo

    0  =  TO_NUMBER | IS_DATE  | IS_SHORT  (number[_format])

2  =  TO_NUMBER | IS_DELTA | IS_SHORT  (number[_format])
3  =  TO_NUMBER | IS_DELTA | IS_LONG   (number[_format])
4  =  TO_STRING | IS_DATE  | IS_SHORT  (string|date_format)
5  =  TO_STRING | IS_DATE  | IS_LONG   (string|date_format)
6  =  TO_STRING | IS_DELTA | IS_SHORT  (string|delta_format)
7  =  TO_STRING | IS_DELTA | IS_LONG   (string|delta_fo
    rmat)

    El primer parámetro de la función de callback es, por supuesto, la referencia del objeto en cuestión mismo (por lo tanto, la función de callback puede ser en realidad un método de objeto - pero no un método de clase, por razones

    obvias).

    El tercer parámetro es el número del idioma (en el rango "[1..Languages()]") que siempre deberías pasar junto cuando uses cualquiera de las siguientes funciones del módulo "Date::Calc" en tu

    manejador:

    "Decode_Month()", "Decode_Day_of_Week()", "Compressed_to_Text()", "Date_to_Text()", "Date_to_Text_Long()", "Calendar()", "Month_to_Text()", "Day_of_Week_to_Text()", "Day_of_Week_Abbreviation()", "Decode_Date_EU()", "Decode_Date_US()", "Decode_Date_EU2()", "Decode_Date_US2()", "Parse_Dat

    e()".

    El manejador de callback debe devolver el número o la cadena resultante, según se

    solicite.

    cambios!

{
    my($self,$code,$lang) = @_;
    if    ($code == 0) # TO_NUMBER | IS_DATE  | IS_SHORT

    }

    }

             ( ( $self->hours() * 60 +
                 $self->minutes() ) * 60 +
                 $self->seconds() ) / 86400;

        return join( "/", $self->date() );
    }
    elsif ($code == 5) # TO_STRING | IS_DATE  | IS_LONG

    }

        return join( "|", $self->date() );
    }
    elsif ($code == 7) # TO_STRING | IS_DELTA | IS_LONG

        return join( "|", $self->datetime() );

    }

  • Languages

    Note that this module is completely transparent to the setting of a language in "Date::Calc". This means that you can choose a language in "Date::Calc" (with the "Language()" function) and all dates subsequently printed by this module will automatically be in that language - provided that you use the built-in formats of this module, or that you pass the third parameter of the callback funtion to the funtions of the "Date::Calc" module which accept

    it.

    However, this global language setting can be overridden for individual date (or delta) objects by using the OBJECT me

    thod 
    $oldlang = $date->language($newlang)
    ;

    (The global setting is not altered by this in any

    way.)

    In order to deactivate such an individual language setting (so that the global setting applies again), simply pass the value "undef" explicitly to the "language()" object

    method: 
    $date->language(undef)
    ;

    The CLASS me

    thod 
    $oldlang = Date::Calc->language($newlang)
    ;

    is just a convenient wrapper around the "Language()" function, which allows you to enter language numbers (as returned by the "Decode_Language()" function) or strings (as returned by the "Language_to_Text()" function), whatever you

    prefer.

    The "language()" method (both class and object) always returns the NAME (one of ""Language_to_Text(1..Languages())"") of the current setting (and never its

    number).

    module!

    The class method is retained only for backward compatibility and for convenience in stand-alone applications when it is guaranteed that no such conflicts can

    arise.
