Data__Hierarchy(3pm)

Paquete: perl-data-hierarchy

Licencias: GPL, PerlArtistic

Hierarchy(3) Documentación de Perl aportada por el usuario Hierarchy(3)

NOMBRE

Data::Hierarchy - Manejar datos en una estructura jerárquica

SINOPSIS

my $tree = Data::Hierarchy->new();
$tree->store ('/', {access => 'all'});
$tree->store ('/private', {access => 'auth',
                           '.note' => 'this is private'});
$info = $tree->get ('/private/somewhere/deep');
# return actual data points in list context
($info, @fromwhere) = $tree->get ('/private/somewhere/deep');
my @items = $tree->find ('/', {access => qr/.*/});
# override all children
$tree->store ('/', {'.note' => undef}, {override_sticky_descendents => 1});

DESCRIPCIÓN

Data::Hierarchy proporciona una interfaz sencilla para manipular datos heredables adjuntos a un entorno jerárquico (como un sistema de archivos).

Un uso de Data::Hierarchy es permitir que una aplicación anote rutas en un sistema de archivos real en una única estructura de datos compacta. Sin embargo, la jerarquía no necesita corresponder necesariamente a un sistema de archivos real.

Las rutas en una jerarquía se referencian con una sintaxis tipo Unix; "/" es el "directorio" raíz. (Puede especificar un carácter separador diferente a la barra cuando construya un objeto Data::Hierarchy.) Con la excepción de la ruta raíz, las rutas nunca deben contener barras finales. Puede asociar propiedades, que son pares arbitrarios de nombre/valor, con cualquier ruta. (Las propiedades no pueden contener el valor indefinido.) Por defecto, las propiedades son heredadas por las rutas hijas: así, si almacena algunos datos en "/some/path":

$tree->store('/some/path', {color => 'red'});

puede obtenerlos de nuevo en una "/some/path/below/that":

print $tree->get('/some/path/below/that')->{'color'};
# prints red

Por otro lado, las propiedades cuyos nombres comienzan con puntos no son heredadas, o son "pegajosas" (sticky):

$tree->store('/some/path', {'.color' => 'blue'});
print $tree->get('/some/path')->{'.color'};            # prints blue
print $tree->get('/some/path/below/that')->{'.color'}; # undefined

Tenga en cuenta que no necesita (y de hecho no puede) añadir explícitamente "archivos" o "directorios" a la jerarquía; simplemente añade y elimina propiedades de las rutas.

CONSTRUCTOR

Crea un nuevo objeto de jerarquía. Acepta las siguientes opciones:

sep
La cadena utilizada como separador entre niveles de ruta. Por defecto es '/'.

MÉTODOS

Métodos de instancia

"store $path, $properties, {%options}"
Dada una ruta y una referencia a un hash de propiedades, almacena las propiedades en la ruta.

A menos que la "override_descendents" opción se proporcione con un valor falso, elimina cualquier propiedad no pegajosa en un descendiente de $path con el mismo nombre.

Si la "override_sticky_descendents" opción se proporciona con un valor verdadero, elimina cualquier propiedad pegajosa en un descendiente de $path con el mismo nombre. Sobrescribir la propiedad.

Un valor de undef elimina ese valor; tenga en cuenta, sin embargo, que si un ancestro de $path define esa propiedad, el valor del ancestro será heredado allí; es decir, con:

$t->store('/a',   {k => 'top'});
$t->store('/a/b', {k => 'bottom'});
$t->store('/a/b', {k => undef});
print $t->get('/a/b')->{'k'};

imprimirá 'top'.

"get $path, [$dont_clone]"
Dada una ruta, busca todas las propiedades (pegajosas y no) y las devuelve en una referencia a un hash. Los valores son clones, a menos que pase un valor verdadero para $dont_clone.

Si se llama en contexto de lista, devuelve esa referencia a un hash seguida de todas las rutas ancestrales de $path que contienen propiedades no pegajosas (posiblemente incluyéndose a sí misma).

"find $path, $property_regexps"
Dada una ruta y una referencia a un hash de pares nombre/expresión regular, devuelve una lista de todas las rutas que son descendientes de $path (incluyéndose a sí misma) y definen en esa ruta misma (no heredadas) todas las propiedades del hash con valores que coinciden con las expresiones regulares dadas. (Puede querer usar "qr/.*/" simplemente para ver si tiene algún valor definido allí.) Las propiedades pueden ser pegajosas o no.
"merge $other_hierarchy, $path"
Dado un segundo objeto Data::Hierarchy y una ruta, copia todas las propiedades del otro objeto en $path o debajo en las rutas correspondientes del objeto sobre el que se invoca este método. Todas las propiedades del objeto sobre el que se invoca en $path o debajo son borradas primero.
"to_relative $base_path"
Dada una ruta que debe contener cada elemento de la jerarquía, devuelve un objeto especial Data::Hierarchy::Relative que representa la jerarquía relativa a esa ruta. Lo único que puede hacer con un objeto Data::Hierarchy::Relative es llamar a to_absolute($new_base_path) en él, lo que devuelve un nuevo objeto Data::Hierarchy en esa ruta base. Por ejemplo, si todo en la jerarquía está enraizado en "/home/super_project" y necesita ser movido a "/home/awesome_project", puede hacer 
$hierarchy = $hierarchy->to_relative('/home/super_project')->to_absolute('/home/awesome_project');

(Los objetos Data::Hierarchy::Relative pueden ser un formato de serialización más conveniente que los objetos Data::Hierarchy, si están rastreando el estado de algún recurso reubicable.)
