Paquete: dialog

Licencias: LGPL2.1

DIALOG() Comandos de usuario DIALOG()

NOMBRE

dialog - mostrar cuadros de diálogo desde scripts de shell

SINOPSIS

dialog --clear
dialog --create-rc archivo
dialog --print-maxsize
dialog opciones-comunes opciones-de-cuadro

DESCRIPCIÓN

Dialog es un programa que le permitirá presentar una variedad de preguntas o mostrar mensajes utilizando cuadros de diálogo desde un script de shell. Estos tipos de cuadros de diálogo están implementados (aunque no todos están necesariamente compilados en dialog):

buildlist, calendar, checklist, dselect, editbox, form, fselect, gauge, infobox, inputbox, inputmenu, menu, mixedform, mixedgauge, msgbox (mensaje), passwordbox, passwordform, pause, prgbox, programbox, progressbox, radiolist, rangebox, tailbox, tailboxbg, textbox, timebox, treeview y yesno (sí/no).

Puede poner más de un cuadro de diálogo en un script:

  • Use el token "--and-widget" para forzar a dialog a continuar al siguiente cuadro de diálogo a menos que haya presionado ESC para cancelar, o
  • Simplemente agregue los tokens para el siguiente cuadro de diálogo, creando una cadena. Dialog detiene la cadena cuando el código de retorno de un cuadro de diálogo es distinto de cero, por ejemplo, Cancelar o No (ver DIAGNÓSTICOS).

Algunos widgets, por ejemplo, checklist, escribirán texto en la salida de dialog. Normalmente es el error estándar, pero hay opciones para cambiar esto: "--output-fd", "--stderr" y "--stdout". No se escribe ningún texto si se presiona el botón Cancelar (o ESC); dialog sale inmediatamente en ese caso.

OPCIONES

Todas las opciones comienzan con "--" (dos guiones ASCII, para beneficio de aquellos que usan sistemas con soporte de localización alterado).

Un "--" por sí solo se utiliza como escape, es decir, el siguiente token en la línea de comandos no se tratará como una opción. Esto es diferente de getopt(1), que usa ese token para tratar los tokens restantes como parámetros en lugar de opciones.

dialog --title -- --No es una opción
dialog --title Esto -- --título no es una opción

Dialog no utiliza parámetros y utiliza su propio analizador de opciones.

Cuando una opción común (por ejemplo, no de widget) se repite, la última encontrada es la que se utiliza. Las opciones booleanas se manejan especialmente para que puedan ser canceladas, agregando (u omitiendo) un modificador "no" después del guion "--" inicial. Por ejemplo, --no-shadow se documenta aquí, pero --shadow también se acepta.

La opción "--args" le dice a dialog que liste los parámetros de la línea de comandos al error estándar. Esto es útil al depurar scripts complejos que usan "--" y "--file", ya que la línea de comandos puede ser reescrita a medida que estos se expanden.

La opción "--file" le dice a dialog que lea los parámetros del archivo con el nombre dado como su valor.

dialog --file archivodeparametros

Los espacios en blanco que no están entre comillas dobles se descartan (use barras invertidas para citar caracteres individuales). El resultado se inserta en la línea de comandos, reemplazando "--file" y su valor de opción. La interpretación de la línea de comandos se reanuda desde ese punto. Si archivodeparametros comienza con "&", dialog interpreta el texto siguiente como un número de descriptor de archivo en lugar de un nombre de archivo.

La mayoría de los widgets aceptan parámetros de altura y anchura, que se pueden usar para dimensionar automáticamente el widget para acomodar valores de mensaje de varias líneas:

  • Si el parámetro es negativo, dialog usa el tamaño de la pantalla.
  • Si el parámetro es cero, dialog usa el tamaño mínimo para que el widget muestre el mensaje y los datos.
  • De lo contrario, dialog usa el tamaño dado para el widget.

Opciones Comunes

La mayoría de las opciones comunes se restablecen antes de procesar cada widget.

--ascii-lines
En lugar de dibujar líneas gráficas alrededor de los cuadros, dibuja "+" y "-" ASCII en el mismo lugar. Ver también "--no-lines".
--aspect ratio
Esto le da cierto control sobre las dimensiones del cuadro al usar el dimensionamiento automático (especificando 0 para altura y anchura). Representa anchura / altura. El valor predeterminado es 9, lo que significa 9 caracteres de anchura por cada 1 línea de altura.
--backtitle backtitle
Especifica una cadena de backtitle que se mostrará en el fondo, en la parte superior de la pantalla.
--begin y x
Especifica la posición de la esquina superior izquierda de un cuadro de diálogo en la pantalla.
--cancel-label cadena
Anula la etiqueta utilizada para los botones "Cancelar".
--clear
Borra la pantalla del widget, manteniendo solo el fondo screen_color. Úselo cuando combine widgets con "--and-widget" para borrar el contenido de un widget anterior en la pantalla, para que no se vea debajo del contenido de un widget siguiente. Entienda esto como el complemento de "--keep-window". Para comparar los efectos, use estos:
Los tres widgets visibles, efecto de escalera, ordenados 1,2,3:
dialog \
                               --begin 2 2 --yesno "" 0 0 \
    --and-widget               --begin 4 4 --yesno "" 0 0 \
    --and-widget               --begin 6 6 --yesno "" 0 0
Solo el último widget queda visible:
dialog \
                 --clear       --begin 2 2 --yesno "" 0 0 \
    --and-widget --clear       --begin 4 4 --yesno "" 0 0 \
    --and-widget               --begin 6 6 --yesno "" 0 0
Los tres widgets visibles, efecto de escalera, ordenados 3,2,1:
dialog \
                 --keep-window --begin 2 2 --yesno "" 0 0 \
    --and-widget --keep-window --begin 4 4 --yesno "" 0 0 \
    --and-widget               --begin 6 6 --yesno "" 0 0
Primer y tercer widget visibles, efecto de escalera, ordenados 3,1:
dialog \
                 --keep-window --begin 2 2 --yesno "" 0 0 \
    --and-widget --clear       --begin 4 4 --yesno "" 0 0 \
    --and-widget               --begin 6 6 --yesno "" 0 0
Tenga en cuenta que si desea restaurar los colores originales de la consola y enviar el cursor a la esquina superior izquierda después de que el programa dialog haya salido, use el comando clear(1). Por el contrario, si desea borrar la pantalla y enviar el cursor a la esquina inferior izquierda después de que el programa dialog haya salido, use la opción "--erase-on-exit".
--color-mode código
Extiende la opción --colors al contenido de programbox, tailbox y textbox. Use el código "2" para esta característica.
--colors
Interpreta las secuencias "\Z" incrustadas en el texto del diálogo por el carácter siguiente, que le indica a dialog que establezca colores o atributos de video:
  • 0 a 7 son los números de color ANSI utilizados en curses: negro, rojo, verde, amarillo, azul, magenta, cian y blanco respectivamente.
  • Negrita se establece con 'b', se restablece con 'B'.
  • Invertido se establece con 'r', se restablece con 'R'.
  • Subrayado se establece con 'u', se restablece con 'U'.
  • La configuración es acumulativa, por ejemplo, "\Zb\Z1" hace que el texto siguiente sea negrita (quizás brillante) rojo.
  • Restaure la configuración normal con "\Zn".

--no-mouse

--no-ok
Suprime el botón "OK", para que no se muestre. Un script aún puede probar si el usuario pulsó la tecla "Intro" para aceptar los datos:
•
La tecla "Intro" siempre se maneja como el botón "OK" cuando se utiliza la opción --no-ok. Es decir, por defecto está enlazada a la tecla virtual LEAVE.
Cuando no se utiliza --no-ok, puede usar la tecla Tab para mover el cursor a través de los campos y botones del widget. En ese caso, la tecla "Intro" activa el botón actual si el cursor está posicionado en un botón.
•
Para contemplar el caso en que desee activar un botón al usar --no-ok, existe otra tecla virtual LEAVE, que activa el botón actual. Por defecto, ^D (EOF) está enlazada a esa tecla.
--no-shadow
Suprime las sombras que se dibujarían a la derecha e inferior de cada cuadro de diálogo.
--no-tags
Algunos widgets (checklist, inputmenu, radiolist, menu) muestran una lista con dos columnas (una "etiqueta" y una "descripción"). La etiqueta es útil para scripting, pero puede no ayudar al usuario. La opción --no-tags (de Xdialog) puede usarse para suprimir la columna de etiquetas de la visualización. A diferencia de la opción --no-items, esto no afecta a los datos que se leen del script.
Xdialog no muestra la columna de etiquetas para los widgets análogos buildlist y treeview; dialog hace lo mismo.
Normalmente dialog le permite moverse rápidamente a las entradas de la lista mostrada, coincidiendo un solo carácter con el primer carácter de la etiqueta. Cuando se da la opción --no-tags, dialog coincide con el primer carácter de la descripción. En cualquier caso, el carácter coincidente se resalta.
--ok-label cadena
Anula la etiqueta utilizada para los botones "OK".
--output-fd fd
Dirige la salida al descriptor de archivo dado. La mayoría de los scripts de dialog escriben en la salida estándar de error, pero los mensajes de error también pueden escribirse allí, dependiendo de su script.

--print-version
Imprime la versión de dialog en la salida de dialog. Esto se puede usar solo, sin otras opciones. No provoca que dialog salga por sí mismo.
--quoted
Normalmente dialog entrecomilla las cadenas devueltas por checklist, así como el texto de ayuda del elemento. Utilice esta opción para entrecomillar todos los resultados de cadena según sea necesario (es decir, si la cadena contiene espacios en blanco o un carácter de comilla simple o doble).
--reorder
Por defecto, el widget buildlist utiliza el mismo orden para la salida (derecha) que para la entrada (izquierda). Utilice esta opción para indicar a dialog que utilice el orden en el que un usuario agrega selecciones a la lista de salida.
--scrollbar
Para los widgets que contienen un conjunto de datos desplazable, dibuja una barra de desplazamiento en su margen derecho. Esto no responde al ratón.
--separate-output
Para ciertos widgets (buildlist, checklist, treeview), produce la salida línea por línea, sin comillas. Esto facilita el análisis por parte de otro programa.
--separate-widget cadena
Especifica una cadena que separará la salida en la salida de dialog de cada widget. Esto se utiliza para simplificar el análisis del resultado de un diálogo con varios widgets. Si no se proporciona esta opción, la cadena separadora predeterminada es un carácter de tabulación.
--single-quoted
Utiliza comillas simples según sea necesario (y ninguna comilla si no es necesario) para la salida de checklist, así como el texto de ayuda del elemento.
Si esta opción no está configurada, dialog puede usar comillas dobles alrededor de cada elemento. En cualquier caso, dialog agrega barras invertidas para que la salida sea útil en scripts de shell.
Se necesitarían comillas simples si la cadena contiene espacios en blanco o un carácter de comilla simple o doble.
--size-err
Comprueba el tamaño resultante de un cuadro de diálogo antes de intentar usarlo, imprimiendo el tamaño resultante si es mayor que la pantalla. (Esta opción es obsoleta, ya que todas las llamadas a new-window se comprueban).
--sleep secs
Duerme (espera) durante el número de segundos dado después de procesar un cuadro de diálogo.
--stderr
Dirige la salida a la salida estándar de error. Este es el valor predeterminado, ya que curses normalmente escribe actualizaciones de pantalla en la salida estándar.
--stdout
Dirige la salida a la salida estándar. Esta opción se proporciona por compatibilidad con Xdialog; sin embargo, su uso en scripts portátiles no se recomienda, ya que curses normalmente escribe sus actualizaciones de pantalla en la salida estándar. Si usa esta opción, dialog intenta reabrir la terminal para poder escribir en la pantalla. Dependiendo de la plataforma y su entorno, eso puede fallar.
--tab-correct
Convierte cada carácter de tabulación en uno o más espacios (para el widget textbox; de lo contrario, en un solo espacio). De lo contrario, las tabulaciones se representan según la interpretación de la biblioteca curses. La opción --no-collapse deshabilita la expansión de tabulaciones.
--tab-len n
Especifica el número de espacios que ocupa un carácter de tabulación si se da la opción "--tab-correct". El valor predeterminado es 8. Esta opción solo es efectiva para el widget textbox.
--time-format formato
Si el host proporciona strftime, esta opción le permite especificar el formato de la hora impresa para el widget --timebox. Los valores del día, mes y año en este caso son para la hora local actual.
--timeout secs
Tiempo de espera si no hay respuesta del usuario en el número de segundos dado. Un tiempo de espera de cero segundos se ignora.
Normalmente, un tiempo de espera provoca que se introduzca un carácter ESC en el widget actual, cancelándolo. Otros widgets aún pueden estar en la pantalla; estos no se cancelan. Establezca la variable de entorno DIALOG_TIMEOUT para indicar a dialog que salga directamente en su lugar, es decir, cancelando todos los widgets en la pantalla.
Esta opción es ignorada por el widget "--pause". También se anula si se utiliza la opción en segundo plano "--tailboxbg" para configurar varios widgets concurrentes.

ASIGNACIONES DE TECLAS

Puedes anular o agregar asignaciones de teclas en dialog agregando al archivo de configuración. El comando bindkey de Dialog asigna teclas individuales a su codificación interna.

bindkey widget curses_key dialog_key

El nombre del widget puede ser “*” (todos los widgets), o widgets específicos como textbox. Las asignaciones de widgets específicos anulan las asignaciones de “*”. Las asignaciones definidas por el usuario anulan las asignaciones integradas.

La curses_key se puede expresar de diferentes formas:

  • Puede ser cualquiera de los nombres derivados de curses.h, por ejemplo, “HELP” de “KEY_HELP”.
  • Dialog también reconoce caracteres de control ANSI como “^A”, “^?”, así como controles C1 como “~A” y “~?”.
  • Finalmente, dialog permite escapes de barra invertida como en C. Estos pueden ser valores de caracteres octales como “\033” (el carácter de escape ASCII), o los caracteres listados en esta tabla:
Escapado Real
\b retroceso (backspace)
\f salto de página (form feed)
\n nueva línea (line feed)
\r retorno de carro (carriage return)
\s espacio
\t tabulación (tab)
\^ “^” (acento circunflejo)
\? “?” (signo de interrogación)
\\ “\” (barra invertida)

Los nombres de códigos de tecla internos de Dialog corresponden al tipo DLG_KEYS_ENUM en dlg_keys.h, por ejemplo, “HELP” de “DLGK_HELP”.

Ejemplo

Normalmente dialog utiliza teclas diferentes para navegar entre los botones y el área de edición de un cuadro de diálogo, y para navegar dentro del área de edición. Es decir, la tabulación (y la tabulación inversa) recorren los botones (o entre los botones y el área de edición), mientras que las teclas de flecha recorren los campos dentro del área de edición. Las tabulaciones también se reconocen como un caso especial para navegar entre widgets, por ejemplo, al usar múltiples widgets tailboxbg.

Algunos usuarios pueden desear usar la misma tecla para navegar dentro del área de edición que para navegar entre botones. El widget form está escrito para admitir este tipo de redefinición de teclas, agregando un grupo especial en dlgk_keys.h para “form” (izquierda/derecha/siguiente/anterior). Aquí hay un ejemplo de asignación que demuestra cómo hacer esto:

bindkey formfield TAB  form_NEXT
bindkey formbox   TAB  form_NEXT
bindkey formfield BTAB form_prev
bindkey formbox   BTAB form_prev

Este tipo de redefinición no sería útil en otros widgets, por ejemplo, calendar, debido al gran número potencial de campos a recorrer.

El estado de salida está sujeto a ser anulado por variables de entorno. Los valores predeterminados y las variables de entorno correspondientes que pueden anularlos son:

0
si se presiona el botón YES o OK (DIALOG_OK).
1
si se presiona el botón No o Cancel (DIALOG_CANCEL).
2
si se presiona el botón Help (DIALOG_HELP),
excepto como se indica a continuación sobre DIALOG_ITEM_HELP.
3
si se presiona el botón Extra (DIALOG_EXTRA).
4
si se presiona el botón Help,
y la opción --item-help está configurada
y la variable de entorno DIALOG_ITEM_HELP está configurada a 4.
Aunque cualquiera de los códigos de salida puede ser anulado usando variables de entorno, este caso especial se introdujo en 2004 para simplificar la compatibilidad. Dialog usa DIALOG_ITEM_HELP (4) internamente, pero a menos que la variable de entorno también esté configurada, la cambia a DIALOG_HELP (2) al salir.
5
si expira un tiempo de espera y la variable DIALOG_TIMEOUT está configurada a 5.
-1
si ocurren errores dentro de dialog (DIALOG_ERROR) o dialog sale porque se presionó la tecla ESC (DIALOG_ESC).
