distccd es el servidor para el compilador distribuido distcc(1). Acepta y ejecuta trabajos de compilación para clientes de red. distcc puede ejecutarse tanto sobre TCP como sobre un comando de conexión como ssh(1). Las conexiones TCP son rápidas pero relativamente inseguras. Las conexiones

SSH son seguras
pero más lentas.

Para las conexiones SSH, distccd debe estar instalado en el voluntario pero no debe ejecutarse como demonio -- se iniciará a través de SSH según sea necesario. Las conexiones SSH tienen varias ventajas: ni el cliente ni el servidor escuchan en ningún puerto nuevo; las compilaciones se ejecutan con los privilegios del usuario que las solicitó; los usuarios no autorizados no pueden acceder al servidor; y el código fuente y la salida

están protegidos durante el tránsito.

Para las conexiones TCP, distccd puede ejecutarse tanto desde un programa estilo inetd como como un servidor independiente. Se recomienda el modo independiente porque es ligeramente más eficiente y permite a distccd regular el número de trabajos entrantes. Las

opciones

--liste

n

y

--allow pueden usarse para un control de acceso basado en IP simple. distcc puede iniciarse tanto por root como por cualquier otro usuario. Si se ejecuta como root, cede privilegios y cambia al usuario especificado por la

opción

--user [[30]], o al usuario llamado "distcc", o al usuario llamado "nobody". distccd no tiene un archivo de configuración; su comportamiento se controla solo mediante opciones de línea de comandos y peticiones de los

clientes.

El método recomendado para ejecutar distccd es como servidor independiente. distccd escuchará conexiones de red y generará varios procesos hijos para

atenderlas.

Si instaló distcc usando una versión empaquetada, puede ser capaz de iniciar el servidor usando el mecanismo estándar de su sistema operativo,

como

# service distcc

start

endiente, ejecute un comando como este, ya

distccd puede ejecutarse como un demonio independiente bajo el control de otro programa como init(8) o daemontools. El super-servidor inicia distccd cuando el sistema arranca, y cada vez

que sale.

distccd debería iniciarse igual que para un servidor independiente, excepto que la

opción

--no-detach debería usarse para que el super-servidor pueda

monitorizarlo.

Por ejemplo, para añadir distccd como un proceso a Linux sysvinit, añada esta línea a /etc/initta

b

dscc:2345:respawn:/

usr/local/bin/distc
cd --verbose --no-
detach --daemon

EJECUCIÓN DESDE

INETD

distccd puede iniciarse desde un super-servidor de red como inetd o xinetd. En este caso, inetd escucha conexiones de red e invoca a distccd cuando una

llega.

Esto es ligeramente menos eficiente que ejecutar un demonio distccd independiente. distccd no es capaz de regular el número de trabajos concurrentes aceptados, pero puede haber una opción en su configuración de inetd para

hacerlo.

Para el inetd tradicional de Unix, se puede añadir una línea como esta a /etc/inetd.

conf:

distcc stream tcp nowait.6

000 root /usr/local/bin/d
istccd distccd --inetd

inetd impone un límite en la tasa de conexiones a un servicio para proteger contra el uso exce

sivo accidental o intencional. El valor por defecto en el inetd de Linux NetKit es 40 por minu
to, lo cual es demasiado bajo para distccd. La opción .6000 eleva el límite a 6000 por minuto.

--inetd
Atiende a un cliente conectado a stdin/stdout. Como su nombre sugiere, esta opción debe usarse cuando distccd se ejecuta desde un super-servidor como inetd. distccd asume el modo inetd cuando stdin es un socket.
--daemon
Enlaza y escucha en un socket, en lugar de ejecutarse desde inetd. Esto se usa para el modo independiente. distccd asume el modo daemon al inicio si stdin es un tty, por lo que --daemon debe especificarse explícitamente al iniciar distccd desde un script o en una conexión ssh no interactiva.
--enable-tcp-insecure
Por defecto (desde Distcc 3.3), distcc solo ejecutará binarios que estén enmascarados como distcc en /usr/lib/distcc. Esto lo desactiva y permite que distcc ejecute código arbitrario. Esta función es principalmente para la suite de pruebas de distcc. Véase MASQUERADING de distcc(1).
--zeroconf
Registra la disponibilidad de este servidor distccd usando el Descubrimiento de Servicio DNS Zeroconf de Avahi (DNS-SD). Esto permite a los clientes distcc de la red local acceder a este servidor distccd sin listar explícitamente su nombre de host o dirección IP en su lista de hosts distcc: los clientes distcc pueden simplemente usar "+zeroconf" en sus listas de hosts distcc. Opcionalmente se puede usar el parámetro -j para especificar el número máximo de trabajos que este servidor puede procesar concurrentemente. Esta opción solo está disponible si distccd fue compilado con el soporte de Avahi habilitado.
--auth
Realiza autenticación mutua basada en GSS-API. Esta opción solo está disponible si distccd fue compilado con la opción de configuración --with-auth.
--show-principal
Muestra el nombre del principio de seguridad de distccd extraído del entorno. Esta opción solo está disponible si distccd fue compilado con la opción de configuración --with-auth.
--blacklist=FILE
Indica a distccd que rechace conexiones de usuarios cuyos nombres de principal estén listados en FILE. Esta opción solo está disponible si distccd fue compilado con la opción de configuración --with-auth y si distccd se ejecuta con la opción --auth.
--whitelist=FILE
Indica a distccd que acepte conexiones solo de usuarios cuyos nombres de principal estén listados en FILE. Esta opción solo está disponible si distccd fue compilado con la opción de configuración --with-auth y si distccd se ejecuta con la opción --auth.

RUTAS DE BÚSQUEDA

distcc puede pasar a distccd un nombre relativo o absoluto para el compilador. Si a distcc se le da un nombre de archivo de compilador absoluto explícito, ese nombre se usa literalmente tanto en el cliente como en el servidor. Si el nombre del compilador no es una ruta absoluta, o si el cliente se usa en modo enmascarado, se busca en el PATH del servidor.

distccd hereda su ruta de búsqueda de su proceso padre. Por defecto, distccd intenta eliminar los directorios que parecen contener enlaces enmascarados de distccd, para prevenir una recursión inadvertida. La variable de entorno DISTCCD_PATH puede usarse para establecer la ruta.

La ruta de búsqueda se registra en el log cuando se usa --verbose. En caso de confusión, revise los registros.

Cuando distccd se ejecuta sobre ssh, el archivo $HOME/.ssh/environment puede ser útil para establecer la ruta. Véase ssh(1).

DIAGNÓSTICO

distccd registra mensajes en la facilidad daemon de syslog por defecto, que normalmente escribe en /var/log/daemon o /var/log/messages. Los mensajes de registro pueden enviarse a un archivo diferente usando la opción --log-file.

VARIABLES DE ENTORNO

DISTCC_CMDLIST
Si la variable de entorno DISTCC_CMDLIST está definida, se carga una lista de comandos soportados desde el archivo nombrado por DISTCC_CMDLIST, y se rechaza servir cualquier comando cuyas últimas DISTCC_CMDLIST_MATCHWORDS palabras no coincidan con las de un comando de esa lista. Véase los comentarios en src/serve.c.
DISTCC_CMDLIST_NUMWORDS
El número de palabras, desde el final del comando, a comparar. El valor por defecto es 1.
DISTCCD_PATH
Al iniciar distccd, si este valor está definido se usará sin alterar para el PATH de ejecución de comandos. El código que normalmente intenta eliminar los directorios enmascarados de la ruta se omite.
DISTCC_SAVE_TEMPS
Si se establece en 1, los archivos temporales no se eliminan después de su uso.

Tenga en cuenta que DISTCC_LOG no afecta al destino del log para el servidor.

DISTCC_TCP_DEFER_ACCEPT
En Linux, activa la opción de socket TCP_DEFER_ACCEPT. Por defecto está activada.
TMPDIR
Directorio para archivos temporales como la salida del preprocesador. Por defecto se usa /tmp/.
DISTCCD_PRINCIPAL
Si está definida, especifica el nombre del principal bajo el que se ejecuta distccd, y se usa para autenticarse con el cliente. Esta variable de entorno solo se usa si distccd fue compilado con la opción de configuración --with-auth y si distccd se ejecuta con la opción --auth.

ERRORES

El control de acceso basado en IP no es seguro frente a atacantes capaces de falsificar conexiones TCP, y no puede discriminar a diferentes usuarios en un cliente.

Las conexiones TCP no son seguras frente a atacantes capaces de observar o modificar el tráfico de red.

Debido a que ccache no almacena en caché la compilación desde archivos .i , no es útil llamarlo desde distccd.
