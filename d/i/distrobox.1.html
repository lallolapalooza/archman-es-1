COMPATIBILIDA

D

Este proyecto no necesita una imagen dedicada. Puede usar cualquier imagen OCI de docker-hub, quay.io o cualquier registro de su

elección.

Muchas imágenes en la nube están recortadas a propósito para ahorrar tamaño y pueden no incluir comandos como que, mount, less o vi). Se pueden instalar paquetes adicionales una vez dentro del contenedor. Recomendamos usar su herramienta de automatización preferida dentro del contenedor si se encuentra teniendo que crear repetidamente nuevos contenedores. Mantener su propia imagen personalizada también es una

opción.

La principal preocupación es tener las utilidades básicas de Linux (mount), las utilidades básicas de gestión de usuarios (usermod, passwd), y sudo correctamente

configurado.

DISTRIBUCIONES

ANTIGUAS

Para distribuciones antiguas como CentOS 5, CentOS 6, Debian 6, Ubuntu 12.04, la compatibilidad no está

garantizada.

Su versión de libc es incompatible con versiones del kernel posteriores a >=4.11. Una solución para esto es usar la bandera vsyscall=emulate en el cargador de arranque del

host.

Ten también en cuenta que los mirrors podrían estar caídos para versiones

tan antiguas, así que necesitarás construir una imagen de distrobox
personalizada para asegurar que se cumplen las dependencias básicas.

manualmente)

distrobox-init es el punto de entrada de un distrobox creado. Tenga en cuenta que esto TIENE que ejecutarse desde dentro de un distrobox, no funcionará si lo ejecuta desde su

host.

No está destinado a ser usado manualmente, sino que es usado por distrobox-create para configurar el punto de entrada del

contenedor.

distrobox-init se encargará de instalar las dependencias que falten

(por ejemplo, sudo), configurar el usuario y los grupos, y montar
directorios desde el host para asegurar una integración estrecha.
