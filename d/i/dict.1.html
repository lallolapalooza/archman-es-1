NOMBRE

dict - Cliente del Protocolo DICT

SINOPSIS

dict palabra
dict [opciones] [palabra]
dict [opciones] dict://host:puerto/d:palabra:base_de_datos
dict [opciones] dict://host:puerto/m:palabra:base_de_datos:estrategia

DESCRIPCIÓN

dict es un cliente para el Protocolo de Servidor de Diccionarios (DICT), un protocolo de consulta/respuesta basado en transacciones TCP que proporciona acceso a definiciones de diccionario a partir de un conjunto de bases de datos de diccionarios de lenguaje natural. El estado de salida es 0 si la operación tuvo éxito, o distinto de cero en caso contrario.
Véase la sección ESTADO DE SALIDA .

OPCIONES

-h servidor o --host servidor
Especifica el nombre de host para el servidor DICT. Las combinaciones de servidor/puerto pueden especificarse en el archivo de configuración. Si no se especifican servidores en el archivo de configuración ni en la línea de comandos, dict fallará. Si la búsqueda de IP de un servidor se expande a una lista de direcciones IP (como hace dict.org actualmente), se intentará cada IP en el orden en que se enumeran.
-p servicio o --port servicio
Especifica el puerto (por ejemplo, 2628) o servicio (por ejemplo, dict) para las conexiones. El valor predeterminado es 2628, como se especifica en la RFC del Protocolo DICT. Las combinaciones de servidor/puerto pueden especificarse en el archivo de configuración.
-d nombre_base o --database nombre_base
Especifica una base de datos específica en la que buscar. El valor predeterminado es buscar en todas las bases de datos (un "*" en el protocolo DICT). Tenga en cuenta que un "!" en el protocolo DICT significa buscar en todas las bases de datos hasta que se encuentre una coincidencia, y luego dejar de buscar.
-m o --match
En lugar de imprimir una definición, realiza una búsqueda de coincidencias utilizando la estrategia especificada.
-s estrategia o --strategy estrategia
Especifica una estrategia de coincidencia. De forma predeterminada, se utiliza la estrategia de coincidencia predeterminada del servidor. Esto suele ser "exact" (exacta) para las definiciones, y alguna forma de estrategia de corrección ortográfica para las coincidencias ("." en el protocolo DICT). Las estrategias disponibles dependen de la implementación del servidor. Para obtener una lista de las estrategias disponibles, consulte la opción -S o --strats.
-C o --nocorrect
Normalmente, si se solicita una definición y no se encuentra la palabra, se solicita la corrección ortográfica al servidor, y se proporciona una lista de posibles palabras. Esta opción desactiva la generación de esta lista.
-c archivo o --config archivo
Especifica el archivo de configuración. El valor predeterminado es intentar ~/.dictrc y /etc/dict/dict.conf, usando el primer archivo que exista. Si se especifica un archivo de configuración específico, no se intentarán los valores predeterminados.
-D o --dbs
Consulta al servidor y muestra una lista de las bases de datos disponibles.
-S o --strats
Consulta al servidor y muestra una lista de las estrategias de búsqueda disponibles.
-H o --serverhelp
Consulta al servidor y muestra la información de ayuda que proporciona.
-i nombre_base o --info nombre_base
Solicita información sobre la base de datos especificada (normalmente el servidor proporcionará información sobre el origen, descriptiva u otra información sobre la base de datos o su contenido).
-I o --serverinfo
Consulta al servidor y muestra información sobre el servidor.
-M o --mime
Envía el comando OPTION MIME al servidor.
NOTA: No se comprueban las capacidades del servidor.
-f o --formatted
Habilita la salida formateada, es decir, una salida conveniente para el postprocesamiento por utilidades UNIX estándar. No, no es XML ;-) También los mensajes de error y advertencia como
" No matches...", " Invalid strategy..." etc. se envían a stderr, no a stdout.
Formato:
-I, -i, -H y similares:
host<TAB>puerto
<SPC><SPC>línea1
<SPC><SPC>línea2
...
-S:
host<TAB>puerto<TAB>estrategia1<TAB>descripción_corta1
host<TAB>puerto<TAB>estrategia2<TAB>descripción_corta2
...
-D:
host<TAB>puerto<TAB>base_datos1<TAB>descripción_base_datos1
host<TAB>puerto<TAB>base_datos2<TAB>descripción_base_datos2
...
-m:
host<TAB>puerto<TAB>base_datos1<TAB>coincidencia1
host<TAB>puerto<TAB>base_datos2<TAB>coincidencia2
...
-a o --noauth
Desactiva la autenticación (es decir, no envía un comando AUTH).
-u usuario o --user usuario
Especifica el nombre de usuario para la autenticación.
-k clave o --key clave
Especifica el secreto compartido para la autenticación.
-V o --version
Muestra la información de la versión.
-L o --license
Muestra la información de copyright y licencia.
-4
Fuerza a dict a usar solo direcciones IPv4.
-6
Fuerza a dict a usar solo direcciones IPv6.
--help
Muestra la información de ayuda.
-v o --verbose
Ser detallado.
-r o --raw
Ser muy detallado: muestra la interacción cruda cliente/servidor.
--pipesize
Especifica el tamaño del búfer para la canalización de comandos. El valor predeterminado es 256, lo que debería ser suficiente para tareas generales y estar por debajo del MTU para la mayoría de los medios de transporte. Valores más grandes pueden proporcionar un rendimiento más rápido o más lento, dependiendo del MTU. Si el búfer es demasiado pequeño, las solicitudes se serializarán. Los valores menores que 0 y mayores que un millón se cambian silenciosamente a algo más razonable.
--client texto
Especifica texto adicional que se enviará usando el comando CLIENT.
--debug indicador
Establece un indicador de depuración. Los indicadores válidos son:
verbose
Lo mismo que -v o --verbose.
raw
Lo mismo que -r o --raw.
scan
Depura el escáner para el archivo de configuración.
parse
Depura el analizador para el archivo de configuración.
pipe
Depura la compatibilidad con canalización TCP (véase la RFC de DICT y la RFC1854).
serial
Desactiva la compatibilidad con canalización.
time
Realiza la medición de tiempo de las transacciones.

CONFIGURACIÓN

El archivo de configuración actualmente tiene un formato muy simple. Las líneas se utilizan para especificar servidores, por ejemplo:

server dict.org
o, con opciones:
server dict.org { port 8080 }
server dict.org { user usuario secreto }
server dict.org { port dict user usuario secreto }
las opciones port y user pueden especificarse en cualquier orden. La opción port se utiliza para especificar un puerto opcional (por ejemplo, 2628) o servicio (por ejemplo, dict) para la conexión TCP/IP. La opción user se utiliza para especificar un nombre de usuario y un secreto compartido que se utilizarán para la autenticación con este servidor en particular.

Los servidores se prueban en el orden en que se enumeranhasta que se establece una conexión.

ESTADO DE SALIDA


0 Finalización correcta


20 No se encontraron coincidencias
21 Se encontraron coincidencias aproximadas
22 No hay bases de datos disponibles
23 No hay estrategias disponibles


30 Código de respuesta inesperado del servidor
31 El servidor no está disponible temporalmente
32 El servidor se está apagando
33 Error de sintaxis, comando no reconocido
34 Error de sintaxis, parámetros ilegales
35 Comando no implementado
36 Parámetro del comando no implementado
37 Acceso denegado
38 Autenticación fallida
39 Base de datos no válida
40 Estrategia no válida
41 La conexión con el servidor falló

ERRORES

Si se proporciona una URL dict: en la línea de comandos, solo se usa la primera. El resto se ignoran.

Si una URL dict: contiene un especificador para la n-ésima definición o coincidencia de una palabra, se ignorará y se proporcionarán todas las definiciones o coincidencias. Esto viola la RFC y se corregirá en una versión futura.

Si una URL dict: contiene un secreto compartido, no se analizará correctamente.

Cuando se envía el comando OPTION MIME al servidor (opción -M ), no se comprueban las capacidades del servidor.
