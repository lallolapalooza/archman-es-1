Digest::SHA(3perl) Guía de Referencia para Programadores de Perl Digest::SHA(3perl)

NOMBRE

Digest::SHA - Extensión de Perl para SHA-1/224/256/384/512

SINOPSIS

En programas:

        # Interfaz funcional
use Digest::SHA qw(sha1 sha1_hex sha1_base64 ...);
$digest = sha1($data);
$digest = sha1_hex($data);
$digest = sha1_base64($data);
$digest = sha256($data);
$digest = sha384_hex($data);
$digest = sha512_base64($data);
        # Orientado a objetos
use Digest::SHA;
$sha = Digest::SHA->new($alg);
$sha->add($data);               # alimenta datos en el flujo
$sha->addfile(*F);
$sha->addfile($filename);
$sha->add_bits($bits);
$sha->add_bits($data, $nbits);
$sha_copy = $sha->clone;        # crea una copia del objeto digest
$state = $sha->getstate;        # guarda el estado actual en una cadena
$sha->putstate($state);         # restaura el estado $state anterior
$digest = $sha->digest;         # calcula el digest
$digest = $sha->hexdigest;
$digest = $sha->b64digest;

Desde la línea de comandos:

$ shasum files
$ shasum --help

SINOPSIS (HMAC-SHA)

        Solo interfaz funcional
use Digest::SHA qw(hmac_sha1 hmac_sha1_hex ...);
$digest = hmac_sha1($data, $key);
$digest = hmac_sha224_hex($data, $key);
$digest = hmac_sha256_base64($data, $key);

RESUMEN

Digest::SHA es una implementación completa del Estándar de Hash Seguro (Secure Hash Standard) de NIST. Proporciona a los programadores de Perl una forma conveniente de calcular los resúmenes de mensajes SHA-1, SHA-224, SHA-256, SHA-384, SHA-512, SHA-512/224 y SHA-512/256. El módulo puede manejar todo tipo de entrada, incluyendo datos de longitud parcial de byte.

DESCRIPCIÓN

Digest::SHA está escrito en C para mayor velocidad. Si su plataforma carece de un compilador C, puede instalar el módulo funcionalmente equivalente (pero mucho más lento) Digest::SHA::PurePerl.

La interfaz de programación es fácil de usar: es la misma que se encuentra en el módulo Digest de CPAN. Por lo tanto, si sus aplicaciones usan actualmente Digest::MD5 y preferiría la mayor seguridad de SHA, es un simple asunto convertirlas.

La interfaz proporciona dos formas de calcular los resúmenes: de una sola vez o por etapas. Para ilustrarlo, el siguiente programa corto calcula el resumen SHA-256 de "hello world" usando cada enfoque:

use Digest::SHA qw(sha256_hex);
$data = "hello world";
@frags = split(//, $data);
# de una sola vez (estilo funcional)
$digest1 = sha256_hex($data);
# por etapas (estilo POO)
$state = Digest::SHA->new(256);
for (@frags) { $state->add($_) }
$digest2 = $state->hexdigest;
print $digest1 eq $digest2 ?
        "whew!\n" : "oops!\n";

Para calcular el resumen de un mensaje de n bits donde n no es un múltiplo de 8, use el método add_bits() . Por ejemplo, considere el mensaje de 446 bits que consiste en la cadena de bits "110" repetida 148 veces, seguida de "11". He aquí cómo mostrar su resumen SHA-1:

use Digest::SHA;
$bits = "110" x 148 . "11";
$sha = Digest::SHA->new(1)->add_bits($bits);
print $sha->hexdigest, "\n";

Tenga en cuenta que para cadenas de bits más grandes, es más eficiente usar la versión de dos argumentos add_bits($data, $nbits), donde $data está en el formato binario empaquetado habitual utilizado para cadenas de Perl.

El módulo también le permite guardar estados intermedios de SHA en una cadena. El método getstate() genera texto portátil y legible por humanos que describe el estado actual del cálculo. Posteriormente puede restaurar ese estado con putstate() para reanudar donde se dejó el cálculo.

Para ver cómo es una descripción de estado, simplemente ejecute lo siguiente:

use Digest::SHA;
print Digest::SHA->new->add("Shaw" x 1962)->getstate;

Como conveniencia adicional, el módulo Digest::SHA ofrece rutinas para calcular hashes con clave usando los algoritmos HMAC-SHA-1/224/256/384/512. Estos servicios existen solo en forma funcional y imitan el estilo y comportamiento de las funciones sha(), sha_hex()y sha_base64() .

# Vector de prueba de draft-ietf-ipsec-ciph-sha-256-01.txt
use Digest::SHA qw(hmac_sha256_hex);
print hmac_sha256_hex("Hi There", chr(0x0b) x 32), "\n";

UNICODE Y EFECTOS SECUNDARIOS

Perl soporta cadenas Unicode desde la versión 5.6. Dichas cadenas pueden contener caracteres anchos, es decir, caracteres cuyos valores ordinales son mayores que 255. Esto puede causar problemas para algoritmos de resumen como SHA que están especificados para operar sobre secuencias de bytes.

La regla por la cual Digest::SHA maneja una cadena Unicode es fácil de enunciar, pero potencialmente confusa de comprender: la cadena se interpreta como una secuencia de valores de byte, donde cada valor de byte es igual al valor ordinal (es decir, punto de código) de su carácter Unicode correspondiente. De esa manera, la cadena Unicode 'abc' tiene exactamente el mismo valor de resumen que la cadena ordinaria 'abc'.

Dado que un carácter ancho no cabe en un byte, las rutinas de Digest::SHA se quejan si encuentran uno. Sin embargo, si una cadena Unicode no contiene caracteres anchos, el módulo la acepta felizmente. El siguiente código ilustra los dos casos:

$str1 = pack('U*', (0..255));
print sha1_hex($str1);          # ok
$str2 = pack('U*', (0..256));
print sha1_hex($str2);          # se queja

Tenga en cuenta que las rutinas de resumen convierten silenciosamente la entrada UTF-8 en su secuencia de bytes equivalente en la codificación nativa (cf. utf8::downgrade). Este efecto secundario influye solo en la forma en que Perl almacena los datos internamente, pero de lo contrario deja intacto el valor real de los datos.

DECLARACIÓN DEL NIST SOBRE SHA-1

El NIST reconoce que el trabajo de la Prof. Xiaoyun Wang constituye un ataque de colisión práctico sobre SHA-1. Por lo tanto, el NIST fomenta la rápida adopción de las funciones hash SHA-2 (por ejemplo, SHA-256) para aplicaciones que requieren fuerte resistencia a colisiones, como firmas digitales.

ref. http://csrc.nist.gov/groups/ST/hash/statement.html

RELLENO DE RESÚMENES BASE64

Por convención, los módulos Digest de CPAN no rellenan su salida Base64. Pueden ocurrir problemas al alimentar tales resúmenes a otro software que espera codificaciones Base64 debidamente rellenadas.

Por el momento, cualquier relleno necesario debe ser hecho por el usuario. Afortunadamente, es una operación simple: si la longitud de un resumen codificado en Base64 no es un múltiplo de 4, simplemente agregue caracteres "=" al final del resumen hasta que lo sea:

while (length($b64_digest) % 4) {
        $b64_digest .= '=';
}

Para ilustrar, sha256_base64("abc") se calcula como

ungWv48Bz+pBQUDeXa4iI7ADYaOWF3qctBD/YfIAFa0

que tiene una longitud de 43. Por lo tanto, la versión debidamente rellenada es

ungWv48Bz+pBQUDeXa4iI7ADYaOWF3qctBD/YfIAFa0=
