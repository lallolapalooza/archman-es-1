DESCRIPCIÓ

N

digitaglinktree creará un árbol de enlaces para todas las fotos en una base de datos de digikam que tengan etiquetas asignadas. Las etiquetas (como por ejemplo "familia", "eventos", ...) se utilizan en digikam para crear carpetas virtuales que contienen imágenes que todas tienen una o más etiquetas asignadas. Tenga en cuenta: Las fotos que no tienen ninguna etiqueta asignada son ignoradas silenciosamente por este script. El programa no modificará ni tocará sus fotos originales gestionadas por

digikam.

El script se puede usar de dos maneras: Si lo llama usando la opción -l taglinkdir, el script creará el directorio especificado por el usuario taglinkdir y dentro de este directorio creará subdirectorios para las etiquetas de digikam establecidas en las fotos. Dentro de estos subdirectorios colocará finalmente enlaces simbólicos o duros (véase -H) a las fotos que tengan las etiquetas en cuestión. Como resultado, verá las etiquetas de sus fotos como carpetas y en estas carpetas encontrará enlaces a sus fotos

originales.

De esta manera puede acceder a la colección de todas las imágenes que comparten una determinada etiqueta cambiando de directorio a la carpeta con el nombre de la etiqueta creada por este script. Esto le permite, por ejemplo, ejecutar JAlbum, un software de álbumes de fotos que necesita encontrar las imágenes para ponerlas en un álbum web en el sistema de archivos porque JAlbum no puede acceder directamente a las carpetas virtuales de

digikam.

La segunda forma de llamar a este script es el llamado modo archivo estableciendo la opción -A archiveDir

.

El modo archivo está pensado para personas que quieren archivar fotos con etiquetas independientemente de los directorios raíz de digikam y las fotos en ellos. De esta manera puede poner sus fotos y su estructura de etiquetas en, por ejemplo, un archivo tar y enviarlo a un amigo, quien puede ver las fotos a través de su estructura de etiquetas. En este modo, el script crea el directorio dado como parámetro a -A y en este directorio dos subdirectorios más. Uno llamado Photos y un segundo llamado Tags. El directorio Photos contiene enlaces duros a sus fotos originales, y el directorio Tags contiene un subdirectorio para cada etiqueta usada por cualquiera de sus fotos. Dentro de este subdirectorio hay enlaces (ya sean simbólicos o duros) a los archivos en el directorio Photos. De esta manera el directorio de archivo casi no necesita espacio adicional en su disco duro y usted tiene un archivo que le permite a usted o a un amigo ver fácilmente la estructura de etiquetas de las

fotos.

Otro beneficio de usar este script es que tiene una especie de copia de seguridad de sus configuraciones de etiquetas para todas s

us fotos. La copia de seguridad es simplemente la estructura de directorios que contiene enlaces a las imágenes originales que ll
evan las etiquetas. Esto podría volverse importante si por alguna razón el archivo digikam.db se corrompe o incluso se pierde.

OPCIONES DE LÍNEA DE

COMANDOS
-l taglinkd
ir
Parámetro taglinkdir denota un directorio en el que se exportará la estructura de etiquetas de todas sus fotos almacenadas en rootdir creando subdirectorios para cada etiqueta y colocando enlaces simbólicos en estos subdirectorios que apuntan a la foto original que lleva las etiquetas. Si llama al script con la opción -l taglinkDir también debe especificar las opciones -r rootdir así como -d database
.
-A archivedirect
ory
archivedirectory denota un directorio en el que el script exportará las fotos y su estructura de etiquetas. -A debe usarse junto con la opción -r rootdir si se usa la versión de digikam < 0.10, así como -d database, de lo contrario el script terminará. Dentro del directorio de archivo, el script creará un directorio Photos y un directorio Tags. Colocará enlaces duros en el directorio Photos que apuntan a sus fotos originales. Al usar enlaces duros usted es independiente de los cambios en su directorio raíz de digikam, pero por otro lado está limitado a un sistema de archivos. Así que el directorio dado por -r rootdir y el directorio especificado para -A archivedir deben estar en el mismo sistema de archivos. Si se usa digikam en la versión >= 0.10 no puede especificar -r rootdir . En su lugar, las rutas raíz de todos los álbumes se toman directamente de la base de datos de digikam. Sin embargo la requisito sigue siendo que archivedir debe estar en el mismo sistema de archivos que todos los directorios raíz que contienen fotos que usted definió en digikam. Si uno de los directorios raíz de digikam está en otro sistema de archivos, este no será procesado, ¡ya que el enlace duro de las fotos dentro del directorio Photos no funcionaría en este caso! El subdirectorio Tags contendrá enlaces a los archivos en el directorio Photos. De esta manera tiene un directorio de archivo completamente autónomo. Puede comprimirlo con tar, enviarlo a un amigo o simplemente ponerlo en algún lugar para fines de archivo o copia de seguridad. Usualmente solo se archivarán aquellas fotos que tengan una etiqueta de digikam establecida. Sin embargo, usando la opción -C puede realizar un archivo completo. Vea -C para más
información.
-d databa
se
database es la ruta completa incluyendo el nombre de archivo a la base de datos de fotos de digikam, que usualmente se encuentra en el directorio raíz de digikam. El nombre del archivo es usualmente digikam.
db .
-r rootd
ir
rootdir denota el directorio base de digikam que contiene todas sus fotos si está usando digikam en una versión anterior a 0.10. Si está usando digikam 0.10 o más nuevo no debe usar esta opción. Si lo hace de todos modos verá un aviso de que la opción dada será ignorada porque la base de datos de la versión 0.10 de digikam contiene los directorios raíz de todos los álbumes definidos en
digikam.
-
C
Cuando el script se llama con la opción -A archivedir solo aquellas fotos serán archivadas (colocando enlaces) en el subdirectorio Photos de archivedir que tengan al menos una etiqueta de digikam establecida. Al establecer la opción -C todas las fotos serán archivadas en archivedir sin importar si tienen una etiqueta establecida o no. Nota: Esto solo cambia el contenido del subdirectorio Photos, no el del subdirectorio Tags en el directorio archivedir
.
-
a
Por defecto el script intentará crear enlaces simbólicos relativos desde el directorio taglinkdir establecido por la opción -l a los archivos de fotos bajo rootdir dado por la opción -r. Usar esta opción resultará en la creación de enlaces simbólicos absolutos en lugar de
relativos.
-
H
Por defecto el script creará enlaces blandos (simbólicos) desde el árbol de etiquetas a las fotos. Al establecer la opción -H el script usará enlaces duros en su lugar. Tenga en cuenta que los enlaces duros solo se pueden crear dentro de un sistema de archivos. Así que sus fotos y el árbol de etiquetas deben estar en el mismo sistema de archivos. Si no, verá una advertencia sobre este problema y el script no se
ejecutará.
-
f
En digikam las fotos pueden tener etiquetas jerárquicas (etiquetas que tienen subetiquetas). En este caso digitaglinktree por defecto añadiría un directorio para la etiqueta y un subdirectorio para cada una de las subetiquetas de esta etiqueta. Al establecer -f una subetiqueta se trata como una etiqueta regular, igual que su etiqueta padre, así que digitaglinktree creará todos los subdirectorios para etiquetas y subetiquetas en el mismo nivel independientemente de la jerarquía etiqueta -
subetiqueta.
-
Y
Crear directorio de año bajo cada directorio de etiqueta. La información del año se toma de "Fecha de toma" en la base de
datos.
-i tag1,..,
tagn
tag1,..,tagn Incluir solo imágenes con etiquetas en la lista. Use la coma como separador de etiquetas. El valor predeterminado es "none". Use "all" para incluir todas las etiquetas a la vez si realmente lo desea. Es mejor probar primero una lista con solo algunas etiquetas para ver cuánto tiempo tarda en
completarse.
-e tag1,..,
tagn
tag1,..,tagn Excluir imágenes con etiquetas en la lista. Use la coma como separador de etiqueta. El valor predeterminado es
"none".
-M level_numb
er
level_number especifica el número de niveles de directorio. -M especifica que en lugar de seguir la jerarquía normal de etiquetas, crea una jerarquía que combina diferentes etiquetas juntas y no solo dentro de una jerarquía de una sola etiqueta (por ejemplo, combinando etiquetas de Lugares y Personas). Debes añadir etiquetas para que se incluyan usando la opción -i (ver arriba). Dependiendo del nivel dado, del número de etiquetas que hayas incluido y de cuántas fotos gestiones con digikam, esta opción puede tardar una cantidad considerable de tiempo (posiblemente más de una hora) en completarse. el número de nivel de "5" parece ser el nivel máximo razonable para empezar en este modo. ¡Las opciones -A -C -a -H -f no se han probado con esta
opción!

CONFIGURACIÓ

N

Por defecto, este script se ejecutará con todas las bases de datos de fotos creadas por digikam versión 0.10, así como versiones anteriores como 0.9 y 0.8. Si aún tienes digikam versión 0.7, tendrás que reconfigurar el script en

sí.

Tienes que reconfigurar el script estableciendo la ruta al binario sqlite que usa el script para consultar la base de datos de digikam digikam.db. Dado que versiones muy antiguas de digikam usan sqlite en la versión 2, pero versiones posteriores de digikam necesitan sqlite versión 3, debes asegurarte de instalar la versión correcta de sqlite para la versión de digikam instalada y de establecer la ruta al ejecutable sqlite correcto en la cabecera del

script:

Elig

e

$SQLITE="/usr/bin/sqlite3"

;

para digikam versión 0.8x y 0.9x y 0.

10x

$SQLITE="/usr/bin/sqlite"

;

para digi

kam vers
ión 0.7x.

EJEMPL

O

A continuación se muestra una llamada a digitaglinktree

:

digiTagLinktree -l /home/user/tags
-d /home/user/photos/digikam.

db

En este ejemplo asumimos que estás ejecutando digikam versión 0.10 o superior, por lo que no se usó la opción -r para especificar el directorio raíz de las fotos. En su lugar, esta información se obtendrá automáticamente de la base de datos de

digikam.

En caso de que quieras ejecutar el script en una base de datos de digikam que fue creada por digikam versión 0.9 o anterior, tienes que usar -r para especificar el directorio raíz donde guardas todas tus fotos gestionadas por

digikam:

digiTagLinktree -l /home/user/tags
-d /home/user/photos/digikam.

db

En este ejemplo, la raíz de fotos de digikam denotada por -r es /home/user/photos

.

La opción -l /home/user/tags le dice al script que todos los subdirectorios y enlaces simbólicos se colocarán en el directorio /home/user/tags. Se eligió esta carpeta para que el directorio de etiquetas no esté bajo la raíz de fotos de digikam. Puedes poner la carpeta de etiquetas dentro de la raíz de fotos de digikam, pero este no es el método preferido. Como el directorio de enlaces contiene solo enlaces, esta estructura de etiquetas apenas necesita espacio adicional en tu disco

duro.

digiTagLinktree -r /home/user/photos -l /home/user/tags -d /home/user/photos/digikam.db
-i People,Place
-M 2
