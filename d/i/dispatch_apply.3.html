NOMBRE

dispatch_apply — programar bloques para ejecución iterativa

SINOPSIS

#include <dispatch/dispatch.h>

void
dispatch_apply(size_t iterations, dispatch_queue_t queue, void (^block)(size_t));

void
dispatch_apply_f(size_t iterations, dispatch_queue_t queue, void *context, void (*function)(void *, size_t));

DESCRIPCIÓN

La función dispatch_apply() proporciona concurrencia a nivel de datos a través de un primitivo similar a un bucle "for (;;)":

size_t iterations = 10;

// 'idx' está indexado desde cero, al igual que:
// for (idx = 0; idx < iterations; idx++)

dispatch_apply(iterations, DISPATCH_APPLY_AUTO, ^(size_t idx) {
	printf("%zu\n", idx);
});

Aunque se puede usar cualquier cola, se recomienda encarecidamente utilizar DISPATCH_APPLY_AUTO como argumento de queue tanto para dispatch_apply() como para dispatch_apply_f(), como se muestra en el ejemplo anterior, ya que esto permite al sistema utilizar automáticamente hilos de trabajo que coinciden lo más posible con la configuración del hilo actual. No se deben hacer suposiciones sobre qué cola concurrente global se utilizará.

Al igual que un bucle "for (;;)", la función dispatch_apply() es síncrona. Si se desea un comportamiento asíncrono, envuelva la llamada a dispatch_apply() con una llamada a dispatch_async() en otra cola.

A veces, cuando el bloque pasado a dispatch_apply() es simple, el uso de pasos (striding) puede ajustar el rendimiento. Calcular el paso óptimo es mejor dejarlo a la experimentación. Empiece con un paso de uno y aumente hasta lograr el rendimiento deseado (quizás usando una búsqueda de potencia de dos):

#define STRIDE 3

dispatch_apply(count / STRIDE, DISPATCH_APPLY_AUTO, ^(size_t idx) {
	size_t j = idx * STRIDE;
	size_t j_stop = j + STRIDE;
	do {
		printf("%zu\n", j++);
	} while (j < j_stop);
});

size_t i;
for (i = count - (count % STRIDE); i < count; i++) {
	printf("%zu\n", i);
}

REFERENCIAS IMPLÍCITAS

Las funciones síncronas dentro del framework de dispatch retienen una referencia implícita en la cola de destino. En otras palabras, la función síncrona toma prestada la referencia de la función que llama (esto es válido porque la función que llama está bloqueada esperando el resultado de la función síncrona, y por lo tanto no puede modificar el contador de referencias de la cola de destino hasta después de que la función síncrona haya retornado).

Esto contrasta con las funciones asíncronas que deben retener tanto el bloque como la cola de destino durante la duración de la operación asíncrona (ya que la función que llama puede liberar inmediatamente su interés en estos objetos).

FUNDAMENTOS

dispatch_apply() y dispatch_apply_f() intentan crear rápidamente suficientes hilos de trabajo para ejecutar el trabajo en paralelo de manera eficiente. Por el contrario, un bucle que pasa elementos de trabajo individualmente a dispatch_async() o dispatch_async_f() incurrirá en más sobrecarga y no expresa las semánticas de ejecución paralela deseadas al sistema, por lo que puede que no cree un número óptimo de hilos de trabajo para una carga de trabajo paralela. Por esta razón, prefiera usar dispatch_apply() o dispatch_apply_f() cuando la ejecución paralela sea importante.

La función dispatch_apply() es un envoltorio alrededor de dispatch_apply_f().

ADVERTENCIAS

A diferencia de dispatch_async(), se espera que un bloque enviado a dispatch_apply() sea independiente o dependa únicamente del trabajo ya realizado en invocaciones de índice inferior del bloque. Si la dependencia del índice del bloque no es lineal, se recomienda usar un bucle for alrededor de las invocaciones de dispatch_async().
