DIALOG() Llamadas a bibliotecas DIALOG()

NOMBRE

dialog - widgets y utilidades para el programa dialog

SINOPSIS

cc [ flag ... ] archivo ... -ldialog [ biblioteca ... ]
   o
cc $(dialog-config --cflags) archivo ... $(dialog-config --libs) ]

#include <dialog.h>

Dialog es un programa que le permitirá presentar una variedad de preguntas o mostrar mensajes utilizando cuadros de diálogo desde un script de shell. Está construido a partir de la biblioteca dialog, que consta de varios widgets así como de funciones de utilidad que son utilizadas por los widgets o el programa principal.

DESCRIPCIÓN

Esta página del manual documenta las características de <dialog.h> que probablemente sean importantes para los desarrolladores que utilizan los widgets directamente. También se dan algunas pistas para desarrollar nuevos widgets.

Aquí hay una versión dialog de Hola Mundo:

int main(void)
{
	int status;
	init_dialog(stdin, stdout);
	status = dialog_yesno(
			"Hola, en formato dialog",
			"¡Hola Mundo!",
			0, 0);
	end_dialog();
	return status;
}

DEFINICIONES

Los códigos de salida (pasados al programa principal para su uso) se definen con un prefijo de "DLG_EXIT_". Las constantes definidas pueden mapearse usando variables de entorno como se describe en dialog(1), p. ej., DLG_EXIT_OK corresponde a $DIALOG_OK.

Las constantes de caracteres útiles que corresponden a la entrada del usuario se nombran con el prefijo "CHR_", p. ej., CHR_BACKSPACE.

Los colores y atributos de video se categorizan y asocian con configuraciones en el archivo de configuración (ver la discusión de $DIALOGRC en dialog(1)). La macro DIALOG_ATR(n) se usa para definir las referencias a la tabla combinada de colores y atributos dlg_color_table[].

La aplicación dialog pasa sus parámetros de línea de comandos a las funciones de widget. Algunos de esos parámetros son valores únicos, pero algunos de los widgets aceptan datos como un array de valores. Estos incluyen checklist/radiobox, menubox y formbox. Cuando se proporciona la opción --item-help, se espera una columna adicional de datos. Las macros USE_ITEM_HELP(), CHECKBOX_TAGS, MENUBOX_TAGS y FORMBOX_TAGS se utilizan para ocultar esta diferencia de la aplicación que llama.

La mayoría de las otras definiciones que se encuentran en <dialog.h> se utilizan como conveniencia para construir la biblioteca o el programa principal. Estas incluyen definiciones basadas en el encabezado generado <dlg_config.h>.

ESTRUCTURAS DE DATOS

Todos los datos globales de la biblioteca dialog se almacenan en algunas estructuras: DIALOG_STATE, DIALOG_VARS y DIALOG_COLORS. Las variables globales correspondientes dialog_state, dialog_vars y dlg_color_table deben inicializarse a cero, y luego poblarse con los datos a usar. Algunas de estas deben ser distintas de cero para que los widgets correspondientes funcionen. Al igual que con los nombres de las funciones, las variables que comienzan con "dialog_" están diseñadas para ser utilizadas por la aplicación que llama, mientras que las variables que comienzan con "dlg_" están destinadas a niveles inferiores, p. ej., por la biblioteca dialog.

DIALOG_STATE

Las variables de *estado* son las variables de trabajo de dialog. Las inicializa, las utiliza para gestionar los widgets.

.todas_subventanas

Esta es una lista enlazada de todas las subventanas creadas por la biblioteca. La función dlg_del_window utiliza esto para liberar el almacenamiento de las subventanas al eliminar una ventana.

.todas_ventanas

Esta es una lista enlazada de todas las ventanas creadas por la biblioteca. La función dlg_del_window utiliza esto para localizar ventanas que pueden ser redibujadas después de eliminar una ventana.

.relacion_aspecto

Esto corresponde a la opción de línea de comandos "--aspect-ratio". El valor da a la aplicación cierto control sobre las dimensiones del cuadro cuando se utiliza el tamaño automático (especificando 0 para altura y anchura). Representa anchura / altura. El valor predeterminado es 9, lo que significa 9 caracteres de ancho por cada línea de alto.

.cadena_final

Cuando se establece en verdadero, esto permite que las llamadas a dlg_finish_string descarten los datos correspondientes que se crean para acelerar los cálculos de diseño para la cadena dada. El widget gauge utiliza esta característica.

.callbacks_getc

Esto se configura en ui_getc.c para registrar ventanas que deben ser encuestadas en busca de entrada, p. ej., para manejar el widget de cola de fondo. Una ventana se designa como ventana de primer plano o de control.

.redireccion_getc

Si la ventana de control para DIALOG_STATE.getc_callbacks se cierra, la lista se transfiere a esta variable. Cerrar todas las ventanas provoca la salida de la aplicación.

.tuvo_redimensionamiento

Esto se establece en TRUE en dlg_will_resize o dlg_result_key cuando se lee KEY_RESIZE, para indicar a dialog que ignore los ERR posteriores.

.sin_raton

Esto corresponde a la opción de línea de comandos "--no-mouse". Si es verdadero, dialog no inicializará (y habilitará) el ratón en init_dialog.

.salida

Esto se establece en la aplicación dialog para el flujo en el que las funciones de la aplicación y la biblioteca pueden escribir resultados de texto. Normalmente, ese es el error estándar, ya que la biblioteca curses prefiere escribir sus datos en la salida estándar. Algunos scripts, a cambio de portabilidad por conveniencia, prefieren escribir resultados en la salida estándar, p. ej., utilizando la opción "--stdout".

.contador_salida

Esto es incrementado por dlg_does_output, que es llamado por cada widget que escribe texto en la salida. La aplicación dialog usa eso para decidir si también debe escribir un separador, es decir, DIALOG_STATE.separate_str, entre llamadas a cada widget.

.entrada_tuberia

Esto se establece en init_dialog a un flujo que puede ser utilizado por el widget gauge, que debe ser la entrada estándar de la aplicación. La aplicación dialog llama a init_dialog normalmente con input establecido en la entrada estándar, pero opcionalmente basado en la opción "--input-fd". Dado que la aplicación no puede leer desde una tubería (entrada estándar) y al mismo tiempo leer la entrada de curses desde la entrada estándar, debe permitir la reapertura de esta última desde un descriptor de archivo específico, o directamente desde la terminal. El valor de flujo de tubería ajustado se almacena en esta variable.

.altura_pantalla

Las funciones de formato de texto utilizan esto para el número de filas utilizadas para formatear una cadena.

Es utilizado por dialog para las opciones de línea de comandos "--print-text-size" y "--print-text-only".

.pantalla_inicializada

Esto se establece en init_dialog y se restablece en end_dialog. Se utiliza para verificar si curses se ha inicializado y si la función endwin debe ser llamada al salir.

.salida_pantalla

Esto se establece en init_dialog para el flujo de salida utilizado por la biblioteca curses.

.dlg_clear_screen

Esto corresponde a la opción de línea de comandos "--clear". Esta opción está implementada en el programa principal, no en la biblioteca. Si es verdadera, la pantalla se borrará al salir. Esta opción puede usarse sola, sin otras opciones.

.erase_on_exit

Esto corresponde a la opción de línea de comandos "--erase-on-exit". Si es verdadera, elimina el widget de diálogo al salir del programa, borrando toda la pantalla hasta su color de fondo nativo, y coloca el cursor de la terminal en la esquina inferior izquierda de la pantalla.

Esto es útil para hacer que el contenido de la ventana sea invisible al final de una serie de cuadros de diálogo. También se puede usar en etapas anteriores de una serie de invocaciones de dialog, si la serie puede abortarse antes de que se complete por completo.

.exit_label

Esto corresponde a la opción de línea de comandos "--exit-label string". La cadena dada anula la etiqueta utilizada para los botones “SALIR”.

.extra_button

Esto corresponde a la opción de línea de comandos "--extra-button". Si es verdadera, algunos widgets muestran un botón extra, entre los botones “Aceptar” y “Cancelar”, o “Sí” y “No”.

.extra_label

Esto corresponde a la opción de línea de comandos "--extra-label string". La cadena dada anula la etiqueta utilizada para los botones “Extra”. Nota: para los widgets inputmenu, el valor predeterminado es “Renombrar”.

.formitem_type

Esto se establece con la opción de línea de comandos "--passwordform" para indicar al widget de formulario que sus campos de texto deben tratarse como widgets de contraseña.

.help_button

Esto corresponde a la opción de línea de comandos "--help-button". Si es verdadera, algunos widgets muestran un botón de ayuda después de los botones “Aceptar” y “Cancelar”, es decir, en las cajas de lista de verificación, lista de selección y menú, o los botones “Sí” y “No” para la caja yesno .

Si --item-help también se proporciona, al salir el estado de retorno será el mismo que para el botón “Aceptar”, y el texto de ayuda del elemento se escribirá en la salida dedialog después del token “HELP”. De lo contrario, el estado de retorno indicará que se presionó el botón Ayuda, y no se imprimirá ningún mensaje.

.help_file

Esto corresponde a la opción de línea de comandos "--hfile string". El nombre de archivo dado se pasa a dialog_helpfile cuando el usuario presiona F1.

.help_label

Esto corresponde a la opción de línea de comandos "--help-label string". La cadena dada anula la etiqueta utilizada para los botones “Ayuda”.

.help_line

Esto corresponde a la opción de línea de comandos "--hline string". La cadena dada se muestra en la parte inferior de los diálogos de ventana, como un subtítulo.

.help_status

Esto corresponde a la opción de línea de comandos "--help-status". Si es verdadera, y se selecciona el botón de ayuda, escribe la información de la lista de verificación o lista de selección después de la información de ayuda del elemento “HELP”. Esto se puede usar para reconstruir el estado de una lista de verificación después de procesar la solicitud de ayuda.

.help_tags

Esto corresponde a la opción de línea de comandos "--help-tags". Si es verdadera, dlg_add_help_formitem y dlg_add_help_listitem usan el valor de la etiqueta del elemento de manera consistente en lugar de usar el valor del texto de ayuda de la etiqueta cuando DIALOG_VARS.item_help está establecido.

.input_length

Es distinto de cero si DIALOG_VARS.input_result está asignado, en lugar de ser un puntero a las variables locales del usuario.

.input_menu

Esta bandera se establece para indicar si el widget menubox implementa un menú versus un widget inputmenu.

.input_result

Puede ser un búfer proporcionado por el usuario, o un búfer asignado dinámicamente por la biblioteca, dependiendo de DIALOG_VARS.input_length:

  • Si DIALOG_VARS.input_length es cero, este es un puntero al búfer del usuario (en la pila, o estático). Se asume que el tamaño del búfer es MAX_LEN, que está definido en <dialog.h>.
  • Cuando DIALOG_VARS.input_length es distinto de cero, este es un búfer asignado dinámicamente usado por los widgets para devolver resultados imprimibles a la aplicación que los invoca.

Ciertos widgets copian un resultado a este búfer. Si el puntero es NULL, o si la longitud no es suficiente para el resultado, entonces la biblioteca dialog asigna un búfer lo suficientemente grande, y establece DIALOG_VARS.input_length. Los invocadores deben verificar este caso si han proporcionado su propio búfer.

.insecure

Esto corresponde a la opción de línea de comandos "--insecure". Si es verdadera, hace que el widget de contraseña sea más amigable pero menos seguro, al reflejar asteriscos por cada carácter.

.in_helpfile

Esta variable se usa para evitar que dialog_helpfile muestre algo, por ejemplo, si se presiona F1 dentro de una visualización de archivo de ayuda.

.iso_week

Esto corresponde a la opción de línea de comandos "--iso-week". Se usa en el widget de calendario para indicar cómo calcular la semana inicial del año:

  • de forma predeterminada, el calendario trata el 1 de enero como la primera semana del año.
  • Si esta variable es verdadera, el calendario usa la convención de ISO 8601. ISO 8601 numera las semanas comenzando con la primera semana de enero que tiene un jueves en el año actual. El 1 de enero puede estar en el año anterior.

.item_help

Esto corresponde a la opción de línea de comandos "--item-help". Si es verdadera, interpreta los datos de las etiquetas para las cajas de lista de verificación, lista de selección y menú agregando una columna cuyo texto se muestra en la línea inferior de la pantalla, para el elemento actualmente seleccionado.

.keep_tite

Esto se establece con la opción de línea de comandos "--keep-tite" para indicar a dialog que no intente cancelar las secuencias de inicialización de la terminal (termcap ti/te) que corresponden al cambio de pantalla alternativa de xterm. Normalmente dialog hace esto para evitar parpadeos cuando se ejecuta varias veces en un script.

.keep_window

Esto corresponde a la opción de línea de comandos "--keep-window". Si es verdadera, no elimina/redibuja la ventana al salir. Esto es útil para mantener el contenido de la ventana visible cuando se ejecutan varios widgets en el mismo proceso. Tenga en cuenta que curses borrará la pantalla al iniciar un nuevo proceso.

.last_key

Esto corresponde a la opción de línea de comandos "--last-key".

.max_input

Esto corresponde a la opción de línea de comandos "--max-input size". Limita las cadenas de entrada al tamaño dado. Si no se especifica, el límite es 2048.

.no_hot_key

Esto corresponde a la opción de línea de comandos "--no-hot-list".

Algunos widgets (buildlist, checklist, inputmenu, menu, radiolist, treeview) muestran una lista para la cual la letra inicial en mayúscula de cada entrada se acepta como una tecla rápida, para mover el foco rápidamente a esa entrada.

Establecer esta variable en TRUE desactiva la función.

.no_items

Esto corresponde a la opción de línea de comandos "--no-items". Algunos widgets (checklist, inputmenu, radiolist, menu) muestran una lista con dos columnas (una “etiqueta” y un “elemento”, es decir, “descripción”). Esto le indica a dialog que lea filas más cortas de los datos, omitiendo la “lista”.

.no_label

Esto corresponde a la opción de línea de comandos "--no-label string". La cadena dada anula la etiqueta utilizada para los botones “No”.

.no_lines

Esto corresponde a la opción de línea de comandos "--no-lines. Suprime el dibujo de líneas. Vea DIALOG_VARS.ascii_lines.

.no_nl_expand

Esto corresponde a la opción de línea de comandos "--no-nl-expand". Si es falsa, dlg_trim_string convierte las subcadenas literales "\n" en un mensaje a saltos de línea.

.no_tags

Esto corresponde a la opción de línea de comandos "--no-tags". Algunos widgets (checklist, inputmenu, radiolist, menu) muestran una lista con dos columnas (una “etiqueta” y un “elemento”, también conocido como “descripción”). La etiqueta es útil para scripting, pero puede no ser útil para el usuario. La opción --no-tags (de Xdialog) se puede utilizar para suprimir la columna de etiquetas de la visualización.

Normalmente dialog le permite moverse rápidamente a las entradas de la lista mostrada, haciendo coincidir un solo carácter con el primer carácter de la etiqueta. Cuando se proporciona la opción --no-tags, dialog busca coincidencias con el primer carácter de la descripción. En cualquier caso, el carácter coincidente se resalta.

.nocancel

Esto corresponde a la opción de línea de comandos "--no-cancel". Si es verdadero, suprime el botón “Cancelar” en los modos checklist, inputbox y menu box. Un script aún puede probar si el usuario presionó la tecla ESC para cancelar y salir.

.nocollapse

Esto corresponde a la opción de línea de comandos "--no-collapse". Normalmente dialog convierte las tabulaciones en espacios y reduce los espacios múltiples a un solo espacio para el texto que se muestra en los cuadros de mensajes, etc. Si es verdadero, esa función está deshabilitada. Tenga en cuenta que dialog seguirá ajustando el texto, sujeto a la opción --cr-wrap.

.nook

Esto corresponde a la opción de línea de comandos "--no-ok. Dialog suprimirá el botón “ok” (o “yes”) del widget.

.ok_label

Esto corresponde a la opción de línea de comandos "--ok-label cadena". La cadena dada anula la etiqueta utilizada para los botones “OK”.

.pause_secs

Cuando se establece, fuerza a dlg_set_timeout a usar 10 milisegundos en lugar de usar el valor de DIALOG_VARS.timeout_secs.

.print_siz

Esto corresponde a la opción de línea de comandos "--print-size". Si es verdadero, cada widget imprime su tamaño en la salida de dialog cuando se invoca.

.quoted

Esto corresponde a la opción de línea de comandos "--quoted. Normalmente dialog cita las cadenas devueltas por checklist, así como el texto de ayuda del elemento. Si es verdadero, dialog citará todas las cadenas de resultados.

.reorder

Esto corresponde a la opción de línea de comandos "--reorder. Por defecto, el widget buildlist utiliza el mismo orden para la salida (derecha) que para la entrada (izquierda). Si es verdadero, dialog utilizará el orden en el que un usuario añade selecciones a la lista de salida.

.separate_output

Esto corresponde a la opción de línea de comandos "--separate-output". Si es verdadero, los widgets checklist devuelven el resultado línea por línea, sin comillas. Esto facilita el análisis por parte de otro programa.

.single_quoted

Esto corresponde a la opción de línea de comandos "--single-quoted". Si es verdadero, utiliza comillas simples según sea necesario (y ninguna comilla si no es necesario) para la salida de checklist, así como para el texto de ayuda del elemento. Si esta opción no está establecida, dialog utiliza comillas dobles alrededor de cada elemento. Esto último requiere el uso ocasional de barras invertidas para que la salida sea útil en scripts de shell.

.size_err

Esto corresponde a la opción de línea de comandos "--size-err". Si es verdadero, comprueba el tamaño resultante de un cuadro de diálogo antes de intentar utilizarlo, imprimiendo el tamaño resultante si es mayor que la pantalla. (Esta opción está obsoleta, ya que todas las llamadas a nuevas ventanas se comprueban).

.tab_correct

FUNCIONES DE UTILIDAD

La mayoría de las funciones que implementan funcionalidades de nivel inferior para el programa de línea de comandos dialog o para los widgets, tienen nombres que comienzan con "dlg_". Por respeto al uso establecido, las funciones que inicializan la pantalla y la finalizan se llaman init_dialog y end_dialog.

La única función que no es de widget cuyo nombre comienza con "dialog_" es dialog_version, que devuelve el número de versión de la biblioteca como una cadena.

Algunas funciones tienen el prefijo "_dlg_", porque son necesarias para uso interno, pero no destinado como parte de la interfaz de programación de la biblioteca.

Aquí hay un breve resumen de las funciones de utilidad y sus parámetros:

dialog(3)

NOMBRE

dialog - genera ventanas de texto en modo de pantalla completa.

SINOPSIS

dialog [opciones] [parámetros]

DESCRIPCIÓN

dialog es un programa para crear cuadros de diálogo de texto en modo de pantalla completa. Se utiliza a menudo en scripts de shell para proporcionar una interfaz de usuario interactiva.

OPCIONES

--ascii-lines
Utiliza líneas ASCII para dibujar los bordes de las ventanas.
--beep
Emite un pitido al finalizar el diálogo.
--colors
Habilita el uso de secuencias de escape de escape de color ANSI.
--help
Muestra un mensaje de ayuda y sale.
--inputbox texto alto ancho [valor inicial]
Muestra un cuadro de entrada de texto.
--msgbox texto alto ancho
Muestra un cuadro de mensaje.
--yesno texto alto ancho
Muestra un cuadro de pregunta sí/no.
--version
Muestra la información de la versión y sale.

PARÁMETROS

No hay parámetros específicos. Las opciones se utilizan para controlar el comportamiento y la apariencia de los cuadros de diálogo.

EJEMPLOS

Para mostrar un cuadro de mensaje simple: 

dialog --msgbox "¡Hola, mundo!" 10 40

Para pedir al usuario un nombre: 

dialog --inputbox "Por favor, introduce tu nombre:" 10 50 "" \
       --output-fd 1

Para preguntar al usuario si desea continuar: 

dialog --yesno "¿Estás seguro de que deseas continuar?" 10 40

La salida de los comandos dialog se puede capturar y utilizar en scripts. Por ejemplo, para almacenar la respuesta de un cuadro --yesno en una variable: 

if dialog --yesno "Continuar?" 10 30; then
    echo "Has elegido continuar."
else
    echo "Has elegido no continuar."
fi
