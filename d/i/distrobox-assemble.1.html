distrobox-assemble(1)

Paquete: distrobox

DISTROBOX-ASSEMBLE(1) Manual de usuario DISTROBOX-ASSEMBLE(1)

NOMBRE

distrobox assemble
distrobox-assemble

DESCRIPCIÓN

distrobox-assemble se encarga de crear o destruir contenedores por lotes, basándose en un archivo de manifiesto. El archivo de manifiesto por defecto es ./distrobox.ini, pero se puede especificar usando el --file indicador.

SINOPSIS

distrobox assemble

--file:         ruta o URL al archivo de manifiesto/ini de distrobox
--name/-n:      ejecutar contra una sola entrada en el archivo de manifiesto/ini
--replace/-R:       reemplazar distroboxes ya existentes con nombres coincidentes
--dry-run/-d:       solo imprimir el comando del gestor de contenedores generado
--verbose/-v:       mostrar más verbosidad
--version/-V:       mostrar versión

EJEMPLOS

Este es un ejemplo de archivo de manifiesto para crear dos contenedores:

[ubuntu]
additional_packages="git vim tmux nodejs"
image=ubuntu:latest
init=false
nvidia=false
pull=true
root=false
replace=true
start_now=false
# Puedes añadir comentarios usando esto #
[arch] # también se admiten comentarios en línea
additional_packages="git vim tmux nodejs"
home=/tmp/home
image=archlinux:latest
init=false
start_now=true
init_hooks="touch /init-normal"
nvidia=true
pre_init_hooks="touch /pre-init"
pull=true
root=false
replace=false
volume="/tmp/test:/run/a /tmp/test:/run/b"

Crear

Podemos levantarlos simplemente usando

distrobox assemble create

Si el archivo se llama distrobox.ini y está en el mismo directorio desde el que lanzas el comando, no se necesitan más argumentos. Puedes especificar una ruta personalizada para el archivo usando

distrobox assemble create --file /my/custom/path.ini

O incluso especificar un archivo remoto, usando una URL:

distrobox-assemble create --file https://raw.githubusercontent.com/89luca89/dotfiles/master/distrobox.ini

Reemplazar

Por defecto, distrobox assemble reemplazará un contenedor solo si replace=true está especificado en el archivo de manifiesto.

En el ejemplo del manifiesto de arriba, el contenedor ubuntu será siempre reemplazado al ejecutar distrobox assemble create, mientras que el contenedor arch no.

Para forzar un reemplazo de todos los contenedores en un manifiesto usa el --replace indicador

distrobox assemble create --replace [--file my/custom/path.ini]

Eliminar

Podemos bajar todos los contenedores en un archivo de manifiesto simplemente haciendo

distrobox assemble rm

O usando una ruta personalizada para el archivo ini

distrobox assemble rm --file my/custom/path.ini

Probar

Siempre puedes probar qué haría distrobox haría usando el --dry-run indicador. Este comando solo imprimiría qué comandos haría distrobox sin ejecutarlos realmente.

Clonar

Aviso: Necesitas iniciar el contenedor una vez para asegurarte de que está completamente inicializado y creado antes de clonarlo. El contenedor que se copia también debe estar detenido antes de que el proceso de clonación pueda proceder.

Opciones disponibles

Esta es una lista de opciones disponibles con el tipo correspondiente:

Leyenda de tipos:

•
bool: verdadero o falso
•
string: una cadena única, por ejemplo home="/home/luca-linux/dbox"
•
string_list: múltiples cadenas, por ejemplo additional_packages="htop vim git". Nota que string_list puede declararse múltiples veces para ser compuesto:
[ubuntu]
image=ubuntu:latest
additional_packages="git vim tmux nodejs"
additional_packages="htop iftop iotop"
additional_packages="zsh fish"
Nombre del indicador Tipo
additional_flags string_list Indicadores adicionales para pasar al gestor de contenedores
additional_packages string_list Paquetes adicionales para instalar dentro del contenedor
home string Qué directorio home debe usar el contenedor
hostname string Establecer el hostname del contenedor
image string Qué imagen debe usar el contenedor, mira aquí para una lista
clone string Nombre del contenedor de Distrobox a usar como base para un nuevo contenedor (el contenedor debe estar detenido).
include string Nombre de la entrada en el manifiesto a incluir en la definición actual.
init_hooks string_list Comandos a ejecutar dentro del contenedor, después de la configuración de paquetes
pre_init_hooks string_list Comandos a ejecutar dentro del contenedor, antes de la configuración de paquetes
volume string_list Volúmenes adicionales a montar dentro de los contenedores
exported_apps string_list Nombres de aplicaciones o rutas de desktopfile a exportar
exported_bins string_list Binarios a exportar
exported_bins_path string Ruta opcional donde exportar los binarios (por defecto: $HOME/.local/bin)
entry bool Generar una entrada para el contenedor en la lista de aplicaciones (por defecto: falso)
start_now bool Iniciar el contenedor inmediatamente (por defecto: falso)
init bool Especificar si este es un contenedor con init (por defecto: falso)
nvidia bool Especificar si quieres habilitar la integración de controladores NVidia (por defecto: falso)
pull bool Especificar si quieres hacer pull de la imagen cada vez (por defecto: falso)
root bool Especificar si el contenedor es rootful (por defecto: falso)
unshare_groups bool Especificar si el contenedor debe hacer unshare de los grupos adicionales del usuario (por defecto: falso)
unshare_ipc bool Especificar si el contenedor debe hacer unshare del espacio de nombres ipc (por defecto: falso)
unshare_netns bool Especificar si el contenedor debe hacer unshare del espacio de nombres de red (por defecto: falso)
unshare_process bool Especificar si el contenedor debe hacer unshare del espacio de nombres de proceso (pid) (por defecto: falso)
unshare_devsys bool Especificar si el contenedor debe hacer unshare de /dev (por defecto: falso)
unshare_all bool Especificar si el contenedor debe hacer unshare de todas las opciones anteriores (por defecto: falso)

La include opción copia los atributos de una definición en otra. Se permiten inclusiones recursivas. Opera sobre el archivo de manifiesto y los distrobox contenedores resultantes no tienen relación de ningún tipo. Ten en cuenta que los atributos en la definición que incluye no sobrescribirán ni ocultarán los de la definición incluida, simplemente se duplicarán.

Para una explicación más detallada de cada una de las otras opciones de la lista, echa un vistazo al uso de distrobox create, cada opción corresponde a uno de los create indicadores.

Ejemplo de clonación

[ubuntu]
paquetes_adicionales="git vim tmux"
imagen=ubuntu:latest
inicializar=false
nvidia=false
traer=true
root=false
reemplazar=true
iniciar_ahora=true
[deno_ubuntu]
clonar=ubuntu
inicializar=false
nvidia=false
traer=true
root=false
reemplazar=true
iniciar_ahora=true
ganchos_de_preinicio=curl -fsSL https://deno.land/install.sh | sh;
[bun_ubuntu]
clonar=ubuntu
inicializar=false
nvidia=false
traer=true
root=false
reemplazar=true
iniciar_ahora=true
ganchos_de_preinicio=curl -fsSL https://bun.sh/install | bash;

Ejemplo de shell de inicio personalizado

[ubuntu]
imagen=ubuntu:latest
ganchos_de_preinicio="export SHELL=/bin/bash;"

Ejemplo de inclusión (heredar campos de otro distrobox)

[ubuntu]
imagen=ubuntu:latest
paquetes_adicionales="git vim tmux nodejs"
paquetes_adicionales="htop iftop iotop"
paquetes_adicionales="zsh fish"
[ubuntu-nvidia]
incluir=ubuntu
nvidia=true
