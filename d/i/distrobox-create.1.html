DISTROBOX-CREATE(1) Manual de usuario DISTROBOX-CREATE(1)

NOMBRE

distrobox create
distrobox-create

DESCRIPCIÓN

distrobox-create se encarga de crear el contenedor con el nombre y la imagen proporcionados. El contenedor creado estará estrechamente integrado con el host, permitiendo el uso compartido del directorio HOME del usuario, el almacenamiento externo, los dispositivos USB externos y las aplicaciones gráficas (X11/Wayland), y el audio.

SINOPSIS

distrobox create

--image/-i:     imagen a usar para el contenedor  por defecto: ${container_image_default}
--name/-n:      nombre para la distrobox          por defecto: ${container_name_default}
--hostname:     nombre de host para la distrobox      por defecto: <container-name>.$(uname -n)
--pull/-p:      obtener la imagen incluso si ya existe localmente (implica --yes)
--yes/-Y:       no interactivo, obtener imágenes sin preguntar
--root/-r:      lanzar podman/docker/lilipod con privilegios de root. Nota: si necesita root, esta es la forma preferida
            en lugar de "sudo distrobox" (nota: si es necesario usar un programa distinto de 'sudo' para los privilegios de root,
            especifíquelo a través de la variable de entorno DBX_SUDO_PROGRAM, o la variable de configuración 'distrobox_sudo_program')
--clone/-c:     nombre del contenedor distrobox a usar como base para un nuevo contenedor
            esto será útil para renombrar una distrobox existente o tener múltiples copias
            del mismo entorno.
--home/-H:      seleccionar un directorio HOME personalizado para el contenedor. Útil para evitar que el home del host se llene de archivos temporales.
--volume:       volúmenes adicionales a añadir al contenedor
--additional-flags/-a:  banderas adicionales a pasar al comando del gestor de contenedores
--additional-packages/-ap:  paquetes adicionales a instalar durante la configuración inicial del contenedor
--init-hooks:       comandos adicionales a ejecutar al final de la inicialización del contenedor
--pre-init-hooks:   comandos adicionales a ejecutar al inicio de la inicialización del contenedor
--init/-I:      usar el sistema init (como systemd) dentro del contenedor.
            esto hará que los procesos del host no sean visibles desde dentro del contenedor. (asume --unshare-process)
            puede requerir paquetes adicionales dependiendo de la imagen del contenedor: https://github.com/89luca89/distrobox/blob/main/docs/useful_tips.md#using-init-system-inside-a-distrobox
--nvidia:       intentar integrar los controladores nVidia del host en el huésped
--platform:     especificar qué plataforma usar, ej: linux/arm64
--unshare-devsys:          no compartir los dispositivos del host y los directorios sysfs del host
--unshare-groups:          no reenviar los grupos adicionales del usuario al contenedor
--unshare-ipc:          no compartir el espacio de nombres ipc con el host
--unshare-netns:        no compartir el espacio de nombres de red con el host
--unshare-process:          no compartir el espacio de nombres de procesos con el host
--unshare-all:          activar todas las banderas unshare de abajo
--compatibility/-C: mostrar la lista de imágenes compatibles
--help/-h:      mostrar este mensaje
--no-entry:     no generar una entrada de contenedor en la lista de aplicaciones
--dry-run/-d:       solo imprimir el comando del gestor de contenedores generado
--verbose/-v:   mostrar más verbosidad
--version/-V:   mostrar la versión
--absolutely-disable-root-password-i-am-really-positively-sure: ⚠️ ⚠️  al configurar una distrobox con root, esto omitirá la configuración de la contraseña del usuario, dejándola en blanco. ⚠️ ⚠️

COMPATIBILIDAD

para una lista de imágenes y gestores de contenedores compatibles, consulte la página man:
    man distrobox
    man distrobox-compatibility
o consulte la página de documentación en: https://github.com/89luca89/distrobox/blob/main/docs/compatibility.md#containers-distros

EJEMPLOS

Crear una distrobox con la imagen alpine, llamada my-alpine container

distrobox create --image alpine my-alpine-container

Crear una distrobox a partir de la imagen fedora-toolbox:35

distrobox create --image registry.fedoraproject.org/fedora-toolbox:35 --name fedora-toolbox-35

Clonar un contenedor distrobox existente

distrobox create --clone fedora-35 --name fedora-35-copy

Siempre obtener la nueva imagen al crear una distrobox

distrobox create --pull --image centos:stream9 --home ~/distrobox/centos9

Añadir variables de entorno adicionales al contenedor

distrobox create --image fedora:35 --name test --additional-flags "--env MY_VAR=value"

Añadir volúmenes adicionales al contenedor

distrobox create --image fedora:35 --name test --volume /opt/my-dir:/usr/local/my-dir:rw --additional-flags "--pids-limit -1"

Añadir paquetes adicionales al contenedor

distrobox create --image alpine:latest --name test2 --additional-packages "git tmux vim"

Usar init-hooks para realizar una acción durante el inicio del contenedor

distrobox create --image alpine:latest --name test --init-hooks "touch /var/tmp/test1 && touch /var/tmp/test2"

Usar pre-init-hooks para realizar una acción al comienzo del inicio del contenedor (antes de que se inicie cualquier gestor de paquetes)

distrobox create -i docker.io/almalinux/8-init --init --name test --pre-init-hooks "dnf config-manager --enable powertools && dnf -y install epel-release"

Usar init para crear un contenedor Systemd (actúa de forma similar a un LXC):

distrobox create -i ubuntu:latest --name test --additional-packages "systemd libpam-systemd pipewire-audio-client-libraries" --init

Usar init para crear un contenedor OpenRC (actúa de forma similar a un LXC):

distrobox create -i alpine:latest --name test --additional-packages "openrc" --init

Usar la integración de los controladores NVidia del host

distrobox create --image ubuntu:22.04 --name ubuntu-nvidia --nvidia

No usar la IP del host dentro del contenedor:

distrobox create --image ubuntu:latest --name test --unshare-netns

Crear un contenedor más aislado, donde solo se comparten el $HOME, los sockets básicos y el sistema de archivos del host (en /run/host):

distrobox create --name unshared-test --unshare-all

Crear un contenedor más aislado, con su propio sistema init, esto actuará de forma muy similar a un contenedor LXC completo:

distrobox create --name unshared-init-test --unshare-all --init --image fedora:latest

Usar variables de entorno para especificar el nombre del contenedor, la imagen y el gestor de contenedores:

DBX_CONTAINER_MANAGER="docker" DBX_NON_INTERACTIVE=1 DBX_CONTAINER_NAME=test-alpine DBX_CONTAINER_IMAGE=alpine distrobox-create

VARIABLES DE ENTORNO

DBX_CONTAINER_ALWAYS_PULL
DBX_CONTAINER_CUSTOM_HOME
DBX_CONTAINER_HOME_PREFIX
DBX_CONTAINER_IMAGE
DBX_CONTAINER_MANAGER
DBX_CONTAINER_NAME
DBX_CONTAINER_HOSTNAME
DBX_NON_INTERACTIVE
DBX_SUDO_PROGRAM

DBX_CONTAINER_HOME_PREFIX define dónde se ubicarán los directorios home de los contenedores. Si lo define como ~/dbx, entonces todos los directorios home de los contenedores futuros serán ~/dbx/$container_name

EXTRA

El --additional-flags o -a es útil para modificar los valores predeterminados en la creación de los contenedores. Por ejemplo:

distrobox create -i docker.io/library/archlinux -n dev-arch
podman container inspect dev-arch | jq '.[0].HostConfig.PidsLimit'
2048
distrobox rm -f dev-arch
distrobox create -i docker.io/library/archlinux -n dev-arch --volume $CBL_TC:/tc --additional-flags "--pids-limit -1"
podman container inspect dev-arch | jq '.[0].HostConfig,.PidsLimit'
0
