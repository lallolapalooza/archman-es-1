DESCRIPCIÓ

N

Los objetos de datos de despacho son contenedores opacos de bytes que representan una o más regiones de memoria. Se crean a partir de búferes de memoria gestionados por la aplicación o el sistema, o a partir de ot

ros objetos de datos de despacho. Los objetos de datos de despacho son inmutables y las regiones de memoria que representan deben permanecer sin cambios durante la vida útil de todos los objetos de datos que las re
ferencian. Los objetos de datos de despacho evitan copiar la memoria representada siempre que sea posible. Múltiples objetos de datos pueden representar las mismas regiones de memoria o subsecciones de las mismas.

CREACIÓ

N

La función dispatch_data_create() crea un nuevo objeto de datos de despacho de un tamaño dado a partir de un búfer. El bloque destructor proporcionado se enviará a la cola especificada cuando el objeto alcance el final de su ciclo de vida, indicando que el sistema ya no referencia el búfer. Esto permite a la aplicación desasignar el almacenamiento asociado. El argumento queue se ignora si se pasa uno de los siguientes destructores

predefinidos:
DISPATCH_DATA_DESTRUCTOR_F
REE
indica que el búfer proporcionado puede desasignarse con free(3)
directamente.
DISPATCH_DATA_DESTRUCTOR_DEFA
ULT
indica que el búfer proporcionado no está
gestionado por la aplicación y debe
copiarse en memoria gestionada y desasig
nada automáticamente por el sistema.

La función dispatch_data_create_concat() crea un nuevo objeto de datos que representa la concatenación de las regiones de memoria representadas por los objetos de datos

proporcionados.

La función dispatch_data_create_subrange() crea un nuevo objeto de datos que representa la subregión del objeto de datos proporcionado especificada por los parámetros offset y length

.

La función dispatch_data_create_map() crea un nuevo objeto de datos al mapear la memoria representada por el objeto de datos proporcionado como una única región de memoria contigua (moviendo o copiando memoria según sea necesario). Si las referencias buffer_ptr y size_ptr no son NULL, se rellenan con la ubicación y la extensión de la región contigua, permitiendo el acceso de lectura directa

a la memoria mapeada. Estos valores son válidos solo m
ientras el objeto recién creado no haya sido liberado.

ACCES

O

La función dispatch_data_apply() proporciona acceso de lectura a la memoria representada sin requerir que se mapee como una única región contigua. Recorre las regiones de memoria representadas por el argumento data en orden lógico, invoca el bloque applier especificado para cada región y devuelve un booleano que indica si la traversión se completó con éxito. El bloque applier recibe los siguientes argumentos para cada región de memoria y devuelve un booleano que indica si la traversión debe

OBJETO DE DATOS

VACÍO

El objeto dispatch_data_empty es el objeto singleton global que representa una región de memoria de longitud cer

o. Es una entrada válida para cualquier función
dispatch_data que tome parámetros de objeto de datos.

MODELO DE

MEMORIA

Los objetos de datos de despacho se retienen y se liberan mediante llamadas a dispatch_retain() y dispatch_release(). Los objetos de datos pasados como argumentos a una función de datos de despacho create o copy pueden liberarse cuando la función devuelve. El objeto recién creado mantiene referencias implícitas a sus regiones de memoria constituyentes según sea necesario.

Las funciones dispatch_data_create_map() y dispatch_data_apply() devuelven un puntero interno a la memoria representada que solo es válido mientras un objeto asociado no haya sido liberado. Cuando el Conteo de Referencias Automatizado de Objective-C está habilitado, se debe tener cuidado si ese objeto se mantiene en una variable con almacenamiento automático. Puede ser necesario anotarlo con el atributo objc_precise_lifetime, o almacenarlo en una variable de instancia __strong en su lugar, para asegurar que el objeto no se libere prematu

ramente antes de que se hayan completado los acc
esos a memoria a través del puntero interno.
