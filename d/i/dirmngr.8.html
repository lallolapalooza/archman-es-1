DESCRIPCIÓ

N

Desde la versión 2.1 de GnuPG, dirmngr se encarga de acceder a los servidores de claves OpenPGP. Como en versiones anteriores, también se utiliza como servidor para gestionar y descargar listas de revocación de certificados (CRL) para certificados X.509, descargar certificados X.509 y proporcionar acceso a proveedores OCSP. Dirmngr es invocado internamente por gpg, gpgsm, o a través de la herramienta gpg-connect-agen

t
.

--add-serve

Esta opción hace que dirmngr agregue cualquier servidor que descubra al validar certificados contra CRL a la lista interna de servidores a consultar para certificados y CRL. En general, no se debe usar esta opción.

Por lo tanto, si dirmngr no agrega ese nuevo servidor a la lista, a menudo no podrá verificar la firma de la CRL a menos que se use la opción --add-servers

--ocsp-signer fpr|fi

Usar el certificado con la huella digital fpr para verificar las respuestas del Responder OCSP predeterminado. Alternativamente, se puede dar un nombre de archivo, en cuyo caso se espera que la respuesta esté firmada por uno de los certificados descritos en ese archivo. Cualquier argumento que contenga una barra, un punto o un virgulilla se considera un nombre de archivo. Se realiza la expansión habitual de nombres de archivo: una virgulilla al principio seguida de una barra se reemplaza por el contenido de ‘HOME’, una ausencia de barra al principio describe un nombre de archivo relativo que se buscará en el directorio de inicio. Para asegurarse de que el archivo se busque en el directorio de inicio, anteponga el nombre con "./" o use un nombre que contenga un punto.

Si una respuesta ha sido firmada por un certificado descrito por estas huellas digitales, no se realiza ninguna otra verificación sobre la validez de este

certificado.

Dirmngr utiliza varios directorios cuando se ejecuta en modo demonio: Hay algunos archivos de configuración para controlar el funcionamiento de dirmngr. De forma predeterminada, todos pueden encontrarse en el directorio de inicio actual (ver: [opción --homedir])

.
dirmngr.
conf
Este es el archivo de configuración estándar leído por dirmngr al inicio. Puede contener cualquier opción larga válida; no se deben introducir los dos guiones iniciales y la opción no se puede abreviar. Este archivo también se lee después de un SIGHUP, sin embargo, no todas las opciones tendrán realmente un efecto. Este nombre predeterminado se puede cambiar en la línea de comandos (ver: [opción --options]). Debería hacer una copia de seguridad de este
archivo.
/etc/gnupg/trusted-ce
rts
Este directorio debería estar lleno con certificados de CA raíz en las que confía para verificar las CRL y firmar las respuestas OCSP.

Usualmente, estos son los mismos certificados que usa con las aplicaciones que utilizan dirmngr. Se espera que cada uno de estos archivos de certificados contenga exactamente un certificado codificado en DER en un archivo con el sufijo ‘.crt’ o ‘.der’. dirmngr lee those los certificados al inicio y cuando recibe un SIGHUP. Los certificados que no se pueden leer o que no constituyen un certificado X.509 válido se ignoran; consulte el archivo de registro para obtener

detalles.

Las aplicaciones que usan dirmngr (por ejemplo, gpgsm) pueden solicitar estos certificados para completar una cadena de confianza de la misma manera que con el directorio extra-certs (ver más

abajo).

Tenga en cuenta que para las respuestas OCSP, el certificado especificado mediante la opción --ocsp-signer siempre se considera v

álido para firmar
solicitudes OCSP.
