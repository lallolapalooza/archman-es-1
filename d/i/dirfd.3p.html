DIRFD(3P) Manual del programador POSIX DIRFD(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

dirfd — extraer el descriptor de archivo utilizado por un flujo DIR

SINOPSIS

#include <dirent.h>
int dirfd(DIR *dirp);

DESCRIPCIÓN

La función dirfd() devolverá un descriptor de archivo que hace referencia al mismo directorio que el argumento dirp. Este descriptor de archivo se cerrará mediante una llamada a closedir(). Si se intenta cerrar el descriptor de archivo, o modificar el estado de la descripción asociada, de forma distinta a través de closedir(), readdir(), readdir_r(), rewinddir() o seekdir(), el comportamiento es indefinido.

VALOR DE RETORNO

Al completarse con éxito, la función dirfd() devolverá un entero que contiene un descriptor de archivo para el flujo al que apunta dirp. De lo contrario, devolverá -1 y establecerá la variable errno para indicar el error.

ERRORES

La función dirfd() puede fallar si:

EINVAL
El argumento dirp no hace referencia a un flujo de directorio válido.

Las siguientes secciones son informativas.

EJEMPLOS

Ninguno.

USO DE LA APLICACIÓN

La función dirfd() está pensada como un mecanismo mediante el cual una aplicación puede obtener un descriptor de archivo para usarlo con la función fchdir().

FUNDAMENTO

Esta interfaz se introdujo porque el volumen de Definiciones Base de POSIX.1‐2017 no hace pública la estructura de datos DIR. Las aplicaciones tienden a utilizar la función fchdir() en el descriptor de archivo devuelto por esta interfaz, y esto ha demostrado ser útil por razones de seguridad; en particular, es una técnica mejor que otras en las que los nombres de los directorios pueden cambiar.

La descripción utiliza el término ``un descriptor de archivo'' en lugar de ``el descriptor de archivo''. La implicación prevista es que una implementación que no utilice un fd para opendir() aún podría open() el directorio para implementar la función dirfd(). Dicho descriptor debe cerrarse más tarde durante una llamada a closedir().

Si es necesario asignar un fd para que lo devuelva dirfd(), debe hacerse en el momento de una llamada a opendir().
