NOMBRE

dispatch_async, dispatch_sync — programar bloques para ejecución

SINOPSIS

#include <dispatch/dispatch.h>

void
dispatch_async(dispatch_queue_t queue, void (^block)(void));

void
dispatch_sync(dispatch_queue_t queue, void (^block)(void));

void
dispatch_async_f(dispatch_queue_t queue, void *context, void (*function)(void *));

void
dispatch_sync_f(dispatch_queue_t queue, void *context, void (*function)(void *));

DESCRIPCIÓN

Las funciones dispatch_async() y dispatch_sync() programan bloques para ejecución concurrente dentro del framework dispatch(3). Los bloques se envían a una cola que dicta la política para su ejecución. Consulte dispatch_queue_create(3) para obtener más información sobre la creación de colas de despacho.

Estas funciones admiten sincronización temporal eficiente, concurrencia en segundo plano y concurrencia a nivel de datos. Estas mismas funciones también se pueden usar para la notificación eficiente de la finalización de bloques asíncronos (también conocidos como devoluciones de llamada).

SINCRONIZACIÓN TEMPORAL

La sincronización a menudo es necesaria cuando múltiples hilos de ejecución acceden a datos compartidos concurrentemente. La forma más simple de sincronización es la exclusión mutua (un bloqueo), mediante la cual diferentes subsistemas se ejecutan concurrentemente hasta que se accede a una sección crítica compartida. En la familia de procedimientos pthread(3), la sincronización temporal se logra de la siguiente manera:

int r = pthread_mutex_lock(&my_lock);
assert(r == 0);

// sección crítica

r = pthread_mutex_unlock(&my_lock);
assert(r == 0);

La función dispatch_sync() se puede usar con una cola serializada para lograr el mismo estilo de sincronización. Por ejemplo:

dispatch_sync(my_queue, ^{
	// sección crítica
});

Además de proporcionar una expresión de sincronización más concisa, este enfoque es menos propenso a errores ya que la sección crítica no se puede abandonar accidentalmente sin restaurar la cola a un estado reentrante.

La función dispatch_async() se puede usar para implementar secciones críticas diferidas cuando el resultado del bloque no se necesita localmente. Las secciones críticas diferidas tienen las mismas propiedades de sincronización que el código anterior, pero no bloquean y, por lo tanto, son más eficientes de realizar. Por ejemplo:

dispatch_async(my_queue, ^{
	// sección crítica
});

CONCURRENCIA EN SEGUNDO PLANO

La función dispatch_async() se puede usar para ejecutar tareas triviales en segundo plano en una cola global concurrente. Por ejemplo:

dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT,0), ^{
	// operación en segundo plano
});

Este enfoque es un reemplazo eficiente para pthread_create(3).

DEVOLUCIONES DE LLAMADA DE FINALIZACIÓN

Las devoluciones de llamada de finalización se pueden lograr mediante llamadas anidadas a la función dispatch_async(). Es importante recordar retener la cola de destino antes de la primera llamada a dispatch_async(), y liberar esa cola al final de la devolución de llamada de finalización para asegurar que la cola de destino no se libere mientras la devolución de llamada de finalización está pendiente. Por ejemplo:

void
async_read(object_t obj,
	void *where, size_t bytes,
	dispatch_queue_t destination_queue,
	void (^reply_block)(ssize_t r, int err))
{
	// Hay mejores maneras de hacer I/O asíncrono.
	// Este es solo un ejemplo de bloques anidados.

	dispatch_retain(destination_queue);

	dispatch_async(obj->queue, ^{
		ssize_t r = read(obj->fd, where, bytes);
		int err = errno;

		dispatch_async(destination_queue, ^{
			reply_block(r, err);
		});
		dispatch_release(destination_queue);
	});
}

BLOQUEOS RECURSIVOS

Mientras que dispatch_sync() puede reemplazar un bloqueo, no puede reemplazar un bloqueo recursivo. A diferencia de los bloqueos, las colas admiten operaciones asíncronas y síncronas, y esas operaciones están ordenadas por definición. Una llamada recursiva a dispatch_sync() provoca un simple interbloqueo ya que el bloque en ejecución actual espera a que se complete el siguiente bloque, pero el siguiente bloque no comenzará hasta que se complete el bloque que se está ejecutando actualmente.

Mientras se diseñaba el framework de despacho, estudiamos los bloqueos recursivos. Descubrimos que la gran mayoría de los bloqueos recursivos se implementan retroactivamente cuando se descubren jerarquías de bloqueo mal definidas. Como consecuencia, la adopción de bloqueos recursivos a menudo muta errores obvios en errores oscuros. Este estudio también reveló una idea: si la reentrada es inevitable, entonces los bloqueos de lectura/escritura son preferibles a los bloqueos recursivos. El uso disciplinado de los bloqueos de lectura/escritura permite la reentrada solo cuando la reentrada es segura (el lado de "lectura" del bloqueo).

Sin embargo, si es absolutamente necesario, lo siguiente es una forma imperfecta de implementar bloqueos recursivos utilizando el framework de despacho:

void
sloppy_lock(object_t object, void (^block)(void))
{
	if (object->owner == pthread_self()) {
		return block();
	}
	dispatch_sync(object->queue, ^{
		object->owner = pthread_self();
		block();
		object->owner = NULL;
	});
}

El ejemplo anterior no resuelve el caso en el que la cola A se ejecuta en el hilo X que llama a dispatch_sync() contra la cola B que se ejecuta en el hilo Y que llama recursivamente a dispatch_sync() contra la cola A, lo que bloquea ambos ejemplos. Esto es compatible, error por error, con el uso no trivial de pthread. De hecho, la reentrada no trivial es imposible de soportar en bloqueos recursivos una vez que se implementa el nivel definitivo de reentrada (IPC o RPC).

REFERENCIAS IMPLÍCITAS

Las funciones síncronas dentro del framework de despacho tienen una referencia implícita en la cola de destino. En otras palabras, la función síncrona toma prestada la referencia de la función que llama (esto es válido porque la función que llama está bloqueada esperando el resultado de la función síncrona, y por lo tanto no puede modificar el recuento de referencia de la cola de destino hasta después de que la función síncrona haya devuelto). Por ejemplo:

queue = dispatch_queue_create("com.example.queue", NULL);
assert(queue);
dispatch_sync(queue, ^{
	do_something();
	//dispatch_release(queue); // NO SEGURO -- dispatch_sync() todavía está usando 'queue'
});
dispatch_release(queue); // Equilibrado DE FORMA SEGURA fuera del bloque proporcionado a dispatch_sync()

Esto contrasta con las funciones asíncronas que deben retener tanto el bloque como la cola de destino durante la operación asíncrona (ya que la función que llama puede liberar inmediatamente su interés en estos objetos).

TEMPORAL SYNCHRONIZATION

The dispatch_sync() function is used to synchronize operations. If the target queue is a serial queue, then the call to dispatch_sync() will block the calling thread until the block completes execution. If the target queue is a concurrent queue, then the call to dispatch_sync() will block the calling thread until the block completes execution.

Use dispatch_sync() to ensure that a block is executed and completed before the calling thread continues.

BACKGROUND CONCURRENCY

The dispatch_async() function is used to submit blocks for asynchronous execution. The function returns immediately, and does not wait for the block to complete execution.

Use dispatch_async() to offload work to a background thread or queue without blocking the calling thread.

COMPLETION CALLBACKS

When using dispatch_sync() or dispatch_async() with C-style functions (using dispatch_sync_f() and dispatch_async_f()), you can use a dispatch_semaphore_create(3) semaphore to wait for completion of the block, and a wrapper around the block to signal its completion. See dispatch_semaphore_create(3) for more information about dispatch semaphores. The actual implementation of the dispatch_sync() function may be optimized and differ from the above description.

The dispatch_async() function is a wrapper around dispatch_async_f(). The application-defined context parameter is passed to the function when it is invoked on the target queue.
