NOMBRE

dispatch_io_create, dispatch_io_create_with_path, dispatch_io_close, dispatch_io_set_high_water, dispatch_io_set_low_water, dispatch_io_set_interval, dispatch_io_barrier — abrir, cerrar y configurar canales de E/S de dispatch

SINOPSIS

#include <dispatch/dispatch.h>

dispatch_io_t
dispatch_io_create(dispatch_io_type_t type, int fd, dispatch_queue_t queue, void (^cleanup_handler)(int error));

dispatch_io_t
dispatch_io_create_with_path(dispatch_io_type_t type, const char *path, int oflag, mode_t mode, dispatch_queue_t queue, void (^cleanup_handler)(int error));

void
dispatch_io_close(dispatch_io_t channel, dispatch_io_close_flags_t flags);

void
dispatch_io_set_high_water(dispatch_io_t channel, size_t high_water);

void
dispatch_io_set_low_water(dispatch_io_t channel, size_t low_water);

void
dispatch_io_set_interval(dispatch_io_t channel, uint64_t interval, dispatch_io_interval_flags_t flags);

void
dispatch_io_barrier(dispatch_io_t channel, void (^barrier)(void));

DESCRIPCIÓN

El marco de trabajo de E/S de dispatch es una API para operaciones de E/S de lectura y escritura asíncronas. Es una aplicación de las ideas e idiomas presentes en el dispatch(3) marco de trabajo a la E/S de dispositivos. E/S de dispatch permite a una aplicación evitar más fácilmente las operaciones de E/S bloqueantes y le permite expresar sus requisitos de E/S de manera más directa que usando la API de archivos POSIX sin procesar. E/S de dispatch hará todo lo posible por optimizar cómo y cuándo se realizan las operaciones de E/S asíncronas basándose en las capacidades del dispositivo de destino.

Esta página proporciona detalles sobre cómo crear y configurar canales de E/S de dispatch. La lectura y escritura en estos canales se tratan en la página dispatch_io_read(3) . El marco de trabajo de E/S de dispatch también proporciona las funciones de conveniencia dispatch_read(3) y dispatch_write(3) para usos que no requieren toda la funcionalidad proporcionada por los canales de E/S.

FUNDAMENTOS

Un canal de E/S de dispatch representa la política de E/S asíncrona aplicada a un descriptor de archivo y lo encapsula con fines de seguimiento de propiedad mientras las operaciones de E/S están en curso.

TIPOS DE CANAL

Los canales de E/S de dispatch pueden tener uno de los siguientes tipos:

DISPATCH_IO_STREAM
canales que representan un flujo de bytes y no soportan lecturas y escrituras en desplazamientos arbitrarios, como tuberías o sockets. Los canales de este tipo realizan operaciones de lectura y escritura secuencialmente en la posición actual del puntero de archivo e ignoran cualquier desplazamiento especificado. Dependiendo del descriptor de archivo subyacente, las operaciones de lectura pueden realizarse simultáneamente con las operaciones de escritura.
DISPATCH_IO_RANDOM
canales que representan archivos de acceso aleatorio en disco. Solo soportado para descriptores de archivo y rutas que permiten búsqueda. Los canales de este tipo pueden realizar operaciones de lectura y escritura enviadas de forma concurrente en el desplazamiento especificado (interpretado relativo a la posición del puntero de archivo cuando se creó el canal).

APERTURA Y CIERRE DE CANALES

Las funciones dispatch_io_create() y dispatch_io_create_with_path() crean un canal de E/S de dispatch del tipo proporcionado a partir de un descriptor de archivo fd o una ruta de nombre absoluta, respectivamente. Pueden considerarse análogas a la función POSIX fdopen(3) y la función fopen(3) en la biblioteca estándar de C. Para un canal creado a partir de una ruta de nombre, los parámetros proporcionados path, oflag y mode se pasarán a open(2) cuando la primera operación de E/S en el canal esté lista para ejecutarse.

El bloque cleanup_handler proporcionado será enviado a la cola especificada cuando todas las operaciones de E/S en el canal se hayan completado y este se cierre o alcance el final de su ciclo de vida. Si ocurre un error durante la creación del canal, el bloque cleanup_handler se enviará inmediatamente y se le pasará un parámetro error con el error POSIX encontrado. Si se especifica un tipo inválido o un argumento path no absoluto, estas funciones devolverán NULL y el cleanup_handler no será invocado. Después de crear con éxito un canal de E/S de dispatch a partir de un descriptor de archivo, la aplicación debe tener cuidado de no modificar ese descriptor de archivo hasta que el cleanup_handler asociado sea invocado, ver PROPIEDAD DEL DESCRIPTOR DE ARCHIVO para detalles.

La función dispatch_io_close() cierra un canal de E/S de dispatch a nuevos envíos de operaciones de E/S. Si se pasa DISPATCH_IO_STOP en el parámetro flags , el sistema además no realizará las operaciones de E/S ya enviadas al canal que aún estén pendientes e interrumpirá, dentro de lo posible, cualquier operación en curso. A los manejadores de las operaciones afectadas se les pasará el código de error ECANCELED , junto con cualquier resultado parcial.

CONFIGURACIÓN DE CANALES

Los canales de E/S de dispatch tienen configuraciones de marca de agua alta, marca de agua baja e intervalo que determinan si y cuándo se entregan resultados parciales de las operaciones de E/S a través de sus manejadores de E/S asociados.

Las funciones dispatch_io_set_high_water() y dispatch_io_set_low_water() configuran los ajustes de marca de agua de un canal. El sistema leerá o escribirá al menos el número de bytes especificado por low_water antes de enviar un manejador de E/S con resultados parciales, y hará todo lo posible por enviar un manejador de E/S tan pronto como el número de bytes leídos o escritos alcance high_water.

La función dispatch_io_set_interval() configura el intervalo de tiempo en el que se envían los manejadores de E/S (medido en nanosegundos). Si se pasa DISPATCH_IO_STRICT_INTERVAL en el parámetro flags , el intervalo se observará estrictamente incluso si hay una cantidad insuficiente de datos para entregar; de lo contrario, la entrega se omitirá para los intervalos en los que la cantidad de datos disponibles sea inferior a la marca de agua baja del canal. Tenga en cuenta que el el sistema puede diferir la encolación de manejadores de E/S de intervalo por una pequeña cantidad no especificada de holgura para alinearla con otra actividad del sistema, mejorando el rendimiento del sistema o el consumo de energía.

ENTREGA DE DATOS

El tamaño de los objetos de datos pasados a los manejadores de E/S de un canal nunca será mayor que la marca de agua alta establecida en el canal; tampoco será nunca menor que la marca de agua baja, excepto en los siguientes casos:

  • la última invocación del manejador para una operación de E/S
  • se encontró EOF (fin de archivo)
  • el canal tiene un intervalo con el DISPATCH_IO_STRICT_INTERVAL indicador establecido
Tenga en cuenta que los canales de E/S de dispatch normalmente entregarán cantidades de datos significativamente mayores que la marca de agua baja. El valor predeterminado para la marca de agua baja no está especificado, pero se debe asumir que permite invocaciones intermedias de manejadores. El valor predeterminado para la marca de agua alta es ilimitado (es decir, SIZE_MAX). Los canales que requieren resultados intermedios de tamaño fijo deben tener tanto la marca de agua baja como la marca de agua alta establecidas a ese tamaño. Los canales que no deseen recibir ningún resultado intermedio deben tener la marca de agua baja establecida a SIZE_MAX.

PROPIEDAD DEL DESCRIPTOR DE ARCHIVO

Cuando una aplicación crea un canal de E/S de dispatch a partir de un descriptor de archivo con la dispatch_io_create() close(2) el descriptor de archivo. Mientras un descriptor de archivo está bajo el control de un canal de E/S de dispatch, los indicadores del descriptor de archivo como O_NONBLOCK serán modificados por el sistema en nombre de la aplicación. Es un error que la aplicación modifique un descriptor de archivo directamente mientras está bajo el control de un canal de E/S de dispatch, pero puede crear más canales de E/S a partir de ese descriptor de archivo o usar las funciones de conveniencia dispatch_read(3) y dispatch_write(3) con ese descriptor de archivo. Si se han creado múltiples canales de E/S a partir del mismo descriptor de archivo, todos los manejadores de limpieza asociados se enviarán juntos una vez que el último canal haya sido cerrado o todas las referencias a esos canales hayan sido liberadas. Si también se han usado funciones de conveniencia en ese descriptor de archivo, el envío de sus manejadores estará vinculado al envío de los manejadores de limpieza del canal también.

OPERACIONES DE BARRERA

La dispatch_io_barrier() read(2) o write(2)) en el descriptor de archivo subyacente hayan terminado. No se iniciarán nuevas operaciones de E/S hasta que el bloque de barrera termine.

El bloque de barrera puede operar en el descriptor de archivo subyacente con funciones como fsync(2) o lseek(2). Como se discutió en la PROPIEDAD DEL DESCRIPTOR DE ARCHIVO sección, el bloque de barrera no debe close(2) el descriptor de archivo, y si cambia algún indicador en el descriptor de archivo, debe restaurarlo antes de terminar.

No hay sincronización entre un bloque de barrera y ningún dispatch_io_read(3) o dispatch_io_write(3) bloques de manejador; pueden estar ejecutándose al mismo tiempo. El bloque de barrera en sí es responsable de cualquier sincronización requerida.

MODELO DE MEMORIA

Los objetos de canal de E/S de dispatch se retienen y se liberan mediante llamadas a dispatch_retain() dispatch_release().
