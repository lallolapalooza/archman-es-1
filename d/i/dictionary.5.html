NOMBRE

dictionary - Archivo de diccionario RADIUS

DESCRIPCIÓN

El archivo de diccionario RADIUS maestro reside en /etc/raddb/dictionary. Referencia a otros archivos de dictionary ubicados en /usr/share/freeradius/. Cada archivo de diccionario contiene una lista de atributos y valores RADIUS, que el servidor utiliza para mapear entre nombres descriptivos y datos en tránsito. Los nombres no tienen significado fuera del propio servidor RADIUS, y nunca se intercambian entre el servidor y los clientes.

Es decir, editar los diccionarios NO TENDRÁ EFECTO en nada más que en el servidor que está leyendo esos archivos. Añadir nuevos atributos a los diccionarios NO TENDRÁ EFECTO en los clientes RADIUS, y no hará que los clientes RADIUS comprendan mágicamente esos atributos. Los diccionarios son exclusivamente para la conveniencia del administrador local, y son específicos para cada versión de FreeRADIUS.

Los diccionarios en /usr/share NO DEBERÍAN ser editados a menos que sepa exactamente lo que está haciendo. Modificarlos probablemente romperá su implementación RADIUS.

Si necesita añadir nuevos atributos, por favor edite el archivo /etc/raddb/dictionary. Su único propósito es contener definiciones locales del sitio que son añadidas por el administrador local.

FORMATO

Cada línea que comienza con un signo de almohadilla ('#') se trata como un comentario y se ignora.

Cada línea del archivo puede contener una de las siguientes cadenas:

ATTRIBUTE nombre oid tipo [indicadores]
Define un mapeo de nombre a número de atributo RADIUS.

El campo nombre es un campo imprimible, tomado de varias especificaciones o definiciones de proveedores. Es más comúnmente usado como una serie de palabras, separadas por guiones. Ej. "User-Name". Los atributos específicos del proveedor (VSA) son prefijados por el nombre del proveedor, Ej. "Cisco-AVPair". Los nombres deben ser globalmente únicos, ya que se utilizan como clave para buscar las propiedades del atributo.

El campo oid se toma de la especificación relevante para ese nombre. En la mayoría de los casos, es un número decimal, como "256". Para ciertos atributos, se utiliza una notación de "número punteado", Ej. "1.2". La notación de "número punteado" se utiliza solo para ciertos atributos.

El campo tipo puede ser uno de los tipos estándar:


string Texto imprimible UTF-8 (las RFCs lo llaman "text")
octets Datos binarios opacos (las RFCs lo llaman "string")
ipaddr Dirección IPv4
date Segundos desde el 1 de enero de 1970 (32 bits)
integer Entero sin signo de 32 bits
ipv6addr Dirección IPv6
ipv6prefix Prefijo IPV6, con máscara
ifid Identificador de Interfaz (hex:hex:hex:hex)
integer64 Entero sin signo de 64 bits

El campo tipo puede ser uno de los siguientes tipos no estándar:


ether Dirección MAC Ethernet
abinary Formato de filtro binario Ascend
byte Entero sin signo de 8 bits
short Entero sin signo de 16 bits
signed Entero con signo de 31 bits (empaquetado en campo de 32 bits)
tlv Tipo-Longitud-Valor (permite atributos anidados)
ipv4prefix Prefijo IPv4 como se da en RFC 6572.

El último campo (opcional) de una definición de atributo son indicadores adicionales para ese atributo, en una lista separada por comas. Versiones anteriores del servidor permitían que estos indicadores incluyeran un nombre de proveedor. Este comportamiento puede seguir funcionando, pero está obsoleto y no se recomienda.

Las opciones son:


array Múltiples valores se empaquetan en un atributo.
concat Múltiples atributos deben concatenarse
encrypt=# establece tipo de encriptación 1, 2 o 3.
has_tag El atributo puede tener una etiqueta estilo RFC 2868
secret Un valor que no debe imprimirse en modo de depuración
virtual El atributo es especial para el servidor.

El indicador "array" se utiliza solo para DHCP. Indica que una opción DHCP puede contener una matriz de múltiples valores.

El indicador "concat" indica que cuando hay múltiples atributos presentes en un paquete, el contenido debe concatenarse para obtener el contenido final. De manera similar, al codificar paquetes, un valor largo debe dividirse en múltiples atributos.

El indicador "encrypt" marca el atributo como encriptado con uno de los tres métodos posibles. "1" significa que el atributo está encriptado con el método definido en RFC2865 para el atributo User-Password. "2" significa que la contraseña está encriptada con el método definido en RFC2868 para el atributo Tunnel-Password. "3" significa que el atributo está encriptado según las definiciones de Ascend para el atributo Ascend-Send-Secret.

El indicador "has_tag" marca el atributo como permitido tener una etiqueta, como se define en RFC2868. El propósito de la etiqueta es permitir la agrupación de atributos para usuarios tunelizados. Consulte RFC2868 para más detalles.

El indicador "secret" indica que el valor no debe imprimirse en modo de depuración normal. El valor se imprimirá cuando el nivel de depuración sea 3 o superior.

El indicador "virtual" es para el servidor, e indica que el atributo no existe realmente. En su lugar, el valor se toma de una llamada de retorno interna.

Cuando el servidor recibe un atributo codificado en un paquete RADIUS, busca ese atributo por su número en el diccionario, y utiliza la definición encontrada allí para imprimir mensajes de diagnóstico y registro. Cuando el servidor ve un nombre de atributo en un archivo de configuración, busca ese atributo por su nombre en el diccionario, y utiliza la definición encontrada allí.

VALUE nombre-atributo nombre-valor número
Define un mapeo de nombre a número de valor de atributo, para un atributo de tipo integer. El campo nombre-atributo DEBE estar definido previamente por una entrada de ATTRIBUTE. El campo nombre-valor puede ser cualquier texto sin espacios, pero generalmente se toma de RFC2865 u otros documentos. El campo número también se toma de los documentos relevantes, para ese nombre.

Cuando el servidor recibe un valor codificado en un paquete RADIUS, busca el valor de ese atributo por su número en el diccionario, y utiliza el nombre encontrado allí para imprimir mensajes de diagnóstico y registro.

VENDOR nombre-proveedor número [format=...]
Define una encapsulación de Atributo Específico del Proveedor para nombre-proveedor a número. Para una lista de nombres y números de proveedores, consulte http://www.iana.org/enterprise-numbers.txt.

La declaración "format=t,l" le dice al servidor cuántos octetos usar para codificar/decodificar los campos de "tipo" y "longitud" del proveedor en los atributos. El valor predeterminado es "format=1,1", que no tiene que especificarse. Para los VSA de USR, el formato es "format=4,0", para los VSA de Lucent es "format=2,1", y para los VSA de Starent es "format=2,2".

Los valores soportados para el número de octetos de tipo (es decir, el primer dígito) son 1, 2 y 4. Los valores soportados para el número de octetos de longitud (es decir, el segundo dígito) son 0, 1 y 2. Cualquier combinación de esos valores funcionará.

BEGIN-VENDOR nombre-proveedor
Define el inicio de un bloque de atributos específicos del proveedor. Todas las siguientes definiciones de ATTRIBUTE se interpretan como para el proveedor nombrado, hasta que el bloque se cierre con una declaración "END-VENDOR".

Esta práctica es preferible a colocar el nombre del proveedor al final de una definición de ATTRIBUTE.

Para los VSA en el espacio "Extended vendor-specific" de RFC 6929, se puede especificar un formato después del "nombre-proveedor". El formato debe ser "format=Extended-Vendor-Specific-1", a "format=Extended-Vendor-Specific-6". El "END-VENDOR" correspondiente solo debe tener el "nombre-proveedor", sin la cadena de formato.
