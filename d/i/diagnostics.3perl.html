diagnostics(3perl) Guía de referencia para programadores de Perl diagnostics(3perl)

NOMBRE

diagnostics, splain - producir diagnósticos de advertencia detallados

SINOPSIS

Usando la "diagnostics" directiva:

use diagnostics;
use diagnostics -verbose;
diagnostics->enable;
diagnostics->disable;

Usando el "splain" programa de filtrado independiente:

perl program 2>diag.out
splain [-v] [-p] diag.out

Usando diagnostics para obtener trazas de pila de un script que se comporta mal:

perl -Mdiagnostics=-traceonly my_script.pl

DESCRIPCIÓN

La directiva "diagnostics"

Este módulo extiende los diagnósticos concisos que normalmente emiten tanto el compilador de perl como el intérprete de perl (al ejecutar perl con el interruptor -w o "use warnings"), aumentándolos con las descripciones más explicativas y agradables que se encuentran en perldiag. Como las demás directivas, afecta a la fase de compilación de tu programa en lugar de limitarse a la fase de ejecución.

Para usarlo en tu programa como directiva, simplemente invoca

use diagnostics;

al principio (o cerca del principio) de tu programa. (Ten en cuenta que esto activa la bandera -w de perl.) Toda tu compilación estará entonces sujeta (sufriendo :-) a los diagnósticos mejorados. Estos siguen saliendo por STDERR.

Debido a la interacción entre problemas en tiempo de ejecución y en tiempo de compilación, y porque probablemente no sea una buena idea de todos modos, no puedes usar "no diagnostics" para desactivarlos en tiempo de compilación. Sin embargo, puedes controlar su comportamiento en tiempo de ejecución usando los métodos disable() y enable() para desactivarlos y activarlos respectivamente.

La bandera -verbose imprime primero la introducción de perldiag antes de cualquier otro diagnóstico. La variable $diagnostics::PRETTY puede generar secuencias de escape más agradables para pagers.

Las advertencias despachadas por el propio perl (o más precisamente, aquellas que coinciden con descripciones encontradas en perldiag) solo se muestran una vez (sin descripciones duplicadas). Las advertencias generadas por el código del usuario al estilo de warn() no se ven afectadas, permitiendo que se muestren mensajes de usuario duplicados.

Este módulo también añade una traza de pila al mensaje de error cuando perl muere. Esto es útil para localizar qué causó la muerte. La bandera -traceonly (o simplemente -t) desactiva las explicaciones de los mensajes de advertencia dejando solo las trazas de pila. Así que si tu script está muriendo, ejecútalo de nuevo con

perl -Mdiagnostics=-traceonly my_bad_script

para ver la pila de llamadas en el momento de la muerte. Proporcionando la bandera -warntrace (o simplemente -w), cualquier advertencia emitida también vendrá con una traza de pila.

El programa splain Programa

Otro programa, splain es en realidad nada más que un enlace al módulo (ejecutable) diagnostics.pm , así como un enlace a la documentación diagnostics.pod . La bandera -v es como la directiva "use diagnostics -verbose" . La bandera -p es como la variable $diagnostics::PRETTY . Dado que estás postprocesando con splain, no tiene sentido poder enable() o disable() el procesamiento.

La salida de splain se dirige a STDOUT, a diferencia de la directiva.

EJEMPLOS

El siguiente archivo seguramente provocará algunos errores tanto en tiempo de ejecución como en tiempo de compilación:

use diagnostics;
print NOWHERE "nothing\n";
print STDERR "\n\tThis message should be unadorned.\n";
warn "\tThis is a user warning";
print "\nDIAGNOSTIC TESTER: Please enter a <CR> here: ";
my $a, $b = scalar <STDIN>;
print "\n";
print $x/$y;

Si prefieres ejecutar tu programa primero y ver sus problemas después, haz esto:

perl -w test.pl 2>test.out
./splain < test.out

Ten en cuenta que esto generalmente no es posible en shells de procedencia más dudosa, ya que el teórico

(perl -w test.pl >/dev/tty) >& test.out
./splain < test.out

Porque acabas de mover el stdout existente a algún otro lugar.

Si no quieres modificar tu código fuente, pero aún así quieres advertencias en tiempo real, haz esto:

exec 3>& perl -w test.pl 2>&1 1>&3 3>&- | splain 1>&2 3>&-

Ingenioso, ¿verdad?

Si quieres controlar las advertencias en tiempo real, haz algo como esto. Asegúrate de hacer el "use" primero, o no podrás acceder a los enable() o disable() métodos.

use diagnostics; # checks entire compilation phase 
    print "\ntime for 1st bogus diags: SQUAWKINGS\n";
    print BOGUS1 'nada';
    print "done with 1st bogus\n";
diagnostics->disable; # only turns off runtime warnings
    print "\ntime for 2nd bogus: (squelched)\n";
    print BOGUS2 'nada';
    print "done with 2nd bogus\n";
diagnostics->enable; # turns back on runtime warnings
    print "\ntime for 3rd bogus: SQUAWKINGS\n";
    print BOGUS3 'nada';
    print "done with 3rd bogus\n";
diagnostics->disable;
    print "\ntime for 4th bogus: (squelched)\n";
    print BOGUS4 'nada';
    print "done with 4th bogus\n";

INTERNOS

Los mensajes de diagnóstico se derivan del archivo perldiag.pod cuando está disponible en tiempo de ejecución. De lo contrario, pueden estar incrustados en el archivo mismo cuando se construye el paquete splain. Ver el Makefile para detalles.

Si se descubre un manejador $SIG{__WARN__} existente, continuará siendo atendido, pero solo después de que la función diagnostics::splainthis() (el interceptador $SIG{__WARN__} del módulo) haya hecho lo suyo con tus advertencias.

Hay una variable $diagnostics::DEBUG que puedes establecer si estás desesperadamente curioso sobre qué tipo de cosas están siendo interceptadas.

BEGIN { $diagnostics::DEBUG = 1 }

ERRORES

No poder decir "no diagnostics" es molesto, pero puede no ser insuperable.

La directiva "-pretty" se llama demasiado tarde para afectar los asuntos. Tienes que hacer esto en su lugar, y antes de cargar el módulo.

BEGIN { $diagnostics::PRETTY = 1 }

Podría arrancar más rápido retrasando la compilación hasta que se necesite, pero esto produce un "panic: top_level" al usar la forma de directiva en Perl 5.001e.

Aunque es cierto que esta documentación es algo poco seria, si usas un programa llamado splain, deberías esperar un poco de fantasía.

    NOMBRE

    diagnostics - Módulo de diagnóstico de Perl

    SINOPSIS

        use diagnostics;
    use diagnostics qw(:all);
    use diagnostics qw(diagnoze);
    no diagnostics;

    DESCRIPCIÓN

    El módulo diagnostics es un módulo de ayuda que proporciona información de diagnóstico útil sobre advertencias de Perl.

    ADVERTENCIAS

    Cuando se utiliza el módulo diagnostics, las advertencias generadas por Perl se amplían para proporcionar más detalles y contexto. Esto puede ser útil para depurar y comprender por qué se generan ciertas advertencias.

    EJEMPLOS

    Aquí hay un ejemplo simple de cómo usar el módulo diagnostics:

        use diagnostics;

    my $var;
    print $var; # Esto generará una advertencia de variable indefinida,
                # pero con 'diagnostics' será más detallada.
