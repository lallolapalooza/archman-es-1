Dist::CheckConflicts(3) Documentación de Perl aportada por el usuario Dist::CheckConflicts(3)

NOMBRE

Dist::CheckConflicts - declarar conflictos de versión para tu distribución

VERSIÓN

versión 0.11

SINOPSIS

use Dist::CheckConflicts
    -dist => 'Class-MOP',
    -conflicts => {
        'Moose'                => '1.14',
        'namespace::autoclean' => '0.08',
    },
    -also => [
        'Package::Stash::Conflicts',
    ];
__PACKAGE__->check_conflicts;

DESCRIPCIÓN

Una de las deficiencias de los clientes de CPAN que existen actualmente es que no tienen forma de especificar dependencias aguas abajo conflictivas de los módulos. Este módulo intenta sortear este problema al permitirte especificar versiones conflictivas de módulos por separado, y tratar con ellas después de que el módulo termine de instalarse.

Por ejemplo, supongamos que tienes un módulo "Foo", y algún otro módulo "Bar" usa "Foo". Si "Foo" cambiara su API de una manera no compatible hacia atrás, esto causaría que "Bar" se rompiera hasta que se actualizara para usar la nueva API. "Foo" no puede simplemente depender de la versión corregida de "Bar", porque esto causaría una dependencia circular (porque "Bar" ya depende de "Foo"), y esto tampoco expresa la intención correctamente de todos modos - "Foo" no usa "Bar" en absoluto. La solución ideal sería que hubiera una manera de especificar versiones conflictivas de módulos de una forma que permitiera a los clientes de CPAN actualizar los módulos conflictivos automáticamente después de que un módulo existente se actualizara, pero hasta que eso suceda, este módulo permitirá a los usuarios hacer esto manualmente.

Este módulo acepta un hash de opciones pasadas a su "use" declaración, siendo válidas estas claves:

-conflicts
Un hashref de especificaciones de conflicto, donde las claves son nombres de módulos, y los valores son la última versión rota - cualquier versión mayor que la versión especificada debería funcionar.
-also
Módulos adicionales de los que obtener conflictos (potencialmente recursivamente). Esto debería ser generalmente una lista de módulos que usan Dist::CheckConflicts, que corresponden a las distribuciones de las que tu distribución depende. (En un mundo ideal, esto se deduciría directamente de tu lista de dependencias, pero la lista de dependencias no está disponible fuera del tiempo de compilación).
-dist
El nombre de la distribución, para hacer que el mensaje de error de check_conflicts sea más amigable para el usuario.

Los métodos listados abajo son exportados por este módulo al módulo que lo usa, así que deberías llamar a estos métodos en tu módulo, no en Dist::CheckConflicts.

Como ejemplo, esta línea de comandos puede usarse para actualizar tus módulos, después de instalar la "Foo" distribución (asumiendo que "Foo::Conflicts" es el módulo en la "Foo" distribución que usa Dist::CheckConflicts):

perl -MFoo::Conflicts -e'print "$_\n"
    for map { $_->{package} } Foo::Conflicts->calculate_conflicts' | cpanm

Como bono adicional, cargar tu módulo de conflictos proporcionará advertencias en tiempo de ejecución si se detectan módulos conflictivos (independientemente de si se cargan antes o después).

MÉTODOS

conflicts

Devuelve la especificación de conflicto (el "-conflicts" parámetro a import()), como un hash.

dist

Devuelve el nombre de la distribución (ya sea el especificado por el "-dist" parámetro a import(), o el nombre del paquete que "use"ó este módulo).

check_conflicts

Examina los módulos que están actualmente instalados, y lanza una excepción con información útil si algún módulo está en versiones que entran en conflicto con la distribución.

calculate_conflicts

Examina los módulos que están actualmente instalados, y devuelve una lista de módulos que entran en conflicto con la distribución. Los módulos se devolverán como una lista de hashrefs, cada uno conteniendo las claves "package", "installed", y "required" .

Por favor, reporta cualquier error a GitHub Issues en https://github.com/doy/dist-checkconflicts/issues.
