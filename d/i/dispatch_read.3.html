NOMBRE

dispatch_read, dispatch_write — leer y escribir de forma asíncrona en descriptores de archivo

SINOPSIS

#include <dispatch/dispatch.h>

void
dispatch_read(int fd, size_t length, dispatch_queue_t queue, void (^handler)(dispatch_data_t data, int error));

void
dispatch_write(int fd, dispatch_data_t data, dispatch_queue_t queue, void (^handler)(dispatch_data_t data, int error)));

DESCRIPCIÓN

Las funciones dispatch_read() y dispatch_write() leen y escriben de forma asíncrona en descriptores de archivo POSIX. Se pueden considerar como versiones asíncronas y basadas en callbacks de las funciones fread() y fwrite() proporcionadas por la biblioteca C estándar. Son funciones de conveniencia basadas en las funciones dispatch_io_read(3) y dispatch_io_write(3), destinadas a solicitudes simples de lectura o escritura de un solo uso. Para múltiples solicitudes en el mismo descriptor de archivo, es mejor utilizar las funciones completas del canal de E/S de dispatch subyacente.

COMPORTAMIENTO

La función dispatch_read() programa una operación de lectura asíncrona en el descriptor de archivo fd. Una vez que el descriptor de archivo es legible, el sistema leerá tantos datos como estén disponibles actualmente, hasta la length especificada, comenzando desde la posición actual del puntero de archivo. El bloque handler proporcionado se enviará a queue cuando la operación se complete o ocurra un error. Al bloque se le pasará un objeto data de dispatch con el resultado de la operación de lectura. Si ocurrió un error al leer del descriptor de archivo, el parámetro error del bloque se establecerá al código de error POSIX apropiado y data contendrá cualquier dato que se haya podido leer con éxito. Si la posición del puntero de archivo está al final del archivo, se pasarán datos vacíos (data) y cero (error) al bloque handler.

La función dispatch_write() programa una operación de escritura asíncrona en el descriptor de archivo fd. El sistema intentará escribir todo el contenido del objeto data proporcionado en fd en la posición actual del puntero de archivo. El bloque handler proporcionado se enviará a queue cuando la operación se complete o ocurra un error. Si la operación de escritura se completó con éxito, el parámetro error del bloque se establecerá a cero; de lo contrario, se establecerá al código de error POSIX apropiado y el parámetro data contendrá cualquier dato que no se haya podido escribir.

ADVERTENCIAS

El objeto data que se pasa a un bloque handler es liberado por el sistema cuando el bloque retorna. Si data se necesita fuera del bloque handler, debe concatenarlo, copiarlo o retenerlo.

Una vez que se ha enviado una operación de lectura o escritura asíncrona en un descriptor de archivo fd, el sistema toma el control de ese descriptor de archivo hasta que se ejecute el bloque handler. Durante este tiempo, la aplicación no debe manipular fd directamente; en particular, solo es seguro cerrar fd desde el bloque handler (o después de que haya retornado).

Si se envían múltiples operaciones de lectura o escritura asíncronas al mismo descriptor de archivo, se realizarán en orden, pero sus handlers solo se enviarán una vez que todas las operaciones se hayan completado y se haya cedido el control del descriptor de archivo. Para obtener detalles sobre esto y sobre la interacción con los canales de E/S de dispatch creados desde el mismo descriptor de archivo, consulte PROPIEDAD DEL DESCRIPTOR DE ARCHIVO en dispatch_io_create(3).
