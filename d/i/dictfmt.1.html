DESCRIPCIÓ

N

dictfmt toma un archivo, ARCHIVO, de la entrada estándar, y crea una base de datos de diccionario llamada nombre_base.dict, que se ajusta al protocolo DICT. También crea un archivo de índice llamado nombre_base.index. Por defecto, el índice se ordena de acuerdo con la configuración regional C, y solo se usan caracteres alfanuméricos y espacios para la ordenación, sin embargo esto puede cambiarse con las opciones --locale y --allchars. ( nombre_base se elige comúnmente para que corresponda al nombre base de ARCHIVO, pero esto no es obligatorio.

)

A menos que la base de datos sea extremadamente pequeña, se recomienda encarecidamente que nombre_base.dict se comprima con /usr/bin/dictzip para crear nombre_base.dict.dz. (dictzip está incluido en el paquete fuente dictd.

)

ARCHIVO puede estar en cualquiera de los varios formatos descritos por las opciones de formato -c5, -t, -e, -f, -h, -j, -p, -i o -I. Exactamente una de estas opciones debe ser

proporcionada.

dictfmt antepone varios encabezados al archivo .dict. El encabezado 00-database-url proporciona el valor de la opción -u como la URL del sitio del cual se obtuvo la base de datos original. El encabezado 00-database-short proporciona el valor de la opción -s como el nombre corto del diccionario. (Este "nombre corto" es el nombre identificador dado por la opción "dict- D".) Si las opciones -u y/o -s se omiten, estos valores se mostrarán como "desconocido", lo cual es indeseable para una base de datos distribuida

públicamente.

La fecha de conversión (formateo) se da en el encabezado 00-database-info. Todo el texto en el archivo de entrada antes de la

primera palabra clave (según lo definido por la opción de formateo apropiada) se agrega a este encabezado. Todo el texto e
n el archivo de entrada después de una palabra clave, hasta la siguiente palabra clave, se copia sin cambios al archivo .dict.

OPCIONES DE

FORMATEO
-c
5
ARCHIVO se formatea con palabras clave precedidas por 5 o más caracteres de subrayado (_) y una línea en blanco. Todo el texto hasta la siguiente palabra clave se considera la definición. Cualquier carácter inicial '@' se elimina, pero el archivo no se modifica de otra manera. Esta opción se escribió para formatear el CIA WORLD FACTBOOK
1995.
-
t
Se implican las opciones -c5, --without-info y --without-headword. Use esta opción, si una base de datos de entrada proviene de la utilidad dictunforma
t.
-
e
ARCHIVO está en formato html, con la palabra clave etiquetada en negrita. (<B>palabra clave -
</B>
)
Esta opción se escribió para formatear el EASTON'S 1897 BIBLE DICTIONARY. Una entrada típica de Easton es:

<A NAME="T0000005">
<B>Abagtha - </B>
uno de los siete eunucos en la corte de Asuero (Esther 1:10; 2:21)

.

Esto se convierte en:
Abagtha
uno de los siete eunucos en la corte de Asuero (Esther 1:10; 2:21)

.

El encabezado "<A NAME="T0000005"> se omite, y la palabra clave `Abagtha' se

indexa.

NOTA: Esta opción debe usarse con precaución. Elimina varias etiquetas html (suficientes para formatear Easton correctamente), pero no todas. El Makefile que se escribió originalmente para formatear dict-easton usa scripts sed

para modificar ciertas etiquetas de referencia cruzada. Puede ser necesario canalizar el archivo de entrada a travé
s de un script sed, o modificar el código fuente de dictfmt para formatear correctamente otras bases de datos html.
-
f
ARCHIVO se formatea con las palabras clave comenzando en la columna 0, con la definición indentada al menos un espacio (o carácter de tabulación) en las líneas siguientes. La tercera línea que comienza en la columna 0 se toma como la primera palabra clave, y las primeras dos líneas que comienzan en la columna 0 se tratan como parte del encabezado 00-database-info. Esta opción se escribió para formatear el F.O.L.D.
O.C.
-
h
ARCHIVO se formatea con las palabras clave comenzando en la columna 0, seguidas de una coma, con la definición continuando en la misma línea. Todo el texto antes de la primera línea de un solo carácter se incluye en el encabezado 00-database-info, y las líneas con solo un carácter se omiten del archivo .dict. La primera palabra clave está en la línea que sigue a la primera línea de un solo carácter. La palabra clave se indexa; el texto del archivo no se modifica. Esta opc
ión se escribió para formatear el HIT
CHCOCK'S BIBLE NAMES DICTIONARY.
-
j
ARCHIVO se formatea con palabras clave comenzando en la columna 0, encerradas en dos puntos, seguidas de la definición. Los dos puntos que rodean la palabra clave se eliminan, y la palabra clave se indexa. Las líneas que comienzan con '*', '=' o '-' también se eliminan. Todo el texto antes de l
a primera palabra clave se incluye en los encabezados.
Esta opción se escribió para formatear el JARGON FILE.
NOTA: Algunas versiones recientes del JARGON FILE tenían tres espacios en blanco insertados antes de los dos puntos en cada palabra clave. Estos deben eliminarse antes de procesar con dictfmt. (Se han utilizado scripts sed para este propósito. También son posibles scripts ed, awk o perl.
)
-
p
ARCHIVO se formatea con `%h' en la columna 0, seguido de un espacio en blanco, seguido de la palabra clave, opcionalmente seguida de una línea que contiene '%d' en la columna 0. La definición comienza en la línea siguiente. La primera línea que comienza con '%h' y cualquier línea que comience con '%d' se eliminan del archivo .dict, y '%h ' se elimina delante de la palabra clave. Todo el texto antes de la primera palabra clave se incluye en los encabezados. La segunda línea que comienza con '%h' se toma como la primera palabra clave. Esta opción se escribió para formatear la base de datos de elementos de Jay
Kominek.
-i -
I
Estas dos opciones son diferentes de todas las demás opciones de formateo. Se destinan a reordenar (de acuerdo con el requisito de dictd) un archivo .index dado en la entrada estándar. Es decir, el archivo .dict no se genera en absoluto. Solo se hace el reordenamiento. Se espera una entrada .index de tres o cuatro columnas. -i espera un desplazamiento y longitud en decimal, mientras que -I espera
en f
ormato
base64.
