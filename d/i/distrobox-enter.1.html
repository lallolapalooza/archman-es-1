DISTROBOX-ENTER(1) Manual de Usuario DISTROBOX-ENTER(1)

NOMBRE

distrobox enter
distrobox-enter

DESCRIPCIÓN

distrobox enter se encarga de entrar al contenedor con el nombre especificado. El comando ejecutado por defecto es tu SHELL, pero puedes especificar diferentes shells o comandos completos a ejecutar. Si lo usas dentro de un script, una aplicación o un servicio, puedes especificar el modo –headless para deshabilitar tty e interactividad.

SINOPSIS

distrobox enter

--name/-n:      nombre para el distrobox                      por defecto: mi-distrobox
--/-e:          los argumentos de fin ejecutan el resto como comando a ejecutar al iniciar   por defecto: shell de ${USER} por defecto
--no-tty/-T:        no instanciar un tty
--no-workdir/-nw:   iniciar siempre el contenedor desde el directorio home del contenedor
--additional-flags/-a:  flags adicionales a pasar al comando del gestor de contenedores
--help/-h:      mostrar este mensaje
--root/-r:      lanzar podman/docker/lilipod con privilegios de root. Nota que si necesitas root, esta es la forma preferida
            en lugar de "sudo distrobox" (nota: si usas un programa diferente a 'sudo' para privilegios de root es necesario,
            especifícalo a través de la variable de entorno DBX_SUDO_PROGRAM, o la variable de configuración 'distrobox_sudo_program')
--dry-run/-d:       solo imprimir el comando del gestor de contenedores generado
--verbose/-v:       mostrar más verbosidad
--version/-V:       mostrar versión

EJEMPLOS

Entrar a un distrobox llamado “example”

distrobox-enter example

Entrar a un distrobox especificando un comando

distrobox-enter --name fedora-toolbox-35 -- bash -l
distrobox-enter mi-contenedor-alpine -- sh -l

Usar flags adicionales de podman/docker/lilipod al entrar a un distrobox

distrobox-enter --additional-flags "--preserve-fds" --name test -- bash -l

Especificar variables de entorno adicionales al entrar a un distrobox

distrobox-enter --additional-flags "--env MY_VAR=value" --name test -- bash -l
MY_VAR=value distrobox-enter --additional-flags "--preserve-fds" --name test -- bash -l

También puedes usar variables de entorno para especificar el gestor de contenedores y el nombre del contenedor:

DBX_CONTAINER_MANAGER="docker" DBX_CONTAINER_NAME=test-alpine distrobox-enter

VARIABLES DE ENTORNO

DBX_CONTAINER_NAME
DBX_CONTAINER_MANAGER
DBX_SKIP_WORKDIR
DBX_SUDO_PROGRAM

EXTRA

Este comando se usa para entrar al propio distrobox. Personalmente, simplemente creo múltiples perfiles en mi gnome-terminal para tener múltiples distribuciones accesibles.

El argumento --additional-flags o -a es útil para modificar el comando por defecto al ejecutar en el contenedor. Por ejemplo:

distrobox enter -n dev-arch --additional-flags "--env my_var=test" -- printenv &| grep my_var
my_var=test

Esto también es posible usando variables de entorno normales:

my_var=test distrobox enter -n dev-arch --additional-flags -- printenv &| grep my_var
my_var=test

Si te gustaría entrar a un contenedor rootful y hacer que distrobox use un programa distinto a `sudo' para ejecutar podman/docker/lilipod como root, como `pkexec' o `doas', puedes especificarlo con la variable de entorno DBX_SUDO_PROGRAM. Por ejemplo, para usar `doas' para entrar a un contenedor rootful:

DBX_SUDO_PROGRAM="doas" distrobox enter -n container --root

Adicionalmente, en una de las rutas de archivo de configuración que distrobox soporta, como ~/.distroboxrc, también puedes añadir la línea distrobox_sudo_program="doas" (por ejemplo) para ejecutar siempre comandos de distrobox que involucren contenedores rootful usando `doas'.
