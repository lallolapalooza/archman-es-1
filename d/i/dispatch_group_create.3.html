NOMBRE

dispatch_group_create, dispatch_group_async, dispatch_group_wait, dispatch_group_notify — agrupa bloques enviados a colas

SINOPSIS

#include <dispatch/dispatch.h>

dispatch_group_t
dispatch_group_create(void);

void
dispatch_group_enter(dispatch_group_t group);

void
dispatch_group_leave(dispatch_group_t group);

long
dispatch_group_wait(dispatch_group_t group, dispatch_time_t timeout);

void
dispatch_group_notify(dispatch_group_t group, dispatch_queue_t queue, void (^block)(void));

void
dispatch_group_notify_f(dispatch_group_t group, dispatch_queue_t queue, void *context, void (*function)(void *));

void
dispatch_group_async(dispatch_group_t group, dispatch_queue_t queue, void (^block)(void));

void
dispatch_group_async_f(dispatch_group_t group, dispatch_queue_t queue, void *context, void (*function)(void *));

DESCRIPCIÓN

Un grupo de dispatch es una asociación de uno o más bloques enviados a colas de dispatch para invocación asíncrona. Las aplicaciones pueden usar grupos de dispatch para esperar la finalización de los bloques asociados con el grupo.

La función dispatch_group_create() devuelve un grupo de dispatch nuevo y vacío.

Las funciones dispatch_group_enter() y dispatch_group_leave() actualizan el número de bloques en ejecución dentro de un grupo.

La función dispatch_group_wait() espera hasta que todos los bloques asociados con el grupo hayan completado, o hasta que el timeout especificado haya transcurrido. Si el grupo queda vacío dentro del tiempo especificado, la función devolverá cero indicando éxito. De lo contrario, se devolverá un código de retorno distinto de cero. Cuando se pasa DISPATCH_TIME_FOREVER como timeout, las llamadas a esta función esperarán una cantidad ilimitada de tiempo hasta que el grupo quede vacío y el valor de retorno sea siempre cero.

La función dispatch_group_notify() proporciona notificación asíncrona de la finalización de los bloques asociados con el grupo enviando el block a la queue especificada una vez que todos los bloques asociados con el grupo hayan completado. El sistema mantiene una referencia al grupo de dispatch mientras una notificación asíncrona está pendiente, por lo tanto, es válido liberar el grupo después de establecer un bloque de notificación. El grupo estará vacío en el momento en que el bloque de notificación se envíe a la cola de destino. El grupo puede ser liberado con dispatch_release() o reutilizado para operaciones adicionales.

La función de conveniencia dispatch_group_async() se comporta de la siguiente manera:

void
dispatch_group_async(dispatch_group_t group, dispatch_queue_t queue, dispatch_block_t block)
{
	dispatch_retain(group);
	dispatch_group_enter(group);
	dispatch_async(queue, ^{
		block();
		dispatch_group_leave(group);
		dispatch_release(group);
	});
}

VALOR DE RETORNO

La función dispatch_group_create() devuelve NULL en caso de fallo y un valor distinto de NULL en caso de éxito.

La función dispatch_group_wait() devuelve cero en caso de éxito y un valor distinto de cero después de que expira el timeout. Si el timeout es DISPATCH_TIME_FOREVER, entonces dispatch_group_wait() espera para siempre y siempre devuelve cero.

MODELO DE MEMORIA

Los grupos de dispatch son retenidos y liberados mediante llamadas a dispatch_retain() y dispatch_release().

FUNDAMENTOS

Las funciones dispatch_group_async() y dispatch_group_notify() son envolturas para dispatch_group_async_f() y dispatch_group_notify_f() respectivamente.

ADVERTENCIAS

Para garantizar un comportamiento determinista, se recomienda llamar a dispatch_group_wait() solo después de que todos los bloques se hayan enviado al grupo. Si posteriormente se determina que deben ejecutarse nuevos bloques, se recomienda no reutilizar un grupo ya en ejecución, sino crear un nuevo grupo.

dispatch_group_wait() retorna tan pronto como hay exactamente cero bloques enviados o en ejecución asociados con un grupo (más precisamente, tan pronto como cada llamada a dispatch_group_enter() se ha equilibrado con una llamada a dispatch_group_leave()). Si un hilo espera a un grupo mientras otro hilo envía nuevos bloques al grupo, el recuento de bloques asociados puede llegar momentáneamente a cero antes de que se envíen todos los bloques. Si esto sucede, dispatch_group_wait() retornará demasiado pronto: algunos bloques asociados con el grupo han finalizado, pero otros aún no se han enviado o ejecutado.

Sin embargo, como caso especial, un bloque asociado con un grupo puede enviar nuevos bloques asociados con su propio grupo. En este caso, el comportamiento es determinista: un hilo en espera no despertará hasta que los bloques recién enviados también hayan finalizado.

Todo lo anterior también se aplica a dispath_group_notify(), con la sustitución de "bloque a enviar" por "hilo en espera".
