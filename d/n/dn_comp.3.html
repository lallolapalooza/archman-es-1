DESCRIPCIÓN

Nota: Esta página está incompleta (varias funciones del resolutor proporcionadas por glibc no se describen) y probablemente desactualizada.

Las funciones descritas a continuación realizan consultas a los servidores de nombres de dominio de Internet e interpretan sus respuestas.

La API consta de un conjunto de funciones más modernas y reentrantes, y un conjunto más antiguo de funciones no reentrantes que han sido reemplazadas. Las interfaces tradicionales del resolutor como res_init() y res_query() utilizan un estado estático (global) almacenado en la estructura _res, lo que hace que estas funciones no sean seguras para hilos. BIND 8.2 introdujo un conjunto de nuevas interfaces res_ninit(), res_nquery(), etc., que toman un res_state como primer argumento, por lo que puede usar un estado de resolutor por hilo.

Las funciones res_ninit() y res_init() leen los archivos de configuración (consulte resolv.conf(5)) para obtener el nombre de dominio predeterminado y la(s) dirección(es) del servidor de nombres. Si no se proporciona ningún servidor, se intenta con el host local. Si no se proporciona ningún dominio, se utiliza el asociado con el host local. Puede ser anulado por la variable de entorno LOCALDOMAIN. res_ninit() o res_init() se ejecuta normalmente en la primera llamada a una de las otras funciones. Cada llamada a res_ninit() requiere una llamada correspondiente a res_nclose() para liberar la memoria asignada por res_ninit() y las llamadas posteriores a res_nquery().

Las funciones res_nquery() y res_query() consultan al servidor de nombres para el nombre de dominio completamente calificado name de los type y class especificados. La respuesta se deja en el búfer answer de longitud anslen proporcionado por el llamador.

Las funciones res_nsearch() y res_search() realizan una consulta y esperan la respuesta como res_nquery() y res_query(), pero además implementan las reglas predeterminadas y de búsqueda controladas por RES_DEFNAMES y RES_DNSRCH (consulte la descripción de las opciones de _res a continuación).

Las funciones res_nquerydomain() y res_querydomain() realizan una consulta utilizando res_nquery()/res_query() sobre la concatenación de name y domain.

Las siguientes funciones son rutinas de bajo nivel utilizadas por res_nquery()/res_query().

Las funciones res_nmkquery() y res_mkquery() construyen un mensaje de consulta en buf de longitud buflen para el nombre de dominio dname. El tipo de consulta op es uno de los siguientes (típicamente QUERY):

QUERY
Consulta estándar.
IQUERY
Consulta inversa. Esta opción se eliminó en glibc 2.26, ya que no ha sido soportada por los servidores DNS durante mucho tiempo.
NS_NOTIFY_OP
Notificar a la secundaria el cambio de SOA (Inicio de Autoridad).

newrr no se utiliza actualmente.

La función res_nsend() y res_send() envía una consulta preformateada dada en msg de longitud msglen y devuelve la respuesta en answer que es de longitud anslen. Llamarán a res_ninit()/res_init() si aún no se ha llamado.

La función dn_comp() comprime el nombre de dominio exp_dn y lo almacena en el búfer comp_dn de longitud length. La compresión utiliza una matriz de punteros dnptrs a nombres previamente comprimidos en el mensaje actual. El primer puntero apunta al principio del mensaje y la lista termina con NULL. El límite de la matriz se especifica mediante lastdnptr. Si dnptr es NULL, los nombres de dominio no se comprimen. Si lastdnptr es NULL, la lista de etiquetas no se actualiza.

La función dn_expand() expande el nombre de dominio comprimido comp_dn a un nombre de dominio completo, que se coloca en el búfer exp_dn de tamaño length. El nombre comprimido está contenido en una consulta o respuesta del mensaje, y msg apunta al principio del me

RETORNO

Las funciones res_ninit() y res_init() devuelven 0 en caso de éxito, o -1 si ocurre un

error.

Las funciones res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), res_querydomain(), res_nmkquery(), res_mkquery(), res_nsend(), y res_send() devuelven la longitud de la respuesta, o -1 si ocurre un

error.

Las funciones dn_comp() y dn_expand() devuelven la longitud del nombre comprimido, o -1 si ocurre un

error.

En el caso de un error devuelto por res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), o res_querydomain(), se puede consultar la variable global h_errno (ver gethostbyname(3)) para d

eterminar
el error.
