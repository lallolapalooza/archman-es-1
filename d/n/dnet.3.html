DESCRIPCIÓ

N

dnet proporciona una interfaz simplificada y portable a varias rutinas de red de bajo nivel, incluyendo manipulación de direcciones de red, búsqueda y manipulación de la caché arp(4) y la tabla route(4) del kernel, filtrado de red (firewalling), búsqueda y manipulación de interfaces de red, y transmisión de paquetes IP y tramas Ethernet en bruto. Está destinado a complementar la funcionalidad proporcionada por pcap(

3).

Además, dnet también proporciona definiciones independientes de la plataforma para varios formatos y valores de protocolos de red para programación de red portable de bajo nivel, así como una API simple de manejo de buffers

binarios.

Dirección de

red

Las direcciones de red se describen con la siguiente

estructura: 
struct addr {
	uint16_t		addr_type;
	uint16_t		addr_bits;
	union {
		eth_addr_t	__eth;
		ip_addr_t	__ip;
		ip6_addr_t	__ip6;

		uint8_t		__d
ata8[16]; uint16_t __data16[8]; uint32_t __data32[4]; } __addr_u; }; #define addr_eth __addr_u.__eth #define addr_ip __addr_u.__ip #de
fine addr_ip6 __addr_u.__ip6 #define addr_data8 __addr_u.__data8 #define addr_data16 __addr_u.__data16 #define addr_data32 __addr_u.__data32

Se definen los siguientes valores para addr_type

: 
#define ADDR_TYPE_NONE		0	/* No address set */
#define	ADDR_TYP
E_ETH 1 /* Ethernet */ #define ADDR_TYPE_IP 2 /* Internet Pro
tocol v4 */ #define ADDR_TYPE_IP6 3 /* Internet Protocol v6 */

El campo addr_bits denota la longitud de la máscara de red en

bits.

addr_cmp() compara las direcciones de red a y b, devolviendo un entero menor que, igual a o mayor que cero si a se encuentra, respectivamente, para ser menor que, igual o mayor que b. Ambas direcciones deben ser del mismo tipo de dirección.

addr_bcast() calcula la dirección de broadcast para la red especificada en a y la escribe en b.

addr_net() calcula la dirección de red para la red especificada en a y la escribe en b.

addr_ntop() convierte una dirección del formato de red a una cadena.

addr_pton() convierte una dirección de una cadena al formato de red.

addr_ntoa() convierte una dirección del formato de red a una cadena, devolviendo un puntero al resultado en memoria estática.

addr_aton() es un sinónimo de addr_pton().

addr_ntos() convierte una dirección del formato de red a la struct sockaddr apropiada.

addr_ston() convierte una dirección de una struct sockaddr al formato de red.

addr_btos() convierte una longitud de máscara de red a una máscara de red especificada como una struct sockaddr.

addr_stob() convierte una máscara de red especificada en una struct sockaddr a una longitud de máscara de red.

addr_btom() convierte una longitud de máscara de red a una máscara de red en orden de bytes de red.

addr_mtob() convierte una máscara de red en orden de bytes de red a una longitud de máscara de red.

Protocolo de Resolución de Direcciones

Las entradas de la caché ARP se describen mediante la siguiente estructura:

struct arp_entry {
	struct addr	arp_pa;		/* dirección del protocolo */
	struct addr	arp_ha;		/* dirección de hardware */
};

arp_open() se utiliza para obtener un manejador para acceder a la caché de arp(4) del kernel.

arp_add() añade una nueva entrada entry ARP.

arp_delete() elimina la entrada entry ARP para la dirección del protocolo especificada por arp_pa.

arp_get() recupera la entrada entry ARP para la dirección del protocolo especificada por arp_pa.

arp_loop() itera sobre la caché arp(4) del kernel, invocando el callback especificado con cada entry y el contexto arg pasado a arp_loop().

arp_close() cierra el manejador especificado.

Búferes binarios

Los búferes binarios se describen mediante la siguiente estructura:

typedef struct blob {
	u_char		*base;		/* inicio de los datos */
	int		 off;		/* desplazamiento en los datos */
	int		 end;		/* fin de los datos */
	int		 size;		/* tamaño de la asignación */
} blob_t;

blob_new() se utiliza para asignar un nuevo búfer binario dinámico, devolviendo NULL en caso de error.

blob_read() lee len bytes desde el desplazamiento actual en el búfer b hacia buf, devolviendo el número total de bytes leídos, o -1 en caso de error.

blob_write() escribe len bytes desde buf al búfer b, avanzando el desplazamiento actual. Devuelve el número de bytes escritos, o -1 en caso de error.

blob_seek() reubica el desplazamiento dentro del búfer b a off, según la directiva whence (ver lseek(2) para detalles), devolviendo el nuevo desplazamiento absoluto, o -1 en caso de error.

blob_index() devuelve el desplazamiento de la primera ocurrencia en el búfer b del buflen, o -1 en caso de error.

blob_rindex() devuelve el desplazamiento de la última ocurrencia en el búfer b del buflen, o -1 en caso de error.

blob_pack() convierte y escribe, y blob_unpack() lee y convierte datos en el búfer b según el formato dado fmt como se describe a continuación, devolviendo 0 en caso de éxito y -1 en caso de error.

La cadena de formato se compone de cero o más directivas: caracteres ordinarios (que no sean %), que se copian a / leen del búfer, y especificaciones de conversión, cada una de las cuales resulta en la lectura / escritura de cero o más argumentos posteriores.

Cada especificación de conversión se introduce con el carácter %, y puede ir prefijada por un especificador de longitud. Los argumentos deben corresponder adecuadamente (después de la promoción de tipo) con los especificadores de longitud y conversión.

El especificador de longitud es una cadena de dígitos decimales que especifica la longitud del argumento siguiente, o el carácter literal * que indica que la longitud debe leerse de un argumento entero para el argumento que le sigue.

Los especificadores de conversión y sus significados son:

D
Un entero de 32 bits sin signo en orden de bytes de red.
H
Un entero de 16 bits sin signo en orden de bytes de red.
b
Un búfer binario (se requiere especificador de longitud).
c
Un carácter sin signo.
d
Un entero de 32 bits sin signo en orden de bytes del host.
h
Un entero de 16 bits sin signo en orden de bytes del host.
s
Una cadena estilo C terminada en nulo, cuya longitud máxima debe especificarse al desempaquetar.

Las rutinas de conversión personalizadas y sus especificadores se pueden registrar a través de blob_register_pack(), actualmente no documentado.

blob_print() imprime len bytes del contenido del búfer b desde el desplazamiento actual en el estilo especificado style; actualmente solo está disponible "hexl".

blob_free() libera la memoria asociada con el búfer b y devuelve NULL.

Ethernet

eth_open() se utiliza para obtener un manejador para transmitir tramas Ethernet crudas a través del dispositivo de red especificado.

eth_get() recupera la dirección MAC de hardware para la interfaz especificada por e.

eth_set() configura la dirección MAC de hardware para la interfaz especificada por e.

eth_send() transmite len bytes de la trama Ethernet apuntada por buf.

eth_close() cierra el manejador especificado.
