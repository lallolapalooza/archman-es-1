DIRECTIVAS de dnsval.conf

El archivo de configuración dnsval.conf se utiliza para configurar las políticas de validación de DNSSEC para libval. El archivo consta de una serie de directivas de configuración que se pueden organizar en etiquetas o aplicarse globalmente. Las directivas de etiquetas se utilizan para especificar políticas para dominios o grupos de dominios específicos, mientras que las directivas globales se aplican a todas las operaciones de validación.

Las directivas de etiquetas se especifican mediante el siguiente constructo:

label-name [options]
    directive1 value1
    directive2 value2
    ...
;

Donde label-name es un nombre de etiqueta que puede ser un nombre de dominio o un comodín. La etiqueta . (punto) se utiliza para especificar políticas predeterminadas que se aplican a todos los nombres de dominio que no coinciden explícitamente con otra etiqueta.

Las siguientes directivas de etiquetas están definidas para dnsval.conf:

provably-insecure-status
Establece el estado de la condición de "inseguro demostrable" para un dominio. Los valores posibles son trusted o untrusted. El valor predeterminado es trusted.
untrusted
Trata la condición de inseguro demostrable como inválida.

El valor predeterminado para el estado de inseguro demostrable para un dominio es "trusted". En el siguiente ejemplo, para los contextos de validación DNSSEC creados con la etiqueta predeterminada, la condición de inseguro demostrable se trata como válida para todos los dominios excepto el dominio net, donde esta condición se trata como inválida.

: provably-insecure-status
    . trusted
    net untrusted
;
clock-skew
Para el atributo "clock-skew", los datos adicionales son una secuencia del nombre de dominio y el número de segundos de desfase de reloj aceptable para las firmas en nombres de ese dominio. Un valor de desfase de reloj de -1 tiene el efecto de desactivar las comprobaciones de tiempo de inicio y expiración en las firmas de ese dominio. El desfase de reloj predeterminado es 0. En el siguiente ejemplo, para los contextos de validación DNSSEC creados con la etiqueta "mta", las comprobaciones de inicio y expiración de firmas se deshabilitan para todos los nombres bajo el dominio example.com. 
mta clock-skew
    example.com -1
;
nsec3-max-iter [solo si LIBVAL_NSEC3 está habilitado]
Especifica el número máximo de iteraciones permitidas al calcular el hash NSEC3 para una zona. Un valor de -1 no establece un límite máximo en el número de iteraciones. Esta es también la configuración predeterminada para una zona.
dlv-trust-points [solo si LIBVAL_DLV está habilitado]
Especifica el árbol DLV para la zona de destino. En el siguiente ejemplo, libval utilizará el registro DLV definido en dlv.isc.org. para todas las consultas bajo la raíz que no nos den una respuesta confiable utilizando el mecanismo DNSSEC normal y tengan una expectativa de seguridad de zona de validar. 
dlv dlv-trust-points
    .   dlv.isc.org.
;

Para que DLV se utilice en el ejemplo anterior, también debe haber una política de ancla de confianza definida para el registro dlv, con la política de expectativa de seguridad de zona para el registro establecida en validar.

dlv trust-anchor

                A11D16F6733983E159EDF8053B2FB57B479D81A309A5\
                0EAA79A81AF48A47C617
;

Además de las opciones de configuración específicas de la zona, también es posible configurar opciones globales para la validación en dnsval.conf. Las opciones globales se pueden especificar utilizando el siguiente constructo.

global-options
    keyword1 value1
    keyword2 value2
    ...
;

Solo puede haber un constructo global-options definido para dnsval.conf. Si se definen varios constructos, solo se utiliza el primero.

Las siguientes palabras clave están definidas para global-options en dnsval.conf

trust-local-answers
Esta opción ha sido obsoleta. Utilice trust-oob-answers en su lugar.
trust-oob-answers
Si el valor para esta opción es yes, entonces, para todas las respuestas devueltas utilizando algún mecanismo fuera de banda (por ejemplo, un almacén de archivos como /etc/hosts), el valor devuelto por la función val_istrusted() (ver libval(3)) es mayor que uno.
edns0-size
Al consultar varios servidores de nombres, libsres también intentará varios tamaños EDNS0, terminando con una consulta en la que EDNS0 está deshabilitado (es decir, sin bit CD establecido). Los siguientes tamaños EDNS0 se prueban de forma predeterminada: 4096, 1492, 512. El control de política "edns0-size" se puede utilizar para cambiar el tamaño EDNS0 más grande que se intenta.
env-policy
Esta opción permite al administrador de dnsval.conf controlar si libval utiliza valores especificados por el usuario en variables de entorno al determinar la política de libval y los destinos de registro. Consulte la sección a continuación sobre la anulación de políticas de dnsval.conf para obtener detalles adicionales sobre esta opción.
app-policy
Esta opción permite al administrador del archivo dnsval.conf controlar si libval buscará automáticamente una política de validación con una etiqueta igual al nombre de la aplicación en dnsval.conf. Consulte la sección a continuación sobre la anulación de políticas de dnsval.conf para obtener detalles adicionales sobre esta opción.
closest-ta-only
El comportamiento de validación predeterminado es buscar cualquier cadena de autenticación que valide correctamente. Por lo tanto, si hay anclas de confianza para example.com y test.example.com, el validador devolverá éxito si la cadena de autenticación se puede anclar al ancla de confianza de example.com, incluso si el ancla de confianza de test.example.com no coincide. En los casos en que esto no sea deseable, se puede utilizar la opción closest-ta-only.

Si esta opción se establece en yes, el algoritmo de validación termina en la TA coincidente más cercana.

rec-fallback
Esta opción se utiliza para controlar si libval intentará recurrir a una búsqueda recursiva del nombre si la respuesta del servidor de nombres en caché devolvió un error. De forma predeterminada, esta opción se establece en yes; se puede desactivar estableciendo esta opción en no.
max-refresh
Esta opción se utiliza junto con el indicador de consulta VAL_QUERY_SKIP_CACHE. Cuando las consultas tienen este indicador habilitado, normalmente omitirán las entradas en caché. Sin embargo, max-refresh puede limitar la frecuencia con la que se envían realmente las consultas por el cable. Cuando esta opción se establece en un valor positivo, solo se envía una nueva consulta si el valor almacenado en caché se almacenó hace más de (el valor especificado por) max-refresh segundos. Si max-refresh es 0, la caché siempre se omite. Si el valor es -1, la caché nunca se omite. El valor predeterminado para max-refresh es 60 segundos. Eso significa que dos consultas enviadas con el indicador VAL_QUERY_SKIP_CACHE establecido con menos de un minuto de diferencia solo resultarán en una consulta vista en el cable.
proto
Esta opción se utiliza para controlar el protocolo de red que libval usa para enviar consultas a varios servidores de nombres. Si el valor se establece en ipv6, libval solo usa IPv6; si se establece en ipv4, libval solo usa IPv4. El valor predeterminado es any, lo que hace que libval envíe a través de cualquiera de los protocolos disponibles para el servidor de nombres dado.
timeout
Esta opción anula el valor predeterminado del tiempo de espera del resolutor con el valor proporcionado.
retry
Esta opción anula el valor predeterminado de reintento del resolutor con el valor proporcionado.
log
Esta opción controla el nivel de registro y el destino del registro para libval. El valor esperado para esta opción es el mismo que el especificado para val_add_log_optarg (ver libval(3)).

A continuación, se muestra un ejemplo de constructo global-options:

global-options
    trust-oob-answers yes
    edns0-size 4096
    env-policy enable
    app-policy enable
    log 5:stderr
;

ANULAR POLÍTICAS de resolv.conf

libval primero examina las opciones del resolutor presentes en el archivo resolv.conf especificado en el momento de ejecutar configure. Si este archivo está ausente, libval busca en el archivo /etc/resolv.conf las opciones del resolutor.

Esto permite a los usuarios anular las políticas del resolutor de forma sencilla. El resolv.conf específico del sistema puede permanecer sin cambios, mientras que cualquier política adicional que pueda ser necesaria para libval se puede utilizar en el archivo resolv.conf proporcionado por configure.

ANULAR POLÍTICAS de dnsval.conf

libval proporciona tres formas de adaptar las políticas de dnsval.conf a un entorno determinado.

Múltiples archivos include
libval permite incluir archivos dnsval.conf adicionales con un archivo dnsval.conf dado. La opción se especifica de la siguiente manera: 
include /ruta/al/archivo/de/anulación/dnsval.conf

Los archivos se leen en amplitud. Las políticas se evalúan de manera que la última política definida tiene más precedencia que las anteriores. Por lo tanto, un administrador puede proporcionar un dnsval.conf con políticas predeterminadas que incluyen otro archivo del directorio de inicio del usuario. El archivo incluido puede utilizarse para anular las políticas especificadas en el archivo dnsval.conf base.

Políticas de nombre de aplicación
Si la opción global app-policy no está deshabilitada, libval busca automáticamente una política en dnsval.conf con un valor de etiqueta construido a partir del nombre de la aplicación. Por ejemplo, dnsval.conf puede definirse con políticas de validador para la etiqueta foo. La aplicación foo, cuando se ejecuta, utilizará la política definida contra la etiqueta foo durante su operación de validación.
Políticas a través del entorno
Si la opción global env-policy no está deshabilitada, libval examina las variables de entorno VAL_CONTEXT_LABEL y VAL_LOG_TARGET para determinar la etiqueta de la política del validador y el destino del registro.
Precedencia de la etiqueta del validador
Hay efectivamente cuatro tipos diferentes de etiquetas de política que pueden ser aplicadas por libval: políticas de nombre de aplicación, políticas a través de VAL_CONTEXT_LABEL y etiquetas especificadas por la aplicación (ya sea NULL o no NULL). La precedencia de la aplicación de estas etiquetas se define con las siguientes reglas:

1. Si env-policy es "override", utilice la etiqueta especificada en la variable de entorno VAL_CONTEXT_LABEL (si está definida).

2. Si env-policy es "enable" y la política especificada por la aplicación es NULL, utilice la etiqueta especificada en la variable de entorno VAL_CONTEXT_LABEL (si está definida).

3. Si app-policy es "override", utilice la etiqueta generada a partir del nombre de la aplicación. Si esta etiqueta de política no existe en el sistema de configuración, utilice la política predeterminada.

4. Si app-policy es "enable" y la política especificada por la aplicación es NULL, utilice la etiqueta generada a partir del nombre de la aplicación.
