NOMBRE

dnssec-importkey - importar registros DNSKEY de sistemas externos para que puedan ser gestionados

SINOPSIS

dnssec-importkey [-K directorio] [-L ttl] [-P fecha/desplazamiento] [-P sync fecha/desplazamiento] [-D fecha/desplazamiento] [-D sync fecha/desplazamiento] [-h] [-v nivel] [-V] {archivo_clave}

dnssec-importkey {-f nombre_archivo} [-K directorio] [-L ttl] [-P fecha/desplazamiento] [-P sync fecha/desplazamiento] [-D fecha/desplazamiento] [-D sync fecha/desplazamiento] [-h] [-v nivel] [-V] [nombre_dominio_dns]

DESCRIPCIÓN

dnssec-importkey lee un registro DNSKEY público y genera un par de archivos .key/.private. El registro DNSKEY puede leerse desde un archivo .key existente, en cuyo caso se genera un archivo .private correspondiente, o puede leerse desde cualquier otro archivo o desde la entrada estándar, en cuyo caso se generan ambos archivos .key y .private.

El archivo .private recién creado no contiene datos de clave privada y no puede usarse para firmar. Sin embargo, tener un archivo .private permite establecer tiempos de publicación (-P) y eliminación (-D) para la clave, lo que significa que la clave pública puede añadirse y eliminarse del conjunto de registros RR DNSKEY de forma programada, incluso si la clave privada real se almacena fuera de línea.

Al usar dnssec-policy, no utilice dnssec-importkey para importar archivos de clave que no se puedan utilizar para firmar. En este caso, simplemente publique el registro DNSKEY importado en la zona y asegúrese de que los archivos estén fuera del directorio-clave configurado.

OPCIONES

-f nombre_archivo
Esta opción indica el modo de archivo de zona. En lugar del nombre de un archivo de clave pública, el argumento es el nombre de dominio DNS de un archivo maestro de zona, que puede leerse desde nombre_archivo. Si el nombre de dominio es el mismo que nombre_archivo, puede omitirse.

Si nombre_archivo se establece en "-", los datos de la zona se leen desde la entrada estándar.

-K directorio
Esta opción establece el directorio en el que residirán los archivos de clave.
-L ttl
Esta opción establece el TTL predeterminado a usar para esta clave cuando se convierta en un RR DNSKEY. Este es el TTL utilizado cuando la clave se importa a una zona, a menos que ya hubiera un conjunto de registros RR DNSKEY establecido, en cuyo caso el TTL existente tiene prioridad. Establecer el TTL predeterminado en 0 o none lo elimina de la clave.
-h
Esta opción muestra un mensaje de uso y sale.
-v nivel
Esta opción establece el nivel de depuración.
-V
Esta opción imprime la información de la versión.

OPCIONES DE TEMPORIZACIÓN

Las fechas pueden expresarse en el formato AAAA MM DD o AAAA MM DD HH MM SS. (que es el formato utilizado dentro de los archivos de clave), o 'Día Mes DD HH:MM:SS AAAA' (como imprime dnssec-settime -p), o tiempo Unix epoch (como imprime dnssec-settime -up), o la literal now.

Al argumento le puede seguir + o - y un desplazamiento desde la fecha dada. La literal now puede omitirse antes de un desplazamiento. El desplazamiento puede ir seguido de uno de los sufijos y, mo, w, d, h, o mi, para que se calcule en años (definidos como 365 días de 24 horas, ignorando años bisiestos), meses (definidos como 30 días de 24 horas), semanas, días, horas o minutos, respectivamente. Sin sufijo, el desplazamiento se calcula en segundos.

Para evitar explícitamente que se establezca una fecha, use none, never, o unset.

Todos estos formatos no distinguen entre mayúsculas y minúsculas.

-P fecha/desplazamiento
Esta opción establece la fecha en la que una clave debe publicarse en la zona. Después de esa fecha, la clave se incluye en la zona pero no se usa para firmarla.
sync fecha/desplazamiento
Esta opción establece la fecha en la que los registros CDS y CDNSKEY que coinciden con esta clave deben publicarse en la zona.
-D fecha/desplazamiento
Esta opción establece la fecha en la que la clave debe ser eliminada. Después de esa fecha, la clave ya no se incluye en la zona. (Sin embargo, puede permanecer en el repositorio de claves.)
sync fecha/desplazamiento
Esta opción establece la fecha en la que los registros CDS y CDNSKEY que coinciden con esta clave deben ser eliminados.

ARCHIVOS

Un archivo de clave puede ser diseñado por la identificación de clave Knnnn.+aaa+iiiii o el nombre de archivo completo Knnnn.+aaa+iiiii.key, como lo genera dnssec-keygen <#std-iscman-dnssec-keygen>.
