Está destinada principalmente a medir el rendimiento de servidores DNS autoritativos, pero también puede usarse para medir el rendimiento de servidores de caché en un entorno de laboratorio cerrado. Para probar servidores de caché que resuelven contra Internet en vivo, se prefiere elprogramaresperf.Se recomienda quednsperfy el servidor de nombres bajo prueba se ejecuten en máquinas separadas, para que el uso de la CPU dednsperf en sí no ralentice al servidor de nombres. Las dos máquinas deben estar conectadas con una red rápida, preferiblemente un segmento dedicado de Gigabit Ethernet. No es aconsejable probar a través de un enrutador o cortafuegos.Configuración del servidor de nombresSi se us

Además, asegúrese de desactivar la recursión en la configuración del servidor (en BIND 8/9, especifique "recursion no;" en el bloque de opciones). En BIND 8, también debe especificar "fetch-glue no;"; de lo contrario, el servidor puede intentar recuperar información de enlace (glue) de Internet durante la prueba, ralentizándolo por un factor impredecible. Construcción de un archivo de entrada de

consultas

Un archivo de entrada de dnsperf debe contener un conjunto grande y realista de consultas, del orden de diez mil a un millón. El archivo de entrada contiene una línea por consulta, que consta de un nombre de dominio y un nombre de tipo RR separados por un espacio. La clase de la consulta es implícitamente

IN.

Al medir el rendimiento al servir zonas no terminales como la zona raíz o los TLD, tenga en cuenta que dichos servidores pasan la mayor parte de su tiempo proporcionando respuestas de referencia (referral), no respuestas autoritativas. Por lo tanto, un archivo de entrada realista podría consistir principalmente en consultas de tipo A para nombres *por debajo*, no en, las delegaciones presentes en la zona. Por ejemplo, al probar el rendimiento de un servidor configurado como autoritativo para el dominio de primer nivel "fi.", que contiene delegaciones para dominios como "helsinki.fi" y "turku.fi", el archivo de entrada podría

contener líneas como

www.turku.fi A www.helsinki.fi A donde el prefijo "www" asegura que el servidor responderá con una referencia. Idealmente, una proporción realista de consultas para dominios inexistentes debería mezclarse con las de los existentes, y las líneas del archivo de entrada deberían estar en un orden

aleatorio.

Cada paquete va precedido por un preámbulo de 2 bytes que especifica la longitud del siguiente paquete DNS en orden de bytes de red, seguido inmediatamente por los bytes crudos del paquete. Los dos primeros bytes de cualquier paquete deben contener el ID del mensaje y son sobrescritos

Los paquetes en el datafile pueden contener bytes arbitrarios y no se comprueba su validez. -D

Establece el bit DO (DNSSEC OK) [RFC3225] en todos los paquetes enviados. Esto también habilita EDNS0, que es necesario para DNSSEC. Esta opción es mutuamente exclusiva con -B
.

-e

Habilita EDNS0 [RFC2671], añadiendo un registro OPT a todos los paquetes enviados.esta opción es mutuamente exclusiva con -B.

-E code:value

Añade una opción EDNS [RFC2671] a todos los paquetes enviados, utilizando el código de opción numérico especificado y el valor expresado como una cadena codificada en hexadecimal. Esto también habilita EDNS0. Esta opción es mutuamente exclusiva con -B.

-f family

Especifica la familia de direcciones utilizada para enviar paquetes DNS. Los valores posibles son "inet", "inet6" o "any". Si se especifica "any" (el valor por defecto), dnsperf usará la familia de direcciones apropiada para el servidor al que envía los paquetes.

-h

Imprime una declaración de uso y sale.

-l limit

Especifica un límite de tiempo para la ejecución, en segundos. Esto puede hacer que la entrada se lea varias veces, o que solo se lea una parte de la entrada. El comportamiento por defecto es leer la entrada una vez, sin un límite de tiempo específico.

-n runs_through_file

Recorre el archivo de entrada como máximo este número de veces. Si no se establece un límite de tiempo, el archivo se leerá exactamente este número de veces; si se establece un límite de tiempo, el archivo puede leerse menos veces.

-p port

Establece el puerto en el que se envían los paquetes DNS. Si no se especifica, se usa el puerto DNS estándar (udp/tcp 53, DoT 853, DoH 443).

-q num_queries

Establece el número máximo de solicitudes pendientes. Cuando se alcanza este valor, dnsperf no enviará más solicitudes hasta que se reciban respuestas o las solicitudes caduquen. El valor por defecto es 100.

-Q max_qps

Limita el número de solicitudes por segundo. No hay un límite por defecto.

-m mode

Especifica el modo de transporte a utilizar, "udp", "tcp", "dot" o "doh". El valor por defecto es "udp".

-s server_addr

Especifica el nombre o la dirección del servidor al que se enviarán las solicitudes. El valor por defecto es la dirección de bucle local, 127.0.0.1.

-S stats_interval

Si se especifica este parámetro, se imprimirá un recuento del número de respuestas recibidas por segundo durante el intervalo cada stats_interval segundos.

-t timeout

Especifica el valor de tiempo de espera de la solicitud, en segundos. dnsperf dejará de esperar una respuesta a una solicitud particular después de que hayan transcurrido estos segundos. El valor por defecto es 5 segundos.

-T threads

Ejecuta múltiples hilos de cliente. Por defecto, dnsperf usa un hilo para enviar solicitudes y un hilo para recibir respuestas. Si se especifica esta opción, dnsperf usará en su lugar N pares de hilos de envío/recepción.

-u

Indica a dnsperf que envíe mensajes de actualización dinámica DNS, en lugar de consultas. El formato del archivo de entrada es diferente en este caso; consulte la sección "Construcción de un archivo de entrada de actualización dinámica" para más detalles. Esta opción es mutuamente exclusiva con -B.

-v

Habilita el modo detallado. El RCODE DNS de cada respuesta se informará a la salida estándar cuando se reciba la respuesta, al igual que la latencia. Si una consulta expira, se informará con la cadena especial "T" en lugar de un RCODE DNS normal. Si una consulta es interrumpida, se informará con la cadena especial "I". También se informará información adicional sobre la disponibilidad y congestión de la red.

-W

Registra advertencias y errores en la salida estándar en lugar de la salida de error estándar, facilitando que scripts, pruebas y automatización capturen toda la salida.

-x local_port

Especifica el puerto local desde el cual enviar solicitudes. El valor por defecto es el puerto comodín (0).

Si actúa como múltiples clientes y se usa el puerto comodín, cada cliente usará un puerto aleatorio diferente. Si se especifica un puerto, los clientes usarán un rango de puertos que comienza con el especificado.

-y [alg:]name:secret

Añade un registro TSIG [RFC2845] a todos los paquetes enviados, utilizando el algoritmo, nombre y secreto de la clave TSIG especificados, donde el algoritmo por defecto es hmac-md5 y el secreto se expresa como una cadena codificada en base-64. Los algoritmos disponibles son: hmac-md5, hmac-sha1, hmac-sha224, hmac-sha256, hmac-sha384 y hmac-sha512. Esta opción es mutuamente exclusiva con -B.

-O option=value

Establece una opción larga extendida para varias cosas para controlar diferentes aspectos de las pruebas o los módulos de protocolo, consulte OPCIONES EXTENDIDAS para la lista de opciones disponibles.

OPCIONES EXTENDIDAS

doh-uri=URI

La URI a usar para DNS-over-HTTPS, el valor por defecto es "https://localhost/dns-query".

doh-method=HTTP_METHOD

El método HTTP a usar al consultar con DNS-over-HTTPS, el valor por defecto es GET. Los métodos disponibles son: GET, POST.

tls-sni=SERVER_NAME

El Server Name Indication (SNI) a usar para conexiones TLS (como DNS-over-TLS o DNS-over-HTTPS), por defecto se omite la extensión SNI en el saludo del cliente.

suppress=MESSAGE[,MESSAGE,...]

Suprime varios mensajes y advertencias que pueden mostrarse excesivamente en algunas situaciones, como la disponibilidad del socket al conectarse a un servicio lento. Puede suprimir múltiples tipos listándolos como una lista separada por comas. Los siguientes tipos están disponibles.

timeouts: Suprime los mensajes sobre consultas que agotan el tiempo de espera
congestion: Suprime los mensajes sobre congestión de la red
sendfailed: Suprime los mensajes sobre fallos al enviar paquetes o si solo se enviaron partes del paquete
sockready: Suprime los mensajes sobre disponibilidad del socket
unexpected: Suprime los mensajes sobre respuestas con un ID de mensaje inesperado

num-queries-per-conn=NUMBER
Esto limitará el número de consultas enviadas a través de una conexión antes de desencadenar una reconexión. Una vez reconectado, restablecerá el contador y continuará enviando consultas hasta que se alcance el límite de nuevo, desencadenando otra reconexión y así sucesivamente. Usar esta opción también habilitará el recuento del número de respuestas recibidas para cada conexión y una vez que se alcance el límite para el envío de consultas, esperará hasta que se haya recibido la misma cantidad de respuestas antes de reconectar. La espera de respuestas puede agotar el tiempo de espera y el tiempo de espera utilizado para esto es el mismo que el especificado por -t. Tenga en cuenta que esta opción solo es útil para protocolos orientados a conexiones.

verbose-interval-stats

Cambia el formato de las estadísticas de -S al que se muestra al final de la ejecución.

Tenga en cuenta: Los valores mínimos/máximos para la latencia y las conexiones no están disponibles en las estadísticas de intervalo. El número de respuestas recibidas dentro de stats_interval puede superar legítimamente el número de consultas enviadas, dependiendo de la latencia de la respuesta, el timeoutconfigurado, y stats_interval.

Solo disponible en dnsperf.

latency-histogram

Imprime histogramas de latencia detallados para las respuestas DNS y conexiones. La latencia se cuantiza en intervalos con aproximadamente un 3 % de resolución, y el rango de latencia para intervalos individuales aumenta logarítmicamente. Esto se hace para limitar la cantidad de memoria requerida para los histogramas y también permite visualizar la latencia usando histogramas de percentiles logarítmicos con un mínimo postprocesamiento.

Solo disponible en dnsperf y si se detectó soporte en tiempo de compilación.

qps-threshold-wait=<microseconds>

Al usar -Q para limitar la tasa de consultas enviadas, esta opción controla el tiempo mínimo (en microsegundos) que debe haber entre consultas para usar nanosleep() y esperar hasta enviar la siguiente consulta. Establecer a cero (0) deshabilitará cualquier llamada a nanosleep() entre el envío de consultas.

Si el tiempo entre consultas es menor que este, no se realiza ninguna espera para tener más precisión sobre cuándo enviar la siguiente consulta. Esto se debe a que durante la limitación de tasa de alta QPS puede llevar más tiempo simplemente llamar a las funciones para esperar cuándo enviar la siguiente consulta que el tiempo real entre consultas.

Si no se establece, el tiempo medio de llamada a nanosleep() se medirá durante el inicio.

Solo disponible en dnsperf.
