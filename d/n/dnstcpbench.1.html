DNSTCPBENCH(1) Servidor Autoritativo PowerDNS DNSTCPBENCH(1)

NOMBRE

dnstcpbench - herramienta para realizar benchmarking de DNS sobre TCP de servidores de nombres

SINOPSIS

dnstcpbench [OPCIÓN]... DIRECCIÓN-REMOTA [PUERTO-REMOTO]

DESCRIPCIÓN

dnstcpbench lee consultas DNS (por defecto desde la entrada estándar) y las envía en paralelo a un servidor de nombres remoto. Por defecto se usa TCP/IP, pero opcionalmente, se intenta UDP primero, lo que permite la evaluación comparativa de la recursión de TCP/IP.

El programa informa números medios y medianos tanto para consultas por segundo como para latencias UDP y TCP. Cada consulta solo se cuenta una vez, incluso si se intenta primero sobre UDP. Esto significa efectivamente que pasar '-u' puede reducir las tasas de consulta si muchas consultas se desvían a TCP.

El formato de entrada es una consulta por línea: qname espacio qtype. Un ejemplo:

www.powerdns.com ANY

Al realizar pruebas de rendimiento en ejecuciones prolongadas, puede ser necesario habilitar la reutilización de TIME_WAIT, ya que de lo contrario las tuplas de puertos TCP/IP podrían agotarse. En Linux, esto se realiza ejecutando:

echo 1 > /proc/sys/net/ipv4/tcp_tw_recycle

El equivalente para IPv6 no se conoce.

OPCIONES

DIRECCIÓN-REMOTA
IPv4 o IPv6 contra el que probar.
PUERTO-REMOTO
Puerto contra el que probar, por defecto es 53.
-f <NOMBRE-ARCHIVO>, --archivo <NOMBRE-ARCHIVO>
NOMBRE-ARCHIVO del que leer las consultas. Por defecto es la entrada estándar si no se especifica.
-h, --ayuda
Proporcionar un mensaje de ayuda.
--timeout-msec <MSEC>
MSEC milisegundos para esperar una respuesta.
-u, --udp-primero
Intentar la resolución vía UDP primero, solo usar TCP si se recibe una respuesta truncada.
-v, --verboso
Ser detallado sobre lo que está haciendo el programa.
--workers <NUM>
Usar NUM hilos de trabajo paralelos.

ERRORES

Actualmente, el código de tiempo de espera no realiza conexiones ni escrituras no bloqueantes. Por lo tanto, una conexión o escrituras lentas aún causarán un bajo rendimiento y retrasos.

Las estadísticas de medianas de consultas por segundo se reportan como 0 para ejecuciones de menos de un segundo.
