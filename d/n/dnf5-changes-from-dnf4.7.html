NOMBRE

dnf5-changes-from-dnf4 - Cambios respecto a DNF4

Este capítulo describe las diferencias entre DNF5 https://github.com/rpm-software-management/dnf5 y DNF https://github.com/rpm-software-management/dnf.

CAMBIOS EN LA LÍNEA DE COMANDOS

Opciones

Ámbito de las opciones globales

Las opciones que no se pueden aplicar a todos los comandos o que pueden ser aplicables pero no tienen efecto, se eliminan de las opciones generales y se implementan solo para comandos relacionados.

Ejemplos: --best, --no-best solo son relevantes para varios comandos de transacción.

Renombrado de opciones

Renombrado de opciones booleanas a los siguientes formatos:

  • --<opción> y --no-<opción>
  • --enable-<opción> y --disable-<opción>

Las opciones con nombres originales se conservan por ahora como alias de compatibilidad.

Ejemplos: --best y --no-best.

Comportamiento estricto

  • Las opciones --disable-repo=REPO_ID y --setopt=[REPO_ID.]OPTION=VALUE ahora generan consistentemente un error cuando se les proporciona un REPO_ID no válido.
  • El comportamiento ahora está alineado con --repo=REPO_ID y --enable-repo=REPO_ID.
  • La opción de configuración strict ya no se considera, consulte la deprecación de la opción strict para obtener más información.

Sin separador de valor después de opciones cortas

Las opciones cortas no tienen un separador entre el nombre de la opción y el valor de la opción. Por ejemplo, dnf -x package es equivalente a dnf --exclude package y a las formas largas de dnf --exclude=package. Pero dnf -x=package significa dnf --exclude =package.

•
El comando shell ha sido reemplazado por el nuevo comando do.
•
La principal ventaja del comando antiguo era su capacidad para realizar múltiples acciones dentro de una sola transacción. El nuevo comando do conserva esta funcionalidad principal, pero con un modelo de uso diferente.
•
Uso: El comando shell permitía introducir acciones a través de un shell interactivo o un archivo redirigido. El nuevo comando do, sin embargo, requiere que las acciones se proporcionen como argumentos de línea de comandos. El soporte directo para leer un archivo de comandos no está disponible en este momento. Sin embargo, el contenido del archivo se puede pasar como argumentos en la línea de comandos (por ejemplo, dnf do $(cat file)).
