DESCRIPCIÓ

N

DNF5 utiliza de forma predeterminada el archivo de configuración global en /etc/dnf/dnf.

conf.

El archivo de configuración tiene formato INI, que consta de una declaración de sección y opciones nombre=valor debajo, cada una en una línea separada. Hay dos tipos de secciones en los archivos de configuración: main y repository. La sección main define todas las opciones de configuración globales y solo debe haber

una.

Las secciones de repositorio definen la configuración para cada repositorio (remoto o local). El nombre de la sección del repositorio entre corchetes sirve como referencia de ID d

e repositorio y debe ser único en todos los archivos de configuración. Los caracteres permitidos para la cadena de ID de repositorio son letras alfabéticas en minúsculas y mayúscul
as, dígitos, -, _, . y :. El archivo de configuración mínimo de repositorio debe, además del ID de repositorio, contener la definición de la opción baseurl, metalink o mirrorlist.

NOMBRES DE REPOSITORIOS DE FUENTE Y

DEBUGINFO

Para un repositorio dado con un identificador en la forma "<ID>-rpms", se espera que su repositorio de fuente correspondiente tenga un identificador en la forma "<ID>-source-rpms" y el repositorio de debuginfo un identificador en la forma "<ID>-debug-rpms". De lo contrario (si el identificador del repositorio no tiene el sufijo "-rpms"), se espera que el repositorio de fuente tenga un identificador en la forma "<ID>-source" y el repositorio de debuginfo un identificador en la forma "<ID>

-debuginfo".

Por ejemplo, para el repositorio "fedora", el repositorio de fuente es "fedora-source" y el repositorio de debuginfo es "fedora-debuginfo". Para el repositorio "fedora-rpms", el repositorio de fuente es "fedora-source-rpms" y el repositorio de debuginfo es "fedora-debug-rpms

"
.

Esta marca permite al proveedor del repositorio estimar el número de sistemas que consumen el repositorio, contando tales solicitudes durante una semana. Este método es más preciso que simplemente contar direcciones IP únicas (lo cual está sujeto tanto a sobreconteo como a subconteo debido a arrendamientos DHCP cortos y NAT, respectivamente)
