NOMBRE

dnssec-keyfromlabel - Herramienta de generación de claves DNSSEC

SINOPSIS

dnssec-keyfromlabel {-l etiqueta} [-3] [-a algoritmo] [-A fecha/desplazamiento] [-c clase] [-D fecha/desplazamiento] [-D sincronización fecha/desplazamiento] [-E motor] [-f bandera] [-G] [-I fecha/desplazamiento] [-i intervalo] [-k] [-K directorio] [-L ttl] [-M etiqueta_min:etiqueta_max] [-n tiponombre] [-P fecha/desplazamiento] [-P sincronización fecha/desplazamiento] [-p protocolo] [-R fecha/desplazamiento] [-S clave] [-t tipo] [-v nivel] [-V] [-y] {nombre}

DESCRIPCIÓN

dnssec-keyfromlabel genera un par de archivos de clave que referencian un objeto de clave almacenado en un módulo de servicio de hardware criptográfico (HSM). El archivo de clave privada puede usarse para la firma DNSSEC de datos de zona como si fuera una clave de firma convencional creada por dnssec-keygen <#std-iscman-dnssec-keygen>, pero el material de la clave se almacena dentro del HSM y la firma real se realiza allí.

El nombre de la clave se especifica en la línea de comandos. Debe coincidir con el nombre de la zona para la que se está generando la clave.

OPCIONES

-a algoritmo
Esta opción selecciona el algoritmo criptográfico. El valor de algoritmo debe ser uno de RSASHA1 (obsoleto), NSEC3RSASHA1 (obsoleto), RSASHA256, RSASHA512, ECDSAP256SHA256, ECDSAP384SHA384, ED25519, o ED448.

Estos valores no distinguen entre mayúsculas y minúsculas. En algunos casos, se admiten abreviaturas, como ECDSA256 para ECDSAP256SHA256 y ECDSA384 para ECDSAP384SHA384. Si se especifica RSASHA1 (obsoleto) junto con la opción -3, se utilizará NSEC3RSASHA1 (obsoleto) en su lugar.

Esta opción es obligatoria, excepto cuando se utiliza la opción -S, que copia el algoritmo de la clave predecesora.

Cambiado en la versión 9.12.0: Se eliminó el valor predeterminado RSASHA1 (obsoleto) para las claves recién generadas.

-3
Esta opción utiliza un algoritmo compatible con NSEC3 para generar una clave DNSSEC. Si esta opción se usa con un algoritmo que tiene versiones NSEC y NSEC3, se utilizará la versión NSEC3; por ejemplo, dnssec-keygen -3a RSASHA1 especifica el algoritmo NSEC3RSASHA1 (obsoleto).
-E motor
Esta opción especifica el hardware criptográfico a utilizar.

Cuando BIND 9 se compila con OpenSSL, esto debe configurarse en el identificador del motor de OpenSSL que controla el acelerador criptográfico o el módulo de servicio de hardware (generalmente pkcs11).

-l etiqueta
Esta opción especifica la etiqueta para un par de claves en el hardware criptográfico.

Cuando BIND 9 se compila con soporte PKCS#11 basado en OpenSSL, la etiqueta es una cadena arbitraria que identifica una clave particular. Puede ir precedida por un nombre de motor OpenSSL opcional, seguido de dos puntos, como en pkcs11:keylabel.

-n tiponombre
Esta opción especifica el tipo de propietario de la clave. El valor de tiponombre debe ser ZONE (para una clave de zona DNSSEC (KEY/DNSKEY)), HOST o ENTITY (para una clave asociada con un host (KEY)), USER (para una clave asociada con un usuario (KEY)), u OTHER (DNSKEY). Estos valores no distinguen entre mayúsculas y minúsculas.
-C
Esta opción habilita el modo de compatibilidad, que genera una clave de estilo antiguo, sin metadatos. Por defecto, dnssec-keyfromlabel incluye la fecha de creación de la clave en los metadatos almacenados con la clave privada; otras fechas pueden configurarse allí, incluyendo la fecha de publicación, la fecha de activación, etc. Las claves que incluyen estos datos pueden ser incompatibles con versiones anteriores de BIND; la opción -C las suprime.
-c clase
Esta opción indica que el registro DNS que contiene la clave debe tener la clase especificada. Si no se especifica, se utiliza la clase IN.
-f bandera
Esta opción establece la bandera especificada en el campo de flags del registro KEY/DNSKEY. Las únicas banderas reconocidas son KSK (Key-Signing Key) y REVOKE.
-G
Esta opción genera una clave, pero no la publica ni firma con ella. Esta opción es incompatible con -P y -A.
-h
Esta opción imprime un breve resumen de las opciones y argumentos para dnssec-keyfromlabel.
-K directorio
Esta opción establece el directorio en el que se escribirán los archivos de clave.
-k
Esta opción genera registros KEY en lugar de registros DNSKEY.
-L ttl
Esta opción establece el TTL predeterminado a utilizar para esta clave cuando se convierta en un RR DNSKEY. Este es el TTL utilizado cuando la clave se importa en una zona, a menos que ya hubiera un conjunto de registros DNSKEY en su lugar, en cuyo caso el TTL existente tendría precedencia. Establecer el TTL predeterminado a 0 o none lo elimina.
-M etiqueta_min:etiqueta_max
Esta opción establece el rango de valores de etiqueta de clave que dnssec-keyfromlabel aceptará. Si la etiqueta de clave de la nueva clave o la etiqueta de clave de la versión revocada de la nueva clave está fuera de este rango, la nueva clave será rechazada. Esto está diseñado para ser utilizado al generar claves en un escenario de múltiples firmantes, donde a cada operador se le da un rango de etiquetas de clave para evitar colisiones entre diferentes operadores. Los valores válidos para etiqueta_min y etiqueta_max son [0..65535]. El valor predeterminado permite que se acepten todos los valores de etiqueta de clave.
-p protocolo
Esta opción establece el valor del protocolo para la clave. El protocolo es un número entre 0 y 255. El valor predeterminado es 3 (DNSSEC). Otros valores posibles para este argumento se enumeran en RFC 2535 https://datatracker.ietf.org/doc/html/rfc2535.html y sus sucesores.
-S clave
Esta opción genera una clave como sucesora explícita de una clave existente. El nombre, algoritmo, tamaño y tipo de la clave se establecen para que coincidan con los de la predecesora. La fecha de activación de la nueva clave se establece en la fecha de inactivación de la existente. La fecha de publicación se establece en la fecha de activación menos el intervalo de prepublicación, que por defecto es de 30 días.
-t tipo
Esta opción indica el tipo de clave. tipo debe ser uno de AUTHCONF, NOAUTHCONF, NOAUTH, o NOCONF. El valor predeterminado es AUTHCONF. AUTH se refiere a la capacidad de autenticar datos, y CONF a la capacidad de cifrar datos.
-v nivel
Esta opción establece el nivel de depuración.
-V
Esta opción imprime información de la versión.
-y
Esta opción permite generar archivos de clave DNSSEC incluso si la ID de clave colisionaría con la de una clave existente, en caso de que alguna de las claves sea revocada. (Solo es seguro habilitar esto si RFC 5011 https://datatracker.ietf.org/doc/html/rfc5011.html está habilitado para la zona, de lo contrario, la clave caducará después de su revocación).
-A fecha/desplazamiento
Establece la fecha y hora en que la clave estará activa para firmar. Los valores pueden ser una marca de tiempo Unix o una cadena con formato 'YYYYMMDDHHMMSS'. Si se utiliza un desplazamiento, este se sumará a la hora actual.
-D fecha/desplazamiento
Establece la fecha y hora en que la clave se publicará (es decir, se añadirá a la zona). Los valores pueden ser una marca de tiempo Unix o una cadena con formato 'YYYYMMDDHHMMSS'. Si se utiliza un desplazamiento, este se sumará a la hora actual.
-D sincronización fecha/desplazamiento
Establece la fecha y hora en que la clave se publicará y sincronizará con la zona. Los valores pueden ser una marca de tiempo Unix o una cadena con formato 'YYYYMMDDHHMMSS'. Si se utiliza un desplazamiento, este se sumará a la hora actual.
-I fecha/desplazamiento
Establece la fecha y hora en que la clave se inactivará. Los valores pueden ser una marca de tiempo Unix o una cadena con formato 'YYYYMMDDHHMMSS'. Si se utiliza un desplazamiento, este se sumará a la hora actual.
-i intervalo
Establece el intervalo de prepublicación, que es el tiempo que se espera antes de que la clave sea publicada. El valor predeterminado es de 30 días.
-P fecha/desplazamiento
Establece la fecha y hora en que la clave será publicada. Los valores pueden ser una marca de tiempo Unix o una cadena con formato 'YYYYMMDDHHMMSS'. Si se utiliza un desplazamiento, este se sumará a la hora actual.
-P sincronización fecha/desplazamiento
Establece la fecha y hora en que la clave será publicada y sincronizada con la zona. Los valores pueden ser una marca de tiempo Unix o una cadena con formato 'YYYYMMDDHHMMSS'. Si se utiliza un desplazamiento, este se sumará a la hora actual.
-R fecha/desplazamiento
Establece la fecha y hora en que la clave será revocada. Los valores pueden ser una marca de tiempo Unix o una cadena con formato 'YYYYMMDDHHMMSS'. Si se utiliza un desplazamiento, este se sumará a la hora actual.
-S clave
Establece que la clave generada es una sucesora de la clave especificada. La clave predecesora se asume que tiene el mismo nombre y el mismo tipo de algoritmo. La fecha de activación de la nueva clave se establece en la fecha de desactivación de la clave predecesora. La fecha de publicación se establece en la fecha de activación menos el intervalo de prepublicación, que por defecto es de 30 días.

FECHAS Y DESPLAZAMIENTOS

Las fechas y los desplazamientos se pueden especificar en varios formatos. Las fechas pueden ser marcas de tiempo Unix o cadenas en formato 'YYYYMMDDHHMMSS'. Si se usa un desplazamiento, este se suma a la hora actual.

ALGORITMOS Y TIPOS DE CLAVE

Los algoritmos y tipos de clave se especifican mediante cadenas de texto. Consulte la documentación de BIND para obtener una lista completa de los algoritmos y tipos de clave admitidos.

EJEMPLOS

Generar una clave KSK para la zona example.com:

dnssec-keyfromlabel -l mykey -f KSK example.com

Generar una clave ZSK para la zona example.com, que será activa en 30 días:

dnssec-keyfromlabel -l mykey -A +30d example.com

Generar una clave RSA SHA-256 para la zona example.com, que se publicará en 7 días y estará activa en 14 días:

dnssec-keyfromlabel -a RSASHA256 -D +7d -A +14d example.com

OPCIONES DE TEMPORIZACIÓN

Las fechas pueden expresarse en el formato AAAAMMDD o AAAAMMDDHHMMSS (que es el formato utilizado dentro de los archivos de claves), o 'Día Mes DD HH:MM:SS AAAA' (como lo imprime dnssec-settime -p), o el tiempo de época UNIX (como lo imprime dnssec-settime -up), o el literal now.

Al argumento puede seguirle + o - y un desplazamiento a partir de la hora dada. El literal now puede omitirse antes de un desplazamiento. El desplazamiento puede ir seguido de uno de los sufijos y, mo, w, d, h, o mi, de modo que se calcule en años (definidos como 365 días de 24 horas, ignorando los años bisiestos), meses (definidos como 30 días de 24 horas), semanas, días, horas o minutos, respectivamente. Sin un sufijo, el desplazamiento se calcula en segundos.

Para impedir explícitamente que se establezca una fecha, utilice none, never, o unset.

Todos estos formatos no distinguen entre mayúsculas y minúsculas.

-P fecha/desplazamiento
Esta opción establece la fecha en la que la clave debe publicarse en la zona. Después de esa fecha, la clave se incluye en la zona pero no se utiliza para firmarla. Si no se establece, y si la opción -G no se ha utilizado, el valor predeterminado es la fecha actual.
sync fecha/desplazamiento
Esta opción establece la fecha en la que los registros CDS y CDNSKEY que coinciden con esta clave deben publicarse en la zona.
-A fecha/desplazamiento
Esta opción establece la fecha en la que la clave debe activarse. Después de esa fecha, la clave se incluye en la zona y se utiliza para firmarla. Si no se establece, y si la opción -G no se ha utilizado, el valor predeterminado es la fecha actual.
-R fecha/desplazamiento
Esta opción establece la fecha en la que la clave debe revocarse. Después de esa fecha, la clave se marca como revocada. Se incluye en la zona y se utiliza para firmarla.
-I fecha/desplazamiento
Esta opción establece la fecha en la que la clave debe retirarse. Después de esa fecha, la clave todavía se incluye en la zona, pero no se utiliza para firmarla.
-D fecha/desplazamiento
Esta opción establece la fecha en la que la clave debe eliminarse. Después de esa fecha, la clave ya no se incluye en la zona. (Sin embargo, puede permanecer en el repositorio de claves.)
sync fecha/desplazamiento
Esta opción establece la fecha en la que los registros CDS y CDNSKEY que coinciden con esta clave deben eliminarse.
-i intervalo
Esta opción establece el intervalo de prepublicación para una clave. Si se establece, las fechas de publicación y activación deben estar separadas por al menos este tiempo. Si se especifica la fecha de activación pero no la de publicación, la fecha de publicación será, por defecto, este tiempo antes de la fecha de activación; a la inversa, si se especifica la fecha de publicación pero no la de activación, la activación se establece este tiempo después de la publicación.

Si la clave se está creando como sucesora explícita de otra clave, el intervalo de prepublicación predeterminado es de 30 días; de lo contrario, es cero.

Al igual que con los desplazamientos de fecha, si al argumento le sigue uno de los sufijos y, mo, w, d, h, o mi, el intervalo se mide en años, meses, semanas, días, horas o minutos, respectivamente. Sin un sufijo, el intervalo se mide en segundos.

ARCHIVOS DE CLAVES GENERADOS

Cuando dnssec-keyfromlabel se completa correctamente, imprime una cadena de la forma Knnnn.+aaa+iiiii en la salida estándar. Esta es una cadena de identificación para los archivos de claves que ha generado.

  • nnnn es el nombre de la clave.
  • aaa es la representación numérica del algoritmo.
  • iiiii es el identificador (o huella digital) de la clave.

dnssec-keyfromlabel crea dos archivos, con nombres basados en la cadena impresa. Knnnn.+aaa+iiiii.key contiene la clave pública, y Knnnn.+aaa+iiiii.private contiene la clave privada.

El archivo .key contiene un registro DNS KEY que puede insertarse en un archivo de zona (directamente o con una declaración $INCLUDE).

El archivo .private contiene campos específicos del algoritmo. Por razones de seguridad evidentes, este archivo no tiene permiso de lectura general.
