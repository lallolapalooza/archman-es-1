NOMBRE

dnf5-do - Comando do

SINOPSIS

dnf5 do [opciones] [argumentos]

DESCRIPCIÓN

El comando do es un comando universal para la gestión de paquetes en DNF5. Permite al usuario definir múltiples acciones (instalar, eliminar, actualizar, bajar de versión, y reinstalar).

A diferencia de una serie de comandos específicos (install, remove, upgrade, downgrade, y reinstall), el comando do maneja todas las acciones solicitadas juntas y las ejecuta en una única transacción. Esto simplifica operaciones complejas y las hace más eficientes.

Otra diferencia es que el comando do permite la especificación explícita de tipos de objetos en la transacción: package, group, o auto. Para el tipo group, es posible especificar si se utiliza un ID de grupo o un nombre de grupo. Por defecto, el tipo auto está activo. En este modo, el comando do se comporta como otros comandos, infiriendo el tipo del objeto a partir de su especificación. Por ejemplo, si una especificación comienza con el carácter @, se trata como un ID de grupo o un módulo.

Las acciones individuales y los tipos de objetos se especifican mediante opciones y son combinables.

Otras opciones tienen el mismo significado y uso que con los comandos (install, remove, upgrade, downgrade, y reinstall). Las excepciones son las opciones --installed-from-repo y --from-repo. Si bien tienen el mismo significado, solo se aplican a los paquetes que les siguen en la línea de comandos. Además, se pueden repetir con valores diferentes.

OPCIONES

--action
Acción a realizar sobre los siguientes elementos.

Esta es una opción obligatoria que debe preceder a los elementos (objetos) de la transacción. El comando do necesita esta información para saber qué acción realizar sobre los elementos especificados. Admite: install, remove, upgrade, downgrade, reinstall.

--type
Tipo de los siguientes elementos.

Admite: auto, package, group. auto es el valor predeterminado hasta que se usa la opción type.

--allowerasing
Permitir la eliminación de paquetes instalados para resolver cualquier posible problema de dependencia.
--skip-broken
Resolver cualquier problema de dependencia eliminando paquetes que causan problemas de la transacción.
--skip-unavailable
Permitir omitir paquetes que no están disponibles en los repositorios. Todos los paquetes disponibles serán instalados.
--allow-downgrade
Habilitar la bajada de versión de dependencias al resolver la operación solicitada.
--no-allow-downgrade
Deshabilitar la bajada de versión de dependencias al resolver la operación solicitada.
--installed-from-repo=ID_REPO,...
Filtra los paquetes instalados por el ID del repositorio desde el que fueron instalados.
--from-repo=ID_REPO,...
Los paquetes (o sus proporciona) especificados explícitamente en la línea de comandos solo se buscarán en los repositorios especificados.
Estos repositorios se habilitan automáticamente.
La habilitación y deshabilitación de repositorios aún se aplica. Las dependencias de estos paquetes se resolverán desde cualquier repositorio habilitado.
--downloadonly
Descarga el conjunto de paquetes resuelto sin ejecutar una transacción RPM.
--offline
Almacena la transacción para que se realice sin conexión. Ver dnf5-offline(8), Comando sin conexión <#offline-command-ref-label>.
--advisories=NOMBRE_ASESORIA,...
Incluye contenido contenido en asesorías con el nombre especificado.
Esta es una opción de lista.
Los valores esperados son IDs de asesoría, por ejemplo, FEDORA-2201-123.
Cualquier comando de transacción (install, upgrade) fallará con un error si no hay una asesoría existente en la lista; esto se puede evitar utilizando el interruptor --skip-unavailable.
--advisory-severities=SEVERIDAD_ASESORIA,...
Incluye contenido contenido en asesorías con la severidad especificada.
Esta es una opción de lista.
Los valores aceptados son: critical, important, moderate, low, none.
--bzs=ID_BUGZILLA,...
Incluye contenido contenido en asesorías que corrigen un ticket del ID de Bugzilla dado.
Esta es una opción de lista.
Los valores esperados son IDs numéricos, por ejemplo, 123123.
Cualquier comando de transacción (install, upgrade) fallará con un error si no hay una asesoría que corrija el ticket dado; esto se puede evitar utilizando el interruptor --skip-unavailable.
--cves=ID_CVE,...
Incluye contenido contenido en asesorías que corrigen un ticket del ID de CVE (Common Vulnerabilities and Exposures) dado.
Esta es una opción de lista.
Los valores esperados son IDs de cadena en formato CVE, por ejemplo, CVE-2201-0123.
Cualquier comando de transacción (install, upgrade) fallará con un error si no hay una asesoría que corrija el ticket dado; esto se puede evitar utilizando el interruptor --skip-unavailable.
--security
Incluye contenido contenido en asesorías de seguridad.
--bugfix
Incluye contenido contenido en asesorías de corrección de errores.
--enhancement
Incluye contenido contenido en asesorías de mejora.
--newpackage
Incluye contenido contenido en asesorías de nuevos paquetes.

EJEMPLOS

dnf5 do --action=install tito
Instala el paquete tito.
dnf5 do --action=remove sddm-wayland-plasma --action=install sddm-x11
Reemplaza el paquete sddm-wayland-plasma con sddm-x11.
dnf5 do --action=install --type=group id=office 'name=Games and Entertainment' --type=package iftop --action=remove atop
Instala el grupo office (por ID), el grupo Games and Entertainment (por nombre), y el paquete iftop, y elimina el paquete atop.
dnf5 do --action=install pkg --from-repo=myrepo1 pkg1 --from-repo=myrepo2 pkg2 --action=remove --installed-from-repo=compromised_repo '*'
Instala el paquete pkg desde cualquier repositorio habilitado, así como el paquete pkg1 desde el repositorio myrepo1 y el paquete pkg2 desde el repositorio myrepo2. Las dependencias
es para estos paquetes se instalan desde cualquier repositorio habilitado. Además, elimine todos los paquetes instalados desde el compromised_repo.
