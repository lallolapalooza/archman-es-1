Licencias: MPL2

NOMBRE

dnssec-ksr - crear archivos de respuesta de clave firmada (SKR) para configuraciones KSK fuera de línea

SINOPSIS

dnssec-ksr [-E engine] [-e fecha/desplazamiento] [-F] [-f archivo] [-h] [-i fecha/desplazamiento] [-K directorio] [-k política] [-l archivo] [-o] [-V] [-v nivel] {comando} {zona}

DESCRIPCIÓN

El dnssec-ksr se puede utilizar para emitir varios comandos que son necesarios para generar conjuntos de registros prefirmados para una zona donde el archivo de clave privada de la Clave de Firma de Claves (KSK) normalmente está fuera de línea. Esto requiere que las Claves de Firma de Zona (ZSK) se pregeneren, y que los conjuntos de registros DNSKEY, CDNSKEY y CDS ya estén firmados de antemano.

Lo último se hace creando Solicitudes de Firma de Claves (KSR) que se pueden importar en el entorno donde está disponible la KSK. Una vez allí, este programa puede crear Respuestas de Clave Firmada (SKR) que pueden ser cargadas por un servidor DNS autoritativo.

OPCIONES

-E engine
Esta opción especifica el hardware criptográfico a utilizar, cuando corresponda.

Cuando BIND 9 está compilado con OpenSSL, esto necesita establecerse al identificador del motor de OpenSSL que controla el acelerador criptográfico o el módulo de servicio de hardware (generalmente pkcs11).

-e fecha/desplazamiento
Esta opción establece la fecha de finalización para la cual se necesitan generar claves o SKRs (dependiendo del comando).
-F
Esta opción activa el modo FIPS (Estándares Federales de Procesamiento de Información de EE. UU.) si la biblioteca criptográfica subyacente soporta la ejecución en modo FIPS.
-f
Esta opción establece el archivo SKR a firmar al emitir un comando sign .
-h
Esta opción imprime un resumen corto de las opciones y argumentos de dnssec-ksr.
-i fecha/desplazamiento
Esta opción establece la fecha de inicio para la cual se necesitan generar claves o SKRs (dependiendo del comando).
-K directorio
Esta opción establece el directorio en el cual se leerán o escribirán los archivos de clave (dependiendo del comando).
-k política
Esta opción establece la dnssec-policy específica para la cual se necesitan generar o firmar claves.
-l archivo
Esta opción proporciona un archivo de configuración que contiene una declaración dnssec-policy (que coincida con la política establecida con -k).
-o
Normalmente, al pregenerar claves, se crean ZSKs. Cuando se establece esta opción, se crean KSKs en su lugar.
-V
Esta opción imprime la información de la versión.
-v nivel
Esta opción establece el nivel de depuración. El nivel 1 está destinado a ser útilmente detallado para usuarios generales; niveles más altos están destinados para desarrolladores.

comando

El comando KSR a ejecutar. Vea abajo los comandos disponibles.

zona

El nombre de la zona para la cual se está ejecutando el comando KSR.

COMANDOS

keygen
Pre-genera un número de claves, dada una política DNSSEC y un intervalo. El número de claves generadas depende del intervalo y la vida útil de la clave.
request
Crea una Solicitud de Firma de Claves (KSR), dada una política DNSSEC y un intervalo. Esto generará un archivo con un número de paquetes de claves, donde cada paquete contiene las ZSKs actualmente publicadas (según los metadatos de temporización).
sign
Firma una Solicitud de Firma de Claves (KSR), dada una política DNSSEC y un intervalo, creando una Respuesta de Clave Firmada (SKR). Esto añadirá los registros DNSKEY, CDS y CDNSKEY correspondientes para la KSK que se está utilizando para firmar.

ESTADO DE SALIDA

El comando dnssec-ksr termina con 0 en caso de éxito, o con un valor distinto de cero si ocurrió un error.

EJEMPLOS

Cuando necesite generar ZSKs para la zona "example.com" para el próximo año, dada una dnssec-policy llamada "mypolicy":

dnssec-ksr -i now -e +1y -k mypolicy -l named.conf keygen example.com

Crear un KSR para la misma zona y periodo se puede hacer con:

dnssec-ksr -i now -e +1y -k mypolicy -l named.conf request example.com > ksr.txt

Típicamente, ahora transferiría el KSR al sistema que tiene acceso a la KSK.

Firmar el KSR creado arriba se puede hacer con:

dnssec-ksr -i now -e +1y -k kskpolicy -l named.conf -f ksr.txt sign example.com

Asegúrese de que los parámetros DNSSEC en kskpolicy coincidan con los de mypolicy.
