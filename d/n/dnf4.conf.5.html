exclude_from_weak_autodetect
boolean

Si está habilitado, dnf detectará automáticamente las dependencias débiles no cumplidas (recomendaciones o suplementos) de los paquetes instalados en el sistema. Los proveedores de estas dependencias débiles ya no serán instalados por dnf como dependencias débiles (aún se instalarán si se arrastran como una dependencia regular). El valor predeterminado es true.

exit_on_lock
boolean

El cliente dnf debe salir inmediatamente cuando algo más tenga el bloqueo. El valor predeterminado es False.

gpgkey_dns_verification
boolean

dnf debe intentar verificar automáticamente las claves de verificación GPG utilizando el sistema DNS. Esta opción requiere que el módulo python unbound (python3-unbound) esté instalado en el sistema cliente. Este sistema tiene dos características principales. La primera es comprobar si alguna de las claves ya instaladas ha sido revocada. La eliminación automática de la clave aún no está disponible, por lo que corresponde al usuario eliminar las claves revocadas del sistema. La segunda característica es la verificación automática de las nuevas claves cuando se añade un repositorio al sistema. En modo interactivo, el resultado se escribe en la salida como una sugerencia al usuario. En modo no interactivo (es decir, cuando se usa -y), este sistema aceptará automáticamente las claves que estén disponibles en el DNS y estén correctamente firmadas usando DNSSEC. También aceptará claves que no existan en el sistema DNS y cuya NO existencia esté criptográficamente probada usando DNSSEC. Esto es principalmente para preservar la compatibilidad hacia atrás. El valor predeterminado es False.

group_package_types
list

Lista de los siguientes: optional, default, mandatory. Le indica a dnf qué tipo de paquetes en los grupos se instalarán cuando se llame a 'groupinstall'. El valor predeterminado es: default, mandatory.

ignorearch
boolean

Si se establece en True, RPM permitirá intentos de instalar paquetes incompatibles con la arquitectura de la CPU. El valor predeterminado es False. A menudo se usa junto con la opción arch.

installonlypkgs
list

Lista de nombres de proveedores de paquetes que solo deben ser instalados, nunca actualizados. Los kernels en particular caen en esta categoría. Estos paquetes nunca son eliminados por dnf autoremove incluso si se instalaron como dependencias (ver clean_requirements_on_remove para detalles sobre la eliminación automática). Esta opción añade los valores de la lista a la lista installonlypkgs predeterminada usada por DNF. El número de versiones de paquetes mantenidas está regulado por installonly_limit.

installonly_limit
integer

Número de paquetes installonly permitidos para ser instalados concurrentemente. El valor predeterminado es 3. El número mínimo de paquetes installonly es 2. El valor 0 significa un número ilimitado de paquetes installonly. El valor 1 está explícitamente no permitido ya que complica las actualizaciones del kernel debido a la protección del kernel en ejecución contra la eliminación.

installroot
string

La raíz del sistema de archivos para todas las operaciones de empaquetado. Requiere una ruta absoluta. Ver también la opción de línea de comandos --installroot.

install_weak_deps
boolean

Cuando esta opción se establece en True y se va a instalar un nuevo paquete, todos los paquetes vinculados por una relación de dependencia débil (indicadores Recommends o Supplements) con este paquete serán arrastrados a la transacción. El valor predeterminado es True.

keepcache
boolean

Mantiene los paquetes descargados en la caché cuando se establece en True. Incluso si se establece en False y los paquetes no se han instalado, persistirán hasta la siguiente transacción exitosa. El valor predeterminado es False.

logdir
string

Directorio donde se almacenarán los archivos de registro. El valor predeterminado es /var/log.

logfilelevel
integer

Nivel de salida de los mensajes del archivo de registro, en el rango de 0 a 10. Cuanto más alto sea el número, más salida de depuración se escribirá en los registros. El valor predeterminado es 9.

Esta opción controla dnf.log, dnf.librepo.log y hawkey.log. Aunque dnf.librepo.log y hawkey.log solo se ven afectados al establecer logfilelevel en 10.

log_compress
boolean

Cuando se establece en True, los archivos de registro se comprimen cuando se rotan. El valor predeterminado es False.

log_rotate
integer

Los archivos de registro se rotan log_rotate veces antes de ser eliminados. Si log_rotate es 0, la rotación no se realiza. El valor predeterminado es 4.

log_size
tamaño de almacenamiento

Los archivos de registro se rotan cuando crecen más allá de log_size bytes. Si log_size es 0, la rotación no se realiza. El valor predeterminado es 1 MB. Las unidades válidas son 'k', 'M', 'G'.

El tamaño se aplica a archivos de registro individuales, no a la suma de todos los archivos de registro. Ver también log_rotate.

metadata_timer_sync
tiempo en segundos

El período mínimo entre dos ejecuciones consecutivas del makecache timer . El comando se detendrá inmediatamente si ha pasado menos tiempo que este período desde su última ejecución. No afecta a una ejecución simple de makecache . Use 0 para deshabilitar completamente la sincronización automática de metadatos. El valor predeterminado corresponde a tres horas. El valor se redondea a la hora siguiente comenzada.

module_obsoletes
boolean

Esta opción controla si dnf debe aplicar obsoletos modulares cuando sea posible. El valor predeterminado es False.

module_platform_id
string

Establezca esto en $name:$stream para anular el PLATFORM_ID detectado desde /etc/os-release. Es necesario para realizar una actualización del sistema y cambiar a una nueva plataforma.

module_stream_switch
boolean

Esta opción controla si es posible cambiar los flujos habilitados de un módulo. El valor predeterminado es False.

multilib_policy
string

Controla cómo se tratan los paquetes multilib durante las operaciones de instalación. Puede ser "best" (el predeterminado) para que el solucionador de dependencias prefiera paquetes que coincidan mejor con la arquitectura del sistema, o "all" para instalar paquetes para todas las arquitecturas disponibles.

obsoletes
boolean

Esta opción solo tiene efecto durante una instalación/actualización. Habilita la lógica de procesamiento de obsoletos de dnf, lo que significa que hace que dnf compruebe si alguna de las dependencias de un paquete dado ya no es necesaria y las elimina. Útil al hacer actualizaciones a nivel de distribución. El valor predeterminado es 'true'.

Opción de línea de comandos: --obsoletes <#obsoletes-option-label>

optional_metadata_types
list

Lista de tipos de metadatos a cargar además de primary, modules, comps, updateinfo y presto, que siempre se cargan.

Tenga en cuenta que la lista puede ser extendida por comandos individuales para solicitar explícitamente la carga de un tipo de metadato específico.

Actualmente solo se admite el valor filelists . El valor predeterminado es una lista vacía.

persistdir
string

Directorio donde DNF almacena sus datos persistentes entre ejecuciones. El valor predeterminado es "/var/lib/dnf".

persistence
string

Si los cambios deben persistir a través de los reinicios del sistema. El valor predeterminado es auto. Pasar --transient <#transient-option-label> anulará esta configuración a transient. Los valores válidos son:

  • auto: Los cambios persistirán a través de los reinicios, a menos que el destino sea un sistema bootc en ejecución y el sistema ya esté en un estado desbloqueado (es decir, /usr es escribible).
  • transient: Los cambios se perderán en el próximo reinicio. Solo aplicable en sistemas bootc. Tenga cuidado de que los cambios a /etc y /var serll persistir, dependiendo de la configuración de su sistema bootc. Véase también https://bootc-dev.github.io/bootc/man/bootc-usr-overlay.html.
  • persist: Los cambios persistirán a través de los reinicios.
pluginconfpath
lista

Lista de directorios en los que se buscan configuraciones de complementos para cargar. Se analizan todos los archivos de configuración encontrados en estos directorios que tengan el mismo nombre que un complemento. La ruta predeterminada es /etc/dnf/plugins.

pluginpath
lista

Lista de directorios en los que se buscan complementos para cargar. Se utilizan los complementos encontrados en cualquiera de los directorios en esta opción de configuración. El valor predeterminado contiene una ruta específica de la versión de Python.

plugins
booleano

Controla si los complementos están habilitados. El valor predeterminado es True.

protected_packages
lista

Lista de paquetes que DNF nunca debe eliminar por completo. Están protegidos mediante Obsoletes, así como mediante eliminaciones de usuarios o complementos.

El valor predeterminado es: dnf, glob:/etc/yum/protected.d/*.conf y glob:/etc/dnf/protected.d/*.conf. Por lo tanto, cualquier paquete que deba protegerse puede hacerlo incluyendo un archivo en /etc/dnf/protected.d con su nombre de paquete en él.

DNF también protegerá el paquete correspondiente a la versión en ejecución del kernel. Véase también la opción protect_running_kernel.

protect_running_kernel
booleano

Controla si el paquete correspondiente a la versión en ejecución del kernel está protegido contra la eliminación. El valor predeterminado es True.

releasever
cadena

Se utiliza para la sustitución de $releasever en la configuración del repositorio.

Las variables $releasever_major y $releasever_minor se derivarán automáticamente de $releasever dividiéndolo en el primer .. Por ejemplo, si $releasever está establecido en 1.23, entonces $releasever_major será 1 y $releasever_minor será 23.

$releasever_major y $releasever_minor también pueden ser establecidos por la distribución.

Véase también las variables del repositorio.

reposdir
lista

DNF busca los archivos de configuración de repositorios en las rutas especificadas por reposdir. El comportamiento de reposdir podría diferir cuando se utiliza junto con la opción --installroot.

rpmverbosity
cadena

Nivel de salida de depuración de los scriptlets de RPM. Uno de: critical, emergency, error, warn, info o debug. El valor predeterminado es info.

strict
booleano

Si está deshabilitado, todos los paquetes no disponibles o los paquetes con dependencias rotas proporcionados al comando DNF se omitirán sin generar el error que haría fallar toda la operación. Actualmente solo funciona para el comando install. El valor predeterminado es True.

tsflags
lista

Lista de cadenas que añaden indicadores adicionales a la transacción de RPM.

valor de tsflag Indicador de transacción de RPM
noscripts RPMTRANS_FLAG_NOSCRIPTS
test RPMTRANS_FLAG_TEST
notriggers RPMTRANS_FLAG_NOTRIGGERS
nodocs RPMTRANS_FLAG_NODOCS
justdb RPMTRANS_FLAG_JUSTDB
nocontexts RPMTRANS_FLAG_NOCONTEXTS
nocaps RPMTRANS_FLAG_NOCAPS
nocrypto RPMTRANS_FLAG_NOFILEDIGEST
deploops RPMTRANS_FLAG_DEPLOOPS

La opción nocrypto también establecerá los indicadores VS _RPMVSF_NOSIGNATURES y _RPMVSF_NODIGESTS . La opción test proporciona una comprobación de la transacción sin realizar la transacción. Incluye la descarga de paquetes, la comprobación de claves gpg (incluyendo la importación permanente de claves adicionales si es necesario) y la comprobación de rpm para prevenir conflictos de archivos. La opción nocaps es compatible con rpm-4.14 o posterior. Cuando se utiliza nocaps pero rpm no lo admite, DNF solo lo informa como un tsflag no válido.

upgrade_group_objects_upgrade
booleano

Establezca esto en False para deshabilitar la ejecución automática de la actualización de grupo al ejecutar el comando upgrade . El valor predeterminado es True (realizar la operación).

usr_drift_protected_paths
lista

Lista de rutas que probablemente causarán problemas cuando su contenido se desvíe con respecto a /usr, por ejemplo /etc/pam.d/*. Si una transición transitoria modificaría estas rutas, DNF aborta la operación e imprime un error. Admite comodines. El valor predeterminado es glob:/etc/dnf/usr-drift-protected-paths.d/*.conf. Por lo tanto, se puede proteger una lista de rutas creando un archivo .conf en /etc/dnf/usr-drift-protected-paths.d/ que contenga una ruta (o un patrón de comodín) por línea.

Al utilizar persistence=transient en sistemas bootc, se crea una capa de sobreposición transitoria en /usr, y cualquier cambio que DNF haga en /usr se descartará al reiniciar. Sin embargo, otras rutas como /etc y /var (a menudo) no están respaldadas por una capa de sobreposición transitoria, por lo que los cambios en ellas persistirán a través de los reinicios. Normalmente, este "desvío del sistema de archivos" no es un problema, pero puede causar problemas en ciertas situaciones. Por ejemplo, un archivo de configuración en /etc que es compartido por múltiples paquetes podría referenciar un archivo .so bajo /usr/lib64 que ya no existe.

varsdir
lista

Lista de directorios en los que se buscan los archivos de definición de variables. El valor predeterminado es "/etc/dnf/vars", "/etc/yum/vars". Véase los archivos de variables en la referencia de configuración.

zchunk
booleano

Habilita o deshabilita el uso de metadatos de repositorio comprimidos con el formato zchunk (si está disponible). El valor predeterminado es True.

OPCIONES DEL REPOSITORIO

baseurl
lista

Lista de URL para el repositorio. El valor predeterminado es [].

Las URL se prueban en el orden indicado (equivalente al comportamiento de yum "failovermethod=priority").

cost
entero

El costo relativo de acceder a este repositorio, con un valor predeterminado de 1000. Este valor se compara cuando las prioridades de dos repositorios son iguales. Se elige el repositorio con el costo más bajo . Es útil para hacer que la biblioteca prefiera repositorios en disco a los remotos.

enabled
booleano

Incluir este repositorio como fuente de paquetes. El valor predeterminado es True.

gpgkey
lista de cadenas

URL de archivos de claves GPG que pueden usarse para firmar los metadatos y los paquetes de este repositorio, vacío por defecto. Si un archivo no puede verificarse usando las claves ya importadas, se intenta importar las claves de esta opción y luego se usan para la verificación.

metalink
cadena

URL de un metalink para el repositorio. El valor predeterminado es None.

mirrorlist
cadena

URL de una lista de espejos para el repositorio. El valor predeterminado es None.

module_hotfixes
booleano

Establezca esto en True para desactivar el filtrado de RPM de módulos y hacer que todos los RPM del repositorio estén disponibles. El valor predeterminado es False. Esto permite al usuario crear un repositorio con correcciones urgentes seleccionadas que se incluyen en un conjunto de paquetes en un sistema modular.

name
cadena

Un nombre legible para humanos del repositorio. El valor predeterminado es el ID del repositorio.

priority
entero

El valor de prioridad de este repositorio, el valor predeterminado es 99. Si hay más de un paquete candidato para una operación particular, se elige el del repositorio con el valor de prioridad más bajo , posiblemente a pesar de ser menos conveniente en otros aspectos (por ejemplo, por ser una versión más baja).

type
cadena

Tipo de metadatos del repositorio. Los valores admitidos son: rpm-md. Alias para rpm-md: rpm, repomd, rpmmd, yum, YUM.

NOMBRES DE REPOSITORIOS DE FUENTE Y DEBUGINFO

Para un repositorio dado con un identificador en la forma "<ID>-rpms", se espera que su repositorio de fuente correspondiente tenga un identificador en la forma "<ID>-source-rpms" y el repositorio de debuginfo un identificador en la forma "<ID>-debug-rpms". De lo contrario (si el identificador del repositorio no tiene el sufijo "-rpms"), se espera que el repositorio de fuente tenga un identificador en la forma "<ID>-source" y el repositorio de debuginfo un identificador en la forma "<ID>-debuginfo".

Por ejemplo, para el repositorio "fedora", el repositorio de fuente es "fedora-source" y el repositorio de debuginfo es "fedora-debuginfo". Para el repositorio "fedora-rpms", el repositorio de fuente es "fedora-source-rpms" y el repositorio de debuginfo es "fedora-debug-rpms".

VARIABLES DEL REPOSITORIO

El lado derecho de cada opción de repositorio puede enriquecerse con las siguientes variables:

$arch

Se refiere a la arquitectura de CPU del sistema, por ejemplo, aarch64, i586, i686 y x86_64.

$basearch

Se refiere a la arquitectura base del sistema. Por ejemplo, las máquinas i686 y i586 tienen ambas una arquitectura base de i386, y las máquinas AMD64 e Intel64 tienen una arquitectura base de x86_64.

$releasever

Se refiere a la versión de lanzamiento del sistema operativo que DNF deriva de la información disponible en RPMDB.

$releasever_major

Versión principal de $releasever, es decir, el componente de $releasever que aparece antes del primer ..

$releasever_minor

Versión secundaria de $releasever, es decir, el componente de $releasever que aparece después del primer ..

Además de estas variables codificadas, también se pueden usar variables definidas por el usuario. Pueden definirse mediante archivos de variables o usando variables de entorno especiales. Los nombres de estas variables deben tener el prefijo DNF_VAR_ y solo pueden constar de caracteres alfanuméricos y guiones bajos:

$ DNF_VAR_MY_VARIABLE=value

Para usar una variable así en la configuración de su repositorio, elimine el prefijo. Por ejemplo:

[myrepo]
baseurl=https://example.site/pub/fedora/$MY_VARIABLE/releases/$releasever

Tenga en cuenta que no es posible anular las variables arch y basearch usando archivos de variables o variables de entorno.

Aunque se anima a los usuarios a usar variables con nombre, las variables de entorno numeradas DNF0 - DNF9 todavía son compatibles:

$ DNF1=value
[myrepo]
baseurl=https://example.site/pub/fedora/$DNF1/releases/$releasever

Se admite una forma limitada de expansión de parámetros similar a la de shell para las variables.

${my_variable:-word} Si my_variable no está definida o está vacía, se sustituirá word . De lo contrario, se sustituirá el valor de my_variable .

${my_variable:+word} Si my_variable está definida y no está vacía, se sustituirá word . De lo contrario, se sustituirá la cadena vacía.

Las expansiones de parámetros pueden anidarse hasta una profundidad máxima de 32. Por ejemplo:

${my_defined_variable:+${my_undefined_variable:-foobar}}

se evaluará como foobar.

OPCIONES PARA [MAIN] Y REPOSITORIO

Algunas opciones pueden aplicarse en la sección principal, por repositorio, o en una combinación. El valor proporcionado en la sección principal se usa para todos los repositorios como valor predeterminado, que los repositorios pueden anular luego en su configuración.

bandwidth
tamaño de almacenamiento

Ancho de banda total disponible para la descarga. Tiene sentido cuando se usa con la opción throttle. El tamaño de almacenamiento está en bytes por defecto, pero puede especificarse con una unidad de storage. Las unidades válidas son 'k', 'M', 'G'.

countme
booleano

Cuando está habilitado, una (y solo una) solicitud HTTP GET para el archivo metalink se seleccionará al azar cada semana para llevar una bandera de URL especial.

Esta bandera permite al proveedor del repositorio estimar el número de sistemas que consumen el repositorio, contando dichas solicitudes durante una semana. Este método es más preciso que solo contar direcciones IP únicas (que está sujeto a sobreconteo y subconteo debido a arrendamientos DHCP cortos y NAT, respectivamente).

Esta *no* es una solicitud HTTP fuera de banda realizada solo para este propósito. Solo las solicitudes iniciadas por DNF durante la operación normal, como para verificar actualizaciones de metadatos, pueden recibir esta bandera.

La bandera es un simple parámetro "countme=N" agregado a la URL metalink donde N es un entero que representa el "cubo" de antigüedad al que pertenece este sistema. Se definen cuatro cubos, basados en cuántas semanas completas han transcurrido desde la instalación de un sistema:

cubo antigüedad del sistema
1 primera semana
2 primer mes (2 - 4 semanas)
3 primeros 6 meses (5 - 24 semanas)
4 más de 6 meses (> 24 semanas)

Este número está destinado a ayudar a distinguir máquinas de corta duración (desechables) de instalaciones a largo plazo y a obtener una mejor imagen de cómo se utilizan los sistemas a lo largo del tiempo.

Para determinar el tiempo de instalación de un sistema ("época"), se utiliza el tiempo de modificación del archivo machine-id(5) como única fuente de verdad. Este archivo está semánticamente ligado a la vida útil del sistema, ya que normalmente se rellena en el momento de la instalación o durante el primer arranque por una herramienta de instalación o un sistema init (como systemd(1)), respectivamente, y permanece sin cambios.

Si el archivo está vacío o falta (como en contenedores), el tiempo de la primera solicitud realizada utilizando la URL metalink expandida (es decir, con cualquier variable de repositorio como $releasever sustituida) que llevaba la bandera se declara como la época.

Si no se define ninguna URL metalink para este repositorio pero sí una URL mirrorlist, esta última se utiliza para este propósito en su lugar.

El valor predeterminado es Falso.

deltarpm
booleano

Cuando está habilitado, DNF ahorra ancho de banda al descargar archivos delta RPM mucho más pequeños, reconstruyéndolos en RPM localmente. Sin embargo, esto consume bastantes CPU y E/S. El valor predeterminado es Falso. Requiere /usr/bin/applydeltarpm en el sistema.

deltarpm_percentage
entero

Cuando el tamaño relativo del delta frente al pkg es mayor que este, no se utiliza el delta. El valor predeterminado es 75 (Los deltas deben ser al menos un 25% más pequeños que el pkg). Use 0 para desactivar el procesamiento de delta RPM. Los repositorios locales (con baseurl <file://>) tienen los delta RPM desactivados por defecto.

enablegroups
booleano

Determina si DNF permitirá el uso de grupos de paquetes para este repositorio. El valor predeterminado es Verdadero (se permiten los grupos de paquetes).

excludepkgs
lista

Excluir paquetes de este repositorio, especificados por un nombre o un comodín y separados por una coma, de todas las operaciones. Se puede deshabilitar utilizando el interruptor de línea de comandos --disableexcludes. El valor predeterminado es [].

fastestmirror
booleano

Si está habilitado, la latencia del socket TCP se utiliza para encontrar el espejo disponible más cercano. Luego se selecciona un espejo al azar con menos del doble de la latencia más baja para fines de balanceo de carga. Esto anula el orden proporcionado por el propio archivo mirrorlist/metalink, y no tiene en cuenta los parámetros de mirrorlist como el ancho de banda del espejo ni los espejos preferidos para las direcciones IP del cliente.

gpgcheck
booleano

Si se debe realizar una verificación de firma GPG en los paquetes encontrados en este repositorio. El valor predeterminado es Falso.

Esta opción solo se puede utilizar para fortalecer la política de seguridad RPM activa establecida con la macro %_pkgverify_level (consulte el archivo /usr/lib/rpm/macros para obtener más detalles). Eso significa que, si la macro se establece en 'signature' o 'all' y esta opción es Falsa, se reemplazará a Verdadera durante el tiempo de ejecución de DNF, y se imprimirá una advertencia. Para suprimir la advertencia, asegúrese de que esta opción sea Verdadera para cada repositorio habilitado, y también habilite localpkg_gpgcheck.

includepkgs
lista

Incluir paquetes de este repositorio, especificados por un nombre o un comodín y separados por una coma, en todas las operaciones. Inverso de excludepkgs, DNF excluirá cualquier paquete en el repositorio que no coincida con esta lista. Esto funciona en conjunto con excludepkgs y no lo anula, por lo que si 'excludepkgs=*.i386' y 'includepkgs=python*', entonces solo los paquetes que comiencen con python que no tengan una arquitectura i386 serán vistos por DNF en este repo. Se puede deshabilitar utilizando el interruptor de línea de comandos --disableexcludes. El valor predeterminado es [].

ip_resolve
tipo de dirección IP

Determina cómo DNF resuelve los nombres de host. Establézcalo en '4'/'IPv4' o '6'/'IPv6' para resolver solo a direcciones IPv4 o IPv6, respectivamente. Por defecto, DNF resuelve a ambas direcciones.

localpkg_gpgcheck
booleano

Si se debe realizar una verificación de firma GPG en paquetes locales (paquetes en un archivo, no en un repositorio). El valor predeterminado es Falso. Esta opción está sujeta a la política de seguridad RPM activa (consulte gpgcheck para más detalles).

max_parallel_downloads
entero

Número máximo de descargas de paquetes simultáneas. El valor predeterminado es 3. Máximo de 20.

metadata_expire
tiempo en segundos

El período después del cual se verifica el repositorio remoto en busca de actualizaciones de metadatos y, en caso afirmativo, se actualiza la caché de metadatos local. El valor predeterminado corresponde a 48 horas. Establezca esto en -1 o never para que el repositorio nunca se considere expirado. La expiración de metadatos también puede ser desencadenada por un cambio en la marca de tiempo de los archivos de configuración (dnf.conf, <repo>.repo). Consulte también check_config_file_age.

minrate
tamaño de almacenamiento

Esto establece el umbral de baja velocidad en bytes por segundo. Si el servidor está enviando datos a una velocidad igual o inferior a este valor durante al menos los segundos de la opción timeout, DNF aborta la conexión. El valor predeterminado es 1000. Las unidades válidas son 'k', 'M', 'G'.

password
cadena

La contraseña a utilizar para conectarse a un repositorio con autenticación HTTP básica. Vacío por defecto.

proxy
cadena

URL de un servidor proxy para conectarse. Establézcalo a una cadena vacía en la configuración del repositorio para deshabilitar la configuración del proxy heredada de la sección principal. El formato esperado de esta opción es <scheme>://<ip-o-hostname>[:puerto]. (Por compatibilidad con versiones anteriores, '_none_' puede usarse en lugar de la cadena vacía).

Nota: Las variables de entorno de curl (como http_proxy) son efectivas si esta opción no está establecida (o se establece '_none_' en la configuración del repositorio). Consulte la página man de curl para obtener más detalles.

proxy_username
cadena

El nombre de usuario a utilizar para conectarse al servidor proxy. Vacío por defecto.

proxy_password
cadena

La contraseña a utilizar para conectarse al servidor proxy. Vacío por defecto.
