val_context_setqflags() - administrar las banderas del contexto del validador

val_resolve_and_check(), val_free_result_chain() - consultar y validar respuestas de un servidor de nombres DNS

DESCRIPCIÓN

La función val_resolve_and_check() consulta a un conjunto de servidores de nombres para la tupla <nombre_dominio, tipo, clase> y verifica y valida la respuesta. La verificación implica comprobar los RRSIG y la validación es la verificación de una cadena de autenticación desde un ancla de confianza configurada.

El parámetro flags se puede utilizar para controlar los resultados de la validación. Los siguientes valores, que se pueden combinar con OR, están definidos actualmente para este campo:

VAL_QUERY_DONT_VALIDATE
Esta bandera hace que el validador deshabilite la validación para esta consulta.
VAL_QUERY_IGNORE_SKEW
Esta bandera hace que el validador deshabilite la comprobación de los tiempos de inicio y expiración de las firmas en los RRSIG.
VAL_QUERY_AC_DETAIL
Esta bandera hace que el validador copie los detalles de la cadena de autenticación en el miembro val_rc_answer dentro de la estructura val_result_chain devuelta.
VAL_QUERY_ASYNC
Esta bandera habilita la resolución asíncrona de consultas para esa búsqueda.
VAL_QUERY_NO_DLV
Esta bandera hace que el validador deshabilite el procesamiento de DLV para esta consulta. Esto solo está disponible si la biblioteca libval(3) se ha compilado con soporte DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Al consultar varios servidores de nombres, libsres(3) también intentará varios tamaños de EDNS0, terminando con una consulta que tiene EDNS0 deshabilitado (es decir, sin el bit CD establecido). Esta bandera hace que libval deshabilite la recuperación de EDNS0 para la consulta.
VAL_QUERY_ITERATE
Esta bandera fuerza a libval a realizar una búsqueda iterativa de la consulta consultando varios servidores de nombres en la jerarquía de delegación, en lugar de solicitar esta información a cualquier servidor de nombres en caché que pueda estar configurado en dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Esta bandera fuerza a libval a mirar solo su caché mientras intenta resolver un nombre.
VAL_QUERY_SKIP_CACHE
Hay dos niveles de caché que ocurren dentro de libval: a nivel de aserción y a nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en ambas cachés mientras intenta resolver un nombre.
VAL_QUERY_SKIP_ANS_CACHE
Hay dos niveles de caché que ocurren dentro de libval: a nivel de aserción y a nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en la caché de respuestas mientras intenta resolver un nombre. Si ya existe una aserción para el nombre, clase y tipo dados, esa aserción se reutiliza hasta que expira. Una vez que expira, el nombre se busca a través de una consulta, incluso si un registro más nuevo (obtenido por otra aserción en el mismo o diferente contexto) está disponible en su caché de respuestas.

El primer parámetro de val_resolve_and_check() es el contexto del validador. Las aplicaciones pueden crear un nuevo contexto de validador utilizando la función val_create_context(). Esta función analiza los archivos de configuración del resolvedor y del validador y crea el manejador newcontext para esta información analizada. La información almacenada como parte del contexto del validador incluye la política de validación y la política del resolvedor.

Las políticas del validador y del resolvedor se leen de los archivos /etc/dnsval.conf y /etc/resolv.conf por defecto. /etc/root.hints proporciona información de arranque para el validador cuando funciona como un resolvedor completo (ver dnsval.conf(3)). Estos valores predeterminados pueden ser diferentes si se especificó algún otro valor en el momento de la configuración de la biblioteca. Si no se encuentra el archivo de configuración del resolvedor por defecto en la ubicación especificada, libval también intentará recurrir a /etc/resolv.conf como último recurso.

Las aplicaciones también pueden crear un contexto de validador con una política personalizada utilizando la función val_create_context_ex().

El argumento opt en val_create_context_ex() apunta a la siguiente estructura:

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags especifica las banderas de consulta por defecto para las consultas asociadas con el contexto. Este campo es idéntico al argumento flags en la función val_resolve_and_check().

Los campos vc_val_conf, vc_res_conf y vc_root_conf se pueden usar para especificar archivos de configuración alternativos en lugar de los archivos por defecto utilizados para la información de configuración del validador, el resolvedor y los hints raíz.

El campo vc_valpol se puede usar para proporcionar un "fragmento" de configuración de validador personalizado al validador. El validador analiza esta información y la aplica a la configuración del validador por defecto, ya sea como una extensión o como una anulación, según lo especificado por el campo vc_polflags. El campo vc_nslist, de manera similar, se puede usar para proporcionar una lista personalizada de servidores de nombres recursivos a los que enviar consultas, además de (o en lugar de) la lista de servidores de nombres especificada en el archivo resolv.conf. La lista de servidores de nombres en vc_res_conf debe especificarse como una lista de direcciones IP o IPv6 separadas por espacios en blanco.

Se puede crear un mapeo personalizado entre una zona y un servidor de nombres utilizando la función val_context_store_ns_for_zone().

vc_polflags se puede configurar con los siguientes valores:

CTX_DYN_POL_VAL_OVR
Cuando esta bandera está activada, solo la configuración del validador especificada en el campo vc_valpol se utiliza para la configuración del validador. Las opciones especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_OVR
Cuando esta bandera está activada, solo la configuración del resolvedor especificada en el campo vc_res_conf se utiliza para la configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.
CTX_DYN_POL_ROOT_OVR
Cuando esta bandera está activada, solo la configuración de hints raíz especificada en el campo vc_root_conf se utiliza para la configuración de hints raíz. Las opciones especificadas en el archivo root.hints se ignoran.
CTX_DYN_POL_VAL_EXT
Cuando esta bandera está activada, la configuración del validador especificada en el campo vc_valpol se añade a la configuración del validador existente. Las opciones especificadas en dnsval.conf se utilizan como base y las opciones proporcionadas en vc_valpol tienen prioridad sobre las de dnsval.conf.
CTX_DYN_POL_RES_EXT
Cuando esta bandera está activada, la configuración del resolvedor especificada en el campo vc_res_conf se añade a la configuración del resolvedor existente. Las opciones especificadas en resolv.conf se utilizan como base y las opciones proporcionadas en vc_res_conf tienen prioridad sobre las de resolv.conf.
CTX_DYN_POL_ROOT_EXT
Cuando esta bandera está activada, la configuración de hints raíz especificada en el campo vc_root_conf se añade a la configuración de hints raíz existente. Las opciones especificadas en root.hints se utilizan como base y las opciones proporcionadas en vc_root_conf tienen prioridad sobre las de root.hints.

La función val_context_setqflags() se utiliza para establecer banderas de consulta por defecto para todas las futuras consultas realizadas con el contexto dado. El parámetro action puede ser VAL_CONTEXT_SETQFLAGS_SET o VAL_CONTEXT_SETQFLAGS_UNSET para establecer o borrar las banderas, respectivamente. El parámetro flags contiene las banderas que se establecerán o borrarán.

Las funciones p_val_status(), p_ac_status() y p_val_error() se utilizan para obtener representaciones de cadena legibles de los diferentes estados de validación, estados de cadena de autenticación y errores que puede devolver la biblioteca.

Las funciones val_istrusted(), val_isvalidated() y val_does_not_exist() se utilizan para comprobar propiedades de un estado de validación devuelto por val_resolve_and_check().

La función val_log_add_optarg() se utiliza para controlar la salida de los mensajes de registro de la biblioteca. El parámetro args es una cadena de texto que especifica las opciones de registro, similar a las opciones de línea de comandos de dnsval. El parámetro use_stderr se puede establecer en 1 para dirigir la salida del registro a stderr, o en 0 para utilizar la ubicación especificada en args.

Las funciones val_free_context() y val_free_result_chain() se utilizan para liberar la memoria asignada por val_create_context() y val_resolve_and_check(), respectivamente.

val_ac_status
Estado de validación del elemento de la cadena de autenticación. Este campo contendrá el código de estado para el componente dado en la cadena de autenticación. Este campo puede contener uno de los siguientes valores:
VAL_AC_UNSET
El estado no pudo ser determinado.
VAL_AC_IGNORE_VALIDATION
La validación del registro de recursos dado fue ignorada, ya sea debido a alguna directiva de política local o debido a algún comportamiento específico del protocolo.
VAL_AC_UNTRUSTED_ZONE
La política local definió una zona dada como no confiable, sin considerarse necesaria ninguna validación adicional.
VAL_AC_PINSECURE
La cadena de autenticación desde un ancla de confianza hasta una zona dada no pudo ser construida debido a la ausencia comprobable de un registro DS para esta zona en el padre.
VAL_AC_BARE_RRSIG
La respuesta fue para una consulta de tipo RRSIG. Los RRSIGs contienen las firmas criptográficas para otros datos DNS y no pueden ser validados por sí mismos.
VAL_AC_NO_LINK
No se configuró ningún ancla de confianza para una cadena de autenticación dada o la cadena no se conectó.
VAL_AC_TRUST
Al menos una de las firmas que cubren el conjunto de registros DNSKEY dado se verificó directamente usando una clave configurada como ancla de confianza DNSSEC.
VAL_AC_RRSIG_MISSING
Los datos RRSIG no pudieron ser recuperados para un registro de recursos.
VAL_AC_DNSKEY_MISSING
La DNSKEY para un RRSIG que cubre un registro de recursos no pudo ser recuperada.
VAL_AC_DS_MISSING
El registro DS que cubre un registro DNSKEY no estaba disponible.
VAL_AC_DATA_MISSING
No se devolvieron datos para una consulta y el DNS no indicó un error.
VAL_AC_DNS_ERROR
Se encontró algún error durante el procesamiento del DNS.
VAL_AC_NOT_VERIFIED
Todos los RRSIG que cubren el conjunto de registros no pudieron ser verificados.
VAL_AC_VERIFIED
Al menos un RRSIG que cubre un registro de recursos tuvo un estado de VAL_AC_RRSIG_VERIFIED.

val_ac_trust

REGISTRO (LOGGING)

libval proporciona la función val_log_add_optarg() para controlar la verbosidad y la ubicación de la salida de los mensajes de registro.

La función val_log_add_optarg() toma dos argumentos: el primer argumento args es un valor de cadena de caracteres que especifica la ubicación y la verbosidad. El segundo argumento, use_stderr, si se establece en un valor mayor que 0, permite que libval envíe mensajes de registro a stderr.

La cadena de caracteres que especifica la ubicación y la verbosidad del destino del registro tiene un formato específico:

<nivel-depuración>:<tipo-destino>[:<opciones-destino>]

donde
<nivel-depuración> es 1-7, para niveles crecientes de verbosidad
<tipo-destino> es uno de file, net, syslog, stderr, stdout
<opciones-destino> depende de <tipo-destino>
file:<nombre-archivo> (abierto en modo de adjuntar)
net[:<nombre-host>:<puerto-host>] (127.0.0.1:1053)
syslog[:facility] (0-23 (predeterminado 1 USER))

Los niveles de registro se pueden traducir aproximadamente a diferentes tipos de mensajes de registro de la siguiente manera (los mensajes devueltos para cada nivel en esta lista subsumen los mensajes devueltos para el nivel superior):

3 : Error   : error encontrado
4 : Warning : recuperándose de un error
5 : Notice  : proporciona los resultados de validación finales para una consulta
              y detalles sobre archivos de políticas y etiquetas utilizadas
6 : Info
: proporciona detalles sobre las cadenas de autenticación 7 : Debug : proporciona información del nivel de depuración
