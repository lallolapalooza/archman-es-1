DD(1) Comandos de usuario DD(1)

NOMBRE

dd - convierte y copia un archivo

SINOPSIS

dd [OPERANDO]...
dd OPCIÓN

DESCRIPCIÓN

Copia un archivo, convirtiendo y formateando según los operandos.

bs=BYTES
lee y escribe hasta BYTES bytes a la vez (por defecto: 512); anula ibs y obs
cbs=BYTES
convierte BYTES bytes a la vez
conv=CONVS
convierte el archivo según la lista de símbolos separada por comas
count=N
copia solo N bloques de entrada
ibs=BYTES
lee hasta BYTES bytes a la vez (por defecto: 512)
if=FILE
lee desde FILE en lugar de la entrada estándar
iflag=FLAGS
lee según la lista de símbolos separada por comas
obs=BYTES
escribe BYTES bytes a la vez (por defecto: 512)
of=FILE
escribe en FILE en lugar de la salida estándar
oflag=FLAGS
escribe según la lista de símbolos separada por comas
seek=N
(o oseek=N) salta N bloques de salida del tamaño de obs
skip=N
(o iseek=N) salta N bloques de entrada del tamaño de ibs
status=LEVEL
El NIVEL de información a imprimir en la salida de error estándar; 'none' suprime todo excepto los mensajes de error, 'noxfer' suprime las estadísticas de transferencia finales, 'progress' muestra estadísticas de transferencia periódicas

N y BYTES pueden ir seguidos de los siguientes sufijos multiplicadores: c=1, w=2, b=512, kB=1000, K=1024, MB=1000*1000, M=1024*1024, xM=M, GB=1000*1000*1000, G=1024*1024*1024, y así sucesivamente para T, P, E, Z, Y, R, Q. También se pueden usar prefijos binarios: KiB=K, MiB=M, y así sucesivamente. Si N termina en 'B', cuenta bytes no bloques.

Cada símbolo de CONV puede ser:

ascii
de EBCDIC a ASCII
ebcdic
de ASCII a EBCDIC
ibm
de ASCII a EBCDIC alternativo
block
rellena registros terminados por nueva línea con espacios hasta el tamaño cbs
unblock
reemplaza los espacios finales en registros del tamaño cbs con nueva línea
lcase
cambia mayúsculas a minúsculas
ucase
cambia minúsculas a mayúsculas
sparse
intenta saltar en lugar de escribir bloques de NUL completos
swab
intercambia cada par de bytes de entrada
sync
rellena cada bloque de entrada con NUL hasta el tamaño ibs; cuando se usa con block o unblock, rellena con espacios en lugar de NULs
excl
falla si el archivo de salida ya existe
nocreat
no crea el archivo de salida
notrunc
no trunca el archivo de salida
noerror
continúa después de errores de lectura
fdatasync
escribe físicamente los datos del archivo de salida antes de finalizar
fsync
lo mismo, pero también escribe metadatos

Cada símbolo de FLAG puede ser:

append
modo de añadir (solo tiene sentido para la salida; se sugiere conv=notrunc)
direct
usa E/S directa para los datos
directory
falla a menos que sea un directorio
dsync
usa E/S sincronizada para los datos
sync
lo mismo, pero también para metadatos
fullblock
acumula bloques completos de entrada (solo iflag)
nonblock
usa E/S no bloqueante
noatime
no actualiza la hora de acceso
nocache
Solicita desechar la caché. Ver también oflag=sync
noctty
no asigna terminal de control desde el archivo
nofollow
no sigue enlaces simbólicos

Enviar una señal USR1 a un proceso 'dd' en ejecución hace que imprima estadísticas de E/S en la salida de error estándar y luego reanude la copia.

Las opciones son:

--help
muestra esta ayuda y sale
--version
muestra información de versión y sale
