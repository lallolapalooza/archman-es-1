DESCRIPCIÓ

N

Linux implementa los protocolos AppleTalk descritos en Inside AppleTalk. Solo la capa DDP y AARP están presentes en el kernel. Están diseñados para ser utilizados a través de las bibliotecas de protocolo netatalk. Esta página documenta la interfaz para aquellos que deseen o necesiten usar la capa DDP

directamente.

La comunicación entre AppleTalk y el programa de usuario funciona utilizando una interfaz de socket compatible con BSD. Para obtener más información sobre sockets, ver socket(

7).

Un socket AppleTalk se crea llamando a la función socket(2) con un argumento de familia de socket AF_APPLETALK. Los tipos de socket válidos son SOCK_DGRAM para abrir un socket ddp o SOCK_RAW para abrir un socket raw. protocol es el protocolo AppleTalk a ser recibido o enviado. Para SOCK_RAW debes especificar ATPROTO_DDP

.

Los sockets raw solo pueden ser abiertos por un proceso con ID de usuario efectivo 0 o cuando el proceso tiene la capacidad CAP_NET_RAW

.

Formato de

dirección

Una dirección de socket AppleTalk se define como una combinación de un número de red, un número de nodo y un número de

puerto. 


struct at_addr {
    unsigned short s_net;
    unsigned char  s_node;
};
struct sockaddr_atalk {
    sa_family_t    sat_family;    /* familia de dirección */
    unsigned char  sat_port;      /* puerto */
    struct at_addr sat_addr;      /* red/nodo */
}
;

sat_family siempre se establece en AF_APPLETALK. sat_port contiene el puerto. Los números de puerto por debajo de 129 se conocen como puertos reservados. Solo los procesos con ID de usuario efectivo 0 o la capacidad CAP_NET_BIND_SERVICE pueden hacer bind(2) a estos sockets. sat_addr es la dirección del host. El miembro net de struct at_addr contiene la red del host en orden de bytes de red. El valor de AT_ANYNET es un comodín y también implica "esta red". El miembro node de struct at_addr contiene el número de nodo del host. El valor de AT_ANYNODE es un comodín y también implica "este nodo". El valor de ATADDR_BCAST es una direcció

n de broadcast
local de enlace.

NOTA

S

Ten mucho cuidado con la opción SO_BROADCAST; no es privilegiada en Linux. Es fácil sobrecargar la red con el envío descuidado a direcciones de

broadcast.

Compatibilida

d

La interfaz básica de socket AppleTalk es compatible con netatalk en sistemas derivados de BSD. Muchos sistemas BSD no verifican SO_BROADCAST al enviar tramas de broadcast; esto puede llevar a problemas de

compatibilidad.

El modo de socket raw es único de Linu

x y existe para soportar el paquete
CAP alternativo y las herramientas de
monitoreo de AppleTalk más fácilmente.
