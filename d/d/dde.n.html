NOMBRE

dde - Ejecutar un comando de Intercambio Dinámico de Datos

SINOPSIS

package require dde 1.4

dde servername ?-force? ?-handler proc? ?--? ?topic?

dde execute ?-async? ?-binary? service topic data

dde poke ?-binary? service topic item data

dde request ?-binary? service topic item

dde services service topic

dde eval ?-async? topic cmd ?arg arg ...?

DESCRIPCIÓN

Este comando permite a una aplicación enviar un comando de Intercambio Dinámico de Datos (DDE) cuando se ejecuta en Microsoft Windows. El Intercambio Dinámico de Datos es un mecanismo mediante el cual las aplicaciones pueden intercambiar datos sin procesar. Cada transacción DDE necesita un nombre de servicio y un tema. Tanto el nombre de servicio como el tema son definidos por la aplicación; Tcl usa el nombre de servicio TclEval, mientras que el nombre del tema es el nombre del intérprete dado por dde servername. Otras aplicaciones tienen sus propios nombres de servicio y temas. Por ejemplo, Microsoft Excel tiene el nombre de servicio Excel.

COMANDOS DDE

Los siguientes comandos son un subconjunto del conjunto completo de comandos de Intercambio Dinámico de Datos.

dde servername ?-force? ?-handler proc? ?--? ?topic?
dde servername registra el intérprete como un servidor DDE con el nombre de servicio TclEval y el nombre de tema especificado por topic. Si no se proporciona ningún topic , dde servername devuelve el nombre del tema actual o la cadena vacía si no está registrado como servicio. Si el nombre de topic dado ya está en uso, se añade un sufijo de la forma “ #2” o “ #3” al nombre para hacerlo único. El resultado del comando será el nombre realmente utilizado. La opción -force se usa para forzar el registro de exactamente el nombre de topic dado.

La opción -handler especifica un procedimiento Tcl que será llamado para procesar las llamadas al servidor dde. Si el paquete se ha cargado en un intérprete seguro, se debe definir un procedimiento -handler . El procedimiento se llama con todos los argumentos proporcionados por la llamada remota.

dde execute ?-async? ?-binary? service topic data
dde execute toma los data y los envía al servidor indicado por service con el tema indicado por topic. Típicamente, service es el nombre de una aplicación, y topic es un archivo con el que trabajar. El campo data se le da a la aplicación remota. Típicamente, la aplicación trata el campo data como un script, y el script se ejecuta en la aplicación. La opción -async solicita una invocación asíncrona. El comando devuelve un mensaje de error si el script no se ejecutó, a menos que se haya usado la bandera -async , en cuyo caso el comando devuelve inmediatamente sin error. Sin la opción -binary todos los datos se enviarán en unicode. Para clientes dde que no implementan el formato de portapapeles CF_UNICODE, esto se traducirá automáticamente a la codificación del sistema. Puedes usar la opción -binary en combinación con el resultado de encoding convertto para enviar datos en cualquier otra codificación.
dde poke ?-binary? service topic item data
dde poke pasa los data al servidor indicado por service usando el topic y el item especificados. Típicamente, service es el nombre de una aplicación. topic es específico de la aplicación pero puede ser un comando para el servidor o el nombre de un archivo con el que trabajar. El item también es específico de la aplicación y a menudo no se usa, pero siempre debe ser no nulo. El campo data se le da a la aplicación remota. Sin la opción -binary todos los datos se enviarán en unicode. Para clientes dde que no implementan el formato de portapapeles CF_UNICODE, esto se traducirá automáticamente a la codificación del sistema. Puedes usar la opción -binary en combinación con el resultado de encoding convertto para enviar datos en cualquier otra codificación.
dde request ?-binary? service topic item
dde request se usa típicamente para obtener el valor de algo; el valor de una celda en Microsoft Excel o el texto de una selección en Microsoft Word. service es típicamente el nombre de una aplicación, topic es típicamente el nombre del archivo, y item es específico de la aplicación. El comando devuelve el valor de item tal como está definido en la aplicación. Normalmente esto se interpreta como una cadena con un nulo final. Si se especifica -binary , el resultado se devuelve como un array de bytes.
dde services service topic
dde services devuelve una lista de pares servicio-tema que existen actualmente en la máquina. Si service y topic son ambas cadenas vacías ({}), se devuelven todos los pares servicio-tema actualmente disponibles en el sistema. Si service está vacío y topic no lo está, se devuelven todos los servicios con el tema especificado. Si service no está vacío y topic sí lo está, se devuelven todos los temas de un servicio dado. Si ambos no están vacíos, si ese par servicio-tema existe actualmente, se devuelve; de lo contrario, se devuelve una cadena vacía.
dde eval ?-async? topic cmd ?arg arg ...?
dde eval evalúa un comando y sus argumentos usando el intérprete especificado por topic. El servicio DDE debe ser el servicio TclEval . La opción -async solicita una invocación asíncrona. El comando devuelve un mensaje de error si el script no se ejecutó, a menos que se haya usado la bandera -async , en cuyo caso el comando devuelve inmediatamente sin error. Este comando se puede usar para reemplazar send en Windows.

DDE Y TCL

Un intérprete Tcl siempre tiene un nombre de servicio de TclEval. Cada intérprete diferente de todas las aplicaciones Tcl en ejecución debe tener un nombre único especificado por dde servername. Cada intérprete está disponible como un tema DDE solo si se usó el comando dde servername para establecer el nombre del tema para cada intérprete. Así que un comando dde services TclEval {} devolverá una lista de pares servicio-tema, donde cada uno de los intérpretes actualmente en ejecución será un tema.

Cuando Tcl procesa un comando dde execute , los datos para el execute se ejecutan como un script en el intérprete nombrado por el tema del comando dde execute .

Cuando Tcl procesa un comando dde request , devuelve el valor de la variable dada en el comando dde en el contexto del intérprete nombrado por el tema dde. Tcl reserva la variable $TCLEVAL$EXECUTE$RESULT para uso interno, y los comandos dde request para esa variable darán resultados impredecibles.

Una aplicación externa que desee ejecutar un script en Tcl debe hacer que ese script almacene su resultado en una variable, ejecute el comando dde execute , y luego ejecute dde request para obtener el valor de la variable.

Al usar DDE, ten cuidado de asegurarte de que la cola de eventos se vacíe usando update o vwait. Esto ocurre por defecto al usar wish a menos que se llame a un comando bloqueante (como exec sin añadir el & para poner el proceso en segundo plano). Si por alguna razón la cola de eventos no se vacía, los comandos DDE pueden bloquearse hasta que la cola de eventos se vacíe. Esto puede crear una situación de bloqueo mutuo.

EJEMPLO

Esto le pide a Internet Explorer (que ya debe estar en ejecución) ir a un sitio web particularmente importante:

package require dde
dde execute -async iexplore WWW_OpenURL http://www.tcl-lang.org/
