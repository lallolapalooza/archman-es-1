DESCRIPCIÓ

N

El módulo Dpkg::Deps proporciona clases que implementan varios tipos de

dependencias.

La función más importante es deps_parse(), que convierte una línea de dependencia en un conjunto

de objetos Dpkg::Deps::{Simple,AND
,OR,Union} dependiendo del caso.

Esta función analiza la línea de dependencia y devuelve un objeto

use_arch (por defecto
1)
Tiene en cuenta la parte de restricción de arquitectura de las dependencias. Establecer a 0 para ignorar completamente esa
información.
host_arch (por defecto la arquitectura
actual)
Define la arquitectura host. Por defecto usa Dpkg::Arch::get_host_arch() para identificar la arquitectura
adecuada.
build_arch (por defecto la arquitectura
actual)
Define la arquitectura de compilación. Por defecto usa Dpkg::Arch::get_build_arch() para identificar la arquitectura
adecuada.
reduce_arch (por defecto
0)
Si se establece a 1, ignora las dependencias que no conciernen a la arquitectura host actual. Esto elimina implícitamente la lista de restricciones de arquitectura para que las dependencias resultantes sean directamente aplicables a la arquitectura
actual.
use_profiles (por defecto
1)
Tiene en cuenta la parte de restricción de perfil de las dependencias. Establecer a 0 para ignorar completamente esa
información.
build_profiles (por defecto sin
perfil)
Define los perfiles de compilación activos. Por defecto no se define ningún
perfil.
reduce_profiles (por defecto
0)
Si se establece a 1, ignora las dependencias que no conciernen al perfil de compilación actual. Esto elimina implícitamente la fórmula de restricción de perfil para que las dependencias resultantes sean directamente aplicables a los perfiles
actuales.
reduce_restrictions (por defecto
0)
Si se establece a 1, ignora las dependencias que no conciernen al conjunto actual de restricciones. Esto elimina implícitamente cualquier lista de restricciones de arquitectura o fórmula de restricción para que las dependencias resultantes sean directamente aplicables a la restricción actual. Esto implica actualmente "reduce_arch" y "reduce_profiles", y los anula si están
establecidos.
union (por defecto
0)
Si se establece a 1, devuelve un Dpkg::Deps::Union en lugar de un Dpkg::Deps::AND. Usar esto al analizar campos que no son dependencias como
Conflicts.
virtual (por defecto
0)
Si se establece a 1, permite solo relaciones de versión de paquetes virtuales, es decir, ninguna o "=". Esto debería establecerse siempre que se trabaje con campos
Provides.
build_dep (por defecto
0)
Si se establece a 1, permite calificadores de arquitectura solo para dependencias de compilación, es decir ":native". Esto debería establecerse siempre que se trabaje con dependencias de
compilación.
tests_dep (por defecto
0)
Si se establece a 1, permite nombres de paquetes específicos de pruebas en las dependencias, es decir "@" y "@builddeps@" (desde dpkg 1.18.7). Esto debería establecerse siempre que se trabaje con campos de dependencia de debian/tests/control.

Esta opción habilita implícitamente (y forzadamente) "build_dep" porque las dependencias de

CLASES - Dpkg::Deps::

*

Hay varios tipos de dependencias. Una dependencia Dpkg::Deps::Simple representa una sola declaración de dependencia (se relaciona con un solo paquete). Las dependencias Dpkg::Deps::Multiple se construyen sobre esta clase y combinan varias dependencias de diferentes maneras. Dpkg::Deps::AND representa el "Y" lógico entre dependencias mientras que Dpkg::Deps::OR representa el "O" lógico. Los objetos Dpkg::Deps::Multiple pueden contener objetos Dpkg::Deps::Simple así como otros objetos Dpkg::Deps::

Multiple.

En la práctica, el código está destinado a manejar los casos realistas que, dada la estructura de dependencias de Debian, implican esas restricciones: AND puede contener objetos Simple u OR, OR solo puede contener objetos

Simple.

Dpkg::Deps::KnownFacts es una clase especial que se usa mientras se evalúan d

ependencias y mientras se intenta simplificarlas. Representa un conjunto de p
aquetes instalados junto con los paquetes virtuales que podrían proporcionar.
