NOMBRE

dpkg-gensymbols - genera archivos de símbolos (información de dependencia de bibliotecas compartidas)

SINOPSIS

dpkg-gensymbols [opción...]

DESCRIPCIÓN

dpkg-gensymbols escanea un árbol de compilación temporal (debian/tmp por defecto) en busca de bibliotecas y genera un archivo de *símbolos* que las describe. Este archivo, si no está vacío, se instala en el subdirectorio DEBIAN del árbol de compilación para que termine incluido en la información de control del paquete.

Al generar estos archivos, utiliza como entrada algunos archivos de símbolos proporcionados por el mantenedor. Busca los siguientes archivos (y usa el primero que encuentra):

  • debian/paquete.symbols.arquitectura
  • debian/symbols.arquitectura
  • debian/paquete.symbols
  • debian/symbols

El principal interés de estos archivos es proporcionar la versión mínima asociada a cada símbolo proporcionado por las bibliotecas. Normalmente corresponde a la primera versión de ese paquete que proporcionó el símbolo, pero puede ser incrementada manualmente por el mantenedor si la ABI del símbolo se extiende sin romper la compatibilidad hacia atrás. Es responsabilidad del mantenedor mantener estos archivos actualizados y precisos, pero dpkg-gensymbols ayuda con eso.

Cuando los archivos de símbolos generados difieren del proporcionado por el mantenedor, dpkg-gensymbols imprimirá una diferencia entre las dos versiones. Además, si la diferencia es demasiado significativa, fallará (puedes personalizar cuánta diferencia toleras, consulta la opción -c).

Este programa se introdujo en dpkg 1.14.8.

MANTENIMIENTO DE ARCHIVOS DE SÍMBOLOS

El formato básico de intercambio del archivo de símbolos se describe en deb-symbols(5), que es utilizado por los archivos de símbolos incluidos en los paquetes binarios. Estos se generan a partir de archivos de símbolos plantilla con un formato basado en el anterior, descrito en deb-src-symbols(5) e incluido en los paquetes fuente.

Los archivos de símbolos solo son realmente útiles si reflejan la evolución del paquete a través de varios lanzamientos. Por lo tanto, el mantenedor tiene que actualizarlos cada vez que se añade un nuevo símbolo para que su versión mínima asociada coincida con la realidad.

Las diferencias contenidas en los registros de compilación pueden utilizarse como punto de partida, pero el mantenedor, además, debe asegurarse de que el comportamiento de esos símbolos no ha cambiado de manera que algo que utilice esos símbolos y se vincule a la nueva versión deje de funcionar con la versión antigua.

En la mayoría de los casos, la diferencia se aplica directamente al archivo debian/paquete.symbols. Dicho esto, normalmente se necesitan ajustes adicionales: se recomienda, por ejemplo, omitir la revisión de Debian de la versión mínima para que los backports con un número de versión inferior pero la misma versión upstream sigan satisfaciendo las dependencias generadas. Si la revisión de Debian no se puede omitir porque el símbolo se añadió realmente por el cambio específico de Debian, entonces se debe añadir el sufijo ‘~’ a la versión.

Antes de aplicar cualquier parche al archivo de símbolos, el mantenedor debe comprobar minuciosamente que es coherente. Los símbolos públicos no deben desaparecer, por lo que el parche idealmente solo debería añadir nuevas líneas.

Tenga en cuenta que puede incluir comentarios en los archivos de símbolos.

No olvide comprobar si las versiones antiguas de los símbolos necesitan ser incrementadas. No hay forma de que dpkg-gensymbols avise de esto. Aplicar ciegamente la diferencia o asumir que no hay nada que cambiar si no hay diferencia, sin comprobar dichos cambios, puede llevar a paquetes con dependencias laxas que afirman poder funcionar con paquetes más antiguos con los que no pueden. Esto introducirá errores difíciles de encontrar durante actualizaciones (parciales).

Buena gestión de bibliotecas

Una biblioteca bien mantenida tiene las siguientes características:

  • su API es estable (los símbolos públicos nunca se eliminan, solo se añaden nuevos símbolos públicos) y los cambios incompatibles solo ocurren cuando cambia el SONAME;
  • idealmente, utiliza el versionado de símbolos para lograr estabilidad de ABI a pesar de cambios internos y extensiones de API;
  • no exporta símbolos privados (dichos símbolos pueden etiquetarse como opcionales como solución).

Al mantener el archivo de símbolos, es fácil notar la aparición y desaparición de símbolos. Pero es más difícil detectar cambios incompatibles en la API y ABI. Por lo tanto, el mantenedor debe leer detenidamente el registro de cambios (changelog) de upstream en busca de casos en los que se hayan roto las reglas de una buena gestión de bibliotecas. Si se descubren problemas potenciales, se debe notificar al autor de upstream, ya que una corrección en upstream siempre es mejor que una solución específica de Debian.

OPCIONES

-Pdirectorio-compilación-paquete
Escanea directorio-compilación-paquete en lugar de debian/tmp.
-ppaquete
Define el nombre del paquete. Requerido si se lista más de un paquete binario en debian/control (o si no hay archivo debian/control).
-vversión
Define la versión del paquete. Por defecto, la versión extraída de debian/changelog. Requerido si se llama fuera de un árbol de paquetes fuente.
-earchivo-biblioteca
Solo analiza las bibliotecas listadas explícitamente en lugar de encontrar todas las bibliotecas públicas. Puedes usar patrones de shell utilizados para expansiones de nombres de ruta (consulta la página del manual de File::Glob para más detalles) en archivo-biblioteca para que coincidan varias bibliotecas con un solo argumento (de lo contrario, necesitas múltiples -e).
-ldirectorio
Antepone directorio a la lista de directorios donde buscar bibliotecas compartidas privadas (desde dpkg 1.19.1). Esta opción se puede usar varias veces.

Nota: Usa esta opción en lugar de establecer LD_LIBRARY_PATH, ya que esa variable de entorno se usa para controlar el enlazador en tiempo de ejecución y abusar de ella para establecer las rutas de bibliotecas compartidas en tiempo de compilación puede ser problemático al compilar cruzadamente, por ejemplo.

-Inombre-archivo
Usa nombre-archivo como archivo de referencia para generar el archivo de símbolos que se integra en el propio paquete.
-O[nombre-archivo]
Imprime el archivo de símbolos generado en la salida estándar o en nombre-archivo si se especifica, en lugar de en debian/tmp/DEBIAN/symbols (o directorio-compilación-paquete/DEBIAN/symbols si se usó -P). Si nombre-archivo ya existe, su contenido se utiliza como base para el archivo de símbolos generado. Puedes usar esta característica para actualizar un archivo de símbolos de modo que coincida con una versión upstream más reciente de tu biblioteca.
-t
Escribe el archivo de símbolos en modo plantilla en lugar del formato compatible con deb-symbols(5). La principal diferencia es que en el modo plantilla los nombres de símbolos y las etiquetas se escriben en su forma original, a diferencia de los nombres de símbolos post-procesados con etiquetas eliminadas en el modo de compatibilidad. Además, algunos símbolos pueden omitirse al escribir un archivo deb-symbols(5) estándar (según las reglas de procesamiento de etiquetas), mientras que todos los símbolos siempre se escriben en la plantilla del archivo de símbolos.
-c[0-4]
Define las comprobaciones a realizar al comparar el archivo de símbolos generado con el archivo plantilla utilizado como punto de partida. Por defecto, el nivel es 1. Niveles crecientes realizan más comprobaciones e incluyen todas las comprobaciones de niveles inferiores.
Nivel 0
Nunca falla.
Nivel 1
Falla si han desaparecido algunos símbolos.
Nivel 2
Falla si se han introducido algunos símbolos nuevos.
Nivel 3
Falla si han desaparecido algunas bibliotecas.
Nivel 4
Falla si se han introducido algunas bibliotecas nuevas.
-v
Imprime la versión de dpkg-gensymbols y sale.
-h, --help
Muestra un mensaje de ayuda y sale.

EJEMPLO

Como mantenedor de un paquete que proporciona una biblioteca compartida, deberías añadir una línea a tu debian/rules para generar el archivo de símbolos:

    override_dh_gensymbols:
        dh_gensymbols --package=my-package

Esto generará el archivo debian/my-package.symbols (o debian/my-package.symbols.arch si está definido) a partir de las bibliotecas encontradas en debian/tmp y comparará el resultado con debian/my-package.symbols.in (si existe).

Si no incluyes la opción --package, se intentará adivinar el nombre del paquete a partir del control de Debian. Si solo hay un paquete binario en debian/control, su nombre se usará automáticamente.

Si tu archivo de símbolos no existe, el contenido generado se instalará directamente. Si existe, se comparará y se mostrará una diferencia si existe. Si la diferencia es demasiado importante, el proceso de compilación fallará (según el nivel de comprobación).

Para generar un archivo de símbolos para un paquete que proporciona varias bibliotecas, puedes usar la opción -e:

    override_dh_gensymbols:
        dh_gensymbols -e libfoo.so.1 -e libbar.so.2

Para actualizar un archivo de símbolos existente con nuevas bibliotecas que se han añadido:

    dh_gensymbols -Odebian/my-package.symbols

Esto imprimirá el archivo de símbolos actualizado en la salida estándar. Luego puedes copiarlo y pegarlo en tu archivo debian/my-package.symbols.

Si quieres utilizar la versión más reciente de la biblioteca para actualizar tu archivo de símbolos:

    dh_gensymbols -Odebian/my-package.symbols -Idebian/my-package.symbols

Esto imprimirá el archivo de símbolos actualizado en la salida estándar. Luego puedes copiarlo y pegarlo en tu archivo debian/my-package.symbols.

NAME

dpkg-gensymbols — generate symbols dependency files

SYNOPSIS

dpkg-gensymbols [option...]

DESCRIPTION

This program scans shared libraries in a package and generates a symbols file for them. It is intended to be run by maintainers of Debian packages.

It is typically called from the debian/rules file. For example:

      override_dh_shlibdeps:
              dh_shlibdeps
              dpkg-gensymbols -plibfoo

The symbols file generated by dpkg-gensymbols is stored in the debian/ directory. It will be named libfoo.symbols (or libfoo.symbols.override if the -o option is used). This file is used by dpkg-deb(1) to check for symbol version changes when a new version of the package is installed.

The symbols file format is documented in deb-symbols(5).

If no template file is found, dpkg-gensymbols generates a new symbols file from scratch. Otherwise, it compares the generated symbols with the existing symbols file and reports any differences.

MAINTAINING SYMBOLS FILES

When a symbols file is generated for the first time, or when you want to update it, you should use the -g or -o option respectively. After generation, you should carefully review the file and commit it to the version control system.

When upgrading a library, you should check the output of dpkg-gensymbols for warnings about new or lost symbols and libraries. If new symbols are introduced, they should be added to the symbols file and exported. If symbols are removed, they should be kept in the symbols file with an appropriate deprecation note, or removed if they are truly gone.

When a library is rebuilt without any changes, the generated symbols file should match the template file exactly. If there are differences, it might indicate an unintended change in the library's API or ABI, or a problem with the symbols file itself.

OPTIONS

-e
Generate symbols file even if the library is not installed, provided its binaries are available in the current directory. This option is ignored if a template file is found.
-g
Generate a new symbols file based on the symbols in the installed libraries. This option is only useful when no template file exists, and it implies the -e option.
-ofile
Write the output to file instead of debian/libfoo.symbols. The file can also be named debian/libfoo.symbols.override. If file exists, dpkg-gensymbols will generate a diff between the generated symbols and the template file.
-clevel
Set the check level for symbol differences. The level can be a number from 0 to 3.
0
No checks are performed. No differences are reported.
1
Only new symbols are reported. This is the default level.
2
New and lost symbols are reported.
3
New, lost, and changed symbols are reported.
This value can be overridden by the environment variable DPKG_GENSYMBOLS_CHECK_LEVEL.
-q
Keep quiet and never generate a diff between generated symbols file and the template file used as starting point or show any warnings about new/lost libraries or new/lost symbols. This option only disables informational output but not the checks themselves (see -c option).
-aarch
Assume arch as host architecture when processing symbol files. Use this option to generate a symbol file or diff for any architecture provided its binaries are already available.
-d
Enable debug mode. Numerous messages are displayed to explain what dpkg-gensymbols does.
-V
Enable verbose mode. The generated symbols file contains deprecated symbols as comments. Furthermore in template mode, pattern symbols are followed by comments listing real symbols that have matched the pattern.
-?, --help
Show the usage message and exit.
--version
Show the version and exit.

ENVIRONMENT

DEB_HOST_ARCH
Sets the host architecture if the --arch option has not be specified.
DPKG_GENSYMBOLS_CHECK_LEVEL
Overrides the command check level, even if the -c command-line argument was given (note that this goes against the common convention of command-line arguments having precedence over environment variables).
DPKG_COLORS
Sets the color mode (since dpkg 1.18.5). The currently accepted values are: auto (default), always and never.
DPKG_NLS
If set, it will be used to decide whether to activate Native Language Support, also known as internationalization (or i18n) support (since dpkg 1.19.0). The accepted values are: 0 and 1 (default).
