NOMBRE

dpkg-trigger - una utilidad de activadores de paquetes

SINOPSIS

dpkg-trigger [opción...] nombre-del-activador

dpkg-trigger [opción...] comando

DESCRIPCIÓN

dpkg-trigger es una herramienta para activar explícitamente activadores y comprobar su compatibilidad en el dpkg en ejecución.

Esto puede ser utilizado por scripts de mantenimiento en situaciones complejas y condicionales donde los activadores de archivos, o la directiva declarativa del archivo de control activate, no son suficientemente ricos. También puede ser utilizado para pruebas y por administradores del sistema (pero ten en cuenta que dpkg-trigger no ejecutará realmente los activadores).

Las sintaxis de nombres de activadores no reconocidas son un error para dpkg-trigger.

Este programa se introdujo en dpkg 1.14.17.

COMANDOS

--check-supported
Comprueba si el dpkg en ejecución soporta activadores (normalmente se llama desde un postinst). Saldrá con 0 si se ha ejecutado un dpkg capaz de activar, o 1 con un mensaje de error a stderr si no. Normalmente, sin embargo, es mejor simplemente activar el activador deseado con dpkg-trigger.
-?, --help
Muestra el mensaje de uso y sale.
--version
Muestra la versión y sale.

OPCIONES

--admindir=dir
Cambia la ubicación de la base de datos de dpkg. Por defecto es /var/lib/dpkg si DPKG_ADMINDIR no ha sido establecido.
--root=directorio
Establece el directorio raíz a directorio, lo que establece el directorio administrativo a «directorio/var/lib/dpkg» (desde dpkg 1.21.0).
--by-package=paquete
Anula al esperador de activadores (normalmente establecido por dpkg a través de la variable de entorno DPKG_MAINTSCRIPT_PACKAGE de los scripts de mantenimiento, nombrando al paquete al que pertenece el script, y este se utilizará por defecto).
--no-await
Esta opción hace que el paquete que llama T (si lo hay) no tenga que esperar el procesamiento de este activador; los paquetes interesados I, no se añadirán a la lista de espera de procesamiento de activadores de T y el estado de T no cambiará. T puede considerarse instalado incluso si I aún no ha procesado el activador.
--await
Esta opción hace lo contrario de --no-await (desde dpkg 1.17.21). Si el paquete interesado ha declarado una directiva de “noawait”, entonces esta opción no será efectiva. Actualmente es el comportamiento por defecto.
--no-act
Solo probar, no cambiar nada realmente.

ESTADO DE SALIDA

0
La acción solicitada se realizó con éxito. O un comando de verificación o aserción devolvió verdadero.
1
Un comando de verificación o aserción devolvió falso.
2
Error fatal o irrecuperable debido a un uso inválido de la línea de comandos, o interacciones con el sistema, como accesos a la base de datos, asignaciones de memoria, etc.

AMBIENTE

DPKG_ROOT
Si se establece y la opción --root no se ha especificado, se usará como directorio raíz del sistema de archivos (desde dpkg 1.21.0).
DPKG_ADMINDIR
Si se establece y la opción --admindir no se ha especificado, se usará como el directorio de datos de dpkg.
DPKG_DEBUG
Establece la máscara de depuración (desde dpkg 1.21.10) a partir de un valor octal. Las banderas actualmente aceptadas se describen en la opción dpkg --debug, pero no todas estas banderas podrían tener efecto en este programa.
DPKG_COLORS
Establece el modo de color (desde dpkg 1.18.5). Los valores aceptados actualmente son: auto (por defecto), always (siempre) y never (nunca).
DPKG_NLS
Si se establece, se utilizará para decidir si activar o no el Soporte de Lenguaje Nativo, también conocido como soporte de internacionalización (o i18n) (desde dpkg 1.22.7). Los valores aceptados son: 0 y 1 (por defecto).
