NOMBRE

dpkg-architecture - establece y determina la arquitectura para la creación de paquetes

SINOPSIS

dpkg-architecture [opción...] [comando]

DESCRIPCIÓN

dpkg-architecture proporciona una facilidad para determinar y establecer la arquitectura de compilación y host para la creación de paquetes.

La arquitectura de compilación siempre se determina por la variable DEB_BUILD_ARCH si está establecida (y no se especifica --force) o mediante una llamada externa a dpkg(1), y no puede ser establecida en la línea de comandos.

Puede especificar la arquitectura host proporcionando una o ambas opciones --host-arch y --host-type, de lo contrario se usa la variable DEB_HOST_ARCH si está establecida (y no se especifica --force). El valor predeterminado se determina mediante una llamada externa a gcc(1), o la misma que la arquitectura de compilación si CC o gcc no están disponibles. Una de las opciones --host-arch y --host-type es suficiente, el valor de la otra se establecerá a un valor predeterminado usable. De hecho, a menudo es mejor especificar solo una, porque dpkg-architecture le advertirá si su elección no coincide con el valor predeterminado.

COMANDOS

-l, --list
Imprime las variables de entorno, una por línea, en el formato VARIABLE=valor. Esta es la acción predeterminada.
-e, --equal arquitectura
Comprueba la igualdad de la arquitectura (desde dpkg 1.13.13). Compara la arquitectura Debian host actual o especificada con arquitectura, para comprobar si son iguales. Esta acción no expandirá los comodines de arquitectura. El comando finaliza con un estado de salida de 0 si coincide, 1 si no coincide.
-i, --is comodin-arquitectura
Comprueba la identidad de la arquitectura (desde dpkg 1.13.13). Compara la arquitectura Debian host actual o especificada con comodin-arquitectura después de haberla expandido como un comodín de arquitectura, para comprobar si coinciden. El comando finaliza con un estado de salida de 0 si coincide, 1 si no coincide.
-q, --query nombre-variable
Imprime el valor de una sola variable.
-s, --print-set
Imprime un comando de exportación. Esto se puede utilizar para establecer las variables de entorno utilizando el shell POSIX o make eval, dependiendo del formato de salida.
-u, --print-unset
Imprime un comando similar a --print-set pero para desestablecer todas las variables.
-c, --command cadena-comando
Ejecuta una cadena-comando en un entorno que tiene todas las variables establecidas a su valor determinado.

Si la cadena-comando contiene metacaracteres del shell, se invocará a través del shell bourne del sistema.

-L, --list-known
Imprime una lista de nombres de arquitectura válidos. Posiblemente restringida por una o más de las opciones coincidentes --match-wildcard, --match-bits o --match-endian (desde dpkg 1.17.14).
-?, --help
Muestra el mensaje de uso y sale.
--version
Muestra la versión y sale.

OPCIONES

-a, --host-arch arquitectura
Establece la arquitectura Debian host.
-t, --host-type tipo-sistema-gnu
Establece el tipo de sistema GNU host.
-A, --target-arch arquitectura
Establece la arquitectura Debian de destino (desde dpkg 1.17.14).
-T, --target-type tipo-sistema-gnu
Establece el tipo de sistema GNU de destino (desde dpkg 1.17.14).
-W, --match-wildcard comodin-arquitectura
Restringe las arquitecturas listadas por --list-known a aquellas que coinciden con el comodín de arquitectura especificado (desde dpkg 1.17.14).
-B, --match-bits bits-arquitectura
Restringe las arquitecturas listadas por --list-known a aquellas con los bits de CPU especificados (desde dpkg 1.17.14). Puede ser 32 o 64.
-E, --match-endian endianness-arquitectura
Restringe las arquitecturas listadas por --list-known a aquellas con la endianness especificada (desde dpkg 1.17.14). Puede ser little o big.
--print-format formato
Establece el formato de salida para --print-set y --print-unset (desde dpkg 1.20.6), a shell (predeterminado) o make.
-f, --force
Los valores establecidos por variables de entorno existentes con el mismo nombre que los utilizados por los scripts son respetados (es decir, usados por dpkg-architecture), excepto si está presente esta bandera de fuerza. Esto permite al usuario anular un valor incluso cuando la llamada a dpkg-architecture está incrustada en otro script (por ejemplo, dpkg-buildpackage(1)).

TÉRMINOS

máquina de compilación
La máquina en la que se compila el paquete.
máquina host
La máquina para la que se compila el paquete.
máquina de destino
La máquina para la que el compilador está construyendo, o para la que un emulador ejecutará código. Esto solo es necesario al construir una herramienta cruzada (o emulador), que se construirá en la arquitectura de compilación, para ejecutarse en la arquitectura host, y que en sí misma compilará (o ejecutará código emulado) para la arquitectura de destino.
arquitectura Debian
La cadena de arquitectura Debian, utilizada en los paquetes binarios, que especifica el árbol binario en un repositorio de paquetes.

Ejemplos: i386, sparc, hurd-i386.

tupla de arquitectura Debian
Una tupla de arquitectura Debian es la arquitectura completamente calificada con todos sus componentes descritos. Esto difiere de las arquitecturas Debian en que al menos el componente cpu no incrusta el abi. La tupla actual tiene el formato abi-libc-os-cpu.

Ejemplos: base-gnu-linux-amd64, eabihf-musl-linux-arm.

comodín de arquitectura Debian
Un comodín de arquitectura Debian es una cadena de arquitectura especial que coincidirá con cualquier arquitectura real de la que sea parte. La forma general es una tupla de arquitectura Debian con cuatro o menos elementos, y con al menos uno de ellos siendo any. Los elementos faltantes de la tupla se prefijan implícitamente como any, y por lo tanto los siguientes pares son equivalentes:
any-any-any-any = any
any-any-os-any = os-any
any-libc-any-any = libc-any-any

Ejemplos: linux-any, any-i386, hurd-any, eabi-any-any-arm, musl-any-any.

tipo de sistema GNU
Una cadena de especificación de arquitectura que consta de dos partes separadas por un guion: CPU y sistema.

La parte de la CPU nunca contiene un guion, mientras que la parte del sistema puede contener un guion para separar un kernel de su ABI general, donde el ABI general puede contener tanto el tiempo de ejecución (como libc) como la ejecución.

ENTORNO

DPKG_DATADIR
Si se establece, se utilizará como el dpkg directorio de datos, donde se encuentran las tablas de arquitectura (desde dpkg 1.14.17). Por defecto es «/usr/share/dpkg».
DPKG_COLORS
Establece el modo de color (desde dpkg 1.18.5). Los valores aceptados actualmente son: auto (por defecto), always y never.
DPKG_NLS
Si se establece, se utilizará para decidir si activar el soporte de idioma nativo (Native Language Support), también conocido como soporte de internacionalización (o i18n) (desde dpkg 1.19.0). Los valores aceptados son: 0 y 1 (por defecto).

NOTAS

Todos los nombres largos de comandos y opciones están disponibles solo desde dpkg 1.17.17.
