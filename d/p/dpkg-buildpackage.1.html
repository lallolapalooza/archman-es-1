NOMBRE

dpkg-buildpackage - construye paquetes binarios o de origen a partir de fuentes

SINOPSIS

dpkg-buildpackage [opción...] [--] [nombre-de-archivo.dsc|directorio]

DESCRIPCIÓN

dpkg-buildpackage es un programa que automatiza el proceso de construcción de un paquete Debian.

Los argumentos nombre-de-archivo.dsc y directorio se admiten desde dpkg 1.22.7. Su semántica es experimental.

Consiste en los siguientes pasos:

1.
Ejecuta el gancho preinit antes de leer cualquier archivo de origen. Si se ha especificado un archivo .dsc , lo desempaqueta de nuevo y cambia al directorio correspondiente; si se ha especificado un directorio , cambia a ese directorio; de lo contrario, espera que el directorio actual contenga el árbol de fuentes. Prepara el entorno de compilación estableciendo varias variables de entorno (véase ENTORNO), ejecuta el gancho init y llama a dpkg-source --before-build (a menos que se haya utilizado -T o --target ).
2.
Comprueba que las dependencias y conflictos de compilación se satisfacen (a menos que se especifique -d o --no-check-builddeps ).
3.
Si se han seleccionado uno o más objetivos específicos con la opción -T o --target , llama a esos objetivos y se detiene aquí. De lo contrario, ejecuta el gancho preclean y llama a fakeroot debian/rules clean para limpiar el árbol de compilación (a menos que se especifique -nc o --no-pre-clean ).
4.
Ejecuta el gancho source y llama a dpkg-source -b para generar el paquete de origen (si se ha solicitado una compilación de source con --build u opciones equivalentes, y si no se ha especificado ningún archivo .dsc ).
5.
Ejecuta el gancho build y llama a debian/rules objetivo-de-compilación, luego ejecuta el gancho binary seguido de fakeroot debian/rules objetivo-binario (a menos que se haya solicitado una compilación solo de origen con --build=source u opciones equivalentes). Tenga en cuenta que objetivo-de-compilación y objetivo-binario son build y binary (caso por defecto, o si se ha solicitado una compilación any y all con --build u opciones equivalentes), o build-arch y binary-arch (si se ha solicitado una compilación any y no all con --build u opciones equivalentes), o build-indep y binary-indep (si se ha solicitado una compilación all y no any con --build u opciones equivalentes).
6.
Ejecuta el gancho buildinfo y llama a dpkg-genbuildinfo para generar un archivo .buildinfo . Varias opciones de dpkg-buildpackage se reenvían a dpkg-genbuildinfo. Si se ha especificado un archivo .dsc , se hará referencia a él en el archivo .buildinfo generado, ya que podemos determinar la procedencia del árbol de fuentes.
7.
Ejecuta el gancho changes y llama a dpkg-genchanges para generar un archivo .changes . El nombre del archivo .changes dependerá del tipo de compilación y será lo más específico que sea necesario, pero no más; el nombre será:
nombre-del-origen_versión-binaria_arquitectura.changes
para una compilación que incluya any
nombre-del-origen_versión-binaria_all.changes
de lo contrario, para una compilación que incluya all
nombre-del-origen_versión-del-origen_source.changes.
de lo contrario, para una compilación que incluya source

Muchas opciones de dpkg-buildpackage se reenvían a dpkg-genchanges.

8.
Ejecuta el gancho postclean y, si se especifica -tc o --post-clean , volverá a llamar a fakeroot debian/rules clean .
9.
Llama a dpkg-source --after-build.
10.
Ejecuta el gancho check y llama a un verificador de paquetes para el archivo .changes (si se especifica un comando en DEB_CHECK_COMMAND o con --check-command).
11.
Ejecuta el gancho sign y firma utilizando el backend OpenPGP (siempre que no sea una compilación UNRELEASED, o se especifique --no-sign ) para firmar el archivo .dsc (si existe, a menos que se especifique -us o --unsigned-source ), el archivo .buildinfo (a menos que se especifique -ui, --unsigned-buildinfo, -uc o --unsigned-changes ) y el archivo .changes (a menos que se especifique -uc o --unsigned-changes ).
12.
Si se ha especificado un archivo .dsc , elimina el directorio de fuentes extraído.
13.
Ejecuta el gancho done .

OPCIONES

Todas las opciones largas pueden especificarse tanto en la línea de comandos como en los archivos de configuración del sistema y del usuario de dpkg-buildpackage . Cada línea del archivo de configuración es una opción (exactamente igual que la opción de la línea de comandos pero sin los guiones iniciales) o un comentario (si comienza con ‘#’).

--build=tipo
Especifica el tipo de compilación a partir de una lista de componentes separados por comas (desde dpkg 1.18.5). Todos los componentes especificados se combinan para seleccionar el único tipo de compilación a utilizar, lo que implica una única ejecución de compilación con un único archivo .changes generado. Se pasa a dpkg-genchanges.

Los valores permitidos son:

source
Construye el paquete de origen.

Nota: Al usar este valor de forma independiente y si lo que desea es simplemente (re)construir el paquete de origen a partir de un árbol de fuentes limpio, usar dpkg-source directamente siempre es una mejor opción, ya que no requiere que se instalen dependencias de compilación que de otro modo serían necesarias para poder llamar al objetivo clean .

any
Construye los paquetes binarios específicos de la arquitectura.
all
Construye los paquetes binarios independientes de la arquitectura.
binary
Construye los paquetes binarios específicos e independientes de la arquitectura. Este es un alias para any,all.
full
Construye todo. Este es un alias para source,any,all, e idéntico al caso por defecto cuando no se especifica ninguna opción de compilación.
-g
Equivalente a --build=source,all (desde dpkg 1.17.11).
-G
Equivalente a --build=source,any (desde dpkg 1.17.11).
-b
Equivalente a --build=binary o --build=any,all.
-B
Equivalente a --build=any.
-A
Equivalente a --build=all.
-S
Equivalente a --build=source.
-F
Equivalente a --build=full, --build=source,binary o --build=source,any,all (desde dpkg 1.15.8).
--target=objetivo[,...]
--target objetivo[,...]
-T, --rules-target=objetivo[,...]
Llama a debian/rules objetivo una vez por cada objetivo especificado, después de haber configurado el entorno de compilación (excepto por llamar a dpkg-source --before-build), y detiene el proceso de compilación del paquete aquí (desde dpkg 1.15.0, opción larga desde dpkg 1.18.8, soporte para múltiples objetivos desde dpkg 1.18.16). Si también se indica --as-root , el comando se ejecuta como root (véase --root-command). Tenga en cuenta que los objetivos conocidos que son que se requiere que se ejecute como root no necesitan esta opción (es decir, los objetivos clean, binary, binary-arch y binary-indep ).
--as-root
Solo tiene significado junto con --target (desde dpkg 1.15.0). Requiere que el objetivo se ejecute con permisos de root.
-si
-sa
-sd
-vversion
-Cchanges-description
-mmaintainer-address
-emaintainer-address
Se pasan sin cambios a dpkg-genchanges. Véase su página de manual.
--build-by=maintainer-address
--source-by=maintainer-address (desde dpkg 1.21.10)
Se pasa como -m a dpkg-genchanges. Véase su página de manual.
--release-by=maintainer-address
--changed-by=maintainer-address (desde dpkg 1.21.10)
Se pasa como -e a dpkg-genchanges. Véase su página de manual.
-a, --host-arch architecture
Especifica la arquitectura de Debian para la que se compila (opción larga desde dpkg 1.17.17). La arquitectura de la máquina en la que se compila se determina automáticamente, y también es la predeterminada para la máquina anfitriona.
-t, --host-type gnu-system-type
Especifica el tipo de sistema GNU para el que se compila (opción larga desde dpkg 1.17.17). Se puede usar en lugar de --host-arch o como complemento para anular el tipo de sistema GNU predeterminado de la arquitectura de Debian anfitriona.
--target-arch architecture
Especifica la arquitectura de Debian para la que compilarán los binarios generados (desde dpkg 1.17.17). El valor predeterminado es la máquina anfitriona.
--target-type gnu-system-type
Especifica el tipo de sistema GNU para el que compilarán los binarios generados (desde dpkg 1.17.17). Se puede usar en lugar de --target-arch o como complemento para anular el tipo de sistema GNU predeterminado de la arquitectura de destino de Debian.
-P, --build-profiles=profile[,...]
Especifica el(los) perfil(es) para los que se compila, como una lista separada por comas (desde dpkg 1.17.2, opción larga desde dpkg 1.18.8). El comportamiento predeterminado es compilar sin ningún perfil específico. También los establece (como una lista separada por espacios) en la variable de entorno DEB_BUILD_PROFILES lo que permite, por ejemplo, que los archivos debian/rules usen esta información para compilaciones condicionales.
-j, --jobs[=jobs|auto]
Especifica el número de trabajos que se pueden ejecutar simultáneamente (desde dpkg 1.14.7, opción larga desde dpkg 1.18.8). El número de trabajos coincide con el número de procesadores en línea si se especifica auto (desde dpkg 1.17.10), o es un número ilimitado si no se especifica jobs . El comportamiento predeterminado es auto (desde dpkg 1.18.11) en modo no forzado (desde dpkg 1.21.10), y como tal siempre es más seguro usarlo con cualquier paquete, incluidos aquellos que no son seguros para compilaciones paralelas. Establecer el número de trabajos a 1 restaurará la ejecución en serie.

Añadirá parallel=jobs o parallel a la variable de entorno DEB_BUILD_OPTIONS lo que permite que los archivos debian/rules opten por usar esta información para sus propios fines. El valor jobs anulará la opción parallel=jobs o parallel en la variable de entorno DEB_BUILD_OPTIONS . Tenga en cuenta que el valor auto será reemplazado por el número real de procesadores activos actualmente, y como tal no se propagará a ningún proceso secundario. Si no se puede inferir el número de procesadores en línea, el código recurrirá a usar la ejecución en serie (desde dpkg 1.18.15), aunque esto solo debería ocurrir en sistemas exóticos y no soportados.

-J, --jobs-try[=jobs|auto]
Esta opción (desde dpkg 1.18.2, opción larga desde dpkg 1.18.8) es equivalente a -j anterior.

Dado que el comportamiento de -j cambió en dpkg 1.21.10 a modo de opt-in, puede usar esta opción en su lugar si necesita garantizar la semántica a través de las series de versiones de dpkg.

--jobs-force[=jobs|auto]
Esta opción (desde dpkg 1.21.10) es equivalente a la opción --jobs excepto que habilitará el modo paralelo forzado, añadiendo la opción make -j con el número calculado de trabajos paralelos a la variable de entorno MAKEFLAGS .

Esto debería hacer que todas las invocaciones subsecuentes de make hereden la opción, forzando así la configuración paralela en el empaquetado (y posiblemente en el sistema de compilación original si usa make(1)) independientemente de su soporte para compilaciones paralelas, lo que podría causar fallos de compilación.

Nota: Cualquier Makefile que no sea seguro para compilaciones paralelas debe considerarse defectuoso. Estos deberían hacerse seguros para compilaciones paralelas, o marcarse como no seguros con el objetivo make(1) .NOTPARALLEL .

-D, --check-builddeps
Comprueba las dependencias y conflictos de compilación; aborta si no se satisfacen (opción larga desde dpkg 1.18.8). Este es el comportamiento predeterminado.
-d, --no-check-builddeps
No comprueba las dependencias y conflictos de compilación (opción larga desde dpkg 1.18.8).
--ignore-builtin-builddeps
No comprueba las dependencias y conflictos de compilación incorporados (desde dpkg 1.18.2). Estas son las dependencias de compilación implícitas específicas de la distribución que normalmente se requieren en un entorno de compilación, el llamado conjunto de paquetes Build-Essential.
--rules-requires-root
No respeta el campo Rules-Requires-Root , recurriendo a su valor predeterminado heredado binary-targets (desde dpkg 1.19.1).
-nc, --no-pre-clean
No limpia el árbol de fuentes antes de compilar (opción larga desde dpkg 1.18.8). Implica -b si no se ha seleccionado nada más entre -F, -g, -G, -B, -A o -S. Implica -d con -S (desde dpkg 1.18.0).
--pre-clean
Limpia el árbol de fuentes antes de compilar (desde dpkg 1.18.8). Este es el comportamiento predeterminado.
-tc, --post-clean
Limpia el árbol de fuentes (usando gain-root-command debian/rules clean) después de que se haya compilado el paquete (opción larga desde dpkg 1.18.8).
--no-post-clean
No limpia el árbol de fuentes después de que se haya compilado el paquete (desde dpkg 1.19.1). Este es el comportamiento predeterminado.
--sanitize-env
Sanea el entorno de compilación (desde dpkg 1.20.0). Esto restablecerá o eliminará variables de entorno, umask y cualquier otro atributo del proceso que podrían afectar adversamente la compilación de paquetes. Debido a que el punto de entrada oficial para compilar paquetes es debian/rules, los paquetes no pueden depender de que estos ajustes estén en su lugar, y por lo tanto deberían funcionar incluso cuando no lo estén. Qué se sanea es específico del proveedor.
-r, --root-command=gain-root-command
Cuando dpkg-buildpackage necesita ejecutar parte del proceso de compilación como root, antepone al comando que ejecuta gain-root-command si se ha especificado uno (opción larga desde dpkg 1.18.8). De lo contrario, si no se ha especificado ninguno, se usará fakeroot por defecto, si el comando está presente. gain-root-command debe empezar con el nombre de un programa en el PATH y recibirá como argumentos el nombre del comando real a ejecutar y los argumentos que debe recibir. gain-root-command puede incluir parámetros (deben estar separados por espacios) pero no meta-caracteres de shell. gain-root-command podría ser típicamente fakeroot, sudo, super o really. su no es adecuado, ya que solo puede invocar el shell del usuario con -c en lugar de pasar los argumentos individualmente al comando que se va a ejecutar.
-R, --rules-file=rules-file
Compilar un paquete de Debian normalmente implica invocar debian/rules como un comando con varios parámetros estándar (desde dpkg 1.14.17, opción larga desde dpkg 1.18.8). Con esta opción es posible usar otra invocación de programa para compilar el paquete (puede incluir parámetros separados por espacios). Alternativamente, se puede usar para ejecutar el archivo de reglas estándar con otro programa make (por ejemplo, usando /usr/local/bin/make -f debian/rules como rules-file).
--check-command=check-command
Comando usado para comprobar el archivo .changes en sí mismo y cualquier artefacto compilado referenciado en el archivo (desde dpkg 1.17.6). El comando debe recibir la ruta del archivo .changes como argumento. Este comando normalmente será lintian.
--check-option=opt
Pasa la opción opt al check-command especificado con DEB_CHECK_COMMAND o --check-command (desde dpkg 1.17.6). Se puede usar varias veces.
--hook-hook-name=hook-command
Establece el código de shell especificado hook-command como el hook hook-name, que se ejecutará en los momentos especificados en los pasos de ejecución (desde dpkg 1.17.6). Los hooks siempre se ejecutarán incluso si la acción siguiente no se realiza (excepto para el hook binary ). Todos los hooks se ejecutarán en el directorio de fuentes descomprimido.

Algunos hooks pueden recibir información adicional a través de variables de entorno (desde dpkg 1.22.0). Todos los hooks reciben el nombre del hook en la DPKG_BUILDPACKAGE_HOOK_NAME variable de entorno (desde dpkg 1.22.0).

Nota: Los ganchos pueden afectar al proceso de compilación y causar fallos de compilación si sus comandos fallan, así que cuidado con las consecuencias no deseadas.

Los nombres de gancho hook-name soportados actualmente son:

preinit
init
preclean
source
Obtiene DPKG_BUILDPACKAGE_HOOK_SOURCE_OPTIONS con las listas de opciones separadas por espacios que se pasarán a la llamada a dpkg-source .
build
Obtiene DPKG_BUILDPACKAGE_HOOK_BUILD_TARGET con el nombre del objetivo debian/rules build que se ha llamado. Antes de dpkg 1.22.7 la variable solo se establecía si el objetivo era llamado.
binary
Obtiene DPKG_BUILDPACKAGE_HOOK_BINARY_TARGET con el nombre del objetivo debian/rules binary que se ha llamado, pero solo si fue llamado.
buildinfo
Obtiene DPKG_BUILDPACKAGE_HOOK_BUILDINFO_OPTIONS con las listas de opciones separadas por espacios que se pasarán a la llamada a dpkg-genbuildinfo .
changes
Obtiene DPKG_BUILDPACKAGE_HOOK_CHANGES_OPTIONS con las listas de opciones separadas por espacios que se pasarán a la llamada a dpkg-genchanges .
postclean
check
Obtiene DPKG_BUILDPACKAGE_HOOK_CHECK_OPTIONS con las listas de opciones separadas por espacios que se pasarán a la llamada al comando de verificación.
sign
done

El hook-command admite el siguiente formato de cadena de sustitución, que se le aplicará antes de la ejecución:

Un carácter % único.
%a
Un valor booleano (0 o 1), que indica si la siguiente acción se está realizando.
%p
El nombre del paquete fuente.
%v

%s
La versión del paquete fuente (sin la época).
%u
La versión upstream.

--buildinfo-option=opt
Pasa la opción opt a dpkg-genbuildinfo (desde dpkg 1.18.11). Se puede usar varias veces.
--sign-backend=sign-backend

El valor por defecto es auto, donde se usará el mejor backend disponible actualmente. Los backends OpenPGP específicos soportados, en orden de preferencia, son:

-p, --sign-command=sign-command
Cuando dpkg-buildpackage necesite ejecutar un comando de backend OpenPGP para firmar un archivo de control de fuentes (.dsc), un .buildinfo o un .changes ejecutará sign-command (buscando en el PATH si es necesario) en lugar del comando de backend por defecto o autodetectado (opción larga desde dpkg 1.18.8). sign-command recibirá todos los argumentos específicos del backend de acuerdo con el --sign-backend seleccionado. sign-command no debe contener espacios ni ningún otro metacarácter del shell.
-k, --sign-keyid=key-id
--sign-key=key-id
Especifica un ID de clave OpenPGP (una huella digital o un ID de usuario) para la clave secreta a usar al firmar paquetes (--sign-key desde dpkg 1.18.8, --sign-keyid desde dpkg 1.21.10).
--sign-keyfile=key-file
Especifica un key-file OpenPGP que contiene la clave secreta a usar al firmar paquetes (desde dpkg 1.21.10).

Nota: Por razones de seguridad es mejor mantener el key-file bloqueado con una contraseña.

-ui, --unsigned-buildinfo

-uc, --unsigned-changes

--no-sign

--force-sign

ENTORNO

Entorno externo

DEB_CHECK_COMMAND
Si está establecido, se usará como el comando para verificar el .changes (desde dpkg 1.17.6). Lo anula la --check-command opción.
DEB_SIGN_KEYID
Si está establecido, se usará para firmar los .changes, .buildinfo y .dsc (desde dpkg 1.17.2). Lo anula la --sign-keyid opción.
DEB_SIGN_KEYFILE
Si está establecido, se usará para firmar los .changes, .buildinfo y .dsc (desde dpkg 1.21.10). Lo anula la --sign-keyfile opción.
DEB_BUILD_OPTIONS
Si está establecido, contendrá una lista de opciones separadas por espacios que afectan al comportamiento de algunas herramientas de dpkg involucradas en la construcción de paquetes, y podría afectar al proceso de construcción del paquete si el código en debian/rules las respeta. Estas opciones pueden tener parámetros especificados inmediatamente después de un signo igual (‘=‘). Para las opciones que admiten múltiples parámetros, estos no se separarán por espacios, ya que estos están reservados para separar opciones.

Las siguientes son las opciones conocidas y soportadas por las herramientas de dpkg, otras opciones respetadas por debian/rules podrían ser definidas por políticas específicas de la distribución.

parallel=N
El debian/rules en el empaquetado podría usar esta opción para configurar el proceso de construcción para usar N trabajos en paralelo. Lo anulan las opciones --jobs y --jobs-force .
nocheck
dpkg-buildpackage ignorará la variable DEB_CHECK_COMMAND . No se espera que el debian/rules en el empaquetado ejecute suites de pruebas durante la construcción.
noopt

OPTIONS

no-parallel
Inhibit parallel builds. It is passed to the make command.
make-args=arg1 arg2 ...
Pass the given arguments to the make command, overriding make arguments passed on the command line. It is possible to specify spaces and shell metacharacters and initial arguments for make. See also dpkg-buildpackage(1) for the behaviour of this option.
build-arch-dep
Build binary package(s) which are architecture dependent and architecture independent.
build-indep
Build binary package(s) which are architecture independent.
build-arch
Build binary package(s) which are architecture dependent.
build
Build binary package(s) which are architecture dependent and architecture independent. This is the default build target.
debian-flavor=flavor
Use the specified package flavor when building the package. See dpkg-buildflags(1) for further details.
dpkg-buildflags
Use dpkg-buildflags to set up the build flags, those will be set to not enable any optimizations.
nostrip
The debian/rules in the packaging should ensure that objects do not get the debugging information stripped. If debian/rules includes the mk/buildtools.mk make fragment the STRIP make variable will respect this option.
terse
dpkg-buildpackage will append the --no-print-directory make(1) flag to the MAKEFLAGS environment variable. The debian/rules in the packaging should reduce verbosity, while not being completely quiet.
hardening=feature-spec
reproducible=feature-spec
abi=feature-spec
future=feature-spec
qa=feature-spec
optimize=feature-spec
sanitize=feature-spec
These are feature areas that control build flag features. See dpkg-buildflags(1) for further details.

Environment variables

DEB_BUILD_PROFILES
If set, it will be used as the active build profile(s) for the package being built (since dpkg 1.17.2). It is a space separated list of profile names. Overridden by the -P option.
DPKG_COLORS
Sets the color mode (since dpkg 1.18.5). The currently accepted values are: auto (default), always and never.
DPKG_NLS
If set, it will be used to decide whether to activate Native Language Support, also known as internationalization (or i18n) support (since dpkg 1.19.0). The accepted values are: 0 and 1 (default).

Internal environment

Even if dpkg-buildpackage exports some variables, debian/rules should not rely on their presence and should instead use the respective interface to retrieve the needed values, because that file is the main entry point to build packages and running it standalone should be supported.

DEB_BUILD_*
DEB_HOST_*
DEB_TARGET_*
dpkg-architecture is called with the -a and -t parameters forwarded. Any variable that is output by its -s option is integrated in the build environment.
DEB_RULES_REQUIRES_ROOT
This variable is set to the value obtained from the Rules-Requires-Root field, the dpkg-build-api level or from the command-line. When set, it will be a valid value for the Rules-Requires-Root field. It is used to notify debian/rules whether the rootless-builds.txt specification is supported.
DEB_GAIN_ROOT_CMD
This variable is set to gain-root-command when the field Rules-Requires-Root is set to a value different to no and binary-targets.
SOURCE_DATE_EPOCH
This variable is set to the Unix timestamp since the epoch of the latest entry in debian/changelog, if it is not already defined.

NOTES

Compiler flags are no longer exported

Between dpkg 1.14.17 and 1.16.1, dpkg-buildpackage exported compiler flags (CFLAGS, CXXFLAGS, FFLAGS, CPPFLAGS and LDFLAGS) with values as returned by dpkg-buildflags. This is no longer the case.

Default build targets

dpkg-buildpackage is using the build-arch and build-indep targets since dpkg 1.16.2. Before dpkg 1.22.7, there was code to try to detect the missing targets and fallback on the build target. Those targets are thus mandatory.

SECURITY

Building binary or source packages should only be performed over trusted source data.

BUGS

It should be possible to specify spaces and shell metacharacters and initial arguments for gain-root-command and sign-command.
