NOMBRE

Dpkg::IPC - funciones auxiliares para IPC

DESCRIPCIÓN

Dpkg::IPC ofrece funciones auxiliares para permitirte ejecutar otros programas de una manera fácil, pero flexible, ocultando todos los detalles tediosos de IPC (Comunicación entre Procesos) de tu vista.

FUNCIONES

$pid = spawn(%opts)
Crea un proceso hijo y ejecuta otro programa en él. Los argumentos se interpretan como un hash de opciones, especificando cómo manejar la entrada y salida del programa a ejecutar. Devuelve el pid del proceso hijo (a menos que se haya proporcionado la opción wait_child).

Cualquier error hará que la función salga con una de las funciones de Dpkg::ErrorHandling.

Opciones:

exec (requerido)
Puede ser un escalar, es decir, el nombre del programa a ejecutar, o una referencia a un array, es decir, el nombre del programa más argumentos adicionales. Ten en cuenta que el programa nunca se ejecutará a través del shell, por lo que no puedes especificar argumentos adicionales en la cadena escalar ni usar ninguna facilidad del shell como globbing.
from_file, to_file, error_to_file
Nombre de archivo como escalar. La entrada/salida/error estándar del proceso hijo se redirigirá al archivo especificado.
from_handle, to_handle, error_to_handle
Filehandle. La entrada/salida/error estándar del proceso hijo se duplicará desde el handle.
from_pipe, to_pipe, error_to_pipe
Referencia a escalar u objeto basado en IO::Handle. Se abrirá una tubería para cada una de las dos opciones y se devolverá el extremo de lectura ("to_pipe" y "error_to_pipe") o el extremo de escritura ("from_pipe") en el escalar referenciado. La entrada/salida/error estándar del proceso hijo se duplicará a los otros extremos de las tuberías.
from_string, to_string, error_to_string
Referencia a escalar. La entrada/salida/error estándar del proceso hijo se redirigirá a la cadena dada como referencia. Ten en cuenta que no sería estrictamente necesario usar una referencia escalar para "from_string", ya que la cadena no se modifica de ninguna manera. Esto se eligió solo por razones de simetría con "to_string" y "error_to_string". "to_string" y "error_to_string" implican la opción "wait_child".
wait_child
Escalar. Si contiene un valor verdadero, se llamará a wait_child() antes de devolver el resultado. El valor de retorno de spawn() será un valor verdadero, no el pid.
nocheck
Escalar. Opción de la llamada a wait_child().
timeout
Escalar. Opción de la llamada a wait_child().
chdir
Escalar. El proceso hijo cambiará de directorio al indicado antes de llamar a exec.
env
Referencia a hash. El proceso hijo poblará %ENV con los elementos del hash antes de llamar a exec. Esto permite exportar variables de entorno.
delete_env
Referencia a array. El proceso hijo eliminará todas las variables de entorno listadas en el array antes de llamar a exec.
sig
Referencia a hash. El proceso hijo poblará %SIG con los elementos del hash antes de llamar a exec. Esto permite configurar las disposiciones de las señales.
delete_sig
Referencia a array. El proceso hijo restablecerá todas las señales listadas en el array a sus disposiciones predeterminadas antes de llamar a exec.
wait_child($pid, %opts)
Toma como primer argumento el pid del proceso al que esperar. Los argumentos restantes se toman como un hash de opciones. No devuelve nada. Falla si el hijo ha sido terminado por una señal o si salió con un código distinto de cero.

Opciones:

cmdline
Cadena para identificar el proceso hijo en los mensajes de error. Por defecto es "proceso hijo".
nocheck
Si es verdadero, no comprueba el estado de retorno del hijo (y por lo tanto no falla si ha sido matado o si salió con un código de retorno distinto de cero).
timeout
Establece un tiempo máximo para esperar al proceso, después de lo cual se matará al proceso y se fallará con un mensaje de error.

CAMBIOS

Versión 1.02 (dpkg 1.18.0)

Opciones cambiadas: wait_child() ahora mata el proceso al alcanzar el 'timeout'.

Versión 1.01 (dpkg 1.17.11)

Nuevas opciones: spawn() ahora acepta 'sig' y 'delete_sig'.

Versión 1.00 (dpkg 1.15.6)

Marca el módulo como público.
