DESCRIPCIÓ

N

El programa dmstats gestiona regiones de estadísticas de E/S para dispositivos que utilizan el controlador device-mapper. Las regiones de estadísticas pueden crearse, eliminarse, listarse e informarse con la

herramienta.

El primer argumento de dmstats es un command

.

El segundo argumento es el device name, uuid o los números major y minor

.

Opciones adicionales permiten la selección de regiones, el control del formato de salida y el comportamiento de los

informes.

Cuando no se proporciona ningún argumento de dispositivo, dmstats operará por defecto sobre todos los dispositivos device-mapper presentes. Los comandos create y delete requieren el uso de --alldevices cuando se u

tilizan de
esta manera.

Esto significa que el grupo se actualizará para reflejar que un nuevo archivo ha sido movido a la misma ruta que el archivo original. Este modo es útil para archivos que se espera sean actualizados mediante unlink y rename.

En el modo follow-path, el demonio salirá si el archivo se elimina y no se reemplaza dentro de un breve intervalo de tolerancia.

eliminado.

COMANDO

S

clear device_name [--allprograms|--programidid] [--allregions|--regionidid]
Indica al kernel que borre los contadores de estadísticas para las regiones especificadas (con la excepción de los contadores de IO en vuelo)

.

create device_name ...|file_path ...|--alldevices [--areasnr_areas|--areasizearea_size] [--boundshistogram_boundaries] [--filemap] [--followfollow_mode] [--foreground] [--nogroup] [--nomonitor] [--precise] [--startstart_sector --lengthlength|--segments] [--userdatauser_data] [--programidid]
Crea una o más nuevas regiones de estadísticas en el(los) dispositivo(s) especificado(s).

La región abarcará todo el dispositivo a menos que se proporcionen --start y --length o --segments. Las opciones --start y --length permiten colocar una región de longitud arbitraria en un desplazamiento arbitrario dentro del dispositivo. La opción --segments hace que se cree una nueva región para cada objetivo en la tabla del dispositivo device-mapper correspondiente.

Si se usa la opción --precise, el comando intentará crear una región usando contadores de precisión de nanosegundos.

Si se proporciona --bounds, se rastreará un histograma de latencia para la nueva región. Los límites de los contenedores del histograma se dan como una lista de valores de latencia separados por comas. Hay un límite inferior implícito de cero en el primer contenedor y un límite superior implícito de infinito (o la duración del intervalo configurado) en el último contenedor.

Las latencias se dan en nanosegundos. Se puede dar un sufijo de unidad opcional de ns, us, ms o s después de cada valor para especificar unidades de nanosegundos, microsegundos, milisegundos o segundos respectivamente, así que por ejemplo, 10 ms es equivalente a 10,000,000. Los valores de latencia con una precisión de menos de un milisegundo solo se pueden usar cuando las marcas de tiempo precisas están habilitadas: si --precise no se da y se usan valores de menos de un milisegundo, se habilitará automáticamente.

Se puede asociar una cadena program_id o user_data opcional con la región. Un program_id puede entonces usarse para seleccionar regiones para operaciones posteriores de lista, impresión e informe. El user_data almacena una cadena arbitraria y no es usada por dmstats ni por el subsistema de estadísticas del kernel del device-mapper.

Por defecto, dmstats crea regiones con un program_id de "dmstats".

En caso de éxito, el region_id de la región recién creada se imprime en stdout.

Si se da la opción --filemap con un archivo regular, o una lista de archivos, como el argumento file_path, en lugar de crear regiones con parámetros especificados en la línea de comandos, dmstats abrirá los archivos ubicados en file_path y creará regiones corresponding a los intervalos físicos asignados al archivo. Esto se puede utilizar para monitorear estadísticas de archivos individuales en el sistema de archivos, por ejemplo, imágenes de máquinas virtuales, áreas de intercambio o archivos grandes de bases de datos.

Para trabajar con la opción --filemap, los archivos deben estar ubicados en un sistema de archivos local, respaldado por un dispositivo device-mapper, que soporte datos de intervalos físicos usando el ioctl FIEMAP (p. ej., Ext4 y XFS).

Por defecto, las regiones que mapean un archivo se colocan en un grupo y el alias del grupo se establece con el nombre base del archivo. Este comportamiento se puede anular con la opción --alias y la opción --nogroup.

La creación de un grupo que mapea un archivo inicia automáticamente un demonio, dmfilemapd(8) para monitorear el archivo y actualizar el mapeo a medida que cambian los intervalos asignados al archivo. Este comportamiento se puede deshabilitar usando la opción --nomonitor.

Use la opción --group para mostrar solo información de los grupos al listar e

informar.

delete device_name|--alldevices [--allprograms|--programidid] [--allregions|--regionidid]
Elimina la región de estadísticas especificada. Todos los contadores y recursos utilizados por la región se liberan y la región no aparecerá en la salida de las operaciones posteriores de listado, impresión o informe.

Todas las regiones registradas en un dispositivo se pueden eliminar usando --allregions.

Para eliminar todas las regiones en todos los dispositivos, se deben usar tanto --allregions como --alldevices.

Si se proporciona un --groupid en lugar de un --regionid, el comando intentará eliminar el grupo y todas las regiones que contiene.

Si la región eliminada es el primer miembro de un grupo de regiones, el grupo también se

eliminará.

group [device_name|--alldevices] [--aliasname] [--regionsregions]
Combina una o más regiones de estadísticas en el dispositivo especificado en un grupo.

La lista de regiones a agrupar se especifica con --regions y se puede asignar un alias opcional con --alias. El conjunto de regiones se da como una lista de identificadores de regiones separados por comas. Un rango continuo de identificadores que abarque desde R1 hasta R2 se puede expresar como'R1-R2'.

Las regiones que tienen un histograma configurado se pueden agrupar: en este caso, el número de intervalos del histograma y sus límites deben coincidir exactamente.

En caso de éxito, la lista de grupos y el group_id recién creado se imprimen en stdout.

Los metadatos del grupo se almacenan con el region_id primero (de menor número) en el grupo: eliminar esta región también eliminará el grupo y los demás miembros del grupo volverán a su estado

anterior.

help [-c|-C|--columns]
Produce un resumen de los comandos disponibles, opcionalmente incluyendo la lista de campos de

informe.

list [device_name] [--allprograms|--programidid] [--area] [--group] [--region] [--histogram] [--nosuffix] [--notimesuffix] [--unitsunits]
Lista las regiones de estadísticas, áreas o grupos registrados en el dispositivo. Si se proporciona la opción --allprograms, se listarán todas las regiones independientemente de los valores del ID de programa de la región.

Por defecto, solo se incluyen regiones y grupos en la salida de la lista. Si se proporciona -v o --verbose, el informe también incluirá una fila de información para cada grupo configurado y para cada área contenida en cada región mostrada.

Las regiones que contienen un solo área se omiten por defecto de la lista detallada, ya que sus propiedades son idénticas a las del área que contienen; para ver todas las regiones independientemente del número de áreas presentes, use --region. Para ver también las áreas contenidas dentro de las regiones, use --area.

Si se proporciona --histogram, el informe incluirá el recuento de intervalos y los valores de límite de latencia para cualquier histograma

configurado.

print [device_name] [--clear] [--allprograms|--programidid] [--allregions|--regionidid]
Imprime los contadores de estadísticas sin procesar para la región especificada o para todas las regiones

presentes.

report [device_name] [--intervalseconds] [--countcount] [--unitsunits] [--allprograms|--programidid] [--allregions|--regionidid] [--area] [--group] [--region] [--histogram] [--nosuffix] [--notimesuffix] [--unitsunits] [-O|--sortsort_fields] [-S|--selectselection]
Inicia un informe para el objeto especificado o para todos los objetos presentes. Si se especifica el argumento count, el informe se repetirá en un intervalo fijo establecido por la opción --interval. El intervalo predeterminado es de un segundo.

Si se proporciona la opción --allprograms, se listarán todas las regiones, independientemente de los valores del ID de programa de la región.

Si se proporciona --histogram, el informe incluirá los valores del histograma y los límites de latencia.

Si se usa --relative, el campo de histograma predeterminado muestra los valores de los intervalos como un porcentaje del número total de E/S.

Los tipos de objetos (áreas, regiones y grupos) a incluir en el informe se seleccionan usando las opciones --area, --region y --group

.

ungroup [device_name|--alldevices] [--groupidid]
Elimina un grupo existente y devuelve todas las regiones del grupo a su estado original.

El grupo a eliminar se especifica usando --groupid

.

update_filemap file_path [--followfollow_mode] [--foreground] [--groupidid] [--nomonitor]
Actualiza un grupo de regiones de dmstats especificado por group_id, que fueron creadas previamente con --filemap, ya sea directamente, o iniciando el demonio de monitoreo dmfilemapd(8).

Esto añadirá y eliminará regiones para reflejar los cambios en los intervalos asignados al archivo en disco, desde el momento en que se creó o se actualizó por última vez.

El uso de este comando normalmente no es necesario, ya que el demonio dmfilemapd(8) monitoreará automáticamente los grupos de filemap y realizará estas actualizaciones cuando sea necesario.

Si un grupo con filemap se creó con --nomonitor, o el demonio ha sido terminado, se puede usar update_filemap para forzar manualmente una actualización o iniciar un nuevo demonio.

Use --nomonitor para forzar una actualización directa y

deshabilitar el inicio del
demonio de monitoreo.

REGIONES, ÁREAS Y

GRUPOS

La funcionalidad de estadísticas de device-mapper permite mantener contadores de rendimiento separados para regiones arbitrarias de los dispositivos. Una región puede abarcar cualquier rango: desde un solo sector hasta todo el dispositivo. Una región puede subdividirse a su vez en un número de áreas distintas (una o más), cada una con su propio conjunto de contadores. En este caso, también está disponible un valor resumen de toda la región para su uso en los

informes.

Además, una o más regiones en un dispositivo se pueden combinar en un grupo de estadísticas. Los grupos permiten que varias regiones se agreguen e informen como una sola entidad; los contadores de todas las regiones y áreas se suman y se usan para informar los totales de todos los miembros del grupo. Los grupos también permiten la asignación de un alias opcional, lo que permite asociar nombres significativos con conjuntos de

regiones.

Los metadatos del grupo se almacenan con el region_id primero (de menor número) en el grupo: eliminar esta región también eliminará el grupo y los demás miembros del grupo volverán a su estado

anterior.

Por defecto, las nuevas regiones abarcan todo el dispositivo. Las opciones --start y --length permiten colocar una región de cualquier tamaño en cualquier ubicación del

dispositivo.

Usando desplazamientos, es posible crear regiones que mapeen objetos individuales dentro de un dispositivo de bloque (por ejemplo: particiones, archivos en un sistema de archivos, o bandas u otras estructuras en un volumen RAID). Los grupos permiten ensamblar varias regiones no contiguas para su informe y agregación de

datos.

Una región se puede dividir en el número especificado de áreas de tamaño igual, o en áreas del tamaño dado especificando una de las opciones --areas o --areasize al crear una región con el comando create. Dependiendo del tamaño de las áreas y de la región del dispositivo, el área final dentro de la región puede ser más pequeña de lo

solicitado.

Identificadores de

regiones

A cada región se le asigna un identificador cuando se crea, que se usa para referenciar la región en operaciones posteriores. Los identificadores de regiones son únicos dentro de un dispositivo dado (incluyendo a través de diferentes valores de program_id)

.

Dependiendo de la secuencia de operaciones de creación y eliminación, pueden existir huecos en la secuencia de valores de region_id para un dispositivo en

particular.

El region_id debe tratarse como un identificado

r opaco usado para
referenciar la región.

Identificadores de

grupos

A los grupos también se les asigna un identificador entero en el momento de la creación; al igual que los identificadores de regiones, los identificadores de grupos son únicos dentro del dispositivo que los

contiene.

El group_id debe tratarse como un iden

tificador opaco u
sado para refe
renciar el grupo.

MAPEO DE

ARCHIVOS

Usando --filemap, es posible crear regiones que correspondan a los intervalos de un archivo en el sistema de archivos. Esto permite monitorear estadísticas de E/S a nivel de archivo, por ejemplo, para observar archivos grandes de bases de datos, imágenes de máquinas virtuales u otros archivos de

interés.

Para poder usar el mapeo de archivos, el archivo debe estar respaldado por un dispositivo device-mapper, y en un sistema de archivos que soporte el ioctl FIEMAP (y que devuelva datos que describan la ubicación física de los intervalos). Esto incluye actualmentees xfs(5) y ext4(

5).

Por defecto, las regiones que componen un archivo se colocan juntas en un grupo, y el alias del grupo se establece con el nombre base (basename(3)) del archivo. Esto permite informar estadísticas para el archivo como un todo, agregando los valores de las regiones que componen el grupo. Para ver solo el archivo completo (grupo) al usar los comandos list y report, utilice --group

.

Dado que es posible que el archivo cambie después de que se crea el grupo inicial de regiones, se proporcionan el comando update_filemap y el demonio dmfilemapd(8) para actualizar los grupos de archivos mapeados ya sea manual o automáticamente

.

Modos de seguimiento de

archivos

El demonio de monitoreo de mapas de archivos puede monitorear archivos de dos maneras distintas: modo follow-inode y modo

follow-path.

El modo afecta el comportamiento del demonio cuando un archivo bajo monitoreo es renombrado o desvinculado, y las condiciones que hacen que el demonio

termine.

Si se usa el modo follow-inode, el demonio mantendrá el archivo abierto y continuará actualizando las regiones desde el mismo descriptor de archivo. Esto significa que el mapeo seguirá las operaciones de renombrar, mover (dentro del mismo sistema de archivos) y desvincular. Este modo es útil si se espera que el archivo sea movido, renombrado o desvinculado mientras está siendo

monitoreado.

En el modo follow-inode, el demonio saldrá una vez que detecte que el archivo ha sido desvinculado y que es el último poseedor de una referencia a

él.

Si se usa follow-path, el demonio reabrirá la ruta proporcionada en cada iteración de monitoreo. Esto significa que el grupo se actualizará para reflejar un nuevo archivo movido a la misma ruta que el archivo original. Este modo es útil para archivos que se espera que sean actualizados mediante unlink y

rename.

En el modo follow-path, el demonio saldrá si el archivo es eliminado y no reemplazado dentro de un breve intervalo de tolerancia (un segundo)

.

Para detener el demonio, elimine el grupo que contiene las regiones mapeadas: el demonio se apagará automáticamente

.

El demonio también puede ser terminado de forma segura en cualquier momento y el grupo conservado: si el archivo sigue siendo asignado, el mapeo se volverá progresivamente obsoleto a medida que se añaden y eliminan extensiones (en este caso, el demonio puede reiniciarse o el grupo actualizarse manualmente con el comando update_filemap)

.

Consulte el comando create y las opciones --filemap, --follow y --nomonitor para

más info
rmación.

Limitacione

s

El demonio intenta mantener una buena sincronización entre las extensiones del archivo y las regiones contenidas en el grupo; sin embargo, como solo puede reaccionar a nuevas asignaciones una vez que se han escrito, inevitablemente hay algunos eventos de E/S que no pueden ser contados cuando un archivo está creciendo, particularmente si el archivo está siendo extendido por un solo hilo que escribe más allá del final del archivo (por ejemplo, el programa dd(1))

.

Hay una pérdida adicional de eventos en que actualmente no existe una forma de redimensionar atómicamente una región de dmstats y preservar sus valores de contador actuales. Esto afecta a los archivos cuando crecen extendiendo la extensión final, en lugar de asignar una nueva extensión: cualquier evento que se haya acumulado en la región entre cualquier operación previa y el redimensionamiento se

pierde.

El mapeo de archivos es actualmente más efectivo en los cas

os en que la mayoría de la E/S no desencadena la asigna
ción de extensiones. Actualizaciones futuras podrían a
bordar estas limitaciones cuando haya soporte en el kernel.
