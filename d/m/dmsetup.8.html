DESCRIPCIÓN

dmsetup gestiona dispositivos lógicos que utilizan el controlador device-mapper. Los dispositivos se crean cargando una tabla que especifica un objetivo para cada sector (512 bytes) en el dispositivo lógico.

El primer argumento de dmsetup es un comando. El segundo argumento es el nombre o uuid del dispositivo lógico.

Invocar la herramienta dmsetup como devmap_name (que no se distribuye normalmente y solo se admite por razones históricas) es equivalente a dmsetup info -c --noheadings -j major -m minor.

OPCIONES

--addnodeoncreate
Asegura que el nodo /dev/mapper exista después de dmsetup create.
--addnodeonresume
Asegura que el nodo /dev/mapper exista después de dmsetup resume (predeterminado con udev).
--checks
Realiza comprobaciones adicionales sobre las operaciones solicitadas e informa posibles problemas. Útil al depurar scripts. En algunos casos estas comprobaciones pueden ralentizar notablemente las operaciones.
-c|-C|--columns
Muestra la salida en columnas en lugar de como líneas Campo: Valor.
--count count
Especifica el número de veces que se repetirá un informe. Establécelo a cero para continuar hasta que se interrumpa. El intervalo predeterminado es de un segundo.
-f|--force
Intenta con más ahínco completar la operación.
-h|--help
Muestra un resumen de los comandos disponibles, incluyendo opcionalmente la lista de campos de informe (sinónimo del comando help).
--inactive
Al devolver cualquier información de tabla desde el kernel, informa sobre la tabla inactiva en lugar de la tabla activa. Requiere la versión 4.16.0 o superior del controlador del kernel.
--interval seconds
Especifica el intervalo en segundos entre iteraciones sucesivas para repetir informes. Si se especifica --interval pero no --count, los informes continuarán repitiéndose hasta que se interrumpa. El intervalo predeterminado es de un segundo.
--manglename auto|hex|none
Transforma cualquier carácter que no esté en una lista blanca usando mangling_mode al procesar nombres y UUID de dispositivos device-mapper. Los nombres y UUID se transforman en la entrada y se restauran en la salida, donde el modo de transformación es uno de: auto (solo transforma si aún no está transformado, no hace nada si ya está transformado, error si es mixto), hex (siempre transforma) y none (sin transformación). El modo predeterminado es auto. Lista blanca de caracteres: 0–9, A–Z, a–z, #+-.:=@_. Esta lista blanca también es compatible con udev. Cualquier carácter que no esté en la lista blanca se reemplaza con su valor hexadecimal (dos dígitos) precedido por \x. El modo de transformación también se puede establecer usando la variable de entorno DM_DEFAULT_NAME_MANGLING_MODE.
-j| --major major
Especifica el número mayor.
-m|--minor minor
Especifica el número menor.
-n|--notable
Al crear un dispositivo, no carga ninguna tabla.
--nameprefixes
Añade un prefijo "DM_" más el nombre del campo a la salida. Útil con --noheadings para producir una lista de pares campo=valor que pueden usarse para establecer variables de entorno (por ejemplo, en reglas de udev(7)).
--noheadings
Suprime la línea de encabezados al usar salida en columnas.
--headings none|abbrev|full|0|1|2
Tipo de línea de encabezados a usar para la salida en columnas.
none o 0 – Sin encabezados.
abbrev o 1 – Abreviaturas de nombres de columna.
full o 2 – Nombres completos de columna.
--noflush
No vacía la E/S pendiente al suspender un dispositivo, o no confirma los metadatos de thin-pool al obtener el estado de thin-pool.
--nolockfs
No intenta sincronizar el sistema de archivos, p. ej., al suspender un dispositivo.
--noopencount
Indica al kernel que no proporcione el recuento de referencias abiertas para el dispositivo.
--noudevrules
No permite que udev gestione los nodos de los dispositivos en el directorio device-mapper.
--noudevsync
No sincroniza con udev al crear, renombrar o eliminar dispositivos.
-o|--options options
Especifica qué campos mostrar.
--readahead [+]sectors|auto|none
Especifica el tamaño de lectura anticipada en unidades de sectores. El valor predeterminado es auto, que permite al kernel elegir un valor adecuado automáticamente. El prefijo + permite especificar un valor mínimo que no se usará si es menor que el valor elegido por el kernel. El valor none equivale a especificar cero.
-r|--readonly
Establece la tabla que se carga como de solo lectura.
-S|--select selection
Procesa solo los elementos que coinciden con los criterios de selection. Si el comando produce salida de informe, añadir la columna "selected" (-o selected) muestra todas las filas e indica 1 si la fila coincide con la selection y 0 en caso contrario. Los criterios de selección se definen especificando nombres de columna y sus valores válidos mientras se usan los operadores de comparación admitidos. Como ayuda rápida y para ver la lista completa de nombres de columna que pueden usarse en la selección y el conjunto de operadores de selección admitidos, consulta la salida del comando dmsetup info -c -S help.
--table table
Especifica una tabla de una línea directamente en la línea de comandos. Consulta más abajo para más información sobre el formato de tabla.
--udevcookie cookie
Usa una cookie para la sincronización con udev.
Nota: debe usarse la misma cookie para el mismo tipo de operaciones, es decir, la creación de múltiples dispositivos diferentes. No se recomienda combinar diferentes operaciones sobre un mismo dispositivo.
-u|--uuid uuid
Especifica el uuid.
-y|--yes
Responde sí a todas las preguntas automáticamente.
-v|--verbose [-v|--verbose]
Produce salida adicional. Repite hasta 4 veces (-vvvv) para aumentar el detalle: -vv habilita mensajes de depuración, -vvv añade el tiempo transcurrido después de cada ioctl, -vvvv añade el archivo fuente y los números de línea.
--verifyudev
Si la sincronización con udev está habilitada, verifica que las operaciones de udev se realicen correctamente e intenta corregir los nodos de dispositivo después si no es así.
--version
Muestra la versión de la biblioteca y del controlador del kernel.

COMMANDS

clear device_name
Destroys the table in the inactive table slot for device_name.

create device_name [-n|--notable|--table table|table_file] [--readahead [+]sectors|auto|none] [-u|--uuid uuid] [--addnodeoncreate|--addnodeonresume]
Creates a device with the given name. If table or table_file is supplied, the table is loaded and made live. Otherwise a table is read from standard input unless --notable is used. The optional uuid can be used in place of device_name in subsequent dmsetup commands. If successful, the device will appear in the table, and for the live device, the node /dev/mapper/device_name is created. See below for more information on the table format.

create --concise [concise_device_specification]
Creates one or more devices from a concise device specification. Each device is specified by a comma-separated list: name, uuid, minor number, flags, comma-separated table lines. Flags default to read-write (rw) or may be read-only (ro). Uuid, minor number and flags are optional so those fields may be empty. A semi-colon separates specifications of different devices. Use a backslash to escape the following character, for example a comma or semi-colon in a name or table. See also CONCISE FORMAT below.

deps [-o options] [device_name ...]
Outputs a list of devices referenced by the live table for the specified device. Device names on output can be customised by the following options: devno (major and minor pair, used by default), blkdevname (block device name), devname (map name for device-mapper devices, equal to blkdevname otherwise).

help [-c|-C|--columns]
Outputs a summary of the commands available, optionally including the list of report fields.

info [device_name ...]
Outputs some brief information about the device in the form:

State: SUSPENDED|ACTIVE, READ-ONLY
Read Ahead: sectors
Tables present: LIVE and/or INACTIVE
Open reference count
Last event sequence number (used by wait)
Major and minor device number
Number of targets in the live table
UUID

info -c|-C|--columns [--count count] [--interval seconds] [--noheadings|--headings none|abbrev|full|0|1|2] [-o fields] [-O|--sort sort_fields] [--nameprefixes] [--separator separator] [device_name]
Output that can be customised. Fields are comma-separated and chosen from the following list: name, major, minor, attr, open, segments, events, uuid. Attributes are: (L)ive, (I)nactive, (s)uspended, (r)ead-only, read-(w)rite. Precede the list with '+' to append to the default selection of columns instead of replacing it. Precede any sort field with '-' for a reverse sort on that column.

ls [--target target_type] [-o options] [--exec command] [--tree]
List device names. Optionally only list devices that have at least one target of the specified type. Optionally execute a command for each device. The device name is appended to the supplied command. Device names on output can be customised by the following options: devno (major and minor pair, used by default), blkdevname (block device name), devname (map name for device-mapper devices, equal to blkdevname otherwise). --tree displays dependencies between devices as a tree. It accepts a comma-separated list of options. Some specify the information displayed against each node: device / nodevice; blkdevname; active, open, rw, uuid. Others specify how the tree is displayed: ascii, utf, vt100; compact, inverted, notrunc.

reload device_name [--table table|table_file]
Loads table or table_file into the inactive table slot for device_name. If neither is supplied, reads a table from standard input.

mangle [device_name ...]
Ensure existing device-mapper device_name and UUID are in the correct mangled form containing only whitelisted characters (supported by udev) and do a rename if necessary. Any character not on the whitelist will be mangled based on the --manglename setting. Automatic rename works only for device names and not for device UUIDs because the kernel does not allow changing the UUID of active devices. Any incorrect UUIDs are reported only and they must be manually corrected by deactivating the device first and then reactivating it with the proper mangling mode (see also --manglename).

measure [device_name ...]
Show the data that device_name would report to the IMA subsystem if a measurement was triggered at the current time. This is for debugging and does not actually trigger a measurement.

message device_name sector message
message Send a message to the target. If no sector is needed, use 0.

mknodes [device_name ...]
Ensure that the node in /dev/mapper for device_name is correct. If no device_name is supplied, ensure that all nodes in /dev/mapper correspond to mapped devices currently loaded by the device-mapper kernel driver, adding, changing or removing nodes as necessary.

remove [-f|--force] [--retry] [--deferred] device_name ...
Removes a device. It will no longer be visible to dmsetup. Open devices cannot be removed, but adding --force will replace the table with one that fails all I/O. --deferred will enable deferred removal of open devices - the device will be removed when the last user closes it. The deferred removal feature is supported since version 4.27.0 of the device-mapper driver available in upstream kernel version 3.13. (Use dmsetup version to check this.) If an attempt to remove a device fails, perhaps because a process run from a quick udev rule temporarily opened the device, the --retry option will cause the operation to be retried for a few seconds before failing. Do NOT combine --force and --udevcookie, as udev may start to process udev rules in the middle of error target replacement and result in nondeterministic behavior.

remove_all [-f|--force] [--deferred]
Attempts to remove all device definitions i.e. reset the driver. This also runs mknodes afterwards. Use with care! Open devices cannot be removed, but adding --force will replace the table with one that fails all I/O. --deferred will enable deferred removal of open devices - the device will be removed when the last user closes it. The deferred removal feature is supported since version 4.27.0 of the device-mapper driver available in upstream kernel version 3.13.

rename device_name new_name
Renames a device.

rename device_name --setuuid uuid
Sets the UUID of a device that was created without a UUID. After a UUID has been set it cannot be changed.

resume device_name ... [--addnodeoncreate|--addnodeonresume] [--noflush] [--nolockfs] [--readahead [+]sectors|auto|none]
Un-suspends a device. If an inactive table has been loaded, it becomes live. Postponed I/O then gets re-queued for processing.

setgeometry device_name cyl head sect start
Sets the device geometry to C/H/S.

splitname device_name [subsystem]
Splits the given device name into subsystem constituents. The default subsystem is LVM. LVM currently generates device names by concatenating the names of the Volume Group, Logical Volume and any internal layer with a hyphen as separator. Any hyphens within the names are doubled to escape them. The precise encoding might change without notice in any future release, so we recommend you always decode using the current version of this command.

stats command [options]
Manages IO statistics regions for devices. See dmstats(8) for more details.

status [--target target_type] [--noflush] [device_name ...]
Outputs status information for each of the device's targets. With --target, only information relating to the specified target type is displayed. With --noflush, the thin target (from version 1.3.0) doesn't commit any outstanding changes to disk before reporting its statistics.

suspend device_name ... [--nolockfs] [--noflush]
Suspends a device. Any I/O that has already been mapped by the device but has not yet completed will be flushed. Any further I/O to that device will be postponed for as long as the device is suspended. If there's a filesystem on the device which supports the operation, an attempt will be made to sync it first unless --nolockfs is specified. Some targets such as recent (October 2006) versions of multipath may support the --noflush option. This lets outstanding I/O that has not yet reached the device to remain unflushed.

table [--concise] [--target target_type] [--showkeys] [device_name ...]
Outputs the current table for the device in a format that can be fed back in using the create or load commands. With --target, only information relating to the specified target type is displayed. Real encryption keys are suppressed in the table output for crypt and integrity targets unless the --showkeys parameter is supplied. Kernel key references prefixed with : are not affected by the parameter and are always displayed (crypt target only). With --concise, the output is presented concisely on a single line. Commas separate the name, uuid, minor device number, flags ('ro' or 'rw') and the table (if present). Semi-colons separate devices. Backslashes escape any commas, semi-colons or backslashes. See CONCISE FORMAT below.

targets
Displays the names and versions of the currently-loaded targets.

udevcomplete cookie
Wake any processes that are waiting for udev to complete processing the specified cookie.

udevcomplete_all [age_in_minutes]
Remove all cookies older than the specified number of minutes. Any process waiting on a cookie will be resumed immediately.

udevcookie
List all existing cookies. Cookies are system-wide semaphores with keys prefixed by two predefined bytes (0x0D4D).

udevcreatecookie
Creates a new cookie to synchronize actions with udev processing. The output is a cookie value. Normally we don't need to create cookies since dmsetup creates and destroys them for each action automatically. However, we can generate one explicitly to group several actions together and use only one cookie instead. We can define a cookie to use for each relevant command by using the --udevcookie option. Alternatively, we can export this value into the environment of the dmsetup process as DM_UDEV_COOKIE variable and it will be used automatically with all subsequent commands until it is unset. Invoking this command will create a system-wide semaphore that needs to be cleaned up explicitly by calling udevreleasecookie command.

udevflags cookie
Parses the given cookie value and extracts any encoded udev control flags. The output is in environment key format that is suitable for use in udev rules. If the flag has its symbolic name assigned then the output is DM_UDEV_FLAG_<flag_name> = '1', DM_UDEV_FLAG<flag_position> = '1' otherwise. Subsystem udev flags don't have symbolic names assigned and they are always reported as DM_SUBSYSTEM_UDEV_FLAG<flag_position> = '1'. There are 16 udev flags altogether.

udevreleasecookie [cookie]
Waits for all pending udev processing bound to the given cookie value and releases the underlying semaphore. If the cookie is not given directly, the command will try to use a value defined by DM_UDEV_COOKIE environment variable.

version
Outputs version information.

wait device_name [--noflush] [event_nr]
Sleeps until the event counter for device_name exceeds event_nr. Use -v to see the event number returned. To wait until the next event is triggered, use info to find the last event number. With --noflush, the thin target (from version 1.3.0) doesn't commit any outstanding changes to disk before reporting its statistics.

wipe_table device_name ... [-f|--force] [--noflush] [--nolockfs]
Wait for any I/O in-flight through the device to complete, then replace the table with a new table that fails any new I/O sent to the device. If successful, this should release any devices held open by the device's table(s).

FORMATO DE TABLA

Cada línea de la tabla especifica un único destino y tiene la forma:

sector_inicial_lógico num_sectores tipo_de_destino argumentos_del_destino

Los tipos de destino simples y los argumentos de destino incluyen:

linear dispositivo_destino sector_inicial
La asignación lineal tradicional.

striped num_franjas tamaño_de_bloque [dispositivo_destino sector_inicial] ...
Crea un área con franjas.
p. ej., striped 2 32 /dev/hda1 0 /dev/hdb1 0 asignará el primer bloque (16 KiB) de la siguiente manera:

Bloque LV 1 → hda1, bloque 1
Bloque LV 2 → hdb1, bloque 1
Bloque LV 3 → hda1, bloque 2
Bloque LV 4 → hdb1, bloque 2
etc.
error
Genera errores en cualquier E/S que vaya a esta área. Útil para pruebas o para crear dispositivos con huecos.
zero
Devuelve bloques de ceros en las lecturas. Cualquier dato escrito se descarta silenciosamente. Este es el equivalente en dispositivo de bloque del sumidero de datos del dispositivo de caracteres /dev/zero descrito en null(4).

Los destinos más complejos incluyen:

cache
Mejora el rendimiento de un dispositivo de bloque (p. ej., un disco) migrando dinámicamente algunos de sus datos a un dispositivo más rápido y más pequeño (p. ej., un SSD).
crypt
Cifrado transparente de dispositivos de bloque usando la API criptográfica del kernel.
delay
Retrasa las lecturas y/o escrituras a diferentes dispositivos. Útil para pruebas.
flakey
Crea una asignación similar al destino linear pero presenta un comportamiento poco fiable periódicamente. Útil para simular dispositivos defectuosos durante las pruebas.
mirror
Replica datos en dos o más dispositivos.
multipath
Media el acceso a través de múltiples rutas al mismo dispositivo.
raid
Ofrece una interfaz al controlador de raid por software del kernel, md.
snapshot
Admite instantáneas de dispositivos.
thin, thin-pool
Admite aprovisionamiento fino de dispositivos y también proporciona una mejor compatibilidad con instantáneas.

Para obtener más información sobre los distintos destinos y sus formatos de tabla y líneas de estado, lea los archivos en el directorio Documentation/admin-guide/device-mapper del árbol de fuentes del kernel. (Su distribución podría incluir una copia de esta información en el directorio de documentación del paquete device-mapper.)

EJEMPLOS

# Una tabla para unir dos discos
0 1028160 linear /dev/hda 0
1028160 3903762 linear /dev/hdb 0

# Una tabla para distribuir en franjas entre los dos discos,
# y añadir el espacio libre de
# hdb al final del volumen
0 2056320 striped 2 32 /dev/hda 0 /dev/hdb 0
2056320 2875602 linear /dev/hdb 1028160

FORMATO CONCISO

Una representación concisa de uno o más dispositivos:

  • Una coma separa los campos de cada dispositivo.
  • Un punto y coma separa los dispositivos.

La representación de un dispositivo toma la forma:

<nombre>,<uuid>,<menor>,<indicadores>,<tabla>[,<tabla>+][;<nombre>,<uuid>,<menor>,<indicadores>,<tabla>[,<tabla>+]]

Los campos son:

nombre
El nombre del dispositivo.
uuid
El UUID del dispositivo (o vacío).
menor
El número menor del dispositivo. Si está vacío, el kernel asigna un número menor adecuado.
indicadores
Los indicadores admitidos son:
ro
Establece la tabla que se carga para el dispositivo como de solo lectura
rw
Establece la tabla que se carga para el dispositivo como de lectura-escritura (predeterminado)
tabla
Una línea de la tabla. Consulte FORMATO DE TABLA más arriba.

EJEMPLOS

# Un dispositivo lineal simple de solo lectura
test-linear-small,,,ro,\
 0 2097152 linear /dev/loop0 0,\
 2097152 2097152 linear /dev/loop1 0

# Dos dispositivos lineales
test-linear-small,,,,\
 0 2097152 linear /dev/loop0 0;\
 test-linear-large,,,,\
 0 2097152 linear /dev/loop1 0,\
 2097152 2097152 linear /dev/loop2 0

VARIABLES DE ENTORNO

DM_DEV_DIR
El nombre del directorio de dispositivos. Por defecto es "/dev" y debe ser una ruta absoluta.
DM_UDEV_COOKIE
Una cookie que se usará para todos los comandos relevantes para sincronizar con el procesamiento de udev. Es una alternativa al uso de la opción --udevcookie.
DM_DEFAULT_NAME_MANGLING_MODE
Un modo de modificación de nombres predeterminado. Por defecto es "auto". Es una alternativa al uso de la opción --manglename.
DM_DEBUG_WITH_LINE_NUMBERS
Establezca en 1 para anteponer el archivo fuente y el número de línea a los mensajes de depuración. Se habilita automáticamente con -vvvv.
