DESCRIPCIÓ

N

dmsetup gestiona dispositivos lógicos que utilizan el controlador device-mapper. Los dispositivos se crean cargando una tabla que especifica un destino para cada sector (512 bytes) en el dispositivo

lógico.

El primer argumento de dmsetup es un comando. El segundo argumento es el nombre o uuid del dispositivo

lógico.

Invocar la herramienta dmsetup como devmap_name (que normalmente no se distribuye y se soporta solo por razones históricas) es equivalente a dmsetup info -c --noheadings -j major -m minor

.

Nombre

dmsetup - Controlar dispositivos de mapeo de dispositivos (device mapper)

SINOPSIS

dmsetup [-r] [-v[v]] [-S <target_cache_size>] [-a <al_cache_size>] [-W <map_cache_size>] [-m] [-p] [--udev-dir <dir>] [--no-dm-lock] [--dm-lock-holder <id>] [--dm-lock-timeout <secs>] [-H <hash_size>] [-w] [--plt <num>] [-h | --help] [-V | --version] command [command_args...]

COMANDOS

Los comandos y sus argumentos son los siguientes:

create <device_name> [--udevcookie <cookie>] [--addnodeoncreate] [--addnodeonresume] [--noflush] [--nolockfs] [--readahead [+]<sectors>|auto|none]
Crea un dispositivo de mapeo de dispositivos con el nombre especificado. El dispositivo se define mediante una tabla de destinos que se lee del entrada estándar. Consulte la sección TABLE FORMAT para ver el formato de la tabla. El nombre del dispositivo se puede pasar a través de la opción --udevcookie.
device_state <device_name> [--setstate <state>]
Muestra el estado del dispositivo especificado. Si se utiliza --setstate, el estado se puede cambiar. Los estados válidos son active, inactive, unknown. El estado se puede utilizar para controlar el comportamiento de la suspensión/reanudación.
deps [--showkeys]
Muestra las dependencias de todos los dispositivos definidos actualmente. Con --showkeys, las claves de cifrado reales se suprimen para los destinos criptográficos a menos que se proporcione el parámetro --showkeys.
events [--interval <secs>]
Muestra información sobre los eventos recientes del dispositivo de mapeo. Con --interval, se muestran los eventos que han ocurrido dentro del intervalo de tiempo especificado.
info [--showkeys] [device_name ...]
Muestra información detallada sobre el dispositivo o dispositivos especificados. Con --showkeys, las claves de cifrado reales se suprimen para los destinos criptográficos a menos que se proporcione el parámetro --showkeys.
load [-f|--force] [--retry] [--deferred] [--udevcookie <cookie>] [--addnodeoncreate|--addnodeonresume] [--noflush] [--nolockfs] [--readahead [+]<sectors>|auto|none] device_name [table_file]
Carga una nueva tabla de dispositivos de mapeo de dispositivos. Si no se especifica table_file, la tabla se lee de la entrada estándar. Se pueden especificar opciones para anular el comportamiento por defecto de udev. La opción --deferred permite la eliminación diferida de dispositivos abiertos; el dispositivo se eliminará cuando el último usuario lo cierre. La característica de eliminación diferida es compatible desde la versión 4.27.0 del controlador device-mapper disponible en la versión 3.13 del kernel upstream. (Utilice dmsetup version para comprobarlo). La opción --retry reintentará la operación durante unos segundos antes de fallar si la eliminación falla, quizás porque un proceso lanzado desde una regla udev rápida abrió temporalmente el dispositivo. NO combine --force y --udevcookie, ya que udev podría empezar a procesar reglas udev en medio del reemplazo del destino de error y dar lugar a un resultado no determinista.
message <device_name> <sector> <message>
Envía un mensaje al destino especificado. Si el sector no es necesario, utilice 0.
mknodes [device_name ...]
Asegura que el nodo en /dev/mapper para device_name sea correcto. Si no se suministra ningún device_name, asegura que todos los nodos en /dev/mapper correspondan a los dispositivos mapeados cargados actualmente por el controlador device-mapper del kernel, añadiendo, modificando o eliminando nodos según sea necesario.
remove [-f|--force] [--retry] [--deferred] <device_name> ...
Elimina un dispositivo. Ya no será visible para dmsetup. Los dispositivos abiertos no se pueden eliminar, pero añadir --force reemplazará la tabla por una que falle todas las E/S. --deferred habilitará la eliminación diferida de dispositivos abiertos; el dispositivo se eliminará cuando el último usuario lo cierre. La característica de eliminación diferida es compatible desde la versión 4.27.0 del controlador device-mapper disponible en la versión 3.13 del kernel upstream. (Utilice dmsetup version para comprobarlo). Si un intento de eliminar un dispositivo falla, quizás porque un proceso lanzado desde una regla udev rápida abrió temporalmente el dispositivo, la opción --retry hará que la operación se reintente durante unos segundos antes de fallar. NO combine --force y --udevcookie, ya que udev podría empezar a procesar reglas udev en medio del reemplazo del destino de error y dar lugar a un resultado no determinista.
remove_all [-f|--force] [--deferred]
Intenta eliminar todas las definiciones de dispositivos, es decir, restablecer el controlador. Esto también ejecuta mknodes después. ¡Úselo con cuidado! Los dispositivos abiertos no se pueden eliminar, pero añadir --force reemplazará la tabla por una que falle todas las E/S. --deferred habilitará la eliminación diferida de dispositivos abiertos; el dispositivo se eliminará cuando el último usuario lo cierre. La característica de eliminación diferida es compatible desde la versión 4.27.0 del controlador device-mapper disponible en la versión 3.13 del kernel upstream.
rename <device_name> <new_name>
Renombra un dispositivo.
rename <device_name> --setuuid <uuid>
Establece el uuid de un dispositivo que fue creado sin uuid. Una vez establecido un uuid, no se puede cambiar.
resume <device_name> ... [--addnodeoncreate|--addnodeonresume] [--noflush] [--nolockfs] [--readahead [+]<sectors>|auto|none]
Reanuda un dispositivo. Si se cargó una tabla inactiva, esta se vuelve activa. Las E/S pospuestas se vuelven a encolar para su procesamiento.
setgeometry <device_name> <cyl> <head> <sect> <start>
Establece la geometría del dispositivo a C/H/S.
splitname <device_name> [subsystem]
Divide el device name dado en sus constituyentes de subsystem. El subsistema predeterminado es LVM. LVM genera actualmente nombres de dispositivo concatenando los nombres del Grupo de Volúmenes, Volumen Lógico y cualquier capa interna con un guion como separador. Cualquier guion dentro de los nombres se duplica para escaparlos. La codificación precisa puede cambiar sin previo aviso en cualquier versión futura, por lo que recomendamos decodificar siempre utilizando la versión actual de este comando.
stats <command> [options]
Gestiona regiones de estadísticas de E/S para dispositivos. Consulte dmstats(8) para más detalles.
status [--target <target_type>] [--noflush] [device_name ...]
Muestra información de estado para cada uno de los destinos del dispositivo. Con --target, solo se muestra información relacionada con el tipo de destino especificado. Con --noflush, el destino thin (a partir de la versión 1.3.0) no confirma los cambios pendientes en disco antes de informar sus estadísticas.
suspend <device_name> ... [--nolockfs] [--noflush]
Suspende un dispositivo. Cualquier E/S que ya haya sido mapeada por el dispositivo pero que no se haya completado se vaciará. Cualquier E/S adicional a ese dispositivo se pospondrá mientras el dispositivo esté suspendido. Si hay un sistema de archivos en el dispositivo que admita la operación, se intentará sincronizarlo primero a menos que se especifique --nolockfs. Algunos destinos, como las versiones recientes (octubre de 2006) de multipath, pueden admitir la opción --noflush. Esto permite que las E/S pendientes que aún no han llegado al dispositivo permanezcan sin vaciar.
table [--concise] [--target <target_type>] [--showkeys] [device_name ...]
Muestra la tabla actual del dispositivo en un formato que puede ser alimentado de nuevo utilizando los comandos create o load. Con --target, solo se muestra información relacionada con el tipo de destino especificado. Las claves de cifrado reales se suprimen en la salida de la tabla para los destinos crypt e integrity a menos que se proporcione el parámetro --showkeys. Las referencias de clave del kernel prefijadas con : no se ven afectadas por el parámetro y se muestran siempre (solo destino crypt). Con --concise, la salida se presenta de forma concisa en una sola línea. Las comas separan el nombre, uuid, número de dispositivo menor, flags ('ro' o 'rw') y la tabla (si está presente). Los puntos y comas separan los dispositivos. Las barras invertidas escapan cualquier coma, punto y coma o barra invertida. Consulte FORMATO CONCISO a continuación.
targets
Muestra los nombres y versiones de los destinos cargados actualmente.
udevcomplete <cookie>
Activa cualquier proceso que esté esperando a que udev complete el procesamiento de la cookie especificada.
udevcomplete_all [age_in_minutes]
Elimina todas las cookies con una antigüedad superior al número de minutos especificado. Cualquier proceso que espere una cookie será reanudado inmediatamente.
udevcookie
Lista todas las cookies existentes. Las cookies son semáforos de ámbito sistémico con claves prefijadas por dos bytes predefinidos (0x0D4D).
udevcreatecookie
Crea una nueva cookie para sincronizar acciones con el procesamiento de udev. La salida es un valor de cookie. Normalmente no necesitamos crear cookies ya que dmsetup las crea y destruye automáticamente para cada acción. Sin embargo, podemos generar una explícitamente para agrupar varias acciones y usar solo una cookie en su lugar. Podemos definir una cookie para usar en cada comando relevante utilizando la opción --udevcookie. Alternativamente, podemos exportar este valor al entorno del proceso dmsetup como la variable DM_UDEV_COOKIE y se utilizará automáticamente con todos los comandos posteriores hasta que se desactive. Invocar este comando creará un semáforo de ámbito sistémico que deberá ser limpiado explícitamente llamando al comando udevreleasecookie.
udevflags <cookie>
Analiza el valor de cookie dado y extrae cualquier flag de control de udev codificado. La salida está en formato de clave de entorno que es adecuado para su uso en reglas udev. Si el flag tiene asignado su nombre simbólico, la salida es DM_UDEV_FLAG_<flag_name> = '1', DM_UDEV_FLAG<flag_position> = '1' en caso contrario. Los flags de subsistema udev no tienen nombres simbólicos asignados y estos siempre se informan como DM_SUBSYSTEM_UDEV_FLAG<flag_position> = '1'. Hay 16 flags de udev en total.
udevreleasecookie [cookie]
Espera a que todo el procesamiento pendiente de udev asociado al valor de cookie dado se complete y limpia la cookie con el semáforo subyacente. Si la cookie no se proporciona directamente, el comando intentará usar un valor definido por la variable de entorno DM_UDEV_COOKIE.
version
Muestra información de la versión.
wait <device_name> [--noflush] [event_nr]
Duerme hasta que el contador de eventos para device_name supere event_nr. Utilice -v para ver el número de evento devuelto. Para esperar hasta que se active el siguiente evento, utilice info para encontrar el último número de evento. Con --noflush, el destino thin (a partir de la versión 1.3.0) no confirma los cambios pendientes en disco antes de informar sus estadísticas.
wipe_table <device_name> ... [-f|--force] [--noflush] [--nolockfs]
Espera a que cualquier E/S en curso a través del dispositivo se complete, luego reemplaza la tabla con una nueva tabla que falla cualquier E/S nueva enviada al dispositivo. Si tiene éxito, esto debería liberar cualquier dispositivo que esté abierto por las tablas del dispositivo.

FORMATO DE TABLA

Cada línea de la tabla especifica un único destino y tiene el siguiente formato:

<logical_start_sector> <num_sectors> target_type <target_args>

Los tipos de destino y argumentos simples incluyen:

linear <destination_device start_sector>
El mapeo lineal tradicional.
striped <num_stripes chunk_size> [<destination start_sector>] ...
Crea un área rayada (striped).
por ejemplo: striped 2 32 /dev/hda1 0 /dev/hdb1 0 mapeará el primer chunk (16 KiB) de la siguiente manera:

LV chunk 1 → hda1, chunk 1
LV chunk 2 → hdb1, chunk 1
LV chunk 3 → hda1, chunk 2
LV chunk 4 → hdb1, chunk 2
etc.
error
Genera un error en cualquier E/S que vaya a esta área. Útil para pruebas o para crear dispositivos con huecos.
zero
Devuelve bloques de ceros en las lecturas. Cualquier dato escrito se descarta silenciosamente. Este es el equivalente a un dispositivo de bloque del sumidero de datos de dispositivo de caracteres /dev/zero descrito en null(4).

Los destinos más complejos incluyen:

cache...
Destino que implementa una caché de escritura para otro dispositivo.
crypt...
Destino que cifra o descifra los datos que pasan.
default...
Destino predeterminado.
delay...
Destino que introduce retrasos simulados en las operaciones de E/S.
error...
Destino que genera errores.
integrity...
Destino que añade verificaciones de integridad de datos.
linear...
Destino que mapea una región a una parte de otro dispositivo.
log...
Destino que registra las operaciones de E/S.
mirror...
Destino que espeja datos en dos o más dispositivos.
multipath...
Destino que gestiona múltiples caminos a un dispositivo de almacenamiento.
snapshot...
Destino que proporciona una instantánea de un dispositivo.
snapmerge...
Destino que gestiona la fusión de instantáneas.
striped...
Destino que divide los datos entre varios dispositivos.
swap...
Destino que se utiliza para el almacenamiento de intercambio.
thin...
Destino que implementa el aprovisionamiento delgado.
thin-pool...
Destino que gestiona un pool de almacenamiento para aprovisionamiento delgado.
zero...
Destino que devuelve ceros.

FORMATO CONCISO

En el formato conciso, cada dispositivo se representa en una sola línea con los siguientes campos separados por comas: nombre, uuid, número menor del dispositivo, flags ('ro' o 'rw') y la tabla (si está presente). Los puntos y comas separan los dispositivos. Las barras invertidas escapan cualquier coma, punto y coma o barra invertida.

Ejemplo:

my_device,uuid_of_my_device,123,rw,linear my_target_device 0

EJEMPLOS

Crear un dispositivo lineal llamado 'my_device' que mapea '/dev/sda1' a partir del sector 0:

echo '0 $(blockdev --getsize /dev/sda1) linear /dev/sda1 0' | dmsetup create my_device

Cargar una tabla de un archivo llamado 'my_table.txt' para un dispositivo llamado 'my_device':

dmsetup load my_device my_table.txt

Mostrar el estado de todos los dispositivos:

dmsetup status

Eliminar un dispositivo llamado 'my_device':

dmsetup remove my_device
