DESCRIPCIÓN
dmeventd es el demonio de monitoreo de eventos para dispositivos device-mapper. Las bibliotecas de plugins pueden registrar y llevar a cabo
acciones desencadenadas cuando ocurren eventos particulares.
OPCIONES -dRepetir de 1 a 3 veces (-d ,-dd ,-ddd) para aumentar el detalle de los mensajes de depuración enviados a syslog. Cada d adicional agrega más información de depuración.-e exit_on_pathEspecifica la ruta del archivo cuya presencia es verificada por el demonio cuando recibe una señal (SIGINT, SIGTERM) y le permite salir incluso si aún hay dispositivos monitoreados. Esto puede ayudar con el apagado del sistema donde los dispositivos no han sido desmonitoreados correctamente. Para deshabilitar este comportamiento, establezca esto a la cadena vacía "". El valor por defecto es "/run/nologin". -fNo hacer fork, ejecutar en primer plano.-gsecondsEstablece el período de gracia para la limpieza del hilo de monitoreo (0-300 segundos, por defecto: 10). Durante este período, los hilos de monitoreo que han terminado de procesar eventos esperarán una posible reutilización en lugar de terminar inmediatamente. Si la misma combinación de dispositivo y plugin se registra de nuevo dentro del período de gracia, el hilo existente se reutiliza, reduciendo significativamente la sobrecarga. Establecer a 0 para deshabilitar la reutilización de hilos.-

La advertencia se repite cuando más del 85%, 90% y 95% del VDO pool está lleno. Ver lvm.conf(5) . Cuando un VDO pool se llena más del 50% el plugin vdo llama al dmeventd/vdo_command configurado con cada aumento del 5%. Con la configuración por defecto llama al interno lvm lvextend --use-policies para redimensionar el VDO pool cuando se ha llenado por encima del umbral configurado activation/vdo_pool_autoextend_threshold . Si el comando falla, el plugin vdo de dmeventd seguirá reintentando la ejecución con un retraso de tiempo creciente entre reintentos hasta 42 minutos.
