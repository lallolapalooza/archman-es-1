DESCRIPCIÓ

N

DMTCP es una herramienta para hacer checkpointing transparente del estado de un grupo arbitrario de programas distribuidos en muchas máquinas y conectados por sockets. No modifica el programa del usuario ni el sistema operativo. MTCP es un componente independiente de DMTCP disponible com

o una biblioteca de check
pointing para un solo proceso.

DMTCP_COORDINATO

R

Cada cálculo que se va a someter a checkpoint debe incluir un proceso coordinador de DMTCP. Se puede iniciar explícitamente un coordinador a través de dmtcp_coordinator, o permitir que uno se inicie implícitamente en segundo plano por dmtcp_launch o dmtcp_restart para operar. La dirección del coordinador único debe ser especificada por dmtcp_launch, dmtcp_restart y dmtcp_command, ya sea a través de las opciones --host y --port de la línea de comandos o a través de las variables de entorno DMTCP_HOST y DMTCP_PORT. Si ninguna es proporcionada, el par host-puerto por defecto es localhost-7779. El par host-puerto asociado con un coordinador particular es proporcionado por las opciones de línea de comandos usadas en el comando dmtcp_coordinator, o las variables de entorno entonces en efecto, o el valor por defecto

localhost-7779.

El coordinador es inmutable y no se somete a checkpoint. En el reinicio, se puede usar un coordinador existente o uno nuevo. Múltiples cálculos bajo el control de DMTCP pueden coexistir proporcionando un coordinador único (con un par host-puerto único) para cada

cálculo.

El coordinador inicia un checkpoint para todos los procesos en su grupo de cálculo. Los checkpoints pueden: realizarse automáticamente en un intervalo (ver DMTCP_CHECKPOINT_INTERVAL arriba); o iniciarse manualmente en la entrada estándar del coordinador (ver siguiente párrafo); o iniciarse directamente bajo control del programa por el cálculo a través de la API de plugin (ver abajo)

.

El coordinador acepta los siguientes comandos en su entrada estándar. Cada comando debe ir seguido de la tecla <return>. Los comandos son:
l : Listar nodos conectados
s : Imprimir mensaje de estado
c : Checkpoint de todos los nodos
f : Forzar un reinicio incluso si faltan nodos (depuración)
k : Matar todos los nodos
q : Matar todos los nodos y salir
? : Mostrar este

mensaje

Los comandos del coordinador también pueden emitirse de forma remota usando dmtcp_comman

PLUGIN

DMTCP

La distribución de código fuente incluye un directorio de nivel superior plugin, con ejemplos de cómo escribir un plugin para DMTCP. Los plugins permiten que una aplicación sometida a checkpoint se desconecte de un recurso externo y luego se reconecte a él en el momento del reinicio. Más ejemplos están en el directorio test/plugin. En particular, test/plugin/applic-initiated demuestra cómo una aplicación puede solicitar un checkpoint bajo control del

programa.

La característica de plugin añade tres nuevas capacidades programables por el usuario. Un plugin puede: añadir envoltorios alrededor de llamadas al sistema; tomar acciones especiales en durante ciertos eventos (por ejemplo, pre-checkpoint, reanudar/post-checkpoint, reinicio); y puede insertar pares clave-valor en una base de datos en el momento del reinicio que luego está disponible para ser consultado por los procesos reiniciados de un cálculo. (Los eventos disponibles para la característica de plugin forman un superconjunto de los eventos disponibles con la interfaz dmtcpaware.) Uno o más plugins son invocados a través de una lista de rutas absolutas separadas por dos

puntos.


dmtcp_launch --with-plugin PLUGIN1[:PLUGIN2].

API

DMTCPAWARE

Esta API ahora está obsoleta en favor de los plugins de DMTCP (ver arriba). DMTCP proporciona una interfaz de programación para permitir que las aplicaciones sometidas a checkpoint interactúen con dmtcp. En la distribución de código fuente, ver dmtcpaware/dmtcpaware.h para las funciones disponibles. Ver test/dmtcpaware[123].c para tres ejemplos de aplicaciones. Para un ejemplo de su uso,

intente:

CÓDIGO DE

RETORNO

Un programa objetivo bajo el control de DMTCP normalmente devuelve el mismo código de retorno que si se ejecutara sin DMTCP. Sin embargo, si DMTCP falla (a diferencia del fallo del programa objetivo), DMTCP devuelve un código de retorno específico de DMTCP, rc (o rc+1, rc+2 para dos casos especiales), donde rc es el valor entero de la variable de entorno DMTCP_FAIL_RC si está establecida, o si no el valor porvalor
