Documentación de la función/subrutina

subrutina dgejsv (character*1 joba, character*1 jobu, character*1 jobv, character*1 jobr, character*1 jobt, character*1 jobp, integer m, integer n, double precision, dimension( lda, * ) a, integer lda, double precision, dimension( n ) sva, double precision, dimension( ldu, * ) u, integer ldu, double precision, dimension( ldv, * ) v, integer ldv, double precision, dimension( lwork ) work, integer lwork, integer, dimension( * ) iwork, integer info)

DGEJSV

Propósito:

!>
!> DGEJSV calcula la descomposición en valores singulares (SVD) de una matriz real M por N [A],
!> donde M >= N. La SVD de [A] se escribe como
!>
!>              [A] = [U] * [SIGMA] * [V]^t,
!>
!> donde [SIGMA] es una matriz N por N (M por N) que es cero excepto por sus N
!> elementos diagonales, [U] es una matriz ortonormal M por N (o M por M), y
!> [V] es una matriz ortogonal N por N. Los elementos diagonales de [SIGMA] son
!> los valores singulares de [A]. Las columnas de [U] y [V] son los vectores
!> singulares izquierdos y derechos de [A], respectivamente. Las matrices [U] y [V]
!> se calculan y almacenan en los arreglos U y V, respectivamente. La diagonal
!> de [SIGMA] se calcula y almacena en el arreglo SVA.
!> DGEJSV a veces puede calcular valores singulares muy pequeños y sus vectores singulares
!> de manera mucho más precisa que otras rutinas de SVD, ver abajo en Detalles Adicionales.
!>

Parámetros

JOBA 
!>          JOBA es CHARACTER*1
!>        Especifica el nivel de precisión:
!>       = 'C': Esta opción funciona bien (alta precisión relativa) si A = B * D,
!>             con B bien condicionada y matriz diagonal D arbitraria.
!>             La precisión no puede ser perjudicial por el escalado de COLUMNA. La
!>             precisión de la salida calculada depende de la condición de
!>             B, y el procedimiento apunta a la mejor precisión teórica.
!>             El error relativo max_{i=1:N}|d sigma_i| / sigma_i está
!>             acotado por f(M,N)*epsilon* cond(B), independiente de D.
!>             La matriz de entrada se preprocesa con la QRF con pivote de
!>             columna. Este preprocesamiento inicial y preacondicionamiento por
!>             una factorización QR reveladora de rango es común para todos los valores de
!>             JOBA. Las acciones adicionales se especifican de la siguiente manera:
!>       = 'E': Cálculo como con 'C' con una estimación adicional del
!>             número de condición de B. Proporciona un límite de error realista.
!>       = 'F': Si A = D1 * C * D2 con escalados diagonales mal
!>             condicionados D1, D2, y matriz C bien condicionada, esta opción da
!>             mayor precisión que la opción 'C'. Si la estructura de la
!>             matriz de entrada no se conoce, y se desea precisión relativa,
!>             entonces se recomienda esta opción. La matriz de entrada A
!>             se preprocesa con una factorización QR con pivoteo COMPLETO (filas y
!>             columnas).
!>       = 'G': Cálculo como con 'F' con una estimación adicional del
!>             número de condición de B, donde A=D*B. Si A tiene filas fuertemente
!>             ponderadas, entonces usar este número de condición da un límite de
!>             error demasiado pesimista.
!>       = 'A': Los valores singulares pequeños son ruido y la matriz se trata
!>             como numéricamente de rango deficiente. El error en los valores
!>             singulares calculados está acotado por f(m,n)*epsilon*||A||.
!>             La SVD calculada A = U * S * V^t restaura A hasta
!>             f(m,n)*epsilon*||A||.
!>             Esto da al procedimiento la licencia para descartar (poner a cero)
!>             todos los valores singulares por debajo de N*epsilon*||A||.
!>       = 'R': Similar a 'A'. Se utiliza la propiedad reveladora de rango de la
!>             factorización QR inicial para revelar (usando el factor triangular)
!>             una brecha sigma_{r+1} < epsilon * sigma_r en cuyo caso el
!>             RANGO numérico se declara como r. La SVD se calcula con
!>             límites de error absolutos, pero con mayor precisión que con 'A'.
!>

JOBU

!>          JOBU es CHARACTER*1
!>        Especifica si se deben calcular las columnas de U:
!>       = 'U': Se devuelven N columnas de U en el arreglo U.
!>       = 'F': Se devuelve el conjunto completo de M vectores singulares izquierdos en el arreglo U.
!>       = 'W': U puede usarse como espacio de trabajo de longitud M*N. Ver la descripción
!>             de U.
!>       = 'N': U no se calcula.
!>

JOBV

!>          JOBV es CHARACTER*1
!>        Especifica si se debe calcular la matriz V:
!>       = 'V': Se devuelven N columnas de V en el arreglo V; las rotaciones de Jacobi
!>             no se acumulan explícitamente.
!>       = 'J': Se devuelven N columnas de V en el arreglo V, pero se
!>             calculan como el producto de rotaciones de Jacobi. Esta opción solo
!>             se permite si JOBU .NE. 'N', es decir, al calcular la SVD completa.
!>       = 'W': V puede usarse como espacio de trabajo de longitud N*N. Ver la descripción
!>             de V.
!>       = 'N': V no se calcula.
!>

JOBR

!>          JOBR es CHARACTER*1
!>        Especifica el RANGO para los valores singulares. Da licencia para
!>        poner a cero pequeños valores singulares positivos si están fuera del
!>        rango especificado. Si A .NE. 0 se escala para que el valor singular
!>        más grande de c*A sea alrededor de DSQRT(BIG), BIG=SLAMCH('O'), entonces JOBR da
!>        licencia para anular columnas de A cuyo norma en c*A sea menor que
!>        DSQRT(SFMIN) (para JOBR = 'R'), o menor que SMALL=SFMIN/EPSLN,
!>        donde SFMIN=SLAMCH('S'), EPSLN=SLAMCH('E').
!>       = 'N': No anular columnas pequeñas de c*A. Esta opción asume que
!>             BLAS y las factorizaciones QR y los solucionadores triangulares están
!>             implementados para trabajar en ese rango. Si la condición de A
!>             es mayor que BIG, use DGESVJ.
!>       = 'R': RANGO RESTRINGIDO para sigma(c*A) es [DSQRT(SFMIN), DSQRT(BIG)]
!>             (aproximadamente, como se describe arriba). Se recomienda esta opción.
!>                                            ~~~~~~~~~~~~~~~~~~~~~~~~~~~
!>        Para calcular los valores singulares en el rango COMPLETO [SFMIN,BIG]
!>        use DGESVJ.
!>

JOBT

!>          JOBT es CHARACTER*1
!>        Si la matriz es cuadrada, el procedimiento puede decidir usar
!>        A transpuesta si A^t parece ser mejor con respecto a la convergencia.
!>        Si la matriz no es cuadrada, JOBT se ignora. Esto está sujeto a
!>        cambios en el futuro.
!>        La decisión se basa en dos valores de entropía sobre la órbita adjunta
!>        de A^t * A. Ver las descripciones de WORK(6) y WORK(7).
!>       = 'T': transponer si la prueba de entropía indica posiblemente una convergencia más rápida
!>        del proceso de Jacobi si A^t se toma como entrada. Si A es
!>        reemplazada por A^t, entonces el pivoteo de fila se incluye automáticamente.
!>       = 'N': no especular.
!>        Esta opción se puede usar para calcular solo los valores singulares, o la
!>        SVD completa (U, SIGMA y V). Para un solo conjunto de vectores singulares
!>        (U o V), el llamador debe proporcionar tanto U como V, ya que una de las
!>        matrices se usa como espacio de trabajo si la matriz A se transpone.
!>        El implementador puede eliminar fácilmente esta restricción y hacer que el
!>        código sea más complicado. Ver las descripciones de U y V.
!>

JOBP

!>          JOBP es CHARACTER*1
!>        Da licencia para introducir perturbaciones estructuradas para ahogar
!>        números desnormalizados. Esta licencia debe estar activa si los
!>        desnormales están mal implementados, causando un cálculo lento,
!>        especialmente en casos de convergencia rápida (!). Para
detalles ver [1,2]. !> Por simplicidad, estas perturbaciones se incluyen solo !> cuando se solicita la SVD completa o solo los valores singulares. El !> implementador/usuario puede añadir fácilmente la perturbación para los casos de !> cálculo de un conjunto de vectores singulares. !> = 'P': introducir perturbación !> = 'N': no perturbar !>

M

!>          M es INTEGER
!>         El número de filas de la matriz de entrada A.  M >= 0.
!>

N

!>          N es INTEGER
!>         El número de columnas de la matriz de entrada A. M >= N >= 0.
!>

A

!>          A es un array DOUBLE PRECISION, dimensión (LDA,N)
!>          En la entrada, la matriz A de M por N.
!>

LDA

!>          LDA es INTEGER
!>          La dimensión principal del array A.  LDA >= max(1,M).
!>

SVA

!>          SVA es un array DOUBLE PRECISION, dimensión (N)
!>          En la salida,
!>          - Para WORK(1)/WORK(2) = ONE: Los valores singulares de A. Durante el
!>            cálculo, SVA contiene las normas euclídeas de las columnas de las
!>            matrices iteradas en el array A.
!>          - Para WORK(1) .NE. WORK(2): Los valores singulares de A son
!>            (WORK(1)/WORK(2)) * SVA(1:N). Esta forma factorizada se usa si
!>            sigma_max(A) desborda o si los valores singulares pequeños han sido
!>            salvados del desbordamiento por debajo escalando la matriz de entrada A.
!>          - Si JOBR='R' entonces algunos de los valores singulares pueden ser devueltos
!>            como ceros exactos obtenidos por  porque están
!>            por debajo del umbral de rango numérico o son números denormalizados.
!>

U

!>          U es un array DOUBLE PRECISION, dimensión ( LDU, N ) o ( LDU, M )
!>          Si JOBU = 'U', entonces U contiene en la salida la matriz M por N de
!>                         los vectores singulares izquierdos.
!>          Si JOBU = 'F', entonces U contiene en la salida la matriz M por M de
!>                         los vectores singulares izquierdos, incluyendo una ONB
!>                         del complemento ortogonal del Rango(A).
!>          Si JOBU = 'W'  .AND. (JOBV = 'V' .AND. JOBT = 'T' .AND. M = N),
!>                         entonces U se usa como espacio de trabajo si el procedimiento
!>                         reemplaza A con A^t. En ese caso, [V] se calcula
!>                         en U como vectores singulares izquierdos de A^t y luego
!>                         se copia de vuelta al array V. Esta opción 'W' es solo
!>                         un recordatorio para el llamador de que en este caso U está
!>                         reservada como espacio de trabajo de longitud N*N.
!>          Si JOBU = 'N'  U no se referencia, a menos que JOBT='T'.
!>

LDU

!>          LDU es INTEGER
!>          La dimensión principal del array U,  LDU >= 1.
!>          SI  JOBU = 'U' o 'F' o 'W',  entonces LDU >= M.
!>

V

!>          V es un array DOUBLE PRECISION, dimensión ( LDV, N )
!>          Si JOBV = 'V', 'J' entonces V contiene en la salida la matriz N por N de
!>                         los vectores singulares derechos;
!>          Si JOBV = 'W', AND (JOBU = 'U' AND JOBT = 'T' AND M = N),
!>                         entonces V se usa como espacio de trabajo si el procedimiento
!>                         reemplaza A con A^t. En ese caso, [U] se calcula
!>                         en V como vectores singulares derechos de A^t y luego
!>                         se copia de vuelta al array U. Esta opción 'W' es solo
!>                         un recordatorio para el llamador de que en este caso V está
!>                         reservada como espacio de trabajo de longitud N*N.
!>          Si JOBV = 'N'  V no se referencia, a menos que JOBT='T'.
!>

LDV

!>          LDV es INTEGER
!>          La dimensión principal del array V,  LDV >= 1.
!>          Si JOBV = 'V' o 'J' o 'W', entonces LDV >= N.
!>

WORK

!>          WORK es un array DOUBLE PRECISION, dimensión (MAX(7,LWORK))
!>          En la salida, si N > 0 .AND. M > 0 (de lo contrario no se referencia),
!>          WORK(1) = SCALE = WORK(2) / WORK(1) es el factor de escala tal
!>                    que SCALE*SVA(1:N) son los valores singulares calculados
!>                    de A. (Ver la descripción de SVA().)
!>          WORK(2) = Ver la descripción de WORK(1).
!>          WORK(3) = SCONDA es una estimación del número de condición de
!>                    A equilibrado por columnas. (Si JOBA = 'E' o 'G')
!>                    SCONDA es una estimación de DSQRT(||(R^t * R)^(-1)||_1).
!>                    Se calcula usando DPOCON. Se cumple
!>                    N^(-1/4) * SCONDA <= ||R^(-1)||_2 <= N^(1/4) * SCONDA
!>                    donde R es el factor triangular de la QRF de A.
!>                    Sin embargo, si R se trunca y el rango numérico se
!>                    determina estrictamente menor que N, SCONDA se
!>                    devuelve como -1, indicando así que los valores
!>                    singulares más pequeños podrían perderse.
!>
!>          Si se necesita la SVD completa, los siguientes dos números de condición son
!>          útiles para el análisis del algoritmo. Se proporcionan para
!>          un desarrollador/implementador que esté familiarizado con los detalles de
!>          el método.
!>
!>          WORK(4) = una estimación del número de condición escalado del
!>                    factor triangular en la primera factorización QR.
!>          WORK(5) = una estimación del número de condición escalado del
!>                    factor triangular en la segunda factorización QR.
!>          Los siguientes dos parámetros se calculan si JOBT = 'T'.
!>          Se proporcionan para un desarrollador/implementador que esté familiarizado
!>          con los detalles del método.
!>
!>          WORK(6) = la entropía de A^t*A :: esta es la entropía de Shannon
!>                    de diag(A^t*A) / Trace(A^t*A) tomada como punto en el
!>                    simplex de probabilidad.
!>          WORK(7) = la entropía de A*A^t.
!>

LWORK

!>          LWORK es INTEGER
!>          Longitud de WORK para confirmar la asignación adecuada del espacio de trabajo.
!>          LWORK depende del trabajo:
!>
!>          Si solo se necesita SIGMA (JOBU = 'N', JOBV = 'N') y
!>            -> .. no se requiere estimación de condición escalada (JOBE = 'N'):
!>               LWORK >= max(2*M+N,4*N+1,7). Este es el requisito mínimo.
!>               ->> Para un rendimiento óptimo (código bloqueado) el valor óptimo
!>               es LWORK >= max(2*M+N,3*N+(N+1)*NB,7). Aquí NB es el tamaño de bloque óptimo
!>               para DGEQP3 y DGEQRF.
!>               En general, el LWORK óptimo se calcula como
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3),N+LWORK(DGEQRF), 7).
!>            -> .. se requiere una estimación del número de condición escalado de A
!>               (JOBA='E', 'G'). En este caso, LWORK es el máximo
!>               de lo anterior y N*N+4*N, es decir, LWORK >= max(2*M+N,N*N+4*N,7).
!>               ->> Para un rendimiento óptimo (código bloqueado) el valor óptimo
!>               es LWORK >= max(2*M+N,3*N+(N+1)*NB, N*N+4*N, 7).
!>               En general, la longitud óptima LWORK se calcula como
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3),N+LWORK(DGEQRF),
!>                                                     N+N*N+LWORK(DPOCON),7).
!>
!>          Si se necesitan SIGMA y los vectores singulares derechos (JOBV = 'V'),
!>            -> el requisito mínimo es LWORK >= max(2*M+N,4*N+1,7).
!>            -> Para un rendimiento óptimo, LWORK >= max(2*M+N,3*N+(N+1)*NB,7),
!>               donde NB es el tamaño de bloque óptimo para DGEQP3, DGEQRF, DGELQF,
!>               DORMLQ. En general, la longitud óptima LWORK se calcula como
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3), N+LWORK(DPOCON),
!>                       N+LWORK(DGELQF), 2*N+LWORK(DGEQRF), N+LWORK(DORMLQ)).
!>
!>          Si se necesitan SIGMA y los vectores singulares izquierdos
!>            -> el requisito mínimo es LWORK >= max(2*M+N,4*N+1,7).
!>            -> Para un rendimiento óptimo:
!>               si JOBU = 'U' :: LWORK >= max(2*M+N,3*N+(N+1)*NB,7),
!>               si JOBU = 'F' :: LWORK >= max(2*M+N,3*N+(N+1)*NB,N+M*NB,7),
!>               donde NB es el tamaño de bloque óptimo para DGEQP3, DGEQRF, DORMQR.
!>               En general, la longitud óptima LWORK se calcula como
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3),N+LWORK(DPOCON),
!>                        2*N+LWORK(DGEQRF), N+LWORK(DORMQR)).
!>               Aquí LWORK(DORMQR) es igual a N*NB (para JOBU = 'U') o
!>               M*NB (para JOBU = 'F').
!>
!>          Si se necesita la SVD completa: (JOBU = 'U' o JOBU = 'F') y
!>            -> si JOBV = 'V'
!>               el requisito mínimo es LWORK >= max(2*M+N,6*N+2*N*N).
!>            -> si JOBV = 'J' el requisito mínimo es
!>               LWORK >= max(2*M+N, 4*N+N*N,2*N+N*N+6).
!>            -> Para un rendimiento óptimo, LWORK debería ser adicionalmente
!>               mayor que N+M*NB, donde NB es el tamaño de bloque óptimo
!>               para DORMQR.
!>

IWORK

!>          IWORK es un array INTEGER, dimensión (MAX(3,M+3*N)).
!>          En la salida,
!>          IWORK(1) = el rango numérico determinado después de la
!>                     factorización QR inicial con pivoteo. Ver las descripciones
!>                     de JOBA y JOBR.
!>          IWORK(2) = el número de valores singulares distintos de cero calculados
!>          IWORK(3) = si es distinto de cero, un mensaje de advertencia:
!>                     Si IWORK(3) = 1 entonces algunas de las normas de columna de A
!>                     eran flotantes denormalizados. La alta precisión solicitada
!>                     no está garantizada por los datos.
!>

INFO

!>          INFO es INTEGER
!>           < 0:  si INFO = -i, entonces el i-ésimo argumento tenía un valor ilegal.
!>           = 0:  salida exitosa;
!>           > 0:  DGEJSV  no convergió en el número máximo permitido de
!>                 barridos. Los valores calculados pueden ser inexactos.

Detalles adicionales:

!>
!>  DGEJSV implementa un algoritmo SVD de Jacobi preacondicionado. Usa DGEQP3,
!>  DGEQRF, y DGELQF como preprocesadores y preacondicionadores. Opcionalmente, un
!>  pivoteo de fila adicional puede usarse como preprocesador, lo que en algunos
!>  casos resulta en una precisión mucho mayor. Un ejemplo es la matriz A con la
!>  estructura A = D1 * C * D2, donde D1, D2 son matrices diagonales arbitrariamente mal
!>  condicionadas y C es una matriz bien condicionada. En ese caso, el pivoteo
!>  completo en las primeras factorizaciones QR proporciona una precisión dependiente del
!>  número de condición de C, e independiente de D1, D2. Tal mayor precisión no está
!>  completamente entendida teóricamente, pero funciona bien en la práctica.
!>  Además, si A puede escribirse como A = B*D, con B bien condicionada y alguna
!>  diagonal D, entonces la alta precisión está garantizada, tanto teóricamente como
!>  en el software, independiente de D. Para más detalles ver [1], [2].
!>     El rango computacional para los valores singulares puede ser el rango completo
!>  ( UNDERFLOW,OVERFLOW ), provided that the machine arithmetic and the BLAS
!>  & LAPACK routines called by DGEJSV are implemented to work in that range.
!>  If that is not the case, then the restriction for safe computation with
!>  the singular values in the range of normalized IEEE numbers is that the
!>  spectral condition number kappa(A)=sigma_max(A)/sigma_min(A) does not
!>  overflow. This code (DGEJSV) is best used in this restricted range,
!>  meaning that singular values of magnitude below ||A||_2 / DLAMCH('O') are
!>  returned as zeros. See JOBR for details on this.
!>     Further, this implementation is somewhat slower than the one described
!>  in [1,2] due to replacement of some non-LAPACK components, and because
!>  the choice of some tuning parameters in the iterative part (DGESVJ) is
!>  left to the implementer on a particular machine.
!>     The rank revealing QR factorization (in this code: DGEQP3) should be
!>  implemented as in [3]. We have a new version of DGEQP3 under development
!>  that is more robust than the current one in LAPACK, with a cleaner cut in
!>  rank deficient cases. It will be available in the SIGMA library [4].
!>  If M is much larger than N, it is obvious that the initial QRF with
!>  column pivoting can be preprocessed by the QRF without pivoting. That
!>  well known trick is not used in DGEJSV because in some cases heavy row
!>  weighting can be treated with complete pivoting. The overhead in cases
!>  M much larger than N is then only due to pivoting, but the benefits in
!>  terms of accuracy have prevailed. The implementer/user can incorporate
!>  this extra QRF step easily. The implementer can also improve data movement
!>  (matrix transpose, matrix copy, matrix transposed copy) - this
!>  implementation of DGEJSV uses only the simplest, naive data movement.
!>
