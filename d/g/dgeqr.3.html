info)

DGEQ

R

Propósito

: 
!>
!> DGEQR calcula una factorización QR de una matriz real M-por-N A:
!>
!>    A = Q * ( R ),
!>            ( 0 )
!>
!> donde:
!>
!>    Q es una matriz ortogonal M-por-M;
!>    R es una matriz triangular superior N-por-N;
!>    0 es una matriz cero (M-N)-por-N, si M > N.
!>
!
>

Parámetro

s
M 
!>          M es INTEGER
!>          El número de filas de la matriz A.  M >= 0.
!
>

N 
!>          N es INTEGER
!>          El número de columnas de la matriz A.  N >= 0.
!
>

A 
!>          A es un array DOUBLE PRECISION, dimensión (LDA,N)
!>          En la entrada, la matriz A M-por-N.
!>          En la salida, los elementos en y sobre la diagonal del array
!>          contienen la matriz trapezoidal superior min(M,N)-por-N R
!>          (R es triangular superior si M >= N);
!>          los elementos por debajo de la diagonal se utilizan para almacenar parte de la
!>          estructura de datos que representa Q.
!
>

LD

A 
!>          LDA es INTEGER
!>          La dimensión principal del array A.  LDA >= max(1,M).
!
>

T 
!>          T es un array DOUBLE PRECISION, dimensión (MAX(5,TSIZE))
!>          En la salida, si INFO = 0, T(1) devuelve el TSIZE óptimo (o bien el mínimo
!>          u óptimo, si se asume una consulta). Ver TSIZE para más detalles.
!>          El resto de T contiene parte de la estructura de datos utilizada para representar Q.
!>          Si se desea aplicar o construir Q, entonces se necesita conservar T
!>          (además de A) y pasarlo a las subrutinas posteriores.
!
>

TSIZ

E 
!>          TSIZE es INTEGER
!>          Si TSIZE >= 5, la dimensión del array T.
!>          Si TSIZE = -1 o -2, se asume una consulta de espacio de trabajo. La rutina
!>          solo calcula los tamaños de los arrays T y WORK, devuelve estos
!>          valores como las primeras entradas de los arrays T y WORK, y XERBLA no emite
!>          ningún mensaje de error relacionado con T o WORK.
!>          Si TSIZE = -1, la rutina calcula el tamaño óptimo de T para el
!>          rendimiento óptimo y devuelve este valor en T(1).
!>          Si TSIZE = -2, la rutina calcula el tamaño mínimo de T y
!>          devuelve este valor en T(1).
!
>

WOR

K 
!>          (espacio de trabajo) array DOUBLE PRECISION, dimensión (MAX(1,LWORK))
!>          En la salida, si INFO = 0, WORK(1) contiene el LWORK óptimo (o bien el mínimo
!>          u óptimo, si se asumió una consulta).
!>          Ver LWORK para más detalles.
!
>

LWOR

K 
!>          LWORK es INTEGER
!>          La dimensión del array WORK. LWORK >= 1.
!>          Si LWORK = -1 o -2, se asume una consulta de espacio de trabajo. La rutina
!>          solo calcula los tamaños de los arrays T y WORK, devuelve estos
!>          valores como las primeras entradas de los arrays T y WORK, y XERBLA no emite
!>          ningún mensaje de error relacionado con T o WORK.
!>          Si LWORK = -1, la rutina calcula el tamaño óptimo de WORK para el
!>          rendimiento óptimo y devuelve este valor en WORK(1).
!>          Si LWORK = -2, la rutina calcula el tamaño mínimo de WORK y
!>          devuelve este valor en WORK(1).
!
>

INF

O 
!>          INFO es INTEGER
!>          = 0:  salida exitosa
!>          < 0:  si INFO = -i, el i-ésimo argumento tenía un valor ilegal
!
>

!>
!> El objetivo de la interfaz es dar la máxima libertad a los desarrolladores para
!> crear cualquier algoritmo de factorización QR que deseen. La R triangular
!> (trapezoidal) debe almacenarse en la parte superior de A. La parte inferior de A
!> y el array T pueden usarse para almacenar cualquier información relevante para aplicar o
!> construir el factor Q. El array WORK puede descartarse con seguridad después de la salida.
!>
!> Precaución: No se debe esperar que los tamaños de T y WORK sean los mismos de una
!> implementación de LAPACK a otra, o incluso de una ejecución a otra.
!> Se necesita una consulta de espacio de trabajo (para T y WORK) en cada ejecución. Sin embargo,
!> para una ejecución dada, el tamaño de T y WORK son fijos y no cambiarán
!> de una consulta a la siguiente.
!>
!
>

Más detalles particulares de esta implementación de

LAPACK: 
!>
!> Estos detalles son particulares para esta implementación de LAPACK. Los usuarios no deben
!> darlos por sentados. Estos detalles pueden cambiar en el futuro y es probable que no sean
!> ciertos para otra implementación de LAPACK. Estos detalles son relevantes si se quiere
!> intentar entender el código. No forman parte de la interfaz.
!>
!> En esta versión,
!>
!>          T(2): tamaño de bloque de filas (MB)
!>          T(3): tamaño de bloque de columnas (NB)
!>          T(6:TSIZE): estructura de datos necesaria para Q, calculada por
!>                           DLATSQR o DGEQRT
!>
!>  Dependiendo de las dimensiones de la matriz M y N, y los tamaños de bloque
!>  de filas y columnas MB y NB devueltos por ILAENV, DGEQR usará
!>  DLATSQR (si la matriz es alta y delgada) o DGEQRT para calcular
!>  la factorización QR.
!>
!
>
