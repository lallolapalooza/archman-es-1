-m, --add-bom
Escribir una Marca de Orden de Bytes (BOM) en el archivo de salida. Por defecto, se escribe una BOM UTF-8.

Cuando el archivo de entrada es UTF-16 y se usa la opción "-u", se escribirá una BOM UTF-16.

Nunca use esta opción cuando la codificación de salida sea distinta de UTF-8, UTF-16 o GB18030. Consulte también la sección UNICODE.

-n, --newfile INFILE OUTFILE ...
Modo de archivo nuevo. Convierte el archivo INFILE y escribe la salida en el archivo OUTFILE. Los nombres de archivo deben proporcionarse por pares y los nombres comodín no deben usarse o perderá sus archivos.

La persona que inicia la conversión en modo de archivo nuevo (emparejado) será la propietaria del archivo convertido. Los permisos de lectura/escritura del nuevo archivo serán los permisos del archivo original menos la umask del usuario que ejecuta la conversión.

--no-allow-chown
No permitir el cambio de propiedad del archivo en modo de archivo antiguo (por defecto).

Abortar la conversión cuando la propiedad del usuario y/o grupo del archivo original no se pueda conservar en modo de archivo antiguo. Consulte también las opciones "-o" y "-n". Esta opción solo está disponible si dos2unix tiene soporte para conservar la propiedad del usuario y grupo de los archivos.

--no-add-eol
No agregar un salto de línea a la última línea si no existe.
-O, --to-stdout
Escribir en la salida estándar, como un filtro Unix. Utilice la opción "-o" para volver al modo de archivo antiguo (in situ).

Combinado con la opción "-e", los archivos se pueden concatenar correctamente. Sin líneas finales y primeras líneas fusionadas, y sin marcas de orden de bytes Unicode en el medio del archivo concatenado. Ejemplo:

dos2unix -e -O file1.txt file2.txt > output.txt
-o, --oldfile ARCHIVO ...
Modo de archivo antiguo. Convierte el archivo ARCHIVO y sobrescribe la salida en él. El programa por defecto se ejecuta en este modo. Se pueden usar nombres comodín.

En el modo de archivo antiguo (in situ), el archivo convertido obtendrá el mismo propietario, grupo y permisos de lectura/escritura que el archivo original. Incluso cuando el archivo es convertido por otro usuario que tiene permisos de escritura sobre el archivo (por ejemplo, el usuario root). La conversión se abortará cuando no sea posible conservar los valores originales. El cambio de propietario puede significar que el propietario original ya no pueda leer el archivo. El cambio de grupo podría ser un riesgo de seguridad, el archivo podría hacerse legible para personas para las que no está destinado. La preservación del propietario, grupo y permisos de lectura/escritura solo se admite en Unix.

Para comprobar si dos2unix tiene soporte para conservar la propiedad del usuario y grupo de los archivos, escriba "dos2unix -V".

La conversión siempre se realiza a través de un archivo temporal. Cuando ocurre un error a mitad de la conversión, el archivo temporal se elimina y el archivo original permanece intacto. Cuando la conversión es exitosa, el archivo original se reemplaza con el archivo temporal. Puede tener permiso de escritura sobre el archivo original, pero no tiene permiso para poner las mismas propiedades de propietario y/o grupo en el archivo temporal que tiene el archivo original. Esto significa que no puede conservar la propiedad del usuario y/o grupo del archivo original. En este caso, puede usar la opción "--allow-chown" para continuar con la conversión:

dos2unix --allow-chown foo.txt

Otra opción es usar el modo de archivo nuevo:

dos2unix -n foo.txt foo.txt

La ventaja de la opción "--allow-chown" es que puede usar comodines y las propiedades de propiedad se conservarán cuando sea posible.

MODO MAC

\n

Por defecto, los saltos de línea se convierten de DOS a Unix y viceversa. Los saltos de línea de Mac no se convierten.

\n

En modo Mac, los saltos de línea se convierten de Mac a Unix y viceversa. Los saltos de línea de DOS no se modifican.

\n

Para ejecutar en modo Mac, usa la opción de línea de comandos "-c mac" o los comandos "mac2unix" o "unix2mac".

MODOS DE CONVERSIÓN

\n
\n
ascii
\n
Este es el modo de conversión predeterminado. Este modo es para convertir archivos codificados en ASCII y compatibles con ASCII, como UTF-8. Habilitar el modo ascii deshabilita los modos 7bit e iso.\n

Si dos2unix tiene soporte UTF-16, los archivos codificados en UTF-16 se convierten a la codificación de caracteres del locale actual en sistemas POSIX y a UTF-8 en Windows. Habilitar el modo ascii deshabilita la opción de conservar la codificación UTF-16 ("-u") y las opciones para asumir entrada UTF-16 ("-ul" y "-ub"). Para ver si dos2unix tiene soporte UTF-16, escribe "dos2unix -V". Ver también la sección UNICODE.

\n
\n
7bit
\n
En este modo, todos los caracteres no ASCII de 8 bits (con valores de 128 a 255) se convierten a un espacio de 7 bits.
\n
iso
\n
Los caracteres se convierten entre un conjunto de caracteres DOS (página de códigos) y un conjunto de caracteres ISO ISO-8859-1 (Latin-1) en Unix. Los caracteres DOS sin equivalente en ISO-8859-1, para los cuales la conversión no es posible, se convierten a un punto. Lo mismo ocurre con los caracteres ISO-8859-1 sin contraparte DOS.\n

Cuando solo se usa la opción "-iso", dos2unix intentará determinar la página de códigos activa. Cuando esto no es posible, dos2unix usará la página de códigos predeterminada CP437, que se usa principalmente en EE. UU. Para forzar una página de códigos específica, use las opciones -437 (EE. UU.), -850 (Europa Occidental), -860 (Portugués), -863 (Canadiense Francés) o -865 (Nórdico). La página de códigos de Windows CP1252 (Europa Occidental) también es compatible con la opción -1252. Para otras páginas de códigos, use dos2unix en combinación con iconv(1). Iconv puede convertir entre una larga lista de codificaciones de caracteres.

\n

Nunca use la conversión ISO en archivos de texto Unicode. Corromperá los archivos codificados en UTF-8.

\n

Algunos ejemplos:

\n

Convertir de la página de códigos predeterminada de DOS a Unix Latin-1:

\n 
dos2unix -iso -n in.txt out.txt\n
\n

Convertir de DOS CP850 a Unix Latin-1:

\n 
dos2unix -850 -n in.txt out.txt\n
\n

Convertir de Windows CP1252 a Unix Latin-1:

\n 
dos2unix -1252 -n in.txt out.txt\n
\n

Convertir de Windows CP1252 a Unix UTF-8 (Unicode):

\n 
iconv -f CP1252 -t UTF-8 in.txt | dos2unix > out.txt\n
\n

Convertir de Unix Latin-1 a la página de códigos predeterminada de DOS:

\n 
unix2dos -iso -n in.txt out.txt\n
\n

Convertir de Unix Latin-1 a DOS CP850:

\n 
unix2dos -850 -n in.txt out.txt\n
\n

Convertir de Unix Latin-1 a Windows CP1252:

\n 
unix2dos -1252 -n in.txt out.txt\n
\n

Convertir de Unix UTF-8 (Unicode) a Windows CP1252:

\n 
unix2dos < in.txt | iconv -f UTF-8 -t CP1252 > out.txt\n
\n

Ver también http://czyborra.com/charsets/codepages.html\n y http://czyborra.com/charsets/iso8859.html.

UNICODE

\n
\n

Codificaciones

\n

Existen diferentes codificaciones Unicode. En Unix y Linux, los archivos Unicode se codifican típicamente en UTF-8. En Windows, los archivos de texto Unicode pueden codificarse en UTF-8, UTF-16 o UTF-16 big endian, pero la mayoría se codifican en formato UTF-16.

\n
\n
\n

Conversión

\n

Los archivos de texto Unicode pueden tener saltos de línea DOS, Unix o Mac, al igual que los archivos de texto ASCII.

\n

Todas las versiones de dos2unix y unix2dos pueden convertir archivos codificados en UTF-8, ya que UTF-8 fue diseñado para la compatibilidad con versiones anteriores con ASCII.

\n

dos2unix y unix2dos con soporte Unicode UTF-16 pueden leer archivos de texto codificados en UTF-16 little y big endian. Para ver si dos2unix fue compilado con soporte UTF-16, escribe "dos2unix -V".

\n

En Unix/Linux, los archivos codificados en UTF-16 se convierten a la codificación de caracteres del locale. Usa el comando locale(1) para averiguar cuál es la codificación de caracteres del locale. Cuando la conversión no es posible, ocurrirá un error de conversión y el archivo se omitirá.

\n

En Windows, los archivos UTF-16 se convierten por defecto a UTF-8. Los archivos de texto en formato UTF-8 son bien soportados tanto en Windows como en Unix/Linux.

\n

Las codificaciones UTF-16 y UTF-8 son totalmente compatibles, no se perderá texto en la conversión. Cuando ocurre un error de conversión de UTF-16 a UTF-8, por ejemplo, cuando el archivo de entrada UTF-16 contiene un error, el archivo se omitirá.

\n

Cuando se usa la opción "-u", el archivo de salida se escribirá en la misma codificación UTF-16 que el archivo de entrada. La opción "-u" evita la conversión a UTF-8.

\n

dos2unix y unix2dos no tienen una opción para convertir archivos UTF-8 a UTF-16.

\n

Los modos de conversión ISO y de 7 bits no funcionan en archivos UTF-16.

\n
\n
\n

Marca de Orden de Byte

\n

En Windows, los archivos de texto Unicode suelen tener una Marca de Orden de Byte (BOM), porque muchos programas de Windows (incluido el Bloc de notas) añaden BOMs por defecto. Ver también https://en.wikipedia.org/wiki/Byte_order_mark.

\n

En Unix, los archivos Unicode típicamente no tienen BOM. Se asume que los archivos de texto están codificados en la codificación de caracteres del locale.

\n

dos2unix solo puede detectar si un archivo está en formato UTF-16 si el archivo tiene una BOM. Cuando un archivo UTF-16 no tiene BOM, dos2unix lo verá como un archivo binario.

\n

Usa la opción "-ul" o "-ub" para convertir un archivo UTF-16 sin BOM.

\n

Por defecto, dos2unix no escribe una BOM en el archivo de salida. Con la opción "-b", dos2unix escribe una BOM si el archivo de entrada tiene una BOM.

\n

unix2dos escribe por defecto una BOM en el archivo de salida si el archivo de entrada tiene una BOM. Usa la opción "-r" para eliminar la BOM.

\n

dos2unix y unix2dos siempre escriben una BOM cuando se usa la opción "-m".

\n
\n
\n

Nombres de archivo Unicode en Windows

\n

dos2unix tiene soporte opcional para leer y escribir nombres de archivo Unicode en la Consola de Windows. Esto significa que dos2unix puede abrir archivos que tienen caracteres en el nombre que no forman parte de la página de códigos ANSI del sistema predeterminado. Para ver si dos2unix para Windows fue compilado con soporte para nombres de archivo Unicode, escribe "dos2unix -V".

\n

Existen algunos problemas al mostrar nombres de archivo Unicode en una consola de Windows. Ver la opción "-D", "--display-enc". Los nombres de archivo pueden mostrarse incorrectamente en la consola, pero los archivos se escribirán con el nombre correcto.

\n

GB18030 es un estándar del gobierno chino. Un subconjunto obligatorio del estándar GB18030 es oficialmente requerido para todos los productos de software vendidos en China. Véase también https://en.wikipedia.org/wiki/GB_18030

.

GB18030 es totalmente compatible con Unicode, y puede considerarse un formato de transformación unicode. Al igual que UTF-8, GB18030 es compatible con ASCII. GB18030 también es compatible con la página de código de Windows 936, también conocida como

En Unix/Linux los archivos UTF-16 se convierten a GB18030 cuando la codificación de la configuración regional (locale) está establecida en GB18030. compatibles.

En Windows necesita usar la opción "-gb" para convertir archivos UTF-16 a

CONVERSIÓN

RECURSIVA

En un shell de Unix, los comandos find(1) y xargs(1) pueden usarse para ejecutar dos2unix recursivamente sobre todos los archivos de texto en un árbol de directorios. Por ejemplo, para convertir todos los archivos .txt en el árbol de directorios bajo el directorio actual,

escriba: 
find . -name '*.txt' -print0 |xargs -0
dos2unix

La opción find(1) "-print0" y la opción correspondiente xargs(1) -0 son necesarias cuando hay archivos con espacios o comillas en el nombre. De lo contrario, estas opciones pueden omitirse. Otra opción es usar find(1) con la opción "-e

xec": 
find . -name '*.txt' -exec dos2unix {}
\;

En un Símbolo del sistema de Windows se puede usar el siguiente

comando: 
for /R %G in (*.txt) do dos2unix
"%G"

Los usuarios de PowerShell pueden usar el siguiente comando en Windows

PowerShell: 
get-childitem -path . -filter
'*.txt' -recurse | foreach-
object {dos2unix $_.Fullname}
