ONBUILD
-- ONBUILD [INSTRUCTION]
La instrucción ONBUILD añade una instrucción de activación a una imagen. La
instrucción de activación se ejecuta más tarde, cuando la imagen se usa como base para
otra compilación. Docker ejecuta la instrucción de activación en el contexto de la compilación descendente, como si la instrucción de activación existiera inmediatamente después de la
instrucción FROM en
el dDockerfile aguas

abajo.

Puedes registrar cualquier instrucción de construcción como un disparador. Un disparador es útil si
estás definiendo una imagen para usar como base para construir otras imágenes. Por
ejemplo, si estás definiendo un entorno de construcción de aplicaciones o un demonio
que está personalizado con una configuración específica del

usuario.

Considera una imagen destinada a ser un constructor reutilizable de aplicaciones Python. Debe
añadir el código fuente de la aplicación a un directorio particular, y podría necesitar un script de construcción
llamado después de eso. No puedes simplemente llamar a ADD y RUN ahora, porque
aún no tienes acceso al código fuente de la aplicación, y es diferente
para cada construcción de

aplicación.

-- Proporcionar a los desarrolladores de aplicaciones una plantilla de Dockerfile para copiar y pegar
en su aplicación es ineficiente, propenso a errores y
difícil de actualizar porque se mezcla con el código específico de la aplicación.
La solución es usar ONBUILD para registrar instrucciones de antemano, para
ejecutarlas más tarde,

durante la siguiente
etapa de construcción.
