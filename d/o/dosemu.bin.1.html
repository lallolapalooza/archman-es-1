DOSEMU.BIN(1) Emulación DOS DOSEMU.BIN(1)

NOMBRE

dosemu.bin, dosdebug - ejecutar DOS y programas DOS bajo Linux

SINOPSIS

dosemu.bin [ -234ABCcdKkmNnOpSstVwX ] [ -h nivel ] [ -F archivo ] [ --Fusers archivo ] [ --Flibdir directorio ] [ --Fimagedir directorio ] [ -f archivo ] [ -L archivo_ejecutable ] [ -u variable_config ] [ -D flags ] [ -M tamaño ] [ -e tamaño ] [ -x tamaño ] [ -P archivo ] [ -o archivo ] [ 2> archivo_debug ] [ -I opciones_config ] [ -i [directorio_arranque] ] [ -U tubería_entrada[:tubería_salida] ] [ [-E] comando_dos ]

dosdebug

DESCRIPCIÓN

dosemu.bin es el binario envuelto por el script dosemu(1) que invoca el emulador DOS de Linux, también conocido como DOSEMU.
archivo_debug es un archivo opcional al que se redirigirá toda la salida de depuración.

dosdebug se utiliza para controlar o depurar un DOSEMU ya en ejecución.

Aunque este programa se conoce como el *emulador* DOS, en realidad es una máquina virtual para DOS, que permite que DOS y los programas escritos para DOS operen en un entorno similar a un PC/AT estándar de IBM o compatible con un procesador Intel 80x86 en modo real. DOSEMU proporciona emulación de servicios como video BIOS, disco, teclado, serie e impresora; memoria CMOS para información de configuración; un reloj en tiempo real; asignación de memoria a través de la especificación XMS 3.0, EMS 4.0 y DPMI 0.9.

Dado que DOSEMU no es realmente un emulador de DOS, se requiere una copia de FreeDos, que ahora está preconfigurada y forma parte de la distribución oficial de binarios de DOSEMU. Además, cualquier DOS propietario actualmente disponible (como MS-DOS, PC-DOS, DR-DOS) se puede arrancar, cuando está debidamente configurado.

REQUISITOS DEL NÚCLEO

Por el momento, necesitarás Linux 2.0.28 o superior con la opción SYSV IPC (System V Inter-Process Communication facilities, ver ipc(2)) compilada. SYSV IPC es una opción en la configuración durante la compilación de un kernel de Linux.

OPCIONES

-2,3,4,5
elige el procesador 286, 386, 486 o 586 a simular.
-A
arrancar desde el disco flexible A (no tiene que ser un disco flexible real, ver más abajo)
-B
arrancar desde el disco flexible B (no tiene que ser un disco flexible real, ver más abajo)
-C
arrancar desde el disco duro C (no tiene que ser un disco duro real o incluso un sistema de archivos msdos, ver más abajo)
-c
usar video de Consola directa (debe estar en la consola, requiere privilegios especiales y -s).
-d
desacoplarse de la consola virtual o tty actual y adjuntarse a la primera consola virtual libre
[-E] comando_dos
Ejecuta el comando DOS al iniciar DOSEMU y, si no se da '-E', sal de DOSEMU después de ejecutar el comando. El comando también se puede dar con una ruta de Linux (por ejemplo, /home/joeuser/dosemu/freedos/bin/xcopy.exe). Nota: esto solo funciona si tu autoexec.bat contiene un comando "unix -e".
-k
usar Teclado de consola RAW (debe estar en la consola)
-F
Analizar este script de configuración en lugar del archivo global.conf incorporado (necesitas ejecutarte como root en un DOSEMU suid para esto)
--Fusers
Omitir dosemu.users y tomar este archivo en su lugar (solo se acepta cuando dosemu.bin *no* es suid-root).
--Flibdir
Omitir el DOSEMU_LIB_DIR predeterminado (como quizás se define en dosemu.users) y usar este directorio en su lugar.
--Fimagedir
Omitir el directorio predeterminado para el directorio de arranque y las imágenes de disco duro (DOSEMU_HDIMAGE_DIR) y usar este directorio en su lugar.
-f
Analizar este archivo de configuración en lugar de .dosemurc
-n
Omitir (no usar) dosemu.users y dosemu.conf (solo se acepta cuando dosemu.bin *no* es suid-root).
-u
establecer una variable de configuración de usuario. Se antepone un prefijo u_ al nombre para evitar conflictos de nombres. Esta variable se puede comprobar luego en dosemu.conf o global.conf para realizar una configuración especial.
-L
Cargar y ejecutar un archivo DEXE (imagen de disco duro especial preconfigurada y arrancable que contiene solo una aplicación DOS)
-I
Analizar la cadena detrás de -I con la misma sintaxis que global.conf o .dosemurc, como
dos ... -I 'video { mda }'

Esto es útil si solo deseas anular un parámetro de configuración dado temporalmente. También puedes tener una configuración genérica ejecutando un script como

dos ... -I "`myconf.sh`"

donde myconf.sh es un script que escribe la configuración en stdout. Si tienes un archivo de configuración alternativo además de .dosrc,

dos ... -I "`cat myother.conf`"

hará el trabajo. Ten en cuenta, sin embargo, que debes comillar el parámetro detrás de -I porque se espera que sea *un* argumento.

-i[directorio_arranque]
lanzado como parte de una instalación en todo el sistema, esta opción (re)instala un DOS que se utiliza en DOSEMU (este puede ser el FreeDOS distribuido por DOSEMU o cualquier DOS propietario, que se puede arrancar a través de fatfs). directorio_arranque es el nombre base de un directorio. El enlace simbólico ~/.dosemu/drives/c se cambiará para que apunte a este directorio. La reinstalación rara vez es necesaria, ya que en la práctica los enlaces simbólicos apuntarán automáticamente a archivos actualizados.
-D
especifica qué mensajes de Depuración permitir/suprimir
-h
descarga la configuración a stderr y sale (implícitamente establece -D+c). Esto es útil para depurar archivos de configuración, debes usar también -O para dirigir los mensajes tipo +c a stderr. `nivel' puede ser 0, 1 o 2 y controla la cantidad de salida de depuración del analizador de configuración: Sin depuración del analizador (0), depuración del bucle del analizador (1), depuración if_else_endif (2).
-H
especifica las banderas de soporte de dosdebug, actualmente solo `1' es razonable. con -H1 obligas a dosemu a esperar hasta que la terminal dosdebug se conecte. Por lo tanto, para depurar una sesión DOS desde el principio, primero inicias dosemu con -H1 y luego inicias dosdebug. DOSEMU entonces se bloqueará antes de saltar al sector de arranque cargado, esperando a que dosdebug se conecte. Una vez conectado, estarás en estado 'detenido' y podrás establecer puntos de interrupción o ejecutar paso a paso el código de arranque.
-M
establece la memoria base en TAMAÑO Kilobytes
-m
alternar el soporte interno del ratón
-O
usar stderr para la salida de mensajes de Depuración
-o
usar este archivo para la salida de mensajes de Depuración
-P
copiar la salida de depuración a ARCHIVO
-p
detenerse para solicitar confirmación si se detecta un problema de configuración no fatal
-S
ejecutar usando SDL
-s
modo superusuario/todas las funciones: habilita el acceso directo al hardware. Usa este interruptor si deseas usar gráficos en la consola, necesitas acceso directo a puertos, interrupciones de hardware o acceso a red en bruto. Implica -V y -k por defecto
-t
detectar automáticamente la terminal de Linux y el TTY de video correspondiente.
-u
ignorar la configuración de usuario (archivo .dosemurc).
-V
modo de servidor X: usar el servidor X (X11) en lugar de la consola directa. Por defecto, dosemu entra en modo de servidor X cuando se le llama desde un entorno X.
-w
en modo de servidor X, evita que la ventana X tome el foco de entrada automáticamente. En modo de consola, esta opción no tiene ningún efecto y siempre se ignora.
-X
forzar el modo de servidor X.

VÍDE

O

DOSEMU puede ejecutarse en cualquier dispositivo tty. Sin embargo, se puede obtener un mayor rendimiento y funcionalidad aprovechando características especiales de la consola de Linux. Aquellos que ejecuten DOSEMU en la consola pueden desear investigar los -c, -k y -V interruptores, explicados con más detalle en README.txt. También hay algo de documentación muy breve en el archivo dosemu.conf, que puede editarse según sus

necesidades.

En resumen, el uso adecuado del dispositivo de consola y los interruptores correspondiente

s permite al usuario ver un programa DOS en su color y fuente originales, sin ninguno de l
os problemas periódicos de actualización de pantalla con el código de salida tty genérico.

TECLAD

O

Aquellos que usen DOSEMU en la consola de Linux también pueden desear usar el soporte de teclado RAW. Este modo de operación, seleccionado por el -k interruptor, proporciona al usuario acceso a todo el teclado accesible bajo DOS. Cualquier combinación de las te

clas ALT, CTRL y SHIFT puede usarse para generar los có

DEPURACIÓN

Los mensajes de depuración pueden controlarse tanto en la línea de comandos como en el archivo de configuración. Eche un vistazo a la documentación dentro del archivo config.dist incluido con DOSEMU en el subdirectorio examples, para las opciones de depuración. En la línea de comandos, puede especificar qué clases de mensajes desea que dos permita. La sintaxis de esto es DOSEMU toma una opción "-D FLAGS", donde FLAGS es una cadena de letras que especifican qué opciones imprimir o suprimir. DOSEMU analiza esta cadena de izquierda a

derecha.


+ activa las siguientes opciones (estado inicial)
- desactiva las siguientes opciones
a activa/desactiva todas las opciones, dependiendo del indicador
0 desactiva todas las opciones
1-9 establece el nivel de depuración, cuanto más alto, más salida
# donde # es una letra de la lista de clases válidas,
desactiva/activa esa opción dependiendo del
estado

+/-.

Clases de

Mensajes:


d disco R lectura de disco W escritura de disco
D int 21h C cdrom v vídeo
X soporte X k teclado i E/S de puerto
s serie m ratón # ints por defecto
p impresora g general c configuración
w advertencia h hardware I IPC
E EMS x XMS M DPMI
n red IPX P controlador de paquetes S SONIDO
r PIC T trazado de E/S Z PCI-BIOS
A controlador ASPI Q controlador de

mapeo

Cualquier clase de depuración que siga a un + carácter, hasta un - carácter, será activada (no suprimida). Cualquier después de un - carácter, hasta un + carácter, será suprimida. El carácter a actúa como una cadena de todas las clases de depuración posibles, así que +a activa todos los mensajes de depuración, y -a desactiva todos los mensajes de depuración. Los caracteres 0 y 1-9 también son especiales: 0 desactiva todos los mensajes de depuración, y 1-9 activa todos los mensajes de depuración, pero también establece el nivel de

depuración.

Se asume un + al principio de la cadena FLAGS. Algunas clases, como error, no pueden desactivarse. En caso de que no haya redirigido stderr, casi toda la salida a stderr va a /dev/null

.

Algunos ejemplos:
"-D+a-v" o "-D1-v" : todos los mensajes excepto vídeo
"-D+kd" : por defecto + teclado y disco
"-D0+RW" : solo LECTURA y ESCRITURA de

disco

Cualquier letra de opción puede aparecer en cualquier lugar. Incluso combinaciones sin sentido, como -D01-a-1+0, se analizarán sin error, así que tenga cuidado. Algunas opciones están establecidas por defecto, algunas están limpias. Esto está sujeto

a mi capricho, y probablemente cambiará entre versiones. Puede asegurar
se de cuáles están establecidas especificándolas siempre explícitamente.
