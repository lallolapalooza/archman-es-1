--destroy

Elimina el contenedor original que estamos clonando una vez utilizado para imitar la configuración.

--device-read-bps=ruta:velocidad

Limita la velocidad de lectura (en bytes por segundo) desde un dispositivo (por ejemplo, --device-read-bps=/dev/sda:1mb).

En algunos sistemas, cambiar los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, consulta https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas cgroups V1 sin root.

--device-write-bps=ruta:velocidad

Limita la velocidad de escritura (en bytes por segundo) hacia un dispositivo (por ejemplo, --device-write-bps=/dev/sda:1mb).

En algunos sistemas, cambiar los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, consulta https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas cgroups V1 sin root.

--force, -f

Fuerza la eliminación del contenedor original que estamos clonando. Solo puede usarse en conjunto con --destroy.

--memory, -m=número[unidad]

Límite de memoria. Una unidad puede ser b (bytes), k (kibibytes), m (mebibytes), o g (gibibytes).

Permite restringir la memoria disponible para un contenedor. Si el host admite memoria swap, entonces la configuración de memoria -m puede ser mayor que la RAM física. Si se especifica un límite de 0 (sin usar -m), la memoria del contenedor no está limitada. El límite real puede redondearse al múltiplo del tamaño de página del sistema operativo (el valor es muy grande, son millones de billones).

Esta opción no es compatible con sistemas cgroups V1 sin root.

Si no se especifican límites de memoria, se utilizan los límites de memoria del contenedor original.

--memory-reservation=número[unidad]

Límite suave de memoria. Una unidad puede ser b (bytes), k (kibibytes), m (mebibytes), o g (gibibytes).

Después de establecer la reserva de memoria, cuando el sistema detecta contención de memoria o poca memoria, los contenedores se ven obligados a restringir su consumo a su reserva. Por lo tanto, establece siempre el valor por debajo de --memory, de lo contrario, el límite duro tiene prioridad. Por defecto, la reserva de memoria es igual al límite de memoria.

Esta opción no es compatible con sistemas cgroups V1 sin root.

Si no se especifica, la reserva de memoria es igual al límite de memoria del contenedor que se está clonando.

--memory-swap=número[unidad]

Un valor límite igual a memoria más swap. Una unidad puede ser b (bytes), k (kibibytes), m (mebibytes), o g (gibibytes).

Debe usarse con el indicador -m (--memory). El valor del argumento debe ser mayor que el de
-m (--memory). Por defecto, se establece al doble del valor de --memory.

Establece número en -1 para habilitar swap ilimitado.

Esta opción no es compatible con sistemas cgroups V1 sin root.

Si no se especifica, se utiliza el contenedor que se está clonando para derivar el valor de swap.

--memory-swappiness=número

Ajusta el comportamiento de swappiness de memoria de un contenedor. Acepta un entero entre 0 y 100.

Este indicador solo es compatible con sistemas cgroups V1 con root.

--name

Establece un nombre personalizado para el contenedor clonado. El valor predeterminado, si no se especifica, tiene la sintaxis: <NOMBRE_ORIGINAL>-clone

--pod=nombre

Clona el contenedor en un pod existente. Es útil para mover un contenedor a un pod existente. El contenedor se une a los espacios de nombres compartidos del pod, perdiendo su configuración que entra en conflicto con los espacios de nombres compartidos.

--run

Cuando se establece en true, este indicador ejecuta el contenedor recién creado después de que el proceso de clonación se haya completado, esto especifica un modo de ejecución desprendido.

Clona el contenedor especificado en un nuevo contenedor:

# podman container clone d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584

Clona el contenedor especificado en un contenedor con un nuevo nombre:

# podman container clone --name=clone d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584

Reemplaza el contenedor especificado con las restricciones de recursos seleccionadas en un nuevo contenedor, eliminando el contenedor original:

# podman container clone --destroy --cpus=5 d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584
