NOMBRE

podman-remote - Un CLI remoto para Podman: Una herramienta de gestión simple para pods, contenedores e imágenes.

SINOPSIS

podman-remote [opciones] comando

DESCRIPCIÓN

Podman (Pod Manager) es un motor de contenedores con todas las funciones que es una herramienta simple sin demonio. Podman proporciona una línea de comandos comparable a la de Docker-CLI que facilita la transición desde otros motores de contenedores y permite la gestión de pods, contenedores e imágenes. En pocas palabras: alias docker=podman. La mayoría de los comandos de Podman se pueden ejecutar como un usuario normal, sin requerir privilegios adicionales.

Podman utiliza Buildah(1) internamente para crear imágenes de contenedor. Ambas herramientas comparten el almacenamiento de imágenes (no de contenedores), por lo que cada una puede usar o manipular imágenes (pero no contenedores) creadas por la otra.

Podman-remote proporciona un cliente local que interactúa con un nodo backend de Podman a través de una API RESTful tunelizada mediante una conexión SSH. En este contexto, un nodo Podman es un sistema Linux con Podman instalado y el servicio de API activado. Las credenciales para esta sesión se pueden pasar usando indicadores, variables de entorno o en containers.conf.

El archivo containers.conf se coloca bajo $HOME/.config/containers/containers.conf en Linux y Mac, y %APPDATA%\containers\containers.conf en Windows.

podman [OPCIONES GLOBALES]

OPCIONES GLOBALES

--connection=nombre, -c

Nombre de la conexión remota

Anula la variable de entorno CONTAINER_CONNECTION si está establecida.

--help, -h

Imprime la declaración de uso

--identity=ruta

Ruta al archivo de identidad SSH. Si el archivo de identidad ha sido cifrado, Podman solicita al usuario la frase de contraseña. Si no se proporciona ningún archivo de identidad y no se especifica ningún usuario, Podman utiliza por defecto el usuario que ejecuta el comando podman. Podman solicita la contraseña de inicio de sesión en el servidor remoto.

Precedencia de resolución del valor de identidad:
- valor de la línea de comandos
- variable de entorno CONTAINER_SSHKEY, si se encuentra CONTAINER_HOST
- containers.conf

--log-level=nivel

Registra mensajes por encima del nivel especificado: debug, info, warn, error (por defecto), fatal o panic

--url=valor

URL para acceder al servicio Podman (por defecto desde containers.conf, rootless "unix:///run/user/$UID/podman/podman.sock" o como root "unix:///run/podman/podman.sock).

  • CONTAINER_HOST tiene el formato <schema>://[<usuario[:<contraseña>]@]<host>[:<puerto>][<ruta>]
  • CONTAINER_PROXY tiene el formato <socks5|socks5h>://[<usuario[:<contraseña>]@]<host>[:<puerto>]

Detalles:
- schema es uno de:
* ssh (por defecto): un socket unix(7) local en el host y puerto especificados, accesible a través de SSH
* tcp: una conexión TCP no cifrada y no autenticada al host y puerto especificados, puede funcionar con proxy si CONTAINER_PROXY está establecido
* unix: un socket unix(7) local en la ruta especificada, o el valor por defecto para el usuario
- usuario por defecto es root o el usuario que se está ejecutando actualmente (solo ssh)
- contraseña no tiene valor por defecto (solo ssh)
- host debe ser proporcionado y es la IP o el nombre de la máquina que aloja el servicio Podman (ssh y tcp)
- puerto por defecto es 22 (ssh y tcp)
- ruta por defecto es /run/podman/podman.sock, o /run/user/$UID/podman/podman.sock si se ejecuta sin root (unix), o debe especificarse explícitamente (ssh)
- CONTAINER_PROXY: usar proxy (socks5 o socks5h) para acceder al servicio Podman (solo tcp)

Precedencia de resolución del valor de URL:
- valor de la línea de comandos
- variable de entorno CONTAINER_HOST
- tabla engine.service_destinations en containers.conf, excluyendo el directorio /usr/share/containers
- unix:///run/podman/podman.sock

Las conexiones remotas usan el containers.conf local para el valor por defecto.

Algunos ejemplos de valores de URL en formatos válidos:
- unix:///run/podman/podman.sock
- unix:///run/user/$UID/podman/podman.sock
- ssh://notroot@localhost:22/run/user/$UID/podman/podman.sock
- ssh://root@localhost:22/run/podman/podman.sock
- tcp://localhost:34451
- tcp://127.0.0.1:34451

Variables de Entorno

Podman puede configurar variables de entorno desde la tabla env de [engine] en containers.conf. Estas variables se pueden anular pasando variables de entorno antes de los comandos de podman.

CONTAINERS_CONF

Establece las ubicaciones por defecto del archivo containers.conf

CONTAINER_CONNECTION

Establece el valor por defecto de --connection para acceder al servicio Podman.

CONTAINER_HOST

Establece el valor por defecto de --url para acceder al servicio Podman.

CONTAINER_SSHKEY

Establece la ruta por defecto del archivo de clave SSH para el valor --identity utilizada para acceder al servicio Podman.

Códigos de Salida

La salida de podman proporciona información sobre por qué el contenedor no se ejecutó o por qué salió. Cuando los comandos de podman salen con un código distinto de cero, los códigos de salida siguen el estándar de chroot, véase a continuación:
