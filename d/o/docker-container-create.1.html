Los sistemas de etiquetado como SELinux requieren que se coloquen etiquetas adecuadas en el contenido del volumen montado en un contenedor. Sin una etiqueta, el sistema de seguridad podría impedir que los procesos que se ejecutan dentro del contenedor usen el contenido. Por defecto, Docker no cambia las etiquetas establecidas por el SO. Para cambiar una etiqueta en el contexto del contenedor, puede añadir cualquiera de los dos sufijos :z o :Z al montaje del volumen. Estos sufijos le indican a Docker que reetiquete los objetos de archivo en los volúmenes compartidos. La opción z le indica a Docker que dos contenedores comparten el contenido del volumen. Como resultado, Docker etiqueta el contenido con una etiqueta de contenido compartido. Las etiquetas de volumen compartido permiten a todos los contenedores leer/escribir el contenido.

La opción

Z le indica a Docker que etiquete el contenido con una etiqueta privada no compartida. Solo el contenedor actual puede usar un volumen privado. Por defecto, los volúmenes montados por enlace son privados . Eso significa que cualquier montaje hecho dentro del contenedor no será visible en el host y viceversa. Se puede cambiar este comportamiento especificando una propiedad de propagación de montaje de volumen. Hacer un volumen compartido hace que los montajes hechos bajo ese volumen dentro del contenedor sean visibles en el host y viceversa. Hacer un volumen esclavo habilita solo la propagación de montaje en una dirección, y es que los montajes hechos en el host bajo ese volumen serán visibles dentro del contenedor pero no al revés. Para controlar la propiedad de propagación de montaje de un volumen se puede usar el indicador de propagación :[r]shared , :[r]slave o

:[r]private . La propiedad de propagación solo puede especificarse para volúmenes montados por enlace y no para volúmenes internos o volúmenes con nombre. Para que la propagación de montaje funcione, el punto de montaje de origen (el punto de montaje donde se monta el directorio de origen) debe tener las propiedades de propagación correctas. Para volúmenes compartidos, el punto de montaje de origen debe ser compartido. Y para volúmenes esclavos, el montaje de origen debe ser compartido o esclavo. Us

EJEMPLO

### Especificar la tecnología de aislamiento para el contenedor (--isolation)
Esta opción es útil en situaciones donde se están ejecutando contenedores Docker en
Windows. La opción `--isolation=<valor>` establece la tecnología de
aislamiento de un contenedor. En Linux, la única opción soportada es `default` la cual usa
espacios de nombres de Linux. En Microsoft Windows, puede especificar estos valores:
* `default`: Usar el valor especificado por `--exec-opt` del demonio de Docker. Si el `daemon` no especifica una tecnología de aislamiento, Microsoft Windows usa `process` como su valor por defecto.
* `process`: Solo aislamiento por espacios de nombres.
* `hyperv`: Aislamiento basado en partición del hipervisor Hyper-V.
### Manejo de dispositivos creados dinámicamente (--device-cgroup-rule)
Los dispositivos disponibles para un contenedor se asignan en el momento de su creación.
Los dispositivos asignados se añadirán tanto al archivo cgroup.allow como se
crearán en el contenedor una vez que se ejecute. Esto plantea un problema cuando
se necesita añadir un nuevo dispositivo a un contenedor en ejecución.
Una de las soluciones es añadir una regla más permisiva a un contenedor
permitiéndole el acceso a una gama más amplia de dispositivos. Por ejemplo, suponiendo
que nuestro contenedor necesita acceso a un dispositivo de caracteres con mayor `42`
y cualquier número de número menor (añadido a medida que aparezcan nuevos dispositivos), se
añadiría la siguiente regla:
```console
$ docker create --device-cgroup-rule='c 42:* rmw' --name my-container my-image

Luego, un usuario podría pedir udev que ejecute un script que ejecutaría docker exec my-container mknod newDevX c 42 <minor> para crear el dispositivo requerido cuando se añada.

NOTA: los dispositivos inicialmente presentes todavía necesitan ser añadidos explícitamente al comando create/run

```
