NOMBRE

podman-machine-init - Inicializa una nueva máquina virtual

SINOPSIS

podman machine init [opciones] [nombre]

DESCRIPCIÓN

Inicializa una nueva máquina virtual para Podman.

El nombre de máquina por defecto es podman-machine-default. Si un nombre de máquina no se especifica como argumento, entonces la nueva máquina se llamará podman-machine-default.

Solo sin raíz (rootless).

Podman en MacOS y Windows requiere una máquina virtual. Esto es porque los contenedores son de Linux - los contenedores no se ejecutan en ningún otro SO porque la funcionalidad principal de los contenedores está ligada al kernel de Linux. La máquina de Podman debe usarse para gestionar máquinas MacOS y Windows, pero puede usarse opcionalmente en Linux.

podman machine init inicializa una nueva máquina virtual de Linux donde se ejecutan los contenedores. Las claves SSH se generan automáticamente para acceder a la VM, y se añaden conexiones de sistema a la cuenta raíz y a una cuenta de usuario dentro de la VM.

Por defecto, la distribución de la VM es una imagen personalizada basada en Fedora CoreOS subida a quay.io/podman/machine-os (compilada en https://github.com/containers/podman-machine-os). WSL es una excepción y está basada en una imagen personalizada de Fedora.

Para comprobar si hay una actualización disponible para tu sistema operativo de la máquina, puedes ejecutar el siguiente comando:

$ podman machine ssh 'sudo rpm-ostree upgrade --check'

Si hay una actualización disponible, puedes volver a ejecutar el comando anterior y eliminar el --check y tu sistema operativo será actualizado. Después de actualizar, debes detener y arrancar tu máquina con podman machine stop && podman machine start para que surta efecto.

El mecanismo anterior solo se usa para actualizar versiones de parche (Z) de podman. Para actualizaciones a nuevas versiones principales y menores (X.Y) usa el podman machine os apply comando, consulta la documentación allí para más información.

Nota: Actualizar como se describe arriba puede resultar en discrepancias de versión entre Podman en el host y Podman en la máquina. Ejecutar podman info debería revelar las versiones de ambos. Una configuración donde el host de Podman y la máquina discrepan no está soportada.

Para actualizar la imagen de WSL debes ejecutar dnf update dentro, usa el siguiente comando:

$ podman machine ssh dnf update

Los ajustes por defecto de la máquina de Podman pueden establecerse a través de la sección [machine] en el archivo containers.conf(5).

OPCIONES

--cpus=número

Número de CPUs.

--disk-size=número

Tamaño del disco para la VM invitada en GiB.

--help

Imprime la declaración de uso.

--ignition-path

Ruta completamente calificada del archivo de ignition.

Si se proporciona un archivo de ignition, el archivo se copia en el CONF_DIR del usuario y se renombra. Además, no se generan claves SSH, ni se realizan conexiones de sistema. Se asume que el usuario hace estas cosas manualmente o las gestiona de otra forma.

--image

Registro, ruta o URL completamente calificados para una imagen de VM. El destino del registro debe estar en la forma de docker://registro/repo/imagen:versión.

Nota: Solo se soportarán las imágenes proporcionadas por podman.

--memory, -m=número

Memoria (en MiB). Nota: 1024MiB = 1GiB.

--now

Arranca la máquina virtual inmediatamente después de que haya sido inicializada.

--playbook

Añade el playbook de Ansible proporcionado a la máquina y lo ejecuta después del primer arranque.

Nota: El playbook se ejecutará con los mismos privilegios dados al usuario en la máquina virtual. El playbook proporcionado no puede incluir otros archivos del sistema host, ya que no serán copiados. El uso del --playbook indicador requerirá que la imagen incluya Ansible. La imagen por defecto proporcionada tendrá Ansible incluido.

--rootful

Si esta máquina prefiere ejecución de contenedores con raíz (true) o sin raíz (false). Esta opción determina la conexión remota por defecto si no hay configuraciones de conexión remota existentes.

El reenvío de API, si está disponible, sigue esta configuración.

--swap, -s=número

Swap (en MiB). Nota: 1024MiB = 1GiB.

Genera un archivo zram-generator.conf con zram-size establecido al valor pasado a --swap

--timezone

Establece la zona horaria para la máquina y los contenedores. Los valores válidos son local o una zona horaria como America/Chicago. Un valor de local, que es el valor por defecto, significa usar la zona horaria de la máquina host.

La configuración de zona horaria no se usa con WSL. WSL establece automáticamente la zona horaria a la misma que el sistema operativo host de Windows.

--tls-verify

Requiere HTTPS y verifica certificados al contactar con registros (por defecto: true). Si se establece explícitamente a true, se usa la verificación TLS. Si se establece a false, no se usa la verificación TLS. Si no se especifica, se usa la verificación TLS a menos que el registro de destino esté listado como un registro inseguro en containers-registries.conf(5)

--usb=bus=número,devnum=número o vendor=hexadecimal,product=hexadecimal

Asigna un dispositivo USB del host a la VM a través de passthrough USB. Solo soportado para Máquinas QEMU.

El dispositivo necesita tener los permisos adecuados para ser pasado a la máquina. Esto significa que el dispositivo necesita estar bajo tu grupo de usuario.

Ten en cuenta que usar el número de bus y dispositivo es más simple pero los valores pueden cambiar en cada arranque o cuando el dispositivo se desconecta.

Al especificar un USB usando los IDs de vendor y product, si más de un dispositivo tiene el mismo vendor y product ID, se asigna el primer dispositivo disponible.

--user-mode-networking

Esta opción solo puede usarse para el proveedor WSL en Windows. En todas las demás plataformas esta opción se ignora y el modo de usuario de red siempre será true allí porque estos proveedores siempre dependen de gvproxy (nuestra herramienta de red en modo de usuario para las VMs)

En contraste, el backend Windows/WSL tiene por defecto false, y sigue la configuración de red estándar de WSL. Cambiar esta configuración a true en Windows/WSL informa a Podman para reemplazar la configuración de red de WSL al arrancar esta instancia de máquina con una distribución de red en modo de usuario. Dado que WSL comparte el mismo kernel entre distribuciones, todas las demás distribuciones en ejecución reutilizan esta red. Del mismo modo, cuando la última instancia de máquina con una true configuración se detiene, se restaura la configuración de red original.

En algunas configuraciones de VPN, la VPN puede descartar tráfico de interfaces de red alternativas, incluyendo dispositivos de red de VM. Al habilitar la red en modo de usuario, las VPNs observan todo el tráfico de la máquina de podman como proveniente del host, evitando el problema.

--username

Nombre de usuario para usar al ejecutar comandos en la VM remota. El valor por defecto es core para FCOS y user para Fedora (por defecto en hosts de Windows). Debería coincidir con el usado dentro de la imagen de VM resultante.

--volume, -v=origen:destino[:opciones]

Monta un volumen de origen a destino.

Crea un montaje. Si /host-dir:/machine-dir se especifica como el *origen:destino*, Podman monta host-dir en el host a machine-dir en la máquina de Podman.

Se pueden especificar opciones adicionales como una cadena separada por comas. Las opciones reconocidas son: * ro: montar volumen de solo lectura * * rw: montar volumen de lectura/escritura (por defecto) * * security_model=[modelo]: especificar el modelo de seguridad 9p (ver abajo)

Nota: Los siguientes destinos están prohibidos para volúmenes: /bin, /boot, /dev, /etc, /home, /proc, /root, /run, /sbin, /sys, /tmp, /usr, y /var. Los subdirectorios de estos destinos están permitidos pero los usuarios deberían tener cuidadoreful de no montar en directorios importantes, ya que pueden ocurrir resultados inesperados.

El modelo de seguridad de 9p [determina] https://wiki.qemu.org/Documentation/9psetup#Starting_the_Guest_directly si y cómo el sistema de archivos 9p traduce algunas operaciones del sistema de archivos antes del almacenamiento real en el host.

Para permitir que los enlaces simbólicos funcionen, en MacOS el modelo de seguridad predeterminado es
none.

El valor de mapped-xattr especifica que 9p almacena enlaces simbólicos y algunos atributos de archivo como atributos extendidos en el host. Esto es adecuado cuando el host y el huésped no necesitan interoperar en el sistema de archivos compartido, pero tiene advertencias para el acceso compartido real; en particular, los enlaces simbólicos en el host no son utilizables en el huésped y viceversa. Si se requiere interoperabilidad, elija none en su lugar, pero tenga en cuenta que el huésped no puede hacer cosas que el usuario que ejecuta la máquina virtual no puede hacer, por ejemplo, crear archivos propiedad de otro usuario. Usar none es casi con certeza la mejor opción para volúmenes de solo lectura.

Ejemplo: -v "$HOME/git:$HOME/git:ro,security_model=none"

Los montajes de volumen predeterminados se definen en containers.conf. A menos que se cambien, los valores predeterminados son $HOME:$HOME.

Nota sobre Windows Subsystem for Linux (WSL) Dado que todas las unidades se montan en /mnt en el inicio de forma predeterminada en WSL, pasar --volume es redundante y no tiene efecto. El directorio de inicio del host para una unidad C: se montará en /mnt/c/Users/<mi nombre de usuario>.

EJEMPLOS

Inicializar la máquina Podman predeterminada, descargando el contenido de internet.

$ podman machine init

Inicializar una máquina Podman con el nombre especificado descargando el contenido de internet.

$ podman machine init myvm

Inicializar e iniciar una nueva máquina Podman en un solo paso.

podman machine init --now

Inicializar la máquina Podman predeterminada descargando el contenido de internet, usando el modo rootful de forma predeterminada. El modo predeterminado es rootless.

$ podman machine init --rootful

Inicializar la máquina Podman predeterminada, sobrescribiendo su tamaño de disco, descargando el contenido de internet.

$ podman machine init --disk-size 50

Inicializar la máquina Podman especificada, sobrescribiendo su tamaño de memoria, descargando el contenido de internet.

$ podman machine init --memory=1024 myvm

Inicializar la máquina Podman predeterminada con el directorio del host /Users montado en la VM en /Users.

$ podman machine init -v /Users:/Users

Inicializar la máquina Podman predeterminada con un dispositivo usb pasado a través especificado con opciones. Solo soportado para máquinas QEMU.

$ podman machine init --usb vendor=13d3,product=5406

Inicializar la máquina Podman predeterminada con un dispositivo usb pasado a través especificado con opciones. Solo soportado para máquinas QEMU.

$ podman machine init --usb bus=1,devnum=3
