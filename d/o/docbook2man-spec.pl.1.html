NOMBRE

docbook2man-spec.pl - convertir RefEntries de DocBook a páginas man

SINOPSIS

sgmlspl docbook2man-spec.pl

nsgmls [ documento sgml ]| sgmlspl docbook2man-spec.pl

DESCRIPCIÓN

docbook2man es un archivo de especificación de sgmlspl que produce páginas man (usando las macros -man) a partir de marcado RefEntry de DocBook.

El programa lee ESIS producido por nsgmls (u otros analizadores SGML) de la entrada estándar. El marcado no encontrado en RefEntry se descarta.

Su salida, las páginas man convertidas, se escribe en el directorio actual. Si no se especifica información de RefMeta en una RefEntry, la página man se escribirá en la salida estándar.

El archivo manpage.links también se creará, que contiene los alias de las páginas man generadas. Este archivo tiene el formato:

<página man> <alias
    página man>

El archivo manpage.refs realiza un seguimiento de las referencias XRef. Tenga en cuenta que si el documento de entrada tiene referencias futuras, es posible que docbook2man tenga que invocarse dos veces (la primera vez actualizando manpage.refs) para resolverlas.

REQUISITOS

El paquete SGMLSpm de CPAN. Este paquete incluye el script sgmlspl que también se necesita.

LIMITACIONES

Intentar usar docbook2man en SGML no-DocBook o no conforme resulta en un comportamiento indefinido. :-)

Este programa es un script de Perl lento y dudoso.

Este programa no se acerca a admitir todo el marcado posible en DocBook, y puede producir resultados incorrectos en algunos casos con el marcado admitido.

EN CONSTRUCCIÓN

Cosas obvias:

•
Corregir los fallos de docbook2man encontrados en los documentos de prueba, especialmente weird.sgml.
•
Añadir manejo de nuevos elementos y corregir el manejo existente. Ser robusto.
•
Producir la salida man más limpia y legible posible (a diferencia de otros conversores). Seguir la convención man(7) de Linux. Como la conversión a páginas man generalmente no se realiza muy a menudo, es mejor ser más lento/más complicado que producir resultados incorrectos. Además, si alguien decide dejar de usar DocBook por cualquier motivo, las páginas man convertidas por última vez pueden mantenerse manualmente.
•
Hacerlo más rápido. Creo que la mayoría de los problemas de velocidad hasta ahora se deben al análisis de ESIS. Reescribir SGMLS.pm en C y/o obtener entrada directamente de SP.
•
Soportar otros idiomas (humanos). Pero ¿qué hacer con los juegos de caracteres no ASCII? SGMLSpm no los informa y roff no los entiende. [Comentario: el texto después de las listas cerradas (y los bloques SS) romperá docbook2man] Si hacemos esto, más gente podrá usar DocBook.
