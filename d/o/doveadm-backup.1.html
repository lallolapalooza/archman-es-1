DESCRIPCIÓ

N

dsync (abreviatura de doveadm sync) es la función de sincronización de buzones de Dovecot. Se puede utilizar para varios casos de uso diferentes: sincronización bidireccional de buzones, creación de copias de seguridad de correos y conversión de buzones desde/hacia diferentes formatos de buzón. Todos estos se pueden utilizar dentro del mismo servidor o entre diferentes servidores (a través de ssh(1) o conexiones tcp). Los buzones remotos también se pueden acceder a través del protocolo IMAP, lo que permite usar

dsync

para la migración de buzones. Puede

ejecutar
  • dsync en uno de tres modos: doveadm backup realiza una sincronización unidireccional. Si hay cambios en el destino, se revertirán, de modo que el destino se verá exactamente como el
    • origen.
  • doveadm sync realiza una sincronización bidireccional. Fusiona todos los cambios sin perder nada. Ambos buzones quedarán idénticos después de que finalice la sincronización. doveadm sync -1 realiza
    • una
  • sincronización unidireccional. Si hay cambios en el destino, se conservarán y los nuevos cambios se fusionarán sobre ellos. Esta fusión actualmente no funciona perfectamente, por lo que su uso debe ser limitado. Su propósito principal es que durante la migración de buzones puede ejecutar doveadm backup varias veces, luego cambiar los correos para que se entreguen al nuevo buzón y ejecutar doveadm sync -1 una vez más para transferir cualquier último correo nuevo del buzón antiguo. • El algoritmo un

Usar esta opción en combinación con usuarios del sistema de userdb { driver = passwd } no se recomienda, porque contiene también usuarios con un UID más bajo que el configurado con ffirst_valid_uid configuración.

-F archivo

Ejecuta el comando para todos los usuarios en el archivo. Esto es similar a la opción -A , pero en lugar de obtener la lista de usuarios de la base de datos de usuarios (userdb), se leen del archivo dado. El archivo contiene un nombre de usuario por línea.

-1

Realiza una sincronización unidireccional en lugar de bidireccional.

-f

Realiza una sincronización completa.

-N

Sincroniza todos los espacios de nombres disponibles. Por defecto, solo se sincroniza el espacio de nombres inbox=yes.

--no-userdb-lookup

No realiza la búsqueda en la base de datos de usuarios (userdb). Usa la variable de entorno USER para especificar el nombre de usuario.

-P

Ejecuta un doveadm-purge(1) en el almacenamiento de destino (remoto) después de la sincronización.

-R

Realiza una sincronización inversa. Normalmente, los mensajes se enviarían desde el sistema local al destino (remoto). Esta opción invierte el flujo y, en su lugar, traerá los mensajes del remoto al almacenamiento local.

-S ruta_del_socket

El argumento de la opción es o bien una ruta absoluta a un socket de dominio UNIX local, o un nombre de host y puerto (nombre_de_host:puerto), para conectarse a un host remoto a través de un socket TCP.

Esto permite a un administrador ejecutar comandos de correo de doveadm(1) a través del socket dado.

-T segs

Especifica el tiempo en segundos que doveadm(1) debe esperar por operaciones de E/S estancadas. El tiempo de espera predeterminado es 600 segundos.

-p configuración=valor

Anula la configuración para el almacenamiento de origen.

-g guia_del_buzón

Igual que -m, pero encuentra el buzón a sincronizar por su GUID en lugar de por su nombre.

-l segs

Bloquea el dsync para este usuario. Espera un máximo de segs antes de rendirse. Este parámetro debe usarse para evitar una sincronización rota si es posible que dsync se esté ejecutando concurrentemente para el mismo usuario.

-m buzón

Sincroniza solo este nombre de buzón.

-n espacio_de_nombre

Sincroniza solo el espacio de nombres especificado. Este parámetro puede usarse varias veces.

-a todos_los_buzones

Nombre para el buzón virtual "Todos los correos". Si se especifica, se intentará copiar los correos de este buzón en lugar de guardarlos por separado. Esto puede reducir el uso total de espacio en disco, así como las operaciones de E/S de disco.

-t fecha_inicio

Omite cualquier correo cuya marca de tiempo de recepción sea anterior a la hora especificada.

-e fecha_fin

Omite cualquier correo cuya marca de tiempo de recepción sea posterior a la hora especificada.

-O marca_de_sincronización

Sincroniza solo los correos que tienen la marca especificada. Si el nombre de la marca comienza con "-", sincroniza todos los correos excepto los que tienen la marca especificada.

-I tamaño_máx

Omite cualquier correo mayor que el tamaño especificado.

-r ruta_del_registro_bruto

Al ejecutar dsync de forma remota, escribe el tráfico de entrada/salida remoto en el archivo de registro especificado.

-s estado_anterior

Usa una sincronización con estado. Si el estado anterior es desconocido, usa una cadena vacía. El nuevo estado siempre se imprime en la salida estándar.

-u usuario/máscara

Ejecuta el comando solo para el usuariodado. También es posible usar los comodines '*' y '?' (por ejemplo, -u *@example.org).

-x máscara_del_buzón

Excluye el nombre/máscara de buzón especificado. La máscara puede contener los comodines "?" y "*****". La máscara también puede ser un nombre de uso especial (por ejemplo, \Trash). Este parámetro puede usarse varias veces.

ARGUMENTOS

destino

Este argumento especifica el destino de la sincronización.

Puede ser uno de los siguientes:

controlador_de_correo:ruta_del_correo : Usa el almacenamiento especificado por controlador_de_correo y ruta_del_correo. Usa el parámetro -p para especificar configuraciones adicionales.

remoto: usuario@host : Usa la configuración dsync_remote_cmd para conectarse al host remoto (normalmente a través de ssh)

prefijo_remoto:usuario@host : Esto es lo mismo que remoto, excepto que se envía "usuario@dominio\n" antes de que comience el protocolo dsync. Esto permite implementar un script envoltorio de confianza que ejecute doveadm dsync-server leyendo el nombre de usuario de la primera línea.

tcp: host[:puerto] : Se conecta al servidor doveadm remoto a través de TCP. El puerto predeterminado lo especifica la configuración doveadm_port .

tcps: host[:puerto] : Esto es lo mismo que tcp, pero con SSL.

comando [arg1 [, arg2, ...]] : Ejecuta un comando local que conecta su entrada y salida estándar a un servidor dsync.

ESTADO DE SALIDA

dsync saldrá con uno de los siguientes valores:

0

La sincronización se realizó perfectamente.

2

La sincronización se realizó sin errores, pero algunos cambios no pudieron realizarse, por lo que los buzones no están perfectamente sincronizados. Ejecutar dsync de nuevo generalmente soluciona esto. Esto ocurre típicamente con las secuencias de modificación de mensajes en buzones recién creados. También puede ocurrir si uno de los buzones cambia durante la sincronización.

1, >2

La sincronización falló.

Consulte también doveadm(1) para otros códigos de error posibles.

EJEMPLO

SINCRONIZACIÓN

Sincroniza buzones con un servidor remoto. Cualquier error se escribe en stderr:

doveadm sync -u usuario@example.com remoto:server-replica.example.com

Si necesita parámetros más complejos para ssh, puede usar, por ejemplo:

doveadm sync -u usuario@example.com ssh -i id_dsa.dovecot \
  mailuser@example.com doveadm dsync-server -u usuario@example.com

CONVERSIÓN

Ejemplo para convertir correos del formato Maildir al formato especificado en el archivo de configuración:

doveadm backup -u usuario maildir:~/Maildir

Si desea hacer esto sin ningún tiempo de inactividad, puede realizar la conversión un usuario a la vez. Inicialmente:

  • La configuración usa mail_driver = maildir y mail_path = ~/Maildir
  • Configure la posibilidad de usar una ubicación de correo por usuario usando campos extra de la base de datos de usuarios (userdb).

Luego, para cada usuario:

1.
Ejecute doveadm sync una vez para realizar la conversión inicial.
2.
Ejecute doveadm sync de nuevo, porque la conversión inicial pudo haber tardado un tiempo y pudieron haber ocurrido cambios nuevos durante ella. Esta segunda vez solo aplica cambios, por lo que debería ser rápida.
3.
Actualice la base de datos de usuarios (userdb) para que devuelva la configuración de formato de correo deseada. Por ejemplo: mail_driver = mdbox y mail_path = ~/mdbox. Si está usando la caché de autenticación, necesita vaciarla, por ejemplo doveadm auth cache flush.
4.
Espere unos segundos y luego finalice (doveadm kick) todas las sesiones imap y pop3 existentes del usuario (que todavía están usando maildir).
5.
Ejecute doveadm sync una vez más para aplicar los cambios finales que se hayan realizado posiblemente. Después de esto no debería haber cambios en Maildir, porque la ubicación de correo del usuario ha sido cambiada y todos los procesos existentes que la usaban han sido finalizados.

Una vez que todos los usuarios hayan sido convertidos, puede actualizar las configuraciones globales mail_driver y mail_path y eliminar las ubicaciones de correo por usuario de la base de datos de usuarios (userdb).
