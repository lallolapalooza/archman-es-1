NOMBRE

docbook2texi-spec.pl - convierte Libros DocBook a documentos Texinfo

SINOPSIS

sgmlspl docbook2man-spec.pl

nsgmls [ documento sgml ]| sgmlspl docbook2texi-spec.pl [ nombre_base ]

DESCRIPCIÓN

docbook2texi es un archivo de especificaciones de sgmlspl que produce documentos GNU Texinfo a partir de documentos DocBook.

El programa lee ESIS producido por nsgmls (u otros analizadores SGML) desde la entrada estándar. Actualmente, el elemento del documento debe ser Book, de lo contrario, los resultados no están definidos.

Su salida, el documento Texinfo convertido, se escribe en la salida estándar.

También se creará el archivo nombre_base.refs, que contiene todos los nodos del documento y sus nodos 'hijos' inmediatos. Como el procesamiento de nodos siempre requiere referencias hacia adelante, docbook2texi debe ejecutarse dos veces para cada documento: la primera vez para construir las referencias y la segunda para generar realmente un documento válido.

REQUISITOS

El paquete SGMLSpm de CPAN. Este paquete incluye el script sgmlspl que también se necesita.

LIMITACIONES

Intentar docbook2man en SGML no DocBook o no conforme resulta en un comportamiento indefinido. :-)

Este programa es un script de Perl lento y dudoso.

Este programa no se acerca a soportar todo el marcado posible en DocBook y puede producir resultados incorrectos en algunos casos con el marcado soportado.

POR HACER

•
¿Cómo demonios se representa una barra invertida (\\) en Texinfo!!@? He probado con \\ pero TeX se queja.
•
Corregir errores encontrados en los documentos de prueba.
•
Agregar manejo de nuevos elementos y corregir el manejo existente. Ser robusto.
•
Hacerlo más rápido. Creo que la mayoría de los problemas de velocidad hasta ahora se deben al análisis de ESIS. Reescribir SGMLS.pm con C y/o obtener la entrada directamente de SP.
•
Hay algunas dependencias de elementos que ocurren cuando en realidad son opcionales (según la DTD). Necesitamos corregirlo (preferiblemente) o indicar prominentemente los requisitos.
•
Permitir otros elementos de documento más comunes.
•
Separar la referencia de nodos a un script separado. No solo lo haría más rápido/fácil de mantener porque está separado del código principal, sino que también me gustaría que evolucionara en un generador automático de Tabla de Contenidos de DocBook.
