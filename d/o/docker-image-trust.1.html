NOMBRE

podman-image-trust - Gestiona la política de confianza de imágenes de registros de contenedores

SINOPSIS

podman image trust set|show [opciones] registro[/repositorio]

DESCRIPCIÓN

Gestiona en qué registros confiar como fuente de imágenes de contenedores basándose en su ubicación. (Esta opción no está disponible con el cliente Podman remoto, incluyendo máquinas Mac y Windows (excluyendo WSL2))

La ubicación está determinada por el transporte y el host del registro de la imagen. Usando esta imagen de contenedor docker://docker.io/library/busybox como ejemplo, docker es el transporte y docker.io es el host del registro.

La confianza está definida en /etc/containers/policy.json y se aplica cuando un usuario intenta obtener una imagen remota de un registro. La política de confianza en policy.json describe un ámbito de registro (registro y/o repositorio) para la confianza. Esta confianza puede usar claves públicas para imágenes firmadas.

El ámbito de la confianza se evalúa de lo más específico a lo menos específico. En otras palabras, una política puede ser:

  • Definida para un registro completo.
  • Definida para un repositorio particular en ese registro.
  • Definida para una imagen firmada específica dentro del registro.

La siguiente lista son ejemplos de valores de ámbito válidos usados en policy.json de lo más específico a lo menos específico:

docker.io/library/busybox:notlatest

docker.io/library/busybox

docker.io/library

docker.io

Si no se encuentra configuración para ninguno de estos ámbitos, se usa el valor predeterminado (especificado usando "default" en lugar de REGISTRO[/REPOSITORIO]).

La confianza type proporciona una manera de:

Poner en lista blanca ("accept") o en lista negra ("reject") registros o Requerir una firma de simple firma ("signedBy"), Requerir una firma sigstore ("sigstoreSigned").

La confianza puede actualizarse usando el comando podman image trust set para un ámbito de confianza existente.

OPCIONES

--help, -h

Imprime la declaración de uso.

set OPCIONES

--pubkeysfile, -f=CLAVE1

Una ruta a una clave pública exportada en el sistema local. Las rutas de claves se referencian en policy.json. Se puede usar cualquier ruta a un archivo pero se recomienda ubicar el archivo en
/etc/pki/containers . La opción puede usarse múltiples veces para requerir que una imagen esté firmada por múltiples claves. La
opción --pubkeysfile es requerida para los tipos signedBy y sigstoreSigned .

--type, -t=valor

El tipo de confianza para esta entrada de política.
Valores aceptados:
signedBy (predeterminado): Requiere firmas de simple firma con la lista correspondiente de
claves públicas
sigstoreSigned: Requiere firmas sigstore con la lista correspondiente de
claves públicas
accept: no requiere ninguna firma para este
ámbito de registro
reject: no acepta imágenes para este ámbito de registro

show OPCIONES

--json, -j

Salida de confianza como JSON para análisis por máquina

--noheading, -n

Omite los encabezados de la tabla del listado.

--raw

Salida del archivo de política de confianza como JSON sin procesar

EJEMPLOS

Aceptar todas las imágenes sin firmar de un registro:

sudo podman image trust set --type accept docker.io

Modificar la política de confianza predeterminada:

sudo podman image trust set -t reject default

Mostrar la política de confianza del sistema:

podman image trust show
TRANSPORTE      NOMBRE                       TIPO        ID                   ALMACÉN
all            default                      reject
repository     docker.io/library            accept
repository     registry.access.redhat.com   signed      security@redhat.com  https://access.redhat.com/webassets/docker/content/sigstore
repository     registry.redhat.io           signed      security@redhat.com  https://registry.redhat.io/containers/sigstore
repository     docker.io                    reject
docker-daemon                                accept
