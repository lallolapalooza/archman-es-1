NOMBRE

domain - resolutor de dominios de nnrpd

SINOPSIS

domain nombre-dominio

DESCRIPCIÓN

Este programa se puede utilizar en readers.conf para otorgar acceso basado en la parte del subdominio del nombre de host remoto. En particular, solo devuelve éxito si el nombre de host remoto termina en nombre-dominio. (Un punto inicial en nombre-dominio es opcional; incluso sin él, el argumento debe coincidir en los límites separados por puntos). El "nombre de usuario" devuelto es la parte inicial del nombre de host remoto que queda después de eliminar nombre-dominio. Es un error si no hay una parte inicial (es decir, si el nombre de host remoto es exactamente el nombre-dominio especificado).

EJEMPLO

El siguiente fragmento de readers.conf(5) otorga acceso a hosts con nombres de dominio internos:

auth internal {
    res: "domain .internal"
    default-domain: "example.com"
}
access internal {
    users: "*@example.com"
    newsgroups: example.*
}

Se concede acceso a los grupos example.* para todas las conexiones desde hosts cuyos nombres de host se resuelven a nombres que terminan en ".internal"; una conexión desde "foo.internal" coincidiría con los grupos de acceso como identidad "foo@example.com".

ERRORES

Parece que el código no confirma que la parte coincidente esté realmente al final del nombre de host remoto (por ejemplo, "domain: example.com" coincidiría con el host remoto "foo.example.com.org" ignorando la parte final ".org").

¿Este resolutor proporciona alguna funcionalidad útil que no esté disponible al usar comodines en el parámetro hosts de readers.conf(5)? Si es así, el ejemplo anterior debería reflejar esta funcionalidad.
