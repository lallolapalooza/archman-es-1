docker-image-pull(1)

Paquete: docker

Licencias: Apache-2.0

DOCKER(1) Manuales de usuario de Docker DOCKER(1)

NOMBRE

docker-image-pull - Descarga una imagen desde un registro

SINOPSIS

docker image pull [OPCIONES] NOMBRE[:ETIQUETA|@DIGESTO]

DESCRIPCIÓN

Este comando descarga una imagen o un repositorio desde un registro. Si hay más de una imagen para un repositorio (por ejemplo, fedora) entonces todas las imágenes para ese nombre de repositorio pueden descargarse incluyendo cualquier etiqueta (ver la opción -a o --all-tags).

Si no especifica un HOST_DEL_REGISTRO, el comando usa el registro público de Docker ubicado en registry-1.docker.io por defecto.

EJEMPLOS

Descargar una imagen desde Docker Hub

Para descargar una imagen en particular, o un conjunto de imágenes (es decir, un repositorio), use docker image pull (o la abreviatura docker pull ). Si no se proporciona una etiqueta, Docker Engine usa la etiqueta :latest como predeterminada. Este ejemplo descarga la imagen debian:latest :

$ docker image pull debian
Using default tag: latest
latest: Pulling from library/debian
e756f3fdd6a3: Pull complete
Digest: sha256:3f1d6c17773a45c97bd8f158d665c9709d7b29ed7917ac934086ad96f92e4510
Status: Downloaded newer image for debian:latest
docker.io/library/debian:latest

Las imágenes de Docker pueden consistir en múltiples capas. En el ejemplo de arriba, la imagen consiste en una sola capa; e756f3fdd6a3.

Las capas pueden ser reutilizadas por las imágenes. Por ejemplo, la imagen debian:bookworm comparte su capa con debian:latest. Descargar la imagen debian:bookworm por lo tanto solo descarga sus metadatos, pero no sus capas, porque la capa ya está presente localmente:

$ docker image pull debian:bookworm
bookworm: Pulling from library/debian
Digest: sha256:3f1d6c17773a45c97bd8f158d665c9709d7b29ed7917ac934086ad96f92e4510
Status: Downloaded newer image for debian:bookworm
docker.io/library/debian:bookworm

Para ver qué imágenes están presentes localmente, use el comando docker-images(1) :

$ docker images
REPOSITORY   TAG        IMAGE ID       CREATED        SIZE
debian       bookworm   4eacea30377a   8 days ago     124MB
debian       latest     4eacea30377a   8 days ago     124MB

Docker usa un almacén de imágenes direccionable por contenido, y el ID de la imagen es un digesto SHA256 que cubre la configuración y las capas de la imagen. En el ejemplo de arriba, debian:bookworm y debian:latest tienen el mismo ID de imagen porque son la misma imagen etiquetada con diferentes nombres. Debido a que son la misma imagen, sus capas se almacenan solo una vez y no consumen espacio de disco extra.

Para más información sobre imágenes, capas, y el almacén direccionable por contenido, consulte entender imágenes, contenedores y controladores de almacenamiento ⟨https://docs.docker.com/storage/storagedriver/⟩ en la documentación en línea.

Descargar una imagen por digesto (identificador inmutable)

Hasta ahora, ha descargado imágenes por su nombre (y "etiqueta"). Usar nombres y etiquetas es una manera conveniente de trabajar con imágenes. Cuando usa etiquetas, puede docker image pull una imagen de nuevo para asegurarse de que tiene la versión más actualizada de esa imagen. Por ejemplo, docker image pull ubuntu:24.04 descarga la última versión de la imagen Ubuntu 24.04.

En algunos casos no quiere que las imágenes se actualicen a versiones más nuevas, sino que prefiere usar una versión fija de una imagen. Docker le permite descargar una imagen por su digesto. Al descargar una imagen por digesto, usted especifica exactamente qué versión de una imagen descargar. Hacer esto le permite "fijar" una imagen a esa versión, y garantizar que la imagen que está usando es siempre la misma.

Para conocer el digesto de una imagen, descargue la imagen primero. Vamos a descargar la última imagen ubuntu:24.04 desde Docker Hub:

$ docker image pull ubuntu:24.04
24.04: Pulling from library/ubuntu
125a6e411906: Pull complete
Digest: sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30
Status: Downloaded newer image for ubuntu:24.04
docker.io/library/ubuntu:24.04

Docker imprime el digesto de la imagen después de que la descarga ha terminado. En el ejemplo de arriba, el digesto de la imagen es:

sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30

Docker también imprime el digesto de una imagen cuando empuja a un registro. Esto puede ser útil si quiere fijar a una versión de la imagen que acaba de empujar.

Un digesto toma el lugar de la etiqueta al descargar una imagen, por ejemplo, para descargar la imagen de arriba por digesto, ejecute el siguiente comando:

$ docker image pull ubuntu@sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30
docker.io/library/ubuntu@sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30: Pulling from library/ubuntu
Digest: sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30
Status: Image is up to date for ubuntu@sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30
docker.io/library/ubuntu@sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30

El digesto también puede usarse en el FROM de un Dockerfile, por ejemplo:

FROM ubuntu@sha256:2e863c44b718727c860746568e1d54afd13b2fa71b160f5cd9058fc436217b30
LABEL org.opencontainers.image.authors="some maintainer <maintainer@example.com>"

Nota

Usar esta característica "fija" una imagen a una versión específica en el tiempo. Docker por lo tanto no descarga versiones actualizadas de una imagen, las cuales pueden incluir actualizaciones de seguridad. Si quiere descargar una imagen actualizada, necesita cambiar el digesto en consecuencia.

Descargar desde un registro diferente

Por defecto, docker image pull descarga imágenes desde Docker Hub. También es posible especificar manualmente la ruta de un registro desde el cual descargar. Por ejemplo, si ha configurado un registro local, puede especificar su ruta para descargar desde él. La ruta de un registro es similar a una URL, pero no contiene un especificador de protocolo (https://).

El siguiente comando descarga la imagen testing/test-image desde un registro local escuchando en el puerto 5000 (myregistry.local:5000):

$ docker image pull myregistry.local:5000/testing/test-image

Las credenciales del registro son gestionadas por docker-login(1).

Docker usa el protocolo https:// para comunicarse con un registro, a menos que se permita acceder al registro a través de una conexión insegura. Consulte la sección de registros inseguros ⟨https://docs.docker.com/engine/reference/commandline/dockerd/#insecure-registries⟩ en la documentación en línea para más información.

Descargar un repositorio con múltiples imágenes

Por defecto, docker image pull descarga una sola imagen desde el registro. Un repositorio puede contener múltiples imágenes. Para descargar todas las imágenes de un repositorio, proporcione la opción -a (o --all-tags) al usar docker image pull.

Este comando descarga todas las imágenes del repositorio ubuntu :

$ docker image pull --all-tags ubuntu
Pulling repository ubuntu
ad57ef8d78d7: Download complete
105182bb5e8b: Download complete
511136ea3c5a: Download complete
73bd853d2ea5: Download complete
....
Status: Downloaded newer image for ubuntu

Después de que la descarga se complete use el comando docker image ls (o la abreviatura docker images ) para ver las imágenes que fueron descargadas. El ejemplo de abajo muestra todas las imágenes ubuntu que están presentes localmente:

$ docker image ls --filter reference=ubuntu
REPOSITORY   TAG       IMAGE ID       CREATED        SIZE
ubuntu       22.04     8a3cdc4d1ad3   3 weeks ago    77.9MB
ubuntu       jammy     8a3cdc4d1ad3   3 weeks ago    77.9MB
ubuntu       24.04     35a88802559d   6 weeks ago    78.1MB
ubuntu       latest    35a88802559d   6 weeks ago    78.1MB
ubuntu       noble     35a88802559d   6 weeks ago    78.1MB

Cancelar una descarga

Terminar el proceso docker image pull , por ejemplo presionando CTRL-c mientras estáejecutándose en una terminal, terminará la operación de extracción.

$ docker image pull ubuntu
Using default tag: latest
latest: Pulling from library/ubuntu
a3ed95caeb02: Pulling fs layer
236608c7b546: Pulling fs layer
^C

El Motor termina una operación de extracción cuando se pierde la conexión entre el demonio del Motor de Docker y el cliente del Motor de Docker que inicia la extracción. Si la conexión con el demonio del Motor se pierde por otras razones que no sean una interacción manual, la extracción también se cancela.

OPCIONES

-a, --all-tags[=false] Descargar todas las imágenes etiquetadas en el repositorio

--platform="" Establecer la plataforma si el servidor es compatible con múltiples plataformas

-q, --quiet[=false] Suprimir la salida detallada
