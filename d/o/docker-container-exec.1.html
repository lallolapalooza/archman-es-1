NOMBRE

docker-container-exec - Ejecuta un comando en un contenedor en ejecución

SINOPSIS

docker container exec [OPCIONES] CONTENEDOR COMANDO [ARG...]

DESCRIPCIÓN

Ejecuta un proceso en un contenedor en ejecución.

El comando iniciado con docker exec solo se ejecutará mientras el proceso principal del contenedor (PID 1) esté en ejecución y no se reiniciará si el contenedor se reinicia.

Si el contenedor está en pausa, el comando docker exec esperará hasta que el contenedor se reanude y luego se ejecutará.

CAPACIDADES

privileged otorga al proceso capacidades extendidas de Linux ⟨https://man7.org/linux/man-pages/man7/capabilities.7.html⟩ al ejecutarse en un contenedor.

Sin esta opción, el proceso ejecutado por docker exec en un contenedor en ejecución tiene las mismas capacidades que el contenedor, las cuales pueden ser limitadas. Establezca --privileged para otorgar todas las capacidades al proceso.

USUARIO

user establece el nombre de usuario o UID utilizado y opcionalmente el nombre de grupo o GID para el comando especificado.

Los siguientes ejemplos son válidos:
--user [usuario | usuario:grupo | uid | uid:gid | usuario:gid | uid:grupo]

Sin este argumento, el comando se ejecutará como root en el contenedor.

Estado de Salida

El código de salida de docker exec proporciona información sobre por qué el contenedor falló al ejecutar o por qué salió. Cuando docker exec sale con un código distinto de cero, los códigos de salida siguen el estándar chroot, ver abajo:

126 si el comando contenido no se puede invocar

$ docker exec busybox /etc; echo $?
# exec: "/etc": permission denied
  docker: Error response from daemon: Contained command could not be invoked
  126

127 si el comando contenido no se encuentra

$ docker exec busybox foo; echo $?
# exec: "foo": executable file not found in $PATH
  docker: Error response from daemon: Contained command not found or does not exist
  127

Código de salida del comando contenido en otros casos

$ docker exec busybox /bin/sh -c 'exit 3' 
# 3

OPCIONES

-d, --detach[=false] Modo separado: ejecuta el comando en segundo plano

--detach-keys="" Anula la secuencia de teclas para separar un contenedor

-e, --env= Establece variables de entorno

--env-file= Lee un archivo de variables de entorno

-i, --interactive[=false] Mantiene STDIN abierto incluso si no está adjunto

--privileged[=false] Otorga privilegios extendidos al comando

-t, --tty[=false] Asigna un pseudo-TTY

-u, --user="" Nombre de usuario o UID (formato: "[:]")

-w, --workdir="" Directorio de trabajo dentro del contenedor
