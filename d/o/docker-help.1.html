--root=valor

Directorio raíz de almacenamiento en el que se guardan los datos, incluidas las imágenes (predeterminado: "/var/lib/containers/storage" para UID 0, "$HOME/.local/share/containers/storage" para otros usuarios). El directorio raíz predeterminado está configurado en containers-storage.conf(5).

Anular esta opción hace que la configuración storage-opt en containers-storage.conf(5) sea ignorada. El usuario debe especificar opciones adicionales mediante el indicador --storage-opt .

--runroot=valor

Directorio de estado de almacenamiento donde se guarda toda la información de estado (predeterminado: "/run/containers/storage" para UID 0, "/run/user/$UID/run" para otros usuarios). El directorio de estado predeterminado está configurado en containers-storage.conf(5).

--runtime=valor

Nombre del runtime OCI tal como se especifica en containers.conf o ruta absoluta al binario compatible con OCI utilizado para ejecutar contenedores.

--runtime-flag=flag

Añade indicadores globales para el runtime del contenedor. Para listar los indicadores admitidos, consulte las páginas de manual del runtime de contenedor seleccionado (runc es el runtime predeterminado, la página de manual a consultar es runc(8). Cuando la máquina está configurada para cgroup V2, el runtime predeterminado es crun, la página de manual a consultar es crun(8).).

Los indicadores de runtime predeterminados pueden añadirse en containers.conf.

Nota: No pase el -- inicial del indicador. Para pasar el indicador de runc --log-format json a podman build, la opción dada puede ser --runtime-flag log-format=json.

--ssh=valor

Esta opción permite al usuario cambiar el modo ssh, lo que significa que en lugar de usar el modo golang predeterminado, se puede usar --ssh=native para usar el binario ssh instalado y el archivo de configuración declarado en containers.conf.

--storage-driver=valor

Controlador de almacenamiento. El controlador de almacenamiento predeterminado para UID 0 está configurado en containers-storage.conf(5) en modo sin raíz), y es vfs para usuarios no root cuando fuse-overlayfs no está disponible. La variable de entorno STORAGE_DRIVER anula el valor predeterminado. El controlador especificado por --storage-driver anula todos.

Anular esta opción hace que la configuración storage-opt en containers-storage.conf(5) sea ignorada. El usuario debe especificar opciones adicionales mediante el indicador --storage-opt .

--storage-opt=valor

Especifica una opción del controlador de almacenamiento. Las opciones predeterminadas del controlador de almacenamiento están configuradas en containers-storage.conf(5). La variable de entorno STORAGE_OPTS anula el valor predeterminado. Las opciones especificadas por --storage-opt anulan todas. Especifique --storage-opt="" para que no se use ninguna opción de almacenamiento.

--syslog

Envía la información de registro a syslog así como a la consola (predeterminado false).

En clientes remotos, incluidas máquinas Mac y Windows (excluyendo WSL2), el registro se dirige al archivo $HOME/.config/containers/podman.log.

--tls-ca=ruta

Ruta a un archivo PEM que contiene el paquete de autoridad de certificación para verificar el certificado del servidor.

--tls-cert=ruta

Ruta a un archivo PEM que contiene el certificado TLS del cliente para presentar al servidor. --tls-key también debe proporcionarse.

--tls-key=ruta

Ruta a un archivo PEM que contiene la clave privada que coincide con --tls-cert. --tls-cert también debe proporcionarse.

--tmpdir=ruta

Ruta al directorio temporal para el contenido del runtime de libpod. Por defecto es $XDG_RUNTIME_DIR/libpod/tmp sin raíz y /run/libpod/tmp con raíz.

NOTA --tmpdir no se usa para el almacenamiento temporal de imágenes descargadas. Use la variable de entorno TMPDIR para cambiar la ubicación de almacenamiento temporal de las imágenes de contenedor descargadas. Podman usa por defecto /var/tmp.

--transient-store

Habilita un modo de almacenamiento transitorio global donde todos los metadatos del contenedor se almacenan en medios no persistentes (es decir, en la ubicación especificada por --runroot). Este modo permite iniciar contenedores más rápido, así como garantizar un estado nuevo en el arranque en caso de apagados no limpios u otros problemas. Sin embargo, no es compatible con un modelo tradicional donde los contenedores persisten a través de reinicios.

El valor predeterminado para esto está configurado en containers-storage.conf(5).

--url=valor

URL para acceder al servicio de Podman (predeterminado de containers.conf, sin raíz unix:///run/user/$UID/podman/podman.sock o como root unix:///run/podman/podman.sock). Establecer esta opción cambia la opción --remote a true.

•
CONTAINER_HOST tiene el formato <esquema>://[<usuario[:<contraseña>]@]<host>[:<puerto>][<ruta>]

Detalles:
- esquema es uno de:
* ssh (predeterminado): un socket unix(7) local en el host y puertonombrados, accesible vía SSH
* tcp: una conexión TCP sin cifrar y sin autenticación al host y puerto
nombrados unix: un socket unix(7) local en la rutaespecificada, o el predeterminado para el usuario
- usuario por defecto es root o el usuario actual en ejecución (ssh solamente)
- contraseña no tiene valor predeterminado (ssh solamente)
- host debe proporcionarse y es la IP o el nombre de la máquina que aloja el servicio de Podman (ssh y tcp)
- puerto por defecto es 22 (ssh y tcp)
- ruta por defecto es /run/podman/podman.sock, o /run/user/$UID/podman/podman.sock si se ejecuta sin raíz (unix), o debe especificarse explícitamente (ssh)

Precedencia de resolución del valor de URL:
- valor de la línea de comandos
- variable de entorno CONTAINER_HOST
- tabla engine.service_destinations en containers.conf, excluyendo el directorio /usr/share/containers
- unix:///run/podman/podman.sock

Las conexiones remotas usan el containers.conf local por defecto.

Algunos ejemplos de valores de URL en formatos válidos:
- unix:///run/podman/podman.sock
- unix:///run/user/$UID/podman/podman.sock
- ssh://notroot@localhost:22/run/user/$UID/podman/podman.sock
- ssh://root@localhost:22/run/podman/podman.sock
- tcp://localhost:34451
- tcp://127.0.0.1:34451

Variables de entorno

Podman puede configurar variables de entorno desde env de la tabla [engine] en containers.conf. Estas variables pueden anularse pasando variables de entorno antes de los comandos podman .

CONTAINERS_CONF

Establece las ubicaciones predeterminadas del archivo containers.conf

CONTAINERS_REGISTRIES_CONF

Establece la ubicación predeterminada del archivo registries.conf.

CONTAINERS_STORAGE_CONF

Establece la ubicación predeterminada del archivo storage.conf.

CONTAINER_CONNECTION

Anula el valor predeterminado de --connection para acceder al servicio de Podman. Habilita automáticamente la opción --remote.

CONTAINER_HOST

Establece el valor predeterminado de --url para acceder al servicio de Podman. Habilita automáticamente la opción --remote.

CONTAINER_SSHKEY

Establece la ruta predeterminada de --identity al archivo de clave ssh utilizado para acceder al servicio de Podman.

PODMAN_CONNECTIONS_CONF

La ruta al archivo donde se almacenan las conexiones del sistema y las granjas creadas con podman system connection add y podman farm add , por defecto usa ~/.config/containers/podman-connections.json.

STORAGE_DRIVER

Establece el valor predeterminado de --storage-driver .

STORAGE_OPTS

Establece el valor predeterminado de --storage-opt .

TMPDIR

Establece la ubicación de almacenamiento temporal de las imágenes de contenedor descargadas. Podman usa por defecto /var/tmp.

XDG_CONFIG_HOME

En modo sin raíz, los archivos de configuración se leen de XDG_CONFIG_HOME cuando se especifica, de lo contrario en el directorio de inicio del usuario bajo $HOME/.config/containers.

XDG_DATA_HOME

En modo sin raíz, las imágenes se descargan bajo XDG_DATA_HOME cuando se especifica, de lo contrario en el directorio de inicio del usuario bajo $HOME/.local/share/containers/storage.

XDG_RUNTIME_DIR

En modo sin raíz, los datos de configuración temporales se almacenan en ${XDG_RUNTIME_DIR}/containers.

Modo sin raíz

(Rootless)

Podman también se puede usar como usuario sin privilegios de root. Cuando podman se ejecuta en modo sin raíz, se crea un espacio de nombres de usuarioe se crea automáticamente para el usuario, definido en /etc/subuid y /etc/subgid.

Los contenedores creados por un usuario no root no son visibles para otros usuarios y no son vistos ni administrados por Podman ejecutándose como root.

Se requiere tener múltiples UID/GID asignados a un usuario. Asegúrate de que el usuario esté presente en los archivos /etc/subuid y /etc/subgid.

Ejecuta los siguientes comandos para agregar los rangos a los archivos

$ sudo usermod --add-subuids 10000-75535 NOMBRE_USUARIO
$ sudo usermod --add-subgids 10000-75535 NOMBRE_USUARIO

O simplemente agrega el contenido manualmente.

$ echo NOMBRE_USUARIO:10000:65536 >> /etc/subuid
$ echo NOMBRE_USUARIO:10000:65536 >> /etc/subgid

Consulta las páginas del manual de subuid(5) y subgid(5) para obtener más información.

Nota: Los espacios en blanco en cualquier fila de /etc/subuid o /etc/subgid, incluidos los espacios finales, pueden provocar fallas al no registrar una entrada.

Las imágenes se descargan bajo XDG_DATA_HOME cuando se especifica, de lo contrario, en el directorio principal del usuario bajo .local/share/containers/storage.

Actualmente, se requiere tener instalado slirp4netns o pasta para crear un dispositivo de red, de lo contrario, los contenedores sin root deben ejecutarse en el espacio de nombres de red del host.

En ciertos entornos como HPC (Computación de Alto Rendimiento), los usuarios no pueden aprovechar los UID y GID adicionales de los sistemas /etc/subuid y /etc/subgid. Sin embargo, en este entorno, Podman sin root puede operar con un solo UID. Para que esto funcione, establece la opción ignore_chown_errors en el archivo containers-storage.conf(5). Esta opción le indica a Podman que, al descargar una imagen, ignore los errores de chown al intentar cambiar un archivo en una imagen de contenedor para que coincida con el UID no root en la imagen. Esto significa que todos los archivos se guardan como el UID del usuario. Ten en cuenta que esto puede causar problemas al ejecutar el contenedor.

NOTA: Sistemas de archivos no compatibles en modo sin root

El sistema de archivos Overlay (OverlayFS) no es compatible con kernels anteriores a 5.12.9 en modo sin root. El paquete fuse-overlayfs es una herramienta que proporciona la funcionalidad de OverlayFS en el espacio de nombres del usuario, lo que permite montar sistemas de archivos en entornos sin root. Se recomienda instalar el paquete fuse-overlayfs. En modo sin root, Podman utiliza automáticamente el programa fuse-overlayfs como el programa de montaje (`mount_program`) si está instalado, siempre que el archivo $HOME/.config/containers/storage.conf no se haya creado previamente. Si storage.conf existe en el directorio principal, agrega `mount_program = "/usr/bin/fuse-overlayfs"` bajo `[storage.options.overlay]` para habilitar esta función.

El Sistema de Archivos de Red (NFS) y otros sistemas de archivos distribuidos (por ejemplo: Lustre, Spectrum Scale, General Parallel File System (GPFS)) no son compatibles cuando se ejecutan en modo sin root, ya que estos sistemas de archivos no comprenden el espacio de nombres del usuario. Sin embargo, Podman sin root puede utilizar un Directorio Principal NFS modificando $HOME/.config/containers/storage.conf para que la opción `graphroot` apunte a un directorio almacenado en almacenamiento local (No NFS).
