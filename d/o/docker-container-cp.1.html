DOCKER(1) Manuales de usuario de Docker DOCKER(1)

NOMBRE

docker-container-cp - Copia archivos/carpetas entre un contenedor y el sistema de archivos local

SINOPSIS

docker container cp [OPCIONES] CONTENEDOR:RUTA_ORIGEN RUTA_DESTINO|- docker cp [OPCIONES] RUTA_ORIGEN|- CONTENEDOR:RUTA_DESTINO

DESCRIPCIÓN

La utilidad docker container cp copia el contenido de RUTA_ORIGEN a RUTA_DESTINO. Puedes copiar desde el sistema de archivos del contenedor a la máquina local o al revés, desde el sistema de archivos local al contenedor. Si se especifica - para RUTA_ORIGEN o RUTA_DESTINO, también puedes transmitir un archivo tar desde STDIN o hacia STDOUT. El CONTENEDOR puede ser un contenedor en ejecución o detenido. La RUTA_ORIGEN o RUTA_DESTINO puede ser un archivo o un directorio.

El comando docker container cp asume que las rutas del contenedor son relativas al directorio / (raíz) del contenedor. Esto significa que proporcionar la barra diagonal inicial es opcional; El comando considera compassionate_darwin:/tmp/foo/myfile.txt y compassionate_darwin:tmp/foo/myfile.txt como idénticos. Las rutas de la máquina local pueden ser un valor absoluto o relativo. El comando interpreta las rutas relativas de una máquina local como relativas al directorio de trabajo actual donde se ejecuta docker container cp .

El comando cp se comporta como el comando de Unix cp -a en el sentido de que los directorios se copian recursivamente con los permisos preservados si es posible. La propiedad se establece al usuario y grupo principal en el destino. Por ejemplo, los archivos copiados a un contenedor se crean con UID:GID del usuario root. Los archivos copiados a la máquina local se crean con el UID:GID del usuario que invocó el comando docker container cp . Si especificas la opción -L , docker container cp sigue cualquier enlace simbólico en RUTA_ORIGEN. docker container cp no crea directorios padre para RUTA_DESTINO si no existen.

Asumiendo un separador de ruta de /, un primer argumento de RUTA_ORIGEN y un segundo argumento de RUTA_DESTINO, el comportamiento es el siguiente:

•
RUTA_ORIGEN especifica un archivo
•
RUTA_DESTINO no existe
•
el archivo se guarda en un archivo creado en RUTA_DESTINO
•
RUTA_DESTINO no existe y termina con /
•
Condición de error: el directorio de destino debe existir.
•
RUTA_DESTINO existe y es un archivo
•
el destino se sobrescribe con el contenido del archivo de origen
•
RUTA_DESTINO existe y es un directorio
•
el archivo se copia en este directorio usando el nombre base de RUTA_ORIGEN
•
RUTA_ORIGEN especifica un directorio
•
RUTA_DESTINO no existe
•
RUTA_DESTINO se crea como un directorio y el contenido del directorio de origen se copia en este directorio
•
RUTA_DESTINO existe y es un archivo
•
Condición de error: no se puede copiar un directorio a un archivo
•
RUTA_DESTINO existe y es un directorio
•
RUTA_ORIGEN no termina con /. (es decir: barra diagonal seguida de punto)
•
el directorio de origen se copia en este directorio
•
RUTA_ORIGEN sí termina con /. (es decir: barra diagonal seguida de punto)
•
el contenido del directorio de origen se copia en este directorio

El comando requiere que RUTA_ORIGEN y RUTA_DESTINO existan de acuerdo con las reglas anteriores. Si RUTA_ORIGEN es local y es un enlace simbólico, el enlace simbólico, no el destino, se copia por defecto. Para copiar el destino del enlace y no el enlace, especifica la opción -L .

Se usa dos puntos (:) como delimitador entre CONTENEDOR y su ruta. También puedes usar : al especificar rutas para una RUTA_ORIGEN o RUTA_DESTINO en una máquina local, por ejemplo archivo:nombre.txt. Si usas un : en una ruta de máquina local, debes ser explícito con una ruta relativa o absoluta, por ejemplo:

`/ruta/al/archivo:nombre.txt` o `./archivo:nombre.txt`

No es posible copiar ciertos archivos del sistema como recursos bajo /proc, /sys, /dev, tmpfs y montajes creados por el usuario en el contenedor. Sin embargo, aún puedes copiar tales archivos ejecutando manualmente tar en docker exec. Por ejemplo (considerando que RUTA_ORIGEN y RUTA_DESTINO son directorios):

$ docker exec foo tar Ccf $(dirname RUTA_ORIGEN) - $(basename RUTA_ORIGEN) | tar Cxf RUTA_DESTINO -

o

$ tar Ccf $(dirname RUTA_ORIGEN) - $(basename RUTA_ORIGEN) | docker exec -i foo tar Cxf RUTA_DESTINO -

Usar - como RUTA_ORIGEN transmite el contenido de STDIN como un archivo tar. El comando extrae el contenido del tar a la RUTA_DESTINO en el sistema de archivos del contenedor. En este caso, RUTA_DESTINO debe especificar un directorio. Usar - como RUTA_DESTINO transmite el contenido del recurso como un archivo tar a STDOUT.

EJEMPLOS

Supongamos que un contenedor ha terminado de producir alguna salida como un archivo que guarda en algún lugar de su sistema de archivos. Esta podría ser la salida de un trabajo de compilación o algún otro cálculo. Puedes copiar estas salidas del contenedor a una ubicación en tu host local.

Si quieres copiar el /tmp/foo directorio de un contenedor al directorio existente /tmp en tu host. Si ejecutas docker container cp en tu directorio ~ (inicio) en el host local:

$ docker container cp compassionate_darwin:tmp/foo /tmp

Docker crea un /tmp/foo directorio en tu host. Alternativamente, puedes omitir la barra diagonal inicial en el comando. Si ejecutas este comando desde tu directorio de inicio:

$ docker container cp compassionate_darwin:tmp/foo tmp

Si ~/tmp no existe, Docker lo creará y copiará el contenido de /tmp/foo del contenedor a este nuevo directorio. Si ~/tmp ya existe como directorio, entonces Docker copiará el contenido de /tmp/foo del contenedor a un directorio en ~/tmp/foo.

Al copiar un solo archivo a un RUTA_LOCALexistente, el comando docker container cp sobrescribirá el contenido de RUTA_LOCAL si es un archivo o lo colocará en RUTA_LOCAL si es un directorio, sobrescribiendo un archivo existente con el mismo nombre si existe. Por ejemplo, este comando:

$ docker container cp sharp_ptolemy:/tmp/foo/myfile.txt /test

Si /test no existe en la máquina local, se creará como un archivo con el contenido de /tmp/foo/myfile.txt del contenedor. Si /test existe como archivo, se sobrescribirá. Por último, si /test existe como directorio, el archivo se copiará a /test/myfile.txt.

A continuación, supongamos que quieres copiar un archivo o carpeta a un contenedor. Por ejemplo, este podría ser un archivo de configuración o alguna otra entrada a un cálculo de larga duración que te gustaría colocar en un contenedor creado antes de que se inicie. Esto es útil porque no requiere que el archivo de configuración u otra entrada existan en la imagen del contenedor.

Si tienes un archivo, config.yml, en el directorio actual de tu host local y deseas copiarlo a un directorio existente en /etc/my-app.d en un contenedor, se puede usar este comando:

$ docker container cp config.yml myappcontainer:/etc/my-app.d

Si tienes varios archivos en un directorio local /config que necesitas copiar a un directorio /etc/my-app.d en un contenedor:

$ docker container cp /config/. myappcontainer:/etc/my-app.d

Elove command will copy the contents of the local /config directory into the directory /etc/my-app.d in the container.

Finally, if you want to copy a symbolic link into a container, you typically want to copy the linked target and not the link itself. To copy the target, use the -L option, for example:

$ ln -s /tmp/somefile /tmp/somefile.ln
$ docker container cp -L /tmp/somefile.ln myappcontainer:/tmp/

This command copies content of the local /tmp/somefile into the file /tmp/somefile.ln in the container. Without -L option, the /tmp/somefile.ln preserves its symbolic link but not its content.

OPCIONES

-a, --archive[=false] Modo de archivo (copiar toda la información uid/gid)

-L, --follow-link[=false] Seguir siempre el enlace simbólico en SRC_PATH

-q, --quiet[=false] Suprimir la salida de progreso durante la copia. La salida de progreso se suprime automáticamente si no hay un terminal conectado
