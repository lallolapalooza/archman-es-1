NOMBRE

podman-container-checkpoint - Punto de control de uno o más contenedores en ejecución

SINOPSIS

podman container checkpoint [opciones] contenedor [contenedor ...]

DESCRIPCIÓN

podman container checkpoint crea un punto de control de todos los procesos en uno o más contenedores. Un contenedor puede restaurarse desde un punto de control con podman-container-restore. Se utilizan los IDs de contenedor o nombres como entrada.

IMPORTANTE: Si el contenedor está utilizando systemd como punto de entrada es posible que no se pueda crear un punto de control del contenedor.

OPCIONES

--all, -a

Crea un punto de control de todos los contenedores en ejecución .El valor predeterminado es
false .IMPORTANTE: Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.
IMPORTANTE: Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.

--compress, -c=zstd | none | gzip

Especifica el algoritmo de compresión utilizado para el archivo del punto de control creado con la OPCIÓN --export, -e . Los algoritmos posibles son zstd, none y gzip.
Una posible razón para usar none es permitir una creación más rápida de archivos de puntos de control. No comprimir el archivo del punto de control puede resultar en una creación más rápida del archivo del punto de control.
El valor predeterminado es zstd.

--create-image=imagen

Crea una imagen de punto de control a partir de un contenedor en ejecución. Esta es una imagen OCI estándar creada en el almacén de imágenes local. Consiste en una sola capa que contiene todos los archivos del punto de control. El contenido de esta capa de imagen está en el mismo formato que un punto de control creado con --export. Una imagen de punto de control se puede enviar a un registro de contenedores estándar y descargar en un sistema diferente para permitir la migración de contenedores. Además, la imagen se puede exportar con podman image save e inspeccionar con podman inspect. Inspeccionar una imagen de punto de control muestra información adicional, almacenada como anotaciones, sobre el entorno del host utilizado para hacer el punto de control:

  • io.podman.annotations.checkpoint.name: Nombre legible del contenedor original.
  • io.podman.annotations.checkpoint.rawImageName: Nombre sin procesar de la imagen utilizada para crear el contenedor original (como lo especificó el usuario).
  • io.podman.annotations.checkpoint.rootfsImageID: ID de la imagen utilizada para crear el contenedor original.
  • io.podman.annotations.checkpoint.rootfsImageName: Nombre de la imagen utilizada para crear el contenedor original.
  • io.podman.annotations.checkpoint.podman.version: Versión de Podman utilizada para crear el punto de control.
  • io.podman.annotations.checkpoint.criu.version: Versión de CRIU utilizada para crear el punto de control.
  • io.podman.annotations.checkpoint.runtime.name: Tiempo de ejecución del contenedor (por ejemplo, runc, crun) utilizado para crear el punto de control.
  • io.podman.annotations.checkpoint.runtime.version: Versión del tiempo de ejecución del contenedor utilizado para crear el punto de control.
  • io.podman.annotations.checkpoint.conmon.version: Versión de conmon utilizada con el contenedor original.
  • io.podman.annotations.checkpoint.host.arch: Arquitectura de CPU del host en el que se creó el punto de control.
  • io.podman.annotations.checkpoint.host.kernel: Versión del kernel de Linux del host donde se creó el punto de control.
  • io.podman.annotations.checkpoint.cgroups.version: Versión de cgroup utilizada por el host donde se creó el punto de control.
  • io.podman.annotations.checkpoint.distribution.version: Versión de la distribución del host en la que se creó el punto de control.
  • io.podman.annotations.checkpoint.distribution.name: Nombre de la distribución del host en la que se creó el punto de control.

--export, -e=archivo

Exporta el punto de control a un archivo. El tipo de archivo se especifica con --compress. El punto de control exportado se puede utilizar para importar el contenedor en otro sistema y así permitir la migración en vivo de contenedores. Este archivo de punto de control también incluye todos los cambios en el sistema de archivos raíz del contenedor , a menos que se deshabilite explícitamente con --ignore-rootfs.

--file-locks

Crea un punto de control de un contenedor con bloqueos de archivo. Si una aplicación que se ejecuta en el contenedor está utilizando bloqueos de archivo, esta OPCIÓN es necesaria durante el punto de control y la restauración. De lo contrario, se espera que falle el punto de control de contenedores con bloqueos de archivo. Si no se utilizan bloqueos de archivo, esta opción se ignora.
El valor predeterminado es false.

--ignore-rootfs

Si un punto de control se exporta a un archivo, es posible con la ayuda de --ignore-rootfs deshabilitar explícitamente la inclusión de cambios en el sistema de archivos raíz en el archivo del punto de control.
El valor predeterminado es false.
IMPORTANTE: Esta OPCIÓN solo funciona en combinación con --export, -e.

--ignore-volumes

Esta OPCIÓN debe usarse en combinación con la OPCIÓN --export, -e . Cuando se especifica esta OPCIÓN, el contenido de los volúmenes asociados con el contenedor no se incluye en el archivo del punto de control.
El valor predeterminado es false.

--keep, -k

Mantiene todos los archivos temporales de registro y estadísticas creados por CRIU durante el punto de control. Estos archivos no se eliminan si el punto de control falla, para una mayor depuración. Si el punto de control tiene éxito, estos archivos no son necesarios en teoría, pero si se necesitan, Podman puede mantener los archivos para un análisis posterior.
El valor predeterminado es false.

--latest, -l

En lugar de proporcionar el ID del contenedor o nombre, usa el último contenedorcreado. El valor predeterminado es false. IMPORTANTE: Esta OPCIÓN no está disponible con el cliente remoto de Podman, incluyendo máquinas Mac y Windows (excluyendo WSL2). Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.

--leave-running, -R

Deja el contenedor en ejecución después del punto de control en lugar de detenerlo.
El valor predeterminado es false.

--pre-checkpoint, -P

Vuelca solo la información de memoria del contenedor , dejando el contenedor en ejecución. Las operaciones posteriores reemplazan los volcados anteriores.
El valor predeterminado es false.

La funcionalidad de hacer un punto de control solo de la memoria del contenedor y en un segundo punto de control escribir solo las páginas de memoria que han cambiado desde el primer punto de control depende del bit de "sucio suave" (soft-dirty) del kernel de Linux, que no está disponible en todos los sistemas ya que depende de la arquitectura del sistema y de la configuración del kernel de Linux. Podman verifica si el sistema actual soporta esta funcionalidad y devuelve un error si el sistema actual no la soporta.

--print-stats

Imprime estadísticas sobre el punto de control del(los) contenedor(es). La salida se presenta en un array JSON y contiene información sobre cuánto tiempo requirieron diferentes operaciones de punto de control. Muchas de las estadísticas del punto de control son creadas por CRIU y simplemente se pasan a Podman. La siguiente información se proporciona en el array JSON:

  • podman_checkpoint_duration: Tiempo total (en microsegundos) necesario para crear todos los puntos de control.
  • runtime_checkpoint_duration: Tiempo (en microsegundos) que el tiempo de ejecución del contenedor necesitó para crear el punto de control.
  • freezing_time: Tiempo (en microsegundos) que CRIU necesitó para pausar (congelar) todos los procesos en el contenedor (medido por CRIU).
  • frozen_time: Tiempo (en microsegundos) que todos los procesos en el contenedor estuvieron pausados (medido por CRIU).
  • memdump_time: Tiempo (en microsegundos) necesario para extraer todas las páginas de memoria requeridas de todos los procesos del contenedor (medido por CRIU).
  • memwrite_time: Tiempo (en microsegundos) necesario para escribir todas las páginas de memoria requeridas en los archivos de imagen de punto de control correspondientes (medido por CRIU).
  • pages_scanned: Número de páginas de memoria escaneadas para determinar si necesitan ser incluidas en un punto de control (medido por CRIU).
  • pages_written: Número de páginas de memoria realmente escritasdiez a la archivos de imagen de punto de control (medido por CRIU).

El valor predeterminado es false.

--tcp-established

Realiza un punto de control de un contenedor con conexiones TCP establecidas. Si la imagen del punto de control contiene conexiones TCP establecidas, esta OPCIÓN es necesaria durante la restauración. De forma predeterminada, no se realizan puntos de control de contenedores con conexiones TCP establecidas.
El valor predeterminado es false.

--with-previous

Comprueba el contenedor con los archivos de imagen de criu anteriores en pre-dump. Solo funciona en runc 1.0-rc3 o superior.
El valor predeterminado es false.
IMPORTANTE: Esta OPCIÓN no está disponible con --pre-checkpoint.

Esta opción requiere que la opción --pre-checkpoint haya sido utilizada antes en el mismo contenedor. Sin un pre-checkpoint existente, esta opción falla.

Consulte también --pre-checkpoint para obtener información adicional sobre la disponibilidad de --pre-checkpoint en diferentes sistemas.

EJEMPLOS

Realiza un punto de control para el contenedor "mywebserver".

# podman container checkpoint mywebserver

Crea una imagen de punto de control para el contenedor "mywebserver".

# podman container checkpoint --create-image mywebserver-checkpoint-1 mywebserver

Vuelca la información de memoria del contenedor más reciente en un archivo.

# podman container checkpoint -P -e pre-checkpoint.tar.zst -l

Conserva la información de memoria de un volcado anterior y añade la información de memoria del nuevo contenedor.

# podman container checkpoint --with-previous -e checkpoint.tar.zst -l

Vuelca la información de memoria del contenedor más reciente en un archivo con el método de compresión especificado.

# podman container checkpoint -l --compress=none --export=dump.tar
# podman container checkpoint -l --compress=gzip --export=dump.tar.gz
