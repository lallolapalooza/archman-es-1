Históricamente, las imágenes de contenedores describen el contenido (por ejemplo, capas) y cómo un tiempo de ejecución de contenedores (por ejemplo, crun(1) o runc(1)) ejecuta el contenedor. Por ejemplo, una imagen puede establecer el entorno y el comando en su configuración. Sin embargo, una imagen de contenedor no puede especificar directamente cómo un motor de contenedores como Podman la ejecuta. Por ejemplo, la configuración de una imagen no incluye información sobre controladores de registro, espacios de

nombres o qué capacidades necesita para ejecutarse correctamente.

podman container runlabelaborda la limitación de las imágenes de contenedores de una manera simple pero eficiente. Podman lee el contenido de la etiqueta y lo interpreta como un comando que se ejecuta en el host. De esta manera, una imagen puede describir exactamente cómo es ejecutada por Podman. Por ejemplo, una etiqueta con el contenido /usr/bin/podman run -d --pid=host --privileged \${IMAGE} instruye a la imagen para que se ejecute en un contenedor desprendido y privilegiado que utiliza el espacio de nombres de PID del host. Esto eleva la autodescripción de una imagen de contenedor de "qué" a "cómo".Tenga en cu
