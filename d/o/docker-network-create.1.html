DESCRIPCIÓ

N

Crea una nueva red. El DRIVER acepta bridge o overlay, que son los controladores de red integrados. Si has instalado un controlador de red de terceros o uno personalizado propio, puedes especificar ese DRIVER aquí también. Si no especificas la opción --driver, el comando crea automáticamente una red bridge por ti. Cuando instalas Docker Engine, este crea una red bridge automáticamente. Esta red corresponde al puente docker0 en el que Engine ha confiado tradicionalmente. Cuando lanzas un nuevo contenedor con docker run, este se conecta automáticamente a esta red bridge. No puedes eliminar esta red bridge predeterminada, pero puedes crear nuevas usando el comando network

create. 
$ docker network create -d bridge my-bridge-networ
k

Las redes bridge son redes aisladas en una sola instalación de Engine. Si quieres crear una red que abarque múltiples hosts de Docker cada uno ejecutando un Engine, debes habilitar el modo Swarm y crear una red overlay. Para leer más sobre redes overlay con el modo Swarm, consulta " ⟨https://docs.docker.com/network/overlay/⟩

.

Una vez que hayas habilitado el modo swarm, puedes crear una red overlay con ámbito de

swarm: 
$ docker network create --scope=swarm --attachable -d overlay my-multihost-networ
k

Por defecto, las redes con ámbito de swarm no permiten que contenedores iniciados manualmente se conecten. Esta restricción se añade para evitar que alguien que tenga acceso a un nodo no gestor en el clúster swarm ejecute un contenedor capaz de acceder a la pila de red de un servicio de

swarm.

La opción --attachable utilizada en el ejemplo anterior desactiva esta restricción y permite tanto a los servicios de swarm como a los contenedores iniciados manualmente conectarse a la red

overlay.

Los nombres de red deben ser únicos. El demonio de Docker intenta identificar conflictos de nombres, pero esto no está garantizado. Es responsabilidad del usuario evitar conflictos de

nombres.

Limitaciones de las redes

overlay

Deberías crear redes overlay con bloques /24 (el predeterminado), lo que te limita a 256 direcciones IP, cuando creas redes usando el modo de extremo basado en VIP predeterminado. Esta recomendación aborda limitaciones con el modo swarm ⟨https://github.com/moby/moby/issues/30820⟩. Si necesitas más de 256 direcciones IP, no aumentes el tamaño del bloque IP. Puedes usar el modo de extremo dnsrr con un balanceador de carga externo, o usar múltiples redes overlay más pequeñas. Consulta Configurar el descubrimiento de servicios ⟨https://docs.docker.com/engine/swarm/networking/#configu

re-service-discovery⟩ par

diferentes modos de extremo.

Conectar

contenedores

Cuando inicies un contenedor, usa la opción --network para conectarlo a una red. Este ejemplo añade el contenedor busybox a la red myn

et: 
$ docker run -itd --network=mynet
busybox

Si quieres añadir un contenedor a una red después de que el contenedor ya esté en ejecución, usa el subcomando docker network

connect.

Puedes conectar múltiples contenedores a la misma red. Una vez conectados, los contenedores pueden comunicarse usando solo la dirección IP o el nombre de otro contenedor. Para redes overlay o plugins personalizados que soporten conectividad multi-host, los contenedores conectados a la misma red multi-host pero lanzados desde diferentes Engines también pueden comunicarse de esta

manera.

Puedes desconectar un contenedor de una red usando el comando docker network di

sconnect.

Especificar opciones

avanzadas

Cuando creas una red, Engine crea una subred no superpuesta para la red por defecto. Esta subred no es una subdivisión de una red existente. Es puramente para propósitos de direccionamiento IP. Puedes anular este valor predeterminado y especificar valores de subred directamente usando la opción --subnet. En una red bridge solo puedes crear un solo

subred: 
$ docker network create --driver=bridge --subnet=192.168.0.0/16
br0

Además, también puedes especificar las opciones --gateway, --ip-range y --aux-address

. 
$ docker network create \
  --driver=bridge \
  --subnet=172.28.0.0/16 \
  --ip-range=172.28.5.0/24 \
  --gateway=172.28.5.254 \
br0

Si omites la opción --gateway, Engine selecciona una por ti desde dentro de un rango preferido. Para redes overlay y para plugins de controlador de red que lo soporten, puedes crear múltiples subredes. Este ejemplo usa dos máscaras de subred /25 para adherirse a la guía actual de no tener más de 256 IPs en una sola red overlay. Cada una de las subredes tiene 126 direcciones

utilizables. 
$ docker network create -d overlay \
  --subnet=192.168.10.0/25 \
  --subnet=192.168.20.0/25 \
  --gateway=192.168.10.100 \
  --gateway=192.168.20.100 \
  --aux-address="my-router=192.168.10.5" --aux-address="my-switch=192.168.10.6" \
  --aux-address="my-printer=192.168.20.5" --aux-address="my-nas=192.168.20.6" \
  my-multihost-networ
k

Asegúrate de que tus subredes no se supe

rpongan. Si lo hacen, la creación de
la red falla y Engine devuelve un error.

Modo interno de la

red

Por defecto, cuando conectas un contenedor a una red overlay, Docker también conecta una red bridge a ella para proporcionar conectividad externa. Si quieres crear una red overlay externamente aislada, puedes especificar la opción --

inter
nal.

Modo de ingreso de

red

Puede crear la red que se utilizará para proporcionar el routing-mesh en el clúster swarm. Lo hace especificando --ingress al crear la red. Solo se puede crear una red de ingreso a la vez. La red solo puede eliminarse si ningún servicio depende de ella. Cualquier opción disponible al crear una red superpuesta también está disponible al crear la red de ingreso, además de la opción --attachable

. 
$ docker network create -d overlay \
  --subnet=10.11.0.0/16 \
  --ingress \
  --opt com.docker.network.driver.mtu=9216 \
  --opt encrypted=true \
  my-ingress-netwo
r
k

Ejecutar servicios en redes

predefinidas

Puede crear servicios en las redes predefinidas de docker bridge y host

. 
$ docker service create --name
my-service \ --network host \
--replicas 2 \ busybox top

Redes de swarm con controladores de ámbito

local

Puede crear una red de swarm con controladores de red de ámbito local. Lo hace promoviendo el ámbito de la red a swarm durante la creación de la red. A continuación, podrá usar esta red al crear

servicios. 
$ docker network create -d bridge \
  --scope swarm \
  --attachable \
swarm-network

Para los controladores de red que proporcionan conectividad entre hosts (por ejemplo, macvlan), si se necesitan configuraciones específicas del nodo para conectar la red en cada host, proporcionará esa configuración a través de una red de solo configuración. Al crear la red con ámbito swarm, especificará el nombre de la red que contiene la

configuración. 
node1$ docker network create --config-only --subnet 192.168.100.0/24 --gateway
192.168.100.115 mv-config node2$ docker network create --config-only --subnet
192.168.200.0/24 --gateway 192.168.200.202 mv-config node1$ docker network crea
te -d macvlan --scope swarm --config-from mv-config --attachable swarm-network
