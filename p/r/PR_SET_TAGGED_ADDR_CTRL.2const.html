PR_SET_TAGGED_ADDR_CTRL(2const) PR_SET_TAGGED_ADDR_CTRL(2const)

NOMBRE

PR_SET_TAGGED_ADDR_CTRL - controlar el soporte para pasar direcciones de espacio de usuario etiquetadas al kernel

LIBRERÍA

Librería C estándar (libc, -lc)

SINOPSIS

#include <linux/prctl.h>  /* Definición de constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_TAGGED_ADDR_CTRL, long modo, 0L, 0L, 0L);

DESCRIPCIÓN

Controla el soporte para pasar direcciones de espacio de usuario etiquetadas al kernel (es decir, direcciones donde los bits 56-63 no son todos cero).

El nivel de soporte se selecciona mediante soporte, que puede ser uno de los siguientes:

0L
Las direcciones que se pasan con el propósito de ser desreferenciadas por el kernel deben no estar etiquetadas.
PR_TAGGED_ADDR_ENABLE
Las direcciones que se pasan con el propósito de ser desreferenciadas por el kernel pueden estar etiquetadas, con las excepciones resumidas a continuación.

En caso de éxito, el modo especificado en modo se establece para el hilo que realiza la llamada.

Si prctl(PR_SET_TAGGED_ADDR_CTRL, 0L, 0L, 0L, 0L) falla con EINVAL, entonces todas las direcciones que se pasen al kernel deben no estar etiquetadas.

Independientemente del modo establecido, las direcciones pasadas a ciertas interfaces siempre deben no estar etiquetadas:

•
brk(2), mmap(2), shmat(2), shmdt(2), y el argumento new_address de mremap(2).
(Antes de Linux 5.6, estos aceptaban direcciones etiquetadas, pero el comportamiento puede no ser el esperado. No confíes en ello.)
•
Interfaces 'polimórficas' que aceptan punteros a tipos arbitrarios convertidos a void * u otro tipo genérico, específicamente prctl(), ioctl(2), y en general setsockopt(2) (solo ciertas opciones específicas de setsockopt(2) permiten direcciones etiquetadas).

Esta lista de exclusiones puede reducirse al pasar de una versión del kernel a una posterior. Aunque el kernel puede hacer algunas garantías por razones de compatibilidad hacia atrás, para el propósito del nuevo software, el efecto de pasar direcciones etiquetadas a estas interfaces no está especificado.

El modo establecido por esta llamada se hereda en fork(2) y clone(2). El modo se restablece por execve(2) a 0 (es decir, las direcciones etiquetadas no están permitidas en la ABI usuario/kernel).

VALOR DE RETORNO

En caso de éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
modo es inválido o no soportado.
EINVAL
Esta característica está deshabilitada a través de /proc/sys/abi/tagged_addr_disabled.

FICHEROS

/proc/sys/abi/tagged_addr_disabled

ESTÁNDARES

Linux. Solo arm64.

HISTORIA

Linux 5.4 (arm64).

ADVERTENCIAS

Esta llamada está destinada principalmente a ser utilizada por el entorno de ejecución. Una llamada exitosa a PR_SET_TAGGED_ADDR_CTRL en otro lugar puede hacer que el proceso que llama falle. Las condiciones para usarla de forma segura son complejas y dependen del sistema. No la uses a menos que sepas lo que estás haciendo.

VER TAMBIÉN

prctl(2), PR_SET_TAGGED_ADDR_CTRL(2const)

Para más información, consulta el archivo fuente del kernel Documentation/arm64/tagged-address-abi.rst.
