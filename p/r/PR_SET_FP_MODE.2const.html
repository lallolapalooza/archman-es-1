PR_SET_FP_MODE(2const) PR_SET_FP_MODE(2const)

NOMBRE

PR_SET_FP_MODE - establece el modo de punto flotante del proceso llamador

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/prctl.h>  /* Definición de las constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_FP_MODE, unsigned long modo);

DESCRIPCIÓN

En la arquitectura MIPS, el código del espacio de usuario puede ser compilado usando una ABI que permite enlazar con código que tiene requisitos más restrictivos de punto flotante (FP). Por ejemplo, el código del espacio de usuario puede ser compilado para el ABI O32 FPXX y enlazado con código compilado para uno de los ABI más restrictivos FP32 o FP64. Cuando se enlaza código más restrictivo, el requisito general para el proceso es usar el modo de punto flotante más restrictivo.

Debido a que el kernel no tiene medios para saber de antemano en qué modo debe ejecutarse el proceso, y dado que estas restricciones pueden cambiar durante la vida del proceso, la operación PR_SET_FP_MODE se proporciona para permitir el control del modo de punto flotante desde el espacio de usuario.

El argumento modo es una máscara de bits que describe el modo de punto flotante utilizado:

PR_FP_MODE_FR
Cuando este bit está desactivado (llamado modo FR=0 o FR0), los 32 registros de punto flotante tienen 32 bits de ancho, y los registros de 64 bits se representan como un par de registros (impar y par, con el registro de número par conteniendo los 32 bits inferiores, y el registro de número impar conteniendo los 32 bits superiores).
Cuando este bit está activado (en hardware compatible), los 32 registros de punto flotante tienen 64 bits de ancho (llamado modo FR=1 o FR1). Tenga en cuenta que las implementaciones MIPS modernas (MIPS R6 y posteriores) solo admiten el modo FR=1.
Las aplicaciones que utilizan el ABI O32 FP32 solo pueden operar cuando este bit está desactivado (FR=0; o pueden usarse con FRE habilitado, ver más abajo). Las aplicaciones que utilizan el ABI O32 FP64 (y el ABI O32 FP64A, que existe para proporcionar la capacidad de operar con código FP32 existente; ver más abajo) solo pueden operar cuando este bit está activado (FR=1). Las aplicaciones que utilizan el ABI O32 FPXX pueden operar con FR=0 o FR=1.
PR_FP_MODE_FRE
Habilita la emulación del modo de punto flotante de 32 bits. Cuando este modo está habilitado, emula operaciones de punto flotante de 32 bits generando una excepción de instrucción reservada en cada instrucción que utiliza formatos de 32 bits y el kernel maneja la instrucción en software. (El problema radica en la discrepancia del manejo de registros impares que son los 32 bits altos de los registros de 64 bits con números pares en modo FR=0 y las partes inferiores de 32 bits de los registros de 64 bits con números impares en modo FR=1). Habilitar este bit es necesario cuando el código con el ABI O32 FP32 debe operar con código con ABIs compatibles O32 FPXX u O32 FP64A (que requieren el modo FPU FR=1) o cuando se ejecuta en hardware más nuevo (MIPS R6 en adelante) que carece de soporte para el modo FR=0 cuando se usa una binaria con el ABI FP32.
Tenga en cuenta que este modo solo tiene sentido cuando la FPU está en modo de 64 bits (FR=1).
Tenga en cuenta que el uso de la emulación tiene intrínsecamente un impacto significativo en el rendimiento y debe evitarse si es posible.

En el ABI N32/N64, siempre se utiliza el modo de punto flotante de 64 bits, por lo que no se requiere emulación de FPU y la FPU siempre opera en modo FR=1.

Esta operación está destinada principalmente a ser utilizada por el enlazador dinámico (ld.so(8)).

VALOR DE RETORNO

Al éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EOPNOTSUPP
modo tiene un valor inválido o no soportado.

ESTANDARES

Linux. Solo MIPS.

HISTORIA

Linux 4.0 (MIPS).

VER TAMBIÉN
