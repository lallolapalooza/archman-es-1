PR_SET_PDEATHSIG(2const) PR_SET_PDEATHSIG(2const)

NOMBRE

PR_SET_PDEATHSIG - establecer la señal de muerte del padre del proceso llamante

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/prctl.h>  /* Definición de las constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_PDEATHSIG, long sig);

DESCRIPCIÓN

Establece la señal de muerte del padre del proceso llamante a sig (ya sea un valor de señal en el rango [1, NSIG - 1], o 0 para borrar). Esta es la señal que recibirá el proceso llamante cuando muera su padre.

La señal de muerte del padre se envía tras la terminación posterior del hilo padre y también tras la terminación de cada proceso subreaper (ver PR_SET_CHILD_SUBREAPER(2const)) al que el llamante sea reparentado posteriormente. Si el hilo padre y todos los subreapers ancestros ya han terminado en el momento de la operación PR_SET_PDEATHSIG, entonces no se envía ninguna señal de muerte del padre al llamante.

La señal de muerte del padre está dirigida al proceso (ver signal(7)) y, si el hijo instala un manejador usando el flag SA_SIGINFO de sigaction(2), el campo si_pid del argumento siginfo_t del manejador contiene el PID del proceso padre que termina.

La configuración de la señal de muerte del padre se borra para el hijo de un fork(2). También se borra (desde Linux 2.4.36 / 2.6.23) al ejecutar un binario con ID de usuario o grupo establecido, o un binario que tiene capacidades asociadas (ver capabilities(7)); de lo contrario, este valor se conserva a través de execve(2). La configuración de la señal de muerte del padre también se borra al cambiar cualquiera de las siguientes credenciales del hilo: ID de usuario efectivo, ID de grupo efectivo, ID de usuario del sistema de archivos o ID de grupo del sistema de archivos.

VALOR DE RETORNO

En caso de éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
sig no es un número de señal válido.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.1.57.

ADVERTENCIAS

El "padre" en este caso se considera el hilo que creó este proceso. En otras palabras, la señal se enviará cuando ese hilo termine (a través de, por ejemplo, pthread_exit(3)), en lugar de después de que todos los hilos del proceso padre terminen.

VER TAMBIÉN

prctl(2), PR_GET_PDEATHSIG(2const)
