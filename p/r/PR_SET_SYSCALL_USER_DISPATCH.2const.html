PR_SET_SYSCALL_USER_DISPATCH(2const) PR_SET_SYSCALL_USER_DISPATCH(2const)

NOMBRE

PR_SET_SYSCALL_USER_DISPATCH - configurar el mecanismo de envío de llamadas al sistema para el hilo que llama

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/prctl.h>  /* Definición de constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_SYSCALL_USER_DISPATCH, long op, ...);
int prctl(PR_SET_SYSCALL_USER_DISPATCH, PR_SYS_DISPATCH_ON,
          unsigned long off, unsigned long size, int8_t *switch);
int prctl(PR_SET_SYSCALL_USER_DISPATCH, PR_SYS_DISPATCH_OFF, 0L, 0L, 0L);

DESCRIPCIÓN

Configura el mecanismo de Envío de Llamadas al Sistema por Usuario para el hilo que llama. Este mecanismo permite a una aplicación interceptar selectivamente llamadas al sistema para que puedan ser manejadas dentro de la propia aplicación. La interceptación toma la forma de una señal SIGSYS dirigida al hilo que se entrega al hilo cuando realiza una llamada al sistema. Si se intercepta, el kernel no ejecuta la llamada al sistema.

PR_SYS_DISPATCH_ON
Habilita este mecanismo.
Una vez habilitado, las llamadas al sistema posteriores serán interceptadas selectivamente, dependiendo de una variable de control proporcionada por el espacio de usuario. En este caso, off y size identifican respectivamente el desplazamiento y el tamaño de una única región de memoria contigua en el espacio de direcciones del proceso desde donde siempre se permite la ejecución de llamadas al sistema, independientemente de la variable de control. (Típicamente, esta área incluiría el área de memoria que contiene la biblioteca C).
switch apunta a una variable que es un interruptor rápido para permitir/bloquear la ejecución de llamadas al sistema sin la sobrecarga de realizar otra llamada al sistema para reconfigurar el Envío de Llamadas al Sistema. Esta variable de control puede establecerse en SYSCALL_DISPATCH_FILTER_BLOCK para bloquear la ejecución de llamadas al sistema o en SYSCALL_DISPATCH_FILTER_ALLOW para permitir temporalmente su ejecución. El kernel comprueba este valor en cada entrada de llamada al sistema, y cualquier valor inesperado generará un SIGSYS inalcanzable en ese momento, matando la aplicación.
Cuando se intercepta una llamada al sistema, el kernel envía una señal SIGSYS dirigida al hilo a la señal que la desencadenó. Se establecerán varios campos en la estructura siginfo_t (ver sigaction(2)) asociada a la señal:
•
si_signo contendrá SIGSYS.
•
si_call_addr mostrará la dirección de la instrucción de llamada al sistema.
•
si_syscall y si_arch indicarán qué llamada al sistema se intentó.
•
si_code contendrá SYS_USER_DISPATCH.
•
si_errno se establecerá en 0.
El contador de programa estará como si la llamada al sistema hubiera ocurrido (es decir, el contador de programa no apuntará a la instrucción de llamada al sistema).
Cuando el manejador de señales regrese al kernel, la llamada al sistema se completará inmediatamente y devolverá el control al hilo que la llamó, sin ser ejecutada realmente. Si es necesario (es decir, al emular la llamada al sistema en el espacio de usuario), el manejador de señales debería establecer el valor de retorno de la llamada al sistema a un valor seguro, modificando el contexto de registro almacenado en el argumento ucontext del manejador de señales. Ver sigaction(2), sigreturn(2) y getcontext(3) para más información.
PR_SYS_DISPATCH_OFF
El Envío de Llamadas al Sistema por Usuario está deshabilitado para ese hilo.

La configuración no se conserva a través de fork(2), clone(2) o execve(2).

VALOR DE RETORNO

Al éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
switch es una dirección inválida.
EINVAL
op es PR_SYS_DISPATCH_ON y el rango de memoria especificado está fuera del espacio de direcciones del proceso.
EINVAL
op es inválido.

ESTÁNDARES

Linux. Solo x86.

HISTORIA

Linux 5.11 (x86).

VER TAMBIÉN
