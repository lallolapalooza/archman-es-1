PR_RISCV_SET_ICACHE_FLUSH_CTX(2const) PR_RISCV_SET_ICACHE_FLUSH_CTX(2const)

NOMBRE

PR_RISCV_SET_ICACHE_FLUSH_CTX - Habilita/deshabilita instrucciones de purga de caché de instrucciones en el espacio de usuario.

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/prctl.h>  /* Definición de constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_RISCV_SET_ICACHE_FLUSH_CTX, unsigned long ctx,
          unsigned long scope);

DESCRIPCIÓN

El contexto y el alcance se pueden proporcionar usando ctx y scope respectivamente.

Cuando el alcance se establece en PR_RISCV_SCOPE_PER_PROCESS, se permite a todos los hilos del proceso emitir instrucciones de purga de caché de instrucciones. Cada vez que un hilo del proceso sea migrado, se garantizará que la caché de instrucciones del hart correspondiente sea coherente con el almacenamiento de instrucciones. Esto no impone ninguna garantía fuera de la migración. Si un hilo modifica una instrucción que otro hilo podría intentar ejecutar, el otro hilo aún debe emitir una instrucción de purga de caché de instrucciones antes de intentar ejecutar la instrucción potencialmente modificada. Esto debe ser realizado por el programa en espacio de usuario.

En el contexto por hilo (por ejemplo, si el alcance se establece en PR_RISCV_SCOPE_PER_THREAD), solo el hilo que llama a esta función tiene permiso para emitir instrucciones de purga de caché de instrucciones. Cuando el hilo sea migrado, se garantizará que la caché de instrucciones del hart correspondiente sea coherente con el almacenamiento de instrucciones.

En kernels configurados sin SMP, este prctl PR_RISCV_SET_ICACHE_FLUSH_CTX es un no-op, ya que las migraciones entre harts no ocurrirán.

Los siguientes valores para ctx se pueden especificar:

PR_RISCV_CTX_SW_FENCEI_ON (desde Linux 6.10)
Permite `fence.i` en el espacio de usuario.
PR_RISCV_CTX_SW_FENCEI_OFF (desde Linux 6.10)
No permite `fence.i` en el espacio de usuario. Todos los hilos de un proceso se verán afectados cuando el alcance se establezca en PR_RISCV_SCOPE_PER_PROCESS. Por lo tanto, se debe tener cuidado; use esta bandera solo cuando pueda garantizar que ningún hilo del proceso emitirá `fence.i` a partir de ese momento.

Los siguientes valores para scope se pueden especificar:

PR_RISCV_SCOPE_PER_PROCESS (desde Linux 6.10)
Garantiza que la caché de instrucciones de cualquier hilo de este proceso sea coherente con el almacenamiento de instrucciones tras la migración.
PR_RISCV_SCOPE_PER_THREAD (desde Linux 6.10)
Garantiza que la caché de instrucciones del hilo actual sea coherente con el almacenamiento de instrucciones tras la migración.

EJEMPLOS

Los siguientes archivos están destinados a ser compilados y enlazados entre sí. La función `modify_instruction()` reemplaza un `add` con cero por un `add` con uno, lo que hace que la secuencia de instrucciones en `get_value()` pase de devolver cero a devolver uno.

Fuente del programa: cmodx.c

#include <stdio.h>
#include <sys/prctl.h>
extern int get_value(void);
extern void modify_instruction(void);
int
main(void)
{
    int value = get_value();
    printf("Valor antes de cmodx: %d\n", value);
    // Llamar a prctl antes de que se llame a la primera fence.i
    prctl(PR_RISCV_SET_ICACHE_FLUSH_CTX, PR_RISCV_CTX_SW_FENCEI_ON,
          PR_RISCV_SCOPE_PER_PROCESS);
    modify_instruction();
    // Llamar a prctl después de que se llame a la última fence.i en el proceso
    prctl(PR_RISCV_SET_ICACHE_FLUSH_CTX, PR_RISCV_CTX_SW_FENCEI_OFF,
          PR_RISCV_SCOPE_PER_PROCESS);
    value = get_value();
    printf("Valor después de cmodx: %d\n", value);
    return 0;
}

Fuente del programa: cmodx.S

.option norvc
.text
.global modify_instruction
modify_instruction:
lw a0, new_insn
lui a5,%hi(old_insn)
sw  a0,%lo(old_insn)(a5)
fence.i
ret
.section modifiable, "awx"
.global get_value
get_value:
li a0, 0
old_insn:
addi a0, a0, 0
ret
.data
new_insn:
addi a0, a0, 1

Resultado esperado

Valor antes de cmodx: 0
Valor después de cmodx: 1
