NOMBRE

PREPARE - prepara una sentencia para su ejecución

SINOPSIS

PREPARE nombre [ ( tipo_dato [, ...] ) ] AS sentencia

DESCRIPCIÓN

PREPARE crea una sentencia preparada. Una sentencia preparada es un objeto del lado del servidor que se puede usar para optimizar el rendimiento. Cuando se ejecuta la sentencia PREPARE, la sentencia especificada se analiza, se examina y se reescribe. Cuando posteriormente se emite un comando EXECUTE, se planifica y se ejecuta la sentencia preparada. Esta división del trabajo evita el trabajo repetitivo de análisis, al tiempo que permite que el plan de ejecución dependa de los valores de los parámetros específicos proporcionados.

Las sentencias preparadas pueden tener parámetros: valores que se sustituyen en la sentencia cuando se ejecuta. Al crear la sentencia preparada, haga referencia a los parámetros por posición, usando $1, $2, etc. Opcionalmente, se puede especificar una lista correspondiente de tipos de datos de parámetros. Cuando no se especifica el tipo de dato de un parámetro o se declara como desconocido, el tipo se infiere del contexto en el que se hace referencia al parámetro por primera vez (si es posible). Al ejecutar la sentencia, especifique los valores reales para estos parámetros en la sentencia EXECUTE. Consulte EXECUTE(7) para obtener más información al respecto.

Las sentencias preparadas solo duran durante la sesión de base de datos actual. Cuando finaliza la sesión, se olvida la sentencia preparada, por lo que debe recrearse antes de volver a usarla. Esto también significa que una única sentencia preparada no puede ser utilizada por múltiples clientes de base de datos simultáneos; sin embargo, cada cliente puede crear su propia sentencia preparada para usarla. Las sentencias preparadas se pueden limpiar manualmente utilizando el comando DEALLOCATE.

Las sentencias preparadas potencialmente tienen la mayor ventaja de rendimiento cuando se utiliza una única sesión para ejecutar un gran número de sentencias similares. La diferencia de rendimiento será particularmente significativa si las sentencias son complejas de planificar o reescribir, por ejemplo, si la consulta implica la unión de muchas tablas o requiere la aplicación de varias reglas. Si la sentencia es relativamente simple de planificar y reescribir, pero relativamente costosa de ejecutar, la ventaja de rendimiento de las sentencias preparadas será menos notable.

PARÁMETROS

nombre

Un nombre arbitrario asignado a esta sentencia preparada específica. Debe ser único dentro de una sola sesión y posteriormente se utiliza para ejecutar o liberar una sentencia previamente preparada.

tipo_dato

El tipo de dato de un parámetro para la sentencia preparada. Si el tipo de dato de un parámetro particular no está especificado o se especifica como desconocido, se inferirá del contexto en el que se hace referencia al parámetro por primera vez. Para hacer referencia a los parámetros en la propia sentencia preparada, utilice $1, $2, etc.

sentencia

Cualquier sentencia SELECT, INSERT, UPDATE, DELETE, MERGE o VALUES.

NOTAS

Una sentencia preparada se puede ejecutar con un plan genérico o un plan personalizado. Un plan genérico es el mismo en todas las ejecuciones, mientras que un plan personalizado se genera para una ejecución específica utilizando los valores de los parámetros dados en esa llamada. El uso de un plan genérico evita la sobrecarga de planificación, pero en algunas situaciones un plan personalizado será mucho más eficiente de ejecutar porque el planificador puede hacer uso del conocimiento de los valores de los parámetros. (Por supuesto, si la sentencia preparada no tiene parámetros, entonces esto es irrelevante y siempre se utiliza un plan genérico).

Por defecto (es decir, cuando plan_cache_mode está configurado como auto), el servidor elegirá automáticamente si utilizar un plan genérico o personalizado para una sentencia preparada que tiene parámetros. La regla actual para esto es que las primeras cinco ejecuciones se realizan con planes personalizados y se calcula el costo estimado promedio de esos planes. Luego se crea un plan genérico y su costo estimado se compara con el costo promedio del plan personalizado. Las ejecuciones posteriores utilizan el plan genérico si su costo no es tan superior al costo promedio del plan personalizado como para que la repetición de la planificación parezca preferible.

Esta heurística puede ser anulada, forzando al servidor a usar planes genéricos o personalizados, estableciendo plan_cache_mode en force_generic_plan o force_custom_plan respectivamente. Esta configuración es principalmente útil si la estimación del costo del plan genérico es errónea por alguna razón, lo que permite que se elija aunque su costo real sea mucho mayor que el de un plan personalizado.

Para examinar el plan de consulta que PostgreSQL está utilizando para una sentencia preparada, utilice EXPLAIN, por ejemplo

EXPLAIN EXECUTE nombre(valores_parámetros);

Si se está utilizando un plan genérico, contendrá símbolos de parámetros $n, mientras que un plan personalizado tendrá los valores de parámetros proporcionados sustituidos en él.

Para obtener más información sobre la planificación de consultas y las estadísticas recopiladas por PostgreSQL para ese propósito, consulte la documentación de ANALYZE(7).

Aunque el objetivo principal de una sentencia preparada es evitar el análisis y la planificación repetidos de la sentencia, PostgreSQL forzará la re-analización y la re-planificación de la sentencia antes de usarla siempre que los objetos de la base de datos utilizados en la sentencia hayan sufrido cambios de definición (DDL) o sus estadísticas del planificador se hayan actualizado desde el uso anterior de la sentencia preparada. Además, si el valor de search_path cambia de un uso a otro, la sentencia se volverá a analizar utilizando el nuevo search_path. (Este último comportamiento es nuevo a partir de PostgreSQL 9.3.) Estas reglas hacen que el uso de una sentencia preparada sea semánticamente casi equivalente a reenviar el mismo texto de consulta una y otra vez, pero con un beneficio de rendimiento si no se cambian las definiciones de los objetos, especialmente si el mejor plan sigue siendo el mismo entre usos. Un ejemplo de un caso en el que la equivalencia semántica no es perfecta es que si la sentencia se refiere a una tabla por un nombre no calificado, y luego se crea una nueva tabla con el mismo nombre en un esquema que aparece antes en el search_path, no ocurrirá ningún reanálisis automático ya que ningún objeto utilizado en la sentencia cambió. Sin embargo, si algún otro cambio fuerza un reanálisis, la nueva tabla será referenciada en usos posteriores.

Puede ver todas las sentencias preparadas disponibles en la sesión consultando la vista del sistema pg_prepared_statements.

EJEMPLOS

Crear una sentencia preparada para una sentencia INSERT, y luego ejecutarla:

PREPARE fooplan (int, text, bool, numeric) AS
    INSERT INTO foo VALUES($1, $2, $3, $4);
EXECUTE fooplan(1, 'Hunter Valley', 't', 200.00);

Crear una sentencia preparada para una sentencia SELECT, y luego ejecutarla:

PREPARE usrrptplan (int) AS
    SELECT * FROM users u, logs l WHERE u.usrid=$1 AND u.usrid=l.usrid
    AND l.date = $2;
EXECUTE usrrptplan(1, current_date);

En este ejemplo, el tipo de dato del segundo parámetro no está especificado, por lo que se infiere del contexto en el que se utiliza $2.

COMPATIBILIDAD

El estándar SQL incluye una sentencia PREPARE, pero es solo para uso en SQL incrustado. Esta versión de la sentencia PREPARE también utiliza una sintaxis algo diferente.

NAME
PREPARE — crear un plan de ejecución de consulta preparado
SYNOPSIS
PREPARE nombre_plan [ ( [ tipo_parametro [, ...] ] ) ]
    AS sentencia
DESCRIPTION

La sentencia PREPARE crea un plan de ejecución preparado a partir de una sentencia SQL. Los planes preparados se pueden usar para ejecutar la misma sentencia varias veces de manera más eficiente.

Una vez que un plan se ha preparado, se puede ejecutar usando la sentencia EXECUTE. Los planes preparados se guardan solo durante la sesión actual; se descartan cuando finaliza la sesión.

PARAMETERS
nombre_plan
El nombre que se le da al plan preparado. Debe ser único entre los planes preparados en la sesión actual.
tipo_parametro
Si se especifican, estos son los tipos de datos de los parámetros de entrada para la sentencia preparada. Si no se especifican, los tipos de parámetros se infieren de la sentencia.
sentencia
La sentencia SQL (generalmente SELECT, INSERT, UPDATE, o DELETE) para la que se creará el plan preparado.
NOTES

Si una sentencia preparada se ejecuta varias veces, puede ser más rápida que ejecutar la sentencia original cada vez, ya que el plan de ejecución se genera solo la primera vez. Sin embargo, si la sentencia preparada usa parámetros, el planificador puede ser capaz de generar un plan más optimizado si conoce los tipos de los parámetros. Por lo tanto, especificar tipo_parametro puede mejorar el rendimiento en algunos casos.

Los planes preparados se descartan automáticamente cuando finaliza la sesión. Para eliminar un plan preparado explícitamente, se usa la sentencia DEALLOCATE.

EXAMPLES

Preparar una sentencia SELECT para obtener información de un usuario por su ID: 

PREPARE obtener_usuario (integer) AS
    SELECT * FROM usuarios WHERE id = $1;

Ejecutar el plan preparado con un ID de usuario específico: 

EXECUTE obtener_usuario(123);

Preparar una sentencia INSERT: 

PREPARE insertar_registro (integer, text) AS
    INSERT INTO registros (id, descripcion) VALUES ($1, $2);

Ejecutar el plan preparado: 

EXECUTE insertar_registro(456, 'Nuevo registro');
COMPATIBILITY

La sentencia PREPARE es una característica estándar de SQL y está disponible en la mayoría de los sistemas de bases de datos SQL.
