NOMBRE

PREPARE_TRANSACTION - prepara la transacción actual para el commit en dos fases

SINOPSIS

PREPARE TRANSACTION id_transaccion

DESCRIPCIÓN

PREPARE TRANSACTION prepara la transacción actual para el commit en dos fases. Después de este comando, la transacción ya no está asociada con la sesión actual; en cambio, su estado se almacena completamente en disco, y existe una probabilidad muy alta de que pueda completarse con éxito, incluso si ocurre un fallo de la base de datos antes de que se solicite el commit.

Una vez preparada, una transacción puede ser completada o revertida más tarde con COMMIT PREPARED o ROLLBACK PREPARED, respectivamente. Esos comandos pueden ser emitidos desde cualquier sesión, no solo desde la que ejecutó la transacción original.

Desde el punto de vista de la sesión que emite el comando, PREPARE TRANSACTION no es muy diferente de un comando ROLLBACK: después de ejecutarlo, no hay ninguna transacción actual activa, y los efectos de la transacción preparada ya no son visibles. (Los efectos volverán a ser visibles si la transacción se completa.)

Si el comando PREPARE TRANSACTION falla por cualquier motivo, se convierte en un ROLLBACK: la transacción actual se cancela.

PARÁMETROS

id_transaccion

Un identificador arbitrario que más tarde identifica esta transacción para COMMIT PREPARED o ROLLBACK PREPARED. El identificador debe ser escrito como un literal de cadena y debe tener menos de 200 bytes de longitud. No debe ser el mismo que el identificador utilizado para ninguna transacción preparada actualmente.

NOTAS

PREPARE TRANSACTION no está pensado para ser utilizado en aplicaciones o sesiones interactivas. Su propósito es permitir que un gestor de transacciones externo realice transacciones globales atómicas a través de múltiples bases de datos u otros recursos transaccionales. A menos que esté escribiendo un gestor de transacciones, probablemente no debería usar PREPARE TRANSACTION.

Este comando debe usarse dentro de un bloque de transacción. Use BEGIN para iniciar uno.

Actualmente no está permitido PREPARE una transacción que haya ejecutado operaciones que involucren tablas temporales o el espacio de nombres temporal de la sesión, haya creado cursores WITH HOLD, o haya ejecutado LISTEN, UNLISTEN o NOTIFY. Esas características están demasiado ligadas a la sesión actual para ser útiles en una transacción que se va a preparar.

Si la transacción modificó algún parámetro en tiempo de ejecución con SET (sin la opción LOCAL), esos efectos persisten después de PREPARE TRANSACTION, y no se verán afectados por ningún COMMIT PREPARED o ROLLBACK PREPARED posterior. Por lo tanto, en este único aspecto, PREPARE TRANSACTION actúa más como COMMIT que como ROLLBACK.

Todas las transacciones preparadas actualmente disponibles se listan en la vista del sistema pg_prepared_xacts.


Precaución

No es aconsejable dejar transacciones en estado preparado durante mucho tiempo. Esto interferirá con la capacidad de VACUUM para recuperar espacio y, en casos extremos, podría causar que la base de datos se cierre para evitar el desbordamiento del ID de transacción (ver Sección 24.1.5). Tenga en cuenta también que la transacción continúa manteniendo los bloqueos que tuviera. El uso previsto de esta característica es que una transacción preparada normalmente se completará o revertirá tan pronto como un gestor de transacciones externo haya verificado que otras bases de datos también están listas para completar.

Si no ha configurado un gestor de transacciones externo para rastrear las transacciones preparadas y asegurarse de que se cierran puntualmente, es mejor mantener la característica de transacción preparada deshabilitada estableciendo max_prepared_transactions en cero. Esto evitará la creación accidental de transacciones preparadas que luego puedan olvidarse y eventualmente causar problemas.

EJEMPLOS

Prepara la transacción actual para el commit en dos fases, usando foobar como identificador de transacción:

PREPARE TRANSACTION 'foobar';

COMPATIBILIDAD

PREPARE TRANSACTION es una extensión de PostgreSQL. Está destinado a ser utilizado por sistemas externos de gestión de transacciones, algunos de los cuales están cubiertos por estándares (como X/Open XA), pero el lado SQL de esos sistemas no está estandarizado.
