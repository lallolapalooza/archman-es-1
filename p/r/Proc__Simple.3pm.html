NOMBRE

Proc::Simple -- lanzar y controlar procesos en segundo plano

SINOPSIS

use Proc::Simple;
$mi_proceso = Proc::Simple->new();        # Crear un nuevo objeto de proceso
$mi_proceso->start("linea-de-comando-shell"); # Lanzar un programa externo
$mi_proceso->start("comando",             # Lanzar un programa externo
               "parametro", ...);         # con parámetros

$mi_proceso->start(sub { ... });          # Lanzar una subrutina de perl
$mi_proceso->start(\&subrutina);         # Lanzar una subrutina de perl
$mi_proceso->start(\&subrutina,          # Lanzar una subrutina de perl
               $parametro, ...);          # con parámetros
$corriendo = $mi_proceso->poll();           # Sondear el proceso en ejecución
$estado_salida = $mi_proceso->wait();       # Esperar hasta que el proceso termine
$proc->kill_on_destroy(1);            # Establecer matar al destruir
$proc->signal_on_destroy("KILL");     # Especificar la señal a enviar
                                      # al destruir
$mi_proceso->kill();                      # Matar proceso (SIGTERM)
$mi_proceso->kill("SIGUSR1");             # Enviar señal especificada
$mi_proceso->exit_status();               # Devolver el estado de salida del proceso
Proc::Simple::debug($nivel);          # Activar depuración

DESCRIPCIÓN

El paquete Proc::Simple proporciona objetos que imitan procesos de la vida real desde el punto de vista del usuario. Se crea un nuevo objeto de proceso con

$mi_proceso = Proc::Simple->new();

Se pueden lanzar y controlar tanto programas externos como subrutinas de perl como procesos en segundo plano.

Un proceso de espera de 10 segundos, por ejemplo, se puede lanzar como un programa externo como en

$mi_proceso->start("/bin/sleep 10");    # o
$mi_proceso->start("/bin/sleep", "10");

o como una subrutina de perl, como en

sub misueño { sleep(shift); }    # Definir mysleep()
$mi_proceso->start(\&misueño, 10);   # Lanzarlo.

o incluso como

$mi_proceso->start(sub { sleep(10); });

El método start devuelve inmediatamente después de iniciar el proceso especificado en segundo plano, es decir, no hay bloqueo. Devuelve 1 si el proceso se lanzó con éxito y 0 si no.

El método poll comprueba si el proceso sigue en ejecución

$corriendo = $mi_proceso->poll();

y devuelve 1 si lo está, 0 si no. Finalmente,

$mi_proceso->kill();

termina el proceso enviándole la señal SIGTERM. Como opción, se puede especificar otra señal.

$mi_proceso->kill("SIGUSR1");

envía la señal SIGUSR1 al proceso en ejecución. kill devuelve 1 si tiene éxito al enviar la señal, 0 si no.

Los métodos se discuten con más detalle en la siguiente sección.

Se proporciona un destructor para que se pueda enviar una señal a los procesos creados por fork automáticamente si el objeto de proceso se destruye o si el proceso sale. Por defecto, este comportamiento está desactivado (ver los métodos kill_on_destroy y signal_on_destroy).

MÉTODOS

Los siguientes métodos están disponibles:

new (Constructor)
Crea una nueva instancia de esta clase escribiendo 
$proc = new Proc::Simple;

o

$proc = Proc::Simple->new();

No toma argumentos.

start
Lanza un nuevo proceso. El método start() se puede utilizar para lanzar tanto programas externos (como "/bin/echo") como subrutinas definidas por el usuario (como foo()) en un nuevo proceso.

Para iniciar un programa externo, llame

$status = $proc->start("nombre-programa");

Si desea pasar un par de parámetros al programa lanzado, existen dos opciones: Puede pasarlos en un solo argumento como en

$status = $proc->start("/bin/echo hola mundo");

o en varios argumentos como en

$status = $proc->start("/bin/echo", "hola", "mundo");

Al igual que en la función system() de Perl, existe una gran diferencia entre los dos métodos: Si proporciona un argumento que contiene una línea de comando separada por espacios, su shell procesará cualquier meta-carácter (si decide usar alguno) antes de que el proceso se lance realmente:

$status = $proc->start("/bin/ls -l /etc/initt*");

expandirá "/etc/initt*" a "/etc/inittab" antes de ejecutar el comando "ls". Si, por otro lado, dice

$status = $proc->start("/bin/ls", "-l", "*");

el "*" permanecerá sin expandir, lo que significa que buscará un archivo con el nombre literal "*" (lo cual es poco probable que exista en su sistema a menos que cree deliberadamente archivos con nombres confusos :). Para más información sobre esto, busque "perldoc -f exec".

Si, por otro lado, desea iniciar una subrutina de Perl en segundo plano, simplemente proporcione la referencia de la función como en

$status = $proc->start(\&tu_funcion);

o proporcione una subrutina sin nombre:

$status = $proc->start( sub { sleep(1) } );

También puede proporcionar parámetros adicionales para que se pasen a la función:

$status = $proc->start(\&imprimeme, "hola", "mundo");

El método start devuelve inmediatamente después de iniciar el proceso especificado en segundo plano, es decir, en modo no bloqueante. Devuelve 1 si el proceso se lanzó con éxito y 0 si no.

poll
El método poll comprueba si el proceso sigue en ejecución 
$corriendo = $mi_proceso->poll();

y devuelve 1 si lo está, 0 si no.

kill
El método kill(): 
$mi_proceso->kill();

termina el proceso enviándole la señal SIGTERM. Como opción, se puede especificar otra señal.

$mi_proceso->kill("SIGUSR1");

envía la señal SIGUSR1 al proceso en ejecución. kill devuelve 1 si tiene éxito al enviar la señal, 0 si no.

kill_on_destroy
Establece una bandera para determinar si el proceso asociado a este objeto debe ser terminado cuando el objeto sea destruido. Por defecto, esta bandera está establecida en falso. Se devuelve el valor actual. 
$actual = $proc->kill_on_destroy;
$proc->kill_on_destroy(1); # Establecer bandera a verdadero
$proc->kill_on_destroy(0); # Establecer bandera a falso
signal_on_destroy
Método para establecer la señal que se enviará al proceso cuando el objeto sea destruido (Suponiendo que kill_on_destroy es verdadero). Devuelve la configuración actual. 
$actual = $proc->signal_on_destroy;
$proc->signal_on_destroy("KILL");
redirect_output
Redirige la salida estándar (stdout) y/o el error estándar (stderr) a un archivo. Especifique undef para dejar los manejadores de stderr/stdout del proceso sin cambios. 
# stdout a un archivo, stderr sin cambios
$proc->redirect_output ("/tmp/someapp.stdout", undef);

# stderr a un archivo, stdout sin cambios
$proc->redirect_output (undef, "/tmp/someapp.stderr");

# stdout y stderr a un archivo separado
$proc->redirect_output ("/tmp/someapp.stdout", "/tmp/someapp.stderr");

Llame a este método antes de ejecutar el método start.

pid
Devuelve el pid del proceso creado por fork asociado con este objeto 
$pid = $proc->pid;
t0
Devuelve el time() de inicio del proceso creado por fork asociado con este objeto 
$t0 = $proc->t0();
t1
Devuelve el time() de parada del proceso creado por fork asociado con este objeto

METHODS

t0
Returns the time when the process was started.
t1
Returns the time when the process finished.
DESTROY (Destructor)
Destructor de objetos. Este método se llama cuando el objeto es destruido (p.ej. con "undef" o al salir de perl). Si kill_on_destroy es verdadero, se envía la señal signal_on_destroy (SIGTERM si no está definida) al proceso asociado con el objeto.
exit_status
Devuelve el estado de salida del proceso tal como lo indica la variable $!. Si el proceso todavía se está ejecutando, se devuelve "undef".
wait
El método wait: 
$estado_salida = $mi_proc->wait();

espera hasta que el proceso termine y devuelve su estado de salida.

debug
Activa y desactiva los mensajes de depuración -- Proc::Simple::debug(1) los activa, Proc::Simple::debug(0) mantiene Proc::Simple silencioso.
cleanup
Proc::Simple guarda datos de procesos terminados, p.ej. puedes verificar a través de t0() y t1() cuánto tiempo se ejecutó un proceso, incluso si ya terminó hace tiempo. Con el tiempo, estos datos siguen ocupando más y más memoria y si tienes un programa de larga ejecución, podrías querer ejecutar "Proc::Simple->cleanup()" de vez en cuando para eliminar los datos de procesos que ya no se usan.

NOTA

Por favor, ten en cuenta que no hay garantía de que la señal SIGTERM realmente termine un proceso. Los procesos pueden tener manejadores de señales definidos que eviten el cierre. En caso de duda sobre si un proceso todavía existe, compruébalo repetidamente con la rutina poll después de enviar la señal.

Procesos de Shell

Si pasas un programa de shell a Proc::Simple, usará exec() para lanzarlo. Como se indica en el manual de Perl para exec(), los comandos simples para la versión de un argumento de exec() se pasarán directamente a execvp(), mientras que los comandos que contengan caracteres como ";" o "*" se pasarán a un shell para asegurar que reciban el tratamiento de expansión del shell.

Esto tiene el efecto secundario interesante de que si lanzas algo como

$p->start("./womper *");

verás dos procesos en tu lista de procesos:

$ ps auxww | grep womper
mschilli  9126 11:21 0:00 sh -c ./womper *
mschilli  9127 11:21 0:00 /usr/local/bin/perl -w ./womper ...

Un kill() normal en el PID del proceso solo mataría el primer proceso, pero el kill() de Proc::Simple usará una señal negativa y la enviará al primer proceso (9126). Como marcó el proceso como líder de grupo de procesos cuando lo creó previamente (a través de setsid()), esto hará que ambos procesos anteriores reciban la señal enviada por kill().
