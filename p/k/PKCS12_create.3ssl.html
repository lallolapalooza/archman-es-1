PKCS12_create(3ssl)

Paquete: openssl

Licencias: Apache-2.0

PKCS12_CREATE(3ssl) OpenSSL PKCS12_CREATE(3ssl)

NOMBRE

PKCS12_create, PKCS12_create_ex, PKCS12_create_cb, PKCS12_create_ex2 - crear una estructura PKCS#12

SINOPSIS

 #include <openssl/pkcs12.h>
 PKCS12 *PKCS12_create(const char *pass, const char *name, EVP_PKEY *pkey,
                       X509 *cert, STACK_OF(X509) *ca,
                       int nid_key, int nid_cert, int iter, int mac_iter, int keytype);
 PKCS12 *PKCS12_create_ex(const char *pass, const char *name, EVP_PKEY *pkey,
                          X509 *cert, STACK_OF(X509) *ca, int nid_key, int nid_cert,
                          int iter, int mac_iter, int keytype,
                          OSSL_LIB_CTX *ctx, const char *propq);
 typedef int PKCS12_create_cb(PKCS12_SAFEBAG *bag, void *cbarg);
 PKCS12 *PKCS12_create_ex2(const char *pass, const char *name, EVP_PKEY *pkey,
                           X509 *cert, STACK_OF(X509) *ca, int nid_key, int nid_cert,
                           int iter, int mac_iter, int keytype,
                           OSSL_LIB_CTX *ctx, const char *propq,
                           PKCS12_create_cb *cb, void *cbarg);
=head1 DESCRIPCIÓN

PKCS12_create() crea una estructura PKCS#12.

pass es la contraseña a utilizar. name es el friendlyName a utilizar para el certificado y la clave proporcionados. pkey es la clave privada a incluir en la estructura y cert su certificado correspondiente. ca, si no es NULL, es un conjunto opcional de certificados a incluir también en la estructura.

nid_key y nid_cert son los algoritmos de cifrado que deben usarse para la clave y el certificado respectivamente. Los modos GCM, CCM, XTS y OCB no son compatibles. iter es el contador de iteraciones del algoritmo de cifrado a utilizar y mac_iter es el contador de iteraciones MAC a utilizar. keytype es el tipo de clave.

PKCS12_create_ex() es idéntica a PKCS12_create() pero permite un contexto de biblioteca ctx y una consulta de propiedad propq para ser utilizados para seleccionar implementaciones de algoritmos.

PKCS12_create_ex2() es idéntica a PKCS12_create_ex() pero permite una función de devolución de llamada definida por el usuario cb de tipo PKCS12_create_cb para ser especificada y también permite un argumento opcional cbarg para ser pasado de vuelta a la función de devolución de llamada.

La función cb, si se especifica, se llamará para cada safebag añadido a la estructura PKCS12 y permite el procesamiento opcional de la aplicación en el safebag asociado. Por ejemplo, un uso de este tipo podría ser añadir atributos al safebag.

NOTAS

Los parámetros nid_key, nid_cert, iter, mac_iter y keytype se pueden establecer a cero y se usarán valores predeterminados sensatos.

Estos valores predeterminados son: cifrado basado en contraseña AES (PBES2 con PBKDF2 y AES-256-CBC) para claves privadas y certificados, el contador de iteraciones de derivación de clave PBKDF2 y MAC de PKCS12_DEFAULT_ITER (actualmente 2048), y algoritmo MAC HMAC con SHA2-256. El algoritmo de derivación de clave MAC utilizado para la estructura PKCS#12 externa es PKCS12KDF.

El contador de iteraciones MAC predeterminado es 1 para mantener la compatibilidad con software antiguo que no interpretaba los contadores de iteraciones MAC. Si dicha compatibilidad no es necesaria, mac_iter debería establecerse en PKCS12_DEFAULT_ITER.

keytype añade una bandera al almacén de claves privadas. Esta es una extensión no estándar que actualmente solo es interpretada por MSIE. Si se establece a cero, la bandera se omite; si se establece a KEY_SIG, la clave se puede usar solo para firmar; si se establece a KEY_EX, se puede usar para firmar y cifrar. Esta opción fue útil para software de grado de exportación antiguo que podía usar claves de solo firma de tamaño arbitrario pero tenía restricciones en los tamaños permitidos de claves que podían usarse para cifrar.

Si name es NULL y cert contiene un alias, entonces este se usará para el friendlyName correspondiente en la estructura PKCS12 en su lugar. De manera similar, si pkey es NULL y cert contiene un keyid, entonces este se usará para el localKeyID correspondiente en la estructura PKCS12 en lugar del ID calculado a partir de pkey.

Para todos los certificados en ca, si un certificado contiene un alias o keyid, entonces este se usará para el friendlyName o localKeyID correspondiente en la estructura PKCS12.

Se puede pasar pkey, cert o ambos como NULL para indicar que no se requiere ninguna clave o certificado. En versiones anteriores, ambos debían estar presentes o se devolvía un error fatal.

nid_key o nid_cert se pueden establecer a -1 para indicar que no se debe usar cifrado.

mac_iter se puede establecer a -1 y el MAC se omitirá por completo. Esto puede ser útil cuando se ejecuta con el proveedor FIPS, ya que PKCS12KDF no es un algoritmo aprobado por FIPS.

PKCS12_create() hace suposiciones sobre la codificación de la frase de contraseña dada. Consulte passphrase-encoding(7) para más información.

Si se especifica cb, entonces debería devolver 1 en caso de éxito y -1 en caso de error fatal. Un retorno de 0 está destinado a significar que no se agregue la bolsa después de todo.

VALORES DE RETORNO

PKCS12_create() devuelve una estructura PKCS12 válida o NULL si ocurrió un error.

HISTORIA

PKCS12_create_ex() se añadió en OpenSSL 3.0. PKCS12_create_ex2() se añadió en OpenSSL 3.2.

Los valores predeterminados para los algoritmos de cifrado, el algoritmo MAC y el contador de iteraciones de derivación de clave MAC se cambiaron en OpenSSL 3.0 a estándares más modernos.
