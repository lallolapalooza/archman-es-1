PKGBUILD(5) Manual de Pacman PKGBUILD(5)

NOMBRE

PKGBUILD - Archivo de descripción de compilación de paquetes

SINOPSIS

PKGBUILD

DESCRIPCIÓN

Esta página del manual describe las reglas generales sobre los PKGBUILDs. Una vez escrito un PKGBUILD, el paquete real se compila usando makepkg y se instala con pacman.


Nota

Un PKGBUILD de ejemplo, útil como referencia, se encuentra en /usr/share/pacman junto con otros archivos de ejemplo, como un script de instalación. Puedes copiar el archivo PKGBUILD.proto proporcionado a un nuevo directorio de compilación de paquetes y realizar personalizaciones para adaptarlo a tus necesidades.

OPCIONES Y DIRECTIVAS

La siguiente es una lista de opciones y directivas estándar disponibles para su uso en un PKGBUILD. Todas estas son entendidas e interpretadas por makepkg, y la mayoría de ellas se transferirán directamente al paquete compilado. Los campos obligatorios para un PKGBUILD mínimamente funcional son pkgname, pkgver, pkgrel y arch.

Si necesitas crear variables personalizadas para usarlas en tu proceso de compilación, se recomienda prefijar su nombre con un _ (guion bajo). Esto evitará posibles conflictos de nombres con las variables internas de makepkg. Por ejemplo, para almacenar la versión base del kernel en una variable, usa algo similar a $_basekernver.

pkgname (array)

El nombre del paquete o una matriz de nombres para paquetes divididos. Los caracteres válidos para los miembros de esta matriz son alfanuméricos y cualquiera de los siguientes caracteres: “@ . _ + -”. Además, los nombres no pueden empezar con guiones o puntos.

pkgver

La versión del software tal como la publica el autor (por ejemplo, 2.7.1). La variable no puede contener dos puntos, barras inclinadas, guiones o espacios en blanco.

La variable pkgver puede actualizarse automáticamente proporcionando una función pkgver() en el PKGBUILD que devuelva la nueva versión del paquete. Esto se ejecuta después de descargar y extraer las fuentes y ejecutar la función prepare() (si está presente), por lo que puede utilizar esos archivos para determinar la nueva pkgver. Esto es más útil cuando se usa con fuentes de sistemas de control de versiones (ver más abajo).

pkgrel

Este es el número de versión específico de la distribución. Esto permite a los mantenedores de paquetes realizar actualizaciones en las banderas de configuración del paquete, por ejemplo. Normalmente se establece en 1 para cada nueva versión del software principal y se incrementa para las actualizaciones intermedias del PKGBUILD. La variable es un entero positivo, con un nivel de sub-versión opcional especificado añadiendo otro entero positivo separado por un punto (es decir, en la forma x.y).

epoch

Se utiliza para forzar que el paquete se considere más nuevo que cualquier versión anterior con una época inferior, incluso si el número de versión normalmente no provocaría dicha actualización. Este valor debe ser un entero positivo; el valor predeterminado si no se especifica es 0. Esto es útil cuando el esquema de numeración de versiones de un paquete cambia (o es alfanumérico), rompiendo la lógica normal de comparación de versiones. Consulte pacman(8) para obtener más información sobre las comparaciones de versiones.

pkgdesc

Debería ser una breve descripción del paquete y su funcionalidad. Intenta mantener la descripción en una sola línea de texto y no usar el nombre del paquete.

url

Este campo contiene una URL asociada al software que se está empaquetando. Típicamente es el sitio web del proyecto.

license (array)

Este campo especifica la(s) licencia(s) que se aplican al paquete. Si son aplicables varias licencias, enumera todas: license=('GPL' 'FDL').

install

Especifica un script de instalación especial que se incluirá en el paquete. Este archivo debe residir en el mismo directorio que el PKGBUILD y makepkg lo copiará al paquete. No necesita incluirse en el array de fuentes (por ejemplo, install=$pkgname.install).

changelog

Especifica un archivo de registro de cambios que se incluirá en el paquete. El archivo de registro de cambios debe terminar en un único salto de línea. Este archivo debe residir en el mismo directorio que el PKGBUILD y makepkg lo copiará al paquete. No necesita incluirse en el array de fuentes (por ejemplo, changelog=$pkgname.changelog).

source (array)

Una matriz de archivos fuente necesarios para compilar el paquete. Los archivos fuente deben residir en el mismo directorio que el PKGBUILD, o ser una URL completa que makepkg pueda usar para descargar el archivo. Para simplificar el mantenimiento de los PKGBUILDs, utiliza las variables $pkgname y $pkgver al especificar la ubicación de descarga, si es posible. Los archivos comprimidos se extraerán automáticamente a menos que se encuentren en la matriz noextract descrita a continuación.

Se pueden añadir fuentes adicionales específicas de la arquitectura añadiendo un guion bajo y el nombre de la arquitectura, por ejemplo, source_x86_64=(). Debe haber una matriz de integridad correspondiente con sumas de verificación, por ejemplo, cksums_x86_64=().

También es posible cambiar el nombre del archivo descargado, lo cual es útil con URLs extrañas y para manejar varios archivos fuente con el mismo nombre. La sintaxis es: source=('nombre_archivo::url').

makepkg también soporta la compilación de versiones de desarrollo de paquetes utilizando fuentes descargadas de sistemas de control de versiones (VCS). Para más información, ver Uso de Fuentes VCS abajo.

Los archivos en la matriz source con extensiones .sig, .sign o .asc son reconocidos por makepkg como firmas PGP y se utilizarán automáticamente para verificar la integridad del archivo fuente correspondiente.

validpgpkeys (array)

Una matriz de huellas digitales PGP. Si esta matriz no está vacía, makepkg solo aceptará firmas de las claves listadas aquí e ignorará los valores de confianza del llavero. Si el archivo fuente fue firmado con una subclave, makepkg seguirá utilizando la clave principal para la comparación.

Solo se aceptan huellas digitales completas. Deben estar en mayúsculas y no contener espacios en blanco.

noextract (array)

Una matriz de nombres de archivos correspondientes a los de la matriz source. Los archivos listados aquí no se extraerán con el resto de los archivos fuente. Esto es útil para paquetes que utilizan datos comprimidos directamente.

cksums (array)

Esta matriz contiene sumas de verificación CRC para cada archivo fuente especificado en la matriz source (en el mismo orden). makepkg la utilizará para verificar la integridad de los archivos fuente durante las compilaciones posteriores. Si se pone SKIP en la matriz en lugar de una suma de verificación normal, se omitirá la verificación de integridad para ese archivo fuente. Para generar fácilmente las cksums, ejecuta "makepkg -g >> PKGBUILD". Si lo deseas, mueve la línea de cksums a la ubicación apropiada. Ten en cuenta que las sumas de verificación generadas por "makepkg -g" deben verificarse utilizando los valores de suma de verificación proporcionados por el desarrollador del software.

md5sums, sha1sums, sha224sums, sha256sums, sha384sums, sha512sums, b2sums (arrays)

Sumas de verificación de integridad alternativas que makepkg soporta; todas estas se comportan de manera similar a la opción cksums descrita anteriormente. Para habilitar el uso y la generación de estas sumas de verificación, asegúrate de configurar la opción INTEGRITY_CHECK en makepkg.conf(5).

groups (array)

Una matriz de nombres simbólicos que representan grupos de paquetes, lo que te permite instalar varios paquetes solicitando un solo objetivo. Por ejemplo, se podrían instalar todos los paquetes de KDE instalando el grupo kde.

arch (array)

Define en qué arquitecturas está disponible el paquete dado (por ejemplo, arch=('i686' 'x86_64')). Los paquetes que no contienen archivos específicos de la arquitectura deben usar arch=('any'). Los caracteres válidos para los miembros de esta matriz son alfanuméricos y “_”.

backup (array)

Una matriz de nombres de archivo, sin barras previas, que deben guardarse como copia de seguridad si el paquete se elimina o se actualiza. Esto se usa comúnmente para paquetes que colocan archivos de configuración en /etc. Consulte "Gestión de archivos de configuración" en pacman(8) para obtener más información.

depends (array)

Una matriz de paque

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

agedías de las que este paquete depende para ejecutarse. Las entradas en esta lista deben ir entre comillas simples y contener al menos el nombre del paquete. Las entradas también pueden incluir un requisito de versión de la forma nombre<>versión, donde <> es una de las cinco comparaciones: >= (mayor o igual que), <= (menor o igual que), = (igual a), > (mayor que), o < (menor que).

Si el nombre de la dependencia parece ser una biblioteca (termina en .so), makepkg intentará encontrar un binario que dependa de la biblioteca en el paquete compilado y agregará la versión necesaria para el binario. Agregar la versión manualmente deshabilita la detección automática.

Se pueden agregar depends adicionales específicos de la arquitectura agregando un guion bajo y el nombre de la arquitectura, por ejemplo, depends_x86_64=().

makedepends (array)

Un array de paquetes de los que este paquete depende para compilarse, pero que no se necesitan en tiempo de ejecución. Los paquetes en esta lista siguen el mismo formato que depends.

Se pueden agregar makedepends adicionales específicos de la arquitectura agregando un guion bajo y el nombre de la arquitectura, por ejemplo, makedepends_x86_64=().

checkdepends (array)

Un array de paquetes de los que este paquete depende para ejecutar su conjunto de pruebas, pero que no se necesitan en tiempo de ejecución. Los paquetes en esta lista siguen el mismo formato que depends. Estas dependencias solo se consideran cuando la función check() está presente y va a ser ejecutada por makepkg.

Se pueden agregar checkdepends adicionales específicos de la arquitectura agregando un guion bajo y el nombre de la arquitectura, por ejemplo, checkdepends_x86_64=().

optdepends (array)

Un array de paquetes (y razones asociadas) que no son esenciales para la funcionalidad básica, pero que pueden ser necesarios para aprovechar al máximo el contenido de este paquete. optdepends son actualmente solo para fines informativos y no son utilizados por pacman durante la resolución de dependencias. Los paquetes en esta lista siguen el mismo formato que depends, con una descripción opcional agregada. El formato para especificar descripciones de optdepends es: 
optdepends=('python: para enlaces de bibliotecas')

Se pueden agregar optdepends adicionales específicos de la arquitectura agregando un guion bajo y el nombre de la arquitectura, por ejemplo, optdepends_x86_64=().

conflicts (array)

Un array de paquetes que entrarán en conflicto con este paquete (es decir, no pueden ser instalados al mismo tiempo). Esta directiva sigue el mismo formato que depends. Los conflictos con versiones son compatibles utilizando los operadores descritos en depends.

Se pueden agregar conflicts adicionales específicos de la arquitectura agregando un guion bajo y el nombre de la arquitectura, por ejemplo, conflicts_x86_64=().

provides (array)

Un array de “provisiones virtuales” que este paquete proporciona. Esto permite que un paquete proporcione dependencias distintas de su propio nombre de paquete. Por ejemplo, el paquete dcron puede proporcionar cron, lo que permite que los paquetes dependan de cron en lugar de dcron O fcron.

Las provisiones con versión también son posibles, en el formato nombre=versión. Por ejemplo, dcron puede proporcionar cron=2.0 para satisfacer la dependencia cron>=2.0 de otros paquetes. Las provisiones que involucran los operadores > y < no son válidas, ya que solo se pueden proporcionar versiones específicas de un paquete.

Si el nombre de la provisión parece ser una biblioteca (termina en .so), makepkg intentará encontrar la biblioteca en el paquete compilado y agregar la versión correcta. Agregar la versión manualmente deshabilita la detección automática.

Se pueden agregar provides adicionales específicos de la arquitectura agregando un guion bajo y el nombre de la arquitectura, por ejemplo, provides_x86_64=().

replaces (array)

Un array de paquetes que este paquete debe reemplazar. Esto se puede usar para manejar paquetes renombrados/combinados. Por ejemplo, si el paquete j2re se renombra a jre, esta directiva permite que las actualizaciones futuras continúen como se esperaba, aunque el paquete se haya movido. Los reemplazos con versión son compatibles utilizando los operadores descritos en depends.

Sysupgrade es actualmente la única operación de pacman que utiliza este campo. Una sincronización o actualización normal no utilizará su valor.

Se pueden agregar replaces adicionales específicos de la arquitectura agregando un guion bajo y el nombre de la arquitectura, por ejemplo, replaces_x86_64=().

options (array)

Este array le permite anular parte del comportamiento predeterminado de makepkg al compilar paquetes. Para establecer una opción, simplemente incluya el nombre de la opción en el array options. Para revertir el comportamiento predeterminado, coloque un “!” al principio de la opción. Especifique solo las opciones que desea anular específicamente, el resto se tomará de makepkg.conf(5). **NOTA:** force es una opción eliminada en favor de la variable superior epoch.

strip

Elimina símbolos de binarios y bibliotecas. Si usa frecuentemente un depurador en programas o bibliotecas, puede ser útil deshabilitar esta opción.

docs

Guarda directorios de documentación. Si desea eliminar los directorios de documentación, especifique !docs en el array.

libtool

Deja archivos libtool (.la) en los paquetes. Especifique !libtool para eliminarlos.

staticlibs

Deja archivos de biblioteca estática (.a) en los paquetes. Especifique !staticlibs para eliminarlos (si tienen una contraparte compartida).

emptydirs

Deja directorios vacíos en los paquetes.

zipman

Comprime las páginas de manual e info con gzip.

ccache

Permite el uso de ccache durante build(). Más útil en su forma negativa !ccache con paquetes seleccionados que tienen problemas para compilar con ccache.

distcc

Permite el uso de distcc durante build(). Más útil en su forma negativa !distcc con paquetes seleccionados que tienen problemas para compilar con distcc.

buildflags

Permite el uso de flags de compilación específicos del usuario (CPPFLAGS, CFLAGS, CXXFLAGS, LDFLAGS) durante build() según se especifica en makepkg.conf(5). Más útil en su forma negativa !buildflags con paquetes seleccionados que tienen problemas para compilar con flags de compilación personalizados.

makeflags

Permite el uso de makeflags específicos del usuario durante build() según se especifica en makepkg.conf(5). Más útil en su forma negativa !makeflags con paquetes seleccionados que tienen problemas para compilar con makeflags personalizados, como -j2 (o superior).

debug

Agrega las flags de depuración especificadas por el usuario (DEBUG_CFLAGS, DEBUG_CXXFLAGS) a sus contrapartes de flags de compilación especificadas en makepkg.conf(5). Cuando se usa en combinación con la opción ‘strip’, se crea un paquete separado que contiene los símbolos de depuración.

lto

Habilita la compilación de paquetes utilizando optimización en tiempo de enlazado. Agrega -flto a CFLAGS y CXXFLAGS.

FUNCIONES DE EMPAQUETADO

Además de las directivas anteriores, los PKGBUILDs requieren un conjunto de funciones que proporcionan instrucciones para compilar e instalar el paquete. Como mínimo, el PKGBUILD debe contener una función package() que instala todos los archivos del paquete en el directorio de empaquetado, con funciones opcionales prepare(), build() y check() que se utilizan para crear esos archivos a partir del código fuente.

Esto se carga y ejecuta directamente por makepkg, por lo que cualquier cosa que Bash o el sistema tengan disponible se puede usar aquí. Asegúrese de que cualquier comando exótico utilizado esté cubierto por el array makedepends.

Si crea alguna variable propia en alguna de estas funciones, se recomienda utilizar la palabra clave local de Bash para delimitar la variable dentro de la función.

Función package()

La función package() se utiliza para instalar archivos en el directorio que se convertirá en el directorio raíz del paquete compilado y se ejecuta después de todas las funciones opcionales que se enumeran a continuación. La etapa de empaquetado se ejecuta utilizando fakeroot para garantizar los permisos de archivo correctos en el paquete resultante. Todas las demás funciones se ejecutarán como el usuario que llama a makepkg. Esta función se ejecuta dentro de $srcdir.

Función verify()

Se puede especificar una función verify() opcional para implementar la autenticación arbitraria de fuentes. La función debe devolver un código de salida distinto de cero cuando la verificación falla. Esta función se ejecuta antes de que se extraigan las fuentes. Esta función se ejecuta dentro de $startdir.

Función prepare()

Se puede especificar una función prepare() opcional en la que se realizan operaciones para preparar las fuentes para la compilación, como la aplicación de parches. Esta función se ejecuta después de la extracción de las fuentes y antes de la función build(). La función prepare() se omite cuando se omite la extracción de las fuentes. Esta función se ejecuta dentro de $srcdir.

Función build()

La función build() opcional se utiliza para compilar y/o ajustar los archivos fuente en preparación para ser instalados por la función package(). Esta función se ejecuta dentro de $srcdir.

Función check()

Se puede especificar una función check() opcional en la que se puede ejecutar el conjunto de pruebas de un paquete. Esta función se ejecuta entre las funciones build() y package(). Asegúrese de que cualquier comando exótico utilizado esté cubierto por el array checkdepends. Esta función se ejecuta dentro de $srcdir.

Todas las variables anteriores, como $pkgname y $pkgver, están disponibles para su uso en las funciones de empaquetado. Además, makepkg define las siguientes variables:

srcdir

Contiene el directorio donde makepkg extrae o copia todos los archivos fuente.

pkgdir

Contiene el directorio donde makepkg agrupa el paquete instalado. Este directorio se convertirá en el directorio raíz de su paquete compilado. Esta variable solo debe usarse en la función package().

startdir

Contiene la ruta absoluta al directorio donde se encuentra el PKGBUILD, que generalmente es la salida de $(pwd) cuando se inicia makepkg. El uso de esta variable está obsoleto y se desaconseja enérgicamente.

DIVISIÓN DE PAQUETES

makepkg admite la compilación de varios paquetes a partir de un solo PKGBUILD. Esto se logra asignando un array de nombres de paquetes a la directiva pkgname. Cada paquete dividido utiliza una función de empaquetado correspondiente con el nombre package_foo(), donde foo es el nombre del paquete dividido.

NAME

PKGBUILD - package build script

SYNOPSIS

A PKGBUILD is a shell script that defines how a package is built. It is used by makepkg(8) to build a package for the Arch Linux distribution.

DESCRIPTION

The PKGBUILD is sourced by makepkg(8), which executes the defined functions in order to build a package. The script is written in POSIX shell syntax.

A typical PKGBUILD file contains several variables defining the package metadata, and functions defining the build process.

OPTIONS AND DIRECTIVES

The following variables are used to define package metadata and build options.

pkgbase

The name used to refer to the group of packages in the output of makepkg and in the naming of source-only tarballs. If not specified, the first element in the pkgname array is used. Valid characters for this variable are alphanumerics, and any of the following characters: “@ . _ + -”. Additionally, the variable is not allowed to start with hyphens or dots.

pkgname

An array of strings defining the name of the package. If there is only one package, this array may contain a single element. If multiple packages are built from the same PKGBUILD, this array must contain the names of all split packages.

pkgver

The version of the package.

pkgrel

The release number of the package. This should be incremented for fixes to the PKGBUILD itself, or when rebuilding the package with the same source files.

pkgdesc

A short description of the package.

arch

An array of strings defining the architectures the package is built for. Use 'any' if the package is architecture-independent.

url

The URL to the project's homepage.

license

An array of strings defining the licenses the package adheres to. Standard license identifiers should be used.

groups

An array of strings defining the groups the package belongs to.

depends

An array of strings defining the runtime dependencies of the package.

makedepends

An array of strings defining the build-time dependencies of the package.

optdepends

An array of strings defining optional runtime dependencies. Each element can be a package name or a string explaining the optional functionality.

provides

An array of strings defining virtual packages or features provided by this package.

conflicts

An array of strings defining packages that conflict with this package.

replaces

An array of strings defining packages that this package replaces.

backup

An array of strings defining files and directories that should be preserved during package upgrades. These are files that might be modified by the user and shouldn't be overwritten.

options

An array of strings to enable or disable specific build options. Prepend with a hyphen to disable. Available options include: debug, strip, zipman, ccache, purge, emptydirs, buildmodes, foreignlibprog, makeflags, distcc, loadavg.

install

Specifies the name of an install script to be executed by pacman during package installation, upgrade, and removal.

changelog

Specifies the name of a changelog file to be included in the package.

source

An array of strings defining the source files for the package. This can include URLs, local files, or VCS repository URLs.

sha256sums

An array of strings containing the SHA256 checksums for the files listed in the source array. Use 'SKIP' to skip checksum validation for a specific source file (e.g., for PGP-signed sources).

md5sums

An array of strings containing the MD5 checksums for the files listed in the source array. This is deprecated and sha256sums should be preferred.

PACKAGING FUNCTIONS

The PKGBUILD script is composed of several functions that are executed in a specific order by makepkg.

prepare()

This function is used for any necessary patching or configuration before the build process begins. It is executed after the source files have been downloaded and extracted.

build()

This function contains the commands to compile and build the package.

check()

This function contains the commands to run the package's test suite. It is only executed if the makepkg(8) command is run with the --skipcheck option omitted.

package()

This function is used to install the built files into the package directory structure. The destination directory is specified by the $pkgdir variable.

PACKAGE SPLITTING

All options and directives for the split packages default to the global values given in the PKGBUILD. Nevertheless, the following ones can be overridden within each split package’s packaging function: pkgdesc, arch, url, license, groups, depends, optdepends, provides, conflicts, replaces, backup, options, install, and changelog.

Note that makepkg does not consider split package depends when checking if dependencies are installed before package building and with --syncdeps. All packages required to make the package are required to be specified in the global depends and makedepends arrays.

An optional global directive is available when building a split package:

pkgbase

The name used to refer to the group of packages in the output of makepkg and in the naming of source-only tarballs. If not specified, the first element in the pkgname array is used. Valid characters for this variable are alphanumerics, and any of the following characters: “@ . _ + -”. Additionally, the variable is not allowed to start with hyphens or dots.

INSTALL/UPGRADE/REMOVE SCRIPTING

Pacman has the ability to store and execute a package-specific script when it installs, removes, or upgrades a package. This allows a package to configure itself after installation and perform an opposite action upon removal.

The exact time the script is run varies with each operation, and should be self-explanatory. Note that during an upgrade operation, none of the install or remove functions will be called.

Scripts are passed either one or two “full version strings”, where a full version string is either pkgver-pkgrel or epoch:pkgver-pkgrel, if epoch is non-zero.

pre_install

Run right before files are extracted. One argument is passed: new package full version string.

post_install

Run right after files are extracted. One argument is passed: new package full version string.

pre_upgrade

Run right before files are extracted. Two arguments are passed in this order: new package full version string, old package full version string.

post_upgrade

Run after files are extracted. Two arguments are passed in this order: new package full version string, old package full version string.

pre_remove

Run right before files are removed. One argument is passed: old package full version string.

post_remove

Run right after files are removed. One argument is passed: old package full version string.

To use this feature, create a file such as pkgname.install and put it in the same directory as the PKGBUILD script. Then use the install directive:

install=pkgname.install

The install script does not need to be specified in the source array. A template install file is available in /usr/share/pacman as proto.install for reference with all of the available functions defined.

USING VCS SOURCES

Building a developmental version of a package using sources from a version control system (VCS) is enabled by specifying the source in the form:

source=('directory::url#fragment?query')

Currently makepkg supports the Bazaar, Git, Subversion, Fossil and Mercurial version control systems. For other version control systems, manual cloning of upstream repositories must be done in the prepare() function.

Some VCS Sources like Git support pinning the checkout by a checksum of its content using deterministic export functionality like “git archive”.

The source URL is divided into four components:

directory

(optional) Specifies an alternate directory name for makepkg to download the VCS source into.

url

The URL to the VCS repository. This must include the VCS in the URL protocol for makepkg to recognize this as a VCS source. If the protocol does not include the VCS name, it can be added by prefixing the URL with vcs+. For example, using a Git repository over HTTPS would have a source URL in the form: git+https://....

fragment

(optional) Allows specifying a revision number or branch for makepkg to checkout from the VCS. A fragment has the form type=value, for example to checkout a given revision the source line would be source=(url#revision=123). The available types depends on the VCS being used:

bzr

revision (see 'bzr help revisionspec' for details)

fossil

branch, commit, tag

git

branch, commit, tag

hg

branch, revision, tag

svn

revision

query

(optional) Allows specifying whether a VCS checkout should be checked for PGP-signed revisions. The source line should have the format source=(url#fragment?signed) or source=(url?signed#fragment). Currently only supported by Git.

EXAMPLE

The following is an example PKGBUILD for the patch package. For more examples, look through the build files of your distribution’s packages.

# Maintainer: Joe User <joe.user@example.com>
pkgname=patch
pkgver=2.7.1
pkgrel=1
pkgdesc="A utility to apply patch files to original sources"
arch=('i686' 'x86_64')
url="https://www.gnu.org/software/patch/patch.html"
license=('GPL')
