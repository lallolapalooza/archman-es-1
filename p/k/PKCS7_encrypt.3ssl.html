PKCS7_encrypt(3ssl)

Paquete: openssl

Licencias: Apache-2.0

PKCS7_ENCRYPT(3ssl) OpenSSL PKCS7_ENCRYPT(3ssl)

NOMBRE

PKCS7_encrypt_ex, PKCS7_encrypt - crear una estructura PKCS#7 envelopedData

SINOPSIS

#include <openssl/pkcs7.h>
PKCS7 *PKCS7_encrypt_ex(STACK_OF(X509) *certs, BIO *in,
                        const EVP_CIPHER *cipher, int flags,
                        OSSL_LIB_CTX *libctx, const char *propq);
PKCS7 *PKCS7_encrypt(STACK_OF(X509) *certs, BIO *in, const EVP_CIPHER *cipher,
                     int flags);

DESCRIPCIÓN

PKCS7_encrypt_ex() crea y devuelve una estructura PKCS#7 envelopedData. certs es una lista de certificados de destinatario. in es el contenido a cifrar. cipher es el cifrado simétrico a utilizar. flags es un conjunto opcional de indicadores. El contexto de la biblioteca libctx y la consulta de propiedades propq se utilizan al recuperar algoritmos de los proveedores.

Solo se admiten claves RSA en PKCS#7 y envelopedData, por lo que los certificados de destinatario proporcionados a esta función deben contener todas claves públicas RSA, aunque no tengan que estar firmadas utilizando el algoritmo RSA.

EVP_des_ede3_cbc() (triple DES) es el algoritmo elegido para uso S/MIME porque la mayoría de los clientes lo admitirán.

Algunos clientes antiguos de "grado de exportación" solo admiten cifrado débil utilizando RC2 de 40 o 64 bits. Estos se pueden usar pasando EVP_rc2_40_cbc() y EVP_rc2_64_cbc() respectivamente.

El algoritmo pasado en el parámetro cipher debe admitir la codificación ASN1 de sus parámetros.

Muchos navegadores implementan una opción de "firmar y cifrar", que es simplemente un envelopedData S/MIME que contiene un mensaje firmado S/MIME. Esto se puede producir fácilmente almacenando el mensaje firmado S/MIME en un BIO de memoria y pasándolo a PKCS7_encrypt().

Los siguientes indicadores se pueden pasar en el parámetro flags.

Si se establece el indicador PKCS7_TEXT, se anteponen cabeceras MIME para el tipo text/plain a los datos.

Normalmente, el contenido proporcionado se traduce al formato canónico MIME (como lo requieren las especificaciones S/MIME). Si se establece PKCS7_BINARY, no se realiza ninguna traducción. Esta opción debe utilizarse si los datos proporcionados están en formato binario, de lo contrario, la traducción los corromperá. Si se establece PKCS7_BINARY, se ignora PKCS7_TEXT.

Si se establece el indicador PKCS7_STREAM, se genera una estructura PKCS7 parcial adecuada para E/S en streaming: no se leen datos del BIO in.

Si se establece el indicador PKCS7_STREAM, la estructura PKCS7 devuelta no está completa y la salida de sus contenidos a través de una función que no finaliza correctamente la estructura PKCS7 dará resultados impredecibles.

Varias funciones, incluidas SMIME_write_PKCS7(), i2d_PKCS7_bio_stream(), PEM_write_bio_PKCS7_stream(), finalizan la estructura. Alternativamente, la finalización se puede realizar obteniendo directamente el BIO ASN1 de streaming utilizando BIO_new_PKCS7().

PKCS7_encrypt() es similar a PKCS7_encrypt_ex() pero utiliza valores predeterminados de NULL para el contexto de la biblioteca libctx y la consulta de propiedades propq.

VALORES DE RETORNO

PKCS7_encrypt_ex() y PKCS7_encrypt() devuelven una estructura PKCS7 o NULL si ocurrió un error. El error se puede obtener de ERR_get_error(3).

VER TAMBIÉN

ERR_get_error(3), PKCS7_decrypt(3)

HISTORIA

La función PKCS7_encrypt_ex() se añadió en OpenSSL 3.0.

El indicador PKCS7_STREAM se añadió en OpenSSL 1.0.0.
