NAME

PKGINFO - Información sobre paquetes basados en ALPM (versión 2).

DESCRIPCIÓN

El formato PKGINFO es un formato textual que describe metadatos de paquetes. Dichos archivos están ubicados en la raíz de los paquetes ALPM y se nombran .PKGINFO. Se utilizan, por ejemplo, por los gestores de paquetes para evaluar y presentar el contexto de un paquete dentro de su entorno. Casos de uso incluyen la representación de metadatos comunes y la relación con otros paquetes.

El formato PKGINFO existe en múltiples versiones. La información en este documento es para la versión 2, que es la actual y ha sido introducida con la versión 6.1.0 de pacman el 4 de marzo de 2024.

Formato general

Un archivo PKGINFO consta de una serie de líneas, cada una proporcionando información sobre un aspecto de un paquete. Las líneas que empiezan con un carácter # son comentarios y siempre se ignoran. El espacio en blanco inicial siempre se ignora.

A menos que se indique de otro modo, la información contenida en un archivo PKGINFO se considera cubierta por el conjunto de los 95 caracteres ASCII imprimibles [1].

Cambios desde la última versión

El nuevo palabra clave xdata ha sido añadido para registrar datos adicionales de un paquete.

Palabras clave

Cada línea codifica información que representa una asignación de palabra clave. Todos los asignados de palabra clave están formados por una clave de la siguiente lista, seguida de un espacio en blanco, un signo =, otro espacio en blanco y un valor.

Por defecto, hay que tener exactamente una asignación de palabra clave por palabra clave en un archivo PKGINFO. Como excepción a esta regla, las palabras clave license, replaces, group, conflict, provides, backup, depend, optdepend, makedepend y checkdepend pueden proporcionarse cero o más veces. Como excepción adicional, la palabra clave xdata puede proporcionarse una o más veces.

pkgname

El nombre del paquete. El valor es un alpm-package-name (por ejemplo, example).

pkgbase

El alpm-package-base del paquete. El valor es un alpm-package-base (por ejemplo, example).

xdata

Los datos adicionales asociados al paquete. Esta palabra clave debe ser asignada una vez para definir un valor específico, pero puede ser proporcionada varias veces después para proporcionar más datos adicionales. El valor es una cadena UTF-8 que representa otro par clave-valor, delimitado por un signo = (por ejemplo, key=value).

Un archivo PKGINFO debe contener una asignación de palabra clave xdata que defina una asignación pkgtype en su valor (por ejemplo, pkgtype=pkg). Los valores válidos de pkgtype son debug (para paquetes de depuración), pkg (para paquetes individuales), src (para paquetes de fuente) y split (para paquetes divididos).

Asignaciones adicionales de palabra clave xdata pueden proporcionarse según las reglas de formato general.

pkgver

La versión completa del paquete. Debe tener en cuenta que esto no se debe confundir con alpm-pkgver, que solo representa una subconjunto de este palabra clave! El valor es un alpm-package-version, que puede estar en forma completa o en forma completa con epoch (por ejemplo, 1.0.0-1 o 1:1.0.0-1, respectivamente).

pkgdesc

La descripción del paquete. El valor es una cadena UTF-8, de longitud cero o más (por ejemplo, A project used for something). Las descripciones de paquetes deben tener ningún espacio en blanco al inicio ni al final, no pueden contener espacios en blanco excepto el espacio único (« ») y no pueden tener espacios consecutivos. Se sugiere que sea «brevemente» y que no contenga el nombre del paquete (ver pkgname).

url

La URL del proyecto del paquete. El valor es una URL válida o una cadena vacía (por ejemplo, https://example.org).

builddate

La fecha en la que comenzó la construcción del paquete. El valor debe ser numérico y debe representar los segundos desde el Epoch, es decir, «fecha del tiempo Unix» (por ejemplo, 1729181726).

packager

El UID del ente que construyó el paquete. El valor es el UID que se usa para busquedas de identidad y representa un OpenPGP User ID[2]. Así, el valor es una cadena UTF-8, que se compone usualmente de un nombre y un correo electrónico, alineado con el formato descrito en RFC 28223.

size

El tamaño de los (sin comprimir y desempacados) contenidos del paquete en bytes. El valor es un entero no negativo que representa el tamaño absoluto de los contenidos del paquete, con múltiples archivos firmes contados solo una vez (por ejemplo, 181849963).

arch

La arquitectura del paquete (ver alpm-architecture para información adicional). El valor debe ser cubierto por el conjunto de caracteres alfanuméricos y _ (por ejemplo, x86_64 o any).

license

Una licencia que aplica al paquete. Esta palabra clave puede ser asignada cero o más veces. El valor representa una identidad de licencia, que es una cadena de longitud no cero (por ejemplo, GPL). Aunque no hay restricciones específicas para el valor, se recomienda usar expresiones de licencia SPDX (por ejemplo, GPL-3.0-or-later o Apache-2.0 OR MIT). Consulte la lista de licencias SPDX [4] para más información.

replaces

Otro componente virtual o paquete que el paquete reemplaza al instalarlo. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo replacement (por ejemplo, example o example=1.0.0).

group

Un string arbitrario que representa un grupo distribuido a escala de paquetes que el paquete está en. Los grupos se utilizan, por ejemplo, por gestores de paquetes para agrupar paquetes y permitir instalarlos en masa, o por otros software para mostrar información sobre estos paquetes relacionados. Esta palabra clave puede ser asignada cero o más veces. El valor se representa por una cadena UTF-8. Aunque se puede usar una cadena UTF-8, se recomienda usar el formato pkgname para el valor, ya que los gestores de paquetes pueden usar group para instalar un grupo completo de paquetes.

conflict

Otro componente virtual o paquete que el paquete conflita con. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo conflict (por ejemplo, example o example=1.0.0).

provides

Otro componente virtual o paquete que el paquete proporciona. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo provision (por ejemplo, example o example=1.0.0).

backup

Otro componente virtual o paquete que el paquete backup. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo backup (por ejemplo, example o example=1.0.0).

depend

Otro componente virtual o paquete que el paquete depende. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo dependency (por ejemplo, example o example=1.0.0).

optdepend

Otro componente virtual o paquete que el paquete depende opcionalmente. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo optional dependency (por ejemplo, example o example=1.0.0).

makedepend

Otro componente virtual o paquete que el paquete necesita para ser construido. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo build dependency (por ejemplo, example o example=1.0.0).

checkdepend

Otro componente virtual o paquete que el paquete necesita para ser verificado. Esta palabra clave puede ser asignada cero o más veces. El valor es un alpm-package-relation de tipo check dependency (por ejemplo, example o example=1.0.0).

alpm-package-relation

Se espera que el valor de las palabras clave de relación (por ejemplo, depend, conflict, etc.) sea un alpm-package-relation. El formato para las relaciones de paquetes es un nombre de paquete precedido opcionalmente por un operador de relación, como <, <=, =, !=, >=, o >. Si no se especifica un operador, se asume que es =.

Por ejemplo, example es equivalente a =example. example=1.0.0 es equivalente a =example=1.0.0.

alpm-package-name

El nombre de un paquete o componente virtual. Debe ser una cadena de longitud no cero, que solo puede contener caracteres alfanuméricos y los caracteres especiales _, +, -, y ..

alpm-package-version

El formato de una versión de paquete. Debe ser una cadena de longitud no cero, que solo puede contener caracteres alfanuméricos y los caracteres especiales _, +, -, y .. También puede estar precedido opcionalmente por un entero seguido de un signo de dos puntos (epoch:).

NAME

PKGINFOv2 - PKGINFO file format version 2

DESCRIPTION

This document describes the format of the PKGINFO file, which stores metadata about an Arch Linux package. This format is a successor to PKGINFOv1(5), adding support for new keywords.

Keywords are case-insensitive and are specified in the format keyword = value or keyword: value. Keywords may be repeated unless otherwise specified. The value is typically a string, but may also be a comma-separated list or a file path, depending on the keyword.

pkgname

The name of the package. This keyword MUST be specified exactly once.

pkgbase

The base name of the package. This is used for metapackages and split packages. This keyword MAY be assigned zero or one times.

pkgtype

The type of package. This keyword MAY be assigned zero or one times. The value MUST be one of the following:

pkg
A standard package.
pkg-group
A package group.

pkgver

The version of the package. This keyword MUST be specified exactly once. The value is an alpm-package-version(7) string (e.g. 1.0.0-1).

pkgdesc

A short description of the package. This keyword MAY be assigned zero or one times. The value is a string.

url

The URL of the project homepage. This keyword MAY be assigned zero or one times. The value is a valid URL.

builddate

The date the package was built, represented as the number of seconds since the Unix epoch. This keyword MAY be assigned zero or one times. The value is an integer.

packager

The name and email address of the packager. This keyword MAY be assigned zero or one times. The value is a string formatted as Name <email@example.org>.

size

The uncompressed size of the package in bytes. This keyword MAY be assigned zero or one times. The value is an integer.

arch

The architecture the package is built for. This keyword MUST be specified exactly once. The value is an alpm-architecture(7) string (e.g. x86_64, any).

license

The license(s) under which the package is distributed. This keyword may be assigned zero or more times. The value is an SPDX License Expression (e.g. GPL-3.0-or-later).

replaces

A package or virtual component that this package replaces. This keyword may be assigned zero or more times. The value is an alpm-package-relation of type replaces (e.g. other-package>0.9.0-3).

group

A package group that this package belongs to. This keyword may be assigned zero or more times. The value is a string (e.g. kde-applications).

conflict

A package or virtual component that conflicts with this package. This keyword may be assigned zero or more times. The value is an alpm-package-relation of type conflict (e.g. conflicting-package<1.0.0).

provides

A virtual component or package that this package provides. This keyword may be assigned zero or more times. The value is an alpm-package-relation of type provides (e.g. some-component or some-component=1:1.0.0-1).

backup

A relative file path of a file in the package, that denotes a file for the package manager to keep backups for in case it changes or is deleted during a package update action (see pacman ‘.pacnew’ and ‘.pacsave’ files). This keyword may be assigned zero or more times. The value must be a valid relative Unix file path (e.g. etc/package.conf).

depend

A run-time dependency of the package (virtual component or package). This keyword may be assigned zero or more times. The value is an alpm-package-relation of type run-time dependency (e.g. example or example=1.0.0).

optdepend

An optional dependency of the package (virtual component or package). This keyword may be assigned zero or more times. The value is an alpm-package-relation of type optional dependency (e.g. example or example: this is a description).

makedepend

A build time dependency of the package (virtual component or package). This keyword may be assigned zero or more times. The value is an alpm-package-relation of type build dependency (e.g. example or example=1.0.0).

checkdepend

A dependency for running tests of the package’s upstream project. This keyword may be assigned zero or more times. The value is an alpm-package-relation of type test dependency (e.g. example or example=1.0.0).

EXAMPLES

pkgname = example
pkgbase = example
xdata = pkgtype=pkg
pkgver = 1:1.0.0-1
pkgdesc = A project that does something
url = https://example.org
builddate = 1729181726
packager = John Doe <john@example.org>
size = 181849963
arch = any
license = GPL-3.0-or-later
license = LGPL-3.0-or-later
replaces = other-package>0.9.0-3
group = package-group
group = other-package-group
conflict = conflicting-package<1.0.0
conflict = other-conflicting-package<1.0.0
provides = some-component
provides = some-other-component=1:1.0.0-1
backup = etc/example/config.toml
backup = etc/example/other-config.txt
depend = glibc
depend = gcc-libs
optdepend = python: for special-python-script.py
optdepend = ruby: for special-ruby-script.rb
makedepend = cmake
makedepend = python-sphinx
checkdepend = extra-test-tool
checkdepend = other-extra-test-tool
