DESCRIPCIÓN

Derivación de claves

PKCS5_PBE_keyivgen() y PKCS5_PBE_keyivgen_ex() toman una contraseña pass de longitud passlen, parámetros param y una función de resumen de mensajes md_type y realizan una derivación de clave según PKCS#5 PBES1. La clave resultante se utiliza luego para inicializar el contexto de cifrado ctx con un cifrador cipher para cifrado (en_de=1) o descifrado (en_de=0).

pass es un parámetro opcional y puede ser NULL. Si passlen es -1, la función calculará la longitud de pass usando strlen().

PKCS5_v2_PBE_keyivgen() y PKCS5_v2_PBE_keyivgen_ex() son similares a las anteriores pero utilizan en su lugar PKCS#5 PBES2 como algoritmo de cifrado utilizando los parámetros suministrados.

PKCS5_v2_scrypt_keyivgen() y PKCS5_v2_scrypt_keyivgen_ex() utilizan SCRYPT como parte de la derivación de clave del algoritmo de cifrado.

salt es la sal utilizada en la derivación de longitud saltlen. Si salt es NULL, entonces saltlen debe ser 0. La función no intentará calcular la longitud de la salt ya que no se supone que termine en NULL.

iter es el contador de iteraciones y su valor debe ser mayor o igual a 1. RFC 2898 sugiere un contador de iteraciones de al menos 1000. Cualquier iter menor que 1 se trata como una única iteración.

digest es la función de resumen de mensajes utilizada en la derivación.

Las funciones que terminan en _ex() toman los parámetros opcionales libctx y propq que se utilizan para seleccionar las implementaciones de algoritmo adecuadas.

Creación de identificadores de algoritmo

PKCS5_pbe_set(), PKCS5_pbe_set_ex(), PKCS5_pbe2_set(), PKCS5_pbe2_set_iv(), PKCS5_pbe2_set_iv_ex() y PKCS5_pbe2_set_scrypt() generan un objeto X509_ALGOR que representa un AlgorithmIdentifier que contiene el OID del algoritmo y los parámetros asociados para el algoritmo PBE.

PKCS5_pbkdf2_set() y PKCS5_pbkdf2_set_ex() generan un objeto X509_ALGOR que representa un AlgorithmIdentifier que contiene el OID del algoritmo y los parámetros asociados para el algoritmo PBKDF2.

PKCS5_pbe_set0_algor() y PKCS5_pbe_set0_algor_ex() establecen el OID del algoritmo PBE y los parámetros en el X509_ALGOR suministrado.

Si salt es NULL, entonces saltlen especifica el tamaño en bytes de la sal aleatoria a generar. Si saltlen es 0, se utiliza un tamaño predeterminado. Para funciones relacionadas con PBE como PKCS5_pbe_set_ex(), la longitud de sal predeterminada es de 8 bytes. Para funciones relacionadas con PBE2 que utilizan PBKDF2 como PKCS5_pbkdf2_set(), PKCS5_pbe2_set_scrypt() y PKCS5_pbe2_set(), la longitud de sal predeterminada es de 16 bytes.

NOTAS

Las funciones *_keyivgen() se utilizan típicamente en PKCS#12 para cifrar objetos.

Estas funciones no hacen suposiciones sobre la contraseña dada. Simplemente se tratará como una secuencia de bytes.

VALORES DE RETORNO

PKCS5_PBE_keyivgen(), PKCS5_v2_PBE_keyivgen(), PKCS5_v2_PBE_keyivgen_ex(), PKCS5_v2_scrypt_keyivgen(), PKCS5_v2_scrypt_keyivgen_ex(), PKCS5_pbe_set0_algor() y PKCS5_pbe_set0_algor_ex() devuelven 1 en caso de éxito y 0 si ocurre un error.

PKCS5_pbe_set(), PKCS5_pbe_set_ex(), PKCS5_pbe2_set(), PKCS5_pbe2_set_iv(), PKCS5_pbe2_set_iv_ex(), PKCS5_pbe2_set_scrypt(), PKCS5_pbkdf2_set() y PKCS5_pbkdf2_set_ex() devuelven un objeto X509_ALGOR o NULL si ocurre un error.

DESCRIPTION

These functions implement various password-based encryption (PBE) schemes as defined in PKCS#5. They are primarily used for generating a symmetric encryption key and initialization vector (IV) from a password and other parameters.

The older PBE schemes use PBKDF1, which is a simple key derivation function. The newer schemes use PBKDF2 or Scrypt as defined in PKCS#5 v2.0.

The functions can be classified as follows:

  • PKCS5_PBE_keyivgen*, PKCS5_v2_scrypt_keyivgen*, PKCS5_pbe_set*, PKCS5_pbe2_set*, PKCS5_pbkdf2_set*: These are the primary key and IV generation functions. They take the password, salt, iteration count, and desired key/IV length as input and generate the key and IV. The *_ex variants allow specifying an OSSL_PROVIDER.

  • PKCS5_pbe_set0_algor*: These functions set the algorithm identifier within a PKCS5_PBES2_INFO structure. The *_ex variant allows specifying an OSSL_PROVIDER.

The different types of PBE are determined by the type parameter, which should be one of the following constants:

PKCS5_legacy
Uses the legacy PKCS#5 v1.5 PBE schemes (e.g., PBEWithMD5AndDES-CBC).
PKCS5_PBES2
Uses the PKCS#5 v2.0 PBES2 scheme.

The salt is a random value used to prevent identical passwords from producing identical keys. The iteration count (iter) controls how many times the hash function is applied, increasing the security against brute-force attacks.

PKCS5_PBE_v2_keyivgen* and PKCS5_pbkdf2_set* use a PKCS5_PBKDF2_INFO structure. This structure contains parameters for the PBKDF2 algorithm, including the hash function, salt, iteration count, and key length.

PKCS5_v2_scrypt_keyivgen* uses the Scrypt key derivation function, which is designed to be resistant to GPU-based attacks.

NOTES

The PKCS5_PBE_keyivgen, PKCS5_PBE_keyivgen_ex, PKCS5_PBE_v2_keyivgen, PKCS5_PBE_v2_keyivgen_ex, PKCS5_pbe_set0_algor, PKCS5_pbe_set0_algor_ex, PKCS5_pbe_set, PKCS5_pbe_set_ex, PKCS5_pbe2_set, PKCS5_pbe2_set_ex, PKCS5_pbkdf2_set and PKCS5_pbkdf2_set_ex functions were added in OpenSSL 3.0.

From OpenSSL 3.0 the PBKDF1 algorithm used in PKCS5_PBE_keyivgen and PKCS5_PBE_keyivgen_ex has been moved to the legacy provider as an EVP_KDF.

In OpenSSL 3.2 the default salt length changed from 8 bytes to 16 bytes for PBE2 related functions such as PKCS5_pbe2_set. This is required for PBKDF2 FIPS compliance.
