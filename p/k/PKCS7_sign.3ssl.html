PKCS7_sign(3ssl)

Paquete: openssl

Licencias: Apache-2.0

PKCS7_SIGN(3ssl) OpenSSL PKCS7_SIGN(3ssl)

NOMBRE

PKCS7_sign_ex, PKCS7_sign - crear una estructura PKCS#7 signedData

SINOPSIS

#include <openssl/pkcs7.h>
PKCS7 *PKCS7_sign_ex(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs,
                     BIO *data, int flags, OSSL_LIB_CTX *libctx,
                     const char *propq);
PKCS7 *PKCS7_sign(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs,
                  BIO *data, int flags);

DESCRIPCIÓN

PKCS7_sign_ex() crea y devuelve una estructura PKCS#7 signedData. signcert es el certificado con el que firmar, pkey es la clave privada correspondiente. certs es un conjunto opcional de certificados adicionales para incluir en la estructura PKCS#7 (por ejemplo, cualquier CA intermedia en la cadena). El contexto de biblioteca libctx y la consulta de propiedades propq se utilizan al recuperar algoritmos de los proveedores.

Los datos que se van a firmar se leen del BIO data.

flags es un conjunto opcional de indicadores.

Cualquiera de los siguientes indicadores (combinados con OR) se puede pasar en el parámetro flags.

Muchos clientes S/MIME esperan que el contenido firmado incluya encabezados MIME válidos. Si se establece el indicador PKCS7_TEXT, se anteponen encabezados MIME de tipo "text/plain" a los datos.

Si se establece PKCS7_NOCERTS, el certificado del firmante y los certificados adicionales certs no se incluirán en la estructura PKCS7. Sin embargo, el certificado del firmante aún debe proporcionarse en el parámetro signcert. Esto puede reducir el tamaño de las firmas si los certificados del firmante se pueden obtener por otros medios: por ejemplo, un mensaje firmado previamente.

Los datos que se firman se incluyen en la estructura PKCS7, a menos que se establezca PKCS7_DETACHED, en cuyo caso se omite. Esto se utiliza para firmas PKCS7 separadas que se usan en mensajes de texto sin formato firmados S/MIME, por ejemplo.

Normalmente, el contenido proporcionado se traduce al formato canónico MIME (según lo exigen las especificaciones S/MIME). Si se establece PKCS7_BINARY, no se realiza ninguna traducción. Esta opción debe usarse si los datos proporcionados están en formato binario, de lo contrario, la traducción los corromperá.

La estructura signedData incluye varios PKCS#7 authenticatedAttributes, que incluyen la hora de la firma, el tipo de contenido PKCS#7 y la lista admitida de cifradores en un atributo SMIMECapabilities. Si se establece PKCS7_NOATTR, no se utilizarán authenticatedAttributes. Si se establece PKCS7_NOSMIMECAP, solo se omitirán los SMIMECapabilities.

Si está presente, el atributo SMIMECapabilities indica soporte para los siguientes algoritmos: triple DES, RC2 de 128 bits, RC2 de 64 bits, DES y RC2 de 40 bits. Si alguno de estos algoritmos está deshabilitado, no se incluirá.

Si se establece el indicador PKCS7_STREAM, la estructura PKCS7 devuelta solo se inicializa lista para realizar la operación de firma. Sin embargo, la firma no se realiza y los datos que se van a firmar no se leen del parámetro data. La firma se aplaza hasta después de que se hayan escrito los datos. De esta manera, los datos se pueden firmar en una sola pasada.

Si se establece el indicador PKCS7_PARTIAL, se genera una estructura PKCS7 parcial a la que se pueden agregar firmantes y capacidades adicionales antes de la finalización.

Si se establece el indicador PKCS7_STREAM, la estructura PKCS7 devuelta no está completa y la salida de sus contenidos a través de una función que no finaliza correctamente la estructura PKCS7 dará como resultado resultados impredecibles.

Varias funciones, incluidas SMIME_write_PKCS7(), i2d_PKCS7_bio_stream() y PEM_write_bio_PKCS7_stream(), finalizan la estructura. Alternativamente, la finalización se puede realizar obteniendo directamente el BIO ASN1 de transmisión utilizando BIO_new_PKCS7().

Si se especifica un firmante, utilizará el digest predeterminado para el algoritmo de firma. Este es SHA256 tanto para claves RSA como DSA.

Los parámetros certs, signcert y pkey pueden ser NULL si se establece el indicador PKCS7_PARTIAL. Se pueden agregar uno o más firmantes utilizando la función PKCS7_sign_add_signer(). También se debe llamar a PKCS7_final() para finalizar la estructura si no está habilitada la transmisión. Los digests de firma alternativos también se pueden especificar utilizando este método.

Si signcert y pkey son NULL, se genera una estructura PKCS#7 solo de certificados.

En versiones de OpenSSL anteriores a la 1.0.0, los parámetros signcert y pkey no deben ser NULL.

PKCS7_sign() es similar a PKCS7_sign_ex() excepto que utiliza valores predeterminados de NULL para el contexto de biblioteca libctx y la consulta de propiedades propq. Esto se conserva por compatibilidad con versiones anteriores de la API.

ERRORES

Algunos atributos avanzados, como las contra-firmas, no son compatibles.

VALORES DE RETORNO

PKCS7_sign_ex() y PKCS7_sign() devuelven una estructura PKCS7 válida o NULL si ocurrió un error. El error se puede obtener de ERR_get_error(3).

VER TAMBIÉN

ERR_get_error(3), PKCS7_verify(3)

HISTORIAL

La función PKCS7_sign_ex() se añadió en OpenSSL 3.0.

El indicador PKCS7_PARTIAL, y la capacidad de que los parámetros certs, signcert y pkey sean NULL se añadieron en OpenSSL 1.0.0.

El indicador PKCS7_STREAM se añadió en OpenSSL 1.0.0.
