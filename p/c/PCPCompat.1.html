NOMBRE

PCPCompat, pcp-collectl, pmmgr, pmwebd - compatibilidad retroactiva en el Performance Co-Pilot (PCP)

INTRODUCCIÓN

El Performance Co-Pilot (PCP) es un conjunto de herramientas diseñadas para monitorear y gestionar el rendimiento del sistema. Estos servicios están distribuidos y escalables para adaptarse a las configuraciones más complejas de sistemas y problemas de rendimiento.

Para lograr estos objetivos de manera efectiva, se proporciona compatibilidad de protocolo y de disco entre diferentes versiones de PCP. Es factible (y en realidad se recomienda) utilizar las herramientas actuales de PCP para interrogar cualquier sistema remoto, una versión antigua o una versión reciente pmcd(1) y también para retransmitir cualquier archivo histórico de PCP (¡la suite de pruebas de PCP incluye archivos de PCP creados hace más de 20 años!).

A veces, los desarrolladores de PCP dejan de usar y eliminan herramientas de PCP antiguas, reemplazándolas por nuevas versiones que proporcionan funciones similares. Esta página describe herramientas de reemplazo para herramientas históricas de PCP.

PYTHON2

PCP proporciona interfaces de python(1) para el PMAPI(3) (API de métricas del sistema), el PMDA(3) (API de agentes de métricas del sistema), el mmv_stats_register(3) (API de valores de memoria-asignada) y la creación de archivos de PCP LOGIMPORT(3).

Con la versión python 2 llegando al fin de su vida útil en 2020, hemos eliminado todo el soporte para esta versión (a partir de la versión 7 de PCP y posteriores). Todas las API de PCP y herramientas basadas en python soportan python 3 y han estado en uso durante varios años; ¡la actualización es fuertemente recomendada!

QT4

PCP proporciona interfaces gráficas opcionales basadas en la librería de Qt, especialmente pmchart(1) y pmtime(1).

Con el fin de vida de Qt v4 en 2015, hemos eliminado el soporte para todas las versiones anteriores a Qt v5. Además, algunos elementos están ausentes en versiones tempranas de Qt v5, que ahora son obligatorios al construir y usar herramientas de PCP de Qt. Como resultado, la versión mínima requerida de Qt para PCP v6 y posteriores es ahora Qt 5.6.

NSS

Las versiones de PCP anteriores a v6 usaron una combinación de Mozilla NSS (Servicios de Seguridad de Red) y OpenSSL para la parte de la funcionalidad de encriptación de sockets seguros. Desde PCP v6, esto se ha simplificado al uso exclusivo de OpenSSL para todos los usos de encriptación en PCP. Este cambio afecta la configuración de funciones opcionales en pmcd(1) y PMAPI(3) usando sockets seguros.

El efecto neto de este cambio es que la encriptación se configura de la misma manera, usando los mismos certificados, en la funcionalidad HTTPS de pmproxy(1), así como en la función de protocolo de encriptación entre pmcd, pmproxy y clientes PMAPI. Además, el servidor de servicio de clave-valor utilizado por pmseries(1) y pmproxy también usa exclusivamente OpenSSL, y en un modo similar a PCP, lo que hace que la administración de estos servicios sea significativamente más sencilla.

SAR2PCP, IOSTAT2PCP

Las herramientas sar2pcp(1) y iostat2pcp(1) están obsoletas y se retirarán en una versión futura de PCP (v7). Serán reemplazadas por soporte nativo para generar archivos de PCP dentro de los paquetes de *sysstat* (que proporcionan sar mismo, así como la utilidad sadf que genera archivos de PCP mediante la opción -l).

PMLOGCONF-SETUP

Versiones anteriores de PCP (antes de v5.1.1) proporcionaban un script de shell que se utilizaba internamente por pmlogconf(1), ubicado en el directorio PCP_BINADM_DIR, llamado pmlogconf-setup. Este script ha sido retirado. La funcionalidad equivalente aún está disponible en el caso raro en el que se necesite mediante la opción -s o --setup de pmlogconf(1).

El formato de configuración del antiguo pmlogconf-setup (de IRIX) fue también retirado en este lanzamiento, tras más de 10 años de transición automática a formato v2 por pmlogconf.

PMMGR

El gestor de daemon de PCP pmmgr ha sido retirado desde la versión v5.2.0 de PCP. Fue desactivado en favor de la más simple pmfind(1) para configurar las ``granjas'' de sistemas de recolección de PCP de pmie(1) y pmlogger(1) descubiertas con pmfind_check(1). Los nuevos mecanismos, especialmente cuando integrados con systemd, requieren ningún otro servicio adicional y son más integrados con el servicio de pmie y pmlogger usado en otros lugares dentro de PCP.

PCP-COLLECTL

La herramienta pcp-collectl ha sido reemplazada por pmrep(1) desde la versión v5 de PCP.

La equivalente de pcp-collectl en el reporte de sistemas de recolección se logra de la siguiente manera:

pmrep :collectl-sc
Vista de subsistema de procesadores.
pmrep :collectl-sm
Vista de subsistema de memoria.
pmrep :collectl-sd
Vista de discos.
pmrep :collectl-sD
Vista por dispositivo de disco.
pmrep :collectl-dm-sD
Vista de mapeador de dispositivos.
pmrep :collectl-sn
Vista de subsistema de red.

PCP-WEBAPPS

Las aplicaciones web separadas que se incluían con versiones antiguas de PCP han sido reemplazadas por grafana-server(1) con el plugin grafana-pcp https://github.com/performancecopilot/grafana-pcp.

Este plugin proporciona una implementación de la aplicación Vector, así como fuentes de datos para pmdabpftrace(1) (scripts de bpftrace(8)) y pmseries(1) (análisis de series temporales más rápido, escalable y distribuido).

PMWEBD

El daemon pmwebd ha sido reemplazado por pmproxy(1) desde la versión v5 de PCP.

Por defecto, pmproxy ahora escuchará en ambos sus puertos originales (44322) y el puerto de la API web de PCP (44323) cuando se construya el soporte de series temporales.

pmproxy proporciona una implementación compatible de las interfaces de vivo PMWEBAPI(3) tradicionalmente usadas por la aplicación web Vector (ver la sección ``PCP-WEBAPPS''). También proporciona extensiones a las APIs REST originales de pmwebd (como métricas derivadas, consultas de espacio de nombres y perfiles de dominio de instancia), soporte del protocolo HTTPS y consultas de series temporales rápidas y escalables usando la API REST pmseries(1) con un servidor de clave-valor distribuido como https://valkey.io/).

La emulación parcial de la API de Graphite proporcionada por pmwebd no ha sido reimplementada; las aplicaciones que deseen usar servicios similares podrían utilizar las API escalables de series temporales descritas en PMWEBAPI(3).
