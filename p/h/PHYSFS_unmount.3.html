Detailed Description

Main header file for PhysicsFS.

Macro Definition Documentation

#define PHYSFS_file PHYSFS_File

1.0 API compatibility define. PHYSFS_file is identical to PHYSFS_File. This #define is here for backwards compatibility with the 1.0 API, which had an inconsistent capitalization convention in this case. New code should use PHYSFS_File, as this #define may go away someday.

#define PHYSFS_VERSION( x)

Value:

{ \
    (x)->major = PHYSFS_VER_MAJOR; \
    (x)->minor = PHYSFS_VER_MINOR; \
    (x)->patch = PHYSFS_VER_PATCH; \
}

Macro to determine PhysicsFS version program was compiled against. This macro fills in a PHYSFS_Version structure

con la versión de la biblioteca con la que compilaste. Esto se determina por el encabezado que utiliza el compilador. Ten en cuenta que si vinculaste dinámicamente la biblioteca, es posible que tengas una versión ligeramente más nueva o más antigua en tiempo de ejecución. Esa versión se puede determinar con PHYSFS_getLinkedVersion(), que, a diferencia de PHYSFS_VERSION, no es una macro.

Parámetros

x Un puntero a una estructura PHYSFS_Version para inicializar.

Posibles valores de retorno de PHYSFS_EnumerateCallback. Firma de función para devoluciones de llamada que enumeran y devuelven resultados.

Estos valores dictan si una devolución de llamada de enumeración debe continuar activándose o detenerse (y por qué se detiene).

Ver también

PHYSFS_EnumerateCallback

PHYSFS_enumerate

Esto es lo mismo que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, excepto que puede devolver un resultado de la devolución de llamada: a saber: si estás buscando algo específico, una vez que lo encuentres, puedes indicarle a PhysicsFS que deje de enumerar más. Esto se utiliza con PHYSFS_enumerate(), que esperamos que hayamos hecho bien esta vez. :)

Parámetros

data Puntero a datos definidos por el usuario, pasado desde la API que finalmente llamó a la devolución de llamada.
origdir Una cadena que contiene la ruta completa, en notación independiente de la plataforma, del directorio que contiene este archivo. En la mayoría de los casos, este es el directorio sobre el cual solicitaste la enumeración, pasado en la devolución de llamada para tu conveniencia.
fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otras devoluciones de llamada que se hayan activado, y no contendrá la ruta completa. Puedes recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

Devoluciones

Un valor de PHYSFS_EnumerateCallbackResult. Todos los demás valores están (actualmente) indefinidos; no los uses.

PHYSFS_EnumerateCallbackResult

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para devoluciones de llamada que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, utiliza PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso.

Se utilizan para informar una lista de entradas de directorio a un llamador original, un archivo/directorio/enlace simbólico por devolución de llamada. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estas devoluciones de llamada se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que necesitan ser limpiadas con PHYSFS_freeList(). La devolución de llamada significa que la biblioteca no necesita asignar una lista completa y todas las cadenas por adelantado.

Ten en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente así en las versiones de devolución de llamada. Consulta la documentación de las API específicas, pero las cadenas pueden no estar ordenadas como esperas y podrías obtener cadenas duplicadas.

enum PHYSFS_ErrorCode

Valores que representan causas específicas de fallo. La mayoría de las veces, solo deberías preocuparte por si una operación dada falló o no, pero puede haber ocasiones en las que planees manejar un caso de fallo específico con gracia, por lo que proporcionamos códigos de error específicos.

La mayoría de estos errores son un poco vagos, y la mayoría no son cosas que puedas arreglar... si hay un error de permisos, por ejemplo, todo lo que realmente puedes hacer es pasar esa información al usuario y dejar que averigüe cómo manejarla. En la mayoría de estos casos, tu programa solo debe saber que no logró cumplir sus objetivos, y no debe importarle específicamente por qué.

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio en la ruta de búsqueda, utilizando una función de devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() solo llama a esta función y luego crea una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. En cambio, llama a una función especificada por la aplicación una vez por cada elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return physFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/alguna/ruta", printDir, NULL);

No se garantiza que los elementos enviados a la función de devolución de llamada estén en ningún orden específico. No se realiza ningún ordenamiento a este nivel, y si lo necesitas, probablemente deberías usar PHYSFS_enumerateFiles() en su lugar, que garantiza el ordenamiento alfabético. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. Cualquier ordenamiento que encuentres en estas devoluciones de llamada es pura suerte. No confíes en él. Como esto recorre toda la lista de archivos, puedes recibir nombres de archivo duplicados.

Esta API y las propias funciones de devolución de llamada son capaces de informar errores. Antes de esta API, las funciones de devolución de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS en sí tenía un problema (error de disco o similar), no podía informarlo a la aplicación que llama, solo tendría que omitir elementos o detener la enumeración directamente, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su función de devolución de llamada tiene control si desea que la enumeración se detenga antes. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su función de devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, a enumerar.
c Función de devolución de llamada para notificar sobre los elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la función de devolución de llamada. Puede ser NULL.

Devuelve

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si la función de devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse antes, esto se considerará un éxito. Las funciones de devolución de llamada que devuelven PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establecerán el código de error en PHYSFS_ERR_APP_CALLBACK.

Advertencia

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * Tenemos [%s].\n", *i);
PHYSFS_freeList(rc);

* Tenemos [z.sav].

PHYSFS_mount

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

int PHYSFS_registerArchiver(const PHYSFS_Archiver* archiver)

Añade un nuevo archivador al sistema.

Advertencia

Esto es para usuarios avanzados. No lo necesita a menos que sepa realmente lo que está haciendo. La mayoría de las aplicaciones no lo necesitarán.

Si desea proporcionar su propio archivador (por ejemplo, un formato de archivo de archivo personalizado, o algo virtual que desee que parezca un sistema de archivos al que pueda acceder a través de las API habituales de PhysicsFS), aquí es donde comienza. Internamente, PhysicsFS utiliza esta función para registrar sus propios archivadores integrados, como el soporte .zip, etc.

No puede tener dos archivadores que manejen la misma extensión. Si va a haber un conflicto, puede anular el registro del otro archivador (incluidos los integrados) con PHYSFS_deregisterArchiver().

Los datos en (archiver) se copian; puede liberar este puntero cuando esta función retorne.

Una vez que esta función retorne con éxito, PhysicsFS podrá admitir archivos de este tipo hasta que anule el registro del archivador nuevamente.

archiver El archivador a registrar.

Retorna

Cero en caso de error, distinto de cero en caso de éxito.

int PHYSFS_setAllocator(const PHYSFS_Allocator* allocator)

Engancha tus propias rutinas de asignación en PhysicsFS. (Esto es para uso limitado y avanzado. Si no ve una necesidad inmediata, probablemente pueda ignorar esto para siempre).

Por defecto, PhysicsFS utilizará lo que sea razonable para una plataforma para administrar la memoria dinámica (generalmente malloc/realloc/free de ANSI C, pero algunas plataformas pueden usar algo más), pero en algunos casos poco comunes, la aplicación podría querer más control sobre la gestión de memoria de la biblioteca. Esto le permite redirigir PhysicsFS para que utilice sus propias rutinas de asignación en su lugar. Solo puede llamar a esta función antes de PHYSFS_init(); si la biblioteca está inicializada, rechazará sus esfuerzos para cambiar el asignador a mitad de camino. Puede llamar a esta función después de PHYSFS_deinit() si está dispuesto a apagar la biblioteca y reiniciarla con un nuevo asignador; esta es una operación segura y compatible. El asignador permanece intacto entre las llamadas de deinit/init. Si desea volver al asignador predeterminado de la plataforma, pase un NULL aquí.

Si no está seguro de qué hacer con esta función, puede ignorarla con seguridad.

Parámetros

allocator Estructura que contiene los puntos de entrada de su asignador.

Retorna

Cero en caso de fallo, distinto de cero en caso de éxito. Esta llamada solo falla cuando se utiliza entre llamadas a PHYSFS_init() y PHYSFS_deinit().

int PHYSFS_setRoot (const char * archive, const char * subdir)

Convierte un subdirectorio de un archivo en su directorio raíz. Esto te permite delimitar los archivos accesibles en un archivo específico. Detailed Description

These functions are convenience wrappers around PHYSFS_write(3) that will convert an unsigned integer from the platform's native byte order to the specified endianness, and then write it to the specified file handle.

They are intended to be used when writing out data files that have a specific endianness specified, regardless of the platform the program is running on.
