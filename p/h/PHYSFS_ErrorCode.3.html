Posibles valores de retorno de PHYSFS_EnumerateCallback. Firma de función para las devoluciones de llamada que enumeran y devuelven resultados.

Estos valores dictan si una devolución de llamada de enumeración debe continuar ejecutándose o detenerse (y por qué se detiene).

PHYSFS_enumerate

Esto es lo mismo que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, excepto que puede devolver un resultado de la devolución de llamada: en concreto: si estás buscando algo específico, una vez que lo encuentras, puedes decirle a PhysicsFS que deje de enumerar más. Esto se usa con PHYSFS_enumerate(), que esperamos que hayamos hecho bien esta vez. :)

Parámetros

data Puntero de datos definido por el usuario, pasado desde la API que eventualmente llamó a la devolución de llamada.
origdir Una cadena que contiene la ruta completa, en notación independiente de la plataforma, del directorio que contiene este archivo. En la mayoría de los casos, este es el directorio sobre el cual solicitaste la enumeración, pasado en la devolución de llamada para tu conveniencia.
fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otras devoluciones de llamada que se hayan ejecutado, y no contendrá la ruta completa. Puedes recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para las devoluciones de llamada que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso.

Estos se utilizan para informar a un llamador original de una lista de entradas de directorio, un archivo/directorio/enlace simbólico por devolución de llamada. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estas devoluciones de llamada se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que deben ser limpiadas con PHYSFS_freeList(). La devolución de llamada significa que la biblioteca no necesita asignar una lista completa y todas las cadenas por adelantado.

Ten en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente el mismo en las versiones de devolución de llamada. Consulta la documentación de APIs específicas, pero es posible que las cadenas no estén ordenadas como esperas y que obtengas cadenas duplicadas.

enum PHYSFS_ErrorCode

Valores que representan causas específicas de fallo. La mayoría de las veces, solo deberías preocuparte por si una operación dada falló o no, pero puede haber ocasiones en las que planees manejar un caso de fallo específico con gracia, por lo que proporcionamos códigos de error específicos.

La mayoría de estos errores son un poco vagos, y la mayoría no son cosas que puedas arreglar... si hay un error de permisos, por ejemplo, todo lo que realmente puedes hacer es pasar esa información al usuario y dejar que descubra cómo manejarlo. En la mayoría de estos casos, tu programa solo debería preocuparse de que no logró sus objetivos, y no preocuparse específicamente por qué.

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). int PHYSFS_delete(const char *filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio de ruta de búsqueda, utilizando una función de devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego construye una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. En cambio, llama a una función especificada por la aplicación una vez por elemento de la ruta de búsqueda:

{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/alguna/ruta", printDir, NULL);

No se garantiza que los elementos enviados a la función de devolución de llamada estén en ningún orden en absoluto. No se realiza ninguna ordenación en este nivel, y si la necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza la ordenación alfabética. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. Cualquier ordenación que encuentre en estas devoluciones de llamada es pura suerte. No dependa de ella. A medida que recorre toda la lista de archivos, puede recibir nombres de archivo duplicados.

Esta API y las propias funciones de devolución de llamada son capaces de informar errores. Antes de esta API, las funciones de devolución de llamada tenían que aceptar todos los elementos enumerados, incluso si solo buscaban algo específico y querían detenerse después de eso, o tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS en sí tenía un problema (error de disco o similar), no podía informarlo a la aplicación que lo llamaba, solo tenía que omitir elementos o dejar de enumerar directamente, y el que llama no sabría que había perdido algunos datos en el camino.

Ahora el que llama puede estar seguro de que obtuvo un conjunto de datos completo, y su función de devolución de llamada tiene control si desea que la enumeración se detenga temprano. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su función de devolución de llamada.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. ¡Los archivos dentro de archivos pueden ser muy lentos! Si bien un PHYSFS_File puede buscar incluso cuando los datos están comprimidos, puede hacerlo rebobinando al principio y descomprimiendo todo antes del punto de búsqueda. El uso normal de archivos puede implicar muchas búsquedas en segundo plano. Como tal, podría encontrar el uso normal de archivos extremadamente engorroso si se monta de esta manera. void PHYSFS_permitSymbolicLinks(int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparentemente) el archivo al que apunta.

Por defecto, PhysicsFS comprobará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarlo fuera de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si desea asumir ese riesgo, llame a esta función con un parámetro distinto de cero. Tenga en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En términos generales, un usuario podría tener una razón legítima para crear un enlace simbólico, por lo que a menos que sienta que hay un peligro específico en permitirlos, debería permitirlos.

Tenga en cuenta que PHYSFS_stat() siempre comprobará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlace simbólico se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

Convierte una cadena UTF-8 a una cadena Latin1. Las cadenas Latin1 tienen 8 bits por carácter: una codificación popular de "ASCII superior".

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, asigna un búfer que sea el doble del tamaño del búfer de origen. UTF-8 expande los puntos de código latin1 mayores a 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

Tenga en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiéndote lejos de ella en todo momento.

src Cadena de origen terminada en nulo en formato Latin1.
dst Búfer para almacenar la cadena UTF-8 convertida.
