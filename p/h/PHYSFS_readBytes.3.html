Esto es lo mismo que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, excepto que puede devolver un resultado del callback: a saber: si está buscando algo específico, una vez que lo encuentra, puede indicarle a PhysicsFS que deje de enumerar más. typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para callbacks que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, use PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; le da más control sobre el proceso.

Estos se utilizan para informar una lista de entradas de directorio a un llamador original, un archivo/directorio/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estos callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que necesitan ser limpiadas con PHYSFS_freeList(). El callback significa que la biblioteca no necesita asignar una lista completa y todas las cadenas por adelantado.

Tenga en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente así en las versiones de callback. Consulte la documentación de las API específicas, pero las cadenas pueden no estar ordenadas como espera y puede obtener cadenas duplicadas.

origdir Una cadena que contiene la ruta completa, en notación independiente de la plataforma, del directorio que contiene este archivo. En la mayoría de los casos, este es el directorio sobre el cual solicitó la enumeración, pasado en el callback para su conveniencia.
fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otros callbacks que se han ejecutado, y no contendrá la ruta completa. Puede recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtenga una lista de archivos del directorio de una ruta de búsqueda, utilizando una función de devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego crea una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica, excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. Más bien, llama a una función especificada por la aplicación una vez por cada elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dadme más datos, por favor.
}
// ...
PHYSFS_enumerate("/alguna/ruta", printDir, NULL);

No se garantiza que los elementos enviados a la función de devolución de llamada estén en ningún orden en absoluto. No se realiza ningún ordenamiento a este nivel, y si lo necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza el ordenamiento alfabético. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un solo archivo, no podemos garantizar el orden en que descubrirá los datos. *Cualquier ordenación que encuentre en estas devoluciones de llamada es pura suerte. No dependa de ello.* Dado que esto recorre toda la lista de archivos, puede recibir nombres de archivo duplicados.

Esta API y las propias funciones de devolución de llamada son capaces de informar errores. Antes de esta API, las funciones de devolución de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o tenían un error grave y no podían alertar a nadie. Además, si el propio PhysicsFS tenía un problema (error de disco o similar), no podía informarlo a la aplicación que llamaba, solo tendría que omitir elementos o dejar de enumerar por completo, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su función de devolución de llamada tiene el control si desea que la enumeración se detenga antes. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su función de devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, para enumerar.
c Función de devolución de llamada para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la función de devolución de llamada. Puede ser NULL.

Devoluciones

Distinto de cero en caso de éxito, cero en caso de error. Utilice PHYSFS_getLastErrorCode() para obtener el error específico. Si la función de devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse antes, esto se considerará un éxito. Las funciones de devolución de llamada que devuelven PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establecerán el código de error en PHYSFS_ERR_APP_CALLBACK.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivados contienen archivos que son simplemente punteros a otros archivos. Al abrir un enlace simbólico físico, se abrirá transparentemente el archivo al que se refiere.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarte fuera de los caminos de lectura y escritura, comprometiendo la seguridad.

Si deseas tomar ese riesgo, llama a esta función con un valor no cero. Este es más para los contenedores de un lenguaje de scripting de un programa, en caso de scripts no confiados intenten comprometer el sistema. Generalmente, un usuario podría tener una razón válida para establecer un enlace simbólico, así que no deberías deshabilitarlo, a menos que sientas que hay un peligro específico en permitirlos.

Los enlaces simbólicos se verán solo cuando se trate de nombres de archivos en notación independiente del sistema. Es decir, cuando se establecen tus caminos de búsqueda y escritura, etc., los enlaces simbólicos nunca se verán.

Nota: PHYSFS_stat() siempre verificará el camino especificado; si ese camino es un enlace simbólico, no se lo seguirá en ningún caso. Si los enlaces simbólicos no se permiten a través de esta función, PHYSFS_stat() los ignora y tratará la consulta como si el camino no existiera.

El permiso de enlaces simbólicos puede habilitarse o deshabilitarse después de haber llamado PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow no cero para permitir enlaces simbólicos, cero para negar el enlace.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Establece un subdirectorio de un archivo como su directorio raíz. Esto te permite acotar los archivos accesibles en un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/z.txt, montado en /a, si llamas a PHYSFS_setRoot("x.zip", "/y"), entonces la llamada PHYSFS_openRead("/a/z.txt") tendrá éxito.

int PHYSFS_setSaneConfig (const char * organization, const char * appName, const char * archiveExt, int includeCdRoms, int archivesFirst)

Configura rutas predeterminadas y sensatas. Función de ayuda.

El directorio de escritura se establecerá en el directorio de preferencias devuelto por

PHYSFS_getPrefDir(organization, appName)

, que se crea si no existe.

Lo anterior es suficiente para asegurar que el directorio de configuración de tu programa esté separado de otro desorden y sea independiente de la plataforma.

La ruta de búsqueda será:

  • El Directorio de Escritura (creado si no existe)
  • El Directorio Base (PHYSFS_getBaseDir())
  • Todos los directorios de CD-ROM encontrados (opcionalmente)

Estos directorios se buscan luego para encontrar archivos que terminan con la extensión (archiveExt), que, si son archivos válidos y compatibles, también se agregarán a la ruta de búsqueda. Si especificaste "PKG" para (archiveExt), y hay un archivo llamado data.PKG en el directorio base, se comprobará. Los archivos se pueden agregar o anteponer a la ruta de búsqueda en orden alfabético, independientemente de los directorios en los que se encontraron. Todos los archivos se montan en la raíz del sistema de archivos virtual ("/").

Todo esto se puede lograr desde la aplicación, pero esto simplemente lo hace todo por ti. Siéntete libre de agregar más a la ruta de búsqueda manualmente, también.

Parámetros

organization Nombre de tu empresa/grupo/etc. que se utilizará como nombre de directorio, así que mantenlo corto y sencillo.
appName Nombre específico del programa para separarlo de otros programas que usan PhysicsFS.
archiveExt Extensión de archivo utilizada por tu programa para especificar un archivo. Por ejemplo, Quake 3 usa "pk3", aunque solo son archivos zip. Especifica NULL para no extraer archivos automáticamente. No especifiques el carácter '.'; si quieres buscar archivos ZIP, especifica "ZIP" y no ".ZIP"... la búsqueda de archivos no distingue entre mayúsculas y minúsculas.
includeCdRoms Distinto de cero para incluir CD-ROMs en la ruta de búsqueda, y (si (archiveExt) != NULL) buscarlos para encontrar archivos. Esto puede causar una cantidad significativa de bloqueos mientras se accede a los discos, y si no hay discos en la unidad (o incluso no están montados en sistemas Unix), es posible que no se pongan a disposición de todos modos. Es posible que desees especificar cero y manejar la configuración del disco tú mismo.
