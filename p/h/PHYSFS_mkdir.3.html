typedef void(* physfs_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para callbacks que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso.

Estos se utilizan para informar una lista de entradas de directorio a un llamador original, un archivo/directorio/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estos callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que deben ser limpiadas con PHYSFS_freeList(). El callback significa que la biblioteca no necesita asignar una lista completa y todas las cadenas de antemano.

Ten en cuenta que el orden prometido de los datos en las versiones de lista no es necesariamente el mismo en las versiones de callback. Consulta la documentación de las APIs específicas, pero es posible que las cadenas no estén ordenadas como esperas y que obtengas cadenas duplicadas.

Parámetros

data Puntero de datos definido por el usuario, pasado desde la API que eventualmente llamó al callback.
origdir Una cadena que contiene la ruta completa, en notación independiente de la plataforma, del directorio que contiene este archivo. En la mayoría de los casos, este es el directorio sobre el cual solicitaste la enumeración, pasado en el callback para tu conveniencia.
fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otros callbacks que se han ejecutado, y no contendrá la ruta completa. Puedes reconstruir la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

enum PHYSFS_ErrorCode

Valores que representan causas específicas de fallo. La mayoría de las veces, solo deberías preocuparte por si una operación dada falló o no, pero puede haber ocasiones en las que planees manejar un caso de fallo específico con gracia, por lo que proporcionamos códigos de error específicos.

La mayoría de estos errores son un poco vagos, y la mayoría no son cosas que puedas arreglar... si hay un error de permisos, por ejemplo, todo lo que realmente puedes hacer es pasar esa información al usuario y dejar que descubra cómo manejarlo. En la mayoría de estos casos, tu programa solo debería preocuparse por no haber logrado sus objetivos, y no importarle específicamente por qué.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtener una lista de archivos de un directorio de ruta de búsqueda, utilizando una devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego crea una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica, excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. Más bien, llama a una función especificada por la aplicación una vez por elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

No se garantiza que los elementos enviados a la devolución de llamada estén en ningún orden. No se realiza ninguna ordenación en este nivel, y si la necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza la ordenación alfabética. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. Cualquier ordenación que encuentre en estas devoluciones de llamada es pura suerte. No confíe en ella. A medida que recorre toda la lista de archivos, puede recibir nombres de archivo duplicados.

Esta API y las propias devoluciones de llamada son capaces de informar errores. Antes de esta API, las devoluciones de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS tenía un problema (error de disco o similar), no podía informarlo a la aplicación que llamaba, solo tenía que omitir elementos o dejar de enumerar por completo, y el que llamaba no sabría que había perdido algunos datos en el camino.

Ahora, el que llama puede estar seguro de que obtuvo un conjunto de datos completo, y su devolución de llamada tiene el control si desea que la enumeración se detenga antes. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, para enumerar.
c Función de devolución de llamada para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la devolución de llamada. Puede ser NULL.

Devoluciones

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si la devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse antes, esto se considerará un éxito. Las devoluciones de llamada que devuelven PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezca el código de error en PHYSFS_ERR_APP_CALLBACK.

Advertencia

En versiones de PhysicsFS anteriores a la 2.1, esta función devolvía tantos elementos como podía frente a una condición de fallo (falta de memoria, error de E/S de disco, etc.). Dado que esto significaba que las aplicaciones no podían distinguir entre el éxito total y el fallo parcial, y dado que la función siempre podía devolver NULL para informar fallos catastróficos de todos modos, en PhysicsFS 2.1 la política de esta función cambió: devolverá una lista de resultados completos o devolverá NULL para cualquier fallo de cualquier tipo, por lo que podemos garantizar que la enumeración se completó y no tiene lagunas en sus resultados.

char **rc = PHYSFS_enumerateFiles("savegames");

for (i = rc; *i != NULL; i++)

PHYSFS_freeList(rc);

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Añadir un archivo o directorio a la ruta de búsqueda. Si es un duplicado, el registro no se agrega de nuevo, incluso si el función es exitosa. No puedes añadir el mismo archivo a dos diferentes mountpoints: el control de duplicados se realiza contra el archivo y no contra el mountpoint.

Cuando montas un archivo, se añade a un sistema de archivos virtual... todos los archivos de todos los archivos montados se interpolan en un árbol de directorios único. Dos archivos montados en el mismo lugar (o un archivo con archivos superpuestos en otro mountpoint) pueden tener archivos superpuestos: en ese caso, el archivo más temprano en la ruta de búsqueda es seleccionado, y los otros archivos no son accesibles para la aplicación. Esto permite que los archivos puedan usarse para reemplazar revisiones previas; puedes usar el mecanismo de montaje para colocar archivos en un punto específico en el árbol de archivos y evitar superposiciones; es útil para modos descargados que puedan dañar datos de aplicación o sí mismos.

El mountpoint no necesita existir antes de montar, lo cual es diferente de lo que se espera en el concepto Unix de "montar" de los usuarios familiarizados. Además, más de un archivo puede montarse en el mismo mountpoint, o montpoints y contenidos de archivos pueden superponerse... el mecanismo de interpolación sigue funcionando así.

Se permite especificar un enlace simbólico a un archivo o directorio, independientemente del estado de PHYSFS_permitSymbolicLinks(). La función solo maneja enlaces simbólicos dentro del directorio o archivo montado.

mountPoint ubicación en el árbol interpolado donde este archivo será "montado", en notación independiente de la plataforma. NULL o "" es equivalente a "/".
appendToPath no cero para append a la ruta de búsqueda, cero para prepend.

Retorna

nozero si añadido a la ruta, zero en caso de error (archivo inválido, directorio no encontrado, etc). Usar PHYSFS_getLastErrorCode() para obtener el error específico.

void PHYSFS_permitSymbolicLinks(int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir dicho enlace abrirá (transparente) el archivo al que apunta.

Description

These functions convert a value from the platform's native byte order to either big-endian or little-endian, and then write it to the specified file.

They are convenience functions that wrap the logic of byte swapping and writing.

It is recommended to use these functions for writing binary data that needs to be portable across different architectures.
