typedef void(* physFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para callbacks que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso.

Estos se utilizan para informar una lista de entradas de directorio a un llamador original, un archivo/directorio/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estos callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que deben ser limpiadas con PHYSFS_freeList(). El callback significa que la biblioteca no necesita asignar una lista completa y todas las cadenas por adelantado.

Ten en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente el mismo en las versiones de callback. Consulta la documentación de APIs específicas, pero las cadenas pueden no estar ordenadas como esperas y podrías obtener cadenas duplicadas.

fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otros callbacks que se hayan ejecutado, y no contendrá la ruta completa. const PHYSFS_Allocator * PHYSFS_getAllocator (void )

Get the currently used allocator. This can be useful for apps that want to access PhysicsFS's internal, default allocation routines, as well as for external code that wants to share the same allocator, even if the application specified their own.

This call is only valid between PHYSFS_init() and PHYSFS_deinit() calls; it will return NULL if the library isn't initialized. As we can't guarantee the state of the internal allocators unless the library is initialized, you shouldn't use any allocator returned here after a call to PHYSFS_deinit().

If you aren't immediately sure what to do with this function, you can safely ignore it altogether.

const char * PHYSFS_getLastError (void )

Get human-readable error information.

Deprecated

Use PHYSFS_getLastErrorCode() and PHYSFS_getErrorByCode() instead.

Warning

As of PhysicsFS 2.1, this function has been nerfed. Before PhysicsFS 2.1, this function was the only way to get error details beyond a given function's basic return value. This was meant to be a human-readable string in one of several languages, and was not useful for application parsing. This was a problem, because the developer and not the user chose the language at compile time, and the PhysicsFS maintainers had to (poorly) maintain a significant amount of localization work. The app couldn't parse the strings, even if they counted on a specific language, since some were dynamically generated. In 2.1 and later, this always returns a static string in English; you may use it as a key string for your own localizations if you like, as we'll promise not to change existing error strings. Also, if your application wants to look at specific errors, we now offer a better option: use PHYSFS_getLastErrorCode() instead.

int PHYSFS_mount(const char *newDir, const char *mountPoint, int appendToPath)

Agregar un archivo o directorio a la ruta de búsqueda. Si es un duplicado, la entrada no se agrega de nuevo, aunque la función tenga éxito. No puede agregar el mismo archivo a dos puntos de montaje diferentes: la verificación de duplicados se realiza contra el archivo y no contra el punto de montaje.

Cuando monta un archivo, se agrega a un sistema de archivos virtual... todos los archivos en todos los archivos se interpolan en un único árbol de archivos jerárquico. Dos archivos montados en el mismo lugar (o un archivo con archivos que se superponen con otro punto de montaje) pueden tener archivos superpuestos: en tal caso, se selecciona el archivo anterior en la ruta de búsqueda, y los otros archivos son inaccesibles para la aplicación. Esto permite usar archivos para anular revisiones anteriores; puede usar el mecanismo de montaje para colocar archivos en un punto específico del árbol de archivos y evitar la superposición; esto es útil para modificaciones descargables que podrían pisotear datos de la aplicación o entre sí, por ejemplo.

El punto de montaje no necesita existir antes de montar, lo cual es diferente de lo que los familiarizados con el concepto de "montar" de Unix podrían esperar. Además, se pueden montar varios archivos en el mismo punto de montaje, o los puntos de montaje y el contenido de los archivos pueden superponerse... el mecanismo de interpolación sigue funcionando como de costumbre.

Se permite especificar un enlace simbólico a un archivo o directorio aquí, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esa función solo trata con enlaces simbólicos dentro del directorio o archivo montado.

Se utiliza para optimizar la selección del archivero (si lo nombras XXXXX.zip, podríamos intentar primero el archivero ZIP, por ejemplo, o elegir directamente un archivero que solo pueda confiar en que los datos son válidos por la extensión del nombre del archivo). No necesita referirse a un archivo real en absoluto. Si la extensión del nombre del archivo no es útil, el sistema intentará con cada archivero hasta que uno funcione o ninguno lo haga. Este nombre de archivo debe ser único, ya que el sistema no te permitirá tener dos archivos con el mismo nombre.

(ptr) debe permanecer hasta que el archivo se desmonte. Cuando el archivo se desmonte, el sistema llamará a (del)(ptr), lo que te notificará que el sistema ha terminado con el búfer y te dará la oportunidad de liberar tus recursos. (del) puede ser NULL, en cuyo caso el sistema no intentará liberar el búfer.

Si esta función falla, no se llama a (del).

Parámetros

buf Dirección del búfer de memoria que contiene los datos del archivo.
len Tamaño del búfer de memoria, en bytes.
del Una llamada de retorno que se activa al desmontar. Puede ser NULL.
newDir Nombre de archivo que puede representar este flujo.
mountPoint Ubicación en el árbol interpolado donde se "montará" este archivo, en notación independiente de la plataforma. NULL o "" es equivalente a "/".
appendToPath distinto de cero para añadir a la ruta de búsqueda, cero para anteponer.

Retorna

distinto de cero si se añadió a la ruta, cero en caso de fallo (archivo inválido, etc.). Usa PHYSFS_getLastErrorCode() para obtener el error específico.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y arquitecturas contienen archivos que son simples referencias a otros archivos. Al abrir un enlace simbólico en un sistema físico, este se abrirá transparentemente para el archivo al que se refiere.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si es así. De lo contrario, el enlace podría llevarte fuera de las rutas de lectura y escritura, poniendo en peligro la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un valor distinto de cero. Ten en cuenta que esto es más para la seguridad del lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una buena razón legítima para crear un enlace simbólico, por lo que no deberías deshabilitarlo a menos que percibas un riesgo específico.

Los enlaces simbólicos solo se verifican explícitamente cuando se trata de nombres de archivo en notación independiente de plataforma. Es decir, cuando se establecen tus rutas de búsqueda y escritura, etc., los enlaces simbólicos nunca se verifican.

Nota: PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, se seguirá en cualquier caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera.

La permitividad de enlaces simbólicos se puede habilitar o deshabilitar en cualquier momento después de haber llamado PHYSFS_init(), y está deshabilitada por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para deshabilitar la vinculación.
