DESCRIPTION

This is the main header file for the PhysicsFS library.

It declares functions for manipulating files and archives in a platform-independent way.

Byte Order Conversion

The following functions convert values between the platform's native byte order and little-endian or big-endian formats. This is useful when reading or writing binary files that may have been created on systems with different byte orders.

PHYSFS_swapULE32, PHYSFS_swapSLE32
Swap unsigned/signed 32-bit little-endian values to native byte order.
PHYSFS_swapUBE16, PHYSFS_swapSBE16
Swap unsigned/signed 16-bit big-endian values to native byte order.
PHYSFS_swapUBE32, PHYSFS_swapSBE32
Swap unsigned/signed 32-bit big-endian values to native byte order.
PHYSFS_swapUBE64, PHYSFS_swapSLE64
Swap unsigned/signed 64-bit big-endian/little-endian values to native byte order.

Reading and Writing Binary Data

These functions read and write specific data types to and from PHYSFS_File handles, automatically handling byte order conversion.

PHYSFS_readULE16, PHYSFS_readSLE16, PHYSFS_readUBE16, PHYSFS_readSBE16
Read unsigned/signed 16-bit little-endian/big-endian values.
PHYSFS_readULE32, PHYSFS_readSLE32, PHYSFS_readUBE32, PHYSFS_readSBE32
Read unsigned/signed 32-bit little-endian/big-endian values.
PHYSFS_readULE64, PHYSFS_readSLE64, PHYSFS_readUBE64, PHYSFS_readSBE64
Read unsigned/signed 64-bit little-endian/big-endian values.
PHYSFS_writeULE16, PHYSFS_writeSLE16, PHYSFS_writeUBE16, PHYSFS_writeSBE16
Write unsigned/signed 16-bit little-endian/big-endian values.
PHYSFS_writeULE32, PHYSFS_writeSLE32, PHYSFS_writeUBE32, PHYSFS_writeSBE32
Write unsigned/signed 32-bit little-endian/big-endian values.
PHYSFS_writeULE64, PHYSFS_writeSLE64, PHYSFS_writeUBE64, PHYSFS_writeSBE64
Write unsigned/signed 64-bit little-endian/big-endian values.

Initialization and Deinitialization

PHYSFS_init
Initializes the PhysicsFS library. Must be called before any other PhysicsFS function. The argv0 argument is used to determine the default search path on some platforms.
PHYSFS_deinit
Shuts down the PhysicsFS library. Frees any allocated resources.
PHYSFS_isInit
Returns true if the library has been initialized, false otherwise.

Mounting and Unmounting Archives

These functions manage the search path, which is a list of directories and archive files (like ZIP files) that PhysicsFS searches for files.

PHYSFS_mount
Adds a directory or archive file to the search path. newDir is the path to the directory or archive. mountPoint is the directory within the search path where this archive will be mounted. If mountPoint is NULL, it defaults to the archive's name. appendToPath indicates whether to add this to the beginning (0) or end (non-zero) of the search path.
PHYSFS_mountIo
Similar to PHYSFS_mount, but takes a pointer to a PHYSFS_Io structure, allowing you to mount archives from custom I/O sources.
PHYSFS_mountMemory
Mounts an archive contained within a memory buffer. The buffer is specified by buf and len. The del callback is an optional function to free the buffer memory when it's no longer needed. Other parameters are similar to PHYSFS_mount.
PHYSFS_mountHandle
Mounts an archive that is already open as a PHYSFS_File handle.
PHYSFS_unmount
Removes a directory or archive from the search path.
PHYSFS_getMountPoint
Returns the mount point for a given directory or archive in the search path.

Traversing the Search Path

These functions allow you to iterate over the contents of the search path and directories.

PHYSFS_getSearchPathCallback
Calls the specified callback function for each directory in the search path.
PHYSFS_getCdRomDirsCallback
Calls the specified callback function for each directory found on CD-ROM media.
PHYSFS_enumerateFilesCallback
Calls the specified callback function for each file and subdirectory within a given directory. The callback receives the file/directory name and a user- defined data pointer.
PHYSFS_enumerate
Similar to PHYSFS_enumerateFilesCallback, but returns an error code if any problems occur during enumeration.

File Operations

These functions provide basic file I/O operations through PhysicsFS.

PHYSFS_openRead, PHYSFS_openWrite, PHYSFS_openAppend
Opens a file for reading, writing, or appending, respectively. Returns a file descriptor (an integer) on success, or -1 on failure.
PHYSFS_close
Closes an open file descriptor.
PHYSFS_read, PHYSFS_write
Reads data from or writes data to an open file descriptor. Returns the number of bytes read/written, or -1 on error.
PHYSFS_readBytes, PHYSFS_writeBytes
Reads or writes a specified number of bytes from/to a PHYSFS_File handle. Returns the number of bytes read/written, or -1 on error.
PHYSFS_seek
Sets the current read/write position in an open file.
PHYSFS_tell, PHYSFS_fileTell
Returns the current read/write position in an open file.
PHYSFS_eof
Checks if the end of the file has been reached.
PHYSFS_delete
Deletes a file.
PHYSFS_mkdir
Creates a new directory.
PHYSFS_stat
Retrieves information about a file or directory (e.g., size, modification time).
PHYSFS_copy
Copies a file from one location to another.

String and Character Encoding Utilities

These functions handle conversions between different character encodings and provide string comparison utilities.

PHYSFS_getDirSeparator
Returns the platform-specific directory separator character ('/' or '\').
PHYSFS_utf8FromUcs2, PHYSFS_utf8FromUcs4, PHYSFS_utf8FromLatin1, PHYSFS_utf8FromUtf16
Convert strings from various encodings (UCS-2, UCS-4, Latin-1, UTF-16) to UTF-8.
PHYSFS_utf8ToUcs2, PHYSFS_utf8ToUcs4, PHYSFS_utf8ToUtf16
Convert UTF-8 strings to UCS-2, UCS-4, or UTF-16.
PHYSFS_caseFold
Converts a Unicode codepoint to its lowercase equivalent.
PHYSFS_utf8stricmp, PHYSFS_utf16stricmp, PHYSFS_ucs4stricmp
Perform case-insensitive comparisons on UTF-8, UTF-16, and UCS-4 strings, respectively.

Preference Directory

PHYSFS_getPrefDir
Returns the platform-specific path to a directory where user preferences or configuration files can be stored. org is the name of the organization, and app is the name of the application.

Allocator Functions

PHYSFS_setAllocator
Allows you to provide custom memory allocation routines (malloc, free, etc.) to PhysicsFS.
PHYSFS_getAllocator
Retrieves the currently active memory allocator.

Archiver Handling

PHYSFS_registerArchiver
Registers a new archive format handler with PhysicsFS. This allows PhysicsFS to read from custom archive types.
PHYSFS_deregisterArchiver
Removes a previously registered archiver based on its file extension.
PHYSFS_setRoot
Sets a subdirectory within an archive as the new root directory. This is useful for games that store assets in a subdirectory of an archive.

Error Handling

PHYSFS_getLastErrorCode
Returns the last error code generated by a PhysicsFS function.
PHYSFS_getErrorByCode
Returns a human-readable string describing a given error code.
PHYSFS_setErrorCode
Sets the error code for the current thread.

Symbolic Link Handling

PHYSFS_permitSymbolicLinks
Enables or disables the handling of symbolic links. By default, symbolic links are not followed.
PHYSFS_symbolicLinksPermitted
Returns true if symbolic links are currently permitted, false otherwise.

MACRO DEFINITION DOCUMENTATION

#define PHYSFS_file PHYSFS_File

This is a compatibility define for the 1.0 API. The internal structure representing a file handle was named PHYSFS_file in version 1.0, but was changed to PHYSFS_File later. This define ensures that code compiled against older versions will still work. New code should use PHYSFS_File directly.

#define PHYSFS_VERSION( x)

This macro is used to retrieve the version of the PhysicsFS library that the application was compiled against. It takes a pointer to a PHYSFS_Version structure, which it fills with the major, minor, and patch numbers of the library.

Value:

{ \
    (x)->major = PHYSFS_VER_MAJOR; \
    (x)->minor = PHYSFS_VER_MINOR; \
    (x)->patch = PHYSFS_VER_PATCH; \
}
b> estructura con la versión de la biblioteca contra la que compilaste. Esto se determina por el encabezado que el compilador utiliza. Ten en cuenta que si enlazaste la biblioteca dinámicamente, podrías tener una versión ligeramente más nueva o más antigua en tiempo de ejecución. Esa versión se puede determinar con PHYSFS_getLinkedVersion(), que, a diferencia de PHYSFS_VERSION, no es una macro.

int PHYSFS_deinit (void )

Desinicializar la biblioteca PhysicsFS. Esto cierra todos los archivos abiertos a través de PhysicsFS, borra las rutas de búsqueda/escritura, libera memoria e invalida todos sus manejadores de archivo.

Tenga en cuenta que esta llamada puede FALLAR si hay un archivo abierto para escritura que se niega a cerrar (por ejemplo, el sistema operativo subyacente estaba almacenando en búfer escrituras en un sistema de archivos de red y el servidor de archivos ha fallado, o un disco duro ha fallado, etc.). distinto de cero si tiene éxito, cero si hay error. Los detalles del error se pueden obtener de PHYSFS_getLastError(). Si falla, el estado de PhysFS es indefinido y probablemente muy dañado.

Eliminar un archivo o directorio. (filename) se especifica en notación independiente de la plataforma en relación con el directorio de escritura.

Un directorio debe estar vacío antes de que esta llamada pueda eliminarlo.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio de la ruta de búsqueda, utilizando una devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego crea una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. Más bien, llama a una función especificada por la aplicación una vez por cada elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

No se garantiza que los elementos enviados a la devolución de llamada estén en ningún orden. No se realiza ningún ordenamiento en este nivel, y si lo necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza el ordenamiento alfabético. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. Cualquier ordenamiento que encuentre en estas devoluciones de llamada es pura suerte. No confíe en él. Dado que esto recorre toda la lista de archivos, es posible que reciba nombres de archivo duplicados.

Esta API y las propias devoluciones de llamada son capaces de informar errores. Antes de esta API, las devoluciones de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o si tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS en sí tenía un problema (error de disco o similar), no podía informarlo a la aplicación que lo llamaba, solo tenía que omitir elementos o dejar de enumerar por completo, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su devolución de llamada tiene control si desea que la enumeración se detenga temprano. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, a enumerar.
c Función de devolución de llamada para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la devolución de llamada. Puede ser NULL.

Retorna

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si la devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse temprano, esto se considerará un éxito. Las devoluciones de llamada que devuelvan PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezca el código de error en PHYSFS_ERR_APP_CALLBACK.

char ** PHYSFS_enumerateFiles (const char * dir)

Obtiene una lista de archivos de un directorio de la ruta de búsqueda.

Advertencia

En las versiones de PhysicsFS anteriores a 2.1, esta función devolvería tantos elementos como pudiera frente a una condición de error (falta de memoria, error de E/S de disco, etc.). Dado que esto significaba que las aplicaciones no podían distinguir entre el éxito completo y el fallo parcial, y dado que la función siempre podía devolver NULL para informar fallos catastróficos de todos modos, en PhysicsFS 2.1 la política de esta función cambió: devolverá una lista de resultados completos o devolverá NULL para cualquier fallo de cualquier tipo, para que podamos garantizar que la enumeración se completó y no tiene lagunas en sus resultados.

Se interpolan los directorios coincidentes. Es decir, si "C:\mydir" está en la ruta de búsqueda y contiene un directorio "savegames" que contiene "x.sav", "y.sav", y "z.sav", y también hay un "C:\userdir" en la ruta de búsqueda que tiene un subdirectorio "savegames" con "w.sav", entonces el siguiente código:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * Tenemos [%s].\n", *i);
PHYSFS_freeList(rc);
* Tenemos [x.sav].
* Tenemos [y.sav].
* Tenemos [z.sav].
* Tenemos [w.sav]..fi
Siéntase libre de ordenar la lista como prefiera. Sin embargo, los datos devueltos no contendrán duplicados y siempre estarán ordenados alfabéticamente (o mejor dicho, en orden Unicode sensible a mayúsculas y minúsculas).
No olvide llamar a PHYSFS_freeList() con el valor de retorno de esta función cuando haya terminado con él.
Parámetros
dir directorio en notación independiente de la plataforma a enumerar. 
Retorna
Matriz terminada en nulo de cadenas terminadas en nulo, o NULL para casos de fallo.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

El uso normal de archivos puede implicar muchas búsquedas en segundo plano. Como tal, puede encontrar que el uso normal de archivos es extremadamente doloroso si se monta de esta manera. Planifique en consecuencia: si, por ejemplo, tiene un archivo .zip autoextraíble y desea montar algo en él, comprima el contenido del archivo interno y asegúrese de que el archivo .zip externo no comprima el archivo interno también.

Esta función opera igual que PHYSFS_mount(), pero toma un manejador de PHYSFS_File en lugar de un nombre de ruta. Este manejador contiene todos los datos del archivo y se utiliza en lugar de un archivo real en el sistema de archivos físico. El PHYSFS_File puede estar respaldado por un archivo real en el sistema de archivos físico, pero no es necesariamente así. El uso más popular para esto es probablemente montar archivos almacenados dentro de otros archivos.

(newDir) debe ser una cadena única para identificar este archivo. Se utiliza para optimizar la selección del archivador (si lo nombra XXXXX.zip, podríamos intentar primero el archivador ZIP, por ejemplo, o elegir directamente un archivador que solo pueda confiar en que los datos son válidos por la extensión del nombre del archivo). No necesita referirse a un archivo real en absoluto. Si la extensión del nombre del archivo no es útil, el sistema intentará con cada archivador hasta que uno funcione o ninguno lo haga. Este nombre de archivo debe ser único, ya que el sistema no le permitirá tener dos archivos con el mismo nombre.

(file) debe permanecer hasta que el archivo se desmonte. Cuando el archivo se desmonte, el sistema llamará a PHYSFS_close(file). Si necesita que este manejador sobreviva, tendrá que envolverlo en un PHYSFS_Io y usar PHYSFS_mountIo() en su lugar.

Si esta función falla, no se llama a PHYSFS_close(file).

void PHYSFS_permitSymbolicLinks (int allow)

Enable or disable following of symbolic links. Some physical filesystems and archives contain files that are just pointers to other files. On the physical filesystem, opening such a link will (transparently) open the file that is pointed to.

By default, PhysicsFS will check if a file is really a symlink during open calls and fail if it is. Otherwise, the link could take you outside the write and search paths, and compromise security.

If you want to take that risk, call this function with a non-zero parameter. Note that this is more for sandboxing a program's scripting language, in case untrusted scripts try to compromise the system. Generally speaking, a user could very well have a legitimate reason to set up a symlink, so unless you feel there's a specific danger in allowing them, you should permit them.

Symlinks are only explicitly checked when dealing with filenames in platform-independent notation. That is, when setting up your search and write paths, etc, symlinks are never checked for.

Please note that PHYSFS_stat() will always check the path specified; if that path is a symlink, it will not be followed in any case. If symlinks aren't permitted through this function, PHYSFS_stat() ignores them, and would treat the query as if the path didn't exist at all.

Symbolic link permission can be enabled or disabled at any time after you've called PHYSFS_init(), and is disabled by default.

Parameters

allow nonzero to permit symlinks, zero to deny linking.

See also

PHYSFS_symbolicLinksPermitted

Establecer tus propias rutinas de asignación en PhysicsFS. (Esto es para uso limitado y avanzado. Si no ves inmediatamente una necesidad, puedes ignorarlo siempre que lo desees).

int PHYSFS_setBuffer (PHYSFS_File * handle, PHYSFS_uint64 bufsize)

Establecer el búfer para un manejador de archivo PhysicsFS. Configura un búfer de E/S para un manejador de archivo. Se asignará un bloque de memoria de (bufsize) bytes y se asociará con (handle).

Para archivos abiertos para lectura, se leerán hasta (bufsize) bytes de (handle) y se almacenarán en el búfer interno. Las llamadas a PHYSFS_read() tomarán de este búfer hasta que esté vacío, y luego se rellenará el búfer para lecturas posteriores. Ten en cuenta que los archivos comprimidos, como los ZIP, se descomprimirán mientras se almacenan en búfer, lo que puede ser útil para desplazar operaciones que consumen mucha CPU. El búfer no se llenará hasta que realices tu próxima lectura.

void PHYSFS_setBuffer (PHYSFS_File* handle, unsigned int bufsize)

Establece un nuevo tamaño de búfer para un archivo abierto. Si el búfer es mayor que cero, se asignará un nuevo búfer de ese tamaño. Si el tamaño del búfer es cero, se liberará cualquier búfer existente.

Si el búfer es mayor que cero, y el búfer se libera porque se necesita un nuevo búfer, se intentará vaciar el búfer existente. Esto puede fallar por las mismas razones que podría fallar PHYSFS_flush.

Los tamaños de búfer mayores que cero se pueden lograr mediante llamadas repetidas a esta función. El búfer predeterminado para los archivos abiertos por PhysicsFS es de 4096 bytes. Tenga en cuenta que llamar a esto con un tamaño de búfer de 0 bytes todavía puede fallar.

Los archivos abiertos para escritura se vaciarán automáticamente al cerrar, lo que implícitamente causa un vaciado... ¡comprueba tus valores de retorno!

Seeking, etc. tiene en cuenta el almacenamiento en búfer de forma transparente.

Puede cambiar el tamaño de un búfer existente llamando a esta función más de una vez en el mismo archivo. Establecer el tamaño del búfer a cero liberará un búfer existente.

Los identificadores de archivo de PhysicsFS no tienen búfer de forma predeterminada.

¡Por favor, comprueba el valor de retorno de esta función! Los fallos pueden incluir la imposibilidad de buscar hacia atrás en un archivo de solo lectura al eliminar el búfer, la imposibilidad de asignar el búfer y la imposibilidad de vaciar el búfer en el disco, entre otros problemas inesperados.

handle identificador devuelto por PHYSFS_open*().
bufsize tamaño, en bytes, del búfer a asignar.

distinto de cero si tiene éxito, cero en caso de error.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Haz que un subdirectorio de un archivo sea su directorio raíz. Esto te permite limitar los archivos accesibles en un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/o.txt, montado en /a, si llamas a PHYSFS_setRoot("x.zip", "/y"), entonces la llamada PHYSFS_openRead("/a/z.txt") tendrá éxito.

Puedes cambiar la raíz de un archivo en cualquier momento, alterando el árbol de archivos interpolado (dependiendo de dónde cambien las rutas, un archivo diferente puede estar proporcionando varios archivos). Si estableces la raíz a NULL o "/", el archivo se tratará como si no se hubiera establecido ninguna raíz especial (como si el archivo se hubiera montado normalmente).

Cambiar la raíz solo afecta a las operaciones futuras en nombres de ruta; un archivo que se abrió desde una ruta que cambió debido a un setRoot no se verá afectado.

Establecer una nueva raíz no se limita a los archivos en la ruta de búsqueda; puedes establecer una en el directorio de escritura, lo que podría ser útil si tienes archivos abiertos para escritura y por lo tanto no puedes cambiar el directorio de escritura en este momento.

No es un error establecer un subdirectorio que no existe como raíz de un archivo; sin embargo, no se verán archivos en este caso. Si los directorios faltantes terminan siendo creados (un mkdir al sistema de archivos físico, etc.), esto se reflejará en el árbol interpolado.

Parámetros

archive directorio/archivo en el que cambiar la raíz.
subdir nuevo subdirectorio que se convertirá en la raíz de este archivo.

Retorna

distinto de cero en caso de éxito, cero en caso de fallo. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

int PHYSFS_setSaneConfig (const char * organization, const char * appName, const char * archiveExt, int includeCdRoms, int archivesFirst)

Configura rutas predeterminadas y sensatas. Función auxiliar.

El directorio de escritura se establecerá en el directorio de preferencias devuelto por

PHYSFS_getPrefDir(organization, appName)

, que se crea si no existe.

Lo anterior es suficiente para asegurar que el directorio de configuración de tu programa esté separado de otro desorden, y sea independiente de la plataforma.

La ruta de búsqueda será:

  • El Directorio de Escritura (creado si no existe)
  • El Directorio Base (PHYSFS_getBaseDir())
  • Todos los directorios de CD-ROM encontrados (opcionalmente)

Estos directorios se buscan para encontrar archivos que terminen con la extensión (archiveExt), que, si son archivos válidos y compatibles, también se añadirán a la ruta de búsqueda. Si especificaste "PKG" para (archiveExt), y hay un archivo llamado data.PKG en el directorio base, se comprobará. Los archivos pueden ser añadidos o prefijados a la ruta de búsqueda en orden alfabético, independientemente de los directorios en los que se encontraran. Todos los archivos se montan en la raíz del sistema de archivos virtual ("/").

Todo esto se puede lograr desde la aplicación, pero esto simplemente lo hace todo por ti. Siéntete libre de añadir más a la ruta de búsqueda manualmente, también.

Parámetros

organization Nombre de tu empresa/grupo, etc., que se utilizará como nombre de directorio, así que mantenlo corto y sencillo.
appName Nombre específico del programa para tu programa, para separarlo de otros programas que utilizan PhysicsFS.
archiveExt Extensión de archivo utilizada por tu programa para especificar un archivo. Por ejemplo, Quake 3 usa "pk3", aunque solo sean archivos zip. Especifica NULL para no buscar archivos automáticamente. No especifiques el carácter '.'; si quieres buscar archivos ZIP, especifica "ZIP" y no ".ZIP" ... la búsqueda de archivos no distingue entre mayúsculas y minúsculas.
includeCdRoms Distinto de cero para incluir CD-ROMs en la ruta de búsqueda, y (si (archiveExt) != NULL) buscarlos para encontrar archivos. Esto puede causar una cantidad significativa de bloqueo mientras se accede a los discos, y si no hay discos en la unidad (o incluso no montados en sistemas Unix), es posible que no se pongan a disposición de todos modos. Es posible que desees especificar cero y manejar la configuración del disco tú mismo.
archivesFirst Distinto de cero para prefijar los archivos a la ruta de búsqueda. Cero para añadirlos. Ignorado si !(archiveExt).

Retorna

distinto de cero en caso de éxito, cero en caso de fallo. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convertir una cadena UTF-8 a una cadena Latin1. Las cadenas Latin1 son de 8 bits por carácter: una codificación popular de "ASCII superior".

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, reserve un búfer que sea el doble del tamaño del búfer de origen. UTF-8 expande los puntos de código latin1 mayores que 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no caben en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

Tenga en cuenta que no proporcionamos un convertidor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiéndote lejos de ella en todo momento.

Parámetros

src Cadena de origen terminada en nulo en formato Latin1.
dst Búfer para almacenar la cadena UTF-8 convertida.
len Tamaño, en bytes, del búfer de destino.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 *dst, PHYSFS_uint64 len)

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

dst Buffer to store converted UTF-16 string.

PHYSFS_sint64 PHYSFS_writeBytes (PHYSFS_File * handle, const void * buffer, PHYSFS_uint64 len)

Write data to a PhysicsFS filehandle. The file must be opened for writing.

Please note that while (len) is an unsigned 64-bit integer, you are limited to 63 bits (9223372036854775807 bytes), so we can return a negative value on error. If length is greater than 0x7FFFFFFFFFFFFFFF, this function will immediately fail. For systems without a 64-bit datatype, you are limited to 31 bits (0x7FFFFFFF, or 2147483647 bytes). We trust most things won't need to do multiple gigabytes of i/o in one call anyhow, but why limit things?

PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64, PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64 - Convert and write big/little-endian values to a file.

Description

These are convenience functions for writing basic integer types to a file in a specific endianness. They convert the value from the platform's native byte order to the specified endianness (big-endian or little-endian) before writing it to the file.

It is assumed that the file was opened with write access using PHYSFS_openWrite().

The functions are named as follows: PHYSFS_write[BE|LE][16|32|64]. BE stands for big-endian, LE for little-endian, and the number indicates the bit size of the integer type.

On failure, you can find out what went wrong from PHYSFS_getLastErrorCode().
