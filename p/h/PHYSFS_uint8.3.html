int PHYSFS_caseFold(const PHYSFS_uint32 from, PHYSFS_uint32 *to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_deinit(void)

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete(const char *filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

int PHYSFS_deregisterArchiver(const char *ext)

Remove an archiver from the system. If for some reason, you only need your previously-registered archiver to live for a portion of your app's lifetime, you can remove it from the system once you're done with it through this function.

This fails if there are any archives still open that use this archiver.

This function can also remove internally-supplied archivers, like .zip support or whatnot. This could be useful in some situations, like disabling support for them outright or overriding them with your own implementation. Once an internal archiver is disabled like this, PhysicsFS provides no mechanism to recover them, short of calling PHYSFS_deinit() and PHYSFS_init() again.

PHYSFS_deinit() will automatically de

register all archivers, so you don't need to explicitly deregister yours if you otherwise shut down cleanly.

Parámetros

ext Extensión de nombre de archivo que maneja el archivador.

Retorna

Cero en caso de error, distinto de cero en caso de éxito.

Obtiene una lista de archivos de un directorio de ruta de búsqueda, utilizando una devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego crea una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representan los datos a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. En su lugar, llama a una función especificada por la aplicación una vez por elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/alguna/ruta", printDir, NULL);

No se garantiza que los elementos enviados a la devolución de llamada estén en ningún orden. No se realiza ningún ordenamiento a este nivel, y si lo necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza el ordenamiento alfabético. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. _Cualquier ordenamiento que encuentre en estas devoluciones de llamada es pura suerte. No confíe en él._ A medida que recorre toda la lista de archivos, puede recibir nombres de archivo duplicados.

Esta API y las devoluciones de llamada en sí mismas son capaces de informar errores. Antes de esta API, las devoluciones de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o si tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS en sí tenía un problema (error de disco o similar), no podía informarlo a la aplicación que lo llamaba; simplemente tendría que omitir elementos o dejar de enumerar directamente, y el llamador no sabría que perdió algunos datos en el camino.

Ahora, el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su devolución de llamada tiene control si desea que la enumeración se detenga antes. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su devolución de llamada.

distinto de cero en caso de éxito, cero en caso de fallo. Utilice PHYSFS_getLastErrorCode() para obtener el error específico. int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Añadir un archivo o directorio al camino de búsqueda. Si es un duplicado, el registro no se añade de nuevo, incluso si la función es exitosa. No puedes añadir el mismo archivo a dos diferentes puntos de montaje: el control de duplicado se realiza con el archivo y no con el punto de montaje.

Cuando montas un archivo, se añade a un sistema de archivos virtual... todos los archivos de todos los archivos montados se interpolan en un árbol de directorios único. Dos archivos montados en el mismo lugar (o un archivo con archivos que superponen un punto de montaje) pueden tener archivos superpuestos: en ese caso, el archivo más antiguo en la búsqueda de camino es seleccionado, y los otros archivos son inaccesibles para la aplicación. Esto permite usar archivos para reemplazar revisiones antiguas; puedes usar el mecanismo de montaje para colocar archivos en un punto específico en el árbol de archivos y evitar superposiciones; esto es útil para mods descargables que puedan dañar los datos del programa o sí mismos.

El punto de montaje no debe existir previamente al montaje, lo cual es diferente de lo que se espera en el concepto de montaje de Unix familiar. Además, más de un archivo puede ser montado en el mismo punto de montaje, o los puntos de montaje y los contenidos de los archivos pueden superponerse... el mecanismo de interpolación aún funciona.

Es permitido especificar un enlace simbólico hacia un archivo o directorio, independientemente del estado de physFS_permitSymbolicLinks(). Esta función solo maneja enlaces simbólicos dentro del directorio o archivo montado.

appendToPath noche para appendar a la búsqueda de camino, 0 para prependar.

void PHYSFS_permitSymbolicLinks(int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparenntly) el archivo al que apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas `open` y fallará si lo es. De lo contrario, el enlace podría sacarte de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si quieres asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sientas que hay un peligro específico al permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se verifican explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., nunca se verifican los enlaces simbólicos.

Ten en cuenta que PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlaces simbólicos se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para denegar enlaces.

Structure PHYSFS_Allocator

Structure for custom memory allocators.

typedef struct PHYSFS_Allocator {
    void *(*malloc)(size_t size);
    void (*free)(void *ptr);
    void *(*realloc)(void *ptr, size_t size);
} PHYSfs_allocator;

This structure is used to hook your own memory allocation routines into PhysicsFS. This is for advanced users only.

malloc
A pointer to a function that allocates a block of memory at least size bytes in length; the block is suitable for use by allocating functions described below. The space returned is suitably aligned to hold any data type. If the allocation fails, malloc returns NULL. If size is zero, the memory returned need not have unique identity but must be a valid pointer that can be passed to free().
free
A pointer to a function that causes the region of memory pointed to by ptr to be made available for future allocation. The pointer ptr must have been returned by a previous call to malloc or realloc. If ptr is NULL, no action is taken.
realloc
A pointer to a function that changes the size of the memory block pointed to by ptr to size bytes. The contents of the memory referred to *by the resulting pointer*, up to the lesser of the new and old sizes, remain unchanged. If the new size is larger than the old size, the value of the returned pointer, up to the old size, is undetermined. If the allocation fails, realloc returns NULL, and the original block is unaltered. The new pointer need not have the same value as the old pointer. If ptr is NULL, then the call is equivalent to malloc(size), for which its valid use is described above. If size is equal to zero, and ptr is not NULL, then the call is equivalent to free(ptr), and possibly returns a NULL pointer. The pointer returned is suitably aligned for any data type. If realloc is passed a ptr that was not returned from a prior call to malloc or realloc, or if ptr is not NULL and size is zero, the behavior is undefined.

PHYSFS_setBuffer()

Set the buffering behavior of a file handle.

When you open a file with PHYSFS_openRead() or PHYSFS_openWrite(), it's unbuffered by default. You can change this by calling PHYSFS_setBuffer(). The buffer size is in bytes. A buffer size of zero will disable buffering on an existing file handle, effectively freeing any buffer that it might have.

Buffering is done on a per-file basis. You must call this for every file handle you want buffered.

A size of zero will effectively turn off buffering and flush any pending writes.

Seeking, etc. transparently accounts for buffering.

You can resize an existing buffer by calling this function more than once on the same file. Setting the buffer size to zero will free an existing buffer.

Los manejadores de archivos de PhysicsFS no tienen búfer por defecto.

¡Por favor, compruebe el valor de retorno de esta función! Los fallos pueden incluir la imposibilidad de buscar hacia atrás en un archivo de solo lectura al eliminar el búfer, la imposibilidad de asignar el búfer y la imposibilidad de vaciar el búfer en el disco, entre otros problemas inesperados.

Parámetros

handle manejador devuelto por PHYSFS_open*().
bufsize tamaño, en bytes, del búfer a asignar.

Devuelve

distinto de cero si tiene éxito, cero en caso de error.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Establece un subdirectorio de un archivo como directorio raíz. Esto te permite acotar los archivos accesibles en un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/z.txt, montado en /a, si llamas a PHYSFS_setRoot("x.zip", "/y"), entonces la llamada PHYSFS_openRead("/a/z.txt") tendrá éxito.

Puedes cambiar la raíz de un archivo en cualquier momento, alterando el árbol de archivos interpolado (dependiendo de dónde cambien las rutas, un archivo diferente puede estar proporcionando varios archivos). Si estableces la raíz a NULL o "/", el archivo se tratará como si no se hubiera establecido ninguna raíz especial (como si el archivo se hubiera montado normalmente).

Cambiar la raíz solo afecta a las operaciones futuras sobre nombres de ruta; un archivo que se abrió desde una ruta que cambió debido a un setRoot no se verá afectado.

Establecer una nueva raíz no se limita a los archivos en la ruta de búsqueda; también puedes establecer una en el directorio de escritura, lo que podría ser útil si tienes archivos abiertos para escritura y por lo tanto no puedes cambiar el directorio de escritura en este momento.

No es un error establecer un subdirectorio que no existe como raíz de un archivo; sin embargo, en este caso no serán visibles ningún archivo. Si los directorios faltantes llegan a crearse (un mkdir al sistema de archivos físico, etc.), esto se reflejará en el árbol interpolado.

archive directorio/archivo sobre el cual cambiar la raíz.
subdir nuevo subdirectorio a establecer como raíz de este archivo.

distinto de cero en caso de éxito, cero en caso de fallo. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

NAME

PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64, PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64 - Convert and write an unsigned integer value in a specific endianness.

SYNOPSIS

#include <physfs.h>

int PHYSFS_writeUBE16(PHYSFS_File *file, PHYSFS_uint16 val);
int PHYSFS_writeUBE32(PHYSFS_File *file, PHYSFS_uint32 val);
int PHYSFS_writeUBE64(PHYSFS_File *file, PHYSFS_uint64 val);
int PHYSFS_writeULE16(PHYSFS_File *file, PHYSFS_uint16 val);
int PHYSFS_writeULE32(PHYSFS_File *file, PHYSFS_uint32 val);
int PHYSFS_writeULE64(PHYSFS_File *file, PHYSFS_uint64 val);

DESCRIPTION

These are convenience functions that convert an unsigned integer from the platform's native byte order to a specified endianness (big-endian or little-endian) and write it to a PHYSFS_File.

PHYSFS_writeUBE16() converts and writes an unsigned 16-bit big-endian value.

PHYSFS_writeUBE32() converts and writes an unsigned 32-bit big-endian value.

PHYSFS_writeUBE64() converts and writes an unsigned 64-bit big-endian value.

PHYSFS_writeULE16() converts and writes an unsigned 16-bit little-endian value.

PHYSFS_writeULE32() converts and writes an unsigned 32-bit little-endian value.

PHYSFS_writeULE64() converts and writes an unsigned 64-bit little-endian value.

PARAMETERS

file
A pointer to the PHYSFS_File structure to which the value will be written.
val
The unsigned integer value to convert and write.

RETURN VALUES

On success, these functions return a non-zero value. On failure, they return zero. If an error occurs, you can determine the specific error code by calling PHYSFS_getLastErrorCode().

WARNING

Note that on platforms lacking 64-bit support, `PHYSFS_uint64` might only be 32 bits. Be mindful of this limitation when using `PHYSFS_writeUBE64` and `PHYSFS_writeULE64`.
