Macro Documentation

#define PHYSFS_VERSION

This macro is defined to a long integer literal that represents the version of the library you compiled against. The value is structured as follows: `XXYYZZ`, where `XX` is the major version number, `YY` is the minor version number, and `ZZ` is the patchlevel.

For example, version 2.1.3 would be represented as `020103`. This macro is meant to be used for compile-time checks. You can check if the library you're linking against is new enough by doing something like:

#if PHYSFS_VERSION < 10200 /* Minimum version 1.2.0 */ #error "PhysicsFS library is too old!" #endif

Note that this macro represents the version of the library that your application was *compiled* against. It may not necessarily be the same version that is running at *runtime* if you dynamically linked the library. That runtime version can be determined with PHYSFS_getLinkedVersion().

Example

To check if the linked version of PhysicsFS is at least version 2.1.0:

#include <physfs.h>

int main() {
    PHYSFS_Version linkedVersion;
    PHYSFS_getLinkedVersion(&linkedVersion);

    if (linkedVersion.major < 2 ||
        (linkedVersion.major == 2 && linkedVersion.minor < 1)) {
        // Handle older version...
        fprintf(stderr, "Warning: PhysicsFS library version is older than expected (2.1.0).\n");
    }

    // ... proceed with application logic ...

    return 0;
}

This example demonstrates how to use PHYSFS_getLinkedVersion() to retrieve the version information and then compare the major and minor version numbers. The macro PHYSFS_VERSION can be used for compile-time checks against the version of the library you compiled against. This is determined by what header the compiler uses. Note that if you dynamically linked the library, you might have a slightly newer or older version at runtime. That version can be determined with PHYSFS_getLinkedVersion(), which, unlike PHYSFS_VERSION, is not a macro.

Parameters

x A pointer to a PHYSFS_Version struct to initialize.

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Function signature for callbacks that enumerate files.

Warning

As of PhysicsFS 2.1, Use PHYSFS_EnumerateCallback with PHYSFS_enumerate() instead; it gives you more control over the process.

These are used to report a list of directory entries to an original caller, one file/dir/symlink per callback. All strings are UTF-8 encoded. Functions should not try to modify or free any string's memory.

These callbacks are used, starting in PhysicsFS 1.1, as an alternative to functions that would return lists that need to be cleaned up with PHYSFS_freeList(). The callback means that the library doesn't need to allocate an entire list and all the strings up front.

Be aware that promised data ordering in the list versions are not necessarily so in the callback versions. Check the documentation on specific APIs, but strings may not be sorted as you expect and you might get duplicate strings.

enum PHYSFS_ErrorCode

Values that represent specific causes of failure. Most of the time, you should only concern yourself with whether a given operation failed or not, but there may be occasions where you plan to handle a specific failure case gracefully, so we provide specific error codes.

Most of these errors are a little vague, and most aren't things you can fix...if there's a permission error, for example, all you can really do is pass that information on to the user and let them figure out how to handle it. In most these cases, your program should only care that it failed to accomplish its goals, and not care specifically why.

int PHYSFS_deinit(void)

Desinicializa la librería PhysicsFS. Cierra cualquier archivo abierto con PhysicsFS, limpia las rutas de búsqueda/escritura, libera la memoria e invalida todos tus manejadores de archivo.

Nota: Esta llamada puede fallar si hay un archivo abierto para escritura que no se cierra (por ejemplo, el sistema operativo estaba almacenando en búfer escrituras en un sistema de archivos de red, y el servidor de archivos ha colapsado, o un disco duro ha fallado, etc.). Es usualmente mejor cerrar todos los manejadores de escritura tú mismo antes de llamar a esta función, para manejar un fallo específico de forma elegante.

Una vez desinicializada correctamente, PHYSFS_init() puede llamarse nuevamente para reiniciar el subsistema. Todos los estados por defecto de la API se restauran en este punto, excepto cualquier asignador personalizado que hayas especificado, que sobrevive entre inicializaciones.

Retorno

Distinto de cero en caso de éxito, cero en caso de error. Los detalles del error se pueden obtener de PHYSFS_getLastError(). Si hay un fallo, el estado de PhysFS es indefinido y probablemente está mal construido.

int PHYSFS_delete(const char *filename)

Elimina un archivo o directorio. (filename) se especifica en notación independiente de plataforma en relación al directorio de escritura.

Un directorio debe estar vacío antes de poder eliminarlo.

Eliminar un enlace simbólico eliminará el enlace, no lo que apunta, independientemente de si se permiten los enlaces simbólicos o no.

Por lo tanto, si el directorio de escritura está configurado como "C:\mygame\writedir" y se llama a PHYSFS_delete("downloads/maps/level1.map"), se eliminará el archivo "C:\mygame\writedir\downloads\maps\level1.map" del sistema de archivos físico, si existe y el sistema operativo permite la eliminación.

Nota: En sistemas Unix, la eliminación de un archivo puede ser exitosa, pero el archivo real no se eliminará hasta que todos los procesos que tengan un archivo abierto a él (incluyendo tu programa) cierren sus manejadores.

La mayor parte del tiempo, los bits que componen el archivo aún existen, pero están disponibles para ser escritos sobre en un futuro. No considere esto como un método de seguridad.

int PHYSFS_enumerate (const char *dir, PHYSFS_EnumerateCallback c, void *d)

Get a file listing of a search path's directory, using an application-defined callback, with errors reported. Internally, PHYSFS_enumerateFiles() just calls this function and then builds a list before returning to the application, so functionality is identical except for how the information is represented to the application.

Unlike PHYSFS_enumerateFiles(), this function does not return an array. Rather, it calls a function specified by the application once per element of the search path:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // give me more data, please.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

Items sent to the callback are not guaranteed to be in any order whatsoever. There is no sorting done at this level, and if you need that, you should probably use PHYSFS_enumerateFiles() instead, which guarantees alphabetical sorting. This form reports whatever is discovered in each archive before moving on to the next. Even within one archive, we can't guarantee what order it will discover data. Any sorting you find in these callbacks is just pure luck. Do not rely on it. As this walks the entire list of archives, you may receive duplicate filenames.

This API and the callbacks themselves are capable of reporting errors. Prior to this API, callbacks had to accept every enumerated item, even if they were only looking for a specific thing and wanted to stop after that, or had a serious error and couldn't alert anyone. Furthermore, if PhysicsFS itself had a problem (disk error or whatnot), it couldn't report it to the calling app, it would just have to skip items or stop enumerating outright, and the caller wouldn't know it had lost some data along the way.

Now the caller can be sure it got a complete data set, and its callback has control if it wants enumeration to stop early. See the documentation for PHYSFS_EnumerateCallback for details on how your callback should behave.

dir Directory, in platform-independent notation, to enumerate.
c Callback function to notify about search path elements.
d Application-defined data passed to callback. Can be NULL.

Returns

non-zero on success, zero on failure. Use PHYSFS_getLastErrorCode() to obtain the specific error. If the callback returns PHYSFS_ENUM_STOP to stop early, this will be considered success. int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Añadir un archivo o directorio a la ruta de búsqueda. Si es un duplicado, la entrada no se añade de nuevo, aunque la función tenga éxito. No puede añadir el mismo archivo a dos puntos de montaje diferentes: la comprobación de duplicados se realiza contra el archivo y no contra el punto de montaje.

Cuando monta un archivo, se añade a un sistema de archivos virtual... todos los archivos de todos los archivos se interpolan en un único árbol de archivos jerárquico. Dos archivos montados en el mismo lugar (o un archivo con archivos que se superponen a otro punto de montaje) pueden tener archivos superpuestos: en tal caso, se selecciona el archivo que aparece antes en la ruta de búsqueda, y los otros archivos son inaccesibles para la aplicación. Esto permite que los archivos se utilicen para sobrescribir revisiones anteriores; puede usar el mecanismo de montaje para colocar archivos en un punto específico del árbol de archivos y evitar la superposición; esto es útil para mods descargables que podrían pisar datos de la aplicación o entre sí, por ejemplo.

El punto de montaje no necesita existir antes de montarlo, lo que es diferente de lo que aquellos familiarizados con el concepto de "montaje" de Unix pueden esperar. Además, se pueden montar varios archivos en el mismo punto de montaje, o los puntos de montaje y el contenido de los archivos pueden superponerse... el mecanismo de interpolación sigue funcionando como de costumbre.

Se permite especificar un enlace simbólico a un archivo o directorio aquí, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esa función solo se ocupa de los enlaces simbólicos dentro del directorio o archivo montado.

appendToPath distinto de cero para añadir a la ruta de búsqueda, cero para anteponer.

void PHYSFS_permitSymbolicLinks(int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparente) el archivo al que apunta.

Por defecto, PhysicsFS comprobará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarte fuera de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para poner en cuarentena el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sientas que hay un peligro específico al permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se comprueban explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., nunca se comprueban los enlaces simbólicos.

Ten en cuenta que PHYSFS_stat() siempre comprobará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlaces simbólicos se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para denegar enlaces.

The write dir will be set to the pref dir returned by

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte un string Latin1 en un string UTF-8. Los strings Latin1 son de 8 bits por carácter: una popular codificación "high ASCII".

Para asegurar que el buffer de destino sea lo suficientemente grande para la conversión, por favor, asigna un buffer que sea el doble del tamaño del buffer de origen. UTF-8 expande los códigos Latin1 mayores que 127 de 1 a 2 bytes, así que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el buffer de destino serán truncadas, pero siempre terminarán en nulo y nunca tendrán una secuencia incompleta de UTF-8 al final. Si el tamaño del buffer es 0, esta función no hará nada.

Nota: No ofrecemos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar muchos códigos Unicode. Es una codificación antigua; deberías estar convirtiendo siempre desde ella.

Parámetros

src Cadena de origen terminada en nulo en formato Latin1.

Comparación insensible a mayúsculas y minúsculas de dos cadenas UTF-8. Este es un reemplazo para strcasecmp/stricmp que espera que ambas cadenas estén en codificación UTF-8. Realizará un "plegado de mayúsculas" para decidir si los códigos Unicode en las cadenas coinciden.

Si ambas cadenas son exclusivamente de caracteres ASCII bajos, esto hará lo correcto, ya que también es válido UTF-8. Si hay algún carácter ASCII alto, ¡no hará lo que esperas!

Informará qué cadena es "mayor que" la otra, pero ten en cuenta que esto no significa necesariamente nada: 'a' puede ser "menor que" 'b', pero un kuten japonés no tiene ninguna relación alfabética significativa con una lambda griega, pero ser capaz de asignar un "valor" fiable hace que los algoritmos de ordenación sean posibles, si no del todo sensatos. La mayoría de los casos deberían tratar el valor de retorno como "igual" o "no igual".

Al igual que stricmp, esto espera que ambas cadenas terminen en NULL.

Parámetros

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Devuelve

-1 si str1 es "menor que" str2, 1 si es "mayor que", 0 si son iguales.

Warning

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. Windows releases before 2000 used TCHAR, but only handled UCS-2. UTF-16 is UCS-2, except for the characters that are 4 bytes, which aren't representable in UCS-2 at all anyhow. If you aren't sure, you should be using UTF-16 at this point on Windows.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UTF-16 always uses two to four, so an entirely low-ASCII string will double in size! The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

dst Buffer to store converted UTF-16 string.
