DESCRIPTION

The PhysicsFS library provides a platform-independent API for accessing files in archives. It can read and write files from archives, directories, and even CD-ROMs.

PhysicsFS provides byte-swapping functions for various integer types. These functions are useful for reading and writing files in specific endianness formats, such as little-endian or big-endian.

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para callbacks que enumeran archivos. Advertencia A partir de PhysicsFS 2.1, utiliza PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso. Estos se utilizan para informar a un llamador original una lista de entradas de directorio, un archivo/directorio/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena. Estos callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que necesitan ser limpiadas con PHYSFS_freeList(). El callback significa que la biblioteca no necesita asignar una lista completa y todas las cadenas por adelantado. Ten en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente así en las versiones de callback. Consulta la documentación de las API específicas, pero es posible que las cadenas no estén ordenadas como esperas y que obtengas cadenas duplicadas. int PHYSFS_registerArchiver (PHYSFS_Archiver * archiver)

Registra un nuevo controlador de archivos. PhysicsFS soporta archivos comprimidos (como ZIP, RAR, etc.) además de archivos normales. Para apoyar un nuevo formato de archivo, debes crear una estructura PHYSFS_Archiver que describa las operaciones para ese formato y luego registrarla con esta función. Si múltiples controladores pueden manejar la misma extensión, el último que se registró tendrá prioridad.

Note: Normalmente no necesitas llamar a esto directamente. PhysicsFS proporciona implementaciones predeterminadas para formatos comunes. Sin embargo, si estás creando tu propio formato de archivo o necesitas controlar qué controlador se usa para una extensión determinada, esta función es para ti.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio de la ruta de búsqueda, utilizando una función de callback definida por la aplicación, con informe de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego construye una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve un array. En cambio, llama a una función especificada por la aplicación una vez por cada elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

No se garantiza que los elementos enviados a la función de callback estén en ningún orden particular. No se realiza ninguna ordenación a este nivel, y si necesitas eso, probablemente deberías usar PHYSFS_enumerateFiles() en su lugar, que garantiza la ordenación alfabética. Esta forma reporta lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un mismo archivo, no podemos garantizar el orden en que descubrirá los datos. Cualquier ordenación que encuentres en estas callbacks es pura suerte. No confíes en ella. A medida que recorre la lista completa de archivos, puedes recibir nombres de archivo duplicados.

Esta API y las propias callbacks son capaces de reportar errores. Antes de esta API, las callbacks tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían parar después de encontrarlo, o si tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS tenía un problema (error de disco o similar), no podía reportarlo a la aplicación que llamaba, solo tenía que omitir elementos o dejar de enumerar, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su callback tiene control si desea que la enumeración se detenga temprano. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su callback.

Parameters

dir Directorio, en notación independiente de la plataforma, a enumerar.
c Función de callback para notificar sobre los elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la callback. Puede ser NULL.

Returns

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si la callback devuelve PHYSFS_ENUM_STOP para detenerse temprano, esto se considerará un éxito. Las callbacks que devuelvan PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezcan el código de error en PHYSFS_ERR_APP_CALLBACK.

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);

char ** PHYSFS_getCdRomDirs (void )

Obtiene una matriz de rutas a las unidades de CD-ROM disponibles. Los directorios devueltos son dependientes de la plataforma ("D:\" en Win32, "/cdrom" o similar en Unix). Solo se devuelven directorios si hay un disco listo y accesible en la unidad. Por lo tanto, si tienes dos unidades (D: y E:), y solo E: tiene un disco insertado, eso es todo lo que obtienes. Si el usuario inserta un disco en D: y vuelves a llamar a esta función, obtendrás ambas unidades. Si, en una máquina Unix, el usuario desmonta un disco y lo vuelve a montar en otro lugar, la próxima llamada a esta función reflejará ese cambio. Esta función se refiere a medios de "CD-ROM", pero en realidad significa "medios de disco insertados", como DVD-ROM, HD-DVD, CDRW y discos Blu-Ray. Busca sistemas de archivos y, por lo tanto, no informará un CD de audio, a menos que haya una pista de sistema de archivos montada en él. El valor devuelto es una matriz de cadenas, con una entrada NULL para indicar el final de la lista: ``` char **cds = PHYSFS_getCdRomDirs(); char **i; for (i = cds; *i != NULL; i++) printf("directorio de cdrom [%s] está disponible.\n", *i); ``` PHYSFS_freeList(cds);

Esta llamada puede bloquearse mientras las unidades se activan. Tenlo en cuenta.

Cuando hayas terminado con la información devuelta, puedes liberar los recursos llamando a PHYSFS_freeList() con el puntero devuelto.

Devuelve

Matriz terminada en NULL de cadenas terminadas en NULL.

Obtiene una descripción legible por humanos para un código de error dado. Obtiene una cadena estática, en formato UTF-8, que representa una descripción en inglés de un código de error dado.

const char * PHYSFS_getLastError (void )

Obtiene información de error legible por humanos.

Obsoleto

Usa PHYSFS_getLastErrorCode() y PHYSFS_getErrorByCode() en su lugar.

Advertencia

A partir de PhysicsFS 2.1, esta función ha sido degradada. Antes de PhysicsFS 2.1, esta función era la única forma de obtener detalles de error más allá del valor de retorno básico de una función dada. Se suponía que era una cadena legible por humanos en uno de varios idiomas, y no era útil para el análisis de aplicaciones. Esto era un problema, porque el desarrollador y no el usuario elegía el idioma en tiempo de compilación, y los mantenedores de PhysicsFS tenían que mantener (mal) una cantidad significativa de trabajo de localización. La aplicación no podía analizar las cadenas, incluso si dependían de un idioma específico, ya que algunas se generaban dinámicamente. En la versión 2.1 y posteriores, esto siempre devuelve una cadena estática en inglés; puedes usarla como cadena clave para tus propias localizaciones si lo deseas, ya que prometemos no cambiar las cadenas de error existentes. Además, si tu aplicación quiere examinar errores específicos, ahora ofrecemos una mejor opción: usa PHYSFS_getLastErrorCode() en su lugar.

Obtiene el último mensaje de error de PhysicsFS como una cadena legible por humanos y terminada en NULL. Devolverá NULL si no ha habido ningún error desde la última llamada a esta función. El puntero devuelto por esta llamada apunta a un búfer interno. Cada hilo tiene un estado de error único asociado, pero cada vez que se establece un nuevo mensaje de error, se sobrescribirá el anterior asociado con ese hilo. Es seguro llamar a esta función en cualquier momento, incluso antes de PHYSFS_init().

PHYSFS_getLastError() y PHYSFS_getLastErrorCode() ambos restablecen el mismo estado de error específico del hilo. Llamar a uno anulará los datos del otro. Si necesitas ambos, llama a PHYSFS_getLastErrorCode(), luego pasa ese valor a PHYSFS_getErrorByCode().

A partir de PhysicsFS 2.1, esta función solo presenta texto en inglés, pero las cadenas son estáticas, por lo que puedes usarlas como claves en tu propio diccionario de localización. Estas cadenas están destinadas a ser pasadas directamente al usuario.

En general, las aplicaciones solo deberían preocuparse por si una función dada falló; sin embargo, si tu código requiere más detalles, deberías usar PHYSFS_getLastErrorCode() en lugar de esta función.

Devuelve

Cadena de solo lectura del último mensaje de error.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, la apertura de dicho enlace abrirá (de forma transparente) el archivo al que apunta.

Por defecto, PhysicsFS comprobará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría sacarte de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sientas que hay un peligro específico al permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se comprueban explícitamente al tratar con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., nunca se comprueban los enlaces simbólicos.

Ten en cuenta que PHYSFS_stat() siempre comprobará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlaces simbólicos se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para denegar el enlace.

Establece un subdirectorio de un archivo como directorio raíz. Esto le permite delimitar los archivos accesibles en un archivo específico.
