PHYSFS_enumerate

Este es lo mismo que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, a menos que devuelva un resultado de callback: si estás buscando algo específico, una vez encontrado, puedes decir a PhysicsFS que deje de enumerar. Esto se usa con PHYSFS_enumerate(), que esperamos que hayamos obtenido correctamente. :)

Parámetros

data puntero a un PHYSFS_Version para inicializar.
origdir cadena que contiene la ruta completa, en notación independiente del sistema operativo, del directorio que contiene este archivo. En la mayoría de los casos, es el directorio en el que solicitaste la enumeración, pasado en el callback para tu conveniencia.
fname el nombre del archivo que se está enumerando. Puede no estar en orden alfabético comparado con otros callbacks que hayan sido llamados, y no contendrá la ruta completa. Puedes recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

Retorna

Un valor de PHYSFS_EnumerateCallbackResult. Todos otros valores son (actualmente) undefined; no los uses.

typedef void(* physFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Signature de función para callbacks que enumeran archivos.

Advertencia

Desde PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate() para tener más control sobre el proceso.

Estos se utilizan para reportar una lista de entradas de directorio a un llamador original, una entrada por callback. Todos los strings son codificados en UTF-8. Las funciones no deben intentar modificar o liberar la memoria de cualquier string.

Estos callbacks se utilizan, desde PhysicsFS 1.1, como alternativa a funciones que devuelven listas que deben ser limpiadas con PHYSFS_freeList(). El callback significa que la librería no necesita alojar un lista completa y todas las strings por adelante.

Tenga en cuenta que el orden prometido en las versiones de lista no necesariamente se cumple en las versiones de callback. Verifique la documentación de APIs específicas, pero los strings no necesariamente estarán ordenados como lo esperado y podrían obtener strings duplicados.

Parámetros

data puntero a datos definidos por el usuario, pasado a través de la API que finalmente llamó al callback.
origdir cadena que contiene la ruta completa, en notación independiente del sistema operativo, del directorio que contiene este archivo. En la mayoría de los casos, es el directorio en el que solicitaste la enumeración, pasado en el callback para tu conveniencia.
fname el nombre del archivo que se está enumerando. Puede no estar en orden alfabético comparado con otros callbacks que hayan sido llamados, y no contendrá la ruta completa. Puedes recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

enum PHYSFS_ErrorCode

Valores que representan causas específicas de fallo. En la mayoría de los casos, debes preocuparte solo por si una operación falló o no, pero hay ocasiones donde planeas manejar un caso específico de fallo de manera gracieza, así que ofrecemos códigos específicos de error.

Más de estos errores son un poco vagos, y no siempre son cosas que puedas corregir... si hay un error de permisos, por ejemplo, lo único que puedes hacer es pasar esa información al usuario y dejar que ellos se encarguen de cómo manejarlo. En la mayoría de estos casos, tu programa solo debe preocuparse de que falló al lograr sus metas, y no importar específicamente por qué.

int PHYSFS_caseFold (const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Dobla" un punto de código Unicode a un equivalente en minúscula. (Esto es para un uso limitado y muy específico. Si no ves inmediatamente una necesidad para ello, probablemente puedas ignorarlo para siempre).

Esto convertirá un punto de código Unicode en su equivalente en minúscula. Los puntos de código inválidos y los puntos de código sin equivalente en minúscula se devolverán sin convertir.

¡Ten en cuenta que podrías obtener varios puntos de código como resultado! Por ejemplo, el símbolo Eszett alemán se doblará en dos puntos de código latinos en minúscula 's'. La teoría es que si doblas dos cadenas, una con Eszett y otra con "SS", coincidirán.

Advertencia

Cualquiera que haya estudiado Unicode conoce el problema de la "i turca". Esta API no lo maneja. Asume que esta única letra en todo Unicode definitivamente se doblará de forma incorrecta. Si no sabes de qué se trata, probablemente puedas ignorar este problema para la mayor parte del planeta, pero la perfección es imposible.

Advertencia

Get the last error code from the PhysicsFS library. This is useful for determining the exact nature of a failure when a function returns an error status. The error code is reset by any function that can fail, so you should call this function immediately after detecting a failure.

PhysicsFS maintains an error state per thread. This means that calling PHYSFS_getLastErrorCode() will not affect the error state of other threads, and vice versa.

If you need to preserve the error state across multiple calls that might reset it, you can call PHYSFS_getLastErrorCode(), save the value, and then pass it to PHYSFS_getErrorByCode() to retrieve the error string. Note that calling PHYSFS_getLastErrorCode() will reset the current thread's error state to PHYSFS_ERR_OK. If you need to preserve the error code *and* its associated string, call PHYSFS_getLastError() instead.

Normally, applications should only care whether a function failed, not why. However, if you need more specific information, you can use this function to retrieve it, especially if you anticipate and plan to handle specific errors. For most file system operations, it's best to report the error to the user and let them handle it. In such cases, you might prefer using PHYSFS_getErrorByCode().

An enumeration value representing the last reported error.

Especifica el nombre de su organización (si no es una organización real, su nombre o un dominio de Internet que posea podría servir) y el nombre de su aplicación. Estos deben ser nombres propios.

Tanto las cadenas (org) como (app) pueden convertirse en parte del nombre de un directorio, así que siga estas reglas:

  • Intente usar la misma cadena de organización (incluida la distinción entre mayúsculas y minúsculas) para todas sus aplicaciones que utilicen esta función.
  • Siempre use una cadena de aplicación única para cada una, y asegúrese de que nunca cambie para una aplicación una vez que haya decidido sobre ella.
  • Los caracteres Unicode son legales, siempre que estén codificados en UTF-8, pero...
  • ...solo use letras, números y espacios. Evite la puntuación como "Nombre del Juego 2: ¡La Venganza del Malo!" ... "Nombre del Juego 2" es suficiente.

El puntero devuelto por esta función permanece válido hasta que vuelva a llamar a esta función, o llame a PHYSFS_deinit(). Sin embargo, esta no es necesariamente una llamada rápida, por lo que debe llamarla una vez al inicio y copiar la cadena si la necesita.

Debería asumir que la ruta devuelta por esta función es el único lugar seguro para escribir archivos (y que PHYSFS_getUserDir() y PHYSFS_getBaseDir(), aunque puedan ser escribibles, o incluso padres de la ruta devuelta, no son donde debe escribir cosas).

El nombre de archivo devuelto será el elemento de la ruta de búsqueda donde se encontró el archivo, que puede ser un directorio o un archivo. int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Añade un directorio o archivo a la ruta de búsqueda. Si es un duplicado, la entrada no se añade de nuevo, incluso si la función tiene éxito. No puedes añadir el mismo archivo a dos puntos de montaje diferentes: la comprobación de duplicados se realiza contra el archivo y no contra el punto de montaje.

Al montar un directorio, se añade a un sistema de archivos virtual... todos los archivos de todos los directorios montados se interpolan en un único árbol jerárquico. Dos directorios montados en el mismo lugar (o un directorio con archivos que se superponen a un punto de montaje) pueden tener archivos que se superponen: en ese caso, se selecciona el archivo más cercano en la ruta de búsqueda, y los otros archivos no son accesibles por la aplicación. Esto permite usar directorios para reemplazar revisiones anteriores; puedes usar el mecanismo de montaje para colocar directorios en un punto específico del árbol de archivos y evitar la superposición; esto es útil para modos descargados que pueden superponerse a los datos de la aplicación o entre sí, por ejemplo.

Se permite especificar un enlace simbólico a un directorio o archivo, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esta función solo se enfoca en enlaces simbólicos dentro del directorio o archivo montado.

Parámetros

newDir directorio o archivo a añadir a la ruta, en notación dependiente del sistema.
mountPoint ubicación en el árbol interpolado donde se montará este directorio, en notación independiente del sistema. NULL o "" es equivalente a "/".
appendToPath distinto de cero para añadir al final de la ruta de búsqueda, cero para añadir al principio.

Devuelve

Distinto de cero si se añadió a la ruta, cero en caso de error (archivos inválidos, directorios faltantes, etc.). Usa PHYSFS_getLastErrorCode() para obtener el error específico.

Adds an archive built on a PHYSFS_Io to the search path.

Warning

Unless you have some very specific low-level requirements, you should use PHYSFS_mount() instead of this function.

This function works exactly like PHYSFS_mount(), but it accepts a PHYSFS_Io instead of a path name. Behind the scenes, PHYSFS_mount() calls this function with a PHYSFS_Io based on the physical file system.

(newDir) must be a unique string to identify this archive. newDir A name representing this archive.
mountPoint The location in the interpolated tree where this archive is "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
