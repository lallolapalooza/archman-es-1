typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para callbacks que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso.

Estos se utilizan para informar una lista de entradas de directorio a un llamante original, un archivo/directorio/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estos callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que necesitarían ser liberadas con PHYSFS_freeList(). El callback significa que la biblioteca no necesita asignar una lista completa y todas las cadenas por adelantado.

Ten en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente así en las versiones de callback. Consulta la documentación de APIs específicas, pero es posible que las cadenas no estén ordenadas como esperas y que obtengas cadenas duplicadas.

fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otros callbacks que se hayan disparado, y no contendrá la ruta completa. Puedes recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

enum PHYSFS_ErrorCode

Valores que representan causas específicas de fallo. La mayoría de las veces, solo deberías preocuparte por si una operación dada falló o no, pero puede haber ocasiones en las que planees manejar un caso de fallo específico con gracia, por lo que proporcionamos códigos de error específicos.

La mayoría de estos errores son un poco vagos, y la mayoría no son cosas que puedas arreglar... si hay un error de permisos, por ejemplo, todo lo que realmente puedes hacer es pasar esa información al usuario y dejar que descubra cómo manejarlo. En la mayoría de estos casos, tu programa solo debería preocuparse de que no logró sus objetivos, y no preocuparse específicamente por qué.

int PHYSFS_mount(const char *newDir, const char *mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

newDir directory or archive to add to the path, in platform-dependent notation.
mountPoint Location in the interpolated tree that this archive will be "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
appendToPath nonzero to append to search path, zero to prepend.

Returns

nonzero if added to path, zero on failure (bogus archive, dir missing, etc). Use PHYSFS_getLastErrorCode() to obtain the specific error.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir dicho enlace abrirá (transparente) el archivo al que apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarlo fuera de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si desea asumir ese riesgo, llame a esta función con un parámetro distinto de cero. Tenga en cuenta que esto es más para poner en cuarentena el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En términos generales, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sienta que hay un peligro específico en permitirlos, debe permitirlos.

Los enlaces simbólicos solo se verifican explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar sus rutas de búsqueda y escritura, etc., los enlaces simbólicos nunca se verifican.

Tenga en cuenta que PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlace simbólico se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para denegar la vinculación.

UTF-8 nunca usa más de 32 bits por carácter, por lo que aunque puede reducir el tamaño de una cadena UTF-16, también puede expandirla.

Las cadenas que no quepan en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

int PHYSFS_utf8stricmp (const char * str1, const char * str2)

Comparación insensible a mayúsculas y minúsculas de dos cadenas UTF-8. Este es un reemplazo de strcasecmp/stricmp que espera que ambas cadenas estén en codificación UTF-8. Realizará un "plegado de mayúsculas" para decidir si los puntos de código Unicode en las cadenas coinciden.

Si ambas cadenas son exclusivamente caracteres ASCII de bajo nivel, esto hará lo correcto, ya que también es UTF-8 válido. Si hay algún carácter ASCII superior, ¡esto no hará lo que esperas!

Informará cuál cadena es "mayor que" la otra, pero ten en cuenta que esto no significa necesariamente nada: 'a' puede ser "menor que" 'b', pero un kuten japonés no tiene una relación alfabética significativa con una lambda griega, pero poder asignar un "valor" confiable hace posibles los algoritmos de ordenación, aunque no sean del todo sensatos. La mayoría de los casos deberían tratar el valor de retorno como "igual" o "no igual".

Al igual que stricmp, esto espera que ambas cadenas estén terminadas en NULL.

Parámetros

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Devuelve

-1 si str1 es "menor que" str2, 1 si "mayor que", 0 si son iguales.

NAME

PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64, PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64 - Convert and write unsigned integer values in different endiannesses.

SYNOPSIS

#include <physfs.h>

int PHYSFS_writeUBE16 (PHYSFS_File * file, PHYSFS_uint16 val);
int PHYSFS_writeUBE32 (PHYSFS_File * file, PHYSFS_uint32 val);
int PHYSFS_writeUBE64 (PHYSFS_File * file, PHYSFS_uint64 val);
int PHYSFS_writeULE16 (PHYSFS_File * file, PHYSFS_uint16 val);
int PHYSFS_writeULE32 (PHYSFS_File * file, PHYSFS_uint32 val);
int PHYSFS_writeULE64 (PHYSFS_File * file, PHYSFS_uint64 val);

Detailed Description

These functions are convenience wrappers around PHYSFS_write() that convert an unsigned integer from the platform's native byte order to either big-endian or little-endian, and then write the result to a file.

PHYSFS_writeUBE16, PHYSFS_writeUBE32, and PHYSFS_writeUBE64 write the value in big-endian format.

PHYSFS_writeULE16, PHYSFS_writeULE32, and PHYSFS_writeULE64 write the value in little-endian format.

These functions are useful for writing data files that need to be read by programs on different platforms, or by programs that expect specific byte orders.

If you are writing a file that will only ever be read by programs on the same platform, you may not need these functions; you can just use PHYSFS_write() directly, assuming the file format doesn't specify endianness.

Warning: On platforms that lack 64-bit integer support, PHYSFS_uint64 is only 32 bits. The functions PHYSFS_writeUBE64() and PHYSFS_writeULE64() will still work, but they will only write 32 bits of data.
