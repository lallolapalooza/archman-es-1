Descripción detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados. No lo necesitas a menos que realmente sepas lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se limitaban a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivos de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que PhysicsFS no proporciona directamente: quizás algún formato propietario que solo tu aplicación necesita entender.

Internamente, todo el soporte de archivo incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver es el código fuente de PhysicsFS.

Un archivador se agrega al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser manejado con tu archivador, se le dará control según corresponda.

Estos métodos tratan con manejadores de directorios. Tienes una instancia de tu archivador, y genera un manejador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el propio archivador; la aplicación puede usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para comprobar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en ello.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de regresar. PhysicsFS pasará estos errores de vuelta a la aplicación sin modificaciones en la mayoría de los casos.

Seguridad de hilos: Las implementaciones de PHYSFS_Archiver no están garantizadas de ser seguras para hilos en sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador determinado dentro de la biblioteca, pero no promete que el uso del mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo se maneja por ti siempre que el PHYSFS_Io que devuelves de PHYSFS_open* no cambie ningún estado de tu Archivador, ya que el PHYSFS_Io no estará tan agresivamente protegido.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluido el PHYSFS_Io original y el propio (opaque), si corresponde. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, por lo que puedes desecharla al regresar de la devolución de llamada. (dirname) está en notación independiente de la plataforma. Si tienes un fallo, llama a PHYSFS_SetErrorCode() con el código que parezca apropiado y devuelve PHYSFS_ENUM_ERROR. Si la devolución de llamada devuelve PHYSFS_ENUM_ERROR, por favor llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y devuelve también PHYSFS_ENUM_ERROR. No llames a la devolución de llamada de nuevo bajo ninguna circunstancia. Si la devolución de llamada devuelve PHYSFS_ENUM_STOP, deja de enumerar y devuelve también PHYSFS_ENUM_STOP. No llames a la devolución de llamada de nuevo bajo ninguna circunstancia. No establezcas un código de error en este caso. Las devoluciones de llamada solo deben devolver un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene un comportamiento indefinido. Siempre que la devolución de llamada haya devuelto PHYSFS_ENUM_OK y no hayas experimentado ningún error propio, sigue enumerando hasta que hayas terminado y luego devuelve PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate devuelve cero o no cero (éxito o fallo), ¡así que ten en cuenta que este puntero de función devuelve valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Se utiliza para identificar tu archivo y se devuelve en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivo. Si la aplicación intenta crear múltiples directorios, PhysicsFS los dividirá en múltiples llamadas antes de pasarlas a tu controlador. Si el archivo es de solo lectura, esta operación debería fallar. Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivador para añadir. Si el archivo no existe, debe crearse. La posición de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo, y llama a PHYSFS_setErrorCode(). Devuelve no-NULL en caso de éxito. El puntero devuelto se pasará como el parámetro "opaque" para futuras llamadas de archivo.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Abrir un archivo en este archivero para lectura. El nombre del archivo, (fnm), está en notación independiente del sistema operativo. Fallar si el archivo no existe. Devuelve NULL en caso de fallo, y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto será pasado como el parámetro opaque para llamadas posteriores a funciones de archivo.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Abrir un archivo en este archivero para escritura. Si el archivo no existe, debe crearlo. Si existe, debe truncar a cero bytes. El desplazamiento de escritura debe ser el inicio del archivo. Si el archivero es solo lectura, esta operación debe fallar. El nombre del archivo está en notación independiente del sistema operativo. Devuelve NULL en caso de fallo, y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto será pasado como el parámetro opaque para llamadas posteriores a funciones de archivo.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Eliminar un archivo o directorio en este archivero. Esta misma llamada se usa para archivos y directorios; no hay una llamada separada de rmdir. Los directorios solo se pueden eliminar si están vacíos. Si el archivero es solo lectura, esta operación debe fallar.

Devolver no cero en caso de éxito, cero en caso de fallo. El nombre del archivo está en notación independiente del sistema operativo. En caso de fallo, llama a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtener metadatos básicos de un archivo. En caso de éxito, llenarán todos los campos en (stat) con valores por defecto razonables para los campos aplicables al archivero. Devolver no cero en caso de éxito, cero en caso de fallo. El nombre del archivo está en notación independiente del sistema operativo. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Información de compatibilidad binaria. Esta debe establecerse a cero en este momento. Las futuras versiones de este estructura incrementarán este campo, así que sabremos qué implementaciones soportan. Lo probable es que mantengamos soportar versiones antiguas mientras ofrecemos nuevos funcionalidades.
