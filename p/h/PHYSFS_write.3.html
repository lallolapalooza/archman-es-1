int PHYSFS_caseFold(const PHYSFS_uint32 from, PHYSFS_uint32 *to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_deinit(void )

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete(const char *filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Agrega un archivo o directorio a la ruta de búsqueda. Si es un duplicado, la entrada no se agrega de nuevo, aunque la función tenga éxito. No puede agregar el mismo archivo a dos puntos de montaje diferentes: la verificación de duplicados se realiza contra el archivo y no contra el punto de montaje.

Cuando monta un archivo, se agrega a un sistema de archivos virtual... todos los archivos en todos los archivos se interpolan en un solo árbol de archivos jerárquico. Dos archivos montados en el mismo lugar (o un archivo con archivos que se superponen a otro punto de montaje) pueden tener archivos superpuestos: en tal caso, se selecciona el archivo anterior en la ruta de búsqueda, y los otros archivos son inaccesibles para la aplicación. Esto permite que los archivos se utilicen para reemplazar revisiones anteriores; puede usar el mecanismo de montaje para colocar archivos en un punto específico del árbol de archivos y evitar superposiciones; esto es útil para mods descargables que podrían pisotear los datos de la aplicación o entre sí, por ejemplo.

El punto de montaje no necesita existir antes de montarlo, lo que es diferente de lo que los familiarizados con el concepto de "montaje" de Unix pueden esperar. Además, se pueden montar más de un archivo en el mismo punto de montaje, o los puntos de montaje y los contenidos de los archivos pueden superponerse... el mecanismo de interpolación aún funciona como de costumbre.

Se permite especificar un enlace simbólico a un archivo o directorio aquí, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esa función solo trata con enlaces simbólicos dentro del directorio o archivo montado.

Parámetros

newDir directorio o archivo a agregar a la ruta, en notación dependiente de la plataforma.
mountPoint Ubicación en el árbol interpolado donde este archivo se "montará", en notación independiente de la plataforma. NULL o "" es equivalente a "/".
appendToPath distinto de cero para agregar a la ruta de búsqueda, cero para agregar al principio.

Devoluciones

distinto de cero si se agregó a la ruta, cero en caso de falla (archivo inválido, directorio faltante, etc.). Use PHYSFS_getLastErrorCode() para obtener el error específico.

¡Los archivos dentro de archivos pueden ser muy lentos! Si bien un PHYSFS_File puede buscar incluso cuando los datos están comprimidos, puede hacerlo rebobinando al principio y descomprimiendo todo antes del punto de búsqueda. El uso normal de archivos puede realizar muchas búsquedas en segundo plano. Como tal, puede encontrar que el uso normal de archivos es extremadamente doloroso si se monta de esta manera. Planifique en consecuencia: si, por ejemplo, tiene un archivo .zip autoextraíble y desea montar algo dentro de él, comprima el contenido del archivo interno y asegúrese de que el archivo .zip externo no comprima también el archivo interno.

This setup ensures that your program's configuration directory is separated from other clutter and is platform-independent.

The search path will be configured as follows:

  • The Write Directory (created if it doesn't exist)
  • The Base Directory (PHYSFS_getBaseDir())
  • All found CD-ROM directories (optional)

These directories are then searched for files ending with the specified extension (`archiveExt`). If these files are valid and supported archives, they will also be added to the search path. For example, if you specify "PKG" for `archiveExt` and there is a file named `data.PKG` in the base directory, it will be checked. All archives are mounted at the root of the virtual file system ('/').

This can cause significant blocking while accessing discs, and may not work if no discs are present or mounted. You might want to set this to zero and handle disc access yourself.
archivesFirst Set to non-zero to prepend discovered archives to the search path. Set to zero to append them. This parameter is ignored if `archiveExt` is NULL.

int PHYSFS_compareStrings (const char * str1, const char * str2)

Compara dos cadenas de texto para ver si son iguales, o si una es mayor o menor que la otra. Este es un reemplazo para strcmp/stricmp y espera que ambas cadenas estén codificadas en UTF-8.

Si ambas cadenas contienen exclusivamente caracteres ASCII de bajo nivel, esto funcionará correctamente, ya que también es UTF-8 válido. ¡Si hay algún carácter ASCII de alto nivel, esto no hará lo que esperas!

Informará cuál cadena es "mayor que" la otra, pero ten en cuenta que esto no significa necesariamente nada: 'a' puede ser "menor que" 'b', pero un kuten japonés no tiene una relación alfabética significativa con una lambda griega, pero poder asignar un "valor" confiable hace que los algoritmos de ordenación sean posibles, aunque no del todo sensatos. La mayoría de los casos deberían tratar el valor de retorno como "igual" o "no igual".

Como strcmp, espera que ambas cadenas estén terminadas en NULL.

Parámetros

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Devuelve

-1 si str1 es "menor que" str2, 1 si es "mayor que", 0 si son iguales.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte una cadena Latin1 a una cadena UTF-8. Las cadenas Latin1 son 8 bits por carácter: una codificación popular de "ASCII superior".

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, asigna un búfer que sea el doble del tamaño del búfer de origen. UTF-8 expande los puntos de código latin1 mayores que 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

Por favor, ten en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiendo desde ella en todo momento.

Parámetros

src Cadena de origen terminada en nulo en formato Latin1.
dst Búfer para almacenar la cadena UTF-8 convertida.
len Tamaño, en bytes, del búfer de destino.

Informará cuál cadena es "mayor que" la otra, pero ten en cuenta que esto no significa necesariamente nada: 'a' puede ser "menor que" 'b', pero un kuten japonés no tiene una relación alfabética significativa con una lambda griega, pero poder asignar un "valor" confiable hace que los algoritmos de ordenación sean posibles, aunque no del todo sensatos. La mayoría de los casos deberían tratar el valor de retorno como "igual" o "no igual".

Al igual que stricmp, esto espera que ambas cadenas estén terminadas en NULL.

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Devuelve

-1 si str1 es "menor que" str2, 1 si es "mayor que", 0 si son iguales.

Advertencia

Esta función no informará de un error si hay secuencias UTF-8 inválidas en la cadena de origen. Las reemplazará con un carácter '?' y continuará.

Las cadenas UCS-2 son de 16 bits por carácter: TCHAR en Windows, cuando se compila con soporte Unicode. These functions convert an integer from the platform's native byte order to the specified byte order (BE = Big Endian, LE = Little Endian) and write it to the specified PhysicsFS file handle.

The U prefix functions (e.g., PHYSFS_writeUBE16) are convenience functions. They convert an unsigned integer from the platform's native byte order to the specified byte order (BE = Big Endian, LE = Little Endian) and write it to the specified PhysicsFS file handle.

The B prefix functions (e.g., PHYSFS_writeBE16) write the value directly without any byte-swapping, assuming the native byte order of the platform is big-endian. If the native byte order is little-endian, the value will be byte-swapped.

The L prefix functions (e.g., PHYSFS_writeLE16) write the value directly without any byte-swapping, assuming the native byte order of the platform is little-endian. If the native byte order is big-endian, the value will be byte-swapped.

These functions are useful for writing data in a platform-independent format, such as for saving game state or configuration files.

On failure, these functions return zero and you can query the error code using PHYSFS_getLastErrorCode().
