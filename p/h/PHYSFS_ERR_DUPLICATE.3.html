Documentación de Definiciones de Macros

#define PHYSFS_file PHYSFS_File

Define de compatibilidad con la API 1.0. PHYSFS_file es idéntico a PHYSFS_File. Esta definición #define existe para compatibilidad retroactiva con la API 1.0, que tenía una convención de capitalización inconsistente en este caso. El nuevo código debe usar PHYSFS_File, ya que esta definición #define podría desaparecer en el futuro.

int PHYSFS_deinit (void )

Desinicializa la biblioteca PhysicsFS. Esto cierra todos los archivos abiertos a través de PhysicsFS, borra las rutas de búsqueda/escritura, libera memoria e invalida todos sus descriptores de archivo.

Tenga en cuenta que esta llamada puede FALLAR si hay un archivo abierto para escritura que se niega a cerrarse (por ejemplo, el sistema operativo subyacente estaba almacenando en búfer escrituras en un sistema de archivos de red, y el servidor de archivos se ha caído, o un disco duro ha fallado, etc.). Generalmente es mejor cerrar todos los descriptores de escritura usted mismo antes de llamar a esta función, para que pueda manejar de forma elegante un fallo específico.

Una vez desinicializado con éxito, se puede volver a llamar a PHYSFS_init() para reiniciar el subsistema. Todos los estados de la API predeterminados se restauran en este punto, con la excepción de cualquier asignador personalizado que pueda haber especificado, que sobrevive entre inicializaciones.

Retorna

distinto de cero en caso de éxito, cero en caso de error. Los detalles del error se pueden obtener de PHYSFS_getLastError(). Si falla, el estado de PhysFS es indefinido y probablemente está muy dañado.

int PHYSFS_delete (const char * filename)

Elimina un archivo o directorio. (nombre de archivo) se especifica en notación independiente de la plataforma en relación con el directorio de escritura.

Un directorio debe estar vacío antes de que esta llamada pueda eliminarlo.

La eliminación de un enlace simbólico eliminará el enlace, no lo que apunta, independientemente de si "permite enlaces simbólicos" o no.

Por lo tanto, si tiene el directorio de escritura establecido en "C:\mi_juego\directorio_escritura" y llama a PHYSFS_delete("descargas/mapas/nivel1.map"), entonces el archivo "C:\mi_juego\directorio_escritura\descargas\mapas\nivel1.map" se eliminará del sistema de archivos físico, si existe y el sistema operativo permite la eliminación.

Tenga en cuenta que en los sistemas Unix, la eliminación de un archivo puede ser exitosa, pero el archivo real no se eliminará hasta que todos los procesos que tengan un descriptor de archivo abierto para él (incluido su programa) cierren sus descriptores.

Lo más probable es que los bits que componen el archivo aún existan, simplemente se ponen a disposición para ser sobrescritos en un momento posterior. No considere esto un método de seguridad ni nada parecido. :)

Parámetros

filename Nombre del archivo a eliminar.

Retorna

distinto de cero en caso de éxito, cero en caso de error. Utilice PHYSFS_getLastErrorCode() para obtener el error específico.

Elimina un archivador del sistema. Si por alguna razón, solo necesita que su archivador registrado previamente viva durante una parte de la vida útil de su aplicación, puede eliminarlo del sistema una vez que haya terminado con él a través de esta función.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Get a file listing of a search path's directory, using an application-defined callback, with errors reported. Internally, PHYSFS_enumerateFiles() just calls this function and then builds a list before returning to the application, so functionality is identical except for how the information is represented to the application.

Unlike PHYSFS_enumerateFiles(), this function does not return an array. Rather, it calls a function specified by the application once per element of the search path:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // give me more data, please.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

Items sent to the callback are not guaranteed to be in any order whatsoever. There is no sorting done at this level, and if you need that, you should probably use PHYSFS_enumerateFiles() instead, which guarantees alphabetical sorting. This form reports whatever is discovered in each archive before moving on to the next. Even within one archive, we can't guarantee what order it will discover data. Any sorting you find in these callbacks is just pure luck. Do not rely on it. As this walks the entire list of archives, you may receive duplicate filenames.

This API and the callbacks themselves are capable of reporting errors. Prior to this API, callbacks had to accept every enumerated item, even if they were only looking for a specific thing and wanted to stop after that, or had a serious error and couldn't alert anyone. Furthermore, if PhysicsFS itself had a problem (disk error or whatnot), it couldn't report it to the calling app, it would just have to skip items or stop enumerating outright, and the caller wouldn't know it had lost some data along the way.

Now the caller can be sure it got a complete data set, and its callback has control if it wants enumeration to stop early. See the documentation for PHYSFS_EnumerateCallback for details on how your callback should behave.

Parameters

dir Directory, in platform-independent notation, to enumerate.
c Callback function to notify about search path elements.
d Application-defined data passed to callback. Can be NULL.

Returns

non-zero on success, zero on failure. Use PHYSFS_getLastErrorCode() to obtain the specific error. If the callback returns PHYSFS_ENUM_STOP to stop early, this will be considered success. Callbacks returning PHYSFS_ENUM_ERROR will make this function return zero and set the error code to PHYSFS_ERR_APP_CALLBACK.

char **PHYSFS_enumerateFiles (const char * dir)

Get a file listing of a search path's directory.

Warning

In PhysicsFS versions prior to 2.1, this function would return as many items as it could in the face of a failure condition (out of memory, disk i/o error, etc). Since this meant apps couldn't distinguish between complete success and partial failure, and since the function could always return NULL to report catastrophic failures anyway, in PhysicsFS 2.1 this function's policy changed: it will either return a list of complete results or it will return NULL for any failure of any kind, so we can guarantee that the enumeration ran to completion and has no gaps in its results.

Matching directories are interpolated. That is, if "C:\mydir" is in the search path and contains a directory "savegames" that contains "x.sav", "y.sav", and "z.sav", and there is also a "C:\userdir" in the search path that has a "savegames" subdirectory with "w.sav", then the following code:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);
* We've got [x.sav].
* We've got [y.sav].
* We've got [z.sav].
* We've got [w.sav]..fi
Feel free to sort the list however you like. However, the returned data will always contain no duplicates, and will be always sorted in alphabetic (rather: case-sensitive Unicode) order for you.
Don't forget to call PHYSFS_freeList() with the return value from this function when you are done with it.

En Windows, podría verse así: "C:\\Users\\bob\\AppData\\Roaming\\My Company\\My Program Name"

En Linux, podría verse así: ""/home/bob/.local/share/My Program Name"

En Mac OS X, podría verse así: ""/Users/bob/Library/Application Support/My Program Name"

(etc.)

Probablemente deberías usar el directorio de preferencias como tu directorio de escritura, y también ponerlo cerca del principio de tu ruta de búsqueda. Versiones anteriores de PhysicsFS ofrecían solo PHYSFS_getUserDir() y te dejaban a ti decidir dónde debían ir los archivos dentro de ese árbol. Esto encuentra la ubicación correcta para cualquier plataforma, lo cual no solo cambia entre sistemas operativos, sino también entre versiones del mismo sistema operativo.

Especificas el nombre de tu organización (si no es una organización real, tu nombre o un dominio de Internet que poseas podría servir) y el nombre de tu aplicación. Estos deben ser nombres propios.

Tanto las cadenas (org) como (app) pueden formar parte de un nombre de directorio, así que por favor sigue estas reglas:

  • Intenta usar la misma cadena de org (incluyendo mayúsculas y minúsculas) para todas tus aplicaciones que utilicen esta función.
  • Siempre usa una cadena de app única para cada una, y asegúrate de que nunca cambie para una app una vez que hayas decidido sobre ella.
  • Los caracteres Unicode son legales, siempre que estén codificados en UTF-8, pero...
  • ...solo usa letras, números y espacios. Evita la puntuación como "Game Name 2: Bad Guy's Revenge!" ... "Game Name 2" es suficiente.

El puntero devuelto por esta función permanece válido hasta que vuelvas a llamar a esta función, o llames a PHYSFS_deinit(). Sin embargo, esta no es necesariamente una llamada rápida, por lo que deberías llamarla una vez al inicio y copiar la cadena si la necesitas.

int PHYSFS_mount(const char *newDir, const char *mountPoint, int appendToPath)

Agrega un archivo o directorio a la ruta de búsqueda. Si es un duplicado, la entrada no se agrega nuevamente, aunque la función tenga éxito. No puede agregar el mismo archivo a dos puntos de montaje diferentes: la verificación de duplicados se realiza contra el archivo y no contra el punto de montaje.

Cuando monta un archivo, se agrega a un sistema de archivos virtual... todos los archivos en todos los archivos se interpolan en un solo árbol de archivos jerárquico. Dos archivos montados en el mismo lugar (o un archivo con archivos que se superponen con otro punto de montaje) pueden tener archivos superpuestos: en tal caso, se selecciona el archivo anterior en la ruta de búsqueda, y los otros archivos son inaccesibles para la aplicación. Esto permite que los archivos se utilicen para anular revisiones anteriores; puede usar el mecanismo de montaje para colocar archivos en un punto específico del árbol de archivos y evitar la superposición; esto es útil para modificaciones descargables que podrían pisar los datos de la aplicación o entre sí, por ejemplo.

El punto de montaje no necesita existir antes de montarlo, lo que es diferente de lo que pueden esperar aquellos familiarizados con el concepto de "montaje" de Unix. Además, se pueden montar varios archivos en el mismo punto de montaje, o los puntos de montaje y el contenido de los archivos pueden superponerse... el mecanismo de interpolación aún funciona como de costumbre.

Se permite especificar un enlace simbólico a un archivo o directorio aquí, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esa función solo se ocupa de los enlaces simbólicos dentro del directorio o archivo montado.

mountPoint Ubicación en el árbol interpolado donde este archivo será "montado", en notación independiente de la plataforma. NULL o "" es equivalente a "/".
appendToPath distinto de cero para agregar a la ruta de búsqueda, cero para anteponer.

Devuelve

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, asigne un búfer del doble del tamaño del búfer de origen. UTF-8 expande los puntos de código Latin1 mayores que 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Tenga en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; debería alejarse de ella en todo momento.

int PHYSFS_utf8stricmp(const char *str1, const char *str2)

Comparación insensible a mayúsculas y minúsculas de dos cadenas UTF-8. Es un reemplazo de strcasecmp/stricmp que espera que ambas cadenas estén en codificación UTF-8. Realizará un "plegado de mayúsculas" para decidir si los puntos de código Unicode en las cadenas coinciden.

Si ambas cadenas son exclusivamente caracteres ASCII bajos, esto hará lo correcto, ya que también es UTF-8 válido. ¡Si hay algún carácter ASCII alto, esto no hará lo que espera!

Informará cuál cadena es "mayor que" la otra, pero tenga en cuenta que esto no significa necesariamente nada: 'a' puede ser "menor que" 'b', pero un kuten japonés no tiene una relación alfabética significativa con una lambda griega, pero poder asignar un "valor" confiable hace que los algoritmos de ordenación sean posibles, aunque no del todo sensatos. La mayoría de los casos deberían tratar el valor de retorno como "igual" o "no igual".

Al igual que stricmp, esto espera que ambas cadenas estén terminadas en nulo.

Parámetros

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Retorna

-1 si str1 es "menor que" str2, 1 si es "mayor que", 0 si son iguales.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. Windows releases before 2000 used TCHAR, but only handled UCS-2. UTF-16 is UCS-2, except for the characters that are 4 bytes, which aren't representable in UCS-2 at all anyhow. If you aren't sure, you should be using UTF-16 at this point on Windows.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UTF-16 always uses two to four, so an entirely low-ASCII string will double in size! The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UTF-16 string.
len Size, in bytes, of destination buffer.
