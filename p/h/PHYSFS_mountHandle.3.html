1.0 API compatibility define. PHYSFS_file is identical to PHYSFS_File. This #define is here for backwards compatibility with the 1.0 API, which had an inconsistent capitalization convention in this case. New code should use PHYSFS_File, as this #define may go away someday.

#define PHYSFS_VERSION( x)

Value:

{ \
    (x)->major = PHYSFS_VER_MAJOR; \
    (x)->minor = PHYSFS_VER_MINOR; \
    (x)->patch = PHYSFS_VER_PATCH; \
}

Macro to determine PhysicsFS version program was compiled against. This macro fills in a PHYSFS_Version struct

struct PHYSFS_Version

This structure holds version information. You can use it to compare the version of the library you compiled against with the version of the library you linked against. This is determined by what header the compiler uses. Note that if you dynamically linked the library, you might have a slightly newer or older version at runtime. That version can be determined with PHYSFS_getLinkedVersion(), which, unlike PHYSFS_VERSION, is not a macro.

Parameters

x A pointer to a PHYSFS_Version struct to initialize.

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para callbacks que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso.

Estos se utilizan para informar a un llamador original de una lista de entradas de directorio, un archivo/directorio/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estos callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que deben limpiarse con PHYSFS_freeList(). El callback significa que la biblioteca no necesita asignar una lista completa y todas las cadenas por adelantado.

Ten en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente el mismo en las versiones de callback. Consulta la documentación de las API específicas, pero las cadenas podrían no estar ordenadas como esperas y podrías obtener cadenas duplicadas.

data Puntero a datos definido por el usuario, pasado desde la API que finalmente llamó al callback.
origdir Una cadena que contiene la ruta completa, en notación independiente de la plataforma, del directorio que contiene este archivo. En la mayoría de los casos, este es el directorio sobre el cual solicitaste la enumeración, pasado en el callback para tu conveniencia.
fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otros callbacks que se hayan ejecutado, y no contendrá la ruta completa. Puedes recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio de ruta de búsqueda, utilizando una devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego crea una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. Más bien, llama a una función especificada por la aplicación una vez por elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // give me more data, please.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

No se garantiza que los elementos enviados a la devolución de llamada estén en ningún orden. No se realiza ninguna ordenación en este nivel, y si la necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza la ordenación alfabética. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. *Cualquier ordenación que encuentre en estas devoluciones de llamada es pura suerte. No confíe en ella.* Al recorrer toda la lista de archivos, es posible que reciba nombres de archivo duplicados.

Esta API y las devoluciones de llamada en sí mismas son capaces de informar errores. Antes de esta API, las devoluciones de llamada tenían que aceptar todos los elementos enumerados, incluso si solo buscaban algo específico y querían detenerse después de eso, o tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS en sí tenía un problema (error de disco o similar), no podía informarlo a la aplicación que llama, solo tendría que omitir elementos o dejar de enumerar directamente, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su devolución de llamada tiene el control si desea que la enumeración se detenga antes. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, a enumerar.
c Función de devolución de llamada para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados ​​a la devolución de llamada. Puede ser NULL.

Devoluciones

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si la devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse antes, esto se considerará un éxito. Las devoluciones de llamada que devuelven PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezca el código de error en PHYSFS_ERR_APP_CALLBACK.

Obtiene una lista de archivos de un directorio de ruta de búsqueda.

Advertencia

En versiones de PhysicsFS anteriores a la 2.1, esta función devolvía tantos elementos como podía ante una condición de error (falta de memoria, error de E/S de disco, etc.). Dado que esto significaba que las aplicaciones no podían distinguir entre el éxito completo y el fallo parcial, y dado que la función siempre podía devolver NULL para informar fallos catastróficos de todos modos, en PhysicsFS 2.1 la política de esta función cambió: devolverá una lista de resultados completos o devolverá NULL para cualquier fallo de cualquier tipo, por lo que podemos garantizar que la enumeración se completó y no tiene lagunas en sus resultados.

Se interpolan los directorios coincidentes. char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);

* We've got [y.sav].
* We've got [z.sav].

const char * PHYSFS_getPrefDir (const char * org, const char * app)

Get the user-and-app-specific path where files can be written. Helper function.

This function will decide the appropriate location in the native filesystem, create the directory if necessary, and return a string in platform-dependent notation, suitable for passing to PHYSFS_setWriteDir().

(etc.)

Older versions of PhysicsFS offered only PHYSFS_getUserDir() and left you to figure out where the files should go under that tree. This finds the correct location for whatever platform, which not only changes between operating systems, but also versions of the same operating system.

You specify the name of your organization (if it's not a real organization, your name or an Internet domain you own might do) and the name of your application. These should be proper names.

  • Try to use the same org string (including case-sensitivity) for all your applications that use this function.

The returned filename will be the element of the search path where the file was found, which may be a directory, or an archive. int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Añade un archivo o directorio a la ruta de búsqueda. Si es un duplicado, la entrada no se añade de nuevo, aunque la función tenga éxito. No puedes añadir el mismo archivo a dos puntos de montaje diferentes: la comprobación de duplicados se hace contra el archivo y no contra el punto de montaje.

Cuando montas un archivo, se añade a un sistema de archivos virtual... todos los archivos de todos los archivos se interpolan en un único árbol de archivos jerárquico. Dos archivos montados en el mismo lugar (o un archivo con archivos que se solapan con otro punto de montaje) pueden tener archivos que se solapan: en tal caso, se selecciona el archivo anterior en la ruta de búsqueda y los otros archivos son inaccesibles para la aplicación. Esto permite usar archivos para sobrescribir revisiones anteriores; puedes usar el mecanismo de montaje para colocar archivos en un punto específico del árbol de archivos y evitar solapamientos; esto es útil para mods descargables que puedan pisotear datos de la aplicación o entre sí, por ejemplo.

El punto de montaje no necesita existir antes de montar, lo que es diferente a lo que los familiarizados con el concepto Unix de "montar" pueden esperar. Además, más de un archivo puede ser montado en el mismo punto de montaje, o los puntos de montaje y el contenido de los archivos pueden solaparse... el mecanismo de interpolación sigue funcionando como de costumbre.

Se permite especificar un enlace simbólico a un archivo o directorio aquí, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esa función solo se ocupa de los enlaces simbólicos dentro del directorio o archivo montado.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparente) el archivo al que apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarlo fuera de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si desea asumir ese riesgo, llame a esta función con un parámetro distinto de cero. Tenga en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En términos generales, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sienta que existe un peligro específico al permitirlos, debe permitirlos.

Los enlaces simbólicos solo se verifican explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar sus rutas de búsqueda y escritura, etc., nunca se verifican los enlaces simbólicos.

Tenga en cuenta que PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlace simbólico se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

  • El directorio base (PHYSFS_getBaseDir())
  • Todos los directorios de CD-ROM encontrados (opcional)

Estos directorios se buscan por extensión (archiveExt), que, si son válidas y soportadas, se añadirán a la lista de búsqueda. Si especificaste "PKG" para (archiveExt) y hay un archivo llamado data.PKG en el directorio base, será verificado. Las carpetas pueden ser añadidas al principio o al final de la lista de búsqueda, independientemente de dónde se encontraron. Todos los archivos se montan en la raíz del sistema de archivos virtual ("/").

Todo lo anterior puede realizarse desde la aplicación, pero esto lo hace todo por ti. Puedes añadir más a la lista de búsqueda manualmente, también.

Parámetros

organization nombre de tu compañía/grupo/etc para usar como directorio, mantenlo corto y sin frases.
appName nombre específico del programa de tu programa, para distinguirlo de otros programas que usan PhysicsFS.
archiveExt extensión usada por tu programa para especificar un archivo. Por ejemplo, Quake 3 usa "pk3", aunque sean simplemente archivos zip. Especifica NULL para no buscar archivos automáticamente. No especifiques el punto "."; si quieres buscar archivos ZIP, especifícalo como "ZIP" y no como ".ZIP"... la búsqueda no distingue mayúsculas de minúsculas.
includeCdRoms No cero para incluir CD-ROMs en la lista de búsqueda, y (si (archiveExt) != NULL) buscar archivos en ellos. Esto puede causar un bloqueo significativo mientras se acceden los discos, y si no hay discos en la unidad (o incluso no montados en sistemas Unix), ellos pueden no estar disponibles. Puedes especificar cero y manejar la configuración de disco tú mismo.
archivesFirst No cero para anteponer las carpetas al principio de la lista de búsqueda. Cero para añadirlas al final. Ignorado si !(archiveExt).

Retorna

1 si es exitoso, 0 en caso de error. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

int PHYSFS_ucs4stricmp (const PHYSFS_uint32 * str1, const PHYSFS_uint32 * str2)

Case-insensitive compare of two UCS-4 strings. This is a strcasecmp/stricmp replacement that expects both strings to be in UCS-4 (aka UTF-32) encoding. It will do "case folding" to decide if the Unicode codepoints in the strings match.

It will report which string is "greater than" the other, but be aware that this doesn't necessarily mean anything: 'a' may be "less than" 'b', but a Japanese kuten has no meaningful alphabetically relationship to a Greek lambda, but being able to assign a reliable "value" makes sorting algorithms possible, if not entirely sane. Most cases should treat the return value as "equal" or "not equal".

Like stricmp, this expects both strings to be NULL-terminated.

Parameters

str1 First string to compare.
str2 Second string to compare.

Returns

-1 if str1 is "less than" str2, 1 if "greater than", 0 if equal.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte una cadena UTF-8 a una cadena Latin1. Las cadenas Latin1 son de 8 bits por carácter: una codificación popular de "ASCII superior".

Para asegurar que el buffer de destino sea lo suficientemente grande para la conversión, por favor, asigna un buffer que sea el doble del tamaño del buffer de origen. UTF-8 expande los puntos de código latin1 mayores a 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el buffer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del buffer es 0, esta función no hace nada.

Por favor, ten en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiendo lejos de ella en todo momento.

dst Buffer para almacenar la cadena UTF-8 convertida.
