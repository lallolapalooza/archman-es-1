DESCRIPTION

The PhysicsFS library provides an abstraction layer over various data archives. It allows you to read files from archives as if they were part of the regular filesystem. This is useful for games, where game data is often packed into archives to reduce the number of files and to prevent users from easily modifying game assets.

PhysicsFS supports multiple archive formats, including ZIP, GZIP, LHA, RAR, and others. It can also mount plain directories as archives, which is useful during development.

The library handles endianness conversions, character encoding conversions (UTF-8, UCS-2, UCS-4, Latin1), and provides functions for enumerating files, mounting/unmounting archives, and error handling.

typedef void(* physFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Signatura de función para callbacks que enumeran archivos.

Advertencia

Desde PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate(); ofrece más control sobre el proceso.

Estos se utilizan para reportar una lista de entradas de directorio a un llamador original, una entrada de directorio/archivo/símbolo por callback. Todos los strings son codificados en UTF-8. Las funciones no deben intentar modificar o liberar la memoria de los strings.

Estos callbacks se utilizan, desde PhysicsFS 1.1, como alternativa a funciones que devuelven listas que necesitan ser limpiadas con PHYSFS_freeList(). El callback significa que la librería no necesita alojar una lista completa y todas las strings de antemano.

Tengan en cuenta que el orden prometido de los datos en las versiones de lista no necesariamente es el mismo en las versiones de callback. Compruebe la documentación específica de las APIs, pero los strings pueden no estar ordenados como esperan y pueden obtener strings duplicados.

fname El nombre de archivo que se está enumerando. Puede no estar en orden alfabético comparado con otros callbacks que hayan sido llamados, y no contendrá la ruta completa. int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio de la ruta de búsqueda, utilizando una función de devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego construye una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. En su lugar, llama a una función especificada por la aplicación una vez por elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/alguna/ruta", printDir, NULL);

No se garantiza que los elementos enviados a la función de devolución de llamada estén en ningún orden en absoluto. No se realiza ningún ordenamiento en este nivel, y si lo necesitas, probablemente deberías usar PHYSFS_enumerateFiles() en su lugar, que garantiza el ordenamiento alfabético. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. Cualquier ordenamiento que encuentres en estas devoluciones de llamada es pura suerte. No confíes en él. Dado que recorre toda la lista de archivos, puedes recibir nombres de archivo duplicados.

Esta API y las propias funciones de devolución de llamada son capaces de informar errores. Antes de esta API, las funciones de devolución de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o si tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS en sí tenía un problema (error de disco o similar), no podía informarlo a la aplicación que llamaba, solo tendría que omitir elementos o dejar de enumerar directamente, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su función de devolución de llamada tiene control si quiere que la enumeración se detenga temprano. Consulta la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse tu función de devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, a enumerar.
c Función de devolución de llamada para notificar sobre los elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la función de devolución de llamada. Puede ser NULL.

Retorna

Distinto de cero en caso de éxito, cero en caso de error. Usa PHYSFS_getLastErrorCode() para obtener el error específico. Si la función de devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse temprano, esto se considerará un éxito. Las funciones de devolución de llamada que devuelvan PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establecerán el código de error a PHYSFS_ERR_APP_CALLBACK.

char ** PHYSFS_enumerateFiles (const char * dir)

Obtiene una lista de archivos de un directorio de la ruta de búsqueda.

Advertencia

En versiones de PhysicsFS anteriores a 2.1, esta función devolvería tantos elementos como pudiera frente a una condición de error (falta de memoria, error de E/S de disco, etc.). Dado que esto significaba que las aplicaciones no podían distinguir entre el éxito completo y el fracaso parcial, y dado que la función siempre podía devolver NULL para informar fallos catastróficos de todos modos, en PhysicsFS 2.1 la política de esta función cambió: devolverá una lista de resultados completos o devolverá NULL para cualquier fallo de cualquier tipo, para que podamos garantizar que la enumeración se completó y no tiene huecos en sus resultados.

Los directorios coincidentes se interpolan. Es decir, si "C:\mi_directorio" está en la ruta de búsqueda y contiene un directorio "savegames" que contiene "x.sav", "y.sav" y "z.sav", y también hay un "C:\directorio_usuario" en la ruta de búsqueda que tiene un subdirectorio "savegames" con "w.sav", entonces el siguiente código:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * Tenemos [%s].\n", *i);
PHYSFS_freeList(rc);
* Tenemos [x.sav].
* Tenemos [y.sav].
* Tenemos [z.sav].
* Tenemos [w.sav]..fi
Siéntete libre de ordenar la lista como quieras. Sin embargo, los datos devueltos siempre contendrán duplicados, y siempre estarán ordenados alfabéticamente (o mejor dicho, en orden Unicode sensible a mayúsculas y minúsculas).
No olvides llamar a PHYSFS_freeList() con el valor de retorno de esta función cuando hayas terminado con él.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

Hace un subdirectorio de un archivo su directorio raíz. Esto permite que puedas reducir los archivos accesibles en un archivo específico. void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte una cadena Latin1 a una cadena UTF-8. Las cadenas Latin1 tienen 8 bits por carácter: una codificación popular de "alto ASCII".

Para asegurar que el buffer de destino sea lo suficientemente grande para la conversión, por favor asigna un buffer que sea el doble del tamaño del buffer de origen. UTF-8 expande los puntos de código latin1 mayores a 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el buffer de destino serán truncadas, pero siempre serán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del buffer es 0, esta función no hace nada.

Por favor, ten en cuenta que no proporcionamos un convertidor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías intentar convertirla siempre.

Parámetros

src Cadena de origen terminada en nulo en formato Latin1.
dst Buffer para almacenar la cadena UTF-8 convertida.
len Tamaño, en bytes, del buffer de destino.

void PHYSFS_utf8ToUcs4 (const char * src, PHYSFS_uint32 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UCS-4 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

int PHYSFS_writeUBE16 (PHYSFS_File * file, PHYSFS_uint16 val)

Convierte y escribe un valor de 16 bits sin signo en formato big-endian. Función de conveniencia. Convierte un valor de 16 bits sin signo del orden de bytes nativo de la plataforma a big-endian y lo escribe en un archivo.

Parámetros

file Manejador de archivo PhysicsFS al que escribir.
val Valor a convertir y escribir.

Retorna

cero en caso de fallo, distinto de cero en caso de éxito. En caso de fallo, puedes averiguar qué salió mal consultando PHYSFS_getLastErrorCode().
