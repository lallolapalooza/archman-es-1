Advertencia A partir de PhysicsFS 2.1, usa PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; te da más control sobre el proceso. Estos se utilizan para informar una lista de entradas de directorio a un llamante original, un archivo/dir/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar o liberar la memoria de ninguna cadena. Estas callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a funciones que devolverían listas que necesitan ser limpiadas con
PHYSFS_freeList() . La callback significa que la biblioteca no tiene que reservar una lista completa y todas las cadenas de antemano. Ten en cuenta que el orden de datos prometido en las versiones de lista no necesariamente es así en las versiones de callback. Revisa la documentación de APIs específicas, pero las cadenas pueden no estar ordenadas como esperas y podrías obtener cadenas duplicadas.Parámetros data Puntero de datos definido por el usuario, pasado a través desde la API que eventualmente llamó a la callback.

void   PHYSFS_permitSymbolicLinks (int 
allow)

Habilitar o deshabilitar el seguimiento de enlaces simbólicos. Algunos
    sistemas de archivos físicos y archivos de archivo contienen archivos que son
    simplemente punteros a otros archivos. En el sistema de archivos físico, abrir
    tal enlace abrirá (de forma transparente) el archivo al que 
apunta.

Por defecto, PhysicsFS comprobará si un archivo es realmente un enlace
    simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario,
    el enlace podría llevarte fuera de las rutas de escritura y búsqueda, y comprometer
    la seguridad. Si quieres correr ese riesgo, llama a esta función con un parámetro no nulo.
  Tenga en cuenta que esto es más para aislar el lenguaje de scripting de un programa,
  por si scripts no confiables intentan comprometer el sistema. En general, un usuario
  podría tener perfectamente una razón legítima para configurar un enlace simbólico,
  por lo que a menos que sientas que hay un peligro específico al permitirlos, deberías
  
permitirlos.

Los enlaces simbólicos solo se verifican explícitamente al manejar nombres de archivo
    en notación independiente de la plataforma. Es decir, al configurar sus rutas de búsqueda y
    escritura, etc., los enlaces simbólicos 
nunca se verifican.
