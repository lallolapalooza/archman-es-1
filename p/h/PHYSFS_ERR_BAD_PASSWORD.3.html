DESCRIPTION

The PhysicsFS library is a C API for accessing data files. It provides a way to manage archives and directories as a unified virtual filesystem. This allows applications to easily manage game assets, such as graphics, sound, and levels, without worrying about their physical location on disk.

The library supports various archive formats and can handle multiple archives simultaneously. It also provides functions for querying file information, manipulating paths, and handling character encoding conversions.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

mountPoint Location in the interpolated tree that this archive will be "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
appendToPath nonzero to append to search path, zero to prepend.

Returns

nonzero if added to path, zero on failure (bogus archive, dir missing, etc). Use PHYSFS_getLastErrorCode() to obtain the specific error.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparentemente) el archivo al que apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría sacarte de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En términos generales, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sientas que hay un peligro específico al permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se verifican explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., nunca se verifican los enlaces simbólicos.

Ten en cuenta que PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlace simbólico se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para denegar el enlace.

NAME

PHYSFS_writeLE16, PHYSFS_writeLE32, PHYSFS_writeLE64, PHYSFS_writeBE16, PHYSFS_writeBE32, PHYSFS_writeBE64 - Write integers in platform-native byte order.

SYNOPSIS

#include <physfs.h>

int PHYSFS_writeLE16(PHYSFS_File *file, PHYSFS_uint16 val);
int PHYSFS_writeLE32(PHYSFS_File *file,PHYSFS_uint32 val);
int PHYSFS_writeLE64(PHYSFS_File *file,PHYSFS_uint64 val);

int PHYSFS_writeBE16(PHYSFS_File *file,PHYSFS_uint16 val);
int PHYSFS_writeBE32(PHYSFS_File *file,PHYSFS_uint32 val);
int PHYSFS_writeBE64(PHYSFS_File *file,PHYSFS_uint64 val);

Detailed Description

These functions convert an integer from the platform's native byte order to the specified endianness (little-endian or big-endian) and write it to a file.

These are convenience functions. You could achieve the same result by manually converting the integer and then calling PHYSFS_write().

Warning: PHYSFS_uint64 is only 32 bits on platforms without 64-bit support. You should check the value of sizeof(PHYSFS_uint64) at runtime if you need to write 64-bit values reliably.
