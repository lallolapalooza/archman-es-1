NOMBRE

PHYSFS_writeUBE64 — Escribe un entero unsigned de 64 bits en un archivo.

SINOPSIS

Typedefs


typedef unsigned long long PHYSFS_uint64
Tipo entero sin signo de 64 bits.

Funciones


PHYSFS_sint64 PHYSFS_writeUBE64 (PHYSFS_File *handle, PHYSFS_uint64 value)

Escribe un entero unsigned de 64 bits en un archivo.

Descripción

Esta función escribe un entero unsigned de 64 bits (`PHYSFS_uint64`) en el archivo especificado por `handle`. La escritura se realiza en el orden de bytes de red (big-endian).

Si la escritura es exitosa, la función devuelve el número de bytes escritos (que siempre será 8 para un `PHYSFS_uint64`). Si ocurre un error, devuelve -1 y se puede obtener más información usando `PHYSFS_getLastError()`.

Es importante asegurarse de que el archivo se ha abierto correctamente para escritura o anexión antes de llamar a esta función.

Consulte también: `PHYSFS_write(3)`, `PHYSFS_readUBE64(3)`.

VALOR DE RETORNO

Devuelve el número de bytes escritos (8) en caso de éxito, o -1 si ocurre un error.

VER TAMBIÉN

PHYSFS_write(3), PHYSfs.h(3), PHYSFS_readUBE64(3)

NAME

PHYSFS_writeUBE64 — write a 64-bit unsigned integer to a file.

SYNOPSIS

Typedefs


typedef unsigned long long PHYSFS_uint64
Unsigned 8-bit integer type.

Functions


PHYSFS_sint64 PHYSFS_writeUBE64 (PHYSFS_File *handle, PHYSFS_uint64 value)

Writes a 64-bit unsigned integer to a file.

Description

This function writes a 64-bit unsigned integer (`PHYSFS_uint64`) to the file specified by `handle`. The write is performed in network byte order (big-endian).

If the write is successful, the function returns the number of bytes written (which will always be 8 for a `PHYSFS_uint64`). If an error occurs, it returns -1, and more information can be obtained using `PHYSFS_getLastError()`.

It is important to ensure the file has been opened correctly for writing or appending before calling this function.

See also: `PHYSFS_write(3)`, `PHYSFS_readUBE64(3)`.

RETURN VALUE

Returns the number of bytes written (8) on success, or -1 if an error occurred.

PHYSFS_write(3), PHYSfs.h(3), PHYSFS_readUBE64(3)

int PHYSFS_caseFold (const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Pliega" un punto de código Unicode a un equivalente en minúsculas. (Esto es para uso limitado y avanzado. Si no ves una necesidad inmediata para ello, probablemente puedas ignorar esto para siempre.)

Esto convertirá un punto de código Unicode a su equivalente en minúsculas. Los puntos de código erróneos y los puntos de código sin un equivalente en minúsculas se devolverán sin convertir.

¡Tenga en cuenta que podría obtener varios puntos de código como resultado! La Eszett alemana, por ejemplo, se plegará en dos puntos de código 's' en minúsculas. La teoría es que si pliegas dos cadenas, una con una Eszett y otra con "SS" hacia abajo, coincidirán.

Advertencia

Cualquiera que sea estudiante de Unicode conoce el problema de la "i turca". Esta API no lo maneja. Suponga que esta única letra en todo Unicode definitivamente se plegará de forma incorrecta. Si no sabe de qué se trata esto, probablemente pueda ignorar este problema para la mayor parte del planeta, pero la perfección es imposible.

Parámetros

from El punto de código a plegar.
to Búfer para almacenar los valores de punto de código plegados. Debería apuntar a espacio para al menos 3 ranuras de PHYSFS_uint32.

Devuelve

El número de puntos de código que produjo el plegado. Entre 1 y 3.

int PHYSFS_deinit (void )

Desinicializa la biblioteca PhysicsFS. Esto cierra todos los archivos abiertos a través de PhysicsFS, vacía las rutas de búsqueda/escritura, libera memoria e invalida todos sus manejadores de archivo.

Devuelve

distinto de cero si tiene éxito, cero si hay un error. Los detalles del error se pueden obtener de PHYSFS_getLastError(). Si falla, el estado de PhysFS es indefinido y probablemente esté muy dañado.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio en la ruta de búsqueda, usando una función de devolución de llamada definida por la aplicación, con notificación de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego construye una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. Más bien, llama a una función especificada por la aplicación una vez por elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/alguna/ruta", printDir, NULL);

No se garantiza que los elementos enviados a la función de devolución de llamada estén en ningún orden específico. No se realiza ninguna ordenación a este nivel, y si la necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza la ordenación alfabética. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un solo archivo, no podemos garantizar el orden en que descubrirá los datos. *Cualquier ordenación que encuentre en estas devoluciones de llamada es pura suerte. No confíe en ella.* Al recorrer toda la lista de archivos, es posible que reciba nombres de archivo duplicados.

Esta API y las propias funciones de devolución de llamada son capaces de informar errores. Antes de esta API, las funciones de devolución de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después, o si tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS mismo tuviera un problema (error de disco o similar), no podría informarlo a la aplicación que llama, solo tendría que omitir elementos o dejar de enumerar por completo, y el llamador no sabría que perdió algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su función de devolución de llamada tiene control si desea que la enumeración se detenga temprano. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su función de devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, para enumerar.
c Función de devolución de llamada para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la función de devolución de llamada. Puede ser NULL.

Retorna

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si la función de devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse temprano, esto se considerará un éxito. Las funciones de devolución de llamada que devuelven PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezca el código de error en PHYSFS_ERR_APP_CALLBACK.

char ** PHYSFS_enumerateFiles (const char * dir)

Obtiene una lista de archivos de un directorio en la ruta de búsqueda.

Advertencia

En las versiones de PhysicsFS anteriores a 2.1, esta función devolvía tantos elementos como podía frente a una condición de fallo (falta de memoria, error de E/S de disco, etc.). Dado que esto significaba que las aplicaciones no podían distinguir entre el éxito completo y el fallo parcial, y dado que la función siempre podía devolver NULL para informar fallos catastróficos, en PhysicsFS 2.1 la política de esta función cambió: devolverá una lista de resultados completos o devolverá NULL para cualquier fallo de cualquier tipo, para que podamos garantizar que la enumeración se completó y no tiene huecos en sus resultados.

Los directorios coincidentes se interpolan. Es decir, si "C:\mydir" está en la ruta de búsqueda y contiene un directorio "savegames" que contiene "x.sav", "y.sav", y "z.sav", y también hay un "C:\userdir" en la ruta de búsqueda que tiene un subdirectorio "savegames" con "w.sav", entonces el siguiente código:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * Tenemos [%s].\n", *i);
PHYSFS_freeList(rc);
* Tenemos [x.sav].
* Tenemos [y.sav].
* Tenemos [z.sav].
* Tenemos [w.sav]..fi
Siéntase libre de ordenar la lista como prefiera. Sin embargo, los datos devueltos siempre contendrán duplicados y siempre estarán ordenados alfabéticamente (más bien: Unicode sensible a mayúsculas y minúsculas) para usted.
No olvide llamar a PHYSFS_freeList() con el valor de retorno de esta función cuando haya terminado con él.

dir directorio en notación independiente de la plataforma para enumerar.

The returned filename will be the element of the search path where the file was found, which may be a directory, or an archive. int PHYSFS_mount(const char *newDir, const char *mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

mountPoint Location in the interpolated tree that this archive will be "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
appendToPath nonzero to append to search path, zero to prepend.

Returns

nonzero if added to path, zero on failure (bogus archive, dir missing, etc). Use PHYSFS_getLastErrorCode() to obtain the specific error.

void PHYSFS_permitirEnlacesSimbolicos (int permitir)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir dicho enlace abrirá (transparentemente) el archivo al que apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría sacarte de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sientas que hay un peligro específico en permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se verifican explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., los enlaces simbólicos nunca se verifican.

int PHYSFS_setRoot (const char * archivo, const char * subdirectorio)

Haz que un subdirectorio de un archivo sea su directorio raíz. Esto te permite limitar los archivos accesibles en un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/z.txt, montado en /a, si llamas a PHYSFS_setRoot("x.zip", "/y"), entonces la llamada PHYSFS_openRead("/a/z.txt") tendrá éxito.

Puedes cambiar la raíz de un archivo en cualquier momento, alterando el árbol de archivos interpolado (dependiendo de dónde cambien las rutas, un archivo diferente puede estar proporcionando varios archivos). Si estableces la raíz a NULL o "/", el archivo se tratará como si no se hubiera establecido ninguna raíz especial (como si el archivo se hubiera montado normalmente).

Cambiar la raíz solo afecta a las operaciones futuras en nombres de ruta; un archivo que se abrió desde una ruta que cambió debido a setRoot no se verá afectado.

Establecer una nueva raíz no se limita a los archivos en la ruta de búsqueda; también puedes establecer una en el directorio de escritura, lo cual podría ser útil si tienes archivos abiertos para escritura y, por lo tanto, no puedes cambiar el directorio de escritura en este momento.

No es un error establecer un subdirectorio que no existe como raíz de un archivo; sin embargo, no se verán archivos en este caso. Si los directorios faltantes terminan creándose (un mkdir en el sistema de archivos físico, etc.), esto se reflejará en el árbol interpolado.

Parámetros

archivo directorio/archivo sobre el cual cambiar la raíz.
subdirectorio nuevo subdirectorio que se convertirá en la raíz de este archivo.

Retorna

distinto de cero si tiene éxito, cero en caso de fallo. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

int PHYSFS_setSaneConfig (const char * organizacion, const char * nombreApp, const char * extArchivo, int incluirCdRoms, int archivosPrimero)

Configura rutas predeterminadas y sensatas. Función auxiliar.

El directorio de escritura se establecerá en el directorio de preferencias devuelto por

PHYSFS_getPrefDir(organizacion, nombreApp)

, que se crea si no existe.

Lo anterior es suficiente para asegurar que el directorio de configuración de tu programa esté separado de otro desorden y sea independiente de la plataforma.

La ruta de búsqueda será:

  • El Directorio de Escritura (creado si no existe)
  • El Directorio Base (PHYSFS_getBaseDir())
  • Todos los directorios de CD-ROM encontrados (opcionalmente)

Estos directorios se buscan luego para archivos que terminan con la extensión (extArchivo), que, si son archivos válidos y compatibles, también se agregarán a la ruta de búsqueda. Si especificaste "PKG" para (extArchivo), y hay un archivo llamado data.PKG en el directorio base, se comprobará. Los archivos pueden agregarse o anteponerse a la ruta de búsqueda en orden alfabético, independientemente de los directorios en los que se encontraron. Todos los archivos se montan en la raíz del sistema de archivos virtual ("/").

Todo esto puede ser logrado por la aplicación, pero esto simplemente hace todo por ti. Siéntete libre de agregar más a la ruta de búsqueda manualmente, también.

Parámetros

organizacion Nombre de tu compañía/grupo/etc. que se usará como nombre de directorio, así que mantenlo pequeño y sin adornos.
nombreApp Nombre específico del programa, para separarlo de otros programas que usan PhysicsFS.
extArchivo Extensión de archivo utilizada por tu programa para especificar un archivo. Por ejemplo, Quake 3 usa "pk3", aunque solo sean archivos zip. Especifica NULL para no buscar archivos automáticamente. No especifiques el carácter '.'; si quieres buscar archivos ZIP, especifica "ZIP" y no ".ZIP"... la búsqueda de archivos no distingue mayúsculas y minúsculas.
incluirCdRoms Distinto de cero para incluir CD-ROMs en la ruta de búsqueda, y (si (extArchivo) != NULL) buscarlos para encontrar archivos. Esto puede causar una cantidad significativa de bloqueo mientras se accede a los discos, y si no hay discos en la unidad (o incluso no montados en sistemas Unix), entonces es posible que no se pongan a disposición de todos modos. Es posible que desees especificar cero y manejar la configuración del disco tú mismo.
archivosPrimero Distinto de cero para anteponer los archivos a la ruta de búsqueda. Cero para agregarlos. Ignorado si !(extArchivo).

Retorna

distinto de cero si tiene éxito, cero en caso de error. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

It will report which string is "greater than" the other, but be aware that this doesn't necessarily mean anything: 'a' may be "less than" 'b', but a Japanese kuten has no meaningful alphabetically relationship to a Greek lambda, but being able to assign a reliable "value" makes sorting algorithms possible, if not entirely sane. Like stricmp, this expects both strings to be NULL-terminated.

Returns

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte una cadena UTF-8 a una cadena Latin1. Las cadenas Latin1 son de 8 bits por carácter: una codificación popular de "ASCII superior".

Para asegurar que el buffer de destino sea lo suficientemente grande para la conversión, por favor, asigna un buffer que sea el doble del tamaño del buffer de origen. UTF-8 expande los puntos de código latin1 mayores que 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el buffer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del buffer es 0, esta función no hace nada.

Tenga en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiéndola en todo momento.

Parámetros

src Cadena de origen terminada en nulo en formato Latin1.
dst Buffer para almacenar la cadena UTF-8 convertida.
len Tamaño, en bytes, del buffer de destino.
