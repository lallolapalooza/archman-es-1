int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de una ruta de búsqueda, usando una función de callback definida por el usuario, con errores reportados. Internamente, PHYSFS_enumerateFiles() llama a esta función y luego construye una lista antes de devolverla al aplicativo, por lo que la funcionalidad es idéntica, salvo cómo la información se presenta al aplicativo.

Diferente de PHYSFS_enumerateFiles(), esta función no devuelve un array. En lugar de eso, llama a una función definida por el aplicativo una vez por cada elemento de la ruta de búsqueda:

static physfs_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // me da más datos, por favor.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

Los elementos enviados a la callback no son garantizados estar en ningún orden específico. No se realiza el ordenamiento en este nivel, y si lo necesitas, deberías usar PHYSFS_enumerateFiles(), que garantiza el orden alfabético. Esta forma devuelve lo que se encuentra en cada arquitectura antes de moverse a la siguiente. Incluso dentro de una sola arquitectura, no puedo garantizar el orden en el cual se descubrirá el dato. Cualquier ordenamiento que encuentres en estos callbacks es pura suerte. No dejes de confiar en ello. Como esta camina toda la lista de arquitecturas, puedes recibir nombres de archivos duplicados.

Esta API y las funciones de callback mismas pueden reportar errores. Antes de esta API, las funciones de callback tenían que aceptar cada elemento enumerado, incluso si solo buscaban un elemento específico y querían detenerse después de eso, o si había un error grave y no podían notificar a nadie. Además, si PhysicsFS mismo tenia un problema (error de disco, etc.), no podía reportarlo al aplicativo, simplemente podría saltar los elementos o detener la enumeración por completo, y el llamador no sabría que había perdido algunos datos durante el camino.

Ahora el llamador puede estar seguro de haber obtenido un conjunto completo de datos, y su callback puede controlar si el enumeración se detiene temprano. Ve la documentación de PHYSFS_EnumerateCallback para detalles sobre cómo debe comportarse tu callback.

Parámetros

dir Carpeta a enumerar, en notación independiente del sistema operativo.
c Función de callback para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por el aplicativo que se pasa a la callback. Puede ser NULL.

Devuelve

No cero si es exitoso, cero en caso de error. Usa PHYSFS_getLastErrorCode() para obtener el error específico. Si la función de callback devuelve PHYSFS_ENUM_STOP para detener temprano, se considera exitoso. Las funciones de callback devolviendo PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezca el código de error a PHYSFS_ERR_APP_CALLBACK.

Obtiene una lista de archivos de una ruta de búsqueda.

Advertencia

En versiones de PhysicsFS previas a 2.1, esta función devolvería tantos elementos como pudiera en caso de falla (error de memoria, error de disco, etc.). Dado que esto hacía que los aplicativos no pudieran distinguir entre éxito completo y fracaso parcial, y dado que la función podía siempre devolver NULL para reportar fallos catastróficos, en PhysicsFS 2.1 esta política cambió: devolverá una lista completa de resultados o NULL en caso de cualquier falla, por lo que podemos garantizar que la enumeración terminó correctamente y no tiene gaps en sus resultados.

char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);

We've got [x.sav].
We've got [y.sav].
We've got [z.sav].
We've got [w.sav].

Librete de la lista como prefieres. Sin embargo, los datos devueltos siempre contienen sin duplicados y están siempre ordenados alfabéticamente (es decir, en orden de caso sensible de Unicode) para ti.

int PHYSFS_mount(const char *newDir, const char *mountPoint, int appendToPath)

Agrega un archivo o directorio a la ruta de búsqueda. Si es un duplicado, la entrada no se agrega de nuevo, aunque la función tenga éxito. No puede agregar el mismo archivo a dos puntos de montaje diferentes: la comprobación de duplicados se realiza contra el archivo y no contra el punto de montaje.

Cuando monta un archivo, se agrega a un sistema de archivos virtual... todos los archivos en todos los archivos se interpolan en un solo árbol de archivos jerárquico. Dos archivos montados en el mismo lugar (o un archivo con archivos que se superponen con otro punto de montaje) pueden tener archivos superpuestos: en tal caso, se selecciona el archivo anterior en la ruta de búsqueda, y los otros archivos son inaccesibles para la aplicación. Esto permite que los archivos se utilicen para reemplazar revisiones anteriores; puede usar el mecanismo de montaje para colocar archivos en un punto específico del árbol de archivos y evitar la superposición; esto es útil para mods descargables que podrían pisotear datos de aplicaciones o entre sí, por ejemplo.

El punto de montaje no necesita existir antes de montar, lo que es diferente de lo que aquellos familiarizados con el concepto de "montaje" de Unix pueden esperar. Además, se puede montar más de un archivo en el mismo punto de montaje, o los puntos de montaje y los contenidos de los archivos pueden superponerse... el mecanismo de interpolación sigue funcionando como de costumbre.

Se permite especificar un enlace simbólico a un archivo o directorio aquí, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esa función solo se ocupa de enlaces simbólicos dentro del directorio montado o archivo.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparentemente) el archivo al que apunta.

Por defecto, PhysicsFS comprobará si un archivo es realmente un enlace simbólico durante las llamadas a open y fallará si lo es. De lo contrario, el enlace podría llevarte fuera de las rutas de escritura y de búsqueda, y comprometer la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En términos generales, un usuario podría tener una razón legítima para crear un enlace simbólico, por lo que a menos que sientas que hay un peligro específico en permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se comprueban explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., los enlaces simbólicos nunca se comprueban.

Ten en cuenta que PHYSFS_stat() siempre comprobará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Informará cuál cadena es "mayor que" la otra, pero tenga en cuenta que esto no significa necesariamente nada: 'a' puede ser "menor que" 'b', pero un kuten japonés no tiene una relación alfabética significativa con una lambda griega, pero poder asignar un "valor" confiable hace que los algoritmos de ordenación sean posibles, aunque no del todo sensatos. Al igual que stricmp, esto espera que ambas cadenas terminen en NULL.

Parámetros

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Devuelve

-1 si str1 es "menor que" str2, 1 si es "mayor que", 0 si son iguales.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte una cadena UTF-8 a una cadena Latin1. Las cadenas Latin1 son de 8 bits por carácter: una codificación popular de "ASCII superior".

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, asigna un búfer que tenga el doble del tamaño del búfer de origen. UTF-8 expande los puntos de código latin1 mayores de 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

Por favor, ten en cuenta que no proporcionamos un convertidor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiéndote lejos de ella en todo momento.

Parámetros

src Cadena de origen terminada en nulo en formato Latin1.
dst Búfer para almacenar la cadena UTF-8 convertida.
len Tamaño, en bytes, del búfer de destino.

Escribe datos en un manejador de archivos PhysicsFS. El archivo debe estar abierto para escritura.

Tenga en cuenta que, si bien (len) es un entero sin signo de 64 bits, está limitado a 63 bits (9223372036854775807 bytes), por lo que podemos devolver un valor negativo en caso de error. número de bytes escritos. Esto puede ser menor que (len); en caso de error, el sistema puede intentar escribir tantos bytes como sea posible, por lo que puede ocurrir una escritura incompleta.
