int PHYSFS_caseFold (const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_deinit (void )

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

const char * PHYSFS_getPrefDir (const char * org, const char * app)

Obtener la ruta específica del usuario y la aplicación donde se pueden escribir archivos. Función de ayuda.

Obtener el "directorio de preferencias". Este está destinado a ser donde los usuarios pueden escribir archivos personales (preferencias y partidas guardadas, etc.) que son específicos de su aplicación. Este directorio es único por usuario, por aplicación.

Esta función decidirá la ubicación apropiada en el sistema de archivos nativo, creará el directorio si es necesario y devolverá una cadena en notación dependiente de la plataforma, adecuada para pasar a PHYSFS_setWriteDir().

En Windows, esto podría verse así: "C:\\Users\\bob\\AppData\\Roaming\\Mi Compañía\\Mi Nombre de Programa"

En Linux, esto podría verse así: "/home/bob/.local/share/Mi Nombre de Programa"

En Mac OS X, esto podría verse así: "/Users/bob/Library/Application Support/Mi Nombre de Programa"

(etc.)

Probablemente debería usar el directorio de preferencias para su directorio de escritura, y también ponerlo cerca del principio de su ruta de búsqueda. Las versiones anteriores de PhysicsFS ofrecían solo PHYSFS_getUserDir() y le dejaban averiguar dónde debían ir los archivos en ese árbol. Esto encuentra la ubicación correcta para cualquier plataforma, que no solo cambia entre sistemas operativos, sino también entre versiones del mismo sistema operativo.

Especifica el nombre de su organización (si no es una organización real, su nombre o un dominio de Internet que posea podrían servir) y el nombre de su aplicación. Estos deben ser nombres propios.

Tanto las cadenas (org) como (app) pueden convertirse en parte de un nombre de directorio, así que siga estas reglas:

  • Intente usar la misma cadena de organización (incluida la sensibilidad a mayúsculas y minúsculas) para todas sus aplicaciones que usen esta función.
  • Siempre use una cadena de aplicación única para cada una, y asegúrese de que nunca cambie para una aplicación una vez que la haya decidido.
  • Los caracteres Unicode son legales, siempre que estén codificados en UTF-8, pero...
  • ...solo use letras, números y espacios. Evite la puntuación como "Nombre del Juego 2: ¡La Venganza del Malo!" ... "Nombre del Juego 2" es suficiente.

El puntero devuelto por esta función permanece válido hasta que vuelva a llamar a esta función, o llame a PHYSFS_deinit(). Sin embargo, esta no es necesariamente una llamada rápida, por lo que debería llamarla una vez al inicio y copiar la cadena si la necesita.

int PHYSFS_mount(const char *newDir, const char *mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

mountPoint Location in the interpolated tree that this archive will be "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
appendToPath nonzero to append to search path, zero to prepend.

Returns

nonzero if added to path, zero on failure (bogus archive, dir missing, etc). Use PHYSFS_getLastErrorCode() to obtain the specific error.

Advertencia

A menos que tenga alguna necesidad especial de bajo nivel, debería estar utilizando PHYSFS_mount() en lugar de esta función.

Los archivos dentro de otros archivos pueden ser muy lentos. Si bien un PHYSFS_File puede buscar incluso cuando los datos están comprimidos, puede hacerlo retrocediendo al inicio y descomprimiendo todo antes del punto de búsqueda. El uso normal de archivos puede realizar muchas búsquedas en segundo plano. Como tal, podría encontrar que el uso normal de archivos es extremadamente doloroso si se monta de esta manera. Planifique en consecuencia: si, por ejemplo, tiene un archivo .zip autoextraíble y desea montar algo dentro de él, comprima el contenido del archivo interno y asegúrese de que el archivo .zip externo no comprima el archivo interno también.

Esta función opera igual que PHYSFS_mount(), pero toma un manejador de PHYSFS_File en lugar de una ruta de archivo. Este manejador contiene todos los datos del archivo y se utiliza en lugar de un archivo real en el sistema de archivos físico. El PHYSFS_File puede estar respaldado por un archivo real en el sistema de archivos físico, pero no es necesariamente así. El uso más popular para esto es probablemente montar archivos almacenados dentro de otros archivos.

(newDir) debe ser una cadena única para identificar este archivo. void PHYSFS_permitSymbolicLinks (int allow)

Activar o desactivar el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparente) el archivo al que apunta.

Por defecto, PhysicsFS comprobará si un archivo es realmente un enlace simbólico durante las llamadas open y fallará si lo es. De lo contrario, el enlace podría sacarte de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si quieres asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sientas que hay un peligro específico en permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se comprueban explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., nunca se comprueban los enlaces simbólicos.

Ten en cuenta que PHYSFS_stat() siempre comprobará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlace simbólico se puede activar o desactivar en cualquier momento después de haber llamado a PHYSFS_init(), y está desactivado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para denegar el enlace.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte una cadena UTF-8 a una cadena Latin1. Las cadenas Latin1 tienen 8 bits por carácter: una codificación popular de "ASCII alto".

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, asigna un búfer del doble del tamaño del búfer de origen. UTF-8 expande los puntos de código latin1 mayores que 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

Por favor, ten en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiéndote lejos de ella en todo momento.

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16.
