Paquete: physfs

Licencias: Zlib

NOMBRE

PHYSFS_writeSLE32

SINTAXIS

#include <physfs.h>

PHYSFS_sint32 PHYSFS_writeSLE32 (PHYSFS_sint32 val);
PHYSFS_uint32 PHYSFS_writeULE32 (PHYSFS_uint32 val);
PHYSFS_sint32 PHYSFS_readSLE32 (PHYSFS_sint32 val);
PHYSFS_uint32 PHYSFS_readULE32 (PHYSFS_uint32 val);

DESCRIPCIÓN

Estas funciones se encargan de escribir y leer enteros con signo y sin signo de 32 bits en formato little-endian (SLE = Signed Little Endian, ULE = Unsigned Little Endian). PhysicsFS maneja de forma nativa los datos en formato little-endian. Estas funciones son útiles cuando se trabaja con formatos de archivo que especifican explícitamente little-endian, independientemente de la arquitectura subyacente.

PHYSFS_writeSLE32 toma un entero con signo de 32 bits como entrada y devuelve su representación en formato little-endian.

PHYSFS_writeULE32 toma un entero sin signo de 32 bits como entrada y devuelve su representación en formato little-endian.

PHYSFS_readSLE32 toma un entero con signo de 32 bits que está en formato little-endian y lo convierte a la representación nativa del sistema (que podría ser big-endian o little-endian).

PHYSFS_readULE32 toma un entero sin signo de 32 bits que está en formato little-endian y lo convierte a la representación nativa del sistema.

RETORNO

Las funciones write devuelven el valor en el formato deseado. Las funciones read devuelven el valor convertido a la arquitectura nativa.

EJEMPLO

#include <stdio.h>
#include <physfs.h>

int main(int argc, char **argv) {
    PHYSFS_sint32 original_value = 123456789;
    PHYSFS_sint32 little_endian_value;
    PHYSFS_sint32 converted_back_value;

    if (!PHYSFS_init(argv[0])) {
        fprintf(stderr, "¡Error al inicializar PhysicsFS!: %s\n", PHYSFS_getLastError());
        return 1;
    }

    // Convertir a little-endian para escritura
    little_endian_value = PHYSFS_writeSLE32(original_value);
    printf("Valor original: %d\n", original_value);
    printf("Valor en little-endian: %d\n", little_endian_value);

    // Leer el valor y convertirlo de nuevo a la arquitectura nativa
    converted_back_value = PHYSFS_readSLE32(little_endian_value);
    printf("Valor convertido de nuevo: %d\n", converted_back_value);

    PHYSFS_deinit();
    return 0;
}

int PHYSFS_caseFold(const PHYSFS_uint32 from, PHYSFS_uint32 *to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_deinit(void)

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete(const char *filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

This function returns a pointer to the currently used allocation routines. This can be useful for apps that want to access PhysicsFS's internal, default allocation routines, as well as for external code that wants to share the same allocator, even if the application specified their own.

const char * PHYSFS_getPrefDir (const char * org, const char * app)

Obtener la ruta específica del usuario y de la aplicación donde se pueden escribir archivos. Función auxiliar.

Obtiene el "directorio de preferencias". Este está destinado a ser donde los usuarios pueden escribir archivos personales (preferencias y partidas guardadas, etc.) que son específicos de su aplicación. Este directorio es único por usuario, por aplicación.

Esta función decidirá la ubicación apropiada en el sistema de archivos nativo, creará el directorio si es necesario y devolverá una cadena en notación dependiente de la plataforma, adecuada para pasar a PHYSFS_setWriteDir().

En Windows, esto podría parecer: "C:\\Users\\bob\\AppData\\Roaming\\Mi Empresa\\Mi Nombre de Programa"

En Linux, esto podría parecer: "/home/bob/.local/share/Mi Nombre de Programa"

En Mac OS X, esto podría parecer: "/Users/bob/Library/Application Support/Mi Nombre de Programa"

(etc.)

Probablemente debería usar el directorio de preferencias para su directorio de escritura, y también ponerlo cerca del principio de su ruta de búsqueda. Versiones anteriores de PhysicsFS ofrecían solo PHYSFS_getUserDir() y lo dejaban a usted para averiguar dónde debían ir los archivos dentro de ese árbol. Esto encuentra la ubicación correcta para cualquier plataforma, que no solo cambia entre sistemas operativos, sino también entre versiones del mismo sistema operativo.

Especifica el nombre de su organización (si no es una organización real, su nombre o un dominio de Internet que posea podría servir) y el nombre de su aplicación. Estos deben ser nombres propios.

  • Intente usar la misma cadena org (incluida la sensibilidad a mayúsculas y minúsculas) para todas sus aplicaciones que usen esta función.
  • Siempre use una cadena de aplicación única para cada una, y asegúrese de que nunca cambie para una aplicación una vez que haya decidido sobre ella.
  • Los caracteres Unicode son legales, siempre que estén codificados en UTF-8, pero...
  • ...solo use letras, números y espacios. Evite la puntuación como "Nombre del Juego 2: La Venganza del Malo" ... "Nombre del Juego 2" es suficiente.

El puntero devuelto por esta función permanece válido hasta que vuelva a llamar a esta función o llame a PHYSFS_deinit(). Sin embargo, esta no es necesariamente una llamada rápida, por lo que debería llamar a esta una vez al inicio y copiar la cadena si la necesita.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Añadir un archivo o directorio a la ruta de búsqueda. Si es un duplicado, la entrada no se añade de nuevo, aunque la función tenga éxito. No puede añadir el mismo archivo a dos puntos de montaje diferentes: la comprobación de duplicados se realiza contra el archivo y no contra el punto de montaje.

Cuando monta un archivo, se añade a un sistema de archivos virtual... todos los archivos en todos los archivos se interpolan en un único árbol de archivos jerárquico. Dos archivos montados en el mismo lugar (o un archivo con archivos que se superponen a otro punto de montaje) pueden tener archivos superpuestos: en tal caso, se selecciona el archivo que está más al principio de la ruta de búsqueda, y los otros archivos son inaccesibles para la aplicación. Esto permite usar archivos para anular revisiones anteriores; puede usar el mecanismo de montaje para colocar archivos en un punto específico del árbol de archivos y evitar la superposición; esto es útil para modificaciones descargables que podrían pisotear datos de la aplicación o entre sí, por ejemplo.

El punto de montaje no necesita existir antes de montarlo, lo cual es diferente a lo que aquellos familiarizados con el concepto de montaje de Unix pueden esperar. Además, se pueden montar varios archivos en el mismo punto de montaje, o los puntos de montaje y los contenidos de los archivos pueden superponerse... el mecanismo de interpolación aún funciona como de costumbre.

Se permite especificar un enlace simbólico a un archivo o directorio aquí, independientemente del estado de PHYSFS_permitSymbolicLinks(). Esa función solo se ocupa de los enlaces simbólicos dentro del directorio o archivo montado.

appendToPath Distinto de cero para añadir a la ruta de búsqueda, cero para anteponer.

void PHYSFS_permitirEnlacesSimbolicos (int permitir)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (transparentemente) el archivo al que apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas a abrir y fallará si lo es. De lo contrario, el enlace podría llevarte fuera de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un parámetro distinto de cero. Ten en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sientas que existe un peligro específico al permitirlos, deberías permitirlos.

Los enlaces simbólicos solo se verifican explícitamente al tratar con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar tus rutas de búsqueda y escritura, etc., nunca se verifican los enlaces simbólicos.

Por favor, ten en cuenta que PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignora y trataría la consulta como si la ruta no existiera en absoluto.

El permiso de enlace simbólico se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

permitir distinto de cero para permitir enlaces simbólicos, cero para denegar el enlace.

Advertencia

Esto es para asuntos avanzados y complejos. No lo necesita a menos que realmente sepa lo que está haciendo. La mayoría de las aplicaciones no lo necesitarán.

Una vez que esta función se completa con éxito, PhysicsFS podrá admitir archivos de este tipo hasta que vuelva a anular el registro del archivador.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convierte una cadena UTF-8 a una cadena Latin1. Las cadenas Latin1 son de 8 bits por carácter: una codificación popular de "ASCII alto".

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, asigna un búfer con el doble del tamaño del búfer de origen. UTF-8 expande los puntos de código latin1 mayores a 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el búfer de destino se truncarán, pero siempre se terminarán con null y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

Por favor, ten en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías estar convirtiéndote lejos de ella en todo momento.

Parámetros

src Cadena de origen terminada en null en formato Latin1.
dst Búfer para almacenar la cadena UTF-8 convertida.
len Tamaño, en bytes, del búfer de destino.
