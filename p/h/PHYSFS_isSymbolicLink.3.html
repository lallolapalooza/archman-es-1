DESCRIPTION

The physfs library provides an abstraction layer for accessing data files. It allows developers to treat archives (like ZIP files) and directories as a single unified filesystem. This can simplify game development by allowing assets to be packed into archives without changing the application code that accesses them.

The library supports various endiannesses for reading and writing data, handling character encoding conversions (UTF-8, UCS-2, UCS-4, Latin-1), and provides functions for managing the search path, enumerating files, and obtaining file information.

Key functionalities include:

  • Byte Order Swapping: Functions to swap byte order for different integer types (16-bit, 32-bit, 64-bit) between little-endian, big-endian, and the platform's native byte order.
  • Reading and Writing Data: Functions to read and write various sized integers in specific endiannesses from/to PHYSFS_File handles.
  • Character Encoding: Functions for converting between different character encodings (UTF-8, UCS-2, UCS-4, Latin-1) and performing case-insensitive string comparisons.
  • Filesystem Abstraction: Functions to mount and unmount archives and directories, manage the search path, and enumerate files within directories.
  • Error Handling: Functions to retrieve the last error code and its description.
  • Allocator Hooking: Ability to provide custom memory allocation routines.
  • Preference Directory: Function to get the platform-specific directory for user preferences or configuration files.
  • Archive Handling: Support for registering and deregistering custom archive formats.

PHYSFS_VERSION( _x)

This macro is used to determine the PhysicsFS version that the program was compiled against. It fills in a PHYSFS_Version structure pointed to by _x with the major, minor, and patch version numbers.

Example:

    PHYSFS_Version version;
    PHYSFS_VERSION(&version);
    // Now version.major, version.minor, and version.patch contain the library version.
structure with the version of the library you compiled against. This is determined by what header the compiler uses. Note that if you dynamically linked the library, you might have a slightly newer or older version at runtime. That version can be determined with PHYSFS_getLinkedVersion(), which, unlike PHYSFS_VERSION, is not a macro.

typedef void(* physfs_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Function signature for callbacks that enumerate files.

Warning

As of PhysicsFS 2.1, Use PHYSFS_EnumerateCallback with PHYSFS_enumerate() instead; it gives you more control over the process.

These are used to report a list of directory entries to an original caller, one file/dir/symlink per callback. All strings are UTF-8 encoded. Functions should not try to modify or free any string's memory.

These callbacks are used, starting in PhysicsFS 1.1, as an alternative to functions that would return lists that need to be cleaned up with PHYSFS_freeList(). The callback means that the library doesn't need to allocate an entire list and all the strings up front.

Be aware that promised data ordering in the list versions are not necessarily so in the callback versions. Check the documentation on specific APIs, but strings may not be sorted as you expect and you might get duplicate strings.

enum PHYSFS_ErrorCode

Values that represent specific causes of failure. Most of the time, you should only concern yourself with whether a given operation failed or not, but there may be occasions where you plan to handle a specific failure case gracefully, so we provide specific error codes.

Most of these errors are a little vague, and most aren't things you can fix...if there's a permission error, for example, all you can really do is pass that information on to the user and let them figure out how to handle it. In most these cases, your program should only care that it failed to accomplish its goals, and not care specifically why.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtiene una lista de archivos de un directorio de ruta de búsqueda, utilizando una función de devolución de llamada definida por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego construye una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. Más bien, llama a una función especificada por la aplicación una vez por cada elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // dame más datos, por favor.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

No se garantiza que los elementos enviados a la función de devolución de llamada estén en ningún orden en absoluto. No se realiza ninguna ordenación en este nivel, y si la necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza la ordenación alfabética. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. *Cualquier ordenación que encuentre en estas* *devoluciones de llamada es pura suerte. No confíe en ella.* A medida que recorre toda la lista de archivos, es posible que reciba nombres de archivo duplicados.

Esta API y las propias funciones de devolución de llamada son capaces de informar errores. Antes de esta API, las funciones de devolución de llamada tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS en sí tenía un problema (error de disco o similar), no podía informarlo a la aplicación que lo llamaba, simplemente tendría que omitir elementos o dejar de enumerar directamente, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su función de devolución de llamada tiene el control si desea que la enumeración se detenga temprano. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su función de devolución de llamada.

Parámetros

dir Directorio, en notación independiente de la plataforma, a enumerar.
c Función de devolución de llamada para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados a la función de devolución de llamada. Puede ser NULL.

Devoluciones

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si la función de devolución de llamada devuelve PHYSFS_ENUM_STOP para detenerse temprano, esto se considerará un éxito. Las funciones de devolución de llamada que devuelvan PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezca el código de error en PHYSFS_ERR_APP_CALLBACK.

Advertencia

En las versiones de PhysicsFS anteriores a la 2.1, esta función devolvía tantos elementos como pudiera frente a una condición de error (falta de memoria, error de E/S de disco, etc.). char **rc = PHYSFS_enumerateFiles("savegames");

for (i = rc; *i != NULL; i++)

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appen(d aToPath)

Añadir un directorio o archivo a la ruta de búsqueda. Si es un duplicado, el registro no se añade de nuevo, incluso si la función se completa con éxito. No puedes añadir el mismo archivo a dos diferentes mountpoints: la verificación de duplicados se realiza contra el archivo y no contra el mountpoint.

Cuando montas un directorio, se añade a un sistema de archivos virtual... todos los archivos de todos los directorios montados se interpolan en una sola estructura de árbol hierárquica. Dos directorios montados en el mismo lugar (o un directorio con archivos que superponen otro mountpoint) pueden tener archivos superpuestos: en ese caso, el archivo más antiguo en la ruta de búsqueda se selecciona, y los otros archivos son inaccesibles para la aplicación. Esto permite utilizar los directorios para reemplazar revisiones previas; puedes usar el mecanismo de montaje para colocar directorios en un punto específico en el árbol de archivos y prevenir superposiciones; esto es útil para modos descargables que puedan sobreponerse sobre los datos de la aplicación o entre sí, por ejemplo.

El mountpoint no necesita existir previamente al montaje, lo cual es diferente de lo que se espera en el concepto Unix de "montar" conocido por los usuarios. Además, más de un directorio puede montarse en el mismo mountpoint, o los mountpoints y contenidos de directorios pueden superponerse... el mecanismo de interpolación sigue funcionando normalmente.

int PHYSFS_setAllocator(const PHYSFS_Allocator* allocator)

Conecta tus propias rutinas de asignación en PhysicsFS. (Esto es para un uso limitado y avanzado. Si no ve inmediatamente una necesidad para ello, probablemente pueda ignorarlo para siempre).

Por defecto, PhysicsFS usará lo que sea razonable para una plataforma para gestionar la memoria dinámica (generalmente malloc/realloc/free de ANSI C, pero algunas plataformas pueden usar algo diferente), pero en algunos casos poco comunes, la aplicación podría querer un mayor control sobre la gestión de memoria de la biblioteca. Esto le permite redirigir PhysicsFS para usar sus propias rutinas de asignación en su lugar. Solo puede llamar a esta función antes de PHYSFS_init(); si la biblioteca está inicializada, rechazará sus esfuerzos por cambiar el asignador en medio del proceso. Puede llamar a esta función después de PHYSFS_deinit() si está dispuesto a cerrar la biblioteca y reiniciarla con un nuevo asignador; esta es una operación segura y compatible. El asignador permanece intacto entre las llamadas de deinit/init. Si desea volver al asignador predeterminado de la plataforma, pase un NULL aquí.

Si no está seguro de qué hacer con esta función de inmediato, puede ignorarla por completo.

Parámetros

allocator Estructura que contiene los puntos de entrada de su asignador.

Retorna

Cero en caso de fallo, distinto de cero en caso de éxito. Esta llamada solo falla cuando se usa entre llamadas a PHYSFS_init() y PHYSFS_deinit().

int PHYSFS_ucs4stricmp (const PHYSFS_uint32 * str1, const PHYSFS_uint32 * str2)

Comparación insensible a mayúsculas y minúsculas de dos cadenas UCS-4. Esta es una sustitución de strcasecmp/stricmp que espera que ambas cadenas estén en formato UCS-4 (también conocido como UTF-32). Realiza un "plegado de mayúsculas" para decidir si los códigos Unicode en las cadenas coinciden.

Devuelve la cadena que es "mayor" que la otra, pero ten en cuenta que esto no necesariamente significa nada: 'a' puede ser "menor" que 'b', pero un carácter japonés no tiene una relación significativa con una letra griega en términos alfabéticos. Sin embargo, la capacidad de asignar un valor confiable permite algoritmos de ordenación, aunque no sea del todo razonable. En casi todos los casos, se trata del valor devuelto como "igual" o "no igual".

Al igual que stricmp, espera que ambas cadenas terminen en NULL.

Parámetros

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Retorno

-1 si str1 es "menor" que str2, 1 si es "mayor", 0 si son iguales.

void PHYSFS_utf8FromLatin1(const char *src, char *dst, PHYSFS_uint64 len)

Convierte una cadena Latin1 a una cadena UTF-8. Las cadenas Latin1 son de 8 bits por carácter: una popular codificación "ASCII superior".

Para asegurar que el búfer de destino sea lo suficientemente grande para la conversión, por favor, asigna un búfer que sea el doble del tamaño del búfer de origen. UTF-8 expande los puntos de código Latin1 mayores de 127 de 1 a 2 bytes, por lo que la cadena puede crecer en algunos casos.

Las cadenas que no quepan en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

Por favor, ten en cuenta que no proporcionamos un conversor de UTF-8 a Latin1, ya que Latin1 no puede expresar la mayoría de los puntos de código Unicode. Es una codificación heredada; deberías alejarte de ella en todo momento.

Parámetros

src Cadena de origen terminada en nulo en formato Latin1.
dst Búfer para almacenar la cadena UTF-8 convertida.
len Tamaño, en bytes, del búfer de destino.

void PHYSFS_utf8FromUcs2(const PHYSFS_uint16 *src, char *dst, PHYSFS_uint64 len)

Convierte una cadena UCS-2 a una cadena UTF-8.

Advertencia

casi con toda seguridad deberías usar PHYSFS_utf8FromUtf16(), que estuvo disponible en PhysicsFS 2.1, a menos que sepas lo que estás haciendo.

Esta función no informará de un error si hay valores UCS-2 inválidos en la cadena de origen. Los reemplazará con un carácter '?' y continuará.

Las cadenas que no quepan en el búfer de destino serán truncadas, pero siempre estarán terminadas en nulo y nunca tendrán una secuencia UTF-8 incompleta al final. Si la longitud del búfer es 0, esta función no hace nada.

int PHYSFS_utf8stricmp(const char *str1, const char *str2)

Comparación insensible a mayúsculas y minúsculas de dos cadenas UTF-8. Este es un reemplazo de strcasecmp/stricmp que espera que ambas cadenas estén en codificación UTF-8. Hará un "plegado de mayúsculas" para decidir si los puntos de código Unicode en las cadenas coinciden.

Si ambas cadenas son exclusivamente caracteres ASCII de bajo nivel, esto hará lo correcto, ya que también es UTF-8 válido. ¡Si hay algún carácter ASCII superior, esto no hará lo que esperas!

Informará qué cadena es "mayor que" la otra, pero ten en cuenta que esto no significa necesariamente nada: 'a' puede ser "menor que" 'b', pero un kuten japonés no tiene una relación alfabética significativa con una lambda griega, pero poder asignar un "valor" fiable hace posibles los algoritmos de ordenación, aunque no del todo sensatos. La mayoría de los casos deberían tratar el valor de retorno como "igual" o "no igual".

Al igual que stricmp, esto espera que ambas cadenas estén terminadas en nulo.

Parámetros

str1 Primera cadena a comparar.
str2 Segunda cadena a comparar.

Retorna

-1 si str1 es "menor que" str2, 1 si es "mayor que", 0 si son iguales.

PHYSFS_sint64 PHYSFS_writeBytes (PHYSFS_File * handle, const void * buffer, PHYSFS_uint64 len)

Escribe datos en un manejador de archivo PhysicsFS. El archivo debe estar abierto para escritura.

Por favor, ten en cuenta que aunque (len) es un entero sin signo de 64 bits, estás limitado a 63 bits (9223372036854775807 bytes), por lo que podemos devolver un valor negativo en caso de error. Si la longitud es mayor que 0x7FFFFFFFFFFFFFFF, esta función fallará inmediatamente. Para sistemas sin un tipo de dato de 64 bits, estás limitado a 31 bits (0x7FFFFFFF, o 2147483647 bytes). Confiamos en que la mayoría de las cosas no necesitarán hacer múltiples gigabytes de E/S en una sola llamada de todos modos, ¡pero ¿por qué limitar las cosas?

número de bytes escritos. Esto puede ser menor que (len); en el caso de un error, el sistema puede intentar escribir tantos bytes como sea posible, por lo que puede ocurrir una escritura incompleta.
