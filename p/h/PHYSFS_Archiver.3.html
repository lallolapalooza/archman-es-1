Descripción detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados. No lo necesitas a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo de archivador y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han limitado a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivos de archivador.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo de archivador que no es proporcionado directamente por PhysicsFS: tal vez algún formato propietario que solo su aplicación necesita entender.

Internamente, todo el soporte de archivador incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS mismo.

Un archivador se agrega al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivador dado puede ser manejado con su archivador, se le dará el control según corresponda.

Estos métodos tratan con identificadores de directorio. Tiene una instancia de su archivador, y genera un identificador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el archivador en sí; la aplicación puede usar simplemente variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para comprobar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de retornar. PhysicsFS pasará estos errores a la aplicación sin modificar en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos en sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, su PHYSFS_Archiver puede asumir que el bloqueo se maneja por usted siempre que el PHYSFS_Io que devuelva de PHYSFS_open* no cambie ningún estado de su Archivador, ya que el PHYSFS_Io no estará tan agresivamente protegido.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluido el PHYSFS_Io original y el propio (opaque), si corresponde. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, para que pueda desecharla al retornar de la devolución de llamada. (dirname) está en notación independiente de la plataforma. Si tiene un error, llame a PHYSFS_SetErrorCode() con el código que parezca apropiado y retorne PHYSFS_ENUM_ERROR. Si la devolución de llamada retorna PHYSFS_ENUM_ERROR, por favor llame a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y retorne PHYSFS_ENUM_ERROR también. No llame a la devolución de llamada de nuevo bajo ninguna circunstancia. Si la devolución de llamada retorna PHYSFS_ENUM_STOP, deje de enumerar y retorne PHYSFS_ENUM_STOP también. No llame a la devolución de llamada de nuevo bajo ninguna circunstancia. No establezca un código de error en este caso. Las devoluciones de llamada solo deben retornar un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene comportamiento indefinido. Mientras la devolución de llamada haya retornado PHYSFS_ENUM_OK y usted no haya experimentado ningún error propio, continúe enumerando hasta que termine y luego retorne PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate retorna cero o no cero (éxito o fracaso), así que ¡ten en cuenta que este puntero de función retorna valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Se utiliza para identificar su archivador y se retorna en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivador. Si la aplicación está intentando crear varios directorios, PhysicsFS los dividirá en varias llamadas antes de pasarlos a su controlador. Si el archivo es de solo lectura, esta operación debería fallar. Retorna un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llame a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivador para añadir. Si el archivo no existe, debería crearse. La posición de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Retorna NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Retorna no-NULL en caso de éxito. El puntero retornado se pasará como parámetro "opaque" para futuras llamadas de archivo.

NAME

PHYSFS_Archiver - An archive handling interface.

SYNOPSIS


#include <physfs.h>

struct PHYSFS_Archiver {
    PHYSFS_uint32 version;
    int (*openArchive) (const char *filename, const void *data, PHYSFS_uint32 dataSize, int forWrite, void **opaque, int *claimed);
    PHYSFS_Io *(*openRead) (void *opaque, const char *fn);
    PHYSFS_Io *(*openWrite) (void *opaque, const char *filename);
    int (*remove) (void *opaque, const char *filename);
    int (*stat) (void *opaque, const char *fn, PHYSFS_Stat *stat);
};

Detailed Description

This is the interface that all archive modules must implement.

Field Documentation

int(* openArchive) (const char *filename, const void *data, PHYSFS_uint32 dataSize, int forWrite, void **opaque, int *claimed)

This function is called when you attempt to mount an archive. (filename) is the name of the file on disk that we're trying to mount as an archive. (data) and (dataSize) are only relevant if you're mounting from memory, not a file. If you're mounting from memory, (filename) will be NULL.

(forWrite) is true if we intend to write to the archive, false otherwise. You should fail if you don't support writing to the archive type and (forWrite) is true.

(opaque) is a pointer to a pointer. You should set this to a pointer to a structure that contains all the information needed to access the archive later. For example, a zip archive might store the file handle and list of files. A read-only archive might just set this to NULL if no per-archive data is needed.

(claimed) is a pointer to an integer. You should set this to 1 if you recognize the archive type, even if you fail to open it for some reason. This is used to decide if we should stop trying other archivers if you fail to open it. For example, the .zip archiver will set this to 1 for something that's got a .zip file signature, even if it failed because the file was also truncated. No sense in trying other archivers here, we already tried to handle it with the appropriate implementation!. Return NULL on failure and set (claimed) appropriately. If no archiver opened the archive or set (claimed), PHYSFS_mount() will report PHYSFS_ERR_UNSUPPORTED. Otherwise, it will report the error from the archiver that claimed the data through (claimed). Return non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later calls.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Open a file in this archive for reading. This filename, (fnm), is in platform-independent notation. Fail if the file does not exist. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Open a file in this archive for writing. If the file does not exist, it should be created. If it exists, it should be truncated to zero bytes. The writing offset should be the start of the file. If the archive is read-only, this operation should fail. This filename is in platform-independent notation. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Delete a file or directory in the archive. This same call is used for both files and directories; there is not a separate rmdir() call. Directories are only meant to be removed if they are empty. If the archive is read-only, this operation should fail.

Return non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtain basic file metadata. On success, fill in all the fields in (stat), using reasonable defaults for fields that apply to your archive.

Returns non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.
