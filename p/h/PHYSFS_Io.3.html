Advertencia

Esto es algo avanzado y complejo. No lo necesitas a menos que realmente sepas lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionó acceso al sistema de archivos físico y a los archivos dentro de ese sistema de archivos. Sin embargo, a veces necesitas más potencia que esto. Quizás necesites proporcionar un archivo que esté completamente contenido en RAM, o necesites conectar alguna otra API de E/S de archivos a PhysicsFS, o necesites traducir los bits (quizás tienes un archivo .zip estándar cifrado, y necesitas descifrarlo sobre la marcha para el desarchiver zip desprevenido).

Un PHYSFS_Io es la interfaz que utilizan los Archivers para obtener datos de archivos. Históricamente, esto se ha mapeado a E/S de archivos al sistema de archivos físico, pero a partir de PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de E/S en tiempo de ejecución.

Esta interfaz no es necesariamente un buen ajuste universal para E/S. Hay algunos requisitos a tener en cuenta:

  • Solo realizan E/S bloqueante (al menos, por ahora).
  • Necesitan ser capaces de duplicarse. Si tienes un manejador de archivo de fopen(), necesitas poder crear un clon único de él (para que tengamos dos manejadores del mismo archivo que puedan buscar/leer/etc. sin interferir entre sí).
  • Necesitan conocer el tamaño de todo su conjunto de datos.
  • Necesitan poder buscar y rebobinar bajo demanda.

...en resumen, probablemente no escribirás una implementación HTTP.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Io sean seguras para hilos en sí mismas. Bajo el capó, donde PhysicsFS las utiliza, la biblioteca proporciona sus propios bloqueos. Si planeas usarlas directamente desde hilos separados, deberías usar mutex para protegerlas, o no usar el mismo PHYSFS_Io desde dos hilos al mismo tiempo.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Limpiar y liberar la instancia de E/S. Liberar los recursos asociados, incluido (opaque) si es aplicable.

Esta función siempre debe tener éxito: como tal, devuelve void. El sistema puede llamar a tu método flush() antes que a este. Puedes reportar un error allí si es necesario. Este método aún puede ser llamado si flush() falla, en cuyo caso tendrás que abandonar los datos no vaciados y otras condiciones de error, y limpiar.

Una vez que se llama a este método para una instancia dada, el sistema asumirá que es inseguro volver a tocar esa instancia y descartará cualquier referencia a ella.

Parámetros

s La instancia de E/S a destruir.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Duplicar esta instancia de E/S. Esto necesita resultar en una copia completa de este PHYSFS_Io, que pueda vivir completamente de forma independiente. La copia debe poder realizar todas sus operaciones sin alterar la original, incluido que cada objeto pueda ser destruido por separado (así, por ejemplo: no pueden compartir un manejador de archivo; cada uno necesita el suyo).

Si no puedes duplicar un manejador, es legal devolver NULL, pero es casi seguro que necesitas esta funcionalidad si quieres usar esto para que PHYSFS_Io respalde un archivo.

Parámetros

io La instancia de E/S a duplicar.

Devoluciones

Un nuevo valor para el campo (opaque) de un stream, o NULL en caso de error.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vaciar recursos a los medios, o a donde sea. Esta es la oportunidad de reportar errores en escrituras que previamente se declararon exitosas, pero que aún tenían la posibilidad de fallar. Este método puede ser NULL si no es necesario vaciar.

Este método puede ser llamado antes de destroy(), ya que puede reportar errores y destroy() no puede. También puede ser llamado en otros momentos.

Parámetros

io La instancia de E/S a vaciar.

Devoluciones

Cero en caso de error, distinto de cero en caso de éxito.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Determinar el tamaño del conjunto de datos de la instancia de E/S. Devolver el número de bytes disponibles en el archivo, o -1 si no se puede determinar. Un error casi seguramente será fatal para el uso posterior de este stream, por lo que no puedes dejar esto sin implementar.

Parámetros

io La instancia de E/S a consultar.

Devoluciones

Tamaño total, en bytes, del conjunto de datos.

void* PHYSFS_Io::opaque

Datos de instancia para esta estructura. Cada instancia tiene un puntero asociado que se puede usar para almacenar lo que desee. Este puntero es por instancia del stream, por lo que presumiblemente cambiará al llamar a duplicate(). Esto se puede liberar durante el método destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Leer más datos. Leer (len) bytes de la interfaz, en la posición actual de E/S, y almacenarlos en (buffer). La posición actual de E/S debe avanzar por el número de bytes leídos con éxito.

No tienes que implementar esto; configúralo a NULL si no está implementado. Esto solo se usará si el archivo se abre para lectura. Si se establece en NULL, se utilizará una implementación predeterminada que informa inmediatamente de un error.

Parámetros

io La instancia de E/S de la que leer.
buf El búfer para almacenar los datos. Debe tener al menos (len) bytes de longitud y no puede ser NULL.
len El número de bytes a leer de la interfaz.

Devoluciones

número de bytes leídos del archivo, 0 en fin de archivo (EOF), -1 en caso de fallo completo.

int(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Mover la posición de E/S a un desplazamiento de byte dado desde el inicio. Este método mueve la posición de E/S, por lo que la próxima lectura/escritura será del byte en el desplazamiento (offset). Las búsquedas más allá del final del archivo se pueden permitir o no, dependiendo de la implementación del archivo subyacente.

No tienes que implementar esto; configúralo a NULL si no está implementado. Esto solo se usará si el archivo se abre para lectura o escritura. Si se establece en NULL, se utilizará una implementación predeterminada que informa inmediatamente de un error.

Parámetros

io La instancia de E/S a buscar.
offset El desplazamiento, en bytes, desde el inicio del archivo.

Devoluciones

Cero en caso de error, distinto de cero en caso de éxito.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Informar la posición actual de E/S. Devuelve el número de bytes desde el inicio del archivo hasta la posición de E/S actual. El valor de retorno debe ser el número de bytes que se han leído o escrito hasta ahora.

Este método debe implementarse siempre que la posición de E/S sea importante. Si no se implementa, se producirá un error.

Parámetros

io La instancia de E/S a consultar.

Devoluciones

La posición actual de E/S, en bytes, o -1 en caso de error.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Escribir más datos. Escribir (len) bytes del (buffer) en la interfaz, en la posición actual de E/S. La posición actual de E/S debe avanzar por el número de bytes escritos con éxito.

No tienes que implementar esto; configúralo a NULL si no está implementado. Esto solo se usará si el archivo se abre para escritura. Si se establece en NULL, se utilizará una implementación predeterminada que informa inmediatamente de un error.

Parámetros

io La instancia de E/S en la que escribir.
buffer El búfer que contiene los datos a escribir. No puede ser NULL.
len El número de bytes a escribir en la interfaz.

Devoluciones

El número de bytes escritos en el archivo, o -1 en caso de fallo completo.

PHYSFS_uint32 PHYSFS_Io::version

Información de compatibilidad binaria.

Esto se usa para garantizar que la estructura de PHYSFS_Io que le pasamos a usted tenga el formato correcto, y para permitir que PhysicsFS evolucione en el futuro. Actualmente, esto debe establecerse en `1'.

PHYSFS_Io(3) — physfs

NAME

PHYSFS_Io — An abstract interface to a filesystem object.

SYNOPSIS

#include <physfs.h>

A structure representing an abstract interface to a filesystem object. Used for archives, regular files, etc.

The structure contains function pointers that operate on an instance of this structure. This instance is passed to each function pointer as the first argument.

typedef struct PHYSFS_Io {
    PHYSFS_sint64 (*read) (struct PHYSFS_Io *io, void *buffer,
                        PHYSFS_uint64 len);
    PHYSFS_sint64 (*write) (struct PHYSFS_Io *io, const void *buffer,
                         PHYSFS_uint64 len);
    PHYSFS_sint64 (*seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset);
    PHYSFS_sint64 (*tell) (struct PHYSFS_Io *io);
    void (*close) (struct PHYSFS_Io *io);
    PHYSFS_uint32 version;
    void *opaque;
} PHYSFS_Io;

Detailed Description

The application only ever sees a PHYSFS_Io structure when it calls PHYSFS_openRead(), PHYSFS_openWrite() or PHYSFS_openAppend(). Applications will never create or destroy them, they are managed entirely by the library.

The library may pass a pointer to an existing PHYSFS_Io structure in the opaque member. This is opaque data, and may contain any data necessary to operate on the actual underlying filesystem object.

void(* PHYSFS_Io::close) (struct PHYSFS_Io *io)

Close the i/o handle. All buffered data should be flushed before this is called. This function may be called even if no other function in this struct has been called (e.g., if PHYSFS_openRead() fails after creating the structure). No error checking is done on the return value of this function.

Parameters

io The i/o instance to close.

void * PHYSFS_Io::opaque

This member is reserved for the user. It can be used to store any data you need when implementing the virtual filesystem yourself.

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read data from the current i/o position. Read up to (len) bytes from the interface into (buffer). The current i/o position should move ahead by the number of bytes successfully read.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading. If set to NULL, a default implementation that immediately reports failure will be used.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The maximum number of bytes to read.

Returns

number of bytes read from file, -1 if error.

PHYSFS_sint64(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Set the new i/o position. The i/o position should be set to (offset) bytes from the beginning of the file. If you don't support seeking, you should set this to NULL and report an error if it is ever called.

Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
