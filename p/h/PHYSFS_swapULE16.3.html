PHYSFS_enumerate

Esto es lo mismo que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, excepto que puede devolver un resultado del callback: a saber: si está buscando algo específico, una vez que lo encuentra, puede indicarle a PhysicsFS que deje de enumerar más. Esto se usa con PHYSFS_enumerate(), que esperamos que hayamos hecho bien esta vez. :)

Parámetros

data Puntero de datos definido por el usuario, pasado desde la API que finalmente llamó al callback.
origdir Una cadena que contiene la ruta completa, en notación independiente de la plataforma, del directorio que contiene este archivo. En la mayoría de los casos, este es el directorio sobre el cual solicitó la enumeración, pasado en el callback para su conveniencia.
fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otros callbacks que se han disparado, y no contendrá la ruta completa. Puede recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

Retorna

Un valor de PHYSFS_EnumerateCallbackResult. Todos los demás valores están (actualmente) indefinidos; no los use.

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Firma de función para callbacks que enumeran archivos.

Advertencia

A partir de PhysicsFS 2.1, use PHYSFS_EnumerateCallback con PHYSFS_enumerate() en su lugar; le brinda más control sobre el proceso.

Se utilizan para informar una lista de entradas de directorio a un llamador original, un archivo/directorio/enlace simbólico por callback. Todas las cadenas están codificadas en UTF-8. Las funciones no deben intentar modificar ni liberar la memoria de ninguna cadena.

Estos callbacks se utilizan, a partir de PhysicsFS 1.1, como una alternativa a las funciones que devolverían listas que necesitan ser limpiadas con PHYSFS_freeList(). El callback significa que la librería no necesita asignar una lista completa y todas las cadenas por adelantado.

Tenga en cuenta que el orden de los datos prometido en las versiones de lista no es necesariamente así en las versiones de callback. Consulte la documentación de las API específicas, pero las cadenas pueden no estar ordenadas como espera y podría obtener cadenas duplicadas.

Parámetros

data Puntero de datos definido por el usuario, pasado desde la API que finalmente llamó al callback.
origdir Una cadena que contiene la ruta completa, en notación independiente de la plataforma, del directorio que contiene este archivo. En la mayoría de los casos, este es el directorio sobre el cual solicitó la enumeración, pasado en el callback para su conveniencia.
fname El nombre del archivo que se está enumerando. Puede que no esté en orden alfabético en comparación con otros callbacks que se han disparado, y no contendrá la ruta completa. Puede recrear la ruta completa con $origdir/$fname ... El archivo puede ser un subdirectorio, un archivo, un enlace simbólico, etc.

Valores que representan causas específicas de fallo. La mayoría de las veces, solo debería preocuparse por si una operación dada falló o no, pero puede haber ocasiones en las que planee manejar un caso de fallo específico graciosamente, por lo que proporcionamos códigos de error específicos.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtener una lista de archivos de un directorio de la ruta de búsqueda, utilizando un callback definido por la aplicación, con informes de errores. Internamente, PHYSFS_enumerateFiles() simplemente llama a esta función y luego crea una lista antes de devolverla a la aplicación, por lo que la funcionalidad es idéntica excepto por cómo se representa la información a la aplicación.

A diferencia de PHYSFS_enumerateFiles(), esta función no devuelve una matriz. En cambio, llama a una función especificada por la aplicación una vez por cada elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Tenemos [%s] en [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // deme más datos, por favor.
}
// ...
PHYSFS_enumerate("/alguna/ruta", printDir, NULL);

No se garantiza que los elementos enviados al callback estén en ningún orden lo que sea. No se realiza ninguna ordenación en este nivel, y si la necesita, probablemente debería usar PHYSFS_enumerateFiles() en su lugar, que garantiza la ordenación alfabética. Esta forma informa lo que se descubre en cada archivo antes de pasar al siguiente. Incluso dentro de un archivo, no podemos garantizar el orden en que descubrirá los datos. Cualquier ordenación que encuentre en estos callbacks es pura suerte. No confíe en ella. Dado que recorre toda la lista de archivos, puede recibir nombres de archivo duplicados.

Esta API y los propios callbacks son capaces de informar de errores. Antes de esta API, los callbacks tenían que aceptar cada elemento enumerado, incluso si solo buscaban algo específico y querían detenerse después de eso, o tenían un error grave y no podían alertar a nadie. Además, si el propio PhysicsFS tenía un problema (error de disco o similar), no podía informarlo a la aplicación que lo llamaba, solo tenía que omitir elementos o dejar de enumerar directamente, y el llamador no sabría que había perdido algunos datos en el camino.

Ahora el llamador puede estar seguro de que obtuvo un conjunto de datos completo, y su callback tiene control si desea que la enumeración se detenga temprano. Consulte la documentación de PHYSFS_EnumerateCallback para obtener detalles sobre cómo debe comportarse su callback.

Parámetros

dir Directorio, en notación independiente de la plataforma, a enumerar.
c Función de callback para notificar sobre elementos de la ruta de búsqueda.
d Datos definidos por la aplicación pasados al callback. Puede ser NULL.

Devoluciones

Distinto de cero en caso de éxito, cero en caso de fallo. Use PHYSFS_getLastErrorCode() para obtener el error específico. Si el callback devuelve PHYSFS_ENUM_STOP para detenerse temprano, esto se considerará un éxito. Los callbacks que devuelven PHYSFS_ENUM_ERROR harán que esta función devuelva cero y establezca el código de error en PHYSFS_ERR_APP_CALLBACK.

char ** PHYSFS_enumerateFiles (const char * dir)

Obtener una lista de archivos de un directorio de la ruta de búsqueda.

Advertencia

En versiones de PhysicsFS anteriores a la 2.1, esta función devolvía tantos elementos como fuera posible ante una condición de fallo (falta de memoria, error de E/S de disco, etc.). Dado que esto significaba que las aplicaciones no podían distinguir entre el éxito completo y el fallo parcial, y dado que la función siempre podía devolver NULL para informar de fallos catastróficos de todos modos, en PhysicsFS 2.1 la política de esta función cambió: devolverá una lista de resultados completos o devolverá NULL para cualquier fallo de cualquier tipo, para que podamos garantizar que la enumeración se completó y no hay lagunas en sus resultados.

Los directorios coincidentes se interpolan. Es decir, si "C:\mydir" está en la ruta de búsqueda y contiene un directorio "savegames" que contiene "x.sav", "y.sav" y "z.sav", y también hay un "C:\userdir" en la ruta de búsqueda que tiene un subdirectorio "savegames" con "w.sav", entonces el siguiente código:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * Tenemos [%s].\n", *i);
PHYSFS_freeList(rc);
* Tenemos [x.sav].
* Tenemos [y.sav].
* Tenemos [z.sav].
* Tenemos [w.sav]..fi
Siéntase libre de ordenar la lista como prefiera. Sin embargo, los datos devueltos siempre estarán libres de duplicados, y siempre estarán ordenados alfabéticamente (o mejor dicho: en orden Unicode sensible a mayúsculas/minúsculas) para usted.
No olvide llamar a PHYSFS_freeList() con el valor devuelto por esta función cuando haya terminado con él.
Parámetros
dir directorio en notación independiente de la plataforma a enumerar. 
Devoluciones
Matriz terminada en nulo de cadenas terminadas en nulo, o NULL para casos de fallo.

PHYSFS_mount

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. Agrega un archivo, contenido en un manejador PHYSFS_File, a la ruta de búsqueda.

Advertencia

A menos que tenga alguna necesidad especial de bajo nivel, debería usar PHYSFS_mount() en lugar de esta función.

¡Los archivos dentro de otros archivos pueden ser muy lentos! Si bien un PHYSFS_File puede buscar incluso cuando los datos están comprimidos, puede hacerlo retrocediendo al principio y descomprimiendo todo antes del punto de búsqueda. El uso normal de archivos puede realizar muchas búsquedas en segundo plano. Como tal, el uso normal de archivos podría resultar extremadamente molesto si se monta de esta manera. Planifique en consecuencia: si tiene, por ejemplo, un archivo .zip autoextraíble y desea montar algo dentro de él, comprima el contenido del archivo interno y asegúrese de que el archivo .zip externo no comprima el archivo interno también.

Esta función opera de manera similar a PHYSFS_mount(), pero toma un manejador PHYSFS_File en lugar de una ruta de archivo. Este manejador contiene todos los datos del archivo y se utiliza en lugar de un archivo real en el sistema de archivos físico. El PHYSFS_File puede estar respaldado por un archivo real en el sistema de archivos físico, pero no es necesariamente así. El uso más popular para esto es probablemente montar archivos almacenados dentro de otros archivos.

(newDir) debe ser una cadena única para identificar este archivo. Se utiliza para optimizar la selección del archivador (si lo nombra XXXXX.zip, podríamos probar primero el archivador ZIP, por ejemplo, o elegir directamente un archivador que solo pueda confiar en que los datos son válidos por la extensión del nombre de archivo). No necesita referirse a un archivo real en absoluto. Si la extensión del nombre de archivo no es útil, el sistema intentará con cada archivador hasta que uno funcione o ninguno de ellos lo haga. Este nombre de archivo debe ser único, ya que el sistema no le permitirá tener dos archivos con el mismo nombre.

(file) debe permanecer hasta que el archivo se desmonte. Cuando el archivo se desmonte, el sistema llamará a PHYSFS_close(file). Si necesita que este manejador sobreviva, tendrá que envolverlo en un PHYSFS_Io y usar PHYSFS_mountIo() en su lugar.

Si esta función falla, no se llama a PHYSFS_close(file).

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivos contienen archivos que son solo punteros a otros archivos. En el sistema de archivos físico, abrir un enlace de este tipo abrirá (de forma transparente) el archivo al que apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría sacarte de las rutas de escritura y búsqueda, y comprometer la seguridad.

Si desea asumir ese riesgo, llame a esta función con un parámetro distinto de cero. Tenga en cuenta que esto es más para aislar el lenguaje de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En términos generales, un usuario podría tener una razón legítima para configurar un enlace simbólico, por lo que a menos que sienta que hay un peligro específico en permitirlos, debería hacerlo.

Los enlaces simbólicos solo se verifican explícitamente cuando se trata con nombres de archivo en notación independiente de la plataforma. Es decir, al configurar sus rutas de búsqueda y escritura, etc., nunca se verifican los enlaces simbólicos.

El permiso de enlace simbólico se puede habilitar o deshabilitar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitado por defecto.

You can change an archive's root at any time, altering the interpolated file tree (depending on where paths shift, a different archive may be providing various files).
