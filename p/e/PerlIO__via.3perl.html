PerlIO::via(3perl) Guía de Programadores de Perl PerlIO::via(3perl)

NOMBRE

PerlIO::via - Clase auxiliar para capas PerlIO implementadas en perl

SINOPSIS

use PerlIO::via::Layer;
open($fh,"<:via(Layer)",...);
use Some::Other::Package;
open($fh,">:via(Some::Other::Package)",...);

DESCRIPCIÓN

El módulo PerlIO::via te permite desarrollar capas PerlIO en Perl, sin tener que meterte en los detalles de programación en C con XS como interfaz a Perl.

Un módulo de ejemplo, PerlIO::via::QuotedPrint, se incluye con Perl 5.8.0, y más módulos de ejemplo están disponibles en CPAN, como PerlIO::via::StripHTML y PerlIO::via::Base64. El módulo PerlIO::via::StripHTML por ejemplo, te permite decir:

use PerlIO::via::StripHTML;
open( my $fh, "<:via(StripHTML)", "index.html" );
my @line = <$fh>;

para obtener el texto de un archivo HTML en un array con todas las etiquetas HTML eliminadas automáticamente.

Ten en cuenta que si la capa se crea en el espacio de nombres PerlIO::via::, no tiene que estar completamente calificada. El módulo PerlIO::via prefijará el espacio de nombres PerlIO::via:: si el nombre de módulo especificado no existe como nombre de módulo completamente calificado.

MÉTODOS ESPERADOS

Para crear un módulo Perl que implemente una capa PerlIO en Perl (en lugar de en C usando XS como interfaz a Perl), necesitas proporcionar algunas de las siguientes subrutinas. Se recomienda crear estos módulos Perl en el espacio de nombres PerlIO::via::, para que puedan ser localizados fácilmente en CPAN y usar la característica de espacio de nombres predeterminado del propio módulo PerlIO::via.

Ten en cuenta que esta es un área de desarrollo reciente en Perl y que la interfaz descrita aquí está, por lo tanto, sujeta a cambios (y esperemos que tenga mejor documentación y más ejemplos).

En las descripciones de métodos a continuación, $fh será una referencia a un glob que puede ser tratado como un manejador de archivos Perl. Se refiere a la capa inferior. $fh no se pasa si la capa está en la parte inferior de la pila, por esta razón y para mantener un cierto nivel de "compatibilidad" con las clases TIEHANDLE, se pasa al final.

$class->PUSHED([$mode,[$fh]])
Debería devolver un objeto o la clase, o -1 en caso de fallo. (Comparar con TIEHANDLE.) Los argumentos son una cadena de modo opcional ("r", "w", "w+", ...) y un manejador de archivos para la capa PerlIO inferior. Obligatorio.

Cuando la capa se inserta como parte de una llamada "open", "PUSHED" se llamará antes de que ocurra la apertura real, ya sea a través de "OPEN", "SYSOPEN", "FDOPEN" o permitiendo que una capa inferior realice la apertura.

$obj->POPPED([$fh])
Opcional - se llama cuando la capa está a punto de ser eliminada.
$obj->UTF8($belowFlag,[$fh])
Opcional - si está presente, se llamará inmediatamente después de que PUSHED haya devuelto. Debería devolver un valor verdadero si la capa espera que los datos estén codificados en UTF-8. Si devuelve verdadero, el resultado es como si el llamador hubiera hecho 
":via(YourClass):utf8"

Si no está presente o si devuelve falso, entonces el flujo queda con el indicador UTF-8 desmarcado. El argumento $belowFlag será verdadero si hay una capa inferior y esa capa esperaba UTF-8.

$obj->OPEN($path,$mode,[$fh])
Opcional - si no está presente, una capa inferior realiza la apertura. Si está presente, se llama para aperturas normales después de que la capa sea insertada. Esta función está sujeta a cambios ya que no hay una forma fácil de hacer que una capa inferior realice la apertura y luego recuperar el control.
$obj->BINMODE([$fh])
Opcional - si no está presente, la capa se elimina en binmode($fh) o cuando se inserta ":raw". Si está presente, debería devolver 0 en éxito, -1 en error, o undef para eliminar la capa.
$obj->FDOPEN($fd,[$fh])
Opcional - si no está presente, una capa inferior realiza la apertura. Si está presente, se llama después de que la capa sea insertada para aperturas que pasan un descriptor de archivo numérico. Esta función está sujeta a cambios ya que no hay una forma fácil de hacer que una capa inferior realice la apertura y luego recuperar el control.
$obj->SYSOPEN($path,$imode,$perm,[$fh])
Opcional - si no está presente, una capa inferior realiza la apertura. Si está presente, se llama después de que la capa sea insertada para aperturas estilo sysopen que pasan un modo y permisos numéricos. Esta función está sujeta a cambios ya que no hay una forma fácil de hacer que una capa inferior realice la apertura y luego recuperar el control.
$obj->FILENO($fh)
Devuelve un valor numérico para un descriptor de archivo similar a Unix. Devuelve -1 si no hay uno. Opcional. El valor predeterminado es fileno($fh).
$obj->READ($buffer,$len,$fh)
Devuelve el número de octetos colocados en $buffer (debe ser undef para indicar un error o un entero no negativo menor o igual al mínimo de $len y la longitud del $buffer actualizado). Opcional. El valor predeterminado es usar FILL en su lugar.
$obj->WRITE($buffer,$fh)
Devuelve el número de octetos de $buffer que se han escrito correctamente.
$obj->FILL($fh)
Debería devolver una cadena para ser colocada en el buffer. Opcional. Si no se proporciona, se debe proporcionar READ o rechazar manejadores abiertos para lectura en PUSHED.
$obj->CLOSE($fh)
Debería devolver 0 en éxito, -1 en error. Opcional.
$obj->SEEK($posn,$whence,$fh)
Debería devolver 0 en éxito, -1 en error. Opcional. El valor predeterminado es fallar, pero es probable que eso cambie en el futuro.
$obj->TELL($fh)
Devuelve la posición del archivo. Opcional. El valor predeterminado está por determinar.
$obj->UNREAD($buffer,$fh)
Devuelve el número de octetos de $buffer que se han guardado correctamente para ser devueltos en futuras llamadas a FILL/READ. Opcional. El valor predeterminado es insertar datos en una capa temporal por encima de esta.
$obj->FLUSH($fh)
Vacía cualquier dato de escritura en búfer. Posiblemente también pueda ser llamado en manejadores legibles. Debería devolver 0 en éxito, -1 en error.
$obj->SETLINEBUF($fh)
Opcional. Sin retorno.
$obj->CLEARERR($fh)
Opcional. Sin retorno.
$obj->ERROR($fh)
Opcional. Devuelve el estado de error. El valor predeterminado es sin error hasta que se resuelva un mecanismo para señalar error (¿die?).
$obj->EOF($fh)
Opcional. Devuelve el estado de fin de archivo. El valor predeterminado es una función del valor de retorno de FILL o READ.

EJEMPLOS

Consulta el espacio de nombres PerlIO::via:: en CPAN para ver ejemplos de capas PerlIO implementadas en Perl. Para darte una idea de lo simple que puede ser la implementación de una capa PerlIO, aquí se incluye un ejemplo simple.

Ejemplo - un Manejador Hexadecimal

Dado el siguiente módulo, PerlIO::via::Hex:

package PerlIO::via::Hex;
sub PUSHED
{
 my ($class,$mode,$fh) = @_;
 # Al escribir, almacenamos los datos en búfer
 my $buf = '';
 return bless \$buf,$class;
}
sub FILL
{
 my ($obj,$fh) = @_;
 my $line = <$fh>;
 return (defined $line) ? pack("H*", $line) : undef;
}
sub WRITE
{
 my ($obj,$buf,$fh) = @_;
 $$obj .= unpack("H*", $buf);
 return length($buf);
}
sub FLUSH
{
 my ($obj,$fh) = @_;
 print $fh $$obj or return -1;
 $$obj = '';
 return 0;
}
1;

El siguiente código abre un manejador de salida que convertirá cualquier salida en un volcado hexadecimal de los bytes de salida: por ejemplo, "A" se convertirá en "41" (en máquinas basadas en ASCII, en plataformas EBCDIC la "A" se convertirá en "c1")

use PerlIO::via::Hex;
open(my $fh, ">:via(Hex)", "foo.hex");

y el siguiente código leerá el volcado hexadecimal y lo convertirá sobre la marcha de nuevo a bytes:

open(my $fh, "<:via(Hex)", "foo.hex");
