Perl::Critic(3pm) Documentación de Perl aportada por el usuario Perl::Critic(3pm)

NOMBRE

Perl::Critic - Criticar código fuente de Perl para las mejores prácticas.

SINOPSIS

use Perl::Critic;
my $archivo = shift;
my $critic = Perl::Critic->new();
my @violaciones = $critic->critique($archivo);
print @violaciones;

DESCRIPCIÓN

Perl::Critic es un framework extensible para crear y aplicar estándares de codificación a código fuente de Perl. Esencialmente, es un motor de análisis estático de código fuente. Perl::Critic se distribuye con varios módulos Perl::Critic::Policy que intentan hacer cumplir diversas directrices de codificación. La mayoría de los módulos Policy se basan en el libro de Damian Conway Perl Best Practices. Sin embargo, Perl::Critic no se limita a PBP e incluso admitirá Policies que contradigan a Conway. Puede habilitar, deshabilitar y personalizar esas Policies a través de la interfaz de Perl::Critic. También puede crear nuevos módulos Policy que se adapten a sus propios gustos.

Para una interfaz de línea de comandos para Perl::Critic, consulte la documentación de perlcritic. Si desea integrar Perl::Critic con su proceso de compilación, Test::Perl::Critic proporciona una interfaz adecuada para programas de prueba. Además, Test::Perl::Critic::Progressive es útil para aplicar gradualmente los estándares de codificación a código heredado. Para la máxima comodidad (a costa de cierta flexibilidad), consulte la pragmática criticism.

Si desea probar Perl::Critic sin instalar nada, hay un servicio web disponible en http://perlcritic.com. El servicio web aún no admite todas las funciones de configuración disponibles en la API nativa de Perl::Critic, pero debería darle una buena idea de lo que hace.

Además, ActivePerl incluye una interfaz gráfica muy elegante para Perl-Critic llamada "perlcritic-gui". Puede obtener una edición comunitaria gratuita de ActivePerl en http://www.activestate.com.

SOPORTE DE INTERFAZ

El módulo "Perl::Critic" se considera una clase pública. Cualquier cambio en su interfaz pasará por un ciclo de depreciación.

CONSTRUCTOR

"new( [ -profile => $ARCHIVO, -severity => $N, -theme => $cadena, -include => \@PATRONES, -exclude => \@PATRONES, -top => $N, -only => $B, -profile-strictness => $PROFILE_STRICTNESS_{WARN|FATAL|QUIET}, -force => $B, -verbose => $N ], -color => $B, -pager => $cadena, -allow-unsafe => $B, -criticism-fatal => $B)"
new()
Devuelve una referencia a un nuevo objeto Perl::Critic. La mayoría de los argumentos se pasan directamente a Perl::Critic::Config, pero los he descrito aquí también. El valor predeterminado para todos los argumentos se puede definir en su archivo .perlcriticrc. Consulte la sección "CONFIGURACIÓN" para obtener más información. Todos los argumentos son pares opcionales de clave-valor como sigue:

-profile es una ruta a un archivo de configuración. Si $ARCHIVO no está definido, Perl::Critic::Config intenta encontrar un archivo de configuración .perlcriticrc en el directorio actual y luego en su directorio de inicio. Alternativamente, puede establecer la variable de entorno "PERLCRITIC" para que apunte a un archivo en otra ubicación. Si no se puede encontrar un archivo de configuración, o si $ARCHIVO es una cadena vacía, entonces todas las Policies se cargarán con su configuración predeterminada. Consulte "CONFIGURACIÓN" para obtener más información.

-severity es el nivel de severidad mínimo. Solo los módulos Policy que tengan una severidad mayor que $N se aplicarán. Los valores de severidad son enteros que van de 1 (violaciones menos severas) a 5 (violaciones más severas). El valor predeterminado es 5. Para un "-profile" determinado, disminuir "-severity" generalmente revelará más violaciones de Policy. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc. Los usuarios pueden redefinir el nivel de severidad para cualquier Policy en su archivo .perlcriticrc. Consulte "CONFIGURACIÓN" para obtener más información.

Si le resulta difícil recordar si la severidad "5" es el nivel más o menos restrictivo, puede usar uno de estos valores con nombre:

NOMBRE DE SEVERIDAD   ...es equivalente a...   NÚMERO DE SEVERIDAD
--------------------------------------------------------
-severity => 'gentle'                     -severity => 5
-severity => 'stern'                      -severity => 4
-severity => 'harsh'                      -severity => 3
-severity => 'cruel'                      -severity => 2
-severity => 'brutal'                     -severity => 1

Los nombres reflejan cuán severamente se critica el código: una crítica "gentle" informa solo las violaciones más severas, y así sucesivamente hasta una crítica "brutal" que informa incluso las violaciones más menores.

-theme es una expresión especial que determina qué Policies aplicar según sus temas respectivos. Por ejemplo, lo siguiente cargaría solo las Policies que tengan un tema 'bugs' Y 'pbp':

my $critic = Perl::Critic->new( -theme => 'bugs && pbp' );

A menos que se proporcione explícitamente la opción "-severity", establecer "-theme" provoca silenciosamente que "-severity" se establezca en 1. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc. Consulte la sección "TEMAS DE POLICY" para obtener más información sobre los temas.

-include es una referencia a una lista de cadenas @PATRONES. Los módulos Policy que coinciden con al menos un "m/$PATRON/ixms" siempre se cargarán, independientemente de todas las demás configuraciones. Por ejemplo:

my $critic = Perl::Critic->new(-include => ['layout'], -severity => 4);

Esto haría que Perl::Critic aplicara todos los módulos Policy de "CodeLayout::*" a pesar de que tienen un nivel de severidad menor que 4. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc. También puede usar "-include" en conjunto con la opción "-exclude". Tenga en cuenta que "-exclude" tiene prioridad sobre "-include" cuando una Policy coincide con ambos patrones.

-exclude es una referencia a una lista de cadenas @PATRONES. Los módulos Policy que coinciden con al menos un "m/$PATRON/ixms" no se cargarán, independientemente de todas las demás configuraciones. Por ejemplo:

my $critic = Perl::Critic->new(-exclude => ['strict'], -severity => 1);

Esto haría que Perl::Critic no aplicara los módulos Policy "RequireUseStrict" y "ProhibitNoStrict" a pesar de que tienen un nivel de severidad mayor que 1. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc. También puede usar "-exclude" en conjunto con la opción "-include". Tenga en cuenta que "-exclude" tiene prioridad sobre "-include" cuando una Policy coincide con ambos patrones.

-single-policy es una cadena "PATRON". Solo se utilizará una política que coincida con "m/$PATRON/ixms". Las políticas que no coincidan se excluirán. Esta opción tiene prioridad sobre las opciones "-severity", "-theme", "-include", "-exclude" y "-only". Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.

-top es el número máximo de Violaciones a devolver cuando se clasifican por sus niveles de severidad. Debe ser un entero positivo. Las violaciones son estipuladas

OPTIONS

-top

This is a positive integer that specifies the maximum number of violations to report for each file. If not specified, then all violations will be reported. The Violations will be returned in the order that they occur within the file. Unless the "-severity" option is explicitly given, setting "-top" silently causes the "-severity" to be set to 1. You can set the default value for this option in your .perlcriticrc file.

-only is a boolean value. If set to a true value, Perl::Critic will only choose from Policies that are mentioned in the user's profile. If set to a false value (which is the default), then Perl::Critic chooses from all the Policies that it finds at your site. You can set the default value for this option in your .perlcriticrc file.

-profile-strictness is an enumerated value, one of "$PROFILE_STRICTNESS_WARN" in Perl::Critic::Utils::Constants (the default), "$PROFILE_STRICTNESS_FATAL" in Perl::Critic::Utils::Constants, and "$PROFILE_STRICTNESS_QUIET" in Perl::Critic::Utils::Constants. If set to "$PROFILE_STRICTNESS_FATAL" in Perl::Critic::Utils::Constants, Perl::Critic will make certain warnings about problems found in a .perlcriticrc or file specified via the -profile option fatal. For example, Perl::Critic normally only "warn"s about profiles referring to non-existent Policies, but this value makes this situation fatal. Correspondingly, "$PROFILE_STRICTNESS_QUIET" in Perl::Critic::Utils::Constants makes Perl::Critic shut up about these things.

-force is a boolean value that controls whether Perl::Critic observes the magical "## no critic" annotations in your code. If set to a true value, Perl::Critic will analyze all code. If set to a false value (which is the default) Perl::Critic will ignore code that is tagged with these annotations. See "BENDING THE RULES" for more information. You can set the default value for this option in your .perlcriticrc file.

-verbose can be a positive integer (from 1 to 11), or a literal format specification. See Perl::Critic::Violation for an explanation of format specifications. You can set the default value for this option in your .perlcriticrc file.

-unsafe directs Perl::Critic to allow the use of Policies that are marked as "unsafe" by the author. Such policies may compile untrusted code or do other nefarious things.

-color and -pager are not used by Perl::Critic but is provided for the benefit of perlcritic.

-criticism-fatal is not used by Perl::Critic but is provided for the benefit of criticism.

-color-severity-highest, -color-severity-high, -color-severity- medium, -color-severity-low, and -color-severity-lowest are not used by Perl::Critic, but are provided for the benefit of perlcritic. Each is set to the Term::ANSIColor color specification to be used to display violations of the corresponding severity.

-files-with-violations and -files-without-violations are not used by Perl::Critic, but are provided for the benefit of perlcritic, to cause only the relevant filenames to be displayed.

MÉTODOS

critique( $source_code )
Ejecuta el $source_code a través del motor Perl::Critic utilizando todas las Políticas que se han cargado en este motor. Si $source_code es una referencia escalar, entonces se trata como una cadena de código Perl real. Si $source_code es una referencia a una instancia de PPI::Document, entonces se utiliza directamente esa instancia. De lo contrario, se trata como una ruta a un archivo local que contiene código Perl. Este método devuelve una lista de objetos Perl::Critic::Violation por cada violación de las Políticas cargadas. La lista está ordenada según el orden en que aparecen las Violaciones en el código. Si no hay violaciones, este método devuelve una lista vacía.
"add_policy( -policy => $policy_name, -params => \%param_hash )"
Crea un objeto Policy y lo carga en este Critic. Si el objeto no se puede instanciar, lanzará una excepción fatal. De lo contrario, devuelve una referencia a este Critic.

-policy es el nombre de un módulo de sub-clase de Perl::Critic::Policy. La parte 'Perl::Critic::Policy' del nombre se puede omitir por brevedad. Este argumento es obligatorio.

-params es una referencia opcional a un hash de parámetros de Policy. El contenido de esta referencia de hash se pasará al constructor del módulo Policy. Consulte la documentación en el módulo Policy relevante para obtener una descripción de los argumentos que admite.

policies()
Devuelve una lista que contiene referencias a todos los objetos Policy que se han cargado en este motor. Los objetos estarán en el orden en que se cargaron.
config()
Devuelve el objeto Perl::Critic::Config que se creó para o se le dio a este Critic.
statistics()
Devuelve el objeto Perl::Critic::Statistics que se creó para este Critic. El objeto Statistics acumula datos de todos los archivos que son analizados por este Critic.

INTERFAZ FUNCIONAL

Para aquellos que prefieren tener una interfaz funcional, el método "critique" puede ser exportado bajo demanda y llamado como una función estática. Si el primer argumento es un hashref, su contenido se utiliza para construir internamente un nuevo objeto Perl::Critic. Las claves de ese hash deben ser las mismas que las admitidas por el método Perl::Critic::new(). Aquí hay algunos ejemplos:

use Perl::Critic qw(critique);
# Usa parámetros por defecto...
@violations = critique( $some_file );
# Usa parámetros personalizados...
@violations = critique( {-severity => 2}, $some_file );
# Como una línea
%> perl -MPerl::Critic=critique -e 'print critique(shift)' some_file.pm

Ninguno de los otros métodos de objeto son actualmente compatibles como funciones estáticas. Lo siento.

CONFIGURACIÓN

La mayoría de las configuraciones para Perl::Critic y cada uno de los módulos Policy pueden ser controladas por un archivo de configuración. El archivo de configuración predeterminado se llama .perlcriticrc. Perl::Critic buscará este archivo primero en el directorio actual y luego en su directorio de inicio. Alternativamente, puede establecer la variable de entorno "PERLCRITIC" para apuntar explícitamente a un archivo diferente en otra ubicación. Si ninguno de estos archivos existe, y no se proporciona la opción "-profile" al constructor, entonces todos los módulos que se encuentran en el espacio de nombres Perl::Critic::Policy se cargarán con su configuración predeterminada.

El formato del archivo de configuración es una serie de bloques estilo INI que contienen pares clave-valor separados por '='. Los comentarios deben comenzar con '#' y pueden colocarse en una línea separada o después de los pares nombre-valor si lo desea.

Los ajustes predeterminados para Perl::Critic en sí mismos pueden establecerse **antes del primer bloque con nombre**. Por ejemplo, colocar cualquiera o todos los siguientes al principio de su archivo de configuración establecerá el valor predeterminado para el argumento correspondiente del constructor.

severity  = 3                                     #Integer or named level
only      = 1                                     #Zero or One
force     = 0                                     #Zero or One
verbose   = 4                                     #Integer or format spec
top       = 50                                    #A positive integer
theme     = (pbp || security) && bugs             #A theme expression
include   = NamingConventions ClassHierarchies    #Space-delimited list
exclude   = Variables  Modules::RequirePackage    #Space-delimited list
criticism-fatal = 1                               #Zero or One
color     = 1                                     #Zero or One
allow-unsafe = 1                                  #Zero or One
pager     = less                                  #pager to pipe output to

El resto del archivo de configuración es una serie de bloques como este:

[Perl::Critic::Policy::Category::PolicyName]
severity = 1
set_themes = foo bar
add_themes = baz
maximum_violations_per_document = 57
arg1 = value1
arg2 = value2

"Perl::Critic::Policy::Category::PolicyName" es el nombre completo de un módulo que implementa la política. Los módulos Policy distribuidos con Perl::Critic se han agrupado en categorías según la tabla de contenido del libro de Damian Conway, Perl Best Practices. Por brevedad, puede omitir la parte 'Perl::Critic::Policy' del nombre del módulo.

"severity" es el nivel de importancia que desea asignar a la Política. Todos los módulos Policy se definen con un valor de severidad predeterminado que varía de 1 (menos severo) a 5 (más severo). Sin embargo, puede no estar de acuerdo con la severidad predeterminada y optar por asignarle una severidad mayor o menor, según su propia filosofía de codificación. Puede establecer la "severity" a un entero de 1 a 5, o usar uno de los nombres equivalentes:

SEVERITY NAME ...is equivalent to... SEVERITY NUMBER
----------------------------------------------------
gentle                                             5
stern                                              4
harsh                                              3
cruel                                              2
brutal                                             1

Los nombres reflejan cuán severamente se critica el código: una crítica "gentle" informa solo las violaciones más severas, y así sucesivamente hasta una crítica "brutal" que informa incluso las violaciones más leves.

"set_themes" establece el tema para la Política y anula su tema predeterminado. El argumento es una cadena de una o más palabras separadas por espacios en blanco. Los temas no distinguen entre mayúsculas y minúsculas. Consulte "POLICY THEMES" para obtener más información.

"add_themes" agrega a los temas predeterminados para esta Política. El argumento es una cadena de una o más palabras separadas por espacios en blanco. Los temas no distinguen entre mayúsculas y minúsculas. Consulte "POLICY TH

EXTENDING THE CRITIC

The Perl::Critic distribution includes Perl::Critic::DEVELOPER file included in this distribution for a step-by-step demonstration of how to create new Policy modules.

If you develop any new Policy modules, feel free to send them to "<team@perlcritic.com>" and I'll be happy to consider putting them into the Perl::Critic distribution. Or if you would like to work on the Perl::Critic project directly, you can fork our repository at https://github.com/Perl-Critic/Perl-Critic.git.

The Perl::Critic team is also available for hire. If your organization has its own coding standards, we can create custom Policies to enforce your local guidelines. Or if your code base is prone to a particular defect pattern, we can design Policies that will help you catch those costly defects before they go into production. To discuss your needs with the Perl::Critic team, just contact "<team@perlcritic.com>".
