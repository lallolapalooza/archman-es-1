Perl__Critic__Policy__BuiltinFunctions__ProhibitStringyEval(3pm)

Paquete: perl-perl-critic

Licencias: PerlArtistic

Perl::Critic::Policy::BuiltinFunctions::ProhibitStringyEval(3pm) Documentación de Perl contribuida por el usuario Perl::Critic::Policy::BuiltinFunctions::ProhibitStringyEval(3pm)

NOMBRE

Perl::Critic::Policy::BuiltinFunctions::ProhibitStringyEval - Escribe "eval { my $foo; bar($foo) }" en lugar de "eval "my $foo; bar($foo);"".

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

La forma de cadena de "eval" se recompila cada vez que se ejecuta, mientras que la forma de bloque solo se compila una vez. Además, la forma de cadena no proporciona advertencias en tiempo de compilación.

eval "print $foo";        # no es correcto
eval {print $foo};        # correcto

CONFIGURACIÓN

Hay una opción booleana "allow_includes" para esta política. Si se establece, entonces se permiten las cadenas que parecen incluir solo una declaración opcional de "package" seguida de una única declaración de "use" o "require" (con la posible declaración siguiente que consiste en un solo número). Con esta opción establecida, lo siguiente se marca como se indica:

eval 'use Foo';                           # correcto
eval 'require Foo';                       # correcto
eval "use $thingy;";                      # correcto
eval "require $thingy;";                  # correcto
eval 'package Pkg; use Foo';              # correcto
eval 'package Pkg; require Foo';          # correcto
eval "package $pkg; use $thingy;";        # correcto
eval "package $pkg; require $thingy;";    # correcto
eval "use $thingy; 1;";                   # correcto
eval "require $thingy; 1;";               # correcto
eval "package $pkg; use $thingy; 1;";     # correcto
eval "package $pkg; require $thingy; 1;"; # correcto
eval 'use Foo; blah;';                    # sigue sin ser correcto
eval 'require Foo; 2; 1;';                # sigue sin ser correcto
eval 'use $thingy;';                      # sigue sin ser correcto
eval 'no Foo';                            # sigue sin ser correcto

Si no entiende por qué se permite el número, consulte Perl::Critic::Policy::ErrorHandling::RequireCheckingReturnValueOfEval.

Esta opción se inspiró en Perl::Critic::Policy::Lax::ProhibitStringyEval::ExceptForRequire de Ricardo SIGNES.
