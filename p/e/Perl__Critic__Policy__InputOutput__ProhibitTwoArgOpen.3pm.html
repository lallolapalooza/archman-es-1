Perl::Critic::Policy::InputOutput::ProhibitTwoArgOpen(3pm) Documentación de Perl aportada por el usuario Perl::Critic::Policy::InputOutput::ProhibitTwoArgOpen(3pm)

NOMBRE

Perl::Critic::Policy::InputOutput::ProhibitTwoArgOpen - Escribe "open $fh, q{<}, $filename;" en lugar de "open $fh, "<$filename";".

AFILIACIÓN

Esta política es parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

La forma de tres argumentos de "open" (introducida en Perl 5.6) previene errores sutiles que ocurren cuando el nombre del archivo comienza con caracteres extraños como '>' o '<'. El módulo IO::File proporciona una interfaz orientada a objetos agradable para los manejadores de archivos, que creo que es más elegante de todos modos.

open( $fh, '>output.txt' );          # no está bien
open( $fh, q{>}, 'output.txt' );     # está bien
use IO::File;
my $fh = IO::File->new( 'output.txt', q{>} ); # ¡aún mejor!

También es más explícitamente claro definir el modo de entrada del archivo, como en la diferencia entre estos dos:

open( $fh, 'foo.txt' );       # MAL: El lector debe pensar cuál es el modo predeterminado
open( $fh, '<', 'foo.txt' );  # BIEN: El lector puede ver el modo de apertura

También existe una forma de un argumento de "open" que recupera la expresión para abrir desde la variable global con el mismo nombre que el manejador, pero esto tiene los mismos problemas que la forma de dos argumentos, y añade más ambigüedad.

our $FH = '<foo.txt';
open( FH ); # no está bien

Esta política no se quejará si el archivo indica explícitamente que es compatible con una versión de perl anterior a la 5.6 mediante una declaración de inclusión, p. ej., teniendo "require 5.005" en él.

CONFIGURACIÓN

Esta política no es configurable excepto por las opciones estándar.

NOTAS

Hay un caso en el que estás obligado a usar la forma de dos argumentos de open: al hacer una apertura segura de tubería (pipe), como se describe en perlipc.
