Nombre

Perl::Critic::TestUtils - Utilidades para probar nuevas políticas.

Soporte de interfaz

Este módulo se considera un módulo público. Cualquier cambio en su interfaz se someterá a un ciclo de depreciación.

SINTAXIS

use Perl::Critic::TestUtils qw(critique pcritique fcritique);
my $code = '<<END_CODE';
package Foo::Bar;
$foo = frobulator();
$baz = $foo ** 2;
1;
END_CODE
# Probar código contra todas las políticas cargadas...
my $perl_critic_config = { -severity => 2 };
my $violation_count = critique( \$code, $perl_critic_config);
# Probar código contra una política específica...
my $custom_policy = 'Miscellanea::ProhibitFrobulation'
my $violation_count = pcritique( $custom_policy, \$code );
# Probar código contra una política relacionada con el nombre de archivo...
my $custom_policy = 'Modules::RequireFilenameMatchesPackage'
my $violation_count = fcritique( $custom_policy, \$code, 'Foo/Bar.pm' );

DESCRIPCIÓN

Este módulo es utilizado por Perl::Critic únicamente para pruebas. Proporciona varias funciones convenientes para probar nuevos módulos de política en Perl::Critic. Consulte los scripts de prueba que vienen con Perl::Critic para ver más ejemplos de cómo usar estas funciones.

EXPORTS

assert_version( $version )
Afirma que la $version proporcionada coincide con la versión de Perl::Critic.
block_perlcriticrc()
Si un usuario tiene un archivo ~/.perlcriticrc, este puede interferir con las pruebas. Esta función deshabilita la búsqueda de ese archivo; simplemente llámala al principio de tu script .t. Ten en cuenta que esto no es fácil de revertir, pero eso no debería importar.
critique_with_violations( $code_string_ref, $config_ref )
Prueba un bloque de código contra una instancia específica de Config de Perl::Critic (o "undef" para el valor predeterminado). Devuelve el número de violaciones que ocurrieron.
critique( $code_string_ref, $config_ref )
Prueba un bloque de código contra una instancia específica de Config de Perl::Critic (o "undef" para el valor predeterminado). Devuelve el número de violaciones que ocurrieron.
pcritique_with_violations( $policy_name, $code_string_ref, $config_ref )
Similar a critique_with_violations(), pero solo prueba una política en lugar de todo el conjunto.
pcritique( $policy_name, $code_string_ref, $config_ref )
Similar a critique(), pero solo prueba una política en lugar de todo el conjunto.
fcritique_with_violations( $policy_name, $code_string_ref, $filename, $config_ref )
Similar a pcritique_with_violations(), pero simula que el código se cargó desde el archivo especificado. Esto es útil para probar políticas como Modules::RequireFilenameMatchesPackage, que se preocupan por el nombre del archivo del código.

El parámetro $filename debe ser una ruta relativa, no absoluta. Los directorios y subdirectorios serán creados por File::Temp y eliminados automáticamente.

fcritique( $policy_name, $code_string_ref, $filename, $config_ref )
Similar a pcritique(), pero simula que el código se cargó desde el archivo especificado. Esto es útil para probar políticas como Modules::RequireFilenameMatchesPackage, que se preocupan por el nombre del archivo del código.

El parámetro $filename debe ser una ruta relativa, no absoluta. Los directorios y subdirectorios serán creados por File::Temp y eliminados automáticamente.

subtests_in_tree( $dir )
Busca en el directorio especificado recursivamente archivos .run. Cada uno encontrado se parsea y devuelve una tabla hash de tablas hash. La tabla hash exterior está indexada por el nombre corto de la política, como Modules::RequireEndWithOne. La tabla hash interior especifica una única prueba que se pasa a pcritique() o fcritique(), incluyendo el string de código, nombre de la prueba, etc. Véase más abajo la sintaxis de los archivos .run.
should_skip_author_tests()
Devuelve si se deben ejecutar las pruebas de autor.
get_author_test_skip_message()
Devuelve un string con el mensaje que se muestra cuando una prueba se salta porque es una prueba de autor y las pruebas de autor no están habilitadas.
starting_points_including_examples()
Devuelve una lista de los directorios que contienen el código que necesita ser probado cuando se quieren incluir los ejemplos.
bundled_policy_names()
Devuelve una lista de los paquetes de políticas que vienen preempaquetados con este paquete. Esta función busca en el archivo MANIFEST por lib/Perl/Critic/Policy/*.pm y convierte los resultados en nombres de paquetes.
names_of_policies_willing_to_work( %configuration )
Devuelve una lista de los paquetes de políticas que funcionan en el sistema actual con la configuración especificada.

Información del archivo .run

La prueba de una política sigue un patrón muy simple:

* Nombre de la política
    * Nombre de la subprueba
    * Parámetros opcionales
    * Número de fallos esperados
    * Opcional: excepción esperada
    * Opcional: nombre de archivo para el código

Cada subprueba de una política se almacena en un archivo .run, con las propiedades de prueba del código del bloque que describe cómo se espera que Perl::Critic reaccione al código. Por ejemplo, si tienes una política llamada Variables::ProhibitVowels:

(En el archivo t/Variables/ProhibitVowels.run)
## name Basics
## failures 1
## cut
my $vrbl_nm = 'foo';    # Bueno, nombre sin vocal
my $wango = 12;         # Malo, nombre pronunciable
## name Sometimes Y
## failures 1
## cut
my $yllw = 0;       # "y" no es una vocal aquí
my $rhythm = 12;    # Pero aquí es así

Estas se llaman "subpruebas", y se muestran dos de ellas arriba. La belleza de incluir múltiples subpruebas en un archivo es que el .run es en sí mismo (aunque principalmente) un archivo Perl válido, y no está oculto en un heredoc, por lo que tu editor aún tendrá su colorización, y es más fácil trabajar con el código y la documentación POD.

Si necesitas pasar cualquier parámetro de configuración para tu subprueba, hazlo así:

## parms { allow_y => '0' }

Nota: todos los valores en esta tabla deben ser cadenas, ya que eso es lo que Perl::Critic te pasa desde un archivo .perlcriticrc.

Si es una subprueba de tipo TODO (probablemente porque hay un rincón raro del PPI que hemos ejercitado que Adam está tratando de arreglar), entonces haz una entrada "##TODO".

## TODO Debería pasar cuando salga PPI 1.xxx

Si el código espera que una política genere una excepción, indícalo así:

## error 1

Si quieres probar el mensaje de error, marca con "/.../" para indicar una prueba like():

## error /Can't load Foo::Bar/

Si la política que estás probando se preocupa por el nombre del archivo del código, puedes indicar que se debe usar "fcritique" así (ver "fcritique" para más detalles):

## filename lib/Foo/Bar.pm

En general, un documento de subprueba se ejecuta desde el "## cut" que lo inicia hasta el siguiente "## name" o el final del archivo. En circunstancias muy raras, es posible que necesites terminar el documento de prueba antes. Un segundo "## cut" hará esto. La única necesidad conocida para esto es en t/Miscellanea/RequireRcsKeywords.run, donde se utiliza para evitar que las palabras clave de RCS en el pie de página del archivo produzcan falsos positivos o negativos en la última prueba.

Ten en cuenta que en ningún lugar dentro del propio archivo .run especificas la política que estás probando. Eso es implícito dentro del nombre del archivo.

BUGS Y OBSERVACIONES Y PENDIENTES

Prueba que tenemos un t/*/*.run por cada lib/*/*.pm

Permítenos especificar la naturaleza de los fallos, y cuál de ellos. Si hay 15 líneas de código, y seis de ellas fallan, ¿cómo sabemos que son las seis correctas?
