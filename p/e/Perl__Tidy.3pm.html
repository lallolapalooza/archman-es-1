NOMBRE

Perl::Tidy - Analiza y embellece código fuente perl

SINOPSIS

use Perl::Tidy;
my $error_flag = Perl::Tidy::perltidy(
    source            => $source,
    destination       => $destination,
    stderr            => $stderr,
    argv              => $argv,
    perltidyrc        => $perltidyrc,
    logfile           => $logfile,
    errorfile         => $errorfile,
    teefile           => $teefile,
    debugfile         => $debugfile,
    formatter         => $formatter,    # objeto callback (ver abajo)
    dump_options      => $dump_options,
    dump_options_type => $dump_options_type,
    prefilter         => $prefilter_coderef,
    postfilter        => $postfilter_coderef,
);

DESCRIPCIÓN

Este módulo hace que la funcionalidad de la utilidad perltidy esté disponible para scripts de perl. Cualquiera o todos los parámetros de entrada pueden omitirse, en cuyo caso la matriz @ARGV se utilizará para proporcionar parámetros de entrada según se describe en la página del manual de perltidy(1).

Por ejemplo, el script perltidy es básicamente solo esto:

use Perl::Tidy;
Perl::Tidy::perltidy();

La llamada a perltidy devuelve un escalar $error_flag que es VERDADERO si un error causó una terminación prematura, y FALSO si el proceso se completó normal. Se discuten errores adicionales a continuación en la sección MANEJO DE ERRORES.

El módulo acepta flujos de entrada y salida mediante una variedad de métodos. La siguiente lista de parámetros puede ser cualquiera de los siguientes: un nombre de archivo, una referencia ARRAY, una referencia SCALAR, o un objeto con un método getline o print, según corresponda.

source            - la fuente del script a formatear
destination       - el destino de la salida formateada
stderr            - salida de error estándar
perltidyrc        - el archivo .perltidyrc
logfile           - el flujo del archivo .LOG, si existe
errorfile         - el flujo del archivo .ERR, si existe
dump_options      - ref a un hash para recibir parámetros (ver abajo),
dump_options_type - controla el contenido de dump_options
dump_getopt_flags - ref a un hash para recibir flags de Getopt
dump_options_category - ref a un hash que da la categoría de las opciones
dump_abbreviations    - ref a un hash que da todas las abreviaturas

El siguiente gráfico ilustra la lógica utilizada para decidir cómo tratar un parámetro.

ref($param)  $param se asume que es:
-----------  ---------------------
undef        un nombre de archivo
SCALAR       ref a una cadena
ARRAY        ref a una matriz
(otro)       objeto con getline (si es source) o método print

Si el parámetro es un objeto, y el objeto tiene un método close, ese método close se llamará al final del flujo.

source
Si se proporciona el parámetro source, define la fuente del flujo de entrada. Si se define un flujo de entrada con el parámetro source, entonces no se pueden especificar otros nombres de archivo de origen en la matriz @ARGV o en el parámetro argv.
destination
Si se proporciona el parámetro destination, se utilizará para definir el archivo o la ubicación de memoria que recibirá la salida de perltidy.

Nota importante si destination es una cadena o una referencia a una matriz. Las cadenas de caracteres de Perl que son decodificadas como utf8 por Perl::Tidy pueden ser devueltas en dos estados posibles, decodificado o codificado, y es importante que el programa que llama y Perl::Tidy estén de acuerdo sobre el estado que se devolverá. Se agregó una bandera --encode-output-strings, o simplemente -eos, en la versión 20220217 de Perl::Tidy con este propósito.

  • Use -eos si Perl::Tidy debe codificar cualquier cadena que decodifique. Este es el valor predeterminado actual porque hace que perltidy funcione bien como un filtro, y es la configuración correcta para la mayoría de los programas. Pero no use esta configuración si el programa que llama también codificará los datos, porque la doble codificación corromperá los datos.
  • Use -neos si una cadena debe permanecer decodificada si fue decodificada por Perl::Tidy. Esto solo es apropiado si el programa que llama manejará cualquier codificación necesaria antes de mostrar la cadena. Si es necesario, esta bandera se puede agregar al final del parámetro argv pasado a Perl::Tidy.

Para obtener información de fondo, consulte https://github.com/perltidy/perltidy/blob/master/docs/eos_flag.md.

Este cambio en el comportamiento predeterminado se realizó durante un período de tiempo de la siguiente manera:

  • Para versiones anteriores a 20220217, la bandera -eos no estaba disponible y el comportamiento era equivalente a -neos.
  • En la versión 20220217 se agregó la bandera -eos pero el valor predeterminado siguió siendo -neos.
  • Para versiones posteriores a 20220217, el valor predeterminado se estableció en -eos.
stderr
El parámetro stderr permite al programa que llama redirigir el flujo que de otro modo iría al dispositivo de salida de error estándar a cualquiera de los tipos de flujo enumerados anteriormente. Este flujo contiene advertencias y errores importantes relacionados con los parámetros pasados a perltidy.
perltidyrc
Si se proporciona el archivo perltidyrc, se utilizará en lugar de cualquier archivo de configuración .perltidyrc que de otro modo se utilizaría.
errorfile
El parámetro errorfile permite al programa que llama capturar el flujo que de otro modo iría a un archivo .ERR. Este flujo contiene advertencias o errores relacionados con el contenido de un archivo o flujo de origen.

La razón por la que esto es diferente del flujo stderr es que cuando se llama a perltidy para procesar varios archivos, habrá hasta un archivo .ERR creado para cada archivo y sería muy confuso si estuvieran combinados.

Sin embargo, si se llama a perltidy para procesar un solo script de perl, puede ser más conveniente combinar el flujo errorfile con el flujo stderr. Esto se puede hacer estableciendo el parámetro -se, en cuyo caso este parámetro se ignora.

logfile
El parámetro logfile permite al programa que llama capturar el flujo de registro. Este flujo solo se crea si se solicita con un parámetro -g. Contiene información detallada de diagnóstico sobre un script que puede ser útil para la depuración.
teefile
El parámetro teefile permite al programa que llama capturar el flujo de "tee". Este flujo solo se crea si se solicita con uno de los parámetros 'tee', un --tee-pod, --tee-block-comments, --tee-side-commnts, o --tee-all-comments.
debugfile
El parámetro debugfile permite al programa que llama capturar el flujo producido por el parámetro --DEBUG. Este parámetro se usa principalmente para depurar el propio perltidy.
argv
Si se proporciona el parámetro argv, se utilizará en lugar de la matriz @ARGV. El parámetro argv puede ser una cadena, una referencia a una cadena o una referencia a una matriz. Si es una cadena o una referencia a una cadena, se analizará en una matriz de elementos como si fuera una cadena de línea de comandos.
dump_options
Si se proporciona el parámetro dump_options, debe ser una referencia a un hash. En este caso, los parámetros contenidos en cualquier archivo de configuración perltidyrc se colocarán en este hash y perltidy regresará inmediatamente. Esto es equivalente a ejecutar perltidy con --dump-options, excepto que los parámetros se devuelven en un hash en lugar de ser volcados a la salida estándar. Además, por defecto solo se devuelven los parámetros del archivo perltidyrc, pero esto se puede cambiar (ver el siguiente parámetro). Este parámetro proporciona un método conveniente para que los programas externos lean un archivo perltidyrc. Un programa de ejemplo que utiliza esta característica, perltidyrc_dump.pl, se incluye en la distribución.

Cualquier combinación de los parámetros dump_ puede usarse juntos.

dump_options_type
Este parámetro controla qué parámetros se incluyen en el hash dump_options. Por defecto, solo se incluyen los parámetros que se han establecido explícitamente en un archivo perltidyrc. Sin embargo, puede solicitar que se incluyan otros parámetros, como se muestra en la siguiente tabla:

dump_options_type  Includes:
-----------------  -------------------------------------------------------------
perltidyrc         Only parameters from the perltidyrc file (default)
all                All parameters
explicit           Only parameters that were explicitly set
implicit           Only parameters that were implicitly set
default            Only parameters that have a default value
used               All parameters that were used by perltidy
all-comments       All parameters, plus all comments from the perltidyrc file
explicit-comments  Only parameters that were explicitly set, plus all comments
implicit-comments  Only parameters that were implicitly set, plus all comments
default-comments   Only parameters that have a default value, plus all comments
used-comments      All parameters that were used by perltidy, plus all comments
Si se especifica un valor de tipo que incluye comentarios, los comentarios se incluirán como el valor de la clave '-- comentarios --'.
dump_getopt_flags
Si se proporciona dump_getopt_flags, debe ser una referencia a un hash. En este caso, las banderas de opciones de la línea de comandos que se utilizaron se colocarán en este hash, y perltidy regresará inmediatamente. Esto es equivalente a ejecutar perltidy con --dump-getopt-flags, excepto que las banderas se devuelven en un hash en lugar de imprimirse en la salida estándar. Las banderas que se incluyen son las que se pasaron al módulo Getopt::Long.
dump_options_category
Si se proporciona dump_options_category, debe ser una referencia a un hash. En este caso, la categoría de cada una de las opciones que se utilizaron se colocarán en este hash, y perltidy regresará inmediatamente. Esto es equivalente a ejecutar perltidy con --dump-options-category, excepto que las categorías se devuelven en un hash en lugar de imprimirse en la salida estándar.
dump_abbreviations
Si se proporciona dump_abbreviations, debe ser una referencia a un hash. En este caso, todas las abreviaturas utilizadas para especificar opciones se colocarán en este hash, y perltidy regresará inmediatamente. Esto es equivalente a ejecutar perltidy con --dump-abbreviations, excepto que las abreviaturas se devuelven en un hash en lugar de imprimirse en la salida estándar.
formatter
Si se proporciona un parámetro formatter, debe ser un objeto que implemente un método format. Este método se llamará en lugar del proceso de formato estándar de perltidy. El método format debe aceptar dos argumentos: el código fuente perl a formatear y una referencia a una matriz de opciones. Debe devolver el código fuente perl formateado.
prefilter
Si se proporciona un parámetro prefilter, debe ser un código de referencia. Este código se llamará antes de que se apliquen las reglas de formateo. El código de referencia debe aceptar una referencia a una cadena que contenga el código fuente perl. Debería modificar la cadena in situ y devolverla.
postfilter
Si se proporciona un parámetro postfilter, debe ser un código de referencia. Este código se llamará después de que se apliquen las reglas de formateo. El código de referencia debe aceptar una referencia a una cadena que contenga el código fuente perl formateado. Debería modificar la cadena in situ y devolverla.

MANEJO DE ERRORES

La función perltidy devuelve un valor de bandera de error que es VERDADERO si ocurrió un error que causó una terminación prematura, y FALSO si el proceso se ejecutó hasta la finalización normal. Los errores se informan a través del flujo stderr o el flujo errorfile.

Los siguientes son algunos de los errores que pueden ocurrir:

  • Error de sintaxis de Perl.
  • Error al leer el archivo fuente.
  • Error al escribir el archivo de destino.
  • Error al procesar el archivo de configuración perltidyrc.
  • Error al procesar un parámetro de la línea de comandos.

Si se produce un error de sintaxis de Perl, perltidy intentará continuar y formatear tanto código como sea posible. Sin embargo, el resultado puede no ser el esperado. Se recomienda encarecidamente que el código fuente de Perl se verifique en busca de errores de sintaxis antes de pasarlo a perltidy.

EJEMPLOS

Aquí hay algunos ejemplos de cómo usar el módulo Perl::Tidy:

Ejemplo 1: Formatear un archivo

use Perl::Tidy;
my $source_file = 'mi_script.pl';
my $destination_file = 'mi_script_formateado.pl';
my $error_flag = Perl::Tidy::perltidy(
    source => $source_file,
    destination => $destination_file,
);
if ($error_flag) {
    print STDERR "Error al formatear el archivo $source_file\n";
}

Ejemplo 2: Formatear una cadena

use Perl::Tidy;
my $source_string = 'print "hola, mundo\n";';
my $formatted_string;
my $error_flag = Perl::Tidy::perltidy(
    source      => \$source_string,
    destination => \$formatted_string,
);
if ($error_flag) {
    print STDERR "Error al formatear la cadena\n";
} else {
    print $formatted_string; # Imprime "print "hola, mundo\\n";\n"
}

Ejemplo 3: Usar argumentos de línea de comandos

use Perl::Tidy;
# Simula los argumentos de línea de comandos
@ARGV = ('--indent=3', 'mi_script.pl');
my $error_flag = Perl::Tidy::perltidy();
if ($error_flag) {
    print STDERR "Error al formatear el archivo usando argumentos de línea de comandos\n";
}

Ejemplo 4: Volcar opciones de perltidyrc

use Perl::Tidy;
my $options;
my $error_flag = Perl::Tidy::perltidy(
    dump_options => \$options,
);
if ($error_flag) {
    print STDERR "Error al volcar opciones\n";
} else {
    use Data::Dumper;
    print Dumper($options);
}

PARÁMETROS

dump_options_type
Este parámetro es una cadena que se puede utilizar para controlar los parámetros que se colocan en la referencia hash suministrada por dump_options. Los valores posibles son 'perltidyrc' (por defecto) y 'full'. El parámetro 'full' hace que se devuelvan tanto las opciones por defecto como cualquier opción encontrada en un archivo perltidyrc.
dump_getopt_flags
Si se proporciona el parámetro dump_getopt_flags, debe ser la referencia a un hash. Este hash recibirá todos los parámetros que perltidy entiende y las banderas que se pasan a Getopt::Long. Este parámetro puede usarse solo o con la bandera dump_options. Perltidy saldrá inmediatamente después de llenar este hash. Ver el programa de demostración perltidyrc_dump.pl para ver un ejemplo de uso.
dump_options_category
Si se proporciona el parámetro dump_options_category, debe ser la referencia a un hash. Este hash recibirá un hash con claves iguales a todos los nombres de parámetros largos y valores iguales al título de la sección correspondiente del manual de perltidy. Ver el programa de demostración perltidyrc_dump.pl para ver un ejemplo de uso.
dump_abbreviations
Si se proporciona el parámetro dump_abbreviations, debe ser la referencia a un hash. Este hash recibirá todas las abreviaturas utilizadas por Perl::Tidy. Ver el programa de demostración perltidyrc_dump.pl para ver un ejemplo de uso.
prefilter
Una referencia de código que se aplicará a la fuente antes de formatear. Se espera que tome el contenido completo como una cadena en su entrada y que genere el contenido transformado.
postfilter
Una referencia de código que se aplicará al resultado formateado antes de su salida. Se espera que tome el contenido completo como una cadena en su entrada y que genere el contenido transformado.

Nota: Una forma conveniente de verificar la funcionalidad de su código prefiltro y postfiltro personalizado es usar la opción --notidy, primero solo con el prefiltro y luego con el prefiltro y el postfiltro. Ver también el archivo filter_example.pl en la distribución de perltidy.

MANEJO DE ERRORES

Perltidy devuelve un valor de salida de 0, 1 o 2 para indicar el estado del resultado.

Un valor de salida de 0 indica que perltidy se ejecutó hasta completar sin mensajes de error.

Un valor de salida de 1 indica que el proceso tuvo que ser terminado tempranamente debido a errores en los parámetros de entrada. Esto puede suceder, por ejemplo, si un parámetro está mal escrito o tiene un valor inválido. El programa que llama debe verificar esta bandera porque si está activada, el flujo de destino estará vacío o incompleto y debe ser ignorado. Los mensajes de error en el flujo de stderr indicarán la causa de cualquier problema.

Un valor de salida de 2 indica que perltidy se ejecutó hasta completar pero hay mensajes de advertencia en el flujo de stderr relacionados con errores de parámetros o conflictos y/o mensajes de advertencia en el flujo de errorfile relacionados con posibles errores de sintaxis en el código fuente que se está formateando.

En caso de un error catastrófico para el cual no es posible la recuperación, perltidy termina realizando llamadas a croak o confess para ayudar al programador a localizar el problema. Estos normalmente solo deberían ocurrir durante el desarrollo del programa.

NOTAS SOBRE LOS PARÁMETROS DE FORMATO

Los parámetros que controlan el formato se pueden pasar de varias maneras: en un archivo de configuración .perltidyrc, en el parámetro perltidyrc y en el parámetro argv.

Si se utiliza el estilo -pbp, típicamente será necesario especificar también una bandera -nst. Esto es necesario para desactivar la bandera -st contenida en el conjunto de parámetros -pbp, que de lo contrario dirigiría el flujo de salida a la salida estándar.

EJEMPLOS

El siguiente ejemplo utiliza referencias de cadena para mantener los flujos de código y error de entrada y salida, y ilustra la verificación de errores.

use Perl::Tidy;
my $source_string = <<'EOT';
my$error=Perl::Tidy::perltidy(argv=>$argv,source=>\$source_string,
  destination=>\$dest_string,stderr=>\$stderr_string,
errorfile=>\$errorfile_string,);
EOT
my $dest_string;
my $stderr_string;
my $errorfile_string;
my $argv = "-npro";   # Ignorar cualquier .perltidyrc en este sitio
$argv .= " -pbp";     # Formatear según las mejores prácticas de perl
$argv .= " -nst";     # Debe desactivar -st en caso de que se especifique -pbp
$argv .= " -se";      # -se añade el archivo de error a stderr
## $argv .= " --spell-check";  # descomentar para generar un error
print "<<FUENTE RAW>>\n$source_string\n";
my $error = Perl::Tidy::perltidy(
    argv        => $argv,
    source      => \$source_string,
    destination => \$dest_string,
    stderr      => \$stderr_string,
    errorfile   => \$errorfile_string,  # ignorado cuando la bandera -se está configurada
    ##phasers   => 'stun',              # descomentar para generar un error
);
if ($error) {
    # error grave en los parámetros de entrada, sin salida formateada
    print "<<STDERR>>\n$stderr_string\n";
    die "Saliendo debido a errores graves\n";
}
if ($dest_string)      { print "<<FUENTE FORMATEADA>>\n$dest_string\n" }
if ($stderr_string)    { print "<<STDERR>>\n$stderr_string\n" }
if ($errorfile_string) { print "<<archivo .ERR>>\n$errorfile_string\n" }

Usando el objeto de callback formatter

El parámetro formatter es un objeto de callback opcional que permite al programa que llama recibir líneas tokenizadas directamente de perltidy para un procesamiento especializado adicional. Cuando se utiliza este parámetro, se ignoran las dos opciones de formato que están integradas en perltidy (formateo o html). El siguiente diagrama ilustra el flujo lógico:

                  |-- (ruta normal)   -> formateo de código
llamador->perltidy->|-- (-bandera html)    -> crear html
                  |-- (formatter dado)-> callback a write_line

Esto puede ser útil para procesar scripts de perl de alguna manera. El parámetro $formatter en la llamada a perltidy,

formatter   => $formatter,

es un objeto creado por el llamador con un método "write_line" que aceptará y procesará líneas tokenizadas, una línea por llamada. Aquí hay un ejemplo simple de un "write_line" que simplemente imprime el número de línea, el tipo de línea (según lo determine perltidy) y el texto de la línea:

sub write_line {
    # Esto es llamado desde perltidy línea por línea
    my $self              = shift;
    my $line_of_tokens    = shift;
    my $line_type         = $line_of_tokens->{_line_type};
    my $input_line_number = $line_of_tokens->{_line_number};
    my $input_line        = $line_of_tokens->{_line_text};
    print "$input_line_number:$line_type:$input_line";
}

El programa completo, perllinetype, se encuentra en la sección de ejemplos de la distribución de código fuente. Como muestra este ejemplo, el método de callback recibe un parámetro $line_of_tokens, que es una referencia a un hash con otra información útil. Este ejemplo utiliza estas entradas del hash:

$line_of_tokens->{_line_number} - el número de línea (1,2,...)
$line_of_tokens->{_line_text}   - el texto de la línea
$line_of_tokens->{_line_type}   - el tipo de línea, uno de:
   SYSTEM         - código específico del sistema antes de la línea hash-bang
   CODE           - línea de código perl (incluyendo comentarios)
   POD_START      - línea que inicia pod, como '=head'
   POD            - texto de documentación pod
   POD_END        - última línea de la sección pod, '=cut'
   HERE           - texto del here-document
   HERE_END       - última línea del here-doc (palabra objetivo)
   FORMAT         - sección de formato
   FORMAT_END     - última línea de la sección de formato, '.'
   DATA_START     - línea __DATA__
   DATA           - texto no identificado después de __DATA__
   END_START      - línea __END__
   END            - texto no identificado después de __END__
   ERROR          - estamos en serios problemas, probablemente no es un script perl

La mayoría de las aplicaciones solo estarán interesadas en las líneas de tipo CODE. Para otro ejemplo, escribamos un programa que busque una de las llamadas variables de coincidencia traviesas "&`", $`, y "$'", que pueden ralentizar el procesamiento. Aquí hay un write_line, del programa de ejemplo find_naughty.pl, que hace eso:

sub write_line {
    # Esto es llamado de vuelta desde perltidy línea por línea
    # Estamos buscando $`, $&, y $'
    my ( $self, $line_of_tokens ) = @_;
    # extraemos algo de información que podríamos necesitar
    my $line_type         = $line_of_tokens->{_line_type};
    my $input_line_number = $line_of_tokens->{_line_number};
    my $input_line        = $line_of_tokens->{_line_text};
    my $rtoken_type       = $line_of_tokens->{_rtoken_type};
    my $rtokens           = $line_of_tokens->{_rtokens};
    chomp $input_line;
    # omitimos comentarios, pod, etc.
    return if ( $line_type ne 'CODE' );
    # recorremos los tokens buscando $`, $&, y $'
    for ( my $j = 0 ; $j < @$rtoken_type ; $j++ ) {
        # solo queremos examinar los tipos de token 'i' (identificador)
        next unless $$rtoken_type[$j] eq 'i';
        # extraemos el texto real del token
        my $token = $$rtokens[$j];
        # y lo comprobamos
        if ( $token =~ /^\$[\`\&\']$/ ) {
            print STDERR
              "$input_line_number: $token\n";
        }
    }
}

Este ejemplo extrae estas variables de tokenización del hash de referencia $line_of_tokens:

$rtoken_type = $line_of_tokens->{_rtoken_type};
$rtokens     = $line_of_tokens->{_rtokens};

La variable $rtoken_type es una referencia a un array de códigos de tipo de token, y $rtokens es una referencia a un array correspondiente de texto de token. Estos obviamente solo se definen para líneas de tipo CODE. Perltidy clasifica los tokens en tipos, y tiene un código breve para cada tipo. Puede obtener una lista completa en cualquier momento ejecutando perltidy desde la línea de comandos con

perltidy --dump-token-types

En el presente ejemplo, solo estamos buscando

tokens de tipo i (identificadores), por lo que el bucle for omite todos los demás tipos. Cuando se encuentra un identificador, se verifica su texto real para ver si es uno de los que se buscan. Si es así, la función write_line anterior imprime el token y su número de línea.

La sección examples de la distribución fuente tiene algunos ejemplos de programas que utilizan la opción formatter.

Para obtener ayuda con la peculiar forma en que perltidy divide las líneas en tokens, puedes ejecutar, desde la línea de comandos:

perltidy -D nombre_archivo

donde nombre_archivo es un script corto de interés. Esto producirá nombre_archivo.DEBUG con líneas de texto intercaladas y sus tipos de tokens. La opción -D ha estado en perltidy desde el principio para este propósito. Si deseas ver el código que crea este archivo, es "sub Perl::Tidy::Debugger::write_debug_entry"

INSTALACIÓN

El módulo 'Perl::Tidy' viene con un binario 'perltidy' que se instala cuando se instala el módulo. El nombre del módulo distingue entre mayúsculas y minúsculas. Por ejemplo, el comando básico para instalar con cpanm es 'cpanm Perl::Tidy'.
