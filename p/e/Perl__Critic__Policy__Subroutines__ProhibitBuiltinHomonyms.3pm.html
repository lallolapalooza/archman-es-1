Perl::Critic::Policy::Subroutines::ProhibitBuiltinHomonyms(3pm) Documentación de Perl aportada por el usuario Perl::Critic::Policy::Subroutines::ProhibitBuiltinHomonyms(3pm)

NOMBRE

Perl::Critic::Policy::Subroutines::ProhibitBuiltinHomonyms - No declare su propia función "open".

AFILIACIÓN

Esta Política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

El sentido común dicta que no debe declarar subrutinas con el mismo nombre que una de las funciones o palabras clave integradas de Perl. Consulte perlfunc para obtener una lista de funciones integradas; consulte perlsyn para conocer las palabras clave.

sub open {}    # no está bien
sub exit {}    # no está bien
sub print {}   # no está bien
sub foreach {} # no está bien
sub if {}      # no está bien
#Ya se entiende...

Se hacen excepciones para los bloques "BEGIN", "END", "INIT" y "CHECK", así como para las subrutinas "AUTOLOAD", "DESTROY" y "import".

CONFIGURACIÓN

Puede configurar homónimos integrados adicionales para aceptarlos especificándolos en una lista separada por espacios a la opción "allow":

[Subroutines::ProhibitBuiltinHomonyms]
allow = default index

Estos se añaden a la lista predeterminada de exenciones de esta política. Por lo tanto, lo anterior permite "sub default {}" y "sub index {}".

ADVERTENCIAS

Es razonable declarar un método de objeto con el mismo nombre que una función integrada de Perl, ya que se distinguen fácilmente entre sí. Sin embargo, en este momento, Perl::Critic no puede determinar si una subrutina es estática o un método de objeto.
