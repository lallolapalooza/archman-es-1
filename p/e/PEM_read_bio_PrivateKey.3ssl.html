No se admite la escritura de parámetros DH o DSA cifrados y se ignoran los argumentos de cifrado. El argumento cb se ignora para las funciones de escritura. El argumento kstr y klen en las funciones de escritura se utilizan para especificar la clave de encriptación, el valor NULL indica que se le debe preguntar al usuario. El argumento rwflag se pasa a pem_password_cb, que indica si la contraseña es para lectura (1) o escritura (0).

DESCRIPCIÓN

Estas funciones implementan las rutinas de lectura y escritura de PEM definidas en pem(5). PEM significa Privacy-Enhanced Mail, y es un formato de codificación para almacenar datos cifrados y autenticados, que utiliza un par codificado en Base64 de la información sobre el tipo de datos y encabezados opcionales, seguidos de los datos codificados en Base64, y terminando con una línea de "fin" opcional.

Las funciones que terminan con _ex son las versiones más nuevas que también aceptan un contexto de biblioteca (libctx) y una propiedad de consulta (propq) para la selección de algoritmos. Consulte EVP_PKEY_CTX_new(3) para obtener más detalles.

Las funciones que usan BIO* como primer argumento leen o escriben desde el objeto BIO dado. Las funciones que usan FILE* como primer argumento leen o escriben desde el flujo FILE* dado. Tenga en cuenta que las funciones FILE* se deprecian en favor de sus contrapartes BIO*.

Las rutinas de escritura PEM_write_bio_PKCS8PrivateKey* y PEM_write_PKCS8PrivateKey* escriben la clave privada en el formato PKCS#8 en lugar del formato tradicional de OpenSSL. El argumento nid especifica el cifrado que se utilizará para cifrar la clave. Si se utiliza EVP_get_default_properties(libctx), entonces se usarán las propiedades predeterminadas.

El tipo pem_password_cb es un puntero a una función de devolución de llamada que se invoca cuando se requiere una contraseña para descifrar una clave privada o para cifrar una clave privada al escribirla. La función de devolución de llamada recibe un búfer (buf) con un tamaño máximo (size), un indicador de lectura/escritura (rwflag) y un puntero a datos definidos por el usuario (u). Debe llenar buf con la contraseña y devolver la longitud de la contraseña. Si rwflag es 0, está escribiendo (cifrando) y si es 1, está leyendo (descifrando). Si la devolución de llamada falla, debe devolver 0.

Las rutinas que leen claves y certificados pueden tomar un puntero a un puntero (x) que apunta a un objeto existente. Si x no es NULL, la clave/certificado leído se almacenará en *x. Si *x es NULL, se asignará un nuevo objeto. Si x es NULL, se asignará un nuevo objeto y se devolverá. De manera similar, las rutinas de escritura pueden aceptar un puntero a un objeto existente.

Las funciones que leen estructuras RSA y DSA (PEM_read_bio_RSAPrivateKey, PEM_read_bio_DSAparams, etc.) utilizan punteros a RSA y DSA respectivamente. Las versiones más nuevas y recomendadas utilizan EVP_PKEY, que puede contener cualquier tipo de clave. El uso de punteros a tipos específicos como RSA se considera obsoleto.

VALOR DE RETORNO

Las funciones de lectura devuelven un puntero al objeto leído (clave, certificado, etc.) en caso de éxito, o NULL en caso de error. Las funciones de escritura devuelven 1 en caso de éxito, o 0 en caso de error.

La función de devolución de llamada de contraseña (pem_password_cb) debe devolver la longitud de la contraseña en el búfer o 0 en caso de error.

EJEMPLOS

Para leer una clave privada cifrada de un archivo:

BIO *bio_err;
EVP_PKEY *pkey;
char *filename = "key.pem";
FILE *fp;
int (*cb)(EVP_PKEY *, EVP_CIPHER *, void *) = NULL; /* O una función de callback personalizada */

/* ... inicialización de bio_err ... */

fp = fopen(filename, "r");
if (fp == NULL) {
    /* Manejar error */
}

pkey = PEM_read_PrivateKey(fp, NULL, cb, NULL); /* La contraseña se solicitará si es necesario */
fclose(fp);

if (pkey == NULL) {
    /* Manejar error */
}

/* ... usar pkey ... */

EVP_PKEY_free(pkey);

Para escribir una clave privada cifrada en un archivo:

BIO *bio_err;
EVP_PKEY *pkey;
char *filename = "key.pem";
FILE *fp;
const EVP_CIPHER *cipher = EVP_aes_256_cbc(); /* Elegir el cifrado */
char *password = "mysecretpassword"; /* O NULL para solicitar */

/* ... inicialización de bio_err y pkey ... */

fp = fopen(filename, "w");
if (fp == NULL) {
    /* Manejar error */
}

if (PEM_write_PrivateKey(fp, pkey, cipher, (unsigned char*)password, strlen(password), NULL, NULL) == 0) {
    /* Manejar error */
}
fclose(fp);

/* ... */

Irrespective of the value of .I x a pointer to the structure is always returned (or NULL if an error occurred). The caller retains ownership of the returned object and needs to free it when it is no longer needed, e.g. using .BR X509_free(3) for X509 objects or .BR EVP_PKEY_free(3) for EVP_PKEY objects. .PP The PEM functions which write private keys take an .I enc parameter which specifies the encryption algorithm to use, encryption is done at the PEM level. If this parameter is set to NULL then the private key is written in unencrypted form. .PP The .I cb argument is the callback to use when querying for the pass phrase used for encrypted PEM structures (normally only private keys). .PP For the PEM write routines if the .I kstr parameter is not NULL then .I klen bytes at .I kstr are used as the passphrase and .I cb is ignored. .PP If the .I cb parameters is set to NULL and the .I u parameter is not NULL then the .I u parameter is interpreted as a NUL terminated string to use as the passphrase. If both .I cb and .I u are NULL then the default callback routine is used which will typically prompt for the passphrase on the current terminal with echoing turned off. .PP The default passphrase callback is sometimes inappropriate (for example in a GUI application) so an alternative can be supplied. The callback routine has the following form: .PP .nf int cb(char *buf, int size, int rwflag, void *u); .fi .PP .I buf is the buffer to write the passphrase to. .I size is the maximum length of the passphrase (i.e. the size of buf). .I rwflag is a flag which is set to 0 when reading and 1 when writing. A typical routine will ask the user to verify the passphrase (for example by prompting for it twice) if .I rwflag is 1. The .I u parameter has the same value as the .I u parameter passed to the PEM routine. It allows arbitrary data to be passed to the callback by the application (for example a window handle in a GUI application). The callback *must* return the number of characters in the passphrase or -1 if an error occurred. The passphrase can be arbitrary data; in the case where it is a string, it is not NUL terminated. See the \"EXAMPLES\" section below. .PP Some implementations may need to use cryptographic algorithms during their operation. If this is the case and .I libctx and .I propq parameters have been passed then any algorithm fetches will use that library context and property query string. Otherwise the default library context and property query string will be used. .SH NOTES .PP The PEM reading functions will skip any extraneous content or PEM data of a different type than they expect. This allows for example having a certificate (or multiple certificates) and a key in the PEM format in a single file. .PP The old .B PrivateKey write routines are retained for comp PEM_read_bio_PrivateKey(3ssl)

DESCRIPTION

The PEM routines read and write various forms of private keys, public keys and parameters in the PEM format. The routines are named according to the object they handle, e.g. X509, RSA, DSA, DH, PUBKEY, PKCS8, and the BIO or FILE stream they use.

The routines fall into several categories:

  • PEM_read_bio_* and PEM_read_*: Read an object from a BIO or FILE pointer respectively.
  • PEM_write_bio_* and PEM_write_*: Write an object to a BIO or FILE pointer respectively.
  • PEM_read_bio_*_ex, PEM_read_*_ex, PEM_write_bio_*_ex, PEM_write_*_ex: These are extended versions which take an optional library context and property query string. These are the preferred versions for new applications.

The object types handled are:

  • EVP_PKEY: This is a generic key structure that can hold any type of key (RSA, DSA, DH, EC, etc.). PEM_read_bio_PrivateKey, PEM_read_PrivateKey, PEM_write_bio_PrivateKey, PEM_write_PrivateKey.
  • PUBKEY: This is a structure that wraps an EVP_PKEY object. It is typically used to hold public keys, but can also hold private keys. PEM_read_bio_PUBKEY, PEM_read_PUBKEY, PEM_write_bio_PUBKEY, PEM_write_PUBKEY.
  • PKCS8_PRIV_KEY_INFO: This structure represents a private key in PKCS#8 format. This is the modern format for storing private keys and is generally preferred over the older traditional PEM format. PEM_read_bio_PKCS8PrivateKey, PEM_read_PKCS8PrivateKey, PEM_write_bio_PKCS8PrivateKey, PEM_write_PKCS8PrivateKey.
  • DHparams, DSAparams: These handle Diffie-Hellman and DSA parameters respectively. PEM_read_bio_DHparams, PEM_read_DHparams, PEM_write_bio_DHparams, PEM_write_DHparams. PEM_read_bio_DSAparams, PEM_read_DSAparams, PEM_write_bio_DSAparams, PEM_write_DSAparams.

The password callback function cb is used to obtain a password if the key is encrypted. The argument u is a user-supplied value passed to the callback. If x is not NULL, the data read is stored in the structure pointed to by x, and the pointer is updated. If x is NULL, then a new structure is allocated and returned. The caller is responsible for freeing any returned structure.

The write functions take an optional encryption cipher enc. If enc is NULL, the key is written unencrypted. Otherwise, the key is encrypted using the specified cipher. A password must be supplied by the password callback for encrypted output.

The kdf_udata, kdf_udata_len, kdf_iter, and privsep_kdf_udata arguments are used for generating the key encryption key (KEK) when writing PKCS#8 or traditional private keys. For PKCS#8 keys, these parameters are passed to the underlying KDF function. For traditional keys, these are ignored and a fixed iteration count of 1 is used. For PKCS#8 keys, if kdf_iter is 0, a default iteration count is used. The privsep_kdf_udata is intended for use in a private key separation context.

The extended functions (ending in _ex) allow specification of the library context ctx and property query string propq, which are used to select algorithms and other parameters.

PEM_def_callback() is a default password callback function that may be used in simple cases, but it is generally recommended to implement a custom callback.

PEM FUNCTION ARGUMENTS

The password callback function pem_password_cb has the following signature:

typedef int pem_password_cb(char *buf, int size, int rwflag, void *u);

The callback function should place the password into the buffer buf which has a maximum size of size. It should return the length of the password placed in the buffer. If an error occurs, it should return -1. If the password is too long for the buffer, it should return 0. The rwflag argument indicates whether the password is being read (0) or written (1). The u argument is the pointer passed to the PEM function.

The callbacks are executed with the password callback registered with the BIO if one exists, otherwise with the password callback passed as an argument. The default callback for BIO is PEM_def_callback().

NOTES

The older routines like PEM_write_bio_PrivateKey() write private keys in a traditional PEM format which is less secure than the PKCS#8 format. The PKCS#8 format is recommended for new applications due to its improved security. New applications should write private keys using the PEM_write_bio_PKCS8PrivateKey() or PEM_write_PKCS8PrivateKey() routines because they are more secure (they use an iteration count of 2048 whereas the traditional routines use a count of 1) unless compatibility with older versions of OpenSSL is important.

The PrivateKey read routines can be used in all applications because they handle all formats transparently.

A frequent cause of problems is attempting to use the PEM routines like this:

X509 *x;
PEM_read_bio_X509(bp, &x, 0, NULL);

this is a bug because an attempt will be made to reuse the data at x which is an uninitialised pointer.

These functions make no assumption regarding the pass phrase received from the password callback. It will simply be treated as a byte sequence.

PEM ENCRYPTION FORMAT

These old PrivateKey routines use a non standard technique for encryption.

The private key (or other data) takes the following form:

-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: DES-EDE3-CBC,3F17F5316E2BAC89
...base64 encoded data...
-----END RSA PRIVATE KEY-----

The line beginning with Proc-Type contains the version and the protection on the encapsulated data. The line beginning DEK-Info contains two comma separated values: the encryption algorithm name as used by EVP_get_cipherbyname() and an initialization vector used by the cipher encoded as a set of hexadecimal digits. After those two lines is the base64-encoded encrypted data.

The encryption key is derived using EVP_BytesToKey(). The cipher's initialization vector is passed to EVP_BytesToKey() as the salt parameter. Internally, PKCS5_SALT_LEN bytes of the salt are used (regardless of the size of the initialization vector). The user's password is passed to EVP_BytesToKey() using the data and datal parameters. Finally, the library uses an iteration count of 1 for EVP_BytesToKey().

The key derived by EVP_BytesToKey() along with the original initialization vector is then used to decrypt the encrypted data. The iv produced by EVP_BytesToKey() is not utilized or needed, and NULL should be passed to the function.

The pseudo code to derive the key would look similar to:

EVP_CIPHER* cipher = EVP_des_ede3_cbc();
EVP_MD* md = EVP_md5();
unsigned int nkey = EVP_CIPHER_get_key_length(cipher);
unsigned int niv = EVP_CIPHER_get_iv_length(cipher);
unsigned char key[nkey];
unsigned char iv[niv];
memcpy(iv, HexToBin("3F17F5316E2BAC89"), niv);
rc = EVP_BytesToKey(cipher, md, iv /*salt*/, pword, plen, 1, key, NULL /*iv*/);
if (rc != nkey)
    /* Error */
/* On success, use key and iv to initialize the cipher */

BUGS

The PEM read routines in some versions of OpenSSL will not correctly reuse an existing structure. Therefore, the following:

PEM_read_bio_X509(bp, &x, 0, NULL);

where x already contains a valid certificate, may not work, whereas:

X509_free(x);
x = PEM_read_bio_X509(bp, NULL, 0, NULL);

is guaranteed to work. It is always acceptable for x to contain a newly allocated, empty X509 object (for example allocated via X509_new_ex(3)).

RETURN VALUES

The read routines return either a pointer to the structure read or NULL if an error occurred.

The write routines return 1 for success or 0 for failure.

EXAMPLES

Although the PEM routines take several arguments in almost all applications most of them are set to 0 or NULL.

To read a certificate with a library context in PEM format from a BIO:

X509 *x = X509_new_ex(libctx, NULL);
if (x == NULL)
    /* Error */
if (PEM_read_bio_X509(bp, &x, 0, NULL) == NULL)
    /* Error */

Read a certificate in PEM format from a BIO:

X509 *x;
x = PEM_read_bio_X509(bp, NULL, 0, NULL);
if (x == NULL)
    /* Error */

Alternative method:

X509 *x = NULL;
if (!PEM_read_bio_X509(bp, &x, 0, NULL))
    /* Error */

Write a certificate to a BIO:

if (!PEM_write_bio_X509(bp, x))
    /* Error */

Write a private key (using traditional format) to a BIO using triple DES encryption, the pass phrase is prompted for:

if (!PEM_write_bio_PrivateKey(bp, key, EVP_des_ede3_cbc(), NULL, 0, 0, NULL))
    /* Error */

Write a private key (using PKCS#8 format) to a BIO using triple DES encryption, using the pass phrase "hello":

if (!PEM_write_bio_PKCS8PrivateKey(bp, key, EVP_des_ede3_cbc(),
                                   NULL, 0, 0, "hello"))
    /* Error */

Read a private key from a BIO using a pass phrase callback:

key = PEM_read_bio_PrivateKey(bp, NULL, pass_cb, "My Private Key");
if (key == NULL)
    /* Error */

Skeleton pass phrase callback:

int pass_cb(char *buf, int size, int rwflag, void *u)
{
    /* We'd probably do something else if 'rwflag' is 1 */
    printf("Enter pass phrase for \"%s\"\n", (char *)u);
    /* get pass phrase, length 'len' into 'tmp' */
    char *tmp = "hello";
    if (tmp == NULL) /* An error occurred */
        return -1;
    size_t len = strlen(tmp);
    if (len > size)
        len = size;
    memcpy(buf, tmp, len);
    return len;
}
