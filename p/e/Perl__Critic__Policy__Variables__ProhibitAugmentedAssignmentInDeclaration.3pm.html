Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration(3pm) Documentación de Perl contribuida por el usuario Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration(3pm)

NOMBRE

Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration - No escribas " my $foo .= 'bar'; ".

AFILIACIÓN

Esta Política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Las declaraciones de variables que también hacen inicialización con '=' son comunes. Perl también permite usar operadores como '.=', '+=', etc., pero es más claro no hacerlo.

my $foo .= 'bar';              # lo mismo que my $foo = 'bar';
our $foo *= 2;                 # lo mismo que our $foo = 0;
my ( $foo, $bar ) += ( 1, 2 ); # lo mismo que my ( $foo, $bar ) = ( undef, 2 );
local $Carp::CarpLevel += 1;   # lo mismo que local $Carp::CarpLevel = 1;
state $foo += 2;               # suma 2 cada vez que se encuentra

Tales construcciones suelen ser el resultado de un pegado y copiado fallidos y, a menudo, son errores. Algunas producen advertencias.

CONFIGURACIÓN

Hay una opción booleana "allow_our" para esta Política. Si se establece, se permiten las asignaciones aumentadas al declarar variables "our". Dado que las variables "our" son globalmente accesibles, algunos módulos querrán permitir a los usuarios inicializar la variable antes de que el módulo la utilice. Los módulos también pueden desear utilizar la misma variable 'our' en diferentes ámbitos sin declararla en el ámbito externo.

Con esta opción establecida, las siguientes se marcan como se indica:

our $DEBUG //= 1;           # ok

Esto se puede habilitar en tu .perlcriticrc:

[Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration]
allow_our = 1
