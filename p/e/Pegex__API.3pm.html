La API de Pegex

Pegex se puede usar de muchas maneras: dentro de scripts, desde la línea de comandos o como base de un marco de trabajo de análisis modular. Este documento detalla las diversas formas de usar Pegex.

En el nivel más abstracto, Pegex funciona así:

$resultado = $parser->new($gramatica, $receptor)->parse($entrada);

Es decir, abstractamente: un analizador Pegex, bajo la dirección de una gramática Pegex, analiza un flujo de entrada y reporta las coincidencias a un receptor Pegex, que produce un resultado.

El analizador, la gramática, el receptor e incluso la entrada, son objetos Pegex. Estos 4 objetos están involucrados en cada operación de análisis de Pegex, así que revisémoslos brevemente:

Pegex::Parser
El motor de análisis de Pegex. Este motor aplica la lógica de la gramática a un texto de entrada. Un objeto parser contiene un objeto grammar y un objeto receiver. Su método principal se llama "parse". El motor de análisis predeterminado es de tipo descenso recursivo y sin retroceso. Sin embargo, existen subclases de analizador para varios tipos alternativos de análisis.
Pegex::Grammar
Una gramática Pegex comienza como un archivo/cadena de texto compuesta en la sintaxis de **Pegex**. Antes de que pueda ser utilizada por un Analizador, debe ser compilada. Después de la compilación, se convierte en un árbol de datos que consiste en reglas y expresiones regulares. En módulos basados en una gramática Pegex, la gramática se compilará en un archivo de clase. Pegex en sí mismo utiliza una clase de gramática Pegex llamada Pegex::Pegex::Grammar para analizar varias gramáticas Pegex.
Pegex::Receiver
Un analizador por sí solo no tiene idea de qué hacer con el texto que coincide. Un receptor de Pegex es una clase que contiene métodos que corresponden a las reglas de una gramática. A medida que una regla en la gramática coincide, se llama a su método receptor correspondiente (si existe) con los datos que han coincidido. Es trabajo del receptor tomar acción sobre los datos, a menudo construyéndolos en alguna nueva estructura. Pegex usará Pegex::Tree::Wrap como receptor predeterminado; produce un árbol razonablemente legible de los datos coincidentes/capturados.
Pegex::Input
Pegex también abstrae sus flujos de entrada en una interfaz de objeto. Cualquier operación que pueda tomar una cadena de entrada, también puede tomar un objeto de entrada. Pegex convertirá cadenas regulares en estos objetos. Este es probablemente el concepto de API que encontrará con menos frecuencia, pero se cubre aquí para completitud.

Todas estas clases de objetos pueden ser subclasificadas para lograr varios resultados. Normalmente, escribirá su propia gramática Pegex y un receptor Pegex para lograr una tarea.

Comenzando de forma sencilla - La función "pegex"

El módulo Pegex exporta una función llamada "pegex" que puede usar para tareas más pequeñas. Aquí hay un ejemplo:

use Pegex;
use YAML;
$gramatica = "
expr: num PLUS num
num: /( DIGIT+ )/
";
print Dump pegex($gramatica)->parse('2+2');

Este programa produciría:

expr:
- num: 2
- num: 2

Repasemos qué está sucediendo aquí. El módulo Pegex está exportando una función "pegex". Esta función toma una cadena de gramática Pegex como entrada. Internamente, esta función compila la cadena de gramática en un objeto de gramática. Luego crea un objeto analizador que contiene el objeto de gramática y lo devuelve.

Se llama al método parse en la cadena de entrada: '2+2'. La cadena coincide y se devuelve una estructura de datos agradable.

Entonces, ¿cómo se creó la estructura de datos? ¡Por el objeto receptor, por supuesto! Pero no especificamos uno, ¿verdad? No. Usó el receptor predeterminado, Pegex::Tree::Wrap. Podríamos haber dicho:

print Dump pegex($gramatica, 'Pegex::Tree::Wrap')->parse('2+2');

Este receptor básicamente genera un mapeo, donde los nombres de las reglas de las coincidencias son las claves y los valores hoja son las capturas de expresiones regulares.

El receptor más básico llamado Pegex::Tree genera un árbol de secuencias que contienen solo los datos (sin los nombres de las reglas). Este código:

print Dump pegex($gramatica, 'Pegex::Tree')->parse('2+2');

produciría:

- 2
- 2

Si escribiéramos nuestra propia clase receptora llamada "Calculator" como esta:

package Calculator;
use base 'Pegex::Tree';
sub got_expr {
    my ($receptor, $data) = @_;
    my ($a, $b) = @$data;
    return $a + $b;
}

Entonces, esto:

print pegex(gramatica, 'Calculator')->parse('2+2');

imprimiría:

4

Uso más explícito

Continuando con el ejemplo anterior, veamos cómo hacerlo un poco más formalmente.

use Pegex::Parser;
use Pegex::Grammar;
use Pegex::Tree;
use Pegex::Input;
use YAML;
$cadena_gramatica = "
expr: num PLUS num
num: /( DIGIT+ )/
";
$gramatica = Pegex::Grammar->new(text => $cadena_gramatica);
$receptor = Pegex::Tree->new();
$parser = Pegex::Parser->new(
    grammar => $gramatica,
    receiver => $receptor,
);
$input = Pegex::Input->new(string => '2+2');
print Dump $parser->parse($input);

Este código hace lo mismo que el primer ejemplo, pero esta vez hemos creado todos los objetos nosotros mismos.

Gramáticas precompiladas

Si distribuyes una gramática Pegex como parte de una distribución CPAN, querrás que esté precompilada en un módulo. Pegex lo facilita.

Digamos que la cadena de gramática se almacena en un archivo llamado "share/expr.pgx". Si creas un módulo llamado "lib/MyThing/Grammar.pm" con contenido como este:

package MyThing::Grammar;
use base 'Pegex::Grammar';
use constant file => './share/expr.pgx';
sub make_tree {
}
1;

Luego ejecuta este comando:

perl -Ilib -MMyThing::Grammar=compile

Reescribirá tu módulo para que se parezca a esto:

package MyThing::Grammar;
use base 'Pegex::Grammar';
use constant file => './share/expr.pgx';
sub make_tree {
  { '+toprule' => 'expr',
    'PLUS' => { '.rgx' => qr/\G\+/ },
    'expr' => {
      '.all' => [
        { '.ref' => 'num' },
        { '.ref' => 'PLUS' },
        { '.ref' => 'num' }
      ]
    },
    'num' => { '.rgx' => qr/\G([0-9]+)/ }
  }
}
1;

Este comando encontró el archivo donde está tu gramática, la compiló y usó Data::Dumper para volcarla de nuevo en el método "make_tree" de tu módulo.

Así es como se ve una gramática Pegex compilada. Tan pronto como este módulo se carga, la gramática está lista para ser utilizada por Pegex.

Recompilación automática durante el desarrollo con variable de entorno

Si te encuentras necesitando compilar tu módulo de gramática muchas veces durante el desarrollo, simplemente establece esta variable de entorno así:

export PERL_PEGEX_AUTO_COMPILE=MyThing::Grammar

Ahora, cada vez que se cargue el módulo de gramática, comprobará si necesita ser recompilado y lo hará sobre la marcha.

Si tienes más de una gramática que recompilar, simplemente lista todos los nombres separados por comas.

Recompilación automática durante el desarrollo usando "make"

Alternativamente, si tu módulo utiliza "ExtUtils::MakeMaker", puedes hacer que "make" reconstruya automáticamente tu clase "Grammar" si tu archivo ".pgx" se actualiza.

Simplemente agrega esto al final de tu "Makefile.PL":

sub MY::postamble {
  <<EOF;
lib/MyThing/Grammar.pm : share/expr.pgx
	\$(PERL) -Ilib -MMyThing::Grammar=compile
EOF
}
