NOMBRE

Perl::Critic::Policy::Subroutines::ProhibitExplicitReturnUndef - Devuelve el fallo con un "return" desnudo en lugar de "return undef".

AFILIACIÓN

Esta Política es parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Devolver "undef" al fallar desde una subrutina es bastante común. Pero si la subrutina se llama en contexto de lista, una declaración explícita "return undef;" devolverá una lista de un elemento que contiene "(undef)". Ahora, si esa lista se pone posteriormente en un contexto booleano para probar el fallo, se evalúa como verdadera. Pero probablemente querías que fuera falsa.

sub read_file {
    my $file = shift;
    -f $file || return undef;  # ¡el archivo no existe!
    # Continuar leyendo el archivo...
}
# y más tarde...
if ( my @data = read_file($filename) ){
    # si $filename no existe,
    # @data será (undef),
    # ¡pero todavía estaré aquí dentro!
    process(@data);
}
else{
    # Este es mi código de manejo de errores.
    # Probablemente quiero estar aquí dentro
    # si $filename no existe.
    die "$filename no encontrado";
}

La solución es simplemente usar una declaración de "return" desnuda siempre que quieras devolver un fallo. En contexto de lista, Perl te dará una lista vacía (que es falsa), y "undef" en contexto escalar (que también es falsa).

sub read_file {
    my $file = shift;
    -f $file || return;  # ¡DWIM!
    # Continuar leyendo el archivo...
}

CONFIGURACIÓN

Esta Política no es configurable, excepto por las opciones estándar.

NOTAS

Puedes engañar a esta política bastante fácilmente ocultando "undef" en una expresión booleana. Pero no te molestes en intentarlo. De hecho, usar valores de retorno para indicar fallos es una técnica bastante pobre de todos modos. Considera usar "die" o "croak" con "eval", o el módulo Error para un modelo de manejo de excepciones mucho más robusto. Conway tiene una muy buena discusión sobre el manejo de errores en el capítulo 13 de PBP.

VER TAMBIÉN

Hay una discusión sobre la idoneidad de esta política en http://perlmonks.org/index.pl?node_id=741847.
