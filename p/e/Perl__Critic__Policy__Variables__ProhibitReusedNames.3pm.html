Perl::Critic::Policy::Variables::ProhibitReusedNames(3pm) Documentación de Perl aportada por el usuario Perl::Critic::Policy::Variables::ProhibitReusedNames(3pm)

NOMBRE

Perl::Critic::Policy::Variables::ProhibitReusedNames - No reutilizar un nombre de variable en un ámbito léxico

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Es muy difícil para los futuros programadores de mantenimiento si reutilizas un nombre de variable en un ámbito léxico. El programador corre el riesgo de confundir qué variable es cuál. Y, lo que es peor, el programador podría eliminar accidentalmente la declaración interna, cambiando así silenciosamente el significado del código interno para usar la variable externa.

my $x = 1;
for my $i (0 .. 10) {
    my $x = $i+1;  # no está bien, "$x" reutilizado
}

Con "use warnings" activo, Perl te advertirá si reutilizas un nombre de variable en el mismo nivel de ámbito, pero no dentro de ámbitos anidados. Como esto:

% perl -we 'my $x; my $x'
"my" variable $x masks earlier declaration in same scope at -e line 1.

Esta política lleva esa advertencia a un nivel más estricto.

ADVERTENCIAS

Cruzar subrutinas

Esta política examina los límites de las subrutinas. Por lo tanto, lo siguiente puede ser un falso positivo para usted:

sub make_accessor {
    my ($self, $fieldname) = @_;
    return sub {
        my ($self) = @_;  # falso positivo, $self declarado como reutilizado
        return $self->{$fieldname};
    }
}

Esto es intencional, sin embargo, ya que detecta errores como este:

my $debug_mode = 0;
sub set_debug {
    my $debug_mode = 1;  # redeclaración accidental
}

Lo he hecho yo mismo varias veces; es un hábito fuerte poner ese "my" delante de las variables al inicio de las subrutinas.

Rendimiento

La implementación actual recorre el árbol una y otra vez. Para un archivo grande, esto puede ser un gran cuello de botella. Estoy considerando reescribirlo para buscar en el documento una sola vez las declaraciones de variables y almacenar en caché el recorrido del árbol en ese único análisis.

CONFIGURACIÓN

Esta política tiene una opción única, "allow", que es una lista de nombres que nunca se contarán como duplicados. Por defecto, contiene $self y $class. Puede añadir a esto añadiendo algo como esto a su .perlcriticrc:

[Variables::ProhibitReusedNames]
allow = $self $class @blah
