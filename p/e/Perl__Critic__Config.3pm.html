NOMBRE

Perl::Critic::Config - La configuración final derivada de Perl::Critic, combinada a partir de cualquier archivo de perfil y parámetros de línea de comandos.

DESCRIPCIÓN

Perl::Critic::Config se encarga de encontrar y procesar las preferencias de usuario para Perl::Critic. El objeto Config define qué módulos de Política se cargarán en el motor Perl::Critic y cómo deben configurarse. En realidad, nunca deberías necesitar instanciar Perl::Critic::Config directamente porque el constructor de Perl::Critic lo hará por ti.

SOPORTE DE INTERFAZ

Esta se considera una clase no pública. Su interfaz está sujeta a cambios sin previo aviso.

CONSTRUCTOR

new(...)
No está documentado correctamente porque no deberías estar usándolo.

MÉTODOS

"add_policy( -policy => $nombre_politica, -params => \%hash_parametros )"
Crea un objeto Política y lo carga en esta Config. Si el objeto no puede ser instanciado, lanzará una excepción fatal. De lo contrario, devuelve una referencia a este Crítico.

-policy es el nombre de un módulo de subclase Perl::Critic::Policy. La porción 'Perl::Critic::Policy' del nombre puede omitirse por brevedad. Este argumento es obligatorio.

-params es una referencia opcional a un hash de parámetros de Política. El contenido de esta referencia hash se pasará al constructor del módulo de Política. Consulta la documentación del módulo de Política relevante para obtener una descripción de los argumentos que soporta.

SUBRUTINAS

Perl::Critic::Config tiene algunas subrutinas estáticas que se utilizan internamente, pero que pueden serle útiles de alguna manera.

site_policy_names()
Devuelve una lista de todos los módulos de Política que están actualmente instalados en el espacio de nombres Perl::Critic::Policy. Estos incluirán módulos que se distribuyen con Perl::Critic más cualquier módulo de terceros que se haya instalado.

CONFIGURACIÓN

La mayoría de los ajustes para Perl::Critic y cada uno de los módulos de Política se pueden controlar mediante un archivo de configuración. El archivo de configuración predeterminado se llama .perlcriticrc. Perl::Critic::Config buscará este archivo primero en el directorio actual y luego en su directorio de inicio. Alternativamente, puede establecer la variable de entorno "PERLCRITIC" para apuntar explícitamente a un archivo diferente en otra ubicación. Si ninguno de estos archivos existe y no se proporciona la opción "-profile" al constructor, entonces todas las Políticas se cargarán con su configuración predeterminada.

El formato del archivo de configuración es una serie de bloques de estilo INI que contienen pares clave-valor separados por '='. Los comentarios deben comenzar con '#' y pueden colocarse en una línea separada o después de los pares nombre-valor si lo desea.

Los ajustes predeterminados para el propio Perl::Critic se pueden establecer antes del primer bloque con nombre. Por ejemplo, colocar cualquiera o todos los siguientes en la parte superior de su archivo de configuración establecerá el valor predeterminado para el argumento correspondiente del constructor de Perl::Critic.

severity  = 3

Perl::Critic::Config(3pm)

NAME

Perl::Critic::Config - Configuration for Perl::Critic

DESCRIPTION

This module reads and parses a .perlcriticrc file. It is responsible for loading the policies that you wish to have run, and for setting any configuration options that you wish to override.

INTERFACE SUPPORT

This module supports a documented, stable interface and can be used and subclassed by applications. No changes are expected to this module's interface.

CONSTRUCTOR

The constructor for Perl::Critic::Config takes an optional hashref of configuration options. These options will override any options found in the .perlcriticrc file. The following options are supported:

    * -profile: The path to the .perlcriticrc file to use.

For example:

    my $critic = Perl::Critic->new({
        -profile => '/path/to/my/.perlcriticrc',
    });

METHODS

This module does not support any public methods.

SUBROUTINES

This module does not support any public subroutines.

CONFIGURATION

The .perlcriticrc file is a Perl file that is loaded by the Perl::Critic::Config module. It can contain any valid Perl code, but it is expected to contain a series of assignments to variables that are localized to the scope of the Perl::Critic::Config module.

The following variables are supported:

    * only      : A list of policies to load. If this is set, then only
                  these policies will be loaded.
    * only      : Zero or One. If set to 1, then only policies that match the
                  'only' list will be loaded.
    * except    : A list of policies to *not* load.
    * except    : Zero or One. If set to 1, then policies that match the
                  'except' list will not be loaded.
    * include   : A space-delimited list of policies to include.
    * exclude   : A space-delimited list of policies to exclude.
    * program-extensions : A space-delimited list of file extensions to
                           consider as programs (e.g., '.pl .cgi .pm').
                           Defaults to '.pl'.
    * theme     : A theme expression that determines which policies to load.
                  See the "POLICY THEMES" section for more
                  information.
    * force     : Zero or One. If set to 1, then policies that are normally
                  disabled will be enabled.
    * verbose   : An integer or format spec. Controls the verbosity of the
                  output.
    * top       : A positive integer. Limits the number of policies that will
                  be run.
    * color     : Zero or One. If set to 1, then output will be colorized.
    * allow-unsafe : Zero or One. If set to 1, then policies that are marked
                     as unsafe will be allowed.
    * color-severity-highest : A Term::ANSIColor color
                               specification for policies with the highest
                               severity.
    * color-severity-high    : A Term::ANSIColor color
                               specification for policies with high
                               severity.
    * color-severity-medium  : A Term::ANSIColor color
                               specification for policies with medium
                               severity.
    * color-severity-low     : A Term::ANSIColor color
                               specification for policies with low
                               severity.
    * color-severity-lowest  : A Term::ANSIColor color
                               specification for policies with the lowest
                               severity.

The following is an example of a .perlcriticrc file:

           #Integer from 1 to 5
only      = 1                                     #Zero or One
force     = 0                                     #Zero or One
verbose   = 4                                     #Integer or format spec
top       = 50                                    #A positive integer
theme     = risky + (pbp * security) - cosmetic   #A theme expression
include   = NamingConventions ClassHierarchies    #Space-delimited list
exclude   = Variables  Modules::RequirePackage    #Space-delimited list
color     = 1                                     #Zero or One
allow_unsafe = 1                                  #Zero or One
color-severity-highest = bold red                 #Term::ANSIColor
color-severity-high = magenta                     #Term::ANSIColor
color-severity-medium =                           #no coloring
color-severity-low =                              #no coloring
color-severity-lowest =                           #no coloring
program-extensions =                              #Space-delimited list

The remainder of the configuration file is a series of blocks like this:

[Perl::Critic::Policy::Category::PolicyName]
severity = 1
set_themes = foo bar
add_themes = baz
arg1 = value1
arg2 = value2

"Perl::Critic::Policy::Category::PolicyName" is the full name of a module that implements the policy. The Policy modules distributed with Perl::Critic have been grouped into categories according to the table of contents in Damian Conway's book Perl Best Practices. For brevity, you can omit the 'Perl::Critic::Policy' part of the module name.

"severity" is the level of importance you wish to assign to the Policy. All Policy modules are defined with a default severity value ranging from 1 (least severe) to 5 (most severe). However, you may disagree with the default severity and choose to give it a higher or lower severity, based on your own coding philosophy.

The remaining key-value pairs are configuration parameters that will be passed into the constructor of that Policy. The constructors for most Policy modules do not support arguments, and those that do should have reasonable defaults. See the documentation on the appropriate Policy module for more details.

Instead of redefining the severity for a given Policy, you can completely disable a Policy by prepending a '-' to the name of the module in your configuration file. In this manner, the Policy will never be loaded, regardless of the "-severity" given to the Perl::Critic::Config constructor.

A simple configuration might look like this:

#--------------------------------------------------------------
# I think these are really important, so always load them
[TestingAndDebugging::RequireUseStrict]
severity = 5
[TestingAndDebugging::RequireUseWarnings]
severity = 5
#--------------------------------------------------------------
# I think these are less important, so only load when asked
[Variables::ProhibitPackageVars]
severity = 2
[ControlStructures::ProhibitPostfixControls]
allow = if unless  #My custom configuration
severity = 2
#--------------------------------------------------------------
# Give these policies a custom theme.  I can activate just
# these policies by saying (-theme => 'larry + curly')
[Modules::RequireFilenameMatchesPackage]
add_themes = larry
[TestingAndDebugging::RequireTestLabels]
add_themes = curly moe
#--------------------------------------------------------------
# I do not agree with these at all, so never load them
[-NamingConventions::Capitalization]
[-ValuesAndExpressions::ProhibitMagicNumbers]
#--------------------------------------------------------------
# For all other Policies, I accept the default severity, theme
# and other parameters, so no additional configuration is
# required for them.

For additional configuration examples, see the perlcriticrc file that is included in this t/examples directory of this distribution.

THE POLICIES

A large number of Policy modules are distributed with Perl::Critic. They are described briefly in the companion document Perl::Critic::PolicySummary and in more detail in the individual modules themselves.

POLICY THEMES

Each Policy is defined with one or more "themes". Themes can be used to create arbitrary groups of Policies. They are intended to provide an alternative mechanism for selecting your preferred set of Policies. For example, you may wish disable a certain subset of Policies when analyzing test programs. Conversely, you may wish to enable only a specific subset of Policies when analyzing modules.

The Policies that ship with Perl::Critic are have been broken into the following themes. This is just our attempt to provide some basic logical groupings. You are free to invent new themes that suit your needs.

THEME             DESCRIPTION
--------------------------------------------------------------------------
core              All policies that ship with Perl::Critic
pbp               Policies that come directly from "Perl Best Practices"
bugs              Policies that prevent or reveal bugs
maintenance       Policies that affect the long-term health of the code
cosmetic          Policies that only have a superficial effect
complexity        Policies that specifically relate to code complexity
security          Policies that relate to security issues
tests             Policies that are specific to test programs

Say `perlcritic -list` to get a listing of all available policies and the themes that are associated with each one. You can also change the theme for any Policy in your .perlcriticrc file. See the "CONFIGURATION" section for more information about that.

Using the "-theme" option, you can combine theme names with mathematical and boolean operators to create an arbitrarily complex expression that represents a custom "set" of Policies. The following operators are supported

Operator       Alternative         Meaning
----------------------------------------------------------------------------
*              and                 Intersection
-              not                 Difference
+              or                  Union

Operator precedence is the same as that of normal mathematics. You can also use parenthesis to enforce precedence. Here are some examples:

Expression                  Meaning
----------------------------------------------------------------------------
pbp * bugs                  All policies that are "pbp" AND "bugs"
pbp and bugs                Ditto
bugs + cosmetic             All policies that are "bugs" OR "cosmetic"
bugs or cosmetic            Ditto
pbp - cosmetic              All policies that are "pbp" BUT NOT "cosmetic"
pbp not cosmetic            Ditto
-maintenance                All policies that are NOT "maintenance"
not maintenance             Ditto
(pbp - bugs) * complexity     All policies that are "pbp" BUT NOT "bugs",
                                 AND "complexity"
(pbp not bugs) and complexity  Ditto

Theme names are case-insensitive. If "-theme" is set to an empty string, then it is equivalent to the set of all Policies. A theme name that doesn't exist is equivalent to an empty set. Please See http://en.wikipedia.org/wiki/Set for a discussion on set theory.
