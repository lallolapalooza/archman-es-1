Perl::Critic::Policy::InputOutput::ProhibitBacktickOperators(3pm) Documentación de Perl contribuida por el usuario Perl::Critic::Policy::InputOutput::ProhibitBacktickOperators(3pm)

NOMBRE

Perl::Critic::Policy::InputOutput::ProhibitBacktickOperators - Desaconsejar cosas como "@files = `ls $directory`".

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Los backticks son súper convenientes, especialmente para programas CGI, pero encuentro que hacen mucho ruido al llenar STDERR con mensajes cuando fallan. Creo que es mejor usar IPC::Open3 para atrapar toda la salida y dejar que la aplicación decida qué hacer con ella.

use IPC::Open3 'open3';
$SIG{CHLD} = 'IGNORE';
@output = `some_command`;                      # no está bien
my ($writer, $reader, $err);
open3($writer, $reader, $err, 'some_command'); # está bien;
@output = <$reader>;  # Salida aquí
@errors = <$err>;     # Errores aquí, en lugar de la consola

CONFIGURACIÓN

Alternativamente, si deseas usar backticks, puedes restringir las verificaciones a contextos vacíos agregando lo siguiente a tu archivo .perlcriticrc:

[InputOutput::ProhibitBacktickOperators]
only_in_void_context = 1

El propósito de los backticks es capturar la salida de un comando externo. Su uso en un contexto vacío es probablemente un error. Si la salida realmente no se requiere, se debe usar system(). De lo contrario, asigna el resultado a una variable.

`some_command`;                      # no está bien
$output = `some_command`;            # está bien
@output = `some_command`;            # está bien

NOTAS

Esta política también prohíbe la forma generalizada de backticks vista como "qx{}".

Ver perlipc para más discusión sobre el uso de wait() en lugar de "$SIG{CHLD} = 'IGNORE'".

Puedes considerar usar la función capture() del módulo IPC::System::Simple para una forma más segura de hacer lo que hacen los backticks, especialmente en Windows. El módulo también tiene un envoltorio seguro alrededor de system().
