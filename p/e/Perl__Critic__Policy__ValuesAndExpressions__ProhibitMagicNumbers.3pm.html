Perl::Critic::Policy::ValuesAndExpressions::ProhibitMagicNumbers(3pm) Documentación de Perl contribuida por el usuario Perl::Critic::Policy::ValuesAndExpressions::ProhibitMagicNumbers(3pm)

NOMBRE

Perl::Critic::Policy::ValuesAndExpressions::ProhibitMagicNumbers - No uses valores que no se explican por sí mismos.

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

¿Qué es un "número mágico"? Un número mágico es un número que aparece en el código sin ninguna explicación; por ejemplo, "$bank_account_balance *= 57.492;". Miras ese número y tienes que preguntarte de dónde vino. Como no entiendes la significación del número, no entiendes el código.

En general, los literales numéricos distintos de 0 o 1 no deben ser utilizados. Utiliza la pragma `constant` o los módulos `Readonly` o `Const::Fast` para dar un nombre descriptivo al número.

Por supuesto, hay excepciones a cuándo se debe aplicar esta regla. Un buen ejemplo es la colocación de objetos en algún contenedor, como formas en un plano o widgets en una interfaz de usuario. En estos casos, la significación de un número se puede determinar fácilmente por el contexto.

El número máximo de violaciones por documento para esta política por defecto es 10.

Formas en las que este módulo aplica esta regla.

Por defecto, esta regla es laxa en el sentido de que se permite el 2 para permitir cosas comunes como la alternancia, el manejador de archivos STDERR, etc.

Los literales numéricos están permitidos en las sentencias "use" y "require" para permitir cosas como restricciones de versión de Perl y planes de Test::More. Las declaraciones de variables de paquete $VERSION están permitidas. El uso de "Readonly", "Readonly::Scalar", "Readonly::Array", y "Readonly::Hash" del módulo Readonly son obviamente válidos, pero el uso de "Readonly::Scalar1", "Readonly::Array1", y "Readonly::Hash1" no son específicamente soportados.

El uso de números binarios, exponenciales, hexadecimales, octales y de versión, incluso para 0 y 1, fuera de las sentencias "use"/"require"/"Readonly" no están permitidos (pero puedes cambiar esto).

Hay una exención especial para acceder al último elemento de un array, es decir, $x[-1].

$x = 0;                                   # ok
$x = 0.0;                                 # ok
$x = 1;                                   # ok
$x = 1.0;                                 # ok
$x = 1.5;                                 # no ok
$x = 0b0                                  # no ok
$x = 0b1                                  # no ok
$x = 0x00                                 # no ok
$x = 0x01                                 # no ok
$x = 000                                  # no ok
$x = 001                                  # no ok
$x = 0e1                                  # no ok
$x = 1e1                                  # no ok
$frobnication_factor = 42;                # no ok
use constant FROBNICATION_FACTOR => 42;   # ok
use 5.6.1;                                # ok
use Test::More plan => 57;                # ok
plan tests => 39;                         # ok
our $VERSION = 0.22;                      # ok
$x = $y[-1]                               # ok
$x = $y[-2]                               # no ok
foreach my $solid (1..5) {                # no ok
    ...
}
use Readonly;
Readonly my $REGULAR_GEOMETRIC_SOLIDS => 5;
foreach my $solid (1..$REGULAR_GEOMETRIC_SOLIDS) {  # ok
    ...
}

CONFIGURACIÓN

Esta política tiene cuatro opciones: "allowed_values", "allowed_types", "allow_to_the_right_of_a_fat_comma", y "constant_creator_subroutines".

"allowed_values"

El parámetro "allowed_values" es un conjunto de valores numéricos permitidos delimitados por espacios; esto no afecta a los formatos numéricos permitidos. Los valores por defecto son equivalentes a tener lo siguiente en tu .perlcriticrc:

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_values = 0 1 2

Ten en cuenta que esta política fuerza los valores 0 y 1 en los valores permitidos. Por lo tanto, especificar ningún valor,

allowed_values =

es lo mismo que simplemente listar 0 y 1:

allowed_values = 0 1

El valor especial "all_integers", como era de esperar, permite que todos los valores integrales pasen, sujetos a las restricciones de tipos de número.

Se pueden especificar rangos como dos números (posiblemente fraccionarios) separados por dos puntos, opcionalmente con un sufijo de incremento utilizando la sintaxis :by() de Perl 6. Por ejemplo:

allowed_values = 7..10

permitirá 0, 1, 7, 8, 9 y 10 como valores literales. Usando valores fraccionarios de esta manera

allowed_values = -3.5..-0.5:by(0.5)

permitirá -3.5, -3, -2.5, -2, -2.5, -1, -0.5, 0 y 1. Como era de esperar, el incremento por defecto es 1, lo que significa que

allowed_values = -3.5..-0.5

hará válidos -3.5, -2.5, -2.5, -0.5, 0 y 1.

Los rangos no son perezosos, es decir, más vale que tengas mucha memoria disponible si usas un rango de "1..1000:by(0.01)". Recuerda también que todo esto se hace utilizando matemáticas de punto flotante, lo que significa que "1..10:by(0.3333)" probablemente no será muy útil.

Especificar un límite superior menor que el límite inferior resultará en que no se produzcan valores a partir de ese rango. No se permiten incrementos negativos.

Se permiten múltiples rangos.

Para poner todo esto junto, la siguiente es una entrada válida, aunque probablemente no se use, en el .perlcriticrc:

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_values = 3.1415269 82..103 -507.4..57.8:by(0.2) all_integers

"allowed_types"

El parámetro "allowed_types" es un conjunto de subclases de PPI::Token::Number delimitadas por espacios.

Los enteros decimales siempre están permitidos. Por defecto, los números de punto flotante también están permitidos.

Por ejemplo, para permitir literales hexadecimales, puedes configurar esta política así

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_types = Hex

pero sin especificar nada para "allowed_values", los literales hexadecimales permitidos serán 0x00, 0x01 y 0x02. Ten en cuenta que tan pronto como especifiques un valor para este parámetro, debes incluir "Float" en la lista para poder seguir utilizando literales de punto flotante. Este efecto se puede utilizar para restringir los literales solo a enteros decimales:

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_types =

Si permites la notación exponencial, automáticamente también permites valores de punto flotante porque un exponencial es una subclase de punto flotante en PPI.

"allow_to_the_right_of_a_fat_comma"

Si esto está configurado, puedes poner cualquier número a la derecha de una coma gorda.

my %hash =     ( a => 4512, b => 293 );         # ok
my $hash_ref = { a => 4512, b => 293 };         # ok
some_subroutine( a => 4512, b => 293 );         # ok

Actualmente, esto solo significa *directamente* a la derecha de la coma gorda. Por defecto, este valor es *true*.

CONFIGURATION

"constant_creator_subroutines"

Este parámetro te permite especificar los nombres de las subrutinas que crean constantes, además de "Readonly", "Const::Fast" y similares. Por ejemplo, si usas un módulo personalizado similar a "Const::Fast" que soporte una subrutina "create_constant" para crear constantes, podrías agregar algo como lo siguiente a tu .perlcriticrc:

[ValuesAndExpressions::ProhibitMagicNumbers]
constant_creator_subroutines = create_constant

Si tienes más de un nombre que agregar, sepáralos por espacios en blanco.

El nombre de la subrutina debe aparecer exactamente como está en tu código. Por ejemplo, si tu código no importa la subrutina de creación, necesitarías configurar esta política como algo parecido a

[ValuesAndExpressions::ProhibitMagicNumbers]
constant_creator_subroutines = create_constant Constant::Create::create_constant

BUGS

Actualmente no hay forma de permitir números de versión en código regular, incluso si los incluyes en "allowed_types". Algunos pueden considerar esto una característica.
