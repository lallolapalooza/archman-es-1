Perl::Critic::Policy::BuiltinFunctions::ProhibitComplexMappings(3pm) Documentación de Perl contribuida por el usuario Perl::Critic::Policy::BuiltinFunctions::ProhibitComplexMappings(3pm)

NOMBRE

Perl::Critic::Policy::BuiltinFunctions::ProhibitComplexMappings - Los bloques de map deben tener una sola sentencia.

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

La función map puede ser confusa para los novatos en las mejores circunstancias. Los mapeos con múltiples sentencias son aún peores. También son una pesadilla para los mantenedores porque cualquier complejidad añadida disminuye drásticamente la legibilidad. ¿Por qué? Porque map es tradicionalmente una línea para convertir un array en otro. Intentar meter mucha funcionalidad en una sola línea es una mala idea en general.

Las mejores soluciones para un mapeo complejo son: 1) escribir una subrutina que realice la manipulación y llamarla desde map; 2) reescribir el map como un bucle for.

ADVERTENCIAS

Esta política actualmente no detecta algunas sentencias compuestas dentro del map. Por ejemplo, el siguiente código incorrectamente no genera una violación:

map { do { foo(); bar() } } @list

CONFIGURACIÓN

Por defecto, esta política marca cualquier mapeo con más de una sentencia. Aunque no lo recomendamos, puede aumentar este límite de la siguiente manera en un archivo .perlcriticrc:

[BuiltinFunctions::ProhibitComplexMappings]
max_statements = 2
