PEM_bytes_read_bio(3ssl)

Paquete: openssl

Licencias: Apache-2.0

PEM_bytes_read_bio(3ssl) OpenSSL PEM_bytes_read_bio(3ssl)

NOMBRE

PEM_bytes_read_bio, PEM_bytes_read_bio_secmem - leer una estructura de datos codificada en PEM de un BIO

SINOPSIS

#include <openssl/pem.h>
int PEM_bytes_read_bio(unsigned char **pdata, long *plen, char **pnm,
                       const char *name, BIO *bp, pem_password_cb *cb,
                       void *u);
int PEM_bytes_read_bio_secmem(unsigned char **pdata, long *plen, char **pnm,
                              const char *name, BIO *bp, pem_password_cb *cb,
                              void *u);

DESCRIPCIÓN

PEM_bytes_read_bio() lee datos con formato PEM (IETF RFC 1421 e IETF RFC 7468) del BIO bp para el tipo de datos dado en name (RSA PRIVATE KEY, CERTIFICATE, etc.). Si hay múltiples estructuras de datos codificadas en PEM presentes en el mismo flujo, PEM_bytes_read_bio() omitirá los tipos de datos que no coincidan y continuará leyendo. Los datos no PEM presentes en el flujo pueden provocar un error.

La cabecera PEM puede indicar que los datos siguientes están cifrados; si es así, los datos se descifrarán, esperando la entrada del usuario para suministrar una contraseña si es necesario. La función de contraseña (callback) cb y el dato u se utilizan para obtener la contraseña de descifrado, si es aplicable.

Algunos tipos de datos tienen alias de compatibilidad, como un archivo que contiene X509 CERTIFICATE que coincide con una solicitud para el tipo obsoleto CERTIFICATE. El tipo real indicado por el archivo se devuelve en *pnm si pnm no es NULL. El llamador debe liberar el almacenamiento apuntado por *pnm.

Los datos devueltos son la forma codificada en DER del tipo solicitado, en *pdata con longitud *plen. El llamador debe liberar el almacenamiento apuntado por *pdata.

PEM_bytes_read_bio_secmem() es similar a PEM_bytes_read_bio(), pero utiliza memoria del montón seguro para sus búferes temporales y el almacenamiento devuelto en *pdata y *pnm. En consecuencia, el llamador debe usar OPENSSL_secure_free() para liberar dicho almacenamiento.

NOTAS

PEM_bytes_read_bio_secmem() solo garantiza que el montón seguro se utiliza para el almacenamiento asignado dentro de la pila de procesamiento PEM. La pila de BIO de la que se leen los datos de entrada también puede usar búferes temporales, que no se asignan necesariamente desde el montón seguro. En casos en los que sea deseable asegurar que el contenido del archivo PEM solo aparezca en memoria del montón seguro, se requiere cuidado al generar el BIO pasado como bp. En particular, el uso de BIO_s_file() indica el uso de la funcionalidad stdio del sistema operativo, que incluye el almacenamiento en búfer como una característica; BIO_s_fd() es probablemente más apropiado en tales casos.

Estas funciones no hacen suposiciones sobre la frase de paso recibida de la función de contraseña. Simplemente se tratará como una secuencia de bytes.

VALORES DE RETORNO

PEM_bytes_read_bio() y PEM_bytes_read_bio_secmem() devuelven 1 en caso de éxito o 0 en caso de error.

VER TAMBIÉN

PEM_read_bio_ex(3), passphrase-encoding(7)

HISTORIA

PEM_bytes_read_bio_secmem() se introdujo en OpenSSL 1.1.1
