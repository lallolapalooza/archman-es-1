Perl::Critic::Policy::Subroutines::ProhibitExcessComplexity(3pm) Documentación de Perl contribuida por el usuario Perl::Critic::Policy::Subroutines::ProhibitExcessComplexity(3pm)

NOMBRE

Perl::Critic::Policy::Subroutines::ProhibitExcessComplexity - Minimizar la complejidad factorizando el código en subrutinas más pequeñas.

AFILIACIÓN

Esta Política es parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Todo lo demás siendo igual, el código complicado es más propenso a errores y más caro de mantener que el código más simple. El primer paso para gestionar la complejidad es establecer métricas formales de complejidad. Una de esas métricas es la puntuación de McCabe, que describe el número de rutas posibles a través de una subrutina. Esta Política aproxima la puntuación de McCabe sumando el número de sentencias y operadores condicionales dentro de una subrutina. La investigación ha demostrado que una puntuación de McCabe superior a 20 es un signo de código de alto riesgo y potencialmente inverificable. Ver http://en.wikipedia.org/wiki/Cyclomatic_complexity para alguna discusión sobre el número de McCabe y otras métricas de complejidad.

La prescripción habitual para reducir la complejidad es refactorizar el código en subrutinas más pequeñas. El libro de Mark Dominus "Higher Order Perl" también describe callbacks, recursión, memoización, iteradores y otras técnicas que ayudan a crear código Perl simple y extensible.

CONFIGURACIÓN

El McCabe máximo aceptable se puede establecer con el elemento de configuración "max_mccabe". Cualquier subrutina con una puntuación de McCabe superior a este número generará una violación de la política. El valor predeterminado es 20. Un ejemplo de sección para un .perlcriticrc:

[Subroutines::ProhibitExcessComplexity]
max_mccabe = 30

NOTAS

"Todo debe hacerse lo más simple posible, pero no más simple."
                                                -- Albert Einstein

La complejidad es subjetiva, pero las métricas de complejidad formales siguen siendo increíblemente valiosas. Cada problema tiene un nivel inherente de complejidad, por lo que no es necesariamente óptimo minimizar el número de McCabe. Así que no te ofendas si tu código activa esta Política. Simplemente considera si podría haber una forma más simple de hacer el trabajo.
