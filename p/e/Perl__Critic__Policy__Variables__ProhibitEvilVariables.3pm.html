Perl::Critic::Policy::Variables::ProhibitEvilVariables(3pm) Documentación de Perl aportada por el usuario Perl::Critic::Policy::Variables::ProhibitEvilVariables(3pm)

NOMBRE

Perl::Critic::Policy::Variables::ProhibitEvilVariables - Prohíbe variables que no han sido bendecidas por tu tienda.

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Utiliza esta política si deseas prohibir el uso de variables específicas. Estas pueden ser variables globales sobre las que se advierte en "perlvar", o simplemente variables cuyos nombres no te gustan.

CONFIGURACIÓN

El conjunto de variables prohibidas se puede configurar a través de las opciones "variables" y "variables_file".

El valor de "variables" debe ser una cadena de nombres de variables completamente cualificados y/o expresiones regulares delimitadas por espacios. Un ejemplo de prohibición de dos variables específicas en un archivo .perlcriticrc:

[Variables::ProhibitEvilVariables]
variables = $[ $^S $SIG{__DIE__}

Si prohíbes un array o un hash (por ejemplo, @INC), el uso de elementos del array o hash también estará prohibido. Si especificas una variable con subíndice (por ejemplo, $SIG{__DIE__}), solo se detectará el subíndice literal especificado. El archivo <.perlcritic> anterior, por ejemplo, provocará que "perlcritic (1)" detecte "$SIG{__DIE__} = \&foo", pero no

my $foo = '__DIE__';
$SIG{$foo} = \&foo;

Las expresiones regulares se identifican por valores que comienzan y terminan con barras inclinadas. Se prohibirá cualquier variable cuyo nombre coincida con "m/patrón/sm". Por ejemplo:

[Variables::ProhibitEvilVariables]
variables = /acme/

prohibirá todas las variables que coincidan con "m/acme/". Si deseas una verificación sin distinción entre mayúsculas y minúsculas, puedes usar (?i: ... ). Por ejemplo

[Variables::ProhibitEvilVariables]
variables = /(?i:acme)/

prohíbe variables que coincidan con "m/acme/smi".

Además, puedes anular el mensaje predeterminado ("Variable prohibida "variable" utilizada") con el tuyo propio, para dar sugerencias de acciones alternativas. Para hacerlo, pon tu mensaje entre llaves después del nombre de la variable o la expresión regular. Así:

[Variables::ProhibitEvilVariables]
variables = $[ {Se encontró uso de $[. Programa con índice base 0 en su lugar}

Si tu mensaje contiene llaves, puedes encerrarlo entre paréntesis, corchetes angulares o corchetes en su lugar.

De manera similar, la opción "variables_file" proporciona el nombre de un archivo que contiene especificaciones de variables prohibidas. Solo se permite una especificación de variable por línea y los comentarios comienzan con un octothorp y van hasta el final de la línea; no es necesario usar llaves para delimitar mensajes:

$[      # Prohíbe la variable "$[" y usa el mensaje predeterminado.
# Prohíbe la variable "$^S" y proporciona un mensaje de reemplazo.
$^S     Tener que pensar en $^S en los manejadores de excepciones está mal
# Usa una expresión regular.
/acme/  No se permiten coyotes.

Por defecto, no hay variables prohibidas, aunque podría pensar en algunas que deberían estarlo. Consulta "perldoc perlvar" para ver algunas sugerencias.

RESTRICCIONES

Las variables de la forma "${^foo}" no son reconocidas por PPI a partir de la versión 1.206. Cuando PPI las reconozca, esta política funcionará para ellas también.

Solo se reconocerán las referencias directas a variables prohibidas y a subíndices literales. Por ejemplo, si prohíbes $[, la primera línea en

my $foo = \$[;
$$foo = 1;

será marcada como una violación, pero no la segunda, aunque la segunda, de hecho, asigne a $[. De manera similar, si prohíbes $SIG{__DIE__}, esta política no reconocerá

my $foo = '__DIE__';
$SIG{$foo} = sub {warn '¡No puedo morir!'};

como una asignación a $SIG{__DIE__}.

NOTAS

Esta política se basa en gran medida en Perl::Critic::Policy::Modules::ProhibitEvilModules de Jeffrey Ryan Thalhammer.
