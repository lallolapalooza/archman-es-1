Perl::Critic::Policy::Subroutines::RequireArgUnpacking(3pm) Documentación Perl contribuida por el usuario Perl::Critic::Policy::Subroutines::RequireArgUnpacking(3pm)

NOMBRE

Perl::Critic::Policy::Subroutines::RequireArgUnpacking - Desempaquetar siempre "@_" primero.

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Las subrutinas que usan @_ directamente en lugar de desempaquetar los argumentos en variables locales primero tienen dos problemas importantes. Primero, son muy difíciles de leer. ¡Si vas a referirte a tus variables por número en lugar de por nombre, podrías estar escribiendo código ensamblador! Segundo, @_ contiene alias a las variables originales. Si modificas el contenido de una entrada de @_, entonces estás modificando la variable fuera de tu subrutina. Por ejemplo:

sub print_local_var_plus_one {
    my ($var) = @_;
    print ++$var;
}
sub print_var_plus_one {
    print ++$_[0];
}
my $x = 2;
print_local_var_plus_one($x); # imprime "3", $x sigue siendo 2
print_var_plus_one($x);       # imprime "3", ¡$x ahora es 3!
print $x;                     # imprime "3"

Esto es una acción fantasmal a distancia y es muy difícil de depurar si no es intencional y está bien documentado (como "chop" o "chomp").

Se hace una excepción para el modismo de delegación habitual "$object->SUPER::something( @_ )". Solo se reconocen "SUPER::" y "NEXT::" (aunque esto es configurable) y la lista de argumentos para el delegado debe consistir únicamente en "( @_ )".

CONFIGURACIÓN

Esta política es indulgente con las subrutinas que tienen "N" o menos declaraciones de nivel superior, donde "N" por defecto es CERO. Puedes anular esto para establecerlo a un número mayor con la configuración "short_subroutine_statements". Esto no se recomienda en absoluto, pero quizás REALMENTE necesites un alto rendimiento. Para hacer esto, coloca entradas en un archivo .perlcriticrc como este:

[Subroutines::RequireArgUnpacking]
short_subroutine_statements = 2

Por defecto, esta política no te permite especificar subíndices de array cuando desempaquetas argumentos (es decir, mediante una porción de array o haciendo referencia a elementos individuales). Si deseas permitir esto, puedes hacerlo usando la configuración "allow_subscripts". Esto por defecto es falso. Puedes establecerlo a verdadero así:

[Subroutines::RequireArgUnpacking]
allow_subscripts = 1

La lógica de delegación se puede configurar para permitir la delegación distinta de a "SUPER::" o "NEXT::". El elemento de configuración es "allow_delegation_to" y toma una lista separada por espacios de delegados permitidos. Si un delegado dado termina en doble dos puntos, se permite cualquier cosa en el espacio de nombres dado. Si no es así, solo se permite esa subrutina. Por ejemplo, para permitir "next::method" de "Class::C3" y _delegate del espacio de nombres actual además de SUPER y NEXT, se podría usar la siguiente configuración:

[Subroutines::RequireArgUnpacking]
allow_delegation_to = next::method _delegate

Herramientas de validación de argumentos como Params::Validate generan un cierre que se utiliza para desempaquetar y validar los argumentos de una subrutina. Para reconocer los cierres como una forma válida de desempaquetar argumentos, debes habilitarlos explícitamente:

[Subroutines::RequireArgUnpacking]
allow_closures = 1

ADVERTENCIAS

PPI actualmente no detecta subrutinas anónimas, por lo que no las verificamos. Esto debería funcionar cuando PPI adquiera esa función.

No verificamos @ARG, el alias de @_ de English.pm. Eso ya está obsoleto de todos modos.
