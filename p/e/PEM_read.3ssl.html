PEM_read(3ssl)

Paquete: openssl

Licencias: Apache-2.0

PEM_READ(3ssl) OpenSSL PEM_READ(3ssl)

NOMBRE

PEM_read, PEM_read_bio, PEM_do_header, PEM_get_EVP_CIPHER_INFO, PEM_write, PEM_write_bio, PEM_ASN1_write, PEM_ASN1_write_bio, PEM_ASN1_write_bio_ctx - Rutinas de codificación PEM

SINOPSIS

#include <openssl/pem.h>
int PEM_read(FILE *fp, char **name, char **header,
             unsigned char **data, long *len);
int PEM_read_bio(BIO *bp, char **name, char **header,
                 unsigned char **data, long *len);
int PEM_get_EVP_CIPHER_INFO(char *header, EVP_CIPHER_INFO *cinfo);
int PEM_do_header(EVP_CIPHER_INFO *cinfo, unsigned char *data, long *len,
                  pem_password_cb *cb, void *u);
int PEM_write(FILE *fp, const char *name, const char *header,
              const unsigned char *data, long len);
int PEM_write_bio(BIO *bp, const char *name, const char *header,
                  const unsigned char *data, long len);
int PEM_ASN1_write(i2d_of_void *i2d, const char *name, FILE *fp,
                   const void *x, const EVP_CIPHER *enc,
                   const unsigned char *kstr, int klen,
                   pem_password_cb *callback, void *u);
int PEM_ASN1_write_bio(i2d_of_void *i2d, const char *name, BIO *bp,
                       const void *x, const EVP_CIPHER *enc,
                       const unsigned char *kstr, int klen,
                       pem_password_cb *callback, void *u);
int PEM_ASN1_write_bio_ctx(OSSL_i2d_of_void_ctx *i2d, void *vctx,
                           const char *name, BIO *bp, const void *x,
                           const EVP_CIPHER *enc, const unsigned char *kstr,
                           int klen, pem_password_cb *callback, void *u);

DESCRIPCIÓN

Estas funciones leen y escriben objetos codificados en PEM, utilizando el tipo PEM name, cualquier información de header adicional y los data brutos de longitud len.

PEM es el término utilizado para la codificación de contenido binario definida por primera vez en el RFC 1421 de la IETF. El contenido es una serie de líneas codificadas en base64, rodeadas por marcadores de inicio/fin cada una en su propia línea. Por ejemplo:

-----BEGIN PRIVATE KEY-----
MIICdg....
... bhTQ==
-----END PRIVATE KEY-----

Las líneas de encabezado opcionales pueden aparecer después de la línea de inicio, y su existencia depende del tipo de objeto que se esté escribiendo o leyendo.

PEM_write() escribe en el archivo fp, mientras que PEM_write_bio() escribe en el BIO bp. El name es el nombre a usar en el marcador, el header es el valor del encabezado o NULL, y data y len especifican los datos y su longitud.

El buffer de data final es típicamente un objeto ASN.1 que puede ser decodificado con la función d2i apropiada al tipo name; consulte d2i_X509(3) para ver ejemplos.

PEM_read() lee del archivo fp, mientras que PEM_read_bio() lee del BIO bp. Ambas omiten cualquier dato que no sea PEM que preceda al inicio del siguiente objeto PEM. Cuando se recupera exitosamente un objeto, el nombre del tipo de la línea "----BEGIN <type>-----" se devuelve a través del argumento name, los encabezados de encapsulación se devuelven en header y el contenido decodificado en base64 y su longitud se devuelven a través de data y len respectivamente. Los punteros name, header y data se asignan a través de OPENSSL_malloc() y deben ser liberados por el llamador a través de OPENSSL_free() cuando ya no sean necesarios.

PEM_get_EVP_CIPHER_INFO() se puede utilizar para determinar si los data devueltos por PEM_read() o PEM_read_bio() están cifrados y para recuperar el cifrador y el IV asociados. El llamador pasa un puntero a una estructura de tipo EVP_CIPHER_INFO a través del argumento cinfo y el header devuelto por PEM_read() o PEM_read_bio(). Si la llamada es exitosa, se devuelve 1 y el cifrador y el IV se almacenan en la dirección apuntada por cinfo. Cuando el encabezado está mal formado, no es compatible o ocurre algún error interno, se devuelve 0. Esta función está obsoleta, consulte las NOTAS a continuación.

PEM_do_header() se puede utilizar entonces para descifrar los datos si el encabezado indica cifrado. El argumento cinfo es un puntero a la estructura inicializada por la llamada anterior a PEM_get_EVP_CIPHER_INFO(). Los argumentos data y len son los devueltos por la llamada anterior a PEM_read() o PEM_read_bio(). Los argumentos cb y u permiten anular la función predeterminada de solicitud de contraseña, como se describe en PEM_read_PrivateKey(3). Al completarse con éxito, los data se descifran en el lugar y len se actualiza para indicar la longitud del texto plano. Esta función está obsoleta, consulte las NOTAS a continuación.

Si se sabe de antemano que los datos no están cifrados, entonces ni PEM_do_header() ni PEM_get_EVP_CIPHER_INFO() necesitan ser llamados.

VALORES DE RETORNO

PEM_read() y PEM_read_bio() devuelven 1 en caso de éxito y 0 en caso de fallo, este último incluye el caso en que no quedan más objetos PEM en el archivo de entrada. Para distinguir el final del archivo de errores más graves, el llamador debe examinar la pila de errores y comprobar si hay PEM_R_NO_START_LINE, lo que indica que no se encontraron más objetos PEM. Consulte ERR_peek_last_error(3), ERR_GET_REASON(3).

PEM_get_EVP_CIPHER_INFO() y PEM_do_header() devuelven 1 en caso de éxito y 0 en caso de fallo. Los data probablemente no tendrán sentido si estas funciones fallan.

NOTAS

Las funciones PEM_get_EVP_CIPHER_INFO() y PEM_do_header() están obsoletas. Esto se debe a que el formato de cifrado PEM subyacente está obsoleto y debe evitarse. Utiliza un formato de cifrado con una función de derivación de claves específica de OpenSSL, que emplea MD5 con un recuento de iteraciones de 1. En su lugar, las claves privadas deben almacenarse en formato PKCS#8, con una PBE fuerte PKCS#5 v2.0. Consulte PEM_write_PrivateKey(3) y d2i_PKCS8PrivateKey_bio(3).

PEM_do_header() no hace suposiciones sobre la frase de contraseña recibida del callback de contraseña. Simplemente se tratará como una secuencia de bytes.

PEM_write() y PEM_write_bio() devuelven el número de bytes codificados (sin contar el encabezado PEM ni el marcador final) escritos en caso de éxito o 0 en caso de fallo.

PEM_ASN1_write_bio() y PEM_ASN1_write_bio_ctx() devuelven 1 en caso de éxito y 0 en caso de fallo. Esta última función pasa un valor de contexto adicional proporcionado por la aplicación a la función i2d que serializa el objeto ASN.1 de entrada.

VER TAMBIÉN

ERR_peek_last_error(3), ERR_GET_LIB(3), d2i_PKCS8PrivateKey_bio(3), passphrase-encoding(7)

HISTORIA

La función PEM_ASN1_write_bio_ctx() se añadió en OpenSSL 3.5.

NOMBRE

PEM_read, PEM_read_bio, PEM_write, PEM_write_bio - Cargar y guardar datos PEM de/a un BIO

SINOPSIS

#include <openssl/pem.h>

int PEM_write(FILE *fp, char *name, char *header, unsigned char *data,
              long len, char *encname, char *passwd, int plen,
              int format);
int PEM_write_bio(BIO *bp, char *name, char *header, unsigned char *data,
                  long len, char *encname, char *passwd, int plen,
                  int format);

int PEM_read(FILE *fp, char **name, char **header, unsigned char **data,
             long *len, char *encname, int format);
int PEM_read_bio(BIO *bp, char **name, char **header, unsigned char **data,
                 long *len, char *encname, int format);

DESCRIPCIÓN

Estas funciones implementan la carga y escritura de datos codificados en formato PEM. El formato PEM es un estándar de facto para el almacenamiento de datos criptográficos en archivos de texto plano. Normalmente se utiliza para almacenar claves privadas, certificados públicos y otras estructuras de datos relacionadas con la criptografía.

Las funciones PEM_write() y PEM_write_bio() escriben datos en formato PEM. Toman varios argumentos:

  • fp (para PEM_write) o bp (para PEM_write_bio): Un puntero a un objeto FILE o BIO en el que se escribirán los datos.
  • name: El nombre del tipo de objeto PEM (por ejemplo, "CERTIFICATE", "PRIVATE KEY").
  • header: Un campo de cabecera opcional, normalmente NULL.
  • data: Un puntero a los datos sin procesar que se van a codificar y escribir.
  • len: La longitud de los datos sin procesar en bytes.
  • encname: El nombre del algoritmo de cifrado utilizado, si procede. Si es NULL, los datos no se cifran.
  • passwd: La contraseña utilizada para cifrar los datos, si procede.
  • plen: La longitud de la contraseña en bytes.
  • format: Un indicador de formato, normalmente 0 para el formato estándar PEM.

Las funciones PEM_read() y PEM_read_bio() leen datos en formato PEM. Toman los siguientes argumentos:

  • fp (para PEM_read) o bp (para PEM_read_bio): Un puntero a un objeto FILE o BIO del que se leerán los datos.
  • name: Un puntero a un puntero que contendrá el nombre del tipo de objeto PEM leído. Se asignará memoria para esto si es necesario.
  • header: Un puntero a un puntero que contendrá cualquier cabecera opcional leída. Se asignará memoria para esto si es necesario.
  • data: Un puntero a un puntero que contendrá los datos sin procesar leídos. Se asignará memoria para esto si es necesario.
  • len: Un puntero a un long que contendrá la longitud de los datos sin procesar leídos.
  • encname: El nombre del algoritmo de cifrado utilizado, si procede.
  • format: Un indicador de formato, normalmente 0 para el formato estándar PEM.

VALORES DE RETORNO

Estas funciones devuelven 1 en caso de éxito y 0 en caso de error.

NOTAS

Las funciones PEM_read() y PEM_read_bio() asignan memoria para name, header y data. El llamador es responsable de liberar esta memoria usando OPENSSL_free() cuando ya no sea necesaria.

Los algoritmos de cifrado soportados y sus nombres se especifican en la documentación de las funciones de cifrado de OpenSSL.
