Perl::Critic::Policy::Subroutines::RequireFinalReturn(3pm) Documentación de Perl aportada por el usuario Perl::Critic::Policy::Subroutines::RequireFinalReturn(3pm)

NOMBRE

Perl::Critic::Policy::Subroutines::RequireFinalReturn - Termina cada camino de una subrutina con una instrucción "return" explícita.

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

Requiere que todas las subrutinas terminen explícitamente con una de las siguientes: "return", "carp", "croak", "die", "exec", "exit", "goto", o "throw".

Las subrutinas sin instrucciones de retorno explícitas al final pueden ser confusas. Puede ser difícil deducir cuál será el valor de retorno.

Además, si el programador no pretendía que hubiera un valor de retorno significativo y omite una instrucción de retorno, parte de los datos internos de la subrutina pueden filtrarse al exterior. Considere este caso:

package Password;
# cada vez que el usuario adivina mal la contraseña, su valor
# se rota en un carácter
my $password;
sub set_password {
    $password = shift;
}
sub check_password {
    my $guess = shift;
    if ($guess eq $password) {
        unlock_secrets();
    } else {
        $password = (substr $password, 1).(substr $password, 0, 1);
    }
}
1;

En este caso, la última instrucción en check_password() es la asignación. El resultado de esa asignación es el valor de retorno implícito, ¡así que un intento fallido devuelve la contraseña correcta! Añadir un "return;" al final de esa subrutina resuelve el problema.

La única excepción permitida es una subrutina vacía.

Tenga cuidado al solucionar problemas identificados por esta política; no ponga ciegamente una instrucción "return;" al final de cada subrutina.

CONFIGURACIÓN

Si ha creado sus propias funciones terminales que se comportan como "die" o "exit", puede configurar Perl::Critic para que reconozca esas funciones también. Simplemente ponga algo como esto en su .perlcriticrc:

[Subroutines::RequireFinalReturn]
terminal_funcs = quit abort bailout

Si ha creado sus propios métodos terminales, puede configurar Perl::Critic para que reconozca esos métodos también, pero la clase no se considerará. Por ejemplo, si define throw_exception como terminal, entonces cualquier método con ese nombre será terminal, independientemente de la clase. Simplemente ponga algo como esto en su .perlcriticrc:

[Subroutines::RequireFinalReturn]
terminal_methods = throw_exception

ERRORES

No buscamos retornos dentro de operadores ternarios. Esa construcción es demasiado complicada de analizar en este momento. Además, una forma mejor es el retorno fuera del ternario como este: "return foo ? 1 : bar ? 2 : 3"
