Perl::Critic::Policy::InputOutput::ProhibitExplicitStdin(3pm) Documentación de Perl contribuida por el usuario Perl::Critic::Policy::InputOutput::ProhibitExplicitStdin(3pm)

NOMBRE

Perl::Critic::Policy::InputOutput::ProhibitExplicitStdin - Usa "<>" o "<ARGV>" o un módulo de solicitud en su lugar de "<STDIN>".

AFILIACIÓN

Esta política forma parte de la distribución central de Perl::Critic.

DESCRIPCIÓN

Perl tiene un manejador de archivos mágico útil llamado *ARGV que comprueba la línea de comandos y si hay algún argumento, abre y lee esos como archivos. Si no hay argumentos, *ARGV se comporta como *STDIN en su lugar. Este comportamiento es casi siempre lo que quieres si quieres crear un programa que lea desde "STDIN". Esto a menudo se escribe en una de las siguientes dos formas equivalentes:

while (<ARGV>) {
  # ... haz algo con cada línea de entrada ...
}
# o, equivalentemente:
while (<>) {
  # ... haz algo con cada línea de entrada ...
}

Si deseas solicitar la entrada del usuario, prueba módulos especiales como IO::Prompt.

CONFIGURACIÓN

Esta política no es configurable, excepto por las opciones estándar.

ADVERTENCIAS

Debido a un error en la versión actual de PPI (v1.119_03) y anteriores, el operador de lectura se interpreta a menudo como operadores menor que y mayor que después de una coma. Por lo tanto, esta política no detecta casos importantes como

my $content = join '', <STDIN>;

porque interpreta esa línea como la declaración sin sentido:

my $content = join '', < STDIN >;

Cuando ese error de PPI se corrija, esta política debería comenzar a detectar esas violaciones automáticamente.
