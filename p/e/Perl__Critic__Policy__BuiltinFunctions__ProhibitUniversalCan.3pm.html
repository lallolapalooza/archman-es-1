Perl::Critic::Policy::BuiltinFunctions::ProhibitUniversalCan(3pm) Documentación de Perl aportada por el usuario Perl::Critic::Policy::BuiltinFunctions::ProhibitUniversalCan(3pm)

NOMBRE

Perl::Critic::Policy::BuiltinFunctions::ProhibitUniversalCan - Escribe "eval { $foo->can($name) }" en lugar de "UNIVERSAL::can($foo, $name)".

AFILIACIÓN

Esta política forma parte de la distribución principal de Perl::Critic.

DESCRIPCIÓN

print UNIVERSAL::can($obj, 'Foo::Bar') ? 'yes' : 'no';  #no está bien
print eval { $obj->can('Foo::Bar') } ? 'yes' : 'no';    #está bien

A partir de Perl 5.9.3, se ha desaconsejado el uso de UNIVERSAL::can como función y se prefiere la forma de método. Anteriormente, la forma funcional se recomendaba porque daba resultados válidos incluso cuando el objeto era "undef" o un escalar sin bendecir. Sin embargo, la forma funcional hace imposible que los paquetes anulen can(), una técnica que es crucial para implementar objetos simulados y algunas fachadas.

Consulta UNIVERSAL::can para una discusión más exhaustiva sobre este tema.

CONFIGURACIÓN

Esta política no es configurable, excepto para las opciones estándar.
