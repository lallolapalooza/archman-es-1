PMNS(5) Manual de formatos de archivo PMNS(5)

NOMBRE

PMNS - el espacio de nombres de métricas de rendimiento

SINOPSIS

$PCP_VAR_DIR/pmns

DESCRIPCIÓN

Al utilizar la Interfaz de Programación de Métricas de Rendimiento (PMAPI) del Performance Co-Pilot (PCP), las métricas de rendimiento se identifican mediante un nombre externo en un espacio de nombres jerárquico de métricas de rendimiento (PMNS) y un identificador interno, el Identificador de Métrica de Rendimiento (PMID).

Un PMNS especifica la asociación entre el nombre de una métrica y su PMID.

Un PMNS se define en uno o más archivos fuente ASCII.

La carga de un PMNS se realiza llamando a pmLoadNameSpace(3) o pmLoadASCIINameSpace(3).

A partir de la versión 3.10.3 de PCP, por defecto **se permiten** nombres duplicados para el mismo PMID en el PMNS, aunque pmLoadASCIINameSpace(3) proporciona una interfaz alternativa con control definido por el usuario sobre el procesamiento de nombres duplicados en el PMNS. El formato externo de un PMNS se ajusta a la sintaxis y semántica descritas en las siguientes secciones.

Existe un PMNS por defecto en los archivos debajo de $PCP_VAR_DIR/pmns, aunque los usuarios y desarrolladores de aplicaciones son libres de crear y usar PMNS alternativos. Para un ejemplo de esto, consulte el Tutorial de PCP en $PCP_DEMOS_DIR/Tutorial.

Aunque una aplicación puede llamar a pmLoadNameSpace(3), normalmente esto solo se hace directamente para la opción de línea de comandos -n donde se especifica un archivo PMNS raíz explícito. Dado que la versión 2 de PCP utiliza un PMNS distribuido (ver abajo), una aplicación puede extraer información del PMNS de un PMCD del host o de un archivo. Si la fuente del PMNS es un archivo de versión 1 (ver PCPIntro(1)), sin embargo, el PMNS local se cargará utilizando la ruta especificada por la variable de entorno PMNS_DEFAULT.

PMNS DISTRIBUIDO

En la versión 1 de PCP, las funciones del PMNS en la API operaban sobre un PMNS cargado localmente desde un archivo. Desde la versión 2 de PCP, sin embargo, las funciones del PMNS pueden obtener la información del PMNS remotamente desde un PMCD o directamente de los metadatos de un archivo.

MARCO DE PROCESAMIENTO

La especificación del PMNS se pasa inicialmente a través de pmcpp(1). Esto significa que se pueden usar las siguientes instalaciones en la especificación:

+
Comentarios estilo C
+
directivas #include
+
directivas #define y sustitución de macros
+
procesamiento condicional a través de #ifdef ... #endif, etc.

Cuando se ejecuta pmcpp(1), los directorios de inclusión "estándar" son el directorio actual y $PCP_VAR_DIR/pmns.

El preprocesamiento con pmcpp(1) puede omitirse en algunos casos en los que se sabe que el PMNS **no** contiene comentarios estilo C, directivas del preprocesador o macros. Consulte las descripciones de pmLoadASCIINameSpace(3) y pmLoadNameSpace(3) para obtener detalles.

SINTAXIS

La sintaxis general para un nodo no terminal en el PMNS es la siguiente:

pathname {
        name      [pmid]
        ...
}

Donde pathname es la ruta completa desde la raíz del PMNS hasta este nodo no terminal, con cada componente de la ruta separado por un punto ("."). El nodo raíz para el PMNS debe tener el nombre especial "root", pero el prefijo común "root." debe omitirse de todas las rutas. Cada componente de la ruta se extrae del conjunto de caracteres ASCII(7), comenzando con un carácter alfabético y seguido de cero o más caracteres extraídos de los alfabéticos, los dígitos y el carácter de guion bajo ("_"). Para los caracteres alfabéticos en un componente de ruta, se distinguen las mayúsculas y minúsculas.

Los nodos no terminales en el PMNS pueden definirse en cualquier orden.

Los nodos descendientes se definen por el conjunto de nombres, relativos al pathname de su nodo padre no terminal. Para los nodos descendientes, los nodos terminales tienen una especificación pmid, los nodos no terminales no. La sintaxis para la especificación pmid ha sido elegida para ayudar a gestionar la asignación de PMIDs en dominios de administración e implementación disjuntos y autónomos. Cada pmid consta de 3 partes enteras, separadas por dos puntos, por ejemplo, 14:27:11. Este esquema de numeración jerárquico está destinado a reflejar la jerarquía de implementación del dominio de métricas de rendimiento, el clúster de métricas (estructura de datos o similitud operativa) y la métrica individual. En la práctica, es probable que los dos componentes principales sean macros en el archivo fuente de la especificación del PMNS, y pmcpp(1) convertirá las macros a enteros. Estas macros para los componentes iniciales del pmid probablemente se definirán en un archivo de inclusión estándar, por ejemplo, $PCP_VAR_DIR/pmns/stdpmid, o en el archivo fuente actual.

Para soportar métricas dinámicas, cuya existencia se conoce a un PMDA, pero no es visible en el PMNS, se soporta una sintaxis variante para el pmid, es decir, un número de dominio seguido de asteriscos para los otros componentes del pmid, por ejemplo, 14:*:*. El nombre de métrica correspondiente forma la raíz de un subárbol de nombres de métricas dinámicas definidos en el PMDA correspondiente, tal como lo identifica el número de dominio.

La asignación actual del componente de orden superior (PMD o dominio) de los PMID es la siguiente.

Rango Asignación
0 reservado
1-384 PMDAs de producción de paquetes PCP
385-510 PMDAs de usuario final (asignar de mayor a menor)
511 reservado para entradas PMNS dinámicas

EJEMPLO

#define KERNEL 1
#define FOO 387
root {
    network
    cpu
    dynamic     FOO:*:*
}
#define NETWORK 26
network {
    intrate     KERNEL:NETWORK:1
    packetrate
}
network.packetrate {
    in          KERNEL:NETWORK:35
    out         KERNEL:NETWORK:36
}
#define CPU 10
cpu {
    syscallrate KERNEL:CPU:10
    util
}
#define USER 20
#define SYSTEM 21
#define IDLE 22
cpu.util {
    user        KERNEL:CPU:USER
    sys         KERNEL:CPU:SYSTEM
    idle        KERNEL:CPU:IDLE
}
