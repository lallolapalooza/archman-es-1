PPIx::Regexp(3) Documentación de Perl contribuida por el usuario PPIx::Regexp(3)

NOMBRE

PPIx::Regexp - Representa una expresión regular de algún tipo

SINOPSIS

use PPIx::Regexp;
use PPIx::Regexp::Dumper;
my $re = PPIx::Regexp->new( 'qr{foo}smx' );
PPIx::Regexp::Dumper->new( $re )
    ->print();

AVISO DE DESUSO

El argumento "postderef" para new() se retira, y las desreferencias postfijas siempre serán reconocidas.

A partir de la versión 0.074_01, el primer uso de este argumento generó una advertencia. Con la versión 0.079_01, todos los usos generaron una advertencia. Con la versión 0.080_01, todos los usos se volvieron fatales. Con la versión 0.084_01, toda mención de este argumento se eliminó, excepto este aviso.

HERENCIA

"PPIx::Regexp" es un PPIx::Regexp::Node.

"PPIx::Regexp" no tiene descendientes.

DESCRIPCIÓN

El propósito del paquete PPIx-Regexp es analizar expresiones regulares de una manera similar a la forma en que el paquete PPI analiza Perl. Esta clase forma la raíz del árbol de análisis, desempeñando un papel similar al de PPI::Document.

Este paquete comparte con PPI la propiedad de ser seguro para el viaje de ida y vuelta. Es decir,

my $expr = 's/ ( \d+ ) ( \D+ ) /$2$1/smxg';
my $re = PPIx::Regexp->new( $expr );
print $re->content() eq $expr ? "yes\n" : "no\n"

debería imprimir 'yes' para cualquier expresión regular válida.

La navegación es similar a la proporcionada por PPI. Es decir, cosas como "children", "find_first", "snext_sibling" y así sucesivamente funcionan prácticamente de la misma manera que en PPI.

La jerarquía de clases también es similar a PPI. Excepto por algunas clases de utilidad (el volquete, el analizador léxico y el tokenizador) todas las clases descienden de PPIx::Regexp::Element, que proporciona navegación básica. Los tokens descienden de PPIx::Regexp::Token, que proporciona contenido. Todos los contenedores descienden de PPIx::Regexp::Node, que proporciona hijos, y todos los elementos de estructura descienden de PPIx::Regexp::Structure, que proporciona delimitadores de inicio y fin, y un tipo.

Hay dos características de PPI que este paquete no proporciona: mutabilidad y sobrecarga de operadores. No hay planes serios de mutabilidad, aunque algo como la funcionalidad de "prune" de PPI podría ser considerada. Del mismo modo, no hay planes para la sobrecarga de operadores, que parece para el autor representar una penalización de rendimiento por una ganancia tangible escasa.

AVISO

El autor intentará preservar la interfaz documentada, pero si la interfaz necesita cambiar para corregir alguna decisión de diseño o implementación egregiamente errónea, entonces cambiará. Cualquier cambio incompatible pasará por un ciclo de desuso.

El objetivo de este paquete es analizar expresiones regulares bien formadas correctamente. Un objetivo secundario es no fallar con expresiones regulares mal formadas. La identificación y caracterización correctas de expresiones regulares mal formadas **no** son un objetivo de este paquete, ni tampoco el análisis consistente de expresiones regulares mal formadas de una versión a otra.

Esta política intenta seguir las características de las versiones de desarrollo, así como las versiones públicas. Sin embargo, las características añadidas en una versión de desarrollo y luego eliminadas antes de la siguiente versión de producción **no** serán seguidas, y cualquier funcionalidad relacionada con dichas características **será eliminada**. El problema aquí es la reutilización potencial (con semántica diferente) de sintaxis que no llegó a la versión de producción.

De vez en cuando, el motor de expresiones regulares de Perl cambia de maneras que alteran el análisis de una expresión regular dada. Cuando estos cambios ocurren, "PPIx::Regexp" se modificará para producir el análisis más moderno. Ejemplos conocidos de esto incluyen:

El '$(' ya no se interpola a partir de Perl 5.005, según "perl5005delta".
Los Perl más nuevos parecen analizar esto como "qr{$}" (es decir, una aserción de fin de cadena o de línea nueva), seguido de un paréntesis abierto, y eso es lo que hace "PPIx::Regexp".
El '$)' y el '$|' también parecen analizarse como la aserción '"$"'
seguida del metacaracter relevante, aunque no tengo referencia documental de esto.
Las "@+" y "@-" ya no se interpolan a partir de Perl 5.9.4
según "perl594delta". Los Perl posteriores tratan "@+" como un literal cuantificado y "@-" como dos literales, y eso es lo que hace "PPIx::Regexp". Tenga en cuenta que las referencias indexadas a estas matrices **sí** interpolan, y son analizadas de esa manera por "PPIx::Regexp".
Solo el espacio y el tabulador horizontal son espacios en blanco a partir de Perl 5.23.4
cuando están dentro de una clase de caracteres entre corchetes, dentro de una clase de caracteres entre corchetes extendida, según "perl5234delta". Anteriormente, cualquier caracter de espacio en blanco se analizaba como espacio en blanco. Este cambio en "PPIx::Regexp" se revertirá si el cambio en Perl no llega a Perl 5.24.0.
Los corchetes de apertura literales sin escapar
se están eliminando en posiciones donde los cuantificadores son legales, para que puedan usarse para nueva funcionalidad. Algunos de ellos han desaparecido en 5.25.1, otros se eliminarán en una versión futura de Perl. En situaciones donde se han eliminado, perl_version_removed() devolverá la versión en la que se eliminaron. Cuando aparezca la nueva funcionalidad, el análisis producido por este software reflejará la nueva funcionalidad.

NOTA que la situación con un corchete de apertura literal después de un carácter literal es complicada. Se convirtió en un error en Perl 5.25.1, y siguió siéndolo en todas las versiones 5.26, pero volvió a ser una advertencia en 5.27.1 debido a su uso en GNU Autoconf. Si alguna vez volverá a ser ilegal no está claro para mí basándome en el contenido de perl5271delta. En este momento perl_version_removed() devuelve "undef", pero obviamente esa no es toda la historia, e se introdujeron los métodos accepts_perl() y requirements_for_perl() para lidiar con esta complicación.

"\o{...}"
se analiza como el equivalente octal de "\x{...}". Este es su significado a partir de perl 5.13.2. Antes de 5.13.2 era simplemente un literal 'o' y así sucesivamente.
"x{,3}"
(con el primer conteo omitido) se permite como cuantificador a partir de Perl 5.33.6. El análisis anterior hacía que todo fueran literales.
"x{ 0 , 3 }"
(con espacios dentro pero adyacentes a los corchetes, o alrededor de la coma si la hay) se permite como cuantificador a partir de Perl 5.33.6. El análisis anterior hacía que todo fueran literales.

Es muy probable que haya otros ejemplos de esto. Cuando salgan a la luz, se documentará que producen el análisis moderno y el código se modificará para producir este análisis si es necesario.

MÉTODOS

Esta clase proporciona los siguientes métodos públicos. Los métodos no documentados aquí son privados y no soportados en el sentido de que el autor se reserva el derecho de cambiarlos o eliminarlos sin previo aviso.

new

my $re = PPIx::Regexp->new('/foo/');

Este método instancia un objeto "PPIx::Regexp" a partir de una cadena, un PPI::Token::QuoteLike::Regexp, un PPI::Token::Regexp::Match, o un PPI::Token::Regexp::Substitute. Honestamente, cualquier PPI::Element funcionará, pero solo las tres clases Regexp mencionadas anteriormente probablemente harán algo útil.

Cualquiera que sea la forma del argumento, se asume que consiste enteramente en una cadena de coincidencia, sustitución o "qr<>" válida.

Opcionalmente, puede pasar uno o más pares nombre/valor después de la expresión regular. Las opciones posibles son:

modificadores_predeterminados
Un hash de modificadores que se asumirá para la expresión regular si no se especifican explícitamente en la cadena de la expresión regular. Los modificadores son:
  • a para 'auto-splits'
  • d para 'dollar-escapes'
  • i para 'ignore-case'
  • m para 'multiline'
  • s para 'single-line'
  • x para 'extended'
  • S para 'unicode'
  • v para 'use-locale'
  • u para 'unicode-properties'

Por ejemplo, si desea analizar qr{foo} como una expresión regular insensible a mayúsculas y minúsculas, puede hacer:

my $re = PPIx::Regexp->new( 'qr{foo}', i => 1 );

O, si desea analizar la cadena de sustitución s/foo/bar/ como una expresión regular que utiliza el modo multilínea y extendido:

my $re = PPIx::Regexp->new( 's/foo/bar/', m => 1, x => 1 );

Si se pasa un argumento pragmas, se utilizará para analizar los modificadores, de forma similar a como funciona el operador qr// en Perl.

my $re = PPIx::Regexp->new( 'qr{foo}', pragmas => 'imxs' );

Este es el comportamiento predeterminado, y se puede omitir si solo se proporcionan los modificadores en la propia cadena de la expresión regular.

my $re = PPIx::Regexp->new( 'qr{foo}imxs' );

accepts_perl

my $bool = $re->accepts_perl( $version );

Devuelve verdadero si la expresión regular dada probablemente se analizará de la misma manera en la versión de Perl especificada que en la versión actual.

Las versiones de Perl se especifican como números de punto flotante, p. ej. 5.008005 o 5.014000. El valor predeterminado es $^V (la versión de Perl en ejecución).

content

my $string = $re->content();

Devuelve la representación de cadena de la expresión regular. Esto es lo que se pasaría a eval para reconstruir la expresión regular.

dump

my $string = $re->dump();

Devuelve una representación de cadena legible por humanos del objeto de expresión regular.

elements

my @elements = $re->elements();

Devuelve una lista de todos los elementos que componen la expresión regular.

find_first

my $element = $re->find_first( $type, $subclass );

Busca la primera aparición de un elemento del tipo especificado (por ejemplo, 'PPIx::Regexp::Token::Literal') y lo devuelve. El argumento $subclass es opcional y se utiliza para buscar un tipo más específico si es necesario.

find_every

my @elements = $re->find_every( $type, $subclass );

Similar a find_first, pero devuelve una lista de todos los elementos que coinciden con los criterios.

find_hashtable

my %elements = $re->find_hashtable( $type, $subclass );

Similar a find_every, pero devuelve una tabla hash donde las claves son los índices de los elementos en la expresión regular y los valores son los propios elementos.

modifiers

my $string = $re->modifiers();

Devuelve una cadena que contiene los modificadores de la expresión regular (por ejemplo, "imxs").

perl_version_removed

my $version = PPIx::Regexp::perl_version_removed( $feature );

Devuelve el número de versión de Perl (como un número de punto flotante) en el que se eliminó la característica dada. Si la característica todavía es válida, o si la información no está disponible, devuelve undef.

Las características actualmente rastreadas son:

literal_curly_opener
Un corchete de apertura literal que no está escapado y no forma parte de un cuantificador.

requirements_for_perl

my $string = PPIx::Regexp->requirements_for_perl( $version );

Devuelve una cadena que describe los requisitos de la versión de Perl para la expresión regular dada. Esto es útil para determinar si una expresión regular puede requerir una versión específica de Perl debido a cambios en la sintaxis o el análisis.

Por ejemplo, para la característica literal_curly_opener, devolverá:

The literal curly opener has been removed in positions where quantifiers
are legal. This started in Perl 5.25.1, but was reverted to a warning in
5.27.1 due to use in GNU Autoconf.

string_content

my $string = $re->string_content();

Devuelve la cadena que representa el contenido de la expresión regular, excluyendo el delimitador inicial y final.

subexpressions

my @subexpressions = $re->subexpressions();

Devuelve una lista de todas las subexpresiones dentro de la expresión regular (por ejemplo, grupos de captura, grupos sin captura).

new

my $re = PPIx::Regexp->new( $string_or_element );
my $re = PPIx::Regexp->new( $string_or_element, optional_argument => value, ... );

This method creates and returns a new "PPIx::Regexp" object. The first argument is either a string containing the regular expression, or a "PPI::Element" object which has a "source()" method that returns the string to be parsed.

The optional arguments are

default_modifiers array_reference
Esta opción especifica una referencia a una matriz de modificadores predeterminados para aplicar a la expresión regular que se está analizando. Cada modificador se especifica como una cadena. Cualquier modificador real encontrado anula los predeterminados.

Al aplicar los predeterminados, '?' y '/' se ignoran por completo, y '^' se ignora a menos que aparezca al principio del modificador. El primer guion ('-') hace que los modificadores posteriores se nieguen.

Así, por ejemplo, si desea producir un objeto "PPIx::Regexp" que represente la expresión regular en

use re '/smx';
{
   no re '/x';
   m/ foo /;
}

lo haría (después de algo de ayuda de PPI para encontrar las declaraciones relevantes), algo como

my $re = PPIx::Regexp->new( 'm/ foo /',
    default_modifiers => [ '/smx', '-/x' ] );
encoding nombre
Esta opción especifica la codificación de la expresión regular. Esto se pasa al tokenizador, que "decodificará" la cadena de la expresión regular antes de tokenizarla. Por ejemplo: 
my $re = PPIx::Regexp->new( '/foo/',
    encoding => 'iso-8859-1',
);
index_locations Booleano
Esta opción booleana especifica si las ubicaciones de los elementos en la expresión regular deben ser indexadas.

Si no se especifica o se especifica como "undef", se utiliza un valor predeterminado. Este valor predeterminado es verdadero si el argumento es un PPI::Element o si se especificó la opción "location". De lo contrario, el valor predeterminado es falso.

location array_reference
Esta opción especifica la ubicación del nuevo objeto en el documento del que se creó. Es una referencia a una matriz de cinco elementos compatible con la devuelta por el método location() de PPI::Element.

Si no se especifica, se utiliza la ubicación de la cadena original si se especificó como un PPI::Element.

Si no se puede determinar ninguna ubicación, los diversos métodos location() devolverán "undef".

postderef Booleano
ESTE ARGUMENTO ESTÁ OBSOLETO. Consulte el AVISO DE OBSOLESCENCIA anterior para obtener detalles.

Esta opción se pasa al tokenizador, donde especifica si se reconocen las desreferencias postfijas en interpolaciones y código. Esta función experimental se introdujo en Perl 5.19.5.

A partir de la versión 0.074_01, el valor predeterminado es verdadero. Hasta la versión 0.074, el valor predeterminado era el valor de $PPIx::Regexp::Tokenizer::DEFAULT_POSTDEREF, que era verdadero. Cuando se introdujo originalmente, era falso, pero se documentó como que se volvería verdadero cuando la desreferencia postfija se generalizara. La intención de generalizar se anunció con Perl 5.23.1 y se convirtió en oficial (por así decirlo) con Perl 5.24.0, por lo que el valor predeterminado se convirtió en verdadero con PPIx::Regexp 0.049_01.

Tenga en cuenta que si PPI comienza a reconocer incondicionalmente las desreferencias postfijas, este argumento se ignorará de inmediato y se someterá a un ciclo de obsolescencia y se eliminará.

strict Booleano
Esta opción se pasa al tokenizador y al analizador léxico, donde especifica si el análisis debe asumir que "use re 'strict'" está en vigor.

La pragmática 'strict' se introdujo en Perl 5.22, y su documentación dice que es experimental y que no hay compromiso con la compatibilidad con versiones anteriores. Lo mismo se aplica al análisis producido cuando se declara esta opción. Además, se aplica la advertencia habitual: si "use re 'strict'" termina siendo retractada, esta opción y toda la funcionalidad relacionada también lo serán.

Dada la naturaleza de "use re 'strict'", debe esperar que si declara esta opción, las expresiones regulares que anteriormente se analizaron sin errores ya no lo hagan. Si un elemento termina siendo declarado un error porque se establece esta opción, su perl_version_introduced() será la versión de Perl en la que "use re 'strict'" comenzó a rechazar estos elementos.

El valor predeterminado es falso.

trace número
Si es mayor que cero, esta opción causa una salida de rastreo del análisis. El autor se reserva el derecho de cambiar o eliminar esto sin previo aviso.

Pasar una entrada opcional distinta de la anterior no es un error, pero tampoco está admitido.

new_from_cache

Este método estático envuelve "new" en un mecanismo de caché. Solo se generará un objeto para un PPI::Element dado, sin importar cuántas veces se llame a este método. Las llamadas posteriores a la primera para un PPI::Element dado simplemente devuelven el mismo objeto "PPIx::Regexp".

Cuando el objeto "PPIx::Regexp" se devuelve de la caché, los valores de los argumentos opcionales se ignoran.

Las llamadas a este método con la expresión regular en una cadena en lugar de un PPI::Element no se almacenarán en caché.

Advertencia: Este método se proporciona para código como Perl::Critic que podría instanciar el mismo objeto varias veces. La caché persistirá hasta que se llame a "flush_cache".

flush_cache

$re->flush_cache();            # Eliminar $re de la caché
PPIx::Regexp->flush_cache();   # Vaciar la caché

Este método vacía la caché utilizada por "new_from_cache". Si se llama como método estático sin argumentos, se vacía toda la caché. De lo contrario, se eliminan de la caché los objetos especificados.

capture_names

foreach my $name ( $re->capture_names() ) {
    print "Capture name '$name'\n";
}

Este método de conveniencia devuelve los nombres de captura encontrados en la expresión regular.

Este método es equivalente a

$self->regular_expression()->capture_names();

excepto que si "$self->regular_expression()" devuelve "undef" (lo que significa que algo salió terriblemente mal con el análisis) este método simplemente devolverá.

delimiters

print join("\t", PPIx::Regexp->new('s/foo/bar/')->delimiters());
# imprime '//      //'

Cuando se llama en contexto de lista, este método devuelve una o dos cadenas, dependiendo de si la expresión analizada tiene una cadena de reemplazo. En el caso de sustituciones no entre corchetes, el delimitador de inicio de la cadena de reemplazo se considera el mismo que su delimitador de finalización, como lo ilustra el ejemplo anterior.

Cuando se llama en contexto escalar, se obtienen los delimitadores de la expresión regular; es decir, el elemento 0 de la matriz que se devuelve en contexto de lista.

Opcionalmente, puede pasar un valor de índice y se devolverán los delimitadores correspondientes; el índice 0 representa los delimitadores de la expresión regular y el índice 1 representa los delimitadores de la cadena de reemplazo, que pueden ser indefinidos. Por ejemplo,

print PPIx::Regexp->new('s{foo}<bar>')->delimiters(1);
# imprime '<>'

Si el objeto no se inicializó con una regexp válida de algún tipo, los resultados de este método no están definidos.

errstr

Este método estático devuelve la cadena de error del intento más reciente de instanciar un "PPIx::Regexp". Será "undef" si el intento más reciente tuvo éxito.

extract_regexps

my $doc = PPI::Document->new( $path );
$doc->index_locations();
my @res = PPIx::Regexp->extract_regexps( $doc )

Este método de conveniencia (bueno, más o menos) toma como argumento un objeto PPI::Document y devuelve objetos "PPIx::Regexp" correspondientes a todas las expresiones regulares encontradas en él, en el orden en que ocurren en el documento. Deberá mantener una referencia al objeto PPI::Document original si desea poder recuperar los objetos PPI::Element originales a través del método source() de PPIx::Regexp.

failures

print "There were ", $re->failures(), " parse failures\n";

Este método devuelve el número de fallos de análisis. Este es un recuento del número de tokens desconocidos más el número de estructuras no terminadas más el número de corchetes derechos no coincidentes de cualquier tipo.

max_capture_number

print "Highest used capture number ",
    $re->max_capture_number(), "\n";

Este método de conveniencia devuelve el número de captura más alto utilizado por la expresión regular. Si no hay capturas, el retorno será 0.

Este método es equivalente a

$self->regular_expression()->max_capture_number();

excepto que si "$self->regular_expression()" devuelve "undef" (lo que significa que algo salió terriblemente mal con el análisis) este método también lo hará.
