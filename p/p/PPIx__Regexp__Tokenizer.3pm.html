PPIx::Regexp::Tokenizer(3) Documentación de Perl Contribuida por el Usuario PPIx::Regexp::Tokenizer(3)

NOMBRE

PPIx::Regexp::Tokenizer - Tokeniza una expresión regular

SINOPSIS

use PPIx::Regexp::Dumper;
PPIx::Regexp::Dumper->new( 'qr{foo}smx' )
    ->print();

HERENCIA

"PPIx::Regexp::Tokenizer" es un PPIx::Regexp::Support.

"PPIx::Regexp::Tokenizer" no tiene descendientes.

DESCRIPCIÓN

Esta clase proporciona la tokenización de la expresión regular.

MÉTODOS

Esta clase proporciona los siguientes métodos públicos. Los métodos no documentados aquí (o documentados a continuación bajo "TOKENIZADORES EXTERNOS") son privados y no soportados en el sentido de que el autor se reserva el derecho de cambiarlos o eliminarlos sin previo aviso.

new

my $tokenizer = PPIx::Regexp::Tokenizer->new( 'xyzzy' );

Este método estático instancia el tokenizador. Debes pasarle la expresión regular a analizar, ya sea como una cadena o como un PPI::Element de algún tipo. También puedes pasar pares de nombre/valor de argumentos opcionales. Los nombres de las opciones se especifican sin guion inicial. Las opciones soportadas son:

default_modifiers referencia_a_array
Este argumento especifica los modificadores de sentencia por defecto. Es opcional, pero si se especifica debe ser una referencia a un array. Ver la documentación de PPIx::Regexp new() para los detalles.
encoding nombre
Esta opción especifica la codificación de la cadena a tokenizar. Si se especifica, se realiza una "Encode::decode" en la cadena (o en el "content" de la clase PPI) antes de que sea tokenizada.
index_locations
Esta opción booleana especifica que se deben calcular las ubicaciones de los tokens generados.
strict booleano
Esta opción especifica si la tokenización debe asumir que "use re 'strict';" está en efecto.

El pragma 'strict' se introdujo en Perl 5.22, y su documentación dice que es experimental y que no hay compromiso de compatibilidad hacia atrás. Lo mismo aplica a la tokenización producida cuando se afirma esta opción.

trace número
Especificar un valor positivo para esta opción causa un rastreo de la tokenización. Esta opción no está soportada en el sentido de que el autor se reserva el derecho de alterarla sin previo aviso.

Si esta opción no se especifica, el valor proviene de la variable de entorno "PPIX_REGEXP_TOKENIZER_TRACE" (ver "VARIABLES DE ENTORNO"). Si esta variable de entorno no existe, el valor por defecto es 0.

Las opciones no documentadas no están soportadas.

El valor devuelto es el tokenizador instanciado, o "undef" si la instanciación falló. En este último caso, una llamada a "errstr" devolverá la razón.

content

print $tokenizer->content();

Este método devuelve la cadena que se está tokenizando. Este será el resultado del método PPI::Element->content() si el objeto fue instanciado con un PPI::Element.

default_modifiers

print join ', ', @{ $tokenizer->default_modifiers() };

Este método devuelve una referencia a una copia del array pasado al argumento "default_modifiers" de new(). Si este argumento no se utilizó para instanciar el objeto, la devolución es una referencia a un array vacío.

encoding

Este método devuelve la codificación de los datos que se están analizando, si se estableció una al instanciar la clase; de lo contrario, simplemente devuelve undef.

errstr

my $tokenizer = PPIx::Regexp::Tokenizer->new( 'xyzzy' )
    or die PPIx::Regexp::Tokenizer->errstr();

Este método estático devuelve una descripción del error si la instanciación del tokenizador falló.

failures

print $tokenizer->failures(), " fallos de tokenización\n";

Este método devuelve el número de fallos de tokenización encontrados. Un fallo de tokenización se representa en el flujo de tokens de salida mediante un PPIx::Regexp::Token::Unknown.

modifier

$tokenizer->modifier( 'x' )
    and print "Tokenizando una expresión regular extendida\n";

Este método devuelve verdadero si el carácter modificador dado se encontró al final de la expresión regular, y falso en caso contrario.

A partir de la versión 0.036_01, si el argumento es un modificador de un solo carácter seguido de un asterisco (pretendido como carácter comodín), la devolución es el número de veces que aparece ese modificador. En este caso se lanzará una excepción si especificas un modificador de varios caracteres (por ejemplo, 'ee*'), o si especificas uno de los modificadores de semántica de coincidencia (por ejemplo, 'a*').

Si es llamado por un tokenizador externo, este método devuelve verdadero si el modificador dado era verdadero en el punto actual de la tokenización.

next_token

my $token = $tokenizer->next_token();

Este método devuelve el siguiente token en el flujo de tokens, o nada si no hay más tokens.

significant

Este método existe simplemente para la conveniencia de PPIx::Regexp::Dumper. Siempre devuelve verdadero.

tokens

my @tokens = $tokenizer->tokens();

Este método devuelve todos los tokens restantes en el flujo de tokens.

TOKENIZADORES EXTERNOS

Esta clase hace muy poco de su propia tokenización. En cambio, las clases de tokens contienen rutinas de tokenización externas, cuyo nombre es '__PPIX_TOKENIZER__' concatenado con el modo actual del tokenizador ('regexp' para expresiones regulares, 'repl' para la cadena de reemplazo).

Estos tokenizadores externos se llaman como métodos estáticos y se les pasa el objeto "PPIx::Regexp::Tokenizer" y el carácter actual en el flujo de caracteres.

Si el tokenizador externo quiere crear uno o más tokens, devuelve un array que contiene la longitud en caracteres para tokens de la propia clase del tokenizador, o los resultados de una o más llamadas a "make_token" para tokens de una clase arbitraria.

Si el tokenizador externo no está interesado en los caracteres que comienzan en la posición actual, simplemente devuelve.

Los siguientes métodos son para el uso de tokenizadores externos y no son parte de la interfaz pública de esta clase.

capture

if ( $tokenizer->find_regexp( qr{ \A ( foo ) }smx ) ) {
    foreach ( $tokenizer->capture() ) {
        print "$_\n";
    }
}

Este método devuelve todo el contenido de cualquier buffer de captura de la llamada anterior a "find_regexp". El primer elemento del array (es decir, el elemento 0) corresponde a $1, y así sucesivamente.

Las capturas se borran con "make_token", así como con otra llamada a "find_regexp".

cookie

$tokenizer->cookie( foo => sub { 1 } );
my $cookie = $tokenizer->cookie( 'foo' );
my $old_hint = $tokenizer->cookie( foo => undef );

Este método crea, elimina o accede a una cookie.

Una cookie es una referencia de código

- title: "cookie" content: | ``` $tokenizer->cookie( 'foo' ) $tokenizer->cookie( 'foo', \&callback ) $tokenizer->cookie( 'foo', undef ) ``` Este método se usa para registrar o llamar a una subrutina (cookie). Si la subrutina se llama a sí misma, se la eliminará. Si se llama a sí misma con `undef` se la eliminará. Si la subrutina se llama a sí misma, se la eliminará. Si se llama a sí misma con `undef` se la eliminará. Establecer explícitamente la cookie en `"undef"` también la elimina. Cuando llamas a `"$tokenizer->cookie( 'foo' )"`, se devuelve la cookie actual. Si pasas un nuevo valor de `"undef"` para eliminar el token, se devuelve la cookie eliminada (si la hay). Cuando el método "make_token" llama a una cookie, le pasa el tokenizador y el token recién creado. Si un token llama a una cookie, se recomienda que simplemente pase el tokenizador, aunque por supuesto el token puede hacer lo que quiera. El mecanismo de cookies parece ser un poco un fraude, pero parecía que requería más trabajo arreglar las cosas en el lexer después de que el tokenizador hiciera algo mal. La forma recomendada de escribir una cookie es usar un closure para almacenar cualquier dato necesario, y hacer que una llamada a la cookie devuelva los datos; de lo contrario, el consumidor final de la cookie no tiene forma de acceder a los datos. Por supuesto, puede ser que la presencia de la cookie en un cierto punto del análisis sea todo lo que se requiere. - title: "expect" content: | ``` $tokenizer->expect( 'PPIx::Regexp::Token::Code' ); ``` Este método inserta una clase dada en la cabeza del escaneo de tokens, solo para la siguiente iteración. Se pueden especificar varias clases. Los nombres de clase se pueden abreviar eliminando el prefijo 'PPIx::Regexp::'. Si no se especifica ninguna clase, este método no hace nada. La expectativa dura desde la próxima vez que se llame a "get_token" hasta la próxima vez que "make_token" cree un token significativo, o hasta la próxima llamada a `"expect"` si esta se realiza antes. - title: "find_regexp" content: | ``` my $end = $tokenizer->find_regexp( qr{ \A \w+ }smx ); my ( $begin, $end ) = $tokenizer->find_regexp( qr{ \A \w+ }smx ); ``` Este método encuentra la expresión regular dada en el contenido, comenzando en la posición actual. Si se llama en contexto escalar, se devuelve el desplazamiento desde la posición actual hasta el final de la cadena coincidente. Si se llama en contexto de lista, se devuelven los desplazamientos tanto al principio como al final de la cadena coincidente. - title: "find_matching_delimiter" content: | ``` my $offset = $tokenizer->find_matching_delimiter(); ``` Este método es utilizado por los tokenizadores para encontrar el delimitador que coincide con el carácter en la posición actual de la cadena de contenido. Si el delimitador es un corchete de apertura de algún tipo, se tendrá en cuenta el anidamiento de corchetes. Al buscar el delimitador coincidente, el carácter de barra invertida se considera que escapa el carácter siguiente, por lo que los delimitadores escapados con barra invertida serán ignorados. Sin embargo, no se reconocen otros mecanismos de comillas, por lo que los delimitadores dentro de comillas todavía cuentan. Esto es en realidad la forma en que funciona Perl, como lo demuestra: ```perl $ perl -e 'qr<(?{ print "}" })>' ``` Este método devuelve el desplazamiento desde la posición actual en la cadena de contenido hasta el delimitador coincidente (que siempre será positivo), o `undef` si no se puede encontrar ninguna coincidencia. - title: "get_mode" content: | Este método devuelve el nombre del modo actual del tokenizador. - title: "get_start_delimiter" content: | ``` my $start_delimiter = $tokenizer->get_start_delimiter(); ``` Este método es utilizado por los tokenizadores para acceder al delimitador de inicio para la expresión regular. - title: "get_token" content: | ``` my $token = $tokenizer->make_token( 3 ); my @tokens = $tokenizer->get_token(); ``` Este método devuelve el siguiente token que se puede crear a partir del flujo de entrada. **No** forma parte de la interfaz externa, sino que está destinado al uso de un tokenizador externo que lo llama después de crear y retener su propio token para examinar el siguiente token (si lo hay) en el flujo de entrada. Si algún tokenizador externo llama a get_token sin haber llamado primero a make_token, se produce un error fatal; esto es mejor que la recursión infinita que ocurriría si la condición no fuera atrapada. Un tokenizador externo **debe** devolver cualquier cosa devuelta por get_token; de lo contrario, los tokens se pierden. - title: "interpolates" content: | Este método devuelve verdadero si la estructura de nivel superior que se está tokenizando se interpola; es decir, si el delimitador no es una comilla simple. - title: "make_token" content: | ``` return $tokenizer->make_token( 3, 'PPIx::Regexp::Token::Unknown' ); ``` Este método es utilizado por esta clase (y posiblemente por tokenizadores individuales) para fabricar un token. Sus argumentos son el número de caracteres a incluir en el token y, opcionalmente, la clase del token. Si no se proporciona ningún nombre de clase, se utiliza la clase del llamador. Los nombres de clase se pueden acortar eliminando el prefijo 'PPIx::Regexp::', que será restaurado por este método. El token se fabricará a partir del número dado de caracteres comenzando en la posición actual del cursor, que se ajustará. Si la longitud dada incluyera caracteres más allá del final de la cadena que se está tokenizando, la longitud se reducirá apropiadamente. Si esto resulta en un token sin caracteres, no se devuelve nada. - title: "match" content: | ``` if ( $tokenizer->find_regexp( qr{ \A \w+ }smx ) ) { print $tokenizer->match(), "\n"; } ``` Este método devuelve la cadena que coincidió con la llamada anterior a "find_regexp". El resultado de la coincidencia se establece en `"undef"` por "make_token", así como por otra llamada a "find_regexp". - title: "modifier_duplicate" content: | ``` $tokenizer->modifier_duplicate(); ``` Este método duplica los modificadores en la parte superior de la pila de modificadores, con la intención de crear una copia de los modificadores con ámbito local. Esto solo debe ser llamado por un tokenizador externo que esté realmente creando un ámbito de modificador. En otras palabras, solo al crear un token PPIx::Regexp::Token::Structure cuyo contenido es '('. - title: "modifier_modify" content: | ``` $tokenizer->modifier_modify( name => $value ... ); ``` Este método establece nuevos valores para los modificadores en el ámbito local. Solo los modificadores cuyos nombres se pasan realmente tienen sus valores cambiados. Este método está destinado a ser llamado después de fabricar un token PPIx::Regexp::Token::Modifier, y se le pasan los resultados de su método `"modifiers"`. - title: "modifier_pop" content: | ``` $tokenizer->modifier_pop(); ``` Este método elimina los modificadores en la parte superior de la pila de modificadores. Esto solo debe ser llamado por un tokenizador externo que esté terminando un ámbito de modificador. En otras palabras, solo al crear un token PPIx::Regexp::Token::Structure cuyo contenido es ')'. Tenga en cuenta que este método nunca extraerá el último elemento de la pila de modificadores, para protegerse contra paréntesis derechos no coincidentes. - title: "modifier_seen" content: | ``` $tokenizer->modifier_seen( 'i' ) and print "Se vio /i en algún momento.\n"; ``` A diferencia de **modifier()**, este método devuelve un valor verdadero si el modificador dado se ha visto en cualquier ámbito visible desde la ubicación actual en el análisis. No hay magia para la semántica de coincidencia de grupo (/a, /aa, /d, /l, /u) o modificadores que se pueden repetir, como /x y /xx, o /e y /ee. - title: "peek" content: | ``` my $character = $tokenizer->peek(); my $next_char = $tokenizer->peek( 1 ); ``` Este método devuelve el carácter en el desplazamiento no negativo dado desde la posición actual. Si no se proporciona ningún desplazamiento, se utiliza un desplazamiento de 0. Si solicita un desplazamiento negativo o un desplazamiento fuera del final de la cadena, se devuelve `"undef"`. - title: "ppi_document" content: | Este método crea un documento PPI a partir del resto de la cadena y lo devuelve. - title: "prior_significant_token" content: | ``` $tokenizer->prior_significant_token( 'can_be_quantified' ) and print "El token anterior puede ser cuantificado.\n"; ``` Este método llama al método nombrado en el token significativo instanciado más recientemente, y devuelve el resultado. Cualquier argumento posterior al nombre del método se pasará al método. Dado que este método está diseñado para ser utilizado dentro del sistema de tokenización, morirá horriblemente si el método nombrado no existe. Si se llama sin ningún argumento, se devuelve el token significativo instanciado más recientemente. - title: "strict" content: | ``` say 'El análisis es ', $tokenizer->strict() ? 'estricto' : 'permisivo'; ``` Este método simplemente devuelve verdadero o falso, dependiendo de si la opción `'strict'` de `new()` era verdadera o falsa. - title: "ENVIRONMENT VARIABLES" content: | Se puede solicitar un rastreo del tokenizador estableciendo la variable de entorno PPIX_REGEXP_TOKENIZER_TRACE a un valor numérico distinto de 0. El uso de esta variable de entorno no está soportado en el mismo sentido que la opción `"trace"` de `"new"` no está soportada. Especificar explícitamente la opción `"trace"` a `"new"` anula la variable de entorno. La verdadera razón por la que esto está documentado es para dar al usuario una forma de depurar resultados extraños del tokenizador. - title: "SUPPORT" content: | El soporte es proporcionado por el autor.
