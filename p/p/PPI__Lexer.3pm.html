PPI::Lexer(3) Documentación de Perl aportada por el usuario PPI::Lexer(3)

NOMBRE

PPI::Lexer - El analizador léxico de PPI

SINOPSIS

use PPI;

# Crear un nuevo analizador léxico
my $Lexer = PPI::Lexer->new;

# Construir un objeto PPI::Document a partir de un flujo de tokens
my $Tokenizer = PPI::Tokenizer->load('My/Module.pm');
my $Document = $Lexer->lex_tokenizer($Tokenizer);

# Construir un objeto PPI::Document para código fuente en bruto
my $source = "print 'Hello World!'; kill(Humans->all);";
$Document = $Lexer->lex_source($source);

# Construir un objeto PPI::Document para un nombre de archivo específico
$Document = $Lexer->lex_file('My/Module.pm');

DESCRIPCIÓN

Este es el analizador léxico de PPI. En el esquema general de las cosas, su trabajo es tomar flujos de tokens, en una variedad de formas, y "analizarlos léxicamente" en estructuras anidadas.

Casi todo en este módulo sucede detrás de escena en este momento. De hecho, por ahora no necesitas instanciar el analizador léxico en absoluto, los tres métodos principales se auto-instanciarán un objeto "PPI::Lexer" según sea necesario.

Todos los métodos realizan una acción única de "analizar esto y darme un objeto PPI::Document".

De hecho, si estás leyendo esto, lo que **probablemente** quieres hacer es simplemente "cargar un documento", en cuyo caso puedes hacerlo de una manera mucho más directa y concisa con uno de los siguientes:

use PPI;

$Document = PPI::Document->load( $filename );
$Document = PPI::Document->new( $string );

Consulta PPI::Document para más detalles.

Para tareas más inusuales, siéntete libre de continuar.

MÉTODOS

new

El constructor "new" crea un nuevo objeto "PPI::Lexer". El objeto en sí solo se utiliza para mantener varios búferes y datos de estado durante el proceso de análisis léxico, y no contiene datos significativos entre las llamadas a ->lex_xxxxx.

Devuelve un nuevo objeto "PPI::Lexer"

lex_file $filename

El método "lex_file" toma un nombre de archivo como argumento. Luego carga el archivo, crea un PPI::Tokenizer para el contenido y analiza el flujo de tokens producido por el tokenizador. Básicamente, es un método todo en uno para obtener un objeto PPI::Document a partir de un nombre de archivo.

Los argumentos adicionales se pasan al tokenizador como un hash.

Devuelve un objeto PPI::Document, o "undef" en caso de error.

lex_source $string

El método "lex_source" toma una cadena escalar normal como argumento. Crea un objeto PPI::Tokenizer para la cadena y luego analiza el flujo de tokens resultante.

Los argumentos adicionales se pasan al tokenizador como un hash.

Devuelve un objeto PPI::Document, o "undef" en caso de error.

lex_tokenizer $Tokenizer

El método "lex_tokenizer" toma como argumento un objeto PPI::Tokenizer. Analiza léxicamente el flujo de tokens del tokenizador en un objeto PPI::Document.

Los argumentos adicionales se establecen en el PPI::Document producido.

Devuelve un objeto PPI::Document, o "undef" en caso de error.

errstr

Para cualquier error que ocurra, puedes usar "errstr", ya sea como un método estático o de objeto, para acceder al mensaje de error.

Si no ocurre ningún error en ninguna acción particular, "errstr" devolverá falso.
