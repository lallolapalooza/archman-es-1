PPI::Element(3) Documentación Perl contribuida por el usuario PPI::Element(3)

NOMBRE

PPI::Element - La clase abstracta Element, una base para todos los objetos de origen

HERENCIA

PPI::Element es la raíz del árbol PDOM

DESCRIPCIÓN

El "PPI::Element" abstracto sirve como clase base para todos los objetos relacionados con el código fuente, desde un único token de espacio en blanco hasta un documento completo. Proporciona un conjunto básico de métodos para ofrecer una interfaz común e implementaciones básicas.

MÉTODOS

significativo

Debido a que tratamos los espacios en blanco y otros elementos no de código como Tokens (para poder "volver a empaquetar" el PPI::Document de vuelta a un archivo), el método "significativo" nos permite distinguir entre los tokens que forman parte del código y los tokens que no son significativos, como los espacios en blanco, POD o la porción de un archivo después (e incluyendo) el token "__END__".

Devuelve verdadero si el Elemento es significativo, o falso si no lo es.

clase

El método "clase" se proporciona como una conveniencia, y en realidad no hace más que devolver ref($self). Sin embargo, algunas personas han descubierto que aprecian la pereza de "$Foo->clase eq 'whatever'", así que he cedido a la demanda popular y lo he incluido.

Devuelve la clase del Elemento como una cadena.

tokens

El método "tokens" devuelve una lista de objetos PPI::Token para el Elemento, esencialmente obteniendo esa parte del documento como si no hubiera sido analizada (lexed).

Esto también significa que no hay Statements ni Structures en la lista, solo las clases Token.

contenido

Para cualquier "PPI::Element", el método "contenido" reconstituirá el código base como una única cadena. Este método es también el método utilizado para la sobrecarga de la stringificación. Cuando un Elemento se utiliza en una cadena entrecomillada doble, por ejemplo, este es el método que se llama.

ADVERTENCIA:

Debe tener en cuenta que, debido a la forma en que se manejan los here-docs, el contenido de cualquier here-doc no se incluye en "contenido", y como tal, no debe evaluar o ejecutar el resultado si contiene algún PPI::Token::HereDoc.

El método PPI::Document "serialize" debe utilizarse para convertir un documento PDOM en algo que pueda ejecutarse como se espera.

Devuelve el código base como una cadena (excluyendo el contenido de here-doc).

padre

Los Elementos en sí mismos no están pensados para contener otros Elementos, eso se deja a la clase abstracta PPI::Node, una subclase de "PPI::Element". Sin embargo, todos los Elementos pueden ser contenidos dentro de un Nodo padre.

Si un Elemento está dentro de un Nodo padre, el método "padre" devuelve el Nodo.

descendiente_de $elemento

Responde si un "PPI::Element" está contenido dentro de otro.

Los "PPI::Element"s se consideran descendientes de sí mismos.

ancestro_de $elemento

Responde si un "PPI::Element" contiene a otro.

Los "PPI::Element"s se consideran ancestros de sí mismos.

declaracion

Para un "PPI::Element" que está contenido (a alguna profundidad) dentro de una PPI::Statement, el método "declaracion" devolverá el primer objeto Statement padre léxicamente 'por encima' del Elemento.

Devuelve un objeto PPI::Statement, que puede ser el mismo Elemento si el Elemento es en sí mismo un objeto PPI::Statement.

Devuelve falso si el Elemento no está dentro de una Statement y no es una Statement en sí mismo.

arriba

Para un "PPI::Element" que está contenido dentro de un árbol PDOM, el método "arriba" devolverá el Nodo de nivel superior en el árbol. La mayoría de las veces será un objeto PPI::Document, sin embargo, esto no siempre será así. Por ejemplo, si una subrutina ha sido eliminada de su Documento para ser movida a otro Documento.

Devuelve el objeto PDOM más alto, que puede ser el mismo Elemento, si no está dentro de ningún objeto PDOM padre.

documento

Para un Elemento que está contenido dentro de un objeto PPI::Document, el método "documento" devolverá el Documento de nivel superior para el Elemento.

Devuelve el PPI::Document para este Elemento, o falso si el Elemento no está contenido dentro de un Documento.

siguiente_hermano

Todos los objetos PPI::Node (específicamente, nuestro Nodo padre) contienen un número de objetos "PPI::Element". El método "siguiente_hermano" devuelve el "PPI::Element" inmediatamente después del actual, o falso si no hay siguiente hermano.

siguiente_hermano_significativo

Al igual que los otros métodos 's', el método "siguiente_hermano_significativo" devuelve el siguiente hermano significativo del objeto "PPI::Element".

Devuelve un objeto "PPI::Element", o falso si no hay un hermano significativo 'siguiente'.

hermano_anterior

Todos los objetos PPI::Node (específicamente, nuestro Nodo padre) contienen un número de objetos "PPI::Element". El método "hermano_anterior" devuelve el Elemento inmediatamente anterior al actual, o falso si no hay un objeto "PPI::Element" 'anterior'.

hermano_anterior_significativo

Al igual que los otros métodos 's', el método "hermano_anterior_significativo" devuelve el hermano significativo anterior del objeto "PPI::Element".

Devuelve un objeto "PPI::Element", o falso si no hay un hermano significativo 'anterior'.

primer_token

Como método de soporte para algoritmos de orden superior que tratan específicamente con tokens y contenido real de Perl, el método "primer_token" encuentra el primer objeto PPI::Token dentro o igual a este.

Es decir, si se llama en una subclase de PPI::Node, descenderá hasta encontrar un PPI::Token. Si se llama en un objeto PPI::Token, devolverá el mismo objeto.

Devuelve un objeto PPI::Token, o muere en caso de error (lo que debería ser extremadamente raro y solo ocurrir si existe una PPI::Statement vacía ilegal en algún lugar debajo del Elemento actual).

ultimo_token

Como método de soporte para algoritmos de orden superior que tratan específicamente con tokens y contenido real de Perl, el método "ultimo_token" encuentra el último objeto PPI::Token dentro o igual a este.

Es decir, si se llama en una subclase de PPI::Node, descenderá hasta encontrar un PPI::Token. Si se llama en un PPI::Token, devolverá el mismo objeto.

Devuelve un objeto PPI::Token, o muere en caso de error (lo que debería ser extremadamente raro y solo ocurrir si existe una PPI::Statement vacía ilegal en algún lugar debajo del Elemento actual).

l a este.

Es decir, si se llama en una subclase de PPI::Node, descenderá hasta que encuentre un PPI::Token. Si se llama en un objeto PPI::Token, devolverá el mismo objeto.

Devuelve un objeto PPI::Token, o falla si ocurre un error (lo cual debería ser extremadamente raro y solo ocurrir si existe una sentencia PPI::Statement vacía e ilegal debajo del Elemento actual en algún lugar).

next_token

Como método de soporte para algoritmos de orden superior que tratan específicamente con tokens y contenido Perl real, el método "next_token" encuentra el objeto PPI::Token que está inmediatamente después del Elemento actual, incluso si no está dentro del mismo PPI::Node padre que aquel para el cual se está llamando al método.

Tenga en cuenta que esto no está definido como un método específico de PPI::Token, ya que puede ser útil para encontrar el siguiente token que está después de, por ejemplo, un PPI::Statement, aunque obviamente sería inútil querer el siguiente token después de un PPI::Document.

Devuelve un objeto PPI::Token, o false si no hay más tokens después del Elemento.

previous_token

Como método de soporte para algoritmos de orden superior que tratan específicamente con tokens y contenido Perl real, el método "previous_token" encuentra el objeto PPI::Token que está inmediatamente antes del Elemento actual, incluso si no está dentro del mismo PPI::Node padre que este.

Tenga en cuenta que esto no está definido como un método exclusivo de PPI::Token, ya que puede ser útil para encontrar el token que está antes de, por ejemplo, un PPI::Statement, aunque obviamente sería inútil querer el siguiente token antes de un PPI::Document.

Devuelve un objeto PPI::Token, o false si no hay más tokens antes del "Elemento".

presumed_features

Devuelve un hash que indica qué características parecen estar activas para el elemento dado.

clone

Según el módulo Clone, el método "clone" crea una copia perfecta de un objeto Elemento. En el caso genérico, la implementación se realiza utilizando el mecanismo del módulo Clone. En casos de orden superior, como para Nodos, hay más trabajo involucrado para mantener los enlaces padre-hijo intactos.

insert_before @Elements

El método "insert_before" le permite insertar contenido léxico Perl, en forma de objetos "PPI::Element", antes del "Elemento" que llama al método. Debe tener mucho cuidado al modificar código Perl, ya que es fácil romper cosas.

En su implementación inicial, este método permite insertar un solo Elemento y realizará algunas verificaciones básicas para evitar que inserte algo que sea estructuralmente incorrecto (en términos de PDOM).

En el futuro, este método puede ser mejorado para permitir la inserción de múltiples Elementos, cadenas de código analizadas en línea o objetos PPI::Document::Fragment.

Devuelve true si el Elemento se insertó correctamente, false si no se puede insertar, o "undef" si no proporciona un objeto "PPI::Element" como parámetro.

insert_after @Elements

El método "insert_after" le permite insertar contenido léxico Perl, en forma de objetos "PPI::Element", después del "Elemento" que llama al método. Debe tener mucho cuidado al modificar código Perl, ya que es fácil romper cosas.

En su implementación inicial, este método permite insertar un solo Elemento y realizará algunas verificaciones básicas para evitar que inserte algo que sea estructuralmente incorrecto (en términos de PDOM).

En el futuro, este método puede ser mejorado para permitir la inserción de múltiples Elementos, cadenas de código analizadas en línea o objetos PPI::Document::Fragment.

Devuelve true si el Elemento se insertó correctamente, false si no se puede insertar, o "undef" si no proporciona un objeto "PPI::Element" como parámetro.

remove

Para un "PPI::Element" dado, el método "remove" lo eliminará de su padre intacto, junto con todos sus hijos.

Devuelve el "Elemento" mismo como conveniencia, o "undef" si ocurre un error al intentar eliminar el "Elemento".

delete

Para un "PPI::Element" dado, el método "delete" lo eliminará de su padre, borrando inmediatamente el "Elemento" y todos sus hijos (si los tiene).

Devuelve true si el "Elemento" se eliminó correctamente, o "undef" si ocurre un error al intentar eliminar el "Elemento".

replace $Element

Aunque algunas clases de nivel superior admiten formas más exóticas de reemplazo, en el nivel básico el método "replace" toma un solo "Elemento" como argumento y reemplaza el "Elemento" actual con él.

Para evitar daños accidentales al código, en esta implementación inicial, el elemento de reemplazo **debe** ser de la misma clase (o una subclase) que el que se está reemplazando.

Si tiene éxito, devuelve el elemento de reemplazo. De lo contrario, devuelve "undef".

location

Si el Elemento existe dentro de un PPI::Document que ha indexado las ubicaciones de los elementos usando "PPI::Document::index_locations", el método "location" devolverá la ubicación del primer carácter del Elemento dentro del Documento.

Devuelve la ubicación como una referencia a un array de cinco elementos en el formato "[ $línea, $caracter_fila, $columna, $linea_logica, $nombre_archivo_logico ]". Los valores están en un formato legible por humanos, con el primer carácter del archivo ubicado en "[ 1, 1, 1, ?, 'algo' ]".

Los segundos y terceros números son similares, excepto que el segundo es el carácter horizontal literal, y el tercero es la columna visual, teniendo en cuenta las tabulaciones (ver "tab_width [ $ancho ]" en PPI::Document).

El cuarto número es el número de línea, teniendo en cuenta las directivas "#line". El quinto elemento es el nombre del archivo en el que se encontró el elemento, si está disponible, teniendo en cuenta las directivas "#line".

Devuelve "undef" en caso de error, o si el objeto PPI::Document no ha sido indexado.

line_number

Si el Elemento existe dentro de un PPI::Document que ha indexado las ubicaciones de los elementos usando "PPI::Document::index_locations", el método "line_number" devolverá el número de línea del primer carácter del Elemento dentro del Documento.

Devuelve "undef" en caso de error, o si el objeto PPI::Document no ha sido indexado.

column_number

Si el Elemento existe dentro de un PPI::Document que ha indexado las ubicaciones de los elementos usando "PPI::Document::index_locations", el método "column_number" devolverá el número de columna del primer carácter del Elemento dentro del Documento.

Devuelve "undef" en caso de error, o si el objeto PPI::Document no ha sido indexado.

visual_column_number

Si el Elemento existe dentro de un PPI::Document que ha indexado las ubicaciones de los elementos usando "PPI::Document::index_locations", el método "visual_column_number" devolverá el número de columna visual del primer carácter del Elemento dentro del Documento, de acuerdo con el valor de "tab_width [ $ancho ]" en PPI::Document.

Devuelve "undef" en caso de error, o si el objeto PPI::Document no ha sido indexado.

logical_line_number

Si el Elemento existe dentro de un PPI::Document que ha indexado las ubicaciones de los elementos usando "PPI::Document::index_locations", el método "logical_line_number" devolverá el número de línea del primer carácter del Elemento dentro del Documento, teniendo en cuenta las directivas "#line".

Devuelve "undef" en caso de error, o si el objeto PPI::Document no ha sido indexado.

logical_filename

Si el Elemento existe dentro de un PPI::Document que ha indexado las ubicaciones de los elementos usando "PPI::Document::index_locations", el método "logical_filename" devolverá el nombre de archivo lógico que contiene el primer carácter del Elemento dentro del Documento, teniendo en cuenta las directivas "#line".

Devuelve

POR HACER

Sería bueno si "location" pudiera usarse de forma ad-hoc. Es decir, si se llama en un Elemento dentro de un Documento que no ha sido indexado, realizará un cálculo único para encontrar la ubicación. Podría ser muy molesto si alguien comenzara a usarlo mucho, sin recordar indexar el documento, pero sería útil para cosas que solo es probable que lo usen una vez, como los manejadores de errores.
