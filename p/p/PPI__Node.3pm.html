PPI::Node(3) Documentación Perl contribuida por el usuario PPI::Node(3)

NOMBRE

PPI::Node - Clase abstracta de nodo PPI, un Elemento que puede contener otros Elementos

HERENCIA

PPI::Node
isa PPI::Element

SINOPSIS

# Crear un nodo típico (un Documento en este caso)
my $Node = PPI::Document->new;

# Añadir un elemento al nodo (en este caso, un token)
my $Token = PPI::Token::Word->new('my');
$Node->add_element( $Token );

# Obtener los elementos del Nodo
my @elements = $Node->children;

# Encontrar todas las palabras clave desnudas dentro de un Nodo
my $barewords = $Node->find( 'PPI::Token::Word' );

# Encontrar con criterios más complejos
my $my_tokens = $Node->find( sub { $_[1]->content eq 'my' } );

# Eliminar todo el espacio en blanco
$Node->prune( 'PPI::Token::Whitespace' );

# Eliminar con criterios más complejos
$Node->prune( sub { $_[1]->content eq 'my' } );

DESCRIPCIÓN

La clase "PPI::Node" proporciona una clase base abstracta para las clases de Elemento que son capaces de contener otros elementos: PPI::Document, PPI::Statement y PPI::Structure.

Además de los listados a continuación, todos los métodos que se aplican a los objetos PPI::Element también se aplican a los objetos "PPI::Node".

MÉTODOS

ámbito

El método "ámbito" (scope) devuelve verdadero si el nodo representa un límite de ámbito léxico, o falso si no lo hace.

add_element $Elemento

El método "add_element" añade un objeto PPI::Element al final de un "PPI::Node". Dado que los Elementos mantienen enlaces a su padre, un Elemento solo puede añadirse a un único Nodo.

Devuelve verdadero si el PPI::Element se añadió. Devuelve "undef" si el Elemento ya estaba dentro de otro Nodo, o si el método no recibe un objeto PPI::Element.

elementos

El método "elementos" accede a todos los elementos hijos estructuralmente dentro del objeto "PPI::Node". Tenga en cuenta que en el caso de las clases PPI::Structure, esto incluye los tokens de llaves al principio y al final de la estructura.

Devuelve una lista de cero o más objetos PPI::Element.

Alternativamente, si se llama en contexto escalar, el método "elementos" devuelve el recuento del número de elementos.

primer_elemento

El método "primer_elemento" accede al primer elemento estructuralmente dentro del objeto "PPI::Node". Al igual que para el método "elementos", esto incluye los tokens de llaves para los objetos PPI::Structure.

Devuelve un objeto PPI::Element, o "undef" si por alguna razón el objeto "PPI::Node" no contiene ningún elemento.

ultimo_elemento

El método "ultimo_elemento" accede al último elemento estructuralmente dentro del objeto "PPI::Node". Al igual que para el método "elementos", esto incluye los tokens de llaves para los objetos PPI::Structure.

Devuelve un objeto PPI::Element, o "undef" si por alguna razón el objeto "PPI::Node" no contiene ningún elemento.

hijos

El método "hijos" accede a todos los elementos hijos léxicamente dentro del objeto "PPI::Node". Tenga en cuenta que en el caso de las clases PPI::Structure, esto NO incluye los tokens de llaves al principio y al final de la estructura.

Devuelve una lista de cero o más objetos PPI::Element.

Alternativamente, si se llama en contexto escalar, el método "hijos" devuelve el recuento del número de hijos léxicos.

shijos

El método "shijos" es realmente solo una conveniencia, la variación significativa-solo del método normal "hijos".

En contexto de lista, devuelve una lista de hijos significativos. En contexto escalar, devuelve el número de hijos significativos.

hijo $indice

El método "hijo" accede a un objeto hijo PPI::Element por su posición dentro del Nodo.

Devuelve un objeto PPI::Element, o "undef" si no hay un elemento hijo en ese nodo.

shijo $indice

La estructura léxica del lenguaje Perl ignora los elementos 'insignificativos', como el espacio en blanco y los comentarios, mientras que PPI trata estos elementos como tokens válidos para poder volver a ensamblar el archivo en cualquier momento. Debido a esto, en muchas situaciones existe la necesidad de encontrar un Elemento dentro de un Nodo por índice, contando solo los Elementos léxicamente significativos.

El método "shijo" devuelve un Elemento hijo por índice, ignorando los Elementos insignificativos. El índice de un Elemento hijo se especifica de la misma manera que para un array normal, con el primer Elemento en el índice 0, y los índices negativos se utilizan para identificar una posición "desde el final".

contiene $Elemento

El método "contiene" se utiliza para determinar si otro objeto PPI::Element está lógicamente "dentro" de un "PPI::Node". Para el caso especial de los tokens de llaves a cada lado de un objeto PPI::Structure, generalmente se consideran "dentro" de un objeto PPI::Structure, incluso si no están realmente en los elementos del PPI::Structure.

Devuelve verdadero si el PPI::Element está dentro de nosotros, falso si no, o "undef" en caso de error.

encontrar $clase | \&deseado

El método "encontrar" se utiliza para buscar dentro de un árbol de código objetos PPI::Element que cumplan una condición particular.

Para especificar la condición, el método puede recibir un nombre de clase simple (completo o abreviado), o una referencia "CODE"/función.

# Encontrar todas las comillas simples en un Documento (que es un Nodo)
$Document->find('PPI::Quote::Single');

# Lo mismo con un nombre de clase abreviado
$Document->find('Quote::Single');

# Cualquier cosa más elaborada, usamos una subrutina
$Document->find( sub {
      # En el nivel superior del archivo...
      $_[1]->parent == $_[0]
      and (
              # ...encontrar todos los comentarios y POD
              $_[1]->isa('PPI::Token::Pod')
              or
              $_[1]->isa('PPI::Token::Comment')
      )
} );

La función recibirá dos argumentos: el "PPI::Node" de nivel superior en el que se está buscando y el PPI::Element actual que está siendo probado por la condición.

La función anónima debe devolver uno de tres valores. Devolver verdadero indica una coincidencia de condición, falso definido (0 o '') indica sin coincidencia, y "undef" indica sin coincidencia y sin descendencia.

En este último caso, el recorrido del árbol omitirá todo lo que esté debajo del elemento que devuelve "undef" y pasará al siguiente elemento al mismo nivel.

PPI::Node(3pm) - Perl Interface Documentation

NAME

PPI::Node - A node within the PPI parse tree

INHERITANCE

PPI::Node isa PPI.

SYNOPSIS

  my $node = $element->find( 'PPI::Node' );
  my $node = $element->find( sub { $_[0]->class eq 'PPI::Node' } );
  my $node = $element->find( sub { $_[0]->name eq 'Sub' } );
  my $node = $element->find( sub { $_[0]->content =~ /\bmy\b/ } );

  my $nodes = $tree->find( 'PPI::Node' );
  my $nodes = $tree->find( sub { $_[0]->class eq 'PPI::Node' } );

  my $first_node = $tree->find_first( 'PPI::Node' );
  my $first_node = $tree->find_first( sub { $_[0]->class eq 'PPI::Node' } );

  my $found = $tree->find_any( 'PPI::Node' );
  my $found = $tree->find_any( sub { $_[0]->class eq 'PPI::Node' } );

  $node->remove_child( $child );
  $node->replace_child( $child, $replacement );
  my $removed = $node->prune( 'PPI::Node' );
  my $removed = $node->prune( sub { $_[0]->class eq 'PPI::Node' } );

DESCRIPTION

This class is the base class for all of the elements within the Perl Document Parse Tree (PPI) that contain other elements. It handles the basic tree traversal and searching, and provides a basis for more specific node types like PPI::Statement, PPI::Structure and PPI::Lexical.

METHODS

find $class | \&wanted

This method searches recursively through the tree that the PPI::Element object is currently in, returning all of the elements that match the specified condition.

The condition can be either a class name (string) or an anonymous subroutine (a coderef).

If the condition is a class name, it will return a list of all elements that are of that class, or a subclass of that class. For example, find('PPI::Statement') will find all statements, including PPI::Statement::Declare, PPI::Statement::Expression, etc.

If the condition is an anonymous subroutine, it will be called for every element in the tree. The subroutine will be passed the element as its only argument (in $_[0]). The subroutine should return true if the element matches, and false otherwise.

The search is performed depth-first.

The return value is an array reference. Each element of the array is a PPI::Element object that matches the condition.

If no elements are found, it returns an empty array reference (not false).

If the condition is invalid, it returns "undef", and emits a warning.

The wanted parameter is passed on to the wanted method of PPI, which is the sub used by PPI::Document etc to perform the search. The wanted sub will also die if the condition is invalid.

Note that this same wanted logic is used for all methods documented to have a "\&wanted" parameter, as this one does.

The "find" method returns a reference to an array of PPI::Element objects that match the condition, false (but defined) if no Elements match the condition, or "undef" if you provide a bad condition, or an error occurs during the search process.

In the case of a bad condition, a warning will be emitted as well.

find_first $class | \&wanted

If the normal "find" method is like a grep, then "find_first" is equivalent to the List::Util "first" function.

Given an element class or a wanted function, it will search depth-first through a tree until it finds something that matches the condition, returning the first Element that it encounters.

See the "find" method for details on the format of the search condition.

Returns the first PPI::Element object that matches the condition, false if nothing matches the condition, or "undef" if given an invalid condition, or an error occurs.

find_any $class | \&wanted

The "find_any" method is a short-circuiting true/false method that behaves like the normal "find" method, but returns true as soon as it finds any Elements that match the search condition.

See the "find" method for details on the format of the search condition.

Returns true if any Elements that match the condition can be found, false if not, or "undef" if given an invalid condition, or an error occurs.

remove_child $Element

If passed a PPI::Element object that is a direct child of the Node, the "remove_element" method will remove the "Element" intact, along with any of its children. As such, this method acts essentially as a 'cut' function.

If successful, returns the removed element. Otherwise, returns "undef".

replace_child $Element, $Replacement

If successful, returns the replace element. Otherwise, returns "undef".

prune $class | \&wanted

The "prune" method is used to strip PPI::Element objects out of a code tree. The argument is the same as for the "find" method, either a class name, or an anonymous subroutine which returns true/false. Any Element that matches the class|wanted will be deleted from the code tree, along with any of its children.

The "prune" method returns the number of "Element" objects that matched and were removed, non-recursively. This might also be zero, so avoid a simple true/false test on the return false of the "prune" method. It returns "undef" on error, which you probably should test for.
