PPI::Document(3) Documentación de Perl contribuida por el usuario PPI::Document(3)

NOMBRE

PPI::Document - Representación de objeto de un documento Perl

HERENCIA

PPI::Document
isa PPI::Node
    isa PPI::Element

SINOPSIS

use PPI;

# Cargar un documento desde un archivo
my $Document = PPI::Document->new('Mi/Modulo.pm');

# Eliminar comentarios
$Document->prune('PPI::Token::Comment');

# Encontrar todas las subrutinas nombradas
my $sub_nodes = $Document->find( 
      sub { $_[1]->isa('PPI::Statement::Sub') and $_[1]->name }
);
my @sub_names = map { $_->name } @$sub_nodes;

# Guardar el archivo
$Document->save('Mi/Modulo.pm.descomentado');

DESCRIPCIÓN

La clase "PPI::Document" representa un único "documento" de Perl. Un objeto "PPI::Document" actúa como una raíz PPI::Node, con algunos métodos adicionales para cargar y guardar, y para trabajar con las ubicaciones de línea/columna de los Elementos dentro de un archivo.

La exención a su comportamiento similar a PPI::Node es que un objeto "PPI::Document" NUNCA puede tener un nodo padre, y siempre es el nodo raíz en un árbol.

Soporte Storable

"PPI::Document" implementa los ganchos "STORABLE_freeze" y "STORABLE_thaw" necesarios para proporcionar soporte nativo para Storable, si lo tienes instalado.

Sin embargo, si deseas clonar un Documento, te recomendamos encarecidamente que utilices el método "$Document->clone" en lugar de la función "dclone" de Storable (aunque "dclone" debería funcionar).

MÉTODOS

La mayoría de las cosas que probablemente querrás hacer con un Documento probablemente implicarán los métodos de la clase PPI::Node, de la cual esta es una subclase.

Los métodos enumerados aquí son los pocos métodos restantes que son verdaderamente específicos de Documento.

new

# Construcción simple
$doc = PPI::Document->new( $nombre_archivo );
$doc = PPI::Document->new( \$fuente  );

# Con el atributo readonly establecido
$doc = PPI::Document->new( $nombre_archivo,
        readonly => 1,
);

El constructor "new" toma como argumento una variedad de fuentes diferentes de código Perl, y crea un único y cohesivo "PPI::Document" de Perl para ello.

Si se le pasa un nombre de archivo como una cadena normal, intentará cargar el documento desde el archivo.

Si se le pasa una referencia a un "SCALAR", esto se toma como código fuente y se analiza directamente para crear el documento.

Si se le pasan cero argumentos, se creará un documento "en blanco" que no contiene ningún contenido.

En todos los casos, el documento se considera "anónimo" y no está vinculado a dónde se creó. Específicamente, si creas un PPI::Document a partir de un nombre de archivo, el documento NO recordará de dónde se creó.

Devuelve un objeto "PPI::Document", o "undef" si el análisis falla. También se pueden lanzar objetos PPI::Exception si hay problemas de análisis.

El constructor también toma flags de atributos.

readonly

Establecer "readonly" a verdadero permitirá que varios sistemas proporcionen optimizaciones y cachés adicionales. Tenga en cuenta que dado que "readonly" es un flag de optimización, está desactivado por defecto y deberá habilitarlo explícitamente.

feature_mods

Establecer feature_mods con un hashref permite definir características de análisis de perl para habilitarlas en todo el documento. (por ejemplo, cuando se asume que el código se ejecuta como una sola línea)

custom_feature_includes

custom_feature_includes =>
  { strEct => { signatures => "Syntax::Keyword::Try" } }

Establecer custom_feature_includes con un hashref permite definir nombres de inclusión que actúan como pragmas que habilitan características de análisis dentro de su ámbito.

Esto es principalmente útil cuando su proyecto de trabajo tiene su propio módulo de plantilla.

También se puede proporcionar como JSON o YAML en la variable de entorno PPI_CUSTOM_FEATURE_INCLUDES, de la siguiente manera:

PPI_CUSTOM_FEATURE_INCLUDES='strEct: {signatures: perl}' \
  perlcritic lib/NuestroModulo.pm
PPI_CUSTOM_FEATURE_INCLUDES='{"strEct":{"signatures":"perl"}}' \
  perlcritic lib/NuestroModulo.pm

custom_feature_include_cb

custom_feature_include_cb => sub {
  my ($statement) = @_;
  return $statement->module eq "strEct" ? { signatures => "perl" } : ();
},

Establecer custom_feature_include_cb con una referencia de código hace que todas las inspecciones de inclusiones llamen a esa subrutina antes de realizar cualquier otra inspección. La subrutina puede decidir devolver un hashref de características para habilitar o deshabilitar, que se usará para el ámbito en el que se llamó la inclusión, o undef para continuar con las inspecciones predeterminadas. El argumento para la subrutina será el objeto PPI::Statement::Include.

Esto puede ser útil cuando su proyecto de trabajo tiene un módulo de plantilla complejo.

set_cache $cache

A partir de PPI 1.100, "PPI::Document" soporta el caché del analizador.

La clase de caché predeterminada PPI::Cache proporciona un caché basado en Storable o el documento analizado basado en el hash MD5 del documento como una cadena.

El método estático "set_cache" se utiliza para establecer el objeto de caché que "PPI::Document" utilizará al cargar documentos. Toma como argumento un objeto PPI::Cache (o algo que "isa" lo mismo).

Si se pasa "undef", este método dejará de usar el caché actual, si lo hay.

Para más información sobre el caché, ver PPI::Cache.

Devuelve verdadero en caso de éxito, o "undef" si no se le pasa un parámetro válido.

get_cache

Si actualmente está configurado un caché de documentos, el método "get_cache" lo devolverá.

Devuelve un objeto PPI::Cache, o "undef" si actualmente no hay ningún caché configurado para "PPI::Document".

filename

El accesor "filename" devuelve el nombre del archivo en el que está almacenado el documento.

readonly

El atributo "readonly" indica si el documento está destinado a ser de solo lectura y nunca será modificado. Este es un flag informativo que los escritores de sistemas relacionados con PPI pueden usar o no para habilitar optimizaciones y cachés para su documento.

Devuelve verdadero si el documento es de solo lectura o falso si no lo es.

tab_width [ $width ]

Para poder manejar correctamente el soporte para "location", los "Documents" necesitan entender el concepto de tabulaciones y ancho de tabulación. El método "tab_width" se utiliza para obtener y establecer el tamaño del ancho de tabulación.

En este momento, PPI solo admite tabulaciones "ingenuas" (ancho 1), pero planeamos admitir anchos de tabulación arbitrarios, predeterminados y de detección automática más adelante.

Devuelve el ancho de tabulación como un entero, o "die" si intentas establecer el ancho de tabulación.
