PPIx::Regexp::Token::Modifier(3) Documentación de Perl contribuida por usuarios PPIx::Regexp::Token::Modifier(3)

NOMBRE

PPIx::Regexp::Token::Modifier - Representa modificadores.

SINOPSIS

use PPIx::Regexp::Dumper;
PPIx::Regexp::Dumper->new( 'qr{foo}smx' )
    ->print();

Las "smx" finales serán representadas por esta clase.

Esta clase también representa el conjunto completo de elementos como "(?ismx)". Pero los modificadores en algo como "(?i:foo)" son representados por un PPIx::Regexp::Token::GroupType::Modifier.

HERENCIA

"PPIx::Regexp::Token::Modifier" es un PPIx::Regexp::Token.

"PPIx::Regexp::Token::Modifier" es el padre de PPIx::Regexp::Token::GroupType::Modifier.

DESCRIPCIÓN

Esta clase representa caracteres modificadores al final de la expresión regular. Por ejemplo, en "qr{foo}smx" esta clase representaría las "smx" terminales.

Los modificadores "a", "aa", "d", "l", y "u"

Los modificadores "a", "aa", "d", "l" y "u", introducidos a partir de Perl 5.13.6, se utilizan para forzar semántica de patrones Unicode ("u"), semántica de localización ("l") semántica predeterminada ("d" las semánticas tradicionales de Perl, que también puede significar 'dual' ya que significa Unicode si el bit UTF-8 de la cadena está activado, y locale si el bit UTF-8 está desactivado), o semántica predeterminada restringida ("a"). Estos son mutuamente excluyentes y solo uno puede ser afirmado a la vez. Afirmar cualquiera de ellos anula el valor heredado de cualquiera de los otros. El método afirmado() informa como afirmado el último que encuentra, o ninguno de ellos si no ha encontrado ninguno.

Por ejemplo, dado "PPIx::Regexp::Token::Modifier" $elem representando el fragmento de expresión regular inválido "(?dul)", "$elem->afirmado('l')" devolvería verdadero, pero "$elem->afirmado('u')" devolvería falso. Nótese que "$elem->negado('u')" también devolvería falso, ya que "u" no está explícitamente negado.

Si $elem representara el fragmento de expresión regular "(?i)", "$elem->afirmado('d')" devolvería falso, ya que aunque "d" representa el comportamiento predeterminado, no se afirma explícitamente.

El modificador caret ("^")

Llamar al "^" un modificador es un poco inexacto. La construcción "(?^...)" se introdujo en Perl 5.13.6, para prevenir la herencia de modificadores. La documentación llama al caret un atajo equivalente a "d-imsx", y esa es la forma en que esta clase lo maneja.

Por ejemplo, dado el fragmento de expresión regular "PPIx::Regexp::Token::Modifier" $elem representando el fragmento de expresión regular "(?^i)", "$elem->afirma('d')" devolvería verdadero, ya que en ausencia de una "l" o "u" explícita, esta clase considera que el "^" afirma explícitamente "d".

El manejo del caret se complica por el hecho de que el modificador 'n' se introdujo en 5.21.8, momento en el que el caret se convirtió en equivalente a "d-imnsx". No sentí que pudiera agregar incondicionalmente el "-n" a la expansión del caret, porque eso produciría una salida confusa de métodos como explain(). Tampoco pude hacerlo condicional a la versión mínima de perl, porque esa información no está disponible lo suficientemente temprano en el análisis. Lo que hice fue expandir el caret a "d-imnsx" si y solo si 'n' estaba en efecto en algún momento en el ámbito en el que se analizó el modificador.

Continuando el ejemplo anterior, "$elem->afirma('n')" y "$elem->modificador_afirmado('n')" ambos devolverían falso, pero "$elem->niega('n')" devolvería verdadero si y solo si el modificador "/m" ha sido afirmado en algún lugar antes y dentro del ámbito de este token. El método modifier_asserted('n') se hereda de PPIx::Regexp::Element.

MÉTODOS

Esta clase proporciona los siguientes métodos públicos. Los métodos no documentados aquí son privados y no soportados en el sentido de que el autor se reserva el derecho de cambiarlos o eliminarlos sin previo aviso.

afirma

$token->afirma( 'i' ) and print "token afirma i";
foreach ( $token->afirma() ) { print "token afirma $_\n" }

Este método devuelve verdadero si el token afirma explícitamente el modificador dado. El ejemplo devolvería verdadero para el modificador en "(?i:foo)", pero falso para "(?-i:foo)".

A partir de la versión 0.036_01, si el argumento es un modificador de un solo carácter seguido de un asterisco (destinado como carácter comodín), la devolución es el número de veces que aparece ese modificador. En este caso, se lanzará una excepción si especifica un modificador de varios caracteres (por ejemplo, 'ee*').

Si se llama sin argumento, o con un argumento undef, se devuelven todos los modificadores explícitamente afirmados por este token.

semántica_de_coincidencia

my $sem = $token->semantica_de_coincidencia();
defined $sem or $sem = 'undefined';
print "Este token tiene $sem de semántica de coincidencia\n";

Este método devuelve la semántica de coincidencia afirmada por el token, como una de las cadenas 'a', 'aa', 'd', 'l' o 'u'. Si no se afirma explícitamente ninguna semántica de coincidencia, este método devuelve "undef".

modificadores

my %mods = $token->modificadores();

Devuelve todos los modificadores afirmados o negados por este token, y los valores establecidos (verdadero para afirmado, falso para negado). Si se llama en contexto escalar, devuelve una referencia a un hash que contiene los valores.

niega

$token->niega( 'i' ) and print "token niega i\n";
foreach ( $token->niega() ) { print "token niega $_\n" }

Este método devuelve verdadero si el token niega explícitamente el modificador dado. El ejemplo devolvería verdadero para el modificador en "(?-i:foo)", pero falso para "(?i:foo)".

Si se llama sin argumento, o con un argumento undef, se devuelven todos los modificadores explícitamente negados por este token.
