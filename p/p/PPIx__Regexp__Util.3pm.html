NOMBRE

PPIx::Regexp::Util - Funciones de utilidad para PPIx::Regexp;

SINOPSIS

use PPIx::Regexp::Util qw{ __instance };
    .
    .
    .
__instance( $foo, 'Bar' )
    or die '$foo no es un Bar';

DESCRIPCIÓN

Este módulo contiene funciones de utilidad para PPIx::Regexp que es conveniente centralizar.

Las subrutinas con doble guion bajo son **privadas** del paquete "PPIx-Regexp". Su documentación se proporciona solo para conveniencia del autor, y están sujetas a cambios sin previo aviso. *Precaución al usuario.*

Este módulo no exporta nada por defecto.

SUBRUTINAS

Este módulo puede exportar las siguientes subrutinas:

is_ppi_regexp_element

is_ppi_regexp_element( $elem )
  and print "$elem es una expresión regular de algún tipo\n";

Esta subrutina es pública y compatible.

Esta subrutina toma como argumento un PPI::Element. Devuelve un valor verdadero si el argumento representa una expresión regular de algún tipo, y un valor falso en caso contrario.

__instance

__instance( $foo, 'Bar' )
    and print '$foo es un Bar', "\n";

Esta subrutina es **privada** del paquete "PPIx-Regexp".

Esta subrutina devuelve verdadero si su primer argumento es una instancia de la clase especificada por su segundo argumento. A diferencia de "UNIVERSAL::isa", el resultado es siempre falso a menos que el primer argumento sea una referencia.

__is_ppi_regexp_element

__is_ppi_regexp_element( $elem )
  and print "$elem es una expresión regular de algún tipo\n";

Esta subrutina es **privada** del paquete "PPIx-Regexp".

Es un sinónimo de is_ppi_regexp_element(), y está obsoleto en favor de esta. Si se llama, se quejará a través de Carp::cluck() y luego "goto &is_ppi_regexp_element".

__merge_perl_requirements

Esta subrutina es **privada** del paquete "PPIx-Regexp".

Esta subrutina fusiona los requisitos de perl tal como son devueltos por los diversos métodos "__perl_requirements()".

__ns_can

Esta subrutina es **privada** del paquete "PPIx-Regexp".

Este método es análogo a can(), pero devuelve una referencia al código solo si está implementado por el espacio de nombres invocador.

__post_rebless_error

Este método es **privado** del paquete "PPIx-Regexp". Su uso previsto es aliastrarlo a "__PPIX_ELEM__post_reblessing()".

Toma argumentos como pares nombre/valor. El argumento "{error}" es el mensaje de error; si se omite, se obtiene una advertencia con un rastreo de pila. El argumento "{explanation}" tiene como valor predeterminado "{error}".

Devuelve el número de errores a añadir a la sintaxis.

raw_width

Este método público devuelve el ancho mínimo y máximo que coincide con el elemento antes de tener en cuenta detalles como qué es realmente el elemento y cómo se cuantifica.

Esta implementación es apropiada para cosas que coinciden exactamente con un carácter; es decir, devuelve "( 1, 1 )".

__to_ordinal_en

Esta subrutina es **privada** del paquete "PPIx-Regexp".

Esta subrutina toma como argumento un entero y devuelve una cadena que representa su ordinal en inglés. Por ejemplo:

say __to_ordinal_en( 17 );
# 17º

width

my ( $min_wid, $max_wid ) = $self->width();

Este método público (bueno, mixin) devuelve el ancho mínimo y máximo del texto que coincide con el elemento.

Los elementos que importan este método también deben implementar un método raw_width() que devuelva el ancho no cuantificado del elemento.

TAGS DE EXPORTACIÓN

Las siguientes etiquetas de exportación están definidas por este módulo. Todas son privadas del paquete "PPIx-Regexp" a menos que se documente lo contrario.

all

Esta etiqueta exporta todo lo exportable por este módulo.

width_one

Esta etiqueta es apropiada para un elemento que, cuando no está cuantificado, coincide exactamente con un carácter. Exporta raw_width() y width().

VER TAMBIÉN

Params::Util, que recomiendo, pero en el caso de "PPIx::Regexp" no quería introducir una dependencia en un módulo XS cuando todo lo que realmente quería era la funcionalidad de la subrutina _INSTANCE() de ese módulo.

NAME

PPIx::Regexp::Util - Utilidades para trabajar con el analizador de expresiones regulares de PPI

SYNOPSIS


    use PPIx::Regexp::Util qw(
        &is_single_quoted_string
        &is_double_quoted_string
        &is_regex_literal
        &is_string_literal
        &is_naked_word
        &is_char_class_element
        &is_simple_char
        &is_string_literal_fragment
        &is_regex_literal_fragment
    );

    my $token = ...; # un token de PPI
    if (is_single_quoted_string($token)) {
        print "Es una cadena de comillas simples\n";
    }
    elsif (is_regex_literal($token)) {
        print "Es un literal de expresión regular\n";
    }
    # ... y así sucesivamente

DESCRIPTION

Esta módulo proporciona un conjunto de funciones de utilidad que pueden ser usadas para determinar la naturaleza de un token de PPI. Se centran específicamente en los tokens que podrían formar parte de literales de cadenas o expresiones regulares.

SUBROUTINES

Cada una de las siguientes subrutinas toma un único argumento, que se espera que sea un objeto token de PPI.

is_single_quoted_string($token)
Devuelve verdadero si el token es un literal de cadena de comillas simples.
is_double_quoted_string($token)
Devuelve verdadero si el token es un literal de cadena de comillas dobles.
is_regex_literal($token)
Devuelve verdadero si el token es un literal de expresión regular (por ejemplo, /abc/).
is_string_literal($token)
Devuelve verdadero si el token es un literal de cadena de comillas simples o dobles.
is_naked_word($token)
Devuelve verdadero si el token es una palabra sin comillas (por ejemplo, un identificador).
is_char_class_element($token)
Devuelve verdadero si el token es un elemento válido dentro de una clase de caracteres de expresión regular (por ejemplo, a, -, \d, \w).
is_simple_char($token)
Devuelve verdadero si el token es un carácter simple y no una secuencia de escape o una clase de caracteres.
is_string_literal_fragment($token)
Devuelve verdadero si el token es un fragmento que podría formar parte de un literal de cadena (por ejemplo, una palabra, un número, un símbolo).
is_regex_literal_fragment($token)
Devuelve verdadero si el token es un fragmento que podría formar parte de un literal de expresión regular (por ejemplo, una palabra, un número, un símbolo, una secuencia de escape, una clase de caracteres).

EXPORT_TAGS

Ninguno (todas las funciones se exportan por defecto).
