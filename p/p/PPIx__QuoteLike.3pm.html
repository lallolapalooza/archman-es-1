PPIx::QuoteLike(3) Documentación de Perl contribuida por el usuario PPIx::QuoteLike(3)

NOMBRE

PPIx::QuoteLike - Analiza literales de cadenas de Perl y cosas similares a literales de cadenas.

SINOPSIS

use PPIx::QuoteLike;
my $str = PPIx::QuoteLike->new( q<"fu$bar"> );
say $str->interpolates() ?
   'interpola' :
   'no interpola';

DESCRIPCIÓN

Esta clase de Perl analiza literales de cadenas de Perl y cosas que son razonablemente parecidas a literales de cadenas. Su verdadera razón de ser es encontrar variables interpoladas para las políticas de Perl::Critic y código similar.

El análisis es bastante sencillo, y un poco de exploración con eg/pqldump debería mostrar cómo va normalmente.

Pero hay al menos una cosa tipo comilla que probablemente necesita alguna explicación.

Documentos Here Indentados

Estos se introdujeron en Perl 5.25.7 (noviembre de 2016) pero no fueron reconocidos por este módulo hasta su versión 0.015 (febrero de 2021). La indentación se analiza como objetos PPIx::QuoteLike::Token::Whitespace, siempre que tenga al menos un carácter de ancho, de lo contrario no se representa en el análisis. Es decir,

<<~EOD
    ¿Cómo el pequeño cocodrilo
    Mejora su brillante cola
    EOD

tendrá las tres indentaciones representadas por objetos de espacio en blanco y cada línea del literal representada por su propio objeto de cadena, pero

<<~EOD
¿Cómo el pequeño cocodrilo
Mejora su brillante cola
EOD

analizará lo mismo que la versión no indentada, excepto por la adición del token que representa el '~'.

PPI está adelantado a este módulo y reconoció los documentos here indentados a partir de su versión 1.246 (mayo de 2019). Desafortunadamente, a partir de la versión 1.270, la indentación se pierde en el análisis, por lo que un objeto "PPIx::QuoteLike" inicializado a partir de dicho PPI::Token::HereDoc se verá como si tuviera una indentación de '' independientemente de la indentación real en el código fuente. Creo que esta restricción desaparecerá cuando se resuelva https://github.com/Perl-Critic/PPI/issues/251.

AVISO DE DEPRECACIÓN

El argumento "postderef" para new() está pasando por un ciclo de deprecación y retracción. Después de la retracción, las desreferencias postfijas siempre serán reconocidas.

A partir de la versión 0.012_01, el primer uso de este argumento emitió una advertencia. Con la versión 0.016_01, todos los usos emiten una advertencia. Con la versión 0.017_01, todos los usos son fatales. Con la versión 0.0.021_01, se elimina toda mención de este argumento, excepto, por supuesto, este aviso.

HERENCIA

"PPIx::QuoteLike" no desciende de ninguna otra clase.

"PPIx::QuoteLike" no tiene descendientes.

MÉTODOS

Esta clase soporta los siguientes métodos públicos:

new

my $str = PPIx::QuoteLike->new( $source, %arg );

Este método estático analiza el argumento y devuelve un nuevo objeto que contiene el análisis. El argumento $source puede ser un escalar o un objeto PPI::Element apropiado. Si el argumento $source es un escalar, se presume que representa un literal tipo comilla de algún tipo, siempre que comience como tal. De lo contrario, este método no devolverá nada. La representación escalar de un documento here es una cadena multilínea cuya primera línea consiste en el " << " inicial y el delimitador de inicio, y cuyas líneas subsiguientes consisten en el contenido del documento here y el delimitador de fin. Los documentos here indentados no fueron compatibles con esta clase hasta la versión 0.015.

Las clases "PPI" que se pueden manejar son PPI::Token::Quote, PPI::Token::QuoteLike::Backtick, PPI::Token::QuoteLike::Command, PPI::Token::QuoteLike::Readline y PPI::Token::HereDoc. Cualquier otro objeto hará que new() no devuelva nada.

Se pueden pasar argumentos opcionales adicionales como pares nombre/valor. Los argumentos admitidos son:

encoding
Esta es la codificación de $source. Si se especifica como algo distinto de "undef", $source se decodificará antes de procesarlo.

Si $source es un "PPI::Element", esta codificación se utiliza solo si el documento que contiene el elemento no tiene marca de orden de bytes ni 'use utf8'.

index_locations
Este argumento booleano determina si se deben calcular las ubicaciones de los tokens. Por defecto es verdadero si el argumento $source es un PPI::Element o si se proporcionó el argumento "location", y falso en caso contrario.
location
Este argumento es una referencia a una matriz compatible con la devuelta por el método location() de PPI::Element. Por defecto es la ubicación del argumento $source si este era un PPI::Element, de lo contrario no habrá ubicaciones disponibles.
trace
Este argumento booleano hace que se escriba un rastro del análisis en la salida estándar. Establecer esto a un valor verdadero no está soportado en el sentido de que el autor no hace ninguna representación sobre lo que sucederá si lo haces, y se reserva el derecho de hacer cambios en la funcionalidad, o retractarla por completo, sin previo aviso.

Todos los demás argumentos no están soportados y están reservados para el autor.

child

my $kid = $str->child( 0 );

Este método devuelve el elemento hijo cuyo índice se proporciona como argumento. Los hijos no incluyen el type(), ni los delimitadores de start() o finish(). Los índices negativos son válidos y tienen la interpretación habitual de Perl.

children

my @kids = $str->children();

Este método devuelve todos los elementos hijos. Los hijos no incluyen el type(), ni los delimitadores de start() o finish().

column_number

Este método devuelve el número de columna del primer carácter del elemento, o "undef" si no se puede determinar.

content

say $str->content();

Este método devuelve el contenido del objeto. Si el argumento original era una cadena válida de Perl, debería ser lo mismo que la cadena analizada originalmente.

delimiters

say $str->delimiters();

Este método devuelve los delimitadores del objeto, como una cadena. Serán dos caracteres a menos que el argumento de new() fuera un documento here, al que le faltara su delimitador de fin, o una cadena inválida. En este último caso, el retorno podría ser cualquier cosa.

elements

my @elem = $str->elements();

Este método devuelve todos los elementos del objeto. Esto incluye type(), start(), children() y finish(), en ese orden.

failures

say $str->failures();

Este método devuelve el número de fallos de análisis encontrados. Estas son instancias en las que el analizador no pudo averiguar qué estaba pasando, y deberían ser lo mismo que el número de objetos PPIx::QuoteLike::Token::Unknown devueltos por elements().

encontrar

for ( @{[ $str->find( $criteria ) || [] } ) {
    ...
}

Este método encuentra y devuelve una referencia a un array de todos los elementos que cumplen los criterios dados. Si no se encuentra nada, se devuelve un valor falso.

El $criteria puede ser el nombre de una clase de PPIx::QuoteLike::Token o una referencia a código. En este último caso, el código se llama para cada elemento en elements(), con el elemento como único argumento. El elemento se incluye en la salida si el código devuelve un valor verdadero.

finalizar

say map { $_->content() } $str->finish();

Este método devuelve los elementos finales del análisis. En realidad es un array, y el primer elemento es un PPIx::QuoteLike::Token::Delimiter. Si el análisis es de un documento here, habrá un segundo elemento, que será un PPIx::QuoteLike::Token::Whitespace que contiene el carácter de nueva línea final.

Si se llama en contexto de lista, se obtiene todo el array. Si se llama en contexto escalar, se obtiene el elemento cuyo índice se proporciona en el argumento, o el elemento cero si no se especifica ningún argumento.

maneja

say PPIx::QuoteLike->handles( $string ) ?
    "Podemos manejar $string" :
    "No podemos manejar $string";

Este método estático de conveniencia devuelve un valor verdadero si se puede esperar que este paquete maneje el contenido de $string (ya sea escalar u objeto), y un valor falso en caso contrario.

indentación

Este método devuelve la cadena de indentación si el objeto representa un documento here indentado, o "undef" si representa cualquier otra cosa, incluido un documento here no indentado.

Nota que si se utiliza sintaxis indentada pero el documento here no está de hecho indentado, esto devolverá '', que se evalúa como falso.

interpola

say $str->interpolates() ?
    'La cadena interpola' :
    'La cadena no interpola';

Este método devuelve un valor verdadero si la cadena analizada interpola, y un valor falso si no lo hace. Esto no indica si realmente se produce alguna interpolación, solo si la cadena es de tipo comilla doble o comilla simple.

número_de_línea

Este método devuelve el número de línea del primer carácter del elemento, o "undef" si no se puede determinar.

ubicación

Este método devuelve una referencia a un array que describe la posición de la cadena, o "undef" si la ubicación no está disponible.

El array es compatible con el método correspondiente de PPI::Element.

nombre_archivo_lógico

Este método devuelve el nombre lógico del archivo (teniendo en cuenta las directivas "#line") del archivo que contiene el primer carácter del elemento, o "undef" si no se puede determinar.

número_línea_lógico

Este método devuelve el número de línea lógico (teniendo en cuenta las directivas "#line") del primer carácter del elemento, o "undef" si no se puede determinar.

padre

Este método no devuelve nada, ya que el invocante solo se utiliza en la parte superior de la jerarquía del objeto.

perl_version_introducida

Este método devuelve el valor máximo de "perl_version_introduced" devuelto por cualquiera de sus elementos. En otras palabras, devuelve la versión mínima de Perl bajo la cual este objeto de tipo comilla es válido. Si no hay elementos, se devuelve 5.000, ya que es el valor mínimo de Perl admitido por este paquete.

perl_version_eliminada

Este método devuelve el valor mínimo definido de "perl_version_removed" devuelto por cualquiera de los elementos del objeto de tipo comilla. En otras palabras, devuelve la versión más baja de Perl en la que este objeto **no** es válido. Si no hay elementos, o si ningún elemento tiene una "perl_version_removed" definida, se devuelve "undef".

hijo_significativo

my $skid = $str->schild( 0 );

Este método devuelve los elementos hijos significativos cuyo índice proporciona el argumento. Los índices negativos se interpretan de la forma habitual.

hijos_significativos

my @skids = $str->schildren();

Este método devuelve los hijos significativos.

fuente

my $source = $str->source();

Este método devuelve el argumento $source de new(), sea lo que sea.

inicio

say map { $_->content() } $str->start();

Este método devuelve los elementos de inicio del análisis. En realidad es un array, y el primer elemento es un PPIx::QuoteLike::Token::Delimiter. Si el análisis es de un documento here, habrá un segundo elemento, que será un PPIx::QuoteLike::Token::Whitespace que contiene el carácter de nueva línea final.

Si se llama en contexto de lista, se obtiene todo el array. Si se llama en contexto escalar, se obtiene el elemento cuyo índice se proporciona en el argumento, o el elemento cero si no se especifica ningún argumento.

declaración

Este método devuelve la PPI::Statement que contiene esta cadena, o nada si la declaración no se puede determinar.

En general, este método devolverá algo solo bajo las siguientes condiciones:

  • La cadena está contenida en un objeto PPIx::QuoteLike;
  • Ese objeto fue inicializado desde un PPI::Element;
  • El PPI::Element está contenido en una declaración.

superior

Este método devuelve la parte superior de la jerarquía; en este caso, el invocante.

tipo

my $type = $str->type();

Este método devuelve el objeto de tipo. Será un PPIx::QuoteLike::Token::Structure si el análisis fue exitoso; de lo contrario, podría ser "undef". Su contenido será todo hasta el delimitador de inicio, y típicamente será 'q', 'qq', 'qx', '<<' (para documentos here) o '' (para cadenas entre comillas).

Los datos del tipo son en realidad un array. Si el segundo elemento está presente, será el espacio en blanco (si lo hay) que separa el tipo real del valor. Si se llama en contexto de lista, se obtiene todo el array. Si se llama en contexto escalar, se obtiene el elemento cuyo índice se proporciona en el argumento, o el elemento cero si no se especifica ningún argumento.

variables

say "Interpola $_" for $str->variables();

NOTA que este método no se recomienda y puede ser obsoleto y eliminado. Tengo dos problemas con él. El primero es que devuelve nombres de variables en lugar de objetos PPI::Element, lo que te deja sin saber cómo se usan las variables. El segundo es que no maneja correctamente cosas como "${^CAPTURE[0]}", y parece inviable que lo haga. Originalmente se escribió para el beneficio de Perl::Critic::Policy::Variables::ProhibitUnusedVarsStricter, pero ha demostrado ser inadecuado para las necesidades de esa política.

Este método de conveniencia devuelve todas las variables interpoladas. Cada una se devuelve solo una vez, y se devuelven sin un orden particular. Si el objeto no representa una cadena que interpola, no se devuelve nada.

número_columna_visual

Este método devuelve el número de columna visual (teniendo en cuenta las tabulaciones) del primer carácter del elemento, o "undef" si no se puede determinar.

RESTRICCIONES

Por la naturaleza de este módulo, nunca va a hacerlo todo bien. Muchas de las áreas problemáticas conocidas involucran interpolaciones de una forma u otra.

Cambios en la Sintaxis

A veces, la introducción de nueva sintaxis cambia la forma en que se analiza una cadena. Por ejemplo, el control de caso "\F" (cambiar a minúsculas) se introdujo en Perl 5.15.8. Pero no representó un error de sintaxis anterior a esa versión de Perl, simplemente se analizó como "F". Así que

$ perl -le 'print "Foo\FBar"'

imprime "FooFBar" en Perl 5.14.4, pero "Foobar" en 5.16.0. "PPIx::QuoteLike" generalmente asume el análisis más moderno en casos como este.

Análisis Estático

Es bien sabido que Perl no puede ser analizado estáticamente. Es decir, no se puede analizar completamente un fragmento de código Perl sin ejecutar ese mismo código.

PPIx::QuoteLike(3pm) - Perl documentation

NAME

PPIx::QuoteLike - Parse Perl quote-like constructs

SYNOPSIS

    use PPIx::QuoteLike;

    my $parser = PPIx::QuoteLike->new;
    my $document = $parser->parse( $string );
    ...

DESCRIPTION

This module parses quote-like constructs, such as those produced by Perl's qq{}, qw{}, qr{}, s{}, and tr{} operators, and their various delimiter forms.

It is intended to be a complement to the PPI (Perl::Parser Interface) module, specifically for handling the content within those quote-like constructs.

DEPRECATION NOTICE

As of version 0.020, this module is deprecated. Its functionality has been subsumed by PPIx::QuoteLike::PPI::Tokenizer, which is the preferred way to parse quote-like constructs.

INHERITANCE

None. This is a utility module.

METHODS

new

Creates a new PPIx::QuoteLike object.

Currently, there are no options or parameters for the constructor.

parse

Takes a string containing Perl code and returns a PPI::Document object representing the parsed code. The quote-like constructs will be parsed into PPI::Token objects.

    my $string = 'my $x = qq{Hello, world!};';
    my $document = $parser->parse( $string );
    my $token = $document->find( 'PPI::Token::Quote::Quoted' );
    print $token->content; # prints Hello, world!

The parse method delegates the actual parsing to PPI::Parser.

parse_string

This method is deprecated and will be removed in a future version. Use parse instead.

RESTRICTIONS

PPI Restrictions

This module relies on PPI for parsing. As such, it inherits all of the restrictions of PPI.

Specifically, PPI does not handle code generation, only parsing. Therefore, this module cannot determine what source code would be generated from a given parsed structure.

Similarly, PPI does not evaluate code. Therefore, this module cannot determine the runtime behavior of quote-like constructs, especially those involving variable interpolation.

For example, consider the following:

    my $var = 'world';
    my $string = "Hello, $var!";

This module will parse "Hello, $var!" as a string containing the literal characters Hello, , a variable interpolation token $var, and the literal character !. It cannot know that at runtime $var will be replaced with world.

While this module *can* parse interpolated strings, it does not attempt to interpret the interpolated content. It simply parses it as Perl code. There might be edge cases where the parsing of interpolated content could affect the parsing of the surrounding quote-like construct, but this module does not attempt to handle such cases.

Caveat user.

PPI Restrictions

As of version 0.015 of this module, the only known instance of this is the handling of indented here documents, as discussed above under Indented Here Documents.

Non-Standard Syntax

There are modules out there that alter the syntax of Perl. If the syntax of a quote-like string is altered, this module has no way to understand that it has been altered, much less to adapt to the alteration. The following modules are known to cause problems:

Acme::PerlML, which renders Perl as XML.

"Data::PostfixDeref", which causes Perl to interpret suffixed empty brackets as dereferencing the thing they suffix. This module by Ben Morrow ("BMORROW") appears to have been retracted.

Filter::Trigraph, which recognizes ANSI C trigraphs, allowing Perl to be written in the ISO 646 character set.

Perl6::Pugs. Enough said.
