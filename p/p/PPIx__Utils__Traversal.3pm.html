PPIx__Utils__Traversal(3pm)

Paquete: perl-ppix-utils

Licencias: PerlArtistic

PPIx::Utils::Traversal(3) Documentación de Perl proporcionada por el usuario PPIx::Utils::Traversal(3)

NOMBRE

PPIx::Utils::Traversal - Funciones de utilidad para recorrer documentos PPI

SINOPSIS

use PPIx::Utils::Traversal ':all';

DESCRIPCIÓN

Este paquete es un componente de PPIx::Utils que contiene funciones para recorrer documentos PPI.

FUNCIONES

Todas las funciones se pueden importar por nombre, o con la etiqueta ":all".

first_arg

my $first_arg = first_arg($element);

Dado un PPI::Element que se presume es una llamada a una función (que normalmente es un PPI::Token::Word), devuelve el primer argumento. Esto es similar a "parse_arg_list" y sigue la misma lógica. Nota que para el código:

int($x + 0.5)

esta función devolverá solo $x, no toda la expresión. Esto es diferente del comportamiento de "parse_arg_list". Otra advertencia es:

int(($x + $y) + 0.5)

que devuelve "($x + $y)" como una instancia de PPI::Structure::List.

parse_arg_list

my @args = parse_arg_list($element);

Dado un PPI::Element que se presume es una llamada a una función (que normalmente es un PPI::Token::Word), divide las expresiones de los argumentos en arrays de tokens. Devuelve una lista que contiene referencias a cada uno de esos arrays. Esto es útil porque los paréntesis son opcionales al llamar a una función, y PPI los analiza de manera muy diferente. Por lo tanto, este método es un árbol de análisis de nodos PPI de "pobre". No es a prueba de fallos porque no respeta la precedencia. En general, no me gusta cómo funciona esta función, así que no cuentes con que sea estable (o incluso que exista).

split_nodes_on_comma

my @args = split_nodes_on_comma(@nodes);

Esto tiene el mismo tipo de retorno que "parse_arg_list" pero espera recibir los nodos que representan el interior de una lista, como:

'foo', 1, 2, 'bar'

get_next_element_in_same_simple_statement

my $element = get_next_element_in_same_simple_statement($element);

Dado un PPI::Element, esta subrutina devuelve el siguiente elemento en la misma sentencia simple tal como se define en "is_ppi_simple_statement" en PPIx::Utils::Classification. Si no se encuentra ningún elemento siguiente, esta subrutina simplemente devuelve "undef".

Si $element es indefinido o no tiene bendición, simplemente devolvemos "undef".

Si $element satisface "is_ppi_simple_statement" en PPIx::Utils::Classification, devolvemos "undef", **a menos que** tenga un padre que sea una PPI::Structure::List.

Si $element es el último elemento significativo en su PPI::Node, lo reemplazamos con su padre e iteramos de nuevo.

De lo contrario, devolvemos "$element->snext_sibling()".

get_previous_module_used_on_same_line

my $element = get_previous_module_used_on_same_line($element);

Dado un PPI::Element, devuelve el PPI::Element que representa el nombre del módulo incluido por el "use" o "require" anterior en la misma línea que $element. Si no se encuentra ninguno, simplemente devuelve "undef".

Por ejemplo, con la línea

use version; our $VERSION = ...;

dada la instancia de PPI::Token::Symbol para $VERSION, esto devolverá "version".

Si el elemento dado está en un "use" o "require", el retorno proviene del "use" o "require" anterior en la línea, si lo hay.

get_constant_name_elements_from_declaring_statement

my @constants = get_constant_name_elements_from_declaring_statement($statement);

Dada una PPI::Statement, si la sentencia es una declaración de Readonly, ReadonlyX o Const::Fast o una declaración de "use constant", devuelve los nombres de las cosas que se están definiendo.

Dado

use constant 1.16 FOO => 'bar';

esto devolverá el PPI::Token::Word que contiene 'FOO'. Dado

use constant 1.16 { FOO => 'bar', 'BAZ' => 'burfle' };

esto devolverá una lista de los PPI::Tokens que contienen 'FOO' y 'BAZ'. De manera similar, dado

Readonly::Hash my %FOO => ( bar => 'baz' );

o

const my %FOO => ( bar => 'baz' );

esto devolverá el PPI::Token::Symbol que contiene '%FOO'.

split_ppi_node_by_namespace

my $subtrees = split_ppi_node_by_namespace($node);

Devuelve los sub-árboles para cada namespace en el nodo como una referencia a un hash de referencias a arrays de PPI::Nodes. Digamos que tenemos el siguiente código:

#!perl
my $x = blah();
package Foo;
my $y = blah_blah();
{
    say 'Whee!';
    package Bar;
    something();
}
thingy();
package Baz;
da_da_da();
package Foo;
foreach ( blrfl() ) {
    ...
}

Llamar a esta función en un PPI::Document para lo anterior devuelve un valor que se parece a esto, usando literales de cadena multilínea para las partes reales del código en lugar de árboles PPI para que esto sea más fácil de leer:

{
    main    => [
        q<
            #!perl
            my $x = blah();
        >,
    ],
    Foo     => [
        q<
            package Foo;
            my $y = blah_blah();
            {
                say 'Whee!';
            }
            thingy();
        >,
        q<
            package Foo;
            foreach ( blrfl() ) {
                ...
            }
        >,
    ],
    Bar     => [
        q<
            package Bar;
            something();
        >,
    ],
    Baz     => [
        q<
            package Baz;
            da_da_da();
        >,
    ],
}

Nota que el valor de retorno contiene copias de los nodos originales, y no los nodos originales en sí debido a la necesidad de manejar namespaces que no están en el ámbito del archivo. (Note cómo el primer elemento para "Foo" arriba difiere del código original.)
