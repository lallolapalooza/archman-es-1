POE::Component::Client::Keepalive(3) Documentación Perl contribuida por el usuario POE::Component::Client::Keepalive(3)

NOMBRE

POE::Component::Client::Keepalive - gestiona conexiones, con mantenimiento de conexión

VERSIÓN

versión 0.272

SINOPSIS

use warnings;
use strict;
use POE;
use POE::Component::Client::Keepalive;
POE::Session->create(
  inline_states => {
    _start    => \&start,
    got_conn  => \&got_conn,
    got_error => \&handle_error,
    got_input => \&handle_input,
  }
);
POE::Kernel->run();
exit;
sub start {
  $_[HEAP]{ka} = POE::Component::Client::Keepalive->new();
  $_[HEAP]{ka}->allocate(
    scheme  => "http",
    addr    => "127.0.0.1",
    port    => 9999,
    event   => "got_conn",
    context => "datos arbitrarios (incluso una referencia) aquí",
    timeout => 60,
  );
  print "La conexión está en progreso.\n";
}
sub got_conn {
  my ($kernel, $heap, $response) = @_[KERNEL, HEAP, ARG0];
  my $conn    = $response->{connection};
  my $context = $response->{context};
  if (defined $conn) {
    if ($response->{from_cache}) {
      print "La conexión se estableció inmediatamente.\n";
    }
    else {
      print "La conexión se estableció de forma asíncrona.\n";
    }
    $conn->start(
      InputEvent => "got_input",
      ErrorEvent => "got_error",
    );
    return;
  }
  print(
    "No se pudo establecer la conexión: ",
    "$response->{function} error $response->{error_num}: ",
    "$response->{error_str}\n"
  );
}
sub handle_input {
  my $input = $_[ARG0];
  print "$input\n";
}
sub handle_error {
  my $heap = $_[HEAP];
  delete $heap->{connection};
  $heap->{ka}->shutdown();
}

DESCRIPCIÓN

POE::Component::Client::Keepalive crea y gestiona conexiones para otros componentes. Mantiene una caché de conexiones mantenidas activas para una reutilización rápida. Está escrito específicamente para clientes que pueden beneficiarse de conexiones mantenidas activas, como los clientes HTTP. Usarlo para conexiones de un solo uso probablemente sería una tontería.

new
Crea un nuevo gestor de conexiones de mantenimiento. Un programa puede contener varios gestores de conexiones. Cada uno operará independientemente de los demás. Ninguno sabrá sobre los límites establecidos en los otros, por lo que es posible sobrecargar los descriptores de archivo de un proceso si no se tiene cuidado.

new() toma hasta cinco parámetros. Todos son opcionales.

Para limitar el número de conexiones simultáneas a un host particular (definido por una combinación de esquema, dirección y puerto):

max_per_host => $max_conexiones_simultaneas_por_host, # por defecto es 4

Para limitar el número total de conexiones que pueden estar abiertas a la vez, use

max_open     => $max_conexiones_abiertas, # por defecto es 128

Los programas deben devolver las conexiones al gestor cuando hayan terminado. Consulte el método free() para ver cómo funciona eso. El gestor de conexiones mantendrá las conexiones activas durante un período de tiempo antes de reciclarlas. El tiempo máximo de mantenimiento se puede establecer con

keep_alive   => $segundos_para_mantener_conexiones_libres_activas, # por defecto es 15

Los programas pueden no querer esperar mucho tiempo para que se establezca una conexión. Pueden establecer el tiempo de espera de la solicitud para alterar cuánto tiempo el componente mantiene una solicitud antes de generar un error.

timeout      => $segundos_para_procesar_una_solicitud, # por defecto es 120

Especifique un bind_address para enlazar todos los sockets de cliente a una dirección local particular. El valor de bind_address se pasará directamente a POE::Wheel::SocketFactory. Consulte la documentación de ese módulo para ver los detalles de implementación.

allocate
Asigna una nueva conexión. Allocate() devolverá un ID de solicitud inmediatamente. La conexión asignada, sin embargo, se publicará de vuelta a la sesión solicitante. Esto ocurre incluso si la conexión se encontró en la caché de mantenimiento de conexión del componente. Es un poco más lento, pero los casos de uso son más limpios de esa manera.

Allocate() requiere cinco parámetros y tiene un sexto opcional.

Especifique el esquema que se utilizará para comunicarse en la conexión (típicamente http o https). El esquema es obligatorio, pero usted es libre de inventar algo aquí. Se utiliza internamente para diferenciar diferentes tipos de sockets (por ejemplo, ssl vs. texto plano) en la misma dirección y puerto.

scheme  => $esquema_de_conexion,

Solicite una conexión a una dirección y puerto particulares. La dirección y el puerto deben ser numéricos. Tanto la dirección como el puerto son obligatorios.

address => $direccion_remota,
port    => $puerto_remoto,

Especifique un nombre para el evento que se publicará cuando una respuesta asíncrona esté lista. Esto es, por supuesto, obligatorio.

event   => $evento_de_retorno,

Establezca el tiempo de espera de la conexión, en segundos. El gestor de conexiones publicará un mensaje de error si no puede establecer una conexión dentro del tiempo solicitado. Este parámetro es opcional. Por defecto, será el tiempo de espera maestro proporcionado al constructor del gestor de conexiones.

timeout => $tiempo_de_espera_de_conexion,

Especifique datos contextuales adicionales. El contexto define el propósito de la conexión. Se utiliza para mantener la continuidad entre una llamada a allocate() y una respuesta asíncrona. Un contexto es extremadamente útil, pero es opcional.

context => $datos_contextuales,

En resumen:

$mgr->allocate(
  scheme   => "http",
  address  => "127.0.0.1",
  port     => 80,
  event    => "got_a_connection",
  context  => \%connection_context,
);

El evento de respuesta ("got_a_connection" en este ejemplo) contiene varios campos, pasados como una lista de pares clave/valor. La lista puede asignarse a un hash para mayor comodidad:

sub got_a_connection {
  my %response = @_[ARG0..$#_];
  ...;
}

Cuatro de los campos existen para repetir sus datos:

$response{address}    = $direccion_solicitada_por_ti;
$response{context}    = $contexto_solicitado_por_ti;
$response{port}       = $puerto_solicitado_por_ti;
$response{scheme}     = $esquema_solicitado_por_ti;

Un campo devuelve el objeto de conexión si la conexión fue exitosa, o undef si hubo un fallo:

$response{connection} = $nuevo_manejador_socket;

En caso de éxito, otro campo le dice si la conexión contiene material completamente nuevo. Es decir, si la conexión se ha reciclado de la caché del componente o se ha creado de nuevo.

$response{from_cache} = $estado;

El estado from_cache puede ser "immediate" si la conexión estuvo inmediatamente disponible en la caché. Será "deferred" si la conexión se reutilizó, pero otro usuario tuvo que liberarla primero. Finalmente, from_cache será falso si la conexión tuvo que crearse para satisfacer allocate().

Tres campos más devuelven información de error si la conexión falló. No están presentes si la conexión fue exitosa.

$response{function}   = $nombre_de_la_funcion_fallida;
$response{error_num}  = $! como número;
$response{error_str}  = $! como cadena;
free
Free() notifica al gestor de conexiones cuando las conexiones están libres para ser reutilizadas. Las conexiones liberadas se introducen en el pool de mantenimiento y pueden ser devueltas por llamadas posteriores a allocate(). 
$mgr->free($socket);

Por ahora, free() se llama con un socket, no con un objeto de conexión. Esto generalmente no es un problema, ya que los objetos POE::Component::Connection::Keepalive llaman a free() por usted cuando se destruyen.

No llamar a free() provocará que un programa filtre conexiones. Esto tampoco es generalmente un problema, ya que free() se llama automáticamente cada vez que se destruyen los objetos de conexión.

deallocate
Cancela una conexión que aún no se ha establecido. Requiere un parámetro, el ID de solicitud devuelto por allocate().
shutdown
El pool de mantenimiento requiere que las conexiones estén activas internamente. Esto puede mantener un programa activo incluso cuando todas las conexiones están inactivas. El método shutdown() le dice al gestor de conexiones que ya no necesita el pool y que puede terminar de forma segura.

POE::Component::Client::Keepalive(3pm)

NAME

POE::Component::Client::Keepalive - Un manejador de Keepalive para clientes POE

VERSION

0.272

SYNOPSIS

  use POE::Component::Client::Keepalive;

  # Crear un manejador
  my $mgr = POE::Component::Client::Keepalive->new (
    # Opciones de configuración, ver abajo
  );

  # Configurar la información de la conexión
  $mgr->register (
    Host    => 'localhost',
    Port    => 8080,
    # ... otras opciones para POE::Component::Client::TCP
  );

  # Empezar el bucle de eventos POE
  POE::Kernel->run();

DESCRIPTION

Este componente proporciona un manejador para gestionar de forma transparente las conexiones de cliente de tipo Keepalive (mantener viva la conexión) en POE. Se basa en POE::Component::Client::TCP, y añade la capacidad de volver a conectar automáticamente y de detectar y solucionar problemas con las conexiones de red que se quedan colgadas.

Este componente está diseñado para usarse con servidores que no cierran las conexiones con los clientes de forma proactiva, pero que se pueden quedar "colgados" si la conexión de red subyacente cae. El objetivo principal es mantener una conexión de red para que un cliente pueda enviar datos al servidor en cualquier momento, sin tener que preocuparse por volver a establecer la conexión cada vez.

Opciones de configuración para `new()`:

'interval'
El número de segundos que el componente esperará entre comprobaciones de la conexión. El valor por defecto es 5 segundos.
'timeout'
El número de segundos que el componente esperará a que una conexión se establezca antes de rendirse. El valor por defecto es 10 segundos.
'reconnect_delay'
El número de segundos que el componente esperará antes de intentar volver a conectar después de que una conexión haya fallado. El valor por defecto es 30 segundos.
'connect_retries'
El número de intentos de conexión que se harán antes de desistir y esperar a `reconnect_delay`. El valor por defecto es 0 (intentos ilimitados).
'keepalive_interval'
Este es el intervalo en segundos entre pings para el servidor. Si el servidor no responde dentro de este tiempo, la conexión se considerará rota. El valor por defecto es 30 segundos.
'keepalive_timeout'
El número de segundos que se esperará por una respuesta del ping. Si no se recibe respuesta dentro de este tiempo, se considera que la conexión está rota. El valor por defecto es 5 segundos.

Opciones de configuración para `register()`:

Todas las opciones que se pasan a `POE::Component::Client::TCP->new()` también se pueden pasar a `register()`. Además, hay las siguientes opciones específicas:

'keepalive_sent'
Un código Perl (puede ser un string que contiene código, un arrayref de strings, o un coderef) que será ejecutado justo antes de que el componente envíe el paquete de "keepalive". Esto es útil si necesita enviar algún tipo de señal al servidor para mantener la conexión activa (por ejemplo, un carácter de control o un comando NOP).
'keepalive_success'
Un código Perl que se ejecutará cuando el servidor responda correctamente al paquete de "keepalive".
'keepalive_failure'
Un código Perl que se ejecutará si el servidor no responde al paquete de "keepalive" dentro del tiempo especificado. Esto puede ser útil para enviar notificaciones o realizar acciones de limpieza.

Eventos enviados por el componente:

'keepalive_sent'
Este evento se dispara cuando se envía el paquete de keepalive. Si se ha proporcionado una opción `keepalive_sent`, su código se ejecutará antes de este evento.
'keepalive_success'
Este evento se dispara cuando se recibe una respuesta exitosa del servidor al keepalive. Si se ha proporcionado una opción `keepalive_success`, su código se ejecutará antes de este evento.
'keepalive_failure'
Este evento se dispara cuando falla el keepalive (ya sea por timeout o por cierre de conexión). Si se ha proporcionado una opción `keepalive_failure`, su código se ejecutará antes de este evento.
'connection_established'
Este evento se dispara cuando se establece una conexión exitosa con el servidor.
'connection_failed'
Este evento se dispara cuando falla la conexión inicial o un intento de reconexión.
'connection_closed'
Este evento se dispara cuando la conexión con el servidor se cierra (ya sea de forma normal o inesperada).

Método `shutdown()`

El método shutdown() fuerza al gestor de conexiones a vaciar su grupo de keep-alive, permitiendo que un programa termine graciosamente.

$mgr->shutdown();
