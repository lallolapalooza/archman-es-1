NOMBRE

Pod::POM::Node - clase base para un nodo POM

SINOPSIS

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS @ACCEPT $EXPECT $ERROR );
@ATTRIBS =   ( indent => 4 );
@ACCEPT  = qw( over item begin for text verbatim );
$EXPECT  =  q( back );
package main;
my $list = Pod::POM::Node::Over->new(8);
$list->add('item', 'Primer Elemento');
$list->add('item', 'Segundo Elemento');

DESCRIPCIÓN

Esta documentación describe el funcionamiento interno del módulo Pod::POM::Node y ofrece una breve visión general de la relación entre este y sus clases derivadas. Está pensada más como una guía de los aspectos internos para hackers interesados que como documentación general para el usuario. Consulte Pod::POM para obtener información sobre el uso de los módulos.

Este módulo implementa un nodo de clase base que se subdivide para representar diferentes elementos dentro de un Modelo de Objeto Pod (Pod Object Model).

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );

La clase base implementa el método constructor new() para instanciar nuevos objetos nodo.

my $list = Pod::POM::Node::Over->new();

Las características de un nodo pueden especificarse definiendo ciertas variables en el paquete derivado. La lista @ATTRIBS puede usarse para denotar atributos que el nodo debe aceptar. En el caso de un nodo "=over", por ejemplo, se puede especificar un atributo "indent" que de otro modo tendría un valor predeterminado de 4.

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS $ERROR );
@ATTRIBS = ( indent => 4 );

El método new() ahora esperará un argumento para establecer el valor de indentación, o usará 4 como valor predeterminado si no se proporciona ningún argumento.

my $list = Pod::POM::Node::Over->new(8);    # indent: 8
my $list = Pod::POM::Node::Over->new( );    # indent: 4

Si el valor predeterminado no está definido, el argumento es obligatorio.

package Pod::POM::Node::Head1;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS $ERROR );
@ATTRIBS = ( title => undef );
package main;
my $head = Pod::POM::Node::Head1->new('Mi Título');

Si no se proporciona un argumento obligatorio, el constructor devolverá undef para indicar un fallo. La variable $ERROR en el paquete derivado se establece para contener una cadena con el formato "$type esperaba un $attribute".

# falla con error: "head1 esperaba un título"
my $head = Pod::POM::Node::Head1->new()
    || die $Pod::POM::Node::Head1::ERROR;

Para mayor comodidad, se puede llamar a la subrutina error() como un método de clase para recuperar este valor.

my $type = 'Pod::POM::Node::Head1';
my $head = $type->new()
    || die $type->error();

La variable de paquete @ACCEPT puede usarse para indicar los tipos de nodo que se permiten como hijos de un nodo.

package Pod::POM::Node::Head1;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS @ACCEPT $ERROR );
@ATTRIBS =   ( title => undef );
@ACCEPT  = qw( head2 over begin for text verbatim );

Luego se puede llamar al método add() en un nodo para agregar un nuevo nodo hijo como parte de su contenido.

$head->add('over', 8);

El primer argumento indica el tipo de nodo. Se examina la lista @ACCEPT para asegurar que el tipo de nodo hijo sea aceptable para el nodo padre. Si es válido, se llama al constructor de la clase de nodo hijo relevante, pasando cualquier argumento restante como atributos. Luego se devuelve el nuevo nodo.

my $list = $head->add('over', 8);

Se puede llamar al método error() en el nodo *padre* para recuperar cualquier error del constructor generado por el nodo *hijo*.

my $list = $head->add('over', 8);
die $head->error() unless defined $list;

Si el nodo hijo no es aceptable para el padre, el método add() devuelve una de las constantes IGNORE, REDUCE o REJECT, según se definen en Pod::POM::Constants. Estos valores de retorno son utilizados por el módulo analizador Pod::POM para implementar un analizador simple de desplazamiento/reducción.

En el caso más común, se devuelve IGNORE para indicar que el nodo padre no sabe nada sobre el nuevo nodo hijo. El analizador utiliza esto como una indicación de que debe retroceder en la pila de análisis hasta que encuentre un nodo que *acepte* este nodo hijo. A través de este mecanismo, el analizador puede terminar implícitamente ciertos bloques POD. Por ejemplo, un elemento de lista iniciado por una etiqueta "=item" *no* aceptará otra etiqueta "=item", sino que devolverá IGNORE. El analizador retrocederá hasta que encuentre el nodo "=over" que lo envuelve y que *sí* lo acepte. Por lo tanto, un nuevo "=item" termina implícitamente cualquier "=item" anterior.

La variable de paquete $EXPECT puede usarse para indicar un tipo de nodo que un padre espera que termine por sí mismo. Un nodo "=over", por ejemplo, siempre debe ser terminado por un "=back" coincidente. Cuando se realiza dicha coincidencia, el método add() devuelve REDUCE para indicar una terminación exitosa.

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS @ACCEPT $EXPECT $ERROR );
@ATTRIBS =   ( indent => 4 );
@ACCEPT  = qw( over item begin for text verbatim );
$EXPECT  =  q( back );
package main;
my $list = Pod::POM::Node::Over->new();
my $item = $list->add('item');
$list->add('back');                 # devuelve REDUCE

Si no se especifica un nodo hijo en la lista @ACCEPT o no coincide con ningún $EXPECT especificado, se devuelve REJECT. El nodo padre establece un error interno con el formato "$type esperaba un $expect terminador". El analizador utiliza esto para detectar etiquetas POD faltantes. En casi todos los casos, el analizador es lo suficientemente inteligente como para corregir la estructura incorrecta y degrada cualquier error a advertencias.

# falla con error 'over esperaba terminador back'
ref $list->add('head1', 'Mi Título')     # devuelve REJECT
    || die $list->error();

Cada nodo contiene un campo 'type' que contiene una cadena simple que indica el tipo de nodo, por ejemplo, 'head1', 'over', etc. Las variables de paquete $NODES y $NAMES (en la clase base) hacen referencia a hash de hashes que mapean estos nombres hacia y desde nombres de paquetes (por ejemplo, head1 <=> Pod::POM::Node::Head1).

print $list->{ type };      # 'over'

Se proporciona un método AUTOLOAD para acceder a dichos elementos internos para aquellos a quienes no les gusta violar la encapsulación de un objeto.

print $list->type();

Los nodos también contienen una lista 'content' (contenido), bendecida en la clase Pod::POM::Node::Content, que contiene el contenido (elementos hijos) del nodo. El método AUTOLOAD devuelve esto como una referencia de lista o como una lista de elementos dependiendo del contexto en el que se llama.

my $items = $list->content();
my @items = $list->content();

Cada nodo también contiene una lista de contenido para cada tipo de nodo hijo individual que puede aceptar.

my @items = $list->item();
my @text  = $list->text();
my @vtext = $list->verbatim();

El método present() se utiliza para presentar un nodo a través de una vista particular. Esto simplemente mapea el tipo de nodo a un método que luego se llama en el objeto de vista. Esto se conoce como 'doble despacho'.

my $view = 'Pod::POM::View::HTML';
print $list->present($view);

El nombre del método se construye a partir del tipo de nodo prefijado por 'view_'. Por lo tanto, lo siguiente es aproximadamente equivalente.

$list->present($view);
$view->view_list($list);

El beneficio del primero sobre el último es, por supuesto, que el llamador no necesita conocer o determinar el tipo del nodo. El nodo en sí está en la mejor posición para determinar qué tipo es.
