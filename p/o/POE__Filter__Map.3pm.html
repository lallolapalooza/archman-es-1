POE::Filter::Map(3) Documentación de Perl aportada por el usuario POE::Filter::Map(3)

NOMBRE

POE::Filter::Map - transforma la entrada y/o salida dentro de una pila de filtros

SINOPSIS

#!perl
use POE qw(
  Wheel::FollowTail
  Filter::Line Filter::Map Filter::Stackable
);
POE::Session->create(
  inline_states => {
    _start => sub {
      my $parse_input_as_lines = POE::Filter::Line->new();
      my $redact_some_lines = POE::Filter::Map->new(
        Code => sub {
          my $input = shift;
          $input = "[REDACTED]" unless $input =~ /sudo\[\d+\]/i;
          return $input;
        },
      );
      my $filter_stack = POE::Filter::Stackable->new(
        Filters => [
          $parse_input_as_lines, # primero en get, último en put
          $redact_some_lines, # primero en put, último en get
        ]
      );
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        Filter => $filter_stack,
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPCIÓN

POE::Filter::Map transforma datos dentro de la pila de filtros. Puede ser usado para transformar la entrada, la salida, o ambas, dependiendo de cómo se construya. Este filtro se llama y modela basándose en la función incorporada map() de Perl.

POE::Filter::Map está diseñado para ser combinado con otros filtros a través de POE::Filter::Stackable. En el ejemplo de la "SINOPSIS", se crea una pila de filtros para analizar logs como líneas y para redactar todas las entradas que no pertenezcan a un proceso sudo.

MÉTODOS PÚBLICOS DEL FILTRO

Además de los métodos habituales de POE::Filter, POE::Filter::Map también soporta los siguientes.

new

new() construye un nuevo objeto POE::Filter::Map. Debe ser llamado con un único parámetro Code, o con ambos parámetros Put y Get. Los valores para Code, Put y Get son referencias de código que, al ser invocadas, devuelven versiones transformadas de sus únicos parámetros. Una función Code se usará tanto para la entrada como para la salida, mientras que las funciones Get y Put permiten que la entrada y la salida se filtren de diferentes maneras.

# Descifrar rot13.
sub decrypt_rot13 {
  my $encrypted = shift;
  $encrypted =~ tr[a-zA-Z][n-za-mN-ZA-M];
  return $encrypted;
}
# Cifrar rot13.
sub encrypt_rot13 {
  my $plaintext = shift;
  $plaintext =~ tr[a-zA-Z][n-za-mN-ZA-M];
  return $plaintext;
}
# Descifrar rot13 en la entrada, y cifrarla en la salida.
my $rot13_transcrypter = POE::Filter::Map->new(
  Get => \&decrypt_rot13,
  Put => \&encrypt_rot13,
);

Rot13 es simétrico, por lo que el ejemplo anterior puede simplificarse para usar una única función Code.

my $rot13_transcrypter = POE::Filter::Map->new(
  Code => sub {
    local $_ = shift;
    tr[a-zA-Z][n-za-mN-ZA-M];
    return $_;
  }
);

modify

modify() cambia el comportamiento de un objeto POE::Filter::Map en tiempo de ejecución. Acepta los mismos parámetros que new() y reemplaza las transformaciones existentes por otras nuevas.

# Cambiar a cifrado "inverso" para pruebas.
$rot13_transcrypter->modify(
  Code => sub { return scalar reverse shift }
);
