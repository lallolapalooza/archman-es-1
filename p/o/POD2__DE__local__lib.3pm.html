POD2::DE::local::lib(3) Documentación de Perl de Contribución de Usuarios POD2::DE::local::lib(3)

NOMBRE

local::lib~[de] - Crear y usar módulos de Perl en un directorio lib/ local con PERL5LIB

SINOPSIS

En el código -

use local::lib; # Usa el directorio ~/perl5 para crear el directorio lib/ local
use local::lib '~/foo'; # lo mismo, pero con ~/foo
# O...
use FindBin;
use local::lib "$FindBin::Bin/../soporte";  # Colección de módulos específica de la aplicación

Desde la shell -

# Instala LWP y todas las dependencias necesarias en el directorio '~/perl5'
perl -MCPAN -Mlocal::lib -e 'CPAN::install(LWP)'
# Imprime los comandos de la shell para preparar el entorno
$ perl -Mlocal::lib
export PERL_MB_OPT='--install_base /home/nombre_usuario/perl5'
export PERL_MM_OPT='INSTALL_BASE=/home/nombre_usuario/perl5'
export PERL5LIB='/home/nombre_usuario/perl5/lib/perl5/i386-linux:/home/nombre_usuario/perl5/lib/perl5'
export PATH="/home/nombre_usuario/perl5/bin:$PATH"

El método de Arrancamiento

Una forma típica de usar local::lib es el llamado método de "Arrancamiento". Este método se usa cuando todavía no hay local::lib instalado en el sistema. En este caso, puedes instalar local::lib directamente en tu directorio de inicio.

Incluso si tienes derechos administrativos, es importante que las variables de entorno del paso 4 se establezcan en tu script de inicio de shell. Sin este paso, los módulos de CPAN seguirán instalándose en el sistema, y los scripts de Perl que ejecutes tampoco usarán el directorio lib/ creado por local::lib.

Por defecto, local::lib se instala en ~/perl5.

Los usuarios de Windows también deben leer esto: "Diferencias al usar este módulo con Win32".

1. Descarga el archivo Tar de CPAN (busca "Descargar" en la página CPAN de local::lib) y descomprímelo en cualquier directorio. Para evitar el problema anterior, debes hacerlo como usuario normal y no como root o administrador.

2. Ejecuta el siguiente comando en el directorio creado:

perl Makefile.PL --bootstrap

Si el sistema te sugiere configurar ciertas cosas automáticamente, en casi todos los casos está perfectamente bien responder "yes".

Si no quieres instalar local::lib en el directorio predeterminado, debes especificar ese directorio como parámetro:

perl Makefile.PL --bootstrap=~/foo

3. Luego, ejecuta el siguiente comando: (local::lib espera que `make` esté disponible en el sistema)

make test && make install

4. Ahora debemos establecer las variables de entorno necesarias para que Perl use nuestro directorio lib/ recién generado. Si usas bash u otra shell de Bourne, puedes añadirlo a tu script de inicio de shell de la siguiente manera:

echo 'eval $(perl -I$HOME/perl5/lib/perl5 -Mlocal::lib)' >>~/.bashrc

Si usas C shell, puedes lograr lo mismo con:

/bin/csh
echo $SHELL
/bin/csh
perl -I$HOME/perl5/lib/perl5 -Mlocal::lib >> ~/.cshrc

Si usaste un directorio diferente al predeterminado durante el arrancamiento, debes especificar ese directorio como parámetro al cargar el módulo local::lib:

echo 'eval $(perl -I$HOME/foo/lib/perl5 -Mlocal::lib=$HOME/foo)' >>~/.bashrc

Después de realizar estos cambios en tu script de inicio de shell, es importante que estas variables de entorno también se establezcan en tu entorno actual. En shells de Bourne, esto se hace, por ejemplo, con ". ~/.bashrc", y en C shell se haría con "source ~/.cshrc".

Si tienes un sistema muy lento o vives bajo regulaciones draconianas de espacio en disco, puedes desactivar la generación automática de las páginas de manual a partir del POD al instalar el módulo durante el arrancamiento con el parámetro "--no-manpages":

perl Makefile.PL --bootstrap --no-manpages

Para evitar tener que hacer múltiples arrancamientos para, por ejemplo, usar instalaciones de local::lib propias para diferentes aplicaciones, puedes usar uno de estos entornos para instalar módulos simplemente en cualquier otro directorio y así obtener entornos lib/ independientes adicionales:

cd ~/mydir1
perl -Mlocal::lib=./
eval $(perl -Mlocal::lib=./)  ### Para establecer las variables de entorno
                              ### para la shell actual
printenv                      ### Aquí puedes ver que ~/mydir1
                              ### está en la variable de entorno PERL5LIB
perl -MCPAN -e install ...    ### los módulos que sean ...
cd ../mydir2
... REPETIR ...

Para múltiples entornos de esta forma, necesitas una modificación en el uso de "use FindBin" en el ejemplo "En el código" de arriba. Si haces esto, y has instalado módulos de Perl, por ejemplo, en "~/mydir1/lib", y tienes un script en "~/mydir1/scripts/myscript.pl", debes indicar allí que los módulos que necesita están en el directorio "~/mydir1/lib".

En "~/mydir1/scripts/myscript.pl" dirá entonces:

use strict;
use warnings;
use local::lib "$FindBin::Bin/..";  ### apunta a ~/mydir1 y local::lib
                                    ### encuentra lib allí
use lib "$FindBin::Bin/../lib";     ### apunta a ~/mydir1/lib

Coloca esto antes de cada bloque BEGIN { ... } que necesite los módulos que has instalado.

Diferencias al Usar este Módulo con Win32

Para establecer las variables de entorno necesarias para estas variables en la sesión actual con "CMD.EXE", puedes usar el siguiente comando:

C:\>perl -Mlocal::lib
set PERL_MB_OPT=--install_base C:\DOCUME~1\ADMINI~1\perl5
set PERL_MM_OPT=INSTALL_BASE=C:\DOCUME~1\ADMINI~1\perl5
set PERL5LIB=C:\DOCUME~1\ADMINI~1\perl5\lib\perl5;C:\DOCUME~1\ADMINI~1\perl5\lib\perl5\MSWin32-x86-multi-thread
set PATH=C:\DOCUME~1\ADMINI~1\perl5\bin;%PATH%
### Para establecer las variables de entorno para esta shell solamente
C:\>perl -Mlocal::lib > %TEMP%\tmp.bat && %TEMP%\tmp.bat && del %TEMP%\temp.bat
### en lugar de $(perl -Mlocal::lib=./) en bash.

Si quieres que las variables de entorno se establezcan permanentemente, debes introducirlas tú mismo permanentemente en el Panel de Control / Sistema o usar App::local::lib::Win32Helper.

El carácter "~" se traduce al directorio del perfil del usuario (el directorio que se conoce como "Documentos y Configuración" en los usuarios de Windows XP y anteriores, o el directorio "Usuario" en Windows Vista y posteriores), a menos que $ENV{HOME} esté establecido. El directorio se convierte aquí al nombre corto correcto, por lo que debe existir definitivamente, y se expande con los subdirectorios necesarios.

PRINCIPIO FUNDAMENTAL

Las versiones de los paquetes de Perl que se necesitan para tareas específicas a menudo no son las versiones correctas o adecuadas preinstaladas en el sistema. Actualizar estos módulos a menudo simplemente no es posible porque faltan los permisos necesarios. Además, generalmente no es bueno reemplazar las versiones de los módulos en el sistema de forma independiente, porque, por supuesto, el resto del sistema espera la versión que fue instalada por la administración del sistema.

local::lib resuelve este problema, te permite tener tu propio directorio completo para tus módulos CPAN y así no estás obligado a usar los módulos del sistema, o viceversa, a obligar a otros usuarios a revisar su código con deseos individuales de módulos porque ciertos módulos se actualizan centralmente para todos a una versión más nueva. La instalación se realiza aquí, por ejemplo, en el directorio de inicio. Solo se establecen variables de entorno que hacen que el Perl instalado utilice los módulos instalados en el directorio de inicio, además y preferentemente.

DESCRIPCION

Este módulo proporciona una forma rápida y legítima de hacer un "arranque" para instalar una colección de módulos en el directorio personal de un usuario. También crea las variables de entorno necesarias para utilizar estos módulos, adaptándose al shell especificado por el usuario en la variable de entorno "SHELL", para que se inserten directamente en los archivos de configuración correspondientes del shell.

Además, local::lib es capaz de utilizar módulos que no están en la ruta estándar @INC de Perl. Esto facilita la instalación de un conjunto específico de módulos para ciertas aplicaciones sin afectar de ninguna manera a los demás módulos del sistema. Por ejemplo, esto permite instalar de forma más segura módulos que aún no están disponibles como versión oficial por parte del mantenedor.

Al importarlo, local::lib establece las siguientes variables de entorno a los valores necesarios:

PERL_MB_OPT
PERL_MM_OPT
PERL5LIB
PATH
Naturalmente, se añade al PATH, no se reemplaza.

Estos valores estarán disponibles para cualquier código que se importe posteriormente.

CREACION DE UNA COLECCION INDEPENDIENTE DE MODULOS

Con lib::core::only existe una forma de hacerlo, pero ten en cuenta que existen muchas trampas y problemas, y siempre se debe tener cuidado de basarse en un Perl que se haya modificado lo menos posible (es decir, con los directorios site y vendor lo más vacíos posible).

METODOS

ensure_dir_structure_for

Parametro: $path
Valor de retorno: Ninguno

Intenta crear el directorio especificado, con todos los directorios superiores necesarios. En caso de error, se lanzará una excepción.

print_environment_vars_for

Parametro: $path
Valor de retorno: Ninguno

Imprime las variables de entorno necesarias para utilizar la ruta especificada como directorio base.

build_environment_vars_for

Parametro: $path, $interpolate
Valor de retorno: \%variables_entorno

Devuelve un hash con las variables necesarias en las variables de entorno para utilizar una instalación en la ruta dada.

setup_env_hash_for

Parametro: $path
Valor de retorno: Ninguno

Establece las entradas de %ENV basándose en la llamada a "build_environment_vars_for".

install_base_perl_path

Parametro: $path
Valor de retorno: $ruta_instalacion_modulos

Devuelve la ruta que se utiliza para instalar módulos Perl basándose en la ruta dada como base. Principalmente, solo se añaden los elementos de ruta "lib" y "perl5".

install_base_arch_path

Parametro: $path
Valor de retorno: $ruta_instalacion_modulos_arquitectura

Devuelve la ruta que se utiliza para instalar módulos Perl dependientes de la arquitectura basándose en la ruta dada como base. Basándose en lo que devuelve "install_base_perl_path", este método añade el valor de $Config{archname}.

install_base_bin_path

Parametro: $path
Valor de retorno: $ruta_instalacion_programas_ejecutables

Devuelve la ruta donde se instalarán los programas ejecutables, basándose en la base de la ruta dada. Basándose en el valor de retorno de "install_base_perl_path", este método añade "bin".

resolve_empty_path

Parametro: $path
Valor de retorno: $ruta_base

Crea y devuelve la ruta que se utiliza como base para la instalación de los módulos. Por defecto, es "~/perl5".

resolve_home_path( $path )

Parametro: $path
Valor de retorno: $home

Intenta encontrar el directorio de inicio del usuario actual. Se lanzará una excepción si no se puede determinar el directorio de inicio.

resolve_relative_path

Parametro: $path
Valor de retorno: $ruta_absoluta

Convierte la ruta especificada en una ruta absoluta.

resolve_path

Parametro: $path
Valor de retorno: $ruta_absoluta

La ruta pasa a través de los siguientes métodos, donde el valor de retorno del primero se pasa al siguiente para configurar el entorno para la instalación de la biblioteca local: "resolve_empty_path", "resolve_home_path", "resolve_relative_path". El resultado se pasa a "resolve_empty_path", cuyo resultado se pasa a "resolve_home_path", cuyo resultado se pasa a "resolve_relative_path". Este resultado se pasa finalmente a "resolve_path", que proporciona el valor de retorno.

UNA ADVERTENCIA SOBRE UNINST=1

Cuando se utiliza local::lib en combinación con "make install UNINST=1", hay que tener cuidado con el hecho de que el proceso de reinstalación no tiene suficiente seguridad en cuanto a dónde debe instalar ahora. Por lo tanto, puede ocurrir que al desinstalar un módulo se desinstale inadvertidamente el módulo global (si se tienen los permisos necesarios), pero la nueva versión solo esté instalada en la versión local. Por lo tanto, es muy importante utilizar "make install UNINST=1" y local::lib solo simultáneamente si se está muy seguro de las consecuencias.

LIMITACIONES

Las herramientas de Perl utilizadas para instalar los paquetes (la llamada "toolchain") lamentablemente no son capaces de manejar correctamente los directorios que contienen espacios y, por lo tanto, no pueden instalar local::lib directamente en un directorio de este tipo. Lo que puedes hacer es mover todo el directorio a su destino *después* de instalar local::lib y los módulos que deseas tener en tu local::lib. local::lib puede manejar el directorio con espacios. Ten en cuenta que, por supuesto, la instalación o actualización posterior de paquetes con el programa CPAN ya no será posible.

La detección del shell es muy primitiva. Actualmente, todo lo que contiene "csh" en su nombre se clasifica como C shell, y todo lo demás se considera Bourne shell, excepto en sistemas Win32. Si la local::lib(3pm) — Arch Linux manual pages

NAME

local::lib - Make Perl modules install and import locally

SYNOPSIS

    # Set up your shell to use local::lib
    eval $(perl -Mlocal::lib)

    # Or, to set up for a specific directory:
    eval $(perl -Mlocal::lib=$HOME/perl5)

    # Or, to set up with a specific version of Perl:
    eval $(perl5.10 -Mlocal::lib)

    # Install a module into your local::lib directory
    cpan -i Some::Module
    perl -MSome::Module -e 'print "ok\n"'

    # Use the locally installed module
    perl my_script.pl

    # Set up a second local::lib directory, which will be used
    # in addition to the first one.
    eval $(perl -Mlocal::lib=$HOME/perl5.2)

    # Set up a third local::lib directory, which will be used
    # in addition to the first one.
    eval $(perl -Mlocal::lib=$HOME/perl5.3,append)

    # Set up the current directory, which will be used in addition
    # to previous ones.
    eval $(perl -Mlocal::lib, .)

GRUNDPRINZIP

local::lib ist ein Perl-Modul, das Perl veranlasst, seine Module lokal zu installieren und zu importieren, anstatt sie global zu installieren. Dies ist besonders nützlich, wenn Sie keine Administratorrechte haben, um Module in das globale Verzeichnis von Perl zu installieren. Es ermöglicht Ihnen auch, separate Sammlungen von Modulen für verschiedene Projekte zu haben.

BESCHREIBUNG

Dieses Modul macht zwei Hauptdinge:

  1. Es veranlasst Perl, Module in einem Verzeichnis zu installieren, das Sie bestimmen (standardmäßig $HOME/.perl oder $HOME/perl5).
  2. Es veranlasst Perl, Module aus diesem lokalen Verzeichnis zu importieren.

Dies geschieht durch Setzen der Umgebungsvariablen PERL5LIB, PERL_MM_OPT und PERL_MB_OPT. Wenn Sie eval $(perl -Mlocal::lib) in Ihrer Shell ausführen, wird Perl ausgeführt, um die notwendigen Umgebungsvariablen zu berechnen und auszugeben, und eval wird verwendet, um diese Variablen in Ihrer aktuellen Shell zu setzen.

ERSTELLEN EINES EIGENSTÄNDIGE SAMMLUNG VON MODULEN

Um eine eigene Sammlung von Modulen für ein bestimmtes Projekt zu erstellen, können Sie den Speicherort des Verzeichnisses angeben:

    eval $(perl -Mlocal::lib=$HOME/myproject/perl5)

Dies stellt sicher, dass alle Module, die Sie mit cpan installieren, in diesem Verzeichnis landen und von Perl gefunden werden.

Wenn Sie bereits eine local::lib-Umgebung eingerichtet haben und eine weitere hinzufügen möchten, ohne die vorherige zu ersetzen, können Sie die Option append verwenden:

    eval $(perl -Mlocal::lib=$HOME/another_perl5,append)

Sie können auch das aktuelle Verzeichnis verwenden, um Module lokal zu installieren:

    eval $(perl -Mlocal::lib, .)

METHODEN

Die Hauptmethode, die Sie verwenden werden, ist die Ausführung von perl -Mlocal::lib ... und die Auswertung der Ausgabe in Ihrer Shell. Dies setzt die erforderlichen Umgebungsvariablen, damit Perl lokale Module finden und installieren kann.

EINE WARNUNG VOR UNINST=1

Wenn Sie UNINST=1 als Option an ExtUtils::MakeMaker übergeben, wird local::lib das Deinstallieren von Modulen aus Ihrem lokalen Verzeichnis nicht korrekt behandeln. Dies liegt daran, dass local::lib nicht weiß, wo die Deinstallationsskripte installiert wurden.

EINSCHRÄNKUNGEN

Wenn die Umgebungsvariable "SHELL" nicht gesetzt ist, wird eine Bourne Shell angenommen.

Bootstrap ist leider ein Hack und wird in jedem Fall CPAN.pm für ExtUtils::MakeMaker verwenden, auch wenn CPANPLUS installiert ist.

Es setzt definitiv PERL5LIB, PERL_MM_OPT und PERL_MB_OPT neu und vernichtet jeden Wert, der vorher gesetzt war.

Es sollte vielleicht eine automatische Korrektur der CPAN Config machen, wenn das nicht schon gemacht wurde.

"Patches Welcome" - Patches sind immer willkommen beim Autor oder den anderen Mitwirkenden.

Auf Win32 Systemen werden die Umgebungsvariablen nicht direkt in die Registrierung geschrieben, damit sie auch nach dem Neustarten erhalten bleiben.

FEHLERANALYSE

Wenn Sie local::lib konfiguriert haben, CPAN Module in Ihrem Home Verzeichnis zu installieren, und Sie danach versuchen, mit "cpan -i Foo::Bar" ein Modul zu installieren und dabei einen Fehler bekommen, wie: "Warning: You do not have permissions to install into /usr/lib64/perl5/site_perl/5.8.8/x86_64-linux at /usr/lib64/perl5/5.8.8/Foo/Bar.pm" und in der Installationsausgabe steht irgendwo ein Fehler, der sagt "'INSTALL_BASE' is not a known MakeMaker parameter name", dann haben Sie aus irgendeinem Grund Ihre neue Version von ExtUtils::MakeMaker verloren.

Um dies zu korrigieren, lassen Sie einfach nochmal die Bootstrapping-Methode laufen, wie oben beschrieben.

Dann starten Sie "rm -r ~/.cpan/build/Foo-Bar*"

Abschließend dann nochmal mit "cpan -i Foo::Bar" installieren und die Probleme sollten verschwunden sein.

UMGEBUNGSVARIABLEN

SHELL
COMSPEC
local::lib schaut in die "SHELL" Umgebungsvariable, um die korrekten Befehle zur Shell-Konfiguration hinzuzufügen.

Auf Win32 Systemen wird "COMSPEC" auch analysiert.
