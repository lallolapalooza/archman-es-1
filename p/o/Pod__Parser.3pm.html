NOMBRE

Pod::Parser - clase base para crear filtros y traductores de POD

SINOPSIS

use Pod::Parser;
package MyParser;
@ISA = qw(Pod::Parser);
sub command { 
    my ($parser, $command, $paragraph, $line_num) = @_;
    ## Interpretar el comando y su texto; las acciones de ejemplo podrían ser:
    if ($command eq 'head1') { ... }
    elsif ($command eq 'head2') { ... }
    ## ... otros comandos y sus acciones
    my $out_fh = $parser->output_handle();
    my $expansion = $parser->interpolate($paragraph, $line_num);
    print $out_fh $expansion;
}
sub verbatim { 
    my ($parser, $paragraph, $line_num) = @_;
    ## Formatear párrafo literal; las acciones de ejemplo podrían ser:
    my $out_fh = $parser->output_handle();
    print $out_fh $paragraph;
}
sub textblock { 
    my ($parser, $paragraph, $line_num) = @_;
    ## Traducir/Formatear este bloque de texto; las acciones de ejemplo podrían ser:
    my $out_fh = $parser->output_handle();
    my $expansion = $parser->interpolate($paragraph, $line_num);
    print $out_fh $expansion;
}
sub interior_sequence { 
    my ($parser, $seq_command, $seq_argument) = @_;
    ## Expandir una secuencia interior; las acciones de ejemplo podrían ser:
    return "*$seq_argument*"     if ($seq_command eq 'B');
    return "`$seq_argument'"     if ($seq_command eq 'C');
    return "_${seq_argument}_'"  if ($seq_command eq 'I');
    ## ... otros comandos de secuencia y su texto resultante
}
package main;
## Crear un objeto parser y hacer que analice el archivo cuyo nombre fue
## dado en la línea de comandos (usar STDIN si no se dieron archivos).
$parser = new MyParser();
$parser->parse_from_filehandle(\*STDIN)  if (@ARGV == 0);
for (@ARGV) { $parser->parse_from_file($_); }

REQUIERE

perl5.005, Pod::InputObjects, Exporter, Symbol, Carp

EXPORTA

Nada.

DESCRIPCIÓN

NOTA: Este módulo se considera obsoleto; las versiones modernas de Perl (5.31.1 y superiores) eliminarán Pod-Parser del núcleo y utilizarán Pod::Simple para todas las cosas de POD.

Pod::Parser es una clase base para crear filtros y traductores de POD. Maneja la mayor parte del esfuerzo involucrado en el análisis de las secciones POD de un flujo de entrada, dejando que las subclases se preocupen únicamente de realizar la traducción real del texto.

Pod::Parser analiza los POD y realiza llamadas a métodos para manejar los diversos componentes del POD. Las subclases de Pod::Parser anulan estos métodos para traducir el POD al formato de salida que deseen.

RESUMEN RÁPIDO

Para crear un filtro de POD para traducir documentación POD a algún otro formato, se crea una subclase de Pod::Parser que típicamente anula solo la implementación de la clase base para los siguientes métodos:

  • command()
  • verbatim()
  • textblock()
  • interior_sequence()

También podría querer anular los métodos begin_input() y end_input() para su subclase (para realizar cualquier inicialización o limpieza necesaria por archivo y/o por documento).

Si necesita realizar algún preprocesamiento de la entrada antes de que se analice, podría querer anular uno o más de preprocess_line() y/o preprocess_paragraph().

A veces puede ser necesario realizar más de un pase sobre los archivos de entrada. Si este es el caso, tiene varias opciones. Puede hacer el primer pase usando Pod::Parser y anular sus métodos para almacenar los resultados intermedios en memoria en algún lugar para que el método end_pod() los procese. Podría usar Pod::Parser para varios pases con una variable de estado apropiada para controlar la operación en cada pase. Si la fuente de entrada no se puede restablecer para comenzar desde el principio, puede almacenarla en alguna otra estructura como una cadena de texto o un array y hacer que esa estructura implemente un método getline() (que es todo lo que usa parse_from_filehandle() para leer la entrada).

Siéntase libre de agregar cualquier campo de datos de miembro que necesite para llevar un registro de cosas como la fuente actual, la indentación, la posición horizontal o vertical, o cualquier otra cosa que desee. Asegúrese de leer "MÉTODOS Y DATOS PRIVADOS" para evitar colisiones de nombres.

En su mayor parte, la clase base Pod::Parser debería ser capaz de hacer la mayor parte del análisis de entrada por usted y dejarle libre para preocuparse de cómo interpretar los comandos y traducir el resultado.

Tenga en cuenta que todo lo que hemos descrito aquí en este resumen rápido es el uso más simple y directo de Pod::Parser para realizar un análisis basado en flujos. También es posible usar la función Pod::Parser::parse_text para realizar un análisis más sofisticado basado en árboles. Consulte "ANÁLISIS BASADO EN ÁRBOLES".

OPCIONES DE ANÁLISIS

Una opción-de-análisis es simplemente una opción nombrada de Pod::Parser con un valor que corresponde a un cierto comportamiento especificado. Estos diversos comportamientos de Pod::Parser pueden ser habilitados/deshabilitados estableciendo o desestableciendo una o más opciones-de-análisis usando el método parseopts(). El conjunto de opciones de análisis actualmente aceptadas es el siguiente:

-want_nonPODs (predeterminado: desestablecido)
Normalmente (por defecto) Pod::Parser solo proporcionará acceso a las secciones POD de la entrada. Los párrafos de entrada que no forman parte de la documentación en formato POD no están disponibles para el llamador (ni siquiera usando preprocess_paragraph()). Establecer esta opción a un valor no vacío y distinto de cero permitirá que preprocess_paragraph() vea secciones no POD de la entrada, así como secciones POD. El método cutting() se puede usar para determinar si el párrafo correspondiente es un párrafo POD o algún otro párrafo de entrada.
-process_cut_cmd (predeterminado: desestablecido)
Normalmente (por defecto) Pod::Parser maneja la directiva POD "=cut" por sí mismo y no la pasa al llamador para su procesamiento. Establecer esta opción a un valor no vacío y distinto de cero hará que Pod::Parser pase la directiva "=cut" al llamador como cualquier otro comando POD (y por lo tanto puede ser procesado por el método command()).

Pod::Parser aún interpretará la directiva "=cut" para significar que se ha entrado (o reentrado) en el modo de "corte", pero el llamador tendrá la oportunidad de capturar el párrafo "=cut" real para cualquier propósito que desee.

-warnings (predeterminado: desestablecido)
Normalmente (por defecto) Pod::Parser reconoce un mínimo de errores y advertencias de sintaxis de pod y emite mensajes de diagnóstico para los errores, pero no para las advertencias. (Use Pod::Checker para realizar una verificación más exhaustiva de la sintaxis POD.) Establecer esta opción a un valor no vacío y distinto de cero hará que Pod::Parser emita diagnósticos para las pocas advertencias que reconoce, así como para los errores.

Por favor, consulte "parseopts()" para una descripción completa de la interfaz para establecer y desestablecer opciones de análisis.

SOBREESCRITURAS RECOMENDADAS DE SUBRUTINAS/MÉTODOS

Pod::Parser proporciona varios métodos que la mayoría de las subclases probablemente querrán anular. Estos métodos son los siguientes:

command()

$parser->command($cmd,$text,$line_num,$pod_para);

Este método debe ser anulado por las subclases para tomar la acción apropiada cuando se encuentra un párrafo de comando POD (denotado por una línea que comienza con "="). Cuando se ve una directiva POD de este tipo en la entrada, se llama a este método y se le pasa:

$cmd
el nombre del comando para este párrafo POD
$text
el texto del párrafo para el comando de párrafo POD dado.
$line_num
el número de línea del inicio del párrafo
$pod_para
una referencia a un objeto "Pod::Paragraph" que contiene más información sobre el comando del párrafo (consulte Pod::InputObjects para obtener detalles).

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

="Pp">Nota que este método se llama para párrafos de "=pod".

verbatim()

$parser->verbatim($text,$line_num,$pod_para);

Este método puede ser sobrescrito por las subclases para tomar la acción apropiada cuando se encuentra un bloque de texto literal. Se le pasan los siguientes parámetros:

$text
el bloque de texto para el párrafo literal
$line_num
el número de línea del inicio del párrafo
$pod_para
una referencia a un objeto "Pod::Paragraph" que contiene información adicional sobre el párrafo (ver Pod::InputObjects para más detalles).

La implementación de la clase base de este método simplemente imprime el bloque de texto (sin modificar) en el manejador de archivo de salida.

textblock()

$parser->textblock($text,$line_num,$pod_para);

Este método puede ser sobrescrito por las subclases para tomar la acción apropiada cuando se encuentra un bloque normal de texto POD (aunque el método de la clase base usualmente hará lo que usted desea). Se le pasan los siguientes parámetros:

$text
el bloque de texto para un párrafo POD
$line_num
el número de línea del inicio del párrafo
$pod_para
una referencia a un objeto "Pod::Paragraph" que contiene información adicional sobre el párrafo (ver Pod::InputObjects para más detalles).

Para procesar secuencias interiores, las implementaciones de las subclases de este método probablemente querrán invocar interpolate() o parse_text(), pasándole el bloque de texto $text, y el número de línea correspondiente en $line_num, y luego realizar cualquier procesamiento deseado sobre el resultado devuelto.

La implementación de la clase base de este método simplemente imprime el bloque de texto tal como apareció en el flujo de entrada).

interior_sequence()

$parser->interior_sequence($seq_cmd,$seq_arg,$pod_seq);

Este método debe ser sobrescrito por las subclases para tomar la acción apropiada cuando se encuentra una secuencia interior. Una secuencia interior es un comando incrustado dentro de un bloque de texto que aparece como un nombre de comando (generalmente un solo carácter en mayúscula) seguido inmediatamente por una cadena de texto encerrada entre corchetes angulares. Este método recibe el comando de secuencia $seq_cmd y el texto correspondiente $seq_arg. Es invocado por el método interpolate() por cada secuencia interior que ocurre en la cadena que se le pasa. Debería devolver la cadena de texto deseada para ser usada en lugar de la secuencia interior. El argumento $pod_seq es una referencia a un objeto "Pod::InteriorSequence" que contiene información adicional sobre la secuencia interior. Por favor, consulte Pod::InputObjects para detalles si necesita acceder a esta información adicional.

Las implementaciones de subclases de este método pueden desear invocar el método nested() de $pod_seq para ver si está anidado dentro de alguna otra secuencia interior (y si es así, cuál).

La implementación de la clase base del método interior_sequence() simplemente devuelve el texto crudo de la secuencia interior (tal como apareció en la entrada) al llamador.

SOBRESCRITURAS OPCIONALES DE SUBRUTINAS/MÉTODOS

Pod::Parser proporciona varios métodos que las subclases pueden querer sobrescribir para realizar cualquier pre/post-procesamiento especial. Estos métodos no tienen que ser sobrescritos, pero puede ser útil para las subclases aprovecharlos.

new()

my $parser = Pod::Parser->new();

Este es el constructor para Pod::Parser y sus subclases. ¡Usted no necesita sobrescribir este método! Es capaz de construir objetos de subclases así como objetos de la clase base, siempre que utilice cualquiera de los siguientes estilos de invocación del constructor:

my $parser1 = MyParser->new();
my $parser2 = new MyParser();
my $parser3 = $parser2->new();

donde "MyParser" es alguna subclase de Pod::Parser.

Usar la sintaxis MyParser::new() para invocar el constructor no es recomendado, pero si insiste en poder hacerlo, entonces la subclase necesitará sobrescribir el método constructor new(). Si sobrescribe el constructor, debe asegurarse de invocar el método initialize() del objeto recién bendecido.

Usando cualquiera de las invocaciones anteriores, el primer argumento para el constructor es siempre el nombre del paquete correspondiente (o referencia de objeto). No se requieren otros argumentos, pero si se desea, se puede pasar un array asociativo (o tabla hash) al constructor new(), como en:

my $parser1 = MyParser->new( MYDATA => $value1, MOREDATA => $value2 );
my $parser2 = new MyParser( -myflag => 1 );

Todos los argumentos pasados al constructor new() serán tratados como pares clave/valor en una tabla hash. El objeto recién construido será inicializado copiando el contenido de la tabla hash dada (que puede haber estado vacía). El constructor new() para esta clase y todas sus subclases devuelve una referencia bendecida al objeto inicializado (tabla hash).

initialize()

$parser->initialize();

Este método realiza cualquier inicialización de objeto necesaria. No toma argumentos (aparte de la instancia del objeto por supuesto, que típicamente se copia a una variable local llamada $self). Si las subclases sobrescriben este método entonces deben asegurarse de invocar "$self->SUPER::initialize()".

begin_pod()

$parser->begin_pod();

Este método es invocado al inicio del procesamiento de cada documento POD que se encuentra en la entrada. Las subclases deben sobrescribir este método para realizar cualquier inicialización por documento.

begin_input()

$parser->begin_input();

Este método es invocado por parse_from_filehandle() inmediatamente antes de procesar la entrada de un manejador de archivo. La implementación de la clase base no hace nada; sin embargo, las subclases pueden sobrescribirlo para realizar cualquier inicialización por archivo.

Tenga en cuenta que si se analizan varios archivos para un solo documento POD (quizás como resultado de alguna futura directiva "=include"), este método se invoca por cada archivo que se analiza. Si desea realizar ciertas inicializaciones una vez por documento, entonces debería usar begin_pod().

end_input()

$parser->end_input();

Este método es invocado por parse_from_filehandle() inmediatamente después de procesar la entrada de un manejador de archivo. La implementación de la clase base no hace nada; sin embargo, las subclases pueden sobrescribirlo para realizar cualquier acción de limpieza por archivo.

Tenga en cuenta que si se analizan varios archivos para un solo documento POD (quizás como resultado de algún tipo de directiva "=include"), este método se invoca por cada archivo que se analiza. Si desea realizar ciertas acciones de limpieza una vez por documento, entonces debería usar end_pod().

end_pod()

$parser->end_pod();

Este método es invocado al final del procesamiento de cada documento POD que se encuentra en la entrada. Las subclases deben sobrescribir este método para realizar cualquier finalización por documento.

preprocess_line()

$textline = $parser->preprocess_line($text, $line_num);

Este método debe ser sobrescrito por las subclases que deseen realizar cualquier tipo de preprocesamiento para cada línea de entrada (antes de que se determine si forma parte o no de un párrafo POD). El parámetro $text es la línea de entrada; y el parámetro $line_num es el número de línea del texto correspondiente.

El valor devuelto debe corresponder al nuevo texto que se usará en su lugar. Si se devuelve una cadena vacía o un valor indefinido, no se realizará ningún procesamiento adicional para esta línea.

Tenga en cuenta que el método preprocess_line() se invoca antes del método preprocess_paragraph(). Después de que todas las líneas (posiblemente preprocesadas) en un párrafo se juntan y se determina que el párrafo es parte de la documentación POD de una de las secciones seleccionadas, entonces se invoca preprocess_paragraph().

La implementación de la clase base de este método devuelve el texto proporcionado.

preprocess_paragraph()

$textblock = $parser->preprocess_paragraph($text, $line_num);

Este método debe ser sobrescrito por las subclases que deseen realizar cualquier tipo de preprocesamiento para cada bloque (párrafo) de documentación POD que aparezca en el flujo de entrada. El parámetro $text es el párrafo POD del archivo de entrada; y el parámetro $line_num es el número de línea del inicio del párrafo correspondiente.

El valor devuelto debe corresponder al nuevo texto que se usará en su lugar. Si se devuelve una cadena vacía o un valor indefinido, el $text proporcionado se ignora (no se procesa).

Este método se invoca después de recopilar todas las líneas de un párrafo y después de determinar el estado de corte del párrafo, pero antes de intentar analizarlos o interpretarlos más a fondo. Después de que preprocess_paragraph() devuelve, se examina el estado de corte actual (que es devuelto por "$self->cutting()"). Si se evalúa como verdadero, entonces el texto de entrada (incluido el $text proporcionado) se corta (no se procesa) hasta que se encuentre la próxima directiva POD.

Tenga en cuenta que el método preprocess_line() se invoca antes del método preprocess_paragraph(). Después de que todas las líneas (posiblemente preprocesadas) en un párrafo se juntan y se determina que el párrafo es parte de la documentación POD de una de las secciones seleccionadas o que el "-want_nonPODs&q

preprocess_paragraph() se invoca.

La implementación de la clase base de este método devuelve el texto dado.

MÉTODOS PARA ANÁLISIS Y PROCESAMIENTO

Pod::Parser proporciona varios métodos para procesar texto de entrada. Estos métodos típicamente no necesitarán ser anulados (y en algunos casos no se pueden anular), pero las subclases pueden querer invocarlos para aprovechar su funcionalidad.

parse_text()

$ptree1 = $parser->parse_text($text, $line_num);
$ptree2 = $parser->parse_text({%opts}, $text, $line_num);
$ptree3 = $parser->parse_text(\%opts, $text, $line_num);

Este método es útil si necesita realizar su propia interpolación de secuencias interiores y no puede confiar en interpolate para expandirlas en un orden simple de abajo hacia arriba.

El parámetro $text es una cadena o bloque de texto para analizar secuencias interiores; y el parámetro $line_num es el número de línea correspondiente al inicio de $text.

parse_text() analizará el texto dado en un árbol de análisis de "nodos" y secuencias interiores. Cada "nodo" en el árbol de análisis es una cadena de texto o un Pod::InteriorSequence. El resultado devuelto es un árbol de análisis de tipo Pod::ParseTree. Consulte Pod::InputObjects para obtener más información sobre Pod::InteriorSequence y Pod::ParseTree.

Si se desea, se puede especificar una referencia hash opcional como primer argumento para personalizar ciertos aspectos del árbol de análisis que se crea y se devuelve. El conjunto de palabras clave de opción reconocidas son:

-expand_seq => código-ref|nombre-de-método
Normalmente, el árbol de análisis devuelto por parse_text() contendrá un objeto "Pod::InteriorSequence" sin expandir para cada secuencia interior encontrada. Especificar -expand_seq le dice a parse_text() que "expanda" cada secuencia interior que vea invocando la función referenciada (o el método nombrado del objeto analizador) y usando el valor de retorno como el resultado expandido.

Si se proporcionó una referencia a una subrutina, se invoca como:

&$code_ref( $parser, $sequence )

y si se proporcionó un nombre de método, se invoca como:

$parser->method_name( $sequence )

donde $parser es una referencia al objeto analizador, y $sequence es una referencia al objeto de secuencia interior. [NOTA: Si se especifica el método interior_sequence(), entonces se invoca de acuerdo con la interfaz especificada en "interior_sequence()"].

-expand_text => código-ref|nombre-de-método
Normalmente, el árbol de análisis devuelto por parse_text() contendrá una cadena de texto por cada secuencia contigua de caracteres fuera de una secuencia interior. Especificar -expand_text le dice a parse_text() que "preprocese" cada cadena de texto que vea invocando la función referenciada (o el método nombrado del objeto analizador) y usando el valor de retorno como el resultado preprocesado (o "expandido"). [Tenga en cuenta que si el resultado es una secuencia interior, entonces *no* se expandirá según lo especificado por la opción -expand_seq; cualquier expansión recursiva de este tipo debe ser manejada por la rutina de devolución de llamada especificada.]

Si se proporcionó una referencia a una subrutina, se invoca como:

&$code_ref( $parser, $text, $ptree_node )

y si se proporcionó un nombre de método, se invoca como:

$parser->method_name( $text, $ptree_node )

donde $parser es una referencia al objeto analizador, $text es la cadena de texto encontrada, y $ptree_node es una referencia al nodo actual en el árbol de análisis (generalmente un objeto de secuencia interior o el nodo de nivel superior del árbol de análisis).

-expand_ptree => código-ref|nombre-de-método
En lugar de devolver un "Pod::ParseTree", pasa el árbol de análisis como argumento a la subrutina referenciada (o el método nombrado del objeto analizador) y devuelve el resultado en lugar del objeto de árbol de análisis.

Si se proporcionó una referencia a una subrutina, se invoca como:

&$code_ref( $parser, $ptree )

y si se proporcionó un nombre de método, se invoca como:

$parser->method_name( $ptree )

donde $parser es una referencia al objeto analizador, y $ptree es una referencia al objeto de árbol de análisis.

interpolate()

$textblock = $parser->interpolate($text, $line_num);

Este método traduce todo el texto (incluidas las secuencias interiores incrustadas) en la cadena de texto dada $text y devuelve el resultado interpolado. El parámetro $line_num es el número de línea correspondiente al inicio de $text.

interpolate() simplemente invoca un método privado para expandir recursivamente las secuencias interiores anidadas en orden de abajo hacia arriba (las secuencias más internas se expanden primero). Si hay una necesidad de expandir secuencias anidadas en un orden alternativo, use parse_text en su lugar.

parse_from_filehandle()

$parser->parse_from_filehandle($in_fh,$out_fh);

Este método toma un manejador de archivo de entrada (que se supone que ya está abierto para lectura) y lee todo el flujo de entrada buscando bloques (párrafos) de documentación POD para ser procesados. Si no se proporciona el primer argumento, se utiliza el manejador de archivo de entrada predeterminado "STDIN".

El parámetro $in_fh puede ser cualquier objeto que proporcione un método getline() para recuperar una sola línea de texto de entrada (por lo tanto, se podría usar un objeto envoltorio apropiado para analizar POD de una sola cadena o un array de cadenas).

Usando "$in_fh->getline()", se lee la entrada línea por línea y se ensambla en párrafos o "bloques" (que se separan por líneas que no contienen nada más que espacios en blanco). Para cada bloque de documentación POD encontrado, invocará un método para analizar el párrafo dado.

Si se proporciona un segundo argumento, debe corresponder a un manejador de archivo donde se enviará la salida (de lo contrario, el manejador de archivo de salida predeterminado es "STDOUT" si no se está utilizando ningún manejador de archivo de salida actualmente).

NOTA: Por razones de rendimiento, este método almacena en caché el flujo de entrada en la parte superior de la pila en una variable local. Cualquier intento de los clientes de cambiar el contenido de la pila durante el procesamiento mientras se ejecuta este método *no afectará* al flujo de entrada utilizado por la invocación actual de este método.

Este método no suele necesitar ser anulado por las subclases.

parse_from_file()

$parser->parse_from_file($filename,$outfile);

Este método toma un nombre de archivo y realiza lo siguiente:

  • abre los archivos de entrada y salida para lectura (creando los manejadores de archivo apropiados)
  • invoca el método parse_from_filehandle() pasándole los manejadores de archivo de entrada y salida correspondientes.
  • cierra los archivos de entrada y salida.

Si se proporciona el nombre de archivo de entrada especial "", "-" o "<&STDIN", se utiliza el manejador de archivo STDIN para la entrada (y no se realiza ninguna apertura o cierre). Si no se especifica ningún nombre de archivo de entrada, se asume "-". También se aceptan referencias a manejadores de archivo u objetos que admiten las operaciones normales de E/S (como "<$fh>" o "$fh-<Egt>getline<Egt"); los manejadores deben estar ya abiertos.

Si se proporciona un segundo argumento, debe ser el nombre del archivo de salida deseado. Si se proporciona el nombre de archivo de salida especial "-" o ">&STDOUT", se utiliza el manejador de archivo STDOUT para la salida (y no se realiza ninguna apertura o cierre). Si se proporciona el nombre de archivo de salida especial ">&STDERR", se utiliza el manejador de archivo STDERR para la salida (y no se realiza ninguna apertura o cierre). Si no se está utilizando ningún manejador de archivo de salida actualmente y no se especifica ningún nombre de archivo de salida, se asume "-". Alternativamente, también se aceptan referencias a manejadores de archivo u objetos que admiten las operaciones normales de E/S (como "print", por ejemplo, IO::String); el objeto debe estar ya abierto.

Este método no suele necesitar ser anulado por las subclases.

MÉTODOS ACCESORES

Los clientes de Pod::Parser deben utilizar los siguientes métodos para acceder a los campos de datos de instancia:

errorsub()

$parser->errorsub("nombre_metodo");
$parser->errorsub(\&warn_user);
$parser->errorsub(sub { print STDERR, @_ });

Especifica el método o subrutina a utilizar al imprimir mensajes de error sobre la sintaxis de POD. El método/subrutina proporcionado *debe* devolver VERDADERO al imprimir correctamente el mensaje. Si se proporciona "undef", se utiliza el builtin carp para emitir mensajes de error (este es el comportamiento predeterminado).

my $errorsub = $parser->errorsub()
my $errmsg = "¡Este es un mensaje de error!\n"
(ref $errorsub) and &{$errorsub}($errmsg)
    or (defined $errorsub) and $parser->$errorsub($errmsg)
        or  carp($errmsg);

Devuelve un nombre de método, o una referencia a la subrutina proporcionada por el usuario utilizada para imprimir mensajes de error. Devuelve "undef" si se utiliza el builtin carp para emitir mensajes de error (este es el comportamiento predeterminado).

cutting()

$boolean = $parser->cutting();

Devuelve el estado actual de "cutting": un escalar de valor booleano que se evalúa como verdadero si el texto del archivo de entrada está actualmente siendo "cortado" (lo que significa que *no* se considera parte del documento POD).

$parser->cutting($boolean);

Establece el estado actual de "cutting" al valor dado y devuelve el resultado.

parseopts()

Cuando se invoca sin argumentos adicionales, parseopts devuelve una tabla hash de todas las opciones de análisis actuales.

## Ver si estamos analizando secciones que no son POD, además de las POD
my %opts = $parser->parseopts();
$opts{'-want_nonPODs}' and print "-want_nonPODs\n";

Cuando se invoca con una única cadena, parseopts trata la cadena como el nombre de una opción de análisis y devuelve su valor correspondiente si existe (devuelve "undef" si no existe).

## ¿Pedimos ver los párrafos de '=cut'?
my $want_cut = $parser->parseopts('-process_cut_cmd');
$want_cut and print "-process_cut_cmd\n";

Cuando se invoca con múltiples argumentos, parseopts los trata como pares clave/valor y los nombres de las opciones de análisis especificados se establecen en los valores dados. Cualquier opción de análisis no especificada no se verá afectada.

## Restablecerlos a los valores predeterminados
$parser->parseopts(-warnings => 0);

Cuando se pasa una única referencia a hash, parseopts usa esa tabla hash para restablecer completamente las opciones de análisis existentes; todos los valores anteriores de las opciones de análisis se pierden.

## Restablecer todas las opciones a los valores predeterminados
$parser->parseopts( { } );

Consulte "OPCIONES DE ANÁLISIS" para obtener más información sobre el nombre y el significado de cada opción de análisis reconocida actualmente.

output_file()

$fname = $parser->output_file();

Devuelve el nombre del archivo de salida que se está escribiendo.

output_handle()

$fhandle = $parser->output_handle();

Devuelve el objeto de descriptor de archivo de salida.

input_file()

$fname = $parser->input_file();

Devuelve el nombre del archivo de entrada que se está leyendo.

input_handle()

$fhandle = $parser->input_handle();

Devuelve el objeto de descriptor de archivo de entrada actual.

MÉTODOS Y DATOS PRIVADOS

Pod::Parser utiliza varios métodos y campos de datos internos que los clientes no deberían necesitar ver ni usar. Para evitar colisiones de nombres para los datos y métodos del cliente, estos métodos y campos se discuten brevemente aquí. Los hackers decididos pueden obtener más información sobre ellos leyendo el código fuente de Pod::Parser.

Los campos de datos privados se almacenan en el objeto hash cuya referencia devuelve el constructor new() para esta clase. Los nombres de todos los métodos y campos de datos privados utilizados por Pod::Parser comienzan con un prefijo de "_" y coinciden con la expresión regular "/^_\w+$/".

ANÁLISIS BASADO EN ÁRBOLES

Si el análisis directo basado en flujos no satisface sus necesidades (como es probable que ocurra en tareas como la traducción de POD a lenguajes de marcado estructurado como HTML y XML), es posible que necesite adoptar el enfoque basado en árboles. En lugar de hacer todo en una sola pasada y llamar al método interpolate() para expandir secuencias en texto, puede ser deseable en su lugar crear un árbol de análisis utilizando el método parse_text() para devolver una estructura similar a un árbol que puede contener una lista ordenada de hijos (cada uno de los cuales puede ser una cadena de texto o una estructura similar a un árbol).

Preste especial atención a "MÉTODOS PARA ANÁLISIS Y PROCESAMIENTO" y a los objetos descritos en Pod::InputObjects. El primero describe los detalles complejos y los parámetros sobre cómo personalizar y extender el comportamiento de análisis de Pod::Parser. Pod::InputObjects proporciona varios objetos que pueden ser utilizados indistintamente como árboles de análisis. El más obvio es el objeto Pod::ParseTree. Define la interfaz y funcionalidad básicas que deben tener todas las cosas que intentan ser un árbol de análisis de POD. Un Pod::ParseTree se define de tal manera que cada "nodo" puede ser una cadena de texto o una referencia a otro árbol de análisis. Cada objeto Pod::Paragraph y cada objeto Pod::InteriorSequence también soportan la interfaz básica de árbol de análisis.

El método parse_text() toma un párrafo de texto dado y devuelve un árbol de análisis que contiene uno o más hijos, cada uno de los cuales puede ser una cadena de texto o un objeto InteriorSequence. También hay opciones de retrollamada que se pueden pasar a parse_text() para personalizar la forma en que expande o transforma las secuencias interiores, así como el resultado devuelto. Estas retrollamadas se pueden usar para crear un árbol de análisis con objetos hechos a medida (que pueden o no admitir la interfaz del árbol de análisis, dependiendo de cómo elija hacerlo).

Si desea convertir un documento POD completo en un árbol de análisis, ese proceso es bastante sencillo. El método parse_text() es la clave para hacerlo con éxito. Cada retrollamada de párrafo (es decir, los métodos polimórficos para los párrafos command(), verbatim() y textblock()) toma un objeto Pod::Paragraph como argumento. Cada objeto de párrafo tiene un método parse_tree() que se puede usar para obtener o establecer un árbol de análisis correspondiente. Por lo tanto, para cada uno de esos métodos de retrollamada de párrafo, simplemente llame a parse_text() con las opciones deseadas y luego use el árbol de análisis devuelto para asignarlo al objeto de párrafo dado.

Eso le da un árbol de análisis para cada párrafo; así que ahora todo lo que necesita es una lista ordenada de párrafos. Puede mantenerla usted mismo como un elemento de datos en el objeto/hash. La forma más sencilla sería simplemente usar una referencia a un array, con el conjunto de "opciones" personalizadas deseadas para cada invocación de parse_text. Supongamos que el conjunto de opciones deseadas está dado por la tabla hash %options. Entonces podríamos hacer algo como lo siguiente:

package MyPodParserTree;
@ISA = qw( Pod::Parser );
...
sub begin_pod {
    my $self = shift;
    $self->{'-paragraphs'} = [];  ## inicializar lista de párrafos
}
sub command {
    my ($parser, $command, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({%options}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    push @{ $self->{'-paragraphs'} }, $pod_para;
}
sub verbatim {
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    push @{ $self->{'-paragraphs'} }, $pod_para;
}
sub textblock {
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({%options}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    push @{ $self->{'-paragraphs'} }, $pod_para;
}
...
package main;
...
my $parser = new MyPodParserTree(...);
$parser->parse_from_file(...);
my $paragraphs_ref = $parser->{'-paragraphs'};

Por supuesto, en la humilde opinión de este autor del módulo, estaría más inclinado a usar el objeto Pod::ParseTree existente que un simple array. De esa manera, todo lo que contiene, tanto párrafos como secuencias, responde a la misma interfaz principal para todos los nodos del árbol de análisis. El resultado se vería algo así:

package MyPodParserTree2;
...
sub begin_pod {
    my $self = shift;
    $self->{'-ptree'} = new Pod::ParseTree;  ## inicializar árbol de análisis
}
sub parse_tree {
    ## método de conveniencia para obtener/establecer el árbol de análisis para todo el POD
    (@_ > 1)  and  $_[0]->{'-ptree'} = $_[1];
    return $_[0]->{'-ptree'};
}
sub command {
    my ($parser, $command, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({<<options>>}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    $parser->parse_tree()->append( $pod_para );
}
sub verbatim {
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    $parser->parse_tree()->append( $pod_para );
}
sub textblock {
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({<<options>>}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    $parser->parse_tree()->append( $pod_para );
}
...
package main;
...
my $parser = new MyPodParserTree2(...);
$parser->parse_from_file(...);
my $ptree = $parser->parse_tree;
...

Ahora tiene todo el documento POD como un gran árbol de análisis. Incluso puede usar la opción -expand_seq de parse_text para insertar objetos completamente diferentes. Simplemente no espere que Pod::Parser sepa qué hacer con ellos después. Eso deberá estar en su código. O, alternativamente, puede insertar cualquier objeto que desee siempre que cumpla con la interfaz de Pod::ParseTree.

Se podría usar esto para crear subclases de Pod::Paragraphs y Pod::InteriorSequences para comandos específicos (o para crear sus propios tipos de nodo personalizados en el árbol de análisis) y agregar algún tipo de método emit() a cada nodo/subclase personalizada en el árbol. Luego, todo lo que necesitaría hacer es recorrer el árbol recursivamente en el orden deseado, procesando los hijos (la mayoría de las veces de izquierda a derecha) formateándolos si son cadenas de texto, o llamando a su método emit() si son objetos/referencias.

ADVERTENCIAS

Tenga en cuenta que POD tiene la noción de "párrafos": esto es algo que comienza *después* de una línea en blanco (es decir, vacía), con la única excepción del inicio del archivo, que también inicia un párrafo. Eso significa que, especialmente un comando (por ejemplo, "=head1") *debe* ir precedido por una línea en blanco; "__END__" *no* es una línea en blanco.

VER TAMBIÉN

Pod::InputObjects, Pod::Select

Pod::InputObjects define objetos de entrada POD que corresponden a párrafos de comandos, árboles de análisis y secuencias interiores.

Pod::Select es una subclase de Pod::Parser que proporciona la capacidad de incluir y/o excluir selectivamente secciones de un documento POD de ser traducidas basándose en el encabezado, subencabezado, subsubencabezado, etc., actual.
