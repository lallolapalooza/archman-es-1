POE::Filter::Line(3) Documentación de Perl aportada por el usuario POE::Filter::Line(3)

NOMBRE

POE::Filter::Line - serializa y analiza registros terminados (líneas)

SINOPSIS

#!perl
use POE qw(Wheel::FollowTail Filter::Line);
POE::Session->create(
  inline_states => {
    _start => sub {
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        Filter => POE::Filter::Line->new(),
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPCIÓN

POE::Filter::Line analiza datos de flujo en registros terminados. El analizador por defecto interpreta los saltos de línea como el terminador de registro, y el serializador por defecto añade saltos de línea de red (CR/LF, o "\x0D\x0A") a los registros salientes.

Los terminadores de registro se eliminan de los datos que devuelve POE::Filter::Line.

POE::Filter::Line soporta varias formas adicionales de analizar líneas. Los parámetros del constructor pueden especificar saltos de línea literales, expresiones regulares o que el filtro detecte los saltos de línea por sí mismo.

MÉTODOS PÚBLICOS DEL FILTRO

El método new() de POE::Filter::Line tiene algunos parámetros interesantes.

new

new() acepta una lista de parámetros con nombre.

En todos los casos, los datos interpretados como terminador de registro se eliminan de los datos que devuelve POE::Filter::Line.

"InputLiteral" puede usarse para analizar registros que terminan con una cadena literal. Por ejemplo, POE::Filter::Line puede usarse para analizar y emitir líneas estilo C, que se terminan con un NULO ASCII:

my $c_line_filter = POE::Filter::Line->new(
  InputLiteral => chr(0),
  OutputLiteral => chr(0),
);

"OutputLiteral" permite a un filtro put() registros con un terminador de registro diferente al que analiza. Esto puede ser útil en aplicaciones que deben traducir terminadores de registro.

"Literal" es una abreviatura para el caso común en que los literales de entrada y salida son idénticos. El ejemplo anterior puede escribirse como:

my $c_line_filter = POE::Filter::Line->new(
  Literal => chr(0),
);

Una aplicación también puede permitir que POE::Filter::Line determine qué salto de línea usar. Esto se hace especificando "InputLiteral" como undef:

my $whichever_line_filter = POE::Filter::Line->new(
  InputLiteral => undef,
  OutputLiteral => "\n",
);

"InputRegexp" puede usarse en lugar de "InputLiteral" para reconocer terminadores de línea basándose en una expresión regular. En este ejemplo, la entrada se termina por dos o más saltos de línea consecutivos. En la salida, el separador de párrafos es "---" en una línea por sí solo.

my $paragraph_filter = POE::Filter::Line->new(
  InputRegexp => "([\x0D\x0A]{2,})",
  OutputLiteral => "\n---\n",
);

"MaxBuffer" establece la cantidad máxima de datos que el filtro conservará mientras intenta encontrar un final de línea. Por defecto es 512 MB.

"MaxLength" establece la longitud máxima de una línea. Por defecto es 64 MB.

Si se excede la restricción de "MaxLength" o "MaxBuffer", "POE::Filter::Line" lanzará una excepción.

MÉTODOS PÚBLICOS DEL FILTRO

POE::Filter::Line no tiene métodos públicos adicionales.

SUBCLASES

POE::Filter::Line exporta la constante FIRST_UNUSED. Esta apunta al primer elemento no utilizado en la referencia de array $self. Las subclases deben almacenar sus propios datos comenzando aquí, y deben exportar sus propias constantes FIRST_UNUSED para ayudar a futuros subclasificadores.

ERRORES

El analizador de salto de línea de entrada por defecto es una expresión regular que tiene una condición de carrera desafortunada. Primero, la expresión regular:

/(\x0D\x0A?|\x0A\x0D?)/

Si bien reconoce rápidamente la mayoría de las formas de salto de línea, a veces puede detectar una línea en blanco adicional. Esto ocurre cuando un carácter de salto de línea de dos bytes se divide entre dos lecturas. Considere esta situación:

some stream dataCR
LFother stream data

La expresión regular verá el primer CR sin su LF correspondiente. El filtro devolverá correctamente "some stream data" como una línea. Cuando llegue el siguiente paquete, el "LF" inicial se tratará como el terminador de una línea de 0 bytes. El filtro devolverá fielmente esta línea vacía.

Se aconseja especificar saltos de línea literales o usar la función de autodetectar en aplicaciones donde las líneas en blanco son significativas.
