DESCRIPCIÓN

Los "componentes" de POE son módulos orientados a eventos que generalmente encapsulan características de programas de nivel medio a alto. Por ejemplo, POE::Component::Client::DNS realiza búsquedas de resolución asíncronas basadas en mensajes. POE::Component::Server::TCP es un servidor de red asíncrono básico.

El espacio de nombres POE::Component se inició como un lugar para que los colaboradores publicaran sus módulos basados en POE sin necesidad de coordinación con la distribución principal de POE. El espacio de nombres es anterior a la convención -X, de lo contrario, estaría leyendo sobre POEx en su lugar.

Al igual que con muchas cosas en Perl, existe más de una forma de implementar interfaces de componentes. Los componentes más nuevos presentan interfaces OO, y algunos incluso usan Moose, pero los más antiguos están únicamente orientados a mensajes.

COMPONENTES ORIENTADOS A OBJETOS

Una forma de crear componentes orientados a objetos es incrustar una instancia de POE::Session dentro de un objeto. Esto se hace creando la sesión durante el constructor del objeto, estableciendo el alias de la sesión en algo único y guardando una copia del alias en el objeto.

package Asynchrotron;
my $alias_index = 0;
sub new {
  my $class = shift;
  my $self = bless {
    alias => __PACKAGE__ . " " . ++$alias_index;
  }, $class;
  POE::Session->create(
    object_states => [
      $self => {
        _start       => "_poe_start",
        do_something => "_poe_do_something",
      },
    ],
  );
  return $self;
}
sub _poe_start {
  $_[KERNEL]->alias_set($_[OBJECT]->{alias});
}

El alias permite que los métodos de objeto pasen eventos a la sesión sin tener que almacenar algo sobre la sesión. La llamada call() de POE::Kernel transfiere la ejecución del contexto de la sesión llamante al contexto de la sesión del componente.

sub do_something {
  my $self = shift;
  print "Dentro de la sesión del llamante ahora: @_\n";
  $poe_kernel->call($self->{alias}, "do_something", @_);
}
sub _poe_do_something {
  my @args = @_[ARG0..$#_];
  print "Dentro de la sesión del componente ahora: @args\n";
  $_[OBJECT]{count}++;
}

Tanto $_[HEAP] como $_[OBJECT] son visibles dentro de la sesión del componente. $_[HEAP] puede usarse para encapsulación ultra-privada, mientras que $_[OBJECT] puede usarse para datos visibles por los accesorios.

sub get_count {
  my $self = shift;
  return $self->{count}; # $_[OBJECT]{count} arriba
}

Demasiadas sesiones pueden ralentizar la creación y destrucción de objetos, así que evite crearlas para cada objeto.

VER TAMBIÉN

La sección SEE ALSO en POE contiene una tabla de contenido que cubre toda la distribución de POE.

POE::Stage es un proyecto naciente para formalizar los componentes de POE, hacer que POE::Kernel sea más orientado a objetos y proporcionar azúcar sintáctico y semántico para muchos aspectos comunes del desarrollo de POE::Component. También es más fácil de escribir. Por favor, investigue el proyecto. Se necesitan ideas y tuits con urgencia para ayudar a que el proyecto despegue.
