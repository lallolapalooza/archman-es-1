POE::Driver::SysRW(3) Documentación Perl aportada por el usuario POE::Driver::SysRW(3)

NOMBRE

POE::Driver::SysRW - I/O en búfer y no bloqueante usando sysread y syswrite

SINOPSIS

"SINOPSIS" en POE::Driver ilustra cómo funciona la interfaz. Este módulo es meramente una implementación.

DESCRIPCIÓN

Este controlador implementa POE::Driver usando sysread y syswrite.

MÉTODOS PÚBLICOS

POE::Driver::SysRW introduce algunas características adicionales no cubiertas en la interfaz base.

new [TamañoDeBloque => OCTETOS]

new() crea un nuevo controlador de I/O en búfer que usa sysread() para leer datos de un manejador y syswrite() para vaciar datos a ese manejador. El constructor acepta un parámetro opcional con nombre, "TamañoDeBloque", que indica el número máximo de OCTETOS que se leerán a la vez.

"TamañoDeBloque" es de 64 kilobytes (65536 octetos) por defecto. Valores más altos pueden mejorar el rendimiento en aplicaciones de streaming, pero la contrapartida es una granularidad de eventos menor y un mayor uso de memoria residente.

Valores más bajos de "TamañoDeBloque" reducen algo el consumo de memoria con las correspondientes penalizaciones en el rendimiento.

my $driver = POE::Driver::SysRW->new;
my $driver = POE::Driver::SysRW->new( TamañoDeBloque => $tama_bloque );

Los controladores se instancian comúnmente dentro de las llamadas al constructor de POE::Wheel:

$_[HEAP]{wheel} = POE::Wheel::ReadWrite->new(
  InputHandle => \*STDIN,
  OutputHandle => \*STDOUT,
  Driver => POE::Driver::SysRW->new(),
  Filter => POE::Filter::Line->new(),
);

Las aplicaciones casi siempre usan POE::Driver::SysRW, por lo que los objetos POE::Wheel casi siempre crearán los suyos si no se especifica un Driver.

Todos los demás métodos

POE::Driver::SysRW documenta la interfaz abstracta documentada en POE::Driver. Por favor, consulta POE::Driver para más detalles sobre los siguientes métodos:

get
get_out_messages_buffered
