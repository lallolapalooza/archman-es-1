NOMBRE

POE::Component::IKC::Client - Cliente de Comunicación Inter-Kernel (IKC) de POE

SINOPSIS

use POE;
use POE::Component::IKC::Client;
POE::Component::IKC::Client->spawn(
    ip=>$ip, 
    port=>$port,
    name=>"Cliente$$",
    subscribe=>[qw(poe:/*/timserver)]
);
...
$poe_kernel->run();

DESCRIPCIÓN

Este módulo implementa un cliente IKC de POE. Un cliente IKC intenta conectarse a un servidor IKC. Si tiene éxito, negocia ciertos parámetros de conexión. Después de esto, el servidor y el cliente de POE son prácticamente idénticos.

FUNCIONES EXPORTADAS

crear_cliente_ikc

Azúcar sintáctico para POE::Component::IKC::Client->spawn.

MÉTODOS DE CLASE

spawn

Este método inicia todo el trabajo de conexión a un servidor IKC. Los parámetros son:

"ip"
Dirección a la que conectarse. Puede ser una cuádruple puntada ('127.0.0.1') o un nombre de host ('foo.pied.nu'). Por defecto es '127.0.0.1', también conocido como INADDR_LOOPBACK.
"port"
Puerto al que conectarse. Puede ser numérico (80) o un servicio ('http').
"unix"
Ruta al socket de dominio Unix en el que el servidor está escuchando.
"name"
Nombre del kernel local. Así es como nos "anunciaremos" a kernels extranjeros. Actúa como un "alias de kernel". Este parámetro es temporal, pendiente de la adición de nombres de kernel reales en el núcleo de POE. Este nombre, y todos los alias, se registrarán con el respondedor para que pueda enviarles mensajes como si fueran remotos.
"aliases"
Referencia de matriz de aún más alias para este kernel. ¡Diversión, diversión, diversión!
"on_connect"
Coderef que se llama cuando se ha establecido la conexión con el kernel extranjero. Normalmente, lo usaría para iniciar las sesiones que envían eventos a kernels extranjeros.

Tenga en cuenta también que el coderef se ejecutará dentro de una sesión de canal IKC, NO dentro de su propia sesión. Esto significa que cosas como $poe_kernel->delay_set() no harán lo que usted cree que deberían.

Sin embargo, significa que puede obtener el ID de sesión del canal IKC para esta conexión.

POE::Component::IKC::Client->spawn(
    ....
        on_connect=>sub {
            $heap->{channel} = $poe_kernel->get_active_session()->ID;
        },
    ....
    );

Sin embargo, IKC/monitor proporciona un mecanismo más potente para detectar conexiones. Vea POE::Component::IKC::Responder.

"on_error"
Coderef que se llama para todos los errores de conexión. Podría usarlo para reiniciar el intento de conexión. Los parámetros son $operation, $errnum y $errstr, que corresponden al Evento de Fallo de POE::Wheel::SocketFactory, que consulte.

Sin embargo, IKC/monitor proporciona un mecanismo más potente para detectar errores. Vea POE::Component::IKC::Responder.

Tenga en cuenta también que el coderef se ejecutará dentro de una sesión IKC, NO dentro de su propia sesión. Esto significa que cosas como $poe_kernel->delay_set() no harán lo que usted cree que deberían.

"subscribe"
Referencia de matriz de especificadores (sesiones extranjeras o estados extranjeros) a los que desea suscribirse. on_connect solo se llamará cuando IKC haya logrado suscribirse a todos los especificadores. Si no puede, morirá(). ¡YOW, eso apesta! "monitor" nos salvará a todos.
"serializers"
Referencia de matriz o escalar de los paquetes que desea utilizar para la serialización de datos. Primero, IKC intenta cargar cada paquete. Luego, al conectarse a un servidor, pregunta al servidor sobre cada uno hasta que el servidor acepta un serializador que funciona en su lado.

Un paquete serializador requiere 2 funciones: freeze (o nfreeze) y thaw. Vea "POE::Filter::Reference".

El valor predeterminado es "[qw(Storable FreezeThaw POE::Component::IKC::Freezer)]". "Storable" y "FreezeThaw" son módulos en C en CPAN. Son mucho, mucho, mucho más rápidos que el serializador incorporado de IKC "POE::Component::IKC::Freezer". Este serializador utiliza "Data::Dumper" y "eval $code" para hacer el trabajo. Hay un problema de seguridad obvio aquí. Sin embargo, tiene la ventaja de ser Perl puro y todos los módulos vienen con la distribución principal de Perl.

Cabe señalar que debe tener la misma versión de "Storable" en ambos lados, ya que algunas versiones no son mutuamente compatibles.

"protocol"
Qué protocolo de negociación IKC utilizar. El protocolo original ("IKC") era síncrono y lento. El nuevo protocolo ("IKC0") envía toda la información a la vez. IKC0 se degradará elegantemente a IKC si el cliente y el servidor no coinciden.

El valor predeterminado es IKC0.
