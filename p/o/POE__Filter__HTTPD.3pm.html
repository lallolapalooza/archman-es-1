POE::Filter::HTTPD(3) Documentación de Perl contribuyida por el usuario POE::Filter::HTTPD(3)

NOMBRE

POE::Filter::HTTPD - analiza solicitudes HTTP simples y serializa respuestas HTTP

SINOPSIS

#!perl
use warnings;
use strict;
use POE qw(Component::Server::TCP Filter::HTTPD);
use HTTP::Response;
POE::Component::Server::TCP->new(
  Port         => 8088,
  ClientFilter => 'POE::Filter::HTTPD',  ### <-- AQUÍ ESTAMOS!
  ClientInput => sub {
    my $request = $_[ARG0];
    # Es una respuesta para el cliente si hubo un problema.
    if ($request->isa("HTTP::Response")) {
      my $response = $request;
      $request = $response->request;
      warn "ERROR: ", $request->message if $request;
      $_[HEAP]{client}->put($response);
      $_[KERNEL]->yield("shutdown");
      return;
    }
    my $request_fields = '';
    $request->headers()->scan(
      sub {
        my ($header, $value) = @_;
        $request_fields .= (
          "<tr><td>$header</td><td>$value</td></tr>"
        );
      }
    );
    my $response = HTTP::Response->new(200);
    $response->push_header( 'Content-type', 'text/html' );
    $response->content(
      "<html><head><title>Tu Solicitud</title></head>" .
      "<body>Detalles sobre tu solicitud:" .
      "<table border='1'>$request_fields</table>" .
      "</body></html>"
    );
    $_[HEAP]{client}->put($response);
    $_[KERNEL]->yield("shutdown");
  }
);
print "Apunta tu navegador al puerto 8088 de este host.\n";
POE::Kernel->run();
exit;

DESCRIPCIÓN

POE::Filter::HTTPD interpreta flujos de entrada como solicitudes HTTP 0.9, 1.0 o 1.1. Devuelve un objeto HTTP::Request cuando se analiza correctamente una solicitud.

En caso de fallo, devuelve un objeto HTTP::Response que describe el fallo. El propósito es que el código de aplicación notifique sobre el objeto HTTP::Response y lo envíe sin más procesamiento. El objeto de solicitud erróneo puede estar disponible a través de $r->request en el método HTTP::Response. Esto se ilustra en la sección "SINOPSIS".

Para la salida, POE::Filter::HTTPD acepta objetos HTTP::Response y devuelve sus flujos correspondientes.

Por favor, consulta HTTP::Request y HTTP::Response para detalles sobre cómo usar estos objetos.

Los encabezados HTTP no pueden contener caracteres UTF-8; deben ser ISO-8859-1. POE::Filter::HTTPD convierte todo el UTF-8 a su equivalente MIME. Utiliza "utf8::is_utf8" para la detección y Email::MIME::RFC2047::Encoder para la conversión. Si utf8 no está instalado, no se realiza la conversión. Si Email::MIME::RFC2047::Encoder no está instalado, se utiliza "utf8::downgrade". En este último caso, se mostrará una advertencia si intentas enviar encabezados UTF-8.

MÉTODOS DE FILTRO PÚBLICOS

POE::Filter::HTTPD implementa la interfaz básica de POE::Filter.

new

new() acepta un conjunto de parámetros con nombre.

"MaxBuffer" establece la cantidad máxima de datos que el filtro almacenará en memoria. El valor predeterminado es 512 MB (536870912 bytes). Debido a que POE::Filter::HTTPD copia todos los datos en memoria, establecer este número a un valor alto permite que un cliente malicioso llene completamente la memoria del servidor y la memoria virtual (swap).

"MaxContent" establece el tamaño máximo del contenido de una solicitud HTTP. El valor predeterminado es 1 MB (1038336 bytes). Debido a que POE::Filter::HTTPD copia todos los datos en memoria, establecer este número a un valor alto permite que un cliente malicioso llene completamente la memoria del servidor y la memoria virtual (swap). Esta opción se ignora si "Streaming" está activado.

"Streaming" activa el modo de transmisión (streaming) de solicitudes. El valor predeterminado es desactivado. En este modo, el filtro devuelve un objeto HTTP::Request o un bloque de contenido. El objeto HTTP::Request se devuelve vacío. Los bloques de contenido son fragmentos del cuerpo de la solicitud, hasta el tamaño de Content-Length. Puedes distinguir entre objetos de solicitud y bloques de contenido utilizando "Scalar::Util/bless" (ver la sección "Solicitud de streaming" a continuación). Esta opción reemplaza a "MaxContent".

ADVERTENCIAS

Algunas versiones de libwww generan solicitudes HTTP inválidas. Por ejemplo, este código (adaptado del documento de HTTP::Request::Common) causará un error en un demonio de POE::Filter::HTTPD:

NOTA: El uso de esta prueba con libwww-perl/5.834 mostró que añadió los datos correctos de HTTP/1.1! No sabemos qué versión de LWP corrigió esto. Este ejemplo es válido para instalaciones antiguas de LWP, ¡pero debes tener cuidado!

use HTTP::Request::Common;
use LWP::UserAgent;
my $ua = LWP::UserAgent->new();
$ua->request(POST 'http://example.com', [ foo => 'bar' ]);

Por defecto, HTTP::Request es agnóstico respecto a la versión HTTP. No intenta agregar un encabezado de versión HTTP a menos que declares un protocolo específicamente usando "$request->protocol('HTTP/1.0')".

Según el RFC HTTP 1.0 (1945), cuando no hay un encabezado de versión HTTP, el analizador debe predecir HTTP/0.9 por defecto. POE::Filter::HTTPD sigue esta convención. En el flujo detallado anterior, el demonio basado en Filter::HTTPD devolverá un error 400 porque POST no es un tipo de solicitud válido para HTTP/0.9.

Al manejar un error de solicitud, es más eficaz y confiable responder con el error y cerrar la conexión. Las solicitudes inválidas pueden dañar el flujo de solicitudes. Por ejemplo, la ausencia de un encabezado Content-Length indica que la solicitud no tiene contenido. Las solicitudes con contenido pero sin ese encabezado se dividirán en una solicitud sin contenido y datos inválidos. Los datos inválidos también pueden aparecer como una solicitud. La comedia continuará, posiblemente repetidamente, hasta que el filtro encuentre la siguiente solicitud válida. Al cerrar la conexión ante el primer signo de error, el cliente puede reintentar su solicitud con una conexión limpia y el filtro.

Solicitud de streaming

Normalmente, POE::Filter::HTTPD lee todo el contenido de la solicitud antes de devolver el objeto HTTP::Request a tu código. En modo de streaming, devuelve el contenido por separado, como escalares no bendecidos. El contenido puede dividirse en bloques de diferentes tamaños, dependiendo del sistema operativo y la comunicación. Tu código puede distinguir entre el objeto de solicitud y los bloques de contenido utilizando "blessed" en Scalar::Util.

use Scalar::Util;
use POE::Wheel::ReadWrite;
use POE::Filter:HTTPD;
$heap->{wheel} = POE::Wheel::ReadWrite->new(
                    InputEvent => 'http_input',
                    Filter => POE::Filter::HTTPD->new( Streaming => 1 ),
                    # ...
            );
sub http_input_handler
{
    my( $heap, $req_or_data ) = @_[ HEAP, ARG0 ];
    if( blessed $req_or_data ) {
        my $request = $req_or_data;
        if( $request->isa( 'HTTP::Response') ) {
            # Error HTTP
            $heap->{wheel}->put( $request );
        }
        else {
            # Solicitud HTTP
            # ...
        }
    }
    else {
        my $data = $req_or_data;
        # ...
    }
}

Si conservas todo el contenido en memoria pero no impone un límite de Content-Length, podrías crear un fallo de DoS. Un atacante podría enviar "Content-Length: 1099511627776" (alias 1 TB) y enviar datos hasta que toda la memoria de tu sistema y el espacio de intercambio (swap) se llenen.

El Content-Length ha sido sanitizado por POE::Filter::HTTPD, por lo que verificarlo es trivial:

if( $request->headers( 'Content-Length' ) > 1024*1024 ) {
    my $resp = HTTP::Response->new( RC_REQUEST_ENTITY_TOO_LARGE ),
                                         "Demasiado contenido!" )
    $heap->{wheel}->put( $resp );
    return;
}

Si deseas manejar grandes cantidades de datos, debes guardar el contenido en un archivo antes de procesarlo. Aun así, debes verificar el Content-Length o un atacante podría llenar el espacio de la partición.

use File::Temp qw(tempfile);
if( blessed $_[ARG0] ) {
    $heap->{request} = $_[ARG0];
    if( $heap->{request}->method eq 'GET' ) {
        handle_get( $heap );
        delete $heap->{request};
        return;
    }
    my( $fh, $file ) = tempfile( "httpd-XXXXXXXX", TMPDIR=>1 );
    $heap->{content_file} = $file;
    $heap->{content_fh} = $fh;
    $heap->{content_size} = 0;
}
