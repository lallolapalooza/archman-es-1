NOMBRE

POE::Resource::Clock - reloj interno usado para ordenar la cola

SINOPSIS

sub POE::Kernel::USE_POSIXRT { 0 }
use POE;

DESCRIPCIÓN

POE::Resource::Clock es un módulo auxiliar para POE::Kernel. Proporciona las funcionalidades para mantener un reloj monotónico interno y un reloj de pared. También convierte entre este reloj monotónico y el reloj de pared.

El reloj monotónico se utiliza para mantener una cola ordenada de eventos. El reloj de pared se utiliza para comunicar la hora con el código del usuario ("alarm_set" en POE::Kernel, "alarm_remove" en POE::Kernel).

Hay 3 fuentes de reloj posibles en orden de preferencia: POSIX::RT::Clock, Time::HiRes y "time" en perlfunc. Solo "POSIX::RT::Clock" tiene un reloj monotónico y uno de pared separados; los otros dos usan la misma fuente para ambos relojes.

La selección y el comportamiento del reloj se controlan con lo siguiente:

USE_POSIXRT

export POE_USE_POSIXRT=0
    o
sub POE::Kernel::USE_POSIXRT { 0 }

Utiliza la fuente de reloj "monotonic" para la prioridad de la cola y la fuente de reloj "realtime" para el reloj de pared. No se usa si POSIX::RT::Clock no está instalado o si tu sistema no tiene un reloj "monotonic".

Por defecto es verdadero. Si deseas el comportamiento anterior de POE, establece esto en 0.

USE_STATIC_EPOCH

export POE_USE_STATIC_EPOCH=0
    o
sub POE::Kernel::USE_STATIC_EPOCH { 0 }

La época del reloj monotónico de POSIX::RT::Clock es diferente a la del reloj de tiempo real. Por ejemplo, en Linux 2.6.18, el reloj monotónico es el número de segundos desde el arranque del sistema. Esta época se utiliza para convertir de tiempo de pared a tiempo monotónico para "alarm" en POE::Kernel, "alarm_add" en POE::Kernel y "alarm_set" en POE::Kernel. Si "USE_STATIC_EPOCH" es verdadero (el valor predeterminado), la época se calcula en el momento de la carga. Si es falso, la época se calcula cada vez que se necesita.

Por defecto es verdadero. Solo relevante si se utiliza POSIX::RT::Clock. Los servidores POE de larga ejecución deben tener esto establecido en falso para que el desfase del reloj del sistema no afecte a la cola.

Es importante señalar que sin una época estática, el orden de las siguientes dos alarmas no está definido.

$poe_kernel->alarm_set( a1 => $time );
$poe_kernel->alarm_set( a2 => $time );

USE_EXACT_EPOCH

export POE_USE_EXACT_EPOCH=1
    o
sub POE::Kernel::USE_EXACT_EPOCH { 1 }

Actualmente no hay forma de obtener exactamente la época del reloj monotónico. En su lugar, se utiliza la diferencia entre el valor actual del reloj monotónico y el valor del reloj de tiempo real. Obviamente, esto es inexacto porque hay un ligero retraso entre las 2 llamadas al sistema. Establecer USE_EXACT_EPOCH en verdadero calculará un promedio de esta diferencia durante 250 ms o al menos 20 muestras. Además, las llamadas al sistema se realizan en ambos órdenes (monotónico y luego tiempo real, tiempo real y luego monotónico) para intentar obtener un valor más exacto.

Por defecto es falso. Solo relevante si "USE_STATIC_EPOCH" es verdadero.

USE_HIRES

export POE_USE_HIRES=0
    o
sub POE::Kernel::USE_HIRES { 0 }

Utiliza Time::HiRes como fuente de reloj monotónico y de pared. Esta era la fuente de reloj predeterminada anterior de POE.

Por defecto es verdadero. Solo relevante si "USE_POSIXRT" es falso. Establece esto en falso para usar "time" en perlfunc.

EXPORTA

Este módulo exporta opcionalmente algunas funciones auxiliares de seguimiento del tiempo.

mono2wall

mono2wall() convierte un tiempo monotónico a un tiempo de pared de época.

my $wall = mono2wall( $monotonic );

monotime

monotime() hace un intento de hacer lo posible por devolver el tiempo de un reloj de sistema monotónico. Puede recurrir a tiempo no monotónico si no hay relojes monotónicos disponibles.

my $monotonic = monotime();

sleep

sleep() hace un intento de hacer lo posible por dormir una cantidad determinada de tiempo de alta resolución utilizando un reloj monotónico. Esta característica se degradará elegantemente a relojes no monotónicos de alta resolución, luego a relojes de baja resolución, dependiendo de las bibliotecas disponibles.

sleep( 3.141 );

time

time() es un alias compatible con versiones anteriores para walltime(). Consulta la documentación de walltime() para obtener detalles.

wall2mono

wall2mono() hace un intento de hacer lo posible por convertir el tiempo de pared a su tiempo equivalente en reloj monotónico. Su funcionalidad se degrada elegantemente según la disponibilidad del reloj.

my $monotonic = wall2mono( $epoch );

walltime

walltime() hace un intento de hacer lo posible por devolver el tiempo de pared no monotónico a la resolución más alta disponible conocida.

my $epoch = walltime();

Poner un paquete en Arch Linux

Este artículo te guiará a través del proceso de empaquetado de software para Arch Linux. Aquí cubriremos los aspectos básicos de la creación de un PKGBUILD y cómo usar makepkg para compilar e instalar su paquete.

¿Qué es un PKGBUILD?

Un PKGBUILD es un script de shell que contiene metadatos e instrucciones para compilar e instalar un paquete. Sigue una sintaxis estándar y es utilizado por makepkg para construir el paquete.

Estructura básica de un PKGBUILD

Aquí tienes un ejemplo simple de un PKGBUILD:

# Contraseña para el paquete. Debe ser un número entero de 6 dígitos.
pkgrel=1

# Nombre del paquete.
pkgname=mi-paquete-ejemplo

# Versión del paquete.
pkgver=1.0

# Breve descripción del paquete.
pkgdesc="Un paquete de ejemplo para Arch Linux."

# URL del proyecto.
url="http://ejemplo.com/"

# Dependencias de compilación.
makedepends=('gcc')

# Dependencias de ejecución.
depends=('glibc')

# Architecturas compatibles.
arch=('i686' 'x86_64')

# SHA256 checksum de la fuente.
sha256sums=('1234567890abcdef1234567890abcdef1234567890abcdef1234567890abcdef')

# Función para descargar y extraer la fuente.
build() {
  cd "$srcdir"/mi-paquete-ejemplo-${pkgver}
  ./configure --prefix=/usr
  make
}

# Función para instalar el paquete.
package() {
  cd "$srcdir"/mi-paquete-ejemplo-${pkgver}
  make DESTDIR="$pkgdir/" install
}

Variables importantes

  • pkgname: El nombre del paquete.
  • pkgver: La versión del paquete.
  • pkgrel: La versión del paquete (se incrementa si se actualizan los metadatos, pero no el código fuente).
  • pkgdesc: Una descripción corta del paquete.
  • arch: Las arquitecturas de CPU compatibles.
  • url: La URL del sitio web del proyecto.
  • license: La licencia del software.
  • depends: Paquetes que deben estar instalados para que este paquete funcione.
  • makedepends: Paquetes que son necesarios solo para compilar este paquete.
  • source: La URL de la fuente o el nombre del archivo de la fuente.
  • sha256sums: El checksum SHA256 de los archivos fuente para verificar su integridad.

Funciones principales

  • prepare(): Se utiliza para aplicar parches o realizar modificaciones en el código fuente antes de la compilación.
  • build(): Aquí es donde se compila el código fuente. Normalmente implica usar `./configure`, `make`, etc.
  • check(): Ejecuta las pruebas de verificación del paquete.
  • package(): Aquí es donde se instalan los archivos compilados en el directorio de preparación del paquete ($pkgdir).

Compilar e instalar el paquete

Una vez que tengas tu PKGBUILD, puedes usar makepkg para compilar e instalar el paquete.

  1. Descarga el código fuente y crea el PKGBUILD en un directorio.
  2. Navega a ese directorio en tu terminal.
  3. Ejecuta makepkg -si.
    • -s: Sincroniza las dependencias necesarias.
    • -i: Instala el paquete después de compilarlo.

Ejemplo práctico

Crearemos un paquete simple para un programa "hola mundo" escrito en C.

Paso 1: Crea el código fuente

Crea un archivo llamado hola.c con el siguiente contenido:

#include <stdio.h>

int main() {
    printf("¡Hola, Arch Linux!\n");
    return 0;
}

Paso 2: Crea el PKGBUILD

Crea un archivo llamado PKGBUILD con el siguiente contenido:

pkgname=hola-mundo
pkgver=1.0
pkgrel=1
pkgdesc="Un programa simple de hola mundo."
arch=('any')
url="http://ejemplo.com/"
license=('MIT')
source=("hola.c")
sha256sums=('...tu-sha256sum-aqui...')

build() {
  gcc hola.c -o hola
}

package() {
  install -D -m 755 hola "$pkgdir/usr/bin/hola"
}

Nota: Deberás reemplazar ...tu-sha256sum-aqui... con el checksum SHA256 real de tu archivo hola.c. Puedes obtenerlo ejecutando sha256sum hola.c.

Paso 3: Compila e instala

En el mismo directorio donde guardaste hola.c y PKGBUILD, ejecuta:

makepkg -si

Paso 4: Prueba el paquete

Ejecuta el programa instalado:

hola

Deberías ver la salida:

¡Hola, Arch Linux!
