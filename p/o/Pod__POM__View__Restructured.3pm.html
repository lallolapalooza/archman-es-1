NOMBRE

Pod::POM::View::Restructured - Vista para Pod::POM que genera reStructuredText

SINOPSIS

use Pod::POM::View::Restructured;

my $view = Pod::POM::View::Restructured->new;
my $parser = Pod::POM->new;
my $pom = $parser->parse_file("$top_dir/lib/Pod/POM/View/Restructured.pm");
my $out = $pom->present($view);

DESCRIPCIÓN

Este módulo genera reStructuredText que se espera que sea utilizado con Sphinx. Las secciones literales (párrafos con sangría) en el POD se generarán con resaltado de sintaxis para código Perl por defecto. Vea "Comandos POD específicamente para reStructuredText" para saber cómo cambiar esto para un bloque específico.

Este módulo se puede descargar desde https://metacpan.org/release/Pod-POM-View-Restructured.

MÉTODOS

new(\%params)

Constructor. \%params es opcional. Si está presente, las siguientes claves son válidas:

"callbacks"
Ver documentación más abajo para convert_file().
"namespace"
Si se declara un espacio de nombres, los enlaces a ese espacio de nombres se convierten en referencias cruzadas y se añade una ancla para cada etiqueta de encabezado.

"convert_file($source_file, $title, $dest_file, $callbacks)"

Convierte el POD en $source_file a reStructuredText. Si $dest_file está definido, escribe la salida allí. Si $title está definido, se utiliza para el título del documento. De lo contrario, se intenta inferir el título de la sección NAME (comprueba si el cuerpo se parece a "/\A\s*(\w+(?:::\w+)+)\s+-\s+/s").

Devuelve la salida como una cadena.

$source_file y $dest_file pueden ser nombres de archivo o manejadores de archivo.

"convert_files($file_spec, $index_file, $index_title, $out_dir)"

Convierte los archivos dados en $file_spec a reStructuredText. Si se proporciona $index_file, es la ruta al archivo de índice que se creará (con una tabla de contenidos que apunta a todos los archivos creados). Si se proporciona $index_title, se utiliza como el título de la sección para el archivo de índice. $out_dir es el directorio donde se escribirán los archivos generados.

$file_spec es una referencia a un array de hashes que especifica atributos para cada archivo a convertir. Las claves válidas son:

"source_file"
Archivo a convertir.
"dest_file"
Archivo donde generar el reStructuredText. Si no se proporciona, se generará un nombre de archivo basado en el título.
"title"
Título de la sección para el reStructuredText generado. Si no se proporciona, se intentará inferir el título de la sección NAME en el POD, si existe. Como último recurso, se generará un título que se parezca a "section_(\d+)".
"callbacks"
Una referencia a un hash que contiene nombres y los callbacks correspondientes.

Actualmente, el único callback válido es "link". Se le da el texto dentro de una sección L<> del POD, y se espera que devuelva una tupla "($url, $label)". Si el valor devuelto para $label no está definido, se utiliza el valor de $url como etiqueta.

"no_toc"
Hace que el elemento no se imprima en el índice ni se devuelva en el campo "toc".

Este método devuelve una referencia a un hash con una tabla de contenidos (el campo "toc") adecuada para una tabla de contenidos reStructuredText.

Por ejemplo:

my $conv = Pod::POM::View::Restructured->new;

my $files = [
              { source_file => "$base_dir/Restructured.pm" },
              { source_file => "$base_dir/DWIW.pm" },
              { source_file => "$base_dir/Wrapper.pm" },
             ];

my $rv = $conv->convert_files($files, "$dest_dir/index.rst", 'Mi Gran Prueba', $dest_dir);

COMANDOS POD específicamente para reStructuredText

Las siguientes secuencias se pueden usar en POD para solicitar acciones específicas para este módulo.

=for pod2rst next-code-block: lang

Esto configura la siguiente sección literal, es decir, el siguiente párrafo con sangría para ser resaltado según la sintaxis del lenguaje de programación/marcado/configuración lang. Las secciones literales se asumen como código Perl por defecto. Sphinx utiliza Pygments para el resaltado de sintaxis en estas secciones, por lo que puede usar cualquier valor para lang que Pygments soporte, por ejemplo, Python, C, C++, Javascript, SQL, etc.

EJEMPLOS

Convirtiendo un archivo único usando "pod2rst"
pod2rst --infile=Restructured.pm --outfile=restructured.rst

TODO

resaltado de código
Actualmente, un bloque literal (párrafo con sangría) se genera como un bloque de código Perl por defecto en reStructuredText. Debería haber una opción (por ejemplo, en el constructor) para cambiar el idioma para el resaltado (para todos los bloques literales), o deshabilitar el resaltado de sintaxis y simplemente hacerlo un párrafo preformateado. Hay una forma de hacer esto en POD (ver "Comandos POD específicamente para reStructuredText"), pero también debería haber una opción en el constructor.
mejorar escapado
Los bloques de texto no se escapan correctamente, por lo que actualmente es posible invocar un comando en reStructuredText por accidente.
