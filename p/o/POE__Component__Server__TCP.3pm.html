NOMBRE

POE::Component::Server::TCP - un servidor TCP simplificado

SINOPSIS

#!perl
use warnings;
use strict;
use POE qw(Component::Server::TCP);
POE::Component::Server::TCP->new(
  Port => 12345,
  ClientConnected => sub {
    print "recibida conexión de $_[HEAP]{remote_ip}\n";
    $_[HEAP]{client}->put("Sonríe desde el servidor!");
  },
  ClientInput => sub {
    my $client_input = $_[ARG0];
    $client_input =~ tr[a-zA-Z][n-za-mN-ZA-M];
    $_[HEAP]{client}->put($client_input);
  },
);
POE::Kernel->run;
exit;

DESCRIPCIÓN

POE::Component::Server::TCP implementa un servidor genérico multi-sesión. Servicios simples pueden ser creados en pocas líneas de código. Por ejemplo, un servidor que repite la entrada de vuelta al cliente:

use POE qw(Component::Server::TCP);
POE::Component::Server::TCP->new(
  Port => 12345,
  ClientInput => sub { $_[HEAP]{client}->put($_[ARG0]) },
);
POE::Kernel->run();

Aceptando Conexiones Tú Mismo

POE::Component::Server::TCP tiene un modo por defecto donde acepta nuevas conexiones y crea las sesiones para manejarlas. Los programas pueden hacer esto por sí mismos proporcionando sus propias callbacks de "Acceptor". Ver "Acceptor" para detalles.

Sesión de Escucha Maestra

Al momento de la creación, POE::Component::Server::TCP inicia una POE::Session para escuchar nuevas conexiones. El "Alias" del componente se refiere a esta sesión maestra.

Si se especifica "Acceptor", entonces depende de esa callback manejar los sockets recién aceptados. Sus parámetros son los de la "SuccessEvent" de POE::Wheel::SocketFactory.

De lo contrario, la callback "Acceptor" por defecto iniciará una nueva sesión para manejar cada conexión. Estas sesiones hijas no tienen sus propios alias, pero sus callbacks "ClientConnected" y "ClientDisconnected" pueden ser usadas para registrar y desregistrar las sesiones con un espacio de nombres compartido, como un hash indexado por IDs de sesión, o un objeto que gestione dicho hash.

my %client_namespace;
sub handle_client_connected {
  my $client_session_id = $_[SESSION]->ID;
  $client_namespace{$client_session_id} = \%anything;
}
sub handle_client_disconnected {
  my $client_session_id = $_[SESSION]->ID;
  $client_namespace{$client_session_id} = \%anything;
}

La callback "Started" del componente se invoca al final de la rutina de inicio de la sesión maestra. Los parámetros @_[ARG0..$#_] se establecen a una copia de los valores del parámetro constructor "ListenerArgs" del servidor. Los otros parámetros son estándar para los manejadores _start de POE::Session.

La callback "Stopped" del componente se invoca al principio de la rutina _stop de la sesión maestra. Los parámetros son estándar para los manejadores _stop de POE::Session.

La callback "Error" del componente se invoca cuando el servidor tiene un problema escuchando conexiones. "Error" también puede ser llamada si el acceptor por defecto del componente tiene problemas para aceptar una conexión. "Error" recibe los parámetros habituales para "FailureEvent" en POE::Wheel::SocketFactory y "ErrorEvent" en POE::Wheel::ReadWrite.

Sesiones de Conexión Hija por Defecto

Si "Acceptor" no está especificado, el manejador por defecto de POE::Component::Server::TCP iniciará una nueva sesión por cada nueva conexión de cliente. Como se mencionó anteriormente, estas sesiones hijas no tienen alias propios, pero pueden establecer alias o registrarse de otra manera durante sus callbacks "ClientConnected" y "ClientDisconnected".

No se puede enfatizar lo suficiente que las siguientes callbacks se ejecutan en el contexto de sesiones hijas dinámicas — una por conexión de cliente — y no en la sesión maestra de escucha. Este ha sido un punto importante de confusión. Damos la bienvenida a sugerencias para hacerlo más claro.

La callback "ClientInput" del componente define cómo las sesiones hijas manejarán la entrada de sus clientes. Sus parámetros son los de la "InputEvent" de POE::Wheel::ReadWrite.

Como se mencionó, "ClientConnected" se llama al final de la rutina "_start" de la sesión hija. La callback "ClientConneted" recibe los mismos parámetros que _start de la sesión del cliente. El arrayref pasado al parámetro "Args" del constructor se aplana y se incluye en los parámetros de "ClientConnected" como @_[ARG0..$#_].

sub handle_client_connected {
  my @constructor_args = @_[ARG0..$#_];
  ...
}

"ClientPreConnect" se llama antes de "ClientConnected", y su propósito es permitir a los programas rechazar conexiones o condicionar sockets antes de que sean entregados a POE::Wheel::ReadWrite para su gestión.

El manejador "ClientPreConnect" se llama con el socket del cliente en $_[ARG0], y su valor de retorno es significativo. Debe devolver un socket de cliente válido si la conexión es aceptable. Debe devolver undef para rechazar la conexión.

La mayoría de los valores de $_[HEAP] son válidos en el manejador "ClientPreConnect". Obviamente, $_[HEAP]{client} no lo es porque esa rueda aún no ha sido creada.

En el siguiente ejemplo, el manejador "ClientPreConnect" devuelve el socket del cliente después de haber sido actualizado a una conexión SSL.

sub handle_client_pre_connect {
  # Asegúrate de que la dirección y el puerto remotos sean válidos.
  return undef unless validate(
    $_[HEAP]{remote_ip}, $_[HEAP]{remote_port}
  );
  # SSLifica el socket, que está en $_[ARG0].
  my $socket = eval { Server_SSLify($_[ARG0]) };
  return undef if $@;
  # Devuelve el socket SSLificado.
  return $socket;
}

"ClientDisconnected" se llama cuando el cliente se ha desconectado, ya sea porque el extremo del socket remoto se ha cerrado o el extremo local ha sido cerrado por el servidor. Esto no significa que la sesión del cliente haya terminado, pero la sesión probablemente lo hará muy pronto. "ClientDisconnected" se llama desde un par de lugares dispares dentro del componente, por lo que sus parámetros no son consistentes ni generalmente útiles.

"ClientError" se llama cuando ha ocurrido un error en el socket. Sus parámetros son los de la "ErrorEvent" de POE::Wheel::ReadWrite.

"ClientFlushed" se llama cuando toda la salida pendiente ha sido enviada al socket del cliente. Sus parámetros provienen de la "ErrorEvent" de POE::Wheel::ReadWrite.

Consideraciones de Rendimiento

Esta facilidad de uso tiene un precio: POE::Component::Server::TCP a menudo funciona significativamente más lento que un servidor comparable escrito con POE::Wheel::SocketFactory y POE::Wheel::ReadWrite.

Si el rendimiento es tu objetivo principal, select_read() y select_write() de POE::Kernel funcionan de manera similar a IO::Select, pero tu código será portable a través de cada bucle de eventos que POE soporte.

Consideraciones Especiales

POE::Component::Server::TCP está escrito para ser fácil para los casos de uso más comunes. Los programas con necesidades más especiales deberían considerar usar POE::Wheel::SocketFactory y POE::Wheel::ReadWrite en su lugar. Estos son módulos de nivel inferior y su uso requiere más esfuerzo. Son más flexibles y personalizables, h

sin embargo.

MÉTODOS PÚBLICOS

new

new() inicia un servidor basado en POE::Component::Server::TCP y devuelve un ID de sesión para la sesión maestra de escucha. Toda la gestión de errores se realiza dentro del servidor, a través de las devoluciones de llamada "Error" y "ClientError".

El servidor puede cerrarse enviando un evento de "shutdown" a la sesión maestra, ya sea por su ID o por el nombre que se le dio con el parámetro "Alias".

POE::Component::Server::TCP realiza mucho trabajo en su constructor. El objetivo del diseño es trasladar la mayor parte de la sobrecarga a la construcción única para que el tiempo de ejecución continuo tenga menos sobrecarga. Debido a esto, el constructor del servidor puede tomar un número de parámetros bastante desalentador.

POE::Component::Server::TCP siempre devuelve un ID de sesión POE::Session para la sesión que estará escuchando nuevas conexiones.

Muchos de los parámetros del constructor se han descrito anteriormente. Se vuelven a cubrir brevemente a continuación.

Configuración de la sesión del servidor

Estos parámetros del constructor afectan a la sesión de escucha principal de POE::Component::Server::TCP.

Acceptor

"Acceptor" define una referencia de CÓDIGO que el "SuccessEvent" de POE::Wheel::SocketFactory activará para manejar nuevas conexiones. Por lo tanto, los parámetros pasados a "Acceptor" son idénticos a los dados a "SuccessEvent".

"Acceptor" es opcional; el manejador predeterminado creará una nueva sesión para cada conexión. Todos los parámetros del constructor "Client" se utilizan para personalizar esta sesión. En otras palabras, "ClientInput" y similares **no se usan cuando se establece **"Acceptor"** **.

El "Acceptor" predeterminado agrega una conveniencia y flexibilidad significativas a POE::Component::Server::TCP, pero no siempre es adecuado para todas las aplicaciones. En algunos casos, un "Acceptor" personalizado o incluso crear uno propio con POE::Wheel::SocketFactory y POE::Wheel::ReadWrite puede ser mejor y/o más rápido.

Acceptor => sub {
  my ($socket, $remote_address, $remote_port) = @_[ARG0..ARG2];
  # Configurar algo para interactuar con el cliente.
}

Address

"Address" define una única dirección de interfaz a la que se enlazará el servidor. Por defecto es INADDR_ANY o INADDR6_ANY, cuando se utiliza IPv4 o IPv6, respectivamente. A menudo se usa con "Port".

El valor en "Address" se pasa al parámetro "BindAddress" de POE::Wheel::SocketFactory, por lo que puede estar en cualquier formato que admita ese módulo. En el momento de escribir esto, puede ser un cuádruple IPv4 con puntos, una dirección IPv6, un nombre de host o una dirección de Internet empaquetada. Ver también "Hostname".

Address => '127.0.0.1'   # Localhost IPv4
Address => "::1"         # Localhost IPv6

Alias

"Alias" es un nombre opcional que se dará a la sesión de escucha maestra del servidor. Los eventos enviados a este nombre no se entregarán a las conexiones individuales.

El "Alias" del servidor puede ser importante si es necesario apagar un servidor.

sub sigusr1_handler {
  $_[KERNEL]->post(chargen_server => 'shutdown');
  $_[KERNEL]->sig_handled();
}

Concurrency

"Concurrency" controla cuántas conexiones pueden estar activas al mismo tiempo. Por defecto es -1, lo que permite a POE::Component::Server::TCP aceptar conexiones concurrentes hasta que el proceso se quede sin recursos.

Establecer "Concurrency" a 0 impide que el servidor acepte nuevas conexiones. Esto puede ser útil si un servidor debe realizar una inicialización larga antes de permitir conexiones. Cuando la inicialización finaliza, puede ceder (set_concurrency => -1) para habilitar conexiones. De manera similar, un servidor en ejecución puede ceder (set_concurrency => 0) o cualquier otro número para ajustar dinámicamente su concurrencia. Ver "EVENTOS" para más sobre el evento set_concurrency.

Nota: Para que "Concurrency" funcione con un "Acceptor" personalizado, la sesión de escucha del servidor debe recibir un evento "disconnected" cada vez que los clientes se desconectan. De lo contrario, el oyente no puede mediar entre sus conexiones.

Ejemplo:

Acceptor => sub {
  # ....
  POE::Session->create(
    # ....
    inline_states => {
      _start => sub {
        # ....
        # recordar quién es nuestro padre
        $_[HEAP]->{server_tcp} = $_[SENDER]->ID;
        # ....
      },
      got_client_disconnect => sub {
        # ....
        $_[KERNEL]->post( $_[HEAP]->{server_tcp} => 'disconnected' );
        # ....
      }
    }
  );
}

Domain

"Domain" establece la familia de direcciones o protocolos dentro de la cual operar. El "Domain" puede ser cualquier valor que POE::Wheel::SocketFactory admita. AF_INET (espacio de direcciones de Internet) se usa por defecto.

Use AF_INET6 para soporte IPv6. Esta constante es exportada por Socket o Socket6, dependiendo de su versión de Perl. Asegúrese también de tener instalado Socket::GetAddrInfo, que es requerido por POE::Wheel::SocketFactory para soporte IPv6.

Error

"Error" es la devolución de llamada que se invocará cuando el socket del servidor informe un error. La devolución de llamada de Error se usará para manejar el FailureEvent de POE::Wheel::SocketFactory, por lo que recibirá los mismos parámetros que se discuten allí.

Se proporcionará un manejador de errores predeterminado si se omite Error. El manejador predeterminado registrará el error en STDERR y cerrará el servidor. Se permitirá que las conexiones activas completen sus transacciones.

Error => sub {
  my ($syscall_name, $err_num, $err_str) = @_[ARG0..ARG2];
  # Manejar el error.
}

Hostname

"Hostname" es el nombre opcional no empaquetado de la interfaz a la que se enlazará el servidor TCP. El nombre de host siempre se resolverá a través de inet_aton() y, por lo tanto, puede ser un cuádruple con puntos o un nombre. La resolución de nombres es una acción de inicio única; no hay penalizaciones de tiempo de ejecución continuas por usarla.

"Hostname" garantiza la resolución de nombres, mientras que "Address" no. Por lo tanto, se prefiere usar "Hostname" en casos donde la resolución debe realizarse siempre.

InlineStates

"InlineStates" es opcional. Si se especifica, debe contener un hashref de devoluciones de llamada nombradas. Su sintaxis es la del parámetro inline_states de POE:Session->create().

Recuerde: Estos manejadores InlineStates se agregarán a las sesiones de cliente, no a la sesión de escucha principal. Un yield() en el oyente no llegará a estos manejadores.

Si POE::Kernel::ASSERT_USAGE está habilitado, el constructor hará croak() si detecta un estado que utiliza internamente. Por ejemplo, utilice las devoluciones de llamada "Started" y "Stopped" si desea especificar sus propios eventos "_start" y "_stop" respectivamente.

ObjectStates

Si se especifica "ObjectStates", debe contener una referencia de array de objetos y los eventos que manejarán. La referencia de array debe seguir la sintaxis del parámetro object_states de POE::Session->create().

Recuerde: Estos manejadores ObjectStates se agregarán a las sesiones de cliente, no a la sesión de escucha principal. Un yield() en el oyente no llegará a estos manejadores.

Si POE::Kernel::ASSERT_USAGE está habilitado, el constructor hará croak() si detecta un estado que utiliza internamente. Por ejemplo, utilice las devoluciones de llamada "Started" y "Stopped" si desea especificar sus propios eventos "_start" y "_stop" respectivamente.

PackageStates

Cuando se establece el "PackageStates" opcional, debe contener una referencia de array de nombres de paquetes y los eventos que manejarán. La referencia de array debe seguir la sintaxis del parámetro package_states de POE::Session->create().

Recuerde: Estos manejadores PackageStates se agregarán a las sesiones de cliente, no a la sesión de escucha principal. Un yield() en el oyente no llegará a estos manejadores.

Si POE::Kernel::ASSERT_USAGE está habilitado, el constructor hará croak() si detecta un estado que utiliza internamente. Por ejemplo, utilice las devoluciones de llamada "Started" y "Stopped" si desea especificar sus propios eventos "_start" y "_stop" respectivamente.

Port

"Port" contiene el puerto al que se enlazará el socket de escucha. Por defecto es 0, lo que generalmente permite al sistema operativo elegir un puerto al azar.

Port => 30023

A menudo se usa con "Address".

Started

"Started" establece una devolución de llamada opcional que se invocará dentro del contexto de la sesión del servidor principal. Notifica al servidor que ha comenzado completamente. Los parámetros de la devolución de llamada son los habituales para el manejador _start de una sesión.

Stopped

"Stopped" establece una devolución de llamada opcional que se invocará dentro del contexto de la sesión del servidor principal. Notifica al servidor que se ha detenido por completo. Los parámetros de la devolución de llamada son los habituales para el manejador _stop de una sesión.

ListenerArgs

"ListenerArgs" se pasa a la sesión del oyente como el parámetro "args". En otras palabras, debe ser una referencia de array, y los valores se pasan al manejador "Started" como ARG0, ARG1, etc.

Configuración de la sesión de conexión

Estos parámetros del constructor afectan a las sesiones individuales que interactúan con las conexiones establecidas.

ClientArgs

"ClientArgs" es opcional. Cuando se especifica, contiene una REFERENCIA DE ARRAY que se expandirá un nivel y se pasará a la devolución de llamada "ClientConnected" en @_[A

RG0..$#_

ClientConnected

Cada nueva conexión de cliente es manejada por una instancia nueva de POE::Session. "ClientConnected" es una devolución de llamada que notifica a la aplicación cuando la sesión de un cliente se inicia y está lista para operar. A menudo se envían banners al cliente remoto desde esta devolución de llamada.

Los parámetros @_[ARG0..$#_] de "ClientConnected" son una copia de los valores en la referencia del array del parámetro constructor "ClientArgs". Los otros miembros de @_ son estándar para un manejador de inicio de POE::Session.

"ClientConnected" se llama una vez por inicio de sesión. Nunca se llamará dos veces para la misma conexión.

ClientConnected => sub {
  $_[HEAP]{client}->put("Hello, client!");
  # Otra inicialización del cliente aquí.
},

ClientDisconnected

"ClientDisconnected" es una devolución de llamada que se invocará cuando el cliente se desconecte o haya sido desconectado por el servidor. Es útil para limpiar información global del cliente, como estructuras de salas de chat. Las devoluciones de llamada "ClientDisconnected" reciben los parámetros habituales de POE, pero no se incluye nada especial.

ClientDisconnected => sub {
  warn "Cliente desconectado"; # registrarlo
}

ClientError

La devolución de llamada "ClientError" se invoca cuando un socket de cliente informa un error. "ClientError" se llama con los parámetros habituales de POE, más los parámetros de error comunes: $_[ARG0] describe lo que estaba sucediendo en el momento del fallo. $_[ARG1] y $_[ARG2] contienen las versiones numéricas y de cadena de $!, respectivamente.

"ClientError" es opcional. Si se omite, POE::Component::Server::TCP proporcionará una devolución de llamada predeterminada que registra la mayoría de los errores en STDERR.

Si "ClientShutdownOnError" está establecido, la conexión se cerrará después de que "ClientError" retorne. Si se especifica "ClientDisconnected", se llamará durante la limpieza de la sesión del cliente.

"ClientError" es activado por el ErrorEvent de POE::Wheel::ReadWrite, por lo que sigue el formato de ese evento. Consulte la documentación de ErrorEvent en POE::Wheel::ReadWrite para obtener más detalles.

ClientError => sub {
  my ($syscall_name, $error_num, $error_str) = @_[ARG0..ARG2];
  # Manejar el error del cliente aquí.
}

ClientFilter

"ClientFilter" especifica el objeto o clase POE::Filter que analizará la entrada de cada cliente y serializará la salida antes de enviarla a cada cliente.

"ClientFilter" puede ser un SCALAR, en cuyo caso debe nombrar la clase POE::Filter a usar. Cada nueva conexión recibirá un filtro recién instanciado de esa clase. No se pasarán parámetros del constructor.

ClientFilter => "POE::Filter::Stream",

Algunos filtros requieren parámetros del constructor. Estos pueden especificarse mediante un ARRAYREF. El primer elemento es el nombre de la clase POE::Filter, y los elementos subsiguientes se pasan al constructor de la clase.

ClientFilter => [ "POE::Filter::Line", Literal => "\n" ],

"ClientFilter" también puede recibir un objeto POE::Filter arquetípico. En este caso, cada nueva sesión de cliente recibirá un clone() del objeto proporcionado.

ClientFilter => POE::Filter::Line->new(Literal => "\n"),

"ClientFilter" es opcional. El componente usará "POE::Filter::Line" si se omite. Hay "ClientInputFilter" y "ClientOutputFilter" si desea especificar un filtro diferente para ambas direcciones.

Los módulos de filtro no se cargan automáticamente. Asegúrese de que el programa cargue la clase antes de usarla.

ClientFlushed

"ClientFlushed" expone el "FlushedEvent" de POE::Wheel::ReadWrite como una devolución de llamada. Se llama cada vez que el búfer de salida del cliente se ha vaciado completamente en el socket del cliente. En este punto, es seguro cerrar el socket sin perder datos.

"ClientFlushed" es útil para servidores de streaming, donde un evento "flushed" señala la necesidad de enviar más datos.

ClientFlushed => sub {
  my $data_source = $_[HEAP]{file_handle};
  my $read_count = sysread($data_source, my $buffer = "", 65536);
  if ($read_count) {
    $_[HEAP]{client}->put($buffer);
  }
  else {
    $_[KERNEL]->yield("shutdown");
  }
},

El "Acceptor" predeterminado de POE::Component::Server::TCP asegura que los datos se vacíen antes de finalizar el cierre de un cliente.

ClientInput

"ClientInput" define una devolución de llamada por conexión para manejar la entrada del cliente. Esta devolución de llamada recibe sus parámetros directamente del "InputEvent" de POE::Wheel::ReadWrite. ARG0 contiene el registro de entrada, cuyo formato está definido por "ClientFilter" o "ClientInputFilter". ARG1 tiene el ID único de la rueda, etc. Consulte POE:Wheel::ReadWrite para una descripción detallada de "InputEvent".

"ClientInput" y "Acceptor" son mutuamente excluyentes. Habilitar uno prohíbe el otro.

ClientInput => sub {
  my $input = $_[ARG0];
  $_[HEAP]{wheel}->put("Dijiste: $input");
},

ClientInputFilter

"ClientInputFilter" se usa con "ClientOutputFilter" para especificar diferentes protocolos para entrada y salida. Ambos deben usarse juntos. Ambos siguen el mismo uso que "ClientFilter". Anula el filtro establecido por "ClientFilter".

ClientInputFilter  => [ "POE::Filter::Line", Literal => "\n" ],
ClientOutputFilter => 'POE::Filter::Stream',

ClientOutputFilter

"ClientOutputFilter" se usa con "ClientInputFilter" para especificar diferentes protocolos para entrada y salida. Ambos deben usarse juntos. Ambos siguen el mismo uso que "ClientFilter". Anula el filtro establecido por "ClientFilter".

ClientInputFilter  => POE::Filter::Line->new(Literal => "\n"),
ClientOutputFilter => 'POE::Filter::Stream',

ClientShutdownOnError

"ClientShutdownOnError" indica al componente si las conexiones de cliente deben cerrarse automáticamente si se detecta un error. Por defecto es "verdadero". Establecerlo en falso (0, undef, "") desactiva esta función.

La aplicación es responsable de lidiar con los errores del cliente si esta función está deshabilitada. No hacerlo puede hacer que el componente emita un flujo constante de errores, eventualmente sobrecargando la aplicación con conexiones muertas que se salen de control.

SessionParams

"SessionParams" especifica parámetros adicionales que se pasarán al constructor de "SessionType" en el momento de la creación. Debe ser una referencia de array.

SessionParams => [ options => { debug => 1, trace => 1 } ],

Nota: POE::Component::Server::TCP suministra sus propios parámetros de constructor de POE::Session. Los conflictos entre estos y "SessionParams" pueden hacer que el componente se comporte de manera errática. Para evitar tales problemas, limite SessionParams al hash "options". Consulte POE::Session para ver las opciones conocidas.

Podríamos habilitar otras opciones más adelante. Por favor, háganos saber si necesita algo.

SessionType

"SessionType" especifica la subclase de POE::Session que se creará para cada nueva conexión de cliente. "POE::Session" es el valor predeterminado.

SessionType => "POE::Session::MultiDispatch"

EVENTOS

Es posible manipular un componente de servidor TCP enviándole mensajes.

Comandos Principales del Servidor

Estos eventos deben enviarse al servidor principal, generalmente por el alias establecido en su parámetro Alias.

disconnected

El evento "disconnected" informa al servidor TCP que se cerró una conexión. Es necesario cuando se usa "Concurrency" con una devolución de llamada "Acceptor". El Acceptor personalizado debe proporcionar su propia notificación de desconexión para que la lógica de conteo de conexiones del servidor funcione.

De lo contrario, se aceptarán clientes de Concurrency, y luego no más. El servidor nunca sabrá cuándo se han desconectado los clientes.

set_concurrency

"set_concurrency" establece el número de conexiones simultáneas que el servidor estará dispuesto a aceptar. Consulte "Concurrency" para obtener más detalles. "set_concurrency" debe tener un parámetro: el nuevo recuento máximo de conexiones.

$kernel->call("mi_alias_de_servidor", "set_concurrency", $max_count);

shutdown

El evento "shutdown" inicia un cierre elegante del servidor. No se aceptarán nuevas conexiones. Se permitirá que las conexiones existentes terminen. El servidor se destruirá después de que finalice la última conexión.

Comandos por Conexión

Estos comandos afectan a cada sesión de conexión de cliente.

shutdown

Enviar "shutdown" a una sesión de cliente individual instruye al servidor para que cierre elegantemente esa conexión. No se recibirá más entrada y se enviará cualquier salida en búfer antes de que finalice la sesión.

Las sesiones de cliente generalmente hacen yield("shutdown") cuando desean desconectar al cliente.

ClientInput => sub {
  if ($_[ARG0] eq "quit") {
    $_[HEAP]{client}->put("¡Adiós!");
    $_[KERNEL]->yield("shutdown");
    return;
  }

POE::Component::Server::TCP(3pm)

NAME

POE::Component::Server::TCP - A generic TCP server component for POE

SYNOPSIS

 use POE::Component::Server::TCP;

 my $server = POE::Component::Server::TCP->new(
     Alias => 'my_tcp_server',
     Port => 8080,
     ClientConnected => \&client_connected_handler,
     ClientDisconnected => \&client_disconnected_handler,
     ClientInput => \&client_input_handler,
 );

 POE::Kernel->run();

 sub client_connected_handler {
     my ($session, $heap, $client) = @_[SESSION, HEAP, ARG0];
     # Called when a client connects
     # $session is the session for this client
     # $heap is the session's heap
     # $client is the POE::Wheel::ReadWrite object for this client
     print "Client connected from ", $heap->{remote_ip}, ":", $heap->{remote_port}, "\n";
     $client->send("Welcome!\n");
 }

 sub client_disconnected_handler {
     my ($session, $heap) = @_[SESSION, HEAP];
     # Called when a client disconnects
     print "Client disconnected: ", $heap->{remote_ip}, "\n";
 }

 sub client_input_handler {
     my ($session, $heap, $input) = @_[SESSION, HEAP, ARG0];
     # Called when data is received from a client
     # $input is the data received
     print "Received from client: ", $input;
     $heap->{client}->send("You said: $input");
 }

DESCRIPTION

POE::Component::Server::TCP is a generic TCP server that can be used as a building block for creating network servers. It handles the low-level details of accepting client connections, managing them, and passing data back and forth.

The component creates a master session that listens for incoming connections. When a connection is accepted, it spawns a new session for that client, providing a convenient interface for handling client-specific data and events.

PUBLIC METHODS

new()
Creates a new POE::Component::Server::TCP object.
Options
Alias
An optional string alias for the master listening session.
BindAddr
The IP address to bind the listening socket to. Defaults to any address (usually 0.0.0.0).
ClientConnected
A callback subref that will be called when a client connects. It receives the client's session, heap, and the POE::Wheel::ReadWrite object.
ClientDisconnected
A callback subref that will be called when a client disconnects. It receives the client's session and heap.
ClientInput
A callback subref that will be called when data is received from a client. It receives the client's session, heap, and the data received.
Concurrency
The maximum number of concurrent client connections allowed. Defaults to unlimited.
Port
The port number to listen on. This is a required parameter.
Reconnect
Boolean. If true, the component will attempt to re-bind to the listening port if it fails.
ReuseAddr
Boolean. If true, the SO_REUSEADDR socket option will be set.
ServerMethod
A callback subref that will be called to create the server's session. Defaults to creating a POE::Session.

EVENTS

The component handles the following events internally:

connection_$_
This event is triggered when a new client connection is accepted. It creates a new session for the client and calls the ClientConnected callback.
read_$_
This event is triggered when data is received from a client. It calls the ClientInput callback.
disconnect_$_
This event is triggered when a client disconnects. It calls the ClientDisconnected callback.
shutdown
This event is used to shut down the server component gracefully.

Reserved HEAP Members

Unlike most POE modules, POE::Component::Server::TCP stores data in the client sessions' HEAPs. These values are provided as conveniences for application developers.

HEAP Members for Master Listening Sessions

The master listening session holds different data than client connections.

alias

$_[HEAP]{alias} contains the server's Alias.

concurrency

$_[HEAP]{concurrency} remembers the server's "Concurrency" parameter.

connections

$_[HEAP]{connections} is used to track the current number of concurrent client connections. It's incremented whenever a new connection is accepted, and it's decremented whenever a client disconnects.

listener

$_[HEAP]{listener} contains the POE::Wheel::SocketFactory object used to listen for connections and accept them.

HEAP Members for Connection Sessions

These data members exist within the individual connections' sessions.

client

$_[HEAP]{client} contains a POE::Wheel::ReadWrite object used to interact with the client. All POE::Wheel::ReadWrite methods work.

got_an_error

$_[HEAP]{got_an_error} remembers whether the client connection has already encountered an error. It is part of the shutdown-on-error procedure.

remote_ip

$_[HEAP]{remote_ip} contains the remote client's numeric address in human-readable form.

remote_port

$_[HEAP]{remote_port} contains the remote client's numeric socket port in human-readable form.

remote_addr

$_[HEAP]{remote_addr} contains the remote client's packed socket address in computer-readable form.

shutdown

$_[HEAP]{shutdown} is true if the client is in the process of shutting down. The component uses it to ignore client input during shutdown, and to close the connection after pending output has been flushed.

shutdown_on_error

$_[HEAP]{shutdown_on_error} remembers whether the client connection should automatically shut down if an error occurs.

BUGS

This looks nothing like what Ann envisioned.

This component currently does not accept many of the options that POE::Wheel::SocketFactory does.

This component will not bind to several addresses at once. This may be a limitation in SocketFactory, but it's not by design.

This component needs better error handling.

Some use cases require different session classes for the listener and the connection handlers. This isn't currently supported. Please send patches. :)
