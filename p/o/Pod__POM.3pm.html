Pod::POM(3) Documentación de Perl aportada por el usuario Pod::POM(3)

NOMBRE

Pod::POM - Modelo de Objetos de Pod

SINOPSIS

use Pod::POM;
my $parser = Pod::POM->new(\%options);
# parsear desde una cadena de texto
my $pom = $parser->parse_text($text)
    || die $parser->error();
# parsear desde un archivo especificado por nombre o manejador de archivo
my $pom = $parser->parse_file($file)
    || die $parser->error();
# parsear desde texto o archivo 
my $pom = $parser->parse($text_or_file)
    || die $parser->error();
# examinar cualquier advertencia generada
foreach my $warning ($parser->warnings()) {
    warn $warning, "\n";
}
# imprimir tabla de contenidos usando el título de cada =head1
foreach my $head1 ($pom->head1()) {
    print $head1->title(), "\n";
}
# imprimir cada sección
foreach my $head1 ($pom->head1()) {
    print $head1->title(), "\n";
    print $head1->content();
}
# imprimir el documento completo como HTML
use Pod::POM::View::HTML;
print Pod::POM::View::HTML->print($pom);
# crear vista personalizada
package My::View;
use parent qw( Pod::POM::View::HTML );
sub view_head1 {
    my ($self, $item) = @_;
    return '<h1>', 
           $item->title->present($self), 
           "</h1>\n",
           $item->content->present($self);
}

package main;
print My::View->print($pom);

DESCRIPCIÓN

Este módulo implementa un analizador para convertir documentos Pod en una forma de modelo de objetos simple, conocida en adelante como Modelo de Objetos de Pod. El modelo de objetos se genera como un árbol jerárquico de nodos, cada uno de los cuales representa un elemento diferente del documento original. El árbol se puede recorrer manualmente y los nodos examinar, imprimir o manipular de otra manera. Además, Pod::POM soporta y proporciona objetos de vista que pueden recorrer automáticamente el árbol, o una sección del mismo, y generar una representación de salida en una u otra forma.

Veamos un documento Pod típico a modo de ejemplo.

=head1 NOMBRE
Mi::Módulo - solo otro Mi::Módulo
=head1 DESCRIPCIÓN
Este es Mi::Módulo, un pedazo de código Perl profundamente genial.
=head2 MÉTODOS
Mi::Módulo implementa los siguientes métodos
=over 4
=item new(\%config)
Este es el método constructor. Acepta las siguientes 
opciones de configuración:
=over 4
=item nombre
El nombre de la cosita.
=item color
El color de la cosita.
=back
=item print()
Esto imprime la cosita.
=back
=head1 AUTOR
Mi::Módulo fue escrito por mí E<lt>mí@aquí.orgE<gt>

Este documento contiene 3 secciones principales, NOMBRE, DESCRIPCIÓN y AUTOR, cada una de las cuales está delimitada por una etiqueta de apertura "=head1". NOMBRE y AUTOR contienen cada una una sola línea de texto, pero DESCRIPCIÓN es más interesante. Contiene una línea de texto seguida de la subsección "=head2", MÉTODOS. Esta contiene una línea de texto y una lista que se extiende desde "=over 4" hasta el "=back" final justo antes de que comience la sección AUTOR. La lista contiene 2 elementos, new(\%config), que a su vez contiene algo de texto y una lista de 2 elementos, y print().

Presentado como texto plano y utilizando indentación para indicar la anidación de elementos, el modelo entonces se parece a esto:

NOMBRE
    Mi::Módulo - solo otro Mi::Módulo
DESCRIPCIÓN
    Este es Mi::Módulo, un pedazo de código Perl profundamente genial.
    MÉTODOS
        Mi::Módulo implementa los siguientes métodos
        * new(\%config)
            Este es el método constructor. Acepta las 
            siguientes opciones de configuración:
            * nombre
                El nombre de la cosita.
            * color
                El color de la cosita.
        * item print()
            Esto imprime la cosita.
AUTOR
    Mi::Miódulo fue escrito por mí <mí@aquí.org>

Aquellos familiarizados con XML pueden preferir pensarlo de la siguiente manera:

<pod>
  <head1 title="NOMBRE">
    <p>Mi::Módulo - solo otro Mi::Módulo</p>
  </head1>
  <head1 title="DESCRIPCIÓN">
    <p>Este es Mi::Módulo, un pedazo de código Perl profundamente 
       genial.</p>
    <head2 title="MÉTODOS">
      <p>Mi::Módulo implementa los siguientes métodos</p>
      <over indent=4>
        <item title="item new(\%config)">
          <p>Este es el método constructor. Acepta las 
             siguientes opciones de configuración:</p>
          <over indent=4>
            <item title="nombre">
              <p>El nombre de la cosita.</p>
            </item>
            <item title="color">
              <p>El color de la cosita.</p>
            </item>
          </over>
        </item>
        <item title="print()">
          <p>Esto imprime la cosita.</p>
        </item>
      </over>
    </head2>
  </head1>
  <head1 title="AUTOR">
    <p>Mi::Miódulo fue escrito por mí &lt;mí@aquí.org&gt;
  </head1>
</pod>

Noten cómo podemos hacer ciertas suposiciones sobre varios elementos. Por ejemplo, podemos asumir que cualquier sección "=head1" que encontremos inicia una nueva sección y termina implícitamente cualquier sección anterior. De manera similar, podemos asumir que un "=item" termina cuando comienza el siguiente, y así sucesivamente. En términos del ejemplo XML que se muestra arriba, estamos diciendo que somos lo suficientemente inteligentes como para agregar un elemento "</head1>" para terminar cualquier "<head1>" abierto previamente cuando encontramos una nueva etiqueta "=head1" en el documento de entrada.

Como sea que prefieras visualizar el contenido, todo se reduce al mismo modelo subyacente. El trabajo del módulo Pod::POM es leer un documento Pod de entrada y construir un modelo de objetos para representarlo en esta forma estructurada.

Cada nodo en el árbol (es decir, elemento en el documento) se representa mediante un objeto Pod::POM::Node::*. Estos encapsulan los atributos de un elemento (como el título de una etiqueta "=head1") y también actúan como contenedores para más objetos Pod::POM::Node::* que representan el contenido del elemento. En los nodos hoja, tenemos tipos de objetos simples para representar párrafos de texto formateado y literal y otros elementos básicos como estos.

Analizando Pod

El módulo Pod::POM implementa los métodos parse_file($file), parse_text($text) y parse($file_or_text) para analizar archivos Pod y texto de entrada. Devuelven un objeto Pod::POM::Node::Pod para representar la raíz del Modelo de Objetos de Pod, efectivamente el elemento "<pod>" en el árbol XML mostrado arriba.

use Pod::POM;
my $parser = Pod::POM->new();
my $pom = $parser->parse_file($filename)
    || die $parser->error();

Los métodos parse(), parse_text() y parse_file() devuelven undef en caso de error. El método error() puede ser llamado para recuperar el mensaje de error generado. Analizar un documento también puede generar advertencias no fatales. Estas pueden recuperarse a través del método warnings(), que devuelve una referencia a una lista en contexto de escalar o una lista de advertencias en contexto de lista.

foreach my $warn ($parser->warnings()) {
    warn $warn, "\n";
}

Alternativamente, la opción de configuración 'warn' puede ser establecida para que las advertencias se emitan automáticamente a través de warn() a medida que se encuentran.

my $parser = Pod::POM->new( warn => 1 );

Recorriendo el Modelo de Objetos

Una vez analizado un documento en un modelo de objetos, podemos seleccionar varios elementos de él. Cada nodo implementa métodos (a través de AUTOLOAD) que corresponden a los atributos y elementos de contenido permitidos dentro de él.

Así, para obtener la lista de secciones '=head1' dentro de nuestro documento analizado, haríamos lo siguiente:

my $sections = $pom->head1();

Métodos como este devolverán una lista de otros objetos Pod::POM::Node::* cuando se llamen en contexto de lista o una referencia a una lista en contexto de escalar. En este último caso, la lista está bendecida en la clase Pod::POM::Node::Content, lo que le da ciertas propiedades mágicas (más sobre eso más adelante).

Dada la lista de objetos Pod::POM::Node::Head1 devuelta por lo anterior, podemos imprimir los atributos de título de cada uno así:

foreach my $s (@$sections) {
    print $s->title();
}

Miremos la segunda sección, DESCRIPCIÓN.

my $desc = $sections->[1];

Podemos imprimir el título de cada subsección dentro de ella:

foreach my $ss ($desc->head2()) {
    print $s

Contenido del Elemento

Si conoces la estructura precisa de un documento antes de comenzar, todo va bien. Para casos más comunes cuando no lo sabes, cada nodo que pueda contener otros nodos proporciona un método 'content' que devuelve una lista completa de todos los otros nodos que contiene. El método 'type' puede llamarse en cualquier nodo para devolver el tipo de elemento (por ejemplo, 'head1', 'head2', 'over', 'item', etc).

foreach my $item ($pom->content()) {
    my $type = $item->type();
    if ($type eq 'head1') {
        ...
    }
    elsif ($type eq 'head2') {
        ...
    }
    ...
}

El contenido de un elemento se representa mediante una referencia a un listado, bendecido en la clase Pod::POM::Node::Content. Esto proporciona cierto mágico en forma de un operador de serialización sobrecargado que imprimirá automáticamente los contenidos del listado si imprimes el objeto mismo. En lenguaje claro, o más bien en lenguaje Perl puro, esto significa que puedes hacer cosas como las siguientes:

foreach my $head1 ($pom->head1()) {
    print '<h1>', $head1->title(), "</h1>\n\n";
    print $head1->content();
}
# imprimir todos los contenidos raíz
foreach my $item ($pom->content()) {
    print $item;
}
# lo mismo que arriba
print $pom->content();

En realidad, todos los objetos Pod::POM::Node::* proporcionan este mágico mismo, y intentarán hacer lo correcto para presentarse en el modo adecuado al imprimirse. Por lo tanto, los siguientes son todos válidos.

print $pom;                 # documento completo
print $pom->content();        # contenido del documento
print $pom->head1->[0];     # solo la primera sección
print $pom->head1();          # imprimir todas las secciones
foreach my $h1 ($pom->head1()) {
    print $h1->head2();     # imprimir todas las subsecciones
}

Vistas de Salida

Para entender cómo los diferentes elementos se presentan en "el modo adecuado", debemos introducir el concepto de una vista. Una vista es simplemente una particular forma de mirar el modelo. En términos reales, podemos pensar en una vista como algo tipo de tipo de salida generado por un convertidor de pod2whatever. Notablemente, podemos pensar en términos de leer un documento de entrada, construyendo un modelo de objeto Pod, y luego generando una vista HTML del documento, y/o una vista LaTeX, una vista de texto plano, y así sucesivamente.

Una vista se representa en este caso mediante un objeto clase que contiene métodos para mostrar cada uno de los diferentes tipos de elementos que puedan verse en cualquier documento Pod. Hay un método para mostrar secciones "=head1" (view_head1()), otro para mostrar secciones "=head2" (view_head2()), uno para "=over" (view_over()), otro para "=item" (view_item()), y así sucesivamente.

Si tenemos una referencia a un $node y sabemos que es un nodo 'head1', podemos llamar directamente al método correcto para que se muestre correctamente:

$view = 'Pod::POM::View::HTML';
$view->view_head1($node);

Por lo tanto, nuestro ejemplo anterior puede modificarse para ser ligeramente menos laborioso y más flexible.

foreach my $node ($pom->content) {
    my $type = $node->type();
    if ($type eq 'head1') {
        print $view->view_head1($node);
    }
    elsif ($type eq 'head2') {
        print $view->view_head2($node);
    }
    ...
}

Sin embargo, esto aún no es ideal. Para hacer vida más fácil, cada clase Pod::POM::Node::* hereda (o podría redefinirse) un método present($view) de la clase base Pod::POM::Node. Este método espera una referencia a un objeto de vista pasado como argumento y simplemente llama al método correspondiente view_xxx() del objeto de vista, pasándole a sí mismo como argumento. En lenguaje de objeto, esto se conoce como "doble desplazamiento". La belleza de ello es que no necesitas saber qué tipo de nodo tienes para poder imprimirlo. Tan solo pasa el nodo a un objeto de vista y deja que se encargue de lo restante.

foreach my $node ($pom->content) {
    print $node->present($view);
}

Si $node es un objeto Pod::POM::Node::Head1, entonces el método view_head1($node) se llama contra el objeto $view. De otra forma, si es un objeto Pod::POM::Node::Head2, el método view_head2($node) se dispara. Y así sucesivamente, con cada nodo sabiendo qué es y hacia dónde va, como si estuviera determinado por un instinto genéticamente pre-programado. Cumpliendo sus destinos, así se dice.

El doble desplazamiento permite evitar todos los control de tipo explícito y otros chistes, y dejar que los objetos nodales se encarguen de dónde deben dirigirse. A costa de una llamada adicional por nodo, obtenemos conveniencia del programa, y eso suele ser un buen chiste.

Vamos a ver cómo podrían ser implementados las clases de vista y nodo.

package Pod::POM::View::HTML;
sub view_pod {
    my ($self, $node) = @_;
    return $node->content->present($self);
}
sub view_head1 {
    my ($self, $node) = @_;
    return "<h1>", $node->title->present($self), "</h1>\n\n"
         . $node->content->present($self);
}
sub view_head2 {
    my ($self, $node) = @_;
    return "<h2>", $node->title->present($self), "</h2>\n\n"
         . $node->content->present($self);
}
...
package Pod::POM::Node::Pod;
sub present {
    my ($self, $view) = @_;
    $view->view_pod($self);
}
package Pod::POM::Node::Head1;
sub present {
    my ($self, $view) = @_;
    $view->view_head1($self);
}
package Pod::POM::Node::Head2;
sub present {
    my ($self, $view) = @_;
    $view->view_head2($self);
}
...

Algunos de los métodos view_xxx hacen llamadas a los objetos nodales para mostrar sus atributos y/o contenido. Esto se muestra, por ejemplo, en el método view_head1() mostrado arriba, donde el método imprime el título de la sección en "<h1>"..."</h1>" y después el contenido restante.

Nota: El atributo título se imprime llamando al método present() de su atributo, pasando por referencia el objeto actual del vist. Similarmente, el método present() para el contenido se llama con la oportunidad de hacer lo correcto mediante el objeto de vista.

Hay una buena oportunidad de que el atributo título sea texto regular, por lo que podríamos ser tentados a simplemente imprimir el título en lugar de llamar al método present().

sub view_head1 {
    my ($self, $node) = @_;
    # no es recomendable, preferir $node->title->present($self)
    return "<h1>", $node->title(), "</h1>\n\n", ...
}

Sin embargo, es totalmente válido que los atributos y otros elementos de texto, así como bloques de texto formatados, contengan secuencias de código como "B<this>" y "I<this>". Estos se usan para indicar estilos de markup diferentes, marcar referencias externas o ítems de índice, y así sucesivamente. Además, pueden contener "B<nested>" y "I<indefinitely>>". Pod::POM maneja todo esto al parsear tal texto, junto con cualquier secuencia incluida, en Yet Another Tree, la raíz del cual es un objeto Pod::POM::Node::Text, posiblemente conteniendo otros objetos Pod::POM::Node::Sequence. Cuando se presenta el texto, el árbol se camina automáticamente y se realizan callbacks relevantes contra la vista para cada tipo de secuencia. Los métodos llamados contra la vista están todos prefijados con 'view_seq_', como 'view_seq_bold', 'view_seq_italic'.

Ahora la magia real entra en juego. Puedes definir una vista para renderizar texto en un estilo específico:

package My::View::Text;
use parent qw( Pod::POM::View::Text );
sub view_seq_bold {
    my ($self, $text) = @_;
    return "*$text*";
}
sub view_seq_italic {
    my ($self, $text) = @_;
    return "_$text_";
}

Y otra vista para renderizarlo en otro estilo:

package My::View::HTML;
use parent qw( Pod::POM::View::HTML );
sub view_seq_bold {
    my ($self, $text) = @_;
    return "<b>$text</b>";
}
sub view_seq_italic {
    my ($self, $text) = @_;
    return "<i>$text</i>";
}

Luego, puedes fácilmente ver un modelo de objeto Pod en cualquiera de estos estilos:

my $text = 'My::View::Text';
my $html = 'My::View::HTML';
print $pom->present($text);
print $pom->present($html);

Y puedes aplicar esta técnica a cualquier nodo dentro del modelo de objeto.

print $pom->head1->[0]->present($text);
print $pom->head1->[0]->present($html);

En estos ejemplos, el vista pasado al método present() ha sido un nombre de clase. Por lo tanto, los métodos view_xxx se llaman como métodos de clase, como si escribieran:

My::View::Text->view_head1(...);

Si tu vista necesita mantener el estado, puedes crear un objeto de vista y pasarlo al método present().

my $view = My::View->new();
$node->present($view);

En este caso, los métodos view_xxx se llaman como métodos de objetos.

sub view_head1 {
    my ($self, $node) = @_;
    my $title = $node->title();
    if ($title eq 'NAME' && ref $self) {
        $self->{ title } = $title();
    }
    $self->SUPER::view_head1($node);
}

Cuando imprimes un objeto Pod::POM::Node::* o haces cualquier cosa que cause a Perl stringifyarlo (como incluirlo en una cadena como "like $this"), entonces su método present() se llama automáticamente. Cuando se llama sin un argumento de vista, el método present() utiliza el vist predeterminado especificado en $Pod::POM::DEFAULT_VIEW, que por defecto es 'Pod::POM::View::Pod'. Este vist regenera el documento original de Pod, aunque se debe señalar que el resultado generado puede no ser exactamente el mismo que el input. El parser es inteligente lo suficiente para detectar algunos errores comunes (como no cerrar una "=over" con una "=back") y los corrigir automáticamente. Por lo tanto, podrías encontrar un "=back" correctamente posicionado en el output, incluso si olvidaste agregarlo al input. Estas correcciones generan warnings no fatales que pueden ser examinados mediante el método warnings().

Puedes actualizar la variable $Pod::POM::DEFAULT_VIEW del paquete para establecer el d

en la vista predeterminada, o llamar al método default_view(). El método default_view() cargará automáticamente cualquier paquete que especifique. Si establece la variable del paquete directamente, debe asegurarse de que cualquier paquete requerido se haya precargado.

use My::View::HTML;
$Pod::POM::DEFAULT_VIEW = 'My::View::HTML';

o

Pod::POM->default_view('My::View::HTML');

Vistas de Template Toolkit

Una de las motivaciones para escribir este módulo fue facilitar la personalización de la documentación Pod para que se ajuste a su propio estilo o convenciones de formato locales. Al separar claramente el contenido (representado por el Modelo de Objetos Pod) del estilo de presentación (representado por una o más vistas), se vuelve mucho más fácil lograr esto.

La última versión de Template Toolkit (2.06 en el momento de escribir esto) proporciona un plugin Pod para interactuar con este módulo. También implementa una nueva directiva VIEW (pero experimental) que se puede utilizar para crear diferentes estilos de presentación para convertir Pod a otros formatos. Template Toolkit está disponible en CPAN:

http://www.cpan.org/modules/by-module/Template/

Las vistas de Template Toolkit son similares a los objetos Pod::POM::View descritos anteriormente, excepto que permiten que el estilo de presentación para cada componente Pod se escriba como un archivo de plantilla o un bloque en lugar de un método de objeto. La sintaxis y estructura exactas de la directiva VIEW están sujetas a cambios (dado que todavía es experimental), pero actualmente se puede utilizar para definir una vista algo así:

[% VIEW myview %]
   [% BLOCK view_head1 %]
      <h1>[% item.title.present(view) %]</h1>
      [% item.content.present(view) %]
   [% END %]

   [% BLOCK view_head2 %]
      <h2>[% item.title.present(view) %]</h2>
      [% item.content.present(view) %]
   [% END %]
   ...
[% END %]

Se proporciona un plugin para interactuar con el módulo Pod::POM:

[% USE pod %]
[% pom = pod.parse('/path/to/podfile') %]

La instancia del Modelo de Objetos Pod devuelta puede ser navegada y presentada a través de la vista de casi cualquier manera imaginable:

<h1>Tabla de Contenidos</h1>
<ul>
[% FOREACH section = pom.head1 %]
   <li>[% section.title.present(view) %]
[% END %]
</ul>
<hr>
[% FOREACH section = pom.head1 %]
   [% section.present(myview) %]
[% END %]

Puede pasar una referencia a la VISTA (myview) al método present() de un nodo Pod::POM:

[% pom.present(myview) %]       # presentar documento completo

O alternativamente llamar al método print() de la VISTA, pasando el nodo Pod::POM como argumento:

[% myview.print(pom) %]

Internamente, la vista llama al método present() en el nodo, pasándose a sí misma como argumento. Por lo tanto, es equivalente al ejemplo anterior.

El nodo Pod::POM y la vista se confabulan para "Hacer lo correcto" para procesar el bloque de plantilla correcto para el nodo. Una referencia al nodo está disponible dentro de la plantilla como la variable 'item'.

[% BLOCK view_head2 %]
   <h2>[% item.title.present(view) %]</h2>
   [% item.content.present(view) %]
[% END %]

La documentación de Template Toolkit contiene más información sobre la definición y el uso de vistas. Sin embargo, como se señaló anteriormente, esto puede estar sujeto a cambios o ser incompleto pendiente de un mayor desarrollo de la directiva VIEW.

MÉTODOS

new(\%config)

Método constructor que instancia y devuelve un nuevo objeto analizador Pod::POM.

use Pod::POM;
my $parser = Pod::POM->new();

Se puede pasar una referencia a un hash de opciones de configuración como argumento.

my $parser = Pod::POM->new( { warn => 1 } );

Para mayor comodidad, las opciones de configuración también se pueden pasar como una lista de pares (clave => valor).

my $parser = Pod::POM->new( warn => 1 );

Las siguientes opciones de configuración están definidas:

código
Esta opción se puede establecer para que todas las partes no-Pod del documento de entrada se almacenen dentro del modelo de objetos como elementos de 'código', representados por objetos de la clase Pod::POM::Node::Code. Está deshabilitada por defecto y las secciones de código se ignoran. 
my $parser = Pod::POM->new( code => 1 );
my $podpom = $parser->parse(\*DATA);
foreach my $code ($podpom->code()) {
    print "<pre>$code</pre>\n";
}
__DATA__
This is some program code.
=head1 NAME
...

Esto generará la siguiente salida:

<pre>This is some program code.</pre>

Tenga en cuenta que los elementos de código se almacenan dentro del elemento POM en el que se encuentran. Por ejemplo, el elemento de código incrustado a continuación entre secciones Pod se almacena en la matriz que se puede recuperar llamando a "$podpom->head1->[0]->code()".

=head1 NAME
My::Module::Name;
=cut
Some program code embedded in Pod.
=head1 SYNOPSIS
...
advertir
Las advertencias no críticas encontradas al analizar un documento Pod se almacenan internamente y están disponibles posteriormente a través del método warnings(). 
my $parser = Pod::POM->new();
my $podpom = $parser->parse_file($filename);
foreach my $warning ($parser->warnings()) {
    warn $warning, "\n";
}

La opción 'warn' se puede establecer para que las advertencias se activen automáticamente a través de warn() tan pronto como se encuentren.

my $parser = Pod::POM->new( warn => 1 );
my $podpom = $parser->parse_file($filename);

Si el valor de configuración se especifica como una referencia a una subrutina, se llamará al código cada vez que se active una advertencia, pasando el mensaje de advertencia como argumento.

sub my_warning {
    my $msg = shift;
    warn $msg, "\n";
};
my $parser = Pod::POM->new( warn => \&my_warning );
my $podpom = $parser->parse_file($filename);
meta
La opción 'meta' se puede establecer para permitir etiquetas "=meta" dentro del documento Pod. 
my $parser = Pod::POM->new( meta => 1 );
my $podpom = $parser->parse_file($filename);

Esta es una característica experimental que no forma parte del POD estándar. Por ejemplo:

=meta author Andy Wardley

Estos están disponibles como elementos de metadatos dentro del nodo raíz del POM analizado.

my $author = $podpom->metadata('author');

Consulte la sección METADATA a continuación para obtener más información.

parse_file($archivo)

Analiza el archivo especificado por nombre o referencia a un manejador de archivo. Devuelve una referencia a un objeto Pod::POM::Node::Pod que representa el nodo raíz del Modelo de Objetos Pod en caso de éxito. En caso de error, se devuelve undef y el mensaje de error generado se puede recuperar llamando a error().

my $podpom = $parser->parse_file($filename)
    || die $parser->error();
my $podpom = $parser->parse_file(\*STDIN)
    || die $parser->error();

Cualquier advertencia encontrada se puede examinar llamando al método warnings().

foreach my $warn ($parser->warnings()) {
    warn $warn, "\n";
}

parse_text($texto)

Analiza la cadena de texto Pod pasada como argumento en un Modelo de Objetos Pod, según parse_file().

parse($texto_o_$archivo)

Método de propósito general que intenta "Hacer lo correcto" llamando a parse_file() o parse_text() según el argumento pasado.

Se puede pasar una referencia a un hash como argumento que contenga una clave 'text' o 'file' y el valor correspondiente.

my $podpom = $parser->parse({ file => $filename })
    || die $parser->error();

De lo contrario, el argumento puede ser una referencia a un manejador de entrada que se pasa a parse_file().

my $podpom = $parser->parse(\*DATA)
    || die $parser->error();

Si el argumento es una cadena de texto que parece texto Pod (es decir, contiene '=' al principio de cualquier línea), se pasa a parse_text().

my $podpom = $parser->parse($podtext)
    || die $parser->error();

De lo contrario, se asume que es un nombre de archivo y se pasa a parse_file().

my $podpom = $parser->parse($podfile)
    || die $parser->error();

TIPOS DE NODOS, ATRIBUTOS Y ELEMENTOS

Esta sección enumera los diferentes nodos que pueden estar presentes en un Modelo de Objetos Pod. Estos se implementan como instancias de objetos Pod::POM::Node::* (por ejemplo, head1 => Pod::POM::Node::Head1). Para presentar un nodo, una vista debe implementar un método que corresponda al nombre del nodo prefijado por 'view_' (por ejemplo, head1 => view_head1()).

pod
El nodo "pod" se utiliza para representar el nodo raíz del Modelo de Objetos Pod.

Elementos de contenido: head1, head2, head3, head4, over, begin, for, verbatim, text, code.

head1
Un nodo "head1" contiene el contenido Pod desde una etiqueta "=head1" hasta la siguiente etiqueta "=head1" o el final del archivo.

Atributos: title

Elementos de contenido: head2, head3, head4, over, begin, for, verbatim, text, code.

head2
Un nodo "head2" contiene el contenido Pod desde una etiqueta "=head2" hasta la siguiente etiqueta "=head1" o "=head2" o el final del archivo.

Atributos: title

Elementos de contenido: head3, head4, over, begin, for, verbatim, text, code.

head3
Un nodo "head3" contiene el contenido Pod desde una etiqueta "=head3"n> etiqueta hasta la siguiente "=head1", "=head2" o "=head3" etiqueta o el final del archivo.

Atributos: title

Elementos de contenido: head4, over, begin, for, verbatim, text, code.

head4
Un nodo "head4" contiene el contenido Pod desde una etiqueta "=head4" hasta la siguiente etiqueta "=head1", "=head2", "=head3" o "=head4" o el final del archivo.

Atributos: title

Elementos de contenido: over, begin, for, verbatim, text, code.

over
El nodo "over" encierra el contenido Pod en una lista que comienza en una etiqueta "=over" y continúa hasta la etiqueta "=back" coincidente. Las listas pueden anidarse indefinidamente.

Atributos: indent (por defecto: 4)

Elementos de contenido: over, item, begin, for, verbatim, text, code.

item
El nodo "item" encierra el contenido Pod en un elemento de lista que comienza con una etiqueta "=item" y continúa hasta la siguiente etiqueta "=item" o una etiqueta "=back" que termina la lista.

Atributos: title (por defecto: *)

Elementos de contenido: over, begin, for, verbatim, text, code.

begin
Un nodo "begin" encierra el contenido Pod en un bloque condicional que comienza con una etiqueta "=begin" y continúa hasta la siguiente etiqueta "=end".

Atributos: format

Elementos de contenido: verbatim, text, code.

for
Un nodo "for" contiene un único párrafo con texto relevante para un formato particular.

Atributos: format, text

verbatim
Un nodo "verbatim" contiene un párrafo de texto literal que está prefijado por espacios en blanco en el documento Pod fuente (es decir, indentado).

Atributos: text

text
Un nodo "text" contiene un párrafo de texto regular. Este puede incluir secuencias incrustadas en línea.

Atributos: text

code
Un nodo "code" contiene código Perl que, por defecto, no se considera parte de un documento Pod. La opción de configuración "code" debe establecerse para que Pod::POM genere bloques de código; de lo contrario, se ignoran.

Atributos: text

SECUENCIAS EN LÍNEA

Se permiten secuencias incrustadas dentro de bloques de texto regulares (es decir, no literales) y atributos de título. Para presentar estas secuencias, una vista debe implementar métodos que correspondan al nombre de la secuencia, prefijados con 'view_seq_' (por ejemplo, bold => view_seq_bold()).

code
Extracto de código, por ejemplo, C<mi código>
bold
Texto en negrita, por ejemplo, B<texto en negrita>
italic
Texto en cursiva, por ejemplo, I<texto en cursiva>
link
Un enlace (referencia cruzada), por ejemplo, L<Mi::Módulo>
space
Texto que contiene un espacio de no separación, por ejemplo, S<Buffy La Cazavampiros>
file
Un nombre de archivo, por ejemplo, F</etc/lilo.conf>
index
Una entrada de índice, por ejemplo, X<Ángel>
zero
Un carácter de ancho cero, por ejemplo, Z<>
entity
Una escapada de entidad, por ejemplo, E<lt>

MÓDULOS Y HERRAMIENTAS INCLUIDOS

La distribución del módulo Pod::POM incluye varios objetos de vista de ejemplo para renderizar Modelos de Objetos Pod en formatos particulares. Estos están incompletos y pueden requerir algo de trabajo adicional, pero actualmente sirven para ilustrar el principio y pueden usarse como base para sus propios objetos de vista.

Pod::POM::View::Pod
Regenera el modelo como Pod.
Pod::POM::View::Text
Presenta el modelo como texto plano.
Pod::POM::View::HTML
Presenta el modelo como HTML.

Se proporciona un script para convertir documentos Pod a otros formatos utilizando los objetos de vista proporcionados. El script "pom2" debe llamarse con dos argumentos, el primero especificando el formato de salida y el segundo el nombre del archivo de entrada. Por ejemplo:

$ pom2 text Mi/Módulo.pm > README
$ pom2 html Mi/Módulo.pm > ~/public_html/Mi/Módulo.html

También puede crear enlaces simbólicos al script si lo prefiere y dejar que determine el formato de salida a partir de su propio nombre.

$ ln -s pom2 pom2text       
$ ln -s pom2 pom2html
$ pom2text Mi/Módulo.pm > README
$ pom2html Mi/Módulo.pm > ~/public_html/Mi/Módulo.html

La distribución también contiene un script trivial, "podlint" (anteriormente "pomcheck"), que verifica la corrección de un documento Pod simplemente analizándolo en un Modelo de Objeto Pod con las advertencias habilitadas. Las advertencias se imprimen en STDERR.

$ podlint Mi/Módulo.pm

La opción "-f" puede establecerse para que el script intente corregir cualquier problema que encuentre. La salida Pod regenerada se imprime en STDOUT.

$ podlint -f Mi/Módulo.pm > newfile

METADATOS

Este módulo incluye soporte para una nueva etiqueta experimental "=meta". Esto está deshabilitado por defecto, pero puede habilitarse cargando Pod::POM con la opción "meta".

use Pod::POM qw( meta );

Alternativamente, puede especificar la opción "meta" como cualquier valor verdadero al instanciar un analizador Pod::POM:

my $parser = Pod::POM->new( meta => 1 );
my $pom    = $parser->parse_file($filename);

Cualquier etiqueta "=meta" en el documento se almacenará como elementos de metadatos en el nodo raíz del modelo Pod creado.

Por ejemplo:

=meta module Foo::Bar
=meta author Andy Wardley

Luego puede acceder a estos elementos a través del método metadata().

print "módulo: ", $pom->metadata('module'), "\n";
print "autor: ", $pom->metadata('author'), "\n";

o

my $metadata = $pom->metadata();
print "módulo: $metadata->{ module }\n";
print "autor: $metadata->{ author }\n";

Tenga en cuenta que esta es una característica experimental que no es compatible con otros procesadores POD y, por lo tanto, es probable que sea muy incompatible. Úselo con cuidado.
