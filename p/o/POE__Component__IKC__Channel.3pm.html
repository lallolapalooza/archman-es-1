IKC::Channel(3) Documentación de usuario aportada por Perl IKC::Channel(3)

NOMBRE

POE::Component::IKC::Channel - Sesión de E/S de Comunicación Inter-Kernel de POE

SINOPSIS

use POE;
use POE::Component::IKC::Channel;
POE::Component::IKC::Channel->spawn( %params );

DESCRIPCIÓN

Nunca usarás un Canal IKC directamente. Son creados por POE::Component::IKC::Server y POE::Component::IKC::Client según sea necesario.

Este módulo implementa una E/S IKC de POE. Cuando se establece una nueva conexión, "IKC::Server" y "IKC::Client" crean un "IKC::Channel" para manejar la E/S.

La comunicación IKC ocurre en 2 fases: fase de negociación y fase normal.

La fase de negociación utiliza "Filter::Line" y se usa para intercambiar varios parámetros entre kernels (ejemplo: nombres de kernel, qué tipo de congelación/descongelación usar, etc.). Después de la negociación, "IKC::Channel" cambia a un "Filter::Reference" y crea un "IKC::Responder", si es necesario. Después de esto, el canal reenvía lecturas y escrituras entre "Wheel::ReadWrite" y el Responder.

"IKC::Channel" también se encarga de limpiar los nombres de kernel cuando el kernel externo se desconecta.

MÉTODOS

spawn

POE::Component::IKC::Channel->spawn(%param);

Crea un nuevo canal IKC para manejar las negociaciones y luego los datos reales.

Los parámetros se organizan por clave de la siguiente manera:

handle
El manejador de Perl que debemos pasar a "Wheel::ReadWrite::new".
kernel_name
El nombre del kernel local. Esto es una solución temporal hasta que se resuelva la asignación de eventos.
on_connect
Referencia de código que se llama cuando la fase de negociación ha terminado. Normalmente, lo usarías para iniciar las sesiones que envían eventos a kernels remotos.
subscribe
Referencia de array de especificadores (ya sean sesiones remotas o estados remotos) a los que te quieres suscribir. $on_connect solo se llamará si puedes suscribirte a todos esos especificadores. Si no puede, hará un die().
unix
Una bandera que indica si el manejador es un socket de dominio Unix o no.
aliases
Referencia de array de alias para el kernel local.
serializers
Referencia de array o escalar de los paquetes que quieres usar para la serialización de datos. Un paquete serializador requiere 2 funciones: freeze (o nfreeze) y thaw. Ver "POE::Component::IKC::Client".
"protocol"
Qué protocolo de negociación IKC usar. El protocolo original ("IKC") era síncrono y lento. El nuevo protocolo ("IKC0") envía toda la información a la vez. IKC0 degradará con gracia a IKC, si el cliente y el servidor no coinciden.

Actualmente, el valor predeterminado es IKC, pero pasará a IKC0 cuando esté seguro del nuevo protocolo.

EVENTOS

shutdown

Este evento hace que el servidor cierre su socket y se retire gradualmente. Normalmente, solo es enviado por IKC::Responder.

Si quieres enviar este evento tú mismo, puedes obtener el ID de sesión del canal de on_connect de IKC::Client:

POE::Component::IKC::Client->spawn(
    ....
        on_connect=>sub {
            $heap->{channel} = $poe_kernel->get_active_session()->ID;
        },
    ....
    );

Luego, cuando sea el momento de desconectarse:

$poe_kernel->call($heap->{channel} => 'shutdown');

Sí, esto es un hack. Se debe proporcionar un mecanismo más limpio.
