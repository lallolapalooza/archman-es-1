NOMBRE

POE::Component::Client::TCP - un cliente TCP simplificado

SINOPSIS

#!perl
use warnings;
use strict;
use POE qw(Component::Client::TCP);
POE::Component::Client::TCP->new(
  RemoteAddress => "yahoo.com",
  RemotePort    => 80,
  Connected     => sub {
    $_[HEAP]{server}->put("HEAD /");
  },
  ServerInput   => sub {
    my $input = $_[ARG0];
    print "desde el servidor: $input\n";
  },
);
POE::Kernel->run();
exit;

DESCRIPCIÓN

POE::Component::Client::TCP implementa un cliente genérico de una única Sesión. Internamente utiliza POE::Wheel::SocketFactory para establecer la conexión y POE::Wheel::ReadWrite para interactuar con el servidor.

POE::Component::Client::TCP se personaliza proporcionando callbacks para operaciones comunes. La mayoría de las operaciones tienen callbacks predeterminados razonables, por lo que los clientes pueden crearse con el mínimo trabajo posible.

Consideraciones de rendimiento

La facilidad de uso de POE::Component::Client::TCP tiene un precio. El componente es genérico, por lo que no está optimizado para funcionar bien en ninguna aplicación en particular.

Si el rendimiento es su objetivo principal, select_read() y select_write() de POE::Kernel funcionan de manera similar a IO::Select, pero su código será portable en todos los bucles de eventos que POE soporte.

MÉTODOS PÚBLICOS

new

new() inicia un cliente basado en POE::Component::Client::TCP y devuelve el ID de la sesión que manejará la interacción del servidor.

new() devuelve inmediatamente, lo que puede ser antes de que el cliente haya establecido su conexión. Siempre es fiable esperar a que se active el callback "Connected" antes de transmitir datos al servidor.

El constructor del cliente puede parecer que acepta un número abrumador de parámetros. Al igual que con la mayoría de los módulos POE, POE::Component::Client::TCP intenta hacer gran parte del trabajo en su constructor para que la ruta de código en tiempo de ejecución sea relativamente ligera.

Parámetros del constructor que afectan la sesión

Los parámetros de esta sección afectan cómo se creará el objeto POE::Session del cliente.

Alias

"Alias" es un nombre simbólico opcional para la Sesión del cliente. Permite que otras sesiones envíen eventos al cliente, como "shutdown" y "reconnect". El cliente mismo puede yield() estos eventos, por lo que normalmente no se necesita un alias.

Alias => "cliente",

Args

"Args" es opcional. Cuando se especifica, contiene una referencia a un ARRAY que se pasará al callback "Started" a través de @_[ARG0..$#_]. Esto permite que un programa pase información adicional al cliente de la sesión.

InlineStates

"InlineStates" es opcional. Si se especifica, debe contener un hashref de callbacks con nombre. Su sintaxis es la del parámetro inline_states de POE:Session->create().

ObjectStates

Si se especifica "ObjectStates", debe contener una referencia a un ARRAY de objetos y los eventos que manejarán. La referencia a ARRAY debe seguir la sintaxis del parámetro object_states de POE::Session->create().

PackageStates

Cuando se establece el opcional "PackageStates", debe contener una referencia a un ARRAY de nombres de paquetes y los eventos que manejarán. La referencia a ARRAY debe seguir la sintaxis del parámetro package_states de POE::Session->create().

PreConnect

"PreConnect" se llama antes de "Connected" y tiene parámetros diferentes: $_[ARG0] contiene una copia del socket antes de que se entregue a POE::Wheel::ReadWrite para su gestión. La mayoría de los miembros de HEAP están configurados, excepto por supuesto $_[HEAP]{server}, ya que el objeto POE::Wheel::ReadWrite aún no se ha creado. "PreConnect" puede habilitar SSL en el socket utilizando POE::Component::SSLify. "PreConnect" debe devolver un socket válido para completar la conexión; el cliente se desconectará si se devuelve cualquier otra cosa.

PreConnect => {
  # Convierte el socket en un socket SSL.
  my $socket = eval { Client_SSLify($_[ARG0]) };
  # Desconéctate si SSL falló.
  return if $@;
  # Devuelve el socket con SSL activado.
  return $socket;
}

SessionType

Cada cliente se crea dentro de su propia Sesión. "SessionType" nombra la clase que se utilizará para crear la sesión.

SessionType => "POE::Session::MultiDispatch",

"SessionType" es opcional. El componente utilizará "POE::Session" por defecto.

SessionParams

"SessionParams" especifica parámetros adicionales que se pasarán al constructor de "SessionType" en el momento de la creación. Debe ser una referencia a un ARRAY.

SessionParams => [ options => { debug => 1, trace => 1 } ],

Nota: POE::Component::Client::TCP proporciona sus propios parámetros del constructor de POE::Session. Los conflictos entre estos y "SessionParams" pueden hacer que el componente se comporte de forma errática. Para evitar tales problemas, limite SessionParams al hash de "options". Consulte POE::Session para conocer las opciones conocidas.

Podemos habilitar otras opciones más adelante. Por favor, infórmenos si necesita algo.

Started

"Started" configura un callback opcional que se invocará una vez que se haya iniciado la sesión del cliente. Los parámetros del callback son los habituales para el manejador _start de la sesión.

"Args" puede usarse para pasar parámetros adicionales a "Started". Esto puede usarse para evitar problemas introducidos por los cierres (closures). Los valores de "Args" se incluirán en los parámetros @_[ARG0..$#_].

sub handle_started {
  my @args = @_[ARG0..$#_];
  # ...
}

Parámetros del constructor de POE::Wheel::SocketFactory

Los parámetros del constructor de esta sección afectan cómo se creará el objeto POE::Wheel::SocketFactory del cliente.

BindAddress

"BindAddress" especifica la dirección de la interfaz local a la que vincularse antes de comenzar a conectar. Esto permite que el cliente se conecte desde una dirección específica cuando hay múltiples interfaces disponibles.

"BindAddress" es opcional. Si se especifica, su valor se pasará directamente al parámetro del constructor BindAddress de POE::Wheel::SocketFactory.

BindPort

"BindPort" establece el puerto del socket local al que se vinculará el cliente antes de comenzar a conectar. Esto permite que el cliente se conecte desde un puerto específico.

Por lo general, no es necesario vincularse a un puerto particular, por lo que "BindPort" es opcional y está deshabilitado por defecto.

Si se especifica, el valor de "BindPort" se pasa directamente al propio parámetro del constructor BindPort de POE::Wheel::SocketFactory.

ConnectError

"ConnectError" es un callback opcional para manejar errores de POE::Wheel::SocketFactory. Estos errores ocurren cuando no se puede crear un socket o hay problemas para conectarse al host remoto.

Los siguientes parámetros se pasarán al callback junto con los parámetros de evento POE habituales: $_[ARG0] describirá qué estaba sucediendo en el momento del fallo. $_[ARG1] y $_[ARG2] contendrán las versiones numéricas y de cadena de $!, respectivamente.

VEA TAMBIÉN

La sección VEA TAMBIÉN en POE contiene un índice que cubre toda la distribución de POE.

POE::Component::Server::TCP es la contraparte del lado del servidor de este módulo.

Este componente utiliza y expone características de POE::Filter, POE::Wheel::SocketFactory y POE::Wheel::ReadWrite.

Consulte "SINOPSIS" en POE::Wheel::SocketFactory para una forma más eficiente pero de nivel inferior de crear clientes y servidores.

ADVERTENCIAS

Esto no se parece en nada a lo que Ann imaginó.

POE::Component::Client::TCP es un cliente genérico. Como tal, no está optimizado para ninguna tarea en particular. Si bien maneja bien los casos comunes y con un mínimo de código, puede que no sea adecuado para todo.
