POE::Wheel::ReadLine(3) Documentación de Perl contribuida por el usuario POE::Wheel::ReadLine(3)

NOMBRE

POE::Wheel::ReadLine - Term::ReadLine no bloqueante para POE

SINOPSIS

#!perl
use warnings;
use strict;
use POE qw(Wheel::ReadLine);
POE::Session->create(
  inline_states=> {
    _start => \&setup_console,
    got_user_input => \&handle_user_input,
  }
);
POE::Kernel->run();
exit;
sub handle_user_input {
  my ($input, $exception) = @_[ARG0, ARG1];
  my $console = $_[HEAP]{console};
  unless (defined $input) {
    $console->put("$exception capturado.  ¡Adiós!");
    $_[KERNEL]->signal($_[KERNEL], "UIDESTROY");
    $console->write_history("./test_history");
    return;
  }
  $console->put("  Ingresaste: $input");
  $console->addhistory($input);
  $console->get("Ir: ");
}
sub setup_console {
  $_[HEAP]{console} = POE::Wheel::ReadLine->new(
    InputEvent => 'got_user_input'
  );
  $_[HEAP]{console}->read_history("./test_history");
  $_[HEAP]{console}->clear();
  $_[HEAP]{console}->put(
    "Ingresa algo de texto.",
    "Ctrl+C o Ctrl+D salen."
  );
  $_[HEAP]{console}->get("Ir: ");
}

DESCRIPCIÓN

POE::Wheel::ReadLine es una forma no bloqueante de Term::ReadLine compatible con POE. Utiliza Term::Cap para interactuar con la pantalla de la terminal y Term::ReadKey para interactuar con el teclado.

POE::Wheel::ReadLine maneja casi todas las teclas comunes de edición de entrada. Proporciona una lista de historial de entrada. Tiene modos vi y emacs. Soporta búsqueda incremental de entrada. Es completamente personalizable y es compatible con implementaciones estándar de readline(3) como Term::ReadLine::Gnu.

POE::Wheel::ReadLine se configura colocando comandos en un archivo de inicialización "inputrc". El nombre del archivo se toma de la variable de entorno "INPUTRC", o ~/.inputrc por defecto. POE::Wheel::ReadLine leerá el archivo inputrc y se configurará según los comandos y variables que contenga. Consulte readline(3) para obtener detalles sobre los archivos inputrc.

El modo de edición por defecto será estilo emacs, aunque esto se puede configurar estableciendo la variable 'editing-mode' dentro de un archivo inputrc. Si todo lo demás falla, POE::Wheel::ReadLine determinará el editor favorito del usuario examinando la variable de entorno EDITOR.

MÉTODOS PÚBLICOS

Constructor

La mayor parte de la interacción de POE::Wheel::ReadLine se realiza a través de su constructor, new().

new

new() crea y devuelve un nuevo objeto POE::Wheel::ReadLine. Asegúrate de instanciar solo uno, ya que múltiples lectores de consola podrían entrar en conflicto.

InputEvent

"InputEvent" nombra el evento que indicará una nueva línea de entrada de consola. Consulte "EVENTOS PÚBLICOS" para más detalles.

PutMode

"PutMode" controla cómo se muestran las salidas cuando se llama a put() durante la entrada del usuario.

Cuando se establece en "immediate", put() interrumpe al usuario inmediatamente. El prompt de entrada y la entrada del usuario hasta la fecha se redisplayan después de que se completa put().

El modo "after" de "PutMode" le dice a put() que espere hasta después de que el usuario ingrese o cancela su entrada.

Finalmente, "idle" permitirá que put() interrumpa la entrada del usuario si el usuario deja de escribir durante "IdleTime" segundos. Este modo se comporta como "after" si el usuario no puede dejar de escribir el tiempo suficiente. Este es el modo por defecto de POE::Wheel::ReadLine.

IdleTime

"IdleTime" le indica a POE::Wheel::ReadLine cuánto tiempo debe estar inactivo el teclado antes de que put() se vuelva inmediato o el texto almacenado en búfer se vacíe en la pantalla. Solo es significativo cuando "PutMode" es "idle". "IdleTime" tiene un valor predeterminado de 2 segundos.

AppName

"AppName" registra un nombre de aplicación que se utiliza para recuperar enlaces de teclas específicos de la aplicación del archivo inputrc. El "AppName" predeterminado es "poe-readline".

# Si usas POE::Wheel::ReadLine, establece
# el mapeo de teclas en modo emacs y
# activa la salida de depuración en una secuencia
# de teclas determinada.
$if poe-readline
set keymap emacs
Control-xP: poe-wheel-debug
$endif

Gestión de la Lista de Historial

POE::Wheel::ReadLine admite un historial de entrada, con búsqueda.

add_history

add_history() acepta una lista de líneas para agregar al historial de entrada. Generalmente se llama con una sola línea: la última línea de entrada recibida de la terminal. La "SINOPSIS" muestra add_history() en acción.

get_history

get_history() devuelve una lista que contiene el historial de entrada actual de POE::Wheel::ReadLine. Puede que no contenga todo lo introducido en la rueda.

write_history

write_history() escribe el historial de entrada actual en un archivo. Acepta un parámetro opcional: el nombre del archivo donde se escribirá el historial de entrada. write_history() escribirá en ~/.history si no se especifica ningún nombre de archivo.

Devuelve verdadero en caso de éxito, o falso si no.

La "SINOPSIS" muestra un ejemplo de write_history() y la correspondiente read_history().

read_history

read_history(FILENAME, START, END) lee un historial de entrada guardado previamente de un archivo con nombre, o de ~/.history si no se especifica ningún nombre de archivo. También puede leer una subsección del archivo de historial si se le dan los parámetros opcionales START y END. El archivo se leerá desde el principio si START se omite o es cero. Se leerá hasta el final si END se omite o es anterior a START.

Devuelve verdadero en caso de éxito, o falso si no.

La "SINOPSIS" muestra un ejemplo de read_history() y la correspondiente write_history().

Lee las primeras diez líneas del historial:

$_[HEAP]{console}->read_history("filename", 0, 9);

history_truncate_file

history_truncate_file() trunca un archivo de historial a un cierto número de líneas. Acepta dos parámetros: el nombre del archivo a truncar y el número máximo de líneas de historial a dejar en el archivo. El archivo de historial se borrará por completo si el recuento de líneas es cero u omitido.

El archivo a truncar por defecto es ~/.history. Por lo tanto, llamar a history_truncate_file() sin parámetros borra ~/.history.

Devuelve verdadero en caso de éxito, o falso si no.

Tenga en cuenta que history_trucate_file() elimina las líneas más antiguas del archivo. Las líneas posteriores permanecen intactas ya que fueron las introducidas más recientemente.

Mantén ~/.history por debajo de 100 líneas manejables:

$_[HEAP]{console}->history_truncate_file(undef, 100);

Métodos de Enlace de Teclas

bind_key

bind_key(KEYSTROKE, FUNCTION) enlaza una FUNCTION a una secuencia de TECLAS nombrada. La secuencia de teclas puede estar en cualquiera de las formas definidas dentro de readline(3). La función debe ser un nombre predefinido, como "self-insert", o una referencia a una función. El enlace se realiza en el mapa de teclas actual. Usa el método rl_set_keymap() para cambiar los mapas de teclas, si lo deseas.

add_defun NAME FN

add_defun(NAME, FUNCTION) define una nueva FUNCTION global, dándole un NAME específico. La función puede luego ser enlazada a secuencias de teclas por ese NAME.

Métodos de Entrada/Salida de Consola

clear

Limpia la terminal.

terminal_size

Devuelve lo que POE::Wheel::ReadLine considera las dimensiones actuales de la terminal. Devuelve una lista de dos valores: el número de columnas y el número de filas, respectivamente.

sub some_event_handler {
  my ($columns, $rows) = $_[HEAP]{console}->terminal_size;
  $_[HEAP]{console}->put(
    "Columnas de terminal: $columns",
    "Filas de terminal: $rows",
  );
}

get

get() hace que POE::Wheel::ReadLine muestre un indicador y luego espere la entrada. La entrada no se nota a menos que get() haya habilitado el observador de E/S interno de la rueda.

Después de llamar a get(), la próxima línea de entrada o excepción en la consola activará un "InputEvent" con los parámetros apropiados. POE::Wheel::ReadLine entrará luego en un estado inactivo hasta que se vuelva a llamar a get().

Las llamadas a get() sin argumento preservarán el indicador actual. Llamar a get() con un argumento antes de recibir una línea completa de entrada cambiará el indicador sobre la marcha.

Ver el "SYNOPSIS" para un ejemplo de uso.

put

put() acepta una lista de líneas para mostrar en la terminal. POE::Wheel::ReadLine se basa en líneas. Consulte POE::Wheel::Curses para ver opciones de visualización más interesantes.

Por favor, no use print() con POE::Wheel::ReadLine. print() invariablemente se equivoca con el salto de línea, dejando la salida de una aplicación en forma de escalera en la terminal. Además, put() entiende cuándo un usuario está ingresando texto, y "PutMode" puede usarse para evitar interrumpir al usuario.

Métodos de Opción de ReadLine

attribs

attribs() devuelve una referencia a un hash de opciones de readline. El hash devuelto se puede usar para consultar o modificar el comportamiento de POE::Wheel::ReadLine.

option

option(NAME) devuelve un miembro específico del hash devuelto por attribs(). Es una forma más conveniente de consultar las opciones de POE::Wheel::ReadLine.

EVENTOS PÚBLICOS

POE::Wheel::ReadLine emite un solo evento.

InputEvent

"InputEvent" nombra el evento que se emitirá ante cualquier tipo de entrada de terminal completa. Cada manejador de "InputEvent" recibe tres parámetros:

$_[ARG0] contiene una línea de entrada. Puede ser una cadena vacía si el usuario ingresó una línea vacía. Un $_[ARG0] indefinido indica alguna excepción, como fin de entrada o el hecho de que el usuario canceló su entrada o presionó C-c (^C).

$_[ARG1] describe una excepción, si ocurrió alguna. Puede contener una de las siguientes cadenas:

cancel
La excepción "cancel" indica cuándo un usuario ha cancelado una línea de entrada. Se envía cuando el usuario activa la función "abort", que está vinculada a C-g (^G) por defecto.
eot
"eot" es el código ASCII para "fin de cinta". Se emite cuando el usuario solicita que se cierre la terminal. Por defecto, se activa cuando el usuario presiona C-d (^D) en una línea vacía.
interrupt
"interrupt" se envía como resultado de que el usuario presione C-c (^C) o active de alguna otra manera la función "interrupt".

Finalmente, $_[ARG2] contiene el ID del objeto POE::Wheel::ReadLine que envió el "InputEvent".

ENLACES PERSONALIZADOS

POE::Wheel::ReadLine permite enlazar funciones personalizadas a secuencias de teclas. La función debe ser visible para la rueda antes de poder enlazarla. Para registrar una función, use el método add_defun() de POE::Wheel::ReadLine:

POE::Wheel::ReadLine->add_defun('reverse-line', \&reverse_line);

Al agregar una nueva defun, se puede proporcionar un tercer parámetro opcional que es una secuencia de teclas para enlazar. Esto debe tener el mismo formato que el entendido por el análisis de inputrc.

Las funciones enlazadas reciben tres parámetros: una referencia al propio objeto de la rueda, la secuencia de teclas que activó la función (en forma imprimible) y la secuencia de teclas sin procesar. Se espera que la función enlazada profundice en los miembros de datos de POE::Wheel::ReadLine para realizar su trabajo y mostrar el contenido de la nueva línea por sí misma.

Esto es menos que ideal y puede cambiar en el futuro.

COMPLETADO PERSONALIZADO

Una aplicación puede modificar la "completion_function" de POE::Wheel::ReadLine para personalizar cómo se debe completar la entrada. La nueva función de completado debe aceptar tres parámetros escalares: la palabra que se está completando, el texto de entrada completo y la posición dentro del texto de entrada de la palabra que se está completando.

La función de completado debe devolver una lista de coincidencias posibles. Por ejemplo:

my $attribs = $wheel->attribs();
$attribs->{completion_function} = sub {
  my ($text, $line, $start) = @_;
  return qw(a list of candidates to complete);
}

Esta es la única forma de completado admitida actualmente.

DIFERENCIAS DE IMPLEMENTACIÓN

Aunque POE::Wheel::ReadLine se modela según la biblioteca readline(3), hay algunas áreas que no se han implementado. La configuración de opciones que tienen efecto en esta implementación son: bell-style, editing-mode, isearch-terminators, comment-begin, print-completions-horizontally, show-all-if-ambiguous y completion_function.

La función 'tab-insert' no está implementada, ni los tabuladores se muestran correctamente.

VER TAMBIÉN

POE::Wheel describe las operaciones básicas de todas las ruedas con más profundidad. Necesitas saber esto.

readline(3), Term::Cap, Term::ReadKey.

La sección SEE ALSO en POE contiene una tabla de contenidos que cubre toda la distribución de POE.

Term::Visual es una alternativa a POE::Wheel::ReadLine. Proporciona retroceso de desplazamiento y una barra de estado además de entrada de usuario editable. Term::Visual soporta POE a pesar de la falta de "POE" en su nombre.

ERRORES

POE::Wheel::ReadLine tiene algunos problemas conocidos:

Perl 5.8.0 Está Roto

La entrada no bloqueante con Term::ReadKey no funciona con Perl 5.8.0, especialmente en sistemas Linux por alguna razón. Actualizar Perl solucionará las cosas. Si no puedes actualizar Perl, considera métodos de entrada alternativos, como Term::Visual.

http://rt.cpan.org/Ticket/Display.html?id=4524 y las entradas relacionadas explican el problema en detalle. Si sospechas que tu sistema es uno donde Term::ReadKey falla, puedes ejecutar este programa de prueba para estar seguro.

#!/usr/bin/perl
use Term::ReadKey;
print "Presiona 'q' para salir de esta prueba.\n";
ReadMode 5; # Desactiva las teclas de control
while (1) {
  while (not defined ($key = ReadKey(-1))) {
    print "No se obtuvo tecla. Durmiendo 1 segundo.\015\012";
    sleep (1);
  }
  print "Tecla obtenida: $key\015\012";
  ($key eq 'q') and last;
}
ReadMode 0; # Restablece el modo tty antes de salir
exit;

Código No Óptimo

Disociar los cursores de entrada y visualización introdujo mucho código. Gran parte de este código se agregó apresuradamente, y probablemente se puedan hacer las cosas con menos trabajo.

Características No Implementadas

La edición de entrada no se mantiene en una sola línea. Si se envuelve, y una terminal no puede envolver hacia atrás a través de una división de línea, el cursor se perderá.

Soporte Unicode. Me siento muy mal por descartar la representación nativa de todos los caracteres con el 8º bit establecido. Tampoco tengo idea de cómo hacer esto, y no tengo un sistema para probarlo. Los parches son muy bienvenidos.

TRAMPAS / PREGUNTAS FRECUENTES

Indicadores Perdidos

P: ¿Por qué pierdo mi indicador cada vez que envío salida a la pantalla?

R: Probablemente estás usando print o printf para escribir la salida de pantalla. ReadLine no rastrea STDOUT por sí mismo, por lo que no sabe cuándo actualizar el indicador después de que lo hagas. Usa el método put() de ReadLine para escribir líneas en la consola.

Las Pulsaciones de Teclas de Edición se Muestran como ^C

P: Ninguna de las teclas de edición funciona. Ctrl-C muestra "^c" en lugar de generar una interrupción. Las teclas de flecha no se desplazan por mi historial de entrada. En general, es una mala experiencia.

R: Probablemente eres un usuario de vi/vim. En ausencia de un archivo ~/.inputrc, POE::Wheel::ReadLine verifica tu variable de entorno EDITOR para obtener pistas sobre tu preferencia de edición. Si ve /vi/ en él, comienza en modo vi. Puedes anular esto creando un archivo ~/.inputrc que contenga la línea "set editing-mode emacs", o agregando esa línea a tu ~/.inputrc existente. Mientras estás en ello, deberías familiarizarte con todas las otras cosas geniales que puedes hacer con los archivos .inputrc.

Falta de Soporte para Windows

P: ¿Por qué POE::Wheel::ReadLine no funciona en Windows? Term::ReadLine sí.

R: POE::Wheel::ReadLine requiere select(), porque eso es lo que POE usa por defecto para detectar pulsaciones de teclas sin bloquear. Aproximadamente la mitad de los sabores de Perl en Windows implementan select() en términos de la misma función en la biblioteca WinSock, lo que limita select() a funcionar solo con sockets. Tu consola no es un socket, por lo que select() no funciona con tu versión de Perl en Windows.

Son posibles soluciones alternativas realmente buenas, pero no existen en el momento de escribir esto. Implican escribir un POE::Loop especial para Windows que utilice un módulo específico de Win32 para una multiplexación mejor, que busque entrada o que utilice observadores de E/S bloqueantes en hilos separados.

BUGS

Cygwin Support

Q: ¿Por qué POE::Wheel::ReadLine se queja de mi terminal "dumb"?

R: ¿Tienes Strawberry Perl instalado? Debido a cómo funciona, al instalar establece una variable de entorno global en MSWin32 para TERM=dumb. (puede que se solucione en una futura versión, ¡pero por ahora está aquí para quedarse, ja!) En este caso, iniciar sesión en la shell de Cygwin a través del lanzador cygwin.bat da como resultado un readline no funcional.

Normalmente, Cygwin establece TERM=cygwin en el lanzador. Sin embargo, si TERM ya estaba establecido, no alterará el valor. ¡Por lo tanto, aparece el "error"! Lo que puedes hacer es modificar el archivo cygwin.bat para añadir esta línea:

SET TERM=cygwin

Otros usuarios informaron que puedes obtener mejores resultados editando el archivo ~/.bash_profile para establecer TERM=cygwin, ya que en una actualización de Cygwin se sobrescribe el archivo cygwin.bat.

Alternativamente, podrías instalar diferentes terminales como "xterm" o "rxvt" como se muestra aquí: http://c2.com/cgi/wiki?BetterCygwinTerminal. Por favor, háznoslo saber si encuentras problemas al usar cualquier terminal que no sea "dumb".

Si te sientes valiente, puedes revisar el ticket de RT en http://rt.cpan.org/Ticket/Display.html?id=55365 para más información sobre este problema.
