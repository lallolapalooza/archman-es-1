NOMBRE

Pod::Simple::XHTML -- dar formato a Pod como XHTML válido

SINOPSIS

use Pod::Simple::XHTML;
my $parser = Pod::Simple::XHTML->new();
...
$parser->parse_file('ruta/al/archivo.pod');

DESCRIPCIÓN

Esta clase es un formateador que toma Pod y lo renderiza como HTML válido según XHTML.

Esta es una subclase de Pod::Simple::Methody y hereda todos sus métodos. La implementación es completamente diferente de Pod::Simple::HTML, pero conserva en gran medida la misma interfaz.

Código mínimo

use Pod::Simple::XHTML;
my $psx = Pod::Simple::XHTML->new;
$psx->output_string(\my $html);
$psx->parse_file('ruta/a/Modulo/Nombre.pm');
open my $out, '>', 'salida.html' or die "No se puede abrir 'salida.html': $!\n";
print $out $html;

También puede controlar la codificación de caracteres y las entidades. Por ejemplo, si está seguro de que el POD está codificado correctamente (usando el comando "=encoding"), puede evitar que los caracteres de alto bit se codifiquen como entidades HTML y declarar el conjunto de caracteres de salida como UTF-8 antes de analizar, así:

  $psx->html_charset('UTF-8');
use warnings;
  $psx->html_encode_chars(q{&<>'"});

MÉTODOS

Pod::Simple::XHTML ofrece una serie de métodos que modifican el formato de la salida HTML. Llámelos después de crear el objeto parser, pero antes de la llamada a "parse_file":

my $parser = Pod::PseudoPod::HTML->new();
$parser->set_optional_param("valor");
$parser->parse_file($archivo);

prefijo_url_perldoc

Al convertir Foo::Bar en http://whatever/Foo%3a%3aBar, qué poner antes de "Foo%3a%3aBar". El valor predeterminado es "https://metacpan.org/pod/".

sufijo_url_perldoc

Qué poner después de "Foo%3a%3aBar" en la URL. Esta opción no está configurada por defecto.

prefijo_url_man

Al convertir "crontab(5)" en http://whatever/man/1/crontab, qué poner antes de "1/crontab". El valor predeterminado es "http://man.he.net/man".

sufijo_url_man

Qué poner después de "1/crontab" en la URL. Esta opción no está configurada por defecto.

prefijo_titulo, sufijo_titulo

Qué poner antes y después del título en la cabecera. Los valores ya deben estar escapados con &.

css_html

$parser->html_css('ruta/a/estilo.css');

La URL o la ruta relativa de un archivo CSS a incluir. Esta opción no está configurada por defecto.

javascript_html

La URL o la ruta relativa de un archivo JavaScript a incluir. Esta opción no está configurada por defecto.

doctype_html

Una etiqueta de tipo de documento para el archivo. Esta opción no está configurada por defecto.

charset_html

El conjunto de caracteres a declarar en la etiqueta meta Content-Type creada por defecto para "html_header_tags". Tenga en cuenta que esta opción se ignorará si el valor de "html_header_tags" se cambia. Por defecto es "ISO-8859-1".

etiquetas_cabecera_html

Etiquetas HTML adicionales arbitrarias para la cabecera del documento. El valor predeterminado es solo una etiqueta de cabecera de tipo de contenido:

<meta http-equiv="Content-Type" content="text/html; charset=ISO-8859-1">

Agregue aquí etiquetas meta adicionales, o bloques de CSS o JavaScript en línea (envueltos en las etiquetas apropiadas).

html_encode_chars

Una cadena que contiene todos los caracteres que deben codificarse como entidades HTML, especificados utilizando la sintaxis de clase de caracteres de expresión regular (lo que se encuentra entre corchetes en las expresiones regulares). Este valor se pasará como segundo argumento a la función "encode_entities" de HTML::Entities. Si HTML::Entities no está instalado, cualquier carácter que no sea "&<""'> se codificará numéricamente.

nivel_h_html

Este es el nivel del elemento HTML "Hn" al que corresponde un "head1" de Pod. Por ejemplo, si "html_h_level" se establece en 2, un head1 producirá un H2, un head2 producirá un H3, y así sucesivamente.

titulo_predeterminado

Establezca un título predeterminado para la página si no se puede determinar ningún título a partir del contenido. El valor de esta cadena ya debe estar escapado con &.

forzar_titulo

Forzar un título para la página (no intentar determinarlo a partir del contenido). El valor de esta cadena ya debe estar escapado con &.

cabecera_html, pie_pagina_html

Establezca la salida HTML al principio y al final de cada archivo. La cabecera predeterminada incluye un título, una etiqueta doctype (si se estableció "html_doctype"), una etiqueta de contenido (personalizada por "html_header_tags"), una etiqueta para un archivo CSS (si se estableció "html_css") y una etiqueta para un archivo JavaScript (si se estableció "html_javascript"). El pie de página predeterminado simplemente cierra las etiquetas "html" y "body".

Las opciones enumeradas anteriormente personalizan partes de la cabecera predeterminada, pero establecer "html_header" o "html_footer" anula completamente la cabecera o el pie de página integrados. Esto puede ser útil si desea utilizar etiquetas de plantilla en lugar de cabeceras y pies de página HTML literales, o si está integrando páginas POD convertidas en un sitio web más grande.

Si no desea que se genere ninguna cabecera o pie de página en el HTML, establezca estas opciones en la cadena vacía.

índice

Si se debe agregar una tabla de contenido en la parte superior de cada página (llamada índice por tradición).

elementos_ancla

Si se debe anclar cada directiva de definición "=item". Esto debe habilitarse si desea poder enlazar a directivas "=item" específicas, que se generan como elementos "<dt>". Deshabilitado por defecto.

enlace_atras

Si se debe convertir cada directiva =head1 en un enlace que apunte a la parte superior de la página (específicamente, a la etiqueta de apertura del body).

SUBCLASES

Si las opciones estándar no son suficientes, puede crear una subclase de Pod::Simple::XHMTL. Estos son los candidatos más probables para los métodos que querrá anular al crear subclases.

NAME

Pod::Simple::XHTML - A POD to HTML converter that is HTML-ID-aware

SYNOPSIS

use Pod::Simple::XHTML;
my $p = Pod::Simple::XHTML->new;
$p->parse_string($pod_text);
# or
$p->parse_file('some_file.pod');

DESCRIPTION

This class is a subclass of Pod::Simple that converts POD to HTML. It is specifically designed to be aware of HTML IDs, so that it can generate links within a document, or link to sections of other documents.

It does this by providing its own implementations of several callback methods that Pod::Simple calls as it parses the POD document.

METHODS

handle_text

This method handles the body of text within any element: it's the body of a paragraph, or everything between a =begin tag and the corresponding =end tag, or the text within an L entity, etc. You would want to override this if you are adding a custom element type that does more than just display formatted text. Perhaps adding a way to generate HTML tables from an extended version of POD.

So, let's say you want to add a custom element called 'foo'. In your subclass's "new" method, after calling "SUPER::new" you'd call:

$new->accept_targets_as_text( 'foo' );

Then override the "start_for" method in the subclass to check for when $flags->{'target'} is equal to 'foo' and set a flag that marks that you're in a foo block (maybe $self->{'in_foo'} = 1). Then override the "handle_text" method to check for the flag, and pass $text to your custom subroutine to construct the HTML output for 'foo' elements, something like:

sub handle_text {
    my ($self, $text) = @_;
    if ($self->{'in_foo'}) {
        $self->{'scratch'} .= build_foo_html($text);
        return;
    }
    $self->SUPER::handle_text($text);
}

handle_code

This method handles the body of text that is marked up to be code. You might for instance override this to plug in a syntax highlighter. The base implementation just escapes the text.

The callback methods "start_code" and "end_code" emits the "code" tags before and after "handle_code" is invoked, so you might want to override these together with "handle_code" if this wrapping isn't suitable.

Note that the code might be broken into multiple segments if there are nested formatting codes inside a "C<...>" sequence. In between the calls to "handle_code" other markup tags might have been emitted in that case. The same is true for verbatim sections if the "codes_in_verbatim" option is turned on.

accept_targets_as_html

This method behaves like "accept_targets_as_text", but also marks the region as one whose content should be emitted literally, without HTML entity escaping or wrapping in a "div" element.

resolve_pod_page_link

my $url = $pod->resolve_pod_page_link('Net::Ping', 'INSTALL');
my $url = $pod->resolve_pod_page_link('perlpodspec');
my $url = $pod->resolve_pod_page_link(undef, 'SYNOPSIS');

Resolves a POD link target (typically a module or POD file name) and section name to a URL. The resulting link will be returned for the above examples as:

https://metacpan.org/pod/Net::Ping#INSTALL
https://metacpan.org/pod/perlpodspec
#SYNOPSIS

Note that when there is only a section argument the URL will simply be a link to a section in the current document.

resolve_man_page_link

my $url = $pod->resolve_man_page_link('crontab(5)', 'EXAMPLE CRON FILE');
my $url = $pod->resolve_man_page_link('crontab');

Resolves a man page link target and numeric section to a URL. The resulting link will be returned for the above examples as:

http://man.he.net/man5/crontab
http://man.he.net/man1/crontab

Note that the first argument is required. The section number will be parsed from it, and if it's missing will default to 1. The second argument is currently ignored, as man.he.net http://man.he.net does not currently include linkable IDs or anchor names in its pages. Subclass to link to a different man page HTTP server.

idify

my $id   = $pod->idify($text);
my $hash = $pod->idify($text, 1);

This method turns an arbitrary string into a valid XHTML ID attribute value. The rules enforced, following http://webdesign.about.com/od/htmltags/a/aa031707.htm, are:

  • The id must start with a letter (a-z or A-Z)
  • All subsequent characters can be letters, numbers (0-9), hyphens (-), underscores (_), colons (:), and periods (.).
  • The final character can't be a hyphen, colon, or period. URLs ending with these characters, while allowed by XHTML, can be awkward to extract from plain text.
  • Each id must be unique within the document.

In addition, the returned value will be unique within the context of the Pod::Simple::XHTML object unless a second argument is passed a true value. ID attributes should always be unique within a single XHTML document, but pass the true value if you are creating not an ID but a URL hash to point to an ID (i.e., if you need to put the #foo in "<a href="#foo">foo</a>".

batch_mode_page_object_init

$pod->batch_mode_page_object_init($batchconvobj, $module, $infile, $outfile, $depth);

Called by Pod::Simple::HTMLBatch so that the class has a chance to initialize the converter. Internally it sets the "batch_mode" property to true and sets batch_mode_current_level(), but Pod::Simple::XHTML does not currently use those features. Subclasses might, though.
