Pod::Simple::Search(3perl) Guía de Referencia del Programador de Perl Pod::Simple::Search(3perl)

NOMBRE

Pod::Simple::Search - buscar documentos POD en árboles de directorios

SINOPSIS

use Pod::Simple::Search;
my $name2path = Pod::Simple::Search->new->limit_glob('LWP::*')->survey;
print "Mira lo que encontré: ",
  join(' ', sort keys %$name2path), "\n";
print "Docs de LWPUA = ",
  Pod::Simple::Search->new->find('LWP::UserAgent') || "?",
  "\n";

DESCRIPCIÓN

Pod::Simple::Search es una clase que se utiliza para realizar búsquedas de archivos Pod. Un objeto de esta clase tiene varios atributos (principalmente opciones para controlar las opciones de búsqueda) y algunos métodos para buscar basándose en esos atributos.

La forma de usar esta clase es crear un nuevo objeto de esta clase, establecer las opciones deseadas y luego llamar a una de las opciones de búsqueda (probablemente "survey" o "find"). Las secciones siguientes discuten las sintaxis para hacer todo eso.

CONSTRUCTOR

Esta clase proporciona un único constructor, llamado "new". No toma parámetros:

use Pod::Simple::Search;
my $search = Pod::Simple::Search->new;

ACCESORES

Esta clase define varios métodos para establecer (y, ocasionalmente, leer) los contenidos de un objeto. Con dos excepciones (discutidas al final de esta sección), estos atributos son solo para controlar la forma en que se llevan a cabo las búsquedas.

Tenga en cuenta que cada uno de estos devuelve $self cuando los llama como "$self->lo_que_sea(valor)". Eso es para que pueda encadenar llamadas de configuración de atributos como esta:

my $name2path =
  Pod::Simple::Search->new
  -> inc(0) -> verbose(1) -> callback(\&blab)
  ->survey(@allí);

...lo cual funciona exactamente como si hubiera hecho esto:

my $search = Pod::Simple::Search->new;
$search->inc(0);
$search->verbose(1);
$search->callback(\&blab);
my $name2path = $search->survey(@allí);
$search->inc( verdadero-o-falso );
Este atributo, si se establece en un valor verdadero, significa que las búsquedas deben incluir implícitamente las rutas @INC de perl. Esto considera automáticamente las rutas especificadas en la variable de entorno "PERL5LIB", ya que el intérprete de Perl las antepone a @INC por sí mismo. El valor predeterminado de este atributo es VERDADERO. Si desea buscar solo directorios específicos, establezca $self->inc(0) antes de llamar a $inc->survey o $inc->find.
$search->verbose( número-no-negativo );
Este atributo, si se establece en un valor positivo distinto de cero, hará que las búsquedas muestren (a través de "warn") notas sobre lo que están haciendo mientras lo hacen. Esta opción puede ser útil para depurar un módulo relacionado con pod. El valor predeterminado de este atributo es cero, lo que significa que no se producen mensajes de "warn". (Establecer verbose a 1 activa algunos mensajes, y establecerlo a 2 activa aún más mensajes, es decir, hace que la siguiente búsqueda (o búsquedas) sea aún más detallada de lo que sería con 1).
$search->limit_glob( alguna-cadena-de-glob );
Esta opción significa que desea limitar los resultados solo a los elementos cuyos nombres de pod coincidan con la expresión de glob/comodín dada. Por ejemplo, podría limitar su búsqueda a solo "LWP::*", para buscar solo módulos que comiencen con "LWP::*" (pero sin incluir el módulo "LWP" en sí); o podría limitar su búsqueda a "LW*" para ver solo módulos cuyos nombres (completos) comiencen con "LW"; o podría buscar "*Find*" para buscar todos los módulos que tengan "Find" en algún lugar de su nombre completo. (También puede usar "?" en una expresión de glob; así "DB?" coincidirá con "DBI" y "DBD".)
$search->callback( \&alguna_rutina );
Este atributo significa que cada vez que esta búsqueda encuentre un archivo Pod coincidente, debe llamar a esta rutina de devolución de llamada. La rutina se llama con dos parámetros: la especificación de archivo del archivo actual y su nombre de pod. (Por ejemplo: "("/etc/perljunk/File/Crunk.pm", "File::Crunk")" estaría en @_.)

El valor de retorno de la rutina de devolución de llamada no se utiliza para nada.

El valor predeterminado de este atributo es falso, lo que significa que no se llama a ninguna devolución de llamada.

$search->laborious( verdadero-o-falso );
A menos que establezca este atributo en un valor verdadero, Pod::Search aplicará heurísticas específicas de Perl para encontrar rápidamente los PODs de módulos correctos. El valor predeterminado de este atributo es falso. Normalmente no necesitará establecerlo en verdadero.

Específicamente: Activar esta opción deshabilitará las heurísticas para ver solo archivos con extensiones similares a Perl, omitir subdirectorios que sean numéricos pero que *no* coincidan con el ID de versión del intérprete de Perl actual, suprimir site_perl como nombre de jerarquía de módulo, etc.

$search->recurse( verdadero-o-falso );
A menos que establezca este atributo en un valor falso, Pod::Search recorrerá recursivamente los subdirectorios de los directorios de búsqueda.
$search->shadows( verdadero-o-falso );
A menos que establezca este atributo en un valor verdadero, Pod::Simple::Search considerará solo el primer archivo de un nombre de módulo dado mientras busca a través de los directorios especificados; es decir, con esta opción desactivada, si Pod::Simple::Search ya ha visto un "somepathdir/Foo/Bar.pm" en esta búsqueda, entonces no se molestará en buscar un "somelaterpathdir/Foo/Bar.pm" más adelante en esa búsqueda, porque ese archivo es simplemente una "sombra". Pero si activa "$self->shadows(1)", entonces estos archivos de "sombra" también se inspeccionan y se notan en el hash de retorno pathname2podname.

El valor predeterminado de este atributo es falso; y normalmente no necesitará activarlo.

$search->is_case_insensitive( verdadero-o-falso );
Por defecto, Pod::Simple::Search asumirá internamente, basándose en el sistema de archivos subyacente donde se encuentra el archivo de clase, si es sensible o no a mayúsculas y minúsculas.

Si se determina que no distingue entre mayúsculas y minúsculas, durante survey() puede omitir archivos/módulos pod que resulten ser iguales a nombres que ya ha visto, ignorando mayúsculas/minúsculas.

Sin embargo, es posible tener archivos distintos en diferentes directorios que intencionalmente tengan el mismo nombre, solo que con diferentes mayúsculas/minúsculas, que deberían informarse. Por lo tanto, puede forzar el comportamiento estableciendo esto en verdadero o falso.

$search->limit_re( algún-regexp );
Establecer este atributo (a un valor que sea un regexp) significa que desea limitar los resultados solo a los elementos cuyos nombres de pod coincidan con el regexp dado. Normalmente esta opción no es necesaria, y en su lugar se utiliza el atributo más eficiente "limit_glob".
$search->dir_prefix( algún-valor-de-cadena );
Establecer este atributo a un valor de cadena significa que las búsquedas deben comenzar en el nombre del subdirectorio especificado (como "Pod" o "File::Find", también expresable como "File/Find"). Por ejemplo, la opción de búsqueda "$search->limit_glob("File::Find::R*")" es lo mismo que la combinación de las opciones de búsqueda "$search->limit_re("^File::Find::R") -> dir_prefix("File::Find")".

Normalmente no necesita saber sobre la opción "dir_prefix", pero la incluyo en caso de que resulte útil para alguien en algún lugar.

(Implementacionalmente, buscar con limit_glob termina estableciendo limit_re y generalmente dir_prefix.)

$search->progress( algún-objeto-de-progreso );
Si establece un valor para este atributo, se espera que el valor sea un objeto (probablemente de una clase que usted defina) que tenga un método "reach" y un método "done". Esto está destinado a informar el progreso durante la búsqueda, si no desea usar un simple

Normalmente no necesitas saber sobre la opción "progress", pero la incluyo en caso de que pueda resultar útil para alguien en algún lugar.

Mientras una búsqueda está en progreso, los métodos "reach" y "done" del objeto de progreso se llaman de la siguiente manera:

# Cada vez que se escanea un archivo en busca de pod:
$progress->reach($count, "Escaneando $file");   ++$count;
# Y luego al final de la búsqueda:
$progress->done("Se notaron $count archivos Pod en total");

Internamente, a menudo establecemos esto a un objeto de la clase Pod::Simple::Progress. Esa clase probablemente no esté documentada, pero es posible que desees ver su código fuente.

$name2path = $self->name2path;
Este atributo no es un parámetro de búsqueda, sino que se utiliza para informar el resultado del método "survey", como se discute en la siguiente sección.
$path2name = $self->path2name;
Este atributo no es un parámetro de búsqueda, sino que se utiliza para informar el resultado del método "survey", como se discute en la siguiente sección.

MÉTODOS PRINCIPALES DE BÚSQUEDA

Una vez que hayas establecido las opciones que desees (si las hay), puedes proceder a utilizar los siguientes métodos para buscar archivos Pod de maneras particulares.

"$search->survey( @directories )"

El método "survey" busca documentos POD en un conjunto dado de archivos y/o directorios. Ejecuta la búsqueda de acuerdo con las diversas opciones establecidas por los accedentes anteriores. (Por ejemplo, si el atributo "inc" está activado, como lo está por defecto, entonces los directorios @INC de perl se añaden implícitamente a la lista de directorios (si los hay) que especificas).

El valor de retorno de "survey" son dos hashes:

"name2path"
Un hash que mapea de cada nombre de pod al especificador de archivo (como "Stuff::Thing" => "/whatever/plib/Stuff/Thing.pm")
"path2name"
Un hash que mapea de cada especificador de archivo Pod a su nombre de pod (como "/whatever/plib/Stuff/Thing.pm" => "Stuff::Thing")

Además de guardar estos hashes como los atributos hashref "name2path" y "path2name", llamar a esta función también devuelve estos hashrefs. En contexto de lista, el valor de retorno de "$search->survey" es la lista "(\%name2path, \%path2name)". En contexto escalar, el valor de retorno es "\%name2path". O puedes simplemente llamar a esto en contexto nulo.

Independientemente del contexto de llamada, llamar a "survey" guarda sus resultados en sus atributos "name2path" y "path2name".

Por ejemplo, al buscar en $HOME/perl5lib, el archivo $HOME/perl5lib/MyModule.pm recibiría el nombre POD MyModule, mientras que $HOME/perl5lib/Myclass/Subclass.pm sería Myclass::Subclass. La información del nombre se puede utilizar para traductores POD.

Solo se encuentran los archivos de texto que contienen al menos un comando POD válido.

En modo detallado, se imprime una advertencia si se encuentran sombras (es decir, más de un archivo POD con el mismo nombre POD), por ejemplo, CPAN.pm en diferentes directorios. Esto generalmente indica ocurrencias duplicadas de módulos en la ruta de búsqueda de @INC, lo cual es ocasionalmente inadvertido (pero a menudo es simplemente un caso de que el directorio de ruta de un usuario tenga una versión más reciente que los directorios de ruta generales del sistema en general).

Las opciones para este argumento es una lista de directorios que se buscan recursivamente, o archivos. (Normalmente no especificarías archivos, solo directorios). O puedes simplemente especificar una lista vacía, como en $name2path; con la opción "inc" activada, como lo está por defecto.

Los nombres POD de los archivos son los nombres base simples con la extensión similar a Perl (.pm, .pl, .pod) eliminada, y los separadores de ruta reemplazados por "::".

Llamar a Pod::Simple::Search->search(...) es un atajo para Pod::Simple::Search->new->search(...). Es decir, se utiliza un objeto desechable con valores de atributos predeterminados.

"$search->simplify_name( $str )"

El método simplify_name es equivalente a basename, pero también elimina las extensiones similares a Perl (.pm, .pl, .pod) y extensiones como .bat, .cmd en Win32 y OS/2, o .com en VMS, respectivamente.

"$search->find( $pod )"

"$search->find( $pod, @search_dirs )"

Devuelve la ubicación de un archivo Pod, dado un nombre de Pod/módulo/script (como "Foo::Bar" o "perlvar" o "perldoc"), y una idea de qué archivos/directorios buscar. Busca de acuerdo con las diversas opciones establecidas por los accedentes anteriores. (Por ejemplo, si el atributo "inc" está activado, como lo está por defecto, entonces los directorios @INC de perl se añaden implícitamente a la lista de directorios (si los hay) que especificas).

Esto devuelve la ruta completa de la primera ocurrencia del archivo. Los nombres de paquetes (por ejemplo, 'A::B') se convierten automáticamente en nombres de directorios en el directorio seleccionado. Además, '.pm', '.pl' y '.pod' se añaden automáticamente a la búsqueda según sea necesario. (Así, por ejemplo, en Unix, "A::B" se convierte en "somedir/A/B.pm", "somedir/A/B.pod", o "somedir/A/B.pl", según corresponda).

Si no se encuentra dicho archivo Pod, este método devuelve undef.

Si alguno de los directorios de búsqueda dados contiene un subdirectorio pod/, entonces se busca. (Así es como logramos encontrar perlfunc, por ejemplo, que generalmente está en pod/perlfunc en la mayoría de las distribuciones de Perl).

Los atributos "verbose" y "inc" influyen en el comportamiento de esta búsqueda; en particular, "inc", si es verdadero, añade @INC y *también* $Config::Config{'scriptdir'} a la lista de directorios a buscar.

Es común simplemente decir "$filename = Pod::Simple::Search-> new ->find("perlvar")" para que solo se busquen los directorios de @INC (bueno, y scriptdir). (Esto ocurre porque el atributo "inc" es verdadero por defecto).

Llamar a Pod::Simple::Search->find(...) es un atajo para Pod::Simple::Search->new->find(...). Es decir, se utiliza un objeto desechable con valores de atributos predeterminados.

"$self->contains_pod( $file )"

Devuelve verdadero si el nombre de archivo proporcionado (no módulo POD) contiene alguna documentación Pod.
