NOMBRE

local::lib~[pt_br] - crea y usa un directorio lib/ local para módulos perl con PERL5LIB

SINOPSIS

En el código -

use local::lib; # configura un lib local en ~/perl5
use local::lib '~/foo'; # igual, pero en ~/foo
# O...
use FindBin;
use local::lib "$FindBin::Bin/../soporte";  # bibliotecas de soporte locales a la aplicación

Desde la línea de comandos (shell) -

# Instala LWP y sus dependencias no encontradas en el directorio '~/perl5'
perl -MCPAN -Mlocal::lib -e 'CPAN::install(LWP)'
# Solo imprime algunos comandos útiles para la shell
$ perl -Mlocal::lib
export PERL_MB_OPT='--install_base /home/username/perl5'
export PERL_MM_OPT='INSTALL_BASE=/home/username/perl5'
export PERL5LIB='/home/username/perl5/lib/perl5/i386-linux:/home/username/perl5/lib/perl5'
export PATH="/home/username/perl5/bin:$PATH"

La técnica de 'bootstrapping'

Una forma común de instalar local::lib es usar lo que se conoce como la técnica de "bootstrapping". Es un buen enfoque si tu administrador de sistemas no ha instalado local::lib. En ese caso, necesitarás instalar local::lib en tu directorio de usuario.

Si tienes privilegios de administrador, aún deberás configurar tus variables de entorno, como se discute en el paso 4, a continuación. Sin ellas, aún instalarás módulos en el CPAN del sistema y tus scripts Perl no utilizarán la ruta al lib/ que has definido con local::lib.

Por defecto, local::lib instala los módulos de CPAN y a sí mismo en ~/perl5.

Los usuarios de Windows deben leer "Diferencias al usar este módulo en Win32".

1. Descarga y descomprime local::lib del CPAN (busca "Download" en la página del CPAN sobre local::lib). Hazlo como un usuario normal, no como root o administrador. Descomprime el archivo en tu directorio de usuario o en cualquier otro lugar conveniente.

2. Ejecuta esto:

perl Makefile.PL --bootstrap

Si el sistema pregunta si debe configurar todo lo que pueda automáticamente, probablemente deberías responder que sí.

Para instalar local::lib en un directorio que no sea el predeterminado, necesitarás especificarlo al llamar al bootstrap, de la siguiente manera:

perl Makefile.PL --bootstrap=~/foo

3. Ejecuta esto: (local::lib asume que tienes el comando 'make' instalado en tu sistema)

make test && make install

4. Ahora necesitamos configurar las variables de entorno apropiadas para que Perl use nuestro recién creado directorio lib/. Si estás usando bash u otra shell Bourne, puedes hacerlo añadiendo la siguiente línea a tu script de inicialización de shell:

echo 'eval $(perl -I$HOME/perl5/lib/perl5 -Mlocal::lib)' >>~/.bashrc

Si estás usando la shell C, puedes hacerlo de la siguiente manera:

/bin/csh
echo $SHELL
/bin/csh
perl -I$HOME/perl5/lib/perl5 -Mlocal::lib >> ~/.cshrc

Si pasaste al bootstrap un directorio que no es el predeterminado, necesitarás indicarlo en la llamada a local::lib, de esta forma:

echo 'eval $(perl -I$HOME/foo/lib/perl5 -Mlocal::lib=$HOME/foo)' >>~/.bashrc

Después de actualizar tu archivo de configuración de shell, asegúrate de procesarlo nuevamente para obtener los cambios en tu shell actual. Las shells Bourne usan ". ~/.bashrc" para esto, mientras que las shells C usan "source ~/.cshrc".

Si estás en una máquina lenta o operando con grandes limitaciones de espacio en disco, puedes desactivar la generación automática de manpages a partir del POD al instalar módulos. Para ello, simplemente pasa el argumento "--no-manpages" durante el bootstrap:

perl Makefile.PL --bootstrap --no-manpages

Para evitar tener que hacer varios bootstraps para varios entornos de módulos Perl en la misma cuenta de usuario - por ejemplo, si usas local::lib para desarrollar diferentes aplicaciones independientes - puedes utilizar una única instalación bootstrap de local::lib para instalar módulos en diferentes directorios de la siguiente manera:

cd ~/midirectorio1
perl -Mlocal::lib=./
eval $(perl -Mlocal::lib=./)  ### Para configurar el entorno solo en esta shell
printenv                      ### Mira que ~/midirectorio1 está en PERL5LIB
perl -MCPAN -e install ...    ### Los módulos que quieras
cd ../midirectorio2
... REPETIR ...

Para múltiples entornos destinados a múltiples aplicaciones, podrías necesitar incluir una versión modificada de las instrucciones de "use FindBin" en el ejemplo "En el código" anterior. Si has hecho algo como lo descrito anteriormente, tendrás un conjunto de módulos Perl en "~/midirectorio1/lib". Si tienes un script en "~/midirectorio1/scripts/miscript.pl", necesitarás indicarle dónde encontrar los módulos que instalaste para él en "~/midirectorio1/lib".

En "~/midirectorio1/scripts/miscript.pl":

use strict;
use warnings;
use local::lib "$FindBin::Bin/..";  ### apunta a ~/midirectorio1 y local::lib encuentra el lib/
use lib "$FindBin::Bin/../lib";     ### apunta a ~/midirectorio1/lib

Coloca esto antes de cualquier bloque BEGIN { ... } que necesite los módulos instalados.

Diferencias al usar este módulo en Win32

Para configurar las variables de entorno apropiadas para tu sesión actual de "CMD.exe", puedes hacer esto:

C:\>perl -Mlocal::lib
set PERL_MB_OPT=--install_base C:\DOCUME~1\ADMINI~1\perl5
set PERL_MM_OPT=INSTALL_BASE=C:\DOCUME~1\ADMINI~1\perl5
set PERL5LIB=C:\DOCUME~1\ADMINI~1\perl5\lib\perl5;C:\DOCUME~1\ADMINI~1\perl5\lib\perl5\MSWin32-x86-multi-thread
set PATH=C:\DOCUME~1\ADMINI~1\perl5\bin;%PATH%
### Para configurar el entorno solo en esta shell
C:\>perl -Mlocal::lib > %TEMP%\tmp.bat && %TEMP%\tmp.bat && del %TEMP%\temp.bat
### en lugar de $(perl -Mlocal::lib=./)

Si quieres que las configuraciones del entorno persistan, necesitarás añadirlas en Panel de Control -> Sistema, o usar App::local::lib::Win32Helper.

El " ~ " se transforma en el directorio del perfil del usuario (el directorio con el nombre del usuario dentro de "Documents and Settings" (Windows XP o anterior) o "Usuarios" (Windows Vista y más recientes)) a menos que $ENV{HOME} exista. Después de eso, el nombre del directorio se acorta y se crean los subdirectorios (lo que significa que el directorio debe existir).

MOTIVACIÓN

La versión de un paquete Perl en tu máquina no siempre es la que necesitas. Obviamente, lo mejor sería actualizarla a la versión deseada. Sin embargo, puedes estar en una situación que te impida hacerlo. Quizás no tengas privilegios de administrador del sistema; o quizás estés usando un sistema de gestión de paquetes como el de Debian, y aún no exista un paquete disponible en la versión deseada.

local::lib resuelve este problema permitiendo la creación de tu propio directorio de paquetes Perl obtenidos del CPAN (en sistemas multiusuario, esto normalmente queda dentro del directorio de tu usuario). La instalación de Perl en el sistema permanece inalterada; simplemente llamas a Perl con el

\n

Este módulo oferece uma forma rápida e conveniente\n para criar um repositório de módulos locais ao usuário, \n dentro do diretório do mesmo. LIMITAÇÕES

As ferramentas auxiliares do perl não conseguem lidar com nomes de diretórios contendo espaços, então não é possível fazer seu bootstrap do local::lib em um diretório com espaços. O que você pode fazer é mover seu local::lib para um diretório com espaços após ter instalado todos os módulos dentro dele. Mas esteja ciente que você não poderá atualizar ou instalar outros módulos do CPAN nesse diretório local após a mudança.

A detecção da shell é relativamente básica. Neste momento, qualquer coisa com csh no nome será tratada como a C shell ou compatível, e todo o resto será tratado como Bourne, exceto em sistemas Win32. Caso a variável de ambiente "SHELL" não esteja disponível, assumiremos tratar-se de uma shell compatível com a Bourne.

A técnica de bootstrap é um hack e usará o CPAN.pm para o ExtUtils::MakeMaker mesmo que você tenha o CPANPLUS instalado.

Destrói qualquer valor pré-existente nas variáveis de ambiente PERL5LIB, PERL_MM_OPT e PERL_MB_OPT.

Provavelmente deveria auto-configurar o CPAN caso isso ainda não tenha sido feito.

Correções (patches) são muito bem-vindos para quaisquer dos itens acima.

Em sistemas Win32, não há uma forma de escrever no registro as variáveis de ambiente criadas, para que elas persistam a uma reinicialização.

SOLUÇÃO DE PROBLEMAS

Se você configurou o local::lib para instalar módulos do CPAN em algum lugar do seu 'home', e mais tarde tentou instalar um módulo fazendo "cpan -i Foo::Bar", mas ele falhou com um erro como: "Warning: You do not have permissions to install into /usr/lib64/perl5/site_perl/5.8.8/x86_64-linux at /usr/lib64/perl5/5.8.8/Foo/Bar.pm" e em algum lugar no seu log de instalação houver um erro dizendo "'INSTALL_BASE' is not a known MakeMaker parameter name", então você de alguma forma perdeu seu ExtUtils::MakeMaker atualizado.

Para remediar a situação, execute novamente o procedimento de bootstrap descrito acima.

Então, execute "rm -r ~/.cpan/build/Foo-Bar*"

Finalmente, execute novamente o "cpan -i Foo::Bar" e ele deve instalar sem problemas.

AMBIENTE

SHELL
COMSPEC
O local::lib procura pela variável de ambiente "SHELL" do usuário ao processar e exibir os comandos a serem adicionados no arquivo de configuração da shell.

Em sistemas Win32, "COMSPEC" também será examinado.
