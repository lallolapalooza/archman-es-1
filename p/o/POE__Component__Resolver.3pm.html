POE::Component::Resolver(3) Documentación de Perl aportada por el usuario POE::Component::Resolver(3)

NOMBRE

POE::Component::Resolver - Un resolvedor getaddrinfo() no bloqueante

VERSIÓN

versión 0.921

SINOPSIS

#!/usr/bin/perl
use warnings;
use strict;
use POE;
use POE::Component::Resolver qw(AF_INET AF_INET6);
my $r = POE::Component::Resolver->new(
        max_resolvers => 8,
        idle_timeout  => 5,
        af_order      => [ AF_INET6, AF_INET ],
        # sidecar_program => $path_to_program,
);
my @hosts = qw( ipv6-test.com );
my $tcp   = getprotobyname("tcp");
POE::Session->create(
        inline_states => {
                _start => sub {
                        foreach my $host (@hosts) {
                                $r->resolve(
                                        host    => $host,
                                        service => "http",
                                        event   => "got_response",
                                        hints   => { protocol => $tcp },
                                ) or die $!;
                        }
                },
                _stop => sub { print "sesión de cliente detenida\n" },
                got_response => sub {
                        my ($error, $addresses, $request) = @_[ARG0..ARG2];
                        use YAML; print YAML::Dump(
                                {
                                        error => $error,
                                        addr => $addresses,
                                        req => $request,
                                }
                        );
                },
        }
);
POE::Kernel->run();

DESCRIPCIÓN

POE::Component::Resolver realiza llamadas a Socket::getaddrinfo() en subprocesos donde se les permite bloquear tanto como sea necesario.

Por defecto, ejecutará ocho subprocesos y preferirá familias de direcciones en el orden en que getaddrinfo() las devuelve. Estos valores por defecto se pueden anular con parámetros del constructor. getaddrinfo() delega al resolvedor del sistema operativo, que puede ser reconfigurado según las convenciones habituales.

MÉTODOS PÚBLICOS

new

Crea un nuevo resolvedor. Devuelve un objeto que debe ser conservado y utilizado para realizar solicitudes. Ver la sinopsis.

Acepta hasta cuatro parámetros con nombre opcionales.

"af_order" puede contener un arrayref con las familias de direcciones a permitir, en el orden en que se prefieren. Sin "af_order", el componente preferirá direcciones IPv4 sobre IPv6 por compatibilidad con versiones anteriores. Esto puede cambiar en el futuro a medida que IPv6 gane más aceptación generalizada. Ver "VARIABLES DE ENTORNO" para una forma de anular el valor predeterminado sin modificar módulos.

# Prefiere direcciones IPv6, pero también devuelve direcciones IPv4.
my $r1 = POE::Component::Resolver->new(
        af_order => [ AF_INET6, AF_INET ]
);
# Solo devuelve direcciones IPv6,
# o nada en casos donde solo existen direcciones IPv4.
my $r2 = POE::Component::Resolver->new(
        af_order => [ AF_INET6 ]
);

"idle_timeout" determina cuánto tiempo se mantienen los subprocesos de resolución inactivos antes de limpiarlos, en segundos. El valor predeterminado es 15.0 segundos.

"max_resolvers" controla el paralelismo del componente al definir el número máximo de procesos auxiliares a gestionar. El valor predeterminado es 8, pero se pueden configurar menos o más procesos según los recursos disponibles y la cantidad de paralelismo requerida.

# Uno a la vez, pero sin el molesto bloqueo.
my $r3 = POE::Component::Resolver->new( max_resolvers => 1 );

"sidecar_program" contiene la ubicación en disco de un programa que realizará búsquedas bloqueantes en la entrada estándar y imprimirá los resultados en la salida estándar. El programa auxiliar solo es necesario en entornos especiales donde la agrupación y ejecución de utilidades adicionales es complicada. PAR es un entorno de este tipo.

El programa auxiliar necesita contener al menos dos declaraciones:

use POE::Component::Resolver::Sidecar;
POE::Component::Resover::Sidecar->main();

resolve

resolve() inicia una nueva solicitud para resolver un dominio. La solicitud se encolará en el componente hasta que un proceso auxiliar pueda atenderla. resolve() devuelve un ID de solicitud que puede ser usado para cancel() una solicitud antes de que se complete (o undef si la solicitud no pudo iniciarse, como durante el apagado). Resolve requiere dos parámetros y acepta algunos opcionales adicionales.

"host" y "service" son requeridos y contienen el host (nombre o dirección de Internet) y el servicio (nombre o puerto numérico) que se pasarán literalmente a getaddrinfo(). Ver Socket para más detalles.

"event" es opcional; contiene el nombre del evento que contendrá la respuesta del resolvedor. Si se omite, el valor predeterminado será "resolver_response"; es posible que desees especificar un nombre de evento más corto.

"hints" es opcional. Si se especifica, debe contener un hashref de pistas exactamente como las espera getaddrinfo(). Ver Socket para más detalles.

"misc" son datos de continuación opcionales que se devolverán en la respuesta. Puede contener cualquier tipo de datos que la aplicación requiera.

cancel

Cancela una solicitud, dado el ID de la solicitud.

my $request_id = $resolver->resolve("poe.dyndns.org", "http");
$resolver->cancel($request_id);

shutdown

Apaga el resolvedor. POE::Component::Resolver retiene recursos, incluidos procesos hijos, hasta "idle_timeout" segundos. Esto puede mantener programas en ejecución hasta "idle_timeout" segundos más de lo que deberían.

POE::Component::Resolver liberará sus recursos (incluidos los procesos hijos) cuando se llame a su método shutdown().

unpack_addr

En contexto escalar, unpack_addr($response_addr_hashref) devuelve el elemento addr de $response_addr_hashref en un formato numérico apropiado para la familia de direcciones de la dirección.

sub handle_resolver_response {
        my ($error, $addresses, $request) = @_[ARG0..ARG2];
        foreach my $a (@$addresses) {
                my $numeric_addr = $resolver->unpack_addr($a);
                print "$request->{host} = $numeric_addr\n";
        }
}

En contexto de lista, devuelve el puerto y la dirección numéricos.

sub handle_resolver_response {
        my ($error, $addresses, $request) = @_[ARG0..ARG2];
        foreach my $a (@$addresses) {
                my ($$numeric_addr, $port) = $resolver->unpack_addr($a);
                print "$request->{host} = $numeric_addr\n";
        }
}

unpack_addr() es un envoltorio de conveniencia para getnameinfo() de Socket. Puedes usar la función discreta en su lugar.

unpack_addr() devuelve un vacío sombrío en caso de error, independientemente del contexto. Puedes verificar si devuelve undef.

EVENTOS PÚBLICOS

resolver_response

El evento de respuesta del resolvedor incluye tres parámetros.

$_[ARG0] y $_[ARG1] contienen los valores de retorno de la llamada getaddrinfo() de Socket. Estos son un mensaje de error (si la llamada falló) y un arrayref de estructuras de direcciones si la llamada tuvo éxito.

El componente proporciona su propio mensaje de error, 'componente detenido'. Esta respuesta se da para cada solicitud pendiente en el momento en que el usuario detiene el componente.

$_[ARG2] contiene un hashref de información proporcionada al método resolve(). Específicamente, los valores de los parámetros "host", "service" y "misc" de resolve().

VARIABLES DE ENTORNO

POCO_RESOLVER_IPV

La variable de entorno POCO_RESOLVER_IPV establece el orden de búsqueda predeterminado de Versión de Protocolo de Internet de este componente. Si la variable existe, debe contener una cadena con los números 4 y/o 6. POE::Component::Resolver los tratará como versiones de Protocolo de Internet a considerar, en el orden en que se prefieren.

DESCRIPTION

POE::Component::Resolver is a POE component that performs asynchronous DNS lookups. It spawns a child process to do the lookups and communicates with it via pipes. This prevents DNS lookups from blocking the main POE event loop.

The component implements the POE component API. Its methods are:

new()
Spawns the resolver process and creates a new POE::Component::Resolver object.
resolve()
Requests a DNS lookup for the specified host. The lookup request is sent to the resolver process. The results are returned via a POE event.
shutdown()
Shuts down the resolver process.

When a lookup is complete, the component will send an event to the session that requested the lookup. The event will be addressed to the session's caller, and will contain a hash reference with the lookup results. The hash reference will contain the following keys:

host
The hostname that was looked up.
addresses
An array reference of IP addresses for the host.
error
An error message, if the lookup failed.

ENVIRONMENT VARIABLES

The behavior of POE::Component::Resolver can be influenced by the following environment variables:

  • POCO_RESOLVER_DEBUG: If set, enables debug messages from the resolver component.
  • POCO_RESOLVER_MAX_CHILDREN: Sets the maximum number of resolver child processes that can be spawned. Defaults to 5.
  • POCO_RESOLVER_IDLE_TIMEOUT: Sets the number of seconds after which an idle resolver child process will exit. Defaults to 15.0 seconds.
  • POCO_RESOLVER_IPV: Controls the preferred IP version for DNS lookups. This can be set to one of the following values:
    • 4: Default to IPv4 addresses only.
    • 6: Default to IPv6 addresses only.
    • 64: Prefer IPv6, but accept IPv4 if needed.
    • 46: Prefer IPv4, but accept IPv6 if needed.

Default to IPv4 addresses only:

export POCO_RESOLVER_IPV=4

Default to IPv6 addresses only:

export POCO_RESOLVER_IPV=6

Prefer IPv6, but accept IPv4 if needed:

export POCO_RESOLVER_IPV=64

Prefer IPv4, but accept IPv6 if needed:

export POCO_RESOLVER_IPV=46

COMPATIBILITY ISSUES

Microsoft Windows

This module requires "Microsoft TCP/IP version 6" to be installed. Steps for Windows XP Pro (the steps for your particular version of Windows may be subtly or drastically different):

  • Open your Control Panel
  • Open your Network Connections
  • Select your network connection from the available one(s)
  • In the Local Area Connection Status dialog, click the Properties button
  • If "Microsoft TCP/IP version 6" is listed as an item being used, you are done.
  • Otherwise click Install...
  • Choose to add a Protocol
  • And install "Microsoft TCP/IP version 6" from the list of network protocols.

BUGS

There is no timeout on requests.

There is no way to cancel a pending request.

TROUBLESHOOTING

programs linger for several seconds before exiting

Programs should shutdown() their POE::Component::Resolver objects when they are through needing asynchronous DNS resolution. Programs should additionally destroy their resolvers if they intend to run awhile and want to reuse the memory they consume.

In some cases, it may be necessary to shutdown components that perform asynchronous DNS using POE::Component::Resolver... such as POE::Component::IRC, POE::Component::Client::Keepalive and POE::Component::Client::HTTP.

By default, the resolver subprocesses hang around for idle_timeout, which defaults to 15.0 seconds. Destroying the Resolver object will clean up the process pool. Assuming only that is keeping the event loop active, the program will then exit cleanly.

Alternatively, reduce idle_timeout to a more manageable number, such as 5.0 seconds.

Otherwise something else may also be keeping the event loop active.
