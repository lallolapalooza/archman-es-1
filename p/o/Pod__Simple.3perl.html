DESCRIPCIÓN

Pod::Simple es una biblioteca de Perl para parsear texto en el lenguaje de marcado Pod ("plain old documentation") que se usa típicamente para escribir documentación para Perl y para módulos de Perl. El formato Pod se explica en perlpod; el formateador más común se llama "perldoc".

Asegúrate de leer "ENCODING" si tu Pod contiene caracteres no ASCII.

Los formateadores de Pod pueden usar Pod::Simple para parsear documentos Pod y renderizarlos en texto plano, HTML o cualquier otro formato. Típicamente, tales formateadores serán subclases de Pod::Simple, y así heredarán sus métodos, como "parse_file". Pero ten en cuenta que Pod::Simple no entiende ni parsea correctamente Perl mismo, por lo que si tienes un archivo que contiene un programa Perl que tiene una cadena entre comillas multilínea con líneas que parecen pod, Pod::Simple las tratará como pod. Esto se puede evitar si el archivo las convierte en here documents indentados en su lugar.

Si estás leyendo este documento solo porque tienes una subclase de procesamiento de Pod que quieres usar, este documento (más la documentación de la subclase) es probablemente todo lo que necesitas leer.

Si estás leyendo este documento porque quieres escribir una subclase de formateador, sigue leyéndolo y luego lee Pod::Simple::Subclassing, y quizás incluso lee perlpodspec (parte de lo cual es para escritores de parsers, pero gran parte son notas para escritores de formateadores).

MÉTODOS PRINCIPALES

"$parser = AlgunaClase->new();"
Esto devuelve un nuevo objeto parser, donde "AlgunaClase" es una subclase de Pod::Simple.
"$parser->output_fh( *OUT );"
Esto establece el manejador de archivo al que se escribirá la salida de $parser. Puedes pasar *STDOUT o *STDERR, de lo contrario probablemente deberías hacer algo como esto: 
my $outfile = "salida.txt";
open TXTOUT, ">$outfile" or die "No se puede escribir en $outfile: $!";
$parser->output_fh(*TXTOUT);

...antes de llamar a uno de los "$parser->parse_algo" métodos.

"$parser->output_string( \$cadena );"
Esto establece la cadena a la que se enviará la salida de $parser, en lugar de cualquier manejador de archivo.
"$parser->parse_file( $nombre_archivo );"
"$parser->parse_file( *MANEJADOR_ENTRADA );"
Esto lee el contenido Pod del archivo (o manejador de archivo) que especificas, y lo procesa con ese objeto $parser, de acuerdo con cómo funcione la clase de $parser, y de acuerdo con las opciones del parser que hayas configurado para este objeto $parser.
"$parser->parse_string_document( $contenido_total );"
Esto funciona igual que "parse_file" excepto que lee el contenido Pod no desde un archivo, sino desde una cadena que ya tienes en memoria.
"$parser->parse_lines( ...@lineas..., undef );"
Esto procesa las líneas en @lineas (donde cada elemento de la lista debe ser un valor definido, y debe contener exactamente una línea de contenido -- así que no se permiten elementos como "foo\nbar"). El "undef" final se utiliza para indicar el fin del documento que se está parseando.

Los otros "parser_algo" métodos están destinados a ser llamados solo una vez por objeto $parser; pero "parse_lines" puede ser llamado tantas veces por objeto $parser como quieras, siempre y cuando la última llamada (y solo la última llamada) termine con un valor "undef".

"$parser->content_seen"
Esto devuelve verdadero solo si se ha visto algún contenido real para este documento. Devuelve falso en casos donde el documento contiene contenido, pero no utiliza ningún marcado Pod.
"AlgunaClase->filter( $nombre_archivo );"
"AlgunaClase->filter( *MANEJADOR_ENTRADA );"
"AlgunaClase->filter( \$contenido_documento );"
Este es un método de acceso directo para crear un nuevo objeto parser, establecer el manejador de salida a STDOUT, y luego procesar el archivo especificado (o manejador de archivo, o documento en memoria). Esto es útil para one-liners como este: 
perl -MPod::Simple::Text -e "Pod::Simple::Text->filter('thingy.pod')"

MÉTODOS SECUNDARIOS

Algunos de estos métodos pueden ser de interés para usuarios generales, así como de interés para escritores de formateadores.

Ten en cuenta que el patrón general aquí es que los métodos accesores leen el valor del atributo con "$valor = $parser->atributo" y establecen el valor del atributo con "$parser->atributo(nuevovalor)". Para cada accesorio, normalmente solo menciono una sintaxis u otra, basándome en la que creo que es más probable que uses.

"$parser->parse_characters( ALGÚNVALOR )"
El parser Pod normalmente espera leer octetos y convertirlos a caracteres basándose en la declaración "=encoding" en la fuente Pod. Establece esta opción a un valor verdadero para indicar que la fuente Pod ya es un flujo de caracteres de Perl. Esto le dice al parser que ignore cualquier comando "=encoding" y que omita todas las rutas de código que implican decodificar octetos.
"$parser->no_whining( ALGÚNVALOR )"
Si estableces este atributo a un valor verdadero, suprimirás las quejas del parser sobre irregularidades en la codificación Pod. Por defecto, el valor de este atributo es falso, lo que significa que se informarán las irregularidades.

Ten en cuenta que poner este atributo a verdadero no suprimirá uno o dos tipos de quejas sobre errores irrecuperables que ocurren raramente.

"$parser->no_errata_section( ALGÚNVALOR )"
Si estableces este atributo a un valor verdadero, detendrás al parser de generar una sección "ERRORES POD" al final del documento. Por defecto, el valor de este atributo es falso, lo que significa que se generará una sección de erratas, según sea necesario.
"$parser->complain_stderr( ALGÚNVALOR )"
Si estableces este atributo a un valor verdadero, enviará informes de errores de parseo a STDERR. Por defecto, el valor de este atributo es falso, lo que significa que no se envía ninguna salida a STDERR.

Establecer "complain_stderr" también establece "no_errata_section".

"$parser->source_filename"
Esto devuelve el nombre del archivo del que se configuró este objeto parser para leer.
"$parser->doc_has_started"
Esto devuelve verdadero si $parser ha leído de una fuente, y ha visto contenido Pod en ella.
"$parser->source_dead"
Esto devuelve verdadero si $parser ha leído de una fuente, y ha llegado al final de esa fuente.
"$parser->strip_verbatim_indent( ALGÚNVALOR )"
La especificación de perlpod para un párrafo Verbatim es "Debe reproducirse exactamente...", lo que significa que el espacio en blanco que has usado para indentar tus bloques verbatim se conservará en la salida. Esto puede ser molesto para salidas como HTML, donde ese espacio en blanco permanecerá delante de cada línea. Es un caso desafortunado donde la sintaxis se convierte en semántica.

MÉTODOS SECUNDARIOS




"$parser->strip_verbatim_indent( indent )"




If the POD contains verbatim blocks, this method can be used to
    strip indentation from them. This is most useful for making POD
    documentation look good when it is indented for the sake of layout within
    the source file.


The indent parameter may be a string, an array reference
    of strings, or a code reference.


If it is a string, that string is stripped from the beginning of
    each line of a verbatim block. For example, to strip two spaces:


$parser->strip_verbatim_indent('  ');



For tab indents, you'd use a tab character:


$parser->strip_verbatim_indent("\t");



If the POD is inconsistent about the indentation of verbatim
    blocks, but you have figured out a heuristic to determine how much a
    particular verbatim block is indented, you can pass a code reference
    instead. The code reference will be executed with one argument, an array
    reference of all the lines in the verbatim block, and should return the
    value to be stripped from each line. For example, if you decide that
    you're fine to use the first line of the verbatim block to set the
    standard for indentation of the rest of the block, you can look at the
    first line and return the appropriate value, like so:


$new->strip_verbatim_indent(sub {
    my $lines = shift;
    (my $indent = $lines->[0]) =~ s/\S.*//;
    return $indent;
});



If you'd rather treat each line individually, you can do that,
    too, by just transforming them in-place in the code reference and
    returning "undef". Say that you don't
    want any lines indented. You can do something like this:


$new->strip_verbatim_indent(sub {
    my $lines = shift;
    sub { s/\s+// for @{ $lines },
    return undef;
});



"$parser->expand_verbatim_tabs( n )"


Default: 8

If after any stripping of indentation in verbatim blocks,
    there remain tabs, this method call indicates what to do with them.
    0 means leave them as tabs, any other number
    indicates that each tab is to be translated so as to have tab stops
    every "n" columns.


This is independent of other methods (except that it operates
    after any verbatim input stripping is done).


Like the other methods, the input parameter is not checked for
    validity. "undef" or containing
    non-digits has the same effect as 8.










MÉTODOS TERCIARIOS




"$parser->abandon_output_fh()"


Cancela la salida al manejador de archivos. Cualquier POD leído por
    $parser no se ve afectado.


"$parser->abandon_output_string()"


Cancela la salida a la cadena de salida. Cualquier POD leído por
    $parser no se ve afectado.


"$parser->accept_code( @codes )"


Alias de accept_codes.


"$parser->accept_codes( @codes )"


Permite que $parser acepte una lista de
    "Códigos de Formato" en perlpod. Esto se puede usar para implementar
    códigos definidos por el usuario.


"$parser->accept_directive_as_data( @directives )"


Permite que $parser acepte una lista de directivas para
    párrafos de datos. Una directiva es la etiqueta de un "Párrafo de Comando"
    en perlpod. Un párrafo de datos es uno delimitado por directivas
    "=begin/=for/=end". Esto se puede usar para implementar
    directivas definidas por el usuario.


"$parser->accept_directive_as_processed( @directives )"


Permite que $parser acepte una lista de directivas para
    párrafos procesados. Una directiva es la etiqueta de un "Párrafo de Comando"
    en perlpod. Un párrafo procesado también se conoce como "Párrafo Ordinario"
    en perlpod. Esto se puede usar para implementar directivas definidas por el
    usuario.


"$parser->accept_directive_as_verbatim( @directives )"


Permite que $parser acepte una lista de directivas para
    "Párrafo Literal" en perlpod. Una directiva es la etiqueta de un "Párrafo de
    Comando" en perlpod. Esto se puede usar para implementar directivas
    definidas por el usuario.


"$parser->accept_target( @targets )"


Alias de accept_targets.


"$parser->accept_target_as_text( @targets )"


Alias de accept_targets_as_text.


"$parser->accept_targets( @targets )"


Acepta objetivos para las secciones "=begin/=for/=end"
    del POD.


"$parser->accept_targets_as_text( @targets )"


Acepta objetivos para las secciones "=begin/=for/=end"
    que deben ser analizadas como POD. Para más detalles, ver "Acerca de los
    Párrafos de Datos" en perlpodspec.


"$parser->any_errata_seen()"


Se utiliza para comprobar si se ha visto alguna errata.

Ejemplo:


die "demasiados errores\n" if $parser->any_errata_seen();





"$parser->errata_seen()"


Devuelve una referencia de hash de todas las erratas vistas, tanto quejas
    como gritos. Las claves de la referencia de hash son el número de línea y
    el valor es una referencia de matriz de los errores para esa línea.

Ejemplo:


if ( $parser->any_errata_seen() ) {
   $logger->log( $parser->errata_seen() );
}





"$parser->detected_encoding()"


Devuelve la codificación correspondiente a
    "=encoding", pero solo si la codificación fue
    reconocida y manejada.


"$parser->encoding()"


Devuelve la codificación del documento, incluso si la codificación no se
    maneja correctamente.


"$parser->parse_from_file( $source, $to )"


Analiza desde el archivo $source al archivo
    $to. Similar a "parse_from_file" en Pod::Parser.


"$parser->scream( @error_messages )"


Registra un error que no se puede ignorar.


"$parser->unaccept_code( @codes )"


Alias de unaccept_codes.


"$parser->unaccept_codes( @codes )"


Elimina @codes como códigos válidos para el análisis.


"$parser->unaccept_directive( @directives )"


Alias de unaccept_directives.


"$parser->unaccept_directives( @directives )"


Elimina @directives como directivas válidas para el
    análisis.


"$parser->unaccept_target( @targets )"


Alias de unaccept_targets.


"$parser->unaccept_targets( @targets )"


Elimina @targets como objetivos válidos para el
    análisis.


"$parser->version_report()"


Devuelve una cadena que describe la versión.


"$parser->whine( @error_messages )"


Registra un error a menos que "$parser->no_whining( TRUE );".








CODIFICACIÓN


El analizador Pod::Simple espera leer **octetos**. El analizador
    decodificará los octetos en la representación de cadena de caracteres interna
    de Perl utilizando el valor de la declaración "=encoding"
    en la fuente del POD.


Si la fuente del POD no incluye una declaración
    "=encoding", el analizador intentará adivinar la
    codificación (seleccionando UTF-8 o CP 1252) examinando los primeros
    bytes no ASCII y aplicando la heurística descrita en perlpodspec. (Si la
    fuente del POD contiene solo bytes ASCII, se asume que la codificación es
    ASCII).


Si establece la opción "parse_characters"
    a un valor verdadero, el analizador esperará caracteres en lugar de octetos;
    ignorará cualquier "=encoding"; y no intentará
    decodificar la entrada.
