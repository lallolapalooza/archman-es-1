POE::Component::Client::DNS(3) Documentación de Perl aportada por el usuario POE::Component::Client::DNS(3)

NOMBRE

POE::Component::Client::DNS - cliente DNS no bloqueante y paralelo

VERSIÓN

versión 1.054

SINOPSIS

use POE qw(Component::Client::DNS);
my $named = POE::Component::Client::DNS->spawn(
  Alias => "named"
);
POE::Session->create(
  inline_states  => {
    _start   => \&start_tests,
    response => \&got_response,
  }
);
POE::Kernel->run();
exit;
sub start_tests {
  my $response = $named->resolve(
    event   => "response",
    host    => "localhost",
    context => { },
  );
  if ($response) {
    $_[KERNEL]->yield(response => $response);
  }
}
sub got_response {
  my $response = $_[ARG0];
  my @answers = $response->{response}->answer();
  foreach my $answer (@answers) {
    print(
      "$response->{host} = ",
      $answer->type(), " ",
      $answer->rdatastr(), "\n"
    );
  }
}

DESCRIPCIÓN

POE::Component::Client::DNS proporciona solicitudes DNS no bloqueantes y paralelas a través de Net::DNS. Usando POE, permite que otras tareas se ejecuten mientras se espera la respuesta de los servidores de nombres.

Para la resolución de nombres simple, incluyendo el manejo inteligente de nombres IPv6, consulte POE::Component::Resolver en su lugar.

MÉTODOS PÚBLICOS

spawn
Un programa debe iniciar al menos una instancia de POE::Component::Client::DNS antes de poder realizar solicitudes DNS en segundo plano. Cada instancia representa una conexión a uno o más servidores de nombres. Si un programa solo necesita solicitar consultas DNS a un servidor, entonces solo necesita una instancia de POE::Component::Client::DNS.

A partir de la versión 0.98, puede anular el tiempo de espera predeterminado por solicitud. A partir de este momento, ya no es necesario iniciar múltiples instancias para afectar diferentes tiempos de espera para cada solicitud.

El método "spawn" de PoCo::Client::DNS toma algunos parámetros con nombre:

Alias establece el alias del componente. Las solicitudes se enviarán a este alias. El alias del componente es "resolver" por defecto si no se proporciona ninguno. Los programas que inician más de un componente cliente DNS deben especificar alias para N-1 de ellos, de lo contrario ocurrirán colisiones de alias.

Alias => $alias_de_sesion,  # por defecto "resolver"

Timeout establece el tiempo de espera predeterminado del componente. El tiempo de espera se puede anular por solicitud. Ver el evento "request", más adelante. Si no se establece un Timeout, el componente esperará 90 segundos por solicitud por defecto.

Los tiempos de espera se pueden establecer como números reales. Los tiempos de espera son más precisos si tiene Time::HiRes instalado. POE (y, por lo tanto, este componente) utilizará Time::HiRes automáticamente si está disponible.

Timeout => $segundos_a_esperar,  # por defecto 90

Nameservers contiene una referencia a una lista de servidores de nombres a intentar. La lista se pasa directamente al método nameservers() de Net::DNS::Resolver. Por defecto, POE::Component::Client::DNS consultará los servidores de nombres que aparecen en /etc/resolv.conf o su equivalente.

Nameservers => \@servidores_de_nombres,  # por defecto los de /etc/resolv.conf

HostsFile (opcional) contiene el nombre de un archivo de hosts específico a usar para resolver direcciones codificadas. Por defecto, busca un archivo llamado /etc/hosts.

En sistemas Windows, puede buscar en los siguientes lugares adicionales:

$ENV{SystemRoot}\System32\Drivers\Etc\hosts
$ENV{SystemRoot}\System\Drivers\Etc\hosts
$ENV{SystemRoot}\hosts
resolve
resolve() solicita al componente que resuelva un nombre de host. Devolverá una referencia hash (descrita en MENSAJES DE RESPUESTA, abajo) si puede satisfacer la solicitud inmediatamente (quizás desde una caché). De lo contrario, devuelve undef si se debe consultar un resolvedor de forma asíncrona.

Las solicitudes se pasan como una lista de campos con nombre.

$resolver->resolve(
  class       => $clase_registro_dns,  # por defecto "IN"
  type        => $tipo_registro_dns,   # por defecto "A"
  host        => $host_solicitud,      # requerido
  context     => $contexto_solicitud,   # requerido
  event       => $evento_respuesta,    # requerido
  timeout     => $timeout_solicitud,   # por defecto Timeout de spawn()
  nameservers => $servidores_nombres,       # por defecto Nombreservers del $resolver
);

Los campos "class" y "type" especifican qué tipo de información devolver sobre un host. La mayoría de las veces se solicitan direcciones de Internet para nombres de host, por lo que la clase y el tipo son por defecto "IN" (internet) y "A" (dirección), respectivamente.

El campo "host" designa el host a buscar. Es requerido.

El campo "event" le dice al componente qué evento enviar de regreso cuando haya una respuesta disponible. Es requerido, pero no se utilizará si resolve() puede devolver inmediatamente una respuesta en caché.

"timeout" le dice al componente cuánto tiempo esperar una respuesta a esta solicitud. Por defecto, es el "Timeout" proporcionado en el momento de spawn().

"context" incluye algunos datos externos que vinculan las respuestas a sus solicitudes. Los datos de contexto son proporcionados por el programa que utiliza POE::Component::Client::DNS. El componente pasará el contexto de regreso al programa sin modificaciones. El parámetro "context" es requerido y puede contener cualquier cosa que quepa en un escalar.

shutdown
shutdown() hace que el componente termine de forma ordenada. Terminará de atender las solicitudes pendientes y luego se cerrará.
get_resolver
POE::Component::Client::DNS utiliza un objeto Net::DNS::Resolver internamente. get_resolver() devuelve ese objeto para que pueda ser interrogado o modificado. Consulte Net::DNS::Resolver para ver las opciones.

Establezca el resolvedor para verificar en el puerto no estándar 1153:

$poco_client_dns->get_resolver()->port(1153);

MENSAJES DE RESPUESTA

POE::Component::Client::DNS responde de una de dos maneras. Su método resolve() devolverá una respuesta inmediatamente si se puede encontrar en la caché del componente. De lo contrario, el componente publica la respuesta en $_[ARG0]. En cualquier caso, la respuesta es una referencia hash que contiene los mismos campos:

host     => $host_solicitud,
type     => $tipo_solicitud,
class    => $clase_solicitud,
context  => $contexto_solicitud,
response => $paquete_net_dns,
error    => $error_net_dns,

Los campos de respuesta "host", "type", "class" y "context" son idénticos a los proporcionados en el mensaje de solicitud.

"response" contiene un objeto Net::DNS::Packet en caso de éxito o undef si la consulta falló. El objeto Net::DNS::Packet describe la respuesta a la solicitud del programa. Puede contener varios registros DNS. Consulte Net::DNS y Net::DNS::Packet para obtener más información.

"error" contiene una descripción de cualquier error que haya ocurrido. Solo es válido si "response" no está definido.

VER TAMBIÉN

POE - POE::Component::Client::DNS se basa en gran medida en POE.

POE::Component::Resolver - Un resolvedor de nombres del sistema, incluyendo soporte para IPv6 y cualquier otra cosa que su sistema admita.

Net::DNS - Este módulo utiliza Net::DNS internamente.

Net::DNS::Packet - Las respuestas se devuelven como objetos Net::DNS::Packet.

OBSOLESCENCIA

Las interfaces más antiguas basadas en listas ya no se documentan a partir de la versión 0.98. Se están eliminando gradualmente. La interfaz basada en métodos, implementada por primera vez en la versión 0.98, reemplazará a las interfaces obsoletas después de un período de eliminación de seis meses.

La versión 0.98 se lanzó en octubre de 2004. Las interfaces obsoletas continuarán funcionando sin advertencias hasta enero de 2005.

DEPRECATIONS

The POE::Component::Client::DNS module is deprecated. It will continue to work, but it will generate mandatory warnings. Those warnings will persist until April 2005.

As of April 2005 the mandatory warnings will be upgraded to mandatory errors. Support for the deprecated interfaces will be removed entirely.

As of late January 2011, POE::Component::Resolver provides basic system resolver support, including IPv6 and mDNS if your resolver's configured ot use it. The use of POE::Component::Client::DNS for basic resolution is deprecated, however it's still the best option for actual DNS server requests.
