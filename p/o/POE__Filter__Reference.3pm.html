POE::Filter::Reference(3) Documentación de Perl aportada por el usuario POE::Filter::Reference(3)

NOMBRE

POE::Filter::Reference - serializar y deserializar datos de Perl arbitrarios

SINOPSIS

#!perl
use YAML;
use POE qw(Wheel::ReadWrite Filter::Reference);
POE::Session->create(
  inline_states => {
    _start => sub {
      pipe(my($read, $write)) or die $!;
      $_[HEAP]{io} = POE::Wheel::ReadWrite->new(
        InputHandle => $read,
        OutputHandle => $write,
        Filter => POE::Filter::Reference->new(),
        InputEvent => "got_perl_data",
      );
      $_[HEAP]{io}->put(
        { key_1 => 111, key_2 => 222 }
      );
    },
    got_perl_data => sub {
      print "Recibido:\n", YAML::Dump($_[ARG0]);
      print "¡Adiós!\n";
      delete $_[HEAP]{io};
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPCIÓN

POE::Filter::Reference permite a los programas enviar y recibir estructuras de datos de Perl arbitrarias sin preocuparse por un protocolo de línea. Su método put() serializa datos de Perl en un flujo de bytes adecuado para la transmisión. get_one() analiza las estructuras de datos de nuevo a partir de dicho flujo.

Por defecto, POE::Filter::Reference utiliza Storable para hacer su magia. Se puede especificar un serializador diferente en el momento de la construcción.

MÉTODOS PÚBLICOS DEL FILTRO

new

new() crea e inicializa un objeto POE::Filter::Reference. Acepta una lista de parámetros con nombre.

Serializer

Cualquier clase que soporte nfreeze() (o freeze()) y thaw() puede usarse como Serializador. Si un Serializador implementa tanto nfreeze() como freeze(), entonces se usará la versión "de red" (nfreeze).

Serializer puede ser un nombre de clase:

# Usar Storable explícitamente, especificado por el nombre del paquete.
my $filter = POE::Filter::Reference->newer( Serializer=>"Storable" );
# Usar YAML en su lugar. Comprimir su salida, ya que puede ser verbosa.
my $filter = POE::Filter::Reference->new("YAML", 1);

Serializer también puede ser un objeto:

# Usar un objeto.
my $serializer = Data::Serializer::Something->new();
my $filter = POE::Filter::Reference->newer( Serializer => $serializer );

Si Serializer se omite o es undef, el filtro Reference intentará usar Storable, FreezeThaw y YAML en ese orden. POE::Filter::Reference fallará si no puede encontrar uno de estos serializadores, pero esto rara vez sucede ya que Storable y YAML vienen incluidos con Perl.

Compression

Si Compression es verdadero, Compress::Zlib se utilizará para reducir el tamaño de los datos serializados. También descomprimirá los datos de entrada del flujo.

MaxBuffer

"MaxBuffer" establece la cantidad máxima de datos que el filtro retendrá mientras intenta construir una nueva referencia. El valor predeterminado es 512 MB.

NoFatals

Si NoFatals es verdadero, los mensajes se deserializarán dentro de un bloque eval. Por defecto, sin embargo, thaw() puede fallar normalmente. Si ocurre un error mientras NoFatals está en efecto, POE::Filter::Reference devolverá una cadena que contiene el contenido de $@ en el momento en que el eval falló. Por lo tanto, al usar NoFatals, es importante verificar si la entrada es realmente una referencia:

sub got_reference {
  my $message = $_[ARG0];
  if (ref $message) {
    print "Recibido:\n", YAML::Dump($message);
  }
  else {
    warn "Error de decodificación de entrada: $message\n";
  }
}

new() intentará cargar cualquier clase que necesite para "Compression" o "Serializer".

new [SERIALIZER [, COMPRESSION [, NO_FATALS]]]

Esta es la sintaxis antigua del constructor. No se ajusta a la sintaxis normal de parámetros del constructor de POE::Filter. Utilice la nueva sintaxis en su lugar.

Llamar a "new" de esta manera es equivalente a

POE::Filter::Reference->new( Serializer => SERIALIZER,
                             Compression => COMPRESSION,
                             NoFatals  => NO_FATALS );

Tenga en cuenta que si tiene una clase serializadora personalizada llamada "Serializer", deberá actualizar su código a la nueva sintaxis.

API DEL SERIALIZADOR

Esto es lo que POE::Filter::Reference espera de sus serializadores.

thaw SERIALIZADO

thaw() es obligatorio. Acepta dos parámetros: $self y un escalar que contiene un flujo de bytes SERIALIZADO que representa una única estructura de datos de Perl. Devuelve una estructura de datos de Perl reconstituida.

sub thaw {
  my ($self, $stream) = @_;
  my $reference = $self->_deserialization_magic($stream);
  return $reference;
}

nfreeze REFERENCIA

Se requiere nfreeze() o freeze(). Se comportan de manera idéntica, excepto que se garantiza que nfreeze() es portable a través de redes y entre arquitecturas de máquinas.

Estos serializadores aceptan dos parámetros: $self y una REFERENCIA a datos de Perl. Devuelven una versión serializada de los datos referenciados.

sub nfreeze {
  my ($self, $reference) = @_;
  my $stream = $self->_serialization_magic($reference);
  return $stream;
}

freeze REFERENCIA

freeze() es una forma alternativa de nfreeze(). Tiene la misma firma de llamada que nfreeze(), pero no garantiza que los datos serializados sean portables entre arquitecturas de máquinas.

Si debe elegir entre implementar freeze() y nfreeze() para su uso con POE::Filter::Reference, opte por nfreeze().

ERRORES

No tantos errores como advertencias:

Es importante usar serializadores idénticos en cada extremo de una conexión. Incluso diferentes versiones del mismo serializador pueden romper los datos en tránsito.

La mayoría (si no todos) los serializadores volverán a bendecir los datos en el destino, pero muchos de ellos no cargarán las clases necesarias para que esas bendiciones funcionen. Asegúrese de que las mismas clases y versiones estén disponibles en ambos extremos del cable.
