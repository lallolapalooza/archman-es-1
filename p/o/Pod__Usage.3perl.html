Pod::Usage(3perl) Guía de referencia del programador de Perl Pod::Usage(3perl)

NOMBRE

Pod::Usage - extrae documentación POD y muestra información de uso.

SINOPSIS

use Pod::Usage;
my $message_text  = "Este texto precede al mensaje de uso.";
my $exit_status   = 2;          ## El estado de salida a usar
my $verbose_level = 0;          ## El nivel de verbosidad a usar
my $filehandle    = \*STDERR;   ## El manejador de archivo al que escribir
pod2usage($message_text);
pod2usage($exit_status);
pod2usage( { -message => $message_text ,
             -exitval => $exit_status  ,
             -verbose => $verbose_level,
             -output  => $filehandle } );
pod2usage(   -msg     => $message_text ,
             -exitval => $exit_status  ,
             -verbose => $verbose_level,
             -output  => $filehandle );
pod2usage(   -verbose => 2,
             -noperldoc => 1  );
pod2usage(   -verbose => 2,
             -perlcmd => $path_to_perl,
             -perldoc => $path_to_perldoc,
             -perldocopt => $perldoc_options );

ARGUMENTOS

pod2usage debe recibir un solo argumento, o una lista de argumentos correspondientes a un array asociativo (un "hash"). Cuando se da un solo argumento, éste debe corresponder exactamente a uno de los siguientes:

  • Una cadena que contiene el texto de un mensaje a imprimir *antes* de imprimir el mensaje de uso.
  • Un valor numérico que corresponde al estado de salida deseado.
  • Una referencia a un hash.

Si se dan más de un argumento, entonces se asume que toda la lista de argumentos es un hash. Si se proporciona un hash (ya sea como referencia o como lista), debe contener uno o más elementos con las siguientes claves:

"-message" cadena
"-msg" cadena
El texto de un mensaje a imprimir inmediatamente antes de imprimir el mensaje de uso del programa.
"-exitval" valor
El estado de salida deseado a pasar a la función exit(). Debe ser un entero, o la cadena "NOEXIT" para indicar que el control simplemente debe ser devuelto sin terminar el proceso invocador.
"-verbose" valor
El nivel de "verbosidad" deseado para imprimir el mensaje de uso. Si el valor es 0, entonces solo se imprimen las secciones "SYNOPSIS" y/o "USAGE". Si el valor es 1, entonces se imprimen las secciones "SYNOPSIS" y/o "USAGE", junto con cualquier sección titulada "OPTIONS", "ARGUMENTS", o "OPTIONS AND ARGUMENTS". Si el valor correspondiente es 2 o más, entonces se imprime la página de manual completa, usando perldoc si está disponible; de lo contrario, se usa Pod::Text para el formato. Para una mejor legibilidad, los encabezados en mayúsculas se convierten a minúsculas, por ejemplo, "SYNOPSIS" => "Synopsis".

El nivel especial de verbosidad 99 requiere especificar también el parámetro -sections; entonces estas secciones se extraen y se imprimen.

"-sections" espec
Hay dos maneras de especificar la selección. Ya sea una cadena (escalar) que representa una expresión regular de selección para las secciones a imprimir cuando -verbose se establece en 99, por ejemplo: 
"NAME|SYNOPSIS|DESCRIPTION|VERSION"

Con la expresión regular anterior, todo el contenido que sigue (e incluyendo) cualquiera de los encabezados "=head1" dados será mostrado. Es posible restringir la salida solo a subsecciones particulares, por ejemplo:

"DESCRIPTION/Algorithm"

Esto imprimirá solo el encabezado "=head2 Algorithm" y el contenido dentro de la sección "=head1 DESCRIPTION". La unión de la expresión regular es más fuerte que el separador de sección, de modo que, por ejemplo:

"DESCRIPTION|OPTIONS|ENVIRONMENT/Caveats"

imprimirá solo la sección "=head2 Caveats" dentro de cualquiera de las tres secciones "=head1".

Alternativamente, se puede usar una referencia a un array de especificaciones de sección:

pod2usage(-verbose => 99, -sections => [
  qw(DESCRIPTION DESCRIPTION/Introduction) ] );

Esto imprimirá solo el contenido de las secciones "=head1 DESCRIPTION" y "=head2 Introduction", pero ninguna otra "=head2", ni ninguna otra "=head1".

"-output" manejador
Una referencia a un manejador de archivo, o la ruta de un archivo al que debe escribirse el mensaje de uso. El valor predeterminado es "\*STDERR" a menos que el valor de salida sea menor que 2 (en cuyo caso el valor predeterminado es "\*STDOUT").
"-input" manejador
Una referencia a un manejador de archivo, o la ruta de un archivo del cual se debe leer la documentación pod del script invocador. Por defecto, es el archivo indicado por $0 ($PROGRAM_NAME para usuarios de English.pm).

Si estás llamando a pod2usage() desde un módulo y quieres mostrar el POD de ese módulo, puedes usar esto:

use Pod::Find qw(pod_where);
pod2usage( -input => pod_where({-inc => 1}, __PACKAGE__) );
"-pathlist" cadena
Una lista de rutas de directorios. Si el archivo de entrada no existe, se buscará en la lista de directorios dada (en el orden en que los directorios aparecen en la lista). Por defecto, es la lista de directorios implícita por $ENV{PATH}. La lista puede especificarse ya sea por una referencia a un array, o por una cadena de rutas de directorios que usan el mismo separador de ruta que $ENV{PATH} en su sistema (por ejemplo, ":" para Unix, ";" para MSWin32 y DOS).
"-noperldoc"
Por defecto, Pod::Usage llamará a perldoc cuando se especifique -verbose >= 2. Esto no funciona bien, por ejemplo, si el script fue empaquetado con PAR. Esta opción suprime la llamada externa a perldoc y utiliza el formateador de texto simple (Pod::Text) para producir la salida del POD.
"-perlcmd"
Por defecto, Pod::Usage llamará a perldoc cuando se especifique -verbose >= 2. En caso de instalaciones de Perl especiales o inusuales, esta opción puede usarse para proporcionar la ruta a un ejecutable de perl que debería ejecutar perldoc.
"-perldoc" ruta-a-perldoc
Por defecto, Pod::Usage llamará a perldoc cuando se especifique -verbose >= 2. En caso de que perldoc no esté instalado donde el intérprete de perl piensa que está (ver Config), la opción -perldoc puede usarse para proporcionar la ruta correcta a perldoc.
"-perldocopt" cadena
Por defecto, Pod::Usage llamará a perldoc cuando se especifique -verbose >= 2. Esta opción puede usarse para proporcionar opciones a perldoc. La cadena puede contener varias opciones separadas por espacios.

Clase base de formato

El formateador de texto predeterminado es Pod::Text. La clase base para Pod::Usage puede definirse preestableciendo $Pod::Usage::Formatter *antes* de cargar Pod::Usage, por ejemplo:

BEGIN { $Pod::Usage::Formatter = 'Pod::Text::Termcap'; }
use Pod::Usage qw(pod2usage);

Pod::Usage utiliza el método _handle_element_end() de Pod::Simple para implementar la selección de secciones y, en caso de verbosidad < 2, convierte los encabezados en mayúsculas a la primera letra mayúscula y el resto en minúsculas, y agrega dos puntos/nueva línea al final de los encabezados, para una mejor legibilidad. Lo mismo ocurre con la verbosidad = 99.

NAME

Pod::Usage - convenience interface to Pod::Text and Pod::Parser

SYNOPSIS

 use Pod::Usage;
 use Pod::Text;
 my $text = Pod::Text->new( );
 my $parser = Pod::Parser->new( );
 pod2usage( \"$0, version 0.01\" );
 pod2usage( \"Cannot open $file: $!\" );
 pod2usage( \"Cannot open $file: $!\", 2 );
 pod2usage( \"Cannot open $file: $!\", exitval => 2 );
 pod2usage( { -message => \"bad option: $opt\", -verbose => 1 } );
 pod2usage( { -message => \"bad option: $opt\", -verbose => 0 } );
 pod2usage( { -exitval => 'soft', -verbose => 1, -output => \*STDOUT } );
 pod2usage( { -exitval => 'NOEXIT', -verbose => 1, -output => \*STDOUT } );
 pod2usage( \$document );

ARGUMENTS

pod2usage() takes a single argument, which can be a scalar string, a reference to a scalar string, or a hash reference. The hash reference allows for more fine-grained control.

The string argument is treated as an error message to be printed to STDERR. A default usage message will be printed before the error message. If the string is meant to be the *only* output, pass it in a hash reference with -verbose set to 0.

The hash reference can contain the following keys:

-message
The error message to display. If not given, and a string is passed, that string is used. If neither is given, nothing is printed to STDERR.
-verbose
This determines how much information to print. It can be a number or a string.

If it is a number, it is treated as the exit status to use. (See -exitval.)

If it is a string, it is interpreted as the name of a manpage (or a file containing a manpage) to display. The manpage is displayed using Pod::Text or Pod::Text::Termcap, depending on your terminal's capabilities.

If the value is 0, only the error message (if any) is printed, and no manpage is displayed. This is the default if the message is non-empty.

If the value is 1, the manpage is displayed. This is the default if no message is given.

Any other positive integer is treated as an exit status and is equivalent to setting -exitval to that number.

-exitval
This determines the exit status of the program. It can be a number, or the string soft or NOEXIT.

If it is a number, the program exits with that status after printing.

If it is soft, the program exits with status 0 if no error message was given, and 1 otherwise.

If it is NOEXIT, the program does not exit at all.

The default is soft.

-output
This is a filehandle or a reference to one. If given, the manpage is printed to this filehandle. By default, it is set to STDERR.

This is a filehandle or a reference to one. If given, the error message is printed to this filehandle. By default, it is set to STDERR.

DESCRIPTION

The Pod::Usage module is intended to provide a convenient way to display usage messages and manpages. It's particularly useful for handling errors and displaying help information from command-line scripts.

When you call pod2usage(), it attempts to locate the POD documentation for the calling script (or module). It then formats this documentation using Pod::Text and prints it to STDERR (or the filehandle specified by -output).

If an error message is provided (either as a string argument or via the -message key in a hash reference), it will be printed to STDERR (or the filehandle specified by - செய்யுங்கள்) before the usage message.

The module tries to be smart about where it finds the POD documentation. It looks for the POD in the main script file first. If that doesn't work, it tries to find the script via the standard module search path.

The -verbose argument is the most powerful. If it's a string, it's treated as a manpage name. This allows you to display the documentation for other modules or even arbitrary manpages installed on your system.

The -exitval argument controls program termination. The default behavior (soft) is to exit with 0 on success (no error message) and 1 on failure (error message provided).

EXAMPLES

 #!/usr/bin/perl
 use strict;
 use warnings;
 use Getopt::Long;
 use Pod::Usage;
 
 my $man = 0;
 my $help = 0;
 my $filename = '';
 
 GetOptions( 'help|?' => \$help, man => \$man, filename=s => \$filename )
  or pod2usage( 2 );
 
 if ($help) {
  pod2usage( -verbose => 1 );
 }
 if ($man) {
  pod2usage( -man => 1, -verbose => 1 );
 }
 
 # ... rest of your script ...
 
 pod2usage( -message => \"No filename specified\", -verbose => 0 ) unless $filename;
 
 exit 0;
 
=head1 NAME
 
 my script - A simple example script
 
=head1 SYNOPSIS
 
 my_script.pl --filename <file> [--help] [--man]
 
=head1 DESCRIPTION
 
 This script demonstrates the use of Getopt::Long and Pod::Usage.
 
=head1 OPTIONS
 
=over
 
=item B --filename <file>
 
 Specifies the file to process.
 
=item B --help
 
 Displays a help message.
 
=item B --man
 
 Displays the full man page.
 
=back

 Your Name <you@example.com>
 
=cut

CAVEATS

Previously, Pod::Usage depended directly on Pod::Parser. This has been refactored, and now depends on Pod::Simple which in turn may use Pod::Text. You may need to install these modules separately if they are not already installed.

Determining the "correct" manpage to display can sometimes be tricky, especially in complex module distributions. The module does its best to find the POD for the calling script.
