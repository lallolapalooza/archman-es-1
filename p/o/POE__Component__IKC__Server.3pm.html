NOMBRE

POE::Component::IKC::Server - Servidor de comunicación entre kernels de POE (IKC)

SINOPSIS

use POE;
use POE::Component::IKC::Server;
POE::Component::IKC::Server->spawn(
    ip=>$ip, 
    port=>$port,
    name=>'Servidor');
...
$poe_kernel->run();

DESCRIPCIÓN

Este módulo implementa un servidor IKC de POE. Un servidor IKC escucha las conexiones entrantes de clientes IKC. Cuando un cliente se conecta, negocia ciertos parámetros de conexión. Después de esto, el servidor y el cliente POE son prácticamente idénticos.

FUNCIONES EXPORTADAS

"crear_servidor_ikc"

Obsoleto. Usa "spawn" en POE::Component::IKC::Server.

MÉTODOS DE CLASE

"spawn"

Este método inicia todo el trabajo de construcción del servidor IKC. Los parámetros son:

"ip"
Dirección en la que escuchar. Puede ser una dirección IP con puntos ('127.0.0.1') o un nombre de host ('foo.pied.nu'). El valor predeterminado es '0.0.0.0', también conocido como INADDR_ANY.
"port"
Puerto en el que escuchar. Puede ser numérico (80) o un servicio ('http'). Si no se especifica, el valor predeterminado será 603. Si estableces el puerto a 0, se elegirá un puerto aleatorio y "spawn" devolverá el número de puerto. 
my $port = POE::Component::IKC::Server->spawn( port => 0 );
warn "Escuchando en el puerto $port";
"unix"
Ruta al socket Unix en el que escuchar. Nota: esta ruta se elimina antes de intentar crear el socket. ¡Cuidado con el comprador!
"name"
Nombre local del kernel. Así es como nos "anunciaremos" a los kernels remotos. Actúa como un "alias de kernel". Este parámetro es temporal, pendiente de la adición de nombres de kernel reales en el núcleo de POE. Este nombre, y todos los alias, se registrarán con el respondedor para que puedas enviarles mensajes como si fueran remotos.
"aliases"
Una referencia a un array de alias adicionales para este kernel. ¡Diversión, diversión, diversión!
"verbose"
Imprime información adicional en STDERR si es verdadero. Esto te permite ver lo que está sucediendo y potencialmente solucionar problemas.
"processes"
Activa el código del servidor pre-fork. Si se establece en un valor positivo, IKC creará process-1 hijos. Las solicitudes IKC solo son atendidas por los hijos. El valor predeterminado es 1 (es decir, no se crea ningún proceso hijo).
"babysit"
Tiempo, en segundos, entre invocaciones del evento babysitter.
"connections"
Número de conexiones que un hijo aceptará antes de salir. Actualmente, las conexiones se atienden de forma concurrente, ya que no hay forma de saber cuándo hemos terminado una solicitud. El valor predeterminado es 1 (es decir, una conexión por hijo).
"concurrency"
Número de clientes conectados simultáneamente permitidos. El valor predeterminado es 0 (ilimitado).

Ten en cuenta que esto es por instancia de IKC::Server; si tienes varias formas de conectarte a un servidor IKC determinado (por ejemplo, tanto un puerto TCP/IP como un pipe Unix), no compartirán el recuento de conexiones concurrentes.

"protocol"
Qué protocolo de negociación IKC usar. El protocolo original ("IKC") tenía un handshake síncrono lento. El nuevo protocolo ("IKC0") envía toda la información del handshake a la vez. IKC0 degradará con gracia a IKC, si el cliente y el servidor no coinciden.

El valor predeterminado es IKC0.

"on_error"
Una referencia de código que se llama para todos los errores. Podrías usar esto para monitorizar problemas al crear procesos hijos o al abrir el socket. Los parámetros son "$operación, $errnum y $errstr", que corresponden al Evento de Fallo de POE::Wheel::SocketFactory, que se puede consultar.

Sin embargo, IKC/monitor proporciona un mecanismo más potente para detectar errores. Consulta POE::Component::IKC::Responder.

Ten en cuenta también que la referencia de código se ejecutará desde dentro de una sesión IKC, NO dentro de tu propia sesión. Esto significa que cosas como $poe_kernel->delay_set() no harán lo que crees que deberían hacer.

"POE::Component::IKC::Server::spawn" devuelve undef(), a menos que especifiques un "port"=0, en cuyo caso, "spawn" devuelve el puerto que se eligió.

EVENTOS

shutdown

Este evento hace que el servidor cierre su socket, limpie todo y se vaya. Normalmente, solo se envía desde IKC::Responder.

ERRORES

El pre-forking es algo así como un truco. En particular, debes asegurarte de que tus sesiones permitirán que los hijos salgan. Esto significa que, si tienes un bucle de delay() o un bucle de eventos, los hijos no saldrán. Una vez que POE obtenga eventos multicast, cambiaré este comportamiento.
