POE::Wheel::FollowTail(3) User Contributed Perl Documentation POE::Wheel::FollowTail(3)

NOMBRE

POE::Wheel::FollowTail - seguir la cola de un archivo en constante crecimiento

SINOPSIS

#!perl
use POE qw(Wheel::FollowTail);
POE::Session->create(
  inline_states => {
    _start => sub {
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        ResetEvent => "got_log_rollover",
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    },
    got_log_rollover => sub {
      print "Log rolled over.\n";
    },
  }
);
POE::Kernel->run();
exit;

DESCRIPCIÓN

Los objetos POE::Wheel::FollowTail vigilan nuevos datos al final de un archivo y generan nuevos eventos cuando ocurren cosas con el archivo. Su parámetro "Filter" define cómo analizar los datos del archivo. Cada nuevo elemento se envía a la sesión del creador como un evento "InputEvent". La rotación del registro activará un "ResetEvent".

POE::Wheel::FollowTail solo lee de un archivo, por lo que no implementa un método put().

MÉTODOS PÚBLICOS

new

new() devuelve un nuevo objeto POE::Wheel::FollowTail. Mientras este objeto exista, generará eventos cuando el estado del archivo correspondiente cambie.

new() acepta un pequeño conjunto de parámetros con nombre:

Driver

El parámetro opcional "Driver" especifica qué controlador usar al leer del archivo seguido. Si se omite, POE::Wheel::FollowTail usará POE::Driver::SysRW. Esto es casi siempre lo correcto.

Filter

"Filter" es un parámetro de constructor opcional que especifica cómo analizar los datos del archivo seguido. Por defecto, POE::Wheel::FollowTail usará POE::Filter::Line para analizar archivos como texto plano separado por saltos de línea.

$_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
  Filename => "/var/log/snort/alert",
  Filter => POE::Filter::Snort->new(),
  InputEvent => "got_snort_alert",
);

PollInterval

POE::Wheel::FollowTail necesita verificar periódicamente si hay nuevos datos en el archivo seguido. "PollInterval" especifica el número de segundos a esperar entre verificaciones. Las aplicaciones que necesiten verificar una vez por segundo pueden omitir "PollInterval", ya que su valor predeterminado es 1.

Se pueden usar intervalos de sondeo más largos para reducir la sobrecarga de sondeo para archivos actualizados con poca frecuencia.

$_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
  ...,
  PollInterval => 10,
);

Seek

Si se especifica, "Seek" instruye a POE::Wheel::FollowTail a buscar en una posición específica en el archivo seguido antes de comenzar a leer. Un valor positivo de "Seek" se interpreta como el número de octetos a buscar desde el inicio del archivo. Un "Seek" negativo, al igual que los índices negativos de arreglos, buscará hacia atrás desde el final del archivo. Un "Seek" de cero comenzará a leer desde el principio del archivo.

Tenga cuidado al usar "Seek", ya que es muy fácil buscar en medio de un registro. En caso de duda, y al comenzar al final del archivo, omita "Seek" por completo. POE::Wheel::FollowTail buscará 4 kilobytes hacia atrás desde el final del archivo, luego analizará y descartará todos los registros hasta EOF. Siempre que los registros del archivo sean más pequeños que 4 kilobytes, esto garantizará que el primer registro devuelto esté completo.

"Seek" también se puede usar con el método tell() de la rueda para restaurar la posición del archivo después de un reinicio del programa. Guarde el valor de tell() antes de salir, y cárguelo y búsquelo de nuevo en el inicio posterior.

SeekBack

"SeekBack" se comporta como la inversa de "Seek". Un valor positivo actúa como un "Seek" negativo. Un valor negativo actúa como un "Seek" positivo. Un "SeekBack" de cero instruye a POE::Wheel::FollowTail a comenzar al final absoluto del archivo.

"Seek" y "SeekBack" son mutuamente excluyentes.

Consulte "Seek" para conocer advertencias, técnicas y una explicación de la magia que ocurre cuando no se especifica ni "Seek" ni "SeekBack".

Handle

POE::Wheel::FollowTail puede seguir un "Handle" de archivo abierto previamente. Desafortunadamente, no puede seguir reinicios de registro de esta manera, ya que no podrá reabrir el archivo una vez que se haya reiniciado. Las aplicaciones que deben seguir reinicios deben usar "Filename" en su lugar.

"Handle" sigue siendo útil para archivos que nunca se reiniciarán, o para dispositivos que requieren una configuración fuera del alcance de POE::Wheel::FollowTail.

"Handle" y "Filename" son mutuamente excluyentes. Sin embargo, uno de ellos es obligatorio.

Filename

Especifique el "Filename" a vigilar. POE::Wheel::FollowTail esperará a que aparezca el archivo si no existe. La rueda también reabrirá el archivo si desaparece, como cuando se ha reiniciado o rotado. En caso de reinicio, POE::Wheel::FollowTail también emitirá un "ResetEvent", si se ha solicitado uno.

"Handle" y "Filename" son mutuamente excluyentes. Sin embargo, uno de ellos es obligatorio.

Consulte la "SINOPSIS" para ver un ejemplo.

IdleEvent

"IdleEvent" es un evento opcional. Si se especifica, se activará cada vez que POE::Wheel::FollowTail verifique la actividad pero no vea nada. Se agregó en POE 1.362 como una forma de avanzar ciertos programas de prueba sin necesidad de esperar cantidades de tiempo conservadoramente grandes.

"IdleEvent" se describe en "EVENTOS PÚBLICOS".

InputEvent

El parámetro "InputEvent" es obligatorio y especifica el evento que se emitirá cuando lleguen nuevos datos al archivo vigilado. "InputEvent" se describe en detalle en "EVENTOS PÚBLICOS".

ResetEvent

"ResetEvent" es opcional. Especifica el nombre del evento que indica el cambio o reinicio del archivo. Por favor, consulte "EVENTOS PÚBLICOS" para más detalles.

ErrorEvent

POE::Wheel::FollowTail puede emitir opcionales "ErrorEvent"s siempre que tenga problemas. Los datos que vienen con este evento se explican en "EVENTOS PÚBLICOS".

event

event() permite a una sesión cambiar los eventos emitidos por una rueda sin destruir y recrear el objeto. Acepta uno o más de los eventos listados en "EVENTOS PÚBLICOS". Los nombres de eventos indefinidos desactivan esos eventos.

Dejar de manejar reinicios de registro:

sub some_event_handler {
  $_[HEAP]{tailor}->event( ResetEvent => undef );
}

Los eventos se describen con más detalle en "EVENTOS PÚBLICOS".

ID

El método ID() devuelve el ID único de la rueda. Es útil para almacenar la rueda en un hash. Todos los eventos de POE::Wheel deben ir acompañados de un ID de rueda, que permite referenciar la rueda en sus manejadores de eventos.

sub setup_tailor {
  my $wheel = POE::Wheel::FollowTail->new(... incompleto ...);
  $_[HEAP]{tailors}{$wheel->ID} = $wheel;
}

Consulte el ejemplo en "ErrorEvent" para ver un manejador que encontrará esta rueda nuevamente.

tell

El método tell() devolverá la posición actual de lectura en el archivo. Esto es útil para guardar el estado de la rueda y reanudarla más tarde.

sub check_and_exit {
  # guardamos la posición actual para poder reanudar más tarde
  my $pos = $_[HEAP]{tailor}->tell();
  # ...
  POE::Kernel->stop();
}

EVENTOS PÚBLICOS

POE::Wheel::FollowTail emitirá los siguientes eventos:

InputEvent

Un evento "InputEvent" se emite cada vez que POE::Wheel::FollowTail detecta nuevos datos en el archivo seguido. Los datos que acompañan a este evento dependen del "Filter" que se esté utilizando. El valor predeterminado de "Filter", POE::Filter::Line, enviará cada línea de texto como un argumento separado por el evento "InputEvent".

Los datos se pasarán como $_[ARG0] para la sesión del creador.

"InputEvent" es obligatorio.

ResetEvent

Un evento "ResetEvent" se emite cuando POE::Wheel::FollowTail detecta que el archivo ha sido reiniciado (es decir, se ha acortado o eliminado y recreado). Esto suele ocurrir cuando los archivos de registro se rotan.

Si se solicita "ResetEvent", se enviará un evento con el nombre especificado a la sesión del creador. No se pasan datos con este evento.

"ResetEvent" es opcional.

IdleEvent

Un evento "IdleEvent" se emite cada vez que POE::Wheel::FollowTail verifica si hay nuevos datos y no encuentra ninguno. Esto puede ser útil en ciertos casos, como para evitar que un programa de prueba se bloquee.

No se pasan datos con este evento.

"IdleEvent" es opcional.

ErrorEvent

Se emitirá un evento "ErrorEvent" si POE::Wheel::FollowTail encuentra un problema. Los datos adjuntos a este evento son una cadena que describe el error.

Si se genera un evento "ErrorEvent", se pasará la siguiente información a la sesión del creador:

Wheel ID

El ID de la rueda que generó el error.

Error String

Una descripción legible por humanos del error.

Un manejador de eventos típico para esto podría ser:

sub log_wheel_error {
  my ($wheel_id, $error_string) = @_[ARG0, ARG1];
  print STDERR "Error in wheel $wheel_id: $error_string\n";
  # si sabemos que es una rueda FollowTail, podemos intentar reiniciarla
  # pero un reinicio no siempre es posible
  # delete $_[HEAP]{tailors}{$wheel_id};
}

"ErrorEvent" es opcional.

TUTORIAL

Aquí hay un ejemplo de cómo usar POE::Wheel::FollowTail para monitorear el archivo de registro de un sistema:

use strict;
use warnings;

use POE qw( Wheel::FollowTail Filter::Line );

# El nombre del archivo de registro a seguir
my $LOGFILE = '/var/log/syslog'; # Cambia esto según sea necesario

POE::Session->create(
    inline_states => {
        _start => sub {
            my $session = shift;
            print "Starting log tailer for $LOGFILE...\n";

            # Crear la rueda FollowTail
            $session->yield(
                'spawn',
                POE::Wheel::FollowTail->new(
                    # El archivo a seguir
                    Filename   => $LOGFILE,
                    # El evento a emitir cuando lleguen nuevas líneas
                    InputEvent => 'log_line',
                    # El evento a emitir cuando el archivo se reinicie/rotará
                    ResetEvent => 'log_reset',
                    # El filtro a usar para leer el archivo (predeterminado es línea)
                    Filter     => POE::Filter::Line->new(),
                    # Intervalo de sondeo en segundos (predeterminado es 1)
                    PollInterval => 1,
                    # Evento para manejar errores
                    ErrorEvent => 'log_error',
                )
            );
        },
        # Manejador para las líneas de registro que llegan
        log_line => sub {
            my ($line) = @_;
            print "LOG: $line\n";
        },
        # Manejador para cuando el archivo de registro se reinicia
        log_reset => sub {
            print "LOG file reset or rotated.\n";
            # Aquí podrías querer hacer algo, como reabrir otros archivos
            # o registrar el evento de reinicio.
        },
        # Manejador para errores de la rueda
        log_error => sub {
            my ($wheel_id, $error_msg) = @_;
            print STDERR "FollowTail Wheel Error ($wheel_id): $error_msg\n";
        },
        # Manejador para salir limpiamente
        shutdown => sub {
            print "Shutting down log tailer.\n";
            POE::Kernel->stop();
        },
    },
    heap => {
        # Aquí podemos almacenar la rueda si necesitamos acceder a ella más tarde
        # por ejemplo, para llamar a tell()
        tailer => undef,
    }
);

# Espera por una señal de interrupción para apagar limpiamente
$SIG{INT} = $SIG{TERM} = sub { POE::Kernel->postfind('main')->call('shutdown') };

# Ejecuta el kernel de POE
POE::Kernel->run();

exit;

Este script creará una rueda POE::Wheel::FollowTail que vigilará el archivo especificado. Cada vez que se agregue una nueva línea al archivo, se emitirá un evento "log_line" con la línea como argumento. Si el archivo se reinicia (por ejemplo, debido a la rotación de registros), se emitirá un evento "log_reset". Los errores se informarán a través del evento "log_error". El script se cerrará limpiamente cuando reciba una señal INT o TERM.

POE::Wheel::FollowTail(3pm) — ArchWiki

NAME

POE::Wheel::FollowTail - Follow the end of a file, like tail(1)

SYNOPSIS

use POE::Wheel::FollowTail;

my $session = POE::Session->create(
    inline_registered_subs => {
        _start => sub {
            my $heap = $_[HEAP];
            $heap->{tailor} = POE::Wheel::FollowTail->new(
                File => shift, # The file to watch
                InputEvent => "file_update",
                ErrorEvent => "tail_error",
                ResetEvent => "file_reset",
            );
        },
        file_update => sub {
            my ($data, $wheel_id) = @_[ARG0, ARG1];
            print "Got $wheel_id: $data\n";
        },
        file_reset => sub {
            my $wheel_id = $_[ARG0];
            warn "File $wheel_id was reset.\n";
        },
        tail_error => sub {
            my ($operation, $errnum, $errstr, $wheel_id) = @_[ARG0..ARG3];
            warn "Wheel $wheel_id: $operation error $errnum: $errstr\n";
            delete $_[HEAP]{tailors}{$wheel_id}; # XXX: Not robust. Do better.
        },
    },
);

POE::Kernel->run();

DESCRIPTION

POE::Wheel::FollowTail is a POE Wheel that watches a file for new data, much like the tail(1) command. It can also detect when a file has been rotated or truncated (reset).

The wheel's main purpose is to provide an easy way to watch log files, or any file from which new data is continually appended.

The wheel may be used in one of two ways:

  • As a filehandle: The wheel is an object that contains an actual filehandle. This is the default mode.

  • As a filename: The wheel watches a file by name. This is necessary when the wheel needs to detect when the file has been reset (rotated, truncated, etc.).

PUBLIC METHODS

new

The constructor for POE::Wheel::FollowTail. It accepts the following parameters:

File

The filename to watch. If this parameter is omitted, the wheel will be constructed from an existing filehandle (see Handle).

Handle

The filehandle to watch. If this parameter is omitted, the wheel will be constructed from a filename (see File).

Seek

A numeric value to seek to when the wheel is first created. This is useful for resuming watching a file where you last left off.

Filter

A subroutine which will be called for each line read from the file. The subroutine will receive the line as its first parameter, and must return the data that will be passed as ARG0 to the InputEvent. This is useful for parsing log lines, etc.

sub parse_log_line {
  my $line = shift;
  # ... parse the line ...
  return { parsed => 1, data => $parsed_data };
}
InputEvent

The name of the event to emit when new data arrives in the file. Defaults to "InputEvent".

ResetEvent

The name of the event to emit when the file is reset. This is only available when watching files by name. Defaults to "ResetEvent".

IdleEvent

The name of the event to emit when the wheel detects no activity on the file. Defaults to "IdleEvent".

ErrorEvent

The name of the event to emit when an error occurs. Defaults to "ErrorEvent".

tell

Returns the current position for the file being watched by POE::Wheel::FollowTail. It may be useful for saving the position program termination. new()'s "Seek" parameter may be used to resume watching the file where tell() left off.

sub handle_shutdown {
  # Not robust.  Do better in production.
  open my $save, ">", "position.save" or die $!;
  print $save $_[HEAP]{tailor}->tell(), "\n";
  close $save;
}
sub handle_startup {
  open my $save, "<", "position.save" or die $!;
  chomp(my $seek = <$save>);
  $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
    ...,
    Seek => $seek,
  );
}

PUBLIC EVENTS

POE::Wheel::FollowTail emits a small number of events.

IdleEvent

"IdleEvent" specifies the name of an event to be fired when POE::Wheel::FollowTail doesn't detect activity on the watched file.

$_[ARG0] contains the ID of the POE::Wheel::FollowTail object that fired the event.

InputEvent

"InputEvent" sets the name of the event to emit when new data arrives into the tailed file. The event will be accompanied by two parameters:

$_[ARG0] contains the data that was read from the file, after being parsed by the current "Filter".

$_[ARG1] contains the wheel's ID, which may be used as a key into a data structure tracking multiple wheels. No assumption should be made about the nature or format of this ID, as it may change at any time. Therefore, track your wheels in a hash.

See the "SYNOPSIS" for an example.

ResetEvent

"ResetEvent" names the event to be emitted whenever the wheel detects that the followed file has been reset. It's only available when watching files by name, as POE::Wheel::FollowTail must reopen the file after it has been reset.

"ResetEvent" comes with only one parameter, $_[ARG0], which contains the wheel's ID. See "InputEvent" for some notes about what may be done with wheel IDs.

See the "SYNOPSIS" for an example.

ErrorEvent

"ErrorEvent" names the event emitted when POE::Wheel::FollowTail encounters a problem. Every "ErrorEvent" comes with four parameters that describe the error and its situation:

$_[ARG0] describes the operation that failed. This is usually "read", since POE::Wheel::FollowTail spends most of its time reading from a file.

$_[ARG1] and $_[ARG2] contain the numeric and stringified values of $!, respectively. They will never contain EAGAIN (or its local equivalent) since POE::Wheel::FollowTail handles that error itself.

$_[ARG3] contains the wheel's ID, which has been discussed in "InputEvent".

This error handler logs a message to STDERR and then shuts down the wheel. It assumes that the session is watching multiple files.

sub handle_tail_error {
  my ($operation, $errnum, $errstr, $wheel_id) = @_[ARG0..ARG3];
  warn "Wheel $wheel_id: $operation error $errnum: $errstr\n";
  delete $_[HEAP]{tailors}{$wheel_id};
}

BUGS

This wheel can't tail pipes and consoles on some operating systems.

POE::Wheel::FollowTail generally reads ahead of the data it returns, so the tell() position may be later in the file than the data an application has already received.
