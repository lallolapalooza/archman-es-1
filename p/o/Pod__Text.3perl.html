Pod::Text(3perl) Manual de Perl Pod::Text(3perl)

NOMBRE

Pod::Text - Convierte datos POD a texto formateado

SINOPSIS

use Pod::Text;
my $parser = Pod::Text->new (sentence => 1, width => 78);
# Lee POD desde STDIN y escribe a STDOUT.
$parser->parse_from_filehandle;
# Lee POD desde file.pod y escribe a file.txt.
$parser->parse_from_file ('file.pod', 'file.txt');

DESCRIPCIÓN

Pod::Text es un módulo que puede convertir el formato de datos de documento en el formato POD (el lenguaje preferido para documentar Perl) en texto formateado. Usa ningún control de formato especial o códigos, y su salida es, por lo tanto, adecuada para casi cualquier dispositivo.

CODIFICACIÓN

Pod::Text utiliza la siguiente lógica para elegir la codificación de salida, en orden:

1.
Si hay una capa de codificación en el manejador de archivo de salida, no se realizará ningún procesamiento de codificación y se recurrirá a la capa de codificación de PerlIO.
2.
Si se especifican las opciones "encoding" o "utf8", se utilizará la codificación de salida especificada por esas opciones.
3.
Si la codificación del archivo fuente de POD fue explícitamente especificada (usando "=encoding") o detectada automáticamente por Pod::Simple, se utilizará esa como codificación de salida.
4.
Si no se especifica ninguna codificación y se está ejecutando en un sistema no EBCDIC, se utilizará UTF-8 como codificación de salida. Como es un superconjunto de ASCII, esto generará salida ASCII sin declarar o detectar una codificación (generalmente mediante escapes E<>).
5.
Para sistemas EBCDIC, se emitirá texto sin codificación, esperando que funcione.

Una advertencia: Pod::Text tiene que comprometerse con una codificación de salida al emitir un carácter no ASCII por primera vez, y luego tiene que seguir con esa codificación para mantener la consistencia. Sin embargo, los comandos "=encoding" no tienen que estar al principio de un documento de POD. Si alguien usa un carácter no ASCII temprano en un documento con un escape, como E<"EF>, y luego coloca "=encoding iso-8859-1", idealmente Pod::Text seguiría la regla 3 y emitiría el documento completo en ISO 8859-1. En su lugar, se comprometerá a UTF-8 al ver ese escape, y luego seguirá con esa codificación para el resto del documento.

A pesar de que no hay una buena elección universal para la codificación de salida, cada elección será incorrecta en algunos casos. Esta aproximación fue elegida principalmente por compatibilidad hacia atrás. Los llamadores deberían considerar forzar la codificación de salida mediante "encoding" si conocen qué codificación el usuario puede esperar.

En particular, considere importar el módulo Encode::Locale, si lo tiene, y establezca "encoding" en "locale" para utilizar una codificación adecuada al lenguaje de locales del usuario. Sin embargo, tenga en cuenta que si el usuario no usa locales o está usando un locale de "C", Encode::Locale establecerá la codificación de salida en ASCII de EE.UU. Esto causará que los caracteres no ASCII se reemplacen por "?" y produzca un montón de advertencias sobre caracteres no soportados, que puede o no ser lo que desea.

MÉTODOS DE CLASE

new(ARGS)
Crea un objeto Pod::Text nuevo. ARGS debe ser una lista de pares clave-valor, donde las claves son elegidas de las siguientes. Cada opción tiene su significado anotado con la versión del módulo Pod::Text en la que fue añadida, su significado actual.
alt
[2.00] Si se establece en un valor verdadero, selecciona un formato alternativo de salida, que, entre otras cosas, utiliza un estilo de encabezado diferente y marca las entradas "=item" con un : en el margen izquierdo. Por defecto es falso.
code
[2.13] Si se establece en un valor verdadero, los elementos no POD del archivo de entrada se incluirán en la salida. Esto es útil para ver el código documentado con bloques de POD renderizados y el código permanente.
encoding
[5.00] Especifica la codificación de salida. El valor debe ser una codificación reconocida por el módulo Encode (ver Encode::Supported). Si el archivo de salida contiene caracteres que no pueden representarse en esta codificación, se reportará un error según la opción "errors". Si el manejo de errores no es "die", el carácter no representable se reemplazará por el carácter de sustitución de Encode (normalmente "?").

Si el archivo de salida tiene una capa de codificación PerlIO establecida, este parámetro se ignora y no se realiza ninguna codificación por parte de Pod::Man. En su lugar, se recurrirá a la capa de codificación para realizar cualquier transformación deseada.

ADVERTENCIA: La codificación de entrada del archivo de POD es independiente de la codificación de salida y el establecimiento de este parámetro no afecta la interpretación del contenido de POD. No importa si el archivo de POD no es ASCII, su codificación debe especificarse con el comando "=encoding" en el archivo, cerca del principio del archivo. Si no se hace esto, Pod::Simple intentará deducir la codificación y puede tener éxito si es Latin-1 o UTF-8, pero producirá advertencias. Consulte perlpod(1) para más información.

errors
[3.17] Cómo reportar errores. "die" indica que se lanzará una excepción en caso de error en el formateo de POD. "stderr" indica que se reportará el error en el stderr pero no se lanzará una excepción. "pod" indica que se incluirá una sección de errores de POD en la documentación resultante que resuma los errores. "none" ignora los errores de POD tan cerca como sea posible.

El valor por defecto es "pod".

guesswork
[5.01] Por defecto, Pod::Text aplica algunas reglas de formato basadas en suposiciones y expresiones regulares que están diseñadas para hacer más fácil la escritura de documentación Perl y reducir la necesidad de marcaje explícito. Estas reglas no siempre son adecuadas, especialmente para documentos no relacionados con Perl. Esta opción permite activar o desactivar parte de estas reglas.

El valor especial "all" activa todas las reglas de suposición. Esto es también el valor por defecto para compatibilidad hacia atrás. El valor especial "none" desactiva todas las reglas de suposición. De lo contrario, el valor de esta opción debe ser una lista separada por comas de uno o más de los siguientes términos:

quoting
Si no se activa la suposición, cualquier texto entre C<> se envía entre comillas dobles en la salida nroff (terminal) a menos que los contenidos ya estén comprobados. Cuando se activa la suposición, las comillas también se suprimen para variables de Perl, nombres de funciones, llamadas a funciones, números y constantes hexadecimales.

Cualquier nombre de suposición no reconocido se ignora silenciosamente (para compatibilidad futura), así que tenga cuidado con la escritura.

indent
[2.00] El número de espacios para indentar el texto regular y el valor por defecto para el indentado de bloques "=over". Por defecto es 4.
loose
[2.00] Si se establece en un valor verdadero, se imprime un espacio en blanco después de un encabezado "=head1". Si se establece en falso (el valor por defecto), no se imprime un espacio en blanco después de "=head1", aunque se imprime todavía después de "=head2". Este es el valor por defecto porque es el formato esperado para los manuales; si estás formateando documentos de texto arbitrarios, establecerlo en verdadero puede resultar en una salida más agradable.
margin
[2.00] El número de espacios para el margen izquierdo. Por defecto es 0.
nowrap
[4.00] Si se establece en un valor verdadero, las líneas largas no se cortarán. Esto puede ser útil para formatear fragmentos de código que pueden tener líneas muy largas. El valor por defecto es falso.
sentence
[2.00] Si se establece en un valor verdadero, se intentará agrupar párrafos en frases lógicas. Esto significa que se emitirá un doble salto de línea entre frases, en lugar de un salto de línea simple entre líneas físicas. El valor por defecto es falso.
width
[2.00] El ancho de la salida en caracteres. Por defecto es 78.

MÉTODOS DE OBJETO

Los siguientes métodos se aplican a objetos Pod::Text creados con Pod::Text->new.

parse_from_file(FROM, TO)
Lee los datos POD del archivo FROM y escribe el texto formateado resultante en el archivo TO. Si TO se omite, se utiliza STDOUT. Si FROM se omite, se utiliza STDIN.
parse_from_filehandle(FROM, TO)
Lee los datos POD del manejador de archivo FROM y escribe el texto formateado resultante en el manejador de archivo TO. Si TO se omite, se utiliza STDOUT. Si FROM se omite, se utiliza STDIN.
parse_string(STRING, TO)
Lee los datos POD de la cadena STRING y escribe el texto formateado resultante en el manejador de archivo TO. Si TO se omite, se utiliza STDOUT.

SUBCLASES

El módulo Pod::Text::FAQ está disponible, el cual proporciona un formato de salida para el archivo FAQ de Perl.

El módulo Pod::Text::Termcap está disponible, el cual proporciona formateo de salida con capacidades de terminal controladas por Termcap/Terminfo.

El módulo Pod::Text::Color está disponible, el cual proporciona formateo de salida con códigos de color ANSI.

OPTIONS

The following options are available to the constructor and/or can be passed to the various parsing methods.

alt
[3.14] Use alternative formatting for URLs. Normally, if an L< link has both text and a URL, both are displayed. With this option, only the text is displayed.
comment
[3.10] If set to a true value, comments in the POD document (lines starting with # outside of a POD command) are preserved in the output. Defaults to false.
encoding
[3.12] The character encoding to use for the output. Defaults to the system's "unsafe" locale encoding (see perluniintro(1)).
errors
[3.10] What to do when a POD syntax error is encountered. May be set to "die" (die on error), "stderr" (print to stderr and continue), or "record" (record errors and continue, default). If set to "record", errors are appended to the output as a "POD ERRORS" section.
indent
[2.21] The amount of indentation (in spaces) to use for the first line of a paragraph. Defaults to 0. This affects only regular paragraphs, not headings or lists.
leftcode
[3.17] The string used to mark the beginning of a C<...> or X<...> sequence. Defaults to "" (empty string).
margin
[2.21] The width of the left margin in spaces. Defaults to 0. This is the margin for all text, including headings, not the amount by which regular text is indented; for the latter, see the indent option. To set the right margin, see the width option.
nourls
[3.17] Normally, L<> formatting codes with a URL but anchor text are formatted to show both the anchor text and the URL. In other words: 
L<foo|http://example.com/>

is formatted as:

foo <http://example.com/>

This option, if set to a true value, suppresses the URL when anchor text is given, so this example would be formatted as just "foo". This can produce less cluttered output in cases where the URLs are not particularly important.

quotes
[4.00] Sets the quote marks used to surround C<> text. If the value is a single character, it is used as both the left and right quote. Otherwise, it is split in half, and the first half of the string is used as the left quote and the second is used as the right quote.

This may also be set to the special value "none", in which case no quote marks are added around C<> text.

sentence
[3.00] If set to a true value, Pod::Text will assume that each sentence ends in two spaces, and will try to preserve that spacing. If set to false, all consecutive whitespace in non-verbatim paragraphs is compressed into a single space. Defaults to false.
stderr
[3.10] Send error messages about invalid POD to standard error instead of appending a POD ERRORS section to the generated output. This is equivalent to setting "errors" to "stderr" if "errors" is not already set. It is supported for backward compatibility.
utf8
[3.12] If this option is set to a true value, the output encoding is set to UTF-8. This is equivalent to setting "encoding" to "UTF-8" if "encoding" is not already set. It is supported for backward compatibility.
width
[2.00] The column at which to wrap text on the right-hand side. Defaults to 76.

INSTANCE METHODS

As a derived class from Pod::Simple, Pod::Text supports the same methods and interfaces. See Pod::Simple for all the details. This section summarizes the most-frequently-used methods and the ones added by Pod::Text.

output_fh(FH)
Direct the output from parse_file(), parse_lines(), or parse_string_document() to the file handle FH instead of "STDOUT".
output_string(REF)
Direct the output from parse_file(), parse_lines(), or parse_string_document() to the scalar variable pointed to by REF, rather than "STDOUT". For example: 
my $man = Pod::Man->new();
my $output;
$man->output_string(\$output);
$man->parse_file('/some/input/file');

Be aware that the output in that variable will already be encoded (see "Encoding").

parse_file(PATH)
Read the POD source from PATH and format it. By default, the output is sent to "STDOUT", but this can be changed with the output_fh() or output_string() methods.
parse_from_file(INPUT, OUTPUT)
parse_from_filehandle(FH, OUTPUT)
Read the POD source from INPUT, format it, and output the results to OUTPUT.

parse_from_filehandle() is provided for backward compatibility with older versions of Pod::Man. parse_from_file() should be used instead.

parse_lines(LINES[, ...[, undef]])
Parse the provided lines as POD source, writing the output to either "STDOUT" or the file handle set with the output_fh() or output_string() methods. This method can be called repeatedly to provide more input lines. An explicit "undef" should be passed to indicate the end of input.

This method expects raw bytes, not decoded characters.

parse_string_document(INPUT)
Parse the provided scalar variable as POD source, writing the output to either "STDOUT" or the file handle set with the output_fh() or output_string() methods.

This method expects raw bytes, not decoded characters.

FUNCTIONS

Pod::Text exports one function for backward compatibility with older versions. This function is deprecated; instead, use the object-oriented interface described above.

pod2text([[-a,] [-NNN,]] INPUT[, OUTPUT])
Convert the POD source from INPUT to text and write it to OUTPUT. If OUTPUT is not given, defaults to "STDOUT". INPUT can be any expression supported as the second argument to two-argument open().

If "-a" is given as an initial argument, pass the "alt" option to the Pod::Text constructor. This enables alternative formatting.

If "-NNN" is given as an initial argument, pass the "width" option to the Pod::Text constructor with the number "NNN" as its argument. This sets the wrap line width to NNN.

DIAGNOSTICS

Bizarre space in item
Item called without tag
(W) Something has gone wrong in internal "=item" processing. These messages indicate a bug in Pod::Text; you should never see them.
Can't open %s for reading: %s
(F) Pod::Text was invoked via the compatibility mode pod2text() interface and the input file it was given could not be opened.
Invalid errors setting "%s"
(F) The "errors" parameter to the constructor was set to an unknown value.
Invalid quote specification "%s"
(F) The quote specification given (the "quotes" option to the constructor) was invalid. A quote specification must be either one character long or an even number (greater than one) characters long.
POD document had syntax errors
(F) The POD document being formatted had syntax errors and the "errors" option was set to "die".

COMPATIBILITY

Pod::Text 2.03 (based on Pod::Parser) was the first version of this module included with Perl, in Perl 5.6.0. Earlier versions of Perl had a different Pod::Text module, with a different API.

The current API based on Pod::Simple was added in Pod::Text 3.00. Pod::Text 3.01 was included in Perl 5.9.3, the first version of Perl to incorporate those changes. This is the first version that correctly supports all modern POD syntax. The parse_from_filehandle() method was re-added for backward compatibility in Pod::Text 3.07, included in Perl 5.9.4.

Pod::Text 3.12, included in Perl 5.10.1, first implemented the current practice of attempting to match the default output encoding with the input encoding of the POD source, unless overridden by the "utf8" option or (added later) the "encoding" option.

Support for anchor text in L<> links of type URL was added in Pod::Text 3.14, included in Perl 5.11.5.

parse_lines(), parse_string_document(), and parse_file() set a default output file handle of "STDOUT" if one was not already set as of Pod::Text 3.18, included in Perl 5.19.5.

Pod::Text 4.00, included in Perl 5.23.7, aligned the module version and the version of the podlators distribution. All modules included in podlators, and the podlators distribution itself, share the same version number from this point forward.

Pod::Text 4.09, included in Perl 5.25.7, fixed a serious bug on EBCDIC systems, present in all versions back to 3.00, that would cause opening brackets to disappear.

Pod::Text 5.00 and later, included in Perl 5.37.7, default, on non-EBCDIC systems, to UTF-8 encoding if it sees a non-ASCII character in the input and the input encoding is not specified. They also commit to an encoding with the first non-ASCII character and does not change the output encoding if the input encoding changes. The Encode module is now used for all output encoding rather than PerlIO layers, which fixes earlier problems with output to scalars.

CAVEATS

Line wrapping is done only at ASCII spaces and tabs, rather than using a correct Unicode-aware line wrapping algorithm.
