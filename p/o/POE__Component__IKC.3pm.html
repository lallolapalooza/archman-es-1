NOMBRE

POE::Component::IKC -- Comunicación entre núcleos POE (Inter-Kernel Communication)

SINOPSIS

Servidor IKC

use POE::Component::IKC::Server;
# crea todas tus sesiones
POE::Component::IKC::Server->spawn(
            port=>30, name=>'Servidor'
    ); # hay más opciones disponibles
$poe_kernel->run();

Cliente IKC

use POE::Component::IKC::Client;
POE::Component::IKC::Client->spawn( 
            host=>nombre, 
            port=>30, 
            name=>'Cliente',
            on_connect=>\&construir);
$poe_kernel->run();
sub construir
{
    # crea sesiones que dependen del núcleo extranjero.
}

Publicar un estado en un núcleo extranjero

$kernel->post('IKC', 'post', "poe://Servidor/sesion/estado", $UN_argumento);

El IKC es peer-to-peer.

El servidor puede enviar al cliente.

$kernel->post('IKC', 'post', 'poe://Cliente/sesion/estado', $UN_argumento);

Llamar un estado en un núcleo remoto

Los semánticas de llamada son imposibles, porque harían que POE se bloqueara. La llamada IKC es un poco diferente. Es un 'post', pero con un parámetro RSVP adicional.

$kernel->post('IKC', 'call', 'poe://Servidor/hola/mundo', $UN_argumento, 
              'poe:callback');

Esto hará que el valor de retorno del estado extranjero sea enviado al estado 'callback' en la sesión actual. Puede que desees que la devolución de llamada esté en otra sesión, pero no creo que sea una buena idea.

$kernel->post('IKC', 'call', 'poe://Servidor/hola/mundo', $UN_argumento, 
              'poe:/otro/lugar/hola');

Nota: si usas ->call('IKC'), devolverá el número de núcleos extranjeros a los que se envió el estado. Esta es una forma útil de saber si todavía estás conectado a un núcleo extranjero.

Un poco de magia

Si un estado es publicado por un núcleo extranjero, $_[SENDER] solo es válido durante ese estado. Sin embargo, podrás enviar de vuelta a él.

$kernel->post($_[SENDER], 'algo', 'la respuesta es foo');

El llamador remoto DEBE haber publicado estados para que puedan ser llamados, ¿eh?

Publicar / Suscribir

Debes publicar la interfaz de una sesión para que esté disponible para núcleos remotos.

Si te suscribes a una sesión remota, puedes acceder a ella como si fuera una sesión local.

Primero, una sesión publica sus interfaces:

$kernel->post('IKC', 'publish', 'alias_sesion',
                    [qw(estado1 estado2 estado3 estado4)], );

Luego, un núcleo extranjero se suscribe a ella:

# Buscar una sesión en todos los núcleos extranjeros conocidos
$kernel->post('IKC', 'subscribe', [qw(poe://*/alias_sesion/)]);
# Buscar una sesión en un núcleo extranjero específico
$kernel->post('IKC', 'subscribe', [qw(poe://Pulso/servidor_tiempo)]);
# Asegurarse de que la sesión tenga un estado dado
$kernel->post('IKC', 'subscribe', [qw(poe://*/servidor_tiempo/conectar)]);

Después de la suscripción, se crea una sesión proxy que puede ser accesada como cualquier otra sesión, aunque ->call() actúa igual que ->post() por razones obvias:

$kernel->post('poe:/Pulso/servidor_tiempo', 'estado', $arg1, $arg2...);

Actualmente, el alias de sesión utilizado para enviar al proxy de sesión debe ser el mismo que se usó al suscribirse. Dado que los núcleos tienen varios nombres, si estás usando '*' como el nombre del núcleo al suscribirte, el alias de sesión podría no ser lo que piensas. Ver "Monitor" para más detalles.

Por supuesto, intentar enviar a una sesión proxy antes de que se cree será problemático. Para ser alertado cuando se cree la sesión proxy, se puede especificar un estado de devolución de llamada,

$kernel->post('IKC', 'subscribe', [qw(poe://*/servidor_tiempo)], 
        'servidor_tiempo_suscrito');

La devolución de llamada se realizará con una lista de todas las sesiones a las que se logró suscribir. Deberías comprobar esta lista antes de continuar. Mejor aún, podrías usar el monitor IKC (ver más abajo).

También se puede dejar que POE::Component::IKC::Client->spawn se encargue de todos los detalles.

POE::Component::IKC::Client->spawn(
        port=>31337, name=>$name,
        subscribe=>[qw(poe://*/servidor_tiempo)],
        on_connect=>\&crear_yo,
    );

'on_connect' solo se llama cuando todas las suscripciones han sido aceptadas. Si una suscripción fue rechazada, create_ikc_client se dará por vencido. Si se consultaron varios núcleos extranjeros para una sesión (como en el caso anterior), la suscripción se considera exitosa si al menos un núcleo extranjero acepta la suscripción.

Para deshacer cosas:

$kernel->post(IKC=>'retract', 'alias_sesion'=>[qw(estados)]);
$kernel->post(IKC=>'unsubscribe', [qw(poe://Pulso/servidor_tiempo)]);

Monitor

Digamos que querías monitorizar todos los núcleos remotos que se conectan a ti:

$kernel->post(IKC=>'monitor', '*'=>{register=>'algún_evento'});
sub algún_evento
{
    my($name, $real)=@_[ARG1, ARG2];
    print "- Núcleo remoto ", ($real ? '' : 'alias '), "$name conectado\n";
}

Más tarde, quieres saber cuándo se desconecta una sesión remota dada:

$kernel->post(IKC=>'monitor', kernel_alguno=>{unregister=>'adiós_adiós'});

O tal vez crees que una sesión debería limpiarse y marcharse cuando IKC lo haga.

$kernel->post(IKC=>'monitor', '*'=>{shutdown=>'otro_evento'});
sub otro_evento
{
    # matar ruedas, alarmas, selects y alias aquí
}

Ver "monitor" en POE::Component::IKC::Responder para más detalles.

Cierre

Cuando sientas que es el momento adecuado y quieras deshacerte de todas las sesiones relacionadas con IKC, simplemente haz lo siguiente:

$kernel->post(IKC=>'shutdown');

Y todas deberían desaparecer. En el peor de los casos, algunas seguirán teniendo alias registrados, pero esto no impedirá que el núcleo salga.

El núcleo local

Puedes enviar al núcleo local como si fuera remoto:

$kernel->post(IKC=>'post', 
                "poe://$kernel->ID/sesion/estado'=>$UN_argumento);

Sin embargo, actualmente no puedes suscribirte a sesiones locales. No sé cómo resolveré esto.

DESCRIPCIÓN

Esto es Comunicación entre Núcleos (Inter-Kernel Communication) para POE. Se utiliza para llevar eventos de un núcleo POE a otro.

VER TAMBIÉN

POE::Component::IKC::Responder -- Corazón del sistema

POE::Component::IKC::Server -- Crea un proceso que escucha a otros núcleos.

POE::Component::IKC::Client -- Crea un proceso que se conecta a otros núcleos.

POE::Component::IKC::ClientLite -- Implementación ligera de IKC para lugares donde no puedes usar POE, como mod_perl.

POE::Component::IKC::Channel -- Maneja la comunicación con otros núcleos.

POE::Component::IKC::Proxy -- Sesión proxy que se crea cuando te suscribes a una sesión remota.

POE::Component::IKC::Freezer -- Método de serialización Pure-Perl.

POE::Component::IKC::Specifier -- Rutinas auxiliares para parsear especificadores IKC.
