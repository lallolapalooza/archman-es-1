POE::Wheel::SocketFactory(3) Documentación de Perl aportada por el usuario POE::Wheel::SocketFactory(3)

NOMBRE

POE::Wheel::SocketFactory - creación de sockets no bloqueantes

SINOPSIS

Ver "SINOPSIS" en POE::Component::Server::TCP para una versión mucho más sencilla de este programa.

#!perl
use warnings;
use strict;
use IO::Socket;
use POE qw(Wheel::SocketFactory Wheel::ReadWrite);
POE::Session->create(
  inline_states => {
    _start => sub {
      # Inicia el servidor.
      $_[HEAP]{server} = POE::Wheel::SocketFactory->new(
        BindPort => 12345,
        SuccessEvent => "on_client_accept",
        FailureEvent => "on_server_error",
      );
    },
    on_client_accept => sub {
      # Comienza a interactuar con el cliente.
      my $client_socket = $_[ARG0];
      my $io_wheel = POE::Wheel::ReadWrite->new(
        Handle => $client_socket,
        InputEvent => "on_client_input",
        ErrorEvent => "on_client_error",
      );
      $_[HEAP]{client}{ $io_wheel->ID() } = $io_wheel;
    },
    on_server_error => sub {
      # Cierra el servidor.
      my ($operation, $errnum, $errstr) = @_[ARG0, ARG1, ARG2];
      warn "Error del servidor $operation $errnum: $errstr\n";
      delete $_[HEAP]{server};
    },
    on_client_input => sub {
      # Maneja la entrada del cliente.
      my ($input, $wheel_id) = @_[ARG0, ARG1];
      $input =~ tr[a-zA-Z][n-za-mN-ZA-M]; # rot13 ASCII
      $_[HEAP]{client}{$wheel_id}->put($input);
    },
    on_client_error => sub {
      # Maneja el error del cliente, incluida la desconexión.
      my $wheel_id = $_[ARG3];
      delete $_[HEAP]{client}{$wheel_id};
    },
  }
);
POE::Kernel->run();
exit;

DESCRIPCIÓN

POE::Wheel::SocketFactory crea sockets bajo demanda. Puede crear sockets UDP sin conexión, pero brilla especialmente para el trabajo cliente/servidor donde el establecimiento de conexiones normalmente bloquearía.

MÉTODOS PÚBLICOS

new

new() crea un nuevo objeto POE::Wheel::SocketFactory. Para sockets que listen() y accept() conexiones, la rueda generará nuevos sockets para cada cliente aceptado. Las fábricas de sockets para sockets de un solo uso, como peers UDP o clientes establecidos por connect(), emiten un solo socket y pueden ser destruidos después sin efectos adversos.

new() siempre devuelve un objeto POE::Wheel::SocketFactory, incluso si falla al establecer el socket. Esto permite consultar el objeto después de que haya enviado un "FailureEvent" a su sesión.

new() acepta un buen número de parámetros con nombre, cada uno rige algún aspecto de la creación del socket.

Creación del Socket

La creación del socket se realiza con la función incorporada socket() de Perl. Los parámetros de new() que comienzan con "Socket" determinan cómo se llamará a socket().

SocketDomain

"SocketDomain" instruye a la rueda para que cree un socket dentro de un dominio particular. Los dominios soportados son "AF_UNIX", "AF_INET", "AF_INET6", "PF_UNIX", "PF_INET", y "PF_INET6". Si se omite, el socket se creará en el dominio "AF_INET".

POE::Wheel::SocketFactory contiene una tabla de dominios soportados y las instrucciones necesarias para crearlos. Por favor, envíe parches para soportar dominios adicionales, según sea necesario.

Nota: "AF_INET6" y "PF_INET6" son proporcionados por el módulo Socket incluido en Perl 5.8.0 o posterior. Las versiones de Perl anteriores a 5.8.0 no deberían intentar usar IPv6 hasta que alguien contribuya con una solución alternativa.

El soporte de IPv6 requiere un módulo Socket que implemente getaddrinfo() y unpack_sockaddr_in6(). Puede haber otros módulos que realicen estas funciones, pero la mayoría, si no todas, han sido deprecados con la llegada del soporte básico adecuado de Socket para IPv6.

SocketType

"SocketType" proporciona a la llamada socket() un tipo de socket particular, que puede ser "SOCK_STREAM" o "SOCK_DGRAM". "SOCK_STREAM" es el valor por defecto si "SocketType" no se especifica.

SocketProtocol

"SocketProtocol" establece el protocolo de la llamada socket(). Los protocolos pueden especificarse por número o nombre. "SocketProtocol" se ignora para los sockets de dominio UNIX.

El protocolo por defecto es "tcp" para los sockets de dominio INET. No hay valor por defecto para otros dominios de socket.

Configuración de Opciones de Socket

POE::Wheel::SocketFactory utiliza ioctl(), fcntl() y setsockopt() para establecer opciones de socket después de que el socket sea creado. Todos los sockets se configuran como no bloqueantes, y los sockets enlazados pueden hacerse reutilizables.

Reuse

Cuando se establece, el parámetro "Reuse" permite que un puerto enlazado se reutilice inmediatamente. "Reuse" se considera habilitado si contiene "yes", "on", o un valor numérico verdadero. Todos los demás valores deshabilitan la reutilización del puerto, al igual que omitir "Reuse" por completo.

Por razones de seguridad, un puerto no puede reutilizarse durante un minuto o más después de que un servidor lo haya liberado. Esto da tiempo a los clientes para darse cuenta de que el puerto ha sido abandonado. De lo contrario, un servicio malicioso podría apoderarse del puerto y suplantar al servicio legítimo.

También es terriblemente molesto esperar un minuto o más entre invocaciones del servidor, especialmente durante el desarrollo.

Enlace del Socket a una Dirección y Puerto

Opcionalmente, un socket puede enlazarse a una interfaz y puerto específicos. La dirección "INADDR_ANY" puede utilizarse para enlazar a un puerto específico en todas las interfaces.

Los sockets se enlazan usando bind(). Los parámetros de POE::Wheel::SocketFactory que comienzan con "Bind" controlan cómo se llama a bind().

BindAddress

"BindAddress" establece una dirección a la que se enlazará el punto final local del socket. Se usará "INADDR_ANY" si no se especifica "BindAddress".

"BindAddress" puede contener una cadena o una dirección de Internet empaquetada (para sockets de dominio "INET"). El parámetro de cadena debe ser una dirección numérica con puntos o un nombre de host resoluble. Tenga en cuenta que el nombre del host se resolverá con una llamada bloqueante. Si esto no es deseable, utilice POE::Component::Client::DNS para realizar una resolución de nombres no bloqueante.

Cuando se utiliza para enlazar un socket de dominio "UNIX", "BindAddress" debe contener una ruta que describa el nombre del archivo del socket. Esto es obligatorio para los sockets del servidor y los sockets cliente datagrama. "BindAddress" no tiene un valor por defecto para los sockets UNIX.

BindPort

"BindPort" solo es significativo para los sockets de dominio "INET". Contiene un puerto en la interfaz "BindAddress" donde se enlazará el socket. Por defecto es 0 si se omite, lo que provocará que la llamada bind() elija un puerto no asignado indeterminado.

"BindPort" puede ser un número de puerto o un nombre que se pueda buscar en la base de datos de servicios (o equivalente) del sistema.

Sockets sin Conexión

Los sockets sin conexión pueden interactuar con puntos finales remotos sin necesidad de listen() para conexiones o connect() a direcciones remotas.

Esta clase de sockets se completa después de la llamada bind().

Conexión del Socket a un Punto Final Remoto

Un socket puede escuchar conexiones entrantes, iniciar conexiones a un punto final remoto, o ser sin conexión (como en el caso de los sockets UDP).

POE::Wheel::SocketFactory iniciará una conexión de cliente cuando new() se complete con parámetros que describen un punto final remoto. En todos los demás casos, el socket escuchará conexiones o será sin conexión dependiendo del tipo de socket.

ClientConnect

"ClientConnect" le dice a la rueda que se conecte a un punto final remoto. Los parámetros para "ClientConnect" son los mismos que los de "BindAddress" y "BindPort".

Si "ClientConnect" se proporciona, la rueda se conectará a ese punto final después de que se cree el socket. Una vez que la conexión sea exitosa, se generará un evento "SuccessEvent". Si falla, se generará un evento "FailureEvent".

Note: Si "ClientConnect" se proporciona, no se debe proporcionar "BindAddress" o "BindPort".

Eventos del Socket

La rueda notificará a la sesión sobre el estado de los sockets mediante eventos.

SuccessEvent

Cuando se crea un socket, o cuando se acepta una conexión, se enviará un evento "SuccessEvent" a la sesión. El argumento pasado al evento será el socket recién creado. Para las conexiones de servidor, este será un objeto socket que escucha las conexiones entrantes. Para las conexiones de cliente, este será el socket conectado.

FailureEvent

Si la rueda no puede crear el socket, o si falla al aceptar una conexión, se enviará un evento "FailureEvent" a la sesión. Los argumentos pasados al evento serán una operación (string), un número de error (int) y una cadena de error (string).

ListenEvent

Cuando un socket está escuchando, se puede enviar un evento "ListenEvent". Los argumentos pasados al evento serán el objeto socket que está escuchando.

AcceptEvent

Cuando una conexión es aceptada, se puede enviar un evento "AcceptEvent". Los argumentos pasados al evento serán el socket que está escuchando y el socket del cliente recién aceptado.

ConnectEvent

Cuando se establece una conexión de cliente, se puede enviar un evento "ConnectEvent". Los argumentos pasados al evento serán el socket cliente recién conectado.

ErrorEvent

Cuando se produce un error en el socket, se puede enviar un evento "ErrorEvent". Los argumentos pasados al evento serán el objeto socket y una cadena de error.

DestroyEvent

Cuando se destruye el socket, se puede enviar un evento "DestroyEvent". El argumento pasado al evento será el objeto socket destruido.

Parámetros Adicionales

Handle

Si se proporciona un Handle, el objeto Wheel no intentará crear un nuevo socket. En su lugar, se adjuntará al Handle proporcionado.

Este parámetro es más útil para las conexiones de cliente. El propietario del Handle es responsable de cualquier configuración de socket, como la configuración de opciones de socket (por ejemplo, reutilización de dirección).

ID

Si se proporciona un ID, se utilizará el ID especificado en lugar de generar un nuevo ID para la rueda.

Esto es útil si el usuario desea mantener el mismo ID para un socket que se reinicia o se transfiere a otro objeto Wheel.

Nombre

Este parámetro se utiliza para identificar la rueda de SocketFactory en el registro de la rueda de POE. Si no se proporciona, POE::Wheel::SocketFactory utilizará el nombre de clase como nombre de registro.

new() puede ser llamado de forma no bloqueante. En este caso, el método devolverá undef inmediatamente, y las respuestas se enviarán a la sesión del solicitante a través de los eventos especificados.

Destroy

Destruye el socket y sus recursos asociados.

Este método es normalmente llamado por el Kernel de POE.

ID

Devuelve el ID único de la rueda.

Name

Devuelve el nombre de la rueda.

Handle

Devuelve el handle del socket asociado con la rueda.

InputHandle

Devuelve el handle de entrada del socket asociado con la rueda.

OutputHandle

Devuelve el handle de salida del socket asociado con la rueda.

State

Devuelve el estado actual de la rueda.

>Los siguientes parámetros describen el punto final remoto de un socket. Determinan cómo POE::Wheel::SocketFactory llamará a la función incorporada de Perl **connect()**. RemoteAddress "RemoteAddress" especifica la dirección remota a la que debe conectarse un socket. Si está presente, POE::Wheel::SocketFactory creará un socket cliente que intentará conectarse a la "RemoteAddress". De lo contrario, si el protocolo lo justifica, la rueda creará un socket de escucha e intentará aceptar conexiones. Al igual que con la dirección de enlace, "RemoteAddress" puede ser una cadena que contenga una dirección de puntos cuádruples o un nombre de host resoluble. También puede ser una dirección de Internet empaquetada o una ruta de socket UNIX. Se empaquetará, con o sin un "RemotePort" acompañante, según sea necesario para el dominio del socket. RemotePort "RemotePort" es el puerto al que debe conectarse el socket. Es necesario para los sockets cliente "INET", ya que el punto final remoto debe contener tanto una dirección como un puerto. El puerto remoto puede ser numérico o puede ser un nombre simbólico que se encuentra en /etc/services o su equivalente para su sistema operativo. *Escuchando Conexiones* Los sockets de transmisión que no tienen un punto final remoto se consideran sockets de servidor. POE::Wheel::SocketFactory llamará a **listen()** para obtener conexiones a estos sockets, **accept()** a los nuevos clientes y enviará eventos a la aplicación con los nuevos sockets de cliente. Los parámetros del constructor de POE::Wheel::SocketFactory que comienzan con "Listen" controlan cómo se llama a la función **listen()**. ListenQueue "ListenQueue" especifica la longitud de la cola de **listen()** del socket. Por defecto es "SOMAXCONN" si se omite. Los valores de "ListenQueue" mayores que "SOMAXCONN" se recortarán a "SOMAXCONN". Las colas "ListenQueue" excesivamente grandes no son necesariamente portátiles y pueden causar errores en casos raros. *Emitiendo Eventos* POE::Wheel::SocketFactory emite un número reducido de eventos dependiendo de lo que suceda durante la configuración del socket o mientras se escuchan nuevas conexiones. Consulte "EVENTOS PÚBLICOS" para obtener más detalles. SuccessEvent "SuccessEvent" nombra el evento que se emitirá cada vez que POE::Wheel::SocketFactory cree con éxito un nuevo socket. Para sockets sin conexión, "SuccessEvent" ocurre justo después de que se crea el socket. Para conexiones de clientes, "SuccessEvent" se activa cuando la conexión se ha establecido correctamente con el punto final remoto. Los sockets de servidor emiten un "SuccessEvent" por cada cliente aceptado con éxito. FailureEvent "FailureEvent" nombra el evento que POE::Wheel::SocketFactory emitirá cuando ocurra algo malo. Generalmente representa algún tipo de error de función incorporada. Consulte "EVENTOS PÚBLICOS" para obtener detalles, ya que algunos errores son manejados internamente por esta rueda. event **event()** permite a una sesión cambiar los eventos emitidos por una rueda sin destruir y recrear la rueda. Acepta uno o más de los eventos enumerados en "EVENTOS PÚBLICOS". Los nombres de eventos indefinidos deshabilitan esos eventos. **event()** se describe con más detalle en POE::Wheel. getsockname **getsockname()** se comporta como la función incorporada del mismo nombre. Devuelve la información del punto final local para el socket de escucha encapsulado de POE::Wheel::SocketFactory. **getsockname()** permite a las aplicaciones determinar la dirección y el puerto a los que POE::Wheel::SocketFactory ha enlazado su socket de escucha. Las aplicaciones de prueba pueden usar **getsockname()** para encontrar el socket del servidor después de que POE::Wheel::SocketFactory se haya enlazado a INADDR_ANY puerto 0. Dado que no hay un evento que se dispare inmediatamente después de la creación exitosa de un socket de escucha, las aplicaciones pueden usar **getsockname()** para verificar esto. ```perl use Socket 'unpack_sockaddr_in'; my $listener = POE::Wheel::SocketFactory->new( BindPort => 123, SuccessEvent => 'got_client', FailureEvent => 'listener_failed', Reuse => 'on', ); my ($port, $addr) = unpack_sockaddr_in($listener->getsockname); print "Socket successfully bound\n" if $port; ``` ID **ID()** devuelve el ID único de la rueda. El ID también se incluirá en cada evento que genere la rueda. Las aplicaciones pueden relacionar eventos con los objetos que los generaron. pause_accept Las aplicaciones pueden necesitar bloquear conexiones entrantes ocasionalmente. **pause_accept()** pausa el observador de eventos que activa **accept()**. Las nuevas conexiones entrantes se acumularán en la cola de **listen()** del socket hasta que la cola se desborde o la aplicación llame a **resume_accept()**. Pausar **accept()** puede limitar la carga que genera un servidor. También es útil en servidores pre-forking cuando el proceso maestro no debe aceptar conexiones en absoluto. **pause_accept()** y **resume_accept()** son más rápidos y confiables que destruir y recrear dinámicamente un objeto POE::Wheel::SocketFactory. resume_accept **resume_accept()** reanuda el observador que activa **accept()**. Consulte "pause_accept" para una discusión más detallada. EVENTOS PÚBLICOS POE::Wheel::SocketFactory emite dos eventos públicos. SuccessEvent "SuccessEvent" nombra un evento que se enviará a la sesión creadora cada vez que POE::Wheel::SocketFactory haya creado un nuevo socket. Para sockets sin conexión, es cuando se crea el socket. Para clientes que se conectan, es después de que se ha establecido la conexión. Y para servidores de escucha, "SuccessEvent" se activa después de que se acepta cada nuevo cliente. *Parámetros Comunes de SuccessEvent* En todos los casos, $_[ARG0] contiene el manejador de archivo del nuevo socket, y $_[ARG3] contiene el ID de POE::Wheel::SocketFactory. Otros parámetros varían según el dominio del socket y si está escuchando o conectándose. Consulte a continuación las diferencias. *Parámetros de SuccessEvent de INET* Para sockets INET, $_[ARG1] y $_[ARG2] contienen la dirección y el puerto remotos del socket, respectivamente. La dirección está empaquetada; consulte "inet_ntop" en Socket si se necesita una dirección legible por humanos. ```perl sub handle_new_client { my $accepted_socket = $_[ARG0]; my $peer_host = inet_ntop( ((length($_[ARG1]) == 4) ? AF_INET : AF_INET6), $_[ARG1] ); print( "Wheel $_[ARG3] accepted a connection from ", "$peer_host port $peer_port\n" ); spawn_connection_session($accepted_handle); } ``` *Parámetros de SuccessEvent de Cliente UNIX* Para sockets de cliente UNIX, $_[ARG1] a menudo (pero no siempre) contiene la dirección del servidor. Algunos sistemas no pueden recuperar la dirección remota de un socket UNIX. $_[ARG2] es siempre indefinido para los sockets de cliente UNIX. *Parámetros de SuccessEvent de Servidor UNIX* Según el *Perl Cookbook*, la dirección remota devuelta por **accept()** en sockets UNIX no está definida, por lo que $_[ARG1] y $_[ARG2] también están indefinidos en este caso. FailureEvent "FailureEvent" nombra el evento que se emitirá cuando ocurra un error de socket. POE::Wheel::SocketFactory maneja internamente "EAGAIN", por lo que no cuenta como un error. Los eventos "FailureEvent" incluyen los parámetros estándar de eventos de error: $_[ARG0] describe en qué parte de la creación del socket falló. A menudo contiene el nombre de una función incorporada de Perl. $_[ARG1] y $_[ARG2] describen cómo falló la operación. Contienen las versiones numéricas y de cadena de $!, respectivamente. Una aplicación no puede simplemente verificar la variable global $! ya que puede cambiar durante el despacho de eventos. Finalmente, $_[ARG3] contiene el ID de la instancia de POE::Wheel::SocketFactory que generó el evento. Consulte "ID" y "ID" en POE::Wheel para ver los usos de los IDs de rueda. Un manejador de ejemplo de FailureEvent: ```perl sub handle_failure { my ($operation, $errnum, $errstr, $wheel_id) = @_[ARG0..ARG3]; warn "Wheel $wheel_id generated $operation error $errnum: $errstr\n"; delete $_[HEAP]{wheels}{$wheel_id}; # shut down that wheel } ``` VER TAMBIÉN POE::Wheel describe las operaciones básicas de todas las ruedas con más detalle. Necesitas saber esto. Socket::GetAddrInfo es necesario para el trabajo con IPv6. POE::Wheel::SocketFactory lo cargará automáticamente si está instalado. SocketDomain => AF_INET6 es necesario para activar los comportamientos de IPv6. AF_INET6 es exportado por el módulo Socket en todas las versiones de Perl 5 excepto las más antiguas. Si tu Socket no proporciona AF_INET6, intenta instalar Socket6 en su lugar. La sección SEE ALSO en POE contiene una tabla de contenido que cubre toda la distribución de POE.
