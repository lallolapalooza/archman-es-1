NOMBRE

POE::Queue - una API de cola de prioridad flexible y genérica

SINOPSIS

POE::Queue especifica métodos adicionales no ilustrados aquí.

#!perl
use warnings;
use strict;
use POE::Queue::Array;
my $pqa = POE::Queue::Array->new();
# Poner en cola algunos elementos.
foreach my $priority (505, 404, 303, 202, 101) {
  $pqa->enqueue($priority, "payload $priority");
}
# Sacar de la cola hasta que se vacíe.
while (1) {
  my ($priority, $queue_id, $payload) = $pqa->dequeue_next();
  last unless defined $priority;
  print(
    "sacado de cola id($queue_id) ",
    "prioridad($priority) ",
    "payload($payload)\n",
  );
}

Salida de ejemplo:

sacado de cola id(5) prioridad(101) payload(payload 101)
sacado de cola id(4) prioridad(202) payload(payload 202)
sacado de cola id(3) prioridad(303) payload(payload 303)
sacado de cola id(2) prioridad(404) payload(payload 404)
sacado de cola id(1) prioridad(505) payload(payload 505)

DESCRIPCIÓN

Las colas de prioridad se pueden implementar de varias maneras, pero tienden a comportarse de forma similar a las listas que se mantienen en orden por algún tipo de "prioridad". Los elementos puestos en cola se almacenan de tal manera que el elemento "siguiente" a recuperar es el de mayor prioridad. Las recuperaciones subsiguientes devuelven la siguiente prioridad más baja, y así sucesivamente, hasta que la cola se vacía.

Las colas de prioridad (también conocidas como montículos de prioridad) intentan hacer esto consumiendo los menores recursos. ¡Ve a leer sobre ello! ¡Son cosas fascinantes!

Elementos de POE::Queue

Los elementos de POE::Queue constan de tres campos: una prioridad, un ID único asignado en el momento de poner en cola y una carga útil. La prioridad y la carga útil son especificadas por el llamador, y el ID único es generado por POE::Queue cuando se pone un elemento en cola.

POE::Queue impone dos limitaciones a las prioridades: las prioridades deben ser numéricas y los números más bajos indican prioridades más altas. Aparte de eso, a POE::Queue no le importan los significados de los números.

Los IDs únicos son identificadores dentro de la cola. POE::Queue los genera y los devuelve a medida que se ponen nuevos elementos en cola. Algunos métodos manipulan elementos y toman IDs para identificar los elementos a modificar.

Las cargas útiles de los elementos son datos arbitrarios de la aplicación. POE::Queue no examina ni modifica las cargas útiles por sí mismo. Cualquier método que necesite examinar cargas útiles aceptará una función de filtro. Las funciones de filtro examinan las cargas útiles para que POE::Queue no tenga que hacerlo.

Métodos Públicos

POE::Queue es una especificación de API. Subclases como POE::Queue::Array proporcionan implementaciones reales.

new

Crea una nueva cola de prioridad. Devuelve una referencia a la cola.

my $queue = POE::Queue::Array->new();

enqueue PRIORIDAD, CARGA ÚTIL

Pone en cola una CARGA ÚTIL, que puede ser casi cualquier cosa que quepa en un escalar de Perl, en un nivel de PRIORIDAD particular. enqueue() devuelve un ID único que puede usarse para manipular la carga útil o su prioridad directamente.

Siguiendo la tradición de UNIX, los números de prioridad más bajos indican prioridades más altas. La carga útil con el número de prioridad más bajo se sacará de la cola primero. Si dos cargas útiles tienen la misma PRIORIDAD, se sacarán de la cola en el orden en que se pusieron.

En este ejemplo, se utiliza una cola para gestionar una serie de alarmas. La "siguiente" alarma será la que venza pronto.

my $payload_id = $queue->enqueue($alarm_time, [ "stuff" ]);

dequeue_next

Elimina el siguiente elemento de la cola, devolviéndolo como tres campos: prioridad, ID y carga útil.

El elemento "siguiente" es el que tiene el número de prioridad más bajo. Si existen varios elementos con la misma prioridad, dequeue_next() devolverá el que recibió la prioridad primero.

ITEM: while (1) {
  my ($priority, $id, $payload) = $queue->dequeue_next();
  last ITEM unless defined $priority;
  ...;
}

get_next_priority

Devuelve la prioridad del elemento en la cabeza de la cola. Esta es la prioridad numérica más baja en la cola.

get_next_priority() puede ser útil para comprobar la cola y ver si es hora de sacar algunos elementos. En este caso, la cola gestiona múltiples alarmas y no hay nada que hacer si la próxima alarma aún no ha vencido.

ALARM: while (1) {
  my $next_alarm_time = $queue->get_next_priority();
  last ALARM unless defined $next_alarm_time;
  if ($next_alarm_time - time() > 0) {
    sleep($next_alarm_time - time());
  }
  my ($priority, $id, $payload) = $queue->dequeue_next();
  ...;
}

get_item_count

Devuelve el número de elementos en la cola. Es otra forma de saber si la cola se ha vaciado por completo. Aquí hay una versión alternativa del ejemplo para get_next_priority().

ALARM: while ($queue->get_item_count()) {
  my $next_alarm_time = $queue->get_next_priority();
  if ($next_alarm_time - time() > 0) {
    sleep($next_alarm_time - time());
  }
  my ($priority, $id, $payload) = $queue->dequeue_next();
  ...;
}

remove_item ID DEL ELEMENTO, FUNCIÓN DE FILTRO

Elimina un solo elemento por su ID, pero solo si una FUNCIÓN DE FILTRO aprueba la carga útil del elemento.

Si se encuentra una carga útil con el ID DEL ELEMENTO dado, se pasa a la FUNCIÓN DE FILTRO para su examen. Si la FUNCIÓN DE FILTRO devuelve verdadero, el elemento se elimina de la cola y se devuelve como tres campos.

my ($priority, $id, $payload) = $queue->remove_item(
  $target_id, \&monkeys
);
sub monkeys {
  my $payload = shift;
  $payload->{type} eq "monkey";
}

El $priority devuelto será undef en caso de fallo, y $! se establecerá en la razón por la cual el elemento no pudo ser eliminado. Ese será ESRCH si el ID DEL ELEMENTO no se encontró en la cola, o EPERM si la función de filtro devolvió falso.

remove_items FUNCIÓN DE FILTRO [, MÁXIMO NÚMERO DE ELEMENTOS ]

Elimina y devuelve elementos de la cola que coinciden con una FUNCIÓN DE FILTRO. remove_items() devolverá inmediatamente si se especifica un MÁXIMO DE NÚMERO DE ELEMENTOS y se han eliminado esa cantidad de elementos de la cola. MÁXIMO NÚMERO DE ELEMENTOS es una pequeña optimización si la aplicación sabe de antemano cuántos elementos coincidirán con la FUNCIÓN DE FILTRO.

Devuelve una lista de elementos que fueron eliminados. Cada elemento es una referencia de matriz que contiene una prioridad, un ID de elemento y una carga útil. No devuelve nada si la FUNCIÓN DE FILTRO no coincidió con nada.

# Eliminar hasta 12 monos.
my @monkeys = $queue->remove_items(\&monkeys, 12);
foreach my $monkey (@monkeys) {
  my ($priority, $id, $payload) = @$monkey;
  print(
    "Mono eliminado:\n",
    "  prioridad = $priority\n",
    "  id de cola = $id\n",
    "  carga útil  = $payload\n",
  );
}

No hay garantía de qué elementos se eliminarán si el MÁXIMO DE NÚMERO DE ELEMENTOS se especifica demasiado bajo.

peek_items FUNCIÓN DE FILTRO [, MÁXIMO NÚMERO DE ELEMENTOS ]

peek_items() devuelve hasta MÁXIMO NÚMERO DE ELEMENTOS que coinciden con una FUNCIÓN DE FILTRO dada sin eliminarlos de la cola.

my @entire_queue = $queue->peek_items(sub { 1 });
foreach my $item (@entire_queue) {
  my ($priority, $id, $payload) = @$item;
  print(
    "Elemento:\n",
    "  prioridad = $priority\n",
    "  id de cola = $id\n",
    "  carga útil  = $payload\n",
  );
}

adjust_priority ID DEL ELEMENTO, FUNCIÓN DE FILTRO, DELTA

Cambia la prioridad de un elemento en DELTA. El elemento se identifica por su ID DEL ELEMENTO, y el cambio solo ocurrirá si la carga útil del elemento satisface una FUNCIÓN DE FILTRO. Devuelve la nueva prioridad, que es la prioridad anterior

NAME

POE::Queue - A generic, threaded queue object

SYNOPSIS

use POE::Queue;

my $queue = POE::Queue->new;

# add items to the queue
$queue->enqueue($item1);
$queue->enqueue($item2);
$queue->insert(0, $item_at_front);

# retrieve items from the queue
my $item = $queue->dequeue;
my $front_item = $queue->peek;

# other operations
$queue->list;
$queue->count;
$queue->empty;
$queue->remove($item_to_remove);
$queue->purge;

# priority queue operations
$queue->adjust_priority($item_id, \&filter, $delta);
$queue->set_priority($item_id, \&filter, $absolute_priority);

DESCRIPTION

POE::Queue is a generic queue object. It can be used in any Perl program, but it's particularly useful in POE programs where you might want to pass messages between different components, or to manage incoming requests.

By default, POE::Queue acts as a FIFO (First-In, First-Out) queue. However, it also supports priority queueing, where items can be given a priority and dequeued based on that priority.

For a simpler queue that doesn't support priorities, consider using POE::Queue::Array.

Priority Queueing

To use priority queueing, items added to the queue must be hashes that contain a 'priority' key. The value of this key is a number. Items with lower priority values are dequeued first. Items with the same priority are dequeued in FIFO order.

When an item is added with enqueue(), if it's a hash with a 'priority' key, it will be inserted into the queue according to its priority. If it's not a hash with a priority key, it will be added to the end of the queue (equivalent to a priority of infinity).

When you use dequeue(), the item with the lowest priority value will be returned. If multiple items share the lowest priority, the one that was enqueued earliest will be returned.

The following methods are specific to priority queueing:

Public Methods

new

Creates a new POE::Queue object.

my $queue = POE::Queue->new;
my $queue = POE::Queue->new( 'threads' => 1 );

The constructor accepts the following options:

threads
If set to true, the queue will be thread-safe. This adds some overhead, so only enable it if you need it.

enqueue ITEM

Adds ITEM to the end of the queue. If ITEM is a hash and contains a 'priority' key, it will be inserted into the queue based on its priority. Otherwise, it will be added to the end with an infinite priority.

$queue->enqueue($item);
$queue->enqueue({ priority => 10, data => 'important' });

insert INDEX, ITEM

Inserts ITEM at the given INDEX. INDEX 0 is the front of the queue. This method ignores priority.

$queue->insert(0, $item_at_front);

dequeue

Removes and returns the item from the front of the queue. If the queue is empty, it returns undef.

my $item = $queue->dequeue;

peek

Returns the item at the front of the queue without removing it. If the queue is empty, it returns undef.

my $item = $queue->peek;

list

Returns a reference to an array containing all items in the queue, in order from front to back. This method is primarily for debugging.

my $items_ref = $queue->list;

count

Returns the number of items currently in the queue.

my $num_items = $queue->count;

empty

Returns true if the queue is empty, false otherwise.

if ($queue->empty) {
  print "Queue is empty.\n";
}

remove ITEM

Removes the first occurrence of ITEM from the queue. Returns true if the item was found and removed, false otherwise. This method performs an exact match and does not consider priority.

if ($queue->remove($item_to_remove)) {
  print "Item removed.\n";
}

purge

Removes all items from the queue, making it empty.

$queue->purge;

adjust_priority ITEM_ID, FILTER_FUNCTION, DELTA

Adjusts an item's priority by adding DELTA to its current priority. The item is identified by its ITEM_ID (which is the item itself in this implementation), and the change will only be allowed to happen if the item's payload satisfies a FILTER_FUNCTION. Returns the new priority.

DELTA may be negative. ABSOLUTE_PRIORITY is calculated as current_priority + DELTA.

my $new_priority = $queue->adjust_priority(
  $item_id, \&one_of_mine, 100
);
sub one_of_mine {
  my $payload = shift;
  return $payload->{owner} == $me;
}

Returns undef if the item's priority could not be adjusted, and sets $! to explain why: ESRCH means that the ITEM_ID could not be found, and EPERM means that the FILTER_FUNCTION was not satisfied.

set_priority ITEM_ID, FILTER_FUNCTION, ABSOLUTE_PRIORITY

Sets an item's priority to a new ABSOLUTE_PRIORITY. The item is identified by its ITEM_ID, and the change will only be allowed to happen if the item's payload satisfies a FILTER_FUNCTION. Returns the new priority, which should match ABSOLUTE_PRIORITY.

Returns undef if the item's priority could not be set, and sets $! to explain why: ESRCH means that the ITEM_ID could not be found, and EPERM means that the FILTER_FUNCTION was not satisfied.

my $new_priority = $queue->set_priority(
  $item_id, \&one_of_mine, time() + 60
);
unless (defined $new_priority) {
  die "one of our submarines is missing: $item_id" if $! == ESRCH;
  die "set_priority disallowed for item $item_id" if $! == EPERM;
  die $!;
}
sub one_of_mine {
  $_[0]{owner} == $me;
}
