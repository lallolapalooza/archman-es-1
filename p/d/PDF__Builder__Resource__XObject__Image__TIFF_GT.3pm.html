NOMBRE

PDF::Builder::Resource::XObject::Image::TIFF_GT - Soporte de imagen TIFF (con Graphics::TIFF habilitado)

Hereda de PDF::Builder::Resource::XObject::Image

MÉTODOS

new

$res = PDF::Builder::Resource::XObject::Image::TIFF_GT->new($pdf, $file, %opts)
Devuelve un objeto de imagen TIFF. $pdf es el objeto PDF al que se está añadiendo, $file es el archivo TIFF de entrada, y el $name opcional del nuevo objeto de imagen padre tiene por defecto IxAAA.

Si el paquete Graphics::TIFF está instalado, y su uso no está suprimido a través del flag "nouseGT" (ver documentación de Builder para "image_tiff"), se utilizará la biblioteca TIFF_GT. De lo contrario, se utilizará la biblioteca TIFF en su lugar.

Opciones:

'notrans' => 1
Ignorar cualquier capa alfa (transparencia) y hacer que la imagen sea completamente opaca.
'name' => 'string'
Este es el nombre que puedes dar al objeto de imagen TIFF. El valor por defecto es Ixnnnn.

El soporte TIFF (cuando se utiliza Graphics::TIFF) es para los valores de "PhotometricInterpretation" 0 (blanco y negro/gris, blanco es 0), 1 (blanco y negro/gris, negro es 0), 2 (RGB) y 3 (color de paleta). Actualmente no soporta 4 (máscara de transparencia), 5 (CMYK separado), 6 (YCbCr), 8 (CIELab) o superiores. Hay un soporte limitado para un canal Alfa (transparencia) (debido a casos de prueba extremadamente limitados). Algunas etiquetas no son compatibles, y una configuración de PlanarConfiguration de 2 es desconocida hasta que tengamos algunos casos de prueba.

Algunas aplicaciones parecen tomar libertades extrañas con las etiquetas TIFF, como añadir un SamplePerPixel sin especificar el tipo ExtraSamples. En tales casos, tratamos una muestra adicional (no definida de otra manera) como un canal Alfa, ¡y esperamos lo mejor!

Si hay etiquetas o valores de campo inválidos dentro de una etiqueta, la biblioteca Graphics::TIFF intentará mostrar un cuadro de diálogo de advertencia, en lugar de simplemente ignorar las cosas inválidas. Si podemos encontrar un interruptor para deshabilitar este comportamiento, buscaremos añadirlo como una opción. Según el propietario de Graphic::TIFF (ticket RT 133955), esto proviene directamente de libtiff (como escritura a STDERR), ¡así que él no puede hacer nada al respecto!

Finalmente, aunque Graphics::TIFF no admite directamente pasar un manejador de archivos (generalmente un GLOB), PDF::Builder intentará detectar este problema y escribirá el contenido (del manejador de archivos) a un archivo temporal, y lo pasará como un archivo normal. ¡Algunos sistemas operativos parecen tener problemas para borrar este archivo temporal, así que ten en cuenta que tales archivos pueden acumularse con el tiempo!

usesLib

$mode = $tif->usesLib()
Devuelve 1 si Graphics::TIFF está instalado y se usa, 0 si no está instalado, o -1 si está instalado pero no se usa (se dio la opción nouseGT a "image_tiff").

Precaución: este método solo se puede usar después de que el objeto de imagen haya sido creado. No puede decirte si Graphics::TIFF está disponible antes de usarlo realmente, en caso de que quieras usar alguna funcionalidad disponible solo en TIFF_GT. Consulta la llamada LA_GT() de PDF::Builder si necesitas saberlo con antelación.
