NOMBRE

PDF::API2::Basic::PDF::Objind - Objeto indirecto PDF de bajo nivel

VARIABLES DE INSTANCIA

Las variables de instancia difieren de las variables de contenido en que todas comienzan con un espacio.

parent
Para un objeto que es una referencia a un objeto en alguna fuente, esto contiene la referencia al objeto fuente, de modo que si la referencia tiene que ser desreferenciada, entonces sabemos a dónde ir a buscar la información.
objnum (R)
El número de objeto en la fuente (solo para referencias de objetos)
objgen (R)
La generación del objeto en la fuente

Hay otras variables de instancia que son utilizadas por el padre para el control de archivos.

isfree
Esto marca si el objeto está en la lista de libres y disponible para su reutilización como otro objeto en otra parte del archivo.
nextfree
Contiene una referencia directa al siguiente objeto libre en la lista de libres.

MÉTODOS

PDF::API2::Basic::PDF::Objind->new()

Crea un nuevo objeto indirecto

uid

Devuelve un ID único para este objeto, creando uno si no tenía uno antes

$r->release

Libera TODA la memoria utilizada por este objeto indirecto y todos sus objetos componentes/hijos. Este método es llamado automáticamente por '"PDF::API2::Basic::PDF::File->release"' (así que no tienes que llamarlo tú mismo).

Nota: es importante que este método sea llamado en algún momento antes de la destrucción real del objeto. Internamente, los archivos PDF tienen una enorme cantidad de referencias cruzadas y esto causa referencias circulares dentro de nuestras propias estructuras de datos internas. Llamar a 'release()' fuerza la limpieza de estas referencias circulares y la purga de toda la estructura de datos interna.

$r->val

Devuelve el valor de este objeto o lee el objeto y luego devuelve su valor.

Tenga en cuenta que todas las subclases directas *deben* crear sus propias versiones de esta subrutina, ¡de lo contrario podríamos tener un bucle muy profundo!

$r->realise

Asegura que el objeto esté completamente leído, etc.

$r->outobjdeep($fh, $pdf)

Si realmente quieres sacar este objeto, entonces debes necesitar leerlo primero. Esto también significa que todas las subclases directas deben subclasar este método ¡o entrar en un bucle infinito!

$r->outobj($fh)

Si es un objeto completo, entonces saca una referencia al objeto, de lo contrario, llama a outobjdeep para sacar el contenido del objeto en este punto.

$r->elements

Relleno abstracto de la función de superclase. Devuelve self aquí pero debería devolver algo más útil si es un array.

$r->empty

Vacía todo el contenido de este objeto para liberar memoria o para ser leído y pasar el objeto a la lista de libres. Simplemente indefinidos todas las variables de instancia que no sean el número de objeto y la generación.

$r->merge($objind)

Esto fusiona información de contenido en un marcador de posición de referencia de objeto. Esto ocurre cuando se lee una referencia de objeto antes de la definición del objeto y la información de los datos leídos necesita ser fusionada en el marcador de posición del objeto.

$r->is_obj($pdf)

Devuelve si este objeto es un objeto completo con su propio número de objeto o si es puramente un sub-objeto. $pdf indica qué archivo de salida nos preocupa que el objeto sea un objeto en él.

$r->copy($pdf, $res)

Devuelve una nueva copia de este objeto. Se asume que el objeto es algún tipo de matriz asociativa y la copia es una copia profunda para los elementos que no son objetos PDF, de acuerdo con $pdf, y una copia superficial para los que sí lo son. Observe que llamar a "copy" en un objeto fuerza al menos una copia de un nivel, incluso si es un objeto PDF. Sin embargo, el objeto devuelto pierde su estado de objeto PDF.

Si $res está definido, entonces la copia va a ese objeto en lugar de crear uno nuevo. Depende del llamante bendecir $res, etc. Observe que los elementos de $self no se copian en $res si ya existe una entrada para ellos en $res.
